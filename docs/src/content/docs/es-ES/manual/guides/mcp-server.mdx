Esta guía explica cómo conectar un cliente MCP externo —Claude Code, un editor,
el MCP Inspector— al propio servidor de herramientas de Control Center.

Control Center registra **110** herramientas y las sirve por el Model Context
Protocol en la versión de protocolo `2024-11-05`. Faltan familias enteras de
herramientas que cabría esperar: no hay herramientas de reuniones ni de
calendario, ni tampoco de proyectos.

## Encontrar el endpoint

La superficie MCP comparte el listener principal de `cc_server`. No hay un
puerto MCP aparte.

| Endpoint | Método   | Propósito                                                |
| -------- | -------- | -------------------------------------------------------- |
| `/mcp`   | `POST`   | Transporte Streamable HTTP — es lo que habla un cliente |
| `/mcp`   | `DELETE` | Cerrar una sesión                                        |
| `/sse`   | `GET`    | Flujo de notificaciones enviadas por el servidor         |

Así que una instalación local predeterminada está en
`http://127.0.0.1:9030/mcp`.

1. Ve a **Ajustes → Servidor → Servidores MCP**
2. Lee la tarjeta **Servidor MCP**: indica en ejecución o detenido y el puerto
   en el que escucha

La superficie está activada por defecto en una instalación nueva. Solo el propietario del servidor ve el token de la tarjeta, y solo él puede iniciar o detener el endpoint. **Iniciar al abrir la app** controla si vuelve tras un reinicio; **Iniciar** / **Detener** son controles de sesión que no cambian esa preferencia.

El servidor se enlaza a loopback por defecto, así que el endpoint solo es
alcanzable desde la máquina en la que se ejecuta `cc_server`, salvo que lo
hayas arrancado con `--bind any`.

## Obtener el token

Cada petición necesita el token de MCP del servidor, desde cualquier máquina, incluidas las de loopback. El servidor lo crea la primera vez que arranca. No hay forma de desactivarlo ni de borrarlo.

1. En **Ajustes → Servidor → Servidores MCP**, busca la fila **Token de autenticación**
2. Pulsa **Mostrar token** y cópialo
3. Para sustituirlo, pulsa **Rotar token**. El servidor cambia al nuevo token de inmediato, y todo cliente que siga usando el anterior se rechaza hasta que le des el nuevo

## Conectar un cliente

Apunta tu cliente al endpoint Streamable HTTP y envía el token como `Authorization: Bearer <token>` en cada petición, incluida `GET /sse`. No hay otra forma de enviarlo: un token en la URL no se acepta. La forma exacta de la configuración es cosa de tu cliente.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code no lo tomará de un `.mcp.json` del proyecto: somete los servidores
MCP de ámbito de proyecto a una solicitud de aprobación que un `claude -p` no
interactivo nunca responde. Pasa la configuración de forma explícita:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` hace que Claude use solo ese archivo, de modo que el mismo
servidor no se descubra también desde el proyecto y quede registrado dos veces.

Punto de control: pide al cliente que liste sus herramientas. Deberías ver
entradas `mcp__*` que cubren tickets, espacios, memoria, el grafo de código y la
revisión.

## Qué rechaza el endpoint

El token abre todas las herramientas del servidor, así que el endpoint también rechaza cualquier cosa que una página web pudiera haber enviado, antes de mirar el token:

| Petición | Respuesta |
| -------- | --------- |
| Un encabezado `Origin` que no es una página de esta máquina (`http://localhost`, `http://127.0.0.1` o `http://[::1]`, cualquier puerto) | `403`, «Cross-origin requests are not accepted» |
| Un encabezado `Host` que no es ni la dirección loopback y el puerto de este listener ni el nombre de host público del servidor | `403`, «Unknown host» |
| Un `POST` cuyo cuerpo no es `application/json` | `415` |
| Sin token, o uno incorrecto | `401` |

Para servir MCP más allá del host, arranca el servidor con `--bind any` y envía el token desde la otra máquina, dirigiéndote al servidor por su nombre de host público.

## Acotar cada llamada a un espacio de trabajo

Toda herramienta que toque datos con ámbito de espacio de trabajo exige
`workspace_id`, y una llamada sin él se rechaza en lugar de resolverse contra
algún espacio de trabajo «actual»:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

El id es el de la URL de tu navegador o de la app: `/workspaces/<workspace_id>/…`.
Las únicas excepciones son las herramientas que abarcan de verdad varios
espacios de trabajo, como `list_workspaces` y las herramientas del feed de
noticias: el feed de noticias es por usuario y un agente no tiene usuario
propio, así que esas herramientas operan sobre los feeds del propietario del
servidor.

Las herramientas con ámbito de repo comprueban además que el repo esté vinculado
a ese espacio de trabajo.

## Saber qué rechazará la superficie

- **Restricción por modo.** Una llamada se resuelve en el servidor contra el
  modo del espacio del agente que llama. Un agente en un modo de solo lectura
  no puede alcanzar una herramienta de escritura omitiendo `space_id`: el modo
  se consulta en su ejecución activa.
- **Barandillas de acción.** Las herramientas que mutan declaran sus clases de
  efecto y pasan por la misma política que usa el resto del producto. Consulta
  [Configurar barandillas](/es-ES/manual/guias/configurar-barandillas/).
- **Confirmación.** Algunas herramientas destructivas construyen una carga de
  confirmación que debe aprobarse antes de que la llamada continúe.

El catálogo completo se anuncia en `tools/list` sin que el descubrimiento filtre
nada: un cliente MCP externo se niega a llamar a una herramienta que no esté en
su lista en caché, de modo que ocultar herramientas las rompe en lugar de
ordenarlas.

## Los servidores MCP personales siguen siendo del propietario

Esta guía trata del endpoint propio de Control Center. La otra dirección, los servidores MCP que Control Center entrega a los agentes que ejecuta, aparece en **Ajustes → Servidor → Servidores MCP → Servidores MCP externos**. Los servidores configurados en la máquina del servidor para Claude, Codex, Cursor, Gemini, VS Code, Windsurf, OpenCode o en un `.mcp.json` se encuentran allí automáticamente.

Estos servidores descubiertos proceden de la configuración de herramientas del propio usuario del servidor y actúan con la identidad y las credenciales de ese usuario, así que pertenecen al propietario del servidor:

- Solo están disponibles dentro de las ejecuciones del arnés integrado que el propietario del servidor inicia o de las que responde, incluida la automatización en un espacio de trabajo del que el propietario responde.
- La ejecución de un miembro, la automatización vinculada a un miembro y toda ejecución en un servidor sin propietario registrado no reciben ninguno de ellos. Allí las herramientas no aparecen en la lista, no se pueden llamar y no se muestran en la búsqueda de herramientas.
- Este endpoint nunca los lista, llama ni busca, para nadie, ni siquiera con el token del propietario, y tampoco transmite sus recursos ni sus prompts. Así que un CLI de agente que alcanza Control Center por MCP, como Claude Code, tampoco los obtiene a través de Control Center; usa su propia configuración.

Los servidores MCP configurados para el espacio de trabajo no se ven afectados por nada de esto.

## Solución de problemas

### El cliente no ve herramientas

- Comprueba que la tarjeta **Servidor MCP** ponga en ejecución
- Comprueba que el puerto coincida con el de tu `cc_server`
- En Claude Code, comprueba que has pasado `--mcp-config` y
  `--strict-mcp-config`

### 401 No autorizado

La petición no llevaba token, o llevaba uno antiguo. Copia el token actual de la fila **Token de autenticación** y envíalo como `Authorization: Bearer <token>`. Un token en la URL se ignora.

### 403 desde un cliente que funcionaba antes

La petición llevaba un `Origin` de una página web, o un `Host` al que el servidor no responde. Llama al endpoint desde un cliente en lugar de desde una página del navegador, por la dirección loopback del servidor o por su nombre de host público.

### 415 Tipo de medio no admitido

Envía los cuerpos de `POST /mcp` como `application/json`.

### Una llamada a una herramienta falla con «Missing or invalid argument: workspace_id»

Añade `workspace_id`. No hay ningún espacio de trabajo implícito.

### Una llamada a una herramienta se rechaza por desconocida

[Herramientas MCP](/es-ES/manual/referencia/herramientas-mcp/) lista el
catálogo. Llama al nombre exactamente como aparece allí.
