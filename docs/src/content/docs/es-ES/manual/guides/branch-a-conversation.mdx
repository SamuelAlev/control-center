Esta guía te muestra cómo volver a un punto anterior de una conversación y llevarla a otro sitio sin perder el camino que dejas atrás.

## Lo único que conviene saber

**Ramificar no escribe nada.** Una conversación es un árbol de mensajes con un puntero en el extremo, y volver atrás mueve el puntero. No se elimina nada, no se oculta nada y volver a cambiar es otro movimiento de puntero.

Por eso editar un prompt y volver a ejecutarlo es seguro aquí: la respuesta con la que estabas comparando sigue ahí.

## Ver las ramas

```
/tree
```

El navegador enumera todos los mensajes, con sangría en cada bifurcación, y marca el camino actual como **En esta rama**. Una conversación en la que nunca se ha bifurcado se muestra como la lista plana de siempre: mirar el navegador no cuesta nada hasta que hay algo que navegar.

Cada fila ofrece dos acciones.

| Acción                                 | Efecto                                                            |
| -------------------------------------- | ----------------------------------------------------------------- |
| **Continuar desde aquí**               | Mueve el puntero. Tu siguiente mensaje continúa desde ese mensaje. |
| **Bifurcar en una conversación nueva** | Copia el camino hasta ese mensaje en una conversación nueva.      |

## Ramificar: probar otro enfoque

1. `/tree`
2. Busca el mensaje desde el que quieres volver a empezar, normalmente el último que te convencía.
3. **Continuar desde aquí.**
4. Escribe el nuevo prompt.

La continuación anterior sigue en el árbol; `/tree` mostrará ahora dos caminos desde ese punto y puedes alternar entre ellos libremente.

:::note[El camino que dejaste sigue ahí]
Ramificar no oculta ni elimina nada. `/tree` enumera todos los caminos, marca el actual como **En esta rama** y es la forma de cambiar de uno a otro.
:::

## Bifurcar: llevarla a otro sitio

Bifurcar copia el camino en una **conversación nueva** dentro del mismo espacio. Úsalo cuando las dos direcciones vayan a seguir divergiendo y las quieras una al lado de la otra en lugar de ir alternando.

La copia usa ids de mensaje nuevos. Dos conversaciones que compartieran filas se mostrarían los mensajes posteriores de la otra, que es justo lo que una bifurcación debe evitar.

## Revertir frente a ramificar

Son herramientas distintas y la diferencia importa.

|                          | Revertir                                     | Ramificar                    |
| ------------------------ | -------------------------------------------- | ---------------------------- |
| Los mensajes posteriores | Se ocultan de la transcripción               | Siguen visibles en `/tree`   |
| El **worktree**          | Se revierte a la instantánea de ese turno    | No se toca                   |
| Deshacer                 | **Deshacer reversión** restaura el conjunto  | Mueve el puntero hacia atrás |

Revertir es lo que quieres cuando el agente cambió *archivos* que quieres recuperar. Ramificar es lo que quieres cuando la conversación tomó el camino equivocado pero los archivos están bien.

Revertir también mueve el extremo de rama, así que tu siguiente mensaje continúa desde el lugar correcto y no desde una cola que ya nadie puede ver.

## Sacarla de la aplicación

### `/export`

Escribe un **archivo HTML autocontenido**: toda la conversación con tarjetas de herramientas plegables que muestran qué recibió cada llamada y qué devolvió. Sin hoja de estilos, sin scripts y sin servidor de imágenes: funciona desde una memoria USB y seguirá funcionando dentro de cinco años.

- **Escritorio:** `Documents/ControlCenter/exports/`, con marca de tiempo para que una segunda exportación no sobrescriba la primera.
- **Web:** una descarga del navegador.

### `/dump`

Copia la transcripción al portapapeles como Markdown, con las llamadas a herramientas en bloques plegables. Esta es la que conviene pegar en un issue.

El razonamiento se omite a propósito: es el espacio de borrador del modelo, y un informe de error lo lee una persona.
