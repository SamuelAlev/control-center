Esta guía muestra cómo dar a tu servidor su propia GitHub App. Tarda unos dos
minutos, solo la hace el propietario del servidor y solo hay que hacerla una vez
por servidor.

:::note[Puede que no la necesites]
Con Control Center Connect activado, las personas inician sesión en GitHub a
través de la App compartida de Control Center, o de la App que usa el Connect de
tu organización. Registra la tuya cuando hayas elegido **Usar mis propias apps**: la App del servidor solo se usa en ese caso. Consulta [Control Center Connect](/es-ES/manual/referencia/connect/).
:::

Para iniciar sesión con tu propia cuenta después, consulta
[Configurar la integración con GitHub](/es-ES/manual/guias/integracion-github/).

## Qué hace la app

De un mismo registro salen dos trabajos distintos:

| Trabajo                       | Qué lo responde                                 | Por qué importa                                                                                         |
| ----------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| **Una persona inicia sesión** | El id de cliente y el secreto de cliente de la app | Cada persona obtiene su propia credencial de GitHub, en el servidor y en todos los dispositivos      |
| **El servidor actúa**         | El id de la app y la clave privada              | Los agentes, los pipelines, los sondeos y las respuestas del bot reciben tokens de un solo repositorio cada vez |

El segundo trabajo nunca toma prestada por completo la credencial de una
persona. Cada token que emite el servidor cubre un solo repositorio y se limita
a lo que un miembro responsable puede hacer en él. Leer un repositorio vinculado
solo necesita la app; cualquier cosa que escriba necesita un miembro que pueda
hacer push. La automatización nunca aprueba una pull request.

La app del servidor solo se aplica con **Usar mis propias apps**. Con Control Center o un Connect propio, Connect ejecuta cada carril, también GitHub; la app del servidor se queda guardada pero sin usar hasta que vuelvas atrás. Una app propia del espacio de trabajo ([Dar a un espacio de trabajo otra app](#dar-a-un-espacio-de-trabajo-otra-app)) se aplica siempre, sea cual sea el modo. Una app a la
que le faltan campos es un error, no un motivo para recurrir a otra cosa: los
inicios de sesión de GitHub se rechazan hasta que todos los campos estén
definidos.

## Requisitos previos

- Eres el **propietario del servidor**. La tarjeta **Aplicaciones de proveedor**
  es invisible para todos los demás
- Una cuenta de GitHub. La app se crea bajo ella
- Una dirección del servidor a la que llegue tu navegador. La URL pública del
  servidor (o loopback, en el servidor propio de un escritorio) es adonde GitHub
  te devuelve

## Crearla con un clic

1. Ve a **Ajustes → Servidor → Inicio de sesión único** y desplázate hasta la
   tarjeta **Aplicaciones de proveedor**
2. En el bloque **GitHub**, escribe si quieres en **Organización (opcional)** la
   organización de GitHub que debe ser propietaria de la app. Déjalo vacío para
   crear la app bajo tu propia cuenta; crearla bajo una organización requiere a
   un propietario de esa organización
3. Haz clic en **Crear mi app de GitHub**
4. El navegador abre GitHub con la app ya rellenada. Haz clic en
   **Create GitHub App**
5. GitHub te devuelve al servidor, que guarda el id de la app, la clave privada,
   el id de cliente y el secreto de cliente, y luego abre la página de
   instalación de la app

No se copia nada a mano, y el código de conversión va directamente de GitHub a
tu servidor. El enlace funciona una sola vez y caduca a los diez minutos; si
caduca, vuelve a hacer clic en **Crear mi app de GitHub**.

La app se llama `Control Center <code>` y pide exactamente lo que usa Control
Center:

| Permiso                                    | Acceso              |
| ------------------------------------------ | ------------------- |
| Metadata                                   | Lectura             |
| Contents                                   | Lectura y escritura |
| Pull requests                              | Lectura y escritura |
| Issues                                     | Lectura y escritura |
| Checks, Actions, Commit statuses           | Lectura             |
| Organization members                       | Lectura             |

Los webhooks están desactivados: el servidor sondea. Para trasladar más adelante
a una organización una app que creaste bajo tu propia cuenta, usa
**Transfer ownership** en los ajustes avanzados de la app en GitHub.

Punto de control: el bloque de GitHub dice «El servidor puede actuar por sí
mismo y las personas pueden iniciar sesión.».

## Instalarla donde están tus repositorios

Una app que está registrada pero no instalada puede iniciar la sesión de las
personas y no leer nada.

1. En la página de instalación que abrió GitHub, elige la cuenta o la
   organización propietaria de tus repositorios
2. Elige **All repositories**, o selecciona los que este servidor deba ver

Para instalarla más adelante en otra cuenta, un administrador del espacio de
trabajo va a **Ajustes → Espacio de trabajo → General**, busca
**Instalaciones de la app de GitHub** en la tarjeta de identidad de GitHub y
hace clic en **Instalar la app de GitHub**. La lista muestra todas las cuentas
en las que está instalada la app y marca las instalaciones suspendidas.

## Autorizar este servidor para una organización

En la App compartida de Control Center, la instalación de una organización solo
sirve a los servidores que sus administradores han autorizado. Instalarla
mediante **Instalar la app de GitHub** autoriza el servidor que lo inició. Para
una instalación que ya existe:

1. Un administrador de esa organización inicia sesión en GitHub en este servidor
2. Abre **Ajustes → Espacio de trabajo → General → Instalaciones de la app de
   GitHub**
3. La fila de la organización dice **No autorizada**. Hace clic en
   **Autorizar este servidor**

La fila pasa entonces a decir **Autorizada**. Tu propia app no necesita nada de
esto: todas sus instalaciones pertenecen a tu servidor.

## Registrarla a mano en su lugar

La tarjeta **Aplicaciones de proveedor** también acepta los valores
directamente, para una app que registraste tú:

| Grupo                          | Campos                                                                                                  |
| ------------------------------ | ------------------------------------------------------------------------------------------------------- |
| **Actuar como el servidor**    | **Id de la app** y **Clave privada** (todo el `.pem`, incluidas las líneas `BEGIN` y `END`)             |
| **Inicio de sesión de las personas** | **Id de cliente** y **Secreto de cliente**. **URL de retorno** muestra la URL que hay que registrar, tal cual |
| **Conversaciones de pull request** | **Login del bot**, que se resuelve al probar la conexión                                             |

Registra la URL de retorno `<server origin>/oauth/github/callback` exactamente
como la muestra la tarjeta, deja activada **Expire user authorization tokens** y
concede los permisos de la tabla anterior. Haz clic en **Probar**: pregunta a
GitHub en qué cuentas está instalada la app, para no confundir «guardado» con
«funciona».

## Configurarla desde el `.env` del servidor

Para una instalación headless o automatizada con scripts, el servidor siembra
cada campo desde su archivo `.env` la primera vez que no tiene un valor
guardado:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

Pon la clave en **una sola línea**: un valor de `.env` es una línea, y `\n`
entre comillas dobles se descodifica como un salto de línea. El servidor se
niega a arrancar cuando `GITHUB_APP_PRIVATE_KEY` o `GITHUB_CLIENT_SECRET` están
exportados en el entorno de su proceso, donde cualquier proceso hijo podría
leerlos; guárdalos en el archivo `.env` (en Docker, móntalo en `/app/bin/.env`).
El sembrado ocurre **una vez por campo**, así que editar en Ajustes no queda
deshecho por el siguiente reinicio.

## Dar a un espacio de trabajo otra app

Un espacio de trabajo puede usar una app propia en lugar de la del servidor. Un
administrador del espacio de trabajo va a **Ajustes → Espacio de trabajo →
General**, elige **Usar otra GitHub App** en la tarjeta **Identidad de GitHub**
e introduce el id de la app, la clave privada, el id de cliente y el secreto de
cliente de esa app. A partir de ahí, los miembros inician sesión en esa app para
este espacio de trabajo. Un espacio de trabajo con su propia app nunca recurre a
la app del servidor ni a Connect: hasta que sus campos estén completos, su
trabajo con GitHub se rechaza. Se aplica sea cual sea la forma en que el servidor inicia la sesión de las personas, también con Connect.

La tarjeta **Aplicaciones de proveedor** de esa misma página hace lo mismo para Google Calendar, Linear y la búsqueda de GIF. Consulta [Dale a un espacio de trabajo su propia aplicación de Linear](/es-ES/manual/guias/integracion-linear/#dale-a-un-espacio-de-trabajo-su-propia-aplicación-de-linear) y [Dale a un espacio de trabajo su propio cliente de Google](/es-ES/manual/guias/conectar-calendario/#dale-a-un-espacio-de-trabajo-su-propio-cliente-de-google).

## Solución de problemas

### Crear mi app de GitHub dice que el servidor no tiene dirección

El servidor no tiene ninguna URL pública a la que pueda volver un navegador.
Define `CC_SERVER_PUBLIC_URL` (o `--public-url`) y vuelve a intentarlo.

### GitHub dice que el enlace ha caducado

La página de un solo uso ya se usó, o pasaron diez minutos. Vuelve a empezar
desde Ajustes.

### Probar dice que las credenciales funcionan, pero la app no está instalada en ninguna parte

El registro y la instalación son pasos distintos. Abre la página de instalación
de la app, o usa **Instalar la app de GitHub** en Espacio de trabajo → General.

### Probar dice que no se ha podido leer la clave privada

Pega el archivo `.pem` completo, incluidas las líneas `-----BEGIN` y `-----END`.
No se puede usar una clave `ed25519` ni EC: las GitHub Apps firman con RSA.

### Un miembro ha iniciado sesión pero no ve ningún repositorio

La app no está instalada en la cuenta propietaria de esos repositorios, o su
instalación selecciona otros distintos. Un inicio de sesión solo concede lo que
la app tiene permitido ver.

### Los agentes dicen que la instalación de la GitHub App está suspendida

Alguien suspendió la instalación en GitHub. Reactívala en
**Settings → Applications → Installed GitHub Apps** de esa cuenta.
