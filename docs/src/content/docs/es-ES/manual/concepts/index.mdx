These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/es-ES/manual/guias/); when you want to look
something up, go to the [reference](/es-ES/manual/referencia/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/es-ES/manual/conceptos/espacios-de-trabajo/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/es-ES/manual/conceptos/modelo-de-agentes/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/es-ES/manual/conceptos/ciclo-de-vida-del-despacho/) — what happens between your message and the agent's first token
- [Modes](/es-ES/manual/conceptos/modos/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/es-ES/manual/conceptos/contexto-de-herramientas/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/es-ES/manual/conceptos/inteligencia-de-codigo/) — the code graph, language server, structural search and debugger
- [Conversation history](/es-ES/manual/conceptos/historial-de-conversacion/) — persistence, compaction and forking a transcript
