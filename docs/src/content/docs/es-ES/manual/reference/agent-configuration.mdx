Esta referencia enumera todos los campos de la entidad de agente, además de las enumeraciones e indicadores que usa. Para ver el procedimiento paso a paso para crear o editar un agente en la aplicación, consulta [Crear y configurar un agente](/es-ES/manual/guias/crear-agente/).

## Campos de la entidad de agente

| Campo                   | Tipo                   | Obligatorio | Descripción                                                                                                                                                                                          |
| ----------------------- | ---------------------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                    | `String`               | Sí          | Identificador único del agente                                                                                                                                                                       |
| `name`                  | `String`               | Sí          | Identificador corto para menciones con @                                                                                                                                                             |
| `title`                 | `String`               | Sí          | Título del rol legible por personas                                                                                                                                                                  |
| `agentMdPath`           | `String`               | Sí          | Ruta absoluta al archivo de definición `.md` del agente                                                                                                                                              |
| `workspaceId`           | `String`               | Sí          | Espacio de trabajo propietario (no null)                                                                                                                                                             |
| `reportsTo`             | `String?`              | No          | Identificador del agente superior                                                                                                                                                                    |
| `skills`                | `AgentSkills`          | Sí          | Conjunto de identificadores de skills                                                                                                                                                                |
| `persona`               | `String?`              | No          | Instrucciones de comportamiento en texto libre                                                                                                                                                       |
| `systemPrompt`          | `String?`              | No          | Anula el prompt de sistema predeterminado                                                                                                                                                            |
| `adapterId`             | `String?`              | No          | Identificador del adaptador de inferencia                                                                                                                                                            |
| `modelId`               | `String?`              | No          | Identificador del modelo dentro del adaptador                                                                                                                                                        |
| `strictMode`            | `bool`                 | No          | Predeterminado `false`. Se escribe en la fila y en el `AGENTS.md` del agente                                                                                                                         |
| `effort`                | `String?`              | No          | Identificador del nivel de razonamiento (p. ej. `'low'`, `'xhigh'`), tomado de `thinkingLevels` del modelo seleccionado                                                                             |
| `contextSize`           | `int?`                 | No          | Tamaño máximo de la ventana de contexto                                                                                                                                                              |
| `role`                  | `AgentRole?`           | No          | Rol del agente                                                                                                                                                                                       |
| `monthlyBudgetMicros`    | `int`                  | No          | Límite de gasto mensual en microdólares (predeterminado `0`, ilimitado)                                                                                                                                  |
| `silenceTimeoutMinutes` | `int?`                 | No          | Anulación del tiempo de silencio en minutos; debe ser null o estar entre 1 y 240 (verificado en el constructor)                                                                                      |
| `maxConcurrentTasks`    | `int`                  | No          | Predeterminado `1`. Cifra de capacidad que comunica el modelo de presencia (los recuentos en ejecución y en cola se comparan con ella)                                                              |
| `visibility`            | `AgentVisibility`      | No          | Predeterminado `workspace`                                                                                                                                                                           |
| `lifecycleStatus`       | `AgentLifecycleStatus` | No          | Estado de gobernanza (predeterminado `active`). Lo escribe la parada dura del presupuesto y se representa en el organigrama y en la lista de presencia. El despacho sigue aceptando trabajo de un agente `paused` |
| `budgetPolicyId`        | `String?`              | No          | Identificador de la política de presupuesto compartida; cuando es null se aplica directamente `monthlyBudgetMicros`                                                                                   |
| `runtimeProfileId`      | `String?`              | No          | Identificador del perfil de tiempo de ejecución personalizado                                                                                                                                        |
| `createdAt`             | `DateTime`             | Sí          | Marca de tiempo de creación                                                                                                                                                                          |

`name` y `title` deben ser ambos no vacíos (verificado en el constructor). Un
`monthlyBudgetMicros` predeterminado de `0` significa ilimitado. Escribe un techo con `agents.upsert`.

## Permisos

Un agente no lleva indicadores de permisos. Hacer push, abrir y publicar pull requests, escribir en un rastreador y la salida a la red son clases de acción (`gitPush`, `prCreate`, `prPublish`, `vendorSyncWrite`, `networkEgress`) que las [barandillas](/es-ES/manual/conceptos/barandillas/) resuelven en el ámbito del espacio de trabajo, del agente o del espacio. El token de GitHub de una ejecución tiene siempre alcance de lectura; los push pasan por la pasarela de ejecuciones de agentes, que pregunta a la regla `gitPush` antes de reenviarlos.

## AgentSkills

Un conjunto inmutable y que no distingue mayúsculas de minúsculas de identificadores de skills. Al despachar, esos slugs se sincronizan como enlaces de skills en el overlay del agente; el arnés carga entonces automáticamente el frontmatter de las skills enlazadas en el prompt.

```
{'flutter', 'dart', 'rest-api'}
```

## Hooks de shell

Los hooks de shell permiten al propietario del servidor ejecutar sus propios scripts alrededor de una ejecución del agente: una vez al iniciar la sesión, antes de cada llamada a una herramienta, después de cada una, cuando el agente terminaría su turno y antes de una compactación. Un hook es código arbitrario, así que los hooks son configuración del host. Solo el propietario del servidor los configura, a mano, en la máquina del servidor. No hay ningún ajuste en la aplicación ni ninguna operación que los escriba.

Para un agente, los hooks viven en su propia carpeta dentro del directorio de datos del servidor:

```text
<data dir>/_agent_hooks/<workspace id>/<agent slug>/hooks.json
```

`<agent slug>` es el nombre de la carpeta del agente en el espacio de trabajo (`agents/<slug>/`). Esa carpeta queda fuera del almacenamiento de todos los espacios de trabajo, y todos los sandboxes ocultan el directorio de datos, así que ningún miembro, ejecución ni terminal puede escribirla.

`hooks.json` asocia cualquiera de cinco claves con un script, mediante una ruta relativa a la carpeta de hooks:

| Clave          | Cuándo se ejecuta                 | Qué significa su código de salida                                  |
| -------------- | --------------------------------- | ------------------------------------------------------------------ |
| `sessionStart` | Una vez, cuando empieza la ejecución | Nada; el hook solo observa                                      |
| `preTool`      | Antes de cada llamada a herramienta | `0` permite la llamada; cualquier otro valor la deniega          |
| `postTool`     | Después de cada llamada a herramienta | Nada; el hook solo observa                                     |
| `stop` | Cuando el agente terminaría su turno | `2` con texto en la salida estándar mantiene la ejecución en marcha con ese texto; cualquier otra cosa deja terminar el turno |
| `preCompact` | Antes de una compactación | `0`: su salida estándar se añade a lo que el resumen debe conservar |

- Cada script se inicia como su propio ejecutable, sin shell y sin argumentos, así que debe ser ejecutable y empezar por una línea shebang. Recibe el evento como JSON por stdin: el nombre del evento y, en los hooks de herramienta, el nombre de la herramienta con sus argumentos (`preTool`) o su resultado (`postTool`).
- Un hook se ejecuta como uno de los procesos de herramienta de la ejecución, en el directorio del agente para esa ejecución. Cuando el servidor pone a los agentes en sandbox, se ejecuta dentro del sandbox de la ejecución. Recibe un entorno mínimo y ninguna de las credenciales de la ejecución: ningún token de la forja ni de proveedor, y ningún acceso a la pasarela.
- Cada hook dispone de 30 segundos. La salida de `sessionStart`, `preTool` y `postTool` se lee y se descarta.
- `preTool` falla en cerrado. Un código de salida distinto de cero, un tiempo agotado o un script que no puede iniciarse deniega la llamada a la herramienta.
- Una ruta absoluta, inexistente o que sale de la carpeta de hooks (tras resolver los enlaces) se rechaza, y el registro de la ejecución indica qué hook se rechazó y por qué. Un hook `preTool` rechazado o ilegible deniega todas las llamadas a herramientas hasta que se corrija.
- Un bloque `hooks` en `.agents/harness.json`, ya sea en un repositorio o en la carpeta propia del agente, se ignora. Un repositorio suele ser código de otra persona, y la carpeta del agente puede escribirla cualquier miembro y las ejecuciones. El registro de la ejecución indica que el bloque se ignoró y de dónde se leen los hooks en su lugar.

### Los hooks stop y preCompact

- `stop` recibe `event: "stop"`, el último mensaje del agente (`last_message`), `stop_hook_active` (true cuando esta parada sigue a una continuación que provocó el hook) y `block_count` (cuántas veces ha mantenido la ejecución en marcha hasta ahora, desde 0). Para mantener la ejecución en marcha, sale con `2` e imprime lo que el agente debe hacer a continuación. El texto, recortado a 2.000 caracteres, llega al agente como mensaje del sistema.
- Un hook `stop` mantiene una ejecución en marcha como máximo 3 veces en una ejecución. Después ya no se vuelve a ejecutar, y el turno termina.
- `stop` falla en abierto. Un timeout, un script que no puede arrancar, cualquier salida distinta de `2`, o una salida `2` sin nada en la salida estándar deja terminar el turno, así que un hook roto no puede mantener una ejecución abierta.
- `preCompact` recibe `event: "pre_compact"`. Su salida estándar, recortada a 1.000 caracteres, se añade al foco de la compactación. Un script que falla no añade nada.

Los hooks de shell se aplican al arnés integrado. En Claude Code, también se ejecutan los hooks `stop` y `preCompact`: los hooks `Stop` y `PreCompact` propios de Claude Code piden al servidor, y el servidor ejecuta los scripts del propietario de la misma forma. Las otras tres claves se aplican solo al arnés integrado. Un hook `preTool` o `postTool` configurado hace que la ejecución llame a sus herramientas de una en una.

## AgentLiveState (derivado)

No se almacena. Siete valores. El orden de declaración es el orden de prioridad (`sortPriority`, fijado por un test), que es el orden por el que ordena la lista de presencia:

| Estado      | `sortPriority` | Condición                                                                                                            |
| ----------- | -------------- | -------------------------------------------------------------------------------------------------------------------- |
| `running`   | 0              | Algún registro de ejecución tiene el estado `running`                                                                |
| `blocked`   | 1              | La vitalidad de la última ejecución es `blocked`, `stalled` o `looping`                                              |
| `failed`    | 2              | El estado de la última ejecución es `error`, o su vitalidad es `failed` o `dead`                                     |
| `queued`    | 3              | Una ejecución se ha despachado pero no se está ejecutando: aparcada detrás de otra ejecución del mismo agente, o escrita pero aún sin iniciar |
| `succeeded` | 4              | La ejecución terminó correctamente                                                                                    |
| `idle`      | 5              | El agente ya se ha ejecutado antes y no tiene nada en curso                                                           |
| `neverRun`  | 6              | No existe ningún registro de ejecución                                                                               |

`queued` y `succeeded` son **solo por ejecución**. `deriveAgentLiveState`, que calcula el estado de la lista de presencia de un agente, nunca produce ninguno de los dos: devuelve `neverRun`, `running`, `failed`, `blocked` o `idle`.
