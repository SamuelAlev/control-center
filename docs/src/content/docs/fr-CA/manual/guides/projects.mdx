Un projet est un regroupement de tickets à l’échelle d’un espace de travail,
autour d’un objectif commun. Les projets n’existent que dans Control Center —
ils ne se synchronisent jamais avec un fournisseur externe comme Linear.

## Créer un projet

1. Déployez le groupe **Tickets** dans la barre latérale de l’espace de
   travail. Il énumère **Tous les tickets**, une ligne par projet non archivé,
   puis **Nouveau projet**.
2. Cliquez sur **Nouveau projet**.
3. Remplissez le **Nom du projet**, une **Description** facultative, puis
   choisissez une **Couleur**.
4. Appuyez sur **Créer le projet**.

Vous arrivez sur la vue d’ensemble du nouveau projet, et le projet apparaît
comme une ligne de la barre latérale sous **Tickets**.

## Ajouter des tickets à un projet

Le projet est un champ propre à un ticket, défini à l’un ou l’autre de deux
endroits :

- Ouvrez le ticket et définissez le **Projet** dans son volet des propriétés.
- Cliquez avec le bouton droit sur le ticket dans la liste et utilisez le
  sous-menu **Projet**.

Le sélecteur du volet des propriétés propose aussi **Nouveau projet**, ce qui
vous permet de classer un ticket dans un projet que vous créez sur-le-champ.
**Aucun projet** vide le champ.

Un ticket appartient à au plus un projet.

:::note[Le projet n’est pas une action groupée]
La barre flottante qui apparaît quand vous sélectionnez plusieurs tickets
couvre le statut, la priorité, l’assigné, les étiquettes et la suppression.
Elle n’a pas de puce de projet, donc classer plusieurs tickets signifie le faire
un par un.
:::

Vous pouvez aussi partir du projet : **Nouveau ticket** sur la vue d’ensemble
du projet crée un ticket et le classe dans ce projet.

## Lire la progression d’un projet

Ouvrez un projet à partir de sa ligne dans la barre latérale, ou rendez-vous à
`/workspaces/<workspace-id>/projects/<project-id>`.

La vue d’ensemble affiche le glyphe et le nom du projet, une pastille de statut,
la description et une barre de progression indiquant les tickets terminés sur
le total. En dessous, les tickets du projet sont regroupés par statut.

Elle n’agrège rien d’autre — il n’y a ni répartition par assigné ni répartition
des priorités. Pour cela, filtrez plutôt la liste principale des tickets.

## Changer le statut d’un projet

Les projets ont trois états :

| Statut      | Signification               |
| ----------- | --------------------------- |
| **Actif**   | Le travail est en cours     |
| **Terminé** | Tout le travail est terminé |
| **Archivé** | Référence historique        |

Utilisez le menu **⋯** de l’en-tête du projet. Il propose **Modifier le
projet**, **Marquer comme terminé** / **Marquer comme actif**, **Archiver** /
**Restaurer** et **Supprimer le projet**.

L’archivage masque le projet de la liste de la barre latérale et des sélecteurs
de tickets. Il est réversible — **Restaurer** remet le projet à l’état actif —
mais le projet n’est accessible que par URL tant qu’il est archivé.

## Les projets créés pour vous

Approuver une orchestration crée un projet et classe le ticket parent sous
celui-ci, aux côtés de tout ce que vous avez classé à la main. Les éléments de
travail générés sont des étapes de pipeline, et non des lignes de ticket, donc
ils n’apparaissent pas sur le tableau du projet. C’est le seul chemin
automatisé : aucun nœud de pipeline ne crée de tickets, donc un pipeline ne peut
pas alimenter un projet. Voir
[Lancer une orchestration](/fr-CA/manuel/guides/lancer-orchestration/).

:::note[Les projets sont une surface d’opérateur]
Créez, listez, modifiez et supprimez les projets dans l’application. Les agents
n’ont pas d’outils de projet.
