Ce guide couvre les volets propres à GitHub de la configuration. GitHub est l’un
des trois hébergeurs de code pris en charge. Consultez
[Connecter un hébergeur de code](/fr-CA/manuel/guides/connecter-hebergeur-de-code/)
pour connecter GitLab ou Bitbucket, et pour savoir comment un espace de travail
les combine.

## Prérequis

- Un compte GitHub ayant accès aux dépôts sur lesquels vous voulez travailler
- Un serveur qui peut connecter les gens à GitHub : soit avec sa propre GitHub
  App (voir [Créer la GitHub App](/fr-CA/manuel/guides/github-app/)), soit avec
  Control Center Connect, au choix du propriétaire du serveur dans **Paramètres →
  Serveur → Authentification unique**

:::note[Les identifiants vivent sur le serveur, rattachés à vous]
Rien n’est stocké sur la machine sur laquelle vous tapez. Votre connexion GitHub
est détenue par votre `cc_server`, indexée par votre identifiant d’utilisateur,
et chaque appareil à partir duquel vous vous connectez l’utilise : bureau, Web et
téléphone. Un autre membre du même serveur ne peut pas l’utiliser, et se
connecter est une chose qu’il fait lui-même.
:::

## Se connecter à GitHub

Pour GitHub, on ne fait que se connecter : il n’y a aucun jeton à coller.

1. Allez dans **Paramètres → Espace de travail → Profil et identité → Hébergement de code** (ou à la première
   étape de la configuration initiale)
2. Sur la ligne **GitHub**, cliquez sur **Se connecter à GitHub**
3. Votre navigateur ouvre GitHub. Approuvez l’app

La façon dont la connexion se termine dépend de qui l’effectue :

- **L’app propre au serveur :** GitHub renvoie votre navigateur au serveur et la
  boîte de dialogue s’en aperçoit d’elle-même. Rien à taper
- **Control Center Connect :** la page du navigateur affiche un code de
  8 caractères. Tapez-le dans la boîte de dialogue, ou laissez le navigateur
  ouvrir Control Center par le lien `control-center://` pour ne pas avoir à le
  taper

Point de contrôle : la ligne **GitHub** affiche « Connecté en tant que
_votre-nom-d’utilisateur_ ».

La boîte de dialogue refuse un code ou un lien qu’elle n’a pas lancé elle-même,
avec **Connexion non lancée d’ici**. Si quelqu’un vous envoie un lien de
connexion, ne continuez pas : aller jusqu’au bout connecterait votre compte à
son serveur.

Cliquez sur **Déconnecter** pour supprimer votre connexion. Vous déconnecter de
GitHub, ou être retiré d’un espace de travail, invalide aussi tous les jetons que
le serveur a émis en votre nom.

## Pour qui parle votre identifiant

- **Tout ce que vous faites** (ouvrir la page de la PR, publier une révision,
  approuver, fusionner) s’exécute avec **votre** connexion et rien d’autre. Si
  vous n’êtes pas connecté, l’app vous le dit et vous demande de vous connecter.
  Aucun autre identifiant ne vous remplace
- **Le travail que personne ne tape** (exécutions d’agents, pipelines,
  interrogation périodique des PR, réponses du robot, clonages) reçoit un jeton
  pour un seul dépôt, émis à partir de la GitHub App du serveur ou par Connect.
  Il est limité à ce qu’un membre responsable peut y faire : le membre qui a fait
  la demande, sinon le propriétaire de l’espace de travail. Un membre qui ne peut
  pas pousser restreint le jeton à la lecture
- **L’automatisation n’approuve jamais** une demande de tirage. L’approbation est
  un geste humain

## Ce que l’intégration vous apporte

| Fonctionnalité           | Comment                                                                                                        |
| ------------------------ | -------------------------------------------------------------------------------------------------------------- |
| Liste et détail des PR   | L’API REST de GitHub, depuis le serveur, avec votre propre connexion                                           |
| Exécutions de vérification | L’API Checks de GitHub                                                                                        |
| Publication des révisions | Une étape nécessitant une action de l’utilisateur, qui publie votre révision dans la PR, en votre nom         |
| Enregistrement des dépôts | Un checkout est accepté si son dépôt distant `origin` pointe vers github.com, ou vers gitlab.com / bitbucket.org |
| Accès des agents à GitHub | Un jeton pour l’unique dépôt de l’exécution, sous forme de `GH_TOKEN` / `GITHUB_TOKEN`; les poussées passent par Control Center |
| Notifications             | Une interrogation côté serveur de votre boîte de réception GitHub déclenche « Mentionné dans une pull request » et « Revue demandée » |
| Profils d’utilisateur     | Cartes de profil au survol et filtrage des PR par auteur                                                       |

Certains chemins passent par l’API GraphQL plutôt que REST lorsqu’elle coûte
moins cher : l’activité des branches pour le sélecteur de PR à composer et l’état
de révision en direct qui détermine si une notification de révision demandée est
toujours en attente.

## Surveiller les pannes de GitHub

La barre de titre affiche une pastille d’état lorsqu’un fournisseur est dégradé,
ce qui couvre GitHub, Claude, OpenAI et Kimi. **Elle est masquée tant que tout va
bien** : c’est sa présence qui signale un problème, et non son absence.

Cliquez sur la pastille pour ouvrir un volet volant présentant l’état de chaque
fournisseur et un bouton d’actualisation. Les états s’actualisent d’eux-mêmes
toutes les deux minutes.

## Savoir comment les agents agissent sur GitHub

- Un agent qui travaille dans un arbre de travail GitHub reçoit un jeton pour ce
  seul dépôt. Il peut lire le code et commenter les demandes de tirage quand le
  membre responsable peut pousser, et seulement lire sinon. Un push passe par
  Control Center, qui interroge la règle **Pousser vers un dépôt distant** puis
  le transmet avec un jeton d’écriture que l’agent ne détient jamais. Voir
  [Configurer les politiques de bac à sable](/fr-CA/manuel/guides/politiques-de-bac-a-sable/)
- Les commits des agents utilisent toujours l’identité Git de la personne qui a fait la demande, à la fois comme auteur et comme committer. Par défaut, la ligne `Co-Authored-By: Control Center <hi@usectrl.dev>` crédite le compte GitHub `@usectrl` comme coauteur. Dans **Paramètres → Vous → Attribution des commits**, désactivez cette mention de coauteur sans changer votre identité. La règle de **Paramètres → Espace de travail → Général** prévaut et verrouille le commutateur personnel. L’attribution propre à Claude Code est toujours désactivée. La signature des commits nécessite toujours sa propre configuration valide
- Un terminal que vous ouvrez sur un rig reçoit votre propre connexion,
  restreinte à ce seul dépôt, de sorte que les poussées qui en partent sont les
  vôtres
- Quand aucun jeton ne peut être émis (personne de responsable n’est connecté,
  l’app n’est pas installée chez le propriétaire, ou l’installation est
  suspendue), l’exécution démarre sans jeton et ses notes expliquent pourquoi.
  Il n’y a aucun identifiant de repli

## Dépannage

### La liste des PR est vide et indique que GitHub n’est pas connecté

Vous n’êtes pas connecté à GitHub sur ce serveur. Cliquez sur **Se connecter à
GitHub** sous **Hébergement de code**. Les dépôts sur d’autres hébergeurs ne sont
pas touchés.

### La ligne GitHub indique que la connexion n’est pas configurée sur ce serveur

Le serveur n’a ni sa propre GitHub App ni Connect. Le propriétaire du serveur
choisit l’un ou l’autre dans **Paramètres → Serveur → Authentification
unique** : **Créer mon application GitHub** prend environ deux minutes. Voir
[Créer la GitHub App](/fr-CA/manuel/guides/github-app/).

### La boîte de dialogue indique que le code ne correspond pas

Tapez le code exactement comme le navigateur l’affiche : 8 lettres et chiffres.
Cinq codes erronés mettent fin à la connexion ; recommencez-la.

### La connexion indique que l’app n’est pas installée

La GitHub App n’a aucune installation sur le compte propriétaire du dépôt. Un
administrateur de l’espace de travail l’installe à partir de **Paramètres →
Espace de travail → Général → Installations de l’application GitHub**. Pour une
organisation sur l’App partagée de Control Center, un administrateur de cette
organisation pourrait devoir cliquer sur **Autoriser ce serveur**. Voir
[Créer la GitHub App](/fr-CA/manuel/guides/github-app/#autoriser-ce-serveur-pour-une-organisation).

### Tout le monde doit se reconnecter à GitHub

Le propriétaire du serveur a renouvelé la clé Connect du serveur, changé de
serveur Connect, ou le répertoire de données a été restauré sur une autre
machine. Les connexions par Connect sont liées au serveur qui les a établies.

### L’ajout d’un dépôt est refusé

L’enregistrement exige les trois conditions suivantes : le chemin se trouve à
l’intérieur d’un arbre de travail git, il possède un dépôt distant `origin`, et
ce dépôt distant pointe vers un hébergeur pris en charge (github.com, gitlab.com
ou bitbucket.org). Voir
[Ajouter des dépôts à un espace de travail](/fr-CA/manuel/guides/ajouter-des-depots/).

### Tout cesse de fonctionner pendant un certain temps après un usage intensif

C’est le coupe-circuit de limite de débit. GitHub signale sa limite principale par
un `403` portant `x-ratelimit-remaining: 0` et un moment de réinitialisation ; dès
qu’il en voit un, le client fait échouer localement les requêtes suivantes sans
appel réseau jusqu’à l’écoulement de la fenêtre, de sorte qu’une tempête de
nouvelles tentatives ne peut pas aggraver la limite. Les défaillances transitoires
sont réessayées jusqu’à trois fois avec un repli exponentiel, en tenant compte de
`retry-after`.
