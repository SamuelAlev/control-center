Ce guide vous montre comment lier votre identité de clavardage à votre utilisateur Control Center et comment délier cette liaison.

Chaque membre effectue cette opération une fois par fournisseur de clavardage. Elle est distincte de la connexion de l’application : la connexion rend le robot joignable pour tout l’espace de travail, tandis que la liaison vous rend _vous_ reconnaissable à l’intérieur de celui-ci.

## Pourquoi la liaison est requise

La passerelle refuse d’agir pour un compte de clavardage qu’elle ne peut pas résoudre à un membre de l’espace de travail. C’est délibéré : sans liaison, chaque message venu de Slack devrait être attribué à la personne qui a installé l’application, et la piste de vérification, les limites de débit par principal et les déclarants des tickets nommeraient tous la mauvaise personne.

Un membre non lié qui mentionne le robot reçoit une réponse dans ce fil Slack expliquant comment se lier. Rien n’est lancé.

## Lier avec un code

La liaison demande les deux côtés : envoyer un code à partir de Slack prouve le compte Slack, et le confirmer dans Control Center prouve que ce compte est le vôtre.

1. Allez dans **Paramètres → Vous → Profil** et repérez la carte **Comptes de messagerie liés**
2. Dans le bloc Slack, cliquez sur **Lier mon compte Slack**. La boîte de dialogue affiche un code à usage unique, par exemple :

```text
K7M2QP
```

3. Dans Slack, envoyez ce code au robot dans un **message direct** : le code seulement, rien d’autre
4. Le robot répond « Got it. Confirm this Slack account in Control Center to finish linking. » et la boîte de dialogue que vous avez laissée ouverte affiche le profil Slack qui a envoyé le code : son nom et son identifiant de membre Slack
5. Si c’est votre compte, cliquez sur **Confirmer**. La liaison est établie, la boîte de dialogue l’indique et le robot le confirme dans le même message direct
6. Si ce n’est pas le vôtre, cliquez sur **Refuser**. Rien n’est lié et le code cesse de fonctionner ; cliquez sur **Obtenir un nouveau code** pour réessayer

Fermer la boîte de dialogue ne fait pas perdre une revendication. Un code qui arrive plus tard attend sur la ligne **Lier mon compte Slack** de cette carte, avec les mêmes boutons **Confirmer** et **Refuser**.

Pourquoi cette étape de confirmation : sans elle, un code lu par-dessus votre épaule et envoyé à partir du compte Slack de quelqu’un d’autre ferait agir ce compte en votre nom. Vous seul pouvez confirmer, et seulement le profil exact qui a envoyé le code.

Le code :

- Est à usage unique et expire **15 minutes** après sa création
- Est toujours créé pour _vous_, jamais pour un coéquipier
- Ne fonctionne que dans un message direct au robot. Dans un canal, ce n’est qu’un message
- Ne peut être revendiqué que par un membre à part entière de l’espace de travail Slack où le robot est installé, pas par un invité ni par quelqu’un d’une autre organisation
- Remplace tout code que vous détenez déjà, donc appuyer de nouveau sur le bouton invalide le précédent
- Ne vit qu’en mémoire, donc un redémarrage du serveur invalide les codes en circulation — appuyez de nouveau sur le bouton

Un code inconnu, expiré, refusé ou créé pour un autre espace de travail échoue de la même façon indiscernable : « That code is not valid (or has expired). »

## Liaison automatique par courriel

Si votre profil Slack porte un courriel confirmé qui correspond au courriel vérifié d’un utilisateur Control Center qui est **déjà membre de cet espace de travail**, la passerelle vous lie la première fois que vous lui parlez. Aucun code n’est nécessaire.

Côté Control Center, le courriel est considéré comme vérifié lorsque l’authentification unique ou SCIM l’a défini, ou lorsque le propriétaire du serveur l’a confirmé dans **Paramètres → Serveur → Personnes**. Une adresse que vous avez saisie dans votre propre profil n’est pas vérifiée : elle ne lie donc rien tant que le propriétaire ne l’a pas confirmée. Utilisez le flux par code en attendant.

Les deux moitiés comptent : la correspondance de courriel prouve l’identité, mais seule l’appartenance accorde l’accès, donc un inconnu dont le courriel se trouve par hasard sur le serveur ne se lie à rien. La liste des comptes liés indique comment chaque liaison a été établie (« associé par courriel » ou « lié avec un code »).

La liaison automatique exige la portée `users:read.email`. Sans elle, Slack ne divulguera pas l’adresse et le parcours par code est la seule voie.

## Voir qui est lié

La liste des comptes liés relève de l’administration de l’espace de travail, donc elle vit dans la carte d’administration : **Paramètres → Espace de travail → Intégrations → Ponts de messagerie → Comptes liés**. Elle répertorie chaque membre lié de l’espace de travail, avec le compte Slack auquel chacun correspond et la façon dont la liaison a été établie.

Votre propre état se trouve dans **Paramètres → Vous → Profil** : la ligne **Lier mon compte Slack** affiche « Lié à _votre-identifiant-slack_ » une fois que vous êtes lié, et vous invite à établir la liaison lorsque vous ne l’êtes pas.

La liste et la revendication sont des abonnements en direct, parce que le changement se produit de l’autre côté : vous envoyez le code dans Slack, donc aucune requête de l’application ne peut rapporter la réponse.

## Délier

Cliquez sur **Délier** dans une ligne de la liste des comptes liés de l’espace de travail.

- Chacun peut se délier lui-même
- Seul un administrateur peut délier un autre membre
- Délier révoque aussi tout code de liaison en circulation pour ce membre

Après la dissociation, ce compte Slack ne peut plus diriger d’agents tant qu’il ne se lie pas de nouveau. Les espaces, les transcriptions et les tickets existants conservent leur attribution d’origine — délier n’est pas une rétractation du travail passé.

## Dépannage

### Le robot dit que je ne suis pas membre de cet espace de travail

Votre compte Slack est lié à un utilisateur Control Center, mais cet utilisateur ne détient aucune appartenance dans cet espace de travail. Demandez à un administrateur de vous inviter ; consultez [Multijoueur — identité, appartenance et présence](/fr-CA/manuel/concepts/multijoueur/).

### Le robot dit que mon rôle est en lecture seule

Les rôles `viewer` et `guest` ne peuvent pas lancer de travail. Un administrateur doit élever votre rôle à `member` ou plus.

### Le robot dit que le code n’est pas valide

Le code a expiré, a déjà été utilisé, a été refusé ou a été remplacé par un plus récent. Cliquez de nouveau sur **Lier mon compte Slack** et envoyez le nouveau code.

### Le robot traite mon code comme une demande

Vous l’avez envoyé dans un canal, ou votre compte Slack est déjà lié. Les codes ne sont acceptés que dans un message direct, et un message en forme de code venant d’un compte lié est une demande ordinaire.
