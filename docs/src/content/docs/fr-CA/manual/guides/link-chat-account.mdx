Ce guide vous montre comment lier votre identité de clavardage à votre utilisateur Control Center et comment délier cette liaison.

Chaque membre effectue cette opération une fois par fournisseur de clavardage. Elle est distincte de la connexion de l’application : la connexion rend le robot joignable pour tout l’espace de travail, tandis que la liaison vous rend _vous_ reconnaissable à l’intérieur de celui-ci.

## Pourquoi la liaison est requise

La passerelle refuse d’agir pour un compte de clavardage qu’elle ne peut pas résoudre à un membre de l’espace de travail. C’est délibéré : sans liaison, chaque message venu de Slack devrait être attribué à la personne qui a installé l’application, et la piste de vérification, les limites de débit par principal et les déclarants des tickets nommeraient tous la mauvaise personne.

Un membre non lié qui mentionne le robot reçoit une réponse dans ce fil Slack expliquant comment se lier. Rien n’est lancé.

## Lier avec un code

1. Allez à **Paramètres → Espace de travail → Profil et identité** et faites défiler jusqu’à la carte **Comptes de messagerie liés**
2. Dans le bloc Slack, cliquez sur **Lier mon compte Slack**
3. Copiez la commande qu’il affiche, par exemple :

```text
/cc link K7M2QP
```

4. Dans Slack, envoyez cette commande au robot — un message privé est l’endroit le plus simple
5. Le robot confirme en indiquant l’utilisateur Control Center auquel vous êtes maintenant lié, et la boîte de dialogue que vous avez laissée ouverte se met à jour pour le dire au même moment — vous n’avez pas à la fermer pour aller voir

Le code :

- Est à usage unique et expire **15 minutes** après sa création
- Est toujours créé pour _vous_, jamais pour un coéquipier
- Remplace tout code que vous détenez déjà, donc appuyer de nouveau sur le bouton invalide le précédent
- Ne vit qu’en mémoire, donc un redémarrage du serveur invalide les codes en circulation — appuyez de nouveau sur le bouton

Un code inconnu, expiré ou créé pour un autre espace de travail échoue de la même façon indiscernable : « ce code n’est pas valide (ou il a expiré) ».

## Liaison automatique par courriel

Si votre profil Slack porte un courriel vérifié qui correspond à un utilisateur Control Center qui est **déjà membre de cet espace de travail**, la passerelle vous lie la première fois que vous lui parlez. Aucun code n’est nécessaire.

Les deux moitiés comptent : la correspondance de courriel prouve l’identité, mais seule l’appartenance accorde l’accès, donc un inconnu dont le courriel se trouve par hasard sur le serveur ne se lie à rien. La liste des comptes liés indique comment chaque liaison a été établie (« associé par courriel » ou « lié avec un code »).

La liaison automatique exige la portée `users:read.email`. Sans elle, Slack ne divulguera pas l’adresse et le parcours par code est la seule voie.

## Voir qui est lié

La liste des comptes liés relève de l’administration de l’espace de travail, donc elle vit de l’autre côté de la surface : **Paramètres → Espace de travail → Général → Ponts de messagerie → Comptes liés**. Elle répertorie chaque membre lié de l’espace de travail, avec le compte Slack auquel chacun correspond et la façon dont la liaison a été établie.

Votre propre état se trouve sur votre page de profil : la ligne **Lier mon compte Slack** affiche « Lié à _votre-identifiant-slack_ » une fois que vous êtes lié, et vous invite à établir la liaison lorsque vous ne l’êtes pas.

La liste est un abonnement en direct, parce que le changement se produit de l’autre côté — vous tapez le code dans Slack, donc aucune requête de l’application ne peut rapporter la réponse.

## Délier

Cliquez sur **Délier** dans une ligne de la liste des comptes liés de l’espace de travail.

- Chacun peut se délier lui-même
- Seul un administrateur peut délier un autre membre
- Délier révoque aussi tout code de liaison en circulation pour ce membre

Après la dissociation, ce compte Slack ne peut plus diriger d’agents tant qu’il ne se lie pas de nouveau. Les espaces, les transcriptions et les tickets existants conservent leur attribution d’origine — délier n’est pas une rétractation du travail passé.

## Dépannage

### Le robot dit que je ne suis pas membre de cet espace de travail

Votre compte Slack est lié à un utilisateur Control Center, mais cet utilisateur ne détient aucune appartenance dans cet espace de travail. Demandez à un administrateur de vous inviter ; consultez [Multijoueur — identité, appartenance et présence](/fr-CA/manuel/concepts/multijoueur/).

### Le robot dit que mon rôle est en lecture seule

Les rôles `viewer` et `guest` ne peuvent pas lancer de travail. Un administrateur doit élever votre rôle à `member` ou plus.

### La commande slash n’est pas reconnue

Vérifiez que la commande slash existe dans Slack et que vous envoyez bien la commande que la boîte de dialogue des paramètres vous a montrée — un administrateur l’a peut-être renommée, auquel cas la boîte de dialogue affiche le nom actuel.
