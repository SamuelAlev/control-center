Ce guide vous montre comment travailler avec Control Center sans quitter GitHub :
demandez une révision par IA depuis la page de la PR, posez une question au robot
dans un commentaire et poursuivez la conversation dans ses fils de révision.

Les réponses passent par la voie GitHub de l’espace de travail : la
[GitHub App](/fr-CA/manuel/guides/github-app/) propre à votre serveur, ou l’App
partagée de Control Center au moyen de Connect. Rien de nouveau n’est enregistré,
et rien n’a besoin d’être accessible depuis Internet : le serveur découvre ce qui
a été dit sur GitHub par interrogation périodique, de sorte qu’un ordinateur
portatif derrière un NAT se comporte exactement comme un déploiement public.

## Prérequis

- L’espace de travail a une voie GitHub : la GitHub App propre au serveur ou
  Connect, avec l’app [installée](/fr-CA/manuel/guides/github-app/#installer-là-où-se-trouvent-vos-dépôts)
  sur le compte propriétaire du dépôt. Une app propre a besoin de **Pull
  requests** et **Issues** en lecture et écriture, ce que **Créer mon
  application GitHub** accorde déjà
- Le dépôt est lié à un espace de travail dans Control Center
- Vous êtes [connecté à GitHub](/fr-CA/manuel/guides/integration-github/) sur ce
  serveur, et vous pouvez pousser vers le dépôt
- Aucune URL de webhook, aucun tunnel, aucun rappel — il n’y a rien à configurer
  du côté du réseau

## Trouver le nom de votre robot

Mentionnez `@usectrl`, le compte GitHub réservé à Control Center. C’est le déclencheur par défaut ; la voie GitHub de votre espace de travail traite toujours la demande et publie les réponses. Vous n’avez pas besoin des identifiants du compte `usectrl`.

L’identifiant propre à l’application, `<appslug>[bot]`, et sa forme courte `@appslug` fonctionnent aussi. Pour trouver cet alias facultatif sur votre propre app :

1. Allez dans **Paramètres → Serveur → Authentification unique** et faites défiler
   jusqu’à la carte **Applications fournisseur**
2. Ouvrez le bloc **GitHub** et cliquez sur **Tester**
3. Copiez **Login du bot** une fois le champ rempli. S’il affiche encore l’indice
   vide, l’identifiant de connexion est toujours `<appslug>[bot]` — saisissez-le,
   ou la forme courte `@appslug`

GitHub ne propose pas les comptes d’application dans la saisie semi-automatique `@`; il faut donc taper ou copier leurs alias. Le compte dédié `@usectrl` est le moyen par défaut de lancer une demande; `@myapp` et `@myapp[bot]` restent tous deux acceptés comme alias de l’application.

:::note[Choisissez un nom d’application distinctif]
La forme courte est mise en correspondance comme du texte. Si un utilisateur
humain de GitHub partage par hasard le slug de votre application, mentionner cet
utilisateur par la forme courte joint aussi le robot. La forme complète
`@myapp[bot]` est toujours sans ambiguïté.
:::

## Demander une révision depuis GitHub

Deux façons, qui démarrent toutes deux le même pipeline `pr_review` préamorcé que
lance le bouton **Ask AI** :

- **Ajoutez l’étiquette `ai-review`** à la PR. C’est ce que GitHub offre de plus
  proche d’une affectation du robot comme relecteur — les comptes d’application ne
  peuvent pas occuper l’emplacement natif de relecteur demandé. Votre compte
  réagit à la PR avec 👀 et la révision démarre dans Control Center ; aucun
  commentaire n’est publié
- **Commentez `@usectrl review`** (ou simplement `@usectrl`) dans la conversation de la
  PR. Un 👀 apparaît sur votre commentaire, puis une réponse indique que la
  révision a démarré (ou qu’une révision est déjà en cours)

Les relecteurs travaillent dans l’espace de révision de la PR ; lisez et publiez
les constats comme dans [Utiliser la révision assistée par
IA](/fr-CA/manuel/guides/revision-par-ia/). La publication vers GitHub demeure une
décision que vous prenez dans Control Center — lancer une révision depuis GitHub
ne publie rien sur GitHub en soi.

L’étiquette se déclenche une seule fois par PR : l’ajouter constitue la demande,
et elle n’est pas réarmée si on la retire puis la remet. Pour relancer une
révision — après un push, par exemple —, mentionnez le robot.

## Poser une question

Commentez dans la conversation de la PR :

```text
@usectrl why does the flaky test in runner_test.dart fail on CI but not locally?
```

Ce qui se passe, dans l’ordre :

1. Un 👀 apparaît sur votre commentaire, venant de votre propre compte, ce qui
   vous confirme que le commentaire a été vu
2. La question est publiée dans l’espace de révision de la PR **en votre nom** —
   la même attribution que si vous l’aviez saisie dans Control Center
3. Un agent répond dans l’espace, et la réponse est publiée dans la PR. Chaque
   réponse commence par `**Control Center** (for @your-login):`

Une question sur une PR encore sans révision réveille l’agent principal (CEO) de
l’espace de travail ; une fois qu’une révision a eu lieu, c’est l’agent qui a parlé
en dernier qui répond, de sorte que les relances aboutissent chez la personne qui
a le contexte.

## Donner suite dans un fil de révision

Répondez dans un fil de révision en ligne auquel le robot participe — un
commentaire de diff qu’il a laissé, ou une réponse qu’il a publiée dans ce fil.
Aucune mention n’est nécessaire ; le fil **est** l’adressage :

```text
> @usectrl the retry loop looks O(n²) to me

what would the complexity be with the bounded queue instead?
```

Les échanges à plusieurs tours fonctionnent de la même façon : chaque réponse est
une nouvelle question dans la même conversation, avec l’espace de révision comme
contexte, et la réponse revient dans le fil.

Une relance dans la chronologie de la conversation de la PR constitue un nouveau
commentaire de premier niveau ; elle a donc toujours besoin d’une @mention.

## À qui le robot parle

Le serveur résout l’auteur d’un commentaire, ou la personne qui a ajouté
l’étiquette `ai-review`, avant de faire quoi que ce soit :

- **Le compte GitHub doit être connecté** sur ce serveur. La correspondance se
  fait sur l’identifiant numérique du compte GitHub, jamais sur l’identifiant de
  connexion. Connectez-vous à partir de **Paramètres → Espace de travail → Profil
  et identité → Hébergement de code**
- **La personne doit être membre avec un rôle d’écriture** (`member`, `admin` ou
  `owner`) dans l’espace de travail qui lie le dépôt
- **La personne doit pouvoir pousser** vers le dépôt sur GitHub. Les réponses
  utilisent un jeton limité aux accès de cette personne, de sorte qu’une personne
  qui ne peut que lire n’obtient aucune réponse

Toute autre personne est ignorée en silence : rien n’est publié, et ses propos
n’entrent jamais dans l’espace de travail. Les commentaires des robots, et les
propres réponses de Control Center, ne sont jamais traités comme des questions.

### Deux serveurs, une PR

Le 👀 est aussi la façon dont les serveurs s’entendent sur celui qui répond. Il
est ajouté avec la connexion propre à l’auteur, et GitHub indique au serveur si
cette réaction est nouvelle. Si vous êtes connecté sur deux serveurs Control
Center qui lient tous deux le dépôt, le premier à réagir répond et l’autre garde
le silence. Il en va de même pour l’étiquette.

## À quoi s’attendre

| Élément                  | Comportement                                                             |
| ------------------------ | ------------------------------------------------------------------------ |
| Accusé de réception      | 👀 de votre compte sur le commentaire (ou sur la PR, pour l’étiquette), en un balayage |
| Réponses                 | Publiées dans la voie où la question a été posée, en commençant par `**Control Center** (for @your-login):`. Avec une app propre, l’auteur est le robot de l’app ; au moyen de Connect, c’est votre compte, qui agit par l’App partagée |
| Attribution dans l’espace | La question est la vôtre ; l’agent s’exécute en votre nom, selon les réglages d’autonomie de l’espace |
| Révisions                | Les constats arrivent dans l’espace de révision ; la publication vers GitHub est manuelle |

Un balayage s’exécute chaque minute avec une app propre et vérifie jusqu’à
25 demandes de tirage ; au moyen de Connect, il s’exécute toutes les deux minutes
et en vérifie jusqu’à 10, parce que ces appels partagent le quota GitHub propre à
chaque membre. Un espace de travail dont le quota GitHub est sous 15 % est ignoré
jusqu’à ce qu’il se rétablisse. Le délai est le prix à payer pour n’avoir besoin
d’aucun accès réseau entrant. Rien n’est perdu pendant que le serveur est hors
ligne — un commentaire qui arrive pendant l’arrêt est rattrapé au balayage
suivant.

## Dépannage

**Rien ne se produit pour un commentaire qui mentionne le robot.**

- L’application est-elle **installée** sur le compte qui possède le dépôt, et le
  dépôt est-il **lié** à un espace de travail ? Un dépôt non lié est ignoré avant
  que quoi que ce soit soit consigné, donc le lier plus tard livre quand même le
  commentaire
- Êtes-vous connecté à GitHub sur ce serveur, membre avec un rôle d’écriture, et
  en mesure de pousser vers le dépôt ? Le serveur ignore toute autre personne
  sans répondre
- Avec l’App partagée de Control Center, l’installation de l’organisation est-elle
  autorisée pour ce serveur ? Voir
  [Autoriser ce serveur pour une organisation](/fr-CA/manuel/guides/github-app/#autoriser-ce-serveur-pour-une-organisation)
- Toujours rien ? Le journal du serveur nomme le balayage et la PR quand quelque
  chose échoue ; cherchez `pr_conversation:` (l’interrogateur périodique) et
  `github_pr_conversation:` (la passerelle)

**L’étiquette ne démarre pas de révision.**

Elle se déclenche une seule fois par PR, et la personne qui l’a ajoutée passe
les mêmes vérifications que l’auteur d’un commentaire. Si une révision a déjà eu
lieu, ou si l’étiquette a été ajoutée avant que le serveur ait vu la PR (le
premier balayage consigne l’arriéré en silence plutôt que de le déclencher d’un
coup), mentionnez plutôt le robot — `@usectrl review` en démarre toujours une, à
moins qu’une révision soit déjà en cours.

**La réponse du robot n’est jamais arrivée sur GitHub.**

La réponse elle-même n’est jamais perdue — elle se trouve dans l’espace de
révision de la PR, dans Control Center. Un échec de publication (GitHub
indisponible, permissions modifiées) est consigné et la réponse n’est pas
réessayée ; reposez la question dans le fil si cela compte.
