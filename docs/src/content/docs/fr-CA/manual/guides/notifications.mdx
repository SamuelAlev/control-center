Ce guide explique comment configurer les notifications et ce que chaque réglage
contrôle vraiment.

Les notifications arrivent sur deux surfaces. Le **centre de notifications** — la
cloche de la barre de titre — lit un fil persistant par espace de travail sur le
serveur. Les **toasts du système d’exploitation** forment une voie distincte,
réservée au bureau, alimentée par les trames en direct que pousse le serveur.

:::note[La version web n’affiche aucune notification du système d’exploitation]
La chaîne de traitement des toasts n’est construite que par l’amorçage du
bureau. Sur `app.usectrl.dev`, il n’y a ni toasts du système d’exploitation, ni
sons de notification, ni bannières d’ambiance — la cloche et son historique
fonctionnent quand même, parce qu’ils lisent le fil du serveur. Le client mobile
n’a aucune surface de notification.
:::

## Activer ou désactiver des catégories

1. Allez dans **Paramètres → Vous → Notifications**
2. Laissez **Activer les notifications** activé
3. Activez ou désactivez les catégories voulues. Il y en a exactement seize :

| Catégorie | Se déclenche quand |
| ------------------------- | -------------------------------------------------------------------------- |
| Agent terminé | Un agent a terminé une exécution |
| PR publiée | Un agent a publié une PR |
| PR fusionnée | Une PR a été fusionnée |
| Nouveaux messages | Un message est arrivé dans un espace que vous ne regardez pas |
| Mentionné dans une pull request | Le sondage de notifications de GitHub a vu que vous étiez mentionné sur une PR |
| Revue demandée | Votre revue a réellement été demandée sur une pull request qui n’est pas un brouillon |
| Revue obsolète | De nouveaux commits sont arrivés sur une pull request que vous aviez déjà révisée |
| Prêt à fusionner | Une pull request dont vous êtes l’auteur est devenue fusionnable, ou a cessé de l’être |
| Décisions de revue | Un réviseur a approuvé, demandé des changements, ou a vu une approbation rejetée |
| Vérifications | La CI a échoué sur une pull request dont vous êtes l’auteur, ou s’est rétablie |
| Fils de revue | Quelqu’un a répondu dans un fil où vous êtes, ou l’a résolu |
| Ticket assigné | Un ticket a été assigné |
| Statut du ticket modifié | Un ticket a changé de statut |
| Réunion imminente | Une réunion du calendrier entre dans votre fenêtre d’anticipation |
| Calendrier déconnecté | Le jeton OAuth d’un calendrier connecté a expiré |
| Mises à jour des enclos | Un enclos a été repris, récupéré ou a échoué |

Tout ce qui ne figure pas dans cette liste ne peut être ni notifié ni filtré —
il n’existe pas de catégorie « tout le reste ».

Ces préférences suivent votre utilisateur d’un appareil à l’autre, de sorte
qu’un téléphone et un ordinateur portatif restent synchronisés. Le volume est
l’exception délibérée et reste propre à chaque appareil.

## Définir les heures de silence

1. Sur la même page, activez **Quiet hours**
2. Saisissez une heure de début et une heure de fin au format `HH:MM` (la plage
   par défaut est 22:00–08:00)

Pendant les heures de silence, les notifications non urgentes sont écartées —
ni mises en file, ni rejouées plus tard.

Deux catégories sont **urgentes** et sont toujours livrées, en contournant les
heures de silence _et_ le mode focus : **Réunion imminente** et **PR publiée**.
Une alerte de réunion que vous ne voyez qu’après coup ne vaut rien, et c’est
précisément la raison.

## Choisir un son

1. Faites défiler jusqu’à **Son de notification**
2. Choisissez l’un des onze sons inclus, ou **Aucun**
3. Appuyez sur le bouton **Tester** pour l’entendre et réglez le volume avec le
   curseur

L’application joue le son elle-même ; la notification du système d’exploitation
est livrée silencieusement, de sorte que vous ne l’entendez jamais deux fois.

## Définir le délai d’anticipation des réunions

1. Faites défiler jusqu’à **Délai d’alerte**
2. Choisissez **5**, **10**, **15** ou **30** minutes

C’est le délai avant un événement du calendrier auquel la notification
**Réunion imminente** se déclenche. La valeur par défaut est 5 minutes.

## Savoir quand une notification est supprimée

Une notification est écartée, en silence, lorsque l’une des conditions suivantes
est vraie :

- Les notifications sont désactivées globalement, ou leur catégorie l’est
- Vous êtes déjà sur la route vers laquelle elle vous mènerait — et, pour un
  message, déjà dans cet espace
- Le mode focus est actif et la catégorie n’est pas urgente
- Les heures de silence sont actives et la catégorie n’est pas urgente

Ces vérifications s’appliquent aux toasts du système d’exploitation. La cloche
persistante enregistre quand même l’événement.

Deux autres suppressions se trouvent plus en amont, dans ce que le serveur envoie
du tout :

- Un message d’un autre **humain** où vous n’êtes pas mentionné ne devient jamais
  une notification
- Les espaces entre agents sont en sourdine dans la barre latérale, de sorte
  qu’ils n’incrémentent jamais la pastille de non-lus des humains

À l’intérieur d’un espace, il n’y a aucun coin tranquille : chaque conversation
notifie de la même façon, fils compris. L’état de lecture est propre à l’espace,
de sorte que les non-lus s’agrègent entre les conversations d’un espace plutôt
que d’être suivis par conversation.

## Lire et vider le centre de notifications

1. Cliquez sur la cloche de la barre de titre

Le volet volant montre l’activité récente et relie chaque entrée par un lien
direct à ce dont elle parle. L’ouvrir ne marque **pas** tout comme lu — utilisez
**Tout marquer comme lu** dans l’en-tête, ou marquez une seule ligne. L’état de
lecture suit votre utilisateur d’un appareil à l’autre.

:::note[Tout effacer est un filigrane, pas une suppression]
**Tout effacer** pose un filigrane propre à chaque utilisateur qui masque tout ce
qui est plus ancien ; les lignes restent. Par ailleurs, chaque espace de travail
ne conserve que ses **200** lignes de fil les plus récentes, élaguées à mesure
que de nouvelles arrivent, tandis que la cloche s’abonne aux **50** plus récentes
et que le volet volant en liste jusqu’à **15**. L’historique au-delà est perdu,
peu importe l’état de lecture.
:::

## Dépannage

### Aucune notification du système d’exploitation sur macOS

L’autorisation est demandée nativement au lancement de l’application. Si vous
l’avez refusée, réactivez Control Center dans Réglages Système → Notifications ;
il n’y a aucune invite dans l’application pour la redemander.

### Rien n’arrive dans la version web

C’est normal — la version web n’a aucune chaîne de traitement de notifications du
système d’exploitation. Utilisez la cloche.

### La pastille de la cloche indique zéro alors qu’il y a clairement de l’activité nouvelle

Jusqu’à ce que le flux de marques de lecture se résolve après la connexion, les
entrées s’affichent comme lues pour éviter une pastille qui clignote puis se
vide. Tout se stabilise dès que la marque est chargée.

### L’exécution d’un agent s’est terminée sans que rien ne m’avertisse

Vérifiez que vous n’étiez pas déjà dans l’espace où elle a eu lieu — une route
active supprime son propre toast du système d’exploitation.
