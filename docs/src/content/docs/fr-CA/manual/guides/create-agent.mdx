Ce guide explique comment ajouter un agent à un espace de travail et le configurer jusqu’à ce qu’il puisse réellement s’exécuter.

Chaque espace de travail est amorcé avec cinq agents — un CEO plus `qa`, `architect`, `engineer` et `librarian` —, de sorte que vous avez habituellement des agents avant même d’en avoir configuré un seul. Les étapes ci-dessous s’appliquent tout autant à un agent amorcé qu’à un nouvel agent.

## Avant de commencer

- Vous êtes à l’intérieur d’un espace de travail. Toute cette surface se trouve dans **Paramètres → Espace de travail → Agents** (`/settings/workspace/agents`).
- L’agent aura besoin d’un backend. Connectez un fournisseur pour le harnais intégré sous **Paramètres → Serveur → Fournisseurs de modèles**, ou installez la CLI Claude Code sur la machine qui héberge `cc_server`.
- Si vous voulez que l’agent porte des skills, installez-les d’abord sous **Paramètres → Espace de travail → Compétences**. Le formulaire de l’agent ne permet d’activer ou de désactiver que les skills qui existent déjà dans l’espace de travail.

## Ajouter l’agent

1. Ouvrez **Paramètres → Espace de travail → Agents**.
2. Cliquez sur **Nouvel agent**.

Il n’y a ni boîte de dialogue ni sélecteur de rôle. Un agent nommé « Agent sans nom » est créé immédiatement et sélectionné dans le volet de détail à droite.

Vous devriez maintenant voir « Agent sans nom » dans la liste à gauche, l’onglet **Paramètres** de son volet de détail ouvert et un champ **Nom** contenant « Agent sans nom ».

## Nommer l’agent

- **Nom** — l’identifiant court utilisé dans les mentions avec @, par exemple `alice`. L’analyse des mentions reconnaît `@` suivi de caractères de mot, de sorte qu’un nom contenant un trait d’union, un point ou un espace ne peut jamais être mentionné.
- **Titre** — l’étiquette lisible par un humain, par exemple « Développeur principal ».
- **Prompt système** — des instructions supplémentaires facultatives, injectées sous forme de section « Agent instructions » ; elles ne remplacent pas le reste du prompt assemblé.

Cliquez sur **Enregistrer les modifications** au bas du formulaire. Tous les champs de cette page sont enregistrés par ce seul bouton.

## Lui attribuer un adaptateur et un modèle

La liste déroulante **Adaptateur** répertorie les exécuteurs dont l’hôte du serveur dispose réellement. L’adaptateur intégré est toujours détecté (c’est le serveur). Claude Code n’apparaît que lorsque sa CLI a été détectée sur cet hôte :

| Adaptateur                | Backend                                     |
| ------------------------- | ------------------------------------------- |
| Control Center (built-in) | La boucle d’agent dans le processus — aucune CLI externe |
| Claude Code               | `claude -p --output-format stream-json`     |

Seul l’adaptateur intégré applique les modes, le pilotage en cours d’exécution, la mise en pause et la reprise, les contrats d’achèvement et les sous-agents. Claude Code n’offre rien de tout cela. Cursor, Codex et les autres fournisseurs de modèles se rattachent à l’adaptateur intégré, et non comme exécuteurs distincts.

:::note[Un adaptateur vide signifie la boucle intégrée]
Un agent dont l’adaptateur n’est pas défini est lancé vers **Control Center (built-in)**, la boucle à l’intérieur du serveur, de sorte que rien n’a besoin d’être installé sur l’hôte. Comme aucun modèle n’est défini non plus, il demande à Anthropic sa valeur par défaut, de sorte qu’un agent entièrement non défini ne s’exécute que si vous avez connecté un compte Anthropic. Les spécialistes amorcés sont livrés sans l’un ni l’autre ; définissez les deux sur tout agent que vous comptez utiliser.
:::

La liste déroulante **Modèle** est dictée par l’adaptateur que vous avez choisi. Pour l’adaptateur intégré, la liste provient en direct des fournisseurs que vous avez connectés sous **Paramètres → Serveur → Fournisseurs de modèles**, de sorte qu’un fournisseur sans identifiant enregistré ne fournit aucun modèle.

## Ajouter des skills

**Compétences** est un sélecteur à puces parmi les ensembles de skills installés dans cet espace de travail. Touchez une puce pour l’activer ou la désactiver ; le glyphe de coche marque celles qui sont sélectionnées. Si l’espace de travail n’a aucun skill, le champ affiche « No skills available. Create skills in Settings → Skills first. »

Vous ne choisissez pas ici les skills propres à un dépôt. Un dépôt qui en fournit (dans `.agents/skills/`, `.claude/skills/` ou `.opencode/skills/`) les attribue automatiquement à l’agent qui travaille dans ce dépôt, et ils sont remplacés lorsque celui-ci passe à un autre — voir [Skills à portée de dépôt](/fr-CA/manuel/concepts/modele-agent/#repo-scoped-skills).

## Définir le rattachement hiérarchique et la persona

- **Rapporte à** — choisissez un autre agent par son nom. Cela construit l’arbre de rattachement affiché par le bouton **Organigramme** dans l’en-tête de la page. Ce n’est pas la liste dont se sert un chef d’équipe lorsqu’il délègue — celle-ci provient des membres de l’équipe et de leurs skills.
- **Persona** — texte libre qui façonne le ton et le comportement, par exemple : « Préfère les solutions simples et lisibles. Écrit des tests pour tout nouveau code. »

## Régler l’exécution

- **Effort de raisonnement** — les options proviennent des niveaux publiés du modèle sélectionné : Low / Medium / High, plus Extra High sur les modèles de style OpenAI et Extra High + Max sur ceux de style Claude. Le champ est entièrement masqué lorsque le modèle sélectionné ne déclare aucun niveau de réflexion, et il prend par défaut la valeur propre au modèle.
- **Taille de la fenêtre de contexte** — préremplie à partir de la fenêtre de contexte du modèle chaque fois que vous changez de modèle, avec des puces en un clic pour la valeur par défaut du modèle, 200k, 500k et 1M. Une valeur que vous saisissez après avoir choisi le modèle l’emporte jusqu’au prochain changement de modèle.
- **Délai de silence (minutes)** — interrompt une exécution après ce délai sans sortie. Laissez le champ vide pour utiliser la valeur par défaut propre au mode.

## Accorder des permissions

**Permissions du sandbox** démarre sur « Utiliser la valeur par défaut de l’espace de travail ». Activez le commutateur pour les définir pour cet agent, puis basculez :

- **Autoriser git push** — injecte le jeton GitHub dont l’agent a besoin pour pousser
- **Autoriser les appels API GitHub** — permet à l’agent de lire les PR, les issues et les métadonnées du dépôt
- **Autoriser les appels API de tickets** — injecte la clé du fournisseur de tickets
- **Autoriser l’accès réseau général** — active aussi les outils `web_fetch` et `web_search` du harnais intégré

Chaque commutateur est vérifié par le courtier d’identifiants au lancement de l’exécution : une capacité désactivée signifie simplement que le jeton correspondant n’est jamais injecté dans l’environnement de l’exécution.

:::caution[La valeur par défaut de l’espace de travail correspond à l’ensemble conservateur du serveur]
Un agent laissé sur « Utiliser la valeur par défaut de l’espace de travail » s’exécute avec git push, l’API GitHub et les tickets tous **désactivés** et le réseau **activé**. Les valeurs par défaut des capacités affichées sous Paramètres → Serveur → Diagnostics et confidentialité sont une préférence côté client. Si vous voulez qu’un agent pousse ou ouvre des PR, activez le commutateur et accordez les capacités explicitement.

Ces capacités contrôlent l’accès aux identifiants et aux outils du harnais, ce qui constitue une couche distincte du bac à sable du système d’exploitation. `cc_server` enveloppe les exécutions d’agent dans le bac à sable de l’hôte lorsqu’il en existe un — Windows n’a aucun backend natif, et Linux et WSL2 ont besoin de `bwrap` et de `socat`. Voir [Bac à sable et sécurité](/fr-CA/manuel/concepts/bac-a-sable-et-securite/) pour l’ensemble des frontières.
:::

## Vérifier qu’il s’exécute

1. Ouvrez **Paramètres → Serveur → Fournisseurs de modèles** et confirmez que l’adaptateur que vous avez choisi signale une version installée plutôt que « Non trouvé ». Cliquez sur **Actualiser** pour relancer la sonde — la sonde s’exécute sur la machine qui héberge `cc_server`, et non sur celle que vous regardez.
2. Ouvrez un espace avec l’agent et envoyez-lui un message, ou mentionnez-le avec @ dans un espace existant.
3. Revenez à **Paramètres → Espace de travail → Agents**, sélectionnez l’agent et ouvrez son onglet **Journaux**. Une exécution devrait apparaître avec un badge d’état, une durée, une heure de début et l’adaptateur qu’elle a utilisé. **Vue** ouvre le flux d’événements de cette exécution.

Si aucune exécution n’apparaît du tout, consultez [Diagnostiquer un agent](/fr-CA/manuel/guides/diagnostiquer-agent/).

## Supprimer un agent

Sélectionnez-le dans la liste. Dans l’onglet **Paramètres**, faites défiler jusqu’à la **Zone sensible** au bas du formulaire et cliquez sur **Supprimer**.
