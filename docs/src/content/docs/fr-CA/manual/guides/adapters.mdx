Ce guide vous montre comment connecter des fournisseurs de modèles et choisir
ce sur quoi un agent s'exécute.

Tout ce qui suit se trouve sur une seule page : **Paramètres → Serveur →
Fournisseurs de modèles**. L'entrée de la sous-barre latérale indique
« Fournisseurs de modèles » ; le titre de la page indique « Adaptateurs ».

## Qu'est-ce qu'un adaptateur

Un adaptateur est l'*exécuteur* qui exécute un tour d'agent. Il y en a deux et
la liste est fixe — vous ne pouvez pas en ajouter un troisième.

| Adaptateur                | CLI      | Transport                                                     |
| ------------------------- | -------- | ------------------------------------------------------------- |
| Control Center (built-in) | aucun    | Boucle d'agent en processus, qui parle aux fournisseurs par HTTP |
| Claude Code               | `claude` | `claude -p --output-format stream-json`                       |

Cursor, Codex, Anthropic, OpenAI et les autres sont des **fournisseurs** de
l'adaptateur intégré, et non des CLI distinctes. Ce que vous *pouvez* ajouter,
c'est un autre fournisseur — tout point de terminaison compatible avec OpenAI ou
Anthropic. C'est l'objet de la section suivante.

:::note[La détection sonde le serveur, et non votre machine]
La carte **Exécuteurs détectés** liste ce que `cc_server` a trouvé dans le
`PATH` de l'*hôte du serveur*. Sur un client léger ou web, il s'agit d'une
machine différente de celle que vous regardez. Installez la CLI sur la machine
qui exécute `cc_server`.
:::

## Connecter un fournisseur de modèles

L'adaptateur intégré a besoin d'au moins un fournisseur connecté avant de
pouvoir s'exécuter. Le catalogue en compte quatorze.

1. Allez dans **Paramètres → Serveur → Fournisseurs de modèles**
2. Faites défiler jusqu'à **Fournisseurs et modèles**
3. Trouvez votre fournisseur et connectez-le :

| Fournisseur                                                                                              | Comment se connecter                                                                                                          |
| -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Anthropic                                                                                                | Clé API. Un abonnement Claude Pro/Max n'est pas une connexion à l'API Anthropic — utilisez l'adaptateur Claude Code pour ce forfait |
| OpenAI, Codex, Cursor                                                                                    | Connexion OAuth dans le navigateur ou clé API. Codex est ChatGPT Plus/Pro par l'entremise du backend Codex Responses, et non un processus CLI lancé |
| Kimi Code                                                                                                | OAuth dans le navigateur uniquement — un flux par code d'appareil. C'est un forfait à tarif fixe, donc aucun prix par jeton    |
| OpenRouter, Groq, Google Gemini, DeepSeek, Mistral, xAI, z.ai, z.ai GLM Coding Plan, Moonshot (Kimi API) | Clé API                                                                                                                       |

Point de contrôle : le badge de la ligne passe à connecté et, en la dépliant,
elle liste les modèles que ce fournisseur sert, chacun avec son prix par million
de jetons et sa fenêtre de contexte.

Les jetons OAuth atterrissent dans le magasin d'identifiants du serveur lui-même
et sont rafraîchis avant leur expiration. Les identifiants des fournisseurs sont
**globaux à l'hôte** — ils sont partagés par chaque espace de travail de
l'installation, et non réservés à un seul.

### Ajouter un fournisseur personnalisé

Servez-vous de cette option pour Ollama, LM Studio, vLLM ou un déploiement
privé.

1. Dans **Fournisseurs et modèles**, sous **Fournisseurs personnalisés**, appuyez
   sur **Ajouter un fournisseur**
2. Renseignez un **nom**, choisissez le **type d'API** (compatible OpenAI ou
   compatible Anthropic) et fournissez l'**URL de base** (par exemple
   `http://localhost:11434/v1`)
3. Ajoutez une **clé API** si le point de terminaison en exige une, puis appuyez
   sur **Ajouter un fournisseur**

Un fournisseur personnalisé apparaît dans la même liste, avec un bouton de
suppression que ses pairs intégrés n'ont pas.

## Choisir un modèle pour un agent

1. Allez dans **Paramètres → Espace de travail → Agents** et sélectionnez l'agent
2. Dans l'onglet **Paramètres**, choisissez l'**adaptateur**
3. Choisissez le **modèle** dans la liste déroulante à côté

Pour l'adaptateur intégré, la liste déroulante est assemblée en direct à partir
du catalogue de chaque fournisseur connecté. Un fournisseur sans identifiant
enregistré ne contribue aucun modèle, et c'est pourquoi une liste déroulante vide
signifie presque toujours « rien de connecté pour l'instant » plutôt que « rien
de disponible ».

:::note[models.dev est un enrichissement, jamais une source d'identifiants]
Le catalogue [models.dev](https://models.dev) fourni donne le prix et la fenêtre
de contexte d'un modèle qui figure déjà dans la liste en direct. Il n'ajoute
jamais d'identifiant de modèle. Si un modèle que vous attendez est absent, le
point de terminaison du fournisseur ne le renvoie pas.
:::

Les identifiants de modèle de l'adaptateur intégré sont qualifiés
`provider/model` et peuvent comporter une chaîne de repli séparée par des `|`.
En cas de repli, le coût est calculé selon le modèle qui a réellement servi le
tour, et non celui que vous aviez demandé.

:::note[Un agent sans adaptateur s'exécute sur la boucle intégrée]
Chaque espace de travail est amorcé avec cinq agents — un CEO plus `qa`,
`architect`, `engineer` et `librarian` — sans adaptateur ni modèle. Le lancement
retombe sur **Control Center (built-in)**, et non sur le réglage **Exécuteurs par
défaut** de cette page, qui est une préférence de client que le chemin de
lancement ne lit jamais. Le journal d'exécution consigne `cc-harness` pour ces
exécutions, de sorte que la transcription nomme ce qui s'est réellement exécuté.

Sans modèle non plus, la boucle intégrée demande à Anthropic son modèle par
défaut. Un agent entièrement non configuré s'exécute donc si vous avez connecté
un compte Anthropic, et échoue autrement avec
`No credential for provider "anthropic"`.

Lorsque vous terminez l'étape Adaptateur de la configuration initiale, la paire
que vous avez choisie est appliquée rétroactivement à **chaque** agent à qui il
manque encore un adaptateur ou un modèle — CEO et spécialistes, dans chaque
espace de travail qui existe à ce moment-là. Les espaces de travail créés plus
tard amorcent encore les cinq agents sans configuration. Définissez explicitement
l'adaptateur et le modèle de chaque agent que vous comptez utiliser.
:::

## Installer une CLI d'exécuteur

L'adaptateur intégré ne nécessite aucune installation. Pour Claude Code,
installez sa CLI **sur l'hôte du serveur** avec le gestionnaire de paquets propre
à cet outil, par exemple :

```bash
npm install -g @anthropic-ai/claude-code
```

Appuyez ensuite sur **Actualiser** en haut de la page. Chaque ligne détectée
affiche la version et le chemin résolus, ainsi que des pastilles indiquant si
l'outil prend en charge le mode JSON et la sélection de modèle.

Une CLI externe conserve ses propres identifiants, dans sa propre configuration,
sur l'hôte du serveur. Control Center ne les gère pas.

:::caution[Les arguments d'adaptateur et les variables d'environnement restent sur cet appareil]
Chaque ligne d'adaptateur offre un champ **Arguments** et une boîte de dialogue
**Variables d'environnement**. Ces valeurs sont stockées sur votre appareil. Le
serveur lit l'argv de lancement et l'env depuis son propre magasin de paramètres.
Placez les clés de fournisseur sur le serveur (OAuth ou le champ de clé sur la
page Fournisseurs de modèles), et non dans ces deux champs.
:::

## Restreindre les fournisseurs qu'un espace de travail peut utiliser

La gouvernance des fournisseurs est propre à chaque espace de travail et la
dernière correspondance l'emporte.

1. Dans **Fournisseurs et modèles**, désactivez l'interrupteur **Autoriser** d'une
   ligne de fournisseur

Cela écrit une instruction `deny` pour ce fournisseur dans l'espace de travail
actif, et ses modèles disparaissent du catalogue de cet espace de travail.
Réactiver l'interrupteur supprime l'instruction.

## Dépannage

### Un exécuteur apparaît comme introuvable

- Vérifiez que la CLI se trouve dans le `PATH` de l'**hôte du serveur**, et pas
  seulement dans le vôtre
- Une application de bureau lancée par l'interface graphique démarre son serveur
  avec un `PATH` minimal ; une CLI installée dans un chemin réservé au shell peut
  lui être invisible
- Appuyez sur **Actualiser** après l'installation

### La liste déroulante des modèles est vide

- L'adaptateur est celui intégré et aucun fournisseur n'est connecté —
  connectez-en un dans **Fournisseurs et modèles**
- Ou bien le fournisseur est connecté, mais refusé par l'interrupteur de
  gouvernance de cet espace de travail

### Un modèle s'exécute, mais le prix s'affiche comme inconnu

La liste de modèles en direct contient l'identifiant ; le prix et le contexte
proviennent de models.dev. Un modèle tout nouveau, ou issu d'un fournisseur
personnalisé, n'a pas encore de fiche au catalogue.
