Ce guide porte sur le démarrage d’une exécution à la main. Pour en surveiller
une, lire la sortie des étapes et vous remettre d’un échec, consultez
[Surveiller les exécutions de pipeline](/fr-CA/manuel/guides/surveiller-pipelines/).

## Démarrer une exécution

1. Cliquez sur **Pipelines** dans la barre latérale de l’espace de travail.
2. Appuyez sur **Exécuter le pipeline** dans l’en-tête. Vous arrivez au
   sélecteur d’exécution (`/workspaces/<workspace-id>/pipelines/run`).
3. Choisissez un modèle dans la colonne de gauche. Chaque carte affiche le nom du
   modèle, sa description et s’il accepte des entrées.
4. Remplissez le formulaire d’entrée à droite. Les champs obligatoires bloquent le
   bouton tant qu’ils n’ont pas de valeur; un modèle sans entrée le signale.
5. Appuyez sur **Exécuter le pipeline**.

Vous arrivez à la page de détail de l’exécution, avec la cascade des durées et le
canevas du graphe en direct.

## Si la colonne est vide

Le sélecteur d’exécution n’affiche un modèle que lorsque **les deux** conditions
suivantes sont réunies :

- L’interrupteur du modèle est activé dans **Paramètres → Espace de travail →
  Modèles de pipeline**.
- **Autoriser l’exécution manuelle** est activé dans la boîte de dialogue
  **Exécution manuelle** de l’éditeur de modèle — c’est cet interrupteur qui crée
  le déclencheur `manual` que lit le sélecteur d’exécution.

Huit des treize modèles intégrés sont livrés désactivés : `external_pr_welcome`,
`cross_review`, `ticket_to_pr`, `pr_triage`, `pre_merge_gate`, `release_notes`,
`dep_audit` et `pr_digest`. Le moteur refuse de démarrer un modèle désactivé;
activez donc son interrupteur avant de le chercher ici.

Il n’existe aucune action **Exécuter** propre à un modèle dans la liste des
modèles, ni de bouton d’exécution dans l’éditeur — le sélecteur d’exécution est
le seul point d’entrée manuel.

## Remplir une entrée de dépôt

Une entrée de type **Dépôt** affiche un sélecteur parmi les dépôts enregistrés de
l’espace de travail. En choisir un remplit `repo_id`, `repo_local_path`,
`repo_full_name` et — lorsque le dépôt a un dépôt distant GitHub — `repo_owner`
et `repo_name` dans la charge utile de l’exécution, de sorte que les étapes en
aval puissent lire ceux dont elles ont besoin.

## Suivre l’exécution

La page de détail de l’exécution comporte trois parties : un bandeau de
métadonnées (heure de début, durée active, progression des étapes, un bandeau
d’échec, **Réessayer** et **Supprimer**), une cascade des durées repliable
affichant la durée et le coût par étape, et le canevas du graphe. Sélectionner un
nœud ouvre le panneau de détail de cette étape.

[Surveiller les exécutions de pipeline](/fr-CA/manuel/guides/surveiller-pipelines/)
couvre tout cela, y compris comment interpréter une étape suspendue et quoi faire
quand une étape échoue.

Chaque exécution que vous démarrez depuis l’application est bien réelle.
