Ce guide vous montre comment revenir à un point antérieur d’une conversation et l’orienter ailleurs — tout en conservant le chemin que vous avez quitté.

## La seule chose à savoir

**Créer une branche n’écrit rien.** Une conversation est un arbre de messages dont la pointe porte un pointeur, et revenir en arrière déplace ce pointeur. Rien n’est supprimé, rien n’est masqué, et changer de chemin de nouveau n’est qu’un autre déplacement du pointeur.

C’est pourquoi modifier un prompt et le réexécuter est sans danger ici : la réponse à laquelle vous vous compariez est toujours là.

## Voir les branches

```
/tree
```

Le navigateur d’arbre énumère chaque message, en retrait à chaque bifurcation, le chemin courant étant marqué **Sur cette branche**. Une conversation qui n’a jamais bifurqué s’affiche comme la liste à plat qu’elle a toujours été — le navigateur ne coûte rien à consulter tant qu’il n’y a rien à parcourir.

Chaque ligne offre deux actions.

| Action                          | Effet                                                    |
| ------------------------------- | --------------------------------------------------------- |
| **Continuer d'ici**             | Déplace le pointeur. Votre prochain message reprend à partir de ce message. |
| **Dupliquer dans une nouvelle conversation** | Copie le chemin jusqu’à ce message dans une nouvelle conversation. |

## Créer une branche : essayer une autre approche

1. `/tree`
2. Repérez le message à partir duquel vous voulez recommencer — habituellement le dernier qui vous satisfaisait.
3. **Continuer d'ici.**
4. Saisissez le nouveau prompt.

L’ancienne suite est toujours dans l’arbre ; `/tree` affichera maintenant deux chemins à partir de ce point, et vous pouvez passer librement de l’un à l’autre.

:::note[Le chemin que vous avez quitté est toujours là]
Créer une branche ne masque ni ne supprime rien. `/tree` énumère chaque chemin, marque le chemin courant **Sur cette branche**, et c’est ainsi que vous changez de chemin.
:::

## Bifurquer : l’envoyer ailleurs

La bifurcation copie le chemin dans une **nouvelle conversation** du même espace. Utilisez-la quand les deux directions continueront de diverger et que vous les voulez côte à côte plutôt que d’avoir à changer de chemin.

La copie obtient de nouveaux identifiants de message. Deux conversations qui partageraient des lignes se montreraient mutuellement leurs messages ultérieurs, ce qui est exactement ce qu’une bifurcation doit empêcher.

## Retour en arrière ou création d’une branche

Ce sont deux outils différents, et la différence compte.

|                          | Retour en arrière                                   | Création d’une branche             |
| ------------------------ | --------------------------------------------------- | ---------------------------------- |
| Les messages ultérieurs  | Masqués de la transcription                          | Toujours visibles dans `/tree`     |
| L’**arbre de travail**   | Ramené à l’instantané de ce tour                     | Intact                             |
| Annulation               | **Annuler le retour** restaure le lot                | Ramener le pointeur en arrière     |

Le retour en arrière est ce qu’il vous faut quand l’agent a modifié des *fichiers* que vous voulez récupérer. Créer une branche est ce qu’il vous faut quand la conversation a mal tourné mais que les fichiers sont intacts.

Le retour en arrière déplace aussi la pointe de branche, de sorte que votre prochain message reprend au bon endroit plutôt qu’à la suite d’une queue que personne ne peut plus voir.

## Sortir la conversation de l’application

### `/export`

Écrit un **fichier HTML autonome** : toute la conversation, avec des cartes d’outils repliables montrant ce qui a été fourni à chaque appel et ce qu’il a renvoyé. Aucune feuille de style, aucun script, aucun hébergeur d’images — il fonctionne depuis une clé USB et il fonctionnera encore dans cinq ans.

- **Bureau :** `Documents/ControlCenter/exports/`, horodaté pour qu’une deuxième exportation n’écrase pas la première.
- **Web :** un téléchargement par le navigateur.

### `/dump`

Copie la transcription dans le presse-papiers en markdown, avec les appels d’outils dans des blocs repliables. C’est celui-ci qu’il faut coller dans un ticket.

Le raisonnement est volontairement laissé de côté : c’est le brouillon du modèle, et un rapport de bogue est lu par une personne.
