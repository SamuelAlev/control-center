Ce guide vous montre comment donner à votre serveur sa propre GitHub App. Cela
prend environ deux minutes, seul le propriétaire du serveur s’en occupe, et il
ne faut le faire qu’une fois par serveur.

:::note[Vous n’en avez peut-être pas besoin]
Lorsque Control Center Connect est activé, les gens se connectent à GitHub au
moyen de l’App partagée de Control Center, ou de l’App qu’utilise le Connect de
votre organisation. Enregistrez la vôtre lorsque vous avez choisi **Utiliser mes
propres applications** : l’App du serveur n’est utilisée que dans ce cas. Voir
[Control Center Connect](/fr-CA/manuel/reference/connect/).
:::

Pour connecter ensuite votre propre compte, voir
[Configurer l’intégration GitHub](/fr-CA/manuel/guides/integration-github/).

## Ce que fait l’app

Une même inscription répond à deux tâches différentes :

| Tâche | Ce qui y répond | Pourquoi c’est important |
| --- | --- | --- |
| **Une personne se connecte** | L’identifiant client et le secret client de l’app | Chacun obtient un identifiant GitHub qui lui est propre, sur le serveur, sur chaque appareil |
| **Le serveur agit** | L’identifiant de l’app et sa clé privée | Les agents, les pipelines, les tâches d’interrogation et les réponses du robot reçoivent des jetons limités à un seul dépôt à la fois |

La seconde tâche n’emprunte jamais l’identifiant d’une personne en bloc. Chaque
jeton émis par le serveur couvre un seul dépôt et se limite à ce qu’un membre
responsable peut y faire. Lire un dépôt lié ne requiert que l’app ; tout ce qui
écrit requiert un membre capable de pousser. L’automatisation n’approuve jamais
une demande de tirage.

L’app du serveur ne s’applique que sous **Utiliser mes propres applications**. Avec Control Center ou un Connect personnalisé, Connect exécute chaque voie, GitHub compris; l’app du serveur reste enregistrée mais inutilisée jusqu’à ce que vous reveniez en arrière. Une app propre à l’espace de travail ([Donner une autre app à un espace de travail](#donner-une-autre-app-à-un-espace-de-travail)) s’applique toujours, quel que soit le mode. Une app dont
certains champs manquent est une erreur, pas un repli : les connexions GitHub
sont refusées tant que tous les champs ne sont pas remplis.

## Prérequis

- Vous êtes le **propriétaire du serveur**. La carte **Applications
  fournisseur** est invisible pour tout le monde
- Un compte GitHub. L’app est créée sous ce compte
- Une adresse de serveur que votre navigateur peut joindre. L’URL publique du
  serveur (ou la boucle locale, pour le serveur propre à un ordinateur de bureau)
  est l’endroit où GitHub vous renvoie

## La créer en un clic

1. Allez dans **Paramètres → Serveur → Authentification unique** et faites
   défiler jusqu’à la carte **Applications fournisseur**
2. Dans le bloc **GitHub**, entrez au besoin, dans **Organisation
   (facultatif)**, l’organisation GitHub qui doit posséder l’app. Laissez le
   champ vide pour créer l’app sous votre propre compte ; pour la créer sous une
   organisation, il faut être propriétaire de cette organisation
3. Cliquez sur **Créer mon application GitHub**
4. Votre navigateur ouvre GitHub avec l’app déjà remplie. Cliquez sur
   **Create GitHub App**
5. GitHub vous renvoie vers le serveur, qui enregistre l’identifiant de l’app,
   la clé privée, l’identifiant client et le secret client, puis ouvre la page
   d’installation de l’app

Rien n’est copié à la main, et le code de conversion va directement de GitHub à
votre serveur. Le lien ne fonctionne qu’une fois et expire au bout de dix
minutes ; s’il a expiré, cliquez de nouveau sur **Créer mon application GitHub**.

L’app s’appelle `Control Center <code>` et demande exactement ce qu’utilise
Control Center :

| Permission | Accès |
| --- | --- |
| Metadata | Lecture |
| Contents | Lecture et écriture |
| Pull requests | Lecture et écriture |
| Issues | Lecture et écriture |
| Checks, Actions, Commit statuses | Lecture |
| Organization members | Lecture |

Les webhooks sont désactivés : le serveur interroge GitHub. Pour transférer
plus tard à une organisation une app créée sous votre propre compte, utilisez
**Transfer ownership** dans les paramètres avancés de l’app sur GitHub.

Point de contrôle : le bloc GitHub indique « Le serveur peut agir en son nom, et
les personnes peuvent se connecter ».

## Installer là où se trouvent vos dépôts

Une app enregistrée mais non installée peut connecter des gens, mais ne peut
rien lire.

1. Sur la page d’installation que GitHub a ouverte, choisissez le compte ou
   l’organisation propriétaire de vos dépôts
2. Choisissez **All repositories**, ou sélectionnez ceux que ce serveur doit
   voir

Pour l’installer plus tard sur un autre compte, un administrateur de l’espace de
travail va dans **Paramètres → Espace de travail → Général**, repère
**Installations de l’application GitHub** sur la carte d’identité GitHub et
clique sur **Installer l’application GitHub**. La liste indique chaque compte
sur lequel l’app est installée et signale une installation suspendue.

## Autoriser ce serveur pour une organisation

Sur l’App partagée de Control Center, l’installation d’une organisation ne sert
que les serveurs que ses administrateurs ont autorisés. Installer au moyen de
**Installer l’application GitHub** autorise le serveur qui a lancé
l’installation. Pour une installation qui existe déjà :

1. Un administrateur de cette organisation se connecte à GitHub sur ce serveur
2. Il ouvre **Paramètres → Espace de travail → Général → Installations de
   l’application GitHub**
3. La ligne de l’organisation indique **Non autorisée**. Il clique sur
   **Autoriser ce serveur**

La ligne indique alors **Autorisée**. Votre propre app n’a besoin de rien de
tout cela : chacune de ses installations appartient à votre serveur.

## L’enregistrer plutôt à la main

La carte **Applications fournisseur** accepte aussi directement les valeurs,
pour une app que vous avez enregistrée vous-même :

| Groupe | Champs |
| --- | --- |
| **Agir en tant que serveur** | **Identifiant d’application**, et **Clé privée** (le `.pem` au complet, lignes `BEGIN` et `END` comprises) |
| **Connexion des utilisateurs** | **Identifiant client** et **Secret client**. **URL de rappel** affiche l’URL à enregistrer, textuellement |
| **Conversations de pull request** | **Login du bot**, résolu lorsque vous testez la connexion |

Enregistrez l’URL de rappel `<server origin>/oauth/github/callback` exactement
comme la carte l’affiche, laissez **Expire user authorization tokens** activé et
accordez les permissions du tableau ci-dessus. Cliquez sur **Tester** : cela
demande à GitHub sur quels comptes l’app est installée, afin de ne pas confondre
« enregistré » et « fonctionne ».

## La configurer depuis le `.env` du serveur

Pour une installation sans interface ou automatisée, le serveur initialise
chaque champ à partir de son fichier `.env` la première fois qu’il n’a aucune
valeur enregistrée :

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

Placez la clé sur **une seule ligne** : une valeur de `.env` tient sur une
ligne, et `\n` entre guillemets doubles est décodé en saut de ligne. Le serveur
refuse de démarrer lorsque `GITHUB_APP_PRIVATE_KEY` ou `GITHUB_CLIENT_SECRET`
est exporté dans l’environnement de son processus, où chaque processus enfant
pourrait le lire ; gardez-les dans le fichier `.env` (sous Docker, montez-le sur
`/app/bin/.env`). L’initialisation se fait **une fois par champ**, donc une
modification faite dans Paramètres n’est pas annulée au prochain redémarrage.

## Donner une autre app à un espace de travail

Un espace de travail peut utiliser sa propre app au lieu de celle du serveur. Un
administrateur de l’espace de travail va dans **Paramètres → Espace de travail →
Général**, choisit **Utiliser une autre GitHub App** sur la carte **Identité
GitHub** et saisit l’identifiant de cette app, sa clé privée, son identifiant
client et son secret client. Les membres se connectent alors à cette app pour
cet espace de travail. Un espace de travail doté de sa propre app ne se rabat
jamais sur l’app du serveur ni sur Connect : tant que ses champs ne sont pas
complets, son travail GitHub est refusé. Cela s’applique quelle que soit la façon dont le serveur connecte les gens, Connect compris.

La carte **Applications fournisseur** de cette même page fait de même pour Google Calendar, Linear et la recherche de GIF. Voir [Donner à un espace de travail sa propre application Linear](/fr-CA/manuel/guides/integration-linear/#donner-à-un-espace-de-travail-sa-propre-application-linear) et [Donner à un espace de travail son propre client Google](/fr-CA/manuel/guides/connecter-calendrier/#donner-à-un-espace-de-travail-son-propre-client-google).

## Dépannage

### Créer mon application GitHub indique que le serveur n’a pas d’adresse

Le serveur n’a aucune URL publique vers laquelle un navigateur pourrait revenir.
Définissez `CC_SERVER_PUBLIC_URL` (ou `--public-url`) et réessayez.

### GitHub indique que le lien a expiré

La page à usage unique a déjà été utilisée, ou dix minutes se sont écoulées.
Recommencez à partir de Paramètres.

### Tester indique que les identifiants fonctionnent, mais que l’app n’est installée nulle part

L’enregistrement et l’installation sont deux étapes distinctes. Ouvrez la page
d’installation de l’app, ou utilisez **Installer l’application GitHub** dans
Espace de travail → Général.

### Tester indique que la clé privée n’a pas pu être lue

Collez le fichier `.pem` au complet, y compris les lignes `-----BEGIN` et
`-----END`. Une clé `ed25519` ou EC ne peut pas être utilisée : les GitHub Apps
signent avec RSA.

### Un membre s’est connecté, mais ne voit aucun dépôt

L’app n’est pas installée sur le compte qui les possède, ou son installation
sélectionne d’autres dépôts. Une connexion n’accorde que ce que l’app est
autorisée à voir.

### Les agents indiquent que l’installation de la GitHub App est suspendue

Quelqu’un a suspendu l’installation sur GitHub. Réactivez-la dans **Settings →
Applications → Installed GitHub Apps** du compte concerné.
