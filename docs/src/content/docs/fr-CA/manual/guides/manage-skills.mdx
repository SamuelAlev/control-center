Ce guide vous montre comment remplir un espace de travail de skills venus de
GitHub : ajoutez un dépôt comme source, installez les skills que vous voulez
depuis celui-ci et tenez-les à jour au fil du temps. Vous pouvez aussi évaluer
une révision enregistrée par rapport à une base de référence appariée avant de
décider de la conserver.

Ce qu'il faut savoir avant de commencer : **un dépôt source n'est pas
fiable.** Son nom, sa description et son nombre d'étoiles sont écrits par
quiconque le possède. Chaque installation passe par la barrière du scan
antivirus avant que quoi que ce soit n'atteigne le disque ou le prompt d'un
agent. Ce verdict est un contrôle d'admission, pas une preuve qu'un skill est
sûr ou utile. Lisez la
[section sur les skills du modèle d'agent](/fr-CA/manuel/concepts/modele-agent/)
pour le modèle d'installation et [Évaluations et
qualité](/fr-CA/manuel/concepts/evaluations-et-qualite/) pour savoir en quoi les
preuves comportementales diffèrent d'un scan.

Les skills se trouvent sous **Paramètres → Espace de travail → Compétences**
(`/workspaces/<id>/settings/workspace/skills`). Ils sont limités à l'espace de
travail : les skills que vous installez ici appartiennent uniquement à cet
espace de travail. La page compte deux onglets :
**Installées** (les skills locaux, y compris un éditeur **Nouvelle
compétence**) et **Sources** (les catalogues GitHub). Les deux écritures
passent par la même barrière de scan.

## Ajouter un dépôt de skills

1. Ouvrez **Paramètres → Espace de travail → Compétences** et basculez vers
   l'onglet **Sources**.
2. Appuyez sur **Ajouter un dépôt**.
3. Collez l'URL d'un dépôt GitHub, p. ex. `https://github.com/anthropics/skills`,
   puis confirmez.

Le serveur vérifie que le dépôt existe et qu'il est visible avec ses
identifiants, puis l'ajoute à la barre latérale gauche. Il n'y a pas de
catalogue organisé au milieu : n'importe quel dépôt GitHub fait l'affaire, ce
qui veut aussi dire que la réputation est à votre jugement — un nombre
d'étoiles est une preuve, jamais une garantie.

Les skills d'un dépôt sont les répertoires qui contiennent un `SKILL.md`
(jusqu'à trois niveaux de profondeur, en plus de la disposition du
marché de plugins de Claude
`plugins/<plugin>/skills/<skill>`, les arborescences de dépendances et de code
tiers étant ignorées).
Si la grille indique plus tard que le dépôt ne contient aucun skill, c'est
exactement ce que cela veut dire : aucun répertoire qu'il contient ne
correspond à la convention des skills.

## Inspecter un skill avant de l'installer

Sélectionnez un dépôt dans la barre latérale ; ses skills apparaissent sous
forme de grille à droite, avec au-dessus un champ de filtre qui restreint le
catalogue par nom, description ou slug. Cliquez sur une carte pour ouvrir la
vue de détail. Elle montre trois choses :

- **Le README**, rendu en markdown — le `README.md` du répertoire du skill, ou
  le corps du `SKILL.md` lorsqu'il n'y a pas de README.
- **L'aperçu du scan** — le verdict (`pass`, `warn` ou `quarantine`), les
  capacités que déclare le contenu du skill (exécute un shell, écrit des
  fichiers, accès réseau…) et chaque constat consigné par l'analyseur.
- **Le nombre de fichiers** — une installation écrit tout le répertoire du
  skill, pas seulement son `SKILL.md`.

L'aperçu analyse exactement les octets qu'écrirait une installation, de sorte
que le verdict que vous voyez est celui que l'installation reçoit ; rien n'est
réévalué à votre insu.

## Installer un skill

1. Ouvrez la vue de détail du skill.
2. Lisez le verdict du scan. Pour un verdict `warn` ou `pass`, appuyez sur
   **Installer**.
3. Pour un verdict `quarantine`, l'installation reste désactivée tant que vous
   ne cochez pas **Je comprends le risque — installer quand même**. Cette
   dérogation est consignée, pas présumée.

L'installation écrit le répertoire du skill dans l'espace de travail, consigne
une épingle dans `skills-lock.json` (dépôt source, chemin, le commit dont il
provient et une empreinte du contenu), et le skill devient disponible pour les
agents de l'espace de travail. Une carte marquée **Nom déjà utilisé** signifie
qu'un autre skill possède déjà ce nom localement — désinstallez-le d'abord.

## Mettre les skills à jour au fil du temps

Les cartes des skills installés portent des badges : **Installé**, ou **Mise à
jour disponible** lorsque le dépôt a dépassé le commit que vous avez épinglé.
Ouvrez la vue de détail et appuyez sur **Mettre à jour** pour récupérer de
nouveau au nouveau commit. Une mise à jour passe par la même barrière de scan
qu'une installation — un skill dont la nouvelle version est mise en
quarantaine est refusé et la version que vous aviez reste en place. L'empreinte
de l'ancienne version est conservée comme référence de retour en arrière dans
le fichier de verrouillage.

## Évaluer un skill

1. Ouvrez **Paramètres → Espace de travail → Compétences**, sélectionnez le
   skill installé et enregistrez vos modifications. Dans **Évaluation de la
   compétence**, vérifiez l'empreinte du paquet.
2. Sélectionnez **Lancer l'évaluation**. Choisissez un **Corpus de tâches**
   correspondant à l'usage du skill et un **adaptateur**. Le harnais intégré
   utilise un fournisseur configuré et un modèle compatible avec les outils.
   **Claude Code** utilise le compte géré par défaut de Claude et un
   identifiant de modèle concret ; connectez-vous d'abord dans **Paramètres →
   Adaptateurs**. Il n'emprunte pas la connexion personnelle de l'opérateur du
   serveur.
3. Choisissez une **Comparaison** dans le tableau ci-dessous.
4. Réglez **Répétitions par tâche** (1–20) et **Budget (cents US)**. Par
   exemple, `100` signifie 1 dollar US. Sélectionnez **Lancer l'évaluation**
   pour autoriser le travail payant du fournisseur.
5. Suivez la campagne dans **Observabilité → Qualité**, ou revenez via
   **Ouvrir Qualité** dans le panneau du skill.

Pour les abonnements Claude Code et Codex OAuth, le budget est un **seuil
d'arrêt d'utilisation équivalente à l'API**, pas un plafond de facturation ni une
mesure du quota d'abonnement. `100` admet un seuil de 1 dollar US : un appel en
cours peut le dépasser, mais aucun autre appel ne démarre dès que l'utilisation
déclarée l'atteint. Une utilisation inconnue arrête elle aussi les appels
suivants. Un petit budget peut laisser la comparaison partielle ; il ne promet
pas de terminer le corpus sélectionné.

Les fournisseurs à clé API conservent des réservations prudentes par appel,
fondées sur les limites de jetons et la tarification documentées. Ils peuvent
refuser `100` avant toute dépense lorsqu'un seul appel réservé en toute sécurité
a besoin de plus. L'erreur indique le modèle sélectionné et la réservation
minimale ; choisissez un modèle moins cher ou augmentez ce budget.

| Comparaison | Servez-vous-en pour répondre |
| --- | --- |
| **Absente ou disponible** | La découverte et l'usage normaux de ce skill améliorent-ils le résultat par rapport à son absence ? |
| **Précédente ou actuelle** | La mise à jour préserve-t-elle ou améliore-t-elle le comportement par rapport à une révision capturée auparavant ? |
| **Chargement forcé ou absence** | Le contenu peut-il aider lorsqu'il est chargé explicitement ? Cela diagnostique des problèmes de chargement ; cela ne démontre pas la découverte normale. |
| **Composition** | L'ajout du candidat aide-t-il ou entre-t-il en conflit avec les skills ambiants sélectionnés ? La base de référence conserve ce même inventaire ambiant sans le candidat. |

La comparaison **Précédente ou actuelle** exige une empreinte de paquet issue
de l'historique des campagnes. Évaluez une révision avant de la remplacer si
vous voulez l'utiliser comme base de référence ; l'historique Git arbitraire
n'est pas importé.

Les modifications non enregistrées, une empreinte indisponible et le mode démo
en lecture seule désactivent le lancement. Le serveur vérifie aussi l'accès à
l'espace de travail et au dépôt, la quarantaine du scan, la politique
d'actions, la prise en charge des modèles, la tarification et le confinement de
l'exécution. Résolvez une vérification échouée plutôt que de la contourner.
L'identité du fournisseur et du modèle est consignée, mais un alias de modèle
distant ne fige pas les poids sous-jacents du fournisseur.

### Inspecter, annuler et exporter

Lisez la couverture et les dépenses aux côtés des résultats par tâche et des
régressions. Ouvrez les tentatives individuelles pour examiner les chargements
de skills observés, les événements d'outils, les erreurs et les preuves des
vérificateurs. Les résultats **Partiels**, **Obsolètes** et **Non concluants**
ne sont pas des recommandations d'adopter une révision. L'empreinte d'un
rapport identifie le paquet capturé, pas nécessairement le paquet actuellement
installé.

Utilisez **Annuler l'exécution** pour le travail en file ou actif. Les
tentatives terminées restent visibles ; l'annulation ne rembourse pas le travail
du fournisseur déjà effectué. **Copier le JSON expurgé** copie dans le
presse-papiers un export de preuves borné, pas un paquet complet de relecture
d'une source privée. Voir [Évaluations et
qualité](/fr-CA/manuel/concepts/evaluations-et-qualite/) pour les preuves et les
limites de la plateforme.

### Réévaluer après les mises à jour

La réévaluation automatique payante est **désactivée par défaut**. Après avoir
évalué la révision actuelle, choisissez une campagne sous **Configuration de la
politique de mise à jour** et sélectionnez **Activer les évaluations des mises
à jour**. Modifier cette politique exige la permission d'administrateur de
l'espace de travail. La campagne choisie fournit le corpus, l'adaptateur, le
fournisseur/modèle, la comparaison, les répétitions et le budget.

Les modifications de contenu admises par la suite planifient du travail
budgété ; les empreintes inchangées sont dédupliquées. **Désactiver les
évaluations des mises à jour** empêche les admissions automatiques futures.
Utilisez **Annuler l'exécution** pour une campagne déjà admise. Les rapports
historiques restent attachés aux empreintes de leurs paquets d'origine ; la
réévaluation ne publie, n'active ni ne réécrit un skill.

## Désinstaller un skill, retirer un dépôt

**Désinstaller** (dans la vue de détail d'un skill installé, ou en supprimant
dans l'onglet Installées) retire ensemble le répertoire du skill et son
épingle de verrouillage — un skill désinstallé ne laisse rien derrière lui.

**Retirer un dépôt** de la barre latérale ne retire que le catalogue : les
skills que vous avez installés depuis celui-ci restent installés et continuent
de se mettre à jour, parce qu'une épingle enregistre le dépôt par son nom
plutôt que par référence à l'entrée source. Rajoutez le dépôt si vous voulez
le parcourir de nouveau.

## Invoquer un skill

Les skills s'invoquent sous leur propre espace de noms, de sorte qu'ils
n'entrent jamais en collision avec les commandes slash intégrées (`/plan`,
`/goal`, `/loop`, `/compact`) :

- `/skill:<name>` — un skill installé dans cet espace de travail, ou rattaché à
  l'agent
- `/skill:<repo>:<name>` — un skill fourni par un dépôt extrait dans cet espace

Un nom seul non intégré se résout quand même, pour les messages écrits avant
l'existence de l'espace de noms. `/skill:plan` est ce qui atteint un skill
nommé `plan` ; `/plan` est toujours la commande intégrée.

## Skills à portée de dépôt

Un dépôt extrait peut fournir ses propres skills, dans `.agents/skills/`,
`.agent/skills/`, `.claude/skills/`, `.opencode/skills/` ou `skills/`. Ceux-ci
ne sont **pas** installés depuis cette page. Un agent ne porte que les skills
du dépôt dans lequel il travaille actuellement ; ils sont échangés lorsqu'il se
déplace. Le composeur n'a pas cette portée : `/skill:<repo>:<name>` atteint
n'importe quel dépôt de l'espace.

Les skills de dépôt passent le même scan à refus par défaut (`pass` / `warn` /
`quarantine`) avant que leur frontmatter n'atteigne un prompt. `warn` est
admis ; `quarantine` est retenu, sans dérogation d'opérateur sur ce chemin.

Voir [Skills à portée de dépôt](/fr-CA/manuel/concepts/modele-agent/#repo-scoped-skills) et
[Commandes slash](/fr-CA/manuel/reference/commandes-slash/).
