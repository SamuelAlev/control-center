Ce guide vous montre comment remplir un espace de travail de skills venus de
GitHub : ajoutez un dépôt comme source, installez les skills que vous voulez
depuis celui-ci et tenez-les à jour au fil du temps.

Ce qu'il faut savoir avant de commencer : **un dépôt source n'est pas
fiable.** Son nom, sa description et son nombre d'étoiles sont écrits par
quiconque le possède. Le seul signal de sécurité auquel Control Center se fie
est le verdict du scan antivirus, par lequel passe chaque installation avant
que quoi que ce soit n'atteigne le disque ou le prompt d'un agent. Si vous
voulez le raisonnement, lisez la
[section sur les skills du modèle d'agent](/fr-CA/manuel/concepts/modele-agent/); cette page
s'en tient à la pratique.

Les skills se trouvent sous **Paramètres → Espace de travail → Compétences**
(`/workspaces/<id>/settings/workspace/skills`). Ils sont limités à l'espace de
travail : les skills que vous installez ici appartiennent uniquement à cet
espace de travail. La page compte deux onglets :
**Installées** (les skills locaux, y compris un éditeur **Nouvelle
compétence**) et **Sources** (les catalogues GitHub). Les deux écritures
passent par la même barrière de scan.

## Ajouter un dépôt de skills

1. Ouvrez **Paramètres → Espace de travail → Compétences** et basculez vers
   l'onglet **Sources**.
2. Appuyez sur **Ajouter un dépôt**.
3. Collez l'URL d'un dépôt GitHub, p. ex. `https://github.com/anthropics/skills`,
   puis confirmez.

Le serveur vérifie que le dépôt existe et qu'il est visible avec ses
identifiants, puis l'ajoute à la barre latérale gauche. Il n'y a pas de
catalogue organisé au milieu : n'importe quel dépôt GitHub fait l'affaire, ce
qui veut aussi dire que la réputation est à votre jugement — un nombre
d'étoiles est une preuve, jamais une garantie.

Les skills d'un dépôt sont les répertoires qui contiennent un `SKILL.md`
(jusqu'à trois niveaux de profondeur, en plus de la disposition du
marché de plugins de Claude
`plugins/<plugin>/skills/<skill>`, les arborescences de dépendances et de code
tiers étant ignorées).
Si la grille indique plus tard que le dépôt ne contient aucun skill, c'est
exactement ce que cela veut dire : aucun répertoire qu'il contient ne
correspond à la convention des skills.

## Inspecter un skill avant de l'installer

Sélectionnez un dépôt dans la barre latérale ; ses skills apparaissent sous
forme de grille à droite, avec au-dessus un champ de filtre qui restreint le
catalogue par nom, description ou slug. Cliquez sur une carte pour ouvrir la
vue de détail. Elle montre trois choses :

- **Le README**, rendu en markdown — le `README.md` du répertoire du skill, ou
  le corps du `SKILL.md` lorsqu'il n'y a pas de README.
- **L'aperçu du scan** — le verdict (`pass`, `warn` ou `quarantine`), les
  capacités que déclare le contenu du skill (exécute un shell, écrit des
  fichiers, accès réseau…) et chaque constat consigné par l'analyseur.
- **Le nombre de fichiers** — une installation écrit tout le répertoire du
  skill, pas seulement son `SKILL.md`.

L'aperçu analyse exactement les octets qu'écrirait une installation, de sorte
que le verdict que vous voyez est celui que l'installation reçoit ; rien n'est
réévalué à votre insu.

## Installer un skill

1. Ouvrez la vue de détail du skill.
2. Lisez le verdict du scan. Pour un verdict `warn` ou `pass`, appuyez sur
   **Installer**.
3. Pour un verdict `quarantine`, l'installation reste désactivée tant que vous
   ne cochez pas **Je comprends le risque — installer quand même**. Cette
   dérogation est consignée, pas présumée.

L'installation écrit le répertoire du skill dans l'espace de travail, consigne
une épingle dans `skills-lock.json` (dépôt source, chemin, le commit dont il
provient et une empreinte du contenu), et le skill devient disponible pour les
agents de l'espace de travail. Une carte marquée **Nom déjà utilisé** signifie
qu'un autre skill possède déjà ce nom localement — désinstallez-le d'abord.

## Mettre les skills à jour au fil du temps

Les cartes des skills installés portent des badges : **Installé**, ou **Mise à
jour disponible** lorsque le dépôt a dépassé le commit que vous avez épinglé.
Ouvrez la vue de détail et appuyez sur **Mettre à jour** pour récupérer de
nouveau au nouveau commit. Une mise à jour passe par la même barrière de scan
qu'une installation — un skill dont la nouvelle version est mise en
quarantaine est refusé et la version que vous aviez reste en place. L'empreinte
de l'ancienne version est conservée comme référence de retour en arrière dans
le fichier de verrouillage.

## Désinstaller un skill, retirer un dépôt

**Désinstaller** (dans la vue de détail d'un skill installé, ou en supprimant
dans l'onglet Installées) retire ensemble le répertoire du skill et son
épingle de verrouillage — un skill désinstallé ne laisse rien derrière lui.

**Retirer un dépôt** de la barre latérale ne retire que le catalogue : les
skills que vous avez installés depuis celui-ci restent installés et continuent
de se mettre à jour, parce qu'une épingle enregistre le dépôt par son nom
plutôt que par référence à l'entrée source. Rajoutez le dépôt si vous voulez
le parcourir de nouveau.

## Invoquer un skill

Les skills s'invoquent sous leur propre espace de noms, de sorte qu'ils
n'entrent jamais en collision avec les commandes slash intégrées (`/plan`,
`/goal`, `/loop`, `/compact`) :

- `/skill:<name>` — un skill installé dans cet espace de travail, ou rattaché à
  l'agent
- `/skill:<repo>:<name>` — un skill fourni par un dépôt extrait dans cet espace

Un nom seul non intégré se résout quand même, pour les messages écrits avant
l'existence de l'espace de noms. `/skill:plan` est ce qui atteint un skill
nommé `plan` ; `/plan` est toujours la commande intégrée.

## Skills à portée de dépôt

Un dépôt extrait peut fournir ses propres skills, dans `.agents/skills/`,
`.agent/skills/`, `.claude/skills/`, `.opencode/skills/` ou `skills/`. Ceux-ci
ne sont **pas** installés depuis cette page. Un agent ne porte que les skills
du dépôt dans lequel il travaille actuellement ; ils sont échangés lorsqu'il se
déplace. Le composeur n'a pas cette portée : `/skill:<repo>:<name>` atteint
n'importe quel dépôt de l'espace.

Les skills de dépôt passent le même scan à refus par défaut (`pass` / `warn` /
`quarantine`) avant que leur frontmatter n'atteigne un prompt. `warn` est
admis ; `quarantine` est retenu, sans dérogation d'opérateur sur ce chemin.

Voir [Skills à portée de dépôt](/fr-CA/manuel/concepts/modele-agent/#repo-scoped-skills) et
[Commandes slash](/fr-CA/manuel/reference/commandes-slash/).
