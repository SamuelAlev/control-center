Linear a deux identités dans Control Center, et toutes deux passent par une
connexion dans le navigateur : la vôtre, pour ce que vous faites, et l’app
Control Center de l’espace de travail, pour ce que font les agents et les
pipelines. Les tickets, les projets, les liens, les collaborateurs, la
délégation et l’attribution fonctionnent tous avec la base de données propre à
Control Center, sans qu’aucun service externe ne soit nécessaire — consultez
[Créer et gérer des tickets](/fr-CA/manuel/guides/gerer-tickets/).

## Prérequis

- Le serveur peut connecter les gens à Linear : au moyen de Control Center
  Connect, ou avec l’application Linear propre au serveur
  ([Enregistrer votre propre application Linear](#enregistrer-votre-propre-application-linear)).
  Le propriétaire du serveur fait ce choix dans **Paramètres → Serveur →
  Authentification unique**
- Un administrateur de l’espace de travail, pour choisir Linear comme
  fournisseur de tickets et pour connecter l’automatisation Linear

## Choisir Linear pour l’espace de travail

1. Allez dans **Paramètres → Espace de travail → Intégrations** et repérez la carte
   **Tickets**
2. Réglez **Fournisseur de tickets** sur **Linear**

Les tickets que vous créez à partir de ce moment portent `provider: linear`.
**Local** garde les tickets dans la base de données de ce serveur et masque les
lignes Linear : il n’y a rien à authentifier.

## Se connecter à Linear

Votre propre connexion à Linear se trouve dans **Paramètres → Vous → Profil**, sur la carte **Tickets** :

1. Cliquez sur **Se connecter à Linear**
2. Approuvez dans votre navigateur
3. Avec l’application propre au serveur, la boîte de dialogue s’en aperçoit
   d’elle-même. Au moyen de Connect, tapez le code de 8 caractères affiché par
   le navigateur, ou laissez-le ouvrir Control Center par le lien
   `control-center://`

Tout ce que vous faites dans Linear à partir de Control Center s’exécute avec
cette connexion et rien d’autre. Si vous n’êtes pas connecté, l’app vous demande
de vous connecter plutôt que d’agir au nom de quelqu’un d’autre.

La connexion fonctionne dans chaque espace de travail du serveur, sauf si un espace de travail a ses propres applications de connexion : cet espace garde alors une connexion Linear à lui. La carte indique laquelle s’applique.

## Connecter l’automatisation Linear

La ligne **Automatisation Linear**, sur la carte **Tickets** dans **Paramètres → Espace de travail → Intégrations**, correspond à l’app Control Center de l’espace
de travail dans Linear. La synchronisation des tickets, les pipelines et les
agents écrivent avec elle, de sorte que les tickets et commentaires automatisés
apparaissent au nom de Control Center plutôt que d’une personne.

1. Un administrateur de l’espace de travail clique sur **Connecter Linear pour
   l’automatisation**
2. Il approuve l’app pour l’espace Linear dans le navigateur, comme ci-dessus

La ligne indique alors « Connecté à _votre espace Linear_ ». Seuls les
administrateurs de l’espace de travail peuvent la connecter ou la déconnecter.

Aucun identifiant Linear n’est placé dans le bac à sable d’un agent : les agents
écrivent les tickets par les outils de Control Center, qui interrogent d’abord
la règle **Écrire dans un outil de suivi externe**.

## Enregistrer votre propre application Linear

Utilisez votre propre application lorsque vous avez choisi **Utiliser mes propres applications**. L’application du serveur ne s’applique que dans ce cas : avec Control Center ou un Connect personnalisé, Connect exécute chaque voie, Linear compris, et l’application du serveur ainsi que sa clé API de service restent enregistrées mais inutilisées. Un espace de travail sur ses propres applications ([plus bas](#donner-à-un-espace-de-travail-sa-propre-application-linear)) utilise sa propre application à la place, quel que soit le mode du serveur.

1. Créez une application OAuth à
   [linear.app/settings/api/applications/new](https://linear.app/settings/api/applications/new)
2. Ajoutez, textuellement, les deux URL de rappel que **Paramètres → Serveur →
   Authentification unique → Applications fournisseur → Linear** affiche sous
   **URL de rappel** : `<server origin>/oauth/linear/callback` et
   `<server origin>/oauth/linear_app/callback`
3. Collez l’**Identifiant client** dans le bloc Linear

Il n’y a aucun secret client : le serveur se connecte avec PKCE. Les jetons
d’actualisation de Linear expirent au bout de 30 jours sans utilisation; le
serveur renouvelle donc une fois par jour toute connexion Linear de plus de
20 jours.

Le même bloc accepte une **Clé API de service** facultative. C’est l’identifiant
Linear propre au serveur, pour l’automatisation dans les espaces de travail qui
n’ont pas connecté l’automatisation Linear. Gardez-la dans **Paramètres** ou
dans le fichier `.env` du serveur sous `LINEAR_API_KEY` : le serveur refuse de
démarrer lorsque `LINEAR_API_KEY` est exporté dans l’environnement de son
processus.

## Donner à un espace de travail sa propre application Linear

Un espace de travail peut se connecter à Linear au moyen d’une application qui lui est propre, plutôt que celle du serveur. Seul un administrateur ou le propriétaire de l’espace de travail peut la configurer.

1. Créez une application OAuth Linear comme indiqué ci-dessus
2. Allez dans **Paramètres → Espace de travail → Intégrations**. Sur la carte **Control Center Connect**, choisissez **Utiliser mes propres applications** puis cliquez sur **Appliquer**
3. Sous Tickets, la carte **Application Linear** apparaît. Ajoutez à l’identique, à l’application Linear, les deux URL de rappel affichées sous **URL de rappel** sur cette carte
4. Collez son **Identifiant client**, et éventuellement une **Clé API de service** pour l’automatisation de cet espace de travail

L’application de l’espace de travail répond alors à chaque demande de connexion et d’automatisation Linear de cet espace, quelle que soit la façon dont le serveur connecte les gens. Elle ne se rabat jamais sur l’application du serveur ni sur Connect : tant qu’aucun identifiant client n’est renseigné, Linear est désactivé dans cet espace de travail, et la carte indique ce qui manque. Sa clé API de service n’est utilisée qu’ici; sans elle, la synchronisation nécessite **Connecter Linear pour l’automatisation**.

**Utiliser mes propres applications** couvre tous les fournisseurs à la fois : GitHub, Google Calendar et la recherche de GIF ne fonctionnent aussi qu’avec les applications propres à l’espace de travail, chacune configurée à côté de son fournisseur sur la même page. Changer les applications de connexion de l’espace de travail, ou modifier son identifiant client, déconnecte de Linear toutes les personnes de cet espace et détache son automatisation. Elles se reconnectent au moyen de la nouvelle application. Les champs enregistrés restent lorsque l’espace de travail revient à un autre choix, mais ne servent qu’avec **Utiliser mes propres applications**. Les secrets ne sont qu’en écriture : la carte indique seulement si l’un d’eux est enregistré. Les autres espaces de travail du serveur ne sont pas concernés.

## Dépannage

### La ligne Linear indique que la connexion n’est pas configurée

Le serveur n’a ni application Linear propre ni Connect. Le propriétaire du
serveur choisit l’un ou l’autre dans **Paramètres → Serveur → Authentification
unique**. Lorsque l’espace de travail utilise ses propres applications, la ligne indique plutôt que sa configuration n’est pas terminée : un administrateur de l’espace de travail renseigne l’identifiant client sur la carte **Application Linear** dans **Paramètres → Espace de travail → Intégrations**.

### La synchronisation des tickets échoue avec une erreur d’authentification

L’espace de travail n’a aucune automatisation Linear connectée et le serveur n’a
aucune clé API de service; la synchronisation n’a donc aucun identifiant. Un
administrateur de l’espace de travail clique sur **Connecter Linear pour
l’automatisation**.

### La connexion de l’automatisation indique que l’espace Linear est connecté ailleurs

L’app Control Center de cet espace Linear est déjà connectée à un autre serveur
Control Center.
