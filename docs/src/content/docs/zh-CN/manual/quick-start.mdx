这是从零开始、直到智能体在你自己的代码上运行起来的最短完整路径。请按顺序操作；每一步都依赖前一步。

你需要 Git、一个 GitHub 账号，以及一个模型提供商账号（Anthropic、OpenAI、Codex、Cursor、Kimi Code，或任何提供 API 密钥的提供商），或者已经安装好的 Claude Code CLI。其余一切都会在过程中配置完成。

## 第 1 步：安装并启动

按[安装](/zh-CN/手册/安装/)中的说明安装 Control Center，然后打开它。

首次启动时，桌面端会询问 **“Control Center 应如何运行？”**。选择 **在此应用中运行**。Control Center 会在这台机器上启动一个无界面的 `cc_server`，它掌管你的数据并完成所有工作。你从来不会看到它；取而代之打开的是引导流程界面。

:::note[不想安装任何东西？]
同一个应用在浏览器中运行于 [app.usectrl.dev](https://app.usectrl.dev)，功能完全相同。不过，
浏览器标签页无法托管服务器，所以你得自己提供一个——在本地运行 `cc_server` 并连接到
`ws://localhost:9030`，或者把它指向另一台机器上的服务器。本快速开始走的是桌面端路线，因为它
不需要配置服务器；浏览器路线见[安装](/zh-CN/手册/安装/#use-it-in-your-browser)。
:::

## 第 2 步：走完引导流程

引导流程有五个步骤，并且按顺序进行——无法跳过其中任何一步。

1. **连接**：用 GitHub 登录，或粘贴一个带有 `repo` 和 `read:org` 权限的个人访问令牌。凭据存储在服务器上，并挂到你的账号上。
2. **工作区**：为你的第一个工作区命名，并可选地挑一个标志。创建它会预置五个智能体——一位 CEO 加上 `qa`、`architect`、`engineer` 和 `librarian`——以及内置流水线模板。
3. **沙箱**：记录沙盒偏好。两种选择都可以让你继续。
4. **适配器**：选择智能体默认使用的适配器和模型。选择 **Control Center (built-in)**，然后用随后出现的提供商选择器登录某个模型提供商——在连接提供商之前，模型列表会一直为空。完成这一步还会把适配器和模型写入工作区的 CEO 智能体。
5. **语音（可选）**：安装用于听写的设备端语音模型，或跳过它。

随后 Control Center 会打开你的工作区收件箱。

:::note[一次智能体运行受什么约束]
在可用的情况下，智能体的命令会被包进宿主机操作系统的原生沙盒——macOS 上是 Seatbelt，Linux 上是 bubblewrap。Windows 没有后端，因此那里的运行只受其他几层约束：对话自己的工作树（Windows 上使用 `git worktree`；在提供 `rift` 的地方使用写时复制）、按每次启动中介并在运行结束时吊销的凭据，以及操作护栏。见[沙盒与安全](/zh-CN/手册/概念/沙盒与安全/)。
:::

## 第 3 步：添加仓库

前往 **设置 → 工作区 → 仓库**，然后点击 **添加仓库**。

该对话框浏览的是运行服务器那台机器上的文件夹，而不是你的客户端，并且它始终停留在服务器配置为对外暴露的根目录之内（默认是该用户的主目录）。只有 git 检出项才会拿到复选框。勾选你自己的那个并把它注册进来。

只有当检出位于 git 工作树内、带有 `origin` 远程、且该远程指向受支持的代码托管——github.com、gitlab.com 或 bitbucket.org——时，它才会被接受。其他任何情况都会被拒绝，并给出原因。

仓库以工作区为作用域：在这里注册一个检出，就把它放进了_这个_工作区。没有单独的关联步骤。

## 第 4 步：为智能体设置适配器和模型

前往 **设置 → 工作区 → 智能体**。在名册中选择 `engineer` 智能体。

在 **设置** 选项卡上设置：

- **适配器**：`Control Center (built-in)`
- **模型**：从你在引导流程中连接的提供商里挑一个

点击 **保存更改**。

实际上这一步并非可选。只有 CEO 智能体会继承引导流程中选定的适配器；四个专业智能体创建时都没有适配器。它们会回退到 **Control Center (built-in)** 并使用 Anthropic 的默认模型，因此只有在你连接了 Anthropic 账号时它们才能运行——而且如果你连接了，跑的会是一个你没有挑选的模型。

## 第 5 步：给智能体派发任务

1. 在侧边栏中找到 **空间** 分区，然后点击 **+** 按钮。
2. 为空间命名，在 **添加智能体** 下添加 `engineer` 智能体，然后创建它。
3. 针对你注册的仓库输入一个具体的小任务，然后按 Enter。

Control Center 会为这段对话预配工作区各仓库的写时复制工作树，根据智能体的角色、人设、技能以及空间的上下文组装提示词，然后派发这次运行。你的源代码检出永远不会被改动。

## 第 6 步：看它工作

你应该会依次看到：

- 输入框的发送按钮变成停止按钮，因为这段对话里有智能体正在工作
- 智能体的推理、工具调用和文本流式写入转录
- 运行结束时发送按钮恢复

然后打开 **设置 → 工作区 → 智能体**，选择该智能体并查看 **日志** 选项卡：一行运行记录，包含它的状态、时长、开始与结束时间，以及它运行时所用的适配器。

这就是那个循环。Control Center 中其他的一切——Pull request 审查、流水线、工单、会议、Slack——都挂在这上面。
