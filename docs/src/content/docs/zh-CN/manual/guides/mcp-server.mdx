本指南介绍如何把外部 MCP 客户端——Claude Code、编辑器、MCP Inspector——连接到
Control Center 自己的工具服务器。

Control Center 注册了 **110** 个工具，并通过 Model Context Protocol 以协议版本
`2024-11-05` 提供这些工具。你可能以为会有的若干工具族在这里完全缺席：没有会议或日历工具，也没有项目工具。

## 找到端点

MCP 接口面复用主 `cc_server` 监听器。没有单独的 MCP 端口。

| 端点   | 方法     | 用途                                          |
| ------ | -------- | --------------------------------------------- |
| `/mcp` | `POST`   | Streamable HTTP 传输——客户端与之通信的就是它   |
| `/mcp` | `DELETE` | 结束会话                                      |
| `/sse` | `GET`    | 服务器发送的通知流                            |

因此，默认的本地安装位于 `http://127.0.0.1:9030/mcp`。

1. 前往 **设置 → 服务器 → MCP 服务器**
2. 查看 **MCP 服务器** 卡片——它会显示运行中还是已停止，以及正在监听的端口

全新安装时该接口面默认开启。只有服务器所有者能看到卡片上的令牌，也只有他们能启动或停止该端点。**随应用启动** 决定它在重启后是否重新启动；**开始** / **停止** 是会话级控制，不会改变该偏好设置。

服务器默认绑定环回地址，因此除非你用 `--bind any` 启动它，否则只有运行 `cc_server` 的那台机器能访问该端点。

## 获取令牌

每个请求都需要服务器的 MCP 令牌，无论来自哪台机器，包括回环请求。服务器在首次启动时创建它。没有办法将其关闭，也没有办法清除它。

1. 在 **设置 → 服务器 → MCP 服务器** 中找到 **身份验证令牌** 行
2. 按 **显示令牌** 并复制它
3. 若要替换它，请按 **轮换令牌**。服务器会立即切换到新令牌，而仍在使用旧令牌的每个客户端都会被拒绝，直到你把新令牌交给它为止

## 连接客户端

把你的客户端指向 Streamable HTTP 端点，并在每个请求上以 `Authorization: Bearer <token>` 发送令牌，包括 `GET /sse`。除此之外没有其他发送方式：URL 中的令牌不被接受。具体的配置形式由你的客户端决定。

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code 不会从项目的 `.mcp.json` 读取这份配置——它把项目范围的 MCP 服务器挡在一个批准提示之
后，而非交互式的 `claude -p` 永远不会回应这个提示。请显式传入配置：

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` 让 Claude 只使用该文件，这样同一个服务器就不会再被从项目中发现并注册两次。

检查点：让客户端列出它的工具。你应该会看到 `mcp__*` 条目，覆盖工单、空间、记忆、代码图和审查。

## 端点会拒绝什么

令牌能打开服务器上的每一个工具，因此端点还会在查看令牌之前，拒绝网页可能发出的任何请求：

| 请求 | 响应 |
| --- | --- |
| 一个并非本机页面的 `Origin` 头（`http://localhost`、`http://127.0.0.1` 或 `http://[::1]`，任意端口） | `403`，"Cross-origin requests are not accepted" |
| 一个既不是本监听器的回环地址和端口、也不是服务器公共主机名的 `Host` 头 | `403`，"Unknown host" |
| 正文不是 `application/json` 的 `POST` | `415` |
| 没有令牌，或令牌错误 | `401` |

若要在本机之外提供 MCP 服务，请以 `--bind any` 启动服务器，并从另一台机器发送令牌，使用服务器的公共主机名来寻址它。

## 让每次调用都限定在工作区内

每个涉及工作区范围数据的工具都要求提供 `workspace_id`，缺少它的调用会被拒绝，而不会被解析到某个
“当前”工作区：

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

这个 id 就是你浏览器或应用 URL 中的那个：`/workspaces/<workspace_id>/…`。唯一的豁免是真正跨工作区
的工具，例如 `list_workspaces` 和新闻流工具——新闻流是按用户划分的，而智能体没有自己的用户，因此
这些工具操作的是服务器所有者的订阅源。

仓库范围的工具还会额外检查该仓库是否已关联到该工作区。

## 了解接口面会拒绝什么

- **模式门控。** 调用会在服务器端按发起调用的智能体所在空间的模式进行解析。处于只读模式的智能体
  无法通过省略 `space_id` 来触达写入工具——模式会改为从它的活动运行中查找。
- **操作护栏。** 会改变状态的工具会声明自己的效果类别，并走产品其余部分所用的同一套策略。参见
  [配置护栏](/zh-CN/手册/操作指南/配置护栏/)。
- **确认。** 某些破坏性工具会构建一份确认载荷，必须获得批准后调用才能继续。

完整目录会在 `tools/list` 中公布，没有任何发现层面的门控——外部 MCP 客户端会拒绝调用不在其缓存
列表中的工具，因此隐藏工具只会把它们弄坏，而不是把它们整理干净。

## 个人 MCP 服务器归所有者所有

本指南介绍的是 Control Center 自己的端点。另一个方向，即 Control Center 交给它运行的智能体使用的 MCP 服务器，列在 **设置 → 服务器 → MCP 服务器 → 外部 MCP 服务器** 下。配置在服务器所在机器上、供 Claude、Codex、Cursor、Gemini、VS Code、Windsurf、OpenCode 使用的服务器，或位于 `.mcp.json` 中的服务器，都会在那里被自动发现。

这些被发现的服务器来自服务器用户自己的工具配置，并以该用户的身份和凭据行事，因此它们属于服务器所有者：

- 它们只在服务器所有者启动或负责的内置工具运行中可用，包括所有者负责的工作区中的自动化。
- 成员的运行、绑定到某个成员的自动化，以及在没有记录所有者的服务器上的每次运行，都得不到其中任何一个。在那里，这些工具不会被列出，无法被调用，也不会出现在工具搜索中。
- 无论对谁，本端点都从不列出、调用或搜索它们，包括所有者的令牌在内，也不会转交它们的资源或提示。因此，通过 MCP 连接 Control Center 的智能体 CLI（例如 Claude Code）也无法经由 Control Center 获得它们；它使用的是自己的配置。

为工作区配置的 MCP 服务器不受以上任何内容影响。

## 故障排查

### 客户端看不到任何工具

- 检查 **MCP 服务器** 卡片是否显示运行中
- 检查端口是否与你的 `cc_server` 端口一致
- 在 Claude Code 上，检查你是否传入了 `--mcp-config` 和 `--strict-mcp-config`

### 401 Unauthorized

请求没有携带令牌，或携带的是旧令牌。请从 **身份验证令牌** 行复制当前令牌，并以 `Authorization: Bearer <token>` 发送。URL 中的令牌会被忽略。

### 曾经正常工作的客户端收到 403

请求携带了来自网页的 `Origin`，或者携带了服务器不响应的 `Host`。请从客户端而非浏览器页面调用端点，并使用服务器的回环地址或其公共主机名。

### 415 Unsupported Media Type

请以 `application/json` 发送 `POST /mcp` 的正文。

### 工具调用失败并提示 “Missing or invalid argument: workspace_id”

添加 `workspace_id`。不存在隐式工作区。

### 工具调用因未知而被拒绝

[MCP 工具](/zh-CN/手册/参考/mcp-工具/) 列出了完整目录。请完全按照那里出现的名称来调用。
