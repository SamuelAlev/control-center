本指南介绍如何把外部 MCP 客户端——Claude Code、编辑器、MCP Inspector——连接到
Control Center 自己的工具服务器。

Control Center 注册了 **110** 个工具，并通过 Model Context Protocol 以协议版本
`2024-11-05` 提供这些工具。你可能以为会有的若干工具族在这里完全缺席：没有会议或日历工具，也没有项目工具。

## 找到端点

MCP 接口面复用主 `cc_server` 监听器。没有单独的 MCP 端口。

| 端点   | 方法     | 用途                                          |
| ------ | -------- | --------------------------------------------- |
| `/mcp` | `POST`   | Streamable HTTP 传输——客户端与之通信的就是它   |
| `/mcp` | `DELETE` | 结束会话                                      |
| `/sse` | `GET`    | 服务器发送的通知流                            |

因此，默认的本地安装位于 `http://127.0.0.1:9030/mcp`。

1. 前往 **设置 → 服务器 → MCP 服务器**
2. 查看 **MCP 服务器** 卡片——它会显示运行中还是已停止，以及正在监听的端口

全新安装时该接口面默认开启，因此环回客户端无需调整任何设置即可使用。**随应用启动** 决定它在重启
后是否重新启动；**开始** / **停止** 是会话级控制，不会改变该偏好设置。

服务器默认绑定环回地址，因此除非你用 `--bind any` 启动它，否则只有运行 `cc_server` 的那台机器能访问该端点。

## 连接客户端

把你的客户端指向 Streamable HTTP 端点。具体的配置形式由你的客户端决定；无论哪种方式，URL 都一样。

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp"
    }
  }
}
```

### Claude Code

Claude Code 不会从项目的 `.mcp.json` 读取这份配置——它把项目范围的 MCP 服务器挡在一个批准提示之
后，而非交互式的 `claude -p` 永远不会回应这个提示。请显式传入配置：

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` 让 Claude 只使用该文件，这样同一个服务器就不会再被从项目中发现并注册两次。

检查点：让客户端列出它的工具。你应该会看到 `mcp__*` 条目，覆盖工单、空间、记忆、代码图和审查。

## 在本机之外提供 MCP 服务

1. 在 **设置 → 服务器 → MCP 服务器** 的 **身份验证令牌** 行上，按 **设置** 并粘贴一个令牌
2. 在每次 `POST /mcp` 请求中把它作为 `Authorization: Bearer <token>` 发送

未配置令牌的接口面会以 403 拒绝任何非环回调用方。这是有意为之的失败即关闭：令牌正是让本机之外的
服务得以成立的东西。

令牌变更会立即对运行中的接口面生效——无需重启。

:::note[`GET /sse` 从查询字符串中获取令牌]
通知流和其他所有路由一样会校验令牌，但浏览器的 `EventSource` 无法发送 `Authorization` 头——因此
`/sse` 也接受以 `?token=<token>` 形式传入的令牌。没有令牌时它会返回 401。
:::

## 让每次调用都限定在工作区内

每个涉及工作区范围数据的工具都要求提供 `workspace_id`，缺少它的调用会被拒绝，而不会被解析到某个
“当前”工作区：

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

这个 id 就是你浏览器或应用 URL 中的那个：`/workspaces/<workspace_id>/…`。唯一的豁免是真正跨工作区
的工具，例如 `list_workspaces` 和新闻流工具——新闻流是按用户划分的，而智能体没有自己的用户，因此
这些工具操作的是服务器所有者的订阅源。

仓库范围的工具还会额外检查该仓库是否已关联到该工作区。

## 了解接口面会拒绝什么

- **模式门控。** 调用会在服务器端按发起调用的智能体所在空间的模式进行解析。处于只读模式的智能体
  无法通过省略 `space_id` 来触达写入工具——模式会改为从它的活动运行中查找。
- **操作护栏。** 会改变状态的工具会声明自己的效果类别，并走产品其余部分所用的同一套策略。参见
  [配置护栏](/zh-CN/手册/操作指南/配置护栏/)。
- **确认。** 某些破坏性工具会构建一份确认载荷，必须获得批准后调用才能继续。

完整目录会在 `tools/list` 中公布，没有任何发现层面的门控——外部 MCP 客户端会拒绝调用不在其缓存
列表中的工具，因此隐藏工具只会把它们弄坏，而不是把它们整理干净。

## 故障排查

### 客户端看不到任何工具

- 检查 **MCP 服务器** 卡片是否显示运行中
- 检查端口是否与你的 `cc_server` 端口一致
- 在 Claude Code 上，检查你是否传入了 `--mcp-config` 和 `--strict-mcp-config`

### 从并非服务器的机器上收到 403

尚未配置 Bearer 令牌。配置一个并发送它。

### 工具调用失败并提示 “Missing or invalid argument: workspace_id”

添加 `workspace_id`。不存在隐式工作区。

### 工具调用因未知而被拒绝

[MCP 工具](/zh-CN/手册/参考/mcp-工具/) 列出了完整目录。请完全按照那里出现的名称来调用。
