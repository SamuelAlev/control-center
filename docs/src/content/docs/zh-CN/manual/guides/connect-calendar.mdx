本指南介绍如何将 Google Calendar 连接到工作区。连接按工作区和成员进行：它会将你在该工作区中的事件同步到 Control Center，你也可以在那里回复邀请、创建、移动和删除事件。完整说明请参阅[日历与日程](/zh-CN/手册/概念/日历/)。

## 前提条件

- 服务器可以让人们登录 Google：通过 Control Center Connect，或使用服务器自己的 Google 客户端（[自带 Google 客户端](#自带-google-客户端)）。由服务器所有者在 **设置 → 服务器 → 单点登录** 中选择
- 已打开一个工作区：日历账户始终属于某一个工作区

## 连接账户

1. 在侧边栏中打开**日历**。
2. 在日历侧边栏中点击**添加日历账户**。（同一设置区块也位于**设置 → 工作区 → 个人资料与身份**中的 **Google 日历**下方。）
3. 点击**连接 Google 日历**。你的浏览器会打开 Google 的同意页面。
4. 选择账户，并批准访问你的日历事件与日历列表。

完成方式取决于由谁执行登录：

- **服务器自己的 Google 客户端：** Google 会把你的浏览器送回服务器，对话框随即自行关闭
- **Control Center Connect：** 浏览器页面会显示一个 8 位代码。把它输入对话框，或让浏览器通过 `control-center://` 链接打开 Control Center，从而无需手动输入

你的事件会立即开始同步。完成交换并保存凭据的是服务器，而不是你的设备。

账户只会连接到**当前活动的工作区**，并且归你所有：两位成员如果连接了同一个 Google 地址，会得到各自独立的账户。切换工作区后，你看到的将是该工作区的日历。

连接流程会请求 `calendar.events` 与 `calendar.calendarlist.readonly` 以及 `openid email`，无论由哪个客户端执行。在 Control Center 能够写入 Google 之前连接的账户只有只读作用域；系统会要求你重新连接，新的登录会授予其余部分。

## 创建、移动、回复和删除事件

- **创建事件：** 在周或日视图中，拖动时间网格以框定时段（在月视图中，跨日期拖动可创建全天事件）。旁边会打开一张卡片，可设置标题、时间、嘉宾、Google Meet 链接、地点、描述，以及要在哪个日历上创建。**保存**会在 Google 上创建事件并打开它。日历标题栏中的 **+** 按钮会为下一个空闲的十五分钟打开同一张卡片。按 Escape 可放弃
- **移动事件：** 将它拖到另一个时间或日期，或拖动其底边以更改结束时间。Google 接受新时间后它才会更新；若 Google 拒绝，它会回到原处。你只能移动自己的事件以及你组织的事件；邀请会留在组织者放置的位置
- **回复邀请：** 打开事件并选择**参加**、**待定**或**不参加**
- **删除事件：** 打开事件并点击垃圾桶图标。确认信息会显示受影响的对象：你组织的事件被取消时，嘉宾会收到通知；删除邀请则只会将其从你的日历中移除。删除周期性事件的单次出现时，其余系列会保留

嘉宾会收到 Google 自己的邮件邀请、更新或取消通知。你只能在你的账户有写入权限的日历上创建事件，而且只能使用你自己的账户：绝不会提供其他成员已连接的日历。 移动周期性事件的单次出现同样会保留其余系列。


## 同步的工作方式

日程由**服务器**掌控：它每两分钟扫描一次每个工作区已连接的账户，并把事件写入该工作区的数据库。客户端从不直接与 Google 通信——它们读取服务器写入的内容。

扫描是增量的。每个日历的首次扫描会拉取一个滚动窗口（过去 60 天、未来 90 天）并记录 Google 的同步令牌；此后的扫描会出示该令牌，只收到发生变化的内容，这也是两分钟的节奏得以可行的原因。该窗口每 24 小时重新完整同步一次，每当 Google 使令牌失效时也会如此。

凭据存放在服务器端的 `secrets.json` 中，位于服务器的数据目录下，仅所有者可读写（`0600`）——不在操作系统钥匙串中，也绝不会出现在客户端设备上。通过 Connect 的登录只保存一份封存的凭据，该凭据只有 Connect 能为本服务器打开；访问令牌保留在服务器的内存中。

## 连接多个账户

一个工作区可以连接多个 Google 账户（例如工作和个人账户）。为每个账户重复连接步骤即可；它们的事件会合并到同一个月／周／议程视图中。每个账户独立同步和刷新，也可以单独断开连接。

## 重新连接过期的账户

如果 Google 永久性地使某个账户的登录失效（会话被撤销或长期过期），同步就会停止，Control Center 会在日历上显示**重新连接**横幅，并发送一条桌面通知。点击**重新连接**并再次登录；横幅会在下一次同步成功后消失。

同一横幅也会在本服务器无法再使用该登录时出现：服务器所有者切换了 Connect 服务器或轮换了 Connect 密钥，服务器自己的 Google 客户端发生了变化，或数据目录被还原到了另一台机器上。

## 断开账户

在日历侧边栏（或**设置 → 工作区 → 个人资料与身份**）中，点击该账户上的**断开连接**。这会删除其已同步的事件，并清除服务器上存储的凭据。

## 自带 Google 客户端

当你选择了**使用我自己的应用**时，才运行你自己的 Google 客户端。服务器自己的客户端只在那种情况下适用：使用 Control Center Connect 或自定义 Connect 时，Connect 会运行每个通道（包括 Google），服务器的客户端会保留但不使用。若要在服务器使用 Connect 时让同意屏幕显示你自己的项目，请为工作区提供自己的客户端（[见下文](#为一个工作区提供自己的-google-客户端)）；此设置在任何模式下都适用。

1. 在 [Google Cloud Console](https://console.cloud.google.com/apis/credentials) 中启用 **Google Calendar API** 并配置 **OAuth 同意屏幕**，添加 `calendar.events`、`calendar.calendarlist.readonly`、`openid` 和 `email` 作用域。在应用尚未通过验证时，把你本人添加为**测试用户**。
2. 创建一个应用类型为 **Web application** 的 **OAuth 客户端 ID**。
3. 添加已授权的重定向 URI `<server origin>/oauth/google/callback`。**设置 → 服务器 → 单点登录 → 提供商应用 → Google** 会在**回调 URL**下显示确切的地址；请原样复制。
4. 把**客户端 ID**和**客户端密钥**粘贴到同一个 Google 区块中，或将它们放入服务器的 `.env` 文件，分别命名为 `GOOGLE_OAUTH_CLIENT_ID` 和 `GOOGLE_OAUTH_CLIENT_SECRET`。

当 `GOOGLE_OAUTH_CLIENT_SECRET` 被导出到服务器的进程环境中时，服务器会拒绝启动；请把它保存在 `.env` 文件中（在 Docker 中，把它挂载到 `/app/bin/.env`）。密钥永远不会离开服务器：没有任何 RPC 响应会携带它。只有客户端 ID 而没有密钥属于未完成的配置，在两者都设置之前，Google 登录会被拒绝。

切换到另一个客户端会让所有人退出 Google 日历：登录归属于签发它的那个客户端。

## 为一个工作区提供自己的 Google 客户端

一个工作区可以改用自己的客户端连接 Google Calendar，而不使用服务器的。只有工作区管理员或所有者可以设置。

1. 按上文第 1、2 步创建 Google **Web application** 客户端
2. 前往 **设置 → 工作区 → 通用 → 提供商应用**，打开 **Google Calendar**
3. 选择**使用此工作区自己的应用**
4. 将该行在**回调 URL**下显示的重定向 URI 原样添加到客户端
5. 粘贴**客户端 ID**和**客户端密钥**

此工作区连接的日历账户之后都会通过该客户端，无论服务器以何种方式让人登录。它绝不会回退到服务器的客户端或 Connect：在两个字段都设置完成之前，此工作区的 Google Calendar 处于关闭状态，该行会说明缺少什么。密钥绝不会离开服务器。

在服务器的客户端与工作区的客户端之间切换，或更改工作区的客户端 ID，会让此工作区中的每个 Google 账户都需要重新连接。**使用本服务器的应用**会删除工作区已保存的字段。服务器上的其他工作区不受影响。

## 故障排查

| 现象                                        | 可能原因                                                                                                                                                     |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **连接 Google 日历** 提示登录未设置         | 服务器既没有自己的 Google 客户端，也没有 Connect。由服务器所有者在 **设置 → 服务器 → 单点登录** 中选择其一                                                  |
| Google 显示 `redirect_uri_mismatch`         | 在客户端上注册的重定向与**回调 URL**的值不完全一致，或者服务器的公开 URL 已更改                                                                              |
| Google 返回 `invalid_client`                | 客户端 ID 和密钥来自不同的客户端，或者该客户端已被删除                                                                                                       |
| 批准成功，但同步内容为空                    | 你的账户不是同意屏幕上的**测试用户**，或者未授予任一所请求的作用域                                                                                         |
| 对话框提示代码不匹配                        | 请按浏览器显示的内容，逐字输入这 8 个字符。连续输错五次会结束登录；请重新开始                                                                                 |
| 回复邀请时显示“无法更新你的回复”，或创建、移动与删除失败               | 账户是以旧的只读作用域连接的，请重新连接；仅与你共享为只读的日历也会拒绝写入                                                                                                             |
| 所有人都必须重新连接                        | 服务器或工作区的 Google 客户端发生了变化，或服务器的 Connect 选择或密钥发生了变化。参见[重新连接过期的账户](#重新连接过期的账户)                                            |
