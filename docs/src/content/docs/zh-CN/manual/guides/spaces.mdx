本指南介绍如何使用空间。**空间**是 Control Center 中的消息界面：一个以工作区为范围的房间，
包含一个或多个参与者（你和/或智能体），并为它创建时涉及的每个仓库持有一份写时复制工作树。

一对一的房间和多智能体的房间都只是空间，区别仅在于参与者有多少。唯一的例外是智能体为
彼此交谈而打开的空间——见下文[智能体与智能体之间的空间](#智能体与智能体之间的空间)。

## 创建空间

1. 导航到**空间**
2. 点击“空间”标题旁的 **+** 按钮
3. 为它取一个**名称**——必填项。名称留空会被拒绝；对话框会保持打开
4. 可选地从工作区添加智能体
5. 当工作区中有任何仓库时，选择该空间为哪些仓库预配工作树。默认全部选中；取消选中所有
   仓库会创建一个什么都没检出的空间
6. 确认

空间以工作区为范围：你只能看到当前工作区中的智能体，空间也绝不会显示来自其他工作区的
数据。

每个仓库都会在空间内检出到 `repos/<name>/`。自带智能体技能的仓库会把这些技能提供给在
其中工作的智能体——一次只提供一个仓库的技能集，随智能体的移动而切换。在输入框中，你
可以用 `/skill:<repo>:<name>` 访问其中任何一个。参见
[仓库范围内的技能](/zh-CN/手册/概念/智能体模型/#repo-scoped-skills)。

该界面位于 `/workspaces/<id>/spaces`，单个空间位于
`/workspaces/<id>/spaces/<spaceId>`。

## 设置空间的模式

新空间以默认模式启动。在输入框工具栏最左侧的**模式下拉菜单**中更改它——不是在创建对话框
（那里没有模式字段），也不是在空间标题栏。

| 模式            | 效果                                                                                                  |
| --------------- | ----------------------------------------------------------------------------------------------------- |
| **Agent**       | 完全访问。默认模式；内部名为 `chat`，在下拉菜单中显示为 "Agent"                                       |
| **Plan**        | 仅限阅读和调研；交付物是一份带类型的计划                                                              |
| **Orchestrate** | 阅读和调研，外加一个 `propose_orchestration` 动词；只有在你批准之后计划才会运行                        |

Shift+Tab 可以在计划模式和智能体模式之间切换，无需打开下拉菜单。

还有第四种模式 **审查**，但它不在下拉菜单中提供——它会自动应用到 PR 审查空间。

模式存储在空间上，因此同一个智能体可以在这个空间里处于计划模式，而在另一个空间里处于
智能体模式。空间内的每段对话都共享该空间的模式。

:::caution[留意强制执行徽标]
当空间的智能体运行在一个无法强制执行你所选模式的适配器上时，模式下拉菜单旁会出现一个
徽标。只有 Control Center 的内置运行器会筛选工具面并对每次调用把关；Claude Code 和 ACP
适配器只是把模式当作一项请求接收，它们的运行器可能遵守，也可能不遵守。没有徽标意味着
“没有做出任何断言”，而不是“已验证安全”。
:::

关于完整的模型，参见[模式](/zh-CN/手册/概念/模式/)。

## 管理参与者与每个智能体的自主程度

点击空间标题栏中的人形图标即可打开**管理参与者**。对于已经在该空间中的每个智能体，你
可以：

- 将它移出该空间
- 为它在这个空间里设置**自主程度**：**默认**、**仅提议**、**批准后行动**或**自由行动**

自主程度是逐（空间、智能体）设置的，因此你在一个房间里信任的智能体，在另一个房间里可以
被限制为仅提议。

## 回应消息

将鼠标悬停在一条消息上，点击笑脸图标即可打开回应面板。它是一组固定的六个：👍 👎 🎉 ❤️ 👀 ✅。
没有自由选择表情符号的选择器——点击其中一个就会为你切换它，聚合后的标签会出现在消息
下方。

## 打开对话

一个空间可以同时承载多段对话，它们彼此完全平等——没有主对话一说。空间始终保留至少一段
活动对话：你无法归档最后一段活动对话，而打开一个还没有任何对话的空间会创建一段无标题的
常设对话。

对话会以编辑器标签页的形式出现，数量超过一个时，还会作为嵌套行出现在侧边栏中空间的下方。
**新对话**位于编辑器的新标签页菜单中，它会创建一段无标题的对话、不提示你输入标题——标题
模型会根据第一条消息为它命名。用它可以让同一个智能体和同一份工作树并行推进多项工作。

每段对话都保有自己的消息历史和智能体会话，同时共享空间的工作树和模式。关闭标签页只是
把它隐藏起来；**归档会话**（侧边栏行或聊天标签页的上下文菜单）只归档那一段对话。

## 发起话题

将鼠标悬停在任意消息上，选择**发起话题**。这会打开一段锚定到该消息的对话：锚点用一行
内容为新对话的智能体上下文打底，而父对话的历史**不会**被复制。

一旦某个话题有了回复，它所挂靠的那条消息下方就会长出一行——发过言者的头像、回复条数，
以及最后一条回复的时间。那一行就是重新进去的入口：点击它会打开（或聚焦）该话题的标签页。
它是话题在分出它的那条消息流中留下的唯一痕迹，这也正是它存在的全部理由。

话题标签页的标题为 `Thread: <name>`，并带有分支符号，因此同一个空间上的两个标签页绝不会
被彼此混淆。

话题绝不会嵌套——锚定到已经位于某个话题内部的消息会被拒绝。对话标题栏会链接回锚点消息。
删除锚点消息会删除该话题，而归档父对话不会影响它已有的话题。

## 已读状态

已读标记以空间为范围，而不是以对话为范围：打开该空间中的任意一段对话都会清空整个房间。
未读仍然跨空间的所有对话汇总，话题也包括在内。当对话列在空间下方时，未读圆点会落在有
未读内容的对话上，而不是父行上。

## 智能体与智能体之间的空间

智能体为彼此交谈而打开的空间会在侧边栏的**智能体**下单独分组，默认折叠，并以弱化样式
呈现。它们绝不会增加你的未读徽标——智能体之间的闲聊在构造上就是安静的，而不是靠某个
你得自己去找到的设置。

空间的种类是以下五个值之一：`topic`（你创建的任何空间的默认值）、`agentPeer`、
`system`（由流水线管理）、`pr`（当 PR 界面需要工作树锚点时创建，在有消息之前会从侧边栏
中隐藏）以及 `slack`（由聊天桥接为某个 Slack 话题或机器人私信创建，并被当作普通的人类
对话对待）。
