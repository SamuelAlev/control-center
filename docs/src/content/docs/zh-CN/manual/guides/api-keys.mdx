本指南说明 Control Center 使用的每一项凭据存放在何处，以及如何更换它们。

**你正在输入的设备上不存储任何内容。**所有凭据都存放在服务器上；某个请求由哪一项凭据应答，取决于它背后是否有真人。

| 凭据                                 | 存储位置                                                  | 使用者                                                          |
| ------------------------------------ | --------------------------------------------------------- | ---------------------------------------------------------------- |
| 你的代码托管 / 工单登录              | 服务器的 0600 密钥文件，以你的用户 id 为键                 | 你做的任何操作：PR 界面、评审、合并、你的 Linear 操作           |
| 服务器的提供商应用                   | 同一个文件，非机密项则放在 `server_settings`               | 为人们登录，以及为智能体、流水线和轮询签发的单仓库令牌           |
| Connect 安装密钥                     | 同一个文件（`connect_install_key`）                        | 向 Control Center Connect 标识此服务器                           |
| 模型提供商密钥与 OAuth 令牌          | 服务器自有的凭据存储                                       | 内置适配器，服务于该安装上的每个工作区                            |
| Slack 机器人凭据                     | 服务器上的 `<dataDir>/<workspaceId>/chat_credentials/`     | 该工作区的聊天桥接：你自己应用的令牌，或共享应用的封存授权        |
| 外部 CLI 凭据                        | 该 CLI 自身使用的存储                                      | 服务器主机上的 Claude Code                                        |

## GitHub：你的登录与单仓库令牌

- **你自己的登录**，来自**登录 GitHub**。所有*代表你*发出的请求都用它，因此以你的名义发表的评审会带上你的名字。其他成员无法使用它，他们会自己登录。没有需要粘贴的 GitHub 令牌
- **无人输入时发起的工作**（智能体、流水线、轮询、机器人回复）每次获得一个仅针对一个仓库的令牌，由服务器的 GitHub App 签发，或通过 Control Center Connect 签发，并且只能做负责任的成员在那里能做的事。它绝不是你的登录整体交出的凭据

你自己的凭据在 **设置 → 工作区 → 个人资料与身份** 的**代码托管**卡片中设置；服务器的应用在 **设置 → 服务器 → 单点登录** 的**提供商应用**中设置。参见[设置 GitHub 集成](/zh-CN/手册/操作指南/github-集成/)和[创建 GitHub App](/zh-CN/手册/操作指南/github-app/)。

GitLab 和 Bitbucket 仍然接受粘贴的个人令牌，并以同样的方式存储。参见[连接代码托管](/zh-CN/手册/操作指南/连接代码托管/)。

:::note[还有一个只能通过 URL 访问的界面]
`/workspaces/<workspaceId>/api-keys` 渲染与入门流程第一步相同的两张卡片。它在**界面的任何位置都没有导航入口**；只能通过输入 URL 访问。请改用设置 → 工作区 → 个人资料与身份。
:::

## 设置模型提供商密钥

内置适配器自行完成对提供商的认证，这些凭据存放在服务器上。

1. 前往 **设置 → 服务器 → 模型提供商**
2. 滚动到**提供商与模型**
3. 连接提供商——OpenAI、Codex、Cursor 和 Kimi Code 使用浏览器 OAuth；Anthropic 及其他使用 API 密钥

完整列表以及添加自定义端点的方法，参见[管理适配器与模型](/zh-CN/手册/操作指南/适配器/)。

这些凭据是**主机全局**的：一个密钥服务于该安装上的每个工作区。OAuth 令牌会在过期前刷新。

外部适配器 CLI 在服务器主机上以自己的配置保存自己的凭据——Control Center 不管理它们。请按照 Claude Code 自身文档的说明，在运行 `cc_server` 的机器上完成认证。

每个适配器的**环境变量**对话框看起来像是为其中之一放置密钥的地方，但事实并非如此：它写入你的设备，而服务器读取自己的副本，两者之间没有任何桥接。参见[管理适配器与模型](/zh-CN/手册/操作指南/适配器/)。

## 连接工单系统供应商

**设置 → 工作区 → 通用** 中的**工单系统**卡片包含同一个决定的两半：你的工单存放在哪个提供商，以及 Control Center 在与它通信时代表谁。选择**本地**会隐藏 Linear 相关的行——本地工单存放在该服务器自己的数据库中，没有任何需要认证的对象。

Linear 有两种登录，且不需要粘贴密钥：**Linear** 是你自己的登录，用于你做的操作；**Linear 自动化**是工作区的 Control Center 应用，由管理员连接，用于工单同步、流水线和智能体。对于未连接自动化的工作区，服务器也可以持有一个**服务 API 密钥**（**提供商应用**）。智能体的沙盒中不会注入任何工单凭据；智能体通过 Control Center 的工具写工单，这些工具会询问**写入外部跟踪器**规则。参见[设置 Linear 集成](/zh-CN/手册/操作指南/linear-集成/)。

## 轮换或吊销

- **你的 GitHub 登录**：按**断开连接**，然后再次**登录 GitHub**。断开连接还会丢弃服务器代你签发的所有令牌
- **GitLab 或 Bitbucket 令牌**：按**更新令牌**并粘贴新令牌，然后在代码托管平台上吊销旧令牌
- **服务器的应用**：在提供商的应用页面上生成新的私钥或客户端密钥，粘贴到**提供商应用**中并按**测试**
- **Connect 安装密钥**：在 **Control Center Connect** 卡片上点击**轮换密钥**，或运行 `cc_server connect rotate-key --yes`。所有通过 Connect 登录的人都需要重新登录。参见 [Control Center Connect](/zh-CN/手册/参考/connect/)
- **某个模型提供商**：在其所在行上退出登录（OAuth）或移除密钥，然后重新连接
- **Slack**：对于你自己的应用，在连接对话框中重新粘贴令牌。共享的 Control Center 应用没有可轮换的令牌：它的机器人令牌通过 Connect 续期，而**断开连接**会吊销它，并从 Slack 中卸载机器人。参见[设置 Slack 集成](/zh-CN/手册/操作指南/slack-集成/)

## 故障排查

### GitLab 或 Bitbucket 令牌在 `curl` 中可用，但在这里不可用

检查**代码托管**行的副标题。如果它显示“来自环境”，那么应答的凭据是服务器的，而不是你的——你的凭据没有被保存。

### 令牌被接受，但后续请求失败

令牌在存储时会接受探测，因此该行会显示它背后的账号——但只显示账号，不显示作用域。作用域不足的令牌可以连接，随后却会在个别请求上失败。请在代码托管平台上检查它的作用域和有效期。

### 提供商提示此服务器未设置登录

服务器既没有该提供商自己的应用，也没有 Control Center Connect。服务器所有者可以在 **设置 → 服务器 → 单点登录** 中选择其一。
