本指南介绍如何塑造新闻流：它从哪些来源拉取内容、文章如何阅读，以及内容拦截会做什么。

:::caution[新闻流按用户划分，而不是按工作区划分]
订阅源和文章属于已登录的用户：你的订阅源列表、阅读状态和书签会跟随你进入每一个工作区，也会跟随你到每一台登录过的设备，其他用户看不到它们。订阅源存放在服务器的全局数据库中，因此 `/newsfeed` URL 之所以带有工作区 id，只是因为应用内的每条路由都是如此。
:::

## 阅读文章

1. 点击侧边栏中的 **新闻流**
2. 用工具栏的分段控件在 **全部**、**未读** 和 **已保存** 之间切换
3. 用搜索框或来源选择器缩小列表范围
4. 用布局按钮在杂志式网格与紧凑列表之间切换

打开文章会把它标为已读。使用页面标题栏中的 **全部标为已读**——它只在存在未读内容时出现——一次性清空积压，用卡片上的书签控件把某篇文章留待以后阅读。

布局选择在各次启动之间保持不变。

## 添加订阅源

1. 打开 **设置 → 你 → 新闻流**（新闻流标题栏中的设置图标可直接跳转到这里）
2. 按下 **添加订阅源**
3. 填写**名称**和**订阅源 URL**（RSS 或 Atom）
4. 可选：展开 **高级** 并设置自定义 **User-Agent**——有些出版方会对默认客户端返回不同的响应
5. 按下 **添加订阅源**

检查点：订阅源会出现在 **订阅源** 列表中，它的文章会在首次抓取后到达。已经订阅过的 URL 会被拒绝，并提示“此 URL 的订阅源已存在。”

首次使用时，每位用户都会预置十四个订阅源：Control Center、The Verge、TechCrunch、Hacker News、ByteByteGo、Product Hunt、TLDR AI、Import AI、The Pragmatic Engineer、Martin Fowler、Will Larson 的 Irrational Exuberance、The Engineering Manager、Lea Verou 和 CSS-Tricks。

## 管理订阅源

**订阅源** 列表中的每一行都提供三个控件：

| 控件      | 作用                                                     |
| --------- | -------------------------------------------------------- |
| 开关      | 停用该订阅源。停用的行会变暗，且不再被抓取               |
| 刷新图标  | 立即抓取这一个订阅源                                     |
| 垃圾桶图标 | 删除该订阅源，需要先确认                                 |

列表顶部的 **全部刷新** 会抓取每一个已启用的订阅源。

订阅源的副标题显示它的描述以及上次抓取距今多久；抓取失败的订阅源会在该位置以警告色显示错误信息。

没有任何编辑入口——要更改订阅源的名称、URL 或 user agent，请删除它再重新添加。

抓取完全在服务器上运行：每位用户在启动时抓取一次（之后创建的账号则在首次使用时抓取），此后每 30 分钟一次。

## 在阅读器中拦截广告与跟踪器

1. 在 设置 → 你 → 新闻流 中，找到 **阅读器偏好**
2. 保持 **在应用内打开文章** 开启可使用内置阅读器，或关闭它把文章交给系统浏览器
3. 保持 **拦截广告、跟踪器与 Cookie 横幅** 开启

拦截默认开启。嵌入式阅读器仅支持 macOS 和 Windows：在网页版构建和 Linux 上，系统浏览器_就是_阅读器，文章会在其中打开（网页端为新标签页）。在网页端，拦截开关、**筛选列表**卡片和**受信任站点**卡片会被隐藏。

应用内阅读器不会重排文章。它在嵌入式 webview 中渲染出版方的页面，并借助缓存的筛选列表抑制广告、跟踪器和 Cookie 横幅。

### 检查或更新筛选列表

**筛选列表** 卡片显示已加载多少条隐藏 Cookie、隐藏广告和网络拦截规则，以及它去除的跟踪参数和列表上次更新的时间。按下 **检查更新** 即可刷新它们。

来源包括 EasyList、i-dont-care-about-cookies、Fanboy Cookiemonster、若干 uBlock Origin 列表以及 uBO 的跟踪参数列表。在下载成功之前，卡片会把这些列表标为从未更新过的内置默认列表——广告、Cookie 和网络规则的数量保持为零；跟踪参数去除仍使用一套内置的默认规则。

### 将站点加入允许列表

有些站点在拦截下会出错。

1. 在 设置 → 你 → 新闻流 中，前往 **受信任站点**
2. 按下 **添加受信任站点** 并输入域名

这些站点会跳过拦截。

## 故障排查

### 我添加的订阅源出现在另一个工作区中

这是预期行为。新闻流按用户划分，而不是按工作区划分——你的订阅源会跟随你到所有已登录的地方。参见开头的警告。

### 订阅源行显示错误而非描述

上次抓取失败了，该行会原样显示原因。按下刷新图标重试，并检查该 URL 是否仍在提供 RSS 或 Atom。拒绝未知客户端的出版方可能需要自定义 user agent，这意味着要删除该订阅源再重新添加。

### 文章页面渲染异常

通过 **受信任站点** 为该域名关闭 **拦截广告、跟踪器与 Cookie 横幅**，或关闭 **在应用内打开文章**，改在浏览器中阅读。
