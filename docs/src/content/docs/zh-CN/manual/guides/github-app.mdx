本指南介绍如何为你的服务器创建它自己的 GitHub App。大约需要两分钟，只需服务器所有者来做，且每台服务器只需做一次。

:::note[你可能不需要它]
开启 Control Center Connect 后，人们通过 Control Center 的共享 App，或通过其组织的 Connect 所使用的 App 来登录 GitHub。当你选择了**使用我自己的应用**时才需要注册自己的应用：服务器自己的应用只在那种情况下使用。参见 [Control Center Connect](/zh-CN/手册/参考/connect/)。
:::

之后要登录你自己的账户，请参阅[设置 GitHub 集成](/zh-CN/手册/操作指南/github-集成/)。

## 这个应用做什么

一次注册可以同时回答两项不同的职责：

| 职责                   | 由什么应答                                              | 为什么重要                                                                 |
| ---------------------- | ------------------------------------------------------- | -------------------------------------------------------------------------- |
| **让人们登录**         | 应用的客户端 ID 与客户端密钥                             | 每个人都在服务器上、每台设备上拿到属于自己的 GitHub 凭据                    |
| **由服务器行事**       | 应用的 ID 与私钥                                         | 智能体、流水线、轮询器和机器人回复每次获得仅针对一个仓库的令牌              |

第二项职责从不会整体借用某个人的凭据。服务器签发的每个令牌只覆盖一个仓库，并且只限于负责任的成员在那里能做的事。读取已关联的仓库只需要该应用；任何写入操作都需要一位有推送权限的成员。自动化永远不会批准 pull request。

服务器自己的应用只在选择了**使用我自己的应用**时适用。使用 Control Center Connect 或自定义 Connect 时，Connect 会运行每个通道（包括 GitHub），服务器的应用会保留但不使用，直到你切换回来。工作区自己的应用（[为一个工作区改用其他应用](#为一个工作区改用其他应用)）在任何模式下都适用。如果应用的某些字段缺失，这属于错误，而不是回退：在所有字段都设置完成之前，GitHub 登录会被拒绝。

## 前提条件

- 你是**服务器所有者**。**提供商应用**卡片对其他人不可见
- 一个 GitHub 账户。应用会在它名下创建
- 一个浏览器能够访问的服务器地址。服务器的公开 URL（对于桌面端自己的服务器，则为回环地址）是 GitHub 把你送回的地方

## 一键创建

1. 前往 **设置 → 服务器 → 单点登录**，向下滚动到**提供商应用**卡片
2. 在 **GitHub** 区块中，可选地在**组织（可选）**中输入应该拥有该应用的 GitHub 组织。留空则在你自己的账户下创建；若在组织下创建，则需要该组织的所有者
3. 点击**创建我的 GitHub 应用**
4. 你的浏览器会打开 GitHub，应用信息已经填好。点击**创建 GitHub 应用**
5. GitHub 会把你送回服务器，服务器保存应用 ID、私钥、客户端 ID 与客户端密钥，然后打开该应用的安装页面

整个过程无需手动复制任何内容，转换代码直接从 GitHub 传到你的服务器。该链接只能使用一次，并在十分钟后过期；如果已过期，请再次点击**创建我的 GitHub 应用**。

应用名为 `Control Center <代码>`，并且只请求 Control Center 实际使用的权限：

| 权限                                       | 访问级别       |
| ------------------------------------------ | -------------- |
| Metadata                                   | 读取           |
| Contents                                   | 读取与写入     |
| Pull requests                              | 读取与写入     |
| Issues                                     | 读取与写入     |
| Checks、Actions、Commit statuses           | 读取           |
| Organization members                       | 读取           |

Webhook 处于关闭状态：服务器通过轮询工作。如果你以后想把在自己账户下创建的应用转移到某个组织，请在 GitHub 上该应用的高级设置中使用**转让所有权**。

检查点：GitHub 区块显示“服务器可以自身身份行事，并且人们可以登录”。

## 将它安装到你的仓库所在处

已注册但未安装的应用既无法让人们登录，也无法读取任何内容。

1. 在 GitHub 打开的安装页面上，选择拥有你仓库的账户或组织
2. 选择**所有仓库**，或选择本服务器应该能看到的那些仓库

之后若要把它安装到另一个账户上，工作区管理员前往 **设置 → 工作区 → 通用**，在 **GitHub 身份**卡片中找到 **GitHub 应用安装**，点击**安装 GitHub 应用**。列表会显示该应用已安装到的每一个账户，并标出已被暂停的安装。

## 为组织授权此服务器

在 Control Center 的共享 App 上，某个组织的安装只为其管理员已授权的服务器提供服务。通过**安装 GitHub 应用**进行安装，会授权发起安装的那台服务器。对于已经存在的安装：

1. 该组织的一位管理员在本服务器上登录 GitHub
2. 他们打开 **设置 → 工作区 → 通用 → GitHub 应用安装**
3. 该组织那一行显示**未授权**。他们点击**授权此服务器**

之后该行会显示**已授权**。你自己的应用不需要这些步骤：它的每一次安装都属于你的服务器。

## 改为手动注册

**提供商应用**卡片也可以直接填写你自己注册的应用的各项值：

| 分组                           | 字段                                                                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------------ |
| **以服务器身份行事**           | **App id**，以及**私钥**（完整的 `.pem`，包括 `BEGIN` 和 `END` 行）                              |
| **让人们登录**                 | **客户端 ID** 与**客户端密钥**。**回调 URL** 会显示需要注册的地址，请原样使用                    |
| **PR 对话**                    | **机器人登录名**，在你测试连接时解析                                                             |

请将回调 URL `<server origin>/oauth/github/callback` 按卡片所示原样注册，保持 **Expire user authorization tokens** 开启，并授予上表中的权限。点击**测试**：它会向 GitHub 询问该应用安装在哪些账户上，从而不会把“已保存”与“可用”混为一谈。

## 从服务器的 `.env` 进行配置

对于无界面或脚本化的安装，服务器在某个字段第一次没有已存储的值时，会从其 `.env` 文件中为该字段赋值：

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

请把密钥放在**一行**上：`.env` 的值只占一行，双引号内的 `\n` 会被解码为换行符。当 `GITHUB_APP_PRIVATE_KEY` 或 `GITHUB_CLIENT_SECRET` 被导出到服务器的进程环境中时（所有子进程都能读取），服务器会拒绝启动；请把它们保存在 `.env` 文件中（在 Docker 中，把它挂载到 `/app/bin/.env`）。赋值**每个字段只发生一次**，因此在设置中所做的编辑不会被下一次重启撤销。

## 为一个工作区改用其他应用

工作区可以改用自己的应用，而不是服务器的应用。工作区管理员前往 **设置 → 工作区 → 通用**，在 **GitHub 身份**卡片上选择**改用其他 GitHub 应用**，并填入该应用的 ID、私钥、客户端 ID 与客户端密钥。之后，成员在该工作区中登录的是这个应用。使用自有应用的工作区绝不会回退到服务器的应用或 Connect：在其字段填写完整之前，它的 GitHub 操作会被拒绝。这一点适用于服务器以何种方式让人登录，包括 Connect。

同一页的**提供商应用**卡片对 Google Calendar、Linear 和 GIF 搜索也做同样的事。参见 [为一个工作区提供自己的 Linear 应用](/zh-CN/手册/操作指南/linear-集成/#为一个工作区提供自己的-linear-应用) 与 [为一个工作区提供自己的 Google 客户端](/zh-CN/手册/操作指南/连接日历/#为一个工作区提供自己的-google-客户端)。

## 故障排查

### 创建我的 GitHub 应用时提示服务器没有地址

服务器没有浏览器能够返回的公开 URL。请设置 `CC_SERVER_PUBLIC_URL`（或 `--public-url`）后重试。

### GitHub 提示链接已过期

该一次性页面已被使用，或已经过去十分钟。请从设置重新开始。

### 测试显示凭据可用，但应用没有安装在任何地方

注册与安装是两个独立的步骤。请打开该应用的安装页面，或在工作区的“通用”设置中使用**安装 GitHub 应用**。

### 测试提示无法读取私钥

请粘贴完整的 `.pem` 文件，包括 `-----BEGIN` 与 `-----END` 行。`ed25519` 或 EC 密钥无法使用：GitHub 应用使用 RSA 签名。

### 某个成员已登录，却看不到任何仓库

该应用没有安装在拥有这些仓库的账户上，或其安装选择的仓库不同。登录只会授予该应用被允许看到的内容。

### 智能体提示 GitHub 应用安装已被暂停

有人在 GitHub 上暂停了该安装。请在该账户的 **设置 → 应用 → 已安装的 GitHub 应用** 中取消暂停。
