本指南介绍如何向工作区添加智能体，并把它配置到真正可以运行的程度。

每个工作区在创建时都会预置五个智能体——一名 CEO，再加上 `qa`、`architect`、`engineer` 和 `librarian`——因此你通常在尚未配置任何智能体之前就已经拥有它们。以下步骤对预置智能体和新建智能体同样适用。

## 开始之前

- 你已处于某个工作区内。整个界面位于 **设置 → 工作区 → 智能体**（`/settings/workspace/agents`）。
- 智能体需要一个后端。你可以在 **设置 → 服务器 → 模型提供商** 中为内置执行框架连接一个提供商，也可以在托管 `cc_server` 的机器上安装 Claude Code CLI。
- 如果你希望智能体具备技能，请先在 **设置 → 工作区 → 技能** 中安装它们。智能体表单只能让你开关工作区中已存在的技能。

## 添加智能体

1. 打开 **设置 → 工作区 → 智能体**。
2. 点击 **新建智能体**。

这里不会弹出对话框，也没有角色选择器。系统会立即创建一个名为“未命名智能体”的智能体，并在右侧的详情面板中选中它。

此时你应当能在左侧的名册中看到“未命名智能体”，其详情面板已打开 **设置** 标签页，且 **名称** 字段中包含“未命名智能体”。

## 给它命名

- **名称**——用于 @提及的简短标识符，例如 `alice`。提及解析会匹配 `@` 后紧跟的单词字符，因此包含连字符、点或空格的名字永远无法被提及。
- **标题**——面向人阅读的标签，例如“资深程序员”。
- **系统提示词**——可选的额外指令，会作为 Agent instructions 一节注入；它们不会替换组装后的提示词的其余部分。

点击表单底部的 **保存更改**。本页上的所有字段都由这一个按钮保存。

## 为它配置适配器和模型

**适配器** 下拉菜单会列出服务器主机上实际存在的运行器。内置适配器始终会被检测到（它就是服务器本身）。只有当该主机上检测到 Claude Code CLI 时，Claude Code 才会出现：

| 适配器                    | 后端                                          |
| ------------------------- | --------------------------------------------- |
| Control Center (built-in) | 进程内智能体循环——无需外部 CLI                |
| Claude Code               | `claude -p --output-format stream-json`       |

只有内置适配器会强制执行模式、引导、暂停/恢复、完成契约和子智能体。Claude Code 这些一样都没有。Cursor、Codex 以及其他模型提供商都挂接到内置适配器上，而不是作为独立的运行器。

:::note[适配器为空意味着使用内置循环]
适配器未设置的智能体会被派发到 **Control Center (built-in)**，也就是服务器内部的循环，因此主机上无需安装任何东西。如果模型也未设置，它会向 Anthropic 请求默认模型，所以一个完全未设置的智能体只有在你已连接 Anthropic 账户时才能运行。预置的专业智能体出厂时两者都没有；对于你打算使用的任何智能体，请把两者都设置好。
:::

**模型** 下拉菜单由你所选的适配器决定。对于内置适配器，该列表实时来自你在 **设置 → 服务器 → 模型提供商** 中已连接的提供商，因此没有存储凭据的提供商会贡献零个模型。

## 添加技能

**技能** 是一个芯片选择器，覆盖此工作区中已安装的技能包。点按芯片即可切换；对勾标记表示已选中。如果工作区中没有技能，该字段会显示“No skills available. Create skills in Settings → Skills first.”

你在这里无法选择某个仓库自带的技能。带有技能的仓库（技能位于 `.agents/skills/`、`.claude/skills/` 或 `.opencode/skills/`）会自动把它们贡献给在该仓库中工作的任何智能体，当智能体转到另一个仓库时这些技能就会被替换——参见[仓库范围的技能](/zh-CN/手册/概念/智能体模型/#repo-scoped-skills)。

## 设置汇报关系和角色设定

- **汇报对象**——按名称选择另一个智能体。这会构建页面标题栏中 **组织架构图** 按钮所显示的汇报树。它并不是团队负责人在委派时使用的名册——那名册来自团队的成员及其技能。
- **角色设定**——用于塑造语气和行为的自由文本，例如：“偏好简单、可读的解决方案。为所有新代码编写测试。”

## 调整运行参数

- **推理力度**——可选项来自所选模型自身发布的级别：Low / Medium / High，在 OpenAI 风格的模型上还有 Extra High，在 Claude 风格的模型上还有 Extra High + Max。当所选模型未声明任何思考级别时，该字段会被完全隐藏，并采用模型自身的默认值。
- **上下文窗口大小**——每次更换模型时，都会根据模型的上下文窗口预先填入，并提供一键芯片按钮：模型默认值、200k、500k 和 1M。在你选定模型之后手动输入的值会生效，直到下一次更换模型。
- **静默超时（分钟）**——在这么长时间没有任何输出后终止运行。留空则使用按模式设定的默认值。

## 授予权限

智能体没有自己的权限开关。它能推送、打开、合并或访问什么，由 **设置 → 工作区 → 智能体权限** 中的操作规则决定，你可以在那里把规则限定到这个智能体。默认情况下，推送、pull request、评审或合并以及写入跟踪器都会先逐项询问你，网络访问则是允许的。

智能体的 GitHub 令牌始终是只读的。推送会经由 Control Center，它在转发前询问**推送到远程仓库**规则。每条规则如何作用于一次运行，请参见[配置沙盒策略](/zh-CN/手册/操作指南/沙盒策略/)。

:::note[规则与操作系统沙盒是两层不同的东西]
规则决定智能体可以做什么；操作系统沙盒限制它的进程能在哪里读、写和连接。主机上存在沙盒时，`cc_server` 会把智能体运行包裹在该沙盒中——Windows 没有原生后端，Linux 和 WSL2 则需要 `bwrap` 和 `socat`。完整的边界集合请参见[沙盒与安全](/zh-CN/手册/概念/沙盒与安全/)。
:::

## 验证它能否运行

1. 打开 **设置 → 服务器 → 模型提供商**，确认你选择的适配器报告的是已安装版本，而不是“未找到”。点击 **刷新** 可重新探测——探测在托管 `cc_server` 的机器上运行，而不是在你正在查看的这台机器上。
2. 打开一个包含该智能体的空间并给它发送消息，或者在现有空间中 @提及它。
3. 回到 **设置 → 工作区 → 智能体**，选中该智能体并打开其 **日志** 标签页。应当会出现一条运行记录，带有状态徽标、时长、开始时间以及所使用的适配器。**查看** 会打开该运行的事件流。

如果完全没有出现任何运行记录，请按[诊断智能体](/zh-CN/手册/操作指南/诊断智能体/)逐步排查。

## 删除智能体

在名册中选中它。在 **设置** 标签页上，滚动到表单底部的 **危险区域**，然后点击 **删除**。
