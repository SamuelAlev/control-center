本指南介绍如何创建团队、为团队指定一位负责人，以及把工作路由到团队。

团队是某个工作区内一组具名的智能体，其中一个智能体被指定为团队的**负责人**。把工单分配给团队会唤醒负责人，由它拆解工作并委派给成员；当某个成员的运行结束时，负责人会被再次唤醒，决定接下来做什么。

在 **设置 → 工作区 → 智能体 → 团队** 中创建、重命名团队并为其配备成员。把工作路由到团队有两种方式：智能体带上该团队的 `team_id` 调用 `assign_ticket`，或者由流水线的 **Team dispatch** 节点派发团队（不分配工单）。工单的负责人选择器列出的是你和单个智能体。

## 创建团队

1. 打开 **设置 → 工作区 → 智能体**（`/settings/workspace/agents`）。
2. 点击页面标题栏中的**团队**。
3. 点击**添加团队**。
4. 输入**名称**（例如“backend”或“review squad”），以及可选的**描述**，然后点击**创建**。

团队随即被创建并选中，其编辑器会在右侧窗格中打开。

## 设置负责人

整个功能都取决于这一步。在团队的编辑器中：

1. 在**负责人**下选择一个智能体。帮助文本对它的描述是：“接收分配给团队的工作，并分派给最合适成员的协调者。”
2. 可选地填写**运作说明** —— 随每张路由过来的工单一起交给负责人的自由文本。

把某个智能体提升为负责人时，如果它原本不是成员，也会同时成为成员。留在**无负责人**状态的团队是惰性的：有工作路由过来时不会派发任何东西；把当前负责人从成员列表中移除，团队会再次失去负责人。

## 添加成员

在同一个编辑器中，用成员卡片从工作区添加智能体，或将它们移除。成员就是负责人据以委派工作的名册。

团队以工作区为作用域：只有本工作区中的智能体才能加入。

## 为团队提供空间

团队没有自动创建的空间。如果你需要一个，请从**空间**创建一个普通空间，并把团队的智能体加进去。`Team` 携带名称、描述、负责人、说明和成员 —— 没有空间关联。

## 汇报关系是另一回事

每个智能体还有一个**汇报对象**字段，在 **设置 → 工作区 → 智能体** 中设置。它会构建出工作区的汇报树，你可以在智能体页面用**组织架构图**按钮查看。

它不会驱动团队路由。负责人依据技能和角色，从团队的成员名册中挑选委派对象，而不是从汇报链中挑选。记忆访问授权以智能体的角色为键，而不是以汇报链为键，也没有任何分析界面按团队或层级进行聚合。委派护栏会限制深度并检测环路，但从不要求目标必须是自己的下属。

## 路由过来的工单会做什么

当工单确实带有团队分配时：

1. 团队的负责人会连同该工单、团队的运作说明和成员名册一起被派发。
2. 负责人向成员委派工作，并用 `record_team_activity` 工具记录自己的评估 —— `action`（已委派）、`no_action`（没有更多要做的事，这会停止后续的再次触发）或 `failed`。
3. 每个完成的成员运行都会再次唤醒负责人，并受 no_action 护栏的约束。

流水线的 **Team dispatch** 节点是另一个入口。它接收团队 id、提示词和派发模式：

- `allParallel` —— 为每个成员各创建一个任务并放入同一个共享的隐藏对话，一直挂起到所有运行都完成，每个成员的输出都收集在该节点的输出键之下
- `manager` —— 只派发负责人，由它在对话中进行协调
