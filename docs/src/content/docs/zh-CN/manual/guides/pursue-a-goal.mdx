目标是智能体持续推进、直到满足完成的标准为止的工作。智能体以**段**为单位推进：每一段都是有边界的运行，由服务器一段接一段地启动，即便中途重启也会继续，直到目标通过验证、由人工关闭，或触及某个限制。智能体不能仅凭自己说“已完成”就关闭目标。服务器会先运行目标的检查，再由评审者查看结果。

## 开始一个目标

在对话的输入框中输入 `/goal` 和目标内容：

```text
/goal --budget 20 --days 2 --check "make test" make the importer handle files over 2 GB
```

当消息以 `/goal` 开头并后接文字时，会打开目标访谈。访谈会询问完成的标准、必须通过的检查、边界与停止条件，并可选择单独的检查器、每段从头开始，以及由智能体自行回答它的问题。每一步都可以跳过。

| 标志 | 含义 |
| --- | --- |
| `--budget <dollars>` | 整个目标最多可花费的金额，默认 50 美元 |
| `--max <N>` | 目标最多可包含的段数。默认不设上限 |
| `--days <N>` | 截止期限，即从现在起的天数 |
| `--check "<command>"` | 必须在工作树中通过的命令，才能完成目标。可重复使用，最多 5 个 |
| `--checker <agent>` | 另一个用于评审“目标已完成”这一断言的智能体，按名称或 ID 指定 |
| `--fresh` | 每段都不带对话历史地开始，只依据目标及其笔记 |
| `--unattended wait` 或 `--unattended assume` | 没有人回应时，智能体的问题会如何处理（见[无人回应时](#无人回应时)） |

- 标志可以出现在消息的任何位置。未知标志、重复的标志、错误的值以及超过 5 个检查，都会被拒绝，你的草稿会留在输入框中，并在下方显示原因。
- 目标开头的数字属于目标内容的一部分。要限制段数，请使用 `--max`。
- 只有你亲自输入的消息中的 `/goal` 才会生效。智能体、流水线或唤醒发出的相同文字只是普通消息。
- 一个智能体在一个工作区中同一时间只推进一个目标。第一个目标仍在进行中时，同一智能体的第二个 `/goal` 会被拒绝。

### 完成的标准

目标的指令中可以包含一些章节，它们会成为目标的契约：

```text
/goal make the importer handle files over 2 GB

## Success criteria
- A 3 GB fixture imports without running out of memory
- The progress bar reaches 100%

## Boundaries
- Don't change the public API

## Stop conditions
- A migration would drop data

## Checks
- `make test` (300 s)
- environment task `test` (600 s)
```

- **成功标准**：最多 12 条，每条最多 300 个字符。每条都是评审者能够确认的事项。
- **检查**：最多 5 项。检查在工作树中运行，或作为空间[环境](/zh-CN/手册/操作指南/环境/)中的一个命名任务运行。每项默认有 300 秒，最多 1,800 秒。
- 超出上限的章节会被拒绝，而不会被截断。

没有标准的目标会让智能体自行决定何时完成；没有检查的目标只依赖评审。目标页面会对此作出说明。

## 目标如何继续

每段都是一次运行，其花费上限为 5 美元或预算剩余额度（取较低者）。每段结束后，服务器会根据该段做了什么来决定接下来的步骤：

- **取得了进展。** 下一段随即开始。
- **它在等待自己安排的事项**：定时、监视、向另一个智能体提出的问题，或已委派的工单。目标会等待这些事项。如果没有任何结果到达，服务器会在 20 分钟后再次查看，之后依次为 40、80、160 分钟，然后每 240 分钟查看一次。卡片上显示 **等待其已安排的工作 · 最迟于某个时间再次查看**。
- **没有取得进展。** 进展指该段自身的工作改动了工作树、检查清单有变化，或智能体做了新的事情。连续 3 段没有进展后，目标会暂停，并显示 **最近几段没有任何进展。**
- **等待太久。** 等待满 24 小时，或在其间没有任何进展的情况下又为新安排的事项等待了 6 次，目标会暂停，并显示 **在数段没有进展后等待中。**
- **失败了。** 服务器会在 30 秒后重试，之后间隔变长，最长 15 分钟。连续失败 3 次后，目标即告失败。
- **它向人提问。** 在有人回答之前，目标保持等待：**需要人工处理**。

目标还会在预算耗尽（**预算已用尽**）、段数上限或截止期限时停止。

## 当智能体说它已完成

智能体会针对每条标准提供证据，并声称目标已完成。随后：

1. **服务器运行检查**，在沙箱中运行，绝不直接在服务器所在的机器上运行。以非零状态退出的检查即为失败。无法运行的检查（命令未找到、不可执行、环境中不存在对应任务）属于损坏：目标会停下来等待人工处理，并显示 **此检查无法运行：** 及其命令。若服务器上没有可用的沙箱，目标会停止，并显示 **没有可用于运行其检查的沙箱。**（若服务器所有者为所有运行关闭了沙箱，则属例外：检查会像智能体自己的命令那样在那里运行。）如果检查失败后工作树没有任何变化，则不会重新运行。
2. **评审者查看结果**，前提是所有检查都已通过或没有检查。评审者是目标的检查器；若无，则是空间的检查器；再无，则是目标自身的智能体。它以只读方式运行，没有对话历史：可以读取文件和检查的输出，但不能做任何修改、运行命令或唤醒其他智能体。它还会拿到智能体所修改的测试和检查脚本的完整差异，并且将智能体在对话和笔记中写下的内容视为主张而非证据。对于没有标准的目标，它会就目标整体作出判断。它的结论是：目标已完成、目标未完成，或无法判断。
3. **完成**：目标随之完成。**未完成**：智能体会收到评审者的意见并继续工作。经过 3 轮“未完成”，或评审者无法判断时，目标会等待你的决定：**等待评审：它声称已完成，但尚未得到确认**。

你在评审者运行期间输入的消息不会发给评审者，评审结束时也不会发送。它会排队等待智能体的下一段。若之后没有下一段，它会在 **发送挂起的消息** 下为你保留。

无法运行的评审者（已被删除，或所用适配器无法保持运行为只读，例如 ACP 智能体）会使目标暂停：**其检查器智能体不可用。请选择另一个检查器，然后继续。** 没有其他智能体会在你不知情的情况下接替。

与目标的智能体来自不同提供商的检查器，较不容易与其存在相同的盲点。若没有单独的检查器，智能体会评审自己的工作，目标会记录 **由其自身验证（没有单独的检查器）**。

## 跟进目标

- **在对话中**：**常规**面板中的目标卡片会显示搁置状态、当前段、相对预算的花费、剩余时间、完成的标准、检查，以及最近一次的结论。
- **目标页面**：侧边栏 → **目标**。目标分为 **等待评审**、**进行中** 和 **已结束** 三组。
- **目标详情页**：打开某个目标即可查看 **当前状态**（段数、花费、截止期限、无进展计数以及接下来会发生什么）、**完成的标准**、**验证**（最近一轮：结论、每项检查及其输出，以及针对每条标准的评审），以及 **定时与唤醒**。每个目标都有自己的地址（`/workspaces/<workspace>/goals/<goal id>`），因此你可以分享链接。

在手机上，目标页面可以启动带检查和段数上限的目标，并显示相同的目标与搁置项。

## 更改或停止目标

| 操作 | 谁可以 |
| --- | --- |
| **暂停目标**、**停止目标** | 可访问该空间的任何人 |
| **继续目标**、**提高预算** | 只有发起该目标的人（对于无人发起的目标，则为工作区管理员） |
| **编辑**完成的标准、**更改检查器** | 在目标暂停期间，仅限发起该目标的人（无人发起的目标则为工作区管理员），且对该空间的仓库具有写入权限 |
| **批准完成** | 在目标等待评审期间，可访问该空间的任何人。由流水线发起的目标：仅限发起该运行的人（无人发起时则为工作区管理员） |

- 在智能体的运行上按下 **停止**，会暂停目标（**已由人工暂停**）。其尚未投递的待处理唤醒会一直等待，直到你恢复目标。
- **批准完成**会凭你的确认将目标标记为已完成。目标会记录 **由人工在没有通过检查的情况下关闭**。
- 用完预算的目标只有在提高预算后才能继续。
- 当发起目标的人离开工作区时，目标会立即暂停并等待评审，其正在运行的智能体会被停止。没有人能够继续它；任何有权访问该空间的人都可以停止它。每日摘要会将其列给工作区管理员。

## 无人回应时

当某段向人提出问题或请求批准而无人回应时，请求默认会等待 72 小时。之后，批准视为被拒绝，问题视为未回答，目标会暂停，并显示 **发给某人的问题或批准请求未得到回应。** 提出请求的那次运行不会再得到回答：它之后提出的其他请求会立即被拒绝，它会完成力所能及的部分。工作区管理员可在 **设置 → 工作区 → 定时 → 无人回应时** 中设定等待时间（1 小时至 7 天）。每天在所设定的时刻，你会收到一份摘要，列出所有等待你处理的事项。

使用 `--unattended assume` 时，若 10 分钟内没有得到回答，且其停止条件允许，智能体会说明其假设并继续推进。这只适用于问题。批准永远不会被假定，评审也从不假定任何事情。

## 用量限额与重启

- **提供商的用量限额。** 当某段在提供商的用量限额处停止，且提供商说明了重置时间（在 7 天之内）时，目标会暂停，但不计入失败次数：**已在用量限额处暂停 · 于某个时间继续**。重置后 30 秒会继续。经过 8 次此类暂停后，目标会等待你的处理：**它过于频繁地触及用量限额。请检查后再继续。** 任何一次继续都会重新开始计数。ACP 智能体不报告重置时间，因此它们的目标不会在限额处等待。
- **服务器重启。** 目标在重启后依然保留。被重启中断的某段会重新开始，目标的定时和待处理唤醒也会保留。

## 目标之后的改进

目标通过验证后，一次简短的只读评审（最多 1 美元）可能会提议改进：一条记忆事实、一项策略、关于智能体的一条备注，或对某个技能的修改。输入 `/refine` 可对该对话的工作请求同样的评审。每个对话每 20 分钟最多运行一次评审。

提议会出现在 **改进** 页面上（侧边栏 → **改进**）。打开某项提议即可查看它会改变什么、依据何在，以及 **接受**、**拒绝** 或 **回滚** 选项。

- 在有人接受之前，提议不会改变任何东西。它会在 30 天后过期。
- 对技能的修改，或对整个工作区策略的修改，需要工作区管理员决定（**由管理员决定**）。
- 技能修改会作为单独的修订版本保存。按 **运行评估**，将其与当前技能进行比较；只有评估通过后才能 **接受**。当评估完整运行，且使用该修改时智能体解决的运行次数至少与使用当前技能时相同，即视为通过；页面会同时显示两个数字。如果技能在评估后又有变动，请重新运行评估。
- **回滚**会恢复之前的文本，前提是自那以后没有人改动过它。

## 在流水线中

流水线可以通过 **Pursue a goal** 步骤（`goal.pursue`）启动一个目标。该步骤会等待目标结束，并传递其摘要和结论。参见[流水线步骤](/zh-CN/手册/参考/流水线步骤/)。
