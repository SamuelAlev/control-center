本指南介绍如何把一个 Git 检出注册到工作区、为其重新建立索引，以及再次将它移除。从服务器的文件夹添加仓库需要服务器所有者；移除仓库则需要工作区管理员。

仓库是**以工作区为作用域**的。既没有全局注册表，也没有关联步骤：添加仓库和把仓库放进工作区是同一件事。同一个检出注册到两个工作区后，会成为两条带不同 ID 的独立记录——跨工作区时，仓库的身份是它的文件系统路径，而绝不是它的 ID。

## 开始之前

只有当以下三个条件同时成立时，文件夹才能被注册：

1. 它位于一个 **git 工作树**内。
2. 该工作树配置了一个 **`origin` 远程仓库**。
3. `origin` 远程仓库指向一个**受支持的代码托管平台**：github.com、gitlab.com 或 bitbucket.org。

其他任何情况都会在注册时被拒绝，并给出明确的提示：“文件夹不在 git 工作树内。”“此仓库未配置 `origin` 远程仓库。”或“`origin` 远程仓库未托管在受支持的代码托管平台（github.com、gitlab.com、bitbucket.org）上。”不存在仅限本地的模式。

代码托管平台从远程仓库读取并存储在仓库上——你从来不需要挑选它。一个工作区可以同时容纳来自这三个平台的仓库，而每个平台都通过各自的 API 和自己的凭据通信。GitLab 的嵌套命名空间会被保留，因此 `gitlab.com/group/subgroup/project` 注册后的所有者为 `group/subgroup`，名称为 `project`。

该文件夹还必须位于承载 `cc_server` 的那台机器上，且在服务器某个 `--repo-roots` 目录之内。这份允许列表默认是服务器用户的主目录，越过某个根目录向上浏览会被拒绝。浏览服务器的文件夹只提供给[服务器所有者](/zh-CN/手册/概念/授权/#服务器所有者)，因为它列出的是这台机器自己的文件。其他人在原本 **添加仓库** 按钮所在的位置会看到“服务器所有者从服务器的文件夹中添加仓库。”；而指向其任何工作区都没有的仓库的链接，会说明该仓库未在其任何工作区中关联，并请其请服务器所有者添加它。

检出可以放在哪里，取决于由谁关联它：

- 服务器上**工作区自己的存储**之内：任何工作区管理员。
- 服务器磁盘上的**其他任何位置**：只有[服务器所有者](/zh-CN/手册/概念/授权/#服务器所有者)，因为只有他们可以让服务器指向这台机器自己的文件。其他人会看到“只有服务器所有者才能关联位于此工作区存储之外的文件夹。”
- **服务器的数据文件夹**或其中的任何内容：永远不可以。

检出的 `origin` 必须是你正在关联的那个仓库。`origin` 指向另一个仓库的文件夹会被拒绝，并显示“该文件夹的 origin 是另一个仓库。”

### 服务器暂不使用的文件夹

未由服务器所有者关联、且其文件夹位于工作区存储之外的仓库（例如导入的工作区中的仓库），会在其行下显示“此文件夹位于工作区存储之外。请确认此服务器可以使用它。”，直到服务器所有者确认为止。其他人看到的则是“此文件夹位于工作区存储之外。只有服务器所有者才能确认。”

所有者只需确认一次：在行上点击**确认**，或在列表上方的通知中点击**全部确认**（当有多个仓库在等待时）。每个仓库都会以所有者身份再次检查，检查项与关联它时相同。在确认之前，它会留在列表中，但不会被打开、预配或索引：没有任何编辑器、终端、环境或空间检出会使用它，代码图也会跳过它。以服务器所有者身份再次添加同一文件夹，效果与确认相同，并保留该仓库的 ID。

如果符号链接把检出移到了别处，同样按此方式处理：它会保持列出但不被使用，直到被允许关联其现在所指向文件夹的人再次关联它。

你还需要登录该仓库的代码托管平台，并且你自己的账户必须能够看到该仓库。

## 注册检出

你需要是服务器所有者才能执行这些步骤。

1. 打开 **设置 → 工作区 → 仓库**（`/workspaces/<id>/settings/workspace/repositories`）。
2. 点击 **添加仓库**。

该对话框是一个可导航的浏览器，浏览的是**服务器**的文件系统，而不是你自己的。桌面端、网页端和手机端的流程完全一致，因为原生文件夹选择器会在错误的机器上选取文件夹。

3. 在服务器已配置的根目录范围内导航。属于 git 检出的文件夹会被标记出来。
4. 勾选任意数量的文件夹。导航过程中选择会一直保留，因此你可以从多个文件夹里收集检出。
5. 一次性将它们批量注册。

某一项勾选失败绝不会连累批次中的其余项——你会拿到已创建的 ID，以及每个被拒绝项对应的按路径错误。重新注册本工作区中已存在的路径会返回现有仓库，而不会重复创建一个。

每个注册后的仓库都会出现在列表里，带着它的 `owner/name`、一个标明其代码托管平台的徽标，以及它在服务器上的路径。GitHub 仓库还会显示所有者的头像；其他代码托管平台没有可推测的所有者头像 URL，因此回退为显示首字母。

在混合了多个平台的工作区里，代码托管平台徽标很重要：两个仓库可以在不同平台上都叫 `acme/web`，而它们的行为并不相同——一次审查能做什么，以及链接会指向哪里。

## 接下来会发生什么

注册会触发一个作用域限定在本工作区的 `RepoAdded` 事件，它会为该检出启动 `index_code` 流水线。正是它填充了代码图，让搜索和影响分析有内容可答。

只有语言已有随附语法的文件才会被索引（Dart、JavaScript、TypeScript、TSX、PHP、Python、Rust、Zig、C、C++、Go、Java、Ruby、C#、Swift、Kotlin、R、Assembly、MATLAB 和 Ada）。参见[用代码图搜索代码](/zh-CN/手册/操作指南/代码搜索/)。

## 重新索引仓库

每一行都带有一个 **索引代码** 按钮。点击它即可为该检出重新运行索引器；运行期间，按钮会变成显示已完成文件数与总数的进度读数，并提供一个取消控件。运行结束后，它会定格为一个带符号数量的对勾，如果运行失败则显示警告。

## 重新排列仓库

拖动某一行上的手柄。你设定的顺序，就是应用内每个仓库列表读回时采用的顺序。

## 修正 GitHub 链接

某一行上的链接图标会打开一个编辑器，用于编辑该仓库的 GitHub 所有者和仓库名称。

你很少需要它。链接绑定在仓库在代码托管平台上的永久 ID 上，因此重命名或转移会被自动跟随。

- 在 Control Center 中重命名仓库只会改变其显示名称。
- 更改链接指向的代码托管平台仓库需要工作区管理员，并使用管理员自己的登录对代码托管平台进行核对，与关联它时相同。
- 已关联的仓库不能转为仅本地的仓库。

如果路径之后指向的是一个**不同**的仓库（原仓库被删除后重新创建，或被另一个仓库移动并替换），Control Center 会停止向它发送任何内容：没有令牌、推送、评论或请求。这同样适用于个人自己的操作：在这样的仓库上进行的审查、合并或评论都会被拒绝，GitHub、GitLab 和 Bitbucket 皆是如此。该行和该仓库的 pull request 会显示“_repo_ 现在指向另一个仓库”，直到工作区管理员点击**重新关联**为止。

## 谁可以打开代码

仅有仓库授权并不能打开仓库的文件。要打开其文件、差异、搜索或终端，成员需要拥有 Control Center 授权，并且其自己的代码托管平台登录必须能够读取该仓库。工作区管理员并不豁免；服务器所有者则可以豁免。参见[代码遵循代码托管平台](/zh-CN/手册/概念/授权/#代码跟随代码托管平台)。

当你把某个仓库授予一个代码托管平台账户无法读取它的人时，授权会被保存，你会看到一条警告，例如“已保存。对方的 GitHub 账户目前无法读取此仓库，因此对其保持隐藏。”

同样的规则也决定谁可以打开某个空间。只有能够打开其所用每个仓库代码的成员才能打开该空间，其他人则看不到它，连同其搜索结果、运行日志、待办事项、活动和通知。没有任何仓库的空间对每位成员都开放。参见[空间跟随其仓库](/zh-CN/手册/概念/授权/#空间跟随其仓库)。

## 移除仓库

1. 打开 **设置 → 工作区 → 仓库**。
2. 点击该行上的垃圾桶图标。
3. 确认“从此工作区移除仓库？”

对话框会说明它会做什么：“_名称_ 将从此工作区移除。磁盘上的本地文件不受影响。”

移除仓库需要工作区管理员。它还会忘记为该仓库保存的代码托管平台凭据，例如 GitLab 或 Bitbucket 的自动化令牌。

移除会从本工作区删除该仓库记录，并级联清除它的代码图记录——符号、边、文件和索引检查点——以及针对它的每一项成员级仓库授权、它的空间与仓库关联，还有它的隔离检出记录。同一个检出如果注册在另一个工作区，则是一条独立记录，不受影响。这些记录所指向的磁盘工作树不会因删除而被拆除。

## 故障排查

### 我有授权，但仓库显示我的账户无法读取它

你自己的代码托管平台账户无法读取该仓库，因此即使工作区已授予权限，Control Center 仍会对你隐藏其代码。如果你尚未登录，请在**设置 → 你 → 个人资料 → 代码托管**中登录代码托管平台，或在代码托管平台上向仓库的所有者申请访问权限。一旦你的代码托管平台账户能够读取该仓库，它就会立即打开。

### “此文件夹位于工作区存储之外”

该仓库的文件夹位于工作区存储之外且未由服务器所有者关联，或者符号链接现在把它指向了别处。它会保持列出但不被使用，直到服务器所有者确认它或重新添加该文件夹为止。如果你不是所有者，请向其询问。如果你是所有者，请在该行上点击**确认**，或在列表上方点击**全部确认**；参见[服务器暂不使用的文件夹](#服务器暂不使用的文件夹)。

### “服务器上该路径已不存在任何内容”

该文件夹在服务器的机器上被移动或删除了。把它放回原处，或让工作区管理员在通知中点击**移除**，然后从其当前所在的文件夹重新添加该仓库。

### “此文件夹无法用作仓库”

存储的文件夹是服务器自己的数据文件夹、其中的某个内容，或工作区存储文件夹本身。这些都不能作为仓库。工作区管理员可在通知中点击**移除**将其删除，然后从检出的真实文件夹重新添加该仓库。

### “无法确认你的代码托管平台访问权限”

Control Center 无法联系代码托管平台来核实你的账户能否读取该仓库，因此它选择拒绝而不是猜测。请稍后重试。
