本指南介绍如何使用收件箱：这个唯一的界面汇集了所有阻塞你或明确要求你处理的事情——待处理的智能体审批、失败的工单同步，以及所有将你列为审查者或作者的 pull request。

## 打开收件箱

1. 点击侧边栏中的**收件箱**。它的徽标统计待处理的智能体审批、失败的同步，以及等待你审阅的未关闭 PR。
2. 或者按下 <kbd>⌘K</kbd> 并运行**收件箱**导航命令。
3. 或者直接深链到 `/workspaces/<workspace-id>/inbox`。

侧边栏条目始终显示实时数量，因此无需打开页面，你就能看到待分拣的工作在不断累积。

## 一眼看清严重程度

从上到下浏览；收件箱已按紧急程度排序：

1. 固定的**需要你处理**提示条位于 PR 分区之上。每张卡片都带有一个严重程度标签。已注册的来源（卡在确认提示上的智能体、厂商镜像已过期的工单同步）会标记为**阻塞**。
2. 提示条内，严重程度最高的排在最前；相同则等待时间最长的条目优先。
3. 提示条下方，PR 被归入固定的审查生命周期分区——**等待你审阅**、**已退回给你**、**已批准**、**草稿**、**等待审阅者**、**正在合并与最近已合并**、**等待作者**。靠前的分区是需要 _你_ 处理的内容；其余分区反映的是 _你的_ PR 所处的状态。**等待你审阅**包含那些仍然请求了你所属团队的 PR（前提是代码托管平台支持团队；在 GitHub 上，一旦任一团队成员完成审查，团队就会被移除）。

只有当某条目阻塞了某事或明确请求你处理时，它才会进入收件箱。提示条为空且分区列表也为空时，只有在这样的“空”可信时，才会显示**全部处理完毕**。

## 覆盖所有代码托管平台的统一收件箱

如果工作区中的仓库分布在多个代码托管平台上，收件箱会把它们合并成单一信息流——GitHub pull request 和 Bitbucket pull request 会出现在同一分区中，按时间排序而非按厂商分组。行的 `repo #number` 元数据可用来区分它们。

“你的”是**按代码托管平台**分别判定的，因为你在每个平台上都是不同的账户。只有当某个 pull request 与仓库实际所在平台上你的身份匹配时，它才算是你的，或被算作请求你审阅。

宕机或未连接的代码托管平台不会贡献任何内容，也不会影响收件箱的其余部分——单个连接中断绝不会清空整个列表。当所有代码托管平台的登录都仍未解决（**无法确认你的 GitHub 账户**——这段文案仍会点名 GitHub）、当 githubstatus.com 报告故障，或当覆盖已关联仓库的 GitHub App 安装被暂停时，空状态会给出说明，而不是显示**全部处理完毕**。

## 清理需要你处理的提示条

每张提示条卡片都有一个后续操作：

1. 如果卡片是一个待处理的智能体确认，点击**审阅**——你会进入该智能体的空间，并看到它待处理的确认。在那里批准或拒绝（参见[与智能体聊天](/zh-CN/手册/操作指南/与智能体聊天/)）。
2. 如果卡片为某个厂商显示**同步失败**，点击**打开**——你会进入**设置 → 工作区 → 通用**，其中的**同步健康状况**卡片会显示每个连接的上次同步时间、连续失败次数和最新结果。收件箱中只显示每个厂商最近一次失败，因此同步恢复后卡片就会消失。
3. 一旦底层状态解决（智能体得到答复、同步恢复），卡片会自动消失——无需手动关闭。

:::note[这些是每轮确认，而不是治理审批]
“智能体审批”卡片是正在运行的智能体在其自身对话中暂停，就某个操作请求许可。它与智能体通过审批 MCP 工具创建的治理 `Approval` 记录不同——后者在应用中没有任何人工界面，也绝不会出现在这里。
:::

:::caution[同步健康状况为只读]
该卡片用于报告工单同步连接；除**立即同步**按钮外，它无法创建、编辑或重新连接，也没有其他界面能做到这些。未配置任何连接时，它只会显示“暂无同步连接”，新工作区就是这种状态。
:::

## 筛选出阻塞项

1. 在没有文本框获得焦点时按下 <kbd>f</kbd> 打开筛选菜单，或点击工具栏中的筛选按钮。
2. 任意组合选择状态、作者、审查者、内容、仓库所有者/名称、日期范围或快速审查。菜单中的分面计数会显示每个选项匹配多少个收件箱条目。
3. 启用的筛选条件会以标签形式出现在列表上方的栏中；点击标签上的 ✕ 即可移除该条件。
4. 使用左侧导航栏在各分区之间跳转——每个条目都显示实时数量，高亮会跟随你的滚动位置。点击分区标题可折叠你不分拣的分区（例如在清理审查时折叠**草稿**）。
5. 点击列标题（标题、变更或更新时间）可对所有分区排序；再次点击当前列可反转方向。显示选项按钮控制草稿可见性、最近已合并时间窗口、行属性、排序方式和分组（只有按作者分组会改变收件箱布局）。

此处的筛选与 PR 队列相互独立——缩小收件箱范围绝不会改变队列的筛选条件，反之亦然。

## 处理 PR 条目

1. 点击任意行打开 PR 详情页。
2. 如果 PR 位于**等待你审阅**中，请审查并提交你的决定——参见[审查并合并 PR](/zh-CN/手册/操作指南/审查并合并-pr/)。
3. 如果 PR 位于**已退回给你**中（已请求变更或 CI 失败），请从你的检出目录推送修复，或把后续工作交给智能体。
4. 如果 PR 位于**已批准**中，请从详情页合并。
5. 如果你更愿意把审查委派出去而不是自己做，参见[派发审查智能体](/zh-CN/手册/操作指南/派发审查智能体/)和[智能体派发生命周期](/zh-CN/手册/概念/派发生命周期/)。

一旦底层状态发生变化（你的审查提交、PR 合并），分类器会自动把该 PR 重新归入新的分区。

## 撤销误操作

1. 按下 <kbd>⌘Z</kbd> 撤销上一步操作，按下 <kbd>⌘⇧Z</kbd> 重做。
2. 如果文本框获得焦点，⌘Z 会改为编辑该字段的文本——若要撤销应用级操作，请先点击字段外部。

## 就地查看快捷键

在没有文本框获得焦点时按下 <kbd>?</kbd> 打开键盘速查表。它会列出当前路由上所有生效的按键绑定，包括收件箱的 <kbd>f</kbd> 筛选快捷键。完整的键位映射见[键盘快捷键参考](/zh-CN/手册/参考/键盘快捷键/)。

## 通过命令面板操作

1. 在任意位置按下 <kbd>⌘K</kbd> 打开命令面板。
2. 输入**收件箱**可跳转到该页面，或输入 PR 标题——命令面板会列出匹配的 pull request 并打开你选择的那个。
3. 收件箱打开时，运行**复制此页面的链接**来复制该 URL 以便分享。该命令复制的是当前路由，因此只有当你在此页面上时，复制得到的才是收件箱的 URL。

## 按需刷新

收件箱会实时更新，但如果你怀疑数据已过期，请点击工具栏中的刷新控件——它会立即对每个已连接的代码托管平台强制执行一次服务器端扫描，并重新获取已合并/已审查的覆盖信息。图标会一直旋转，直到所有请求都完成。
