工作区中的智能体可以互相提问、咨询专家、请求评审、发送消息或委派工单。这一切都不需要智能体停下来等待：提问的智能体可以继续工作，或结束它的这一轮，并在答复到达时于它自己的对话中被唤醒。

## 向另一个智能体提问

智能体使用 `ask_agent` 提问，方式有两种：

- **等待**（默认）：智能体会阻塞，直到收到答复，默认最多等待 600 秒，至多 1,800 秒。
- **在后台**：调用会立即返回，智能体继续工作。

无论哪种方式，问题都会先被记录，然后才会投递。若调用中没有收到答复，提问的智能体会在另一个智能体的运行结束时被唤醒一次，并附上答复：答复已到达、失败，或在 24 小时内未得到答复而过期。在此过程中，提问者可能会各收到一次（每种至多一次）以下消息：另一个智能体承诺稍后给出答复、它正在等待某人、或它在用量限额处停止了。这些都不算作答复。

`consult_agent`（找来最匹配的专家）、`request_peer_review`（对某项评审结论的再次审视）和 `send_to_agent`（单向消息）都通过同一队列运作。`send_to_agent` 会说明另一个智能体是否已被唤醒、消息是否在其当前运行之后等待，或为何被拒绝。

另一个智能体会将该问题视为来自其他智能体的信息，而绝非必须服从的指令，并且它不能运行斜杠命令。

## 移交工作

- **已委派的工单**（`delegate_task`）会在工单结束时，于其委派时所在的对话中唤醒委派它的智能体。
- **团队成员的运行**：若领导者通过 `@mention` 或消息启动了某个成员的运行，该运行结束时会在领导者唤醒该成员时所在的对话中唤醒领导者。（提问以其答复为准，委派的工单以其工单为准。）
- **后台工作进程**在导演模式（`/vibe`）中将其结果交给导演，而导演继续工作。
- **对智能体的 `@mention`**，以及空间的检查器，都以同样的方式投递，即作为唤醒。

智能体无需提问，也能查看另一个智能体正在做什么：`agent_activity` 会显示另一个智能体的状态、当前工具及其最近的消息，且不会唤醒任何人。

## 限制

无论智能体怎么说，服务器都会强制执行以下限制：

| 限制 | 值 |
| --- | --- |
| 提问与移交所形成的链条可以有多深 | 3 |
| 循环（一个智能体提问另一个智能体，而后者通过其他智能体正在等待前者） | 拒绝 |
| 每个提问智能体的待处理提问数 | 10 |
| 每个被提问智能体的待处理提问数 | 20 |
| 对同一智能体重复提出同一问题 | 10 分钟内拒绝 |
| 一对智能体之间的消息 | 每分钟 10 条 |
| 消息或答复的长度 | 16,384 个字符 |

委派同样受提问智能体的自主权和预算约束：智能体不能把工作交给自主权或资金比它更多的另一个智能体。你亲自发送的消息绝不受此限制。

当被提问的智能体在用量限额处停止时，若重置时间早于提问过期，其运行会等待重置；否则提问会立即失败，并告知提问者原因。

## 查看一个智能体在等待什么

在对话中，**常规**面板的 **提问** 部分会列出智能体向它提出的问题：问给谁、类型（**问题**、**咨询**或**评审**）、提问时间，以及其状态（**等待中**、**已回答**、**失败**、**已过期**或**已取消**），并在适用时显示 **已承诺稍后回答** 或 **在后台**。失败的提问会说明原因，例如 **其运行在提供商的用量限额处停止。**

任何有权访问空间的人都可以 **取消提问**。提问的智能体随后不会被唤醒，另一个智能体的运行也不会被停止。

等待某个智能体的答复、消息和已完成的工作，也会出现在输入框上方的提示条中，并显示该智能体正在等待的其他事项（参见[定时与唤醒](/zh-CN/手册/操作指南/定时与唤醒/#查看正在等待的内容)）。
