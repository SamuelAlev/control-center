本指南介绍设置中与 GitHub 相关的部分。GitHub 是三种受支持的代码托管平台之一。连接 GitLab 或 Bitbucket，以及一个工作区如何混用它们，参见[连接代码托管](/zh-CN/手册/操作指南/连接代码托管/)。

## 前提条件

- 一个 GitHub 账号，且能访问你想处理的仓库
- 一台能够为人们登录 GitHub 的服务器：要么是它自己的 GitHub App（参见[创建 GitHub App](/zh-CN/手册/操作指南/github-app/)），要么是 Control Center Connect——由服务器所有者在 **设置 → 服务器 → 单点登录** 中选择

:::note[凭据存放在服务器上，归属于你]
你正在输入的那台机器上不存储任何内容。你的 GitHub 登录由你的 `cc_server` 持有，以你的用户 id 为键，你登录的每台设备都会使用它：桌面端、Web 端和手机端。同一服务器上的其他成员无法使用它，而登录这件事得由他们自己完成。
:::

## 登录 GitHub

GitHub 只支持登录：没有需要粘贴的令牌。

1. 前往 **设置 → 你 → 个人资料 → 代码托管**（或入门流程的第一步）
2. 在 **GitHub** 行上，点击 **登录 GitHub**
3. 你的浏览器会打开 GitHub。批准该应用

登录的完成方式取决于由谁执行登录：

- **服务器自己的应用：** GitHub 会把你的浏览器送回服务器，对话框会自行察觉登录完成。无需输入任何东西
- **Control Center Connect：** 浏览器页面会显示一个 8 位代码。把它输入对话框，或让浏览器通过 `control-center://` 链接打开 Control Center，从而无需手动输入

检查点：**GitHub** 行显示“已以 _your-username_ 身份登录”。

对话框会拒绝它并非从自己发起的代码或链接，并显示**登录并非从这里发起**。如果有人向你发送了登录链接，请不要继续：完成它会把你的账户连接到他们的服务器。

点击**断开连接**即可移除你的登录。退出 GitHub 登录，或被移出工作区，也会丢弃服务器代你签发的所有令牌。

## 你的凭据代表谁

Control Center 遵循 GitHub 自身的划分：以**人的身份**行事，还是以**应用的身份**行事。

| 发生的事                                                                     | 在 GitHub 上显示为                                          |
| ---------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 你自己做的任何事：评论、审查、批准、合并、请求审查者                           | **你**。GitHub 会将对话中的评论标记为由 Control Center 应用发出；审查及其行内评论不带此类标记 |
| AI 审查、智能体在 PR 对话中的回复和评论、标签、流水线和机器人工作                    | **Control Center 机器人**。在共享的 Connect 应用上，只有当 Connect 运营方已列出此安装时，审查才归机器人所有；否则显示为负责的人 |
| 智能体为你打开的 pull request、它对该 pull request 标题或描述的编辑、它的推送以及它的提交                            | **你**。当启用共同作者署名时，Control Center 会被记为共同作者   |
| 无人请求的工作（定时任务、webhook）                                            | **Control Center 机器人**，其提交的作者同样如此。在 Control Center Connect 上，它从不推送或打开 pull request |

- **你所做的任何操作**只使用**你的**登录，别无其他。如果你尚未登录，应用会要求你登录。没有任何其他凭据可以代替你
- **机器人工作**每次获得一个仅针对一个仓库的令牌，并限定在负责任的成员在那里能做的事之内：即发起请求的成员，否则为工作区所有者。没有推送权限的成员会把它限制为只读。代表某人行事的机器人回复会以 **Control Center (for @login)** 开头
- **智能体通过 Control Center 打开 pull request**，而不是从它们的沙盒中打开，因此该 pull request 归你所有，并且 GitHub 自身的规则会阻止你批准它。Control Center 还会拒绝由发起该智能体工作的人本人给出的批准，以及来自 pull request 作者的批准。对于定时或 webhook 运行，这涵盖了在其启用期间启用其触发器或编辑其流水线的每位管理员。必须由其他人审查。如果 Control Center 无法确认是谁打开了 pull request，或代码托管平台上哪个账户是你的，它会拒绝并请你重试
- **智能体也通过 Control Center 发表评论。** 智能体运行获得的 GitHub 令牌只能读取。当智能体在它正在处理的 pull request 上发表评论时，Control Center 会以机器人身份发布评论；若是有人发起了该次运行，则以 **Control Center (for @login)** 开头。智能体只能在它自己的 pull request 上发表评论：必须是同一仓库中的（不是 fork），且其最新提交由该智能体推送，或是其空间分支的当前提交。智能体评论中的 @ 提及不会通知任何人。智能体还可以在其自己的 pull request 仍处于打开状态时，修改该 pull request 的标题或描述。该修改会按打开该 pull request 的方式进行（若是你请求的运行，则以你的身份），默认先请求批准。pull request 的描述会保留其中的 @ 提及，无论智能体是打开还是修改它，它所点名的人都会收到通知
- **在 Control Center Connect 上，机器人从不推送或打开 pull request。** 在那里推送、创建分支或打开 pull request，需要发起请求的人，并以该人的登录执行。定时任务或 webhook 触发的运行若试图推送，会停止并显示说明信息。若要让无人值守的运行能够推送，请在**设置**中为工作区提供自己的 GitHub App
- **Connect 机器人能做什么。** 使用共享的 Connect 应用时，机器人会评论、加标签并添加反应。只有当 Connect 运营方列出了此服务器的安装时，它才会发布审查（AI 审查、审查评论、请求审查者）。否则，审查会以负责任的人自己的登录发出，并以其名义显示。机器人从不打开、编辑、关闭或重命名 pull request，也不撤销审查，或编辑或删除评论；这些操作需要发起请求的人，以其自己的登录完成。Connect 不会把你组织的安装绑定到某一台 Control Center 服务器：任何一台服务器，只要其中有能推送到仓库且通过 Connect 登录的成员，就能为该仓库获得机器人的评论令牌
- **拥有自己 GitHub App 的服务器或工作区**在上述所有事情上都保留机器人，包括审查
- **自动化永远不会批准** pull request。批准是人的行为

当你关联仓库时，Control Center 会检查你的账号是否能看到它，并在 GitHub App 未安装在其组织上或未包含该仓库时发出警告，同时附上修复链接。关联和取消关联都需要工作区管理员；位于工作区存储之外的检出只能由服务器所有者关联；参见[向工作区添加仓库](/zh-CN/手册/操作指南/添加仓库/)。

仓库关联遵循该仓库永久的 GitHub id，因此重命名或转让无需你做任何事。如果路径之后指向了另一个仓库，Control Center 会停止向它发送任何内容，并显示一条通知，直到工作区管理员点击**重新关联**。

打开仓库的代码（文件、差异、搜索、终端）需要工作区中对它的授权，以及你自己能够读取该仓库的 GitHub 登录。工作区管理员遵循同样的规则；只有服务器所有者例外。

## 集成为你提供什么

| 功能                | 实现方式                                                                                                         |
| ------------------- | ---------------------------------------------------------------------------------------------------------------- |
| PR 列表与详情       | 通过服务器调用 GitHub REST API，使用你自己的登录                                                                 |
| 检查运行            | GitHub Checks API                                                                                                |
| 发布审查            | 一个需要用户确认的步骤，会以你的身份把审查发布到 PR 上                                                           |
| 仓库注册            | 只要检出副本的 `origin` 远程指向 github.com，或指向 gitlab.com / bitbucket.org，就会被接受                       |
| 智能体的 GitHub 访问 | 在运行中，`git fetch` 经由 Control Center 执行，由它以运行永远不持有的只读令牌读取该运行所处理的各个仓库。`gh` 使用只读令牌读取它们，该令牌由 Control Center 在被请求时签发，并在运行结束时撤销。推送、pull request、对它们的编辑以及评论都经由 Control Center |
| 通知提醒            | 服务器端轮询你的 GitHub 通知收件箱，触发“在 pull request 中被提及”和“已请求评审”                                |
| 用户资料            | 资料悬浮卡片，以及按作者筛选 PR                                                                                  |

在更划算的地方，某些路径会改用 GraphQL API 而不是 REST：例如撰写 PR 时选择器所需的分支活动，以及用来判断某条“已请求评审”通知是否仍处于待处理状态的实时审查状态。

## 留意 GitHub 服务中断

当某个提供方降级时，标题栏会显示一个状态标签，涵盖 GitHub、Claude、OpenAI 和 Kimi。**一切正常时它是隐藏的**：它的出现是在报告问题，而不是报告没有问题。

点击该标签会打开一个浮出面板，其中列出每个提供方的状态，并带有一个刷新按钮。这些状态每两分钟会自动刷新一次。

## 了解智能体在 GitHub 上的行为

- 在 GitHub 工作树中工作的智能体会拿到一个仅针对该仓库的令牌。它只能读取代码、issue 和 pull request；评论会按上文所述经由 Control Center。推送会经由 Control Center，它先询问**推送到远程仓库**规则，再用一个智能体从不持有的写入令牌转发推送。参见[配置沙盒策略](/zh-CN/手册/操作指南/沙盒策略/)
- 你发起的工作以你的身份提交。当你请智能体做某事，或在 IDE 中提交时，你就是作者和提交者，所用地址由你的代码托管平台验证：你在 GitHub 登录时的 GitHub noreply 地址，或在 GitLab 与 Bitbucket 上你的登录所报告的邮箱。只有在没有任何代码托管平台为你的地址背书的仓库中，你手动进行的提交才会使用工作区的 Git 身份。如果你未登录该代码托管平台，智能体的提交则改由机器人负责，运行的说明会说明原因
- 无人请求的工作以机器人身份提交。定时或 webhook 运行会以工作区 GitHub App 的身份提交（`<app>[bot]`，附其 GitHub noreply 地址），或在没有 GitHub App 时，或仓库位于 GitLab 或 Bitbucket 上时，以 `Control Center <hi@usectrl.dev>` 的身份提交
- **将 Control Center 列为共同作者**（**设置** → **你** → **提交**）会为另一方添加一条 `Co-Authored-By:` 尾注：在你的提交上记载 Control Center，在机器人的提交上记载为该次运行设置触发器的每个人。除非你将其关闭，否则它一直开启。工作区管理员可以在**设置** → **工作区** → **通用**中用**共同作者署名**为所有人决定此设置；此时你自己的选择会被保存，但在该工作区中不生效。Claude Code 自带的署名始终关闭
- 你的提交可以签名。在**设置** → **你** → **提交**下的**已验证的提交**中选择**创建签名密钥**，并把它的公开部分添加到你的 GitHub 或 GitLab 账户中作为签名密钥；此后，你请求的运行所产生的提交，以及你在 IDE 中做的提交，都会显示为已验证。私钥保存在你的服务器上，因此只要密钥仍在你的账户中，控制该服务器的人就可以代你签名提交；而在 GitHub 上，已显示为已验证的提交在你移除该密钥后仍保持已验证。Bitbucket 没有仅用于签名的密钥：请勿在那里添加该密钥，Bitbucket 上的提交也不会签名。机器人的提交从不签名
- 你在 IDE 的**源代码管理**面板中所做的提交会跳过仓库的 Git 钩子，就像 `git commit --no-verify` 那样；服务器的 Git 则会忽略仓库配置的凭据助手、编辑器、外部差异工具和签名程序：它在自己的机器上运行 Git，操作的是一个智能体或 pull request 可以更改的工作树。参见[从源代码管理提交与推送](/zh-CN/手册/操作指南/审查并合并-pr/#从源代码管理提交并推送)
- 智能体推送的每个提交都会先经过检查，包括 `stack_publish` 为堆叠推送的各层。推送若指明他人、去掉或借用某个署名、添加 sign-off，或未按你的设置签名，都会被拒绝。你自己从 IDE 推送的提交属于你，不会以这种方式检查
- 在机台上打开的终端会获得你自己的登录，并限定到那一个仓库，因此在那里的推送归你所有
- 当无法签发令牌时（没有可负责任的已登录成员、应用未安装在所有者账户上，或安装已被暂停），请求令牌的命令会说明原因。没有任何回退凭据

## 故障排查

### PR 列表为空，并提示 GitHub 未连接

你在这台服务器上还没有登录 GitHub。请在**设置 → 你 → 个人资料 → 代码托管**下点击**登录 GitHub**。其他托管平台上的仓库不受影响。

### GitHub 行提示此服务器未设置登录

服务器既没有自己的 GitHub App，也没有 Connect。服务器所有者可以在 **设置 → 服务器 → 单点登录** 中选择其一：**创建我的 GitHub 应用**大约只需两分钟。参见[创建 GitHub App](/zh-CN/手册/操作指南/github-app/)。

在选择了自有应用的工作区中，该行会说明工作区的 GitHub App 缺失或不完整。工作区管理员在 **设置 → 工作区 → 集成** 中的 **GitHub 应用**卡片里补全它；参见[为一个工作区提供自己的应用](/zh-CN/手册/操作指南/github-app/#为一个工作区提供自己的应用)。

### 对话框提示代码不匹配

请按浏览器显示的内容，逐字输入代码：8 个字母和数字。连续输错五次会结束登录；请重新开始。

### 登录提示应用未安装

GitHub App 在拥有该仓库的账户上没有安装实例。工作区管理员可以在 **设置 → 工作区 → 集成 → GitHub 应用安装** 中点击**安装 GitHub 应用**进行安装。

### 每个人都必须重新登录 GitHub

服务器所有者轮换了服务器的 Connect 密钥、切换了 Connect 服务器，或数据目录被还原到了另一台机器上。通过 Connect 完成的登录只与产生它的那台服务器绑定。

### 添加仓库被拒绝

注册需要同时满足以下三项：该路径位于一个 git 工作树内、它有一个 `origin` 远程，并且该远程指向受支持的托管平台（github.com、gitlab.com 或 bitbucket.org）。`origin` 必须是你正在关联的仓库，而位于工作区存储之外的文件夹只能由服务器所有者关联。参见[向工作区添加仓库](/zh-CN/手册/操作指南/添加仓库/)。

### 我有授权，但仓库显示我的账户无法读取它

你的 GitHub 账户无法读取该仓库，因此即使有工作区授权，它的代码对你仍然是关闭的。请在**代码托管**下登录 GitHub，或在 GitHub 上请求该仓库的访问权限。

### “无法确认你的 GitHub 访问权限”

GitHub 无法访问以检查你的权限，因此 Control Center 拒绝了该请求，而不是去猜测。请稍后再试。

### Connect 上的审查显示为我的名字，而不是机器人的

在共享的 Connect 应用上，只有当 Connect 运营方列出了其安装时，机器人才会发布审查。在其他情况下，审查会以负责任的人自己的登录发出。若要让机器人发布审查，请为工作区提供自己的 GitHub App。

### 重度使用后一切会停止工作一段时间

那是限流熔断器。GitHub 用带有 `x-ratelimit-remaining: 0` 的 `403` 以及重置时间来表示它的主要限流；客户端一旦看到，就会在窗口期结束前不再发起网络调用、直接在本地让后续请求失败，因此重试风暴无法加深限流。瞬时故障会以指数退避最多重试三次，并遵循 `retry-after`。
