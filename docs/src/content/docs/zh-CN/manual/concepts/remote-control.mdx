Control Center 是一款桌面应用，但它所跟踪的工作不会在你离开书桌时停下来。
**远程控制**借助 **[Remote](https://remote.usectrl.dev/)**——位于
remote.usectrl.dev 的伴侣应用——把你的手机与 `cc_server` 配对，让你可以在那里
跟进机群：通过端到端加密连接阅读消息与工单、回复智能体、分拣新闻流。手机与
`cc_server` 是受信任的明文端点；中继只承载已加密的应用记录。

可以把它看作主界面的伴侣应用，以读取为主。它并不打算取代完整的桌面客户端。

:::note[两种不同的远程客户端]
手机伴侣和完整的 **Web 构建**（或指向远程服务器的桌面端）都可以直连
`cc_server`，也可以使用经代理中转的 WebSocket 中继。两条路径都要求同一套加密
会话；手机暴露的操作比完整客户端更少。客户端之间的区别见
[部署与客户端](/zh-CN/手册/概念/部署/)。
:::

## 传输方式

手机通过 WebSocket 访问 `cc_server`：要么是直连（回环、LAN、tailnet 或
`wss://`），要么是信令代理上需邀请才能加入的房间。两条路径都要求经过身份验证的
端到端加密会话；代理只转发自己那些已加密的记录。这里没有点对点的数据通道。

## 手机能做什么

已配对的手机只能触达服务器表面里很小、且有意划定的一块：

- **读取**工单、智能体、空间及其消息，以及你的新闻流
- **回复**：在空间中发送消息、更新或分配工单、把文章标为已读或已保存
- **运行剧本**：用参数实例化一个已保存的计划模板。它只会_提出_一个计划；在
  操作者在完整客户端的 Plan Studio 中批准之前，不会有任何执行或花费
- **切换工作区**，在手机自己的选择器里

大致就这些。相比完整客户端，手机是**权限更低的主体**。它不能启动进程、消耗
LLM 预算、推送到 GitHub，也不能创建工作区。它为何是被真正强制执行而不只是设计
意图，见[访问模型](#访问模型)。

## 链路是如何建立的

当手机无法直连服务器时，连接会依托一条**经代理中转的中继**：服务器作为所有者
加入 `wss://` 代理上一个需邀请才能进入的房间，已配对的客户端凭有期限的准入令牌
加入。有三部分共同起作用：

| 组成部分             | 作用                                                                                                                                                                                                                                                          |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Remote（手机应用）** | 伴侣 Web 应用，默认托管在 `remote.usectrl.dev`，也可自托管。它在浏览器中加载，把配对记录保存在 IndexedDB 中。                                                                                                                                                 |
| **中继代理**         | 一条无状态的 `wss://` 中继（`cc_signaling_server`），托管 N 方房间。它转发已加密的记录，既没有配对密钥也没有应用明文，但能看到路由标识符、IP、记录大小和时序。                                                |
| **`cc_server`**      | 房间的所有者。它通过其他所有客户端所用的同一个调度器来应答手机的调用。                                                                                                                                                                                        |

一次配对邀约携带一个**连接描述符**，列出通往服务器的每条路径（LAN、tailnet、
公共 `wss://`、中继）以及服务器的身份指纹。手机的解析器会选出最好的可达路径。
服务器会为加密握手签名，客户端则固定其指纹。首次连接时，请对照二维码或另一个
可信来源检查该指纹：仅凭首次出现的已签名身份，并不能证明你连到的是哪台服务器。
指纹一旦变化就会被拒绝，而不会悄然再次获得信任。不存在直连路径时，中继会承载
密文，但它仍能中断或延迟连接。

## 配对负载是什么

配对凭据由应用生成，并以深链接的形式交付；具体步骤见
[配对设备](/zh-CN/手册/操作指南/配对设备/)。这里重要的是它的结构。

```
https://<pwa-host>/#<payload>
```

负载位于 URL 的**片段**中，也就是 `#` 之后、浏览器在发给 PWA 主机的 HTTP 请求
中不会包含的那一段。它携带了手机访问服务器并证明自己身份所需的一切：连接描述符
（每条路径加上身份指纹）、一个新生成的设备 id、一个 32 字节的预共享密钥，以及
一个过期时间戳。手机会解码它，在本地保存配对记录，并从 URL 中去掉片段。Web 应用
的代码可以读取该片段，因此请使用可信的应用主机，并把链接当作机密对待。

负载有两种形态，二者**不可互换**。从应用内配对面板生成的手机二维码就是上面那种
v2 `PairingPayload`，指向 Remote PWA 主机。`cc_server pair --client-url` 发出的
是 v1 链接（`{s, i, k}` —— 服务器 URL、设备 id、密钥），只面向
**Web** 客户端。这些是配对数据格式，而非传输方式的降级路径：两种客户端都必须
支持当前的加密会话协议。

两者的有效期也不同，这一点很容易搞错：

| 生成方式                              | 凭据有效期                                |
| ------------------------------------- | ----------------------------------------- |
| 应用内配对面板（`pairing.mint`）      | 始终为 30 天                              |
| 命令行上的 `cc_server pair`           | 未编码过期时间；服务器策略仍然适用        |

服务器全局的最大设备时长与空闲超时策略可能会更早地拒绝这两种凭据。两种配对格式
都不会绕过这些策略。

## 访问模型

已配对的设备是**经过身份验证但不受信任**的。若干相互独立的关卡，让一次获批
（或泄露）的配对不会变成对服务器的完全控制。

### 1. 边界是成员身份，而不是配对

有效的配对密钥只能证明你是_哪台设备_。你可以读取或修改什么，由你的**工作区
角色**决定——每次调用都会重新解析——凡涉及仓库内容的操作，还要看按仓库授予的
权限。设备持有完全有效的密钥，但其所属用户不是所指定工作区的成员时，会被拒绝并
提示 “Not a member of this workspace”。

角色下限由操作的类型推导，除非操作自己声明：读取需要 `guest`，变更需要
`member`，破坏性操作需要 `admin`。

### 2. 手机属于更低的会话层级

除角色检查之外，手机会话所携带的能力也低于桌面端或 Web 会话。声明为仅限完整
客户端的操作，会在处理程序运行之前就对手机拒绝，无论其背后的用户权限多高：生成、
列出、重命名和吊销设备配对；读取和设置隧道连接；服务器备份与工作区导出/导入；
进程检测与终止；适配器探测；服务器设置；SSO 管理；机群控制；以及接管或交回
正在运行的智能体。

### 3. 默认拒绝的工具允许列表

具体到 MCP 工具面（`tools/call`），哪些工具可以被手机调用，由一份默认拒绝的
允许列表决定。未列入的工具在运行之前就会被拒绝。这份列表以读取和观察为主，另加
少量**仅限本地**的写入——一条消息、一次工单更新、一个文章标记——它们不消耗
LLM 预算、不启动进程，也不接触任何外部系统。

例如被拒绝的有：向智能体咨询、启动 AI 审查、终止智能体、把审查发布到 GitHub、
招聘或解雇智能体、创建工作区。

### 4. 按调用限定工作区范围

服务器**不**保存“当前工作区”。它按设计是无状态的：每个以工作区为作用域的调用
都必须在其参数中给出目标的 `workspace_id`，一旦缺少该参数，或它指向一个服务器
未注册的工作区，调度器就会直接拒绝这次调用——这发生在任何数据库被打开之前。
因此手机永远无法继承或漂移到另一个客户端的作用域，指定一个外来的工作区也没有用，
因为第 1 道关卡里的成员身份检查仍然适用。这与产品其余部分强制执行的
[工作区隔离](/zh-CN/手册/概念/工作区/)是同一个不变式。

### 5. 直连与经中继连接上的端到端加密

每个直连或经中继的客户端会话都要求经过签名的 Noise 握手。配对密钥为该握手提供
身份验证；由新的临时密钥派生出流量密钥，而不是用配对密钥去密封每一帧。服务器
把自己的身份签入这次交换，客户端则校验自己保存的指纹固定值。不存在明文或旧客户
端的降级路径。中继准入令牌只能让客户端进入房间；它无法解密那些记录。

由应用生成的凭据有 30 天的期限；超过之后，连接关卡会判定它失败，手机必须重新
配对。吊销是实时的：服务器监视设备表，会在几秒内断开已吊销设备的现有会话，而不是
等它下次连接。

### 6. 按主体限流

滑动窗口限流器把远程工具流量限制在每分钟 120 次调用，并对变更类操作再加一个更严
的每分钟 30 次子上限。配额属于**主体，而不是会话**：你的三台设备共用同一份额度，
因此被劫持的客户端无法通过多开会话来换取余量，一个吵闹的成员也无法让其他人挨饿。

### 7. 无法读取应用内容的代理

中继代理托管临时的、需邀请才能加入的房间，并转发已加密的记录，其中既没有应用
明文也没有配对密钥。但它仍能看到 IP 地址、房间与对等方标识符、记录大小、时序和
连接存续时间，还能丢弃或延迟流量。明文端点是已配对的客户端和所选定的
`cc_server`；服务器运营者以及服务器向其发送内容的服务都能看到那些内容。传输中
的加密并不会加密服务器上的静态数据。

## 实时更新

配对之后，手机会以通知帧的形式收到**实时更新**——新的智能体消息、分配给你的工单、
状态变化——与桌面端自己的通知如出一辙。服务器在把事件转发给某个会话之前，会先
检查工作区成员身份。客户端再把那些已获授权的事件过滤到你当前查看的工作区；这个
显示过滤器并不是访问边界。

## 它在哪里

| 界面                                                                                | 显示内容                                                                                                    |
| ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| **设置 → 你 → 你的设备**（`/workspaces/:workspaceId/settings/you/devices`）         | 已配对客户端及其实时状态，另有**配对新客户端**（网页浏览器、桌面应用或手机）和吊销                         |

同一个面板也能为第二个浏览器或桌面应用生成配对，并不只限于手机——流程完全相同，
只有深链接不同。

::::note
远程控制位于服务器端，且**不**通过 MCP 暴露。手机通过其加密的直连或经中继的连接
与服务器自己的调度器通信；它不是外部服务器的 MCP 客户端。
::::
