**可观测性 → 质量**同时包含针对单个任务的评测套件与成对进行的技能评估活动。技能评估活动衡量的是某个包在特定模型和 harness 下被使用时的表现，而不是它自身的 Markdown 质量。

## 评测套件

**评测套件**是一种工作区级的任务定义，用于针对某个智能体运行：一段提示词、一个目标智能体与模式、可选的准备步骤、一个带固定 SHA 的可选夹具，以及一组评分器。评分器以确定性检查为先；确定性检查无法表达的内容，交由按 LLM 评分标准评判的评判器覆盖。

创建工作区时会预置五个入门套件。它们分别覆盖编排提案、能找出预置缺陷的审查、计划模式保持只读、计划模式产出计划，以及工单往返。预置过程会监听 `WorkspaceCreated`（`workspace.upsert` 或 `workspace.create`），跳过已存在的名称，也不会回填较早的工作区。

### 它们出现在哪里

**可观测性 → 质量**（`/workspaces/<id>/observability`）会列出工作区中的每个套件。

通过 `evals.upsertSuite`、`evals.deleteSuite` 和 `evals.watchSuites` 来创建、列出、编辑和删除套件。质量标签页就是这份列表，而这些操作就是编辑器。

## 技能评估活动

一次活动在相同的任务与执行配置下比较两个分组。候选技能可能缺失、以正常方式可用、被显式加载，也可能与某个较早版本或固定的环境技能清单进行比较。这些方式回答的是不同的问题；强制加载是一种诊断手段，而不是正常发现过程的得分。[技能指南](/zh-CN/手册/操作指南/管理技能/#评估技能)介绍了如何选择对比方式并授权一次带预算的运行。

证据属于一个精确的**整包哈希**：`SKILL.md`、元数据、脚本、引用与资源。服务器捕获已扫描的不可变包，并固定任务集、适配器、提供方/原生模型标识、协议、工具 schema 与环境清单。原生 Claude 活动还会固定托管账户和观测到的 CLI 版本。修改某个引用会使当前证据失效，即使 `SKILL.md` 未变。模型别名记录的是被请求的内容，而不是提供方不可变的权重。

每次尝试都获得全新的上下文、主目录和夹具状态。成对分组除声明的技能干预外，使用相同的策略与任务条件。目标缺失意味着候选技能的元数据与文件不可用，而不是所有背景指令或技能都被移除。在正常发现的对比中，任务提示词不得点名候选技能。

授权、执行、预算和工作区持久化都由服务器负责。客户端选择设置并呈现证据。进度在重新连接后依然保留；取消会保留部分结果，而重启会把未完成的工作标记为已中断，而不是静默重跑付费调用。这些活动不提供针对任意评测套件的独立执行器契约。

## 审慎解读证据

- **正确性由结果决定。** 独立的带类型验证器检查产物和最终行为，而不是智能体自称成功。预期答案保留在候选技能的隔离边界之外；生成的代码在单独隔离的副本中评分。
- **加载与有用是两回事。** 可用性、正文/引用加载以及观测到的脚本使用情况说明了执行过程。读取某个文件并不能证明模型遵循了它的指令；无法观测的访问仍然未知。
- **保留匹配的基线。** 仅凭候选技能一次成功的运行无法确立收益。请纳入可用技能被忽略的尝试、失败的尝试及其成本；不要只保留最好的那次重试。
- **重复运行并不是新任务。** 报告按任务聚类不确定性。样本过小、覆盖缺失、标识漂移和未知花费都不足以支撑采用建议。一次已完成的活动仍可能没有明确结论；未能显示出改善，并不等于证明了等效或回归。
- **检查个别的回归。** 总体收益不得掩盖某个受到损害的任务或未经授权的副作用。安全扫描、运行时安全观测与有用性保持相互独立；更便宜的执行无法弥补质量或安全证据的缺失。
- **不要混合不兼容的结果。** 另一个模型、harness、策略、夹具或技能组合就是另一种配置。请把留出集上的迁移与组合证据同开发用例分开保留。

本地编写的九个试点任务集包含 108 个任务条目，覆盖实用性、按家族划分的路由/安全，以及留出集上的迁移/组合。请选择与技能用途匹配的家族。参考解答和已知的不良输出用于检验验证器；这些夹具并不是对某个公开基准的复现，也不构成任何已安装技能有用的证据。使用脚本化提供方响应进行的实现冒烟运行，不是真实模型上的技能质量测量。

## 执行与证据限制

受控的**内置 harness** 与 **Claude Code** 两种适配器都受支持。隔离与有效的凭据必须在执行前通过检查。内置提供方要求有成文的工具支持、令牌限制和定价；Codex OAuth 验证自己的账户，而不要求单独的 OpenAI API 密钥。Claude Code 使用默认的托管账户、具体的模型 ID 及其原生的 API 等价成本报告。

Claude Code 和 Codex OAuth 使用**用量停止阈值**：正在进行的调用可能超出预算，随后后续调用即停止。这既不是计费的订阅支出，也不是硬性账单上限。使用 API 密钥的提供方保留保守的调用前预留。观测到的未知花费会对每种适配器停止后续调用；不完整的覆盖仍为部分或无明确结论。

Claude 在私有的控制器目录中运行其原生模型循环，内置工具与环境技能均已禁用。它唯一的工具是经过身份验证、归服务器所有的 MCP 桥接，通往内置 harness 所用的同一个受限客体。凭据留在该客体之外。CLI 身份或工具面的变化会使该尝试失效，而不是悄然更换执行器。不支持机群评估和 Windows；工作进程的 Git 探测成功或提示词回显都不算作评估。

macOS 上的隔离会拒绝客体网络和外部文件系统访问，阻止进程脱离，限制 CPU/文件/输出，并清理其拥有的后代进程，但**不强制执行硬性内存配额**。Linux 需要 bubblewrap，并施加地址空间限制。最初的隔离验证测试的是 macOS，而不是 Linux。缺少隔离时绝不会回退到宿主 shell。提供方凭据留在服务器上，位于客体工具之外。

尝试证据会被脱敏，并限制为 256 KiB；一次导出限制为 16 MiB。大型导出会为所有已准入的尝试保留精简的结果/成本摘要，并明确报告被省略或已汇总的轨迹内容。导出和报告都不包含完整的私有来源回放包。合成的安全检查并不能确立实际的防外泄能力，不会覆盖隔离，也不会证明某个技能安全。
