智能体通常一次只调用一个工具。每次调用都是一轮模型交互：智能体请求调用，结果返回到它的上下文中，智能体读取结果后才会请求下一次调用。对于大多属于机械性的工作，例如读取二十个文件以找出真正重要的三个，或检查每一张未关闭的工单是否带有某个标签，这些轮次和大部分上下文都花在了智能体随即丢弃的结果上。

代码模式只包含一个工具，即 `repl`。借助它，智能体可以编写一段简短的 JavaScript 脚本来调用其他工具、循环、筛选并合并它们的结果，并且只返回所需的内容。一次 `repl` 调用就能完成几十轮工具调用的工作，而且只有脚本的答案会进入上下文。

服务器能运行脚本时，每次运行都有 `repl`。无需开启任何设置：参见[当运行有 `repl` 时](#当运行有-repl-时)。

## 脚本能做什么

脚本是纯 JavaScript，写成一个异步函数的函数体，因此 `await` 和 `return` 可以直接用在顶层。每次 `repl` 调用都会启动一个新的空解释器。

- **调用工具。** `await tools.read({ path: "README.md" })` 调用一个工具，并返回其结果；调用失败或被拒绝时则抛出错误。彼此独立的调用可以用 `Promise.allSettled` 一起运行。
- **查找工具。** `ALL_TOOLS` 列出脚本可以调用的每个工具。`searchTools(query)` 按工具的用途查找工具，`describeTool(name)` 返回某个工具的描述和参数，`describeNamespace(name)` 列出某一组中的工具。已连接的 MCP 服务器的工具也可以通过这种方式访问。
- **返回结果。** 只有脚本返回的内容，或传给 `text()`、`image()` 或 `console.log()` 的内容，才会返回给智能体。最多四张图片会送达模型。
- **保存值。** `store(key, value)` 和 `load(key)` 可以在同一对话和同一智能体的脚本之间保存小型 JSON 值。只有脚本运行完成时才会保存这些值。子智能体没有存储空间。
- **向人提问。** `await tools.ask_user({ question, options })` 提出问题并等待回答。
- **使用设备端嵌入。** `models.embed`、`models.rank` 和 `models.classify` 在服务器安装了嵌入模型时使用该模型。
- **等待。** `sleep(ms)` 和 `setTimeout` 在脚本的时间限制内可用。`limits()` 返回脚本运行所受的限制。

脚本没有文件系统、网络、进程、模块或环境变量的访问权限：不能使用 `fetch`、`require`、`import` 或 `process`。唯一的出路是工具调用，而且每次工具调用都要经过与智能体直接发起的调用相同的检查。

脚本在之后失败时，它已经完成的工具调用不会被撤销。

## 智能体直接调用哪些工具

内置智能体的每次运行都会获得同一小组、可以按名称直接调用的工具：

- `repl`，排在最前；
- 文件与 shell 工具 `read`、`write`、`edit`、`search`、`find`、`bash` 和 `read_output`；
- `ask_user` 和 `task`；
- `todo_write`、`search_memory` 和 `send_message`；
- 对话所用[模式](/zh-CN/手册/概念/模式/)交付输出或离开该模式所需的动词，例如计划模式中的 `submit_plan`；
- `search_tools`，前提是某些工具需在首次使用时加载（见下文）。

运行可能使用的其他每个工具都通过以下两种方式之一访问：

- **仅脚本**，适用于脚本可以调用它的情况。智能体通过 `searchTools()` 或 `describeTool()` 找到它，并以 `tools.<name>(args)` 的形式调用。其描述永远不会送达模型，因此不占用提示中的任何开销。如果智能体仍直接调用它，回复会告诉它从脚本中调用该工具。如果服务器无法运行该次运行的脚本，则该工具改为在首次使用时加载（参见[无法运行脚本时](#无法运行脚本时)）。
- **首次使用时加载**，适用于脚本不可调用它的情况。智能体只能看到它的名称；按名称调用它，或通过 `search_tools` 找到它，即可加载它。

有些工具永远不能从脚本中调用，其中包括 `repl` 本身（脚本不能启动脚本）、`eval`、`task`、`checkpoint`、`rewind`、`vibe_*` 动词，以及启动或向其他智能体运行发送消息的工具、创建、裁决或评论审批的工具、更改策略或技能的工具，或退出计划模式的工具。智能体直接调用这些工具。

没有 `repl` 的运行会获得同样的直接调用工具，其余所有工具都在首次使用时加载。[工具上下文与提示缓存](/zh-CN/手册/概念/工具上下文/)解释了无论哪种情况，这组工具为何都相同。

代码模式从不添加对话的模式不允许的工具。模式的工具过滤器先被应用，脚本只能调用剩下的工具。

## 当运行有 `repl` 时

服务器启动时，脚本运行器通过了锁定检查（[脚本如何受到约束](#脚本如何受到约束)），此时每次运行都有 `repl`。没有任何工作区、智能体或服务器设置能改变这一点。在以下情况下，运行仍然没有 `repl`：

- 运行器无法在服务器所在的机器上自我锁定；此时服务器完全不运行任何脚本；
- 服务器是公共演示环境，不运行脚本；
- 该运行不属于任何工作区；
- 无法读取工作区的限制，因为在默认值下运行可能会超出管理员调低的限制；
- 运行的日志无法写入，因为每个脚本都须在开始前记录在其运行之下。

此类运行的所有工具都直接调用。

代码模式适用于内置智能体的运行，以及通过 Control Center 的 MCP 端点访问其工具的智能体，例如 Claude Code。对于 MCP 智能体，它收到的工具列表包含 `repl`、直接工具以及脚本不得调用的工具；其余工具则需从脚本调用。只有由 Control Center 启动并为其保留日志的运行才会在此获得 `repl`；其他任何客户端都会收到除 `repl` 之外的全部工具。

**设置 → 工作区 → 代码模式**页面的**状态**一栏显示本服务器能否运行脚本（**可用**或**不可用**，并附服务器给出的原因），以及已安装的**运行器**版本。**查看代码执行记录**会打开已运行脚本的列表。

服务器所有者无法关闭脚本。所有者可以为其设定上限：同时运行的脚本数量，以及单个脚本可使用的内存（参见[限制](#限制)）。

### 无法运行脚本时

一次运行永远不会因为服务器无法运行其脚本而失去任何工具。当服务器拒绝某个脚本，且原因并非其他任何脚本都无法避免（例如脚本不可用、脚本等待了一半时间仍未获得空闲位置、无法写入其记录、该次运行的工具列表过大而无法交给脚本，或运行器无法启动或无法将自身锁定）时，该次运行在其整个生命周期内都不再使用脚本：

- 内置智能体的运行保留 `repl`，而其仅能从脚本访问的每个工具现在都会在首次使用时加载：智能体可直接按名称调用它，或通过 `search_tools` 找到它；
- 发往 MCP 端点的运行会收到一份包含全部工具且不含 `repl` 的工具列表，其客户端会被告知该列表已变更。服务器会记住最近 1,024 次此类运行；更早的运行则回到使用脚本的状态。

这些工具与之前一样经过相同的模式过滤器、护栏和审批，因此不会有原本不可调用的工具变得可调用。若脚本因自身原因失败（例如抛出错误、达到某项限制或某个调用被拒绝），则不会产生任何改变：该次运行仍继续使用脚本。

服务器还会持续检查脚本能否运行。当运行器启动失败且原因并非脚本本身时，服务器会重新执行其锁定检查，但频率最多为每分钟一次。若检查失败，服务器便不运行任何脚本，并记录与启动时相同的 `code_mode=unavailable` 日志行；此期间启动的运行都不会获得 `repl`。服务器会继续检查，频率同样最多为每分钟一次；一旦检查通过，它便会再次运行脚本，并记录 `code_mode=available` 日志行。只有服务器启动时即失败的检查才需要重启。

## 限制

每个脚本都在限制下运行。工作区管理员可以在**设置 → 工作区 → 代码模式**中的**限制**下更改其中六项（**调整限制**）；智能体只能为单个脚本要求更短的时间或更小的输出预算，绝不能更多。

| 限制 | 默认值 | 范围 | 用尽时 |
| --- | --- | --- | --- |
| 每个脚本的时间 | 5 分钟 | 1 秒至 25 分钟 | 脚本被停止，并告知智能体已超时。 |
| 处理器时间 | 30 秒 | 1 秒至 2 分钟 | 脚本被停止。 |
| 内存 | 256 MiB | 16 MiB 至 1 GiB | 脚本被停止。服务器所有者可以为整台服务器设置更低的上限。 |
| 每个脚本的工具调用数 | 500 | 1 至 5,000 | 后续调用被拒绝，并告知脚本原因。 |
| 同时调用数 | 8 | 1 至 32 | 超出此限制的只读调用需等待轮到。会改变状态的调用始终逐个运行。 |
| 智能体读取的输出 | 10,000 个词元 | 100 至 50,000 个词元 | 输出被缩短为开头和结尾，智能体可按需读取其余部分。 |

脚本等待人工操作的时间（审批或提问）不计入其时间限制。等待期间，脚本不会开始其他工具调用：在等待期间发出的调用，会在你作答之后按顺序开始。

有些限制是固定的：脚本源代码最多 256 KiB，一次工具调用的参数 1 MiB 和 16,384 个值，脚本交给会运行它的内置工具的命令至多 16 KiB（工具名计入其中），交给脚本的单个结果 4 MiB，一个存储值 256 KiB，一个对话和智能体共同存储的全部内容 1 MiB。一次运行同时只运行一个脚本。

脚本的工具查找同样受到限制：`searchTools` 查询最多 1,024 个字符，工具或命名空间名称最多 256 个字符，最多返回 50 条结果，并且在所有查找中至多占用服务器 200 次、共 2 秒的时间；超过后，后续查找都会失败。同一工作区的所有脚本共享 2 秒的查找时间，每过一秒返还四分之一秒。搜索索引会为每个工具平均分配约一百万个字符，先用于其参数名，再用于其描述，并且始终为每个工具的名称建立索引，因此即便在非常庞大的目录中，也仍可按名称找到工具。

服务器所有者还限制服务器上同时运行的脚本数量（`--code-mode-max-processes`，默认为处理器核心数的两倍，最多 16），以及单个脚本可使用的内存（`--code-mode-max-heap-mb`）；等待人工的脚本单独计数，最多为该数量的四倍。当该上限大于一时，单个工作区最多可占用约四分之三的名额，因此任何单个工作区都无法占满所有位置。一次运行及其子智能体合计最多使用其工作区位置的一半（至少一个），因此它们的后续脚本会等待，而该工作区其他运行的脚本则先行执行。参见[`cc_server` CLI 参考](/zh-CN/手册/参考/cc-server-cli/#代码模式)。

## 审批与提问

脚本中的工具调用与直接调用的检查方式完全相同：模式的工具过滤器、[操作护栏](/zh-CN/手册/概念/护栏/)、审批提示和工具自身的检查。脚本无法做到智能体自己调用该工具时做不到的任何事情。

脚本发出的调用需要审批时，审批卡片会显示 **来自智能体正在运行的脚本**，**显示脚本** 会在对话中打开该脚本。为避免脚本用大量卡片淹没你：

- 一个脚本最多可请求审批 10 次，并最多提出 10 个问题；
- 一旦你拒绝了它的某个调用，它之后需要审批的调用会被直接拒绝，而不再询问。

对于内置智能体的运行，由脚本运行的命令引发的审批提示（例如推送）同样计入同一上限，并且在一次拒绝之后同样会停止。子智能体的脚本同时运行时，这类提示会同时计入两个脚本，拒绝它会使两者都停止。

在内置智能体的运行中，外部 MCP 服务器工具的审批不会被记住：每次调用都会再次询问，无论该调用来自脚本还是智能体自己，除非该空间的自主程度设为**自由行动**。脚本引发的每个此类审批提示，都计入它最多可请求审批 10 次的上限。

如果脚本在你作答之前结束，审批卡片会被撤回，此后给出的回答不会批准任何内容。

## 在对话中

`repl` 调用在对话中显示为一行，标题为脚本的描述。展开后会显示脚本及其输出，并在**工具调用**下列出脚本进行的工具调用，同时统计其中运行中、成功、失败、被拒绝、已取消、排队中和已跳过的数量。

### 脚本在对话中如何呈现

工具调用按照脚本的书写结构排列，而不是排成一个长列表。运行器会报告每次调用所在的行与列，应用则读取脚本，找出其中的循环、分支和函数：

- **循环**（`for`、`while`）显示为**循环**分组，分组标题为其第一行；传给 `map` 或 `forEach` 等调用的回调则显示为**每一项**分组。当应用能区分循环的各轮时，会在相邻两轮之间画一条细线。
- **一起运行的调用**使用 `Promise.all`、`Promise.allSettled` 或类似组合器时，显示为**并行**分组。
- **分支**（`if`/`else`、`switch`、`try`/`catch`）为每个分支显示一个分组，分组标题为其条件。
- 脚本定义并调用的**函数**显示为**函数**分组。

分组嵌套在另一分组中时，缩进再加一级，最多八级；更深的分组保持在第八级的缩进。

每个分组标题都会显示其中各次调用目前已结束的情况。调用运行之前，其行会显示工具以及脚本中原样书写的参数：

| 状态 | 含义 |
| --- | --- |
| **排队中** | 脚本尚未执行到此调用。 |
| 运行中 | 该调用正在运行。 |
| 已完成 | 调用已结束；该行显示其结果及耗时。 |
| **已跳过** | 脚本略过了此调用，例如未被执行的 `if` 分支，或脚本在到达此调用之前已结束。 |

写在对同一工具的调用的参数里的调用，报告的位置与该外层调用相同。当应用无法判断外层调用是否真的发出时，其行不显示状态词，而不是**已跳过**。

当一个分组的调用超过八次时，其中间部分会折叠：前两次和最后三次保持可见，所有仍在运行、失败或被拒绝的调用，以及开始循环某一轮的那次调用，也保持可见。每按一次**再显示 N 次调用**，就会再多显示 100 次，并列出被隐藏调用中至多四种工具及各自的数量，最少的排在最前，例如 **再显示 12 次调用** · Bash 1 · Read 11。超过 24 个字符的工具名称会在该按钮标签中被截短。

无法放入脚本中的调用，例如 `then` 回调所发出的调用，会列在树形结构之后的**未能放入脚本中的调用**下。当应用无法读取脚本，或没有调用说明其发出位置时，这些调用会按发出顺序显示为普通列表。

每个调用行只显示工具调用参数和结果开头的各至多 8 KiB；一个脚本的各行合计保存这些摘录达 256 KiB 后，其后的各行只显示工具和调用的结束方式。脚本结束后，**打开记录** 会打开其完整记录；如果找不到记录，则改为打开该次运行中脚本的列表。在运行前即被拒绝的脚本（例如同一次运行中另一个脚本仍在运行）没有记录，也没有链接。

## 记录

每个运行的脚本都会在开始前记录在其工作区中，并在结束时完成记录。**可观测性 → 代码执行记录** 按从新到旧列出它们，并可按结果筛选。记录中的 **本次运行中的脚本** 和 **此智能体的脚本** 链接会将列表缩小到某次运行或某个智能体。记录显示以下内容：

- 脚本、其输出及其控制台；
- 开始时间、耗时、所用的处理器时间和峰值内存，以及它是通过内置智能体还是外部智能体运行的；
- 结束方式，以通俗的语言描述（例如超时、或抛出了未被捕获的错误）；
- 每次工具调用，按顺序列出，附有结果、是否被允许、由人工批准还是被拒绝、人工决定花了多长时间、其参数（已移除机密信息，并截断至 8 KiB）以及结果的大小。结果本身不会保存。

记录会保存每次调用在脚本中的位置，因此其工具调用的排列方式与对话中相同。人工批准的调用在此处永远不会被折叠。

仍在运行的脚本显示为运行中，并列出目前已完成的工具调用；其输出、耗时和资源使用情况会在结束时显示。如果服务器在脚本运行期间停止，记录会在服务器重新启动时关闭，并注明此情况；在记录关闭之前，该工作区不会运行任何脚本。

记录随其运行一同保存：删除运行或其空间会一并删除记录。成员可以看到他们有权打开的空间中的记录。

## 脚本如何受到约束

脚本从不在服务器内部运行。每个脚本都在自己的进程中运行，该进程是随服务器一起打包的一个小程序 `cc_codemode`，它在 QuickJS-NG 引擎中运行 JavaScript。在读取脚本之前，该程序会借助操作系统自身的控制机制将自己锁定：在 Linux 上是系统调用过滤器和资源限制，在 macOS 上是默认拒绝的沙盒配置文件，在 Windows 上是 AppContainer 和作业对象。此后它无法打开文件、使用网络、启动进程或看到其他程序。它启动时没有环境变量，也不持有任何凭据；它唯一的通道是服务器，由服务器应答它的工具调用。

服务器启动时会运行该程序的自检，以检查锁定是否生效。如果该机器上锁定不成立（例如在容器中，其安全配置拒绝了其中某一步），服务器在该机器上不运行任何脚本：没有任何运行会获得 `repl`，并且设置页面会以**不可用**显示原因。脚本绝不会在较弱的隔离下运行。Windows 锁定尚未在 Windows 上实际运行过。

运行器会报告脚本中每次调用的位置，因此该位置仅用于排列对话和记录，从不决定调用是否被允许。

关于锁定的覆盖范围和局限，参见[沙盒与安全](/zh-CN/手册/概念/沙盒与安全/#代码模式中的脚本)。
