Control Center 要回答两个授权问题，而它们截然不同。**“这个人可以调用这个操作吗？”**
关乎人、角色与仓库。**“这个智能体可以造成这种影响吗？”** 关乎操作、参数与影响范围——
后者属于[护栏](/zh-CN/手册/概念/护栏/)。

本页讲的是第一个问题，以及两者都会留下的记录。

## 单一决策点

所有涉及人的授权决策都经由同一个函数得出结果：

```
can(principal, permission, resource) → allow | deny + why
```

一个**权限**的形式是 `<domain>:<tier>`——`tickets:write`、
`members:administer`、`repos:read`。权限目录是**派生**出来的，而不是
手工编写的：它由操作本身计算得出（操作名的前缀给出域，它已经强制执行的
角色下限给出层级），因此全部约 550 个操作都带有权限，无需任何人手动输入。

这一派生机制正是值得保护的特性。它意味着新增操作默认就受到管控——
手工标注模型的失败模式是有人忘了标注，而他们忘掉的恰恰是管控。
有一项棘轮测试会固定由此得到的域集合，因此在新的前缀下新增操作，
是人有意做出的命名决定，而不是一次意外。

这四个层级与内置角色精确对应：

| 层级 | 角色下限 | 示例 |
|---|---|---|
| `read` | 访客 | `tickets:read` |
| `write` | 成员 | `tickets:write` |
| `administer` | 管理员 | `members:administer` |
| `own` | 所有者 | `workspace:own` |

## 角色

五个内置角色——**所有者、管理员、成员、查看者、访客**——是这套目录上的
预设。每个工作区的所有权只有一个席位，需通过**转让所有权**显式移交
（否则离职的所有者将无法被移除：SCIM 取消预配会拒绝任何工作区所有者——
请先移交）。

**自定义角色是减法式的。** 自定义角色会指定一个基础预设（`admin`、
`member`、`viewer` 或 `guest`——绝不能是 `owner`），以及一组从其中
移除的权限——“管理员，但不能管理成员”。它授予的权限永远不会超过其基础
预设，这正是它们可以安全引入现有安装的原因：所有既有检查仍然是可靠的
上界。成员以 `custom:<id>` 的形式持有它们，而无法理解该值的旧客户端
会回退到访客，而不是贸然猜测。

角色之下还有**按仓库授予的权限**（`none` / `read` / `review` /
`write`，见[更改代码需要写入权限](#更改代码需要写入权限)）：工作区成员身份绝不会悄悄给出高于代码托管的权限。所有暴露代码
的界面都会检查这些权限——包括那些以旁路方式触达代码的界面，例如在
空间的工作树上打开的终端或编辑器会话。

## 代码跟随代码托管平台

仅有授权本身并不能打开仓库的代码。要查看其文件、差异或搜索结果，或在其上打开终端，成员需要拥有 Control Center 的授权，**并且**其自己的代码托管平台登录必须能读取该仓库。工作区管理员也不例外；服务器所有者则除外，因为代码检出位于其机器上。没有代码托管远程的仓库只需要授权。

- 当管理员把仓库授予一个代码托管账户无法读取它的人时，授权仍会保存，且管理员会看到一条警告。
- 当无法访问代码托管平台进行检查时，结果是否定的，绝不会猜测：该人会看到“无法确认你的 GitHub 访问权限。请重试。”（带有其代码托管平台的名称），并在稍后再试。
- 拉取请求以及由它们产生的一切都遵循同样的规则。

### 更改代码需要写入权限

仓库授权分为三级，每一级都包含它之前的那一级：

- **read**：查看仓库的文件、差异和搜索结果，前提是你自己的代码托管平台登录也能读取它。
- **review**：包括 read 的全部权限，并可批准、请求修改，以及对其拉取请求执行其他评审操作。
- **write**：包括 review 的全部权限，并可更改代码，以及驱动会写入该仓库的智能体运行。更改代码包括在编辑器中保存或还原文件、将工作树同步到其拉取请求的头部、提交和推送、发布分支，以及用于切分、检出或发布某个部分的堆叠操作。

为某个人所做的每次推送，无论是他本人发起，还是他要求的智能体运行发起，都会在推送时检查他对该仓库的写入权限，GitHub、GitLab 和 Bitbucket 均是如此。发布一个堆叠时，会在推送其中任何一个仓库之前检查堆叠中的每个仓库。

拒绝信息会说明缺少哪一级授权。没有读取权限时，应用会显示“你没有此仓库的读取权限。工作区管理员可以授予。”；有读取权限但没有写入权限时，它会显示“你可以读取此仓库，但无法更改。工作区管理员可以授予写入权限。”

### 空间跟随其仓库

智能体对代码所写的内容随代码一起走。空间的内容（其消息、转录和工具输出、搜索结果、运行日志、待办事项、活动和通知）携带着它所处理的仓库的代码，因此只有对空间所使用的每个仓库都持有读取授权、并且自己的代码托管平台登录能够读取它的成员，才能打开该空间。这些仓库是为该空间选中的仓库，若未记录选择，则为工作区的全部仓库。没有任何仓库的空间对每位成员都开放。

某人无法打开的空间，不会在任何地方为他们列出，包括搜索、运行日志、待办事项、活动和通知。工作区管理员持有每项授权，但在代码托管平台这一半上并不例外；服务器所有者则除外。

对于希望每个人都能阅读的对话，请创建没有仓库的空间，或只关联每个人都能读取的仓库。

## 服务器所有者

设置服务器的人是它的**所有者**。服务器在首次启动时记录他们一次，而通过网络发送的任何内容都不会改变这一点。工作区管理员或工作区所有者并不是服务器所有者：任何人都可以被授予某个工作区，但服务器所在的机器只有一个所有者。

**除非服务器所有者启动了它或批准了这类主机执行，否则服务器所在机器上的任何内容都不会在沙盒之外运行。** 具体而言，只有服务器所有者可以：

- 创建工作区。其他人会看到一个页面，要求他们让所有者创建一个工作区，或由工作区管理员邀请。
- 打开服务器托管终端中的主机 shell。其他人则会得到一个沙盒终端，受智能体的限制，位于工作区自己的目录中。
- 打开内嵌的代码编辑器。它以服务器自己的用户身份运行，并带有其终端、任务和扩展。
- 在原生编辑器中打开拉取请求或某个对话的工作树。该编辑器在服务器自己的屏幕上、以服务器用户的身份启动。
- 保存或批准任何在主机上运行内容的[环境](/zh-CN/手册/操作指南/环境/)定义：主机放置、运行命令的检查，或预配或归档任务。
- 在其机器没有沙盒的服务器上运行智能体。其他人的运行在那里会被拒绝，除非所有者以 `--sandbox off` 启动服务器，此时它会不受限制地运行每位成员的智能体（参见[主机没有沙盒时的智能体](/zh-CN/手册/概念/沙盒与安全/#没有沙箱的主机上的智能体)）。
- 关联位于工作区自身存储之外的仓库检出，确认在该规则之前已关联的检出，并在添加仓库时浏览服务器的文件夹（参见[添加仓库](/zh-CN/手册/操作指南/添加仓库/)）。
- 查看并停止服务器上每一个正在运行的智能体进程。其他人只能查看并停止他们所属工作区中的实时智能体运行。
- 让智能体使用服务器用户自己的工具（Claude、Codex、Cursor 等）中配置的 MCP 服务器。只有所有者负责的内置工具运行才会获得它们；参见[个人 MCP 服务器归所有者所有](/zh-CN/手册/操作指南/mcp-服务器/#个人-mcp-服务器归所有者所有)。
- 确认某人的电子邮件地址，以便单点登录能够匹配它（参见[连接 OpenID Connect 提供方](/zh-CN/手册/操作指南/sso-oidc/#登录如何匹配已有账户)）。
- 更改安装范围的设置：SSO、提供方凭据、MCP 端点及其令牌、模型管理、Connect 以及整个安装的备份。这些操作声明为**服务器专属权限**，对其他所有人一律拒绝。

这里刻意只保留一个操作员身份，以及关于它的唯一定义。

## 审计追踪

每一个授权决策——**无论允许还是拒绝**——都会追加到按工作区划分、
以哈希链串联的审计追踪中。

只记录拒绝的日志能回答“我们拦截了什么？”，却回答不了“这个智能体究竟
做了什么，又是谁授权的？”——而这正是事故复盘要问的第一个问题。因此每条
记录都会写下完整的归属链：执行主体、它所代表的人、它所经由的委派、
操作及其参数（以摘要形式）、决策，以及**作出该决策的规则**。

各条目串成一条链：每条的哈希都覆盖前一条，因此编辑、删除或重排任何一行
都会破坏其后的所有哈希。**验证链**会重新推导整条链，并指出第一个不成立
的环节。无法核验的审计日志只是日志；能重新推导的才是证据。

有两个值得了解的后果：

- 审计表**不受基于时间的清理**。哈希链无法从中间裁剪。保留的做法是先
  导出、再截断，而截断会留下一个携带被移除片段末端哈希的检查点，
  因此留存下来的内容仍能一路校验回起点。
- 它与活动时间线**并列**，而不是叠在其上。时间线记录人做了什么；这里
  记录什么被授权、什么被拒绝。借助共享的关联 id，可以在两者中读懂
  同一次调用。

它导出为换行分隔的 JSON，并可以流式发送到 SIEM（Splunk、Elastic、
Sentinel——一个带 bearer token 的 HTTP 端点）。流式发送按设计就是尽力
而为：SIEM 宕机绝不能阻塞智能体的工具调用，而且无论哪种情况，持久、
可校验的副本都在磁盘上。

## 会话

安装可以设置**最长会话时长**和**空闲超时**。两者都在设备凭据检查处强制
执行，所有经过认证的通道都会汇聚到那里——客户端能无视的会话约束回答的
是问卷，而不是攻击者。安装还可以要求使用 SSO，这会禁用新设备的手动配对
（带有锁定保护：在不存在可用 SSO 连接时会拒绝该设置）。

## 不是什么

- **不是按对象的 ACL。** 这里刻意不提供按工单或按消息的权限。团队真正
  需要的是仓库级隔离，而它已经存在；按对象共享会造成组合爆炸，而这里
  并没有表现出这种需求。
- **不是用 DSL 配置的策略引擎。** 词汇表是刻意封闭的，因此整份策略都
  可以被呈现、解释和枚举。
- **除服务器之外，不在任何地方强制执行。** 客户端检查的存在只是为了不
  提供一个必然会被拒绝的操作入口。权威决策始终由服务器作出。
