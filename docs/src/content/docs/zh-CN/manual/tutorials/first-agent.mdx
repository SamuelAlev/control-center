## 你将构建什么

学完本教程后，你将拥有：

- 一个由你自己创建并配置的智能体
- 一个供你和该智能体对话的空间
- 一次已完成的运行，其中的工作在隔离工作树中已提交，并在该智能体的运行日志中留下一行记录

前置条件：已完成[你的第一个工作区](/zh-CN/手册/教程/第一个工作区/)，因此该工作区中已注册仓库，并连接了至少一个模型提供商。

## 第 1 步：创建一个智能体

1. 打开 **设置 → 工作区 → 智能体**
2. 点击 **新建智能体**。系统会立即创建一个名为“未命名智能体”的智能体，并在名册中选中它——不会弹出创建对话框，也没有任何需要确认的内容。你直接在原地配置它。
3. 在 **设置** 标签页中填写：
   - **名称**：简短好记，例如 `alice`。这就是你在 `@` 后面输入的内容。
   - **标题**：它的职责，例如“后端工程师”
   - **适配器**：`Control Center (built-in)`。请有意选择这一项——只有内置运行器可以在运行中途被引导，并在回合边界暂停，而且它不需要在服务器主机上安装任何 CLI。
   - **模型**：从已连接提供商所提供的列表中选择
   - **技能**：附加任何合适的技能，例如 `testing` 或 `architecture`
4. 点击 **保存更改**

:::note[没有适配器的智能体会在内置循环上运行]
当适配器字段未设置时，派发会回退到 **Control Center (built-in)**——即服务器内部的智能体循环，因此主机上无需安装任何东西。它仍然需要一个模型：若未设置，它会向 Anthropic 请求其默认模型；如果你已连接 Anthropic 账号，这会正常工作，否则会以 `No credential for provider "anthropic"` 失败。无论如何都请显式设置这两项，否则你将在一个并非自己选择的模型上运行。
:::

**检查点。** 名册中该行会显示你的智能体名称，以及一个空心的状态环。

## 第 2 步：启动一个空间

1. 在侧边栏中找到 **空间** 区块，然后点击 **+** 按钮
2. 为该空间取名
3. 在 **添加智能体** 下，选择你刚刚创建的智能体
4. 如果该工作区中有仓库，请选择这个空间应在哪些仓库上工作
5. 点击 **创建**

空间随即打开。在后台，Control Center 会为这段对话在选定的仓库上预配一个写时复制工作树，并使用它自己的分支。你的源检出永远不会被改动。

## 第 3 步：发送一项任务

针对你注册的仓库输入一项具体而微小的任务。最好是结果可核验的任务——添加一个测试、修复一处 lint 问题、重命名一个符号。

按 Enter。你无需 `@` 提及任何人：空间中只有一个智能体时，一条普通消息就能唤醒它。若空间中有多个智能体，用 `@name` 指定其中一个。

Control Center 会根据该智能体的指令、角色设定、技能以及这个空间的上下文组装提示词，然后派发这次运行。

**检查点。** 输入框的发送按钮会变成一个停止按钮——有智能体正在这段对话中工作——文本随即开始出现。

## 第 4 步：看它工作

对话会随着运行的进行实时渲染：

- **推理**，在智能体思考时以内联方式展示
- **工具调用**：文件读写、搜索、shell 命令，每项都带有其结果
- **文本**：摘要、说明以及向你提出的问题

如果智能体提出问题，在对话中回答它，它就会继续。

如果要查看某次运行自身的指标以及它的暂停、继续和停止控件，请在空间的常规面板中的 **智能体** 区块找到正在运行的智能体，然后选择 **打开活动**。

在活动窗格中，状态徽章显示 **运行中**，运行结束后变为 **成功**。停滞或陷入循环的运行显示 **已阻塞**；出错的运行显示 **失败**。在智能体登记表中，名册状态环在首次运行前是空心的，智能体重新回到空闲后则变为实心。

约束这次运行的因素包括：它自己的写时复制工作树、在启动时为其代理并在拆除时撤销的凭据、经过净化的环境、其模式所允许的工具面，以及动作护栏。推送分支或创建 pull request 之类的副作用则单独设置门禁——参见[护栏](/zh-CN/手册/概念/护栏/)。

## 第 5 步：检查结果

1. 打开 **设置 → 工作区 → 智能体**，然后选中你的智能体
2. 打开 **日志** 标签页

**检查点。** 一行运行记录，显示其状态、时长、开始与结束时间，以及它所运行的适配器。

该智能体的改动会提交到这段对话的分支上，位于它自己的工作树中。提交以该智能体作为作者，并通过 `Co-Authored-By:` 尾注为你署名。

## 获取一个 pull request

没有任何东西会自动创建 pull request。如果你想要一个，就在同一段对话中提出：

> 推送这个分支，并针对默认分支创建一个 pull request。

推送（`gitPush`）和创建 PR（`prCreate`）都默认先征求你的批准，因此每一步之前都会出现一次确认。如果提示触发时没有连接任何批准人，该操作会被拒绝而不是放行——护栏会失效即拒绝。

该 PR 会以这次运行所用令牌对应的 GitHub 身份创建——如果你保存了个人令牌，那就是你的身份——而不是以智能体的名义。智能体的作者身份体现在提交上。

你也可以自己创建：空间的 **源代码管理** 面板中有一个 **创建 pull request** 按钮，它会把这段对话的分支带入撰写界面，而 **Pull requests → 新建 PR** 会打开同一个界面，但内容为空。下一篇教程就从那里接着讲。

## 小结

你创建了一个智能体，配置了它的适配器和模型，给了它一个空间和一项任务，并看着一次真实的运行在隔离工作树中完成，而完全没有触及你的检出。
