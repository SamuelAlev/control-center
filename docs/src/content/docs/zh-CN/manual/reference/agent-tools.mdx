这些是内置智能体运行时直接注册的**绑定服务端资源**的工具——语言服务器、结构化搜索、调试器、内核、代码模式脚本、提问与工作进程控制——它们既不同于它桥接进来的 [MCP 工具](/zh-CN/手册/参考/mcp-工具/)，也不同于运行器运行时提供的通用文件、搜索和 shell 工具。它们不在 MCP 注册表里：外部 MCP 客户端看不到它们，因为每一个都绑定着一项服务器端的实时资源——一个语言服务器进程、一个调试适配器、一个解释器——而这项资源只属于一次运行。

这里的每一个工具，只有在它的支撑资源为本次运行接入之后才会注册——语言服务器或调试监督进程、一个 tree-sitter 解析器、一个内核工厂、一个提问端口、一份 vibe 名册。对*这次检出*的语言服务器或调试适配器的检测，是另一项更靠后的检查（`status` / `adapters`）：这些工具会一直留在工具面上，好让智能体能问清楚为什么什么都不可用，而不是靠猜。

## 审批层级

每个工具都会声明一个层级，而层级决定的是**哪些调用方能看到这个工具**，而不只是它是否会弹出提示。计划模式和只读子智能体都被限制在 `read`，因此 `write` 或 `exec` 层级的工具根本不会出现在它们的 schema 中。

| 层级 | 含义 | 这里的工具 |
| --- | --- | --- |
| `read` | 无副作用 | `lsp`、`ast_grep`、`ask_user`、`repl`，以及五个 `vibe_*` |
| `write` | 会改动文件 | `lsp_rename`、`ast_edit`、`resolve` |
| `exec` | 启动或控制一个进程 | `debug`、`eval` |

## 直接调用、仅脚本或首次使用时加载

服务器能运行脚本时，运行会直接调用少数工具，并通过[`repl`](#repl--运行调用你的工具的脚本)脚本访问其余工具；完整规则参见[代码模式](/zh-CN/手册/概念/代码模式/#智能体直接调用哪些工具)。本页工具的情况如下：

| 工具 | 有 `repl` | 无 `repl` |
| ---- | ----------- | -------------- |
| `repl` | 直接调用 | 不存在 |
| `ask_user` | 直接调用 | 直接调用 |
| `lsp`, `lsp_rename`, `ast_grep`, `ast_edit`, `resolve`, `debug` | 仅脚本 | 首次使用时加载 |
| `eval` | 首次使用时加载（脚本不能调用它） | 首次使用时加载 |
| `vibe_*` | vibe 模式下直接调用，从不从脚本调用 | vibe 模式下直接调用 |

一旦服务器无法运行该次运行的脚本，被标记为“仅从脚本调用”的工具会改为在首次使用时加载（参见[无法运行脚本时](/zh-CN/手册/概念/代码模式/#无法运行脚本时)）。

## `lsp` — 语言服务器查询

当一次运行拥有语言服务器监督进程和工作目录时才会注册。服务器能否真正作答是在调用时按**交集**来检测的：根标记必须存在，*并且*服务器二进制文件必须能被解析到。只有其中一个成立都不会启动服务器——`status` 会如实说明——而不是悄悄靠猜。

服务器只来自内置表；不读取仓库中的 `lsp.json`。在沙盒中运行时，每次运行都有自己的语言服务器会话，因此服务器会随每次运行重新启动。项目本地的二进制文件（`node_modules/.bin`）只有在运行处于沙盒中时才会使用，并且项目根目录绝不会解析到运行工作目录之上。

定位由 `line` 加一个 `symbol` 子串指定，而绝不用列号。被要求给出列号的模型只能靠猜，而猜错会解析成同一行上的另一个符号——一个看起来正确、说的却是别的东西的答案。在导航类操作中省略 `symbol` 是一种错误，而不是默认猜第一列。

| 操作 | 参数 | 返回 |
| --- | --- | --- |
| `diagnostics` | `file`（或 `"*"`） | 错误和警告；`"*"` 改为运行项目检查器 |
| `definition` | `file`, `line`, `symbol` | 符号声明的位置 |
| `type_definition` | `file`, `line`, `symbol` | 它的类型声明的位置 |
| `implementation` | `file`, `line`, `symbol` | 具体的实现 |
| `references` | `file`, `line`, `symbol` | 每一处使用，上限 50 处 |
| `hover` | `file`, `line`, `symbol` | 签名和文档注释 |
| `symbols` | `query` 或 `file` | 用 `query` 做工作区搜索（上限 100）；用 `file` 取文档符号（上限 200） |
| `code_actions` | `file`, `line`, `symbol` | 服务器提供的快速修复 |
| `status` | — | 哪些服务器正在运行，以及各自对应哪些根 |
| `reload` | — | 重启这个根的服务器 |

### 写入时的诊断

真正的收益并不在工具本身。`write`、`edit` 和 `apply_patch` 都被**包了一层**：写入之后，文件会经过语言服务器同步并保存，只有**新引入的**诊断会被并入工具结果。智能体在弄坏构建的那一刻就知道自己弄坏了，而不必记得去问。

已经报告过的诊断会由一份按运行维护的台账抑制，该台账以严重级别、代码和消息为键——刻意排除了位置，因此仅仅向下移动了四行的诊断不会被当作新增重新报告。

## `lsp_rename` — 全项目重命名

它是一个独立的 `write` 层级工具，理由只有一个：层级决定可见性。把重命名并进 `lsp`，要么是把改写仓库的能力交给一个只读的探索者，要么是让每一次 `hover` 都先过一道审批提示。

| 参数 | 含义 |
| --- | --- |
| `file` | 符号所在的位置 |
| `line` | 从 1 开始计数的行号 |
| `symbol` | 在该行上标识它的子串 |
| `new_name` | 改成什么名字 |

## `ast_grep` — 结构化搜索

它按**形状**而不是按文本查找代码。`$NAME` 匹配任意节点，`$$$NAME` 匹配一串同级节点，`$_` 是通配符，不绑定任何东西。

让它成为一个匹配器、而不只是一个多绕几步的正则的特性在于：同一个模式里重复出现的元变量必须捕获相同的文本。

```
ast_grep(pattern: "if ($X != null) $X.dispose()", language: "dart")
```

它会匹配那种“销毁自己刚刚检查过的对象”的守卫，而**不会**匹配销毁别的东西的守卫。

| 参数 | 含义 |
| --- | --- |
| `pattern` | 一段带元变量的代码片段 |
| `path` | 要搜索的文件或目录；默认为整个工作区 |
| `language` | 随附的语法 id（`dart`、`python`、`rust`、`c` 等）。当 `path` 指向单个文件时会被推断出来 |
| `max_results` | 默认 50 |

:::note[模式由与该文件相同的语法解析]
因此 `dispose(x)` 无论怎么加空格、怎么换行或包裹都能匹配到这个调用——也绝不会匹配字符串字面量或注释里出现的同样字符。
:::

:::caution[片段是放在包裹上下文中解析的，而不是裸着解析]
`dispose(x)` 当作 Dart 顶层内容裸着解析时，是一个完全合法的*函数签名*。模式编译器会依次尝试一整套上下文（语句、表达式、类成员、声明），并采用第一个接受该片段的上下文。没有任何上下文接受的模式会被报告为无法解析，而不是被搜上一圈、然后悄无声息地查无结果。
:::

## `ast_edit` — 结构化重写，先暂存

匹配方式相同，另外还接受一个 `rewrite` 模板，把元变量代回其中。**不会写入任何内容。** 改动会被暂存起来，结果中会给出一个 `edit_id`。

```
ast_edit(pattern: "dispose($X)", rewrite: "$X.dispose()", language: "dart")
→ (proposed) 12 replacements in 4 files … call resolve with edit_id "edit_1"
```

| 参数 | 含义 |
| --- | --- |
| `pattern` | 要匹配什么 |
| `rewrite` | 换成什么，其中 `$NAME` 会被代回 |
| `path` | 作用范围；默认为整个工作区 |
| `language` | 语言 id |

## `resolve` — 提交或丢弃一次暂存的改动

| 参数 | 含义 |
| --- | --- |
| `edit_id` | 来自 `(proposed)` 结果 |
| `action` | `accept` 或 `discard` |

每个文件都会与暂存时捕获的内容比对，**任何**不一致都会拒绝整个改动。只应用了一半的结构化重写，会留下一棵在旧形状和新形状下都编译不过的树。

## `debug` — 驱动调试器

当一次运行拥有调试会话监督进程、工作目录和对话 id 时才会注册。适配器能否真正启动是在调用时按与语言服务器相同的交集规则检测的（根标记*并且*二进制文件）。属于 `exec` 层级；非并行安全（会话是跨调用累积的状态，因此 `continue` 抢在 `stack` 前面会读到一个已经移动过的栈帧）。

每个对话只允许一个会话，并带一个硬性 TTL（30 分钟）。第二次 `launch` 会被拒绝，而不是悄悄替换掉第一个。在沙盒中运行时，会话会在其结束前跨轮次保持自己的沙盒，因此最多持续这 30 分钟。

| 操作 | 参数 | 说明 |
| --- | --- | --- |
| `adapters` | — | 这里哪些适配器可用，以及为什么不可用 |
| `status` | — | 是否有会话正在运行，以及它停在了哪里 |
| `breakpoints` | `file`, `lines[]` | `lines` 为空会清除该文件的断点。可以在启动**之前**设置 |
| `launch` | `program`, `args[]` | 启动程序，并停在你的断点处 |
| `attach` | `port` | 连接到本次运行自己转发的某个端口上已在运行的被调试进程；其他任何端口都会在启动任何内容之前被拒绝 |
| `continue` | `thread_id?` | 运行到下一个停止点 |
| `pause` | `thread_id?` | 让它就地停止 |
| `step_over` / `step_in` / `step_out` | `thread_id?` | 单步移动一步 |
| `threads` | — | 线程 id 和名称 |
| `stack` | `thread_id?` | 栈帧，上限 30 个 |
| `scopes` | `frame_id` | 某个栈帧上的作用域，每个都带一个 `reference` |
| `variables` | `reference` | 子项，上限 50 个；值上限 400 个字符 |
| `evaluate` | `expression`, `frame_id?` | 在该栈帧自身作用域中求值 |
| `output` | — | 被调试进程的 stdout/stderr，有上限 |
| `terminate` | — | 结束会话并杀掉适配器 |

### 适配器

| Id | 命令 | 根标记 |
| --- | --- | --- |
| `dart` | `dart debug_adapter` | `pubspec.yaml` |
| `debugpy` | `python3 -m debugpy.adapter` | `pyproject.toml`, `setup.py`, `requirements.txt` |
| `lldb` | `lldb-dap` | `Cargo.toml`, `CMakeLists.txt` |
| `delve` | `dlv dap` | `go.mod` |

仅当运行处于沙盒中时，`debugpy` 才会优先选择项目本地的 `.venv/bin` 或 `venv/bin`，而不是 `$PATH`：`$PATH` 里的 python 是另一个环境，从错误的环境附加时，失败的样子读起来像代码坏了。未在沙盒中时，它只使用 `$PATH`，因此仓库无法选择在主机上运行的解释器。

## `repl` — 运行调用你的工具的脚本

服务器能运行脚本时，每次运行都会提供此工具（[当运行有 `repl` 时](/zh-CN/手册/概念/代码模式/#当运行有-repl-时)）。该脚本是纯 JavaScript，即一个异步函数的函数体，在其自身进程中的全新且已锁定的解释器中运行：没有文件系统、网络、进程或模块访问权限。`repl` 本身属于 `read` 层级并自我把关，因为脚本进行的每次工具调用都会单独检查。在能运行脚本的服务器上，智能体运行也可通过 MCP 端点使用它。

| 参数 | 含义 |
| ------------------- | --------------------------------------------------------------------------------------------- |
| `code` | 脚本。最多 256 KiB |
| `description` | 必填。对话记录行的简短标签 |
| `timeout_ms` | 可选。比工作区的时间限制更短的值；绝不能更长 |
| `max_output_tokens` | 可选。比工作区的输出预算更小的值；绝不能更大 |

```js
// Read three files together and report only which ones failed.
const paths = ["lib/a.dart", "lib/b.dart", "lib/c.dart"];
const results = await Promise.allSettled(paths.map((path) => tools.read({ path })));
return results
  .map((r, i) => (r.status === "rejected" ? `${paths[i]}: ${r.reason.message}` : null))
  .filter(Boolean);
```

`repl` 的描述告诉智能体：“不在你的直接调用工具之列的工具，在本次请求中没有定义。在第一次调用其中某个工具之前，请先用 `describeTool(name)` 或 `searchTools(query)` 查找它，除非它的确切调用形式已在本次对话中向你展示过。”

`describeTool(name)` 返回工具的描述、其声明、输入和输出 schema，以及结果说明（如果有的话）：即脚本从已完成的调用中收到的内容，用工具自己的措辞描述。`repl` 的描述会列出脚本可以调用的直接工具的说明。工具结果若是 JSON 文本，会以解析后的形式送达，除非其中包含超过 131,072 个值；那时它以文本形式送达，由脚本用 `JSON.parse` 解析。外部 MCP 服务器工具的结果，其文本会在 262,144 个字符处被截断，被截断的文本不再能够解析。

- `tools.<name>(args)` 通过与直接调用相同的过滤器、护栏和审批来调用工具，被拒绝或失败时并抛出错误。只读调用可以一起运行；会改变状态的调用则逐个运行，按脚本发出的顺序执行。脚本的某个调用等待人工时，脚本不会开始其他调用。
- `ALL_TOOLS`、`searchTools(query, { limit, namespace })`、`describeTool(name)` 和 `describeNamespace(name)` 用于查找工具，包括已连接的 MCP 服务器的工具。直接集合之外、脚本可以调用的工具只能从脚本调用；直接调用其中一个时，会返回如何从 `repl` 调用它的说明。一旦服务器无法运行该次运行的脚本，此类工具便改为在首次使用时加载。
- 查找受到限制：查询最多 1,024 个字符，名称或命名空间最多 256 个字符，`limit` 取值范围为 0 到 50；每个脚本最多进行 200 次查找、合计占用服务器 2 秒时间，同时同一工作区的所有脚本共享 2 秒的查找时间，每过一秒返还四分之一秒；超过任一上限后，后续查找都会被拒绝。在非常庞大的目录中，`ALL_TOOLS` 中的描述平均分享约一百万个字符，被截断的描述以 `…` 结尾；`describeTool` 始终返回完整描述。无法显示的类型显示为 `unknown /* too large to show */`，而未知名称则会以最接近的名称作答。
- 工具按命名空间分组：`builtin`（框架自身的工具）、`control-center`（Control Center 的工具），以及每个已连接 MCP 服务器各一个，以服务器名称命名。名为 `builtin`、`control-center` 或 `script`、或名称以 `external-` 开头的服务器（无论大小写如何混合、名称前后是否带有空格），都会被列为 `external-` 加上其名称，并且没有任何工具会出现在 `script` 中。
- 只有脚本返回的内容，或传给 `text()`、`image()` 或 `console.*` 的内容，才会返回。超出预算的输出保留其开头和结尾，`read_output` 可读取其余部分。
- `store(key, value)` / `load(key)` 为同一对话和智能体之后的脚本保存 JSON 值，仅在脚本完成时保存。子智能体的脚本没有存储空间。
- `await tools.ask_user(...)` 提出问题；其回答也会加入结果。`sleep(ms)`、`setTimeout`、`limits()` 以及 `models.embed` / `rank` / `classify`（设备端嵌入）同样可用。
- `describeTool(name)` 和 `searchTools(query)` 也会为脚本自己的函数作答（它们不是工具）：`text`、`image`、`store`、`load`、`sleep`、`setTimeout`、`clearTimeout`、`limits`、`exit` 和 `models.*`，位于 `script` 命名空间下。
- 脚本不可调用：`repl`、`eval`、`task`、`checkpoint`、`rewind`、`compact`、`search_tools` 以及 `vibe_*` 动词。
- 脚本可以读取自己这次运行的过往：`history({start, role, tool, limit})` 按页读取该对话的记录（每次调用最多 50 行；把上一页的 `next_start` 作为 `start` 传入），`outputs()` 列出为该对话和智能体存储的工具输出，`loadOutput(handle)` 读取其中一条的 16,384 个字符。`storedKeys()` 列出已存储的键及其大小。`keep(value, label)` 将一个大值保存为一条输出，之后的脚本或 `read_output` 可以读取它；它仅在脚本完成时才保存（每个值 1 MiB，每次运行 64 个值、共 16 MiB）。`limits().returnBudgetChars` 说明输出预算还剩多少。只读运行（目标评审）可以读取，但不能存储或保留。在 Claude Code 和 ACP 上，`history()` 可用，而 `outputs()`、`loadOutput()` 和 `keep()` 会拒绝执行，因为 Control Center 不保存这些运行的工具输出。
- 来自超时、输出溢出或调用次数上限的错误会说明如何修复。

一次运行同时只运行一个脚本。各项限制及其触发时的行为，参见[代码模式](/zh-CN/手册/概念/代码模式/#限制)页面；每个脚本都记录在 **可观测性 → 代码执行记录** 下。

## `eval` — 持久解释器

一个 Python 或 JavaScript 单元格，它的变量、导入和已加载的数据在多次调用之间都会保留。属于 `exec` 层级；非并行安全。不能从 `repl` 脚本调用它，单元格也不能调用本次运行的工具：若要在代码中调用工具，请使用[`repl`](#repl--运行调用你的工具的脚本)。

| 参数 | 含义 |
| --- | --- |
| `code` | 单元格的代码 |
| `description` | 必填。5–10 个词，用作转录标签 |
| `language` | `python`（默认）或 `javascript` |
| `reset` | 先丢弃解释器，从干净状态重新开始 |

- 最后一个表达式会像 notebook 那样被回显。
- `display()` 可用，pandas 数据框会以表格形式渲染，matplotlib 图形会作为**转录中会显示出来的图像**返回。
- 人们下意识会敲的那些 IPython 惯用写法——`%pip`、`%cd`、`!cmd`、`%%bash`、`%%timeit`——都会被改写成普通代码。`%pip` 还会清空 `sys.modules`，让下一次 `import` 能看到刚刚安装的东西。
- 输出超过其预算的单元格会保留前四分之三和最后四分之一，并附一行说明丢弃了多少个字符和图像。
- 解释器在未被要求的情况下退出时，下一个单元格会被告知一次：其先前的变量已不存在。

:::note[内核在哪里运行]
如果该对话有隔离舱，就在隔离舱中运行；否则在本次运行的主机操作系统沙盒中运行。沙盒关闭或不可用时，它不受限地运行，且 `eval` 会请求主机执行批准。它不会为了做到这一点而启动一个隔离舱——这和阻止机台标签页自动启动的是同一条规则。
:::

## 后台中的 `bash`

带有 `run_in_background: true` 的 `bash` 会启动命令，并立即返回一个句柄（`b1`、`b2`、…），而不是等待。智能体可以继续工作，也可以结束其轮次，待命令退出时再被唤醒。

| 参数 | 含义 |
| ------------------- | ------- |
| `run_in_background` | `true`，立即启动并返回 |
| `timeout_seconds` | 命令被终止前的秒数：默认 600，最多 3,600 |
| `notify` | 可选。一个简单的模式；命令运行时，每条匹配的输出行都会发送给智能体（例如 `listening on\|FAILED`） |

- 同一次运行中最多同时运行 4 个后台命令。每个命令在其超时时以及运行结束时被终止，连同它启动的所有进程一起。
- 命令退出时，智能体会收到一条通知，其中包含退出码、输出的最后 2,000 个字符，以及用于读取其余部分的 `read_output` 句柄。
- 如果智能体剩下的唯一工作是一条后台命令，它会在不调用模型的情况下等待，并且运行的静默看门狗在等待期间暂停。
- `bash_output(handle)` 读取命令的状态和近期输出；`bash_kill(handle)` 停止它。两者都会说明结果是否已经送达。
- 脚本不能启动后台命令。Claude Code 有自己的后台 Bash；对于留下任务仍在运行的那个轮次，Control Center 最多为该运行保持开放 10 分钟。

## `compact` —— 为上下文窗口腾出空间

在下一次模型调用之前压缩对话中较早的上下文，保留 `focus` 所指定的内容（最多 1,000 个字符）。最新的轮次保持原文。智能体每轮的预算行会显示上下文用量为 70%、80% 和 90%，因此在开始一段长的新工作阶段之前，超过约 70% 时调用此工具是值得的。服务器所有者的 `preCompact` 钩子可以向 focus 添加内容（[Shell 钩子](/zh-CN/手册/参考/智能体配置/#shell-钩子)）。压缩之后，服务器会添加一个“Still in flight”区块：目标、待处理的唤醒、未结的提问、后台命令、清单和已存储的键，每项都附有用于恢复它的调用。

## `ask_user` — 向人提问

属于 `read` 层级。这是一次运行向操作者提问的**唯一**方式。它会在对话中渲染一张编号卡片，并一直阻塞，直到有人回答、跳过，或者提问超时。绝不要把问题写成一条聊天消息——那会结束当前回合。

| 参数 | 含义 |
| --- | --- |
| `question` | 要问什么 |
| `context` | 可选：你为什么问，以及答案会决定什么 |
| `options[]` | 可选项，每一项为 `{label, description?}` |
| `allow_free_text` | 是否接受手动输入的答案 |
| `multi_select` | 是否可以选择多项 |

跳过即成功：基于一个明确说明的假设继续推进，并且不再询问。超时则是一种错误，附带同样的指示。权限提示（“我可以这样做吗？”）是另一道闸门，在对话中渲染为同样的卡片。

只有当提问端口和目标空间都存在时才会注册。在没有人工接入的情况下，这次调用会**失败**，而不是永远阻塞下去——这与护栏 `prompt` 在没有连接任何审批人时所采取的失败关闭姿态相同。

## `vibe_*` — 指挥后台工作进程

只有在 [vibe 模式](/zh-CN/手册/操作指南/指挥后台工作进程/) 打开时才会注册。这五个工具都属于 `read` 层级：闸门应当设在工作进程的那些工具上，因为编辑真正发生的地方在那里。

| 工具 | 参数 | 说明 |
| --- | --- | --- |
| `vibe_spawn` | `brief`, `label`, `tier?` | 立即返回；工作进程继续运行 |
| `vibe_send` | `worker_id`, `message` | 追加到简报中并重新运行 |
| `vibe_wait` | `worker_id`, `timeout_seconds?` | 阻塞，直到它结束 |
| `vibe_kill` | `worker_id` | 停止它 |
| `vibe_list` | — | 层级、状态、已用时间和最近一次结果 |

`tier` 可以是 `fast`（规格明确的机械性工作）或 `good`（设计、判断，或审查一个 `fast` 工作进程的产出）。
