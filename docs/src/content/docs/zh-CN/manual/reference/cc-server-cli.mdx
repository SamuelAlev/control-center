每个进程标志都可以通过命令行标志或环境变量设置；优先级依次是标志、环境变量、默认值。提供商凭据是例外——见[提供商应用与 Connect](#提供商应用与-connect)。

:::caution[未知标志会被静默忽略]
参数解析器是手写的，会跳过任何它不认识的内容，因此写错标志（`--tls-key-file`、`--bindany`）不会报错——服务器只是按默认值启动。当某个标志看起来没有生效时，请检查启动日志。值不被接受的[代码模式标志](#代码模式)则不同：服务器会拒绝启动。
:::

## 核心

| 标志            | 环境变量               | 默认值                                    | 含义                                                                                       |
| --------------- | ---------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------ |
| `--data-dir`    | `CC_SERVER_DATA_DIR`   | 操作系统的按用户应用数据目录（见下文）    | 数据库、密钥、模型和缓存的媒体                                                             |
| `--port`        | `CC_SERVER_PORT`       | `9030`                                    | TCP 端口（`0` = 临时端口）                                                                 |
| `--bind`        | `CC_SERVER_BIND`       | `loopback`                                | `loopback`，或 `any`/`all`/`0.0.0.0` 表示所有网络接口（需要 TLS 或 `--insecure`）          |
| `--repo-roots`  | `CC_SERVER_REPO_ROOTS` | 服务器用户的主目录                        | 客户端注册仓库时可以浏览的基准目录，以逗号分隔。超出根目录的浏览会被拒绝                   |
| `--log-level`   | `CC_SERVER_LOG_LEVEL`  | `warning`                                 | `debug`、`info`、`warning` 或 `error`。启动/就绪的日志行始终会打印                          |
| `--server-name` | `CC_SERVER_NAME`       | 本机主机名                                | 在选择器、发现和配对界面中显示的名称                                                       |

## 索引与运行时

| 标志                     | 环境变量                        | 默认值                                | 含义                                                                                                          |
| ------------------------ | ------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `--sandbox`              | `CC_SERVER_SANDBOX`             | `on`                                  | `on` 会用操作系统原生沙盒包裹智能体运行，在没有沙盒的主机上只启动服务器所有者的运行。`off` 会在本主机上不受限地运行每位成员的智能体。见下文 |
| `--code-index`           | `CC_SERVER_CODE_INDEX`          | `on`                                  | 后台代码图索引的现场关停开关。设为 `off` 无需重新构建即可干净启动                                             |

| `--credential-gate`      | `CC_SERVER_CREDENTIAL_GATE`     | `900`                                 | 当凭据无法为某次运行提供服务时，该运行等待人工修复的挂起秒数（限制在 0–3600）。见下文                          |

| `--code-mode-max-heap-mb` | `CC_SERVER_CODE_MODE_MAX_HEAP_MB` | `1024` | 单个脚本可使用的最大内存，取值 16–1024 MiB。工作区更高的内存上限会被降低到此值 |

## 提供商应用与 Connect

任何构建版本都不带提供商凭据。开启 Control Center Connect 时，Connect 会运行每个提供商，服务器自己的应用则保留但不使用。在**使用我自己的应用**下，每个提供商在服务器自己的应用配置完整时使用该应用，否则不可用。工作区自己的应用在两种情况下都优先。自有应用在 **设置 → 服务器 → 单点登录 → 提供商应用** 中设置，或从服务器的 `.env` 文件中一次性赋值。它们没有对应的标志：命令行上的密钥可以通过 `ps` 读到。

| 变量                           | 含义                                                                                          |
| ------------------------------ | --------------------------------------------------------------------------------------------- |
| `GITHUB_APP_ID`                | 服务器 GitHub App 的 id                                                                       |
| `GITHUB_APP_PRIVATE_KEY`       | 其私钥，单行，使用 `\n` 转义。**仅限 `.env`**                                                  |
| `GITHUB_CLIENT_ID`             | 其客户端 id，用于让人们登录                                                                    |
| `GITHUB_CLIENT_SECRET`         | 其客户端密钥。**仅限 `.env`**                                                                  |
| `GOOGLE_OAUTH_CLIENT_ID`       | 服务器的 Google Web 应用客户端                                                                 |
| `GOOGLE_OAUTH_CLIENT_SECRET`   | 其密钥。**仅限 `.env`**                                                                        |
| `LINEAR_CLIENT_ID`             | 服务器的 Linear 应用（PKCE，无密钥）                                                           |
| `LINEAR_API_KEY`               | 用于自动化的 Linear 服务密钥。**仅限 `.env`**                                                  |
| `KLIPY_APP_KEY`                | 服务器自己的 Klipy GIF 搜索密钥，仅在**使用我自己的应用**下使用                              |
| `CC_CONNECT_URL`               | `hosted`、`off` 或 Connect 的 URL。锁定 Connect 的选择；之后设置无法更改它                      |
| `CC_SERVER_CONNECT_HOST`       | `on` 会在 `<server>/connect` 挂载 Control Center Connect，由 `CONNECT_*` 变量配置。参见[运行 Connect 服务器](/zh-CN/手册/操作指南/运行-connect-服务器/#在-cc_server-内挂载-connect) |

`.env` 文件从服务器的工作目录、可执行文件旁，或其上层的源码检出目录中读取；在 Docker 中，把它挂载到 `/app/bin/.env`。当 `GITHUB_APP_PRIVATE_KEY`、`GITHUB_CLIENT_SECRET`、`GOOGLE_OAUTH_CLIENT_SECRET`、`LINEAR_API_KEY` 或任何 `SLACK_*SECRET*` 被导出到服务器的进程环境中时（所有子进程都能读取），服务器会**拒绝启动**（退出代码 `78`）。从 `.env` 的赋值每个字段只发生一次，因此之后在设置中所做的编辑不会被重启撤销。空值视为未设置。

没有任何代码托管平台凭据来自环境变量：GitHub、GitLab 和 Bitbucket 都只以某位成员自己的登录或令牌行事，或以受该成员约束的单仓库 GitHub App 令牌行事。

### `--sandbox`

服务器在启动时会对主机探测一次，只要存在可用的后端，就用操作系统原生沙盒包裹智能体的命令执行：macOS 上是 `sandbox-exec`（Seatbelt），Linux 和 WSL2 上是 `bwrap` 加 `socat`。该决定只做一次，并在服务器重启前保持不变。共有三种结果，每种都会显示在启动时的暴露行中：

| `sandbox=` | 何时 | 哪些人的智能体运行会启动 |
| ---------- | ---- | ------------------------ |
| `native` | 有可用后端且 `--sandbox` 为 `on` | 所有人的运行，并被包裹 |
| `off` | `--sandbox off` | 所有人的运行，在本主机上不受限 |
| `unavailable` | `--sandbox on` 且没有后端（Windows，或缺少 `bwrap` 和 `socat` 的 Linux） | 只有服务器所有者负责的运行，不受限。其他人的运行会被拒绝，并显示“此服务器没有沙箱，因此只有其所有者可以在此运行智能体。” |

对于自动化而言，负责的人是该自动化所绑定的人。若未记录服务器所有者，则 `unavailable` 主机上不会启动任何运行。在安装了 bubblewrap 的 Linux 和 WSL2 上，原生派发目前会对每次运行都采取失败关闭；参见[沙盒后端](/zh-CN/手册/参考/沙盒后端/#linuxbubblewrap)。

`--sandbox off` 是服务器所有者为所有使用该服务器的人做出的选择：它会在这台机器上以不受限的方式运行每位成员的智能体。请在沙盒配置本身行为异常的主机上使用它，或让成员能在没有后端的主机上运行智能体。它不需要重新构建，服务器会在整个进程生命周期内记录一条警告，因此这种状态永远不会悄无声息。

### `--tool-deferral`

内置运行框架发出的请求会附带一小批直接集合的工具定义，加上其余工具的仅含名称的索引；这些工具在首次使用时加载 schema，或由 `repl` 脚本调用。它让始终可见的集合保持在模型能可靠选择工具的区间内。在测试所构建的注册表上测量，内置智能体的标准聊天工具共 14 个定义：有 `repl` 时约为 16.5 KB（其中 `repl` 自身约 4 KB，其定义不得超过 4,096 字节），在无法运行脚本的服务器上约为 13 KB。延迟加载的工具自始至终都可以按名称调用，`search_tools` 也能按意图找到它们。参见[工具上下文与提示缓存](/zh-CN/手册/概念/工具上下文/)。

`--tool-deferral off` 会预先发送每个被准入工具的定义，但有 `repl` 的运行仍会从脚本中调用脚本可以调用的工具。它是针对无法良好应对两层式工具面的模型的关停开关——只需一个标志，而不必重新构建。它只影响内置运行框架；外部客户端看到的 MCP `tools/list` 是完整目录，但在能运行[代码模式](/zh-CN/手册/概念/代码模式/)脚本的服务器上，智能体运行除外。

### `--credential-gate`

当某次运行所用的提供商凭据缺失或已耗尽时，该运行会被**挂起**而不是直接失败：操作员会收到提示去修复它，修复后运行便会继续。默认时限为 900 秒（15 分钟），限制在 0–3600 之间。

这个时限被刻意设置得比审批提示长得多：审批是某个人在几秒内做出的决定，而修复凭据意味着打开终端、登录再回来。正是这个上限让无人值守的运行——流水线步骤、cron 触发器、webhook——不必一直等待某个正在睡觉的人。时限一到，运行就会带着它本来就会给出的那条消息失败。

`--credential-gate=0` 是关停开关：任何运行都不会被挂起，凭据有问题时会像这个闸门出现之前那样直接结束该轮次。

### 代码模式

[代码模式](/zh-CN/手册/概念/代码模式/)让智能体运行调用其工具的 JavaScript 脚本。没有任何标志能开启或关闭它：服务器能运行脚本时，每次运行都会获得 `repl` 工具；公共演示服务器则不运行任何脚本。

脚本在 `cc_codemode` 中运行，这是随服务器打包在 `bin/codemode/` 中的程序。没有它，服务器无法启动：它会打印一行说明缺少什么的信息，并以退出码 `78` 退出。启动时，服务器会运行该程序的锁定自检，并打印一行（仅在 `--log-level error` 时静默）：

```text
cc_server: code_mode=available (cc_codemode 0.1.0 quickjs-ng 0.16.2 protocol 2; 16 scripts at once, at most 12 per workspace; up to 64 more runners kept for scripts waiting on a person; heap at most 1024 MiB per script)
cc_server: code_mode=unavailable (<reason>) — runs on this host get no repl tool; scripts never run without full lockdown
```

`unavailable` 表示该程序无法在此主机上锁定自身，例如在某个容器中，其安全配置拒绝了其中一步，或该程序不是发布构建。服务器仍会正常运行，没有任何运行会获得 `repl`，工作区的代码模式设置会显示原因。

服务器在运行期间会持续检查。当程序因非脚本本身的原因无法启动时，服务器会重新执行自检，但频率最多为每分钟一次。若自检失败，服务器会打印带有原因的 `unavailable` 行，并且不运行任何脚本：此期间启动的运行都不会获得 `repl`，而已经拥有它的运行则直接调用其工具（[无法运行脚本时](/zh-CN/手册/概念/代码模式/#无法运行脚本时)）。服务器会继续检查，频率最多为每分钟一次；当自检再次通过时，它会打印 `available` 行并重新运行脚本。只有启动时即失败的自检才需要重启。工作区设置中显示的原因已移除主机路径；日志行中则保留完整内容。

两个代码模式标志设定脚本可以使用的上限。`--code-mode-max-processes` 限制所有工作区中同时运行的脚本数量（默认为处理器核心数的两倍，最多 16；接受 1–64）。上限为 2 或更大时，单个工作区最多只能占用上限减去其四分之一的名额，因此任何单个工作区都无法占满所有位置，等待中的脚本会在各工作区之间轮流获准运行。等待人工审批或回答的脚本会让出其位置给其他脚本，并且在得到回答之前不会开始任何工具调用；此类等待中的脚本最多可保留上限的四倍，其中来自同一工作区的不超过四分之三，并且每个都仍可在其自身的处理器时间限制内继续计算。`--code-mode-max-heap-mb` 是任何单个脚本可使用的最大内存。

这些参数不接受的值（超出范围的数字，或根本不是数字的值）会使服务器在启动时停止（退出码 `78`），并给出说明可接受值的消息。它绝不会被当作默认值读取。

## 子命令

| 命令                                          | 作用                                                                                                        |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `cc_server`                                   | 运行服务器，直到收到 `SIGINT`/`SIGTERM`                                                                     |
| `cc_server pair`                              | 预配一台设备，并打印其 id 和配对密钥。即使服务器正在为某个数据目录提供服务也可安全执行——运行中的服务器无需重启即可接纳该设备 |
| `cc_server connect <command>`                 | 查看或更改本服务器使用哪个 Control Center Connect，而不启动服务器                                          |
| `cc_server update`                            | 检查、下载并校验更新的独立版本                                                                              |
| `cc_server --version`                         | 打印构建版本和 git SHA——与 `/healthz` 及 RPC 握手对外公布的身份相同                                          |

### `pair`

| 标志           | 默认值                                                    | 含义                                                                                                                                                                 |
| -------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--device`     | `web-client`                                              | 设备 id。平台由它推断得出，因此 `--device desktop` 会创建一行桌面设备，`--device ios`/`android` 会创建一行手机设备；其他任何值都视为 Web                            |
| `--label`      | 平台名称加上本机主机名                                    | 设备列表中的显示名称                                                                                                                                                 |
| `--host`       | `localhost`，或绑定到所有接口时的 `<this-host>`           | 要嵌入打印出的 URL 中的主机。请把它设置为客户端实际会拨号访问的局域网 IP 或隧道主机                                                                                  |
| `--client-url` | 未设置                                                    | 托管式 **Web** 客户端的源。会额外打印一个可扫描的深层链接和终端二维码                                                                                                |

`pair` 也接受核心的 `--data-dir`、`--port` 和 `--bind` 标志：它们决定要写入的数据目录，并影响打印出的服务器 URL（环回时为 `ws`，`--bind any` 时为 `wss`）。对同一个 `--device` 重新运行 `pair` 会轮换其密钥，并断开该设备当前的会话。这里签发的凭据**永不过期**，而应用内配对设置的凭据有效期为 30 天。

:::caution[`--client-url` 的二维码不是手机二维码]
`pair --client-url` 会填写 **Web** 客户端的连接表单（服务器 URL、设备 id 和密钥都在 URL 片段中）。手机配对用的是从应用内配对面板签发的另一种负载——服务器的完整连接描述符加上一个有效期。二者不可互换——参见[配对设备](/zh-CN/手册/操作指南/配对设备/)。
:::

### `connect`

读写与 **设置 → 服务器 → 单点登录** 中 **Control Center Connect** 卡片相同的设置，数据来自数据目录。正在运行的服务器会在 10 分钟内或重启后采纳变更。

| 命令                                | 作用                                                                                                       |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `cc_server connect status`          | 打印模式、地址、`CC_CONNECT_URL` 是否锁定了它、安装 ID、健康状况，以及每条通道的来源（`own`、`connect` 或 `off`） |
| `cc_server connect enable`          | 使用 Control Center 托管的 Connect                                                                          |
| `cc_server connect enable --url <url>` | 使用该地址的自定义 Connect（HTTPS，或回环地址上的 `http`）                                              |
| `cc_server connect disable`         | 停止使用 Connect。只有服务器自己的应用能让人们登录                                                          |

不带命令的 `status` 是默认行为。每个命令都接受 `--data-dir`。`CC_CONNECT_URL` 会覆盖这些设置中存储的值。未知命令以退出代码 `64` 退出。模式、安装身份与状态代码参见 [Control Center Connect](/zh-CN/手册/参考/connect/)。

### `update`

`--apply` 会替换当前的安装；只要配置的端口上仍有服务器在应答，该操作就会被拒绝，除非传入 `--force`。`--allow-downgrade` 允许降级到更旧的版本。

对于它并不拥有的安装，该命令会直接拒绝，给出的是说明而不是错误：

| 环境                          | 检测方式                                    | 给出的说明                                                   |
| ----------------------------- | ------------------------------------------- | ------------------------------------------------------------ |
| 桌面端内嵌的服务器            | `CC_EMBEDDED=1` 或 `CC_BOOTSTRAP_DEVICE_ID` | 请改为更新应用——安装程序会替换整棵目录树                     |
| 用 `dart run` 运行的源码检出  | 脚本路径以 `.dart` 结尾                     | 请用 git 更新                                                |

## 进程生命周期

`cc_server` 会一直运行，直到收到 `SIGINT` / `SIGTERM`。还有一个额外的环境变量控制这一点，它由桌面端设置，而不是由你设置：

| 变量                     | 作用                                                                                                                                                                          |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CC_EXIT_WITH_PARENT=1`  | 当父进程退出时，服务器也随之退出，判断依据是父进程关闭了其 stdin 管道的写入端。桌面端会设置它，这样即使应用崩溃，也不会留下一个仍占用数据目录的孤儿服务器                    |

只有当你把 `cc_server` 作为子进程监管、并希望获得同样的保证时，才需要自行设置它。

`DO_NOT_TRACK=1`（除空值、`0` 或 `false` 以外的任何值）会停止服务器自身的[使用情况分析](/zh-CN/手册/参考/使用情况分析/)，即使服务器级开关处于开启状态也是如此。客户端仍遵循该开关。

## 数据目录结构

默认数据目录在 macOS 上是 `~/Library/Application Support/control-center`，在 Windows 上是 `%APPDATA%\control-center`，其他平台上则是 `$XDG_DATA_HOME/control-center`（否则为 `~/.local/share/control-center`）。只有当主目录和应用数据目录都无法解析时，才会使用相对于当前工作目录的 `.cc_server`。

服务器会将数据目录设为仅其自身账户可访问（`0700`）。当它无法做到这一点时，或当 `global.db` 已损坏或由较新版本写入时，或当其身份文件无法读取时，它会拒绝启动（exit code `78`）。

| 路径                              | 内容                                                                     |
| --------------------------------- | ------------------------------------------------------------------------ |
| `global.db`                       | 工作区注册表、用户、已配对设备、新闻流和机群队列                          |
| `<workspaceId>/workspace.db`      | 每个工作区一个数据库——智能体、空间、工单、记忆                    |
| `<workspaceId>/code_index.db` | 该工作区的代码图。缺失时重建，从不备份 |
| `pre_upgrade/`、`<workspaceId>/pre_upgrade/` | 更新改变格式前数据库的最新两份副本 |
| `<workspaceId>/chat_credentials/` | 聊天机器人令牌，以明文 JSON 保存，因此会随工作区一起迁移                  |
| `secrets.json`                    | 配对密钥、Connect 安装密钥、提供商应用、人们的登录（通过 Connect 完成时为封存的）、webhook 密钥、SSO（`0600`） |
| `backups/<timestamp>/`            | 一份安装快照——`manifest.json`、`global.db` 以及每个工作区的副本          |
| `backups/exports/`                | 单工作区导出，`<workspaceId>-<timestamp>.db`                              |
| `backups/transfer/`               | 备份下载和上传的暂存区；由写入它的路由负责清理                            |
| `models/`                         | 设备端的嵌入、说话人分离和语音模型                                        |
| `codemode/` | 代码模式运行器的开发副本，由 `scripts/natives/build_codemode.sh` 安装；发布包在 `bin/codemode/` 中附带它 |
| `meetings/<meetingId>/`           | 保留的会议音频                                                            |
| `rigs/images/`                    | 导入的机台磁盘镜像（QEMU 桌面界面）                                       |
| `rigs/smolvm/<rigId>/`            | 每个机台的 microVM 运行时状态（代理密钥，`0600`）                         |
| `rigs/smolvm-packs/`              | 预先解压的机器包——让机台重复启动变快的缓存                                |
| `rigs/tls/`                       | 用于机台 HTTPS 的开发域名证书颁发机构（密钥权限 `0600`）                  |
| `rigs/run/<rigId>/`               | QEMU 覆盖层、种子镜像和每台虚拟机的密钥（`0600`）                         |
