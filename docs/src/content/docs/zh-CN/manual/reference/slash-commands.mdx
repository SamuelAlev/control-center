在空间输入框中输入的命令。它们按生效位置分为三组，而这一区别很重要：**本地**命令绝不会作为消息传递，因此既不出现在转录中，也不会到达任何智能体。

| 运行位置 | 含义                                                                    |
| ------------- | ---------------------------------------------------------------------------------- |
| **本地**     | 在客户端处理（或由客户端发起的服务器操作）。该命令绝不会作为消息传递，因此没有智能体能看到它。 |
| **旁路**      | 针对这段对话做一次服务端模型调用。对话不会被改变。 |
| **派发**  | 为这条消息启动的运行设置一种模式或指令。                            |

---

## 指挥一次运行

### `/plan`

**本地 → 派发。** 为对话开启计划模式：一个完全只读的工作树，以及上限为 `read` 的工具面。智能体的交付物是一份计划，而不是一次编辑。单独一个 `/plan` 只会翻转模式，绝不会作为消息传递；如果带上提示词，该行剩余的内容就是启动这次运行的东西。

### `/goal <objective>`

**派发。** 启动一个自主目标，目标监督器会在各个段之间以及重启后重新派发它。

先输入 `/goal` 再跟上文字，会打开**目标访谈**——这是一个简短的环节，在草稿凑齐以下全部五项之前拒绝接受它：评估者无需主观判断即可裁定的成功标准、一条确切的验证命令、尝试次数上限、范围边界，以及停止条件。每一步都提供*跳过并按原样运行*：访谈只是默认做法，而不是一道关卡。

`/goal pause`、`/goal resume` 和 `/goal drop` 不是斜杠命令。暂停、继续和停止位于侧边栏中该对话的目标列表上。目标本身可用的启动标志有 `--budget <dollars>`、`--max <N>`（运行预算）和 `--days <N>`（截止时间）。触及成本上限的目标，只有提高该上限才能恢复，而且要在这同一个侧边栏控件中操作。

:::note[为什么它非要打断]
自主目标是含糊简报真正昂贵的唯一场合。运行会为一个没人定义过“完成”的目标工作好几个小时，然后按自己的标准报告成功。五个问题，比一次什么时候“感觉完成了”就算完成的通宵运行更便宜。
:::

### `/loop [budget] [task]`

**派发。** 反复迭代直到完成。接受一个界限：`/loop 10`、`/loop 30m`、`/loop 1h30m`、`/loop 10 minutes fix the tests`。

一个*看起来*像限制的 token（以数字或符号开头）如果解析失败，就是一个硬错误。普通文字就是普通文字，因此 `/loop keep going until the tests pass` 是一个带内联提示词的无界循环，而不是一次误解析。

### `/vibe [task]`

**派发。** 把会话变成一名**指挥者**：它自己的工具降为 `read` 外加五个工作进程动词，由后台工作进程来执行编辑。参见[指挥后台工作进程](/zh-CN/手册/操作指南/指挥后台工作进程/)。

工作进程绝不会比这个模式活得更久——退出会终止其中每一个。

## 管理上下文

### `/compact`

**本地 → 服务器。** 把较早的历史折叠成一份带锚点的摘要，并在压缩后的上下文上继续。不接受任何面向模型的参数：该命令绝不会作为消息传递，压缩过程也不接受聚焦提示。

### `/shake [target]`

**本地 → 服务器。****不**做摘要地丢弃沉重内容：不调用模型，每个字都保留，只把没人会再读一遍的大块内容清空。

| 目标        | 丢弃内容                             |
| ------------- | --------------------------------- |
| `tool_output` | 无异常的较早工具结果（默认） |
| `images`      | 旧截图，保留它们的文本 |
| `all`         | 两者                              |

这就是“我的上下文很臃肿，但我又不想要摘要”时的逃生出口。

### `/context [agent]`

**本地。** 在独立的标签页中打开这段对话中智能体的上下文浏览器：它上下文窗口的每一段和每一部分——系统提示词、技能、上下文文件、工具 schema、历史和图像——并显示每一部分占用了多少，以及它背后的逐字内容。

该标签页以（空间, 智能体）对为键，因此运行两次会重新聚焦同一个标签页，而不是把同一份分解堆叠成多份。

在拥有**多个智能体**的空间里，单独一个 `/context` 会打开页头上下文计量条正在读取的那个窗口——也就是最近在这里工作过的那个智能体，它的消息位于轨迹最底部——并且该标签页会被标记为 `上下文 · <name>`，以说明它属于谁。要切换到另一个，就指名它：`/context qa`（`@` 是可选的）。输入的名称会精确解析，绝不模糊匹配：两个智能体持有两个不同的窗口，因此一次差之毫厘却打开了另一个窗口的匹配，会是对一个你并未提出的问题给出看似合理的回答。

空间页头里的上下文计量条芯片背后也是同一个浏览器，它跟随的是同一个智能体——命令和该芯片对于这里“上下文”指什么，永远不会产生分歧。

## 询问这段对话

这些命令花一次模型调用，并且**绝不改变对话**。智能体下一个真正的回合看到的，与它本来就会看到的内容完全一样，而这正是“询问”的全部价值所在。

### `/handoff [focus]`

**旁路。** 为冷启动接手这项工作的人写一份交接文档：任务是什么、已经了解到什么、还剩什么。

### `/btw <question>`

**旁路。** 回答一个关于目前工作进展的问题，而不把问题或答案写进转录。

:::note[两个命令，一套实现]
两者形状相同——拿现有的对话照原样，就它提一个问题，两边都不持久化。只实现一次，因此不会各自漂移出两个不同的“截至目前为止的上下文”概念。
:::

## 导航与导出

### `/tree`

**本地。** 打开分支导航器：对话在哪里分叉、当前在哪条路径上，以及如何回到你离开的那一条。参见[分支对话](/zh-CN/手册/操作指南/分支对话/)。

### `/export`

**本地。** 把对话写成一个自包含的 HTML 文件——可折叠的工具卡片，没有样式表、没有脚本、没有图床。在桌面端落到 `Documents/ControlCenter/exports/`，在网页端则下载。

### `/dump`

**本地。** 把转录以 markdown 形式复制到剪贴板，工具调用放在可折叠的块中。推理内容被有意排除在外：粘贴进 bug 报告里的转录是要给人读的。

## 其他命令

### `/todo [subcommand]`

**本地。** 查看和编辑该对话持久化的待办列表。单独一个 `/todo` 会打开编辑器。子命令：`append`、`start`、`done`、`drop`（别名 `rm`）、`edit`、`copy`、`export`、`import`。

### `/skill:<name> [args]`

**派发。** 应用一个已安装的技能。技能位于它们自己的 `skill:` 前缀下，因此与内置命令不共享命名空间——否则，一个名为 `plan` 的技能将永远无法被触达。

### `/<your-command> [args]`

**派发。** 仓库中 `.agents/commands`、`.agent/commands`、`.claude/commands`、`.codex/commands` 或 `.opencode/commands` 下的任意 markdown 文件。嵌套的 `foo/bar.md` 也可以通过 `foo:bar` 触达。

模板化：`$1`、`$@`、`$@[start:length]` 和 `$ARGUMENTS`。frontmatter 可以设置 `description`（输入框自动补全）。`allowed-tools` 和 `model` 会从文件中解析出来，但当前调用用户命令时只会把参数替换进正文——它们不会改变该运行的模型或工具面。

用户自行编写的命令优先于同名的技能——它是人类带着参数有意调用的一条快捷方式。

## 魔法关键词

它们不是命令。提示词任何位置出现的一个小写独立单词，都会为该回合附加一条隐藏指令。

| 单词          | 效果                                                             |
| ------------- | ------------------------------------------------------------------ |
| `ultrathink`  | 该回合使用最高推理强度                              |
| `orchestrate` | 并行委派相互独立的工作，并验证每个阶段        |

匹配器刻意对边界要求严格。`orchestrate,` 会匹配；`orchestrated`、`orchestrate.ts`、`foo::orchestrate` 和 `orchestrate()` 不会，而且围栏代码块、内联代码片段和 XML 区块会先被屏蔽掉。否则，粘贴一段堆栈跟踪就会改变智能体的行为。
