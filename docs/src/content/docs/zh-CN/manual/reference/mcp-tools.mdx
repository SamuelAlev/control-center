`cc_server` 承载一个 MCP（JSON-RPC 2.0）工具注册表，在主服务器端口（默认 `9030`）上以 `POST /mcp` 和 `GET /sse` 对外提供服务，协议版本为 `2024-11-05`。每个客户端触达的都是同一个注册表：桌面端、Web 构建产物、外部 MCP 客户端，以及内置的智能体运行时。外部 MCP 服务器可以作为动态层桥接进同一个注册表。

## 注册表规模

| 指标                                                                         | 数量 |
| ---------------------------------------------------------------------------- | ----- |
| 由 `cc_server` 注册的工具                                                     | 110   |
| 来自 `packages/cc_mcp`                                                       | 108   |
| 来自 `packages/cc_mcp_client`（工具发现）                                     | 2     |
| 在基础注册表中注册（`server_mcp_registry.dart`）                              | 63    |
| 启动后随各自服务就绪而注册（`cc_server_runtime.dart`）                        | 47    |
| 基础注册表那 63 个中，以存在代码图仓库为条件的                                  | 5     |

这五个代码图工具只有在宿主向 `buildServerMcpRegistry` 传入代码图仓库时才会注册。`cc_server` 总会传一个，因此在随附的二进制文件中，全部 110 个都是生效的。

完整的注册表会在 `tools/list` 中公布，不带任何发现门控。工单编辑是类型化工具。

:::note[外部客户端始终能看到完整目录]
`tools/list` 从不裁剪。MCP 客户端会对照自己缓存的那份列表校验工具名，对未列出的名称直接拒绝，从不去询问服务器，因此在那里被隐藏的工具不是安安静静，而是根本无法触达。

**内置运行框架**不一样：每次请求只加载常驻的一部分定义，其余的在首次使用时才拉进来，这是运行框架侧的行为，不会改变这个注册表。参见[工具上下文与提示缓存](/zh-CN/手册/概念/工具上下文)。
:::

:::note[每个工具类都会被注册]
`packages/cc_mcp/lib/src/tools/` 下的每个源文件，都是一个智能体可以调用的工具。
如果新增的工具类没有被任何地方构造，`packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart`
就会让构建失败。
:::

## 通用参数

### `workspace_id`

**必填**。凡是涉及工作区范围数据的工具都要求它。缺失或无效的 `workspace_id` 会返回一个明确的错误，而与目标实体所属工作区不匹配的值会被拒绝，而不是被静默忽略。在真正全局的工具上请省略它：`list_workspaces` 和六个新闻流工具（`list_feeds`、`list_articles`、`get_article`、`set_article_read`、`set_article_saved`、`refresh_feeds`），它们依附于服务器所有者的按用户维度的订阅源列表。发现类工具（`search_tool_bm25`、`list_my_tools`）把它作为可选参数，以便按对话模式对可调用性进行分类。当智能体由服务器派发时，工作区是在服务器侧强制指定的，因此智能体无法通过传入一个外来的 id 触达另一个工作区。

## 工具发现

二者都来自 `cc_mcp_client` 而非 `cc_mcp`，并且都会查询模式守卫，因此它们报告的是*当前*对话模式下可调用的内容。

| 工具               | 说明                                                                                                              |
| ------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `search_tool_bm25` | 按关键词搜索工具目录；返回匹配的工具、它们的参数 schema，以及每个工具此刻是否可调用                                |
| `list_my_tools`    | 列出此对话中此刻可调用的工具，按其模式过滤                                                                         |

第三个发现类工具 **`search_tools`** 只存在于内置运行框架内部，不属于这个 MCP 注册表。它会对本次运行自身的工具面排序，并且与 `search_tool_bm25` 不同，它会**加载**所找到内容的 schema，以便智能体在下一轮就能调用其中的匹配项。运行框架上的智能体应优先用它；MCP 客户端则有 `search_tool_bm25`。

智能体通过空间彼此交流（持久、在名册中可见）。`ask_agent` 是请求/应答模式，超时是强制的；`delegate_task` 在服务器侧由深度上限、环路检测、预算包络和自主权上限守卫。

| `ask_agent`     | 向另一个智能体提问并等待其答复，或等到超时                                                        |

## 隔离舱（机台）工具

在一次运行内部驱动一次性机器——一个被隔离的浏览器或 Linux 桌面、一个 Android
模拟器，或一个 iOS 模拟器。启动后无条件注册：某台机器究竟能否启动，是一个探测问题，
由这些工具在每次调用时回答。同一对话中的重复调用会复用同一台机器；
截图以图片内容返回，每个结果限一张图，而抽取出的页面/界面内容会被围栏标记为
不受信任的数据。四个 use 工具加上 `rig_close` 都会声明 `enclosureControl`
[操作类别](/zh-CN/手册/概念/护栏/)（这些 use 工具还声明 `networkEgress` 和
`processSpawn`；`mobile_use` 和 `ios_use` 另外声明 `packageInstall`），因此只读模式会
拒绝它们。`rig_list` 不声明任何类别——它只读取工作区状态。每种形态完整的动词表见
[机台参考](/zh-CN/手册/参考/机台/#action-verbs)。

| 工具           | 说明                                                                                                                         |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `computer_use` | 在隔离的 VM 中驱动 Linux 桌面：移动、点击、拖拽、滚动、输入、调整大小、剪贴板、截图                                              |
| `browser_use`  | 驱动无头 Chromium、Firefox 或 WebKit（`engine`）：导航、点击、填写、抽取（a11y/DOM/console）、剪贴板、截图                       |
| `mobile_use`   | 通过 ADB 驱动 Android：检查/输入、截图、安装/启动/停止/重置/卸载应用、深链接以及 argv 形式的设备命令                              |
| `ios_use`      | 通过 WebDriverAgent/CoreSimulator 驱动 iOS 模拟器：检查/输入、截图、安装/启动/停止/卸载应用、深链接以及 argv 形式的模拟器进程        |
| `rig_list`     | 列出工作区的机台，含形态、状态、显示尺寸和控制器                                                                                 |
| `rig_close`    | 销毁一台机台并丢弃它拥有的机器状态                                                                                              |

## 未通过 MCP 暴露

日历和会议没有任何 MCP 工具。智能体无法读取你的日历、会议、转录记录、行动项或决定。产出行动项和决定的那份摘要，是作为内置的 [`meeting_summary` 流水线](/zh-CN/手册/概念/会议/)运行的，而不是作为一个智能体可以调用的工具。

## 按模式进行的工具门控

门控由同一张表（`ModeToolPolicy`）强制执行两次：一次在面向 Claude Code 适配器的 MCP 调度器中，一次在内置运行框架注册表中。被阻止的调用会返回原因。

| 模式          | 工具面                                                                                                                                                                                                                              |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`        | 所有已注册的工具；没有允许列表                                                                                                                                                                                                      |
| `plan`        | 一份精心筛选的允许列表。不允许工作树写入，也不允许 `create` / `assign` / `delegate` 这几个工单动词，但允许记忆、工件、待办、`submit_plan`、`exit_plan_mode`，以及针对被派发工单的工单完成动词                                          |
| `review`      | 一份精心筛选的允许列表：审查参与、沟通、只读的上下文获取器，以及完整的工单动词集，包括 `create_ticket` 和 `assign_ticket`                                                                                                            |
| `orchestrate` | 一份精心筛选的允许列表：调研和读取类工具，加上 `propose_orchestration`、`create_playbook` 和 `run_playbook`。招聘、任务分解和工单完成会在批准之后确定性地发生，绝不会在运行中途进行                                                     |

无论允许列表如何，在每种模式下都允许：

| 集合          | 工具                                                                                                                                                                                                                                                              |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 记忆与工件    | `search_memory`, `propose_fact`, `propose_policy`, `supersede_fact`, `supersede_policy`, `record_observation`, `update_my_notes`, `get_my_notes`, `list_memory_domains`, `list_policies`, `publish_artifact`, `revise_artifact`, `list_artifacts`, `get_artifact` |
| 代码图        | `search_code`, `code_symbol`, `code_callers`, `code_callees`, `code_impact`                                                                                                                                                                                       |
| 运行机制      | `search_tool_bm25`, `list_my_tools`, `todo_write`, `todo_read`                                                                                                                                                                                                    |

出现在允许列表上并不等于工具可调用，反过来也一样：向操作员提问这项能力是一个**运行框架**工具（`ask_user`），因此它根本不会出现在这个 MCP 目录中。

## 受审批约束的工具

工具可以声明 `requiresApproval`。调度器随后会构建一个 `ApprovalPayload`，并在工具运行前通过 `ConfirmationPort` 把它呈现出来；`cc_server` 接好了这个端口，因此闸门是生效的。

声明了它的已注册工具：`create_ticket`、`update_ticket`、`assign_ticket`、`reassign_ticket`、`close_ticket`、`ticket_relation`、`create_goal`、`update_goal_progress`、`create_approval`、`decide_approval`、`comment_approval`、`create_work_product`、`save_work_product_revision`、`create_runtime_profile`、`install_skill`、`update_skill`。

另外，统一的操作护栏会对任何声明了非空 `ActionClass` 集合的工具进行门控。在没有连接任何审批者时，`prompt` 决定会被拒绝。参见[护栏](/zh-CN/手册/概念/护栏/)。

## 背后没有对应工具的能力

产品中并非每一项能力都能被智能体触达。这些能力根本没有对应的工具，
因此你在别处可能见过被引用的某个名称，会返回 "unknown tool"：

| 能力                                       | 它改为存在于何处                                                                                                |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| 招聘、解雇或编辑智能体                       | 智能体界面。没有 `hire_agent` / `fire_agent` / `update_agent` 工具                                              |
| 创建工作区                                  | 通过 RPC 调用 `workspace.upsert`，它会播种并盖上所有权标记                                                        |
| 项目（创建 / 列出 / 更新 / 归入）             | 工单界面。项目是操作员的功能面——参见[项目](/zh-CN/手册/操作指南/项目/)                                            |
| 向操作员提问一个会阻塞的问题                  | **运行框架**的 `ask_user` 工具，而非 MCP。它会在对话中渲染一个表单，并阻塞等待回答                                 |
| 逐智能体诊断                                | 无。没有 `doctor`——参见[诊断智能体](/zh-CN/手册/操作指南/诊断智能体/)                                              |
| 日历和会议                                  | 仅面向人类客户端的 RPC（见上文）                                                                                  |
