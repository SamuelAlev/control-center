Control Center 可以向一个 [Umami](https://umami.is) 实例发送**假名化的使用事件**。使用情况分析**默认关闭，直到服务器运营者将其开启**。该设置属于服务器，对连接到它的每个客户端都生效：桌面应用、Web 应用、手机以及服务器本身。

使用情况分析与**分享崩溃报告**相互独立，后者是针对单台设备的崩溃与错误诊断设置。

## 由谁决定

| 开关 | 位置 | 作用 |
| --- | --- | --- |
| **分享使用情况分析** | 引导流程（沙箱步骤）和**设置 → 隐私**。只有服务器运营者可以更改；其他成员只能以只读方式看到当前值 | 作用于整个服务器。以 `telemetry.usage_analytics` 存储在服务器设置中。除非设为 `true`，否则保持关闭 |
| 构建类型 | 自动 | debug 和 profile 构建不会发送，而是把每个事件写入调试日志 |
| `CC_ANALYTICS_DEBUG=1` | `cc_server` 的环境变量或其 `.env` 文件 | 让服务器及所有连接到它的客户端的 debug 和 profile 构建真正发送数据，用于测试。上面的开关仍须开启 |
| `DO_NOT_TRACK=1` | `cc_server` 的环境变量 | 无论开关如何，都会停止服务器自身的上报。客户端仍遵循该开关 |
| 演示服务器 | 自动 | 公共演示服务器不会以自身名义发送任何内容。访客无法更改该开关 |

客户端从服务器读取该设置（先通过 `telemetry.config`，之后通过 `telemetry.watch` 实时获取）。在收到答复之前，事件会在一个小的内存缓冲区中等待。如果答复是否，缓冲区会被丢弃。关闭开关会丢弃所有仍在队列中的内容，并在每个客户端上立即停止发送。

## 永远不会发送的内容

- 消息、工单、审查或会议的内容，标题、提示词、shell 命令和搜索查询
- 姓名、登录名、电子邮件地址、头像和显示名称
- 文件路径、仓库名、分支名、主机名和 URL（仓库只以假名化的 `repo_id` 发送；会议链接只以其服务提供方发送）
- 任何形式的原始标识符

每个事件在离开进程之前都要经过一套属性策略。文本、路径、URL、电子邮件地址、未经包装的 ID，以及 `email`、`*_name`、`path`、`title`、`prompt`、`content` 或 `token` 等键下的字符串都会被丢弃，而不是发送出去。只有当字符串是来自封闭词表的短标记时才会被发送，例如枚举值、版本号、区域设置或模型 ID。

## 假名化 ID

ID 会被发送，但只以假名形式出现。每个工作区、空间、会话、智能体、运行、用户和设备的 ID 都会被替换为使用该安装自身的秘密盐值（`telemetry.pseudonym_salt`）计算的 HMAC-SHA256，并截断为 20 个十六进制字符。同一个工作区始终上报相同的值，因此事件可以关联和计数，但原始 ID 从不离开该安装。盐值在服务器首次启动时创建，从不发送给分析服务提供方。删除服务器的数据目录会生成新的盐值和安装 ID，从而与之前记录的所有内容断开关联。

## 每个事件都带有的属性

| 属性 | 示例 | 含义 |
| --- | --- | --- |
| `app_type` | `desktop` | `desktop`、`web`、`remote`（手机）或 `server`。同时用作 Umami 中的主机名 |
| `app_version` | `0.0.11` | 发布版本 |
| `app_build` | `4baf980` | 该构建的 git 短提交号 |
| `platform` | `macos` | `macos`、`windows`、`linux`、`web`，或手机的操作系统（`ios`、`android`） |
| `locale` | `fr_FR` | 界面语言 |
| `server_mode` | `local` | `local`（桌面端运行自己的服务器）或 `remote` |
| `server_version` | `0.0.11` | 已连接服务器的版本（如已知） |
| `is_demo` | `false` | 客户端是否连接到公共演示 |
| `install_id` | 假名 | 服务器安装 |
| `user_id` | 假名 | 已登录的用户（一旦得知） |
| `device_id` | 假名 | 已配对的设备（一旦得知）。也是 Umami 中的唯一 ID |
| `launch_id` | 假名 | 一次应用启动，用于为一个会话的事件排序 |
| `event_seq` | `12` | 事件在本次启动中的序号 |

此外，Umami 还会收到请求的 IP 地址（它据此推断国家和地区，但不存储地址本身），以及 User-Agent 和屏幕尺寸。

## 屏幕浏览

每次导航都会记录一次页面浏览，其 URL 是**路由模板**，例如 `/workspaces/:workspaceId/spaces/:spaceId`，而不是具体地址。屏幕名称由模板中的字面片段组成，因此上例为 `workspaces_spaces`。以 `Id` 结尾的路由参数会作为假名化的 `*_id` 属性附加，数字参数（例如 PR 编号）则作为数字附加。其他参数一律丢弃。

## 服务器事件

由 `cc_server` 记录，针对任何单个客户端都无法恰好看到一次的事实。智能体的一次运行只计一次，无论有多少客户端在查看。

| 事件 | 属性 | 记录时机 |
| --- | --- | --- |
| `server_started` | `workspace_count`、`startup_ms` | 服务器完成启动 |
| `workspace_created` | `workspace_id` | 创建了一个工作区 |
| `space_created` | `workspace_id`、`space_id` | 创建了一个空间 |
| `repo_added` | `workspace_id`、`repo_id` | 关联了一个仓库 |
| `ticket_created` | `workspace_id`、`ticket_id` | 有人或智能体创建了工单 |
| `agent_run_completed` | `agent_id`、`workspace_id`、`conversation_id`、`run_id`、`status`、`error_family`、`role`、`adapter`、`model`、`effort`、`task_family`、`subagent`、`pipeline`、`resumed_native_session`、`duration_ms`、`time_to_first_token_ms`、`input_tokens`、`output_tokens`、`thought_tokens`、`cache_read_tokens`、`cache_write_tokens`、`output_rejections`、`cost_usd` | 智能体运行结束 |

| `workspace_member_changed` | `workspace_id`、`member_user_id`、`change`（`added`、`removed`、`role_changed`）、`role` | 工作区成员发生变化 |

## 投递

事件从一个最多容纳 200 个事件的内存队列中逐个发送到 `<host>/api/send`。遇到网络错误、超时、`429` 或 `5xx` 时会保留事件，并以指数退避重试，间隔从 1 秒逐步增加到 5 分钟。其他任何 `4xx` 都会丢弃该事件。不会向磁盘写入任何内容，因此应用退出时仍在队列中的事件会丢失。应用转入后台以及服务器关闭时，队列会被清空发送。

## 让构建指向另一个实例

目标地址在构建时确定：

```bash
--dart-define=CC_ANALYTICS_HOST=https://analytics.example.com/
--dart-define=CC_ANALYTICS_WEBSITE_ID=<website uuid>
```

服务提供方适配器位于 `packages/cc_analytics`。要支持其他分析服务，只需在那里添加一个适配器。追踪方案和隐私规则保持不变。
