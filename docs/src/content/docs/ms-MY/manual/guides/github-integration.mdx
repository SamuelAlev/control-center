Panduan ini merangkumi bahagian persediaan yang khusus untuk GitHub. GitHub
ialah salah satu daripada tiga hos kod yang disokong. Lihat
[Sambungkan hos kod](/ms-MY/manual-pengguna/panduan-cara/sambungkan-hos-kod/)
untuk menyambung GitLab atau Bitbucket, dan untuk cara sesuatu ruang kerja
menggabungkan ketiganya.

## Prasyarat

- Akaun GitHub dengan akses ke repo yang anda mahu kerjakan
- Pelayan yang boleh mendaftar masuk orang ke GitHub: sama ada GitHub App milik pelayan anda (lihat
  [Cipta GitHub App](/ms-MY/manual-pengguna/panduan-cara/github-app/)) atau Control Center Connect,
  dipilih oleh pemilik pelayan dalam **Tetapan → Pelayan → Daftar masuk tunggal**

:::note[Kelayakan tersimpan di pelayan, terikat pada anda]
Tiada apa-apa disimpan pada mesin yang anda sedang taip ini. Log masuk GitHub anda
dipegang oleh `cc_server` anda, dikunci berdasarkan id pengguna anda, dan setiap
peranti tempat anda log masuk memakainya — desktop, web dan telefon. Ahli lain
pada pelayan yang sama tidak boleh menggunakannya, dan melog masuk mereka ialah
sesuatu yang mereka lakukan sendiri.
:::

## Log masuk ke GitHub

GitHub hanya menggunakan log masuk: tiada token untuk ditampal.

1. Pergi ke **Tetapan → Anda → Profil → Hos kod** (atau langkah pertama
   onboarding)
2. Pada baris **GitHub**, klik **Log masuk ke GitHub**
3. Pelayar anda membuka GitHub. Luluskan apl itu

Cara log masuk selesai bergantung pada pihak yang menjalankannya:

- **Apl pelayan itu sendiri:** GitHub menghantar pelayar anda kembali ke pelayan dan dialog itu
  mengesannya sendiri. Anda tidak perlu menaip apa-apa
- **Control Center Connect:** halaman pelayar memaparkan kod 8 aksara. Taip kod itu ke dalam
  dialog, atau biarkan pelayar membuka Control Center melalui pautan `control-center://` dan
  langkau menaip kod

Titik pemeriksaan: baris **GitHub** berbunyi "Log masuk sebagai _your-username_".

Dialog itu menolak kod atau pautan yang ia tidak mulakan sendiri, dengan **Log masuk tidak dimulakan di sini**.
Jika seseorang menghantar anda pautan log masuk, jangan teruskan: menyelesaikannya akan menyambungkan
akaun anda kepada pelayan mereka.

Klik **Nyahsambung** untuk membuang log masuk anda. Log keluar daripada GitHub, atau dikeluarkan daripada
sesuatu ruang kerja, juga membatalkan setiap token yang dicetak oleh pelayan bagi pihak anda.

## Siapa yang diwakili kelayakan anda

Control Center mengikut pembahagian GitHub sendiri antara bertindak **sebagai seseorang** dan bertindak **sebagai app**:

| Apa yang berlaku                                                                                  | Dipaparkan di GitHub sebagai                                                                       |
| ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Apa sahaja yang anda lakukan sendiri: mengulas, menyemak, meluluskan, mencantum, meminta penyemak | **Anda**. GitHub menandakan komen dalam perbualan sebagai dibuat dengan apl Control Center; semakan dan komen sebarisnya tidak membawa tanda sedemikian |
| Semakan AI, balasan dan ulasan ejen dalam perbualan PR, label, kerja pipeline dan bot                       | **Bot Control Center**. Pada app Connect dikongsi, semakan hanya milik bot untuk pemasangan yang pengendali Connect senaraikan; jika tidak, ia dipaparkan sebagai orang yang bertanggungjawab                                                                             |
| Pull request yang dibuka oleh ejen untuk anda, suntingan pada tajuk atau keterangan pull request itu, push-nya dan komitnya                              | **Anda**. Control Center dikreditkan sebagai pengarang bersama apabila kredit pengarang bersama dihidupkan |
| Kerja yang tiada sesiapa minta (jadual, webhook)                                                  | **Bot Control Center**, sebagai pengarang komitnya juga. Pada Control Center Connect, ia tidak pernah push atau membuka pull request                 |

- **Apa sahaja yang anda lakukan** berjalan di bawah log masuk **anda** dan tiada yang lain. Jika anda belum log masuk, apl itu meminta anda log masuk. Tiada kelayakan lain yang menggantikan anda
- **Kerja bot** menerima token untuk satu repositori pada satu masa, dihadkan kepada apa yang boleh dilakukan oleh ahli yang bertanggungjawab di sana: yang meminta, atau jika tidak, pemilik ruang kerja. Ahli yang tidak boleh push menghadkannya kepada baca sahaja. Balasan bot yang bertindak untuk seseorang bermula dengan **Control Center (for @login)**
- **Ejen membuka pull request melalui Control Center**, tidak pernah dari kotak pasir mereka, jadi pull request itu milik anda dan peraturan GitHub sendiri menghalang anda daripada meluluskannya. Control Center juga menolak kelulusan daripada orang yang meminta ejen itu dan daripada pengarang pull request. Untuk larian berjadual atau webhook, ini merangkumi setiap pentadbir yang mengaktifkan pencetusnya atau mengedit pipelinenya semasa ia diaktifkan. Orang lain mesti menyemak. Jika Control Center tidak dapat mengesahkan siapa yang membuka pull request, atau akaun mana pada forge yang merupakan milik anda, ia menolak dan meminta anda mencuba semula
- **Ejen mengulas melalui Control Center juga.** Token GitHub yang diterima oleh larian ejen hanya membaca. Apabila ejen mengulas pada pull request yang sedang dikerjakannya, Control Center memposkan komen itu sebagai bot, bermula dengan **Control Center (for @login)** apabila seseorang meminta larian itu. Ejen hanya boleh mengulas pada pull request dalam repositori yang sama (bukan fork), yang komit terakhirnya ditolak oleh ejen atau merupakan komit semasa cawangan ruangnya. @-sebutan dalam komen ejen tidak memberitahu sesiapa. Ejen juga boleh menukar tajuk atau keterangan pull request miliknya semasa ia masih terbuka. Suntingan itu dibuat dengan cara pull request itu dibuka (sebagai anda, apabila anda meminta larian itu), dan meminta kelulusan terlebih dahulu secara lalai. Keterangan pull request mengekalkan @-sebutannya, apabila ejen membukanya dan apabila ejen menyuntingnya, supaya orang yang dinamakannya diberitahu
- **Pada Control Center Connect, bot tidak pernah push atau membuka pull request.** Push, mencipta cawangan atau membuka pull request di sana memerlukan orang yang memintanya, dan berjalan di bawah log masuk orang itu. Larian berjadual atau webhook yang cuba push akan berhenti dengan mesej yang menyatakannya. Untuk membenarkan larian tanpa pengawasan push, berikan ruang kerja GitHub App sendiri dalam **Tetapan**
- **Apa yang boleh dilakukan bot Connect.** Dengan app Connect dikongsi, bot mengulas, melabel dan memberi reaksi. Ia menyiarkan semakan (semakan AI, komen semakan, permintaan penyemak) hanya apabila pengendali Connect telah menyenaraikan pemasangan pelayan ini. Jika tidak, semakan itu dihantar menggunakan log masuk orang yang bertanggungjawab sendiri dan muncul di bawah nama mereka. Bot tidak pernah membuka, mengedit, menutup atau menamakan semula pull request, membatalkan semakan, atau mengedit atau memadam komen; itu memerlukan seseorang yang memintanya, dengan log masuk mereka sendiri. Connect tidak mengikat pemasangan organisasi anda kepada satu pelayan Control Center; mana-mana pelayan tempat ahli yang boleh push ke repositori telah log masuk melalui Connect boleh mendapat token komen bot ini untuk repositori itu
- **Pelayan atau ruang kerja dengan GitHub App sendiri** mengekalkan bot untuk semua di atas, termasuk semakan
- **Automasi tidak pernah meluluskan** pull request. Kelulusan ialah tindakan seseorang

Apabila anda memautkan repo, Control Center menyemak bahawa akaun anda boleh melihatnya, dan memberi amaran apabila GitHub App tidak dipasang pada organisasinya atau tidak merangkumi repo itu, dengan pautan untuk membetulkannya. Memautkan dan menyahpautkan memerlukan admin ruang kerja, dan checkout di luar storan ruang kerja itu sendiri hanya boleh dipautkan oleh pemilik pelayan; lihat [Tambah repo ke ruang kerja](/ms-MY/manual-pengguna/panduan-cara/tambah-repositori/).

Pautan itu mengikut id GitHub kekal repositori, jadi penamaan semula atau pemindahan tidak memerlukan apa-apa daripada anda. Jika laluan itu kemudian menamakan repositori yang berbeza, Control Center berhenti menghantar apa-apa kepadanya dan memaparkan notis sehingga admin ruang kerja mengklik **Pautkan semula**.

Membuka kod repositori (fail, diff, carian, terminal) memerlukan kedua-dua geran dalam ruang kerja dan log masuk GitHub anda yang boleh membacanya. Admin ruang kerja mengikut peraturan yang sama; hanya pemilik pelayan dikecualikan.

## Apa yang integrasi ini berikan kepada anda

| Ciri                  | Cara                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------------- |
| Senarai dan butiran PR | API REST GitHub, dari pelayan, dengan log masuk anda sendiri                                                 |
| Larian semakan        | API Checks GitHub                                                                                             |
| Penerbitan semakan    | Langkah berpagar pengguna yang menyiarkan semakan anda ke PR, atas nama anda                                  |
| Pendaftaran repo      | Checkout diterima jika remote `origin`-nya menunjuk ke github.com — atau ke gitlab.com / bitbucket.org        |
| Akses GitHub ejen     | Dalam larian, `git fetch` melalui Control Center, yang mengambil repositori yang dikerjakan larian dengan token baca sahaja yang tidak pernah dipegang larian. `gh` membacanya dengan token baca sahaja yang diberikan oleh Control Center apabila diminta dan dibatalkan apabila larian tamat. Push, pull request, suntingannya dan komen melalui Control Center |
| Ping pemberitahuan    | Pengundian di sisi pelayan bagi peti masuk pemberitahuan GitHub anda memunculkan "disebut dalam pull request" dan "semakan diminta" |
| Profil pengguna       | Kad hover profil dan penapisan PR mengikut pengarang                                                          |

Sesetengah laluan menggunakan API GraphQL dan bukan REST apabila ia lebih murah:
aktiviti cabang untuk pemilih compose-PR dan keadaan semakan langsung yang
menentukan sama ada pemberitahuan permintaan semakan masih tergantung.

## Perhatikan gangguan GitHub

Bar tajuk menunjukkan cip status apabila sesuatu penyedia terganggu, merangkumi
GitHub, Claude, OpenAI dan Kimi. **Ia tersembunyi selagi semuanya sihat**:
kehadirannya melaporkan masalah, bukan ketiadaannya.

Klik cip itu untuk membuka panel timbul dengan keadaan setiap penyedia dan
butang muat semula. Status itu dimuat semula sendiri setiap dua minit.

## Fahami cara ejen bertindak di GitHub

- Ejen yang bekerja dalam worktree GitHub mendapat token untuk repositori itu. Ia hanya boleh membaca kod, isu dan pull request. Komen melalui Control Center seperti yang diterangkan di atas. Push melalui Control Center, yang bertanya kepada peraturan **Push ke remote** dan kemudian memajukannya dengan token tulis yang tidak pernah dipegang ejen. Lihat
  [Konfigurasikan polisi kotak pasir](/ms-MY/manual-pengguna/panduan-cara/polisi-kotak-pasir/)
- Kerja yang anda mulakan dikomit sebagai anda. Apabila anda meminta ejen untuk sesuatu, atau mengkomit dalam IDE, anda ialah pengarang dan pengkomit, di bawah alamat yang disahkan oleh forge anda: alamat noreply GitHub anda daripada log masuk GitHub anda, atau pada GitLab dan Bitbucket e-mel yang dilaporkan oleh log masuk anda di sana. Identiti Git ruang kerja anda hanya digunakan untuk komit yang anda buat sendiri dalam repositori yang tiada forge mengesahkan alamat anda. Jika anda tidak log masuk ke forge itu, komit ejen ialah milik bot dan nota larian menyatakannya
- Kerja yang tiada sesiapa minta dikomit sebagai bot. Larian berjadual atau webhook mengkomit sebagai GitHub App ruang kerja (`<app>[bot]`, dengan alamat noreply GitHubnya), atau sebagai `Control Center <hi@usectrl.dev>` apabila tiada GitHub App atau repositori berada di GitLab atau Bitbucket
- **Beri kredit kepada Control Center sebagai pengarang bersama** (**Tetapan** → **Anda** → **Commit**) menambah treler `Co-Authored-By:` untuk pihak lain: Control Center pada komit anda, dan pada komit bot setiap orang yang mengaktifkan pencetus di sebalik larian itu. Ia dihidupkan melainkan anda mematikannya. Admin ruang kerja boleh menentukannya untuk semua orang dengan **Kredit pengarang bersama** dalam **Tetapan** → **Ruang kerja** → **Umum**; pilihan anda sendiri kemudian disimpan tetapi tidak terpakai dalam ruang kerja itu. Atribusi Claude Code sendiri sentiasa dinyahaktifkan
- Komit anda boleh ditandatangani. Di bawah **Komit yang disahkan** dalam **Tetapan** → **Anda** → **Commit**, pilih **Cipta kunci tandatangan** dan tambah separuh awamnya pada akaun GitHub atau GitLab anda sebagai kunci tandatangan; sejak itu komit larian yang anda minta, dan komit yang anda buat dalam IDE, dipaparkan sebagai disahkan. Separuh peribadi kekal pada pelayan anda, jadi sesiapa yang mengawal pelayan itu boleh menandatangani komit sebagai anda selagi kunci itu berada pada akaun anda, dan pada GitHub komit yang sudah dipaparkan sebagai disahkan kekal disahkan selepas anda membuang kunci itu. Bitbucket tidak mempunyai kunci khusus tandatangan: jangan tambah kunci di sana, dan komit pada Bitbucket tidak ditandatangani. Komit bot tidak pernah ditandatangani
- Komit yang anda buat dalam panel **Kawalan sumber** IDE melangkau cangkuk Git repositori, seperti `git commit --no-verify`, dan Git pada pelayan mengabaikan pembantu kelayakan, editor, alat diff luaran dan penandatangan yang dikonfigurasikan oleh repositori: ia menjalankan Git pada mesinnya sendiri, dalam pokok yang boleh diubah oleh ejen atau pull request. Lihat [Komit dan tolak dari Kawalan sumber](/ms-MY/manual-pengguna/panduan-cara/semak-dan-cantumkan-pr/#komit-dan-tolak-daripada-kawalan-sumber)
- Setiap komit yang ditolak oleh ejen diperiksa dahulu, termasuk lapisan yang ditolak oleh `stack_publish` untuk stack. Push yang menamakan orang lain, membuang atau meminjam sesuatu kredit, menambah sign-off, atau tidak ditandatangani sebagaimana tetapan anda menyatakan ditolak. Komit yang anda push sendiri dari IDE adalah milik anda dan tidak diperiksa dengan cara ini
- Terminal yang anda buka pada rig menerima log masuk anda sendiri, dihadkan kepada satu repositori, jadi push di sana adalah milik anda
- Apabila tiada token dapat dicetak (tiada ahli yang bertanggungjawab sedang log masuk, apl tidak dipasang pada pemilik, atau pemasangan digantung), arahan yang memintanya menerangkan sebabnya. Tiada kelayakan sandaran

## Penyelesaian masalah

### Senarai PR kosong dan menyatakan GitHub tidak disambungkan

Anda tidak log masuk ke GitHub pada pelayan ini. Klik **Log masuk ke GitHub** di bawah **Tetapan → Anda → Profil → Hos kod**.
Repo pada hos kod lain tidak terjejas.

### Baris GitHub menyatakan log masuk belum disediakan pada pelayan ini

Pelayan tiada GitHub App sendiri mahupun Connect. Pemilik pelayan memilih salah satu dalam **Tetapan → Pelayan →
Daftar masuk tunggal**: **Cipta aplikasi GitHub saya** mengambil masa kira-kira dua minit. Lihat
[Cipta GitHub App](/ms-MY/manual-pengguna/panduan-cara/github-app/).

Dalam ruang kerja yang menggunakan apl sendiri, baris itu menyatakannya apabila GitHub App ruang kerja tiada atau tidak
lengkap. Pentadbir ruang kerja melengkapkannya pada kad **Apl GitHub** dalam **Tetapan → Ruang kerja → Integrasi**; lihat
[Berikan satu ruang kerja app sendiri](/ms-MY/manual-pengguna/panduan-cara/github-app/#berikan-satu-ruang-kerja-app-sendiri).

### Dialog memaklumkan kod tidak sepadan

Taip kod tepat seperti yang dipaparkan pelayar: 8 huruf dan digit. Lima kali salah memasukkan kod akan menamatkan
log masuk; mulakan semula.

### Log masuk memaklumkan apl belum dipasang

GitHub App tidak mempunyai sebarang pemasangan pada akaun yang memiliki repositori. Seorang pentadbir ruang kerja
memasangnya dari **Tetapan → Ruang kerja → Integrasi → Pemasangan aplikasi GitHub**.

### Semua orang perlu log masuk ke GitHub semula

Pemilik pelayan memutar kunci Connect pelayan, bertukar kepada pelayan Connect lain, atau direktori data
dipulihkan ke mesin lain. Log masuk melalui Connect terikat kepada pelayan yang menciptanya.

### Penambahan repo ditolak

Pendaftaran memerlukan ketiga-tiganya: laluan itu berada di dalam work tree git,
ia mempunyai remote `origin`, dan remote itu menunjuk ke hos kod yang disokong
(github.com, gitlab.com atau bitbucket.org). `origin` mestilah repositori yang anda pautkan, dan
folder di luar storan ruang kerja itu sendiri hanya boleh dipautkan oleh pemilik pelayan. Lihat
[Tambah repositori ke ruang kerja](/ms-MY/manual-pengguna/panduan-cara/tambah-repositori/).

### Saya ada geran tetapi repositori menyatakan akaun saya tidak boleh membacanya

Akaun GitHub anda tidak boleh membaca repositori itu, jadi kodnya kekal tertutup kepada anda walaupun
dengan geran ruang kerja. Log masuk ke GitHub di bawah **Hos kod**, atau minta akses kepada repositori
itu di GitHub.

### "Tidak dapat mengesahkan akses GitHub anda"

GitHub tidak dapat dihubungi untuk menyemak akses anda, jadi Control Center menolak dan bukan meneka.
Cuba lagi sebentar nanti.

### Semakan pada Connect muncul di bawah nama saya, bukan nama bot

Pada app Connect dikongsi, bot hanya menyiarkan semakan untuk pemasangan yang pengendali Connect telah
senaraikan. Di tempat lain semakan dihantar menggunakan log masuk orang yang bertanggungjawab sendiri. Untuk membolehkan bot menyiarkan semakan, berikan ruang kerja GitHub App sendiri.

### Semuanya berhenti berfungsi seketika selepas penggunaan berat

Itulah pemutus litar had kadar. GitHub menandakan had utamanya dengan `403` yang
membawa `x-ratelimit-remaining: 0` dan masa set semula; apabila melihatnya,
klien menggagalkan permintaan seterusnya secara setempat tanpa panggilan
rangkaian sehingga tetingkap itu berlalu, jadi ribut cuba semula tidak boleh
memperdalam had itu. Kegagalan sementara dicuba semula sehingga tiga kali dengan
backoff eksponen, sambil menghormati `retry-after`.
