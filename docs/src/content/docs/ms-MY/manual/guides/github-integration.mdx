Panduan ini merangkumi bahagian persediaan yang khusus untuk GitHub. GitHub
ialah salah satu daripada tiga hos kod yang disokong — lihat
[Sambungkan hos kod](/ms-MY/manual-pengguna/panduan-cara/sambungkan-hos-kod/)
untuk menyambung GitLab atau Bitbucket, dan untuk cara sesuatu ruang kerja
menggabungkan ketiganya.

## Prasyarat

- Akaun GitHub dengan akses ke repo yang anda mahu kerjakan
- Sama ada GitHub App yang didaftarkan untuk pelayan anda (lihat
  [Cipta GitHub App](/ms-MY/manual-pengguna/panduan-cara/github-app/)) supaya anda boleh **log masuk**,
  **atau** personal access token dengan `repo` dan `read:org` untuk ditampal

:::note[Kelayakan tersimpan di pelayan, terikat pada anda]
Tiada apa-apa disimpan pada mesin yang anda sedang taip ini. Kelayakan anda
dipegang oleh `cc_server` anda, dikunci berdasarkan id pengguna anda, dan setiap
peranti tempat anda log masuk memakainya — desktop, web dan telefon. Ahli lain
pada pelayan yang sama tidak boleh membacanya, dan melog masuk mereka ialah
sesuatu yang mereka lakukan sendiri.
:::

## Log masuk dengan GitHub

**Aliran peranti**: GitHub menunjukkan kod pendek kepada anda, anda
meluluskannya di github.com, dan pelayan menerima kelayakan itu — tiada URL
panggil balik, tiada port, tiada apa-apa untuk didedahkan. Tersedia apabila
pelayan mempunyai client id, yang sudah disertakan dalam binaan rasmi.

1. Pergi ke **Tetapan → Ruang kerja → Profil & identiti → Hos kod** (atau langkah pertama
   onboarding)
2. Pada baris **GitHub**, klik **Log masuk dengan GitHub**
3. Dialog menunjukkan kod lapan aksara dan membuka
   [github.com/login/device](https://github.com/login/device) dalam pelayar anda.
   Kod itu sudah ada pada papan klip anda
4. Tampalkannya, luluskan apl itu, dan kembali. Baris itu bertukar sendiri
   kepada "Log masuk sebagai _your-username_"

Dialog itu boleh ditutup semasa anda menyelesaikannya dalam pelayar — pelayan
terus mengundi sehingga kod itu tamat tempoh (kira-kira 15 minit), jadi log
masuk itu tetap berjaya.

## Atau tampal token

Pilihan sandaran apabila pelayan tiada apl, apabila apl itu tidak dipasang pada
akaun yang anda perlukan, atau apabila anda lebih suka menggunakan PAT.

1. Pergi ke **Tetapan → Ruang kerja → Profil & identiti → Hos kod**
2. Pada baris **GitHub**, klik **Tambah token**
3. Tampal token dengan `repo` dan `read:org` (classic) kemudian simpan. Token
   **berbutir halus** memerlukan **Contents** dan **Pull requests** repositori
   (baca dan tulis), serta **Checks** dan **Actions** (baca).

Token itu diperiksa semasa ia disimpan, jadi baris itu boleh menamakan akaun
pemiliknya. Klik **Putuskan** untuk membuangnya.

Titik pemeriksaan: baris **GitHub** berbunyi "Log masuk sebagai _your-username_".
Satu akhiran menamakan sumbernya apabila kelayakan yang menjawab bukan milik
anda — "melalui apl pelayan ini" atau "daripada persekitaran".

:::note[Keutamaan adalah tetap]
Permintaan yang dibuat bagi pihak anda menggunakan kelayakan **anda**, dan tiada
yang lain — persekitaran ialah kelayakan pelayan, bukan milik anda, jadi ia
tidak pernah menggantikan anda. Kerja yang tiada manusia di belakangnya
(webhook, pengundian PR, penyegerakan tiket) menggunakan identiti apl pelayan,
kemudian kelayakan pemilik pelayan, kemudian persekitaran.
:::

## Apa yang integrasi ini berikan kepada anda

| Ciri                  | Cara                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------------- |
| Senarai dan butiran PR | API REST GitHub, dari pelayan, dengan identiti apl atau kelayakan anda sendiri                               |
| Larian semakan        | API Checks GitHub                                                                                             |
| Penerbitan semakan    | Langkah berpagar pengguna yang menyiarkan semakan anda ke PR                                                  |
| Pendaftaran repo      | Checkout diterima jika remote `origin`-nya menunjuk ke github.com — atau ke gitlab.com / bitbucket.org        |
| Akses GitHub ejen     | Broker kelayakan menyuntik token baca sahaja sebagai `GH_TOKEN` / `GITHUB_TOKEN`; push melalui Control Center |
| Ping pemberitahuan    | Pengundian di sisi pelayan bagi peti masuk pemberitahuan GitHub anda memunculkan "disebut dalam pull request" dan "semakan diminta" |
| Profil pengguna       | Kad hover profil dan penapisan PR mengikut pengarang                                                          |

Sesetengah laluan menggunakan API GraphQL dan bukan REST apabila ia lebih murah —
aktiviti cabang untuk pemilih compose-PR dan keadaan semakan langsung yang
menentukan sama ada pemberitahuan permintaan semakan masih tergantung.

## Perhatikan gangguan GitHub

Bar tajuk menunjukkan cip status apabila sesuatu penyedia terganggu, merangkumi
GitHub, Claude, OpenAI dan Kimi. **Ia tersembunyi selagi semuanya sihat** —
kehadirannya melaporkan masalah, bukan ketiadaannya.

Klik cip itu untuk membuka panel timbul dengan keadaan setiap penyedia dan
butang muat semula. Status itu dimuat semula sendiri setiap dua minit.

## Fahami cara ejen bertindak di GitHub

- Ejen yang bekerja dalam worktree GitHub sentiasa mendapat token GitHub baca
  sahaja. Push melalui Control Center, yang bertanya kepada peraturan **Push ke
  remote** dan kemudian memajukannya dengan token tulis yang tidak pernah
  dipegang ejen. Lihat
  [Konfigurasikan polisi kotak pasir](/ms-MY/manual-pengguna/panduan-cara/polisi-kotak-pasir/)
- Commit yang dibuat ejen ditulis **atas nama ejen** — nama paparan ditambah
  ` (agent)`, pada alamat sintetik yang dikunci berdasarkan id ejen — tidak
  pernah atas nama manusia. Orang yang memintanya dicatat melalui trailer
  `Co-Authored-By`
- Dengan GitHub App dikonfigurasikan, broker menjana token pemasangan berbutir
  halus, berskop repo, berdurasi kira-kira satu jam bagi setiap pelancaran, dan
  bukan menyerahkan token yang luas. Pemasangan itu diselesaikan daripada
  **pemilik** repo larian tersebut, jadi satu apl yang dipasang pada beberapa
  akaun berskop dengan betul kepada mana-mana akaun yang disentuh oleh larian
  itu. Tanpa apl, ejen menerima token persekitaran, yang tidak boleh
  disempitkan kepada baca sahaja: peraturan push kemudian mengikat `git push`,
  tetapi tidak kod yang menggunakan token secara terus
- Token itu sentiasa milik broker, tidak pernah milik ahli yang meminta. Token
  pelayan ditahan daripada larian yang bertindak bagi ahli yang bukan pemilik
  dan belum menyambungkan GitHub

## Penyelesaian masalah

### Senarai PR kosong dan menyatakan GitHub tidak disambungkan

Anda tiada kelayakan GitHub pada pelayan ini. Log masuk atau tampal token di
bawah **Hos kod**. Repo pada hos kod lain tidak terjejas — hanya repo GitHub
yang tidak menyumbang apa-apa.

### Baris menawarkan "Tambah token" tetapi tiada "Log masuk dengan GitHub"

Pelayan tiada client id — keadaan biasa bagi binaan daripada sumber, kerana
kelayakan hanya ditanam dalam binaan rasmi. Lihat
[Cipta GitHub App](/ms-MY/manual-pengguna/panduan-cara/github-app/): ia mengambil masa kira-kira dua minit
dan hanya pemilik pelayan perlu melakukannya, sekali sahaja.

### Dialog log masuk menyatakan penyedia tidak mengembalikan kod peranti

GitHub App itu wujud tetapi kotak centang **Device flow**-nya dimatikan.
Hidupkannya dalam tetapan apl itu (General → Device flow) kemudian cuba lagi.

### Baris menyatakan "melalui apl pelayan ini" sedangkan saya menjangkakan akaun saya sendiri

Anda belum log masuk; apa yang anda lihat ialah identiti apl pelayan yang
menjawab. Klik **Log masuk dengan GitHub** pada baris itu.

### PAT berbutir halus tidak menunjukkan butang cantum atau status semakan

Token itu memerlukan **Contents** dan **Pull requests** (baca dan tulis), serta
**Checks** dan **Actions** (baca). Selepas mengubahnya, tampalnya semula di
bawah Hos kod.

### Penambahan repo ditolak

Pendaftaran memerlukan ketiga-tiganya: laluan itu berada di dalam work tree git,
ia mempunyai remote `origin`, dan remote itu menunjuk ke hos kod yang disokong
(github.com, gitlab.com atau bitbucket.org). Lihat
[Tambah repositori ke ruang kerja](/ms-MY/manual-pengguna/panduan-cara/tambah-repositori/).

### Semuanya berhenti berfungsi seketika selepas penggunaan berat

Itulah pemutus litar had kadar. GitHub menandakan had utamanya dengan `403` yang
membawa `x-ratelimit-remaining: 0` dan masa set semula; apabila melihatnya,
klien menggagalkan permintaan seterusnya secara setempat tanpa panggilan
rangkaian sehingga tetingkap itu berlalu, jadi ribut cuba semula tidak boleh
memperdalam had itu. Kegagalan sementara dicuba semula sehingga tiga kali dengan
backoff eksponen, sambil menghormati `retry-after`.
