Panduan ini merangkumi bahagian persediaan yang khusus untuk GitHub. GitHub
ialah salah satu daripada tiga hos kod yang disokong. Lihat
[Sambungkan hos kod](/ms-MY/manual-pengguna/panduan-cara/sambungkan-hos-kod/)
untuk menyambung GitLab atau Bitbucket, dan untuk cara sesuatu ruang kerja
menggabungkan ketiganya.

## Prasyarat

- Akaun GitHub dengan akses ke repo yang anda mahu kerjakan
- Pelayan yang boleh mendaftar masuk orang ke GitHub: sama ada GitHub App milik pelayan anda (lihat
  [Cipta GitHub App](/ms-MY/manual-pengguna/panduan-cara/github-app/)) atau Control Center Connect,
  dipilih oleh pemilik pelayan dalam **Tetapan → Pelayan → Daftar masuk tunggal**

:::note[Kelayakan tersimpan di pelayan, terikat pada anda]
Tiada apa-apa disimpan pada mesin yang anda sedang taip ini. Log masuk GitHub anda
dipegang oleh `cc_server` anda, dikunci berdasarkan id pengguna anda, dan setiap
peranti tempat anda log masuk memakainya — desktop, web dan telefon. Ahli lain
pada pelayan yang sama tidak boleh menggunakannya, dan melog masuk mereka ialah
sesuatu yang mereka lakukan sendiri.
:::

## Log masuk ke GitHub

GitHub hanya menggunakan log masuk: tiada token untuk ditampal.

1. Pergi ke **Tetapan → Ruang kerja → Profil & identiti → Hos kod** (atau langkah pertama
   onboarding)
2. Pada baris **GitHub**, klik **Log masuk ke GitHub**
3. Pelayar anda membuka GitHub. Luluskan apl itu

Cara log masuk selesai bergantung pada pihak yang menjalankannya:

- **Apl pelayan itu sendiri:** GitHub menghantar pelayar anda kembali ke pelayan dan dialog itu
  mengesannya sendiri. Anda tidak perlu menaip apa-apa
- **Control Center Connect:** halaman pelayar memaparkan kod 8 aksara. Taip kod itu ke dalam
  dialog, atau biarkan pelayar membuka Control Center melalui pautan `control-center://` dan
  langkau menaip kod

Titik pemeriksaan: baris **GitHub** berbunyi "Log masuk sebagai _your-username_".

Dialog itu menolak kod atau pautan yang ia tidak mulakan sendiri, dengan **Log masuk tidak dimulakan di sini**.
Jika seseorang menghantar anda pautan log masuk, jangan teruskan: menyelesaikannya akan menyambungkan
akaun anda kepada pelayan mereka.

Klik **Nyahsambung** untuk membuang log masuk anda. Log keluar daripada GitHub, atau dikeluarkan daripada
sesuatu ruang kerja, juga membatalkan setiap token yang dicetak oleh pelayan bagi pihak anda.

## Siapa yang diwakili kelayakan anda

- **Apa sahaja yang anda lakukan** (membuka halaman PR, menyiarkan semakan, meluluskan, mencantum) berjalan
  di bawah log masuk **anda** dan tiada yang lain. Jika anda belum log masuk, apl itu akan memaklumkan dan
  meminta anda log masuk. Tiada kelayakan lain yang menggantikan anda
- **Kerja tanpa sesiapa menaip** (larian ejen, pipeline, pengundian PR, balasan bot, clone) menerima token
  untuk satu repositori, dicetak daripada GitHub App pelayan atau melalui Connect. Token itu dihadkan kepada
  apa yang boleh dilakukan oleh ahli yang bertanggungjawab di sana: yang meminta, atau jika tidak, pemilik
  ruang kerja. Ahli yang tidak boleh push akan menghadkan token kepada baca sahaja
- **Automasi tidak pernah meluluskan** pull request. Kelulusan ialah tindakan seseorang

## Apa yang integrasi ini berikan kepada anda

| Ciri                  | Cara                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------------- |
| Senarai dan butiran PR | API REST GitHub, dari pelayan, dengan log masuk anda sendiri                                                 |
| Larian semakan        | API Checks GitHub                                                                                             |
| Penerbitan semakan    | Langkah berpagar pengguna yang menyiarkan semakan anda ke PR, atas nama anda                                  |
| Pendaftaran repo      | Checkout diterima jika remote `origin`-nya menunjuk ke github.com — atau ke gitlab.com / bitbucket.org        |
| Akses GitHub ejen     | Token untuk satu repositori larian sebagai `GH_TOKEN` / `GITHUB_TOKEN`; push melalui Control Center           |
| Ping pemberitahuan    | Pengundian di sisi pelayan bagi peti masuk pemberitahuan GitHub anda memunculkan "disebut dalam pull request" dan "semakan diminta" |
| Profil pengguna       | Kad hover profil dan penapisan PR mengikut pengarang                                                          |

Sesetengah laluan menggunakan API GraphQL dan bukan REST apabila ia lebih murah:
aktiviti cabang untuk pemilih compose-PR dan keadaan semakan langsung yang
menentukan sama ada pemberitahuan permintaan semakan masih tergantung.

## Perhatikan gangguan GitHub

Bar tajuk menunjukkan cip status apabila sesuatu penyedia terganggu, merangkumi
GitHub, Claude, OpenAI dan Kimi. **Ia tersembunyi selagi semuanya sihat**:
kehadirannya melaporkan masalah, bukan ketiadaannya.

Klik cip itu untuk membuka panel timbul dengan keadaan setiap penyedia dan
butang muat semula. Status itu dimuat semula sendiri setiap dua minit.

## Fahami cara ejen bertindak di GitHub

- Ejen yang bekerja dalam worktree GitHub mendapat token untuk repositori itu. Ia boleh membaca kod dan
  mengulas pada pull request apabila ahli yang bertanggungjawab boleh push, dan hanya membaca apabila tidak.
  Push melalui Control Center, yang bertanya kepada peraturan **Push ke remote** dan kemudian memajukannya
  dengan token tulis yang tidak pernah dipegang ejen. Lihat
  [Konfigurasikan polisi kotak pasir](/ms-MY/manual-pengguna/panduan-cara/polisi-kotak-pasir/)
- Komit ejen sentiasa menggunakan identiti Git peminta sebagai pengarang dan pelaku komit. Secara lalai, treler `Co-Authored-By: Control Center <hi@usectrl.dev>` mengiktiraf GitHub `@usectrl` sebagai penulis bersama. **Tetapan → Anda → Atribusi komit** boleh mematikan kredit penulis bersama ini tanpa menukar identiti anda. Tetapan ruang kerja dalam **Tetapan → Ruang kerja → Umum** mengatasi pilihan peribadi dan mengunci suis itu. Atribusi Claude Code sendiri sentiasa dinyahaktifkan. Penandatanganan komit tetap memerlukan konfigurasi sahnya sendiri
- Terminal yang anda buka pada rig menerima log masuk anda sendiri, dihadkan kepada satu repositori, jadi push di sana adalah milik anda
- Apabila tiada token dapat dicetak (tiada ahli yang bertanggungjawab sedang log masuk, apl tidak dipasang pada pemilik, atau pemasangan digantung), larian bermula tanpa token dan notanya menerangkan sebabnya. Tiada kelayakan sandaran

## Penyelesaian masalah

### Senarai PR kosong dan menyatakan GitHub tidak disambungkan

Anda tidak log masuk ke GitHub pada pelayan ini. Klik **Log masuk ke GitHub** di bawah **Hos kod**.
Repo pada hos kod lain tidak terjejas.

### Baris GitHub menyatakan log masuk belum disediakan pada pelayan ini

Pelayan tiada GitHub App sendiri mahupun Connect. Pemilik pelayan memilih salah satu dalam **Tetapan → Pelayan →
Daftar masuk tunggal**: **Cipta aplikasi GitHub saya** mengambil masa kira-kira dua minit. Lihat
[Cipta GitHub App](/ms-MY/manual-pengguna/panduan-cara/github-app/).

### Dialog memaklumkan kod tidak sepadan

Taip kod tepat seperti yang dipaparkan pelayar: 8 huruf dan digit. Lima kali salah memasukkan kod akan menamatkan
log masuk; mulakan semula.

### Log masuk memaklumkan apl belum dipasang

GitHub App tidak mempunyai sebarang pemasangan pada akaun yang memiliki repositori. Seorang pentadbir ruang kerja
memasangnya dari **Tetapan → Ruang kerja → Umum → Pemasangan aplikasi GitHub**. Untuk organisasi yang menggunakan
App kongsi Control Center, pentadbir organisasi itu mungkin perlu klik **Benarkan pelayan ini**. Lihat
[Cipta GitHub App](/ms-MY/manual-pengguna/panduan-cara/github-app/).

### Semua orang perlu log masuk ke GitHub semula

Pemilik pelayan memutar kunci Connect pelayan, bertukar kepada pelayan Connect lain, atau direktori data
dipulihkan ke mesin lain. Log masuk melalui Connect terikat kepada pelayan yang menciptanya.

### Penambahan repo ditolak

Pendaftaran memerlukan ketiga-tiganya: laluan itu berada di dalam work tree git,
ia mempunyai remote `origin`, dan remote itu menunjuk ke hos kod yang disokong
(github.com, gitlab.com atau bitbucket.org). Lihat
[Tambah repositori ke ruang kerja](/ms-MY/manual-pengguna/panduan-cara/tambah-repositori/).

### Semuanya berhenti berfungsi seketika selepas penggunaan berat

Itulah pemutus litar had kadar. GitHub menandakan had utamanya dengan `403` yang
membawa `x-ratelimit-remaining: 0` dan masa set semula; apabila melihatnya,
klien menggagalkan permintaan seterusnya secara setempat tanpa panggilan
rangkaian sehingga tetingkap itu berlalu, jadi ribut cuba semula tidak boleh
memperdalam had itu. Kegagalan sementara dicuba semula sehingga tiga kali dengan
backoff eksponen, sambil menghormati `retry-after`.
