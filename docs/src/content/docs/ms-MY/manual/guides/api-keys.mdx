Panduan ini menunjukkan kepada anda di mana setiap kelayakan yang digunakan oleh
Control Center disimpan dan cara mengubahnya.

**Tiada apa-apa disimpan pada mesin yang anda sedang taip ini.** Setiap kelayakan
berada pada pelayan; kelayakan mana yang menjawab sesuatu permintaan bergantung
pada sama ada ada manusia di belakangnya.

| Kelayakan                            | Disimpan                                                   | Siapa yang menggunakannya                                          |
| ------------------------------------ | ---------------------------------------------------------- | ------------------------------------------------------------------ |
| Kelayakan hos kod / penetikan anda   | Fail rahsia 0600 pelayan, dikunci mengikut id pengguna anda | Apa sahaja yang anda minta: permukaan PR, larian ejen, imej anda   |
| Identiti apl pelayan                 | Fail yang sama, ditambah `server_settings` untuk yang bukan rahsia | Kerja yang tiada manusia meminta: webhook, pengundian PR, penyegerakan tiket |
| Kunci penyedia model dan token OAuth | Stor kelayakan pelayan sendiri                              | Penyesuai terbina, untuk setiap ruang kerja pada pemasangan ini    |
| Token bot Slack                      | `<dataDir>/<workspaceId>/chat_credentials/` pada pelayan    | Jambatan sembang bagi ruang kerja itu                              |
| Kelayakan CLI luaran                 | Apa sahaja yang digunakan oleh CLI itu                      | Claude Code, pada hos pelayan                                      |

## Dua kelayakan GitHub, dan keduanya menjawab soalan yang berbeza

- **Milik anda**, daripada daftar masuk (aliran peranti) atau menampal token.
  Ia yang digunakan oleh setiap permintaan yang dibuat *bagi pihak anda*, jadi
  komen yang disiarkan untuk anda membawa nama anda. Ahli lain tidak boleh
  membacanya, dan mereka menyambungkan milik mereka sendiri
- **Milik pelayan**, daripada GitHub App yang didaftarkan oleh pengendali. Ia
  menjawab semua perkara yang tiada pemanggil — jadi akses hos kod tidak hilang
  apabila seseorang keluar atau memutar token

Milik anda ditetapkan dalam kad **Hos kod** di **Tetapan → Ruang kerja → Profil &
identiti**; milik pelayan dalam **Apl penyedia** di **Tetapan → Pelayan → Daftar
masuk tunggal**. Lihat [Sediakan integrasi GitHub](/ms-MY/manual-pengguna/panduan-cara/integrasi-github/)
dan [Cipta GitHub App](/ms-MY/manual-pengguna/panduan-cara/github-app/).

:::note[Ada juga skrin URL sahaja]
`/workspaces/<workspaceId>/api-keys` memaparkan dua kad yang sama seperti langkah
pertama onboarding. Ia **tiada entri navigasi di mana-mana dalam UI**; ia hanya
boleh dicapai dengan menaip URL itu. Gunakan Tetapan → Ruang kerja → Profil &
identiti sebaliknya.
:::

## Tetapkan kunci penyedia model

Penyesuai terbina mengesahkan penyedia sendiri dan kelayakan tersebut berada pada
pelayan.

1. Pergi ke **Tetapan → Pelayan → Penyedia model**
2. Tatal ke **Penyedia & model**
3. Sambungkan penyedia — OAuth pelayar untuk OpenAI, Codex, Cursor dan Kimi Code;
   kunci API untuk Anthropic dan selebihnya

Lihat [Urus penyesuai dan model](/ms-MY/manual-pengguna/panduan-cara/penyesuai/) untuk senarai penuh
dan untuk menambah titik akhir tersuai.

Kelayakan ini **global hos**: satu kunci melayani setiap ruang kerja pada
pemasangan ini. Token OAuth disegarkan sebelum ia tamat tempoh.

CLI penyesuai luaran menyimpan kelayakannya sendiri, dalam konfigurasinya sendiri,
pada hos pelayan — Control Center tidak menguruskannya. Sahkan Claude Code seperti
yang dinyatakan dalam dokumentasinya sendiri, pada mesin yang menjalankan `cc_server`.

Dialog **Pemboleh ubah persekitaran** bagi setiap penyesuai kelihatan seperti
tempat untuk meletakkan kunci bagi salah satu daripadanya, tetapi bukan: ia
menulis ke peranti anda, manakala pelayan membaca salinannya sendiri dan tiada
apa yang menghubungkan keduanya. Lihat
[Urus penyesuai dan model](/ms-MY/manual-pengguna/panduan-cara/penyesuai/).

## Sambungkan vendor penetikan

Kad **Tiket** pada **Tetapan → Ruang kerja → Umum** memegang kedua-dua belah satu
keputusan: vendor tempat tiket anda berada, dan kelayakan untuknya. Memilih
**Setempat** menyembunyikan baris kelayakan — tiket setempat berada dalam pangkalan
data pelayan ini sendiri dan tiada apa-apa untuk disahkan.

Kunci anda disimpan pada pelayan terhadap id pengguna anda, seperti kunci hos kod.
Pelayan menyimpan kunci Linear-nya sendiri secara berasingan (**Apl penyedia**),
iaitu yang digunakan oleh penyegerakan tiket apabila tiada manusia memintanya.
Tiada kunci penetikan disuntik ke dalam kotak pasir ejen; ejen menulis tiket
melalui alat Control Center, yang bertanya kepada peraturan **Tulis ke penjejak
luaran**. Lihat
[Sediakan integrasi Linear](/ms-MY/manual-pengguna/panduan-cara/integrasi-linear/).

## Putar atau tarik balik

- **Kelayakan GitHub anda**: tekan **Putuskan**, kemudian daftar masuk semula
  atau tampal token baharu. Tarik balik yang lama pada GitHub
- **Apl pelayan**: jana kunci persendirian atau rahsia klien baharu pada halaman
  GitHub apl itu, tampalkannya dalam **Apl penyedia** dan tekan **Uji**
- **Penyedia model**: pada barisnya, daftar keluar (OAuth) atau buang kunci itu,
  kemudian sambung semula
- **Slack**: tampal semula token dalam dialog sambungan. Lihat
  [Sediakan integrasi Slack](/ms-MY/manual-pengguna/panduan-cara/integrasi-slack/)

## Penyelesaian masalah

### Senarai PR kosong tetapi token saya berfungsi dalam `curl`

Semak subtajuk baris **Hos kod**. Jika ia menamakan sumber lain ("melalui apl
pelayan ini", "daripada persekitaran"), kelayakan yang anda uji bukan yang
menjawab — milik anda tidak disimpan.

### Token diterima tetapi permintaan kemudiannya gagal

Token itu diperiksa semasa ia disimpan, jadi baris itu menamakan akaun di
belakangnya — tetapi hanya akaun, bukan skop. Token dengan skop yang terlalu
sedikit akan bersambung dan kemudian gagal pada permintaan individu. Semak skop
dan tarikh luputnya:

```bash
curl -H "Authorization: token YOUR_TOKEN" https://api.github.com/user
```
