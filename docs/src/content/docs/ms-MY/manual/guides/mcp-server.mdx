Panduan ini menunjukkan cara menyambungkan klien MCP luaran — Claude Code, editor,
MCP Inspector — ke pelayan alat Control Center sendiri.

Control Center mendaftarkan **110** alat dan menyajikannya melalui Model Context
Protocol pada versi protokol `2024-11-05`. Keseluruhan keluarga alat yang mungkin
anda jangkakan memang tiada: tiada alat mesyuarat atau kalendar dan tiada alat
projek.

## Cari titik akhir

Permukaan MCP berkongsi pendengar `cc_server` utama. Tiada port MCP yang
berasingan.

| Titik akhir | Kaedah   | Tujuan                                                           |
| ----------- | -------- | ---------------------------------------------------------------- |
| `/mcp`      | `POST`   | Pengangkutan Streamable HTTP — inilah yang dituturkan oleh klien |
| `/mcp`      | `DELETE` | Tamatkan sesi                                                    |
| `/sse`      | `GET`    | Aliran pemberitahuan yang dihantar oleh pelayan                  |

Jadi pemasangan setempat lalai berada di `http://127.0.0.1:9030/mcp`.

1. Pergi ke **Tetapan → Pelayan → Pelayan MCP**
2. Baca kad **Pelayan MCP** — ia menunjukkan berjalan atau dihentikan serta port
   yang sedang didengarnya

Permukaan ini dihidupkan secara lalai pada pemasangan baharu, jadi klien loopback
berfungsi tanpa perlu menyentuh tetapan. **Mula pada pelancaran apl** mengawal
sama ada ia kembali selepas permulaan semula; **Mula** / **Henti** ialah kawalan
sesi yang tidak mengubah keutamaan itu.

Pelayan mengikat loopback secara lalai, jadi titik akhir itu hanya boleh dicapai
dari mesin yang menjalankan `cc_server` melainkan anda memulakannya dengan
`--bind any`.

## Sambungkan klien

Halakan klien anda ke titik akhir Streamable HTTP. Bentuk konfigurasi yang tepat
terserah kepada klien anda; URL-nya tetap sama sama ada cara mana pun.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp"
    }
  }
}
```

### Claude Code

Claude Code tidak akan mengambilnya daripada `.mcp.json` projek — ia
menggerbangi pelayan MCP berskop projek di sebalik gesaan kelulusan yang tidak
pernah dijawab oleh `claude -p` bukan interaktif. Berikan konfigurasi itu secara
eksplisit:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` membuat Claude menggunakan fail itu sahaja, jadi pelayan
yang sama tidak turut ditemui daripada projek dan didaftarkan dua kali.

Titik semak: minta klien menyenaraikan alatnya. Anda sepatutnya melihat entri
`mcp__*` yang merangkumi tiket, ruang, memori, graf kod dan semakan.

## Sajikan MCP di luar hos

1. Pada **Tetapan → Pelayan → Pelayan MCP**, pada baris **Token pengesahan**,
   tekan **Tetapkan** dan tampal token
2. Hantarkannya sebagai `Authorization: Bearer <token>` pada setiap permintaan
   `POST /mcp`

Permukaan tanpa token menolak mana-mana pemanggil bukan loopback dengan 403. Itu
memang gagal tertutup mengikut reka bentuk: token itulah yang membolehkan
perkhidmatan di luar hos sama sekali.

Perubahan token terpakai pada permukaan langsung dengan serta-merta — tiada
permulaan semula.

:::note[`GET /sse` mengambil token dalam rentetan pertanyaan]
Aliran pemberitahuan diperiksa tokennya seperti setiap laluan lain, tetapi
`EventSource` pelayar tidak boleh menghantar pengepala `Authorization` — jadi
`/sse` turut menerima token sebagai `?token=<token>`. Tanpanya, ia menjawab 401.
:::

## Skopkan setiap panggilan kepada ruang kerja

Setiap alat yang menyentuh data berskop ruang kerja memerlukan `workspace_id` dan
panggilan tanpanya ditolak dan bukan diselesaikan terhadap ruang kerja “semasa”
yang entah mana:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

Id itu ialah yang terdapat dalam URL pelayar atau apl anda:
`/workspaces/<workspace_id>/…`. Satu-satunya pengecualian ialah alat yang
benar-benar merentas ruang kerja, seperti `list_workspaces` dan alat suapan
berita — suapan berita bersifat setiap pengguna dan ejen tiada pengguna sendiri,
jadi alat tersebut beroperasi pada suapan pemilik pelayan.

Alat berskop repo pula menyemak tambahan bahawa repo itu dipautkan kepada ruang
kerja berkenaan.

## Ketahui perkara yang akan ditolak oleh permukaan

- **Gerbang modus.** Panggilan diselesaikan terhadap modus ruang ejen pemanggil,
  di sebelah pelayan. Ejen dalam modus baca sahaja tidak boleh mencapai alat
  tulis dengan meninggalkan `space_id` — sebaliknya, modus itu dicari daripada
  larian aktifnya.
- **Guardrail tindakan.** Alat mutasi mengisytiharkan kelas kesannya dan melalui
  polisi yang sama seperti yang digunakan oleh seluruh produk yang lain. Lihat
  [Konfigurasikan guardrail](/ms-MY/manual-pengguna/panduan-cara/konfigurasikan-guardrail/).
- **Pengesahan.** Sesetengah alat pemusnah membina muatan pengesahan yang mesti
  diluluskan sebelum panggilan diteruskan.

Katalog penuh diumumkan dalam `tools/list` tanpa gerbang penemuan — klien MCP
luaran menolak untuk memanggil alat yang tidak berada dalam senarai cache-nya,
jadi menyembunyikan alat merosakkannya dan bukan mengemaskannya.

## Penyelesaian masalah

### Klien tidak melihat sebarang alat

- Semak kad **Pelayan MCP** menunjukkan berjalan
- Semak port itu sepadan dengan port `cc_server` anda
- Pada Claude Code, semak sama ada anda memberikan `--mcp-config` dan
  `--strict-mcp-config`

### 403 daripada mesin yang bukan pelayan

Tiada token pembawa dikonfigurasikan. Tetapkan satu dan hantarkannya.

### Panggilan alat gagal dengan "Missing or invalid argument: workspace_id"

Tambahkan `workspace_id`. Tiada ruang kerja tersirat.

### Panggilan alat ditolak sebagai tidak dikenali

[Alat MCP](/ms-MY/manual-pengguna/rujukan/alat-mcp/) menyenaraikan katalog itu.
Panggil nama itu tepat seperti yang tertera di sana.
