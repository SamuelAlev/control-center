Panduan ini menunjukkan cara menyambungkan klien MCP luaran — Claude Code, editor,
MCP Inspector — ke pelayan alat Control Center sendiri.

Control Center mendaftarkan **110** alat dan menyajikannya melalui Model Context
Protocol pada versi protokol `2024-11-05`. Keseluruhan keluarga alat yang mungkin
anda jangkakan memang tiada: tiada alat mesyuarat atau kalendar dan tiada alat
projek.

## Cari titik akhir

Permukaan MCP berkongsi pendengar `cc_server` utama. Tiada port MCP yang
berasingan.

| Titik akhir | Kaedah   | Tujuan                                                           |
| ----------- | -------- | ---------------------------------------------------------------- |
| `/mcp`      | `POST`   | Pengangkutan Streamable HTTP — inilah yang dituturkan oleh klien |
| `/mcp`      | `DELETE` | Tamatkan sesi                                                    |
| `/sse`      | `GET`    | Aliran pemberitahuan yang dihantar oleh pelayan                  |

Jadi pemasangan setempat lalai berada di `http://127.0.0.1:9030/mcp`.

1. Pergi ke **Tetapan → Pelayan → Pelayan MCP**
2. Baca kad **Pelayan MCP** — ia menunjukkan berjalan atau dihentikan serta port
   yang sedang didengarnya

Permukaan ini dihidupkan secara lalai pada pemasangan baharu. Hanya pemilik pelayan melihat
token kad itu, dan hanya mereka boleh memulakan atau menghentikan titik akhir. **Mula pada pelancaran apl** mengawal
sama ada ia kembali selepas permulaan semula; **Mula** / **Henti** ialah kawalan
sesi yang tidak mengubah keutamaan itu.

Pelayan mengikat loopback secara lalai, jadi titik akhir itu hanya boleh dicapai
dari mesin yang menjalankan `cc_server` melainkan anda memulakannya dengan
`--bind any`.

## Dapatkan token

Setiap permintaan memerlukan token MCP pelayan, dari mana-mana mesin, termasuk loopback. Pelayan
mencipta token itu kali pertama ia dimulakan. Tiada cara untuk mematikannya dan tiada cara untuk
mengosongkannya.

1. Pada **Tetapan → Pelayan → Pelayan MCP**, cari baris **Token pengesahan**
2. Tekan **Tunjukkan token** dan salinnya
3. Untuk menggantikannya, tekan **Jana semula token**. Pelayan beralih kepada token baharu serta-merta,
   dan setiap klien yang masih menggunakan token lama ditolak sehingga anda memberinya token baharu

## Sambungkan klien

Halakan klien anda ke titik akhir Streamable HTTP dan hantar token sebagai
`Authorization: Bearer <token>` pada setiap permintaan, termasuk `GET /sse`. Tiada cara lain untuk
menghantarnya: token dalam URL tidak diterima. Bentuk konfigurasi yang tepat terserah kepada klien anda.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code tidak akan mengambilnya daripada `.mcp.json` projek — ia
menggerbangi pelayan MCP berskop projek di sebalik gesaan kelulusan yang tidak
pernah dijawab oleh `claude -p` bukan interaktif. Berikan konfigurasi itu secara
eksplisit:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` membuat Claude menggunakan fail itu sahaja, jadi pelayan
yang sama tidak turut ditemui daripada projek dan didaftarkan dua kali.

Titik semak: minta klien menyenaraikan alatnya. Anda sepatutnya melihat entri
`mcp__*` yang merangkumi tiket, ruang, memori, graf kod dan semakan.

## Apa yang ditolak oleh titik akhir

Token itu membuka setiap alat pada pelayan, jadi titik akhir juga menolak apa-apa yang mungkin
dihantar oleh halaman web, sebelum ia memeriksa token:

| Permintaan                                                              | Jawapan |
| ----------------------------------------------------------------------- | ------- |
| Pengepala `Origin` yang bukan halaman pada mesin ini (`http://localhost`, `http://127.0.0.1` atau `http://[::1]`, mana-mana port) | `403`, "Permintaan cross-origin tidak diterima" |
| Pengepala `Host` yang bukan alamat loopback dan port pendengar ini mahupun nama hos awam pelayan | `403`, "Hos tidak diketahui" |
| `POST` yang badannya bukan `application/json`                           | `415`   |
| Tiada token, atau yang salah                                            | `401`   |

Untuk menyajikan MCP di luar hos, mulakan pelayan dengan `--bind any` dan hantar token dari mesin
lain, dengan menangani pelayan melalui nama hos awamnya.

## Skopkan setiap panggilan kepada ruang kerja

Setiap alat yang menyentuh data berskop ruang kerja memerlukan `workspace_id` dan
panggilan tanpanya ditolak dan bukan diselesaikan terhadap ruang kerja “semasa”
yang entah mana:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

Id itu ialah yang terdapat dalam URL pelayar atau apl anda:
`/workspaces/<workspace_id>/…`. Satu-satunya pengecualian ialah alat yang
benar-benar merentas ruang kerja, seperti `list_workspaces` dan alat suapan
berita — suapan berita bersifat setiap pengguna dan ejen tiada pengguna sendiri,
jadi alat tersebut beroperasi pada suapan pemilik pelayan.

Alat berskop repo pula menyemak tambahan bahawa repo itu dipautkan kepada ruang
kerja berkenaan.

## Ketahui perkara yang akan ditolak oleh permukaan

- **Gerbang modus.** Panggilan diselesaikan terhadap modus ruang ejen pemanggil,
  di sebelah pelayan. Ejen dalam modus baca sahaja tidak boleh mencapai alat
  tulis dengan meninggalkan `space_id` — sebaliknya, modus itu dicari daripada
  larian aktifnya.
- **Guardrail tindakan.** Alat mutasi mengisytiharkan kelas kesannya dan melalui
  polisi yang sama seperti yang digunakan oleh seluruh produk yang lain. Lihat
  [Konfigurasikan guardrail](/ms-MY/manual-pengguna/panduan-cara/konfigurasikan-guardrail/).
- **Pengesahan.** Sesetengah alat pemusnah membina muatan pengesahan yang mesti
  diluluskan sebelum panggilan diteruskan.

Katalog penuh diumumkan dalam `tools/list` tanpa gerbang penemuan — klien MCP
luaran menolak untuk memanggil alat yang tidak berada dalam senarai cache-nya,
jadi menyembunyikan alat merosakkannya dan bukan mengemaskannya.

## Pelayan MCP yang digunakan oleh ejen anda

Panduan ini tentang titik akhir Control Center sendiri. Arah yang sebaliknya ialah pelayan MCP yang Control Center sambungkan dan serahkan kepada ejen yang dijalankannya. Anda menyediakannya di bawah **Tetapan → Pelayan → Pelayan MCP**, pada dua peringkat: untuk seluruh ruang kerja atau untuk diri anda sendiri. Sama ada cara, Control Center menyambung ke pelayan itu sendiri dan menghantar alatnya ke larian, jadi harness terbina dan Claude Code mendapat alat dan gesaan kelulusan yang sama. Larian Claude Code melihatnya di bawah pelayan `control-center`, sebagai `mcp__control-center__mcp__<server>__<tool>`.

### Pelayan ruang kerja

Admin ruang kerja menambahnya dalam **Pelayan MCP ruang kerja**. Setiap larian ejen dalam ruang kerja itu mendapat alatnya, dan larian dalam ruang kerja lain tidak.

1. Pilih **Tambah pelayan** dan beri nama pendek: huruf, digit, `-` dan `_`, sehingga 24 aksara. Alat muncul sebagai `mcp__<name>__<tool>`.
2. Pilih cara untuk mencapainya:
   - **Arahan (stdio):** satu executable dan argumennya, serta sebarang pembolehubah persekitaran yang diperlukannya.
   - **URL (HTTP atau SSE):** titik akhirnya, serta sebarang header yang diperlukannya, seperti `Authorization: Bearer …`.
3. Simpan. Semakan: pelayan memaparkan **Disambungkan** dengan bilangan alat.

Nilai pembolehubah persekitaran dan header disimpan dalam fail rahsia pelayan dan tidak dipaparkan lagi. Untuk menukar nilai, gantikannya; untuk membuangnya, alih keluar namanya.

Arahan dijalankan di mesin pelayan sebagai pengguna pelayan itu sendiri, jadi ia tidak bermula sehingga pemilik pelayan meluluskannya. Sehingga itu ia dipaparkan sebagai **Menunggu kelulusan**. Pelayan URL berfungsi serta-merta, tetapi ia hanya boleh mencapai alamat awam sehingga pemilik pelayan meluluskannya, yang turut membenarkan `localhost` dan rangkaian persendirian. Apabila pemilik pelayan menyimpan pelayan, itu dikira sebagai kelulusan. Jika orang lain menukar cara pelayan bermula atau tempat ia menyambung, ia perlu diluluskan semula. Menghidupkan atau mematikan pelayan mengekalkan kelulusannya.

### Pelayan sendiri

Setiap ahli menambah pelayan sendiri dalam **Pelayan MCP anda**, menggunakan borang yang sama. Dalam ruang kerja ini, pelayan itu milik anda seorang: ahli lain tidak melihatnya, dan pelayan yang anda log masuk bertindak sebagai anda.

- Hanya larian yang anda mulakan dalam ruang kerja ini mendapat alatnya. Itu meliputi larian harness terbina dan larian Claude Code.
- Larian ahli lain, automasi yang tidak dimulakan oleh sesiapa, dan larian anda dalam ruang kerja lain tidak mendapat satu pun daripadanya. Di situ alat tidak disenaraikan, tidak boleh dipanggil dan tidak muncul dalam carian alat.
- Pelayan anda boleh mempunyai nama yang sama dengan pelayan ruang kerja. Dalam larian anda, pelayan anda yang digunakan.
- Pelayan sendiri dicapai melalui URL dan hanya boleh mencapai alamat awam. Hanya pemilik pelayan boleh menambah pelayan sendiri yang menjalankan arahan.

Kedua-dua pelayan sendiri dan pelayan ruang kerja tidak dihidangkan kepada token MCP atau peranti yang dipasangkan, dan sumber serta promptnya tidak diteruskan.

### Log masuk ke pelayan

Pelayan URL yang meminta anda log masuk menunjukkan **Memerlukan kebenaran**.

1. Pilih **Log masuk** pada pelayan. Pelayar anda membuka halaman log masuk pelayan itu sendiri.
2. Luluskan permintaan di situ. Pelayar kembali ke Control Center dan menunjukkan kod.
3. Taip kod dalam aplikasi. Titik semak: pelayan menunjukkan **Disambungkan**.

Log masuk disimpan bersama pelayan yang dibuatnya. Log masuk ke pelayan ruang kerja memerlukan pentadbir ruang kerja, dan selepas itu setiap larian dalam ruang kerja bertindak sebagai akaun yang log masuk. Log masuk ke pelayan anda hanya menjejaskan larian anda. Membuang pelayan turut membuang log masuknya.

## Penyelesaian masalah

### Klien tidak melihat sebarang alat

- Semak kad **Pelayan MCP** menunjukkan berjalan
- Semak port itu sepadan dengan port `cc_server` anda
- Pada Claude Code, semak sama ada anda memberikan `--mcp-config` dan
  `--strict-mcp-config`

### 401 Unauthorized

Permintaan itu tidak membawa token, atau token lama. Salin token semasa daripada baris **Token
pengesahan** dan hantarkannya sebagai `Authorization: Bearer <token>`. Token dalam URL diabaikan.

### 403 daripada klien yang pernah berfungsi

Permintaan itu membawa `Origin` daripada halaman web, atau `Host` yang tidak dijawab oleh pelayan.
Panggil titik akhir daripada klien, bukan halaman pelayar, dengan alamat loopback pelayan atau nama
hos awamnya.

### 415 Unsupported Media Type

Hantar badan `POST /mcp` sebagai `application/json`.

### Panggilan alat gagal dengan "Missing or invalid argument: workspace_id"

Tambahkan `workspace_id`. Tiada ruang kerja tersirat.

### Panggilan alat ditolak sebagai tidak dikenali

[Alat MCP](/ms-MY/manual-pengguna/rujukan/alat-mcp/) menyenaraikan katalog itu.
Panggil nama itu tepat seperti yang tertera di sana.
