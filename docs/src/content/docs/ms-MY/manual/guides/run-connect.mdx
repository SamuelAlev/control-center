Control Center Connect menjalankan log masuk pembekal (GitHub, Google Calendar, Linear, Slack) untuk pelayan yang belum
mendaftarkan apl mereka sendiri. Panduan ini menunjukkan cara menjalankan Connect anda sendiri, supaya apl pembekal, rahsianya
dan senarai pelayan yang dibenarkan menggunakannya kekal di tangan anda.

Apa yang Connect lihat dan tidak lihat diterangkan dalam [rujukan Connect](/ms-MY/manual-pengguna/rujukan/connect/). Bacalah
dahulu jika anda sedang menimbang untuk menjalankan satu.

:::note[Anda mungkin tidak memerlukannya]
Sebuah pelayan boleh mendaftarkan apl sendiri sebaliknya: **Tetapan → Pelayan → Daftar masuk tunggal → Apl penyedia**, di
mana **Cipta aplikasi GitHub saya** menyediakan GitHub dalam satu langkah. Apl pelayan hanya terpakai di bawah **Gunakan aplikasi saya sendiri**. Dengan Connect Control Center atau Connect tersuai, Connect mengendalikan setiap pembekal, manakala apl ruang kerja kekal terpakai. Jalankan Connect apabila beberapa pelayan sepatutnya berkongsi satu set apl.
:::

## Prasyarat

- Alamat **HTTPS** awam untuk Connect, contohnya `https://connect.example.com`, di belakang proksi yang menamatkan TLS. HTTP
  biasa hanya diterima pada loopback
- Docker, atau `cc_server` yang boleh anda mulakan semula dengan pemboleh ubah persekitaran tambahan
- Kebenaran untuk mendaftarkan apl dengan setiap pembekal yang ingin anda layani
- Pelayan yang akan menggunakannya, dengan pemiliknya berhampiran: setiap pelayan mempunyai ID pemasangan yang anda tambah
  ke senarai benar Connect

## Langkah 1: Pilih alamatnya

Pilih URL sekarang dan simpannya. `CONNECT_PUBLIC_URL` terlibat dalam setiap perkara yang Connect lakukan: tandatangan
permintaan, pemeteraian kelayakan, URL ubah hala pembekal dan ID pemasangan setiap pelayan semuanya terikat kepadanya.
Menukarnya kemudian bermakna mendaftar semula ubah hala dan setiap orang log masuk semula.

## Langkah 2: Daftarkan apl pembekal

Daftarkan hanya pembekal yang ingin anda layani. Pembekal yang pemboleh ubahnya belum lengkap akan dikeluarkan daripada
konfigurasi Connect, dan pelayan melihatnya sebagai tidak tersedia. `<base>` di bawah ialah `CONNECT_PUBLIC_URL` anda.

| Pembekal       | Daftar                                                                                                                                                                                                                                                               | Simpan                                  |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| **GitHub App** | Callback URL `<base>/oauth/github/callback`. Setup URL `<base>/oauth/github/setup` dengan **Redirect on update** dihidupkan. Biarkan **Request user authorization (OAuth) during installation** dimatikan: jika dihidupkan, GitHub mengabaikan setup URL. Biarkan **Expire user authorization tokens** dihidupkan | ID app, slug, ID klien, rahsia klien, kunci peribadi |
| **Google**     | Klien OAuth jenis **Web application** dengan URI ubah hala `<base>/oauth/google/callback`, dan Google Calendar API didayakan                                                                                                                                       | ID klien, rahsia klien                  |
| **Linear**     | Aplikasi OAuth dengan callback URL `<base>/oauth/linear/callback` dan `<base>/oauth/linear_app/callback`                                                                                                                                                              | Hanya ID klien                          |
| **Slack**      | Redirect URL `<base>/oauth/slack_oidc/callback` dan `<base>/oauth/slack/callback`. Event Subscriptions di `<base>/v1/hooks/slack/events` (`app_mention`, `message.*`, `assistant_thread_*`, `app_uninstalled`, `tokens_revoked`). Slash command di `<base>/v1/hooks/slack/commands`. Hidupkan token rotation | ID app, ID klien, rahsia klien, signing secret |

Berikan GitHub App kebenaran repo berikut: **Metadata** baca sahaja, **Contents** baca dan tulis, **Pull requests** baca dan
tulis, **Issues** baca dan tulis, **Checks**, **Actions** dan **Commit statuses** baca sahaja. Tambah kebenaran organisasi
**Members** baca sahaja untuk permintaan semakan pasukan. Webhook boleh dimatikan: pelayan membuat pengundian.

Connect memerlukan kunci peribadi Apl GitHub (**Generate a private key** dalam tetapan App). Ia menandatangani permintaan App yang mencari pemasangan yang meliputi sesuatu repositori (atau, apabila repositori tiada, pemasangan pemiliknya) dan mencetak token pemasangan satu-repo, setiap satunya hanya selepas log masuk sendiri orang yang meminta membuktikan akses kepada repositori itu.

Setiap pelayan pada Connect anda berkongsi bot App. Ia boleh membaca, mengulas, melabel dan bertindak balas sebagai bot untuk mana-mana daripadanya. Menyemak permintaan tarik sebagai bot hanya dibenarkan untuk pelayan yang anda senaraikan dalam `CONNECT_GITHUB_REVIEW_BOT_INSTALLS` (ID pemasangannya, dipisahkan koma); setiap pelayan lain menerbitkan semakan menggunakan token penyemak itu sendiri. Menolak tidak pernah dilakukan sebagai bot. Untuk membenarkan pelayan milik anda menyemak sebagai bot, tambah ID pemasangannya di situ dan mulakan semula. Simpan fail kunci sebagai rahsia, seperti kunci pemeteraian. Linear juga tidak memerlukan rahsia: Connect memulangkan kod kepada pelayan, dan pelayan menyelesaikan pertukaran itu sendiri.

## Langkah 3: Kumpulkan ID pemasangan

Connect hanya menjawab pelayan dalam senarai benarnya. Pada setiap pelayan, tunjuk ia kepada Connect anda, kemudian baca ID
pemasangannya:

1. Pergi ke **Tetapan → Pelayan → Daftar masuk tunggal**, buka kad **Control Center Connect** dan pilih **Gunakan pelayan Connect tersuai**
2. Masukkan URL anda dan simpan. Kad memaparkan **ID pemasangan** pelayan

Daripada terminal pada hos pelayan, perkara yang sama ialah:

```bash
cc_server connect enable --url https://connect.example.com
cc_server connect status
```

`status` mencetak ID pemasangan. Ia memaparkan `install_blocked` sehingga Langkah 5 selesai, dan itu dijangka.

ID pemasangan diperoleh bagi setiap alamat Connect, jadi pelayan yang sama mempunyai ID berbeza untuk setiap Connect yang
dihubunginya. Ia hanya berubah apabila pemiliknya memutar kunci.

## Langkah 4: Cipta kunci pemeteraian

Connect menyulitkan setiap kelayakan yang dipulangkannya dengan kunci pemeteraian. Cipta satu dan simpan sebagai fail rahsia:

```bash
docker run --rm ghcr.io/samuelalev/cc-connect:latest \
  cc-connect-config seal-key > seal_keys
chmod 600 seal_keys
```

Kehilangan kunci pemeteraian akan mengeluarkan semua orang: tiada pemeteraian boleh dibuka tanpanya.

## Langkah 5: Mulakan kontena

Setiap keluaran menerbitkan `ghcr.io/samuelalev/cc-connect` dengan provenans binaan. Dalam pengeluaran, pinkan tag versi.

```bash
docker run -d --name cc-connect -p 8790:8790 \
  -e CONNECT_PUBLIC_URL=https://connect.example.com \
  -e CONNECT_ALLOWED_INSTALLS=<install id>,<install id> \
  -e CONNECT_SEAL_KEYS_FILE=/run/secrets/seal_keys \
  -v "$PWD/seal_keys:/run/secrets/seal_keys:ro" \
  -e CONNECT_GITHUB_APP_ID=123456 \
  -e CONNECT_GITHUB_APP_SLUG=acme-control-center \
  -e CONNECT_GITHUB_CLIENT_ID=Iv23li0123456789abcd \
  -e CONNECT_GITHUB_CLIENT_SECRET_FILE=/run/secrets/github \
  -v "$PWD/github_secret:/run/secrets/github:ro" \
  -e CONNECT_GITHUB_APP_PRIVATE_KEY_FILE=/run/secrets/github_key \
  -v "$PWD/github_app_key.pem:/run/secrets/github_key:ro" \
  -v cc-connect-data:/data \
  ghcr.io/samuelalev/cc-connect:latest
```

Tunjukkan reverse proxy anda kepada port `8790`, dan tetapkan `CONNECT_TRUST_PROXY` kepada bilangan proksi di hadapan Connect supaya had setiap alamatnya melihat alamat setiap klien. Imej berjalan sebagai pengguna tanpa keistimewaan, menyimpan keadaan dalam volum `/data` dan mempunyai pemeriksaan kesihatan terbina dalam (`cc-connect --healthcheck`, yang menyemak `/healthz`: proses itu menjawab). `/readyz` turut menyemak bahawa stor keadaan dan ikatannya menjawab, dan bahawa Redis, apabila digunakan, masih menjalankan `maxmemory-policy noeviction`; tunjukkan pemeriksaan kesediaan pengorkestra ke sana.

Halaman persetujuan log masuk menjawab dengan hantaran borang yang Connect terima hanya daripada halamannya sendiri: `Sec-Fetch-Site`, apabila dihantar, mesti `same-origin`, dan `Origin`, apabila dihantar, mesti asal `CONNECT_PUBLIC_URL`; hantaran yang tiada kedua-duanya ditolak. Maka proksi mesti meluluskan kedua-dua header tanpa diubah, dan `CONNECT_PUBLIC_URL` mesti alamat yang sebenarnya digunakan oleh pelayar orang. Jika meneruskan pada halaman itu sentiasa menunjukkan "Pautan ini telah tamat tempoh", dan log menunjukkan `oauth.done_refused` dengan sebab `origin` atau `no_origin`, salah satu daripada dua itu tidak betul.

Connect enggan bermula (kod keluar `78`) apabila konfigurasinya terbuka, tidak selamat atau separuh siap, dan mencetak
pemboleh ubah mana yang salah. Senarai benar yang hilang, alamat `http` yang bukan loopback, kunci pemeteraian yang format
salah, atau kedua-dua `NAME` dan `NAME_FILE` ditetapkan semuanya akan menghentikannya.

Titik semak: pada setiap pelayan, kad Connect memaparkan **Berfungsi**, dan **Tempat setiap log masuk berjalan** menamakan
**Connect** untuk setiap pembekal yang anda daftarkan. `cc_server connect status` mencetak `Health: ok` bersama lorong yang sama.

## Pasang Connect dalam cc_server

Sebuah pelayan boleh menjalankan Connect sendiri dan bukannya kontena berasingan. Perkhidmatan yang dipasang ialah perkhidmatan
yang sama yang dijalankan oleh imej.

1. Letakkan pemboleh ubah `CONNECT_*` dalam fail `.env` pelayan, seperti dalam Langkah 5. Pelayan enggan bermula apabila rahsia Connect, termasuk `CONNECT_SENTRY_DSN`, dieksport dalam persekitarannya
2. Tambah `CC_SERVER_CONNECT_HOST=on`
3. Mulakan semula pelayan. Lognya mencetak `embedded Connect at <url>`

```bash
CC_SERVER_CONNECT_HOST=on
CONNECT_ALLOWED_INSTALLS=<install id>
CONNECT_SEAL_KEYS=<output of cc-connect-config seal-key>
CONNECT_GITHUB_APP_ID=123456
CONNECT_GITHUB_APP_SLUG=acme-control-center
CONNECT_GITHUB_CLIENT_ID=Iv23li0123456789abcd
CONNECT_GITHUB_CLIENT_SECRET=<secret>
CONNECT_GITHUB_APP_PRIVATE_KEY_FILE=/etc/cc/github_app_key.pem
```

Connect kemudian dilayani di `<server>/connect`:

- `CONNECT_PUBLIC_URL` secara lalai ialah origin URL awam pelayan ditambah `/connect`. Tetapkannya secara eksplisit di belakang
  proksi. Laluannya mesti tepat `/connect`, dan mesti HTTPS kecuali loopback
- Hanya pemboleh ubah `CONNECT_*` sampai kepada perkhidmatan yang dipasang, jadi ia tidak sekali-kali meminjam apl pembekal
  milik pelayan itu sendiri
- `CONNECT_ALLOWED_INSTALLS` masih diperlukan, termasuk untuk pelayan hos itu sendiri
- Pemasangan yang salah konfigurasi menghalang pelayan daripada bermula, daripada melayani broker terbuka
- Pelayan demo tidak sekali-kali memasangnya

Daftarkan ubah hala pembekal terhadap `https://<server>/connect`, kemudian tunjukkan pelayan (termasuk pelayan hos) kepada URL itu
seperti dalam Langkah 3.

## Rujukan konfigurasi

Setiap tetapan ialah pemboleh ubah persekitaran. Mana-mana rahsia boleh diambil daripada fail yang dilekapkan: tetapkan
`NAME_FILE` sebagai ganti `NAME`. Connect membaca semula fail paling kerap setiap 30 saat dan mengekalkan nilai baik terakhir.
Rahsia yang ditanda **dual** juga menerima `NAME_PREVIOUS` (atau `NAME_PREVIOUS_FILE`) semasa putaran.

### Alamat dan akses

| Pemboleh ubah                   | Lalai     | Maksud                                                                                                                           |
| ------------------------------- | --------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `CONNECT_PUBLIC_URL`            | diperlukan | URL awam kanonik. HTTPS, atau `http` hanya pada loopback. Laluan bermakna dipasang. Tiada query atau fragment                    |
| `CONNECT_ALLOWED_INSTALLS`      | diperlukan | ID pemasangan dipisahkan koma. `*` hanya diterima bersama `CONNECT_SIGNED_CONFIG_FILE`                                            |
| `CONNECT_DENY_INSTALLS`         |           | ID pemasangan yang ditolak walaupun dibenarkan                                                                                   |
| `CONNECT_GITHUB_ALLOWED_OWNERS` |           | ID pemilik GitHub berangka. Apabila ditetapkan, token repo hanya dicetak untuk repo yang mereka miliki. Ia tidak mengehadkan siapa yang log masuk: seseorang yang dibenarkan menggunakan Connect ini masih menerima token pengguna App mereka sendiri. Untuk berkhidmat kepada satu organisasi sahaja, pastikan App itu peribadi kepada organisasi tersebut                            |
| `CONNECT_GITHUB_REVIEW_BOT_INSTALLS` | | ID pemasangan yang boleh membenarkan bot App menyemak permintaan tarik. Kosong secara lalai; `*` ditolak, dan setiap ID mesti juga dibenarkan |
| `CONNECT_HOST`, `CONNECT_PORT`  | `0.0.0.0`, `8790` | Alamat ikat dan port                                                                                                     |
| `CONNECT_TRUST_PROXY`           | `0`       | Lompatan proksi dipercayai dalam `X-Forwarded-For` (0 hingga 8). Digunakan untuk had setiap alamat, petunjuk rangkaian halaman log masuk dan alamat yang dilog. Di belakang proksi, `0` mengira setiap klien sebagai proksi, dan log menyatakannya sekali                  |

| Pemboleh ubah                                                               | Lalai | Maksud                                                                      |
| --------------------------------------------------------------------------- | ----- | --------------------------------------------------------------------------- |
| `CONNECT_GITHUB_APP_ID`, `CONNECT_GITHUB_APP_SLUG`, `CONNECT_GITHUB_CLIENT_ID` |       | GitHub App                                                                  |
| `CONNECT_GITHUB_CLIENT_SECRET`                                              |       | Rahsia, dual                                                                |
| `CONNECT_GITHUB_APP_PRIVATE_KEY`                                            |       | Rahsia. Kunci peribadi App (PEM)                                            |
| `CONNECT_GOOGLE_CLIENT_ID`, `CONNECT_GOOGLE_CLIENT_SECRET`                  |       | Klien Google. Rahsianya dual                                                |
| `CONNECT_LINEAR_CLIENT_ID`                                                  |       | Apl Linear. Tiada rahsia                                                    |
| `CONNECT_SLACK_APP_ID`, `CONNECT_SLACK_CLIENT_ID`                           |       | Apl Slack                                                                   |
| `CONNECT_SLACK_CLIENT_SECRET`, `CONNECT_SLACK_SIGNING_SECRET`               |       | Rahsia, dual                                                                |
| `CONNECT_KLIPY_APP_KEY`                                                     |       | Kunci carian GIF Klipy. Rahsia, dual                                        |
| `CONNECT_KLIPY_MODE`                                                        | `proxy` | `proxy` menyimpan kunci dalam Connect; `key` menyerahkannya kepada pelayan |

| Pemboleh ubah                                             | Lalai                      | Maksud                                                                                                     |
| --------------------------------------------------------- | -------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `CONNECT_SEAL_BACKEND`                                    | `local`                    | `local` atau `gcp-kms`                                                                                     |
| `CONNECT_SEAL_KEYS`                                       |                            | Rahsia, diperlukan untuk `local`. Entri `kid:key` dipisahkan koma, terbaharu dahulu; entri lama masih boleh menyahsulit |

| `CONNECT_STATE`                                           | `memory`                   | `memory` untuk satu instance, `redis` untuk berbilang instance. | `CONNECT_REDIS_URL`                                       |                            | Rahsia. `redis://` atau `rediss://`. Redis 6.2 atau lebih baharu dengan `maxmemory-policy noeviction`, kedua-duanya disemak semasa mula                                                                        |

## Jalankan lebih daripada satu instance

Satu instance dengan `CONNECT_STATE=memory` sudah memadai untuk kebanyakan organisasi. Berbilang instance di sebalik satu alamat
memerlukan `CONNECT_STATE=redis` dan `CONNECT_BINDINGS=firestore`, supaya log masuk yang dimulakan pada satu instance boleh diselesaikan pada instance lain dan setiap instance melihat ikatan Slack dan ID pemasangan yang dibersarakan yang sama. `CONNECT_DATA_DIR` yang dikongsi tidak berfungsi: Connect pertama menguncinya. Had permintaan setiap pemasangan, setiap alamat dan setiap instance adalah per instance; had untuk log masuk, token GitHub, token bot, carian GIF setiap alamat, pembersaraan dan pasukan Slack dikongsi melalui stor keadaan.

## Putar rahsia pembekal

Tiada siapa yang dilog keluar:

1. Cipta rahsia baharu di pembekal dan simpan yang lama
2. Pindahkan nilai lama ke `NAME_PREVIOUS`, letakkan yang baharu dalam `NAME`, dan naikkan `CONNECT_<LANE>_SECRET_GENERATION`.
   Fail yang dilekapkan diambil dalam masa 30 saat
3. Tunggu log masuk menyegarkan diri, kemudian padam rahsia lama di pembekal dan buang `NAME_PREVIOUS`

Untuk memutar kunci pemeteraian, letakkan entri `cc-connect-config seal-key` baharu di hadapan `CONNECT_SEAL_KEYS` dan simpan
entri lama sehingga pemeteraiannya telah disegarkan.

## Tukar apl

Pelayan mengingati ID apl dan ID klien yang Connect anda umumkan kali pertama mereka menggunakannya. Jika anda menggantikan
apl, kad Connect setiap pelayan akan memaparkan **Apl Connect telah berubah**, dan log masuk melalui Connect dijeda sehingga
pemiliknya menekan **Percayai aplikasi baharu**. Beritahu pemilik pelayan sebelum anda bertukar, supaya mereka tahu
bahawa gesaan itu daripada anda.

## Sekat pelayan

Tambah ID pemasangannya ke `CONNECT_DENY_INSTALLS` dan mulakan semula. Pemiliknya akan melihat "Connect telah menyekat ID pemasangan pelayan ini. Hubungi pengendali pelayan Connect anda." dan setiap log masuk melalui Connect di sana akan berhenti.

Pelayan juga membersarakan ID pemasangan lamanya sendiri apabila pemiliknya memutar kunci. Ia membuktikan ID itu miliknya dengan satu pemeteraian kelayakan yang Connect ini buat untuknya, jadi hanya pelayan yang pernah mendaftar masuk seseorang boleh membersarakan ID. Connect menyimpan ID yang dibersarakan selama-lamanya, jadi kunci lama dan setiap pemeteraian yang dibuat untuknya berhenti berfungsi, dan ia membebaskan ruang kerja Slack yang terikat kepada ID lama. Token yang sudah dikeluarkan tamat tempoh dengan sendirinya: dalam masa 8 jam untuk token seseorang, 1 jam untuk token bot. Connect menyimpan paling banyak 100,000 ID yang dibersarakan; melebihi itu, putaran ditolak dan log mengatakannya pada aras ralat.

## Penyelesaian masalah

### Sebuah pelayan memaklumkan Connect telah menyekatnya

ID pemasangannya tiada dalam `CONNECT_ALLOWED_INSTALLS`, ia ada dalam `CONNECT_DENY_INSTALLS`, atau ia telah dibersarakan oleh putaran kunci. ID berubah apabila pemilik
pelayan memutar kunci; minta ID yang baharu.

### Setiap log masuk ke satu pembekal gagal

Salah satu pemboleh ubahnya mungkin hilang, jadi Connect mengeluarkan lorong itu. Semak log permulaan dan jadual di atas. GitHub memerlukan
kelima-limanya: ID apl, slug, ID klien, rahsia klien dan kunci peribadi; Google memerlukan ID klien dan rahsia klien.

### Log masuk gagal dengan ralat ketidakpadanan ubah hala

Ubah hala yang didaftarkan dengan pembekal tidak sepadan tepat dengan `CONNECT_PUBLIC_URL`. Bandingkan skema, hos, port dan
laluan `/connect` untuk Connect yang dipasang.

### Semua orang perlu log masuk semula

Kunci pemeteraian berubah atau hilang, sebuah pelayan memutar kuncinya, atau data pelayan dipulihkan ke mesin lain. Kelayakan
yang dimeterai hanya boleh dibuka untuk pemasangan dan Connect yang mencipta.
