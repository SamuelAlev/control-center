Panduan ini menunjukkan cara memberikan pelayan anda GitHub App tersendiri. Ia mengambil masa kira-kira
dua minit, hanya pemilik pelayan yang melakukannya, dan ia hanya perlu dilakukan sekali bagi setiap pelayan.

:::note[Anda mungkin tidak memerlukannya]
Dengan Control Center Connect dihidupkan, orang log masuk ke GitHub melalui app kongsi Control Center, atau melalui
app yang digunakan oleh Connect organisasi anda. Daftarkan app anda sendiri apabila anda memilih **Gunakan aplikasi
saya sendiri**, atau apabila akses GitHub pelayan anda sepatutnya melalui app yang anda kawal. Lihat
[Control Center Connect](/ms-MY/manual-pengguna/rujukan/connect/).
:::

Untuk log masuk ke akaun anda sendiri selepas itu, lihat
[Sediakan integrasi GitHub](/ms-MY/manual-pengguna/panduan-cara/integrasi-github/).

## Apa yang dilakukan app ini

Satu pendaftaran menjawab dua tugasan yang berbeza:

| Tugasan               | Apa yang menjawabnya                                    | Mengapa ia penting                                                                                |
| --------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **Seseorang log masuk** | ID klien dan rahsia klien app                         | Setiap orang mendapat kelayakan GitHub sendiri, pada pelayan, pada setiap peranti                  |
| **Pelayan bertindak**   | ID app dan kunci peribadi                             | Ejen, pipeline, pengundi dan balasan bot menerima token untuk satu repositori pada satu masa        |

Tugasan kedua tidak pernah meminjam kelayakan seseorang secara keseluruhan. Setiap token yang dicetak oleh pelayan
hanya meliputi satu repositori dan dihadkan kepada apa yang boleh dilakukan oleh ahli yang bertanggungjawab di sana.
Membaca repositori yang dipautkan hanya memerlukan app; apa-apa yang menulis memerlukan ahli yang boleh push.
Automasi tidak pernah meluluskan pull request.

App pelayan hanya terpakai di bawah **Gunakan aplikasi saya sendiri**. Dengan Connect Control Center atau Connect tersuai, Connect mengendalikan GitHub, dan app pelayan kekal disimpan tetapi tidak digunakan sehingga anda bertukar semula. Ruang kerja yang menggunakan app sendiri ([Berikan satu ruang kerja app sendiri](#berikan-satu-ruang-kerja-app-sendiri)) menggunakan App sendirinya, tanpa mengira mod pelayan. Sebuah app yang sebahagian medannya
hilang ialah ralat, bukan sandaran: log masuk GitHub ditolak sehingga setiap medan diisi.

## Prasyarat

- Anda ialah **pemilik pelayan**. Kad **Apl penyedia** tidak kelihatan kepada orang lain
- Akaun GitHub. App dicipta di bawah akaun itu
- Alamat pelayan yang boleh dicapai oleh pelayar anda. Alamat awam pelayan (atau loopback, untuk pelayan desktop
  sendiri) ialah tempat GitHub menghantar anda kembali

## Cipta dengan satu klik

1. Pergi ke **Tetapan → Pelayan → Daftar masuk tunggal** dan tatal ke kad **Apl penyedia**
2. Pada blok **GitHub**, pilihan taip nama organisasi GitHub yang akan memiliki app itu dalam
   **Organisasi (pilihan)**. Biarkan kosong untuk mencipta app di bawah akaun anda sendiri; mencipta di bawah
   organisasi memerlukan anda menjadi pemilik organisasi tersebut
3. Klik **Cipta aplikasi GitHub saya**
4. Pelayar anda membuka GitHub dengan app yang sudah diisi. Klik **Create GitHub App**
5. GitHub menghantar anda kembali ke pelayan, yang menyimpan id app, kunci peribadi, id klien dan rahsia klien,
   kemudian membuka halaman pemasangan app

Tiada apa-apa disalin secara manual, dan kod penukaran pergi terus dari GitHub ke pelayan anda. Pautan itu hanya
berfungsi sekali dan tamat tempoh selepas sepuluh minit; jika tamat, klik **Cipta aplikasi GitHub saya** sekali lagi.

App dinamakan `Control Center <code>` dan hanya meminta apa yang digunakan oleh Control Center:

| Kebenaran                                  | Akses          |
| ------------------------------------------ | -------------- |
| Metadata                                   | Baca sahaja    |
| Contents                                   | Baca dan tulis |
| Pull requests                              | Baca dan tulis |
| Issues                                     | Baca dan tulis |
| Checks, Actions, Commit statuses           | Baca sahaja    |
| Organization members                       | Baca sahaja    |

Webhook dimatikan: pelayan membuat pengundian. Untuk memindahkan app yang anda cipta di bawah akaun sendiri ke
organisasi kemudian, gunakan **Transfer ownership** dalam tetapan lanjutan app di GitHub.

Titik pemeriksaan: blok GitHub berbunyi "Pelayan boleh bertindak sebagai dirinya sendiri, dan orang boleh log masuk".

## Pasangkan di tempat repositori anda berada

App yang didaftarkan tetapi tidak dipasang hanya boleh mendaftar masuk orang dan tidak boleh membaca apa-apa.

1. Pilih akaun atau organisasi yang memiliki repositori anda pada halaman pemasangan yang GitHub buka
2. Pilih **All repositories**, atau pilih repositori yang perlu dilihat oleh pelayan ini

Untuk memasang pada akaun lain kemudian, pentadbir ruang kerja pergi ke **Tetapan → Ruang kerja → Integrasi**, mencari
**Pemasangan aplikasi GitHub** pada kad **Apl GitHub** di bawah Hos kod dan klik **Pasang aplikasi GitHub**. Senarai itu
memaparkan setiap akaun tempat app dipasang dan menandakan pemasangan yang digantung.

## Kongsi pemasangan organisasi

Organisasi memasang GitHub App sekali sahaja. Selepas itu, sesiapa dalam organisasi yang log masuk ke GitHub pada mana-mana pelayan Control Center boleh menggunakan pemasangan itu, sama ada pelayan itu milik anda, rakan sekerja, atau mereka sendiri. Tiada apa-apa yang perlu dibenarkan bagi setiap pelayan.

Setiap token yang diperoleh pelayan ialah milik orang yang log masuk itu sendiri, terhad kepada satu repositori dan peranannya di situ, supaya ia tidak sampai lebih jauh daripada yang boleh mereka lakukan di GitHub. Log audit GitHub menunjukkan orang itu, yang bertindak melalui app.

Untuk menghalang Control Center mencapai sesebuah organisasi, pemilik organisasi membuang pemasangan atau menyempitkan repositorinya di GitHub. Membuang seseorang daripada organisasi juga menghentikan aksesnya.

## Daftar secara manual sebagai gantinya

Kad **Apl penyedia** juga menerima nilai secara terus, untuk app yang anda daftarkan sendiri:

| Kumpulan                      | Medan                                                                                          |
| ----------------------------- | ---------------------------------------------------------------------------------------------- |
| **Bertindak sebagai pelayan** | **ID apl**, dan **Kunci peribadi** (keseluruhan `.pem`, termasuk baris `BEGIN` dan `END`)       |
| **Memasukkan orang**          | **ID klien** dan **Rahsia klien**. **URL callback** memaparkan URL yang perlu didaftarkan, seperti sedia ada |
| **Perbualan permintaan tarik** | **Log masuk bot**, diselesaikan apabila anda menguji sambungan                                  |

Daftarkan URL callback `<server origin>/oauth/github/callback` tepat seperti yang dipaparkan kad, biarkan
**Expire user authorization tokens** dihidupkan, dan berikan kebenaran dalam jadual di atas. Klik **Uji**:
ia bertanya GitHub akaun mana app itu dipasang, supaya "disimpan" dan "berfungsi" tidak keliru.

## Konfigurasi daripada `.env` pelayan

Untuk pemasangan tanpa kepala atau berasaskan skrip, pelayan menyemai setiap medan daripada fail `.env`-nya
kali pertama ia tidak mempunyai nilai yang disimpan:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

Letakkan kunci pada **satu baris**: nilai `.env` ialah satu baris, dan `\n` di dalam tanda petik berganda
dinyahkod menjadi baris baharu. Pelayan enggan bermula apabila `GITHUB_APP_PRIVATE_KEY` atau `GITHUB_CLIENT_SECRET`
dieksport dalam persekitaran prosesnya, tempat setiap proses anak boleh membacanya; simpan dalam fail `.env`
(dalam Docker, lekapkan pada `/app/bin/.env`). Penyemaian berlaku **sekali bagi setiap medan**, jadi suntingan
dalam Tetapan tidak dibatalkan oleh permulaan semula.

## Berikan satu ruang kerja app sendiri

Sesebuah ruang kerja boleh berjalan pada app milik sendiri dan bukannya app pelayan:

1. Pentadbir ruang kerja pergi ke **Tetapan → Ruang kerja → Integrasi**
2. Pada kad **Control Center Connect**, mereka memilih **Gunakan aplikasi saya sendiri** dan klik **Terapkan**. Setiap orang dalam ruang kerja log masuk semula melalui app ruang kerja
3. Kad **Apl GitHub** di bawah Hos kod kini memegang medan app itu: **ID apl** dan **Kunci peribadi** di bawah **Bertindak untuk ruang kerja ini**, **ID klien** dan **Rahsia klien** di bawah **Melog masuk orang**. Klik **Uji** apabila medannya telah diisi

Ahli kemudian log masuk ke app itu untuk ruang kerja ini. Ruang kerja pada app sendiri tidak pernah jatuh kembali kepada app pelayan atau Connect: sehingga medannya lengkap, kerja GitHubnya ditolak. Pilihan yang sama meliputi Google Calendar, Linear dan carian GIF, dengan medan masing-masing di sebelah pembekalnya pada halaman yang sama. Lihat [Berikan satu ruang kerja app Linear sendiri](/ms-MY/manual-pengguna/panduan-cara/integrasi-linear/#berikan-satu-ruang-kerja-app-linear-sendiri) dan [Berikan satu ruang kerja klien Google sendiri](/ms-MY/manual-pengguna/panduan-cara/sambungkan-kalendar/#berikan-satu-ruang-kerja-klien-google-sendiri). Pilihan lain pada kad itu, dan apa yang dilakukan setiap satu, terdapat dalam [Pilihan setiap ruang kerja](/ms-MY/manual-pengguna/rujukan/connect/#pilihan-setiap-ruang-kerja).

## Penyelesaian masalah

### Cipta aplikasi GitHub saya memaklumkan pelayan tiada alamat

Pelayan tiada URL awam yang pelayar boleh kembali kepadanya. Tetapkan `CC_SERVER_PUBLIC_URL` (atau `--public-url`)
dan cuba lagi.

### GitHub memaklumkan pautan telah tamat tempoh

Halaman sekali guna telah digunakan, atau sepuluh minit telah berlalu. Mulakan semula dari Tetapan.

### Uji memaklumkan kelayakan berfungsi tetapi app tidak dipasang di mana-mana

Pendaftaran dan pemasangan ialah langkah berasingan. Buka halaman pemasangan app, atau gunakan **Pasang aplikasi
GitHub** dalam Ruang kerja → Integrasi.

### Uji memaklumkan kunci peribadi tidak dapat dibaca

Tampal keseluruhan fail `.pem`, termasuk baris `-----BEGIN` dan `-----END`. Kunci `ed25519` atau EC tidak boleh
digunakan: GitHub Apps menandatangani dengan RSA.

### Seorang ahli telah log masuk tetapi tidak nampak repositori

App tidak dipasang pada akaun yang memilikinya, atau pemasangannya memilih repositori yang berbeza. Log masuk
hanya memberikan apa yang app dibenarkan lihat.

### Ejen memaklumkan pemasangan GitHub App telah digantung

Seseorang telah menggantung pemasangan itu di GitHub. Nyahgantungkannya dalam **Settings → Applications → Installed
GitHub Apps** untuk akaun tersebut.
