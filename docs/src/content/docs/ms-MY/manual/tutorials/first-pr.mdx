## Apa yang akan anda bina

Menjelang akhir tutorial ini, anda akan mempunyai:

- Pull request yang dibuka dalam meja kerja PR Control Center
- Diff PR itu yang dibaca, dengan komen sebaris yang ditinggalkan
- Keputusan semakan yang dihantar
- PR yang telah dicantumkan

Prasyarat: [Hantar ejen pertama anda](/ms-MY/manual-pengguna/tutorial/ejen-pertama/) telah selesai dan satu pull request terbuka pada repo yang didaftarkan dalam ruang kerja ini. Untuk langkah semakan, pilih PR yang bukan anda buka sendiri — butang **Semakan** tersembunyi pada PR anda sendiri. Cantuman masih berfungsi pada PR yang anda buka sendiri.

## Langkah 1: Buka pull request

1. Klik **Pull request** di bar sisi
2. Cari PR anda dan kliknya

**Titik semak.** PR terbuka sebagai meja kerja bertab — Gambaran keseluruhan, Diff, Kawalan sumber, Sembang, Tindakan — dengan tumpuan pada **Gambaran keseluruhan**: tajuk dan tindakannya, penerangan serta garis masa aktiviti dan bar sisi dengan status, penyemak, penerima tugasan, pemeriksaan dan fail yang berubah. Mengklik fail di situ melompat kepadanya dalam tab Diff. Tab **Semakan PR** tidak terbuka sehingga seseorang meminta semakan AI.

:::note[Baris gilir kosong dengan gesaan "sambungkan GitHub"]
Keadaan itu bermakna _pelayan_ tidak memegang token GitHub — klien anda tidak pernah memegangnya. Tetapkan satu di bawah **Tetapan → Ruang kerja → Profil & identiti → Hos kod**, kemudian muat semula senarai itu.
:::

## Langkah 2: Baca diff

Buka tab **Diff**. Pokok fail yang boleh diruntuhkan berada di sebelah kiri, dan jalur di atas diff membawa pemilih julat commit — sempitkan diff kepada satu commit atau satu rentang commit — serta bilangan fail dan penambahan serta pemadaman yang dikemas kini secara langsung.

Butang tetapan dalam bar alat diff mengawal cara ia dipaparkan:

- Paparan **Belah** atau **Bersatu**
- **Balut baris** atau tatal baris panjang
- **Ligatur fon kod**

Tandakan fail sebagai dilihat untuk menjejak kemajuan anda merentas diff yang besar. Navigasi papan kekunci ada dalam [Pintasan papan kekunci](/ms-MY/manual-pengguna/rujukan/pintasan-papan-kekunci/).

## Langkah 3: Tinggalkan komen sebaris

1. Tudingkan kursor pada satu baris dalam diff — pil `+` kecil muncul di margin
2. Kliknya untuk mengomen baris itu, atau seretnya secara menegak dahulu untuk memilih julat
3. Taip maklum balas anda. Komposer menawarkan dua cara hantar:
   - **Mula semakan** (atau **Tambah ke semakan** jika semakan sedang berjalan) menyimpan komen itu dalam baris gilir. Utas itu memaparkan **Semakan tertunda** sehingga anda menghantar keputusan pada langkah 4.
   - **Tambah komen tunggal** menyiarkannya ke GitHub serta-merta. Utas itu memaparkan **Menyiarkan…**, kemudian **Disegerakkan**, dan menawarkan cuba semula jika penyiatan gagal.

Untuk tutorial ini, gunakan **Mula semakan** supaya komen itu keluar bersama keputusan.

:::caution[Komen dalam baris gilir belum ada di GitHub]
**Mula semakan** / **Tambah ke semakan** menahan komen itu secara setempat sehingga anda menghantar keputusan. Hanya **Tambah komen tunggal** menyiarkan serta-merta. _Badan_ semakan yang anda tulis pada langkah 4 ialah draf yang berasingan.
:::

## Langkah 4: Hantar semakan

1. Klik **Semakan** dalam baris tindakan Gambaran keseluruhan — butang yang sama juga ada dalam bar alat tab Diff. Ia tersembunyi pada PR yang anda buka sendiri dan pada PR yang ditutup atau dicantum.
2. Tulis ringkasan dalam komposer. Ia disimpan secara automatik sebagai draf, jadi anda boleh menutupnya dan kembali semula.
3. Pilih keputusan:
   - **Minta perubahan**
   - **Komen**
   - **Luluskan**

Keputusan itu _ialah_ butangnya. Selepas **Luluskan** atau **Minta perubahan**, butang itu melabel semula dirinya sebagai **Diluluskan** atau **Perubahan diminta**. Keputusan **Komen** membiarkan butang itu berlabel **Semakan**.

**Titik semak.** Butang itu berbunyi "Diluluskan" atau "Perubahan diminta" jika anda memilih salah satu daripada kedua-duanya.

## Langkah 5: Cantum

Butang **Cantum** hadir setiap kali GitHub melaporkan PR itu boleh dicantum — ia tidak dikawal oleh kelulusan anda sendiri. Warnanya melaporkan kesediaan dan bukan kebenaran: utama apabila kelulusan yang diperlukan dan pemeriksaan berwarna hijau, sekunder semasa pemeriksaan masih berjalan, destruktif apabila penyemak yang diminta belum meluluskan atau pemeriksaan sedang gagal.

1. Klik **Cantum**
2. Pilih kaedah: **Squash dan cantum**, **Cipta commit cantuman**, atau **Rebase dan cantum**
3. Untuk dua yang pertama, edit tajuk dan mesej commit yang telah diisi awal
4. Sahkan

Sebarang masalah yang belum selesai — "Semakan gagal", "Beberapa semakan masih tertunda" — disenaraikan dalam panel timbul sebelum anda mengesahkan.

:::caution[Mencantum tidak boleh dipulihkan]
Mencantum menolak commit ke GitHub. Ia tidak pernah masuk ke tindanan buat asal Control Center dan tidak boleh dibatalkan dari sini.
:::

Selepas mencantum, acara domain `PrMerged` tercetus; analitik dan pemberitahuan memakannya. Lihat [Acara domain](/ms-MY/manual-pengguna/rujukan/acara-domain/) untuk apa lagi yang mendengarnya.

## Menyemak dengan AI

Control Center boleh meletakkan pipeline penyemak pada PR yang terbuka, tetapi hanya apabila anda memintanya: templat `pr_review` mempunyai pencetus manual dan tiada yang lain.

1. Buka menu limpahan dalam baris tindakan Gambaran keseluruhan dan pilih **Tanya AI**. Control Center memulakan larian itu dan membuka tab **Semakan PR**, supaya anda boleh menonton pakar-pakar itu bekerja.
2. Ejen penyemak merekodkan penemuan mereka sebagai nod semakan dalam ruang PR itu; satu langkah akhir menggabungkannya menjadi satu laporan.

Pipeline itu sengaja tidak menyiarkan ke GitHub — ia tamat selepas menggabungkan. Penerbitan ialah langkah berasingan yang anda lakukan sendiri, dengan butang **Terbitkan ke GitHub** pada tab **Semakan PR**. Lihat [Gunakan semakan berkuasa AI](/ms-MY/manual-pengguna/panduan-cara/semakan-ai/).

## Ringkasan

Anda membuka PR dalam meja kerja, membaca diff dengan penonjolan sintaks, meninggalkan komen sebaris, menghantar keputusan dan mencantum — tanpa meninggalkan apl.

**Seterusnya:** [Bina pipeline pertama anda](/ms-MY/manual-pengguna/tutorial/pipeline-pertama/) untuk mengautomasikan aliran kerja berbilang langkah.
