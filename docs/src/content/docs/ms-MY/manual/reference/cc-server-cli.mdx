Setiap flag proses menerima flag CLI atau pemboleh ubah persekitaran; flag diutamakan,
kemudian persekitaran, kemudian lalai. Kelayakan pembekal ialah pengecualian —
lihat [Apl pembekal dan Connect](#apl-pembekal-dan-connect).

:::caution[Flag yang tidak dikenali diabaikan secara senyap]
Penghurai argumen ditulis sendiri dan melangkau apa-apa yang tidak dikenali, jadi salah taip (`--tls-key-file`, `--bindany`) tidak menghasilkan ralat — pelayan cuma bermula dengan lalai. Periksa baris log permulaan apabila sesuatu flag kelihatan tidak berkesan. Satu [bendera mod kod](#mod-kod) dengan nilai yang tidak diterimanya adalah berbeza: pelayan enggan bermula.
:::

## Teras

| Flag            | Persekitaran           | Lalai                                            | Maksud                                                                                                         |
| --------------- | ---------------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `--data-dir`    | `CC_SERVER_DATA_DIR`   | direktori data aplikasi setiap pengguna OS (lihat di bawah) | Pangkalan data, rahsia, model dan media cache                                                        |
| `--port`        | `CC_SERVER_PORT`       | `9030`                                           | Port TCP (`0` = sementara)                                                                                     |
| `--bind`        | `CC_SERVER_BIND`       | `loopback`                                       | `loopback`, atau `any`/`all`/`0.0.0.0` untuk setiap antara muka (memerlukan TLS atau `--insecure`)             |
| `--repo-roots`  | `CC_SERVER_REPO_ROOTS` | direktori rumah pengguna pelayan                 | Direktori asas dipisahkan koma yang boleh disemak imbas oleh klien semasa mendaftarkan repo. Menyemak imbas melebihi sesuatu akar akan ditolak |
| `--log-level`   | `CC_SERVER_LOG_LEVEL`  | `warning`                                        | `debug`, `info`, `warning`, atau `error`. Baris semasa but/sedia sentiasa dicetak                              |
| `--server-name` | `CC_SERVER_NAME`       | nama hos mesin                                   | Nama yang dipaparkan dalam pemilih, penemuan dan permukaan penggandingan                                      |

| `--public-url`      | `CC_SERVER_PUBLIC_URL`      | diperoleh daripada ikatan     | URL RPC yang dihebahkan oleh pelayan ini kepada klien berganding. **Tetapkan ini secara eksplisit di belakang proksi, NAT atau terowong** — lalai hanyalah tekaan pada ikatan setempat |
| `--allowed-origins` | `CC_SERVER_ALLOWED_ORIGINS` | `https://app.usectrl.dev`     | Asalan penyemak imbas dipisahkan koma yang dibenarkan mendail `/rpc` merentas asalan. Loopback dan klien natif sentiasa dibenarkan                             |

| `--mdns`            | `CC_SERVER_MDNS`            | `auto`                        | Pengiklanan LAN: `auto` (hanya apabila diikat melebihi loopback), `on`, `off`. Penemuan hanya mengiklankan kewujudan — menyertai masih memerlukan penggandingan |
| `--tunnel`          | `CC_SERVER_TUNNEL`          | `off`                         | Penyedia terowong terurus: `off`, `cloudflared`, `ngrok`, `tailscale`. Pendedahan awam adalah pilihan masuk                                                 |
| `--tunnel-binary`   | `CC_SERVER_TUNNEL_BINARY`   | diselesaikan daripada `PATH`  | Laluan binari terowong yang eksplisit                                                                                                                        |
| `--tunnel-sha256`   | `CC_SERVER_TUNNEL_SHA256`   | tidak ditetapkan              | SHA-256 yang dijangka bagi binari itu, disahkan sebelum setiap pelahiran                                                                                     |
| `--tunnel-args`     | `CC_SERVER_TUNNEL_ARGS`     | kosong                        | Argumen tambahan dipisahkan koma untuk pemanggilan terowong                                                                                                  |

## Apl pembekal dan Connect

Tiada binaan membawa kelayakan pembekal. Apabila Control Center Connect dihidupkan, Connect menjalankan setiap pembekal dan apl sendiri kekal disimpan tetapi tidak digunakan. Di bawah **Gunakan aplikasi saya sendiri**, setiap pembekal berjalan pada apl pelayan itu sendiri apabila ia dikonfigurasikan sepenuhnya, jika tidak ia tidak tersedia. Apl ruang kerja terpakai dalam kedua-dua kes. Apl sendiri
ditetapkan dalam **Tetapan → Pelayan → Daftar masuk tunggal → Apl penyedia**, atau disemai sekali daripada fail `.env`
pelayan. Tiada bendera untuknya: rahsia pada baris arahan boleh dibaca melalui `ps`.

| Pemboleh ubah                  | Maksud                                                                                        |
| ------------------------------ | --------------------------------------------------------------------------------------------- |
| `GITHUB_APP_ID`                | ID GitHub App pelayan                                                                         |
| `GITHUB_APP_PRIVATE_KEY`       | Kunci peribadinya, pada satu baris dengan escape `\n`. **Hanya `.env`**                       |
| `GITHUB_CLIENT_ID`             | ID kliennya, untuk mendaftar masuk orang                                                      |
| `GITHUB_CLIENT_SECRET`         | Rahsia kliennya. **Hanya `.env`**                                                             |
| `GOOGLE_OAUTH_CLIENT_ID`       | Klien Google Web application pelayan                                                          |
| `GOOGLE_OAUTH_CLIENT_SECRET`   | Rahsianya. **Hanya `.env`**                                                                   |
| `LINEAR_CLIENT_ID`             | Apl Linear pelayan (PKCE, tanpa rahsia)                                                       |
| `LINEAR_API_KEY`               | Kunci perkhidmatan Linear untuk automasi. **Hanya `.env`**                                    |
| `KLIPY_APP_KEY`                | Kunci Klipy pelayan sendiri untuk carian GIF. Hanya digunakan di bawah **Gunakan aplikasi saya sendiri** |
| `CC_CONNECT_URL`               | `hosted`, `off`, atau URL Connect. Mengunci pilihan Connect; Tetapan tidak dapat menukarnya    |
| `CC_SERVER_CONNECT_HOST`       | `on` memasang Control Center Connect di `<server>/connect`, dikonfigurasi oleh pemboleh ubah `CONNECT_*`. Lihat [Jalankan pelayan Connect](/ms-MY/manual-pengguna/panduan-cara/jalankan-pelayan-connect/#pasang-connect-dalam-cc_server) |

Fail `.env` dibaca dari direktori kerja pelayan, di sebelah boleh laksana, atau dari checkout sumber di atasnya; dalam
Docker, lekapkan pada `/app/bin/.env`. Pelayan **enggan bermula** (kod keluar `78`) apabila `GITHUB_APP_PRIVATE_KEY`,
`GITHUB_CLIENT_SECRET`, `GOOGLE_OAUTH_CLIENT_SECRET`, `LINEAR_API_KEY`, atau mana-mana `SLACK_*SECRET*` dieksport dalam
persekitaran prosesnya, tempat setiap proses anak boleh membacanya. Penyemaian daripada `.env` berlaku sekali bagi setiap
medan, jadi suntingan kemudian dalam Tetapan tidak dibatalkan oleh mula semula. Nilai kosong dibaca sebagai tidak ditetapkan.

Tiada kelayakan forge datang daripada persekitaran: GitHub, GitLab dan Bitbucket semuanya bertindak
melalui log masuk atau token milik ahli sendiri, atau melalui token GitHub App untuk satu repositori
yang terikat kepada ahli bertanggungjawab.

### `--sandbox`

Pelayan menyiasat hos sekali semasa but dan membalut pelaksanaan perintah ejen dalam
kotak pasir natif OS apabila bahagian belakang tersedia: `sandbox-exec` (Seatbelt) pada macOS,
`bwrap` serta `socat` pada Linux dan WSL2.
Keputusan dibuat sekali dan kekal sehingga pelayan dimulakan semula. Terdapat tiga hasil, setiap satu dipaparkan pada baris pendedahan permulaan:

| `sandbox=`    | Bila                                    | Larian ejen siapa yang dimulakan                                                 |
| ------------- | --------------------------------------- | -------------------------------------------------------------------------------- |
| `native`      | Bahagian belakang tersedia dan `--sandbox` ialah `on` | Semua orang, dibalut                                                       |
| `off`         | `--sandbox off`                         | Semua orang, tanpa kurungan pada hos ini                                         |
| `unavailable` | `--sandbox on` dan tiada bahagian belakang (Windows, atau Linux tanpa `bwrap` dan `socat`) | Hanya larian yang pemilik pelayan bertanggungjawab ke atasnya, tanpa kurungan. Yang lain ditolak dengan "Pelayan ini tiada kotak pasir, jadi hanya pemiliknya boleh menjalankan ejen di sini." |

Bagi automasi, orang yang bertanggungjawab ialah orang yang automasi itu terikat kepadanya. Tanpa pemilik pelayan yang direkodkan, tiada larian dimulakan pada hos `unavailable`. Pada Linux dan WSL2 dengan bubblewrap dipasang, penghantaran natif kini gagal tertutup untuk setiap larian; lihat [Bahagian belakang kotak pasir](/ms-MY/manual-pengguna/rujukan/bahagian-belakang-kotak-pasir/#linux-bubblewrap).

`--sandbox off` ialah pilihan pemilik pelayan untuk semua orang yang menggunakan pelayan: ia menjalankan ejen setiap ahli tanpa kurungan pada mesin ini. Gunakannya pada hos tempat profil kotak pasir itu sendiri berkelakuan salah, atau untuk membenarkan ahli menjalankan ejen pada hos tanpa bahagian belakang. Ia tidak memerlukan bina semula, dan pelayan merekodkan amaran sepanjang hayat proses supaya keadaan itu tidak pernah senyap.

### `--tool-deferral`

Larian harness terbina menghantar set langsung kecil takrifan alat serta indeks nama sahaja bagi selebihnya, yang memuatkan skemanya pada kali pertama digunakan, atau dipanggil daripada skrip `repl`. Ia mengekalkan set yang sentiasa kelihatan dalam julat tempat model memilih alat dengan andal. Diukur pada pendaftaran yang dibina oleh ujian, alat sembang piawai ejen terbina berjumlah 14 definisi: kira-kira 16.5 KB dengan `repl` (kira-kira 4 KB daripadanya ialah `repl`, yang definisinya tidak boleh melebihi 4,096 bait), kira-kira 13 KB pada pelayan yang tidak boleh menjalankan skrip. Alat yang ditangguhkan kekal boleh dipanggil dengan nama sepanjang masa, dan `search_tools` menemuinya mengikut niat. Lihat [Konteks alat dan caching prompt](/ms-MY/manual-pengguna/konsep/konteks-alat/).

`--tool-deferral off` menghantar takrifan setiap alat yang diterima terlebih dahulu, kecuali bahawa larian dengan `repl` masih memanggil daripada skrip alat yang boleh dipanggil oleh skrip. Ia ialah suis mati bagi model yang mengendalikan permukaan dua peringkat dengan teruk — satu flag dan bukan bina semula. Ia hanya menjejaskan harness terbina; `tools/list` MCP yang dilihat oleh klien luaran ialah katalog yang lengkap, kecuali bagi larian ejen pada pelayan yang boleh menjalankan skrip [mod kod](/ms-MY/manual-pengguna/konsep/mod-kod/).

### `--credential-gate`

Larian yang kelayakan pembekalnya hilang atau habis akan **diparkirkan** dan bukan
digagalkan: pengendali menerima gesaan untuk membetulkannya, dan larian itu bersambung
semula jika mereka berbuat demikian. Tarikh akhir lalainya ialah 900 saat (15 minit),
dihadkan kepada 0–3600.

Tarikh akhir itu sengaja jauh lebih panjang daripada tarikh akhir gesaan kelulusan:
kelulusan ialah keputusan yang dibuat seseorang dalam beberapa saat, manakala
membetulkan kelayakan bermakna membuka terminal, mendaftar masuk dan kembali semula.
Had atas itulah yang menghalang larian tanpa pengawasan — langkah pipeline, pencetus
cron, webhook — daripada menunggu seseorang yang sedang tidur. Apabila ia tamat,
larian itu gagal dengan mesej yang sama seperti jika ia digagalkan sejak awal.

`--credential-gate=0` ialah suis mati: tiada apa yang pernah diparkirkan dan kelayakan
yang buruk menamatkan giliran tepat seperti sebelum pintu ini wujud.

### Mod kod

[Mod kod](/ms-MY/manual-pengguna/konsep/mod-kod/) membenarkan ejen menjalankan skrip JavaScript yang memanggil alatnya. Tiada bendera yang menghidupkan atau mematikannya: setiap larian mendapat alat `repl` apabila pelayan boleh menjalankan skrip, dan pelayan demo awam tidak menjalankan sebarang skrip.

Skrip berjalan dalam `cc_codemode`, program yang dibundel bersama pelayan dalam `bin/codemode/`. Pelayan tidak akan bermula tanpanya: ia mencetak satu baris yang menamakan apa yang hilang dan keluar dengan kod `78`. Semasa bermula ia menjalankan ujian kendiri kunci program dan mencetak satu baris (hanya didiamkan oleh `--log-level error`):

```text
cc_server: code_mode=available (cc_codemode 0.1.0 quickjs-ng 0.16.2 protocol 2; 16 scripts at once, at most 12 per workspace; up to 64 more runners kept for scripts waiting on a person; heap at most 1024 MiB per script)
cc_server: code_mode=unavailable (<reason>) — runs on this host get no repl tool; scripts never run without full lockdown
```

`unavailable` bermakna program tidak dapat mengunci dirinya pada hos ini, contohnya dalam bekas yang profil keselamatannya menolak salah satu langkahnya, atau kerana ia bukan binaan keluaran. Pelayan berjalan seperti biasa, tiada larian mendapat `repl`, dan halaman tetapan mod kod ruang kerja menunjukkan sebabnya.

Pelayan terus menyemak semasa ia berjalan. Apabila program gagal dimulakan atas sebab yang bukan disebabkan skrip, pelayan menjalankan ujian kendiri sekali lagi, paling kerap sekali seminit. Jika itu gagal, pelayan mencetak baris `unavailable` bersama sebabnya dan tidak menjalankan skrip: larian yang bermula sementara itu tidak mendapat `repl`, dan larian yang sudah memilikinya memanggil alatnya secara langsung ([Apabila skrip tidak boleh dijalankan](/ms-MY/manual-pengguna/konsep/mod-kod/#apabila-skrip-tidak-boleh-dijalankan)). Ia terus menyemak, paling kerap sekali seminit, dan apabila ujian kendiri lulus semula, ia mencetak baris `available` dan menjalankan skrip semula. Hanya ujian kendiri yang gagal semasa permulaan memerlukan permulaan semula. Sebab yang ditunjukkan oleh tetapan ruang kerja telah membuang laluan hos; baris log memaparkannya sepenuhnya.

Dua bendera mod kod menghadkan apa yang boleh digunakan oleh skrip. `--code-mode-max-processes` mengehadkan skrip yang berjalan serentak merentasi setiap ruang kerja (lalai dua kali teras pemproses, paling banyak 16; diterima 1–64). Dengan had 2 atau lebih, satu ruang kerja menggunakan paling banyak had tolak satu perempat daripadanya, supaya tiada satu ruang kerja pun boleh mengambil setiap tempat, dan skrip yang menunggu diterima mengikut giliran merentasi ruang kerja. Skrip yang menunggu kelulusan atau jawapan seseorang menyerahkan tempatnya kepada skrip lain dan tidak memulakan panggilan alat sehingga dijawab; sehingga empat kali had skrip menunggu sedemikian dikekalkan, paling banyak tiga perempat daripadanya dari satu ruang kerja, dan setiap satunya masih boleh mengira dalam had masa pemprosesnya sendiri. `--code-mode-max-heap-mb` ialah jumlah memori paling banyak yang boleh digunakan oleh mana-mana satu skrip.

Nilai yang tidak diterima oleh bendera ini (nombor di luar julat, atau bukan nombor) menghentikan pelayan semasa bermula (kod keluar `78`) dengan mesej yang menamakan nilai yang diterima. Ia tidak sekali-kali dibaca sebagai lalai.

## Subperintah

| Perintah                                      | Apa yang dilakukannya                                                                               |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `cc_server`                                   | Menjalankan pelayan sehingga `SIGINT`/`SIGTERM`                                                     |
| `cc_server pair`                              | Menyediakan peranti dan mencetak id serta kunci penggandingannya. Selamat terhadap direktori data yang sudah disajikan oleh pelayan — pelayan yang berjalan akan mengambil peranti itu tanpa permulaan semula |
| `cc_server connect <command>`                 | Menunjukkan atau menukar Control Center Connect yang digunakan oleh pelayan ini, tanpa memulakannya |
| `cc_server update`                            | Menyemak, memuat turun dan mengesahkan keluaran berdiri sendiri yang lebih baharu                   |
| `cc_server --version`                         | Mencetak versi binaan dan SHA git — identiti yang sama yang dihebahkan oleh `/healthz` dan jabat tangan RPC |

### `pair`

| Flag           | Lalai                                                     | Maksud                                                                                                                                                               |
| -------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--device`     | `web-client`                                              | Id peranti. Platform disimpulkan daripadanya, jadi `--device desktop` menempa baris desktop dan `--device ios`/`android` menempa baris telefon; apa-apa yang lain dianggap web |
| `--label`      | nama platform serta nama hos mesin ini                    | Nama paparan dalam senarai peranti                                                                                                                                   |
| `--host`       | `localhost`, atau `<this-host>` apabila diikat pada mana-mana antara muka | Hos untuk disematkan dalam URL yang dicetak. Tetapkannya kepada IP LAN atau hos terowong yang benar-benar akan didail oleh klien                          |
| `--client-url` | tidak ditetapkan                                          | Asalan klien **web** yang dihoskan. Menambah pautan dalam yang boleh diimbas dan QR terminal                                                                         |

`pair` juga menerima flag teras `--data-dir`, `--port` dan `--bind`: flag itu
memilih direktori data untuk ditulis dan membentuk URL pelayan yang dicetak (`ws` pada loopback,
`wss` apabila `--bind any`). Menjalankan semula `pair` untuk `--device` yang sama
memutar kuncinya dan menggugurkan sesi aktif peranti itu. Kelayakan yang ditempa di
sini **tiada tarikh luput**, tidak seperti 30 hari yang ditetapkan oleh penggandingan
dalam apl.

:::caution[QR `--client-url` bukan QR telefon]
`pair --client-url` mengisi borang sambungan klien **web** (URL pelayan,
id peranti dan kunci dalam serpihan URL). Telefon digandingkan dengan muatan
berbeza yang ditempa daripada panel penggandingan dalam apl — deskriptor sambungan
penuh pelayan serta tarikh luput. Kedua-duanya tidak boleh saling ditukar — lihat [Gandingkan peranti](/ms-MY/manual-pengguna/panduan-cara/gandingkan-peranti/).
:::

### `connect`

Membaca dan menulis tetapan yang sama seperti kad **Control Center Connect** dalam **Tetapan → Pelayan → Daftar masuk tunggal**,
daripada direktori data. Pelayan yang sedang berjalan mengambil perubahan dalam masa 10 minit atau apabila dimulakan semula.

| Arahan                                  | Fungsinya                                                                                                                                |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `cc_server connect status`              | Mencetak mod, URL, sama ada `CC_CONNECT_URL` mengunci, id pemasangan, kesihatan dan sumber setiap lorong (`own`, `connect` atau `off`) |
| `cc_server connect enable`              | Menggunakan Control Center Connect yang dihoskan oleh Control Center                                                                     |
| `cc_server connect enable --url <url>`  | Menggunakan Connect tersuai di URL itu (HTTPS, atau `http` pada loopback)                                                                |
| `cc_server connect disable`             | Berhenti menggunakan Connect. Hanya apl pelayan sendiri yang mendaftar masuk orang                                                      |

`status` tanpa arahan ialah lalai. Setiap arahan menerima `--data-dir`. `CC_CONNECT_URL` mengatasi apa sahaja yang disimpan
oleh arahan-arahan ini. Arahan yang tidak dikenali keluar dengan kod `64`. Lihat [Control Center Connect](/ms-MY/manual-pengguna/rujukan/connect/)
untuk mod, identiti pemasangan dan kod status.

### `update`

`--apply` menggantikan pemasangan; ia ditolak selagi pelayan masih menjawab pada port
yang dikonfigurasikan melainkan anda memberikan `--force`. `--allow-downgrade` membenarkan
keluaran yang lebih lama.

Perintah itu menolak secara terus, dengan penjelasan dan bukan ralat, bagi pemasangan
yang tidak dimilikinya:

| Persekitaran                   | Dikesan oleh                                | Apa yang dikatakannya                                       |
| ------------------------------ | ------------------------------------------- | ----------------------------------------------------------- |
| Pelayan terbenam desktop       | `CC_EMBEDDED=1` atau `CC_BOOTSTRAP_DEVICE_ID` | Kemas kini apl itu sebaliknya — pemasang menukar keseluruhan pokok |
| Checkout sumber `dart run`     | laluan skrip berakhir dengan `.dart`        | Kemas kininya dengan git                                    |
| Docker                         | penanda kontena                             | Tarik imej yang lebih baharu                                |

## Kitaran hayat proses

`cc_server` berjalan sehingga `SIGINT` / `SIGTERM`. Satu pemboleh ubah persekitaran
tambahan mengawalnya, dan ia ditetapkan oleh desktop dan bukan oleh anda:

| Pemboleh ubah            | Kesan                                                                                                                                        |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `CC_EXIT_WITH_PARENT=1`  | Pelayan keluar apabila proses induknya keluar, dikesan oleh induk menutup hujung tulis paip stdinnya. Desktop menetapkannya supaya apl yang ranap tidak pernah meninggalkan pelayan yatim yang memegang direktori data |

Tetapkannya sendiri hanya jika anda menyelia `cc_server` sebagai proses anak dan
mahukan jaminan yang sama.

`DO_NOT_TRACK=1` (sebarang nilai selain kosong, `0` atau `false`) menghentikan
[analitik penggunaan](/ms-MY/manual-pengguna/rujukan/analitik-penggunaan/) pelayan itu sendiri walaupun suis seluruh pelayan
dihidupkan. Klien masih mengikut suis tersebut.

## Susun atur direktori data

Direktori data lalai ialah `~/Library/Application Support/control-center` pada macOS,
`%APPDATA%\control-center` pada Windows dan `$XDG_DATA_HOME/control-center` (jika tidak
`~/.local/share/control-center`) di tempat lain. `.cc_server` yang relatif kepada cwd hanya
digunakan apabila tiada direktori rumah atau data apl dapat diselesaikan.

Pelayan memastikan direktori data kekal peribadi kepada akaunnya sendiri (`0700`). Pelayan enggan bermula (kod keluar `78`) apabila ia tidak dapat berbuat demikian, apabila `global.db` rosak atau ditulis oleh versi yang lebih baharu, atau apabila fail identitinya tidak boleh dibaca.

| Laluan                            | Kandungan                                                                     |
| --------------------------------- | ------------------------------------------------------------------------------- |
| `global.db`                       | Daftar ruang kerja, pengguna, peranti berganding, suapan berita dan barisan armada |
| `<workspaceId>/workspace.db`      | Satu pangkalan data bagi setiap ruang kerja — ejen, ruang, tiket, memori |
| `<workspaceId>/code_index.db` | Graf kod ruang kerja itu. Dibina semula apabila hilang, tidak pernah disandarkan |
| `pre_upgrade/`, `<workspaceId>/pre_upgrade/` | Dua salinan terbaharu pangkalan data daripada sebelum kemas kini menukar formatnya |
| `<workspaceId>/chat_credentials/` | Token bot sembang, sebagai JSON biasa, supaya ia bergerak bersama ruang kerja   |
| `secrets.json`                    | Kunci penggandingan, kunci pemasangan Connect, apl pembekal, log masuk pengguna (dimeterai apabila dicipta melalui Connect), rahsia webhook, SSO (`0600`) |
| `backups/<timestamp>/`            | Satu snapshot pemasangan — `manifest.json`, `global.db` dan salinan setiap ruang kerja |
| `backups/exports/`                | Eksport satu ruang kerja, `<workspaceId>-<timestamp>.db`                         |
| `backups/transfer/`               | Kawasan persediaan untuk muat turun dan muat naik sandaran; disapu oleh laluan yang menulisnya |
| `models/`                         | Model pembenaman, diarisasi dan pertuturan pada peranti                          |
| `codemode/` | Salinan pembangunan pelari mod kod, dipasang oleh `scripts/natives/build_codemode.sh`; bundel keluaran membawanya dalam `bin/codemode/` |
| `meetings/<meetingId>/`           | Audio mesyuarat yang disimpan                                                    |
| `rigs/images/`                    | Imej cakera stesen yang diimport (permukaan desktop QEMU)                        |
| `rigs/smolvm/<rigId>/`            | Keadaan masa jalan microVM setiap stesen (rahsia broker, `0600`)                 |
| `rigs/smolvm-packs/`              | Pek mesin yang telah diekstrak — cache yang mempercepat but stesen berulang     |
| `rigs/tls/`                       | Pihak berkuasa sijil domain dev untuk HTTPS stesen (kunci `0600`)                |
| `rigs/run/<rigId>/`               | Tindanan QEMU, imej benih dan kunci setiap VM (`0600`)                           |
