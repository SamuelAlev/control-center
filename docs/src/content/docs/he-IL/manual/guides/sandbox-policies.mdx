האם הרצת סוכן פועלת בארגז חול נקבע בשרת, באתחול
(`--sandbox`). המתג **הפעלת ארגז חול**, בורר **בקאנד** והמתגים
**יכולות ברירת מחדל · מרחבים חדשים** תחת **הגדרות → שרת →
אבחון ופרטיות** הם העדפות הנשמרות במכשיר שלכם. זיהוי המארח בכרטיס
**ארגז חול** מדווח מה מארח השרת יכול לעטוף.

שני אמצעי בקרה מגיעים אל ההרצה, והמדריך הזה מכסה את שניהם: **הרשאות
ארגז חול** ברמת הסוכן שלהלן, והדגל `--sandbox` של השרת עצמו.

## מה מגביל הרצת סוכן

שישה דברים מגבילים סוכן. הראשון הוא ארגז החול של מערכת ההפעלה, והוא היחיד
שהוא מותנה — החמישה האחרים מחזיקים בכל מארח.

| גבול | מה הוא עושה |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ארגז החול של מערכת ההפעלה | Seatbelt ב-macOS, bubblewrap ב-Linux וב-WSL2. עוטף את ה-CLI של Claude Code, את מתאמי ACP ואת כלי ה-`bash` של מנגנון ההרצה. **נעדר ב-Windows וב-Linux ללא `bwrap` ו-`socat`** |
| עץ העבודה הפרטי שלו | כל שיחה מקבלת צ׳קאאוט בהעתקה בעת כתיבה. הצ׳קאאוט המקורי מקופל לתוך ההרצה כנתיב דחיית כתיבה, וארגז החול הוא מה שאוכף זאת |
| פרטי גישה דרך ה-broker | broker פרטי הגישה מנפיק סביבה לכל הרצה מתוך היכולות של הסוכן ומבטל אותה כשההרצה מתפרקת. אין יכולת — אין אסימון בסביבה |
| מעקות הבטיחות של הפעולות | כל כלי משנה־מצב מצהיר על מחלקות ההשפעה שלו, ומנוע ההכרעה מכריע בהן לפני שהקריאה רצה. `prompt` בלי מאשר מחובר נדחה |
| חיטוי הסביבה | ACP וכלי ה-`bash` של מנגנון ההרצה מקבלים סביבה מסוננת. Claude Code דרך `NoSandboxAdapter` יורש את סביבת המארח |
| משטח הכלים של המצב | מצב לקריאה בלבד מסיר את כלי שינוי עץ העבודה כליל ומצמיד את פועל הפלט של המצב עצמו כדי שיוכל עדיין לספק תוצר |

שלושה דברים נשארים חלשים מכפי שהם נראים:

- רק **מנגנון ההרצה המובנה** אוכף את שער הכלים, חוזי ההשלמה וכללי המצב
  המבניים. מתאם Claude Code אינו עושה זאת. Claude
  Code בפרט מופעל עם `--dangerously-skip-permissions`, משום
  ש-`claude -p` לא אינטראקטיבי היה אחרת נתקע לנצח בבקשת ההרשאה של עצמו —
  כך שקריאות הקריאה, הכתיבה, העריכה וה-bash של Claude עצמו אינן נראות ואינן
  מגודרות בידי Control Center. במקום שארגז החול פועל, הוא הגבול סביבן.
- כלי הקבצים בתהליך של מנגנון ההרצה (read, write, edit, apply patch, search,
  find, search_files) רצים בתוך תהליך השרת, ולכן אף פרופיל של ארגז חול אינו מגביל אותם.
  רק כלי ה-`bash` עובר דרך מריץ הפקודות העטוף בארגז חול. הכלים האלה
  מתוחמים בידי ריתוק הנתיבים שלהם בתוספת מעקות הבטיחות של הפעולות.
- במארח בלי בקאנד השורה הראשונה אינה חלה כלל. ACP וכלי
  ה-`bash` של מנגנון ההרצה נופלים חזרה לחיטוי הסביבה בתוספת מדיניות
  הפקודות; Claude Code יורש את סביבת המארח דרך `NoSandboxAdapter`.
  השרת אומר זאת ביומן האתחול שלו. בדקו את שלכם להלן.

## הגדרת היכולות של סוכן

זהו אמצעי הבקרה היחיד על יכולות שהשרת קורא. הוא לכל סוכן, והוא
קובע מה broker פרטי הגישה מכניס לסביבה של אותו סוכן.

1. עברו אל **הגדרות → סביבת עבודה → סוכנים**
2. בחרו את הסוכן ברשימה
3. בלשונית **הגדרות**, גללו אל **הרשאות ארגז חול**
4. הדליקו את המתג — הכיתוב בשורה משתנה מ**שימוש בברירת המחדל של סביבת העבודה**
5. הגדירו את ארבעת המתגים:

| מתג | על מה הוא שולט |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **אפשר git push** | כשהוא כבוי, ההרצה מקבלת `GIT_ASKPASS=/usr/bin/false` ו-`GIT_TERMINAL_PROMPT=0`, כך שדחיפה אינה יכולה לבקש פרטי גישה |
| **אפשר קריאות ל־API של GitHub** | יחד עם **אפשר git push**, שולט בשאלה אם ה-broker מזריק את אסימון GitHub בתור `GH_TOKEN` / `GITHUB_TOKEN` |
| **התרת קריאות API של ניהול כרטיסים** | שולט בשאלה אם ה-broker מזריק `TICKETING_API_KEY` |
| **אפשר גישה כללית לרשת** | במקום שארגז החול פועל זהו שער יציאה אמיתי: כשהוא כבוי רשימת ההיתר של ההרצה ריקה וכל בקשה יוצאת נדחית ב-proxy. במקום שאין בקאנד, הוא נרשם על ההרצה אך אינו חוסם דבר שמבצע תהליך בן |

6. שמרו

נקודת ביקורת: פתחו מחדש את הסוכן והמתג עדיין דלוק עם המתגים שהגדרתם — ערכת
יכולות שמורה עוברת הלוך ושוב דרך השרת, וסוכן בלי אחת נופל חזרה לברירת המחדל
השמרנית (דחיפה כבויה, API של GitHub כבוי, כרטיסים כבויים, רשת דלוקה).

:::caution[שתי דרכים שבהן זה נושך]
הכיתוב אומר **שימוש בברירת המחדל של סביבת העבודה**, אבל אין הגדרת יכולות
ברמת סביבת העבודה שהשרת קורא. סוכן עם המתג כבוי מקבל את ברירת המחדל
השמרנית המובנית.

לחוד מכך, פרטי הגישה של GitHub להרצה הם תמיד של ה-broker בלבד — אסימון התקנה
של GitHub App מוגבל למאגר, או נסיגת ה-PAT מהסביבה — ולעולם לא האסימון
השמור של החבר המבקש עצמו. `actingUserId` מועבר כדי שה-broker יוכל *לעכב* את
ה-PAT של השרת מחבר שאינו הבעלים ולא חיבר את GitHub; הוא אינו ממזג אסימון
אישי מעל יכולת שכבויה. אל תתייחסו אל **אפשר קריאות ל־API של GitHub** כאל
גבול יציאה קשיח במארח בלי ארגז חול של מערכת ההפעלה: תהליך בן עדיין יכול
להגיע לרשת.
:::

## בדיקה אם הרצות הסוכן שלכם עטופות בארגז חול

שני דברים מכריעים בכך, ושניהם בשרת: אם המארח מציע בקאנד ואם `--sandbox`
פועל. בדקו אותם בסדר הזה.

1. עברו אל **הגדרות → שרת → אבחון ופרטיות**
2. קראו את כרטיס **ארגז חול**. העובדה **מארח** היא המכונה ש-`cc_server`
   רץ עליה, לא המכונה שאתם מסתכלים עליה. השדה **בקאנד** מפרט
   **ארגז חול מקורי** (Seatbelt ב-macOS, bubblewrap ב-Linux וב-WSL2) או
   **ללא בידוד**. העובדה **בתוקף** היא ההעדפה של המכשיר הזה, לא
   העטיפה שהשרת באמת משתמש בה.
3. קראו את יומן האתחול של השרת. הוא מדפיס בדיוק אחת משלוש שורות:
   - `agent sandbox ON` בתוספת הערת הבקאנד — ההרצות עטופות
   - `no OS-native agent sandbox on this host` בתוספת רמז התקנה במקום שיש
     כזה — ההרצות אינן עטופות
   - `agent sandbox DISABLED by --sandbox off` — ביטול מכוון

`GET /healthz` אינו מדווח על מצב ארגז החול, ולכן יומן האתחול הוא הבדיקה.

כדי לכבות את ארגז החול במכוון — מארח שבו הפרופיל מתנהג שלא כשורה הוא
הסיבה שהוא קיים — הפעילו את השרת עם `--sandbox off`, או הגדירו
`CC_SERVER_SANDBOX=off`. ברירת המחדל היא `on`, ו-`on` משמעו "השתמשו בבקאנד
אם למארח יש כזה", ולעולם לא "דרוש אחד".

שני מצבים לעולם אינם מקבלים עטיפת ארגז חול מקורי. ב-**Windows** בדיקת ארגז
החול המקורי מדווחת תמיד כלא זמינה ואין מה להתקין — שיגור הסוכן
משתמש ב-`none`. הבקאנד `microvm` נפרד (מסופים אינטראקטיביים ותחנות)
והוא תלוי בבדיקה של סביבת הריצה שלו בלבד. ב-**Linux וב-WSL2** גם `bwrap` וגם
`socat` חייבים להיות ב-`PATH`; בלעדיהם הבדיקה מדווחת כלא זמינה
ומציינת את החבילות החסרות.

ב-Linux/WSL2 עם bubblewrap מותקן, אי אפשר לאכוף את תבניות הגלוב של קובצי
הסוד במדיניות התקנית על קבצים שסוכן יוצר אחר כך. הרצה מקורית כזו נכשלת כעת
במקום להתעלם מהכללים בשקט. בדיקת אתחול מוצלחת אינה מבטיחה אפוא ששיגור
ב-Linux יצליח להתחיל. `--sandbox off` הוא ביטול מכוון בלי הגבלה, לא גבול
אבטחה חלופי.

## לדעת למה מצב כבר מסרב

המצב נשמר לפי מרחב ומזין את מנוע מעקות הבטיחות כשכבת **ערכת המצב**. שלושה
מארבעת המצבים הם לקריאה בלבד, ומצב לקריאה בלבד מסרב על הסף לאחת עשרה מחלקות
השפעה:

| מצב | עץ העבודה | מסורב בידי הערכה |
| ------------------ | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **סוכן** (`chat`) | ניתן לכתיבה | דבר לא — ברירות המחדל המובנות חלות |
| **תכנון** | לקריאה בלבד | מחיקת קובץ, כתיבה מחוץ לעץ העבודה, ביצוע קומיט, דחיפה, פתיחת בקשת משיכה, פרסום או מיזוג, כתיבה למערכת מעקב חיצונית, התקנת חבילה, הרצת תהליך, שינוי מבנה סביבת העבודה, הפעלה או שליטה במתחם מבודד |
| **סקירה** | לקריאה בלבד | אותן אחת עשרה. אינו ניתן לבחירה בידי המשתמש — תיבת הכתיבה מציעה רק סוכן, תכנון ותזמור |
| **תזמור** | לקריאה בלבד | אותן אחת עשרה |

גישה לרשת וגישה לסודות אינן נמסרות במכוון בסירוב של מצב לקריאה בלבד: מחקר
הוא כל תכליתו של מצב כזה.

## דרישת אישור לפני שפעולה רצה

אישור הוא החלטה של מעקות בטיחות, לא הגדרה של ארגז חול.

1. עברו אל **הגדרות → סביבת עבודה → הרשאות סוכנים**
2. הגדירו את מחלקת הפעולה ל**שאל קודם** בטווח סביבת העבודה, הסוכן או המרחב

החלטת **שאל קודם** קוטעת את ההרצה ושואלת אתכם. בלי מאשר
מחובר היא נכשלת באופן סגור והפעולה נדחית. ראו
[הגדרת מעקות בטיחות](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/הגדרת-מעקות-בטיחות/) לסדר
ההכרעה המלא.

## פתרון תקלות

### סוכן לא מצליח לדחוף ומעולם לא סירבתי לו

בדקו את **הרשאות ארגז חול** של הסוכן. סוכן בלי ערכת יכולות מותאמת
מקבל את ברירת המחדל השמרנית, שבה **אפשר git push** כבוי — ולכן ה-broker
אינו מזריק אסימון GitHub ול-git אין דרך להזדהות.

### כרטיס ארגז החול מדווח שאין ארגז חול מקורי

אז הרצות סוכן במארח הזה אינן עטופות ב-Seatbelt או ב-bubblewrap, והגבולות
שנותרו הם מה שיש לכם. ב-Linux וב-WSL2 התקינו את שני הכלים החסרים —
`sudo apt-get install bubblewrap socat` — והפעילו מחדש את השרת; יומן האתחול
אמור אז לומר שארגז החול פועל. ב-Windows אין בקאנד מקורי להתקין, ולכן הדקו
במקום זאת את מעקות הבטיחות: ראו
[הגדרת מעקות בטיחות](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/הגדרת-מעקות-בטיחות/).

### סוכן הגיע לקובץ מחוץ לעץ העבודה שלו

הכלי שאיתו הוא הגיע מכריע אם זה צפוי.

כלי הקבצים בתהליך של מנגנון ההרצה (read, write, edit, apply patch, search,
find, search_files) רצים בתהליך השרת, ולכן שום פרופיל של ארגז חול אינו חל עליהם
— הגבול שלהם הוא ריתוק הנתיבים שלהם בתוספת מעקות הבטיחות. פקודת `bash` או
ה-CLI של Claude Code _כן_ עטופים במקום שקיים בקאנד, והצ׳קאאוטים הרשומים
שלכם הם דחיית כתיבה בתוך העטיפה הזו בכל מצב, כולל בצורותיהם
המפוענחות-סימבולית (ב-macOS נתיב שמגיעים אליו דרך `/tmp` או
`/var/folders` נפתר תחת `/private`, ושתי הצורות נדחות כעת). במארח בלי בקאנד
שום דבר מזה אינו חל. כך או כך, מעקות הבטיחות יכולים לסרב
ל**כתיבה מחוץ לעץ העבודה** על הסף.
