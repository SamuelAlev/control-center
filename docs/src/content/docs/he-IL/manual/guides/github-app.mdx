מדריך זה מראה כיצד להעניק לשרת שלכם GitHub App משלו. זה לוקח כשתי דקות, רק בעל
השרת עושה זאת, וזה צריך לקרות פעם אחת בלבד לכל שרת.

:::note[ייתכן שאינכם זקוקים לזה]
כש-Control Center Connect מופעל, אנשים נכנסים ל-GitHub דרך ה-App המשותף של Control
Center, או דרך ה-App שבו משתמש ה-Connect של הארגון שלכם. רשמו App משלכם כשבחרתם
**שימוש באפליקציות שלי**: אפליקציית השרת משמשת רק במקרה הזה. ראו [Control Center Connect](/he-IL/מדריך-למשתמש/עזר/connect/).
:::

לכניסה לחשבון שלכם לאחר מכן, ראו
[הגדרת אינטגרציית GitHub](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/אינטגרציית-github/).

## מה האפליקציה עושה

רישום אחד עונה על שתי משימות שונות:

| משימה | מה עונה עליה | למה זה חשוב |
| --- | --- | --- |
| **אדם נכנס** | מזהה הלקוח וסוד הלקוח של האפליקציה | כל אחד מקבל פרטי גישה משלו ל-GitHub, בשרת, בכל מכשיר |
| **השרת פועל** | מזהה האפליקציה והמפתח הפרטי | סוכנים, פייפליינים, סורקים ותשובות בוט מקבלים אסימונים למאגר אחד בכל פעם |

המשימה השנייה לעולם אינה שואלת את פרטי הגישה של אדם כמות שהם. כל אסימון שהשרת מנפיק
מכסה מאגר אחד ומוגבל למה שחבר אחראי יכול לעשות שם. קריאת מאגר מקושר דורשת רק את
האפליקציה; כל מה שכותב דורש חבר שיכול לדחוף. אוטומציה לעולם אינה מאשרת בקשת משיכה.

אפליקציית השרת חלה רק תחת **שימוש באפליקציות שלי**. עם Control Center או Connect משלכם, Connect מריץ כל נתיב, כולל GitHub; אפליקציית השרת נשמרת אך אינה בשימוש עד שתחזירו את הבחירה. אפליקציה של סביבת העבודה ([אפליקציה אחרת לסביבת עבודה אחת](#אפליקציה-אחרת-לסביבת-עבודה-אחת)) חלה תמיד, בכל מצב. אפליקציה שחסרים בה חלק
מהשדות היא שגיאה, לא נפילה לחלופה: כניסות ל-GitHub נדחות עד שכל שדה מוגדר.

## דרישות מוקדמות

- אתם **בעלי השרת**. הכרטיס **אפליקציות ספק** אינו גלוי לאף אחד אחר
- חשבון GitHub. האפליקציה נוצרת תחתיו
- כתובת שרת שהדפדפן שלכם יכול להגיע אליה. הכתובת הציבורית של השרת (או loopback, עבור
  השרת של שולחן העבודה עצמו) היא המקום שאליו GitHub מחזירה אתכם

## יצירה בלחיצה אחת

1. עברו אל **הגדרות ← שרת ← כניסה מאוחדת** וגללו אל הכרטיס **אפליקציות ספק**
2. בבלוק **GitHub**, הקלידו אם תרצו את ארגון ה-GitHub שאמור להחזיק באפליקציה
   ב**ארגון (אופציונלי)**. השאירו ריק כדי ליצור את האפליקציה תחת החשבון שלכם; יצירה
   תחת ארגון דורשת בעלים של אותו ארגון
3. לחצו על **יצירת אפליקציית GitHub שלי**
4. הדפדפן שלכם פותח את GitHub כשהאפליקציה כבר ממולאת. לחצו על **Create GitHub App**
5. GitHub מחזירה אתכם לשרת, שמאחסן את מזהה האפליקציה, המפתח הפרטי, מזהה הלקוח וסוד
   הלקוח, ואז פותח את דף ההתקנה של האפליקציה

שום דבר אינו מועתק ידנית, וקוד ההמרה עובר ישירות מ-GitHub לשרת שלכם. הקישור עובד פעם
אחת ופג אחרי עשר דקות; אם פג, לחצו שוב על **יצירת אפליקציית GitHub שלי**.

שם האפליקציה הוא `Control Center <code>`, והיא מבקשת בדיוק את מה ש-Control Center
משתמש בו:

| הרשאה | גישה |
| --- | --- |
| Metadata | קריאה |
| Contents | קריאה וכתיבה |
| Pull requests | קריאה וכתיבה |
| Issues | קריאה וכתיבה |
| Checks, Actions, Commit statuses | קריאה |
| Organization members | קריאה |

ה-webhooks כבויים: השרת סורק. כדי להעביר אפליקציה שיצרתם תחת החשבון שלכם לארגון
בהמשך, השתמשו ב-**Transfer ownership** בהגדרות המתקדמות של האפליקציה ב-GitHub.

נקודת ביקורת: בבלוק GitHub כתוב "השרת יכול לפעול בשם עצמו, ואנשים יכולים להיכנס.".

## התקנה במקום שבו נמצאים המאגרים שלכם

אפליקציה שנרשמה אך לא הותקנה יכולה להכניס אנשים ואינה קוראת דבר.

1. בחרו את החשבון או הארגון שמחזיקים במאגרים שלכם בדף ההתקנה ש-GitHub פתחה
2. בחרו **All repositories**, או בחרו את המאגרים שהשרת הזה אמור לראות

כדי להתקין אותה בחשבון אחר בהמשך, מנהל סביבת עבודה עובר אל **הגדרות ← סביבת עבודה ←
כללי**, מוצא את **התקנות של אפליקציית GitHub** בכרטיס זהות GitHub ולוחץ על **התקנת
אפליקציית GitHub**. הרשימה מציגה כל חשבון שהאפליקציה מותקנת בו ומסמנת התקנה מושעית.

## אישור השרת הזה עבור ארגון

ב-App המשותף של Control Center, התקנה של ארגון משרתת רק את השרתים שהמנהלים שלו אישרו.
התקנה דרך **התקנת אפליקציית GitHub** מאשרת את השרת שהתחיל אותה. עבור התקנה שכבר
קיימת:

1. מנהל של אותו ארגון נכנס ל-GitHub בשרת הזה
2. הוא פותח את **הגדרות ← סביבת עבודה ← כללי ← התקנות של אפליקציית GitHub**
3. בשורה של הארגון כתוב **לא מורשית**. הוא לוחץ על **אישור השרת הזה**

לאחר מכן כתוב בשורה **מורשית**. אפליקציה משלכם אינה צריכה שום דבר מזה: כל התקנה שלה
שייכת לשרת שלכם.

## או רישום ידני

הכרטיס **אפליקציות ספק** מקבל גם את הערכים ישירות, עבור אפליקציה שרשמתם בעצמכם:

| קבוצה | שדות |
| --- | --- |
| **פעולה בשם השרת** | **מזהה אפליקציה**, ו**מפתח פרטי** (כל קובץ ה-`.pem`, כולל השורות `BEGIN` ו-`END`) |
| **כניסת אנשים** | **מזהה לקוח** ו**סוד לקוח**. **כתובות URL לקריאה חוזרת** מציג את הכתובת לרישום, כלשונה |
| **שיחות בבקשות משיכה** | **שם המשתמש של הבוט**, שנפתר כשבודקים את החיבור |

רשמו את כתובת ה-callback ‏`<server origin>/oauth/github/callback` בדיוק כפי שהכרטיס
מציג אותה, השאירו את **Expire user authorization tokens** מופעל, והעניקו את ההרשאות
שבטבלה שלמעלה. לחצו על **בדוק**: הוא שואל את GitHub באילו חשבונות האפליקציה מותקנת,
כך ש"נשמר" ו"עובד" לא מתבלבלים.

## הגדרה מקובץ ה-`.env` של השרת

בהתקנה ללא ממשק או בהתקנה מתוסרטת, השרת זורע כל שדה מקובץ ה-`.env` שלו בפעם הראשונה
שאין לו ערך שמור:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

שימו את המפתח ב**שורה אחת**: ערך ב-`.env` הוא שורה אחת, ו-`\n` בתוך מירכאות כפולות
מפוענח לשורה חדשה. השרת מסרב לעלות כש-`GITHUB_APP_PRIVATE_KEY` או
`GITHUB_CLIENT_SECRET` מיוצאים בסביבת התהליך שלו, שם כל תהליך בן יכול לקרוא אותם;
שמרו אותם בקובץ ה-`.env` (ב-Docker, עגנו אותו ב-`/app/bin/.env`). הזריעה מתבצעת **פעם
אחת לכל שדה**, כך שעריכה בהגדרות אינה מתבטלת בהפעלה מחדש הבאה.

## אפליקציה אחרת לסביבת עבודה אחת

סביבת עבודה יכולה להשתמש באפליקציה משלה במקום זו של השרת. מנהל סביבת עבודה עובר אל
**הגדרות ← סביבת עבודה ← כללי**, בוחר **להשתמש ב-GitHub App אחר** בכרטיס **זהות
GitHub** ומזין את מזהה האפליקציה, המפתח הפרטי, מזהה הלקוח וסוד הלקוח שלה. חברים נכנסים
אז לאותה אפליקציה עבור סביבת העבודה הזו. סביבת עבודה שעובדת על אפליקציה משלה לעולם
אינה נופלת לאפליקציה של השרת או ל-Connect: עד שהשדות שלה שלמים, העבודה שלה ב-GitHub
נדחית.

הכרטיס **אפליקציות ספק** באותו עמוד עושה אותו דבר עבור Google Calendar, Linear וחיפוש GIF. ראו [הענקת לסביבת עבודה אפליקציית Linear משלה](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/אינטגרציית-linear/#הענקת-לסביבת-עבודה-אפליקציית-linear-משלה) ו[הענקת לסביבת עבודה לקוח Google משלה](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/חיבור-לוח-שנה/#הענקת-לסביבת-עבודה-לקוח-google-משלה).

## פתרון תקלות

### יצירת אפליקציית GitHub שלי אומרת שאין לשרת כתובת

לשרת אין כתובת ציבורית שדפדפן יכול לחזור אליה. הגדירו `CC_SERVER_PUBLIC_URL` (או
`--public-url`) ונסו שוב.

### GitHub אומרת שהקישור פג

הדף החד־פעמי כבר נוצל, או שעברו עשר דקות. התחילו שוב מההגדרות.

### הבדיקה אומרת שפרטי הגישה עובדים אבל האפליקציה אינה מותקנת בשום מקום

רישום והתקנה הם שלבים נפרדים. פתחו את דף ההתקנה של האפליקציה, או השתמשו ב**התקנת
אפליקציית GitHub** בסביבת עבודה ← כללי.

### הבדיקה אומרת שלא ניתן היה לקרוא את המפתח הפרטי

הדביקו את כל קובץ ה-`.pem`, כולל השורות `-----BEGIN` ו-`-----END`. אי אפשר להשתמש
במפתח `ed25519` או EC: אפליקציות GitHub חותמות ב-RSA.

### חבר נכנס אבל אינו רואה מאגרים

האפליקציה אינה מותקנת בחשבון שמחזיק בהם, או שההתקנה שלה בוחרת מאגרים אחרים. כניסה
מעניקה רק את מה שהאפליקציה רשאית לראות.

### סוכנים אומרים שההתקנה של ה-GitHub App מושעית

מישהו השעה את ההתקנה ב-GitHub. בטלו את ההשעיה ב-**Settings → Applications →
Installed GitHub Apps** של אותו חשבון.
