מדריך זה מראה כיצד ליצור ולנהל כרטיסים.

## יצירת כרטיס

### מהממשק

1. לחצו על **כרטיסים** בסרגל הצד של סביבת העבודה.
2. לחצו על **כרטיס חדש**.
3. מלאו:
   - **כותרת** — סיכום קצר. זהו השדה היחיד שחובה למלא.
   - **תיאור** — markdown, עם סרגל עיצוב.
   - **סטטוס** — **לביצוע** (ברירת המחדל) או **בקלוג**. מצבים שהתחילו ומצבי
     סיום מושגים דרך מחזור החיים, ולא ביצירה.
   - **עדיפות** — ללא, דחופה, גבוהה, בינונית או נמוכה.
   - **אחראי** — אתם עצמכם או כל סוכן בסביבת העבודה.
   - **פרויקט** — קיבוץ אופציונלי.
4. לחצו על **יצירה**, או הפעילו קודם את **יצירת עוד** כדי להשאיר את תיבת
   הדו-שיח פתוחה להזנה מהירה.

אין בורר ספקים בתיבת הדו-שיח. הכרטיס נוצר מול ספק הכרטיסים הפעיל של סביבת
העבודה.

### מסוכן

בקשו מסוכן במרחב:

> צרו כרטיס לתיקון בעיית פסק הזמן של הכניסה בחיבורים איטיים.

הסוכן קורא לכלי ה-MCP בשם `create_ticket`. העדיפות בכלי הזה היא **מספר שלם**,
לא שם:

```
create_ticket(
  workspace_id: "...",
  title: "Fix login timeout on slow connections",
  description: "...",
  priority: 2
)
```

| ערך  | עדיפות   |
| ---- | -------- |
| `0`  | ללא      |
| `1`  | דחופה    |
| `2`  | גבוהה    |
| `3`  | בינונית  |
| `4`  | נמוכה    |

רק `workspace_id` ו-`title` נדרשים; `description`, `priority`, `assignee`
(מזהה סוכן) ו-`team_id` הם אופציונליים. הכלי מסווג ככתיבת סנכרון של ספק
ומבקש את אישורכם לפני שהוא רץ.

## עדכון סטטוס כרטיס

הכרטיסים מתנהלים לפי מחזור החיים הזה:

```
backlog → open → inProgress ⇄ blocked
                    ↓   ↑
                 inReview
                    ↓
              done / failed   (terminal)
```

`done`, `failed` ו-`cancelled` הם מצבי סיום. אל `cancelled` אפשר להגיע מכל
סטטוס שאינו מצב סיום. אל `done` ו-`failed` אפשר להגיע מ-`inProgress` או
מ-`inReview`; `open` יכול גם לעבור ישירות ל-`blocked`. בורר הסטטוסים בממשק
מציג כל סטטוס מלבד `failed` — סוכנים מסמנים אותו עם `fail_ticket`.

כדי לשנות אותו, השתמשו בכל אחד מאלה:

- השורה **סטטוס** בפס המאפיינים של הכרטיס,
- תת-התפריט **סטטוס** בתפריט הלחיצה הימנית על כרטיס ברשימה,
- הצ'יפ **סטטוס** בסרגל הצף לאחר בחירה מרובה של כרטיסים.

:::note[גרף מחזור החיים מחייב סוכנים, לא אתכם]
כל שינוי סטטוס שנעשה מהממשק נכפה ועובר, כשהוא עוקף את הגרף לחלוטין — אתם
יכולים להעביר כרטיס לכל סטטוס שהבורר מציג, כולל פתיחה מחדש של כרטיס במצב
`done`, `failed` או `cancelled`. הבורר אינו מציע את `failed` כיעד. התרשים
שלמעלה חל על סוכנים ואוטומציה: מעבר לא חוקי שכלי MCP או מנגנון יישור מנסים
לבצע נרשם ביומן ומתעלמים ממנו, ולא מיושם.
:::

שינויי סטטוס פולטים אירועי תחום (`TicketStatusChanged`, `TicketCompleted`
ואחרים) שיכולים להפעיל פייפליינים. ראו
[הגדרת טריגרים לפייפליין](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/טריגרים-לפייפליין/).

## הקצאת כרטיס

1. פתחו את הכרטיס.
2. בפס המאפיינים, הגדירו **אחראי** — אתם עצמכם, חבר אחר בסביבת העבודה,
   או סוכן.

:::caution[הקצאה אינה מפעילה שום עבודה]
הקצאה רושמת בעלות ותו לא. היא אינה יוצרת מרחב, אינה משנה סטטוס ואינה משגרת
סוכן — `TicketAssigned` הוא אות ביקורת טהור בלי משגר מאחוריו. כדי לגרום
לסוכן לעבוד, כתבו לו במרחב (ראו
[צ'אט עם סוכן](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/צאט-עם-סוכן/)).

החריג היחיד: `TicketAssigned` הוא סוג אירוע שאפשר לחווט אליו טריגר של פייפליין,
כך שתבנית משלכם יכולה להגיב להקצאה.
:::

## הוספת תוויות

תוויות מוחלות בבת אחת מהרשימה של הכרטיסים, ולא מכרטיס בודד — לפס
המאפיינים אין פקד תוויות.

1. רחפו מעל שורה ברשימת הכרטיסים וסמנו את תיבת הסימון שלה. סמנו כמה שאתם
   צריכים; הסרגל הצף מופיע ברגע שמשהו נבחר.
2. בסרגל הזה, פתחו את הצ'יפ **תוויות**.
3. בחרו תווית. היא נוספת לכל כרטיס נבחר שחסרה בו; תוויות קיימות לעולם אינן
   נמחקות. **ניקוי תוויות** מסיר את כולן. הבורר מציג תוויות שכבר קיימות על
   כרטיס בסביבת העבודה. סוכנים יכולים להוסיף שם חדש דרך `update_ticket` או
   `tickets.patch`.

## קישור כרטיסים

הקשרים יושבים בלוח **קשרים** בפס המאפיינים, או מאחורי **קישור אל** בתפריט
הלחיצה הימנית של הרשימה.

1. פתחו את הכרטיס ומצאו את הלוח **קשרים**.
2. לחצו על פקד ההוספה שלו ובחרו את הקשר:

| קשר               | משמעות                                     |
| ----------------- | ------------------------------------------ |
| **תת-כרטיס של…**  | הכרטיס האחר הוא ההורה של הכרטיס הזה        |
| **הורה של…**      | הכרטיס האחר הוא ילד של הכרטיס הזה          |
| **חסום על ידי…**  | הכרטיס הזה חסום על ידי האחר                |
| **חוסם את…**      | הכרטיס הזה חוסם את האחר                    |
| **קשור אל…**      | סימטרי, ללא כיוון משתמע                    |
| **כפילות של…**    | הכרטיס הזה מכפיל את האחר                   |

3. בחרו את כרטיס היעד.

**משוכפל על ידי** מופיע בלוח אך לא בבורר — הוא ההופכי של **כפילות של** ונקבע
מהכרטיס האחר. כל קשר ברשימה ניתן ללחיצה כדי לפתוח את הכרטיס המקושר, וניתן
להסרה במעבר עכבר.

קשרי הורה ותת-כרטיס נשמרים על הכרטיס עצמו ולא כשורות קישור, ולכן מחיקת הורה
יורדת בשרשור אל ילדיו (ראו בהמשך), בעוד שקישורי חסימה וקשירה אינם כך.

## הוספת משתפי פעולה

משתפי פעולה הם רשימה על הכרטיס — מי מעורב, ובאיזה תפקיד.

1. פתחו את הכרטיס.
2. לחצו על פקד הוספת האדם בלוח **הוספת משתף פעולה**.
3. בחרו סוכן.

שלושת התפקידים הם **אחראי**, **משתף פעולה** (ברירת המחדל) ו**סוקר**. הבורר
בממשק מציג רק סוכנים בסביבת העבודה ותמיד כותב את תפקיד ברירת המחדל; בני אדם
יכולים להופיע כשורות אך אינם מוצעים בתפריט הזה. כלי ה-MCP בשם
`add_ticket_collaborator` מקבל `role`.

הוספת משתף פעולה כותבת שורה ואינה מפרסמת שום אירוע תחום; היא אינה מקנה גישה
למרחב. כדי להכניס סוכן לשיחה, הוסיפו אותו כמשתתף מכותרת המרחב במקום זאת — ראו
[מרחבים](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/מרחבים/).

## מחיקת כרטיס

השתמשו ב**מחק כרטיס** בתחתית פס המאפיינים, בתפריט הלחיצה הימנית, או
בפעולת המחיקה של הסרגל הצף לאחר בחירה מרובה.

:::caution[המחיקה מקומית בלבד]
כרטיס שהגיע ממערכת ניהול כרטיסים חיצונית אינו נמחק שם — אין ספק שתומך בכך —
ולכן הוא יכול להופיע שוב בסנכרון הבא. המחיקה גם יורדת בשרשור: משתפי הפעולה
של הכרטיס וכל כרטיסי הילדים נמחקים איתו.
:::
