מדריך זה מציג כיצד לחבר לקוח MCP חיצוני — Claude Code, עורך, ה-MCP Inspector — לשרת הכלים של Control Center עצמו.

Control Center רושם **110** כלים ומגיש אותם דרך Model Context Protocol בגרסת פרוטוקול `2024-11-05`. משפחות שלמות של כלים שאולי הייתם מצפים להן חסרות: אין כלי פגישות או לוח שנה ואין כלי פרויקטים.

## איתור נקודת הקצה

משטח ה-MCP חולק את המאזין הראשי `cc_server`. אין פורט MCP נפרד.

| נקודת קצה | שיטה    | מטרה                                                      |
| -------- | -------- | -------------------------------------------------------- |
| `/mcp`   | `POST`   | תעבורת Streamable HTTP — זו השפה שלקוח מדבר בה           |
| `/mcp`   | `DELETE` | סיום סשן                                                 |
| `/sse`   | `GET`    | זרם התראות שרת-אל-לקוח                                  |

לכן התקנה מקומית כברירת מחדל נמצאת בכתובת `http://127.0.0.1:9030/mcp`.

1. עברו אל **הגדרות → שרת → שרתי MCP**
2. קראו את הכרטיס **שרת MCP** — הוא מציג פועל או נעצר ואת הפורט שהוא מאזין עליו

המשטח פעיל כברירת מחדל בהתקנה חדשה. רק בעל השרת רואה את האסימון של הכרטיס, ורק הוא יכול להפעיל או לעצור את נקודת הקצה. **הפעל בעת עליית היישום** קובע אם הוא חוזר לאחר הפעלה מחדש; **התחל** / **עצור** הם פקדי סשן שאינם משנים את ההעדפה הזו.

השרת מאזין ב-loopback כברירת מחדל, ולכן נקודת הקצה נגישה רק מהמכונה שבה פועל `cc_server`, אלא אם הפעלתם אותו עם `--bind any`.

## קבלת האסימון

כל בקשה צריכה את אסימון ה-MCP של השרת, מכל מכונה, כולל loopback. השרת יוצר אותו בפעם הראשונה שהוא עולה. אי אפשר לכבות אותו ואי אפשר לנקות אותו.

1. ב-**הגדרות → שרת → שרתי MCP**, מצאו את השורה **אסימון גישה**
2. לחצו על **הצגת אסימון** והעתיקו אותו
3. כדי להחליף אותו, לחצו על **החלפת אסימון**. השרת עובר לאסימון החדש מיד, וכל לקוח שעדיין משתמש בישן נדחה, עד שתמסרו לו את החדש

## חיבור לקוח

כוונו את הלקוח שלכם לנקודת הקצה של Streamable HTTP, ושלחו את האסימון כ-`Authorization: Bearer <token>` בכל בקשה, כולל `GET /sse`. אין דרך אחרת לשלוח אותו: אסימון בכתובת ה-URL אינו מתקבל. צורת התצורה המדויקת היא עניינו של הלקוח שלכם.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code לא יאסוף זאת מקובץ `.mcp.json` של הפרויקט — הוא משער שרתי MCP בהיקף הפרויקט מאחורי בקשת אישור שקריאה לא־אינטראקטיבית של `claude -p` לעולם אינה עונה עליה. העבירו את התצורה במפורש:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

‏`--strict-mcp-config` גורם ל-Claude להשתמש רק בקובץ הזה, כך שאותו שרת לא יתגלה גם מהפרויקט ויירשום פעמיים.

נקודת ביקורת: בקשו מהלקוח לפרט את הכלים שלו. אמורים להופיע ערכי `mcp__*` שמכסים כרטיסים, מרחבים, זיכרון, גרף הקוד וסקירה.

## מה נקודת הקצה דוחה

האסימון פותח כל כלי בשרת, ולכן נקודת הקצה דוחה גם כל דבר שדף ווב יכול היה לשלוח, לפני שהיא בודקת את האסימון:

| בקשה | תשובה |
| ---- | ----- |
| כותרת `Origin` שאינה דף של המכונה הזו (`http://localhost`, `http://127.0.0.1` או `http://[::1]`, בכל פורט) | `403`, "Cross-origin requests are not accepted" |
| כותרת `Host` שאינה כתובת ה-loopback של המאזין הזה ופורטו, ואינה שם המארח הציבורי של השרת | `403`, "Unknown host" |
| `POST` שגופו אינו `application/json` | `415` |
| בלי אסימון, או עם אסימון שגוי | `401` |

כדי לשרת MCP מעבר למארח, הפעילו את השרת עם `--bind any` ושלחו את האסימון ממכונה אחרת, כשאתם פונים לשרת לפי שם המארח הציבורי שלו.

## תיחום כל קריאה לסביבת עבודה

כל כלי שנוגע בנתונים בהיקף סביבת עבודה מחייב `workspace_id`, וקריאה בלעדיו נדחית במקום שתיפתר מול איזו סביבת עבודה "נוכחית":

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

המזהה הוא זה שמופיע בכתובת הדפדפן או היישום שלכם: `/workspaces/<workspace_id>/…`. הפטורים היחידים הם כלים שבאמת פורשים על פני סביבות עבודה, כמו `list_workspaces` וכלי עדכוני החדשות — עדכוני החדשות הם לפי משתמש ולסוכן אין משתמש משל עצמו, ולכן הכלים האלה פועלים על הפידים של בעל השרת.

כלים בהיקף מאגר בודקים בנוסף שהמאגר מקושר לאותה סביבת עבודה.

## מה המשטח יסרב

- **שער לפי מצב.** קריאה נפתרת מול המצב של המרחב של הסוכן הקורא, בצד השרת. סוכן במצב לקריאה בלבד אינו יכול להגיע לכלי כתיבה בהשמטת `space_id` — המצב נשלף מהריצה הפעילה שלו במקום.
- **מעקות בטיחות לפעולות.** כלים משנה־מצב מצהירים על מחלקות ההשפעה שלהם ועוברים דרך אותה מדיניות ששאר המוצר משתמש בה. ראו
  [הגדרת מעקות בטיחות](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/הגדרת-מעקות-בטיחות/).
- **אישור.** חלק מהכלים ההרסניים בונים מטען אישור שיש לאשר לפני שהקריאה ממשיכה.

הקטלוג המלא מפורסם ב-`tools/list` בלי שער גילוי — לקוח MCP חיצוני מסרב לקרוא לכלי שאינו ברשימה שבמטמון שלו, כך שהסתרת כלים שוברת אותם במקום לסדר אותם.

## שרתי MCP אישיים נשארים של הבעלים

דף זה עוסק בנקודת הקצה של Control Center עצמה. הכיוון השני, שרתי MCP ש-Control Center מעביר לסוכנים שהוא מריץ, מופיע תחת **הגדרות → שרת → שרתי MCP → שרתי MCP חיצוניים**. שרתים שמוגדרים על מכונת השרת עבור Claude, Codex, Cursor, Gemini, VS Code, Windsurf, OpenCode או ב-`.mcp.json` נמצאים שם אוטומטית.

השרתים שהתגלו מגיעים מתצורת הכלים של משתמש השרת עצמו ופועלים בזהותו ובפרטי הגישה שלו, ולכן הם שייכים לבעל השרת:

- הם זמינים רק בתוך הרצות של ההרנס המובנה שבעל השרת מפעיל או אחראי להן, כולל אוטומציה בסביבת עבודה שהבעלים אחראי לה.
- הרצה של חבר, אוטומציה שקשורה לחבר, וכל הרצה על שרת בלי בעלים רשום לא מקבלים אף אחד מהם. שם הכלים אינם מופיעים, אי אפשר לקרוא להם, והם אינם מופיעים בחיפוש כלים.
- נקודת הקצה הזו לעולם אינה מציגה, מפעילה או מחפשת אותם, לאף אחד, גם לא עם האסימון של הבעלים, והיא אינה מעבירה הלאה את המשאבים או הפרומפטים שלהם. לכן גם סוכן CLI שמתחבר ל-Control Center דרך MCP, כמו Claude Code, אינו מקבל אותם דרך Control Center; הוא משתמש בתצורה שלו.

שרתי MCP שמוגדרים לסביבת העבודה אינם מושפעים מכל זה בכלל.

## פתרון תקלות

### הלקוח אינו רואה כלים

- בדקו שכרטיס **שרת MCP** מראה פועל
- בדקו שהפורט תואם לפורט של `cc_server` שלכם
- ב-Claude Code, בדקו שהעברתם `--mcp-config` ו-`--strict-mcp-config`

### שגיאת 401 Unauthorized

הבקשה לא נשאה אסימון, או שנשאה אסימון ישן. העתיקו את האסימון הנוכחי משורת **אסימון גישה** ושלחו אותו כ-`Authorization: Bearer <token>`. אסימון בכתובת ה-URL מתעלמים ממנו.

### שגיאת 403 מלקוח שעבד בעבר

הבקשה נשאה `Origin` מדף ווב, או `Host` שהשרת אינו מגיב לו. פנו לנקודת הקצה מלקוח ולא מדף דפדפן, לפי כתובת ה-loopback של השרת או שם המארח הציבורי שלו.

### שגיאת 415 Unsupported Media Type

שלחו גופי `POST /mcp` כ-`application/json`.

### קריאת כלי נכשלת עם "Missing or invalid argument: workspace_id"

הוסיפו `workspace_id`. אין סביבת עבודה משתמעת.
