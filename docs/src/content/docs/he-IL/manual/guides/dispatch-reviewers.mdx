המדריך הזה מראה לכם איך לשלוח סוכני סקירה כדי שיסקרו בקשות משיכה.

## מתצוגת ה-PR

1. פתחו את ה-PR ועברו ללשונית **סקירה כללית** שלו
2. פתחו את תפריט ה-⋯ ובחרו ב**שאל את ה־AI**

זה מפעיל את הפייפליין המובנה מראש `pr_review`, שפותח את מרחב הסקירה של ה-PR
ומפזר את הסוקרים לפי רמת הסקירה של סביבת העבודה — שלושה כברירת מחדל (הסוכנים
המובנים מראש **qa**, **architect** ו-**engineer**) — ואז נותן לסוכן המוביל לאחד.
במסלול הזה אתם לא בוחרים את התפקידים. כדי לשלוט אילו תפקידים רצים ואילו קבצים
כל אחד מהם בודק, השתמשו בכלי ה-MCP או בשלב פייפליין שלמטה.

## דרך כלי ה-MCP ‏`dispatch_reviewers`

קראו לו מתוך מרחב סקירה קיים:

```
dispatch_reviewers(
  space_id: "...",
  workspace_id: "...",
  reviewers: [
    {role: "reviewer"},
    {role: "security", scope: "src/auth/**"}
  ]
)
```

‏`space_id`, `workspace_id` ו-`reviewers` כולם חובה. כל מפרט סוקר מקבל `role`
ולצדו `scope` אופציונלי מסוג glob לקבצים, ו-`prompt_override` שמחליף את תדריך
ברירת המחדל. `concurrency` אופציונלי (1–8) מגביל את מספר השליחות המקבילות; כשהוא
מושמט, חלה ההגדרה `review_concurrency` של סביבת העבודה (ברירת מחדל 3, נקבעת
ב**הגדרות ← סביבת עבודה ← כללי**).

הכלי חוזר מיד עם הרשימות `dispatched` ו-`unmatched`. כל סוקר שנשלח מתווסף למרחב
כמשתתף, מוכרז בהודעת מערכת ונשלח עם התדריך שלו. הממצאים נוחתים במרחב הזה
כהודעות `review_node`.

## משלב פייפליין

פתחו את **הגדרות ← סביבת עבודה ← תבניות פייפליין**, פתחו תבנית, ואז:

1. הוסיפו צומת **Reviewer (prompt)** מהפלטה
2. בחרו את הסוכן לשליחה וכתבו את הנחיית הסוקר, עם מצייני מקום `{{key}}` לפלטים
   שבמעלה הזרם (למשל `{{repo_local_path}}`, `{{pr_number}}`)
3. קבעו את מפתח הפלט (ברירת מחדל `reviewer_findings`) כדי ששלבים במורד הזרם
   יוכלו לקרוא את הממצאים

השלב שולח את הסוכן ומושהה עד שההרצה הזו מסתיימת. המנוע אחר כך אוסף את מטען
ה-`submit_output` של ההרצה אל מצב הפייפליין תחת מפתח הפלט של הצומת. (תיאור
הפלטה עדיין אומר שהשלב ממתין לקריאה ל-`complete_task` — כלי כזה אינו קיים;
התעלמו מהמחרוזת.)

פזרו על ידי חיווט כמה צמתי סוקר לאותו שלב במעלה הזרם, ואז אחדו את הפלטים שלהם
בצומת **Consolidate (join)**.

העורך מחווט מחדש את הטרמינל המוסתר לכל יעד נגיש, כך שצומת שתוסיפו אחרי ה-**Step**
המובנה מראש עדיין רץ. צומתי פיזור המחווטים לאותו שלב במעלה הזרם רצים במקביל.

## שליחה אוטומטית עם PR חדש

כדי שפייפליין סקירה יופעל מעצמו:

1. פתחו את התבנית ב**הגדרות ← סביבת עבודה ← תבניות פייפליין**
2. גררו **PR פורסם** או **PR חיצוני נפתח** מהמקטע **טריגרים** בספריית הצמתים אל
   הקנבס (או בחרו אותו מאריח הרפאים **הוספת טריגר**)
3. בחרו את הצומת החדש והדליקו את **מופעל** בחלונית הפרטים שלו, ואז הפעילו את
   התבנית

שני אירועים חשובים כאן והם אינם ניתנים להחלפה:

| אירוע                  | מופעל כאשר                                                                                                        | מפתחות המטען                                                       |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `PullRequestPublished` | PR נפתח **דרך Control Center** — משטח יצירת ה-PR, או סוכן שקורא ל-`pr_lifecycle.publish`                          | `pr_id`, `workspace_id`, `repo_owner`, `repo_name`                 |
| `ExternalPrDetected`   | שירות סקר בקשות המשיכה מוצא PR שנפתח ישירות ב-GitHub                                                              | `repo_owner`, `repo_name`, `pr_number`, `pr_title`, `author`       |

PR שנפתח ב-github.com לעולם לא מרים `PullRequestPublished`, כך שתבנית שמחווטת רק
לאירוע הזה לא תראה אותו. שימו לב גם ש-`PullRequestPublished` לא נושא `pr_number` —
שלב שהסקריפט או ההנחיה שלו מפנים ל-`{{pr_number}}` חייב להיות מוזן
מ-`ExternalPrDetected`, או מהרצה ידנית שמספקת אותו.

נקודת ביקורת: אחרי ההפעלה, פתחו את **פייפליינים** וודאו שמופיעה הרצה עבור ה-PR
התואם הבא. תבנית שנשארת מושבתת גורמת לטריגר שלה לירות אל תוך כלום — המנוע דוחה
תבנית מושבתת וחוזר בלי להתחיל הרצה.

## איך תפקיד משויך לסוכן

‏`dispatch_reviewers` נותן ניקוד לכל סוכן בסביבת העבודה מול כל תווית תפקיד
מבוקשת, בלי הבחנה בין אותיות גדולות לקטנות:

| התאמה                              | ניקוד |
| ---------------------------------- | ----- |
| מיומנות שמכילה את תווית התפקיד     | +3    |
| כותרת הסוכן שמכילה את תווית התפקיד | +2    |
| שם הסוכן שמכיל את תווית התפקיד     | +1    |

הניקוד מצטבר והסכום הגבוה ביותר מנצח (במקרה של תיקו, המועמד הראשון שנמצא). אם אף
מועמד לא מקבל ניקוד מעל אפס, המפרט חוזר ברשימת ה-`unmatched` של הכלי במקום
להישלח — כך שתפקיד שאיש אינו מתאים לו מדווח, ואף פעם לא מדולג בשקט.

## מרחב הסקירה

ל-PR יש **מרחב סקירה אחד** בדיוק, ולא אחד לכל סוקר. הוא נוצר באופן אידמפוטנטי על
ידי `pr.ensureSpace`, מקושר ל-PR דרך `ReviewSpaceAssociation` ומוכן מול ה-head ref
של ה-PR. כל סוקר שנשלח מצטרף למרחב הזה ומפרסם בו את ממצאי ה-`review_node` שלו —
וזה מה שהופך את הממצאים לברי־השוואה ומאפשר לסוכן המוביל להגיע לקונצנזוס ביניהם.

## מעקב אחר השליחה

כל סוקר שנשלח מקבל `AgentRunLog` משלו. עקבו אחר ההתקדמות ב:

- **מרחב הסקירה**, שבו הממצאים זורמים בזמן אמת
- לשונית **סקירה** של ה-PR, שמציגה את שורת המצב של הסקירה ואת ההכרעה
- **ניטור ← בזמן אמת** (`/workspaces/:id/observability`), רשימת הסוכנים עם סטטוס
  לכל הרצה, זמן שחלף בזמן אמת, מגירת תמליל ופקד עצירה. אין קיצור מקלדת לכך —
  הגיעו אליו מתחתית סרגל הצד.
