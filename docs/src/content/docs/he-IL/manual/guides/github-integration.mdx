המדריך הזה מכסה את החלקים הספציפיים ל-GitHub בהגדרה. GitHub הוא אחד משלושה
מארחי קוד נתמכים. ראו [חיבור מארח קוד](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/חיבור-מארח-קוד/)
לחיבור GitLab או Bitbucket, ולמידע על איך סביבת עבודה משלבת ביניהם.

## דרישות מוקדמות

- חשבון GitHub עם גישה למאגרים שעליהם תרצו לעבוד
- שרת שיכול להכניס אנשים ל-GitHub: או GitHub App משלו (ראו
  [יצירת GitHub App](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/github-app/)) או Control Center
  Connect, לפי בחירת בעלי השרת ב**הגדרות ← שרת ← כניסה מאוחדת**

:::note[פרטי הגישה יושבים בשרת ומצורפים אליכם]
דבר אינו נשמר במחשב שאתם מקלידים בו. הכניסה שלכם ל-GitHub מוחזקת ב-`cc_server`
שלכם, לפי מזהה המשתמש שלכם, וכל מכשיר שממנו אתם נכנסים משתמש בה: שולחן העבודה,
הווב והטלפון. חבר אחר באותו שרת לא יכול להשתמש בה, וכניסה שלהם היא משהו שהם עושים
בעצמם.
:::

## כניסה ל-GitHub

‏GitHub הוא כניסה בלבד: אין אסימון להדביק.

1. עברו אל **הגדרות ← אישי ← פרופיל ← אחסון קוד** (או לשלב הראשון
   של ההצטרפות)
2. בשורה של **GitHub**, לחצו על **כניסה ל-GitHub**
3. הדפדפן שלכם פותח את GitHub. אשרו את האפליקציה

אופן סיום הכניסה תלוי במי שמפעיל אותה:

- **האפליקציה של השרת עצמו:** GitHub מחזירה את הדפדפן שלכם לשרת, וחלון הדו-שיח
  מבחין בכך מעצמו. אין מה להקליד
- **Control Center Connect:** דף הדפדפן מציג קוד בן 8 תווים. הקלידו אותו בחלון
  הדו-שיח, או תנו לדפדפן לפתוח את Control Center דרך הקישור `control-center://`
  ודלגו על ההקלדה

נקודת ביקורת: השורה **GitHub** מציגה "מחובר בתור _your-username_".

חלון הדו-שיח דוחה קוד או קישור שהוא לא התחיל בעצמו, עם **הכניסה לא התחילה כאן**.
אם מישהו שולח לכם קישור כניסה, אל תמשיכו: השלמתו תחבר את החשבון שלכם לשרת שלו.

לחצו על **ניתוק** כדי להסיר את הכניסה שלכם. יציאה מ-GitHub, או הסרה מסביבת עבודה,
מבטלות גם כל אסימון שהשרת הנפיק בשמכם.

## בשם מי פרטי הגישה שלכם מדברים

Control Center עוקב אחרי ההפרדה של GitHub בין פעולה **בשם אדם** לבין פעולה **בשם האפליקציה**:

| מה קורה | מופיע ב-GitHub בתור |
| --- | --- |
| כל מה שאתם עושים בעצמכם: תגובה, סקירה, אישור, מיזוג, בקשת סוקרים | **אתם**. GitHub מסמן תגובה בשיחה כתגובה שנכתבה עם אפליקציית Control Center; לסקירה ולהערות המוטבעות שלה אין סימון כזה |
| סקירה באמצעות AI, תשובות ותגובות של סוכנים בשיחות PR, תוויות, עבודת פייפליין ובוט | **הבוט של Control Center**. באפליקציה המשותפת של Connect, סקירה היא של הבוט רק להתקנה שמפעיל Connect רשם; אחרת היא מופיעה בשם האדם האחראי |
| בקשת משיכה שסוכן פותח עבורכם, עריכות הכותרת או התיאור שלה, הדחיפות שלה והקומיטים שלה | **אתם**. Control Center מופיע כשותף לכתיבה כשקרדיט כותב משותף פעיל |
| עבודה שאיש לא ביקש (תזמונים, webhooks) | **הבוט של Control Center**, גם כמחבר הקומיטים שלו. ב-Control Center Connect הוא לעולם אינו דוחף ואינו פותח בקשת משיכה |

- **כל מה שאתם עושים** רץ על **הכניסה שלכם** ועל שום דבר אחר. אם לא נכנסתם, האפליקציה מבקשת מכם להיכנס. שום פרטי גישה אחרים אינם מחליפים אתכם
- **עבודת הבוט** מקבלת אסימון למאגר אחד בכל פעם, מוגבל למה שחבר אחראי יכול לעשות שם: החבר שביקש, ואחרת בעלי סביבת העבודה. חבר שאינו יכול לדחוף מגביל את האסימון לקריאה בלבד. תשובות בוט שפועלות בשם מישהו מתחילות ב-**Control Center (for @login)**
- **סוכנים פותחים בקשות משיכה דרך Control Center**, לעולם לא מתוך ארגז החול שלהם, כך שבקשת המשיכה שייכת לכם וכללי GitHub עצמם מונעים מכם לאשר אותה. Control Center דוחה גם אישור מהאדם שביקש מהסוכן את העבודה, ומהמחבר של בקשת המשיכה. בהרצה מתוזמנת או של webhook, זה חל על כל מנהל שהפעיל את הטריגר שלה או ערך את הפייפליין שלה בזמן שהיה פעיל. אדם אחר חייב לסקור. אם Control Center אינו יכול לאשר מי פתח את בקשת המשיכה, או איזה חשבון ב-forge הוא שלכם, הוא דוחה ומבקש שתנסו שוב
- **סוכנים מגיבים גם הם דרך Control Center.** לאסימון GitHub שמקבלת הרצת סוכן יש הרשאת קריאה בלבד. כשסוכן מגיב בבקשת המשיכה שעליה הוא עובד, Control Center מפרסם את התגובה כבוט, ומתחילה ב-**Control Center (for @login)** כשמישהו ביקש את הריצה. סוכן יכול להגיב רק בבקשת המשיכה שלו: כזו במאגר הזה, לא fork, ושהקומיט האחרון שלה נדחף על ידי הסוכן או הוא הקומיט הנוכחי של ענף המרחב שלו. אזכורי @ בתגובת סוכן אינם שולחים התראה לאיש. סוכן יכול גם לשנות את הכותרת או התיאור של בקשת המשיכה שלו בזמן שהיא פתוחה. העריכה נעשית באותו אופן שבו נפתחה בקשת המשיכה (בשמכם, כשביקשתם את הריצה) ודורשת אישור מראש כברירת מחדל. תיאור בקשת המשיכה שומר על אזכורי ה-@ שבו, כשהסוכן פותח אותה וכשהוא עורך אותה, ולכן האנשים שהוא מזכיר מקבלים התראה
- **ב-Control Center Connect, הבוט לעולם אינו דוחף ואינו פותח בקשת משיכה.** דחיפה, יצירת ענף או פתיחת בקשת משיכה שם דורשות אדם שביקש אותן, ופועלות בכניסה של אותו אדם. הרצה מתוזמנת או מ-webhook שמנסה לדחוף נעצרת עם הודעה שמסבירה זאת. כדי לאפשר להרצות ללא השגחה לדחוף, תנו לסביבת העבודה GitHub App משלה ב-**הגדרות**
- **מה הבוט של Connect יכול לעשות.** עם האפליקציה המשותפת של Connect, הבוט מגיב, מוסיף תוויות ומוסיף ריאקציות. הוא מפרסם סקירה (סקירת AI, הערות סקירה, בקשות לסוקרים) רק כש-מפעיל Connect רשם את ההתקנה של השרת הזה. אחרת הסקירה יוצאת בכניסה של האדם האחראי עצמו, ומופיעה בשמו. הבוט לעולם אינו פותח, עורך, סוגר או משנה כותרת של בקשת משיכה, מבטל סקירה, או עורך או מוחק תגובה; אלה דורשים אדם שביקש, עם הכניסה שלו. Connect אינו קושר את ההתקנה של הארגון שלכם לשרת Control Center אחד: כל שרת שבו חבר שיכול לדחוף למאגר נכנס דרך Connect יכול לקבל את אסימון התגובות של הבוט למאגר הזה
- **שרת או סביבת עבודה עם GitHub App משלהם** שומרים על הבוט לכל האמור לעיל, כולל סקירות
- **אוטומציה לעולם אינה מאשרת** בקשת משיכה. אישור הוא מעשה של אדם

כשמקשרים מאגר, Control Center בודק שהחשבון שלכם יכול לראות אותו, ומזהיר כש-GitHub App אינו מותקן בארגון שלו או אינו כולל את המאגר, עם קישור לתיקון. קישור והסרת קישור דורשים מנהל סביבת עבודה, ותיקייה מחוץ לאחסון של סביבת העבודה יכולה להיות מקושרת רק על ידי בעל השרת; ראו [הוספת מאגרים לסביבת עבודה](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/הוספת-מאגרים/).

הקישור עוקב אחרי מזהה ה-GitHub הקבוע של המאגר, כך ששינוי שם או העברה לא דורשים דבר מכם. אם הנתיב מצביע מאוחר יותר על מאגר אחר, Control Center מפסיק לשלוח אליו דבר ומציג הודעה, עד שמנהל סביבת עבודה לוחץ על **קישור מחדש**.

פתיחת הקוד של מאגר (קבצים, שינויים, חיפוש, טרמינל) דורשת גם הענקה שלו בסביבת העבודה וגם כניסה שלכם ל-GitHub שיכולה לקרוא אותו. מנהלי סביבת עבודה כפופים לאותו כלל; רק בעל השרת פטור.

## מה האינטגרציה נותנת לכם

| תכונה                    | אופן הפעולה                                                                                          |
| ------------------------ | ---------------------------------------------------------------------------------------------------- |
| רשימת בקשות משיכה ופרטיהן | ‏GitHub REST API, מהשרת, על הכניסה שלכם                                                              |
| הרצות בדיקות             | ‏GitHub Checks API                                                                                    |
| פרסום סקירות             | שלב שתלוי בפעולת משתמש ומפרסם את הסקירה שלכם בבקשת המשיכה, בשמכם                                     |
| רישום מאגרים             | עותק מקומי מתקבל אם ה־remote בשם `origin` שלו מצביע אל github.com, או אל gitlab.com / bitbucket.org |
| גישת הסוכן ל-GitHub | בתוך הרצה, `git fetch` עובר דרך Control Center, שמביא את המאגרים שההרצה עובדת עליהם באמצעות אסימון לקריאה בלבד שההרצה לעולם אינה מחזיקה. `gh` קורא אותם באמצעות אסימון לקריאה בלבד ש-Control Center מנפיק לפי בקשה ומבטל כשההרצה מסתיימת. דחיפות, בקשות משיכה, עריכות שלהן והגבות עוברות דרך Control Center |
| התראות                   | סריקה בצד השרת של תיבת ההתראות שלכם ב-GitHub מעלה "אוזכרת בבקשת משיכה" ו"התבקשה סקירה"               |
| פרופילים של משתמשים      | כרטיסי פרופיל בריחוף וסינון בקשות משיכה לפי מחבר                                                      |

חלק מהנתיבים משתמשים ב-API של GraphQL במקום ב-REST כשהוא זול יותר: פעילות ענפים
עבור בורר כתיבת בקשות המשיכה, ומצב הסקירה החי שקובע אם התראת "התבקשה סקירה" עדיין
ממתינה.

## שימו לב לתקלות GitHub

שורת הכותרת מציגה תג סטטוס כשספק במצב פגום, ומכסה את GitHub, Claude, OpenAI
ו-Kimi. **הוא מוסתר כשהכול תקין**: הנוכחות שלו מדווחת על תקלה, לא היעדרותה.

לחצו על התג כדי לפתוח חלון צף עם מצב כל ספק וכפתור רענון. הסטטוסים מתרעננים מעצמם
כל שתי דקות.

## דעו כיצד סוכנים פועלים ב-GitHub

- סוכן שעובד בעץ עבודה של GitHub מקבל אסימון לאותו מאגר אחד. הוא יכול לקרוא רק את
  הקוד, הבעיות ובקשות המשיכה; תגובות עוברות דרך Control Center, כמתואר לעיל.
  דחיפות עוברות דרך Control Center, ששואל את הכלל **דחיפה למאגר מרוחק** ואז מעביר
  את הדחיפה עם אסימון כתיבה שהסוכן לעולם אינו מחזיק. ראו
  [הגדרת מדיניות ארגז חול](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/מדיניות-ארגז-חול/)
- עבודה שאתם מתחילים מתבצעת בשמכם. כשאתם מבקשים מסוכן משהו, או מבצעים קומיט ב-IDE, אתם המחברים והמבצעים, בכתובת ש-forge שלכם אימת: כתובת ה-noreply שלכם ב-GitHub מהכניסה ל-GitHub, או ב-GitLab וב-Bitbucket הדואר שהכניסה שלכם שם מדווחת. זהות ה-Git שלכם בסביבת העבודה משמשת רק לקומיט שאתם מבצעים ביד במאגר שבו אף forge אינו מאמת כתובת שלכם. אם לא נכנסתם לאותו forge, הקומיטים של הסוכן הם של הבוט במקום זאת, וההערות של הריצה אומרות זאת
- עבודה שאיש לא ביקש מתבצעת בשם הבוט. ריצה מתוזמנת או של webhook מבצעת קומיטים בשם ה-GitHub App של סביבת העבודה (`<app>[bot]`, עם כתובת ה-noreply שלו), או בשם `Control Center <hi@usectrl.dev>` כשאין GitHub App או שהמאגר נמצא ב-GitLab או ב-Bitbucket
- **לציין את Control Center ככותב משותף** (**הגדרות ← אתה ← קומיטים**) מוסיפה טריילר `Co-Authored-By:` לצד השני: Control Center על הקומיטים שלכם, ועל הקומיטים של הבוט כל אדם שהפעיל את הטריגר שמאחורי הריצה. זה פעיל אלא אם כיבתם את זה. מנהל סביבת עבודה יכול להכריע זאת לכולם עם **קרדיט כותב משותף** ב**הגדרות ← סביבת עבודה ← כללי**; הבחירה שלכם נשמרת אז אך אינה חלה בסביבת העבודה הזו. שורת הייחוס של Claude Code תמיד מושבתת
- קומיטים שלכם יכולים להיות חתומים. תחת **קומיטים מאומתים** ב**הגדרות ← אתה ← קומיטים**, בחרו **יצירת מפתח חתימה** והוסיפו את החלק הציבורי שלו לחשבון ה-GitHub או ה-GitLab שלכם כמפתח חתימה; מאז, הקומיטים של ריצות שביקשתם, וקומיטים שאתם מבצעים ב-IDE, מופיעים כמאומתים. החלק הפרטי נשאר בשרת שלכם, ולכן מי ששולט בשרת הזה יכול לחתום קומיטים בשמכם כל עוד המפתח מופיע בחשבון שלכם; וב-GitHub קומיט שכבר הוצג כמאומת נשאר מאומת גם אחרי שהסרתם את המפתח. ל-Bitbucket אין מפתח חתימה בלבד: אל תוסיפו את המפתח שם, וקומיטים ב-Bitbucket אינם חתומים. קומיטים של הבוט לעולם אינם חתומים
- קומיטים שאתם מבצעים בחלונית **בקרת מקור** של ה-IDE מדלגים על ה-hooks של Git של המאגר, כמו `git commit --no-verify`, והגיט של השרת מתעלם מ-credential helpers, עורכים, כלי diff חיצוניים וחותמים שהמאגר מגדיר: הוא מריץ Git במכונה שלו, בעץ שסוכן או בקשת משיכה יכולים לשנות. ראו [קומיט ודחיפה מבקרת מקור](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/סקירה-ומיזוג-pr/#קומיט-ודחיפה-מבקרת-מקור)
- כל קומיט שסוכן דוחף נבדק קודם, כולל השכבות ש-`stack_publish` דוחף עבור stack. דחיפה ששמה מישהו אחר, מורידה או משאילה קרדיט, מוסיפה שורת חתימה, או אינה חתומה כפי שההגדרות שלכם קובעות, נדחית. קומיטים שאתם דוחפים בעצמכם מה-IDE הם שלכם ואינם נבדקים בדרך זו
- טרמינל שאתם פותחים בתחנה מקבל את הכניסה שלכם, מצומצמת למאגר האחד, כך שדחיפות שם
  הן שלכם
- כשאי אפשר להנפיק אסימון (אף אחראי אינו מחובר, האפליקציה אינה מותקנת אצל הבעלים,
  או שההתקנה מושעית), הפקודה שביקשה אותו מסבירה מדוע. אין פרטי גישה
  חלופיים

## פתרון תקלות

### רשימת בקשות המשיכה ריקה ומופיע בה ש-GitHub אינו מחובר

לא נכנסתם ל-GitHub בשרת הזה. לחצו על **כניסה ל-GitHub** תחת **הגדרות ← אישי ← פרופיל ← אחסון קוד**. מאגרים
ב-forges אחרים אינם מושפעים.

### השורה של GitHub אומרת שהכניסה אינה מוגדרת בשרת הזה

לשרת אין GitHub App משלו וגם לא Connect. בעלי השרת בוחרים אחד מהם ב**הגדרות ← שרת ←
כניסה מאוחדת**: **יצירת אפליקציית GitHub שלי** לוקחת כשתי דקות. ראו
[יצירת GitHub App](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/github-app/).

בסביבת עבודה על אפליקציות משלה, השורה מציינת זאת כשה-GitHub App של סביבת העבודה חסרה
או לא שלמה. מנהל סביבת העבודה משלים אותה בכרטיס **אפליקציית GitHub** תחת **הגדרות ←
סביבת עבודה ← אינטגרציות**; ראו
[הענקת לסביבת עבודה אפליקציה משלה](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/github-app/#הענקת-לסביבת-עבודה-אפליקציה-משלה).

### חלון הדו-שיח אומר שהקוד אינו תואם

הקלידו את הקוד בדיוק כפי שהדפדפן מציג אותו: 8 אותיות וספרות. חמישה קודים שגויים
מסיימים את הכניסה; התחילו אותה מחדש.

### הכניסה אומרת שהאפליקציה אינה מותקנת

ל-GitHub App אין התקנה בחשבון שמחזיק במאגר. מנהל סביבת עבודה מתקין אותה מ**הגדרות ←
סביבת עבודה ← אינטגרציות ← התקנות של אפליקציית GitHub**.

### כולם צריכים להיכנס שוב ל-GitHub

בעלי השרת החליפו את מפתח ה-Connect של השרת, עברו לשרת Connect אחר, או שתיקיית
הנתונים שוחזרה על מכונה אחרת. כניסות דרך Connect קשורות לשרת שיצר אותן.

### הוספת מאגר נדחית

הרישום דורש את שלושת התנאים: הנתיב נמצא בתוך עץ עבודה של git, יש לו remote בשם
`origin`, וה־remote הזה מצביע אל forge נתמך (github.com, gitlab.com או
bitbucket.org). ה-`origin` חייב להיות המאגר שאתם מקשרים, ותיקייה מחוץ לאחסון של סביבת העבודה יכולה להיות מקושרת רק על ידי בעל השרת. ראו
[הוספת מאגרים לסביבת עבודה](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/הוספת-מאגרים/).

### יש לי הענקה אבל GitHub אומר שחשבוני אינו יכול לקרוא אותו

חשבון GitHub שלכם אינו יכול לקרוא את המאגר הזה, ולכן הקוד שלו סגור בפניכם גם עם הענקה בסביבת העבודה. היכנסו ל-GitHub תחת **אחסון קוד**, או בקשו גישה למאגר ב-GitHub.

### "לא הצלחנו לאשר את הגישה שלכם ל־GitHub"

לא ניתן היה להגיע ל-GitHub כדי לבדוק את הגישה שלכם, ולכן Control Center סירב ולא ניחש. נסו שוב בעוד רגע.

### סקירות ב-Connect מופיעות בשמי, לא בשם הבוט

באפליקציה המשותפת של Connect, הבוט מפרסם סקירות רק להתקנות ש-מפעיל Connect רשם. בכל מקום אחר הסקירה יוצאת בכניסה של האדם האחראי עצמו. כדי שהבוט יפרסם סקירות, תנו לסביבת העבודה GitHub App משלה.

### הכול מפסיק לעבוד לזמן מה אחרי שימוש כבד

זהו מנגנון ההגנה של הגבלת הקצב. GitHub מסמן את המגבלה הראשית שלו ב-`403` הנושא
`x-ratelimit-remaining: 0` וזמן איפוס; כשהוא רואה כזה, הלקוח מכשיל בקשות נוספות
באופן מקומי בלי קריאת רשת עד שחלון הזמן חולף, כך שסופת ניסיונות חוזרים אינה יכולה
להעמיק את המגבלה. כשלים חולפים מנוסים מחדש עד שלוש פעמים עם השהיה מעריכית, תוך
כיבוד `retry-after`.
