המדריך הזה מכסה את החלקים הספציפיים ל-GitHub בהגדרה. GitHub הוא אחד משלושה
מארחי קוד נתמכים — ראו [חיבור מארח קוד](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/חיבור-מארח-קוד/)
לחיבור GitLab או Bitbucket, ולמידע על איך סביבת עבודה משלבת ביניהם.

## דרישות מוקדמות

- חשבון GitHub עם גישה למאגרים שעליהם תרצו לעבוד
- או GitHub App רשום לשרת שלכם (ראו
  [יצירת GitHub App](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/github-app/)) כדי שתוכלו **להיכנס**,
  **או** אסימון גישה אישי עם `repo` ו-`read:org` להדבקה

:::note[פרטי הגישה יושבים בשרת ומצורפים אליכם]
דבר אינו נשמר במחשב שאתם מקלידים בו. פרטי הגישה שלכם מוחזקים ב-`cc_server` שלכם,
לפי מזהה המשתמש שלכם, וכל מכשיר שממנו אתם נכנסים משתמש בהם — שולחן העבודה, הווב
והטלפון. חבר אחר באותו שרת לא יכול לקרוא אותם, וכניסה שלהם היא משהו שהם עושים
בעצמם.
:::

## כניסה עם GitHub

**זרימת מכשיר**: GitHub מציג לכם קוד קצר, אתם מאשרים אותו ב-github.com, והשרת
מקבל את פרטי הגישה — בלי כתובת URL ל-callback, בלי פורט, בלי דבר לחשוף. זמין בכל
פעם שלשרת יש מזהה לקוח, שגרסה רשמית כבר מגיעה איתו.

1. עברו אל **הגדרות ← סביבת עבודה ← פרופיל וזהות ← אחסון קוד** (או לשלב הראשון
   של ההצטרפות)
2. בשורה של **GitHub**, לחצו על **כניסה עם GitHub**
3. חלון דו-שיח מציג קוד בן שמונה תווים ופותח את
   [github.com/login/device](https://github.com/login/device) בדפדפן שלכם.
   הקוד כבר נמצא בלוח שלכם
4. הדביקו אותו, אשרו את האפליקציה וחזרו. השורה מתחלפת מעצמה ל
   "מחובר בתור _your-username_"

אפשר לסגור את חלון הדו-שיח בזמן שאתם מסיימים בדפדפן — השרת ממשיך לסרוק עד שהקוד
פג (כ-15 דקות), כך שהכניסה עדיין מתבצעת.

## או הדבקת אסימון

האפשרות החלופית כשבשרת אין אפליקציה, כשהאפליקציה אינה מותקנת בחשבון שאתם צריכים,
או כשאתם פשוט מעדיפים להשתמש ב-PAT.

1. עברו אל **הגדרות ← סביבת עבודה ← פרופיל וזהות ← אחסון קוד**
2. בשורה של **GitHub**, לחצו על **הוספת אסימון גישה**
3. הדביקו אסימון עם `repo` ו-`read:org` (קלאסי) ושמרו. אסימון **עדין** זקוק
   להרשאות **Contents** ו**Pull requests** במאגר (קריאה וכתיבה), ובנוסף
   ל**Checks** ו**Actions** (קריאה).

האסימון נבדק בזמן שהוא נשמר, כך שהשורה יכולה לציין את החשבון שאליו הוא שייך. לחצו
על **ניתוק** כדי להסיר אותו.

נקודת ביקורת: השורה **GitHub** מציגה "מחובר בתור _your-username_". סיומת מציינת את
המקור כשפרטי הגישה שמשיבים אינם שלכם — "דרך האפליקציה של השרת הזה" או "ממשתני
הסביבה".

:::note[סדר הקדימות קבוע]
בקשה שנעשית בשמכם משתמשת בפרטי הגישה **שלכם**, ושום דבר אחר — הסביבה היא פרטי
הגישה של השרת, לא שלכם, ולכן היא לעולם לא מחליפה אתכם. עבודה שאין מאחוריה אדם
(webhooks, סריקת בקשות משיכה, סנכרון כרטיסים) משתמשת בזהות האפליקציה של השרת, אחר
כך בפרטי הגישה של בעלי השרת, ואחר כך בסביבה.
:::

## מה האינטגרציה נותנת לכם

| תכונה                    | אופן הפעולה                                                                                          |
| ------------------------ | ---------------------------------------------------------------------------------------------------- |
| רשימת בקשות משיכה ופרטיהן | ‏GitHub REST API, מהשרת, בזהות האפליקציה או בפרטי הגישה שלכם                                          |
| הרצות בדיקות             | ‏GitHub Checks API                                                                                    |
| פרסום סקירות             | שלב שתלוי בפעולת משתמש ומפרסם את הסקירה שלכם בבקשת המשיכה                                             |
| רישום מאגרים             | עותק מקומי מתקבל אם ה־remote בשם `origin` שלו מצביע אל github.com — או אל gitlab.com / bitbucket.org |
| גישת הסוכן ל-GitHub      | מתווך פרטי הגישה מזריק אסימון לקריאה בלבד בתור `GH_TOKEN` / `GITHUB_TOKEN`; דחיפות עוברות דרך Control Center |
| התראות                   | סריקה בצד השרת של תיבת ההתראות שלכם ב-GitHub מעלה "אוזכרת בבקשת משיכה" ו"התבקשה סקירה"               |
| פרופילים של משתמשים      | כרטיסי פרופיל בריחוף וסינון בקשות משיכה לפי מחבר                                                      |

חלק מהנתיבים משתמשים ב-API של GraphQL במקום ב-REST כשהוא זול יותר — פעילות ענפים
עבור בורר כתיבת בקשות המשיכה, ומצב הסקירה החי שקובע אם התראת "התבקשה סקירה" עדיין
ממתינה.

## שימו לב לתקלות GitHub

שורת הכותרת מציגה תג סטטוס כשספק במצב פגום, ומכסה את GitHub, Claude, OpenAI
ו-Kimi. **הוא מוסתר כשהכול תקין** — הנוכחות שלו מדווחת על תקלה, לא היעדרותה.

לחצו על התג כדי לפתוח חלון צף עם מצב כל ספק וכפתור רענון. הסטטוסים מתרעננים מעצמם
כל שתי דקות.

## דעו כיצד סוכנים פועלים ב-GitHub

- סוכן שעובד בעץ עבודה של GitHub מקבל תמיד אסימון GitHub לקריאה בלבד. דחיפות
  עוברות דרך Control Center, ששואל את הכלל **דחיפה למאגר מרוחק** ואז מעביר את
  הדחיפה עם אסימון כתיבה שהסוכן לעולם אינו מחזיק. ראו
  [הגדרת מדיניות ארגז חול](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/מדיניות-ארגז-חול/)
- קומיטים שסוכן יוצר מיוחסים **לסוכן** — שם התצוגה בתוספת ` (agent)`, בכתובת
  מלאכותית שנגזרת ממזהה הסוכן — ולעולם לא כאדם. מי שביקש מקבל זיכוי בשורת
  `Co-Authored-By`
- כש-GitHub App מוגדר, המתווך מנפיק בכל הפעלה אסימוני התקנה עדינים, מוגבלים
  למאגר ובעלי תוקף של כשעה, במקום למסור אסימון רחב. ההתקנה נגזרת מה**בעלים** של
  המאגר שאליו רצה ההרצה, כך שאפליקציה אחת המותקנת בכמה חשבונות מותאמת נכון לזה
  שההרצה נוגעת בו. בלי אפליקציה, הסוכנים מקבלים את אסימון הסביבה, שאי אפשר לצמצם
  לקריאה בלבד: כלל הדחיפה מחייב אז את `git push`, אבל לא קוד שמשתמש באסימון ישירות
- האסימון הוא תמיד של המתווך, לעולם לא של החבר המבקש. אסימון השרת מעוכב מהרצות
  שפועלות בשם חבר שאינו הבעלים ולא חיבר את GitHub

## פתרון תקלות

### רשימת בקשות המשיכה ריקה ומופיע בה ש-GitHub אינו מחובר

אין לכם פרטי גישה ל-GitHub בשרת הזה. היכנסו או הדביקו אסימון תחת **אחסון קוד**.
מאגרים ב-forges אחרים אינם מושפעים — רק אלה של GitHub אינם תורמים דבר.

### השורה מציעה "הוספת אסימון גישה" אבל לא "כניסה עם GitHub"

לשרת אין מזהה לקוח — וזה המצב הרגיל בבנייה מקוד מקור, מפני שפרטי גישה מוטמעים רק
בגרסאות רשמיות. ראו
[יצירת GitHub App](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/github-app/): זה לוקח כשתי דקות
ורק בעלי השרת צריך לעשות את זה, פעם אחת.

### חלון הכניסה אומר שהספק לא החזיר קוד מכשיר

‏GitHub App קיים אבל תיבת הסימון **Device flow** שלו כבויה. הפעילו אותה בהגדרות
האפליקציה (General → Device flow) ונסו שוב.

### השורה אומרת "דרך האפליקציה של השרת הזה" כשייחלתי לחשבון שלי

לא נכנסתם; מה שאתם רואים זו זהות האפליקציה של השרת שמשיבה. לחצו על **כניסה עם
GitHub** בשורה הזו.

### ‏PAT עדין לא מציג כפתור מיזוג או מצב בדיקות

האסימון זקוק להרשאות **Contents** ו**Pull requests** (קריאה וכתיבה), ובנוסף
ל**Checks** ו**Actions** (קריאה). אחרי שתשנו אותו, הדביקו אותו שוב תחת אחסון קוד.

### הוספת מאגר נדחית

הרישום דורש את שלושת התנאים: הנתיב נמצא בתוך עץ עבודה של git, יש לו remote בשם
`origin`, וה־remote הזה מצביע אל forge נתמך (github.com, gitlab.com או
bitbucket.org). ראו
[הוספת מאגרים לסביבת עבודה](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/הוספת-מאגרים/).

### הכול מפסיק לעבוד לזמן מה אחרי שימוש כבד

זהו מנגנון ההגנה של הגבלת הקצב. GitHub מסמן את המגבלה הראשית שלו ב-`403` הנושא
`x-ratelimit-remaining: 0` וזמן איפוס; כשהוא רואה כזה, הלקוח מכשיל בקשות נוספות
באופן מקומי בלי קריאת רשת עד שחלון הזמן חולף, כך שסופת ניסיונות חוזרים אינה יכולה
להעמיק את המגבלה. כשלים חולפים מנוסים מחדש עד שלוש פעמים עם השהיה מעריכית, תוך
כיבוד `retry-after`.
