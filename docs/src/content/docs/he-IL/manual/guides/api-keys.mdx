המדריך הזה מראה היכן נשמר כל פרט גישה שבו משתמש Control Center ואיך לשנות
אותו.

**שום דבר לא נשמר במחשב שאתם מקלידים בו.** כל פרטי הגישה נמצאים בשרת; איזה מהם
עונה לבקשה נתונה תלוי בכך אם יש אדם מאחוריה.

| פרט גישה                              | היכן נשמר                                                 | מי משתמש בו                                                     |
| ------------------------------------ | --------------------------------------------------------- | ---------------------------------------------------------------- |
| הכניסה שלכם למארח הקוד / לכרטוס       | קובץ הסודות 0600 של השרת, לפי מזהה המשתמש שלכם             | כל מה שאתם עושים: משטח בקשות המשיכה, סקירות, מיזוגים, הפעולות שלכם ב-Linear |
| אפליקציות הספק של השרת                | אותו קובץ, ובנוסף `server_settings` למה שאינו סוד          | הכנסת אנשים, ואסימונים למאגר אחד עבור סוכנים, פייפליינים וסריקה |

| פרטי גישה של CLI חיצוני                | מה שאותו CLI משתמש בו                                    | Claude Code, במארח השרת                                          |

## GitHub: הכניסה שלכם, ואסימונים למאגר אחד

- **שלכם**, מ**כניסה ל-GitHub**. הוא זה שמשמש כל בקשה שנשלחת *בשמכם*, כך שסקירה
  שמפורסמת עבורכם נושאת את השם שלכם. חבר אחר לא יכול להשתמש בו, וכל אחד נכנס בעצמו.
  אין אסימון GitHub להדביק
- **עבודה שאיש אינו מקליד** (סוכנים, פייפליינים, סריקה, תשובות בוט) מקבלת אסימון
  למאגר אחד בכל פעם, שהונפק מה-GitHub App של השרת או דרך Control Center Connect,
  ומוגבל למה שחבר אחראי יכול לעשות שם. זו לעולם אינה הכניסה שלכם שנמסרת כמות שהיא

שלכם נקבע בכרטיס **אחסון קוד** ב**הגדרות ← סביבת עבודה ← פרופיל וזהות**; של
אפליקציית השרת ב**אפליקציות ספק** ב**הגדרות ← שרת ← כניסה מאוחדת**. ראו
[הגדרת אינטגרציית GitHub](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/אינטגרציית-github/)
ו[יצירת GitHub App](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/github-app/).

GitLab ו-Bitbucket עדיין מקבלים אסימון אישי שמודבק, ונשמר באותה דרך. ראו
[חיבור מארח קוד](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/חיבור-מארח-קוד/).

:::note[יש גם מסך שנגיש רק דרך כתובת URL]
‏`/workspaces/<workspaceId>/api-keys` מציג את אותם שני כרטיסים כמו הצעד הראשון
של תהליך ההיכרות. **אין לו שום ערך ניווט בממשק**; אפשר להגיע אליו רק בהקלדת
הכתובת. השתמשו במקום זה ב**הגדרות ← סביבת עבודה ← פרופיל וזהות**.
:::

## הגדרת מפתחות ספקי מודלים

המתאם המובנה מאמת את הספקים בעצמו, ופרטי הגישה האלה נשמרים בשרת.

1. עברו אל **הגדרות ← שרת ← ספקי מודלים**
2. גללו אל **ספקים ומודלים**
3. חברו את הספק — OAuth בדפדפן עבור OpenAI,‏ Codex,‏ Cursor ו-Kimi Code;
   מפתח API עבור Anthropic והשאר

ראו [ניהול מתאמים ומודלים](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/מתאמים/) לרשימה
המלאה ולהוספה של נקודת קצה מותאמת אישית.

פרטי הגישה האלה הם **גלובליים למארח**: מפתח אחד משרת כל סביבת עבודה בהתקנה.
אסימוני OAuth מתרעננים לפני שפג תוקפם.

ה-CLI של מתאמים חיצוניים שומר על פרטי הגישה שלו, בהגדרות שלו, במארח השרת —
Control Center לא מנהל אותם. אמתו את Claude Code לפי התיעוד שלו, במחשב שעליו
רץ `cc_server`.

הדיאלוג **משתני סביבה** שלכל מתאם נראה כמו מקום לשים בו מפתח עבור אחד מהם,
אבל הוא לא: הוא כותב למכשיר שלכם, בעוד שהשרת קורא את העותק שלו, ושום דבר לא
מגשר בין השניים. ראו
[ניהול מתאמים ומודלים](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/מתאמים/).

## חיבור ספק כרטוס

הכרטיס **כרטוס** ב**הגדרות ← סביבת עבודה ← כללי** מחזיק את שני החצאים של החלטה
אחת: באיזה ספק מאוחסנים הכרטיסים שלכם, ומי Control Center כשהוא מדבר איתו. בחירה
ב**מקומי** מסתירה את שורות Linear — כרטיסים מקומיים נמצאים במסד הנתונים של השרת הזה
עצמו ואין להם למה להזדהות.

ל-Linear יש שתי כניסות ואין מפתח להדביק: **Linear** היא שלכם, עבור מה שאתם עושים,
ו**אוטומציה של Linear** היא אפליקציית Control Center של סביבת העבודה, שמנהל מחבר,
עבור סנכרון כרטיסים, פייפליינים וסוכנים. השרת יכול גם להחזיק **מפתח API של שירות**
(**אפליקציות ספק**) עבור סביבות עבודה שלא חוברה בהן אוטומציה. שום פרט גישה של כרטוס
אינו מוזרק לארגז החול של סוכן; סוכנים כותבים כרטיסים דרך הכלים של Control Center,
ששואלים את הכלל **כתיבה למערכת מעקב חיצונית**. ראו
[הגדרת אינטגרציית Linear](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/אינטגרציית-linear/).

## החלפה או שלילה

- **הכניסה שלכם ל-GitHub**: לחצו על **ניתוק**, ואז שוב על **כניסה ל-GitHub**. ניתוק
  מפיל גם כל אסימון שהשרת הנפיק בשמכם
- **אסימון של GitLab או Bitbucket**: לחצו על **עדכון אסימון גישה** והדביקו את החדש,
  ואז שללו את הישן במארח הקוד
- **האפליקציה של השרת**: צרו מפתח פרטי חדש או סוד לקוח חדש בעמוד של האפליקציה אצל
  הספק, הדביקו אותו ב**אפליקציות ספק** ולחצו על **בדוק**
- **מפתח ההתקנה של Connect**: **החלפת מפתח** בכרטיס **Control Center Connect**, או
  `cc_server connect rotate-key --yes`. כל מי שנכנס דרך Connect נכנס שוב. ראו
  [Control Center Connect](/he-IL/מדריך-למשתמש/עזר/connect/)
- **ספק מודלים**: בשורה שלו, התנתקו (OAuth) או הסירו את המפתח, ואז התחברו שוב
- **Slack**: עבור אפליקציה משלכם, הדביקו שוב את האסימונים בדיאלוג החיבור. לאפליקציית
  Control Center המשותפת אין אסימון להחליף: אסימון הבוט שלה מתחדש דרך Connect,
  ו**ניתוק** שולל אותו ומסיר את הבוט מ-Slack. ראו
  [הגדרת אינטגרציית Slack](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/אינטגרציית-slack/)

## פתרון תקלות

### אסימון של GitLab או Bitbucket עובד ב-`curl` אבל לא כאן

בדקו את כתובית השורה של **אחסון קוד**. אם כתוב בה "מהסביבה", פרט הגישה שעונה הוא של
השרת, לא שלכם — שלכם לא נשמר.

### אסימון של GitLab או Bitbucket מתקבל אבל בקשות מאוחרות יותר נכשלות

האסימון נבדק כפי שהוא נשמר, ולכן השורה מציינת את החשבון שמאחוריו — אבל רק את
החשבון, לא את ההיקפים. אסימון עם מעט מדי היקפים מתחבר ואז נכשל בבקשות בודדות.
בדקו את ההיקפים ואת תפוגת התוקף שלו במארח הקוד.

### ספק אומר שהכניסה לא הוגדרה בשרת הזה

אין לשרת לא אפליקציה משלו עבור אותו ספק ולא Control Center Connect. בעל השרת בוחר
אחת מהן ב**הגדרות ← שרת ← כניסה מאוחדת**.
