המדריך הזה מראה היכן נשמר כל פרט גישה שבו משתמש Control Center ואיך לשנות
אותו.

**שום דבר לא נשמר במחשב שאתם מקלידים בו.** כל פרטי הגישה נמצאים בשרת; איזה מהם
עונה לבקשה נתונה תלוי בכך אם יש אדם מאחוריה.

| פרט גישה                              | היכן נשמר                                                 | מי משתמש בו                                                     |
| ------------------------------------ | --------------------------------------------------------- | ---------------------------------------------------------------- |
| פרט הגישה שלכם למארח הקוד / לכרטוס     | קובץ הסודות 0600 של השרת, לפי מזהה המשתמש שלכם             | כל מה שאתם מבקשים: משטח בקשות המשיכה, הרצות הסוכנים שלכם, התמונות שלכם |
| זהות האפליקציה של השרת                | אותו קובץ, ובנוסף `server_settings` למה שאינו סוד          | עבודה שאף אדם לא ביקש: webhooks, סריקת בקשות משיכה, סנכרון כרטיסים |
| מפתחות ספקי מודלים ואסימוני OAuth      | מאגר פרטי הגישה של השרת עצמו                              | המתאם המובנה, עבור כל סביבת עבודה בהתקנה                         |
| אסימוני הבוט של Slack                 | `<dataDir>/<workspaceId>/chat_credentials/` בשרת          | גשר הצ'אט של אותה סביבת עבודה                                    |
| פרטי גישה של CLI חיצוני                | מה שאותו CLI משתמש בו                                    | Claude Code, במארח השרת                                          |

## שני פרטי גישה ל-GitHub, והם עונים על שאלות שונות

- **שלכם**, מכניסה (device flow) או מהדבקה של אסימון. הוא זה שמשמש כל בקשה
  שנשלחת *בשמכם*, כך שהערה שמפורסמת עבורכם נושאת את השם שלכם. חבר אחר לא יכול
  לקרוא אותו, והוא מחבר את שלו
- **של השרת**, מ-GitHub App שהמפעיל רשם. הוא עונה לכל בקשה שאין מאחוריה אדם —
  כך שהגישה למארח הקוד לא נעלמת כשאדם אחד עוזב או מחליף אסימון

שלכם נקבע בכרטיס **אחסון קוד** ב**הגדרות ← סביבת עבודה ← פרופיל וזהות**; של
השרת ב**אפליקציות ספק** ב**הגדרות ← שרת ← כניסה מאוחדת**. ראו
[הגדרת אינטגרציית GitHub](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/אינטגרציית-github/)
ו[יצירת GitHub App](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/github-app/).

:::note[יש גם מסך שנגיש רק דרך כתובת URL]
‏`/workspaces/<workspaceId>/api-keys` מציג את אותם שני כרטיסים כמו הצעד הראשון
של תהליך ההיכרות. **אין לו שום ערך ניווט בממשק**; אפשר להגיע אליו רק בהקלדת
הכתובת. השתמשו במקום זה ב**הגדרות ← סביבת עבודה ← פרופיל וזהות**.
:::

## הגדרת מפתחות ספקי מודלים

המתאם המובנה מאמת את הספקים בעצמו, ופרטי הגישה האלה נשמרים בשרת.

1. עברו אל **הגדרות ← שרת ← ספקי מודלים**
2. גללו אל **ספקים ומודלים**
3. חברו את הספק — OAuth בדפדפן עבור OpenAI,‏ Codex,‏ Cursor ו-Kimi Code;
   מפתח API עבור Anthropic והשאר

ראו [ניהול מתאמים ומודלים](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/מתאמים/) לרשימה
המלאה ולהוספה של נקודת קצה מותאמת אישית.

פרטי הגישה האלה הם **גלובליים למארח**: מפתח אחד משרת כל סביבת עבודה בהתקנה.
אסימוני OAuth מתרעננים לפני שפג תוקפם.

ה-CLI של מתאמים חיצוניים שומר על פרטי הגישה שלו, בהגדרות שלו, במארח השרת —
Control Center לא מנהל אותם. אמתו את Claude Code לפי התיעוד שלו, במחשב שעליו
רץ `cc_server`.

הדיאלוג **משתני סביבה** שלכל מתאם נראה כמו מקום לשים בו מפתח עבור אחד מהם,
אבל הוא לא: הוא כותב למכשיר שלכם, בעוד שהשרת קורא את העותק שלו, ושום דבר לא
מגשר בין השניים. ראו
[ניהול מתאמים ומודלים](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/מתאמים/).

## חיבור ספק כרטוס

הכרטיס **כרטוס** ב**הגדרות ← סביבת עבודה ← כללי** מחזיק את שני החצאים של החלטה
אחת: באיזה ספק מאוחסנים הכרטיסים שלכם, ופרטי הגישה עבורו. בחירה ב**מקומי**
מסתירה את שורת פרטי הגישה — כרטיסים מקומיים נמצאים במסד הנתונים של השרת הזה
עצמו ואין להם למה להזדהות.

המפתח שלכם נשמר בשרת לפי מזהה המשתמש שלכם, כמו זה של מארח הקוד. השרת שומר מפתח
Linear משלו בנפרד (**אפליקציות ספק**), וזה מה שסנכרון הכרטיסים עובד לפיו כשאף
אדם לא ביקש. מפתח שסוכן מקבל מוזרק רק כשהסוכן מחזיק ביכולת **התרת קריאות API של
ניהול כרטיסים**. ראו
[הגדרת אינטגרציית Linear](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/אינטגרציית-linear/).

## החלפה או שלילה

- **פרט הגישה שלכם ל-GitHub**: לחצו על **ניתוק**, ואז היכנסו שוב או הדביקו את
  האסימון החדש. שללו את הישן ב-GitHub
- **האפליקציה של השרת**: צרו מפתח פרטי חדש או סוד לקוח חדש בעמוד ה-GitHub של
  האפליקציה, הדביקו אותו ב**אפליקציות ספק** ולחצו על **בדוק**
- **ספק מודלים**: בשורה שלו, התנתקו (OAuth) או הסירו את המפתח, ואז התחברו שוב
- **Slack**: הדביקו שוב את האסימונים בדיאלוג החיבור. ראו
  [הגדרת אינטגרציית Slack](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/אינטגרציית-slack/)

## פתרון תקלות

### רשימת בקשות המשיכה ריקה אבל האסימון שלי עובד ב-`curl`

בדקו את כתובית השורה של **אחסון קוד**. אם היא מציינת מקור אחר ("דרך האפליקציה
של השרת הזה", "מהסביבה"), פרט הגישה שאתם בודקים אינו זה שעונה — שלכם לא נשמר.

### האסימון מתקבל אבל בקשות מאוחרות יותר נכשלות

האסימון נבדק כפי שהוא נשמר, ולכן השורה מציינת את החשבון שמאחוריו — אבל רק את
החשבון, לא את ההיקפים. אסימון עם מעט מדי היקפים מתחבר ואז נכשל בבקשות בודדות.
בדקו את ההיקפים ואת תפוגת התוקף:

```bash
curl -H "Authorization: token YOUR_TOKEN" https://api.github.com/user
```
