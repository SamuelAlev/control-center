## מה תבנו

בסוף המדריך הזה יהיו לכם:

- סביבת עבודה הקרויה על שם הפרויקט שלכם
- מאגר Git הרשום בתוכה
- חמישה סוכנים שנזרעו מראש, שאחד מהם הגדרתם מספיק טוב כדי שירוץ
- סביבת עבודה שנייה וריקה שמוכיחה את גבול הבידוד

הכניסה הראשונית כבר יצרה לכם סביבת עבודה. המדריך הזה יוצר במכוון סביבה חדשה, כדי שתראו כל שלב בתהליך.

לפני שתתחילו, בחרו צ׳קאאוט של Git שמקיים את כל שלושת התנאים האלה — שלב הרישום דוחה כל דבר אחר:

- הוא נמצא בתוך עץ עבודה של git
- יש לו remote בשם `origin`
- ה־remote הזה מצביע ל־github.com, ל־gitlab.com או ל־bitbucket.org

## שלב 1: צרו סביבת עבודה

1. לחצו על הצ׳יפ של סביבת העבודה בשורת הכותרת
2. בחרו **הוספת סביבת עבודה…**
3. הזינו שם שמזהה את הפרויקט, כמו "api-service" או "frontend-v2"
4. אפשר לבחור לוגו
5. לחצו על **הוספת סביבת עבודה**

Control Center עוברת לסביבת העבודה החדשה ונוחתת בדואר הנכנס שלה (`/workspaces/<id>/inbox`).

מאחורי הקלעים, השרת מפרסם אירוע `WorkspaceCreated` ומזרע בסביבת העבודה:

- **סוכן CEO**, שהפרסונה שלו היא תיאום והאצלה
- ארבעה מומחים — `qa`, `architect`, `engineer` ו־`librarian` — כל אחד עם ההוראות והמיומנויות שלו
- תבניות הפייפליין המובנות ושורות הטריגר שלהן

כל סביבת עבודה שתצרו מקבלת את כל זה, לא רק הראשונה.

כדי לוודא: פתחו את **הגדרות → סביבת עבודה → סוכנים**. חמישה סוכנים בסגל, ולכל אחד טבעת סטטוס חלולה.

## שלב 2: רשמו מאגר

1. עברו אל **הגדרות → סביבת עבודה → מאגרים**
2. לחצו על **הוספת מאגר**
3. נווטו אל הצ׳קאאוט שלכם. תיבת הדו-שיח עוברת על התיקיות במחשב שמריץ את `cc_server` — לא בלקוח שלכם — ונשארת בתוך השורשים שהשרת הזה חושף (ספריית הבית של המשתמש שלו כברירת מחדל). צ׳קאאוט של git מקבל סמל תיקייה נפרד ותיבת סימון; תיקייה רגילה לא מקבלת אף אחד מהם, ולכן רק צ׳קאאוטים ניתנים לבחירה.
4. סמנו צ׳קאאוט אחד או יותר ורשמו את הקבוצה. הבחירות נשמרות בזמן הניווט, כך שאפשר לאסוף כמה בסיבוב אחד, ובחירה שגויה אחת לעולם לא מפילה את השאר.

Control Center קוראת את ה־remote בשם `origin` של כל צ׳קאאוט, מפענחת את הבעלים והמאגר ויוצרת את שורת המאגר **בתוך סביבת העבודה הזו**. אין שלב שני לקישור: הרישום הוא זה שקובע את ההיקף.

רישום אותו צ׳קאאוט בסביבת עבודה אחרת יוצר לימים שורת מאגר שנייה ועצמאית, עם מזהה משל עצמה. בין סביבות עבודה, צ׳קאאוט מזוהה לפי הנתיב שלו במערכת הקבצים, ולעולם לא לפי מזהה.

כדי לוודא: המאגר מופיע ברשימה עם ה־`owner/repo` שלו והענף הנוכחי.

## שלב 3: הכינו סוכן אחד שאפשר להריץ

לחמישה הסוכנים שסביבת העבודה הזו זה עתה זרעה אין מתאם ואין מודל. השליחה מריצה אותם על **Control Center (built-in)** ובלי מודל מוגדר מבקשת מ-Anthropic את ברירת המחדל שלה — כך שהם עובדים רק אם חיברתם חשבון Anthropic, ועל מודל שלא בחרתם אם חיברתם. הכניסה הראשונית בהרצה הראשונה מטביעה את בחירתה על כל סוכן בסביבת העבודה הראשונה, פעם אחת; סביבת עבודה שתצרו אחר כך מתחילה כשכל החמישה לא מוגדרים. הגדירו אחד מהם עכשיו.

1. פתחו את **הגדרות → סביבת עבודה → סוכנים**
2. בחרו `engineer` בסגל
3. בלשונית **הגדרות**, הגדירו **מתאם** כ־`Control Center (built-in)` ובחרו **מודל** מספק שחיברתם תחת הגדרות → שרת → ספקי מודלים
4. לחצו על **שמור שינויים**

כדי לוודא: פתחו מחדש את הסוכן ושני השדות שומרים על הבחירות שלכם.

לכל סוכן מתאם ומודל משלו, ולכן חזרו על כך בכל סוכן אחר שבכוונתכם להשתמש בו. [יצירה והגדרה של סוכן](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/יצירת-סוכן/) מכסה את שאר הטופס.

## שלב 4: ראו את גבול הבידוד

צרו סביבת עבודה שנייה מהצ׳יפ בשורת הכותרת, בדיוק כמו בשלב 1. לאחר מכן התבוננו בה:

- **הגדרות → סביבת עבודה → מאגרים** ריקה. המאגר שרשמתם לפני דקה אינו שם.
- **הגדרות → סביבת עבודה → סוכנים** מכילה חמישה סוכנים, אבל אלה שורות שונות — המתאם שהגדרתם בשלב 3 נעלם.
- רשימת המרחבים, הכרטיסים והזיכרון — כולם ריקים.

שום דבר לא דלף, כי אין מאיפה לדלוף: השורות של כל סביבת עבודה יושבות בקובץ מסד הנתונים של אותה סביבת עבודה עצמה. קריאה חוצת סביבות עבודה אינה שאילתה שמסוננת — היא שאילתה שאין לה היכן לרוץ. מחיקת סביבת עבודה היא ניתוק של קובץ.

חזרו לסביבה הקודמת עם הצ׳יפ בשורת הכותרת, או פתחו את **ניהול סביבות עבודה** כדי לראותן זו לצד זו.

למודל המלא, קראו את [סביבות עבודה ובידוד](/he-IL/מדריך-למשתמש/מושגים/סביבות-עבודה/).

## סיכום

יצרתם סביבת עבודה, ראיתם אותה זורעת סוכן CEO וארבעה מומחים, רשמתם לתוכה מאגר, נתתם לסוכן אחד מתאם ומודל, ואימתתם שסביבת עבודה שנייה אינה חולקת דבר מכל זה.
