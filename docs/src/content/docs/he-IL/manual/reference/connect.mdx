Control Center Connect מפעיל כניסות לספקים עבור שרתים שלא רשמו אפליקציות משלהם.
שרת משתמש או ב-Connect המאוחסן של Control Center, או ב-Connect שהארגון שלו מפעיל
([הפעלת שרת Connect](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/הפעלת-שרת-connect/)), או
באף אחד מהם. הבחירה נמצאת תחת **הגדרות ← שרת ← כניסה מאוחדת ← Control Center
Connect**, בפקודה `cc_server connect`, או ב-`CC_CONNECT_URL`.

## מסלולים

כל ספק הוא מסלול (lane). תחת **שימוש באפליקציות שלי** (או לפני שמישהו בוחר), מסלול רץ על האפליקציה של השרת עצמו כשהיא מוגדרת במלואה; אחרת הוא לא זמין. עם Control Center או Connect משלכם, Connect מריץ כל מסלול שהוא מציע: האפליקציות המשלו של השרת נשמרות אך אינן בשימוש, לא לכניסות, לא לאוטומציה של השרת ולא לסטטוס שהשרת מדווח. אפליקציה משלה של סביבת העבודה חלה בכל מצב.

| מסלול        | האפליקציה משלו צריכה                              | דרך Connect                                                 |
| ------------ | ------------------------------------------------- | ----------------------------------------------------------- |
| `github`     | App id, private key, client id ו-client secret    | אנשים נכנסים ל-GitHub App המשותף                            |
| `google`     | Client id ו-client secret                         | אנשים מחברים את Google Calendar                             |
| `linear`     | Client id                                         | אנשים נכנסים ל-Linear                                       |
| `linear_app` | Client id                                         | מנהל סביבת עבודה מחבר את ה-actor של אפליקציית Linear         |
| `slack`      | חיבור Slack משלו של סביבת העבודה                  | מנהל סביבת עבודה מחבר את Slack לאפליקציית Slack המשותפת      |
| `klipy`      | `KLIPY_APP_KEY`                                   | חיפוש GIF, שמועבר דרך Connect                               |

אפליקציה משלו שמוגדרת רק בחלקה הופכת את המסלול שלה לשגיאה, ולעולם לא לנפילה
שקטה אל Connect. סביבת עבודה שמשתמשת ב-GitHub App משלה (**הגדרות ← סביבת עבודה ←
כללי ← זהות GitHub**) לעולם אינה עוברת דרך Connect עבור GitHub, וסביבת עבודה שמשתמשת באפליקציה משלה של Google, Linear או Klipy (**הגדרות ← סביבת עבודה ← כללי ← אפליקציות ספק**) לעולם אינה עוברת דרך אפליקציית השרת או דרך Connect עבור אותו ספק. שינוי בבחירת Connect אינו מנתק אף אחד מהאפליקציה המשלו של סביבת עבודה.

## מה Connect רואה ומה הוא לעולם לא רואה

| Connect רואה                                                                                    | Connect לעולם לא רואה                                                            |
| ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| מזהה ההתקנה של השרת וחתימות הבקשות                                                               | קוד מקור, תוכן מאגרים, diffs או טקסט של בקשות משיכה                               |
| חשבון הספק שנכנס, במהלך הכניסה                                                                    | כרטיסים, תמלולים או כל דבר במסד הנתונים של סביבת עבודה                            |
| לאיזו סביבת עבודה שייך פרטי גישה, כמזהה אטום בתוך האטם                                           | מפתח פרטי של GitHub App: אסימוני מאגר מגיעים מתוך הכניסה של אדם                     |
| המאגר שעבורו מונפק אסימון GitHub למאגר בודד                                                       | אסימוני רענון במנוחה: הם קיימים רק בתוך אטמים שהשרת שומר                          |
| מזהי התקנות GitHub שקשורים לשרת                                                                 | סודות Linear: השרת מחליף את הקוד של Linear בעצמו                                  |
| מונחי חיפוש GIF, כשהוא מעביר את Klipy                                                             | סיסמאות, מפתחות צימוד או מפתחות של ספקי מודלים                                    |
| הפניות לאירועי Slack (צוות, ערוץ, מזהה הודעה) וטקסט של פקודות קו נטוי                           | טקסט הודעות Slack: Connect משליך אותו עם ההגעה, והשרת קורא את ההודעה מ-Slack בעצמו |

Connect שומר מצב קצר טווח (כניסות בתהליך, nonces, מטמונים) לכל היותר 15 דקות.
הרשומות המתמשכות היחידות שלו הן קשרי התקנה: אילו שרתים רשאים להשתמש באיזו התקנת
GitHub, ולאיזה שרת כל צוות Slack קשור. שגיאות נושאות קוד בלבד, לעולם לא את התגובה
של הספק, והיומנים מתעדים מזהי התקנה רק כ-hash מפתוח.

## מצבים

| מצב      | הגדרה                             | התנהגות                                                                                                          |
| -------- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| לא מוגדר | שרת חדש                           | אף מסלול לא משתמש ב-Connect. ההכנה מבקשת מבעל השרת לבחור                                                         |
| `hosted` | **שימוש באפליקציות של Control Center** | `https://connect.usectrl.dev`, עם תצורה חתומה מחוץ לרשת. אפליקציות השרת המשלו אינן בשימוש                                                      |
| `custom` | **שימוש בשרת Connect מותאם**      | Connect בכתובת HTTPS (`http` ב-loopback בלבד), שנחשב לאמין בשימוש הראשון. אפליקציות השרת המשלו אינן בשימוש                                        |
| `off`    | **שימוש באפליקציות שלי**           | אף מסלול לא משתמש ב-Connect. רק אפליקציות משלו מכניסות אנשים                                                    |

`CC_CONNECT_URL` בסביבה או ב-`.env` של השרת נועל את הבחירה: `hosted`, `off`, או
כתובת Connect. אז ההגדרות מציגות את המנעול ואינן יכולות לשנות אותה.

הבנייה הזו אינה מקמפלת מפתח תצורה מאוחסן, ולכן מצב hosted מדווח `hosted_unprovisioned`
ואינו מציע אף מסלול. אפליקציות משלו ו-Connect מותאם עובדים.

שרת קורא את התצורה של Connect לכל היותר כל 10 דקות, ומחכה לכל קריאה 5 שניות לכל היותר.
כש-Connect אינו נגיש, התצורה התקינה האחרונה ממשיכה לשמש וההגדרות מסמנות אותה כמיושנת.

## זהות התקנה

| פריט              | מה הוא                                                                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| מפתח התקנה        | seed של 32 בייטים בקובץ הסודות של השרת (`connect_install_key`), נפרד ממפתחות צימוד מכשירים                                                 |
| מפתח לכל Connect  | מפתח Ed25519 שנגזר מה-seed ומכתובת ה-Connect. כל בקשה ל-Connect נחתמת בו (RFC 9421)                                                        |
| מזהה התקנה        | 26 תווים הנגזרים ממפתח הציבורי. מוצג בהגדרות וב-`cc_server connect status`                                                                  |

לאותו שרת יש מזהה התקנה שונה לכל כתובת Connect. המזהה משתנה רק כאשר המפתח מוחלף.

## פרטי גישה אטומים

כניסה דרך Connect מחזירה **אטם פרטי גישה** (credential seal): בלוב מוצפן שרק ה-Connect
שיצר אותו יכול לפתוח. הוא קשור לספק, לכתובת ה-Connect, למזהה ההתקנה, לסביבת העבודה,
לחשבון הספק, לאפליקציה ולדור הסוד.

- השרת שומר את האטם ואת מזהה ההתקנה שעבורו נאטם. אסימוני הגישה נשארים בזיכרון
- כדי לרענן, השרת שולח את האטם בחזרה ומקבל אסימון גישה חדש ואטם חדש
- אטם שמזהה ההתקנה או כתובת ה-Connect שלו כבר אינם תואמים נמחק בקריאה הבאה שלו,
  והאדם נכנס מחדש. זה קורה לאחר החלפת מפתח, מעבר ל-Connect אחר, או תיקיית נתונים
  ששוחזרה על שרת אחר
- אטם ש-Connect אינו יכול לפתוח נדחה עם `access_denied`

## התקנות GitHub

התקנה של ה-GitHub App המשותף שמיש עבור שרת רק כאשר Connect קשר אותה למזהה ההתקנה
של אותו שרת.

- **Install GitHub App** תחת **הגדרות ← סביבת עבודה ← כללי** פותח את GitHub עם כרטיס
  תקף ל-15 דקות. Connect קושר את ההתקנה החדשה כאשר המתקין הוא הבעלים של החשבון
  האישי או מנהל את הארגון
- **Authorize this server** קושר התקנה שכבר קיימת. רק מנהל ארגון יכול לעשות זאת
- התקנה של ארגון יכולה להיקשר למספר שרתים; לכל אחד מהם נדרשת הרשאה ממנהל

## אמון בתצורה

| Connect | איך השרת סומך על התצורה שלו                                                                                                                                                                                                                                  |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hosted  | מאמת חתימת Ed25519 מול מפתחות שמקומפלים בבנייה. מסרב לתצורה עם epoch נמוך מהגבוה ביותר שראה (`rollback`)                                                                                                                                                         |
| Custom  | מצמיד את app id ו-client id של GitHub, את client ids של Google ו-Linear, ואת מזהי האפליקציה והלקוח של Slack בשימוש הראשון. שינוי משהה את הכניסות דרך Connect (`pins_changed`) עד שבעל השרת ילחץ על **Trust new apps** |

## פעולות

כל הגדרות Connect זמינות לבעל השרת בלבד.

| פעולה                 | מה היא עושה                                                                                    |
| --------------------- | ---------------------------------------------------------------------------------------------- |
| `connect.status`      | מצב, כתובת, נעילה, מזהה התקנה, בריאות, epoch של התצורה ומקור כל מסלול                           |
| `connect.configure`   | מגדירה `hosted`, `custom` (עם `url`) או `off`                                                  |
| `connect.test`        | שולפת שוב את התצורה ומדווחת על הבריאות                                                         |
| `connect.confirmPins` | מקבלת את המזהים ששונו של Connect מותאם                                                         |
| `connect.rotateKey`   | מנפיקה מפתח התקנה חדש. כל כניסה דרך Connect בשרת הזה מפסיקה לעבוד                              |

הכניסות עצמן משתמשות ב-`oauth.lanes`, `oauth.begin`, `oauth.status`,
`oauth.complete`, `oauth.connections` ו-`oauth.disconnect`. האדם הוא תמיד מי
שמחובר ומבצע את הקריאה.

## כניסה דרך Connect

1. השרת מבקש מ-Connect להפעיל את המסלול, ומקבל את כתובת ה-authorize של הספק. הוא בודק
   אותה לפני שהוא מציג אותה
2. האדם מאשר בדפדפן. הספק מחזיר אותו אל Connect
3. Connect מציג קוד בן 8 תווים וקישור `control-center://oauth-done`
4. האדם מקליד את הקוד באפליקציה, או פותח את הקישור. השרת מממש את הכניסה עם הקוד
   וההוכחה שלו לבקשה

כניסה פוקעת אחרי 10 דקות. חמישה קודים שגויים מסיימים אותה. קישור שהאפליקציה הזו לא
התחילה נדחה עם **Sign-in not started here**.

## החלפת מפתח ההתקנה

**Rotate key** בכרטיס Connect, או `cc_server connect rotate-key --yes`:

- נותן לשרת מפתח התקנה חדש ומזהה התקנה חדש
- מנתק את כל האנשים מכל מסלול שרץ דרך Connect
- משאיר את הכניסות דרך האפליקציות של השרת עצמו ללא שינוי
- דורש הוספת מזהה ההתקנה החדש לרשימת ההיתרים של Connect מותאם

## קודי סטטוס

| קוד                    | משמעות                                                                 |
| ---------------------- | ---------------------------------------------------------------------- |
| `hosted_unprovisioned` | לבנייה הזו אין מפתח תצורה מאוחסן                                        |
| `signature`            | התצורה המאוחסנת נכשלה בבדיקת החתימה שלה                                 |
| `rollback`             | Connect הגיש תצורה ישנה מזו שהשרת כבר ראה                               |
| `unreachable`          | השרת לא יכול להגיע ל-Connect                                            |
| `install_blocked`      | Connect לא מתיר את מזהה ההתקנה הזה                                      |
| `pins_changed`         | Connect מותאם הכריז על מזהי אפליקציה שונים                              |
| `protocol`             | Connect ענה בצורה שהשרת הזה אינו מבין                                   |
