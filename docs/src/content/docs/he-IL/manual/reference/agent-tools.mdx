אלה הכלים ה**מקושרים לשרת** שמנגנון ההרצה המובנה של הסוכן רושם ישירות — שרת שפה, חיפוש מבני, מנפה, קרנלים, סקריפטים של מצב קוד, שאלות ושליטה בעובדים — להבדיל מ[כלי MCP](/he-IL/מדריך-למשתמש/עזר/כלי-mcp/) שהוא מגשר פנימה, ומכלי הקבצים, החיפוש והמעטפת הגנריים של מנגנון ההרצה. הם אינם נמצאים במרשם MCP: לקוח MCP חיצוני לא יראה אותם, מפני שכל אחד מהם קשור למשאב חי בצד השרת — תהליך שרת שפה, מתאם ניפוי, מפרש — ששייך להרצה אחת.

כל כלי כאן נרשם רק כשהמשאב שעומד מאחוריו מחובר להרצה — מפקח שרת שפה או ניפוי, מנתח tree-sitter, מפעל קרנלים, יציאת שאלות, רשימת עובדי vibe. זיהוי של שרת שפה או מתאם ניפוי עבור *ה־checkout הזה* הוא בדיקה נפרדת ומאוחרת יותר (`status` / `adapters`): הכלים האלה נשארים על המשטח כדי שהסוכן יוכל לשאול מדוע שום דבר אינו שמיש, במקום לנחש.

## דרגות אישור

כל כלי מצהיר על דרגה, והדרגה מכריעה **אילו משטחים רואים אותו** — לא רק אם הוא מבקש אישור. מצב תוכנית וסוכני משנה לקריאה בלבד מוגבלים ל־`read`, כך שכלי בדרגת `write` או `exec` נעדר מהסכימה שלהם לחלוטין.

| דרגה    | משמעות                                | כלים כאן                                         |
| ------- | -------------------------------------- | -------------------------------------------------- |
| `read`  | ללא תופעות לוואי                       | `lsp`, `ast_grep`, `ask_user`, `repl`, חמשת ה־`vibe_*` |
| `write` | משנה קבצים                             | `lsp_rename`, `ast_edit`, `resolve`                |
| `exec`  | מפעיל תהליך או שולט בו                 | `debug`, `eval`                                    |

## ישירים, רק מסקריפט או נטענים בשימוש הראשון

כששרת יכול להריץ סקריפטים, הרצה קוראת לכמה כלים ישירות, ומגיעה לשאר מסקריפט של [`repl`](#repl--הרצת-סקריפט-שקורא-לכלים-שלכם); ראו [מצב קוד](/he-IL/מדריך-למשתמש/מושגים/מצב-קוד/#אילו-כלים-הסוכן-קורא-ישירות) לכלל המלא. לכלים בעמוד הזה:

| כלי | עם `repl` | בלי `repl` |
| ---- | ----------- | -------------- |
| `repl` | ישיר | לא קיים |
| `ask_user` | ישיר | ישיר |
| `lsp`, `lsp_rename`, `ast_grep`, `ast_edit`, `resolve`, `debug` | רק מסקריפט | נטען בשימוש הראשון |
| `eval` | נטען בשימוש הראשון (סקריפט לא יכול לקרוא לו) | נטען בשימוש הראשון |
| `vibe_*` | ישיר במצב vibe, לעולם לא מסקריפט | ישיר במצב vibe |

כלי שמסומן „רק מסקריפט” נטען בשימוש הראשון במקום, מרגע שהשרת לא יכול להריץ את הסקריפטים של ההרצה ([כשסקריפטים לא יכולים לרוץ](/he-IL/מדריך-למשתמש/מושגים/מצב-קוד/#כשסקריפטים-לא-יכולים-לרוץ)).

## `lsp` — שאילתות שרת שפה

נרשם כאשר להרצה יש מפקח שרת שפה ותיקיית עבודה. אם שרת באמת יכול לענות מתגלה בזמן הקריאה, כ**חיתוך**: סמן שורש חייב להתקיים *וגם* קובץ ההרצה של השרת חייב להיפתר. כל אחד מהם לבדו משמעו שאף שרת לא עולה — `status` אומר זאת — במקום ניחוש שקט.

שרתים באים מהטבלה המובנית בלבד; קובץ `lsp.json` של המאגר אינו נקרא. בהרצה בתוך ארגז חול לכל הרצה יש סשן שרת שפה משלה, ולכן השרתים עולים מחדש בכל הרצה. קובצי הרצה מקומיים לפרויקט (`node_modules/.bin`) משמשים רק כאשר ההרצה רצה בארגז חול, ושורש הפרויקט לעולם אינו נפתר מעל תיקיית העבודה של ההרצה.

מיקומים ממוענים לפי `line` בתוספת מחרוזת חלקית של `symbol`, ולעולם לא לפי עמודה. מודל שמתבקש לציין עמודה מנחש, וניחוש שגוי נפתר לסמל אחר באותה שורה — תשובה שנראית נכונה ועוסקת במשהו אחר. השמטת `symbol` בפעולת ניווט היא שגיאה, ולא ניחוש של העמודה הראשונה.

| פעולה            | ארגומנטים                        | מחזיר                                    |
| ----------------- | -------------------------------- | ------------------------------------------ |
| `diagnostics`     | `file` (או `"*"`)                | שגיאות ואזהרות; `"*"` מפעיל במקום זאת את בודק הפרויקט |
| `definition`      | `file`, `line`, `symbol`         | היכן שהסמל מוצהר               |
| `type_definition` | `file`, `line`, `symbol`         | היכן שהטיפוס שלו מוצהר                 |
| `implementation`  | `file`, `line`, `symbol`         | מימושים קונקרטיים                   |
| `references`      | `file`, `line`, `symbol`         | כל שימוש, עד 50                    |
| `hover`           | `file`, `line`, `symbol`         | חתימה והערת תיעוד                  |
| `symbols`         | `query` או `file`                | חיפוש בסביבת העבודה עם `query` (עד 100); סמלי מסמך עם `file` (עד 200) |
| `code_actions`    | `file`, `line`, `symbol`         | תיקונים מהירים שהשרת מציע              |
| `status`          | —                                | אילו שרתים פועלים, ועבור אילו שורשים |
| `reload`          | —                                | מפעיל מחדש את השרת עבור השורש הזה          |

### אבחון בכתיבה

הרווח אינו הכלי עצמו. `write`, `edit` ו־`apply_patch` **עטופים**: אחרי הכתיבה הקובץ מסונכרן ונשמר דרך שרת השפה, ורק אבחונים **שהופיעו זה עתה** מקופלים אל תוך תוצאת הכלי. הסוכן לומד שהוא שבר את הבנייה ברגע ששבר אותה, בלי שהיה עליו לזכור לשאול.

אבחונים שכבר דווחו מושתקים על ידי יומן לכל הרצה שממופתח לפי חומרה, קוד והודעה — המיקום הוחרג במכוון, כך שאבחון שפשוט ירד ארבע שורות למטה אינו מדווח מחדש כחדש.

## `lsp_rename` — שינוי שם בכל הפרויקט

כלי נפרד בדרגת `write`, מסיבה אחת בדיוק: הדרגה מכריעה את הנראות. קיפול של שינוי השם אל תוך `lsp` היה או נותן לחוקר לקריאה בלבד את היכולת לשכתב את המאגר, או שם כל `hover` מאחורי בקשת אישור.

| ארגומנט | משמעות                                    |
| -------- | ------------------------------------------ |
| `file`   | היכן שהסמל נמצא                        |
| `line`   | שורה באינדוקס 1                             |
| `symbol` | מחרוזת חלקית שמזהה אותו באותה שורה      |
| `new_name` | איך לקרוא לו                          |

## `ast_grep` — חיפוש מבני

מוצא קוד לפי **צורה** ולא לפי טקסט. `$NAME` מתאים לכל צומת, `$$$NAME` מתאים לרצף של אחים, ו־`$_` הוא תו כללי שאינו לוכד דבר.

התכונה שהופכת אותו למתאים ולא לביטוי רגולרי עם כמה שלבים נוספים: מטא-משתנה שחוזר בתבנית אחת חייב ללכוד את אותו טקסט.

```
ast_grep(pattern: "if ($X != null) $X.dispose()", language: "dart")
```

מתאים לשומר שמשחרר את מה שבדק, ו**אינו** מתאים לכזה שמשחרר משהו אחר.

| ארגומנט      | משמעות                                                     |
| ------------- | ----------------------------------------------------------- |
| `pattern`     | קטע קוד עם מטא-משתנים                          |
| `path`        | קובץ או תיקייה לחיפוש; ברירת המחדל היא כל סביבת העבודה |
| `language`    | מזהה דקדוק שסופק (`dart`, `python`, `rust`, `c`, …). נגזר כאשר `path` מציין קובץ |
| `max_results` | ברירת מחדל 50                                                  |

:::note[התבנית מנותחת לפי אותו דקדוק של הקובץ]
לכן `dispose(x)` מתאים לקריאה בכל ריווח, שבירה או הערה — ולעולם אינו מתאים את אותם התווים בתוך מחרוזת ליטרלית או הערה.
:::

:::caution[קטע מנותח בפיגום, לא לבדו]
`dispose(x)` שמנותח ברמה העליונה של Dart הוא *חתימת פונקציה* תקפה. מהדר התבניות מנסה סולם של הקשרים (הצהרה, ביטוי, איבר מחלקה, הכרזה) ומשתמש בראשון שמקבל את הקטע. תבנית שאף הקשר לא מקבל מדווחת כלא ניתנת לניתוח, במקום לחפש אותה ולא למצוא אותה בשקט.
:::

## `ast_edit` — שכתוב מבני, בהכנה

אותו מיתוג, בתוספת תבנית `rewrite` שאליה מוחזרים המטא-משתנים. **דבר אינו נכתב.** השינוי עובר הכנה, והתוצאה מציינת `edit_id`.

```
ast_edit(pattern: "dispose($X)", rewrite: "$X.dispose()", language: "dart")
→ (proposed) 12 replacements in 4 files … call resolve with edit_id "edit_1"
```

| ארגומנט   | משמעות                                             |
| ---------- | --------------------------------------------------- |
| `pattern`  | מה להתאים                                       |
| `rewrite`  | מה לשים שם, עם `$NAME` מוחלף         |
| `path`     | היקף; ברירת המחדל היא כל סביבת העבודה              |
| `language` | מזהה שפה                                         |

## `resolve` — החלה או ביטול של שינוי שהוכן

| ארגומנט  | משמעות                          |
| --------- | -------------------------------- |
| `edit_id` | מהתוצאה `(proposed)`     |
| `action`  | `accept` או `discard`            |

כל קובץ מושווה מול התוכן שנלכד בזמן ההכנה, ו**כל** אי-התאמה דוחה את השינוי כולו. שכתוב מבני שהוחל חלקית משאיר עץ שאינו מתקמפל לפי אף אחת מהצורות — לא הישנה ולא החדשה.

## `debug` — הפעלת מנפה

נרשם כאשר להרצה יש מפקח סשן ניפוי, תיקיית עבודה ומזהה שיחה. אם מתאם באמת יכול לעלות מתגלה בזמן הקריאה, לפי אותו כלל חיתוך של שרת השפה (סמן שורש *וגם* קובץ הרצה). דרגת `exec`; אינו בטוח להרצה מקבילה (סשן הוא מצב שנמשך בין קריאות, ולכן `continue` שעוקף את `stack` יקרא מסגרת שכבר זזה).

סשן אחד לכל שיחה, עם TTL קשוח (30 דקות). `launch` שני נדחה במקום להחליף בשקט את הראשון. בהרצה בתוך ארגז חול הסשן שומר על ארגז החול שלו לאורך התורות עד לסיומו, ולכן לכל היותר למשך 30 הדקות האלה.

| פעולה            | ארגומנטים                     | הערות                                          |
| ------------- | ----------------------------- | ---------------------------------------------- |
| `adapters`    | —                             | אילו מתאמים שמישים כאן, ומדוע לא     |
| `status`      | —                             | אם סשן פועל, והיכן הוא נעצר |
| `breakpoints` | `file`, `lines[]`             | `lines` ריק מנקה את הקובץ. אפשר להציב **לפני** ההפעלה |
| `launch`      | `program`, `args[]`           | מפעיל את התוכנית כשהיא עצורה בנקודות העצירה שלכם |
| `attach`      | `port`                        | מתחבר לתוכנית מנופה שכבר רצה, רק על אחד מהפורטים המועברים של ההרצה עצמה; כל פורט אחר נדחה לפני שמשהו מתחיל |
| `continue`    | `thread_id?`                  | רץ עד לעצירה הבאה                        |
| `pause`       | `thread_id?`                  | עוצר אותו במקום שבו הוא נמצא                            |
| `step_over` / `step_in` / `step_out` | `thread_id?` | מתקדם צעד אחד                          |
| `threads`     | —                             | מזהי תהליכונים ושמותיהם                            |
| `stack`       | `thread_id?`                  | מסגרות, עד 30                            |
| `scopes`      | `frame_id`                    | תחומים במסגרת, לכל אחד `reference`      |
| `variables`   | `reference`                   | ילדים, עד 50, ערכים עד 400 תווים |
| `evaluate`    | `expression`, `frame_id?`     | מחושב בתחום של המסגרת עצמה              |
| `output`      | —                             | ה־stdout/stderr של התוכנית המנופה, חסום           |
| `terminate`   | —                             | מסיים את הסשן והורג את המתאם          |

### מתאמים

| מזהה        | פקודה                    | סמני שורש                                    |
| --------- | -------------------------- | ----------------------------------------------- |
| `dart`    | `dart debug_adapter`       | `pubspec.yaml`                                  |
| `debugpy` | `python3 -m debugpy.adapter` | `pyproject.toml`, `setup.py`, `requirements.txt` |
| `lldb`    | `lldb-dap`                 | `Cargo.toml`, `CMakeLists.txt`                  |
| `delve`   | `dlv dap`                  | `go.mod`                                        |

`debugpy` מעדיף `.venv/bin` או `venv/bin` מקומיים לפרויקט על פני `$PATH` כאשר ההרצה רצה בארגז חול: מפרש `python` מ־`$PATH` הוא סביבה אחרת, והתחברות מהלא נכון נכשלת באופן שנראה כמו קוד שבור. בלי ארגז חול הוא משתמש ב-`$PATH` בלבד, כך שמאגר אינו יכול לבחור את המפרש שרץ על המארח.

## `repl` — הרצת סקריפט שקורא לכלים שלכם

מופיע בכל הרצה כששרת יכול להריץ סקריפטים ([כשלהרצה יש `repl`](/he-IL/מדריך-למשתמש/מושגים/מצב-קוד/#כשלהרצה-יש-repl)). הסקריפט הוא JavaScript רגיל, גוף של פונקציית async, ורץ במפרש חדש ונעול בתהליך משלו: בלי גישה למערכת הקבצים, לרשת, לתהליכים או למודולים. `repl` עצמו שייך לשכבת `read` ומגן על עצמו, כי כל קריאה לכלי שהסקריפט מבצע נבדקת לגופה. הוא מופיע גם בנקודת הקצה של MCP, להרצות סוכן בשרת שיכול להריץ סקריפטים.

| ארגומנט | משמעות |
| ------------------- | --------------------------------------------------------------------------------------------- |
| `code` | הסקריפט. עד 256 KiB |
| `description` | חובה. תווית קצרה לשורה בתמלול |
| `timeout_ms` | אופציונלי. זמן קצוב קצר מזה של סביבת העבודה, לעולם לא ארוך ממנו |
| `max_output_tokens` | אופציונלי. תקציב פלט קטן מזה של סביבת העבודה, לעולם לא גדול ממנו |

```js
// Read three files together and report only which ones failed.
const paths = ["lib/a.dart", "lib/b.dart", "lib/c.dart"];
const results = await Promise.allSettled(paths.map((path) => tools.read({ path })));
return results
  .map((r, i) => (r.status === "rejected" ? `${paths[i]}: ${r.reason.message}` : null))
  .filter(Boolean);
```

תיאור `repl` אומר לסוכן: „לכלי שאינו מהכלים הישירים שלך אין הגדרה בבקשה הזו. לפני הקריאה הראשונה אליו, חפש אותו עם `describeTool(name)` או `searchTools(query)`, אלא אם צורת הקריאה המדויקת שלו כבר הוצגה לך בשיחה הזו.”

`describeTool(name)` מחזיר את התיאור של כלי, ההצהרה שלו, סכימות הקלט והפלט שלו ואת הערת התוצאה שלו, כשיש כזו: מה שהסקריפט מקבל מקריאה שהסתיימה, במילים של הכלי עצמו. התיאור של `repl` מפרט את הערות הכלים הישירים שסקריפט רשאי לקרוא להם. תוצאה של כלי שהיא טקסט JSON מגיעה מפוענחת, אלא אם יש בה יותר מ-131,072 ערכים: אז היא מגיעה כטקסט, והסקריפט מפענח אותה בעצמו עם `JSON.parse`. טקסט של תוצאה מכלי של שרת MCP חיצוני מקוצר אחרי 262,144 תווים, וטקסט מקוצר כבר אינו מתפענח.

- `tools.<name>(args)` קורא לכלי דרך אותו מסנן, מעקות הבטיחות ואישור כמו קריאה ישירה, ונדחה עם שגיאה כשהקריאה נדחית או נכשלת. קריאות לקריאה בלבד יכולות לרוץ יחד; קריאות ששונות דבר רצות אחת אחרי השנייה, לפי הסדר שבו הסקריפט ביצע אותן. בזמן שאחת מהקריאות שלו ממתינה לאדם, אף קריאה אחרת של הסקריפט לא מתחילה.
- `ALL_TOOLS`, `searchTools(query, { limit, namespace })`, `describeTool(name)` ו-`describeNamespace(name)` מוצאים כלים, כולל אלה של שרתי MCP מחוברים. כלי מחוץ לקבוצה הישירה שסקריפט רשאי לקרוא לו נקרא רק מסקריפט; קריאה ישירה לאחד מהם מחזירה איך לקרוא לו מ-`repl`. מרגע שהשרת לא יכול להריץ את הסקריפטים של ההרצה, כלי כזה נטען בשימוש הראשון במקום.
- מגבלות על חיפושים: שאילתה עד 1,024 תווים, שם או מרחב שם עד 256, `limit` מ־0 עד 50, ועד 200 חיפושים שנמשכים 2 שניות מזמן השרת בסך הכול לכל סקריפט, בעוד שכל הסקריפטים של סביבת עבודה אחת חולקים 2 שניות של זמן חיפוש, שמוחזרות ברבע שנייה בכל שנייה; מעבר לאחת מהמגבלות, חיפושים נוספים נדחים. בקטלוג גדול מאוד התיאורים ב־`ALL_TOOLS` חולקים באופן שווה כמיליון תווים, ותיאור שנחתך מסתיים ב־`…`; `describeTool` תמיד מחזיר את התיאור כולו. טיפוס גדול מכדי להציג מוצג כ־`unknown /* too large to show */`, ושם לא ידוע מקבל תשובה עם השמות הקרובים ביותר.
- הכלים מקובצים במרחבי שמות: `builtin` (הכלים של הרתמה עצמה), `control-center` (הכלים של Control Center) ומרחב אחד לכל שרת MCP מחובר, הנקרא על שם השרת. שרת ששמו `builtin`, `control-center` או `script`, או ששמו מתחיל ב־`external-`, בכל שילוב של אותיות גדולות וקטנות ובין אם יש רווחים סביבו ובין אם לא, מופיע כ־`external-` ואחריו שמו, ואף כלי לא נמצא לעולם ב־`script`.
- רק מה שהסקריפט מחזיר, או מעביר ל-`text()`, `image()` או `console.*`, חוזר לסוכן. פלט מעבר לתקציב שומר על ההתחלה והסוף שלו, וכלי `read_output` קורא את השאר.
- `store(key, value)` / `load(key)` שומרים ערכי JSON לסקריפטים מאוחרים יותר של אותה שיחה ואותו סוכן, ונשמרים רק כשהסקריפט מסתיים. לסקריפטים של סוכן משנה אין מאגר.
- `await tools.ask_user(...)` שואל שאלה; התשובה שלה נוספת גם לתוצאה. `sleep(ms)`, `setTimeout`, `limits()` ו-`models.embed` / `rank` / `classify` (הטמעות על המכשיר) זמינים גם הם.
- `describeTool(name)` ו-`searchTools(query)` עונים גם על הפונקציות של הסקריפט עצמו, שאינן כלים: `text`, `image`, `store`, `load`, `sleep`, `setTimeout`, `clearTimeout`, `limits`, `exit` ו-`models.*`, תחת מרחב השמות `script`.
- לא ניתנים לקריאה מסקריפט: `repl`, `eval`, `task`, `checkpoint`, `rewind`, `compact`, `search_tools` וכלי ה-`vibe_*`.
- סקריפט קורא את העבר של ההרצה שלו עצמה: `history({start, role, tool, limit})` מדפדף בתמליל השיחה (לכל היותר 50 שורות בקריאה; מעבירים את `next_start` של הדף הקודם כ-`start`), `outputs()` מפרט את הפלטים של כלים שנשמרו לשיחה ולסוכן הזה, ו-`loadOutput(handle)` קורא 16,384 תווים מאחד מהם. `storedKeys()` מפרט את המפתחות השמורים עם הגדלים שלהם. `keep(value, label)` שומר ערך גדול כפלט שסקריפט מאוחר יותר או `read_output` יכולים לקרוא, ונשמר רק כשהסקריפט מסתיים (1 MiB לערך, 64 ערכים ו-16 MiB להרצה). `limits().returnBudgetChars` מראה כמה מתקציב הפלט נותר. הרצה לקריאה בלבד (סקירת מטרה) יכולה לקרוא, אבל לא לשמור או לעשות keep. ב-Claude Code וב-ACP, `history()` עובד, ואילו `outputs()`, `loadOutput()` ו-`keep()` מסרבים, כי Control Center אינו שומר פלטי כלים של ההרצות האלה.
- שגיאה מפסק זמן, מגודש פלט או ממגבלת הקריאות אומרת איך לתקן אותה.

הרצה אחת מריצה סקריפט אחד בכל פעם. המגבלות ומה קורה בכל אחת מהן מופיעות בדף [מצב קוד](/he-IL/מדריך-למשתמש/מושגים/מצב-קוד/#מגבלות); כל סקריפט נרשם תחת **ניטור ← הרצות קוד**.

## `eval` — מפרשים מתמשכים

תא Python או JavaScript שהמשתנים, הייבואים והנתונים שנטענו בו ממשיכים להתקיים בין קריאה לקריאה. דרגת `exec`; אינו בטוח להרצה מקבילה. אי אפשר לקרוא לו מסקריפט של `repl`, ותא לא יכול לקרוא לכלים של ההרצה: כדי לקרוא לכלים מקוד, השתמשו ב-[`repl`](#repl--הרצת-סקריפט-שקורא-לכלים-שלכם).

| ארגומנט      | משמעות                                          |
| ------------- | ------------------------------------------------ |
| `code`        | התא                                         |
| `description` | חובה. 5–10 מילים לתווית בתמלול    |
| `language`    | `python` (ברירת מחדל) או `javascript`               |
| `reset`       | משליך את המפרש ומתחיל נקי מלכתחילה    |

- הביטוי האחרון מוצג חזרה כפי שמחברת עושה.
- `display()` עובד, DataFrame של pandas מרונדר כטבלה, ואיור של matplotlib חוזר כ**תמונה שהתמלול מציג**.
- הקיצורים של IPython שאנשים מקלידים מתוך הרגל — `%pip`, `%cd`, `!cmd`, `%%bash`, `%%timeit` — נכתבים מחדש כקוד רגיל. `%pip` גם מפנה את `sys.modules`, כך שה־`import` הבא רואה את מה שזה עתה הותקן.
- תא שמדפיס יותר מתקציב הפלט שלו שומר את שלושת הרבעים הראשונים ואת הרבע האחרון, עם שורה אחת שאומרת כמה תווים ותמונות נשמטו.
- כשהמפרש נפל בלי שביקשו ממנו, התא הבא מקבל הודעה חד־פעמית שהמשתנים הקודמים שלו אבדו.

:::note[היכן הקרנל רץ]
בתוך המתחם המבודד של השיחה כשיש לה כזה, ואחרת בארגז החול של ההרצה על המארח. בלי ארגז חול, או כאשר הוא אינו זמין, הוא רץ ללא בידוד, ו-`eval` מבקש אישור הרצה על המארח. הוא אינו מפעיל מתחם מבודד לשם כך — אותו כלל שמונע מלשונית תחנה לעלות מעצמה.
:::

## `bash` ברקע

`bash` עם `run_in_background: true` מתחיל את הפקודה וחוזר מיד עם ידית (`b1`, `b2`, …) במקום לחכות. הסוכן ממשיך לעבוד, או מסיים את התור שלו ומתעורר כשהפקודה יוצאת.

| ארגומנט | משמעות |
| ------------------- | ------- |
| `run_in_background` | `true` כדי להתחיל ולחזור מיד |
| `timeout_seconds` | שניות לפני שהפקודה נהרגת: 600 כברירת מחדל, 3,600 לכל היותר |
| `notify` | אופציונלי. תבנית פשוטה; כל שורת פלט שמתאימה לה נשלחת לסוכן בזמן שהפקודה רצה (למשל `listening on\|FAILED`) |

- לכל היותר 4 פקודות ברקע רצות בבת אחת בהרצה אחת. כל אחת נהרגת בפסק הזמן שלה וכשההרצה מסתיימת, יחד עם כל תהליך שהפעילה.
- כשפקודה יוצאת, הסוכן מקבל הודעה עם קוד היציאה, 2,000 התווים האחרונים של הפלט וידית `read_output` לשאר.
- סוכן שהעבודה היחידה שנותרה לו היא פקודה ברקע ממתין בלי לקרוא למודל, ושומר השקט של ההרצה מושהה בזמן ההמתנה.
- `bash_output(handle)` קורא את המצב והפלט האחרון של פקודה; `bash_kill(handle)` עוצר אותה. שניהם אומרים מתי התוצאה כבר נמסרה.
- סקריפט לא יכול להתחיל פקודה ברקע. ל-Claude Code יש Bash ברקע משלו; Control Center משאיר את ההרצה הזו פתוחה לכל היותר 10 דקות אחרי התור שהשאיר משימה רצה.

## `compact` — פינוי מקום בחלון ההקשר

דוחס את ההקשר הישן יותר של השיחה לפני הקריאה הבאה למודל, ושומר את מה ש-`focus` מציין (לכל היותר 1,000 תווים). התורות החדשות ביותר נשארות כלשונן. שורת התקציב של הסוכן לכל תור מציגה את השימוש בהקשר ב-70, 80 ו-90%, ושווה לקרוא לכלי אחרי כ-70% לפני שלב עבודה חדש וארוך. הוק `preCompact` של בעל השרת יכול להוסיף למוקד ([הוקי Shell](/he-IL/מדריך-למשתמש/עזר/הגדרת-סוכן/#הוקי-shell)). אחרי דחיסה, השרת מוסיף בלוק "Still in flight": המטרה, השכמות ממתינות, שאלות פתוחות, פקודות ברקע, רשימת המשימות והמפתחות השמורים, כל אחד עם הקריאה שמשחזרת אותו.

## `ask_user` — לשאול את האדם שאלה

דרגת `read`. הדרך ה**יחידה** שבה הרצה שואלת את המפעיל משהו. הוא מרנדר כרטיס ממוספר בשיחה וחוסם עד שמישהו עונה, מדלג, או שתפוג תקופת ההמתנה של השאלה. לעולם אל תכתבו את השאלה כהודעת צ'אט — זה מסיים את התור.

| ארגומנט       | משמעות                                    |
| -------------- | ------------------------------------------ |
| `question`     | מה לשאול                                |
| `context`      | אופציונלי: מדוע אתם שואלים ומה תלוי בתשובה |
| `options[]`    | אפשרויות, כל אחת `{label, description?}`      |
| `allow_free_text` | אם תשובה מוקלדת מתקבלת       |
| `multi_select` | אם אפשר לבחור כמה אפשרויות      |

דילוג הוא הצלחה: המשיכו על בסיס הנחה מוצהרת ואל תשאלו שוב. פג־זמן הוא שגיאה עם אותה הנחיה. בקשות אישור ("האם מותר לי לעשות את זה?") הן שער נפרד ומרונדרות כאותו כרטיס בשיחה.

נרשם רק כאשר קיימים גם יציאת שאלות וגם מרחב יעד. בלי אדם מחובר הקריאה **נכשלת** במקום להיחסם לנצח — אותה תנוחת כשל־סגור שנוקטת הכרעת `prompt` של מעקה בטיחות כשאין מאשר מחובר.

## `vibe_*` — הכוונת עובדי רקע

נרשמים רק כשמצב [vibe](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/הכוונת-עובדי-רקע/) פעיל. כל החמישה בדרגת `read`: השער שייך לכלים של העובד, שם העריכה באמת קורית.

| כלי         | ארגומנטים                                | הערות                                       |
| ------------ | ---------------------------------------- | ------------------------------------------- |
| `vibe_spawn` | `brief`, `label`, `tier?`                | חוזר מיד; העובד ממשיך לרוץ     |
| `vibe_send`  | `worker_id`, `message`                   | מוסיף לתדרוך ומריץ מחדש            |
| `vibe_wait`  | `worker_id`, `timeout_seconds?`          | חוסם עד שהוא מגיע למצב סופי                     |
| `vibe_kill`  | `worker_id`                              | עוצר אותו                                    |
| `vibe_list`  | —                                        | דרגה, מצב, זמן שחלף ותוצאה אחרונה       |

`tier` הוא `fast` (עבודה מכנית עם מפרט ברור) או `good` (עיצוב, שיקול דעת, או סקירה של הפלט של עובד `fast`).
