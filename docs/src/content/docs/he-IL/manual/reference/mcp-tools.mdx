`cc_server` מארח מרשם כלים אחד של MCP (‏JSON-RPC 2.0), הנחשף בפורט הראשי של השרת (ברירת מחדל `9030`) בנתיבים `POST /mcp` ו-`GET /sse`, בגרסת פרוטוקול `2024-11-05`. כל לקוח מגיע לאותו מרשם: היישום השולחני, גרסת הווב, לקוחות MCP חיצוניים ומנגנון ההרצה המובנה של הסוכן. שרתי MCP חיצוניים משתלבים באותו מרשם בשכבות משלהם: שכבה אחת לכל סביבת עבודה עבור השרתים שמנהליה מגדירים, ושכבה אחת לשרתים שכל חבר הוסיף לעצמו בה. נקודת קצה זו מציגה, מפעילה ומחפשת אותם רק עבור הרצה של סוכן: שרתי סביבת העבודה שלו, בתוספת השרתים שהחבר שהפעיל את ההרצה הוסיף לעצמו. אסימון ה-MCP והמכשירים המזווגים לעולם אינם רואים אותם (ראו [שרתי MCP שהסוכנים שלך משתמשים בהם](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/שרת-mcp/#שרתי-mcp-שהסוכנים-שלך-משתמשים-בהם)).

## גודל המרשם

| מדד                                                                        | מספר |
| ------------------------------------------------------------------------- | ----- |
| כלים ש-`cc_server` רושם                                                    | 116   |
| מ-`packages/cc_mcp`                                                       | 114   |
| מ-`packages/cc_mcp_client` (גילוי כלים)                                    | 2     |
| נרשמים במרשם הבסיס (`server_mcp_registry.dart`)                            | 64    |
| נרשמים לאחר האתחול כשהשירותים שלהם עולים (`cc_server_runtime.dart`)        | 52    |
| מתוך 64 של מרשם הבסיס, מותנים במאגר גרף קוד                                 | 5     |
| מתוך 64 של המרשם הבסיסי, בתנאי שמפעיל מצב הקוד קיים (`repl`) | 1 |

חמשת כלי גרף הקוד נרשמים רק כשהמארח מעביר מאגר גרף קוד אל `buildServerMcpRegistry`, ו-`repl` נרשם רק כשהוא מעביר את מפעיל מצב הקוד. `cc_server` תמיד מעביר את שניהם (הוא לא עולה בלי המפעיל), ולכן כל 111 הכלים רשומים בבינארי המשולח; שרת ההדגמה הציבורי לא רושם את `repl`.

המרשם המלא מוצהר ב-`tools/list` בלי שער גילוי, חוץ מהרצת סוכן שיכולה להריץ סקריפטים (למטה). עריכות כרטיסים מתבצעות בכלים בעלי טיפוסים מוגדרים.

:::note[לקוחות חיצוניים תמיד רואים את כל הקטלוג]
`tools/list` לעולם אינו מקוצר, חוץ משרתי ה-MCP שכל חבר הוסיף לעצמו, שהרשימה כוללת רק עבור הרצה שהבעלים שלהם הפעיל, וכן [מצב קוד](/he-IL/מדריך-למשתמש/מושגים/מצב-קוד/): `repl` נכלל ברשימה רק להרצת סוכן בשרת שיכול להריץ סקריפטים, ולהרצה כזו נכללים ברשימה `repl`, הכלים הישירים (`read`, `write`, `edit`, `search`, `find`, `bash`, `read_output`, `ask_user`, `task`, `todo_write`, `search_memory`, `send_message` והפעלים הקבועים של המצב שלה, במקום שהמרשם מכיל אותם) וכלים שסקריפט לא רשאי לקרוא להם. היא קוראת את השאר מסקריפט; קריאה ישירה לאחד מהם נענית בתשובה על איך לקרוא לו מ-`repl`. לקוחות MCP מאמתים שמות כלים מול העותק השמור שלהם של הרשימה הזו ומסרבים לכל דבר שאינו ברשימה בלי לשאול את השרת, כך שכלי שמוסתר שם הוא בלתי נגיש, ולא סתם שקט.

**מנגנון ההרצה המובנה** שונה: הוא טוען רק קבוצה ישירה קטנה של הגדרות בכל בקשה ומגיע לשאר מסקריפטים או טוען אותם בשימוש הראשון, וזו התנהגות של המנגנון שאינה משנה את המרשם הזה. ראו [הקשר כלים ומטמון הנחיות](/he-IL/מדריך-למשתמש/מושגים/הקשר-כלים/).
:::

:::note[כל מחלקת כלי נרשמת]
קובץ מקור תחת `packages/cc_mcp/lib/src/tools/` הוא כלי שסוכן יכול לקרוא לו. `packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart` מכשיל את הבנייה אם שום דבר לא בונה מחלקת כלי חדשה.
:::

## פרמטרים משותפים

### `workspace_id`

**חובה** בכל כלי שנוגע בנתונים בעלי היקף של סביבת עבודה. `workspace_id` חסר או שגוי מחזיר שגיאה מפורשת, וערך שאינו תואם את סביבת העבודה של הישות שאליה הוא מכוון נדחה ולא מתעלמים ממנו בשקט. השמיטו אותו בכלים גלובליים באמת: `list_workspaces` וששת כלי עדכוני החדשות (`list_feeds`, `list_articles`, `get_article`, `set_article_read`, `set_article_saved`, `refresh_feeds`), שנשענים על רשימת הפידים האישית של בעל השרת. כלי הגילוי (`search_tool_bm25`, `list_my_tools`) מקבלים אותו באופן אופציונלי כדי שיוכלו לסווג את יכולת הקריאה לפי מצב השיחה. כשהשרת שולח סוכן, סביבת העבודה נכפית בצד השרת, כך שהסוכן אינו יכול להגיע לסביבת עבודה אחרת באמצעות מזהה זר.

## גילוי כלים

שניהם מגיעים מ-`cc_mcp_client` ולא מ-`cc_mcp`, ושניהם מתייעצים עם שומר המצב כדי לדווח מה ניתן לקריאה ב_מצב השיחה הנוכחי_.

| כלי                | תיאור                                                                                                                        |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `search_tool_bm25` | חיפוש בקטלוג הכלים לפי מילת מפתח; מחזיר כלים תואמים, את סכימות הארגומנטים שלהם ואם כל אחד מהם ניתן לקריאה כרגע                 |
| `list_my_tools`    | הצגת הכלים הניתנים לקריאה כרגע בשיחה הזו, מסוננים לפי המצב שלה                                                                |

כלי גילוי שלישי, **`search_tools`**, קיים רק בתוך מנגנון ההרצה המובנה ואינו חלק ממרשם ה-MCP הזה. הוא מדרג את משטח הכלים של ההרצה עצמה, ובשונה מ-`search_tool_bm25` הוא **טוען** את הסכימות של מה שהוא מוצא כדי שהסוכן יוכל לקרוא לתוצאה מתאימה בתור הבא שלו. סוכנים שרצים על המנגנון צריכים להעדיף אותו; ללקוחות MCP יש את `search_tool_bm25`.

## מצב קוד

| כלי | תיאור |
| ------ | ----------- |
| `repl` | מריץ סקריפט JavaScript שקורא לכלים האחרים של ההרצה כ-`tools.<id>(args)` ומחזיר רק את מה שהוא צריך. מופיע ברשימה רק להרצת סוכן בשרת שיכול להריץ סקריפטים של [מצב קוד](/he-IL/מדריך-למשתמש/מושגים/מצב-קוד/). כל קריאה מקוננת עוברת את אותו שער כמו `tools/call`. מקבל `code`, `description`, `timeout_ms?`, `max_output_tokens?`         |

סקריפט לא יכול לקרוא ל-`repl`, `search_tool_bm25`, `list_my_tools`, או לכל כלי שמפעיל או שולח הודעה להרצת סוכן אחרת, משייך כרטיס או מגיב עליו, שולח הודעה, יוצר, מכריע או מגיב על אישור, מציע או משנה מדיניות, מתקין או משנה מיומנויות, יוצר פרופיל הרצה, מגיש תוכנית או יוצא ממצב תוכנית, משלים את מטרת השיחה או מגיש את הפלט של הרצת פייפליין. לכלים האלה מוצהר `scriptCallable` כ-false, והם תמיד נקראים ישירות; ברתמה המובנית כלי מחוץ לקבוצה הישירה נטען בשימוש הראשון. `create_ticket` ניתן לקריאה מסקריפט רק בלי `assignee`.

## הודעות בין סוכנים עמיתים והאצלה

סוכנים מדברים זה עם זה דרך מרחבים (עמידים, גלויים בסגל). `ask_agent` או מחכה לתשובה (`mode: wait`, 600 שניות כברירת מחדל, 1,800 לכל היותר) או חוזר מיד (`mode: background`); בשני המקרים השואל מתעורר פעם אחת עם התשובה כשהיא לא חזרה בתוך השורה. `send_to_agent`, `ask_agent`, `consult_agent`, `request_peer_review` ו-`delegate_task` עוברים את אותו שער בצד השרת: עומק (3), זיהוי מעגלים, מעטפת תקציב, תקרת אוטונומיה ומגבלת קצב לכל זוג סוכנים. הזהות של השולח תמיד מגיעה מההרצה הקוראת. ראו [סוכנים שעובדים יחד](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/סוכנים-עובדים-יחד/).

| כלי             | תיאור                                                                                          |
| --------------- | ---------------------------------------------------------------------------------------------- |
| `send_to_agent` | שליחת הודעה חד-כיוונית לסוכן אחר, במיעון לפי `to_agent_id` או `to_agent_name` מדויק; עונה `delivery_status` עם `woken`, `queued_behind_run` או `refused` |
| `ask_agent`     | שאילת שאלה מסוכן אחר; המתנה לתשובה או המשך והתעוררות כשהיא מגיעה                                 |
| `delegate_task` | האצלת משימה לסוכן אחר ככרטיס ילד במעקב                                                          |
| `consult_agent` | הוספת המומחה המתאים ביותר לפי מיומנויות אל המרחב ושליחתו עם תדריך ממוקד                          |
| `todo_read`     | קריאת רשימת המשימות הנשמרת של השיחה הזו                                                         |
| `agent_activity` | קריאה של מה שסוכן אחר עושה עכשיו ומה שעשה לאחרונה (סטטוס, הכלי הנוכחי, ההודעות האחרונות), בלי להעיר אותו |

## כלי השכמה ומטרה

סוכן משתמש באלה במקום לישון או לבדוק שוב ושוב. כל אחד פועל רק עבור הסוכן הקורא בשיחה שלו; הסוכן לעולם אינו ארגומנט. ראו [לוחות זמנים והשכמות](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/לוחות-זמנים-והשכמות/) ו-[השגת מטרה](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/השגת-מטרה/).

| כלי | תיאור |
| ------------- | ----------- |
| `wake_me` | לתזמן התעוררות מאוחר יותר: בזמן (`in:20m`, `at:<ISO time>`), במרווח (`every:30m`), לפי cron (`cron:0 9 * * 1-5`, עם `tz`), בקצב עצמי בתוך לולאה בקצב עצמי (`next`, עם `delay` מ-1 עד 60 דקות), או כשמשהו קורה (`on:pr_checks`, `on:pr_review`, `on:pr_merged`, `on:environment`, `on:ticket:<id>`, `on:pipeline_run:<id>`). אופציונלי: `note`, `max_runs`, `expires_in`, `when_busy` (`skip` או `queue`) ו-`deliver` (`run` או `notify`) |
| `list_wakes` | רשימה של מה שהסוכן ממתין לו בשיחה הזו: לוחות זמנים, מעקבים, השכמות ממתינות ושאלות ללא מענה |
| `cancel_wake` | ביטול לוח זמנים או מעקב שהסוכן קבע לעצמו, לפי המזהה שלו |
| `goal_status` | קריאה של המטרה הפעילה של הסוכן: החוזה, המקטע, ההוצאה והתקציב שנותר, סימוני חוסר התקדמות, ההחזקה, האימות האחרון והשכמות מטרה ממתינות |

`complete_goal` (תחת [כלי תוכנית, פלייבוק וארטיפקט](#כלי-תוכנית-פלייבוק-וארטיפקט)) הוא הדרך היחידה שבה סוכן אומר שמטרה הושלמה, והוא טענה, לא השלמה.

## כלי מתחם מבודד (תחנה)

הפעלת מכונות חד-פעמיות — דפדפן או שולחן עבודה של Linux במתחם מבודד,
אמולטור של Android או סימולטור iOS — מתוך הרצה. נרשמים לאחר האתחול,
ללא תנאי: האם מכונה מסוגלת באמת לעלות היא שאלת בדיקה שהכלים עונים עליה בכל
קריאה. קריאות חוזרות באותה שיחה עושות שימוש חוזר במכונה אחת; צילומי מסך חוזרים
כתוכן תמונה עם תקציב של תמונה אחת לכל תוצאה, ותוכן דף/ממשק שחולץ מגודר כנתון לא
מהימן. ארבעת כלי השימוש יחד עם `rig_close` מצהירים על [מחלקת הפעולה](/he-IL/מדריך-למשתמש/מושגים/מעקות-בטיחות/)
`enclosureControl` (כלי השימוש מצהירים גם על `networkEgress` ו-`processSpawn`;
`mobile_use` ו-`ios_use` מצהירים גם על `packageInstall`), ולכן מצבים לקריאה
בלבד חוסמים אותם. `rig_list` אינו מצהיר על דבר — הוא רק קורא את מצב סביבת
העבודה. מלוא אוצר הפעלים לכל משטח נמצא ב[מדריך העזר לתחנות](/he-IL/מדריך-למשתמש/עזר/תחנות/#פעלים).

| כלי            | תיאור                                                                                                                              |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `computer_use` | הפעלת שולחן עבודה של Linux במכונה וירטואלית מבודדת: הזזה, לחיצה, גרירה, גלילה, הקלדה, שינוי גודל, לוח גזירים, צילום מסך          |
| `browser_use`  | הפעלת Chromium, Firefox או WebKit ללא ממשק (`engine`): ניווט, לחיצה, מילוי, חילוץ (a11y/DOM/console), לוח גזירים, צילום מסך           |
| `mobile_use`   | הפעלת Android דרך ADB: בדיקה וקלט, צילומי מסך, התקנה/הפעלה/עצירה/איפוס/הסרה של אפליקציות, קישורים עמוקים ופקודות מכשיר בצורת argv    |
| `ios_use`      | הפעלת סימולטור iOS דרך WebDriverAgent/CoreSimulator: בדיקה וקלט, צילומי מסך, התקנה/הפעלה/עצירה/הסרה של אפליקציות, קישורים עמוקים ותהליכי סימולטור בצורת argv |
| `rig_list`     | הצגת התחנות של מרחב ההרצה עם המשטח, הסטטוס, גודל התצוגה והבקר                                                                       |

רק הרצות סוכן יכולות לקרוא לכלים האלה; כל מתקשר אחר נדחה. הרצה מגיעה רק לתחנות של המרחב שאליו הוקצתה: `space_id` מגיע מההענקה של ההרצה, לעולם לא מהקריאה, ותחנה של מרחב אחר, או של אף מרחב, עונה בדיוק כמו תחנה שאינה קיימת.

`app_use` הוא כלי use חמישי: הוא מפעיל את החלונות של אפליקציית שולחן עבודה שהופעלה במרחב, ישירות על המארח ולא ב-VM, ומצהיר גם על `fileWriteOutsideWorktree` ו-`fileDelete`. הוא וכלי `environment_*` מתוארים ב[הגדרת סביבות](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/סביבות/).

## לא נחשף דרך MCP

ללוח השנה ולפגישות אין כלי MCP. סוכנים אינם יכולים לקרוא את לוח השנה, הפגישות, התמלולים, פריטי הפעולה או ההחלטות שלכם. הסיכום שמייצר פריטי פעולה והחלטות רץ כפייפליין המובנה [`meeting_summary`](/he-IL/מדריך-למשתמש/מושגים/פגישות/), ולא ככלי שסוכן יכול לקרוא לו.

## שער כלים לפי מצב

השער נאכף פעמיים מאותה טבלה (`ModeToolPolicy`): פעם אחת במפעיל ה-MCP עבור מתאם Claude Code, ופעם אחת במרשם מנגנון ההרצה המובנה. קריאה חסומה מחזירה את הסיבה.

| מצב           | משטח כלים                                                                                                                                                                                                                             |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`        | כל כלי רשום; בלי רשימת היתר                                                                                                                                                                                                          |
| `plan`        | רשימת היתר מצומצמת. אין כתיבה לעצי עבודה ואין פעלי כרטיס `create` / `assign` / `delegate`, אבל זיכרון, ארטיפקטים, רשימות משימות, `submit_plan`, `exit_plan_mode` ופעלי השלמת הכרטיס על הכרטיס שנשלח מותרים                             |
| `review`      | רשימת היתר מצומצמת: השתתפות בסקירה, תקשורת, מביאי הקשר לקריאה בלבד ומלוא מערכת פעלי הכרטיס, כולל `create_ticket` ו-`assign_ticket`                                                                                                     |
| `orchestrate` | רשימת היתר מצומצמת: כלי מחקר וקריאה בתוספת `propose_orchestration`, `create_playbook` ו-`run_playbook`. גיוס, פירוק לתת-משימות והשלמת כרטיסים קורים באופן דטרמיניסטי לאחר האישור, ולעולם לא באמצע ההרצה                                    |

מותרים בכל מצב, ללא תלות ברשימת ההיתר:

| קבוצה              | כלים                                                                                                                                                                                                                                                              |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| זיכרון וארטיפקטים  | `search_memory`, `propose_fact`, `propose_policy`, `supersede_fact`, `supersede_policy`, `record_observation`, `update_my_notes`, `get_my_notes`, `list_memory_domains`, `list_policies`, `publish_artifact`, `revise_artifact`, `list_artifacts`, `get_artifact` |
| גרף קוד            | `search_code`, `code_symbol`, `code_callers`, `code_callees`, `code_impact`                                                                                                                                                                                       |
| מכניקת הרצה        | `search_tool_bm25`, `list_my_tools`, `todo_write`, `todo_read`                                                                                                                                                                                                    |

הכללת כלי ברשימת היתר אינה הופכת אותו לקריא, וההפך נכון גם כן: היכולת לשאול את המפעיל היא כלי של **מנגנון ההרצה** (`ask_user`), ולכן היא כלל אינה מופיעה בקטלוג ה-MCP הזה.

## כלים הדורשים אישור

כלי יכול להצהיר `requiresApproval`. מפעיל ה-MCP בונה אז `ApprovalPayload` וחושף אותו דרך `ConfirmationPort` לפני שהכלי רץ; `cc_server` מחבר את הפורט הזה, ולכן השער פעיל.

כלים רשומים שמצהירים עליו: `create_ticket`, `update_ticket`, `assign_ticket`, `reassign_ticket`, `close_ticket`, `ticket_relation`, `create_goal`, `update_goal_progress`, `create_approval`, `decide_approval`, `comment_approval`, `create_work_product`, `save_work_product_revision`, `create_runtime_profile`, `install_skill`, `update_skill`.

באופן בלתי תלוי, מעקות הבטיחות המאוחדים של הפעולות שמים שער על כל כלי שמצהיר על סט לא ריק של `ActionClass`. החלטת `prompt` בלי מאשר מחובר נדחית. ראו [מעקות בטיחות](/he-IL/מדריך-למשתמש/מושגים/מעקות-בטיחות/).

## יכולות בלי כלי מאחוריהן

לא כל יכולת במוצר נגישה לסוכן. לאלה אין כלי
כלל, ולכן שם שאולי ראיתם במקום אחר מחזיר "unknown tool":

| יכולת                                   | היכן היא נמצאת במקום זאת                                                                              |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| גיוס, פיטורים או עריכה של סוכן          | ממשק הסוכנים. אין כלי `hire_agent` / `fire_agent` / `update_agent`                                    |
| יצירת סביבת עבודה                       | `workspace.create` דרך RPC, לבעל השרת בלבד, שמזריע וחותם בעלות                                        |
| פרויקטים (יצירה / הצגה / עדכון / שיוך)  | ממשק הכרטיסים. פרויקטים הם משטח של המפעיל — ראו [פרויקטים](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/פרויקטים/) |
| שאלת המפעיל שאלה חוסמת                  | הכלי `ask_user` של **מנגנון ההרצה**, ולא MCP. הוא מציג טופס בשיחה וחוסם עד לקבלת התשובה                |
| אבחון לפי סוכן                          | כלום. אין `doctor` — ראו [אבחון סוכן](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/אבחון-סוכן/)                  |
| לוח שנה ופגישות                         | RPC ללקוחות אנושיים בלבד (ראו לעיל)                                                                   |
