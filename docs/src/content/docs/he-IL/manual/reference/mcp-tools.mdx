`cc_server` מארח מרשם כלים אחד של MCP (‏JSON-RPC 2.0), הנחשף בפורט הראשי של השרת (ברירת מחדל `9030`) בנתיבים `POST /mcp` ו-`GET /sse`, בגרסת פרוטוקול `2024-11-05`. כל לקוח מגיע לאותו מרשם: היישום השולחני, גרסת הווב, לקוחות MCP חיצוניים ומנגנון ההרצה המובנה של הסוכן. אפשר לגשר שרתי MCP חיצוניים אל אותו מרשם כשכבה דינמית.

## גודל המרשם

| מדד                                                                        | מספר |
| ------------------------------------------------------------------------- | ----- |
| כלים ש-`cc_server` רושם                                                    | 110   |
| מ-`packages/cc_mcp`                                                       | 108   |
| מ-`packages/cc_mcp_client` (גילוי כלים)                                    | 2     |
| נרשמים במרשם הבסיס (`server_mcp_registry.dart`)                            | 63    |
| נרשמים לאחר האתחול כשהשירותים שלהם עולים (`cc_server_runtime.dart`)        | 47    |
| מתוך 63 של מרשם הבסיס, מותנים במאגר גרף קוד                                 | 5     |

חמשת כלי גרף הקוד נרשמים רק כשהמארח מעביר מאגר גרף קוד אל `buildServerMcpRegistry`. `cc_server` תמיד מעביר אחד, ולכן כל 110 הכלים פעילים בבינארי המשולח.

המרשם המלא מוצהר ב-`tools/list` בלי שער גילוי. עריכות כרטיסים מתבצעות בכלים בעלי טיפוסים מוגדרים.

:::note[לקוחות חיצוניים תמיד רואים את כל הקטלוג]
`tools/list` לעולם אינו מקוצר. לקוחות MCP מאמתים שמות כלים מול העותק השמור שלהם של הרשימה הזו ומסרבים לכל דבר שאינו ברשימה בלי לשאול את השרת, כך שכלי שמוסתר שם הוא בלתי נגיש, ולא סתם שקט.

**מנגנון ההרצה המובנה** שונה: הוא טוען רק תת-קבוצה תושבת של הגדרות בכל בקשה ומושך את השאר בשימוש הראשון, וזו התנהגות של המנגנון שאינה משנה את המרשם הזה. ראו [הקשר כלים ומטמון הנחיות](/he-IL/מדריך-למשתמש/מושגים/הקשר-כלים).
:::

:::note[כל מחלקת כלי נרשמת]
קובץ מקור תחת `packages/cc_mcp/lib/src/tools/` הוא כלי שסוכן יכול לקרוא לו. `packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart` מכשיל את הבנייה אם שום דבר לא בונה מחלקת כלי חדשה.
:::

## פרמטרים משותפים

### `workspace_id`

**חובה** בכל כלי שנוגע בנתונים בעלי היקף של סביבת עבודה. `workspace_id` חסר או שגוי מחזיר שגיאה מפורשת, וערך שאינו תואם את סביבת העבודה של הישות שאליה הוא מכוון נדחה ולא מתעלמים ממנו בשקט. השמיטו אותו בכלים גלובליים באמת: `list_workspaces` וששת כלי עדכוני החדשות (`list_feeds`, `list_articles`, `get_article`, `set_article_read`, `set_article_saved`, `refresh_feeds`), שנשענים על רשימת הפידים האישית של בעל השרת. כלי הגילוי (`search_tool_bm25`, `list_my_tools`) מקבלים אותו באופן אופציונלי כדי שיוכלו לסווג את יכולת הקריאה לפי מצב השיחה. כשהשרת שולח סוכן, סביבת העבודה נכפית בצד השרת, כך שהסוכן אינו יכול להגיע לסביבת עבודה אחרת באמצעות מזהה זר.

## גילוי כלים

שניהם מגיעים מ-`cc_mcp_client` ולא מ-`cc_mcp`, ושניהם מתייעצים עם שומר המצב כדי לדווח מה ניתן לקריאה ב_מצב השיחה הנוכחי_.

| כלי                | תיאור                                                                                                                        |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `search_tool_bm25` | חיפוש בקטלוג הכלים לפי מילת מפתח; מחזיר כלים תואמים, את סכימות הארגומנטים שלהם ואם כל אחד מהם ניתן לקריאה כרגע                 |
| `list_my_tools`    | הצגת הכלים הניתנים לקריאה כרגע בשיחה הזו, מסוננים לפי המצב שלה                                                                |

כלי גילוי שלישי, **`search_tools`**, קיים רק בתוך מנגנון ההרצה המובנה ואינו חלק ממרשם ה-MCP הזה. הוא מדרג את משטח הכלים של ההרצה עצמה, ובשונה מ-`search_tool_bm25` הוא **טוען** את הסכימות של מה שהוא מוצא כדי שהסוכן יוכל לקרוא לתוצאה מתאימה בתור הבא שלו. סוכנים שרצים על המנגנון צריכים להעדיף אותו; ללקוחות MCP יש את `search_tool_bm25`.

## כלי גרף קוד

נרשמים רק כשהמארח מספק מאגר גרף קוד. האינדקס מכסה את ערכת הדקדוקים הנשלחת (Dart, JS/TS, PHP, Python, Rust, Zig, C/C++, Go, Java, Ruby, C#, Swift, Kotlin, R, Assembly, MATLAB, Ada); סמלים בכל שפה אחרת אינם נוכחים.

| כלי            | תיאור                                                                              |
| -------------- | ---------------------------------------------------------------------------------- |
| `search_code`  | חיפוש סמלים מאונדקסים לפי שם, חתימה והערת תיעוד (היברידי BM25 + סמנטי)               |
| `code_symbol`  | איתור סמלים לפי שם מדויק; מחזיר `file:line` וחתימה                                  |

## כלי מתחם מבודד (תחנה)

הפעלת מכונות חד-פעמיות — דפדפן או שולחן עבודה של Linux במתחם מבודד,
אמולטור של Android או סימולטור iOS — מתוך הרצה. נרשמים לאחר האתחול,
ללא תנאי: האם מכונה מסוגלת באמת לעלות היא שאלת בדיקה שהכלים עונים עליה בכל
קריאה. קריאות חוזרות באותה שיחה עושות שימוש חוזר במכונה אחת; צילומי מסך חוזרים
כתוכן תמונה עם תקציב של תמונה אחת לכל תוצאה, ותוכן דף/ממשק שחולץ מגודר כנתון לא
מהימן. ארבעת כלי השימוש יחד עם `rig_close` מצהירים על [מחלקת הפעולה](/he-IL/מדריך-למשתמש/מושגים/מעקות-בטיחות/)
`enclosureControl` (כלי השימוש מצהירים גם על `networkEgress` ו-`processSpawn`;
`mobile_use` ו-`ios_use` מצהירים גם על `packageInstall`), ולכן מצבים לקריאה
בלבד חוסמים אותם. `rig_list` אינו מצהיר על דבר — הוא רק קורא את מצב סביבת
העבודה. מלוא אוצר הפעלים לכל משטח נמצא ב[מדריך העזר לתחנות](/he-IL/מדריך-למשתמש/עזר/תחנות/#action-verbs).

| כלי            | תיאור                                                                                                                              |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `computer_use` | הפעלת שולחן עבודה של Linux במכונה וירטואלית מבודדת: הזזה, לחיצה, גרירה, גלילה, הקלדה, שינוי גודל, לוח גזירים, צילום מסך          |
| `browser_use`  | הפעלת Chromium, Firefox או WebKit ללא ממשק (`engine`): ניווט, לחיצה, מילוי, חילוץ (a11y/DOM/console), לוח גזירים, צילום מסך           |
| `mobile_use`   | הפעלת Android דרך ADB: בדיקה וקלט, צילומי מסך, התקנה/הפעלה/עצירה/איפוס/הסרה של אפליקציות, קישורים עמוקים ופקודות מכשיר בצורת argv    |
| `ios_use`      | הפעלת סימולטור iOS דרך WebDriverAgent/CoreSimulator: בדיקה וקלט, צילומי מסך, התקנה/הפעלה/עצירה/הסרה של אפליקציות, קישורים עמוקים ותהליכי סימולטור בצורת argv |
| `rig_list`     | הצגת התחנות של סביבת עבודה עם המשטח, הסטטוס, גודל התצוגה והבקר                                                                       |
| `rig_close`    | השמדת תחנה והשלכת מצב המכונה שבבעלותה                                                                                              |

## לא נחשף דרך MCP

ללוח השנה ולפגישות אין כלי MCP. סוכנים אינם יכולים לקרוא את לוח השנה, הפגישות, התמלולים, פריטי הפעולה או ההחלטות שלכם. הסיכום שמייצר פריטי פעולה והחלטות רץ כפייפליין המובנה [`meeting_summary`](/he-IL/מדריך-למשתמש/מושגים/פגישות/), ולא ככלי שסוכן יכול לקרוא לו.

## שער כלים לפי מצב

השער נאכף פעמיים מאותה טבלה (`ModeToolPolicy`): פעם אחת במפעיל ה-MCP עבור מתאם Claude Code, ופעם אחת במרשם מנגנון ההרצה המובנה. קריאה חסומה מחזירה את הסיבה.

| מצב           | משטח כלים                                                                                                                                                                                                                             |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`        | כל כלי רשום; בלי רשימת היתר                                                                                                                                                                                                          |
| `plan`        | רשימת היתר מצומצמת. אין כתיבה לעצי עבודה ואין פעלי כרטיס `create` / `assign` / `delegate`, אבל זיכרון, ארטיפקטים, רשימות משימות, `submit_plan`, `exit_plan_mode` ופעלי השלמת הכרטיס על הכרטיס שנשלח מותרים                             |
| `review`      | רשימת היתר מצומצמת: השתתפות בסקירה, תקשורת, מביאי הקשר לקריאה בלבד ומלוא מערכת פעלי הכרטיס, כולל `create_ticket` ו-`assign_ticket`                                                                                                     |
| `orchestrate` | רשימת היתר מצומצמת: כלי מחקר וקריאה בתוספת `propose_orchestration`, `create_playbook` ו-`run_playbook`. גיוס, פירוק לתת-משימות והשלמת כרטיסים קורים באופן דטרמיניסטי לאחר האישור, ולעולם לא באמצע ההרצה                                    |

מותרים בכל מצב, ללא תלות ברשימת ההיתר:

| קבוצה              | כלים                                                                                                                                                                                                                                                              |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| זיכרון וארטיפקטים  | `search_memory`, `propose_fact`, `propose_policy`, `supersede_fact`, `supersede_policy`, `record_observation`, `update_my_notes`, `get_my_notes`, `list_memory_domains`, `list_policies`, `publish_artifact`, `revise_artifact`, `list_artifacts`, `get_artifact` |
| גרף קוד            | `search_code`, `code_symbol`, `code_callers`, `code_callees`, `code_impact`                                                                                                                                                                                       |
| מכניקת הרצה        | `search_tool_bm25`, `list_my_tools`, `todo_write`, `todo_read`                                                                                                                                                                                                    |

הכללת כלי ברשימת היתר אינה הופכת אותו לקריא, וההפך נכון גם כן: היכולת לשאול את המפעיל היא כלי של **מנגנון ההרצה** (`ask_user`), ולכן היא כלל אינה מופיעה בקטלוג ה-MCP הזה.

## כלים הדורשים אישור

כלי יכול להצהיר `requiresApproval`. מפעיל ה-MCP בונה אז `ApprovalPayload` וחושף אותו דרך `ConfirmationPort` לפני שהכלי רץ; `cc_server` מחבר את הפורט הזה, ולכן השער פעיל.

כלים רשומים שמצהירים עליו: `create_ticket`, `update_ticket`, `assign_ticket`, `reassign_ticket`, `close_ticket`, `ticket_relation`, `create_goal`, `update_goal_progress`, `create_approval`, `decide_approval`, `comment_approval`, `create_work_product`, `save_work_product_revision`, `create_runtime_profile`, `install_skill`, `update_skill`.

באופן בלתי תלוי, מעקות הבטיחות המאוחדים של הפעולות שמים שער על כל כלי שמצהיר על סט לא ריק של `ActionClass`. החלטת `prompt` בלי מאשר מחובר נדחית. ראו [מעקות בטיחות](/he-IL/מדריך-למשתמש/מושגים/מעקות-בטיחות/).

## יכולות בלי כלי מאחוריהן

לא כל יכולת במוצר נגישה לסוכן. לאלה אין כלי
כלל, ולכן שם שאולי ראיתם במקום אחר מחזיר "unknown tool":

| יכולת                                   | היכן היא נמצאת במקום זאת                                                                              |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| גיוס, פיטורים או עריכה של סוכן          | ממשק הסוכנים. אין כלי `hire_agent` / `fire_agent` / `update_agent`                                    |
| יצירת סביבת עבודה                       | `workspace.upsert` דרך RPC, שמזריע וחותם בעלות                                                        |
| פרויקטים (יצירה / הצגה / עדכון / שיוך)  | ממשק הכרטיסים. פרויקטים הם משטח של המפעיל — ראו [פרויקטים](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/פרויקטים/) |
| שאלת המפעיל שאלה חוסמת                  | הכלי `ask_user` של **מנגנון ההרצה**, ולא MCP. הוא מציג טופס בשיחה וחוסם עד לקבלת התשובה                |
| אבחון לפי סוכן                          | כלום. אין `doctor` — ראו [אבחון סוכן](/he-IL/מדריך-למשתמש/מדריכים-מעשיים/אבחון-סוכן/)                  |
| לוח שנה ופגישות                         | RPC ללקוחות אנושיים בלבד (ראו לעיל)                                                                   |
