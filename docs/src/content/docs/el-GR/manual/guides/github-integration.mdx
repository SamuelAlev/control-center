Αυτός ο οδηγός καλύπτει τα ειδικά για το GitHub μέρη της ρύθμισης. Το GitHub
είναι ένας από τους τρεις υποστηριζόμενους κεντρικούς υπολογιστές κώδικα — δείτε
[Σύνδεση κεντρικού υπολογιστή κώδικα](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/σύνδεση-κεντρικού-υπολογιστή-κώδικα/)
για τη σύνδεση του GitLab ή του Bitbucket και για το πώς ένας χώρος εργασίας τα
συνδυάζει.

## Προϋποθέσεις

- Λογαριασμός GitHub με πρόσβαση στα αποθετήρια στα οποία θέλετε να εργαστείτε
- Έναν διακομιστή που μπορεί να συνδέει ανθρώπους στο GitHub: είτε με τη δική
  του GitHub App (δείτε [Δημιουργία της GitHub App](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/github-app/)) είτε με το
  Control Center Connect, όπως επιλέγει ο ιδιοκτήτης του διακομιστή στις
  **Ρυθμίσεις → Διακομιστής → Ενιαία σύνδεση**

:::note[Τα διαπιστευτήρια μένουν στον διακομιστή, προσαρτημένα σε εσάς]
Τίποτα δεν αποθηκεύεται στο μηχάνημα στο οποίο πληκτρολογείτε. Τη σύνδεσή σας στο
GitHub την κρατά το `cc_server` σας, με κλειδί το αναγνωριστικό χρήστη σας, και
κάθε συσκευή από την οποία συνδέεστε τη χρησιμοποιεί — επιφάνεια εργασίας, web και
τηλέφωνο. Άλλο μέλος του ίδιου διακομιστή δεν μπορεί να τη χρησιμοποιήσει, και η
σύνδεσή του είναι κάτι που το κάνει το ίδιο.
:::

## Σύνδεση στο GitHub

Το GitHub λειτουργεί μόνο με σύνδεση: δεν υπάρχει token για επικόλληση.

1. Μεταβείτε στις **Ρυθμίσεις → Εσείς → Προφίλ → Φιλοξενία κώδικα** (ή στο πρώτο
   βήμα της εισαγωγής)
2. Στη γραμμή **GitHub**, πατήστε **Σύνδεση στο GitHub**
3. Το πρόγραμμα περιήγησης ανοίγει το GitHub. Εγκρίνετε την εφαρμογή

Το πώς ολοκληρώνεται η σύνδεση εξαρτάται από το ποιος την εκτελεί:

- **Η δική εφαρμογή του διακομιστή:** το GitHub στέλνει το πρόγραμμα περιήγησης
  πίσω στον διακομιστή και το παράθυρο διαλόγου το αντιλαμβάνεται μόνο του. Δεν
  χρειάζεται να πληκτρολογήσετε τίποτα
- **Control Center Connect:** η σελίδα του προγράμματος περιήγησης δείχνει έναν
  κωδικό 8 χαρακτήρων. Πληκτρολογήστε τον στο παράθυρο διαλόγου ή αφήστε το
  πρόγραμμα περιήγησης να ανοίξει το Control Center μέσω του συνδέσμου
  `control-center://` και παραλείψτε την πληκτρολόγηση

Σημείο ελέγχου: η γραμμή **GitHub** γράφει «Συνδεθήκατε ως _your-username_».

Το παράθυρο διαλόγου απορρίπτει έναν κωδικό ή σύνδεσμο που δεν ξεκίνησε το ίδιο,
με το μήνυμα **Η σύνδεση δεν ξεκίνησε από εδώ**. Αν κάποιος σας στείλει σύνδεσμο
σύνδεσης, μη συνεχίσετε: η ολοκλήρωσή του θα συνέδεε τον λογαριασμό σας με τον
δικό του διακομιστή.

Πατήστε **Αποσύνδεση** για να αφαιρέσετε τη σύνδεσή σας. Η αποσύνδεση από το
GitHub ή η αφαίρεσή σας από έναν χώρο εργασίας ακυρώνει επίσης κάθε token που
εξέδωσε ο διακομιστής για λογαριασμό σας.

## Για λογαριασμό ποιου ενεργεί το διαπιστευτήριό σας

Το Control Center ακολουθεί τη δική του διάκριση του GitHub ανάμεσα στο να ενεργείτε **ως πρόσωπο** και στο να ενεργείτε **ως εφαρμογή**:

| Τι συμβαίνει | Εμφανίζεται στο GitHub ως |
| --- | --- |
| Ό,τι κάνετε μόνοι σας: σχόλιο, αξιολόγηση, έγκριση, merge, αίτημα αξιολογητών | **Εσείς**. Το GitHub σημειώνει ένα σχόλιο στη συνομιλία ως γραμμένο με την εφαρμογή Control Center· μια ανασκόπηση και τα ενσωματωμένα σχόλιά της δεν φέρουν καμία τέτοια σήμανση |
| Αξιολόγηση AI, απαντήσεις πρακτόρων και σχόλια σε συζητήσεις PR, ετικέτες, εργασία pipeline και bot | **Το bot του Control Center**. Στο κοινόχρηστο Connect, μια ανασκόπηση ανήκει στο bot μόνο για εγκατάσταση που έχει καταγράψει ο διαχειριστής του Connect· αλλιώς εμφανίζεται ως ο υπεύθυνος άνθρωπος |
| Ένα pull request που ανοίγει ένας πράκτορας για εσάς, οι αλλαγές του στον τίτλο ή στην περιγραφή αυτού του pull request, τα push του και τα commit του | **Εσείς**. Το Control Center πιστώνεται ως συν-συγγραφέας όταν η πίστωση συν-συγγραφέα είναι ενεργή |
| Εργασία που δεν ζήτησε κανείς (χρονοδιαγράμματα, webhook) | **Το bot του Control Center**, και ως συγγραφέας των commit του. Στο Control Center Connect δεν κάνει ποτέ push ούτε ανοίγει pull request |

- **Ό,τι κάνετε** εκτελείται με τη **δική σας** σύνδεση και τίποτα άλλο. Αν δεν είστε συνδεδεμένοι, η εφαρμογή σας ζητά να συνδεθείτε. Κανένα άλλο διαπιστευτήριο δεν ενεργεί στη θέση σας
- **Η εργασία του bot** παίρνει ένα token για ένα αποθετήριο κάθε φορά, περιορισμένο σε ό,τι μπορεί να κάνει εκεί ένα υπεύθυνο μέλος: το μέλος που ζήτησε, αλλιώς ο ιδιοκτήτης του χώρου εργασίας. Ένα μέλος που δεν μπορεί να κάνει push περιορίζει το token σε ανάγνωση. Οι απαντήσεις του bot που ενεργούν για κάποιον ξεκινούν με **Control Center (για @login)**
- **Οι πράκτορες ανοίγουν pull requests μέσω του Control Center**, ποτέ από το sandbox τους, ώστε το pull request να είναι δικό σας και οι δικοί τους κανόνες του GitHub να σας εμποδίζουν να το εγκρίνετε. Το Control Center αρνείται επίσης έγκριση από το άτομο που ζήτησε από τον πράκτορα να το κάνει, και από τον συντάκτη του pull request. Για ένα προγραμματισμένο ή webhook run, αυτό καλύπτει κάθε διαχειριστή που ενεργοποίησε τη σκανδάλη του ή επεξεργάστηκε το pipeline του ενώ ήταν ενεργή. Πρέπει να ελέγξει κάποιος άλλος. Αν το Control Center δεν μπορεί να επιβεβαιώσει ποιος άνοιξε το pull request, ή ποιος λογαριασμός στην πλατφόρμα είστε εσείς, αρνείται και σας ζητά να δοκιμάσετε ξανά
- **Οι πράκτορες σχολιάζουν επίσης μέσω του Control Center.** Το token GitHub που λαμβάνει μια εκτέλεση πράκτορα μόνο διαβάζει. Όταν ένας πράκτορας σχολιάζει το pull request στο οποίο δουλεύει, το Control Center δημοσιεύει το σχόλιο ως bot, ξεκινώντας με **Control Center (για @login)** όταν κάποιος ζήτησε το run. Ένας πράκτορας μπορεί να σχολιάζει μόνο στο δικό του pull request: σε αυτό του ίδιου αποθετηρίου, ποτέ σε fork, του οποίου το τελευταίο commit το έσπρωξε ο πράκτορας ή είναι το τρέχον commit του branch του χώρου του. Οι αναφορές @ στο σχόλιο ενός πράκτορα δεν ειδοποιούν κανέναν. Ένας πράκτορας μπορεί επίσης να αλλάξει τον τίτλο ή την περιγραφή του δικού του pull request όσο είναι ανοιχτό. Αυτή η αλλαγή γίνεται με τον τρόπο με τον οποίο ανοίχτηκε το pull request (ως εσείς, όταν ζητήσατε την εκτέλεση), και ζητά πρώτα έγκριση από προεπιλογή. Η περιγραφή ενός pull request διατηρεί τις αναφορές @ της, όταν ο πράκτορας το ανοίγει και όταν το επεξεργάζεται, οπότε τα άτομα που κατονομάζει ειδοποιούνται
- **Στο Control Center Connect, το bot δεν κάνει ποτέ push ούτε ανοίγει pull request.** Το push, η δημιουργία branch ή το άνοιγμα pull request εκεί απαιτεί ένα άτομο που το ζήτησε και εκτελείται με τη σύνδεσή του. Ένα προγραμματισμένο ή webhook run που επιχειρεί push σταματά με ένα μήνυμα που το λέει. Για να μπορούν τα run χωρίς επίβλεψη να κάνουν push, δώστε στον χώρο εργασίας τη δική του GitHub App στις **Ρυθμίσεις**
- **Τι μπορεί να κάνει το bot του Connect.** Με την κοινόχρηστη εφαρμογή Connect, το bot σχολιάζει, βάζει ετικέτες και αντιδρά. Δημοσιεύει ανασκόπηση (αυτόματη ανασκόπηση, σχόλια ανασκόπησης, αιτήματα αξιολογητών) μόνο όταν ο διαχειριστής του Connect έχει καταγράψει την εγκατάσταση αυτού του διακομιστή. Αλλιώς η ανασκόπηση φεύγει με τη σύνδεση του υπεύθυνου ατόμου και εμφανίζεται με το όνομά του. Το bot δεν ανοίγει, δεν επεξεργάζεται, δεν κλείνει και δεν μετονομάζει pull request, δεν απορρίπτει ανασκόπηση, ούτε επεξεργάζεται ή διαγράφει σχόλιο· αυτά χρειάζονται ένα άτομο που το ζήτησε, με τη δική του σύνδεση. Το Connect δεν δένει την εγκατάσταση του οργανισμού σας με έναν μόνο διακομιστή του Control Center: κάθε διακομιστής όπου ένα μέλος με δικαίωμα push σε αποθετήριο έχει συνδεθεί μέσω Connect μπορεί να λάβει το token σχολίων του bot για εκείνο το αποθετήριο
- **Ένας διακομιστής ή χώρος εργασίας με τη δική του εφαρμογή GitHub** κρατά το bot για όλα τα παραπάνω, συμπεριλαμβανομένων των ανασκοπήσεων
- **Η αυτοματοποίηση δεν εγκρίνει ποτέ** ένα pull request. Η έγκριση είναι πράξη ανθρώπου

Όταν συνδέετε ένα αποθετήριο, το Control Center ελέγχει ότι ο λογαριασμός σας το βλέπει, και σας προειδοποιεί αν η GitHub App δεν είναι εγκατεστημένη στον οργανισμό του ή δεν το περιλαμβάνει, με σύνδεσμο για τη διόρθωση. Η σύνδεση και η αποσύνδεση ενός αποθετηρίου απαιτούν διαχειριστή χώρου εργασίας, και ένα checkout εκτός του αποθηκευτικού χώρου του χώρου εργασίας μπορεί να συνδεθεί μόνο από τον κάτοχο του διακομιστή· δείτε [Προσθήκη αποθετηρίων σε χώρο εργασίας](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/προσθήκη-αποθετηρίων/).

Ο σύνδεσμος ακολουθεί το μόνιμο αναγνωριστικό GitHub του αποθετηρίου, οπότε μια μετονομασία ή μεταφορά δεν χρειάζεται τίποτα από εσάς. Αν η διαδρομή ονομάζει αργότερα άλλο αποθετήριο, το Control Center σταματά να του στέλνει οτιδήποτε και εμφανίζει ειδοποίηση έως ότου ένας διαχειριστής χώρου εργασίας πατήσει **Επανασύνδεση**.

Το άνοιγμα του κώδικα ενός αποθετηρίου (αρχεία, diffs, αναζήτηση, ένα τερματικό) απαιτεί και τη χορήγησή του στον χώρο εργασίας και μια σύνδεσή σας στο GitHub που μπορεί να το διαβάσει. Οι διαχειριστές του χώρου εργασίας ακολουθούν τον ίδιο κανόνα· μόνο ο κάτοχος του διακομιστή εξαιρείται.

## Προσέξτε τις διακοπές του GitHub

Η γραμμή τίτλου εμφανίζει ένα σήμα κατάστασης όταν ένας πάροχος είναι
υποβαθμισμένος, καλύπτοντας τα GitHub, Claude, OpenAI και Kimi. **Κρύβεται όσο όλα
είναι υγιή** — η παρουσία αναφέρει πρόβλημα, όχι η απουσία της.

Πατήστε το σήμα για να ανοίξει ένα αναδυόμενο πλαίσιο με την κατάσταση κάθε παρόχου
και ένα κουμπί ανανέωσης. Οι καταστάσεις ανανεώνονται από μόνες τους κάθε δύο λεπτά.

## Μάθετε πώς ενεργούν οι πράκτορες στο GitHub

- Ένας πράκτορας που δουλεύει σε worktree του GitHub παίρνει ένα token για αυτό το ένα αποθετήριο. Μπορεί μόνο να διαβάζει τον κώδικα, τα issues και τα pull requests· τα σχόλια περνούν από το Control Center, όπως περιγράφηκε παραπάνω. Το push περνά από το Control Center, που ρωτά τον κανόνα **Push σε απομακρυσμένο** και μετά το προωθεί με ένα token εγγραφής που ο πράκτορας δεν κατέχει ποτέ. Δείτε
  [Ρύθμιση πολιτικών sandbox](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/πολιτικές-sandbox/)
- Η εργασία που ξεκινάτε εσείς γίνεται commit ως εσείς. Όταν ζητάτε από πράκτορα κάτι, ή κάνετε commit στο IDE, εσείς είστε ο συγγραφέας και ο committer, με διεύθυνση που έχει επαληθεύσει η πλατφόρμα σας: τη διεύθυνση noreply του GitHub από τη σύνδεσή σας στο GitHub, ή σε GitLab και Bitbucket το email που αναφέρει εκεί η σύνδεσή σας. Η ταυτότητα Git του χώρου εργασίας χρησιμοποιείται μόνο για ένα commit που κάνετε με το χέρι σε αποθετήριο όπου καμία πλατφόρμα δεν εγγυάται διεύθυνση δική σας. Αν δεν είστε συνδεδεμένοι σε αυτή την πλατφόρμα, τα commit ενός πράκτορα είναι του bot και οι σημειώσεις της εκτέλεσης το λένε
- Η εργασία που κανείς δεν ζήτησε γίνεται commit ως bot. Μια προγραμματισμένη εκτέλεση ή εκτέλεση webhook κάνει commit ως η GitHub App του χώρου εργασίας (`<app>[bot]`, με τη διεύθυνση noreply της), ή ως `Control Center <hi@usectrl.dev>` όταν δεν υπάρχει GitHub App ή το αποθετήριο είναι σε GitLab ή Bitbucket
- **Αναφορά του Control Center ως συν-συγγραφέα** (**Ρυθμίσεις → Εσείς → Commits**) προσθέτει ένα trailer `Co-Authored-By:` για το άλλο μέρος: το Control Center στα δικά σας commit, και στα commit του bot κάθε άτομο που ενεργοποίησε τη σκανδάλη πίσω από την εκτέλεση. Είναι ενεργή εκτός αν την απενεργοποιήσετε. Ένας διαχειριστής χώρου εργασίας μπορεί να την καθορίσει για όλους με την **Αναφορά συν-συγγραφέα** στις **Ρυθμίσεις → Χώρος εργασίας → Γενικά**· η δική σας επιλογή τότε αποθηκεύεται αλλά δεν ισχύει σε αυτόν τον χώρο εργασίας. Η απόδοση του ίδιου του Claude Code είναι πάντα απενεργοποιημένη
- Τα commit σας μπορούν να υπογραφούν. Στις **Ρυθμίσεις → Εσείς → Commits**, στο **Επαληθευμένα commit**, επιλέξτε **Δημιουργία κλειδιού υπογραφής** και προσθέστε το δημόσιο μέρος του στον λογαριασμό σας στο GitHub ή στο GitLab ως κλειδί υπογραφής· από τότε τα commit των εκτελέσεων που ζητάτε, και τα commit που κάνετε στο IDE, εμφανίζονται ως επαληθευμένα. Το ιδιωτικό μέρος μένει στον διακομιστή σας, οπότε όποιος ελέγχει τον διακομιστή μπορεί να υπογράφει commit ως εσείς όσο το κλειδί είναι στον λογαριασμό σας, και στο GitHub ένα commit που εμφανίζεται ήδη ως επαληθευμένο μένει επαληθευμένο αφού αφαιρέσετε το κλειδί. Το Bitbucket δεν έχει κλειδί μόνο για υπογραφές: μην το προσθέτετε εκεί, και τα commit στο Bitbucket δεν υπογράφονται. Τα commit του bot δεν υπογράφονται ποτέ
- Τα commit που κάνετε στο πάνελ **Έλεγχος εκδόσεων** του IDE παραλείπουν τα hooks Git του αποθετηρίου, όπως κάνει το `git commit --no-verify`, και το Git του διακομιστή αγνοεί τους βοηθούς διαπιστευτηρίων, τους επεξεργαστές, τα εξωτερικά εργαλεία diff και τους υπογράφοντες που ορίζει το αποθετήριο: τρέχει το Git στον δικό του υπολογιστή, σε δέντρο που μπορεί να αλλάξει ένας πράκτορας ή ένα pull request. Δείτε [Commit και push από τον Έλεγχο εκδόσεων](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/έλεγχος-και-συγχώνευση-pr/#commit-και-push-από-τον-έλεγχο-εκδόσεων)
- Κάθε commit που σπρώχνει ένας πράκτορας ελέγχεται πρώτα, συμπεριλαμβανομένων των επιπέδων που σπρώχνει το `stack_publish` για ένα stack. Ένα push που κατονομάζει κάποιον άλλον, αφαιρεί ή δανείζεται μια πίστωση, προσθέτει ένα sign-off, ή δεν είναι υπογεγραμμένο όπως λένε οι ρυθμίσεις σας απορρίπτεται. Τα commit που σπρώχνετε μόνοι σας από το IDE είναι δικά σας και δεν ελέγχονται έτσι
- Ένα τερματικό που ανοίγετε σε ένα rig παίρνει τη δική σας σύνδεση, περιορισμένη στο ένα αποθετήριο, οπότε τα push από εκεί είναι δικά σας
- Όταν δεν μπορεί να εκδοθεί token (κανένας υπόλογος δεν είναι συνδεδεμένος, η εφαρμογή δεν είναι εγκατεστημένη στον ιδιοκτήτη, ή η εγκατάσταση είναι σε αναστολή), η εντολή που το ζήτησε λέει γιατί. Δεν υπάρχει εναλλακτικό διαπιστευτήριο

## Αντιμετώπιση προβλημάτων

### Η λίστα PR είναι κενή και λέει ότι το GitHub δεν είναι συνδεδεμένο

Δεν έχετε συνδεθεί στο GitHub σε αυτόν τον διακομιστή. Πατήστε **Σύνδεση στο
GitHub** κάτω από τις **Ρυθμίσεις → Εσείς → Προφίλ → Φιλοξενία κώδικα**. Τα αποθετήρια σε άλλα forge δεν επηρεάζονται.

### Η γραμμή GitHub λέει ότι η σύνδεση δεν έχει ρυθμιστεί σε αυτόν τον διακομιστή

Ο διακομιστής δεν έχει ούτε δική του GitHub App ούτε Connect. Ο ιδιοκτήτης του
διακομιστή επιλέγει ένα από τα δύο στις **Ρυθμίσεις → Διακομιστής → Ενιαία
σύνδεση**: η **Δημιουργία της εφαρμογής μου GitHub** διαρκεί περίπου δύο λεπτά.
Δείτε [Δημιουργία της GitHub App](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/github-app/).

Σε έναν χώρο εργασίας με δικές του εφαρμογές, η γραμμή το λέει όταν η GitHub App του χώρου εργασίας λείπει ή είναι ελλιπής. Ένας διαχειριστής του χώρου εργασίας τη συμπληρώνει στην κάρτα **Εφαρμογή GitHub** στις **Ρυθμίσεις → Χώρος εργασίας → Ενσωματώσεις**· δείτε [Δώστε σε έναν χώρο εργασίας τη δική του εφαρμογή](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/github-app/#δώστε-σε-έναν-χώρο-εργασίας-τη-δική-του-εφαρμογή).

### Το παράθυρο διαλόγου λέει ότι ο κωδικός δεν ταιριάζει

Πληκτρολογήστε τον κωδικό ακριβώς όπως τον δείχνει το πρόγραμμα περιήγησης: 8
γράμματα και ψηφία. Πέντε λανθασμένοι κωδικοί τερματίζουν τη σύνδεση· ξεκινήστε
την ξανά.

### Η σύνδεση λέει ότι η εφαρμογή δεν είναι εγκατεστημένη

Η GitHub App δεν έχει εγκατάσταση στον λογαριασμό που κατέχει το αποθετήριο. Ένας
διαχειριστής του χώρου εργασίας την εγκαθιστά από τις **Ρυθμίσεις → Χώρος
εργασίας → Ενσωματώσεις → Εγκαταστάσεις της εφαρμογής GitHub**.

### Όλοι πρέπει να συνδεθούν ξανά στο GitHub

Ο ιδιοκτήτης του διακομιστή έκανε εναλλαγή του κλειδιού Connect του διακομιστή,
άλλαξε διακομιστή Connect, ή ο κατάλογος δεδομένων επαναφέρθηκε σε άλλο μηχάνημα.
Οι συνδέσεις μέσω Connect είναι δεσμευμένες στον διακομιστή που τις έκανε.

### Η προσθήκη αποθετηρίου απορρίπτεται

Η καταχώριση απαιτεί και τα τρία: η διαδρομή βρίσκεται μέσα σε ένα δέντρο εργασίας
git, υπάρχει απομακρυσμένο `origin` και αυτό το απομακρυσμένο δείχνει σε ένα
υποστηριζόμενο forge (github.com, gitlab.com ή bitbucket.org). Το `origin` πρέπει να είναι το αποθετήριο που συνδέετε, και ένας φάκελος εκτός του αποθηκευτικού χώρου του χώρου εργασίας μπορεί να συνδεθεί μόνο από τον κάτοχο του διακομιστή. Δείτε
[Προσθήκη αποθετηρίων σε χώρο εργασίας](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/προσθήκη-αποθετηρίων/).

### Έχω χορήγηση αλλά το αποθετήριο λέει ότι ο λογαριασμός μου δεν μπορεί να το διαβάσει

Ο λογαριασμός σας στο GitHub δεν μπορεί να διαβάσει αυτό το αποθετήριο, οπότε ο κώδικάς του παραμένει κλειστός για εσάς ακόμη και με χορήγηση χώρου εργασίας. Συνδεθείτε στο GitHub στην ενότητα **Φιλοξενία κώδικα**, ή ζητήστε πρόσβαση στο αποθετήριο στο GitHub.

### «Δεν ήταν δυνατή η επιβεβαίωση της πρόσβασής σας στο GitHub»

Το Control Center δεν μπόρεσε να επικοινωνήσει με το GitHub για να ελέγξει την πρόσβασή σας, οπότε αρνήθηκε αντί να μαντέψει. Δοκιμάστε ξανά σε λίγο.

### Οι ανασκοπήσεις στο Connect εμφανίζονται με το όνομά μου και όχι του bot

Στην κοινόχρηστη εφαρμογή Connect, το bot δημοσιεύει ανασκοπήσεις μόνο για εγκαταστάσεις που έχει καταγράψει ο διαχειριστής του Connect. Παντού αλλού η ανασκόπηση φεύγει με τη σύνδεση του υπεύθυνου ατόμου. Για να δημοσιεύει το bot ανασκοπήσεις, δώστε στον χώρο εργασίας τη δική του GitHub App.

### Όλα σταματούν να λειτουργούν για λίγο μετά από εντατική χρήση

Αυτός είναι ο διακόπτης κυκλώματος του ορίου ρυθμού. Το GitHub σηματοδοτεί το κύριο
όριό του με ένα `403` που φέρει `x-ratelimit-remaining: 0` και χρόνο επαναφοράς· όταν
δει ένα τέτοιο, ο πελάτης αποτυγχάνει περαιτέρω αιτήματα τοπικά χωρίς κλήση δικτύου
μέχρι να περάσει το παράθυρο, ώστε μια καταιγίδα επαναλήψεων να μην μπορεί να βαθύνει
το όριο. Οι παροδικές αποτυχίες επαναλαμβάνονται έως τρεις φορές με εκθετική
υποχώρηση, τηρώντας το `retry-after`.
