Το Control Center Connect εκτελεί τις συνδέσεις παρόχων (GitHub, Google Calendar,
Linear, Slack) για διακομιστές που δεν έχουν καταχωρίσει δικές τους εφαρμογές.
Αυτός ο οδηγός δείχνει πώς να εκτελέσετε το δικό σας Connect, ώστε οι εφαρμογές
παρόχων, τα μυστικά τους και η λίστα των διακομιστών που επιτρέπεται να τις
χρησιμοποιούν να μένουν όλα σε εσάς.

Τι μπορεί και τι δεν μπορεί να δει το Connect περιγράφεται στην
[αναφορά του Connect](/el-GR/εγχειρίδιο/αναφορά/connect/). Διαβάστε την πρώτα αν
αποφασίζετε αν θα εκτελέσετε ένα.

:::note[Ίσως δεν το χρειάζεστε]
Ένας διακομιστής μπορεί αντί γι’ αυτό να καταχωρίσει τις δικές του εφαρμογές:
**Ρυθμίσεις → Διακομιστής → Ενιαία σύνδεση → Εφαρμογές παρόχων**, όπου η
**Δημιουργία της εφαρμογής μου GitHub** ρυθμίζει το GitHub σε ένα βήμα. Οι εφαρμογές του διακομιστή ισχύουν μόνο υπό **Χρήση των δικών μου εφαρμογών**: με το Control Center ή ένα δικό σας Connect, το Connect εκτελεί κάθε λωρίδα, ενώ μια δική σας εφαρμογή του χώρου εργασίας ισχύει ακόμη. Εκτελέστε ένα Connect
όταν πολλοί διακομιστές πρέπει να μοιράζονται ένα σύνολο εφαρμογών.
:::

## Προϋποθέσεις

- Μια δημόσια διεύθυνση **HTTPS** για το Connect, όπως `https://connect.example.com`,
  πίσω από έναν διακομιστή μεσολάβησης που τερματίζει το TLS. Το σκέτο `http`
  γίνεται δεκτό μόνο στο loopback
- Docker ή ένας `cc_server` που μπορείτε να επανεκκινήσετε με επιπλέον μεταβλητές
  περιβάλλοντος
- Δικαίωμα καταχώρισης εφαρμογών σε κάθε πάροχο που θέλετε να εξυπηρετήσετε
- Οι διακομιστές που θα το χρησιμοποιούν, με τους ιδιοκτήτες τους διαθέσιμους:
  ο καθένας έχει ένα αναγνωριστικό εγκατάστασης που προσθέτετε στη λίστα
  επιτρεπόμενων του Connect

## Βήμα 1: Επιλέξτε τη διεύθυνση

Επιλέξτε το URL τώρα και κρατήστε το. Το `CONNECT_PUBLIC_URL` συμμετέχει σε
οτιδήποτε κάνει το Connect: οι υπογραφές αιτημάτων, τα σφραγισμένα
διαπιστευτήρια, τα URL ανακατεύθυνσης των παρόχων και το αναγνωριστικό
εγκατάστασης κάθε διακομιστή είναι όλα δεμένα σε αυτό. Αν το αλλάξετε αργότερα,
πρέπει να καταχωρίσετε ξανά τις ανακατευθύνσεις και όλοι να συνδεθούν ξανά.

## Βήμα 2: Καταχωρίστε τις εφαρμογές παρόχων

Καταχωρίστε μόνο τους παρόχους που θέλετε να εξυπηρετήσετε. Ένας πάροχος με
ελλιπείς μεταβλητές μένει εκτός της διαμόρφωσης του Connect, και οι διακομιστές
τον βλέπουν ως μη διαθέσιμο. Παρακάτω, το `<base>` είναι το `CONNECT_PUBLIC_URL`
σας.

| Πάροχος        | Καταχώριση                                                                                                                                                                                                                                                                                         | Κρατήστε                                               |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| **Εφαρμογή GitHub** | Callback URL `<base>/oauth/github/callback`. Setup URL `<base>/oauth/github/setup` με το **Redirect on update** ενεργό. Αφήστε το **Request user authorization (OAuth) during installation** ανενεργό: όταν είναι ενεργό, το GitHub αγνοεί το setup URL. Κρατήστε το **Expire user authorization tokens** ενεργό | App id, slug, client id, client secret, ένα ιδιωτικό κλειδί |
| **Google**     | Ένας OAuth client τύπου **Web application** με redirect URI `<base>/oauth/google/callback` και ενεργοποιημένο το Google Calendar API                                                                                                                                                             | Client id, client secret                               |
| **Linear**     | Μια εφαρμογή OAuth με callback URLs `<base>/oauth/linear/callback` και `<base>/oauth/linear_app/callback`                                                                                                                                                                                         | Μόνο το client id                                      |
| **Slack**      | Redirect URLs `<base>/oauth/slack_oidc/callback` και `<base>/oauth/slack/callback`. Event Subscriptions στο `<base>/v1/hooks/slack/events` (`app_mention`, `message.*`, `assistant_thread_*`, `app_uninstalled`, `tokens_revoked`). Slash commands στο `<base>/v1/hooks/slack/commands`. Token rotation ενεργό | App id, client id, client secret, signing secret       |

Δώστε στη GitHub App αυτά τα δικαιώματα αποθετηρίου: **Metadata** ανάγνωση,
**Contents** ανάγνωση και εγγραφή, **Pull requests** ανάγνωση και εγγραφή,
**Issues** ανάγνωση και εγγραφή, **Checks**, **Actions** και **Commit statuses**
ανάγνωση. Προσθέστε **Members** οργανισμού ανάγνωση για αιτήματα αξιολόγησης από
ομάδες. Τα webhooks μπορούν να μείνουν ανενεργά: οι διακομιστές κάνουν περιοδικό
έλεγχο.

Το Connect χρειάζεται το ιδιωτικό κλειδί της GitHub App (**Generate a private key** στις ρυθμίσεις της App). Υπογράφει τα αιτήματα της App που βρίσκουν την εγκατάσταση που καλύπτει ένα αποθετήριο (ή, όταν το αποθετήριο δεν έχει καμία, την εγκατάσταση του ιδιοκτήτη) και εκδίδει ένα token εγκατάστασης για ένα αποθετήριο, μόνο αφού η σύνδεση του ανθρώπου που ζητά απέδειξε την πρόσβαση σε εκείνο το αποθετήριο.

Κάθε διακομιστής στο Connect σας μοιράζεται το bot της App. Μπορεί να διαβάζει, να σχολιάζει, να βάζει ετικέτες και να αντιδρά ως bot σε οποιονδήποτε από αυτούς. Η ανασκόπηση pull requests ως bot επιτρέπεται μόνο στους διακομιστές που καταχωρίζετε στο `CONNECT_GITHUB_REVIEW_BOT_INSTALLS` (τα αναγνωριστικά εγκατάστασής τους, χωρισμένα με κόμμα)· κάθε άλλος διακομιστής δημοσιεύει ανασκοπήσεις με το token του ίδιου του ελεγκτή. Η ώθηση δεν γίνεται ποτέ ως bot. Για να ανασκοπεί ως bot ένας δικός σας διακομιστής, προσθέστε εκεί το αναγνωριστικό εγκατάστασής του και κάντε επανεκκίνηση. Κρατήστε το αρχείο κλειδιού ως μυστικό, όπως το κλειδί σφράγισης. Το Linear δεν χρειάζεται μυστικό: το Connect επιστρέφει τον κωδικό στον διακομιστή, ο οποίος ολοκληρώνει μόνος του την ανταλλαγή.

## Βήμα 3: Συγκεντρώστε τα αναγνωριστικά εγκατάστασης

Το Connect απαντά μόνο στους διακομιστές της λίστας επιτρεπόμενων. Σε κάθε
διακομιστή, κατευθύνετέ τον στο Connect σας και μετά διαβάστε το αναγνωριστικό
εγκατάστασής του:

1. Μεταβείτε στις **Ρυθμίσεις → Διακομιστής → Ενιαία σύνδεση**, ανοίξτε την κάρτα
   **Control Center Connect** και επιλέξτε **Χρήση προσαρμοσμένου διακομιστή
   Connect**
2. Εισαγάγετε το URL σας και αποθηκεύστε. Η κάρτα δείχνει το **Αναγνωριστικό
   εγκατάστασης** του διακομιστή

Από ένα τερματικό στον κεντρικό υπολογιστή του διακομιστή, το ίδιο γίνεται έτσι:

```bash
cc_server connect enable --url https://connect.example.com
cc_server connect status
```

Το `status` εκτυπώνει το αναγνωριστικό εγκατάστασης. Δείχνει `install_blocked`
μέχρι να ολοκληρωθεί το Βήμα 5, κάτι που είναι αναμενόμενο.

Ένα αναγνωριστικό εγκατάστασης παράγεται ανά διεύθυνση Connect, οπότε ο ίδιος
διακομιστής έχει διαφορετικό αναγνωριστικό για κάθε Connect με το οποίο
επικοινωνεί. Αλλάζει μόνο όταν ο ιδιοκτήτης του εναλλάσσει το κλειδί.

## Βήμα 4: Δημιουργήστε ένα κλειδί σφράγισης

Το Connect κρυπτογραφεί κάθε διαπιστευτήριο που επιστρέφει με ένα κλειδί
σφράγισης. Δημιουργήστε ένα και κρατήστε το ως αρχείο μυστικού:

```bash
docker run --rm ghcr.io/samuelalev/cc-connect:latest \
  cc-connect-config seal-key > seal_keys
chmod 600 seal_keys
```

Αν χάσετε το κλειδί σφράγισης, όλοι αποσυνδέονται: καμία σφραγίδα δεν ανοίγει
χωρίς αυτό.

## Βήμα 5: Ξεκινήστε το κοντέινερ

Κάθε έκδοση δημοσιεύει το `ghcr.io/samuelalev/cc-connect` με προέλευση build
(build provenance). Καρφιτσώστε ένα tag έκδοσης στην παραγωγή.

```bash
docker run -d --name cc-connect -p 8790:8790 \
  -e CONNECT_PUBLIC_URL=https://connect.example.com \
  -e CONNECT_ALLOWED_INSTALLS=<install id>,<install id> \
  -e CONNECT_SEAL_KEYS_FILE=/run/secrets/seal_keys \
  -v "$PWD/seal_keys:/run/secrets/seal_keys:ro" \
  -e CONNECT_GITHUB_APP_ID=123456 \
  -e CONNECT_GITHUB_APP_SLUG=acme-control-center \
  -e CONNECT_GITHUB_CLIENT_ID=Iv23li0123456789abcd \
  -e CONNECT_GITHUB_CLIENT_SECRET_FILE=/run/secrets/github \
  -v "$PWD/github_secret:/run/secrets/github:ro" \
  -e CONNECT_GITHUB_APP_PRIVATE_KEY_FILE=/run/secrets/github_key \
  -v "$PWD/github_app_key.pem:/run/secrets/github_key:ro" \
  -v cc-connect-data:/data \
  ghcr.io/samuelalev/cc-connect:latest
```

Κατευθύνετε τον αντίστροφο διακομιστή μεσολάβησης στη θύρα `8790`, και ορίστε το `CONNECT_TRUST_PROXY` στον αριθμό των διακομιστών μεσολάβησης μπροστά από το Connect, ώστε το όριο ανά διεύθυνση να βλέπει τη διεύθυνση κάθε πελάτη. Η εικόνα εκτελείται ως χρήστης χωρίς προνόμια, κρατά την κατάστασή της στον τόμο `/data` και έχει ενσωματωμένο έλεγχο υγείας (`cc-connect --healthcheck`, που ελέγχει το `/healthz`: η διεργασία απαντά). Το `/readyz` ελέγχει επιπλέον ότι οι αποθήκες κατάστασης και δεσμεύσεων απαντούν και ότι το Redis, αν χρησιμοποιείται, εκτελείται με `maxmemory-policy noeviction`· δείξτε εκεί τον έλεγχο ετοιμότητας ενός orchestrator.

Η σελίδα συγκατάθεσης σύνδεσης απαντά με form post που το Connect δέχεται μόνο από τη δική του σελίδα: το `Sec-Fetch-Site`, όταν στέλνεται, πρέπει να είναι `same-origin`, και το `Origin`, όταν στέλνεται, πρέπει να είναι η προέλευση του `CONNECT_PUBLIC_URL`· ένα post χωρίς κανένα από τα δύο απορρίπτεται. Άρα ο διακομιστής μεσολάβησης πρέπει να περνά και τα δύο headers αναλλοίωτα, και το `CONNECT_PUBLIC_URL` πρέπει να είναι η διεύθυνση που χρησιμοποιούν πράγματι οι περιηγητές των ανθρώπων. Αν η συνέχεια από αυτή τη σελίδα δείχνει πάντα «Αυτός ο σύνδεσμος έχει λήξει» και το αρχείο καταγραφής δείχνει `oauth.done_refused` με αιτία `origin` ή `no_origin`, ένα από τα δύο είναι λάθος.

Το Connect αρνείται να εκκινήσει (κωδικός εξόδου `78`) όταν η διαμόρφωσή του είναι
ανοιχτή, μη ασφαλής ή μισοτελειωμένη, και εκτυπώνει ποια μεταβλητή είναι λάθος.
Μια λίστα επιτρεπόμενων που λείπει, μια διεύθυνση `http` εκτός loopback, ένα
κακοσχηματισμένο κλειδί σφράγισης ή ταυτόχρονος ορισμός των `NAME` και
`NAME_FILE` το σταματούν όλα.

Σημείο ελέγχου: σε κάθε διακομιστή, η κάρτα Connect γράφει **Λειτουργεί**, και το
**Πού εκτελείται κάθε σύνδεση** αναφέρει **Connect** για κάθε πάροχο που
καταχωρίσατε. Το `cc_server connect status` εκτυπώνει `Health: ok` και τις ίδιες
λωρίδες.

## Προσάρτηση του Connect μέσα στο cc_server

Ένας διακομιστής μπορεί να φιλοξενεί ο ίδιος το Connect αντί για ξεχωριστό
κοντέινερ. Η προσαρτημένη υπηρεσία είναι η ίδια που εκτελεί η εικόνα.

1. Βάλτε τις μεταβλητές `CONNECT_*` στο αρχείο `.env` του διακομιστή, όπως στο Βήμα 5.
   Ο διακομιστής αρνείται να εκκινήσει όταν ένα μυστικό του Connect, συμπεριλαμβανομένου του `CONNECT_SENTRY_DSN`, είναι ορισμένο στο περιβάλλον του
2. Προσθέστε `CC_SERVER_CONNECT_HOST=on`
3. Επανεκκινήστε τον διακομιστή. Το αρχείο καταγραφής του εκτυπώνει
   `embedded Connect at <url>`

```bash
CC_SERVER_CONNECT_HOST=on
CONNECT_ALLOWED_INSTALLS=<install id>
CONNECT_SEAL_KEYS=<output of cc-connect-config seal-key>
CONNECT_GITHUB_APP_ID=123456
CONNECT_GITHUB_APP_SLUG=acme-control-center
CONNECT_GITHUB_CLIENT_ID=Iv23li0123456789abcd
CONNECT_GITHUB_CLIENT_SECRET=<secret>
CONNECT_GITHUB_APP_PRIVATE_KEY_FILE=/etc/cc/github_app_key.pem
```

Το Connect εξυπηρετείται τότε στο `<server>/connect`:

- Το `CONNECT_PUBLIC_URL` έχει προεπιλογή την προέλευση του δημόσιου URL του
  διακομιστή συν `/connect`. Ορίστε το ρητά πίσω από διακομιστή μεσολάβησης. Η
  διαδρομή του πρέπει να είναι ακριβώς `/connect` και πρέπει να είναι HTTPS, εκτός
  αν είναι loopback
- Μόνο οι μεταβλητές `CONNECT_*` φτάνουν στην προσαρτημένη υπηρεσία, οπότε δεν
  δανείζεται ποτέ τις δικές εφαρμογές παρόχων του διακομιστή
- Το `CONNECT_ALLOWED_INSTALLS` εξακολουθεί να απαιτείται, και για τον ίδιο τον
  διακομιστή που το φιλοξενεί
- Μια λανθασμένα διαμορφωμένη προσάρτηση εμποδίζει την εκκίνηση του διακομιστή,
  αντί να εξυπηρετεί έναν ανοιχτό μεσολαβητή
- Ο διακομιστής επίδειξης δεν το προσαρτά ποτέ

Καταχωρίστε τις ανακατευθύνσεις των παρόχων στο `https://<server>/connect` και
μετά κατευθύνετε τους διακομιστές (μαζί με αυτόν που το φιλοξενεί) σε εκείνο το URL
όπως στο Βήμα 3.

## Αναφορά διαμόρφωσης

Κάθε ρύθμιση είναι μια μεταβλητή περιβάλλοντος. Κάθε μυστικό μπορεί να προέρχεται
αντί γι’ αυτό από ένα προσαρτημένο αρχείο: ορίστε `NAME_FILE` στη θέση του `NAME`.
Το Connect διαβάζει ξανά το αρχείο το πολύ κάθε 30 δευτερόλεπτα και κρατά την
τελευταία έγκυρη τιμή. Τα μυστικά με την ένδειξη **διπλό** δέχονται επίσης
`NAME_PREVIOUS` (ή `NAME_PREVIOUS_FILE`) κατά τη διάρκεια μιας εναλλαγής.

### Διεύθυνση και πρόσβαση

| Μεταβλητή                       | Προεπιλογή        | Σημασία                                                                                                                                  |
| ------------------------------- | ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `CONNECT_PUBLIC_URL`            | απαιτείται        | Το κανονικό δημόσιο URL. HTTPS, ή `http` μόνο στο loopback. Μια διαδρομή σημαίνει προσάρτηση. Χωρίς query ή fragment                     |
| `CONNECT_ALLOWED_INSTALLS`      | απαιτείται        | Αναγνωριστικά εγκατάστασης χωρισμένα με κόμμα. Το `*` γίνεται δεκτό μόνο μαζί με το `CONNECT_SIGNED_CONFIG_FILE`                         |
| `CONNECT_DENY_INSTALLS`         |                   | Αναγνωριστικά εγκατάστασης που απορρίπτονται ακόμη κι αν επιτρέπονται                                                                    |
| `CONNECT_GITHUB_ALLOWED_OWNERS` |                   | Αριθμητικά id ιδιοκτητών GitHub. Όταν ορίζεται, tokens αποθετηρίου εκδίδονται μόνο για αποθετήρια που τους ανήκουν. Δεν περιορίζει ποιος συνδέεται: ένα πρόσωπο που επιτρέπεται να χρησιμοποιεί αυτό το Connect λαμβάνει ακόμη το δικό του token χρήστη της App. Για να εξυπηρετεί μόνο έναν οργανισμό, κρατήστε την App ιδιωτική σε αυτόν                       |
| `CONNECT_GITHUB_REVIEW_BOT_INSTALLS` |      | Αναγνωριστικά εγκατάστασης που μπορούν να έχουν το bot της App να ανασκοπεί pull requests. Κενό από προεπιλογή· το `*` απορρίπτεται, και κάθε αναγνωριστικό πρέπει να είναι επιτρεπτό επίσης |
| `CONNECT_HOST`, `CONNECT_PORT`  | `0.0.0.0`, `8790` | Διεύθυνση σύνδεσης και θύρα                                                                                                              |
| `CONNECT_TRUST_PROXY`           | `0`               | Αξιόπιστα βήματα διακομιστή μεσολάβησης στο `X-Forwarded-For` (0 έως 8). Χρησιμοποιείται μόνο για τα όρια ανά διεύθυνση, για την ένδειξη δικτύου της σελίδας σύνδεσης και για τη διεύθυνση που καταγράφεται. Πίσω από διακομιστή μεσολάβησης, το `0` μετράει κάθε πελάτη ως τον ίδιο τον διακομιστή μεσολάβησης, και το αρχείο καταγραφής το λέει μία φορά           |

Μια γεμάτη αποθήκη μνήμης απορρίπτει νέες συνδέσεις και αιτήματα αντί να ξεχάσει μια ζωντανή εγγραφή                                                                        |

Redis 6.2 ή νεότερο με `maxmemory-policy noeviction`, και τα δύο ελέγχονται κατά την εκκίνηση                                                                                            |

## Εκτέλεση περισσότερων από ένα στιγμιότυπων

Ένα στιγμιότυπο με `CONNECT_STATE=memory` αρκεί για τους περισσότερους
οργανισμούς. Πολλά στιγμιότυπα πίσω από μία διεύθυνση χρειάζονται `CONNECT_STATE=redis` και
`CONNECT_BINDINGS=firestore`, ώστε μια σύνδεση που ξεκίνησε σε ένα στιγμιότυπο να
μπορεί να ολοκληρωθεί σε άλλο και κάθε στιγμιότυπο να βλέπει τις ίδιες δεσμεύσεις
Slack και τα ίδια ανακληθέντα αναγνωριστικά εγκατάστασης. Ένας κοινόχρηστος
`CONNECT_DATA_DIR` δεν δουλεύει: το πρώτο Connect τον κλειδώνει. Τα όρια αιτημάτων
ανά εγκατάσταση, ανά διεύθυνση και για ολόκληρο το στιγμιότυπο ισχύουν ανά
στιγμιότυπο· τα όρια για συνδέσεις, tokens GitHub, tokens bot, αναζητήσεις GIF ανά
διεύθυνση, ανακλήσεις και ομάδες Slack είναι κοινά μέσω της αποθήκης κατάστασης.

## Εναλλαγή μυστικού παρόχου

Κανείς δεν αποσυνδέεται:

1. Δημιουργήστε το νέο μυστικό στον πάροχο και κρατήστε το παλιό
2. Μεταφέρετε την παλιά τιμή στο `NAME_PREVIOUS`, βάλτε τη νέα στο `NAME` και
   αυξήστε το `CONNECT_<LANE>_SECRET_GENERATION`. Τα προσαρτημένα αρχεία
   εντοπίζονται μέσα σε 30 δευτερόλεπτα
3. Περιμένετε να ανανεωθούν οι συνδέσεις, μετά διαγράψτε το παλιό μυστικό στον
   πάροχο και αφαιρέστε το `NAME_PREVIOUS`

Για να εναλλάξετε ένα κλειδί σφράγισης, βάλτε μια νέα καταχώριση
`cc-connect-config seal-key` πρώτη στο `CONNECT_SEAL_KEYS` και κρατήστε την παλιά
καταχώριση μέχρι να ανανεωθούν οι σφραγίδες της.

## Αλλαγή εφαρμογής

Οι διακομιστές θυμούνται τα id εφαρμογής και client που ανακοίνωσε το Connect σας
την πρώτη φορά που το χρησιμοποίησαν. Αν αντικαταστήσετε μια εφαρμογή, η κάρτα
Connect κάθε διακομιστή δείχνει **Οι εφαρμογές του Connect άλλαξαν**, και οι
συνδέσεις μέσω του Connect παύουν μέχρι ο ιδιοκτήτης του να πατήσει **Εμπιστοσύνη
στις νέες εφαρμογές**. Ενημερώστε τους ιδιοκτήτες διακομιστών πριν κάνετε την
αλλαγή, ώστε να ξέρουν ότι το μήνυμα προέρχεται από εσάς.

## Αποκλεισμός διακομιστή

Προσθέστε το αναγνωριστικό εγκατάστασής του στο `CONNECT_DENY_INSTALLS` και κάντε
επανεκκίνηση. Ο ιδιοκτήτης του βλέπει «Το Connect έχει αποκλείσει το
αναγνωριστικό εγκατάστασης αυτού του διακομιστή. Επικοινωνήστε με τον διαχειριστή του διακομιστή Connect σας.» και κάθε σύνδεση μέσω Connect σε αυτόν σταματά.

Ένας διακομιστής ανακαλεί επίσης το παλιό αναγνωριστικό εγκατάστασής του όταν ο ιδιοκτήτης του εναλλάσσει το κλειδί. Αποδεικνύει ότι το αναγνωριστικό είναι δικό του με μία σφράγιση διαπιστευτηρίου που έκανε για αυτόν αυτό το Connect, οπότε μόνο ένας διακομιστής που έχει ήδη συνδέσει κάποιον μπορεί να ανακαλέσει ένα αναγνωριστικό. Το Connect κρατά τα ανακληθέντα αναγνωριστικά για πάντα, οπότε το παλιό κλειδί και κάθε σφράγιση που έγινε για αυτό παύουν να λειτουργούν, και αποδεσμεύει τους χώρους εργασίας Slack που ήταν δεμένοι με το παλιό αναγνωριστικό. Τα tokens που έχουν ήδη δοθεί λήγουν μόνα τους: μέσα σε 8 ώρες για των ανθρώπων, 1 ώρα για των bot. Το Connect κρατά το πολύ 100.000 ανακληθέντα αναγνωριστικά· πέρα από αυτό, μια εναλλαγή απορρίπτεται και το αρχείο καταγραφής το λέει σε επίπεδο σφάλματος.

## Αντιμετώπιση προβλημάτων

### Ένας διακομιστής λέει ότι το Connect τον έχει αποκλείσει

Το αναγνωριστικό εγκατάστασής του δεν βρίσκεται στο `CONNECT_ALLOWED_INSTALLS`, βρίσκεται
στο `CONNECT_DENY_INSTALLS`, ή ανακλήθηκε από εναλλαγή κλειδιού. Το αναγνωριστικό αλλάζει
όταν ο ιδιοκτήτης του εναλλάσσει το κλειδί· ζητήστε το νέο.

### Κάθε σύνδεση σε έναν πάροχο αποτυγχάνει

Μπορεί να λείπει μία από τις μεταβλητές του, οπότε το Connect άφησε τη λωρίδα εκτός. Ελέγξτε
το αρχείο καταγραφής εκκίνησης και τους παραπάνω πίνακες. Το GitHub χρειάζεται και
τα πέντε: app id, slug, client id, client secret και ιδιωτικό κλειδί· η Google χρειάζεται
και το client id και το μυστικό.

### Οι συνδέσεις αποτυγχάνουν με αναντιστοιχία ανακατεύθυνσης

Η ανακατεύθυνση που καταχωρίστηκε στον πάροχο δεν ταιριάζει ακριβώς με το
`CONNECT_PUBLIC_URL`. Συγκρίνετε σχήμα, κεντρικό υπολογιστή, θύρα και, για ένα
προσαρτημένο Connect, τη διαδρομή `/connect`.

### Όλοι χρειάστηκε να συνδεθούν ξανά

Το κλειδί σφράγισης άλλαξε ή χάθηκε, ένας διακομιστής έκανε εναλλαγή του κλειδιού του ή τα
δεδομένα ενός διακομιστή επαναφέρθηκαν σε άλλο μηχάνημα. Ένα σφραγισμένο
διαπιστευτήριο ανοίγει μόνο για την εγκατάσταση και το Connect που το
δημιούργησαν.
