Αυτός ο οδηγός δείχνει πώς να ρυθμίσετε τους περιορισμούς: τους κανόνες που
αποφασίζουν αν μια ενέργεια πράκτορα θα εκτελεστεί, θα ζητήσει πρώτα έγκριση ή
θα απορριφθεί.

Οι περιορισμοί καλύπτουν τις δεκατρείς κατηγορίες επιδράσεων που δηλώνει κάθε
εργαλείο που μεταβάλλει κατάσταση. Επιβάλλονται στην πλευρά του διακομιστή, τη
στιγμή που καλείται το εργαλείο, ποτέ μέσω οδηγίας σε μια προτροπή.

## Ορίστε μια απόφαση για μια κατηγορία ενέργειας

1. Μεταβείτε στις **Ρυθμίσεις → Χώρος εργασίας → Δικαιώματα πρακτόρων**
2. Επιλέξτε πεδίο εφαρμογής με τον τμηματικό διακόπτη: **Χώρος εργασίας**,
   **Πράκτορας** (έπειτα επιλέξτε τον πράκτορα) ή **Χώρος** (έπειτα επιλέξτε τον
   χώρο)
3. Στη γραμμή της κατηγορίας ενέργειας, επιλέξτε **Αποδοχή**, **Ερώτηση πρώτα** ή
   **Απόρριψη**
4. Για να καταργήσετε έναν κανόνα που ορίσατε, πατήστε το κουμπί επαναφοράς που
   εμφανίζεται στο τέλος αυτής της γραμμής (**Επαναφορά στο κληρονομημένο**) — η
   απόφαση επιστρέφει στο ευρύτερο πεδίο εφαρμογής

Κάθε γραμμή εμφανίζει την ισχύουσα απόφαση ως ετικέτα κατάστασης και ένα σήμα
για την προέλευσή της: **Αυτό το πεδίο**, **Κληρονομημένο** ή **Ενσωματωμένη
προεπιλογή**. Ο πίνακας επιλύεται στη λειτουργία **Πράκτορας** (`chat`), οπότε το
**Προκαθορισμένο λειτουργίας** δεν εμφανίζεται ποτέ εδώ — χρησιμοποιήστε τον
έλεγχο «Τι θα γίνει;» με επιλεγμένη λειτουργία μόνο ανάγνωσης για να δείτε αυτό το
επίπεδο.

Η σύνταξη ενός κανόνα απαιτεί τον ρόλο `admin`. Η ανάγνωση του πίνακα δεν τον
απαιτεί.

Σημείο ελέγχου: ορίστε το **Push σε απομακρυσμένο** σε **Απόρριψη** στο πεδίο
εφαρμογής του χώρου εργασίας και έπειτα εκτελέστε τον έλεγχο «Τι θα γίνει;»
παρακάτω για την εντολή `git push origin main`. Το αποτέλεσμα εμφανίζει `deny` με
πηγή `workspace`.

## Κατανοήστε πώς επιλύεται μια απόφαση

Η επίλυση γίνεται **πρώτα με ειδικότητα και έπειτα με περιοριστικότητα**:

1. Κανόνες **Χώρου**, έπειτα **πράκτορα**, έπειτα **χώρου εργασίας**. Το πρώτο
   πεδίο εφαρμογής με κανόνα που ταιριάζει αποφασίζει και η επίλυση σταματά
2. Αν δεν ταιριάζει κανένας κανόνας, εφαρμόζεται το **προκαθορισμένο λειτουργίας**
   — μια λειτουργία μόνο ανάγνωσης (σχέδιο, ανασκόπηση, ενορχήστρωση) απορρίπτει
   έντεκα από τις δεκατρείς κατηγορίες
3. Αν η λειτουργία δεν έχει τίποτα να πει, εφαρμόζεται η **ενσωματωμένη
   προεπιλογή**

Μέσα σε ένα μόνο πεδίο εφαρμογής, ένας κανόνας εντολής επιλύεται με το
μεγαλύτερο ταιριαστό πρόθεμα και μια εξίσου ειδική σύγκρουση επιλύεται με τον
**πιο περιοριστικό** τρόπο — η απόρριψη υπερισχύει της ερώτησης πρώτα, που
υπερισχύει της αποδοχής. Μια ενέργεια που δηλώνει πολλές κατηγορίες επιλύει
καθεμία ανεξάρτητα και έπειτα τις συνδυάζει με τον πιο περιοριστικό τρόπο.

:::caution[Η αποδοχή δεν υπερισχύει της απόρριψης]
Ένας στενότερος κανόνας υπερισχύει λόγω ειδικότητας και μια ισοπαλία λύνεται με
βάση την περιοριστικότητα — άρα μια **Αποδοχή** στο πεδίο εφαρμογής του χώρου
εργασίας δεν υπερισχύει μιας **Απόρριψης** πουθενά.
:::

Μια απόφαση **Ερώτηση πρώτα** εμφανίζει μία προτροπή έγκρισης που καλύπτει κάθε
κατηγορία που επιλύθηκε σε `prompt`. **Χωρίς συνδεδεμένο εγκριτή απορρίπτεται**,
τόσο για εντολές shell όσο και για κλήσεις εργαλείων του harness. Αυτό είναι
σκόπιμο: μια εκτέλεση χωρίς έλεγχο είναι χειρότερη από μια απορριφθείσα.

### Κατηγορίες ενεργειών και ενσωματωμένες προεπιλογές

| Κατηγορία ενέργειας                              | Ενσωματωμένη προεπιλογή |
| ------------------------------------------------ | ----------------------- |
| Διαγραφή αρχείου                                 | Ερώτηση πρώτα           |
| Εγγραφή εκτός του worktree                       | Αποδοχή                 |
| Δημιουργία commit                                | Αποδοχή                 |
| Push σε απομακρυσμένο                            | Ερώτηση πρώτα           |
| Άνοιγμα pull request                             | Ερώτηση πρώτα           |
| Δημοσίευση ανασκόπησης ή συγχώνευση              | Ερώτηση πρώτα           |
| Εγγραφή σε εξωτερικό tracker                     | Ερώτηση πρώτα           |
| Πρόσβαση στο δίκτυο                              | Αποδοχή                 |
| Ανάγνωση μυστικού                                | Αποδοχή                 |
| Εγκατάσταση πακέτου                              | Αποδοχή                 |
| Εκτέλεση διεργασίας                              | Αποδοχή                 |
| Αλλαγή δομής χώρου εργασίας                      | Αποδοχή                 |
| Έλεγχος απομονωμένου περιβάλλοντος (σταθμός)     | Αποδοχή                 |

Η ταξινομία είναι κλειστή. Ένα νέο εργαλείο που κυκλοφορεί χωρίς να δηλώνει τις
κατηγορίες του αποτυγχάνει σε ένα τεστ καστάνιας στο CI, ώστε τίποτα να μην
φτάνει με σιωπηλά κενό σύνολο επιδράσεων.

## Δοκιμάστε έναν κανόνα με τον έλεγχο «Τι θα γίνει;»

Πριν αλλάξετε έναν κανόνα, ελέγξτε πώς τον επιλύει ήδη η τρέχουσα πολιτική.

1. Στην ίδια σελίδα, μεταβείτε στο **Τι θα γίνει;**
2. Επιλέξτε μια **Ενέργεια** (μία από τις δεκατρείς κατηγορίες)
3. Προαιρετικά συμπληρώστε **Εντολή** (για παράδειγμα `git push origin main`),
   **Πράκτορας**, **Χώρος** και **Λειτουργία**
4. Διαβάστε το αποτέλεσμα: την απόφαση, τον λόγο και την **Πηγή:**

Ο έλεγχος εκτελεί τον ίδιο επιλυτή που χρησιμοποιεί η διαδρομή επιβολής, πάνω
στους ενεργούς κανόνες σας, οπότε η απάντηση είναι ακριβής. Αν σας εκπλήξει,
αλλάξτε έναν κανόνα στον πίνακα παραπάνω και ελέγξτε ξανά.

## Ρυθμίστε το κουμπί αυτονομίας ενός χώρου

Το κουμπί ισχύει ανά πράκτορα και ανά χώρο και συνδυάζεται με τους κανόνες αντί
να τους αντικαθιστά.

1. Ανοίξτε τον χώρο
2. Ανοίξτε τη **Διαχείριση συμμετεχόντων** από την κεφαλίδα του χώρου
3. Στην **Αυτονομία**, στη γραμμή του πράκτορα, επιλέξτε ένα επίπεδο:

| Επίπεδο               | Επίδραση                                                                                                       |
| --------------------- | -------------------------------------------------------------------------------------------------------------- |
| **Προεπιλογή**        | Καμία ρύθμιση χώρου — συμπεριφέρεται ως **Ενέργεια με έγκριση**                                                 |
| **Μόνο πρόταση**      | Κάθε ελεγχόμενο εργαλείο απορρίπτεται ευθέως, με μήνυμα που λέει στον πράκτορα να προτείνει την ενέργεια αντ’ αυτού |
| **Ενέργεια με έγκριση** | Οι ριψοκίνδυνες ενέργειες προσκρούουν στην πύλη έγκρισης που αποτυγχάνει κλειστή                                |
| **Ελεύθερη ενέργεια** | Προεγκρίνει οτιδήποτε δεν επιλύθηκε σε σκληρή απόρριψη                                                          |

:::caution[Η ελεύθερη ενέργεια καταπίνει κάθε προτροπή]
Με την **Ελεύθερη ενέργεια**, μια απόφαση **Ερώτηση πρώτα** εγκρίνεται χωρίς να
σας ρωτήσει. Μόνο ένα `deny` — από κανόνα, από το προκαθορισμένο λειτουργίας ή
από ενσωματωμένη προεπιλογή — εξακολουθεί να μπλοκάρει. Καταφύγετε σε αυτήν όταν
παρακολουθείτε τον χώρο, όχι ως προεπιλογή.
:::

Το κουμπί φτάνει μόνο στο ενσωματωμένο harness. Ο προσαρμογέας Claude Code
εκτελεί τα δικά του εργαλεία εκτός αυτής της πύλης.

## Μάθετε πού δεν φτάνουν οι περιορισμοί

Ο πίνακας **Πού εφαρμόζονται οι κανόνες** στο κάτω μέρος της ίδιας σελίδας είναι
η έκδοση αυτού μέσα στην εφαρμογή: ανά κατηγορία επίδρασης, δηλώνει αν κάθε
εκτελεστής την πιάνει στην πύλη πολιτικής, την αφήνει στο sandbox ή δεν μπορεί να
την αναχαιτίσει καθόλου.

- **Ο προσαρμογέας Claude Code** δεν ελέγχεται ως προς τις δικές του κλήσεις
  εργαλείων. Το Claude Code εκκινείται με `--dangerously-skip-permissions`, οπότε
  οι κλήσεις ανάγνωσης, εγγραφής, επεξεργασίας και bash δεν περνούν ποτέ από τον
  φρουρό. Αυτό που ελέγχεται για αυτόν τον προσαρμογέα είναι η επιφάνεια εργαλείων
  MCP στην οποία καλεί πίσω και η εντολή shell που εκκινεί το Control Center για
  να το ξεκινήσει.
- **Το ρήμα εξόδου της ίδιας της λειτουργίας** (`submit_plan`,
  `propose_orchestration`) είναι καρφιτσωμένο και δεν μπορεί ποτέ να απορριφθεί —
  αλλιώς μια λειτουργία θα ήταν δομικά ανίκανη να παραγάγει το μοναδικό παραδοτέο
  της.
- **Το αν το sandbox ενισχύει αυτούς τους κανόνες εξαρτάται από τον κεντρικό
  υπολογιστή.** Όπου το `cc_server` βρίσκει ένα backend, περιτυλίγει το CLI του
  Claude Code και το εργαλείο `bash` του harness, ώστε ένας κανόνας που δεν
  γράψατε εσείς να έχει ακόμη ένα κατώτατο όριο του λειτουργικού συστήματος από
  κάτω του. Στα **Windows δεν υπάρχει κανένα** και σε Linux ή WSL2 χωρίς `bwrap`
  και `socat` επίσης δεν υπάρχει κανένα — εκεί, οι περιορισμοί μαζί με την
  επιφάνεια εργαλείων της λειτουργίας αποτελούν ολόκληρη την επιβολή, όχι μια
  δεύτερη γραμμή της. Ελέγξτε σε ποια περίπτωση βρίσκεστε με τη
  [Ρύθμιση πολιτικών sandbox](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/πολιτικές-sandbox/).
