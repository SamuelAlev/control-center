Αυτός ο οδηγός δείχνει πώς να δουλέψετε με το Control Center χωρίς να φύγετε
από το GitHub: να ζητήσετε έλεγχο με AI από τη σελίδα του PR, να κάνετε μια
ερώτηση στο bot μέσα σε ένα σχόλιο και να συνεχίσετε τη συνομιλία στα νήματα
ελέγχου του.

Οι απαντήσεις έρχονται μέσω του καναλιού GitHub του χώρου εργασίας: της δικής
[GitHub App](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/github-app/) του διακομιστή σας ή της
κοινόχρηστης App του Control Center μέσω του Connect. Δεν καταχωρίζεται τίποτα νέο και τίποτα δεν χρειάζεται να είναι προσβάσιμο από το
διαδίκτυο: ο διακομιστής ανακαλύπτει όσα λέγονται στο GitHub με περιοδική
σάρωση, οπότε ένας φορητός υπολογιστής πίσω από NAT συμπεριφέρεται ακριβώς όπως
μια δημόσια ανάπτυξη.

## Προϋποθέσεις

- Ο χώρος εργασίας έχει κανάλι GitHub: τη δική GitHub App του διακομιστή ή το
  Connect, με την εφαρμογή [εγκατεστημένη](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/github-app/#εγκαταστήστε-την-εκεί-όπου-βρίσκονται-τα-αποθετήριά-σας)
  στον λογαριασμό που κατέχει το αποθετήριο. Μια δική σας εφαρμογή χρειάζεται
  **Pull requests** και **Issues** για ανάγνωση και εγγραφή, που τα παραχωρεί ήδη
  η **Δημιουργία της εφαρμογής μου GitHub**
- Το αποθετήριο είναι συνδεδεμένο με έναν χώρο εργασίας στο Control Center
- Έχετε [συνδεθεί στο GitHub](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/ενσωμάτωση-github/) σε αυτόν τον
  διακομιστή και μπορείτε να κάνετε push στο αποθετήριο
- Χωρίς URL webhook, χωρίς σήραγγα, χωρίς callback — δεν υπάρχει τίποτα να
  ρυθμίσετε στο δίκτυο

## Βρείτε το όνομα του bot σας

Αναφέρετε το `@usectrl`, τον ειδικό λογαριασμό GitHub του Control Center. Είναι η μόνη ενεργοποίηση. Η αναφορά στο ίδιο το όνομα σύνδεσης της εφαρμογής δεν κάνει τίποτα· το κανάλι GitHub του χώρου εργασίας σας εξακολουθεί να διαχειρίζεται το αίτημα και να δημοσιεύει τις απαντήσεις. Δεν χρειάζεστε διαπιστευτήρια για τον λογαριασμό `usectrl`.

## Ζητήστε έλεγχο από το GitHub

Δύο τρόποι, που ξεκινούν και οι δύο το ίδιο ενσωματωμένο pipeline `pr_review` που
ξεκινά το κουμπί **Ερώτηση AI**:

- **Προσθέστε την ετικέτα `ai-review`** στο PR. Αυτό είναι το κοντινότερο που
  προσφέρει το GitHub στην ανάθεση του bot ως ελεγκτή — οι λογαριασμοί
  εφαρμογών δεν μπορούν να καταλάβουν την εγγενή θέση του ζητούμενου ελεγκτή.
  Ο λογαριασμός σας αντιδρά στο PR με 👀 και ο έλεγχος ξεκινά στο Control
  Center· δεν αναρτάται σχόλιο
- **Σχολιάστε `@usectrl review`** (ή απλώς `@usectrl`) στη συνομιλία του PR. Ένα
  👀 εμφανίζεται στο σχόλιό σας και μετά μια απάντηση λέει ότι ο έλεγχος ξεκίνησε
  (ή ότι ένας εκτελείται ήδη)

Οι ελεγκτές εργάζονται στον χώρο ελέγχου του PR· διαβάστε και δημοσιεύστε τα
ευρήματα όπως στη [Χρήση ελέγχου με AI](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/έλεγχος-με-ai/). Η δημοσίευση
πίσω στο GitHub παραμένει απόφαση που παίρνετε στο Control Center — η έναρξη ενός
ελέγχου από το GitHub δεν δημοσιεύει από μόνη της τίποτα στο GitHub.

Η ετικέτα ενεργοποιείται μία φορά ανά PR: η προσθήκη της είναι το αίτημα και δεν
επανενεργοποιείται όταν αφαιρεθεί και προστεθεί ξανά. Για να εκτελέσετε ξανά έναν
έλεγχο — μετά από ένα push, ας πούμε — κάντε @-αναφορά στο bot.

## Κάντε μια ερώτηση

Σχολιάστε στη συνομιλία του PR:

```text
@usectrl why does the flaky test in runner_test.dart fail on CI but not locally?
```

Τι συμβαίνει, με τη σειρά:

1. Ένα 👀 εμφανίζεται στο σχόλιό σας, από τον δικό σας λογαριασμό, ώστε να ξέρετε
   ότι το σχόλιο ειδώθηκε
2. Η ερώτηση αναρτάται στον χώρο ελέγχου του PR **ως εσείς** — ίδια απόδοση όπως
   αν την είχατε πληκτρολογήσει στο Control Center
3. Ένας πράκτορας απαντά στον χώρο και η απάντηση αναρτάται πίσω στο PR. Κάθε
   απάντηση ξεκινά με `**Control Center** (for @your-login):`

Μια ερώτηση σε PR χωρίς έλεγχο ακόμη ξυπνά τον πράκτορα CEO του χώρου εργασίας·
μόλις εκτελεστεί ένας έλεγχος, απαντά ο πράκτορας που μίλησε τελευταίος, ώστε οι
συνέχειες να καταλήγουν σε όποιον έχει το πλαίσιο.

## Συνεχίστε σε ένα νήμα ελέγχου

Απαντήστε μέσα σε ένα ενσωματωμένο νήμα ελέγχου στο οποίο συμμετέχει το bot — ένα
σχόλιο σε diff που άφησε, ή μια απάντηση που ανήρτησε σε εκείνο το νήμα. Δεν
χρειάζεται @-αναφορά· το νήμα **είναι** η απεύθυνση:

```text
> @usectrl the retry loop looks O(n²) to me

what would the complexity be with the bounded queue instead?
```

Οι πολλαπλές στροφές λειτουργούν με τον ίδιο τρόπο: κάθε απάντηση είναι άλλη μια
ερώτηση στην ίδια συνομιλία, με τον χώρο ελέγχου ως πλαίσιο, και η απάντηση
επιστρέφει στο νήμα.

Μια συνέχεια στο χρονολόγιο της συνομιλίας του PR είναι νέο σχόλιο στο ανώτατο
επίπεδο, οπότε εξακολουθεί να χρειάζεται @-αναφορά.

## Σε ποιον μιλά το bot

Ο διακομιστής αντιστοιχίζει τον συντάκτη ενός σχολίου, ή όποιον πρόσθεσε την
ετικέτα `ai-review`, πριν κάνει οτιδήποτε:

- **Ο λογαριασμός GitHub πρέπει να είναι συνδεδεμένος** σε αυτόν τον διακομιστή.
  Η αντιστοίχιση γίνεται με το αριθμητικό αναγνωριστικό λογαριασμού του GitHub,
  ποτέ με το όνομα σύνδεσης. Συνδεθείτε από τις **Ρυθμίσεις → Εσείς →
  Προφίλ → Φιλοξενία κώδικα**
- **Το πρόσωπο πρέπει να είναι μέλος με ρόλο εγγραφής** (`member`, `admin` ή
  `owner`) στον χώρο εργασίας που συνδέει το αποθετήριο
- **Το πρόσωπο πρέπει να μπορεί να κάνει push** στο αποθετήριο στο GitHub. Οι
  απαντήσεις χρησιμοποιούν ένα token περιορισμένο στην πρόσβαση αυτού του
  προσώπου, οπότε όποιος μπορεί μόνο να διαβάζει δεν παίρνει απάντηση

Οποιοσδήποτε άλλος αγνοείται σιωπηλά: δεν αναρτάται τίποτα και τα λόγια του δεν
μπαίνουν ποτέ στον χώρο εργασίας. Τα σχόλια από bots και οι ίδιες οι απαντήσεις
του Control Center δεν αντιμετωπίζονται ποτέ ως ερωτήσεις.

### Δύο διακομιστές, ένα PR

Το 👀 είναι επίσης ο τρόπος με τον οποίο οι διακομιστές συμφωνούν ποιος απαντά.
Προστίθεται με τη δική σύνδεση του συντάκτη, και το GitHub λέει στον διακομιστή
αν αυτή η αντίδραση είναι νέα. Αν είστε συνδεδεμένοι σε δύο διακομιστές Control
Center που συνδέουν και οι δύο το αποθετήριο, απαντά ο πρώτος που αντιδρά και ο
άλλος μένει σιωπηλός. Το ίδιο ισχύει και για την ετικέτα.

## Τι να περιμένετε

| Θέμα                  | Συμπεριφορά                                                              |
| --------------------- | ------------------------------------------------------------------------ |
| Επιβεβαίωση           | 👀 από τον λογαριασμό σας στο σχόλιο (ή στο PR, για την ετικέτα), μέσα σε μία σάρωση |
| Απαντήσεις            | Αναρτώνται στη λωρίδα όπου τέθηκε η ερώτηση, ξεκινώντας με `**Control Center** (for @your-login):`. Ο συντάκτης είναι το bot της εφαρμογής. Στην κοινόχρηστη εφαρμογή του Connect, μια απάντηση μέσα σε νήμα ανασκόπησης γράφεται από τον δικό σας λογαριασμό, εκτός αν ο διαχειριστής του Connect έχει καταγράψει αυτή την εγκατάσταση |
| Απόδοση εντός χώρου   | Η ερώτηση είναι δική σας· ο πράκτορας εκτελείται για λογαριασμό σας, με τις ρυθμίσεις αυτονομίας του χώρου |
| Έλεγχοι               | Τα ευρήματα προσγειώνονται στον χώρο ελέγχου· η δημοσίευση στο GitHub είναι χειροκίνητη |

Μια σάρωση εκτελείται κάθε λεπτό σε μια δική σας εφαρμογή και ελέγχει έως 25
pull requests· μέσω του Connect εκτελείται κάθε δύο λεπτά και ελέγχει έως 10,
επειδή αυτές οι κλήσεις μοιράζονται το δικό όριο GitHub κάθε μέλους. Ένας χώρος
εργασίας του οποίου το όριο GitHub είναι κάτω από 15 % παραλείπεται μέχρι να
ανακάμψει. Η καθυστέρηση είναι το τίμημα για να μη χρειάζεται καθόλου
εισερχόμενη πρόσβαση δικτύου. Τίποτα δεν χάνεται όσο ο διακομιστής είναι εκτός λειτουργίας — ένα σχόλιο που
φτάνει κατά τη διάρκεια της διακοπής πιάνεται στην επόμενη σάρωση.

## Αντιμετώπιση προβλημάτων

**Δεν συμβαίνει τίποτα για ένα σχόλιο που κάνει @-αναφορά στο bot.**

- Είναι η εφαρμογή **εγκατεστημένη** στον λογαριασμό που κατέχει το αποθετήριο
  και το αποθετήριο **συνδεδεμένο** με χώρο εργασίας; Ένα μη συνδεδεμένο
  αποθετήριο παραλείπεται πριν καταγραφεί οτιδήποτε, οπότε η σύνδεσή του
  αργότερα παραδίδει ακόμη
- Έχετε συνδεθεί στο GitHub σε αυτόν τον διακομιστή, είστε μέλος με ρόλο
  εγγραφής και μπορείτε να κάνετε push στο αποθετήριο; Ο διακομιστής αγνοεί
  οποιονδήποτε άλλον χωρίς να απαντήσει
- Τίποτα ακόμη; Το αρχείο καταγραφής του διακομιστή αναφέρει τη σάρωση και το PR
  όταν κάτι αποτυγχάνει· αναζητήστε τα `pr_conversation:` (η περιοδική σάρωση)
  και `github_pr_conversation:` (η γέφυρα)

**Η ετικέτα δεν ξεκινά έλεγχο.**

Ενεργοποιείται μία φορά ανά PR, και όποιος την πρόσθεσε περνά τους ίδιους
ελέγχους με τον συντάκτη ενός σχολίου. Αν έχει ήδη εκτελεστεί έλεγχος, ή η ετικέτα
προστέθηκε πριν ο διακομιστής δει ποτέ το PR (η πρώτη σάρωση καταγράφει σιωπηλά
ό,τι εκκρεμεί αντί να το πλημμυρίσει), κάντε @-αναφορά στο bot — το
`@usectrl review` ξεκινά πάντα έναν, εκτός αν υπάρχει ήδη έλεγχος σε εξέλιξη.

**Η απάντηση του bot δεν έφτασε ποτέ στο GitHub.**

Η ίδια η απάντηση δεν χάνεται ποτέ — βρίσκεται στον χώρο ελέγχου του PR στο
Control Center. Μια αποτυχία ανάρτησης (το GitHub έπεσε, άλλαξαν τα δικαιώματα)
καταγράφεται και η απάντηση δεν επαναλαμβάνεται· ρωτήστε ξανά στο νήμα αν έχει
σημασία.
