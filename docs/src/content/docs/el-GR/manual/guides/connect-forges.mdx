Το Control Center συνεργάζεται με τρεις κεντρικούς υπολογιστές κώδικα, που σε όλη την εφαρμογή αποκαλούνται **forges**: **GitHub**, **GitLab** και **Bitbucket Cloud**. Κανένας τους δεν είναι ο προεπιλεγμένος. Συνδέστε έναν και όλα λειτουργούν· συνδέστε πολλούς και ένας μόνο χώρος εργασίας μπορεί να φιλοξενεί ταυτόχρονα αποθετήρια από όλους.

Ο κεντρικός υπολογιστής κώδικα είναι ιδιότητα κάθε **αποθετηρίου** και διαβάζεται από το remote `origin` του όταν το καταχωρίζετε. Δεν τον επιλέγετε ποτέ μόνοι σας και δεν υπάρχει ρύθμιση ανά χώρο εργασίας που να μπορεί να πάει στραβά.

## Σύνδεση κεντρικού υπολογιστή κώδικα

1. Ανοίξτε **Ρυθμίσεις → Εσείς → Προφίλ** (`/settings/you/profile`).
2. Βρείτε την κάρτα **Φιλοξενία κώδικα**. Εκεί εμφανίζεται κάθε υποστηριζόμενος κεντρικός υπολογιστής κώδικα, συνδεδεμένος ή όχι.
3. Στο **GitHub**, πατήστε **Σύνδεση στο GitHub**. Στο **GitLab** ή στο **Bitbucket**, πατήστε **Προσθήκη token** και επικολλήστε ένα.

**Το GitHub λειτουργεί μόνο με σύνδεση.** Η σύνδεση εκτελείται μέσω της δικής GitHub App του διακομιστή ή μέσω του Control Center Connect, ανάλογα με το τι ρύθμισε ο ιδιοκτήτης του διακομιστή, ή μέσω των εφαρμογών που επέλεξε για τον χώρο εργασίας ένας διαχειριστής του χώρου εργασίας στις **Ρυθμίσεις → Χώρος εργασίας → Ενσωματώσεις** (δείτε [Ρύθμιση ενσωμάτωσης GitHub](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/ενσωμάτωση-github/))· δεν υπάρχει token GitHub για επικόλληση. Το GitLab και το Bitbucket εξακολουθούν να δέχονται προσωπικό token.

Σε κάθε περίπτωση, το διαπιστευτήριο είναι **δικό σας και φιλοξενείται στον διακομιστή**, με κλειδί το αναγνωριστικό χρήστη σας: κανένα token δεν αποθηκεύεται στη μηχανή στην οποία το πληκτρολογήσατε, κάθε συσκευή από την οποία συνδέεστε χρησιμοποιεί το ίδιο και κανένα άλλο μέλος δεν μπορεί να το διαβάσει. Τίθεται σε ισχύ από το **επόμενο αίτημα** — δεν χρειάζεται επανεκκίνηση, και η αποσύνδεση σταματά αμέσως την αποστολή του.

Η κάρτα δείχνει πού χρησιμοποιούνται οι λογαριασμοί σας. Ένα token GitLab ή Bitbucket ισχύει για εσάς σε **κάθε χώρο εργασίας του διακομιστή**, οπότε το επικολλάτε μία φορά. Η δική σας σύνδεση στο GitHub ισχύει επίσης, εκτός αν ένας χώρος εργασίας έχει δικές του εφαρμογές σύνδεσης: τότε ο χώρος εργασίας κρατά δική του σύνδεση στο GitHub, και η κάρτα το αναφέρει.

Κάθε γραμμή δείχνει την κατάσταση του **δικού σας** διαπιστευτηρίου. Μόνο το δικό σας διαπιστευτήριο απαντά για εσάς· τίποτε άλλο δεν παρεμβάλλεται:

| Η γραμμή λέει | Σημασία |
| ------------- | ------- |
| `Συνδεθήκατε ως octocat` | Χρησιμοποιείται το δικό σας διαπιστευτήριο |
| `Δεν έχει συνδεθεί` | Δεν έχετε διαπιστευτήριο για αυτόν τον κεντρικό υπολογιστή κώδικα |
| `Η σύνδεσή σας στο GitHub ως octocat έληξε. Συνδεθείτε ξανά.` | Η σύνδεσή σας έληξε ή ανακλήθηκε στον κεντρικό υπολογιστή κώδικα |
| `Σε παύση: η υπηρεσία σύνδεσης αυτού του χώρου εργασίας άλλαξε` | Ο χώρος εργασίας μετέβη σε άλλη υπηρεσία σύνδεσης. Η σύνδεσή σας διατηρείται και λειτουργεί ξανά αν επιστρέψει στην προηγούμενη, γι' αυτό δεν υπάρχει κουμπί σύνδεσης |
| `Δεν είναι δυνατή η επικοινωνία με το GitHub αυτή τη στιγμή. Γίνεται νέα προσπάθεια.` | Παροδική διακοπή. Το Control Center συνεχίζει τις προσπάθειες· δεν χρειάζεται να κάνετε κάτι |
| Μια πρόταση που εξηγεί γιατί η σύνδεση δεν είναι διαθέσιμη | Για παράδειγμα `Η σύνδεση με GitHub δεν έχει ρυθμιστεί για αυτόν τον χώρο εργασίας.` ή `Η υπηρεσία σύνδεσης αυτού του χώρου εργασίας άλλαξε ταυτότητα. Ένας διαχειριστής πρέπει να την επιβεβαιώσει.` Οι διαχειριστές έχουν ένα κουμπί προς τη ρύθμιση που το διορθώνει |

### Τι token θέλει κάθε κεντρικός υπολογιστής κώδικα

| Κεντρικός υπολογιστής | Token | Πού να το δημιουργήσετε |
| --------------------- | ----- | ----------------------- |
| **GitLab** | Ένα προσωπικό token πρόσβασης με `api` | gitlab.com → User settings → Access tokens |
| **Bitbucket** | Ένα Atlassian API token, συν το email του λογαριασμού σας | id.atlassian.com → Security → API tokens |

Το Bitbucket αυθεντικοποιείται με το **email του λογαριασμού σας ως όνομα χρήστη** και με το API token ως κωδικό πρόσβασης, γι' αυτό το παράθυρο του Bitbucket ζητά και τα δύο. Ένα **token πρόσβασης** του Bitbucket για αποθετήριο, έργο ή χώρο εργασίας δεν ανήκει σε κανένα πρόσωπο, γι' αυτό αυτό το παράθυρο το απορρίπτει: είναι αντί γι' αυτό ένα [token αυτοματοποίησης](#προσθήκη-token-αυτοματοποίησης). Το ίδιο ισχύει για διακριτικό **έργου** ή **ομάδας** του GitLab: το GitLab ζητά να μάθει σε ποιον ανήκει το token πριν αποθηκευτεί, και εδώ απορρίπτεται το token ενός bot.

Ένα token δεν δένεται ποτέ με έναν χώρο εργασίας: κρατάτε ένα ανά κεντρικό υπολογιστή κώδικα, και κάθε χώρος εργασίας του διακομιστή το χρησιμοποιεί. Το **Αποσύνδεση** το αφαιρεί για όλους.

### Εργασία στο παρασκήνιο

Η εργασία χωρίς άνθρωπο πίσω της (εκτελέσεις πρακτόρων, pipelines, polling PR) χρειάζεται επίσης διαπιστευτήριο, και κάθε κεντρικός υπολογιστής κώδικα το παρέχει διαφορετικά:

- **GitHub** — ένα token για ένα αποθετήριο κάθε φορά, που εκδίδεται από τη GitHub App του διακομιστή ή μέσω του Connect και περιορίζεται σε ό,τι μπορεί να κάνει εκεί ένα υπόλογο μέλος. Δεν είναι ποτέ η σύνδεση ενός ατόμου παραδομένη ολόκληρη, και καμία μεταβλητή περιβάλλοντος ή επικολλημένο token δεν το υποκαθιστά. Δείτε [Ρύθμιση ενσωμάτωσης GitHub](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/ενσωμάτωση-github/#για-λογαριασμό-ποιου-ενεργεί-το-διαπιστευτήριό-σας)
- **GitLab** και **Bitbucket** — μόνο το **token αυτοματοποίησης** του αποθετηρίου: ένα token πρόσβασης bot που προσθέτει ένας διαχειριστής του χώρου εργασίας για αυτό το αποθετήριο ή για κάθε αποθετήριο αυτού του κεντρικού υπολογιστή στον χώρο εργασίας. Το token του αποθετηρίου υπερισχύει αυτού του χώρου εργασίας. Ο έλεγχος PR, τα σχόλια αυτόματης ανασκόπησης AI, και τα push και τα merge requests που δεν ζήτησε κανείς χρησιμοποιούν όλα αυτό, οπότε στον κεντρικό υπολογιστή εμφανίζονται ως αυτό το bot, ποτέ ως μέλος. Δεν υποκαθιστά το προσωπικό token κανενός μέλους, και δεν υπάρχει token σε επίπεδο διακομιστή ή μεταβλητής περιβάλλοντος. Χωρίς αυτό, η εργασία στο παρασκήνιο για το αποθετήριο σταματά προσωρινά και η ειδοποίηση πρόσβασης στα αποθετήρια το λέει.

Η εργασία που ζητά ένα μέλος (σχόλιο, ανασκόπηση, merge request πράκτορα που ανοίχτηκε για λογαριασμό του) εξακολουθεί να χρησιμοποιεί το δικό του token.

## Προσθήκη token αυτοματοποίησης

Τα διακριτικά αυτοματοποίησης τα βλέπουν και τα αλλάζουν μόνο οι διαχειριστές του χώρου εργασίας. Κάθε ένα ελέγχεται από την πλατφόρμα όταν το αποθηκεύετε: απορρίπτεται ένα token που ενεργεί ως άτομο (ένα προσωπικό token GitLab, ένα Atlassian API token ή οποιοδήποτε token Bitbucket που συνδέεται ως λογαριασμός κάποιου ατόμου), και το ίδιο ισχύει για ένα token που δεν μπορεί να διαβάσει το αποθετήριο για το οποίο προορίζεται.

- **Για ένα αποθετήριο:** ανοίξτε **Ρυθμίσεις → Χώρος εργασίας → Αποθετήρια**. Η κάρτα **Διακριτικά αυτοματοποίησης** εμφανίζει κάθε αποθετήριο GitLab και Bitbucket με το bot που δρα εκεί, **Χρησιμοποιεί το διακριτικό του χώρου εργασίας**, ή **Κανένα διακριτικό. Η αυτοματοποίηση είναι σε παύση εδώ.** Πατήστε **Προσθήκη token** στη γραμμή του αποθετηρίου.
- **Για κάθε αποθετήριο ενός κεντρικού υπολογιστή:** ανοίξτε **Ρυθμίσεις → Χώρος εργασίας → Ενσωματώσεις**, βρείτε την κάρτα **Διακριτικά αυτοματοποίησης** και πατήστε **Προσθήκη token** στη γραμμή GitLab ή Bitbucket. Τα αποθετήρια που το token δεν μπορεί να διαβάσει ονομάζονται μετά την αποθήκευση και μένουν σε παύση.

Όταν η εργασία στο παρασκήνιο είναι ήδη σε παύση, οι διαχειριστές βλέπουν επίσης το **Προσθήκη token** απευθείας στην ειδοποίηση πρόσβασης στα αποθετήρια. Το **Ενημέρωση token** αντικαθιστά ένα token· το κουμπί του κάδου το αφαιρεί, και κάθε αποθετήριο που μένει χωρίς αυτό τίθεται σε παύση. Αν ο κεντρικός υπολογιστής αρνηθεί αργότερα ένα αποθηκευμένο token (ανακλήθηκε ή έληξε), η γραμμή του το λέει, και τα αποθετήρια που κάλυπτε μένουν σε παύση μέχρι να το αντικαταστήσετε.

| Κεντρικός υπολογιστής | Token αυτοματοποίησης | Πού να το δημιουργήσετε |
| --- | --- | --- |
| **GitLab** | Ένα **token πρόσβασης έργου** ή **ομάδας** με `read_api` και `read_repository`· προσθέστε `api` και `write_repository` για σχόλια, merge requests και push | Το έργο ή η ομάδα → Ρυθμίσεις → Access tokens |
| **Bitbucket** | Ένα **token πρόσβασης αποθετηρίου**, **έργου** ή **χώρου εργασίας** με ανάγνωση αποθετηρίου, συν εγγραφή pull requests για σχόλια και pull requests (εγγραφή αποθετηρίου για push) | Το αποθετήριο, το έργο ή ο χώρος εργασίας → Ρυθμίσεις → Access tokens |

Το GitLab εμφανίζει τη δουλειά ως χρήστη-bot του token· το Bitbucket την εμφανίζει με το όνομα του token πρόσβασης.

### Bitbucket: token πρόσβασης ή API token

Το Bitbucket έχει δύο είδη token, και το Control Center τα κρατά χωριστά:

- Ένα **API token** (id.atlassian.com) ανήκει στον λογαριασμό σας Atlassian και χρησιμοποιείται μαζί με το email σας. Είναι **το δικό σας** διαπιστευτήριο και μπαίνει στη **Φιλοξενία κώδικα** στις **Ρυθμίσεις → Εσείς → Προφίλ**.
- Ένα **token πρόσβασης** (δημιουργείται στις ρυθμίσεις ενός αποθετηρίου, έργου ή χώρου εργασίας) ανήκει σε αυτό το αποθετήριο, έργο ή χώρο εργασίας, όχι σε πρόσωπο. Είναι ένα **token αυτοματοποίησης** και μπαίνει στα **Διακριτικά αυτοματοποίησης**.

Κάθε παράθυρο διαλόγου απορρίπτει το άλλο είδος και λέει πού ανήκει.

## Είστε διαφορετικό πρόσωπο σε κάθε κεντρικό υπολογιστή κώδικα

Ο ίδιος άνθρωπος είναι `octocat` στο GitHub και κάτι εντελώς διαφορετικό στο GitLab. Το Control Center επιλύει την ταυτότητά σας **ανά κεντρικό υπολογιστή κώδικα** και χρησιμοποιεί τη σωστή για κάθε αποθετήριο, και έτσι οι ενδείξεις «χρειάζεται τον έλεγχό μου», «δημιουργήθηκαν από εμένα» και «το εγκρίνατε» είναι σωστές σε έναν μικτό χώρο εργασίας.

Αν η ταυτότητα ενός κεντρικού υπολογιστή κώδικα δεν έχει επιλυθεί, τα αποθετήριά του δεν συνεισφέρουν τίποτα στα εισερχόμενα, αντί να ταιριάζουν με τα πάντα. Τα εισερχόμενα το δηλώνουν, αντί να ισχυρίζονται ότι είστε πλήρως ενημερωμένοι.

## Βλέπετε μόνο όσα βλέπει ο δικός σας λογαριασμός

Τα pull requests ενός αποθετηρίου φτάνουν σε εσάς μόνο όταν ο ρόλος σας στον χώρο εργασίας επιτρέπει το αποθετήριο **και ο δικός σας λογαριασμός σε αυτόν τον κεντρικό υπολογιστή κώδικα μπορεί να το διαβάσει**. Οι διαχειριστές και ο ιδιοκτήτης του χώρου εργασίας ακολουθούν τον ίδιο κανόνα. Όταν κάποια αποθετήρια είναι κρυφά, τα εισερχόμενα και η ουρά PR λένε πόσα και γιατί, χωρίς να τα κατονομάζουν:

- **Συνδεθείτε στο GitHub για να δείτε pull requests από 3 ακόμη αποθετήρια**: δεν έχετε συνδέσει ακόμη εδώ αυτόν τον κεντρικό υπολογιστή κώδικα. Συνδεθείτε και θα εμφανιστούν
- **3 αποθετήρια είναι κρυφά επειδή ο λογαριασμός σας στο GitHub δεν τα βλέπει**: ζητήστε από κάποιον με πρόσβαση στον κεντρικό υπολογιστή κώδικα
- **3 αποθετήρια είναι κρυφά επειδή δεν έχετε πρόσβαση σε αυτά σε αυτόν τον χώρο εργασίας**: ζητήστε πρόσβαση από διαχειριστή του χώρου εργασίας
- **Ελέγχεται η πρόσβασή σας σε 3 ακόμη αποθετήρια…**: εμφανίζεται για λίγο, όσο το Control Center επιβεβαιώνει τι μπορεί να διαβάσει ο λογαριασμός σας

Ο κώδικας ακολουθεί τον ίδιο κανόνα. Για να ανοίξετε τα αρχεία, τα diffs ή την αναζήτηση ενός αποθετηρίου, ή ένα τερματικό πάνω του, χρειάζεστε τη χορήγησή του σε αυτόν τον χώρο εργασίας και ο δικός σας λογαριασμός στον κεντρικό υπολογιστή κώδικα πρέπει να μπορεί να το διαβάσει· το ίδιο ισχύει και για τους διαχειριστές του χώρου εργασίας, μόνο ο κάτοχος του διακομιστή εξαιρείται. Όταν ο κεντρικός υπολογιστής κώδικα δεν μπορεί να προσεγγιστεί για τον έλεγχο, βλέπετε το «Δεν ήταν δυνατή η επιβεβαίωση της πρόσβασής σας στη φιλοξενία κώδικα. Δοκιμάστε ξανά.» (με το όνομα του κεντρικού υπολογιστή κώδικα). Δείτε [Ο κώδικας ακολουθεί τον κεντρικό υπολογιστή κώδικα](/el-GR/εγχειρίδιο/έννοιες/εξουσιοδότηση/#ο-κώδικας-ακολουθεί-τη-φιλοξενία-κώδικα).

Το ίδιο ισχύει για όλα όσα δημιουργούνται από αυτά τα pull requests. Ένας χώρος αξιολόγησης, τα μηνύματα και τα run των πρακτόρων του εξαφανίζονται όσο δεν μπορείτε να δείτε το pull request του, και ένας ανοιχτός χώρος αξιολόγησης κλείνει αν χάσετε την πρόσβαση. Τα run του pipeline για ένα κρυμμένο pull request εξαφανίζονται από τη λίστα run σας. Οι πράκτορες που δουλεύουν για εσάς δεν μπορούν επίσης να διαβάσουν αυτούς τους χώρους αξιολόγησης. Η λίστα αποθετηρίων του χώρου εργασίας δείχνει κάθε αποθετήριο στο οποίο έχετε πρόσβαση σε αυτόν τον χώρο εργασίας, ακόμη κι αν ο λογαριασμός σας στην πλατφόρμα δεν μπορεί ακόμη να το φτάσει.

Αν η πλατφόρμα περιορίζει τους ρυθμούς αιτημάτων ή είναι εκτός λειτουργίας, το Control Center συνεχίζει να εμφανίζει ό,τι επιβεβαίωσε τελευταία για λίγα λεπτά, και έπειτα κρύβει εκείνα τα pull requests μέχρι να μπορέσει να ελέγξει ξανά.

## Ένα εισερχόμενο για όλους τους κεντρικούς υπολογιστές κώδικα

Τα εισερχόμενα και η ουρά PR απλώνονται σε κάθε κεντρικό υπολογιστή κώδικα που εκπροσωπείται στον χώρο εργασίας και συγχωνεύουν τα αποτελέσματα σε μία ροή — ένα pull request από το GitHub και ένα από το Bitbucket βρίσκονται δίπλα-δίπλα, ταξινομημένα κατά χρόνο και όχι ομαδοποιημένα κατά προμηθευτή.

Οι αποτυχίες είναι απομονωμένες. Ένας κεντρικός υπολογιστής κώδικα που είναι εκτός λειτουργίας ή έχει φτάσει σε όριο ρυθμού αφήνει τους άλλους ανέπαφους, και τα αποθετήριά του διατηρούν την τελευταία γνωστή κατάστασή τους μέχρι να ανακάμψει· δεν αδειάζει ποτέ ολόκληρα τα εισερχόμενα. Ένα αποθετήριο που ο διακομιστής δεν μπορεί πλέον να προσεγγίσει εξαιρείται, αντί να εμφανίζει παλιά pull requests, και η **ειδοποίηση πρόσβασης στα αποθετήρια** το κατονομάζει μαζί με τη λύση: εγκατάσταση της GitHub App στον οργανισμό του, προσθήκη του αποθετηρίου στα αποθετήρια της App, επανέναρξη μιας εγκατάστασης σε παύση ή νέα σύνδεση του υπεύθυνου μέλους, ή προσθήκη token αυτοματοποίησης για αποθετήριο GitLab ή Bitbucket. Οι διαχειριστές έχουν ένα κουμπί για τα βήματα της GitHub App και για την προσθήκη του token.

## Τι μπορεί να κάνει κάθε κεντρικός υπολογιστής κώδικα

Κάθε κεντρικός υπολογιστής κώδικα υποστηρίζει τον βασικό κύκλο: προβολή και άνοιγμα pull requests, ανάγνωση diffs, σχολιασμό inline και σε επίπεδο κορυφής, έλεγχο, συγχώνευση και κλείσιμο. Πέρα από αυτά διαφέρουν πραγματικά, και το Control Center κρύβει ό,τι δεν μπορεί να κάνει ένας κεντρικός υπολογιστής κώδικα, αντί να εμφανίζει ένα χειριστήριο που αποτυγχάνει σιωπηλά.

| Δυνατότητα | GitHub | GitLab | Bitbucket |
| ---------- | :----: | :----: | :-------: |
| Ομαδοποιημένοι (εκκρεμείς) έλεγχοι |   ✓    |   ✓    |     —     |
| Αίτημα αλλαγών |   ✓    |   ✓    |     ✓     |
| Συγχρονισμένη κατάσταση «προβλήθηκε» ανά αρχείο |   ✓    |   —    |     —     |
| Αντιδράσεις emoji |   ✓    |   ✓    |     —     |
| Ελεγκτές ομάδας ή γκρουπ |   ✓    |   ✓    |     —     |
| Προτεινόμενοι ελεγκτές |   ✓    |   —    |     ✓     |
| Αποτελέσματα CI σε ένα PR |   ✓    |   ✓    |     ✓     |

Όπου λείπει μια δυνατότητα, η λειτουργία υποβαθμίζεται με ειλικρίνεια:

- Η **κατάσταση «προβλήθηκε»** εξακολουθεί να λειτουργεί, αλλά μόνο στη συσκευή όπου την ορίσατε.
- Οι **ομαδοποιημένοι έλεγχοι** στο Bitbucket αναρτώνται σχόλιο προς σχόλιο, οπότε οι ελεγκτές τα βλέπουν να φτάνουν μεμονωμένα και όχι όλα μαζί.
- Η **απουσία PR head ref** στο Bitbucket σημαίνει ότι το checkout ενός pull request ανακτά το branch προέλευσής του με το όνομά του, κάτι που αποτυγχάνει μόλις διαγραφεί αυτό το branch.

## Ορολογία

Το GitLab αποκαλεί το pull request **merge request**. Το Control Center λέει «pull request» σε όλο το δικό του μοντέλο και χρησιμοποιεί τον όρο του εκάστοτε κεντρικού υπολογιστή κώδικα όταν μιλάει για αυτόν.

## Αντιμετώπιση προβλημάτων

### Η λίστα PR είναι κενή και αναφέρει ότι ένας κεντρικός υπολογιστής κώδικα δεν είναι συνδεδεμένος

Δεν έχετε διαπιστευτήριο για αυτόν τον κεντρικό υπολογιστή κώδικα. Συνδεθείτε στο GitHub ή επικολλήστε ένα token GitLab ή Bitbucket στις **Ρυθμίσεις → Εσείς → Προφίλ → Φιλοξενία κώδικα**. Τα αποθετήρια των άλλων κεντρικών υπολογιστών κώδικα δεν επηρεάζονται.

### Σύνδεσα έναν κεντρικό υπολογιστή κώδικα, αλλά τα αποθετήριά του δεν δείχνουν ακόμη τίποτα

Ελέγξτε την κατάσταση της γραμμής και μετά τις ειδοποιήσεις πάνω από τη λίστα PR. Το «Συνδεθείτε στο … για να δείτε pull requests από … ακόμη αποθετήρια» σημαίνει ότι ο δικός σας λογαριασμός δεν είναι συνδεδεμένος για αυτά τα αποθετήρια· το «… κρυφά επειδή ο λογαριασμός σας στο … δεν τα βλέπει» σημαίνει ότι ο κεντρικός υπολογιστής κώδικα δεν σας δίνει πρόσβαση. Στο GitHub, η ειδοποίηση πρόσβασης στα αποθετήρια σάς λέει πότε η GitHub App δεν είναι εγκατεστημένη στον οργανισμό του αποθετηρίου ή δεν το περιλαμβάνει.

### Η εργασία στο παρασκήνιο σε αποθετήριο GitLab ή Bitbucket είναι σε παύση

Το αποθετήριο δεν έχει token αυτοματοποίησης που να μπορεί να το διαβάσει. Ένας διαχειριστής του χώρου εργασίας προσθέτει ένα για το αποθετήριο ή για ολόκληρο τον χώρο εργασίας· δείτε [Προσθήκη token αυτοματοποίησης](#προσθήκη-token-αυτοματοποίησης). Το δικό σας προσωπικό token δεν αίρει την παύση: η εργασία στο παρασκήνιο δεν χρησιμοποιεί ποτέ το token ενός μέλους.

### Ένα αποθετήριο δεν καταχωρίζεται

Η καταχώριση απαιτεί και τα τρία: η διαδρομή βρίσκεται μέσα σε ένα worktree του git, υπάρχει ένα remote `origin` και αυτό το remote δείχνει στο github.com, το gitlab.com ή το bitbucket.org. Το `origin` πρέπει επίσης να είναι το αποθετήριο που συνδέετε, και ένας φάκελος εκτός του αποθηκευτικού χώρου του χώρου εργασίας μπορεί να συνδεθεί μόνο από τον κάτοχο του διακομιστή. Δείτε [Προσθήκη αποθετηρίων σε χώρο εργασίας](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/προσθήκη-αποθετηρίων/).

### Έχω χορήγηση, αλλά το αποθετήριο λέει ότι ο λογαριασμός μου δεν μπορεί να το διαβάσει

Ο δικός σας λογαριασμός στον κεντρικό υπολογιστή κώδικα δεν μπορεί να διαβάσει αυτό το αποθετήριο, οπότε ο κώδικάς του παραμένει κλειστός για εσάς, ό,τι κι αν χορηγεί ο χώρος εργασίας. Συνδεθείτε στον κεντρικό υπολογιστή κώδικα στην ενότητα **Φιλοξενία κώδικα** παραπάνω, ή ζητήστε πρόσβαση στο αποθετήριο από τον κεντρικό υπολογιστή κώδικα.

### Δεν ήταν δυνατή η επιβεβαίωση της πρόσβασής σας στη φιλοξενία κώδικα

Ο κεντρικός υπολογιστής κώδικα δεν μπόρεσε να προσεγγιστεί για τον έλεγχο, οπότε το Control Center αρνήθηκε αντί να μαντέψει. Δοκιμάστε ξανά σε λίγο.

### Το _repo_ δείχνει πλέον σε διαφορετικό αποθετήριο

Το αποθετήριο πίσω από αυτή τη διαδρομή άλλαξε: διαγράφηκε και δημιουργήθηκε ξανά, ή μετακινήθηκε και αντικαταστάθηκε. Το Control Center δεν στέλνει σε αυτό τίποτα μέχρι ένας διαχειριστής του χώρου εργασίας να πατήσει **Επανασύνδεση** στην ειδοποίηση ή στη γραμμή του αποθετηρίου. Μια απλή μετονομασία ή μεταβίβαση ακολουθείται αυτόματα και δεν εμφανίζει ποτέ αυτό.

### Όλα σταματούν να λειτουργούν για λίγο μετά από εντατική χρήση

Αυτός είναι ο διακόπτης ασφαλείας του ορίου ρυθμού. Όταν ένας κεντρικός υπολογιστής κώδικα σηματοδοτεί το πρωτεύον όριό του, ο πελάτης αποτυγχάνει τοπικά τα επόμενα αιτήματα, χωρίς κλήση δικτύου, μέχρι να παρέλθει το παράθυρο — έτσι μια καταιγίδα επαναλήψεων δεν μπορεί να επιδεινώσει το όριο. Οι παροδικές αποτυχίες επαναλαμβάνονται με εκθετικό backoff.
