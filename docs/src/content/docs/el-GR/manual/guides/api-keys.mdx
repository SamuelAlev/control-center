Αυτός ο οδηγός δείχνει πού αποθηκεύεται κάθε διαπιστευτήριο που χρησιμοποιεί το
Control Center και πώς να το αλλάξετε.

**Τίποτα δεν αποθηκεύεται στο μηχάνημα στο οποίο πληκτρολογείτε.** Κάθε
διαπιστευτήριο ζει στον διακομιστή· ποιο απαντά σε ένα δεδομένο αίτημα εξαρτάται
από το αν υπάρχει άνθρωπος πίσω του.

| Διαπιστευτήριο                           | Αποθήκευση                                                    | Ποιος το χρησιμοποιεί                                                     |
| ---------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Το διαπιστευτήριό σας για τη φιλοξενία κώδικα και τα εισιτήρια | Το αρχείο μυστικών του διακομιστή με δικαιώματα 0600, με κλειδί το αναγνωριστικό χρήστη σας | Ό,τι ζητάτε εσείς: η επιφάνεια PR, οι εκτελέσεις των πρακτόρων σας, οι εικόνες σας |
| Η ταυτότητα εφαρμογής του διακομιστή     | Το ίδιο αρχείο, συν το `server_settings` για τα μη μυστικά     | Εργασία που δεν τη ζήτησε άνθρωπος: webhooks, polling PR, συγχρονισμός εισιτηρίων |
| Κλειδιά παρόχων μοντέλων και token OAuth | Η δική του αποθήκη διαπιστευτηρίων του διακομιστή             | Ο ενσωματωμένος προσαρμογέας, για κάθε χώρο εργασίας της εγκατάστασης     |
| Token bot του Slack                      | `<dataDir>/<workspaceId>/chat_credentials/` στον διακομιστή   | Η γέφυρα συνομιλίας για αυτόν τον χώρο εργασίας                           |
| Διαπιστευτήρια εξωτερικών CLI            | Ό,τι χρησιμοποιεί αυτό το CLI                                 | Claude Code, στον κεντρικό υπολογιστή του διακομιστή                      |

## Δύο διαπιστευτήρια GitHub, που απαντούν σε διαφορετικά ερωτήματα

- **Το δικό σας**, από τη σύνδεση (ροή συσκευής) ή την επικόλληση ενός token.
  Είναι αυτό που χρησιμοποιεί κάθε αίτημα που γίνεται *για λογαριασμό σας*, οπότε
  ένα σχόλιο που αναρτάται για εσάς φέρει το όνομά σας. Κανένα άλλο μέλος δεν
  μπορεί να το διαβάσει, και συνδέει το δικό του
- **Του διακομιστή**, από τη GitHub App που καταχώρισε ο χειριστής. Απαντά σε ό,τι
  δεν έχει καλούντα — έτσι η πρόσβαση στη φιλοξενία κώδικα δεν χάνεται όταν ένα
  άτομο φύγει ή αλλάξει ένα token

Το δικό σας ορίζεται στην κάρτα **Φιλοξενία κώδικα** στις **Ρυθμίσεις → Χώρος
εργασίας → Προφίλ και ταυτότητα**· του διακομιστή στην κάρτα **Εφαρμογές
παρόχων** στις **Ρυθμίσεις → Διακομιστής → Ενιαία σύνδεση**. Δείτε τη
[Ρύθμιση ενσωμάτωσης GitHub](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/ενσωμάτωση-github/)
και τη [Δημιουργία της GitHub App](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/github-app/).

:::note[Υπάρχει και μια οθόνη μόνο για URL]
Το `/workspaces/<workspaceId>/api-keys` εμφανίζει τις ίδιες δύο κάρτες με το
πρώτο βήμα της αρχικής διαμόρφωσης. Δεν έχει **καμία καταχώριση πλοήγησης
πουθενά στη διεπαφή**· είναι προσβάσιμο μόνο αν πληκτρολογήσετε το URL.
Χρησιμοποιήστε αντ' αυτού τις Ρυθμίσεις → Χώρος εργασίας → Προφίλ και ταυτότητα.
:::

## Ορισμός κλειδιών παρόχων μοντέλων

Ο ενσωματωμένος προσαρμογέας πιστοποιεί ο ίδιος τους παρόχους και αυτά τα
διαπιστευτήρια ζουν στον διακομιστή.

1. Μεταβείτε στις **Ρυθμίσεις → Διακομιστής → Πάροχοι μοντέλων**
2. Μετακινηθείτε στην ενότητα **Πάροχοι και μοντέλα**
3. Συνδέστε τον πάροχο — OAuth μέσω προγράμματος περιήγησης για OpenAI, Codex,
   Cursor και Kimi Code· κλειδί API για Anthropic και τους υπόλοιπους

Δείτε τη [Διαχείριση προσαρμογέων και μοντέλων](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/προσαρμογείς/)
για την πλήρη λίστα και για την προσθήκη προσαρμοσμένου endpoint.

Αυτά τα διαπιστευτήρια είναι **καθολικά στον κεντρικό υπολογιστή**: ένα κλειδί
εξυπηρετεί κάθε χώρο εργασίας της εγκατάστασης. Τα token OAuth ανανεώνονται πριν
λήξουν.

Τα εξωτερικά CLI προσαρμογέων κρατούν τα δικά τους διαπιστευτήρια, στη δική τους
διαμόρφωση, στον κεντρικό υπολογιστή του διακομιστή — το Control Center δεν τα
διαχειρίζεται. Πιστοποιήστε το Claude Code όπως λέει η δική του τεκμηρίωση, στο
μηχάνημα όπου εκτελείται το `cc_server`.

Ο διάλογος **Μεταβλητές περιβάλλοντος** κάθε προσαρμογέα μοιάζει με μέρος για να
βάλετε κλειδί για ένα από αυτά, αλλά δεν είναι: γράφει στη συσκευή σας, ενώ ο
διακομιστής διαβάζει το δικό του αντίγραφο και τίποτα δεν γεφυρώνει τα δύο. Δείτε
τη [Διαχείριση προσαρμογέων και μοντέλων](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/προσαρμογείς/).

## Σύνδεση παρόχου εισιτηρίων

Η κάρτα **Εισιτήρια** στις **Ρυθμίσεις → Χώρος εργασίας → Γενικά** περιέχει και
τα δύο σκέλη μιας απόφασης: σε ποιον πάροχο ζουν τα εισιτήριά σας και το
διαπιστευτήριο για αυτόν. Η επιλογή **Τοπικό** κρύβει τη γραμμή διαπιστευτηρίου —
τα τοπικά εισιτήρια ζουν στη βάση δεδομένων αυτού του διακομιστή και δεν έχουν
τίποτα να πιστοποιήσουν.

Το κλειδί σας αποθηκεύεται στον διακομιστή με βάση το αναγνωριστικό χρήστη σας,
όπως αυτό της φιλοξενίας κώδικα. Ο διακομιστής κρατά το δικό του κλειδί Linear
ξεχωριστά (**Εφαρμογές παρόχων**), και σε αυτό τρέχει ο συγχρονισμός εισιτηρίων
όταν δεν το ζήτησε άνθρωπος. Ένα κλειδί που λαμβάνει ένας πράκτορας εισάγεται
μόνο όταν ο πράκτορας διαθέτει τη δυνατότητα **Να επιτρέπονται κλήσεις API
εισιτηρίων**. Δείτε τη
[Ρύθμιση ενσωμάτωσης Linear](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/ενσωμάτωση-linear/).

## Αλλαγή ή ανάκληση

- **Το διαπιστευτήριό σας στο GitHub**: πατήστε **Αποσύνδεση** και μετά συνδεθείτε
  ξανά ή επικολλήστε το νέο token. Ανακαλέστε το παλιό στο GitHub
- **Η εφαρμογή του διακομιστή**: δημιουργήστε νέο ιδιωτικό κλειδί ή client secret
  στη σελίδα της εφαρμογής στο GitHub, επικολλήστε το στις **Εφαρμογές παρόχων**
  και πατήστε **Δοκιμή**
- **Ένας πάροχος μοντέλων**: στη γραμμή του, αποσυνδεθείτε (OAuth) ή αφαιρέστε το
  κλειδί και μετά συνδεθείτε ξανά
- **Το Slack**: επικολλήστε ξανά τα token στον διάλογο σύνδεσης. Δείτε τη
  [Ρύθμιση ενσωμάτωσης Slack](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/ενσωμάτωση-slack/)

## Αντιμετώπιση προβλημάτων

### Η λίστα PR είναι άδεια, αλλά το token μου δουλεύει στο `curl`

Ελέγξτε τον υπότιτλο της γραμμής **Φιλοξενία κώδικα**. Αν αναφέρει άλλη πηγή
(«μέσω της εφαρμογής αυτού του διακομιστή», «από το περιβάλλον»), το
διαπιστευτήριο που δοκιμάζετε δεν είναι αυτό που απαντά — το δικό σας δεν
αποθηκεύτηκε.

### Το token γίνεται δεκτό, αλλά μεταγενέστερα αιτήματα αποτυγχάνουν

Το token ελέγχεται όπως είναι αποθηκευμένο, οπότε η γραμμή ονομάζει τον
λογαριασμό πίσω του — αλλά μόνο τον λογαριασμό, όχι τα scopes. Ένα token με πολύ
λίγα scopes συνδέεται και μετά αποτυγχάνει σε μεμονωμένα αιτήματα. Ελέγξτε τα
scopes και τη λήξη:

```bash
curl -H "Authorization: token YOUR_TOKEN" https://api.github.com/user
```
