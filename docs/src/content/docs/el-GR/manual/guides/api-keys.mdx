Αυτός ο οδηγός δείχνει πού αποθηκεύεται κάθε διαπιστευτήριο που χρησιμοποιεί το
Control Center και πώς να το αλλάξετε.

**Τίποτα δεν αποθηκεύεται στο μηχάνημα στο οποίο πληκτρολογείτε.** Κάθε
διαπιστευτήριο ζει στον διακομιστή· ποιο απαντά σε ένα δεδομένο αίτημα εξαρτάται
από το αν υπάρχει άνθρωπος πίσω του.

| Διαπιστευτήριο                           | Αποθήκευση                                                    | Ποιος το χρησιμοποιεί                                                     |
| ---------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Η σύνδεσή σας για τη φιλοξενία κώδικα και τα εισιτήρια | Το αρχείο μυστικών του διακομιστή με δικαιώματα 0600, με κλειδί το αναγνωριστικό χρήστη σας | Ό,τι κάνετε εσείς: η επιφάνεια PR, οι ανασκοπήσεις, οι συγχωνεύσεις, οι ενέργειές σας στο Linear |
| Οι εφαρμογές παρόχων του διακομιστή      | Το ίδιο αρχείο, συν το `server_settings` για τα μη μυστικά     | Η σύνδεση των ανθρώπων και τα tokens για ένα αποθετήριο για πράκτορες, pipelines και polling |
| Το κλειδί εγκατάστασης του Connect       | Το ίδιο αρχείο (`connect_install_key`)                         | Η αναγνώριση αυτού του διακομιστή απέναντι στο Control Center Connect     |
| Κλειδιά παρόχων μοντέλων και token OAuth | Η δική του αποθήκη διαπιστευτηρίων του διακομιστή             | Ο ενσωματωμένος προσαρμογέας, για κάθε χώρο εργασίας της εγκατάστασης     |
| Διαπιστευτήρια bot του Slack             | `<dataDir>/<workspaceId>/chat_credentials/` στον διακομιστή   | Η γέφυρα συνομιλίας για αυτόν τον χώρο εργασίας: τα tokens της δικής σας εφαρμογής ή η σφραγισμένη εκχώρηση της κοινόχρηστης εφαρμογής |
| Διαπιστευτήρια εξωτερικών CLI            | Ό,τι χρησιμοποιεί αυτό το CLI                                 | Claude Code, στον κεντρικό υπολογιστή του διακομιστή                      |

## GitHub: η σύνδεσή σας και tokens για ένα αποθετήριο

- **Η δική σας**, από τη **Σύνδεση στο GitHub**. Είναι αυτή που χρησιμοποιεί κάθε
  αίτημα που γίνεται *για λογαριασμό σας*, οπότε μια ανασκόπηση που δημοσιεύεται
  για εσάς φέρει το όνομά σας. Κανένα άλλο μέλος δεν μπορεί να τη χρησιμοποιήσει,
  και συνδέεται μόνο του. Δεν υπάρχει token GitHub για επικόλληση
- **Η εργασία χωρίς κάποιον να πληκτρολογεί** (πράκτορες, pipelines, polling,
  απαντήσεις bot) παίρνει ένα token για ένα αποθετήριο κάθε φορά, που εκδίδεται
  από τη GitHub App του διακομιστή ή μέσω του Control Center Connect και
  περιορίζεται σε ό,τι μπορεί να κάνει εκεί ένα υπόλογο μέλος. Δεν είναι ποτέ η
  σύνδεσή σας παραδομένη ολόκληρη

Η δική σας ορίζεται στην κάρτα **Φιλοξενία κώδικα** στις **Ρυθμίσεις → Χώρος
εργασίας → Προφίλ και ταυτότητα**· η εφαρμογή του διακομιστή στην κάρτα
**Εφαρμογές παρόχων** στις **Ρυθμίσεις → Διακομιστής → Ενιαία σύνδεση**. Δείτε τη
[Ρύθμιση ενσωμάτωσης GitHub](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/ενσωμάτωση-github/)
και τη [Δημιουργία της GitHub App](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/github-app/).

Το GitLab και το Bitbucket εξακολουθούν να δέχονται επικολλημένο προσωπικό token,
που αποθηκεύεται με τον ίδιο τρόπο. Δείτε τη [Σύνδεση κεντρικού υπολογιστή κώδικα](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/σύνδεση-κεντρικού-υπολογιστή-κώδικα/).

:::note[Υπάρχει και μια οθόνη μόνο για URL]
Το `/workspaces/<workspaceId>/api-keys` εμφανίζει τις ίδιες δύο κάρτες με το
πρώτο βήμα της αρχικής διαμόρφωσης. Δεν έχει **καμία καταχώριση πλοήγησης
πουθενά στη διεπαφή**· είναι προσβάσιμο μόνο αν πληκτρολογήσετε το URL.
Χρησιμοποιήστε αντ' αυτού τις Ρυθμίσεις → Χώρος εργασίας → Προφίλ και ταυτότητα.
:::

## Ορισμός κλειδιών παρόχων μοντέλων

Ο ενσωματωμένος προσαρμογέας πιστοποιεί ο ίδιος τους παρόχους και αυτά τα
διαπιστευτήρια ζουν στον διακομιστή.

1. Μεταβείτε στις **Ρυθμίσεις → Διακομιστής → Πάροχοι μοντέλων**
2. Μετακινηθείτε στην ενότητα **Πάροχοι και μοντέλα**
3. Συνδέστε τον πάροχο — OAuth μέσω προγράμματος περιήγησης για OpenAI, Codex,
   Cursor και Kimi Code· κλειδί API για Anthropic και τους υπόλοιπους

Δείτε τη [Διαχείριση προσαρμογέων και μοντέλων](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/προσαρμογείς/)
για την πλήρη λίστα και για την προσθήκη προσαρμοσμένου endpoint.

Αυτά τα διαπιστευτήρια είναι **καθολικά στον κεντρικό υπολογιστή**: ένα κλειδί
εξυπηρετεί κάθε χώρο εργασίας της εγκατάστασης. Τα token OAuth ανανεώνονται πριν
λήξουν.

Τα εξωτερικά CLI προσαρμογέων κρατούν τα δικά τους διαπιστευτήρια, στη δική τους
διαμόρφωση, στον κεντρικό υπολογιστή του διακομιστή — το Control Center δεν τα
διαχειρίζεται. Πιστοποιήστε το Claude Code όπως λέει η δική του τεκμηρίωση, στο
μηχάνημα όπου εκτελείται το `cc_server`.

Ο διάλογος **Μεταβλητές περιβάλλοντος** κάθε προσαρμογέα μοιάζει με μέρος για να
βάλετε κλειδί για ένα από αυτά, αλλά δεν είναι: γράφει στη συσκευή σας, ενώ ο
διακομιστής διαβάζει το δικό του αντίγραφο και τίποτα δεν γεφυρώνει τα δύο. Δείτε
τη [Διαχείριση προσαρμογέων και μοντέλων](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/προσαρμογείς/).

## Σύνδεση παρόχου εισιτηρίων

Η κάρτα **Εισιτήρια** στις **Ρυθμίσεις → Χώρος εργασίας → Γενικά** περιέχει και
τα δύο σκέλη μιας απόφασης: σε ποιον πάροχο ζουν τα εισιτήριά σας και ποιος
είναι το Control Center όταν του μιλά. Η επιλογή **Τοπικό** κρύβει τις γραμμές
Linear — τα τοπικά εισιτήρια ζουν στη βάση δεδομένων αυτού του διακομιστή και δεν
έχουν τίποτα να πιστοποιήσουν.

Το Linear έχει δύο συνδέσεις και κανένα κλειδί για επικόλληση: το **Linear**
είναι η δική σας, για ό,τι κάνετε εσείς, και η **Αυτοματοποίηση Linear** είναι η
εφαρμογή Control Center του χώρου εργασίας, που τη συνδέει ένας διαχειριστής, για
τον συγχρονισμό εισιτηρίων, τα pipelines και τους πράκτορες. Ο διακομιστής μπορεί
επίσης να κρατά ένα **Κλειδί API υπηρεσίας** (**Εφαρμογές παρόχων**) για χώρους
εργασίας χωρίς συνδεδεμένη αυτοματοποίηση. Κανένα διαπιστευτήριο εισιτηρίων δεν
εγχέεται στο sandbox
ενός πράκτορα· οι πράκτορες γράφουν εισιτήρια μέσω των εργαλείων του Control
Center, που ρωτούν τον κανόνα **Εγγραφή σε εξωτερικό tracker**. Δείτε τη
[Ρύθμιση ενσωμάτωσης Linear](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/ενσωμάτωση-linear/).

## Αλλαγή ή ανάκληση

- **Η σύνδεσή σας στο GitHub**: πατήστε **Αποσύνδεση** και μετά ξανά **Σύνδεση
  στο GitHub**. Η αποσύνδεση ακυρώνει επίσης κάθε token που εξέδωσε ο διακομιστής
  για λογαριασμό σας
- **Ένα token GitLab ή Bitbucket**: πατήστε **Ενημέρωση token** και επικολλήστε
  το νέο, μετά ανακαλέστε το παλιό στον κεντρικό υπολογιστή κώδικα
- **Η εφαρμογή του διακομιστή**: δημιουργήστε νέο ιδιωτικό κλειδί ή client secret
  στη σελίδα της εφαρμογής στον πάροχο, επικολλήστε το στις **Εφαρμογές παρόχων**
  και πατήστε **Δοκιμή**
- **Το κλειδί εγκατάστασης του Connect**: **Εναλλαγή κλειδιού** στην κάρτα
  **Control Center Connect** ή `cc_server connect rotate-key --yes`. Όποιος
  συνδέθηκε μέσω Connect συνδέεται ξανά. Δείτε το [Control Center Connect](/el-GR/εγχειρίδιο/αναφορά/connect/)
- **Ένας πάροχος μοντέλων**: στη γραμμή του, αποσυνδεθείτε (OAuth) ή αφαιρέστε το
  κλειδί και μετά συνδεθείτε ξανά
- **Το Slack**: για τη δική σας εφαρμογή, επικολλήστε ξανά τα token στον διάλογο
  σύνδεσης. Η κοινόχρηστη εφαρμογή του Control Center δεν έχει token για εναλλαγή: το
  token του bot της ανανεώνεται μέσω του Connect, και η **Αποσύνδεση** το
  ανακαλεί και απεγκαθιστά το bot από το Slack. Δείτε τη
  [Ρύθμιση ενσωμάτωσης Slack](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/ενσωμάτωση-slack/)

## Αντιμετώπιση προβλημάτων

### Ένα token GitLab ή Bitbucket δουλεύει στο `curl`, αλλά όχι εδώ

Ελέγξτε τον υπότιτλο της γραμμής **Φιλοξενία κώδικα**. Αν αναγράφει «από το
περιβάλλον», το διαπιστευτήριο που απαντά είναι του διακομιστή, όχι το δικό σας —
το δικό σας δεν αποθηκεύτηκε.

### Ένα token GitLab ή Bitbucket γίνεται δεκτό, αλλά μεταγενέστερα αιτήματα αποτυγχάνουν

Το token ελέγχεται όπως είναι αποθηκευμένο, οπότε η γραμμή ονομάζει τον
λογαριασμό πίσω του — αλλά μόνο τον λογαριασμό, όχι τα scopes. Ένα token με πολύ
λίγα scopes συνδέεται και μετά αποτυγχάνει σε μεμονωμένα αιτήματα. Ελέγξτε τα
scopes και τη λήξη του στον κεντρικό υπολογιστή κώδικα.

### Ένας πάροχος λέει ότι η σύνδεση δεν έχει ρυθμιστεί σε αυτόν τον διακομιστή

Ο διακομιστής δεν έχει ούτε δική του εφαρμογή για αυτόν τον πάροχο ούτε Control
Center Connect. Ο ιδιοκτήτης του διακομιστή επιλέγει ένα από τα δύο στις
**Ρυθμίσεις → Διακομιστής → Ενιαία σύνδεση**.
