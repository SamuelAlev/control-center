Αυτός ο οδηγός δείχνει πώς να συνδέσετε έναν εξωτερικό πελάτη MCP — το
Claude Code, έναν επεξεργαστή, το MCP Inspector — στον δικό του διακομιστή
εργαλείων του Control Center.

Το Control Center καταχωρεί **110** εργαλεία και τα εξυπηρετεί μέσω του Model
Context Protocol, στην έκδοση πρωτοκόλλου `2024-11-05`. Ολόκληρες οικογένειες
εργαλείων που ίσως περιμένετε απουσιάζουν: δεν υπάρχουν εργαλεία συσκέψεων ή
ημερολογίου, ούτε εργαλεία έργων.

## Βρείτε το τελικό σημείο

Η επιφάνεια MCP μοιράζεται τον κύριο ακροατή του `cc_server`. Δεν υπάρχει
ξεχωριστή θύρα MCP.

| Τελικό σημείο | Μέθοδος  | Σκοπός                                                    |
| ------------- | -------- | --------------------------------------------------------- |
| `/mcp`        | `POST`   | Μεταφορά Streamable HTTP — αυτήν χρησιμοποιεί ο πελάτης    |
| `/mcp`        | `DELETE` | Τερματισμός συνεδρίας                                     |
| `/sse`        | `GET`    | Ροή ειδοποιήσεων από τον διακομιστή                        |

Έτσι, μια προεπιλεγμένη τοπική εγκατάσταση βρίσκεται στο
`http://127.0.0.1:9030/mcp`.

1. Μεταβείτε στις **Ρυθμίσεις → Διακομιστής → Διακομιστές MCP**
2. Δείτε την κάρτα **Διακομιστής MCP** — δείχνει αν εκτελείται ή έχει διακοπεί
   και τη θύρα στην οποία ακούει

Η επιφάνεια είναι ενεργοποιημένη από προεπιλογή σε μια νέα εγκατάσταση. Μόνο ο κάτοχος του διακομιστή βλέπει το token της κάρτας, και μόνο αυτός μπορεί να ξεκινήσει ή να σταματήσει το τελικό σημείο. Το **Έναρξη με την εκκίνηση της εφαρμογής** ελέγχει αν θα επανέλθει μετά από επανεκκίνηση· τα **Έναρξη** / **Διακοπή** είναι στοιχεία ελέγχου συνεδρίας που δεν αλλάζουν αυτή την προτίμηση.

Ο διακομιστής δεσμεύει το loopback από προεπιλογή, οπότε το τελικό σημείο είναι
προσβάσιμο μόνο από το μηχάνημα στο οποίο εκτελείται το `cc_server`, εκτός αν
τον ξεκινήσατε με `--bind any`.

## Πάρτε το token

Κάθε αίτημα χρειάζεται το token MCP του διακομιστή, από οποιοδήποτε μηχάνημα, και το loopback δεν εξαιρείται. Ο διακομιστής το δημιουργεί την πρώτη φορά που ξεκινά. Δεν μπορεί να απενεργοποιηθεί ούτε να καθαριστεί.

1. Στις **Ρυθμίσεις → Διακομιστής → Διακομιστές MCP**, βρείτε τη γραμμή **Token ελέγχου ταυτότητας**
2. Πατήστε **Εμφάνιση token** και αντιγράψτε το
3. Για να το αντικαταστήσετε, πατήστε **Ανανέωση token**. Ο διακομιστής μεταβαίνει αμέσως στο νέο token, και κάθε πελάτης που χρησιμοποιεί ακόμη το παλιό απορρίπτεται έως ότου του δώσετε το νέο

## Συνδέστε έναν πελάτη

Στρέψτε τον πελάτη σας στο τελικό σημείο Streamable HTTP και στείλτε το token ως `Authorization: Bearer <token>` σε κάθε αίτημα, και το `GET /sse` συμπεριλαμβάνεται. Δεν υπάρχει άλλος τρόπος αποστολής: ένα token στο URL δεν γίνεται δεκτό. Η ακριβής μορφή της διαμόρφωσης είναι θέμα του πελάτη σας.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Το Claude Code δεν θα το διαβάσει από ένα `.mcp.json` ενός έργου — βάζει τους
διακομιστές MCP που ορίζονται σε επίπεδο έργου πίσω από ένα αίτημα έγκρισης που
ένα μη διαδραστικό `claude -p` δεν απαντά ποτέ. Περάστε τη διαμόρφωση ρητά:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

Το `--strict-mcp-config` κάνει το Claude να χρησιμοποιεί μόνο αυτό το αρχείο,
ώστε ο ίδιος διακομιστής να μην εντοπίζεται και από το έργο και να μην
καταχωρίζεται δύο φορές.

Σημείο ελέγχου: ζητήστε από τον πελάτη να παραθέσει τα εργαλεία του. Θα πρέπει
να δείτε καταχωρήσεις `mcp__*` που καλύπτουν εισιτήρια, χώρους, μνήμη, γράφημα
κώδικα και έλεγχο.

## Τι απορρίπτει το τελικό σημείο

Το token ανοίγει κάθε εργαλείο του διακομιστή, γι' αυτό το τελικό σημείο απορρίπτει επίσης ό,τι θα μπορούσε να έχει στείλει μια ιστοσελίδα, πριν ελέγξει καν το token:

| Αίτημα | Απάντηση |
| --- | --- |
| Κεφαλίδα `Origin` που δεν είναι σελίδα αυτού του υπολογιστή (`http://localhost`, `http://127.0.0.1` ή `http://[::1]`, οποιαδήποτε θύρα) | `403`, "Cross-origin requests are not accepted" |
| Κεφαλίδα `Host` που δεν είναι ούτε η διεύθυνση loopback και η θύρα αυτού του ακροατή ούτε το δημόσιο όνομα κεντρικού υπολογιστή του διακομιστή | `403`, "Unknown host" |
| Ένα `POST` του οποίου το σώμα δεν είναι `application/json` | `415` |
| Χωρίς token, ή με λάθος token | `401` |

Για να παρέχετε MCP πέρα από τον τοπικό υπολογιστή, ξεκινήστε τον διακομιστή με `--bind any` και στείλτε το token από το άλλο μηχάνημα, διευθυνσιοδοτώντας τον διακομιστή με το δημόσιο όνομα κεντρικού υπολογιστή του.

## Περιορίστε κάθε κλήση σε έναν χώρο εργασίας

Κάθε εργαλείο που αγγίζει δεδομένα εμβέλειας χώρου εργασίας απαιτεί
`workspace_id` και μια κλήση χωρίς αυτό απορρίπτεται αντί να επιλυθεί με βάση
κάποιο «τρέχοντα» χώρο εργασίας:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

Το id είναι αυτό που εμφανίζεται στο URL του προγράμματος περιήγησης ή της
εφαρμογής: `/workspaces/<workspace_id>/…`. Οι μόνες εξαιρέσεις είναι εργαλεία
που εκτείνονται πραγματικά σε πολλούς χώρους εργασίας, όπως το `list_workspaces`
και τα εργαλεία της ροής ειδήσεων — η ροή ειδήσεων είναι ανά χρήστη και ένας
πράκτορας δεν έχει δικό του χρήστη, οπότε αυτά τα εργαλεία λειτουργούν στις ροές
του ιδιοκτήτη του διακομιστή.

Τα εργαλεία με εμβέλεια αποθετηρίου ελέγχουν επιπλέον ότι το αποθετήριο είναι
συνδεδεμένο με αυτόν τον χώρο εργασίας.

## Μάθετε τι θα απορρίψει η επιφάνεια

- **Περιορισμός ανά λειτουργία.** Μια κλήση επιλύεται ως προς τη λειτουργία του
  χώρου του πράκτορα που καλεί, στην πλευρά του διακομιστή. Ένας πράκτορας σε
  λειτουργία μόνο για ανάγνωση δεν μπορεί να φτάσει σε εργαλείο εγγραφής
  παραλείποντας το `space_id` — η λειτουργία αναζητείται αντ’ αυτού από την
  ενεργή εκτέλεσή του.
- **Περιορισμοί ενεργειών.** Τα εργαλεία που μεταβάλλουν κατάσταση δηλώνουν τις
  κατηγορίες επιδράσεών τους και περνούν από την ίδια πολιτική που χρησιμοποιεί
  το υπόλοιπο προϊόν. Δείτε
  [Ρύθμιση περιορισμών](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/ρύθμιση-περιορισμών/).
- **Επιβεβαίωση.** Κάποια καταστρεπτικά εργαλεία συγκροτούν μια δομή
  επιβεβαίωσης που πρέπει να εγκριθεί πριν προχωρήσει η κλήση.

Ο πλήρης κατάλογος ανακοινώνεται στο `tools/list` χωρίς φραγή ανακάλυψης — ένας
εξωτερικός πελάτης MCP αρνείται να καλέσει εργαλείο που δεν βρίσκεται στην
προσωρινά αποθηκευμένη λίστα του, οπότε η απόκρυψη εργαλείων τα χαλάει αντί να
τα τακτοποιεί.

## Τα προσωπικά διακομιστές MCP μένουν του κατόχου

Αυτός ο οδηγός αφορά το δικό του τελικό σημείο του Control Center. Η άλλη κατεύθυνση, οι διακομιστές MCP που το Control Center παραδίδει στους πράκτορες που εκτελεί, βρίσκεται στις **Ρυθμίσεις → Διακομιστής → Διακομιστές MCP → Εξωτερικοί διακομιστές MCP**. Οι διακομιστές που έχουν ρυθμιστεί στον υπολογιστή του διακομιστή για τα Claude, Codex, Cursor, Gemini, VS Code, Windsurf, OpenCode ή σε ένα `.mcp.json` βρίσκονται εκεί αυτόματα.

Αυτοί οι ανιχνευμένοι διακομιστές προέρχονται από τη ρύθμιση εργαλείων του χρήστη του διακομιστή και ενεργούν με την ταυτότητα και τα διαπιστευτήρια αυτού του χρήστη, οπότε ανήκουν στον κάτοχο του διακομιστή:

- Είναι διαθέσιμοι μόνο μέσα σε εκτελέσεις του ενσωματωμένου harness που ξεκινά ο κάτοχος του διακομιστή ή για τις οποίες ευθύνεται, συμπεριλαμβανομένης της αυτοματοποίησης σε χώρο εργασίας για τον οποίο ευθύνεται ο κάτοχος.
- Η εκτέλεση ενός μέλους, η αυτοματοποίηση δεμένη σε μέλος, και κάθε εκτέλεση σε διακομιστή χωρίς καταγεγραμμένο κάτοχο δεν λαμβάνουν κανέναν από αυτούς. Εκεί τα εργαλεία δεν εμφανίζονται, δεν μπορούν να κληθούν και δεν εμφανίζονται στην αναζήτηση εργαλείων.
- Αυτό το τελικό σημείο δεν τους απαριθμεί, δεν τους καλεί και δεν τους αναζητά, για κανέναν, ούτε καν για το token του κατόχου, και δεν μεταβιβάζει τους πόρους ή τις προτροπές τους. Έτσι, ένας πράκτορας CLI που φτάνει στο Control Center μέσω MCP, όπως το Claude Code, δεν τους λαμβάνει ούτε μέσω του Control Center· χρησιμοποιεί τη δική του ρύθμιση.

Οι διακομιστές MCP που έχουν ρυθμιστεί για τον χώρο εργασίας δεν επηρεάζονται από τίποτα από αυτά.

## Αντιμετώπιση προβλημάτων

### Ο πελάτης δεν βλέπει εργαλεία

- Ελέγξτε ότι η κάρτα **Διακομιστής MCP** δείχνει ότι εκτελείται
- Ελέγξτε ότι η θύρα ταιριάζει με τη θύρα του `cc_server` σας
- Στο Claude Code, ελέγξτε ότι περάσατε τα `--mcp-config` και
  `--strict-mcp-config`

### 401 Μη εξουσιοδοτημένο

Το αίτημα δεν είχε token, ή είχε παλιό. Αντιγράψτε το τρέχον token από τη γραμμή **Token ελέγχου ταυτότητας** και στείλτε το ως `Authorization: Bearer <token>`. Ένα token στο URL αγνοείται.

### 403 από πελάτη που δούλευε πριν

Το αίτημα είχε `Origin` από ιστοσελίδα ή `Host` στο οποίο ο διακομιστής δεν ανταποκρίνεται. Καλέστε το τελικό σημείο από πελάτη και όχι από σελίδα προγράμματος περιήγησης, με τη διεύθυνση loopback του διακομιστή ή το δημόσιο όνομα κεντρικού υπολογιστή του.

### 415 Μη υποστηριζόμενος τύπος περιεχομένου

Στείλτε τα σώματα `POST /mcp` ως `application/json`.

### Μια κλήση εργαλείου αποτυγχάνει με «Missing or invalid argument: workspace_id»

Προσθέστε το `workspace_id`. Δεν υπάρχει σιωπηρός χώρος εργασίας.

### Μια κλήση εργαλείου απορρίπτεται ως άγνωστη

Τα [Εργαλεία MCP](/el-GR/εγχειρίδιο/αναφορά/εργαλεία-mcp/) παραθέτουν τον
κατάλογο. Καλέστε το όνομα ακριβώς όπως εμφανίζεται εκεί.
