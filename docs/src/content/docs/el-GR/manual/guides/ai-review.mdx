Αυτός ο οδηγός δείχνει πώς να βάλετε πράκτορες ελέγχου να ελέγξουν ένα pull
request και πώς να δημοσιεύσετε το αποτέλεσμα στο GitHub.

## Ξεκινήστε έναν έλεγχο με AI

1. Ανοίξτε το PR και μεταβείτε στην καρτέλα **Επισκόπηση**
2. Ανοίξτε το μενού υπερχείλισης ⋯ στη γραμμή ενεργειών και επιλέξτε **Ερώτηση AI**

Το στοιχείο εμφανίζεται μόνο όσο το PR είναι ανοιχτό — είναι ενέργεια πριν από τη
συγχώνευση. Το ίδιο κουμπί προσφέρεται ως **Ερώτηση AI** στην κενή κατάσταση της
καρτέλας **Ανασκόπηση**, πριν υπάρξει οποιαδήποτε ανασκόπηση.

Το Control Center ξεκινά το ενσωματωμένο pipeline `pr_review` και ανοίγει την
καρτέλα **Ανασκόπηση** του PR, ώστε να το παρακολουθήσετε. Το pipeline:

1. Ανοίγει τον δικό του χώρο ελέγχου του PR, του οποίου το απομονωμένο worktree
   έχει το PR σε checkout στο head του
2. Αποστέλλει παράλληλα τους ελεγκτές για το επίπεδο ανασκόπησης του χώρου
   εργασίας — τρεις από προεπιλογή (τους ενσωματωμένους πράκτορες **qa**,
   **architect** και **engineer**, παράλληλα). Δεν γίνεται ανίχνευση γλώσσας ή
   τομέα
3. Βάζει τον επικεφαλής (CEO) πράκτορα να ενοποιήσει τα ευρήματά τους σε μια
   καθοδηγούμενη περιήγηση
4. Οριστικοποιεί: ταξινομεί τα ευρήματα σε κάδους συναίνεσης και υπολογίζει την
   ετυμηγορία. Όταν η συσχέτιση φτάσει σε `awaiting approval`, η **Δημοσίευση στο
   GitHub** εμφανίζεται στην καρτέλα Ανασκόπηση

Το πόσο βαθύς είναι ο έλεγχος εξαρτάται από το **επίπεδο ανασκόπησης** του χώρου
εργασίας — `light` (ένας ελεγκτής), `balanced` (τρεις, η προεπιλογή) ή `thorough`
(και οι πέντε, με τους ειδικούς ασφάλειας και απόδοσης) — που ορίζεται στις
**Ρυθμίσεις → Χώρος εργασίας → Γενικά**, στην κάρτα **Πολιτική χώρου εργασίας**.
Ένα ελαφρύτερο επίπεδο καταχωρίζει ακριβώς τα ίδια ευρήματα· απλώς αναφέρει
λιγότερα από αυτά στο προσκήνιο.

Όλοι οι ελεγκτές αναρτούν στον μοναδικό χώρο ελέγχου του PR, κι αυτό είναι που
κάνει τα ευρήματά τους συγκρίσιμα. Δείτε
[Έλεγχος με AI](/el-GR/εγχειρίδιο/έννοιες/έλεγχος-με-ai/) για το πώς δένουν τα
κομμάτια.

Το `pr_review` παρέχεται μόνο με χειροκίνητο ενεργοποιητή. Για να εκτελείται σε
κάθε δημοσιευμένο PR, προσθέστε τον δικό σας ενεργοποιητή — δείτε
[Αποστολή πρακτόρων ελέγχου](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/αποστολή-πρακτόρων-ελέγχου/). Μπορείτε επίσης
να ξεκινήσετε έναν από το ίδιο το GitHub, χωρίς ενεργοποιητή pipeline: αναφέρετε
το bot του διακομιστή στο PR ή προσθέστε την ετικέτα `ai-review` — δείτε
[Συνομιλία με το Control Center από GitHub PR](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/συνομιλίες-github-pr/).

Αν ένα αναδυόμενο μήνυμα λέει ότι εκτελείται ήδη ανασκόπηση για αυτό το pull
request, τότε υπάρχει ήδη μία σε εξέλιξη· μείνετε στην καρτέλα **Ανασκόπηση** ή
ανοίξτε το **Pipelines** για να τη βρείτε.

## Διαβάστε τα ευρήματα

Οι ελεγκτές καταχωρίζουν τα ευρήματα ως **κόμβους ελέγχου** στον χώρο ελέγχου.
Κάθε κόμβος φέρει:

| Πεδίο          | Περιγραφή                                                   |
| -------------- | ----------------------------------------------------------- |
| Είδος           | `bug`, `suggestion`, `recommendation`, `question` ή `ticket` |
| Προτεραιότητα   | P0 (κρίσιμο) → P3 (μικροπαρατήρηση)                          |
| Κατηγορία       | `security`, `stability`, `data_integrity`, `correctness`, `performance` ή `maintainability` |
| Αρχείο και γραμμή | Πού είναι αγκυρωμένο το εύρημα                             |
| Αρχικός κώδικας | Ο κώδικας στον οποίο αφορά το εύρημα                         |
| Προτεινόμενος κώδικας | Η προτεινόμενη διόρθωση                               |
| Βεβαιότητα      | Πόσο βέβαιος είναι ο ελεγκτής                               |
| Κατάσταση       | `open` → `consensus-ready` → `resolved` ή `dismissed`        |

Ένα εύρημα φτάνει στο **consensus-ready** μόνο όταν το επιβεβαιώσει ένας
_ομότιμος_ ελεγκτής. Ένας πράκτορας δεν μπορεί να επιβεβαιώσει το δικό του
εύρημα, οπότε η γνώμη ενός μόνο ελεγκτή δεν προάγεται ποτέ από μόνη της.

Η καρτέλα **Ανασκόπηση** εμφανίζει τη λίστα ευρημάτων, με φίλτρα κατά είδος και
κατάσταση και με διακόπτη για τα απορριφθέντα ευρήματα, δίπλα στο τεχνούργημα που
δημοσίευσε ο πράκτορας ενοποίησης. Η ντετερμινιστική προβολή — κοόρτες, το ταμπλό
πολλαπλών αξόνων, τα diffs συμβολαίου και τα οπτικά diffs — υπολογίζεται στην
πλευρά του διακομιστή αλλά δεν έχει επιφάνεια στην εφαρμογή· δείτε
[Υπολογισμός ελέγχου](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/υπολογισμός-ελέγχου/) για το τι παράγει το πέρασμα.

## Ελέγξτε το πάνελ διαφωνιών

Όταν δύο ελεγκτές αγκυρώνουν ευρήματα στο ίδιο αρχείο και την ίδια γραμμή αλλά τα
αξιολογούν πολύ διαφορετικά — προτεραιότητες που απέχουν δύο ή περισσότερα
επίπεδα, ή ο ένας να το χαρακτηρίζει `bug` ενώ ο άλλος `suggestion` — ένα πάνελ
διαφωνιών εμφανίζεται πάνω από τη λίστα ευρημάτων. Διαβάστε τα πρώτα: εκεί
αποκλίνουν οι γνώμες των ελεγκτών και εκεί αξίζει περισσότερο η κρίση σας.

## Διαβάστε την ετυμηγορία

Όταν ο επικεφαλής πράκτορας οριστικοποιεί, υπολογίζει μια **ετυμηγορία**:

| Ετυμηγορία | Σημασία                                      |
| ---------- | -------------------------------------------- |
| **Ship**   | Δεν βρέθηκε κάτι που να εμποδίζει            |
| **Hold**   | Ζητήματα που πρέπει να αντιμετωπιστούν πριν τη συγχώνευση |
| **Block**  | Κρίσιμα ζητήματα που πρέπει να διορθωθούν    |

Η ετυμηγορία φέρει μια συνολική βαθμολογία βεβαιότητας και καταμέτρηση των
ευρημάτων ανά προτεραιότητα.

Έπειτα, οι άξονες ελέγχου ενσωματώνονται σε αυτήν και μπορούν μόνο να την κάνουν
**πιο** αυστηρή. Ένας άξονας με πύλη που αποτυγχάνει επιβάλλει **Block**· ένας
άξονας με πύλη που δεν μπόρεσε να ολοκληρωθεί (`partial`) ή που δεν μπόρεσε
καθόλου να εκτελεστεί (`unavailable`) επιβάλλει τουλάχιστον **Hold**. Η απουσία
τεκμηρίων δεν ανοίγει ποτέ μια πύλη.

## Δημοσιεύστε την ανασκόπηση στο GitHub

Η δημοσίευση είναι ένα ξεχωριστό βήμα, σκόπιμα υπό τον έλεγχο του χρήστη. Το
pipeline `pr_review` κρατά την ανασκόπηση στο Control Center· δεν αναρτά στο
GitHub.

1. Στην καρτέλα **Ανασκόπηση**, περιμένετε ώσπου να εμφανιστεί η **Δημοσίευση στο GitHub**
2. Πατήστε **Δημοσίευση στο GitHub**

Το Control Center στέλνει **μία** ανασκόπηση στο GitHub. Τα ευρήματα που έχουν
ήδη επιλυθεί ή απορριφθεί παραλείπονται. Το κουμπί περιλαμβάνει κάθε εναπομείναν
ανοιχτό εύρημα και, σε **Ship**, υποβάλλει `APPROVE`. (Το εργαλείο MCP
`publish_review_to_github` εξακολουθεί να έχει ως προεπιλογή μόνο τα ευρήματα που
έχουν επιβεβαιωθεί από ομότιμους και δεν εγκρίνει εκτός αν περάσετε
`approve_on_ship`.) Όσα φέρουν άγκυρα αρχείου και γραμμής γίνονται ενσωματωμένα
σχόλια· όλα τα υπόλοιπα διπλώνονται στο σώμα της σύνοψης, καθένα με υποσέλιδο
«— Control Center AI review», ώστε η προέλευση να είναι σαφής. Μια ετυμηγορία
**Block** υποβάλλεται ως `REQUEST_CHANGES`· η **Hold** ως `COMMENT`· η **Ship** ως
`APPROVE` από αυτό το κουμπί. Ένα αναδυόμενο μήνυμα τότε εμφανίζει
**Δημοσιεύτηκε**. Η ανασκόπηση δημοσιεύεται με την ταυτότητα εφαρμογής του
διακομιστή.

Αν το GitHub απορρίψει μια ενσωματωμένη άγκυρα επειδή η γραμμή δεν είναι μέρος του
diff, ολόκληρη η ανασκόπηση αποστέλλεται ξανά με κάθε εύρημα διπλωμένο στο σώμα,
ώστε να μη χαθεί τίποτα σιωπηρά.

:::caution[Η δημοσίευση φιλτράρεται από τους περιορισμούς]
Το `pr_review.publishReview` δηλώνει την κλάση ενέργειας `prPublish` και περνά από
το σημείο ελέγχου των περιορισμών. Αν η τελική απόφαση είναι `prompt` και δεν
είναι συνδεδεμένος κανένας εγκριτής, η δημοσίευση απορρίπτεται — οι περιορισμοί
αποτυγχάνουν κλειστά. Ορίστε έναν ρητό κανόνα στις Ρυθμίσεις → Χώρος εργασίας →
Δικαιώματα πρακτόρων αν θέλετε να εκτελείται χωρίς επίβλεψη.
:::

Άλλα ενσωματωμένα pipeline αναρτούν απευθείας στο GitHub: τα `cross_review`,
`pr_triage`, `ticket_to_pr` και `pre_merge_gate` καταλήγουν το καθένα σε ένα βήμα
σχολίου. Μόνο το `pr_review` κρατά την έξοδό του πίσω για εσάς.

## Αποστείλετε τους ελεγκτές μόνοι σας

Για έλεγχο του ποιοι ρόλοι θα ελέγξουν το PR και ποια αρχεία κοιτάζει ο καθένας,
χρησιμοποιήστε το εργαλείο MCP `dispatch_reviewers` μέσα σε έναν υπάρχοντα χώρο
ελέγχου ή προσθέστε κόμβους ελεγκτών σε ένα pipeline. Και οι δύο διαδρομές, με την
ακριβή υπογραφή του εργαλείου, βρίσκονται στην
[Αποστολή πρακτόρων ελέγχου](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/αποστολή-πρακτόρων-ελέγχου/).
