Ένα pull request είναι ήδη το μέρος όπου συμβαίνει η συζήτηση για τον κώδικα.
Οι συνομιλίες PR το κάνουν επιφάνεια ενός χώρου εργασίας του Control Center,
με τον ίδιο τρόπο που μια
[γέφυρα συνομιλίας](/el-GR/εγχειρίδιο/έννοιες/γέφυρες-συνομιλίας/) κάνει το Slack μία: κάντε
@-αναφορά στο `@usectrl` σε ένα
PR, απαντήστε μέσα στα νήματα ελέγχου του ή προσθέστε την ετικέτα `ai-review`,
και η εργασία γίνεται στον χώρο ελέγχου του PR — με την ίδια απόδοση και τους
ίδιους περιορισμούς όπως οτιδήποτε πληκτρολογείται στην εφαρμογή. Ένα σχόλιο και
μια ετικέτα περνούν από την ίδια πύλη: βάσει του μέλους που τα έγραψε ή τα
πρόσθεσε. Οι απαντήσεις επιστρέφουν στο GitHub, στο νήμα όπου τέθηκε η ερώτηση.

Τρεις αποφάσεις διαμορφώνουν τη λειτουργία και καθεμία είναι η ίδια απόφαση που
πήρε η γέφυρα συνομιλίας για τη συνομιλία, διατυπωμένη ξανά για έναν κεντρικό
υπολογιστή κώδικα: **προς ποια κατεύθυνση τρέχει η σύνδεση**, **τι εξουσιοδοτεί
ένα σχόλιο που φτάνει από έξω** και **σε ποιον αποδίδεται κάθε πλευρά**.

## Ο περιοδικός έλεγχος είναι το μέσο μεταφοράς

Το μόνο κανάλι push του GitHub για μια εφαρμογή είναι το webhook, και ένα
webhook χρειάζεται ένα URL εισόδου — το μόνο πράγμα που αυτή η επιφάνεια
σκόπιμα δεν απαιτεί ποτέ. Έτσι, η ανακάλυψη γίνεται με σάρωση: μία αναζήτηση
με ψευδώνυμο ανά εγκατάσταση εφαρμογής ζητά από το GitHub PR που αναφέρουν το
`@usectrl` και ανοιχτά PR που φέρουν την ετικέτα ελέγχου, για
τα PR που έχουν ήδη χώρο ελέγχου διαβάζονται τα νήματα σχολίων τους, και τα πάντα
συγκρίνονται με βάση το αναγνωριστικό σχολίου με ό,τι είχε εμφανιστεί στην
προηγούμενη σάρωση. Μια δική σας εφαρμογή σαρώνει κάθε λεπτό το πολύ 25 PR. Μέσω
του Connect οι κλήσεις χρησιμοποιούν το δικό όριο GitHub των μελών, οπότε η
σάρωση εκτελείται κάθε δύο λεπτά το πολύ σε 10 PR, και ένας χώρος εργασίας κάτω
από το 15 % του ορίου του παραλείπεται μέχρι να ανακάμψει. Το ίδιο το Connect δεν
βλέπει ποτέ το περιεχόμενο των PR.

Οι συνέπειες του σχεδιασμού αξίζει να ονομαστούν:

- **Η καθυστέρηση είναι διάστημα σάρωσης, όχι γεγονός.** Η επιβεβαίωση με 👀
  φτάνει μέσα σε μία σάρωση. Τίποτα επείγον δεν εξαρτάται από αυτό.
- **Ακριβώς μία φορά, ανά σχόλιο.** Τα αναγνωριστικά σχολίων είναι μοναδικά σε
  όλο το GitHub· καθένα καταγράφεται τη στιγμή που χαρακτηρίζεται κατάλληλο,
  πριν ενεργήσει κάτι πάνω του. Μια κατάρρευση μπορεί να χάσει τον χειρισμό
  ενός σχολίου, ποτέ να τον ενεργοποιήσει δύο φορές.
- **Ο χρόνος εκτός λειτουργίας καλύπτεται, δεν αναπαράγεται.** Το σύνολο όσων
  έχουν εμφανιστεί αποθηκεύεται, ώστε μια επανεκκίνηση να παραδίδει ό,τι έφτασε
  όσο ήταν εκτός λειτουργίας. Η μόνη εξαίρεση είναι η πρώτη σάρωση που έγινε
  ποτέ: χωρίς μνήμη για σύγκριση, ό,τι εκκρεμεί καταγράφεται σιωπηλά — ένας
  χειριστής που είχε βάλει ετικέτα σε είκοσι PR πριν υπάρξει αυτός ο διακομιστής
  δεν πρέπει να επιστρέψει σε είκοσι ελέγχους σε εξέλιξη.
- **Η ετικέτα είναι σύνολο, όχι γεγονός.** Η αναζήτηση αναφέρει την _παρουσία_
  της ετικέτας, οπότε ένα PR με ετικέτα ενεργοποιείται μία φορά, για πάντα. Η
  εκ νέου προσθήκη μιας ετικέτας αφού αφαιρεθεί είναι αόρατη στη σάρωση· η
  @-αναφορά είναι η διαδρομή επανεκτέλεσης.

Η αναζήτηση εκτελείται μία φορά ανά λογαριασμό εγκατάστασης, στον πελάτη του
ίδιου του κατόχου, γιατί ένα token βλέπει μόνο τα αποθετήρια της
δικής του εγκατάστασης — ένα μεμονωμένο διαπιστευτήριο για όλο τον διακομιστή
θα έχανε σιωπηλά κάθε PR στις άλλες εγκαταστάσεις της εφαρμογής.

## Η ιδιότητα μέλους εξουσιοδοτεί, όχι το σχόλιο

Ένα σχόλιο σε PR φτάνει κουβαλώντας έναν συντάκτη — μια μη επαληθευμένη
εξωτερική ταυτότητα μέχρι αποδείξεως του αντιθέτου. Ο διακομιστής αντιστοιχίζει
το αμετάβλητο αριθμητικό αναγνωριστικό λογαριασμού GitHub του συντάκτη (ποτέ το
όνομα σύνδεσης, που μπορεί να μετονομαστεί και να επαναχρησιμοποιηθεί) με τις
συνδέσεις στο GitHub των μελών του χώρου εργασίας, που ξαναχτίζονται με TTL,
γιατί άνθρωποι συνδέονται και προσκαλούνται όσο ο διακομιστής εκτελείται. Για την
ετικέτα `ai-review`, το πρόσωπο που αντιστοιχίζεται είναι όποιος την πρόσθεσε
πιο πρόσφατα.

Τρεις έλεγχοι, με τη σειρά, και η αποτυχία σε οποιονδήποτε από αυτούς είναι
σιωπηλή — δεν αναρτάται τίποτα:

- **Ένα συνδεδεμένο μέλος.** Ο λογαριασμός πρέπει να ανήκει σε μέλος _αυτού_ του
  χώρου εργασίας που έχει συνδεθεί στο GitHub σε αυτόν τον διακομιστή
- **Ένας ρόλος εγγραφής.** Οι `viewer` και `guest` δεν μπορούν να ξεκινήσουν
  εργασία
- **Πρόσβαση push.** Οι απαντήσεις χρησιμοποιούν ένα token για ένα μόνο
  αποθετήριο, περιορισμένο στην πρόσβαση αυτού του μέλους σε αυτό. Αν ο
  διακομιστής δεν μπορεί να εκδώσει ένα, δεν προχωρά

Κάθε έλεγχος εκτελείται πριν από οποιαδήποτε επιβεβαίωση, οπότε ένας άγνωστος
δεν παίρνει ούτε αντίδραση ούτε απάντηση. Ένα σχόλιο δεν αποδίδεται ποτέ σε
κάποιον που δεν το έστειλε, και τα λόγια ενός αγνώστου δεν μπαίνουν ποτέ σε έναν
χώρο εργασίας που δεν μπορεί να δει.

### Η διεκδίκηση

Το τελευταίο βήμα πριν από οποιαδήποτε εργασία είναι μια αντίδραση 👀, που
προστίθεται με τη δική σύνδεση του συντάκτη στο GitHub. Το GitHub απαντά `201`
για νέα αντίδραση και `200` για μία που υπάρχει ήδη, οπότε η αντίδραση λειτουργεί
και ως κλείδωμα: όταν το ίδιο πρόσωπο είναι συνδεδεμένο σε δύο διακομιστές που
συνδέουν και οι δύο το αποθετήριο, μόνο ο πρώτος που αντιδρά κάνει την εργασία.
Ένα σχόλιο που βλέπουν πολλοί χώροι εργασίας σε έναν διακομιστή προσφέρεται σε
καθέναν, και αποφασίζει η ίδια διεκδίκηση.

## Δύο ταυτότητες, σκόπιμα

Κάθε πλευρά της συνομιλίας φέρει διαφορετική ταυτότητα, και η διαφορά είναι η
ίδια η λειτουργία:

- **Στο GitHub, η απάντηση είναι αυτοματοποίηση για λογαριασμό σας.** Κάθε
  απάντηση χρησιμοποιεί ένα token για εκείνο το ένα αποθετήριο, περιορισμένο
  στην πρόσβαση του μέλους που ρώτησε, και γράφεται από τον λογαριασμό `[bot]`
  της εφαρμογής. Μία εξαίρεση: στην κοινόχρηστη εφαρμογή Control Center Connect,
  το bot δημοσιεύει σε νήματα ελέγχου μόνο όταν ο χειριστής του Connect έχει
  καταχωρίσει την εγκατάσταση· αλλιώς, μια απάντηση μέσα σε νήμα ελέγχου γράφεται
  από τον λογαριασμό του μέλους που ρώτησε. Σε κάθε
  περίπτωση κάθε απάντηση ξεκινά με `**Control Center** (for @login):`, που λέει
  ποιος ρώτησε και λειτουργεί επίσης ως φύλακας βρόχου. Οι αναφορές @ στα λόγια του πράκτορα απενεργοποιούνται, ώστε μια απάντηση να μην ειδοποιεί ποτέ κάποιον χρήστη ή ομάδα.
- **Στον χώρο, η ερώτηση είναι δική σας.** Το μήνυμα αποδίδεται στο μέλος στο
  οποίο αντιστοιχίστηκε ο συντάκτης, και η εκτέλεση του πράκτορα γίνεται για
  λογαριασμό του: τα commits είναι δικά του, και ο δείκτης
  αυτονομίας και οι περιορισμοί ενεργειών του χώρου εφαρμόζονται ακριβώς όπως
  σε ένα μήνυμα που πληκτρολογήθηκε στην εφαρμογή. Οι εγγραφές στον κεντρικό
  υπολογιστή κώδικα από την εκτέλεση χρησιμοποιούν tokens για ένα αποθετήριο,
  περιορισμένα από αυτό το μέλος, ποτέ τη σύνδεσή του παραδομένη ολόκληρη.

Η δημοσίευση των ευρημάτων ελέγχου πίσω στο GitHub παραμένει απόφαση ενός
ανθρώπου, που λαμβάνεται στο Control Center. Μια @-αναφορά μπορεί να _ξεκινήσει_
έναν έλεγχο· μόνο ένας άνθρωπος δημοσιεύει έναν.

## Ο φύλακας βρόχου

Ό,τι έχει συνταχθεί από λογαριασμό bot απορρίπτεται πριν εκτελεστεί οποιαδήποτε
πύλη — το δικό μας ειδικά, και κάθε κατάληξη `[bot]`, ώστε ούτε το bot ελέγχου
μιας άλλης εφαρμογής να μπορεί να ξυπνήσει το δικό μας — και το ίδιο ισχύει για
κάθε σχόλιο που ξεκινά με το πρόθεμα `**Control Center** (for @`, αφού μια
απάντηση μέσα σε νήμα ελέγχου μέσω Connect μπορεί να συντάσσεται από τον λογαριασμό ενός ανθρώπου. Χωρίς αυτό,
οι απαντήσεις θα έφταναν ως νέα σχόλια και θα ενεργοποιούσαν ξανά τη γέφυρα για
πάντα.

Μόνο το `@usectrl` ξεκινά εργασία. Το όνομα σύνδεσης της ίδιας της εφαρμογής (`<slug>[bot]`) και το γυμνό slug της δεν απευθύνονται σε τίποτα: το GitHub δεν προσφέρει αυτόματη συμπλήρωση για λογαριασμό εφαρμογής, και ένα γυμνό slug μπορεί να ανήκει σε έναν ανθρώπινο χρήστη.

## Τι δεν προσφέρεται σκόπιμα

- **Χωρίς αυτόματη δημοσίευση.** Τα ευρήματα προσγειώνονται στον χώρο ελέγχου·
  η δημοσίευση στο GitHub είναι ξεχωριστή, ανθρώπινη ενέργεια
- **Χωρίς ασαφή ταυτότητα.** Ο συντάκτης αντιστοιχίζεται σε ακριβώς ένα μέλος ή
  αγνοείται — δεν υπάρχει απόδοση κατ' εκτίμηση
- **Χωρίς αυτοματοποιημένη έγκριση.** Η αυτοματοποίηση μπορεί να σχολιάζει και να
  ζητά αλλαγές, αλλά μια ανασκόπηση `APPROVE` απορρίπτεται πριν σταλεί. Η έγκριση
  είναι πράξη ανθρώπου
- **Χωρίς webhook της GitHub App.** Αυτή η επιφάνεια δεν καταχωρεί ποτέ ένα,
  οπότε δεν υπάρχει URL εισόδου που να εκτίθεται για σχόλια PR. Τα άλλα webhook
  του προϊόντος (pipeline, συγχρονισμός εισιτηρίων) αποτελούν ξεχωριστή,
  προαιρετική ρύθμιση.
