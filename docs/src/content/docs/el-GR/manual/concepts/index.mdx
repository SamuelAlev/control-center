These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/); when you want to look
something up, go to the [reference](/el-GR/εγχειρίδιο/αναφορά/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/el-GR/εγχειρίδιο/έννοιες/χώροι-εργασίας/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/el-GR/εγχειρίδιο/έννοιες/μοντέλο-πρακτόρων/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/el-GR/εγχειρίδιο/έννοιες/κύκλος-ζωής-αποστολής/) — what happens between your message and the agent's first token
- [Modes](/el-GR/εγχειρίδιο/έννοιες/λειτουργίες/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/el-GR/εγχειρίδιο/έννοιες/πλαίσιο-εργαλείων/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/el-GR/εγχειρίδιο/έννοιες/νοημοσύνη-κώδικα/) — the code graph, language server, structural search and debugger
- [Conversation history](/el-GR/εγχειρίδιο/έννοιες/ιστορικό-συνομιλιών/) — persistence, compaction and forking a transcript
