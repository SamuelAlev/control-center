Αυτά είναι τα **δεσμευμένα στον διακομιστή** εργαλεία που καταχωρίζει απευθείας το ενσωματωμένο runtime πράκτορα — διακομιστής γλώσσας, δομική αναζήτηση, αποσφαλματωτής, πυρήνες, σενάρια λειτουργίας κώδικα, ερωτήσεις και έλεγχος εργατών — σε αντίθεση με τα [εργαλεία MCP](/el-GR/εγχειρίδιο/αναφορά/εργαλεία-mcp/) που γεφυρώνει και τα γενικά εργαλεία αρχείων, αναζήτησης και shell από το runtime του harness. Δεν βρίσκονται στο μητρώο MCP: ένας εξωτερικός πελάτης MCP δεν θα τα δει, επειδή το καθένα είναι δεσμευμένο σε έναν ζωντανό πόρο στην πλευρά του διακομιστή — μια διεργασία διακομιστή γλώσσας, έναν προσαρμογέα αποσφαλμάτωσης, έναν διερμηνέα — που ανήκει σε μία μόνο εκτέλεση.

Κάθε εργαλείο εδώ καταχωρίζεται μόνο όταν ο πόρος που το στηρίζει είναι συνδεδεμένος για την εκτέλεση — ένας επόπτης διακομιστή γλώσσας ή αποσφαλμάτωσης, ένας αναλυτής tree-sitter, ένα εργοστάσιο πυρήνων, μια θύρα ερωτήσεων, ένας κατάλογος vibe. Η ανίχνευση διακομιστή γλώσσας ή προσαρμογέα αποσφαλμάτωσης για *αυτό το checkout* είναι ξεχωριστός, μεταγενέστερος έλεγχος (`status` / `adapters`): αυτά τα εργαλεία παραμένουν στην επιφάνεια, ώστε ο πράκτορας να μπορεί να ρωτήσει γιατί τίποτα δεν είναι αξιοποιήσιμο, αντί να μαντεύει.

## Βαθμίδες έγκρισης

Κάθε εργαλείο δηλώνει μια βαθμίδα, και η βαθμίδα αποφασίζει **ποιες επιφάνειες το βλέπουν** — όχι απλώς αν ζητά έγκριση. Η λειτουργία σχεδίου και οι υποπράκτορες μόνο για ανάγνωση περιορίζονται στο `read`, οπότε ένα εργαλείο βαθμίδας `write` ή `exec` απουσιάζει εντελώς από το σχήμα τους.

| Βαθμίδα | Σημασία                       | Εργαλεία εδώ                                       |
| ------- | ----------------------------- | -------------------------------------------------- |
| `read`  | Χωρίς παρενέργειες            | `lsp`, `ast_grep`, `ask_user`, `repl`, τα πέντε `vibe_*` |
| `write` | Αλλάζει αρχεία                | `lsp_rename`, `ast_edit`, `resolve`                |
| `exec`  | Ξεκινά ή ελέγχει μια διεργασία | `debug`, `eval`                                    |

## Άμεσα, μόνο από σενάριο ή φορτώνονται στην πρώτη χρήση

Όταν ο διακομιστής μπορεί να εκτελέσει σενάρια, μια εκτέλεση καλεί λίγα εργαλεία άμεσα και φτάνει στα υπόλοιπα από ένα σενάριο [`repl`](#repl--εκτελέστε-ένα-σενάριο-που-καλεί-τα-εργαλεία-σας)· δείτε [Λειτουργία κώδικα](/el-GR/εγχειρίδιο/έννοιες/λειτουργία-κώδικα/#ποια-εργαλεία-καλεί-ο-πράκτορας-άμεσα) για ολόκληρο τον κανόνα. Για τα εργαλεία αυτής της σελίδας:

| Εργαλείο | Με `repl` | Χωρίς `repl` |
| ---- | ----------- | -------------- |
| `repl` | Άμεσο | Δεν υπάρχει |
| `ask_user` | Άμεσο | Άμεσο |
| `lsp`, `lsp_rename`, `ast_grep`, `ast_edit`, `resolve`, `debug` | Μόνο από σενάριο | Φορτώνεται στην πρώτη χρήση |
| `eval` | Φορτώνεται στην πρώτη χρήση (ένα σενάριο δεν μπορεί να το καλέσει) | Φορτώνεται στην πρώτη χρήση |
| `vibe_*` | Άμεσο στη λειτουργία vibe, ποτέ από σενάριο | Άμεσο στη λειτουργία vibe |

Όταν ο διακομιστής δεν μπορεί να εκτελέσει τα σενάρια της εκτέλεσης, ένα εργαλείο με σήμανση «Μόνο από σενάριο» φορτώνεται στην πρώτη χρήση ([Όταν τα σενάρια δεν μπορούν να τρέξουν](/el-GR/εγχειρίδιο/έννοιες/λειτουργία-κώδικα/#όταν-τα-σενάρια-δεν-μπορούν-να-τρέξουν)).

## `lsp` — ερωτήματα διακομιστή γλώσσας

Καταχωρίζεται όταν η εκτέλεση έχει έναν επόπτη διακομιστή γλώσσας και έναν κατάλογο εργασίας. Το αν ένας διακομιστής μπορεί όντως να απαντήσει ανιχνεύεται τη στιγμή της κλήσης, ως **τομή**: ένας δείκτης ρίζας πρέπει να υπάρχει *και* το εκτελέσιμο του διακομιστή πρέπει να επιλύεται. Ο ένας από τους δύο μόνος του σημαίνει ότι κανένας διακομιστής δεν ξεκινά — το `status` το λέει — αντί για μια σιωπηλή εικασία.

Οι διακομιστές προέρχονται μόνο από τον ενσωματωμένο πίνακα· ένα `lsp.json` του αποθετηρίου δεν διαβάζεται. Σε εκτέλεση με sandbox, κάθε εκτέλεση έχει τη δική της συνεδρία διακομιστή γλώσσας, οπότε οι διακομιστές ξεκινούν ξανά με κάθε εκτέλεση. Τα εκτελέσιμα τοπικά στο έργο (`node_modules/.bin`) χρησιμοποιούνται μόνο όταν η εκτέλεση γίνεται σε sandbox, και η ρίζα του έργου δεν ανεβαίνει ποτέ πάνω από τον κατάλογο εργασίας της εκτέλεσης.

Οι θέσεις προσδιορίζονται με `line` συν μια υποσυμβολοσειρά `symbol`, ποτέ με στήλη. Ένα μοντέλο στο οποίο ζητείται στήλη μαντεύει, και μια λανθασμένη μαντεψιά επιλύεται σε διαφορετικό σύμβολο στην ίδια γραμμή — μια απάντηση που φαίνεται σωστή και αφορά κάτι άλλο. Η παράλειψη του `symbol` σε μια ενέργεια πλοήγησης είναι σφάλμα, όχι εικασία για την πρώτη στήλη.

| Ενέργεια          | Ορίσματα                         | Επιστρέφει                                |
| ----------------- | -------------------------------- | ------------------------------------------ |
| `diagnostics`     | `file` (ή `"*"`)                 | Σφάλματα και προειδοποιήσεις· το `"*"` εκτελεί αντ' αυτού τον ελεγκτή έργου |
| `definition`      | `file`, `line`, `symbol`         | Πού δηλώνεται το σύμβολο                   |
| `type_definition` | `file`, `line`, `symbol`         | Πού δηλώνεται ο τύπος του                 |
| `implementation`  | `file`, `line`, `symbol`         | Συγκεκριμένες υλοποιήσεις                  |
| `references`      | `file`, `line`, `symbol`         | Κάθε χρήση, με όριο 50                     |
| `hover`           | `file`, `line`, `symbol`         | Υπογραφή και σχόλιο τεκμηρίωσης            |
| `symbols`         | `query` ή `file`                 | Αναζήτηση στον χώρο εργασίας με `query` (όριο 100)· σύμβολα εγγράφου με `file` (όριο 200) |
| `code_actions`    | `file`, `line`, `symbol`         | Γρήγορες διορθώσεις που προσφέρει ο διακομιστής |
| `status`          | —                                | Ποιοι διακομιστές εκτελούνται, και για ποιες ρίζες |
| `reload`          | —                                | Επανεκκινεί τον διακομιστή για αυτή τη ρίζα |

### Διαγνωστικά κατά την εγγραφή

Το κέρδος δεν είναι το εργαλείο. Τα `write`, `edit` και `apply_patch` είναι **τυλιγμένα**: μετά την εγγραφή, το αρχείο συγχρονίζεται και αποθηκεύεται μέσω του διακομιστή γλώσσας, και μόνο τα **νεοεισαχθέντα** διαγνωστικά ενσωματώνονται στο αποτέλεσμα του εργαλείου. Ένας πράκτορας μαθαίνει ότι έσπασε το build τη στιγμή που το έσπασε, χωρίς να χρειάζεται να θυμηθεί να ρωτήσει.

Τα διαγνωστικά που έχουν ήδη αναφερθεί καταστέλλονται από ένα μητρώο ανά εκτέλεση με κλειδί τη σοβαρότητα, τον κωδικό και το μήνυμα — η θέση αποκλείεται σκόπιμα, ώστε ένα διαγνωστικό που απλώς κατέβηκε τέσσερις γραμμές να μην αναφέρεται ξανά ως νέο.

## `lsp_rename` — μετονομασία σε όλο το έργο

Ένα ξεχωριστό εργαλείο, βαθμίδας `write`, για έναν ακριβώς λόγο: η βαθμίδα αποφασίζει την ορατότητα. Η ενσωμάτωση της μετονομασίας στο `lsp` θα έδινε είτε σε έναν εξερευνητή μόνο για ανάγνωση τη δυνατότητα να ξαναγράψει το αποθετήριο, είτε θα έβαζε κάθε `hover` πίσω από μια προτροπή έγκρισης.

| Όρισμα     | Σημασία                                    |
| ---------- | ------------------------------------------ |
| `file`     | Πού βρίσκεται το σύμβολο                   |
| `line`     | Γραμμή με δείκτη από το 1                  |
| `symbol`   | Υποσυμβολοσειρά που το αναγνωρίζει σε αυτή τη γραμμή |
| `new_name` | Πώς θα ονομαστεί                           |

## `ast_grep` — δομική αναζήτηση

Βρίσκει κώδικα με βάση το **σχήμα** και όχι το κείμενο. Το `$NAME` αντιστοιχίζει οποιονδήποτε κόμβο, το `$$$NAME` αντιστοιχίζει μια σειρά από αδέλφια, και το `$_` είναι ένας μπαλαντέρ που δεν δεσμεύει τίποτα.

Η ιδιότητα που το κάνει αντιστοιχιστή και όχι μια regex με επιπλέον βήματα: μια μεταβλητή μοτίβου που επαναλαμβάνεται σε ένα μοτίβο πρέπει να συλλαμβάνει το ίδιο κείμενο.

```
ast_grep(pattern: "if ($X != null) $X.dispose()", language: "dart")
```

αντιστοιχίζει έναν φρουρό που κάνει dispose σε αυτό που έλεγξε, και **δεν** αντιστοιχίζει έναν που κάνει dispose σε κάτι άλλο.

| Όρισμα        | Σημασία                                                     |
| ------------- | ----------------------------------------------------------- |
| `pattern`     | Ένα απόσπασμα κώδικα με μεταβλητές μοτίβου                   |
| `path`        | Αρχείο ή φάκελος προς αναζήτηση· από προεπιλογή ολόκληρος ο χώρος εργασίας |
| `language`    | Ένα αναγνωριστικό γραμματικής που διανέμεται (`dart`, `python`, `rust`, `c`, …). Συμπεραίνεται όταν το `path` ονομάζει αρχείο |
| `max_results` | Προεπιλογή 50                                               |

:::note[Το μοτίβο αναλύεται από την ίδια γραμματική με το αρχείο]
Έτσι, το `dispose(x)` αντιστοιχίζει την κλήση όπως κι αν είναι αραιωμένη με κενά, τυλιγμένη ή σχολιασμένη — και δεν αντιστοιχίζει ποτέ τους ίδιους χαρακτήρες μέσα σε ένα string literal ή ένα σχόλιο.
:::

:::caution[Ένα απόσπασμα αναλύεται μέσα σε ένα ικρίωμα, όχι σκέτο]
Το `dispose(x)` που αναλύεται στο ανώτατο επίπεδο της Dart είναι μια έγκυρη *υπογραφή συνάρτησης*. Ο μεταγλωττιστής μοτίβων δοκιμάζει μια κλίμακα πλαισίων (εντολή, έκφραση, μέλος κλάσης, δήλωση) και χρησιμοποιεί το πρώτο που αποδέχεται το απόσπασμα. Ένα μοτίβο που κανένα πλαίσιο δεν αποδέχεται αναφέρεται ως μη αναλύσιμο, αντί να αναζητηθεί και να μη βρεθεί σιωπηλά.
:::

## `ast_edit` — δομική αναδιατύπωση, σε στάδιο

Ίδια αντιστοίχιση, συν ένα πρότυπο `rewrite` με τις μεταβλητές μοτίβου να αντικαθίστανται ξανά μέσα. **Τίποτα δεν γράφεται.** Η αλλαγή προετοιμάζεται σε στάδιο και το αποτέλεσμα ονομάζει ένα `edit_id`.

```
ast_edit(pattern: "dispose($X)", rewrite: "$X.dispose()", language: "dart")
→ (proposed) 12 replacements in 4 files … call resolve with edit_id "edit_1"
```

| Όρισμα     | Σημασία                                             |
| ---------- | --------------------------------------------------- |
| `pattern`  | Τι να αντιστοιχιστεί                                |
| `rewrite`  | Τι να μπει εκεί, με αντικατάσταση του `$NAME`       |
| `path`     | Εμβέλεια· από προεπιλογή ολόκληρος ο χώρος εργασίας |
| `language` | Αναγνωριστικό γλώσσας                               |

## `resolve` — υποβολή ή απόρριψη μιας αλλαγής σε στάδιο

| Όρισμα    | Σημασία                          |
| --------- | -------------------------------- |
| `edit_id` | Από το αποτέλεσμα `(proposed)`   |
| `action`  | `accept` ή `discard`             |

Κάθε αρχείο συγκρίνεται με το περιεχόμενο που καταγράφηκε τη στιγμή της προετοιμασίας, και **οποιαδήποτε** ασυμφωνία απορρίπτει ολόκληρη την αλλαγή. Μια μερικώς εφαρμοσμένη δομική αναδιατύπωση αφήνει ένα δέντρο που δεν μεταγλωττίζεται ούτε με το παλιό ούτε με το νέο σχήμα.

## `debug` — οδήγηση αποσφαλματωτή

Καταχωρίζεται όταν η εκτέλεση έχει έναν επόπτη συνεδρίας αποσφαλμάτωσης, έναν κατάλογο εργασίας και ένα αναγνωριστικό συνομιλίας. Το αν ένας προσαρμογέας μπορεί όντως να ξεκινήσει ανιχνεύεται τη στιγμή της κλήσης, με τον ίδιο κανόνα τομής όπως για τον διακομιστή γλώσσας (δείκτης ρίζας *και* εκτελέσιμο). Βαθμίδα `exec`· όχι ασφαλές για παραλληλισμό (μια συνεδρία είναι κατάσταση που διαρκεί μεταξύ κλήσεων, οπότε ένα `continue` που προσπερνά το `stack` θα διάβαζε ένα frame που έχει ήδη μετακινηθεί).

Μία συνεδρία ανά συνομιλία, με αυστηρό TTL (30 λεπτά). Ένα δεύτερο `launch` απορρίπτεται, αντί να αντικαθιστά σιωπηλά το πρώτο. Σε εκτέλεση με sandbox η συνεδρία κρατά το sandbox της σε όλες τις στροφές μέχρι να τελειώσει, άρα για το πολύ αυτά τα 30 λεπτά.

| Λειτουργία    | Ορίσματα                      | Σημειώσεις                                     |
| ------------- | ----------------------------- | ---------------------------------------------- |
| `adapters`    | —                             | Ποιοι προσαρμογείς είναι αξιοποιήσιμοι εδώ, και γιατί όχι |
| `status`      | —                             | Αν εκτελείται μια συνεδρία, και πού σταμάτησε  |
| `breakpoints` | `file`, `lines[]`             | Κενό `lines` καθαρίζει το αρχείο. Μπορούν να οριστούν **πριν** την εκκίνηση |
| `launch`      | `program`, `args[]`           | Ξεκινά το πρόγραμμα σταματημένο στα σημεία διακοπής σας |
| `attach`      | `port`                        | Συνδέεται σε ένα αποσφαλματωμένο πρόγραμμα που εκτελείται ήδη, σε μία από τις προωθημένες θύρες της εκτέλεσης· κάθε άλλη θύρα απορρίπτεται πριν ξεκινήσει οτιδήποτε |
| `continue`    | `thread_id?`                  | Εκτελείται μέχρι την επόμενη διακοπή           |
| `pause`       | `thread_id?`                  | Το σταματά εκεί που βρίσκεται                  |
| `step_over` / `step_in` / `step_out` | `thread_id?` | Μετακινεί ένα βήμα                  |
| `threads`     | —                             | Αναγνωριστικά και ονόματα νημάτων              |
| `stack`       | `thread_id?`                  | Frames, με όριο 30                             |
| `scopes`      | `frame_id`                    | Πεδία εμβέλειας σε ένα frame, καθένα με ένα `reference` |
| `variables`   | `reference`                   | Παιδιά, με όριο 50, τιμές με όριο 400 χαρακτήρες |
| `evaluate`    | `expression`, `frame_id?`     | Αξιολογείται στην εμβέλεια του ίδιου του frame |
| `output`      | —                             | Το stdout/stderr του αποσφαλματωμένου προγράμματος, με όριο |
| `terminate`   | —                             | Τερματίζει τη συνεδρία και σκοτώνει τον προσαρμογέα |

### Προσαρμογείς

| Id        | Εντολή                     | Δείκτες ρίζας                                   |
| --------- | -------------------------- | ----------------------------------------------- |
| `dart`    | `dart debug_adapter`       | `pubspec.yaml`                                  |
| `debugpy` | `python3 -m debugpy.adapter` | `pyproject.toml`, `setup.py`, `requirements.txt` |
| `lldb`    | `lldb-dap`                 | `Cargo.toml`, `CMakeLists.txt`                  |
| `delve`   | `dlv dap`                  | `go.mod`                                        |

Το `debugpy` προτιμά ένα `.venv/bin` ή `venv/bin` τοπικό στο έργο από το `$PATH` όταν η εκτέλεση γίνεται σε sandbox: μια python του `$PATH` είναι διαφορετικό περιβάλλον, και η σύνδεση από το λάθος περιβάλλον αποτυγχάνει με τρόπο που διαβάζεται σαν σπασμένος κώδικας. Χωρίς sandbox χρησιμοποιεί μόνο το `$PATH`, ώστε ένα αποθετήριο να μην μπορεί να επιλέξει τον διερμηνέα που τρέχει στον κεντρικό υπολογιστή.

## `repl` — εκτελέστε ένα σενάριο που καλεί τα εργαλεία σας

Υπάρχει σε κάθε εκτέλεση όταν ο διακομιστής μπορεί να εκτελέσει σενάρια ([Όταν μια εκτέλεση έχει `repl`](/el-GR/εγχειρίδιο/έννοιες/λειτουργία-κώδικα/#όταν-μια-εκτέλεση-έχει-repl)). Το σενάριο είναι απλή JavaScript, το σώμα μιας συνάρτησης async, και τρέχει σε έναν νέο, κλειδωμένο διερμηνέα μέσα στη δική του διεργασία: χωρίς πρόσβαση σε σύστημα αρχείων, δίκτυο, διεργασίες ή μονάδες. Το ίδιο το `repl` ανήκει στο επίπεδο `read` και προστατεύει τον εαυτό του, επειδή κάθε κλήση εργαλείου που κάνει το σενάριο ελέγχεται μεμονωμένα. Είναι επίσης διαθέσιμο στο τελικό σημείο MCP, για εκτελέσεις πρακτόρων σε διακομιστή που μπορεί να εκτελέσει σενάρια.

| Όρισμα | Σημασία |
| ------------------- | --------------------------------------------------------------------------------------------- |
| `code` | Το σενάριο. Το πολύ 256 KiB |
| `description` | Υποχρεωτικό. Μια σύντομη ετικέτα για τη γραμμή της συνομιλίας |
| `timeout_ms` | Προαιρετικό. Ένα μικρότερο χρονικό όριο από αυτό του χώρου εργασίας· ποτέ μεγαλύτερο |
| `max_output_tokens` | Προαιρετικό. Ένας μικρότερος προϋπολογισμός εξόδου από αυτόν του χώρου εργασίας· ποτέ μεγαλύτερος |

```js
// Read three files together and report only which ones failed.
const paths = ["lib/a.dart", "lib/b.dart", "lib/c.dart"];
const results = await Promise.allSettled(paths.map((path) => tools.read({ path })));
return results
  .map((r, i) => (r.status === "rejected" ? `${paths[i]}: ${r.reason.message}` : null))
  .filter(Boolean);
```

Η περιγραφή του `repl` λέει στον πράκτορα: «Ένα εργαλείο που δεν είναι από τα άμεσα εργαλεία σου δεν έχει ορισμό σε αυτό το αίτημα. Πριν από την πρώτη κλήση σε ένα τέτοιο, αναζήτησέ το με το `describeTool(name)` ή το `searchTools(query)`, εκτός αν η ακριβής μορφή κλήσης του σου έχει ήδη δειχθεί σε αυτή τη συνομιλία.»

Το `describeTool(name)` επιστρέφει την περιγραφή ενός εργαλείου, τη δήλωσή του, τα σχήματα εισόδου και εξόδου του και τη σημείωση αποτελέσματός του, όταν έχει μία: ό,τι λαμβάνει ένα σενάριο από μια ολοκληρωμένη κλήση, με τα λόγια του ίδιου του εργαλείου. Η περιγραφή του `repl` απαριθμεί τις σημειώσεις των άμεσων εργαλείων που μπορεί να καλέσει ένα σενάριο. Ένα αποτέλεσμα που είναι κείμενο JSON φτάνει ήδη αναλυμένο, εκτός αν περιέχει περισσότερες από 131.072 τιμές· τότε φτάνει ως κείμενο, και το σενάριο το αναλύει μόνο του με το `JSON.parse`. Το κείμενο ενός αποτελέσματος από εργαλείο εξωτερικού διακομιστή MCP κόβεται στους 262.144 χαρακτήρες, και το κομμένο κείμενο δεν αναλύεται πια.

- Το `tools.<name>(args)` καλεί ένα εργαλείο μέσω του ίδιου φίλτρου, των ίδιων περιορισμών και της ίδιας έγκρισης με μια άμεση κλήση, και απορρίπτεται με σφάλμα όταν αρνείται ή αποτυγχάνει. Οι κλήσεις μόνο για ανάγνωση μπορούν να τρέξουν μαζί· οι κλήσεις που αλλάζουν κάτι τρέχουν μία κάθε φορά, με τη σειρά που τις έκανε το σενάριο. Όσο μία από τις κλήσεις του περιμένει έναν άνθρωπο, καμία άλλη κλήση του σεναρίου δεν ξεκινά.
- Τα `ALL_TOOLS`, `searchTools(query, { limit, namespace })`, `describeTool(name)` και `describeNamespace(name)` βρίσκουν εργαλεία, και αυτά των συνδεδεμένων διακομιστών MCP συμπεριλαμβανομένων. Ένα εργαλείο έξω από το άμεσο σύνολο που μπορεί να καλέσει ένα σενάριο είναι κλητό μόνο από σενάριο· η άμεση κλήση ενός τέτοιου επιστρέφει πώς να κληθεί από το `repl`. Όταν ο διακομιστής δεν μπορεί να εκτελέσει τα σενάρια της εκτέλεσης, ένα τέτοιο εργαλείο φορτώνεται στην πρώτη χρήση.
- Τα όρια των αναζητήσεων είναι τα εξής: ένα ερώτημα έως 1.024 χαρακτήρες, ένα όνομα ή χώρος ονομάτων έως 256, το `limit` από 0 έως 50, και έως 200 αναζητήσεις που διαρκούν συνολικά 2 δευτερόλεπτα χρόνου του διακομιστή ανά σενάριο, ενώ όλα τα σενάρια ενός χώρου εργασίας μοιράζονται 2 δευτερόλεπτα χρόνου αναζήτησης, που επιστρέφονται με ρυθμό ένα τέταρτο του δευτερολέπτου κάθε δευτερόλεπτο· πέρα από οποιοδήποτε από τα δύο, οι επόμενες αναζητήσεις απορρίπτονται. Σε πολύ μεγάλο κατάλογο, οι περιγραφές στο `ALL_TOOLS` μοιράζονται ίσα περίπου ένα εκατομμύριο χαρακτήρες, και μια περικομμένη περιγραφή τελειώνει σε `…`· το `describeTool` επιστρέφει πάντα ολόκληρη την περιγραφή. Ένας τύπος που είναι πολύ μεγάλος για να εμφανιστεί γράφεται `unknown /* too large to show */`, και ένα άγνωστο όνομα απαντάται με τα πλησιέστερα ονόματα.
- Τα εργαλεία ομαδοποιούνται σε χώρους ονομάτων: το `builtin` (τα δικά του εργαλεία του μηχανισμού), το `control-center` (τα εργαλεία του Control Center) και ένας για κάθε συνδεδεμένο διακομιστή MCP, με το όνομα του διακομιστή. Ένας διακομιστής με όνομα `builtin`, `control-center` ή `script`, ή με όνομα που αρχίζει από `external-`, με οποιονδήποτε συνδυασμό κεφαλαίων και πεζών και με ή χωρίς κενά γύρω του, εμφανίζεται ως `external-` ακολουθούμενο από το όνομά του, και κανένα εργαλείο δεν βρίσκεται ποτέ στο `script`.
- Επιστρέφεται μόνο ό,τι επιστρέφει το σενάριο ή ό,τι περνά στα `text()`, `image()` ή `console.*`. Η έξοδος πέρα από τον προϋπολογισμό διατηρεί την αρχή και το τέλος της, και το `read_output` διαβάζει το υπόλοιπο.
- Τα `store(key, value)` / `load(key)` κρατούν τιμές JSON για επόμενα σενάρια της ίδιας συνομιλίας και του ίδιου πράκτορα, που αποθηκεύονται μόνο όταν ολοκληρωθεί το σενάριο. Τα σενάρια ενός υποπράκτορα δεν έχουν αποθήκευση.
- Το `await tools.ask_user(...)` θέτει μια ερώτηση· η απάντησή της προστίθεται και στο αποτέλεσμα. Διαθέσιμα είναι επίσης τα `sleep(ms)`, `setTimeout`, `limits()` και τα `models.embed` / `rank` / `classify` (ενσωματώσεις στη συσκευή).
- το `describeTool(name)` και το `searchTools(query)` απαντούν και για τις συναρτήσεις του ίδιου του σεναρίου, που δεν είναι εργαλεία: `text`, `image`, `store`, `load`, `sleep`, `setTimeout`, `clearTimeout`, `limits`, `exit` και `models.*`, κάτω από τον χώρο ονομάτων `script`.
- Δεν είναι δυνατή η κλήση από σενάριο: `repl`, `eval`, `task`, `checkpoint`, `rewind`, `compact`, `search_tools` και τα ρήματα `vibe_*`.
- Ένα σενάριο διαβάζει το παρελθόν της δικής του εκτέλεσης: το `history({start, role, tool, limit})` σελιδοποιεί το αρχείο συνομιλίας (το πολύ 50 γραμμές ανά κλήση· περάστε το `next_start` της προηγούμενης σελίδας ως `start`), το `outputs()` απαριθμεί τις εξόδους εργαλείων που αποθηκεύτηκαν για αυτή τη συνομιλία και τον πράκτορα, και το `loadOutput(handle)` διαβάζει 16.384 χαρακτήρες από μία από αυτές. Το `storedKeys()` απαριθμεί τα αποθηκευμένα κλειδιά με τα μεγέθη τους. Το `keep(value, label)` αποθηκεύει μια μεγάλη τιμή ως έξοδο που μπορεί να διαβάσει ένα μεταγενέστερο σενάριο ή το `read_output`, και αποθηκεύεται μόνο όταν ολοκληρωθεί το σενάριο (1 MiB μια τιμή, 64 τιμές και 16 MiB μια εκτέλεση). Το `limits().returnBudgetChars` δείχνει πόσο από τον προϋπολογισμό εξόδου έχει απομείνει. Μια εκτέλεση μόνο για ανάγνωση (η ανασκόπηση ενός στόχου) μπορεί να διαβάσει, αλλά όχι να αποθηκεύσει ή να κρατήσει. Στο Claude Code και στο ACP, το `history()` λειτουργεί, ενώ τα `outputs()`, `loadOutput()` και `keep()` αρνούνται, επειδή το Control Center δεν κρατά εξόδους εργαλείων για αυτές τις εκτελέσεις.
- Ένα σφάλμα από timeout, υπέρβαση εξόδου ή όριο κλήσεων λέει πώς να διορθωθεί.

Μια εκτέλεση τρέχει ένα σενάριο τη φορά. Τα όρια και το τι συμβαίνει στο καθένα βρίσκονται στη σελίδα [Λειτουργία κώδικα](/el-GR/εγχειρίδιο/έννοιες/λειτουργία-κώδικα/#όρια)· κάθε σενάριο καταγράφεται στην **Παρατηρησιμότητα → Εκτελέσεις κώδικα**.

## `eval` — μόνιμοι διερμηνείς

Ένα κελί Python ή JavaScript του οποίου οι μεταβλητές, τα imports και τα δεδομένα που φορτώθηκαν επιβιώνουν μεταξύ κλήσεων. Βαθμίδα `exec`· όχι ασφαλές για παραλληλισμό. Δεν είναι κλητό από σενάριο `repl`, και ένα κελί δεν μπορεί να καλέσει τα εργαλεία της εκτέλεσης: για να καλέσει εργαλεία από κώδικα, χρησιμοποιήστε το [`repl`](#repl--εκτελέστε-ένα-σενάριο-που-καλεί-τα-εργαλεία-σας).

| Όρισμα        | Σημασία                                          |
| ------------- | ------------------------------------------------ |
| `code`        | Το κελί                                          |
| `description` | Απαιτείται. 5–10 λέξεις για την ετικέτα της απομαγνητοφώνησης |
| `language`    | `python` (προεπιλογή) ή `javascript`             |
| `reset`       | Απορρίπτει τον διερμηνέα και ξεκινά από καθαρή κατάσταση πρώτα |

- Η τελευταία έκφραση επιστρέφεται όπως σε ένα notebook.
- Το `display()` λειτουργεί, ένα frame της pandas αποδίδεται ως πίνακας, και ένα σχήμα της matplotlib επιστρέφει ως **εικόνα που εμφανίζει η απομαγνητοφώνηση**.
- Τα ιδιώματα της IPython που πληκτρολογεί κανείς αντανακλαστικά — `%pip`, `%cd`, `!cmd`, `%%bash`, `%%timeit` — ξαναγράφονται σε απλό κώδικα. Το `%pip` καθαρίζει επίσης το `sys.modules`, ώστε το επόμενο `import` να βλέπει αυτό που μόλις εγκαταστάθηκε.
- Ένα κελί που τυπώνει περισσότερα από τον προϋπολογισμό εξόδου του κρατά τα πρώτα τρία τέταρτα και το τελευταίο τέταρτο, με μία γραμμή που λέει πόσοι χαρακτήρες και εικόνες αφαιρέθηκαν.
- Όταν ο διερμηνέας πέθανε χωρίς να του ζητηθεί, το επόμενο κελί ενημερώνεται μία φορά ότι οι προηγούμενες μεταβλητές του έχουν χαθεί.

:::note[Πού εκτελείται ο πυρήνας]
Στο περίβλημα της συνομιλίας όταν αυτή έχει ένα, αλλιώς στο sandbox λειτουργικού συστήματος της εκτέλεσης στον κεντρικό υπολογιστή. Με το sandbox ανενεργό ή μη διαθέσιμο εκτελείται χωρίς περιορισμούς, και το `eval` ζητά έγκριση εκτέλεσης στον κεντρικό υπολογιστή. Δεν εκκινεί περίβλημα για να φτάσει εκεί — ο ίδιος κανόνας που εμποδίζει μια καρτέλα σταθμού να ξεκινήσει αυτόματα.
:::

## `bash` στο παρασκήνιο

Το `bash` με `run_in_background: true` ξεκινά την εντολή και επιστρέφει αμέσως με ένα handle (`b1`, `b2`, …) αντί να περιμένει. Ο πράκτορας συνεχίζει να δουλεύει, ή τελειώνει τη στροφή του και ξυπνά όταν τελειώσει η εντολή.

| Όρισμα | Σημασία |
| ------------------- | ------- |
| `run_in_background` | `true` για να ξεκινήσει και να επιστρέψει αμέσως |
| `timeout_seconds` | Δευτερόλεπτα πριν σκοτωθεί η εντολή: 600 από προεπιλογή, το πολύ 3.600 |
| `notify` | Προαιρετικό. Ένα απλό μοτίβο· κάθε γραμμή εξόδου που ταιριάζει στέλνεται στον πράκτορα όσο τρέχει η εντολή (όπως `listening on\|FAILED`) |

- Το πολύ 4 εντολές παρασκηνίου τρέχουν ταυτόχρονα σε μια εκτέλεση. Κάθε μία σκοτώνεται στο timeout της και όταν τελειώσει η εκτέλεση, μαζί με κάθε διεργασία που ξεκίνησε.
- Όταν μια εντολή τελειώνει, ο πράκτορας παίρνει μια ειδοποίηση με τον κωδικό εξόδου, τους τελευταίους 2.000 χαρακτήρες εξόδου και ένα handle `read_output` για το υπόλοιπο.
- Ένας πράκτορας που το μόνο που του απομένει είναι μια εντολή παρασκηνίου περιμένει χωρίς να καλεί το μοντέλο, και ο φύλακας σιωπής της εκτέλεσης σταματά όσο περιμένει.
- Το `bash_output(handle)` διαβάζει την κατάσταση μιας εντολής και την πρόσφατη έξοδό της· το `bash_kill(handle)` τη σταματά. Και τα δύο λένε πότε το αποτέλεσμα έχει ήδη παραδοθεί.
- Ένα σενάριο δεν μπορεί να ξεκινήσει εντολή παρασκηνίου. Το Claude Code έχει τη δική του Bash στο παρασκήνιο· το Control Center κρατά αυτή την εκτέλεση ανοιχτή για το πολύ 10 λεπτά μετά τη στροφή που άφησε μια εργασία να τρέχει.

## `compact` — ελεύθερος χώρος στο παράθυρο συμφραζομένων

Συμπυκνώνει τα παλαιότερα συμφραζόμενα της συνομιλίας πριν από την επόμενη κλήση του μοντέλου, διατηρώντας όσα ονομάζει το `focus` (το πολύ 1.000 χαρακτήρες). Οι πιο πρόσφατες στροφές μένουν αυτούσιες. Η γραμμή προϋπολογισμού στροφής του πράκτορα δείχνει τη χρήση συμφραζομένων στο 70, 80 και 90%, και το εργαλείο αξίζει να καλείται πάνω από περίπου 70% πριν από μια μεγάλη νέα φάση εργασίας. Το hook `preCompact` του κατόχου του διακομιστή μπορεί να προσθέσει στην εστίαση ([Hooks κελύφους](/el-GR/εγχειρίδιο/αναφορά/διαμόρφωση-πράκτορα/#hooks-κελύφους)). Μετά από μια συμπύκνωση, ο διακομιστής προσθέτει ένα μπλοκ «Still in flight»: τον στόχο, τις αναμενόμενες αφυπνίσεις, τις ανοιχτές ερωτήσεις, τις εντολές παρασκηνίου, τη λίστα ελέγχου και τα αποθηκευμένα κλειδιά, με την κλήση που ανακτά το καθένα.

## `ask_user` — ερώτηση προς τον άνθρωπο

Βαθμίδα `read`. Ο **μόνος** τρόπος με τον οποίο μια εκτέλεση ρωτά κάτι τον χειριστή. Αποδίδει μια αριθμημένη κάρτα στη συνομιλία και αποκλείει μέχρι κάποιος να απαντήσει, να παραλείψει, ή μέχρι να λήξει το χρονικό όριο της ερώτησης. Μην γράφετε ποτέ την ερώτηση ως μήνυμα συνομιλίας — αυτό τερματίζει τη στροφή.

| Όρισμα            | Σημασία                                    |
| ----------------- | ------------------------------------------ |
| `question`        | Τι να ρωτηθεί                              |
| `context`         | Προαιρετικό: γιατί ρωτάτε και τι κρέμεται από την απάντηση |
| `options[]`       | Επιλογές, καθεμία `{label, description?}`  |
| `allow_free_text` | Αν γίνεται δεκτή πληκτρολογημένη απάντηση  |
| `multi_select`    | Αν μπορούν να επιλεγούν πολλές επιλογές    |

Μια παράλειψη είναι επιτυχία: προχωρήστε με βάση μια δηλωμένη παραδοχή και μην ξαναρωτήσετε. Η λήξη του χρονικού ορίου είναι σφάλμα με την ίδια οδηγία. Οι προτροπές άδειας («επιτρέπεται να το κάνω αυτό;») είναι ξεχωριστή πύλη και αποδίδονται ως η ίδια κάρτα στη συνομιλία.

Καταχωρίζεται μόνο όταν υπάρχουν και μια θύρα ερωτήσεων και ένας χώρος προορισμού. Χωρίς συνδεδεμένο άνθρωπο, η κλήση **αποτυγχάνει** αντί να αποκλείει για πάντα — η ίδια στάση ασφαλούς αποτυχίας που παίρνει ένα `prompt` περιορισμού όταν δεν είναι συνδεδεμένος εγκρίνων.

## `vibe_*` — κατεύθυνση εργατών παρασκηνίου

Καταχωρίζονται μόνο όσο είναι ενεργή η [λειτουργία vibe](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/κατεύθυνση-εργατών-παρασκηνίου/). Και τα πέντε είναι βαθμίδας `read`: η πύλη ανήκει στα εργαλεία του εργάτη, εκεί όπου συμβαίνει στην πραγματικότητα η επεξεργασία.

| Εργαλείο     | Ορίσματα                                 | Σημειώσεις                                  |
| ------------ | ---------------------------------------- | ------------------------------------------- |
| `vibe_spawn` | `brief`, `label`, `tier?`                | Επιστρέφει αμέσως· ο εργάτης συνεχίζει να εκτελείται |
| `vibe_send`  | `worker_id`, `message`                   | Προσθέτει στην ανάθεση και επανεκτελεί      |
| `vibe_wait`  | `worker_id`, `timeout_seconds?`          | Αποκλείει μέχρι να κατασταλάξει             |
| `vibe_kill`  | `worker_id`                              | Τον σταματά                                 |
| `vibe_list`  | —                                        | Βαθμίδα, κατάσταση, χρόνος που πέρασε και τελευταίο αποτέλεσμα |

Το `tier` είναι `fast` (μηχανική εργασία με σαφή προδιαγραφή) ή `good` (σχεδιασμός, κρίση ή έλεγχος της εξόδου ενός εργάτη `fast`).
