Το `cc_server` φιλοξενεί ένα μητρώο εργαλείων MCP (JSON-RPC 2.0), που εξυπηρετείται στην κύρια θύρα του διακομιστή (προεπιλογή `9030`) στα `POST /mcp` και `GET /sse`, με έκδοση πρωτοκόλλου `2024-11-05`. Κάθε πελάτης φτάνει στο ίδιο μητρώο: η εφαρμογή για υπολογιστή, η έκδοση για web, οι εξωτερικοί πελάτες MCP και ο ενσωματωμένος runtime πράκτορα. Εξωτερικοί διακομιστές MCP μπορούν να γεφυρωθούν στο ίδιο μητρώο ως δυναμικό επίπεδο.

## Μέγεθος μητρώου

| Μέτρηση                                                                                              | Πλήθος |
| ---------------------------------------------------------------------------------------------------- | ------ |
| Εργαλεία που καταχωρίζει το `cc_server`                                                              | 110    |
| Από το `packages/cc_mcp`                                                                             | 108    |
| Από το `packages/cc_mcp_client` (ανακάλυψη εργαλείων)                                                | 2      |
| Καταχωρισμένα στο βασικό μητρώο (`server_mcp_registry.dart`)                                         | 63     |
| Καταχωρισμένα μετά την εκκίνηση, καθώς ενεργοποιούνται οι υπηρεσίες τους (`cc_server_runtime.dart`)  | 47     |
| Από τα 63 του βασικού μητρώου, υπό συνθήκη ύπαρξης αποθετηρίου γραφήματος κώδικα                     | 5      |

Τα πέντε εργαλεία γραφήματος κώδικα καταχωρίζονται μόνο όταν ο ξενιστής περνά αποθετήριο γραφήματος κώδικα στο `buildServerMcpRegistry`. Το `cc_server` περνά πάντα ένα, οπότε και τα 110 είναι ενεργά στο δυαδικό που διανέμεται.

Το πλήρες μητρώο ανακοινώνεται στο `tools/list` χωρίς φραγή ανακάλυψης. Οι επεξεργασίες εισιτηρίων είναι τυποποιημένα εργαλεία.

:::note[Οι εξωτερικοί πελάτες βλέπουν πάντα ολόκληρο τον κατάλογο]
Το `tools/list` δεν περικόπτεται ποτέ. Οι πελάτες MCP επικυρώνουν τα ονόματα εργαλείων με βάση το δικό τους αντίγραφο αυτής της λίστας στην προσωρινή μνήμη και απορρίπτουν καθετί που δεν περιλαμβάνεται χωρίς να ρωτήσουν τον διακομιστή, οπότε ένα εργαλείο κρυμμένο εκεί είναι απρόσιτο και όχι απλώς αθόρυβο.

Ο **ενσωματωμένος μηχανισμός** είναι διαφορετικός: φορτώνει μόνο ένα μόνιμο υποσύνολο ορισμών ανά αίτημα και τραβά τα υπόλοιπα με την πρώτη χρήση, πράγμα που είναι συμπεριφορά της πλευράς του μηχανισμού και δεν αλλάζει αυτό το μητρώο. Δείτε [Πλαίσιο εργαλείων και προσωρινή αποθήκευση προτροπών](/el-GR/εγχειρίδιο/έννοιες/πλαίσιο-εργαλείων).
:::

:::note[Κάθε κλάση εργαλείου καταχωρίζεται]
Ένα αρχείο πηγαίου κώδικα στο `packages/cc_mcp/lib/src/tools/` είναι ένα εργαλείο που
μπορεί να καλέσει ένας πράκτορας. Το `packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart`
σπάει το build αν μια νέα κλάση εργαλείου δεν κατασκευάζεται από τίποτα.
:::

## Κοινές παράμετροι

### `workspace_id`

**Απαιτείται** σε κάθε εργαλείο που αγγίζει δεδομένα εμβέλειας χώρου εργασίας. Ένα απόν ή μη έγκυρο `workspace_id` επιστρέφει ρητό σφάλμα, και μια τιμή που δεν ταιριάζει με τον χώρο εργασίας της οντότητας-στόχου απορρίπτεται αντί να αγνοηθεί σιωπηλά. Παραλείψτε το στα πραγματικά καθολικά εργαλεία: το `list_workspaces` και τα έξι εργαλεία ροής ειδήσεων (`list_feeds`, `list_articles`, `get_article`, `set_article_read`, `set_article_saved`, `refresh_feeds`), που βασίζονται στη λίστα ροών ανά χρήστη του ιδιοκτήτη του διακομιστή. Τα εργαλεία ανακάλυψης (`search_tool_bm25`, `list_my_tools`) το παίρνουν προαιρετικά, ώστε να μπορούν να χαρακτηρίσουν τη δυνατότητα κλήσης ανά λειτουργία συνομιλίας. Όταν ο διακομιστής αποστέλλει έναν πράκτορα, ο χώρος εργασίας επιβάλλεται στην πλευρά του διακομιστή, οπότε ο πράκτορας δεν μπορεί να φτάσει σε άλλον χώρο εργασίας περνώντας ένα ξένο id.

## Ανακάλυψη εργαλείων

Και τα δύο προέρχονται από το `cc_mcp_client`, όχι από το `cc_mcp`, και και τα δύο συμβουλεύονται τον φύλακα λειτουργίας, ώστε να αναφέρουν τι είναι καλούμενο στην _τρέχουσα_ λειτουργία συνομιλίας.

| Εργαλείο           | Περιγραφή                                                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| `search_tool_bm25` | Αναζητά στον κατάλογο εργαλείων με λέξη-κλειδί· επιστρέφει τα εργαλεία που ταιριάζουν, τα σχήματα ορισμάτων τους και αν το καθένα είναι καλούμενο αυτή τη στιγμή |
| `list_my_tools`    | Παραθέτει τα εργαλεία που είναι καλούμενα αυτή τη στιγμή σε αυτή τη συνομιλία, φιλτραρισμένα κατά τη λειτουργία της                    |

Ένα τρίτο εργαλείο ανακάλυψης, το **`search_tools`**, υπάρχει μόνο μέσα στον ενσωματωμένο μηχανισμό και δεν αποτελεί μέρος αυτού του μητρώου MCP. Κατατάσσει την επιφάνεια εργαλείων της ίδιας της εκτέλεσης και, σε αντίθεση με το `search_tool_bm25`, **φορτώνει** τα σχήματα όσων βρίσκει, ώστε ο πράκτορας να μπορεί να καλέσει ένα ταίριασμα στην επόμενη στροφή του. Οι πράκτορες στον μηχανισμό καλό είναι να το προτιμούν· οι πελάτες MCP έχουν το `search_tool_bm25`.

Οι πράκτορες μιλούν μεταξύ τους μέσω χώρων (διαρκών, ορατών στον κατάλογο συμμετεχόντων). | Εργαλείο        | Περιγραφή                                                                                     |
| --------------- | --------------------------------------------------------------------------------------------- |
| `send_to_agent` | Στέλνει μονόδρομο μήνυμα σε άλλον πράκτορα, με διεύθυνση μέσω `to_agent_id` ή ακριβούς `to_agent_name` |
| `ask_agent`     | Ρωτά άλλον πράκτορα και περιμένει την απάντησή του ή λήγει ο χρόνος                            |
| `delegate_task` | Αναθέτει μια εργασία σε άλλον πράκτορα ως παρακολουθούμενο θυγατρικό εισιτήριο                  |
| `consult_agent` | Προσθέτει στον χώρο τον ειδικό που ταιριάζει καλύτερα με βάση τις δεξιότητες και τον αποστέλλει με μια εστιασμένη οδηγία |
| `todo_read`     | Διαβάζει την αποθηκευμένη λίστα ελέγχου εργασιών αυτής της συνομιλίας                            |

## Εργαλεία γραφήματος κώδικα

Καταχωρίζονται μόνο όταν ο ξενιστής παρέχει αποθετήριο γραφήματος κώδικα. Το ευρετήριο καλύπτει το σύνολο γραμματικών που διανέμεται (Dart, JS/TS, PHP, Python, Rust, Zig, C/C++, Go, Java, Ruby, C#, Swift, Kotlin, R, Assembly, MATLAB, Ada)· σύμβολα σε οποιαδήποτε άλλη γλώσσα δεν υπάρχουν.

| Εργαλείο       | Περιγραφή                                                                          |
| -------------- | ---------------------------------------------------------------------------------- |
| `search_code`  | Αναζητά στα ευρετηριασμένα σύμβολα κατά όνομα, υπογραφή και σχόλιο τεκμηρίωσης (υβριδική BM25 + σημασιολογική) |
| `code_symbol`  | Αναζητά σύμβολα κατά ακριβές όνομα· επιστρέφει `file:line` και υπογραφή             |
| `code_callers` | Παραθέτει τα σύμβολα που καλούν ή εξαρτώνται από ένα σύμβολο (εισερχόμενες ακμές)   |

## Εργαλεία περιβλήματος (σταθμών)

Οδηγήστε αναλώσιμες μηχανές — ένα περίκλειστο πρόγραμμα περιήγησης ή επιφάνεια
εργασίας Linux, έναν εξομοιωτή Android ή έναν Προσομοιωτή iOS — μέσα από μια
εκτέλεση. Καταχωρίζονται μετά την εκκίνηση, άνευ όρων: το αν μια μηχανή μπορεί
όντος να εκκινήσει είναι ερώτημα ανίχνευσης που τα εργαλεία απαντούν ανά κλήση.
Επαναλαμβανόμενες κλήσεις σε μία συνομιλία επαναχρησιμοποιούν μία μηχανή· τα
στιγμιότυπα οθόνης επιστρέφουν ως περιεχόμενο εικόνας με προϋπολογισμό μίας
εικόνας ανά αποτέλεσμα, και το εξαγόμενο περιεχόμενο σελίδας/UI περιφράσσεται ως
μη αξιόπιστα δεδομένα. Τα τέσσερα εργαλεία χρήσης συν το `rig_close` δηλώνουν το
`enclosureControl` ως [κλάση ενεργειών](/el-GR/εγχειρίδιο/έννοιες/περιορισμοί/)
(τα εργαλεία χρήσης δηλώνουν επίσης `networkEgress` και `processSpawn`· τα
`mobile_use` και `ios_use` δηλώνουν επίσης `packageInstall`), οπότε οι λειτουργίες
μόνο για ανάγνωση τα αρνούνται. Το `rig_list` δεν δηλώνει καμία — διαβάζει μόνο
την κατάσταση του χώρου εργασίας. Το πλήρες λεξιλόγιο ρημάτων ανά επιφάνεια
βρίσκεται στην [αναφορά σταθμών](/el-GR/εγχειρίδιο/αναφορά/σταθμοί/#action-verbs).

| Εργαλείο       | Περιγραφή                                                                                       |
| -------------- | ----------------------------------------------------------------------------------------------- |
| `computer_use` | Οδηγεί μια επιφάνεια εργασίας Linux σε περίκλειστη VM: μετακίνηση, κλικ, σύρσιμο, κύλιση, πληκτρολόγηση, αλλαγή μεγέθους, πρόχειρο, στιγμιότυπο οθόνης |
| `browser_use`  | Οδηγεί ένα headless Chromium, Firefox ή WebKit (`engine`): πλοήγηση, κλικ, συμπλήρωση, εξαγωγή (a11y/DOM/κονσόλα), πρόχειρο, στιγμιότυπο οθόνης |
| `mobile_use`   | Οδηγεί το Android μέσω ADB: επιθεώρηση/είσοδος, στιγμιότυπα οθόνης, εγκατάσταση/εκκίνηση/διακοπή/επαναφορά/απεγκατάσταση εφαρμογών, βαθείς σύνδεσμοι και εντολές συσκευής σε μορφή argv |
| `ios_use`      | Οδηγεί τον Προσομοιωτή iOS μέσω WebDriverAgent/CoreSimulator: επιθεώρηση/είσοδος, στιγμιότυπα οθόνης, εγκατάσταση/εκκίνηση/διακοπή/απεγκατάσταση εφαρμογών, βαθείς σύνδεσμοι και διεργασίες προσομοιωτή σε μορφή argv |
| `rig_list`     | Παραθέτει τους σταθμούς ενός χώρου εργασίας με επιφάνεια, κατάσταση, μέγεθος οθόνης και ελεγκτή |
| `rig_close`    | Καταστρέφει έναν σταθμό και απορρίπτει την κατάσταση της μηχανής που του ανήκει                  |

## Όσα δεν εκτίθενται μέσω MCP

Το ημερολόγιο και οι συσκέψεις δεν έχουν εργαλεία MCP. Οι πράκτορες δεν μπορούν να διαβάσουν το ημερολόγιό σας, τις συσκέψεις, τις απομαγνητοφωνήσεις, τα στοιχεία ενέργειας ή τις αποφάσεις σας. Η σύνοψη που παράγει στοιχεία ενέργειας και αποφάσεις εκτελείται ως το ενσωματωμένο [pipeline `meeting_summary`](/el-GR/εγχειρίδιο/έννοιες/συσκέψεις/), όχι ως εργαλείο που μπορεί να καλέσει ένας πράκτορας.

## Περιορισμός εργαλείων ανά λειτουργία

Ο περιορισμός επιβάλλεται δύο φορές από έναν πίνακα (`ModeToolPolicy`): μία στον αποστολέα MCP για τον προσαρμογέα Claude Code και μία στο μητρώο του ενσωματωμένου μηχανισμού. Μια αποκλεισμένη κλήση επιστρέφει τον λόγο.

| Λειτουργία    | Επιφάνεια εργαλείων                                                                                                                                                                                                                    |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`        | Κάθε καταχωρισμένο εργαλείο· χωρίς λίστα επιτρεπόμενων                                                                                                                                                                                  |
| `plan`        | Μια επιμελημένη λίστα επιτρεπόμενων. Χωρίς εγγραφές στο worktree και χωρίς τα ρήματα εισιτηρίων `create` / `assign` / `delegate`, αλλά επιτρέπονται η μνήμη, τα τεχνουργήματα, οι λίστες εργασιών, το `submit_plan`, το `exit_plan_mode` και τα ρήματα ολοκλήρωσης εισιτηρίου στο εισιτήριο που έχει αποσταλεί |
| `review`      | Μια επιμελημένη λίστα επιτρεπόμενων: συμμετοχή σε έλεγχο, επικοινωνία, ανακτήσεις πλαισίου μόνο για ανάγνωση και το πλήρες σύνολο ρημάτων εισιτηρίων, συμπεριλαμβανομένων των `create_ticket` και `assign_ticket`                         |
| `orchestrate` | Μια επιμελημένη λίστα επιτρεπόμενων: εργαλεία έρευνας και ανάγνωσης συν τα `propose_orchestration`, `create_playbook` και `run_playbook`. Η πρόσληψη, η αποσύνθεση και η ολοκλήρωση εισιτηρίων συμβαίνουν ντετερμινιστικά μετά την έγκριση, ποτέ στη μέση της εκτέλεσης |

Επιτρέπονται σε κάθε λειτουργία ανεξάρτητα από τη λίστα επιτρεπόμενων:

| Σύνολο                  | Εργαλεία                                                                                                                                                                                                                                                          |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Μνήμη και τεχνουργήματα | `search_memory`, `propose_fact`, `propose_policy`, `supersede_fact`, `supersede_policy`, `record_observation`, `update_my_notes`, `get_my_notes`, `list_memory_domains`, `list_policies`, `publish_artifact`, `revise_artifact`, `list_artifacts`, `get_artifact` |
| Γράφημα κώδικα          | `search_code`, `code_symbol`, `code_callers`, `code_callees`, `code_impact`                                                                                                                                                                                       |
| Μηχανική εκτέλεσης      | `search_tool_bm25`, `list_my_tools`, `todo_write`, `todo_read`                                                                                                                                                                                                    |

Το να βρίσκεται ένα εργαλείο σε λίστα επιτρεπόμενων δεν το κάνει καλούμενο, και ισχύει και το αντίστροφο: η δυνατότητα υποβολής ερώτησης στον χειριστή είναι εργαλείο του **μηχανισμού** (`ask_user`), οπότε δεν εμφανίζεται καθόλου σε αυτόν τον κατάλογο MCP.

## Εργαλεία με πύλη έγκρισης

Ένα εργαλείο μπορεί να δηλώνει `requiresApproval`. Τότε ο αποστολέας χτίζει ένα `ApprovalPayload` και το προβάλλει μέσω του `ConfirmationPort` πριν εκτελεστεί το εργαλείο· το `cc_server` συνδέει αυτή τη θύρα, οπότε η πύλη είναι ενεργή.

Τα καταχωρισμένα εργαλεία που το δηλώνουν: `create_ticket`, `update_ticket`, `assign_ticket`, `reassign_ticket`, `close_ticket`, `ticket_relation`, `create_goal`, `update_goal_progress`, `create_approval`, `decide_approval`, `comment_approval`, `create_work_product`, `save_work_product_revision`, `create_runtime_profile`, `install_skill`, `update_skill`.

Ανεξάρτητα, οι ενοποιημένοι περιορισμοί ενεργειών βάζουν σε πύλη κάθε εργαλείο που δηλώνει μη κενό σύνολο `ActionClass`. Μια απόφαση `prompt` χωρίς συνδεδεμένο εγκρίνοντα απορρίπτεται. Δείτε [Περιορισμοί](/el-GR/εγχειρίδιο/έννοιες/περιορισμοί/).

## Δυνατότητες χωρίς εργαλείο πίσω τους

Δεν είναι κάθε δυνατότητα του προϊόντος προσβάσιμη από πράκτορα. Αυτές δεν έχουν
καθόλου εργαλείο, οπότε ένα όνομα που ίσως έχετε δει να αναφέρεται αλλού
επιστρέφει «άγνωστο εργαλείο»:

| Δυνατότητα                                | Πού ζει αντ' αυτού                                                                                                |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Πρόσληψη, απόλυση ή επεξεργασία πράκτορα  | Το UI των πρακτόρων. Δεν υπάρχει εργαλείο `hire_agent` / `fire_agent` / `update_agent`                            |
| Δημιουργία χώρου εργασίας                 | `workspace.upsert` μέσω RPC, που αρχικοποιεί και σφραγίζει την κυριότητα                                           |
| Έργα (δημιουργία / λίστα / ενημέρωση / καταχώριση) | Το UI των εισιτηρίων. Τα έργα είναι επιφάνεια χειριστή — δείτε [Οργάνωση εργασίας με έργα](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/έργα/) |
| Υποβολή αποκλειστικής ερώτησης στον χειριστή | Το εργαλείο `ask_user` του **μηχανισμού**, όχι το MCP. Αποδίδει μια φόρμα στη συνομιλία και μπλοκάρει μέχρι την απάντηση |
| Διαγνωστικά ανά πράκτορα                  | Τίποτα. Δεν υπάρχει `doctor` — δείτε [Διάγνωση πράκτορα](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/διάγνωση-πράκτορα/)      |
| Ημερολόγιο και συσκέψεις                  | RPC μόνο για ανθρώπινους πελάτες (δείτε παραπάνω)                                                                  |
