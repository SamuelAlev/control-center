Το `cc_server` φιλοξενεί ένα μητρώο εργαλείων MCP (JSON-RPC 2.0), που εξυπηρετείται στην κύρια θύρα του διακομιστή (προεπιλογή `9030`) στα `POST /mcp` και `GET /sse`, με έκδοση πρωτοκόλλου `2024-11-05`. Κάθε πελάτης φτάνει στο ίδιο μητρώο: η εφαρμογή για υπολογιστή, η έκδοση για web, οι εξωτερικοί πελάτες MCP και ο ενσωματωμένος runtime πράκτορα. Οι εξωτερικοί διακομιστές MCP γεφυρώνονται στο ίδιο μητρώο στα δικά τους επίπεδα: ένα για κάθε χώρο εργασίας, για τους διακομιστές που ρυθμίζουν οι διαχειριστές του, και ένα για τους δικούς διακομιστές κάθε μέλους σε αυτόν. Αυτό το τελικό σημείο τους απαριθμεί, τους καλεί και τους αναζητά μόνο για μια εκτέλεση πράκτορα: τους διακομιστές του ίδιου χώρου εργασίας και τους δικούς διακομιστές του μέλους που ξεκίνησε την εκτέλεση. Το token MCP και οι συζευγμένες συσκευές δεν τους βλέπουν ποτέ (βλ. [Οι διακομιστές MCP που χρησιμοποιούν οι πράκτορές σας](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/διακομιστής-mcp/#οι-διακομιστές-mcp-που-χρησιμοποιούν-οι-πράκτορές-σας)).

## Μέγεθος μητρώου

| Μέτρηση                                                                                              | Πλήθος |
| ---------------------------------------------------------------------------------------------------- | ------ |
| Εργαλεία που καταχωρίζει το `cc_server`                                                              | 116    |
| Από το `packages/cc_mcp`                                                                             | 114    |
| Από το `packages/cc_mcp_client` (ανακάλυψη εργαλείων)                                                | 2      |
| Καταχωρισμένα στο βασικό μητρώο (`server_mcp_registry.dart`)                                         | 64     |
| Καταχωρισμένα μετά την εκκίνηση, καθώς ενεργοποιούνται οι υπηρεσίες τους (`cc_server_runtime.dart`)  | 52     |
| Από τα 64 του βασικού μητρώου, υπό συνθήκη ύπαρξης αποθετηρίου γραφήματος κώδικα                     | 5      |
| Από τα 64 του βασικού μητρώου, υπό την προϋπόθεση του runner λειτουργίας κώδικα (`repl`) | 1 |

Τα πέντε εργαλεία γραφήματος κώδικα καταχωρίζονται μόνο όταν ο ξενιστής περνά αποθετήριο γραφήματος κώδικα στο `buildServerMcpRegistry`, και το `repl` μόνο όταν περνά τον runner λειτουργίας κώδικα. Το `cc_server` περνά πάντα και τα δύο (δεν ξεκινά χωρίς τον runner), οπότε και τα 111 είναι καταχωρισμένα στο δυαδικό που διανέμεται· ο δημόσιος διακομιστής επίδειξης δεν καταχωρίζει `repl`.

Το πλήρες μητρώο ανακοινώνεται στο `tools/list` χωρίς φραγή ανακάλυψης, εκτός από μια εκτέλεση πράκτορα που μπορεί να εκτελέσει σενάρια (παρακάτω). Οι επεξεργασίες εισιτηρίων είναι τυποποιημένα εργαλεία.

:::note[Οι εξωτερικοί πελάτες βλέπουν πάντα ολόκληρο τον κατάλογο]
Το `tools/list` δεν περικόπτεται ποτέ, εκτός από τους δικούς διακομιστές MCP των μελών, τους οποίους περιλαμβάνει μόνο για εκτέλεση που ξεκίνησε ο κάτοχός τους, και [λειτουργία κώδικα](/el-GR/εγχειρίδιο/έννοιες/λειτουργία-κώδικα/): το `repl` περιλαμβάνεται μόνο σε εκτέλεση πράκτορα σε διακομιστή που μπορεί να εκτελέσει σενάρια, και αυτή η εκτέλεση παίρνει στη λίστα το `repl`, τα άμεσα εργαλεία (`read`, `write`, `edit`, `search`, `find`, `bash`, `read_output`, `ask_user`, `task`, `todo_write`, `search_memory`, `send_message` και τα δικά της ρήματα εξόδου της λειτουργίας, όπου υπάρχουν στο μητρώο) και τα εργαλεία που δεν μπορεί να καλέσει ένα σενάριο. Τα υπόλοιπα τα καλεί από σενάριο· μια άμεση κλήση σε ένα από αυτά απαντάται με τον τρόπο κλήσης του από το `repl`. Οι πελάτες MCP επικυρώνουν τα ονόματα εργαλείων με βάση το δικό τους αντίγραφο αυτής της λίστας στην προσωρινή μνήμη και απορρίπτουν καθετί που δεν περιλαμβάνεται χωρίς να ρωτήσουν τον διακομιστή, οπότε ένα εργαλείο κρυμμένο εκεί είναι απρόσιτο και όχι απλώς αθόρυβο.

Ο **ενσωματωμένος μηχανισμός** είναι διαφορετικός: φορτώνει μόνο ένα μικρό άμεσο σύνολο ορισμών ανά αίτημα και φτάνει στα υπόλοιπα από σενάρια ή τα φορτώνει στην πρώτη χρήση, πράγμα που είναι συμπεριφορά της πλευράς του μηχανισμού και δεν αλλάζει αυτό το μητρώο. Δείτε [Πλαίσιο εργαλείων και προσωρινή αποθήκευση προτροπών](/el-GR/εγχειρίδιο/έννοιες/πλαίσιο-εργαλείων/).
:::

:::note[Κάθε κλάση εργαλείου καταχωρίζεται]
Ένα αρχείο πηγαίου κώδικα στο `packages/cc_mcp/lib/src/tools/` είναι ένα εργαλείο που
μπορεί να καλέσει ένας πράκτορας. Το `packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart`
σπάει το build αν μια νέα κλάση εργαλείου δεν κατασκευάζεται από τίποτα.
:::

## Κοινές παράμετροι

### `workspace_id`

**Απαιτείται** σε κάθε εργαλείο που αγγίζει δεδομένα εμβέλειας χώρου εργασίας. Ένα απόν ή μη έγκυρο `workspace_id` επιστρέφει ρητό σφάλμα, και μια τιμή που δεν ταιριάζει με τον χώρο εργασίας της οντότητας-στόχου απορρίπτεται αντί να αγνοηθεί σιωπηλά. Παραλείψτε το στα πραγματικά καθολικά εργαλεία: το `list_workspaces` και τα έξι εργαλεία ροής ειδήσεων (`list_feeds`, `list_articles`, `get_article`, `set_article_read`, `set_article_saved`, `refresh_feeds`), που βασίζονται στη λίστα ροών ανά χρήστη του ιδιοκτήτη του διακομιστή. Τα εργαλεία ανακάλυψης (`search_tool_bm25`, `list_my_tools`) το παίρνουν προαιρετικά, ώστε να μπορούν να χαρακτηρίσουν τη δυνατότητα κλήσης ανά λειτουργία συνομιλίας. Όταν ο διακομιστής αποστέλλει έναν πράκτορα, ο χώρος εργασίας επιβάλλεται στην πλευρά του διακομιστή, οπότε ο πράκτορας δεν μπορεί να φτάσει σε άλλον χώρο εργασίας περνώντας ένα ξένο id.

## Ανακάλυψη εργαλείων

Και τα δύο προέρχονται από το `cc_mcp_client`, όχι από το `cc_mcp`, και και τα δύο συμβουλεύονται τον φύλακα λειτουργίας, ώστε να αναφέρουν τι είναι καλούμενο στην _τρέχουσα_ λειτουργία συνομιλίας.

| Εργαλείο           | Περιγραφή                                                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| `search_tool_bm25` | Αναζητά στον κατάλογο εργαλείων με λέξη-κλειδί· επιστρέφει τα εργαλεία που ταιριάζουν, τα σχήματα ορισμάτων τους και αν το καθένα είναι καλούμενο αυτή τη στιγμή |
| `list_my_tools`    | Παραθέτει τα εργαλεία που είναι καλούμενα αυτή τη στιγμή σε αυτή τη συνομιλία, φιλτραρισμένα κατά τη λειτουργία της                    |

Ένα τρίτο εργαλείο ανακάλυψης, το **`search_tools`**, υπάρχει μόνο μέσα στον ενσωματωμένο μηχανισμό και δεν αποτελεί μέρος αυτού του μητρώου MCP. Κατατάσσει την επιφάνεια εργαλείων της ίδιας της εκτέλεσης και, σε αντίθεση με το `search_tool_bm25`, **φορτώνει** τα σχήματα όσων βρίσκει, ώστε ο πράκτορας να μπορεί να καλέσει ένα ταίριασμα στην επόμενη στροφή του. Οι πράκτορες στον μηχανισμό καλό είναι να το προτιμούν· οι πελάτες MCP έχουν το `search_tool_bm25`.

## Λειτουργία κώδικα

| Εργαλείο | Περιγραφή |
| ------ | ----------- |
| `repl` | Εκτελεί ένα σενάριο JavaScript που καλεί τα άλλα εργαλεία της εκτέλεσης ως `tools.<id>(args)` και επιστρέφει μόνο ό,τι χρειάζεται. Καταχωρίζεται μόνο σε εκτέλεση πράκτορα σε διακομιστή που μπορεί να εκτελέσει σενάρια [λειτουργίας κώδικα](/el-GR/εγχειρίδιο/έννοιες/λειτουργία-κώδικα/). Κάθε εμφωλευμένη κλήση περνά από την ίδια πύλη με ένα `tools/call`. Δέχεται `code`, `description`, `timeout_ms?`, `max_output_tokens?`  |

Ένα σενάριο δεν μπορεί να καλέσει τα `repl`, `search_tool_bm25`, `list_my_tools` ή οποιοδήποτε εργαλείο που ξεκινά ή στέλνει μήνυμα σε άλλη εκτέλεση πράκτορα, αναθέτει ή σχολιάζει ένα εισιτήριο, στέλνει μήνυμα, δημιουργεί, αποφασίζει ή σχολιάζει μια έγκριση, προτείνει ή αλλάζει πολιτική, εγκαθιστά ή αλλάζει δεξιότητες, δημιουργεί ένα προφίλ χρόνου εκτέλεσης, υποβάλλει ένα σχέδιο ή βγαίνει από τη λειτουργία σχεδίου, ολοκληρώνει τον στόχο της συνομιλίας ή υποβάλλει την έξοδο μιας εκτέλεσης pipeline. Αυτά τα εργαλεία δηλώνουν το `scriptCallable` ως false και καλούνται πάντα άμεσα· στον ενσωματωμένο μηχανισμό ένα από αυτά που είναι έξω από το άμεσο σύνολο φορτώνεται στην πρώτη χρήση. Το `create_ticket` είναι κλητό από σενάριο μόνο χωρίς `assignee`.

## Ανταλλαγή μηνυμάτων και ανάθεση μεταξύ ομότιμων πρακτόρων

Οι πράκτορες μιλούν μεταξύ τους μέσω χώρων (μόνιμα, ορατά στον κατάλογο παρουσίας). Το `ask_agent` είτε περιμένει την απάντηση (`mode: wait`, 600 δευτερόλεπτα από προεπιλογή, το πολύ 1.800) είτε επιστρέφει αμέσως (`mode: background`)· και στις δύο περιπτώσεις ο ερωτών ξυπνά μία φορά με την απάντηση, όταν αυτή δεν επέστρεψε μέσα στην ίδια κλήση. Τα `send_to_agent`, `ask_agent`, `consult_agent`, `request_peer_review` και `delegate_task` περνούν από την ίδια πύλη στον διακομιστή: βάθος (3), ανίχνευση κύκλων, φάκελο προϋπολογισμού, ανώτατο όριο αυτονομίας και όριο ρυθμού ανά ζεύγος πρακτόρων. Η ταυτότητα του αποστολέα προέρχεται πάντα από την εκτέλεση που κάνει την κλήση. Δείτε [Συνεργασία πρακτόρων](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/συνεργασία-πρακτόρων/).

| Εργαλείο        | Περιγραφή                                                                                     |
| --------------- | --------------------------------------------------------------------------------------------- |
| `send_to_agent` | Στέλνει μονόδρομο μήνυμα σε άλλον πράκτορα, με διεύθυνση μέσω `to_agent_id` ή ακριβούς `to_agent_name`· απαντά με `delivery_status` `woken`, `queued_behind_run` ή `refused` |
| `ask_agent`     | Κάνει ερώτηση σε άλλον πράκτορα· περιμένει την απάντηση ή συνεχίζει και ξυπνά όταν αυτή φτάσει |
| `delegate_task` | Αναθέτει μια εργασία σε άλλον πράκτορα ως παρακολουθούμενο θυγατρικό εισιτήριο                  |
| `consult_agent` | Προσθέτει στον χώρο τον ειδικό που ταιριάζει καλύτερα με βάση τις δεξιότητες και τον αποστέλλει με μια εστιασμένη οδηγία |
| `todo_read`     | Διαβάζει την αποθηκευμένη λίστα ελέγχου εργασιών αυτής της συνομιλίας                            |
| `agent_activity` | Διαβάζει τι κάνει τώρα ένας άλλος πράκτορας και τι έκανε τελευταία (κατάσταση, τρέχον εργαλείο, τελευταία μηνύματα), χωρίς να τον ξυπνά. |

## Εργαλεία αφύπνισης και στόχων

Ένας πράκτορας τα χρησιμοποιεί αντί να κοιμάται ή να κάνει polling. Το καθένα ενεργεί μόνο για τον πράκτορα που κάνει την κλήση, στη δική του συνομιλία· ο πράκτορας δεν είναι ποτέ όρισμα. Δείτε [Χρονοδιαγράμματα και αφυπνίσεις](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/χρονοδιαγράμματα-αφυπνίσεις/) και [Επιδίωξη στόχου](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/επιδίωξη-στόχου/).

| Εργαλείο | Περιγραφή |
| ------------- | ----------- |
| `wake_me` | Ρυθμίζει να ξυπνήσει αργότερα: σε μια ώρα (`in:20m`, `at:<ISO time>`), σε διάστημα (`every:30m`), σε cron (`cron:0 9 * * 1-5`, με `tz`), με τον δικό του ρυθμό μέσα σε έναν αυτορυθμιζόμενο βρόχο (`next`, με `delay` από 1 έως 60 λεπτά), ή όταν συμβαίνει κάτι (`on:pr_checks`, `on:pr_review`, `on:pr_merged`, `on:environment`, `on:ticket:<id>`, `on:pipeline_run:<id>`). Προαιρετικά `note`, `max_runs`, `expires_in`, `when_busy` (`skip` ή `queue`) και `deliver` (`run` ή `notify`) |
| `list_wakes` | Καταγράφει όσα έχει ο πράκτορας σε αναμονή σε αυτή τη συνομιλία: χρονοδιαγράμματα, παρακολουθήσεις, αναμενόμενες αφυπνίσεις και αναπάντητες ερωτήσεις |
| `cancel_wake` | Ακυρώνει ένα χρονοδιάγραμμα ή μια παρακολούθηση που όρισε ο ίδιος ο πράκτορας, με το id του |
| `goal_status` | Διαβάζει τον ενεργό στόχο του πράκτορα: συμβόλαιο, τμήμα, δαπάνη και προϋπολογισμός που απομένει, προειδοποιήσεις έλλειψης προόδου, αναμονή, τελευταία επαλήθευση και εκκρεμείς αφυπνίσεις στόχου |

Το `complete_goal` (στο [Εργαλεία σχεδίου, playbook και τεχνουργημάτων](#εργαλεία-σχεδίου-playbook-και-τεχνουργημάτων)) είναι ο μόνος τρόπος με τον οποίο ένας πράκτορας δηλώνει ότι ένας στόχος έχει ολοκληρωθεί, και είναι ισχυρισμός, όχι ολοκλήρωση.

## Εργαλεία δεξιοτήτων

Κάθε εγκατάσταση και ενημέρωση περνά από πύλη σάρωσης με ασφαλή αποτυχία προτού φτάσει οποιοδήποτε περιεχόμενο δεξιότητας στον δίσκο ή σε προτροπή πράκτορα.

| Εργαλείο             | Περιγραφή                                                                     |
| -------------------- | ----------------------------------------------------------------------------- |
| `list_skills`        | Παραθέτει τα slugs των δεξιοτήτων που είναι διαθέσιμα σε έναν χώρο εργασίας    |
| `create_skill`       | Δημιουργεί νέα δεξιότητα από περιεχόμενο markdown                              |
| `install_skill`      | Εγκαθιστά ολόκληρο τον κατάλογο μιας δεξιότητας από αποθετήριο GitHub σε καρφιτσωμένη αναφορά |
| `update_skill`       | Ενημερώνει μια εγκατεστημένη δεξιότητα GitHub σε νέα αναφορά, με νέα σάρωση και νέο καρφίτσωμα |
| `list_skill_updates` | Παραθέτει τις δεξιότητες για τις οποίες υπάρχει νεότερη έκδοση                  |
| `verify_skills`      | Επαληθεύει τις κλειδωμένες δεξιότητες ως προς τους κατακερματισμούς περιεχομένου τους στον δίσκο |
| `pin_skill`          | Κατακερματίζει μια υπάρχουσα δεξιότητα στον δίσκο στο `skills-lock.json`        |

## Εργαλεία περιβλήματος (σταθμών)

Οδηγήστε αναλώσιμες μηχανές — ένα περίκλειστο πρόγραμμα περιήγησης ή επιφάνεια
εργασίας Linux, έναν εξομοιωτή Android ή έναν Προσομοιωτή iOS — μέσα από μια
εκτέλεση. Καταχωρίζονται μετά την εκκίνηση, άνευ όρων: το αν μια μηχανή μπορεί
όντος να εκκινήσει είναι ερώτημα ανίχνευσης που τα εργαλεία απαντούν ανά κλήση.
Επαναλαμβανόμενες κλήσεις σε μία συνομιλία επαναχρησιμοποιούν μία μηχανή· τα
στιγμιότυπα οθόνης επιστρέφουν ως περιεχόμενο εικόνας με προϋπολογισμό μίας
εικόνας ανά αποτέλεσμα, και το εξαγόμενο περιεχόμενο σελίδας/UI περιφράσσεται ως
μη αξιόπιστα δεδομένα. Τα τέσσερα εργαλεία χρήσης συν το `rig_close` δηλώνουν το
`enclosureControl` ως [κλάση ενεργειών](/el-GR/εγχειρίδιο/έννοιες/περιορισμοί/)
(τα εργαλεία χρήσης δηλώνουν επίσης `networkEgress` και `processSpawn`· τα
`mobile_use` και `ios_use` δηλώνουν επίσης `packageInstall`), οπότε οι λειτουργίες
μόνο για ανάγνωση τα αρνούνται. Το `rig_list` δεν δηλώνει καμία — διαβάζει μόνο
την κατάσταση του χώρου εργασίας. Το πλήρες λεξιλόγιο ρημάτων ανά επιφάνεια
βρίσκεται στην [αναφορά σταθμών](/el-GR/εγχειρίδιο/αναφορά/σταθμοί/#ρήματα-ενεργειών).

| Εργαλείο       | Περιγραφή                                                                                       |
| -------------- | ----------------------------------------------------------------------------------------------- |
| `computer_use` | Οδηγεί μια επιφάνεια εργασίας Linux σε περίκλειστη VM: μετακίνηση, κλικ, σύρσιμο, κύλιση, πληκτρολόγηση, αλλαγή μεγέθους, πρόχειρο, στιγμιότυπο οθόνης |
| `browser_use`  | Οδηγεί ένα headless Chromium, Firefox ή WebKit (`engine`): πλοήγηση, κλικ, συμπλήρωση, εξαγωγή (a11y/DOM/κονσόλα), πρόχειρο, στιγμιότυπο οθόνης |
| `mobile_use`   | Οδηγεί το Android μέσω ADB: επιθεώρηση/είσοδος, στιγμιότυπα οθόνης, εγκατάσταση/εκκίνηση/διακοπή/επαναφορά/απεγκατάσταση εφαρμογών, βαθείς σύνδεσμοι και εντολές συσκευής σε μορφή argv |
| `ios_use`      | Οδηγεί τον Προσομοιωτή iOS μέσω WebDriverAgent/CoreSimulator: επιθεώρηση/είσοδος, στιγμιότυπα οθόνης, εγκατάσταση/εκκίνηση/διακοπή/απεγκατάσταση εφαρμογών, βαθείς σύνδεσμοι και διεργασίες προσομοιωτή σε μορφή argv |
| `rig_list`     | Παραθέτει τους σταθμούς του χώρου της εκτέλεσης με επιφάνεια, κατάσταση, μέγεθος οθόνης και ελεγκτή |
| `rig_close`    | Καταστρέφει έναν σταθμό και απορρίπτει την κατάσταση της μηχανής που του ανήκει                  |

Μόνο οι εκτελέσεις πρακτόρων μπορούν να καλούν αυτά τα εργαλεία· κάθε άλλος καλών αρνείται. Μια εκτέλεση φτάνει μόνο στους σταθμούς του χώρου για τον οποίο μισθώθηκε: το `space_id` προέρχεται από τη χορήγηση της εκτέλεσης, ποτέ από την κλήση, και ένας σταθμός άλλου χώρου, ή χωρίς χώρο, απαντά ακριβώς όπως ένας ανύπαρκτος.

Το `app_use` είναι ένα πέμπτο εργαλείο use: χειρίζεται τα παράθυρα εφαρμογής επιφάνειας εργασίας που εκκινήθηκε σε χώρο, απευθείας στον κεντρικό υπολογιστή και όχι σε VM, και δηλώνει επίσης `fileWriteOutsideWorktree` και `fileDelete`. Αυτό και τα εργαλεία `environment_*` περιγράφονται στη [Ρύθμιση περιβαλλόντων](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/περιβάλλοντα/).

## Όσα δεν εκτίθενται μέσω MCP

Το ημερολόγιο και οι συσκέψεις δεν έχουν εργαλεία MCP. Οι πράκτορες δεν μπορούν να διαβάσουν το ημερολόγιό σας, τις συσκέψεις, τις απομαγνητοφωνήσεις, τα στοιχεία ενέργειας ή τις αποφάσεις σας. Η σύνοψη που παράγει στοιχεία ενέργειας και αποφάσεις εκτελείται ως το ενσωματωμένο [pipeline `meeting_summary`](/el-GR/εγχειρίδιο/έννοιες/συσκέψεις/), όχι ως εργαλείο που μπορεί να καλέσει ένας πράκτορας.

## Περιορισμός εργαλείων ανά λειτουργία

Ο περιορισμός επιβάλλεται δύο φορές από έναν πίνακα (`ModeToolPolicy`): μία στον αποστολέα MCP για τον προσαρμογέα Claude Code και μία στο μητρώο του ενσωματωμένου μηχανισμού. Μια αποκλεισμένη κλήση επιστρέφει τον λόγο.

| Λειτουργία    | Επιφάνεια εργαλείων                                                                                                                                                                                                                    |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`        | Κάθε καταχωρισμένο εργαλείο· χωρίς λίστα επιτρεπόμενων                                                                                                                                                                                  |
| `plan`        | Μια επιμελημένη λίστα επιτρεπόμενων. Χωρίς εγγραφές στο worktree και χωρίς τα ρήματα εισιτηρίων `create` / `assign` / `delegate`, αλλά επιτρέπονται η μνήμη, τα τεχνουργήματα, οι λίστες εργασιών, το `submit_plan`, το `exit_plan_mode` και τα ρήματα ολοκλήρωσης εισιτηρίου στο εισιτήριο που έχει αποσταλεί |
| `review`      | Μια επιμελημένη λίστα επιτρεπόμενων: συμμετοχή σε έλεγχο, επικοινωνία, ανακτήσεις πλαισίου μόνο για ανάγνωση και το πλήρες σύνολο ρημάτων εισιτηρίων, συμπεριλαμβανομένων των `create_ticket` και `assign_ticket`                         |
| `orchestrate` | Μια επιμελημένη λίστα επιτρεπόμενων: εργαλεία έρευνας και ανάγνωσης συν τα `propose_orchestration`, `create_playbook` και `run_playbook`. Η πρόσληψη, η αποσύνθεση και η ολοκλήρωση εισιτηρίων συμβαίνουν ντετερμινιστικά μετά την έγκριση, ποτέ στη μέση της εκτέλεσης |

Επιτρέπονται σε κάθε λειτουργία ανεξάρτητα από τη λίστα επιτρεπόμενων:

| Σύνολο                  | Εργαλεία                                                                                                                                                                                                                                                          |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Μνήμη και τεχνουργήματα | `search_memory`, `propose_fact`, `propose_policy`, `supersede_fact`, `supersede_policy`, `record_observation`, `update_my_notes`, `get_my_notes`, `list_memory_domains`, `list_policies`, `publish_artifact`, `revise_artifact`, `list_artifacts`, `get_artifact` |

Το να βρίσκεται ένα εργαλείο σε λίστα επιτρεπόμενων δεν το κάνει καλούμενο, και ισχύει και το αντίστροφο: η δυνατότητα υποβολής ερώτησης στον χειριστή είναι εργαλείο του **μηχανισμού** (`ask_user`), οπότε δεν εμφανίζεται καθόλου σε αυτόν τον κατάλογο MCP.

## Εργαλεία με πύλη έγκρισης

Ένα εργαλείο μπορεί να δηλώνει `requiresApproval`. Τότε ο αποστολέας χτίζει ένα `ApprovalPayload` και το προβάλλει μέσω του `ConfirmationPort` πριν εκτελεστεί το εργαλείο· το `cc_server` συνδέει αυτή τη θύρα, οπότε η πύλη είναι ενεργή.

Τα καταχωρισμένα εργαλεία που το δηλώνουν: `create_ticket`, `update_ticket`, `assign_ticket`, `reassign_ticket`, `close_ticket`, `ticket_relation`, `create_goal`, `update_goal_progress`, `create_approval`, `decide_approval`, `comment_approval`, `create_work_product`, `save_work_product_revision`, `create_runtime_profile`, `install_skill`, `update_skill`.

Ανεξάρτητα, οι ενοποιημένοι περιορισμοί ενεργειών βάζουν σε πύλη κάθε εργαλείο που δηλώνει μη κενό σύνολο `ActionClass`. Μια απόφαση `prompt` χωρίς συνδεδεμένο εγκρίνοντα απορρίπτεται. Δείτε [Περιορισμοί](/el-GR/εγχειρίδιο/έννοιες/περιορισμοί/).

## Δυνατότητες χωρίς εργαλείο πίσω τους

Δεν είναι κάθε δυνατότητα του προϊόντος προσβάσιμη από πράκτορα. Αυτές δεν έχουν
καθόλου εργαλείο, οπότε ένα όνομα που ίσως έχετε δει να αναφέρεται αλλού
επιστρέφει «άγνωστο εργαλείο»:

| Δυνατότητα                                | Πού ζει αντ' αυτού                                                                                                |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Πρόσληψη, απόλυση ή επεξεργασία πράκτορα  | Το UI των πρακτόρων. Δεν υπάρχει εργαλείο `hire_agent` / `fire_agent` / `update_agent`                            |
| Δημιουργία χώρου εργασίας                 | `workspace.create` μέσω RPC, μόνο για τον κάτοχο του διακομιστή, που αρχικοποιεί και σφραγίζει την κυριότητα        |
| Έργα (δημιουργία / λίστα / ενημέρωση / καταχώριση) | Το UI των εισιτηρίων. Τα έργα είναι επιφάνεια χειριστή — δείτε [Οργάνωση εργασίας με έργα](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/έργα/) |
| Υποβολή αποκλειστικής ερώτησης στον χειριστή | Το εργαλείο `ask_user` του **μηχανισμού**, όχι το MCP. Αποδίδει μια φόρμα στη συνομιλία και μπλοκάρει μέχρι την απάντηση |
| Διαγνωστικά ανά πράκτορα                  | Τίποτα. Δεν υπάρχει `doctor` — δείτε [Διάγνωση πράκτορα](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/διάγνωση-πράκτορα/)      |
| Ημερολόγιο και συσκέψεις                  | RPC μόνο για ανθρώπινους πελάτες (δείτε παραπάνω)                                                                  |
