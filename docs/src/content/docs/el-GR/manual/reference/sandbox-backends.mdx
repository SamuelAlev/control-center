:::caution[Το αν μια εκτέλεση είναι μέσα σε sandbox εξαρτάται από τον κεντρικό υπολογιστή]
Το `cc_server` αποφασίζει μία φορά κατά την εκκίνηση πώς εκτελούνται οι πράκτορες σε αυτόν τον κεντρικό υπολογιστή, και η απόφαση ισχύει έως την επανεκκίνησή του:

- **Σε sandbox** (`native`): η ανίχνευση βρήκε backend και το `--sandbox` δεν είναι `off`. Και οι δύο αρμοί της αποστολής περιτυλίγονται: το CLI του Claude Code μέσω της θύρας sandbox, και το ACP μαζί με το εργαλείο `bash` του ενσωματωμένου harness μέσω του διαχειριστή sandbox.
- **Απενεργοποιημένο** (`off`): ο κάτοχος του διακομιστή τον ξεκίνησε με `--sandbox off`. Κάθε εκτέλεση πράκτορα όλων των μελών τρέχει χωρίς περιορισμούς σε αυτόν τον κεντρικό υπολογιστή, όποιος κι αν την ξεκίνησε.
- **Μη διαθέσιμο** (`unavailable`): το sandbox είναι ενεργό, αλλά η ανίχνευση δεν βρήκε backend (**πάντα στα Windows**, και σε Linux ή WSL2 χωρίς `bwrap` και `socat`). Μια εκτέλεση ξεκινά μόνο όταν το άτομο που ευθύνεται γι' αυτήν είναι ο [κάτοχος](/el-GR/εγχειρίδιο/έννοιες/εξουσιοδότηση/#ο-κάτοχος-του-διακομιστή) του διακομιστή: όποιος ζήτησε την εκτέλεση, ή, για αυτοματοποίηση, το άτομο στο οποίο είναι δεμένη. Η εκτέλεση οποιουδήποτε άλλου απορρίπτεται πριν εκδοθεί διαπιστευτήριο, πριν ληφθεί μίσθωση ή πριν ξεκινήσει διεργασία. Αν δεν έχει καταγραφεί κάτοχος, καμία εκτέλεση δεν ξεκινά.

Μια εκτέλεση που απορρίπτεται αποτυγχάνει με τον κωδικό `sandbox_unavailable`. Η εφαρμογή το εμφανίζει ως **Οι πράκτορες χρειάζονται sandbox σε αυτόν τον διακομιστή**: «Αυτός ο διακομιστής δεν έχει sandbox, γι' αυτό μόνο ο κάτοχός του μπορεί να εκτελεί εδώ πράκτορες. Ο κάτοχος μπορεί να εγκαταστήσει το sandbox ή να απενεργοποιήσει την απομόνωση για όλους.»

Μια εκτέλεση που ξεκινά χωρίς sandbox (υπό `off`, ή η εκτέλεση του κατόχου υπό `unavailable`) τρέχει απευθείας στον κεντρικό υπολογιστή. Το ACP και το εργαλείο `bash` του harness εκκινούν ακόμη με καθαρισμό περιβάλλοντος· το Claude Code περνά από το `NoSandboxAdapter` και κληρονομεί το περιβάλλον του κεντρικού υπολογιστή. Τα υπόλοιπα όρια είναι το ίδιο το worktree της εκτέλεσης (copy-on-write όπου διατίθεται το `rift`· `git worktree` στα Windows), ένα token φιλοξενίας κώδικα μόνο για ανάγνωση, που μεσιτεύεται ανά εκκίνηση και ανακαλείται στον τερματισμό, τα push που πρέπει να περάσουν τον κανόνα push στην πύλη εκτελέσεων πρακτόρων, η πολιτική εντολών ανά λειτουργία, οι ενοποιημένοι [περιορισμοί ενεργειών](/el-GR/εγχειρίδιο/έννοιες/περιορισμοί/) (αποτυγχάνουν κλειστά), ο καθαρισμός περιβάλλοντος στις διαδρομές του ACP και του `bash` του harness, και η επιφάνεια εργαλείων που επιτρέπει η λειτουργία του.

Τα εργαλεία αρχείων εντός διεργασίας του harness (read, write, edit, apply patch, search, find, search_files) βρίσκονται έξω από το sandbox σε κάθε κεντρικό υπολογιστή: εκτελούνται στη διεργασία του διακομιστή, οπότε μόνο το `bash` περιτυλίγεται.

Ο κεντρικός υπολογιστής δεν είναι ποτέ εφεδρική λύση για διακομιστή με sandbox. Αν ο διακομιστής απομονώνει τους πράκτορες αλλά δεν έχει sandbox να δώσει σε μια εκτέλεση, οι διεργασίες εργαλείων και οι εντολές `bash` της απορρίπτονται, δεν ξεκινούν στον κεντρικό υπολογιστή. Η ίδια στάση αποφασίζει και για τις μικρές διεργασίες γύρω από μια εκτέλεση: τα βοηθητικά ACP μιας χρήσης (τίτλοι συνομιλιών, `/btw`, `/handoff`, `/goal`) και τα golden tests ενός pull request στο Review Studio τρέχουν μέσα στο sandbox όταν ο διακομιστής απομονώνει τους πράκτορες, χωρίς περιορισμούς υπό `off`, και υπό `unavailable` μόνο για αίτημα για το οποίο ευθύνεται ο κάτοχος του διακομιστή· αλλιώς παραλείπονται.
:::

## Επισκόπηση των backend

| Backend          | Τιμή      | Πλατφόρμα                                    | Διαθεσιμότητα                                                                                                                    |
| ---------------- | --------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Απομονωμένο VM   | `microvm` | macOS, Linux, Windows (υπερεπόπτης microVM)  | Εξαρτάται από ανίχνευση στον χρόνο εκτέλεσης microVM· εφαρμόζεται σε διαδραστικά τερματικά — το κέλυφος εκτελείται μέσα σε έναν [σταθμό](/el-GR/εγχειρίδιο/έννοιες/σταθμοί/), όχι στον κεντρικό υπολογιστή |
| Εγγενές sandbox  | `native`  | macOS (Seatbelt), Linux και WSL2 (bubblewrap) | Ανιχνεύεται κατά την εκκίνηση· το Linux αρνείται μια εκτέλεση που απαιτεί απορρίψεις εγγραφής με glob ονόματος αρχείου, τις οποίες το bubblewrap δεν μπορεί να επιβάλει |
| Χωρίς απομόνωση  | `none`    | Όλες                                         | Η προεπιλογή της ανάλυσης και η προεπιλογή του τερματικού· η αποστολή πρακτόρων το χρησιμοποιεί υπό `--sandbox off`, και για τις εκτελέσεις του κατόχου όταν δεν υπάρχει διαθέσιμο backend |

Το `SandboxBackend.fromName` επιστρέφει `none` για αποθηκευμένη τιμή null ή μη αναγνωρίσιμη.

**Το `microvm` είναι το μόνο backend με όριο πυρήνα** — το φορτίο εργασίας
πραγματικά δεν εκτελείται στον κεντρικό υπολογιστή. Δεν αποτελεί ποτέ σιωπηλή
εφεδρική λύση προς καμία κατεύθυνση: η ρητή αίτησή του σε έναν κεντρικό
υπολογιστή που δεν μπορεί να εκκινήσει VM αποτυγχάνει με θόρυβο («ζήτησα VM και
πήρα το λάπτοπ μου» είναι η μία υποβάθμιση που το περίβλημα δεν μπορεί να
αντέξει), και μόνο μια *μη καθορισμένη προεπιλογή* υποχωρεί στο `native`, με μια
γραμμή καταγραφής να το δηλώνει. Το πραγματικό backend της συνεδρίας
αναφέρεται πίσω στον πελάτη και επισημαίνεται με ένδειξη, ώστε ένα τερματικό να
μην μπορεί ποτέ να ισχυριστεί ότι είναι περίκλειστο ενώ εκτελείται στον κεντρικό
υπολογιστή. Ο κύκλος ζωής, οι εικόνες και η εξερχόμενη κίνηση του ίδιου του VM
καλύπτονται από την [αναφορά σταθμών](/el-GR/εγχειρίδιο/αναφορά/σταθμοί/).

**Τα Windows δεν έχουν εγγενές sandbox.** Το `NativeSandboxAdapter.probe` επιστρέφει `available: false` σε κάθε κεντρικό υπολογιστή που δεν είναι macOS ή Linux/WSL2. Ένας διακομιστής των Windows είναι επομένως `unavailable`: ξεκινούν μόνο οι εκτελέσεις πρακτόρων του κατόχου του διακομιστή, χωρίς περιορισμούς, και όλες οι υπόλοιπες απορρίπτονται. Για να μπορεί κάθε μέλος να εκτελεί πράκτορες εκεί, ο κάτοχος ξεκινά τον διακομιστή με `--sandbox off`, που εκτελεί όλες τις εκτελέσεις χωρίς περιορισμούς. Το backend `microvm` είναι ξεχωριστό: εξαρτάται από ανίχνευση στον χρόνο εκτέλεσης microVM και εφαρμόζεται σε διαδραστικά τερματικά και σταθμούς, όχι στο περιτύλιγμα του `bash` στον κεντρικό υπολογιστή.

## Αποτελέσματα ανίχνευσης

Η ανίχνευση είναι η πύλη της επιβολής. Εκτελείται μία φορά, στην εκκίνηση του διακομιστή.

| Κεντρικός υπολογιστής                   | `available` | Σημείωση / υπόδειξη                                                        |
| --------------------------------------- | ----------- | -------------------------------------------------------------------------- |
| macOS                                   | `true`      | `sandbox-exec` (Seatbelt) — απομόνωση namespace, χωρίς όριο πυρήνα          |
| Linux ή WSL2 με `bwrap` και `socat`     | `true`      | bubblewrap — απομόνωση namespace, χωρίς όριο πυρήνα                         |
| Linux ή WSL2 χωρίς ένα από τα δύο εργαλεία | `false`  | `requiresInstall: true`, με υπόδειξη εγκατάστασης που ονομάζει τα πακέτα που λείπουν |
| Οποιαδήποτε άλλη πλατφόρμα              | `false`     | Το εγγενές sandbox δεν προσφέρεται σε αυτή την πλατφόρμα                    |

Ο διακομιστής καταγράφει το αποτέλεσμα σε μία γραμμή εκκίνησης: `agent sandbox ON` μαζί με τη σημείωση· `no OS-native agent sandbox on this host` μαζί με την υπόδειξη, η οποία προσθέτει ότι θα ξεκινούν μόνο οι εκτελέσεις για τις οποίες ευθύνεται ο κάτοχος του διακομιστή· ή `agent sandbox DISABLED by --sandbox off`. Η γραμμή έκθεσης που τυπώνεται στην εκκίνηση φέρει την ίδια απόφαση ως `sandbox=native`, `sandbox=off` ή `sandbox=unavailable`. Το `GET /healthz` δεν φέρει πεδίο sandbox.

Το `--sandbox` / `CC_SERVER_SANDBOX` δέχεται `on` (προεπιλογή) ή `off`. Το `on` περιτυλίγει κάθε εκτέλεση όταν ο κεντρικός υπολογιστής προσφέρει backend, και αφήνει να τρέξουν μόνο οι εκτελέσεις του κατόχου όταν δεν το προσφέρει. Το `off` εκτελεί τους πράκτορες όλων των μελών χωρίς περιορισμούς σε αυτόν τον κεντρικό υπολογιστή· είναι επιλογή του κατόχου για όλους, όχι ρύθμιση ανά εκτέλεση.

## Εγγενές backend

### macOS: Seatbelt

Χρησιμοποιεί τον μηχανισμό sandbox Seatbelt της Apple (το ίδιο σύστημα που χρησιμοποιεί το macOS App Sandbox).

Το παραγόμενο προφίλ είναι **επιτρεπτικό από προεπιλογή** (`(allow default)`) και χαράσσει εξαιρέσεις απόρριψης, επειδή ένα προφίλ που απορρίπτει τα πάντα από προεπιλογή καθιστά ένα διαδραστικό κέλυφος άχρηστο — οι κλήσεις dyld, XPC και Mach που θα έπρεπε να καταγραφούν είναι υπερβολικά πολλές. Η πρακτική συνέπεια είναι ότι ένας πράκτορας μπορεί ακόμη να διαβάσει το μεγαλύτερο μέρος του κεντρικού υπολογιστή· τα καταχωρισμένα checkouts σας προστατεύονται από ρητές απορρίψεις εγγραφής και μετονομασίας, όχι από αορατότητα.

- **Αναγνώσεις του συστήματος αρχείων**: απορρίπτονται για τις μυστικές διαδρομές (`~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.config/gh`, `~/Library/Keychains` και το υπόλοιπο σύνολο αποκλεισμού ανάγνωσης)
- **Εγγραφές στο σύστημα αρχείων**: επαναφέρονται σε απόρριψη και έπειτα δίνονται ρητές επιτρεπτικές εξαιρέσεις για υποδιαδρομές, με τις διαδρομές υποχρεωτικής απόρριψης (αρχεία rc του κελύφους, `.git/hooks`, ρυθμίσεις Claude, προστατευμένα checkouts) αποκλεισμένες ακόμη και μέσα σε εγγράψιμη ρίζα. Το `file-write-unlink` απορρίπτεται σε κάθε απορριπτόμενη διαδρομή και στους προγόνους της, ώστε μια μετονομασία να μην μπορεί να παρακάμψει μια απόρριψη εγγραφής
- **Διεργασίες**: το `process-exec` απορρίπτει τα πάντα επικίνδυνα εκτελέσιμα, συν έναν αποκλεισμό εκτέλεσης οτιδήποτε βρίσκεται σε εγγράψιμο κατάλογο. Γνωστά δέντρα εγκατάστασης εργαλείων κάτω από τον προσωπικό σας φάκελο (caches του corepack, του npx και του `pnpm dlx`, διαχειριστές εκδόσεων του Node, προγράμματα περιήγησης του Playwright, rustup και cargo, Go, fvm και η cache του pub, pyenv, uv και pipx, rbenv, sdkman, mise, asdf και το `~/.local/bin`) επανανοίγονται κάτω από αυτόν τον αποκλεισμό. Οι κοινόχρηστοι προσωρινοί κατάλογοι αποκλείονται επίσης. Κάθε συνεδρία λαμβάνει αντ' αυτού ένα ιδιωτικό `TMPDIR` κάτω από το `/private/tmp`, όπου μπορούν να τρέχουν τα προγράμματα που δημιουργεί (ένα δυαδικό `go test`, μια κατασκευή cargo). Οι απορρίψεις των πάντα επικίνδυνων εκτελέσιμων εφαρμόζονται μετά από αυτές τις επιτρέψεις
- **Δίκτυο**: περιορίζεται στις θύρες των proxy εντός διεργασίας συν το DNS — το loopback δεν επιτρέπεται καθολικά και η ακρόαση TCP απορρίπτεται. Οι υποδοχές Unix επιτρέπονται μόνο μέσα στο ιδιωτικό `TMPDIR` της συνεδρίας, το οποίο καλύπτει εργαλεία όπως το tsx και το Chrome που κρατούν εκεί ένα socket IPC· ο πράκτορας SSH σας και οι άλλες υποδοχές παραμένουν μη προσβάσιμες. Οι proxy επιβάλλουν τη λίστα επιτρεπόμενων τομέων ανά συνεδρία (δείτε την [εξερχόμενη κίνηση δικτύου](#εξερχόμενη-κίνηση-δικτύου))
- **Διαμόρφωση**: τα προφίλ παράγονται ανά εκκίνηση από το `SandboxSpec`
- **Οι εντολές του ίδιου του διακομιστή**: καμία άμεση θυγατρική ενός φακέλου από τον οποίο ο διακομιστής εκτελεί προγράμματα (κάθε καταχώριση του `PATH` και οι συνήθεις φάκελοι εργαλείων ανά χρήστη, όπως το `~/.local/bin`, με τους συνδέσμους διαχείρισης εκδόσεων όπως το `~/fvm/default` επιλυμένους) δεν μπορεί να δημιουργηθεί, αντικατασταθεί, διαγραφεί ή μετονομαστεί, ούτε το εγκατεστημένο πακέτο στο οποίο δείχνει μια συνδεδεμένη εντολή. Δείτε [Οι φάκελοι εντολών του διακομιστή](#οι-φάκελοι-εντολών-του-διακομιστή)
- **Αρχεία έναρξης**: κάθε διαδρομή του αρχικού φακέλου που το προφίλ απαγορεύει να διαβαστεί απαγορεύεται και για εγγραφή, και τα αρχεία έναρξης των κελυφών και των συνεδριών του χρήστη του διακομιστή (`.zshenv`, `.zlogin`, `.bash_login`, ρυθμίσεις fish, μονάδες χρήστη του systemd, καταχωρίσεις αυτόματης εκκίνησης και τα παρόμοια) απαγορεύονται για εγγραφή σε κάθε λειτουργία

Απαιτήσεις:

- `sandbox-exec` (`/usr/bin/sandbox-exec`), μέρος κάθε εγκατάστασης macOS — δεν απαιτούνται πρόσθετα εργαλεία

### Linux: bubblewrap

Χρησιμοποιεί το bubblewrap (`bwrap`) για να δημιουργήσει namespace προσάρτησης και PID.

- **Σύστημα αρχείων**: δημιουργεί namespace προσάρτησης όπου είναι ορατές μόνο οι προσδεμένες διαδρομές
- **Δίκτυο**: εκτελείται σε μη κοινόχρηστο namespace δικτύου· η κίνηση φτάνει στους proxy του κεντρικού υπολογιστή μέσω γεφυρών υποδοχών Unix του `socat`
- **Διεργασίες**: απομόνωση namespace PID
- **Οι εντολές του ίδιου του διακομιστή και τα αρχεία έναρξης**: ίδιες προστασίες με το macOS, εκφρασμένες ως προσδέσεις bubblewrap. Δεν έχουν επαληθευτεί ακόμη στο Linux, και ένας λείπων φάκελος εντολών εκεί μπορεί ακόμη να δημιουργηθεί

Απαιτήσεις:

- Εγκατεστημένα τα `bubblewrap` και `socat` (`sudo apt-get install bubblewrap socat` σε Debian/Ubuntu)
- Υποστήριξη namespace στον πυρήνα (στάνταρ στο σύγχρονο Linux)

Το Bubblewrap μπορεί να επισκιάσει μια υπάρχουσα διαδρομή, αλλά δεν μπορεί να
απαγορεύσει ένα *νέο* αρχείο `.env`, `*.key` ή `*.pem` μέσα σε εγγράψιμο bind. Η
τυπική πολιτική αποστολής απαιτεί αυτές τις απορρίψεις με glob ονόματος αρχείου,
οπότε η εγγενής αποστολή πρακτόρων **αποτυγχάνει κλειστά σε Linux/WSL2 ακόμη και
όταν η ανίχνευση βρίσκει το bubblewrap**. Δεν εκτελείται με σιωπηλά ασθενέστερη
πολιτική. Για να αποκατασταθεί η εγγενής αποστολή στο Linux απαιτείται ένα
backend με κανόνες ονομάτων αρχείου κατά τη δημιουργία. Η απενεργοποίηση του
sandboxing είναι ρητή εξαίρεση χωρίς περιορισμούς, όχι ισοδύναμο υποκατάστατο.

Στην πράξη, ένας διακομιστής Linux ή WSL2 εκτελεί σήμερα πράκτορες με έναν από δύο τρόπους. Ξεκινημένος με `--sandbox off`, εκτελεί τους πράκτορες όλων των μελών χωρίς περιορισμούς. Χωρίς εγκατεστημένα τα `bubblewrap` ή `socat`, είναι `unavailable` και εκτελεί μόνο τους πράκτορες του κατόχου του διακομιστή, χωρίς περιορισμούς. Με και τα δύο εργαλεία εγκατεστημένα και το sandbox ενεργό, κάθε εκτέλεση αποτυγχάνει κλειστά, και του κατόχου περιλαμβάνεται.

## Οι φάκελοι εντολών του διακομιστή

Ο διακομιστής βρίσκει, μία φορά κατά την εκκίνηση, κάθε φάκελο από τον οποίο εκτελεί προγράμματα: κάθε καταχώριση του `PATH` του, τους φακέλους εργαλείων ανά χρήστη που ελέγχει (όπως το `~/.local/bin`, το `~/.bun/bin` και τους φακέλους global των npm, yarn και pnpm), και τον πραγματικό φάκελο πίσω από κάθε σύνδεσμο στη διαδρομή (συνδέσμους διαχείρισης εκδόσεων όπως το `~/fvm/default` ή ένα προεπιλεγμένο fnm). Μέσα σε sandbox, ένας πράκτορας δεν μπορεί να προσθέσει, να αντικαταστήσει, να διαγράψει ή να μετονομάσει εντολή σε αυτούς τους φακέλους, τον σύνδεσμο που οδηγεί σε μία, ή το εγκατεστημένο πακέτο στο οποίο δείχνει μια συνδεδεμένη εντολή, ούτε να μετονομάσει τους φακέλους πάνω από αυτούς. Διαφορετικά, μια εκτέλεση σε sandbox θα μπορούσε να τοποθετήσει ένα πρόγραμμα που ο διακομιστής ή το άτομο θα ξεκινούσε αργότερα εκτός sandbox.

Τι αλλάζει για μια εκτέλεση:

- Οι καθολικές εγκαταστάσεις από μέσα σε εκτέλεση σε sandbox αποτυγχάνουν με «Operation not permitted»: `npm i -g`, `pnpm add -g`, `yarn global add`, `bun add -g`, `corepack enable`, `pipx install`, `uv tool install`, και το `cargo install`, `go install` ή `dart pub global activate` όταν ο φάκελος bin τους είναι στο `PATH` του διακομιστή.
- Η αλλαγή προεπιλεγμένης έκδοσης αποτυγχάνει με τον ίδιο τρόπο (`fnm default`, `nvm alias default`, `fvm global`), όπως και μια ενημέρωση ενός εργαλείου στον εαυτό του επί τόπου.
- Οι τοπικές εγκαταστάσεις του έργου (`node_modules/.bin`), το `npx`, το `pnpm dlx`, οι διαχειριστές πακέτων που διαχειρίζεται το corepack, οι cache SDK και οι κανονικές κατασκευές συνεχίζουν να λειτουργούν.

Για να είναι ένα καθολικό εργαλείο διαθέσιμο στους πράκτορες, εγκαταστήστε το στον ίδιο τον διακομιστή, ως ο χρήστης του διακομιστή, και επανεκκινήστε τον διακομιστή ώστε και η νέα εντολή να προστατεύεται. Ή εγκαταστήστε το στο έργο. Μια εντολή που εγκαταστάθηκε αφού ξεκίνησε ο διακομιστής προστατεύεται πλήρως μόνο από την επόμενη εκκίνηση.

Επιβεβαιωμένο και δοκιμασμένο στο macOS. Στο Linux, οι ίδιοι κανόνες είναι προσδέσεις bubblewrap που δεν έχουν επαληθευτεί ακόμη. Τα Windows δεν έχουν sandbox.

## Backend χωρίς απομόνωση

Χωρίς sandboxing. Η διεργασία εκτελείται απευθείας στον κεντρικό υπολογιστή, με πρόσβαση στο σύστημα αρχείων, το δίκτυο και τις διεργασίες του. Το ACP και το εργαλείο `bash` του harness παίρνουν ακόμη καθαρισμό περιβάλλοντος και την πολιτική εντολών· το Claude Code μέσω του `NoSandboxAdapter` κληρονομεί το περιβάλλον του κεντρικού υπολογιστή. Η αποστολή πρακτόρων το χρησιμοποιεί για κάθε εκτέλεση υπό `--sandbox off`, και σε κεντρικό υπολογιστή χωρίς διαθέσιμο backend μόνο για τις εκτελέσεις του κατόχου του διακομιστή· οι εκτελέσεις όλων των άλλων απορρίπτονται εκεί. Για ένα τερματικό είναι το κέλυφος του κεντρικού υπολογιστή, το οποίο μπορεί να ανοίξει μόνο ο κάτοχος του διακομιστή.

## Τερματικό φιλοξενούμενο στον διακομιστή

Το τερματικό του διακομιστή ανοίγει το κέλυφος του κεντρικού υπολογιστή μόνο για τον [κάτοχο](/el-GR/εγχειρίδιο/έννοιες/εξουσιοδότηση/#ο-κάτοχος-του-διακομιστή) του διακομιστή. Όλοι οι άλλοι παίρνουν τερματικό σε sandbox, με τα όρια ενός πράκτορα, στους καταλόγους του ίδιου του χώρου εργασίας.

Η επιλογή backend για μια συνεδρία γίνεται ως εξής:

| Ζητείται | Κάτοχος του διακομιστή | Οποιοσδήποτε άλλος |
| --- | --- | --- |
| Τίποτα | Το προεπιλεγμένο backend του διακομιστή | Η προεπιλογή, με το `none` αντικατεστημένο από `native` |
| `none` (το κέλυφος του κεντρικού υπολογιστή) | Κέλυφος κεντρικού υπολογιστή | Απορρίπτεται: το κέλυφος του κεντρικού υπολογιστή τρέχει στον διακομιστή χωρίς sandbox |
| `native` | Εγγενές sandbox, προφίλ κατόχου | Εγγενές sandbox, προφίλ πράκτορα |
| `microvm` | Απομονωμένο VM | Απομονωμένο VM |
| Άγνωστο όνομα | Απορρίπτεται | Απορρίπτεται |

- **Προφίλ κατόχου.** Το `$HOME` και ο κατάλογος εργασίας της συνεδρίας είναι εγγράψιμα, το δίκτυο είναι ανοιχτό, και οι αναγνώσεις των `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.config/gh` και `~/Library/Keychains` απορρίπτονται.
- **Προφίλ πράκτορα** (`memberTerminalSandboxConfig`). Η ίδια πολιτική με την οποία τρέχει ένας πράκτορας σε εκείνον τον χώρο εργασίας: οι εγγραφές μένουν στον κατάλογο εργασίας, σε έναν ιδιωτικό κατάλογο εκτέλεσης, στο `/tmp` και στα μέρη του `$HOME` όπου επιτρέπεται εγγραφή σε πράκτορα· τα μυστικά απορρίπτονται για ανάγνωση· το δίκτυο είναι η λίστα εξερχόμενης κίνησης του πράκτορα· τα προγράμματα εκτελούνται μόνο από τον κατάλογο εργασίας και τα εγκατεστημένα εργαλεία.
- Ένα τερματικό ανοίγει μόνο μέσα στους δικούς του καταλόγους του χώρου εργασίας. Ένας κατάλογος εργασίας έξω από αυτούς απορρίπτεται, δεν αντικαθίσταται με άλλον.
- Μόνο όποιος άνοιξε ένα τερματικό μπορεί να το διαβάσει, να γράψει σε αυτό, να αλλάξει το μέγεθός του ή να το κλείσει. Σε οποιονδήποτε άλλο το αναγνωριστικό του φαίνεται άγνωστο.
- Το `microvm` που ζητείται ρητά σε κεντρικό υπολογιστή χωρίς υπηρεσία σταθμού αποτυγχάνει αντί να γυρίσει πίσω. Μια προεπιλογή `microvm` σε τέτοιον κεντρικό υπολογιστή υποβαθμίζεται σε `native` και το αναφέρει στο αρχείο καταγραφής.

Το token φιλοξενίας κώδικα μόνο για ανάγνωση και η πύλη push δεν ισχύουν στα τερματικά: αυτά είναι ζητήματα της αποστολής. Αν το περιτύλιγμα δεν υποστηρίζεται, η συνεδρία αποτυγχάνει αντί να δείξει ένδειξη sandbox πάνω σε συνεδρία κελύφους του κεντρικού υπολογιστή.

## Εξερχόμενη κίνηση δικτύου

Όταν εκκινείται ένα sandbox, η εξερχόμενη πρόσβαση στο δίκτυο επιβάλλεται από proxy εντός διεργασίας, όχι από κανόνες τείχους προστασίας του πυρήνα. Μια εκτέλεση που δεν είναι σε sandbox (κάθε εκτέλεση υπό `--sandbox off`, ή η εκτέλεση του κατόχου σε κεντρικό υπολογιστή χωρίς backend) δεν έχει τίποτα από αυτά: μια διεργασία που ξεκινά φτάνει στο δίκτυο ακριβώς όπως θα έφτανε ο χρήστης του διακομιστή.

- Ο χρόνος εκτέλεσης του sandbox τρέχει έναν proxy HTTP/HTTPS και έναν proxy SOCKS5 στο `127.0.0.1` μέσα στη διεργασία του `cc_server`, **ένα ζεύγος ανά περιορισμένη συνεδρία** (`http_proxy.dart`, `socks_proxy.dart`). Οι ταυτόχρονες εκτελέσεις δεν μοιράζονται ζεύγος.
- Οι διεργασίες μέσα σε sandbox λαμβάνουν μεταβλητές περιβάλλοντος proxy (`HTTP_PROXY`/`HTTPS_PROXY` → ο proxy HTTP, `ALL_PROXY` → ο proxy SOCKS· το `GIT_SSH_COMMAND` δρομολογεί το git-over-SSH μέσω του proxy SOCKS). Στο Linux το namespace δικτύου δεν είναι κοινόχρηστο, οπότε οι proxy είναι η μόνη διέξοδος· στο macOS το sandbox μοιράζεται το loopback του κεντρικού υπολογιστή και μιλά απευθείας μαζί τους.
- Ο κεντρικός υπολογιστής-στόχος κάθε σύνδεσης αντιστοιχίζεται με τη λίστα επιτρεπόμενων τομέων της συνεδρίας· οτιδήποτε άλλο απορρίπτεται. Δύο μορφές μπαλαντέρ, καθεμία με ακριβώς ένα `*`: ένα αρχικό `*.example.com` ταιριάζει με κάθε υποτομέα (συμπεριλαμβανομένου του `a.b.example.com`) αλλά όχι με τον ίδιο τον τομέα κορυφής· ένα μπαλαντέρ σε ενδιάμεσο επίπεδο `bedrock.*.amazonaws.com` ταιριάζει με ακριβώς ένα επίπεδο (`bedrock.us-east-1.amazonaws.com`, όχι `bedrock.evil.attacker.amazonaws.com`).
- Η λίστα επιτρεπομένων επιλύεται ανά συνεδρία από το επιμελημένο βασικό σύνολο (`kBaselineAllowedDomains`: πάροχοι LLM, φιλοξενία Git, μητρώα πακέτων), συν τους τομείς GitHub (`kGithubDomains`), συν το `SandboxSpec.egressAllowlist`. Η διαδρομή αποστολής δεν περνά ποτέ πρόσθετες εγγραφές `egressAllowlist`, οπότε στην πράξη κάθε εκτέλεση παίρνει το βασικό σύνολο συν το GitHub.
- Μια σταθερή λίστα απαγόρευσης (`kBaselineDeniedDomains`: τελικά σημεία μεταδεδομένων cloud, προορισμοί τηλεμετρίας) υπερισχύει όλων των επιτρεπτικών.
- Το `networkEnabled: false` ξεκινά ακόμη τους proxy ανά συνεδρία, αλλά η λίστα επιτρεπομένων είναι κενή, οπότε κάθε εξερχόμενη σύνδεση απορρίπτεται. Η αποστολή το ορίζει όταν ξεκινά η εκτέλεση από τον κανόνα **Πρόσβαση στο δίκτυο**: η απόρριψη κλείνει το δίκτυο, η αποδοχή και η ερώτηση πρώτα το αφήνουν ανοιχτό.

## SandboxSpec

Η προδιαγραφή που περνά στο `SandboxPort.launch`:

| Πεδίο             | Τύπος                                       | Περιγραφή                                                                                                                                   |
| ----------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `sessionId`       | `String`                                    | Σταθερό αναγνωριστικό συνεδρίας (συνήθως το id του χώρου)                                                                                    |
| `workspaceId`     | `String`                                    | Το id του χώρου εργασίας στον οποίο ανήκει                                                                                                  |
| `agentId`         | `String?`                                   | Ο πράκτορας που είναι αυτή τη στιγμή δεσμευμένος στο sandbox, αν υπάρχει                                                                     |
| `bindMounts`      | `List<SandboxBindMount>`                    | Προσαρτήσεις από τον κεντρικό υπολογιστή στο φιλοξενούμενο· το sandbox βλέπει μόνο τις διαδρομές που παρατίθενται εδώ                        |
| `networkEnabled`  | `bool` (προεπιλογή `true`)                  | Ορίζεται κατά την αποστολή από τον κανόνα εξερχόμενης δικτυακής κίνησης (ανενεργό μόνο όταν αυτός επιλύεται σε απόρριψη). Όταν είναι ανενεργό, οι proxy ανά συνεδρία ξεκινούν ακόμη, αλλά η λίστα επιτρεπομένων είναι κενή, οπότε κάθε εξερχόμενη σύνδεση απορρίπτεται |
| `egressAllowlist` | `List<String>` (προεπιλογή `[]`)            | Πρόσθετοι επιτρεπόμενοι τομείς εξερχόμενης κίνησης· υποστηρίζονται μπαλαντέρ (`*.example.com`, συν μια ενδιάμεση μορφή ενός επιπέδου). Η αποστολή δεν το συμπληρώνει ποτέ, οπότε μια περιτυλιγμένη εκτέλεση παίρνει το επιμελημένο βασικό σύνολο συν τους τομείς GitHub |
| `guestWorkdir`    | `String?`                                   | Προεπιλεγμένος κατάλογος εργασίας μέσα στο sandbox· μεμονωμένες κλήσεις `exec` μπορούν να τον παρακάμψουν                                        |
| `mode`            | `Mode` (προεπιλογή `chat`)                  | Χαράσσει τους κανόνες εγγραφής του συστήματος αρχείων: το `chat` διατηρεί τα bind mounts εγγράψιμα· τα `review`, `plan` και `orchestrate` είναι μόνο για ανάγνωση |
| `protectedPaths`  | `List<String>` (προεπιλογή `[]`)            | Διαδρομές του κεντρικού υπολογιστή που δεν πρέπει ποτέ να είναι εγγράψιμες μέσα στο sandbox, σε καμία λειτουργία                              |
| `runnerStateDirs` | `List<String>` (προεπιλογή `[]`)            | Κατάλογοι του κεντρικού υπολογιστή όπου ο runner κρατά τη δική του κατάσταση, εγγράψιμοι σε κάθε λειτουργία (ένας `CLAUDE_CONFIG_DIR` υπό τη διαχείριση του Control Center είναι ο τρέχων) |
| `execGrantRoots`  | `List<String>` (προεπιλογή `[]`)            | Δέντρα καταλόγων εγκεκριμένα από τον χειριστή που ανοίγουν ξανά τον αποκλεισμό exec του εγγράψιμου καταλόγου στο macOS. Το Linux τα αγνοεί — το bwrap δεν έχει αποκλεισμό exec για το `$HOME` που θα άνοιγε ξανά |

Το `protectedPaths` περιέχει τα αρχικά καταχωρισμένα checkouts των αποθετηρίων, που επιλύονται ανά αποστολή από τα αποθετήρια του χώρου εργασίας. Οι πράκτορες εργάζονται αποκλειστικά σε worktrees copy-on-write ανά συνομιλία, οπότε τα πρωτότυπα δεν πρέπει ποτέ να είναι εγγράψιμα από μέσα στο sandbox — στο macOS, η καθολική επιτρεπτική εξαίρεση εγγραφής του Seatbelt για το `$HOME` θα τα άφηνε κατά τα άλλα εγγράψιμα μέσω `bash`. Εντάσσονται στο σύνολο απαγόρευσης εγγραφής των μυστικών σε κάθε λειτουργία, `chat` συμπεριλαμβανομένης.

Κάθε διαδρομή αποκλεισμού ανάγνωσης και εγγραφής εκπέμπεται και στην κυριολεκτική γραφή της και στη γραφή της μετά την επίλυση symlink. Ο πυρήνας αντιστοιχίζει έναν κανόνα απόρριψης με την επιλυμένη διαδρομή, οπότε ένας κανόνας γραμμένος για μια διαδρομή με symlink δεν ενεργοποιείται ποτέ — και στο macOS αυτή είναι η συνήθης περίπτωση και όχι η εξωτική, αφού το `/tmp` επιλύεται σε `/private/tmp` και το `/var/folders/…` σε `/private/var/folders/…`. Οι εγγραφές που περιέχουν `*` ή `?` αντιμετωπίζονται ως glob και μένουν ως έχουν· μια διαδρομή που δεν επιλύεται διατηρείται όπως γράφτηκε.

## SandboxHandle

Επιστρέφεται από το `SandboxPort.launch`:

| Πεδίο       | Τύπος                  | Περιγραφή                                                                                  |
| ----------- | ---------------------- | ------------------------------------------------------------------------------------------ |
| `sessionId` | `String`               | Αναγνωριστικό συνεδρίας                                                                    |
| `backend`   | `SandboxBackend`       | Ποιο backend εκτελείται                                                                     |
| `state`     | `SandboxState`         | Κατάσταση κύκλου ζωής                                                                       |
| `error`     | `Object?`              | Ορίζεται όταν το `state` είναι `error`                                                      |
| `details`   | `Map<String, Object?>` | Εσωτερικά δεδομένα τήρησης του προσαρμογέα (κατάλογος εργασίας, PID, διαδρομή προφίλ κ.λπ.) |

### SandboxState

| Κατάσταση   | Περιγραφή                                            |
| ----------- | ---------------------------------------------------- |
| `created`   | Η προδιαγραφή δημιουργήθηκε, αλλά το VM δεν έχει ξεκινήσει ακόμη |
| `warm`      | Εκτελείται και είναι έτοιμο να δεχτεί εντολές exec    |
| `active`    | Εκτελεί αυτή τη στιγμή μια εντολή                     |
| `suspended` | Σε παύση / με σημείο ελέγχου στον δίσκο για εξοικονόμηση RAM |
| `destroyed` | Καταστράφηκε· η λαβή δεν είναι πλέον έγκυρη           |
| `error`     | Η εκκίνηση απέτυχε — δείτε το `SandboxHandle.error`   |

## Γεγονότα sandbox

| Τύπος γεγονότος | Περιγραφή                                                       |
| --------------- | --------------------------------------------------------------- |
| `stdout`        | Τυπική έξοδος από το sandbox                                     |
| `stderr`        | Τυπικό σφάλμα από το sandbox                                     |
| `exit`          | Η διεργασία του sandbox τερματίστηκε (φέρει `exitCode`)           |
| `starting`      | Το sandbox ξεκινά                                                |
| `ready`         | Το sandbox είναι έτοιμο να δεχτεί κλήσεις exec                    |
| `killed`        | Η διεργασία τερματίστηκε βίαια από τον κεντρικό υπολογιστή (OOM, χρονικό όριο, χειροκίνητη διακοπή) |
| `violation`     | Παραβιάστηκε μια πολιτική sandbox (φέρει ένα `SandboxViolation`)  |
