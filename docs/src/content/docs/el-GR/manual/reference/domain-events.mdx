## Δίαυλος γεγονότων

Ο `DomainEventBus` είναι ένας ενδοδιεργασιακός δίαυλος δημοσίευσης/συνδρομής με εκπομπή. Οι εκδότες καλούν `publish(event)`· οι συνδρομητές καταναλώνουν μια ροή `on<T>()` με τύπο. Κάθε γεγονός υλοποιεί το `DomainEvent` και φέρει `occurredAt`.

**Ο δίαυλος εκτελείται μέσα στο `cc_server`.** Κάθε εκδότης και κάθε ενεργός συνδρομητής βρίσκεται εκεί. Κανένας πελάτης δεν βλέπει αυτόν τον δίαυλο — ο διακομιστής προωθεί ένα επιμελημένο υποσύνολο ως πλαίσια JSON-RPC `notifications/*`, φιλτραρισμένα ανά συνδρομητή με βάση την ιδιότητα μέλους στον χώρο εργασίας.

| Μέτρηση                                                     | Αριθμός                                       |
| ----------------------------------------------------------- | --------------------------------------------- |
| Συγκεκριμένες κλάσεις γεγονότων                             | 53                                          |
| Αρχεία προέλευσης (`packages/cc_domain/lib/core/domain/events/`) | 14 (συν το `domain_event_bus.dart`)           |
| Αφηρημένες βάσεις που δεν δημοσιεύονται ποτέ απευθείας      | 1 (`TaskLifecycleEvent`, μια σφραγισμένη ιεραρχία) |

Κάθε γεγονός στον παρακάτω κατάλογο ζει σε εκείνον τον έναν κατάλογο· δεν υπάρχουν γεγονότα τομέα δηλωμένα αλλού.

## Γεγονότα PR και ανασκόπησης

Το πρώτο μπλοκ είναι ο κύκλος ζωής του ίδιου του PR. Το δεύτερο είναι η **παρακολούθηση PR που συντάξατε**: σήματα για ένα PR που ανοίξατε *εσείς*, καθένα από τα οποία φέρει `forUserId`, ώστε ο περιοδικός έλεγχος να τα δρομολογεί στο πρόσωπο που αφορούν αντί να τα εκπέμπει σε όλους.

## Γεγονότα κύκλου ζωής εργασίας

Η ενοποιημένη ροή κύκλου ζωής εργασιών — μία αποσταλμένη εκτέλεση πράκτορα, κλειδωμένη με το αναγνωριστικό του αρχείου καταγραφής εκτέλεσής της. Κάθε γεγονός φέρει `taskId`, ένα μονοτονικό `seq` ανά εργασία, `workspaceId?`, `agentId?` και μια `phase`· οι παρακάτω γραμμές παραθέτουν μόνο τα πρόσθετα πεδία.

| Γεγονός                     | Φορτίο                       | Ενεργοποιείται όταν                                                                              |
| --------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------ |
| `TaskDispatched`            | —                             | Η εργασία παραδίδεται σε ένα backend για εκτέλεση                                                |
| `TaskRunning`               | —                             | Η εργασία άρχισε να παράγει έξοδο                                                                |
| `TaskWaitingLocalDirectory` | `lockedPath`, `holderTaskId?` | Η εργασία σταθμεύει — μια άλλη εργασία κατέχει το κλείδωμα διαδρομής στον δίσκο που της χρειάζεται |
| `TaskProgress`              | `note?`                       | Σημείο ελέγχου προόδου στα μισά της εκτέλεσης                                                    |
| `TaskMessage`               | `messageType`, `content`      | Μήνυμα σε ροή (text/thinking/tool_use/tool_result/error)· αναφέρεται στη φάση `progress`         |
| `TaskCompleted`             | `summary?`                    | Η εργασία ολοκληρώθηκε με επιτυχία                                                               |
| `TaskFailed`                | `errorMessage`                | Η εργασία ολοκληρώθηκε με σφάλμα                                                                 |
| `TaskCancelled`             | —                             | Η εργασία ακυρώθηκε πριν ολοκληρωθεί                                                             |

Το enum `TaskPhase` έχει επίσης ένα μέλος `queued`, αλλά τίποτα δεν δημοσιεύει γεγονός ουράς — δεν υπάρχει κλάση `TaskQueued`. Το πρώτο παρατηρήσιμο πλαίσιο μιας εργασίας είναι το `TaskDispatched`.

## Γεγονότα pipeline

| Γεγονός                | Φορτίο                                       | Ενεργοποιείται όταν                                                          |
| ---------------------- | --------------------------------------------- | --------------------------------------------------------------------------- |
| `PipelineRunCompleted` | `workspaceId`, `pipelineRunId`, `templateId`  | Η εκτέλεση ολοκληρώνεται                                                    |
| `PipelineRunCancelled` | `workspaceId`, `pipelineRunId`, `templateId`  | Η εκτέλεση ακυρώνεται (από τον χρήστη ή το σύστημα) — μια σκόπιμη διακοπή, όχι σφάλμα |

| Γεγονός                      | Φορτίο                          | Ενεργοποιείται όταν                                                                                        |

## Γεγονότα σταθμών

| Γεγονός             | Φορτίο                                       | Ενεργοποιείται όταν                                                                                                                 |
| ------------------- | --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `RigClosedEvent`    | `workspaceId`, `rigId`, `reason`              | Ένας σταθμός χάθηκε, με τον λόγο κλεισίματός του· οι καταναλωτές δρουν μόνο στο `backendFailure` — κάθε άλλος λόγος είναι ζητημένος ή συνοδεύεται από ένα `RigReaped` |
| `RigControlChanged` | `workspaceId`, `rigId`, `controller?`         | Ένας άνθρωπος πήρε αποκλειστικό έλεγχο ενός σταθμού ή τον επέστρεψε (`controller` null κατά την απελευθέρωση — το γεγονός δεν καταγράφει ποιος άφησε) |
| `RigReaped`         | `workspaceId`, `rigId`, `reason`, `agentId?`  | Το σύστημα ανέκτησε μια μηχανή: αδράνεια, TTL ή αποβολή λόγω πίεσης μνήμης (αναφέρεται ως `idleTimeout`), μαζί με τον πράκτορα που την οδηγούσε |

Το **άνοιγμα** ενός σταθμού δεν είναι γεγονός. Η εκκίνηση ολοκληρώνεται και η γραμμή του σταθμού μεταπίπτει σε έτοιμος· τίποτα δεν δημοσιεύεται, οπότε δεν υπάρχει `RigOpened` για να εγγραφείτε.

## Υποτομείς χωρίς κανένα γεγονός

Αρκετά υποσυστήματα που από έξω φαίνονται καθοδηγούμενα από γεγονότα δεν είναι. Παρατίθενται εδώ επειδή η απουσία τους είναι σχεδιαστική απόφαση που αξίζει να γνωρίζετε πριν αρχίσετε να ψάχνετε για άγκιστρο:

| Υποτομέας         | Πώς κινείται αντ' αυτού η κατάσταση                                                                     |
| ----------------- | --------------------------------------------------------------------------------------------------------- |
| Μνήμη             | Τα `record_memory_fact` και τα συναφή γράφουν και επιστρέφουν· η ανάκληση διαβάζει. Τίποτα δεν δημοσιεύει όταν δημιουργείται ένα γεγονός ή μια σύγκρουση |
| Ενορχήστρωση      | Η πρόταση, η έγκρισή της και η παραγόμενη εκτέλεση pipeline είναι γραμμές και κλήσεις RPC              |
| Έγγραφα σχεδίου   | Το `submit_plan` γράφει μια αναθεώρηση· η έγκριση υλοποιεί μια ενορχήστρωση. Κανένα από τα δύο δεν ανακοινώνεται |
| Τεχνουργήματα     | Τα `publish_artifact` / `revise_artifact` γράφουν αναθεωρήσεις απευθείας                                |
| Εγκρίσεις         | Η κλιμάκωση χειρίζεται μέσα στην υπηρεσία ροής εγκρίσεων                                                |
| Συγχρονισμός εισιτηρίων | Ο συντονιστής προμηθευτών εγγράφεται στα παραπάνω γεγονότα εισιτηρίων· τα εισερχόμενα webhooks εφαρμόζονται απευθείας |
| Ανανέωση ημερολογίου | Ένας συγχρονισμός εισάγει ή ενημερώνει γεγονότα και ο πελάτης ξαναδιαβάζει· δεν υπάρχει εκπομπή ανανέωσης |
| Συγχωνεύσεις worktree | Καταγράφονται στο `worktree_merge_log` και διαβάζονται από εκεί                                        |

| `LocalRpcServer` / `RemoteRelayHost` | `WorkspaceMemberRemoved` — απορρίπτει τις συνδεδεμένες συνδρομές χώρου εργασίας αυτού του χρήστη· η υποδοχή παραμένει ανοιχτή |

Το `TicketAssigned` είναι σήμα ελέγχου και ειδοποίησης και ενεργοποιητής pipeline. Η ανάθεση σε έναν πράκτορα καταγράφει την κυριότητα και δεν ξεκινά καμία εκτέλεση — δεν υπάρχει αποστολέας εισιτηρίων. Η ανάθεση σε ομάδα (όταν έχει οριστεί το `assignedTeamId`) είναι η εξαίρεση: το `TeamRoutingService` αποστέλλει τον ηγέτη της ομάδας.

Ο `TicketRemoteSyncHandler` δηλώνεται αλλά δεν κατασκευάζεται ποτέ σε κώδικα παραγωγής, οπότε δεν εγγράφεται σε τίποτα σήμερα. Ο `NotificationEventMapper` στην πλευρά του πελάτη κατασκευάζεται μόνο στο δικό του τεστ — είναι το υπόλειμμα της ενδοδιεργασιακής διαδρομής από πριν από τον διαχωρισμό πελάτη/διακομιστή. Τα ζωντανά αναδυόμενα μηνύματα προέρχονται από τα πλαίσια δικτύου παρακάτω.

## Αντιστοίχιση ειδοποιήσεων

Στον διακομιστή, οι `NotificationFeedRecorder` και `RemoteEventForwarder` μετατρέπουν αυτά τα γεγονότα σε πλαίσια δικτύου `notifications/*` (`notification_wire.dart`). Στον πελάτη, ο `RpcNotificationMapper` → `mapNotificationFrame` μετατρέπει ένα πλαίσιο σε `AppNotification`.

Υπάρχουν ακριβώς **δεκαέξι** κατηγορίες ειδοποιήσεων. Αρκετά γεγονότα αντιστοιχίζονται σε περισσότερες από μία μεθόδους δικτύου, επειδή το πλαίσιο μεταφέρει τη μετάβαση (αποτυχία έναντι ανάκτησης) ενώ η κατηγορία μεταφέρει την ερώτηση («τι κάνει το CI;»).

| Κατηγορία              | Γεγονός προέλευσης        | Μέθοδος δικτύου                                                          |
| ---------------------- | ------------------------- | ------------------------------------------------------------------------ |
| `newMessage`           | `MessageReceived`         | `notifications/message_received` (σας αναφέρει)                        |
| `agentRunCompleted`    | `MessageReceived`         | `notifications/message_received` (`is_agent_message`, χωρίς αναφορά σε εσάς) |
| `ticketAssigned`       | `TicketAssigned`          | `notifications/ticket_assigned`                                        |
| `ticketStatusChanged`  | `TicketStatusChanged`     | `notifications/ticket_status_changed`                                  |
| `pullRequestPublished` | `PullRequestPublished`    | `notifications/pr_published`                                           |
| `prMerged`             | `PrMerged`                | `notifications/pr_merged`                                              |
| `prMerged`             | `ExternalPrMerged`        | `notifications/external_pr_merged`                                     |
| `prMentioned`          | `PrMentioned`             | `notifications/pr_mentioned`                                           |
| `prMentioned`          | `PrCommentMentioned`      | `notifications/pr_comment_mentioned`                                   |
| `reviewRequested`      | `PrReviewRequested`       | `notifications/pr_review_requested`                                    |
| `reviewStale`          | `ReviewBecameStale`       | `notifications/review_stale`                                           |
| `prMergeReadiness`     | `PrMergeReadinessChanged` | `notifications/pr_ready_to_merge` / `pr_merge_blocked`                 |
| `prReviewDecision`     | `PrReviewDecisionChanged` | `notifications/pr_approved` / `pr_changes_requested` / `pr_review_dismissed` |
| `prChecksStatus`       | `PrChecksStatusChanged`   | `notifications/pr_checks_failed` / `pr_checks_recovered`               |
| `prThreadActivity`     | `PrThreadReplied`         | `notifications/pr_thread_replied`                                      |
| `prThreadActivity`     | `PrThreadResolved`        | `notifications/pr_thread_resolved`                                     |
| `meetingStartsSoon`    | `MeetingStartingSoon`     | `notifications/meeting_starting_soon`                                  |
| `calendarAuthExpired`  | `CalendarAuthExpired`     | `notifications/calendar_auth_expired`                                  |
| `rigStatusChanged`     | `RigControlChanged`       | `notifications/rig_control_changed`                                    |
| `rigStatusChanged`     | `RigReaped`               | `notifications/rig_reaped`                                             |
| `rigStatusChanged`     | `RigClosedEvent`          | `notifications/rig_closed`                                             |

Το πλαίσιο ανάληψης σταθμού δεν παραδίδεται πίσω σε όποιον πήρε το τιμόνι, μια
απελευθέρωση είναι χωρίς φίλτρο (το γεγονός δεν καταγράφει ποιος άφησε) και μόνο
ένα κλείσιμο `backendFailure` παράγει πλαίσιο `rig_closed` — οι άλλοι λόγοι
είτε είναι ζητημένοι είτε καλύπτονται ήδη από το πλαίσιο περισυλλογής.

Οι πέντε κατηγορίες PR που συντάξατε φέρουν `forUserId`, οπότε φτάνουν στον συντάκτη και όχι σε όλους στον χώρο εργασίας.

Ο `RemoteEventForwarder` προωθεί επιπλέον το `TicketReassigned` ως `notifications/ticket_reassigned` και κάθε `TaskLifecycleEvent` ως `notifications/task_<phase>`. Κανένα από τα δύο δεν αντιστοιχίζεται σε κατηγορία ειδοποίησης — τροφοδοτούν ζωντανή διεπαφή χρήστη, όχι το κέντρο ειδοποιήσεων. Τα γεγονότα ιδιότητας μέλους δεν προωθούνται ως πλαίσια: ακυρώνουν την προσωρινή μνήμη του προωθητή και οι οικοδεσπότες συνεδριών απορρίπτουν τις συνδρομές χώρου εργασίας του μέλους που αφαιρέθηκε.
