Όλα όσα μπορεί να αντιγράψει, να παραδώσει ή να υιοθετήσει το Control Center, και η
ακριβής μορφή κάθε τεχνουργήματος. Για να πάρετε πραγματικά ένα αντίγραφο ασφαλείας,
δείτε το
[Αντίγραφο ασφαλείας και επαναφορά](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/αντίγραφο-ασφαλείας-και-επαναφορά/); για τον λόγο που η αποθήκευση είναι χωρισμένη κατ' αυτόν τον τρόπο, δείτε τους
[Χώρους εργασίας και απομόνωση](/el-GR/εγχειρίδιο/έννοιες/χώροι-εργασίας/).

## Τεχνουργήματα

Υπάρχουν τρία τεχνουργήματα αντιγραφής βάσεων δεδομένων, με διαφορετική εμβέλεια και
πολιτική διαγραφής.

| Τεχνούργημα             | Γράφεται από                 | Μορφή                                 | Καλύπτει                     |
| ----------------------- | ---------------------------- | ------------------------------------- | ----------------------------- |
| **Στιγμιότυπο εγκατάστασης** | `server.backupNow`      | Ένας κατάλογος με **χρονοσήμανση**    | Κάθε βάση δεδομένων της εγκατάστασης |
| **Workspace backup**    | pipeline `Workspace backup`  | Κατάλογος με χρονοσήμανση που περιέχει ένα `.db` | Τη βάση δεδομένων ενός χώρου εργασίας |
| **Εξαγωγή χώρου εργασίας** | `workspace.export`        | Ένα μεμονωμένο `.db` **αρχείο**       | Τη βάση δεδομένων ενός χώρου εργασίας |

Όλα γράφονται με SQLite `VACUUM INTO`, το οποίο είναι ασφαλές απέναντι σε μια ενεργή βάση
δεδομένων WAL: λαμβάνει μια συναλλαγή ανάγνωσης, παράγει ένα αποσυμπιεσμένο και
συναλλακτικά συνεπές αντίγραφο, και δεν απαιτεί ποτέ τη διακοπή του διακομιστή.

Αυτά τα αρχεία και τα ληφθέντα αντίγραφα **δεν κρυπτογραφούνται σε ηρεμία** από το
Control Center. Η κρυπτογραφημένη από άκρο σε άκρο μεταφορά προστατεύει τα byte κατά
τη μεταφορά μεταξύ ενός συζευγμένου πελάτη και του `cc_server` του, είτε σε
απευθείας είτε σε αναμεταδιδόμενες συνδέσεις. Προστατέψτε ξεχωριστά την τοπική
αποθήκευση και τα αντίγραφα εκτός μηχανήματος· ο διακομιστής και κάθε
εξουσιοδοτημένος παραλήπτης μπορούν να διαβάσουν τα αρχεία της βάσης δεδομένων.

## Διάταξη στιγμιότυπου

```
<dataDir>/backups/2026-07-28T09-12-33-000Z/
  manifest.json
  global.db
  <workspaceId>/workspace.db      one directory per workspace
```

Η διάταξη καθρεφτίζει ακριβώς τον ενεργό κατάλογο δεδομένων, και αυτό είναι που κάνει την
επαναφορά μιας εγκατάστασης απλή αντιγραφή πίσω αντί για μετάφραση. Το όνομα του καταλόγου
είναι η χρονοσήμανση UTC με τα `:` και `.` αντικατεστημένα από `-`, οπότε είναι ασφαλές για
το σύστημα αρχείων στα Windows και ταξινομείται χρονολογικά ως απλή συμβολοσειρά.

Τα προγραμματισμένα αντίγραφα ασφαλείας χώρων εργασίας βρίσκονται ξεχωριστά στη διαδρομή
`<dataDir>/backups/workspace-backups/<workspaceId>/<timestamp>/workspace.db`.
Καθένα έχει ένα `manifest.json` για εκείνο το ένα αρχείο και δεν έχει `global.db`· δεν είναι στιγμιότυπα εγκατάστασης. Μια επαναφορά διατηρεί τη βάση δεδομένων που αντικαθιστά στο ίδιο σημείο, ως `<timestamp>-pre-restore`.
Το βήμα διατήρησης του εβδομαδιαίου pipeline αφαιρεί μόνο αντίγραφα ασφαλείας του δικού
του χώρου εργασίας που είναι παλαιότερα από τη διαμορφωμένη ηλικία του (30 ημέρες από
προεπιλογή)· τα χειροκίνητα στιγμιότυπα εγκατάστασης δεν εκκαθαρίζονται ποτέ από αυτό το
βήμα. Το `server.listBackups` απαριθμεί μόνο στιγμιότυπα εγκατάστασης, μαζί και τα
μη επαληθευμένα· το `workspace.listBackups` απαριθμεί τα προγραμματισμένα αντίγραφα ασφαλείας ενός
χώρου εργασίας.

Η διαγραφή ενός χώρου εργασίας αφήνει αυτόν τον κατάλογο στη θέση του. Το πρόγραμμα του
χώρου εργασίας σταματά μαζί του, οπότε τίποτα δεν εκκαθαρίζει πια αυτά τα αντίγραφα, και
μένουν εκεί μέχρι να τα αφαιρέσει ο ιδιοκτήτης της εγκατάστασης. Το
`server.listOrphanedBackups` τα αναφέρει.


### `manifest.json`

| Πεδίο                      | Τύπος           | Σημασία                                                             |
| -------------------------- | --------------- | ------------------------------------------------------------------- |
| `format`                   | ακέραιος        | Μορφή του μανιφέστου. Αυτή τη στιγμή `2`                            |
| `created_at`               | ISO-8601 UTC    | Πότε λήφθηκε το στιγμιότυπο                                         |
| `global`                   | αντικείμενο     | Η εγγραφή του `global.db`. Απουσιάζει από ένα προγραμματισμένο αντίγραφο ασφαλείας χώρου εργασίας |
| `workspaces[]`             | πίνακας         | Μία εγγραφή ανά καταγεγραμμένο χώρο εργασίας                         |
| `workspaces[].workspace_id`| συμβολοσειρά    | Ο χώρος εργασίας που κατέχει αυτό το αρχείο                          |
| `skipped_workspaces[]`     | πίνακας         | Χώροι εργασίας που το αντίγραφο ασφαλείας **δεν** μπόρεσε να καταγράψει |
| `skipped_workspaces[].workspace_id` | συμβολοσειρά | Ο χώρος εργασίας που παραλείφθηκε |
| `skipped_workspaces[].reason` | συμβολοσειρά | `no_file`, `damaged` ή `failed` |

Το `global` και κάθε εγγραφή του `workspaces[]` καταγράφουν ένα αρχείο που αντιγράφηκε, μετρημένο στο αντίγραφο αφού γράφτηκε:

| Πεδίο            | Τύπος  | Σημασία                                                                        |
| ---------------- | ------ | ------------------------------------------------------------------------------ |
| `file`                     | συμβολοσειρά    | Διαδρομή σχετική με τη ρίζα του στιγμιότυπου: `global.db` ή `<workspaceId>/workspace.db` |
| `bytes`                    | ακέραιος        | Μέγεθος του αντιγράφου                                              |
| `sha256`                   | συμβολοσειρά    | SHA-256 του αντιγράφου, σε πεζά δεκαεξαδικά                         |
| `quick_check`              | συμβολοσειρά    | Τι είπε το `quick_check` της SQLite για το αντίγραφο: `ok`, ή το εύρημά του |
| `user_version`             | ακέραιος        | Έκδοση σχήματος του αντιγράφου                                      |
| `application_id`           | ακέραιος        | Το `application_id` της SQLite του αντιγράφου                       |

Ένας χώρος εργασίας παραλείπεται όταν είναι καταχωρισμένος αλλά δεν έχει γραφτεί ποτέ (`no_file`), όταν η βάση δεδομένων του αποτυγχάνει στον έλεγχο ακεραιότητας (`damaged`· ένα κατεστραμμένο αντίγραφο δεν λαμβάνεται ποτέ), ή όταν απέτυχε το αντίγραφό του ή ο έλεγχος αυτού του αντιγράφου (`failed`). Σε κάθε περίπτωση το στιγμιότυπο ολοκληρώνεται και το μανιφέστο ονομάζει τι λείπει. Το μανιφέστο γράφεται τελευταίο.

### Πληρότητα

Το `server.listBackups` αναφέρει μια σημαία `complete` ανά στιγμιότυπο. Είναι false όταν το μανιφέστο απουσιάζει, δεν μπορεί να αναλυθεί ή είναι άλλης μορφής, όταν ένα αρχείο που ονομάζει λείπει ή έχει άλλο μέγεθος, ή όταν ένα αντίγραφο δεν πέρασε τον έλεγχό του. Η εφαρμογή εμφανίζει ένα τέτοιο στιγμιότυπο ως **Μη επαληθευμένο**. Τα στιγμιότυπα που λήφθηκαν πριν από τη μορφή `2` βρίσκονται σε αυτή την κατάσταση.

Ένα μη επαληθευμένο στιγμιότυπο εξακολουθεί να εμφανίζεται στη λίστα, επειδή ένα στιγμιότυπο που
δεν βλέπει ένας διαχειριστής είναι ένα στιγμιότυπο που πιστεύει ότι έχει. Όταν το
μανιφέστο δεν είναι αναγνώσιμο, η λίστα καταφεύγει στην ίδια τη διάταξη και αναφέρει όποια
αρχεία `<workspaceId>/workspace.db` βρει — αυτά παραμένουν μεμονωμένα υιοθετήσιμα μέσω του
`workspace.import`, ακόμη και αν το στιγμιότυπο στο σύνολό του δεν μπορεί να επαναφέρει
μια εγκατάσταση.

Ένα καταγεγραμμένο στιγμιότυπο ή προγραμματισμένο αντίγραφο ασφαλείας φέρει `pinned_reason: "last_good_copy"` όσο κρατά το νεότερο επαληθευμένο αντίγραφο ενός χώρου εργασίας του οποίου η ζωντανή βάση δεδομένων είναι κατεστραμμένη. Το βήμα διατήρησης το παραλείπει έως ότου επαναφερθεί αυτός ο χώρος εργασίας.

## Τι δεν περιέχει ένα αντίγραφο ασφαλείας

Και τα δύο τεχνουργήματα είναι **μόνο βάσεις δεδομένων**. Ένας κατάλογος χώρου εργασίας
περιέχει περισσότερα από τη βάση δεδομένων του, και τίποτα από τα υπόλοιπα δεν ταξιδεύει:

| Διαδρομή                            | Σε ένα στιγμιότυπο; | Σε μια εξαγωγή χώρου εργασίας; |
| ----------------------------------- | -------------- | ---------------------- |
| `global.db`                         | Ναι            | Όχι                    |
| `<workspaceId>/workspace.db`        | Ναι            | Ναι (το *είναι* το αρχείο) |
| `<workspaceId>/code_index.db`       | Όχι            | Όχι                    |
| `<workspaceId>/blobs/`              | Όχι            | Όχι                    |
| `<workspaceId>/skills/`             | Όχι            | Όχι                    |
| `<workspaceId>/agents/`             | Όχι            | Όχι                    |
| `<workspaceId>/chat_credentials/`   | Όχι            | Όχι                    |
| `<workspaceId>/spaces/<spaceId>/`   | Όχι            | Όχι                    |
| `<workspaceId>/pr_clones/`          | Όχι            | Όχι                    |
| `secrets.json`                      | Όχι            | Όχι                    |
| `models/`                           | Όχι            | Όχι                    |
| `meetings/<meetingId>/`             | Όχι            | Όχι                    |
| `rigs/`                             | Όχι            | Όχι                    |
| `_agent_hooks/`                     | Όχι            | Όχι                    |

Κάποια από αυτά είναι αναλώσιμα — το `spaces/` περιέχει worktrees copy-on-write που παρέχονται εκ νέου από τα αποθετήρια, το `pr_clones/` είναι προσωρινή αποθήκευση, το `code_index.db` ξαναχτίζεται, το `models/` κατεβαίνει ξανά με λήψη, το `rigs/` είναι κατάσταση μηχανήματος. Κάποια άλλα δεν είναι: το `blobs/` περιέχει επικολλημένες εικόνες στις οποίες δείχνουν γραμμές της βάσης δεδομένων, τα `skills/` και `agents/` περιέχουν τα αρχεία με τα οποία εκτελείται ένας πράκτορας, και το `secrets.json` περιέχει κάθε κλειδί σύζευξης, διαπιστευτήριο παρόχου και ρύθμιση SSO της εγκατάστασης. Δείτε το [Αντίγραφο ασφαλείας και επαναφορά](/el-GR/εγχειρίδιο/οδηγοί-πρακτικής/αντίγραφο-ασφαλείας-και-επαναφορά/#αντιγραφή-αντιγράφων-ασφαλείας-εκτός-του-μηχανήματος) για την κάλυψη των υπολοίπων.
:::note[Τα μυστικά μένουν έξω από τις βάσεις δεδομένων]
`workspace.db` είναι ολόκληρος ο χώρος εργασίας: συνομιλίες, αρχεία εκτελέσεων, συνδέσεις αποθετηρίων, ορισμοί περιβαλλόντων και μέλη. Τα tokens webhook των pipeline και τα μυστικά webhook του συγχρονισμού εισιτηρίων βρίσκονται στο `secrets.json`: η βάση δεδομένων περιέχει μια αναφορά σε καθένα, και ο δείκτης διαδρομών περιέχει ένα hash με κλειδί για κάθε διακριτικό. Ένας χώρος εργασίας που επαναφέρεται σε άλλη εγκατάσταση δεν λαμβάνει επομένως κανένα webhook έως ότου τα triggers του αποθηκευτούν ξανά εκεί. Τα διακριτικά σύνδεσης παρόχων, τα κλειδιά συσκευών και τα μυστικά χρηστών βρίσκονται στο `global.db` και στο `secrets.json`.
:::

:::note[Τα διακριτικά συνομιλίας μένουν σκόπιμα πίσω]
Το ότι το `chat_credentials/` βρίσκεται δίπλα στη βάση δεδομένων και όχι μέσα της είναι ο
λόγος που ένας χώρος εργασίας που παραδίδεται σε κάποιον άλλο δεν μεταφέρει ενεργά
διακριτικά chat bot. Δείτε την
[αναφορά γέφυρας συνομιλίας](/el-GR/εγχειρίδιο/αναφορά/γέφυρα-συνομιλίας/).
:::

## Λειτουργίες

Τα RPC αντιγράφων ασφαλείας της εγκατάστασης και η εξαγωγή/εισαγωγή χώρου εργασίας είναι
μόνο για `fullClient`: ένα συζευγμένο τηλέφωνο δεν μπορεί να τα ενεργοποιήσει. Όλα
απουσιάζουν εντελώς — δεν απορρίπτονται, απουσιάζουν δομικά — σε έναν διακομιστή χωρίς
συνδεδεμένη θύρα αντιγράφων ασφαλείας, όπως ο διακομιστής επίδειξης.

| Λειτουργία           | Είδος     | Εμβέλεια      | Ελάχιστος ρόλος | Ορίσματα     | Επιστρέφει                   |
| -------------------- | --------- | ------------- | --------------- | ------------ | ---------------------------- |
| `server.backupNow`   | μετάλλαξη | Εγκατάσταση   | **ιδιοκτήτης** της εγκατάστασης | κανένα | `{ok, path}` |
| `server.listBackups` | ανάγνωση  | Εγκατάσταση   | **ιδιοκτήτης** της εγκατάστασης | κανένα | `{backups: [...]}` |
| `server.deleteBackup` | μετάλλαξη | Εγκατάσταση  | **ιδιοκτήτης** της εγκατάστασης | `name` | `{ok}` |
| `server.listOrphanedBackups` | ανάγνωση | Εγκατάσταση | **ιδιοκτήτης** της εγκατάστασης | κανένα | `{workspaces: [...]}` |
| `server.deleteOrphanedBackup` | μετάλλαξη | Εγκατάσταση | **ιδιοκτήτης** της εγκατάστασης | `workspace_id`, `name` | `{ok}` |
| `workspace.listBackups` | ανάγνωση | Χώρος εργασίας | `admin` | κανένα | `{backups: [...]}` |
| `workspace.deleteBackup` | μετάλλαξη | Χώρος εργασίας | `owner` | `name` | `{ok}` |
| `workspace.export`   | ανάγνωση  | Χώρος εργασίας | `admin`        | κανένα       | `{ok, path}`                 |
| `workspace.import`   | μετάλλαξη | Χώρος εργασίας | `owner`, και ο κάτοχος του διακομιστή | `source_path` | `{ok, workspace_id}`        |
| `workspace.importHolds.list` | ανάγνωση | Χώρος εργασίας | `owner`, και ο κάτοχος του διακομιστή | κανένα | `{holds: [...]}` |
| `workspace.importHolds.resolve` | μετάλλαξη | Χώρος εργασίας | `owner`, και ο κάτοχος του διακομιστή | `hold_id`, `accept` | `{ok, applied}` |
| `workspace.delete`   | μετάλλαξη | Εγκατάσταση*  | `owner`        | `id`         | γραμμή μητρώου σημαδεμένη ως διαγραμμένη |

* Το `workspace.delete` δεν έχει εμβέλεια, επειδή η γραμμή που σημαδεύει ζει στο καθολικό
μητρώο· ο χειριστής του ελέγχει την ιδιότητα μέλους του καλούντος στον επώνυμο χώρο
εργασίας και απαιτεί `owner`.

Το `path` σε κάθε απόκριση είναι μια διαδρομή στον **κεντρικό υπολογιστή του διακομιστή**.

Το `server.listOrphanedBackups` επιστρέφει μία εγγραφή ανά χώρο εργασίας που δεν είναι πλέον
ενεργός: `workspace_id`, `workspace_name` όταν το μητρώο εξακολουθεί να το γνωρίζει, και
`backups`. Ένας διαγραμμένος χώρος εργασίας δεν μπορεί πλέον να περάσει έλεγχο ρόλου χώρου
εργασίας, οπότε τα αντίγραφά του ανήκουν στον ιδιοκτήτη της εγκατάστασης. Το
`server.deleteOrphanedBackup` αρνείται έναν ενεργό χώρο εργασίας, του οποίου τα αντίγραφα
μένουν πίσω από το `workspace.deleteBackup` και τους ρόλους αυτού του χώρου εργασίας. Και οι
δύο λειτουργίες διαγραφής δέχονται μόνο ένα καταγεγραμμένο όνομα καταλόγου χρονοσφραγίδας,
όχι διαδρομή.

Το `workspace.importHolds.list` επιστρέφει όσα κράτησε πίσω μια εισαγωγή. Κάθε κράτηση έχει ένα `id`, ένα `kind` (`action_policy`, `sandbox_exec_grant`, `repo_grant`, `membership_role` ή `invite`), το `payload` που θα επανέφερε, το `imported_at` και το `source_install_id`. Το `workspace.importHolds.resolve` με `accept: true` τη χορηγεί ξανά και με `false` την αφαιρεί. Το `applied` είναι false όταν όποιος ή ό,τι αφορούσε η χορήγηση δεν ανήκει πλέον στον χώρο εργασίας.

:::note[Ένα στιγμιότυπο ολόκληρης της εγκατάστασης απαιτεί τον ιδιοκτήτη και στις δύο λωρίδες]
Τα `server.backupNow`, `server.listBackups` και `server.deleteBackup` απαιτούν τον
**ιδιοκτήτη** της εγκατάστασης (`ServerAuthority.serverOwner`), την ίδια πύλη με το
`GET /backup/snapshot`. Ένα στιγμιότυπο καταγράφει τη βάση δεδομένων κάθε χώρου εργασίας,
οπότε το να είστε διαχειριστής ενός χώρου εργασίας δεν αρκεί για να διαχειριστείτε τους
άλλους. Η διαγραφή δέχεται μόνο το όνομα του καταλόγου χρονοσήμανσης που εμφανίζεται στη
λίστα, όχι μια αυθαίρετη διαδρομή διακομιστή, και αφαιρεί ολόκληρο το στιγμιότυπο (μαζί και
τα μη επαληθευμένα). Οι εξαγωγές και οι λήψεις προγραμματισμένων αντιγράφων ασφαλείας ανά χώρο εργασίας μένουν στον διαχειριστή του χώρου εργασίας.
:::

:::note[Η επαναφορά ανήκει στον κάτοχο του διακομιστή]
`workspace.import` και `POST /backup/restore` κάνουν τον διακομιστή να υιοθετεί ένα αρχείο βάσης δεδομένων, των οποίων οι εγγραφές θεωρούνται πλέον δικές του: συνδέσεις αποθετηρίων και ποιος τις δημιούργησε, ορισμοί περιβαλλόντων που τρέχουν στον ξενιστή, διαδρομές worktree και καταγραφών. Γι' αυτό και τα δύο απαιτούν τον κάτοχο του διακομιστή (`ServerAuthority.serverOwner`), ο οποίος πρέπει να είναι και ιδιοκτήτης του χώρου εργασίας. Όποιος άλλος, και κάθε καλούντας σε ξενιστή χωρίς καταγεγραμμένο ιδιοκτήτη, απορρίπτεται με `server_owner_required`. Κανένα trigger, προβολή, στήλη ή περιορισμός που φέρνει το αρχείο δεν υιοθετείται.
:::

### Απόκριση του `server.listBackups`

Από το νεότερο προς το παλαιότερο, ταξινομημένα κατά όνομα καταλόγου (που είναι η
χρονοσήμανση, οπότε η σειρά ισχύει ακόμη και για ένα στιγμιότυπο του οποίου το μανιφέστο
δεν μπορούσε να διαβαστεί).

```json
{
  "backups": [
    {
      "path": "/…/backups/2026-07-28T09-12-33-000Z",
      "name": "2026-07-28T09-12-33-000Z",
      "created_at": "2026-07-28T09:12:33.000Z",
      "bytes": 481203712,
      "complete": true,
      "workspaces": [
        {
          "workspace_id": "w_9f2c…",
          "path": "/…/backups/2026-07-28T09-12-33-000Z/w_9f2c…/workspace.db",
          "bytes": 190840832
        }
      ],
      "skipped_workspace_ids": []
    }
  ]
}
```

Το `created_at` παραλείπεται όταν το μανιφέστο δεν μπορούσε να διαβαστεί. Το `bytes` στο
ανώτατο επίπεδο είναι το πραγματικό μέγεθος στον δίσκο ολόκληρου του καταλόγου, όχι το
άθροισμα του ίδιου του μανιφέστου — η ερώτηση που θέτει ένας διαχειριστής που καθαρίζει
στιγμιότυπα είναι πόσο κοστίζει ο κατάλογος, όχι τι σκόπευε να γράψει το αντίγραφο
ασφαλείας.

Κάθε `workspaces[].path` είναι ακριβώς αυτό που δέχεται το `workspace.import` ως
`source_path`. Αυτό είναι σκόπιμο: το «επαναφορά αυτού του χώρου εργασίας από αυτό το
στιγμιότυπο» *είναι* η λειτουργία εισαγωγής, ώστε οι δύο να μην μπορούν να αποκλίνουν σε
διαφορετικούς χειρισμούς του ίδιου αρχείου.

### Επικύρωση του `workspace.import`

Πριν αντικατασταθεί οτιδήποτε, το υποψήφιο αρχείο αντιγράφεται σε αρχείο προετοιμασίας δίπλα στον προορισμό και ελέγχεται εκεί. Μια απόρριψη δεν αγγίζει τίποτα και φέρει το είδος της ως `data.kind`.

| Συνθήκη                                          | Αποτέλεσμα                                                       |
| ------------------------------------------------ | ---------------------------------------------------------------- |
| Το αρχείο δεν υπάρχει | Απορρίπτεται, `import.missing_source` |
| Δεν είναι αναγνώσιμη βάση δεδομένων SQLite, ή αποτυγχάνει στο `quick_check` | Απορρίπτεται, `import.damaged` |
| Προέρχεται από στιγμιότυπο και το SHA-256 του διαφέρει από αυτό του μανιφέστου | Απορρίπτεται, `import.checksum_mismatch` |
| Το έγραψε νεότερη έκδοση του διακομιστή | Απορρίπτεται, `import.newer_schema` |
| Άλλο `application_id`, ή δεν υπάρχει `workspace_meta` | Απορρίπτεται, `import.foreign_file` |
| Δεν μπορεί να φέρει στο σχήμα αυτού του διακομιστή | Απορρίπτεται, `import.schema_mismatch` |
| Τα webhooks ή οι προσκλήσεις του δρομολογούνται ήδη σε άλλον χώρο εργασίας | Απορρίπτεται, `import.route_conflict` |
| Το καταγεγραμμένο αναγνωριστικό χώρου εργασίας ≠ του προορισμού | **Επιτρέπεται**. Οι εγγραφές του αντιστοιχίζονται ξανά στον προορισμό. Έτσι αντιγράφεται ένας χώρος εργασίας ή επαναφέρεται υπό νέο αναγνωριστικό |
| Το καταγεγραμμένο αναγνωριστικό εγκατάστασης ≠ αυτής της εγκατάστασης | **Επιτρέπεται**. Τα αναγνωριστικά χρηστών του ανήκουν σε εκείνη την εγκατάσταση και δεν θα επιλυθούν εδώ |

Κατά την αποδοχή, το αρχείο προετοιμασίας φέρνεται στο σχήμα αυτού του διακομιστή και πρέπει έπειτα να ταιριάζει ακριβώς με αυτό. Οι χορηγήσεις που ένα αρχείο δεν επιτρέπεται να χορηγεί στον εαυτό του αφαιρούνται από αυτό: οι εγκρίσεις για εκτέλεση ορισμού περιβάλλοντος στον ξενιστή εκκαθαρίζονται, και οι κανόνες ενεργειών που επιτρέπουν ή ζητούν έγκριση, οι χορηγήσεις εκτέλεσης sandbox, οι χορηγήσεις αποθετηρίων πέραν της ανάγνωσης, οι ρόλοι πέραν του μέλους και οι προσκλήσεις σε αυτούς τους ρόλους γίνονται κρατήσεις προς έλεγχο από τον κάτοχο του διακομιστή. Ο εισαγωγέας διατηρεί ή αποκτά τον ρόλο του ιδιοκτήτη. Η βάση δεδομένων που αντικαθίσταται διατηρείται ως προγραμματισμένο αντίγραφο ασφαλείας με όνομα `<timestamp>-pre-restore`, το αρχείο προετοιμασίας μετονομάζεται στη θέση του με κλειστές τις συνδέσεις του χώρου εργασίας, το `code_index.db` διαγράφεται για να ξαναχτιστεί, και τα ευρετήρια FTS ξαναχτίζονται.

## Διαδρομές μεταφοράς

Οι λειτουργίες εξαγωγής/εισαγωγής και προβολής λίστας στιγμιότυπων παραπάνω μιλούν
με διαδρομές στην πλευρά του διακομιστή, που είναι πλήρης απάντηση μόνο όταν ο
διακομιστής είναι το δικό σας μηχάνημα. Αυτές οι διαδρομές σε σχήμα HTTP
μεταφέρουν τα byte των αντιγράφων ασφαλείας **μέσα στην ίδια πιστοποιημένη,
κρυπτογραφημένη από άκρο σε άκρο σήραγγα πόρων** με άλλους ευαίσθητους πόρους, είτε
η σύνδεση RPC είναι άμεση είτε αναμεταδιδόμενη. Δεν είναι δημόσια τελικά σημεία
μεταφοράς αρχείων HTTP: ένα αίτημα προς μία από αυτές στον δημόσιο ακροατή
επιστρέφει `426 Upgrade Required`, ακόμη και από το loopback. Μέσα στην
κρυπτογραφημένη σήραγγα, η συσκευή που έχει πιστοποιηθεί με Noise πρέπει να
ταιριάζει με το `d`· ο χειριστής ελέγχει επιπλέον την υπογραφή της συσκευής πάνω
στη συμβολοσειρά προορισμού της χρησιμοποιώντας το PSK σύζευξής της και τον ρόλο
παρακάτω.

| Διαδρομή                | Μέθοδος | Παράμετροι      | Υπογεγραμμένος προορισμός      | Απαιτεί                 |
| ----------------------- | ------- | --------------- | ------------------------------ | ----------------------- |
| `/backup/workspace`     | GET     | `w`, `d`, `s`   | `backup-workspace:<workspaceId>` | **διαχειριστής** του χώρου εργασίας |
| `/backup/snapshot`      | GET     | `n`, `d`, `s`   | `backup-snapshot:<name>`       | **ιδιοκτήτης** της εγκατάστασης |
| `/backup/stored`        | GET     | `w`, `n`, `d`, `s` | `backup-stored:<workspaceId>:<name>` | **διαχειριστής** του χώρου εργασίας· **ιδιοκτήτης** της εγκατάστασης μόλις διαγραφεί ο χώρος εργασίας |
| `/backup/restore`       | POST    | `w`, `d`, `s`   | `backup-restore:<workspaceId>` | **ιδιοκτήτης** της εγκατάστασης που είναι επίσης **ιδιοκτήτης** του χώρου εργασίας (`403` με `server_owner_required` διαφορετικά) |

Το `w` είναι αναγνωριστικό χώρου εργασίας, το `n` όνομα καταλόγου στιγμιότυπου ή προγραμματισμένου
αντιγράφου ασφαλείας, το `d` το αναγνωριστικό της καλούσας συσκευής, το `s` η υπογραφή. Στο
`/backup/snapshot`, το `n` επιλύεται απέναντι στη λίστα
αντιγράφων ασφαλείας αντί να συνενώνεται με τη ρίζα των αντιγράφων, οπότε η διαδρομή δεν
μπορεί να στοχεύσει σε κατάλογο που η λίστα δεν θα είχε εμφανίσει. Στο `/backup/stored` πρέπει
να είναι όνομα χρονοσφραγίδας, και το αρχείο πρέπει να είναι πραγματικό αρχείο μέσα στον δικό
του κατάλογο αντιγράφων ασφαλείας αυτού του χώρου εργασίας.

| Κατάσταση | Αιτία                                                                              |
| --------- | ----------------------------------------------------------------------------------- |
| `400` | Λείπει μια απαιτούμενη παράμετρος, ένα όνομα αντιγράφου ασφαλείας δεν είναι έγκυρο, το σώμα μιας μεταφόρτωσης είναι κενό, ή το μεταφορτωμένο αρχείο απορρίφθηκε (το σώμα είναι `{error, kind}` με ένα είδος `import.*`) |
| `403`  | Άγνωστη ή ανακλημένη συσκευή, κακή υπογραφή, ή ο καλών δεν έχει τον ρόλο               |
| `404`  | Δεν υπάρχει θύρα αντιγράφων ασφαλείας σε αυτόν τον κεντρικό υπολογιστή, ή το επώνυμο στιγμιότυπο, αντίγραφο ασφαλείας ή αρχείο χώρου εργασίας δεν υπάρχει |
| `405`  | Κλήση του `/backup/restore` με οτιδήποτε άλλο εκτός από `POST`                        |
| `413`  | Το σώμα της μεταφόρτωσης ξεπερνά τα 8 GiB, είτε κατά το δηλωμένο content-length είτε κατά τα byte που διαβάστηκαν στην πραγματικότητα |
| `426`  | Κάθε άμεσο αίτημα προς διαδρομή μεταφοράς στον δημόσιο ακροατή HTTP· χρησιμοποιήστε την κρυπτογραφημένη σήραγγα πόρων ενός συζευγμένου πελάτη |
| `500`  | Η εξαγωγή ή το αρχείο συμπίεσης απέτυχε στην πλευρά του διακομιστή                    |

Και οι τρεις λήψεις απαντούν `Cache-Control: no-store` με `Accept-Ranges: none`.
Τα `/backup/workspace` και `/backup/snapshot` δημιουργούν ένα **φρέσκο** αντίγραφο ανά αίτημα και το διαγράφουν μόλις μεταδοθεί με ροή, οπότε μια
απόκριση από προσωρινή μνήμη ή μια συνεχισμένη απόκριση θα συνέραπτε byte από δύο
διαφορετικές εξαγωγές σε ένα αρχείο που φαίνεται έγκυρο και δεν είναι.

Το `/backup/stored` είναι η εξαίρεση: μεταδίδει με ροή ένα προγραμματισμένο αντίγραφο ασφαλείας ως `<workspaceId>-<name>.db`
και αφήνει το αρχείο στη θέση του, επειδή αυτό το αρχείο είναι το αντίγραφο.

Το `/backup/snapshot` επιστρέφει `<name>.zip`, με εγγραφές σχετικές με τη ρίζα του
στιγμιότυπου, ώστε η αποσυμπίεση να αναπαράγει `manifest.json` + `global.db` +
`<workspaceId>/workspace.db`. Οι εγγραφές γράφονται σε ταξινομημένη σειρά, οπότε δύο
αρχεία συμπίεσης του ίδιου στιγμιότυπου είναι το ίδιο αρχείο συμπίεσης.

Το `/backup/restore` μεταδίδει το σώμα κατευθείαν σε ένα αρχείο προσωρινής αποθήκευσης αντί
να το αποθηκεύσει ενδιάμεσα, το περιορίζει πριν και κατά τη διάρκεια της ανάγνωσης, και
διαγράφει το αρχείο προσωρινής αποθήκευσης σε **κάθε** διαδρομή εξόδου, ακόμη και σε
άρνηση.

::::caution[Η απευθείας σύνδεση και η αναμετάδοση χρησιμοποιούν την ίδια κρυπτογραφημένη μεταφορά]
Η αναμετάδοση μεταφέρει αιτήματα πόρων, ροές αποκρίσεων και byte μεταφόρτωσης ως
κρυπτοκείμενο· δεν μπορεί να διαβάσει το περιεχόμενο των αντιγράφων ασφαλείας. Μια
διαδρομή στην πλευρά του διακομιστή παραμένει διαδρομή στον ξενιστή του διακομιστή,
όχι αρχείο στην αναμετάδοση. Η πρόσβαση εξακολουθεί να απαιτεί τη συζευγμένη
συσκευή, την υπογραφή προορισμού και τον κατάλληλο ρόλο χώρου εργασίας ή
εγκατάστασης. Καμία από τις δύο μεταφορές δεν κρυπτογραφεί τα παραγόμενα αρχεία
αντιγράφων ασφαλείας σε ηρεμία.
::::

## Διαδρομές και όρια

| Στοιχείο                        | Τιμή                                                        |
| ------------------------------ | ------------------------------------------------------------ |
| Στιγμιότυπα                    | `<dataDir>/backups/<timestamp>/`                             |
| Προγραμματισμένα αντίγραφα ασφαλείας χώρων εργασίας | `<dataDir>/backups/workspace-backups/<workspaceId>/<timestamp>/workspace.db` |
| Εξαγωγές χώρων εργασίας        | `<dataDir>/backups/exports/<workspaceId>-<timestamp>.db`     |
| Βάση δεδομένων που αντικαταστάθηκε από επαναφορά | `<dataDir>/backups/workspace-backups/<workspaceId>/<timestamp>-pre-restore/` |
| Βάσεις δεδομένων όπως ήταν πριν μια ενημέρωση αλλάξει τη μορφή τους | `<dataDir>/pre_upgrade/` και `<dataDir>/<workspaceId>/pre_upgrade/`, οι δύο νεότερες του καθενός |
| Προσωρινή αποθήκευση μεταφοράς | `<dataDir>/backups/transfer/` — ένας πάγκος εργασίας, που τον σαρώνει η διαδρομή που τον γράφει |
| Όνομα αρχείου συμπίεσης στιγμιότυπου | `<snapshot directory name>.zip`                         |
| Όριο μεταφόρτωσης              | 8 GiB ανά κρυπτογραφημένη μεταφόρτωση `/backup/restore`        |
| Διατήρηση                      | Στιγμιότυπα εγκατάστασης: χειροκίνητη διαγραφή. Αντίγραφα ασφαλείας χώρων εργασίας: εβδομαδιαίο pipeline, προεπιλογή 30 ημερών, ή χειροκίνητη διαγραφή. Αντίγραφα ασφαλείας διαγραμμένου χώρου εργασίας: μόνο χειροκίνητη διαγραφή |

Οι κατάλογοι `exports/`, `transfer/` και `workspace-backups/` δεν είναι στιγμιότυπα
εγκατάστασης και εξαιρούνται από το `server.listBackups`. Μόνο ο τελευταίος κατάλογος έχει
προγραμματισμένη διατήρηση, και μόνο όσο υπάρχει ο χώρος εργασίας του· η διαγραφή ενός στιγμιότυπου εγκατάστασης απαιτεί ρητή ενέργεια
του ιδιοκτήτη της εγκατάστασης.
