## Ce vei construi

La finalul acestui tutorial vei avea:

- Un pull request deschis în bancul de lucru pentru PR-uri al Control Center
- Diff-ul citit și un comentariu inline lăsat
- Un verdict de revizuire trimis
- PR-ul îmbinat

Cerințe preliminare: [Trimite primul agent](/ro-RO/manual/tutoriale/primul-agent/) finalizat și un pull request deschis pe un depozit înregistrat în acest spațiu de lucru. Pentru pașii de revizuire, alege un PR pe care nu l-ai deschis tu — butonul **Revizuire** este ascuns pe PR-urile proprii. Îmbinarea funcționează în continuare pe un PR pe care tu l-ai creat.

## Pasul 1: Deschide pull request-ul

1. Apasă **Pull request-uri** în bara laterală
2. Găsește-ți PR-ul și apasă pe el

**Punct de control.** PR-ul se deschide ca un banc de lucru cu tab-uri — Prezentare, Diff, Control sursă, Chat, Acțiuni — focalizat pe **Prezentare**: titlul și acțiunile, descrierea și cronologia activității, plus o bară laterală cu starea, recenzenții, asignații, verificările și fișierele modificate. Dacă apeși un fișier de acolo, sari la el în tab-ul Diff. Tab-ul **Revizuire PR** nu este deschis până când cineva nu cere o revizuire IA.

:::note[Coadă goală cu un îndemn „Conectează GitHub”]
Această stare înseamnă că _serverul_ nu deține niciun token GitHub — clientul tău nu deține niciodată unul. Setează unul în **Setări → Spațiu de lucru → Profil și identitate → Găzduire de cod**, apoi reîmprospătează lista.
:::

## Pasul 2: Citește diff-ul

Deschide tab-ul **Diff**. În stânga se află un arbore de fișiere pliabil, iar banda de deasupra diff-ului conține un selector pentru intervalul de commit-uri — restrânge diff-ul la un commit sau la un interval dintre ele — plus numărul de fișiere și adăugările și ștergerile în curs.

Butonul de setări din bara de instrumente a diff-ului controlează modul în care acesta se afișează:

- Vedere **împărțită** sau **unificată**
- **Încadrează liniile** sau derulează liniile lungi
- **Ligaturi font de cod**

Marchează un fișier ca vizualizat pentru a-ți urmări progresul printr-un diff mare. Navigarea cu tastatura este în [Scurtături de tastatură](/ro-RO/manual/referinta/scurtaturi-de-tastatura/).

## Pasul 3: Lasă un comentariu inline

1. Treci cu cursorul peste o linie din diff — o pastilă mică `+` apare în margine
2. Apasă pe ea ca să comentezi la acea linie, sau trage-o mai întâi vertical pentru a selecta un interval
3. Scrie-ți observațiile. Composerul oferă două butoane de trimitere:
   - **Pornește o revizuire** (sau **Adaugă la revizuire** dacă o revizuire este deja în curs) pune comentariul în coadă. Firul afișează **Revizuire în așteptare** până când trimiți un verdict la pasul 4.
   - **Adaugă un singur comentariu** îl publică imediat pe GitHub. Firul afișează **Se postează…**, apoi **Sincronizat**, și oferă o reîncercare dacă publicarea eșuează.

Pentru acest tutorial, folosește **Pornește o revizuire**, ca să plece comentariul împreună cu verdictul.

:::caution[Un comentariu pus în coadă nu este încă pe GitHub]
**Pornește o revizuire** / **Adaugă la revizuire** păstrează comentariul local până când trimiți un verdict. Doar **Adaugă un singur comentariu** publică imediat. _Corpul_ revizuirii pe care îl scrii la pasul 4 este o schiță separată.
:::

## Pasul 4: Trimite o revizuire

1. Apasă **Revizuire** în rândul de acțiuni din Prezentare — același buton se află și în bara de instrumente a tab-ului Diff. Este ascuns pe PR-urile pe care tu le-ai creat și pe un PR închis sau îmbinat.
2. Scrie un rezumat în composer. Se salvează automat ca schiță, așa că poți închide suprapunerea și reveni.
3. Alege un verdict:
   - **Cere modificări**
   - **Comentează**
   - **Aprobă**

Verdictul este butonul. După **Aprobă** sau **Cere modificări**, butonul se reetichetează ca **Aprobat** sau **Modificări solicitate**. Un verdict **Comentează** îl lasă etichetat **Revizuire**.

**Punct de control.** Butonul afișează „Aprobat” sau „Modificări solicitate” dacă ai ales una dintre aceste două opțiuni.

## Pasul 5: Îmbină

Butonul **Fuzionează** este prezent oricând GitHub raportează că PR-ul poate fi îmbinat — nu este condiționat de propria ta aprobare. Culoarea lui indică gradul de pregătire, nu permisiunea: primară când aprobările și verificările obligatorii sunt verzi, secundară cât timp o verificare încă rulează, distructivă când un recenzent solicitat nu a aprobat sau o verificare eșuează.

1. Apasă **Fuzionează**
2. Alege o metodă: **Squash and merge**, **Creează un commit de fuziune** sau **Rebase and merge**
3. Pentru primele două, editează titlul și mesajul de commit precompletate
4. Confirmă

Orice probleme nerezolvate — „Verificări eșuate”, „Unele revizuiri sunt în așteptare” — sunt listate în panoul derulant înainte să confirmi.

:::caution[Îmbinarea este ireversibilă]
Îmbinarea împinge commit-uri către GitHub. Nu intră niciodată în stiva de anulare a Control Center și nu poate fi anulată de aici.
:::

După îmbinare, se emite un eveniment de domeniu `PrMerged`; analitica și notificările îl consumă. Vezi [Evenimente de domeniu](/ro-RO/manual/referinta/evenimente-de-domeniu/) pentru ce altceva îl ascultă.

## Revizuirea cu IA

Control Center poate pune un pipeline de recenzori pe un PR deschis, dar numai când ceri tu: șablonul `pr_review` are un trigger manual și nimic altceva.

1. Deschide meniul derulant din rândul de acțiuni din Prezentare și alege **Întreabă AI**. Control Center pornește rularea și deschide tab-ul **Revizuire PR**, ca să poți urmări cum lucrează specialiștii.
2. Agenții recenzori își înregistrează constatările ca noduri de revizuire în spațiul PR-ului; un pas final le consolidează într-un singur raport.

Pipeline-ul nu publică în mod deliberat pe GitHub — se încheie după consolidare. Publicarea este un pas separat pe care îl faci singur, cu butonul **Publică pe GitHub** din tab-ul **Revizuire PR**. Vezi [Folosește revizuirea bazată pe IA](/ro-RO/manual/ghiduri-practice/revizuire-ia/).

## Recapitulare

Ai deschis un PR în bancul de lucru, ai citit diff-ul cu evidențiere sintactică, ai lăsat un comentariu inline, ai trimis un verdict și ai îmbinat — fără să părăsești aplicația.

**În continuare:** [Construiește primul pipeline](/ro-RO/manual/tutoriale/primul-pipeline/) pentru a automatiza fluxuri de lucru cu mai mulți pași.
