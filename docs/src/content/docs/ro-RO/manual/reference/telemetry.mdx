Control Center poate trimite **evenimente de utilizare pseudonimizate** către o instanță [Umami](https://umami.is). Statisticile de utilizare sunt **oprite până când operatorul serverului le pornește**. Setarea aparține serverului și se aplică fiecărui client conectat la el: aplicația desktop, aplicația web, telefonul și serverul însuși.

Statisticile de utilizare sunt separate de **Partajează rapoartele de crash**, o setare per dispozitiv pentru diagnosticarea crash-urilor și a erorilor.

## Cine decide

| Comutator | Unde | Efect |
| --- | --- | --- |
| **Partajează statisticile de utilizare** | Configurarea inițială (pasul sandbox) și **Setări → Confidențialitate**. Doar operatorul serverului o poate schimba; ceilalți membri văd valoarea curentă doar în citire | La nivelul întregului server. Stocată ca `telemetry.usage_analytics` în setările serverului. Oprită dacă nu este setată la `true` |
| Tipul build-ului | Automat | Build-urile debug și profile nu trimit nimic. Scriu în schimb fiecare eveniment în jurnalul de depanare |
| `CC_ANALYTICS_DEBUG=1` | Mediul `cc_server` sau fișierul său `.env` | Permite build-urilor debug și profile ale serverului, și ale fiecărui client conectat la el, să trimită date reale, pentru testare. Comutatorul de mai sus trebuie să fie în continuare pornit |
| `DO_NOT_TRACK=1` | Mediul `cc_server` | Oprește raportarea proprie a serverului, indiferent de comutator. Clienții urmează în continuare comutatorul |
| Serverul demo | Automat | Serverul demo public nu trimite nimic în nume propriu. Vizitatorii nu pot schimba comutatorul |

Clienții citesc setarea de la server (`telemetry.config`, apoi în timp real prin `telemetry.watch`). Până sosește răspunsul, evenimentele așteaptă într-un mic buffer în memorie. Dacă răspunsul este nu, buffer-ul este eliminat. Oprirea comutatorului elimină tot ce mai este în coadă și oprește imediat trimiterea, pe fiecare client.

## Ce nu se trimite niciodată

- Conținutul mesajelor, tichetelor, recenziilor sau întâlnirilor, titluri, prompturi, comenzi shell și interogări de căutare
- Nume, conturi de autentificare, adrese de email, avatare și nume afișate
- Căi de fișiere, nume de depozite, nume de ramuri, nume de gazdă și URL-uri (un depozit este trimis doar ca `repo_id` pseudonimizat; un link de întâlnire doar ca furnizorul său)
- Identificatori bruți de orice fel

Fiecare eveniment trece printr-o politică de proprietăți înainte să părăsească procesul. Textul, căile, URL-urile, adresele de email, ID-urile neîmpachetate și șirurile de sub chei precum `email`, `*_name`, `path`, `title`, `prompt`, `content` sau `token` sunt eliminate în loc să fie trimise. Un șir este trimis doar dacă este un token scurt dintr-un vocabular închis, cum ar fi o valoare enum, o versiune, o setare regională sau un ID de model.

## ID-uri pseudonimizate

ID-urile sunt trimise, dar numai ca pseudonime. Fiecare ID de spațiu de lucru, spațiu, conversație, agent, rulare, utilizator și dispozitiv este înlocuit cu un HMAC-SHA256 calculat cu sarea secretă proprie a instalării (`telemetry.pseudonym_salt`), trunchiat la 20 de caractere hexazecimale. Același spațiu de lucru raportează mereu aceeași valoare, astfel încât evenimentele pot fi corelate și numărate, dar ID-ul brut nu părăsește niciodată instalarea. Sarea este creată la prima pornire a serverului și nu este trimisă niciodată furnizorului de statistici. Ștergerea directorului de date al serverului creează o sare și un ID de instalare noi, ceea ce rupe legătura cu tot ce s-a înregistrat înainte.

## Vizualizări de ecran

Fiecare navigare înregistrează o vizualizare de pagină al cărei URL este **șablonul rutei**, de exemplu `/workspaces/:workspaceId/spaces/:spaceId`, niciodată adresa concretă. Numele ecranului este format din segmentele literale ale șablonului, deci pentru acest exemplu este `workspaces_spaces`. Parametrii de rută care se termină în `Id` sunt atașați ca proprietăți `*_id` pseudonimizate, iar cei numerici (de exemplu, un număr de PR) ca numere. Toți ceilalți parametri sunt eliminați.

## Livrare

Evenimentele sunt trimise unul câte unul către `<host>/api/send` dintr-o coadă în memorie de cel mult 200 de evenimente. O eroare de rețea, un timeout, `429` sau `5xx` păstrează evenimentul și reîncearcă cu backoff exponențial, de la 1 secundă până la 5 minute. Orice alt `4xx` îl elimină. Nimic nu se scrie pe disc, așa că evenimentele aflate încă în coadă când aplicația se închide se pierd. Coada este golită când aplicația trece în fundal și când serverul se oprește.

## Direcționarea unui build către altă instanță

Destinația este fixată la momentul build-ului:

```bash
--dart-define=CC_ANALYTICS_HOST=https://analytics.example.com/
--dart-define=CC_ANALYTICS_WEBSITE_ID=<website uuid>
```

Adaptorul furnizorului se află în `packages/cc_analytics`. Suportul pentru un alt serviciu de statistici înseamnă adăugarea unui adaptor acolo. Planul de urmărire și regulile de confidențialitate rămân aceleași.
