`cc_server` găzduiește un singur registru de instrumente MCP (JSON-RPC 2.0), servit pe portul principal al serverului (implicit `9030`) la `POST /mcp` și `GET /sse`, versiunea de protocol `2024-11-05`. Fiecare client ajunge la același registru: aplicația desktop, versiunea web, clienții MCP externi și runtime-ul de agenți încorporat. Serverele MCP externe pot fi conectate în același registru ca un strat dinamic.

## Dimensiunea registrului

| Măsură                                                                              | Număr |
| ----------------------------------------------------------------------------------- | ----- |
| Instrumente înregistrate de `cc_server`                                             | 110   |
| Din `packages/cc_mcp`                                                               | 108   |
| Din `packages/cc_mcp_client` (descoperirea instrumentelor)                          | 2     |
| Înregistrate în registrul de bază (`server_mcp_registry.dart`)                      | 63    |
| Înregistrate după pornire, pe măsură ce serviciile lor devin disponibile (`cc_server_runtime.dart`) | 47    |
| Dintre cele 63 ale registrului de bază, condiționate de un repo cu graf de cod        | 5     |

Cele cinci instrumente de graf de cod sunt înregistrate doar când gazda transmite un repo cu graf de cod către `buildServerMcpRegistry`. `cc_server` transmite mereu unul, așa că toate cele 110 sunt active în binarul livrat.

Registrul complet este anunțat în `tools/list`, fără restricționare la descoperire. Editările de tichete sunt instrumente tipizate.

:::note[Clienții externi văd mereu catalogul întreg]
`tools/list` nu este niciodată trunchiat. Clienții MCP validează numele instrumentelor față de propria copie din cache a acelei liste și refuză orice nu apare acolo fără să întrebe serverul, așa că un instrument ascuns este inaccesibil, nu doar tăcut.

**Harness-ul încorporat** este diferit: încarcă per cerere doar un subset rezident de definiții și aduce restul la prima utilizare, ceea ce este un comportament de partea harness-ului și nu schimbă acest registru. Vezi [Contextul instrumentelor și cache-ul prompturilor](/ro-RO/manual/concepte/contextul-instrumentelor).
:::

:::note[Fiecare clasă de instrumente este înregistrată]
Un fișier sursă din `packages/cc_mcp/lib/src/tools/` este un instrument pe care un
agent îl poate apela. `packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart`
face build-ul să eșueze dacă o clasă de instrumente nouă nu este construită de nimic.
:::

## Parametri comuni

### `workspace_id`

**Obligatoriu** la fiecare instrument care atinge date limitate la spațiul de lucru. Un `workspace_id` lipsă sau nevalid returnează o eroare explicită, iar o valoare care nu corespunde spațiului de lucru al entității țintă este refuzată, nu ignorată în tăcere. Omite-l la instrumentele cu adevărat globale: `list_workspaces` și cele șase instrumente de flux de știri (`list_feeds`, `list_articles`, `get_article`, `set_article_read`, `set_article_saved`, `refresh_feeds`), care se folosesc de lista de fluxuri per utilizator a proprietarului serverului. Instrumentele de descoperire (`search_tool_bm25`, `list_my_tools`) îl primesc opțional, ca să poată clasifica apelabilitatea după modul conversației. Când serverul trimite un agent, spațiul de lucru este impus pe server, așa că agentul nu poate ajunge în alt spațiu de lucru transmitând un id străin.

## Descoperirea instrumentelor

Ambele vin din `cc_mcp_client`, nu din `cc_mcp`, și ambele consultă garda de mod, ca să raporteze ce este apelabil în modul _curent_ al conversației.

| Instrument         | Descriere                                                                                                                   |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `search_tool_bm25` | Caută în catalogul de instrumente după cuvânt cheie; returnează instrumentele potrivite, schemele lor de argumente și dacă fiecare este apelabil chiar acum |
| `list_my_tools`    | Listează instrumentele apelabile chiar acum în această conversație, filtrate după modul ei                                   |

Un al treilea instrument de descoperire, **`search_tools`**, există doar în interiorul harness-ului încorporat și nu face parte din acest registru MCP. El clasează suprafața proprie de instrumente a rulării și, spre deosebire de `search_tool_bm25`, **încarcă** schemele a ceea ce găsește, ca agentul să poată apela o potrivire la următorul tur. Agenții de pe harness ar trebui să îl prefere; clienții MCP au `search_tool_bm25`.

## Mesagerie între agenți și delegare

Agenții vorbesc între ei prin spații (durabile, vizibile în listă). `ask_agent` este cerere/răspuns cu un timeout obligatoriu; `delegate_task` este protejat pe server de un plafon de adâncime, detectarea ciclurilor, o anvelopă bugetară și un plafon de autonomie.

| Instrument      | Descriere                                                                                      |
| --------------- | ---------------------------------------------------------------------------------------------- |
| `send_to_agent` | Trimite un mesaj unidirecțional altui agent, adresat prin `to_agent_id` sau prin `to_agent_name` exact |
| `ask_agent`     | Pune o întrebare altui agent și așteaptă răspunsul lui sau expiră                               |
| `delegate_task` | Deleagă o sarcină altui agent ca tichet copil urmărit                                          |
| `consult_agent` | Adaugă în spațiu specialistul cel mai potrivit după skill-uri și îl trimite cu un brief concentrat |
| `todo_read`     | Citește lista de sarcini persistată a acestei conversații                                      |

## Instrumente pentru medii izolate (stații)

Conduc mașini de unică folosință — un browser sau un desktop Linux într-un mediu
izolat, un emulator Android sau un simulator iOS — din interiorul unei rulări.
Înregistrate după pornire, necondiționat: dacă o mașină poate porni efectiv este o
întrebare de sondare la care instrumentele răspund la fiecare apel. Apelurile
repetate dintr-o conversație refolosesc o singură mașină; capturile de ecran se
întorc ca conținut imagine, cu un buget de o imagine per rezultat, iar conținutul
de pagină/UI extras este delimitat ca date neîncrezute. Cele patru instrumente de
utilizare plus `rig_close` declară [clasa de acțiuni](/ro-RO/manual/concepte/guardrail-uri/)
`enclosureControl` (instrumentele de utilizare declară și `networkEgress` și
`processSpawn`; `mobile_use` și `ios_use` declară și `packageInstall`), așa că
modurile doar-citire le refuză. `rig_list` nu declară niciuna — citește doar starea
spațiului de lucru. Vocabularul complet de verbe pentru fiecare suprafață se află în
[referința stațiilor](/ro-RO/manual/referinta/statii/#action-verbs).

| Instrument     | Descriere                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------- |
| `computer_use` | Conduce un desktop Linux într-o VM izolată: mișcă, dă clic, trage, derulează, tastează, redimensionează, clipboard, captură de ecran |
| `browser_use`  | Conduce un Chromium, Firefox sau WebKit headless (`engine`): navighează, dă clic, completează, extrage (a11y/DOM/consolă), clipboard, captură de ecran |
| `mobile_use`   | Conduce Android prin ADB: inspectare/intrare, capturi de ecran, instalare/pornire/oprire/resetare/dezinstalare de aplicații, link-uri profunde și comenzi de dispozitiv în forma argv |
| `ios_use`      | Conduce simulatorul iOS prin WebDriverAgent/CoreSimulator: inspectare/intrare, capturi de ecran, instalare/pornire/oprire/dezinstalare de aplicații, link-uri profunde și procese de simulator în forma argv |
| `rig_list`     | Listează stațiile unui spațiu de lucru cu suprafața, starea, dimensiunea afișajului și controlerul |
| `rig_close`    | Distruge o stație și aruncă starea mașinii pe care o deține                                        |

## Nu sunt expuse prin MCP

Calendarul și întâlnirile nu au instrumente MCP. Agenții nu pot citi calendarul, întâlnirile, transcrierile, acțiunile de urmat sau deciziile tale. Rezumatul care produce acțiunile de urmat și deciziile rulează ca pipeline-ul încorporat [`meeting_summary`](/ro-RO/manual/concepte/intalniri/), nu ca un instrument pe care un agent îl poate apela.

## Restricționarea instrumentelor după mod

Restricționarea este aplicată de două ori, pornind de la un singur tabel (`ModeToolPolicy`): o dată în dispecerul MCP pentru adaptorul Claude Code și o dată în registrul harness-ului încorporat. Un apel blocat returnează motivul.

| Mod           | Suprafața de instrumente                                                                                                                                                                                                            |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`        | Toate instrumentele înregistrate; fără listă de permisiuni                                                                                                                                                                          |
| `plan`        | O listă de permisiuni atent selectată. Fără scrieri în worktree și fără verbele de tichet `create` / `assign` / `delegate`, dar memoria, artefactele, todo-urile, `submit_plan`, `exit_plan_mode` și verbele de finalizare a tichetului pe tichetul trimis sunt permise |
| `review`      | O listă de permisiuni atent selectată: participare la revizuire, comunicare, preluări de context doar-citire și setul complet de verbe de tichet, inclusiv `create_ticket` și `assign_ticket`                                        |
| `orchestrate` | O listă de permisiuni atent selectată: instrumente de cercetare și de citire, plus `propose_orchestration`, `create_playbook` și `run_playbook`. Angajarea, descompunerea și finalizarea tichetelor se produc determinist după aprobare, niciodată în timpul rulării |

Permise în orice mod, indiferent de lista de permisiuni:

| Set                  | Instrumente                                                                                                                                                                                                                                                       |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Memorie și artefacte | `search_memory`, `propose_fact`, `propose_policy`, `supersede_fact`, `supersede_policy`, `record_observation`, `update_my_notes`, `get_my_notes`, `list_memory_domains`, `list_policies`, `publish_artifact`, `revise_artifact`, `list_artifacts`, `get_artifact` |
| Graf de cod          | `search_code`, `code_symbol`, `code_callers`, `code_callees`, `code_impact`                                                                                                                                                                                       |
| Mecanica rulării     | `search_tool_bm25`, `list_my_tools`, `todo_write`, `todo_read`                                                                                                                                                                                                    |

Faptul de a fi pe o listă de permisiuni nu face un instrument apelabil, și nici invers: capabilitatea de a pune întrebări operatorului este un instrument de **harness** (`ask_user`), așa că nu apare niciodată în acest catalog MCP.

## Instrumente cu poartă de aprobare

Un instrument poate declara `requiresApproval`. Dispecerul construiește atunci un `ApprovalPayload` și îl expune prin `ConfirmationPort` înainte ca instrumentul să ruleze; `cc_server` conectează acel port, așa că poarta este activă.

Instrumentele înregistrate care îl declară: `create_ticket`, `update_ticket`, `assign_ticket`, `reassign_ticket`, `close_ticket`, `ticket_relation`, `create_goal`, `update_goal_progress`, `create_approval`, `decide_approval`, `comment_approval`, `create_work_product`, `save_work_product_revision`, `create_runtime_profile`, `install_skill`, `update_skill`.

Independent, guardrail-urile unificate de acțiuni aplică o poartă oricărui instrument care declară un set nevid de `ActionClass`. O decizie `prompt` fără niciun aprobator conectat este refuzată. Vezi [Guardrail-uri](/ro-RO/manual/concepte/guardrail-uri/).

## Capabilități fără niciun instrument în spate

Nu orice capabilitate din produs este accesibilă unui agent. Acestea nu au niciun
instrument, așa că un nume pe care poate l-ai văzut menționat altundeva returnează „unknown tool":

| Capabilitate                                            | Unde se află în schimb                                                                             |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Angajarea, concedierea sau editarea unui agent           | Interfața de agenți. Nu există niciun instrument `hire_agent` / `fire_agent` / `update_agent`        |
| Crearea unui spațiu de lucru                             | `workspace.upsert` prin RPC, care inițializează și aplică proprietatea                                |
| Proiecte (creare / listare / actualizare / încadrare)    | Interfața de tichete. Proiectele sunt o suprafață de operator — vezi [Organizează munca cu proiecte](/ro-RO/manual/ghiduri-practice/proiecte/) |
| Adresarea unei întrebări blocante operatorului           | Instrumentul de **harness** `ask_user`, nu MCP. Randează un formular în conversație și așteaptă blocat răspunsul |
| Diagnosticarea per agent                                 | Nimic. Nu există `doctor` — vezi [Diagnostichează un agent](/ro-RO/manual/ghiduri-practice/diagnosticare-agent/) |
| Calendar și întâlniri                                    | RPC doar pentru clienții umani (vezi mai sus)                                                         |
