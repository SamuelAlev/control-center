Acest ghid îți arată cum să umpli un spațiu de lucru cu skill-uri de pe GitHub:
adaugi un depozit ca sursă, instalezi skill-urile dorite din el și le menții la zi
în timp.

Lucrul important de știut înainte de a începe: **un depozit sursă este
neîncrezut.** Numele, descrierea și numărul lui de stele sunt scrise de cine îl
deține. Singurul semnal de siguranță în care Control Center are încredere este
verdictul scanării antivirus, prin care trece fiecare instalare înainte ca ceva
să ajungă pe disc sau într-un prompt de agent. Dacă vrei raționamentul, citește
[secțiunea despre skill-uri a modelului agenților](/ro-RO/manual/concepte/modelul-agentilor/); această
pagină rămâne la partea practică.

Skill-urile se află la **Setări → Spațiu de lucru → Abilități**
(`/workspaces/<id>/settings/workspace/skills`). Sunt limitate la spațiul de
lucru: skill-urile pe care le instalezi aici aparțin doar acestui spațiu de
lucru. Pagina are două file: **Instalate** (skill-uri locale, inclusiv un editor
**Abilitate nouă**) și **Surse** (cataloage GitHub). Ambele operații de scriere
trec prin aceeași poartă de scanare.

## Adaugă un depozit de skill-uri

1. Deschide **Setări → Spațiu de lucru → Abilități** și comută pe fila **Surse**.
2. Apasă **Adaugă depozit**.
3. Lipește un URL de depozit GitHub, de exemplu `https://github.com/anthropics/skills`,
   și confirmă.

Serverul verifică dacă depozitul există și este vizibil cu credențialele lui,
apoi îl adaugă în bara laterală din stânga. Nu există un magazin curatoriat la
mijloc: orice depozit GitHub funcționează, ceea ce înseamnă și că reputația este
a ta de evaluat — numărul de stele este o dovadă, niciodată o garanție.

Skill-urile unui depozit sunt directoarele care conțin un `SKILL.md` (până la
trei niveluri în adâncime, plus structura Claude de marketplace de plugin-uri
`plugins/<plugin>/skills/<skill>`, cu arborii de dependențe și cei de vendor
săriți). Dacă grila spune mai târziu că depozitul nu are skill-uri, exact asta
înseamnă: niciun director din el nu respectă convenția de skill-uri.

## Inspectează un skill înainte de instalare

Selectează un depozit în bara laterală; skill-urile lui apar ca o grilă în
dreapta, cu un câmp de filtrare deasupra care restrânge catalogul după nume,
descriere sau slug. Dă clic pe un card pentru a deschide vizualizarea detaliată.
Aceasta arată trei lucruri:

- **README-ul**, redat ca markdown — `README.md` din directorul skill-ului sau
  corpul `SKILL.md` atunci când nu există README.
- **Previzualizarea scanării** — verdictul (`pass`, `warn` sau `quarantine`),
  capabilitățile declarate de conținutul skill-ului (rulează shell, scrie
  fișiere, acces la rețea…) și fiecare constatare înregistrată de scanner.
- **Numărul de fișiere** — o instalare scrie întregul director al skill-ului,
  nu doar `SKILL.md`.

Previzualizarea scanează exact octeții pe care i-ar scrie o instalare, așa că
verdictul pe care îl vezi este verdictul pe care îl primește instalarea; nimic nu
este reevaluat pe la spatele tău.

## Instalează un skill

1. Deschide vizualizarea detaliată a skill-ului.
2. Citește verdictul scanării. Pentru un verdict `warn` sau `pass`, apasă
   **Instalează**.
3. Pentru un verdict `quarantine`, instalarea rămâne dezactivată până când bifezi
   **Înțeleg riscul — instalează oricum**. Acea suprascriere este înregistrată,
   nu presupusă.

Instalarea scrie directorul skill-ului în spațiul de lucru, înregistrează o
fixare în `skills-lock.json` (depozitul sursă, calea, commit-ul din care provine
și un hash de conținut), iar skill-ul devine disponibil pentru agenții din
spațiul de lucru. Un card marcat **Nume folosit** înseamnă că un alt skill
deține deja acel nume la nivel local — dezinstalează-l mai întâi pe acela.

## Actualizează skill-urile în timp

Cardurile skill-urilor instalate poartă insigne: **Instalat** sau **Actualizare
disponibilă** atunci când depozitul a trecut dincolo de commit-ul la care l-ai
fixat. Deschide vizualizarea detaliată și apasă **Actualizează** pentru a relua
descărcarea la noul commit. O actualizare trece prin aceeași poartă de scanare ca
o instalare — un skill a cărui versiune nouă intră în carantină este refuzat, iar
versiunea pe care o aveai rămâne pe loc. Hash-ul versiunii vechi este păstrat în
fișierul de blocare ca referință de revenire.

## Dezinstalează un skill, elimină un depozit

**Dezinstalează** (din vizualizarea detaliată a unui skill instalat sau prin
ștergere din fila Instalate) elimină împreună directorul skill-ului și fixarea
lui din fișierul de blocare — un skill dezinstalat nu lasă nimic în urmă.

**Eliminarea unui depozit** din bara laterală elimină doar catalogul: skill-urile
instalate din el rămân instalate și se actualizează în continuare, pentru că o
fixare înregistrează depozitul după nume, nu printr-o referință la intrarea de
sursă. Adaugă depozitul înapoi dacă vrei să-l răsfoiești din nou.

## Invocă un skill

Skill-urile sunt invocate sub propriul lor spațiu de nume, așa că nu se ciocnesc
niciodată cu comenzile slash încorporate (`/plan`, `/goal`, `/loop`, `/compact`):

- `/skill:<name>` — un skill instalat în acest spațiu de lucru sau atașat
  agentului
- `/skill:<repo>:<name>` — un skill livrat de un repo cu checkout în acest spațiu

Un nume simplu care nu este încorporat se rezolvă în continuare, pentru mesajele
scrise înainte să existe spațiul de nume. `/skill:plan` este ceea ce ajunge la un
skill numit `plan`; `/plan` este întotdeauna cel încorporat.

## Skill-uri limitate la repo

Un repo cu checkout își poate livra propriile skill-uri, în `.agents/skills/`,
`.agent/skills/`, `.claude/skills/`, `.opencode/skills/` sau `skills/`. Acestea
**nu** se instalează prin această pagină. Un agent poartă doar skill-urile
repo-ului în care lucrează în acel moment; ele se schimbă când se mută.
Composerul nu este limitat astfel: `/skill:<repo>:<name>` ajunge la orice repo
din spațiu.

Skill-urile de repo trec prin aceeași scanare cu eșec închis (`pass` / `warn` /
`quarantine`) înainte ca frontmatter-ul lor să ajungă într-un prompt. `warn` este
admis; `quarantine` este reținut, fără nicio suprascriere din partea
operatorului pe acea cale.

Vezi [Skill-uri limitate la repo](/ro-RO/manual/concepte/modelul-agentilor/#repo-scoped-skills) și
[Comenzi slash](/ro-RO/manual/referinta/comenzi-slash/).
