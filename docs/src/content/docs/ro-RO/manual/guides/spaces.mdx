Acest ghid îți arată cum să folosești spațiile. Un **spațiu** este suprafața de
mesagerie din Control Center: o cameră limitată la spațiul de lucru, cu unul sau
mai mulți participanți (tu și/sau agenți), care deține câte un worktree
copy-on-write pentru fiecare repo pentru care a fost creat.

Camerele unu-la-unu și cele cu mai mulți agenți sunt tot spații, distinse doar
prin numărul de participanți. Singura excepție sunt spațiile pe care agenții le
deschid ca să vorbească între ei — vezi
[Spații agent-la-agent](#spații-agent-la-agent) mai jos.

## Creează un spațiu

1. Navighează la **Spații**
2. Dă clic pe butonul **+** de lângă titlul Spații
3. Dă-i un **nume** — obligatoriu. Un nume gol este refuzat; dialogul
   rămâne deschis
4. Opțional, adaugă agenți din spațiul de lucru
5. Când spațiul de lucru are vreun repo, alege pentru care dintre ele
   provisionează acest spațiu worktree-uri. Toate sunt selectate implicit;
   deselectarea tuturor repo-urilor creează un spațiu cu nimic extras
6. Confirmă

Spațiile sunt limitate la spațiul de lucru: vezi doar agenți din spațiul de lucru
curent, iar un spațiu nu expune niciodată date din alt spațiu de lucru.

Fiecare repo este extras la `repos/<name>/` în interiorul spațiului. Un repo care
își livrează propriile skill-uri de agent le contribuie agentului care lucrează în
el — câte un set de repo o dată, schimbându-se pe măsură ce agentul se mută. Din
composer le poți atinge pe oricare cu `/skill:<repo>:<name>`. Vezi
[Skill-uri limitate la repo](/ro-RO/manual/concepte/modelul-agentilor/#repo-scoped-skills).

Suprafața se află la `/workspaces/<id>/spaces`, iar un singur spațiu la
`/workspaces/<id>/spaces/<spaceId>`.

## Setează modul spațiului

Un spațiu nou pornește în modul implicit. Schimbă-l din **lista derulantă de
moduri** din extrema stângă a barei de instrumente a composerului — nu din
dialogul de creare (care nu are câmp de mod) și nu din antetul spațiului.

| Mod             | Efect                                                                                                 |
| --------------- | ----------------------------------------------------------------------------------------------------- |
| **Agent**       | Acces complet. Modul implicit; `chat` la nivel intern, etichetat „Agent” în lista derulantă            |
| **Plan**        | Doar citire și cercetare; livrabilul este un plan tipizat                                             |
| **Orchestrează** | Doar citire și cercetare, plus un singur verb `propose_orchestration`; planul rulează doar după ce îl aprobi |

Shift+Tab comută între modul plan și modul agent fără să deschidă lista derulantă.

Un al patrulea mod, **revizuire**, există, dar nu este oferit în lista derulantă —
este aplicat automat spațiilor de revizuire PR.

Modul este stocat pe spațiu, așa că același agent poate fi în modul plan într-un
spațiu și în modul agent în altul. Fiecare conversație din interiorul unui spațiu
împărtășește modul acelui spațiu.

:::caution[Atenție la insigna de aplicare]
O insignă apare lângă lista derulantă de moduri când agenții spațiului rulează pe un
adaptor care nu poate impune modul pe care l-ai ales. Doar harness-ul încorporat
Control Center filtrează suprafața de instrumente și pune o poartă în fața fiecărui
apel; adaptoarele Claude Code și ACP primesc modul ca o cerere pe care executantul
lor o poate onora sau nu. Absența unei insigne înseamnă „nu se afirmă nimic”, nu
„verificat ca sigur”.
:::

Vezi [Moduri](/ro-RO/manual/concepte/moduri/) pentru modelul complet.

## Gestionează participanții și autonomia per agent

Dă clic pe pictograma cu persoane din antetul spațiului pentru a deschide
**Gestionează participanții**. Pentru fiecare agent aflat deja în spațiu poți:

- Să-l elimini din spațiu
- Să-i setezi **Autonomia** pentru acest spațiu: **Implicit**, **Doar propune**,
  **Acționează cu aprobare** sau **Acționează liber**

Cadranul de autonomie este per (spațiu, agent), așa că un agent în care ai
încredere într-o cameră poate fi ținut pe „doar propune” în alta.

## Reacționează la un mesaj

Treci cu mouse-ul peste un mesaj și dă clic pe pictograma cu zâmbet pentru a
deschide paleta de reacții. Este un set fix de șase: 👍 👎 🎉 ❤️ 👀 ✅. Nu există
un selector liber de emoji — atingerea unui emoji îl comută pentru tine, iar
pastilele agregate apar sub mesaj.

## Deschide o conversație

Un spațiu găzduiește mai multe conversații simultan, iar acestea sunt egale, fără
ierarhie — nu există una principală. Un spațiu păstrează mereu cel puțin o
conversație activă: nu poți arhiva ultima conversație activă, iar deschiderea unui
spațiu care nu are încă niciuna creează o conversație permanentă fără titlu.

Conversațiile apar ca file în editor și ca rânduri imbricate sub spațiu în bara
laterală, odată ce sunt mai multe. **Conversație nouă** se află în meniul de file
nou al editorului și creează o conversație fără titlu, fără nicio solicitare de
titlu — modelul de titluri o denumește după primul mesaj. Folosește una pentru a
rula muncă în paralel cu același agent și același worktree.

Fiecare conversație își păstrează propriul istoric de mesaje și propriile sesiuni
de agent, împărțind în schimb worktree-urile spațiului și modul acestuia.
Închiderea unei file o ascunde; **Arhivează conversația** (rândul din bara
laterală sau meniul contextual al filei de chat) arhivează doar acea conversație.

## Pornește un fir

Treci cu mouse-ul peste orice mesaj și alege **Pornește fir**. Asta deschide o
conversație ancorată la acel mesaj: ancora alimentează contextul agentului noii
conversații cu o singură linie, iar istoricul părintelui **nu** este copiat.

Odată ce un fir are răspunsuri, mesajul de care atârnă dezvoltă un rând dedesubt —
chipurile celor care au vorbit, numărul de răspunsuri și când a sosit ultimul
răspuns. Acel rând este calea de întoarcere: dacă dai clic pe el, se deschide (sau
primește focus) fila firului. Este singura urmă pe care o lasă un fir în fluxul din
care s-a ramificat, motiv pentru care există.

Fila unui fir este intitulată `Thread: <name>` și poartă simbolul de ramură, așa
că două file din același spațiu nu sunt niciodată confundate una cu alta.

Firele nu se imbrică niciodată — ancorarea la un mesaj care se află deja într-un
fir este refuzată. Antetul conversației trimite înapoi la mesajul de ancoră.
Ștergerea mesajului de ancoră șterge firul, iar arhivarea conversației părinte nu
blochează firele ei existente.

## Starea de citire

Marcajele de citire sunt limitate la spațiu, nu la conversație: deschiderea oricărei
conversații din spațiu marchează camera ca citită. Necititele se agregă în
continuare pe toate conversațiile unui spațiu, inclusiv firele. Când conversațiile
sunt listate sub spațiu, punctul de necitit stă pe conversația care are muncă
nevăzută, nu pe rândul părinte.

## Spații agent-la-agent

Spațiile pe care agenții le deschid ca să vorbească între ei sunt grupate separat
în bara laterală, sub **Agenți**, restrânse implicit și afișate estompat. Nu-ți
cresc niciodată insigna de necitite — pălăvrăgeala agenților este discretă prin
construcție, nu printr-o setare pe care trebuie să o găsești.

Tipul unui spațiu este una dintre cinci valori: `topic` (implicitul pentru orice
creezi), `agentPeer`, `system` (gestionat de pipeline), `pr` (creat când o
suprafață de PR are nevoie de o ancoră de worktree și ascuns din bara laterală
până când are mesaje) și `slack` (creat de puntea de chat pentru un fir Slack sau
un DM de bot și tratat ca o conversație umană obișnuită).
