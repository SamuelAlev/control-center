Acest ghid îți arată cum să lucrezi cu Control Center fără să părăsești GitHub:
cere o revizuire IA chiar din pagina PR-ului, pune botului o întrebare într-un
comentariu și continuă conversația în firele lui de revizuire.

Răspunsurile vin prin banda GitHub a spațiului de lucru: propria
[GitHub App](/ro-RO/manual/ghiduri-practice/github-app/) a serverului tău sau
aplicația partajată a Control Center prin Connect. Nu se înregistrează nimic nou și nimic nu trebuie să fie accesibil din
internet: serverul descoperă ce s-a spus pe GitHub prin interogare periodică,
așa că un laptop aflat în spatele unui NAT se comportă exact ca o implementare
publică.

## Cerințe preliminare

- Spațiul de lucru are o bandă GitHub: GitHub App proprie a serverului sau
  Connect, cu aplicația
  [instalată](/ro-RO/manual/ghiduri-practice/github-app/#instaleaz-o-acolo-unde-sunt-depozitele-tale)
  pe contul care deține repozitoriul. O aplicație proprie are nevoie de
  **Pull requests** și **Issues** cu citire și scriere, pe care
  **Creează aplicația mea GitHub** le acordă deja
- Repozitoriul este legat de un spațiu de lucru din Control Center
- Ești [autentificat în GitHub](/ro-RO/manual/ghiduri-practice/integrare-github/)
  pe acest server și poți face push în repozitoriu
- Fără URL de webhook, fără tunel, fără callback — nu e nimic de configurat pe
  partea de rețea

## Găsește numele botului tău

Menționează `@usectrl`, contul GitHub dedicat al Control Center. Acesta este declanșatorul implicit; banda GitHub a spațiului tău de lucru gestionează în continuare solicitarea și publică răspunsurile. Nu ai nevoie de acreditările contului `usectrl`.

Loginul propriu al aplicației, `<appslug>[bot]`, și forma scurtă `@appslug` funcționează și ele. Ca să găsești acest alias opțional pe propria ta aplicație:

1. Mergi la **Setări → Server → Autentificare unică** și derulează până la
   cardul **Aplicații provider**
2. Deschide secțiunea **GitHub** și apasă **Test**
3. Copiază **Login bot** când se completează. Dacă încă afișează indicația de
   câmp gol, loginul este întotdeauna `<appslug>[bot]` — tastează asta, sau
   forma scurtă `@appslug`

GitHub nu afișează conturile App în autocompletarea pentru `@`, așa că aliasurile aplicației trebuie tastate sau copiate. Utilizatorul dedicat `@usectrl` este invocarea implicită; atât `@myapp`, cât și `@myapp[bot]` rămân aliasuri acceptate ale aplicației.

:::note[Alege un nume de aplicație distinct]
Forma scurtă este potrivită ca text. Dacă un utilizator GitHub obișnuit are din
întâmplare același slug ca aplicația ta, menționarea acelui utilizator prin forma
scurtă ajunge tot la bot. Forma completă `@myapp[bot]` este întotdeauna lipsită
de ambiguitate.
:::

## Cere o revizuire din GitHub

Două metode, ambele pornind același pipeline predefinit `pr_review` pe care îl
pornește butonul **Întreabă AI**:

- **Adaugă eticheta `ai-review`** pe PR. Este cel mai apropiat lucru de a atribui
  botul ca recenzent pe care îl oferă GitHub — conturile de aplicație nu pot
  ocupa locul nativ de recenzent solicitat. Contul tău reacționează la PR cu 👀,
  iar revizuirea pornește în Control Center; nu se postează niciun comentariu
- **Comentează `@usectrl review`** (sau doar `@usectrl`) în conversația PR-ului.
  Pe comentariul tău apare un 👀, apoi un răspuns spune că revizuirea a pornit
  (sau că una rulează deja)

Recenzenții lucrează în spațiul de revizuire al PR-ului; citește și publică
constatările ca în
[Folosește revizuirea bazată pe IA](/ro-RO/manual/ghiduri-practice/revizuire-ia/).
Publicarea înapoi pe GitHub rămâne o decizie pe care o iei în Control Center —
pornirea unei revizuiri din GitHub nu publică nimic pe GitHub de la sine.

Eticheta se declanșează o singură dată per PR: adăugarea ei este cererea, și nu
se re-armează când este eliminată și adăugată din nou. Ca să rulezi din nou o
revizuire — după un push, de exemplu — menționează botul.

## Pune o întrebare

Comentează în conversația PR-ului:

```text
@usectrl why does the flaky test in runner_test.dart fail on CI but not locally?
```

Ce se întâmplă, în ordine:

1. Pe comentariul tău apare un 👀, de pe propriul tău cont, ca să știi că
   comentariul a fost văzut
2. Întrebarea este postată în spațiul de revizuire al PR-ului **ca tine** — aceeași
   atribuire ca și cum ai fi tastat-o în Control Center
3. Un agent răspunde în spațiu, iar răspunsul este postat înapoi pe PR. Fiecare
   răspuns începe cu `**Control Center** (for @your-login):`

O întrebare pe un PR fără nicio revizuire încă trezește agentul CEO al spațiului
de lucru; după ce a rulat o revizuire, răspunde agentul care a vorbit ultimul,
așa că continuările ajung la cine are contextul.

## Continuă într-un fir de revizuire

Răspunde într-un fir de revizuire inline din care botul face parte — un comentariu
pe diff lăsat de el, sau un răspuns postat de el în acel fir. Nu e nevoie de
nicio mențiune; firul **este** adresarea:

```text
> @usectrl the retry loop looks O(n²) to me

what would the complexity be with the bounded queue instead?
```

Conversația pe mai multe replici funcționează la fel: fiecare răspuns este o nouă
întrebare în aceeași conversație, cu spațiul de revizuire ca context, iar
răspunsul se întoarce în fir.

O continuare pe cronologia conversației PR-ului este un comentariu nou de nivel
superior, așa că are nevoie în continuare de o mențiune cu @.

## Cu cine vorbește botul

Serverul rezolvă autorul unui comentariu, sau pe cel care a adăugat eticheta
`ai-review`, înainte de a face orice:

- **Contul GitHub trebuie să fie autentificat** pe acest server. Potrivirea se
  face după id-ul numeric al contului GitHub, niciodată după login.
  Autentifică-te din **Setări → Spațiu de lucru → Profil și identitate →
  Găzduire de cod**
- **Persoana trebuie să fie membru cu un rol de scriere** (`member`, `admin`
  sau `owner`) în spațiul de lucru care leagă repozitoriul
- **Persoana trebuie să poată face push** în repozitoriu pe GitHub. Răspunsurile
  folosesc un token limitat la accesul acelei persoane, așa că cineva care poate
  doar citi nu primește niciun răspuns

Oricine altcineva este ignorat în tăcere: nu se postează nimic, iar vorbele lui
nu intră niciodată în spațiul de lucru. Comentariile boților și răspunsurile
proprii ale Control Center nu sunt niciodată tratate drept întrebări.

### Două servere, un singur PR

👀 este și felul în care serverele se înțeleg cine răspunde. Este adăugat cu
autentificarea proprie a autorului, iar GitHub îi spune serverului dacă reacția
este nouă. Dacă ești autentificat pe două servere Control Center care leagă
amândouă repozitoriul, primul care reacționează răspunde, iar celălalt tace.
Același lucru e valabil pentru etichetă.

## Ce să te aștepți

| Lucru                | Comportament                                                             |
| -------------------- | ------------------------------------------------------------------------ |
| Confirmare           | 👀 de pe contul tău pe comentariu (sau pe PR, pentru etichetă), în decurs de o scanare |
| Răspunsuri           | Postate în firul în care a fost pusă întrebarea, începând cu `**Control Center** (for @your-login):`. Pe o aplicație proprie, autorul este botul aplicației; prin Connect este contul tău, acționând prin aplicația partajată |
| Atribuirea în spațiu | Întrebarea este a ta; agentul rulează în numele tău, sub setările de autonomie ale spațiului |
| Revizuiri            | Constatările ajung în spațiul de revizuire; publicarea pe GitHub este manuală |

O scanare rulează în fiecare minut pe o aplicație proprie și verifică până la 25
de pull request-uri; prin Connect rulează la fiecare două minute și verifică
până la 10, pentru că acele apeluri împart cota GitHub proprie a fiecărui
membru. Un spațiu de lucru a cărui cotă GitHub este sub 15% este sărit până se
reface. Latența este prețul plătit pentru a nu avea deloc nevoie de acces de
rețea de intrare. Nimic nu se pierde cât timp serverul este offline — un comentariu care sosește în timpul unei
perioade de nefuncționare este prins la scanarea următoare.

## Depanare

**Nu se întâmplă nimic pentru un comentariu care menționează botul.**

- Aplicația este **instalată** pe contul care deține repo-ul, iar repo-ul este
  **legat** de un spațiu de lucru? Un repo nelegat este sărit înainte de a se
  înregistra ceva, așa că legarea lui mai târziu livrează totuși
- Ești autentificat în GitHub pe acest server, membru cu un rol de scriere și
  poți face push în repo? Serverul îi ignoră pe toți ceilalți fără să răspundă
- Pe aplicația partajată a Control Center, instalarea organizației este
  autorizată pentru acest server? Vezi
  [Autorizează acest server pentru o organizație](/ro-RO/manual/ghiduri-practice/github-app/#autorizează-acest-server-pentru-o-organizație)
- Tot nimic? Jurnalul serverului numește scanarea și PR-ul când ceva eșuează;
  caută `pr_conversation:` (interogatorul) și `github_pr_conversation:` (puntea)

**Eticheta nu pornește o revizuire.**

Se declanșează o singură dată per PR, iar persoana care a adăugat-o trece prin
aceleași verificări ca autorul unui comentariu. Dacă o revizuire a rulat deja, sau eticheta
a fost adăugată înainte ca serverul să vadă vreodată PR-ul (prima scanare
înregistrează restanța în silență, în loc să o ia cu asalt), menționează botul în
schimb — `@usectrl review` pornește întotdeauna una, dacă nu este deja o revizuire
în curs.

**Răspunsul botului nu a ajuns niciodată pe GitHub.**

Răspunsul în sine nu se pierde niciodată — se află în spațiul de revizuire al
PR-ului din Control Center. O eroare de postare (GitHub căzut, permisiuni
schimbate) este consemnată în jurnal, iar răspunsul nu este reîncercat; întreabă
din nou în fir dacă contează.
