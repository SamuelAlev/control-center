Acest ghid arată cum să adaugi un agent într-un spațiu de lucru și să îl configurezi până când poate rula cu adevărat.

Fiecare spațiu de lucru este populat cu cinci agenți — un CEO plus `qa`, `architect`, `engineer` și `librarian` — așa că de obicei ai agenți înainte să fi configurat vreunul. Pașii de mai jos se aplică în egală măsură unui agent populat și unuia nou.

## Înainte de a începe

- Te afli într-un spațiu de lucru. Întreaga suprafață se află la **Setări → Spațiu de lucru → Agenți** (`/settings/workspace/agents`).
- Agentul va avea nevoie de un backend. Fie conectezi un provider pentru harness-ul încorporat la **Setări → Server → Provideri de modele**, fie instalezi CLI-ul Claude Code pe mașina care găzduiește `cc_server`.
- Dacă vrei ca agentul să poarte abilități, instalează-le mai întâi la **Setări → Spațiu de lucru → Abilități**. Formularul agentului îți permite doar să comuți abilitățile care există deja în spațiul de lucru.

## Adaugă agentul

1. Deschide **Setări → Spațiu de lucru → Agenți**.
2. Apasă **Agent nou**.

Nu există niciun dialog și niciun selector de rol. Un agent numit „Agent fără nume" este creat imediat și selectat în panoul de detalii din dreapta.

Ar trebui să vezi acum „Agent fără nume" în lista din stânga, cu fila **Setări** a panoului său de detalii deschisă și un câmp **Nume** care conține „Agent fără nume".

## Dă-i un nume

- **Nume** — identificatorul scurt folosit în mențiunile cu @, de exemplu `alice`. Analizarea mențiunilor potrivește `@` urmat de caractere de cuvânt, așa că un nume care conține o cratimă, un punct sau un spațiu nu poate fi niciodată menționat.
- **Titlu** — eticheta lizibilă pentru oameni, de exemplu „Programator senior".
- **Prompt de sistem** — instrucțiuni suplimentare opționale, injectate ca o secțiune „Agent instructions"; ele nu înlocuiesc restul promptului compus.

Apasă **Salvează modificările** în partea de jos a formularului. Toate câmpurile de pe această pagină sunt salvate de acel singur buton.

## Dă-i un adaptor și un model

Lista derulantă **Adaptor** enumeră runnerii pe care îi are efectiv gazda serverului. Adaptorul încorporat este întotdeauna găsit (este serverul). Claude Code apare doar când CLI-ul său a fost detectat pe acea gazdă:

| Adaptor                   | Backend                                       |
| ------------------------- | --------------------------------------------- |
| Control Center (built-in) | Bucla de agent din proces — niciun CLI extern |
| Claude Code               | `claude -p --output-format stream-json`       |

Doar adaptorul încorporat impune moduri, dirijare, pauză/reluare, contracte de finalizare și subagenți. Claude Code nu îți oferă niciunul dintre ele. Cursor, Codex și ceilalți provideri de modele se atașează la adaptorul încorporat, nu ca runneri separați.

:::note[Un adaptor gol înseamnă bucla încorporată]
Un agent al cărui adaptor nu este setat este trimis către **Control Center (built-in)**, bucla din interiorul serverului, așa că nu trebuie instalat nimic pe gazdă. Dacă nici modelul nu este setat, cere de la Anthropic valoarea lui implicită, așa că un agent complet nesetat rulează doar dacă ai conectat un cont Anthropic. Specialiștii populați vin fără niciunul dintre ele; setează-le pe amândouă pe orice agent pe care intenționezi să îl folosești.
:::

Lista derulantă **Model** este determinată de adaptorul pe care l-ai ales. Pentru adaptorul încorporat, lista vine în timp real de la providerii pe care i-ai conectat la **Setări → Server → Provideri de modele**, așa că un provider fără acreditare stocată contribuie cu zero modele.

## Adaugă abilități

**Abilități** este un selector cu cipuri pentru pachetele de abilități instalate în acest spațiu de lucru. Atinge un cip pentru a-l comuta; simbolul de bifă le marchează pe cele selectate. Dacă spațiul de lucru nu are abilități, câmpul afișează „No skills available. Create skills in Settings → Skills first."

Aici nu alegi abilitățile proprii ale unui repo. Un repo care le livrează (în `.agents/skills/`, `.claude/skills/` sau `.opencode/skills/`) le contribuie automat agentului care lucrează în acel repo, iar ele se schimbă când acesta se mută în altul — vezi [Skill-uri limitate la repo](/ro-RO/manual/concepte/modelul-agentilor/#repo-scoped-skills).

## Setează linia de raportare și personajul

- **Raportează către** — alege un alt agent după nume. Astfel se construiește arborele de raportare afișat de butonul **Organigramă** din antetul paginii. Nu este lista pe care o folosește un lider de echipă când deleagă — aceea provine din membrii echipei și abilitățile lor.
- **Personaj** — text liber care modelează tonul și comportamentul, de exemplu: „Preferă soluții simple și lizibile. Scrie teste pentru tot codul nou."

## Ajustează rularea

- **Efort de raționament** — opțiunile provin din nivelurile publicate ale modelului selectat: Low / Medium / High, plus Extra High la modelele în stil OpenAI și Extra High + Max la cele în stil Claude. Câmpul este ascuns complet când modelul selectat nu declară niveluri de gândire și folosește valoarea implicită a modelului.
- **Dimensiunea ferestrei de context** — precompletată din fereastra de context a modelului ori de câte ori schimbi modelul, cu cipuri de un singur clic pentru valoarea implicită a modelului, 200k, 500k și 1M. O valoare tastată după ce alegi modelul are prioritate până la următoarea schimbare de model.
- **Timeout de tăcere (minute)** — încheie o rulare după acest interval fără nicio ieșire. Lasă-l gol pentru a folosi valoarea implicită pentru fiecare mod.

## Acordă permisiuni

**Permisiuni sandbox** pornește pe „Folosește implicitul spațiului de lucru". Activează comutatorul pentru a le seta pentru acest agent, apoi comută:

- **Permite git push** — injectează tokenul GitHub de care are nevoie agentul pentru a face push
- **Permite apeluri GitHub API** — îi permite agentului să citească PR-uri, issues și metadate de repo
- **Permite apeluri ticketing API** — injectează cheia providerului de ticketing
- **Permite accesul general la rețea** — activează și instrumentele `web_fetch` și `web_search` ale harness-ului încorporat

Fiecare comutator este verificat de brokerul de acreditări la lansarea rulării: o capacitate oprită înseamnă pur și simplu că tokenul corespunzător nu este niciodată emis în mediul rulării.

:::caution[Implicitul spațiului de lucru înseamnă setul conservator al serverului]
Un agent lăsat pe „Folosește implicitul spațiului de lucru" rulează cu git push, GitHub API și ticketing toate **oprite** și rețeaua **pornită**. Valorile implicite ale capacităților afișate la Setări → Server → Diagnosticări și confidențialitate sunt o preferință de client. Dacă vrei ca un agent să facă push sau să deschidă PR-uri, activează comutatorul și acordă capacitățile în mod explicit.

Aceste capacități controlează acreditările și instrumentele harness-ului, un strat separat de sandbox-ul sistemului de operare. `cc_server` învelește rulările agenților în sandbox-ul gazdei acolo unde există unul — Windows nu are niciun backend nativ, iar Linux și WSL2 au nevoie de `bwrap` și `socat`. Vezi [Sandbox și securitate](/ro-RO/manual/concepte/sandbox-si-securitate/) pentru setul complet de granițe.
:::

## Verifică dacă rulează

1. Deschide **Setări → Server → Provideri de modele** și confirmă că adaptorul pe care l-ai ales raportează o versiune instalată, nu „Negăsit". Apasă **Reîmprospătează** pentru a re-sonda — sondarea rulează pe mașina care găzduiește `cc_server`, nu pe mașina la care te uiți.
2. Deschide un spațiu cu agentul și trimite-i un mesaj, sau menționează-l cu @ într-un spațiu existent.
3. Revino la **Setări → Spațiu de lucru → Agenți**, selectează agentul și deschide fila **Jurnale**. Ar trebui să apară o rulare cu un ecuson de stare, o durată, o oră de începere și adaptorul folosit. **Vizualizează** deschide fluxul de evenimente al acelei rulări.

Dacă nu apare nicio rulare, parcurge [Diagnostichează un agent](/ro-RO/manual/ghiduri-practice/diagnosticare-agent/).

## Șterge un agent

Selectează-l în listă. Pe fila **Setări**, derulează până la **Zonă periculoasă** din partea de jos a formularului și apasă **Șterge**.
