Acest ghid îți arată cum să conectezi provideri de modele și cum să alegi pe ce
rulează un agent.

Tot ce este aici se află pe o singură pagină: **Setări → Server → Provideri de
modele**. Intrarea din sub-bara laterală scrie „Provideri de modele”; titlul
paginii scrie „Adaptori”.

## Ce este un adaptor

Un adaptor este _runnerul_ care execută o rundă de agent. Există două, iar lista
este fixă — nu poți adăuga un al treilea.

| Adaptor                   | CLI       | Transport                                                     |
| ------------------------- | --------- | ------------------------------------------------------------- |
| Control Center (încorporat) | niciunul | Bucla de agent din proces, vorbește cu providerii prin HTTP    |
| Claude Code               | `claude`  | `claude -p --output-format stream-json`                       |

Cursor, Codex, Anthropic, OpenAI și restul sunt **provideri** pe adaptorul
încorporat, nu CLI-uri separate. Ce _poți_ adăuga este un alt provider — orice
endpoint compatibil OpenAI sau Anthropic. Despre asta este secțiunea următoare.

:::note[Detectarea interoghează serverul, nu mașina ta]
Cardul **Runnere detectate** listează ce a găsit `cc_server` în `PATH`-ul
_mașinii gazdă a serverului_. Pe un client subțire sau web, aceea este o altă
mașină decât cea la care te uiți. Instalează CLI-ul pe mașina care rulează
`cc_server`.
:::

## Conectează un provider de model

Adaptorul încorporat are nevoie de cel puțin un provider conectat ca să poată
rula. Catalogul include paisprezece.

1. Mergi la **Setări → Server → Provideri de modele**
2. Derulează până la **Provideri și modele**
3. Găsește-ți providerul și conectează-l:

| Provider                                                                                                 | Cum se conectează                                                                                                             |
| -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Anthropic                                                                                                | Cheie API. Un abonament Claude Pro/Max nu este o autentificare API Anthropic — pentru acel plan folosește adaptorul Claude Code |
| OpenAI, Codex, Cursor                                                                                    | Autentificare OAuth în browser sau o cheie API. Codex este ChatGPT Plus/Pro prin backend-ul Codex Responses, nu o lansare de CLI |
| Kimi Code                                                                                                | Doar OAuth în browser — un flux de tip device-code. Este un plan cu tarif forfetar, deci nu are preț pe token                 |
| OpenRouter, Google Gemini, DeepSeek, Mistral, xAI, z.ai, z.ai GLM Coding Plan, Moonshot (Kimi API)       | Cheie API                                                                                                                     |

Punct de verificare: insigna rândului trece în starea conectat, iar extinderea
lui listează modelele pe care le servește providerul, fiecare cu prețul pe milion
de tokeni și fereastra de context.

Tokenurile OAuth ajung în depozitul propriu de credențiale al serverului și sunt
reîmprospătate înainte de a expira. Credențialele providerilor sunt **globale la
nivel de gazdă** — sunt partajate de fiecare spațiu de lucru de pe instalare, nu
sunt limitate la unul singur.

### Adaugă un provider personalizat

Folosește asta pentru Ollama, LM Studio, vLLM sau o implementare privată.

1. În **Provideri și modele**, sub **Provideri personalizați**, apasă **Adaugă
   provider**
2. Completează un **nume**, alege **tipul de API** (compatibil OpenAI sau
   compatibil Anthropic) și dă **URL-ul de bază** (de exemplu
   `http://localhost:11434/v1`)
3. Adaugă o **cheie API** dacă endpointul are nevoie de una, apoi apasă **Adaugă
   provider**

Un provider personalizat apare în aceeași listă, cu un buton de ștergere pe care
frații lui încorporați nu îl au.

## Alege un model pentru un agent

1. Mergi la **Setări → Spațiu de lucru → Agenți** și selectează agentul
2. În fila **Setări**, alege **adaptorul**
3. Alege **modelul** din lista derulantă de lângă el

Pentru adaptorul încorporat, lista derulantă este compusă în timp real din
catalogul propriu al fiecărui provider conectat. Un provider fără nicio
credențială stocată contribuie cu zero modele, motiv pentru care o listă
derulantă goală înseamnă aproape întotdeauna „încă nu este conectat nimic”, nu
„nimic disponibil”.

:::note[models.dev este un plus de informație, niciodată o sursă de id-uri]
Catalogul [models.dev](https://models.dev) inclus furnizează prețul și fereastra
de context pentru un model care se află deja în lista live. Nu adaugă niciodată
un id de model. Dacă un model pe care îl aștepți lipsește, endpointul
providerului nu îl returnează.
:::

Id-urile de model pentru adaptorul încorporat sunt calificate `provider/model`
și pot purta un lanț de rezervă separat cu `|`. În cazul unui lanț de rezervă,
costul este calculat pentru modelul care a servit efectiv runda, nu pentru cel
pe care l-ai cerut.

:::note[Un agent fără adaptor rulează pe bucla încorporată]
Fiecare spațiu de lucru creează cinci agenți — un CEO plus `qa`, `architect`,
`engineer` și `librarian` — fără adaptor și fără model. Trimiterea revine la
**Control Center (încorporat)**, nu la setarea **Runnere implicite** de pe
această pagină, care este o preferință de client ce nu este citită niciodată de
calea de trimitere. Jurnalul rulării înregistrează `cc-harness` pentru acele
rulări, astfel încât transcriptul numește ce a rulat efectiv.

Fără model, bucla încorporată cere de la Anthropic modelul său implicit. Un
agent lăsat complet neconfigurat rulează așadar dacă ai conectat un cont
Anthropic și, în caz contrar, eșuează cu `No credential for provider "anthropic"`.

Finalizarea pasului de adaptor din onboarding **modifică retroactiv fiecare**
agent căruia îi lipsește încă un adaptor sau un model — CEO și specialiști, în
fiecare spațiu de lucru care există în acel moment — cu perechea pe care ai
ales-o. Spațiile de lucru create mai târziu tot pornesc cu toți cinci
neconfigurați. Setează explicit adaptorul și modelul pe fiecare agent pe care
intenționezi să îl folosești.
:::

## Instalează un CLI de runner

Adaptorul încorporat nu are nevoie de instalare. Pentru Claude Code, instalează
CLI-ul **pe mașina gazdă a serverului** cu managerul de pachete al acelui
instrument, de exemplu:

```bash
npm install -g @anthropic-ai/claude-code
```

Apoi apasă **Reîmprospătează** în partea de sus a paginii. Fiecare rând detectat
arată versiunea și calea rezolvate, plus etichete pentru dacă suportă modul JSON
și selectarea modelului.

Un CLI extern își păstrează propriile credențiale, în propria configurare, pe
mașina gazdă a serverului. Control Center nu le gestionează.

:::caution[Argumentele adaptorului și variabilele de mediu rămân pe acest dispozitiv]
Fiecare rând de adaptor oferă un câmp **Argumente** și un dialog **Variabile de
mediu**. Acele valori sunt stocate pe dispozitivul tău. Serverul citește argv-ul
de lansare și variabilele de mediu din propriul depozit de setări. Pune cheile
providerilor pe server (OAuth sau câmpul de cheie din pagina Provideri de
modele), nu în acele două câmpuri.
:::

## Restrânge ce provideri poate folosi un spațiu de lucru

Guvernanța providerilor este per spațiu de lucru și se evaluează după regula
ultimul-potrivit-câștigă.

1. În **Provideri și modele**, dezactivează comutatorul **Permite** de pe rândul
   unui provider

Asta scrie o instrucțiune `deny` pentru acel provider în spațiul de lucru activ,
iar modelele lui ies din catalog pentru acel spațiu de lucru. Revenirea
comutatorului în poziția pornit elimină instrucțiunea.

## Depanare

### Un runner apare ca negăsit

- Verifică faptul că CLI-ul este în `PATH`-ul **mașinii gazdă a serverului**, nu
  doar în al tău
- O aplicație desktop lansată din GUI își pornește serverul cu un `PATH`
  minimal; un CLI instalat într-o cale disponibilă doar în shell poate fi
  invizibil pentru ea
- Apasă **Reîmprospătează** după instalare

### Lista derulantă de modele este goală

- Adaptorul este cel încorporat și niciun provider nu este conectat — conectează
  unul în **Provideri și modele**
- Sau providerul este conectat, dar este blocat de comutatorul de guvernanță al
  acestui spațiu de lucru

### Un model rulează, dar prețul apare ca necunoscut

Lista live de modele conține id-ul; prețul și contextul vin de la models.dev. Un
model nou-nouț sau unul de la un provider personalizat nu are încă o intrare în
catalog.
