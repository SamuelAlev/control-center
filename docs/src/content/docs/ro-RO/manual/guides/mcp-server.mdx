Acest ghid îți arată cum să conectezi un client MCP extern — Claude Code, un
editor, MCP Inspector — la serverul propriu de instrumente al Control Center.

Control Center înregistrează **110** instrumente și le servește prin Model Context
Protocol, la versiunea de protocol `2024-11-05`. Lipsesc familii întregi de
instrumente la care te-ai putea aștepta: nu există instrumente pentru întâlniri sau
calendar și nici instrumente pentru proiecte.

## Găsește endpointul

Suprafața MCP folosește același listener principal `cc_server`. Nu există un port
MCP separat.

| Endpoint | Metodă   | Scop                                                          |
| -------- | -------- | ------------------------------------------------------------- |
| `/mcp`   | `POST`   | Transport HTTP streamable — aceasta este ce vorbește un client |
| `/mcp`   | `DELETE` | Încheie o sesiune                                             |
| `/sse`   | `GET`    | Flux de notificări trimise de server                          |

Așadar, o instalare locală implicită se află la `http://127.0.0.1:9030/mcp`.

1. Mergi la **Setări → Server → Servere MCP**
2. Citește cardul **Server MCP** — arată dacă rulează sau este oprit și portul pe
   care ascultă

Suprafața este activă implicit la o instalare nouă, așa că un client loopback
funcționează fără nicio vizită prin setări. **Pornește la lansarea aplicației**
controlează dacă revine după o repornire; **Pornește** / **Oprește** sunt comenzi de
sesiune care nu schimbă această preferință.

Serverul se leagă la loopback implicit, așa că endpointul este accesibil doar de pe
mașina pe care rulează `cc_server`, în afară de cazul în care l-ai pornit cu
`--bind any`.

## Conectează un client

Îndreaptă clientul către endpointul HTTP streamable. Forma exactă a configurației
este problema clientului tău; URL-ul este același în ambele cazuri.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp"
    }
  }
}
```

### Claude Code

Claude Code nu va prelua acest lucru dintr-un `.mcp.json` de proiect — ține
serverele MCP din sfera proiectului în spatele unui prompt de aprobare la care un
`claude -p` neinteractiv nu răspunde niciodată. Transmite configurația în mod
explicit:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` face ca Claude să folosească doar acel fișier, astfel încât
același server să nu fie descoperit și din proiect și înregistrat de două ori.

Punct de verificare: cere clientului să își listeze instrumentele. Ar trebui să vezi
intrări `mcp__*` care acoperă tichete, spații, memorie, graful de cod și revizuirea.

## Servește MCP dincolo de gazdă

1. În **Setări → Server → Servere MCP**, pe rândul **Token de autentificare**,
   apasă **Setează** și lipește un token
2. Trimite-l ca `Authorization: Bearer <token>` la fiecare cerere `POST /mcp`

O suprafață fără token refuză cu 403 orice apelant care nu vine prin loopback.
Aceasta eșuează închis prin proiectare: tokenul este exact ceea ce face posibil, în
primul rând, serviciul în afara gazdei.

Modificările de token se aplică imediat suprafeței active — fără repornire.

:::note[`GET /sse` preia tokenul din șirul de interogare]
Fluxul de notificări este verificat după token ca orice altă rută, dar un
`EventSource` din browser nu poate trimite un antet `Authorization` — așa că `/sse`
acceptă tokenul și sub forma `?token=<token>`. Fără token, răspunde cu 401.
:::

## Limitează fiecare apel la un spațiu de lucru

Fiecare instrument care atinge date din sfera unui spațiu de lucru necesită
`workspace_id`, iar un apel fără el este refuzat, în loc să fie rezolvat față de un
spațiu de lucru „curent”:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

Id-ul este cel din browser sau din URL-ul aplicației: `/workspaces/<workspace_id>/…`.
Singurele excepții sunt instrumentele care acoperă în mod real mai multe spații de
lucru, cum ar fi `list_workspaces` și instrumentele pentru fluxul de știri — fluxul
de știri este per utilizator, iar un agent nu are un utilizator al lui, așa că acele
instrumente operează pe fluxurile proprietarului serverului.

Instrumentele limitate la un repo verifică în plus dacă repo-ul este legat de acel
spațiu de lucru.

## Află ce va refuza suprafața

- **Filtrarea după mod.** Un apel este rezolvat pe server față de modul spațiului
  agentului apelant. Un agent aflat într-un mod doar în citire nu poate ajunge la un
  instrument de scriere omitând `space_id` — modul este căutat, în schimb, din
  rularea lui activă.
- **Guardrail-urile de acțiune.** Instrumentele care modifică starea își declară
  clasele de efect și trec prin aceeași politică pe care o folosește restul
  produsului. Vezi
  [Configurează guardrail-urile](/ro-RO/manual/ghiduri-practice/configureaza-guardrail-uri/).
- **Confirmarea.** Unele instrumente distructive construiesc o sarcină de confirmare
  care trebuie aprobată înainte ca apelul să continue.

Catalogul complet este anunțat în `tools/list` fără filtrare la descoperire — un
client MCP extern refuză să apeleze un instrument care nu se află în lista lui din
cache, așa că a ascunde instrumentele le strică, în loc să le facă mai ordonate.

## Depanare

### Clientul nu vede niciun instrument

- Verifică dacă pe cardul **Server MCP** scrie că rulează
- Verifică dacă portul corespunde portului tău `cc_server`
- În Claude Code, verifică dacă ai transmis `--mcp-config` și `--strict-mcp-config`

### Eroare 403 de pe o mașină care nu este serverul

Nu este configurat niciun token bearer. Setează unul și trimite-l.

### Un apel de instrument eșuează cu „Missing or invalid argument: workspace_id”

Adaugă `workspace_id`. Nu există niciun spațiu de lucru implicit.

### Un apel de instrument este refuzat ca necunoscut

[Instrumente MCP](/ro-RO/manual/referinta/instrumente-mcp/) listează catalogul.
Apelează numele exact așa cum apare acolo.
