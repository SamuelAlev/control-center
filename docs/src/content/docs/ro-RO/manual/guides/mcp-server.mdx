Acest ghid îți arată cum să conectezi un client MCP extern — Claude Code, un
editor, MCP Inspector — la serverul propriu de instrumente al Control Center.

Control Center înregistrează **110** instrumente și le servește prin Model Context
Protocol, la versiunea de protocol `2024-11-05`. Lipsesc familii întregi de
instrumente la care te-ai putea aștepta: nu există instrumente pentru întâlniri sau
calendar și nici instrumente pentru proiecte.

## Găsește endpointul

Suprafața MCP folosește același listener principal `cc_server`. Nu există un port
MCP separat.

| Endpoint | Metodă   | Scop                                                          |
| -------- | -------- | ------------------------------------------------------------- |
| `/mcp`   | `POST`   | Transport HTTP streamable — aceasta este ce vorbește un client |
| `/mcp`   | `DELETE` | Încheie o sesiune                                             |
| `/sse`   | `GET`    | Flux de notificări trimise de server                          |

Așadar, o instalare locală implicită se află la `http://127.0.0.1:9030/mcp`.

1. Mergi la **Setări → Server → Servere MCP**
2. Citește cardul **Server MCP** — arată dacă rulează sau este oprit și portul pe
   care ascultă

Suprafața este activă implicit la o instalare nouă. Doar proprietarul serverului vede tokenul de pe card și doar el poate porni sau opri endpoint-ul. **Pornește la lansarea aplicației** controlează dacă revine după o repornire; **Pornește** / **Oprește** sunt comenzi de sesiune care nu schimbă această preferință.

Serverul se leagă la loopback implicit, așa că endpointul este accesibil doar de pe
mașina pe care rulează `cc_server`, în afară de cazul în care l-ai pornit cu
`--bind any`.

## Obține tokenul

Fiecare cerere are nevoie de tokenul MCP al serverului, de pe orice mașină, inclusiv de pe loopback. Serverul îl creează prima dată când pornește. Nu există nicio cale să-l dezactivezi sau să-l ștergi.

1. În **Setări → Server → Servere MCP**, găsește rândul **Token de autentificare**
2. Apasă **Afișează tokenul** și copiază-l
3. Ca să îl înlocuiești, apasă **Rotește tokenul**. Serverul trece pe noul token imediat, iar fiecare client care folosește încă pe cel vechi este refuzat până îi dai pe cel nou

## Conectează un client

Îndreaptă clientul către endpointul HTTP streamable și trimite tokenul ca `Authorization: Bearer <token>` la fiecare cerere, inclusiv la `GET /sse`. Nu există altă cale de a-l trimite: un token în URL nu este acceptat. Forma exactă a configurației este problema clientului tău.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code nu va prelua acest lucru dintr-un `.mcp.json` de proiect — ține
serverele MCP din sfera proiectului în spatele unui prompt de aprobare la care un
`claude -p` neinteractiv nu răspunde niciodată. Transmite configurația în mod
explicit:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` face ca Claude să folosească doar acel fișier, astfel încât
același server să nu fie descoperit și din proiect și înregistrat de două ori.

Punct de verificare: cere clientului să își listeze instrumentele. Ar trebui să vezi
intrări `mcp__*` care acoperă tichete, spații, memorie, graful de cod și revizuirea.

## Ce refuză endpoint-ul

Tokenul deschide fiecare unealtă de pe server, așa că endpoint-ul refuză și orice ar fi putut trimite o pagină web, înainte să se uite la token:

| Cerere | Răspuns |
| ------ | ------- |
| Un antet `Origin` care nu este o pagină de pe această mașină (`http://localhost`, `http://127.0.0.1` sau `http://[::1]`, pe orice port) | `403`, "Cross-origin requests are not accepted" |
| Un antet `Host` care nu este nici adresa loopback și portul acestui listener, nici numele public de gazdă al serverului | `403`, "Unknown host" |
| Un `POST` al cărui corp nu este `application/json` | `415` |
| Fără token sau cu unul greșit | `401` |

Ca să servești MCP dincolo de gazdă, pornește serverul cu `--bind any` și trimite tokenul de pe cealaltă mașină, adresând serverul prin numele lui public de gazdă.

## Limitează fiecare apel la un spațiu de lucru

Fiecare instrument care atinge date din sfera unui spațiu de lucru necesită
`workspace_id`, iar un apel fără el este refuzat, în loc să fie rezolvat față de un
spațiu de lucru „curent”:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

Id-ul este cel din browser sau din URL-ul aplicației: `/workspaces/<workspace_id>/…`.
Singurele excepții sunt instrumentele care acoperă în mod real mai multe spații de
lucru, cum ar fi `list_workspaces` și instrumentele pentru fluxul de știri — fluxul
de știri este per utilizator, iar un agent nu are un utilizator al lui, așa că acele
instrumente operează pe fluxurile proprietarului serverului.

Instrumentele limitate la un repo verifică în plus dacă repo-ul este legat de acel
spațiu de lucru.

## Află ce va refuza suprafața

- **Filtrarea după mod.** Un apel este rezolvat pe server față de modul spațiului
  agentului apelant. Un agent aflat într-un mod doar în citire nu poate ajunge la un
  instrument de scriere omitând `space_id` — modul este căutat, în schimb, din
  rularea lui activă.
- **Guardrail-urile de acțiune.** Instrumentele care modifică starea își declară
  clasele de efect și trec prin aceeași politică pe care o folosește restul
  produsului. Vezi
  [Configurează guardrail-urile](/ro-RO/manual/ghiduri-practice/configureaza-guardrail-uri/).
- **Confirmarea.** Unele instrumente distructive construiesc o sarcină de confirmare
  care trebuie aprobată înainte ca apelul să continue.

Catalogul complet este anunțat în `tools/list` fără filtrare la descoperire — un
client MCP extern refuză să apeleze un instrument care nu se află în lista lui din
cache, așa că a ascunde instrumentele le strică, în loc să le facă mai ordonate.

## Serverele MCP personale rămân ale proprietarului

Acest ghid se referă la endpoint-ul propriu al Control Center. Cealaltă direcție, serverele MCP pe care Control Center le dă agenților pe care îi rulează, este listată în **Setări → Server → Servere MCP → Servere MCP externe**. Serverele configurate pe mașina serverului pentru Claude, Codex, Cursor, Gemini, VS Code, Windsurf, OpenCode sau într-un `.mcp.json` sunt găsite acolo automat.

Serverele descoperite vin din configurația de unelte a utilizatorului serverului și acționează cu identitatea și credențialele acelui utilizator, deci aparțin proprietarului serverului:

- Sunt disponibile doar în rulările harness-ului integrat pe care proprietarul serverului le pornește sau pentru care răspunde, inclusiv automatizarea dintr-un spațiu de lucru pentru care proprietarul răspunde.
- Rularea unui membru, automatizarea legată de un membru și fiecare rulare pe un server fără proprietar înregistrat nu primesc niciunul. Acolo uneltele nu sunt listate, nu pot fi apelate și nu apar în căutarea de unelte.
- Acest endpoint nu le listează, nu le apelează și nu le caută niciodată, pentru nimeni, nici cu tokenul proprietarului, și nu transmite nici resursele, nici prompturile lor. Așadar, un CLI de agent care ajunge la Control Center prin MCP, cum este Claude Code, nu le primește nici prin Control Center; folosește propria lui configurație.

Serverele MCP configurate pentru spațiul de lucru nu sunt afectate de nimic din toate acestea.

## Depanare

### Clientul nu vede niciun instrument

- Verifică dacă pe cardul **Server MCP** scrie că rulează
- Verifică dacă portul corespunde portului tău `cc_server`
- În Claude Code, verifică dacă ai transmis `--mcp-config` și `--strict-mcp-config`

### Eroare 401 Unauthorized

Cererea nu avea token, sau avea unul vechi. Copiază tokenul actual din rândul **Token de autentificare** și trimite-l ca `Authorization: Bearer <token>`. Un token din URL este ignorat.

### Eroare 403 de pe un client care mergea înainte

Cererea avea un `Origin` de la o pagină web sau un `Host` la care serverul nu răspunde. Apelează endpoint-ul dintr-un client, nu dintr-o pagină de browser, folosind adresa loopback a serverului sau numele lui public de gazdă.

### Eroare 415 Unsupported Media Type

Trimite corpurile `POST /mcp` ca `application/json`.

### Un apel de instrument eșuează cu „Missing or invalid argument: workspace_id”

Adaugă `workspace_id`. Nu există niciun spațiu de lucru implicit.

### Un apel de instrument este refuzat ca necunoscut

[Instrumente MCP](/ro-RO/manual/referinta/instrumente-mcp/) listează catalogul.
Apelează numele exact așa cum apare acolo.
