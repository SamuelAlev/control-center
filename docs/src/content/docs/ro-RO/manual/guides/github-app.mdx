Acest ghid îți arată cum să îi dai serverului tău propria GitHub App. Durează
aproximativ două minute, o face doar proprietarul serverului și trebuie făcut o
singură dată per server.

:::note[S-ar putea să nu ai nevoie de ea]
Cu Control Center Connect pornit, oamenii se autentifică în GitHub prin
aplicația partajată a Control Center sau prin aplicația pe care o folosește
Connect-ul organizației tale. Înregistrează-ți propria aplicație când ai ales
**Folosește aplicațiile mele**: aplicația proprie a serverului se folosește doar atunci.
Vezi
[Control Center Connect](/ro-RO/manual/referinta/connect/).
:::

Pentru autentificarea în propriul cont după aceea, vezi
[Configurează integrarea GitHub](/ro-RO/manual/ghiduri-practice/integrare-github/).

## Ce face aplicația

O singură înregistrare răspunde la două sarcini diferite:

| Sarcină                         | Ce răspunde                                     | De ce contează                                                                                   |
| ------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **O persoană se autentifică**   | Client id-ul și client secret-ul aplicației     | Fiecare primește propria acreditare GitHub, pe server, pe fiecare dispozitiv                      |
| **Serverul acționează**         | Id-ul aplicației și cheia privată               | Agenții, pipeline-urile, interogatorii și răspunsurile botului primesc tokenuri pentru câte un singur depozit |

A doua sarcină nu împrumută niciodată întreaga acreditare a unei persoane.
Fiecare token pe care îl emite serverul acoperă un singur depozit și este limitat
la ce poate face acolo un membru responsabil. Citirea unui depozit legat are
nevoie doar de aplicație; orice scrie are nevoie de un membru care poate face
push. Automatizarea nu aprobă niciodată un pull request.

Aplicația proprie a serverului se aplică doar sub **Folosește aplicațiile mele**.
Cu Control Center Connect sau cu un Connect propriu, Connect gestionează toate
benzile, inclusiv GitHub; aplicația serverului rămâne salvată, dar nefolosită,
până treci înapoi. Un spațiu de lucru pe propriile aplicații
([Dă unui spațiu de lucru propria aplicație](#dă-unui-spațiu-de-lucru-propria-aplicație))
folosește aplicația proprie în locul celei a serverului, indiferent de modul serverului. O aplicație căreia îi lipsesc unele câmpuri este o eroare, nu o revenire
la alternativă: autentificările GitHub sunt refuzate până când fiecare câmp este
setat.

## Cerințe preliminare

- Ești **proprietarul serverului**. Cardul **Aplicații provider** este invizibil
  pentru toți ceilalți
- Un cont GitHub. Aplicația este creată sub el
- O adresă a serverului pe care browserul tău o poate accesa. URL-ul public al
  serverului (sau loopback, pentru serverul propriu al unui desktop) este locul
  în care te trimite GitHub înapoi

## Creeaz-o dintr-un singur clic

1. Mergi la **Setări → Server → Autentificare unică** și derulează până la
   cardul **Aplicații provider**
2. În blocul **GitHub**, poți tasta opțional organizația GitHub care ar trebui
   să dețină aplicația în **Organizație (opțional)**. Lasă câmpul gol ca să
   creezi aplicația sub propriul cont; crearea ei sub o organizație necesită un
   proprietar al acelei organizații
3. Apasă **Creează aplicația mea GitHub**
4. Browserul deschide GitHub cu aplicația deja completată. Apasă
   **Create GitHub App**
5. GitHub te trimite înapoi la server, care stochează id-ul aplicației, cheia
   privată, client id-ul și client secret-ul, apoi deschide pagina de instalare
   a aplicației

Nimic nu se copiază de mână, iar codul de conversie merge direct de la GitHub la
serverul tău. Linkul funcționează o singură dată și expiră după zece minute;
dacă expiră, apasă din nou **Creează aplicația mea GitHub**.

Aplicația se numește `Control Center <code>` și cere exact ce folosește Control
Center:

| Permisiune                                 | Acces              |
| ------------------------------------------ | ------------------ |
| Metadata                                   | Citire             |
| Contents                                   | Citire și scriere  |
| Pull requests                              | Citire și scriere  |
| Issues                                     | Citire și scriere  |
| Checks, Actions, Commit statuses           | Citire             |
| Organization members                       | Citire             |

Webhook-urile sunt dezactivate: serverul interoghează periodic. Ca să muți mai
târziu într-o organizație o aplicație creată sub propriul cont, folosește
**Transfer ownership** din setările avansate ale aplicației pe GitHub.

Punct de control: blocul GitHub afișează „Serverul poate acționa ca el însuși,
iar oamenii se pot autentifica.”

## Instaleaz-o acolo unde sunt depozitele tale

O aplicație înregistrată, dar neinstalată, poate autentifica oameni și nu poate
citi nimic.

1. Pe pagina de instalare pe care a deschis-o GitHub, alege contul sau
   organizația care deține depozitele tale
2. Alege **All repositories** sau selectează depozitele pe care acest server ar
   trebui să le vadă

Ca să o instaleze mai târziu pe alt cont, un administrator al spațiului de lucru
merge la **Setări → Spațiu de lucru → Integrări**, găsește **Instalări ale
aplicației GitHub** pe cardul **Aplicația GitHub**, din Găzduire de cod, și apasă
**Instalează aplicația GitHub**. Lista arată fiecare cont pe care este instalată aplicația și
semnalează o instalare suspendată.

## Împarte instalarea unei organizații

O organizație instalează GitHub App o singură dată. După aceea, oricine din ea
care se autentifică în GitHub pe un server Control Center poate folosi instalarea,
indiferent de server: al tău, al unui coleg sau al lui. Nu trebuie autorizat nimic
pe fiecare server.

Fiecare token pe care îl primește un server este al persoanei autentificate,
limitat la un singur depozit și la rolul ei în acel depozit, așa că nu ajunge mai
departe decât ar putea ajunge ea pe GitHub. Jurnalul de audit al GitHub arată
acea persoană, care acționează prin aplicație.

Ca să oprească accesul Control Center la o organizație, un proprietar al
organizației elimină instalarea sau îi restrânge depozitele pe GitHub. Scoaterea
unei persoane din organizație îi oprește și accesul.

## Înregistreaz-o manual

Cardul **Aplicații provider** acceptă și valorile direct, pentru o aplicație pe
care ai înregistrat-o singur:

| Grup                                 | Câmpuri                                                                                          |
| ------------------------------------ | ------------------------------------------------------------------------------------------------ |
| **Acționează ca serverul**           | **App id** și **Cheie privată** (întregul `.pem`, inclusiv liniile `BEGIN` și `END`)            |
| **Autentificarea oamenilor**         | **Client id** și **Client secret**. **URL-uri de callback** arată URL-ul de înregistrat, întocmai |
| **Conversații de pull request**      | **Login bot**, rezolvat când testezi conexiunea                                                  |

Înregistrează URL-ul de callback `<server origin>/oauth/github/callback` exact
cum îl arată cardul, lasă **Expire user authorization tokens** activat și acordă
permisiunile din tabelul de mai sus. Apasă **Test**: întreabă GitHub pe ce
conturi este instalată aplicația, ca „salvat” și „funcționează” să nu fie
confundate.

## Configureaz-o din `.env`-ul serverului

Pentru o instalare headless sau prin script, serverul inițializează fiecare câmp
din fișierul său `.env` prima dată când nu are o valoare stocată:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

Pune cheia pe **un singur rând**: o valoare din `.env` este un singur rând, iar
`\n` între ghilimele duble se decodează ca rând nou. Serverul refuză să pornească
atunci când `GITHUB_APP_PRIVATE_KEY` sau `GITHUB_CLIENT_SECRET` este exportat în
mediul procesului său, unde l-ar putea citi orice proces copil; păstrează-le în
fișierul `.env` (în Docker, montează-l la `/app/bin/.env`). Inițializarea are
loc **o singură dată per câmp**, așa că o editare în Setări nu este anulată de
următoarea repornire.

## Dă unui spațiu de lucru propria aplicație

Un spațiu de lucru poate folosi o aplicație proprie în locul celei a serverului:

1. Un administrator al spațiului de lucru merge la **Setări → Spațiu de lucru → Integrări**
2. Pe cardul **Control Center Connect**, alege **Folosește aplicațiile mele** și apasă **Aplică**. Toți din spațiul de lucru se autentifică din nou prin aplicațiile spațiului de lucru
3. Cardul **Aplicația GitHub**, din Găzduire de cod, are acum câmpurile aplicației: **App id** și **Cheie privată** sub **Acționează pentru acest spațiu de lucru**, **Client id** și **Client secret** sub **Autentificarea oamenilor**. Apasă **Test** odată ce sunt completate

Membrii se autentifică apoi în acea aplicație pentru acest spațiu de lucru. Un spațiu de lucru pe propriile aplicații nu revine niciodată la aplicația serverului sau la Connect: până când câmpurile lui sunt complete, munca lui pe GitHub este refuzată. Aceeași alegere acoperă Google Calendar, Linear și căutarea GIF, fiecare cu propriile câmpuri lângă furnizorul său, pe aceeași pagină. Vezi [Dă unui spațiu de lucru propria aplicație Linear](/ro-RO/manual/ghiduri-practice/integrare-linear/#dă-unui-spațiu-de-lucru-propria-aplicație-linear)
și [Dă unui spațiu de lucru propriul client Google](/ro-RO/manual/ghiduri-practice/conecteaza-calendar/#dă-unui-spațiu-de-lucru-propriul-client-google).
Celelalte alegeri de pe acest card, și ce face fiecare, sunt în [Alegerea pe spațiu de lucru](/ro-RO/manual/referinta/connect/#alegerea-pe-spațiu-de-lucru).

## Depanare

### Creează aplicația mea GitHub spune că serverul nu are nicio adresă

Serverul nu are un URL public la care să se poată întoarce un browser. Setează
`CC_SERVER_PUBLIC_URL` (sau `--public-url`) și încearcă din nou.

### GitHub spune că linkul a expirat

Pagina de unică folosință a fost deja folosită sau au trecut zece minute.
Pornește din nou din Setări.

### Testul spune că datele de autentificare funcționează, dar aplicația nu este instalată nicăieri

Înregistrarea și instalarea sunt pași separați. Deschide pagina de instalare a
aplicației sau folosește **Instalează aplicația GitHub** din Spațiu de lucru →
Integrări.

### Testul spune că cheia privată nu a putut fi citită

Lipește tot fișierul `.pem`, inclusiv liniile `-----BEGIN` și `-----END`. O cheie
`ed25519` sau EC nu poate fi folosită: GitHub Apps semnează cu RSA.

### Un membru s-a autentificat, dar nu vede niciun depozit

Aplicația nu este instalată pe contul care le deține sau instalarea ei
selectează alte depozite. O autentificare acordă doar ce are voie să vadă
aplicația.

### Agenții spun că instalarea GitHub App este suspendată

Cineva a suspendat instalarea pe GitHub. Anulează suspendarea în **Settings →
Applications → Installed GitHub Apps** al contului respectiv.
