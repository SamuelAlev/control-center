Acest ghid arată cum să creezi o echipă, să îi dai un lider și să direcționezi munca spre ea.

O echipă este un grup de agenți cu nume, dintr-un singur spațiu de lucru, în care un agent este desemnat drept **lider**. Când asignezi un tichet echipei, liderul este trezit, descompune munca și deleagă către membri; când o rulare de membru se încheie, liderul este trezit din nou ca să decidă ce urmează.

Creezi, redenumești și completezi echipe din **Setări → Spațiu de lucru → Agenți → Echipe**. Direcționezi munca spre o echipă în unul dintre două moduri: un agent apelează `assign_ticket` cu `team_id`-ul acelei echipe, sau un nod de pipeline **Team dispatch** trimite echipa (fără să asigneze un tichet). Selectorul de asignați ai tichetului te listează pe tine și pe agenții individuali.

## Creează o echipă

1. Deschide **Setări → Spațiu de lucru → Agenți** (`/settings/workspace/agents`).
2. Apasă **Echipe** în antetul paginii.
3. Apasă **Adaugă echipă**.
4. Introdu un **nume** (de exemplu „backend” sau „review squad”) și o **descriere** opțională, apoi apasă **Creează**.

Echipa este creată și selectată, iar editorul ei se deschide în panoul din dreapta.

## Setează liderul

Acesta este pasul de care depinde întreaga funcționalitate. În editorul echipei:

1. La **Lider**, alege un agent. Textul de ajutor îl descrie exact: „Coordonatorul care primește munca asignată echipei și o deleagă membrului cel mai potrivit.”
2. Opțional, completează **Instrucțiuni de operare** — text liber transmis liderului împreună cu fiecare tichet direcționat.

Promovarea unui agent la rolul de lider îl face și membru, dacă nu era deja. O echipă lăsată pe **Fără lider** este inertă: nu se trimite nimic când munca este direcționată spre ea, iar scoaterea liderului actual din lista de membri lasă din nou echipa fără lider.

## Adaugă membri

În același editor, folosește cardul de membri ca să adaugi agenți din spațiul de lucru și să îi elimini. Membrii formează lista din care liderul deleagă.

Echipele sunt limitate la un spațiu de lucru: doar agenții din acest spațiu de lucru se pot alătura.

## Oferă echipei un spațiu

Nu există un spațiu de echipă automat. Dacă vrei unul, creează un spațiu obișnuit din **Spații** și adaugă în el agenții echipei. Un `Team` poartă un nume, o descriere, un lider, instrucțiuni și membri — fără nicio asociere cu un spațiu.

## Liniile de raportare sunt o chestiune separată

Fiecare agent are și un câmp **Raportează către**, setat în **Setări → Spațiu de lucru → Agenți**. Acesta construiește arborele de raportare al spațiului de lucru, pe care îl poți vedea cu butonul **Organigramă** din pagina de agenți.

El nu guvernează direcționarea către echipe. Un lider alege un delegat din lista de membri ai echipei, după skill-uri și rol, nu din lanțul de raportare. Drepturile de acces la memorie se acordă după rolul agentului, nu după lanțul de raportare, iar nicio suprafață de analiză nu agregă pe echipe sau pe ierarhie. Gărzile de delegare plafonează adâncimea și detectează ciclurile, dar nu cer niciodată ca ținta să fie un subordonat.

## Ce face un tichet direcționat

Când un tichet are într-adevăr o asignare de echipă:

1. Liderul echipei este trimis împreună cu tichetul, cu instrucțiunile lui de operare și cu lista de membri.
2. Liderul deleagă către membri și își înregistrează evaluarea cu instrumentul `record_team_activity` — `action` (a delegat), `no_action` (nu mai este nimic de făcut, ceea ce oprește declanșările ulterioare) sau `failed`.
3. Fiecare rulare de membru care se încheie trezește din nou liderul, în limita impusă de garda no-action.

Nodul de pipeline **Team dispatch** este celălalt punct de intrare. Primește un ID de echipă, un prompt și un mod de dispatch:

- `allParallel` — câte o sarcină pentru fiecare membru, într-o conversație ascunsă comună, cu suspendare până când se încheie toate rulările, iar rezultatul fiecărui membru este colectat sub cheia de ieșire a nodului
- `manager` — trimite doar liderul, care coordonează în conversație
