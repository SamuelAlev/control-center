Acest ghid arată cum să creezi și să gestionezi tichete.

## Creează un tichet

### Din interfață

1. Dă clic pe **Tichete** în bara laterală a spațiului de lucru.
2. Apasă **Tichet nou**.
3. Completează:
   - **Titlu** — un rezumat scurt. Este singurul câmp obligatoriu.
   - **Descriere** — markdown, cu o bară de instrumente de formatare.
   - **Stare** — **De făcut** (valoarea implicită) sau **Backlog**. Stările de
     început și cele finale se ating prin ciclul de viață, nu la creare.
   - **Prioritate** — niciuna, urgent, ridicată, medie sau scăzută.
   - **Asignat** — pe tine sau pe orice agent din spațiul de lucru.
   - **Proiect** — grupare opțională.
4. Apasă **Creează** sau activează mai întâi **Creează încă** pentru a ține
   dialogul deschis și a introduce rapid mai multe tichete.

Nu există niciun selector de furnizori în dialog. Tichetul este creat pe
furnizorul de tichete activ al spațiului de lucru.

### De la un agent

Cere unui agent într-un spațiu:

> Creează un tichet pentru repararea problemei de expirare a autentificării pe
> conexiuni lente.

El apelează instrumentul MCP `create_ticket`. Prioritatea la acel instrument
este un **întreg**, nu un nume:

```
create_ticket(
  workspace_id: "...",
  title: "Fix login timeout on slow connections",
  description: "...",
  priority: 2
)
```

| Valoare | Prioritate |
| ------- | ---------- |
| `0`     | Niciuna    |
| `1`     | Urgent     |
| `2`     | Ridicată   |
| `3`     | Medie      |
| `4`     | Scăzută    |

Doar `workspace_id` și `title` sunt obligatorii; `description`, `priority`,
`assignee` (un id de agent) și `team_id` sunt opționale. Instrumentul este
clasificat ca scriere de sincronizare către un furnizor și cere aprobarea ta
înainte de a rula.

## Actualizează starea unui tichet

Tichetele urmează acest ciclu de viață:

```
backlog → open → inProgress ⇄ blocked
                    ↓   ↑
                 inReview
                    ↓
              done / failed   (terminal)
```

`done`, `failed` și `cancelled` sunt finale. `cancelled` este accesibilă din
orice stare nefinală. `done` și `failed` sunt accesibile din `inProgress` sau
`inReview`; `open` poate trece și direct în `blocked`. Selectorul de stări din
interfață listează toate stările, cu excepția lui `failed` — agenții o
marchează cu `fail_ticket`.

Pentru a o schimba, folosește oricare dintre:

- rândul **Stare** din panoul de proprietăți al tichetului,
- submeniul **Stare** din meniul de clic dreapta al unui tichet din listă,
- butonul **Stare** din bara flotantă, după ce selectezi mai multe tichete.

:::note[Graful ciclului de viață îi leagă pe agenți, nu pe tine]
Orice schimbare de stare făcută din interfață este forțată, ocolind complet
graful — poți muta un tichet în orice stare listată de selector, inclusiv
redeschiderea unuia `done`, `failed` sau `cancelled`. Selectorul nu oferă
`failed` ca țintă. Diagrama de mai sus guvernează agenții și automatizarea:
o tranziție ilegală încercată de un instrument MCP sau de un reconciliator este
înregistrată în jurnal și ignorată, nu aplicată.
:::

Schimbările de stare emit evenimente de domeniu (`TicketStatusChanged`,
`TicketCompleted` și altele) care pot declanșa pipeline-uri. Vezi
[Configurează trigger-ele pipeline-urilor](/ro-RO/manual/ghiduri-practice/triggere-pipeline/).

## Atribuie un tichet

1. Deschide tichetul.
2. În panoul de proprietăți, setează **Asignat** — pe tine, pe un alt membru al
   spațiului de lucru sau pe un agent.

:::caution[Atribuirea nu pornește nicio muncă]
Atribuirea consemnează proprietatea și nimic altceva. Nu creează niciun spațiu,
nu schimbă nicio stare și nu trimite niciun agent — `TicketAssigned` este un
semnal pur de audit, fără niciun dispecer în spate. Ca să pui un agent la
treabă, trimite-i un mesaj într-un spațiu
(vezi [Discută cu un agent](/ro-RO/manual/ghiduri-practice/discuta-cu-agent/)).

Singura excepție: `TicketAssigned` este un tip de eveniment la care poți lega un
trigger de pipeline, așa că un șablon al tău poate reacționa la o atribuire.
:::

## Adaugă etichete

Etichetele se aplică în bloc din lista de tichete, nu dintr-un singur tichet —
panoul de proprietăți nu are niciun control pentru etichete.

1. Treci cu cursorul peste un rând din lista de tichete și bifează caseta lui de
   selectare. Bifează câte ai nevoie; bara flotantă apare de îndată ce ceva este
   selectat.
2. În acea bară, deschide butonul **Etichete**.
3. Alege o etichetă. Ea se adaugă la fiecare tichet selectat care nu o are;
   etichetele existente nu se șterg niciodată. **Șterge etichetele** le elimină
   pe toate. Selectorul listează etichetele deja prezente pe un tichet din
   spațiul de lucru. Agenții pot adăuga un nume nou prin `update_ticket` sau
   `tickets.patch`.

## Leagă tichete

Relațiile stau pe cardul **Relații** al tichetului, în panoul de proprietăți,
sau în spatele opțiunii **Leagă de** din meniul de clic dreapta al listei.

1. Deschide tichetul și găsește cardul **Relații**.
2. Apasă controlul lui de adăugare și alege relația:

| Relație            | Semnificație                              |
| ------------------ | ----------------------------------------- |
| **Sub-issue al…**  | Părintele acestui tichet este celălalt    |
| **Părinte al…**    | Celălalt tichet este copilul acestuia     |
| **Blocat de…**     | Acest tichet este blocat de celălalt      |
| **Blochează…**     | Acest tichet îl blochează pe celălalt     |
| **Legat de…**      | Simetrică, fără direcție implicită        |
| **Duplicat al…**   | Acest tichet îl duplică pe celălalt       |

3. Alege tichetul țintă.

**Duplicat de** apare pe card, dar nu în selector — este inversul lui
**Duplicat al** și se setează din celălalt tichet. Fiecare relație listată este
clicabilă pentru a deschide tichetul legat și se poate elimina la trecerea
cursorului.

Relațiile de părinte și de sub-sarcină sunt stocate pe tichetul însuși, nu ca
rânduri de legătură, așa că ștergerea unui părinte se propagă în cascadă la
copiii lui (vezi mai jos), în timp ce legăturile de blocare și de înrudire nu fac
asta.

## Adaugă colaboratori

Colaboratorii sunt o listă de persoane pe tichet — cine este implicat și în ce
calitate.

1. Deschide tichetul.
2. Apasă controlul cu simbolul persoană-plus de pe cardul **Adaugă colaborator**.
3. Alege un agent.

Cele trei roluri sunt **assignee**, **collaborator** (valoarea implicită) și
**reviewer**. Selectorul din interfață listează doar agenți din spațiul de lucru
și scrie întotdeauna rolul implicit; oamenii pot apărea ca rânduri, dar nu sunt
oferiți în acel meniu. Instrumentul MCP `add_ticket_collaborator` acceptă un
`role`.

Adăugarea unui colaborator scrie un rând și nu publică niciun eveniment de
domeniu; nu acordă acces la niciun spațiu. Ca să pui un agent într-o conversație,
adaugă-l ca participant din antetul spațiului — vezi
[Folosește spațiile](/ro-RO/manual/ghiduri-practice/spatii/).

## Șterge un tichet

Folosește **Șterge tichetul** în partea de jos a panoului de proprietăți, în
meniul de clic dreapta sau acțiunea de ștergere a barei flotante, după ce
selectezi mai multe tichete.

:::caution[Ștergerea este doar locală]
Un tichet care provine dintr-un tracker extern nu este șters acolo — niciun
furnizor nu suportă asta — așa că poate reapărea la următoarea sincronizare.
Ștergerea se propagă și în cascadă: colaboratorii tichetului și eventualele
tichete copil dispar împreună cu el.
:::
