Niniejsza dokumentacja referencyjna wymienia każde pole encji agenta oraz używane przez nią typy wyliczeniowe i flagi. Instrukcję krok po kroku tworzenia i edytowania agenta w aplikacji znajdziesz w sekcji [Utwórz i skonfiguruj agenta](/pl-PL/podrecznik/poradniki/tworzenie-agenta/).

## Pola encji agenta

| Pole                    | Typ                    | Wymagane | Opis                                                                                                                                                                                                                                                                |
| ----------------------- | ---------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                    | `String`               | Tak      | Unikatowy identyfikator agenta                                                                                                                                                                                                                                      |
| `name`                  | `String`               | Tak      | Krótki identyfikator używany we wzmiankach @                                                                                                                                                                                                                        |
| `title`                 | `String`               | Tak      | Czytelny dla człowieka tytuł stanowiska                                                                                                                                                                                                                             |
| `agentMdPath`           | `String`               | Tak      | Bezwzględna ścieżka do pliku definicji `.md` agenta                                                                                                                                                                                                                 |
| `workspaceId`           | `String`               | Tak      | Obszar roboczy będący właścicielem (nigdy nie jest pusty)                                                                                                                                                                                                           |
| `reportsTo`             | `String?`              | Nie      | Identyfikator agenta nadrzędnego                                                                                                                                                                                                                                    |
| `skills`                | `AgentSkills`          | Tak      | Zestaw identyfikatorów skillów                                                                                                                                                                                                                                      |
| `persona`               | `String?`              | Nie      | Swobodny tekst z instrukcjami behawioralnymi                                                                                                                                                                                                                        |
| `systemPrompt`          | `String?`              | Nie      | Nadpisanie domyślnego promptu systemowego                                                                                                                                                                                                                           |
| `adapterId`             | `String?`              | Nie      | Identyfikator adaptera inferencji                                                                                                                                                                                                                                   |
| `modelId`               | `String?`              | Nie      | Identyfikator modelu w obrębie adaptera                                                                                                                                                                                                                             |
| `strictMode`            | `bool`                 | Nie      | Domyślnie `false`. Zapisywane w wierszu i w pliku `AGENTS.md` agenta                                                                                                                                                                                                 |
| `effort`                | `String?`              | Nie      | Identyfikator poziomu rozumowania (np. `'low'`, `'xhigh'`), czerpany z `thinkingLevels` wybranego modelu                                                                                                                                                             |
| `contextSize`           | `int?`                 | Nie      | Maksymalny rozmiar okna kontekstu                                                                                                                                                                                                                                   |
| `role`                  | `AgentRole?`           | Nie      | Rola agenta                                                                                                                                                                                                                                                         |
| `monthlyBudgetMicros`    | `int`                  | Nie      | Miesięczny limit wydatków w mikrodolarach (domyślnie `0`, bez limitu)                                                                                                                                                                                                     |
| `silenceTimeoutMinutes` | `int?`                 | Nie      | Nadpisanie limitu ciszy w minutach; musi być null albo mieścić się w zakresie 1–240 (weryfikowane w konstruktorze)                                                                                                                                                  |
| `maxConcurrentTasks`    | `int`                  | Nie      | Domyślnie `1`. Liczba określająca pojemność, którą raportuje model obecności (porównuje się z nią liczbę uruchomień w toku i w kolejce)                                                                                                                              |
| `visibility`            | `AgentVisibility`      | Nie      | Domyślnie `workspace`                                                                                                                                                                                                                                               |
| `lifecycleStatus`       | `AgentLifecycleStatus` | Nie      | Status zarządzania (domyślnie `active`). Zapisywany przez twarde zatrzymanie budżetu i wyświetlany na schemacie organizacyjnym oraz liście obecności. Wysyłanie nadal przyjmuje pracę od agenta w stanie `paused`                                                    |
| `budgetPolicyId`        | `String?`              | Nie      | Identyfikator współdzielonej polityki budżetowej; gdy null, bezpośrednio obowiązuje `monthlyBudgetMicros`                                                                                                                                                            |
| `runtimeProfileId`      | `String?`              | Nie      | Identyfikator niestandardowego profilu środowiska uruchomieniowego                                                                                                                                                                                                  |
| `createdAt`             | `DateTime`             | Tak      | Znacznik czasu utworzenia                                                                                                                                                                                                                                           |

`name` i `title` muszą być niepuste (weryfikowane w konstruktorze). Domyślna
wartość `monthlyBudgetMicros` wynosząca `0` oznacza brak limitu. Pułap ustawisz za pomocą `agents.upsert`.

## Uprawnienia

Agent nie ma flag uprawnień. Push, otwieranie i publikowanie pull requestów, zapis do trackera i ruch wychodzący sieci to klasy akcji (`gitPush`, `prCreate`, `prPublish`, `vendorSyncWrite`, `networkEgress`), które [guardraile](/pl-PL/podrecznik/koncepcje/guardraile/) rozstrzygają w zakresie obszaru roboczego, agenta lub przestrzeni. Token GitHub uruchomienia zawsze ma zakres tylko do odczytu; push przechodzi przez bramę uruchomień agentów, która przed przekazaniem go dalej pyta regułę `gitPush`.

## AgentSkills

Niezmienny zestaw identyfikatorów skillów, w którym wielkość liter nie ma znaczenia. Przy wysłaniu te slugi są synchronizowane jako dowiązania skillów w nakładce agenta; harness wczytuje następnie frontmatter dowiązanych skillów do promptu.

```
{'flutter', 'dart', 'rest-api'}
```

## Haki powłoki

Haki powłoki pozwalają właścicielowi serwera uruchamiać własne skrypty wokół uruchomienia agenta: raz na starcie sesji, przed każdym wywołaniem narzędzia, po każdym wywołaniu narzędzia, gdy agent miałby zakończyć turę, oraz przed kompaktowaniem. Hak to dowolny kod, więc haki są konfiguracją hosta. Ustawia je wyłącznie właściciel serwera, ręcznie, na maszynie serwera. Nie ma żadnego ustawienia w aplikacji ani operacji, która je zapisuje.

Dla agenta haki leżą w jego własnym folderze w katalogu danych serwera:

```text
<data dir>/_agent_hooks/<workspace id>/<agent slug>/hooks.json
```

`<agent slug>` to nazwa folderu agenta w obszarze roboczym (`agents/<slug>/`). Ten folder leży poza pamięcią każdego obszaru roboczego, a każda piaskownica ukrywa katalog danych, więc żaden członek, uruchomienie ani terminal nie może go zapisać.

`hooks.json` przypisuje każdemu z pięciu kluczy skrypt, podając ścieżkę względną do folderu haka:

| Klucz          | Kiedy działa                       | Co oznacza kod wyjścia                                  |
| -------------- | ---------------------------------- | ------------------------------------------------------- |
| `sessionStart` | Raz, gdy uruchomienie się zaczyna  | Nic; hak tylko obserwuje                                |
| `preTool`      | Przed każdym wywołaniem narzędzia  | `0` zezwala na wywołanie; cokolwiek innego je odrzuca   |
| `postTool`     | Po każdym wywołaniu narzędzia      | Nic; hak tylko obserwuje                                |
| `stop` | Gdy agent miałby zakończyć turę | `2` z tekstem na stdout podtrzymuje uruchomienie z tym tekstem; cokolwiek innego pozwala turze się zakończyć |
| `preCompact` | Przed kompaktowaniem | `0`: jego stdout jest dodawany do tego, co podsumowanie ma zachować |

- Każdy skrypt jest uruchamiany jako osobny plik wykonywalny, bez powłoki i bez argumentów, więc musi mieć uprawnienie do wykonania i zaczynać się od linii shebang. Otrzymuje zdarzenie jako JSON na stdin: nazwę zdarzenia, a dla haków narzędzi nazwę narzędzia wraz z jego argumentami (`preTool`) albo wynikiem (`postTool`).
- Hak działa jako jeden z procesów narzędzi uruchomienia, w katalogu agenta dla tego uruchomienia. Gdy serwer uruchamia agentów w piaskownicy, działa wewnątrz piaskownicy uruchomienia. Dostaje minimalne środowisko i żadne poświadczenia uruchomienia: ani tokenu forge czy dostawcy, ani dostępu do bramy.
- Każdy hak ma 30 sekund. Wyjście `sessionStart`, `preTool` i `postTool` jest odczytywane i odrzucane.
- `preTool` działa w trybie zamkniętym: kod wyjścia inny niż zero, przekroczenie czasu albo skrypt, którego nie da się uruchomić, odrzucają wywołanie narzędzia.
- Ścieżka bezwzględna, nieistniejąca albo wychodząca poza folder haka (po rozwiązaniu dowiązań) jest odrzucana, a dziennik uruchomienia mówi, który hak został odrzucony i dlaczego. Odrzucony albo nieczytelny hak `preTool` odrzuca każde wywołanie narzędzia, dopóki nie zostanie naprawiony.
- Blok `hooks` w `.agents/harness.json`, czy to w repozytorium, czy we własnym folderze agenta, jest ignorowany. Repozytorium to często cudzy kod, a folder agenta mogą zapisywać członkowie i uruchomienia. Dziennik uruchomienia mówi, że blok został zignorowany i skąd zamiast tego czytane są haki.

### Haki stop i preCompact

- `stop` otrzymuje `event: "stop"`, ostatnią wiadomość agenta (`last_message`), `stop_hook_active` (true, gdy to zatrzymanie następuje po kontynuacji, którą wywołał hak) oraz `block_count` (ile razy dotąd podtrzymał uruchomienie, od 0). Aby podtrzymać uruchomienie, kończy się kodem `2` i wypisuje, co agent ma zrobić dalej. Tekst, obcięty do 2 000 znaków, trafia do agenta jako wiadomość systemowa.
- Hak `stop` podtrzymuje uruchomienie co najwyżej 3 razy w jednym uruchomieniu. Potem nie jest już uruchamiany i tura się kończy.
- `stop` zawodzi otwarcie. Przekroczenie czasu, skrypt, którego nie da się uruchomić, dowolny kod wyjścia inny niż `2` albo kod `2` przy pustym stdout pozwala turze się zakończyć, więc uszkodzony hak nie może utrzymać uruchomienia otwartego.
- `preCompact` otrzymuje `event: "pre_compact"`. Jego stdout, obcięty do 1 000 znaków, jest dodawany do skupienia kompaktowania. Skrypt, który zawiedzie, nic nie dodaje.

Haki powłoki dotyczą wbudowanego harnessu. W Claude Code działają także haki `stop` i `preCompact`: własne haki `Stop` i `PreCompact` Claude Code pytają serwer, a serwer uruchamia skrypty właściciela w ten sam sposób. Pozostałe trzy klucze dotyczą wyłącznie wbudowanego harnessu. Skonfigurowany hak `preTool` albo `postTool` powoduje, że uruchomienie wywołuje swoje narzędzia po jednym naraz.

## AgentLiveState (pochodny)

Nie jest zapisywany. Siedem wartości. Kolejność deklaracji to kolejność priorytetów (`sortPriority`, przypięta testem), czyli kolejność, według której sortuje lista obecności:

| Stan        | `sortPriority` | Warunek                                                                                                              |
| ----------- | -------------- | -------------------------------------------------------------------------------------------------------------------- |
| `running`   | 0              | Dowolny dziennik uruchomienia ma status `running`                                                                    |
| `blocked`   | 1              | Żywotność najnowszego uruchomienia to `blocked`, `stalled` lub `looping`                                              |
| `failed`    | 2              | Status najnowszego uruchomienia to `error` albo jego żywotność to `failed` lub `dead`                                 |
| `queued`    | 3              | Uruchomienie zostało wysłane, ale nie jest wykonywane — czeka za innym uruchomieniem tego samego agenta albo zostało zapisane, lecz jeszcze nie wystartowało |
| `succeeded` | 4              | Uruchomienie zakończyło się pomyślnie                                                                                 |
| `idle`      | 5              | Agent działał już wcześniej i nie ma nic w toku                                                                       |
| `neverRun`  | 6              | Nie istnieje żaden dziennik uruchomienia                                                                              |

`queued` i `succeeded` dotyczą **wyłącznie pojedynczego uruchomienia**. `deriveAgentLiveState`, który wylicza stan agenta na liście obecności, nigdy nie zwraca żadnego z nich — zwraca `neverRun`, `running`, `failed`, `blocked` lub `idle`.
