These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/pl-PL/podrecznik/poradniki/); when you want to look
something up, go to the [reference](/pl-PL/podrecznik/dokumentacja-referencyjna/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/pl-PL/podrecznik/koncepcje/obszary-robocze/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/pl-PL/podrecznik/koncepcje/model-agentow/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/pl-PL/podrecznik/koncepcje/cykl-zycia-wysylania/) — what happens between your message and the agent's first token
- [Modes](/pl-PL/podrecznik/koncepcje/tryby/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/pl-PL/podrecznik/koncepcje/kontekst-narzedzi/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/pl-PL/podrecznik/koncepcje/inteligencja-kodu/) — the code graph, language server, structural search and debugger
- [Conversation history](/pl-PL/podrecznik/koncepcje/historia-rozmow/) — persistence, compaction and forking a transcript
