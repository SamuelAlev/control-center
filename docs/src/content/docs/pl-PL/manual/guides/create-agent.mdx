Ten poradnik pokazuje, jak dodać agenta do obszaru roboczego i konfigurować go
tak, aby naprawdę działał.

Każdy obszar roboczy powstaje z pięcioma agentami — CEO oraz `qa`, `architect`,
`engineer` i `librarian` — więc zwykle masz agentów, zanim skonfigurujesz
choćby jednego. Poniższe kroki dotyczą tak samo agenta utworzonego razem
z obszarem, jak i zupełnie nowego.

## Zanim zaczniesz

- Jesteś wewnątrz obszaru roboczego. Całość mieści się w **Ustawienia → Obszar
  roboczy → Agenci** (`/settings/workspace/agents`).
- Agent będzie potrzebować backendu. Połącz dostawcę dla wbudowanego harnessu
  w **Ustawienia → Serwer → Dostawcy modeli** albo zainstaluj CLI Claude Code na
  maszynie hostującej `cc_server`.
- Jeśli chcesz, aby agent miał skille, zainstaluj je najpierw w **Ustawienia →
  Obszar roboczy → Umiejętności**. Formularz agenta pozwala przełączać tylko
  skille, które już istnieją w obszarze roboczym.

## Dodaj agenta

1. Otwórz **Ustawienia → Obszar roboczy → Agenci**.
2. Kliknij **Nowy agent**.

Nie ma żadnego okna dialogowego ani wyboru roli. Agent o nazwie „Agent bez
nazwy” powstaje od razu i zostaje wybrany w panelu szczegółów po prawej.

Powinien teraz pojawić się na liście po lewej jako „Agent bez nazwy”, z otwartą
kartą **Ustawienia** w panelu szczegółów i polem **Nazwa** zawierającym „Agent
bez nazwy”.

## Nadaj mu nazwę

- **Nazwa** — krótki identyfikator używany we wzmiankach @, na przykład
  `alice`. Analiza wzmianek dopasowuje `@` wraz z następującymi po nim znakami
  słowa, więc nazwa zawierająca myślnik, kropkę lub spację nigdy nie może
  zostać wspomniana.
- **Tytuł** — etykieta czytelna dla człowieka, na przykład „Starszy
  programista”.
- **Prompt systemowy** — opcjonalne dodatkowe instrukcje, wstrzykiwane jako
  sekcja „Agent instructions”; nie zastępują reszty składanego promptu.

Kliknij **Zapisz zmiany** na dole formularza. Wszystkie pola na tej stronie
zapisuje ten jeden przycisk.

## Przypisz mu adapter i model

Lista rozwijana **Adapter** wymienia runnery, które host serwera rzeczywiście
ma. Wbudowany adapter jest wykrywany zawsze (to sam serwer). Claude Code pojawia
się tylko wtedy, gdy jego CLI zostało wykryte na tym hoście:

| Adapter                   | Backend                                                     |
| ------------------------- | ----------------------------------------------------------- |
| Control Center (built-in) | Pętla agenta w procesie — bez zewnętrznego CLI              |
| Claude Code               | `claude -p --output-format stream-json`                     |

Tylko wbudowany adapter egzekwuje tryby, sterowanie, pauzę/wznowienie,
kontrakty ukończenia i podagentów. Claude Code nie daje żadnego z nich. Cursor,
Codex i pozostali dostawcy modeli podłączają się do wbudowanego adaptera, a nie
jako osobne runnery.

:::note[Pusty adapter oznacza wbudowaną pętlę]
Agent, który nie ma ustawionego adaptera, jest wysyłany do **Control Center
(built-in)**, czyli pętli wewnątrz serwera, więc na hoście nie trzeba nic
instalować. Gdy nie ma też ustawionego modelu, pyta Anthropic o jego model
domyślny, więc całkowicie nieskonfigurowany agent uruchomi się tylko wtedy, gdy
masz połączone konto Anthropic. Agenci tworzeni razem z obszarem roboczym nie
mają ani jednego, ani drugiego; ustaw oba u każdego agenta, którego zamierzasz
używać.
:::

Lista rozwijana **Model** zależy od wybranego adaptera. W przypadku wbudowanego
adaptera lista pochodzi na bieżąco od dostawców połączonych w **Ustawienia →
Serwer → Dostawcy modeli**, więc dostawca bez zapisanych poświadczeń nie wnosi
żadnych modeli.

## Dodaj skille

**Umiejętności** to selektor chipów obejmujący pakiety skilli zainstalowane
w tym obszarze roboczym. Kliknij chip, aby go przełączyć; znacznik wyboru
oznacza wybrane. Jeśli obszar roboczy nie ma żadnych skilli, w polu widnieje
„No skills available. Create skills in Settings → Skills first.”

Nie wybierasz tutaj skilli należących do samego repozytorium. Repozytorium,
które je dostarcza (w `.agents/skills/`, `.claude/skills/` lub
`.opencode/skills/`), przekazuje je automatycznie temu agentowi, który pracuje
w tym repozytorium, a gdy przenosi się on do innego, skille zostają podmienione
— zob. [Skille w zakresie repozytorium](/pl-PL/podrecznik/koncepcje/model-agentow/#repo-scoped-skills).

## Ustaw linię raportowania i personę

- **Raportuje do** — wybierz innego agenta po nazwie. Buduje to drzewo
  raportowania wyświetlane przez przycisk **Schemat organizacyjny** w nagłówku
  strony. To nie jest lista, z której korzysta lider zespołu, gdy deleguje
  zadania — ta wynika z członków zespołu i ich skilli.
- **Persona** — dowolny tekst kształtujący ton i zachowanie, na przykład:
  „Woli proste, czytelne rozwiązania. Pisze testy do każdego nowego kodu.”

## Dostrój uruchomienie

- **Wysiłek rozumowania** — opcje pochodzą z poziomów publikowanych przez sam
  wybrany model: Low / Medium / High, plus Extra High na modelach w stylu
  OpenAI oraz Extra High + Max na modelach w stylu Claude. Pole jest
  całkowicie ukrywane, gdy wybrany model nie deklaruje poziomów myślenia,
  a jego wartością domyślną jest wartość domyślna samego modelu.
- **Rozmiar okna kontekstu** — wstępnie wypełniany na podstawie okna kontekstu
  modelu przy każdej zmianie modelu, z chipami jednego kliknięcia dla wartości
  domyślnej modelu, 200k, 500k i 1M. Wartość wpisana po wybraniu modelu
  obowiązuje aż do następnej zmiany modelu.
- **Limit ciszy (minuty)** — zakończ uruchomienie po takim czasie bez żadnych
  danych wyjściowych. Pozostaw puste, aby użyć wartości domyślnej danego trybu.

## Przyznaj uprawnienia

Agent nie ma własnych przełączników uprawnień. To, co może wypchnąć, otworzyć,
scalić lub osiągnąć, ustalają reguły akcji w **Ustawienia → Obszar roboczy →
Uprawnienia agentów**, gdzie regułę można ograniczyć do tego agenta. Domyślnie
push, pull request, recenzja lub scalenie i zapis do trackera najpierw pytają
Cię o zgodę, każde z osobna, a dostęp do sieci jest dozwolony.

Token GitHub agenta zawsze jest tylko do odczytu. Push przechodzi przez Control
Center, który przed przekazaniem go dalej pyta regułę **Push do zdalnego
repozytorium**. Jak każda reguła dociera do uruchomienia, opisuje
[Skonfiguruj polityki sandboxa](/pl-PL/podrecznik/poradniki/polityki-sandboxa/).

:::note[Reguły i piaskownica systemu operacyjnego to osobne warstwy]
Reguły decydują, co agent może robić; piaskownica systemu operacyjnego
ogranicza, gdzie jego procesy mogą czytać, zapisywać i się łączyć. `cc_server`
opakowuje uruchomienia agentów w piaskownicę hosta, tam gdzie ona istnieje —
Windows nie ma natywnego backendu, a Linux i WSL2 wymagają `bwrap` i `socat`.
Pełny zestaw granic znajdziesz w [Sandbox i bezpieczeństwo](/pl-PL/podrecznik/koncepcje/sandbox-i-bezpieczenstwo/).
:::

## Sprawdź, czy działa

1. Otwórz **Ustawienia → Serwer → Dostawcy modeli** i potwierdź, że wybrany
   adapter zgłasza zainstalowaną wersję, a nie „Nie znaleziono”. Kliknij
   **Odśwież**, aby ponownie przeskanować — skanowanie odbywa się na maszynie
   hostującej `cc_server`, a nie na tej, na którą patrzysz.
2. Otwórz przestrzeń z agentem i wyślij mu wiadomość albo wspomnij go przez @
   w istniejącej przestrzeni.
3. Wróć do **Ustawienia → Obszar roboczy → Agenci**, wybierz agenta i otwórz
   jego kartę **Logi**. Powinno pojawić się uruchomienie z plakietką stanu,
   czasem trwania, godziną rozpoczęcia i użytym adapterem. **Widok** otwiera
   strumień zdarzeń tego uruchomienia.

Jeśli nie pojawia się żadne uruchomienie, przejdź przez [Diagnozuj
agenta](/pl-PL/podrecznik/poradniki/diagnostyka-agenta/).

## Usuń agenta

Wybierz go na liście. Na karcie **Ustawienia** przewiń do **Strefy
niebezpieczeństwa** na dole formularza i kliknij **Usuń**.
