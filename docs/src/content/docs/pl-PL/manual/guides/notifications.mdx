Ten poradnik pokazuje, jak skonfigurować powiadomienia i czym naprawdę steruje
każde ustawienie.

Powiadomienia docierają dwiema powierzchniami. **Centrum powiadomień** —
dzwonek na pasku tytułu — czyta trwały kanał na serwerze, prowadzony osobno dla
każdego obszaru roboczego. **Toasty systemowe** to oddzielna ścieżka dostępna
tylko na pulpicie, zasilana ramkami przesyłanymi na żywo z serwera.

:::note[Wersja webowa nie pokazuje powiadomień systemowych]
Potok toastów tworzy wyłącznie bootstrap wersji desktopowej. W `app.usectrl.dev`
nie ma toastów systemowych, dźwięków powiadomień ani banerów w tle — dzwonek i
jego historia nadal działają, bo czytają kanał z serwera. Klient mobilny nie ma
żadnej powierzchni powiadomień.
:::

## Włączaj i wyłączaj kategorie

1. Przejdź do **Ustawienia → Ty → Powiadomienia**
2. Zostaw **Włącz powiadomienia** włączone
3. Przełącz kategorie, których chcesz. Jest ich dokładnie szesnaście:

| Kategoria                 | Wyzwalane, gdy                                                             |
| ------------------------- | -------------------------------------------------------------------------- |
| Agent ukończył pracę      | Agent zakończył uruchomienie                                               |
| Opublikowano PR           | Agent opublikował PR                                                       |
| Scalono PR                | PR został scalony                                                          |
| Nowe wiadomości           | Wiadomość dotarła do przestrzeni, na którą nie patrzysz                    |
| Wzmianka w pull requeście | Odpytywanie powiadomień GitHuba wykryło, że wspomniano Cię w PR            |
| Prośba o recenzję         | Twoja recenzja została faktycznie zamówiona w PR, który nie jest wersją roboczą |
| Nieaktualna recenzja      | Do pull requesta, który już zrecenzowałeś, trafiły nowe commity            |
| Gotowy do scalenia        | Utworzony przez Ciebie pull request stał się możliwy do scalenia albo przestał |
| Decyzje recenzji          | Recenzent zatwierdził, zażądał zmian albo jego zatwierdzenie zostało odrzucone |
| Sprawdzenia               | CI zawiodło w utworzonym przez Ciebie pull requeście albo znów zadziałało  |
| Wątki recenzji            | Ktoś odpowiedział w wątku, w którym uczestniczysz, albo go rozwiązał       |
| Przypisano zgłoszenie     | Zgłoszenie zostało przypisane                                              |
| Zmieniono status zgłoszenia | Zgłoszenie zmieniło status                                               |
| Spotkanie wkrótce się rozpocznie | Spotkanie w kalendarzu wchodzi w okno wyprzedzenia                  |
| Kalendarz rozłączony      | Wygasł token OAuth połączonego kalendarza                                  |
| Aktualizacje rigów        | Rig został przejęty, odzyskany albo uległ awarii                           |

Wszystko poza tą listą nie może być zgłaszane ani filtrowane — nie ma kategorii
„wszystko inne”.

Te preferencje podążają za Twoim użytkownikiem na wszystkie urządzenia, więc
telefon i laptop pozostają zgodne. Głośność to celowy wyjątek i pozostaje
ustawieniem danego urządzenia.

## Ustaw godziny ciszy

1. Na tej samej stronie włącz **Quiet hours**
2. Wpisz godzinę początku i końca w formacie `HH:MM` (domyślne okno to
   22:00–08:00)

W godzinach ciszy powiadomienia niepilne są odrzucane — nie trafiają do kolejki
ani nie są odtwarzane później.

Dwie kategorie są **pilne** i docierają zawsze, omijając godziny ciszy _oraz_
tryb skupienia: **Spotkanie wkrótce się rozpocznie** i **Opublikowano PR**.
Alert o spotkaniu, który zobaczysz dopiero po fakcie, jest bezwartościowy — i
właśnie to jest tego powodem.

## Wybierz dźwięk

1. Przewiń do **Dźwięk powiadomienia**
2. Wybierz jeden z jedenastu dołączonych dźwięków albo **Brak**
3. Naciśnij przycisk testu, aby go usłyszeć, a suwakiem ustaw głośność

Dźwięk odtwarza sama aplikacja; powiadomienie systemowe dostarczane jest
bezgłośnie, więc nie usłyszysz go dwa razy.

## Ustaw czas wyprzedzenia spotkania

1. Przewiń do **Czas wyprzedzenia alertu**
2. Wybierz **5**, **10**, **15** lub **30** minut

Tyle wcześniej przed wydarzeniem w kalendarzu wyzwalane jest powiadomienie
**Spotkanie wkrótce się rozpocznie**. Domyślnie jest to 5 minut.

## Wiedz, kiedy powiadomienie jest wstrzymywane

Powiadomienie jest po cichu odrzucane, gdy spełniony jest którykolwiek z tych
warunków:

- Powiadomienia są globalnie wyłączone albo wyłączona jest jego kategoria
- Jesteś już na trasie, na którą miało Cię zaprowadzić — a w przypadku
  wiadomości, już w tej przestrzeni
- Tryb skupienia jest aktywny, a kategoria nie jest pilna
- Godziny ciszy są aktywne, a kategoria nie jest pilna

Te warunki dotyczą toastów systemowych. Trwały dzwonek i tak zapisuje zdarzenie.

Dwa kolejne wstrzymania działają wcześniej, na tym, co serwer w ogóle wysyła:

- Wiadomość od innego **człowieka**, w której nie ma wzmianki o Tobie, nigdy nie
  staje się powiadomieniem
- Przestrzenie agent–agent są wyciszone na pasku bocznym, więc nigdy nie
  zwiększają plakietki nieprzeczytanych

W obrębie przestrzeni nie ma cichego zakątka: każda rozmowa powiadamia tak samo,
łącznie z wątkami. Stan przeczytania obowiązuje dla całej przestrzeni, więc
nieprzeczytane sumują się w obrębie jej rozmów, a nie są śledzone osobno dla
każdej rozmowy.

## Czytaj i czyść centrum powiadomień

1. Kliknij dzwonek na pasku tytułu

Wyskakujące okienko pokazuje ostatnią aktywność, prowadząc każdy wpis
bezpośrednim linkiem do tego, czego dotyczy. Jego otwarcie **nie** oznacza
wszystkiego jako przeczytane — użyj **Oznacz wszystkie jako przeczytane** w
nagłówku albo oznacz pojedynczy wiersz. Stan przeczytania podąża za Twoim
użytkownikiem na wszystkie urządzenia.

:::note[Wyczyść wszystko to znak wodny, nie usunięcie]
**Wyczyść wszystko** stawia znak wodny dla danego użytkownika, który ukrywa
wszystko starsze; wiersze zostają. Osobno każdy obszar roboczy przechowuje
tylko **200** najnowszych wierszy kanału, przycinanych w miarę napływania
nowych, a dzwonek subskrybuje najnowsze **50** pozycji, z których wyskakujące
okienko wymienia maksymalnie **15**. Historia poza tym przepada, niezależnie od
stanu przeczytania.
:::

## Rozwiązywanie problemów

### Brak powiadomień systemowych w systemie macOS

Zgoda jest pytana natywnie przy uruchomieniu aplikacji. Jeśli ją odrzucisz,
włącz ponownie Control Center w Ustawienia systemowe → Powiadomienia; w
aplikacji nie ma monitu, który wywołałby tę prośbę ponownie.

### W wersji webowej nic nie dociera

To oczekiwane — wersja webowa nie ma potoku powiadomień systemowych. Użyj
dzwonka.

### Plakietka dzwonka pokazuje zero, choć wyraźnie widać nową aktywność

Dopóki po połączeniu nie ustali się strumień znaczników przeczytania, wpisy
wyświetlają się jako przeczytane, aby plakietka nie mrugała i nie pustoszała.
Ustabilizuje się, gdy znacznik się wczyta.

### Uruchomienie agenta się zakończyło, ale nic mnie nie powiadomiło

Sprawdź, czy nie byłeś już w przestrzeni, w której to się stało — aktywna trasa
wstrzymuje własny toast systemowy.
