Ten poradnik pokazuje, gdzie przechowywane jest każde poświadczenie używane przez
Control Center i jak je zmienić.

**Nic nie jest przechowywane na maszynie, na której piszesz.** Każde poświadczenie
znajduje się na serwerze; to, które z nich odpowie na dane żądanie, zależy od tego,
czy stoi za nim człowiek.

| Poświadczenie                        | Gdzie jest przechowywane                                  | Kto go używa                                                     |
| ------------------------------------ | --------------------------------------------------------- | ---------------------------------------------------------------- |
| Twoje poświadczenie hosta kodu / systemu zgłoszeń | Plik sekretów serwera z uprawnieniami 0600, przypisany do Twojego identyfikatora użytkownika | Wszystko, o co poprosisz: powierzchnia pull requestów, uruchomienia Twoich agentów, Twoje obrazy |
| Tożsamość aplikacji serwera          | Ten sam plik, a dla danych niebędących sekretami — `server_settings` | Praca, o którą nie poprosił żaden człowiek: webhooki, odpytywanie pull requestów, synchronizacja zgłoszeń |
| Klucze dostawców modeli i tokeny OAuth | Własny magazyn poświadczeń serwera                      | Wbudowany adapter, dla każdego obszaru roboczego w instalacji     |
| Tokeny bota Slack                    | `<dataDir>/<workspaceId>/chat_credentials/` na serwerze   | Most czatu tego obszaru roboczego                                |
| Poświadczenia zewnętrznych CLI       | To, czego używa dane CLI                                  | Claude Code, na hoście serwera                                   |

## Dwa poświadczenia GitHub, które odpowiadają na różne pytania

- **Twoje**, z logowania za pomocą kodu urządzenia lub wklejenia tokenu. Stoi za
  każdym żądaniem wykonanym *w Twoim imieniu*, więc komentarz opublikowany za Ciebie
  nosi Twoje imię. Inny członek nie może go odczytać i łączy własne
- **Serwera**, z GitHub App zarejestrowanej przez operatora. Odpowiada na wszystko,
  co nie ma wywołującego — dzięki temu dostęp do hosta kodu nie znika, gdy jedna
  osoba odejdzie albo wymieni token

Twoje ustawia się w karcie **Hosting kodu** w **Ustawienia → Obszar roboczy → Profil
i tożsamość**; poświadczenie serwera — w **Aplikacje dostawców** w **Ustawienia →
Serwer → Logowanie jednokrotne**. Zobacz
[Skonfiguruj integrację GitHub](/pl-PL/podrecznik/poradniki/integracja-github/)
i [Utwórz GitHub App](/pl-PL/podrecznik/poradniki/github-app/).

:::note[Istnieje też ekran dostępny tylko pod adresem URL]
`/workspaces/<workspaceId>/api-keys` wyświetla te same dwie karty co pierwszy krok
konfiguracji. **Nie ma żadnego wpisu w nawigacji w całym interfejsie**; można do
niego trafić tylko, wpisując adres URL. Zamiast tego użyj Ustawienia → Obszar
roboczy → Profil i tożsamość.
:::

## Ustawianie kluczy dostawców modeli

Wbudowany adapter sam uwierzytelnia dostawców, a te poświadczenia znajdują się na
serwerze.

1. Przejdź do **Ustawienia → Serwer → Dostawcy modeli**
2. Przewiń do **Dostawcy i modele**
3. Połącz dostawcę — OAuth w przeglądarce dla OpenAI, Codex, Cursor i Kimi Code; klucz
   API dla Anthropic i pozostałych

Pełną listę oraz informacje o dodawaniu własnego punktu końcowego znajdziesz
w [Zarządzaj adapterami i modelami](/pl-PL/podrecznik/poradniki/adaptery/).

Te poświadczenia są **globalne dla hosta**: jeden klucz obsługuje każdy obszar
roboczy w instalacji. Tokeny OAuth są odświeżane, zanim wygasną.

Zewnętrzne CLI adapterów przechowują własne poświadczenia, we własnej konfiguracji,
na hoście serwera — Control Center nimi nie zarządza. Uwierzytelnij Claude Code tak,
jak mówi jego własna dokumentacja, na maszynie, na której działa `cc_server`.

Okno **Zmienne środowiskowe** dla danego adaptera wygląda jak miejsce na klucz dla
jednego z nich, ale nim nie jest: zapisuje dane na Twoim urządzeniu, podczas gdy
serwer czyta własną kopię i nic ich nie łączy. Zobacz
[Zarządzaj adapterami i modelami](/pl-PL/podrecznik/poradniki/adaptery/).

## Łączenie dostawcy zgłoszeń

Karta **Zgłoszenia** w **Ustawienia → Obszar roboczy → Ogólne** zawiera obie części
jednej decyzji: u którego dostawcy znajdują się Twoje zgłoszenia i jakie są dla niego
poświadczenia. Wybranie opcji **Lokalnie** ukrywa wiersz poświadczeń — lokalne
zgłoszenia znajdują się we własnej bazie danych tego serwera i nie mają się wobec
czego uwierzytelniać.

Twój klucz jest przechowywany na serwerze przy Twoim identyfikatorze użytkownika,
podobnie jak klucz hosta kodu. Serwer przechowuje własny klucz Linear osobno
(**Aplikacje dostawców**) — to na nim działa synchronizacja zgłoszeń, gdy nie poprosił
o nią żaden człowiek. Klucz przekazywany agentowi jest wstrzykiwany tylko wtedy, gdy
agent ma uprawnienie **Zezwalaj na wywołania API zgłoszeń**. Zobacz
[Skonfiguruj integrację Linear](/pl-PL/podrecznik/poradniki/integracja-linear/).

## Wymiana i unieważnianie

- **Twoje poświadczenie GitHub**: naciśnij **Rozłącz**, a następnie zaloguj się
  ponownie lub wklej nowy token. Unieważnij stary w GitHub
- **Aplikacja serwera**: wygeneruj nowy klucz prywatny lub sekret klienta na stronie
  aplikacji w GitHub, wklej go w **Aplikacje dostawców** i naciśnij **Test**
- **Dostawca modeli**: w jego wierszu wyloguj się (OAuth) lub usuń klucz, a następnie
  połącz się ponownie
- **Slack**: wklej ponownie tokeny w oknie łączenia. Zobacz
  [Skonfiguruj integrację Slack](/pl-PL/podrecznik/poradniki/integracja-slack/)

## Rozwiązywanie problemów

### Lista pull requestów jest pusta, ale mój token działa w `curl`

Sprawdź podtytuł wiersza **Hosting kodu**. Jeśli wskazuje inne źródło („przez
aplikację tego serwera”, „ze środowiska”), testowane poświadczenie nie jest tym,
które odpowiada — Twoje nie zostało zapisane.

### Token jest akceptowany, ale późniejsze żądania kończą się niepowodzeniem

Token jest sprawdzany w postaci, w jakiej jest przechowywany, więc wiersz podaje
konto, które za nim stoi — ale tylko konto, nie zakresy uprawnień. Token o zbyt
wąskich zakresach łączy się, a następnie poszczególne żądania kończą się
niepowodzeniem. Sprawdź zakresy i termin ważności:

```bash
curl -H "Authorization: token YOUR_TOKEN" https://api.github.com/user
```
