Ten poradnik pokazuje, jak połączyć dostawców modeli i wybrać, na czym działa agent.

Wszystko to mieści się na jednej stronie: **Ustawienia → Serwer → Dostawcy modeli**. Wpis w podmenu nosi nazwę „Dostawcy modeli", a nagłówek strony — „Adaptery".

## Czym jest adapter

Adapter to _runner_, który wykonuje turę agenta. Są dwa i lista jest stała — nie można dodać trzeciego.

| Adapter                   | CLI      | Transport                                           |
| ------------------------- | -------- | --------------------------------------------------- |
| Control Center (built-in) | brak     | Pętla agenta w procesie, komunikuje się z dostawcami przez HTTP |
| Claude Code               | `claude` | `claude -p --output-format stream-json`             |

Cursor, Codex, Anthropic, OpenAI i reszta to **dostawcy** wbudowanego adaptera, a nie osobne CLI. Dodać można natomiast kolejnego dostawcę — dowolny punkt końcowy zgodny z OpenAI albo z Anthropic. O tym jest następny rozdział.

:::note[Wykrywanie sonduje serwer, a nie Twój komputer]
Karta **Wykryte runnery** wylicza, co `cc_server` znalazł w `PATH` na _hoście serwera_. W przypadku klienta cienkiego lub webowego to inna maszyna niż ta, na którą patrzysz. Zainstaluj CLI na maszynie, na której działa `cc_server`.
:::

## Połącz dostawcę modeli

Wbudowany adapter potrzebuje co najmniej jednego połączonego dostawcy, zanim zacznie działać. W katalogu jest ich czternaście.

1. Przejdź do **Ustawienia → Serwer → Dostawcy modeli**
2. Przewiń do **Dostawcy i modele**
3. Znajdź swojego dostawcę i połącz go:

| Dostawca                                                                                                 | Jak połączyć                                                                                                                  |
| -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Anthropic                                                                                                | Klucz API. Subskrypcja Claude Pro/Max to nie to samo co logowanie do API Anthropic — dla tego planu użyj adaptera Claude Code |
| OpenAI, Codex, Cursor                                                                                    | Logowanie OAuth w przeglądarce albo klucz API. Codex to ChatGPT Plus/Pro przez backend Codex Responses, a nie uruchamiane CLI |
| Kimi Code                                                                                                | Wyłącznie OAuth w przeglądarce — przepływ z kodem urządzenia. To plan ryczałtowy, więc nie ma ceny za token                   |
| OpenRouter, Google Gemini, DeepSeek, Mistral, xAI, z.ai, z.ai GLM Coding Plan, Moonshot (Kimi API)       | Klucz API                                                                                                                     |

Punkt kontrolny: plakietka wiersza zmienia się na „Połączono", a po rozwinięciu wiersz wylicza modele obsługiwane przez tego dostawcę — każdy z ceną za milion tokenów i oknem kontekstu.

Tokeny OAuth trafiają do własnego magazynu poświadczeń serwera i są odświeżane, zanim wygasną. Poświadczenia dostawców są **globalne dla hosta** — współdzieli je każdy obszar roboczy w danej instalacji, nie są przypisane do jednego.

### Dodaj dostawcę własnego

Użyj tego dla Ollama, LM Studio, vLLM albo prywatnego wdrożenia.

1. W **Dostawcy i modele**, pod **Dostawcy własni**, naciśnij **Dodaj dostawcę**
2. Wpisz **Nazwę**, wybierz **Typ API** (zgodny z OpenAI albo zgodny z Anthropic) i podaj **Bazowy URL** (na przykład
   `http://localhost:11434/v1`)
3. Dodaj **Klucz API**, jeśli punkt końcowy go wymaga, a następnie naciśnij **Dodaj dostawcę**

Dostawca własny pojawia się na tej samej liście i ma przycisk usuwania, którego nie mają jego wbudowani odpowiednicy.

## Wybierz model dla agenta

1. Przejdź do **Ustawienia → Obszar roboczy → Agenci** i wybierz agenta
2. Na karcie **Ustawienia** wybierz **Adapter**
3. Wybierz **Model** z listy rozwijanej obok

W przypadku wbudowanego adaptera lista rozwijana jest składana na bieżąco z katalogu każdego połączonego dostawcy. Dostawca bez zapisanych poświadczeń nie wnosi żadnych modeli — dlatego pusta lista rozwijana prawie zawsze oznacza „nic jeszcze nie podłączono", a nie „nic nie jest dostępne".

:::note[models.dev to wzbogacenie, nigdy źródło identyfikatorów]
Dołączony katalog [models.dev](https://models.dev) dostarcza cenę i okno kontekstu dla modelu, który już jest na bieżącej liście. Nigdy nie dodaje identyfikatora modelu. Jeśli brakuje modelu, którego oczekujesz, to punkt końcowy dostawcy go nie zwraca.
:::

Identyfikatory modeli dla wbudowanego adaptera mają postać `provider/model` i mogą nieść łańcuch zapasowy rozdzielony znakiem `|`. W przypadku łańcucha zapasowego koszt jest liczony według modelu, który faktycznie obsłużył turę, a nie tego, o który poproszono.

:::note[Agent bez adaptera działa na wbudowanej pętli]
Każdy obszar roboczy tworzy pięciu agentów — CEO oraz `qa`, `architect`, `engineer` i `librarian` — bez adaptera i bez modelu. Wysyłanie zadań cofa się do **Control Center (built-in)**, a nie do ustawienia **Domyślne runnery** na tej stronie, które jest preferencją klienta nigdy nieodczytywaną przez ścieżkę wysyłania. Dziennik uruchomień zapisuje `cc-harness` dla takich uruchomień, więc transkrypt podaje, co faktycznie zostało uruchomione.

Gdy nie ma też modelu, wbudowana pętla pyta Anthropic o jego model domyślny. Agent pozostawiony całkowicie bez ustawień uruchomi się więc, jeśli masz połączone konto Anthropic, a w przeciwnym razie zakończy się błędem `No credential for provider "anthropic"`.

Ukończenie kroku adaptera w onboardingu uzupełnia **każdego** agenta, któremu wciąż brakuje adaptera lub modelu — CEO i specjalistów, we wszystkich obszarach roboczych istniejących w tym momencie — wybraną parą. Obszary robocze utworzone później wciąż tworzą tych pięciu bez ustawień. Ustaw adapter i model jawnie dla każdego agenta, którego zamierzasz używać.
:::

## Zainstaluj CLI runnera

Wbudowany adapter nie wymaga instalacji. Dla Claude Code zainstaluj jego CLI **na hoście serwera** za pomocą menedżera pakietów tego narzędzia, na przykład:

```bash
npm install -g @anthropic-ai/claude-code
```

Następnie naciśnij **Odśwież** u góry strony. Każdy wykryty wiersz pokazuje ustaloną wersję i ścieżkę oraz plakietki informujące, czy obsługuje tryb JSON i wybór modelu.

Zewnętrzne CLI przechowuje własne poświadczenia, we własnej konfiguracji, na hoście serwera. Control Center nimi nie zarządza.

:::caution[Dodatkowe argumenty adaptera i zmienne środowiskowe zostają na tym urządzeniu]
Każdy wiersz adaptera oferuje pole **Dodatkowe argumenty** i okno **Zmienne środowiskowe**. Te wartości są przechowywane na Twoim urządzeniu. Serwer odczytuje argv i zmienne środowiskowe uruchomienia z własnego magazynu ustawień. Klucze dostawców umieść na serwerze (OAuth albo pole klucza na stronie Dostawcy modeli), a nie w tych dwóch polach.
:::

## Ogranicz, których dostawców może używać obszar roboczy

Zarządzanie dostawcami działa per obszar roboczy i rozstrzyga się według ostatniego dopasowania.

1. W **Dostawcy i modele** wyłącz przełącznik **Zezwól** w wierszu dostawcy

To zapisuje instrukcję `deny` dla tego dostawcy w aktywnym obszarze roboczym, a jego modele wypadają z katalogu tego obszaru. Ponowne włączenie przełącznika usuwa tę instrukcję.

## Rozwiązywanie problemów

### Runner jest oznaczony jako nieznaleziony

- Sprawdź, czy CLI jest w `PATH` **hosta serwera**, a nie tylko w Twoim
- Aplikacja desktopowa uruchomiona z poziomu GUI startuje swój serwer z minimalnym `PATH`; CLI zainstalowane w ścieżce dostępnej tylko z powłoki może być dla niej niewidoczne
- Po instalacji naciśnij **Odśwież**

### Lista rozwijana modeli jest pusta

- Adapter jest wbudowany i żaden dostawca nie jest połączony — połącz jednego w **Dostawcy i modele**
- Albo dostawca jest połączony, ale zablokowany przełącznikiem zarządzania w tym obszarze roboczym

### Model działa, ale cena jest nieznana

Bieżąca lista modeli niesie identyfikator; cena i kontekst pochodzą z models.dev. Całkiem nowy model albo model od dostawcy własnego nie ma jeszcze wpisu w katalogu.
