Ten poradnik pokazuje, jak połączyć zewnętrznego klienta MCP — Claude Code,
edytor, MCP Inspector — z serwerem narzędzi samego Control Center.

Control Center rejestruje **110** narzędzi i udostępnia je przez Model Context
Protocol w wersji protokołu `2024-11-05`. Całych rodzin narzędzi, których można
by się spodziewać, brakuje: nie ma narzędzi do spotkań ani kalendarza, nie ma
też narzędzi projektowych.

## Znajdź punkt końcowy

Powierzchnia MCP korzysta z głównego nasłuchu `cc_server`. Nie ma osobnego
portu MCP.

| Punkt końcowy | Metoda   | Przeznaczenie                                                |
| ------------- | -------- | ------------------------------------------------------------ |
| `/mcp`        | `POST`   | Transport Streamable HTTP — właśnie tym posługuje się klient  |
| `/mcp`        | `DELETE` | Zakończ sesję                                                |
| `/sse`        | `GET`    | Strumień powiadomień wysyłanych przez serwer                  |

Domyślna instalacja lokalna działa więc pod `http://127.0.0.1:9030/mcp`.

1. Przejdź do **Ustawienia → Serwer → Serwery MCP**
2. Odczytaj kartę **Serwer MCP** — pokazuje, czy działa, czy jest zatrzymany,
   oraz port, na którym nasłuchuje

Powierzchnia jest domyślnie włączona w świeżej instalacji. Token karty widzi tylko właściciel
serwera, i tylko on może uruchomić lub zatrzymać punkt końcowy. **Uruchom przy starcie aplikacji** decyduje,
czy powróci ona po restarcie; **Uruchom** / **Zatrzymaj** to elementy sterujące
sesją, które nie zmieniają tej preferencji.

Serwer domyślnie wiąże się z loopbackiem, więc punkt końcowy jest osiągalny
tylko z maszyny, na której działa `cc_server` — chyba że uruchomiono go
z `--bind any`.

## Pobierz token

Każde żądanie wymaga tokenu MCP serwera, z dowolnej maszyny, także z loopbacku. Serwer tworzy go
przy pierwszym uruchomieniu. Nie ma sposobu, by go wyłączyć, ani by go wyczyścić.

1. W **Ustawienia → Serwer → Serwery MCP** znajdź wiersz **Token uwierzytelniający**
2. Naciśnij **Pokaż token** i skopiuj go
3. Aby go zastąpić, naciśnij **Zrotuj token**. Serwer przełącza się na nowy token od razu, a każdy
   klient, który wciąż używa starego, jest odrzucany, dopóki nie dostanie nowego

## Połącz klienta

Skieruj klienta na punkt końcowy Streamable HTTP i wysyłaj token jako
`Authorization: Bearer <token>` przy każdym żądaniu, także `GET /sse`. Nie ma innego sposobu jego
wysłania: token w adresie URL nie jest przyjmowany. Dokładny kształt konfiguracji to sprawa klienta.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code nie podchwyci tego z projektowego pliku `.mcp.json` — serwery MCP
o zasięgu projektu stawia za monitem o zatwierdzenie, na który nieinteraktywne
`claude -p` nigdy nie odpowie. Przekaż konfigurację wprost:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` sprawia, że Claude korzysta wyłącznie z tego pliku, więc
ten sam serwer nie zostanie dodatkowo wykryty z projektu i zarejestrowany dwa
razy.

Punkt kontrolny: poproś klienta o wyliczenie swoich narzędzi. Powinny pojawić
się wpisy `mcp__*` obejmujące zgłoszenia, przestrzenie, pamięć, graf kodu
i recenzję.

## Czego punkt końcowy odmawia

Token otwiera każde narzędzie na serwerze, więc punkt końcowy odrzuca też wszystko, co mogła
wysłać strona internetowa, zanim spojrzy na token:

| Żądanie | Odpowiedź |
| ------- | --------- |
| Nagłówek `Origin`, który nie jest stroną na tej maszynie (`http://localhost`, `http://127.0.0.1` lub `http://[::1]`, dowolny port) | `403`, „Żądania między domenami nie są przyjmowane” |
| Nagłówek `Host`, który nie jest ani adresem loopback i portem tego nasłuchu, ani publiczną nazwą hosta serwera | `403`, „Nieznany host” |
| `POST`, którego treść nie jest `application/json` | `415` |
| Brak tokenu albo zły token | `401` |

Aby obsłużyć MCP poza hostem, uruchom serwer z `--bind any` i wysyłaj token z innej maszyny,
adresując serwer po jego publicznej nazwie hosta.

## Ogranicz każde wywołanie do obszaru roboczego

Każde narzędzie dotykające danych o zasięgu obszaru roboczego wymaga
`workspace_id`, a wywołanie bez niego jest odrzucane, a nie rozstrzygane
względem jakiegoś „bieżącego" obszaru roboczego:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

Identyfikator to ten z adresu URL w przeglądarce lub aplikacji:
`/workspaces/<workspace_id>/…`. Jedyne wyjątki to narzędzia, które rzeczywiście
obejmują wiele obszarów roboczych, jak `list_workspaces` i narzędzia newsfeeda —
newsfeed należy do użytkownika, a agent nie ma własnego użytkownika, więc te
narzędzia działają na kanałach właściciela serwera.

Narzędzia o zasięgu repozytorium dodatkowo sprawdzają, czy repozytorium jest
powiązane z tym obszarem roboczym.

## Wiedz, czego powierzchnia odmówi

- **Bramkowanie trybem.** Wywołanie jest rozstrzygane po stronie serwera
  względem trybu przestrzeni wywołującego agenta. Agent w trybie tylko do odczytu
  nie sięgnie po narzędzie zapisu przez pominięcie `space_id` — tryb jest
  bowiem odczytywany z jego aktywnego uruchomienia.
- **Guardraile działań.** Narzędzia mutujące deklarują swoje klasy efektów
  i przechodzą przez tę samą politykę, której używa reszta produktu. Zobacz
  [Skonfiguruj guardraile](/pl-PL/podrecznik/poradniki/konfiguracja-guardraili/).
- **Potwierdzenie.** Niektóre niszczące narzędzia budują ładunek potwierdzenia,
  który trzeba zatwierdzić, zanim wywołanie ruszy dalej.

Pełny katalog jest ogłaszany w `tools/list` bez bramkowania wykrywania —
zewnętrzny klient MCP odmawia wywołania narzędzia, którego nie ma na jego
zbuforowanej liście, więc ukrywanie narzędzi je psuje, a nie porządkuje.

## Serwery MCP używane przez agentów

Ten poradnik dotyczy własnego punktu końcowego Control Center. Drugi kierunek to serwery MCP, z którymi Control Center się łączy i które przekazuje agentom, jakie uruchamia. Konfiguruje się je w **Ustawienia → Serwer → Serwery MCP**, na dwóch poziomach. W obu przypadkach Control Center łączy się z samym serwerem i przekazuje jego narzędzia do uruchomienia, więc wbudowany harness i Claude Code dostają te same narzędzia oraz te same prośby o zatwierdzenie. Uruchomienie Claude Code widzi je w serwerze `control-center` jako `mcp__control-center__mcp__<server>__<tool>`.

### Serwery obszaru roboczego

Administratorzy obszaru roboczego dodają je w **Serwery MCP obszaru roboczego**. Każde uruchomienie agenta w obszarze roboczym dostaje ich narzędzia, a uruchomienia w innych obszarach roboczych nie.

1. Wybierz **Dodaj serwer** i nadaj mu krótką nazwę: litery, cyfry, `-` i `_`, do 24 znaków. Narzędzia pojawiają się jako `mcp__<name>__<tool>`.
2. Wybierz sposób połączenia:
   - **Polecenie (stdio):** plik wykonywalny i jego argumenty oraz zmienne środowiskowe, których potrzebuje.
   - **URL (HTTP lub SSE):** adres punktu końcowego i potrzebne nagłówki, na przykład `Authorization: Bearer …`.
3. Zapisz. Punkt kontrolny: serwer pokazuje **Połączono** i liczbę narzędzi.

Wartości zmiennych środowiskowych i nagłówków są zapisywane w pliku z sekretami serwera i nie są pokazywane ponownie. Aby zmienić wartość, zastąp ją; aby ją usunąć, usuń nazwę.

Polecenie działa na maszynie serwera jako własny użytkownik serwera, dlatego nie uruchomi się, dopóki właściciel serwera go nie zatwierdzi. Do tego czasu widnieje przy nim **Oczekuje na zatwierdzenie**. Serwer z URL działa od razu, ale do zatwierdzenia przez właściciela serwera może łączyć się tylko z publicznymi adresami; zatwierdzenie pozwala też na `localhost` i sieci prywatne. Gdy właściciel zapisze serwer, liczy się to jako zatwierdzenie. Jeśli ktokolwiek inny zmieni sposób uruchamiania serwera albo adres połączenia, potrzebne jest ponowne zatwierdzenie. Włączenie lub wyłączenie serwera nie zmienia zatwierdzenia.

### Serwery osobiste

Serwery osobiste należą do właściciela serwera i są wymienione pod **Zewnętrzne serwery MCP**. Serwery skonfigurowane na maszynie serwera dla Claude, Codex, Cursor, Gemini, VS Code, Windsurf, OpenCode lub w `.mcp.json` są tam znajdowane automatycznie. Właściciel serwera może dodać własne, używając **Dodaj serwer** i tego samego formularza. Serwer dodany ręcznie ma pierwszeństwo przed wykrytym o tej samej nazwie.

Działają z tożsamością i poświadczeniami właściciela serwera:

- Są dostępne tylko w uruchomieniach, które właściciel serwera rozpoczyna lub za które odpowiada, w tym w automatyzacji w obszarze roboczym, za który właściciel odpowiada. Dotyczy to wbudowanych uruchomień harnessu i uruchomień Claude Code.
- Uruchomienie członka, automatyzacja przypisana do członka i każde uruchomienie na serwerze bez zapisanego właściciela nie dostają żadnego z nich. Tam narzędzia nie są wyświetlane, nie można ich wywołać i nie pojawiają się w wyszukiwaniu narzędzi.
- Ani serwery osobiste, ani serwery obszaru roboczego nie są udostępniane tokenowi MCP ani sparowanym urządzeniom, a ich zasoby i prompty nie są przekazywane dalej.

Logowanie do serwera przez OAuth nie jest dostępne z formularza. Użyj serwera, który przyjmuje token w nagłówku, albo skonfiguruj go dla jednego z narzędzi powyżej, w którym zostanie wykryty.

## Rozwiązywanie problemów

### Klient nie widzi żadnych narzędzi

- Sprawdź, czy karta **Serwer MCP** pokazuje, że działa
- Sprawdź, czy port zgadza się z portem Twojego `cc_server`
- W Claude Code sprawdź, czy przekazano `--mcp-config` i `--strict-mcp-config`

### 401 Unauthorized

Żądanie nie zawierało tokenu albo zawierało stary. Skopiuj bieżący token z wiersza **Token
uwierzytelniający** i wyślij go jako `Authorization: Bearer <token>`. Token w adresie URL jest
ignorowany.

### 403 od klienta, który działał wcześniej

Żądanie zawierało `Origin` ze strony internetowej albo `Host`, na który serwer nie odpowiada.
Wywołuj punkt końcowy z klienta, a nie ze strony w przeglądarce, po adresie loopback serwera albo
jego publicznej nazwie hosta.

### 415 Unsupported Media Type

Wysyłaj treści `POST /mcp` jako `application/json`.

### Wywołanie narzędzia kończy się błędem "Missing or invalid argument: workspace_id"

Dodaj `workspace_id`. Nie istnieje żaden domyślny obszar roboczy.

### Wywołanie narzędzia jest odrzucane jako nieznane

[Narzędzia MCP](/pl-PL/podrecznik/dokumentacja-referencyjna/narzedzia-mcp/)
wymieniają katalog. Wywołuj nazwę dokładnie tak, jak tam występuje.
