Ten poradnik pokazuje, jak połączyć zewnętrznego klienta MCP — Claude Code,
edytor, MCP Inspector — z serwerem narzędzi samego Control Center.

Control Center rejestruje **110** narzędzi i udostępnia je przez Model Context
Protocol w wersji protokołu `2024-11-05`. Całych rodzin narzędzi, których można
by się spodziewać, brakuje: nie ma narzędzi do spotkań ani kalendarza, nie ma
też narzędzi projektowych.

## Znajdź punkt końcowy

Powierzchnia MCP korzysta z głównego nasłuchu `cc_server`. Nie ma osobnego
portu MCP.

| Punkt końcowy | Metoda   | Przeznaczenie                                                |
| ------------- | -------- | ------------------------------------------------------------ |
| `/mcp`        | `POST`   | Transport Streamable HTTP — właśnie tym posługuje się klient  |
| `/mcp`        | `DELETE` | Zakończ sesję                                                |
| `/sse`        | `GET`    | Strumień powiadomień wysyłanych przez serwer                  |

Domyślna instalacja lokalna działa więc pod `http://127.0.0.1:9030/mcp`.

1. Przejdź do **Ustawienia → Serwer → Serwery MCP**
2. Odczytaj kartę **Serwer MCP** — pokazuje, czy działa, czy jest zatrzymany,
   oraz port, na którym nasłuchuje

Powierzchnia jest domyślnie włączona w świeżej instalacji, więc klient loopback
działa bez zaglądania do ustawień. **Uruchom przy starcie aplikacji** decyduje,
czy powróci ona po restarcie; **Uruchom** / **Zatrzymaj** to elementy sterujące
sesją, które nie zmieniają tej preferencji.

Serwer domyślnie wiąże się z loopbackiem, więc punkt końcowy jest osiągalny
tylko z maszyny, na której działa `cc_server` — chyba że uruchomiono go
z `--bind any`.

## Połącz klienta

Skieruj klienta na punkt końcowy Streamable HTTP. Dokładny kształt konfiguracji
to sprawa klienta; adres URL jest taki sam w obu przypadkach.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp"
    }
  }
}
```

### Claude Code

Claude Code nie podchwyci tego z projektowego pliku `.mcp.json` — serwery MCP
o zasięgu projektu stawia za monitem o zatwierdzenie, na który nieinteraktywne
`claude -p` nigdy nie odpowie. Przekaż konfigurację wprost:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` sprawia, że Claude korzysta wyłącznie z tego pliku, więc
ten sam serwer nie zostanie dodatkowo wykryty z projektu i zarejestrowany dwa
razy.

Punkt kontrolny: poproś klienta o wyliczenie swoich narzędzi. Powinny pojawić
się wpisy `mcp__*` obejmujące zgłoszenia, przestrzenie, pamięć, graf kodu
i recenzję.

## Obsłuż MCP poza hostem

1. W **Ustawienia → Serwer → Serwery MCP**, w wierszu **Token uwierzytelniający**,
   naciśnij **Ustaw** i wklej token
2. Wysyłaj go jako `Authorization: Bearer <token>` przy każdym żądaniu
   `POST /mcp`

Powierzchnia bez tokenu odrzuca każdego wywołującego spoza loopbacku kodem 403.
To celowa postawa domyślnej odmowy (fail-closed): to token w ogóle umożliwia
obsługę poza hostem.

Zmiany tokenu obowiązują na żywej powierzchni natychmiast — bez restartu.

:::note[`GET /sse` przyjmuje token w ciągu zapytania]
Strumień powiadomień jest sprawdzany pod kątem tokenu jak każda inna trasa, ale
przeglądarkowy `EventSource` nie może wysłać nagłówka `Authorization` — dlatego
`/sse` przyjmuje token także jako `?token=<token>`. Bez niego odpowiada 401.
:::

## Ogranicz każde wywołanie do obszaru roboczego

Każde narzędzie dotykające danych o zasięgu obszaru roboczego wymaga
`workspace_id`, a wywołanie bez niego jest odrzucane, a nie rozstrzygane
względem jakiegoś „bieżącego" obszaru roboczego:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

Identyfikator to ten z adresu URL w przeglądarce lub aplikacji:
`/workspaces/<workspace_id>/…`. Jedyne wyjątki to narzędzia, które rzeczywiście
obejmują wiele obszarów roboczych, jak `list_workspaces` i narzędzia newsfeeda —
newsfeed należy do użytkownika, a agent nie ma własnego użytkownika, więc te
narzędzia działają na kanałach właściciela serwera.

Narzędzia o zasięgu repozytorium dodatkowo sprawdzają, czy repozytorium jest
powiązane z tym obszarem roboczym.

## Wiedz, czego powierzchnia odmówi

- **Bramkowanie trybem.** Wywołanie jest rozstrzygane po stronie serwera
  względem trybu przestrzeni wywołującego agenta. Agent w trybie tylko do odczytu
  nie sięgnie po narzędzie zapisu przez pominięcie `space_id` — tryb jest
  bowiem odczytywany z jego aktywnego uruchomienia.
- **Guardraile działań.** Narzędzia mutujące deklarują swoje klasy efektów
  i przechodzą przez tę samą politykę, której używa reszta produktu. Zobacz
  [Skonfiguruj guardraile](/pl-PL/podrecznik/poradniki/konfiguracja-guardraili/).
- **Potwierdzenie.** Niektóre niszczące narzędzia budują ładunek potwierdzenia,
  który trzeba zatwierdzić, zanim wywołanie ruszy dalej.

Pełny katalog jest ogłaszany w `tools/list` bez bramkowania wykrywania —
zewnętrzny klient MCP odmawia wywołania narzędzia, którego nie ma na jego
zbuforowanej liście, więc ukrywanie narzędzi je psuje, a nie porządkuje.

## Rozwiązywanie problemów

### Klient nie widzi żadnych narzędzi

- Sprawdź, czy karta **Serwer MCP** pokazuje, że działa
- Sprawdź, czy port zgadza się z portem Twojego `cc_server`
- W Claude Code sprawdź, czy przekazano `--mcp-config` i `--strict-mcp-config`

### Kod 403 z maszyny, która nie jest serwerem

Nie skonfigurowano tokenu bearer. Ustaw go i wysyłaj.

### Wywołanie narzędzia kończy się błędem "Missing or invalid argument: workspace_id"

Dodaj `workspace_id`. Nie istnieje żaden domyślny obszar roboczy.

### Wywołanie narzędzia jest odrzucane jako nieznane

[Narzędzia MCP](/pl-PL/podrecznik/dokumentacja-referencyjna/narzedzia-mcp/)
wymieniają katalog. Wywołuj nazwę dokładnie tak, jak tam występuje.
