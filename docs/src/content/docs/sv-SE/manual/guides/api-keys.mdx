Den här guiden visar var varje autentiseringsuppgift som Control Center använder
lagras, och hur du ändrar den.

**Inget lagras på maskinen du skriver på.** Varje autentiseringsuppgift finns på
servern; vilken av dem som svarar på en viss begäran beror på om det finns en
människa bakom den.

| Autentiseringsuppgift                     | Lagras                                                                      | Vem som använder den                                                |
| ----------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Din kodvärds-/ärendeautentiseringsuppgift | Serverns hemlighetsfil med rättigheterna 0600, knuten till ditt användar-id | Allt du ber om: PR-ytan, dina agentkörningar, dina images           |
| Serverns appidentitet                     | Samma fil, plus `server_settings` för det som inte är hemligheter           | Arbete som ingen människa bad om: webhooks, PR-pollning, ärendesynk |
| Modellleverantörsnycklar och OAuth-tokens | Serverns eget uppgiftslager                                                 | Den inbyggda adaptern, för varje arbetsyta i installationen         |
| Slack-bottokens                           | `<dataDir>/<workspaceId>/chat_credentials/` på servern                      | Chattbryggan för den arbetsytan                                     |
| Autentiseringsuppgifter för externa CLI:n | Det som det CLI:t använder                                                  | Claude Code, på servervärden                                        |

## Två GitHub-autentiseringsuppgifter som svarar på olika frågor

- **Din egen**, från inloggningen (device-code-flödet) eller från att du klistrar
  in en token. Det är den som varje begäran som görs *för din räkning* använder,
  så en kommentar som publiceras för dig bär ditt namn. En annan medlem kan inte
  läsa den, och ansluter sin egen
- **Serverns egen**, från GitHub-appen som operatören registrerade. Den svarar på
  allt som inte har någon anropare – så åtkomsten till kodvärden försvinner inte
  när någon slutar eller roterar en token

Din egen anges i kortet **Kodvärd** under **Inställningar → Arbetsyta → Profil och
identitet**; serverns i **Leverantörsappar** under **Inställningar → Server → Enkel
inloggning**. Se [Konfigurera GitHub-integration](/sv-SE/handbok/how-to-guider/github-integration/)
och [Skapa GitHub-appen](/sv-SE/handbok/how-to-guider/github-app/).

:::note[Det finns även en skärm som bara nås via URL]
`/workspaces/<workspaceId>/api-keys` visar samma två kort som första steget i
introduktionsflödet. Den har **ingen navigationspost någonstans i gränssnittet**;
den nås bara genom att skriva URL:en. Använd Inställningar → Arbetsyta → Profil
och identitet i stället.
:::

## Ange nycklar för modellleverantörer

Den inbyggda adaptern autentiserar leverantörerna själv, och de
autentiseringsuppgifterna finns på servern.

1. Gå till **Inställningar → Server → Modellleverantörer**
2. Bläddra ned till **Leverantörer och modeller**
3. Anslut leverantören – OAuth i webbläsaren för OpenAI, Codex, Cursor och Kimi
   Code; en API-nyckel för Anthropic och övriga

Se [Hantera adapters och modeller](/sv-SE/handbok/how-to-guider/adapters/) för hela listan och
för att lägga till en anpassad slutpunkt.

De här autentiseringsuppgifterna är **globala för värden**: en nyckel betjänar
varje arbetsyta i installationen. OAuth-tokens förnyas innan de går ut.

Externa adapter-CLI:n behåller sina egna autentiseringsuppgifter, i sin egen
konfiguration, på servervärden – Control Center hanterar dem inte. Autentisera
Claude Code på det sätt som dess egen dokumentation beskriver, på maskinen som
kör `cc_server`.

Dialogen **Miljövariabler** per adapter ser ut som en plats att lägga en nyckel
för en av dem på, men det är den inte: den skriver till din enhet, medan servern
läser sin egen kopia och ingenting överbryggar de två. Se
[Hantera adapters och modeller](/sv-SE/handbok/how-to-guider/adapters/).

## Anslut en ärendeleverantör

Kortet **Ärenden** under **Inställningar → Arbetsyta → Allmänt** rymmer båda
halvorna av ett och samma beslut: hos vilken leverantör dina ärenden ligger, och
autentiseringsuppgiften för den. Om du väljer **Lokal** döljs raden för
autentiseringsuppgiften – lokala ärenden ligger i serverns egen databas och har
inget att autentisera mot.

Din nyckel lagras på servern knuten till ditt användar-id, precis som
kodvärdsnyckeln. Servern håller sin egen Linear-nyckel separat
(**Leverantörsappar**), och det är den ärendesynken kör på när ingen människa har
bett om något. Ingen ärendenyckel injiceras i en agents sandlåda; agenter
skriver ärenden via Control Centers verktyg, som frågar regeln **Skriv till ett
externt ärendesystem**. Se
[Konfigurera Linear-integration](/sv-SE/handbok/how-to-guider/linear-integration/).

## Rotera eller återkalla

- **Din GitHub-autentiseringsuppgift**: tryck på **Koppla från** och logga sedan
  in igen eller klistra in den nya token. Återkalla den gamla på GitHub
- **Serverns app**: generera en ny privat nyckel eller klienthemlighet på appens
  GitHub-sida, klistra in den i **Leverantörsappar** och tryck på **Test**
- **En modellleverantör**: logga ut på dess rad (OAuth) eller ta bort nyckeln och
  anslut sedan igen
- **Slack**: klistra in tokens igen i anslutningsdialogen. Se
  [Konfigurera Slack-integration](/sv-SE/handbok/how-to-guider/slack-integration/)

## Felsökning

### PR-listan är tom men min token fungerar i `curl`

Kontrollera undertexten på raden **Kodvärd**. Om den anger en annan källa (”via
den här serverns app”, ”från miljön”) är det inte autentiseringsuppgiften du
testar som svarar – din sparades inte.

### Token accepteras men senare begäranden misslyckas

Token avsöks så som den lagras, så raden namnger kontot bakom den – men bara
kontot, inte behörigheterna. En token med för få behörigheter ansluter och
misslyckas sedan med enskilda begäranden. Kontrollera behörigheterna och
giltighetstiden:

```bash
curl -H "Authorization: token YOUR_TOKEN" https://api.github.com/user
```
