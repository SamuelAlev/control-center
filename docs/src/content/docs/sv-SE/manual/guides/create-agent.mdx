Den här guiden visar hur du lägger till en agent i en arbetsyta och konfigurerar den tills den faktiskt kan köra.

Varje arbetsyta skapas med fem agenter – en CEO plus `qa`, `architect`, `engineer` och `librarian` – så du har oftast agenter redan innan du har konfigurerat någon. Stegen nedan gäller lika mycket för en medföljande agent som för en ny.

## Innan du börjar

- Du är inne i en arbetsyta. Hela gränssnittet ligger under **Inställningar → Arbetsyta → Agenter** (`/settings/workspace/agents`).
- Agenten behöver en backend. Antingen ansluter du en leverantör för den inbyggda harnessen under **Inställningar → Server → Modellleverantörer**, eller så installerar du Claude Code CLI på maskinen som kör `cc_server`.
- Om du vill att agenten ska ha skills installerar du dem först under **Inställningar → Arbetsyta → Färdigheter**. I agentformuläret kan du bara slå på skills som redan finns i arbetsytan.

## Lägg till agenten

1. Öppna **Inställningar → Arbetsyta → Agenter**.
2. Klicka på **Ny agent**.

Det finns ingen dialog och ingen rollväljare. En agent med namnet ”Namnlös agent” skapas direkt och markeras i detaljpanelen till höger.

Nu bör du se ”Namnlös agent” i listan till vänster, med fliken **Inställningar** i detaljpanelen öppen och ett fält **Namn** som innehåller ”Namnlös agent”.

## Ge den ett namn

- **Namn** – den korta identifieraren som används i @-omnämnanden, till exempel `alice`. Tolkningen av omnämnanden matchar `@` följt av ordtecken, så ett namn med bindestreck, punkt eller mellanslag kan aldrig nämnas.
- **Titel** – den läsbara etiketten, till exempel ”Seniorutvecklare”.
- **Systemprompt** – valfria extra instruktioner som injiceras som avsnittet Agent instructions; de ersätter inte resten av den sammansatta prompten.

Klicka på **Spara ändringar** längst ned i formuläret. Varje fält på den här sidan sparas med den enda knappen.

## Ge den en adapter och en modell

Listrutan **Adapter** visar de körare som servervärden faktiskt har. Den inbyggda adaptern hittas alltid (den är servern). Claude Code visas bara om dess CLI har upptäckts på den värden:

| Adapter                   | Backend                                       |
| ------------------------- | --------------------------------------------- |
| Control Center (built-in) | Den processinterna agentloopen – ingen extern CLI |
| Claude Code               | `claude -p --output-format stream-json`       |

Bara den inbyggda adaptern upprätthåller lägen, styrning, paus/återupptagning, slutförandekontrakt och subagenter. Claude Code ger dig inget av det. Cursor, Codex och de andra modellleverantörerna kopplas till den inbyggda adaptern, inte som egna körare.

:::note[En tom adapter betyder den inbyggda loopen]
En agent vars adapter inte är angiven skickas till **Control Center (built-in)**, loopen inuti servern, så inget behöver installeras på värden. Om inte heller någon modell är angiven frågar den Anthropic efter dennes standard, så en helt oangiven agent körs bara om du har anslutit ett Anthropic-konto. De medföljande specialisterna levereras utan båda; ange båda på varje agent du tänker använda.
:::

Listrutan **Modell** styrs av den adapter du valde. För den inbyggda adaptern kommer listan direkt från de leverantörer du har anslutit under **Inställningar → Server → Modellleverantörer**, så en leverantör utan sparad inloggningsuppgift bidrar med noll modeller.

## Lägg till skills

**Färdigheter** är en chipväljare över de skill-paket som är installerade i den här arbetsytan. Tryck på en chip för att slå på eller av den; bockikonen markerar de valda. Om arbetsytan inte har några skills står det ”No skills available. Create skills in Settings → Skills first.” i fältet.

Du väljer inte ett repos egna skills här. Ett repo som levererar dem (i `.agents/skills/`, `.claude/skills/` eller `.opencode/skills/`) bidrar automatiskt med dem till den agent som arbetar i det repot, och de byts ut när den flyttar till ett annat – se [Reposcopade skills](/sv-SE/handbok/koncept/agentmodell/#repo-scoped-skills).

## Ange rapporteringslinje och persona

- **Rapporterar till** – välj en annan agent via namnet. Det här bygger rapporteringsträdet som knappen **Organisationsschema** i sidhuvudet visar. Det är inte den lista som en teamledare använder när den delegerar – den kommer från teamets medlemmar och deras skills.
- **Persona** – fri text som formar ton och beteende, till exempel: ”Föredrar enkla, läsbara lösningar. Skriver tester för all ny kod.”

## Finjustera körningen

- **Resonemangsinsats** – alternativen kommer från den valda modellens egna publicerade nivåer: Low / Medium / High, plus Extra High på modeller i OpenAI-stil och Extra High + Max på modeller i Claude-stil. Fältet döljs helt när den valda modellen inte anger några resonemangsnivåer, och det står på modellens egen standard.
- **Storlek på kontextfönster** – förifylls från modellens kontextfönster varje gång du byter modell, med chips för ett tryck för modellens standard, 200k, 500k och 1M. Ett värde som du skriver in efter att ha valt modellen gäller till nästa modellbyte.
- **Tystnadstimeout (minuter)** – avsluta en körning efter så här lång tid utan utdata. Lämna tomt för att använda standarden per läge.

## Bevilja behörigheter

**Sandlådebehörigheter** börjar på ”Använd arbetsytans standard”. Slå på växeln för att ange dem för den här agenten och växla sedan:

- **Tillåt git push** – injicerar GitHub-token som agenten behöver för att pusha
- **Tillåt GitHub API-anrop** – låter agenten läsa PR:ar, issues och repometadata
- **Tillåt API-anrop för ärenden** – injicerar ärendeleverantörens nyckel
- **Tillåt allmän nätverksåtkomst** – aktiverar även den inbyggda harnessens verktyg `web_fetch` och `web_search`

Varje växel kontrolleras av brokern när körningen startar: en förmåga som är av betyder helt enkelt att den matchande token aldrig skapas och läggs i körningens miljö.

:::caution[Arbetsytans standard betyder serverns försiktiga uppsättning]
En agent som lämnas på ”Använd arbetsytans standard” körs med git push, GitHub-API och ärenden **av** och nätverk **på**. Standardförmågorna som visas under Inställningar → Server → Diagnostik och integritet är en inställning på klientsidan. Om du vill att en agent ska pusha eller öppna PR:ar slår du på växeln och beviljar förmågorna uttryckligen.

De här förmågorna reglerar åtkomsten till inloggningsuppgifter och harness-verktyg, vilket är ett separat lager från OS-sandlådan. `cc_server` omsluter agentkörningar i värdens sandlåda där en sådan finns – Windows har ingen inbyggd backend, och Linux och WSL2 behöver `bwrap` och `socat`. Se [Sandlåda och säkerhet](/sv-SE/handbok/koncept/sandlada-och-sakerhet/) för alla gränser.
:::

## Verifiera att den körs

1. Öppna **Inställningar → Server → Modellleverantörer** och bekräfta att adaptern du valde rapporterar en installerad version i stället för ”Hittades inte”. Klicka på **Uppdatera** för att söka igen – sökningen körs på maskinen som kör `cc_server`, inte på maskinen du tittar på.
2. Öppna en yta med agenten och skicka ett meddelande till den, eller @-nämn den i en befintlig yta.
3. Gå tillbaka till **Inställningar → Arbetsyta → Agenter**, välj agenten och öppna fliken **Loggar**. En körning bör visas med en statusbricka, en varaktighet, en starttid och adaptern den använde. **Visa** öppnar körningens händelseström.

Om ingen körning visas alls går du igenom [Felsök en agent](/sv-SE/handbok/how-to-guider/felsok-agent/).

## Ta bort en agent

Välj den i listan. På fliken **Inställningar** rullar du ned till **Farozon** längst ned i formuläret och klickar på **Ta bort**.
