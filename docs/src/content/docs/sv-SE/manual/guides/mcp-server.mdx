Den här guiden visar hur du ansluter en extern MCP-klient – Claude Code, en
editor, MCP Inspector – till Control Centers egen verktygsserver.

Control Center registrerar **110** verktyg och betjänar dem över Model Context
Protocol i protokollversionen `2024-11-05`. Hela verktygsfamiljer som du kanske
förväntar dig saknas: det finns inga mötes- eller kalenderverktyg och inga
projektverktyg.

## Hitta slutpunkten

MCP-ytan delar den huvudsakliga `cc_server`-lyssnaren. Det finns ingen separat
MCP-port.

| Slutpunkt | Metod    | Syfte                                                    |
| --------- | -------- | -------------------------------------------------------- |
| `/mcp`    | `POST`   | Streamable HTTP-transport – det här är vad en klient talar |
| `/mcp`    | `DELETE` | Avsluta en session                                       |
| `/sse`    | `GET`    | Server-sent-aviseringsström                              |

Så en standardinstallation lokalt ligger på `http://127.0.0.1:9030/mcp`.

1. Gå till **Inställningar → Server → MCP-servrar**
2. Läs kortet **MCP-server** – det visar om den körs eller är stoppad och vilken
   port den lyssnar på

Ytan är på som standard i en nyinstallation, så en loopback-klient fungerar utan
att du behöver röra inställningarna. **Starta vid applansering** styr om den
kommer tillbaka efter en omstart; **Starta** / **Stoppa** är sessionskontroller
som inte ändrar den inställningen.

Servern binder till loopback som standard, så slutpunkten nås bara från
maskinen som `cc_server` kör på, om du inte startade den med `--bind any`.

## Anslut en klient

Peka din klient mot Streamable HTTP-slutpunkten. Exakt hur konfigurationen ser
ut är upp till din klient; URL:en är densamma oavsett.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp"
    }
  }
}
```

### Claude Code

Claude Code plockar inte upp detta från en `.mcp.json` i projektet – den lägger
projektspecifika MCP-servrar bakom en godkännandeprompt som en icke-interaktiv
`claude -p` aldrig svarar på. Skicka med konfigurationen explicit:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` gör att Claude bara använder den filen, så att samma
server inte också upptäcks från projektet och registreras två gånger.

Kontrollpunkt: be klienten lista sina verktyg. Du bör se `mcp__*`-poster som
täcker ärenden, ytor, minne, kodgraf och granskning.

## Betjäna MCP utanför värden

1. I **Inställningar → Server → MCP-servrar**, på raden **Autentiseringstoken**,
   tryck på **Ange** och klistra in en token
2. Skicka den som `Authorization: Bearer <token>` i varje `POST /mcp`-begäran

En yta utan token avvisar alla anropare utanför loopback med 403. Det är
fail-closed med avsikt: token är det som över huvud taget gör tjänsten utanför
värden möjlig.

Tokenändringar slår igenom på den körande ytan omedelbart – ingen omstart krävs.

:::note[`GET /sse` tar token i frågesträngen]
Aviseringsströmmen kontrolleras mot token precis som alla andra rutter, men en
`EventSource` i webbläsaren kan inte skicka headern `Authorization` – så `/sse`
accepterar även token som `?token=<token>`. Utan en sådan svarar den 401.
:::

## Begränsa varje anrop till en arbetsyta

Varje verktyg som rör arbetsytespecifik data kräver `workspace_id`, och ett
anrop utan det avvisas i stället för att lösas mot någon ”aktuell” arbetsyta:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

Id:t är det som står i webbläsarens eller appens URL:
`/workspaces/<workspace_id>/…`. De enda undantagen är verktyg som verkligen
spänner över arbetsytor, som `list_workspaces` och nyhetsflödesverktygen –
nyhetsflödet gäller per användare och en agent har ingen egen användare, så de
verktygen arbetar mot serverägarens flöden.

Repospecifika verktyg kontrollerar dessutom att repot är länkat till den
arbetsytan.

## Vet vad ytan vägrar

- **Lägesstyrning.** Ett anrop löses mot läget för den anropande agentens yta,
  på serversidan. En agent i ett skrivskyddat läge kan inte nå ett skrivverktyg
  genom att utelämna `space_id` – läget slås i stället upp från dess aktiva
  körning.
- **Åtgärdsräcken.** Förändrande verktyg deklarerar sina effektklasser och
  passerar samma policy som resten av produkten använder. Se
  [Konfigurera räcken](/sv-SE/handbok/how-to-guider/konfigurera-racken/).
- **Bekräftelse.** Vissa destruktiva verktyg bygger en bekräftelsenyttolast som
  måste godkännas innan anropet fortsätter.

Hela katalogen annonseras i `tools/list` utan upptäcktsstyrning – en extern
MCP-klient vägrar anropa ett verktyg som inte finns i dess cachade lista, så att
dölja verktyg förstör dem i stället för att snygga till dem.

## Felsökning

### Klienten ser inga verktyg

- Kontrollera att kortet **MCP-server** säger att den körs
- Kontrollera att porten matchar din `cc_server`-port
- I Claude Code: kontrollera att du skickade med `--mcp-config` och
  `--strict-mcp-config`

### 403 från en maskin som inte är servern

Ingen bearer-token är konfigurerad. Ange en och skicka den.

### Ett verktygsanrop misslyckas med "Missing or invalid argument: workspace_id"

Lägg till `workspace_id`. Det finns ingen implicit arbetsyta.

### Ett verktygsanrop avvisas som okänt

[MCP-verktyg](/sv-SE/handbok/referens/mcp-verktyg/) listar katalogen. Anropa
namnet exakt som det står där.
