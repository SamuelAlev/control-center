Den här guiden visar hur du skapar och hanterar ärenden.

## Skapa ett ärende

### Från gränssnittet

1. Klicka på **Ärenden** i arbetsytans sidopanel.
2. Tryck på **Nytt ärende**.
3. Fyll i:
   - **Titel** — kort sammanfattning. Det är det enda obligatoriska fältet.
   - **Beskrivning** — markdown, med ett formateringsverktygsfält.
   - **Status** — **Att göra** (standardvärdet) eller **Backlog**. Startade och
     terminala tillstånd nås genom livscykeln, inte vid skapandet.
   - **Prioritet** — ingen, brådskande, hög, medel eller låg.
   - **Tilldelad** — du själv eller valfri agent i arbetsytan.
   - **Projekt** — valfri gruppering.
4. Tryck på **Skapa**, eller slå på **Skapa fler** först för att hålla
   dialogrutan öppen för snabb inmatning.

Det finns ingen leverantörsväljare i dialogrutan. Ärendet skapas mot arbetsytans
aktiva ärendeleverantör.

### Från en agent

Be en agent i en yta:

> Skapa ett ärende för att åtgärda problemet med inloggningstimeout vid
> långsamma anslutningar.

Den anropar MCP-verktyget `create_ticket`. Prioriteten i det verktyget är ett
**heltal**, inte ett namn:

```
create_ticket(
  workspace_id: "...",
  title: "Fix login timeout on slow connections",
  description: "...",
  priority: 2
)
```

| Värde | Prioritet    |
| ----- | ------------ |
| `0`   | Ingen        |
| `1`   | Brådskande   |
| `2`   | Hög          |
| `3`   | Medel        |
| `4`   | Låg          |

Endast `workspace_id` och `title` är obligatoriska; `description`, `priority`,
`assignee` (ett agent-id) och `team_id` är valfria. Verktyget klassas som en
skrivning till ett externt ärendesystem och begär ditt godkännande innan det
körs.

## Uppdatera ärendestatus

Ärenden följer den här livscykeln:

```
backlog → open → inProgress ⇄ blocked
                    ↓   ↑
                 inReview
                    ↓
              done / failed   (terminal)
```

`done`, `failed` och `cancelled` är terminala. `cancelled` nås från vilken
icke-terminal status som helst. `done` och `failed` nås från `inProgress` eller
`inReview`; `open` kan också flyttas direkt till `blocked`. Gränssnittets
statusväljare listar alla statusar utom `failed` — agenter markerar den med
`fail_ticket`.

Du ändrar statusen på något av följande sätt:

- raden **Status** i ärendets egenskapspanel,
- undermenyn **Status** i ett ärendes högerklicksmeny i listan,
- taggen **Status** på den flytande listen när du har markerat flera ärenden.

:::note[Livscykelgrafen binder agenter, inte dig]
Varje statusändring som görs från gränssnittet tvingas igenom och kringgår grafen
helt — du kan flytta ett ärende till vilken status som helst som väljaren
listar, inklusive att återöppna ett `done`-, `failed`- eller `cancelled`-ärende.
Väljaren erbjuder inte `failed` som mål. Diagrammet ovan styr agenter och
automatisering: en otillåten övergång som ett MCP-verktyg eller en avstämmare
försöker göra loggas och ignoreras, den tillämpas inte.
:::

Statusändringar skickar domänhändelser (`TicketStatusChanged`, `TicketCompleted`
och andra) som kan utlösa pipelines. Se
[Ställ in pipelinetriggers](/sv-SE/handbok/how-to-guider/pipelinetriggers/).

## Tilldela ett ärende

1. Öppna ärendet.
2. Ange **Tilldelad** i egenskapspanelen — du själv, en annan medlem i
   arbetsytan eller en agent.

:::caution[Att tilldela startar inget arbete]
Tilldelning registrerar ägande och inget annat. Den skapar ingen yta, ändrar
ingen status och skickar ut ingen agent — `TicketAssigned` är en ren
revisionssignal utan någon dispatcher bakom sig. Om du vill få en agent att
arbeta skickar du ett meddelande till den i en yta
(se [Chatta med en agent](/sv-SE/handbok/how-to-guider/chatta-med-agent/)).

Det enda undantaget: `TicketAssigned` är en händelsetyp som du kan koppla en
pipelinetrigger till, så en egen mall kan reagera på en tilldelning.
:::

## Lägg till etiketter

Etiketter läggs på i bulk från ärendelistan, inte från ett enskilt ärende —
egenskapspanelen har ingen etikettkontroll.

1. Håll muspekaren över en rad i ärendelistan och markera kryssrutan. Markera så
   många du behöver; en flytande list visas så snart något är markerat.
2. Öppna taggen **Etiketter** i den listen.
3. Välj en etikett. Den läggs till på varje markerat ärende som saknar den;
   befintliga etiketter raderas aldrig. **Rensa etiketter** tar bort alla.
   Väljaren listar etiketter som redan finns på ett ärende i arbetsytan. Agenter
   kan lägga till ett nytt namn via `update_ticket` eller `tickets.patch`.

## Länka ärenden

Relationer finns på ärendets **Relationer**-kort i egenskapspanelen, eller
bakom **Relatera till** i listans högerklicksmeny.

1. Öppna ärendet och leta upp **Relationer**-kortet.
2. Tryck på dess lägg till-kontroll och välj relationen:

| Relation              | Betydelse                                    |
| --------------------- | -------------------------------------------- |
| **Underärende till…** | Det här ärendets förälder är det andra       |
| **Förälder till…**   | Det andra ärendet är ett barn till det här   |
| **Blockerad av…**     | Det här ärendet blockeras av det andra       |
| **Blockerar…**        | Det här ärendet blockerar det andra          |
| **Relaterad till…**   | Symmetrisk, ingen riktning antyds            |
| **Dubblett av…**      | Det här ärendet är en dubblett av det andra  |

3. Välj målärendet.

**Duplicerad av** visas på kortet men inte i väljaren — den är inversen av
**Dubblett av** och ställs in från det andra ärendet. Varje listad relation går
att klicka på för att öppna det länkade ärendet och kan tas bort genom att hålla
muspekaren över den.

Relationer mellan förälder och underärende lagras på själva ärendet i stället
för som länkrader, så att ta bort en förälder kaskaderar till dess barn (se
nedan), medan blockerings- och relaterade länkar inte gör det.

## Lägg till medarbetare

Medarbetare är en förteckning på ärendet — vilka som är inblandade och i vilken
roll.

1. Öppna ärendet.
2. Tryck på person-plus-kontrollen på kortet **Lägg till medarbetare**.
3. Välj en agent.

De tre rollerna är **Tilldelad**, **Medarbetare** (standard) och **Granskare**.
Gränssnittets väljare listar bara agenter i arbetsytan och skriver alltid
standardrollen; människor kan visas som rader men erbjuds inte i den menyn.
MCP-verktyget `add_ticket_collaborator` tar emot en `role`.

Att lägga till en medarbetare skriver en rad och publicerar ingen domänhändelse;
det ger ingen åtkomst till någon yta. Om du vill få in en agent i ett samtal
lägger du i stället till den som deltagare från ytans huvud — se
[Använd ytor](/sv-SE/handbok/how-to-guider/ytor/).

## Ta bort ett ärende

Använd **Ta bort ärende** längst ner i egenskapspanelen, i högerklicksmenyn
eller den flytande listans borttagningsåtgärd när du har markerat flera.

:::caution[Borttagning är endast lokal]
Ett ärende som kommer från ett externt ärendehanteringssystem tas inte bort där —
ingen leverantör stöder det — så det kan dyka upp igen vid nästa synkning.
Borttagningen kaskaderar också: ärendets medarbetare och eventuella barnärenden
följer med.
:::
