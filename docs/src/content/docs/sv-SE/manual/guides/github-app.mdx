Den här guiden visar hur du ger din server en egen GitHub-app. Det tar ungefär
två minuter, bara serverägaren gör det, och det behöver bara göras en gång per
server.

:::note[Du kanske inte behöver det]
När Control Center Connect är påslaget loggar personer in på GitHub via Control
Centers delade app, eller via appen som din organisations Connect använder.
Registrera en egen när du har valt **Använd mina egna appar**: serverns egen app används bara då. Se
[Control Center Connect](/sv-SE/handbok/referens/connect/).
:::

För att logga in på ditt eget konto efteråt, se
[Konfigurera GitHub-integration](/sv-SE/handbok/how-to-guider/github-integration/).

## Vad appen gör

En registrering löser två olika uppgifter:

| Uppgift                     | Vad som svarar                                  | Varför det spelar roll                                                                 |
| --------------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------- |
| **En person loggar in**     | Appens klient-ID och klienthemlighet            | Alla får en egen GitHub-inloggningsuppgift, på servern, på varje enhet                 |
| **Servern agerar**          | Appens ID och privata nyckel                    | Agenter, pipelines, pollare och botsvar får token för ett repo i taget                 |

Den andra uppgiften lånar aldrig en persons inloggningsuppgift i sin helhet.
Varje token som servern utfärdar täcker ett repo och är begränsad till vad en
ansvarig medlem kan göra där. Att läsa ett länkat repo kräver bara appen; allt
som skriver kräver en medlem som kan pusha. Automatisering godkänner aldrig en
pull request.

Serverns egen app gäller bara under **Använd mina egna appar**. Med Control Center Connect eller en egen Connect sköter Connect alla spår, GitHub inräknat; serverns app förblir sparad men oanvänd tills du byter tillbaka. En arbetsyta med egna appar ([Ge en arbetsyta en egen app](#ge-en-arbetsyta-en-egen-app)) använder i stället sin egen app, oavsett serverns läge. En app där några av fälten saknas är ett fel, inte en reservväg: GitHub-inloggningar avvisas tills varje fält är ifyllt.

## Förutsättningar

- Du är **serverägare**. Kortet **Leverantörsappar** är osynligt för alla andra
- Ett GitHub-konto. Appen skapas under det
- En serveradress som din webbläsare kan nå. Serverns offentliga URL (eller
  loopback, för en skrivbordsapps egen server) är dit GitHub skickar tillbaka dig

## Skapa den med ett klick

1. Gå till **Inställningar → Server → Enkel inloggning** och rulla till kortet
   **Leverantörsappar**
2. I blocket **GitHub** kan du ange den GitHub-organisation som ska äga appen i
   **Organisation (valfritt)**. Lämna fältet tomt för att skapa appen under ditt
   eget konto; för att skapa den under en organisation krävs en ägare av den
   organisationen
3. Klicka på **Skapa min GitHub-app**
4. Din webbläsare öppnar GitHub med appen redan ifylld. Klicka på
   **Create GitHub App**
5. GitHub skickar tillbaka dig till servern, som sparar app-ID:t, den privata
   nyckeln, klient-ID:t och klienthemligheten och sedan öppnar appens
   installationssida

Inget kopieras för hand, och konverteringskoden går direkt från GitHub till din
server. Länken fungerar en gång och går ut efter tio minuter; om den går ut
klickar du på **Skapa min GitHub-app** igen.

Appen heter `Control Center <code>` och ber om exakt det som Control Center
använder:

| Behörighet                                 | Åtkomst          |
| ------------------------------------------ | ---------------- |
| Metadata                                   | Läsa             |
| Contents                                   | Läsa och skriva  |
| Pull requests                              | Läsa och skriva  |
| Issues                                     | Läsa och skriva  |
| Checks, Actions, Commit statuses           | Läsa             |
| Organization members                       | Läsa             |

Webhooks är avstängda: servern pollar. För att senare flytta en app som du skapade
under ditt eget konto till en organisation använder du **Transfer ownership** i
appens avancerade inställningar på GitHub.

Kontrollpunkt: GitHub-blocket visar ”Servern kan agera som sig själv, och
personer kan logga in”.

## Installera den där dina repos finns

En app som är registrerad men inte installerad kan logga in personer och läser
ingenting.

1. Välj kontot eller organisationen som äger dina repos på installationssidan som
   GitHub öppnade
2. Välj **All repositories**, eller välj de repos som den här servern ska se

För att installera den på ett annat konto senare går en administratör i
arbetsytan till **Inställningar → Arbetsyta → Integrationer**, letar upp
**Installationer av GitHub-appen** på kortet **GitHub-app** under Kodvärd och klickar på
**Installera GitHub-appen**. Listan visar varje konto som appen är installerad på
och markerar en avstängd installation.

## Dela en organisations installation

En organisation installerar GitHub-appen en gång. Därefter kan alla i den som
loggar in på GitHub på en Control Center-server använda installationen, oavsett
vilken server det är: din, en kollegas eller deras egen. Det finns inget att
auktorisera per server.

Varje token en server får är den inloggade personens egen, begränsad till ett
repo och till personens roll där, så den når aldrig längre än personen kan på
GitHub. GitHubs granskningslogg visar den personen, som agerar via appen.

För att stoppa Control Center från att nå en organisation tar en ägare av
organisationen bort installationen eller begränsar dess repos på GitHub. Att ta
bort en person från organisationen stoppar också deras åtkomst.

## Registrera den för hand i stället

Kortet **Leverantörsappar** tar också emot värdena direkt, för en app som du har
registrerat själv:

| Grupp                        | Fält                                                                                            |
| ---------------------------- | ----------------------------------------------------------------------------------------------- |
| **Agerar som servern**       | **App-ID** och **Privat nyckel** (hela `.pem`-filen, inklusive raderna `BEGIN` och `END`)        |
| **Logga in personer**        | **Klient-ID** och **Klienthemlighet**. **Callback-URL:er** visar URL:en som ska registreras, ordagrant |
| **Pull request-samtal**      | **Bot-inloggning**, som slås upp när du testar anslutningen                                     |

Registrera callback-URL:en `<server origin>/oauth/github/callback` exakt som
kortet visar den, låt **Expire user authorization tokens** vara påslaget och
bevilja behörigheterna i tabellen ovan. Klicka på **Test**: den frågar GitHub
vilka konton appen är installerad på, så att ”sparad” och ”fungerar” inte
förväxlas.

## Konfigurera den från serverns `.env`

För en headless- eller skriptad installation fyller servern varje fält från sin
`.env`-fil första gången det saknar ett sparat värde:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

Lägg nyckeln på **en rad**: ett `.env`-värde är en rad, och `\n` inom dubbla
citattecken avkodas till en radbrytning. Servern vägrar starta när
`GITHUB_APP_PRIVATE_KEY` eller `GITHUB_CLIENT_SECRET` är exporterad i dess
processmiljö, där varje underprocess skulle kunna läsa den; förvara dem i
`.env`-filen (i Docker monterar du den på `/app/bin/.env`). Ifyllningen sker **en
gång per fält**, så ändringar i Inställningar skrivs inte över vid nästa
omstart.

## Ge en arbetsyta en egen app

En arbetsyta kan köra på en egen app i stället för serverns:

1. En administratör i arbetsytan går till **Inställningar → Arbetsyta → Integrationer**
2. På kortet **Control Center Connect** väljer de **Använd mina egna appar** och klickar på **Tillämpa**. Alla i arbetsytan loggar in igen via arbetsytans appar
3. Kortet **GitHub-app** under Kodvärd innehåller nu appens fält: **App-ID** och **Privat nyckel** under **Agerar för den här arbetsytan**, **Klient-ID** och **Klienthemlighet** under **Logga in personer**. Klicka på **Test** när de är ifyllda

Medlemmarna loggar sedan in på den appen för den här arbetsytan. En arbetsyta med egna appar faller aldrig tillbaka på serverns app eller på Connect: tills fälten är kompletta avvisas dess GitHub-arbete. Samma val gäller Google Calendar, Linear och GIF-sökning, var och en med sina egna fält bredvid sin leverantör på samma sida. Se [Ge en arbetsyta en egen Linear-applikation](/sv-SE/handbok/how-to-guider/linear-integration/#ge-en-arbetsyta-en-egen-linear-applikation) och [Ge en arbetsyta en egen Google-klient](/sv-SE/handbok/how-to-guider/anslut-kalender/#ge-en-arbetsyta-en-egen-google-klient). De övriga valen på kortet, och vad vart och ett gör, finns i [Arbetsytans eget val](/sv-SE/handbok/referens/connect/#arbetsytans-eget-val).

## Felsökning

### Skapa min GitHub-app säger att servern inte har någon adress

Servern har ingen offentlig URL som en webbläsare kan återvända till. Ange
`CC_SERVER_PUBLIC_URL` (eller `--public-url`) och försök igen.

### GitHub säger att länken har gått ut

Engångssidan har redan använts, eller så har tio minuter gått. Börja om från
Inställningar.

### Test säger att inloggningsuppgifterna fungerar men att appen inte är installerad någonstans

Registrering och installation är två separata steg. Öppna appens
installationssida, eller använd **Installera GitHub-appen** under Arbetsyta →
Integrationer.

### Test säger att den privata nyckeln inte kunde läsas

Klistra in hela `.pem`-filen, inklusive raderna `-----BEGIN` och `-----END`. En
`ed25519`- eller EC-nyckel kan inte användas — GitHub Apps signerar med RSA.

### En medlem loggade in men ser inga arkiv

Appen är inte installerad på kontot som äger dem, eller så omfattar
installationen andra arkiv. En inloggning ger bara åtkomst till det appen får se.

### Agenter säger att GitHub-appens installation är avstängd

Någon har stängt av installationen på GitHub. Häv avstängningen under kontots
**Settings → Applications → Installed GitHub Apps**.
