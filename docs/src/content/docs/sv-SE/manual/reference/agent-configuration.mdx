Den här referensen listar alla fält på agententiteten, plus de uppräkningar och flaggor den använder. En steg-för-steg-genomgång av att skapa eller redigera en agent i appen finns i [Skapa och konfigurera en agent](/sv-SE/handbok/how-to-guider/skapa-agent/).

## Fält på agententiteten

| Fält | Typ | Obligatoriskt | Beskrivning |
| ---- | --- | ------------- | ----------- |
| `id` | `String` | Ja | Unikt agent-id |
| `name` | `String` | Ja | Kort identifierare för @-omnämnanden |
| `title` | `String` | Ja | Människoläsbar rolltitel |
| `agentMdPath` | `String` | Ja | Absolut sökväg till agentens `.md`-definitionsfil |
| `workspaceId` | `String` | Ja | Ägande arbetsyta (icke-null) |
| `reportsTo` | `String?` | Nej | Förälderagentens id |
| `skills` | `AgentSkills` | Ja | Uppsättning skillidentifierare |
| `persona` | `String?` | Nej | Fritext med beteendeinstruktioner |
| `systemPrompt` | `String?` | Nej | Åsidosätt den förvalda systemprompten |
| `adapterId` | `String?` | Nej | Id för inferensadaptern |
| `modelId` | `String?` | Nej | Modell-id inom adaptern |
| `strictMode` | `bool` | Nej | Standard `false`. Skrivs till raden och till agentens `AGENTS.md` |
| `effort` | `String?` | Nej | Id för resonemangsnivå (t.ex. `'low'`, `'xhigh'`), hämtat från den valda modellens `thinkingLevels` |
| `contextSize` | `int?` | Nej | Maximal storlek på kontextfönstret |
| `role` | `AgentRole?` | Nej | Agentens roll |
| `capabilities` | `AgentCapabilities?` | Nej | Standard för förmågor per agent; när den är null gäller användarnivåns standard vid dispatch och ett samtal kan fortfarande skriva över |
| `monthlyBudgetCents` | `int` | Nej | Månatligt utgiftstak i cent (standard `0`, obegränsat) |
| `silenceTimeoutMinutes` | `int?` | Nej | Överstyrning av tystnadsövervakningen i minuter; måste vara null eller mellan 1 och 240 (kontrolleras i konstruktorn) |
| `maxConcurrentTasks` | `int` | Nej | Standard `1`. Kapacitetssiffran som närvaromodellen rapporterar (antalet körande och köade jämförs mot den) |
| `visibility` | `AgentVisibility` | Nej | Standard `workspace` |
| `lifecycleStatus` | `AgentLifecycleStatus` | Nej | Styrningsstatus (standard `active`). Skrivs av budgetens hårda stopp och visas i organisationsschemat och närvarolistan. Dispatch tar fortfarande emot arbete från en agent med statusen `paused` |
| `budgetPolicyId` | `String?` | Nej | Id för delad budgetpolicy; när den är null gäller `monthlyBudgetCents` direkt |
| `runtimeProfileId` | `String?` | Nej | Id för anpassad runtime-profil |
| `createdAt` | `DateTime` | Ja | Tidsstämpel för skapandet |

Både `name` och `title` måste vara icke-tomma (kontrolleras i konstruktorn). Standardvärdet `0` för
`monthlyBudgetCents` betyder obegränsat. Sätt ett tak med `agents.upsert`.

## AgentVisibility-uppräkningen

| Värde | Beskrivning |
| ----- | ----------- |
| `workspace` | Standardvärdet; okända och null-lagrade värden tolkas som det |
| `private` | Privat för användaren som skapade den |

## AgentLifecycleStatus-uppräkningen

| Värde | Beskrivning |
| ----- | ----------- |
| `active` | Standardvärdet. `isDispatchable` är sant endast för det här värdet |
| `paused` | Sätts av budgetens hårda stopp. Visas i närvarolistan; dispatch tar fortfarande emot arbete |
| `archived` | Pensionerad och dold från aktiva personallistor |

## AgentCapabilities-flaggor

Löses upp per dispatch: agentens standard, med fallback till användarnivåns standard när den är null, och med en överstyrning per samtal ovanpå. Framtvingas genom frånvaro — mäklaren för inloggningsuppgifter skapar eller injicerar helt enkelt inte det som en avstängd förmåga omfattar.

| Flagga | Typ | Standard | Beskrivning |
| ------ | --- | -------- | ----------- |
| `canPushToRepo` | `bool` | `false` | Pusha commits till fjärren; styr injicering av GitHub-token tillsammans med `canCallGitHubApi` |
| `canCallGitHubApi` | `bool` | `false` | Anropa api.github.com; styr injicering av `GH_TOKEN` och GitHubs utgående domäner |
| `canCallTicketing` | `bool` | `false` | Anropa ärendehanteringsleverantörens API; styr injicering av leverantörens API-nyckel och dess utgående domäner |
| `canAccessNetwork` | `bool` | `true` | Godtycklig utgående trafik. Styr även harnessens `web_fetch`- och `web_search`-verktyg |

`AgentCapabilities.safeDefault` är konstruktorns fyra standardvärden. `legacyDefault` (alla fyra sanna) används bara av migreringen som efterfyllde samtal som skapades innan förmågor fanns. En felaktig eller tom lagrad blob tolkas som `safeDefault`; den äldre nyckeln `canCallLinear` läses som `canCallTicketing`.

## AgentSkills

En oföränderlig, skiftlägesokänslig uppsättning skillidentifierare. Vid dispatch synkas dessa sluggar som skillänkar i agentens överlägg; harnessen läser sedan automatiskt in de länkade skillsens frontmatter i prompten.

```
{'flutter', 'dart', 'rest-api'}
```

## AgentLiveState (härledd)

Lagras inte. Sju värden. Deklarationsordningen är prioritetsordningen (`sortPriority`, låst av ett test), som är den ordning personallistan sorterar efter:

| Tillstånd | `sortPriority` | Villkor |
| --------- | -------------- | ------- |
| `running` | 0 | Någon körningslogg har statusen `running` |
| `blocked` | 1 | Den senaste körningens livsstatus är `blocked`, `stalled` eller `looping` |
| `failed` | 2 | Den senaste körningens status är `error`, eller dess livsstatus är `failed` eller `dead` |
| `queued` | 3 | En körning är dispatchad men körs inte — parkerad bakom en annan körning av samma agent, eller skriven men ännu inte startad |
| `succeeded` | 4 | Körningen slutfördes framgångsrikt |
| `idle` | 5 | Agenten har kört tidigare och har inget i luften |
| `neverRun` | 6 | Inga körningsloggar finns |

`queued` och `succeeded` finns **endast per körning**. `deriveAgentLiveState`, som beräknar personallistans tillstånd för en agent, producerar aldrig något av dem — den returnerar `neverRun`, `running`, `failed`, `blocked` eller `idle`.
