These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/sv-SE/handbok/how-to-guider/); when you want to look
something up, go to the [reference](/sv-SE/handbok/referens/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/sv-SE/handbok/koncept/arbetsytor/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/sv-SE/handbok/koncept/agentmodell/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/sv-SE/handbok/koncept/livscykel-agentdispatch/) — what happens between your message and the agent's first token
- [Modes](/sv-SE/handbok/koncept/lagen/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/sv-SE/handbok/koncept/verktygskontext/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/sv-SE/handbok/koncept/kodintelligens/) — the code graph, language server, structural search and debugger
- [Conversation history](/sv-SE/handbok/koncept/samtalshistorik/) — persistence, compaction and forking a transcript
