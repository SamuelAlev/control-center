These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/it-IT/manuale/guide/); when you want to look
something up, go to the [reference](/it-IT/manuale/riferimento/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/it-IT/manuale/concetti/spazi-di-lavoro/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/it-IT/manuale/concetti/modello-agenti/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/it-IT/manuale/concetti/ciclo-di-vita-invio/) — what happens between your message and the agent's first token
- [Modes](/it-IT/manuale/concetti/modalita/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/it-IT/manuale/concetti/contesto-strumenti/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/it-IT/manuale/concetti/intelligence-del-codice/) — the code graph, language server, structural search and debugger
- [Conversation history](/it-IT/manuale/concetti/cronologia-conversazioni/) — persistence, compaction and forking a transcript

- [Rigs and enclosures](/it-IT/manuale/concetti/rig/) — why agents get disposable VMs instead of your machine, and what the boundary actually is
