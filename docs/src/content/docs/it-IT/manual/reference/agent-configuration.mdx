Questa pagina di riferimento elenca tutti i campi dell'entità agente, oltre alle enumerazioni e ai flag che usa. Per una procedura dettagliata di creazione o modifica di un agente nell'app, vedi [Crea e configura un agente](/it-IT/manuale/guide/crea-agente/).

## Campi dell'entità agente

| Campo                   | Tipo                   | Obbligatorio | Descrizione                                                                                                                                                                                                              |
| ----------------------- | ---------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `id`                    | `String`               | Sì           | Identificatore univoco dell'agente                                                                                                                                                                                       |
| `name`                  | `String`               | Sì           | Identificatore breve per le @-menzioni                                                                                                                                                                                   |
| `title`                 | `String`               | Sì           | Titolo del ruolo leggibile da una persona                                                                                                                                                                                |
| `agentMdPath`           | `String`               | Sì           | Percorso assoluto del file di definizione `.md` dell'agente                                                                                                                                                              |
| `workspaceId`           | `String`               | Sì           | Spazio di lavoro proprietario (mai null)                                                                                                                                                                                 |
| `reportsTo`             | `String?`              | No           | Id dell'agente padre                                                                                                                                                                                                     |
| `skills`                | `AgentSkills`          | Sì           | Insieme di identificatori di skill                                                                                                                                                                                       |
| `persona`               | `String?`              | No           | Istruzioni comportamentali in testo libero                                                                                                                                                                               |
| `systemPrompt`          | `String?`              | No           | Sostituisce il prompt di sistema predefinito                                                                                                                                                                             |
| `adapterId`             | `String?`              | No           | Id dell'adattatore di inferenza                                                                                                                                                                                          |
| `modelId`               | `String?`              | No           | Id del modello all'interno dell'adattatore                                                                                                                                                                               |
| `strictMode`            | `bool`                 | No           | Predefinito `false`. Scritto nella riga e nell'`AGENTS.md` dell'agente                                                                                                                                                   |
| `effort`                | `String?`              | No           | Id del livello di ragionamento (ad es. `'low'`, `'xhigh'`), tratto dai `thinkingLevels` del modello selezionato                                                                                                          |
| `contextSize`           | `int?`                 | No           | Dimensione massima della finestra di contesto                                                                                                                                                                            |
| `role`                  | `AgentRole?`           | No           | Ruolo dell'agente                                                                                                                                                                                                        |
| `monthlyBudgetMicros`    | `int`                  | No           | Limite di spesa mensile in microdollari (predefinito `0`, illimitato)                                                                                                                                                       |
| `silenceTimeoutMinutes` | `int?`                 | No           | Override del timeout di silenzio in minuti; deve essere null o compreso tra 1 e 240 (verificato dal costruttore)                                                                                                         |
| `maxConcurrentTasks`    | `int`                  | No           | Predefinito `1`. Cifra di capacità che il modello delle presenze riporta (i conteggi delle esecuzioni attive e in coda vengono confrontati con essa)                                                                     |
| `visibility`            | `AgentVisibility`      | No           | Predefinito `workspace`                                                                                                                                                                                                  |
| `lifecycleStatus`       | `AgentLifecycleStatus` | No           | Stato di governance (predefinito `active`). Scritto dall'arresto forzato del budget e mostrato nell'organigramma e nell'elenco delle presenze. L'invio accetta comunque lavoro da un agente `paused`                      |
| `budgetPolicyId`        | `String?`              | No           | Id della policy di budget condivisa; quando è null si applica direttamente `monthlyBudgetMicros`                                                                                                                          |
| `runtimeProfileId`      | `String?`              | No           | Id del profilo di runtime personalizzato                                                                                                                                                                                 |
| `createdAt`             | `DateTime`             | Sì           | Data e ora di creazione                                                                                                                                                                                                  |

`name` e `title` devono essere entrambi non vuoti (verificato dal costruttore). Un
`monthlyBudgetMicros` predefinito di `0` significa illimitato. Imposta un tetto di spesa con
`agents.upsert`.

## Permessi

Un agente non porta flag di permesso. Eseguire push, aprire e pubblicare pull request, scrivere su un tracker e l'uscita di rete sono classi di azione (`gitPush`, `prCreate`, `prPublish`, `vendorSyncWrite`, `networkEgress`) che i [guardrail](/it-IT/manuale/concetti/guardrail/) risolvono nell'ambito dello spazio di lavoro, dell'agente o dello spazio. Il token GitHub di un'esecuzione ha sempre ambito di lettura; i push passano dal gateway delle esecuzioni degli agenti, che interroga la regola `gitPush` prima di inoltrarli.

## AgentSkills

Un insieme immutabile e senza distinzione tra maiuscole e minuscole di identificatori di skill. Al momento dell'invio quegli slug vengono sincronizzati come collegamenti di skill nell'overlay dell'agente; l'harness carica poi automaticamente il frontmatter delle skill collegate nel prompt.

```
{'flutter', 'dart', 'rest-api'}
```

## Hook di shell

Gli hook di shell permettono al proprietario del server di eseguire i propri script attorno a un'esecuzione dell'agente: una volta all'avvio della sessione, prima di ogni chiamata a uno strumento e dopo ogni chiamata, quando l'agente terminerebbe il suo turno, e prima di una compattazione. Un hook è codice arbitrario, quindi gli hook sono configurazione dell'host. Solo il proprietario del server li configura, a mano, sulla macchina del server. Non esiste un'impostazione nell'app né un'operazione che li scriva.

Per un agente, gli hook vivono nella sua cartella dentro la directory dei dati del server:

```text
<data dir>/_agent_hooks/<workspace id>/<agent slug>/hooks.json
```

`<agent slug>` è il nome della cartella dell'agente nello spazio di lavoro (`agents/<slug>/`). Quella cartella si trova fuori dallo spazio di archiviazione di ogni spazio di lavoro, e ogni sandbox nasconde la directory dei dati, quindi nessun membro, esecuzione o terminale può scriverla.

`hooks.json` associa una qualunque di cinque chiavi a uno script, tramite un percorso relativo alla cartella degli hook:

| Chiave         | Quando viene eseguito        | Cosa significa il suo codice di uscita                         |
| -------------- | ---------------------------- | -------------------------------------------------------------- |
| `sessionStart` | Una volta, all'avvio dell'esecuzione | Niente; l'hook si limita a osservare                    |
| `preTool`      | Prima di ogni chiamata a uno strumento | `0` consente la chiamata; qualunque altro valore la nega |
| `postTool`     | Dopo ogni chiamata a uno strumento | Niente; l'hook si limita a osservare                      |
| `stop` | Quando l'agente terminerebbe il suo turno | `2` con testo su stdout mantiene l'esecuzione in corso con quel testo; qualunque altro esito lascia terminare il turno |
| `preCompact` | Prima di una compattazione | `0`: il suo stdout viene aggiunto a ciò che il riassunto deve conservare |

- Ogni script viene avviato come eseguibile autonomo, senza shell e senza argomenti, quindi deve essere eseguibile e iniziare con una riga shebang. Riceve l'evento come JSON su stdin: il nome dell'evento e, per gli hook sugli strumenti, il nome dello strumento con i suoi argomenti (`preTool`) o il suo risultato (`postTool`).
- Un hook viene eseguito come uno dei processi degli strumenti dell'esecuzione, nella cartella dell'agente per l'esecuzione. Quando il server isola gli agenti in sandbox, viene eseguito dentro la sandbox dell'esecuzione. Riceve un ambiente minimo e nessuna delle credenziali dell'esecuzione: nessun token di forge o di provider e nessun accesso al gateway.
- Ogni hook ha 30 secondi. L'output di `sessionStart`, `preTool` e `postTool` viene letto e scartato.
- `preTool` fallisce in modo chiuso. Un'uscita diversa da zero, un timeout o uno script che non riesce ad avviarsi nega la chiamata allo strumento.
- Un percorso assoluto, mancante, o che esce dalla cartella degli hook (con i link risolti) viene rifiutato, e il log dell'esecuzione dice quale hook è stato rifiutato e perché. Un hook `preTool` rifiutato o illeggibile nega ogni chiamata a uno strumento finché non viene corretto.
- Un blocco `hooks` in `.agents/harness.json`, sia in un repository sia nella cartella propria dell'agente, viene ignorato. Un repository è spesso codice di qualcun altro, e la cartella dell'agente può essere scritta dai membri e dalle esecuzioni. Il log dell'esecuzione dice che il blocco è stato ignorato e da dove vengono letti invece gli hook.

### Gli hook stop e preCompact

- `stop` riceve `event: "stop"`, l'ultimo messaggio dell'agente (`last_message`), `stop_hook_active` (true quando questo stop segue una continuazione causata dall'hook) e `block_count` (quante volte ha mantenuto l'esecuzione in corso finora, a partire da 0). Per mantenere l'esecuzione in corso, esce con `2` e stampa ciò che l'agente deve fare dopo. Il testo, troncato a 2.000 caratteri, arriva all'agente come messaggio di sistema.
- Un hook `stop` mantiene un'esecuzione in corso al massimo 3 volte per esecuzione. Dopo, non viene più eseguito e il turno termina.
- `stop` fallisce in modo aperto. Un timeout, uno script che non riesce ad avviarsi, un codice di uscita diverso da `2`, oppure un codice `2` senza nulla su stdout lasciano terminare il turno, così un hook guasto non può tenere aperta un'esecuzione.
- `preCompact` riceve `event: "pre_compact"`. Il suo stdout, troncato a 1.000 caratteri, viene aggiunto al focus della compattazione. Uno script che fallisce non aggiunge nulla.

Gli hook di shell si applicano all'harness integrato. Su Claude Code, anche gli hook `stop` e `preCompact` vengono eseguiti: gli hook `Stop` e `PreCompact` di Claude Code chiedono al server, e il server esegue gli script del proprietario allo stesso modo. Le altre tre chiavi si applicano solo all'harness integrato. Un hook `preTool` o `postTool` configurato fa sì che l'esecuzione chiami i suoi strumenti uno alla volta.

## AgentLiveState (derivato)

Non memorizzato. Sette valori. L'ordine di dichiarazione è l'ordine di priorità (`sortPriority`, fissato da un test), che è l'ordine con cui ordina l'elenco:

| Stato       | `sortPriority` | Condizione                                                                                                                    |
| ----------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `running`   | 0              | Un qualsiasi log di esecuzione ha stato `running`                                                                              |
| `blocked`   | 1              | La vitalità dell'ultima esecuzione è `blocked`, `stalled` o `looping`                                                          |
| `failed`    | 2              | Lo stato dell'ultima esecuzione è `error`, oppure la sua vitalità è `failed` o `dead`                                           |
| `queued`    | 3              | Un'esecuzione è stata inviata ma non è in corso — in attesa dietro un'altra esecuzione dello stesso agente, oppure scritta ma non ancora avviata |
| `succeeded` | 4              | L'esecuzione si è conclusa correttamente                                                                                       |
| `idle`      | 5              | L'agente ha già eseguito e non ha nulla in volo                                                                                |
| `neverRun`  | 6              | Non esiste alcun log di esecuzione                                                                                             |

`queued` e `succeeded` sono **solo per singola esecuzione**. `deriveAgentLiveState`, che calcola lo stato dell'elenco per un agente, non ne produce mai nessuno dei due — restituisce `neverRun`, `running`, `failed`, `blocked` o `idle`.
