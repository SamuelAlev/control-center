Questa guida mostra come dare al tuo server una propria GitHub App. Richiede
circa due minuti, la esegue solo il proprietario del server e va fatta una sola
volta per server.

:::note[Potresti non averne bisogno]
Con Control Center Connect attivo, le persone accedono a GitHub tramite l'App
condivisa di Control Center, o tramite l'App usata dal Connect della tua
organizzazione. Registra la tua quando hai scelto **Usa le mie app**: l'App del server vale solo in quel caso. Vedi [Control Center Connect](/it-IT/manuale/riferimento/connect/).
:::

Per accedere in seguito con il tuo account, vedi
[Configura l'integrazione GitHub](/it-IT/manuale/guide/integrazione-github/).

## Cosa fa l'app

Una sola registrazione risponde a due compiti diversi:

| Compito                 | Cosa risponde                                  | Perché conta                                                                                          |
| ----------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| **Una persona accede**  | L'id client e il segreto client dell'app       | Ognuno ottiene una propria credenziale GitHub, sul server, su ogni dispositivo                         |
| **Il server agisce**    | L'id dell'app e la sua chiave privata          | Agenti, pipeline, processi di polling e risposte del bot ricevono token per un repository alla volta  |

Il secondo compito non prende mai in prestito per intero la credenziale di una
persona. Ogni token emesso dal server copre un solo repository ed è limitato a
ciò che un membro responsabile può fare lì. Leggere un repository collegato
richiede solo l'app; qualsiasi scrittura richiede un membro che possa eseguire
push. L'automazione non approva mai una pull request.

L'App del server vale solo con **Usa le mie app**. Con Connect di Control Center o un Connect
personalizzato, Connect gestisce GitHub, e l'App del server resta salvata ma inutilizzata finché non
torni indietro. Uno spazio di lavoro che usa le proprie app ([Dai a uno spazio di lavoro la sua app](#dai-a-uno-spazio-di-lavoro-la-sua-app))
usa invece la propria App, qualunque sia la modalità del server. Un'app con alcuni campi mancanti è un errore, non un ripiego: gli accessi a GitHub vengono
rifiutati finché ogni campo non è impostato.

## Prerequisiti

- Sei il **proprietario del server**. La scheda **App del fornitore** è
  invisibile a tutti gli altri
- Un account GitHub. L'app viene creata sotto di esso
- Un indirizzo del server raggiungibile dal tuo browser. L'URL pubblico del
  server (o il loopback, per il server di un desktop) è dove GitHub ti rimanda

## Creala con un clic

1. Vai in **Impostazioni → Server → Accesso single sign-on** e scorri fino alla
   scheda **App del fornitore**
2. Nel blocco **GitHub**, se vuoi, scrivi in **Organizzazione (facoltativo)**
   l'organizzazione GitHub che deve possedere l'app. Lascia il campo vuoto per
   creare l'app con il tuo account; per crearla in un'organizzazione serve un
   proprietario di quell'organizzazione
3. Fai clic su **Crea la mia app GitHub**
4. Il browser apre GitHub con l'app già compilata. Fai clic su
   **Create GitHub App**
5. GitHub ti rimanda al server, che memorizza l'id dell'app, la chiave privata,
   l'id client e il segreto client, e poi apre la pagina di installazione
   dell'app

Nulla viene copiato a mano, e il codice di conversione va direttamente da GitHub
al tuo server. Il link funziona una sola volta e scade dopo dieci minuti; se è
scaduto, fai di nuovo clic su **Crea la mia app GitHub**.

L'app si chiama `Control Center <code>` e chiede esattamente ciò che Control
Center usa:

| Permesso                                   | Accesso              |
| ------------------------------------------ | -------------------- |
| Metadata                                   | Lettura              |
| Contents                                   | Lettura e scrittura  |
| Pull requests                              | Lettura e scrittura  |
| Issues                                     | Lettura e scrittura  |
| Checks, Actions, Commit statuses           | Lettura              |
| Organization members                       | Lettura              |

I webhook sono disattivati: il server esegue il polling. Per spostare in seguito
in un'organizzazione un'app creata con il tuo account, usa **Transfer
ownership** nelle impostazioni avanzate dell'app su GitHub.

Punto di controllo: il blocco GitHub indica «Il server può agire per conto
proprio e le persone possono accedere».

## Installala dove si trovano i tuoi repository

Un'app registrata ma non installata può far accedere le persone, ma non può
leggere nulla.

1. Nella pagina di installazione aperta da GitHub, scegli l'account o
   l'organizzazione proprietaria dei tuoi repository
2. Scegli **All repositories**, oppure seleziona quelli che questo server deve
   vedere

Per installarla in seguito su un altro account, un amministratore dello spazio di
lavoro va in **Impostazioni → Spazio di lavoro → Integrazioni**, trova
**Installazioni dell'app GitHub** nella scheda **App GitHub** sotto **Hosting del codice** e fa clic su
**Installa l'app GitHub**. L'elenco mostra ogni account su cui l'app è
installata e segnala un'installazione sospesa.

## Condividi l'installazione di un'organizzazione

Un'organizzazione installa la GitHub App una sola volta. Dopodiché chiunque al suo interno acceda a GitHub su un server di Control Center può usare l'installazione, qualunque sia quel server: il tuo, quello di un collega o uno proprio. Non c'è nulla da autorizzare per server.

Ogni token che un server ottiene è della persona che ha effettuato l'accesso, limitato a un solo repository e al suo ruolo su di esso, quindi non va mai oltre quanto potrebbe fare su GitHub. Il log di audit di GitHub mostra quella persona, che agisce tramite l'app.

Per impedire a Control Center di raggiungere un'organizzazione, un proprietario dell'organizzazione rimuove l'installazione o ne restringe i repository su GitHub. Rimuovere una persona dall'organizzazione blocca anche il suo accesso.

## Oppure registrala a mano

La scheda **App del fornitore** accetta anche direttamente i valori, per un'app
che hai registrato tu:

| Gruppo                                 | Campi                                                                                              |
| -------------------------------------- | -------------------------------------------------------------------------------------------------- |
| **Agire come server**                  | **Id app**, e **Chiave privata** (l'intero `.pem`, righe `BEGIN` ed `END` comprese)                |
| **Accesso delle persone**              | **Id client** e **Segreto client**. **URL di callback** mostra l'URL da registrare, alla lettera    |
| **Conversazioni sulle pull request**   | **Login del bot**, risolto quando testi la connessione                                             |

Registra l'URL di callback `<server origin>/oauth/github/callback` esattamente
come lo mostra la scheda, lascia attivo **Expire user authorization tokens** e
concedi i permessi della tabella qui sopra. Fai clic su **Test**: chiede a
GitHub su quali account è installata l'app, così «salvato» e «funziona» non si
confondono.

## Configurala dal `.env` del server

Per un'installazione headless o tramite script, il server inizializza ogni campo
dal proprio file `.env` la prima volta che non ha alcun valore memorizzato:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

Metti la chiave su **una sola riga**: un valore di `.env` sta su una riga, e
`\n` tra virgolette doppie viene decodificato come a capo. Il server si rifiuta
di avviarsi quando `GITHUB_APP_PRIVATE_KEY` o `GITHUB_CLIENT_SECRET` sono
esportati nell'ambiente del suo processo, dove ogni processo figlio potrebbe
leggerli; tienili nel file `.env` (in Docker, montalo su `/app/bin/.env`).
L'inizializzazione avviene **una sola volta per campo**, quindi una modifica in
Impostazioni non viene annullata al riavvio successivo.

## Dai a uno spazio di lavoro la sua app

Uno spazio di lavoro può funzionare con un'app propria invece di quella del server:

1. Un amministratore dello spazio di lavoro va in **Impostazioni → Spazio di lavoro → Integrazioni**
2. Nella scheda **Control Center Connect** sceglie **Usa le mie app** e fa clic su **Applica**. Tutti nello spazio di lavoro accedono di nuovo tramite le app dello spazio di lavoro
3. La scheda **App GitHub** sotto Hosting del codice ora contiene i campi dell'app: **Id app** e **Chiave privata** sotto **Agisce per questo spazio di lavoro**, **Id client** e **Segreto client** sotto **Accesso delle persone**. Fai clic su **Test** quando sono impostati

I membri accedono allora a quell'app per questo spazio di lavoro. Uno spazio di lavoro con le proprie app non
ripiega mai sull'app del server né su Connect: finché i suoi campi non sono completi, il suo lavoro su GitHub
viene rifiutato. Questo vale comunque sia il modo in cui il server fa accedere le persone, Connect incluso.
La stessa scelta copre Google Calendar, Linear e la ricerca GIF, ciascuno con i propri campi accanto al proprio
provider nella stessa pagina. Vedi [Assegna a uno spazio di lavoro un'app propria di Linear](/it-IT/manuale/guide/integrazione-linear/#assegna-a-uno-spazio-di-lavoro-unapp-propria-di-linear)
e [Assegna allo spazio di lavoro un client Google proprio](/it-IT/manuale/guide/collega-calendario/#assegna-allo-spazio-di-lavoro-un-client-google-proprio).
Le altre scelte di quella scheda, e cosa fa ciascuna, sono in [Scelta per spazio di lavoro](/it-IT/manuale/riferimento/connect/#scelta-per-spazio-di-lavoro).

## Risoluzione dei problemi

### Crea la mia app GitHub dice che il server non ha un indirizzo

Il server non ha alcun URL pubblico a cui un browser possa tornare. Imposta
`CC_SERVER_PUBLIC_URL` (o `--public-url`) e riprova.

### GitHub dice che il link è scaduto

La pagina monouso è già stata usata, oppure sono passati dieci minuti.
Ricomincia da Impostazioni.

### Il test dice che le credenziali funzionano ma l'app non è installata da nessuna parte

Registrazione e installazione sono passaggi separati. Apri la pagina di
installazione dell'app, oppure usa **Installa l'app GitHub** in Spazio di lavoro → Integrazioni.

### Il test dice che non è stato possibile leggere la chiave privata

Incolla l'intero file `.pem`, comprese le righe `-----BEGIN` e `-----END`. Una
chiave `ed25519` o EC non può essere usata: le GitHub App firmano con RSA.

### Un membro ha effettuato l'accesso ma non vede alcun repository

L'app non è installata sull'account che li possiede, oppure la sua installazione
seleziona repository diversi. Un accesso concede solo ciò che l'app può vedere.

### Gli agenti dicono che l'installazione della GitHub App è sospesa

Qualcuno ha sospeso l'installazione su GitHub. Riattivala in **Settings →
Applications → Installed GitHub Apps** dell'account.
