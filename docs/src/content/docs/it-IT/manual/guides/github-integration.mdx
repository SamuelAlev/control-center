Questa guida copre le parti della configurazione specifiche di GitHub. GitHub è
uno dei tre host di codice supportati — vedi
[Collega un host di codice](/it-IT/manuale/guide/collega-host-di-codice/) per
collegare GitLab o Bitbucket e per capire come uno spazio di lavoro li combina.

## Prerequisiti

- Un account GitHub con accesso ai repo su cui vuoi lavorare
- Una GitHub App registrata per il tuo server (vedi
  [Crea la GitHub App](/it-IT/manuale/guide/github-app/)) così puoi
  **accedere**, **oppure** un personal access token con `repo` e `read:org` da
  incollare

:::note[Le credenziali risiedono sul server, collegate a te]
Niente viene memorizzato sulla macchina su cui stai digitando. La tua
credenziale è conservata dal tuo `cc_server`, indicizzata per il tuo id utente, e
ogni dispositivo da cui accedi la usa — desktop, web e telefono. Un altro membro
dello stesso server non può leggerla, e far accedere lui è una cosa che fa da sé.
:::

## Accedi con GitHub

Un **device flow**: GitHub ti mostra un codice breve, tu lo approvi su
github.com e il server riceve la credenziale — nessun URL di callback, nessuna
porta, niente da esporre. Disponibile ogni volta che il server ha un client id,
che una build ufficiale fornisce già.

1. Vai su **Impostazioni → Spazio di lavoro → Profilo e identità → Hosting del
   codice** (o al primo passaggio dell'onboarding)
2. Sulla riga **GitHub**, clicca su **Accedi con GitHub**
3. Una finestra di dialogo mostra un codice di otto caratteri e apre
   [github.com/login/device](https://github.com/login/device) nel tuo browser.
   Il codice è già negli appunti
4. Incollalo, approva l'app e torna qui. La riga diventa da sola
   «Autenticato come _tuo-nome-utente_»

Puoi chiudere la finestra di dialogo mentre completi nel browser — il server
continua a eseguire il polling finché il codice non scade (circa 15 minuti),
quindi l'accesso va comunque a buon fine.

## Oppure incolla un token

La soluzione di ripiego quando il server non ha un'app, quando l'app non è
installata su un account che ti serve, o quando preferisci semplicemente usare un
PAT.

1. Vai su **Impostazioni → Spazio di lavoro → Profilo e identità → Hosting del
   codice**
2. Sulla riga **GitHub**, clicca su **Aggiungi token**
3. Incolla un token con `repo` e `read:org` (classico) e salva. Un token
   **fine-grained** richiede **Contents** e **Pull requests** del repository (in
   lettura e scrittura), più **Checks** e **Actions** (in lettura).

Il token viene verificato mentre viene salvato, così la riga può indicare
l'account a cui appartiene. Clicca su **Disconnetti** per rimuoverlo.

Verifica: la riga **GitHub** mostra «Autenticato come _tuo-nome-utente_». Un
suffisso indica l'origine quando la credenziale che risponde non è la tua —
«tramite l'app di questo server» o «dall'ambiente».

:::note[La precedenza è fissa]
Una richiesta fatta a tuo nome usa **la tua** credenziale e nient'altro —
l'ambiente è la credenziale del server, non la tua, quindi non ti sostituisce
mai. Il lavoro senza un umano dietro (webhook, polling delle PR,
sincronizzazione dei ticket) usa l'identità applicativa del server, poi la
credenziale del proprietario del server, infine l'ambiente.
:::

## Cosa ti offre l'integrazione

| Funzionalità            | Come                                                                                                           |
| ----------------------- | -------------------------------------------------------------------------------------------------------------- |
| Elenco e dettaglio delle PR | L'API REST di GitHub, dal server, sull'identità applicativa o sulla tua credenziale                       |
| Esecuzioni dei controlli | L'API Checks di GitHub                                                                                        |
| Pubblicazione delle revisioni | Un passaggio attivato dall'utente che pubblica la tua revisione sulla PR                                 |
| Registrazione dei repo  | Un checkout viene accettato se il suo remote `origin` punta a github.com — o a gitlab.com / bitbucket.org      |
| Accesso GitHub degli agenti | Il broker delle credenziali inietta il token come `GH_TOKEN` / `GITHUB_TOKEN`, vincolato dalle capacità dell'agente |
| Ping delle notifiche    | Un polling lato server della tua casella delle notifiche GitHub genera «menzionato in una pull request» e «revisione richiesta» |
| Profili utente          | Schede del profilo al passaggio del mouse e filtro delle PR per autore                                         |

Alcuni percorsi usano l'API GraphQL invece di REST dove costa meno — l'attività
dei branch per il selettore di composizione delle PR e lo stato di revisione in
tempo reale che decide se una notifica di revisione richiesta è ancora in
sospeso.

## Sapere come agiscono gli agenti su GitHub

- Un agente ottiene un token GitHub solo se ha **Consenti chiamate API GitHub** o
  **Consenti git push**. Vedi
  [Configura le policy del sandbox](/it-IT/manuale/guide/policy-sandbox/)
- I commit creati da un agente sono attribuiti **all'agente** — il nome
  visualizzato più ` (agent)`, a un indirizzo sintetico derivato dall'id
  dell'agente — mai a una persona. Chi ha fatto la richiesta viene accreditato
  con un trailer `Co-Authored-By`
- Con una GitHub App configurata, il broker conia token di installazione
  fine-grained, limitati al repo e di circa un'ora per ogni avvio, invece di
  consegnare un token ampio. L'installazione viene risolta dal **proprietario**
  del repo dell'esecuzione, quindi un'unica app installata su più account si
  limita correttamente a quello che l'esecuzione tocca. Senza un'app, gli agenti
  ricevono il token dell'ambiente
- Un'esecuzione richiesta da un membro che ha effettuato l'accesso agisce con
  l'identità GitHub **di quel membro** — la sua credenziale viene unita dopo
  l'ambiente del broker, quindi un commit o un commento che un agente fa per lui
  è a lui attribuibile

## Risoluzione dei problemi

### L'elenco delle PR è vuoto e dice che GitHub non è collegato

Non hai alcuna credenziale GitHub su questo server. Accedi o incolla un token in
**Hosting del codice**. I repo su altri forge non sono interessati — solo quelli
di GitHub non contribuiscono nulla.

### La riga offre «Aggiungi token» ma non «Accedi con GitHub»

Il server non ha un client id — che è lo stato normale per una build dal codice
sorgente, dato che le credenziali vengono incorporate solo nelle build ufficiali.
Vedi [Crea la GitHub App](/it-IT/manuale/guide/github-app/): richiede circa due
minuti e solo il proprietario del server deve farlo, una volta sola.

### La finestra di accesso dice che il provider non ha restituito alcun device code

La GitHub App esiste, ma la sua casella **Device flow** è disattivata. Attivala
nelle impostazioni dell'app (General → Device flow) e riprova.

### La riga dice «tramite l'app di questo server» quando mi aspettavo il mio account

Non hai effettuato l'accesso; quello che vedi è l'identità applicativa del server
che risponde. Clicca su **Accedi con GitHub** su quella riga.

### Un PAT fine-grained non mostra il pulsante di unione né lo stato dei controlli

Il token richiede **Contents** e **Pull requests** (in lettura e scrittura), più
**Checks** e **Actions** (in lettura). Dopo averlo modificato, incollalo di nuovo
in Hosting del codice.

### L'aggiunta di un repo viene rifiutata

La registrazione richiede tutte e tre le condizioni: il percorso è dentro un git
work tree, ha un remote `origin` e quel remote punta a un forge supportato
(github.com, gitlab.com o bitbucket.org). Vedi
[Aggiungi repo a uno spazio di lavoro](/it-IT/manuale/guide/aggiungi-repo/).

### Tutto smette di funzionare per un po' dopo un uso intenso

È l'interruttore di circuito del rate limit. GitHub segnala il suo limite primario
con un `403` che porta `x-ratelimit-remaining: 0` e un orario di reset;
vedendone uno, il client fa fallire localmente le richieste successive senza una
chiamata di rete finché la finestra non trascorre, così una tempesta di tentativi
non può aggravare il limite. I guasti transitori vengono ritentati fino a tre
volte con backoff esponenziale, rispettando `retry-after`.
