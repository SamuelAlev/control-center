Questa guida spiega come avviare un'esecuzione a mano. Per seguirne una, leggere
l'output dei passaggi e riprenderti da un errore, vedi
[Monitora le esecuzioni delle pipeline](/it-IT/manuale/guide/monitora-pipeline/).

## Avvia un'esecuzione

1. Fai clic su **Pipelines** nella barra laterale dello spazio di lavoro.
2. Premi **Esegui pipeline** nell'intestazione. Arrivi sulla pagina di esecuzione
   (`/workspaces/<workspace-id>/pipelines/run`).
3. Scegli un modello dalla barra laterale sinistra. Ogni scheda mostra il nome del
   modello, la sua descrizione e se accetta input.
4. Compila il modulo degli input a destra. I campi obbligatori bloccano il pulsante
   finché non hanno un valore; un modello senza input lo dichiara.
5. Premi **Esegui pipeline**.

Arrivi sulla pagina di dettaglio dell'esecuzione, con la cascata dei tempi e il
canvas del grafo in tempo reale.

## Se la barra laterale è vuota

La pagina di esecuzione mostra un modello solo quando **entrambe** le condizioni
sono vere:

- L'interruttore del modello è attivo in **Impostazioni → Spazio di lavoro → Modelli di pipeline**.
- **Consenti esecuzione manuale** è attivo nella finestra **Esecuzione manuale**
  dell'editor del modello: è quell'interruttore a creare il trigger `manual` che
  la pagina di esecuzione legge.

Otto dei tredici modelli integrati arrivano disabilitati: `external_pr_welcome`,
`cross_review`, `ticket_to_pr`, `pr_triage`, `pre_merge_gate`, `release_notes`,
`dep_audit` e `pr_digest`. Il motore rifiuta di avviare un modello disabilitato,
quindi attiva il suo interruttore prima di cercarlo qui.

Non esiste alcuna azione **Esegui** per singolo modello nell'elenco dei modelli né
alcun pulsante di esecuzione dentro l'editor: la pagina di esecuzione è l'unico
punto di ingresso manuale.

## Compila un input di tipo repository

Un input di tipo **Repository** mostra un selettore sui repository registrati
nello spazio di lavoro. Sceglierne uno popola `repo_id`, `repo_local_path`,
`repo_full_name` e — quando il repository ha un remote GitHub — `repo_owner` e
`repo_name` nel payload dell'esecuzione, così i passaggi a valle possono leggere
quello che serve loro.

## Segui l'esecuzione

La pagina di dettaglio dell'esecuzione ha tre parti: una barra dei metadati (ora
di inizio, durata attiva, avanzamento dei passaggi, un banner di errore,
**Riprova** ed **Elimina**), una cascata dei tempi richiudibile con durata e costo
per passaggio e il canvas del grafo. Selezionando un nodo si apre il pannello di
dettaglio di quel passaggio.

[Monitora le esecuzioni delle pipeline](/it-IT/manuale/guide/monitora-pipeline/)
copre tutto questo, incluso come leggere un passaggio sospeso e cosa fare quando
uno non riesce.

Ogni esecuzione che avvii dall'app è reale.
