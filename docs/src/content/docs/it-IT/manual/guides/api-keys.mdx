Questa guida mostra dove è archiviata ogni credenziale usata da Control Center e
come modificarla.

**Niente è archiviato sulla macchina su cui stai digitando.** Ogni credenziale
vive sul server; quale risponda a una data richiesta dipende dal fatto che ci
sia o meno un umano dietro di essa.

| Credenziale                                   | Archiviazione                                                  | Chi la usa                                                                  |
| --------------------------------------------- | -------------------------------------------------------------- | --------------------------------------------------------------------------- |
| Il tuo accesso forge / ticket                 | Il file dei segreti 0600 del server, indicizzato per id utente  | Tutto ciò che fai: la superficie delle PR, le revisioni, i merge, le tue azioni su Linear |
| Le app dei provider del server                | Lo stesso file, più `server_settings` per gli elementi non segreti | L'accesso delle persone, e i token limitati a un repository per agenti, pipeline e polling |
| La chiave di installazione Connect            | Lo stesso file (`connect_install_key`)                          | Identificare questo server presso Control Center Connect                    |
| Chiavi dei fornitori di modelli e token OAuth | L'archivio di credenziali del server stesso                     | L'adattatore integrato, per ogni spazio di lavoro dell'installazione        |
| Credenziali del bot Slack                     | `<dataDir>/<workspaceId>/chat_credentials/` sul server          | Il ponte di chat di quello spazio di lavoro: i token della tua app, o l'autorizzazione sigillata dell'app condivisa |
| Credenziali delle CLI esterne                 | Qualunque cosa usi quella CLI                                   | Claude Code, sull'host del server                                           |

## GitHub: il tuo accesso e i token limitati a un repository

- **Il tuo**, da **Accedi a GitHub**. È quello che usa ogni richiesta fatta *a
  tuo nome*, quindi una revisione pubblicata per te porta il tuo nome. Un altro
  membro non può usarlo e accede da sé. Non c'è alcun token GitHub da incollare
- **Il lavoro che nessuno digita** (agenti, pipeline, polling, risposte del bot)
  riceve un token per un repository alla volta, emesso dalla GitHub App del
  server o tramite Control Center Connect, e limitato a ciò che un membro
  responsabile può fare lì. Non è mai il tuo accesso consegnato per intero

Il tuo si imposta nella scheda **Hosting del codice** in **Impostazioni → Tu → Profilo**; l'app del server in **App del fornitore** in
**Impostazioni → Server → Accesso single sign-on**. Vedi [Configura
l'integrazione GitHub](/it-IT/manuale/guide/integrazione-github/) e [Crea la
GitHub App](/it-IT/manuale/guide/github-app/).

GitLab e Bitbucket accettano ancora un token personale incollato, archiviato
allo stesso modo. Vedi [Collega un host di codice](/it-IT/manuale/guide/collega-host-di-codice/).

:::note[C'è anche una schermata accessibile solo tramite URL]
`/workspaces/<workspaceId>/api-keys` mostra le stesse schede del primo
passaggio dell'onboarding. Non ha **alcuna voce di navigazione da nessuna parte
nell'interfaccia**; è raggiungibile solo digitando l'URL. Usa invece
Impostazioni → Tu → Profilo per i tuoi accessi, e Impostazioni → Spazio di lavoro → Integrazioni per il fornitore di ticket.
:::

## Imposta le chiavi dei fornitori di modelli

L'adattatore integrato autentica i fornitori da sé e quelle credenziali vivono
sul server.

1. Vai in **Impostazioni → Server → Fornitori di modelli**
2. Scorri fino a **Provider e modelli**
3. Collega il fornitore — OAuth via browser per OpenAI, Codex, Cursor e Kimi
   Code; una chiave API per Anthropic e gli altri

Vedi [Gestisci adapter e modelli](/it-IT/manuale/guide/adapter/) per l'elenco
completo e per aggiungere un endpoint personalizzato.

Queste credenziali sono **globali per l'host**: una sola chiave serve ogni spazio
di lavoro dell'installazione. I token OAuth vengono rinnovati prima della
scadenza.

Claude Code accede tramite **Account Claude Code** in **Impostazioni → Server → Fornitori di modelli**: ogni account ottiene una propria cartella di configurazione sul server, e lì esegui il comando `claude auth login` che ti mostra l'app.

La finestra **Variabili d'ambiente** di ogni adattatore sembra il posto giusto
per inserire una chiave per uno di essi, ma non lo è: scrive sul tuo dispositivo,
mentre il server legge la propria copia e nulla collega le due. Vedi
[Gestisci adapter e modelli](/it-IT/manuale/guide/adapter/).

## Collega un fornitore di ticket

La scheda **Ticket** in **Impostazioni → Spazio di lavoro → Integrazioni** racchiude
la parte dello spazio di lavoro: presso quale fornitore vivono i tuoi
ticket e chi è Control Center quando vi lavora in autonomia. Scegliendo **Locale** si
nascondono le righe Linear — i ticket locali vivono nel database di questo
server e non hanno nulla da autenticare.

Linear ha due accessi e nessuna chiave da incollare: **Linear** è il tuo, per ciò
che fai tu, e vive in **Impostazioni → Tu → Profilo**; **Automazione Linear** è l'app Control Center dello spazio di
lavoro, collegata da un amministratore nella scheda **Ticket**, per la sincronizzazione dei ticket, le
pipeline e gli agenti. Il server può inoltre conservare una **Chiave API di
servizio** (**App del fornitore**) per gli spazi di lavoro senza automazione
collegata. Nel sandbox di un agente non viene iniettata alcuna credenziale di
ticketing; gli agenti scrivono i ticket tramite gli strumenti di Control Center,
che interrogano la regola **Scrivere su un tracker esterno**. Vedi
[Configura l'integrazione Linear](/it-IT/manuale/guide/integrazione-linear/).

## Ruota o revoca

- **Il tuo accesso GitHub**: premi **Disconnetti**, poi di nuovo **Accedi a
  GitHub**. La disconnessione fa cadere anche ogni token che il server ha emesso
  a tuo nome
- **Un token GitLab o Bitbucket**: premi **Aggiorna token** e incolla quello
  nuovo, poi revoca quello vecchio sulla forge
- **L'app del server**: genera una nuova chiave privata o un nuovo client secret
  sulla pagina dell'app presso il provider, incollala in **App del fornitore** e
  premi **Test**
- **La chiave di installazione Connect**: il proprietario del server preme
  **Ruota la chiave** nella scheda **Control Center Connect**. Chi ha effettuato
  l'accesso tramite Connect deve accedere di nuovo. Se un server Connect non è
  raggiungibile, non cambia nulla e ti viene proposto **Rigenera comunque**. Vedi
  [Ruota la chiave di installazione](/it-IT/manuale/riferimento/connect/#ruota-la-chiave-di-installazione)
- **Un fornitore di modelli**: sulla sua riga, disconnetti (OAuth) o rimuovi la
  chiave, poi collega di nuovo
- **Slack**: per la tua app, reincolla i token nella finestra di connessione.
  L'app Control Center condivisa non ha alcun token da ruotare: il suo token del
  bot viene rinnovato tramite Connect, e **Disconnetti** lo revoca e disinstalla
  il bot da Slack. Vedi [Configura l'integrazione Slack](/it-IT/manuale/guide/integrazione-slack/)

## Risoluzione dei problemi

### Un token GitLab o Bitbucket funziona in `curl` ma non qui

Controlla la riga **Hosting del codice**. Se dice «Non connesso» o ti chiede di
collegarti di nuovo, il token non è stato salvato o è stato rifiutato. Per
Bitbucket, inserisci l'email del tuo account Atlassian insieme al token API.

### Un token GitLab o Bitbucket viene accettato ma le richieste successive falliscono

Il token viene verificato così com'è archiviato, quindi la riga indica l'account
che vi sta dietro — ma solo l'account, non gli scope. Un token con troppi pochi
scope si connette e poi fallisce le singole richieste. Controllane gli scope e la
scadenza sulla forge.

### Un provider indica che l'accesso non è configurato su questo server

Il server non ha né un'app propria per quel provider né Control Center Connect.
Il proprietario del server ne sceglie uno in **Impostazioni → Server → Accesso
single sign-on**.
