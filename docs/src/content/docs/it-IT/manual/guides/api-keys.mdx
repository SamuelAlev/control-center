Questa guida mostra dove è archiviata ogni credenziale usata da Control Center e
come modificarla.

**Niente è archiviato sulla macchina su cui stai digitando.** Ogni credenziale
vive sul server; quale risponda a una data richiesta dipende dal fatto che ci
sia o meno un umano dietro di essa.

| Credenziale                                   | Archiviazione                                                  | Chi la usa                                                                  |
| --------------------------------------------- | -------------------------------------------------------------- | --------------------------------------------------------------------------- |
| La tua credenziale forge / ticket             | Il file dei segreti 0600 del server, indicizzato per id utente  | Tutto ciò che richiedi: la superficie delle PR, le esecuzioni dei tuoi agenti, le tue immagini |
| L'identità applicativa del server             | Lo stesso file, più `server_settings` per gli elementi non segreti | Il lavoro che nessun umano ha richiesto: webhook, polling delle PR, sincronizzazione dei ticket |
| Chiavi dei fornitori di modelli e token OAuth | L'archivio di credenziali del server stesso                     | L'adattatore integrato, per ogni spazio di lavoro dell'installazione        |
| Token del bot Slack                           | `<dataDir>/<workspaceId>/chat_credentials/` sul server          | Il ponte di chat di quello spazio di lavoro                                 |
| Credenziali delle CLI esterne                 | Qualunque cosa usi quella CLI                                   | Claude Code, sull'host del server                                           |

## Due credenziali GitHub, che rispondono a domande diverse

- **La tua**, ottenuta accedendo (device flow) o incollando un token. È quella
  che usa ogni richiesta fatta *a tuo nome*, quindi un commento pubblicato per te
  porta il tuo nome. Un altro membro non può leggerla e collega la propria
- **Quella del server**, dalla GitHub App registrata dall'operatore. Risponde a
  tutto ciò che non ha un chiamante — così l'accesso alla forge non scompare
  quando una persona se ne va o ruota un token

La tua si imposta nella scheda **Hosting del codice** in **Impostazioni → Spazio
di lavoro → Profilo e identità**; quella del server in **App del fornitore** in
**Impostazioni → Server → Accesso single sign-on**. Vedi [Configura
l'integrazione GitHub](/it-IT/manuale/guide/integrazione-github/) e [Crea la
GitHub App](/it-IT/manuale/guide/github-app/).

:::note[C'è anche una schermata accessibile solo tramite URL]
`/workspaces/<workspaceId>/api-keys` mostra le stesse due schede del primo
passaggio dell'onboarding. Non ha **alcuna voce di navigazione da nessuna parte
nell'interfaccia**; è raggiungibile solo digitando l'URL. Usa invece
Impostazioni → Spazio di lavoro → Profilo e identità.
:::

## Imposta le chiavi dei fornitori di modelli

L'adattatore integrato autentica i fornitori da sé e quelle credenziali vivono
sul server.

1. Vai in **Impostazioni → Server → Fornitori di modelli**
2. Scorri fino a **Provider e modelli**
3. Collega il fornitore — OAuth via browser per OpenAI, Codex, Cursor e Kimi
   Code; una chiave API per Anthropic e gli altri

Vedi [Gestisci adapter e modelli](/it-IT/manuale/guide/adapter/) per l'elenco
completo e per aggiungere un endpoint personalizzato.

Queste credenziali sono **globali per l'host**: una sola chiave serve ogni spazio
di lavoro dell'installazione. I token OAuth vengono rinnovati prima della
scadenza.

Le CLI degli adattatori esterni conservano le proprie credenziali, nella propria
configurazione, sull'host del server — Control Center non le gestisce. Autentica
Claude Code come indica la sua documentazione, sulla macchina su cui gira
`cc_server`.

La finestra **Variabili d'ambiente** di ogni adattatore sembra il posto giusto
per inserire una chiave per uno di essi, ma non lo è: scrive sul tuo dispositivo,
mentre il server legge la propria copia e nulla collega le due. Vedi
[Gestisci adapter e modelli](/it-IT/manuale/guide/adapter/).

## Collega un fornitore di ticket

La scheda **Ticket** in **Impostazioni → Spazio di lavoro → Generale** racchiude
entrambe le metà di una sola decisione: presso quale fornitore vivono i tuoi
ticket e la credenziale per accedervi. Scegliendo **Locale** si nasconde la riga
della credenziale — i ticket locali vivono nel database di questo server e non
hanno nulla da autenticare.

La tua chiave è archiviata sul server in base al tuo id utente, come quella della
forge. Il server conserva separatamente la propria chiave Linear (**App del
fornitore**), ed è quella su cui gira la sincronizzazione dei ticket quando
nessun umano l'ha richiesto. Una chiave ricevuta da un agente viene iniettata
solo quando l'agente ha la capacità **Consenti chiamate API dei ticket**. Vedi
[Configura l'integrazione Linear](/it-IT/manuale/guide/integrazione-linear/).

## Ruota o revoca

- **La tua credenziale GitHub**: premi **Disconnetti**, poi accedi di nuovo o
  incolla il nuovo token. Revoca quella vecchia su GitHub
- **L'app del server**: genera una nuova chiave privata o un nuovo client secret
  sulla pagina GitHub dell'app, incollala in **App del fornitore** e premi
  **Test**
- **Un fornitore di modelli**: sulla sua riga, disconnetti (OAuth) o rimuovi la
  chiave, poi collega di nuovo
- **Slack**: reincolla i token nella finestra di connessione. Vedi [Configura
  l'integrazione Slack](/it-IT/manuale/guide/integrazione-slack/)

## Risoluzione dei problemi

### L'elenco delle PR è vuoto ma il mio token funziona in `curl`

Controlla il sottotitolo della riga **Hosting del codice**. Se indica un'altra
origine («tramite l'app di questo server», «dall'ambiente»), la credenziale che
stai testando non è quella che risponde — la tua non è stata salvata.

### Il token viene accettato ma le richieste successive falliscono

Il token viene verificato così com'è archiviato, quindi la riga indica l'account
che vi sta dietro — ma solo l'account, non gli scope. Un token con troppi pochi
scope si connette e poi fallisce le singole richieste. Controlla gli scope e la
scadenza:

```bash
curl -H "Authorization: token YOUR_TOKEN" https://api.github.com/user
```
