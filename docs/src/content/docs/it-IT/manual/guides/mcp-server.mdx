Questa guida mostra come collegare un client MCP esterno — Claude Code, un
editor, l'MCP Inspector — al server di strumenti di Control Center.

Control Center registra **110** strumenti e li espone tramite il Model Context
Protocol, alla versione di protocollo `2024-11-05`. Intere famiglie di strumenti
che ti aspetteresti sono assenti: non ci sono strumenti per riunioni o calendario
e nessuno strumento per i progetti.

## Trova l'endpoint

La superficie MCP condivide il listener principale di `cc_server`. Non esiste una
porta MCP separata.

| Endpoint | Metodo   | Scopo                                                     |
| -------- | -------- | --------------------------------------------------------- |
| `/mcp`   | `POST`   | Trasporto Streamable HTTP — è quello che parla un client   |
| `/mcp`   | `DELETE` | Termina una sessione                                      |
| `/sse`   | `GET`    | Flusso di notifiche server-sent                           |

Quindi un'installazione locale predefinita è su `http://127.0.0.1:9030/mcp`.

1. Vai su **Impostazioni → Server → Server MCP**
2. Leggi la scheda **Server MCP**: mostra se è in esecuzione o arrestato e la
   porta su cui è in ascolto

La superficie è attiva per impostazione predefinita in un'installazione nuova. Solo il
proprietario del server vede il token nella scheda, e solo lui può avviare o fermare l'endpoint.
**Avvia all'apertura dell'app** controlla se torna attiva dopo un riavvio; **Avvia** /
**Ferma** sono controlli di sessione che non modificano quella preferenza.

Il server si associa al loopback per impostazione predefinita, quindi l'endpoint è
raggiungibile solo dalla macchina su cui è in esecuzione `cc_server`, a meno che
tu non l'abbia avviato con `--bind any`.

## Ottieni il token

Ogni richiesta richiede il token MCP del server, da qualsiasi macchina, anche dal loopback. Il
server lo crea la prima volta che si avvia. Non c'è modo di disattivarlo né di cancellarlo.

1. Su **Impostazioni → Server → Server MCP**, trova la riga **Token di autenticazione**
2. Premi **Mostra token** e copialo
3. Per sostituirlo, premi **Rigenera token**. Il server passa subito al nuovo token, e ogni client
   che usa ancora quello vecchio viene rifiutato finché non gli dai il nuovo

## Collega un client

Punta il tuo client sull'endpoint Streamable HTTP e invia il token come
`Authorization: Bearer <token>` in ogni richiesta, `GET /sse` compreso. Non c'è altro modo di
inviarlo: un token nell'URL non viene accettato. La forma esatta della configurazione dipende dal
tuo client.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code non lo rileverà da un `.mcp.json` di progetto: subordina i server MCP
con ambito di progetto a un prompt di approvazione a cui un `claude -p` non
interattivo non risponde mai. Passa la configurazione esplicitamente:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` fa usare a Claude solo quel file, così lo stesso server non
viene anche rilevato dal progetto e registrato due volte.

Verifica: chiedi al client di elencare i suoi strumenti. Dovresti vedere voci
`mcp__*` che coprono ticket, spazi, memoria, grafo del codice e revisione.

## Cosa rifiuta l'endpoint

Il token apre ogni strumento del server, quindi l'endpoint rifiuta anche tutto ciò che una pagina
web potrebbe aver inviato, prima di esaminare il token:

| Richiesta | Risposta |
| --------- | -------- |
| Un'intestazione `Origin` che non è una pagina di questa macchina (`http://localhost`, `http://127.0.0.1` o `http://[::1]`, qualsiasi porta) | `403`, "Cross-origin requests are not accepted" |
| Un'intestazione `Host` che non è né l'indirizzo loopback e la porta di questo listener né il nome host pubblico del server | `403`, "Unknown host" |
| Un `POST` il cui corpo non è `application/json` | `415` |
| Nessun token, o uno sbagliato | `401` |

Per servire MCP oltre l'host, avvia il server con `--bind any` e invia il token dall'altra macchina,
indirizzando il server tramite il suo nome host pubblico.

## Limita ogni chiamata a uno spazio di lavoro

Ogni strumento che tocca dati con ambito di spazio di lavoro richiede
`workspace_id`, e una chiamata che ne è priva viene rifiutata invece di essere
risolta su uno spazio di lavoro «corrente»:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

L'id è quello presente nell'URL del browser o dell'app:
`/workspaces/<workspace_id>/…`. Le uniche eccezioni sono gli strumenti che
abbracciano davvero più spazi di lavoro, come `list_workspaces` e gli strumenti
delle notizie: le notizie sono per utente e un agente non ha un utente proprio,
quindi quegli strumenti operano sui feed del proprietario del server.

Gli strumenti con ambito di repository verificano inoltre che il repository sia
collegato a quello spazio di lavoro.

## Scopri cosa rifiuterà la superficie

- **Controllo tramite modalità.** Una chiamata viene risolta lato server in base
  alla modalità dello spazio dell'agente chiamante. Un agente in una modalità di
  sola lettura non può raggiungere uno strumento di scrittura omettendo
  `space_id`: la modalità viene invece ricavata dalla sua esecuzione attiva.
- **Guardrail delle azioni.** Gli strumenti che modificano lo stato dichiarano le
  loro classi di effetto e passano dalla stessa policy usata dal resto del
  prodotto. Vedi
  [Configura i guardrail](/it-IT/manuale/guide/configura-guardrail/).
- **Conferma.** Alcuni strumenti distruttivi costruiscono un payload di conferma
  che deve essere approvato prima che la chiamata proceda.

Il catalogo completo viene annunciato in `tools/list` senza alcun filtro in fase
di scoperta: un client MCP esterno rifiuta di chiamare uno strumento che non è
nella sua lista memorizzata nella cache, quindi nascondere gli strumenti li rompe
invece di rimetterli in ordine.

## I server MCP personali restano del proprietario

Questa guida riguarda l'endpoint proprio di Control Center. L'altra direzione, i server MCP che
Control Center consegna agli agenti che esegue, si trova in **Impostazioni → Server → Server MCP →
Server MCP esterni**. I server configurati sulla macchina del server per Claude, Codex, Cursor,
Gemini, VS Code, Windsurf, OpenCode o in un `.mcp.json` vengono trovati lì automaticamente.

Questi server rilevati provengono dalla configurazione degli strumenti dell'utente del server e
agiscono con l'identità e le credenziali di quell'utente, quindi appartengono al proprietario del
server:

- Sono disponibili solo all'interno delle esecuzioni dell'harness integrato che il proprietario del
  server avvia o di cui risponde, inclusa l'automazione in uno spazio di lavoro di cui il proprietario
  risponde.
- L'esecuzione di un membro, l'automazione legata a un membro e ogni esecuzione su un server senza
  proprietario registrato non ne ottengono nessuno. Lì gli strumenti non sono elencati, non possono
  essere chiamati e non compaiono nella ricerca degli strumenti.
- Questo endpoint non li elenca, non li chiama né li cerca mai, per chiunque, token del proprietario
  incluso, e non ne inoltra risorse o prompt. Quindi un CLI di agente che raggiunge Control Center
  tramite MCP, come Claude Code, non li ottiene nemmeno tramite Control Center; usa la propria
  configurazione.

I server MCP configurati per lo spazio di lavoro non sono toccati da nulla di tutto questo.

## Risoluzione dei problemi

### Il client non vede alcuno strumento

- Controlla che la scheda **Server MCP** indichi che è in esecuzione
- Controlla che la porta corrisponda a quella del tuo `cc_server`
- Su Claude Code, controlla di aver passato `--mcp-config` e
  `--strict-mcp-config`

### 401 Unauthorized

La richiesta non aveva alcun token, oppure ne aveva uno vecchio. Copia il token attuale dalla riga
**Token di autenticazione** e invialo come `Authorization: Bearer <token>`. Un token nell'URL viene
ignorato.

### 403 da un client che prima funzionava

La richiesta aveva un `Origin` di una pagina web, oppure un `Host` a cui il server non risponde.
Chiama l'endpoint da un client anziché da una pagina del browser, usando l'indirizzo loopback del
server o il suo nome host pubblico.

### 415 Unsupported Media Type

Invia i corpi di `POST /mcp` come `application/json`.

### Una chiamata a uno strumento fallisce con «Missing or invalid argument: workspace_id»

Aggiungi `workspace_id`. Non esiste uno spazio di lavoro implicito.

### Una chiamata a uno strumento viene rifiutata come sconosciuta

[Strumenti MCP](/it-IT/manuale/riferimento/strumenti-mcp/) elenca il catalogo.
Usa il nome esattamente come compare lì.
