Questa guida mostra come riempire uno spazio di lavoro di skill provenienti da
GitHub: aggiungi un repository come sorgente, installa da esso le skill che
vuoi e mantienile aggiornate nel tempo.

La cosa importante da sapere prima di iniziare: **un repository sorgente non è
attendibile.** Il suo nome, la sua descrizione e il numero di stelle sono
scritti da chi lo possiede. L'unico segnale di sicurezza di cui Control Center
si fida è il verdetto della scansione antivirus, che ogni installazione
attraversa prima che qualsiasi cosa arrivi su disco o in un prompt di un
agente. Se vuoi il ragionamento, leggi la
[sezione sulle skill del modello degli agenti](/it-IT/manuale/concetti/modello-agenti/); questa pagina resta
sul fare.

Le skill si trovano in **Impostazioni → Spazio di lavoro → Competenze**
(`/workspaces/<id>/settings/workspace/skills`). Hanno come ambito lo spazio di
lavoro: le skill che installi qui appartengono solo a questo spazio di lavoro.
La pagina ha due schede: **Installate** (skill locali, con un editor **Nuova
competenza**) e **Sorgenti** (cataloghi GitHub). Entrambe le scritture passano
per lo stesso varco di scansione.

## Aggiungi un repository di skill

1. Apri **Impostazioni → Spazio di lavoro → Competenze** e passa alla scheda **Sorgenti**.
2. Premi **Aggiungi repository**.
3. Incolla l'URL di un repository GitHub, ad es. `https://github.com/anthropics/skills`,
   e conferma.

Il server verifica che il repository esista e sia visibile con le sue
credenziali, poi lo aggiunge alla barra laterale sinistra. Non c'è nessun
catalogo curato nel mezzo: qualsiasi repository GitHub va bene, il che
significa anche che la reputazione sta a te giudicarla — un numero di stelle è
una prova, mai una garanzia.

Le skill di un repository sono le directory che contengono un `SKILL.md` (fino
a tre livelli di profondità, più la struttura del marketplace dei plugin di
Claude `plugins/<plugin>/skills/<skill>`, saltando gli alberi delle dipendenze
e dei vendor). Se in seguito la griglia dice che il repository non ha skill,
ecco cosa significa: nessuna directory al suo interno corrisponde alla
convenzione delle skill.

## Ispeziona una skill prima di installarla

Seleziona un repository nella barra laterale; le sue skill compaiono come una
griglia a destra, con sopra un campo di filtro che restringe il catalogo per
nome, descrizione o slug. Fai clic su una scheda per aprire la vista di
dettaglio. Mostra tre cose:

- **Il README**, renderizzato come markdown — il `README.md` della directory
  della skill, oppure il corpo del `SKILL.md` quando non c'è un README.
- **L'anteprima della scansione** — il verdetto (`pass`, `warn` o
  `quarantine`), le capacità dichiarate dal contenuto della skill (esegue
  shell, scrive file, accesso alla rete…) e ogni riscontro registrato dallo
  scanner.
- **Il numero di file** — un'installazione scrive l'intera directory della
  skill, non solo il suo `SKILL.md`.

L'anteprima analizza esattamente i byte che scriverebbe un'installazione,
quindi il verdetto che vedi è il verdetto che ottiene l'installazione; nulla
viene rigiudicato alle tue spalle.

## Installa una skill

1. Apri la vista di dettaglio della skill.
2. Leggi il verdetto della scansione. Per un verdetto `warn` o `pass`, premi **Installa**.
3. Per un verdetto `quarantine`, l'installazione resta disattivata finché non
   metti la spunta su **Accetto il rischio — installa comunque**. Quell'override
   viene registrato, non dato per scontato.

L'installazione scrive la directory della skill nello spazio di lavoro,
registra un pin in `skills-lock.json` (repository sorgente, percorso, il commit
da cui proviene e un hash del contenuto), e la skill diventa disponibile agli
agenti dello spazio di lavoro. Una scheda contrassegnata **Nome in uso**
significa che un'altra skill possiede già quel nome in locale — disinstalla
prima quella.

## Aggiorna le skill nel tempo

Le schede delle skill installate portano dei badge: **Installata**, oppure
**Aggiornamento disponibile** quando il repository è andato oltre il commit che
hai fissato. Apri la vista di dettaglio e premi **Aggiorna** per recuperare di
nuovo al nuovo commit. Un aggiornamento passa per lo stesso varco di scansione
di un'installazione — una skill la cui nuova versione finisce in quarantena
viene rifiutata e la versione che avevi resta al suo posto. L'hash della
versione precedente viene conservato come riferimento per il rollback nel lock.

## Disinstalla una skill, rimuovi un repository

**Disinstalla** (nella vista di dettaglio di una skill installata, oppure
elimina nella scheda Installate) rimuove insieme la directory della skill e il
suo pin nel lock — una skill disinstallata non lascia nulla dietro di sé.

**Rimuovere un repository** dalla barra laterale rimuove solo il catalogo: le
skill che hai installato da esso restano installate e continuano ad
aggiornarsi, perché un pin registra il repository per nome anziché per
riferimento alla voce sorgente. Riaggiungi il repository se vuoi sfogliarlo di
nuovo.

## Richiama una skill

Le skill vengono richiamate sotto il proprio namespace, così non entrano mai in
collisione con i comandi slash integrati (`/plan`, `/goal`, `/loop`, `/compact`):

- `/skill:<name>` — una skill installata in questo spazio di lavoro, o collegata
  all'agente
- `/skill:<repo>:<name>` — una skill fornita da un repo di cui è stato fatto il
  checkout in questo spazio

Un nome nudo non integrato viene comunque risolto, per i messaggi scritti prima
che il namespace esistesse. `/skill:plan` è ciò che raggiunge una skill
chiamata `plan`; `/plan` è sempre quello integrato.

## Skill con ambito di repository

Un repo di cui è stato fatto il checkout può fornire skill proprie, in
`.agents/skills/`, `.agent/skills/`, `.claude/skills/`, `.opencode/skills/` o
`skills/`. Quelle **non** vengono installate tramite questa pagina. Un agente
porta con sé solo le skill del repo in cui sta lavorando in quel momento;
cambiano quando si sposta. Il composer non è limitato in quel modo:
`/skill:<repo>:<name>` raggiunge qualsiasi repo dello spazio.

Le skill di repo passano la stessa scansione fail-closed (`pass` / `warn` /
`quarantine`) prima che il loro frontmatter arrivi a un prompt. `warn` è
ammesso; `quarantine` viene trattenuto, senza alcun override dell'operatore su
quel percorso.

Vedi [Skill con ambito di repository](/it-IT/manuale/concetti/modello-agenti/#repo-scoped-skills) e
[Comandi slash](/it-IT/manuale/riferimento/comandi-slash/).
