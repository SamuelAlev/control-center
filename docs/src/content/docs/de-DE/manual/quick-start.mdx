Das ist der kürzeste vollständige Weg von null bis zu einem Agenten, der an deinem eigenen Code arbeitet. Geh ihn der Reihe nach; jeder Schritt hängt vom vorherigen ab.

Du brauchst Git, ein GitHub-Konto und entweder ein Konto bei einem Modellanbieter (Anthropic, OpenAI, Codex, Cursor, Kimi Code oder ein beliebiger Anbieter mit API-Schlüssel) oder die bereits installierte Claude Code CLI. Alles andere richtest du unterwegs ein.

## Schritt 1: Installieren und starten

Installiere Control Center wie unter [Installation](/de-DE/handbuch/installation/) beschrieben und öffne es.

Beim ersten Start fragt der Desktop **„Wie soll Control Center laufen?“** Wähle **In dieser App ausführen**. Control Center startet auf diesem Rechner einen headless `cc_server`, der deine Daten besitzt und die ganze Arbeit erledigt. Du siehst ihn nie; stattdessen öffnet sich der Onboarding-Bildschirm.

:::note[Lieber nichts installieren?]
Dieselbe App läuft im Browser unter [app.usectrl.dev](https://app.usectrl.dev) mit denselben
Funktionen. Ein Browser-Tab kann den Server aber nicht selbst hosten, du stellst also
einen bereit — starte `cc_server` lokal und verbinde dich mit `ws://localhost:9030`, oder
zeige auf einen Server auf einem anderen Rechner. Dieser Schnellstart nimmt den
Desktop-Weg, weil dafür kein Server eingerichtet werden muss; den Browser-Weg findest du
unter [Installation](/de-DE/handbuch/installation/#im-browser-nutzen).
:::

## Schritt 2: Das Onboarding durchgehen

Das Onboarding hat fünf Schritte, und sie laufen der Reihe nach — vorausspringen geht nicht.

1. **Verbinden**: Melde dich mit GitHub an oder füge ein persönliches Zugriffstoken mit `repo` und `read:org` ein. Die Zugangsdaten liegen auf dem Server und sind an dein Konto gebunden.
2. **Workspace**: Benenne deinen ersten Arbeitsbereich und wähle optional ein Logo. Beim Anlegen entstehen fünf Agenten — ein CEO plus `qa`, `architect`, `engineer` und `librarian` — und die mitgelieferten Pipeline-Vorlagen.
3. **Sandbox**: hält eine Sandbox-Präferenz fest. Beide Entscheidungen lassen dich weitergehen.
4. **Adapter**: Wähle den Adapter und das Modell, das Agenten standardmäßig nutzen sollen. Wähle **Control Center (built-in)** und melde dich dann in der Anbieterauswahl, die erscheint, bei einem Modellanbieter an — die Modellliste bleibt leer, bis einer verbunden ist. Mit dem Abschluss dieses Schritts werden Adapter und Modell auch auf den CEO-Agenten des Arbeitsbereichs geschrieben.
5. **Stimme (optional)**: Installiere ein Sprachmodell auf dem Gerät fürs Diktat, oder überspringe den Schritt.

Control Center öffnet danach den Posteingang deines Arbeitsbereichs.

:::note[Was einen Agentenlauf begrenzt]
Agentenbefehle werden mit der nativen Sandbox des Host-Betriebssystems umhüllt, sobald eine vorhanden ist — Seatbelt unter macOS, bubblewrap unter Linux. Windows hat kein Backend, dort begrenzen die Läufe also nur die anderen Schichten: der eigene Worktree der Unterhaltung (`git worktree` unter Windows; Copy-on-Write, wo `rift` mitgeliefert wird), Zugangsdaten, die bei jedem Start vermittelt und beim Aufräumen widerrufen werden, und die Aktions-Schutzregeln. Siehe [Sandbox und Sicherheit](/de-DE/handbuch/konzepte/sandbox-und-sicherheit/).
:::

## Schritt 3: Ein Repository hinzufügen

Geh zu **Einstellungen → Arbeitsbereich → Repositorys** und klicke auf **Repository hinzufügen**.

Der Dialog durchsucht die Ordner auf dem Rechner, der den Server ausführt, nicht die deines Clients, und er bleibt in den Wurzeln, die dieser Server freigeben soll (standardmäßig das Home-Verzeichnis seines Benutzers). Nur Git-Checkouts bekommen ein Kontrollkästchen. Hake deinen an und registriere ihn.

Ein Checkout wird nur angenommen, wenn er in einem Git-Arbeitsbaum liegt, ein `origin`-Remote hat und dieses Remote auf eine unterstützte Forge zeigt — github.com, gitlab.com oder bitbucket.org. Alles andere wird mit der Begründung abgelehnt.

Repos sind an den Arbeitsbereich gebunden: Ein Checkout, den du hier registrierst, landet in _diesem_ Arbeitsbereich. Einen eigenen Verknüpfungsschritt gibt es nicht.

## Schritt 4: Einem Agenten Adapter und Modell geben

Geh zu **Einstellungen → Arbeitsbereich → Agenten**. Wähle den Agenten `engineer` in der Liste.

Auf dem Tab **Einstellungen** setzt du:

- **Adapter**: `Control Center (built-in)`
- **Modell**: wähle eines vom Anbieter, den du im Onboarding verbunden hast

Klicke auf **Änderungen speichern**.

Dieser Schritt ist in der Praxis nicht optional. Nur der CEO-Agent übernimmt den Adapter aus dem Onboarding; die vier Spezialisten werden ohne einen angelegt. Sie fallen auf **Control Center (built-in)** mit dem Standardmodell von Anthropic zurück, laufen also nur, wenn du ein Anthropic-Konto verbunden hast — und dann auf einem Modell, das du nicht gewählt hast, falls du eins verbunden hast.

## Schritt 5: Dem Agenten eine Aufgabe schicken

1. Such in der Seitenleiste den Abschnitt **Bereiche** und klicke auf **+**.
2. Benenne den Bereich, füge den Agenten `engineer` unter **Agenten hinzufügen** hinzu und lege ihn an.
3. Tippe eine konkrete, kleine Aufgabe zum Repo, das du registriert hast, und drücke Enter.

Control Center stellt für diese Unterhaltung einen Copy-on-Write-Worktree der Repos des Arbeitsbereichs bereit, setzt einen Prompt aus Rolle, Persona und Skills des Agenten sowie dem Kontext des Bereichs zusammen und dispatcht den Lauf. Dein Quell-Checkout wird nie verändert.

## Schritt 6: Bei der Arbeit zusehen

Du solltest der Reihe nach sehen:

- Die Senden-Schaltfläche des Composers wird zur Stopp-Schaltfläche, weil ein Agent in dieser Unterhaltung arbeitet
- Reasoning-Abschnitte, Werkzeugaufrufe und Text des Agenten streamen ins Transkript
- Die Senden-Schaltfläche kommt zurück, wenn der Lauf endet

Öffne dann **Einstellungen → Arbeitsbereich → Agenten**, wähle den Agenten und prüfe den Tab **Protokolle**: eine Laufzeile mit Status, Dauer, Start- und Endzeit und dem Adapter, auf dem er gelaufen ist.

Das ist die Schleife. Alles andere in Control Center — Pull-Request-Review, Pipelines, Tickets, Besprechungen, Slack — hängt daran.
