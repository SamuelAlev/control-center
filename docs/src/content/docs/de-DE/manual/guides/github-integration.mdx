Diese Anleitung behandelt die GitHub-spezifischen Teile der Einrichtung. GitHub ist einer von drei
unterstützten Code-Hosts. Siehe [Einen Code-Host verbinden](/de-DE/handbuch/anleitungen/code-host-verbinden/),
wenn du GitLab oder Bitbucket verbindest und wissen willst, wie ein Arbeitsbereich sie mischt.

## Voraussetzungen

- Ein GitHub-Konto mit Zugriff auf die Repos, an denen du arbeiten willst
- Ein Server, der Personen bei GitHub anmelden kann: entweder mit seiner eigenen
  GitHub App (siehe [Die GitHub App erstellen](/de-DE/handbuch/anleitungen/github-app/))
  oder über Control Center Connect, gewählt vom Server-Eigentümer unter
  **Einstellungen → Server → Single sign-on**

:::note[Die Zugangsdaten liegen auf dem Server, an dich gebunden]
Auf dem Rechner, an dem du tippst, liegt nichts. Deine GitHub-Anmeldung hält dein
`cc_server`, gebunden an deine Benutzer-ID, und jedes Gerät, von dem du dich anmeldest, nutzt
sie: Desktop, Web und Smartphone. Ein anderes Mitglied desselben Servers kann sie nicht nutzen,
und anmelden muss es sich selbst.
:::

## Bei GitHub anmelden

Bei GitHub gibt es nur die Anmeldung: Ein Token zum Einfügen gibt es nicht.

1. Öffne **Einstellungen → Arbeitsbereich → Profil und Identität → Code-Hosting** (oder den ersten
   Schritt des Onboardings)
2. Klicke in der Zeile **GitHub** auf **Bei GitHub anmelden**
3. Dein Browser öffnet GitHub. Gib die App frei

Wie die Anmeldung endet, hängt davon ab, wer sie ausführt:

- **Die eigene App des Servers:** GitHub schickt deinen Browser zum Server
  zurück, und der Dialog merkt das von selbst. Nichts einzutippen
- **Control Center Connect:** Die Browserseite zeigt einen 8-stelligen Code.
  Tippe ihn in den Dialog ein, oder lass den Browser Control Center über den
  Link `control-center://` öffnen und spar dir das Eintippen

Zur Kontrolle: Die Zeile **GitHub** zeigt „Angemeldet als _dein-benutzername_“.

Einen Code oder Link, den der Dialog nicht selbst gestartet hat, lehnt er mit
**Anmeldung nicht hier gestartet** ab. Schickt dir jemand einen Anmeldelink, mach
nicht weiter: Ihn abzuschließen würde dein Konto mit dem Server dieser Person
verbinden.

Klicke auf **Trennen**, um deine Anmeldung zu entfernen. Meldest du dich bei
GitHub ab oder wirst du aus einem Arbeitsbereich entfernt, fallen ebenfalls alle
Tokens weg, die der Server in deinem Namen ausgestellt hat.

## Für wen dein Zugangsdatum spricht

- **Alles, was du tust** (die PR-Seite öffnen, ein Review posten, genehmigen,
  mergen), läuft über **deine** Anmeldung und sonst nichts. Bist du nicht
  angemeldet, sagt die App das und fordert dich auf, dich anzumelden. Kein
  anderes Zugangsdatum springt für dich ein
- **Arbeit, bei der niemand tippt** (Agentenläufe, Pipelines, PR-Polling,
  Bot-Antworten, Klone), bekommt ein Token für ein Repository, ausgestellt über
  die GitHub App des Servers oder über Connect. Es ist auf das begrenzt, was ein
  verantwortliches Mitglied dort tun darf: das Mitglied, das gefragt hat, sonst
  der Besitzer des Arbeitsbereichs. Ein Mitglied, das nicht pushen darf,
  beschränkt das Token aufs Lesen
- **Automatisierung genehmigt nie** einen Pull Request. Genehmigen ist die
  Handlung einer Person

## Was die Integration bringt

| Funktion                  | Wie                                                                                                            |
| ------------------------- | -------------------------------------------------------------------------------------------------------------- |
| PR-Liste und Detail       | Die GitHub-REST-API, vom Server aus, über deine eigene Anmeldung                                              |
| Check-Runs                | Die GitHub Checks API                                                                                          |
| Review veröffentlichen    | Ein Schritt, den ein Nutzer auslöst und der dein Review unter deinem Namen an den PR postet                  |
| Repo-Registrierung        | Ein Checkout wird angenommen, wenn sein `origin`-Remote auf github.com zeigt, oder auf gitlab.com / bitbucket.org |
| GitHub-Zugang für Agenten | Ein Token für das eine Repository des Laufs als `GH_TOKEN` / `GITHUB_TOKEN`; Pushes laufen durch Control Center |
| Benachrichtigungen        | Eine serverseitige Abfrage deines GitHub-Benachrichtigungspostfachs erzeugt „In Pull Request erwähnt“ und „Review angefragt“ |
| Nutzerprofile             | Profilkarten beim Überfahren und die Filterung der PRs nach Autor                                             |

Manche Pfade nutzen die GraphQL-API statt REST, wo das günstiger ist: die Branch-
Aktivität für die Auswahl beim Erstellen eines Pull Requests und der aktuelle Review-Status, der entscheidet,
ob eine Benachrichtigung „Review angefragt“ noch offen ist.

## GitHub-Ausfälle im Blick behalten

Die Titelleiste zeigt ein Status-Kennzeichen, wenn ein Anbieter beeinträchtigt ist: GitHub,
Claude, OpenAI und Kimi. **Solange alles gesund ist, bleibt es ausgeblendet**: sichtbar
meldet es eine Störung, nicht deren Abwesenheit.

Klicke auf das Kennzeichen, um ein Fenster mit dem Zustand jedes Anbieters und der Schaltfläche
**Aktualisieren** zu öffnen. Die Statuswerte aktualisieren sich alle zwei Minuten von selbst.

## So handeln Agenten auf GitHub

- Ein Agent, der in einem GitHub-Worktree arbeitet, bekommt ein Token für
  dieses eine Repository. Es kann den Code lesen und Pull Requests
  kommentieren, wenn das verantwortliche Mitglied pushen darf, und nur lesen,
  wenn nicht. Ein Push läuft durch Control Center, das
  die Regel **Zu einem Remote pushen** fragt und ihn dann mit einem
  Schreib-Token weiterleitet, das der Agent nie besitzt. Siehe
  [Sandbox-Richtlinien konfigurieren](/de-DE/handbuch/anleitungen/sandbox-richtlinien/)
- Agenten-Commits verwenden immer die Git-Identität der anfragenden Person als Autor und Committer. Standardmäßig weist der Trailer `Co-Authored-By: Control Center <hi@usectrl.dev>` das GitHub-Konto `@usectrl` als Mitautor aus. Unter **Einstellungen → Du → Commit-Zuordnung** kannst du diese Mitautorenschaft abschalten, ohne deine Identität zu ändern. Die Vorgabe unter **Einstellungen → Arbeitsbereich → Allgemein** hat Vorrang und sperrt den persönlichen Schalter. Die eigene Zuordnung von Claude Code ist stets deaktiviert. Die Commit-Signierung erfordert weiterhin eine eigene gültige Konfiguration
- Ein Terminal, das du auf einem Rig öffnest, bekommt deine eigene Anmeldung,
  eingeschränkt auf das eine Repository, Pushes von dort sind also deine
- Lässt sich kein Token ausstellen (niemand Verantwortliches ist angemeldet, die
  App ist beim Besitzer nicht installiert, oder die Installation ist gesperrt),
  startet der Lauf ohne, und seine Notizen nennen den Grund. Ersatz-Zugangsdaten
  gibt es nicht

## Fehlersuche

### Die PR-Liste ist leer und meldet, GitHub sei nicht verbunden

Du bist auf diesem Server nicht bei GitHub angemeldet. Klicke unter
**Code-Hosting** auf **Bei GitHub anmelden**. Repos auf anderen Code-Hosts bleiben unberührt.

### Die Zeile GitHub meldet, die Anmeldung sei auf diesem Server nicht eingerichtet

Der Server hat weder eine eigene GitHub App noch Connect. Der Server-Eigentümer
wählt eins davon unter **Einstellungen → Server → Single sign-on**: **Meine
GitHub-App erstellen** dauert etwa zwei Minuten. Siehe
[Die GitHub App erstellen](/de-DE/handbuch/anleitungen/github-app/).

### Der Dialog meldet, dass der Code nicht passt

Tippe den Code genau so ein, wie der Browser ihn zeigt: 8 Buchstaben und
Ziffern. Fünf falsche Codes beenden die Anmeldung; starte sie neu.

### Die Anmeldung meldet, die App sei nicht installiert

Die GitHub App hat keine Installation auf dem Konto, dem das Repository gehört.
Ein Administrator des Arbeitsbereichs installiert sie unter **Einstellungen →
Arbeitsbereich → Allgemein → GitHub-App-Installationen**. Bei einer Organisation
auf der gemeinsamen App von Control Center muss ein Administrator dieser
Organisation unter Umständen auf **Diesen Server autorisieren** klicken. Siehe
[Die GitHub App erstellen](/de-DE/handbuch/anleitungen/github-app/#diesen-server-für-eine-organisation-autorisieren).

### Alle müssen sich erneut bei GitHub anmelden

Der Server-Eigentümer hat den Connect-Schlüssel des Servers rotiert oder den
Connect-Server gewechselt, oder das Datenverzeichnis wurde auf einer anderen
Maschine wiederhergestellt. Anmeldungen über Connect sind an den Server
gebunden, der sie erzeugt hat.

### Ein Repo wird beim Hinzufügen abgelehnt

Zur Registrierung müssen alle drei gelten: Der Pfad liegt in einem Git-Arbeitsbaum, er hat ein
`origin`-Remote, und dieses Remote zeigt auf eine unterstützte Forge (github.com,
gitlab.com oder bitbucket.org). Siehe
[Repos zu einem Arbeitsbereich hinzufügen](/de-DE/handbuch/anleitungen/repos-hinzufuegen/).

### Nach starker Nutzung steht eine Weile alles still

Das ist der Schutzschalter für das Rate-Limit. GitHub signalisiert sein primäres Limit mit einem
`403`, das `x-ratelimit-remaining: 0` und eine Reset-Zeit trägt; sobald der Client eines sieht,
lässt er weitere Anfragen lokal scheitern, ohne Netzwerkaufruf, bis das Fenster
abgelaufen ist, damit eine Flut von Wiederholungen das Limit nicht weiter verschärft. Vorübergehende Fehler werden
bis zu dreimal mit exponentiellem Backoff erneut versucht, und `retry-after` wird beachtet.
