Diese Anleitung zeigt dir, wie du deine Chat-Identität mit deinem Nutzer in Control Center verknüpfst und wie du eine Verknüpfung wieder löst.

Jedes Mitglied macht das einmal pro Chat-Anbieter. Das ist etwas anderes, als die App zu verbinden: Die Verbindung macht den Bot für den ganzen Arbeitsbereich erreichbar, die Verknüpfung macht _dich_ darin erkennbar.

## Warum die Verknüpfung nötig ist

Die Brücke weigert sich, für ein Chat-Konto zu handeln, das sie keinem Mitglied des Arbeitsbereichs zuordnen kann. Das ist Absicht — ohne Verknüpfung müsste jede Nachricht aus Slack der Person zugerechnet werden, die die App installiert hat, und Prüfpfad, Rate-Limits pro Prinzipal und die Melder der Tickets würden alle die falsche Person nennen.

Ein nicht verknüpftes Mitglied, das den Bot erwähnt, bekommt in diesem Slack-Thread eine Antwort, die erklärt, wie die Verknüpfung geht. Es wird nichts ausgeführt.

## Mit einem Code verknüpfen

1. Geh zu **Einstellungen → Arbeitsbereich → Profil und Identität** und scrolle zur Karte **Verknüpfte Chat-Konten**
2. Klicke im Slack-Block auf **Mein Slack-Konto verknüpfen**
3. Kopiere den Befehl, den sie anzeigt, zum Beispiel:

```text
/cc link K7M2QP
```

4. Schick diesen Befehl in Slack an den Bot — eine Direktnachricht ist der einfachste Ort
5. Der Bot bestätigt mit dem Nutzer in Control Center, mit dem du jetzt verknüpft bist, und der Dialog, den du offen gelassen hast, sagt im selben Moment dasselbe — du musst ihn nicht schließen und nachsehen

Der Code:

- Ist einmalig und läuft **15 Minuten** nach dem Erzeugen ab
- Wird immer für _dich_ erzeugt, nie für ein Teammitglied
- Ersetzt jeden Code, den du schon hältst, sodass ein erneuter Klick auf die Schaltfläche den vorherigen ungültig macht
- Liegt nur im Speicher, sodass ein Neustart des Servers noch offene Codes ungültig macht — tippe erneut auf die Schaltfläche

Ein Code, der unbekannt, abgelaufen oder für einen anderen Arbeitsbereich erzeugt wurde, scheitert jedes Mal auf dieselbe, nicht unterscheidbare Weise: „that code is not valid (or has expired)“.

## Automatisch per E-Mail verknüpfen

Trägt dein Slack-Profil eine verifizierte E-Mail, die zu einem Nutzer in Control Center passt, der **bereits Mitglied dieses Arbeitsbereichs** ist, verknüpft die Brücke dich beim ersten Gespräch. Kein Code nötig.

Beide Hälften zählen: Der E-Mail-Abgleich beweist die Identität, aber nur die Mitgliedschaft gewährt Zugang, sodass ein Fremder, dessen E-Mail zufällig auf dem Server liegt, mit nichts verknüpft wird. Die Liste zeigt, wie jede Verknüpfung entstanden ist („per E-Mail zugeordnet“ oder „mit einem Code verknüpft“).

Die automatische Verknüpfung braucht den Scope `users:read.email`. Ohne ihn gibt Slack die Adresse nicht preis, und der Weg über den Code ist der einzige.

## Sehen, wer verknüpft ist

Die Liste gehört zur Verwaltung des Arbeitsbereichs, sie liegt also auf der anderen Hälfte der Oberfläche: **Einstellungen → Arbeitsbereich → Allgemein → Chat-Brücken → Verknüpfte Konten**. Sie führt jedes verknüpfte Mitglied des Arbeitsbereichs auf, mit dem Slack-Konto, auf das es abbildet, und damit, wie die Verknüpfung entstanden ist.

Deinen eigenen Stand siehst du auf deiner Profilseite: Die Zeile **Mein Slack-Konto verknüpfen** liest „Verknüpft mit _your-slack-id_“, sobald du verknüpft bist, und fordert dich zum Verknüpfen auf, solange du es nicht bist.

Die Liste ist ein Live-Abonnement, weil die Änderung auf der anderen Seite geschieht — du tippst den Code in Slack, also kann keine Anfrage aus der App die Antwort zurücktragen.

## Verknüpfung lösen

Klicke in einer Zeile der Liste des Arbeitsbereichs auf **Verknüpfung lösen**.

- Jede Person kann die eigene Verknüpfung lösen
- Nur ein Admin kann die Verknüpfung eines anderen Mitglieds lösen
- Das Lösen widerruft auch jeden noch offenen Verknüpfungscode dieses Mitglieds

Danach kann dieses Slack-Konto keine Agenten mehr steuern, bis es erneut verknüpft wird. Vorhandene Bereiche, Transkripte und Tickets behalten ihre ursprüngliche Zuordnung — das Lösen nimmt vergangene Arbeit nicht zurück.

## Fehlersuche

### Der Bot sagt, ich sei kein Mitglied dieses Arbeitsbereichs

Dein Slack-Konto ist mit einem Nutzer in Control Center verknüpft, aber dieser Nutzer hat in diesem Arbeitsbereich keine Mitgliedschaft. Bitte einen Admin, dich einzuladen; siehe [Multiplayer — Identität, Mitgliedschaft und Präsenz](/de-DE/handbuch/konzepte/multiplayer/).

### Der Bot sagt, meine Rolle sei nur lesend

Die Rollen `viewer` und `guest` können keine Arbeit starten. Ein Admin muss deine Rolle auf `member` oder höher setzen.

### Der Slash-Befehl wird nicht erkannt

Prüfe, dass der Slash-Befehl in Slack existiert und dass du den Befehl schickst, den dir der Einstellungsdialog gezeigt hat — ein Admin kann ihn umbenannt haben, dann zeigt der Dialog den aktuellen Namen.
