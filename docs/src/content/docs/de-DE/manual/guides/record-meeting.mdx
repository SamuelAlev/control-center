Diese Anleitung zeigt, wie du eine Besprechung aufzeichnest und eine von der KI
erzeugte Zusammenfassung bekommst. Wie das funktioniert, steht unter
[Besprechungen und Transkription](/de-DE/handbuch/konzepte/besprechungen/).

## Vor dem Start

- **Warte auf das Sprachmodell und starte den Server danach neu.** Ein normaler
  Start installiert das gewählte ASR-Modell zwingend im Hintergrund nach
  (Parakeet TDT 0.6B v3, der mehrsprachige Standard, etwa 600 MB). Der Server
  löst das Modell **einmal beim Start** auf, deshalb hat der erste Lauf noch
  keine Aufnahmeoperationen, bis du neu startest. Liegt kein Modell auf der
  Platte, schlägt die Aufnahme mit `Could not start
  recording on the host: …` fehl. Ein anderes Build wählst du unter **Einstellungen → Server →
  Sprach- und Meeting-Modelle**. Auch das braucht einen Neustart.
- Erteile die Berechtigung für das **Mikrofon**, wenn das Betriebssystem beim
  ersten Aufnehmen danach fragt.
- Unter **macOS 14.4+** wird das Systemaudio mit Core-Audio-Taps auf Prozesse
  aufgenommen. Es ist kein Treiber zu installieren, aber das Betriebssystem
  fragt ein zweites Mal nach einer Berechtigung zur _Audioaufnahme_. Das ist
  nicht die Bildschirmaufnahme, und die Anzeige für die Bildschirmaufnahme
  leuchtet nie auf. Verweigerst du sie, schlägt der Start mit
  `System-audio capture permission denied.` fehl. Unterhalb von macOS 14.4
  gibt es keine Aufnahme des Systemaudios.
- Unter **Linux** müssen `parecord` (pulseaudio-utils) oder `pw-record`
  (pipewire) auf dem `PATH` liegen. Die Aufnahme startet eines davon gegen
  eine Monitor-Quelle von PipeWire oder PulseAudio. Fehlt beides, schlägt der
  Start mit `No system-audio capture tool found` fehl.

:::caution[Wohin das Audio deiner Besprechung geht]
Aufnahme, Transkription, Echounterdrückung und Diarisierung laufen alle auf
dem Gerät, ohne Cloud-Aufruf. „Gerät“ meint dabei den **Host von cc_server**,
und das ist eine andere Maschine, wenn du den Server entfernt betreibst. Die
fertige Zusammenfassung ist ein gewöhnlicher Agentenlauf: Die Pipeline
`meeting_summary` schickt das vollständige Transkript und deine groben Notizen
an den Modellanbieter, den dieser Agent nutzt. Richte den Agenten auf einen
lokalen Anbieter, wenn das Transkript die Maschine nicht verlassen darf.

Der Aufnahmebildschirm sagt das, während du aufnimmst. Die Entscheidung liegt
also vor dir, bevor es ein Transkript zum Verschicken gibt.
:::

## Eine Aufnahme starten

1. Öffne **Besprechungen** in der Seitenleiste.
2. Klicke auf **Besprechung aufnehmen**. Das HUD der laufenden Aufnahme öffnet
   sich unter `/meetings/record`.

Die Aufnahme startet sofort und nimmt dein Mikrofon plus die Systemausgabe
auf, also die anderen Teilnehmenden. Es gibt keine Modusabfrage und keine
Auswahl der Audioquelle: Der Vor-Ort-Modus mit einem Mikrofon existiert in der
API, hat heute aber keine Oberfläche.

Im Browser funktioniert derselbe Ablauf, mit einem Unterschied: Das
„Systemaudio“ ist eine Bildschirmfreigabe, die eine Audiospur enthalten muss.
Gib einen Browser-Tab (oder den ganzen Bildschirm) frei und aktiviere im
Auswahldialog „Audio des Tabs teilen“ bzw. „Systemaudio teilen“. Safari,
Firefox und die Vollbildfreigabe unter macOS können oft keine liefern.

Das HUD zeigt eine Pegelanzeige, die verstrichene Zeit und auf einer Seite ein
Live-Transkript, das mitwächst.

## Während der Besprechung

- **Mach grobe Notizen** im Notizbereich. Sie werden beim Tippen gespeichert
  und später an den Zusammenfassungsagenten gegeben, also notiere, was das
  Transkript verpassen könnte.
- **Wähle die Notizvorlage** in der Zeile **Aktive Vorlage**. Sie formt die
  Zusammenfassung dieser Besprechung und wird mit der Aufnahme festgehalten,
  sodass ein späterer Neulauf die Vorlage reproduziert, die du hier gewählt
  hast.
- **Pausiere und setze fort** über **Pause**. Solange pausiert ist, stoppt die
  Transkription und der Timer steht.
- Das Transkript kommt mit Sprecher-Tags herein: deine Wörter als **Du**, alle
  im Gespräch als **Andere**, bis die Diarisierung Andere in `Person 1`,
  `Person 2`, … aufteilt, die du umbenennen kannst.

:::note[Ein sehr leiser Sprecher wird möglicherweise nicht transkribiert]
Die Transkription überspringt jedes Audiofenster, das nie über eine
Stille-Schwelle gestiegen ist, ganz ohne Dekodierung. So verbrennt ein leiser
Kanal keine CPU an halluzinierten Token ohne Sprachinhalt. Ein leiser oder
entfernter Sprecher kann dadurch aber kein Transkript erzeugen. Prüfe die
Pegelanzeige früh, nicht erst am Ende.
:::

## Stoppen und zusammenfassen

1. Klicke auf **Stoppen und zusammenfassen**.
2. Control Center bringt dich direkt in die Detailansicht der Besprechung,
   markiert mit **Verarbeitung**: Die Diarisierung teilt den entfernten Kanal
   in einzelne Sprecher, und die Pipeline `meeting_summary` erzeugt die
   Zusammenfassung.
3. Die Besprechung wechselt auf **Fertig**, sobald diese Pipeline fertig ist.
   Du musst nicht darauf warten. Die Detailansicht aktualisiert sich von
   selbst.

## Die Zusammenfassung prüfen

Die Detailansicht der Besprechung (`/meetings/:meetingId`) hat vier Tabs:

| Tab              | Was dort liegt                                                                          |
| ---------------- | --------------------------------------------------------------------------------------- |
| **Notizen**      | Die KI-Zusammenfassung und die aufbereiteten Notizen, aus deinen groben Notizen und dem Transkript |
| **Transkript**   | Das vollständige, nach Sprechern markierte Transkript mit Zeitstempeln                 |
| **Aufgaben**     | Extrahierte Aufgaben, jede mit einer optionalen verantwortlichen Person                |
| **Entscheidungen** | Entscheidungen, die im Gespräch festgehalten wurden                                   |

Von hier aus kannst du:

- **Sprecher umbenennen**: ändere `Person 1` in einen echten Namen. Das gilt
  für das ganze Transkript.
- **Aufgaben abhaken**, wenn du sie erledigt hast.
- **Ticket erstellen** aus einer Aufgabe: Das legt ein neues, nicht
  zugewiesenes Ticket an, betitelt mit der Aufgabe, und verknüpft es mit der
  Zeile. Weise es vom Ticket aus einem Agenten zu (siehe
  [Arbeit an Agenten delegieren](/de-DE/handbuch/anleitungen/tickets-delegieren/)).
- **Zusammenfassung neu erstellen** für einen neuen Durchlauf (zum Beispiel
  nach dem Umbenennen von Sprechern). Dabei wird die Vorlage wiederverwendet,
  die beim Aufnehmen festgehalten wurde. Die aktive Vorlage wählst du unter
  **Einstellungen → Arbeitsbereich → Besprechungen**.

Notizen, Titel, Aufgaben und Entscheidungen lassen sich überall bearbeiten.
**Zusammenfassung neu erstellen** und das Abbrechen einer Besprechung in
Verarbeitung gibt es **nur auf dem Desktop**. Im Browser tun beide
Schaltflächen nichts.

## Direkt aus einem Kalendertermin aufnehmen

Wenn du [einen Kalender verbunden](/de-DE/handbuch/anleitungen/kalender-verbinden/)
hast, kannst du den manuellen Start überspringen. Das gibt es **nur auf dem
Desktop**; der Web-Client lehnt es ab.

1. Öffne den Termin unter **Kalender**.
2. Klicke auf **Aufnehmen und verknüpfen**.

Die Aufnahme startet mit dem Titel des Termins und ist mit ihm verknüpft,
sodass die Notizen und der Kalendereintrag verbunden bleiben.

:::note[Das Löschen einer Besprechung löscht ihr Audio nicht]
Das Löschen einer Besprechung entfernt ihre Zeilen, die aufgezeichneten
WAV-Dateien unter `<dataDir>/meetings/<meetingId>/` bleiben aber auf der
Platte. Es gibt keine Aufbewahrungsrichtlinie, keine Größenobergrenze und
keinen Aufräumlauf. Entferne das Verzeichnis selbst, wenn das Audio eine
Rolle spielt.
:::
