Diese Anleitung zeigt, wie du Tickets anlegst und verwaltest.

## Ein Ticket anlegen

### Über die Oberfläche

1. Klicke in der Seitenleiste des Arbeitsbereichs auf **Tickets**.
2. Drücke **Neues Ticket**.
3. Trag ein:
   - **Titel** — kurze Zusammenfassung. Das ist das einzige Pflichtfeld.
   - **Beschreibung** — Markdown, mit einer Formatierungsleiste.
   - **Status** — **Zu erledigen** (die Vorgabe) oder **Backlog**. Begonnene
     Zustände und Endzustände erreichst du über den Lebenszyklus, nicht beim
     Anlegen.
   - **Priorität** — keine, dringend, hoch, mittel oder niedrig.
   - **Zugewiesen an** — du selbst oder ein Agent im Arbeitsbereich.
   - **Projekt** — optionale Gruppierung.
4. Drücke **Erstellen**, oder aktiviere zuerst **Weitere erstellen**, damit
   der Dialog für schnelles Anlegen offen bleibt.

Im Dialog gibt es keine Anbieterauswahl. Das Ticket entsteht beim aktiven
Ticket-Anbieter des Arbeitsbereichs.

### Über einen Agenten

Frag einen Agenten in einem Bereich:

> Lege ein Ticket an, das den Login-Timeout bei langsamen Verbindungen behebt.

Er ruft das MCP-Tool `create_ticket` auf. Die Priorität an diesem Tool ist eine
**Ganzzahl**, kein Name:

```
create_ticket(
  workspace_id: "...",
  title: "Fix login timeout on slow connections",
  description: "...",
  priority: 2
)
```

| Wert | Priorität |
| ---- | --------- |
| `0`  | Keine     |
| `1`  | Dringend  |
| `2`  | Hoch      |
| `3`  | Mittel    |
| `4`  | Niedrig   |

Nur `workspace_id` und `title` sind Pflicht; `description`, `priority`,
`assignee` (eine Agenten-ID) und `team_id` sind optional. Das Tool ist als
Schreibzugriff der Anbieter-Synchronisierung eingestuft und verlangt vor dem
Lauf deine Freigabe.

## Den Ticket-Status ändern

Tickets folgen diesem Lebenszyklus:

```
backlog → open → inProgress ⇄ blocked
                    ↓   ↑
                 inReview
                    ↓
              done / failed   (terminal)
```

`done`, `failed` und `cancelled` sind Endzustände. `cancelled` ist von jedem
Status erreichbar, der kein Endzustand ist. `done` und `failed` sind von
`inProgress` oder `inReview` erreichbar; `open` kann auch direkt zu `blocked`
wechseln. Die Statusauswahl der Oberfläche listet jeden Status außer `failed`
— Agenten setzen den mit `fail_ticket`.

Zum Ändern nimmst du eines von diesen:

- die Zeile **Status** in der Leiste **Eigenschaften** des Tickets,
- das Untermenü **Status** im Rechtsklickmenü eines Tickets in der Liste,
- den Chip **Status** auf der schwebenden Leiste nach einer Mehrfachauswahl.

:::note[Der Lebenszyklusgraph bindet Agenten, nicht dich]
Jede Statusänderung aus der Oberfläche wird erzwungen und umgeht den Graphen
vollständig — du kannst ein Ticket auf jeden Status setzen, den die Auswahl
anbietet, auch ein `done`-, `failed`- oder `cancelled`-Ticket wieder öffnen.
Die Auswahl bietet `failed` nicht als Ziel. Das Diagramm oben gilt für Agenten
und Automatisierung: Ein unerlaubter Übergang eines MCP-Tools oder eines
Reconcilers wird protokolliert und ignoriert, nicht angewendet.
:::

Statusänderungen senden Domain-Ereignisse (`TicketStatusChanged`,
`TicketCompleted` und weitere), die Pipelines auslösen können. Siehe
[Pipeline-Trigger einrichten](/de-DE/handbuch/anleitungen/pipeline-trigger/).

## Ein Ticket zuweisen

1. Öffne das Ticket.
2. Setze in der Leiste **Eigenschaften** **Zugewiesen an** — auf dich selbst,
   ein anderes Mitglied des Arbeitsbereichs oder einen Agenten.

:::caution[Eine Zuweisung startet keine Arbeit]
Die Zuweisung hält die Zuständigkeit fest und sonst nichts. Sie legt keinen
Bereich an, ändert keinen Status und startet keinen Agenten — `TicketAssigned`
ist ein reines Audit-Signal, hinter dem kein Dispatcher steht. Damit ein Agent
arbeitet, schreibst du ihm in einem Bereich (siehe
[Mit einem Agenten chatten](/de-DE/handbuch/anleitungen/mit-agent-chatten/)).

Die eine Ausnahme: `TicketAssigned` ist ein Ereignistyp, an den du einen
Pipeline-Trigger hängen kannst, damit eine eigene Vorlage auf eine Zuweisung
reagiert.
:::

## Labels hinzufügen

Labels setzt du gesammelt aus der Ticketliste, nicht an einem einzelnen
Ticket — die Leiste **Eigenschaften** hat kein Label-Steuerelement.

1. Fahre über eine Zeile in der Ticketliste und setze ihr Kontrollkästchen.
   Setze so viele, wie du brauchst; sobald etwas ausgewählt ist, erscheint
   eine schwebende Leiste.
2. Öffne in dieser Leiste den Chip **Labels**.
3. Wähle ein Label. Es kommt auf jedes ausgewählte Ticket, dem es fehlt;
   vorhandene Labels werden nie gelöscht. **Labels entfernen** nimmt alle
   weg. Die Auswahl listet Labels, die schon auf einem Ticket im
   Arbeitsbereich liegen. Agenten können über `update_ticket` oder
   `tickets.patch` einen neuen Namen hinzufügen.

## Tickets verknüpfen

Beziehungen liegen auf der Karte **Beziehungen** in der Leiste
**Eigenschaften** des Tickets oder hinter **Verknüpfen mit** im
Rechtsklickmenü der Liste.

1. Öffne das Ticket und finde die Karte **Beziehungen**.
2. Drücke ihr Steuerelement zum Hinzufügen und wähle die Beziehung:

| Beziehung             | Bedeutung                                     |
| --------------------- | --------------------------------------------- |
| **Unteraufgabe von…** | Das andere Ticket ist das übergeordnete       |
| **Übergeordnet zu…**  | Das andere Ticket ist ein Unterticket hiervon |
| **Blockiert von…**    | Dieses Ticket wird vom anderen blockiert      |
| **Blockiert…**        | Dieses Ticket blockiert das andere            |
| **Verwandt mit…**     | Symmetrisch, ohne Richtung                    |
| **Duplikat von…**     | Dieses Ticket ist ein Duplikat des anderen    |

3. Wähle das Ziel-Ticket.

**Dupliziert von** erscheint auf der Karte, nicht in der Auswahl — es ist die
Umkehrung von **Duplikat von** und wird vom anderen Ticket aus gesetzt. Jede
aufgeführte Beziehung lässt sich anklicken, um das verknüpfte Ticket zu
öffnen, und beim Darüberfahren entfernen.

Eltern- und Unteraufgaben-Beziehungen liegen am Ticket selbst und nicht als
Verknüpfungszeilen. Das Löschen eines übergeordneten Tickets kaskadiert
deshalb auf seine Kinder (siehe unten), blockierende und verwandte
Verknüpfungen nicht.

## Mitarbeiter hinzufügen

Mitarbeiter sind eine Besetzung am Ticket — wer beteiligt ist und in welcher
Rolle.

1. Öffne das Ticket.
2. Drücke auf der Karte **Mitarbeiter hinzufügen** das Steuerelement mit
   Person und Plus.
3. Wähle einen Agenten.

Die drei Rollen sind **assignee**, **collaborator** (die Vorgabe) und
**reviewer**. Die Auswahl der Oberfläche listet nur Agenten des
Arbeitsbereichs und schreibt immer die Vorgaberolle; Menschen können als
Zeilen erscheinen, werden in diesem Menü aber nicht angeboten. Das MCP-Tool
`add_ticket_collaborator` nimmt ein `role` an.

Einen Mitarbeiter hinzuzufügen schreibt eine Zeile und veröffentlicht kein
Domain-Ereignis; es gewährt keinen Zugang zu einem Bereich. Damit ein Agent
in einer Unterhaltung sitzt, fügst du ihn stattdessen aus der Kopfzeile des
Bereichs als Teilnehmer hinzu — siehe
[Bereiche](/de-DE/handbuch/anleitungen/bereiche/).

## Ein Ticket löschen

Nutze **Ticket löschen** unten in der Leiste **Eigenschaften**, im
Rechtsklickmenü oder über die Löschaktion der schwebenden Leiste nach einer
Mehrfachauswahl.

:::caution[Löschen ist nur lokal]
Ein Ticket, das von einem externen Tracker kam, wird dort nicht gelöscht —
kein Anbieter unterstützt das — und kann bei der nächsten Synchronisierung
wieder auftauchen. Das Löschen kaskadiert außerdem: die Mitarbeiter des
Tickets und alle Untertickets gehen mit.
:::
