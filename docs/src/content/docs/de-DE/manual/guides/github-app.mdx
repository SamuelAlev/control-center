Diese Anleitung zeigt, wie du deinem Server eine eigene GitHub App gibst. Sie
dauert etwa zwei Minuten, nur der Server-Eigentümer macht das, und pro Server nur
einmal.

:::note[Du brauchst sie vielleicht nicht]
Ist Control Center Connect eingeschaltet, melden sich Personen über die
gemeinsame App von Control Center bei GitHub an, oder über die App, die das
Connect deiner Organisation nutzt. Registriere eine eigene, wenn du **Eigene
Apps verwenden** gewählt hast: Die App des Servers wird nur dann genutzt. Siehe
[Control Center Connect](/de-DE/handbuch/referenz/connect/).
:::

Wie du dich danach mit deinem eigenen Konto anmeldest, steht unter
[GitHub-Integration einrichten](/de-DE/handbuch/anleitungen/github-integration/).

## Was die App macht

Eine Registrierung erfüllt zwei verschiedene Aufgaben:

| Aufgabe | Was sie beantwortet | Warum es zählt |
| --- | --- | --- |
| **Eine Person meldet sich an** | Client-ID und Client-Secret der App | Alle bekommen eigene GitHub-Zugangsdaten, auf dem Server, auf jedem Gerät |
| **Der Server handelt** | ID und privater Schlüssel der App | Agenten, Pipelines, Poller und Bot-Antworten bekommen Tokens für jeweils ein Repository |

Die zweite Aufgabe leiht sich nie die Zugangsdaten einer Person im Ganzen. Jedes
Token, das der Server ausstellt, deckt ein Repository ab und ist auf das
begrenzt, was ein verantwortliches Mitglied dort tun darf. Ein verknüpftes
Repository zu lesen braucht nur die App; alles, was schreibt, braucht ein
Mitglied, das pushen darf. Automatisierung genehmigt nie einen Pull Request.

Die App des Servers gilt nur unter **Eigene Apps verwenden**. Mit Apps von
Control Center oder einem eigenen Connect-Server läuft Connect jede Spur, GitHub
eingeschlossen; die App des Servers bleibt gespeichert, aber ungenutzt, bis du
zurückwechselst. Eine App des Arbeitsbereichs
([Einem Arbeitsbereich eine andere App geben](#einem-arbeitsbereich-eine-andere-app-geben))
gilt weiterhin in jedem Modus. Eine App, der einige
Felder fehlen, ist ein Fehler und kein Rückfall: GitHub-Anmeldungen werden
abgelehnt, bis jedes Feld gesetzt ist.

## Voraussetzungen

- Du bist der **Server-Eigentümer**. Die Karte **Anbieter-Apps** bleibt für alle
  anderen unsichtbar
- Ein GitHub-Konto. Die App wird darunter angelegt
- Eine Serveradresse, die dein Browser erreicht. Die öffentliche URL des Servers
  (oder Loopback, beim eigenen Server eines Desktops) ist der Ort, an den GitHub
  dich zurückschickt

## Mit einem Klick erstellen

1. Geh zu **Einstellungen → Server → Single sign-on** und scrolle zur Karte
   **Anbieter-Apps**
2. Trag im Block **GitHub** optional unter **Organisation (optional)** die
   GitHub-Organisation ein, der die App gehören soll. Lass das Feld leer, um die
   App unter deinem eigenen Konto anzulegen; unter einer Organisation braucht es
   einen Owner dieser Organisation
3. Klicke auf **Meine GitHub-App erstellen**
4. Dein Browser öffnet GitHub mit bereits ausgefüllter App. Klicke auf
   **Create GitHub App**
5. GitHub schickt dich zum Server zurück. Er speichert App-ID, privaten
   Schlüssel, Client-ID und Client-Secret und öffnet dann die
   Installationsseite der App

Nichts wird von Hand kopiert, und der Umwandlungscode geht direkt von GitHub an
deinen Server. Der Link funktioniert einmal und läuft nach zehn Minuten ab; ist
er abgelaufen, klicke erneut auf **Meine GitHub-App erstellen**.

Die App heißt `Control Center <code>` und fordert genau das an, was Control
Center nutzt:

| Berechtigung | Zugriff |
| --- | --- |
| Metadata | Lesen |
| Contents | Lesen und schreiben |
| Pull requests | Lesen und schreiben |
| Issues | Lesen und schreiben |
| Checks, Actions, Commit statuses | Lesen |
| Organization members | Lesen |

Webhooks sind aus: Der Server pollt. Um eine App, die du unter deinem eigenen
Konto angelegt hast, später in eine Organisation zu verschieben, nutze **Transfer
ownership** in den erweiterten Einstellungen der App auf GitHub.

Kontrolle: der GitHub-Block lautet „Der Server kann für sich selbst handeln, und
Personen können sich anmelden.“

## Dort installieren, wo deine Repositories liegen

Eine App, die registriert, aber nicht installiert ist, kann Personen anmelden
und sonst nichts lesen.

1. Wähle auf der Installationsseite, die GitHub geöffnet hat, das Konto oder die
   Organisation, der deine Repositories gehören
2. Wähle **All repositories**, oder die Repositories, die dieser Server sehen soll

Um sie später auf einem anderen Konto zu installieren, geht ein Administrator
des Arbeitsbereichs zu **Einstellungen → Arbeitsbereich → Allgemein**, sucht auf
der Karte GitHub-Identität den Eintrag **GitHub-App-Installationen** und klickt
auf **GitHub-App installieren**. Die Liste zeigt jedes Konto, auf dem die App
installiert ist, und markiert eine gesperrte Installation.

## Diesen Server für eine Organisation autorisieren

Bei der gemeinsamen App von Control Center bedient die Installation einer
Organisation nur die Server, die ihre Administratoren autorisiert haben. Eine
Installation über **GitHub-App installieren** autorisiert den Server, der sie
gestartet hat. Für eine Installation, die schon existiert:

1. Ein Administrator dieser Organisation meldet sich auf diesem Server bei
   GitHub an
2. Er öffnet **Einstellungen → Arbeitsbereich → Allgemein →
   GitHub-App-Installationen**
3. Die Zeile der Organisation zeigt **Nicht autorisiert**. Er klickt auf
   **Diesen Server autorisieren**

Danach zeigt die Zeile **Autorisiert**. Deine eigene App braucht nichts davon:
Jede ihrer Installationen gehört zu deinem Server.

## Stattdessen von Hand registrieren

Die Karte **Anbieter-Apps** nimmt die Werte auch direkt, für eine App, die du
selbst registriert hast:

| Gruppe | Felder |
| --- | --- |
| **Als Server handeln** | **App-ID** und **Privater Schlüssel** (die ganze `.pem`, die Zeilen `BEGIN` und `END` mit) |
| **Personen anmelden** | **Client-ID** und **Client-Secret**. **Callback-URLs** zeigt die URL, die du wörtlich registrierst |
| **Pull-Request-Konversationen** | **Bot-Login**, aufgelöst, wenn du die Verbindung testest |

Registriere die Callback-URL `<server origin>/oauth/github/callback` genau so,
wie die Karte sie zeigt, lass **Expire user authorization tokens** an und vergib
die Berechtigungen aus der Tabelle oben. Klicke auf **Testen**: Es fragt GitHub,
auf welchen Konten die App installiert ist, damit „gespeichert“ und
„funktioniert“ nicht verwechselt werden.

## Über die `.env` des Servers konfigurieren

Für eine Headless- oder skriptgesteuerte Installation belegt der Server jedes
Feld aus seiner `.env`-Datei, und zwar beim ersten Mal, wenn noch kein
gespeicherter Wert vorliegt:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

Setze den Schlüssel in **eine Zeile**: Ein Wert in der `.env` ist eine Zeile,
und `\n` in doppelten Anführungszeichen wird zum Zeilenumbruch. Der Server
verweigert den Start, wenn `GITHUB_APP_PRIVATE_KEY` oder `GITHUB_CLIENT_SECRET`
in seiner Prozessumgebung exportiert ist, wo jeder Kindprozess es lesen könnte;
bewahre sie in der `.env`-Datei auf (in Docker eingehängt unter
`/app/bin/.env`). Das Belegen passiert **einmal je Feld**, eine Änderung unter
Einstellungen macht der nächste Neustart also nicht rückgängig.

## Einem Arbeitsbereich eine andere App geben

Ein Arbeitsbereich kann statt der App des Servers eine eigene nutzen. Ein
Administrator des Arbeitsbereichs geht zu **Einstellungen → Arbeitsbereich →
Allgemein**, wählt auf der Karte **GitHub-Identität** die Option **Eine andere
GitHub-App verwenden** und trägt ID, privaten Schlüssel, Client-ID und
Client-Secret dieser App ein. Mitglieder melden sich dann für diesen
Arbeitsbereich bei dieser App an. Ein Arbeitsbereich mit eigener App fällt nie
auf die App des Servers oder auf Connect zurück: Solange ihre Felder nicht
vollständig sind, wird seine GitHub-Arbeit abgelehnt. Sie gilt unabhängig davon,
wie der Server Personen anmeldet, auch über Connect.

Die Karte **Anbieter-Apps** auf derselben Seite macht dasselbe für Google
Calendar, Linear und die GIF-Suche. Siehe
[Einem Arbeitsbereich eine eigene Linear-Anwendung geben](/de-DE/handbuch/anleitungen/linear-integration/#einem-arbeitsbereich-eine-eigene-linear-anwendung-geben)
und [Einem Arbeitsbereich einen eigenen Google-Client geben](/de-DE/handbuch/anleitungen/kalender-verbinden/#einem-arbeitsbereich-einen-eigenen-google-client-geben).

## Fehlersuche

### Meine GitHub-App erstellen meldet, der Server habe keine Adresse

Der Server hat keine öffentliche URL, zu der ein Browser zurückkehren könnte.
Setze `CC_SERVER_PUBLIC_URL` (oder `--public-url`) und versuche es erneut.

### GitHub meldet, der Link sei abgelaufen

Die einmalige Seite wurde schon benutzt, oder zehn Minuten sind vergangen.
Fang in den Einstellungen neu an.

### Testen sagt, die Zugangsdaten funktionieren, die App ist aber nirgends installiert

Registrierung und Installation sind getrennte Schritte. Öffne die
Installationsseite der App oder nutze **GitHub-App installieren** unter
Arbeitsbereich → Allgemein.

### Testen sagt, der private Schlüssel ließ sich nicht lesen

Füge die ganze `.pem`-Datei ein, inklusive der Zeilen `-----BEGIN` und
`-----END`. Ein Schlüssel `ed25519` oder EC geht nicht: GitHub Apps signieren
mit RSA.

### Ein Mitglied hat sich angemeldet und sieht keine Repositories

Die App ist nicht auf dem Konto installiert, dem die Repositories gehören, oder
die Installation wählt andere Repositories aus. Eine Anmeldung gibt nur frei,
was die App sehen darf.

### Agenten melden, die Installation der GitHub App sei gesperrt

Jemand hat die Installation auf GitHub gesperrt. Heb die Sperre in den
**Settings → Applications → Installed GitHub Apps** des Kontos auf.
