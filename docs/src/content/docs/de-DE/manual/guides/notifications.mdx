Diese Anleitung zeigt, wie du Benachrichtigungen konfigurierst und was jede
Einstellung wirklich steuert.

Benachrichtigungen kommen auf zwei Oberflächen an. Die
**Benachrichtigungszentrale** — die Glocke in der Titelleiste — liest einen
dauerhaften Feed je Arbeitsbereich auf dem Server. **Betriebssystem-Toasts**
sind ein eigener Weg, nur auf dem Desktop, gespeist von Live-Frames, die der
Server zustellt.

:::note[Der Web-Build zeigt keine Betriebssystem-Benachrichtigungen]
Die Toast-Pipeline baut nur der Desktop-Bootstrap. Auf `app.usectrl.dev` gibt
es keine Betriebssystem-Toasts, keine Benachrichtigungstöne und keine
Umgebungs-Bannerleiste. Die Glocke und ihr Verlauf funktionieren weiter, weil
sie den Feed auf dem Server lesen. Der Smartphone-Client hat überhaupt keine
Benachrichtigungsfläche.
:::

## Kategorien ein- oder ausschalten

1. Gehe zu **Einstellungen → Du → Benachrichtigungen**
2. Lass **Benachrichtigungen aktivieren** eingeschaltet
3. Schalte die Kategorien um, die du willst. Es sind genau sechzehn:

| Kategorie               | Auslöser                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------------- |
| Agent abgeschlossen     | Ein Agent hat einen Lauf abgeschlossen                                                      |
| PR veröffentlicht       | Ein Agent hat einen PR veröffentlicht                                                       |
| PR zusammengeführt      | Ein PR wurde zusammengeführt                                                                |
| Neue Nachrichten        | Eine Nachricht ist in einem Bereich angekommen, den du gerade nicht ansiehst               |
| In Pull Request erwähnt | Der Benachrichtigungsabruf von GitHub hat gesehen, dass du in einem PR erwähnt wurdest     |
| Review angefragt        | Dein Review wurde wirklich für einen PR angefragt, der kein Entwurf ist                    |
| Prüfung veraltet        | Neue Commits sind auf einem Pull Request gelandet, den du schon geprüft hast               |
| Bereit zum Mergen       | Ein Pull Request, den du erstellt hast, wurde mergebar oder ist es nicht mehr              |
| Review-Entscheidungen   | Ein Reviewer hat freigegeben, Änderungen angefordert, oder eine Freigabe wurde verworfen   |
| Prüfungen               | CI ist bei einem Pull Request, den du erstellt hast, fehlgeschlagen oder hat sich erholt   |
| Review-Threads          | Jemand hat in einem Thread geantwortet oder ihn aufgelöst, in dem du bist                  |
| Ticket zugewiesen       | Ein Ticket wurde zugewiesen                                                                 |
| Ticket-Status geändert  | Ein Ticket hat den Status geändert                                                          |
| Meeting beginnt bald    | Ein Kalendertermin liegt in deinem Vorlauffenster                                           |
| Kalender getrennt       | Das OAuth-Token eines verbundenen Kalenders ist abgelaufen                                  |
| Gehege-Updates          | Ein Gehege wurde übernommen, zurückgeholt oder ist ausgefallen                              |

Alles außerhalb dieser Liste wird weder gemeldet noch gefiltert. Eine Kategorie
„alles andere“ gibt es nicht.

Diese Einstellungen folgen deinem Benutzer auf jedes Gerät, deshalb bleiben
Smartphone und Laptop auf demselben Stand. Die Lautstärke ist die bewusste
Ausnahme und bleibt am Gerät.

## Quiet hours festlegen

1. Schalte auf derselben Seite **Quiet hours** ein
2. Tippe Start- und Endzeit im Format `HH:MM` (das Standardfenster ist 22:00–08:00)

Solange Quiet hours aktiv sind, werden nicht dringende Benachrichtigungen
verworfen, nicht für eine spätere Zustellung vorgemerkt.

Zwei Kategorien sind **dringend** und kommen immer an. Sie umgehen Quiet hours
_und_ den Fokusmodus: **Meeting beginnt bald** und **PR veröffentlicht**. Eine
Meeting-Warnung, die du erst hinterher siehst, ist wertlos. Genau das ist der
Grund.

## Einen Ton wählen

1. Scrolle zu **Benachrichtigungston**
2. Wähle einen der elf mitgelieferten Töne oder **Keiner**
3. Drücke **Testen**, um ihn zu hören, und stelle die **Lautstärke** mit dem Regler ein

Die App spielt den Ton selbst ab. Die Betriebssystem-Benachrichtigung kommt
stumm an, damit du ihn nicht zweimal hörst.

## Die Vorlaufzeit für Meetings festlegen

1. Scrolle zu **Vorlaufzeit der Erinnerung**
2. Wähle **5**, **10**, **15** oder **30** Minuten

So weit vor einem Kalendertermin wird **Meeting beginnt bald** ausgelöst. Die
Vorgabe ist 5 Minuten.

## Wann eine Benachrichtigung unterdrückt wird

Eine Benachrichtigung wird still verworfen, wenn eines davon zutrifft:

- Benachrichtigungen sind global aus, oder ihre Kategorie ist aus
- Du bist schon auf der Route, zu der sie dich führen würde, und bei einer
  Nachricht schon in diesem Bereich
- Der Fokusmodus ist aktiv und die Kategorie ist nicht dringend
- Quiet hours sind aktiv und die Kategorie ist nicht dringend

Diese Prüfungen gelten für Betriebssystem-Toasts. Die dauerhafte Glocke schreibt
das Ereignis trotzdem auf.

Zwei weitere Unterdrückungen liegen vorgelagert, bei dem, was der Server
überhaupt sendet:

- Eine Nachricht eines anderen **Menschen**, in der du nicht erwähnt wirst,
  wird nie zu einer Benachrichtigung
- Bereiche von Agent zu Agent sind in der Seitenleiste stumm, deshalb erhöhen
  sie nie das Ungelesen-Badge eines Menschen

In einem Bereich gibt es keine stille Ecke: jede Unterhaltung benachrichtigt
gleich, Threads eingeschlossen. Der Lesestatus gilt für den ganzen Bereich,
deshalb summiert sich Ungelesenes über die Unterhaltungen eines Bereichs, statt
je Unterhaltung geführt zu werden.

## Die Benachrichtigungszentrale lesen und leeren

1. Klicke auf die Glocke in der Titelleiste

Das Popover zeigt die jüngste Aktivität, und jeder Eintrag verweist direkt auf
das, worum es geht. Beim Öffnen wird **nicht** alles als gelesen markiert.
Nutze **Alle als gelesen markieren** in der Kopfzeile, oder markiere eine
einzelne Zeile. Der Lesestatus folgt deinem Benutzer über Geräte hinweg.

:::note[Alle löschen ist ein Wasserzeichen, kein Löschen]
**Alle löschen** setzt ein Wasserzeichen je Benutzer, das alles Ältere
ausblendet; die Zeilen bleiben. Getrennt davon behält jeder Arbeitsbereich nur
seine jüngsten **200** Feed-Zeilen und schneidet sie ab, sobald neue ankommen.
Die Glocke abonniert die neuesten **50**, und das Popover listet bis zu **15**
davon. Was darüber hinausgeht, ist weg, unabhängig vom Lesestatus.
:::

## Fehlerbehebung

### Keine Betriebssystem-Benachrichtigungen unter macOS

Die Berechtigung wird beim Start der App nativ angefragt. Hast du sie
abgelehnt, aktiviere Control Center wieder unter Systemeinstellungen →
Mitteilungen. In der App gibt es keinen Hinweis, der die Anfrage erneut
auslöst.

### Auf dem Web-Build kommt nichts an

Das ist so gewollt: Der Web-Build hat keine Pipeline für
Betriebssystem-Benachrichtigungen. Nutze die Glocke.

### Das Glocken-Badge steht auf null, obwohl es neue Aktivität gibt

Bis nach dem Verbinden die Lesemarken da sind, werden Einträge als gelesen
dargestellt, damit das Badge nicht aufblitzt und gleich wieder leer wird. Es
pendelt sich ein, sobald die Marke geladen ist.

### Der Lauf eines Agenten ist fertig, aber nichts hat mich benachrichtigt

Prüfe, ob du nicht schon in dem Bereich warst, in dem es passiert ist. Eine
aktive Route unterdrückt ihren eigenen Betriebssystem-Toast.
