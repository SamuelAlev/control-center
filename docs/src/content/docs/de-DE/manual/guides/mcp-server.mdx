Diese Anleitung zeigt, wie du einen externen MCP-Client — Claude Code, einen
Editor, den MCP Inspector — mit dem eigenen Werkzeugserver von Control Center
verbindest.

Control Center registriert **110** Werkzeuge und stellt sie über das Model
Context Protocol bereit, Protokollversion `2024-11-05`. Ganze
Werkzeugfamilien, die du erwarten könntest, fehlen: Es gibt keine Werkzeuge
für Besprechungen oder den Kalender und keine für Projekte.

## Den Endpunkt finden

Die MCP-Oberfläche teilt sich den Listener von `cc_server`. Einen eigenen
MCP-Port gibt es nicht.

| Endpunkt | Methode  | Zweck                                                    |
| -------- | -------- | -------------------------------------------------------- |
| `/mcp`   | `POST`   | Streamable-HTTP-Transport — darüber spricht ein Client  |
| `/mcp`   | `DELETE` | Eine Sitzung beenden                                     |
| `/sse`   | `GET`    | Benachrichtigungsstrom per Server-Sent Events           |

Eine lokale Standardinstallation erreichst du also unter
`http://127.0.0.1:9030/mcp`.

1. Geh zu **Einstellungen → Server → MCP-Server**
2. Lies die Karte **MCP-Server** — sie zeigt **Läuft** oder **Gestoppt** und
   den Port, auf dem sie lauscht

Bei einer Neuinstallation ist die Oberfläche standardmäßig an. Nur der
Serverinhaber sieht das Token der Karte, und nur er kann den Endpunkt starten
oder stoppen. **Beim App-Start starten** steuert, ob sie nach einem Neustart
wieder hochkommt; **Starten** / **Stoppen** gelten nur für die Sitzung und
ändern diese Einstellung nicht.

Der Server bindet standardmäßig Loopback, deshalb erreichst du den Endpunkt
nur von der Maschine, auf der `cc_server` läuft, außer du hast ihn mit
`--bind any` gestartet.

## Das Token besorgen

Jede Anfrage braucht das MCP-Token des Servers, von jeder Maschine aus, auch von Loopback. Der Server erzeugt es beim ersten Start. Es gibt keine Möglichkeit, es abzuschalten, und keine, es zu leeren.

1. Unter **Einstellungen → Server → MCP-Server** findest du die Zeile **Authentifizierungstoken**
2. Drücke **Token anzeigen** und kopiere es
3. Um es zu ersetzen, drücke **Token erneuern**. Der Server wechselt sofort auf das neue Token, und jeder Client, der noch das alte nutzt, wird abgewiesen, bis du ihm das neue gibst

## Einen Client verbinden

Richte deinen Client auf den Streamable-HTTP-Endpunkt und sende das Token bei jeder Anfrage als `Authorization: Bearer <token>`, auch bei `GET /sse`. Einen anderen Weg gibt es nicht: Ein Token in der URL wird nicht akzeptiert. Die genaue Form der Konfiguration ist Sache deines Clients.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code übernimmt das nicht aus einer `.mcp.json` im Projekt —
projektbezogene MCP-Server liegen hinter einer Freigabeabfrage, die ein
nicht-interaktives `claude -p` nie beantwortet. Übergib die Konfiguration
ausdrücklich:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` sorgt dafür, dass Claude nur diese Datei nutzt, damit
derselbe Server nicht zusätzlich aus dem Projekt entdeckt und doppelt
registriert wird.

Kontrollpunkt: Bitte den Client, seine Werkzeuge aufzulisten. Du solltest
Einträge `mcp__*` sehen, die Tickets, Bereiche, Gedächtnis, den Code-Graph
und die Review abdecken.

## Was der Endpunkt ablehnt

Das Token öffnet jedes Werkzeug des Servers, deshalb lehnt der Endpunkt außerdem alles ab, was eine Webseite gesendet haben könnte, bevor er das Token prüft:

| Anfrage                                                                 | Antwort |
| ----------------------------------------------------------------------- | ------- |
| Ein `Origin`-Header, der keine Seite auf dieser Maschine ist (`http://localhost`, `http://127.0.0.1` oder `http://[::1]`, beliebiger Port) | `403`, "Cross-origin requests are not accepted" |
| Ein `Host`-Header, der weder die Loopback-Adresse und der Port dieses Listeners noch der öffentliche Host-Name des Servers ist | `403`, "Unknown host" |
| Ein `POST`, dessen Body nicht `application/json` ist                    | `415`   |
| Kein Token oder ein falsches                                            | `401`   |

Um MCP über den Host hinaus bereitzustellen, starte den Server mit `--bind any` und sende das Token von der anderen Maschine aus, wobei du den Server über seinen öffentlichen Host-Namen ansprichst.

## Jeden Aufruf auf einen Arbeitsbereich begrenzen

Jedes Werkzeug, das arbeitsbereichsbezogene Daten berührt, verlangt
`workspace_id`. Ein Aufruf ohne das Feld wird abgelehnt, statt gegen irgendeinen
„aktuellen“ Arbeitsbereich aufgelöst zu werden:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

Die ID ist die aus der URL im Browser oder in der App:
`/workspaces/<workspace_id>/…`. Die einzigen Ausnahmen sind Werkzeuge, die
wirklich arbeitsbereichsübergreifend sind, etwa `list_workspaces` und die
Newsfeed-Werkzeuge — der Newsfeed gilt pro Benutzer, und ein Agent hat keinen
eigenen Benutzer, deshalb arbeiten diese Werkzeuge mit den Feeds des
Server-Besitzers.

Werkzeuge mit Repo-Bezug prüfen zusätzlich, dass das Repo mit diesem
Arbeitsbereich verknüpft ist.

## Wissen, was die Oberfläche ablehnt

- **Modus-Gating.** Ein Aufruf wird serverseitig gegen den Modus des Bereichs
  des aufrufenden Agenten aufgelöst. Ein Agent in einem Nur-Lese-Modus
  erreicht ein schreibendes Werkzeug nicht, indem er `space_id` weglässt —
  der Modus wird stattdessen aus seinem aktiven Lauf ermittelt.
- **Schutzregeln für Aktionen.** Verändernde Werkzeuge deklarieren ihre
  Effektklassen und durchlaufen dieselbe Richtlinie wie der Rest des
  Produkts. Siehe
  [Schutzregeln konfigurieren](/de-DE/handbuch/anleitungen/schutzregeln-konfigurieren/).
- **Bestätigung.** Manche zerstörenden Werkzeuge bauen eine
  Bestätigungsnutzlast, die freigegeben werden muss, bevor der Aufruf
  weitergeht.

Der volle Katalog steht in `tools/list`, ohne dass bei der Entdeckung etwas
ausgeblendet wird — ein externer MCP-Client weigert sich, ein Werkzeug
aufzurufen, das nicht in seiner zwischengespeicherten Liste steht. Werkzeuge
zu verstecken macht sie kaputt, statt die Liste aufzuräumen.

## Persönliche MCP-Server bleiben beim Inhaber

Diese Anleitung beschreibt den eigenen Endpunkt von Control Center. Die andere Richtung, also MCP-Server, die Control Center den Agenten übergibt, die es startet, steht unter **Einstellungen → Server → MCP-Server → Externe MCP-Server**. Auf der Maschine des Servers für Claude, Codex, Cursor, Gemini, VS Code, Windsurf, OpenCode oder in einer `.mcp.json` eingerichtete Server werden dort automatisch gefunden.

Diese gefundenen Server stammen aus der Werkzeugkonfiguration des Serverbenutzers und handeln mit dessen Identität und Zugangsdaten, deshalb gehören sie dem Serverinhaber:

- Sie stehen nur in eingebauten Harness-Läufen zur Verfügung, die der Serverinhaber startet oder für die er einsteht, einschließlich der Automatisierung in einem Arbeitsbereich, für den der Inhaber einsteht.
- Der Lauf eines Mitglieds, eine Automatisierung, die an ein Mitglied gebunden ist, und jeder Lauf auf einem Server ohne eingetragenen Inhaber bekommen keine davon. Dort werden die Werkzeuge nicht aufgelistet, können nicht aufgerufen werden und tauchen auch nicht in der Werkzeugsuche auf.
- Dieser Endpunkt listet, ruft oder durchsucht sie nie, für niemanden, auch nicht mit dem Token des Inhabers, und gibt ihre Ressourcen oder Prompts nicht weiter. Ein Agent-CLI, das über MCP zu Control Center findet, etwa Claude Code, bekommt sie deshalb auch nicht über Control Center; es nutzt seine eigene Konfiguration.

MCP-Server, die für den Arbeitsbereich eingerichtet sind, sind davon nicht betroffen.

## Fehlerbehebung

### Der Client sieht keine Werkzeuge

- Prüfe, ob die Karte **MCP-Server** **Läuft** anzeigt
- Prüfe, ob der Port zu deinem `cc_server`-Port passt
- Bei Claude Code prüfe, ob du `--mcp-config` und `--strict-mcp-config`
  übergeben hast

### 401 Nicht autorisiert

Die Anfrage trug kein Token oder ein altes. Kopiere das aktuelle Token aus der Zeile **Authentifizierungstoken** und sende es als `Authorization: Bearer <token>`. Ein Token in der URL wird ignoriert.

### 403 von einem Client, der vorher funktioniert hat

Die Anfrage trug einen `Origin` von einer Webseite oder einen `Host`, auf den der Server nicht antwortet. Rufe den Endpunkt von einem Client aus auf statt von einer Browserseite, über die Loopback-Adresse des Servers oder seinen öffentlichen Host-Namen.

### 415 Nicht unterstützter Medientyp

Sende `POST /mcp`-Bodies als `application/json`.

### Ein Werkzeugaufruf scheitert mit „Missing or invalid argument: workspace_id“

Füge `workspace_id` hinzu. Einen impliziten Arbeitsbereich gibt es nicht.

### Ein Werkzeugaufruf wird als unbekannt abgelehnt

[MCP-Tools](/de-DE/handbuch/referenz/mcp-tools/) listet den Katalog. Rufe den
Namen genau so auf, wie er dort steht.
