Diese Anleitung zeigt dir, wie du Modellanbieter verbindest und festlegst, worauf
ein Agent läuft.

Alles davon liegt auf einer Seite: **Einstellungen → Server → Modellanbieter**. Der
Eintrag in der Seitenleiste darunter lautet „Modellanbieter“, die Überschrift der
Seite lautet „Adapter“.

## Was ein Adapter ist

Ein Adapter ist der _Runner_, der einen Agenten-Turn ausführt. Es gibt zwei, und
die Liste ist fest — eine dritte kannst du nicht hinzufügen.

| Adapter                   | CLI      | Transport                                              |
| ------------------------- | -------- | ------------------------------------------------------ |
| Control Center (built-in) | keine    | Prozessinterne Agentenschleife, spricht über HTTP mit den Anbietern |
| Claude Code               | `claude` | `claude -p --output-format stream-json`                |

Cursor, Codex, Anthropic, OpenAI und der Rest sind **Anbieter** auf dem
eingebauten Adapter, keine eigenen CLIs. Was du _hinzufügen_ kannst, ist ein
weiterer Anbieter — jeder Endpunkt, der mit OpenAI oder Anthropic kompatibel
ist. Das ist der nächste Abschnitt.

:::note[Die Erkennung prüft den Server, nicht deinen Rechner]
Die Karte **Erkannte Runner** listet, was `cc_server` auf dem `PATH` des
_Server-Hosts_ gefunden hat. Bei einem schlanken Client oder im Web ist das
eine andere Maschine als die, auf die du gerade schaust. Installiere die CLI
auf der Maschine, auf der `cc_server` läuft.
:::

## Einen Modellanbieter verbinden

Der eingebaute Adapter braucht mindestens einen verbundenen Anbieter, bevor er
laufen kann. Vierzehn sind im Katalog enthalten.

1. Geh zu **Einstellungen → Server → Modellanbieter**
2. Scrolle zu **Anbieter & Modelle**
3. Suche deinen Anbieter und verbinde ihn:

| Anbieter                                                                                                 | So verbindest du ihn                                                                                                          |
| -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Anthropic                                                                                                | API-Schlüssel. Ein Claude-Pro/Max-Abo ist keine Anmeldung an der Anthropic-API — für diesen Tarif nimm den Claude-Code-Adapter |
| OpenAI, Codex, Cursor                                                                                    | OAuth-Anmeldung im Browser oder ein API-Schlüssel. Codex ist ChatGPT Plus/Pro über das Codex-Responses-Backend, kein gestarteter CLI-Prozess |
| Kimi Code                                                                                                | Nur OAuth im Browser — ein Device-Code-Flow. Es ist ein Pauschaltarif, deshalb gibt es keinen Preis je Token                  |
| OpenRouter, Groq, Google Gemini, DeepSeek, Mistral, xAI, z.ai, z.ai GLM Coding Plan, Moonshot (Kimi API) | API-Schlüssel                                                                                                                 |

Kontrolle: Das Badge der Zeile wechselt auf **Verbunden**, und aufgeklappt
listet sie die Modelle, die dieser Anbieter ausliefert, jedes mit Preis je
Million Token und Kontextfenster.

OAuth-Tokens landen im eigenen Zugangsdatenspeicher des Servers und werden
aufgefrischt, bevor sie ablaufen. Die Zugangsdaten der Anbieter gelten **für
den ganzen Host** — jeder Arbeitsbereich der Installation teilt sie, sie
gehören nicht zu einem einzelnen.

### Eigenen Anbieter hinzufügen

Dafür nimmst du Ollama, LM Studio, vLLM oder eine private Bereitstellung.

1. Unter **Anbieter & Modelle**, bei **Eigene Anbieter**, drücke **Anbieter hinzufügen**
2. Fülle **Name** aus, wähle den **API-Typ** (OpenAI-kompatibel oder
   Anthropic-kompatibel) und gib die **Basis-URL** an (zum Beispiel
   `http://localhost:11434/v1`)
3. Trag einen **API-Schlüssel** ein, wenn der Endpunkt einen braucht, und drücke dann **Anbieter hinzufügen**

Ein eigener Anbieter erscheint in derselben Liste, mit einer Schaltfläche zum
Entfernen, die die mitgelieferten nicht haben.

## Modell für einen Agenten wählen

1. Geh zu **Einstellungen → Arbeitsbereich → Agenten** und wähle den Agenten
2. Wähle auf dem Tab **Einstellungen** den **Adapter**
3. Wähle das **Modell** aus dem Dropdown daneben

Beim eingebauten Adapter setzt sich das Dropdown live aus dem eigenen Katalog
jedes verbundenen Anbieters zusammen. Ein Anbieter ohne gespeicherte
Zugangsdaten steuert null Modelle bei. Ein leeres Dropdown heißt deshalb fast
immer, dass noch nichts verbunden ist, und nicht, dass nichts verfügbar wäre.

:::note[models.dev reichert an und ist nie eine Quelle für IDs]
Der mitgelieferte Katalog [models.dev](https://models.dev) liefert Preis und
Kontextfenster für ein Modell, das schon in der Live-Liste steht. Eine Modell-ID
fügt er nie hinzu. Fehlt ein Modell, das du erwartest, liefert der Endpunkt des
Anbieters es nicht zurück.
:::

Modell-IDs für den eingebauten Adapter sind qualifiziert als `provider/model`
und können eine mit `|` getrennte Fallback-Kette tragen. Bei einem Fallback
werden die Kosten nach dem Modell berechnet, das den Turn tatsächlich bedient
hat, nicht nach dem, das du angefordert hast.

:::note[Ein Agent ohne Adapter läuft auf der eingebauten Schleife]
Jeder Arbeitsbereich legt fünf Agenten an — einen CEO plus `qa`, `architect`,
`engineer` und `librarian` — ohne Adapter und ohne Modell. Die Ausführung fällt
auf **Control Center (built-in)** zurück, nicht auf die Einstellung
**Standard-Runner** auf dieser Seite. Das ist eine Client-Präferenz, die der
Ausführungspfad nie liest. Im Laufprotokoll steht für diese Läufe `cc-harness`,
das Transkript nennt also, was tatsächlich gelaufen ist.

Auch ohne Modell fragt die eingebaute Schleife Anthropic nach seinem
Standardmodell. Ein Agent, der ganz ungesetzt bleibt, läuft also, wenn du ein
Anthropic-Konto verbunden hast, und scheitert sonst mit `No credential for provider "anthropic"`.

Schließt du den Adapter-Schritt im Onboarding ab, werden **alle** Agenten
nachgetragen, denen noch ein Adapter oder ein Modell fehlt — CEO und
Spezialisten, in jedem Arbeitsbereich, der in diesem Moment existiert — mit
dem Paar, das du gewählt hast. Arbeitsbereiche, die du später anlegst, starten
weiter mit allen fünf ungesetzt. Setze Adapter und Modell ausdrücklich bei
jedem Agenten, den du nutzen willst.
:::

## Eine Runner-CLI installieren

Der eingebaute Adapter braucht keine Installation. Für Claude Code
installierst du die CLI **auf dem Server-Host** mit dem eigenen Paketmanager
des Tools, zum Beispiel:

```bash
npm install -g @anthropic-ai/claude-code
```

Drücke danach oben auf der Seite **Aktualisieren**. Jede erkannte Zeile zeigt
die aufgelöste Version und den Pfad, dazu Chips dafür, ob **JSON-Modus** und
**Modellauswahl** unterstützt werden.

Eine externe CLI behält ihre eigenen Zugangsdaten in ihrer eigenen
Konfiguration auf dem Server-Host. Control Center verwaltet sie nicht.

:::caution[Zusätzliche Argumente und Umgebungsvariablen bleiben auf diesem Gerät]
Jede Adapter-Zeile bietet ein Feld **Zusätzliche Argumente** und einen Dialog
**Umgebungsvariablen**. Diese Werte liegen auf deinem Gerät. Der Server liest
argv und env für den Start aus seinem eigenen Einstellungsspeicher. Lege
Anbieterschlüssel auf dem Server ab (OAuth oder das Feld **API-Schlüssel** auf
der Seite Modellanbieter), nicht in diesen beiden Feldern.
:::

## Festlegen, welche Anbieter ein Arbeitsbereich nutzen darf

Die Anbieterregelung gilt pro Arbeitsbereich, und der letzte Treffer gewinnt.

1. Schalte unter **Anbieter & Modelle** den Schalter **Erlaubt** in einer Anbieterzeile aus

Das schreibt eine `deny`-Anweisung für diesen Anbieter in den aktiven
Arbeitsbereich, und seine Modelle fallen für diesen Arbeitsbereich aus dem
Katalog. Schaltest du den Schalter wieder ein, verschwindet die Anweisung.

## Fehlersuche

### Ein Runner zeigt „Nicht gefunden“

- Prüfe, dass die CLI auf dem `PATH` **des Server-Hosts** liegt, nicht nur auf deinem
- Eine über die grafische Oberfläche gestartete Desktop-App startet ihren Server mit einem knappen `PATH`; eine CLI, die nur auf einem Shell-Pfad liegt, kann dafür unsichtbar sein
- Drücke nach der Installation **Aktualisieren**

### Das Modell-Dropdown ist leer

- Der Adapter ist der eingebaute, und kein Anbieter ist verbunden — verbinde einen unter
  **Anbieter & Modelle**
- Oder der Anbieter ist verbunden, dieser Arbeitsbereich lehnt ihn aber über den Schalter ab

### Ein Modell läuft, der Preis steht auf unbekannt

Die Live-Liste der Modelle trägt die ID; Preis und Kontext kommen von models.dev.
Ein ganz neues Modell oder eines von einem eigenen Anbieter hat noch keinen
Katalogeintrag.
