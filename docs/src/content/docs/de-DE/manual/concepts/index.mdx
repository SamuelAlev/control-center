These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/de-DE/handbuch/anleitungen/); when you want to look
something up, go to the [reference](/de-DE/handbuch/referenz/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/de-DE/handbuch/konzepte/arbeitsbereiche/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/de-DE/handbuch/konzepte/agentenmodell/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/de-DE/handbuch/konzepte/ausfuehrungs-lebenszyklus/) — what happens between your message and the agent's first token
- [Modes](/de-DE/handbuch/konzepte/modi/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/de-DE/handbuch/konzepte/tool-kontext/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/de-DE/handbuch/konzepte/code-intelligenz/) — the code graph, language server, structural search and debugger
- [Conversation history](/de-DE/handbuch/konzepte/unterhaltungsverlauf/) — persistence, compaction and forking a transcript

- [Rigs and enclosures](/de-DE/handbuch/konzepte/rigs/) — why agents get disposable VMs instead of your machine, and what the boundary actually is
