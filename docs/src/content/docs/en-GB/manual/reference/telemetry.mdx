Control Center can send **pseudonymised usage events** to an [Umami](https://umami.is) instance. Usage analytics are **off until the server operator switches them on**. The setting belongs to the server and applies to every client connected to it: the desktop app, the web app, the phone and the server itself.

Usage analytics are separate from **Share crash reports**, which is a per-device setting for crash and error diagnostics.

## Who decides

| Switch | Where | Effect |
| --- | --- | --- |
| **Share usage analytics** | Onboarding (sandbox step) and **Settings → Privacy**. Only the server operator can change it; other members see the current value read-only | Server-wide. Stored as `telemetry.usage_analytics` in the server settings. Off unless set to `true` |
| Build type | Automatic | Debug and profile builds don't send. They write each event to the debug log instead |
| `CC_ANALYTICS_DEBUG=1` | `cc_server` environment or its `.env` | Lets debug and profile builds of the server, and of every client connected to it, send for real, for testing. The switch above must still be on |
| `DO_NOT_TRACK=1` | `cc_server` environment | Stops the server's own reporting, whatever the switch says. Clients still follow the switch |
| Demo server | Automatic | The public demo server sends nothing of its own. Visitors cannot change the switch |

Clients read the setting from the server (`telemetry.config`, then live through `telemetry.watch`). Until the answer arrives, events wait in a small in-memory buffer. If the answer is no, the buffer is discarded. Switching analytics off discards anything still queued and stops sending at once, on every client.

## What is never sent

- Message, ticket, review or meeting content, titles, prompts, shell commands and search queries
- Names, logins, email addresses, avatars and display names
- File paths, repository names, branch names, hostnames and URLs (a repository is sent only as a pseudonymised `repo_id`; a meeting link only as its provider)
- Raw identifiers of any kind

Every event goes through a property policy before it leaves the process. Text, paths, URLs, email addresses, IDs that have not been pseudonymised, and strings under keys such as `email`, `*_name`, `path`, `title`, `prompt`, `content` or `token` are dropped rather than sent. A string is sent only if it is a short token from a closed vocabulary, such as an enum value, a version, a locale or a model ID.

## Pseudonymised IDs

IDs are sent, but only as pseudonyms. Every workspace, space, conversation, agent, run, user and device ID is replaced by an HMAC-SHA256 under the install's own secret salt (`telemetry.pseudonym_salt`), truncated to 20 hex characters. The same workspace always reports the same value, so events can be linked and counted, but the raw ID never leaves the install. The salt is created on the server's first start and is never sent to the analytics provider. Deleting the server's data directory creates a new salt and install ID, which unlinks everything recorded before.

## Properties on every event

| Property | Example | Meaning |
| --- | --- | --- |
| `app_type` | `desktop` | `desktop`, `web`, `remote` (the phone) or `server`. Also used as the Umami hostname |
| `app_version` | `0.0.11` | Release version |
| `app_build` | `4baf980` | Short git commit of the build |
| `platform` | `macos` | `macos`, `windows`, `linux`, `web`, or the phone's OS (`ios`, `android`) |
| `locale` | `fr_FR` | UI language |
| `server_mode` | `local` | `local` (desktop running its own server) or `remote` |
| `server_version` | `0.0.11` | Connected server's version, when known |
| `is_demo` | `false` | Whether the client is connected to the public demo |
| `install_id` | pseudonym | The server install |
| `user_id` | pseudonym | The signed-in user, once known |
| `device_id` | pseudonym | The paired device, once known. Also the Umami distinct ID |
| `launch_id` | pseudonym | One app launch, for ordering a session's events |
| `event_seq` | `12` | Position of the event within the launch |

Umami additionally receives the request's IP address, from which it derives country and region without storing the address, plus the User-Agent and the screen size.

## Screen views

Each navigation records a page view whose URL is the **route template**, such as `/workspaces/:workspaceId/spaces/:spaceId`, never the concrete address. The screen name is the template's literal segments, so that example is `workspaces_spaces`. Route parameters ending in `Id` are attached as pseudonymised `*_id` properties, and numeric ones (such as a PR number) as numbers. All other parameters are dropped.

## Delivery

Events are sent one at a time to `<host>/api/send` from an in-memory queue of up to 200 events. A network error, timeout, `429` or `5xx` keeps the event and retries with exponential backoff, from 1 second up to 5 minutes. Any other `4xx` drops it. Nothing is written to disk, so events still queued when the app quits are lost. The queue is flushed when the app goes to the background and when the server shuts down.

## Pointing a build at another instance

The destination is set at build time:

```bash
--dart-define=CC_ANALYTICS_HOST=https://analytics.example.com/
--dart-define=CC_ANALYTICS_WEBSITE_ID=<website uuid>
```

The provider adapter lives in `packages/cc_analytics`. Supporting another analytics service means adding an adapter there. The tracking plan and privacy rules stay the same.
