These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/en-GB/manual/guides/); when you want to look
something up, go to the [reference](/en-GB/manual/reference/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/en-GB/manual/concepts/workspaces/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/en-GB/manual/concepts/agent-model/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/en-GB/manual/concepts/dispatch-lifecycle/) — what happens between your message and the agent's first token
- [Modes](/en-GB/manual/concepts/modes/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/en-GB/manual/concepts/tool-context/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/en-GB/manual/concepts/code-intelligence/) — the code graph, language server, structural search and debugger
- [Conversation history](/en-GB/manual/concepts/conversation-history/) — persistence, compaction and forking a transcript

- [Authorisation](/en-GB/manual/concepts/authorisation/) — roles, the permission catalogue and the audit trail
- [Rigs and enclosures](/en-GB/manual/concepts/rigs/) — why agents get disposable VMs instead of your machine, and what the boundary actually is
