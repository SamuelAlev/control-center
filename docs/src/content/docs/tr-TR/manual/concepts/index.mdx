These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/tr-TR/kilavuz/nasil-yapilir/); when you want to look
something up, go to the [reference](/tr-TR/kilavuz/referans/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/tr-TR/kilavuz/kavramlar/calisma-alanlari/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/tr-TR/kilavuz/kavramlar/ajan-modeli/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/tr-TR/kilavuz/kavramlar/gonderim-yasam-dongusu/) — what happens between your message and the agent's first token
- [Modes](/tr-TR/kilavuz/kavramlar/modlar/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/tr-TR/kilavuz/kavramlar/arac-baglami/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/tr-TR/kilavuz/kavramlar/kod-zekasi/) — the code graph, language server, structural search and debugger
- [Conversation history](/tr-TR/kilavuz/kavramlar/konusma-gecmisi/) — persistence, compaction and forking a transcript
