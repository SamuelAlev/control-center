Control Center는 **가명 처리된 사용 이벤트**를 [Umami](https://umami.is) 인스턴스로 보낼 수 있습니다. 사용 분석은 **서버 운영자가 켜기 전까지 꺼져 있습니다**. 이 설정은 서버에 속하며 서버에 연결된 모든 클라이언트, 즉 데스크톱 앱, 웹 앱, 휴대폰, 그리고 서버 자체에 적용됩니다.

사용 분석은 크래시와 오류 진단을 위한 기기별 설정인 **크래시 리포트 공유**와는 별개입니다.

## 누가 결정하는가

| 스위치 | 위치 | 효과 |
| --- | --- | --- |
| **사용 분석 공유** | 온보딩(샌드박스 단계)과 **설정 → 개인정보**. 서버 운영자만 변경할 수 있으며, 다른 멤버에게는 현재 값이 읽기 전용으로 표시됩니다 | 서버 전체에 적용됩니다. 서버 설정에 `telemetry.usage_analytics`로 저장됩니다. `true`로 설정하지 않으면 꺼져 있습니다 |
| 빌드 유형 | 자동 | debug 및 profile 빌드는 전송하지 않습니다. 대신 각 이벤트를 디버그 로그에 기록합니다 |
| `CC_ANALYTICS_DEBUG=1` | `cc_server` 환경 또는 그 `.env` | 테스트를 위해 서버와 서버에 연결된 모든 클라이언트의 debug 및 profile 빌드가 실제로 전송하도록 허용합니다. 이 경우에도 위의 스위치가 켜져 있어야 합니다 |
| `DO_NOT_TRACK=1` | `cc_server` 환경 | 스위치 값과 관계없이 서버 자체의 전송을 중지합니다. 클라이언트는 계속 스위치를 따릅니다 |
| 데모 서버 | 자동 | 공개 데모 서버는 자체적으로 아무것도 보내지 않습니다. 방문자는 스위치를 변경할 수 없습니다 |

클라이언트는 서버에서 설정을 읽습니다(`telemetry.config`로 읽은 뒤 `telemetry.watch`로 실시간 반영). 응답이 도착할 때까지 이벤트는 작은 메모리 버퍼에서 대기합니다. 응답이 '아니요'이면 버퍼는 폐기됩니다. 스위치를 끄면 아직 대기열에 있는 항목이 모두 폐기되고, 모든 클라이언트에서 전송이 즉시 중지됩니다.

## 절대 전송되지 않는 항목

- 메시지, 티켓, 리뷰, 회의의 내용, 제목, 프롬프트, 셸 명령, 검색어
- 이름, 로그인, 이메일 주소, 아바타, 표시 이름
- 파일 경로, 저장소 이름, 브랜치 이름, 호스트 이름, URL(저장소는 가명 처리된 `repo_id`로만, 회의 링크는 제공업체 이름으로만 전송됩니다)
- 모든 종류의 원시 식별자

모든 이벤트는 프로세스를 벗어나기 전에 속성 정책을 거칩니다. 텍스트, 경로, URL, 이메일 주소, 래핑되지 않은 ID, 그리고 `email`, `*_name`, `path`, `title`, `prompt`, `content`, `token` 같은 키 아래의 문자열은 전송되지 않고 폐기됩니다. 문자열은 enum 값, 버전, 로캘, 모델 ID처럼 닫힌 어휘에 속한 짧은 토큰인 경우에만 전송됩니다.

## 가명 ID

ID는 전송되지만 가명으로만 전송됩니다. 워크스페이스, 스페이스, 대화, 에이전트, 실행, 사용자, 기기의 각 ID는 설치본 고유의 비밀 솔트(`telemetry.pseudonym_salt`)를 사용한 HMAC-SHA256으로 대체되고, 16진수 20자로 잘립니다. 같은 워크스페이스는 항상 같은 값을 보고하므로 이벤트를 연결하고 집계할 수 있지만, 원시 ID는 설치본 밖으로 나가지 않습니다. 솔트는 서버를 처음 시작할 때 생성되며 분석 제공업체로 전송되지 않습니다. 서버의 데이터 디렉터리를 삭제하면 새 솔트와 설치 ID가 생성되어, 이전에 기록된 모든 데이터와의 연결이 끊어집니다.

## 화면 조회

탐색할 때마다 URL이 **경로 템플릿**인 페이지 조회가 기록됩니다. 예를 들어 `/workspaces/:workspaceId/spaces/:spaceId`처럼 기록되며, 구체적인 주소는 기록되지 않습니다. 화면 이름은 템플릿의 리터럴 세그먼트로 구성되므로 이 예에서는 `workspaces_spaces`입니다. `Id`로 끝나는 경로 매개변수는 가명 처리된 `*_id` 속성으로, 숫자 매개변수(PR 번호 등)는 숫자로 첨부됩니다. 그 밖의 매개변수는 모두 폐기됩니다.

| `skill_updated` | `workspace_id`, `skill_id`, `origin`, `scan_verdict` | 워크스페이스 스킬이 설치, 업데이트되거나 디스크에서 변경되었을 때 |
| `calendar_auth_expired` | `workspace_id` | 캘린더 연결에 다시 로그인해야 할 때 |
| `calendar_meeting_starting_soon` | `workspace_id`, `calendar_event_id`, `has_meeting_link`, `lead_s` | 캘린더 이벤트가 곧 시작될 때 |
| `budget_threshold_crossed` | `scope_type`, `scope_id`, `spent_cents`, `budget_cents`, `hard_stop` | 지출이 예산 임계값을 넘었을 때 |
| `pull_request_review_requested` | `workspace_id`, `repo_id` | 추적 중인 PR에 리뷰가 요청되었을 때 |
| `pull_request_review_decision_changed` | `workspace_id`, `repo_id`, `decision`, `reviewers_remaining` | 추적 중인 PR의 리뷰 결정이 바뀌었을 때 |
| `external_pull_request_merged` | `workspace_id`, `repo_id` | 에이전트가 열지 않은 PR이 연결된 저장소에서 병합되었을 때 |

## 전송

이벤트는 최대 200개를 담는 메모리 내 대기열에서 `<host>/api/send`로 한 번에 하나씩 전송됩니다. 네트워크 오류, 타임아웃, `429` 또는 `5xx`가 발생하면 이벤트를 유지한 채 1초부터 최대 5분까지 지수 백오프로 재시도합니다. 그 밖의 `4xx`는 이벤트를 폐기합니다. 디스크에는 아무것도 기록하지 않으므로, 앱이 종료될 때 대기열에 남아 있던 이벤트는 사라집니다. 대기열은 앱이 백그라운드로 전환될 때와 서버가 종료될 때 비워집니다.

## 빌드가 다른 인스턴스를 가리키게 하기

전송 대상은 빌드 시점에 고정됩니다.

```bash
--dart-define=CC_ANALYTICS_HOST=https://analytics.example.com/
--dart-define=CC_ANALYTICS_WEBSITE_ID=<website uuid>
```

제공업체 어댑터는 `packages/cc_analytics`에 있습니다. 다른 분석 서비스를 지원하려면 그곳에 어댑터를 추가하면 됩니다. 추적 계획과 개인정보 보호 규칙은 그대로 유지됩니다.
