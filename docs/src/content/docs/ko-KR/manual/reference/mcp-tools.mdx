`cc_server`는 하나의 MCP(JSON-RPC 2.0) 도구 레지스트리를 호스팅하며, 메인 서버 포트(기본값 `9030`)에서 `POST /mcp`와 `GET /sse`로 제공되고 프로토콜 버전은 `2024-11-05`입니다. 데스크톱, 웹 빌드, 외부 MCP 클라이언트, 내장 에이전트 런타임 등 모든 클라이언트가 같은 레지스트리에 도달합니다. 외부 MCP 서버는 동적 계층으로서 같은 레지스트리에 브리지될 수 있습니다.

## 레지스트리 규모

| 항목                                                                      | 개수 |
| ------------------------------------------------------------------------- | ----- |
| `cc_server`가 등록하는 도구                                               | 110   |
| `packages/cc_mcp`에서                                                    | 108   |
| `packages/cc_mcp_client`에서(도구 탐색)                                   | 2     |
| 기본 레지스트리에 등록됨(`server_mcp_registry.dart`)                      | 63    |
| 부팅 후 서비스가 올라오면서 등록됨(`cc_server_runtime.dart`)              | 47    |
| 기본 레지스트리 63개 중 코드 그래프 저장소에 조건부인 것                  | 5     |

다섯 개의 코드 그래프 도구는 호스트가 `buildServerMcpRegistry`에 코드 그래프 저장소를 넘길 때만 등록됩니다. `cc_server`는 항상 하나를 넘기므로, 배포된 바이너리에서는 110개가 모두 살아 있습니다.

전체 레지스트리는 검색 게이팅 없이 `tools/list`에 게시됩니다. 티켓 편집은 타입이 지정된 도구입니다.

:::note[외부 클라이언트는 항상 전체 카탈로그를 봅니다]
`tools/list`는 결코 줄어들지 않습니다. MCP 클라이언트는 도구 이름을 자체 캐시된 목록 사본과 대조해 검증하고, 서버에 묻지도 않은 채 목록에 없는 것은 무엇이든 거부합니다. 따라서 거기서 숨겨진 도구는 조용한 것이 아니라 도달할 수 없는 상태입니다.

**내장 하네스**는 다릅니다. 요청마다 정의의 상주 부분집합만 적재하고 나머지는 처음 사용할 때 가져오는데, 이는 하네스 측 동작이며 이 레지스트리를 바꾸지 않습니다. [도구 컨텍스트와 프롬프트 캐싱](/ko-KR/매뉴얼/개념/도구-컨텍스트)을 참고하십시오.
:::

:::note[모든 도구 클래스가 등록됩니다]
`packages/cc_mcp/lib/src/tools/` 아래의 소스 파일은 에이전트가 호출할 수
있는 도구입니다. 새 도구 클래스가 아무 데서도 생성되지 않으면
`packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart`가
빌드를 실패시킵니다.
:::

## 공통 매개변수

### `workspace_id`

워크스페이스 범위 데이터를 다루는 모든 도구에서 **필수**입니다. `workspace_id`가 없거나 유효하지 않으면 명시적인 오류가 반환되고, 대상 엔터티의 워크스페이스와 일치하지 않는 값은 조용히 무시되지 않고 거부됩니다. 진정으로 전역인 도구, 즉 `list_workspaces`와 여섯 개의 뉴스피드 도구(`list_feeds`, `list_articles`, `get_article`, `set_article_read`, `set_article_saved`, `refresh_feeds`)에서는 생략하십시오. 이들은 서버 소유자의 사용자별 피드 목록을 사용합니다. 탐색 도구(`search_tool_bm25`, `list_my_tools`)는 대화 모드별로 호출 가능성을 분류할 수 있도록 이 값을 선택적으로 받습니다. 서버가 에이전트를 디스패치할 때는 워크스페이스가 서버 측에서 강제되므로, 에이전트가 외부 id를 넘겨 다른 워크스페이스에 도달할 수 없습니다.

## 도구 탐색

둘 다 `cc_mcp`가 아니라 `cc_mcp_client`에서 오며, 둘 다 모드 가드를 참조하므로 _현재_ 대화 모드에서 호출 가능한 것을 보고합니다.

| 도구               | 설명                                                                                                                        |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `search_tool_bm25` | 키워드로 도구 카탈로그를 검색하고, 일치하는 도구와 그 인자 스키마, 그리고 각각이 지금 호출 가능한지 여부를 반환합니다        |
| `list_my_tools`    | 이 대화에서 지금 호출 가능한 도구를 해당 모드로 필터링해 나열합니다                                                          |

세 번째 탐색 도구인 **`search_tools`**는 내장 하네스 안에만 존재하며 이 MCP 레지스트리의 일부가 아닙니다. 이것은 실행 자체의 도구 표면의 순위를 매기고, `search_tool_bm25`와 달리 찾아낸 것의 스키마를 **적재**하므로 에이전트가 다음 턴에 일치 항목을 호출할 수 있습니다. 하네스의 에이전트는 이것을 우선해야 하며, MCP 클라이언트에게는 `search_tool_bm25`가 있습니다.

## 에이전트 간 메시징과 위임

에이전트는 스페이스를 통해 서로 대화합니다(영속적이며 로스터에 표시됨). `ask_agent`는 필수 타임아웃이 있는 요청/응답이고, `delegate_task`는 깊이 상한, 순환 감지, 예산 봉투, 자율성 상한으로 서버 측에서 보호됩니다.

| 도구            | 설명                                                                                            |
| --------------- | ------------------------------------------------------------------------------------------------ |
| `send_to_agent` | `to_agent_id` 또는 정확한 `to_agent_name`으로 지정해 다른 에이전트에 일방향 메시지를 보냅니다   |
| `ask_agent`     | 다른 에이전트에 질문하고 답변을 기다리거나 타임아웃됩니다                                        |
| `delegate_task` | 작업을 추적되는 자식 티켓으로 다른 에이전트에 위임합니다                                          |
| `consult_agent` | 스킬 기준으로 가장 잘 맞는 전문가를 스페이스에 추가하고 집중된 브리프로 디스패치합니다          |
| `todo_read`     | 이 대화의 영속 작업 체크리스트를 읽습니다                                                        |

## 스킬 도구

모든 설치와 업데이트는 스킬 콘텐츠가 디스크나 에이전트 프롬프트에 도달하기 전에 실패 시 닫히는 검사 관문을 통과합니다.

| 도구                 | 설명                                                                        |
| -------------------- | ---------------------------------------------------------------------------- |
| `list_skills`        | 워크스페이스에서 사용할 수 있는 스킬 슬러그를 나열합니다                     |
| `create_skill`       | 마크다운 콘텐츠로 새 스킬을 생성합니다                                       |
| `install_skill`      | 핀으로 고정한 ref에서 GitHub 저장소의 스킬 디렉터리 전체를 설치합니다        |
| `update_skill`       | 설치된 GitHub 스킬을 새 ref로 업데이트하며, 다시 검사하고 핀을 다시 고정합니다 |
| `list_skill_updates` | 더 새 버전을 사용할 수 있는 스킬을 나열합니다                                |
| `verify_skills`      | 잠긴 스킬을 디스크상의 콘텐츠 해시와 대조해 검증합니다                        |
| `pin_skill`          | 디스크에 있는 기존 스킬을 해시해 `skills-lock.json`에 기록합니다            |

## 인클로저(리그) 도구

실행 안에서 일회용 머신 — 인클로저 안의 브라우저나 Linux 데스크톱, Android
에뮬레이터 또는 iOS 시뮬레이터 — 을 조작합니다. 부팅 후 무조건 등록됩니다.
머신이 실제로 부팅될 수 있는지는 도구가 호출마다 답하는 프로브 질문입니다.
한 대화에서 반복 호출하면 하나의 머신을 재사용하며, 스크린샷은 결과당 한 장의
이미지 예산으로 이미지 콘텐츠로 반환되고, 추출된 페이지/UI 콘텐츠는 신뢰할 수
없는 데이터로 격리됩니다. 네 개의 사용 도구와 `rig_close`는 `enclosureControl`
[액션 클래스](/ko-KR/매뉴얼/개념/가드레일/)를 선언하므로(사용 도구는
`networkEgress`와 `processSpawn`도 선언하고, `mobile_use`와 `ios_use`는
`packageInstall`도 선언합니다), 읽기 전용 모드에서는 이들을 거부합니다.
`rig_list`는 아무것도 선언하지 않으며, 워크스페이스 상태만 읽습니다. 표면별
전체 동사 어휘는 [리그 레퍼런스](/ko-KR/매뉴얼/레퍼런스/리그/#action-verbs)에
있습니다.

| 도구           | 설명                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| `computer_use` | 인클로저 VM의 Linux 데스크톱을 조작합니다: 이동, 클릭, 드래그, 스크롤, 입력, 크기 조정, 클립보드, 스크린샷 |
| `browser_use`  | 헤드리스 Chromium, Firefox 또는 WebKit(`engine`)을 조작합니다: 탐색, 클릭, 채우기, 추출(a11y/DOM/콘솔), 클립보드, 스크린샷 |
| `mobile_use`   | ADB로 Android를 조작합니다: 검사/입력, 스크린샷, 앱 설치/시작/중지/초기화/설치 해제, 딥 링크, argv 형태의 기기 명령 |
| `ios_use`      | WebDriverAgent/CoreSimulator를 통해 iOS 시뮬레이터를 조작합니다: 검사/입력, 스크린샷, 앱 설치/시작/중지/설치 해제, 딥 링크, argv 형태의 시뮬레이터 프로세스 |
| `rig_list`     | 워크스페이스의 리그를 표면, 상태, 디스플레이 크기, 컨트롤러와 함께 나열합니다                          |
| `rig_close`    | 리그를 파괴하고 그 리그가 소유한 머신 상태를 버립니다                                                   |

## MCP로 노출되지 않는 것

캘린더와 회의에는 MCP 도구가 없습니다. 에이전트는 여러분의 캘린더, 회의, 전사, 실행 항목, 결정을 읽을 수 없습니다. 실행 항목과 결정을 만들어 내는 요약은 에이전트가 호출할 수 있는 도구가 아니라 내장 [`meeting_summary` 파이프라인](/ko-KR/매뉴얼/개념/회의/)으로 실행됩니다.

## 모드별 도구 게이팅

게이팅은 하나의 표(`ModeToolPolicy`)에서 두 번 적용됩니다. Claude Code 어댑터의 MCP 디스패처에서 한 번, 내장 하네스 레지스트리에서 한 번입니다. 차단된 호출은 그 이유를 반환합니다.

| 모드          | 도구 표면                                                                                                                                                                                                                              |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`        | 등록된 모든 도구, 허용 목록 없음                                                                                                                                                                                                      |
| `plan`        | 선별된 허용 목록입니다. 워크트리 쓰기와 `create` / `assign` / `delegate` 티켓 동사는 허용되지 않지만, 메모리, 아티팩트, 할 일, `submit_plan`, `exit_plan_mode`, 그리고 디스패치된 티켓의 티켓 완료 동사는 허용됩니다                    |
| `review`      | 선별된 허용 목록입니다: 리뷰 참여, 커뮤니케이션, 읽기 전용 컨텍스트 페처, 그리고 `create_ticket`과 `assign_ticket`을 포함한 전체 티켓 동사 집합                                                                                          |
| `orchestrate` | 선별된 허용 목록입니다: 조사 및 읽기 도구와 `propose_orchestration`, `create_playbook`, `run_playbook`. 채용, 분해, 티켓 완료는 승인 후 결정적으로 일어나며 결코 실행 도중에 일어나지 않습니다                                         |

허용 목록과 무관하게 모든 모드에서 허용되는 것:

| 집합             | 도구                                                                                                                                                                                                                                                           |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 메모리와 아티팩트 | `search_memory`, `propose_fact`, `propose_policy`, `supersede_fact`, `supersede_policy`, `record_observation`, `update_my_notes`, `get_my_notes`, `list_memory_domains`, `list_policies`, `publish_artifact`, `revise_artifact`, `list_artifacts`, `get_artifact` |
| 코드 그래프       | `search_code`, `code_symbol`, `code_callers`, `code_callees`, `code_impact`                                                                                                                                                                                     |
| 실행 역학         | `search_tool_bm25`, `list_my_tools`, `todo_write`, `todo_read`                                                                                                                                                                                                  |

허용 목록에 있다고 해서 도구가 호출 가능해지는 것은 아니며, 반대도 마찬가지입니다. 운영자에게 묻는 기능은 **하네스** 도구(`ask_user`)이므로 이 MCP 카탈로그에는 아예 나타나지 않습니다.

## 승인이 필요한 도구

도구는 `requiresApproval`을 선언할 수 있습니다. 그러면 디스패처가 `ApprovalPayload`를 만들어 도구가 실행되기 전에 `ConfirmationPort`로 표면화합니다. `cc_server`가 그 포트를 연결하므로 관문이 살아 있습니다.

이를 선언한 등록 도구: `create_ticket`, `update_ticket`, `assign_ticket`, `reassign_ticket`, `close_ticket`, `ticket_relation`, `create_goal`, `update_goal_progress`, `create_approval`, `decide_approval`, `comment_approval`, `create_work_product`, `save_work_product_revision`, `create_runtime_profile`, `install_skill`, `update_skill`.

이와 별개로, 통합 액션 가드레일은 비어 있지 않은 `ActionClass` 집합을 선언하는 모든 도구를 게이팅합니다. 승인자가 연결되지 않은 `prompt` 결정은 거부됩니다. [가드레일](/ko-KR/매뉴얼/개념/가드레일/)을 참고하십시오.

## 뒤에 도구가 없는 기능

제품의 모든 기능을 에이전트가 도달할 수 있는 것은 아닙니다. 다음은 도구가
아예 없으므로, 다른 곳에서 참조된 것을 본 이름은 "unknown tool"을 반환합니다:

| 기능                             | 대신 어디에 있는가                                                                                            |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 에이전트 채용, 해고, 편집        | 에이전트 UI. `hire_agent` / `fire_agent` / `update_agent` 도구는 없습니다                                     |
| 워크스페이스 생성                | RPC를 통한 `workspace.upsert`. 소유권을 시드하고 각인합니다                                                    |
| 프로젝트(생성 / 나열 / 업데이트 / 파일링) | 티켓 UI. 프로젝트는 운영자 표면입니다 — [프로젝트](/ko-KR/매뉴얼/사용-가이드/프로젝트/)를 참고하십시오            |
| 운영자에게 차단 질문하기         | MCP가 아니라 **하네스** `ask_user` 도구입니다. 대화에 양식을 렌더링하고 답변을 기다리며 차단합니다              |
| 에이전트별 진단                  | 없습니다. `doctor`가 없습니다 — [에이전트 진단](/ko-KR/매뉴얼/사용-가이드/에이전트-진단/)을 참고하십시오         |
| 캘린더와 회의                    | 사람 클라이언트 전용 RPC(위 참조)                                                                              |
