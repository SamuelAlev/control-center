Control Center Connect는 자체 앱을 등록하지 않은 서버를 위해 프로바이더 로그인을
실행합니다. 서버는 Control Center의 호스팅 Connect, 조직이 운영하는 Connect([Connect
서버 실행](/ko-KR/매뉴얼/사용-가이드/connect-서버-실행/)) 중 하나를 쓰거나, 아무것도 쓰지
않습니다. 이 선택은 **설정 → 서버 → 싱글 사인온 → Control Center Connect**,
`cc_server connect`, 또는 `CC_CONNECT_URL`에서 합니다.

## 레인

각 프로바이더는 하나의 레인입니다. **내 앱 사용**(또는 아직 선택하지 않은 경우) 아래에서는 서버 자체 앱이 완전히 구성되어 있으면 레인은 그 앱에서 실행되고, 아니면 사용할 수 없습니다. Control Center 또는 사용자 지정 Connect를 쓰면 Connect가 제공하는 모든 레인을 Connect가 담당합니다. 서버 자체 앱은 저장만 되며 로그인, 서버 자동화, 서버가 보고하는 상태에 쓰이지 않습니다. 워크스페이스 자체 앱은 모든 모드에서 우선합니다.

| 레인         | 자체 앱에 필요한 것                                 | Connect를 거칠 때                                                |
| ------------ | --------------------------------------------------- | ---------------------------------------------------------------- |
| `github`     | 앱 ID, 비공개 키, 클라이언트 ID, 클라이언트 시크릿   | 사람들이 공유 GitHub App에 로그인합니다                          |
| `google`     | 클라이언트 ID와 클라이언트 시크릿                   | 사람들이 Google Calendar를 연결합니다                            |
| `linear`     | 클라이언트 ID                                       | 사람들이 Linear에 로그인합니다                                   |
| `linear_app` | 클라이언트 ID                                       | 워크스페이스 관리자가 Linear의 앱 액터를 연결합니다              |
| `slack`      | 워크스페이스 자체 Slack 앱 연결                     | 워크스페이스 관리자가 Slack을 공유 Slack 앱에 연결합니다         |
| `klipy`      | `KLIPY_APP_KEY`                                     | Connect가 프록시하는 GIF 검색                                    |

일부만 구성된 자체 앱은 그 레인을 오류로 만들며, 결코 조용히 Connect로 폴백하지
않습니다. 자체 GitHub App을 쓰는 워크스페이스(**설정 → 워크스페이스 → 일반 → GitHub
신원**)는 GitHub에 대해 결코 Connect를 거치지 않습니다. 자체 Google, Linear 또는 Klipy 앱을 쓰는 워크스페이스(**설정 → 워크스페이스 → 일반 → 프로바이더 앱**)는 해당 프로바이더에 대해 서버 앱이나 Connect를 거치지 않습니다. Connect 선택을 바꿔도 워크스페이스 자체 앱에서 로그아웃되는 사람은 없습니다.

## Connect가 보는 것과 결코 보지 않는 것

| Connect가 보는 것                                                                  | Connect가 결코 보지 않는 것                                                          |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 서버의 설치 ID와 요청 서명                                                         | 소스 코드, 저장소 내용, diff, 풀 리퀘스트 텍스트                                     |
| 로그인 중, 로그인한 프로바이더 계정                                                | 티켓, 대화 기록, 워크스페이스 데이터베이스의 어떤 것                                 |
| 자격 증명이 속한 워크스페이스. 봉인 안의 불투명한 ID로서입니다                     | GitHub App 비공개 키. 저장소 토큰은 사람의 로그인에서 나옵니다                       |
| 저장소 하나에 대한 GitHub 토큰이 발급되는 저장소                                   | 저장된 상태의 갱신 토큰. 서버가 보관하는 봉인 안에만 존재합니다                      |
| 서버에 바인딩된 GitHub 설치 ID                                                     | Linear 시크릿. 서버가 Linear의 코드를 직접 교환합니다                                |
| Klipy를 프록시할 때의 GIF 검색어                                                   | 비밀번호, 페어링 키, 모델 프로바이더 키                                              |
| Slack 이벤트 참조(팀, 채널, 메시지 id)와 슬래시 명령 텍스트                        | Slack 메시지 텍스트. Connect는 도착 즉시 이를 버리고, 서버가 Slack에서 메시지를 직접 읽습니다 |

Connect는 수명이 짧은 상태(준비 중인 로그인, 논스, 캐시)를 최대 15분 동안 보관합니다.
유일하게 오래 남는 기록은 설치 바인딩입니다. 어떤 서버가 어떤 GitHub 설치를 쓸 수 있는지,
각 Slack 팀이 어느 서버에 묶여 있는지입니다. 오류에는 코드만 담기며 프로바이더의 응답은
결코 담기지 않고, 로그에는 설치 ID가 키가 적용된 해시로만 기록됩니다.

## 모드

| 모드     | 설정                                      | 동작                                                                                   |
| -------- | ----------------------------------------- | -------------------------------------------------------------------------------------- |
| 미설정   | 새 서버                                   | 어떤 레인도 Connect를 쓰지 않습니다. 온보딩에서 서버 소유자에게 선택을 요청합니다      |
| `hosted` | **Control Center의 앱 사용**              | 오프라인으로 서명된 구성을 가진 `https://connect.usectrl.dev`. 서버 자체 앱은 사용되지 않습니다 |
| `custom` | **사용자 지정 Connect 서버 사용**         | HTTPS URL(루프백에서만 `http`)의 Connect. 처음 사용할 때 신뢰합니다. 서버 자체 앱은 사용되지 않습니다 |
| `off`    | **내 앱 사용**                            | 어떤 레인도 Connect를 쓰지 않습니다. 자체 앱만 사람들을 로그인시킵니다                 |

서버의 환경이나 `.env`에 있는 `CC_CONNECT_URL`은 선택을 잠급니다. 값은 `hosted`, `off`,
또는 Connect URL입니다. 그러면 설정에 잠금이 표시되며 바꿀 수 없습니다.

이 빌드에는 호스팅 구성 키가 컴파일되어 있지 않으므로, 호스팅 모드는
`hosted_unprovisioned`를 보고하고 어떤 레인도 제공하지 않습니다. 자체 앱과 사용자 지정
Connect는 작동합니다.

서버는 Connect의 구성을 최대 10분마다 읽고, 각 호출에서 최대 5초를 기다립니다. Connect에
연결할 수 없으면 마지막으로 유효했던 구성을 계속 사용하고, 설정에 그것이 오래되었다고
표시합니다.

## 설치 신원

| 항목              | 무엇인가                                                                                                       |
| ----------------- | -------------------------------------------------------------------------------------------------------------- |
| 설치 키           | 서버 시크릿 파일의 32바이트 시드(`connect_install_key`). 기기 페어링 키와는 별개입니다                          |
| Connect별 키      | 시드와 Connect 주소에서 파생된 Ed25519 키. Connect에 보내는 모든 요청은 이 키로 서명됩니다(RFC 9421)            |
| 설치 ID           | 그 공개 키에서 파생된 26자. 설정과 `cc_server connect status`에 표시됩니다                                      |

같은 서버라도 Connect 주소마다 설치 ID가 다릅니다. ID는 키를 교체할 때만 바뀝니다.

## 봉인된 자격 증명

Connect를 통한 로그인은 **자격 증명 봉인**을 돌려줍니다. 그것을 만든 Connect만 열 수 있는
암호화된 블롭입니다. 봉인은 프로바이더, Connect 주소, 설치 ID, 워크스페이스, 프로바이더
계정, 앱, 시크릿 세대에 묶입니다.

- 서버는 봉인과 그 봉인이 대상으로 한 설치 ID를 저장합니다. 액세스 토큰은 메모리에만
  머뭅니다
- 갱신하려면 서버가 봉인을 돌려보내고, 새 액세스 토큰과 새 봉인을 받습니다
- 설치 ID나 Connect 주소가 더 이상 일치하지 않는 봉인은 다음에 읽힐 때 삭제되고, 그
  사람은 다시 로그인합니다. 키 교체, 다른 Connect로의 전환, 다른 서버에 복원된 데이터
  디렉터리 이후에 이런 일이 일어납니다
- Connect가 열 수 없는 봉인은 `access_denied`로 거부됩니다

## GitHub 설치

공유 GitHub App의 설치는 Connect가 그것을 그 서버의 설치 ID에 바인딩했을 때만 그 서버가
쓸 수 있습니다.

- **설정 → 워크스페이스 → 일반**의 **GitHub 앱 설치**는 15분짜리 티켓과 함께 GitHub를
  엽니다. 설치하는 사람이 개인 계정을 소유하거나 조직을 관리하면 Connect가 새 설치를
  바인딩합니다
- **이 서버 승인**은 이미 존재하는 설치를 바인딩합니다. 조직 관리자만 할 수 있습니다
- 조직 설치는 여러 서버에 바인딩될 수 있으며, 각 서버마다 관리자의 승인이 필요합니다

## 구성 신뢰

| Connect   | 서버가 그 구성을 신뢰하는 방법                                                                                                                     |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 호스팅    | 빌드에 컴파일된 키로 Ed25519 서명을 검증합니다. 지금까지 본 가장 높은 에포크보다 낮은 에포크는 거부합니다(`rollback`)                               |
| 사용자 지정 | 처음 사용할 때 GitHub 앱 ID와 클라이언트 ID, Google과 Linear의 클라이언트 ID, Slack 앱 ID와 클라이언트 ID를 고정합니다. 변경되면 서버 소유자가 **새 앱 신뢰**를 누를 때까지 Connect 로그인이 일시 중지됩니다(`pins_changed`) |

## 작업

모든 Connect 설정은 서버 소유자 전용입니다.

| 작업                  | 하는 일                                                                                |
| --------------------- | -------------------------------------------------------------------------------------- |
| `connect.status`      | 모드, URL, 잠금, 설치 ID, 상태, 구성 에포크, 각 레인의 출처                            |
| `connect.configure`   | `hosted`, `custom`(`url`과 함께) 또는 `off`를 설정합니다                               |
| `connect.test`        | 구성을 다시 가져와 상태를 보고합니다                                                   |
| `connect.confirmPins` | 사용자 지정 Connect의 변경된 식별자를 받아들입니다                                     |
| `connect.rotateKey`   | 새 설치 키를 발급합니다. 이 서버에서 Connect를 통한 모든 로그인이 작동을 멈춥니다       |

로그인 자체는 `oauth.lanes`, `oauth.begin`, `oauth.status`, `oauth.complete`,
`oauth.connections`, `oauth.disconnect`를 사용합니다. 그 사람은 항상 로그인한
호출자입니다.

## Connect를 통한 로그인

1. 서버가 Connect에 레인 시작을 요청하고 프로바이더의 승인 URL을 받으며, 이를 표시하기
   전에 확인합니다
2. 사람이 브라우저에서 승인합니다. 프로바이더는 Connect로 돌아옵니다
3. Connect가 8자리 코드와 `control-center://oauth-done` 링크를 표시합니다
4. 사람이 앱에 코드를 입력하거나 링크를 따라갑니다. 서버는 코드와 요청에 대한 자체
   증명으로 로그인을 회수합니다

로그인은 10분 후에 만료됩니다. 잘못된 코드를 다섯 번 입력하면 끝납니다. 이 앱이 시작하지
않은 링크는 **여기서 시작한 로그인이 아닙니다**로 거부됩니다.

## 설치 키 교체

Connect 카드의 **키 교체** 또는 `cc_server connect rotate-key --yes`:

- 서버에 새 설치 키와 새 설치 ID를 부여합니다
- Connect를 거치는 모든 레인에서 모두를 로그아웃시킵니다
- 서버 자체 앱을 통한 로그인은 그대로 둡니다
- 사용자 지정 Connect의 허용 목록에 새 설치 ID를 추가해야 합니다

## 상태 코드

| 코드                   | 의미                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| `hosted_unprovisioned` | 이 빌드에는 호스팅 구성 키가 없습니다                                |
| `signature`            | 호스팅 구성이 서명 검사에 실패했습니다                               |
| `rollback`             | Connect가 서버가 이미 본 것보다 오래된 구성을 제공했습니다           |
| `unreachable`          | 서버가 Connect에 연결할 수 없습니다                                  |
| `install_blocked`      | Connect가 이 설치 ID를 허용하지 않습니다                             |
| `pins_changed`         | 사용자 지정 Connect가 다른 앱 식별자를 알렸습니다                    |
| `protocol`             | Connect가 이 서버가 이해하지 못하는 형식으로 응답했습니다            |
