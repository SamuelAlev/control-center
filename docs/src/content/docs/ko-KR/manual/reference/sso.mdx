싱글 사인온에 대해 구성할 수 있는 모든 것을 한곳에 모았습니다. 값은
`global.db`의 `sso_connections` 행에 저장되고(설계상 서버 전체 범위),
**설정 → 서버 → 싱글 사인온** 또는 `sso.*` RPC 작업으로 편집합니다.
저장된 행이 유일한 진실 공급원입니다 — `CC_SAML_*` / `CC_OIDC_*` 환경
변수 경로는 없습니다(두 곳에서 도착할 수 있는 연결은 설정 화면과
불일치할 수 있는 연결입니다).

## 연결 필드

| 필드                   | 적용 대상  | 기본값          | 의미                                                                                                                                                 |
| ---------------------- | ---------- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `enabled`              | 둘 다      | 꺼짐            | 이 연결로 로그인할 수 있습니다                                                                                                                       |
| `idpMetadataXml`       | SAML       | —               | IdP의 `EntityDescriptor` XML(활성화하려면 필수)                                                                                                       |
| `spEntityId`           | SAML       | `<origin>/saml` | 우리 엔터티 ID로, 오리진이 달라질 때 고정됩니다                                                                                                       |
| `emailAttribute`       | SAML       | `email`         | 이메일을 담는 특성이며, 이메일 형식의 NameID를 대체로 사용합니다                                                                                      |
| `displayNameAttribute` | SAML       | `displayName`   | 표시 이름 특성                                                                                                                                        |
| `groupsAttribute`      | SAML       | `groups`        | 그룹 이름 특성                                                                                                                                        |
| `clockSkewSeconds`     | SAML       | 90              | 수명 검증 시 허용하는 오차                                                                                                                            |
| `allowIdpInitiated`    | SAML       | 꺼짐            | 유효한 요청하지 않은 응답(`InResponseTo` 없음)을 수락합니다. 브라우저는 수신자에게 봉인된 자격 증명을 받기 전에 단기 grant를 요구해야 합니다 |
| `wantResponseSigned`   | SAML       | 꺼짐            | Response 루트 서명을 요구합니다(어설션 서명은 항상 필요합니다)                                                                                        |
| `issuer`               | OIDC       | —               | 발급자 기본 URL(활성화하려면 필수)                                                                                                                    |
| `clientId`             | OIDC       | —               | 공개 클라이언트 id(활성화하려면 필수)                                                                                                                 |
| `clientSecret`         | OIDC       | —               | 기밀 클라이언트 전용이며, 0600 시크릿 파일에 저장되고 데이터베이스에는 절대 저장되지 않습니다 — RPC로는 쓰기 전용입니다(`sso.getConfig`는 `clientSecretPresent`를 보고합니다) |
| `groupsClaim`          | OIDC       | `groups`        | 그룹 이름을 담는 클레임                                                                                                                               |
| `defaultRole`          | 둘 다      | `member`        | 일치하는 그룹이 없을 때의 역할 — 절대 `owner`가 아닙니다                                                                                              |
| `groupRoleMap`         | 둘 다      | `{}`            | 그룹 → 역할. 소유자 매핑은 저장 시 거부됩니다                                                                                                         |
| `autoMember`           | 둘 다      | 켜짐            | 첫 로그인 시 모든 워크스페이스에 사용자를 자동 추가합니다                                                                                             |
| `allowJit`             | 둘 다      | 켜짐            | 로그인 시 알 수 없는 사용자를 프로비저닝합니다                                                                                                        |

## 프로세스 구성

SSO 연결은 환경에서 시드되지 않습니다. 남은 프로세스 플래그 하나는 SSO 콜백 후
브라우저가 웹 클라이언트를 어디에서 열지 정합니다:

| 변수 / 플래그                            | 의미                                                                                                                  |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `--web-client-url` / `CC_SERVER_WEB_CLIENT_URL` | 봉인된 자격 증명 핸드오프용 웹 클라이언트 URL입니다. 설정하지 않으면 핸드오프는 같은 오리진으로 유지됩니다(웹 클라이언트가 거기에서 제공될 때만 유용합니다). `web-popup` 로그인에서는 시작한 탭의 허용된 `client_origin`이 우선합니다. |

발급자 URL 자체는 `https`여야 합니다(루프백 발급자 `localhost`,
`127.0.0.1`, `::1`에 한해 `http`도 허용됩니다). IdP 콜백과 웹 클라이언트
호스트에는 신뢰할 수 있는 TLS를 사용하세요. 수신자 키를 생성하는 페이지와 그것이
전달하는 JavaScript는 신뢰 경계의 일부입니다. HTTPS가 그 부트스트랩을 보호합니다.
페어링 후에는 직접 연결과 릴레이 `/rpc` 세션 모두 Noise 암호화와 고정된 서버
신원을 요구합니다.

## HTTP 엔드포인트

| 엔드포인트                                       | 인증                | 용도                                                                                                                                                                                                            |
| ------------------------------------------------ | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /saml/login?relay=…&handoff_key=…`         | 없음(리디렉션)      | 클라이언트가 보유한 X25519 수신자 키로 SP 시작 로그인을 시작합니다. `relay=desktop`은 앱으로 핸드오프하고, `relay=web-popup`은 대기 중인 연결 탭에 postMessage합니다(그 `client_origin`은 오리진 허용 목록이 신뢰할 때만 반영됩니다) |
| `POST /saml/acs`                                 | 없음(IdP POST)      | 어설션을 검증하고 사용자를 프로비저닝합니다. SP 시작 로그인은 발급된 기기 자격 증명을 시작한 수신자 키로 봉인합니다. 허용된 요청하지 않은 SAML은 대신 브라우저에 묶인 클레임을 반환합니다 |
| `POST /saml/claim`                               | 같은 오리진의 브라우저 grant | 일회용 요청하지 않은 SAML grant를 쿠키와 새 `handoff_key`로 교환합니다. 수신자에게 봉인된 자격 증명을 반환하며, 평문 페어링 키는 절대 반환하지 않습니다 |
| `GET /saml/metadata`                             | 없음                | 우리 SP `EntityDescriptor`                                                                                                                                                                                      |
| `GET /oidc/login?relay=…&handoff_key=…` / `GET /oidc/callback` | 없음                | OIDC 왕복입니다. 로그인에는 클라이언트가 보유한 수신자 키가 필요합니다. `relay=desktop`은 앱으로, `relay=web-popup`은 대기 중인 연결 탭으로 핸드오프합니다(같은 `client_origin` 규칙) |
| `GET /auth/providers`                            | 없음, CORS `*`      | 연결 화면 프로브입니다: 제공되는 SSO 연결(`id`/`kind`/`label`) + `pairingEnabled`                                                                                                                               |
| `/scim/v2/Users…`                                | Bearer(SCIM 토큰)   | Users 생성/get/list+filter/PUT/PATCH/DELETE                                                                                                                                                                     |
| `/scim/v2/Groups`                                | Bearer              | 읽기 전용이며, 그룹 푸시는 설계상 501로 응답합니다                                                                                                                                                              |
| `/scim/v2/ServiceProviderConfig`                 | Bearer              | 기능 문서                                                                                                                                                                                                       |

SP 시작 SAML과 OIDC에서 로그인 시작 URL에는 유효한 `handoff_key`(시작하는
클라이언트의 X25519 공개 키)가 필요합니다. 서버는 대기 중인 로그인과 함께 그 키를
보관하고, 콜백에서 발급된 기기 자격 증명을 임시 X25519, HKDF-SHA256,
AES-256-GCM으로 서버 오리진에 묶어 봉인합니다. 데스크톱 핸드오프는
`control-center://pair`를, 같은 탭 웹 핸드오프는 URL 프래그먼트를 사용하며,
`web-popup`은 (제공되면) 허용된 `client_origin`에, 그렇지 않으면 구성된 웹
클라이언트 URL이나 콜백 오리진에 postMessage합니다. 그 프래그먼트나 팝업
메시지에는 평문 페어링 키가 아니라 봉인된 봉투가 실립니다. 시작한 클라이언트는
그것을 열기 위한 대응하는 개인 키를 보관합니다. 이 봉투는 페어링 후 수립되는 필수
Noise 세션과는 별개입니다.

IdP 시작 SAML 응답(활성화된 경우)에는 시작한 수신자가 없습니다. 대신 ACS는
5분짜리 HttpOnly, SameSite=Strict 브라우저 쿠키를 설정하고 **웹 클라이언트 열기** /
**데스크톱 앱 열기** 선택지를 제공합니다. 그 페이지는 새 수신자 키를 생성하고 그
공개 절반과 grant 핸들을 같은 오리진에서 `POST /saml/claim`으로 보냅니다. 교환에는
일치하는 쿠키와 오리진(CSRF 경계)이 필요하고, grant를 한 번만 소비하며, 수신자에게
봉인된 봉투만 반환합니다. 이어지는 웹/데스크톱 프래그먼트는 대상 클라이언트가
열 수 있도록 그 봉투와 수신자의 개인 키 자료를 운반하며, 평문 기기 자격 증명을
운반하지 **않습니다**. 다른 브라우저나 만료된 grant는 그것을 교환할 수 없습니다.
대상 웹 클라이언트 오리진은 프래그먼트에 접근해 해독할 수 있습니다. 침해된 콜백
페이지나 웹 클라이언트 오리진은 자격 증명을 훔칠 수 있습니다. 암호화가 신뢰할 수
없는 제공 코드를 안전하게 만들지는 않습니다.

## RPC 작업

모든 `sso.*` 작업은 서버 범위이며 **서버 소유자**(설치의 운영자,
`ServerAuthority.serverOwner`)로 제한됩니다. 워크스페이스를 소유하는
것만으로는 충분하지 않으며, 페어링만으로는 결코 권한이 부여되지
않습니다.

| 작업                      | 용도                                                                                                                                                          |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sso.getConfig`           | 종류별로 저장된 연결                                                                                                                                          |
| `sso.saveConfig`          | 검증하고, 저장하고, 실시간으로 적용합니다                                                                                                                     |
| `sso.status`              | 활성화/구성됨 플래그, SCIM 토큰 존재 여부, 정규 오리진                                                                                                        |
| `sso.testConnection`      | 브라우저 왕복 없이 연결을 테스트합니다(SAML: 메타데이터 파싱 + AuthnRequest 생성, OIDC: 발급자 디스커버리). 화면에만 있고 아직 저장하지 않은 값을 선택적으로 사용할 수 있습니다 |
| `sso.spMetadata`          | 특정 오리진의 SP `EntityDescriptor`를 출력합니다                                                                                                              |
| `sso.setPairingEnabled`   | 수동 페어링(초대 코드, 페어링 키)을 허용/금지합니다. 동작하는 SSO 연결이 없을 때 비활성화를 거부하여 잠금을 방지합니다                                        |
| `sso.sessionPolicy`       | 설치의 기기 자격 증명 최대 수명과 유휴 타임아웃을 읽습니다(분 단위, `0` = 미설정)                                                                              |
| `sso.setSessionPolicy`    | 해당 한도를 설정합니다. 기기 검사 시점에 적용되며 클라이언트에 알려지지 않습니다                                                                              |
| `sso.scimRegenerateToken` | SCIM bearer 토큰을 생성해 반환합니다(한 번만)                                                                                                                 |

## 검증 오류 코드

`cc_saml_verify_response` 실패는 안정적인 코드를 함께 반환합니다:

| 코드                   | 의미                                                                            |
| ---------------------- | ------------------------------------------------------------------------------- |
| `signature`            | 서명 누락/신뢰할 수 없음/변조, 또는 허용되지 않는 알고리즘/변환                  |
| `expired`              | `NotBefore`/`NotOnOrAfter` 범위 밖(오차 초과)                                   |
| `audience`             | 대상 제한이 우리를 지칭하지 않음                                                |
| `destination`          | 응답 목적지가 우리 ACS가 아님                                                   |
| `request_match`        | `InResponseTo`가 대기 중인 요청과 일치하지 않거나, 허용되지 않은 상태에서 요청하지 않은 응답임 |
| `issuer`               | 발급자가 구성된 IdP가 아님                                                      |
| `recipient`            | 주체 확인 수신자가 우리 ACS가 아님                                              |
| `malformed`            | XML/스키마 수준 실패                                                            |
| `status`               | IdP가 보고한 상태가 Success가 아님                                              |
| `invalid` / `internal` | 그 외 전부 / 경계 실패                                                          |

## 데이터베이스 표면

- `sso_connections` (global.db) — 종류별로 행이 하나, 설계상
  워크스페이스 간 공유입니다.
- `users.sso_subject` + `users.sso_issuer` — 제공자 주체 고정으로, 부분
  인덱스를 통해 `(issuer, subject)`마다 고유합니다.
- `users.deactivated_at` — SCIM 비활성화 스탬프.
- SCIM bearer 토큰과 OIDC 클라이언트 시크릿은 0600 시크릿 파일에
  저장되며, 데이터베이스에는 절대 저장되지 않습니다.
