아무것도 없는 상태에서 여러분의 코드를 대상으로 에이전트가 실행되기까지의 가장 짧은 완전 경로입니다. 순서대로 따라 하세요. 각 단계는 앞 단계에 의존합니다.

Git, GitHub 계정, 그리고 모델 공급자 계정(Anthropic, OpenAI, Codex, Cursor, Kimi Code 또는 API 키가 있는 임의의 공급자)이나 이미 설치된 Claude Code CLI 중 하나가 필요합니다. 나머지는 진행하면서 설정합니다.

## 1단계: 설치 및 실행

[설치](/ko-KR/매뉴얼/설치/)에 설명된 대로 Control Center를 설치한 다음 실행합니다.

데스크톱 앱은 처음 실행할 때 **"Control Center를 어떻게 실행할까요?"**라고 묻습니다. **이 앱에서 실행**을 선택하세요. 그러면 Control Center가 이 머신에 헤드리스 `cc_server`를 실행하며, 이 서버가 데이터를 소유하고 모든 작업을 수행합니다. 서버는 눈에 보이지 않고, 대신 온보딩 화면이 열립니다.

:::note[아무것도 설치하고 싶지 않으신가요?]
같은 앱이 [app.usectrl.dev](https://app.usectrl.dev)에서 브라우저로도 같은 기능과 함께
실행됩니다. 다만 브라우저 탭은 서버를 호스팅할 수 없으므로 서버는 직접 마련해야 합니다.
`cc_server`를 로컬에서 실행하고 `ws://localhost:9030`에 연결하거나, 다른 머신의 서버를
가리키면 됩니다. 이 빠른 시작은 서버 설정이 필요 없는 데스크톱 경로를 따릅니다. 브라우저
경로는 [설치](/ko-KR/매뉴얼/설치/#use-it-in-your-browser)를 참고하세요.
:::

## 2단계: 온보딩 진행

온보딩은 다섯 단계로 이루어지며 순서대로 진행됩니다. 건너뛸 수 없습니다.

1. **연결**: GitHub로 로그인하거나 `repo` 및 `read:org` 권한이 있는 개인 액세스 토큰을 붙여 넣습니다. 자격 증명은 서버에 저장되고 계정에 연결됩니다.
2. **워크스페이스**: 첫 워크스페이스의 이름을 정하고, 원한다면 로고를 고릅니다. 워크스페이스를 만들면 에이전트 다섯 개(CEO와 `qa`, `architect`, `engineer`, `librarian`)와 기본 제공 파이프라인 템플릿이 함께 생성됩니다.
3. **샌드박스**: 샌드박싱 기본 설정을 기록합니다. 어느 쪽을 골라도 계속 진행할 수 있습니다.
4. **어댑터**: 에이전트가 기본으로 사용할 어댑터와 모델을 고릅니다. **Control Center (built-in)** 을 선택한 다음, 나타나는 공급자 선택기로 모델 공급자에 로그인합니다. 공급자를 연결하기 전까지 모델 목록은 비어 있습니다. 이 단계를 마치면 워크스페이스의 CEO 에이전트에도 어댑터와 모델이 기록됩니다.
5. **음성(선택 사항)**: 받아쓰기용 온디바이스 음성 모델을 설치하거나 건너뜁니다.

그러면 Control Center가 워크스페이스 받은편지함을 엽니다.

:::note[에이전트 실행을 제한하는 것]
에이전트 명령은 호스트의 OS 네이티브 샌드박스를 사용할 수 있을 때 그 안에서 실행됩니다.
macOS에서는 Seatbelt, Linux에서는 bubblewrap입니다. Windows에는 백엔드가 없으므로,
그곳의 실행은 다른 계층으로만 제한됩니다. 즉 대화 자체의 워크트리(Windows에서는
`git worktree`, `rift`가 제공되는 곳에서는 copy-on-write), 실행할 때마다 발급되고 종료 시
폐기되는 자격 증명, 그리고 동작 가드레일입니다. [샌드박스와 보안](/ko-KR/매뉴얼/개념/샌드박스와-보안/)을
참고하세요.
:::

## 3단계: 저장소 추가

**설정 → 워크스페이스 → 리포지토리**로 이동한 다음 **리포지토리 추가**를 클릭합니다.

이 대화 상자는 여러분의 클라이언트가 아니라 서버를 실행하는 머신의 폴더를 탐색하며, 서버가 노출하도록 구성된 루트(기본값은 서버 사용자의 홈 디렉터리) 안에 머뭅니다. 체크박스는 git 체크아웃에만 표시됩니다. 원하는 체크아웃을 선택하고 등록하세요.

체크아웃은 git 워크트리 안에 있고, `origin` 원격이 있으며, 그 원격이 지원되는 forge(github.com, gitlab.com 또는 bitbucket.org)를 가리킬 때만 허용됩니다. 그 밖의 경우는 사유와 함께 거부됩니다.

저장소는 워크스페이스 범위입니다. 여기서 체크아웃을 등록하면 _이_ 워크스페이스에 들어갑니다. 별도의 연결 단계는 없습니다.

## 4단계: 에이전트에 어댑터와 모델 지정

**설정 → 워크스페이스 → 에이전트**로 이동합니다. 목록에서 `engineer` 에이전트를 선택하세요.

**설정** 탭에서 다음을 지정합니다:

- **어댑터**: `Control Center (built-in)`
- **모델**: 온보딩에서 연결한 공급자의 모델 중 하나를 고릅니다

**변경 사항 저장**을 누릅니다.

실제로 이 단계는 선택 사항이 아닙니다. 온보딩에서 고른 어댑터를 상속받는 것은 CEO 에이전트뿐이며, 네 명의 전문 에이전트는 어댑터 없이 생성됩니다. 이들은 Anthropic의 기본 모델과 함께 **Control Center (built-in)** 로 폴백하므로, Anthropic 계정을 연결한 경우에만 실행되며, 연결했다 해도 여러분이 고르지 않은 모델로 실행됩니다.

## 5단계: 에이전트에 작업 보내기

1. 사이드바에서 **스페이스** 섹션을 찾아 **+** 버튼을 클릭합니다.
2. 스페이스 이름을 정하고, **에이전트 추가**에서 `engineer` 에이전트를 추가한 뒤 생성합니다.
3. 등록한 저장소를 대상으로 구체적이고 작은 작업을 입력하고 Enter를 누릅니다.

Control Center는 이 대화를 위해 워크스페이스 저장소의 copy-on-write 워크트리를 마련하고, 에이전트의 역할, 페르소나, 스킬과 스페이스의 컨텍스트로 프롬프트를 구성한 뒤 실행을 디스패치합니다. 여러분의 원본 체크아웃은 건드리지 않습니다.

## 6단계: 작동하는 모습 지켜보기

다음이 순서대로 보일 것입니다:

- 이 대화에서 에이전트가 작업 중이므로 작성기의 전송 버튼이 중지 버튼으로 바뀝니다
- 에이전트의 추론, 도구 호출, 텍스트가 트랜스크립트로 스트리밍됩니다
- 실행이 끝나면 전송 버튼이 다시 돌아옵니다

그런 다음 **설정 → 워크스페이스 → 에이전트**를 열고 에이전트를 선택한 뒤 **로그** 탭을 확인하세요. 실행 행 하나가 표시되며, 상태, 소요 시간, 시작 및 종료 시각, 실행에 사용된 어댑터가 함께 나옵니다.

이것이 핵심 루프입니다. Control Center의 나머지 모든 것, 즉 풀 리퀘스트 리뷰, 파이프라인, 티켓, 회의, Slack은 여기에 매달려 있습니다.
