이 가이드에서는 실행을 직접 시작하는 방법을 다룹니다. 실행을 지켜보고, 단계
출력을 읽고, 실패에서 복구하는 방법은
[파이프라인 실행 모니터링](/ko-KR/매뉴얼/사용-가이드/파이프라인-모니터링/)을
참고하세요.

## 실행 시작

1. 워크스페이스 사이드바에서 **파이프라인**을 클릭합니다.
2. 헤더에서 **파이프라인 실행**을 누릅니다. 그러면 런처
   (`/workspaces/<workspace-id>/pipelines/run`)로 이동합니다.
3. 왼쪽 레일에서 템플릿을 선택합니다. 각 카드에는 템플릿의 이름, 설명,
   입력을 받는지 여부가 표시됩니다.
4. 오른쪽의 입력 양식을 채웁니다. 필수 필드는 값이 있을 때까지 버튼을
   비활성화하고, 입력이 없는 템플릿은 그렇게 표시됩니다.
5. **파이프라인 실행**을 누릅니다.

그러면 실행 상세 페이지로 이동하며, 타이밍 워터폴과 그래프 캔버스가 실시간으로
표시됩니다.

## 레일이 비어 있다면

런처는 다음 두 조건이 **모두** 참일 때만 템플릿을 표시합니다.

- 템플릿의 스위치가 **설정 → 워크스페이스 → 파이프라인 템플릿**에서 켜져
  있습니다.
- 템플릿 편집기의 **수동 실행** 대화 상자에서 **수동 실행 허용**이 켜져
  있습니다. 이 스위치가 런처가 읽는 `manual` 트리거를 만듭니다.

기본 제공 템플릿 13개 중 8개는 비활성 상태로 제공됩니다: `external_pr_welcome`,
`cross_review`, `ticket_to_pr`, `pr_triage`, `pre_merge_gate`, `release_notes`,
`dep_audit`, `pr_digest`. 엔진은 비활성 템플릿의 실행을 거부하므로, 여기에서
찾기 전에 해당 스위치를 켜세요.

템플릿 목록에는 템플릿별 **실행** 액션이 없고 편집기 안에도 실행 버튼이
없습니다. 런처가 유일한 수동 진입점입니다.

## 저장소 입력 채우기

**저장소** 유형의 입력은 워크스페이스에 등록된 리포지토리를 선택하는 피커를
표시합니다. 하나를 선택하면 실행 페이로드에 `repo_id`, `repo_local_path`,
`repo_full_name`이 채워지고, 리포지토리에 GitHub 원격이 있으면 `repo_owner`와
`repo_name`도 채워지므로, 이후 단계에서 필요한 값을 읽을 수 있습니다.

## 실행 지켜보기

실행 상세 페이지는 세 부분으로 구성됩니다. 메타 스트립(시작 시각, 활성 기간,
단계 진행률, 실패 배너, **재시도**와 **삭제**), 단계별 기간과 비용을 보여 주는
접을 수 있는 타이밍 워터폴, 그래프 캔버스입니다. 노드를 선택하면 해당 단계의
상세 패널이 열립니다.

[파이프라인 실행 모니터링](/ko-KR/매뉴얼/사용-가이드/파이프라인-모니터링/)에서
일시 중단된 단계를 읽는 방법과 단계가 실패할 때 대처하는 방법을 포함해 이 모든
내용을 다룹니다.

앱에서 시작하는 모든 실행은 실제 실행입니다.
