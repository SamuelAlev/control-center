이 가이드에서는 회의를 녹음하고 AI가 생성한 정리본을 얻는 방법을 설명합니다.
작동 방식은 [회의와 전사](/ko-KR/매뉴얼/개념/회의/)를 참고하십시오.

## 시작하기 전에

- **음성 모델을 기다린 뒤 서버를 재시작하십시오.** 일반 부팅은 선택된 ASR 모델
  (다국어 기본값인 Parakeet TDT 0.6B v3, 약 600 MB)을 백그라운드에서 강제
  설치합니다. 서버는 모델을 **부팅 시 한 번만** 확인하므로, 재시작하기 전까지는
  첫 실행에도 녹음 작업이 없습니다. 디스크에 모델이 없으면 녹음이 `Could not
  start recording on the host: …`와 함께 실패합니다. 다른 빌드를 고르려면
  **설정 → 서버 → 음성 및 미팅 모델**로 이동하십시오. 이 경우에도 재시작이
  필요합니다.
- 첫 녹음 시 운영체제가 요청하면 **마이크** 권한을 부여하십시오.
- **macOS 14.4+**에서는 시스템 오디오를 Core Audio 프로세스 탭으로 캡처합니다. 설치할 드라이버는 없지만, 운영체제가 _오디오 캡처_ 권한을 한 번 더 요청합니다. 이는 화면 기록이 아니며 화면 기록 표시등을 절대 켜지 않습니다. 거부하면 시작이 `System-audio capture permission denied.`와 함께 실패합니다. macOS 14.4 미만에는 시스템 오디오 캡처가 없습니다.
- **Linux**에서는 `parecord`(pulseaudio-utils) 또는 `pw-record`(pipewire)가 `PATH`에 있어야 합니다. 캡처는 PipeWire/PulseAudio 모니터 소스를 대상으로 이 중 하나를 실행합니다. 둘 다 없으면 시작이 `No system-audio capture tool found`와 함께 실패합니다.

:::caution[회의 오디오는 어디로 가는가]
캡처, 전사, 에코 제거, 화자 분리는 모두 온디바이스에서 실행되며 클라우드 호출이
없습니다. 하지만 "디바이스"는 **cc_server 호스트**를 뜻하고, 서버를 원격으로
실행할 때는 그 호스트가 다른 머신입니다. 그리고 최종 정리본은 평범한 에이전트
실행입니다. `meeting_summary` 파이프라인이 전체 트랜스크립트와 대략적인 노트를
그 에이전트가 사용하는 모델 프로바이더로 전송합니다. 트랜스크립트가 머신을
벗어나면 안 된다면 그 에이전트를 로컬 프로바이더로 지정하십시오.

녹음 화면은 녹음하는 동안 이 점을 알려 주므로, 보낼 트랜스크립트가 생기기 전에
결정을 마주하게 됩니다.
:::

## 녹음 시작

1. 사이드바에서 **회의**를 엽니다.
2. **회의 녹음**을 클릭합니다. 실시간 녹음 HUD가 `/meetings/record`에서 열립니다.

녹음은 즉시 시작되어 마이크와 시스템 출력 오디오, 즉 다른 참가자의 오디오를
캡처합니다. 모드 프롬프트도 오디오 소스 선택기도 없습니다. 대면 단일 마이크 모드는
API에는 있지만 현재 UI에는 없습니다.

브라우저에서도 같은 흐름이 동작하지만 차이가 하나 있습니다. "시스템 오디오"가
오디오 트랙을 반드시 포함해야 하는 화면 공유라는 점입니다. 브라우저 탭(또는 전체
화면)을 공유하고 선택기에서 "탭 오디오 공유" / "시스템 오디오 공유"를 활성화하십시오.
Safari와 Firefox, 그리고 macOS의 전체 화면 공유는 대개 오디오 트랙을 제공하지
못합니다.

HUD에는 레벨 미터, 경과 시간, 그리고 한쪽에 실시간으로 쌓이는 트랜스크립트가
표시됩니다.

## 회의 중

- 노트 패널에 **대략적인 노트를 작성하십시오**. 노트는 입력하는 대로 저장되고 나중에 요약 에이전트에 전달되므로, 트랜스크립트가 놓칠 수 있는 내용은 무엇이든 적어 두십시오.
- **활성 템플릿** 행에서 **노트 템플릿을 고르십시오**. 이 템플릿은 이 회의의 요약을 결정하고 녹음과 함께 저장되므로, 나중에 다시 실행하면 여기서 고른 템플릿이 그대로 재현됩니다.
- 일시 정지 컨트롤로 **일시 정지와 다시 시작**을 합니다. 일시 정지 중에는 전사가 멈추고 타이머가 고정됩니다.
- 트랜스크립트는 화자 태그가 붙은 채로 스트리밍됩니다. 여러분의 발언은 **나**, 통화의 다른 모든 사람은 **기타**로 표시됩니다. 화자 분리가 기타를 이름을 바꿀 수 있는 `Person 1`, `Person 2`, …로 나눌 때까지는 그렇습니다.

:::note[아주 조용한 화자는 전사되지 않을 수 있습니다]
전사는 무음 임계값을 한 번도 넘지 않은 오디오 윈도는 디코딩조차 하지 않고
건너뜁니다. 덕분에 조용한 채널이 환각된 비음성 토큰으로 CPU를 태우지 않지만,
그만큼 희미하거나 멀리 있는 화자가 트랜스크립트를 전혀 남기지 않을 수도 있습니다.
끝날 때가 아니라 일찍 레벨 미터를 확인하십시오.
:::

## 중지하고 요약

1. **중지하고 요약**을 클릭합니다.
2. Control Center가 회의의 상세 보기로 곧바로 이동하며, 이 회의는 **처리 중**으로 표시됩니다. 화자 분리가 원격 채널을 개별 화자로 나누고 `meeting_summary` 파이프라인이 정리본을 생성합니다.
3. 그 파이프라인이 끝나면 회의가 **완료**로 바뀝니다. 기다릴 필요가 없습니다. 상세 보기가 스스로 갱신됩니다.

## 정리본 검토

회의 상세 화면(`/meetings/:meetingId`)에는 네 개의 탭이 있습니다.

| 탭               | 내용                                                                            |
| ---------------- | ------------------------------------------------------------------------------- |
| **노트**         | 대략적인 노트와 트랜스크립트로 구성된 AI 요약과 보강된 노트                     |
| **트랜스크립트** | 타임스탬프가 있는 전체 화자 태그 트랜스크립트                                   |
| **액션 아이템**  | 추출된 할 일, 각 항목에 선택적 담당자                                           |
| **결정 사항**    | 통화 중 기록된 결정 사항                                                        |

여기서 다음을 할 수 있습니다.

- **화자 이름 바꾸기**: `Person 1`을 실제 이름으로 바꾸면 트랜스크립트 전체에 적용됩니다.
- 완료한 대로 **액션 아이템을 체크합니다**.
- 액션 아이템에서 **티켓 만들기**: 액션 아이템을 제목으로 하는 새 미할당 티켓을 만들고 그 행에 다시 연결합니다. 티켓 자체에서 에이전트에 할당하십시오([에이전트에 작업 위임](/ko-KR/매뉴얼/사용-가이드/티켓-위임/) 참고).
- **요약 다시 실행**으로 새로 요약합니다(예: 화자 이름을 바꾼 뒤). 녹음 시 저장된 템플릿을 재사용합니다. 활성 템플릿은 **설정 → 워크스페이스 → 회의**에서 고릅니다.

노트, 제목, 액션 아이템, 결정 사항 편집은 어디서나 됩니다.
**요약 다시 실행**과 처리 중인 회의 취소는 **데스크톱 전용**이며, 브라우저에서는
두 버튼 모두 아무 동작도 하지 않습니다.

## 캘린더 이벤트에서 바로 녹음

[캘린더를 연결](/ko-KR/매뉴얼/사용-가이드/캘린더-연결/)했다면 수동으로 시작할 필요가
없습니다. 이 기능은 **데스크톱 전용**이며, 웹 클라이언트에서는 거부합니다.

1. **캘린더**에서 이벤트를 엽니다.
2. **녹음 시작 및 연결**을 클릭합니다.

녹음에는 이벤트의 제목이 초기값으로 설정되고 이벤트에 다시 연결되므로, 노트와
캘린더 항목이 연결된 상태로 유지됩니다.

:::note[회의를 삭제해도 오디오는 삭제되지 않습니다]
회의를 삭제하면 행만 제거되지만, `<dataDir>/meetings/<meetingId>/` 아래에 녹음된
WAV 파일은 디스크에 그대로 남습니다. 보존 정책도, 크기 상한도, 정리 스윕도 없습니다.
오디오가 중요하다면 그 디렉터리를 직접 제거하십시오.
:::
