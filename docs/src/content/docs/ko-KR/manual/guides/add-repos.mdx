이 가이드에서는 Git 체크아웃을 워크스페이스에 등록하고, 다시 인덱싱한 다음,
제거하는 방법을 설명합니다. 서버의 폴더에서 저장소를 추가하려면 서버 소유자가 필요하며, 저장소를 제거하려면 워크스페이스 관리자가 필요합니다.

저장소는 **워크스페이스 범위**입니다. 전역 레지스트리도, 연결 단계도 없습니다.
저장소를 추가하는 일과 그것을 워크스페이스에 넣는 일은 같은 동작입니다. 같은
체크아웃을 두 워크스페이스에 등록하면 서로 다른 두 개의 id를 가진 두 개의
독립된 행이 됩니다. 워크스페이스를 넘어서는 순간 저장소의 정체성은 파일 시스템
경로이며, id는 결코 아닙니다.

## 시작하기 전에

폴더는 다음 세 가지를 모두 충족할 때만 등록할 수 있습니다:

1. **git 워크트리** 안에 있어야 합니다.
2. 그 워크트리에 **`origin` 원격**이 있어야 합니다.
3. `origin` 원격이 **지원되는 forge**를 가리켜야 합니다: github.com, gitlab.com,
   bitbucket.org.

그 밖의 경우는 등록 시점에 명시적인 메시지와 함께 거부됩니다: "Folder is not
inside a git work tree.", "No `origin` remote configured for this repository.",
"The `origin` remote is not hosted on a supported forge (github.com, gitlab.com,
bitbucket.org).". 로컬 전용 모드는 없습니다.

forge는 원격에서 읽어 저장소에 저장되며, 사용자가 직접 고르는 값이 아닙니다.
워크스페이스 하나가 세 forge의 저장소를 동시에 담을 수 있고, 각 저장소와는 자체
자격 증명을 가진 자체 API로 통신합니다. GitLab의 중첩 네임스페이스는 그대로
유지되므로, `gitlab.com/group/subgroup/project`는 소유자 `group/subgroup`, 이름
`project`로 등록됩니다.

폴더는 `cc_server`를 호스팅하는 머신에 있어야 하며, 그 서버의 `--repo-roots`
디렉터리 중 하나 안에 있어야 합니다. 이 허용 목록의 기본값은 서버 사용자의 홈
디렉터리이며, 루트보다 위로 탐색하는 것은 거부됩니다. 서버 머신 자체의 파일을 나열하므로, 서버의 폴더 탐색은 [서버 소유자](/ko-KR/매뉴얼/개념/권한-부여/#서버-소유자)에게만 제공됩니다. 그 밖의 사용자에게는 **리포지토리 추가** 버튼이 있던 자리에 "리포지토리는 서버 소유자가 서버의 폴더에서 추가합니다."가 표시되며, 어느 워크스페이스에도 없는 저장소로 가는 링크에는 그 저장소가 여러분의 어떤 워크스페이스에도 연결되어 있지 않다는 것과, 서버 소유자에게 추가를 요청하라는 내용이 표시됩니다.

저장소 체크아웃이 있을 수 있는 위치는 누가 연결하는지에 따라 달라집니다:

- **서버의 워크스페이스 저장소 안**: 모든 워크스페이스 관리자.
- **서버 디스크의 그 밖 어디든**: [서버 소유자](/ko-KR/매뉴얼/개념/권한-부여/#서버-소유자)만 가능합니다. 서버가 머신 자체의 파일을 가리키게 할 수 있는 사람이 서버 소유자뿐이기 때문입니다. 그 밖의 사용자에게는 "이 워크스페이스의 저장소 밖에 있는 폴더는 서버 소유자만 연결할 수 있습니다."가 표시됩니다.
- **서버의 데이터 폴더**, 또는 그 안의 어떤 것: 결코 불가능합니다.

체크아웃의 `origin`은 연결하려는 저장소여야 합니다. `origin`이 다른 저장소를 가리키는 폴더는 "해당 폴더의 origin은 다른 리포지토리입니다."라는 메시지와 함께 거부됩니다.

### 서버가 아직 사용하지 않는 폴더

폴더가 워크스페이스의 저장소 밖에 있고 서버 소유자가 연결하지 않은 저장소(예: 가져온 워크스페이스의 저장소)는, 서버 소유자가 확인할 때까지 해당 행 아래에 "이 폴더는 워크스페이스의 저장소 밖에 있습니다. 이 서버가 이 폴더를 사용해도 되는지 확인하세요."가 표시됩니다. 그 밖의 사용자에게는 대신 "이 폴더는 워크스페이스의 저장소 밖에 있습니다. 서버 소유자만 확인할 수 있습니다."가 표시됩니다.

서버 소유자는 한 번만 확인하면 됩니다. 행의 **확인**을 누르거나, 여러 저장소가 기다리고 있으면 목록 위 알림의 **모두 확인**을 누릅니다. 각 저장소는 소유자로서 다시 검사되며, 연결할 때와 같은 검사를 받습니다. 그때까지 목록에는 남지만 열리거나, 프로비저닝되거나, 인덱싱되지 않습니다. 편집기, 터미널, 환경, 스페이스 체크아웃 중 어느 것도 이를 사용하지 않으며, 코드 그래프도 건너뜁니다. 서버 소유자로서 같은 폴더를 다시 추가하면 확인과 같은 효과가 나며 저장소 id는 유지됩니다.

심볼릭 링크가 다른 곳으로 옮긴 체크아웃도 같은 방식으로 다룹니다. 목록에는 남지만 사용되지 않으며, 이제 가리키는 폴더를 연결할 수 있는 사람이 다시 연결할 때까지 그렇습니다.

본인도 저장소의 forge에 로그인되어 있어야 하며, 본인의 계정이 그 저장소를 볼 수 있어야 합니다.

## 체크아웃 등록

이 단계는 서버 소유자가 수행해야 합니다.

1. **설정 → 워크스페이스 → 리포지토리**(`/workspaces/<id>/settings/workspace/repositories`)를
   엽니다.
2. **리포지토리 추가**를 클릭합니다.

이 대화 상자는 사용자의 파일 시스템이 아니라 **서버**의 파일 시스템을 탐색하는
브라우저입니다. 데스크톱, 웹, 휴대폰에서 흐름이 같습니다. 네이티브 폴더
선택기를 쓰면 엉뚱한 머신의 폴더를 고르게 되기 때문입니다.

3. 서버에 구성된 루트 안에서 탐색합니다. git 체크아웃인 폴더에는 표시가 붙습니다.
4. 원하는 만큼 선택합니다. 탐색하는 동안 선택이 유지되므로, 여러 폴더에서
   체크아웃을 모을 수 있습니다.
5. 한 번에 일괄 등록합니다.

선택 하나가 실패해도 나머지 일괄 처리분이 버려지지 않습니다. 생성된 id와 함께,
거부된 경로마다 개별 오류가 표시됩니다. 이 워크스페이스에 이미 있는 경로를 다시
등록하면 중복을 만들지 않고 기존 저장소를 반환합니다.

등록된 각 저장소는 목록에 `owner/name`, forge를 나타내는 배지, 서버상의 경로와
함께 표시됩니다. GitHub 저장소는 소유자의 아바타도 보여 주지만, 다른 forge는
소유자 아바타 URL을 유추할 수 없어 이니셜로 대체합니다.

forge 배지는 여러 forge가 섞인 워크스페이스에서 중요합니다. 서로 다른 forge의 두
저장소가 모두 `acme/web`이라고 불릴 수 있는데, 리뷰로 무엇을 할 수 있는지, 링크가
어디로 향하는지가 서로 다르게 동작합니다.

## 다음에 일어나는 일

등록은 이 워크스페이스 범위의 `RepoAdded` 이벤트를 발생시키고, 이것이 해당
체크아웃의 `index_code` 파이프라인을 시작합니다. 이 파이프라인이 코드 그래프를
채우므로, 검색과 영향 분석이 답할 수 있는 대상이 생깁니다.

언어별 문법이 함께 제공되는 파일만 인덱싱됩니다(Dart, JavaScript, TypeScript,
TSX, PHP, Python, Rust, Zig, C, C++, Go, Java, Ruby, C#, Swift, Kotlin, R,
Assembly, MATLAB, Ada).
[코드 그래프로 코드 검색](/ko-KR/매뉴얼/사용-가이드/코드-검색/)을 참고하세요.

## 저장소 다시 인덱싱

각 행에는 **코드 인덱싱** 버튼이 있습니다. 클릭하면 그 체크아웃의 인덱서가 다시
실행됩니다. 실행되는 동안 버튼은 전체 파일 수 대비 완료한 파일 수를 보여 주는 진행
표시로 바뀌고 취소 컨트롤이 함께 나타납니다. 실행이 끝나면 심볼 개수와 함께 체크
표시로 바뀌고, 실행이 실패했다면 경고가 표시됩니다.

## 저장소 순서 변경

행의 핸들을 끌어 옮깁니다. 설정한 순서가 앱의 모든 저장소 목록이 읽어 들이는
순서가 됩니다.

## GitHub 링크 수정

행의 링크 아이콘을 누르면 저장소의 GitHub 소유자와 리포지토리 이름을 편집하는
화면이 열립니다.

이 화면이 필요한 경우는 드뭅니다. 링크는 forge에서 저장소의 영구 id에 묶여 있으므로, 이름 변경이나 이전은 자동으로 따라갑니다.

- Control Center에서 저장소 이름을 바꾸면 표시 이름만 바뀝니다.
- 링크가 가리키는 forge 저장소를 바꾸려면 워크스페이스 관리자가 필요하며, 연결할 때와 마찬가지로 관리자 본인의 로그인으로 forge에서 확인합니다.
- 연결된 저장소를 로컬 전용 저장소로 바꿀 수는 없습니다.

나중에 경로가 **다른** 저장소를 가리키게 되면(원래 저장소가 삭제된 뒤 다시 만들어졌거나, 다른 저장소로 옮겨져 대체된 경우), Control Center는 그 저장소로 아무것도 보내지 않습니다. 토큰, 푸시, 댓글, 요청 모두 해당합니다. 본인의 행동도 예외가 아닙니다. 그런 저장소에서 하는 리뷰, 병합, 댓글은 GitHub, GitLab, Bitbucket 모두에서 거부됩니다. 워크스페이스 관리자가 **다시 연결**을 누를 때까지 행과 그 저장소의 풀 리퀘스트에 "_repo_가 이제 다른 리포지토리를 가리킵니다"가 표시됩니다.

## 누가 코드를 열 수 있는지

저장소에 대한 부여만으로는 저장소의 파일이 열리지 않습니다. 저장소의 파일, diff, 검색 또는 터미널을 열려면 구성원에게 Control Center 부여가 있어야 하고, 본인의 forge 로그인이 그 저장소를 읽을 수 있어야 합니다. 워크스페이스 관리자도 예외가 아니며, 서버 소유자만 예외입니다. [코드는 forge를 따릅니다](/ko-KR/매뉴얼/개념/권한-부여/#코드는-forge를-따릅니다)를 참고하세요.

forge 계정이 읽을 수 없는 사람에게 저장소를 부여하면 부여는 저장되고, "저장했습니다. 구성원의 GitHub 계정으로는 아직 이 리포지토리를 읽을 수 없어 구성원에게 표시되지 않습니다."와 같은 경고가 표시됩니다.

같은 규칙이 누가 스페이스를 열 수 있는지도 정합니다. 스페이스는 스페이스가 사용하는 모든 저장소의 코드를 열 수 있는 구성원에게만 열리며, 그 밖의 사람에게는 메시지, 검색 결과, 실행 로그, 할 일, 활동, 알림과 함께 숨겨집니다. 저장소가 없는 스페이스는 모든 구성원에게 열려 있습니다. [스페이스는 저장소를 따릅니다](/ko-KR/매뉴얼/개념/권한-부여/#스페이스는-저장소를-따릅니다)를 참고하세요.

## 저장소 제거

1. **설정 → 워크스페이스 → 리포지토리**를 엽니다.
2. 행의 휴지통 아이콘을 클릭합니다.
3. "워크스페이스에서 리포지토리를 제거할까요?"를 확인합니다.

대화 상자는 수행할 작업을 그대로 알려 줍니다: "*name*이(가) 이 워크스페이스에서
제거됩니다. 디스크의 로컬 파일은 변경되지 않습니다."

저장소를 제거하려면 워크스페이스 관리자가 필요합니다. 또한 그 저장소에 저장된 forge 자격 증명(예: GitLab 또는 Bitbucket 자동화 토큰)도 지웁니다.

제거하면 이 워크스페이스에서 저장소 행이 삭제되고, 그 저장소의 코드 그래프 행 —
심볼, 엣지, 파일, 인덱스 체크포인트 — 이 연쇄적으로 정리됩니다. 여기에 더해 그
저장소에 대한 멤버별 저장소 부여, 스페이스-저장소 연결, 격리된 체크아웃 기록도
함께 삭제됩니다. 다른 워크스페이스에 등록된 같은 체크아웃은 독립된 행이므로
영향을 받지 않습니다. 그 기록들이 가리키던 디스크상의 워크트리는 이 삭제로 함께
정리되지 않습니다.

## 문제 해결

### 부여는 있지만 계정이 저장소를 읽을 수 없습니다

본인의 forge 계정으로 저장소를 읽을 수 없으므로, 워크스페이스가 부여했더라도 Control Center는 코드를 본인에게 보여 주지 않습니다. 아직 로그인하지 않았다면 **설정 → 나 → 프로필 → 코드 호스팅**에서 forge에 로그인하거나, forge에서 저장소 소유자에게 접근 권한을 요청하세요. 본인의 forge 계정이 저장소를 읽을 수 있게 되면 저장소가 바로 열립니다.

### "이 폴더는 워크스페이스의 저장소 밖에 있습니다"

이 저장소의 폴더는 워크스페이스의 저장소 밖에 있고 서버 소유자가 연결하지 않았거나, 심볼릭 링크가 지금 다른 곳을 가리키고 있습니다. 서버 소유자가 확인하거나 폴더를 다시 추가할 때까지 목록에는 남지만 사용되지 않습니다. 본인이 소유자가 아니라면 소유자에게 요청하세요. 소유자라면 행의 **확인** 또는 목록 위의 **모두 확인**을 누르세요. [서버가 아직 사용하지 않는 폴더](#서버가-아직-사용하지-않는-폴더)를 참고하세요.

### "서버의 이 경로에는 더 이상 아무것도 없습니다"

서버 머신에서 폴더가 옮겨졌거나 삭제되었습니다. 폴더를 되돌려 놓거나, 워크스페이스 관리자가 알림의 **제거**로 저장소를 제거한 뒤 현재 폴더에서 다시 추가하세요.

### "이 폴더는 리포지토리로 사용할 수 없습니다"

저장된 폴더가 서버 자신의 데이터 폴더이거나, 그 안의 무엇이거나, 워크스페이스의 저장소 폴더 자체입니다. 이들 중 어떤 것도 저장소가 될 수 없습니다. 워크스페이스 관리자가 알림의 **제거**로 제거한 뒤 체크아웃의 실제 폴더에서 저장소를 다시 추가하세요.

### "포지 접근 권한을 확인할 수 없습니다"

Control Center가 본인 계정이 저장소를 읽을 수 있는지 확인하려고 forge에 연결하지 못해, 추측하는 대신 거부했습니다. 잠시 후 다시 시도하세요.
