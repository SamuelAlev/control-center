이 가이드는 설정 가운데 GitHub에 특화된 부분을 다룹니다. GitHub은 지원하는 세 가지
코드 호스트 중 하나입니다 — GitLab 또는 Bitbucket 연결과, 한 워크스페이스에서 여러
코드 호스트를 함께 쓰는 방법은
[코드 호스트 연결](/ko-KR/매뉴얼/사용-가이드/코드-호스트-연결/)을 참고하십시오.

## 사전 준비

- 작업하려는 저장소에 접근할 수 있는 GitHub 계정
- 사람들을 GitHub에 로그인시킬 수 있는 서버. 서버 자체 GitHub App
  ([GitHub App 만들기](/ko-KR/매뉴얼/사용-가이드/github-app/) 참고) 또는 Control Center
  Connect 중 하나이며, 서버 소유자가 **설정 → 서버 → 싱글 사인온**에서 고릅니다

:::note[자격 증명은 서버에 있고 본인에게 연결됩니다]
지금 입력 중인 기기에는 아무것도 저장되지 않습니다. GitHub 로그인은 사용자 id를 키로 삼아
`cc_server`가 보관하며, 로그인한 모든 기기에서 이를 사용합니다 — 데스크톱, 웹, 휴대폰
모두입니다. 같은 서버의 다른 구성원은 이를 사용할 수 없고, 그 구성원의 로그인은 본인이
직접 해야 합니다.
:::

## GitHub에 로그인

GitHub는 로그인 방식만 지원합니다. 붙여 넣을 토큰은 없습니다.

1. **설정 → 워크스페이스 → 프로필 및 신원 → 코드 호스팅**으로 이동합니다(또는 온보딩
   첫 단계에서)
2. **GitHub** 행에서 **GitHub에 로그인**을 클릭합니다
3. 브라우저에서 GitHub가 열립니다. 앱을 승인합니다

로그인이 끝나는 방식은 누가 로그인을 실행하느냐에 따라 다릅니다.

- **서버 자체 앱:** GitHub가 브라우저를 서버로 돌려보내고 대화 상자가 알아서 이를
  감지합니다. 입력할 것은 없습니다
- **Control Center Connect:** 브라우저 페이지에 8자리 코드가 표시됩니다. 이를 대화 상자에
  입력하거나, `control-center://` 링크를 통해 브라우저가 Control Center를 열도록 해 입력을
  건너뜁니다

확인: **GitHub** 행에 "_your-username_(으)로 로그인했습니다."가 표시됩니다.

대화 상자는 자신이 시작하지 않은 코드나 링크를 **여기서 시작한 로그인이 아닙니다**라고
표시하며 거부합니다. 누군가 로그인 링크를 보내오면 계속하지 마십시오. 완료하면 내 계정이
그 사람의 서버에 연결됩니다.

로그인을 제거하려면 **연결 해제**를 클릭합니다. GitHub에서 로그아웃하거나 워크스페이스에서
제거되면 서버가 나를 대신해 발급한 모든 토큰도 함께 폐기됩니다.

## 자격 증명이 누구를 대신하는가

- **내가 하는 일**(PR 페이지 열기, 리뷰 게시, 승인, 병합)은 **내** 로그인으로만 실행되며
  다른 것은 쓰이지 않습니다. 로그인하지 않았다면 앱이 그렇게 알리고 로그인하라고
  안내합니다. 다른 자격 증명이 나를 대신하는 일은 없습니다
- **아무도 입력하지 않는 작업**(에이전트 실행, 파이프라인, PR 폴링, 봇 답장, 클론)은
  서버의 GitHub App에서 또는 Connect를 통해 발급된 저장소 하나에 대한 토큰을 받습니다.
  이 토큰은 책임지는 멤버(요청한 사람, 아니면 워크스페이스 소유자)가 그곳에서 할 수 있는
  범위로 제한됩니다. 푸시할 수 없는 멤버라면 토큰은 읽기로 한정됩니다
- **자동화는 결코 풀 리퀘스트를 승인하지 않습니다**. 승인은 사람의 행위입니다

## 통합으로 얻는 것

| 기능                | 방법                                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------------------ |
| PR 목록과 세부 정보 | 서버에서 본인의 로그인으로 호출하는 GitHub REST API                                                    |
| 검사 실행           | GitHub Checks API                                                                                      |
| 리뷰 게시           | 사용자가 승인해야 진행되는 단계로, 내 리뷰를 나로서 PR에 게시합니다                                    |
| 저장소 등록         | 체크아웃의 `origin` 리모트가 github.com 또는 gitlab.com / bitbucket.org를 가리키면 등록이 허용됩니다    |
| 에이전트의 GitHub 접근 | 실행의 저장소 하나에 대한 토큰을 `GH_TOKEN` / `GITHUB_TOKEN`으로 주입합니다. 푸시는 Control Center를 거칩니다 |
| 알림 핑             | 서버가 GitHub 알림 받은편지함을 폴링해 "풀 리퀘스트에서 멘션됨"과 "리뷰 요청됨"을 발생시킵니다         |
| 사용자 프로필       | 프로필 호버 카드와 작성자별 PR 필터링                                                                  |

일부 경로는 더 저렴한 곳에서는 REST 대신 GraphQL API를 사용합니다 — PR 작성 화면의
브랜치 선택기에서 쓰는 브랜치 활동과, 리뷰 요청 알림이 아직 대기 중인지 판단하는
실시간 리뷰 상태가 그렇습니다.

## GitHub 장애 확인하기

제목 표시줄에는 GitHub, Claude, OpenAI, Kimi 가운데 제공자 하나가 저하된 상태일 때
상태 칩이 표시됩니다. **모두 정상일 때는 이 칩이 숨겨집니다** — 칩이 있다는 사실이
문제를 알리는 것이지, 칩이 없다는 사실이 문제를 알리는 것은 아닙니다.

칩을 클릭하면 각 제공자의 상태와 새로 고침 버튼이 있는 플라이아웃이 열립니다. 상태는
2분마다 자동으로 새로 고쳐집니다.

## 에이전트가 GitHub에서 작동하는 방식

- GitHub 워크트리에서 작업하는 에이전트는 그 저장소 하나에 대한 토큰을 받습니다.
  책임지는 멤버가 푸시할 수 있으면 코드를 읽고 풀 리퀘스트에 댓글을 달 수 있으며, 그렇지
  않으면 읽기만 할 수 있습니다. 푸시는 Control Center를 거치며, Control Center는
  **리모트에 푸시** 규칙에 물은 뒤 에이전트가 결코 갖지 않는 쓰기 토큰으로 이를 전달합니다.
  [샌드박스 정책 구성](/ko-KR/매뉴얼/사용-가이드/샌드박스-정책/)을 참고하십시오
- 에이전트 커밋은 항상 요청자의 Git 신원을 작성자와 커미터 모두에 사용합니다. 기본적으로 `Co-Authored-By: Control Center <hi@usectrl.dev>` 트레일러는 GitHub 계정 `@usectrl`을 공동 작성자로 표기합니다. **설정 → 나 → 커밋 기여자 표시**에서 신원을 변경하지 않고 이 공동 작성자 표시를 끌 수 있습니다. **설정 → 워크스페이스 → 일반**의 재정의가 우선하며 개인 토글을 잠급니다. Claude Code 자체의 기여 표시는 항상 비활성화됩니다. 커밋 서명에는 여전히 별도의 유효한 설정이 필요합니다
- 리그에서 연 터미널은 저장소 하나로 좁혀진 내 로그인을 받으므로, 그곳에서의 푸시는
  내 것이 됩니다
- 토큰을 발급할 수 없으면(책임지는 사람이 로그인하지 않았거나, 앱이 소유자에게 설치되지
  않았거나, 설치가 일시 중단된 경우) 실행은 토큰 없이 시작되고 그 이유가 실행 메모에
  남습니다. 폴백 자격 증명은 없습니다

## 문제 해결

### PR 목록이 비어 있으면서 GitHub이 연결되지 않았다고 표시됩니다

이 서버에서 GitHub에 로그인하지 않았습니다. **코드 호스팅**에서 **GitHub에 로그인**을
클릭하십시오. 다른 forge의 저장소는 영향을 받지 않습니다.

### GitHub 행에 이 서버에서는 로그인이 설정되지 않았다고 표시됩니다

서버에 자체 GitHub App도 Connect도 없습니다. 서버 소유자가 **설정 → 서버 → 싱글
사인온**에서 하나를 고릅니다. **내 GitHub 앱 만들기**는 약 2분이면 됩니다.
[GitHub App 만들기](/ko-KR/매뉴얼/사용-가이드/github-app/)를 참고하십시오.

### 대화 상자에 코드가 일치하지 않는다고 표시됩니다

브라우저에 표시된 그대로 코드를 입력하십시오. 영문자와 숫자 8자리입니다. 잘못된 코드를
다섯 번 입력하면 로그인이 끝나므로 다시 시작하십시오.

### 로그인 중 앱이 설치되어 있지 않다고 표시됩니다

저장소를 소유한 계정에 GitHub App 설치가 없습니다. 워크스페이스 관리자가 **설정 →
워크스페이스 → 일반 → GitHub 앱 설치**에서 설치합니다. Control Center의 공유 App을 쓰는
조직이라면 그 조직의 관리자가 **이 서버 승인**을 클릭해야 할 수 있습니다.
[GitHub App 만들기](/ko-KR/매뉴얼/사용-가이드/github-app/#조직에-대해-이-서버-승인하기)를
참고하십시오.

### 모두가 GitHub에 다시 로그인해야 합니다

서버 소유자가 서버의 Connect 키를 교체했거나, Connect 서버를 바꿨거나, 데이터 디렉터리가
다른 머신에 복원되었습니다. Connect를 통한 로그인은 그것을 만든 서버에 묶여 있습니다.

### 저장소 추가가 거부됩니다

등록에는 세 가지가 모두 필요합니다. 경로가 git 워크트리 안에 있고, `origin` 리모트가
있으며, 그 리모트가 지원되는 forge(github.com, gitlab.com 또는 bitbucket.org)를
가리켜야 합니다.
[워크스페이스에 저장소 추가](/ko-KR/매뉴얼/사용-가이드/저장소-추가/)를 참고하십시오.

### 많이 사용한 뒤 한동안 모든 것이 작동을 멈춥니다

속도 제한 서킷 브레이커입니다. GitHub은 `x-ratelimit-remaining: 0`과 재설정 시각을 담은
`403`으로 기본 한도에 도달했음을 알립니다. 이런 응답을 보면 클라이언트는 시간 창이
지날 때까지 네트워크 호출 없이 이후 요청을 로컬에서 실패시킵니다. 따라서 재시도 폭주가
한도를 더 악화시킬 수 없습니다. 일시적 실패는 `retry-after`를 준수하며 지수 백오프로
최대 세 번까지 재시도됩니다.
