이 가이드에서는 워크스페이스에 에이전트를 추가하고 실제로 실행될 때까지 구성하는 방법을 설명합니다.

모든 워크스페이스에는 다섯 개의 에이전트가 시딩됩니다. CEO 한 명과 `qa`, `architect`, `engineer`, `librarian`입니다. 따라서 아무것도 구성하기 전부터 에이전트가 있는 것이 보통입니다. 아래 단계는 시딩된 에이전트와 새 에이전트 모두에 똑같이 적용됩니다.

## 시작하기 전에

- 워크스페이스 안에서 작업합니다. 관련 화면은 모두 **설정 → 워크스페이스 → 에이전트**(`/settings/workspace/agents`)에 있습니다.
- 에이전트에는 백엔드가 필요합니다. **설정 → 서버 → 모델 제공업체**에서 내장 하네스용 프로바이더를 연결하거나, `cc_server`를 호스팅하는 머신에 Claude Code CLI를 설치합니다.
- 에이전트가 스킬을 지니게 하려면 먼저 **설정 → 워크스페이스 → 스킬**에서 스킬을 설치합니다. 에이전트 양식에서는 이미 워크스페이스에 존재하는 스킬만 켜고 끌 수 있습니다.

## 에이전트 추가

1. **설정 → 워크스페이스 → 에이전트**를 엽니다.
2. **새 에이전트**를 클릭합니다.

대화 상자도, 역할 선택기도 없습니다. "이름 없는 에이전트"라는 에이전트가 즉시 만들어지고 오른쪽 상세 창에서 선택됩니다.

이제 왼쪽 로스터에 "이름 없는 에이전트"가 보이고, 상세 창의 **설정** 탭이 열려 있으며 **이름** 필드에 "이름 없는 에이전트"가 들어 있어야 합니다.

## 이름 지정

- **이름** — @멘션에 사용되는 짧은 식별자입니다(예: `alice`). 멘션 파싱은 `@` 뒤에 단어 문자가 오는 형태를 인식하므로, 하이픈이나 마침표, 공백이 들어간 이름은 멘션될 수 없습니다.
- **제목** — 사람이 읽을 수 있는 레이블입니다(예: "숙련 개발자").
- **시스템 프롬프트** — 선택적 추가 지침이며, Agent instructions 섹션으로 주입됩니다. 조립된 프롬프트의 나머지 부분을 대체하지는 않습니다.

양식 맨 아래에서 **변경 사항 저장**을 클릭합니다. 이 페이지의 모든 필드는 이 버튼 하나로 저장됩니다.

## 어댑터와 모델 지정

**어댑터** 드롭다운에는 서버 호스트가 실제로 가지고 있는 러너가 나열됩니다. 내장 어댑터는 항상 검색됩니다(그 자체가 서버이기 때문입니다). Claude Code는 해당 호스트에서 CLI가 감지된 경우에만 나타납니다:

| 어댑터                    | 백엔드                                      |
| ------------------------- | ------------------------------------------- |
| Control Center (built-in) | 프로세스 내 에이전트 루프 — 외부 CLI 없음   |
| Claude Code               | `claude -p --output-format stream-json`     |

내장 어댑터만이 모드, 스티어링, 일시 중지/재개, 완료 계약, 서브에이전트를 강제합니다. Claude Code는 이 중 어느 것도 제공하지 않습니다. Cursor, Codex 및 기타 프로바이더는 별도의 러너가 아니라 내장 어댑터에 붙습니다.

:::note[어댑터가 비어 있으면 내장 루프를 사용합니다]
어댑터가 설정되지 않은 에이전트는 서버 내부의 루프인 **Control Center (built-in)**으로 디스패치되므로, 호스트에 아무것도 설치할 필요가 없습니다. 모델도 설정하지 않으면 Anthropic에 기본값을 요청하므로, 완전히 설정되지 않은 에이전트는 Anthropic 계정을 연결한 경우에만 실행됩니다. 시딩된 전문 에이전트는 둘 다 없이 제공되므로, 사용할 에이전트에는 두 가지를 모두 설정하세요.
:::

**모델** 드롭다운은 선택한 어댑터에 따라 달라집니다. 내장 어댑터의 경우 목록은 **설정 → 서버 → 모델 제공업체**에서 연결한 프로바이더에서 실시간으로 가져오므로, 저장된 자격 증명이 없는 프로바이더는 모델을 하나도 제공하지 않습니다.

## 스킬 추가

**스킬**은 이 워크스페이스에 설치된 스킬 번들을 대상으로 하는 칩 선택기입니다. 칩을 눌러 켜고 끄며, 체크 글리프가 선택된 칩을 나타냅니다. 워크스페이스에 스킬이 없으면 이 필드에는 "No skills available. Create skills in Settings → Skills first."가 표시됩니다.

여기서는 저장소 자체의 스킬을 고르지 않습니다. 스킬을 함께 제공하는 저장소(`.agents/skills/`, `.claude/skills/`, `.opencode/skills/`)는 그 저장소에서 작업하는 에이전트에게 스킬을 자동으로 제공하며, 에이전트가 다른 저장소로 옮기면 스킬도 교체됩니다. 자세한 내용은 [저장소 범위 스킬](/ko-KR/매뉴얼/개념/에이전트-모델/#repo-scoped-skills)을 참고하세요.

## 보고 체계와 페르소나 설정

- **보고 대상** — 다른 에이전트를 이름으로 고릅니다. 이것이 페이지 헤더의 **조직도** 버튼에 표시되는 보고 트리를 만듭니다. 팀 리더가 위임할 때 사용하는 명단은 이것이 아닙니다. 그 명단은 팀의 멤버와 그들의 스킬에서 나옵니다.
- **페르소나** — 어조와 행동을 형성하는 자유 텍스트입니다. 예: "단순하고 읽기 쉬운 해법을 선호합니다. 모든 새 코드에 테스트를 작성합니다."

## 실행 조정

- **추론 강도** — 선택지는 선택한 모델이 자체적으로 공개한 수준에서 나옵니다. Low / Medium / High, 그리고 OpenAI 스타일 모델에서는 Extra High, Claude 스타일 모델에서는 Extra High + Max가 추가됩니다. 선택한 모델이 사고 수준을 선언하지 않으면 이 필드는 완전히 숨겨지고, 모델 자체의 기본값이 적용됩니다.
- **컨텍스트 윈도우 크기** — 모델을 변경할 때마다 해당 모델의 컨텍스트 윈도우로 미리 채워지며, 모델 기본값, 200k, 500k, 1M을 위한 원탭 칩이 있습니다. 모델을 고른 뒤 직접 입력한 값은 다음 모델 변경 전까지 우선합니다.
- **무응답 제한 시간(분)** — 이 시간 동안 출력이 없으면 실행을 종료합니다. 비워 두면 모드별 기본값을 사용합니다.

## 권한 부여

**샌드박스 권한**은 "워크스페이스 기본값 사용"에서 시작합니다. 스위치를 켜면 이 에이전트에 대해 권한을 설정할 수 있으며, 그다음 다음 항목을 켜고 끕니다:

- **git push 허용** — 에이전트가 푸시하는 데 필요한 GitHub 토큰을 주입합니다
- **GitHub API 호출 허용** — 에이전트가 PR, 이슈, 저장소 메타데이터를 읽을 수 있게 합니다
- **티켓팅 API 호출 허용** — 티켓팅 프로바이더 키를 주입합니다
- **일반 네트워크 접근 허용** — 내장 하네스의 `web_fetch` 및 `web_search` 도구도 사용하도록 설정합니다

각 토글은 실행이 시작될 때 자격 증명 브로커가 확인합니다. 기능이 꺼져 있으면 해당 토큰이 실행 환경에 발급되지 않을 뿐입니다.

:::caution[워크스페이스 기본값은 서버의 보수적인 집합을 뜻합니다]
"워크스페이스 기본값 사용"으로 남겨 둔 에이전트는 git push, GitHub API, 티켓팅이 모두 **꺼진** 상태로, 네트워크는 **켜진** 상태로 실행됩니다. 설정 → 서버 → 진단 및 개인정보 보호에 표시되는 기능 기본값은 클라이언트 측 기본 설정입니다. 에이전트가 푸시하거나 PR을 열게 하려면 스위치를 켜고 해당 기능을 명시적으로 부여하세요.

이 기능들은 자격 증명과 하네스 도구를 게이트하며, 이는 OS 샌드박스와는 별개의 계층입니다. `cc_server`는 샌드박스가 있는 호스트에서 에이전트 실행을 호스트의 샌드박스로 감쌉니다. Windows에는 네이티브 백엔드가 없고, Linux와 WSL2에는 `bwrap`과 `socat`이 필요합니다. 경계의 전체 목록은 [샌드박스와 보안](/ko-KR/매뉴얼/개념/샌드박스와-보안/)을 참고하세요.
:::

## 실행 확인

1. **설정 → 서버 → 모델 제공업체**를 열고 선택한 어댑터가 "찾을 수 없음"이 아니라 설치된 버전을 보고하는지 확인합니다. **새로 고침**을 클릭하면 다시 프로브합니다. 프로브는 지금 보고 있는 머신이 아니라 `cc_server`를 호스팅하는 머신에서 실행됩니다.
2. 해당 에이전트가 있는 스페이스를 열고 메시지를 보내거나, 기존 스페이스에서 @멘션합니다.
3. **설정 → 워크스페이스 → 에이전트**로 돌아와 에이전트를 선택하고 **로그** 탭을 엽니다. 상태 배지, 기간, 시작 시각, 사용한 어댑터와 함께 실행이 나타나야 합니다. **보기**를 클릭하면 해당 실행의 이벤트 스트림이 열립니다.

실행이 전혀 나타나지 않으면 [에이전트 진단](/ko-KR/매뉴얼/사용-가이드/에이전트-진단/)을 차례로 확인하세요.

## 에이전트 삭제

로스터에서 에이전트를 선택합니다. **설정** 탭에서 양식 맨 아래의 **위험 영역**으로 스크롤한 뒤 **삭제**를 클릭합니다.
