이 가이드에서는 Google Calendar를 워크스페이스에 연결하는 방법을 설명합니다.
연결은 워크스페이스 단위이자 멤버 단위이며, 해당 워크스페이스에서 내 일정을 Control Center에 동기화하며, 그곳에서 초대에 응답하고 새 일정을 예약, 이동 또는 삭제할 수도 있습니다. 전체 그림은
[캘린더와 일정](/ko-KR/매뉴얼/개념/캘린더/)을 참고하세요.

## 사전 요구 사항

- 서버가 사람들을 Google에 로그인시킬 수 있어야 합니다. Control Center Connect를 통하거나
  서버 자체 Google 클라이언트로 합니다
  ([자체 Google 클라이언트 사용](#자체-google-클라이언트-사용)). 어느 쪽을 쓸지는 서버
  소유자가 **설정 → 서버 → 싱글 사인온**에서 고릅니다
- 열려 있는 워크스페이스. 캘린더 계정은 항상 워크스페이스 하나에 속합니다

## 계정 연결

1. 사이드바에서 **캘린더**를 엽니다.
2. 캘린더 사이드바에서 **캘린더 계정 추가**를 클릭합니다. (같은 섹션은 **설정 → 워크스페이스 → 프로필 및 신원**의 **Google Calendar** 아래에도 있습니다.)
3. **Google Calendar 연결**을 클릭합니다. 브라우저에서 Google 동의 페이지가 열립니다.
4. 계정을 고르고 캘린더 일정과 캘린더 목록에 대한 액세스를 승인합니다.

끝나는 방식은 누가 로그인을 실행하느냐에 따라 다릅니다.

- **서버 자체 Google 클라이언트:** Google이 브라우저를 서버로 돌려보내고 대화 상자가
  저절로 닫힙니다
- **Control Center Connect:** 브라우저 페이지에 8자리 코드가 표시됩니다. 이를 대화 상자에
  입력하거나, `control-center://` 링크를 통해 브라우저가 Control Center를 열도록 해 입력을
  건너뜁니다

일정 동기화는 바로 시작됩니다. 교환을 마치고 자격 증명을 보관하는 주체는 내 기기가 아니라
서버입니다.

계정은 **활성 워크스페이스에만** 연결되며 내 것입니다. 같은 Google 주소를 연결한 두
멤버에게는 별도의 계정이 생깁니다. 워크스페이스를 전환하면 그 워크스페이스의 캘린더가
대신 표시됩니다.

연결 플로는 어떤 클라이언트로 실행하든 `calendar.events`와 `calendar.calendarlist.readonly`, 그리고 `openid email`을 요청합니다.
Control Center가 Google에 쓸 수 있기 전에 연결된 계정은 읽기 전용 범위만 가지므로, 다시 연결하라는 안내가 나오며 새 로그인에서 나머지 범위가 부여됩니다.

## 일정 예약, 이동, 응답, 삭제

- **일정 예약:** 주 또는 일 뷰에서 시간 그리드를 드래그해 구간을 지정합니다(월 뷰에서는 날짜를 가로질러 드래그하면 종일 일정이 됩니다). 제목, 시간, 게스트, Google Meet 링크, 위치, 설명, 예약할 캘린더가 담긴 카드가 옆에 열립니다. **저장**을 누르면 Google에 예약되고 해당 일정이 열립니다. 캘린더 헤더의 **+** 버튼은 다음 빈 15분 단위에 대해 같은 카드를 엽니다. Escape를 누르면 취소됩니다
- **일정 이동:** 일정을 다른 시간이나 날짜로 드래그하거나, 아래쪽 가장자리를 드래그해 종료 시간을 바꿉니다. Google이 새 시간을 받아들이면 새 시간에 표시되고, 거부하면 원래 자리로 돌아갑니다. 이동할 수 있는 것은 내 일정과 내가 주최한 일정뿐이며, 초대는 주최자가 둔 자리에 그대로 남습니다
- **초대에 응답:** 일정을 열고 **예**, **미정**, **아니요** 중 하나를 선택합니다
- **일정 삭제:** 일정을 열고 휴지통 아이콘을 클릭합니다. 확인 창에는 영향을 받는 사람이 표시됩니다. 내가 주최한 일정은 게스트에게 취소되었다고 알리고, 초대를 삭제하면 내 캘린더에서만 제거됩니다. 반복 일정의 한 발생을 삭제해도 시리즈의 나머지는 남습니다

게스트는 Google이 보내는 초대, 업데이트 또는 취소 이메일을 받습니다. 반복 일정의 한 발생을 이동해도 시리즈의 나머지는 남습니다. 계정이 쓰기 권한을 가진 캘린더에만, 그리고 내 계정으로만 예약할 수 있습니다. 다른 멤버가 연결한 캘린더는 절대 제안되지 않습니다.

## 동기화 방식

일정을 소유하는 주체는 **서버**입니다. 서버는 2분마다 모든 워크스페이스의
연결된 계정을 스윕하고 해당 워크스페이스의 데이터베이스에 일정을 기록합니다.
클라이언트는 Google과 직접 통신하지 않고, 서버가 기록한 내용을 읽습니다.

스윕은 증분 방식입니다. 캘린더별 첫 번째 패스는 롤링 윈도(60일 전부터 90일
후까지)를 가져오고 Google의 동기화 토큰을 저장합니다. 이후 패스는 그 토큰을
제시하고 변경된 부분만 받으며, 덕분에 2분 주기를 감당할 수 있습니다. 이
윈도는 24시간마다, 그리고 Google이 토큰을 무효화할 때마다 전체 동기화로
기준을 다시 잡습니다.

자격 증명은 서버 측에서 서버의 데이터 디렉터리 아래 `secrets.json`에 저장되고 소유자
전용 권한(`0600`)으로 기록됩니다 — OS 키체인에 저장되지 않으며, 클라이언트 기기에
저장되는 일도 없습니다. Connect를 통한 로그인은 Connect가 이 서버만을 위해 열 수 있는
봉인된 자격 증명만 저장하며, 그 액세스 토큰은 서버의 메모리에만 머뭅니다.

## 여러 계정 연결

워크스페이스에는 여러 Google 계정을 연결할 수 있습니다(예: 업무용과 개인용).
계정마다 연결 단계를 반복하세요. 각 계정의 일정은 같은 월 / 주 / 아젠다 보기에
합쳐집니다. 각 계정은 독립적으로 동기화되고 갱신되며, 개별적으로 연결을 해제할
수 있습니다.

## 만료된 계정 다시 연결

Google이 계정의 로그인을 영구적으로 무효화하면(세션이 취소되었거나 오랫동안
만료된 경우), 동기화가 중단되고 Control Center는 캘린더에 **다시 연결** 배너와
데스크톱 알림을 표시합니다. **다시 연결**을 클릭하고 다시 로그인하면, 다음
동기화가 성공할 때 배너가 사라집니다.

이 서버가 그 로그인을 더 이상 사용할 수 없을 때도 같은 배너가 나타납니다. 서버 소유자가
Connect 서버를 바꿨거나 Connect 키를 교체한 경우, 서버 자체 Google 클라이언트가 바뀐 경우,
또는 데이터 디렉터리가 다른 머신에 복원된 경우입니다.

## 계정 연결 해제

캘린더 사이드바(또는 **설정 → 워크스페이스 → 프로필 및 신원**)에서 해당 계정의
**연결 해제**를 클릭합니다. 그러면 그 계정의 동기화된 일정이 삭제되고 서버에
저장된 자격 증명이 지워집니다.

## 자체 Google 클라이언트 사용

**내 앱 사용**을 골랐을 때만 자체 Google 클라이언트를 운영하세요. 서버의 클라이언트는 그 경우에만 적용됩니다. Control Center 또는 사용자 지정 Connect를 쓰면 Connect가 Google을 포함한 모든 레인을 담당하고, 서버 클라이언트는 저장만 되고 사용되지 않습니다. 서버가 Connect를 쓰면서 동의 화면에 내 프로젝트 이름을 보이게 하려면 워크스페이스에 자체 클라이언트를 설정하세요([아래](#워크스페이스에-자체-google-클라이언트-설정하기)). 이는 모든 모드에서 적용됩니다.

1. [Google Cloud Console](https://console.cloud.google.com/apis/credentials)에서 **Google Calendar API**를 사용 설정하고 **OAuth 동의 화면**을 구성하면서 `calendar.events`, `calendar.calendarlist.readonly`, `openid`, `email` 범위를 추가합니다. 앱이 확인되지 않은 동안에는 자신을 **테스트 사용자**로 추가합니다.2. 애플리케이션 유형이 **웹 애플리케이션**인 **OAuth 클라이언트 ID**를 만듭니다.
3. 승인된 리디렉션 URI `<server origin>/oauth/google/callback`을 추가합니다. **설정 → 서버 → 싱글 사인온 → 프로바이더 앱 → Google**의 **콜백 URL**에 정확한 URL이 표시되므로 그대로 복사합니다.
4. **클라이언트 ID**와 **클라이언트 시크릿**을 그 Google 블록에 붙여 넣거나, 서버의 `.env` 파일에 `GOOGLE_OAUTH_CLIENT_ID`와 `GOOGLE_OAUTH_CLIENT_SECRET`으로 넣습니다.

`GOOGLE_OAUTH_CLIENT_SECRET`이 프로세스 환경에 내보내져 있으면 서버가 시작을 거부합니다.
`.env` 파일에 두세요(Docker에서는 `/app/bin/.env`에 마운트합니다). 시크릿은 서버를
벗어나지 않으며, 어떤 RPC 응답에도 포함되지 않습니다. 시크릿 없는 클라이언트 ID는
완료되지 않은 설정이며, 둘 다 설정될 때까지 Google 로그인이 거부됩니다.

다른 클라이언트로 바꾸면 모두가 Google Calendar에서 로그아웃됩니다. 로그인은 그것을
발급한 클라이언트에 속하기 때문입니다.

## 워크스페이스에 자체 Google 클라이언트 설정하기

워크스페이스는 서버 대신 자체 클라이언트를 사용해 Google Calendar에 연결할 수 있습니다. 워크스페이스 관리자 또는 소유자만 설정할 수 있습니다.

1. 위의 1번과 2번 단계처럼 Google **웹 애플리케이션** 클라이언트를 만듭니다
2. **설정 → 워크스페이스 → 일반 → 프로바이더 앱**으로 이동해 **Google Calendar**를 엽니다
3. **이 워크스페이스의 앱 사용**을 선택합니다
4. 행의 **콜백 URL**에 표시되는 리디렉션 URI를 그대로 클라이언트에 추가합니다
5. **클라이언트 ID**와 **클라이언트 시크릿**을 붙여 넣습니다

이 워크스페이스에서 연결된 캘린더 계정은 서버가 사람들을 로그인시키는 방식과 관계없이 그 클라이언트를 사용합니다. 서버 클라이언트나 Connect로 대체되지 않습니다. 두 필드가 모두 설정되기 전까지 이 워크스페이스에서는 Google Calendar가 꺼져 있고, 해당 행에 무엇이 부족한지 표시됩니다. 시크릿은 서버를 떠나지 않습니다.

서버 클라이언트와 워크스페이스 클라이언트를 전환하거나 워크스페이스 클라이언트 ID를 바꾸면, 이 워크스페이스의 모든 Google 계정이 다시 연결해야 하도록 표시됩니다. **이 서버의 앱 사용**을 선택하면 워크스페이스에 저장된 필드가 삭제됩니다. 서버의 다른 워크스페이스는 영향을 받지 않습니다.

## 문제 해결

| 증상                                                | 가능한 원인                                                                                                                                           |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Google Calendar 연결**에 로그인이 설정되지 않았다고 표시됨 | 서버에 자체 Google 클라이언트도 Connect도 없습니다. 서버 소유자가 **설정 → 서버 → 싱글 사인온**에서 하나를 고릅니다                         |
| Google에 `redirect_uri_mismatch` 표시               | 클라이언트에 등록한 리디렉션이 **콜백 URL** 값과 정확히 일치하지 않거나, 서버의 공개 URL이 바뀌었습니다                                              |
| Google에서 `invalid_client` 반환                    | ID와 시크릿이 서로 다른 클라이언트의 것이거나, 클라이언트가 삭제되었습니다                                                                           |
| 승인은 성공했지만 동기화 결과가 비어 있음           | 동의 화면에서 내 계정이 **테스트 사용자**가 아니거나 요청한 범위 중 일부가 부여되지 않았습니다                                                        |
| 대화 상자에 코드가 일치하지 않는다고 표시됨         | 브라우저에 표시된 8자리를 정확히 입력하세요. 잘못된 코드를 다섯 번 입력하면 로그인이 끝나므로 다시 시작하세요                                         |
| RSVP에서 "응답을 업데이트할 수 없습니다" 표시, 또는 예약·이동·삭제 실패       | 계정이 이전 읽기 전용 범위로 연결되었습니다. 다시 연결하세요. 읽기 전용으로 공유된 캘린더는 쓰기도 거부합니다                                                                                  |
| 모두가 다시 연결해야 함                             | 서버 또는 워크스페이스의 Google 클라이언트가 바뀌었거나, 서버의 Connect 선택 또는 키가 바뀌었습니다. [만료된 계정 다시 연결](#만료된-계정-다시-연결)을 참고하세요              |
