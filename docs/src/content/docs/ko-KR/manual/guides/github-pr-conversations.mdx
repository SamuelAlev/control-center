이 가이드에서는 GitHub를 벗어나지 않고 Control Center로 작업하는 방법을
설명합니다. PR 페이지에서 AI 리뷰를 요청하고, 댓글로 봇에게 질문하고, 봇의
리뷰 스레드에서 대화를 이어 갈 수 있습니다.

답글은 워크스페이스의 GitHub 레인을 통해 옵니다. 서버 자체의
[GitHub App](/ko-KR/매뉴얼/사용-가이드/github-app/)이거나, Connect를 통한 Control
Center의 공유 App입니다. 새로 등록하는 것은 없고, 인터넷에서 접근 가능해야 하는
것도 없습니다. 서버는 폴링으로 GitHub에서 오간 말을 알아내므로, NAT 뒤의
노트북도 공개 배포와 똑같이 동작합니다.

## 사전 준비

- 워크스페이스에 GitHub 레인이 있어야 합니다. 서버 자체 GitHub App 또는 Connect이며,
  앱이 저장소를 소유한 계정에
  [설치](/ko-KR/매뉴얼/사용-가이드/github-app/#저장소가-있는-곳에-설치하기)되어 있어야
  합니다. 자체 앱에는 **Pull requests**와 **Issues**의 읽기 및 쓰기 권한이 필요하며,
  **내 GitHub 앱 만들기**가 이미 이를 부여합니다
- 저장소가 Control Center의 워크스페이스에 연결되어 있어야 합니다
- 이 서버에서 [GitHub에 로그인](/ko-KR/매뉴얼/사용-가이드/github-통합/)되어 있고,
  저장소에 푸시할 수 있어야 합니다
- 웹훅 URL도, 터널도, 콜백도 필요 없습니다 — 네트워크 쪽에서 구성할 것은
  아무것도 없습니다

## 봇의 이름 찾기

Control Center 전용 GitHub 계정인 `@usectrl`을 멘션하세요. 유일한 호출 방식입니다. 앱 자체 로그인을 멘션해도 아무 일도 일어나지 않습니다.
요청 처리와 답글 게시는 계속 워크스페이스의 GitHub 레인이 담당합니다. `usectrl`
계정의 자격 증명은 필요하지 않습니다.

## GitHub에서 리뷰 요청하기

두 가지 방법이 있으며, 둘 다 **AI에게 물어보기** 버튼이 시작하는 것과 같은
시드된 `pr_review` 파이프라인을 시작합니다.

- PR에 **`ai-review` 레이블을 추가합니다**. GitHub에서 봇을 리뷰어로 지정하는
  것에 가장 가까운 방법입니다 — 앱 계정은 GitHub의 기본 리뷰 요청자 자리를
  차지할 수 없습니다. 여러분의 계정이 PR에 👀로 반응하고 리뷰가 Control
  Center에서 시작됩니다. 댓글은 게시되지 않습니다
- PR 대화에 **`@usectrl review`**라고 댓글을 답니다(또는 `@usectrl`만). 댓글에
  👀가 붙은 뒤, 리뷰가 시작되었다고(또는 이미 실행 중이라고) 답글이 달립니다

리뷰어들은 PR의 리뷰 스페이스에서 작업합니다. 발견 사항을 읽고 게시하는 방법은
[AI 기반 리뷰 사용](/ko-KR/매뉴얼/사용-가이드/ai-리뷰/)과 같습니다. GitHub로 다시
게시하는 것은 여전히 Control Center에서 내리는 결정입니다 — GitHub에서 리뷰를
시작해도 저절로 GitHub에 게시되는 것은 없습니다.

레이블은 PR당 한 번만 작동합니다. 추가하는 것이 곧 요청이며, 뗐다가 다시 붙여도
다시 무장되지 않습니다. 푸시 후처럼 리뷰를 다시 실행하려면 봇을 멘션하세요.

## 질문하기

PR 대화에 댓글을 답니다:

```text
@usectrl why does the flaky test in runner_test.dart fail on CI but not locally?
```

순서대로 일어나는 일은 다음과 같습니다.

1. 댓글이 확인되었다는 표시로 여러분 자신의 계정에서 댓글에 👀가 붙습니다
2. 질문이 **여러분으로서** PR의 리뷰 스페이스에 게시됩니다 — Control Center에서
   직접 입력한 것과 같은 귀속입니다
3. 에이전트가 스페이스에서 답하고, 그 답변이 PR에 다시 게시됩니다. 모든 답글은
   `**Control Center** (for @your-login):`으로 시작합니다

아직 리뷰가 없는 PR의 질문은 워크스페이스의 CEO 에이전트를 깨웁니다. 리뷰가 한
번 실행된 뒤에는 마지막으로 발언한 에이전트가 답하므로, 후속 질문은 맥락을 가진
쪽에 도달합니다.

## 리뷰 스레드에서 후속 질문하기

봇이 참여하고 있는 인라인 리뷰 스레드 안에서 답장합니다 — 봇이 남긴 diff
댓글이나 그 스레드에 게시한 답변입니다. 멘션은 필요 없습니다. 스레드
**자체가** 주소 지정입니다:

```text
> @usectrl the retry loop looks O(n²) to me

what would the complexity be with the bounded queue instead?
```

여러 턴의 대화도 같은 방식입니다. 각 답장은 같은 대화의 또 다른 질문이며 리뷰
스페이스를 맥락으로 삼고, 답변은 그 스레드로 돌아옵니다.

PR 대화 타임라인에 남기는 후속 글은 새로운 최상위 댓글이므로 여전히 @멘션이
필요합니다.

## 봇이 누구와 대화하는지

서버는 무엇이든 하기 전에 댓글의 작성자, 또는 `ai-review` 레이블을 붙인 사람을
확인합니다.

- **그 GitHub 계정이 이 서버에 로그인되어 있어야 합니다**. 대조는 로그인이 아니라
  GitHub의 숫자 계정 id로 이루어집니다. **설정 → 나 → 프로필 →
  코드 호스팅**에서 로그인합니다
- **저장소를 연결한 워크스페이스에서 쓰기 역할(`member`, `admin`, `owner`)을
  가진 멤버여야 합니다**
- **GitHub에서 그 저장소에 푸시할 수 있어야 합니다**. 답글은 그 사람의 접근
  권한으로 제한된 토큰을 쓰므로, 읽기만 할 수 있는 사람에게는 답글이 가지
  않습니다

그 외의 사람은 조용히 무시됩니다. 아무것도 게시되지 않으며, 그들의 말은 결코
워크스페이스에 들어가지 않습니다. 봇의 댓글과 Control Center 자신의 답글은 결코
질문으로 취급되지 않습니다.

### 두 서버, 하나의 PR

👀는 어느 서버가 답할지 서버들이 합의하는 방법이기도 합니다. 리액션은 작성자 자신의
로그인으로 추가되며, GitHub는 그 리액션이 새것인지 서버에 알려 줍니다. 둘 다 그
저장소를 연결한 두 Control Center 서버에 로그인해 있으면, 먼저 리액션을 단 서버가
답하고 다른 서버는 침묵합니다. 레이블도 마찬가지입니다.

## 예상되는 동작

| 항목                | 동작                                                                     |
| ------------------- | ------------------------------------------------------------------------ |
| 확인                | 스윕 한 번 안에 여러분의 계정에서 댓글(레이블의 경우 PR)에 👀가 붙습니다 |
| 답변                | 질문이 제기된 레인에 게시되며, `**Control Center** (for @your-login):`으로 시작합니다. 작성자는 앱의 봇입니다. 공유 Connect 앱의 리뷰 스레드 안 답변은 여러분의 계정으로 작성되며, 단 Connect 운영자가 이 설치를 목록에 올린 경우는 예외입니다 |
| 스페이스 내 귀속    | 질문은 여러분의 것이고, 에이전트는 스페이스의 자율성 설정에 따라 여러분을 대신해 실행됩니다 |
| 리뷰                | 발견 사항은 리뷰 스페이스에 쌓이고, GitHub 게시는 수동입니다             |

스윕은 자체 앱에서 1분마다 실행되어 최대 25개의 풀 리퀘스트를 확인합니다.
Connect를 거치면 그 호출들이 각 멤버 자신의 GitHub 할당량을 공유하므로 2분마다
실행되어 최대 10개를 확인합니다. GitHub 할당량이 15% 미만인 워크스페이스는 회복될
때까지 건너뜁니다. 이 지연은 인바운드 네트워크 접근이 전혀 필요 없다는 점과 맞바꾼
대가입니다. 서버가 오프라인인 동안에도 잃는 것은 없습니다 — 중단 중에 도착한
댓글은 다음 스윕에서 수집됩니다.

## 문제 해결

**봇을 멘션한 댓글에 아무 일도 일어나지 않습니다.**

- 저장소를 소유한 계정에 앱이 **설치**되어 있고, 저장소가 워크스페이스에
  **연결**되어 있나요? 연결되지 않은 저장소는 아무것도 기록되기 전에
  건너뛰므로, 나중에 연결해도 여전히 전달됩니다
- 이 서버에서 GitHub에 로그인되어 있고, 쓰기 역할을 가진 멤버이며, 저장소에
  푸시할 수 있나요? 서버는 그 외의 사람을 답글 없이 무시합니다
- 그래도 아무 일이 없나요? 실패하면 서버 로그에 스윕과 PR이 기록됩니다.
  `pr_conversation:`(폴러)과 `github_pr_conversation:`(브리지)를 찾아보세요

**레이블이 리뷰를 시작하지 않습니다.**

레이블은 PR당 한 번만 작동하며, 그것을 붙인 사람은 댓글 작성자와 같은 검사를
거칩니다. 리뷰가 이미 실행되었거나, 서버가 PR을 보기도 전에 레이블이
추가되었다면(첫 스윕은 밀린 댓글에 몰려들지 않고 조용히 기록합니다), 대신 봇을
멘션하세요 — 이미 리뷰가 진행 중이지만 않다면 `@usectrl review`가 항상 리뷰를
시작합니다.

**봇의 답변이 GitHub에 도착하지 않았습니다.**

답변 자체는 결코 사라지지 않습니다 — Control Center의 PR 리뷰 스페이스에
있습니다. 게시 실패(GitHub 장애, 권한 변경)는 로그에 기록되고 답변은
재시도되지 않으므로, 중요하다면 스레드에서 다시 질문하세요.
