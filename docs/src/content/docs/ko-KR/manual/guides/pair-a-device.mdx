이 가이드에서는 휴대폰을 Control Center와 페어링해 어디서든 메시지와 티켓을
읽고 답장하는 방법을 보여 줍니다. 같은 흐름으로 두 번째 브라우저나 데스크톱
앱도 페어링할 수 있습니다. 링크가 작동하는 방식과 보안 모델은
[원격 제어와 모바일](/ko-KR/매뉴얼/개념/원격-제어/)을 참고하세요.

## 사전 요구 사항

- 서버에 연결된 데스크톱 또는 웹 클라이언트와 설정된 워크스페이스. 페어링 작업에는 풀 클라이언트가 필요하므로, 페어링된 휴대폰은 다른 기기를 페어링하거나 해지할 수 없습니다.
- 페어링하려는 기기에서 서버에 접근할 수 있어야 합니다. 같은 네트워크에서는 그냥 작동하고, 더 멀리 있으면 브로커를 거치는 릴레이가 트래픽을 나릅니다. 패널이 QR이나 자격 증명 대신 **접근 불가**로 응답하면 먼저 서버로 가는 경로를 공개하세요 — **설정 → 서버 → 연결 및 상태**의 터널 옵트인(**이 서버 공유**), 또는 서버의 `--public-url`입니다([헤드리스 서버 실행](/ko-KR/매뉴얼/사용-가이드/헤드리스-서버-실행/) 참고).
- 휴대폰의 경우: 설치할 것이 없습니다. QR을 스캔하면 **Remote** 웹 앱(기본값은 [remote.usectrl.dev](https://remote.usectrl.dev/))이 열립니다.

**자체 호스팅.** Remote와 릴레이 브로커는 이 저장소에서 오픈 소스입니다: 휴대폰
앱(`apps/cc_remote`, `wrangler.jsonc`를 통해 Cloudflare Pages에, `docker/cc_remote`
nginx 이미지에, 또는 HTTPS를 지원하는 아무 정적 호스트에나 배포할 수 있는
Flutter 웹 PWA — 서비스 워커와 IndexedDB는 보안 컨텍스트에서만 사용할 수
있습니다)과 릴레이(`apps/cc_signaling_server`, 앱 데이터를 보유하지 않고 페어링
비밀을 결코 보지 않으며 종단 간 봉인된 프레임만 전달하는 무상태 Dart 바이너리
하나)입니다. 빌드 및 실행 단계는 각 README를 참고하세요.

## 1단계: 페어링 패널 열기

**설정 → 나 → 내 기기**를 엽니다. **내 기기** 섹션에는 이 서버에서 내 계정에
페어링된 클라이언트가 나열됩니다. (서버 소유자는 서버의 모든 기기를 보고,
그 외의 사용자는 자신의 기기만 봅니다.)

## 2단계: 새 클라이언트 페어링

페이지 헤더에서 **새 클라이언트 페어링**을 클릭하고 이름을 지정한
다음(예: "내 휴대폰"), 유형 — **웹 브라우저**, **데스크톱 앱**, **휴대폰** — 을
고르고 **페어링**을 클릭합니다.

- **휴대폰**의 경우 QR 코드가 나타납니다. 휴대폰 카메라로 스캔하거나, 링크를 복사해 아무 브라우저에서나 여세요. 이 링크는 Remote 앱을 서버로 향하게 하고 자격 증명을 담고 있습니다.
- **브라우저**나 **데스크톱**의 경우에는 표시된 링크(또는 기기 id와 페어링 키)를 새 클라이언트에 복사해 넣으세요. 원탭 링크는 웹 클라이언트에서 페어링할 때만 제공됩니다. 데스크톱 바이너리에는 링크를 만들 웹 오리진이 없기 때문입니다.

휴대폰 QR과 CLI에서 `cc_server pair --client-url`이 출력하는 링크는 **서로 다른
페이로드이며 호환되지 않습니다**: CLI 링크는 웹 클라이언트의 연결 양식을
채우는 반면, 이 QR은 Remote PWA를 위해 서버의 전체 연결 디스크립터와 신원
지문을 담고 있습니다.

휴대폰 쪽에서 페어링 링크를 열어도 조용히 페어링되지 않습니다. Remote는 서버가
알리는 이름을 보여 주고 무엇이든 저장하기 전에 확인을 요청하므로, 위조된
링크로 앱을 다른 사람의 서버로 가로챌 수 없습니다.

:::caution[스캔한 QR은 즉시 접근 권한을 부여합니다]
대기 후 승인하는 단계는 없습니다: 발급된 기기는 생성되는 순간부터 활성
상태이고, 연결 게이트는 자격 증명이 활성이며 만료되지 않았는지만 확인합니다.
QR과 페어링 키를 비밀번호처럼 취급하고, 넘겨줄 의도가 없었던 것은 무엇이든
해지하세요.
:::

## 페어링된 기기 관리

**설정 → 나 → 내 기기**에서 다음을 할 수 있습니다:

- 기기 **이름 바꾸기**
- 더 이상 신뢰하지 않는 기기 **해지**. 해지하면 자격 증명이 파괴되고 열려 있는 세션이 몇 초 안에 끊기므로, 다시 연결할 때 닫힌 상태로 실패합니다

분실했거나 교체한 휴대폰에는 해지가 적절한 조치입니다. 기기 입장에서는 즉시,
되돌릴 수 없이 적용됩니다.

이 패널에서 발급한 자격 증명은 시간이 제한됩니다: 발급되고 30일 후에 만료되며,
그 이후에는 연결 게이트가 이를 닫힌 상태로 실패 처리합니다. 명령줄에서
`cc_server pair`로 발급한 자격 증명은 **만료가 전혀 없습니다** — 대상 머신을 더
이상 쓰지 않게 되면 직접 해지하세요.

## 휴대폰에서 워크스페이스 전환

페어링된 휴대폰은 데스크톱과 독립적으로 워크스페이스를 전환할 수 있습니다.
휴대폰은 모든 호출에 워크스페이스를 함께 보내고, 서버는 호출마다 해당
워크스페이스에서의 멤버십과 역할을 확인합니다 — 따라서 휴대폰은 자신이 멤버인
워크스페이스에만 도달하며, 휴대폰에서 전환해도 데스크톱에 표시되는 내용은
바뀌지 않습니다.

휴대폰 세션은 추가로 읽기 위주의 도구로 이루어진 작은 허용 목록으로
제한됩니다: 티켓, 에이전트, 스페이스, 메시지, 뉴스피드 글을 나열하고 읽을 수
있으며, 티켓을 갱신하거나 할당하고, 스페이스에 메시지를 보내고, 글을 읽음
또는 저장됨으로 표시할 수 있습니다. 이 집합 밖의 것은 서버의 디스패처에
도달하기 전에 거부됩니다.
