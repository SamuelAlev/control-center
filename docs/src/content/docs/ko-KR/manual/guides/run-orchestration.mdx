이 가이드에서는 하나의 큰 목표를 스스로 실행되는 팀 전체 계획으로 바꾸는
방법을 설명합니다. 동작 방식은
[오케스트레이션](/ko-KR/매뉴얼/개념/오케스트레이션/)을 참고하십시오.

## 오케스트레이션을 사용할 때

요청이 에이전트 하나가 감당할 범위보다 크고 정확한 단계를 아직 모를 때
오케스트레이션을 사용합니다. 작업이 하나뿐이라면
[스페이스](/ko-KR/매뉴얼/사용-가이드/에이전트와-채팅/)에서 에이전트에게
메시지를 보내고, 손으로 단계를 나열할 수 있는 프로세스라면
[파이프라인 템플릿](/ko-KR/매뉴얼/사용-가이드/파이프라인-만들기/)을
만드십시오.

## 1단계: 계획 요청하기

1. 스페이스를 열고(또는 만들고) **앵커 티켓**을 준비합니다. 모든 제안에는
   앵커 티켓이 필요하며(`propose_orchestration`은 `ticket_id`를 받습니다),
   공유 스페이스는 그 티켓에서 정해집니다.
2. 필요하면 컴포저의 모드 드롭다운을 **오케스트레이트**로 전환합니다. 이
   모드는 에이전트를 읽기와 제안으로 좁힙니다 — 메모리, 코드 그래프, 저장소와
   티켓 읽기, `propose_orchestration`, 플레이북 도구 — 따라서 계획 대신 코드를
   쓰기 시작할 수 없습니다.
3. 오케스트레이터(보통 CEO 에이전트)를 @멘션하고 목표를 평이한 언어로
   설명합니다:

> @ceo 오프라인 우선 회의 녹음기의 경쟁 환경을 조사하고 한 페이지 분량의
> 포지셔닝 문서를 작성해 줘.

오케스트레이터는 스페이스에 구조화된 **제안** 카드로 응답합니다. 카드에는
필요한 역할, 하위 티켓으로 나뉜 작업, 선택적인 리서치 및 토론 단계, 산출물을
만들어 내는 종합 단계, 예산이 담깁니다.

제안은 타입이 지정된 객체이므로, 앱은 실행 전에 이를 검증합니다(올바른 형식의
역할, 선언된 출력 스키마, 순환이 없는 DAG). 검증에 실패한 제안은 승인할 수
없습니다.

## 2단계: 제안 검토 및 편집

채팅 내 카드는 **계획 승인**, **거절**, **열기** 세 가지 작업을 제공합니다.
**열기**는 계획을 편집기 탭으로 Plan Studio에서 엽니다. 카드 자체는 편집할 수
없습니다.

무엇이든 바꾸려면 **열기**를 누르고 오른쪽 인스펙터에서 작업합니다:

- 모든 작업 단계의 **제목**, **설명**, **역할**, **의존 대상**, **출력
  스키마**. 여기서 역할이란 계획에 이미 있는 역할 키 중 어느 것이 그 단계를
  소유하는지를 뜻합니다 — 역할을 특정 이름의 에이전트에 고정하거나
  인스펙터에서 채용 목록을 편집할 수 없으며, 예산도 편집할 수 없습니다.

읽기 전용인 것은 두 가지입니다. 구조 노드(리서치, 토론, 종합)와 이미 작업이
실행된 모든 노드입니다. 편집은 오케스트레이션이 아직 `proposed`인 동안에만
가능합니다.

확정하기 전에 승인 바에서 **추정**을 눌러 비용, 소요 시간, 영향 범위를
확인하십시오. 전체 편집기는
[Plan Studio에서 작업](/ko-KR/매뉴얼/사용-가이드/plan-studio/)을 참고하십시오.

:::note[예산은 지출 한도가 아닙니다]
제안의 예산은 승인 바의 _추정치_ 와 비교됩니다. 추정치의 상한이 예산을 넘으면
총액이 빨간색으로 바뀌고 예산 초과 경고가 표시됩니다. 계획이 실행되는 동안에는
지출을 확인하는 곳이 없으므로, 예산이 실행을 멈추거나 실패시키지 않습니다.
실제로 지출을 중단하려면 에이전트별 예산 정책을 사용하십시오 — [비용
관리](/ko-KR/매뉴얼/사용-가이드/비용-관리/)를 참고하십시오.
:::

## 3단계: 승인

채팅 카드에서 또는 Plan Studio의 승인 바에서 계획을 승인합니다. **이것이
여러분이 내리는 유일한 결정입니다.** 승인은 운영자 전용입니다 — 이를 위한
MCP 도구가 없으므로, 에이전트는 제안하고 수정할 수 있지만 자신의 계획을
승인할 수는 없습니다.

여기서부터 결정적 머티리얼라이저(순수 함수이며 LLM을 쓰지 않습니다)가 제안을
실제 [파이프라인](/ko-KR/매뉴얼/개념/파이프라인/)으로 바꾸고 다음 골격을
만듭니다:

- 새 역할을 채용합니다(채용한 에이전트 id를 기록하므로 승인 도중 크래시가
  나도 중복 채용 없이 재개할 수 있습니다)
- 역할을 **팀**으로 묶습니다
- **프로젝트**를 만들고 상위 티켓을 그 아래에 등록합니다
- 이 모든 것을 구동하는 **파이프라인 실행**을 시작합니다

상태는 `approved`, 그다음 `executing`으로 바뀝니다.

## 4단계: 실행 지켜보기

하위 티켓은 파이프라인 단계로 실행됩니다. 토론 라운드를 켰다면 각 역할이 먼저
입장을 게시합니다. 진행 상황은 여러분이 이미 보고 있는 곳에 나타납니다:

- 오케스트레이션이 기준으로 삼은 **상위 티켓**
- 팀이 대화하는 공유 **스페이스** — 여기서 계획의 행이 각 노드의 상태를
  추적합니다
- **파이프라인 실행** 상세 — 평소의 워터폴과 단계별 비용이 표시됩니다 —
  [파이프라인 실행
  모니터링](/ko-KR/매뉴얼/사용-가이드/파이프라인-모니터링/)을 참고하십시오
- 상위 티켓이 등록된 **프로젝트**

하위 티켓이 끝나면 상태가 `synthesizing`으로 바뀌고 종합 단계가 산출물을
만듭니다. 그 텍스트는 공유 스페이스에 게시되고 상위 티켓은 완료로 표시된 다음
`completed`가 됩니다.

## 중간에 중지하기

채팅 내 카드에서 **오케스트레이션 취소**를 누르거나 Plan Studio의 승인
바에서 **실행 중단**을 누릅니다. 취소하면 진행 중인 작업이 정리됩니다.

오케스트레이션은 머티리얼라이제이션이 실패하거나, 생성된 파이프라인 실행이
실패할 때 실패합니다(리서치, 토론, 종합, 영속 단계는 실패해도 계속 진행하지
않습니다). 생성된 **작업** 단계는 항상 실패해도 계속 진행하므로, 하위 티켓
하나가 실패해도 실행 전체가 실패하지 않습니다. 예산 초과 실패 경로는 없으며,
"모든 하위 티켓이 실패함" 임계값도 없습니다.
