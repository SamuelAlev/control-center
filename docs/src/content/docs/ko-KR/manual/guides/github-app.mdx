이 가이드에서는 서버에 자체 GitHub App을 부여하는 방법을 설명합니다.
2분 정도면 되고, 서버 소유자만 수행하며, 서버마다 한 번만 하면 됩니다.

:::note[필요하지 않을 수도 있습니다]
Control Center Connect를 켜 두면 사람들은 Control Center의 공유 App이나 조직의 Connect가
사용하는 App을 통해 GitHub에 로그인합니다. **내 앱 사용**을 골랐다면 자체 App을 등록하십시오. 서버 자체 App은 그 경우에만 사용됩니다.
[Control Center Connect](/ko-KR/매뉴얼/레퍼런스/connect/)를 참고하십시오.
:::

이후 본인 계정으로 로그인하는 방법은
[GitHub 통합 설정](/ko-KR/매뉴얼/사용-가이드/github-통합/)을 참고하십시오.

## 앱이 하는 일

한 번의 등록이 서로 다른 두 가지 일을 맡습니다.

| 일                     | 무엇이 처리하는가                                  | 왜 중요한가                                                                                     |
| ---------------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **사람이 로그인한다**  | 앱의 클라이언트 ID와 클라이언트 시크릿             | 모두가 서버에, 모든 기기에서 쓸 수 있는 자신만의 GitHub 자격 증명을 갖습니다                    |
| **서버가 동작한다**    | 앱의 ID와 비공개 키                                | 에이전트, 파이프라인, 폴러, 봇 답장이 한 번에 저장소 하나에 대한 토큰을 받습니다                |

두 번째 일은 결코 사람의 자격 증명을 통째로 빌리지 않습니다. 서버가 발급하는 각 토큰은
저장소 하나를 대상으로 하며, 책임지는 멤버가 그곳에서 할 수 있는 범위로 제한됩니다. 연결된
저장소를 읽는 데는 앱만 있으면 되고, 쓰기가 필요한 작업에는 푸시할 수 있는 멤버가 필요합니다.
자동화는 결코 풀 리퀘스트를 승인하지 않습니다.

서버 자체 앱은 **내 앱 사용**에서만 적용됩니다. Control Center 또는 사용자 지정 Connect를 쓰면 Connect가 GitHub를 포함한 모든 레인을 담당하며, 서버 앱은 다시 전환할 때까지 저장만 되고 사용되지 않습니다. [워크스페이스 자체 앱](#한-워크스페이스에-다른-앱-쓰기)은 모든 모드에서 계속 적용됩니다. 일부 필드가 빠진 앱은 폴백이 아니라
오류이며, 모든 필드가 설정될 때까지 GitHub 로그인이 거부됩니다.

## 시작하기 전에

- **서버 소유자**여야 합니다. **프로바이더 앱** 카드는 다른 사람에게는 보이지 않습니다
- GitHub 계정. 앱은 이 계정 아래에 만들어집니다
- 브라우저가 도달할 수 있는 서버 주소. 서버의 공개 URL(데스크톱 자체 서버라면 루프백)이
  GitHub가 나를 돌려보내는 곳입니다

## 클릭 한 번으로 만들기

1. **설정 → 서버 → 싱글 사인온**으로 이동해 **프로바이더 앱** 카드까지 스크롤합니다
2. **GitHub** 블록에서, 앱을 소유할 GitHub 조직을 필요하면 **조직(선택 사항)**에
   입력합니다. 비워 두면 내 계정 아래에 앱이 만들어집니다. 조직 아래에 만들려면 그 조직의
   소유자여야 합니다
3. **내 GitHub 앱 만들기**를 클릭합니다
4. 앱 내용이 미리 채워진 GitHub가 브라우저에서 열립니다. **Create GitHub App**을 클릭합니다
5. GitHub가 나를 서버로 돌려보내면, 서버는 앱 ID, 비공개 키, 클라이언트 ID, 클라이언트
   시크릿을 저장한 뒤 앱의 설치 페이지를 엽니다

손으로 복사할 것은 없으며, 변환 코드는 GitHub에서 서버로 곧바로 전달됩니다. 이 링크는 한
번만 작동하며 10분 후에 만료됩니다. 만료되면 **내 GitHub 앱 만들기**를 다시 클릭하십시오.

앱 이름은 `Control Center <code>`이며, Control Center가 사용하는 것만 정확히 요청합니다.

| 권한                                       | 접근           |
| ------------------------------------------ | -------------- |
| Metadata                                   | Read           |
| Contents                                   | Read and write |
| Pull requests                              | Read and write |
| Issues                                     | Read and write |
| Checks, Actions, Commit statuses           | Read           |
| Organization members                       | Read           |

웹훅은 꺼져 있습니다. 서버가 폴링합니다. 내 계정 아래에 만든 앱을 나중에 조직으로 옮기려면
GitHub의 앱 고급 설정에서 **Transfer ownership**을 사용하십시오.

확인 지점: GitHub 블록에 "서버가 자체 자격 증명으로 동작하며, 사용자가 로그인할 수
있습니다."라고 표시됩니다.

## 저장소가 있는 곳에 설치하기

등록만 되고 설치되지 않은 앱은 사람을 로그인시킬 수는 있어도 아무것도 읽지 못합니다.

1. GitHub가 연 설치 페이지에서 저장소를 소유한 계정이나 조직을 고릅니다
2. **All repositories**를 고르거나, 이 서버가 볼 저장소를 선택합니다

나중에 다른 계정에 설치하려면, 워크스페이스 관리자가 **설정 → 워크스페이스 → 일반**으로
이동해 GitHub 신원 카드에서 **GitHub 앱 설치**를 찾아 **GitHub 앱 설치**를 클릭합니다. 목록에는
앱이 설치된 모든 계정이 표시되고, 일시 중단된 설치에는 표시가 붙습니다.

## 조직에 대해 이 서버 승인하기

Control Center의 공유 App에서는 조직의 설치가 그 조직의 관리자가 승인한 서버에만 제공됩니다.
**GitHub 앱 설치**로 설치하면 이를 시작한 서버가 승인됩니다. 이미 존재하는 설치의 경우:

1. 그 조직의 관리자가 이 서버에서 GitHub에 로그인합니다
2. **설정 → 워크스페이스 → 일반 → GitHub 앱 설치**를 엽니다
3. 조직의 행에 **승인되지 않음**이 표시됩니다. **이 서버 승인**을 클릭합니다

그러면 행에 **승인됨**이 표시됩니다. 자체 앱에는 이 과정이 필요 없습니다. 그 앱의 모든
설치가 내 서버의 것이기 때문입니다.

## 대신 직접 등록하기

**프로바이더 앱** 카드에는 직접 등록한 앱의 값을 바로 입력할 수도 있습니다.

| 그룹                         | 필드                                                                                            |
| ---------------------------- | ----------------------------------------------------------------------------------------------- |
| **서버로 동작**              | **앱 ID**와 **비공개 키**(`BEGIN`과 `END` 줄을 포함한 `.pem` 전체)                               |
| **사용자 로그인**            | **클라이언트 ID**와 **클라이언트 시크릿**. **콜백 URL**에 등록할 URL이 그대로 표시됩니다         |
| **풀 리퀘스트 대화**         | **봇 로그인**. 연결을 테스트할 때 확인됩니다                                                    |

카드에 표시된 그대로 콜백 URL `<server origin>/oauth/github/callback`을 등록하고,
**Expire user authorization tokens**는 켜 둔 채, 위 표의 권한을 부여합니다. **테스트**를
클릭하면 앱이 어느 계정에 설치되어 있는지 GitHub에 묻기 때문에 "저장됨"과 "작동함"을
혼동하지 않습니다.

## 서버의 `.env`로 구성하기

헤드리스 또는 스크립트 설치에서는, 서버가 저장된 값이 없는 첫 시점에 `.env` 파일에서 각
필드의 초기값을 채웁니다.

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

키는 **한 줄**로 넣으십시오. `.env` 값은 한 줄이며, 큰따옴표 안의 `\n`은 줄바꿈으로
디코딩됩니다. `GITHUB_APP_PRIVATE_KEY` 또는 `GITHUB_CLIENT_SECRET`이 모든 자식 프로세스가
읽을 수 있는 프로세스 환경에 내보내져 있으면 서버가 시작을 거부합니다. 이 값들은 `.env`
파일에 두십시오(Docker에서는 `/app/bin/.env`에 마운트합니다). 초기값 채우기는 **필드마다
한 번** 일어나므로, 설정에서 편집한 내용이 다음 재시작으로 되돌려지지 않습니다.

## 한 워크스페이스에 다른 앱 쓰기

워크스페이스는 서버의 앱 대신 자체 앱을 쓸 수 있습니다. 워크스페이스 관리자가 **설정 →
워크스페이스 → 일반**으로 이동해 **GitHub 신원** 카드에서 **다른 GitHub App 사용**을 고르고,
그 앱의 ID, 비공개 키, 클라이언트 ID, 클라이언트 시크릿을 입력합니다. 그러면 멤버들은 이
워크스페이스에서 그 앱에 로그인합니다. 자체 앱을 쓰는 워크스페이스는 결코 서버의 앱이나
Connect로 폴백하지 않습니다. 필드가 모두 채워질 때까지 그 GitHub 작업은 거부됩니다. 이는 서버가 사람들을 로그인시키는 방식(Connect 포함)과 관계없이 적용됩니다.

같은 페이지의 **프로바이더 앱** 카드도 Google Calendar, Linear, GIF 검색에 대해 같은 일을 합니다. 자세한 내용은 [워크스페이스에 자체 Linear 애플리케이션 설정하기](/ko-KR/매뉴얼/사용-가이드/linear-통합/#워크스페이스에-자체-linear-애플리케이션-설정하기)와 [워크스페이스에 자체 Google 클라이언트 설정하기](/ko-KR/매뉴얼/사용-가이드/캘린더-연결/#워크스페이스에-자체-google-클라이언트-설정하기)를 참고하세요.

## 문제 해결

### 내 GitHub 앱 만들기에서 서버에 주소가 없다고 합니다

서버에 브라우저가 돌아올 수 있는 공개 URL이 없습니다. `CC_SERVER_PUBLIC_URL`(또는
`--public-url`)을 설정하고 다시 시도하십시오.

### GitHub에서 링크가 만료되었다고 합니다

일회용 페이지가 이미 사용되었거나 10분이 지났습니다. 설정에서 다시 시작하십시오.

### 테스트에서 자격 증명은 정상이지만 앱이 어디에도 설치되지 않았다고 합니다

등록과 설치는 별개의 단계입니다. 앱의 설치 페이지를 열거나, 워크스페이스 → 일반의
**GitHub 앱 설치**를 사용하십시오.

### 테스트에서 비공개 키를 읽을 수 없다고 합니다

`-----BEGIN`과 `-----END` 줄을 포함해 `.pem` 파일 전체를 붙여넣으십시오. `ed25519`나 EC
키는 사용할 수 없습니다. GitHub App은 RSA로 서명합니다.

### 구성원이 로그인했는데 저장소가 보이지 않습니다

저장소를 소유한 계정에 앱이 설치되어 있지 않거나, 그 설치가 다른 저장소를 선택하고
있습니다. 로그인은 앱이 볼 수 있는 것만 부여합니다.

### 에이전트가 GitHub App 설치가 일시 중단되었다고 합니다

누군가 GitHub에서 설치를 일시 중단했습니다. 해당 계정의 **Settings → Applications →
Installed GitHub Apps**에서 일시 중단을 해제하십시오.
