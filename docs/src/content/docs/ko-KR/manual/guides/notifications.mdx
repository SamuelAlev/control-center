이 가이드에서는 알림을 구성하는 방법과 각 설정이 실제로 무엇을 제어하는지 설명합니다.

알림은 두 가지 표면으로 도착합니다. **알림 센터** — 제목 표시줄의 종 — 는 서버에
있는 워크스페이스별 영속 피드를 읽습니다. **OS 토스트**는 별개의 데스크톱 전용
경로로, 서버에서 푸시되는 라이브 프레임으로 공급됩니다.

:::note[웹 빌드에서는 OS 알림이 표시되지 않습니다]
토스트 파이프라인은 데스크톱 부트스트랩에서만 구성됩니다. `app.usectrl.dev`에는 OS
토스트도, 알림 소리도, 주변 배너도 없습니다 — 종과 그 기록은 서버 피드를 읽기
때문에 여전히 작동합니다. 휴대폰 클라이언트에는 알림 표면이 전혀 없습니다.
:::

## 카테고리 켜기 또는 끄기

1. **설정 → 나 → 알림**으로 이동합니다
2. **알림 활성화**를 켠 상태로 둡니다
3. 원하는 카테고리를 전환합니다. 카테고리는 정확히 열여섯 개입니다:

| 카테고리                  | 발생 조건                                                                  |
| ------------------------- | -------------------------------------------------------------------------- |
| 에이전트 완료             | 에이전트가 실행을 완료함                                                   |
| PR 게시됨                 | 에이전트가 PR을 게시함                                                     |
| PR 병합됨                 | PR이 병합됨                                                                |
| 새 메시지                 | 보고 있지 않은 스페이스에 메시지가 도착함                                  |
| 풀 리퀘스트에서 멘션됨    | GitHub 알림 폴링에서 PR에 멘션된 것을 확인함                               |
| 리뷰 요청됨               | 초안이 아닌 PR에서 리뷰가 실제로 요청됨                                    |
| 리뷰 오래됨               | 이미 리뷰한 풀 리퀘스트에 새 커밋이 쌓임                                   |
| 병합 가능                 | 내가 작성한 풀 리퀘스트가 병합 가능해지거나, 더 이상 병합할 수 없게 됨     |
| 리뷰 결정                 | 리뷰어가 승인하거나, 변경을 요청하거나, 승인이 취소됨                      |
| 검사                      | 내가 작성한 풀 리퀘스트에서 CI가 실패하거나 복구됨                         |
| 리뷰 스레드               | 내가 참여한 스레드에 누군가 답글을 달거나 스레드를 해결함                  |
| 티켓 할당됨               | 티켓이 할당됨                                                              |
| 티켓 상태 변경됨          | 티켓의 상태가 변경됨                                                       |
| 회의가 곧 시작됩니다      | 캘린더 회의가 사전 알림 시간 안에 들어옴                                   |
| 캘린더 연결 해제됨        | 연결된 캘린더의 OAuth 토큰이 만료됨                                        |
| 인클로저 업데이트         | 인클로저가 인수되거나, 회수되거나, 실패함                                  |

이 목록에 없는 항목은 알림도 필터링도 할 수 없습니다 — "그 밖의 모든 것"이라는
카테고리는 존재하지 않습니다.

이러한 환경설정은 사용자를 따라 기기를 넘어 유지되므로 휴대폰과 노트북이 같은
상태를 유지합니다. 볼륨만은 의도적인 예외로 기기별로 유지됩니다.

## Quiet hours 설정

1. 같은 페이지에서 **Quiet hours**를 켭니다
2. 시작 시각과 종료 시각을 `HH:MM` 형식으로 입력합니다(기본 시간대는 22:00–08:00)

Quiet hours 동안에는 긴급하지 않은 알림이 버려집니다 — 나중을 위해 대기열에
쌓였다가 다시 재생되지 않습니다.

두 카테고리는 **긴급**이라서 항상 전달되며, Quiet hours와 포커스 모드를 _모두_
우회합니다: **회의가 곧 시작됩니다**와 **PR 게시됨**입니다. 회의 알림은 나중에야
보게 된다면 쓸모가 없기 때문입니다.

## 소리 선택

1. **알림 소리**까지 스크롤합니다
2. 함께 제공되는 11가지 소리 중 하나를 고르거나 **없음**을 선택합니다
3. 테스트 버튼을 눌러 소리를 듣고 슬라이더로 볼륨을 설정합니다

소리는 앱이 직접 재생합니다. OS 알림은 무음으로 전달되므로 같은 소리를 두 번
듣는 일은 없습니다.

## 회의 사전 알림 시간 설정

1. **사전 알림 시간**까지 스크롤합니다
2. **5**, **10**, **15**, **30**분 중에서 선택합니다

이 값은 캘린더 일정보다 얼마나 앞서 **회의가 곧 시작됩니다** 알림이 발생하는지를
나타냅니다. 기본값은 5분입니다.

## 알림이 억제되는 경우

다음 중 하나라도 해당하면 알림은 소리 없이 버려집니다:

- 알림이 전체적으로 꺼져 있거나, 해당 카테고리가 꺼져 있음
- 해당 알림이 이동시키려는 경로에 이미 있음 — 메시지의 경우 이미 그 스페이스에
  있음
- 포커스 모드가 활성 상태이고 해당 카테고리가 긴급하지 않음
- Quiet hours가 활성 상태이고 해당 카테고리가 긴급하지 않음

이 검사는 OS 토스트에 적용됩니다. 영속적인 종에는 여전히 이벤트가 기록됩니다.

더 상류, 곧 서버가 애초에 전송하는 내용에도 두 가지 억제가 더 있습니다:

- 다른 **사람**이 보낸, 멘션이 없는 메시지는 알림이 되지 않음
- 에이전트 간 스페이스는 사이드바에서 음소거되므로 사람의 읽지 않음 배지를
  올리지 않음

스페이스 안에는 알림이 오지 않는 구석이 없습니다. 스레드를 포함해 모든 대화가
똑같이 알림을 보냅니다. 읽음 상태는 스페이스 단위이므로, 읽지 않음은 대화별로
추적되지 않고 스페이스의 모든 대화에 걸쳐 집계됩니다.

## 알림 센터 확인 및 지우기

1. 제목 표시줄의 종을 클릭합니다

팝오버에는 최근 활동이 표시되며, 각 항목은 해당 내용으로 딥링크됩니다. 팝오버를
열어도 모든 항목이 읽음으로 표시되지는 **않습니다** — 헤더의 **모두 읽음으로
표시**를 사용하거나 행 하나만 읽음으로 표시합니다. 읽음 상태는 사용자를 따라
기기를 넘어 유지됩니다.

:::note[모두 지우기는 삭제가 아니라 워터마크입니다]
**모두 지우기**는 사용자별 워터마크를 찍어 그보다 오래된 모든 항목을 숨깁니다.
행은 그대로 남습니다. 이와 별개로 각 워크스페이스는 가장 최근 **200**개의 피드
행만 보관하며 새 행이 도착할 때마다 오래된 행이 정리됩니다. 한편 종은 최신
**50**개를 구독하고 팝오버는 그중 최대 **15**개를 나열합니다. 그보다 오래된
기록은 읽음 상태와 무관하게 사라집니다.
:::

## 문제 해결

### macOS에서 OS 알림이 오지 않음

권한은 앱을 시작할 때 네이티브로 요청됩니다. 거부했다면 시스템 설정 → 알림에서
Control Center를 다시 활성화합니다. 앱 안에서 다시 요청하는 프롬프트는 없습니다.

### 웹 빌드에서는 아무것도 오지 않음

정상입니다 — 웹 빌드에는 OS 알림 파이프라인이 없습니다. 종을 사용합니다.

### 종 배지가 0인데 분명히 새 활동이 있음

연결한 뒤 읽음 표시 스트림이 해결될 때까지는, 배지가 잠깐 나타났다가 비는 것을
피하기 위해 항목이 읽음으로 렌더링됩니다. 표시가 로드되면 안정됩니다.

### 에이전트 실행이 끝났는데 알림이 오지 않음

해당 실행이 일어난 스페이스에 이미 있지 않았는지 확인합니다 — 활성 경로는 자신의
OS 토스트를 억제합니다.
