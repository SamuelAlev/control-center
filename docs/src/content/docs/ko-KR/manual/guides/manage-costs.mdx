이 가이드에서는 에이전트 실행에 드는 비용을 확인하는 방법과 자율 실행에 상한을 거는 방법을 설명합니다.

## 비용이 기록되는 방식

모든 에이전트 실행은 입력 토큰, 출력 토큰, 추론 토큰, 캐시 읽기 및 캐시 쓰기 토큰, 센트 단위의 추정 비용, 그리고 자신이 생성한 서브에이전트의 비용을 담은 실행 로그를 기록합니다.

가격 정보는 models.dev 카탈로그에서 가져오며, 이 카탈로그는 모델 목록에 가격과 컨텍스트 창을 덧붙이는 용도로만 사용됩니다 — 모델 id의 원천으로는 결코 쓰이지 않습니다. 카탈로그가 가격을 매길 수 없는 모델은 **$0**으로 기록되고, 비용이 0인 실행은 **사용량 및 비용** 요약에서 제외됩니다. 따라서 로컬 Ollama 모델은 지출이 전혀 표시되지 않지만, 토큰 수는 여전히 기록됩니다. 정액제 요금제(kimi-code, Claude 구독)는 카탈로그가 서빙된 모델의 가격을 갖고 있지 않을 때에만 마찬가지입니다. 가격이 있으면 어쨌든 그 요율로 실행 비용이 추정됩니다. 폴백 체인에서는 요청한 모델이 아니라 실제로 실행을 처리한 모델을 기준으로 비용이 매겨집니다.

## 지출 확인

### 옵저버빌리티 → 인사이트

사이드바 하단 → **옵저버빌리티**에서 들어갑니다. 처음에는 **사용량** 탭이 열립니다(누적 토큰 합계). 비용을 다루는 주 화면은 **인사이트** — 두 번째 탭 — 으로 전환하면 나옵니다:

- 기간 선택기: 최근 24시간, 최근 7일, 최근 30일 또는 전체 기간
- 에이전트, 모델, 상태, 역할에 대한 패싯 필터를 해제 가능한 칩으로 제공
- KPI 스트립: 총 실행, 총 비용, 오류율, 캐시율, 초당 토큰, 평균 지연 시간, 첫 토큰까지 시간이며, 각각 이전 기간 대비 변화가 함께 표시됩니다("전체 기간"에서는 숨겨짐)
- 활동 및 비용 차트, 그리고 지출을 메인 에이전트, 그 서브에이전트, 어드바이저로 나눈 **역할별 비용** 분석
- 비용순으로 정렬된 에이전트별 표로, 상위 10개가 표시되며 전체 표시 토글이 있습니다. 행을 탭하면 다른 모든 화면이 그 에이전트로 필터링됩니다
- 상세 실행 로그로, 선택한 실행의 트랜스크립트 드로어를 엽니다

:::note["전체 기간"은 전체 기간이 아닙니다]
실행 피드는 모든 워크스페이스에 걸쳐 가장 최근 실행 로그 2000개를 구독한 뒤 활성 워크스페이스로 필터링합니다. 워크스페이스가 많고 바쁜 서버에서는 조용한 워크스페이스의 오래된 기록이 이 범위 밖으로 밀려납니다.
:::

### 설정 → 서버 → 모델 제공업체

이 페이지의 **사용량 및 비용** 카드는 최근 7일간 관측된 지출을 하나의 달러 금액으로 보여 주며, 프로바이더별 분석과 함께, 프로바이더가 공개하는 경우 다음 할당량 구간이 재설정되기까지 남은 시간도 표시합니다.

### 단일 에이전트의 실행

**설정 → 워크스페이스 → 에이전트** → 에이전트 선택 → **로그**에는 상태, 소요 시간, 시작 및 완료 시각, PID, 어댑터와 함께 실행 목록이 나옵니다. 이 탭은 비용을 **표시하지 않습니다** — 비용은 옵저버빌리티 → 인사이트의 에이전트별 표를 사용하세요.

## 자율 실행에 상한 걸기

스페이스 컴포저에 입력하는 두 가지 슬래시 명령만 지출 상한이 있는 실행입니다:

```
/goal ship the auth refactor --budget 20
/loop keep the flaky tests green
```

- `/goal` 또는 `/loop` 실행의 각 구간은 비용이 매겨진 지출이 **500센트($5.00)**에 도달하면 멈춥니다. 그 80% 지점에서 루프는 먼저 모델을 마무리하고 깔끔하게 인계하도록 스티어링하므로, 작업 도중에 죽지 않습니다.
- 지속 목표 전체에는 `--budget <dollars>`를 전달하지 않는 한 **5000센트($50.00)** 상한이 적용됩니다. 감독자가 목표의 _남은_ 예산을 각 구간에 이어 주므로, 명시한 예산을 한 구간만큼 초과하는 일은 결코 없습니다.
- `--days N`은 실제 시간 기준 마감을 추가하고, `--max N`은 실행 횟수 상한을 추가합니다. 둘 다 선택 사항이며, 이것들이 없으면 목표는 비용으로만 제한됩니다.
- 상한에 도달한 목표는 `budgetExhausted`에서 멈추며, 예산을 올려야만 다시 시작할 수 있습니다.

상한은 가격을 기준으로 하므로, 카탈로그가 가격을 매길 수 없는 모델은 결코 그 상한에 도달하지 않습니다. 그런 실행은 대신 둠 루프 반복 가드, 세 번 연속 실패 후 감독자의 포기, 그리고 사용자로 인해 제한됩니다.

스페이스의 메시지, @멘션, 파이프라인 단계에는 지출 상한이 없습니다. 실행은 모델이 멈추거나, 사용자가 중지하거나, 둠 루프 가드가 방향을 바꿀 때 끝납니다.

## 토큰 사용 줄이기

### 긴 대화 압축

스페이스 컴포저에 `/compact`를 입력합니다. 이 명령은 클라이언트 측에서 가로채므로 트랜스크립트에 결코 남지 않습니다. 서버는 오래된 기록을 고정 요약으로 접어 넣고, 대화는 압축된 컨텍스트 위에서 계속됩니다.

압축은 에이전트가 턴을 진행 중이거나 접을 만큼 오래된 내용이 없을 때 거부됩니다. 내장 하네스는 기록이 모델의 컨텍스트 창에 가까워지면 스스로도 압축합니다.

### 추론 강도를 의도적으로 선택

에이전트의 **추론 강도**(설정 → 워크스페이스 → 에이전트)는 선택한 모델이 공개하는 수준을 제시합니다. 수준이 높을수록 추론 토큰을 더 많이 씁니다. 최상위 수준은 그것이 필요한 작업에 남겨 두세요.

### 에이전트별 모델 선택

모델은 에이전트별 필드이므로, 포매팅이나 분류를 맡은 에이전트는 저렴한 모델로, 아키텍처 에이전트는 비싼 모델로 실행할 수 있습니다. 옵저버빌리티 → 인사이트의 에이전트별 표를 모델로 필터링하면 어떤 조합이 실제로 비용을 쓰고 있는지 알 수 있습니다.

### 토큰 수가 유난히 큰 실행 찾기

인사이트 실행 로그(필터링된 최신 실행 50개)와 이상해 보이는 항목의 트랜스크립트 드로어를 열어 보세요. 흔한 원인은 지나치게 긴 시스템 프롬프트나 페르소나, 압축했어야 할 컨텍스트, 여러 개의 작은 작업으로 나눴어야 할 작업입니다.

## 예산을 정규 경로 밖에서 설정하면 어떻게 되는가

참고로, `monthlyBudgetCents`나 예산 정책을 에이전트 행에 직접 기록하면 다음과 같습니다:

- 예산은 디스패치 전이 아니라 실행이 완료된 **후에** 평가됩니다. 실행 완료 리스너가 에이전트의 월 누적 지출을 상한과 비교합니다.
- 소프트 임계값(기본값 80%)을 넘으면 경고 인시던트가 기록되고, 파이프라인 트리거를 걸 수 있는 `BudgetThresholdCrossed` 이벤트가 발행됩니다.
- 예산을 모두 소진하면 심각 인시던트가 기록되고, 같은 이벤트가 발행되며, 에이전트의 수명주기 상태가 `paused`로 바뀝니다.
- 디스패치 전 차단은 존재하지만 복구를 예약할 때 고아 실행 수거기와 고립 티켓 조정기만 참조합니다 — 일반 디스패치는 결코 여기에 도달하지 않고, 디스패치 경로의 어떤 것도 일시 중지 상태를 확인하지 않습니다. 유일하게 보이는 신호는 조직도의 수명주기 배지입니다.
