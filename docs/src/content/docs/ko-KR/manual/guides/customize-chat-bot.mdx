이 가이드에서는 Control Center를 벗어나지 않고 제공업체 측 봇 앱을 바꾸는 방법을
설명합니다.

## 사전 요구 사항

- 워크스페이스의 `owner` 또는 `admin` 역할
- **연결된** 제공업체. **봇 맞춤 설정** 행은 워크스페이스가 연결된 뒤에만 나타납니다
- Control Center가 관리할 수 있는 앱. Slack의 경우 연결에 앱 구성 리프레시 토큰(`xoxe-…`)이 있어야 합니다. 없으면 행이 그 사실을 알리고 비활성 상태로 남습니다

## 변경할 수 있는 항목

| 필드                            | 의미                                              | 제한                                                |
| ------------------------------- | ------------------------------------------------- | --------------------------------------------------- |
| **앱 이름**                     | 제공업체가 앱을 나열하는 이름                     | 1~35자                                              |
| **봇 이름 (@ 뒤에 입력하는 이름)** | 멤버가 `@` 뒤에 입력하는 이름                   | 1~80자                                              |
| **짧은 설명**                   | 제공업체가 보여 주는 한 줄                        | 140자 이하                                          |
| **봇이 할 수 있다고 말하는 내용** | 봇과의 DM 위에 표시됨                           | 300자 이하                                          |
| **슬래시 명령**                 | 멤버가 호출하는 명령(슬래시 제외)                 | 소문자, `a–z 0–9 _ -`만 허용, 32자에서 잘림         |
| **다이렉트 메시지**             | 봇이 DM/에이전트 환경을 노출하는지 여부           | 켜짐 또는 꺼짐                                      |

Control Center는 제공업체를 호출하기 전에 네 개의 텍스트 필드를 검증하므로,
직접 볼 수 없는 서버가 돌려주는 불투명한 `invalid_manifest` 대신 "the app name
must be between 1 and 35 characters"라는 메시지를 받습니다. 명령은 거부되지 않고
정규화됩니다. 앞의 슬래시는 제거되고, 나머지는 소문자로 바뀌며, `a–z 0–9 _ -`
밖의 문자는 버려지고, 결과가 비면 `cc`로 대체됩니다.

## 봇 편집

1. **설정 → 워크스페이스 → 일반**으로 이동해 **채팅 브리지** 카드까지 스크롤합니다
2. 제공업체 블록에서 **봇 맞춤 설정**을 클릭합니다
3. 대화상자는 제공업체에서 다시 읽어 온 앱의 _실시간_ 값으로 열립니다 — 따라서 누군가 Slack 자체 UI에서 한 변경이 곧 시작점이 됩니다
4. 필요한 내용을 편집하고 저장합니다

그 실시간 값을 읽으면 Slack 쪽에서 토큰 회전이 한 번 발생합니다. 그래서 이 행은
페이지가 로드될 때 자동으로 실행되는 것이 아니라 의도적으로 클릭해야 하는
항목입니다.

쓰기는 변경 사항을 앱의 현재 정의 위에 덮어씁니다. Control Center가 모델링하지
않는 것 — Slack에서 추가한 두 번째 슬래시 명령, 워크플로 단계, 관련 없는 설정 —
은 그대로 유지됩니다. 스코프와 이벤트는 병합될 뿐, 결코 제거되지 않습니다.

저장한 뒤 Control Center는 봇의 신원을 다시 읽어, 설정의 이름이 채팅 앱의
이름과 일치하게 합니다.

## 권한이 바뀌면 다시 설치

:::caution[권한 변경 후 재설치]
Slack은 새 앱 정의를 즉시 적용하지만 설치된 권한 부여는 그대로 유지합니다.
권한 변경을 적용하려면 앱을 다시 설치하세요. 그렇게 할 때까지 브리지는 이전
권한 부여로 계속 실행됩니다.
:::

저장으로 권한이 바뀌면 대화상자는 열린 채로 남아 "Slack에서 앱 권한이
변경되었습니다. 적용하려면 앱을 다시 설치하세요."라고 표시하고, 해당 앱의 Slack
팀 설치 페이지를 여는 **앱 다시 설치** 버튼을 보여 줍니다. Slack에서는
**Install App → Reinstall to Workspace**입니다.

## 슬래시 명령 이름 바꾸기

**슬래시 명령**을 바꾸고 저장합니다. 그러면 브리지는 마지막으로 호출된 명령을
사용해 안내문을 작성하므로, 도움말 텍스트와 연결 안내가 더 이상 존재하지 않는
명령을 지칭하는 대신 새 이름을 따릅니다.

이름을 바꿔도 기존의 브리지 스레드는 깨지지 않습니다. 스레드는 명령이 아니라
대화를 키로 삼기 때문입니다.

## Control Center가 바꾸지 않는 항목

- **구조적 설정.** 전송 방식(Socket Mode), 필수 스코프, 이벤트 구독은 제안되는 것이 아니라 강제됩니다. 설정 화면에서 침묵하도록 구성할 수 있는 앱은 기능이 아니라 지원 티켓입니다
- **봇 아이콘.** 제공업체 자체의 앱 설정에서만 바꿀 수 있으며, 대화상자도 그렇게 안내합니다
- **제공업체 자체의 기능 마이그레이션.** 이미 Slack의 레거시 어시스턴트 형태를 쓰는 앱은 그대로 유지됩니다. 이 대화상자는 설명을 편집할 뿐, 앱을 마이그레이션하지 않습니다

## 문제 해결

### 봇 맞춤 설정 행이 아예 없습니다

워크스페이스가 아직 연결되지 않았습니다. 제공업체 블록에 활성 연결이 표시되어야
그 행이 나타납니다.
[Slack 통합 설정](/ko-KR/매뉴얼/사용-가이드/slack-통합/)을 참고하세요.

### 봇 맞춤 설정 행이 비활성화되어 있습니다

연결에 앱 관리 자격 증명이 없습니다 — 행의 부제에는 "봇을 수정하려면 Control
Center에 앱 구성 토큰이 필요합니다. 다시 연결하고 토큰을 포함하세요."라고
표시됩니다. Slack의 경우 [api.slack.com/apps](https://api.slack.com/apps)에서 앱
구성 토큰 쌍을 생성하고, 리프레시 토큰을 채워 다시 연결합니다. 손으로 만든
앱이나 **Slack에서 만들기**로 만든 앱에서는 이것이 정상입니다. Slack은 자기가
어떤 앱을 만들었는지 결코 알려 주지 않기 때문입니다.

### "Control Center does not know which app to edit"

저장된 연결에 앱 id가 없습니다 — 보통 id가 기록되기 전에 손으로 연결한 앱이
그렇습니다. 워크스페이스를 다시 연결하거나 Control Center에서 앱을 만드세요.

### 봇의 새 이름이 채팅에 나타나지 않았습니다

제공업체는 앱 메타데이터를 잠시 캐시합니다. 1분이 지나도 이름이 갱신되지
않으면, 저장 시 앱을 다시 설치하라는 안내가 있었는지 확인하세요.
