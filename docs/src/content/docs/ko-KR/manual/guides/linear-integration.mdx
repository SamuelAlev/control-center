Control Center에서 Linear에는 두 가지 신원이 있으며, 둘 다 브라우저 로그인입니다.
하나는 내 것으로 내가 하는 일에 쓰이고, 다른 하나는 워크스페이스의 Control Center 앱으로
에이전트와 파이프라인이 하는 일에 쓰입니다. 티켓, 프로젝트, 링크, 협업자, 위임, 배정은
모두 외부 서비스 없이 Control Center 자체 데이터베이스에서 작동합니다 —
[티켓 생성 및 관리](/ko-KR/매뉴얼/사용-가이드/티켓-관리/)를 참고하세요.

## 사전 요구 사항

- 서버가 사람들을 Linear에 로그인시킬 수 있어야 합니다. Control Center Connect를
  통하거나 서버 자체 Linear 애플리케이션으로 합니다
  ([자체 Linear 애플리케이션 등록하기](#자체-linear-애플리케이션-등록하기)).
  어느 쪽을 쓸지는 서버 소유자가 **설정 → 서버 → 싱글 사인온**에서 고릅니다
- Linear를 티켓팅 제공자로 고르고 Linear 자동화를 연결할 워크스페이스 관리자

## 워크스페이스에서 Linear 선택하기

1. **설정 → 워크스페이스 → 일반**으로 이동해 **티켓팅** 카드를 찾습니다
2. **티켓팅 제공자**를 **Linear**로 설정합니다

이후 생성하는 티켓에는 `provider: linear`가 표시됩니다. **로컬**을 고르면 티켓이 이
서버 자체 데이터베이스에 보관되고 Linear 행이 숨겨집니다. 인증할 대상이 없기 때문입니다.

## Linear에 로그인하기

같은 카드의 **Linear** 행은 내 것입니다.

1. **Linear에 로그인**을 클릭합니다
2. 브라우저에서 승인합니다
3. 서버 자체 애플리케이션을 쓰면 대화 상자가 알아서 이를 감지합니다. Connect를 거치면
   브라우저에 표시되는 8자리 코드를 입력하거나, `control-center://` 링크를 통해
   브라우저가 Control Center를 열도록 둡니다

Control Center에서 Linear로 하는 모든 일은 이 로그인으로만 실행되며 다른 것은 쓰이지
않습니다. 로그인하지 않았다면 앱은 다른 사람으로 동작하는 대신 로그인하라고 안내합니다.

## Linear 자동화 연결하기

**Linear 자동화** 행은 Linear에 있는 워크스페이스의 Control Center 앱입니다. 티켓 동기화,
파이프라인, 에이전트가 이것으로 쓰기 때문에, 자동화가 만든 이슈와 댓글은 사람이 아니라
Control Center로 표시됩니다.

1. 워크스페이스 관리자가 **자동화를 위해 Linear 연결**을 클릭합니다
2. 위와 같이 브라우저에서 Linear 워크스페이스에 앱을 승인합니다

그러면 행에 "_내 Linear 워크스페이스_에 연결됨"이 표시됩니다. 워크스페이스 관리자만
연결하거나 연결을 해제할 수 있습니다.

에이전트의 샌드박스에는 Linear 자격 증명이 놓이지 않습니다. 에이전트는 Control Center
자체 도구로 티켓을 쓰며, 그 도구가 먼저 **외부 트래커에 쓰기** 규칙에 묻습니다.

## 자체 Linear 애플리케이션 등록하기

**내 앱 사용**을 고른 경우 자체 애플리케이션을 사용합니다. 서버의 자체 애플리케이션은 그 경우에만 적용됩니다. Control Center 또는 사용자 지정 Connect를 쓰면 Connect가 Linear를 포함한 모든 레인을 담당하고, 서버의 애플리케이션과 서비스 API 키는 저장만 되고 사용되지 않습니다. [워크스페이스 자체 애플리케이션](#워크스페이스에-자체-linear-애플리케이션-설정하기)은 모든 모드에서 계속 적용됩니다.

1. [linear.app/settings/api/applications/new](https://linear.app/settings/api/applications/new)에서
   OAuth 애플리케이션을 만듭니다
2. **설정 → 서버 → 싱글 사인온 → 프로바이더 앱 → Linear**의 **콜백 URL**에 표시되는
   두 콜백 URL을 그대로 모두 추가합니다:
   `<server origin>/oauth/linear/callback`과
   `<server origin>/oauth/linear_app/callback`
3. **클라이언트 ID**를 Linear 블록에 붙여 넣습니다

클라이언트 시크릿은 없습니다. 서버는 PKCE로 로그인합니다. Linear의 리프레시 토큰은
30일 동안 쓰이지 않으면 만료되므로, 서버는 20일보다 오래된 모든 Linear 로그인을 하루에
한 번 갱신합니다.

같은 블록에는 선택 사항인 **서비스 API 키**도 있습니다. Linear 자동화를 연결하지 않은
워크스페이스에서 자동화에 쓰는 서버 자체 Linear 자격 증명입니다. **설정**에 두거나 서버의
`.env` 파일에 `LINEAR_API_KEY`로 두세요. `LINEAR_API_KEY`가 프로세스 환경에 내보내져
있으면 서버가 시작을 거부합니다.

## 워크스페이스에 자체 Linear 애플리케이션 설정하기

워크스페이스는 서버의 애플리케이션 대신 자체 애플리케이션으로 Linear에 로그인할 수 있습니다. 워크스페이스 관리자 또는 소유자만 설정할 수 있습니다.

1. 위의 단계에 따라 Linear OAuth 애플리케이션을 만듭니다
2. **설정 → 워크스페이스 → 일반 → 프로바이더 앱**으로 이동해 **Linear**를 엽니다
3. **이 워크스페이스의 앱 사용**을 선택합니다
4. 행의 **콜백 URL**에 표시되는 두 개의 콜백 URL을 그대로 Linear 애플리케이션에 모두 추가합니다
5. **클라이언트 ID**를 붙여 넣고, 선택적으로 이 워크스페이스의 자동화용 **서비스 API 키**를 붙여 넣습니다

워크스페이스 애플리케이션은 서버가 사람들을 로그인시키는 방식과 관계없이 이 워크스페이스의 모든 Linear 로그인과 자동화 요청을 처리합니다. 서버 애플리케이션이나 Connect로 대체되지 않습니다. 클라이언트 ID가 설정되기 전까지 이 워크스페이스에서 Linear는 꺼져 있고, 해당 행에 무엇이 부족한지 표시됩니다. 서비스 API 키는 여기서만 사용됩니다. 키가 없으면 동기화에는 **자동화를 위해 Linear 연결**이 필요합니다.

서버 애플리케이션과 워크스페이스 애플리케이션을 전환하거나 워크스페이스의 클라이언트 ID를 바꾸면, 이 워크스페이스의 모든 사람이 Linear에서 로그아웃되고 자동화 연결이 끊어집니다. 새 애플리케이션을 통해 다시 로그인합니다. **이 서버의 앱 사용**을 선택하면 워크스페이스에 저장된 필드가 삭제됩니다. 시크릿은 쓰기 전용이라 행에는 저장되어 있는지 여부만 표시됩니다. 서버의 다른 워크스페이스는 영향을 받지 않습니다.

## 문제 해결

### Linear 행에 로그인이 설정되지 않았다고 표시됩니다

서버에 자체 Linear 애플리케이션도 Connect도 없습니다. 서버 소유자가 **설정 → 서버 →
싱글 사인온**에서 하나를 고릅니다. 워크스페이스가 자체 애플리케이션을 쓰는 경우에는 대신 행에 설정이 아직 완료되지 않았다고 표시되며, 워크스페이스 관리자가 **설정 → 워크스페이스 → 일반 → 프로바이더 앱**에서 클라이언트 ID를 추가합니다.

### 티켓 동기화가 인증 오류로 실패합니다

워크스페이스에 Linear 자동화가 연결되어 있지 않고 서버에 서비스 API 키도 없어서, 동기화에
쓸 자격 증명이 없습니다. 워크스페이스 관리자가 **자동화를 위해 Linear 연결**을 클릭합니다.

### 자동화를 연결하면 Linear 워크스페이스가 다른 곳에 연결되어 있다고 표시됩니다

그 Linear 워크스페이스의 Control Center 앱이 이미 다른 Control Center 서버에 연결되어
있습니다.
