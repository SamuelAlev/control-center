These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/ko-KR/매뉴얼/사용-가이드/); when you want to look
something up, go to the [reference](/ko-KR/매뉴얼/레퍼런스/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/ko-KR/매뉴얼/개념/워크스페이스/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/ko-KR/매뉴얼/개념/에이전트-모델/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/ko-KR/매뉴얼/개념/디스패치-수명주기/) — what happens between your message and the agent's first token
- [Modes](/ko-KR/매뉴얼/개념/모드/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/ko-KR/매뉴얼/개념/도구-컨텍스트/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/ko-KR/매뉴얼/개념/코드-인텔리전스/) — the code graph, language server, structural search and debugger
- [Conversation history](/ko-KR/매뉴얼/개념/대화-기록/) — persistence, compaction and forking a transcript
