**옵저버빌리티 → 품질**에는 단일 작업 평가 스위트와 짝을 이룬 스킬 캠페인이 모두
있습니다. 스킬 캠페인은 특정 모델과 하네스가 사용한 패키지를 측정하는 것이지, 그
Markdown 자체의 품질을 측정하는 것이 아닙니다.

## 평가 스위트

**평가 스위트**는 에이전트를 상대로 실행할 작업을 워크스페이스 범위에서 정의한
것입니다. 프롬프트, 대상 에이전트와 모드, 선택적 설정, 고정된 SHA가 있는 선택적
픽스처, 그리고 채점기 목록으로 이루어집니다. 채점기는 결정적 검사를 우선하며,
LLM 루브릭 판정자가 그런 검사로 표현할 수 없는 부분을 담당합니다.

워크스페이스를 만들면 스타터 스위트 다섯 개가 시드됩니다. 이들은 오케스트레이션
제안, 심어 둔 버그를 찾아내는 리뷰, 읽기 전용을 유지하는 플랜 모드, 플랜을
산출하는 플랜 모드, 티켓 왕복을 다룹니다. 시딩은 `WorkspaceCreated`
(`workspace.upsert` 또는 `workspace.create`)를 수신하고, 이미 있는 이름은
건너뛰며, 기존 워크스페이스를 소급해 채우지는 않습니다.

### 표시되는 위치

**옵저버빌리티 → 품질**(`/workspaces/<id>/observability`)에는 워크스페이스의 각
스위트가 나열됩니다.

`evals.upsertSuite`, `evals.deleteSuite`, `evals.watchSuites`로 스위트를 생성하고,
나열하고, 편집하고, 삭제합니다. 품질 탭이 목록이고, 그 작업들이 편집기입니다.

## 스킬 캠페인

캠페인은 같은 작업과 실행 구성 아래에서 두 개의 갈래를 비교합니다. 후보는 없거나,
평소처럼 사용 가능하거나, 명시적으로 로드되거나, 이전 리비전 또는 고정된 기본 제공
스킬 목록과 비교됩니다. 이것들은 서로 다른 질문에 답합니다. 강제 로드는 진단이며,
평소의 발견에 대한 점수가 아닙니다.
[스킬 가이드](/ko-KR/매뉴얼/사용-가이드/스킬-관리/#스킬-평가)에서 비교를 고르고
예산이 정해진 실행을 승인하는 방법을 설명합니다.

근거는 정확한 **패키지 전체 해시**에 속합니다: `SKILL.md`, 메타데이터, 스크립트,
참조, 자산입니다. 서버는 검사된 불변 패키지를 캡처하고 작업 모음, 어댑터,
제공업체/네이티브 모델 식별자, 프로토콜, 도구 스키마, 기본 제공 목록을 고정합니다.
네이티브 Claude 캠페인은 관리형 계정과 관측된 CLI 버전도 고정합니다. `SKILL.md`가
바뀌지 않았더라도 참조를 편집하면 현재 근거는 무효가 됩니다. 모델 별칭은 요청된
내용을 기록하는 것이지, 제공업체의 불변 가중치가 아닙니다.

각 시도는 새로운 컨텍스트, 홈, 픽스처 상태를 받습니다. 짝을 이룬 갈래는 선언된 스킬
개입을 제외하고 동일한 정책과 작업 조건을 사용합니다. 대상 없음은 후보의 메타데이터와
파일을 사용할 수 없다는 뜻이며, 모든 배경 지침이나 스킬이 제거되었다는 뜻이 아닙니다.
평소의 발견 비교에서는 작업 프롬프트에 후보의 이름을 적어서는 안 됩니다.

서버가 권한 부여, 실행, 예산, 워크스페이스 지속성을 담당합니다. 클라이언트는 설정을
고르고 근거를 표시합니다. 진행 상황은 재연결을 넘어 유지되고, 취소는 부분 결과를
보존하며, 재시작은 미완료 작업을 유료 호출을 조용히 반복하는 대신 중단됨으로
표시합니다. 이 캠페인은 임의의 평가 스위트를 위한 별도의 실행자 계약을 제공하지
않습니다.

## 근거를 보수적으로 읽기

- **정확성은 결과가 결정합니다.** 독립적인 형식 지정 검증자가 에이전트가 성공했다는
  주장이 아니라 결과물과 그로 인한 동작을 확인합니다. 예상 답은 후보의 격리 영역
  밖에 남고, 생성된 코드는 별도로 격리된 복사본에서 채점됩니다.
- **로드와 유용성은 다릅니다.** 사용 가능성, 본문/참조 로드, 관측된 스크립트 사용이
  실행을 설명합니다. 파일을 읽었다고 해서 모델이 그 지침을 따랐다는 증거는 아니며,
  관측할 수 없는 접근은 알 수 없는 상태로 남습니다.
- **짝을 맞춘 기준선을 유지하세요.** 후보 실행이 한 번 성공했다고 해서 이점이
  입증되지는 않습니다. 사용 가능한 스킬이 무시된 시도, 실패한 시도와 그 비용을
  포함하세요. 최선의 재시도만 남겨 두어서는 안 됩니다.
- **반복은 새로운 작업이 아닙니다.** 보고서는 작업별로 불확실성을 묶습니다. 적은
  표본, 누락된 적용 범위, 식별 정보 표류, 알 수 없는 지출은 채택 권고를 정당화할 수
  없습니다. 완료된 캠페인도 결론이 나지 않을 수 있으며, 개선을 보이지 못한 것이
  동등성이나 성능 저하의 증거는 아닙니다.
- **개별 성능 저하를 살펴보세요.** 집계된 이득이 손상된 작업이나 승인되지 않은
  부작용을 감춰서는 안 됩니다. 보안 검사, 런타임 안전성 관측, 유용성은 계속
  분리되어 있으며, 더 저렴한 실행이 누락된 품질이나 안전성 근거를 대신할 수는
  없습니다.
- **호환되지 않는 결과를 합치지 마세요.** 다른 모델, 하네스, 정책, 픽스처, 스킬
  조합은 다른 구성입니다. 따로 보관한 전이 및 구성 근거는 개발 사례와 분리해 두세요.

로컬에서 작성한 아홉 개의 파일럿 코퍼스에는 유용성, 계열별 라우팅/안전성, 따로 보관한
전이/구성을 아우르는 108개의 작업 항목이 있습니다. 스킬의 목적에 맞는 계열을
고르세요. 참조 솔루션과 알려진 불량 출력이 검증자를 점검합니다. 이 픽스처는 공개
벤치마크의 재현이 아니며, 설치된 스킬이 유용하다는 근거도 아닙니다. 스크립트화된
제공업체 응답으로 수행한 구현 스모크 실행은 실제 모델에서의 스킬 품질 측정이
아닙니다.

## 실행과 근거의 한계

통제된 **내장 하네스**와 **Claude Code** 어댑터가 지원됩니다. 실행 전에 격리와 활성
자격 증명 검사를 통과해야 합니다. 내장 제공업체는 문서화된 도구 지원, 토큰 한도,
가격 책정이 필요합니다. **Codex OAuth**는 별도의 OpenAI API 키를 요구하지 않고
자체 계정을 인증합니다. **Claude Code**는 기본 관리형 계정, 구체적인 모델 ID,
네이티브 API 환산 비용 보고서를 사용합니다.

**Claude Code**와 **Codex OAuth**는 **사용량 중단 임계값**을 사용합니다. 진행 중인
호출이 예산을 초과할 수 있고, 그다음 이후 호출이 중단됩니다. 이것은 청구되는 구독
지출도, 엄격한 청구 상한도 아닙니다. API 키 제공업체는 호출 전 보수적인 예약을
유지합니다. 관측된 지출을 알 수 없으면 모든 어댑터에서 이후 호출이 중단됩니다.
불완전한 적용 범위는 부분 또는 결론 불가로 남습니다.

**Claude**는 내장 도구와 기본 제공 스킬을 비활성화한 상태에서 프라이빗 컨트롤러
디렉터리에서 네이티브 모델 루프를 실행합니다. 유일한 도구는 내장 하네스가 사용하는
것과 동일한 격리된 게스트로 들어가는, 인증된 서버 소유 MCP 브리지입니다. 자격 증명은
그 게스트 밖에 남습니다. CLI 식별 정보나 도구 표면이 바뀌면 실행자를 조용히 교체하는
대신 해당 시도가 무효가 됩니다. 플릿 평가와 Windows는 지원되지 않습니다. 워커의 Git
프로브나 프롬프트 에코가 성공해도 평가로 치지 않습니다.

macOS 격리는 게스트 네트워크와 외부 파일 시스템 접근을 거부하고, 프로세스 분리를
차단하며, CPU/파일/출력을 제한하고 소유한 하위 프로세스를 정리하지만, **엄격한 메모리
할당량을 강제하지는 않습니다**. Linux는 bubblewrap이 필요하며 주소 공간 한도를
적용합니다. 초기 격리 검증은 macOS를 대상으로 했으며 Linux는 아니었습니다. 격리가
없다고 해서 호스트 셸로 되돌아가는 일은 결코 없습니다. 제공업체 자격 증명은 게스트
도구 밖인 서버에 남습니다.

시도 근거는 민감 정보가 제거되고 256 KiB로 제한됩니다. 내보내기는 16 MiB로
제한됩니다. 큰 내보내기는 허용된 모든 시도에 대해 간결한 결과/비용 요약을 보존하고
생략되거나 요약된 트레이스 내용을 명시적으로 보고합니다. 내보내기나 보고서 어느 쪽도
비공개 소스의 완전한 재현 번들을 담지 않습니다. 합성 안전성 검사는 실제 유출 저항성을
입증하지 않고, 격리를 무효화하지 않으며, 스킬을 안전하다고 인증하지도 않습니다.
