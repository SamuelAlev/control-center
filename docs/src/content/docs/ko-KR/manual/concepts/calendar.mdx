Control Center는 Google Calendar에 연결해 여러분의 하루가 플릿과 나란히
자리하도록 합니다. 일정을 동기화하고 월, 주, 일, 아젠다 뷰로 보여 주며, 일정을 예약, 이동, 응답, 삭제할 수 있게 하고, 회의가
시작되기 전에 알려 주고, 어떤 이벤트든 녹음과 요약이 이루어지는
[회의](/ko-KR/매뉴얼/개념/회의/)로 바꿔 줍니다.

## Google에서 바꾸는 것

내가 직접 하는 것만 바뀝니다. 초대에 응답하고, 이벤트를 예약(시간 그리드를 드래그하거나 **+** 버튼 사용)하고,
이벤트를 이동(시간 그리드에서 드래그하거나 길이를 조정)하고 삭제할 수 있습니다. 이동할 수 있는 것은 내 이벤트와 내가 주최한 이벤트뿐입니다. 게스트가 옮기면 다른 모든 사람은 예전 시간에 남게 되기 때문입니다. 각 변경은 서버가 내 계정의 로그인으로, 내 캘린더에 대해 수행하며, 다른 멤버의
계정이나 나에게 읽기 전용으로 공유된 캘린더에 대한 이벤트는 서버가 거부합니다. Google은 Google Calendar에서와
마찬가지로 게스트에게 이메일을 보냅니다. 반복 이벤트의 한 발생만 이동하거나 삭제해도 시리즈의 나머지는 남습니다.

Connect를 통하든 서버 자체 Google 클라이언트를 쓰든 모든 연결은 `calendar.events`(이벤트 읽기 및 변경)와
`calendar.calendarlist.readonly`(계정의 캘린더 목록 확인)에 `openid email`을 더해 요청합니다. 서버는 다른 범위
집합으로 돌아온 로그인을 거부하므로, 이전 읽기 전용 범위로 연결된 계정은 다시 연결해야 합니다.

이벤트는 **서버의** 워크스페이스 자체 데이터베이스
(`<dataDir>/<workspaceId>/workspace.db`)로 동기화되고, 모든 클라이언트가 RPC를
통해 렌더링합니다. 어떤 클라이언트도 Google 자격 증명을 보유하지 않습니다.

## 워크스페이스별 계정

캘린더 계정은 Control Center의 다른 모든 것과 마찬가지로 워크스페이스 범위이며,
각각 그것을 연결한 멤버에게 속합니다. 각
[워크스페이스](/ko-KR/매뉴얼/개념/워크스페이스/)는 자체 Google 계정을 연결하며, 한
워크스페이스의 이벤트와 자격 증명은 다른 워크스페이스에서 절대 보이지 않습니다. 같은
Google 주소를 연결한 두 멤버에게는 계정이 두 개 생깁니다. 워크스페이스를 전환하면
보이는 캘린더도 바뀝니다.

워크스페이스는 업무용 계정과 개인 계정처럼 **여러** Google 계정을 연결할 수
있으며, 그 이벤트는 같은 뷰에 병합됩니다.

## 로그인이 서버에 도달하는 방식

연결은 브라우저 로그인이며, 이를 완료하는 것은 서버입니다. 어떤 클라이언트로
실행할지는 서버 소유자가 고릅니다.

- **서버 자체 Google 클라이언트.** 리디렉션 `<server origin>/oauth/google/callback`으로
  등록한 웹 애플리케이션 클라이언트입니다. Google이 브라우저를 서버로 바로 돌려보내므로
  브라우저가 서버에 도달할 수 있어야 합니다
- **Control Center Connect.** Google이 브라우저를 Connect로 돌려보내고, Connect는
  8자리 코드와 `control-center://` 링크를 표시합니다. 사용자가 앱에 코드를 입력하거나
  링크를 따라가면, 서버가 그것으로 로그인을 받아 갑니다. 이 경우 서버에 공개 주소가
  필요 없으며, 덕분에 사설 네트워크의 헤드리스 서버도 캘린더를 연결할 수 있습니다

자체 클라이언트가 항상 우선합니다. 시크릿 없는 클라이언트 ID는 완료되지 않은 설정이며,
Connect로 폴백하지 않고 로그인을 거부합니다.

자격 증명은 서버를 떠나지 않습니다. 데이터 디렉터리의 `secrets.json`에
`google_google:<workspaceId>:<userId>:<email>` 키로 기록되며, 데이터베이스와 나란히, 동일한
호스트 파일 시스템 신뢰 경계 아래에 놓입니다. 자체 클라이언트 로그인은 액세스 토큰과
리프레시 토큰을 저장합니다. Connect 로그인은 Connect가 이 서버만을 위해 여는 봉인된
자격 증명만 저장하며, 액세스 토큰은 메모리에만 머뭅니다. 서버는 액세스를 자동으로
갱신하며, Google이 계정을 영구적으로 무효화하면(취소되었거나 오래 만료된 세션)
`CalendarAuthExpired`를 게시하고 조용히 실패하는 대신 **다시 연결** 배너를
표시합니다. 이 서버가 더 이상 사용할 수 없는 로그인(다른 자체 클라이언트가 발급했거나,
다른 설치나 Connect용으로 봉인된 것)은 다음에 읽힐 때 지워지고 같은 배너가 표시됩니다.

Google 자격 증명을 포함한 빌드는 없습니다. 서버의 클라이언트는 **설정 → 서버 → 싱글
사인온 → 프로바이더 앱** 또는 서버의 `.env` 파일(`GOOGLE_OAUTH_CLIENT_ID`,
`GOOGLE_OAUTH_CLIENT_SECRET`)에서 가져옵니다. 명령줄 플래그는 의도적으로 없습니다.
명령줄의 시크릿은 `ps`로 읽을 수 있으며, 시크릿이 프로세스 환경에 내보내져 있으면
서버가 시작을 거부합니다.

직접 Google 프로젝트를 운영하려면
[Google Calendar 연결](/ko-KR/매뉴얼/사용-가이드/캘린더-연결/)을 참고하십시오.

## 동기화

서버는 연결된 각 계정의 이벤트, 즉 기본 캘린더만이 아니라 계정의 모든 캘린더를
**2분마다** 롤링 윈도우로 가져오며, 필요할 때(시작, 연결, 수동 새로 고침)에도
가져옵니다. 이렇게 짧은 주기가 가능한 것은 스윕이 증분 방식이기 때문입니다. 각
캘린더는 자체 동기화 토큰을 가지므로, 변경되지 않은 캘린더는 5개월 윈도우를 다시
가져오는 대신 거의 빈 응답 하나만 소비합니다.

반복 이벤트는 서버 쪽에서 확장되므로 어떤 클라이언트도 반복 규칙을 파싱하지
않습니다. 현재 윈도우 밖의 달로 이동하면 해당 범위를 지연 로드합니다.
삭제되었거나 범위 밖으로 이동한 이벤트는 다음 동기화에서 정리됩니다.

## 뷰

| 뷰         | 표시 내용                                             |
| ---------- | ----------------------------------------------------- |
| **월**     | 한 달 전체 그리드(`kalender` 패키지 사용)             |
| **주**     | 한 주의 시간 지정 이벤트를 시간 그리드로              |
| **일**     | 하루의 시간 지정 이벤트를 시간 그리드로               |
| **아젠다** | 다가오는 이벤트의 스크롤 가능한 목록                  |

캘린더는 `/calendar`에서 열며, 이벤트를 선택하면 `/calendar/:eventId`에서 상세가
열립니다. 선택한 뷰는 그 클라이언트 자체 환경설정에 저장되므로 다른 기기로
따라가지 않습니다.

## 회의 알림

1분마다 실행되는 스케줄러가 구성 가능한 사전 알림 구간 안에 시작하는 이벤트를
검사하고 **"회의가 곧 시작됩니다"** 알림(`MeetingStartingSoon`
[도메인 이벤트](/ko-KR/매뉴얼/개념/도메인-이벤트/))을 발생시킵니다. 알림에는 참가
URL이 있을 때 그것이 함께 실리며, 클릭하면 이벤트 상세가 열립니다. 알림은
이벤트의 `alertedAt`을 기준으로 중복 제거되므로, 재시작을 넘어서도 같은 회의가 두
번 알리지 않으며, 앱이 닫혀 있는 동안 시작 시각이 지난 이벤트도 다시 재생되지
않습니다.

쉽게 걸려 넘어질 수 있는 두 가지 제한이 있습니다. 스케줄러는 **데스크톱의
클라이언트 측에서** 실행되며 현재 열어 둔 워크스페이스에만 적용됩니다. 들어가 있지
않은 워크스페이스는 알림을 발생시키지 않습니다. 그리고 웹 빌드에는 OS 알림
파이프라인이 전혀 없으므로 웹에서도 알림이 발생하지 않습니다.

## 녹음 및 연결

캘린더 이벤트에서 이벤트 제목을 초깃값으로 한
[회의 녹음](/ko-KR/매뉴얼/개념/회의/)을 시작할 수 있습니다. Control Center는 녹음과
이벤트 사이에 일대일 링크를 저장하므로, 어느 기능도 서로에 의존하지 않으면서 회의
노트와 캘린더 항목이 연결된 상태로 유지됩니다.

**녹음 시작 및 연결**은 데스크톱 전용입니다. 웹 클라이언트에서 이 작업은 녹음이
사용할 수 없다고 알립니다. 회의 화면 자체의 녹음 흐름은 브라우저에서 작동하는데도
그렇습니다.

:::note[에이전트는 캘린더를 읽을 수 없습니다]
캘린더 MCP 도구는 없습니다. 에이전트는 이벤트를 나열하거나 이벤트 상세를 읽거나
여러분을 대신해 예약, 이동, 삭제 또는 참석 응답을 할 수 없습니다. `calendar.*` 표면은 사람 클라이언트
전용 RPC입니다.
:::
