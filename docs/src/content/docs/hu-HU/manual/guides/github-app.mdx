Ez az útmutató bemutatja, hogyan adhat a szerverének saját GitHub Appot.
Körülbelül két percet vesz igénybe, csak a szerver tulajdonosa végzi el, és
szerverenként csak egyszer kell megtenni.

:::note[Lehet, hogy nincs rá szüksége]
Bekapcsolt Control Center Connect mellett az emberek a Control Center megosztott
Appján vagy a szervezete Connectje által használt Appon keresztül jelentkeznek
be a GitHubra. Akkor regisztráljon sajátot, ha a **Saját alkalmazások
használata** lehetőséget választotta: a szerver saját Appja csak ebben az esetben érvényes. Lásd:
[Control Center Connect](/hu-HU/kezikonyv/referencia/connect/).
:::

A saját fiókjába való későbbi bejelentkezésről lásd a
[GitHub-integráció beállítása](/hu-HU/kezikonyv/gyakorlati-utmutatok/github-integracio/)
oldalt.

## Mit csinál az alkalmazás

Egyetlen regisztráció két különböző feladatot lát el:

| Feladat                      | Mi szolgálja ki                                 | Miért fontos                                                                                    |
| ---------------------------- | ----------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **Egy személy bejelentkezik** | Az alkalmazás kliens-ID-ja és kliens titka      | Mindenki saját GitHub-hitelesítő adatot kap, a szerveren, minden eszközén                       |
| **A szerver cselekszik**     | Az alkalmazás azonosítója és privát kulcsa      | Az ügynökök, a pipeline-ok, a lekérdezők és a botválaszok egyszerre egyetlen repóra szóló tokeneket kapnak |

A második feladat soha nem kölcsönzi el egészben egy személy hitelesítő adatát.
Minden token, amelyet a szerver kiállít, egyetlen repóra szól, és arra
korlátozódik, amit egy felelős tag ott megtehet. Egy kapcsolt repó olvasásához
elég az alkalmazás; bármihez, ami ír, olyan tag kell, aki pusholhat. Az
automatizálás soha nem hagy jóvá pull requestet.

A szerver saját alkalmazása csak a **Saját alkalmazások használata** esetén érvényes. A
Control Center vagy egyéni Connect esetén a Connect kezeli az összes sávot, a GitHubot is,
a szerver alkalmazása pedig mentve marad, de nincs használatban, amíg vissza nem vált. A
saját alkalmazásokat használó munkaterület ([Egy munkaterület saját alkalmazása](#egy-munkaterület-saját-alkalmazása))
a saját alkalmazását használja a szerver módjától függetlenül. Az az alkalmazás, amelynek egyes mezői hiányoznak, hiba, nem
tartalékra váltás: a GitHub-bejelentkezések elutasításra kerülnek, amíg minden mező be nincs állítva.

## Előfeltételek

- Ön a **szerver tulajdonosa**. A **Szolgáltatói alkalmazások** kártya mindenki
  más számára láthatatlan
- Egy GitHub-fiók. Az alkalmazás ez alatt jön létre
- Egy szervercím, amelyet a böngészője elér. A szerver nyilvános URL-je (vagy
  egy asztali gép saját szerverénél a loopback) az a hely, ahová a GitHub
  visszaküldi Önt

## Létrehozás egyetlen kattintással

1. Lépjen a **Beállítások → Szerver → Egyszeri bejelentkezés** oldalra, és
   görgessen a **Szolgáltatói alkalmazások** kártyához
2. A **GitHub** blokkban a **Szervezet (nem kötelező)** mezőbe beírhatja azt a
   GitHub-szervezetet, amelynek az alkalmazás tulajdonában kell lennie. Hagyja
   üresen, ha a saját fiókja alatt szeretné létrehozni; egy szervezet alatti
   létrehozáshoz a szervezet egyik tulajdonosa kell
3. Kattintson a **Saját GitHub-alkalmazás létrehozása** elemre
4. A böngészője megnyitja a GitHubot az előre kitöltött alkalmazással.
   Kattintson a **Create GitHub App** gombra
5. A GitHub visszaküldi Önt a szerverre, amely eltárolja az alkalmazás
   azonosítóját, a privát kulcsot, a kliens-ID-t és a kliens titkot, majd
   megnyitja az alkalmazás telepítési oldalát

Semmit nem kell kézzel másolni, és a konverziós kód közvetlenül a GitHubról jut
a szerverére. A hivatkozás egyszer működik, és tíz perc után lejár; ha lejár,
kattintson újra a **Saját GitHub-alkalmazás létrehozása** elemre.

Az alkalmazás neve `Control Center <code>`, és pontosan azt kéri, amit a
Control Center használ:

| Jogosultság                                | Hozzáférés        |
| ------------------------------------------ | ----------------- |
| Metadata                                   | Olvasás           |
| Contents                                   | Olvasás és írás   |
| Pull requests                              | Olvasás és írás   |
| Issues                                     | Olvasás és írás   |
| Checks, Actions, Commit statuses           | Olvasás           |
| Organization members                       | Olvasás           |

A webhookok ki vannak kapcsolva: a szerver lekérdez. Ha a saját fiókja alatt
létrehozott alkalmazást később egy szervezethez szeretné áthelyezni, használja a
**Transfer ownership** lehetőséget az alkalmazás speciális beállításaiban a
GitHubon.

Ellenőrzőpont: a GitHub blokk ezt írja: „A szerver tud magaként viselkedni, és
az emberek bejelentkezhetnek.”

## Telepítse oda, ahol a repói vannak

A regisztrált, de nem telepített alkalmazás be tudja jelentkeztetni az
embereket, de semmit nem olvas.

1. A GitHub által megnyitott telepítési oldalon válassza ki azt a fiókot vagy
   szervezetet, amely a repói tulajdonosa
2. Válassza az **All repositories** lehetőséget, vagy jelölje ki azokat,
   amelyeket ennek a szervernek látnia kell

Ha később egy másik fiókra szeretné telepíteni, egy munkaterület-adminisztrátor
a **Beállítások → Munkaterület → Integrációk** oldalra lép, a **GitHub-alkalmazás**
kártyán (a Kódtárhely alatt) megkeresi a **GitHub-alkalmazás telepítései** részt, és a
**GitHub-alkalmazás telepítése** elemre kattint. A lista minden fiókot mutat,
amelyre az alkalmazás telepítve van, és jelöli a felfüggesztett telepítést.

## Egy szervezet telepítésének megosztása

Egy szervezet egyszer telepíti a GitHub Appot. Ezután a szervezet bármely tagja, aki bejelentkezik a GitHubra egy Control Center szerveren, használhatja a telepítést, bárhol is legyen az a szerver: az Öné, egy munkatársáé vagy a sajátja. Szerverenként nincs mit engedélyezni.

A szerver minden tokenje a bejelentkezett személyé, egyetlen repóra és az ott betöltött szerepére korlátozva, így soha nem terjedhet tovább annál, mint amit a GitHubon maga is megtehetne. A GitHub naplója ezt a személyt mutatja, aki az alkalmazáson keresztül jár el.

Hogy a Control Center ne érhessen el egy szervezetet, a szervezet tulajdonosa eltávolítja a telepítést a GitHubon, vagy szűkíti a repóit. A személy szervezetből való eltávolítása az ő hozzáférését is megszünteti.

## Regisztrálás inkább kézzel

A **Szolgáltatói alkalmazások** kártya az értékeket közvetlenül is elfogadja egy
olyan alkalmazáshoz, amelyet saját maga regisztrált:

| Csoport                          | Mezők                                                                                           |
| -------------------------------- | ----------------------------------------------------------------------------------------------- |
| **A szerverként viselkedés**     | **Alkalmazás-ID** és **Privát kulcs** (a teljes `.pem`, a `BEGIN` és `END` sorokkal együtt)      |
| **Emberek bejelentkeztetése**    | **Kliens-ID** és **Kliens titok**. A **Visszahívási URL-ek** szó szerint mutatják a regisztrálandó URL-t |
| **Pull request beszélgetések**   | **Bot bejelentkezési név**, a kapcsolat tesztelésekor feloldva                                  |

Regisztrálja a `<server origin>/oauth/github/callback` visszahívási URL-t
pontosan úgy, ahogy a kártya mutatja, hagyja bekapcsolva az **Expire user
authorization tokens** beállítást, és adja meg a fenti táblázat jogosultságait.
Kattintson a **Teszt** elemre: megkérdezi a GitHubot, mely fiókokra van
telepítve az alkalmazás, így a „mentve” és a „működik” nem keveredik össze.

## Beállítás a szerver `.env` fájljából

Headless vagy szkriptelt telepítésnél a szerver minden mezőt a `.env` fájljából
tölt fel, amikor először nincs rá tárolt értéke:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

A kulcsot **egy sorba** írja: egy `.env`-érték egyetlen sor, és a dupla
idézőjelek közötti `\n` sortörésként dekódolódik. A szerver nem indul el, ha a
`GITHUB_APP_PRIVATE_KEY` vagy a `GITHUB_CLIENT_SECRET` a folyamata környezetébe
van exportálva, ahol minden gyermekfolyamat kiolvashatná; tartsa őket a `.env`
fájlban (Dockerben csatolja a `/app/bin/.env` helyre). A feltöltés **mezőnként
egyszer** történik, így a Beállításokban végzett szerkesztést a következő
újraindítás nem vonja vissza.

## Egy munkaterület saját alkalmazása

Egy munkaterület a szerver alkalmazása helyett saját alkalmazást is használhat:

1. Egy munkaterület-adminisztrátor a **Beállítások → Munkaterület → Integrációk** oldalra lép
2. A **Control Center Connect** kártyán a **Saját alkalmazások használata** lehetőséget választja, majd az **Alkalmazás** gombra kattint. Mindenki a munkaterületen ezután a munkaterület alkalmazásain keresztül jelentkezik be
3. A **GitHub-alkalmazás** kártya a Kódtárhely alatt mostantól tartalmazza az alkalmazás mezőit: az **Alkalmazás-ID** és a **Privát kulcs** az **Ennek a munkaterületnek nevében jár el** alatt, a **Kliens-ID** és a **Kliens titok** az **Emberek bejelentkeztetése** alatt. Miután ezek be vannak állítva, kattintson a **Teszt** gombra

A tagok ezután ehhez a munkaterülethez ebbe az alkalmazásba jelentkeznek be. A saját alkalmazásokat
használó munkaterület soha nem vált a szerver alkalmazására vagy a Connectre: amíg a mezői nem
teljesek, a GitHub-munkája elutasításra kerül.
Ugyanez a választás vonatkozik a Google Calendarra, a Linearra és a GIF-keresésre is, mindegyik a
saját mezőivel a szolgáltatója mellett ugyanazon az oldalon. Lásd: [Egy munkaterület saját Linear-alkalmazásának beállítása](/hu-HU/kezikonyv/gyakorlati-utmutatok/linear-integracio/#egy-munkaterület-saját-linear-alkalmazásának-beállítása)
és [Egy munkaterület saját Google-kliensének beállítása](/hu-HU/kezikonyv/gyakorlati-utmutatok/naptar-csatlakoztatasa/#egy-munkaterület-saját-google-kliensének-beállítása).
A többi választást és azok hatását a [Munkaterületenkénti választás](/hu-HU/kezikonyv/referencia/connect/#munkaterületenkénti-választás) szakasz írja le.

## Hibaelhárítás

### A Saját GitHub-alkalmazás létrehozása azt írja, hogy a szervernek nincs címe

A szervernek nincs olyan nyilvános URL-je, amelyre egy böngésző visszatérhetne.
Állítsa be a `CC_SERVER_PUBLIC_URL` értékét (vagy a `--public-url` kapcsolót), és
próbálja újra.

### A GitHub azt írja, hogy a hivatkozás lejárt

Az egyszer használatos oldalt már felhasználták, vagy eltelt tíz perc. Kezdje
újra a Beállításokból.

### A teszt szerint a hitelesítő adatok működnek, de az alkalmazás sehol nincs telepítve

A regisztráció és a telepítés külön lépés. Nyissa meg az alkalmazás telepítési
oldalát, vagy használja a **GitHub-alkalmazás telepítése** elemet a Munkaterület
→ Integrációk helyen.

### A teszt szerint a privát kulcs nem olvasható

Illessze be a teljes `.pem` fájlt, a `-----BEGIN` és `-----END` sorokkal együtt.
`ed25519` vagy EC kulcs nem használható: a GitHub Appok RSA-val írnak alá.

### Egy tag bejelentkezett, de nem lát repókat

Az alkalmazás nincs telepítve a repók tulajdonosának fiókján, vagy a telepítése
más repókat jelöl ki. A bejelentkezés csak azt teszi elérhetővé, amit az
alkalmazás láthat.

### Az ügynökök azt írják, hogy a GitHub App telepítése fel van függesztve

Valaki felfüggesztette a telepítést a GitHubon. Szüntesse meg a felfüggesztést
az adott fiók **Settings → Applications → Installed GitHub Apps** oldalán.
