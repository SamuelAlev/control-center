Ez az útmutató a beállítás GitHub-specifikus részeit tárgyalja. A GitHub a három
támogatott kódhoszt egyike. A GitLab vagy a Bitbucket csatlakoztatásáról,
illetve arról, hogyan használ egy munkaterület egyszerre többet, lásd a
[Kódhoszt csatlakoztatása](/hu-HU/kezikonyv/gyakorlati-utmutatok/kodhoszt-csatlakoztatasa/)
oldalt.

## Előfeltételek

- Egy GitHub-fiók, amely hozzáfér azokhoz a repókhoz, amelyeken dolgozni szeretne
- Egy szerver, amely be tudja jelentkeztetni az embereket a GitHubra: vagy a
  saját GitHub Appjával (lásd a
  [GitHub App létrehozása](/hu-HU/kezikonyv/gyakorlati-utmutatok/github-app/) oldalt), vagy a
  Control Center Connecttel; ezt a szerver tulajdonosa választja ki a
  **Beállítások → Szerver → Egyszeri bejelentkezés** helyen

:::note[A hitelesítő adatok a szerveren élnek, Önhöz rendelve]
Semmi nem tárolódik azon a gépen, amelyen éppen gépel. A GitHub-bejelentkezését
a `cc_server` tárolja, az Ön felhasználói azonosítójához rendelve, és minden
eszköz, amelyről bejelentkezik, ugyanazt használja: asztali gép, web és
telefon. Ugyanazon szerver egy másik tagja nem tudja használni, és a
bejelentkeztetése olyan dolog, amelyet ők maguk végeznek el.
:::

## Bejelentkezés a GitHubra

A GitHub kizárólag bejelentkezéssel működik: nincs beillesztendő token.

1. Nyissa meg a **Beállítások → Munkaterület → Profil és identitás → Kódtárhely**
   oldalt (vagy a bevezető első lépését)
2. A **GitHub** sorban kattintson a **Bejelentkezés: GitHub** elemre
3. A böngészője megnyitja a GitHubot. Hagyja jóvá az alkalmazást

A bejelentkezés befejezése attól függ, ki futtatja:

- **A szerver saját alkalmazása:** a GitHub visszaküldi a böngészőt a szerverre,
  és a párbeszédablak ezt magától észreveszi. Nem kell semmit beírnia
- **Control Center Connect:** a böngészőoldal egy 8 karakteres kódot mutat. Írja
  be a párbeszédablakba, vagy hagyja, hogy a böngésző a `control-center://`
  hivatkozáson keresztül megnyissa a Control Centert, és hagyja ki a beírást

Ellenőrzőpont: a **GitHub** sor ezt írja: „Bejelentkezve mint _your-username_”.

A párbeszédablak elutasítja azt a kódot vagy hivatkozást, amelyet nem ő maga
indított, ezzel az üzenettel: **A bejelentkezést nem innen indították**. Ha valaki
bejelentkezési hivatkozást küld Önnek, ne folytassa: a befejezése az Ön fiókját
az ő szerveréhez kapcsolná.

A bejelentkezés eltávolításához kattintson a **Leválasztás** elemre. Ha
kijelentkezik a GitHubról, vagy eltávolítják egy munkaterületről, azzal minden
olyan token is megszűnik, amelyet a szerver az Ön nevében állított ki.

## Kinek a nevében szól a hitelesítő adata

- **Bármi, amit Ön tesz** (a PR-oldal megnyitása, átnézés közzététele,
  jóváhagyás, összefésülés), az **Ön** bejelentkezésén fut, és semmi máson. Ha
  nincs bejelentkezve, az alkalmazás ezt jelzi, és bejelentkezést kér. Semmilyen
  más hitelesítő adat nem lép az Ön helyébe
- **Az a munka, amelynél senki sem gépel** (ügynökfutások, pipeline-ok,
  PR-lekérdezés, botválaszok, klónozás), egyetlen repóra szóló tokent kap,
  amelyet a szerver GitHub Appja vagy a Connect állít ki. Ez arra korlátozódik,
  amit egy felelős tag ott megtehet: aki kérte, egyébként a munkaterület
  tulajdonosa. Az a tag, aki nem pusholhat, olvasásra korlátozza a tokent
- **Az automatizálás soha nem hagy jóvá** pull requestet. A jóváhagyás egy
  személy cselekedete

## Mit ad az integráció

| Funkció | Hogyan |
| --- | --- |
| PR-lista és részletek | A GitHub REST API a szerverről, az Ön saját bejelentkezésével |
| Check-futtatások | A GitHub Checks API |
| Átnézés közzététele | Felhasználó által indított lépés, amely közzéteszi az átnézését a PR-ben, az Ön nevében |
| Repóregisztráció | Egy checkout akkor fogadható el, ha az `origin` remote-ja a github.com-ra mutat, vagy a gitlab.com / bitbucket.org oldalra |
| Ügynök GitHub-hozzáférése | Egy token a futtatás egyetlen repójára `GH_TOKEN` / `GITHUB_TOKEN` néven; a pushok a Control Centeren mennek át |
| Értesítési jelzések | A GitHub-értesítési postaládájának szerveroldali lekérdezése „Említve egy pull requestben” és „Átnézést kértek” értesítéseket vált ki |
| Felhasználói profilok | Profilkártyák rámutatáskor és a PR-ek szerző szerinti szűrése |

Egyes útvonalak a REST helyett a GraphQL API-t használják, ahol az olcsóbb: az
ágak tevékenységét a PR-összeállító választóhoz, és az élő átnézési állapotot,
amely eldönti, hogy egy „átnézést kértek” értesítés még függőben van-e.

## Figyelje a GitHub-kimaradásokat

A címsor állapotjelvényt mutat, ha egy szolgáltató csökkentett szolgáltatással
üzemel; ez a GitHubra, a Claude-ra, az OpenAI-ra és a Kimira terjed ki.
**Mindaddig rejtve marad, amíg minden egészséges**: a jelenlét problémát jelez,
nem annak hiányát.

Kattintson a jelvényre egy lenyíló panel megnyitásához, amely minden szolgáltató
állapotát és egy frissítés gombot mutat. Az állapotok maguktól frissülnek
kétpercenként.

## Hogyan lépnek fel az ügynökök a GitHubon

- Egy GitHub-worktree-ben dolgozó ügynök erre az egy repóra szóló tokent kap.
  Olvashatja a kódot, és megjegyzést fűzhet a pull requestekhez, ha a felelős
  tag pusholhat, ha pedig nem, csak olvashat. A push a Control Centeren megy át, amely megkérdezi a
  **Küldés távoli tárolóra** szabályt, majd egy olyan írási tokennel továbbítja,
  amely soha nincs az ügynök birtokában. Lásd a
  [Homokozószabályzatok konfigurálása](/hu-HU/kezikonyv/gyakorlati-utmutatok/homokozoszabalyzatok/) oldalt
- Az ügynök commitjai mindig a kérő Git-identitását használják szerzőként és commitolóként is. Alapértelmezés szerint a `Co-Authored-By: Control Center <hi@usectrl.dev>` trailer a GitHub `@usectrl` fiókját társszerzőként tünteti fel. A **Beállítások → Ön → Commit-hozzárendelés** oldalon kikapcsolhatja ezt a társszerzői elismerést az identitása megváltoztatása nélkül. A **Beállítások → Munkaterület → Általános** oldalon megadott felülírás elsőbbséget élvez, és zárolja a személyes kapcsolót. A Claude Code saját szerzőségi jelölése mindig ki van kapcsolva. A commitok aláírásához továbbra is külön érvényes konfiguráció szükséges
- Egy állomáson megnyitott terminál az Ön saját bejelentkezését kapja, erre az
  egy repóra szűkítve, így az onnan indított pushok az Önéi
- Ha nem állítható ki token (senki felelős nincs bejelentkezve, az alkalmazás
  nincs telepítve a tulajdonosnál, vagy a telepítés fel van függesztve), a futás
  token nélkül indul, és a jegyzetei megmondják, miért. Nincs tartalék
  hitelesítő adat

## Hibakeresés

### A PR-lista üres, és azt írja, hogy a GitHub nincs csatlakoztatva

Nincs bejelentkezve a GitHubra ezen a szerveren. Kattintson a **Bejelentkezés:
GitHub** elemre a **Kódtárhely** alatt. A más kódhosztokon lévő repók
érintetlenek.

### A GitHub sor azt írja, hogy a bejelentkezés nincs beállítva ezen a szerveren

A szervernek nincs sem saját GitHub Appja, sem Connectje. A szerver tulajdonosa
a **Beállítások → Szerver → Egyszeri bejelentkezés** helyen választja ki az
egyiket: a **Saját GitHub-alkalmazás létrehozása** körülbelül két percet vesz
igénybe. Lásd a [GitHub App létrehozása](/hu-HU/kezikonyv/gyakorlati-utmutatok/github-app/) oldalt.

### A párbeszédablak azt írja, hogy a kód nem egyezik

Írja be a kódot pontosan úgy, ahogy a böngésző mutatja: 8 betű és számjegy. Öt
hibás kód lezárja a bejelentkezést; kezdje újra.

### A bejelentkezés azt írja, hogy az alkalmazás nincs telepítve

A GitHub Appnak nincs telepítése azon a fiókon, amely a repó tulajdonosa. Egy
munkaterület-adminisztrátor a **Beállítások → Munkaterület → Általános →
GitHub-alkalmazás telepítései** helyen telepíti. A Control Center megosztott
Appját használó szervezetnél előfordulhat, hogy a szervezet egyik
adminisztrátorának a **A szerver engedélyezése** gombra kell kattintania. Lásd:
[GitHub App létrehozása](/hu-HU/kezikonyv/gyakorlati-utmutatok/github-app/#a-szerver-engedélyezése-egy-szervezet-számára).

### Mindenkinek újra be kell jelentkeznie a GitHubra

A szerver tulajdonosa lecserélte a szerver Connect-kulcsát, Connect-szervert
váltott, vagy az adatkönyvtárat egy másik gépre állították vissza. A Connecten
keresztüli bejelentkezések ahhoz a szerverhez kötődnek, amely létrehozta őket.

### Egy repó hozzáadása elutasításra kerül

A regisztrációhoz mindhárom feltétel kell: az útvonal egy git-worktree-n belül
van, van `origin` remote-ja, és ez a remote egy támogatott kódhosztra mutat
(github.com, gitlab.com vagy bitbucket.org). Lásd a
[Repók hozzáadása munkaterülethez](/hu-HU/kezikonyv/gyakorlati-utmutatok/repok-hozzaadasa/) oldalt.

### Nagy használat után egy időre minden leáll

Ez a sebességkorlát-védőkapcsoló. A GitHub az elsődleges korlátját egy `403`-mal
jelzi, amely `x-ratelimit-remaining: 0` értéket és egy visszaállítási időt
hordoz; amikor a kliens ilyet lát, a további kéréseket hálózati hívás nélkül,
helyben hiúsítja meg az ablak elteltéig, így az újrapróbálkozások vihara nem
mélyíti tovább a korlátot. Az átmeneti hibákat legfeljebb háromszor próbálja
újra exponenciális visszalépéssel, a `retry-after` fejlécet betartva.
