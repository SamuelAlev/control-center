Ez az útmutató megmutatja, hogyan csatlakoztasson egy külső MCP-klienst — a
Claude Code-ot, egy szerkesztőt, az MCP Inspectort — a Control Center saját
eszközszerveréhez.

A Control Center **110** eszközt regisztrál, és ezeket a Model Context
Protocolon keresztül, `2024-11-05` protokollverzióval szolgálja ki. Egész
eszközcsaládok hiányoznak, amelyekre pedig számítana: nincsenek megbeszélés-
vagy naptáreszközök, és projekteszközök sincsenek.

## A végpont megkeresése

Az MCP-felület a fő `cc_server` figyelőt használja. Nincs külön MCP-port.

| Végpont | Metódus  | Cél                                                       |
| ------- | -------- | --------------------------------------------------------- |
| `/mcp`  | `POST`   | Streamable HTTP átvitel — ezen beszél a kliens            |
| `/mcp`  | `DELETE` | Munkamenet befejezése                                     |
| `/sse`  | `GET`    | Szerver által küldött értesítési folyam                   |

Egy alapértelmezett helyi telepítés tehát a `http://127.0.0.1:9030/mcp` címen
érhető el.

1. Nyissa meg a **Beállítások → Szerver → MCP-szerverek** oldalt
2. Olvassa le az **MCP-szerver** kártyát — mutatja, hogy fut vagy leállt, és
   hogy melyik porton figyel

A felület friss telepítésen alapértelmezés szerint be van kapcsolva, így egy
loopback kliens a beállítások megérintése nélkül működik. Az **Indítás az
alkalmazás indításakor** szabályozza, hogy visszatér-e újraindítás után; az
**Indítás** / **Leállítás** munkamenet-vezérlők, amelyek nem változtatják meg
ezt a beállítást.

A szerver alapértelmezés szerint loopbackre köt, így a végpont csak arról a
gépről érhető el, amelyen a `cc_server` fut, kivéve, ha `--bind any`
kapcsolóval indította.

## Kliens csatlakoztatása

Irányítsa a klienst a Streamable HTTP végpontra. A konfiguráció pontos formája
a kliensének a dolga; az URL mindkét esetben ugyanaz.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp"
    }
  }
}
```

### Claude Code

A Claude Code ezt nem veszi át egy projekt `.mcp.json` fájljából — a
projekthatókörű MCP-szervereket egy jóváhagyási kérés mögé zárja, amelyet egy
nem interaktív `claude -p` soha nem válaszol meg. Adja át a konfigurációt
explicit módon:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

A `--strict-mcp-config` hatására a Claude csak azt a fájlt használja, így
ugyanaz a szerver nem kerül fel a projektből is, és nem regisztrálódik kétszer.

Ellenőrzőpont: kérje meg a klienst, hogy listázza az eszközeit. `mcp__*`
bejegyzéseket kell látnia, amelyek a jegyeket, a tereket, a memóriát, a
kódgráfot és az átnézést fedik le.

## MCP kiszolgálása a hoszton túl

1. A **Beállítások → Szerver → MCP-szerverek** oldalon a **Hitelesítési token**
   sorban nyomja meg a **Beállítás** gombot, és illesszen be egy tokent
2. Küldje el `Authorization: Bearer <token>` fejlécként minden `POST /mcp`
   kérésnél

A token nélküli felület minden nem loopback hívót 403-mal utasít el. Ez
szándékosan zárt hibamódú: épp a token teszi egyáltalán lehetővé a hoszton
kívüli kiszolgálást.

A token módosításai azonnal érvényesülnek az élő felületen — újraindítás nélkül.

:::note[`GET /sse` a tokent a lekérdezési sztringben fogadja]
Az értesítési folyamot a rendszer ugyanúgy token alapján ellenőrzi, mint minden
más útvonalat, de a böngésző `EventSource` nem tud `Authorization` fejlécet
küldeni — ezért a `/sse` a tokent `?token=<token>` formában is elfogadja.
Enélkül 401-gyel válaszol.
:::

## Minden hívás munkaterülethez kötése

Minden eszköz, amely munkaterület-hatókörű adatot érint, megköveteli a
`workspace_id` mezőt, és a nélküle érkező hívást elutasítja a rendszer, nem
pedig valamely „aktuális” munkaterületre oldja fel:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

Az azonosító az, amely a böngészője vagy az alkalmazás URL-jében szerepel:
`/workspaces/<workspace_id>/…`. Az egyetlen kivételt azok az eszközök
jelentik, amelyek valóban munkaterületeken átnyúlóak, például a
`list_workspaces` és a hírfolyam-eszközök — a hírfolyam felhasználónkénti, és
az ügynöknek nincs saját felhasználója, így ezek az eszközök a szerver
tulajdonosának hírfolyamain működnek.

A repóhoz kötött eszközök ezenfelül ellenőrzik, hogy a repó hozzá van-e
kapcsolva ehhez a munkaterülethez.

## Ismerje, mit fog elutasítani a felület

- **Módkapuzás.** A hívás feloldása kiszolgálóoldalon, a hívó ügynök terének
  módja szerint történik. Egy csak olvasható módban lévő ügynök nem érhet el egy
  íróeszközt a `space_id` elhagyásával — a módot a rendszer az aktív futásából
  keresi ki helyette.
- **Műveleti korlátok.** Az állapotmódosító eszközök deklarálják a
  hatásosztályaikat, és ugyanazon a szabályzaton mennek át, amelyet a termék
  többi része használ. Lásd:
  [Korlátok konfigurálása](/hu-HU/kezikonyv/gyakorlati-utmutatok/korlatok-konfiguralasa/).
- **Megerősítés.** Egyes destruktív eszközök megerősítési adatcsomagot állítanak
  össze, amelyet jóvá kell hagyni, mielőtt a hívás továbbhalad.

A teljes katalógust a `tools/list` hirdeti meg, felfedezési kapuzás nélkül — egy
külső MCP-kliens megtagadja egy olyan eszköz hívását, amely nem szerepel a
gyorsítótárazott listájában, így az eszközök elrejtése inkább elrontja őket,
mintsem rendbe tenné.

## Hibaelhárítás

### A kliens egyetlen eszközt sem lát

- Ellenőrizze, hogy az **MCP-szerver** kártya azt mutatja-e, hogy fut
- Ellenőrizze, hogy a port megegyezik-e a `cc_server` portjával
- A Claude Code esetében ellenőrizze, hogy átadta-e a `--mcp-config` és a
  `--strict-mcp-config` kapcsolót

### 403 egy olyan gépről, amely nem a szerver

Nincs beállítva bearer token. Állítson be egyet, és küldje el.

### Egy eszközhívás a következő hibával hiúsul meg: „Missing or invalid argument: workspace_id”

Adja hozzá a `workspace_id` mezőt. Nincs implicit munkaterület.

### Egy eszközhívást ismeretlenként utasít el a rendszer

katalógust. Pontosan úgy hívja meg a nevet, ahogy ott szerepel.
