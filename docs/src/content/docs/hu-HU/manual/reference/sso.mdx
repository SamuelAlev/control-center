Az egyszeri bejelentkezés minden beállítható eleme egy helyen. Az értékek a
`global.db` `sso_connections` soraiban élnek (tervezés szerint szerver
szintűek), és a **Beállítások → Szerver → Egyszeri bejelentkezés** felületen
vagy az `sso.*` RPC-műveletekkel szerkeszthetők. A mentett sor az egyetlen
igazságforrás — nincs `CC_SAML_*` / `CC_OIDC_*` környezeti útvonal (egy
kapcsolat, amely két helyről érkezhetne, olyan, amellyel a beállítások
képernyő ellentmondhat).

| Mező                   | Érvényes erre | Alapértelmezés  | Jelentés                                                                                                                                            |
| ---------------------- | ------------- | --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `enabled`              | mindkettő     | ki              | a bejelentkezések használhatják ezt a kapcsolatot                                                                                                   |
| `idpMetadataXml`       | SAML          | —               | az IdP `EntityDescriptor` XML-je (az engedélyezéshez kötelező)                                                                                       |
| `spEntityId`           | SAML          | `<origin>/saml` | a saját entitásazonosítónk, rögzítve, amikor az origin változik                                                                                      |
| `emailAttribute`       | SAML          | `email`         | az e-mail-címet hordozó attribútum; e-mail alakú NameID a tartalék                                                                                   |
| `displayNameAttribute` | SAML          | `displayName`   | a megjelenítendő nevet hordozó attribútum                                                                                                           |
| `groupsAttribute`      | SAML          | `groups`        | a csoportneveket hordozó attribútum                                                                                                                 |
| `clockSkewSeconds`     | SAML          | 90              | az élettartam-ellenőrzés megengedett óraeltérése                                                                                                    |
| `allowIdpInitiated`    | SAML          | ki              | érvényes kéretlen válaszok elfogadása (nincs `InResponseTo`); a böngészőnek rövid életű grantot kell igényelnie, mielőtt címzettnek lezárt hitelesítő adatot kap |
| `wantResponseSigned`   | SAML          | ki              | a válasz gyökérelemének aláírásának megkövetelése (az állítás aláírása mindig kötelező)                                                              |

| `clientSecret`         | OIDC          | —               | csak bizalmas kliensekhez; a 0600 jogosultságú titkosfájlban tárolva, soha nem az adatbázisban — RPC-n keresztül csak írható (`sso.getConfig` a `clientSecretPresent` értéket jelenti) |

| `autoMember`           | mindkettő     | be              | a felhasználók automatikus hozzáadása minden munkaterülethez az első bejelentkezéskor                                                              |
| `allowJit`             | mindkettő     | be              | ismeretlen felhasználók provisionálása bejelentkezéskor                                                                                             |

## Folyamatkonfiguráció

Az SSO-kapcsolatok nem a környezetből töltődnek fel. Egy megmaradt
folyamatkapcsoló azt választja meg, hol nyitja meg a böngésző a webes klienst egy
SSO-visszahívás után:

| Változó / kapcsoló                               | Jelentés                                                                                                                                    |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `--web-client-url` / `CC_SERVER_WEB_CLIENT_URL` | webeskliens-URL egy lezárt hitelesítőadat-átadáshoz; beállítatlanul az átadás azonos originen marad (csak akkor hasznos, ha a webes klienst ott szolgálják ki). Egy `web-popup` bejelentkezésnél az indító lap egy engedélyezett `client_origin` értéke élvez elsőbbséget. |

Magának a kibocsátó URL-jének `https`-nek kell lennie (`http` csak
visszacsatolási (loopback) kibocsátókhoz, a `localhost`, `127.0.0.1` és `::1`
esetében fogadható el). Használjon megbízható TLS-t az IdP-visszahíváshoz és a
webeskliens-hoszthoz: a címzettkulcsot előállító oldal és az általa kiszolgált
JavaScript a bizalmi határ része. A HTTPS ezt a bootstrapet védi; párosítás után
a közvetlen és a relén átvezetett `/rpc`-munkamenetek egyaránt Noise-titkosítást
és rögzített szerveridentitást igényelnek.

## HTTP-végpontok

| Végpont                                          | Hitelesítés         | Cél                                                                                                                                                                                                              |
| ------------------------------------------------ | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /saml/login?relay=…&handoff_key=…`         | nincs (átirányítás) | SP által indított bejelentkezés indítása egy kliens által birtokolt X25519 címzettkulccsal; a `relay=desktop` átadja az alkalmazásnak, a `relay=web-popup` postMessage-t küld a várakozó csatlakozási lapnak (a `client_origin` értékét csak akkor vesszük figyelembe, ha az origin-engedélylista megbízik benne) |
| `POST /saml/acs`                                 | nincs (IdP POST)    | az állítás ellenőrzése és a felhasználó provisionálása; az SP által indított bejelentkezés a kiállított eszközhitelesítő adatot az indító címzettkulcshoz zárja le; az engedélyezett kéretlen SAML helyette egy böngészőhöz kötött claimet ad |
| `POST /saml/claim`                               | azonos originen lévő böngészőgrant | egy egyszer használatos kéretlen SAML-grant beváltása a cookie-jával és egy friss `handoff_key`-jel; a címzettnek lezárt hitelesítő adatot adja vissza, soha nem nyílt szöveges párosítási kulcsot |
| `GET /saml/metadata`                             | nincs               | a saját SP `EntityDescriptor`-ünk                                                                                                                                                                                |
| `GET /oidc/login?relay=…&handoff_key=…` / `GET /oidc/callback` | nincs | az OIDC-körforduló; a bejelentkezéshez a kliens által birtokolt címzettkulcs kell; a `relay=desktop` átadja az alkalmazásnak, a `relay=web-popup` a várakozó csatlakozási lapnak (ugyanaz a `client_origin` konvenció) |
| `GET /auth/providers`                            | nincs, CORS `*`     | a csatlakozási képernyő próbája: a felkínált SSO-kapcsolatok (`id`/`kind`/`label`) + `pairingEnabled`                                                                                                             |
| `/scim/v2/Users…`                                | Bearer (SCIM-token) | Users létrehozás/lekérés/lista+szűrés/PUT/PATCH/DELETE                                                                                                                                                            |
| `/scim/v2/Groups`                                | Bearer              | csak olvasható; a csoportpush tervezés szerint 501-gyel válaszol                                                                                                                                                  |
| `/scim/v2/ServiceProviderConfig`                 | Bearer              | képességdokumentum                                                                                                                                                                                                |

Az SP által indított SAML és OIDC esetében a bejelentkezést indító URL-hez
érvényes `handoff_key` kell (az indító kliens X25519 nyilvános kulcsa). A szerver
a függőben lévő bejelentkezéssel együtt megőrzi ezt a kulcsot, és a
visszahívásnál efemer X25519, HKDF-SHA256 és AES-256-GCM segítségével a
szerver-originhez kötve lezárja a kiállított eszközhitelesítő adatot. Az asztali
átadás a `control-center://pair` hivatkozást használja, az ugyanabban a lapban
történő webes átadás egy URL-fragmentumot, a `web-popup` pedig postMessage-t küld
az engedélyezett `client_origin` címre, ha meg van adva (egyébként a beállított
webeskliens-URL-re vagy a visszahívási originre). A lezárt boríték, nem egy nyílt
szöveges párosítási kulcs utazik abban a fragmentumban vagy popup-üzenetben. Az
indító kliens megőrzi a hozzá tartozó privát kulcsot a megnyitásához. Ez a
boríték különbözik a párosítás után létrejövő kötelező Noise-munkamenettől.

Az IdP által indított SAML-válasznak (ha engedélyezett) nincs indító címzettje.
Helyette az ACS beállít egy öt percig érvényes, HttpOnly, SameSite=Strict
böngésző-cookie-t, és felkínálja a **Webes kliens megnyitása** / **Asztali
alkalmazás megnyitása** választást. Ez az oldal friss címzettkulcsot állít elő,
és ugyanarról az originről elküldi annak nyilvános felét és a grant-kezelőt a
`POST /saml/claim` végpontra. A beváltáshoz a hozzá tartozó cookie és origin kell
(egy CSRF-határ), a grantot egyszer használja fel, és csak egy címzettnek lezárt
borítékot ad vissza. A rákövetkező webes/asztali fragmentum azt a borítékot és a
címzett privátkulcs-anyagát szállítja, hogy a cél kliens meg tudja nyitni,
**nem** egy nyílt szöveges eszközhitelesítő adatot. Egy másik böngésző vagy egy
lejárt grant nem tudja beváltani. A cél webeskliens-origin hozzáfér a
fragmentumhoz, és vissza tudja fejteni; egy kompromittált visszahívási oldal
vagy webeskliens-origin el tudja lopni a hitelesítő adatokat. A titkosítás nem
teszi biztonságossá a nem megbízható, kiszolgált kódot.

## RPC-műveletek

Minden `sso.*` művelet szerverhatókörű, és a **szerver tulajdonosa** (a
telepítés operátora, `ServerAuthority.serverOwner`) számára engedélyezett. A
munkaterület tulajdonlása nem elég; a puszta párosítás soha nem adja meg
ezeket.

| Művelet                   | Cél                                                                                                                                                        |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sso.getConfig`           | egy adott fajtához mentett kapcsolat                                                                                                                        |
| `sso.saveConfig`          | érvényesítés, mentés és élő alkalmazás                                                                                                                      |
| `sso.status`              | engedélyezett/beállított jelzők, a SCIM-token megléte, a kanonikus origin                                                                                    |
| `sso.testConnection`      | kapcsolat tesztelése a böngészős körforduló nélkül (SAML: metaadat-feldolgozás + AuthnRequest felépítése; OIDC: kibocsátófelfedezés), opcionális, még nem mentett képernyőértékekkel |
| `sso.spMetadata`          | az SP `EntityDescriptor` kibocsátása egy originhez                                                                                                          |
| `sso.setPairingEnabled`   | a kézi párosítás engedélyezése/tiltása (meghívókódok, párosítási kulcsok); a letiltás megtagadása, amíg nem létezik működő SSO-kapcsolat, a kizárás ellen véd |
| `sso.sessionPolicy`       | a telepítés eszközhitelesítő adatának maximális élettartamának és tétlenségi időtúllépésének beolvasása (percben; `0` = nincs beállítva)                     |
| `sso.setSessionPolicy`    | e korlátok beállítása; az eszközellenőrzésnél érvényesülnek, a klienseknek nem hirdetjük őket                                                               |
| `sso.scimRegenerateToken` | a SCIM bearer token előállítása + visszaadása (egyszer)                                                                                                     |

## Érvényesítési hibakódok

A `cc_saml_verify_response` hibái stabil kódot hordoznak:

| Kód                    | Jelentés                                                                         |
| ---------------------- | -------------------------------------------------------------------------------- |
| `signature`            | hiányzó/nem megbízható/módosított aláírás, vagy nem engedélyezett algoritmus/transzformáció |
| `expired`              | a `NotBefore`/`NotOnOrAfter` tartományon kívül (az eltérésen túl)                |
| `audience`             | a célközönség-korlátozás nem minket nevez meg                                    |
| `destination`          | a válasz célállomása nem a mi ACS-ünk                                            |
| `request_match`        | az `InResponseTo` nem egyezik egy függőben lévő kéréssel, vagy kéretlen, miközben tilos |
| `issuer`               | a kibocsátó nem a beállított IdP                                                 |
| `recipient`            | az alany-megerősítés címzettje nem a mi ACS-ünk                                  |
| `malformed`            | XML-/sémaszintű hiba                                                             |
| `status`               | az IdP által jelentett állapot nem Success volt                                  |
| `invalid` / `internal` | minden más / illesztési hiba                                                     |

## Adatbázis-felületek

- `sso_connections` (global.db) — fajtánként egy sor, TERVEZÉS SZERINT
  MUNKATERÜLETEKEN ÁTNYÚLÓ.
- `users.sso_subject` + `users.sso_issuer` — a szolgáltatói alany rögzítése,
  `(issuer, subject)` szerint egyedi, részleges indexszel.
- `users.deactivated_at` — a SCIM-deaktiválás bélyegzője.
- A SCIM bearer token és az OIDC kliens titkos kulcsa a 0600 jogosultságú
  titkosfájlban él, soha nem az adatbázisban.
