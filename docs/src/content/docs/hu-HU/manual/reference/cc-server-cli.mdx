Minden folyamatszintű beállítás megadható parancssori kapcsolóként vagy környezeti
változóként; ilyenkor a kapcsoló nyer, aztán a környezet, végül az alapértelmezett érték. A
szolgáltatói hitelesítő adatok kivételt képeznek — lásd: [Szolgáltatói alkalmazások és Connect](#szolgáltatói-alkalmazások-és-connect).

:::caution[Az ismeretlen kapcsolókat csendben figyelmen kívül hagyja]
Az argumentumelemző kézzel írt, és mindent kihagy, amit nem ismer fel, ezért egy elírás (`--tls-key-file`, `--bindany`) nem ad hibát — a szerver egyszerűen az alapértelmezéssel indul el. Ha úgy tűnik, hogy egy kapcsolónak nincs hatása, ellenőrizze az indítási napló sorait. A [kódmód-kapcsoló](#kódmód) más: ha olyan értéket kap, amelyet nem fogad el, a szerver nem indul el.
:::

## Szolgáltatói alkalmazások és Connect

Egyetlen build sem tartalmaz szolgáltatói hitelesítő adatokat. Ha a Control Center Connect be van
kapcsolva, a Connect fut minden szolgáltatón, a saját alkalmazások pedig mentve maradnak, de nincsenek
használatban. A **Saját alkalmazások használata** alatt minden szolgáltató a szerver saját alkalmazásán
fut, ha az teljesen be van állítva, egyébként nem érhető el. A munkaterület saját alkalmazása mindkét
esetben érvényes. A saját
alkalmazásokat a **Beállítások → Szerver → Egyszeri bejelentkezés → Szolgáltatói
alkalmazások** helyen lehet beállítani, vagy egyszer, a szerver `.env` fájljából
feltölteni. Kapcsolók nincsenek hozzájuk: a parancssorban szereplő titok a `ps`
segítségével kiolvasható.

| Változó                        | Jelentés                                                                                      |
| ------------------------------ | --------------------------------------------------------------------------------------------- |
| `GITHUB_APP_ID`                | A szerver GitHub Appjának azonosítója                                                         |
| `GITHUB_APP_PRIVATE_KEY`       | A privát kulcsa, egy sorban, `\n` escape-ekkel. **Csak `.env`**                            |
| `GITHUB_CLIENT_ID`             | A kliens-ID-ja, az emberek bejelentkeztetéséhez                                               |
| `GITHUB_CLIENT_SECRET`         | A kliens titka. **Csak `.env`**                                                               |
| `GOOGLE_OAUTH_CLIENT_ID`       | A szerver Web application típusú Google-kliense                                               |
| `GOOGLE_OAUTH_CLIENT_SECRET`   | A titka. **Csak `.env`**                                                                      |
| `LINEAR_CLIENT_ID`             | A szerver Linear-alkalmazása (PKCE, titok nélkül)                                             |
| `LINEAR_API_KEY`               | Linear-szolgáltatáskulcs az automatizáláshoz. **Csak `.env`**                                 |
| `KLIPY_APP_KEY`                | A szerver saját Klipy-kulcsa a GIF-kereséshez. Csak a **Saját alkalmazások használata** alatt használatos |
| `CC_CONNECT_URL`               | `hosted`, `off` vagy egy Connect-URL. Rögzíti a Connect-választást; a Beállítások ezután nem módosíthatják |
| `CC_SERVER_CONNECT_HOST`       | Az `on` a `<server>/connect` alá csatolja a Control Center Connectet, amelyet a `CONNECT_*` változók konfigurálnak. Lásd: [Connect-szerver futtatása](/hu-HU/kezikonyv/gyakorlati-utmutatok/connect-szerver-futtatasa/#connect-csatolása-a-cc_server-be) |

A `.env` fájlt a szerver a munkakönyvtárából, a végrehajtható fájl mellől vagy egy
fölötte lévő forráskód-checkoutból olvassa; Dockerben csatolja a `/app/bin/.env`
helyre. A szerver **nem indul el** (`78`-as kilépési kód), ha a
`GITHUB_APP_PRIVATE_KEY`, a `GITHUB_CLIENT_SECRET`, a `GOOGLE_OAUTH_CLIENT_SECRET`,
a `LINEAR_API_KEY` vagy bármely `SLACK_*SECRET*` a folyamata környezetébe van
exportálva, ahol minden gyermekfolyamat kiolvashatná. A `.env` fájlból való
feltöltés mezőnként egyszer történik, így egy későbbi szerkesztést a Beállításokban
nem vonja vissza egy újraindítás. Az üres érték beállítatlanként értelmeződik.

Egyik kódtárhely-hitelesítő adat sem a környezetből származik: a GitHub, a GitLab és a Bitbucket mind egy tag saját bejelentkezésével vagy tokenjével, illetve egyetlen tárolóra szóló, egy felelős taggal korlátozott GitHub-alkalmazás-tokenekkel működik.

### `--sandbox`

A szerver indításkor egyszer megvizsgálja a gazdagépet, és ha van elérhető
háttérrendszer, az ügynökparancsok végrehajtását az OS-natív homokozóba csomagolja:
macOS-en `sandbox-exec` (Seatbelt), Linuxon és WSL2-ben `bwrap` plusz `socat`. A
döntés egyszer születik meg, és a szerver újraindításáig érvényes. Három kimenetel
van, mindegyik megjelenik az indítási kitettségi sorban:

| `sandbox=`    | Mikor                                    | Kinek az ügynökfuttatásai indulnak el                                                                                                                                 |
| ------------- | ---------------------------------------- | -------------------------------------------------------------------------------- |
| `native`      | Van háttérrendszer, és a `--sandbox` értéke `on` | Mindenkiéi, becsomagolva                                                                                                                 |
| `off`         | `--sandbox off`                          | Mindenkiéi, homokozó nélkül ezen a gazdagépen                                                                                              |
| `unavailable` | `--sandbox on`, és nincs háttérrendszer (Windows, vagy Linux `bwrap` és `socat` nélkül) | Csak azoké, amelyekért a szerver tulajdonosa felel, homokozó nélkül. A többieket visszautasítjuk: „Ezen a szerveren nincs homokozó, ezért itt csak a tulajdonosa futtathat ügynököket.” |

Automatizálásnál a felelős személy az, akihez az automatizálás kötve van. Ha nincs
rögzített szerver-tulajdonos, `unavailable` gazdagépen egyetlen futtatás sem indul.
Linuxon és WSL2-n, ha a bubblewrap telepítve van, a natív indítás jelenleg minden
futtatásra hibával zár; lásd: [Homokozó-háttérrendszerek](/hu-HU/kezikonyv/referencia/homokozo-hatterrendszerek/#linux-bubblewrap).

A `--sandbox off` a szerver tulajdonosának döntése mindenki számára, aki a szervert
használja: ilyenkor minden tag ügynöke homokozó nélkül fut ezen a gépen. Akkor
használja, ha a homokozóprofil hibásan viselkedik egy gazdagépen, vagy ha a tagok
háttérrendszer nélküli gazdagépen szeretnének ügynököket futtatni. Nem igényel
újraépítést, és a szerver a folyamat teljes élettartama alatt figyelmeztetést naplóz,
így az állapot soha nem marad csendben.

### `--tool-deferral`

A beépített harnessfuttatások az eszközdefiníciók egy kis közvetlen készletét küldik el, a többihez pedig egy csak neveket tartalmazó indexet; ezek a sémáikat az első használatkor töltik be, vagy egy `repl` szkriptből hívják őket. Így az állandóan látható készlet abban a tartományban marad, ahol a modellek megbízhatóan választanak eszközt. A tesztek által épített regiszteren mérve a beépített ügynök szokásos csevegőeszközei 14 definíciót tesznek ki: nagyjából 16,5 KB `repl`-lel (ebből nagyjából 4 KB a `repl`-é, amelynek definíciója legfeljebb 4 096 bájt lehet), és nagyjából 13 KB olyan szerveren, amely nem tud szkripteket futtatni. A halasztott eszközök végig név szerint hívhatók maradnak, a `search_tools` pedig szándék alapján megtalálja őket. Lásd: [Eszközkontextus és promptgyorsítótár](/hu-HU/kezikonyv/fogalmak/eszkozkontextus/).

A `--tool-deferral off` minden beengedett eszköz definícióját előre elküldi, kivéve, hogy a `repl`-es futtatás továbbra is szkriptből hívja azokat az eszközöket, amelyeket a szkript hívhat. Ez a vészkapcsoló arra a modellre, amely rosszul kezeli a kétszintű felületet — egy kapcsoló, nem pedig újraépítés. Csak a beépített harnessre hat; az MCP `tools/list`, amelyet a külső kliensek látnak, a teljes katalógus, kivéve egy olyan ügynökfuttatásnál, amely olyan szerveren fut, ahol a [kódmód](/hu-HU/kezikonyv/fogalmak/kodmod/) szkriptek futtathatók.

### `--credential-gate`

Egy futás, amelynek szolgáltatói hitelesítő adata hiányzik vagy elfogyott, **parkol**,
nem pedig meghiúsul: az üzemeltető kap egy felszólítást a javítására, és a futás
folytatódik, ha megteszi. Az alapértelmezett határidő 900 másodperc (15 perc), 0–3600
közé szorítva.

A határidő szándékosan sokkal hosszabb, mint a jóváhagyási kérésé: egy jóváhagyás olyan
döntés, amelyet valaki másodpercek alatt meghoz, míg egy hitelesítő adat kijavítása
terminál megnyitását, bejelentkezést és visszatérést jelent. A felső korlát az, ami
megakadályozza, hogy egy felügyelet nélküli futás — egy pipeline-lépés, egy
cron-eseményindító, egy webhook — olyasvalakire várjon, aki alszik. Amikor lejár, a futás
ugyanazzal az üzenettel hiúsul meg, amellyel egyébként is meghiúsult volna.

A `--credential-gate=0` a vészkapcsoló: semmi sem parkol soha, és egy hibás hitelesítő
adat pontosan úgy zárja le a kört, ahogy a kapu létezése előtt tette.

### Kódmód

A [kódmód](/hu-HU/kezikonyv/fogalmak/kodmod/) lehetővé teszi, hogy egy ügynök JavaScript-szkriptet futtasson, amely az eszközeit hívja. Nincs kapcsoló, amellyel be- vagy kikapcsolható: minden futtatás megkapja a `repl` eszközt, ha a szerver tud szkripteket futtatni, a nyilvános demószerver pedig egyet sem futtat.

A szkriptek a `cc_codemode`-ban futnak, egy a szerverrel együtt szállított programban, a `bin/codemode/` mappában. Ez nélkül a szerver nem indul el: kiír egy sort, amely megnevezi, mi hiányzik, és `78` kilépési kóddal leáll. Induláskor lefuttatja a program zárolási önellenőrzését, és kiír egy sort (csak a `--log-level error` némítja el):

```text
cc_server: code_mode=available (cc_codemode 0.1.0 quickjs-ng 0.16.2 protocol 2; 16 scripts at once, at most 12 per workspace; up to 64 more runners kept for scripts waiting on a person; heap at most 1024 MiB per script)
cc_server: code_mode=unavailable (<reason>) — runs on this host get no repl tool; scripts never run without full lockdown
```

Az `unavailable` azt jelenti, hogy a program nem tudja lezárni magát ezen a gépen, például egy olyan konténerben, amelynek biztonsági profilja megtagadja valamelyik lépését, vagy ha a program nem kiadási build. A szerver normálisan fut, egyetlen futtatás sem kap `repl`-t, a munkaterület kódmód-beállítási oldala pedig megmutatja az okot.

A szerver futás közben is folyamatosan ellenőriz. Ha a program a szkripttől független okból nem tud elindulni, a szerver percenként legfeljebb egyszer újra lefuttatja az önellenőrzést. Ha az meghiúsul, a szerver kiírja az `unavailable` sort az okával, és nem futtat szkripteket: az addig induló futtatások nem kapnak `repl`-t, a már meglévő futtatás pedig közvetlenül hívja az eszközeit ([Amikor a szkriptek nem futtathatók](/hu-HU/kezikonyv/fogalmak/kodmod/#amikor-a-szkriptek-nem-futtathatók)). Percenként legfeljebb egyszer továbbra is ellenőriz, és amikor az önellenőrzés ismét sikeres, kiírja az `available` sort, és újra futtat szkripteket. Csak az indításkor meghiúsult önellenőrzés igényel újraindítást. A munkaterület beállításaiban megjelenő ok ki van szedve a gépen lévő útvonalakból; a naplósor teljes egészében tartalmazza.

A két kódmód-kapcsoló korlátozza, mit használhatnak a szkriptek. A `--code-mode-max-processes` az egyszerre futó szkriptek számát korlátozza az összes munkaterületen (alapértelmezés: a processzormagok számának kétszerese, legfeljebb 16; elfogadott értékek: 1–64). Ha a korlát 2 vagy annál nagyobb, egy munkaterület legfeljebb a korlát mínusz annak egynegyedét használhatja, így egyetlen munkaterület sem foglalhatja el az összes helyet, és a várakozó szkriptek munkaterületek között sorban kapnak helyet. Egy személy jóváhagyására vagy válaszára váró szkript átadja a helyét egy másik szkriptnek, és addig nem indít el eszközhívást, amíg választ nem kap; az ilyen várakozó szkriptekből legfeljebb a korlát négyszeresét tartják meg, ezek legfeljebb háromnegyede ugyanabból a munkaterületből származhat, és mindegyik a saját feldolgozási időkorlátján belül még számolhat. A `--code-mode-max-heap-mb` az egyes szkriptek által használható legnagyobb memória.

Ha ezek a kapcsolók nem fogadnak el egy értéket (tartományon kívüli szám vagy nem szám), a szerver indításkor leáll (kilépési kód: `78`), és egy üzenetet ír ki, amely megnevezi az elfogadott értékeket. Soha nem értelmezik alapértelmezettként.

## Alparancsok

| Parancs                                       | Mit tesz                                                                                            |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `cc_server`                                   | Addig futtatja a szervert, amíg `SIGINT`/`SIGTERM` nem érkezik                                       |
| `cc_server pair`                              | Provisionál egy eszközt, és kiírja annak azonosítóját és párosítási kulcsát. Biztonságos olyan adatkönyvtárral szemben, amelyet egy szerver már kiszolgál — a futó szerver újraindítás nélkül felveszi az eszközt |
| `cc_server connect <command>`                 | Megmutatja vagy módosítja, melyik Control Center Connectet használja ez a szerver, elindítása nélkül |
| `cc_server update`                            | Ellenőrzi, letölti és hitelesíti az újabb önálló kiadást                                            |
| `cc_server --version`                         | Kiírja a build verzióját és a git SHA-t — ugyanazt az azonosságot, amelyet a `/healthz` és az RPC-kézfogás hirdet |

| `--device`     | `web-client`                                              | Az eszköz azonosítója. A platform ebből következtethető, így a `--device desktop` egy asztali sort hoz létre, a `--device ios`/`android` pedig egy telefonosat; minden más webként kezelődik |
| `--label`      | a platform neve és e gép hosztneve                        | Az eszközlistában megjelenő név                                                                                                                                      |
| `--host`       | `localhost`, vagy `<this-host>` bármely interfészre kötve | A kiírt URL-be ágyazandó hoszt. Állítsa arra a LAN IP-re vagy alagúthosztra, amelyet egy kliens valóban hívni fog                                                       |
| `--client-url` | nincs beállítva                                           | A hosztolt **webes** kliens originje. Beolvasható deep linket és terminál-QR-kódot ad hozzá                                                                          |

A `pair` elfogadja az alapvető `--data-dir`, `--port` és `--bind` kapcsolókat is: ezek
választják ki az írandó adatkönyvtárat, és alakítják a kiírt szerver-URL-t (`ws`
loopbacken, `wss` `--bind any` esetén). Ha ugyanarra a `--device` értékre újra lefuttatja
a `pair` parancsot, az lecseréli annak kulcsát, és eldobja az eszköz élő munkameneteit. Az
itt kiállított hitelesítő adatnak **nincs lejárata**, ellentétben az alkalmazáson belüli
párosítás által beállított 30 nappal.

:::caution[A `--client-url` QR-kód nem a telefon QR-kódja]
A `pair --client-url` a **webes** kliens csatlakozási űrlapját tölti ki (szerver-URL,
eszközazonosító és kulcs az URL-töredékben). A telefon egy másik hasznos teherrel
párosul, amelyet az alkalmazáson belüli párosítási panel állít ki — a szerver teljes
kapcsolatleírójával és egy lejárattal. A kettő nem felcserélhető — lásd: [Eszköz párosítása](/hu-HU/kezikonyv/gyakorlati-utmutatok/eszkoz-parositasa/).
:::

### `connect`

Ugyanazokat a beállításokat olvassa és írja az adatkönyvtárból, mint a **Control
Center Connect** kártya a **Beállítások → Szerver → Egyszeri bejelentkezés**
helyen. Egy futó szerver 10 percen belül vagy újraindításkor veszi fel a
változást.

| Parancs                         | Mit tesz                                                                                                         |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `cc_server connect status`      | Kiírja a módot, az URL-t, azt, hogy a `CC_CONNECT_URL` rögzíti-e, a telepítési azonosítót, az állapotot és az egyes sávok forrását (`own`, `connect` vagy `off`) |
| `cc_server connect enable`      | A Control Center által üzemeltetett Connectet használja                                                          |
| `cc_server connect enable --url <url>` | Egyéni Connectet használ az adott URL-en (HTTPS, vagy `http` loopbacken)                               |
| `cc_server connect disable`     | Abbahagyja a Connect használatát. Csak a szerver saját alkalmazásai jelentkeztetik be az embereket              |

Parancs nélkül a `status` az alapértelmezett. Minden parancs elfogadja a
`--data-dir` kapcsolót. A `CC_CONNECT_URL` felülírja azt, amit ezek tárolnak. Egy
ismeretlen parancs `64`-es kóddal lép ki. A módokat, a telepítési identitást és
az állapotkódokat lásd: [Control Center Connect](/hu-HU/kezikonyv/referencia/connect/).

### `update`

A `--apply` lecseréli a telepítést; a rendszer megtagadja, amíg egy szerver még válaszol a
beállított porton, hacsak nem adja meg a `--force` kapcsolót. Az `--allow-downgrade` egy
régebbi kiadást tesz lehetővé.

A parancs azonnal megtagadja — hibaszöveg helyett magyarázattal — azokat a
telepítéseket, amelyek nem a sajátjai:

| Környezet                          | Felismerés módja                            | Mit mond                                                     |
| ---------------------------------- | ------------------------------------------- | ----------------------------------------------------------- |
| Az asztali alkalmazás beágyazott szervere | `CC_EMBEDDED=1` vagy `CC_BOOTSTRAP_DEVICE_ID` | Inkább az alkalmazást frissítse — a telepítő a teljes fát lecseréli |
| Egy `dart run` forrás-munkapéldány | a szkript útvonala `.dart`-ra végződik      | Frissítse gittel                                            |
| Docker                             | konténerjelzők                              | Húzzon le egy újabb image-et                                |

## Folyamat életciklusa

A `cc_server` addig fut, amíg `SIGINT` / `SIGTERM` nem érkezik. Ezt egyetlen extra
környezeti változó szabályozza, amelyet nem Ön, hanem az asztali alkalmazás állít be:

| Változó                 | Hatás                                                                                                                                      |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `CC_EXIT_WITH_PARENT=1` | A szerver akkor lép ki, amikor a szülőfolyamata is kilép; ezt a szülő azt jelezve érzékeli, hogy lezárja a stdin-cső írási végét. Az asztali alkalmazás azért állítja be, hogy egy összeomlott app soha ne hagyjon maga után árva szervert, amely fogva tartja az adatkönyvtárat |

Csak akkor állítsa be saját maga, ha gyermekfolyamatként felügyeli a `cc_server`-t, és
ugyanezt a garanciát szeretné.

A `DO_NOT_TRACK=1` (bármely érték, ami nem üres, `0` vagy `false`) leállítja a szerver saját
[használati statisztikáit](/hu-HU/kezikonyv/referencia/hasznalati-statisztikak/) akkor is, ha a szerverszintű kapcsoló
be van kapcsolva. A kliensek továbbra is a kapcsolót követik.

## Az adatkönyvtár felépítése

Az alapértelmezett adatkönyvtár macOS-en `~/Library/Application Support/control-center`,
Windowson `%APPDATA%\control-center`, másutt pedig `$XDG_DATA_HOME/control-center` (ha ez
nincs, `~/.local/share/control-center`). A munkakönyvtárhoz viszonyított `.cc_server`
csak akkor használatos, ha sem otthoni, sem alkalmazásadat-könyvtár nem oldható fel.

A szerver az adatkönyvtárat csak a saját fiókja számára tartja hozzáférhetővé (`0700`). Ha ezt nem tudja biztosítani, vagy ha a `global.db` sérült vagy újabb verzió írta, vagy ha az azonosítófájlját nem lehet beolvasni, a szerver nem indul el (kilépési kód: `78`).

| Útvonal                           | Tartalom                                                                        |
| --------------------------------- | ------------------------------------------------------------------------------- |
| `global.db`                       | A munkaterület-nyilvántartás, a felhasználók, a párosított eszközök, a hírfolyam és a flottasor |
| `<workspaceId>/workspace.db`      | Munkaterületenként egy adatbázis — ügynökök, terek, jegyek, memória   |
| `<workspaceId>/code_index.db` | Az adott munkaterület kódgráfja. Hiány esetén újraépül, soha nem mentik |
| `pre_upgrade/`, `<workspaceId>/pre_upgrade/` | Egy adatbázis két legfrissebb másolata abból az időből, mielőtt egy frissítés megváltoztatta a formátumát |
| `<workspaceId>/chat_credentials/` | Csevegőbot-tokenek egyszerű JSON-ként, hogy a munkaterülettel együtt mozogjanak  |
| `secrets.json`                    | Párosítási kulcsok, a Connect telepítési kulcsa, szolgáltatói alkalmazások, az emberek bejelentkezései (lepecsételve, ha a Connecten keresztül jöttek létre), webhook-titkok, SSO (`0600`) |
| `backups/<timestamp>/`            | Egy telepítési pillanatkép — `manifest.json`, `global.db` és minden munkaterület egy másolata |
| `backups/exports/`                | Egyetlen munkaterület exportjai, `<workspaceId>-<timestamp>.db`                  |
| `backups/transfer/`               | Átmeneti terület a mentések letöltéséhez és feltöltéséhez; az azt író útvonal takarítja |
| `models/`                         | Eszközön futó beágyazási, diarizációs és beszédmodellek                          |
| `codemode/` | A kódmód-futtató fejlesztői példánya, amelyet a `scripts/natives/build_codemode.sh` telepít; a kiadási csomagok a `bin/codemode/` mappában tartalmazzák |
| `meetings/<meetingId>/`           | Megőrzött megbeszélés-hanganyag                                                  |
| `rigs/images/`                    | Importált állomáslemezképek (a QEMU asztali felülete)                            |
| `rigs/smolvm/<rigId>/`            | Állomásonkénti microVM futásidejű állapot (a bróker titka, `0600`)               |
| `rigs/smolvm-packs/`              | Előre kicsomagolt gépcsomagok — az a gyorsítótár, amely gyorssá teszi az ismételt állomásindításokat |
| `rigs/tls/`                       | Az állomás HTTPS-hez használt fejlesztői domain tanúsítványhatósága (kulcsok `0600`) |
| `rigs/run/<rigId>/`               | QEMU-overlay-ek, seed-lemezképek és VM-enkénti kulcsok (`0600`)                  |
