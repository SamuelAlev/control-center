These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/hu-HU/kezikonyv/gyakorlati-utmutatok/); when you want to look
something up, go to the [reference](/hu-HU/kezikonyv/referencia/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/hu-HU/kezikonyv/fogalmak/munkateruletek/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/hu-HU/kezikonyv/fogalmak/ugynokmodell/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/hu-HU/kezikonyv/fogalmak/ugynokinditas-eletciklusa/) — what happens between your message and the agent's first token
- [Modes](/hu-HU/kezikonyv/fogalmak/modok/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/hu-HU/kezikonyv/fogalmak/eszkozkontextus/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/hu-HU/kezikonyv/fogalmak/kodintelligencia/) — the code graph, language server, structural search and debugger
- [Conversation history](/hu-HU/kezikonyv/fogalmak/beszelgetesi-elozmenyek/) — persistence, compaction and forking a transcript
