یہ کچھ نہ ہونے سے لے کر آپ کے اپنے کوڈ پر چلتے ایجنٹ تک کا مختصر ترین مکمل راستہ ہے۔ اسے ترتیب سے پورا کریں؛ ہر قدم اپنے سے پہلے والے قدم پر منحصر ہے۔

آپ کے پاس Git، ایک GitHub اکاؤنٹ، اور ساتھ ہی یا تو ماڈل فراہم کنندہ کا اکاؤنٹ (Anthropic، OpenAI، Codex، Cursor، Kimi Code، یا API کلید والا کوئی بھی فراہم کنندہ) یا پہلے سے انسٹال شدہ Claude Code CLI ہونا چاہیے۔ باقی سب کچھ راستے میں ہی ترتیب پا جاتا ہے۔

## مرحلہ 1: انسٹال کریں اور لانچ کریں

[انسٹال](/ur-PK/ہدایت-نامہ/انسٹال/) میں بتائے گئے طریقے سے Control Center انسٹال کریں، پھر اسے کھولیں۔

پہلی بار لانچ کرنے پر ڈیسک ٹاپ پوچھتا ہے **"Control Center کیسے چلے؟"**۔ **اس ایپ میں چلائیں** چنیں۔ Control Center اِس مشین پر ایک ہیڈلیس `cc_server` لانچ کر دیتا ہے، جو آپ کا ڈیٹا رکھتا ہے اور سارا کام کرتا ہے۔ آپ اسے کبھی نہیں دیکھتے؛ اس کے بجائے آن بورڈنگ اسکرین کھل جاتی ہے۔

:::note[کیا کچھ انسٹال کرنا نہیں چاہتے؟]
وہی ایپ براؤزر میں [app.usectrl.dev](https://app.usectrl.dev) پر بھی اِنہی
خصوصیات کے ساتھ چلتی ہے۔ مگر ایک براؤزر ٹیب سرور کی میزبانی نہیں کر سکتا، اس لیے
سرور آپ کو مہیا کرنا ہوگا — `cc_server` مقامی طور پر چلائیں اور `ws://localhost:9030`
سے جڑیں، یا اسے کسی دوسری مشین کے سرور کی طرف اشارہ کریں۔ یہ فوری آغاز ڈیسک ٹاپ
راستہ لیتا ہے کیونکہ اسے سرور کی کسی ترتیب کی ضرورت نہیں؛ براؤزر راستے کے لیے
[انسٹال](/ur-PK/ہدایت-نامہ/انسٹال/#use-it-in-your-browser) دیکھیں۔
:::

## مرحلہ 2: آن بورڈنگ سے گزریں

آن بورڈنگ کے پانچ مراحل ہیں اور وہ ترتیب سے چلتے ہیں — آگے چھوڑ کر جانے کا کوئی راستہ نہیں۔

1. **منسلک کریں**: GitHub سے سائن اِن کریں یا `repo` اور `read:org` والا پرسنل ایکسیس ٹوکن پیسٹ کریں۔ یہ کریڈنشل سرور پر محفوظ ہوتا ہے اور آپ کے اکاؤنٹ سے منسلک ہوتا ہے۔
2. **ورک اسپیس**: اپنے پہلے ورک اسپیس کا نام رکھیں اور اختیاری طور پر کوئی لوگو چنیں۔ اسے بنانے پر پانچ ایجنٹ — ایک CEO کے علاوہ `qa`، `architect`، `engineer` اور `librarian` — اور بلٹ اِن پائپ لائن ٹیمپلیٹس شامل ہو جاتے ہیں۔
3. **سینڈ باکس**: سینڈ باکسنگ کی ترجیح ریکارڈ کرتا ہے۔ کوئی بھی انتخاب آپ کو آگے بڑھنے دیتا ہے۔
4. **اڈاپٹر**: وہ اڈاپٹر اور ماڈل چنیں جو ایجنٹس کے لیے ڈیفالٹ ہونے چاہئیں۔ **Control Center (built-in)** چنیں، پھر جو فراہم کنندہ پکر ظاہر ہو اُس سے کسی ماڈل فراہم کنندہ میں سائن اِن کریں — جب تک کوئی منسلک نہ ہو، ماڈل کی فہرست خالی رہتی ہے۔ یہ مرحلہ مکمل کرنے پر اڈاپٹر اور ماڈل ورک اسپیس کے CEO ایجنٹ پر بھی لگ جاتے ہیں۔
5. **آواز (اختیاری)**: ڈکٹیشن کے لیے آن ڈیوائس اسپیچ ماڈل انسٹال کریں، یا اسے چھوڑ دیں۔

اس کے بعد Control Center آپ کے ورک اسپیس کا ان باکس کھولتا ہے۔

:::note[ایجنٹ کے رن کی حدیں کیا طے کرتی ہیں]
دستیاب ہونے پر ایجنٹ کی کمانڈز کو ہوسٹ کے OS-نیٹو سینڈ باکس میں لپیٹ دیا جاتا ہے — macOS پر Seatbelt، Linux پر bubblewrap۔ Windows کا کوئی بیک اینڈ نہیں، چنانچہ وہاں رنز صرف باقی پرتوں سے محدود رہتے ہیں: خود گفتگو کا ورک ٹری (Windows پر `git worktree`؛ جہاں `rift` موجود ہو وہاں copy-on-write)، ہر لانچ پر بروکر کیے جانے والے اور ٹیئر ڈاؤن پر منسوخ ہو جانے والے کریڈنشلز، اور ایکشن گارڈریلز۔ دیکھیں [سینڈ باکس اور سیکیورٹی](/ur-PK/ہدایت-نامہ/تصورات/سینڈ-باکس-سیکیورٹی/)۔
:::

## مرحلہ 3: ایک ریپوزٹری شامل کریں

**ترتیبات → ورک اسپیس → ریپوزٹریز** پر جائیں اور **ریپوزٹری شامل کریں** پر کلک کریں۔

یہ ڈائیلاگ اُن فولڈرز کو براؤز کرتا ہے جو سرور چلا رہی مشین پر ہیں، آپ کے کلائنٹ پر نہیں، اور وہ اُنہی روٹس کے اندر رہتا ہے جنہیں ظاہر کرنے کے لیے سرور کنفیگر کیا گیا ہو (ڈیفالٹ میں اس کے صارف کی ہوم ڈائریکٹری)۔ چیک باکس صرف git چیک آؤٹس کو ملتا ہے۔ اپنے چیک آؤٹ پر نشان لگائیں اور اسے رجسٹر کریں۔

کوئی چیک آؤٹ صرف اُس صورت قبول کیا جاتا ہے جب وہ کسی git ورک ٹری کے اندر ہو، اس کا `origin` ریموٹ موجود ہو اور وہ ریموٹ کسی معاون forge کی طرف اشارہ کرے — github.com، gitlab.com یا bitbucket.org۔ باقی سب کچھ وجہ کے ساتھ مسترد کر دیا جاتا ہے۔

ریپوز ورک اسپیس کے دائرے میں ہوتے ہیں: یہاں کوئی چیک آؤٹ رجسٹر کرنے سے وہ _اِسی_ ورک اسپیس میں آ جاتا ہے۔ لنک کرنے کا کوئی الگ مرحلہ نہیں۔

## مرحلہ 4: ایجنٹ کو اڈاپٹر اور ماڈل دیں

**ترتیبات → ورک اسپیس → ایجنٹس** پر جائیں۔ روسٹر میں `engineer` ایجنٹ منتخب کریں۔

**ترتیبات** ٹیب پر، یہ مقرر کریں:

- **اڈاپٹر**: `Control Center (built-in)`
- **ماڈل**: آن بورڈنگ میں جو فراہم کنندہ آپ نے منسلک کیا، اُس سے کوئی ایک چنیں

**تبدیلیاں محفوظ کریں** دبائیں۔

عملی طور پر یہ مرحلہ اختیاری نہیں۔ آن بورڈنگ کے دوران چنا گیا اڈاپٹر صرف CEO ایجنٹ کو وراثت میں ملتا ہے؛ باقی چار ماہرین اڈاپٹر کے بغیر بنائے جاتے ہیں۔ وہ Anthropic کے ڈیفالٹ ماڈل کے ساتھ **Control Center (built-in)** پر واپس چلے جاتے ہیں، اس لیے وہ صرف اُس وقت چلتے ہیں جب آپ نے Anthropic اکاؤنٹ منسلک کیا ہو — اور اگر کیا ہو تو اُس ماڈل پر چلتے ہیں جو آپ نے نہیں چنا۔

## مرحلہ 5: ایجنٹ کو کام بھیجیں

1. سائیڈبار میں **اسپیسز** سیکشن تلاش کریں اور **+** بٹن پر کلک کریں۔
2. اسپیس کا نام رکھیں، **ایجنٹس شامل کریں** کے تحت `engineer` ایجنٹ شامل کریں اور اسے بنا دیں۔
3. آپ نے جو ریپو رجسٹر کیا، اُس کے حوالے سے کوئی ٹھوس، چھوٹا کام ٹائپ کریں اور Enter دبائیں۔

Control Center اِس گفتگو کے لیے ورک اسپیس کے ریپوز کا copy-on-write ورک ٹری تیار کرتا ہے، ایجنٹ کے رول، شخصیت، مہارتوں اور اسپیس کے کانٹیکسٹ سے ایک پرامپٹ جوڑتا ہے اور رن ڈسپیچ کر دیتا ہے۔ آپ کے سورس چیک آؤٹ کو کبھی ہاتھ نہیں لگایا جاتا۔

## مرحلہ 6: اسے کام کرتے دیکھیں

آپ کو ترتیب سے یہ نظر آنا چاہیے:

- کمپوزر کا بھیجنے والا بٹن ایک روکیں بٹن میں بدل جاتا ہے، کیونکہ اِس گفتگو میں ایک ایجنٹ کام کر رہا ہے
- ایجنٹ کا استدلال، ٹول کالز اور متن ٹرانسکرپٹ میں اسٹریم ہوتے ہوئے
- رن ختم ہونے پر بھیجنے والا بٹن واپس آ جاتا ہے

پھر **ترتیبات → ورک اسپیس → ایجنٹس** کھولیں، ایجنٹ منتخب کریں اور **لاگز** ٹیب دیکھیں: ایک رن کی قطار، جس میں اس کی اسٹیٹس، مدت، شروع اور اختتام کے اوقات اور وہ اڈاپٹر شامل ہو جس پر وہ چلا۔

یہی وہ چکر ہے۔ Control Center میں باقی سب کچھ — pull-request ریویو، پائپ لائنز، ٹکٹس، میٹنگز، Slack — اسی سے وابستہ ہے۔
