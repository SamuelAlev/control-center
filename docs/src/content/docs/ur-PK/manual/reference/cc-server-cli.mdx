پروسیس کا ہر فلیگ یا تو CLI فلیگ سے آتا ہے یا ماحول کے ویری ایبل سے؛ پہلے فلیگ کا
اختیار چلتا ہے، پھر ماحول کا، پھر ڈیفالٹ کا۔ فریقِ ثالث کی اسناد اس کا استثنا ہیں — [فراہم کنندہ ایپس اور Connect](#ارائه-دہندگان-ایپ-اور-connect) دیکھیں۔

:::caution[نامعلوم فلیگز خاموشی سے نظر انداز ہو جاتے ہیں]
آرگیومنٹ پارسر ہاتھ سے بنا ہے اور جو چیز وہ نہ پہچانے اُسے چھوڑ دیتا ہے، چنانچہ کوئی ٹائپو (`--tls-key-file`، `--bindany`) کوئی خرابی پیدا نہیں کرتا — سرور محض ڈیفالٹ کے ساتھ شروع ہو جاتا ہے۔ جب کوئی فلیگ بے اثر لگے تو اسٹارٹ اپ لاگ کی لائنیں دیکھیں۔ ایک [کوڈ موڈ فلیگ](#کوڈ-موڈ) جس کی ایسی قدر ہو جو وہ قبول نہ کرے مختلف ہے: سرور شروع ہونے سے انکار کرتا ہے۔
:::

| `--server-name` | `CC_SERVER_NAME`       | مشین کا ہوسٹ نیم                                  | وہ نام جو پکرز، دریافت اور پیئرنگ کی سطحوں میں دکھایا جاتا ہے                                                  |

| `--web-client-url`  | `CC_SERVER_WEB_CLIENT_URL`  | غیر سیٹ                       | میزبان ویب کلائنٹ کا اوریجن جہاں سنگل سائن اَن کے کال بیک واپس آتے ہیں                                                                                         |

| ------------------------ | ------------------------------- | ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `--sandbox`              | `CC_SERVER_SANDBOX`             | `on`                                  | `on` ایجنٹ رنز کو میزبان کے OS نیٹو سینڈ باکس میں لپیٹتا ہے، اور بغیر سینڈ باکس والے میزبان پر صرف سرور کے مالک کے رن شروع کرتا ہے۔ `off` اس میزبان پر ہر رکن کے ایجنٹس کو غیر محدود چلاتا ہے۔ نیچے دیکھیں |
| `--code-index`           | `CC_SERVER_CODE_INDEX`          | `on`                                  | بیک گراؤنڈ کوڈ گراف انڈیکسنگ کے لیے فیلڈ بندش سوئچ۔ `off` بغیر دوبارہ بلڈ صاف بوٹ ہوتا ہے                                      |
| `--code-index-defer`     | `CC_SERVER_CODE_INDEX_DEFER`    | `15`                                  | تیار بینر کے بعد پہلی انڈیکس جھاڑو روکنے کے سیکنڈ (0–300 تک محدود)                                                             |
| `--tool-deferral`        | `CC_SERVER_TOOL_DEFERRAL`       | `on`                                  | کہ ہارنس رنز ایک چھوٹا براہِ راست ٹول سیٹ کے ساتھ نام کا انڈیکس بھیجیں، اور باقی پہلی استعمال پر لوڈ ہوں۔ نیچے دیکھیں           |
| `--credential-gate`      | `CC_SERVER_CREDENTIAL_GATE`     | `900`                                 | وہ سیکنڈ جن تک کوئی رن ایسے کریڈنشل کے درست ہونے کے انتظار میں پارک رہتا ہے جو اُس کی خدمت نہیں کر سکتا (0–3600 تک محدود)۔ نیچے دیکھیں |
| `--code-mode-max-processes` | `CC_SERVER_CODE_MODE_MAX_PROCESSES` | `min(16, 2 × cores)` | اس سرور پر ایک ساتھ چلنے والے کوڈ موڈ اسکرپٹس، کسی شخص کے انتظار میں موجود اسکرپٹس کو چھوڑ کر، 1–64۔ نیچے دیکھیں |
| `--code-mode-max-heap-mb` | `CC_SERVER_CODE_MODE_MAX_HEAP_MB` | `1024` | کسی ایک اسکرپٹ کی زیادہ سے زیادہ میموری، 16–1024 MiB۔ ورک اسپیس کی زیادہ حد اسی تک کم کر دی جاتی ہے |

## ارائه دہندگان ایپ اور Connect

کوئی build provider کریڈینشلز ساتھ نہیں رکھتا۔ Control Center Connect آن ہو تو Connect ہر provider چلاتا ہے، اور سرور کی اپنی ایپس محفوظ رہتی ہیں مگر استعمال نہیں ہوتیں۔ **اپنی ایپس استعمال کریں** کے تحت ہر provider سرور کی اپنی ایپ پر چلتا ہے جب وہ مکمل طور پر کنفیگر ہو، ورنہ دستیاب نہیں۔ workspace کی اپنی ایپ دونوں صورتوں میں فوقیت رکھتی ہے۔ اپنی ایپس **ترتیبات ← سرور ← سنگل سائن آن ← فراہم کنندہ ایپس** میں سیٹ ہوتی ہیں، یا سرور کی `.env` فائل سے ایک بار بیج (seed) ہوتی ہیں۔ ان کے لیے کوئی فلیگ نہیں: کمانڈ لائن پر راز `ps` کے ذریعے پڑھا جا سکتا ہے۔

| متغیر                          | مطلب                                                                                                                      |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `GITHUB_APP_ID`                | سرور کی GitHub App کا id                                                                                                  |
| `GITHUB_APP_PRIVATE_KEY`       | اس کی private key، `\n` escapes کے ساتھ ایک لائن میں۔ **صرف `.env`**                                                    |
| `GITHUB_CLIENT_ID`             | اس کا client id، لوگوں کو sign in کرانے کے لیے                                                                           |
| `GITHUB_CLIENT_SECRET`         | اس کا client secret۔ **صرف `.env`**                                                                                       |
| `GOOGLE_OAUTH_CLIENT_ID`       | سرور کا Google Web application client                                                                                     |
| `GOOGLE_OAUTH_CLIENT_SECRET`   | اس کا secret۔ **صرف `.env`**                                                                                              |
| `LINEAR_CLIENT_ID`             | سرور کی Linear application (PKCE، کوئی secret نہیں)                                                                       |
| `LINEAR_API_KEY`               | automation کے لیے Linear service key۔ **صرف `.env`**                                                                     |
| `KLIPY_APP_KEY`                | GIF search کے لیے سرور کی اپنی Klipy key۔ صرف **اپنی ایپس استعمال کریں** کے تحت استعمال ہوتی ہے                              |
| `CC_CONNECT_URL`               | `hosted`، `off`، یا Connect URL۔ Connect کا انتخاب lock کرتا ہے؛ Settings اسے نہیں بدل سکتیں                                |
| `CC_SERVER_CONNECT_HOST`       | `on` تو Control Center Connect `<server>/connect` پر mount ہوتا ہے، جو `CONNECT_*` متغیرات سے کنفیگر ہوتا ہے۔ دیکھیں [Connect سرور چلائیں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/connect-سرور-چلائیں/#cc_server-کے-اندر-connect-mount-کریں) |

`.env` فائل سرور کی ورکنگ ڈائریکٹری سے، ایگزیکیوٹیبل کے ساتھ، یا اوپر کسی source checkout سے پڑھی جاتی ہے؛ Docker میں اسے `/app/bin/.env` پر mount کریں۔ سرور **شروع ہونے سے انکار کرتا ہے** (exit code `78`) جب `GITHUB_APP_PRIVATE_KEY`، `GITHUB_CLIENT_SECRET`، `GOOGLE_OAUTH_CLIENT_SECRET`، `LINEAR_API_KEY` یا کوئی `SLACK_*SECRET*` اس کے پروسیس ماحول میں ایکسپورٹ ہو، جہاں ہر child process انہیں پڑھ سکتا ہے۔ `.env` سے بیج کرنا ہر فیلڈ کے لیے ایک بار ہوتا ہے، اس لیے Settings میں بعد کی ترمیم restart سے ختم نہیں ہوتی۔ خالی قدر کو غیر سیٹ سمجھا جاتا ہے۔

کوئی forge credential ماحول سے نہیں آتا: GitHub، GitLab اور Bitbucket سب کسی رکن کے اپنے sign-in یا ٹوکن پر، یا اس سے محدود ایک ریپو والے GitHub App ٹوکنز پر عمل کرتے ہیں۔


### `--sandbox`

سرور بوٹ کے وقت ایک بار میزبان کا جائزہ لیتا ہے اور جب کوئی بیک اینڈ دستیاب ہو تو ایجنٹ
کی کمانڈ ایگزیکیوشن کو OS نیٹو سینڈ باکس میں لپیٹ دیتا ہے: macOS پر `sandbox-exec`
(Seatbelt)، اور Linux و WSL2 پر `bwrap` کے ساتھ `socat`۔ یہ فیصلہ بوٹ پر ایک بار ہوتا ہے اور سرور کے دوبارہ شروع ہونے تک قائم رہتا ہے۔ تین نتائج ہیں، ہر ایک اسٹارٹ اپ exposure لائن پر دکھایا جاتا ہے:

| `sandbox=`    | کب                                      | کس کے ایجنٹ رنز شروع ہوتے ہیں                                                    |
| ------------- | --------------------------------------- | -------------------------------------------------------------------------------- |
| `native`      | بیک اینڈ دستیاب ہو اور `--sandbox` `on` ہو | سب کے، لپیٹے ہوئے                                                        |
| `off`         | `--sandbox off`                         | سب کے، اس میزبان پر غیر محدود                                              |
| `unavailable` | `--sandbox on` اور کوئی بیک اینڈ نہ ہو (Windows، یا `bwrap` اور `socat` کے بغیر Linux) | صرف وہ رنز جن کا ذمہ دار سرور کا مالک ہو، غیر محدود۔ باقی مسترد ہوتے ہیں، "اس سرور پر سینڈ باکس نہیں ہے، اس لیے یہاں صرف اس کا مالک ایجنٹس چلا سکتا ہے۔" کے ساتھ |

خودکار عمل کے لیے ذمہ دار شخص وہ ہے جس سے خودکار عمل بندھا ہو۔ جب سرور کا کوئی مالک ریکارڈ شدہ نہ ہو تو `unavailable` میزبان پر کوئی رن شروع نہیں ہوتا۔ Linux اور WSL2 پر جہاں bubblewrap انسٹال ہو، نیٹو ڈسپیچ فی الحال ہر رن کے لیے بند ہو کر ناکام ہوتا ہے؛ دیکھیں [سینڈ باکس بیک اینڈز](/ur-PK/ہدایت-نامہ/حوالہ/سینڈ-باکس-بیک-اینڈز/#linux-bubblewrap)۔

`--sandbox off` سرور کے مالک کا سب کے لیے فیصلہ ہے جو سرور استعمال کرتے ہیں: اس مشین پر ہر رکن کے ایجنٹس غیر محدود چلتے ہیں۔ اسے اُس جگہ استعمال کریں جہاں خود سینڈ باکس پروفائل غلط برتاؤ کرتا ہو، یا جہاں ارکان بغیر بیک اینڈ والے میزبان پر ایجنٹس چلانا چاہتے ہوں۔ اسے دوبارہ بلڈ کی ضرورت نہیں، اور سرور پروسیس کی پوری عمر کے لیے ایک انتباہ لاگ کرتا ہے تاکہ یہ حالت کبھی خاموش نہ رہے۔

### `--tool-deferral`

بلٹ اِن ہارنس کے رنز ٹول تعریفوں کا ایک چھوٹا براہِ راست سیٹ اور باقی سب کا صرف نام والا انڈیکس بھیجتے ہیں، جو پہلی بار استعمال ہونے پر یا `repl` اسکرپٹ سے کال ہونے پر اپنے اسکیمے لوڈ کرتے ہیں۔ یہ ہمیشہ نظر آنے والے سیٹ کو اُس حد کے اندر رکھتا ہے جہاں ماڈلز قابلِ اعتماد طریقے سے ٹولز منتخب کرتے ہیں۔ ٹیسٹ جو رجسٹری بناتے ہیں اس پر ناپا گیا: بلٹ اِن ایجنٹ کے معیاری چیٹ ٹولز 14 تعریفیں بنتے ہیں: `repl` کے ساتھ تقریباً 16.5 KB (جن میں سے تقریباً 4 KB `repl` کے ہیں، جس کی تعریف 4,096 بائٹس سے زیادہ نہیں ہو سکتی)، اور ایسے سرور پر تقریباً 13 KB جو اسکرپٹ نہیں چلا سکتا۔ طلب پر لوڈ ٹولز ہر وقت نام سے کال کے قابل رہتے ہیں، اور `search_tools` اُنہیں ارادے سے ڈھونڈ لیتا ہے۔ دیکھیں [ٹول کانٹیکسٹ اور پرامپٹ کیشنگ](/ur-PK/ہدایت-نامہ/تصورات/ٹول-کانٹیکسٹ/)۔

`--tool-deferral off` ہر منظور شدہ ٹول کی تعریف پہلے ہی بھیجتا ہے، سوائے اس کے کہ `repl` والا رن اب بھی وہ ٹولز اسکرپٹ سے کال کرتا ہے جنہیں اسکرپٹ کال کر سکتا ہے۔ یہ ایسے ماڈل کے لیے بندش سوئچ ہے جو دو درجوں والی سطح کو بری طرح سنبھالتا ہو — دوبارہ بلڈ کے بجائے ایک فلیگ۔ یہ صرف بلٹ اِن ہارنس پر اثر کرتا ہے؛ بیرونی کلائنٹس کو نظر آنے والی MCP `tools/list` مکمل کیٹلاگ ہوتی ہے، سوائے اس ایجنٹ رن کے جو ایسے سرور پر ہو جو [کوڈ موڈ](/ur-PK/ہدایت-نامہ/تصورات/کوڈ-موڈ/) اسکرپٹس چلا سکتا ہو۔

### `--credential-gate`

جس رن کا فراہم کنندہ کریڈنشل غائب ہو یا ختم ہو چکا ہو، وہ ناکام ہونے کے بجائے **پارک**
کر دیا جاتا ہے: آپریٹر کو اُسے درست کرنے کا پرامپٹ ملتا ہے، اور اگر وہ درست کر دے تو رن
دوبارہ شروع ہو جاتا ہے۔ ڈیفالٹ مہلت 900 سیکنڈ (15 منٹ) ہے، جو 0–3600 تک محدود ہے۔

یہ مہلت جان بوجھ کر منظوری کے پرامپٹ سے کہیں طویل ہے: منظوری ایک فیصلہ ہے جو کوئی
سیکنڈوں میں کر لیتا ہے، جبکہ کریڈنشل درست کرنے کا مطلب ہے ٹرمنل کھولنا، سائن اِن کرنا
اور واپس آنا۔ اونچی حد ہی اُس غیر حاضر رن کو — کوئی پائپ لائن قدم، کوئی cron ٹرگر،
کوئی ویب ہک — اُس شخص کا انتظار کرنے سے روکتی ہے جو سو رہا ہو۔ جب یہ ختم ہو جاتی ہے تو
رن اُسی پیغام کے ساتھ ناکام ہوتا ہے جس کے ساتھ وہ بہرحال ناکام ہوتا۔

`--credential-gate=0` بندش سوئچ ہے: کچھ بھی کبھی پارک نہیں ہوتا اور خراب کریڈنشل باری
کو بالکل ویسے ہی ختم کر دیتا ہے جیسے گیٹ کے وجود سے پہلے ہوتا تھا۔

### کوڈ موڈ

[کوڈ موڈ](/ur-PK/ہدایت-نامہ/تصورات/کوڈ-موڈ/) ایجنٹ کو ایک JavaScript اسکرپٹ چلانے دیتا ہے جو اس کے ٹولز کو کال کرتا ہے۔ اسے آن یا بند کرنے کا کوئی فلیگ نہیں: سرور اسکرپٹس چلا سکے تو ہر رن کو `repl` ٹول ملتا ہے، اور عوامی ڈیمو سرور کوئی اسکرپٹ نہیں چلاتا۔

اسکرپٹس `cc_codemode` میں چلتے ہیں، ایک پروگرام جو `bin/codemode/` میں سرور کے ساتھ آتا ہے۔ اس کے بغیر سرور شروع نہیں ہوتا: وہ ایک لائن چھاپتا ہے جو بتاتی ہے کہ کیا غائب ہے، اور ایگزٹ کوڈ `78` کے ساتھ باہر نکل جاتا ہے۔ شروع ہوتے وقت یہ پروگرام کا لاک ڈاؤن سیلف-ٹیسٹ چلاتا ہے اور ایک لائن چھاپتا ہے (جو صرف `--log-level error` سے خاموش ہوتی ہے):

```text
cc_server: code_mode=available (cc_codemode 0.1.0 quickjs-ng 0.16.2 protocol 2; 16 scripts at once, at most 12 per workspace; up to 64 more runners kept for scripts waiting on a person; heap at most 1024 MiB per script)
cc_server: code_mode=unavailable (<reason>) — runs on this host get no repl tool; scripts never run without full lockdown
```

`unavailable` کا مطلب ہے کہ پروگرام اس ہوسٹ پر خود کو لاک ڈاؤن نہیں کر سکتا، مثلاً ایسے کنٹینر میں جس کا سیکیورٹی پروفائل اس کے کسی مرحلے کو مسترد کرتا ہو، یا وہ ریلیز بلڈ نہ ہو۔ سرور معمول کے مطابق چلتا ہے، کسی رن کو `repl` نہیں ملتا، اور ورک اسپیس کے کوڈ موڈ کی ترتیبات وجہ دکھاتی ہیں۔

سرور چلتے ہوئے بھی جانچ کرتا رہتا ہے۔ جب پروگرام کسی ایسی وجہ سے شروع نہ ہو جو اسکرپٹ کی نہ ہو، تو سرور سیلف-ٹیسٹ زیادہ سے زیادہ ہر منٹ ایک بار دوبارہ چلاتا ہے۔ اگر وہ ناکام ہو، تو سرور اپنی وجہ کے ساتھ `unavailable` لائن پرنٹ کرتا ہے اور کوئی اسکرپٹ نہیں چلاتا: اس دوران شروع ہونے والے رنز کو `repl` نہیں ملتا، اور جس رن کے پاس پہلے سے ہے وہ اپنے ٹولز براہِ راست کال کرتا ہے ([جب اسکرپٹس نہیں چل سکتے](/ur-PK/ہدایت-نامہ/تصورات/کوڈ-موڈ/#جب-اسکرپٹس-نہیں-چل-سکتے))۔ یہ جانچتا رہتا ہے، زیادہ سے زیادہ ہر منٹ ایک بار، اور جب سیلف-ٹیسٹ دوبارہ پاس ہو تو `available` لائن پرنٹ کرتا ہے اور دوبارہ اسکرپٹس چلاتا ہے۔ صرف وہ سیلف-ٹیسٹ جو شروع ہوتے وقت ناکام ہوا ہو ری اسٹارٹ مانگتا ہے۔ ورک اسپیس کی ترتیبات میں دکھائی جانے والی وجہ سے میزبان مشین کے فائل راستے ہٹا دیے جاتے ہیں؛ لاگ لائن میں وہ مکمل ہوتی ہے۔

دو کوڈ موڈ فلیگز طے کرتے ہیں کہ اسکرپٹس کیا استعمال کر سکتے ہیں۔ `--code-mode-max-processes` تمام ورک اسپیسز میں ایک ساتھ چلنے والے اسکرپٹس کی حد مقرر کرتا ہے (ڈیفالٹ پروسیسر کورز کا دوگنا، زیادہ سے زیادہ 16؛ قبول شدہ 1–64)۔ جب حد 2 یا اس سے زیادہ ہو، تو ایک ورک اسپیس زیادہ سے زیادہ حد منہا اس کا ایک چوتھائی استعمال کرتی ہے، تاکہ کوئی ایک ورک اسپیس سب جگہیں نہ لے سکے، اور انتظار کرنے والے اسکرپٹس ورک اسپیسز کے درمیان باری باری داخل ہوتے ہیں۔ منظوری یا جواب کے انتظار میں موجود اسکرپٹ اپنی جگہ دوسرے اسکرپٹ کو دے دیتا ہے اور جواب ملنے تک کوئی ٹول کال شروع نہیں کرتا؛ ایسے انتظار کرنے والے اسکرپٹس حد کے چار گنا تک رکھے جاتے ہیں، جن میں سے زیادہ سے زیادہ تین چوتھائی ایک ہی ورک اسپیس کے ہوں، اور ہر ایک اپنی پروسیسر-ٹائم حد کے اندر حساب جاری رکھ سکتا ہے۔ `--code-mode-max-heap-mb` کسی ایک اسکرپٹ کی زیادہ سے زیادہ میموری ہے۔

وہ قدر جو یہ فلیگز قبول نہیں کرتے (حد سے باہر کا نمبر، یا جو نمبر ہی نہ ہو) سرور کو شروع ہوتے وقت روک دیتی ہے (ایگزٹ کوڈ `78`) اور ایک پیغام آتا ہے جو قبول شدہ قدریں بتاتا ہے۔ اسے کبھی ڈیفالٹ نہیں پڑھا جاتا۔

### `pair`

| فلیگ           | ڈیفالٹ                                                   | مطلب                                                                                                                                                                  |
| -------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--device`     | `web-client`                                              | ڈیوائس id۔ پلیٹ فارم اِسی سے اخذ ہوتا ہے، چنانچہ `--device desktop` ایک ڈیسک ٹاپ قطار بناتا ہے اور `--device ios`/`android` ایک فون قطار؛ باقی کچھ بھی ویب سمجھا جاتا ہے |
| `--label`      | پلیٹ فارم کا نام اور اِس مشین کا ہوسٹ نیم                 | ڈیوائسز کی فہرست میں دکھایا جانے والا نام                                                                                                                              |
| `--host`       | `localhost`، یا ہر انٹرفیس پر بائنڈ ہونے پر `<this-host>`  | پرنٹ شدہ URL میں شامل کرنے والا ہوسٹ۔ اِسے وہ LAN IP یا ٹنل ہوسٹ بنائیں جسے کلائنٹ واقعی ڈائل کرے گا                                                                   |
| `--client-url` | غیر سیٹ                                                   | میزبان **ویب** کلائنٹ کا اوریجن۔ ایک اسکین کے قابل ڈیپ لنک اور ٹرمنل QR شامل کرتا ہے                                                                                    |

`pair` بنیادی `--data-dir`، `--port` اور `--bind` فلیگز بھی قبول کرتا ہے: یہ لکھنے
کے لیے ڈیٹا ڈائر منتخب کرتے ہیں اور پرنٹ ہونے والا سرور URL بناتے ہیں (لوپ بیک پر
`ws`، اور `--bind any` پر `wss`)۔ ایک ہی `--device` کے لیے `pair` دوبارہ چلانے سے
اُس کی کلید بدل جاتی ہے اور اُس ڈیوائس کے زندہ سیشنز گر جاتے ہیں۔ یہاں بنایا گیا
کریڈنشل **بغیر میعاد** ہوتا ہے، اُن 30 دنوں کے برعکس جو ایپ کے اندر کی پیئرنگ مقرر
کرتی ہے۔

:::caution[`--client-url` کا QR فون کا QR نہیں ہے]
`pair --client-url` **ویب** کلائنٹ کا کنیکٹ فارم بھر دیتا ہے (سرور URL،
ڈیوائس id اور کلید URL فریگمنٹ میں)۔ فون ایک مختلف پے لوڈ سے پیئر ہوتا ہے جو
ایپ کے اندر کے پیئرنگ پینل سے بنتا ہے — سرور کا مکمل کنکشن ڈسکرپٹر
اور ایک میعاد۔ یہ دونوں ایک دوسرے کی جگہ استعمال نہیں ہو سکتے — دیکھیں
[ڈیوائس پیئر کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/ڈیوائس-پیئر-کریں/)۔
:::

### `connect`

اُنہی settings کو پڑھتا اور لکھتا ہے جو **ترتیبات → سرور → سنگل سائن آن** کے تحت **Control Center Connect** کارڈ میں ہیں، data directory سے۔ چلتا ہوا سرور تبدیلی 10 منٹ کے اندر یا restart پر لے لیتا ہے۔

| کمانڈ                                  | کیا کرتی ہے                                                                                                                       |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `cc_server connect status`             | mode، URL، کیا `CC_CONNECT_URL` اسے lock کرتا ہے، install id، health اور ہر lane کا source (`own`، `connect` یا `off`) پرنٹ کرتی ہے |
| `cc_server connect enable`             | Control Center کا hosted Connect استعمال کرتی ہے                                                                                  |
| `cc_server connect enable --url <url>` | اس URL پر custom Connect استعمال کرتی ہے (HTTPS، یا loopback پر `http`)                                                            |
| `cc_server connect disable`            | Connect استعمال کرنا بند کرتی ہے۔ صرف سرور کی اپنی apps لوگوں کو sign in کراتی ہیں                                                  |

بغیر کمانڈ کے `status` ڈیفالٹ ہے۔ ہر کمانڈ `--data-dir` قبول کرتی ہے۔ `CC_CONNECT_URL` وہ سب کچھ override کرتا ہے جو یہ کمانڈز محفوظ کرتی ہیں۔ نامعلوم کمانڈ کوڈ `64` کے ساتھ ختم ہوتی ہے۔ modes، install identity اور status codes کے لیے [Control Center Connect کا حوالہ](/ur-PK/ہدایت-نامہ/حوالہ/connect/) دیکھیں۔

### `update`

`--apply` انسٹال کو بدل دیتا ہے؛ جب تک کوئی سرور کنفیگر شدہ پورٹ پر جواب دے رہا ہو
اُس وقت یہ مسترد کر دیا جاتا ہے، الا یہ کہ آپ `--force` دیں۔ `--allow-downgrade`
کسی پرانی ریلیز کی اجازت دیتا ہے۔

وہ انسٹالز جن کا یہ خود مالک نہ ہو، کمانڈ اُن کے لیے خرابی کے بجائے وضاحت کے ساتھ
صاف انکار کر دیتی ہے:

| ماحول                          | کس سے پتہ چلتا ہے                            | یہ کیا کہتی ہے                                                |
| ----------------------------- | ------------------------------------------- | ------------------------------------------------------------- |
| ڈیسک ٹاپ کا ایمبیڈڈ سرور       | `CC_EMBEDDED=1` یا `CC_BOOTSTRAP_DEVICE_ID`  | اس کے بجائے ایپ اپ ڈیٹ کریں — انسٹالر پورا درخت بدل دیتا ہے   |
| `dart run` والا سورس چیک آؤٹ   | اسکرپٹ کی پاتھ `.dart` پر ختم ہوتی ہے        | اِسے git سے اپ ڈیٹ کریں                                       |
| Docker                        | کنٹینر مارکرز                                | نئی امیج پل کریں                                              |

## پروسیس لائف سائیکل

`cc_server` `SIGINT` / `SIGTERM` تک چلتا ہے۔ اِسے ایک اضافی ماحول ویری ایبل کنٹرول
کرتا ہے، اور اُسے آپ کے بجائے ڈیسک ٹاپ سیٹ کرتا ہے:

| ویری ایبل                 | اثر                                                                                                                                                     |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CC_EXIT_WITH_PARENT=1`  | سرور اُس وقت ختم ہو جاتا ہے جب اُس کا پیرنٹ پروسیس ہو، جس کا پتہ پیرنٹ کے اپنے stdin پائپ کا رائٹ اینڈ بند کرنے سے چلتا ہے۔ ڈیسک ٹاپ اِسے اِس لیے سیٹ کرتا ہے تاکہ کوئی کریش شدہ ایپ کبھی ڈیٹا ڈائر تھامے ہوئے کوئی یتیم سرور پیچھے نہ چھوڑے |

اِسے خود صرف اُس وقت سیٹ کریں جب آپ `cc_server` کو بطور چائلڈ پروسیس نگرانی میں رکھے
ہوں اور وہی ضمانت چاہتے ہوں۔

`DO_NOT_TRACK=1` (خالی، `0` یا `false` کے علاوہ کوئی بھی ویلیو) سرور کے اپنے
[استعمال کے تجزیات](/ur-PK/ہدایت-نامہ/حوالہ/استعمال-کے-تجزیات/) روک دیتا ہے، چاہے سرور بھر کا سوئچ
آن ہو۔ کلائنٹس پھر بھی سوئچ کی پیروی کرتے ہیں۔

## ڈیٹا ڈائر کی ترتیب

ڈیفالٹ ڈیٹا ڈائر macOS پر `~/Library/Application Support/control-center`، Windows پر
`%APPDATA%\control-center` اور باقی جگہوں پر `$XDG_DATA_HOME/control-center` (ورنہ
`~/.local/share/control-center`) ہوتا ہے۔ cwd کے نسبتی `.cc_server` صرف اُس وقت
استعمال ہوتا ہے جب کوئی ہوم یا ایپ-ڈیٹا ڈائریکٹری حل نہ ہو۔

سرور ڈیٹا ڈائریکٹری کو اپنے ہی اکاؤنٹ تک محدود رکھتا ہے (`0700`)۔ یہ شروع ہونے سے انکار کرتا ہے (exit code `78`) جب وہ ایسا نہ کر سکے، جب `global.db` خراب ہو یا نئے ورژن نے لکھا ہو، یا جب اس کی شناختی فائل نہ پڑھی جا سکے۔

| پاتھ                              | مواد                                                                             |
| --------------------------------- | ------------------------------------------------------------------------------- |
| `global.db`                       | ورک اسپیس رجسٹری، صارفین، پیئر شدہ ڈیوائسز، نیوز فیڈ اور فلیٹ قطار               |
| `<workspaceId>/workspace.db`      | ہر ورک اسپیس کے لیے ایک ڈیٹا بیس — ایجنٹس، اسپیسز، ٹکٹس، میموری        |
| `<workspaceId>/code_index.db`     | اُس ورک اسپیس کا کوڈ گراف۔ غائب ہو تو دوبارہ بنایا جاتا ہے، اور کبھی بیک اپ نہیں ہوتا        |
| `pre_upgrade/`, `<workspaceId>/pre_upgrade/` | کسی اپڈیٹ سے پہلے کے ڈیٹا بیس کی دو تازہ ترین کاپیاں، جب اپڈیٹ نے اس کا فارمیٹ بدلا |
| `<workspaceId>/chat_credentials/` | چیٹ بوٹ ٹوکنز، سادہ JSON کی صورت میں، تاکہ وہ ورک اسپیس کے ساتھ ہی رہیں          |
| `secrets.json`                    | Connect install key، provider apps، لوگوں کے sign-ins (Connect کے ذریعے بنائے گئے ہوں تو sealed)، webhook secrets، SSO (`0600`) |
| `backups/<timestamp>/`            | ایک انسٹال اسنیپ شاٹ — `manifest.json`، `global.db` اور ہر ورک اسپیس کی ایک کاپی |
| `backups/exports/`                | واحد ورک اسپیس کی ایکسپورٹس، `<workspaceId>-<timestamp>.db`                     |
| `backups/transfer/`               | بیک اپ ڈاؤن لوڈز اور اپ لوڈز کے لیے اسٹیجنگ؛ اُسی روٹ سے صاف ہوتا ہے جو اسے لکھتا ہے |
| `models/`                         | ڈیوائس پر موجود ایمبیڈنگ، ڈائریائزیشن اور اسپیچ ماڈلز                            |
| `codemode/` | کوڈ موڈ رنر کا ایک ڈیولپمنٹ نسخہ، `scripts/natives/build_codemode.sh` کے ذریعے انسٹال؛ ریلیز بنڈلز اسے `bin/codemode/` میں رکھتے ہیں |
| `meetings/<meetingId>/`           | محفوظ رکھی گئی میٹنگ آڈیو                                                        |
| `rigs/images/`                    | درآمد شدہ رگ ڈسک امیجز (QEMU ڈیسک ٹاپ سطح)                                       |
| `rigs/smolvm/<rigId>/`            | فی رگ microVM رن ٹائم حالت (بروکر سیکرٹ، `0600`)                                  |
| `rigs/smolvm-packs/`              | پہلے سے ایکسٹریکٹ شدہ مشین پیکس — وہ کیش جو بار بار رگ بوٹ کو تیز بناتا ہے        |
| `rigs/tls/`                       | رگ HTTPS کے لیے ڈیولپمنٹ ڈومین کی سرٹیفکیٹ اتھارٹی (کلیدیں `0600`)               |
| `rigs/run/<rigId>/`               | QEMU اوورلے، سیڈ امیجز اور فی VM کلیدیں (`0600`)                                 |
