سنگل سائن اَن سے جڑی ہر قابلِ کنفیگریشن چیز، ایک ہی جگہ۔ اقدار `global.db` کی
`sso_connections` قطاروں میں رہتی ہیں (ڈیزائن ہی سے سرور بھر کے لیے)، اور
**ترتیبات → سرور → سنگل سائن آن** یا `sso.*` RPC آپریشنز کے ذریعے ترمیم کی
جاتی ہیں۔ محفوظ شدہ قطار ہی واحد حقیقت کا ماخذ ہے — `CC_SAML_*` / `CC_OIDC_*`
ماحول کا کوئی راستہ نہیں (ایسا کنکشن جو دو جگہوں سے آ سکتا ہو، وہ ہے جس سے
ترتیبات کی اسکرین اختلاف کر سکتی ہے)۔

## پروسیس کی کنفیگریشن

SSO کنکشنز ماحول سے سیڈ نہیں کیے جاتے۔ ایک باقی بچا پروسیس فلیگ یہ طے کرتا ہے کہ
SSO کال بیک کے بعد براؤزر ویب کلائنٹ کہاں کھولے:

| ویری ایبل / فلیگ | مطلب |
| --- | --- |
| `--web-client-url` / `CC_SERVER_WEB_CLIENT_URL` | سیل شدہ اسناد کی ہینڈ آف کے لیے ویب کلائنٹ URL؛ سیٹ نہ ہونے پر ہینڈ آف اسی اوریجن پر رہتا ہے (صرف اُس وقت مفید جب ویب کلائنٹ وہیں پیش کیا جاتا ہو)۔ `web-popup` لاگ اِن کے لیے، شروع کرنے والے ٹیب سے ایک اجازت یافتہ `client_origin` کو ترجیح ملتی ہے۔ |

خود جاری کنندہ کا URL لازماً `https` ہونا چاہیے (`http` صرف لوپ بیک جاری
کنندگان `localhost`، `127.0.0.1` اور `::1` کے لیے قبول کیا جاتا ہے)۔ IdP کال بیک
اور ویب کلائنٹ ہوسٹ کے لیے قابلِ اعتماد TLS استعمال کریں: وہ صفحہ جو وصول کنندہ کی
کلید بناتا ہے اور اُس کا فراہم کردہ JavaScript اعتماد کی حد کا حصہ ہیں۔ HTTPS اُس
بوٹ اسٹرپ کی حفاظت کرتا ہے؛ پیئرنگ کے بعد، براہِ راست اور ریلے والے `/rpc` سیشنز
دونوں کو Noise انکرپشن اور پن شدہ سرور شناخت درکار ہوتی ہے۔

## HTTP اینڈ پوائنٹس

| اینڈ پوائنٹ | تصدیق | مقصد |
| --- | --- | --- |
| `GET /saml/login?relay=…&handoff_key=…` | کوئی نہیں (redirect) | SP سے شروع ہونے والا لاگ اِن کلائنٹ کے پاس موجود X25519 وصول کنندہ کلید کے ساتھ شروع کریں؛ `relay=desktop` ایپ کو ہینڈ آف کرتا ہے، `relay=web-popup` منتظر کنیکٹ ٹیب کو postMessages کرتا ہے (اُس کا `client_origin` صرف اُس وقت مانا جاتا ہے جب اوریجن کی اجازت فہرست اُس پر بھروسا کرے) |
| `POST /saml/acs` | کوئی نہیں (IdP POST) | ایسرشن کی توثیق کریں اور صارف کو پروویژن کریں؛ SP سے شروع ہونے والا لاگ اِن جاری کردہ ڈیوائس اسناد کو شروع کرنے والی وصول کنندہ کلید پر سیل کرتا ہے؛ اجازت یافتہ غیر طلب شدہ SAML اِس کے بجائے براؤزر سے بندھا دعویٰ دیتا ہے |
| `POST /saml/claim` | اسی اوریجن کا براؤزر گرانٹ | ایک بار استعمال ہونے والے غیر طلب شدہ SAML گرانٹ کو اُس کی کوکی اور تازہ `handoff_key` کے ساتھ چھڑائیں؛ وصول کنندہ کے لیے سیل شدہ اسناد واپس کرتا ہے، کبھی پلین ٹیکسٹ پیئرنگ کلید نہیں |
| `GET /saml/metadata` | کوئی نہیں | ہمارا SP `EntityDescriptor` |
| `GET /oidc/login?relay=…&handoff_key=…` / `GET /oidc/callback` | کوئی نہیں | OIDC کا راؤنڈ ٹرپ؛ لاگ اِن کے لیے کلائنٹ کے پاس موجود وصول کنندہ کلید درکار ہے؛ `relay=desktop` ایپ کو ہینڈ آف کرتا ہے، `relay=web-popup` منتظر کنیکٹ ٹیب کو (وہی `client_origin` رواج) |
| `GET /auth/providers` | کوئی نہیں، CORS `*` | کنیکٹ اسکرین کی پروب: پیش کردہ SSO کنکشنز (`id`/`kind`/`label`) + `pairingEnabled` |
| `/scim/v2/Users…` | Bearer (SCIM ٹوکن) | Users کے لیے create/get/list+filter/PUT/PATCH/DELETE |
| `/scim/v2/Groups` | Bearer | صرف پڑھنے کے لیے؛ گروپ پش ڈیزائن ہی سے 501 جواب دیتا ہے |
| `/scim/v2/ServiceProviderConfig` | Bearer | اہلیت کی دستاویز |

SP سے شروع ہونے والے SAML اور OIDC کے لیے، لاگ اِن شروع کرنے والے URL کو ایک درست
`handoff_key` درکار ہوتا ہے (شروع کرنے والے کلائنٹ کی X25519 عوامی کلید)۔ سرور اُس
کلید کو زیرِ التوا لاگ اِن کے ساتھ رکھتا ہے اور کال بیک پر جاری کردہ ڈیوائس اسناد
کو عارضی X25519، HKDF-SHA256 اور AES-256-GCM کے ذریعے سرور اوریجن سے باندھ کر سیل
کرتا ہے۔ ڈیسک ٹاپ ہینڈ آف `control-center://pair` استعمال کرتا ہے، اسی ٹیب والا ویب
ہینڈ آف URL فریگمنٹ استعمال کرتا ہے، اور `web-popup` اگر فراہم ہو تو اجازت یافتہ
`client_origin` کو postMessage کرتا ہے (ورنہ کنفیگر کردہ ویب کلائنٹ URL یا کال بیک
اوریجن کو)۔ اُس فریگمنٹ یا پاپ اَپ پیغام میں سیل شدہ لفافہ سفر کرتا ہے، نہ کہ کوئی
پلین ٹیکسٹ پیئرنگ کلید۔ شروع کرنے والا کلائنٹ اُسے کھولنے کے لیے متعلقہ نجی کلید
رکھتا ہے۔ یہ لفافہ پیئرنگ کے بعد قائم ہونے والے لازمی Noise سیشن سے الگ ہے۔

IdP سے شروع ہونے والی SAML Response (جب فعال ہو) کا کوئی شروع کرنے والا وصول کنندہ
نہیں ہوتا۔ اِس کے بجائے، ACS پانچ منٹ کی، HttpOnly، SameSite=Strict براؤزر کوکی
سیٹ کرتا ہے اور **Open web client** / **Open desktop app** کا انتخاب پیش کرتا ہے۔ وہ
صفحہ ایک تازہ وصول کنندہ کلید بناتا ہے اور اُس کا عوامی نصف اور گرانٹ ہینڈل اسی
اوریجن سے `POST /saml/claim` کو بھیجتا ہے۔ claim کے لیے مماثل کوکی اور اوریجن درکار
ہوتے ہیں (ایک CSRF حد)، گرانٹ کو ایک بار استعمال کرتا ہے اور صرف وصول کنندہ کے لیے
سیل شدہ لفافہ واپس کرتا ہے۔ بعد کا ویب/ڈیسک ٹاپ فریگمنٹ وہی لفافہ اور وصول کنندہ کے
نجی کلید کا مواد لے کر چلتا ہے تاکہ منزل کا کلائنٹ اُسے کھول سکے، **نہ** کہ کوئی
پلین ٹیکسٹ ڈیوائس اسناد۔ کوئی دوسرا براؤزر یا میعاد ختم شدہ گرانٹ اُسے چھڑا نہیں
سکتا۔ منزل کے ویب کلائنٹ کا اوریجن فریگمنٹ تک رسائی رکھتا ہے اور اُسے ڈی کرپٹ کر
سکتا ہے؛ کوئی متاثر شدہ کال بیک صفحہ یا ویب کلائنٹ اوریجن اسناد چرا سکتا ہے۔
انکرپشن غیر قابلِ اعتماد طور پر پیش کیے جانے والے کوڈ کو محفوظ نہیں بناتی۔

## RPC آپریشنز

تمام `sso.*` آپریشنز سرور کے دائرے میں ہیں اور **سرور مالک** تک محدود ہیں (اِس
انسٹال کا آپریٹر، `ServerAuthority.serverOwner`)۔ کسی ورک اسپیس کا مالک ہونا
کافی نہیں؛ پیئرنگ اکیلی انہیں کبھی نہیں دیتی۔

| آپریشن | مقصد |
| --- | --- |
| `sso.getConfig` | کسی ایک قسم کے لیے محفوظ شدہ کنکشن |
| `sso.saveConfig` | توثیق کریں، محفوظ کریں اور لائیو لاگو کریں |
| `sso.status` | فعال/کنفیگر شدہ فلیگز، SCIM ٹوکن کی موجودگی، کینونیکل اوریجن |
| `sso.testConnection` | براؤزر راؤنڈ ٹرپ کے بغیر کنکشن جانچیں (SAML: میٹا ڈیٹا پارس + AuthnRequest بلڈ؛ OIDC: جاری کنندہ discovery)، اسکرین پر موجود غیر محفوظ اقدار کے اختیاری استعمال کے ساتھ |
| `sso.spMetadata` | کسی اوریجن کے لیے SP `EntityDescriptor` جاری کریں |
| `sso.setPairingEnabled` | دستی پیئرنگ کی اجازت دیں/روکیں (دعوتی کوڈز، پیئرنگ کیز)؛ جب کوئی کام کرنے والا SSO کنکشن موجود نہ ہو تو اِسے بند کرنے سے انکار لاک آؤٹ سے بچاتا ہے |
| `sso.sessionPolicy` | انسٹال کی ڈیوائس اسناد کی زیادہ سے زیادہ عمر اور آئیڈل ٹائم آؤٹ پڑھیں (منٹ میں؛ `0` = سیٹ نہیں) |
| `sso.setSessionPolicy` | وہ حدود سیٹ کریں؛ ڈیوائس چیک پر لاگو ہوتی ہیں، کلائنٹس کو بتائی نہیں جاتیں |
| `sso.scimRegenerateToken` | SCIM bearer ٹوکن بنائیں + واپس دیں (ایک بار) |

## توثیق کے ایرر کوڈز

`cc_saml_verify_response` کی ناکامیاں ایک مستحکم کوڈ لے کر آتی ہیں:

| کوڈ | مطلب |
| --- | --- |
| `signature` | دستخط غائب/ناقابلِ بھروسا/چھیڑے گئے، یا کوئی ممنوع الگورتھم/ٹرانسفارم |
| `expired` | `NotBefore`/`NotOnOrAfter` سے باہر (اسکیو سے زیادہ) |
| `audience` | مخاطب کی پابندی ہمارا نام نہیں لیتی |
| `destination` | ریسپانس کی منزل ہمارا ACS نہیں |
| `request_match` | `InResponseTo` کسی زیر التواء درخواست سے مماثل نہیں، یا غیر طلب شدہ جب کہ ممنوع ہو |
| `issuer` | جاری کنندہ کنفیگر شدہ IdP نہیں |
| `recipient` | سبجیکٹ کی تصدیق کا وصول کنندہ ہمارا ACS نہیں |
| `malformed` | XML/اسکیما سطح کی ناکامی |
| `status` | IdP کا بتایا ہوا `status`، Success نہیں تھا |
| `invalid` / `internal` | کوئی بھی اور / seam کی ناکامی |

## ڈیٹا بیس کی سطحیں

- `sso_connections` (global.db) — فی قسم ایک قطار، ڈیزائن ہی سے ورک اسپیسوں
  کے پار۔
- `users.sso_subject` + `users.sso_issuer` — فراہم کنندہ سبجیکٹ کا پن، جو
  `(issuer, subject)` کے حساب سے پارشل انڈیکس کے ذریعے یکتا ہے۔
- `users.deactivated_at` — SCIM ڈی ایکٹیویشن کا اسٹیمپ۔
- SCIM bearer ٹوکن اور OIDC کلائنٹ سیکرٹ 0600 سیکرٹس فائل میں رہتے ہیں،
  ڈیٹا بیس میں کبھی نہیں۔
