## AgentCapabilities فلیگ

ہر ڈسپیچ پر حل ہوتے ہیں: ایجنٹ کا ڈیفالٹ، جو null ہونے پر صارف سطح کے ڈیفالٹ پر واپس آ جاتا ہے، اور اُس کے اوپر فی گفتگو ایک اوور رائیڈ۔ نفاذ عدم کی صورت میں ہوتا ہے — کریڈینشل بروکر بس وہ چیز جاری یا انجیکٹ ہی نہیں کرتا جسے کوئی غیر فعال قابلیت گھیرتی ہو۔

| فلیگ               | قسم   | ڈیفالٹ | وضاحت                                                                              |
| ------------------ | ------ | ------- | ---------------------------------------------------------------------------------------- |
| `canPushToRepo`    | `bool` | `false` | ریموٹ پر کامٹس پش کریں؛ `canCallGitHubApi` کے ساتھ مل کر GitHub ٹوکن انجیکشن کو گیٹ کرتا ہے    |
| `canCallGitHubApi` | `bool` | `false` | api.github.com کال کریں؛ `GH_TOKEN` انجیکشن اور GitHub ایگریس ڈومینز کو گیٹ کرتا ہے            |
| `canCallTicketing` | `bool` | `false` | ٹکٹنگ فراہم کنندہ کی API کال کریں؛ فراہم کنندہ کی API کلید کے انجیکشن اور اس کے ایگریس ڈومینز کو گیٹ کرتا ہے |
| `canAccessNetwork` | `bool` | `true`  | من مانی آؤٹ باؤنڈ ایگریس۔ ہارنس کے `web_fetch` اور `web_search` ٹولز کو بھی گیٹ کرتا ہے     |

`AgentCapabilities.safeDefault` چاروں کنسٹرکٹر ڈیفالٹس پر مشتمل ہے۔ `legacyDefault` (چاروں true) صرف اُس مائیگریشن میں استعمال ہوتا ہے جس نے قابلیتوں کے وجود سے پہلے بنائی گئی گفتگوؤں کو بیک فل کیا۔ خراب یا خالی محفوظ blob `safeDefault` میں پارس ہو جاتا ہے؛ لیگیسی کلید `canCallLinear` کو `canCallTicketing` پڑھا جاتا ہے۔

## AgentLiveState (اخذ شدہ)

محفوظ نہیں ہوتی۔ سات اقدار۔ اعلان کی ترتیب ہی ترجیح کی ترتیب ہے (`sortPriority`، جو ایک ٹیسٹ نے پن کیا ہوا ہے)، اور روسٹر اسی ترتیب سے چھانٹا جاتا ہے:

| حالت       | `sortPriority` | شرط                                                                                                           |
| ----------- | -------------- | ------------------------------------------------------------------------------------------------------------------- |
| `running`   | 0              | کسی بھی رن لاگ کی اسٹیٹس `running` ہو                                                                                    |
| `blocked`   | 1              | تازہ ترین رن کی فعالیت `blocked`، `stalled` یا `looping` ہو                                                     |
| `failed`    | 2              | تازہ ترین رن کی اسٹیٹس `error` ہو، یا اس کی فعالیت `failed` یا `dead` ہو                                           |
| `queued`    | 3              | رن ڈسپیچ ہو چکا مگر چل نہیں رہا — اُسی ایجنٹ کے کسی دوسرے رن کے پیچھے کھڑا ہے، یا لکھا جا چکا مگر ابھی شروع نہیں ہوا |
| `succeeded` | 4              | رن کامیابی سے مکمل ہوا                                                                                       |
| `idle`      | 5              | ایجنٹ پہلے چل چکا ہے اور اس وقت کچھ بھی پرواز میں نہیں                                                                  |
| `neverRun`  | 6              | کوئی رن لاگ موجود نہیں                                                                                                   |

`queued` اور `succeeded` **صرف فی رن** ہیں۔ `deriveAgentLiveState`، جو کسی ایجنٹ کے لیے روسٹر کی حالت نکالتا ہے، ان میں سے کوئی بھی کبھی پیدا نہیں کرتا — وہ `neverRun`، `running`، `failed`، `blocked` یا `idle` واپس کرتا ہے۔
