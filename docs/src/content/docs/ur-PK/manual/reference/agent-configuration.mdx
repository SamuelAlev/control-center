## شیل ہکس

شیل ہکس سرور کے مالک کو اجازت دیتے ہیں کہ ایجنٹ رن کے گرد اپنی اسکرپٹس چلائیں: سیشن شروع ہونے پر ایک بار، ہر ٹول کال سے پہلے، ہر ٹول کال کے بعد، جب ایجنٹ اپنی باری ختم کرنے والا ہو، اور کمپیکشن سے پہلے۔ ہک ایک آزاد کوڈ ہوتا ہے، اس لیے ہکس ہوسٹ کی ترتیب ہیں۔ انہیں صرف سرور کا مالک، ہاتھ سے، سرور کی مشین پر ترتیب دیتا ہے۔ ایپ میں اس کے لیے کوئی سیٹنگ نہیں اور کوئی آپریشن انہیں نہیں لکھتا۔

ایجنٹ کے لیے ہکس سرور کی ڈیٹا ڈائریکٹری میں اس کے اپنے فولڈر میں رہتے ہیں:

```text
<data dir>/_agent_hooks/<workspace id>/<agent slug>/hooks.json
```

`<agent slug>` ورک اسپیس میں ایجنٹ کے فولڈر (`agents/<slug>/`) کا نام ہے۔ یہ فولڈر ہر ورک اسپیس کے اسٹوریج سے باہر ہے، اور ہر سینڈ باکس ڈیٹا ڈائریکٹری کو چھپاتا ہے، اس لیے کوئی رکن، رن یا ٹرمینل اسے نہیں لکھ سکتا۔

`hooks.json` پانچ کیز میں سے کسی کو ہک فولڈر کے نسبتی راستے کے ذریعے ایک اسکرپٹ سے جوڑتا ہے:

| کی             | کب چلتا ہے               | اس کے exit code کا مطلب                                        |
| -------------- | ------------------------ | -------------------------------------------------------------- |
| `sessionStart` | ایک بار، رن شروع ہونے پر | کچھ نہیں؛ ہک صرف مشاہدہ کرتا ہے                                |
| `preTool`      | ہر ٹول کال سے پہلے       | `0` کال کی اجازت دیتا ہے؛ کوئی بھی اور اسے مسترد کرتا ہے        |
| `postTool`     | ہر ٹول کال کے بعد        | کچھ نہیں؛ ہک صرف مشاہدہ کرتا ہے                                |
| `stop` | جب ایجنٹ اپنی باری ختم کرنے والا ہو | `2` کے ساتھ stdout پر متن رن کو اسی متن کے ساتھ جاری رکھتا ہے؛ باقی ہر چیز باری کو ختم ہونے دیتی ہے |
| `preCompact` | کمپیکشن سے پہلے | `0`: اس کا stdout اُس میں شامل ہوتا ہے جو خلاصے نے محفوظ رکھنا ہے |

- ہر اسکرپٹ ایک الگ executable کے طور پر شروع ہوتا ہے، بغیر شیل اور بغیر آرگیومنٹس کے، اس لیے اسے executable ہونا اور shebang لائن سے شروع ہونا چاہیے۔ یہ واقعہ stdin پر JSON کے طور پر وصول کرتا ہے: واقعے کا نام، اور ٹول ہکس کے لیے ٹول کا نام اس کے آرگیومنٹس کے ساتھ (`preTool`) یا اس کے نتیجے کے ساتھ (`postTool`)۔
- ہک رن کے ٹول پروسیسز میں سے ایک کے طور پر، رن کے لیے ایجنٹ کی ڈائریکٹری میں چلتا ہے۔ جب سرور ایجنٹس کو سینڈ باکس کرتا ہے تو یہ رن کے سینڈ باکس کے اندر چلتا ہے۔ اسے کم از کم ماحول ملتا ہے اور رن کی کوئی credential نہیں: نہ کوئی forge یا provider ٹوکن، نہ gateway تک رسائی۔
- ہر ہک کو 30 سیکنڈ ملتے ہیں۔ `sessionStart`، `preTool` اور `postTool` کا آؤٹ پٹ پڑھا جاتا ہے اور پھینک دیا جاتا ہے۔
- `preTool` ناکامی پر بند ہوتا ہے۔ non-zero exit، ٹائم آؤٹ، یا وہ اسکرپٹ جو شروع نہ ہو سکے، ٹول کال کو مسترد کرتا ہے۔
- ایسا راستہ جو مطلق ہو، غائب ہو، یا ہک فولڈر سے باہر نکلتا ہو (links resolve ہونے کے بعد)، مسترد کیا جاتا ہے، اور رن کا لاگ بتاتا ہے کہ کون سا ہک اور کیوں مسترد ہوا۔ مسترد یا ناقابلِ پڑھائی `preTool` ہک، درست ہونے تک، ہر ٹول کال کو مسترد کرتا ہے۔
- کسی ریپوزٹری میں، یا ایجنٹ کے اپنے فولڈر میں، `.agents/harness.json` کا `hooks` بلاک نظرانداز کیا جاتا ہے۔ ریپوزٹری اکثر کسی اور کا کوڈ ہوتی ہے، اور ایجنٹ کا فولڈر ممبرز اور رنز دونوں لکھ سکتے ہیں۔ رن کا لاگ بتاتا ہے کہ بلاک نظرانداز ہوا، اور ہکس کہاں سے پڑھے جاتے ہیں۔

### stop اور preCompact ہکس

- `stop` کو `event: "stop"` ملتا ہے، ایجنٹ کا آخری پیغام (`last_message`)، `stop_hook_active` (true جب یہ اسٹاپ ہک کی وجہ سے ہونے والے تسلسل کے بعد آئے) اور `block_count` (اب تک کتنی بار اس نے رن کو جاری رکھا، 0 سے)۔ رن جاری رکھنے کے لیے یہ `2` سے باہر نکلتا ہے اور لکھتا ہے کہ ایجنٹ کو آگے کیا کرنا ہے۔ یہ متن، 2,000 حروف تک کاٹ کر، ایجنٹ کو سسٹم پیغام کے طور پر پہنچتا ہے۔
- ایک `stop` ہک کسی رن کو زیادہ سے زیادہ 3 بار جاری رکھتا ہے۔ اس کے بعد وہ دوبارہ نہیں چلتا، اور باری ختم ہو جاتی ہے۔
- `stop` ناکامی پر کھلا رہتا ہے۔ ٹائم آؤٹ، ایسی اسکرپٹ جو شروع نہ ہو سکے، `2` کے علاوہ کوئی بھی exit، یا stdout پر کچھ نہ ہو اور exit `2` ہو، تو باری ختم ہو جاتی ہے، تاکہ ٹوٹا ہوا ہک رن کو کھلا نہ رکھ سکے۔
- `preCompact` کو `event: "pre_compact"` ملتا ہے۔ اس کا stdout، 1,000 حروف تک کاٹ کر، کمپیکشن کے فوکس میں شامل ہوتا ہے۔ ناکام ہونے والی اسکرپٹ کچھ شامل نہیں کرتی۔

شیل ہکس بلٹ اِن ہارنس پر لاگو ہوتے ہیں۔ Claude Code پر `stop` اور `preCompact` ہکس بھی چلتے ہیں: Claude Code کے اپنے `Stop` اور `PreCompact` ہکس سرور سے پوچھتے ہیں، اور سرور مالک کی اسکرپٹس اسی طرح چلاتا ہے۔ باقی تین کیز صرف بلٹ اِن ہارنس پر لاگو ہوتی ہیں۔ ترتیب شدہ `preTool` یا `postTool` ہک رن کو اپنے ٹولز ایک وقت میں ایک کر کے کال کرواتا ہے۔

## AgentLiveState (اخذ شدہ)

محفوظ نہیں ہوتی۔ سات اقدار۔ اعلان کی ترتیب ہی ترجیح کی ترتیب ہے (`sortPriority`، جو ایک ٹیسٹ نے پن کیا ہوا ہے)، اور روسٹر اسی ترتیب سے چھانٹا جاتا ہے:

| حالت       | `sortPriority` | شرط                                                                                                           |
| ----------- | -------------- | ------------------------------------------------------------------------------------------------------------------- |
| `running`   | 0              | کسی بھی رن لاگ کی اسٹیٹس `running` ہو                                                                                    |
| `blocked`   | 1              | تازہ ترین رن کی فعالیت `blocked`، `stalled` یا `looping` ہو                                                     |
| `failed`    | 2              | تازہ ترین رن کی اسٹیٹس `error` ہو، یا اس کی فعالیت `failed` یا `dead` ہو                                           |
| `queued`    | 3              | رن ڈسپیچ ہو چکا مگر چل نہیں رہا — اُسی ایجنٹ کے کسی دوسرے رن کے پیچھے کھڑا ہے، یا لکھا جا چکا مگر ابھی شروع نہیں ہوا |
| `succeeded` | 4              | رن کامیابی سے مکمل ہوا                                                                                       |
| `idle`      | 5              | ایجنٹ پہلے چل چکا ہے اور اس وقت کچھ بھی پرواز میں نہیں                                                                  |
| `neverRun`  | 6              | کوئی رن لاگ موجود نہیں                                                                                                   |

`queued` اور `succeeded` **صرف فی رن** ہیں۔ `deriveAgentLiveState`، جو کسی ایجنٹ کے لیے روسٹر کی حالت نکالتا ہے، ان میں سے کوئی بھی کبھی پیدا نہیں کرتا — وہ `neverRun`، `running`، `failed`، `blocked` یا `idle` واپس کرتا ہے۔
