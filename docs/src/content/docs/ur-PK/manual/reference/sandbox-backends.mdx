:::caution[رن سینڈ باکس میں چلتا ہے یا نہیں، یہ ہوسٹ پر منحصر ہے]
`cc_server` بوٹ کے وقت ایک بار طے کرتا ہے کہ اس ہوسٹ پر ایجنٹس کیسے چلیں گے، اور یہ فیصلہ دوبارہ اسٹارٹ ہونے تک برقرار رہتا ہے:

- **سینڈ باکس شدہ** (`native`): پروب کو ایک بیک اینڈ ملا اور `--sandbox` `off` نہیں ہے۔ ڈسپیچ کے دونوں سیمز لپیٹے جاتے ہیں: Claude Code CLI سینڈ باکس پورٹ کے ذریعے، اور ACP نیز بلٹ اِن ہارنس کا `bash` ٹول سینڈ باکس مینیجر کے ذریعے۔
- **بند** (`off`): سرور کے مالک نے اسے `--sandbox off` کے ساتھ شروع کیا ہے۔ ہر رکن کا ایجنٹ اس مشین پر بغیر کسی پابندی کے چلتا ہے، چاہے اسے کسی نے بھی شروع کیا ہو۔
- **دستیاب نہیں** (`unavailable`): سینڈ باکس آن ہے مگر پروب کو کوئی بیک اینڈ نہیں ملا (**Windows میں ہمیشہ**، اور وہ Linux یا WSL2 جس میں `bwrap` اور `socat` نہ ہوں)۔ رن صرف تب شروع ہوتا ہے جب اس کا ذمہ دار شخص سرور کا [مالک](/ur-PK/ہدایت-نامہ/تصورات/اجازت/#سرور-کا-مالک) ہو: وہ شخص جس نے اسے مانگا، یا خودکاری کے لیے وہ شخص جس سے وہ بندھی ہو۔ کسی اور کا رن کسی کریڈینشل کے جاری ہونے، لیز لیے جانے یا پروسیس شروع ہونے سے پہلے مسترد ہو جاتا ہے۔ اگر کوئی مالک ریکارڈ نہ ہو تو کسی کا رن شروع نہیں ہوتا۔

مسترد ہونے والا رن کوڈ `sandbox_unavailable` کے ساتھ ناکام ہوتا ہے۔ ایپ اسے **ایجنٹس کو اس سرور پر سینڈ باکس چاہیے** کے طور پر دکھاتی ہے: "اس سرور پر سینڈ باکس نہیں ہے، اس لیے یہاں صرف اس کا مالک ایجنٹس چلا سکتا ہے۔ مالک سینڈ باکس انسٹال کر سکتا ہے یا سب کے لیے سینڈ باکسنگ بند کر سکتا ہے۔"

جو رن بغیر سینڈ باکس کے شروع ہوتا ہے (`off` کے تحت، یا `unavailable` کے تحت مالک کا اپنا رن) وہ براہِ راست ہوسٹ پر چلتا ہے۔ ACP اور ہارنس کا `bash` ٹول پھر بھی ماحول کی صفائی کے ساتھ اسپان ہوتے ہیں؛ Claude Code `NoSandboxAdapter` سے گزرتا ہے اور ہوسٹ کا ماحول ورثے میں پاتا ہے۔ باقی سرحدیں یہ ہیں: خود رن کا worktree (جہاں `rift` جہاز ہوتا ہے وہاں copy-on-write؛ Windows پر `git worktree`)، فی لانچ بروکر کیے جانے والے اور اختتام پر منسوخ کیے جانے والے صرف پڑھنے والے فورج ٹوکن، وہ پش جنہیں ایجنٹ رن گیٹ وے پر پش قاعدے سے گزرنا ہوتا ہے، فی موڈ کمانڈ پالیسی، متحدہ [ایکشن گارڈریلز](/ur-PK/ہدایت-نامہ/تصورات/گارڈریلز/) (fail-closed)، ACP اور ہارنس `bash` پاتھوں پر ماحول کی صفائی، اور وہ ٹول سرفیس جس کی اس کے موڈ کو اجازت ہو۔

ہارنس کے اِن پروسیس فائل ٹولز (read، write، edit، apply patch، search، find، search_files) ہر ہوسٹ پر سینڈ باکس سے باہر ہوتے ہیں: یہ سرور پروسیس میں چلتے ہیں، اس لیے صرف `bash` لپیٹا جاتا ہے۔

ہوسٹ کبھی سینڈ باکس والے سرور کے لیے فال بیک نہیں ہوتا۔ اگر سرور ایجنٹس کو سینڈ باکس کرتا ہے مگر کسی رن کو دینے کے لیے کوئی سینڈ باکس نہیں، تو اس کے ٹول پروسیسز اور `bash` کمانڈز مسترد ہوتے ہیں، ہوسٹ پر شروع نہیں ہوتے۔ وہی اصول رن کے گرد کے چھوٹے پروسیسز بھی طے کرتا ہے: ACP کے ایک بار چلنے والے معاون (گفتگو کے عنوان، `/btw`، `/handoff`، `/goal`) اور Review Studio میں pull request کے golden ٹیسٹس، جب سرور ایجنٹس کو سینڈ باکس کرتا ہو تو سینڈ باکس میں چلتے ہیں، `off` کے تحت بغیر کسی پابندی کے، اور `unavailable` کے تحت صرف اُس درخواست کے لیے جس کا ذمہ دار سرور کا مالک ہو؛ ورنہ وہ چھوڑ دیے جاتے ہیں۔
:::

## بیک اینڈ کا جائزہ

| بیک اینڈ | ویلیو | پلیٹ فارم | دستیابی |
| --------- | ----- | ---------- | -------- |
| بند VM | `microvm` | macOS، Linux، Windows (microVM ہائپر وائزر) | microVM رن ٹائم پر پروب سے مشروط؛ انٹرایکٹو ٹرمنلز پر لاگو ہوتا ہے — شیل ہوسٹ پر نہیں، ایک [رگ](/ur-PK/ہدایت-نامہ/تصورات/رگز/) کے اندر چلتا ہے |
| نیٹو | `native` | macOS (Seatbelt)، Linux اور WSL2 (bubblewrap) | بوٹ پر پروب ہوتا ہے؛ Linux ایسے رن سے انکار کر دیتا ہے جس میں فائل نام گلوب رائٹ انکار درکار ہوں، جنہیں bubblewrap نافذ نہیں کر سکتا |
| None | `none` | سب | پارس کا ڈیفالٹ اور ٹرمنل کا ڈیفالٹ؛ ایجنٹ ڈسپیچ اسے `--sandbox off` کے تحت استعمال کرتا ہے، اور مالک کے اپنے رنز کے لیے جب کوئی بیک اینڈ دستیاب نہ ہو |

`SandboxBackend.fromName` null یا ناقابلِ شناخت محفوظ ویلیو کے لیے `none` واپس کرتا ہے۔

**`microvm` واحد بیک اینڈ ہے جس کی کرنل سرحد ہوتی ہے** — ورک لوڈ واقعی ہوسٹ پر نہیں چلتا۔ یہ کسی بھی سمت خاموش فال بیک نہیں ہوتا: جو ہوسٹ VM بوٹ نہ کر سکے، اس پر اسے واضح طور پر طلب کرنا بلند آواز میں ناکام ہوتا ہے ("میں نے VM مانگا تھا اور مجھے اپنا لیپ ٹاپ مل گیا" ہی وہ واحد گراوٹ ہے جو انکلوژر برداشت نہیں کر سکتا)، اور صرف *غیر متعین ڈیفالٹ* ہی `native` تک نیچے اترتا ہے، اور لاگ کی ایک لائن یہ بتا دیتی ہے۔ سیشن کا حقیقی بیک اینڈ کلائنٹ کو واپس بتایا جاتا ہے اور اس پر بیج دکھایا جاتا ہے، اس لیے کوئی ٹرمنل ہوسٹ پر چلتے ہوئے یہ دعویٰ نہیں کر سکتا کہ وہ انکلوژر میں ہے۔ خود VM کے لائف سائیکل، امیجز اور ایگریس کے لیے [رگز کا حوالہ](/ur-PK/ہدایت-نامہ/حوالہ/رگز/) دیکھیں۔

**Windows میں کوئی نیٹو سینڈ باکس نہیں۔** `NativeSandboxAdapter.probe` ہر ایسے ہوسٹ پر `available: false` واپس کرتا ہے جو macOS یا Linux/WSL2 نہ ہو۔ اس لیے Windows سرور `unavailable` ہوتا ہے: صرف سرور کے مالک کے ایجنٹ رنز شروع ہوتے ہیں، بغیر کسی پابندی کے، اور باقی سب کے مسترد ہوتے ہیں۔ ہر رکن کو وہاں ایجنٹس چلانے کی اجازت دینے کے لیے مالک سرور کو `--sandbox off` کے ساتھ شروع کرتا ہے، جو ان سب کو بغیر کسی پابندی کے چلاتا ہے۔ `microvm` بیک اینڈ الگ ہے: یہ microVM رن ٹائم پر پروب سے مشروط ہے اور انٹرایکٹو ٹرمنلز اور رگز پر لاگو ہوتا ہے، ہوسٹ پر `bash` لپیٹنے پر نہیں۔

## پروب کے نتائج

پروب ہی نافذ کاری کو گیٹ کرتا ہے۔ یہ ایک بار، سرور بوٹ پر چلتا ہے۔

| ہوسٹ | `available` | نوٹ / اشارہ |
| ---- | ----------- | ----------- |
| macOS | `true` | `sandbox-exec` (Seatbelt) — نین اسپیس تنہائی، کوئی کرنل سرحد نہیں |
| `bwrap` اور `socat` والا Linux یا WSL2 | `true` | bubblewrap — نین اسپیس تنہائی، کوئی کرنل سرحد نہیں |
| Linux یا WSL2 جس میں کوئی ایک ٹول بھی غائب ہو | `false` | `requiresInstall: true`، ساتھ انسٹال کا اشارہ جو غائب پیکیجز کے نام بتاتا ہے |
| کوئی بھی دوسرا پلیٹ فارم | `false` | اس پلیٹ فارم پر نیٹو سینڈ باکس پیش نہیں کیا جاتا |

سرور نتیجہ اسٹارٹ اپ کی ایک لائن پر لاگ کرتا ہے: `agent sandbox ON` کے ساتھ نوٹ؛ `no OS-native agent sandbox on this host` کے ساتھ اشارہ، جس میں یہ بھی ہے کہ صرف وہی رن شروع ہوں گے جن کا ذمہ دار سرور کا مالک ہو؛ یا `agent sandbox DISABLED by --sandbox off`۔ اسٹارٹ اپ پر چھپنے والی exposure لائن وہی فیصلہ `sandbox=native`، `sandbox=off` یا `sandbox=unavailable` کے طور پر دکھاتی ہے۔ `GET /healthz` میں سینڈ باکس کا کوئی فیلڈ نہیں ہوتا۔

`--sandbox` / `CC_SERVER_SANDBOX` `on` (ڈیفالٹ) یا `off` قبول کرتا ہے۔ `on` ہر رن کو لپیٹتا ہے جب ہوسٹ کوئی بیک اینڈ پیش کرے، اور جب نہ کرے تو صرف مالک کے رنز کو قبول کرتا ہے۔ `off` ہر رکن کے ایجنٹس کو اس ہوسٹ پر بغیر کسی پابندی کے چلاتا ہے؛ یہ ہر رن کی ترتیب نہیں بلکہ مالک کا سب کے لیے فیصلہ ہے۔

## نیٹو بیک اینڈ

### macOS: Seatbelt

Apple کے Seatbelt سینڈ باکس میکنزم کو استعمال کرتا ہے (وہی نظام جو macOS App Sandbox استعمال کرتا ہے)۔

بنایا گیا پروفائل **ڈیفالٹ کے اعتبار سے اجازت دینے والا** ہوتا ہے (`(allow default)`) اور انکار تراشتا ہے، کیونکہ مکمل ڈیفالٹ سے انکار کرنے والا پروفائل انٹرایکٹو شیل کو ناقابلِ استعمال بنا دیتا ہے — dyld، XPC اور Mach کالز اتنی زیادہ ہیں کہ گنی نہ جائیں۔ عملی نتیجہ یہ ہے کہ ایجنٹ پھر بھی ہوسٹ کا بیشتر حصہ پڑھ سکتا ہے؛ آپ کے رجسٹرڈ چیک آؤٹس واضح رائٹ اور رینیم انکاروں سے محفوظ رہتے ہیں، نہ کہ نظر نہ آنے سے۔

- **فائل سسٹم ریڈز**: خفیہ پاتھوں کے لیے انکار (`~/.ssh`، `~/.aws`، `~/.gnupg`، `~/.config/gh`، `~/Library/Keychains` اور ریڈ سے انکار والا باقی سیٹ)
- **فائل سسٹم رائٹس**: انکار پر ری سیٹ، پھر واضح سب پاتھ اجازتیں، اور لازمی انکار والے پاتھ (شیل rc فائلیں، `.git/hooks`، Claude کنفیگ، محفوظ چیک آؤٹس) کسی رائٹ ایبل روٹ کے اندر بھی بلاک۔ `file-write-unlink` ہر انکار شدہ پاتھ اور اس کے آباؤ اجداد پر انکار ہوتا ہے، اس لیے رینیم کسی رائٹ سے انکار کو بائی پاس نہیں کر سکتا
- **پروسیس**: ہمیشہ خطرناک بائنریز کے لیے `process-exec` انکار، نیز کسی رائٹ ایبل ڈائریکٹری سے کچھ بھی ایگزیکیوٹ کرنے پر پابندی۔ ہوم ڈائریکٹری کے تحت معروف ٹول چین انسٹالیشن ٹری (corepack، npx اور `pnpm dlx` کیشز، node ورژن مینیجرز، Playwright براؤزرز، rustup اور cargo، Go، fvm اور pub کیش، pyenv، uv اور pipx، rbenv، sdkman، mise، asdf اور `~/.local/bin`) اس پابندی کے نیچے دوبارہ کھول دیے جاتے ہیں۔ مشترکہ عارضی ڈائریکٹریز بھی بلاک ہیں۔ اس کے بجائے ہر سیشن کو `/private/tmp` کے تحت ایک نجی `TMPDIR` ملتا ہے، جہاں وہ پروگرام چل سکتے ہیں جو سیشن خود بناتا ہے (ایک `go test` بائنری، ایک cargo build)۔ ہمیشہ خطرناک بائنریز کے انکارات ان اجازتوں کے بعد لاگو ہوتے ہیں
- **نیٹ ورک**: اِن پروسیس پراکسی پورٹس اور DNS تک محدود — loopback کو کلی اجازت نہیں اور TCP لسننگ انکار شدہ ہے۔ Unix سوکٹس صرف سیشن کے نجی `TMPDIR` کے اندر اجازت یافتہ ہیں، جو tsx اور Chrome جیسے ٹولز کا احاطہ کرتی ہیں جو وہاں اپنا IPC سوکٹ رکھتے ہیں؛ آپ کا SSH agent اور دیگر سوکٹس ناقابلِ رسائی رہتے ہیں۔ پراکسیاں فی سیشن ڈومین اجازت فہرست نافذ کرتی ہیں ([نیٹ ورک ایگریس](#نیٹ-ورک-ایگریس) دیکھیں)
- **کنفیگریشن**: پروفائلز ہر لانچ پر `SandboxSpec` سے بنائے جاتے ہیں
- **سرور کے اپنے کمانڈز**: وہ فولڈر جن سے سرور پروگرام چلاتا ہے (`PATH` کا ہر اندراج اور عام فی صارف ٹول فولڈرز، جیسے `~/.local/bin`، جن میں `~/fvm/default` جیسے version-manager لنکس حل ہو کر آتے ہیں) کا کوئی براہِ راست چائلڈ نہ بنایا، بدلا، حذف یا رینیم کیا جا سکتا ہے، اور نہ وہ انسٹال شدہ پیکیج جس کی طرف کوئی لنک شدہ کمانڈ اشارہ کرے۔ دیکھیں [سرور کے کمانڈ فولڈرز](#سرور-کے-کمانڈ-فولڈرز)
- **اسٹارٹ اپ فائلیں**: ہر ہوم پاتھ جسے پروفائل ریڈ سے منع کرتا ہے، رائٹ سے بھی منع ہے، اور سرور صارف کے شیلز اور سیشنز کی اسٹارٹ اپ فائلیں (`.zshenv`، `.zlogin`، `.bash_login`، fish کنفیگ، systemd یوزر یونٹس، autostart اندراجات اور ان جیسی) ہر موڈ میں رائٹ سے منع ہیں

تقاضے:

- `sandbox-exec` (`/usr/bin/sandbox-exec`)، جو ہر macOS انسٹال کا حصہ ہے — کسی اضافی ٹولنگ کی ضرورت نہیں

### Linux: bubblewrap

ماؤنٹ اور PID نین اسپیس بنانے کے لیے bubblewrap (`bwrap`) استعمال کرتا ہے۔

- **فائل سسٹم**: ایسا ماؤنٹ نین اسپیس بناتا ہے جس میں صرف بائنڈ شدہ پاتھ نظر آتے ہیں
- **نیٹ ورک**: اَن شیئرڈ نیٹ ورک نین اسپیس میں چلتا ہے؛ ٹریفک `socat` Unix سوکٹ برجز کے ذریعے ہوسٹ پراکسیوں تک پہنچتی ہے
- **پروسیس**: PID نین اسپیس تنہائی
- **سرور کے اپنے کمانڈز اور اسٹارٹ اپ فائلیں**: macOS جیسی ہی حفاظت، bubblewrap بائنڈز کے طور پر۔ یہ Linux پر ابھی تک تصدیق شدہ نہیں ہیں، اور وہاں کمانڈ فولڈر غائب ہو تو پھر بھی بن سکتا ہے

تقاضے:

- `bubblewrap` اور `socat` انسٹال ہوں (Debian/Ubuntu پر `sudo apt-get install bubblewrap socat`)
- کرنل نین اسپیس سپورٹ (جدید Linux پر معیاری)

Bubblewrap کسی موجودہ پاتھ کو چھپا سکتا ہے، لیکن کسی رائٹ ایبل بائنڈ کے اندر *نئی* `.env`، `*.key` یا `*.pem` فائل کو منع نہیں کر سکتا۔ معیاری ڈسپیچ پالیسی کو ان فائل نام گلوب انکاروں کی ضرورت ہوتی ہے، اس لیے Linux/WSL2 پر نیٹو ایجنٹ ڈسپیچ اس وقت **fail closed ہوتا ہے، چاہے پروب کو bubblewrap مل ہی جائے**۔ یہ خاموشی سے کمزور پالیسی کے ساتھ نہیں چلتا۔ Linux پر نیٹو ڈسپیچ بحال کرنے کے لیے ایسا بیک اینڈ درکار ہے جس میں فائل نام کے قواعد تخلیق کے وقت لاگو ہوں۔ سینڈ باکسنگ بند کرنا ایک واضح غیر محدود آپٹ آؤٹ ہے، کوئی مساوی کام چلاؤ راستہ نہیں۔

عملی طور پر Linux یا WSL2 سرور آج ایجنٹس دو طریقوں میں سے ایک سے چلاتا ہے۔ `--sandbox off` کے ساتھ شروع ہو تو ہر رکن کے ایجنٹس بغیر کسی پابندی کے چلتے ہیں۔ bubblewrap یا `socat` انسٹال نہ ہوں تو یہ `unavailable` ہوتا ہے اور صرف سرور کے مالک کے ایجنٹس بغیر کسی پابندی کے چلاتا ہے۔ دونوں ٹولز انسٹال ہوں اور سینڈ باکس آن ہو تو ہر رن fail closed ہوتا ہے، مالک کا بھی۔

## سرور کے کمانڈ فولڈرز

سرور ایک بار اسٹارٹ پر ہر اُس فولڈر کو تلاش کرتا ہے جس سے وہ پروگرام چلاتا ہے: اس کے `PATH` کا ہر اندراج، فی صارف ٹول فولڈرز جن کی وہ جانچ کرتا ہے (جیسے `~/.local/bin`، `~/.bun/bin` اور npm، yarn اور pnpm کے گلوبل فولڈرز)، اور راستے میں آنے والے ہر لنک کے پیچھے کا اصل فولڈر (`~/fvm/default` یا fnm ڈیفالٹ جیسے version-manager لنکس)۔ سینڈ باکس کے اندر کوئی ایجنٹ ان فولڈرز میں کسی کمانڈ کو شامل، بدل، حذف یا رینیم نہیں کر سکتا، نہ اُس تک جانے والا لنک، نہ وہ انسٹال شدہ پیکیج جس کی طرف لنک شدہ کمانڈ اشارہ کرے، اور نہ ان کے اوپر کے فولڈرز کو رینیم کر سکتا ہے۔ ورنہ ایک سینڈ باکس شدہ رن ایسا پروگرام لگا سکتا ہے جسے سرور یا شخص بعد میں سینڈ باکس سے باہر شروع کرے۔

اس سے ایک رن پر یہ تبدیلیاں آتی ہیں:

- سینڈ باکس شدہ رن کے اندر سے گلوبل انسٹالز "Operation not permitted" کے ساتھ ناکام ہوتے ہیں: `npm i -g`، `pnpm add -g`، `yarn global add`، `bun add -g`، `corepack enable`، `pipx install`، `uv tool install`، اور `cargo install`، `go install` یا `dart pub global activate` جب ان کا bin فولڈر سرور کے `PATH` پر ہو۔
- ڈیفالٹ ورژن بدلنا اسی طرح ناکام ہوتا ہے (`fnm default`، `nvm alias default`، `fvm global`)، جیسے کوئی ٹول اپنے آپ کو اسی جگہ اپ ڈیٹ کرے۔
- پروجیکٹ کے اندر کی انسٹالز (`node_modules/.bin`)، `npx`، `pnpm dlx`، corepack کے ذریعے منظم پیکیج مینیجرز، SDK کیشز اور عام بلڈز پہلے کی طرح کام کرتے رہتے ہیں۔

کسی گلوبل ٹول کو ایجنٹس کے لیے دستیاب کرنے کے لیے، اسے سرور پر خود، سرور کے صارف کے طور پر انسٹال کریں، اور سرور کو دوبارہ اسٹارٹ کریں تاکہ نئی کمانڈ بھی محفوظ ہو۔ یا اسے پروجیکٹ میں انسٹال کریں۔ سرور اسٹارٹ ہونے کے بعد انسٹال ہونے والی کمانڈ صرف اگلے اسٹارٹ سے مکمل طور پر محفوظ ہوتی ہے۔

macOS پر نافذ اور جانچا گیا ہے۔ Linux پر یہی اصول bubblewrap بائنڈز ہیں جو ابھی تصدیق شدہ نہیں ہیں۔ Windows میں کوئی سینڈ باکس نہیں ہے۔

## None بیک اینڈ

کوئی سینڈ باکسنگ نہیں۔ پروسیس براہِ راست ہوسٹ پر چلتا ہے، ہوسٹ کے فائل سسٹم، نیٹ ورک اور پروسیس تک رسائی کے ساتھ۔ ACP اور ہارنس کے `bash` ٹول کو پھر بھی ماحول کی صفائی اور کمانڈ پالیسی ملتی ہے؛ `NoSandboxAdapter` کے ذریعے Claude Code ہوسٹ کا ماحول ورثے میں پاتا ہے۔ ایجنٹ ڈسپیچ اسے ہر رن کے لیے `--sandbox off` کے تحت استعمال کرتا ہے، اور ایسے ہوسٹ پر جہاں کوئی بیک اینڈ دستیاب نہ ہو صرف سرور کے مالک کے اپنے رنز کے لیے؛ کسی اور کا رن وہاں مسترد ہوتا ہے۔ ٹرمنل کے لیے یہ ہوسٹ شیل ہے، جسے صرف سرور کا مالک کھول سکتا ہے۔

## سرور-ہوسٹڈ ٹرمنل

سرور پر ہوسٹ ٹرمنل صرف سرور کے [مالک](/ur-PK/ہدایت-نامہ/تصورات/اجازت/#سرور-کا-مالک) کے لیے ہوسٹ شیل کھولتا ہے۔ باقی سب کو ورک اسپیس کی اپنی ڈائریکٹریز میں، ایجنٹ کی حدوں کے ساتھ، سینڈ باکس شدہ ٹرمنل ملتا ہے۔

سیشن کے لیے بیک اینڈ اس طرح چنا جاتا ہے:

| مانگا گیا | سرور کا مالک | باقی سب |
| --- | --- | --- |
| کچھ نہیں | سرور کا ڈیفالٹ بیک اینڈ | ڈیفالٹ، جس میں `none` کی جگہ `native` ہوتا ہے |
| `none` (ہوسٹ شیل) | ہوسٹ شیل | مسترد: ہوسٹ شیل سرور پر بغیر سینڈ باکس کے چلتا ہے |
| `native` | نیٹو سینڈ باکس، مالک کی پروفائل | نیٹو سینڈ باکس، ایجنٹ کی پروفائل |
| `microvm` | بند VM | بند VM |
| نامعلوم نام | مسترد | مسترد |

- **مالک کی پروفائل۔** `$HOME` اور سیشن کی ورکنگ ڈائریکٹری رائٹ ایبل ہیں، نیٹ ورک کھلا ہے، اور `~/.ssh`، `~/.aws`، `~/.gnupg`، `~/.config/gh` اور `~/Library/Keychains` ریڈ سے منع ہیں۔
- **ایجنٹ کی پروفائل** (`memberTerminalSandboxConfig`)۔ وہی پالیسی جس کے تحت اس ورک اسپیس کا ایجنٹ چلتا ہے: رائٹ ورکنگ ڈائریکٹری، ایک نجی رن ڈائریکٹری، `/tmp` اور `$HOME` کے وہ حصے جن میں ایجنٹ لکھ سکتا ہے، تک محدود ہے؛ خفیہ فائلیں ریڈ سے منع ہیں؛ نیٹ ورک ایجنٹ کی egress اجازت فہرست ہے؛ پروگرام صرف ورکنگ ڈائریکٹری اور انسٹال شدہ ٹول چینز سے چلتے ہیں۔
- ٹرمنل صرف ورک اسپیس کی اپنی ڈائریکٹریز کے اندر کھلتا ہے۔ ان سے باہر کی ورکنگ ڈائریکٹری مسترد ہوتی ہے، کبھی کسی اور سے بدلی نہیں جاتی۔
- ٹرمنل کو صرف وہ شخص پڑھ، اس میں ٹائپ، اس کا سائز بدل یا اسے بند کر سکتا ہے جس نے اسے کھولا۔ کسی اور کے لیے اس کا id نامعلوم دکھائی دیتا ہے۔
- کسی رگ سروس کے بغیر ہوسٹ پر `microvm` واضح طور پر مانگا جائے تو وہ ناکام ہوتا ہے، بجائے اس کے کہ کسی اور بیک اینڈ پر چلے۔ ایسے ہوسٹ پر `microvm` کا ڈیفالٹ `native` پر اتر آتا ہے اور لاگ میں یہ بتایا جاتا ہے۔

ٹرمنل کے لیے صرف پڑھنے والا فورج ٹوکن اور پش گیٹ وے لاگو نہیں ہوتے: وہ ڈسپیچ کے معاملات ہیں۔ اگر لپیٹنے کی سپورٹ نہ ہو تو سیشن ناکام ہوتا ہے، بجائے اس کے کہ ہوسٹ شیل والے سیشن پر سینڈ باکس کا بیج دکھائے۔

## نیٹ ورک ایگریس

جب کوئی سینڈ باکس لانچ ہوتا ہے تو آؤٹ باؤنڈ نیٹ ورک رسائی اِن پروسیس پراکسیوں سے نافذ ہوتی ہے، کرنل فائر وال قواعد سے نہیں۔ جو رن سینڈ باکس شدہ نہیں (`--sandbox off` کے تحت ہر رن، یا کسی بیک اینڈ کے بغیر ہوسٹ پر مالک کا رن) اسے ان میں سے کچھ بھی نہیں ملتا: اس کا اسپان کردہ پروسیس نیٹ ورک تک بالکل اسی طرح پہنچتا ہے جیسے سرور صارف پہنچتا۔

- سینڈ باکس رن ٹائم `cc_server` پروسیس کے اندر `127.0.0.1` پر ایک HTTP/HTTPS پراکسی اور ایک SOCKS5 پراکسی چلاتا ہے، **ہر محدود سیشن کے لیے ایک جوڑا** (`http_proxy.dart`، `socks_proxy.dart`)۔ بیک وقت چلنے والے رنز ایک جوڑا شیئر نہیں کرتے۔
- سینڈ باکس شدہ پروسیسز کو پراکسی ماحول متغیرات ملتے ہیں (`HTTP_PROXY`/`HTTPS_PROXY` → HTTP پراکسی، `ALL_PROXY` → SOCKS پراکسی؛ `GIT_SSH_COMMAND` git-over-SSH کو SOCKS پراکسی سے گزارتا ہے)۔ Linux پر نیٹ ورک نین اسپیس اَن شیئرڈ ہوتا ہے، اس لیے باہر نکلنے کا واحد راستہ پراکسیاں ہی ہیں؛ macOS پر سینڈ باکس ہوسٹ loopback شیئر کرتا ہے اور ان سے براہِ راست بات کرتا ہے۔
- ہر کنکشن کے ٹارگٹ ہوسٹ کو سیشن کی ڈومین اجازت فہرست سے میچ کیا جاتا ہے؛ باقی سب کچھ مسترد ہو جاتا ہے۔ وائلڈ کارڈ کی دو صورتیں، ہر ایک میں بالکل ایک `*`: شروع والا `*.example.com` کسی بھی سب ڈومین سے میچ کرتا ہے (`a.b.example.com` سمیت) لیکن خود apex سے نہیں؛ درمیانی لیبل والا `bedrock.*.amazonaws.com` بالکل ایک لیبل سے میچ کرتا ہے (`bedrock.us-east-1.amazonaws.com`، نہ کہ `bedrock.evil.attacker.amazonaws.com`)۔
- اجازت فہرست فی سیشن منتخب بیس لائن (`kBaselineAllowedDomains`: LLM فراہم کنندگان، Git ہوسٹنگ، پیکیج رجسٹریاں) سے حل ہوتی ہے، نیز GitHub ڈومینز (`kGithubDomains`)، نیز `SandboxSpec.egressAllowlist`۔ ڈسپیچ پاتھ اضافی `egressAllowlist` اندراجات کبھی نہیں بھیجتا، اس لیے عملاً ہر رن کو بیس لائن کے ساتھ GitHub ملتا ہے۔
- ایک مقررہ انکار فہرست (`kBaselineDeniedDomains`: کلاؤڈ میٹاڈیٹا اینڈپوائنٹس، ٹیلی میٹری سنکس) تمام اجازتوں پر غالب آتی ہے۔
- `networkEnabled: false` پھر بھی فی سیشن پراکسیاں شروع کرتا ہے، مگر اجازت فہرست خالی ہوتی ہے، اس لیے ہر آؤٹ باؤنڈ کنکشن مسترد ہو جاتا ہے۔ ڈسپیچ رن کے آغاز پر یہ قدر **نیٹ ورک تک رسائی** قاعدے سے مقرر کرتا ہے: منع کرنا نیٹ ورک بند کرتا ہے، اجازت اور پہلے پوچھیں اسے آن رکھتے ہیں۔

## SandboxSpec

`SandboxPort.launch` کو دی جانے والی اسپیسفیکیشن:

| فیلڈ | قسم | تفصیل |
| ---- | --- | ----- |
| `sessionId` | `String` | مستحکم سیشن شناخت کنندہ (عموماً اسپیس آئی ڈی) |
| `workspaceId` | `String` | مالک ورک اسپیس آئی ڈی |
| `agentId` | `String?` | فی الحال سینڈ باکس سے منسلک ایجنٹ، اگر کوئی ہو |
| `bindMounts` | `List<SandboxBindMount>` | ہوسٹ→گیسٹ ماؤنٹس؛ سینڈ باکس صرف وہی ہوسٹ پاتھ دیکھتا ہے جو یہاں درج ہوں |
| `networkEnabled` | `bool` (ڈیفالٹ `true`) | ڈسپیچ کے وقت نیٹ ورک ایگریس قاعدے سے مقرر ہوتا ہے (صرف منع پر حل ہونے کی صورت میں بند)۔ بند ہونے پر فی سیشن پراکسیاں پھر بھی شروع ہوتی ہیں مگر اجازت فہرست خالی ہوتی ہے، اس لیے ہر آؤٹ باؤنڈ کنکشن مسترد ہوتا ہے |
| `egressAllowlist` | `List<String>` (ڈیفالٹ `[]`) | اضافی اجازت یافتہ ایگریس ڈومینز؛ وائلڈ کارڈز کی سپورٹ (`*.example.com`، نیز درمیانی ایک لیبل والی صورت)۔ ڈسپیچ اسے کبھی نہیں بھرتا، اس لیے لپیٹا گیا رن منتخب بیس لائن کے ساتھ GitHub ڈومینز پاتا ہے |
| `guestWorkdir` | `String?` | سینڈ باکس کے اندر ڈیفالٹ ورکنگ ڈائریکٹری؛ انفرادی `exec` کالز اسے اوور رائیڈ کر سکتی ہیں |
| `mode` | `Mode` (ڈیفالٹ `chat`) | فائل سسٹم کے رائٹ قواعد تراشتا ہے: `chat` بائنڈ ماؤنٹس کو رائٹ ایبل رکھتا ہے؛ `review`، `plan` اور `orchestrate` ریڈ-اونلی ہیں |
| `protectedPaths` | `List<String>` (ڈیفالٹ `[]`) | ایسے ہوسٹ پاتھ جو کسی بھی موڈ میں سینڈ باکس کے اندر کبھی رائٹ ایبل نہ ہوں |
| `runnerStateDirs` | `List<String>` (ڈیفالٹ `[]`) | ایسی ہوسٹ ڈائریکٹریاں جن میں رنر اپنی اسٹیٹ رکھتا ہے، ہر موڈ میں رائٹ ایبل (Control Center کے زیرِ انتظام `CLAUDE_CONFIG_DIR` اس وقت کی واحد ہے) |
| `execGrantRoots` | `List<String>` (ڈیفالٹ `[]`) | آپریٹر سے منظور شدہ ڈائریکٹری درخت جو macOS پر رائٹ ایبل ڈائری والا exec بلاک دوبارہ کھول دیتے ہیں۔ Linux انہیں نظر انداز کرتا ہے — bwrap میں دوبارہ کھولنے کے لیے کوئی `$HOME` exec بلاک ہی نہیں |

`protectedPaths` اصل رجسٹرڈ ریپو چیک آؤٹس رکھتا ہے، جو فی ڈسپیچ ورک اسپیس کے ریپوز سے حل ہوتے ہیں۔ ایجنٹس صرف فی گفتگو copy-on-write worktrees میں کام کرتے ہیں، اس لیے اصل کاپیاں سینڈ باکس کے اندر سے کبھی رائٹ ایبل نہیں ہونی چاہئیں — ورنہ macOS پر Seatbelt کی `$HOME` کو دی جانے والی عام رائٹ اجازت انہیں `bash` کے ذریعے رائٹ ایبل چھوڑ دیتی۔ یہ ہر موڈ میں، `chat` سمیت، خفیہ پاتھوں کے رائٹ سے انکار والے سیٹ میں شامل ہو جاتے ہیں۔

ہر deny-read اور deny-write پاتھ اپنی لفظی اور symlink سے حل شدہ دونوں ہجوں میں خارج ہوتا ہے۔ کرنل انکار کے اصول کو resolved پاتھ کے مقابلے میں میچ کرتا ہے، اس لیے symlink والے پاتھ کے خلاف لکھا گیا اصول کبھی فعال نہیں ہوتا — اور macOS پر یہ غیر معمولی کے بجائے عام صورت ہے، کیونکہ `/tmp` حل ہو کر `/private/tmp` بنتا ہے اور `/var/folders/…` حل ہو کر `/private/var/folders/…`۔ جن اندراجات میں `*` یا `?` ہو انہیں گلوب سمجھا جاتا ہے اور چھوڑ دیا جاتا ہے؛ جو پاتھ حل نہ ہو اسے جیسا لکھا گیا ہے ویسا ہی رکھا جاتا ہے۔

## SandboxBindMount

| فیلڈ | قسم | تفصیل |
| ---- | --- | ----- |
| `hostPath` | `String` | ہوسٹ پر مطلق پاتھ |
| `guestPath` | `String` | سینڈ باکس کے اندر پاتھ (نیٹو سینڈ باکس کے ساتھ یہ `hostPath` کے برابر ہوتا ہے؛ اڈاپٹر کی ہم شکلی کے لیے رکھا گیا ہے) |
| `readOnly` | `bool` (ڈیفالٹ `false`) | true ہونے پر ریڈ-اونلی ماؤنٹ |

## SandboxHandle

`SandboxPort.launch` سے واپس ملتا ہے:

| فیلڈ | قسم | تفصیل |
| ---- | --- | ----- |
| `sessionId` | `String` | سیشن شناخت کنندہ |
| `backend` | `SandboxBackend` | کون سا بیک اینڈ چل رہا ہے |
| `state` | `SandboxState` | لائف سائیکل حالت |
| `error` | `Object?` | جب `state` کی ویلیو `error` ہو تو مقرر ہوتا ہے |
| `details` | `Map<String, Object?>` | اڈاپٹر کا نجی حساب کتاب (ورکنگ ڈائریکٹری، PID، پروفائل پاتھ وغیرہ) |

### SandboxState

| حالت | تفصیل |
| ---- | ----- |
| `created` | اسپیک بن گئی مگر VM ابھی شروع نہیں ہوئی |
| `warm` | چل رہا ہے اور کمانڈز ایگزیکیوٹ کرنے کے لیے تیار |
| `active` | اس وقت کوئی کمانڈ ایگزیکیوٹ ہو رہی ہے |
| `suspended` | RAM بچانے کے لیے روکا گیا / ڈسک پر چیک پوائنٹ شدہ |
| `destroyed` | ختم کر دیا گیا؛ ہینڈل اب درست نہیں |
| `error` | لانچ ناکام — `SandboxHandle.error` دیکھیں |

## سینڈ باکس ایونٹس

| ایونٹ کی قسم | تفصیل |
| ------------ | ----- |
| `stdout` | سینڈ باکس سے معیاری آؤٹ پٹ |
| `stderr` | سینڈ باکس سے معیاری ایرر |
| `exit` | سینڈ باکس پروسیس ختم ہو گیا (`exitCode` ساتھ لاتا ہے) |
