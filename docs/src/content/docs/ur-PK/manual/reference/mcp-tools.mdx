`cc_server` ایک ہی MCP (JSON-RPC 2.0) ٹول رجسٹری رکھتا ہے، جو مرکزی سرور پورٹ (ڈیفالٹ `9030`) پر `POST /mcp` اور `GET /sse` کے ذریعے پیش کی جاتی ہے، پروٹوکول ورژن `2024-11-05`۔ ہر کلائنٹ اِسی ایک رجسٹری تک پہنچتا ہے: ڈیسک ٹاپ، ویب بلڈ، بیرونی MCP کلائنٹس اور بلٹ اِن ایجنٹ رن ٹائم۔ بیرونی MCP سرورز کو ایک ڈائنامک تہہ کے طور پر اِسی رجسٹری میں پل بنایا جا سکتا ہے۔

## رجسٹری کا حجم

| پیمائش                                                                   | تعداد |
| ------------------------------------------------------------------------- | ----- |
| `cc_server` کی رجسٹر کردہ ٹولز                                           | 110   |
| `packages/cc_mcp` سے                                                     | 108   |
| `packages/cc_mcp_client` سے (ٹول ڈسکوری)                                 | 2     |
| بیس رجسٹری میں رجسٹر شدہ (`server_mcp_registry.dart`)                     | 63    |
| بوٹ کے بعد، سروسز کے آنے پر رجسٹر شدہ (`cc_server_runtime.dart`)          | 47    |
| بیس رجسٹری کے 63 میں سے، کوڈ گراف ریپوزٹری پر مشروط                        | 5     |

پانچ کوڈ گراف ٹولز صرف اُس وقت رجسٹر ہوتے ہیں جب ہوسٹ `buildServerMcpRegistry` کو کوئی کوڈ گراف ریپوزٹری دے۔ `cc_server` ہمیشہ ایک دیتا ہے، اس لیے بھیجے گئے بائنری میں سب 110 زندہ ہوتے ہیں۔

پوری رجسٹری `tools/list` میں بغیر کسی ڈسکوری گیٹنگ کے ظاہر کی جاتی ہے۔ ٹکٹ میں ترمیم ٹائپ شدہ ٹولز سے ہوتی ہے۔

:::note[بیرونی کلائنٹس ہمیشہ پورا کیٹلاگ دیکھتے ہیں]
`tools/list` کبھی تراشا نہیں جاتا۔ MCP کلائنٹس ٹول کے نام اُسی فہرست کی اپنی کیشڈ نقل کے خلاف جانچتے ہیں اور سرور سے پوچھے بغیر ہر غیر درج نام سے انکار کر دیتے ہیں، چنانچہ وہاں چھپایا گیا ٹول محض خاموش نہیں بلکہ ناقابلِ رسائی ہوتا ہے۔

**بلٹ اِن ہارنس** مختلف ہے: یہ فی درخواست صرف تعریفوں کا ایک مقیم ذیلی مجموعہ لوڈ کرتا ہے اور باقی پہلی استعمال پر کھینچ لاتا ہے، جو ہارنس کی طرف کا رویہ ہے اور اِس رجسٹری کو نہیں بدلتا۔ دیکھیں [ٹول کانٹیکسٹ اور پرامپٹ کیشنگ](/ur-PK/ہدایت-نامہ/تصورات/ٹول-کانٹیکسٹ)۔
:::

:::note[ہر ٹول کلاس رجسٹر ہوتی ہے]
`packages/cc_mcp/lib/src/tools/` کے نیچے موجود سورس فائل وہ ٹول ہے جسے ایجنٹ
کال کر سکتا ہے۔ `packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart`
بلڈ کو ناکام کر دیتا ہے اگر کوئی نئی ٹول کلاس کسی چیز سے تعمیر نہ ہو رہی ہو۔
:::

## مشترک پیرامیٹرز

### `workspace_id`

**لازمی** ہر اُس ٹول پر جو ورک اسپیس اسکوپ والا ڈیٹا چھوتا ہے۔ `workspace_id` غائب ہو یا غلط ہو تو واضح خرابی واپس آتی ہے، اور ایسی قدر جو ہدف ہستی کے ورک اسپیس سے میل نہ کھائے، خاموشی سے نظر انداز ہونے کے بجائے مسترد کر دی جاتی ہے۔ حقیقی طور پر گلوبل ٹولز پر اِسے چھوڑ دیں: `list_workspaces` اور چھ نیوز فیڈ ٹولز (`list_feeds`، `list_articles`، `get_article`، `set_article_read`، `set_article_saved`، `refresh_feeds`)، جو سرور کے مالک کی فی صارف فیڈ فہرست پر سوار ہوتے ہیں۔ ڈسکوری ٹولز (`search_tool_bm25`، `list_my_tools`) اِسے اختیاری طور پر لیتے ہیں تاکہ وہ گفتگو کے موڈ کے لحاظ سے قابلِ کال ہونے کی درجہ بندی کر سکیں۔ جب سرور کسی ایجنٹ کو ڈسپیچ کرتا ہے تو ورک اسپیس سرور کی طرف سے مسلط کر دیا جاتا ہے، اس لیے ایجنٹ کوئی بیرونی id دے کر کسی دوسرے ورک اسپیس تک نہیں پہنچ سکتا۔

## ٹول ڈسکوری

دونوں `cc_mcp` سے نہیں بلکہ `cc_mcp_client` سے آتے ہیں اور دونوں موڈ گارڈ سے رجوع کرتے ہیں، اس لیے وہ بتاتے ہیں کہ _موجودہ_ گفتگو کے موڈ میں کیا کال کرنا ممکن ہے۔

| ٹول                | تفصیل                                                                                                                      |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `search_tool_bm25` | ٹول کیٹلاگ میں کلیدی لفظ سے تلاش کریں؛ مماثل ٹولز، اُن کے آرگومنٹ اسکیما اور یہ کہ ہر ایک اس وقت قابلِ کال ہے یا نہیں، واپس کرتا ہے |
| `list_my_tools`    | اس گفتگو میں اس وقت قابلِ کال ٹولز کی فہرست دیں، جو اُس کے موڈ سے فلٹر شدہ ہو                                                |

تیسرا ڈسکوری ٹول، **`search_tools`**، صرف بلٹ اِن ہارنس کے اندر موجود ہے اور اِس MCP رجسٹری کا حصہ نہیں۔ یہ رن کی اپنی ٹول سطح کی درجہ بندی کرتا ہے اور `search_tool_bm25` کے برعکس جو کچھ ملے اُس کے اسکیما **لوڈ** کر لیتا ہے تاکہ ایجنٹ اپنی اگلی باری میں کسی مماثل ٹول کو کال کر سکے۔ ہارنس پر چلنے والے ایجنٹس کو اِسی کو ترجیح دینی چاہیے؛ MCP کلائنٹس کے پاس `search_tool_bm25` ہے۔

## ایجنٹس کے درمیان پیغام رسانی اور تفویض

ایجنٹس اسپیسز کے ذریعے ایک دوسرے سے بات کرتے ہیں (پائیدار، روسٹر پر نظر آنے والے)۔ `ask_agent` درخواست/جواب ہے جس کی ٹائم آؤٹ لازمی ہے؛ `delegate_task` سرور کی طرف سے گہرائی کی حد، چکر کی شناخت، بجٹ لفافے اور خود مختاری کی چھت سے محفوظ کیا جاتا ہے۔

| ٹول             | تفصیل                                                                                          |
| --------------- | ---------------------------------------------------------------------------------------------- |
| `send_to_agent` | کسی دوسرے ایجنٹ کو یک طرفہ پیغام بھیجیں، جسے `to_agent_id` یا بالکل درست `to_agent_name` سے مخاطب کیا گیا ہو |
| `ask_agent`     | کسی دوسرے ایجنٹ سے سوال پوچھیں اور اس کا جواب یا ٹائم آؤٹ کا انتظار کریں                        |
| `delegate_task` | کسی کام کو ٹریک ہونے والے ذیلی ٹکٹ کے طور پر دوسرے ایجنٹ کو تفویض کریں                          |
| `consult_agent` | مہارتوں کے لحاظ سے بہترین مماثل ماہر کو اسپیس میں شامل کریں اور اسے ایک مرکوز بریف کے ساتھ ڈسپیچ کریں |
| `todo_read`     | اس گفتگو کی محفوظ شدہ ٹاسک چیک لسٹ پڑھیں                                                        |

| ٹول                  | تفصیل                                                                      |
| -------------------- | ------------------------------------------------------------------------- |
| `list_skills`        | کسی ورک اسپیس میں دستیاب مہارت کے سلگس کی فہرست دیں                        |
| `create_skill`       | مارک ڈاؤن مواد سے ایک نئی مہارت بنائیں                                     |
| `install_skill`      | کسی مہارت کی پوری ڈائریکٹری کسی GitHub ریپوزٹری سے پن شدہ ref پر انسٹال کریں |
| `update_skill`       | انسٹال شدہ GitHub مہارت کو نئے ref پر اپ ڈیٹ کریں، دوبارہ اسکین اور دوبارہ پن کرتے ہوئے |
| `list_skill_updates` | ایسی مہارتوں کی فہرست دیں جن کا نیا ورژن دستیاب ہو                          |
| `verify_skills`      | لاک شدہ مہارتوں کو ڈسک پر موجود مواد کے ہیشز کے خلاف جانچیں                 |

## انکلوژر (رگ) ٹولز

رن کے اندر سے ضائع ہونے والی مشینیں چلائیں — ایک انکلوژر براؤزر یا Linux
ڈیسک ٹاپ، ایک Android ایمولیٹر یا ایک iOS سمیولیٹر۔ بوٹ کے بعد، بغیر کسی شرط
کے رجسٹر ہوتے ہیں: کوئی مشین واقعی بوٹ ہو سکتی ہے یا نہیں، یہ ایک پروب سوال ہے
جس کا جواب ٹولز فی کال دیتے ہیں۔ ایک گفتگو میں دہرائی گئی کالیں ایک ہی مشین
دوبارہ استعمال کرتی ہیں؛ اسکرین شاٹس تصویری مواد کے طور پر واپس آتے ہیں جس میں
فی نتیجہ ایک تصویر کا بجٹ ہوتا ہے، اور نکالا گیا صفحہ/UI مواد ناقابلِ اعتماد
ڈیٹا کے طور پر باڑ میں بند کر دیا جاتا ہے۔ چار یوز ٹولز کے ساتھ `rig_close` بھی
`enclosureControl` [ایکشن کلاس](/ur-PK/ہدایت-نامہ/تصورات/گارڈریلز/) کا اعلان کرتے
ہیں (یوز ٹولز `networkEgress` اور `processSpawn` بھی بتاتے ہیں؛ `mobile_use` اور
`ios_use` `packageInstall` بھی بتاتے ہیں)، اس لیے صرف پڑھنے والے موڈز اُن سے انکار
کر دیتے ہیں۔ `rig_list` کوئی اعلان نہیں کرتا — وہ صرف ورک اسپیس کی حالت پڑھتا ہے۔
فی سطح فعل کی مکمل ذخیرہ الفاظ
[رگز حوالہ](/ur-PK/ہدایت-نامہ/حوالہ/رگز/#action-verbs) میں ہے۔

| ٹول            | تفصیل                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------ |
| `computer_use` | انکلوژر VM میں Linux ڈیسک ٹاپ چلائیں: حرکت، کلک، ڈریگ، اسکرول، ٹائپ، ری سائز، کلپ بورڈ، اسکرین شاٹ |
| `browser_use`  | ہیڈلیس Chromium، Firefox یا WebKit چلائیں (`engine`): نیویگیٹ، کلک، فل، ایکسٹریکٹ (a11y/DOM/console)، کلپ بورڈ، اسکرین شاٹ |
| `mobile_use`   | ADB کے ذریعے Android چلائیں: معائنہ/اِن پٹ، اسکرین شاٹس، ایپس کی انسٹال/شروع/روکیں/ری سیٹ/اَن انسٹال، ڈیپ لنکس اور argv کی شکل والی ڈیوائس کمانڈز |
| `ios_use`      | WebDriverAgent/CoreSimulator کے ذریعے iOS سمیولیٹر چلائیں: معائنہ/اِن پٹ، اسکرین شاٹس، ایپس کی انسٹال/شروع/روکیں/اَن انسٹال، ڈیپ لنکس اور argv کی شکل والے سمیولیٹر پراسیس |
| `rig_list`     | کسی ورک اسپیس کے رگز سطح، حیثیت، ڈسپلے سائز اور کنٹرولر کے ساتھ درج کریں |
| `rig_close`    | ایک رگ کو تباہ کریں اور اس کی ملکیت والی مشین کی حالت ضائع کر دیں |

## جو MCP پر پیش نہیں کیے جاتے

کیلنڈر اور میٹنگز کے پاس کوئی MCP ٹول نہیں۔ ایجنٹس آپ کا کیلنڈر، میٹنگز، ٹرانسکرپٹس، ایکشن آئٹمز یا فیصلے نہیں پڑھ سکتے۔ وہ خلاصہ جو ایکشن آئٹمز اور فیصلے پیدا کرتا ہے، بلٹ اِن [`meeting_summary` پائپ لائن](/ur-PK/ہدایت-نامہ/تصورات/میٹنگز/) کے طور پر چلتا ہے، نہ کہ کسی ایسے ٹول کے طور پر جسے ایجنٹ کال کر سکے۔

## موڈ کے لحاظ سے ٹول گیٹنگ

گیٹنگ ایک ہی ٹیبل (`ModeToolPolicy`) سے دو بار نافذ کی جاتی ہے: ایک بار Claude Code اڈاپٹر کے MCP ڈسپیچر میں اور ایک بار بلٹ اِن ہارنس رجسٹری میں۔ روکی گئی کال وجہ واپس کرتی ہے۔

| موڈ           | ٹول سطح                                                                                                                                                                                                                             |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`        | ہر رجسٹر شدہ ٹول؛ کوئی اجازت فہرست نہیں                                                                                                                                                                                              |
| `plan`        | ایک چنی ہوئی اجازت فہرست۔ worktree میں کوئی تحریر نہیں اور نہ `create` / `assign` / `delegate` ٹکٹ فعل، مگر میموری، آرٹی فیکٹس، ٹوڈوز، `submit_plan`، `exit_plan_mode` اور ڈسپیچ شدہ ٹکٹ پر ٹکٹ مکمل کرنے والے فعل کی اجازت ہے |
| `review`      | ایک چنی ہوئی اجازت فہرست: ریویو میں شرکت، مواصلات، صرف پڑھنے والے کانٹیکسٹ حاصل کرنے والے اور ٹکٹ فعل کا پورا مجموعہ، بشمول `create_ticket` اور `assign_ticket`                                                                       |
| `orchestrate` | ایک چنی ہوئی اجازت فہرست: تحقیق اور پڑھنے کے ٹولز نیز `propose_orchestration`، `create_playbook` اور `run_playbook`۔ بھرتیاں، تجزیہ اور ٹکٹ کی تکمیل منظوری کے بعد متعیّن انداز میں ہوتی ہیں، کبھی رن کے دوران نہیں                |

ہر موڈ میں اجازت یافتہ، اجازت فہرست سے قطع نظر:

| مجموعہ               | ٹولز                                                                                                                                                                                                                                                             |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| میموری اور آرٹی فیکٹس | `search_memory`، `propose_fact`، `propose_policy`، `supersede_fact`، `supersede_policy`، `record_observation`، `update_my_notes`، `get_my_notes`، `list_memory_domains`، `list_policies`، `publish_artifact`، `revise_artifact`، `list_artifacts`، `get_artifact` |
| کوڈ گراف             | `search_code`، `code_symbol`، `code_callers`، `code_callees`، `code_impact`                                                                                                                                                                                       |
| رن میکینکس           | `search_tool_bm25`، `list_my_tools`، `todo_write`، `todo_read`                                                                                                                                                                                                    |

کسی اجازت فہرست میں ہونا کسی ٹول کو قابلِ کال نہیں بنا دیتا، اور اُلٹا بھی سچ ہے: آپریٹر سے سوال کرنے کی صلاحیت ایک **ہارنس** ٹول (`ask_user`) ہے، اس لیے یہ اِس MCP کیٹلاگ میں سرے سے کبھی ظاہر نہیں ہوتی۔

## منظوری گیٹ والے ٹولز

کوئی ٹول `requiresApproval` کا اعلان کر سکتا ہے۔ پھر ڈسپیچر ٹول چلنے سے پہلے ایک `ApprovalPayload` بناتا ہے اور اسے `ConfirmationPort` کے ذریعے سامنے لاتا ہے؛ `cc_server` اُس پورٹ کو وائر کرتا ہے، اس لیے گیٹ فعال ہے۔

اِس کا اعلان کرنے والے رجسٹر شدہ ٹولز: `create_ticket`، `update_ticket`، `assign_ticket`، `reassign_ticket`، `close_ticket`، `ticket_relation`، `create_goal`، `update_goal_progress`، `create_approval`، `decide_approval`، `comment_approval`، `create_work_product`، `save_work_product_revision`، `create_runtime_profile`، `install_skill`، `update_skill`۔

اِس سے الگ، متحد ایکشن گارڈریلز ہر اُس ٹول کو گیٹ کرتے ہیں جو خالی نہ ہونے والا `ActionClass` مجموعہ بتائے۔ کوئی `prompt` فیصلہ جس کے ساتھ کوئی منظور کنندہ جڑا نہ ہو، مسترد کر دیا جاتا ہے۔ دیکھیں [گارڈریلز](/ur-PK/ہدایت-نامہ/تصورات/گارڈریلز/)۔

## وہ صلاحیتیں جن کے پیچھے کوئی ٹول نہیں

پروڈکٹ کی ہر صلاحیت ایجنٹ کی پہنچ میں نہیں۔ اِن کے پیچھے سرے سے کوئی ٹول
نہیں، اس لیے کوئی ایسا نام جس کا حوالہ آپ نے کہیں اور دیکھا ہو، "unknown tool" واپس کرتا ہے:

| صلاحیت                                  | یہ بجائے اس کے کہاں رہتی ہے                                                                      |
| -------------------------------------- | -------------------------------------------------------------------------------------------- |
| ایجنٹ کی بھرتی، برطرفی یا ترمیم          | ایجنٹس UI۔ کوئی `hire_agent` / `fire_agent` / `update_agent` ٹول نہیں ہے                      |
| ورک اسپیس بنانا                          | RPC پر `workspace.upsert`، جو سیڈ کرتا اور ملکیت کی مہر لگاتا ہے                                 |
| پروجیکٹس (بنانا / فہرست / اپ ڈیٹ / فائل کرنا) | ٹکٹس UI۔ پروجیکٹس ایک آپریٹر سطح ہیں — دیکھیں [پروجیکٹس](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/پروجیکٹس/)     |
