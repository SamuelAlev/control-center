یہ وہ **سرور سے بندھے** ٹولز ہیں جو بلٹ اِن ایجنٹ رن ٹائم براہِ راست رجسٹر کرتا ہے — لینگویج سرور، ساختی تلاش، ڈی بگر، کرنل، کوڈ موڈ اسکرپٹس، سوالات اور ورکر کنٹرول — بخلاف اُن [MCP ٹولز](/ur-PK/ہدایت-نامہ/حوالہ/mcp-ٹولز/) کے جو وہ برج کے ذریعے جوڑتا ہے، اور ہارنس رن ٹائم کے عام فائل، تلاش اور شیل ٹولز کے۔ یہ MCP رجسٹری پر نہیں ہیں: کوئی بیرونی MCP کلائنٹ انہیں نہیں دیکھے گا، کیونکہ ہر ایک سرور کی جانب موجود کسی زندہ وسیلے سے بندھا ہوتا ہے — ایک لینگویج سرور پروسیس، ایک ڈی بگ اڈاپٹر، ایک انٹرپریٹر — جو کسی ایک رن کا ہوتا ہے۔

یہاں ہر ٹول صرف اُس وقت رجسٹر ہوتا ہے جب اُس کا پشت پناہ وسیلہ اُس رن کے لیے جڑا ہو — لینگویج سرور یا ڈی بگ سپروائزر، ایک ٹری-سِٹر پارسر، ایک کرنل فیکٹری، ایک سوال پورٹ، ایک vibe راسٹر۔ *اِس چیک آؤٹ* کے لیے لینگویج سرور یا ڈی بگ اڈاپٹر کی پہچان ایک الگ، بعد کی جانچ ہے (`status` / `adapters`): وہ ٹولز سطح پر موجود رہتے ہیں تاکہ ایجنٹ اندازہ لگانے کے بجائے پوچھ سکے کہ کچھ بھی قابلِ استعمال کیوں نہیں۔

## منظوری کے درجے

ہر ٹول ایک درجہ قرار دیتا ہے، اور درجہ ہی طے کرتا ہے کہ **اُسے کون سی سطحیں دیکھتی ہیں** — نہ کہ صرف یہ کہ وہ پرامپٹ کرتا ہے یا نہیں۔ پلان موڈ اور صرف پڑھنے والے ذیلی ایجنٹس `read` تک محدود رہتے ہیں، اس لیے `write` یا `exec` درجے کا ٹول اُن کے اسکیما سے مکمل طور پر غائب ہوتا ہے۔

| درجہ   | مطلب                                  | یہاں کے ٹولز                                         |
| ------- | -------------------------------------- | -------------------------------------------------- |
| `read`  | کوئی ضمنی اثر نہیں                     | `lsp`, `ast_grep`, `ask_user`, `repl`, پانچوں `vibe_*` |
| `write` | فائلیں بدلتا ہے                        | `lsp_rename`, `ast_edit`, `resolve`                |
| `exec`  | کوئی پروسیس شروع یا کنٹرول کرتا ہے     | `debug`, `eval`                                    |

## براہِ راست، صرف اسکرپٹ سے، یا پہلی استعمال پر لوڈ

جب سرور اسکرپٹس چلا سکتا ہو، تو رن چند ٹولز براہِ راست کال کرتا ہے اور باقی [`repl`](#repl--وہ-اسکرپٹ-چلائیں-جو-آپ-کے-ٹولز-کو-کال-کرے) اسکرپٹ سے پہنچتا ہے؛ پورا اصول دیکھنے کے لیے [کوڈ موڈ](/ur-PK/ہدایت-نامہ/تصورات/کوڈ-موڈ/#وہ-ٹولز-جنہیں-ایجنٹ-براہِ-راست-کال-کرتا-ہے) دیکھیں۔ اس صفحے کے ٹولز کے لیے:

| ٹول | `repl` کے ساتھ | `repl` کے بغیر |
| ---- | ----------- | -------------- |
| `repl` | براہِ راست | موجود نہیں |
| `ask_user` | براہِ راست | براہِ راست |
| `lsp`, `lsp_rename`, `ast_grep`, `ast_edit`, `resolve`, `debug` | صرف اسکرپٹ سے | پہلی استعمال پر لوڈ |
| `eval` | پہلی استعمال پر لوڈ (اسکرپٹ اسے کال نہیں کر سکتا) | پہلی استعمال پر لوڈ |
| `vibe_*` | وائب موڈ میں براہِ راست، کبھی اسکرپٹ سے نہیں | وائب موڈ میں براہِ راست |

وہ ٹول جس پر “صرف اسکرپٹ سے” لکھا ہو، جب سرور کسی رن کے اسکرپٹس نہ چلا سکے تو پہلی استعمال پر لوڈ ہوتا ہے ([جب اسکرپٹس نہیں چل سکتے](/ur-PK/ہدایت-نامہ/تصورات/کوڈ-موڈ/#جب-اسکرپٹس-نہیں-چل-سکتے))۔

## `lsp` — لینگویج سرور کوئریز

اُس وقت رجسٹر ہوتا ہے جب رن کے پاس لینگویج سرور سپروائزر اور ایک ورکنگ ڈائریکٹری ہو۔ سرور واقعی جواب دے سکتا ہے یا نہیں، یہ کال کے وقت ایک **تقاطع** کے طور پر پہچانا جاتا ہے: روٹ مارکر کا موجود ہونا لازم ہے *اور* سرور بائنری کا حل ہونا بھی۔ صرف ایک کا ہونا یعنی کوئی سرور شروع نہیں ہوتا — `status` یہی بتاتا ہے — خاموش اندازے کے بجائے۔

سرورز بلٹ اِن ٹیبل سے ہی آتے ہیں؛ ریپوزٹری کی `lsp.json` نہیں پڑھی جاتی۔ سینڈ باکس شدہ رن میں ہر رن کا اپنا لینگویج سرور سیشن ہوتا ہے، اس لیے ہر رن کے ساتھ سرور دوبارہ شروع ہوتے ہیں۔ پروجیکٹ کے اندر کی بائنریز (`node_modules/.bin`) صرف سینڈ باکس شدہ رن میں استعمال ہوتی ہیں، اور پروجیکٹ روٹ کبھی رن کی ورکنگ ڈائریکٹری سے اوپر حل نہیں ہوتا۔

پوزیشنیں `line` کے ساتھ `symbol` کے سب اسٹرنگ سے مخاطب کی جاتی ہیں، کالم سے کبھی نہیں۔ جس ماڈل سے کالم مانگا جائے وہ اندازہ لگاتا ہے، اور غلط اندازہ اُسی لائن کے کسی مختلف علامت پر اتر آتا ہے — ایسا جواب جو درست لگتا ہے مگر کسی اور چیز کے بارے میں ہے۔ نیویگیشن ایکشن پر `symbol` چھوڑ دینا ایک خرابی ہے، پہلے کالم کا اندازہ نہیں۔

| ایکشن            | آرگیومنٹس                        | واپسی                                    |
| ----------------- | -------------------------------- | ------------------------------------------ |
| `diagnostics`     | `file` (یا `"*"`)                | ایررز اور وارننگز؛ `"*"` اُس کے بجائے پروجیکٹ چیکر چلاتا ہے |
| `definition`      | `file`, `line`, `symbol`         | جہاں علامت کا اعلان کیا گیا ہے               |
| `type_definition` | `file`, `line`, `symbol`         | جہاں اُس کے ٹائپ کا اعلان کیا گیا ہے                 |
| `implementation`  | `file`, `line`, `symbol`         | ٹھوس اپلیمنٹیشنز                   |
| `references`      | `file`, `line`, `symbol`         | ہر استعمال، زیادہ سے زیادہ 50                    |
| `hover`           | `file`, `line`, `symbol`         | سگنیچر اور ڈاک کمینٹ                  |
| `symbols`         | `query` یا `file`                | `query` کے ساتھ ورک اسپیس تلاش (حد 100)؛ `file` کے ساتھ دستاویزی علامات (حد 200) |
| `code_actions`    | `file`, `line`, `symbol`         | سرور کی پیش کردہ فوری اصلاحات              |
| `status`          | —                                | کون سے سرور چل رہے ہیں، اور کون سے روٹس کے لیے |
| `reload`          | —                                | اِس روٹ کے لیے سرور دوبارہ شروع کرتا ہے          |

### تحریر پر تشخیصات

اصل فائدہ ٹول نہیں ہے۔ `write`، `edit` اور `apply_patch` **لپیٹے ہوئے** ہیں: تحریر کے بعد فائل لینگویج سرور کے ذریعے سنک اور محفوظ ہوتی ہے، اور صرف **نئی سامنے آنے والی** تشخیصات ٹول کے نتیجے میں شامل کی جاتی ہیں۔ ایجنٹ کو اُسی لمحے پتہ چل جاتا ہے جب اُس نے بلڈ توڑا، بغیر یہ یاد رکھنے کے کہ پوچھنا تھا۔

پہلے بتائی جا چکی تشخیصات کو فی رن ایک لیجر دبا دیتا ہے جو شدت، کوڈ اور پیغام کی بنیاد پر کلید بندھا ہوتا ہے — پوزیشن جان بوجھ کر خارج، تاکہ جو تشخیص صرف چار لائن نیچے سرک گئی ہو، اُسے نئی کہہ کر دوبارہ نہ بتایا جائے۔

## `lsp_rename` — پورے پروجیکٹ میں نام کی تبدیلی

ایک الگ، `write` درجے کا ٹول، بالکل ایک ہی وجہ سے: درجہ ہی نظر آنا طے کرتا ہے۔ نام کی تبدیلی کو `lsp` میں سمو دینا یا تو صرف پڑھنے والے ایکسپلورر کو ریپو دوبارہ لکھنے کی اہلیت دے دیتا، یا ہر `hover` کو منظوری کے پرامپٹ کے پیچھے ڈال دیتا۔

| آرگیومنٹ | مطلب                                    |
| -------- | ------------------------------------------ |
| `file`   | جہاں علامت ہے                        |
| `line`   | 1-انڈیکس والی لائن                             |
| `symbol` | اُس لائن پر اسے پہچاننے والا سب اسٹرنگ      |
| `new_name` | اُسے کیا کہا جائے                          |

## `ast_grep` — ساختی تلاش

کوڈ کو متن کے بجائے **شکل** سے ڈھونڈتا ہے۔ `$NAME` کسی بھی نوڈ سے میل کھاتا ہے، `$$$NAME` بہن بھائیوں کی کسی قطار سے، اور `$_` ایسا وائلڈ کارڈ ہے جو کچھ نہیں باندھتا۔

وہ خاصیت جو اسے چند اضافی قدموں والا ریجیکس بننے سے روکتی ہے: ایک ہی پیٹرن میں دہرایا گیا میٹا متغیر لازماً وہی متن پکڑتا ہے۔

```
ast_grep(pattern: "if ($X != null) $X.dispose()", language: "dart")
```

ایسی گارڈ سے میل کھاتا ہے جو اُسی چیز کو ڈسپوز کرتی ہے جس کی اُس نے جانچ کی تھی، اور ایسی گارڈ سے میل **نہیں** کھاتا جو کسی اور چیز کو ڈسپوز کرے۔

| آرگیومنٹ      | مطلب                                                     |
| ------------- | ----------------------------------------------------------- |
| `pattern`     | میٹا متغیرات والا کوڈ ٹکڑا                          |
| `path`        | تلاش کے لیے فائل یا ڈائریکٹری؛ ڈیفالٹ پورا ورک اسپیس |
| `language`    | کوئی فراہم کردہ گرامر آئی ڈی (`dart`, `python`, `rust`, `c`, …)۔ جب `path` کسی فائل کا نام ہو تو خود اخذ ہو جاتی ہے |
| `max_results` | ڈیفالٹ 50                                                  |

:::note[پیٹرن اُسی گرامر سے پارس ہوتا ہے جس سے فائل]
چنانچہ `dispose(x)` اُس کال سے میل کھاتا ہے، خواہ وہ کسی بھی طرح فاصلے، لپیٹ یا تبصرے میں ہو — اور سٹرنگ لٹرل یا تبصرے کے اندر انہی حروف سے کبھی میل نہیں کھاتا۔
:::

:::caution[ٹکڑا ننگے طور پر نہیں، ایک سکیفولڈ میں پارس ہوتا ہے]
Dart کے ٹاپ لیول پر پارس کیا گیا `dispose(x)` ایک درست *فنکشن سگنیچر* ہے۔ پیٹرن کمپائلر سیاق و سباق کی ایک سیڑھی آزماتا ہے (سٹیٹمنٹ، ایکسپریشن، کلاس ممبر، اعلان) اور جو پہلا ٹکڑے کو قبول کر لے، وہی استعمال کرتا ہے۔ جس پیٹرن کو کوئی سیاق قبول نہ کرے، اُسے تلاش کر کے خاموشی سے نہ پائے جانے کے بجائے ناقابلِ پارس بتا دیا جاتا ہے۔
:::

## `ast_edit` — ساختی ری رائٹ، اسٹیج شدہ

وہی میچنگ، باضافہ ایک `rewrite` ٹیمپلیٹ جس میں میٹا متغیرات واپس شامل کر دیے جاتے ہیں۔ **کچھ بھی نہیں لکھا جاتا۔** تبدیلی اسٹیج کر دی جاتی ہے اور نتیجہ ایک `edit_id` کا نام لیتا ہے۔

```
ast_edit(pattern: "dispose($X)", rewrite: "$X.dispose()", language: "dart")
→ (proposed) 12 replacements in 4 files … call resolve with edit_id "edit_1"
```

| آرگیومنٹ   | مطلب                                             |
| ---------- | --------------------------------------------------- |
| `pattern`  | کس سے میل کھانا ہے                                       |
| `rewrite`  | وہاں کیا رکھنا ہے، `$NAME` شامل کر کے         |
| `path`     | دائرہ کار؛ ڈیفالٹ پورا ورک اسپیس              |
| `language` | زبان کی آئی ڈی                                         |

## `resolve` — اسٹیج شدہ تبدیلی کمٹ یا مسترد کریں

| آرگیومنٹ  | مطلب                          |
| --------- | -------------------------------- |
| `edit_id` | `(proposed)` نتیجے سے     |
| `action`  | `accept` یا `discard`            |

ہر فائل کا موازنہ اسٹیجنگ کے وقت محفوظ کیے گئے مواد سے کیا جاتا ہے، اور **کوئی بھی** عدم مطابقت پوری تبدیلی کو مسترد کر دیتی ہے۔ ادھورا لاگو ہوا ساختی ری رائٹ ایسا درخت چھوڑتا ہے جو نہ پرانی شکل میں کمپائل ہوتا ہے نہ نئی میں۔

## `debug` — ڈی بگر چلائیں

اُس وقت رجسٹر ہوتا ہے جب رن کے پاس ڈی بگ سیشن سپروائزر، ایک ورکنگ ڈائریکٹری اور ایک گفتگو آئی ڈی ہو۔ اڈاپٹر واقعی شروع ہو سکتا ہے یا نہیں، یہ کال کے وقت اُسی تقاطع اصول سے پہچانا جاتا ہے جو لینگویج سرور کا ہے (روٹ مارکر *اور* بائنری)۔ `exec` درجہ؛ متوازی کے لیے محفوظ نہیں (سیشن کالز کے درمیان حالت ہوتا ہے، چنانچہ `stack` سے آگے نکل جانے والا `continue` ایسا فریم پڑھے گا جو آگے بڑھ چکا ہوگا)۔

فی گفتگو ایک سیشن، سخت TTL کے ساتھ (30 منٹ)۔ دوسری `launch` خاموشی سے پہلی کی جگہ لینے کے بجائے مسترد کر دی جاتی ہے۔ سینڈ باکس شدہ رن میں سیشن موڑوں کے درمیان اپنا سینڈ باکس رکھتا ہے جب تک وہ ختم نہ ہو، یعنی زیادہ سے زیادہ انہی 30 منٹ تک۔

| آپریشن            | آرگیومنٹس                     | نوٹس                                          |
| ------------- | ----------------------------- | ---------------------------------------------- |
| `adapters`    | —                             | یہاں کون سے اڈاپٹرز قابلِ استعمال ہیں، اور کیوں نہیں     |
| `status`      | —                             | کوئی سیشن چل رہا ہے یا نہیں، اور کہاں رکا |
| `breakpoints` | `file`, `lines[]`             | خالی `lines` فائل صاف کر دیتا ہے۔ لانچ کرنے سے **پہلے** سیٹ کیا جا سکتا ہے |
| `launch`      | `program`, `args[]`           | پروگرام کو آپ کے بریک پوائنٹس پر رکا ہوا شروع کرتا ہے |
| `attach`      | `port`                        | رن کے اپنے فارورڈ کیے ہوئے پورٹس میں سے کسی ایک پر چل رہے ڈی بگی سے جڑتا ہے؛ کوئی اور پورٹ شروع ہونے سے پہلے مسترد ہو جاتا ہے |
| `continue`    | `thread_id?`                  | اگلے اسٹاپ تک چلتا ہے                        |
| `pause`       | `thread_id?`                  | اسے وہیں روک دیتا ہے جہاں ہے                            |
| `step_over` / `step_in` / `step_out` | `thread_id?` | ایک قدم آگے بڑھاتا ہے                          |
| `threads`     | —                             | تھریڈ آئی ڈیز اور نام                            |
| `stack`       | `thread_id?`                  | فریمز، زیادہ سے زیادہ 30                            |
| `scopes`      | `frame_id`                    | ایک فریم پر اسکوپس، ہر ایک کے ساتھ ایک `reference`      |
| `variables`   | `reference`                   | بچے، حد 50، ویلیوز حد 400 حروف |
| `evaluate`    | `expression`, `frame_id?`     | فریم کے اپنے اسکوپ میں جانچا گیا              |
| `output`      | —                             | ڈی بگی کی stdout/stderr، محدود           |
| `terminate`   | —                             | سیشن ختم کرتا ہے اور اڈاپٹر مار ڈالتا ہے          |

## `repl` — وہ اسکرپٹ چلائیں جو آپ کے ٹولز کو کال کرے

جب سرور اسکرپٹس چلا سکتا ہو تو ہر رن پر موجود ہوتا ہے ([جب رن کے پاس `repl` ہو](/ur-PK/ہدایت-نامہ/تصورات/کوڈ-موڈ/#جب-رن-کے-پاس-repl-ہو))۔ اسکرپٹ سادہ JavaScript ہے، جو ایک async فنکشن کی باڈی کے طور پر ہوتا ہے، اور ایک تازہ، لاک ڈاؤن شدہ انٹرپریٹر میں اپنے الگ پروسیس میں چلتا ہے: فائل سسٹم، نیٹ ورک، پروسیس یا ماڈیول تک کوئی رسائی نہیں۔ `repl` ٹول خود `read` ٹیئر میں ہے اور اپنی حفاظت خود کرتا ہے، کیونکہ اسکرپٹ کی ہر ٹول کال اپنے طور پر جانچی جاتی ہے۔ یہ ان ایجنٹ رنز کے لیے MCP اینڈ پوائنٹ پر بھی موجود ہے جو ایسے سرور پر ہوں جو اسکرپٹس چلا سکتا ہو۔

| آرگیومنٹ | مطلب |
| ------------------- | --------------------------------------------------------------------------------------------- |
| `code` | اسکرپٹ۔ زیادہ سے زیادہ 256 KiB |
| `description` | لازمی۔ ٹرانسکرپٹ قطار کے لیے ایک مختصر لیبل |
| `timeout_ms` | اختیاری۔ ورک اسپیس کی حد سے چھوٹی وقت کی حد؛ کبھی بڑی نہیں |
| `max_output_tokens` | اختیاری۔ ورک اسپیس کے بجٹ سے چھوٹا آؤٹ پٹ بجٹ؛ کبھی بڑا نہیں |

```js
// Read three files together and report only which ones failed.
const paths = ["lib/a.dart", "lib/b.dart", "lib/c.dart"];
const results = await Promise.allSettled(paths.map((path) => tools.read({ path })));
return results
  .map((r, i) => (r.status === "rejected" ? `${paths[i]}: ${r.reason.message}` : null))
  .filter(Boolean);
```

`repl` کی تفصیل ایجنٹ کو بتاتی ہے: “اس درخواست میں آپ کے براہِ راست ٹولز میں سے نہ ہونے والے ٹول کی کوئی تعریف نہیں ہوتی۔ کسی ایک کو پہلی بار کال کرنے سے پہلے اسے `describeTool(name)` یا `searchTools(query)` سے دیکھیں، جب تک اس کی درست کال کی شکل اس گفتگو میں آپ کو پہلے ہی نہ دکھائی گئی ہو۔”

`describeTool(name)` کسی ٹول کی تفصیل، اس کا اعلان، اس کے ان پٹ اور آؤٹ پٹ اسکیمے، اور اگر ہو تو اس کا نتیجے کا نوٹ لوٹاتا ہے: یعنی مکمل ہونے والی کال سے اسکرپٹ کو کیا ملتا ہے، ٹول کے اپنے الفاظ میں۔ `repl` کی تفصیل ان براہِ راست ٹولز کے نوٹس درج کرتی ہے جنہیں اسکرپٹ کال کر سکتا ہے۔ اگر نتیجہ JSON متن ہو تو وہ تجزیہ شدہ پہنچتا ہے، جب تک اس میں 131,072 سے زیادہ قدریں نہ ہوں؛ اس صورت میں وہ متن کے طور پر پہنچتا ہے، اور اسکرپٹ اسے `JSON.parse` کے ساتھ تجزیہ کرتا ہے۔ بیرونی MCP سرور کے کسی ٹول کے نتیجے کا متن 262,144 حروف پر کاٹ دیا جاتا ہے، اور کٹا ہوا متن اب تجزیہ نہیں ہوتا۔

- `tools.<name>(args)` براہِ راست کال جیسے ہی فلٹر، گارڈریلز اور منظوری سے ٹول کال کرتا ہے، اور منع ہونے یا ناکام ہونے پر خرابی کے ساتھ ریجیکٹ ہوتا ہے۔ صرف-پڑھنے والی کالز ایک ساتھ چل سکتی ہیں؛ جو کالیں کچھ بدلتی ہیں وہ ایک ایک کر کے، اسی ترتیب سے چلتی ہیں جس میں اسکرپٹ نے انہیں بنایا۔ جب اس کی کوئی کال کسی شخص کا انتظار کر رہی ہو تو اسکرپٹ کی کوئی دوسری کال شروع نہیں ہوتی۔
- `ALL_TOOLS`، `searchTools(query, { limit, namespace })`، `describeTool(name)` اور `describeNamespace(name)` ٹولز تلاش کرتے ہیں، کنیکٹڈ MCP سرورز کے ٹولز سمیت۔ براہِ راست سیٹ سے باہر وہ ٹول جسے اسکرپٹ کال کر سکتا ہو صرف اسکرپٹ سے کال ہو سکتا ہے؛ اس کی براہِ راست کال یہ لوٹاتی ہے کہ اسے `repl` سے کیسے کال کیا جائے۔ جب سرور کسی رن کے اسکرپٹس نہ چلا سکے، تو ایسا ٹول اس کے بجائے پہلی استعمال پر لوڈ ہوتا ہے۔
- تلاشیں محدود ہیں: استفسار زیادہ سے زیادہ 1,024 حروف، نام یا نیم اسپیس زیادہ سے زیادہ 256، `limit` 0 سے 50 تک، اور فی اسکرپٹ کل ملا کر سرور کے وقت کے 2 سیکنڈ تک لینے والی زیادہ سے زیادہ 200 تلاشیں، جبکہ ایک ورک اسپیس کے تمام اسکرپٹس 2 سیکنڈ تلاش کا وقت مشترک رکھتے ہیں، جو ہر سیکنڈ میں ایک چوتھائی سیکنڈ واپس ملتا ہے؛ دونوں میں سے کسی ایک کے ختم ہونے کے بعد مزید تلاشیں مسترد ہوتی ہیں۔ بہت بڑے کیٹلاگ میں `ALL_TOOLS` کی تفصیلات تقریباً ایک ملین حروف برابر بانٹتی ہیں، اور کٹی ہوئی تفصیل `…` پر ختم ہوتی ہے؛ `describeTool` ہمیشہ پوری تفصیل لوٹاتا ہے۔ جو قسم دکھانے کے لیے بہت بڑی ہو وہ `unknown /* too large to show */` دکھاتی ہے، اور نامعلوم نام کا جواب قریب ترین ناموں سے دیا جاتا ہے۔
- ٹولز نیم اسپیسز میں گروپ ہوتے ہیں: `builtin` (ہارنس کے اپنے ٹولز)، `control-center` (Control Center کے ٹولز) اور ہر کنیکٹڈ MCP سرور کے لیے ایک، جس کا نام سرور کے نام پر ہوتا ہے۔ `builtin`، `control-center` یا `script` نامی سرور، یا جس کا نام `external-` سے شروع ہو، کیپٹلز کے کسی بھی امتزاج میں اور اس کے آس پاس اسپیس کے ساتھ یا بغیر، `external-` کے بعد اس کے نام کے ساتھ درج ہوتا ہے، اور کوئی ٹول کبھی `script` میں نہیں ہوتا۔
- صرف وہی واپس آتا ہے جو اسکرپٹ لوٹاتا ہے، یا جو `text()`، `image()` یا `console.*` کو دیا جائے۔ بجٹ سے زیادہ آؤٹ پٹ اپنا شروع اور آخر برقرار رکھتا ہے، اور `read_output` باقی پڑھتا ہے۔
- `store(key, value)` / `load(key)` ایک ہی گفتگو اور ایجنٹ کے بعد کے اسکرپٹس کے لیے JSON قدریں رکھتے ہیں، جو صرف اسکرپٹ مکمل ہونے پر محفوظ ہوتی ہیں۔ سب ایجنٹ کے اسکرپٹس کے پاس کوئی اسٹور نہیں ہوتا۔
- `await tools.ask_user(...)` ایک سوال پوچھتا ہے؛ اس کا جواب نتیجے میں بھی شامل ہوتا ہے۔ `sleep(ms)`، `setTimeout`، `limits()` اور `models.embed` / `rank` / `classify` (ڈیوائس پر موجود ایمبیڈنگز) بھی دستیاب ہیں۔
- `describeTool(name)` اور `searchTools(query)` اسکرپٹ کے اپنے فنکشنز کے لیے بھی جواب دیتے ہیں، جو ٹولز نہیں ہیں: `text`، `image`، `store`، `load`، `sleep`، `setTimeout`، `clearTimeout`، `limits`، `exit` اور `models.*`، نیم اسپیس `script` کے تحت۔
- اسکرپٹ سے کال نہیں ہو سکتے: `repl`، `eval`، `task`، `checkpoint`، `rewind`، `compact`، `search_tools` اور `vibe_*` ورب۔
- ایک اسکرپٹ اپنے ہی رن کا ماضی پڑھ سکتی ہے: `history({start, role, tool, limit})` گفتگو کے ٹرانسکرپٹ کے صفحات دیتا ہے (ایک کال میں زیادہ سے زیادہ 50 قطاریں؛ پچھلے صفحے کا `next_start` بطور `start` دیں)، `outputs()` اس گفتگو اور ایجنٹ کے لیے محفوظ ٹول آؤٹ پٹس کی فہرست دیتا ہے، اور `loadOutput(handle)` ان میں سے ایک کے 16,384 حروف پڑھتا ہے۔ `storedKeys()` محفوظ کیز کو ان کے سائز کے ساتھ دکھاتا ہے۔ `keep(value, label)` ایک بڑی ویلیو کو آؤٹ پٹ کے طور پر محفوظ کرتا ہے جسے بعد کی اسکرپٹ یا `read_output` پڑھ سکتی ہے، جو صرف اسکرپٹ مکمل ہونے پر محفوظ ہوتی ہے (ایک ویلیو 1 MiB، ایک رن میں 64 ویلیوز اور 16 MiB تک)۔ `limits().returnBudgetChars` بتاتا ہے کہ آؤٹ پٹ بجٹ میں سے کتنا باقی ہے۔ صرف پڑھنے والا رن (ہدف کا ریویو) پڑھ سکتا ہے، مگر محفوظ یا keep نہیں کر سکتا۔ Claude Code اور ACP پر `history()` کام کرتا ہے، جبکہ `outputs()`، `loadOutput()` اور `keep()` مسترد ہوتے ہیں، کیونکہ Control Center ان رنز کے ٹول آؤٹ پٹس نہیں رکھتا۔
- ٹائم آؤٹ، آؤٹ پٹ کے حد سے بڑھنے یا کال کی حد سے آنے والی خرابی بتاتی ہے کہ اسے کیسے ٹھیک کیا جائے۔

ایک رن ایک وقت میں ایک اسکرپٹ چلاتا ہے۔ ہر حد اور ہر حد پہنچنے پر کیا ہوتا ہے، یہ [کوڈ موڈ](/ur-PK/ہدایت-نامہ/تصورات/کوڈ-موڈ/#حدیں) صفحے پر ہے؛ ہر اسکرپٹ **آبزرویبلٹی → کوڈ ایگزیکیوشنز** کے تحت ریکارڈ ہوتا ہے۔

## `eval` — مستقل انٹرپریٹرز

ایک Python یا JavaScript سیل جس کے ویری ایبلز، امپورٹس اور لوڈ شدہ ڈیٹا کالز کے درمیان برقرار رہتے ہیں۔ `exec` درجہ؛ متوازی کے لیے محفوظ نہیں۔ اسے `repl` اسکرپٹ سے کال نہیں کیا جا سکتا، اور سیل رن کے ٹولز کال نہیں کر سکتا: کوڈ سے ٹولز کال کرنے کے لیے [`repl`](#repl--وہ-اسکرپٹ-چلائیں-جو-آپ-کے-ٹولز-کو-کال-کرے) استعمال کریں۔

| آرگیومنٹ      | مطلب                                          |
| ------------- | ------------------------------------------------ |
| `code`        | سیل                                         |
| `description` | لازمی۔ ٹرانسکرپٹ لیبل کے لیے 5–10 الفاظ    |
| `language`    | `python` (ڈیفالٹ) یا `javascript`               |
| `reset`       | انٹرپریٹر رد کر کے پہلے صاف سا شروع کرتا ہے    |

- آخری ایکسپریشن ویسے ہی ظاہر ہوتا ہے جیسے نوٹ بک کرتی ہے۔
- `display()` کام کرتا ہے، pandas فریم ٹیبل کی صورت میں رینڈر ہوتا ہے، اور matplotlib فگر ایک **تصویر** کی صورت میں واپس آتا ہے جسے ٹرانسکرپٹ دکھاتا ہے۔
- وہ IPython محاورے جو لوگ بے ساختہ ٹائپ کرتے ہیں — `%pip`، `%cd`، `!cmd`، `%%bash`، `%%timeit` — سادہ کوڈ میں دوبارہ لکھ دیے جاتے ہیں۔ `%pip` ساتھ ہی `sys.modules` سے بھی نکال دیتا ہے، تاکہ اگلا `import` وہی دیکھے جو ابھی انسٹال ہوا۔
- جو سیل اپنے آؤٹ پٹ بجٹ سے زیادہ چھاپتا ہے وہ پہلے تین چوتھائی اور آخری چوتھائی رکھتا ہے، اور ایک لائن بتاتی ہے کہ کتنے حروف اور تصاویر ہٹائی گئیں۔
- جب انٹرپریٹر بغیر کہے مر جائے تو اگلے سیل کو ایک بار بتایا جاتا ہے کہ اس کے پہلے کے ویری ایبلز ختم ہو چکے ہیں۔

:::note[کرنل کہاں چلتا ہے]
گفتگو کا انکلوژر ہو تو اُسی میں، ورنہ رن کے OS سینڈ باکس میں ہوسٹ پر۔ سینڈ باکس بند ہو یا دستیاب نہ ہو تو یہ غیر محدود چلتا ہے اور `eval` ہوسٹ پر چلانے کی منظوری مانگتا ہے۔ یہ وہاں تک پہنچنے کے لیے انکلوژر **بوٹ نہیں** کرتا — وہی اصول جو رگ ٹیب کو خودکار شروع ہونے سے روکتا ہے۔
:::

## `bash` پس منظر میں

`run_in_background: true` کے ساتھ `bash` کمانڈ شروع کرتا ہے اور انتظار کرنے کے بجائے فوراً ایک ہینڈل (`b1`، `b2`، …) کے ساتھ واپس آتا ہے۔ ایجنٹ کام جاری رکھتا ہے، یا اپنی باری ختم کرتا ہے اور کمانڈ ختم ہونے پر بیدار ہوتا ہے۔

| آرگیومنٹ | مطلب |
| ------------------- | ------- |
| `run_in_background` | `true` ہو تو فوراً شروع کر کے واپس آ جاتا ہے |
| `timeout_seconds` | کمانڈ کو مارے جانے سے پہلے سیکنڈ: ڈیفالٹ 600، زیادہ سے زیادہ 3,600 |
| `notify` | اختیاری۔ ایک سادہ پیٹرن؛ آؤٹ پٹ کی ہر وہ لائن جو اس سے میل کھائے، کمانڈ چلنے کے دوران ایجنٹ کو بھیجی جاتی ہے (جیسے `listening on\|FAILED`) |

- ایک رن میں ایک وقت میں زیادہ سے زیادہ 4 پس منظر کمانڈز چلتی ہیں۔ ہر ایک اپنی ٹائم آؤٹ پر مارا جاتا ہے اور رن ختم ہونے پر بھی، اپنے شروع کردہ ہر پروسیس کے ساتھ۔
- کمانڈ ختم ہونے پر ایجنٹ کو ایک اطلاع ملتی ہے، جس میں exit کوڈ، آؤٹ پٹ کے آخری 2,000 حروف اور باقی کے لیے ایک `read_output` ہینڈل ہوتا ہے۔
- جس ایجنٹ کا باقی کام صرف پس منظر کی کمانڈ ہو وہ ماڈل کو کال کیے بغیر انتظار کرتا ہے، اور انتظار کے دوران رن کا سائلنس واچ ڈاگ رک جاتا ہے۔
- `bash_output(handle)` کسی کمانڈ کی حالت اور حالیہ آؤٹ پٹ پڑھتا ہے؛ `bash_kill(handle)` اسے روکتا ہے۔ دونوں بتاتے ہیں کہ نتیجہ پہلے ہی پہنچ چکا تھا یا نہیں۔
- اسکرپٹ پس منظر کی کمانڈ شروع نہیں کر سکتی۔ Claude Code کا اپنا پس منظر Bash ہے؛ Control Center اس رن کو زیادہ سے زیادہ 10 منٹ تک کھلا رکھتا ہے، اس باری کے بعد جس نے کوئی کام چلتا چھوڑا ہو۔

## `compact` — کانٹیکسٹ ونڈو میں جگہ خالی کریں

اگلی ماڈل کال سے پہلے گفتگو کا پرانا کانٹیکسٹ کمپیکٹ کرتا ہے، اور وہ رکھتا ہے جو `focus` بتائے (زیادہ سے زیادہ 1,000 حروف)۔ تازہ ترین باریاں جوں کی توں رہتی ہیں۔ ایجنٹ کی ہر باری کی بجٹ لائن کانٹیکسٹ کا استعمال 70، 80 اور 90 فیصد پر دکھاتی ہے، اور کام کے کسی لمبے نئے مرحلے سے پہلے ٹول کو تقریباً 70 فیصد سے آگے کال کرنا فائدہ مند ہے۔ سرور کے مالک کا `preCompact` ہک فوکس میں اضافہ کر سکتا ہے ([شیل ہکس](/ur-PK/ہدایت-نامہ/حوالہ/ایجنٹ-کنفیگریشن/#شیل-ہکس))۔ کمپیکشن کے بعد سرور ایک “Still in flight” بلاک شامل کرتا ہے: ہدف، انتظار میں بیداریاں، کھلے سوالات، پس منظر کی کمانڈز، چیک لسٹ اور محفوظ کیز، ہر ایک کے ساتھ وہ کال جو اسے بحال کرتی ہے۔

## `ask_user` — انسان سے سوال پوچھیں

`read` درجہ۔ کسی رن کا آپریٹر سے کچھ پوچھنے کا **واحد** طریقہ۔ یہ گفتگو میں نمبر والا کارڈ دکھاتا ہے اور جب تک کوئی جواب نہ دے، نہ چھوڑے، یا سوال ٹائم آؤٹ نہ ہو جائے، رکتا ہے۔ سوال کو کبھی چیٹ پیغام کے طور پر نہ لکھیں — وہ ٹرن ختم کر دیتا ہے۔

| آرگیومنٹ       | مطلب                                    |
| -------------- | ------------------------------------------ |
| `question`     | کیا پوچھنا ہے                                |
| `context`      | اختیاری: آپ کیوں پوچھ رہے ہیں اور جواب پر کیا منحصر ہے |
| `options[]`    | انتخاب، ہر ایک `{label, description?}`      |
| `allow_free_text` | آیا ٹائپ کیا گیا جواب قبول کیا جاتا ہے       |
| `multi_select` | آیا کئی اختیار چنے جا سکتے ہیں      |

چھوڑ دینا کامیابی ہے: ایک بیان کردہ مفروضے پر آگے بڑھیں اور دوبارہ نہ پوچھیں۔ ٹائم آؤٹ ایک خرابی ہے، اُسی ہدایت کے ساتھ۔ اجازت کے پرامپٹس (”کیا میں یہ کر سکتا ہوں؟“) ایک الگ چوک پوائنٹ ہیں اور گفتگو میں وہی کارڈ دکھاتے ہیں۔

صرف اُس وقت رجسٹر ہوتا ہے جب سوال پورٹ اور ہدف اسپیس، دونوں موجود ہوں۔ کوئی انسان منسلک نہ ہو تو کال ہمیشہ کے لیے رکنے کے بجائے **ناکام** ہو جاتی ہے — وہی بند ہو کر ناکام ہونے کا رویہ جو کوئی گارڈریل `prompt` کوئی منظور کنندہ منسلک نہ ہونے پر اپناتا ہے۔

## `vibe_*` — پس منظر ورکرز کی ہدایت

صرف اُس وقت رجسٹر ہوتے ہیں جب [vibe موڈ](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/پس-منظر-ورکرز-کی-ہدایت/) آن ہو۔ پانچوں `read` درجے کے ہیں: گیٹ ورکر کے ٹولز پر ہونا چاہیے، جہاں ترمیم واقعی ہوتی ہے۔

| ٹول         | آرگیومنٹس                                | نوٹس                                       |
| ------------ | ---------------------------------------- | ------------------------------------------- |
| `vibe_spawn` | `brief`, `label`, `tier?`                | فوراً واپس آ جاتا ہے؛ ورکر چلتا رہتا ہے     |
| `vibe_send`  | `worker_id`, `message`                   | بریف میں شامل کر کے دوبارہ چلاتا ہے            |
| `vibe_wait`  | `worker_id`, `timeout_seconds?`          | جب تک وہ اپنا کام ختم نہ کر لے رکتا ہے                     |
| `vibe_kill`  | `worker_id`                              | اسے روک دیتا ہے                                    |
| `vibe_list`  | —                                        | درجہ، حیثیت، گزرا ہوا وقت اور آخری نتیجہ       |

`tier` یا `fast` ہے (واضح تفصیل والا مکینیکل کام) یا `good` (ڈیزائن، فیصلہ سازی، یا کسی `fast` ورکر کے آؤٹ پٹ کا جائزہ)۔
