یہ گائیڈ دکھاتی ہے کہ اپنے سرور کو اس کی اپنی GitHub App کیسے دیں۔ اس میں تقریباً دو منٹ لگتے ہیں، صرف سرور کا مالک یہ کرتا ہے، اور ہر سرور کے لیے یہ صرف ایک بار ہونا ضروری ہے۔

جب Control Center Connect آن ہو تو لوگ Control Center کی مشترکہ App کے ذریعے یا اس App کے ذریعے GitHub میں sign in کرتے ہیں جسے آپ کی تنظیم کا Connect استعمال کرتا ہے۔ اپنی App تب رجسٹر کریں جب آپ **اپنی ایپس استعمال کریں** چنیں، یا جب آپ کے سرور کی GitHub رسائی ایسی App سے گزرنی چاہیے جسے آپ کنٹرول کرتے ہوں۔ دیکھیں [Control Center Connect](/ur-PK/ہدایت-نامہ/حوالہ/connect/)۔

بعد میں اپنے اکاؤنٹ میں sign in کے لیے دیکھیں [GitHub انضمام سیٹ کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/github-انضمام/)۔

## یہ app کیا کرتی ہے

ایک رجسٹریشن دو مختلف کام پورے کرتی ہے:

| کام                   | کیا جواب دیتا ہے                                               | یہ کیوں اہم ہے                                                                                 |
| --------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| **ایک شخص sign in کرتا ہے** | ایپ کا client id اور client secret                            | ہر کوئی اپنا GitHub credential حاصل کرتا ہے، سرور پر، ہر آلے پر                                  |
| **سرور عمل کرتا ہے**   | ایپ کا id اور private key                                      | ایجنٹس، پائپ لائنز، pollers اور بوٹ کے جوابات ہر بار ایک repository کے لیے ٹوکن حاصل کرتے ہیں     |

دوسرا کام کبھی کسی فرد کا credential مکمل طور پر ادھار نہیں لیتا۔ سرور جو بھی ٹوکن بناتا ہے وہ ایک repository کو کور کرتا ہے اور اس تک محدود ہے کہ ایک ذمہ دار رکن وہاں کیا کر سکتا ہے۔ جڑے ہوئے repository کو پڑھنے کے لیے صرف app درکار ہے؛ جو کچھ لکھتا ہے اسے ایسے رکن کی ضرورت ہے جو push کر سکے۔ خودکارسازی کبھی pull request کو منظور نہیں کرتی۔

سرور کی اپنی app صرف **اپنی ایپس استعمال کریں** کے تحت استعمال ہوتی ہے۔ Control Center Connect یا custom Connect کے ساتھ، Connect ہر lane چلاتا ہے، GitHub سمیت؛ سرور کی app محفوظ رہتی ہے مگر استعمال نہیں ہوتی جب تک آپ واپس نہ جائیں۔ جو workspace اپنی ایپس پر ہو ([ایک workspace کو اپنی app دیں](#ایک-workspace-کو-اپنی-app-دیں)) سرور کے mode سے قطع نظر اپنی App استعمال کرتا ہے۔ وہ app جس کے کچھ فیلڈز خالی ہوں وہ fall back نہیں بلکہ غلطی ہے: جب تک تمام فیلڈز سیٹ نہ ہوں، GitHub sign-ins رد ہوتے ہیں۔

## پیشگی شرائط

- آپ **سرور کے مالک** ہیں۔ **فراہم کنندہ ایپس** کارڈ باقی سب کے لیے نظر نہیں آتا
- ایک GitHub اکاؤنٹ۔ app اسی کے تحت بنتی ہے
- ایک سرور کا پتہ جس تک آپ کا براؤزر پہنچ سکے۔ سرور کا عوامی URL (یا desktop کے اپنے سرور کے لیے loopback) وہ جگہ ہے جہاں GitHub آپ کو واپس بھیجتا ہے

## ایک کلک میں بنائیں

1. **ترتیبات → سرور → سنگل سائن آن** پر جائیں اور **فراہم کنندہ ایپس** کارڈ تک اسکرول کریں
2. **GitHub** بلاک پر، اگر چاہیں تو **تنظیم (اختیاری)** میں وہ GitHub organization لکھیں جس کے پاس app ہونی چاہیے۔ خالی چھوڑنے پر app آپ کے اپنے اکاؤنٹ کے تحت بنتی ہے؛ کسی organization کے تحت بنانے کے لیے اس organization کا owner ہونا ضروری ہے
3. **میری GitHub ایپ بنائیں** پر کلک کریں
4. آپ کا براؤزر GitHub کھولتا ہے جس میں app پہلے سے بھری ہوتی ہے۔ **Create GitHub App** پر کلک کریں
5. GitHub آپ کو سرور پر واپس بھیجتا ہے، جو app id، private key، client id اور client secret محفوظ کرتا ہے، پھر app کا install page کھولتا ہے

کچھ بھی ہاتھ سے کاپی نہیں ہوتا، اور conversion کوڈ GitHub سے سیدھا آپ کے سرور تک جاتا ہے۔ یہ لنک ایک بار کام کرتا ہے اور دس منٹ بعد ختم ہو جاتا ہے؛ اگر ختم ہو جائے تو **میری GitHub ایپ بنائیں** دوبارہ دبائیں۔

app کا نام `Control Center <code>` ہے اور وہ بالکل وہی مانگتی ہے جو Control Center استعمال کرتا ہے:

| اجازت                                      | رسائی           |
| ------------------------------------------ | --------------- |
| Metadata                                   | پڑھنا           |
| Contents                                   | پڑھنا اور لکھنا |
| Pull requests                              | پڑھنا اور لکھنا |
| Issues                                     | پڑھنا اور لکھنا |
| Checks، Actions، Commit statuses           | پڑھنا           |
| Organization members                       | پڑھنا           |

Webhooks بند ہیں: سرور polling کرتا ہے۔ اگر آپ نے اپنے اکاؤنٹ کے تحت بنی app کو بعد میں کسی organization میں منتقل کرنا ہو تو GitHub پر app کی advanced settings میں **ملکیت منتقل کریں** استعمال کریں۔

checkpoint: GitHub بلاک کہتا ہے "The server can act as itself, and people can sign in"۔

## اسے وہاں انسٹال کریں جہاں آپ کے repositories ہیں

جو app رجسٹر ہو مگر انسٹال نہ ہو، وہ لوگوں کو sign in تو کرا سکتی ہے مگر کچھ پڑھ نہیں سکتی۔

1. GitHub کے کھولے ہوئے install page پر وہ اکاؤنٹ یا organization چنیں جس کے پاس آپ کے repositories ہیں
2. **All repositories** چنیں، یا وہ repositories منتخب کریں جنہیں یہ سرور دیکھے

بعد میں کسی دوسرے اکاؤنٹ پر انسٹال کرنے کے لیے، workspace admin **ترتیبات → ورک اسپیس → انٹیگریشنز** پر جاتا ہے، کوڈ ہوسٹنگ کے تحت **GitHub App** کارڈ پر **GitHub ایپ کی انسٹالیشنز** تلاش کرتا ہے اور **GitHub ایپ انسٹال کریں** پر کلک کرتا ہے۔ فہرست ہر اکاؤنٹ دکھاتی ہے جس پر app انسٹال ہے اور معطل installation کو نشان زد کرتی ہے۔

## کسی organization کی installation کو شیئر کریں

ایک organization GitHub App کو ایک بار انسٹال کرتی ہے۔ اس کے بعد اس میں شامل جو بھی Control Center سرور پر GitHub میں sign in کرتا ہے، وہ installation استعمال کر سکتا ہے، چاہے وہ کوئی بھی سرور ہو: آپ کا، کسی ساتھی کا، یا ان کا اپنا۔ ہر سرور کے لیے کچھ مجاز کرنے کی ضرورت نہیں۔

ہر سرور کو ملنے والا token sign in کرنے والے شخص کا اپنا ہوتا ہے، ایک repository اور اس repository میں اس کے role تک محدود۔ اس لیے وہ اس سے آگے نہیں جاتا جتنا وہ GitHub پر کر سکتا ہے۔ GitHub کا audit log اس شخص کو دکھاتا ہے جو app کے ذریعے کام کر رہا ہے۔

Control Center کو کسی organization تک پہنچنے سے روکنے کے لیے، organization کا کوئی owner GitHub پر installation ہٹا دیتا ہے یا اس کے repositories محدود کر دیتا ہے۔ کسی شخص کو organization سے نکالنے سے اس کی رسائی بھی رک جاتی ہے۔

## بجائے اس کے، دستی طور پر رجسٹر کریں

**فراہم کنندہ ایپس** کارڈ قدریں براہِ راست بھی قبول کرتا ہے، اس app کے لیے جو آپ نے خود رجسٹر کی ہو:

| گروپ                              | فیلڈز                                                                                                                       |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| **سرور کے طور پر عمل**            | **App id**، اور **پرائیویٹ کلید** (پوری `.pem` فائل، `BEGIN` اور `END` لائنز سمیت)                                             |
| **لوگوں کو sign in کرانا**        | **Client id** اور **Client secret**۔ **کال بیک URLs** وہ URL دکھاتا ہے جو رجسٹر کرنا ہے، ہو بہو                             |
| **Pull request گفتگوئیں**         | **بوٹ لاگ اِن**، جو کنکشن ٹیسٹ کرنے پر حل ہوتا ہے                                                                             |

callback URL `<server origin>/oauth/github/callback` کو بالکل ویسے رجسٹر کریں جیسا کارڈ دکھاتا ہے، **Expire user authorization tokens** کو آن رکھیں، اور اوپر کے جدول کی اجازتیں دیں۔ **ٹیسٹ** پر کلک کریں: یہ GitHub سے پوچھتا ہے کہ app کن اکاؤنٹس پر انسٹال ہے، تاکہ "محفوظ" اور "کام کرتا ہے" آپس میں الجھ نہ جائیں۔

## سرور کی `.env` سے کنفیگر کریں

headless یا scripted انسٹالیشن کے لیے، سرور ہر فیلڈ کو اپنی `.env` فائل سے بیج کرتا ہے جب اس کی کوئی محفوظ قدر نہ ہو:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

key کو **ایک لائن** میں رکھیں: `.env` کی قدر ایک لائن ہوتی ہے، اور دوہرے کوٹیشن کے اندر `\n` نئی لائن میں تبدیل ہوتا ہے۔ سرور شروع ہونے سے انکار کرتا ہے جب `GITHUB_APP_PRIVATE_KEY` یا `GITHUB_CLIENT_SECRET` اس کے پروسیس ماحول میں ایکسپورٹ ہوں، جہاں ہر child process انہیں پڑھ سکتا ہے؛ انہیں `.env` فائل میں رکھیں (Docker میں، اسے `/app/bin/.env` پر mount کریں)۔ بیج کرنا **ہر فیلڈ کے لیے ایک بار** ہوتا ہے، اس لیے Settings میں ترمیم اگلے restart سے ختم نہیں ہوتی۔

## ایک workspace کو اپنی app دیں

ایک workspace سرور کی app کے بجائے اپنی app پر چل سکتا ہے:

1. ایک workspace admin **ترتیبات → ورک اسپیس → انٹیگریشنز** پر جاتا ہے
2. **Control Center Connect** کارڈ پر **اپنی ایپس استعمال کریں** چنتا ہے اور **لاگو کریں** پر کلک کرتا ہے۔ سب workspace کی ایپس کے ذریعے دوبارہ sign in کرتے ہیں
3. کوڈ ہوسٹنگ کے تحت **GitHub App** کارڈ میں اب ایپ کے فیلڈز ہیں: **اس ورک اسپیس کی طرف سے کام کرنا** کے تحت **App id** اور **پرائیویٹ کلید**، **لوگوں کو سائن اِن کرنا** کے تحت **Client id** اور **Client secret**۔ ایک بار سیٹ ہونے پر **ٹیسٹ** پر کلک کریں

اراکین پھر اس workspace کے لیے اس app میں sign in کرتے ہیں۔ جو workspace اپنی ایپس پر ہو وہ کبھی سرور کی app یا Connect پر fall back نہیں کرتا: جب تک اس کے فیلڈز مکمل نہ ہوں، اس کا GitHub کام رد ہوتا ہے۔ یہی انتخاب Google Calendar، Linear اور GIF search پر بھی لاگو ہوتا ہے، ہر ایک کے اپنے فیلڈز اسی صفحے پر اس کے provider کے ساتھ ہیں۔ دیکھیں [ایک workspace کو اپنی Linear application دیں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/linear-انضمام/#ایک-workspace-کو-اپنی-linear-application-دیں) اور [ایک workspace کو اپنا Google client دیں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/کیلنڈر-جوڑیں/#ایک-workspace-کو-اپنا-google-client-دیں)۔ کارڈ کے باقی انتخابات، اور ہر ایک کیا کرتا ہے، [ہر workspace کا اپنا انتخاب](/ur-PK/ہدایت-نامہ/حوالہ/connect/#ہر-workspace-کا-اپنا-انتخاب) میں ہیں۔

## خرابیوں کا ازالہ

### Create my GitHub App کہتا ہے سرور کا کوئی پتہ نہیں

سرور کے پاس کوئی عوامی URL نہیں جس پر براؤزر واپس آ سکے۔ `CC_SERVER_PUBLIC_URL` (یا `--public-url`) سیٹ کریں اور دوبارہ کوشش کریں۔

### GitHub کہتا ہے لنک ختم ہو گیا

ایک بار استعمال ہونے والا صفحہ پہلے ہی استعمال ہو چکا تھا، یا دس منٹ گزر گئے۔ Settings سے دوبارہ شروع کریں۔

### Test کہتا ہے اعتبارنامے کام کرتے ہیں مگر app کہیں انسٹال نہیں

رجسٹریشن اور انسٹالیشن الگ مراحل ہیں۔ app کا install page کھولیں، یا ورک اسپیس → انٹیگریشنز میں **GitHub ایپ انسٹال کریں** استعمال کریں۔

### Test کہتا ہے private key پڑھی نہیں جا سکی

پوری `.pem` فائل چسپاں کریں، جس میں `-----BEGIN` اور `-----END` لائنز شامل ہوں۔ `ed25519` یا EC key استعمال نہیں ہو سکتی: GitHub Apps RSA سے sign کرتی ہیں۔

### ایک رکن sign in ہوا مگر کوئی repository نظر نہیں آتی

app اس اکاؤنٹ پر انسٹال نہیں جس کے تحت repositories ہیں، یا اس کی installation مختلف repositories منتخب کرتی ہے۔ sign-in صرف وہی دیتا ہے جو app دیکھ سکتی ہو۔

### Agents کہتے ہیں GitHub App installation معطل ہے

کسی نے GitHub پر installation معطل کر دی ہے۔ اکاؤنٹ کی **Settings → Applications → Installed GitHub Apps** میں اسے بحال کریں۔
