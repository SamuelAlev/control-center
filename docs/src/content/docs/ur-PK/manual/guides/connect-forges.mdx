Control Center تین code hosts کے ساتھ کام کرتا ہے، جنہیں ایپ میں پورے طور پر **forges** کہا جاتا ہے: **GitHub**، **GitLab** اور **Bitbucket Cloud**۔ ان میں سے کوئی بھی ڈیفالٹ نہیں ہے۔ ایک جوڑیں تو سب کچھ کام کرتا ہے؛ کئی جوڑیں تو ایک ہی ورک اسپیس میں تینوں کے ریپوز بیک وقت رکھے جا سکتے ہیں۔

forge ہر **ریپو** کی خاصیت ہے، جو اس کی رجسٹریشن کے وقت اس کے `origin` remote سے پڑھی جاتی ہے۔ آپ کبھی اسے نہیں چنتے، اور ورک اسپیس کی کوئی ایسی سیٹنگ نہیں جسے غلط کیا جا سکے۔

## کوئی forge جوڑیں

1. **ترتیبات → آپ → پروفائل** (`/settings/you/profile`) کھولیں۔
2. **کوڈ ہوسٹنگ** کارڈ تلاش کریں۔ ہر تعاون یافتہ forge درج ہوتا ہے، جڑا ہوا ہو یا نہ ہو۔
3. **GitHub** پر **Sign in to GitHub** دبائیں۔ **GitLab** یا **Bitbucket** پر **ٹوکن شامل کریں** دبائیں اور ایک ٹوکن چسپاں کریں۔

**GitHub صرف sign-in ہے۔** sign-in سرور کی اپنی GitHub App یا Control Center Connect کے ذریعے چلتا ہے، جو بھی سرور کے مالک نے سیٹ اپ کیا ہو، یا ان apps کے ذریعے جو ورک اسپیس کا admin **ترتیبات → ورک اسپیس → انٹیگریشنز** میں اس ورک اسپیس کے لیے چنے (دیکھیں [GitHub انضمام سیٹ کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/github-انضمام/))؛ چسپاں کرنے کے لیے کوئی GitHub ٹوکن نہیں ہے۔ GitLab اور Bitbucket اب بھی ذاتی ٹوکن لیتے ہیں۔

دونوں صورتوں میں credential **آپ کا ہے اور سرور پر رہتا ہے**، آپ کے user id سے کلید کیا ہوا: جس مشین پر آپ نے ٹائپ کیا وہاں کوئی ٹوکن محفوظ نہیں ہوتا، ہر ڈیوائس جس سے آپ sign in کریں وہی ایک استعمال کرتی ہے، اور کوئی اور رکن اسے نہیں پڑھ سکتا۔ یہ **اگلی درخواست** پر اثر کرتا ہے — کچھ دوبارہ شروع کرنے کی ضرورت نہیں، اور منقطع کرنا اسے فوراً بھیجنا روک دیتا ہے۔

کارڈ بتاتا ہے کہ آپ کے اکاؤنٹس کہاں استعمال ہوتے ہیں۔ GitLab یا Bitbucket کا ٹوکن آپ کا ہے اور **سرور کی ہر ورک اسپیس** میں چلتا ہے، اس لیے آپ اسے ایک بار چسپاں کرتے ہیں۔ GitHub کا sign-in بھی یہی ہے، جب تک کوئی ورک اسپیس اپنی sign-in ایپس نہ رکھتی ہو: وہ ورک اسپیس اپنا GitHub sign-in رکھتی ہے، اور کارڈ اس کا نام بتاتا ہے۔

ہر قطار **آپ کے** credential کی حالت دکھاتی ہے۔ صرف آپ کا اپنا credential آپ کی جانب سے جواب دیتا ہے؛ کوئی اور چیز اس کی جگہ نہیں لیتی:

| قطار کیا کہتی ہے                                              | مطلب                                                                                                                         |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `octocat کے طور پر sign in ہیں`                               | آپ کا اپنا credential استعمال ہو رہا ہے                                                                                                  |
| `منسلک نہیں`                                                  | آپ کے پاس اس forge کا کوئی credential نہیں                                                                                   |
| `octocat کے طور پر آپ کا GitHub سائن اِن ختم ہو گیا ہے۔ دوبارہ سائن اِن کریں۔` | آپ کا sign-in forge پر ختم ہو گیا یا منسوخ ہو گیا                                                                  |
| `موقوف: اس ورک اسپیس کی سائن اِن سروس بدل گئی ہے`                | یہ ورک اسپیس کسی اور sign-in سروس پر چلا گیا ہے۔ آپ کا sign-in محفوظ رہتا ہے اور واپس بدلنے پر دوبارہ کام کرتا ہے، اس لیے یہاں sign-in بٹن نہیں ہے |
| `ابھی GitHub تک رسائی نہیں ہو پا رہی۔ دوبارہ کوشش کی جا رہی ہے۔`              | عارضی رکاوٹ۔ Control Center دوبارہ کوشش کرتا رہتا ہے؛ آپ کو کچھ نہیں کرنا                                                       |
| sign-in کیوں دستیاب نہیں، اس کی وضاحت کرنے والا ایک جملہ        | مثلاً `اس ورک اسپیس کے لیے GitHub سائن اِن سیٹ اپ نہیں ہے۔` یا `اس ورک اسپیس کی سائن اِن سروس نے اپنی شناخت بدل لی ہے۔ کسی ایڈمن کو اس کی تصدیق کرنی ہوگی۔` ایڈمن کو اس ترتیب کا بٹن ملتا ہے جو مسئلہ ٹھیک کرتی ہے |

### ہر forge کون سا ٹوکن چاہتا ہے

| Forge         | ٹوکن                                                      | کہاں بنائیں                                               |
| ------------- | --------------------------------------------------------- | --------------------------------------------------------- |
| **GitLab**    | `api` کے ساتھ ایک ذاتی access token                       | gitlab.com → User settings → Access tokens                 |
| **Bitbucket** | ایک Atlassian API ٹوکن، ساتھ آپ کا اکاؤنٹ ای میل           | id.atlassian.com → Security → API tokens                   |

Bitbucket آپ کے **اکاؤنٹ ای میل کو یوزرنیم** اور API ٹوکن کو پاس ورڈ کے طور پر استعمال کرتے ہوئے تصدیق کرتا ہے، اس لیے Bitbucket ڈائیلاگ دونوں مانگتا ہے۔ Bitbucket ریپوزٹری، پروجیکٹ یا ورک اسپیس کا **access token** کسی شخص سے تعلق نہیں رکھتا، اس لیے یہ ڈائیلاگ اسے قبول نہیں کرتا: اس کے بجائے یہ ایک [آٹومیشن ٹوکن](#آٹومیشن-ٹوکن-شامل-کریں) ہے۔ GitLab پروجیکٹ یا گروپ access token کے لیے بھی یہی ہے: ٹوکن محفوظ ہونے سے پہلے GitLab سے پوچھا جاتا ہے کہ یہ کس کا ہے، اور بوٹ کا ٹوکن یہاں قبول نہیں ہوتا۔

ٹوکن کبھی ایک ورک اسپیس سے منسلک نہیں ہوتا: آپ فی forge ایک ٹوکن رکھتے ہیں، اور سرور کی ہر ورک اسپیس اسے استعمال کرتی ہے۔ **منقطع کریں** اسے سب کے لیے ہٹاتا ہے۔

### پس منظر کا کام

جس کام کے پیچھے کوئی انسان نہ ہو (ایجنٹ رنز، pipelines، PR پولنگ) اسے بھی credential چاہیے، اور ہر forge اسے مختلف طریقے سے حل کرتا ہے:

- **GitHub** — ایک وقت میں ایک ریپو کے لیے ایک ٹوکن، جو سرور کی GitHub App سے یا Connect کے ذریعے بنایا جاتا ہے اور اس تک محدود ہوتا ہے جو ایک ذمہ دار رکن وہاں کر سکتا ہے۔ یہ کبھی کسی شخص کا پورا sign-in نہیں ہوتا، اور نہ کوئی environment variable یا چسپاں ٹوکن اس کی جگہ لیتا ہے۔ دیکھیں [GitHub انضمام سیٹ کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/github-انضمام/#آپ-کا-credential-کس-کی-نمائندگی-کرتا-ہے)
- **GitLab** اور **Bitbucket** — صرف ریپو کا **آٹومیشن ٹوکن**: ایک bot access token جو ورک اسپیس کا admin اس ریپو کے لیے، یا ورک اسپیس میں اس forge کے ہر ریپو کے لیے شامل کرتا ہے۔ ریپو کا اپنا ٹوکن ورک اسپیس کے ٹوکن پر فوقیت رکھتا ہے۔ pull request پولنگ، AI ریویو کے تبصرے، اور وہ pushes اور merge requests جو کسی نے نہیں مانگے، سب اسے استعمال کرتے ہیں، اس لیے forge پر وہ اسی bot کے طور پر دکھتے ہیں، کبھی کسی رکن کے طور پر نہیں۔ کسی رکن کا ذاتی ٹوکن اس کی جگہ نہیں لیتا، اور کوئی سرور سطح یا environment-variable ٹوکن نہیں ہے۔ اس کے بغیر ریپو پر پس منظر کا کام موقوف ہو جاتا ہے اور ریپو تک رسائی کی اطلاع یہ بتاتی ہے۔

کسی رکن کی طرف سے مانگا گیا کام (تبصرہ، ریویو، یا اس کے لیے کھولی گئی ایجنٹ merge request) اب بھی اسی رکن کا اپنا ٹوکن استعمال کرتا ہے۔

## آٹومیشن ٹوکن شامل کریں

صرف ورک اسپیس کے ایڈمنز آٹومیشن ٹوکن دیکھ یا بدل سکتے ہیں۔ ہر ٹوکن محفوظ کرتے وقت forge کے ساتھ جانچا جاتا ہے: وہ ٹوکن جو کسی شخص کے طور پر عمل کرے رد ہوتا ہے (GitLab کا ذاتی access token، Atlassian API token، یا کوئی بھی Bitbucket ٹوکن جو کسی کے اکاؤنٹ کے طور پر سائن ان ہو)، اور وہ ٹوکن بھی جو اس ریپو کو نہ پڑھ سکے جس کے لیے وہ ہے۔

- **ایک ریپو کے لیے:** **ترتیبات → ورک اسپیس → ریپوزٹریز** کھولیں۔ **آٹومیشن ٹوکن** کارڈ ہر GitLab اور Bitbucket ریپو کو درج کرتا ہے، اور وہ bot جو وہاں کام کرتا ہے، **ورک اسپیس کا ٹوکن استعمال کرتا ہے**، یا **کوئی ٹوکن نہیں۔ آٹومیشن یہاں موقوف ہے۔** ریپو کی قطار پر **ٹوکن شامل کریں** دبائیں۔
- **کسی forge کے ہر ریپو کے لیے:** **ترتیبات → ورک اسپیس → انٹیگریشنز** کھولیں، **آٹومیشن ٹوکن** کارڈ تلاش کریں اور GitLab یا Bitbucket قطار پر **ٹوکن شامل کریں** دبائیں۔ محفوظ کرنے کے بعد جو ریپوز ٹوکن نہیں پڑھ سکتا، اس کا نام لیا جاتا ہے اور وہ موقوف رہتے ہیں۔

جب پس منظر کا کام پہلے ہی موقوف ہو، تو ایڈمنز کو ریپو رسائی کی اطلاع پر ہی **ٹوکن شامل کریں** نظر آتا ہے۔ **ٹوکن اپ ڈیٹ کریں** ٹوکن بدلتا ہے؛ ڈسٹ بن بٹن اسے ہٹاتا ہے، اور جو ریپو بغیر ٹوکن رہ جائے وہ موقوف ہو جاتا ہے۔ اگر forge بعد میں محفوظ شدہ ٹوکن کو رد کر دے (منسوخ یا ختم شدہ)، تو اس کی قطار یہ بتاتی ہے اور اس کے زیرِ اثر ریپوز آپ کے نیا ٹوکن لگانے تک موقوف رہتے ہیں۔

| Forge         | آٹومیشن ٹوکن                                                                                             | کہاں بنائیں                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| **GitLab**    | ایک **پروجیکٹ** یا **گروپ access token** جس میں `read_api` اور `read_repository` ہوں؛ تبصروں، merge requests اور pushes کے لیے `api` اور `write_repository` شامل کریں | پروجیکٹ یا گروپ → Settings → Access tokens                     |
| **Bitbucket** | ایک **ریپوزٹری**، **پروجیکٹ** یا **ورک اسپیس access token** جس میں ریپوزٹری پڑھنے کی اجازت ہو، اور تبصروں اور pull requests کے لیے pull request لکھنے کی اجازت (pushes کے لیے ریپوزٹری لکھنے کی اجازت) | ریپوزٹری، پروجیکٹ یا ورک اسپیس → Settings → Access tokens     |

GitLab یہ کام ٹوکن کے bot user کے طور پر دکھاتا ہے؛ Bitbucket اسے access token کے نام کے تحت دکھاتا ہے۔

### Bitbucket: access token یا API token

Bitbucket کے دو قسم کے ٹوکن ہیں، اور Control Center انہیں الگ رکھتا ہے:

- ایک **API ٹوکن** (id.atlassian.com) آپ کے Atlassian اکاؤنٹ سے تعلق رکھتا ہے اور آپ کے ای میل کے ساتھ استعمال ہوتا ہے۔ یہ **آپ کا** credential ہے اور **کوڈ ہوسٹنگ** کے تحت **ترتیبات → آپ → پروفائل** میں جاتا ہے۔
- ایک **access token** (ریپوزٹری، پروجیکٹ یا ورک اسپیس کی ترتیبات میں بنایا گیا) اس ریپوزٹری، پروجیکٹ یا ورک اسپیس سے تعلق رکھتا ہے، کسی شخص سے نہیں۔ یہ ایک **آٹومیشن ٹوکن** ہے اور **آٹومیشن ٹوکنز** کے تحت جاتا ہے۔

ہر ڈائیلاگ دوسری قسم کو رد کرتا ہے اور بتاتا ہے کہ وہ کہاں جانی چاہیے۔

## آپ ہر forge پر ایک مختلف شخص ہیں

وہی انسان GitHub پر `octocat` ہے اور GitLab پر بالکل کچھ اور۔ Control Center آپ کی شناخت **ہر forge کے لحاظ سے** طے کرتا ہے اور ہر ریپو کے لیے درست شناخت استعمال کرتا ہے، اور یہی وجہ ہے کہ ملی جلی ورک اسپیس میں "میرے ریویو کی ضرورت ہے"، "میں نے بنایا" اور "آپ نے منظور کیا" درست رہتے ہیں۔

اگر کسی forge کی شناخت طے نہ ہو سکی ہو، تو اس کے ریپوز ان باکس میں کچھ بھی شامل نہیں کرتے، بجائے اس کے کہ ہر چیز سے میل کھائیں۔ ان باکس یہ بتاتا ہے، یہ دعویٰ نہیں کرتا کہ آپ سب کچھ دیکھ چکے ہیں۔

## آپ صرف وہی دیکھتے ہیں جو آپ کا اپنا اکاؤنٹ دیکھ سکتا ہے

کسی ریپو کے pull requests آپ تک تبھی پہنچتے ہیں جب آپ کا ورک اسپیس رول وہ ریپو اجازت دے **اور forge پر آپ کا اپنا اکاؤنٹ اسے پڑھ سکے**۔ ورک اسپیس کے ایڈمنز اور مالک بھی یہی قاعدہ مانتے ہیں۔ جب کچھ ریپوز چھپے ہوں، تو ان باکس اور PR قطار ان کی تعداد اور وجہ بتاتے ہیں، نام لیے بغیر:

- **3 مزید ریپوز کے pull requests دیکھنے کے لیے GitHub میں sign in کریں**: آپ نے ابھی یہاں اس forge کو نہیں جوڑا۔ sign in کریں اور وہ ظاہر ہو جائیں گے
- **3 ریپوز چھپے ہیں کیونکہ آپ کا GitHub اکاؤنٹ انہیں نہیں دیکھ سکتا**: forge پر رسائی رکھنے والے کسی شخص سے پوچھیں
- **3 ریپوز چھپے ہیں کیونکہ اس ورک اسپیس میں آپ کے پاس ان تک رسائی نہیں**: کسی ورک اسپیس ایڈمن سے رسائی مانگیں
- **3 مزید ریپوز تک آپ کی رسائی کی جانچ ہو رہی ہے…**: Control Center کے یہ تصدیق کرنے کے دوران مختصر طور پر دکھایا جاتا ہے کہ آپ کا اکاؤنٹ کون سے ریپوز پڑھ سکتا ہے

کوڈ بھی یہی قاعدہ مانتا ہے۔ کسی ریپوزٹری کی فائلیں، diffs یا سرچ کھولنے کے لیے، یا اس پر ٹرمینل کے لیے، آپ کو اس ورک اسپیس میں اس کی گرانٹ درکار ہے اور آپ کا اپنا فورج اکاؤنٹ اسے پڑھ سکتا ہو؛ ورک اسپیس ایڈمنز بھی، صرف سرور کا مالک مستثنیٰ ہے۔ جب فورج جانچ کے لیے نہ پہنچ سکے تو آپ کو فورج کا نام لے کر "آپ کی فورج تک رسائی کی تصدیق نہیں ہو سکی۔ دوبارہ کوشش کریں۔" نظر آتا ہے۔ دیکھیں [کوڈ فورج کی پیروی کرتا ہے](/ur-PK/ہدایت-نامہ/تصورات/اجازت/#کوڈ-فورج-کی-پیروی-کرتا-ہے)۔

یہی قاعدہ ان تمام چیزوں پر لاگو ہوتا ہے جو ان pull requests سے بنتی ہیں۔ ریویو اسپیس، اس کے پیغامات اور اس کے ایجنٹ کے رنز اُس وقت غائب ہو جاتے ہیں جب آپ اس کا pull request نہیں دیکھ سکتے، اور کھلی ریویو اسپیس اُس وقت بند ہو جاتی ہے جب آپ کی رسائی ختم ہو جائے۔ چھپے ہوئے pull request کے بارے میں پائپ لائن رنز آپ کی رنز کی فہرست سے نکل جاتے ہیں۔ آپ کے لیے کام کرنے والے ایجنٹس بھی ان ریویو اسپیسز کو نہیں پڑھ سکتے۔ ورک اسپیس کی ریپوزٹری فہرست اس ورک اسپیس میں آپ کی ہر اُس ریپو کو دکھاتی ہے جس تک آپ کی رسائی ہو، حتیٰ کہ اُس ریپو کو بھی جس تک آپ کا forge اکاؤنٹ ابھی نہ پہنچ سکے۔

اگر forge rate-limited ہو یا بند ہو، تو Control Center چند منٹ تک وہی دکھاتا رہتا ہے جو اس نے آخری بار تصدیق کیا تھا، پھر ان pull requests کو چھپا دیتا ہے جب تک وہ دوبارہ جانچ نہ سکے۔

## ایک ان باکس، ہر forge

ان باکس اور PR قطار ورک اسپیس میں موجود ہر forge تک پھیلتے ہیں اور نتائج کو ایک ہی سلسلے میں ملاتے ہیں — GitHub کا pull request اور Bitbucket کا pull request ایک دوسرے کے ساتھ آتے ہیں، وقت کے لحاظ سے ترتیب دیے گئے، نہ کہ فروش کے لحاظ سے گروپ کیے گئے۔

ناکامیاں الگ تھلگ رہتی ہیں۔ جو forge بند ہو یا rate-limited ہو، وہ دوسروں کو متاثر نہیں کرتا، اور اس کے ریپوز بحالی تک اپنی آخری معلوم حالت برقرار رکھتے ہیں؛ وہ پورے ان باکس کو کبھی خالی نہیں کرتا۔ جس ریپو تک سرور اب نہ پہنچ سکے وہ فہرست سے ہٹ جاتا ہے بجائے اس کے کہ پرانے pull requests دکھائے، اور **ریپو رسائی کی اطلاع** اس کا نام اور درستی کا طریقہ بتاتی ہے: اس کی تنظیم پر GitHub App انسٹال کریں، ریپو کو App کی ریپوزٹریز میں شامل کریں، معطل انسٹالیشن بحال کریں، جو رکن ذمہ دار ہے اس سے دوبارہ sign in کروائیں، یا GitLab یا Bitbucket ریپو کے لیے آٹومیشن ٹوکن شامل کریں۔ ایڈمنز کو GitHub App کے مراحل اور ٹوکن شامل کرنے کا بٹن ملتا ہے۔

## ہر forge کیا کر سکتا ہے

ہر forge بنیادی سائیکل سپورٹ کرتا ہے: pull requests کی فہرست بنانا اور کھولنا، diffs پڑھنا، inline اور اوپری سطح پر تبصرہ کرنا، ریویو کرنا، merge اور بند کرنا۔ اس سے آگے وہ واقعی مختلف ہیں، اور Control Center وہ کنٹرول چھپاتا ہے جو کوئی forge نہیں کر سکتا، بجائے اس کے کہ ایسا کنٹرول دکھائے جو خاموشی سے ناکام ہو۔

| صلاحیت                           | GitHub | GitLab | Bitbucket |
| -------------------------------- | :----: | :----: | :-------: |
| بیچ (زیرِ التواء) ریویوز         |   ✓    |   ✓    |     —     |
| تبدیلیاں مانگنا                  |   ✓    |   ✓    |     ✓     |
| فائل کے لحاظ سے "دیکھا گیا" حالت سنک |   ✓    |   —    |     —     |
| ایموجی ری ایکشنز                 |   ✓    |   ✓    |     —     |
| ٹیم / گروپ ریویورز               |   ✓    |   ✓    |     —     |
| تجویز کردہ ریویورز               |   ✓    |   —    |     ✓     |
| PR پر CI نتائج                   |   ✓    |   ✓    |     ✓     |
| CI job کے مراحل/لاگز کی تفصیل    |   ✓    |   ✓    |     —     |
| اسٹیک شدہ pull requests          |   ✓    |   —    |     —     |
| PR تفصیل کے ٹیمپلیٹس             |   ✓    |   ✓    |     —     |
| اطلاعات کی پولنگ                 |   ✓    |   —    |     —     |
| بھرپور صارف پروفائلز             |   ✓    |   ✓    |     —     |
| سرور کی جانب PR head ref         |   ✓    |   ✓    |     —     |

جہاں صلاحیت موجود نہ ہو، وہاں خصوصیت ایمانداری سے کم ہو جاتی ہے:

- **"دیکھا گیا" حالت** اب بھی کام کرتی ہے، لیکن صرف اس ڈیوائس پر جہاں آپ نے اسے سیٹ کیا۔
- Bitbucket پر **بیچ ریویوز** تبصرہ بہ تبصرہ پوسٹ ہوتے ہیں، اس لیے ریویورز انہیں ایک ایک کرکے آتے دیکھتے ہیں، ایک ساتھ نہیں۔
- Bitbucket پر **PR head ref نہ ہونے** کا مطلب ہے کہ pull request کو checkout کرتے وقت اس کی source branch نام سے لائی جاتی ہے، جو حذف ہونے کے بعد ناکام ہو جاتی ہے۔

## اصطلاحات

GitLab pull request کو **merge request** کہتا ہے۔ Control Center اپنے ماڈل میں ہر جگہ "pull request" کہتا ہے، اور جب کسی forge کی بات کرتا ہے تو اس forge کا اپنا نام استعمال کرتا ہے۔

## مسائل کا حل

### PR کی فہرست خالی ہے اور کہتی ہے کہ کوئی forge منسلک نہیں

اس forge کے لیے آپ کے پاس کوئی credential نہیں۔ **ترتیبات → آپ → پروفائل → کوڈ ہوسٹنگ** میں GitHub میں sign in کریں، یا GitLab یا Bitbucket ٹوکن چسپاں کریں۔ دوسرے forges کے ریپوز متاثر نہیں ہوتے۔

### میں نے forge جوڑا مگر اُس کے ریپوز پھر بھی کچھ نہیں دکھاتے

قطار کی حالت دیکھیں، پھر PR فہرست کے اوپر کی اطلاعات۔ "… مزید ریپوز کے pull requests دیکھنے کے لیے sign in کریں" کا مطلب ہے کہ آپ کا اپنا اکاؤنٹ ان ریپوز کے لیے منسلک نہیں؛ "… ریپوز چھپے ہیں کیونکہ آپ کا … اکاؤنٹ انہیں نہیں دیکھ سکتا" کا مطلب ہے کہ forge آپ کو رسائی نہیں دیتا۔ GitHub پر، ریپو رسائی کی اطلاع بتاتی ہے کہ GitHub App ریپو کی تنظیم پر انسٹال نہیں ہے یا اس میں ریپو شامل نہیں ہے۔

### GitLab یا Bitbucket ریپو پر پس منظر کا کام موقوف ہے

ریپو کے پاس کوئی آٹومیشن ٹوکن نہیں جو اسے پڑھ سکے۔ ایک ورک اسپیس ایڈمن اسے ریپو کے لیے یا پورے ورک اسپیس کے لیے شامل کرتا ہے؛ دیکھیں [آٹومیشن ٹوکن شامل کریں](#آٹومیشن-ٹوکن-شامل-کریں)۔ آپ کا اپنا ذاتی ٹوکن اسے بحال نہیں کرتا: پس منظر کا کام کبھی کسی رکن کا ٹوکن استعمال نہیں کرتا۔

### کوئی ریپو رجسٹر نہیں ہوتا

رجسٹریشن کے لیے تینوں شرائط درکار ہیں: راستہ git work tree کے اندر ہو، اس کا `origin` remote ہو، اور وہ remote github.com، gitlab.com یا bitbucket.org کی طرف اشارہ کرے۔ `origin` کا لازماً وہی ریپوزٹری ہونا چاہیے جسے آپ لنک کر رہے ہیں، اور ورک اسپیس کے اپنے اسٹوریج سے باہر کا فولڈر صرف سرور کا مالک لنک کر سکتا ہے۔ دیکھیں [workspace میں repos شامل کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/ریپوز-شامل-کریں/)۔

### میرے پاس گرانٹ ہے مگر ریپوزٹری کہتی ہے کہ میرا اکاؤنٹ اسے نہیں پڑھ سکتا

آپ کا اپنا forge اکاؤنٹ اس ریپوزٹری کو نہیں پڑھ سکتا، اس لیے اس کا کوڈ ورک اسپیس کی گرانٹ جو بھی کہے، آپ کے لیے بند رہتا ہے۔ اوپر **کوڈ ہوسٹنگ** کے تحت forge میں sign in کریں، یا forge پر اس ریپوزٹری تک رسائی حاصل کریں۔

### "آپ کی فورج تک رسائی کی تصدیق نہیں ہو سکی"

فورج کو جانچ کے لیے نہیں پہنچا جا سکا، اس لیے Control Center اندازہ لگانے کے بجائے انکار کر دیتا ہے۔ کچھ دیر بعد دوبارہ کوشش کریں۔

### ایک ریپوزٹری کہتی ہے کہ وہ اب ایک مختلف ریپوزٹری کی طرف اشارہ کرتی ہے

اس راستے کے پیچھے کی ریپوزٹری بدل گئی ہے: وہ حذف کر کے دوبارہ بنائی گئی، یا منتقل کر کے اس کی جگہ لی گئی۔ جب تک کوئی ورک اسپیس ایڈمن اطلاع یا ریپوزٹری کی قطار پر **دوبارہ لنک کریں** نہ دبائے، Control Center اسے کچھ نہیں بھیجتا۔ سادہ نام کی تبدیلی یا منتقلی خود بخود فالو ہو جاتی ہے اور یہ کبھی نہیں دکھاتی۔

### بھاری استعمال کے بعد کچھ دیر کے لیے سب کچھ کام کرنا بند کر دیتا ہے

یہ rate-limit circuit breaker ہے۔ جب کوئی forge اپنی بنیادی حد کا اشارہ دے، تو کلائنٹ مزید درخواستیں نیٹ ورک کال کے بغیر مقامی طور پر ناکام کرتا ہے جب تک وقفہ نہ گزر جائے — تاکہ retry کا طوفان حد کو اور گہرا نہ کر سکے۔ عارضی ناکامیوں کو exponential backoff کے ساتھ دوبارہ کوشش کیا جاتا ہے۔
