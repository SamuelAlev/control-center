یہ گائیڈ دکھاتی ہے کہ کسی بیرونی MCP کلائنٹ — Claude Code، کوئی ایڈیٹر یا MCP Inspector — کو Control Center کے اپنے ٹول سرور سے کیسے جوڑا جائے۔

Control Center **110** ٹولز رجسٹر کرتا ہے اور انہیں Model Context Protocol کے ذریعے پروٹوکول ورژن `2024-11-05` پر پیش کرتا ہے۔ آپ جن مکمل ٹول خاندانوں کی توقع کریں گے، وہ غائب ہیں: نہ میٹنگ یا کیلنڈر کے ٹولز ہیں اور نہ پروجیکٹ کے ٹولز۔

## اینڈ پوائنٹ تلاش کریں

MCP سطح اسی مرکزی `cc_server` لسنر کو شیئر کرتی ہے۔ MCP کے لیے کوئی الگ پورٹ نہیں ہے۔

| اینڈ پوائنٹ | میتھڈ   | مقصد                                                  |
| -------- | -------- | -------------------------------------------------------- |
| `/mcp`   | `POST`   | Streamable HTTP ٹرانسپورٹ — کلائنٹ اسی سے بات کرتا ہے |
| `/mcp`   | `DELETE` | سیشن ختم کریں                                            |
| `/sse`   | `GET`    | سرور کی بھیجی ہوئی اطلاعات کا اسٹریم                          |

چنانچہ ڈیفالٹ مقامی انسٹال `http://127.0.0.1:9030/mcp` پر ہوتا ہے۔

1. **ترتیبات → سرور → MCP سرورز** پر جائیں
2. **MCP سرور** کارڈ پڑھیں — یہ دکھاتا ہے کہ چل رہا ہے یا رک گیا، اور کس پورٹ پر سن رہا ہے

نئی انسٹال پر یہ سطح بطور ڈیفالٹ آن ہوتی ہے۔ کارڈ کا ٹوکن صرف سرور کا مالک دیکھتا ہے، اور صرف وہی اینڈ پوائنٹ شروع یا بند کر سکتا ہے۔ **ایپ لانچ پر شروع کریں** طے کرتا ہے کہ ری اسٹارٹ کے بعد یہ واپس آئے گا یا نہیں؛ **شروع** / **روکیں** سیشن کنٹرولز ہیں جو اس ترجیح کو نہیں بدلتے۔

سرور بطور ڈیفالٹ loopback پر بائنڈ ہوتا ہے، اس لیے یہ اینڈ پوائنٹ صرف اُسی مشین سے پہنچتا ہے جس پر `cc_server` چل رہا ہو، الا یہ کہ آپ نے اسے `--bind any` کے ساتھ شروع کیا ہو۔

## ٹوکن حاصل کریں

ہر درخواست کو سرور کا MCP ٹوکن درکار ہے، کسی بھی مشین سے، loopback سمیت۔ سرور اسے پہلی بار اسٹارٹ ہونے پر بناتا ہے۔ اسے بند کرنے یا صاف کرنے کا کوئی طریقہ نہیں ہے۔

1. **ترتیبات → سرور → MCP سرورز** پر، **تصدیقی ٹوکن** قطار تلاش کریں
2. **ٹوکن دکھائیں** دبائیں اور اسے کاپی کریں
3. اسے بدلنے کے لیے **ٹوکن بدلیں** دبائیں۔ سرور فوراً نئے ٹوکن پر منتقل ہو جاتا ہے، اور پرانا ٹوکن استعمال کرنے والا ہر کلائنٹ مسترد ہوتا ہے جب تک اسے نیا ٹوکن نہ دیا جائے

## کلائنٹ جوڑیں

اپنے کلائنٹ کو Streamable HTTP اینڈ پوائنٹ کی طرف لگائیں اور ٹوکن کو ہر درخواست پر `Authorization: Bearer <token>` کے طور پر بھیجیں، `GET /sse` سمیت۔ اس کا کوئی اور طریقہ نہیں: URL میں ٹوکن قبول نہیں ہوتا۔ کنفیگریشن کی صحیح شکل آپ کے کلائنٹ کی اپنی بات ہے۔

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code اسے پروجیکٹ کی `.mcp.json` سے نہیں اٹھائے گا — وہ پروجیکٹ اسکوپ والے MCP سرورز کو ایک منظوری کے پرامپٹ کے پیچھے رکھتا ہے، جس کا جواب غیر تعاملی `claude -p` کبھی نہیں دیتا۔ کنفیگ واضح طور پر پاس کریں:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` Claude کو صرف اسی فائل کے استعمال پر مجبور کرتا ہے، تاکہ وہی سرور پروجیکٹ سے بھی دریافت نہ ہو اور دو بار رجسٹر نہ ہو جائے۔

جانچ: کلائنٹ سے کہیں کہ اپنے ٹولز کی فہرست دے۔ آپ کو `mcp__*` اندراجات نظر آنے چاہئیں جو ٹکٹس، اسپیسز، میموری، کوڈ گراف اور ریویو کا احاطہ کرتے ہوں۔

## وہ کیا رد کرتا ہے

ٹوکن ہر ٹول کو کھولتا ہے، اس لیے اینڈ پوائنٹ وہ بھی رد کرتا ہے جو ایک ویب پیج بھیج سکتا تھا، ٹوکن دیکھنے سے پہلے:

| درخواست | جواب |
| ----------------------------------------------------------------------- | ------ |
| ایک `Origin` ہیڈر جو اس مشین کا پیج نہ ہو (`http://localhost`، `http://127.0.0.1` یا `http://[::1]`، کوئی بھی پورٹ) | `403`، "Cross-origin requests are not accepted" |
| ایک `Host` ہیڈر جو نہ اس لسنر کا loopback پتہ اور پورٹ ہو اور نہ سرور کا عوامی ہوسٹ نام | `403`، "Unknown host" |
| ایک `POST` جس کا body `application/json` نہ ہو | `415` |
| کوئی ٹوکن نہیں، یا غلط ٹوکن | `401` |

MCP سطح کو ہوسٹ سے باہر پیش کرنے کے لیے سرور کو `--bind any` کے ساتھ شروع کریں اور دوسری مشین سے ٹوکن بھیجیں، سرور کو اس کے عوامی ہوسٹ نام سے مخاطب کرتے ہوئے۔

## ہر کال کو ورک اسپیس تک محدود کریں

ہر وہ ٹول جو ورک اسپیس اسکوپ والا ڈیٹا چھوتا ہے، `workspace_id` مانگتا ہے، اور اس کے بغیر کال کسی ”موجودہ“ ورک اسپیس کے خلاف حل کرنے کے بجائے مسترد کر دی جاتی ہے:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

یہ id وہی ہے جو آپ کے براؤزر یا ایپ کے URL میں ہوتی ہے: `/workspaces/<workspace_id>/…`۔ واحد استثنا وہ ٹولز ہیں جو واقعی کئی ورک اسپیسز پر پھیلے ہوتے ہیں، مثلاً `list_workspaces` اور نیوز فیڈ ٹولز — نیوز فیڈ فی صارف ہوتی ہے اور ایجنٹ کا اپنا کوئی صارف نہیں ہوتا، اس لیے وہ ٹولز سرور کے مالک کی فیڈز پر کام کرتے ہیں۔

ریپو اسکوپ والے ٹولز اس کے علاوہ جانچتے ہیں کہ ریپو اُس ورک اسپیس سے لنک شدہ ہے۔

## جانیں کہ سطح کس چیز سے انکار کرے گی

- **موڈ گیٹنگ۔** کال سرور کی طرف سے کال کرنے والے ایجنٹ کے اسپیس کے موڈ کے خلاف حل کی جاتی ہے۔ صرف پڑھنے والے موڈ میں موجود ایجنٹ `space_id` چھوڑ کر کسی لکھنے والے ٹول تک نہیں پہنچ سکتا — موڈ اس کے فعال رن سے دیکھا جاتا ہے۔
- **ایکشن گارڈریلز۔** تبدیل کرنے والے ٹولز اپنی ایفیکٹ کلاسز کا اعلان کرتے ہیں اور وہی پالیسی استعمال کرتے ہیں جو باقی پورا پروڈکٹ استعمال کرتا ہے۔ [گارڈریلز کنفیگر کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/گارڈریلز-کنفیگر-کریں/) دیکھیں۔
- **تصدیق۔** کچھ تباہ کن ٹولز ایک تصدیقی پیلوڈ بناتے ہیں جسے کال کے آگے بڑھنے سے پہلے منظور کرانا ہوتا ہے۔

مکمل کیٹلاگ `tools/list` میں بغیر کسی ڈسکوری گیٹنگ کے ظاہر کیا جاتا ہے — کوئی بیرونی MCP کلائنٹ ایسا ٹول کال کرنے سے انکار کر دیتا ہے جو اس کی کیشڈ فہرست میں شامل نہ ہو، چنانچہ ٹولز چھپانا انہیں سنوارنے کے بجائے توڑ دیتا ہے۔

## ذاتی MCP سرورز مالک کے رہتے ہیں

یہ گائیڈ Control Center کے اپنے اینڈ پوائنٹ کے بارے میں ہے۔ دوسری سمت، یعنی وہ MCP سرورز جو Control Center اُن ایجنٹس کو دیتا ہے جو وہ چلاتا ہے، **ترتیبات → سرور → MCP سرورز → بیرونی MCP سرورز** کے تحت درج ہیں۔ سرور کی مشین پر Claude، Codex، Cursor، Gemini، VS Code، Windsurf، OpenCode کے لیے یا `.mcp.json` میں کنفیگر شدہ سرورز وہاں خودکار طور پر مل جاتے ہیں۔

یہ دریافت شدہ سرورز سرور صارف کی اپنی ٹول کنفیگریشن سے آتے ہیں اور اسی صارف کی شناخت اور اسناد کے ساتھ کام کرتے ہیں، اس لیے یہ سرور کے مالک کے ہیں:

- یہ صرف اُن built-in harness رنز کے اندر دستیاب ہیں جنہیں سرور کا مالک شروع کرتا ہے یا جن کا وہ ذمہ دار ہے، بشمول اُس ورک اسپیس کی خودکاری جس کا مالک ذمہ دار ہے۔
- کسی رکن کا رن، کسی رکن سے جڑی خودکاری، اور ہر وہ رن جو کسی ایسے سرور پر ہو جس کا کوئی ریکارڈ شدہ مالک نہ ہو، ان میں سے کوئی نہیں پاتا۔ وہاں ٹولز درج نہیں ہوتے، کال نہیں ہو سکتے، اور ٹول سرچ میں ظاہر نہیں ہوتے۔
- یہ اینڈ پوائنٹ انہیں کسی کے لیے بھی درج، کال یا سرچ نہیں کرتا، مالک کا ٹوکن بھی نہیں، اور نہ ہی ان کے ریسورسز یا پرامپٹس آگے بھیجتا ہے۔ اس لیے وہ ایجنٹ CLI جو MCP کے ذریعے Control Center تک پہنچتا ہے، جیسے Claude Code، انہیں Control Center کے ذریعے بھی نہیں پاتا؛ وہ اپنی کنفیگریشن استعمال کرتا ہے۔

ورک اسپیس کے لیے کنفیگر شدہ MCP سرورز پر ان میں سے کسی کا اثر نہیں ہوتا۔

## خرابیوں کا ازالہ

### کلائنٹ کو کوئی ٹول نظر نہیں آتا

- دیکھیں کہ **MCP سرور** کارڈ ”چل رہا ہے“ کہتا ہے
- دیکھیں کہ پورٹ آپ کے `cc_server` پورٹ سے میل کھاتا ہے
- Claude Code پر دیکھیں کہ آپ نے `--mcp-config` اور `--strict-mcp-config` پاس کیے ہیں

### 401 Unauthorized

درخواست میں کوئی ٹوکن نہیں تھا، یا پرانا ٹوکن تھا۔ **تصدیقی ٹوکن** قطار سے موجودہ ٹوکن کاپی کریں اور اسے `Authorization: Bearer <token>` کے طور پر بھیجیں۔ URL میں ٹوکن نظرانداز ہوتا ہے۔

### 403 from a client that worked before

درخواست میں ایک `Origin` تھا جو ویب پیج سے آیا تھا، یا ایک `Host` جس کا سرور جواب نہیں دیتا۔ اینڈ پوائنٹ کو براؤزر پیج کے بجائے کلائنٹ سے کال کریں، سرور کے loopback پتے یا اس کے عوامی ہوسٹ نام سے۔

### 415 Unsupported Media Type

`POST /mcp` کا body `application/json` کے طور پر بھیجیں۔

### کوئی ٹول کال ”Missing or invalid argument: workspace_id“ کے ساتھ ناکام ہوتی ہے

`workspace_id` شامل کریں۔ کوئی مضمر ورک اسپیس نہیں ہوتی۔

### کوئی ٹول کال نامعلوم قرار دے کر مسترد کر دی جاتی ہے

[MCP ٹولز](/ur-PK/ہدایت-نامہ/حوالہ/mcp-ٹولز/) میں کیٹلاگ درج ہے۔ نام ٹھیک ویسے ہی کال کریں جیسے وہاں لکھا ہو۔
