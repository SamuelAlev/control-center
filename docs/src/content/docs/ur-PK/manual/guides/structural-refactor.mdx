یہ گائیڈ دکھاتی ہے کہ کسی ایجنٹ سے وسیع میکانیکی تبدیلی کیسے کرائی جائے — کوئی کودم، کوئی بلک API منتقلی، کوئی ایسا پیٹرن جسے آپ ختم کرنا چاہتے ہیں — ساختی تلاش اور ری رائٹ کے ذریعے، اور تبدیلی کچھ بھی لکھے جانے سے پہلے جائزے کے لیے اسٹیج کر دی جائے۔

`ast_grep` کوڈ کو **شکل** سے میچ کرتا ہے۔ `ast_edit` اسے دوبارہ لکھتا ہے۔ `resolve` کمٹ یا مسترد کرتا ہے۔

## شروع کرنے سے پہلے

ساختی ٹولز اُن زبانوں کا احاطہ کرتے ہیں جو کوڈ گراف پارس کرتا ہے: Dart، JavaScript، TypeScript، TSX، PHP، Python، Rust، Zig، C، C++، Go، Java، Ruby، C#، Swift، Kotlin، R، Assembly، MATLAB اور Ada۔ انہیں tree-sitter گرامرز اسٹیج شدہ چاہیے ہوتے ہیں، جو شپ شدہ بلڈ میں ہمیشہ ہوتے ہیں — گرامر کی کمی تلاش کو کمزور کرنے کے بجائے سرور روک دیتی ہے۔

## پہلے ساخت ڈھونڈیں

جس چیز کو آپ نے دیکھا نہ ہو، اُسے کبھی دوبارہ نہ لکھیں۔ ایجنٹ سے تلاش کرنے کو کہیں:

> ہر وہ جگہ ڈھونڈیں جہاں ہم کسی نل ایبل پر `dispose()` کال کرتے ہیں جس کا ابھی null چیک کیا گیا ہو۔

```
ast_grep(pattern: "if ($X != null) $X.dispose()", language: "dart")
```

آؤٹ پٹ ہر جگہ کے لیے `file:line` کے ساتھ میچ شدہ سورس پر مشتمل ہوتا ہے۔

### پیٹرن سنٹیکس آپ کو کیا دیتی ہے

| ٹوکن       | میچ                                        |
| ---------- | ------------------------------------------ |
| `$NAME`    | کوئی ایک نوڈ، کیپچر شدہ                     |
| `$$$NAME`  | بہن بھائیوں کا کوئی بھی تسلسل — آرگیومنٹس، اسٹیٹمنٹس |
| `$_`       | کچھ بھی، بغیر نام کے کیپچر شدہ               |

اہم بات یہ ہے: **دہرایا گیا `$NAME` لازماً وہی متن پکڑتا ہے**۔

```
if ($X != null) $X.dispose()
```

یہ ایسی گارڈ ڈھونڈتا ہے جو اُسی چیز کو ڈسپوز کرے جس کی اس نے جانچ کی تھی۔ یہ `if (a != null) b.dispose()` **نہیں** ڈھونڈتا — جو عموماً وہی بگ ہوتا ہے جس کی آپ کو تلاش تھی۔ کوئی متنی تلاش اس کا اظہار نہیں کر سکتی۔

:::note[یہ کسی سٹرنگ یا تبصرے کے اندر میچ نہیں کر سکتا]
پیٹرن اُسی گرامر سے پارس ہوتا ہے جو فائل کا ہوتا ہے، چنانچہ کسی doc comment یا سٹرنگ لٹرل میں لکھا گیا `dispose(x)` کوئی کال نہیں اور اس سے میچ نہیں ہوتا۔ `grep` کے بجائے اسے استعمال کرنے کی پوری وجہ یہی ہے۔
:::

### جب پیٹرن کچھ نہ ڈھونڈے

دو چیزیں ہیں جو ترتیب سے آزمائیں:

1. **اسے چھوٹا کریں۔** `if (a) { foo($X); }` سے پہلے `foo($X)`۔ جو پیٹرن اپنے طور پر درست کوڈ نہ ہو، وہ عموماً وہی ساخت بھی نہیں ہوتا جو آپ کا مطلب تھا۔
2. **زبان کا نام دیں۔** `language:` صرف اُس وقت خود بخود سمجھا جاتا ہے جب `path` کسی ایک فائل کا نام لے۔

جو پیٹرن کوئی پارس سیاق قبول نہ کرے، اُسے ناقابلِ پارس بتا دیا جاتا ہے — ٹول ایسی چیز کے لیے "کوئی میچ نہیں" بتانے کے بجائے صاف کہہ دیتا ہے، جسے کبھی اُس نظر سے پڑھا ہی نہیں جا رہا تھا جیسا وہ دکھتا ہے۔

## دوبارہ لکھیں، اور نافذ ہونے سے پہلے دیکھ لیں

```
ast_edit(
  pattern: "if ($X != null) $X.dispose()",
  rewrite: "$X?.dispose()",
  language: "dart",
)
```

نتیجہ ایک **تجویز** ہوتا ہے:

```
(proposed) ast_edit: if ($X != null) $X.dispose() → $X?.dispose()
12 replacements in 4 files:
  lib/features/a/x.dart (3)
  lib/features/b/y.dart (5)
  …
Nothing has been written. Call resolve with edit_id "edit_1" and action
"accept" to apply it, or "discard" to drop it.
```

ابھی ڈسک پر کچھ نہیں۔ فہرست پڑھیں، تلاش کے بتائے ہوئے ایک آدھ مقام کا جائزہ لیں، پھر:

```
resolve(edit_id: "edit_1", action: "accept")
```

یا

```
resolve(edit_id: "edit_1", action: "discard")
```

:::caution[کمٹ سب یا کچھ نہیں]
ہر فائل کا موازنہ اُس مواد سے کیا جاتا ہے جو تبدیلی کے اسٹیج ہونے کے وقت محفوظ کیا گیا تھا۔ اگر ان میں سے کوئی ایک بھی بدل چکی ہو — ایجنٹ نے اسے ہاتھ سے ایڈٹ کر دیا، کوئی فارمیٹر چل گیا، کسی تشخیصی پاس نے اسے دوبارہ لکھ دیا — تو **پوری** تبدیلی مسترد اور ضائع کر دی جاتی ہے۔ ادھورا لاگو ہوا ساختی ری رائٹ ایسا درخت چھوڑتا ہے جو نہ پرانی شکل میں کمپائل ہوتا ہے نہ نئی میں۔

ٹول موجودہ فائلوں کے خلاف دوبارہ چلائیں؛ پرانی id کے ساتھ دوبارہ کوشش نہ کریں۔
:::

## کمپائلر سے اپنے کام کی جانچ کریں

اسے ساختی طور پر کرنے کا مقصد یہی ہے کہ یہ وسیع ہوتا ہے۔ وسیع تبدیلیاں بالکل وہیں ہوتی ہیں جہاں کوئی صحیح دکھنے والا ری رائٹ کوئی ٹائپ توڑ دیتا ہے۔ تجویز طے ہو جانے کے بعد تشخیص طلب کریں:

```
lsp(action: "diagnostics", file: "*")
```

`file: "*"` فی فائل کوئری کے بجائے پروجیکٹ کا اپنا چیکر (`dart analyze`، `tsc --noEmit`، `cargo check`، `go build`) چلاتا ہے — چالیس فائلوں کو چھونے والی تبدیلی کے بعد سوال کی صحیح شکل یہی ہے۔

## مکمل مثال: ایک کال کی منتقلی

فرض کریں `log(msg, level)` اب `log(level: level, message: msg)` بن رہا ہے۔

```
ast_grep(pattern: "log($MSG, $LEVEL)", language: "dart")
```

ملنے والی جگہیں دیکھیں۔ اگر ان میں سے کچھ کوئی *دوسرا* دو آرگیومنٹ والا `log` ہو، تو فرق کو پیٹرن میں بیان کرنے کی کوشش کے بجائے پیٹرن کو تنگ کریں اور `path` کو اُس ڈائریکٹری تک محدود کر دیں جس کا وہ `log` ہے جو آپ کا مطلب ہے۔

```
ast_edit(
  pattern: "log($MSG, $LEVEL)",
  rewrite: "log(level: $LEVEL, message: $MSG)",
  path: "lib/features/telemetry",
  language: "dart",
)
```

پھر `resolve`، پھر `lsp(action: "diagnostics", file: "*")`۔
