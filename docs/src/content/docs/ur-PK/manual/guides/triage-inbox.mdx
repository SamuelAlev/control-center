یہ گائیڈ دکھاتی ہے کہ ان باکس پر کام کیسے کریں: وہ واحد سطح جو ہر اُس چیز کو جمع کرتی ہے جو آپ کو روکے یا واضح طور پر آپ کو طلب کرے — زیر التوا ایجنٹ منظوریاں، ناکام ٹکٹ سنکس اور ہر وہ pull request جس میں آپ بطور ریویوور یا مصنف شامل ہوں۔

## ان باکس کھولیں

1. سائیڈبار میں **ان باکس** پر کلک کریں۔ اُس کا بیج زیر التوا ایجنٹ منظوریاں، ناکام سنکس اور آپ کے ریویو کے منتظر کھلے PRs گنتا ہے۔
2. یا <kbd>⌘K</kbd> دبائیں اور **ان باکس** نیویگیشن کمانڈ چلائیں۔
3. یا سیدھا `/workspaces/<workspace-id>/inbox` پر ڈیپ لنک کریں۔

سائیڈبار کی یہ اندراج ہمیشہ لائیو گنتی دکھاتی ہے، چنانچہ صفحہ کھولے بغیر آپ دیکھ سکتے ہیں کہ ٹرائیج کا کام جمع ہوتا جا رہا ہے۔

## ایک نظر میں شدت پڑھیں

اوپر سے نیچے تک دیکھیں؛ ان باکس پہلے ہی عجلت کے مطابق ترتیب دیا ہوا ہے:

1. پن شدہ **آپ کی توجہ درکار** پٹی PR سیکشنز کے اوپر بیٹھتی ہے۔ ہر کارڈ پر شدت کی چپ ہوتی ہے۔ رجسٹرڈ ذرائع (کوئی ایجنٹ جو تصدیقی پرامپٹ پر اٹکا ہو، کوئی ٹکٹ سنک جس کا وینڈر مرر پرانا ہو) **بلاک** خارج کرتے ہیں۔
2. پٹی کے اندر سب سے زیادہ عجلت پہلے آتی ہے؛ برابر ہونے پر وہ آئٹم آگے آتا ہے جو سب سے طویل انتظار میں رہا ہو۔
3. پٹی کے نیچے، PRs مقررہ ریویو لائف سائیکل سیکشنز میں گروپ ہوتے ہیں —
   **آپ کے ریویو کی ضرورت**، **آپ کو واپس**، **منظور**، **ڈرافٹس**،
   **ریویوورز کا انتظار**، **مرج ہو رہا ہے اور حال ہی میں مرج**، **مصنف کا
   انتظار**۔ اوپر والے سیکشنز وہ ہیں جنہیں _آپ_ درکار ہیں؛ باقی وہ جگہ ہے جہاں _آپ_ کے
   PRs کی حالت ہے۔ **آپ کے ریویو کی ضرورت** میں وہ PRs بھی شامل ہوتے ہیں جو ایسے
   کوڈ ہوسٹس پر اب بھی کسی ایسی ٹیم کا ریویو طلب کرتے ہیں جس کا آپ رکن ہوں (GitHub
   ٹیم کو ہٹا دیتا ہے جب کوئی ساتھی ریویو کر لے)۔

آئٹم ان باکس میں صرف اُس وقت آتا ہے جب وہ کسی چیز کو روکے یا واضح طور پر
آپ کو طلب کرے۔ خالی پٹی کے ساتھ خالی سیکشن فہرست **آپ سب
دیکھ چکے ہیں** صرف اُس وقت دکھاتی ہے جب وہ خالی پن قابلِ اعتماد ہو۔

## ہر کوڈ ہوسٹ پر ایک ہی ان باکس

اگر ورک اسپیس میں ایک سے زیادہ کوڈ ہوسٹس کے ریپوز ہوں تو ان باکس اُنہیں
ایک ہی سلسلے میں ضم کر دیتا ہے — ایک GitHub pull request اور ایک Bitbucket pull request ایک
ہی سیکشن میں بیٹھتے ہیں، وینڈر کے حساب سے گروپ ہونے کے بجائے وقت کے مطابق ترتیب پاتے
ہیں۔ قطار کا `repo #number` میٹا ہی ان میں فرق بتاتا ہے۔

"آپ کا" کا تعین **ہر کوڈ ہوسٹ کے حساب سے** ہوتا ہے، کیونکہ ہر ایک پر آپ کا اکاؤنٹ الگ ہوتا ہے۔
کوئی pull request آپ کا، یا آپ کے ریویو کی درخواست کرنے والا، صرف اُس وقت شمار ہوتا ہے جب وہ
اُس کوڈ ہوسٹ پر آپ کی شناخت سے مماثل ہو جہاں وہ ریپو واقعی موجود ہے۔

جو کوڈ ہوسٹ بند ہو یا جڑا ہوا نہ ہو وہ کچھ نہیں ڈالتا اور ان باکس کے باقی حصے
کو جوں کا توں رکھتا ہے — ایک ٹوٹا کنکشن کبھی پوری فہرست خالی نہیں کرتا۔ خالی
حالت **آپ سب دیکھ چکے ہیں** کے بجائے ایک انتباہ بتاتی ہے جب ہر کوڈ ہوسٹ کا
لاگ اِن ابھی تک حل نہ ہوا ہو (**آپ کا GitHub اکاؤنٹ تصدیق نہیں ہو سکا** — عبارت میں پھر بھی
GitHub کا نام آتا ہے)، جب githubstatus.com کسی واقعے کی اطلاع دے، یا جب منسلک
ریپوز کا احاطہ کرنے والا GitHub App انسٹال معطل ہو۔

## توجہ کی پٹی صاف کریں

پٹی کے ہر کارڈ کا ایک ہی اگلا عمل ہوتا ہے:

1. اگر کارڈ کوئی زیر التوا ایجنٹ تصدیق ہو تو **ریویو** پر کلک کریں — آپ
   اُس ایجنٹ کی اسپیس میں اُس کی زیر التوا تصدیق کے ساتھ پہنچ جاتے ہیں۔ وہیں منظوری دیں یا مسترد کریں
   ([ایجنٹ سے چیٹ کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/ایجنٹ-سے-چیٹ/) دیکھیں)۔
2. اگر کوئی کارڈ کسی وینڈر کے لیے **سنک ناکام** کہے تو **کھولیں** پر کلک کریں — آپ
   **ترتیبات → ورک اسپیس → عام** پر پہنچ جاتے ہیں، جہاں کا **سنک صحت** کارڈ ہر
   کنکشن کا آخری سنک، مسلسل ناکامیوں کا سلسلہ اور تازہ ترین نتیجہ دکھاتا ہے۔ ان باکس میں ہر
   وینڈر کی صرف تازہ ترین ناکامی آتی ہے، چنانچہ سنک بحال ہوتے ہی کارڈ غائب ہو جاتا ہے۔
3. بنیادی حالت حل ہوتے ہی (ایجنٹ کو جواب مل جائے، سنک بحال ہو جائے) کارڈز خود بخود غائب ہو
   جاتے ہیں — دستی طور پر ہٹانے کے لیے کچھ نہیں ہوتا۔

:::note[یہ فی باری تصدیقاں ہیں، گورننس کی منظوریاں نہیں]
"ایجنٹ منظوری" کارڈ ایک چلتے ایجنٹ کا اپنی ہی گفتگو میں کسی ایک
عمل کی اجازت مانگنے کے لیے رکنا ہے۔ یہ اُس گورننس
`Approval` ریکارڈ سے الگ چیز ہے جو ایجنٹس منظوری کے MCP ٹولز سے بناتے ہیں — ایپ میں اُن کے لیے
کہیں کوئی انسانی اسکرین نہیں اور وہ یہاں کبھی ظاہر نہیں ہوتے۔
:::

:::caution[سنک صحت صرف پڑھنے کے لیے ہے]
یہ کارڈ ٹکٹ سنک کنکشنز کی رپورٹ دیتا ہے؛ **اب سنک کریں** بٹن کے سوا یہ
کسی کنکشن کو بنا، بدل یا دوبارہ جوڑ نہیں سکتا اور کوئی اور اسکرین بھی یہ نہیں کر سکتی۔ کوئی
کنکشن کنفیگر نہ ہو تو یہ صرف "ابھی کوئی سنک کنکشن نہیں" پڑھتا ہے،
جو ایک نئے ورک اسپیس میں دکھتا ہے۔
:::

## صرف روکنے والی چیزوں تک فلٹر کریں

1. فلٹر مینو کھولنے کے لیے <kbd>f</kbd> دبائیں (جب کوئی ٹیکسٹ فیلڈ فوکس میں نہ ہو)، یا
   ٹول بار میں فلٹر بٹن پر کلک کریں۔
2. اسٹیٹس، مصنف، ریویوورز، مواد، ریپو
   مالک/نام، تاریخ کی حدود، یا فوری ریویو کے قابل — کا کوئی بھی امتزاج چنیں۔ مینو میں فیسٹ کی گنتیاں بتاتی
   ہیں کہ ہر آپشن کتنے ان باکس آئٹمز سے مماثل ہے۔
3. فعال فلٹرز فہرست کے اوپر والی پٹی میں چپس کی صورت میں ظاہر ہوتے ہیں؛ اُس
   معیار کو ہٹانے کے لیے کسی چپ کے ✕ پر کلک کریں۔
4. سیکشنز کے درمیان جانے کے لیے بائیں ریل استعمال کریں — ہر اندراج اپنی لائیو
   گنتی دکھاتی ہے اور نمایاں حصہ آپ کے اسکرول کی پوزیشن کے ساتھ چلتا ہے۔ جن سیکشنز کو آپ
   ٹرائیج نہیں کرتے اُنہیں سمیٹنے کے لیے سیکشن ہیڈر پر کلک کریں (مثلاً ریویوز نمٹاتے وقت
   **ڈرافٹس**)۔
5. ہر سیکشن کو ترتیب دینے کے لیے کالم ہیڈر (عنوان، تبدیلیاں، یا اپ ڈیٹ) پر کلک کریں؛
   سمت پلٹنے کے لیے فعال کالم پر دوبارہ کلک کریں۔ ڈسپلے آپشنز بٹن
   ڈرافٹ کی نمائش، حال ہی میں مرج شدہ کی ونڈو، قطار کی خصوصیات،
   ترتیب اور گروپ بندی کو کنٹرول کرتا ہے (ان باکس لے آؤٹ صرف مصنف کے حساب سے گروپ بندی سے بدلتا ہے)۔

یہاں کے فلٹرز PR قطار سے آزاد ہیں — ان باکس کو تنگ کرنا کبھی
قطار کے فلٹرز نہیں بدلتا اور نہ اِس کے برعکس۔

## کسی PR آئٹم پر عمل کریں

1. PR تفصیل کا صفحہ کھولنے کے لیے کسی بھی قطار پر کلک کریں۔
2. اگر PR **آپ کے ریویو کی ضرورت** میں ہو تو اُس کا ریویو کریں اور اپنا فیصلہ جمع کرائیں —
   [PR ریویو اور مرج کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/pr-ریویو-اور-مرج/) دیکھیں۔
3. اگر PR **آپ کو واپس** میں ہو (تبدیلیاں طلب کی گئی ہوں یا CI ناکام ہوا ہو) تو اپنے
   چیک آؤٹ سے فکسز پش کریں یا فالو اپ کسی ایجنٹ کے حوالے کر دیں۔
4. اگر PR **منظور** میں ہو تو اُسے تفصیل کے صفحے سے مرج کریں۔
5. اگر آپ خود ریویو کرنے کے بجائے کوئی ریویو کسی اور کے سپرد کرنا پسند کریں تو
   [ریویوور ایجنٹس بھیجیں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/ریویوور-ایجنٹس-بھیجیں/) اور
   [ڈسپیچ لائف سائیکل](/ur-PK/ہدایت-نامہ/تصورات/ڈسپیچ-لائف-سائیکل/) دیکھیں۔

بنیادی حالت بدلتے ہی (آپ کا ریویو جمع ہو جائے، PR مرج ہو جائے)،
درجہ بند کرنے والا PR کو خود بخود اُس کے نئے سیکشن میں منتقل کر دیتا ہے۔

## غلطی سے کیا گیا عمل واپس کریں

1. آخری عمل واپس کرنے کے لیے <kbd>⌘Z</kbd> دبائیں، اُسے دہرانے کے لیے <kbd>⌘⇧Z</kbd>۔
2. اگر کوئی ٹیکسٹ فیلڈ فوکس میں ہو تو ⌘Z اُس کے بجائے فیلڈ کا متن بدلتا ہے — ایپ
   سطح کا عمل واپس کرنے کے لیے پہلے فیلڈ سے باہر کلک کریں۔

## شارٹ کٹس وہیں دیکھ لیں

کی بورڈ چیٹ شیٹ کھولنے کے لیے <kbd>?</kbd> دبائیں (جب کوئی ٹیکسٹ فیلڈ فوکس میں نہ ہو)۔ یہ
موجودہ روٹ پر فعال ہر بائنڈنگ کی فہرست دیتی ہے، جس میں ان باکس کا <kbd>f</kbd>
فلٹر شارٹ کٹ بھی شامل ہے۔ مکمل نقشہ
[کی بورڈ شارٹ کٹس کے حوالے](/ur-PK/ہدایت-نامہ/حوالہ/کی-بورڈ-شارٹ-کٹس/) میں ہے۔

## کمانڈ پیلیٹ سے چلائیں

1. کہیں بھی کمانڈ پیلیٹ کھولنے کے لیے <kbd>⌘K</kbd> دبائیں۔
2. صفحے پر جانے کے لیے **ان باکس** ٹائپ کریں، یا کوئی PR عنوان ٹائپ کریں — پیلیٹ
   مماثل pull requests کی فہرست دکھاتا ہے اور آپ جو چنیں وہ کھول دیتا ہے۔
3. ان باکس کھلا ہونے کے دوران، وہ URL شیئر کرنے کے لیے کاپی کرنے کی خاطر
   **اس صفحے کا لنک کاپی کریں** چلائیں۔ یہ کمانڈ موجودہ روٹ کاپی کرتی ہے، چنانچہ یہ ان باکس کا URL
   صرف اُس وقت ہوتا ہے جب آپ اِسی صفحے پر ہوں۔

## طلب پر ریفریش کریں

ان باکس لائیو اپ ڈیٹ ہوتا ہے، لیکن اگر آپ کو پرانے ڈیٹا کا شک ہو تو ٹول بار میں ریفریش
کنٹرول پر کلک کریں — یہ ہر جڑے کوڈ ہوسٹ کا فوری سرور طرفی جھاڑو لگاتا ہے
اور مرج شدہ/ریویو شدہ اوورلیز دوبارہ لاتا ہے۔ ہر فیچ مکمل ہونے تک آئیکن گھومتا رہتا ہے۔
