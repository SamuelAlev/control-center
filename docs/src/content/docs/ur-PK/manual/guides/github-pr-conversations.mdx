یہ گائیڈ دکھاتی ہے کہ GitHub چھوڑے بغیر Control Center کے ساتھ کیسے کام کریں: PR صفحے سے AI ریویو مانگیں، کسی تبصرے میں بوٹ سے سوال پوچھیں، اور اس کے ریویو تھریڈز میں گفتگو جاری رکھیں۔

جوابات workspace کی GitHub lane سے آتے ہیں: سرور کی اپنی [GitHub App](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/github-app/)، یا Connect کے ذریعے Control Center کی مشترکہ App۔ کچھ نیا رجسٹر نہیں ہوتا اور کچھ انٹرنیٹ سے قابلِ رسائی نہیں ہونا چاہیے: سرور GitHub پر کہی گئی باتوں کو polling کے ذریعے دریافت کرتا ہے، اس لیے NAT کے پیچھے لیپ ٹاپ بالکل عوامی deploy کی طرح برتاؤ کرتا ہے۔

## پیشگی شرائط

- workspace کی ایک GitHub lane ہو: سرور کی اپنی GitHub App یا Connect، جس کی app اس اکاؤنٹ پر [انسٹال](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/github-app/#انسٹال-کریں-جہاں-آپ-کے-repositories-ہیں) ہو جس کی ملکیت میں repository ہے۔ اپنی app کو **Pull requests** اور **Issues** پر read اور write درکار ہے، جو **میری GitHub ایپ بنائیں** پہلے سے دیتی ہے
- repository Control Center میں کسی workspace سے جڑی ہو
- آپ اس سرور پر [GitHub میں sign in](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/github-انضمام/) ہوں اور repository پر push کر سکتے ہوں
- کوئی webhook URL نہیں، کوئی tunnel نہیں، کوئی callback نہیں — نیٹ ورک کی طرف سے ترتیب دینے کو کچھ نہیں

## اپنے بوٹ کا نام تلاش کریں

`@usectrl` کو mention کریں، یعنی Control Center کا مخصوص GitHub اکاؤنٹ۔ یہ ڈیفالٹ محرک ہے؛ آپ کی workspace کی GitHub lane پھر بھی درخواست سنبھالتی ہے اور جوابات پوسٹ کرتی ہے۔ `usectrl` اکاؤنٹ کے لیے آپ کو کسی credential کی ضرورت نہیں۔

app کا اپنا login، `<appslug>[bot]`، اور مختصر `@appslug` شکل بھی کام کرتی ہے۔ اپنی app پر اس اختیاری عرف کو تلاش کرنے کے لیے:

1. **ترتیبات → سرور → سنگل سائن آن** پر جائیں اور **فراہم کنندہ ایپس** کارڈ تک اسکرول کریں
2. **GitHub** بلاک کھولیں اور **ٹیسٹ** پر کلک کریں
3. **بوٹ لاگ اِن** بھرنے پر اسے کاپی کریں۔ اگر اب بھی خالی اشارہ دکھائے تو login ہمیشہ `<appslug>[bot]` ہوتا ہے — وہی ٹائپ کریں، یا مختصر `@appslug`

GitHub `@` کی خودکار تکمیل میں app اکاؤنٹس نہیں دیتا، اس لیے app کے عرف ٹائپ یا کاپی کرنے ہوں گے۔ مخصوص `@usectrl` user ڈیفالٹ کال ہے؛ `@myapp` اور `@myapp[bot]` دونوں app کے قبول شدہ عرف رہتے ہیں۔

:::note[ایک منفرد app کا نام چنیں]
مختصر شکل بطور متن ملائی جاتی ہے۔ اگر کوئی انسانی GitHub user آپ کی app کا slug رکھتا ہو، تو اس user کو مختصر شکل میں mention کرنے سے بھی بوٹ تک بات پہنچ جائے گی۔ مکمل شکل `@myapp[bot]` ہمیشہ بے ابہام ہے۔
:::

## GitHub سے ریویو کی درخواست

دو طریقے، جو دونوں وہی seeded `pr_review` پائپ لائن شروع کرتے ہیں جو **AI سے پوچھیں** بٹن شروع کرتا ہے:

- PR پر **`ai-review` لیبل شامل کریں**۔ یہ GitHub کی طرف سے بوٹ کو ریویور بنانے کے قریب ترین طریقہ ہے، کیونکہ app اکاؤنٹس مقامی requested-reviewer جگہ نہیں رکھ سکتے۔ آپ کا اکاؤنٹ PR پر 👀 ری ایکشن دیتا ہے اور ریویو Control Center میں شروع ہوتا ہے؛ کوئی تبصرہ پوسٹ نہیں ہوتا
- PR گفتگو میں **`@usectrl review`** (یا صرف `@usectrl`) لکھیں۔ آپ کے تبصرے پر 👀 ظاہر ہوتا ہے، پھر ایک جواب بتاتا ہے کہ ریویو شروع ہو گیا (یا ایک پہلے ہی چل رہا ہے)

ریویور PR کی review space میں کام کرتے ہیں؛ نتائج پڑھیں اور انہیں اسی طرح شائع کریں جیسا [AI سے چلنے والا ریویو استعمال کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/ai-ریویو/) میں ہے۔ GitHub پر واپس شائع کرنا Control Center میں آپ کا فیصلہ ہی رہتا ہے — GitHub سے ریویو شروع کرنا خود سے GitHub پر کچھ شائع نہیں کرتا۔

لیبل ہر PR کے لیے ایک بار فائر ہوتا ہے: اسے شامل کرنا درخواست ہے، اور ہٹا کر دوبارہ شامل کرنے سے یہ دوبارہ فعال نہیں ہوتا۔ کسی push کے بعد دوبارہ ریویو کے لیے بوٹ کو mention کریں۔

## ایک سوال پوچھیں

PR گفتگو میں تبصرہ کریں:

```text
@usectrl why does the flaky test in runner_test.dart fail on CI but not locally?
```

ترتیب سے کیا ہوتا ہے:

1. آپ کے تبصرے پر 👀 ظاہر ہوتا ہے، آپ کے اپنے اکاؤنٹ سے، تاکہ آپ جانیں کہ تبصرہ دیکھا گیا
2. سوال PR کی review space میں **آپ کے نام سے** پوسٹ ہوتا ہے — وہی انتساب جو اس صورت میں ہوتا جب آپ اسے Control Center میں ٹائپ کرتے
3. space میں ایک ایجنٹ جواب دیتا ہے، اور جواب PR پر واپس پوسٹ ہوتا ہے۔ ہر جواب `**Control Center** (for @your-login):` سے شروع ہوتا ہے

ایسے PR پر سوال جس کا ابھی کوئی ریویو نہ ہو CEO ایجنٹ کو جگاتا ہے؛ ایک ریویو چلنے کے بعد، آخری بار بات کرنے والا ایجنٹ جواب دیتا ہے، تاکہ فالو اپس اسی کے پاس جائیں جس کے پاس سیاق ہو۔

## ریویو تھریڈ میں فالو اپ کریں

اس inline ریویو تھریڈ کے اندر جواب دیں جس کا بوٹ حصہ ہے — وہ diff تبصرہ جو اس نے چھوڑا، یا وہ جواب جو اس نے اس تھریڈ میں پوسٹ کیا۔ کسی mention کی ضرورت نہیں؛ تھریڈ خود پتہ ہے:

```text
> @usectrl the retry loop looks O(n²) to me

what would the complexity be with the bounded queue instead?
```

کئی مراحل پر مبنی گفتگو اسی طرح کام کرتی ہے: ہر جواب اسی گفتگو میں ایک اور سوال ہوتا ہے، review space سیاق کے طور پر، اور جواب اسی تھریڈ میں واپس آتا ہے۔

PR گفتگو کی timeline پر فالو اپ ایک نیا اعلیٰ سطحی تبصرہ ہوتا ہے، اس لیے اسے پھر بھی mention کی ضرورت ہوتی ہے۔

## بوٹ کس سے بات کرتا ہے

سرور تبصرے کے مصنف، یا جس نے `ai-review` لیبل شامل کیا، اسے کچھ کرنے سے پہلے پہچانتا ہے:

- **GitHub اکاؤنٹ اس سرور پر sign in ہونا چاہیے**۔ مطابقت GitHub کے عددی account id پر ہوتی ہے، کبھی login پر نہیں۔ **ترتیبات → ورک اسپیس → پروفائل اور شناخت → کوڈ ہوسٹنگ** سے sign in کریں
- **وہ workspace میں لکھنے کے role والا رکن ہو** (`member`، `admin` یا `owner`) جو repository کو جوڑتا ہے
- **وہ GitHub پر repository میں push کر سکے**۔ جوابات اس شخص کی رسائی تک محدود ٹوکن استعمال کرتے ہیں، اس لیے جو صرف پڑھ سکتا ہے اسے جواب نہیں ملتا

باقی ہر کوئی خاموشی سے نظرانداز ہوتا ہے: کچھ پوسٹ نہیں ہوتا، اور اس کے الفاظ کبھی workspace میں داخل نہیں ہوتے۔ بوٹ اکاؤنٹس کے تبصرے، اور خود Control Center کے جوابات، کبھی سوال نہیں سمجھے جاتے۔

### دو سرور، ایک PR

👀 یہ بھی طریقہ ہے جس سے سرورز طے کرتے ہیں کہ کون جواب دے۔ یہ مصنف کے اپنے sign-in کے ساتھ شامل ہوتا ہے، اور GitHub سرور کو بتاتا ہے کہ آیا وہ ری ایکشن نیا ہے۔ اگر آپ دو Control Center سرورز پر sign in ہیں جو دونوں repository کو جوڑتے ہیں، تو جو پہلے ری ایکٹ کرے وہ جواب دیتا ہے اور دوسرا خاموش رہتا ہے۔ لیبل کے لیے بھی یہی ہے۔

## کیا توقع رکھیں

| چیز                  | رویہ                                                                                                                                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| تصدیق                | تبصرے پر آپ کے اکاؤنٹ سے 👀 (یا لیبل کے لیے PR پر)، ایک sweep کے اندر                                                                                                                                             |
| جوابات               | اس راستے میں پوسٹ ہوتے ہیں جس میں سوال پوچھا گیا، اور `**Control Center** (for @your-login):` سے شروع ہوتے ہیں۔ اپنی app پر مصنف بوٹ `[bot]` اکاؤنٹ ہوتا ہے؛ Connect کے ذریعے یہ آپ کا اکاؤنٹ ہوتا ہے جو مشترکہ App کے ذریعے عمل کرتا ہے |
| space میں انتساب     | سوال آپ کا ہے؛ ایجنٹ آپ کی جانب سے، space کی خودمختاری کی ترتیبات کے تحت چلتا ہے                                                                                                                                 |
| ریویوز               | نتائج review space میں آتے ہیں؛ GitHub پر شائع کرنا دستی ہے                                                                                                                                                       |

اپنی app پر sweep ہر منٹ چلتا ہے اور زیادہ سے زیادہ 25 pull requests چیک کرتا ہے؛ Connect کے ذریعے یہ ہر دو منٹ چلتا ہے اور زیادہ سے زیادہ 10 چیک کرتا ہے، کیونکہ وہ کالیں ہر رکن کے اپنے GitHub کوٹے کو بانٹتی ہیں۔ وہ workspace جس کا GitHub کوٹہ 15% سے کم ہو، بحالی تک چھوڑ دیا جاتا ہے۔ تاخیر اس قیمت ہے جو کسی بھی inbound نیٹ ورک رسائی کی ضرورت نہ ہونے کے لیے دی جاتی ہے۔ سرور بند ہونے کے دوران کچھ ضائع نہیں ہوتا — ڈاؤن ٹائم کے دوران آنے والا تبصرہ اگلے sweep میں پکڑا جاتا ہے۔

## خرابیوں کا ازالہ

**بوٹ کو mention کرنے والے تبصرے پر کچھ نہیں ہوتا۔**

- کیا app اس اکاؤنٹ پر **انسٹال** ہے جس کی ملکیت میں repo ہے، اور کیا repo کسی workspace سے **جڑا** ہے؟ غیر جڑا repo کچھ ریکارڈ ہونے سے پہلے چھوڑ دیا جاتا ہے، اس لیے بعد میں جوڑنے سے بھی جواب پہنچ جاتا ہے
- کیا آپ اس سرور پر GitHub میں sign in ہیں، لکھنے کے role والے رکن ہیں، اور repo پر push کر سکتے ہیں؟ سرور کسی اور کو جواب دیے بغیر نظرانداز کرتا ہے
- Control Center کی مشترکہ App پر، کیا اس organization کی installation اس سرور کے لیے مجاز ہے؟ دیکھیں [اس سرور کو کسی organization کے لیے مجاز کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/github-app/#اس-سرور-کو-کسی-organization-کی-installation-کے-لیے-مجاز-کریں)
- ابھی بھی کچھ نہیں؟ سرور کا log کسی ناکامی پر sweep اور PR کا نام بتاتا ہے؛ `pr_conversation:` (poller) اور `github_pr_conversation:` (bridge) تلاش کریں

**لیبل ریویو شروع نہیں کرتا۔**

لیبل ہر PR کے لیے ایک بار فائر ہوتا ہے، اور جس نے اسے شامل کیا وہ وہی جانچ پاس کرتا ہے جو تبصرے کے مصنف کو کرنی ہوتی ہے۔ اگر پہلے ہی ایک ریویو چل چکا ہو، یا لیبل اس وقت شامل ہوا جب سرور نے PR کو دیکھا ہی نہیں تھا (پہلا sweep بیک لاگ کو خاموشی سے ریکارڈ کرتا ہے بجائے اس کے کہ اس کا طوفان بنے)، تو اس کی جگہ بوٹ کو mention کریں — `@usectrl review` ہمیشہ ایک شروع کرتا ہے، جب تک کہ ایک ریویو پہلے ہی راستے میں نہ ہو۔

**بوٹ کا جواب GitHub پر نہیں پہنچا۔**

جواب خود کبھی ضائع نہیں ہوتا — وہ Control Center میں PR کی review space میں ہوتا ہے۔ پوسٹ کرنے کی ناکامی (GitHub بند، اجازتیں بدل گئیں) log ہوتی ہے اور دوبارہ کوشش نہیں ہوتی؛ اگر یہ اہم ہو تو تھریڈ میں دوبارہ پوچھیں۔
