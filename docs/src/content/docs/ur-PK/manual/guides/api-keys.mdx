یہ گائیڈ دکھاتی ہے کہ Control Center جو اسناد استعمال کرتا ہے وہ کہاں محفوظ ہوتی ہیں اور انہیں کیسے تبدیل کیا جائے۔

**آپ جس مشین پر ٹائپ کر رہے ہیں، اس پر کچھ محفوظ نہیں ہوتا۔** ہر اسناد سرور پر رہتی ہے؛ کسی مخصوص درخواست کا جواب کون سی دیتی ہے، یہ اس پر منحصر ہے کہ اس کے پیچھے کوئی انسان ہے یا نہیں۔

| اسناد | کہاں محفوظ ہوتی ہے | کون استعمال کرتا ہے |
| ------------------------------------ | --------------------------------------------------------- | ---------------------------------------------------------------- |
| آپ کی forge / ٹکٹنگ اسناد | سرور کی 0600 خفیہ فائل، آپ کے صارف id کے تحت | ہر وہ کام جو آپ مانگیں: PR سطح، آپ کے ایجنٹ رنز، آپ کی امیجز |
| سرور کی ایپ شناخت | وہی فائل، نیز غیر خفیہ چیزوں کے لیے `server_settings` | وہ کام جو کسی انسان نے نہیں مانگا: ویب ہکس، PR پولنگ، ٹکٹ ہم آہنگی |
| ماڈل فراہم کنندہ کی کلیدیں اور OAuth ٹوکن | سرور کا اپنا اسناد کا ذخیرہ | بلٹ اِن اڈاپٹر، انسٹال کی ہر ورک اسپیس کے لیے |
| Slack بوٹ ٹوکن | سرور پر `<dataDir>/<workspaceId>/chat_credentials/` | اُس ورک اسپیس کا چیٹ برج |
| بیرونی CLI اسناد | جو بھی وہ CLI استعمال کرتا ہے | Claude Code، سرور ہوسٹ پر |

## دو GitHub اسناد، اور وہ مختلف سوالوں کے جواب دیتی ہیں

- **آپ کی**، سائن اِن (ڈیوائس فلو) سے یا ٹوکن پیسٹ کرنے سے۔ *آپ کی طرف سے* کی گئی ہر درخواست یہی استعمال کرتی ہے، اس لیے آپ کے لیے پوسٹ کیا گیا کوئی تبصرہ آپ کا نام لے کر جاتا ہے۔ کوئی دوسرا رکن اسے پڑھ نہیں سکتا، اور وہ اپنی اسناد خود جوڑتا ہے
- **سرور کی**، اُس GitHub App سے جو آپریٹر نے رجسٹر کی۔ بغیر کسی کالر کے ہر چیز کا جواب یہی دیتی ہے — چنانچہ کوئی شخص چھوڑ کر جائے یا ٹوکن تبدیل کرے تو forge رسائی غائب نہیں ہوتی

آپ کی اسناد **ترتیبات → ورک اسپیس → پروفائل اور شناخت** کے **کوڈ ہوسٹنگ** کارڈ میں سیٹ ہوتی ہیں؛ سرور والی **ترتیبات → سرور → سنگل سائن آن** کے **فراہم کنندہ ایپس** میں۔ [GitHub انضمام سیٹ کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/github-انضمام/) اور [GitHub App بنائیں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/github-app/) دیکھیں۔

:::note[صرف URL سے کھلنے والی ایک اسکرین بھی ہے]
`/workspaces/<workspaceId>/api-keys` وہی دو کارڈ دکھاتا ہے جو آن بورڈنگ کے پہلے قدم میں ہوتے ہیں۔ **UI میں کہیں اس کا کوئی نیویگیشن اندراج نہیں**؛ یہ صرف URL ٹائپ کرنے سے پہنچتا ہے۔ اس کے بجائے ترتیبات → ورک اسپیس → پروفائل اور شناخت استعمال کریں۔
:::

## ماڈل فراہم کنندہ کی کلیدیں سیٹ کریں

بلٹ اِن اڈاپٹر خود فراہم کنندگان کی توثیق کرتا ہے اور وہ اسناد سرور پر رہتی ہیں۔

1. **ترتیبات → سرور → ماڈل فراہم کنندگان** پر جائیں
2. **فراہم کنندگان اور ماڈلز** تک اسکرول کریں
3. فراہم کنندہ جوڑیں — OpenAI، Codex، Cursor اور Kimi Code کے لیے براؤزر OAuth؛ Anthropic اور باقیوں کے لیے API کلید

مکمل فہرست اور حسبِ ضرورت اینڈ پوائنٹ شامل کرنے کے لیے [اڈاپٹرز اور ماڈلز منظم کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/اڈاپٹرز/) دیکھیں۔

یہ اسناد **ہوسٹ گلوبل** ہیں: ایک کلید انسٹال کی ہر ورک اسپیس کو کام دیتی ہے۔ OAuth ٹوکن میعاد ختم ہونے سے پہلے تازہ کر دیے جاتے ہیں۔

بیرونی اڈاپٹر CLI اپنی اسناد اپنی کنفیگریشن میں، سرور ہوسٹ پر رکھتے ہیں — Control Center انہیں منظم نہیں کرتا۔ Claude Code کی توثیق اُسی طرح کریں جس طرح اس کی اپنی دستاویزات کہتی ہیں، اُس مشین پر جس پر `cc_server` چلتا ہے۔

فی اڈاپٹر **ماحول کے ویری ایبلز** ڈائیلاگ ایسا لگتا ہے کہ ان میں سے کسی کے لیے کلید رکھنے کی جگہ ہے، مگر ایسا نہیں: یہ آپ کے ڈیوائس پر لکھتا ہے، جبکہ سرور اپنی کاپی پڑھتا ہے اور دونوں کے درمیان کوئی پل نہیں۔ [اڈاپٹرز اور ماڈلز منظم کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/اڈاپٹرز/) دیکھیں۔

## ٹکٹنگ وینڈر جوڑیں

**ترتیبات → ورک اسپیس → عام** پر **ٹکٹنگ** کارڈ ایک ہی فیصلے کے دونوں حصے رکھتا ہے: آپ کے ٹکٹس کس وینڈر میں رہتے ہیں، اور اس کی اسناد۔ **مقامی** چننے پر اسناد کی قطار چھپ جاتی ہے — مقامی ٹکٹس اسی سرور کے اپنے ڈیٹا بیس میں رہتے ہیں اور ان کی توثیق کرنے کو کچھ نہیں۔

آپ کی کلید سرور پر آپ کے صارف id کے تحت محفوظ ہوتی ہے، forge والی کی طرح۔ سرور اپنی Linear کلید الگ رکھتا ہے (**فراہم کنندہ ایپس**)، اور جب کسی انسان نے نہ مانگا ہو تو ٹکٹ ہم آہنگی اسی پر چلتی ہے۔ ایجنٹ کے سینڈ باکس میں کوئی ٹکٹنگ کلید داخل نہیں کی جاتی؛ ایجنٹ Control Center کے ٹولز کے ذریعے ٹکٹ لکھتے ہیں، جو **بیرونی ٹریکر پر لکھیں** قاعدے سے پوچھتے ہیں۔ [Linear انضمام سیٹ کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/linear-انضمام/) دیکھیں۔

## تبدیل یا منسوخ کریں

- **آپ کی GitHub اسناد**: **منقطع کریں** دبائیں، پھر دوبارہ سائن اِن کریں یا نیا ٹوکن پیسٹ کریں۔ پرانی والی GitHub پر منسوخ کر دیں
- **سرور کی ایپ**: ایپ کے GitHub صفحے پر نئی پرائیویٹ کلید یا کلائنٹ سیکرٹ بنائیں، اسے **فراہم کنندہ ایپس** میں پیسٹ کریں اور **ٹیسٹ** دبائیں
- **کوئی ماڈل فراہم کنندہ**: اس کی قطار پر سائن آؤٹ کریں (OAuth) یا کلید ہٹائیں، پھر دوبارہ جوڑیں
- **Slack**: کنیکٹ ڈائیلاگ میں ٹوکن دوبارہ پیسٹ کریں۔ [Slack انضمام سیٹ کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/slack-انضمام/) دیکھیں

## خرابیوں کا ازالہ

### PR فہرست خالی ہے مگر میرا ٹوکن `curl` میں چلتا ہے

**کوڈ ہوسٹنگ** قطار کا ذیلی عنوان دیکھیں۔ اگر وہ کوئی اور ذریعہ بتاتا ہو ("اس سرور کی ایپ کے ذریعے"، "ماحول سے")، تو آپ جو اسناد جانچ رہے ہیں وہ جواب دینے والی نہیں — آپ والی محفوظ نہیں ہوئی۔

### ٹوکن قبول ہو جاتا ہے مگر بعد کی درخواستیں ناکام ہوتی ہیں

ٹوکن جیسے محفوظ ہوا ہے ویسے ہی جانچا جاتا ہے، اس لیے قطار اس کے پیچھے والا اکاؤنٹ بتا دیتی ہے — مگر صرف اکاؤنٹ، اسکوپس نہیں۔ بہت کم اسکوپس والا ٹوکن جڑ تو جاتا ہے، مگر پھر الگ الگ درخواستوں میں ناکام ہوتا ہے۔ اسکوپس اور میعاد دیکھیں:

```bash
curl -H "Authorization: token YOUR_TOKEN" https://api.github.com/user
```
