یہ گائیڈ دکھاتی ہے کہ کسی ورک اسپیس میں ایجنٹ کیسے شامل کریں اور اسے کس طرح کنفیگر کریں کہ وہ واقعی چل سکے۔

ہر ورک اسپیس میں پانچ ایجنٹ پہلے سے موجود ہوتے ہیں — ایک CEO کے علاوہ `qa`، `architect`، `engineer` اور `librarian` — یعنی عام طور پر کوئی ایجنٹ کنفیگر کرنے سے پہلے ہی آپ کے پاس ایجنٹ موجود ہوتے ہیں۔ نیچے دیے گئے مراحل پہلے سے موجود ایجنٹ اور نئے ایجنٹ، دونوں پر یکساں لاگو ہوتے ہیں۔

## شروع کرنے سے پہلے

- آپ ایک ورک اسپیس کے اندر ہیں۔ ساری سطح **ترتیبات → ورک اسپیس → ایجنٹس** (`/settings/workspace/agents`) پر موجود ہے۔
- ایجنٹ کو بیک اینڈ درکار ہوگا۔ یا تو **ترتیبات → سرور → ماڈل فراہم کنندگان** کے تحت بلٹ اِن ہارنس کے لیے کوئی فراہم کنندہ جوڑیں، یا `cc_server` کی میزبانی کرنے والی مشین پر Claude Code CLI انسٹال کریں۔
- اگر آپ چاہتے ہیں کہ ایجنٹ کے پاس مہارتیں ہوں تو پہلے انہیں **ترتیبات → ورک اسپیس → مہارتیں** کے تحت انسٹال کریں۔ ایجنٹ فارم صرف اُن مہارتوں کو ٹوگل کرنے دیتا ہے جو ورک اسپیس میں پہلے سے موجود ہوں۔

## ایجنٹ شامل کریں

1. **ترتیبات → ورک اسپیس → ایجنٹس** کھولیں۔
2. **نیا ایجنٹ** پر کلک کریں۔

کوئی ڈائیلاگ اور کوئی رول چننے والا نہیں ہوتا۔ “بے نام ایجنٹ” کے نام سے ایجنٹ فوراً بنا دیا جاتا ہے اور دائیں طرف کے تفصیلی پین میں منتخب ہو جاتا ہے۔

اب آپ کو بائیں طرف روسٹر میں “بے نام ایجنٹ” نظر آنا چاہیے، ساتھ ہی اس کے تفصیلی پین کا **ترتیبات** ٹیب کھلا ہوگا اور **نام** فیلڈ میں “بے نام ایجنٹ” درج ہوگا۔

## اس کا نام رکھیں

- **نام** — وہ مختصر شناخت کنندہ جو @-ذکر میں استعمال ہوتا ہے، مثلاً `alice`۔ ذکر کی پارسنگ `@` کے بعد آنے والے ورڈ کریکٹرز سے مماثلت رکھتی ہے، اس لیے ہائفن، ڈاٹ یا اسپیس پر مشتمل نام کا ذکر کبھی نہیں ہو سکتا۔
- **عنوان** — انسان کے پڑھنے کے قابل لیبل، مثلاً “سینئر کوڈر”۔
- **سسٹم پرامپٹ** — اختیاری اضافی ہدایات، جو «ایجنٹ کی ہدایات» کے سیکشن کے طور پر شامل کی جاتی ہیں؛ یہ تیار شدہ پرامپٹ کے باقی حصے کی جگہ نہیں لیتیں۔

فارم کے نیچے **تبدیلیاں محفوظ کریں** پر کلک کریں۔ اس صفحے کی ہر فیلڈ اسی ایک بٹن سے محفوظ ہوتی ہے۔

## اسے اڈاپٹر اور ماڈل دیں

**اڈاپٹر** ڈراپ ڈاؤن میں وہ رنرز درج ہوتے ہیں جو سرور ہوسٹ پر واقعی موجود ہیں۔ بلٹ اِن اڈاپٹر ہمیشہ مل جاتا ہے (وہ خود سرور ہے)۔ Claude Code صرف اُس وقت ظاہر ہوتا ہے جب اُس ہوسٹ پر اس کی CLI کا پتہ چل جائے:

| اڈاپٹر                   | بیک اینڈ                                     |
| ------------------------- | ------------------------------------------- |
| Control Center (built-in) | ان پروسیس ایجنٹ لوپ — کوئی بیرونی CLI نہیں   |
| Claude Code               | `claude -p --output-format stream-json`     |

صرف بلٹ اِن اڈاپٹر ہی موڈز، اسٹیرنگ، توقف اور دوبارہ آغاز، مکمل ہونے کے معاہدوں اور سب ایجنٹس کو نافذ کرتا ہے۔ Claude Code ان میں سے کوئی چیز نہیں دیتا۔ Cursor، Codex اور دیگر ماڈل فراہم کنندگان الگ رنرز کے طور پر نہیں بلکہ بلٹ اِن اڈاپٹر کے ساتھ منسلک ہوتے ہیں۔

:::note[خالی اڈاپٹر کا مطلب بلٹ اِن لوپ ہے]
جس ایجنٹ کا اڈاپٹر غیر مقرر ہو، اسے **Control Center (built-in)** یعنی سرور کے اندر موجود لوپ پر بھیجا جاتا ہے، اس لیے ہوسٹ پر کچھ انسٹال کرنے کی ضرورت نہیں۔ ماڈل بھی غیر مقرر ہونے پر یہ اپنے ڈیفالٹ کے لیے Anthropic سے پوچھتا ہے، یعنی مکمل طور پر غیر مقرر ایجنٹ صرف اُس صورت میں چلتا ہے جب آپ نے Anthropic اکاؤنٹ جوڑا ہو۔ پہلے سے موجود ماہرین ان میں سے کوئی چیز لے کر نہیں آتے؛ جو بھی ایجنٹ آپ استعمال کرنا چاہیں، اُس پر دونوں مقرر کریں۔
:::

**ماڈل** ڈراپ ڈاؤن آپ کے منتخب کردہ اڈاپٹر کے مطابق چلتا ہے۔ بلٹ اِن اڈاپٹر کے لیے فہرست براہِ راست اُن فراہم کنندگان سے آتی ہے جو آپ نے **ترتیبات → سرور → ماڈل فراہم کنندگان** کے تحت جوڑے ہیں، اس لیے جس فراہم کنندہ کے پاس کوئی محفوظ کریڈنشل نہ ہو، وہ صفر ماڈلز فراہم کرتا ہے۔

## مہارتیں شامل کریں

**مہارتیں** اس ورک اسپیس میں انسٹال شدہ مہارت بنڈلز کے اوپر ایک چپ پکر ہے۔ کسی چپ کو ٹوگل کرنے کے لیے اس پر ٹیپ کریں؛ چیک کا نشان منتخب شدہ مہارتوں کو ظاہر کرتا ہے۔ اگر ورک اسپیس میں کوئی مہارت نہ ہو تو فیلڈ یہ دکھاتی ہے: “کوئی مہارت دستیاب نہیں۔ پہلے ترتیبات → مہارتیں میں مہارتیں بنائیں۔”

آپ یہاں کسی ریپو کی اپنی مہارتیں منتخب نہیں کرتے۔ جو ریپو انہیں اپنے ساتھ بھیجتا ہے (`.agents/skills/`، `.claude/skills/` یا `.opencode/skills/` میں)، وہ انہیں خودکار طور پر اُس ایجنٹ کو فراہم کرتا ہے جو اُس ریپو میں کام کر رہا ہو، اور جب وہ کسی دوسرے ریپو میں منتقل ہو تو وہ بدل جاتی ہیں — دیکھیں [ریپو کے دائرہ کار کی مہارتیں](/ur-PK/ہدایت-نامہ/تصورات/ایجنٹ-ماڈل/#repo-scoped-skills)۔

## رپورٹنگ لائن اور شخصیت مقرر کریں

- **رپورٹ کرتا ہے** — نام کے ذریعے کوئی دوسرا ایجنٹ چنیں۔ یہ وہ رپورٹنگ ٹری بناتا ہے جو صفحے کے ہیڈر میں **آرگ چارٹ** بٹن دکھاتا ہے۔ یہ وہ روسٹر نہیں ہے جو ٹیم لیڈر تفویض کرتے وقت استعمال کرتا ہے — وہ ٹیم کے اراکین اور ان کی مہارتوں سے آتا ہے۔
- **شخصیت** — آزاد متن جو لہجے اور رویے کو تشکیل دیتا ہے، مثلاً: “سادہ، پڑھنے کے قابل حل پسند کرتا ہے۔ تمام نئے کوڈ کے لیے ٹیسٹ لکھتا ہے۔”

## رن کو ایڈجسٹ کریں

- **ریزننگ کا زور** — اختیارات منتخب ماڈل کی اپنی شائع شدہ سطحوں سے آتے ہیں: کم / درمیانہ / زیادہ، اور OpenAI طرز کے ماڈلز پر Extra High نیز Claude طرز کے ماڈلز پر Extra High + Max۔ جب منتخب ماڈل سوچ کی کوئی سطح ظاہر نہ کرے تو یہ فیلڈ مکمل طور پر چھپ جاتی ہے اور یہ ماڈل کے اپنے ڈیفالٹ پر رہتی ہے۔
- **سیاق ونڈو سائز** — جب بھی آپ ماڈل بدلیں، یہ ماڈل کی سیاق ونڈو سے پیشگی بھری جاتی ہے، ساتھ ہی ماڈل ڈیفالٹ، 200k، 500k اور 1M کے لیے ایک ٹیپ والی چپس ہوتی ہیں۔ ماڈل چننے کے بعد آپ کی ٹائپ کردہ قدر اگلے ماڈل تبدیلی تک غالب رہتی ہے۔
- **خاموشی ٹائم آؤٹ (منٹ)** — اتنی دیر بغیر آؤٹ پٹ گزرنے پر رن ختم کر دیں۔ فی موڈ ڈیفالٹ استعمال کرنے کے لیے اسے خالی چھوڑ دیں۔

## اجازتیں دیں

**سینڈ باکس اجازتیں** “ورک اسپیس ڈیفالٹ استعمال کریں” پر شروع ہوتی ہیں۔ اس ایجنٹ کے لیے انہیں مقرر کرنے کے لیے سوئچ آن کریں، پھر ٹوگل کریں:

- **git push کی اجازت دیں** — وہ GitHub ٹوکن انجیکٹ کرتا ہے جو ایجنٹ کو پش کرنے کے لیے درکار ہوتا ہے
- **GitHub API کالز کی اجازت دیں** — ایجنٹ کو PRs، ایشوز اور ریپو میٹاڈیٹا پڑھنے دیتا ہے
- **ٹکٹنگ API کالز کی اجازت دیں** — ٹکٹنگ فراہم کنندہ کی کلید انجیکٹ کرتا ہے
- **عام نیٹ ورک رسائی کی اجازت دیں** — بلٹ اِن ہارنس کے `web_fetch` اور `web_search` ٹولز بھی فعال کرتا ہے

ہر ٹوگل کو رن کے آغاز پر کریڈنشل بروکر جانچتا ہے: جو قابلیت بند ہو، اس کا سیدھا مطلب یہ ہے کہ متعلقہ ٹوکن رن کے ماحول میں کبھی جاری نہیں کیا جاتا۔

:::caution[ورک اسپیس ڈیفالٹ کا مطلب سرور کا محتاط سیٹ ہے]
“ورک اسپیس ڈیفالٹ استعمال کریں” پر چھوڑا گیا ایجنٹ git push، GitHub API اور ٹکٹنگ سب **بند** کے ساتھ چلتا ہے اور نیٹ ورک **آن** ہوتا ہے۔ ترتیبات → سرور → تشخیص اور پرائیویسی کے تحت دکھائے گئے قابلیت ڈیفالٹس کلائنٹ کی طرف کی ترجیح ہیں۔ اگر آپ چاہتے ہیں کہ کوئی ایجنٹ پش کرے یا PRs کھولے تو سوئچ آن کریں اور قابلیتیں واضح طور پر دیں۔

یہ قابلیتیں کریڈنشلز اور ہارنس ٹولز کو گیٹ کرتی ہیں، جو OS سینڈ باکس سے الگ پرت ہے۔ جہاں ایسا سینڈ باکس موجود ہو، `cc_server` ایجنٹ رنز کو ہوسٹ کے سینڈ باکس میں لپیٹ دیتا ہے — Windows کا کوئی نیٹو بیک اینڈ نہیں، اور Linux اور WSL2 کو `bwrap` اور `socat` درکار ہوتے ہیں۔ تمام سرحدوں کا مکمل سیٹ دیکھنے کے لیے [سینڈ باکس اور سیکیورٹی](/ur-PK/ہدایت-نامہ/تصورات/سینڈ-باکس-سیکیورٹی/) دیکھیں۔
:::

## تصدیق کریں کہ یہ چلتا ہے

1. **ترتیبات → سرور → ماڈل فراہم کنندگان** کھولیں اور تصدیق کریں کہ آپ کے منتخب کردہ اڈاپٹر نے “نہیں ملا” کے بجائے کوئی انسٹال شدہ ورژن بتایا ہو۔ دوبارہ جانچنے کے لیے **تازہ کریں** پر کلک کریں — جانچ اُس مشین پر چلتی ہے جو `cc_server` کی میزبانی کرتی ہے، نہ کہ اُس مشین پر جو آپ دیکھ رہے ہیں۔
2. ایجنٹ کے ساتھ کوئی اسپیس کھولیں اور اسے پیغام بھیجیں، یا کسی موجودہ اسپیس میں اس کا @-ذکر کریں۔
3. **ترتیبات → ورک اسپیس → ایجنٹس** پر واپس آئیں، ایجنٹ منتخب کریں اور اس کا **لاگز** ٹیب کھولیں۔ ایک رن نظر آنا چاہیے جس میں اسٹیٹس بیج، مدت، شروع ہونے کا وقت اور استعمال شدہ اڈاپٹر ہو۔ **دیکھیں** اُس رن کا ایونٹ اسٹریم کھولتا ہے۔

اگر کوئی رن بالکل نظر نہ آئے تو [ایجنٹ کی تشخیص کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/ایجنٹ-کی-تشخیص/) پر عمل کریں۔

## ایجنٹ حذف کریں

روسٹر میں اسے منتخب کریں۔ **ترتیبات** ٹیب پر، فارم کے نیچے **خطرناک زون** تک اسکرول کریں اور **حذف کریں** پر کلک کریں۔
