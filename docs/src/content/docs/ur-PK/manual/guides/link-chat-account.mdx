یہ گائیڈ دکھاتی ہے کہ اپنی چیٹ شناخت کو اپنے Control Center user سے کیسے لنک کریں، اور کسی لنک کو کیسے ختم کریں۔

ہر رکن یہ کام ہر چیٹ provider کے لیے ایک بار کرتا ہے۔ یہ app کو کنیکٹ کرنے سے الگ ہے: کنکشن پورے workspace کے لیے بوٹ کو قابلِ رسائی بناتا ہے، اور لنک _آپ_ کو اس کے اندر پہچانے جانے کے قابل بناتا ہے۔

## لنکنگ کیوں ضروری ہے

bridge ایسے چیٹ اکاؤنٹ کے لیے عمل کرنے سے انکار کرتا ہے جسے وہ workspace کے کسی رکن تک حل نہ کر سکے۔ یہ جان بوجھ کر ہے: لنک کے بغیر Slack کے ہر پیغام کو اُس شخص سے منسوب کرنا پڑتا جس نے app انسٹال کی تھی، اور audit trail، فی فرد rate limits اور ticket reporters سب غلط نام درج کرتے۔

جو رکن لنک نہیں ہے اور بوٹ کو mention کرتا ہے، اسے اسی Slack thread میں ایک جواب ملتا ہے جو بتاتا ہے کہ لنک کیسے کرنا ہے۔ کچھ بھی dispatch نہیں ہوتا۔

## کوڈ کے ساتھ لنک کرنا

لنکنگ میں دونوں طرف شامل ہیں: Slack سے کوڈ بھیجنا Slack اکاؤنٹ کو ثابت کرتا ہے، اور Control Center میں اس کی تصدیق یہ ثابت کرتی ہے کہ وہ اکاؤنٹ آپ کا ہے۔

1. **Settings → Workspace → Profile & identity** پر جائیں اور **Linked chat accounts** کارڈ تک اسکرول کریں
2. Slack والے بلاک پر **Link my Slack account** پر کلک کریں۔ dialog ایک ایک بار استعمال ہونے والا کوڈ دکھاتا ہے، مثلاً:

```text
K7M2QP
```

3. Slack میں، وہ کوڈ بوٹ کو **direct message** میں بھیجیں: صرف کوڈ، اور کچھ نہیں
4. بوٹ جواب دیتا ہے "Got it. Confirm this Slack account in Control Center to finish linking." اور جو dialog آپ نے کھلا چھوڑا تھا وہ اس Slack profile کو دکھاتا ہے جس نے کوڈ بھیجا: اس کا نام اور Slack member id
5. اگر یہ آپ کا اکاؤنٹ ہے تو **Confirm** پر کلک کریں۔ لنک بن جاتا ہے، dialog یہ بتاتا ہے اور بوٹ اسی direct message میں تصدیق کرتا ہے
6. اگر یہ آپ کا نہیں ہے تو **Decline** پر کلک کریں۔ کچھ بھی لنک نہیں ہوتا اور کوڈ کام کرنا بند کر دیتا ہے؛ دوبارہ کوشش کے لیے **Get a new code** پر کلک کریں

dialog بند کرنے سے claim ضائع نہیں ہوتا۔ بعد میں آنے والا کوڈ آپ کے profile page کی **Link my Slack account** قطار میں انتظار کرتا ہے، اسی **Confirm** اور **Decline** کے ساتھ۔

تصدیق کا مرحلہ کیوں ہے: اگر کوئی کوڈ کسی کے کندھے پر سے پڑھا جائے اور کسی اور کے Slack اکاؤنٹ سے بھیجا جائے تو وہ اکاؤنٹ آپ کے طور پر عمل کرنے لگتا۔ صرف آپ تصدیق کر سکتے ہیں، اور صرف وہی profile جس نے کوڈ بھیجا۔

کوڈ:

- ایک بار استعمال ہوتا ہے اور جاری ہونے کے **15 منٹ** بعد ختم ہو جاتا ہے
- ہمیشہ _آپ_ کے لیے جاری ہوتا ہے، کبھی کسی ساتھی کے لیے نہیں
- صرف بوٹ کو direct message میں کام کرتا ہے۔ channel میں یہ صرف ایک عام پیغام ہے
- صرف اس Slack workspace کا مکمل رکن دعویٰ کر سکتا ہے جہاں بوٹ انسٹال ہے، کوئی guest یا کسی دوسری تنظیم کا فرد نہیں
- جو کوڈ آپ کے پاس پہلے سے ہے اسے بدل دیتا ہے، اس لیے بٹن دوبارہ دبانے سے پچھلا کوڈ باطل ہو جاتا ہے
- صرف memory میں رہتا ہے، اس لیے سرور کا restart باقی کوڈز کو باطل کر دیتا ہے — بٹن دوبارہ دبائیں

جو کوڈ نامعلوم ہو، ختم ہو چکا ہو، مسترد کیا گیا ہو، یا کسی اور workspace کے لیے جاری ہوا ہو، وہ ایک ہی غیر متمیز طریقے سے ناکام ہوتا ہے: "That code is not valid (or has expired)."

## ای میل کے ذریعے خودکار لنکنگ

اگر آپ کی Slack profile میں ایک confirmed ای میل ہے جو اس Control Center user کی verified ای میل سے میل کھاتی ہے جو **پہلے ہی اس workspace کا رکن ہے**، تو bridge پہلی بار بات کرنے پر آپ کو لنک کر دیتا ہے۔ کوڈ کی ضرورت نہیں۔

دونوں حصے اہم ہیں: ای میل کا میل شناخت ثابت کرتا ہے، لیکن رکنیت ہی رسائی دیتی ہے، اس لیے وہ اجنبی جس کی ای میل اتفاق سے سرور پر موجود ہو، کسی چیز سے لنک نہیں ہوتا۔ فہرست دکھاتی ہے کہ ہر لنک کیسے بنا ("ای میل سے ملا" یا "کوڈ کے ذریعے لنک ہوا")۔

خودکار لنکنگ کو `users:read.email` scope کی ضرورت ہے۔ اس کے بغیر Slack پتہ ظاہر نہیں کرتا، اور کوڈ کا طریقہ ہی واحد راستہ رہ جاتا ہے۔

## لنک شدہ افراد دیکھیں

لنک شدہ افراد کی فہرست workspace administration ہے، اس لیے یہ سطح کے دوسرے حصے میں ہے: **Settings → Workspace → General → Chat bridges → Linked accounts**۔ یہ workspace کے ہر لنک شدہ رکن کو اس Slack اکاؤنٹ کے ساتھ دکھاتی ہے جس سے وہ جڑا ہے اور لنک کیسے بنا۔

آپ کی اپنی حالت آپ کے profile page پر ہے: **Link my Slack account** قطار لنک ہونے کے بعد "Linked to _your-slack-id_" دکھاتی ہے اور لنک نہ ہونے پر آپ کو لنک کرنے کو کہتی ہے۔

فہرست اور claim دونوں live subscriptions ہیں، کیونکہ تبدیلی دوسری طرف ہوتی ہے: آپ Slack میں کوڈ بھیجتے ہیں، اس لیے app کی کوئی درخواست جواب واپس نہیں لا سکتی۔

## لنک ختم کرنا

workspace کی فہرست میں ایک قطار پر **Unlink** پر کلک کریں۔

- کوئی بھی خود کو unlink کر سکتا ہے
- صرف admin کسی دوسرے رکن کو unlink کر سکتا ہے
- unlink کرنے سے اس رکن کا کوئی بھی باقی link code بھی باطل ہو جاتا ہے

unlink کرنے کے بعد وہ Slack اکاؤنٹ دوبارہ لنک ہونے تک ایجنٹس کو نہیں چلا سکتا۔ موجودہ spaces، transcripts اور tickets اپنی اصل انتسابی معلومات برقرار رکھتے ہیں — unlink کرنا ماضی کے کام کو واپس لینا نہیں ہے۔

## خرابیوں کا ازالہ

### بوٹ کہتا ہے میں اس workspace کا رکن نہیں ہوں

آپ کا Slack اکاؤنٹ ایک Control Center user سے لنک ہے، لیکن اس user کی اس workspace میں کوئی رکنیت نہیں۔ کسی admin سے کہیں کہ آپ کو مدعو کرے؛ دیکھیں [Multiplayer — identity, membership and presence](/ur-PK/ہدایت-نامہ/تصورات/ملٹی-پلیئر/)۔

### بوٹ کہتا ہے میرا role صرف پڑھنے کا ہے

`viewer` اور `guest` roles کام شروع نہیں کر سکتے۔ کسی admin کو آپ کا role `member` یا اس سے اوپر کرنا ہوگا۔

### بوٹ کہتا ہے کوڈ درست نہیں ہے

کوڈ ختم ہو گیا، پہلے استعمال ہو چکا، مسترد ہوا، یا کسی نئے کوڈ سے بدل دیا گیا۔ **Link my Slack account** پر دوبارہ کلک کریں اور نیا کوڈ بھیجیں۔

### بوٹ میرے کوڈ کو درخواست سمجھتا ہے

آپ نے اسے channel میں بھیجا، یا آپ کا Slack اکاؤنٹ پہلے سے لنک ہے۔ کوڈ صرف direct message میں قبول ہوتے ہیں، اور لنک شدہ اکاؤنٹ سے کوڈ جیسا پیغام ایک عام درخواست ہے۔
