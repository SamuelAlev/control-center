کسی ایجنٹ کا رن سینڈ باکس میں چلے گا یا نہیں، یہ سرور پر، بوٹ کے وقت طے ہوتا ہے
(`--sandbox`)۔ **سینڈ باکسنگ فعال کریں** ٹوگل، **بیک اینڈ** چننے والا کنٹرول اور
**ترتیبات → سرور → تشخیص اور پرائیویسی** کے تحت **ڈیفالٹ صلاحیتیں · نئی اسپیسز**
ٹوگلز آپ کے ڈیوائس پر محفوظ ترجیحات ہیں۔ **سینڈ باکسنگ** کارڈ کی ہوسٹ جانچ بتاتی
ہے کہ سرور کا ہوسٹ کس چیز کو لپیٹ سکتا ہے۔

کسی رن تک دو کنٹرول پہنچتے ہیں اور یہ گائیڈ دونوں کا احاطہ کرتی ہے: نیچے دی گئی
فی ایجنٹ **سینڈ باکس اجازتیں** اور سرور کا اپنا `--sandbox` فلیگ۔

## ایک ایجنٹ کے رن کو کیا محدود کرتا ہے

ایک ایجنٹ کو چھ چیزیں باندھتی ہیں۔ پہلی OS سینڈ باکس ہے اور یہی وہ ہے جو مشروط
ہے — باقی پانچ ہر ہوسٹ پر قائم رہتی ہیں۔

| حد | یہ کیا کرتی ہے |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OS سینڈ باکس | macOS پر Seatbelt، Linux اور WSL2 پر bubblewrap۔ Claude Code CLI، ACP اڈاپٹرز اور ہارنس کے `bash` ٹول کو لپیٹتا ہے۔ **Windows پر اور اُن Linux ہوسٹس پر موجود نہیں جہاں `bwrap` اور `socat` نہ ہوں** |
| اس کی اپنی worktree | ہر گفتگو کو copy-on-write چیک آؤٹ ملتا ہے۔ اصل چیک آؤٹ رن میں رائٹ سے انکار والے پاتھ کے طور پر شامل کر دیا جاتا ہے اور اسی کو نافذ کرنے والی چیز سینڈ باکس ہے |
| بروکر کے ذریعے جاری کریڈنشلز | کریڈنشل بروکر ایجنٹ کی صلاحیتوں سے ہر رن کے لیے ماحول تیار کرتا ہے اور رن کے اختتام پر اسے منسوخ کر دیتا ہے۔ قابلیت نہ ہو تو ماحول میں ٹوکن بھی نہیں ہوتا |
| ایکشن گارڈریلز | ہر تبدیلی لانے والا ٹول اپنی اثر کلاسز ظاہر کرتا ہے اور گارڈ کال چلنے سے پہلے اُن کا تعین کرتا ہے۔ کوئی `prompt` جس سے کوئی منظور کنندہ منسلک نہ ہو، مسترد کر دیا جاتا ہے |
| ماحول کی صفائی | ACP اور ہارنس کے `bash` ٹول کو چھنا ہوا ماحول ملتا ہے۔ `NoSandboxAdapter` کے ذریعے Claude Code ہوسٹ کا ماحول ورثے میں پاتا ہے |
| موڈ کا ٹول سرفیس | ریڈ اونلی موڈ worktree میں تبدیلی کرنے والے ٹولز سرے سے نکال دیتا ہے اور موڈ کے اپنے آؤٹ پٹ فعل کو پن کر دیتا ہے تاکہ وہ پھر بھی حوالے کر سکے |

تین چیزیں دکھنے سے زیادہ کمزور رہ جاتی ہیں:

- صرف **بلٹ اِن ہارنس** ہی ٹول گیٹ، تکمیل کے معاہدے اور موڈ کے ساختی قواعد نافذ
  کرتا ہے۔ Claude Code اڈاپٹر نہیں کرتا۔ خاص طور پر Claude Code کو
  `--dangerously-skip-permissions` کے ساتھ لانچ کیا جاتا ہے، کیونکہ غیر تعاملی
  `claude -p` ورنہ اپنے ہی پرامپٹ پر ہمیشہ کے لیے بلاک ہو جاتا — چنانچہ Claude کی
  اپنی read، write، edit اور bash کالز نہ Control Center دیکھتا ہے اور نہ اُن پر
  گیٹ لگاتا ہے۔ جہاں سینڈ باکس آن ہو، وہی اُن کے گرد سرحد ہے۔
- ہارنس کے اِن پروسیس فائل ٹولز (read، write، edit، apply patch، search،
  find، search_files) سرور پروسیس کے اندر چلتے ہیں، اس لیے کوئی سینڈ باکس
  پروفائل اُنہیں محدود نہیں کرتا۔ صرف `bash` ٹول سینڈ باکس شدہ کمانڈ رنر سے
  گزرتا ہے۔ وہ ٹولز اپنے پاتھ کنفائنمنٹ کے ساتھ ایکشن گارڈریلز سے بندھے ہوتے
  ہیں۔
- جس ہوسٹ کے پاس کوئی بیک اینڈ نہ ہو وہاں پہلی قطار بالکل لاگو نہیں ہوتی۔ ACP
  اور ہارنس کا `bash` ٹول ماحول کی صفائی کے علاوہ کمانڈ پالیسی پر واپس چلے
  جاتے ہیں؛ Claude Code `NoSandboxAdapter` کے ذریعے ہوسٹ کا ماحول ورثے میں
  پاتا ہے۔ سرور یہ اپنے اسٹارٹ اپ لاگ میں بتا دیتا ہے۔ نیچے اپنا معاملہ جانچیں۔

## ایجنٹ کی صلاحیتیں مقرر کریں

یہ واحد قابلیت کنٹرول ہے جو سرور پڑھتا ہے۔ یہ فی ایجنٹ ہوتا ہے اور طے کرتا ہے کہ
کریڈنشل بروکر اُس ایجنٹ کے ماحول میں کیا رکھتا ہے۔

1. **ترتیبات → ورک اسپیس → ایجنٹس** پر جائیں
2. فہرست میں سے ایجنٹ منتخب کریں
3. **ترتیبات** ٹیب پر **سینڈ باکس اجازتیں** تک اسکرول کریں
4. سوئچ آن کریں — قطار کا کیپشن **ورک اسپیس ڈیفالٹ استعمال کریں** سے بدل جاتا ہے
5. چاروں ٹوگلز مقرر کریں:

| ٹوگل | یہ کس چیز کا گیٹ ہے |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **git push کی اجازت دیں** | اس کے بند ہونے پر رن کو `GIT_ASKPASS=/usr/bin/false` اور `GIT_TERMINAL_PROMPT=0` ملتا ہے، اس لیے کوئی پش کریڈنشل مانگ ہی نہیں سکتا |
| **GitHub API کالز کی اجازت دیں** | **git push کی اجازت دیں** کے ساتھ مل کر طے کرتا ہے کہ بروکر GitHub ٹوکن کو `GH_TOKEN` / `GITHUB_TOKEN` کے طور پر انجیکٹ کرتا ہے یا نہیں |
| **ٹکٹنگ API کالز کی اجازت دیں** | طے کرتا ہے کہ بروکر `TICKETING_API_KEY` انجیکٹ کرتا ہے یا نہیں |
| **عام نیٹ ورک رسائی کی اجازت دیں** | جہاں سینڈ باکس آن ہو، یہ حقیقی ایگریس گیٹ ہے: اس کے بند ہونے پر رن کی allowlist خالی ہوتی ہے اور ہر آؤٹ باؤنڈ درخواست پراکسی پر مسترد ہو جاتی ہے۔ جہاں کوئی بیک اینڈ نہ ہو، یہ رن پر درج تو ہوتا ہے مگر اسپان کیے گئے پروسیس کے کسی فعل کو نہیں روکتا |

6. محفوظ کریں

چیک پوائنٹ: ایجنٹ دوبارہ کھولیں تو سوئچ اب بھی آن ہوگا اور آپ کے ٹوگلز برقرار
رہیں گے — محفوظ شدہ قابلیت کا سیٹ سرور سے گزر کر واپس آتا ہے اور جس ایجنٹ کے پاس
کوئی سیٹ نہ ہو وہ محتاط ڈیفالٹ پر واپس چلا جاتا ہے (پش بند، GitHub API بند،
ٹکٹنگ بند، نیٹ ورک آن)۔

:::caution[دو طرح سے یہ نقصان دیتا ہے]
کیپشن **ورک اسپیس ڈیفالٹ استعمال کریں** کہتا ہے، مگر ایسی کوئی ورک اسپیس سطح کی
قابلیت سیٹنگ نہیں جسے سرور پڑھتا ہو۔ جو ایجنٹ سوئچ بند رکھے، اُسے بلٹ اِن محتاط
ڈیفالٹ ملتا ہے۔

اس کے علاوہ، رن کا GitHub کریڈنشل صرف بروکر کا ہوتا ہے — ریپو دائرے کا GitHub App
انسٹالیشن ٹوکن، یا ماحول کا PAT فال بیک — کبھی درخواست کرنے والے رکن کا اپنا
محفوظ ٹوکن نہیں۔ `actingUserId` اس لیے بھیجا جاتا ہے کہ بروکر ایسے رکن سے سرور کا
PAT *روک* سکے جو مالک نہ ہو اور جس نے GitHub منسلک نہ کیا ہو؛ یہ کسی بند قابلیت پر
ذاتی ٹوکن اوپر نہیں چڑھاتا۔ جس ہوسٹ پر OS سینڈ باکس نہ ہو وہاں **GitHub API کالز
کی اجازت دیں** کو سخت ایگریس سرحد نہ سمجھیں: اسپان کیا گیا پروسیس پھر بھی نیٹ ورک
تک پہنچ سکتا ہے۔
:::

## جانچیں کہ آپ کے ایجنٹ رنز سینڈ باکس میں چلتے ہیں یا نہیں

اس کا فیصلہ دو چیزیں کرتی ہیں، اور دونوں سرور پر ہیں: ہوسٹ کوئی بیک اینڈ پیش کرتا
ہے یا نہیں، اور `--sandbox` آن ہے یا نہیں۔ اسی ترتیب سے جانچیں۔

1. **ترتیبات → سرور → تشخیص اور پرائیویسی** پر جائیں
2. **سینڈ باکسنگ** کارڈ پڑھیں۔ **ہوسٹ** والی حقیقت وہ مشین ہے جس پر `cc_server`
   چلتا ہے، نہ کہ وہ مشین جو آپ سامنے دیکھ رہے ہیں۔ **بیک اینڈ** فیلڈ **نیٹو
   سینڈ باکس** (macOS پر Seatbelt، Linux اور WSL2 پر bubblewrap) یا **کوئی
   علیحدگی نہیں** بتاتی ہے۔ **نافذ** والی حقیقت اِس ڈیوائس کی ترجیح ہے، وہ رَیپ
   نہیں جو سرور واقعی استعمال کرتا ہے۔
3. سرور کا اسٹارٹ اپ لاگ پڑھیں۔ یہ تین میں سے ٹھیک ایک لائن چھاپتا ہے:
   - `agent sandbox ON` اور ساتھ بیک اینڈ کا نوٹ — رنز لپیٹے جاتے ہیں
   - `no OS-native agent sandbox on this host` اور جہاں کوئی ہو وہاں انسٹالیشن کا
     اشارہ — رنز لپیٹے نہیں جاتے
   - `agent sandbox DISABLED by --sandbox off` — جان بوجھ کر باہر نکلنا

`GET /healthz` سینڈ باکس کی حالت نہیں بتاتا، اس لیے جانچ اسٹارٹ اپ لاگ ہی ہے۔

سینڈ باکس جان بوجھ کر بند کرنے کے لیے — جس ہوسٹ پر پروفائل بے ڈھنگ برتاؤ کرے،
وہی اس کے بند ہونے کی وجہ ہے — سرور کو `--sandbox off` کے ساتھ شروع کریں، یا
`CC_SERVER_SANDBOX=off` سیٹ کریں۔ ڈیفالٹ `on` ہے اور `on` کا مطلب ہے ”ہوسٹ کے پاس
ہو تو بیک اینڈ استعمال کرو“، ہرگز ”بیک اینڈ لازم کرو“ نہیں۔

دو صورتوں کو کبھی نیٹو سینڈ باکس رَیپ نہیں ملتا۔ **Windows** پر نیٹو پروب ہمیشہ
ناقابلِ دستیاب بتاتا ہے اور انسٹال کرنے کو کچھ نہیں ہوتا — ایجنٹ ڈسپیچ `none`
استعمال کرتا ہے۔ `microvm` بیک اینڈ الگ ہے (انٹرایکٹو ٹرمنلز اور رگز) اور اپنے رن
ٹائم پر پروب گیٹڈ ہے۔ **Linux اور WSL2** پر `bwrap` اور `socat` دونوں کا `PATH` پر
ہونا لازم ہے؛ اُن کے بغیر پروب ناقابلِ دستیاب بتاتا ہے اور غائب پیکیجز کے نام
گنواتا ہے۔

bubblewrap انسٹال ہونے کے ساتھ Linux/WSL2 پر، ایجنٹ کی بعد میں بنائی گئی فائلوں کے
لیے معیاری پالیسی کے خفیہ فائل گلوبز نافذ نہیں کیے جا سکتے۔ ایسا نیٹو رن اب قواعد
کو خاموشی سے نظرانداز کرنے کے بجائے ناکام ہو جاتا ہے۔ چنانچہ بوٹ پروب کا کامیاب
ہونا اس بات کی ضمانت نہیں کہ Linux ڈسپیچ شروع ہو سکے گا۔ `--sandbox off` جان بوجھ
کر بغیر پابندی چلنے کا انتخاب ہے، سیکیورٹی سرحد کا نعم البدل نہیں۔

## جانیں کہ کوئی موڈ پہلے ہی کس چیز سے منع کرتا ہے

موڈ فی اسپیس محفوظ ہوتا ہے اور گارڈریل ریزالور کو **موڈ پری سیٹ** کی تہہ کے طور پر
کھلایا جاتا ہے۔ چار میں سے تین موڈ ریڈ اونلی ہیں اور کوئی ریڈ اونلی موڈ گیارہ اثر
کلاسز سے سرے سے انکار کر دیتا ہے:

| موڈ | worktree | پری سیٹ سے مسترد |
| ------------------ | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ایجنٹ** (`chat`) | قابلِ تحریر | کچھ نہیں — بلٹ اِن ڈیفالٹس لاگو ہوتے ہیں |
| **پلان** | ریڈ اونلی | فائل حذف کریں، worktree سے باہر لکھیں، کمیٹ بنائیں، ریموٹ پر پش کریں، pull request کھولیں، ریویو شائع کریں یا مرج کریں، بیرونی ٹریکر پر لکھیں، پیکیج انسٹال کریں، پراسیس چلائیں، ورک اسپیس کا ڈھانچہ بدلیں، انکلوژر بوٹ کریں یا چلائیں |
| **ریویو** | ریڈ اونلی | وہی گیارہ۔ صارف کے لیے منتخب کرنے کے قابل نہیں — کمپوزر صرف ایجنٹ، پلان اور آرکیسٹریٹ پیش کرتا ہے |
| **آرکیسٹریٹ** | ریڈ اونلی | وہی گیارہ |

نیٹ ورک رسائی اور راز تک رسائی سے کوئی ریڈ اونلی موڈ جان بوجھ کر _انکار نہیں_
کرتا: تحقیق ہی تو اُس کا مقصد ہے۔

## کسی ایکشن کے چلنے سے پہلے منظوری لازمی کریں

منظوری گارڈریل کا فیصلہ ہے، سینڈ باکس کی سیٹنگ نہیں۔

1. **ترتیبات → ورک اسپیس → ایجنٹ اجازتیں** پر جائیں
2. ایکشن کلاس کو ورک اسپیس، ایجنٹ یا اسپیس دائرے پر **پہلے پوچھیں** کر دیں

**پہلے پوچھیں** کا فیصلہ رن کو روک کر آپ سے پوچھتا ہے۔ کوئی منظور کنندہ منسلک نہ
ہو تو یہ بند ہو کر ناکام ہوتا ہے اور ایکشن مسترد کر دیا جاتا ہے۔ تعین کی مکمل
ترتیب کے لیے
[گارڈریلز کنفیگر کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/گارڈریلز-کنفیگر-کریں/) دیکھیں۔

## خرابیوں کا ازالہ

### کوئی ایجنٹ پش نہیں کر پاتا اور میں نے کبھی منع نہیں کیا

ایجنٹ کی **سینڈ باکس اجازتیں** دیکھیں۔ جس ایجنٹ کے پاس کوئی حسب ضرورت قابلیت سیٹ
نہ ہو، اُسے محتاط ڈیفالٹ ملتا ہے جس میں **git push کی اجازت دیں** بند ہوتا ہے —
چنانچہ بروکر کوئی GitHub ٹوکن انجیکٹ نہیں کرتا اور git کے پاس تصدیق کا کوئی راستہ
نہیں رہتا۔

### سینڈ باکسنگ کارڈ کوئی نیٹو سینڈ باکس نہ ہونے کی اطلاع دیتا ہے

تو اُس ہوسٹ پر ایجنٹ رنز Seatbelt یا bubblewrap میں لپیٹے نہیں جاتے اور جو سرحدیں
باقی ہیں وہی آپ کے پاس ہیں۔ Linux اور WSL2 پر دونوں غائب ٹولز انسٹال کریں —
`sudo apt-get install bubblewrap socat` — اور سرور دوبارہ شروع کریں؛ پھر اسٹارٹ اپ
لاگ بتائے گا کہ سینڈ باکس آن ہے۔ Windows پر انسٹال کرنے کو کوئی نیٹو بیک اینڈ نہیں،
اس لیے اس کے بجائے گارڈریلز سخت کریں:
[گارڈریلز کنفیگر کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/گارڈریلز-کنفیگر-کریں/) دیکھیں۔

### کوئی ایجنٹ اپنی worktree سے باہر کی فائل تک پہنچ گیا

یہ متوقع ہے یا نہیں، اس کا فیصلہ اس بات سے ہوتا ہے کہ کون سا ٹول وہاں پہنچا۔

ہارنس کے اِن پروسیس فائل ٹولز (read، write، edit، apply patch، search، find،
search_files) سرور پروسیس میں چلتے ہیں، اس لیے اُن پر کوئی سینڈ باکس پروفائل لاگو
نہیں ہوتا — اُن کی حد ان کا اپنا پاتھ کنفائنمنٹ اور گارڈریلز ہیں۔ کوئی `bash`
کمانڈ یا Claude Code CLI، جہاں بیک اینڈ موجود ہو، وہاں _لپیٹا جاتا ہے_ اور آپ کے
رجسٹرڈ چیک آؤٹ اُس رَیپ کے اندر ہر موڈ میں رائٹ سے انکار والے ہوتے ہیں، بشمول اُن
کی symlink سے حل شدہ ہجوں کے (macOS پر `/tmp` یا `/var/folders` کے ذریعے پہنچا پاتھ
`/private` کے تحت حل ہوتا ہے اور اب دونوں ہجے مسترد کیے جاتے ہیں)۔ جس ہوسٹ پر کوئی
بیک اینڈ نہ ہو، وہاں اس میں سے کچھ بھی لاگو نہیں ہوتا۔ دونوں صورتوں میں، گارڈریلز
**worktree سے باہر لکھیں** سے سرے سے انکار کر سکتے ہیں۔
