یہ گائیڈ بتاتی ہے کہ کوئی ایجنٹ رنز کیوں پیدا نہیں کر رہا، یہ کیسے معلوم کریں۔

اوپر سے نیچے کی طرف کام کریں: پہلے ایجنٹ کے اپنے رنز، پھر اس کا بیک اینڈ، پھر سرور، پھر ہوسٹ۔

## 1. ایجنٹ کی رن ہسٹری چیک کریں

**ترتیبات → ورک اسپیس → ایجنٹس** → ایجنٹ منتخب کریں → **لاگز**۔

ہر رن ایک اسٹیٹس بیج، ایک دورانیہ (جاری رہتے ہوئے "Running…")، اس کے آغاز اور تکمیل کے اوقات، اس کا PID اور وہ اڈاپٹر جو اس نے استعمال کیا، دکھاتا ہے۔ **دیکھیں** اُس رن کا خام ایونٹ اسٹریم کھولتا ہے۔ **روکیں** چلتے ہوئے پروسیس کو ختم کرتا ہے اور رن کو "Killed by user" کے طور پر نشان زد کرتا ہے؛ ہیڈر میں **چلتے ہوئے ختم کریں** اُس ایجنٹ کے ہر جاری رن کے لیے یہی کرتا ہے۔

اسے یوں پڑھیں:

- **کوئی رن بالکل نہیں** — ڈسپیچ ہوا ہی نہیں۔ کمپوزر کے ذکر `@` کے ساتھ ورڈ کریکٹرز (حروف، ہندسے، انڈر اسکور) پر مشتمل ہوتے ہیں۔ ریزولوشن ایجنٹ کے نام پر ایک عین یا پری فکس مماثلت ہوتی ہے، اس لیے `@code-reviewer` کو `code` کے طور پر پارس کیا جاتا ہے اور یہ پھر بھی `code-reviewer` نام والے ایجنٹ کو جگا سکتا ہے۔ خالی جگہ والے نام کا ایک ہی ٹوکن کے طور پر ذکر نہیں کیا جا سکتا۔ پھر مرحلہ 2 پر جائیں۔
- **ایک رن جو فوراً خرابی کے ساتھ ختم ہو گیا** — **دیکھیں** کھولیں۔ بیک اینڈ لانچ کرنے میں ناکامی یہاں پراسیس خرابی کے طور پر سامنے آتی ہے۔
- **"Running…" پر اٹکا ہوا رن** — اسے روکیں، پھر ترتیبات ٹیب میں ایجنٹ کا **خاموشی ٹائم آؤٹ** چیک کریں۔ سیٹ نہ کی گئی ٹائم آؤٹ فی موڈ ڈیفالٹ استعمال کرتی ہے۔
- **مکمل شدہ مگر بے کار آؤٹ پٹ والا رن** — ایسے رن کے لیے جو اپنی اعلان کردہ ڈیلیوریبل کے بغیر ختم ہو، رن لاگ کا اسٹیٹس `completed` ہی رہتا ہے؛ سچا اشارہ بیج نہیں بلکہ سمری متن ہے۔

لاگز ٹیب کوئی لاگت نہیں دکھاتا۔ خرچ کے لیے، **آبزرویبلٹی → بصیرتیں** میں فی ایجنٹ ٹیبل استعمال کریں۔

## 2. ایجنٹ کا بیک اینڈ چیک کریں

**ترتیبات → سرور → ماڈل فراہم کنندگان** (`/settings/server/providers`)۔

**دریافت شدہ رنرز** فہرست ہر اڈاپٹر کو اس کے پروب نتیجے کے ساتھ دکھاتی ہے — کوئی انسٹال شدہ ورژن، "چیک ہو رہا ہے…"، یا "نہیں ملا" — علاوہ حل شدہ پاتھ اور ملنے والی CLI کے لیے کیپبیلٹی چپس۔ دوبارہ پروب کرنے کے لیے صفحے کے ہیڈر میں **تازہ کریں** پر کلک کریں۔

پروب اُس مشین پر چلتی ہے جو `cc_server` کی میزبانی کرتی ہے، نہ کہ اُس مشین پر جو آپ دیکھ رہے ہیں۔ اگر آپ ویب کلائنٹ یا پیئر شدہ ڈیوائس پر ہیں، تو "نہیں ملا" کا مطلب ہے کہ سرور ہوسٹ پر CLI غائب ہے۔

دو چیزیں تصدیق کرنی ہیں:

- **ایجنٹ کا اڈاپٹر سیٹ ہے یا نہیں۔** خالی اڈاپٹر والا ایجنٹ **Control Center (بلٹ اِن)** پر ڈسپیچ ہوتا ہے اور رن لاگ `cc-harness` درج کرتا ہے، سو ٹرانسکرپٹ بتا دیتا ہے کہ کیا چلا۔ ماڈل کے بھی نہ ہونے پر یہ Anthropic سے اس کا ڈیفالٹ مانگتا ہے — جو `No credential for provider "anthropic"` کے ساتھ ناکام ہوتا ہے، جب تک آپ نے Anthropic اکاؤنٹ جوڑ نہ رکھا ہو۔ سیڈ کیے گئے اسپیشلسٹ بغیر اڈاپٹر آتے ہیں۔
- **بلٹ اِن اڈاپٹر کا ماڈل ہے یا نہیں۔** اس کی ماڈل فہرست اسی صفحے پر نیچے جڑے فراہم کنندگان سے لائیو آتی ہے، اس لیے جس فراہم کنندہ کے پاس کوئی محفوظ کریڈنشل نہ ہو وہ صفر ماڈل دیتا ہے۔

اڈاپٹر کیٹلاگ خود مقرر ہے — نیا اڈاپٹر رجسٹر کرنے کا کوئی طریقہ نہیں۔ یہاں فی اڈاپٹر جو آپ تبدیل کر سکتے ہیں وہ اس کے لانچ آرگومنٹس اور ماحول کے ویری ایبلز ہیں۔ نوٹ کریں کہ فی اڈاپٹر ماحول کی اوور رائیڈ، اسناد حل ہوتے وقت، خاموشی سے جڑے ہوئے فراہم کنندہ اکاؤنٹ پر غالب آ جاتی ہے۔

## 3. سرور چیک کریں

**ترتیبات → سرور → کنکشن اور اسٹیٹس** (`/settings/server/connection`) دکھاتا ہے کہ یہ کلائنٹ کس سرور سے بات کر رہا ہے اور وہ کیا رپورٹ کرتا ہے۔

ہیڈلیس سرور کے لیے، `GET /healthz` بغیر کلائنٹ کے وہی معلومات ہے۔ یہ بغیر تصدیق کے اور جان بوجھ کر CORS-open ہے:

```
curl http://localhost:9030/healthz
```

یہ سرور کا اسٹیٹس، سیکنڈوں میں اپ ٹائم، لائیو کنکشن گنتی، بائنڈ پورٹ، بلڈ ورژن اور git SHA، ورک اسپیس اسکیما ورژن، RPC کیٹلاگ ورژن، سرور id، نام اور شناخت کا فنگر پرنٹ، کہ بائنڈ غیر محفوظ ہے یا نہیں، اور `watching` / `indexing` / `pending` گنتیوں والا ایک `codeGraph` بلاک لوٹاتا ہے۔ جب کسی کیش نے ٹریفک دیکھی ہو تو یہ ایک `caches` بلاک بھی شامل کرتا ہے؛ ایک ڈیمو سرور `demo: true` شامل کرتا ہے۔

دو چیزیں جاننے کے قابل ہیں جب کوئی تبدیلی "ٹیسٹوں میں چلتی ہے مگر ایپ میں نہیں":

- ڈیسک ٹاپ سورس کے بجائے ترجیحی طور پر ایک **پہلے سے بنائی گئی** `cc_server` بائنری لانچ کرتا ہے۔ کوئی نیا RPC آپریشن یا MCP ٹول اُس وقت تک ظاہر نہیں ہوتا جب تک بائنری دوبارہ بلڈ نہ ہو، اور جب چائلڈ کا git SHA ایپ سے مختلف ہو تو بوٹ ایک وارننگ لاگ کرتا ہے۔
- ڈیسک ٹاپ اُس سپان کیے گئے سرور کو مار دیتا ہے جو 20 سیکنڈ کے اندر اپنا تیار ہونے کا بینر پرنٹ نہ کرے، اور ایک خرابی کی اسکرین پر چلا جاتا ہے۔

## 4. ہوسٹ چیک کریں

**ترتیبات → سرور → تشخیص اور پرائیویسی** (`/settings/server/diagnostics`) ہوسٹ سطح کا صفحہ ہے۔ اس میں شامل ہیں:

- **سینڈ باکسنگ** — ماسٹر ٹوگل، دریافت شدہ بیک اینڈ اور انسٹال کی رہنمائی۔ صرف دریافت شدہ بیک اینڈ سرور سے آتا ہے؛ نیچے دی گئی احتیاط دیکھیں۔ کوئی ری سیٹ کنٹرول نہیں۔
- **سیمانٹک تلاش** — ڈیوائس پر موجود ایمبیڈنگ ماڈل کا لائف سائیکل: انسٹال شدہ، فیصد کے ساتھ ڈاؤن لوڈ ہو رہا، انسٹال نہیں، یا کوئی انسٹال خرابی۔ جب تک یہ انسٹال نہ ہو، میموری اور کوڈ تلاش صرف مطلوبہ الفاظ تک محدود رہتی ہے۔
- **سسٹم رویہ** — ایجنٹس چلتے ہوئے کمپیوٹر کو جگائے رکھیں۔
- **لاگ لیول** — کسی ناکامی کو دوبارہ پیدا کرنے سے پہلے اسے بڑھائیں۔
- **پرائیویسی** — کہ خام diff مواد ایجنٹ کے ماڈل کو بھیجا جا سکتا ہے یا نہیں اور کہ کریش رپورٹس بھیجی جاتی ہیں یا نہیں۔

:::caution[یہ سیکشن ہوسٹ کی رپورٹ دیتا ہے اور اس کے کنٹرولز کلائنٹ سائیڈ ہیں]
اب شناخت اور نفاذ متفق ہیں: جہاں ڈیٹیکٹر کسی نیٹو بیک اینڈ کی رپورٹ دیتا ہے، وہاں اُس ہوسٹ پر ایجنٹ رنز واقعی اُس میں لپٹے ہوتے ہیں۔ مگر اس سیکشن میں واحد زندہ چیز ڈیٹیکٹر ہی ہے۔ ماسٹر ٹوگل اور بیک اینڈ پکر ایسی ترجیحات ہیں جو آپ کے آلے پر محفوظ ہوتی ہیں اور سرور ان میں سے کوئی نہیں پڑھتا — سرور کا اپنا سوئچ `--sandbox` ہے (`on` بطور ڈیفالٹ، باہر نکلنے کے لیے `off`)۔

تو یہاں کی وارننگ پر عمل کرنا بجا ہے، مگر عام طور پر اسی وجہ سے ایجنٹ ناکام نہیں ہو رہا ہوتا۔ یہ تصدیق کرنے کے لیے کہ سرور کس حالت میں ہے، اس کا اسٹارٹ اپ لاگ پڑھیں: یہ بیک اینڈ نوٹ کے ساتھ `agent sandbox ON`، انسٹال کی رہنمائی کے ساتھ `no OS-native agent sandbox on this host`، یا `agent sandbox DISABLED by --sandbox off` پرنٹ کرتا ہے۔ `GET /healthz` میں کوئی سینڈ باکس فیلڈ نہیں ہوتا۔

جہاں کوئی بیک اینڈ نہیں — Windows ہمیشہ، اور Linux یا WSL2 جب `bwrap` اور `socat` نہ ہوں — وہاں رنز سینڈ باکس شدہ **نہیں** ہوتے اور انہیں جو باندھتا ہے وہ گفتگو کا اپنا چیک آؤٹ، صرف پڑھنے والا فورج ٹوکن اور پش گیٹ وے، ایکشن گارڈریلز، ماحول کی صفائی اور ٹول سطح جو اس کا موڈ اجازت دیتا ہے۔
:::

## عام ناکامیاں

### رن شروع ہی نہیں ہوتا اور اڈاپٹر "نہیں ملا" دکھاتا ہے

CLI کو **سرور ہوسٹ پر** انسٹال کریں، پھر ماڈل فراہم کنندگان صفحے پر **تازہ کریں** پر کلک کریں۔ یا ایجنٹ کو بلٹ اِن اڈاپٹر پر بدل دیں، جسے کسی CLI کی ضرورت نہیں، اور اُسی صفحے پر کوئی فراہم کنندہ جوڑیں۔

### ایجنٹ push یا pull request نہیں کھول سکتا

دیکھیں کہ git یا ایجنٹ نے کیا پرنٹ کیا۔ `Control Center policy: …` کا مطلب ہے کہ کسی ایکشن قاعدے نے منع کیا، یا کسی منظوری کا جواب نہیں آیا: **ترتیبات → ورک اسپیس → ایجنٹ اجازتیں** میں **ریموٹ پر پش کریں** اور **pull request کھولیں** دیکھیں۔ اگر git کہے کہ Control Center کے پاس کوئی ایسا GitHub کریڈنشل نہیں جو پش کر سکے، تو اُس ریپو پر GitHub App انسٹال کریں، یا GitHub منسلک کریں۔

### سیمانٹک تلاش کچھ کارآمد نہیں لوٹاتی

**ترتیبات → سرور → تشخیص اور پرائیویسی → سیمانٹک تلاش** چیک کریں۔ جب تک ایمبیڈنگ ماڈل انسٹال نہ ہو، تلاش صرف مطلوبہ الفاظ تک محدود ہے۔ ماڈل انسٹال ہونے سے پہلے لکھی گئی قطاریں کبھی بیک فل نہیں ہوتیں، اس لیے وہ بعد میں بھی صرف مطلوبہ الفاظ تک محدود رہتی ہیں۔

### سرور بالکل بوٹ ہی نہیں ہوتا

نیٹو لائبریریاں لازمی ہیں اور کوئی کمزور موڈ نہیں۔ کوئی غائب dylib `cc_server` کو شروع ہونے سے انکار کرنے پر مجبور کرتی ہے اور خرابی میں قصوروار کا نام دیتی ہے۔ `scripts/natives/build_natives.sh` سے نیٹوز اسٹیج کریں اور سرور بائنری دوبارہ بلڈ کریں۔

### کوئی ایکشن خاموشی سے مسترد ہو جاتا ہے

بغیر کسی منسلک منظور کنندہ کے `prompt` گارڈریل فیصلہ، بطور ڈیزائن مسترد ہوتا ہے۔ **ترتیبات → ورک اسپیس → ایجنٹ اجازتیں** میں ورک اسپیس کے قواعد چیک کریں۔
