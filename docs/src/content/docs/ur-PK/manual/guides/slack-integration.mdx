یہ گائیڈ دکھاتی ہے کہ Slack کو Control Center workspace سے کیسے جوڑیں: مشترکہ Control Center app شامل کر کے، یا اپنی ایک app کے ساتھ جو Control Center آپ کے لیے بناتا ہے یا جو آپ خود بناتے ہیں۔

پہلی باقاعدہ رہنمائی شدہ شروعات کے لیے، دیکھیں [Bridge Slack to your workspace](/ur-PK/ہدایت-نامہ/ٹیوٹوریلز/پہلا-چیٹ-برج/)۔

:::note[Slack واحد chat provider ہے]
bridge ساخت کے لحاظ سے provider سے آزاد ہے — ہر provider کے لیے ایک adapter کے اوپر ایک descriptor-driven UI — لیکن Slack ہی واحد adapter موجود ہے۔ Discord، Telegram، Teams یا Matrix کا کوئی نفاذ نہیں ہے۔
:::

## پیشگی شرائط

- Control Center workspace میں `owner` یا `admin` کا role — chat app جوڑنا workspace settings کی تبدیلی ہے
- Slack workspace میں app بنانے اور انسٹال کرنے کی اجازت
- کچھ بھی عوامی طور پر قابلِ رسائی ہونا ضروری نہیں: آپ کی اپنی app Socket Mode کے ذریعے باہر کی طرف کنکشن کرتی ہے، اور مشترکہ app کے events long poll کے ذریعے Control Center Connect سے سرور تک پہنچتے ہیں، اس لیے سرور کو کسی inbound port، tunnel یا domain کی ضرورت نہیں

## مشترکہ app یا اپنی

ایک workspace ایک وقت میں انہی میں سے کسی ایک پر چلتا ہے۔

| Mode                          | کیا درکار ہے                                                                                                       | آپ کو کیا ملتا ہے                                                                           |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| **Shared Control Center app** | سرور Control Center Connect استعمال کرتا ہے (**Settings → Server → Single sign-on**) اور Connect Slack فراہم کرتا ہے | ایک کلک اور Slack sign-in۔ کوئی app بنانا نہیں، کوئی token چسپاں نہیں، کچھ rotate نہیں کرنا |
| **Your own app**              | آپ کے Slack workspace میں ایک Slack app، جو نیچے دیے گئے تین طریقوں میں سے کسی ایک سے بنی ہو                         | آپ کا اپنا bot نام، descriptions اور slash command، جو Control Center سے editable ہیں        |

### Shared Control Center app شامل کریں

1. Control Center میں **Settings → Workspace → General** پر جائیں اور **Chat bridges** کارڈ تک اسکرول کریں
2. Slack والے بلاک پر **Add Control Center to Slack** قطار تلاش کریں اور **Add to Slack** پر کلک کریں
3. آپ کا براؤزر Slack کھولتا ہے۔ Slack کے ساتھ sign in کریں، Slack workspace چنیں اور install کی منظوری دیں
4. جب براؤزر ایک کوڈ دکھائے، تو اسے اس dialog میں درج کریں جو Control Center نے کھلا چھوڑا ہے۔ اگر براؤزر خود آپ کو app میں واپس لے آئے تو کچھ ٹائپ کرنے کی ضرورت نہیں
5. ایک toast بتاتا ہے کہ app کس Slack workspace میں شامل ہوئی، اور Slack والا بلاک کنکشن کو shared Control Center app پر چلتا دکھاتا ہے

صرف workspace admin app شامل کر سکتا ہے۔ قطار بتاتی ہے کہ جب سرور اپنی apps کے بجائے Connect استعمال کرتا ہو، یا آپ کے Connect میں Slack app نہ ہو، یا اس workspace میں پہلے سے اپنی Slack app جڑی ہو، تو وہ کیوں شروع نہیں ہو سکتی۔

اپنی app سے فرق:

- Slack shared app کے events کو Connect کو بھیجتا ہے۔ Connect صرف ایک reference رکھتا ہے (team، channel اور message id) اور message text گرا دیتا ہے؛ سرور Connect سے references کے لیے long-poll کرتا ہے اور ہر message خود Slack سے پڑھتا ہے۔ slash command کا text Connect سے گزرتا ہے، اسی لیے [`/cc ticket`](#ticket-drafts-from-slack) صرف ایک draft بناتا ہے
- bot token اس سرور کے لیے sealed ہوتا ہے اور Connect کے ذریعے renew ہوتا ہے، اس لیے کوئی token چسپاں یا rotate کرنے کی ضرورت نہیں
- bot کا نام، descriptions اور slash command shared app کے ہیں۔ Slack قطار بتاتی ہے کہ کنکشن shared app پر چل رہا ہے اور **Customize bot** نہیں دیتی
- ایک Slack workspace ایک وقت میں ایک Control Center سرور سے جڑا ہوتا ہے۔ کسی دوسرے سرور سے app شامل کرنے سے وہ وہاں منتقل ہو جاتا ہے اور اس سرور کا کنکشن رک جاتا ہے

mode بدلنے کے لیے، disconnect کریں اور دوسری سمت سے connect کریں۔

### اپنی app: اسے حاصل کرنے کے تین طریقے

| راستہ               | آپ کیا فراہم کرتے ہیں                   | Control Center کیا کرتا ہے                                                                                                                  |
| ------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **Guided**          | ایک app configuration token (`xoxe-…`) | app کو صحیح scopes، events، Socket Mode اور slash command کے ساتھ بناتا ہے؛ وہ دو مرحلے دیتا ہے جن کے لیے Slack کے پاس API نہیں            |
| **Create in Slack** | کچھ نہیں                                 | وہی configuration پہلے سے بھرا ہوا Slack کھولتا ہے؛ آپ workspace چنتے اور تصدیق کرتے ہیں                                                    |
| **By hand**         | مکمل app کے tokens                      | انہیں verify کرتا ہے اور جوڑ دیتا ہے                                                                                                          |

صرف Guided راستہ app کو Control Center سے _قابلِ انتظام_ بھی رکھتا ہے، اور یہی [chat bot کو حسب ضرورت بنانے](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/چیٹ-بوٹ-حسب-ضرورت/) کو ممکن بناتا ہے۔ ایک **Create in Slack** app بعد میں connect dialog میں configuration token چسپاں کر کے قابلِ انتظام بنائی جا سکتی ہے۔

آپ کی اپنی app کے events کبھی Connect سے نہیں گزرتے: Socket Mode انہیں براہِ راست اس سرور تک پہنچاتا ہے۔

## آپشن A: Control Center کو app بنانے دیں

1. [api.slack.com/apps](https://api.slack.com/apps) پر app configuration token کا جوڑا بنائیں اور **refresh** token (`xoxe-…`) کاپی کریں
2. Control Center میں **Settings → Workspace → General** پر جائیں اور **Chat bridges** کارڈ تک اسکرول کریں
3. Slack والے بلاک پر **Create app for me** پر کلک کریں
4. token چسپاں کریں، app کا نام، bot نام، descriptions اور slash command ایڈجسٹ کریں، پھر **Create app** پر کلک کریں
5. dialog کے دکھائے ہوئے باقی دو مراحل پورے کریں، ہر ایک Slack کا لنک ہے:
   - **Basic Information → App-Level Tokens**: `connections:write` scope کے ساتھ ایک token بنائیں (`xapp-…`)
   - **Install App**: workspace میں install کریں اور **Bot User OAuth Token** (`xoxb-…`) کاپی کریں
6. **Paste the credentials** پر کلک کریں اور [Connect](#connect) کے ساتھ جاری رکھیں

configuration token ہر استعمال پر rotate ہوتا ہے۔ Control Center rotated value کو جیسے جیسے آگے بڑھتا ہے محفوظ کرتا ہے، اس لیے آپ کو اسے دوبارہ چسپاں نہیں کرنا پڑتا۔

## آپشن B: Slack میں پہلے سے بھری ہوئی app بنائیں

وہی app، configuration token کے بغیر — Slack آپ کو اپنی create screen دکھاتا ہے جس میں پورا manifest پہلے سے بھرا ہوتا ہے۔

1. Control Center میں **Settings → Workspace → General** پر جائیں اور **Chat bridges** کارڈ تک اسکرول کریں
2. Slack والے بلاک پر **Create app for me** پر کلک کریں
3. app کا نام، bot نام، descriptions اور slash command ایڈجسٹ کریں — یہ link کے ساتھ جاتے ہیں
4. **Create in Slack** پر کلک کریں۔ آپ کا براؤزر Slack کا app-creation page کھولتا ہے جس میں configuration پہلے سے بھری ہوتی ہے
5. Slack workspace چنیں اور تصدیق کریں۔ scopes، events، Socket Mode اور slash command پہلے سے درست ہیں
6. Control Center پر واپس آ کر dialog کے دکھائے ہوئے باقی دو مراحل پورے کریں:
   - **Basic Information → App-Level Tokens**: `connections:write` scope کے ساتھ ایک token بنائیں (`xapp-…`)
   - **Install App**: workspace میں install کریں اور **Bot User OAuth Token** (`xoxb-…`) کاپی کریں
7. **Paste the credentials** پر کلک کریں اور [Connect](#connect) کے ساتھ جاری رکھیں

Slack نہیں بتاتا کہ اس نے کون سی app بنائی، اس لیے Control Center app id نہیں جانتا، اور مرحلہ 6 کے لنک آپ کی app کے بجائے آپ کی app کی فہرست پر جاتے ہیں۔ **Customize bot** کے لیے configuration token درکار ہے۔

## آپشن C: app خود بنائیں

[api.slack.com/apps](https://api.slack.com/apps) پر ایک app بنائیں، پھر اسے اس طرح سیٹ کریں۔

**Socket Mode**: اسے فعال کریں اور ہر request URL خالی چھوڑ دیں۔ Slack ایسے manifest کو مسترد کرتا ہے جو Socket Mode اور webhook delivery دونوں مانگے۔

**Bot token scopes** (OAuth & Permissions):

```text
app_mentions:read
assistant:write
channels:history
chat:write
commands
groups:history
im:history
users:read
users:read.email
```

**Event subscriptions** (bot events):

```text
app_home_opened
app_mention
message.channels
message.groups
message.im
```

`message.channels` اور `message.groups` ہی وہ چیز ہیں جو پہلے سے bridged Slack thread کے اندر _reply_ کو کام کرواتے ہیں۔ ان کے بغیر صرف پہلا mention پہنچتا ہے۔

**Slash command**: `/cc` (کوئی بھی نام چلتا ہے — bridge وہی نام استعمال کرتا ہے جو آخری بار بلایا گیا تھا)۔

**App Home**: Messages tab فعال کریں اور اسے لکھنے کے لیے کھلا رکھیں، تاکہ اراکین bot کو DM کر سکیں۔

**Tokens**: `connections:write` کے ساتھ ایک app-level token بنائیں، پھر app انسٹال کریں اور bot user OAuth token کاپی کریں۔

## Connect

آپ کی اپنی app کے tokens اسی طرح Control Center تک پہنچتے ہیں۔ shared app کو ان میں سے کسی کی ضرورت نہیں۔

1. **Settings → Workspace → General** پر جائیں اور **Chat bridges** کارڈ تک اسکرول کریں
2. Slack والے بلاک پر **Connect Slack** پر کلک کریں
3. فیلڈز بھریں:

| فیلڈ                                          | قدر      | Slack میں یہ کہاں ہے                                          |
| --------------------------------------------- | -------- | -------------------------------------------------------------- |
| **Bot user OAuth token**                      | `xoxb-…` | OAuth & Permissions → Bot User OAuth Token                     |
| **App-level token**                           | `xapp-…` | Basic Information → App-Level Tokens (`connections:write`)     |
| **App configuration refresh token** (اختیاری) | `xoxe-…` | api.slack.com/apps پر app configuration token کا جوڑا           |

ہر قدر کا prefix کوئی بھی چیز بھیجنے سے پہلے دونوں طرف جانچا جاتا ہے، اس لیے غلط خانے میں چسپاں قدر دونوں صورتوں میں ایک ہی جملے کے ساتھ مسترد ہوتی ہے۔

4. **Connect** پر کلک کریں

Control Center کچھ بھی محفوظ کرنے سے _پہلے_ bot token کو Slack کے `auth.test` سے verify کرتا ہے، تاکہ ٹائپو کی اطلاع آپ کو ملے نہ کہ ایک ایسا socket بن جائے جو خاموشی سے کبھی کام نہ کرے۔ app-level token صرف socket کھول کر ہی ثابت ہو سکتا ہے، اس لیے خراب token ایک لمحے بعد اسی قطار میں connection error کے طور پر ظاہر ہوتا ہے۔

اختیاری app configuration token کے بغیر کنکشن ٹھیک کام کرتا ہے — بس آپ Control Center سے bot میں ترمیم نہیں کر سکتے۔

## کنکشن کیا کرتا ہے

- اعتبارنامے workspace کی اپنی ڈائریکٹری میں، اس کے database کے ساتھ، صرف مالک کے لیے قابلِ پڑھائی کے طور پر محفوظ کیے جاتے ہیں۔ یہ کبھی کلائنٹ کی طرف واپس نہیں جاتے۔ shared app کے لیے یہ sealed grant ہے؛ وہ مختصر مدت کا bot token جس میں یہ renew ہوتا ہے، memory میں رہتا ہے
- mentions، Slack thread replies، DMs اور slash commands وصول کرنا شروع کرتا ہے: آپ کی app کے لیے ایک Socket Mode کنکشن کے ذریعے، یا shared app کے لیے سرور کے ایک Connect long poll کے ذریعے
- پہلے bridged ہونے والے ہر Slack thread کو دوبارہ arm کرتا ہے، تاکہ reconnect موجودہ گفتگوؤں کو جاری رکھے اور انہیں بے سہارا نہ چھوڑے
- ایسی workspaces کے لیے کوئی لاگت نہیں جن میں chat app نہ ہو: نہ socket، نہ timers، نہ traffic

:::note[tokens کہاں رکھے جاتے ہیں، اور keychain کیوں نہیں]
bot credentials ہر provider کے لیے `<dataDir>/<workspaceId>/chat_credentials/` میں ایک سادہ JSON فائل ہوتی ہے، جو atomically لکھی جاتی ہے اور صرف owner کے لیے سخت کی جاتی ہے۔ یہ جان بوجھ کر ہے: کسی workspace کو delete کرنے سے وہ directory unlink ہو جاتی ہے تاکہ اس کے tokens بھی ساتھ جائیں، اور `workspace.export` اور backups `workspace.db` کاپی کرتے ہیں — directory نہیں — اس لیے وہ workspace جو آپ کسی اور کو دیتے ہیں اس کے اندر کبھی زندہ bot tokens نہیں ہوتے۔ اس کا نتیجہ یہ ہے کہ کسی دوسری جگہ workspace بحال کرنے کے لیے وہاں Slack کو دوبارہ جوڑنا ہوگا۔

bridge تک رسائی workspace کی **رکنیت** سے ہے، کسی token کے پاس ہونے سے نہیں۔ Slack اکاؤنٹ کو ایک Control Center user سے لنک ہونا چاہیے جو لکھنے والے role کے ساتھ رکن ہو۔ connect، disconnect، shared app کی install، guided setup، setup link اور bot customization سب admin تک محدود ہیں۔
:::

## تصدیق

Slack کی قطار ایک status tag دکھاتی ہے: **Live**، **Connecting…**، **Connection error** (ساتھ میں Slack کی اپنی error)، یا **Not connected**۔ سرے سے سرے تک جانچنے کے لیے:

1. Slack میں، بوٹ کو channel میں مدعو کریں: `/invite @your-bot-name`
2. ایک request کے ساتھ اسے mention کریں
3. ایک Slack thread reply ظاہر ہوتا ہے اور Control Center میں ایک مماثل space ظاہر ہوتی ہے

پھر ہر وہ رکن جو bridge استعمال کرنا چاہتا ہے اپنا اکاؤنٹ خود لنک کرتا ہے — دیکھیں [اپنا Slack اکاؤنٹ لنک کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/چیٹ-اکاؤنٹ-لنک-کریں/)۔

## Slack میں جواب کیسا دکھتا ہے

stream ہونے والے الفاظ کے اوپر ایک گروپ کیا ہوا کارڈ ہوتا ہے جس میں ہر قدم کی ایک قطار ہے۔ setup ایک قطار ہے جس کا عنوان `Working on it…` سے `Cloning …` اور پھر `Starting the agent…` تک بدلتا ہے۔ reasoning ایک `Thinking…` قطار شامل کرتا ہے؛ جب وہ قدم ختم ہو تو اس پر ایک مختصر خیال ظاہر ہو سکتا ہے۔ ہر tool اپنی قطار ہے (`Read lib/main.dart`)۔ جواب کارڈ کے نیچے عام متن کے طور پر آتا ہے۔ کارڈ turn ختم ہونے پر مکمل ہو جاتا ہے، اور run ناکام ہونے، روکے جانے یا turn limit تک پہنچنے پر errored ہو جاتا ہے۔

کارڈ اس لمحے شروع ہوتا ہے جب بوٹ mention قبول کرتا ہے — `Working on it…` — تاکہ Slack thread اس دوران خاموش نہ رہے جب workspace ابھی بن رہا ہو۔ Slack channel میں آپ کا پہلا mention گفتگو بناتا ہے، جو وہ repos کلون کرتا ہے جن پر ایجنٹ کام کرتا ہے، اس لیے وہ setup قطار `Cloning acme/widgets…` پڑھتی ہے، پھر `Setting up Reviewer…`، پھر `Starting the agent…`، اور پھر ایک `Thinking…` قطار جب ایجنٹ واقعی سوچ رہا ہو۔ بڑے repository پر پہلا setup کچھ وقت لیتا ہے؛ کارڈ یہ بتاتا ہے کہ وہ کام کر رہا ہے اور آپ کو نظرانداز نہیں کر رہا۔ اسی Slack thread میں بعد کے mentions پھر بھی `Working on it…` سے شروع ہوتے ہیں، پھر clone کے مراحل چھوڑ دیتے ہیں کیونکہ workspace پہلے سے موجود ہے۔

reasoning دیوار جیسے متن اور tool output کے طور پر رہتی ہے اور کبھی Control Center نہیں چھوڑتی — `Thinking…` قطار کا خیال ایک مختصر سطر ہے، transcript نہیں۔ کارڈ پر **View in Control Center** مکمل گفتگو desktop app میں کھولتا ہے — لنک آپ کے اپنے Control Center سرور پر جاتا ہے، جو براؤزر کو app کے حوالے کر دیتا ہے۔

اگر اس پر کلک کرنے سے کچھ نہ ہو تو یا تو پیغام بھیجنے والا سرور اس مشین سے قابلِ رسائی نہیں جہاں سے آپ نے کلک کیا (مثلاً صرف loopback پر چلنے والا سرور جس پر فون سے کلک کیا گیا)، یا Control Center وہاں چل ہی نہیں رہا۔ جس سرور کا کوئی قابلِ رسائی پتہ نہ ہو وہ بغیر بٹن کے کارڈ بھیجتا ہے، ایسا بٹن نہیں جو کہیں نہ لے جائے۔

## Slack سے ticket drafts

کوئی بھی لنک شدہ رکن جس کا role لکھنے کا ہو، Slack سے ticket تجویز کر سکتا ہے:

```text
/cc ticket Fix the flaky login test | It fails on CI about once a day.
```

`|` سے پہلے کا متن عنوان ہے، اور اس کے بعد کا متن تفصیل۔ بوٹ جواب دیتا ہے کہ اس نے ticket کا draft بنا دیا ہے۔ ابھی کچھ نہیں بنایا جاتا اور نہ ہی ticket automation چلتا ہے: draft آپ کے لیے **Settings → Workspace → Profile & identity → Ticket drafts from chat** میں منتظر رہتا ہے، جہاں آپ عنوان اور تفصیل درست کر سکتے ہیں، پھر **Create ticket** یا **Discard** پر کلک کریں۔

- صرف وہ رکن جس نے کمانڈ چلائی، draft دیکھتا ہے
- جو draft آپ چھوڑ دیں وہ ایک دن بعد ختم ہو جاتا ہے۔ drafts صرف memory میں رہتے ہیں، اس لیے سرور کا restart انہیں بھی ختم کر دیتا ہے
- کارڈ صرف اس وقت ظاہر ہوتا ہے جب آپ کے پاس drafts ہوں

کمانڈ کا متن Slack سے دوبارہ نہیں پڑھا جا سکتا اور shared app پر وہ Connect سے گزرا تھا۔ Control Center میں ticket بنانا ہی اسے آپ کا بناتا ہے۔

## token کو rotate کرنا

یہ سیکشن آپ کی اپنی app پر لاگو ہوتا ہے۔ shared app کا کوئی token rotate کرنے کے لیے نہیں ہے۔

connect dialog میں نئی قدر دوبارہ چسپاں کریں اور **Connect** پر کلک کریں۔ connect کرنے سے اس workspace کے لیے چلنے والا کوئی بھی کنکشن بدل جاتا ہے، اس لیے socket نئی credentials کے ساتھ دوبارہ کھولا جاتا ہے۔

دونوں مطلوبہ tokens ہر connect پر موجود ہونے چاہئیں۔ اختیاری app configuration token جب آپ باکس خالی چھوڑیں تو اپنی محفوظ قدر رکھتا ہے، اس لیے bot token کو rotate کرنے سے app میں ترمیم کرنے کی صلاحیت کبھی ضائع نہیں ہوتی۔

## Disconnect

Slack قطار پر **Disconnect** پر کلک کریں (صرف admins)۔ کنکشن بند ہو جاتا ہے اور اعتبارنامے بھلا دیے جاتے ہیں۔ shared app کے لیے Control Center bot کو Slack workspace سے uninstall بھی کرتا ہے اور اس سرور سے اس کا binding جاری کرتا ہے۔

spaces اور user links جان بوجھ کر باقی رہتے ہیں: اسی app کو دوبارہ connect کرنے سے ہر bridged Slack thread بحال ہو جاتا ہے۔ یہ workspace کے دائرے کی rows ہیں، اس لیے workspace کو delete کرنے سے یہ ویسے بھی ختم ہو جاتی ہیں۔

## خرابیوں کا ازالہ

### قطار پر "Connection error" لکھا ہے

tag کے ساتھ دکھائی گئی error پڑھیں۔ مسترد شدہ credential (`invalid_auth`، `not_authed`، `token_revoked`، `account_inactive`) حتمی ہے — bridge retry بند کر دیتا ہے اور نئے tokens کا انتظار کرتا ہے، کیونکہ منسوخ شدہ token کو بار بار retry کرنا صرف آپ کو rate limit کرتا ہے۔ connect dialog میں tokens دوبارہ چسپاں کریں۔

`missing_scope` error کا مطلب ہے کہ app bridge کی ضرورت سے کم scopes کے ساتھ انسٹال ہے۔ گمشدہ scope شامل کریں، app کو Slack میں دوبارہ انسٹال کریں، پھر دوبارہ connect کریں۔

کوئی بھی عارضی مسئلہ (socket گرنا، Slack کی چھوٹی خرابی) خودبخود exponential backoff کے ساتھ دوبارہ جڑ جاتا ہے، جو 30 سیکنڈ تک محدود ہے، اور Slack کا معمول کا socket rotation یہ backoff بڑھاتا نہیں۔

### بوٹ mention کا جواب نہیں دیتا

- **کیا بوٹ channel میں ہے؟** Slack channel کے پیغامات صرف ان apps کو دیتا ہے جو رکن ہوں۔ `/invite @your-bot-name` چلائیں
- **کیا آپ لنک ہیں؟** غیر لنک شدہ رکن کو اسی Slack thread میں جواب ملتا ہے جو بتاتا ہے کہ کیسے لنک کرنا ہے۔ دیکھیں [اپنا Slack اکاؤنٹ لنک کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/چیٹ-اکاؤنٹ-لنک-کریں/)
- **کیا آپ لکھنے والے role کے ساتھ workspace کے رکن ہیں؟** `viewer` یا `guest` کو بتایا جاتا ہے کہ ان کا role صرف پڑھنے کا ہے۔ bridge کبھی ایسے شخص کی طرف سے کام شروع نہیں کرتا جسے وہ منسوب نہ کر سکے
- **کیا workspace میں کوئی ایجنٹ ہے؟** ایجنٹ کے بغیر پیغام محفوظ ہو جاتا ہے، لیکن اس کا جواب دینے والا کوئی نہیں ہوتا

### channel میں جواب دیتا ہے مگر عام پیغامات کو نظرانداز کرتا ہے

یہ جان بوجھ کر ہے۔ DM کے باہر، bridge صرف اس پیغام پر عمل کرتا ہے جو بوٹ کو mention کرے، یا اس Slack thread میں جواب جو اس کی اپنی ہو۔ باقی سب دوسروں کی گفتگو ہے۔

### جوابات ایک بڑے پیغام کے طور پر آتے ہیں، بہاؤ میں نہیں

قطار کہتی ہے "Live streaming is off for this Slack app — replies arrive as one message."۔ Slack کے stream ہونے والے جوابات کے لیے Agents & AI Apps کی خصوصیت ایک ادائیگی والے پلان پر درکار ہے؛ جب Slack اس سے انکار کرے تو bridge اس کنکشن کی باقی عمر کے لیے اسے مانگنا بند کر دیتا ہے اور مکمل جوابات بھیجتا ہے۔ کچھ ضائع نہیں ہوتا — مکمل transcript ہمیشہ Control Center میں ہوتا ہے۔

stream ہونے کے لیے Slack thread anchor بھی درکار ہے، اس لیے جواب جس کے پاس بڑھنے کے لیے کوئی Slack thread نہ ہو وہ مکمل بھیجا جاتا ہے۔ task card پھر بھی پہنچتا ہے: مکمل جواب کی صورت میں وہ اسی پیغام پر آتا ہے، پہلے ہی مکمل۔

### جواب کے اوپر کارڈ نہیں ہے

Slack کے task cards اسی نئی Agents & AI Apps سطح کا حصہ ہیں جس میں stream بھی ہے، اور Slack انہیں صرف کال کے وقت مسترد کرتا ہے۔ جب ایسا ہو تو Control Center جواب رکھتا ہے اور کارڈ کو اس کنکشن کی باقی عمر کے لیے ہٹا دیتا ہے — بغیر جواب کے status line سے بہتر ہے بغیر status line کے جواب۔

### "Control Center needs an app configuration token to edit the bot"

**Customize bot** قطار غیر فعال ہے کیونکہ کنکشن میں app configuration token نہیں ہے۔ (shared app میں **Customize bot** قطار سرے سے نہیں ہوتی: بوٹ shared app کا ہے۔) یہ ہاتھ سے یا **Create in Slack** کے ذریعے بنی app کے لیے متوقع ہے — Slack نے کبھی Control Center کو نہیں بتایا کہ وہ کون سی app ہے۔ api.slack.com/apps پر ایک token جوڑا بنائیں اور refresh token بھر کر دوبارہ connect کریں۔

### طویل جواب کٹ جاتا ہے

Slack ایک پیغام کو زیادہ سے زیادہ 40,000 حروف تک محدود کرتا ہے، اس لیے bridge 39,000 پر کاٹتا ہے اور Control Center کا حوالہ شامل کرتا ہے — مختصر کیا ہوا جواب اس جواب سے بہتر ہے جسے Slack مکمل طور پر مسترد کر دے۔ مکمل متن ہمیشہ space transcript میں ہوتا ہے۔
