یہ گائیڈ دکھاتی ہے کہ گفتگو کے پہلے کے کسی نقطے پر واپس جا کر اُسے کسی اور سمت لے جانا کیسے ممکن ہے — اور ساتھ ہی جو راستہ آپ نے چھوڑا وہ بھی برقرار رہے۔

## ایک بات جو جاننے کے قابل ہے

**شاخ بنانا کچھ نہیں لکھتا۔** گفتگو پیغامات کا ایک درخت ہے جس کی نوک پر ایک پوائنٹر ہوتا ہے، اور واپس جانا اُسی پوائنٹر کو ہلاتا ہے۔ نہ کچھ حذف ہوتا ہے، نہ کچھ چھپتا ہے، اور واپس بدلنا ایک اور پوائنٹر حرکت ہے۔

اسی لیے یہاں پرامپٹ میں ترمیم کر کے دوبارہ چلانا محفوظ ہے: جس جواب سے آپ موازنہ کر رہے تھے وہ اب بھی موجود ہے۔

## شاخیں دیکھیں

```
/tree
```

نیویگیٹر ہر پیغام کی فہرست دیتا ہے، ہر فورک پر انڈینٹ کر کے، اور موجودہ راستے پر **اس برانچ پر** کا نشان لگا ہوتا ہے۔ جس گفتگو میں کبھی فورک نہ ہوا ہو وہ ویسی ہی سیدھی فہرست دکھائی دیتی ہے جیسی وہ ہمیشہ رہی — جب تک نیویگیٹ کرنے کو کچھ نہ ہو، نیویگیٹر دیکھنے میں کچھ نہیں لیتا۔

ہر قطار دو ایکشن پیش کرتی ہے۔

| ایکشن                          | اثر                                                    |
| ------------------------------- | --------------------------------------------------------- |
| **یہاں سے جاری رکھیں**          | پوائنٹر کو ہلاتا ہے۔ آپ کا اگلا پیغام اُسی پیغام سے جاری رہتا ہے۔ |
| **نئی گفتگو میں فورک کریں** | اُس پیغام تک کا راستہ ایک نئی گفتگو میں کاپی کرتا ہے۔ |

## شاخ: مختلف طریقہ آزمائیں

1. `/tree`
2. وہ پیغام ڈھونڈیں جہاں سے آپ دوبارہ شروع کرنا چاہتے ہیں — عام طور پر وہی آخری پیغام جس پر آپ مطمئن تھے۔
3. **یہاں سے جاری رکھیں۔**
4. نیا پرامپٹ ٹائپ کریں۔

پرانا سلسلہ اب بھی درخت میں موجود ہے؛ `/tree` اب اُس نقطے سے دو راستے دکھائے گا، اور آپ اُن کے درمیان آزادی سے بدل سکتے ہیں۔

:::note[جو راستہ آپ نے چھوڑا وہ اب بھی موجود ہے]
شاخ بنانا کچھ نہیں چھپاتا اور نہ کچھ حذف کرتا ہے۔ `/tree` ہر راستے کی فہرست دیتا ہے، موجودہ پر **اس برانچ پر** کا نشان لگاتا ہے، اور بدلنے کا ذریعہ یہی ہے۔
:::

## فورک: اُسے کہیں اور لے جائیں

فورک کرنا راستے کو اُسی اسپیس میں ایک **نئی گفتگو** میں کاپی کرتا ہے۔ اِسے اُس وقت استعمال کریں جب دونوں سمتیں آگے بھی الگ الگ ہوتی رہیں گی اور آپ بدلنے کے بجائے اُنہیں ساتھ ساتھ رکھنا چاہتے ہوں۔

کاپی میں پیغامات کی نئی ids ہوتی ہیں۔ اگر دو گفتگوئیں ایک ہی قطاریں سانجھا کرتیں تو ایک دوسری کے بعد والے پیغامات دکھانے لگتیں، اور فورک کو روکنا بالکل یہی چیز ہے۔

## واپس کرنا بمقابلہ شاخ بنانا

یہ دو مختلف اوزار ہیں اور یہ فرق اہم ہے۔

|                     | واپس کرنا                                             | شاخ بنانا                          |
| ------------------- | -------------------------------------------------- | ------------------------------- |
| بعد والے پیغامات  | ٹرانسکرپٹ سے چھپ جاتے ہیں                          | `/tree` میں اب بھی نظر آتے ہیں         |
| **worktree**    | اُس باری کے اسنیپ شاٹ تک واپس کر دیا جاتا ہے                 | بغیر تبدیلی                        |
| انڈو                | **واپسی انڈو کریں** بیچ بحال کر دیتا ہے                  | پوائنٹر واپس ہلاتا ہے            |

واپس کرنا اُس وقت چاہیے جب ایجنٹ نے ایسی *فائلیں* بدلی ہوں جو آپ واپس چاہتے ہیں۔ شاخ اُس وقت چاہیے جب گفتگو غلط سمت چلی گئی ہو مگر فائلیں ٹھیک ہوں۔

واپس کرنا شاخ کی نوک کو بھی ہلاتا ہے، اس لیے آپ کا اگلا پیغام صحیح جگہ سے جاری ہوتا ہے، نہ کہ ایسی دُم سے جو اب کوئی نہیں دیکھ سکتا۔

## اِسے ایپ سے باہر نکالیں

### `/export`

ایک **خود مکمل HTML فائل** لکھتا ہے: پوری گفتگو، ساتھ میں سمیٹنے کے قابل ٹول کارڈز جو دکھاتے ہیں کہ ہر کال کو کیا دیا گیا اور اُس نے کیا واپس کیا۔ کوئی اسٹائل شیٹ نہیں، کوئی اسکرپٹ نہیں، کوئی امیج ہوسٹ نہیں — یہ USB اسٹک سے چلتی ہے اور پانچ سال بعد بھی چلے گی۔

- **ڈیسک ٹاپ:** `Documents/ControlCenter/exports/`، ٹائم سٹیمپ کے ساتھ تاکہ دوسرا ایکسپورٹ پہلے والے کو نہ لکھ مارے۔
- **ویب:** براؤزر ڈاؤن لوڈ۔

### `/dump`

ٹرانسکرپٹ کو کلپ بورڈ پر markdown کے طور پر کاپی کرتا ہے، ٹول کالز سمیٹنے کے قابل بلاکس میں۔ کسی issue میں پیسٹ کرنے کے لیے یہی والا ہے۔

استدلال جان بوجھ کر شامل نہیں کیا جاتا: یہ ماڈل کی عارضی جگہ ہے، اور بگ رپورٹ کوئی شخص پڑھتا ہے۔
