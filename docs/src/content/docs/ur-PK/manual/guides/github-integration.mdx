یہ گائیڈ سیٹ اپ کے GitHub سے متعلق حصوں کا احاطہ کرتی ہے۔ GitHub تین معاون
کوڈ ہوسٹس میں سے ایک ہے — GitLab یا Bitbucket جوڑنے، اور یہ کہ ایک ورک اسپیس انہیں کیسے
ملاتی ہے، کے لیے [کوڈ ہوسٹ جوڑیں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/کوڈ-ہوسٹ-جوڑیں/)
دیکھیں۔

## پیشگی شرائط

- ایسا GitHub اکاؤنٹ جس کے پاس اُن ریپوز تک رسائی ہو جن پر آپ کام کرنا چاہتے ہیں
- یا تو آپ کے سرور کے لیے رجسٹر شدہ ایک GitHub App (دیکھیں
  [GitHub App بنائیں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/github-app/)) تاکہ آپ **سائن اِن** کر سکیں،
  **یا** `repo` اور `read:org` والا ذاتی رسائی ٹوکن پیسٹ کرنے کے لیے

:::note[اسناد سرور پر رہتی ہیں، آپ سے منسلک]
جو مشین آپ پر ٹائپ کر رہے ہیں اس پر کچھ محفوظ نہیں ہوتا۔ آپ کی اسناد آپ کے
`cc_server` کے پاس، آپ کے صارف id کے تحت رکھی جاتی ہیں، اور آپ جس بھی ڈیوائس سے سائن اِن
کرتے ہیں وہی استعمال کرتی ہے — ڈیسک ٹاپ، ویب اور فون۔ اُسی سرور کا کوئی دوسرا رکن اسے
پڑھ نہیں سکتا، اور کسی کو سائن اِن کرانا وہ خود کرتا ہے۔
:::

## GitHub سے سائن اِن کریں

ایک **ڈیوائس فلو**: GitHub آپ کو ایک مختصر کوڈ دکھاتا ہے، آپ github.com پر اس کی منظوری
دیتے ہیں، اور سرور کو اسناد مل جاتی ہیں — نہ کوئی callback URL، نہ پورٹ، نہ ظاہر کرنے کو
کچھ۔ یہ تب دستیاب ہے جب سرور کے پاس کلائنٹ id ہو، جو کوئی سرکاری بلڈ پہلے سے لے کر آتا ہے۔

1. **ترتیبات → ورک اسپیس → پروفائل اور شناخت → کوڈ ہوسٹنگ** پر جائیں (یا آن بورڈنگ کا پہلا
   قدم)
2. **GitHub** قطار پر **GitHub سے سائن اِن** پر کلک کریں
3. ایک ڈائیلاگ آٹھ حروف کا کوڈ دکھاتا ہے اور آپ کے براؤزر میں
   [github.com/login/device](https://github.com/login/device) کھولتا ہے۔
   کوڈ پہلے ہی آپ کے کلپ بورڈ پر ہے
4. اسے پیسٹ کریں، ایپ کی منظوری دیں اور واپس آ جائیں۔ قطار خود ہی
   "_your-username_ کے طور پر سائن اِن" پر بدل جاتی ہے

براؤزر میں کام مکمل کرتے وقت ڈائیلاگ بند کیا جا سکتا ہے — سرور کوڈ کی میعاد ختم ہونے
(تقریباً 15 منٹ) تک پولنگ کرتا رہتا ہے، چنانچہ سائن اِن پھر بھی مکمل ہو جاتا ہے۔

## یا ٹوکن پیسٹ کریں

یہ اُس وقت کا متبادل ہے جب سرور کے پاس کوئی App نہ ہو، جب App کسی ایسے اکاؤنٹ پر انسٹال
نہ ہو جس کی آپ کو ضرورت ہو، یا جب آپ بس PAT استعمال کرنا ترجیح دیں۔

1. **ترتیبات → ورک اسپیس → پروفائل اور شناخت → کوڈ ہوسٹنگ** پر جائیں
2. **GitHub** قطار پر **ٹوکن شامل کریں** پر کلک کریں
3. `repo` اور `read:org` والا ٹوکن پیسٹ کریں (کلاسک) اور محفوظ کریں۔ **fine-grained**
   ٹوکن کو ریپوزٹری **Contents** اور **Pull requests** (پڑھنا اور لکھنا)، نیز
   **Checks** اور **Actions** (پڑھنا) درکار ہوتے ہیں۔

ٹوکن کو محفوظ ہوتے ہی جانچ لیا جاتا ہے، اس لیے قطار اس اکاؤنٹ کا نام بتا سکتی ہے جس سے
یہ تعلق رکھتا ہے۔ اسے ہٹانے کے لیے **منقطع کریں** پر کلک کریں۔

چیک پوائنٹ: **GitHub** قطار "_your-username_ کے طور پر سائن اِن" پڑھتی ہے۔ جب جواب
دینے والی اسناد آپ کی نہ ہو تو ایک لاحقہ ذریعہ بتاتا ہے — "اس سرور کی ایپ کے ذریعے" یا
"ماحول سے"۔

:::note[ترجیح مقرر ہے]
آپ کی طرف سے کی گئی درخواست **آپ کی** اسناد استعمال کرتی ہے، اور بس — ماحول سرور کی
اسناد ہے، آپ کی نہیں، اس لیے وہ کبھی آپ کی جگہ نہیں لیتا۔ جس کام کے پیچھے کوئی انسان نہ
ہو (ویب ہکس، PR پولنگ، ٹکٹ ہم آہنگی) وہ پہلے سرور کی ایپ شناخت، پھر سرور مالک کی اسناد،
پھر ماحول استعمال کرتا ہے۔
:::

## انضمام آپ کو کیا دیتا ہے

| خصوصیت                 | کیسے                                                                                                           |
| ----------------------- | -------------------------------------------------------------------------------------------------------------- |
| PR فہرست اور تفصیل      | GitHub REST API، سرور سے، ایپ شناخت یا آپ کی اپنی اسناد پر                                                     |
| چیک رنز                 | GitHub Checks API                                                                                              |
| ریویو کی اشاعت          | ایک صارف گیٹ شدہ قدم جو آپ کا ریویو PR پر پوسٹ کرتا ہے                                                          |
| ریپو رجسٹریشن           | کوئی چیک آؤٹ قبول ہوتا ہے اگر اس کا `origin` ریموٹ github.com — یا gitlab.com / bitbucket.org — کی طرف اشارہ کرے |
| ایجنٹ کی GitHub رسائی   | اسناد بروکر صرف پڑھنے والا ٹوکن `GH_TOKEN` / `GITHUB_TOKEN` کے طور پر داخل کرتا ہے؛ پش Control Center سے گزرتے ہیں |
| اطلاعاتی پنگز           | آپ کے GitHub اطلاعاتی ان باکس کی سرور کی طرف سے پولنگ "pull request میں ذکر" اور "ریویو کی درخواست" اٹھاتی ہے   |
| صارف پروفائلز           | پروفائل ہوور کارڈز اور فی مصنف PR فلٹرنگ                                                                        |

کچھ راستے سستا پڑنے پر REST کے بجائے GraphQL API استعمال کرتے ہیں — compose-PR چنندہ کے
لیے برانچ کی سرگرمی، اور وہ لائیو ریویو حالت جو فیصلہ کرتی ہے کہ ریویو کی درخواست والی
اطلاع ابھی زیر التوا ہے یا نہیں۔

## GitHub کے تعطل پر نظر رکھیں

جب کوئی فراہم کنندہ متاثر ہو تو ٹائٹل بار ایک اسٹیٹس چپ دکھاتا ہے، جو GitHub، Claude،
OpenAI اور Kimi کا احاطہ کرتی ہے۔ **سب کچھ ٹھیک ہونے پر یہ چھپی رہتی ہے** — اس کا موجود
ہونا مسئلہ بتاتا ہے، اس کا غائب ہونا نہیں۔

اسٹیٹس چپ پر کلک کر کے ایک فل آؤٹ کھولیں جس میں ہر فراہم کنندہ کی حالت اور ایک ریفریش بٹن
ہوتا ہے۔ حالتیں ہر دو منٹ میں خود بخود تازہ ہو جاتی ہیں۔

## جانیں کہ ایجنٹس GitHub پر کیسے عمل کرتے ہیں

- GitHub worktree میں کام کرنے والے ایجنٹ کو ہمیشہ صرف پڑھنے والا GitHub ٹوکن ملتا ہے۔ پش
  Control Center سے گزرتے ہیں، جو پہلے **ریموٹ پر پش کریں** قاعدے سے پوچھتا ہے اور پھر
  پش کو ایسے رائٹ ٹوکن کے ساتھ آگے بڑھاتا ہے جو ایجنٹ کے پاس کبھی نہیں ہوتا۔ دیکھیں
  [سینڈ باکس پالیسیاں کنفیگر کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/سینڈ-باکس-پالیسیاں/)
- ایجنٹ جو کمیٹ بناتا ہے وہ **بطور ایجنٹ** تصنیف ہوتے ہیں — ڈسپلے نام کے ساتھ
  ` (agent)`، ایجنٹ کے id پر بنے ایک مصنوعی ایڈریس پر — کبھی کسی انسان کے طور پر نہیں۔
  جس نے مانگا اُسے ایک `Co-Authored-By` trailer کے ساتھ کریڈٹ ملتا ہے
- GitHub App کنفیگر ہونے پر، بروکر ہر لانچ پر وسیع ٹوکن دینے کے بجائے باریک دائرے والے،
  ریپو تک محدود، تقریباً ایک گھنٹے کے انسٹالیشن ٹوکن بناتا ہے۔ انسٹالیشن رن کے ریپو کے
  **مالک** سے طے ہوتی ہے، چنانچہ کئی اکاؤنٹس پر انسٹال ایک ہی App صحیح طور پر اُس اکاؤنٹ
  تک محدود رہتا ہے جسے رن چھوتا ہے۔ App کے بغیر، ایجنٹس کو ماحول والا ٹوکن ملتا ہے، جسے
  صرف پڑھنے تک محدود نہیں کیا جا سکتا: تب پش قاعدہ `git push` کو پابند کرتا ہے، مگر اُس
  کوڈ کو نہیں جو ٹوکن براہِ راست استعمال کرے
- ٹوکن ہمیشہ بروکر کا ہوتا ہے، کبھی درخواست کرنے والے رکن کا نہیں۔ ایسے رنز سے سرور کا
  ٹوکن روک لیا جاتا ہے جو کسی ایسے رکن کی جانب سے چل رہے ہوں جو مالک نہ ہو اور جس نے
  GitHub منسلک نہ کیا ہو

## خرابیوں کا ازالہ

### PR فہرست خالی ہے اور کہتی ہے کہ GitHub منسلک نہیں

اِس سرور پر آپ کی کوئی GitHub اسناد نہیں۔ **کوڈ ہوسٹنگ** میں سائن اِن کریں یا ٹوکن پیسٹ
کریں۔ دوسرے کوڈ ہوسٹس کے ریپوز متاثر نہیں ہوتے — صرف GitHub والے کچھ نہیں ڈالتے۔

### قطار "ٹوکن شامل کریں" دکھاتی ہے مگر "GitHub سے سائن اِن" نہیں

سرور کے پاس کوئی کلائنٹ id نہیں — جو کہ سورس سے بنائے گئے بلڈ کی معمول کی حالت ہے، کیونکہ
اسناد صرف سرکاری بلڈز میں شامل کی جاتی ہیں۔ دیکھیں
[GitHub App بنائیں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/github-app/): اس میں تقریباً دو منٹ
لگتے ہیں اور یہ صرف سرور مالک کو، ایک بار کرنا ہوتا ہے۔

### سائن اِن ڈائیلاگ کہتا ہے کہ فراہم کنندہ نے کوئی ڈیوائس کوڈ واپس نہیں کیا

GitHub App موجود ہے مگر اس کا **Device flow** چیک باکس بند ہے۔ ایپ کی ترتیبات
(General → Device flow) میں اسے آن کریں اور دوبارہ کوشش کریں۔

### جب مجھے اپنے اکاؤنٹ کی توقع تھی تو قطار "اس سرور کی ایپ کے ذریعے" کہتی ہے

آپ نے سائن اِن نہیں کیا؛ جو آپ دیکھ رہے ہیں وہ سرور کی ایپ شناخت کا جواب ہے۔ اُس قطار پر
**GitHub سے سائن اِن** پر کلک کریں۔

### fine-grained PAT مرج بٹن یا چیک اسٹیٹس نہیں دکھاتا

ٹوکن کو **Contents** اور **Pull requests** (پڑھنا اور لکھنا)، نیز **Checks** اور
**Actions** (پڑھنا) درکار ہیں۔ اسے تبدیل کرنے کے بعد، کوڈ ہوسٹنگ میں دوبارہ پیسٹ کریں۔

### ریپو شامل کرنا مسترد ہو جاتا ہے

رجسٹریشن کے لیے تینوں لازم ہیں: پاتھ کسی git ورک ٹری کے اندر ہو، اس میں ایک `origin`
ریموٹ ہو، اور وہ ریموٹ کسی معاون کوڈ ہوسٹ (github.com، gitlab.com یا bitbucket.org) کی
طرف اشارہ کرے۔ دیکھیں
[ورک اسپیس میں ریپوز شامل کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/ریپوز-شامل-کریں/)۔

### زیادہ استعمال کے بعد سب کچھ کچھ دیر کے لیے رک جاتا ہے

یہ ریٹ لمٹ سرکٹ بریکر ہے۔ GitHub اپنی بنیادی حد کا اشارہ `403` کے ساتھ
`x-ratelimit-remaining: 0` اور ایک ری سیٹ وقت سے دیتا ہے؛ ایک دیکھتے ہی، کلائنٹ ونڈو
گزرنے تک مزید درخواستیں نیٹ ورک کال کے بغیر مقامی طور پر ناکام کر دیتا ہے، چنانچہ دوبارہ
کوششوں کا طوفان حد کو مزید گہرا نہیں کر سکتا۔ عارضی ناکامیاں exponential backoff کے ساتھ
تین بار تک دوبارہ کی جاتی ہیں، `retry-after` کا لحاظ رکھتے ہوئے۔
