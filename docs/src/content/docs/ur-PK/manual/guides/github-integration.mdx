یہ گائیڈ سیٹ اپ کے GitHub سے مخصوص حصوں کا احاطہ کرتی ہے۔ GitHub تین تعاون یافتہ code hosts میں سے ایک ہے۔ GitLab یا Bitbucket جوڑنے کے لیے، اور یہ دیکھنے کے لیے کہ ایک workspace انہیں کیسے ملاتا ہے، دیکھیں [کوڈ ہوسٹ جوڑیں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/کوڈ-ہوسٹ-جوڑیں/)۔

## پیشگی شرائط

- ایک GitHub اکاؤنٹ جس کی ان repos تک رسائی ہو جن پر آپ کام کرنا چاہتے ہیں
- ایک سرور جو لوگوں کو GitHub میں sign in کرا سکے: یا اپنی GitHub App (دیکھیں [GitHub App بنائیں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/github-app/))، یا Control Center Connect، جسے سرور کا مالک **ترتیبات → سرور → سنگل سائن آن** میں چنتا ہے

:::note[اعتبارنامے سرور پر رہتے ہیں اور آپ سے منسلک ہیں]
جس مشین پر آپ ٹائپ کر رہے ہیں اس پر کچھ بھی محفوظ نہیں ہوتا۔ آپ کا GitHub sign-in آپ کے `cc_server` کے پاس رہتا ہے، آپ کے user id سے کلید کیا ہوا، اور جس آلے سے بھی آپ sign in کریں وہ اسے استعمال کرتا ہے: desktop، web اور phone۔ اسی سرور کا کوئی اور رکن اسے استعمال نہیں کر سکتا، اور انہیں sign in کرانا ان کا اپنا کام ہے۔
:::

## GitHub میں sign in

GitHub صرف sign-in ہے: کوئی ٹوکن چسپاں کرنے کی ضرورت نہیں۔

1. **ترتیبات → ورک اسپیس → پروفائل اور شناخت → کوڈ ہوسٹنگ** پر جائیں (یا آن بورڈنگ کے پہلے مرحلے پر)
2. **GitHub** قطار پر، **Sign in to GitHub** پر کلک کریں
3. آپ کا براؤزر GitHub کھولتا ہے۔ app کی منظوری دیں

sign-in کیسے ختم ہوتا ہے، اس کا انحصار اس پر ہے کہ اسے کون چلا رہا ہے:

- **سرور کی اپنی app:** GitHub آپ کے براؤزر کو سرور پر واپس بھیجتا ہے اور dialog خود پہچان لیتا ہے۔ ٹائپ کرنے کو کچھ نہیں
- **Control Center Connect:** براؤزر کا صفحہ ایک 8 حروف کا کوڈ دکھاتا ہے۔ اسے dialog میں ٹائپ کریں، یا براؤزر کو `control-center://` لنک کے ذریعے Control Center کھولنے دیں اور ٹائپ کرنے سے بچیں

checkpoint: **GitHub** قطار پڑھتی ہے "Signed in as _your-username_"۔

dialog ایسا کوڈ یا لنک رد کرتا ہے جو اس نے خود شروع نہیں کیا، اور **یہ سائن اِن یہاں سے شروع نہیں ہوا** دکھاتا ہے۔ اگر کوئی آپ کو sign-in کا لنک بھیجے تو آگے نہ بڑھیں: اسے مکمل کرنے سے آپ کا اکاؤنٹ ان کے سرور سے جڑ جائے گا۔

اپنا sign-in ہٹانے کے لیے **منقطع کریں** پر کلک کریں۔ GitHub سے sign out کرنا، یا workspace سے ہٹایا جانا، سرور کے آپ کی جانب سے جاری کیے ہوئے ہر ٹوکن کو بھی باطل کر دیتا ہے۔

## آپ کا credential کس کی نمائندگی کرتا ہے

- **آپ جو بھی کرتے ہیں** (PR صفحہ کھولنا، ریویو پوسٹ کرنا، منظوری، merge) وہ **آپ کے** sign-in پر چلتا ہے اور کسی اور پر نہیں۔ اگر آپ sign in نہیں ہیں تو ایپ یہ بتاتی ہے اور sign in کرنے کو کہتی ہے۔ کوئی اور credential آپ کی جگہ نہیں لیتا
- **وہ کام جو کوئی ٹائپ نہیں کر رہا** (ایجنٹ runs، pipelines، PR polling، بوٹ کے جوابات، clones) ایک repository کے لیے ٹوکن لیتا ہے، جو سرور کی GitHub App سے یا Connect کے ذریعے جاری ہوتا ہے۔ یہ اس تک محدود ہے جو وہاں ایک ذمہ دار رکن کر سکتا ہے: وہ رکن جس نے درخواست کی، ورنہ workspace کا مالک۔ جو رکن push نہیں کر سکتا، وہ ٹوکن کو صرف پڑھنے تک محدود کر دیتا ہے
- **خودکارسازی کبھی pull request کو منظور نہیں کرتی۔** منظوری ایک فرد کا کام ہے

## انضمام آپ کو کیا دیتا ہے

| خصوصیت                 | طریقہ                                                                                                                         |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| PR فہرست اور تفصیل     | سرور سے GitHub REST API، آپ کے اپنے sign-in پر                                                                               |
| Check runs             | GitHub Checks API                                                                                                             |
| ریویو اشاعت            | ایک user-gated قدم جو آپ کا ریویو آپ کے نام سے PR پر پوسٹ کرتا ہے                                                             |
| Repo رجسٹریشن          | checkout قبول ہوتا ہے اگر اس کا `origin` remote github.com، یا gitlab.com / bitbucket.org کی طرف اشارہ کرے                       |
| ایجنٹ کی GitHub رسائی  | run کے ایک repository کا ٹوکن بطور `GH_TOKEN` / `GITHUB_TOKEN`؛ pushes Control Center کے ذریعے جاتے ہیں                       |
| اطلاعی pings           | آپ کے GitHub notification inbox کا سرور کی جانب سے poll "mentioned in pull request" اور "review requested" اٹھاتا ہے          |
| صارف پروفائلز          | پروفائل ہوور کارڈز اور ہر مصنف کے لحاظ سے PR فلٹرنگ                                                                            |

کچھ راستے REST کے بجائے GraphQL API استعمال کرتے ہیں جہاں یہ سستا ہو: compose-PR picker کے لیے branch activity، اور وہ live review state جو طے کرتی ہے کہ "review requested" اطلاع ابھی زیرِ التوا ہے یا نہیں۔

## GitHub کی outages پر نظر رکھیں

جب کوئی provider خراب ہو تو title bar ایک status chip دکھاتا ہے، جو GitHub، Claude، OpenAI اور Kimi کو کور کرتا ہے۔ **جب سب کچھ صحت مند ہو تو یہ چھپا رہتا ہے**: presence مسئلہ بتاتا ہے، اس کی غیر موجودگی نہیں۔

chip پر کلک کریں تو ہر provider کی حالت اور refresh بٹن کے ساتھ ایک flyout کھلتا ہے۔ statuses ہر دو منٹ بعد خود refresh ہوتے ہیں۔

## جانیں کہ ایجنٹس GitHub پر کیسے عمل کرتے ہیں

- GitHub worktree میں کام کرنے والا ایجنٹ اس ایک repository کا ٹوکن لیتا ہے۔ وہ کوڈ پڑھ سکتا ہے اور جب ذمہ دار رکن push کر سکے تو pull requests پر تبصرہ کر سکتا ہے، اور جب نہ کر سکے تو صرف پڑھ سکتا ہے۔ push Control Center سے گزرتا ہے، جو **push to a remote** قاعدے سے پوچھتا ہے اور پھر اسے ایک write ٹوکن پر آگے بڑھاتا ہے جو ایجنٹ کبھی نہیں رکھتا۔ دیکھیں [sandbox policies ترتیب دیں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/سینڈ-باکس-پالیسیاں/)
- ایجنٹ کے کامیٹس ہمیشہ requester کی Git شناخت کو author اور committer دونوں کے طور پر استعمال کرتے ہیں۔ پہلے سے طے شدہ طور پر، `Co-Authored-By: Control Center <hi@usectrl.dev>` trailer GitHub `@usectrl` کو co-author کے طور پر کریڈٹ دیتا ہے۔ **ترتیبات → آپ → کمیٹ کی نسبت** اس co-author کریڈٹ کو بغیر آپ کی شناخت بدلے بند کر سکتا ہے۔ **ترتیبات → ورک اسپیس → عام** میں workspace کی سطح کی تبدیلی مقدم ہوتی ہے اور اس ذاتی toggle کو لاک کر دیتی ہے۔ Claude Code کی اپنی attribution ہمیشہ غیر فعال ہے۔ commit signing کو اپنی درست کنفیگریشن درکار ہے
- rig پر آپ جو terminal کھولتے ہیں وہ آپ کا اپنا sign-in لیتا ہے، ایک repository تک محدود، اس لیے وہاں کے pushes آپ کے ہیں
- جب کوئی ٹوکن جاری نہ ہو سکے (کوئی ذمہ دار شخص sign in نہیں، app مالک پر انسٹال نہیں، یا installation معطل ہے)، تو run ٹوکن کے بغیر شروع ہوتا ہے اور اس کی notes وجہ بتاتے ہیں۔ کوئی fallback credential نہیں

## خرابیوں کا ازالہ

### PR فہرست خالی ہے اور کہتی ہے GitHub متصل نہیں

آپ اس سرور پر GitHub میں sign in نہیں ہیں۔ **کوڈ ہوسٹنگ** کے تحت **Sign in to GitHub** پر کلک کریں۔ دوسرے forges کے repos متاثر نہیں ہوتے۔

### GitHub قطار کہتی ہے اس سرور پر sign-in سیٹ نہیں

سرور کے پاس نہ اپنی GitHub App ہے نہ Connect۔ سرور کا مالک **ترتیبات → سرور → سنگل سائن آن** میں ایک چنتا ہے: **میری GitHub ایپ بنائیں** تقریباً دو منٹ لیتا ہے۔ دیکھیں [GitHub App بنائیں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/github-app/)۔

### dialog کہتا ہے کوڈ میل نہیں کھاتا

کوڈ بالکل ویسے ٹائپ کریں جیسے براؤزر دکھاتا ہے: 8 حروف اور ہندسے۔ پانچ غلط کوڈ sign-in ختم کر دیتے ہیں؛ دوبارہ شروع کریں۔

### sign-in کہتا ہے app انسٹال نہیں ہے

GitHub App کی اس اکاؤنٹ پر کوئی installation نہیں جس کی ملکیت میں repository ہے۔ ایک workspace admin اسے **ترتیبات → ورک اسپیس → عام → GitHub ایپ کی انسٹالیشنز** سے انسٹال کرتا ہے۔ Control Center کی مشترکہ App پر کسی organization کے لیے، اس organization کے کسی admin کو **اس سرور کو مجاز کریں** پر کلک کرنا پڑ سکتا ہے۔ دیکھیں [GitHub App بنائیں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/github-app/#اس-سرور-کو-کسی-organization-کی-installation-کے-لیے-مجاز-کریں)۔

### سب کو دوبارہ GitHub میں sign in کرنا پڑتا ہے

سرور کے مالک نے سرور کی Connect key rotate کی، Connect سرورز بدلے، یا data directory کسی اور مشین پر بحال ہوئی۔ Connect کے ذریعے sign-ins اس سرور سے جڑے ہوتے ہیں جس نے انہیں بنایا۔

### repo شامل کرنا رد ہوتا ہے

رجسٹریشن کے لیے تینوں شرائط درکار ہیں: راستہ git work tree کے اندر ہو، اس کا `origin` remote ہو، اور وہ remote کسی تعاون یافتہ forge (github.com، gitlab.com یا bitbucket.org) کی طرف اشارہ کرے۔ دیکھیں [workspace میں repos شامل کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/ریپوز-شامل-کریں/)۔

### بھاری استعمال کے بعد کچھ دیر کے لیے سب کچھ رک جاتا ہے

یہ rate-limit circuit breaker ہے۔ GitHub اپنی بنیادی حد `x-ratelimit-remaining: 0` اور reset وقت والے `403` کے ذریعے بتاتا ہے؛ کلائنٹ ایسا دیکھ کر مزید درخواستوں کو نیٹ ورک کال کے بغیر مقامی طور پر ناکام کرتا ہے جب تک وقفہ نہ گزر جائے، تاکہ retry کا طوفان حد کو اور گہرا نہ کر سکے۔ عارضی ناکامیوں کی exponential backoff کے ساتھ تین بار تک retry ہوتی ہے، `retry-after` کا احترام کرتے ہوئے۔
