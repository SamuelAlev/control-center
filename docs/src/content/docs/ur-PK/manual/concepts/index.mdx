These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/); when you want to look
something up, go to the [reference](/ur-PK/ہدایت-نامہ/حوالہ/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/ur-PK/ہدایت-نامہ/تصورات/ورک-اسپیسز/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/ur-PK/ہدایت-نامہ/تصورات/ایجنٹ-ماڈل/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/ur-PK/ہدایت-نامہ/تصورات/ڈسپیچ-لائف-سائیکل/) — what happens between your message and the agent's first token
- [Modes](/ur-PK/ہدایت-نامہ/تصورات/موڈز/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/ur-PK/ہدایت-نامہ/تصورات/ٹول-کانٹیکسٹ/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/ur-PK/ہدایت-نامہ/تصورات/کوڈ-انٹیلیجنس/) — the code graph, language server, structural search and debugger
- [Conversation history](/ur-PK/ہدایت-نامہ/تصورات/گفتگو-کی-تاریخ/) — persistence, compaction and forking a transcript
