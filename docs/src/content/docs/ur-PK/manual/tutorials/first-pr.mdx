## آپ کیا بنائیں گے

اِس ٹیوٹوریل کے اختتام تک، آپ کے پاس یہ ہوگا:

- Control Center کے PR ورک بینچ میں ایک pull request کھولی ہوگی
- اُس کا ڈف پڑھا ہوگا اور ایک اِن لائن تبصرہ چھوڑا ہوگا
- ایک ریویو فیصلہ جمع کرایا ہوگا
- PR مرج کیا ہوگا

پیشگی شرائط: [اپنا پہلا ایجنٹ بھیجیں](/ur-PK/ہدایت-نامہ/ٹیوٹوریلز/پہلا-ایجنٹ/) مکمل ہو، اور اِس ورک اسپیس میں رجسٹر شدہ کسی ریپو پر ایک کھلا pull request موجود ہو۔ ریویو کے مراحل کے لیے ایسا PR چنیں جو آپ نے خود نہ کھولا ہو — **ریویو** بٹن آپ کے اپنے PRs پر چھپا رہتا ہے۔ آپ کے لکھے ہوئے PR پر مرج پھر بھی کام کرتا ہے۔

## مرحلہ 1: pull request کھولیں

1. سائیڈبار میں **Pull requests** پر کلک کریں
2. اپنا PR ڈھونڈ کر اُس پر کلک کریں

**چیک پوائنٹ۔** PR ایک ٹیبز والے ورک بینچ کی صورت میں کھلتا ہے — جائزہ، Diff، سورس کنٹرول، چیٹ، ایکشنز — جو **جائزہ** پر مرکوز ہوتا ہے: عنوان اور ایکشنز، تفصیل اور ایکٹیویٹی ٹائم لائن، اور ایک سائیڈبار جس میں اسٹیٹس، ریویوورز، تفویض شدہ افراد، چیکس اور تبدیل شدہ فائلیں ہوتی ہیں۔ وہاں کسی فائل پر کلک کرنا Diff ٹیب میں اُسی فائل پر پہنچا دیتا ہے۔ **PR ریویو** ٹیب اُس وقت تک نہیں کھلتا جب تک کوئی AI ریویو کی درخواست نہ کرے۔

:::note[خالی قطار جس میں "GitHub جوڑیں" کا پرامپٹ ہو]
یہ حالت بتاتی ہے کہ _سرور_ کے پاس کوئی GitHub ٹوکن نہیں ہے — آپ کے کلائنٹ کے پاس کبھی نہیں ہوتا۔ **ترتیبات → ورک اسپیس → پروفائل اور شناخت → کوڈ ہوسٹنگ** کے تحت ایک ٹوکن سیٹ کریں، پھر فہرست ریفریش کریں۔
:::

## مرحلہ 2: ڈف پڑھیں

**Diff** ٹیب کھولیں۔ بائیں طرف ایک سمیٹنے والا فائل ٹری ہوتا ہے اور ڈف کے اوپر والی پٹی میں ایک کمیٹ-رینج سلیکٹر ہوتا ہے — جس سے ڈف کو ایک کمیٹ یا اُن کے ایک دورانیے تک محدود کیا جا سکتا ہے — نیز فائلوں کی تعداد اور اضافوں اور حذفوں کی جاری گنتی۔

ڈف ٹول بار میں سیٹنگز کا بٹن کنٹرول کرتا ہے کہ یہ کیسے رینڈر ہو:

- **تقسیم** یا **یکجا** ویو
- **لائنیں لپیٹیں** یا لمبی لائنیں اسکرول کریں
- **کوڈ فونٹ لیگیچرز**

بڑے ڈف میں اپنی پیش رفت دیکھنے کے لیے کسی فائل کو دیکھی گئی کے طور پر نشان زد کریں۔ کی بورڈ نیویگیشن [کی بورڈ شارٹ کٹس](/ur-PK/ہدایت-نامہ/حوالہ/کی-بورڈ-شارٹ-کٹس/) میں ہے۔

## مرحلہ 3: اِن لائن تبصرہ چھوڑیں

1. ڈف کی کسی لائن پر ہوور کریں — گٹر میں ایک چھوٹی `+` گولی ظاہر ہوتی ہے
2. اُس لائن پر تبصرہ کرنے کے لیے اُس پر کلک کریں، یا کسی دورانیے کے انتخاب کے لیے پہلے اُسے عمودی طور پر ڈریگ کریں
3. اپنا فیڈبیک لکھیں۔ کمپوزر دو جمع کرانے پیش کرتا ہے:
   - **ریویو شروع کریں** (یا **ریویو میں شامل کریں** اگر کوئی ریویو پہلے سے جاری ہو) تبصرے کو قطار میں لگاتا ہے۔ تھریڈ **زیرِ التوا ریویو** دکھاتا ہے جب تک آپ مرحلے 4 میں کوئی فیصلہ جمع نہ کرائیں۔
   - **اکیلا تبصرہ شامل کریں** اُسے فوراً GitHub پر پوسٹ کر دیتا ہے۔ تھریڈ **پوسٹ ہو رہا ہے…** دکھاتا ہے، پھر **سنک شدہ**، اور پوسٹ ناکام ہونے پر دوبارہ کوشش کی پیشکش کرتا ہے۔

اِس ٹیوٹوریل کے لیے **ریویو شروع کریں** استعمال کریں تاکہ تبصرہ فیصلے کے ساتھ چلا جائے۔

:::caution[قطار میں لگا تبصرہ ابھی GitHub پر نہیں ہے]
**ریویو شروع کریں** / **ریویو میں شامل کریں** تبصرے کو مقامی طور پر روکے رکھتے ہیں جب تک آپ کوئی فیصلہ جمع نہ کرائیں۔ صرف **اکیلا تبصرہ شامل کریں** فوراً پوسٹ کرتا ہے۔ مرحلے 4 میں لکھی گئی ریویو _باڈی_ ایک الگ مسودہ ہے۔
:::

## مرحلہ 4: ریویو جمع کرائیں

1. جائزہ کی ایکشن قطار میں **ریویو** پر کلک کریں — یہی بٹن Diff ٹیب کے ٹول بار میں بھی ہوتا ہے۔ یہ اُن PRs پر چھپا رہتا ہے جو آپ نے خود لکھے ہوں اور کسی بند یا مرج شدہ PR پر بھی۔
2. کمپوزر میں خلاصہ لکھیں۔ وہ خود بخود ایک مسودے کے طور پر محفوظ ہو جاتا ہے، چنانچہ آپ اوورلے بند کر کے واپس آ سکتے ہیں۔
3. کوئی فیصلہ چنیں:
   - **تبدیلیاں مانگیں**
   - **تبصرہ**
   - **منظور کریں**

فیصلہ _خود_ بٹن ہے۔ **منظور کریں** یا **تبدیلیاں مانگیں** کے بعد بٹن اپنا لیبل بدل کر **منظور** یا **مانگی گئی تبدیلیاں** کر لیتا ہے۔ **تبصرہ** کا فیصلہ بٹن پر **ریویو** کا لیبل برقرار رکھتا ہے۔

**چیک پوائنٹ۔** اگر آپ نے اُن دو میں سے کوئی ایک چنا تو بٹن "منظور" یا "مانگی گئی تبدیلیاں" پڑھتا ہے۔

## مرحلہ 5: مرج

**مرج** بٹن اُس وقت موجود ہوتا ہے جب GitHub PR کو قابلِ مرج بتائے — یہ آپ کی اپنی منظوری پر مشروط نہیں۔ اُس کا رنگ اجازت کے بجائے تیاری بتاتا ہے: بنیادی جب مطلوبہ منظوریاں اور چیکس سبز ہوں، ثانوی جب کوئی چیک ابھی چل رہا ہو، اور تباہ کن جب کسی درخواست کردہ ریویوور نے منظوری نہ دی ہو یا کوئی چیک ناکام ہو رہا ہو۔

1. **مرج** پر کلک کریں
2. کوئی طریقہ چنیں: **Squash and merge**، **مرج کمیٹ بنائیں**، یا **Rebase and merge**
3. پہلے دو کے لیے، پہلے سے بھرے کمیٹ عنوان اور پیغام میں ترمیم کریں
4. تصدیق کریں

کوئی بھی باقی مسئلہ — "چیکس ناکام"، "کچھ ریویوز زیرِ التوا ہیں" — آپ کے تصدیق کرنے سے پہلے فلائی آؤٹ میں درج ہوتا ہے۔

:::caution[مرج کرنا ناقابلِ واپسی ہے]
مرج کرنا GitHub پر کمیٹس پش کرتا ہے۔ یہ کبھی Control Center کے undo اسٹیک میں داخل نہیں ہوتا اور یہاں سے واپس نہیں کیا جا سکتا۔
:::

مرج کرنے کے بعد ایک `PrMerged` ڈومین ایونٹ چلتا ہے؛ اینالیٹکس اور اطلاعات اُسے استعمال کرتی ہیں۔ یہ اور کون سنتا ہے، [ڈومین ایونٹس](/ur-PK/ہدایت-نامہ/حوالہ/ڈومین-ایونٹس/) میں دیکھیں۔

## AI کے ساتھ ریویو

Control Center کسی کھلے PR پر ایک ریویوور پائپ لائن لگا سکتا ہے، مگر صرف اُس وقت جب آپ کہیں: `pr_review` ٹیمپلیٹ میں صرف ایک دستی ٹریگر ہے اور کچھ نہیں۔

1. جائزہ کی ایکشن قطار میں اوور فلو مینو کھولیں اور **AI سے پوچھیں** چنیں۔ Control Center رن شروع کرتا ہے اور **PR ریویو** ٹیب کھول دیتا ہے، تاکہ آپ اسپیشلسٹس کو کام کرتے دیکھ سکیں۔
2. ریویوور ایجنٹس اپنے نتائج PR کی اسپیس میں ریویو نوڈز کے طور پر درج کرتے ہیں؛ ایک آخری قدم اُنہیں یکجا کر کے ایک رپورٹ بناتا ہے۔

یہ پائپ لائن جان بوجھ کر GitHub پر پوسٹ نہیں کرتی — یکجا کرنے کے بعد ختم ہو جاتی ہے۔ اشاعت ایک الگ قدم ہے جو آپ خود اٹھاتے ہیں، **PR ریویو** ٹیب پر **GitHub پر شائع کریں** بٹن کے ساتھ۔ [AI سے چلنے والا ریویو استعمال کریں](/ur-PK/ہدایت-نامہ/طریقہ-کار-گائیڈز/ai-ریویو/) دیکھیں۔

## خلاصہ

آپ نے ورک بینچ میں ایک PR کھولا، سنٹیکس ہائی لائٹنگ کے ساتھ ڈف پڑھا، ایک اِن لائن تبصرہ چھوڑا، ایک فیصلہ جمع کرایا اور مرج کیا — ایپ سے باہر نکلے بغیر۔
