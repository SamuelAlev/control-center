## آپ کیا بنائیں گے

اس ٹیوٹوریل کے اختتام پر آپ کے پاس یہ ہوگا:

- ایک ایجنٹ جو آپ نے خود بنایا اور کنفیگر کیا
- ایک اسپیس جہاں آپ اور وہ ایجنٹ بات کرتے ہیں
- ایک مکمل شدہ رن، جس میں الگ تھلگ ورک ٹری میں کمیٹ شدہ کام اور ایجنٹ کے رن لاگ میں ایک قطار ہو

پیشگی ضروریات: [آپ کا پہلا ورک اسپیس](/ur-PK/ہدایت-نامہ/ٹیوٹوریلز/پہلا-ورک-اسپیس/) مکمل ہو، تاکہ اِس ورک اسپیس میں ایک ریپو رجسٹر شدہ ہو اور کم از کم ایک ماڈل فراہم کنندہ منسلک ہو۔

## مرحلہ 1: ایک ایجنٹ بنائیں

1. **ترتیبات → ورک اسپیس → ایجنٹس** پر جائیں
2. **نیا ایجنٹ** پر کلک کریں۔ “بے نام ایجنٹ” نام کا ایجنٹ فوراً بنا دیا جاتا ہے اور روسٹر میں منتخب ہو جاتا ہے — کوئی بنانے والا ڈائیلاگ نہیں اور تصدیق کرنے کو کچھ نہیں۔ آپ اِسی جگہ اسے کنفیگر کرتے ہیں۔
3. **ترتیبات** ٹیب پر، یہ بھریں:
   - **نام**: کچھ مختصر اور یاد رہنے والا، مثلاً `alice`۔ یہی وہ چیز ہے جو آپ `@` کے بعد ٹائپ کرتے ہیں۔
   - **عنوان**: یہ کیا کرتا ہے، مثلاً “بیک اینڈ انجینئر”
   - **اڈاپٹر**: `Control Center (built-in)`۔ اسے سوچ سمجھ کر چنیں — صرف بلٹ اِن ہارنس ہی رن کے دوران اسٹیئر کیا جا سکتا ہے اور باری کی حد پر روکا جا سکتا ہے، اور اس کے لیے سرور ہوسٹ پر کوئی CLI انسٹال کرنے کی ضرورت نہیں۔
   - **ماڈل**: منسلک فراہم کنندہ جو فہرست پیش کرتا ہے، اُس سے چنیں
   - **مہارتیں**: جو موزوں لگیں وہ لگائیں، مثلاً `testing` یا `architecture`
4. **تبدیلیاں محفوظ کریں** دبائیں

:::note[بغیر اڈاپٹر والا ایجنٹ بلٹ اِن لوپ پر چلتا ہے]
جب اڈاپٹر فیلڈ غیر مقرر ہو، تو ڈسپیچ **Control Center (built-in)** پر واپس گر جاتا ہے — یعنی سرور کے اندر موجود ایجنٹ لوپ، اس لیے ہوسٹ پر کچھ انسٹال کرنے کی ضرورت نہیں۔ اسے پھر بھی ایک ماڈل درکار ہوتا ہے: کوئی مقرر نہ ہو تو یہ اپنے ڈیفالٹ کے لیے Anthropic سے پوچھتا ہے، جو اُس صورت کام کرتا ہے جب آپ نے Anthropic اکاؤنٹ منسلک کیا ہو، ورنہ `No credential for provider "anthropic"` کے ساتھ ناکام ہو جاتا ہے۔ بہرحال دونوں واضح طور پر مقرر کریں، ورنہ آپ ایسے ماڈل پر چل رہے ہوں گے جو آپ نے نہیں چنا۔
:::

**چیک پوائنٹ۔** روسٹر کی قطار آپ کے ایجنٹ کا نام اور اسٹیٹس کا ایک کھوکھلا حلقہ دکھاتی ہے۔

## مرحلہ 2: ایک اسپیس شروع کریں

1. سائیڈبار میں **اسپیسز** سیکشن تلاش کریں اور **+** بٹن پر کلک کریں
2. اسپیس کو کوئی نام دیں
3. **ایجنٹس شامل کریں** کے تحت وہی ایجنٹ منتخب کریں جو ابھی آپ نے بنایا
4. اگر ورک اسپیس میں کوئی ریپو ہو، تو چنیں کہ یہ اسپیس کن پر کام کرے
5. **بنائیں** پر کلک کریں

اسپیس کھل جاتی ہے۔ پس منظر میں Control Center اِس گفتگو کے لیے منتخب ریپوز کا copy-on-write ورک ٹری، اپنی الگ برانچ پر، تیار کرتا ہے۔ آپ کے سورس چیک آؤٹ میں کبھی تبدیلی نہیں کی جاتی۔

## مرحلہ 3: کوئی کام بھیجیں

آپ نے جو ریپو رجسٹر کیا، اُس کے حوالے سے کوئی ایک ٹھوس، چھوٹا کام ٹائپ کریں۔ ایسا کام بہترین رہتا ہے جس کا نتیجہ جانچا جا سکے — ایک ٹیسٹ شامل کریں، کوئی لنٹ ٹھیک کریں، کسی سمبل کا نام بدلیں۔

Enter دبائیں۔ آپ کو کسی کا `@`-ذکر کرنے کی ضرورت نہیں: اسپیس میں ایک ہی ایجنٹ ہو تو سادہ پیغام ہی اسے جگا دیتا ہے۔ کئی ایجنٹس والی اسپیس میں `@name` کسی ایک کو چنتا ہے۔

Control Center پرامپٹ کو ایجنٹ کی ہدایات، شخصیت، مہارتوں اور اسپیس کے کانٹیکسٹ سے جوڑتا ہے، پھر رن ڈسپیچ کرتا ہے۔

**چیک پوائنٹ۔** کمپوزر کا بھیجنے والا بٹن ایک روکیں بٹن میں بدل جاتا ہے — اِس گفتگو میں ایک ایجنٹ کام کر رہا ہے — اور متن آنا شروع ہو جاتا ہے۔

## مرحلہ 4: اسے کام کرتے دیکھیں

گفتگو رن کو ہوتے ہوئے دکھاتی ہے:

- **ریزننگ**، جو ایجنٹ کے سوچتے ہی ساتھ ساتھ دکھائی جاتی ہے
- **ٹول کالز**: فائل ریڈز اور رائٹس، تلاشیں، شیل کمانڈز، ہر ایک اپنے نتیجے کے ساتھ
- **متن**: خلاصے، وضاحتیں اور آپ کے لیے سوالات

اگر ایجنٹ کچھ پوچھے تو گفتگو میں جواب دیں اور وہ دوبارہ شروع ہو جاتا ہے۔

کسی رن کی اپنی میٹرکس اور اس کے وقفے، دوبارہ آغاز اور روکنے کے کنٹرولز کے لیے، اسپیس کے عام پینل کے **ایجنٹس** سیکشن میں چلتا ہوا ایجنٹ تلاش کریں اور **سرگرمی کھولیں** چنیں۔

سرگرمی پین میں اسٹیٹس بیج **چل رہا ہے** پڑھتا ہے، اور رن ختم ہونے پر **کامیاب**۔ جو رن اٹک جائے یا لوپ میں پھنس جائے وہ **بلاک** پڑھتا ہے؛ جو خرابی دے وہ **ناکام**۔ ایجنٹ رجسٹری میں روسٹر کا حلقہ پہلے رن سے پہلے کھوکھلا ہوتا ہے اور ایجنٹ کے دوبارہ بیکار ہوتے ہی ٹھوس ہو جاتا ہے۔

رن کو کیا محدود کرتا ہے: اس کا اپنا copy-on-write ورک ٹری، وہ کریڈینشلز جو لانچ پر اس کے لیے بروکر کیے جاتے ہیں اور ٹیئر ڈاؤن پر منسوخ کر دیے جاتے ہیں، ایک صاف شدہ ماحول، وہ ٹول سطح جس کی اس کا موڈ اجازت دیتا ہے، اور ایکشن گارڈریلز۔ کسی برانچ کو پش کرنے یا pull request کھولنے جیسے اثرات الگ سے گیٹ کیے جاتے ہیں — دیکھیں [گارڈریلز](/ur-PK/ہدایت-نامہ/تصورات/گارڈریلز/)۔

## مرحلہ 5: نتیجہ جانچیں

1. **ترتیبات → ورک اسپیس → ایجنٹس** کھولیں اور اپنا ایجنٹ منتخب کریں
2. **لاگز** ٹیب کھولیں

**چیک پوائنٹ۔** ایک رن کی قطار، جو اس کا اسٹیٹس، مدت، شروع اور اختتام کے اوقات اور وہ اڈاپٹر دکھاتی ہے جس پر وہ چلا۔

ایجنٹ کی تبدیلیاں گفتگو کی برانچ پر، اس کے ورک ٹری میں، کمیٹ کر دی جاتی ہیں۔ کمیٹس ایجنٹ کے طور پر تصنیف ہوتی ہیں، جبکہ آپ کا ذکر ایک `Co-Authored-By:` ٹریلر میں کریڈٹ کے ساتھ ہوتا ہے۔

## pull request حاصل کرنا

کوئی چیز خود بخود pull request نہیں کھولتی۔ اگر آپ کو ایک چاہیے تو اُسی گفتگو میں اس کی درخواست کریں:

> یہ برانچ پش کریں اور ڈیفالٹ برانچ کے خلاف ایک pull request کھولیں۔

پش کرنا (`gitPush`) اور PR بنانا (`prCreate`) دونوں ڈیفالٹ میں آپ کی منظوری مانگتے ہیں، اس لیے ہر ایک سے پہلے ایک تصدیق کی توقع رکھیں۔ جب پرامپٹ آئے اور کوئی منظور کنندہ منسلک نہ ہو، تو ایکشن کی اجازت دینے کے بجائے انکار کر دیا جاتا ہے — گارڈریلز بند ہو کر ناکام ہوتے ہیں۔

PR اُس GitHub شناخت کے تحت کھولا جاتا ہے جس کا ٹوکن رن نے استعمال کیا — یعنی آپ کی، اگر آپ نے ذاتی ٹوکن محفوظ کیا ہو — نہ کہ ایجنٹ کے نام سے۔ ایجنٹ کی مصنفیت کمیٹس پر ظاہر ہوتی ہے۔

آپ اسے خود بھی کھول سکتے ہیں: اسپیس کے **سورس کنٹرول** پینل میں **pull request بنائیں** کا بٹن ہے جو گفتگو کی برانچ کو کمپوز اسکرین میں لے جاتا ہے، اور **Pull requests → نیا PR** وہی اسکرین خالی حالت میں کھولتا ہے۔ اگلا ٹیوٹوریل یہیں سے آگے بڑھتا ہے۔

## خلاصہ

آپ نے ایک ایجنٹ بنایا، اس کا اڈاپٹر اور ماڈل کنفیگر کیا، اسے ایک اسپیس اور ایک کام دیا، اور ایک حقیقی رن کو الگ تھلگ ورک ٹری میں، آپ کے چیک آؤٹ کو چھوئے بغیر، مکمل ہوتے دیکھا۔
