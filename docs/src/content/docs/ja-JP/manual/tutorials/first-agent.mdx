## 作るもの

このチュートリアルを終えると、次のものが揃っています:

- 自分で作成して設定したエージェント
- あなたとそのエージェントが会話するスペース
- 完了した 1 回の実行 — 分離されたワークツリーにコミットされた作業と、エージェントの実行ログの 1 行

前提条件: [初めてのワークスペース](/ja-JP/マニュアル/チュートリアル/初めてのワークスペース/)を完了していること。これにより、このワークスペースにはリポジトリが登録され、少なくとも 1 つのモデルプロバイダーが接続された状態になります。

## ステップ 1: エージェントを作成する

1. **設定 → ワークスペース → エージェント**を開きます
2. **新しいエージェント**をクリックします。「名前なしエージェント」というエージェントがすぐに作成され、名簿内で選択されます — 作成ダイアログはなく、確認するものもありません。設定はその場で行います。
3. **設定**タブで次を入力します:
   - **名前**: `alice` のような、短くて覚えやすいもの。`@` の後に入力する名前です。
   - **タイトル**: そのエージェントの役割。例: 「バックエンドエンジニア」
   - **アダプター**: `Control Center (built-in)`。これは意図的に選んでください — 実行中に軌道修正でき、ターン境界で一時停止できるのは内蔵ハーネスだけであり、サーバーホストに CLI をインストールする必要もありません。
   - **モデル**: 接続済みプロバイダーが提供する一覧から選びます
   - **スキル**: 適したものを付けます。例: `testing` や `architecture`
4. **変更を保存**を押します

:::note[アダプターのないエージェントは組み込みループで実行される]
アダプターフィールドが未設定の場合、ディスパッチは **Control Center (built-in)** にフォールバックします — サーバー内部のエージェントループなので、ホストにインストールするものはありません。それでもモデルは必要です。モデルも設定されていなければ Anthropic にそのデフォルトを問い合わせます。これは Anthropic アカウントを接続していれば機能し、そうでなければ `No credential for provider "anthropic"` で失敗します。いずれにせよ両方を明示的に設定してください。さもないと、自分で選んでいないモデルで実行することになります。
:::

**チェックポイント。** 名簿の行に、エージェントの名前と中空のステータスリングが表示されます。

## ステップ 2: スペースを開始する

1. サイドバーで**スペース**セクションを見つけ、**+** ボタンをクリックします
2. スペースに名前を付けます
3. **エージェントを追加**で、作成したばかりのエージェントを選択します
4. ワークスペースにリポジトリがある場合は、このスペースで作業するものを選びます
5. **作成**をクリックします

スペースが開きます。バックグラウンドで Control Center が、この会話のために選択したリポジトリのコピーオンライトのワークツリーを、それぞれ独自のブランチでプロビジョニングします。ソースのチェックアウトが変更されることはありません。

## ステップ 3: タスクを送信する

登録したリポジトリに対して、具体的で小さなタスクを 1 つ入力します。結果を確認できるものが最適です — テストを追加する、lint を修正する、シンボルの名前を変更するなどです。

Enter を押します。誰かを `@` でメンションする必要はありません。スペースにエージェントが 1 体だけなら、通常のメッセージでそのエージェントが動き出します。エージェントが複数いるスペースでは、`@name` で 1 体を選びます。

Control Center は、エージェントの指示、ペルソナ、スキル、スペースのコンテキストからプロンプトを組み立ててから、実行をディスパッチします。

**チェックポイント。** コンポーザーの送信ボタンが停止ボタンに変わります — この会話でエージェントが作業している証拠です — そしてテキストが届き始めます。

## ステップ 4: 実行の様子を見る

会話は、実行の進行に合わせてそれを描画します:

- **推論** — エージェントの思考に合わせてインラインで表示されます
- **ツール呼び出し**: ファイルの読み取りと書き込み、検索、シェルコマンド。それぞれに結果が付きます
- **テキスト**: 要約、説明、あなたへの質問

エージェントが何かを尋ねてきたら、会話の中で答えれば再開します。

実行自体のメトリクスと、その一時停止・再開・停止のコントロールについては、スペースの一般パネルの**エージェント**セクションで実行中のエージェントを見つけ、**アクティビティを開く**を選びます。

アクティビティペインでは、ステータスバッジは**実行中**と表示され、実行が終わると**成功**になります。停止またはループしている実行は**ブロック中**、エラーになった実行は**失敗**と表示されます。エージェントレジストリでは、名簿のリングは最初の実行前は中空で、エージェントが再びアイドルになると塗りつぶされます。

実行を制約するもの: それ自身のコピーオンライトのワークツリー、起動時にブローカー経由で発行され、終了時に取り消される資格情報、サニタイズされた環境、そのモードが許可するツールサーフェス、そしてアクションガードレールです。ブランチのプッシュやプルリクエストの作成といったエフェクトは別途ゲートされます — [ガードレール](/ja-JP/マニュアル/コンセプト/ガードレール/)を参照してください。

## ステップ 5: 結果を確認する

1. **設定 → ワークスペース → エージェント**を開き、自分のエージェントを選択します
2. **ログ**タブを開きます

**チェックポイント。** 実行の行が 1 つあり、そのステータス、所要時間、開始時刻と終了時刻、実行に使われたアダプターが表示されます。

エージェントの変更は、会話のブランチ上、そのワークツリー内にコミットされます。コミットの作者はエージェントで、あなたは `Co-Authored-By:` トレーラーにクレジットされます。

## プルリクエストを開く

プルリクエストを勝手に開くものはありません。開きたい場合は、同じ会話の中で依頼します:

> このブランチをプッシュし、デフォルトブランチに対するプルリクエストを開いてください。

プッシュ（`gitPush`）と PR の作成（`prCreate`）はいずれも既定で承認を求めるため、それぞれの前に確認が入ります。プロンプトが発火した時点で承認者が接続されていなければ、アクションは許可されるのではなく拒否されます — ガードレールはフェイルクローズします。

PR は、その実行が使用したトークンの GitHub アイデンティティ（個人トークンを保存していればあなた）の下で開かれ、エージェントの名前で開かれることはありません。エージェントが作者であることはコミットに現れます。

自分で開くこともできます。スペースの**ソース管理**パネルには**プルリクエストを作成**ボタンがあり、会話のブランチを作成画面に引き継ぎます。また、**プルリクエスト → 新しい PR** は同じ画面を空の状態で開きます。次のチュートリアルはここから続きます。

## まとめ

エージェントを作成し、そのアダプターとモデルを設定し、スペースとタスクを与え、チェックアウトに触れることなく、実際の実行が分離されたワークツリー内で完了するのを見ました。

**次:** [初めてのプルリクエストをレビュー](/ja-JP/マニュアル/チュートリアル/初めてのプルリクエスト/)で、レビューワークフローを学びます。

エージェントについて詳しくは: [エージェントモデル](/ja-JP/マニュアル/コンセプト/エージェントモデル/)。ディスパッチの詳細については: [エージェントのディスパッチライフサイクル](/ja-JP/マニュアル/コンセプト/ディスパッチライフサイクル/)。
