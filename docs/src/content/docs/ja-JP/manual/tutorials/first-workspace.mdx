## このチュートリアルで作るもの

このチュートリアルを終えると、次のものが揃っています:

- プロジェクトの名前を付けたワークスペース
- そこに登録された Git リポジトリ
- シードされた 5 体のエージェント — うち 1 体は実行できる程度に設定済み
- 分離の境界を証明する、2 つ目の空のワークスペース

オンボーディングですでにワークスペースが作成されています。このチュートリアルでは、プロセスのすべての部分を見られるように、あえて新しく作成します。

始める前に、次の 3 つすべてを満たす Git チェックアウトを用意してください — 登録ステップはそれ以外を受け付けません:

- git ワークツリーの内部にあること
- `origin` リモートがあること
- そのリモートが github.com、gitlab.com、bitbucket.org のいずれかを指していること

## ステップ 1: ワークスペースを作成する

1. タイトルバーのワークスペースチップをクリックします
2. **ワークスペースを追加…** を選択します
3. プロジェクトを識別できる名前を入力します。たとえば "api-service" や "frontend-v2" です
4. 任意でロゴを選びます
5. **ワークスペースを追加** をクリックします

Control Center は新しいワークスペースに切り替わり、その受信トレイ（`/workspaces/<id>/inbox`）を開きます。

その裏で、サーバーは `WorkspaceCreated` イベントを発行し、ワークスペースに次をシードします:

- **CEO エージェント** — そのペルソナは調整と委任です
- 4 体のスペシャリスト — `qa`、`architect`、`engineer`、`librarian` — それぞれに独自の指示とスキルがあります
- 組み込みのパイプラインテンプレートとそのトリガー行

作成するすべてのワークスペースがこれらすべてを手に入れます。最初の 1 つだけではありません。

確認: **設定 → ワークスペース → エージェント** を開きます。名簿には 5 体のエージェントがあり、それぞれに中空のステータスリングが付いています。

## ステップ 2: リポジトリを登録する

1. **設定 → ワークスペース → リポジトリ** に移動します
2. **リポジトリを追加** をクリックします
3. 自分のチェックアウトまで参照します。このダイアログがたどるのは `cc_server` を実行しているマシン上のフォルダーであり、あなたのクライアントではありません。また、そのサーバーが公開しているルート（既定ではそのユーザーのホームディレクトリ）の内部にとどまります。git のチェックアウトには専用のフォルダーアイコンとチェックボックスが付き、通常のフォルダーにはどちらも付きません。そのため選択できるのはチェックアウトだけです。
4. 1 つ以上のチェックアウトにチェックを入れ、まとめて登録します。選択内容は移動しても保持されるため、1 回の操作で複数まとめることができ、1 つ選び損ねても残りが失われることはありません。

Control Center は各チェックアウトの `origin` リモートを読み取り、オーナーとリポジトリを解決して、リポジトリの行を**このワークスペースの内部に**作成します。リンクするための 2 つ目のステップはありません。スコープを決めるのは登録そのものです。

あとで同じチェックアウトを別のワークスペースに登録すると、独自の id を持つ 2 つ目の独立したリポジトリ行が作成されます。ワークスペースをまたぐ場合、チェックアウトはファイルシステムのパスで識別され、id で識別されることはありません。

確認: リポジトリが一覧に表示され、その `owner/repo` と現在のブランチが示されます。

## ステップ 3: 1 体のエージェントを実行可能にする

このワークスペースが今シードした 5 体のエージェントには、アダプターもモデルもありません。ディスパッチはそれらを **Control Center (built-in)** 上で実行し、モデルが設定されていなければ Anthropic に既定のモデルを問い合わせます — つまり、Anthropic アカウントを接続している場合にだけ動作し、接続している場合はあなたが選んでいないモデルで実行されます。初回起動時のオンボーディングは、最初のワークスペースのすべてのエージェントにその選択を 1 回だけ刻印します。あとから作成したワークスペースは、5 体すべてが未設定の状態で始まります。ここで 1 体を設定しましょう。

1. **設定 → ワークスペース → エージェント** を開きます
2. 名簿で `engineer` を選択します
3. **設定** タブで、**アダプター**を `Control Center (built-in)` に設定し、**設定 → サーバー → モデルプロバイダー**で接続したプロバイダーから**モデル**を選びます
4. **変更を保存** を押します

確認: エージェントを再度開くと、2 つのフィールドに選んだ内容が保持されています。

各エージェントは独自のアダプターとモデルを持ちます。使う予定の他のエージェントについても同じ手順を繰り返してください。[エージェントの作成と設定](/ja-JP/マニュアル/ハウツーガイド/エージェント作成/)で、フォームの残りの部分を説明します。

## ステップ 4: 分離の境界を確認する

タイトルバーのチップから、ステップ 1 とまったく同じように 2 つ目のワークスペースを作成します。そして次を見てください:

- **設定 → ワークスペース → リポジトリ** は空です。さきほど登録したリポジトリはそこにありません。
- **設定 → ワークスペース → エージェント** には 5 体のエージェントがありますが、別の行です — ステップ 3 で設定したアダプターは消えています。
- スペース一覧、チケット、メモリはすべて空です。

何も漏れていません。漏れる元がないからです。各ワークスペースの行は、そのワークスペース自身のデータベースファイルに存在します。ワークスペースをまたぐ読み取りは、フィルターされるクエリではなく、実行する場所がないクエリです。ワークスペースの削除は、ファイルのリンクを外すことにほかなりません。

タイトルバーのチップで切り替えて戻るか、**ワークスペースを管理** を開くと、それらを並べて見られます。

モデル全体については、[ワークスペースと分離](/ja-JP/マニュアル/コンセプト/ワークスペース/)を参照してください。

## まとめ

ワークスペースを作成し、CEO と 4 体のスペシャリストがシードされるのを見て、リポジトリを登録し、1 体のエージェントにアダプターとモデルを与え、2 つ目のワークスペースがそのどれも共有していないことを確認しました。
