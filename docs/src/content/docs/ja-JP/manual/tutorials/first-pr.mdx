## このチュートリアルで作るもの

このチュートリアルを終えると、次のことができるようになります:

- Control Center の PR ワークベンチでプルリクエストを開く
- その差分を読んでインラインコメントを残す
- レビューの判定を送信する
- PR をマージする

前提条件: [初めてのエージェントをディスパッチ](/ja-JP/マニュアル/チュートリアル/初めてのエージェント/)を完了していること、およびこのワークスペースに登録済みのリポジトリにオープンなプルリクエストが 1 件あることです。レビューの手順では、自分が開いていない PR を選びます — 自分の PR では **レビュー** ボタンが非表示になるためです。自分が作成した PR でもマージは機能します。

## ステップ 1: プルリクエストを開く

1. サイドバーの **プルリクエスト** をクリックします
2. 自分の PR を見つけてクリックします

**チェックポイント。** PR はタブ式のワークベンチとして開きます — 概要、差分、ソース管理、チャット、操作 — 最初は **概要** にフォーカスしており、タイトルとアクション、説明とアクティビティのタイムライン、そしてステータス、レビュアー、担当者、チェック、変更されたファイルを表示するサイドバーが並びます。ここでファイルをクリックすると、差分タブのそのファイルにジャンプします。**PRレビュー** タブは、誰かが AI レビューを依頼するまで開きません。

:::note[キューが空で「GitHub を接続」というプロンプトが表示される場合]
この状態は、_サーバー_ が GitHub トークンを保持していないことを意味します — クライアントがトークンを保持することはありません。**設定 → ワークスペース → プロフィールと識別情報 → コードホスティング** で設定し、一覧を更新してください。
:::

## ステップ 2: 差分を読む

**差分** タブを開きます。左側に折りたたみ可能なファイルツリーがあり、差分の上のストリップにはコミット範囲セレクター — 差分を 1 つのコミットまたは複数コミットの範囲に絞り込めます — と、ファイル数、および追加と削除の累計が表示されます。

差分ツールバーの設定ボタンで、表示方法を制御できます:

- **分割** ビューまたは **統合** ビュー
- **行の折り返し** または長い行のスクロール
- **コードフォントの合字**

大きな差分での進捗を追うには、ファイルを閲覧済みにします。キーボードナビゲーションについては [キーボードショートカット](/ja-JP/マニュアル/リファレンス/キーボードショートカット/)を参照してください。

## ステップ 3: インラインコメントを残す

1. 差分内の行にカーソルを合わせます — ガターに小さな `+` ピルが表示されます
2. クリックするとその行にコメントできます。範囲を選択する場合は、先に垂直方向にドラッグします
3. フィードバックを入力します。コンポーザーには 2 つの送信方法があります:
   - **レビューを開始**（レビューがすでに進行中の場合は **レビューに追加**）はコメントをキューに入れます。ステップ 4 で判定を送信するまで、スレッドには **保留中のレビュー** と表示されます。
   - **単一のコメントを追加** は即座に GitHub へ投稿します。スレッドには **投稿中…** と表示され、その後 **同期済み** になり、投稿に失敗した場合は再試行を提供します。

このチュートリアルでは、コメントが判定とともに送信されるよう、**レビューを開始** を使います。

:::caution[キューに入れたコメントはまだ GitHub 上にありません]
**レビューを開始** / **レビューに追加** は、判定を送信するまでコメントをローカルに保持します。**単一のコメントを追加** だけが即座に投稿します。ステップ 4 で書くレビューの _本文_ は別の下書きです。
:::

## ステップ 4: レビューを送信する

1. **概要** のアクション行で **レビュー** をクリックします — 同じボタンは差分タブのツールバーにもあります。自分が作成した PR と、クローズ済みまたはマージ済みの PR では非表示になります。
2. コンポーザーに概要を書きます。下書きとして自動保存されるため、オーバーレイを閉じてから戻ってくることができます。
3. 判定を選択します:
   - **変更をリクエスト**
   - **コメント**
   - **承認**

判定とはボタンそのものです。**承認** または **変更をリクエスト** の後、ボタンは **承認済み** または **変更リクエスト** に表示が変わります。**コメント** の判定では、ボタンは **レビュー** の表示のままです。

**チェックポイント。** この 2 つのいずれかを選んだ場合、ボタンは「承認済み」または「変更リクエスト」と表示されます。

## ステップ 5: マージする

**マージ** ボタンは、GitHub が PR をマージ可能と報告している限り表示されます — 自分自身の承認を条件とはしません。その色は権限ではなく準備状況を示します: 必須の承認とチェックがグリーンのときはプライマリ、チェックがまだ実行中のときはセカンダリ、レビューを依頼した担当者が承認していないかチェックが失敗しているときは破壊的です。

1. **マージ** をクリックします
2. 方法を選択します: **スカッシュしてマージ**、**マージコミットを作成**、または **リベースしてマージ**
3. 最初の 2 つでは、あらかじめ入力されたコミットのタイトルとメッセージを編集します
4. 確定します

未解決の問題 —「チェックが失敗しています」「一部のレビューが保留中です」— は、確定する前にフライアウトに一覧表示されます。

:::caution[マージは取り消せません]
マージはコミットを GitHub にプッシュします。Control Center の取り消しスタックには入らず、ここから元に戻すことはできません。
:::

マージ後、`PrMerged` ドメインイベントが発火し、分析と通知がこれを消費します。ほかに何が購読しているかは [ドメインイベント](/ja-JP/マニュアル/リファレンス/ドメインイベント/)を参照してください。

## AI を使ったレビュー

Control Center はオープンな PR にレビュアーパイプラインを配置できますが、それは依頼したときだけです: `pr_review` テンプレートには手動トリガーしかなく、ほかのトリガーはありません。

1. **概要** のアクション行でオーバーフローメニューを開き、**AIに質問** を選択します。Control Center は実行を開始し、**PRレビュー** タブを開くので、スペシャリストが作業する様子を確認できます。
2. レビュアーエージェントは検出結果を PR のスペース内のレビューノードとして記録し、最終ステップでそれらを 1 つのレポートに統合します。

このパイプラインは意図的に GitHub へ投稿しません — 統合したあとに終了します。公開は自分で行う別のステップであり、**PRレビュー** タブの **GitHubに公開** ボタンを使います。[AI レビューを使う](/ja-JP/マニュアル/ハウツーガイド/ai-レビュー/)を参照してください。

## まとめ

ワークベンチで PR を開き、シンタックスハイライト付きの差分を読み、インラインコメントを残し、判定を送信してマージしました — アプリから離れることなく。
