## 作成するもの

このチュートリアルを終えると、次のものが揃っています:

- プロンプトでエージェントをディスパッチする、保存済みのパイプラインテンプレート
- 手動で開始できるようにする、手動実行を有効にした状態
- 完了した 1 回の実行 — そのステップの入力と出力を確認できる状態

前提条件: [初めてのエージェントをディスパッチする](/ja-JP/マニュアル/チュートリアル/初めてのエージェント/)を完了していること。これにより、アダプターとモデルを設定したエージェントができている状態になります。

パイプラインはステップからなる DAG です。テンプレートがグラフを定義し、run はその実行にあたります。背景にあるモデルについては[パイプラインと自動化](/ja-JP/マニュアル/コンセプト/パイプライン/)を、ステップの語彙全体については[パイプラインステップ](/ja-JP/マニュアル/リファレンス/パイプラインステップ/)を参照してください。

## ステップ 1: テンプレートを作成する

1. **設定 → ワークスペース → パイプラインテンプレート**に移動します
2. **新しいテンプレート**をクリックします

エディターは、**新しいパイプライン**という名前の用意されたスケルトン（ID は `pipeline_N`）で開きます。ヘッダーのタイトルをクリックして名前を変更します — このチュートリアルでは `code_quality_check` が良い名前です。ID のダイアログはなく、説明フィールドもありません。

キャンバスは空白ではありません。新しいテンプレートは **Trigger → Step → terminal** としてあらかじめ配線されています。ここで「Step」はプロンプトエージェントノードで、terminal は不可視のセンチネルです。エディターはこのセンチネルを、到達可能なすべてのシンクに再接続します。

設定するのは、すでに配置されている Step ノードです。

## ステップ 2: ステップを設定する

1. キャンバス上の **Step** ノードをクリックします
2. 右側の**ノード設定**パネルで次を設定します:
   - **エージェント**: 前のチュートリアルで作成したエージェント
   - **プロンプトテンプレート**: 「現在のブランチのコードを品質上の問題がないかレビューしてください。見つかったものを列挙してください。」
3. **Triggers from** はそのままにします — このノードはすでに Trigger の後に発火するよう配線されています

## ステップ 3: 保存する

エディターのヘッダーで**保存**を押します。

**チェックポイント。** 「未保存の変更」の表示が消えます。

## ステップ 4: 手動実行を許可する

1. キャンバス上の破線の**トリガーを追加**タイルをクリックし（またはノードライブラリのトリガーセクションから**手動実行**をドラッグし）、**手動実行**を選びます。
2. そのノードを選択します。右側のインスペクターで**有効**をオンにします — 「実行ページに表示し、手動で開始します。」

これは省略できず、見落としやすい項目です。新しいテンプレートは**トリガー行がまったくない**状態で作成されるため、これをオンにするまで実行ページに一覧表示されず、開始するものもありません。このスイッチはトリガーを即座に書き込みます。別の保存を待ちません。

同じスイッチは、エディターのヘッダーにある**手動実行**の背後にもあります。そこでは、テンプレートが宣言した入力と並んで表示されます。

## ステップ 5: 実行する

1. サイドバーで**パイプライン**をクリックします
2. ヘッダーの**パイプラインを実行**をクリックします
3. 左のレールで `code_quality_check` を選びます
4. フォームの**パイプラインを実行**をクリックします — このテンプレートは入力を宣言していないため、入力するものはありません

**チェックポイント。** 実行が開始されたことをトーストが知らせ、Control Center が実行の詳細を開きます。

エンジンは実行レコードを作成し、トリガーを完了し、ステップをスケジュールし、エージェントをディスパッチし、終端センチネルへの入力ブランチが完了した時点で実行を完了します。

## ステップ 6: 結果を確認する

実行内のステップをクリックして、その詳細パネルを開きます:

- **開始**と**終了**のタイムスタンプ、そして**所要時間**
- **入力**: ステップに渡されたステート
- **出力**: ステップが生成したもの — ここではエージェントの応答
- **エージェントのアクティビティ**、ステップが実行した会話へのリンク付き

**チェックポイント。** ステップが完了と表示され、その出力にエージェントのレビューが入っています。

## ステップをさらに追加する

ノードを追加するには、左側のノードライブラリから項目をキャンバスにドラッグするか、ノードのすぐ後ろで**ステップを追加**（`+`）を押します。ノードの出力ポートから別のノードへドラッグすると接続できます。または、新しいノードを選択し、**Triggers from** でその上流ステップにチェックを入れます。

終端ノードは描画されず、選択もできません。エディターはそれを到達可能なすべてのシンクに再接続するため、用意された Step の後に追加したノードも実行されます。

## まとめ

テンプレートを作成し、もとからあるプロンプトエージェントノードを設定して保存し、手動で実行できるようにし、実行を開始して、ステップの入力と出力を確認しました。

パイプラインはこれよりはるかに大きくなります — 条件付きルーター、並列ブランチ、ジョインノード、For each のファンアウト、人間による承認ゲート — しかし形は変わりません。DAG 内のステップがステートを受け渡します。
