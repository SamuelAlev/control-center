何もない状態から、自分のコードに対して動くエージェントができるまでの、最短の完全な道筋です。順番どおりに進めてください。各ステップはその前のステップに依存しています。

必要なのは Git、GitHub アカウント、そしてモデルプロバイダーのアカウント（Anthropic、OpenAI、Codex、Cursor、Kimi Code、または API キーを持つ任意のプロバイダー）か、インストール済みの Claude Code CLI のいずれかです。それ以外は途中で設定していきます。

## ステップ 1: インストールして起動する

[インストール](/ja-JP/マニュアル/インストール/)の説明に従って Control Center をインストールし、起動します。

初回起動時に、デスクトップ版は **「Control Centerをどのように実行しますか？」** と尋ねます。**このアプリ内で実行** を選びます。Control Center はこのマシン上でヘッドレスの `cc_server` を起動し、これがデータを所有してすべての作業を行います。`cc_server` を目にすることはありません。代わりにオンボーディング画面が開きます。

:::note[何もインストールしたくない場合]
同じアプリは、同じ機能のままブラウザーで [app.usectrl.dev](https://app.usectrl.dev) でも動作します。
ただし、ブラウザーのタブはサーバーをホストできないため、サーバーは自分で用意します —
`cc_server` をローカルで実行して `ws://localhost:9030` に接続するか、別のマシン上の
サーバーを指定します。このクイックスタートは、サーバーのセットアップが不要なデスクトップ版の
経路をたどります。ブラウザーでの方法は[インストール](/ja-JP/マニュアル/インストール/#use-it-in-your-browser)を参照してください。
:::

## ステップ 2: オンボーディングを進める

オンボーディングには 5 つのステップがあり、順番に実行されます — 途中を飛ばすことはできません。

1. **接続**: GitHub でサインインするか、`repo` と `read:org` を持つパーソナルアクセストークンを貼り付けます。資格情報はサーバー上に、あなたのアカウントに紐づけて保存されます。
2. **ワークスペース**: 最初のワークスペースに名前を付け、任意でロゴを選びます。作成すると 5 体のエージェント（CEO と `qa`、`architect`、`engineer`、`librarian`）と、組み込みのパイプラインテンプレートがシードされます。
3. **サンドボックス**: サンドボックスの設定を記録します。どちらを選んでも続行できます。
4. **アダプター**: エージェントが既定で使うアダプターとモデルを選びます。**Control Center (built-in)** を選択し、続いて表示されるプロバイダーピッカーでモデルプロバイダーにサインインします — 1 つ接続するまでモデル一覧は空のままです。このステップを完了すると、ワークスペースの CEO エージェントにアダプターとモデルが刻印されます。
5. **音声（任意）**: ディクテーション用のオンデバイス音声モデルをインストールするか、スキップします。

その後、Control Center がワークスペースの受信トレイを開きます。

:::note[エージェントの実行を制約するもの]
利用可能であれば、エージェントのコマンドはホストの OS ネイティブのサンドボックスでラップされます — macOS では Seatbelt、Linux では bubblewrap です。Windows にはバックエンドがないため、そこでの実行を制約するのは他の層だけです: 会話自身のワークツリー（Windows では `git worktree`、`rift` が出荷される環境ではコピーオンライト）、起動ごとにブローカー経由で発行され終了時に取り消される資格情報、そしてアクションガードレールです。[サンドボックスとセキュリティ](/ja-JP/マニュアル/コンセプト/サンドボックスとセキュリティ/)を参照してください。
:::

## ステップ 3: リポジトリを追加する

**設定 → ワークスペース → リポジトリ** に移動し、**リポジトリを追加** をクリックします。

ダイアログが参照するのは、サーバーを実行しているマシン上のフォルダーであり、あなたのクライアントではありません。また、そのサーバーが公開するよう設定されているルート（既定ではそのサーバーのユーザーのホームディレクトリ）の内部にとどまります。チェックボックスが付くのは git のチェックアウトだけです。自分のものにチェックを入れて登録します。

チェックアウトが受け入れられるのは、git ワークツリーの内部にあり、`origin` リモートを持ち、そのリモートがサポート対象のコードホスト — github.com、gitlab.com、bitbucket.org — を指している場合だけです。それ以外は理由とともに拒否されます。

リポジトリのスコープはワークスペース単位です: ここでチェックアウトを登録すると、それは_この_ワークスペースに入ります。別途リンクする手順はありません。

## ステップ 4: エージェントにアダプターとモデルを設定する

**設定 → ワークスペース → エージェント** に移動します。名簿で `engineer` エージェントを選択します。

**設定** タブで、次を設定します:

- **アダプター**: `Control Center (built-in)`
- **モデル**: オンボーディングで接続したプロバイダーから 1 つ選びます

**変更を保存** を押します。

このステップは事実上省略できません。オンボーディングで選んだアダプターを継承するのは CEO エージェントだけであり、4 体のスペシャリストはアダプターなしで作成されます。彼らは Anthropic の既定モデルで **Control Center (built-in)** にフォールバックするため、実行されるのは Anthropic アカウントを接続している場合だけです — そして接続している場合は、あなたが選んでいないモデルで実行されます。

## ステップ 5: エージェントにタスクを送る

1. サイドバーで **スペース** セクションを見つけ、**+** ボタンをクリックします。
2. スペースに名前を付け、**エージェントを追加** で `engineer` エージェントを追加し、作成します。
3. 登録したリポジトリに対する、具体的で小さなタスクを入力し、Enter を押します。

Control Center は、この会話のためにワークスペースのリポジトリのコピーオンライトのワークツリーをプロビジョニングし、エージェントのロール、ペルソナ、スキル、そしてスペースのコンテキストからプロンプトを組み立てて、実行をディスパッチします。元のチェックアウトに触れることは一切ありません。

## ステップ 6: 動く様子を確認する

次の順で表示されるはずです:

- この会話でエージェントが作業しているため、コンポーザーの送信ボタンが停止ボタンに変わる
- エージェントの推論、ツール呼び出し、テキストがトランスクリプトにストリーミングされる
- 実行が終わると送信ボタンが戻る

次に **設定 → ワークスペース → エージェント** を開き、エージェントを選択して **ログ** タブを確認します: 実行が 1 行あり、そのステータス、所要時間、開始時刻と終了時刻、実行に使用されたアダプターが示されています。

これがループです。Control Center のその他すべて — プルリクエストのレビュー、パイプライン、チケット、ミーティング、Slack — は、これを起点に広がっています。
