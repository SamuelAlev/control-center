These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/ja-JP/マニュアル/ハウツーガイド/); when you want to look
something up, go to the [reference](/ja-JP/マニュアル/リファレンス/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/ja-JP/マニュアル/コンセプト/ワークスペース/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/ja-JP/マニュアル/コンセプト/エージェントモデル/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/ja-JP/マニュアル/コンセプト/ディスパッチライフサイクル/) — what happens between your message and the agent's first token
- [Modes](/ja-JP/マニュアル/コンセプト/モード/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/ja-JP/マニュアル/コンセプト/ツールコンテキスト/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/ja-JP/マニュアル/コンセプト/コードインテリジェンス/) — the code graph, language server, structural search and debugger
- [Conversation history](/ja-JP/マニュアル/コンセプト/会話履歴/) — persistence, compaction and forking a transcript
