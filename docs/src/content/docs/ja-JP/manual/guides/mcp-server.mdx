このガイドでは、外部の MCP クライアント — Claude Code、エディター、MCP
Inspector — を Control Center 自身のツールサーバーに接続する方法を説明します。

Control Center は **110** 個のツールを登録し、プロトコルバージョン `2024-11-05`
の Model Context Protocol でそれらを提供します。期待されるかもしれないツール
ファミリーが丸ごと存在しません。ミーティングやカレンダーのツールはなく、
プロジェクトのツールもありません。

## エンドポイントを見つける

MCP サーフェスはメインの `cc_server` リスナーを共有します。MCP 専用のポートは
ありません。

| エンドポイント | メソッド | 用途                                                     |
| -------------- | -------- | -------------------------------------------------------- |
| `/mcp`         | `POST`   | Streamable HTTP トランスポート — クライアントが話すのはこれです |
| `/mcp`         | `DELETE` | セッションを終了する                                      |
| `/sse`         | `GET`    | サーバー送信の通知ストリーム                              |

したがって、既定のローカルインストールでは `http://127.0.0.1:9030/mcp` に
なります。

1. **設定 → サーバー → MCPサーバー**に移動します
2. **MCP サーバー**カードを確認します — 実行中か停止済みか、およびリッスンして
   いるポートが表示されます

新規インストールではこのサーフェスは既定で有効です。カードのトークンが見えるのはサーバーオーナーだけで、エンドポイントを開始または停止できるのも、オーナーだけです。**アプリ起動時に開始**は再起動後に再び起動するかどうかを制御します。**開始** / **停止**はセッションのコントロールであり、この設定を変更しません。

サーバーは既定でループバックにバインドするため、`--bind any` を付けて起動しない
限り、エンドポイントに到達できるのは `cc_server` が動作しているマシンからのみです。

## トークンを取得する

すべてのリクエストには、どのマシンからでも、ループバックを含めて、サーバーの MCP トークンが必要です。サーバーは最初の起動時にそれを作成します。オフにする方法も、消去する方法もありません。

1. **設定 → サーバー → MCPサーバー** で、**認証トークン** の行を見つけます
2. **トークンを表示** を押して、コピーします
3. 置き換えるには **トークンをローテーション** を押します。サーバーはすぐに新しいトークンに切り替わり、古いトークンを使い続けているクライアントは、新しいトークンを渡されるまで拒否されます

## クライアントを接続する

クライアントを Streamable HTTP エンドポイントに向け、すべてのリクエスト（`GET /sse` を含む）で、トークンを `Authorization: Bearer <token>` として送信します。ほかに送る方法はありません。URL にトークンを含めても受け付けられません。設定の正確な形はお使いのクライアント次第です。

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code はプロジェクトの `.mcp.json` からこれを読み込みません — プロジェクト
スコープの MCP サーバーは承認プロンプトの背後にゲートされており、非対話の
`claude -p` はそれに決して回答しません。設定を明示的に渡してください:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` は Claude にそのファイルだけを使わせるので、同じサーバーが
プロジェクトからも検出されて二重に登録されることはありません。

チェックポイント: クライアントにツールを一覧表示させます。チケット、スペース、
メモリ、コードグラフ、レビューをカバーする `mcp__*` のエントリが表示されるはず
です。

## エンドポイントが拒否するもの

トークンはサーバー上のすべてのツールを開くため、エンドポイントは、トークンを確認する前に、Web ページから送られてきた可能性のあるものもすべて拒否します。

| リクエスト | 応答 |
| --- | --- |
| このマシン上のページではない `Origin` ヘッダー（`http://localhost`、`http://127.0.0.1`、`http://[::1]`、ポートは任意） | `403`、"Cross-origin requests are not accepted" |
| このリスナーのループバックのアドレスとポート、またはサーバーの公開ホスト名のいずれでもない `Host` ヘッダー | `403`、"Unknown host" |
| 本文が `application/json` ではない `POST` | `415` |
| トークンがない、または誤っている | `401` |

ホストの外に MCP を提供するには、`--bind any` でサーバーを起動し、別のマシンからトークンを送信します。その際、サーバーはその公開ホスト名で指定します。

## すべての呼び出しをワークスペースにスコープする

ワークスペーススコープのデータに触れるすべてのツールは `workspace_id` を必須とし、
それがなければ呼び出しは、何らかの「現在の」ワークスペースに解決されるのではなく
拒否されます:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

ID はブラウザーまたはアプリの URL にあるものです: `/workspaces/<workspace_id>/…`。
唯一の例外は、`list_workspaces` やニュースフィードのツールのように、本当に
ワークスペースをまたぐツールです — ニュースフィードはユーザー単位であり、
エージェントは自分自身のユーザーを持たないため、これらのツールはサーバー所有者の
フィードを操作します。

リポジトリスコープのツールはさらに、そのリポジトリがそのワークスペースにリンク
されているかを確認します。

## サーフェスが何を拒否するかを知る

- **モードによるゲート。** 呼び出しはサーバー側で、呼び出し元エージェントのスペース
  のモードに対して解決されます。読み取り専用モードのエージェントは、`space_id` を
  省略しても書き込みツールに到達できません — 代わりに、そのモードはその実行中の
  実行から参照されます。
- **アクションガードレール。** 変更を加えるツールは自身のエフェクトクラスを宣言し、
  製品の他の部分と同じポリシーを通ります。
  [ガードレールを設定](/ja-JP/マニュアル/ハウツーガイド/ガードレール設定/)を参照して
  ください。
- **確認。** 一部の破壊的なツールは確認ペイロードを生成し、呼び出しが進む前に承認
  される必要があります。

完全なカタログは `tools/list` で、ディスカバリーのゲートなしに公開されます — 外部の
MCP クライアントは、自身のキャッシュ済みリストにないツールの呼び出しを拒否するため、
ツールを隠すことはそれらを整理するのではなく壊すことになります。

## 個人の MCP サーバーはオーナーのもの

このガイドは Control Center 自身のエンドポイントについてのものです。もう一方の方向、つまり Control Center が実行するエージェントに渡す MCP サーバーは、**設定 → サーバー → MCPサーバー → 外部 MCP サーバー** に一覧されています。サーバーのマシン上で Claude、Codex、Cursor、Gemini、VS Code、Windsurf、OpenCode 向けに設定された、または `.mcp.json` にある MCP サーバーは、そこで自動的に見つかります。

見つかったサーバーは、サーバーユーザー自身のツール設定に由来し、そのユーザーの ID と認証情報で動作するため、サーバーオーナーに属します。

- サーバーオーナーが開始した、またはオーナーが責任を負う組み込みのハーネスの実行でのみ利用できます。オーナーが責任を負うワークスペース内の自動化も含みます
- メンバーの実行、メンバーに紐付けられた自動化、記録されたオーナーがいないサーバー上のすべての実行には、これらは一切提供されません。そこではツールは一覧に表示されず、呼び出すこともできず、ツール検索にも表示されません
- このエンドポイントは、誰に対しても、オーナーのトークンを含めて、それらを一覧表示、呼び出し、検索することは決してなく、そのリソースやプロンプトを中継することもありません。そのため、Claude Code のように MCP 経由で Control Center に接続するエージェント CLI は、Control Center を通じてそれらを受け取ることはなく、自身の設定を使います

ワークスペース向けに構成された MCP サーバーは、これらのいずれの影響も受けません。

## トラブルシューティング

### クライアントにツールが表示されない

- **MCP サーバー**カードが「実行中」と表示されているか確認します
- ポートが `cc_server` のポートと一致しているか確認します
- Claude Code では、`--mcp-config` と `--strict-mcp-config` を渡したか確認します

### 401 Unauthorized

リクエストにトークンがないか、古いトークンが付いていました。**認証トークン** の行から現在のトークンをコピーし、`Authorization: Bearer <token>` として送信してください。URL にあるトークンは無視されます。

### 以前動いていたクライアントからの 403

リクエストに、Web ページからの `Origin`、またはサーバーが応答しない `Host` が含まれていました。ブラウザーのページではなくクライアントから、サーバーのループバックのアドレスまたは公開ホスト名を指定してエンドポイントを呼び出してください。

### 415 Unsupported Media Type

`POST /mcp` の本文は `application/json` で送信してください。

### ツール呼び出しが "Missing or invalid argument: workspace_id" で失敗する

`workspace_id` を追加します。暗黙のワークスペースは存在しません。

### ツール呼び出しが不明として拒否される

[MCP ツール](/ja-JP/マニュアル/リファレンス/mcp-ツール/)にカタログがあります。
そこに表示されているとおりの名前で呼び出してください。
