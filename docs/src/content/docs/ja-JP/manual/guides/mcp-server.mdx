このガイドでは、外部の MCP クライアント — Claude Code、エディター、MCP
Inspector — を Control Center 自身のツールサーバーに接続する方法を説明します。

Control Center は **110** 個のツールを登録し、プロトコルバージョン `2024-11-05`
の Model Context Protocol でそれらを提供します。期待されるかもしれないツール
ファミリーが丸ごと存在しません。ミーティングやカレンダーのツールはなく、
プロジェクトのツールもありません。

## エンドポイントを見つける

MCP サーフェスはメインの `cc_server` リスナーを共有します。MCP 専用のポートは
ありません。

| エンドポイント | メソッド | 用途                                                     |
| -------------- | -------- | -------------------------------------------------------- |
| `/mcp`         | `POST`   | Streamable HTTP トランスポート — クライアントが話すのはこれです |
| `/mcp`         | `DELETE` | セッションを終了する                                      |
| `/sse`         | `GET`    | サーバー送信の通知ストリーム                              |

したがって、既定のローカルインストールでは `http://127.0.0.1:9030/mcp` に
なります。

1. **設定 → サーバー → MCP サーバー**に移動します
2. **MCP サーバー**カードを確認します — 実行中か停止済みか、およびリッスンして
   いるポートが表示されます

新規インストールではこのサーフェスは既定で有効なので、ループバックのクライアント
は設定を触ることなく動作します。**アプリ起動時に開始**は再起動後に再び起動するか
どうかを制御します。**開始** / **停止**はセッションのコントロールであり、この設定
を変更しません。

サーバーは既定でループバックにバインドするため、`--bind any` を付けて起動しない
限り、エンドポイントに到達できるのは `cc_server` が動作しているマシンからのみです。

## クライアントを接続する

クライアントを Streamable HTTP エンドポイントに向けます。設定の正確な形はお使いの
クライアント次第ですが、URL はどちらでも同じです。

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp"
    }
  }
}
```

### Claude Code

Claude Code はプロジェクトの `.mcp.json` からこれを読み込みません — プロジェクト
スコープの MCP サーバーは承認プロンプトの背後にゲートされており、非対話の
`claude -p` はそれに決して回答しません。設定を明示的に渡してください:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` は Claude にそのファイルだけを使わせるので、同じサーバーが
プロジェクトからも検出されて二重に登録されることはありません。

チェックポイント: クライアントにツールを一覧表示させます。チケット、スペース、
メモリ、コードグラフ、レビューをカバーする `mcp__*` のエントリが表示されるはず
です。

## ホストの外に MCP を公開する

1. **設定 → サーバー → MCP サーバー**で、**認証トークン**の行にある**設定**を押し、
   トークンを貼り付けます
2. すべての `POST /mcp` リクエストで `Authorization: Bearer <token>` として送信
   します

トークンのないサーフェスは、ループバック以外の呼び出し元をすべて 403 で拒否します。
これは設計上フェイルクローズです。トークンがあってこそ、ホスト外へのサービス提供が
そもそも可能になります。

トークンの変更は実行中のサーフェスに即座に反映されます — 再起動は不要です。

:::note[`GET /sse` はトークンをクエリ文字列で受け取る]
通知ストリームも他のすべてのルートと同様にトークンを検査しますが、ブラウザーの
`EventSource` は `Authorization` ヘッダーを送信できません — そのため `/sse` は
`?token=<token>` としてのトークンも受け付けます。トークンがない場合は 401 を返し
ます。
:::

## すべての呼び出しをワークスペースにスコープする

ワークスペーススコープのデータに触れるすべてのツールは `workspace_id` を必須とし、
それがなければ呼び出しは、何らかの「現在の」ワークスペースに解決されるのではなく
拒否されます:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

ID はブラウザーまたはアプリの URL にあるものです: `/workspaces/<workspace_id>/…`。
唯一の例外は、`list_workspaces` やニュースフィードのツールのように、本当に
ワークスペースをまたぐツールです — ニュースフィードはユーザー単位であり、
エージェントは自分自身のユーザーを持たないため、これらのツールはサーバー所有者の
フィードを操作します。

リポジトリスコープのツールはさらに、そのリポジトリがそのワークスペースにリンク
されているかを確認します。

## サーフェスが何を拒否するかを知る

- **モードによるゲート。** 呼び出しはサーバー側で、呼び出し元エージェントのスペース
  のモードに対して解決されます。読み取り専用モードのエージェントは、`space_id` を
  省略しても書き込みツールに到達できません — 代わりに、そのモードはその実行中の
  実行から参照されます。
- **アクションガードレール。** 変更を加えるツールは自身のエフェクトクラスを宣言し、
  製品の他の部分と同じポリシーを通ります。
  [ガードレールを設定](/ja-JP/マニュアル/ハウツーガイド/ガードレール設定/)を参照して
  ください。
- **確認。** 一部の破壊的なツールは確認ペイロードを生成し、呼び出しが進む前に承認
  される必要があります。

完全なカタログは `tools/list` で、ディスカバリーのゲートなしに公開されます — 外部の
MCP クライアントは、自身のキャッシュ済みリストにないツールの呼び出しを拒否するため、
ツールを隠すことはそれらを整理するのではなく壊すことになります。

## トラブルシューティング

### クライアントにツールが表示されない

- **MCP サーバー**カードが「実行中」と表示されているか確認します
- ポートが `cc_server` のポートと一致しているか確認します
- Claude Code では、`--mcp-config` と `--strict-mcp-config` を渡したか確認します

### サーバー以外のマシンから 403 が返る

ベアラートークンが設定されていません。設定して送信してください。

### ツール呼び出しが "Missing or invalid argument: workspace_id" で失敗する

`workspace_id` を追加します。暗黙のワークスペースは存在しません。

### ツール呼び出しが不明として拒否される

[MCP ツール](/ja-JP/マニュアル/リファレンス/mcp-ツール/)にカタログがあります。
そこに表示されているとおりの名前で呼び出してください。
