このガイドでは、Git チェックアウトをワークスペースに登録し、再インデックスし、再び削除する方法を説明します。サーバーのフォルダーからリポジトリを追加するにはサーバーオーナーが必要で、リポジトリを削除するにはワークスペース管理者が必要です。

リポジトリは**ワークスペース単位**です。グローバルなレジストリもリンク手順もありません。リポジトリを追加することと、それをワークスペースに置くことは同じ行為です。同じチェックアウトを2つのワークスペースに登録すると、2つの異なる id を持つ2つの独立した行になります。ワークスペースをまたぐ場合、リポジトリの同一性はそのファイルシステム上のパスであり、id では決してありません。

## 始める前に

フォルダーを登録できるのは、次の3つすべてに当てはまる場合だけです。

1. **git ワークツリー**の内部にある。
2. そのワークツリーに **`origin` リモート**がある。
3. `origin` リモートが**対応しているコードホスト**（github.com、gitlab.com、bitbucket.org）を指している。

それ以外は登録時に明示的なメッセージとともに拒否されます。「Folder is not inside a git work tree.」「No `origin` remote configured for this repository.」「The `origin` remote is not hosted on a supported forge (github.com, gitlab.com, bitbucket.org).」のいずれかです。ローカルのみのモードはありません。

コードホストはリモートから読み取られてリポジトリに保存されます。自分で選ぶことはありません。1つのワークスペースに3つのコードホストのリポジトリを同時に置くことができ、それぞれは独自の認証情報を持つ独自の API を通じてやり取りされます。GitLab のネストされた名前空間は保持されるため、`gitlab.com/group/subgroup/project` はオーナー `group/subgroup`、名前 `project` として登録されます。

フォルダーは、`cc_server` をホストしているマシン上で、そのサーバーの `--repo-roots` ディレクトリのいずれかの内側にある必要もあります。この許可リストの既定値はサーバーユーザーのホームディレクトリで、ルートより上を参照することは拒否されます。サーバーのフォルダーの参照は、マシン自身のファイルを一覧にするため、[サーバーオーナー](/ja-JP/マニュアル/コンセプト/認可/#サーバーオーナー)だけに提供されます。それ以外の人には、**リポジトリを追加**ボタンがあるはずの場所に「リポジトリは、サーバーのフォルダーからサーバーオーナーが追加します。」と表示され、どのワークスペースにもないリポジトリへのリンクには、どのワークスペースにもリンクされていないこと、そしてサーバーオーナーに追加を依頼することが表示されます。

チェックアウトを置ける場所は、リンクする人によって決まります。

- **サーバー上のワークスペース自身のストレージの内側**: どのワークスペース管理者も可能です。
- **サーバーのディスク上のそれ以外のどこか**: [サーバーオーナー](/ja-JP/マニュアル/コンセプト/認可/#サーバーオーナー)だけです。マシン自身のファイルをサーバーに指せるのはサーバーオーナーだけだからです。それ以外の人には「このワークスペースのストレージの外にあるフォルダーは、サーバーオーナーだけがリンクできます。」と表示されます。
- **サーバーのデータフォルダー**、またはその内側: 決して不可です。

チェックアウトの `origin` は、リンクしようとしているリポジトリでなければなりません。`origin` が別のリポジトリを指すフォルダーは、「そのフォルダーの origin は別のリポジトリです。」と表示されて拒否されます。

### サーバーがまだ使わないフォルダー

ワークスペースのストレージの外にあるフォルダーを持ち、サーバーオーナーがリンクしていないリポジトリ（インポートされたワークスペースのものなど）は、サーバーオーナーが確認するまで、その行の下に「このフォルダーはワークスペースのストレージの外にあります。このサーバーの使用を確認してください。」と表示されます。それ以外の人には、代わりに「このフォルダーはワークスペースのストレージの外にあります。確認できるのはサーバーオーナーだけです。」と表示されます。

オーナーは一度だけ確認します。行の **確認** を押すか、複数のリポジトリが待っている場合はリストの上の通知にある **すべて確認** を押します。それぞれは、リンクするときと同じチェックを、オーナーとして再度受けます。確認するまでは、リストには残りますが、開かれず、プロビジョニングもインデックスもされません。エディター、ターミナル、環境、スペースのチェックアウトのどれもそれを使わず、コードグラフはそれを飛ばします。サーバーオーナーとして同じフォルダーをもう一度追加すると、確認するのと同じことになり、リポジトリの id は保たれます。

シンボリックリンクによって別の場所に移されたチェックアウトも、同じように扱われます。リストには残りますが使われず、それが今指しているフォルダーをリンクする権限のある人が再度リンクするまで使われません。

あなたは、そのリポジトリのフォージにサインインしている必要もあり、あなた自身のアカウントがそのリポジトリを見られる必要があります。

## チェックアウトを登録する

これらの手順にはサーバーオーナーである必要があります。

1. **設定 → ワークスペース → リポジトリ**を開きます（`/workspaces/<id>/settings/workspace/repositories`）。
2. **リポジトリを追加**をクリックします。

このダイアログは、自分のものではなく**サーバーの**ファイルシステムを参照する、ナビゲート可能なブラウザーです。デスクトップ、ウェブ、スマートフォンで同じ流れになります。ネイティブのフォルダピッカーでは、誤ったマシン上のフォルダーを選んでしまうからです。

3. サーバーに設定されたルート内を移動します。git チェックアウトであるフォルダーには印が付きます。
4. 任意の数のフォルダーにチェックを入れます。選択内容は移動しても保持されるため、複数のフォルダーからチェックアウトを集められます。
5. それらを一括で登録します。

1つの選択が失敗しても、バッチの残りが取り消されることはありません。作成された id に加えて、拒否されたパスごとのエラーが返ります。このワークスペースにすでに存在するパスを再登録すると、重複を作らずに既存のリポジトリが返されます。

登録された各リポジトリは、リストに `owner/name`、コードホスト名を示すバッジ、サーバー上のパスとともに表示されます。GitHub のリポジトリはオーナーのアバターも表示します。ほかのコードホストには推測できるオーナーアバターの URL がないため、イニシャルにフォールバックします。

コードホストのバッジは混在したワークスペースで重要になります。2つのリポジトリが別々のコードホスト上で同じ `acme/web` を名乗ることがあり、レビューでできることやリンクの飛び先が異なります。

## 次に起こること

登録すると、このワークスペースにスコープされた `RepoAdded` イベントが発火し、そのチェックアウトの `index_code` パイプラインが開始されます。これがコードグラフを埋めるので、検索と影響分析が答えるべき対象を持てます。

同梱の文法がある言語のファイルだけがインデックスされます（Dart、JavaScript、TypeScript、TSX、PHP、Python、Rust、Zig、C、C++、Go、Java、Ruby、C#、Swift、Kotlin、R、Assembly、MATLAB、Ada）。[コードグラフでコードを検索](/ja-JP/マニュアル/ハウツーガイド/コード検索/)を参照してください。

## リポジトリを再インデックスする

各行には**コードをインデックス**ボタンがあります。クリックすると、そのチェックアウトのインデクサーが再実行されます。実行中はボタンが、完了ファイル数と合計を示す進行状況の表示に変わり、キャンセル操作が付きます。完了すると、シンボル数が付いたチェックに落ち着き、実行が失敗した場合は警告になります。

## リポジトリを並べ替える

行のハンドルをドラッグします。設定した順序は、アプリ内のすべてのリポジトリリストが読み出す順序になります。

## GitHub リンクを修正する

行のリンクアイコンをクリックすると、そのリポジトリの GitHub オーナーとリポジトリ名のエディターが開きます。

これを使う場面はほとんどありません。リンクはフォージ上のリポジトリの永続的な id に結び付いているため、名前の変更や移転は自動的に追従されます。

- Control Center でリポジトリの名前を変えても、変わるのは表示名だけです。
- リンクが指すフォージのリポジトリを変えるには、ワークスペース管理者が必要で、リンクするときと同じく、その管理者自身のサインインでフォージに対して確認されます。
- リンクされたリポジトリを、ローカルのみのリポジトリに変えることはできません。

後からパスが**別の**リポジトリを指すようになった場合（元のものが削除されて作り直された、または別のものに移動されて差し替えられた場合）、Control Center はそれに何も送信しなくなります。トークン、プッシュ、コメント、リクエストは一切送りません。これは個人自身の操作にも及びます。そのようなリポジトリに対するレビュー、マージ、コメントは、GitHub、GitLab、Bitbucket のいずれでも拒否されます。ワークスペース管理者が **再リンク** を押すまで、その行とリポジトリのプルリクエストには「_repo_ は別のリポジトリを指すようになりました」と表示されます。

## コードを開けるユーザー

リポジトリの権限だけでは、そのリポジトリのファイルは開けません。ファイル、差分、検索、またはターミナルを開くには、メンバーが Control Center の権限を持ち、かつ自分のフォージのサインインでそのリポジトリを読めなければなりません。ワークスペース管理者は例外ではありません。例外はサーバーオーナーだけです。[コードはフォージに従います](/ja-JP/マニュアル/コンセプト/認可/#コードはフォージに従う) を参照してください。

フォージのアカウントがそのリポジトリを読めない人にリポジトリを付与すると、権限は保存されますが、「保存しました。お使いの GitHub アカウントではまだこのリポジトリを読めないため、表示されません。」のような警告が表示されます。

同じルールがスペースを開ける人も決めます。スペースは、そこで使われているすべてのリポジトリのコードを開ける人にだけ開かれ、それ以外の人からは、そのスペースは検索結果、実行ログ、Todo、アクティビティ、通知とともに隠されます。リポジトリのないスペースは、すべてのメンバーに開かれています。[スペースはリポジトリに従います](/ja-JP/マニュアル/コンセプト/認可/#スペースはリポジトリに従う) を参照してください。

## リポジトリを削除する

1. **設定 → ワークスペース → リポジトリ**を開きます。
2. 行のゴミ箱アイコンをクリックします。
3. 「ワークスペースからリポジトリを削除しますか？」を確認します。

ダイアログにはその動作が書かれています。「_name_ はこのワークスペースから削除されます。ディスク上のローカルファイルは変更しません。」

リポジトリを削除するにはワークスペース管理者が必要です。また、そのリポジトリ用に保存されたフォージの認証情報（GitLab や Bitbucket の自動化トークンなど）も忘れられます。

削除すると、このワークスペースからリポジトリの行が消え、そのコードグラフの行（シンボル、エッジ、ファイル、インデックスのチェックポイント）が連鎖的に削除されます。さらに、そのリポジトリに対するメンバーごとの許可、スペースとリポジトリのリンク、分離チェックアウトの記録も削除されます。別のワークスペースに登録された同じチェックアウトは独立した行であり、影響を受けません。それらの記録が指していたディスク上のワークツリーは、この削除によって破棄されません。

## トラブルシューティング

### 権限はあるのに、リポジトリがアカウントで読めないと表示される

あなた自身のフォージアカウントではそのリポジトリを読めないため、ワークスペースが権限を付与していても、Control Center はそのコードをあなたから隠します。まだであれば、**設定 → 自分 → プロフィール → コードホスティング** でフォージにサインインしてください。または、フォージ上でリポジトリの所有者にアクセスを依頼してください。フォージのアカウントがリポジトリを読めるようになると、すぐに開けます。

### 「このフォルダーはワークスペースのストレージの外にあります」

リポジトリのフォルダーはワークスペースのストレージの外にあり、サーバーオーナーがリンクしていないか、シンボリックリンクがそれを今は別の場所に向けています。サーバーオーナーが確認するか、フォルダーを再度追加するまで、リストには残りますが使われません。オーナーでない場合は、オーナーに依頼してください。オーナーの場合は、行の **確認** を押すか、リストの上の **すべて確認** を押してください。[サーバーがまだ使わないフォルダー](#サーバーがまだ使わないフォルダー) を参照してください。

### 「サーバー上のこのパスには、もう何もありません」

フォルダーはサーバーのマシン上で移動されたか削除されました。元に戻すか、ワークスペース管理者に、通知の **削除** でリポジトリを削除してもらい、現在のフォルダーから再度追加してもらってください。

### 「このフォルダーはリポジトリとして使用できません」

保存されているフォルダーが、サーバー自身のデータフォルダー、その内側のもの、またはワークスペースのストレージフォルダー自体です。これらはいずれもリポジトリにはなれません。ワークスペース管理者が通知の **削除** で削除し、そのあと、チェックアウトの実際のフォルダーから再度リポジトリを追加します。

### 「フォージへのアクセスを確認できませんでした」

アカウントがリポジトリを読めることを確認するためにフォージに到達できなかったため、Control Center は推測せずに拒否しました。しばらくしてからもう一度お試しください。
