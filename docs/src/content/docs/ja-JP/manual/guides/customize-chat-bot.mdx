このガイドでは、Control Center を離れずに、プロバイダー側のボットアプリを作り変える方法を説明します。

## 前提条件

- ワークスペースでの `owner` または `admin` ロール
- **接続済み**のプロバイダー。**ボットをカスタマイズ**の行は、ワークスペースが接続されてから初めて表示されます
- Control Center が管理できるアプリ。Slack の場合は、接続がアプリ設定のリフレッシュトークン（`xoxe-…`）を保持している必要があります。保持していない場合、その行はその旨を表示して無効のままになります

## 変更できるもの

| フィールド | 意味 | 制限 |
| --------------------- | ----------------------------------------------- | ---------------------------------------------------------- |
| **アプリ名** | プロバイダーがアプリを一覧表示するときの名前 | 1〜35 文字 |
| **ボット名（メンバーが@の後に入力するもの）** | メンバーが `@` の後に入力するもの | 1〜80 文字 |
| **簡単な説明** | プロバイダーが表示する 1 行 | 140 文字以内 |
| **ボットの自己紹介** | ボットとの DM の上に表示される | 300 文字以内 |
| **スラッシュコマンド** | メンバーが呼び出すコマンド（スラッシュを除く） | 小文字化され、`a–z 0–9 _ -` のみ、32 文字で切り詰め |
| **ダイレクトメッセージ** | ボットが DM とエージェントの体験を公開するかどうか | オンまたはオフ |

Control Center はプロバイダーを呼び出す前に 4 つのテキストフィールドを検証します。そのため、見ることのできないサーバーから不透明な `invalid_manifest` が返る代わりに、「the app name must be between 1 and 35 characters」が返ります。コマンドは拒否されず、正規化されます。先頭のスラッシュは取り除かれ、残りは小文字化され、`a–z 0–9 _ -` 以外の文字は削除され、結果が空になった場合は `cc` にフォールバックします。

## ボットを編集する

1. **設定 → ワークスペース → 全般**に移動し、**チャットブリッジ**カードまでスクロールします
2. プロバイダーのブロックで、**ボットをカスタマイズ**をクリックします
3. ダイアログは、プロバイダーから読み戻された、アプリの_ライブ_の値で開きます — そのため、誰かが Slack 自身の UI で加えた変更が、あなたの出発点になります
4. 必要な箇所を編集して保存します

これらのライブの値を読み取ると、Slack 側でトークンのローテーションが発生します。だからこそこの行は、ページの読み込み時に自動で実行されるのではなく、意図してクリックするものになっています。

書き込みは、あなたの変更をアプリの現在の定義に重ねます。Control Center がモデル化していないもの — Slack で追加した 2 つ目のスラッシュコマンド、ワークフローのステップ、無関係な設定 — はそのまま残ります。スコープとイベントはマージされ、差し引かれることはありません。

保存後、Control Center はボットのアイデンティティを読み直すため、設定の名前とチャットアプリの名前が一致します。

## 権限が変わったら再インストールする

:::caution[権限変更後の再インストール]
Slack は新しいアプリ定義を即座に適用しますが、インストール済みの付与はそのまま
保持します。権限の変更を反映するには、アプリを再インストールしてください。
それを行うまで、ブリッジは以前の付与で動き続けます。
:::

保存によって権限が変わると、ダイアログは開いたままになり、「Slackがアプリの権限を変更しました。反映するにはアプリを再インストールしてください。」と表示します。あわせて、そのアプリを Slack のチームにインストールするページを開く**アプリを再インストール**ボタンも表示されます。Slack 側では、これが **Install App → Reinstall to Workspace** です。

## スラッシュコマンドの名前を変更する

**スラッシュコマンド**を変更して保存します。するとブリッジは、最後に呼び出されたときのコマンドを使って案内を書き出すため、ヘルプテキストとリンクの案内は、存在しなくなったコマンドを名指しするのではなく、名前の変更に追随します。

名前を変更しても、既存のブリッジ済みスレッドは壊れません。スレッドはコマンドではなく会話をキーにしているためです。

## Control Center が変更しないもの

- **構造的な設定。** トランスポート（Socket Mode）、必須のスコープ、イベント購読は表明されるものであり、提供されるものではありません。設定画面から設定して沈黙させられるアプリは、機能ではなくサポートチケットです
- **ボットのアイコン。** 変更できるのはプロバイダー自身のアプリ設定だけで、ダイアログにもその旨が表示されます
- **プロバイダー自身の機能マイグレーション。** すでに Slack の旧来のアシスタント形態にあるアプリはそれを維持します。このダイアログは説明文を編集するものであり、アプリを移行するものではありません

## トラブルシューティング

### 「ボットをカスタマイズ」の行がまったく表示されない

ワークスペースがまだ接続されていません。この行は、プロバイダーのブロックが
稼働中の接続を示してから初めて表示されます。[Slack インテグレーションを設定](/ja-JP/マニュアル/ハウツーガイド/slack-インテグレーション/)を参照してください。

### 「ボットをカスタマイズ」の行が無効になっている

接続にアプリ管理用の資格情報がありません — 行のサブタイトルには
「ボットを編集するには、Control Centerにアプリ設定トークンが必要です。再接続して、
トークンを含めてください。」と表示されます。Slack の場合は、
[api.slack.com/apps](https://api.slack.com/apps) でアプリ設定トークンのペアを生成し、
リフレッシュトークンを入力して再接続してください。これは、手作業で構築したアプリや
**Slackで作成**を通じて作成したアプリでは想定どおりの動作です。Slack はどのアプリを
作成したかを決して報告しないためです。

### 「Control Center does not know which app to edit」

保存された接続にアプリ id が含まれていません — 通常は、id が記録される前に手作業で接続されたアプリです。ワークスペースを再接続するか、Control Center からアプリを作成してください。

### ボットの新しい名前がチャットに表示されない

プロバイダーはアプリのメタデータを一時的にキャッシュします。1 分経っても名前が古いままなら、保存時にアプリの再インストールを求められたかどうかを確認してください。
