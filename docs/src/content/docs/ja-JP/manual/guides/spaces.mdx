このガイドでは、スペースの使い方を説明します。**スペース**とは Control Center の
メッセージングサーフェスです。ワークスペース単位のルームで、1 人以上の参加者
（あなたやエージェント、またはその両方）を持ち、作成対象となったリポジトリごとに
コピーオンライトのワークツリーを所有します。

1 対 1 のルームも複数エージェントのルームも、どちらも単なるスペースであり、違いは
参加者の数だけです。唯一の例外は、エージェント同士が会話するために開くスペースです
— 後述の[エージェント間のスペース](#エージェント間のスペース)を参照してください。

## スペースを作成

1. **スペース**に移動します
2. 「スペース」見出しの横にある **+** ボタンをクリックします
3. **名前**を付けます — 必須です。空の名前は拒否され、ダイアログは開いたままに
   なります
4. 任意で、ワークスペースからエージェントを追加します
5. ワークスペースにリポジトリが 1 つでもある場合は、このスペースがワークツリーを
   プロビジョニングする対象を選びます。デフォルトではすべてが選択されています。
   すべてのリポジトリの選択を外すと、何もチェックアウトされていないスペースが
   作成されます
6. 確定します

スペースはワークスペース単位です。表示されるのは現在のワークスペースのエージェント
だけで、スペースが別のワークスペースのデータを表に出すことはありません。

各リポジトリは、スペース内の `repos/<name>/` にチェックアウトされます。独自の
エージェントスキルを同梱するリポジトリは、そこで作業しているエージェントにそれらを
提供します — 同時に有効なのは 1 つのリポジトリのセットだけで、エージェントが移動
するたびに入れ替わります。コンポーザーからは `/skill:<repo>:<name>` でそのいずれにも
到達できます。
[リポジトリ単位のスキル](/ja-JP/マニュアル/コンセプト/エージェントモデル/#repo-scoped-skills)
を参照してください。

このサーフェスは `/workspaces/<id>/spaces` にあり、単一のスペースは
`/workspaces/<id>/spaces/<spaceId>` にあります。

## スペースのモードを設定

新しいスペースはデフォルトモードで始まります。モードを変更するのは、コンポーザーの
ツールバー左端にある**モードドロップダウン**です — 作成ダイアログ（そこにモード
フィールドはありません）からでも、スペースヘッダーからでもありません。

| モード          | 効果                                                                                                     |
| --------------- | -------------------------------------------------------------------------------------------------------- |
| **Agent**       | 完全なアクセス。デフォルトです。内部的には `chat` で、ドロップダウンでは「Agent」と表示されます           |
| **Plan**        | 読み取りと調査のみ。成果物は型付きのプランです                                                            |
| **Orchestrate** | 読み取りと調査に加えて、単一の `propose_orchestration` 動詞。プランはあなたが承認した後にのみ実行されます |

Shift+Tab は、ドロップダウンを開かずにプランモードとエージェントモードを切り替えます。

4 つ目のモードである **review** は存在しますが、ドロップダウンには表示されません —
PR レビューのスペースに自動的に適用されます。

モードはスペースに保存されるため、同じエージェントが一方のスペースではプランモード、
もう一方ではエージェントモードになることがあります。スペース内のすべての会話は、その
スペースのモードを共有します。

:::caution[強制バッジに注意]
モードドロップダウンの横にバッジが表示されるのは、スペースのエージェントが、選択した
モードを強制できないアダプター上で実行されている場合です。ツールサーフェスを
フィルタリングし、すべての呼び出しをゲートするのは、組み込みの Control Center
ハーネスだけです。Claude Code と ACP のアダプターはモードをリクエストとして受け取り、
そのランナーがそれに従うかどうかは保証されません。バッジがないことは「何も主張して
いない」という意味であり、「安全が検証済み」という意味ではありません。
:::

モデル全体については[モード](/ja-JP/マニュアル/コンセプト/モード/)を参照してください。

## 参加者とエージェントごとの自律性を管理

スペースヘッダーの人のアイコンをクリックすると、**参加者を管理**が開きます。すでに
スペースにいるエージェントごとに、次のことを行えます:

- スペースから削除する
- このスペースにおける**自律度**を設定する: **デフォルト**、**提案のみ**、
  **承認後に実行**、**自由に実行**

自律度のダイヤルは (スペース, エージェント) の組ごとに設定されるため、あるルームで
信頼しているエージェントを、別のルームでは提案のみに留めることができます。

## メッセージにリアクションする

メッセージにマウスを重ねてスマイリーアイコンをクリックすると、リアクションのパレット
が開きます。内容は 👍 👎 🎉 ❤️ 👀 ✅ の 6 つに固定されています。自由な絵文字ピッカー
はありません — 1 つタップするとあなたの分が切り替わり、集計されたチップがメッセージ
の下に表示されます。

## 会話を開く

スペースは複数の会話を同時に抱えることができ、それらは対等で、主要なものはありません。
スペースには常に少なくとも 1 つの生きている会話が残ります。最後のアクティブな会話は
アーカイブできず、まだ 1 つもないスペースを開くと、無題の常設会話が作成されます。

会話はエディターのタブとして表示され、2 つ以上になるとサイドバーのスペースの下に
ネストされた行としても表示されます。**新しい会話**はエディターの新規タブメニューに
あり、タイトルを尋ねずに無題の会話を作成します — タイトルモデルが最初のメッセージに
基づいて名前を付けます。同じエージェントと同じワークツリーで並行作業を行うのに使え
ます。

各会話は独自のメッセージ履歴とエージェントセッションを保持しつつ、スペースの
ワークツリーとモードを共有します。タブを閉じるとその会話は隠れます。**会話を
アーカイブ**（サイドバーの行、またはチャットタブのコンテキストメニュー）は、その
会話だけをアーカイブします。

## スレッドを開始

任意のメッセージにマウスを重ねて**スレッドを開始**を選びます。すると、そのメッセージに
アンカーされた会話が開きます。アンカーは、1 行で新しい会話のエージェントコンテキスト
を初期化し、親の履歴はコピー**されません**。

スレッドに返信が付くと、そのスレッドがぶら下がっているメッセージの下に行が 1 つ増え
ます — 発言した人の顔、返信数、最後の返信が届いた時刻です。この行が戻るための入口です
— クリックするとスレッドのタブが開く（またはフォーカスされる）からです。これが、分岐
元のストリームにスレッドが残す唯一の痕跡であり、そもそもこれがあるのはそのためです。

スレッドのタブのタイトルは `Thread: <name>` で、ブランチのグリフが付くため、同じ
スペース上の 2 つのタブが取り違えられることはありません。

スレッドはネストしません — すでにスレッド内にあるメッセージにアンカーすることは拒否
されます。会話ヘッダーはアンカーメッセージへリンクで戻ります。アンカーメッセージを
削除するとスレッドも削除され、親の会話をアーカイブしても既存のスレッドはブロック
されません。

## 既読状態

既読マークは会話ではなくスペース単位です。スペース内のどの会話を開いても、ルーム
全体が既読になります。ただし未読は、スレッドを含むスペースのすべての会話にまたがって
集計されます。会話がスペースの下に一覧表示されている場合、未読ドットは親の行ではなく、
未見の作業がある会話に付きます。

## エージェント間のスペース

エージェント同士が会話するために開くスペースは、サイドバーの**エージェント**の下に
別立てでまとめられ、デフォルトでは折りたたまれ、淡色で表示されます。これらのスペース
が未読バッジを増やすことはありません — エージェントのおしゃべりが静かなのは、あなた
が見つけなければならない設定によるのではなく、構造上そうなっているからです。

スペースの種類は次の 5 つの値のいずれかです: `topic`（あなたが作成するものすべての
デフォルト）、`agentPeer`、`system`（パイプラインで管理）、`pr`（PR サーフェスが
ワークツリーのアンカーを必要としたときに作成され、メッセージが付くまでサイドバーから
隠されます）、`slack`（Slack スレッドまたはボットへの DM のためにチャットブリッジが
作成し、通常の人間の会話として扱われます）。
