Control Center での Linear には 2 つのアイデンティティがあり、どちらもブラウザーでの
サインインです。1 つはあなた自身のもので、あなたが行う操作に使われます。もう 1 つは
ワークスペースの Control Center アプリで、エージェントとパイプラインが行う操作に使われます。
チケット、プロジェクト、リンク、コラボレーター、委任、割り当てはすべて Control Center
自身のデータベースに対して動作し、外部サービスは不要です — [チケットの作成と管理](/ja-JP/マニュアル/ハウツーガイド/チケット管理/)
を参照してください。

## 前提条件

- サーバーが Linear へのサインインを提供できること。Control Center Connect を通じて、
  またはサーバー自身の Linear アプリケーションで行います
  （[独自の Linear アプリケーションを登録する](#独自の-linear-アプリケーションを登録する)）。
  どちらにするかはサーバー所有者が **設定 → サーバー → シングルサインオン** で選びます
- Linear をチケットプロバイダーに選び、Linear 自動化を接続するための、ワークスペース管理者

## ワークスペースで Linear を選ぶ

1. **設定 → ワークスペース → 全般** に移動し、**チケット管理** カードを見つけます
2. **チケットプロバイダー** を **Linear** に設定します

それ以降に作成するチケットには `provider: linear` が刻印されます。**ローカル** を選ぶと、
チケットはこのサーバー自身のデータベースに保存され、Linear の行は非表示になります。
認証する相手がないためです。

## Linear にサインインする

同じカードの **Linear** の行はあなた自身のものです:

1. **Linearにサインイン** をクリックします
2. ブラウザーで承認します
3. サーバー自身のアプリケーションの場合、ダイアログは自動的にそれを検知します。Connect
   を通じる場合は、ブラウザーに表示される 8 文字のコードを入力するか、`control-center://`
   リンクを通じてブラウザーに Control Center を開かせます

Control Center から Linear で行う操作は、すべてこのサインインで実行され、ほかのものは
使われません。サインインしていない場合、アプリは別の誰かとして動作するのではなく、
サインインを求めます。

## Linear 自動化を接続する

**Linearの自動化** の行は、Linear におけるワークスペースの Control Center アプリです。
チケット同期、パイプライン、エージェントはこれを使って書き込むため、自動化による Issue や
コメントは、個人ではなく Control Center として表示されます。

1. ワークスペース管理者が **自動化のためにLinearを接続** をクリックします
2. 上と同じように、ブラウザーで Linear ワークスペースに対してアプリを承認します

その後、行には「_あなたの Linear ワークスペース_に接続済み」と表示されます。接続や切断が
できるのはワークスペース管理者だけです。

エージェントのサンドボックスに Linear の資格情報が置かれることはありません。エージェントは
Control Center 自身のツールでチケットを書き込み、それらのツールがまず**外部トラッカーへの
書き込み**のルールに問い合わせます。

## 独自の Linear アプリケーションを登録する

**自分のアプリを使う** を選んだ場合は、独自のアプリケーションを使います。サーバー自身の
アプリケーションが適用されるのはその場合だけです。Control Center のものまたはカスタムの
Connect を使う場合、Connect が Linear を含むすべてのレーンを担当し、サーバーのアプリケーション
とサービス API キーは切り替えて戻すまで保存されたまま使われません。ワークスペース自身の
アプリケーション（[下記](#ワークスペースに独自の-linear-アプリを設定する)）は、すべてのモードで引き続き適用されます。

1. [linear.app/settings/api/applications/new](https://linear.app/settings/api/applications/new)
   で OAuth アプリケーションを作成します
2. **設定 → サーバー → シングルサインオン → プロバイダーアプリ → Linear** の
   **コールバックURL** に表示される 2 つのコールバック URL を、そのまま両方追加します:
   `<server origin>/oauth/linear/callback` と
   `<server origin>/oauth/linear_app/callback`
3. **クライアントID** を Linear ブロックに貼り付けます

クライアントシークレットはありません。サーバーは PKCE でサインインします。Linear の
リフレッシュトークンは 30 日間使われないと失効するため、サーバーは 20 日より古いすべての
Linear サインインを 1 日 1 回更新します。

同じブロックには、任意で **サービスAPIキー** を設定できます。これは、Linear 自動化を接続して
いないワークスペースで自動化に使う、サーバー自身の Linear 資格情報です。**設定** に保存するか、
サーバーの `.env` ファイルに `LINEAR_API_KEY` として置いてください。`LINEAR_API_KEY` が
プロセス環境にエクスポートされていると、サーバーは起動を拒否します。

## ワークスペースに独自の Linear アプリを設定する

ワークスペースは、サーバーのものではなく独自のアプリケーションを使って Linear にサインインできます。
設定できるのはワークスペースの管理者またはオーナーだけです。

1. 上記の手順のとおりに Linear の OAuth アプリケーションを作成します
2. **設定 → ワークスペース → 全般 → プロバイダーアプリ** に進み、**Linear** を開きます
3. **このワークスペースのアプリを使う** を選びます
4. その行の **コールバックURL** に表示される 2 つのコールバック URL を、そのまま両方とも Linear
   アプリケーションに追加します
5. その **クライアントID** を貼り付けます。任意で、このワークスペースの自動化用の **サービスAPIキー**
   も貼り付けられます

ワークスペースのアプリケーションは、サーバーがサインインさせる方法にかかわらず、このワークスペース内の
すべての Linear サインインと自動化のリクエストに応答します。サーバーのアプリケーションや Connect に
フォールバックすることは決してありません。クライアント ID が設定されるまで、ワークスペースでは Linear が
オフになり、その行に不足している項目が表示されます。そのサービス API キーはここでのみ使われます。
キーがない場合、同期には **自動化のためにLinearを接続** が必要です。

サーバーのアプリケーションとワークスペースのアプリケーションを切り替えたり、ワークスペースのクライアント
ID を変更したりすると、このワークスペースのすべての人が Linear からサインアウトされ、その自動化は
切断されます。新しいアプリケーションで改めてサインインします。**このサーバーのアプリを使う** を選ぶと、
ワークスペースの保存済みフィールドが削除されます。シークレットは書き込み専用で、行には保存されているか
どうかだけが表示されます。サーバー上の他のワークスペースは影響を受けません。

## トラブルシューティング

### Linear の行に、サインインが設定されていないと表示される

サーバーには独自の Linear アプリケーションも Connect もありません。サーバー所有者が
**設定 → サーバー → シングルサインオン** でどちらかを選びます。ワークスペースが独自の
アプリケーションを使っている場合は、代わりに行の設定が完了していないと表示されます。
ワークスペース管理者が **設定 → ワークスペース → 全般 → プロバイダーアプリ** で
クライアント ID を追加します。

### チケット同期が認証エラーで失敗する

ワークスペースに Linear 自動化が接続されておらず、サーバーにもサービス API キーがないため、
同期に使う資格情報がありません。ワークスペース管理者が **自動化のためにLinearを接続**
をクリックします。

### 自動化を接続すると、その Linear ワークスペースは別の場所に接続されていると表示される

その Linear ワークスペースの Control Center アプリは、すでに別の Control Center サーバーに
接続されています。
