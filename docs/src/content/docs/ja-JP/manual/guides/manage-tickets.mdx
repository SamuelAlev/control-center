このガイドでは、チケットの作成と管理の方法を説明します。

## チケットを作成する

### UI から

1. ワークスペースのサイドバーで**チケット**をクリックします。
2. **新規チケット**を押します。
3. 次の項目を入力します:
   - **タイトル** — 短い要約。唯一の必須フィールドです。
   - **説明** — Markdown。書式設定ツールバーが付いています。
   - **ステータス** — **未着手**（既定）または**バックログ**。着手済みの状態と
     終端の状態には、作成時ではなくライフサイクルを通じて到達します。
   - **優先度** — なし、緊急、高、中、低。
   - **担当者** — 自分自身、またはワークスペース内の任意のエージェント。
   - **プロジェクト** — 任意のグループ化。
4. **作成**を押します。または、先に**続けて作成**をオンにすると、ダイアログが
   開いたままになり、続けて入力できます。

ダイアログにプロバイダーのピッカーはありません。チケットは、ワークスペースで
有効なチケットプロバイダーに対して作成されます。

### エージェントから

スペース内のエージェントに依頼します:

> 遅い回線でのログインタイムアウト問題を修正するチケットを作成してください。

エージェントは `create_ticket` MCP ツールを呼び出します。このツールの優先度は
名前ではなく**整数**です:

```
create_ticket(
  workspace_id: "...",
  title: "Fix login timeout on slow connections",
  description: "...",
  priority: 2
)
```

| 値  | 優先度 |
| --- | ------ |
| `0` | なし   |
| `1` | 緊急   |
| `2` | 高     |
| `3` | 中     |
| `4` | 低     |

必須なのは `workspace_id` と `title` だけです。`description`、`priority`、
`assignee`（エージェント id）、`team_id` は任意です。このツールはベンダー同期の
書き込みとして分類され、実行前に承認を求めます。

## チケットのステータスを更新する

チケットは次のライフサイクルに従います:

```
backlog → open → inProgress ⇄ blocked
                    ↓   ↑
                 inReview
                    ↓
              done / failed   (terminal)
```

`done`、`failed`、`cancelled` は終端です。`cancelled` には、終端以外の任意の
ステータスから到達できます。`done` と `failed` には `inProgress` または
`inReview` から到達できます。また `open` は `blocked` へ直接移動することも
できます。UI のステータスピッカーには、`failed` を除くすべてのステータスが
並びます — エージェントはそれを `fail_ticket` で設定します。

変更するには、次のいずれかを使います:

- チケットのプロパティパネルにある**ステータス**行、
- リスト内のチケットの右クリックメニューにある**ステータス**サブメニュー、
- チケットを複数選択した後のフローティングバーにある**ステータス**チップ。

:::note[ライフサイクルグラフが縛るのはエージェントであり、あなたではありません]
UI から行われるすべてのステータス変更は、グラフを完全に迂回して強制適用
されます — ピッカーに並ぶ任意のステータスへチケットを移動でき、`done`、
`failed`、`cancelled` のチケットを再び開くこともできます。ピッカーは `failed`
を移動先として提示しません。上の図が統制するのはエージェントと自動化です。
MCP ツールやリコンサイラーが試みた不正な遷移は、適用されず、ログに記録されて
無視されます。
:::

ステータスの変更は、パイプラインをトリガーできるドメインイベント
（`TicketStatusChanged`、`TicketCompleted` など）を発行します。
[パイプライントリガーを設定](/ja-JP/マニュアル/ハウツーガイド/パイプライントリガー/)
を参照してください。

## チケットを割り当てる

1. チケットを開きます。
2. プロパティパネルで**担当者**を設定します — 自分自身、別のワークスペース
   メンバー、またはエージェントです。

:::caution[割り当てても作業は何も始まりません]
割り当ては所有権を記録するだけで、それ以外は何もしません。スペースを作成せず、
ステータスも変更せず、エージェントもディスパッチしません — `TicketAssigned` は
ディスパッチャーを一切伴わない、純粋な監査シグナルです。エージェントに作業させる
には、スペース内でそのエージェントにメッセージを送ります
（[エージェントとチャット](/ja-JP/マニュアル/ハウツーガイド/エージェントとチャット/)
を参照）。

唯一の例外は、`TicketAssigned` がパイプライントリガーを接続できるイベント種別で
あることです。そのため、独自のテンプレートが割り当てに反応できます。
:::

## ラベルを追加する

ラベルは、単一のチケットからではなく、チケットリストから一括で適用します —
プロパティパネルにラベルの操作はありません。

1. チケットリストの行にカーソルを合わせ、そのチェックボックスをオンにします。
   必要な数だけオンにします。何かが選択されるとフローティングバーが表示されます。
2. そのバーで**ラベル**チップを開きます。
3. ラベルを選びます。選択したすべてのチケットのうち、そのラベルを持たないものに
   追加されます。既存のラベルが消えることはありません。**ラベルをクリア**は
   すべてのラベルを削除します。ピッカーには、ワークスペース内のチケットにすでに
   付いているラベルが並びます。エージェントは `update_ticket` または
   `tickets.patch` を通じて新しい名前を追加できます。

## チケットをリンクする

関連は、プロパティパネルのチケットの**関連**カード、またはリストの右クリック
メニューの**関連付ける**にあります。

1. チケットを開き、**関連**カードを見つけます。
2. その追加コントロールを押し、関連の種類を選びます:

| 関連                      | 意味                                               |
| ------------------------- | -------------------------------------------------- |
| **…のサブイシュー**       | このチケットの親はもう一方のチケットです           |
| **…の親**                 | もう一方のチケットはこのチケットの子です           |
| **…にブロックされている** | このチケットはもう一方によってブロックされています |
| **…をブロック中**         | このチケットはもう一方をブロックしています         |
| **…に関連**               | 対称であり、方向は含みません                       |
| **…の重複**               | このチケットはもう一方の重複です                   |

3. 対象のチケットを選びます。

**重複先**はカードには表示されますが、ピッカーには表示されません — これは
**…の重複**の逆であり、もう一方のチケットから設定します。一覧に表示される各関連は
クリックするとリンクされたチケットが開き、ホバーすると削除できます。

親とサブイシューの関連は、リンク行としてではなくチケット自体に保存されるため、
親を削除するとその子にカスケードします（後述）が、ブロックと関連のリンクは
カスケードしません。

## コラボレーターを追加する

コラボレーターはチケット上の名簿です — 誰が、どの立場で関わっているかです。

1. チケットを開きます。
2. **コラボレーターを追加**カードにある人物追加のコントロールを押します。
3. エージェントを選びます。

3 つのロールは**担当者**、**コラボレーター**（既定）、**レビュアー**です。
UI のピッカーにはワークスペースのエージェントだけが並び、常に既定のロールを
書き込みます。人間は行として表示されることはありますが、このメニューには並び
ません。MCP の `add_ticket_collaborator` ツールは `role` を受け取ります。

コラボレーターを追加すると行が書き込まれますが、ドメインイベントは発行されず、
スペースへのアクセス権も付与しません。エージェントを会話に参加させるには、
代わりにスペースのヘッダーから参加者として追加します —
[スペース](/ja-JP/マニュアル/ハウツーガイド/スペース/)を参照してください。

## チケットを削除する

プロパティパネルの下部にある**チケットを削除**、右クリックメニュー、または複数
選択後のフローティングバーの削除アクションを使います。

:::caution[削除はローカルに限られます]
外部トラッカーから取り込まれたチケットは、そちらでは削除されません — どの
プロバイダーも対応していないため、次回の同期で再び現れることがあります。削除は
カスケードもします。チケットのコラボレーターと子チケットも一緒に削除されます。
:::
