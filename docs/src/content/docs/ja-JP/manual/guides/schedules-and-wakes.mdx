エージェントは待っている間、スリープもポーリングもしません。エージェント自身、またはあなたが、**起動予約**を設定します。起動予約とは、会話でエージェントの実行を、ある時刻に、または何かが起きたときに開始または継続する、永続的な要求です。誰かが入力せずにサーバーが開始する実行はすべて、起動予約として始まります。ゴールの次のセグメント、スケジュール、監視、別のエージェントからの返信、委任した作業の完了、利用上限の解除、再起動後に残った作業がそれに当たります。起動予約はワークスペースのデータベースに保存されるため、再起動後も残ります。

## エージェントを自分でスケジュールする

会話の入力欄に次のいずれかを入力します:

```text
/loop every 30m --days 3 check the deploy and fix what broke
/loop keep the flaky tests green
/schedule in 2h look at the overnight benchmark
/schedule at 09:00 summarize what changed overnight
/schedule cron "0 9 * * 1-5" --max 20 triage new tickets
```

| コマンド | 動作 |
| --- | --- |
| `/loop every <interval> <prompt>` | プロンプトでエージェントを今すぐ起動し、その後は間隔ごとに起動します（間隔は少なくとも60秒） |
| `/loop <prompt>` | 自分でペースを決めるループです。エージェントを今すぐ起動し、実行が終わるたびに、エージェント自身が次の遅延を1分から60分の間で選びます（既定は20分）。 |
| `/schedule in <duration> <prompt>` | 指定した遅延の後に、エージェントを1回起動します |
| `/schedule at <HH:MM or ISO time> <prompt>` | エージェントを1回起動します。`HH:MM` はワークスペースのタイムゾーンで次にその時刻が来るときを指します。オフセットのない ISO 時刻は UTC として扱われます |
| `/schedule cron "<expression>" <prompt>` | ワークスペースのタイムゾーンで読まれる5フィールドの cron で、エージェントを起動します。引用符は省略できます |

- `--max <N>` は実行回数を制限し、`--days <N>` はその日数の後にスケジュールを終了します（既定は30日、最大365日）。`--budget <dollars>` はスケジュール全体で使える金額を制限します（指定がなければワークスペースの既定値で、初期値は50ドルです）。
- `/loop` は最初の実行をすぐに行います。`/schedule` は指定した時刻を待ちます。
- 期間には `s`、`m`、`h`、`d` を使います。例えば `90s`、`20m`、`1h30m` などです。
- これらのコマンドは、あなた自身が入力したメッセージでのみ読み取られます。

コンポーザーがその書き方を手伝います。`/loop` や `/schedule` のあとにスペースを入力すると、候補リストに発火するタイミングが表示され、入力に応じて絞り込まれます。時刻のあとに `--` と入力すると上限を指定できます。Enter または Tab で候補の行を選ぶと、何も送信されません。すると、テキストの上の行にコマンドの内容が表示されます。いつ発火するか、いつ終了するか、まだ不足しているものは何か、が分かります。読み取れないコマンドで Enter を押すと、その行に問題の内容が表示され、ドラフトは残ります。

**設定 → ワークスペース → スケジュール**の下の**新しいスケジュール**からスケジュールを作成することもできます。スペース、会話、エージェントを選び、いつ起動するか、各実行が何から始まるか、終了、実行回数の上限、コストの上限を指定します。**エージェントが取り込み中の場合**では、その起動を飛ばすか、エージェントが空くまで待つかを選びます。**実行ごと**では、実行を開始するか、メモ付きの通知だけを送るかを選びます。

## エージェントが設定するもの

エージェントは、同じ目的と監視のために `wake_me` ツールを使います:

| 監視 | 発火するとき |
| --- | --- |
| `on:pr_checks` | スペースのプルリクエストのチェックが完了したとき |
| `on:pr_review` | スペースのプルリクエストにレビューまたは返信が付いたとき |
| `on:pr_merged` | スペースのプルリクエストがマージされたとき |
| `on:environment` | スペースの環境のタスクが終了したとき、または環境が準備完了になったとき |
| `on:ticket:<id>` | チケットが確定したとき |
| `on:pipeline_run:<id>` | パイプラインの実行が終了したとき |

- プルリクエストの監視は、スペース自身のプルリクエスト、または指定した1件のプルリクエスト（`on:pr_checks:acme/shop-ui#12`）を対象とします。監視する人が読めないものへの監視は拒否されます。
- エージェント自身の操作では、そのエージェントの監視は発火しません。エージェントが作業中に届いたイベントは失われず、実行が終わるまで待ち、その後のイベントは同じ起動予約にまとめられます。
- エージェントのスケジュールには、実行回数の上限か終了日が必要です。既定では7日後に終了し、最大30日です。監視は既定で10回実行されます。
- エージェントが、自身のスケジュールによって開始された実行の中で設定するスケジュールは、最初のスケジュールの終了、実行回数の上限、コストの上限を共有します。そのため、エージェントのスケジュールのチェーンが最初のものより長く続くことはありません。最初のスケジュールを削除するとチェーン全体が終了し、一時停止するとそのスケジュールだけが一時停止します。チェーンが他のエージェントを通じて開始した実行は、同じコスト上限に計上されます。あなたが作成したスケジュールはチェーンを開始しません。エージェントが自分の実行で設定するものは、あなたのメッセージの後に設定されるものと同じように制限されます。
- エージェントは `list_wakes` で待機中のものを一覧にし、自分で設定した起動予約を `cancel_wake` でキャンセルします。あなたが設定したものはキャンセルできません。

## 待機中のものを確認する

**コンポーザーの上。** 会話内でエージェントを待っている起動予約があると、その一覧が表示されます: **待機中の起動予約 N件**。各起動予約の発生元（**ゴール**、**スケジュール**、**監視**、**エージェントからの返信**、**上限のリセット**、**復旧**、…）、起動予定時刻、保留の理由が表示されます。

| ボタン | 動作 | 実行できるユーザー |
| --- | --- | --- |
| **今すぐ配信** | 保留中の起動予約を直ちに配信します | 起動予約の対象となる人だけ |
| **再開** | 保留中の起動予約を解放します | 起動予約の対象となる人だけ |
| **起動予約をキャンセル** | キャンセルします | スペースへのアクセス権を持つ人 |

配信されなかった起動予約は、その理由を示す行を1つ会話に残します。例えば **エージェントは一時停止中です。** や **予算により実行がブロックされています。** のような行です。

**スケジュールページ。** **設定 → ワークスペース → スケジュール**で、表示できるすべてのスケジュールと監視が状態別に一覧表示されます。cron スケジュールには、あなたのタイムゾーンでの次の3回の時刻が表示されます。1つ開くと、そのメモ、所有者、次の発火、実行、スキップ、支出、終了、そして**最近の起動予約と実行**が確認できます。各スケジュールには固有のアドレス（`/workspaces/<workspace>/settings/workspace/schedules/<id>`）があります。

| 操作 | 実行できるユーザー |
| --- | --- |
| **一時停止**、**終了** | スペースへのアクセス権を持つ人 |
| **再開**、**延長** | その所有者だけ（人が関与せずにエージェントが作成したスケジュールは、ワークスペース管理者） |

スケジュールの所有者以外の人がそれを一時停止すると、会話には、その人の名前を示す行が表示されます。

スマートフォンでは、ゴールの画面にある**繰り返す**で、一定の分数または時間ごと（またはペースを自分で決める形式）に繰り返すプロンプトを、コストの上限と終了付きで開始できます。**スケジュール**画面では、スケジュールの一時停止、再開、削除ができます。会話の進捗ビューには、待機中のものが表示されます。利用上限での一時停止（**今すぐ再開**、**キャンセル**）や、サーバー停止後に残った作業も含まれます。

## スケジュールの実行の仕方

- スケジュールや監視の各実行は5ドル、またはスケジュールに残っている額のうち少ない方が上限で、スケジュールはそのコストの上限に達すると停止します。
- 時計が進む際に飛ばされる時刻に当たる cron の時刻は、その日の1時間後に実行されます（02:30 は 03:30 に実行されます）。時計が戻る際に繰り返される時刻に当たる時刻は、1回だけ実行されます。
- スケジュールの実行が、すでに進行中の実行に合流することはありません。時刻指定のスケジュールが発火したときにエージェントが取り込み中の場合、その発火は黙って飛ばされます。ただし、エージェントが空くまで待つ設定の場合は除きます。
- スケジュールや監視が開始した実行で、問題なく終わったものは、誰かに言及していない限り通知しません。スケジュールが終了すると、通知ベルに理由が表示されます（**実行回数の上限に達しました。**、**終了日に達しました。**、…）。音は鳴りません。
- 1つの会話で起動予約から始まる実行は1時間に最大30回、ワークスペース全体では300回までです。
- スケジュールが代わって動く相手の人がワークスペースから退出すると、そのスケジュールは終了します。その人のために動いていた他のものもすべて停止します。待機中の起動予約は取り消され、キューに入ったメッセージと保留中のメッセージは削除され、実行中のエージェントは停止します。

## 停止、再起動、利用上限

- **停止。** エージェントの実行で**停止**を押すと、その保留中の起動予約（ゴールに属さないもの）と、そのエージェント宛てにあなたがキューに入れたメッセージが保留されます。それらは**再開**または**保留中のメッセージを送信**を待ちます。保留中のメッセージは、それぞれの人が自分で送ります。他の人のものを送ることはありません。
- **サーバーの再起動。** 起動予約とスケジュールは再起動後も残ります。起動予約によって開始された実行は、再起動後に再開されます（最大3回まで試行）。あなたが自分で開始した実行は、自動では再実行されません。その場合、保留中の**復旧**の起動予約が残り、あなたが**再開**を押すと続きます。サーバーの停止中に実行されるはずだった時刻を逃した時刻指定のスケジュールは、短い猶予期間（間隔の半分、最大10分。一回限りのものは24時間）内に限り遅れて実行されます。それ以外の場合は、スキップが1回記録されます: **サーバーの停止中に逃しました。**
- **プロバイダーの利用上限。** 実行がプロバイダーの利用上限で停止し、プロバイダーがリセット時刻を示した場合（7日以内）、その実行は一時停止します。サーバーが開始した実行（ゴールのセグメントやスケジュールの実行など）は、リセットから30秒後に自動的に再開します。あなたが開始した実行は、あなたの操作を待ちます。会話には**一時停止中**（プロバイダーの**利用上限。上限のリセット時刻**）と表示され、その時刻が示されます。**再開**（あなたのみ）と**キャンセル**（スペースの誰でも）が使えます。**再開**を押すと、上限のリセット後に実行が続きます。再開されない一時停止は、リセットから7日後に期限切れになります。利用上限で入力したメッセージは、再開された実行に送られます。実行がリセットを待たなかった場合、または一時停止がキャンセルされたり期限切れになったりした場合は、代わりに**保留中のメッセージを送信**のもとで保留されます。他の人がキューに入れたメッセージは、すぐにその人のために保留されます。スケジュールの次の発火は、一時停止中の実行が再開するまで待ちます。ACPエージェントはリセット時刻を報告しないため、その実行は待ちません。

## ワークスペースの上限

ワークスペース管理者は、同じページの一覧の下で上限を設定します:

- **スケジュールの上限**: 1つのエージェントが1つの会話で保持できる（有効または一時停止中の）スケジュールの数（10件）、ワークスペース内（50件）、ワークスペース全体（500件）。スケジュールの既定のコストの上限（50ドル）。cron スケジュールと日次ダイジェストが使うタイムゾーン（初期値はUTC）。
- **誰も回答しない場合**: サーバーが開始した実行が担当者の回答や承認を待つ時間（既定では72時間、1時間から7日まで）。その後、承認は却下、質問は未回答として扱われます（その後、同じ実行が尋ねる他の内容はすぐに拒否されます）。また、ゴール、スケジュール、サーバーが開始したその他の実行であなたを待っているものの日次ダイジェストの時刻も設定します。
