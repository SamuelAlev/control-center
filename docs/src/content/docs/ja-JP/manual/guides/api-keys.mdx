このガイドでは、Control Center が使用する各認証情報がどこに保存されるか、そしてその変更方法を説明します。

**入力しているマシンには何も保存されません。** すべての認証情報はサーバー上にあり、あるリクエストにどの認証情報が応答するかは、その背後に人間がいるかどうかによって決まります。

| 認証情報                             | 保存場所                                                  | 使用者                                                          |
| ------------------------------------ | --------------------------------------------------------- | --------------------------------------------------------------- |
| 自分のコードホスト / チケットのサインイン | サーバーの 0600 シークレットファイル。自分のユーザー id をキーとする | 自分が行うことすべて: PR 画面、レビュー、マージ、自分の Linear 操作 |
| サーバーのプロバイダーアプリ         | 同じファイル。シークレット以外は `server_settings`        | 人々のサインインと、エージェント・パイプライン・ポーリング用の 1 リポジトリ限定トークン |
| Connect のインストールキー           | 同じファイル（`connect_install_key`）                     | Control Center Connect に対してこのサーバーを識別する            |
| モデルプロバイダーのキーと OAuth トークン | サーバー自身の認証情報ストア                             | インストール上のすべてのワークスペースで使用される組み込みアダプター |
| Slack ボットの認証情報               | サーバー上の `<dataDir>/<workspaceId>/chat_credentials/` | そのワークスペースのチャットブリッジ: 自分のアプリのトークン、または共有アプリの封印されたグラント |
| 外部 CLI の認証情報                  | その CLI が使用する任意の場所                            | サーバーホスト上の Claude Code                                  |

## GitHub: 自分のサインインと、1 リポジトリ限定のトークン

- **自分の認証情報**。**GitHubにサインイン** から取得します。*自分の代理*で行われるすべてのリクエストがこれを使用するため、自分のために投稿されたレビューには自分の名前が付きます。他のメンバーはこれを使うことができず、各自が自分でサインインします。貼り付ける GitHub トークンはありません
- **誰も操作していない作業**（エージェント、パイプライン、ポーリング、ボットの返信）は、サーバーの GitHub App から、または Control Center Connect を通じて発行される、一度に 1 つのリポジトリだけを対象とするトークンを受け取ります。このトークンは、責任を負うメンバーがそこでできることに制限されます。自分のサインインがそのまま渡されることはありません

自分の認証情報は、**設定 → ワークスペース → プロフィールと識別情報**の**コードホスティング**カードで設定します。サーバーのアプリは、**設定 → サーバー → シングルサインオン**の**プロバイダーアプリ**で設定します。詳しくは [GitHub インテグレーションを設定](/ja-JP/マニュアル/ハウツーガイド/github-インテグレーション/) と [GitHub App を作成](/ja-JP/マニュアル/ハウツーガイド/github-app/) を参照してください。

GitLab と Bitbucket は引き続き個人トークンを貼り付け、同じ方法で保存されます。詳しくは [コードホストを接続](/ja-JP/マニュアル/ハウツーガイド/コードホスト接続/) を参照してください。

:::note[URL 専用の画面もあります]
`/workspaces/<workspaceId>/api-keys` は、オンボーディングの最初のステップと同じ 2 つのカードを表示します。**UI のどこにもナビゲーションの項目はありません**。URL を入力した場合にのみ到達できます。代わりに 設定 → ワークスペース → プロフィールと識別情報 を使用してください。
:::

## モデルプロバイダーのキーを設定する

組み込みアダプターはプロバイダーの認証を自身で行い、それらの認証情報はサーバー上に保存されます。

1. **設定 → サーバー → モデルプロバイダー**に移動します
2. **プロバイダーとモデル**までスクロールします
3. プロバイダーを接続します — OpenAI、Codex、Cursor、Kimi Code はブラウザー OAuth、Anthropic とその他は API キーです

完全なリストとカスタムエンドポイントの追加方法については、[アダプターとモデルを管理](/ja-JP/マニュアル/ハウツーガイド/アダプター/) を参照してください。

これらの認証情報は**ホスト全体で共通**です。1 つのキーがインストール上のすべてのワークスペースで使われます。OAuth トークンは有効期限が切れる前に更新されます。

外部アダプター CLI は、サーバーホスト上の独自の設定の中に、独自の認証情報を保持します — Control Center はそれらを管理しません。Claude Code は、`cc_server` が実行されているマシン上で、そのドキュメントに記載されている方法で認証してください。

アダプターごとの**環境変数**ダイアログは、それらのいずれかのキーを入れる場所のように見えますが、そうではありません。これは自分のデバイスに書き込むのに対し、サーバーは自身のコピーを読み取り、両者をつなぐものはありません。詳しくは [アダプターとモデルを管理](/ja-JP/マニュアル/ハウツーガイド/アダプター/) を参照してください。

## チケッティングベンダーを接続する

**設定 → ワークスペース → 全般**の**チケット管理**カードは、1 つの決定の両方の側面を扱います。チケットがどのベンダーにあるか、そしてベンダーと話すときに Control Center が誰として振る舞うかです。**ローカル**を選ぶと Linear の行は非表示になります — ローカルのチケットはこのサーバー自身のデータベースにあり、認証する対象がないためです。

Linear にはサインインが 2 つあり、貼り付けるキーはありません。**Linear** は自分のもので、自分が行うことに使われます。**Linearの自動化** はワークスペースの Control Center アプリで、管理者が接続し、チケット同期、パイプライン、エージェントに使われます。サーバーは、自動化を接続していないワークスペースのために **サービスAPIキー**（**プロバイダーアプリ**）を保持している場合もあります。エージェントのサンドボックスにチケットの認証情報が注入されることはありません。エージェントは Control Center のツールでチケットを書き込み、それらのツールが**外部トラッカーへの書き込み**のルールに問い合わせます。詳しくは [Linear インテグレーションを設定](/ja-JP/マニュアル/ハウツーガイド/linear-インテグレーション/) を参照してください。

## ローテーションまたは失効

- **自分の GitHub サインイン**: **切断**を押してから、もう一度 **GitHubにサインイン** します。切断すると、サーバーが自分の代わりに発行したすべてのトークンも破棄されます
- **GitLab または Bitbucket のトークン**: **トークンを更新**を押して新しいトークンを貼り付け、古いトークンをコードホスト側で失効させます
- **サーバーのアプリ**: アプリのプロバイダーページで新しい秘密鍵またはクライアントシークレットを生成し、**プロバイダーアプリ**に貼り付けて**テスト**を押します
- **Connect のインストールキー**: **Control Center Connect** カードの **鍵を更新**、または `cc_server connect rotate-key --yes` を使います。Connect を通じてサインインした全員が再度サインインします。詳しくは [Control Center Connect](/ja-JP/マニュアル/リファレンス/connect/) を参照してください
- **モデルプロバイダー**: その行でサインアウトする（OAuth）かキーを削除してから、もう一度接続します
- **Slack**: 自分のアプリの場合は、接続ダイアログでトークンを貼り直します。共有の Control Center アプリにはローテーションするトークンがありません。そのボットトークンは Connect を通じて更新され、**切断** するとトークンが失効し、ボットが Slack からアンインストールされます。詳しくは [Slack インテグレーションを設定](/ja-JP/マニュアル/ハウツーガイド/slack-インテグレーション/) を参照してください

## トラブルシューティング

### GitLab または Bitbucket のトークンが `curl` では機能するのに、ここでは機能しない

**コードホスティング**の行のサブタイトルを確認します。「環境変数から」と表示されている場合、応答している認証情報はサーバーのものであり、自分のものではありません — 自分の認証情報は保存されていません。

### GitLab または Bitbucket のトークンは受け入れられるのに、後続のリクエストが失敗する

トークンは保存された状態のまま検証されるため、その行には背後にあるアカウント名が表示されます — ただしアカウントのみで、スコープは表示されません。スコープが足りないトークンは接続には成功しますが、個々のリクエストで失敗します。コードホスト側でスコープと有効期限を確認してください。

### プロバイダーに、このサーバーではサインインが設定されていないと表示される

サーバーには、そのプロバイダー用の独自アプリも Control Center Connect もありません。サーバー所有者が **設定 → サーバー → シングルサインオン** でどちらかを選びます。
