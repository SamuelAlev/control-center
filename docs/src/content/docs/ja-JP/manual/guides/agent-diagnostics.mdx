このガイドでは、エージェントが実行を生み出さない理由を突き止める方法を説明します。

上から順にたどります。まずエージェント自身の実行、次にそのバックエンド、次にサーバー、最後にホストです。

## 1. エージェントの実行履歴を確認する

**設定 → ワークスペース → エージェント** → エージェントを選択 → **ログ**。

各実行には、ステータスバッジ、所要時間（進行中は「Running…」）、開始時刻と完了時刻、PID、使用したアダプターが表示されます。**表示**を押すと、その実行の生のイベントストリームが開きます。**停止**は実行中のプロセスを強制終了し、その実行を「Killed by user」として記録します。ヘッダーの**実行中を強制終了**は、そのエージェントの進行中のすべての実行に対して同じことを行います。

次のように読み解きます:

- **実行がまったくない** — ディスパッチが発生していません。メッセージ入力欄でのメンションは、`@` と単語文字（英字、数字、アンダースコア）です。解決はエージェント名に対する完全一致または前方一致なので、`@code-reviewer` は `code` として解析され、`code-reviewer` という名前のエージェントを依然として起動できます。名前に空白が含まれる場合、それを 1 つのトークンとしてメンションすることはできません。その場合は手順 2 に進みます。
- **すぐにエラーで終了した実行** — **表示**を開きます。バックエンドの起動失敗は、ここにプロセスエラーとして現れます。
- **「Running…」のまま止まっている実行** — 停止してから、設定タブでそのエージェントの**無応答タイムアウト**を確認します。タイムアウトが未設定の場合、モードごとのデフォルトが使われます。
- **完了したが役立つ出力がない実行** — 宣言された成果物を出さずに終了した実行では、実行ログのステータスは `completed` のままです。正直なシグナルはバッジではなく、要約テキストです。

ログタブにはコストが表示されません。支出については、**オブザーバビリティ → インサイト**にあるエージェントごとの表を使用します。

## 2. エージェントのバックエンドを確認する

**設定 → サーバー → モデルプロバイダー**（`/settings/server/providers`）。

**検出されたランナー**の一覧には、各アダプターとそのプローブ結果 — インストール済みのバージョン、「確認中…」、「見つかりません」のいずれか — に加えて、解決されたパスと、見つかった CLI のケイパビリティチップが表示されます。再プローブするには、ページヘッダーの**更新**をクリックします。

プローブは、今見ているマシンではなく、`cc_server` をホストしているマシン上で実行されます。Web クライアントやペアリング済みデバイスを使っている場合、「見つかりません」はサーバーホストにその CLI がないことを意味します。

確認すべきことは 2 つあります:

- **エージェントにアダプターが設定されているか。** アダプターが空のエージェントは **Control Center (built-in)** にディスパッチされ、実行ログには `cc-harness` が記録されるため、トランスクリプトに何が実行されたかが示されます。モデルもない場合、組み込みループは Anthropic にデフォルトを問い合わせます — Anthropic アカウントを接続していなければ、これは `No credential for provider "anthropic"` で失敗します。シードされるスペシャリストはアダプターなしで出荷されます。
- **組み込みアダプターにモデルがあるか。** そのモデル一覧は、同じページの下方で接続されているプロバイダーからリアルタイムに取得されるため、資格情報が保存されていないプロバイダーはモデルを 1 つも提供しません。

アダプターのカタログ自体は固定です — 新しいアダプターを登録する方法はありません。ここでアダプターごとに変更できるのは、その起動引数と環境変数です。資格情報が解決されるとき、アダプターごとの環境変数の上書きが、接続済みのプロバイダーアカウントを黙って打ち負かす点に注意してください。

## 3. サーバーを確認する

**設定 → サーバー → 接続とステータス**（`/settings/server/connection`）には、このクライアントがどのサーバーと通信しているか、そしてそのサーバーが何を報告しているかが表示されます。

ヘッドレスサーバーの場合、`GET /healthz` はクライアントなしで同じ情報を提供します。これは設計上、認証不要で CORS もオープンです:

```
curl http://localhost:9030/healthz
```

返されるのは、サーバーのステータス、稼働時間（秒）、ライブ接続数、バインドされたポート、ビルドバージョンと git SHA、ワークスペーススキーマバージョン、RPC カタログバージョン、サーバー ID、名前とアイデンティティフィンガープリント、バインドが安全でないかどうか、そして `watching` / `indexing` / `pending` のカウントを持つ `codeGraph` ブロックです。キャッシュがトラフィックを受けたことがある場合は `caches` ブロックも含まれ、デモサーバーは `demo: true` を追加します。

変更が「テストでは動くがアプリでは動かない」ときに知っておくべきことが 2 つあります:

- デスクトップは、ソースよりも**ビルド済み**の `cc_server` バイナリを優先して起動します。新しい RPC オペレーションや MCP ツールは、バイナリを再ビルドするまで現れず、子プロセスの git SHA がアプリのものと異なる場合、起動時に警告がログに記録されます。
- デスクトップは、20 秒以内に準備完了のバナーを出力しなかった起動済みサーバーを強制終了し、エラー画面に移行します。

## 4. ホストを確認する

**設定 → サーバー → 診断とプライバシー**（`/settings/server/diagnostics`）はホストレベルのページです。ここには次のものがあります:

- **サンドボックス化** — マスタートグル、検出されたバックエンド、インストールのヒント、デフォルトのケイパビリティトグルです。サーバーから取得するのは検出されたバックエンドだけです。後述の注意を参照してください。リセット用のコントロールはありません。
- **セマンティック検索** — オンデバイスの埋め込みモデルのライフサイクル（インストール済み、パーセント付きでダウンロード中、未インストール、インストールエラー）です。インストールされるまで、メモリとコード検索はキーワードのみのままです。
- **システムの動作** — エージェントの実行中にコンピューターをスリープさせないようにします。
- **同期エンジン** — チケット、メッセージング、ノートのストアごとのキルスイッチです。これは完全スナップショット購読へ戻すための緊急脱出ハッチです。変更は新しい購読にのみ影響するため、完全に有効になるのはリロード後です。
- **ログレベル** — 障害を再現する前に引き上げます。
- **プライバシー** — 生の diff 内容をエージェントのモデルへ転送してよいかどうか、およびクラッシュレポートを送信するかどうかです。

:::caution[このセクションが報告するのはホストであり、そのコントロールはクライアント側です]
検出と強制は今や一致しています。検出器がネイティブバックエンドを報告する場所では、そのホスト上のエージェント実行は実際にそれでラップされます。しかし、このセクションで実際に生きているのは検出器だけです。マスタートグル、バックエンドの選択、デフォルトのケイパビリティトグルはお使いのデバイスに保存された設定であり、サーバーはそのどれも読みません — サーバー自身のスイッチは `--sandbox` で（既定は `on`、オプトアウトするには `off`）、「ワークスペースのデフォルトを使用」のままにされたエージェントに対しては、サーバーは自身の保守的なデフォルトへフォールバックします: git push なし、GitHub API なし、チケットキーなし、ネットワークはオンです。

したがって、ここに警告が出たら対処する価値はありますが、それがエージェントの失敗の原因であることは通常ありません。サーバーがどの状態にあるかを確認するには、その起動ログを読みます。ログには、バックエンドの注記を伴う `agent sandbox ON`、インストールのヒントを伴う `no OS-native agent sandbox on this host`、または `agent sandbox DISABLED by --sandbox off` が出力されます。`GET /healthz` にサンドボックスのフィールドはありません。

バックエンドが存在しない場合 — 常に Windows、および `bwrap` と `socat` のない Linux や WSL2 — 実行はサンドボックス化され**ません**。それを制約するのは、会話自身のチェックアウト、それにどの資格情報が発行されるかをゲートするケイパビリティ、アクションガードレール、環境のサニタイズ、そしてそのモードが許可するツールサーフェスです。
:::

## よくある失敗

### 実行が始まらず、アダプターが「見つかりません」と表示する

CLI を**サーバーホストに**インストールし、モデルプロバイダーページで**更新**をクリックします。または、CLI を必要としない組み込みアダプターにエージェントを切り替え、同じページでプロバイダーを接続します。

### エージェントがプッシュもプルリクエストの作成もできない

ゲートとなるのはエージェントのケイパビリティです。**設定 → ワークスペース → エージェント** → そのエージェント → **サンドボックスの権限**を開き、スイッチをオンにして、**git push を許可**と **GitHub API の呼び出しを許可**を有効にします。スイッチを「ワークスペースのデフォルトを使用」のままにすると、エージェントにはこれらのどれも与えられません。

### セマンティック検索が役立つ結果を返さない

**設定 → サーバー → 診断とプライバシー → セマンティック検索**を確認します。埋め込みモデルがインストールされるまで、検索はキーワードのみです。モデルのインストール前に書き込まれた行はバックフィルされないため、その後もキーワードのみのままです。

### サーバーがまったく起動しない

ネイティブライブラリは必須で、劣化モードはありません。dylib が見つからないと、`cc_server` は起動を拒否し、エラーの中で問題のファイルを名指しします。`scripts/natives/build_natives.sh` でネイティブをステージし、サーバーバイナリを再ビルドします。

### アクションが黙って拒否される

承認者が接続されていない `prompt` のガードレール判定は、設計上拒否されます。**設定 → ワークスペース → エージェントの権限**でワークスペースのルールを確認します。
