このガイドでは、セットアップのうち GitHub に固有の部分を扱います。GitHub は対応している 3 つの
コードホストの 1 つです — GitLab や Bitbucket の接続方法と、ワークスペースでこれらを
併用する方法については、[コードホストを接続](/ja-JP/マニュアル/ハウツーガイド/コードホスト接続/)
を参照してください。

## 前提条件

- 作業したいリポジトリにアクセスできる GitHub アカウント
- 人々を GitHub にサインインさせられるサーバー。サーバー自身の GitHub App（
  [GitHub App を作成](/ja-JP/マニュアル/ハウツーガイド/github-app/)を参照）か Control Center
  Connect のどちらかで、サーバー所有者が **設定 → サーバー → シングルサインオン** で選びます

:::note[認証情報はサーバー上にあり、あなたに紐づきます]
入力しているマシン上には何も保存されません。あなたの GitHub サインインは
`cc_server` が保持し、あなたのユーザー id をキーとして管理されます。サインインしたすべてのデバイスが
それを使用します — デスクトップ、ウェブ、スマートフォンです。同じサーバーの別のメンバーはそれを
使うことはできず、その人のサインインはその人自身が行います。
:::

## GitHub にサインインする

GitHub はサインインのみです。貼り付けるトークンはありません。

1. **設定 → ワークスペース → プロフィールと識別情報 → コードホスティング**（またはオンボーディングの
   最初のステップ）に移動します
2. **GitHub** の行で **GitHubにサインイン** をクリックします
3. ブラウザーで GitHub が開きます。アプリを承認します

サインインの完了の仕方は、誰がそれを実行するかによって異なります:

- **サーバー自身のアプリ:** GitHub がブラウザーをサーバーに戻し、ダイアログが自動的にそれを
  検知します。入力するものはありません
- **Control Center Connect:** ブラウザーのページに 8 文字のコードが表示されます。それをダイアログに
  入力するか、`control-center://` リンクを通じてブラウザーに Control Center を開かせ、入力を省きます

チェックポイント: **GitHub** の行に「_your-username_としてサインインしています。」と表示されます。

ダイアログは、自分で開始していないコードやリンクを **ここで開始されたサインインではありません** と
表示して拒否します。誰かからサインインのリンクが送られてきても、続行しないでください。完了すると、
あなたのアカウントがその人のサーバーに接続されてしまいます。

サインインを削除するには **切断** をクリックします。GitHub からサインアウトするか、ワークスペースから
外されると、サーバーがあなたの代わりに発行したすべてのトークンも破棄されます。

## 認証情報が誰の代わりに動くか

- **あなたが行うこと**（PR ページを開く、レビューを投稿する、承認する、マージする）は、すべて
  **あなたの** サインインで実行され、ほかのものは使われません。サインインしていない場合、アプリは
  その旨を伝えてサインインを求めます。ほかの認証情報があなたの代わりになることはありません
- **誰も操作していない作業**（エージェント実行、パイプライン、PR のポーリング、ボットの返信、
  クローン）は、サーバーの GitHub App から、または Connect を通じて発行される、1 つのリポジトリ用の
  トークンを受け取ります。これは責任を負うメンバー（依頼した人、そうでなければワークスペース所有者）が
  そこでできることに制限されます。プッシュできないメンバーの場合、トークンは読み取りに限定されます
- **自動化がプルリクエストを承認することはありません**。承認は人の行為です

## インテグレーションでできること

| 機能             | 仕組み                                                                                                            |
| ------------------- | -------------------------------------------------------------------------------------------------------------- |
| PR 一覧と詳細  | サーバーから、あなた自身のサインインで GitHub REST API を利用                                                    |
| チェック実行          | GitHub Checks API                                                                                          |
| レビューの公開   | あなたのレビューをあなたとして PR に投稿する、ユーザーの操作を必要とするステップ                                     |
| リポジトリの登録   | チェックアウトの `origin` リモートが github.com — または gitlab.com / bitbucket.org — を指していれば受け入れられます          |
| エージェントの GitHub アクセス | 実行の 1 つのリポジトリ用のトークンを `GH_TOKEN` / `GITHUB_TOKEN` として注入します。プッシュは Control Center を通ります |
| 通知ピング  | サーバー側で GitHub の通知受信トレイをポーリングし、「プルリクエストでメンション」と「レビュー依頼」を発生させます |
| ユーザープロフィール       | プロフィールのホバーカードと、作者ごとの PR フィルタリング                                                                |

一部の経路では、よりコストが低い箇所で REST の代わりに GraphQL API を使用します — PR 作成
ピッカーのブランチアクティビティと、レビュー依頼の通知がまだ保留中かどうかを判断する
ライブのレビュー状態です。

## GitHub の障害を監視する

プロバイダーが機能低下しているとき、タイトルバーにステータスチップが表示されます。対象は GitHub、
Claude、OpenAI、Kimi です。**すべてが正常な間は非表示になります** — 表示は障害の存在を
伝えるものであり、その不在を伝えるものではありません。

チップをクリックすると、各プロバイダーの状態と更新ボタンを備えたフライアウトが開きます。
ステータスは 2 分ごとに自動で更新されます。

## エージェントが GitHub でどのように動作するか

- GitHub のワークツリーで作業するエージェントは、そのリポジトリ 1 つだけを対象とするトークンを
  受け取ります。責任を負うメンバーがプッシュできる場合は、コードを読み取ってプルリクエストに
  コメントでき、できない場合は読み取りだけが可能です。プッシュは Control Center を通り、Control Center は
  **リモートへプッシュ** のルールに問い合わせてから、エージェントが決して持たない書き込みトークンで
  プッシュを転送します。[サンドボックスポリシーを設定](/ja-JP/マニュアル/ハウツーガイド/サンドボックスポリシー/)を参照してください
- エージェントのコミットは常に、依頼者の Git ID を作成者とコミッターの両方に使用します。デフォルトでは、`Co-Authored-By: Control Center <hi@usectrl.dev>` トレーラーによって GitHub アカウント `@usectrl` が共同著者として記載されます。**設定 → 自分 → コミットの帰属**で、この記載を自分の ID を変えずにオフにできます。**設定 → ワークスペース → 全般**での上書きが優先され、個人用スイッチはロックされます。Claude Code 自身の帰属表示は常に無効です。コミットの署名には引き続き、別途有効な設定が必要です
- リグで開いたターミナルは、その 1 つのリポジトリに絞り込まれたあなた自身のサインインを受け取るため、
  そこでのプッシュはあなたのものになります
- トークンを発行できない場合（責任を負う人がサインインしていない、アプリが所有者にインストール
  されていない、インストールが一時停止されている）、実行はトークンなしで始まり、その理由が実行メモに
  記録されます。フォールバックの認証情報はありません

## トラブルシューティング

### PR 一覧が空で、GitHub が接続されていないと表示される

このサーバーで GitHub にサインインしていません。**コードホスティング** の下の **GitHubにサインイン**
をクリックしてください。他のコードホストのリポジトリには影響しません。

### GitHub の行に、このサーバーではサインインが設定されていないと表示される

サーバーには独自の GitHub App も Connect もありません。サーバー所有者が **設定 → サーバー →
シングルサインオン** でどちらかを選びます。**自分のGitHubアプリを作成** は約 2 分で完了します。
[GitHub App を作成](/ja-JP/マニュアル/ハウツーガイド/github-app/)を参照してください。

### ダイアログに、コードが一致しないと表示される

ブラウザーに表示されたとおりにコードを入力してください。英数字 8 文字です。誤ったコードを 5 回
入力するとサインインは終了するので、最初からやり直してください。

### サインインで、アプリがインストールされていないと表示される

リポジトリを所有するアカウントに GitHub App のインストールがありません。ワークスペース管理者が
**設定 → ワークスペース → 全般 → GitHubアプリのインストール** からインストールします。Control Center の
共有 App を使う組織では、その組織の管理者が **このサーバーを承認** をクリックする必要がある場合が
あります。[GitHub App を作成](/ja-JP/マニュアル/ハウツーガイド/github-app/#組織に対してこのサーバーを承認する)を参照してください。

### 全員が GitHub に再度サインインしなければならない

サーバー所有者がサーバーの Connect 鍵を更新したか、Connect サーバーを切り替えたか、データ
ディレクトリが別のマシンに復元されました。Connect を通じたサインインは、それを作成したサーバーに
結び付けられています。

### リポジトリの追加が拒否される

登録には次の 3 つすべてが必要です。パスが git ワークツリーの内部にあること、`origin`
リモートがあること、そしてそのリモートが対応しているコードホスト（github.com、
gitlab.com、bitbucket.org）を指していることです。
[ワークスペースにリポジトリを追加](/ja-JP/マニュアル/ハウツーガイド/リポジトリ追加/)を参照してください。

### 集中的に使ったあと、しばらく何も動かなくなる

それはレート制限のサーキットブレーカーです。GitHub はプライマリ制限を、
`x-ratelimit-remaining: 0` とリセット時刻を伴う `403` で通知します。クライアントはそれを見ると、
ウィンドウが経過するまで、ネットワーク呼び出しを行わずに以降のリクエストをローカルで失敗させるため、
リトライの嵐が制限を深刻化させることはありません。一時的な失敗は、
指数バックオフで最大 3 回再試行され、`retry-after` が尊重されます。
