プロジェクトは、共通の目標に向けたチケットをワークスペース単位でまとめたものです。
プロジェクトは Control Center 専用です — Linear のような外部プロバイダーに
同期されることはありません。

## プロジェクトを作成する

1. ワークスペースのサイドバーで**チケット**グループを展開します。ここには
   **すべてのチケット**、アーカイブされていないプロジェクトごとの行、そして
   **新規プロジェクト**が並びます。
2. **新規プロジェクト**をクリックします。
3. **プロジェクト名**、任意の**説明**を入力し、**色**を選択します。
4. **プロジェクトを作成**を押します。

新しいプロジェクトの概要が表示され、プロジェクトは**チケット**の下の
サイドバーの行として表示されます。

## チケットをプロジェクトに追加する

プロジェクトはチケット単位のフィールドで、次の 2 か所のいずれかで設定します:

- チケットを開き、そのプロパティパネルで**プロジェクト**を設定します。
- リスト内のチケットを右クリックし、**プロジェクト**サブメニューを使います。

プロパティパネルのピッカーにも**新規プロジェクト**があるため、その場で作成した
プロジェクトにチケットを登録できます。**プロジェクトなし**はフィールドを
クリアします。

チケットは最大 1 つのプロジェクトに属します。

:::note[プロジェクトは一括操作ではありません]
複数のチケットを選択したときに表示されるフローティングバーが扱うのは、
ステータス、優先度、担当者、ラベル、削除です。プロジェクトのチップはないため、
多数のチケットをまとめて整理するには 1 件ずつ行う必要があります。
:::

プロジェクト側から始めることもできます。プロジェクトの概要にある
**新規チケット**は、チケットを作成してそのプロジェクトに登録します。

## プロジェクトの進捗を確認する

サイドバーの行からプロジェクトを開くか、
`/workspaces/<workspace-id>/projects/<project-id>` に移動します。

概要には、プロジェクトのグリフと名前、ステータスバッジ、説明、および
全体に対する完了数のプログレスバーが表示されます。その下には、プロジェクトの
チケットがステータス別にグループ化されて表示されます。

ほかの集計は行われません — 担当者別の内訳も、優先度の分布もありません。
それらが必要な場合は、代わりにメインのチケットリストをフィルタリングしてください。

## プロジェクトのステータスを変更する

プロジェクトには 3 つの状態があります:

| ステータス       | 意味                     |
| ---------------- | ------------------------ |
| **アクティブ**   | 作業が進行中です         |
| **完了**         | すべての作業が終わっています |
| **アーカイブ済み** | 履歴として参照するための状態です |

プロジェクトヘッダーの**⋯**メニューを使います。ここには**プロジェクトを編集**、
**完了にする**／**アクティブにする**、**アーカイブ**／**復元**、
**プロジェクトを削除**があります。

アーカイブすると、プロジェクトはサイドバーのリストとチケットのピッカーから
非表示になります。これは元に戻せます — **復元**でプロジェクトはアクティブに
戻ります — ただし、アーカイブ中は URL でしかプロジェクトにアクセスできません。

## 自動で作成されるプロジェクト

オーケストレーションを承認すると、プロジェクトが作成され、手動で登録した
ものと並んで、親チケットがその下に登録されます。生成された作業項目は
チケットの行ではなくパイプラインステップであるため、プロジェクトボードには
表示されません。自動化された経路はこれだけです。パイプラインのどのノードも
チケットを作成しないため、パイプラインがプロジェクトを埋めることはありません。
詳しくは[オーケストレーションを実行](/ja-JP/マニュアル/ハウツーガイド/オーケストレーション実行/)
を参照してください。

:::note[プロジェクトはオペレーター用のサーフェスです]
プロジェクトの作成、一覧表示、更新、削除はアプリで行います。エージェントに
プロジェクト用のツールはありません。
