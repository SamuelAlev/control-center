ゴールとは、完了の条件を満たすまでエージェントが取り組み続ける作業です。エージェントは**セグメント**と呼ばれる有限の実行を単位に作業します。サーバーがセグメントを次々に開始し、再起動をまたいで続けます。ゴールが検証されるか、担当者が閉じるか、上限に達するまで続きます。エージェントが完了したと言うだけではゴールは閉じられません。まずサーバーがゴールのチェックを実行し、レビュー担当者が結果を確認します。

## 開始する

会話の入力欄に `/goal` と目的を入力します:

```text
/goal --budget 20 --days 2 --check "make test" make the importer handle files over 2 GB
```

テキストを付けて `/goal` と入力すると、目的のインタビューが開きます。インタビューでは、完了の条件、合格が必要なチェック、境界と停止条件を尋ね、別のチェッカー、各セグメントを新しく開始すること、エージェント自身の質問への回答を選べます。どの手順も省略できます。

| フラグ | 意味 |
| --- | --- |
| `--budget <dollars>` | ゴール全体で使える金額です。既定は50ドルです |
| `--max <N>` | ゴールが取れるセグメントの最大数です。既定では上限はありません |
| `--days <N>` | 期限です。今日から指定した日数後です |
| `--check "<command>"` | ゴールを完了する前に合格しなければならないコマンドです。ワークツリーで実行されます。繰り返し指定できますが、最大5つです |
| `--checker <agent>` | 完了の主張をレビューする別のエージェントです。名前かIDで指定します |
| `--fresh` | 各セグメントを会話の履歴なしで開始し、ゴールとそのメモだけを使います |
| `--unattended wait` または `--unattended assume` | 誰も回答しないときにエージェントの質問をどう扱うかです（[誰も回答しない場合](#誰も回答しない場合)を参照） |

- フラグはメッセージのどこに置いても構いません。不明なフラグ、同じフラグの繰り返し、不正な値、5つを超えるチェックは拒否され、入力欄に下書きが残り、理由が表示されます。
- 目的の先頭にある数字は目的の一部です。セグメントの上限を設けるには `--max` を使います。
- `/goal` は、あなた自身が入力したメッセージでのみ読み取られます。同じ文面でも、エージェント、パイプライン、起動予約からのものは通常のメッセージになります。
- 1つのワークスペースで、エージェントは一度に1つのゴールに取り組みます。同じエージェントに対する2つ目の `/goal` は、最初のゴールが進行中の間は拒否されます。

### 完了の条件

目的には、ゴールの契約になるセクションを含められます:

```text
/goal make the importer handle files over 2 GB

## Success criteria
- A 3 GB fixture imports without running out of memory
- The progress bar reaches 100%

## Boundaries
- Don't change the public API

## Stop conditions
- A migration would drop data

## Checks
- `make test` (300 s)
- environment task `test` (600 s)
```

- **成功の基準**: 最大12件、各300文字以内です。それぞれ、レビュー担当者が確認できる項目である必要があります。
- **チェック**: 最大5件です。チェックはワークツリーで、またはスペースの[環境](/ja-JP/マニュアル/ハウツーガイド/環境/)の名前付きタスクとして実行されます。既定では各300秒で、最大1,800秒です。
- 上限を超えたセクションは切り詰められず、拒否されます。

完了の条件が空のゴールでは、いつ完了かはエージェントが決めます。チェックがないゴールはレビューだけに頼ります。ゴールのページにもそのことが表示されます。

## ゴールがどう続くか

各セグメントは、5ドルと予算の残りのうち小さい方を上限とする実行です。各セグメントの後、サーバーはそのセグメントが行ったことをもとに、次に何が起こるかを決めます:

- **進捗がありました。** 次のセグメントが開始されます。
- **自分で設定したものを待機中です**: スケジュール、監視、別のエージェントへの質問、または委任したチケットです。ゴールはそれを待ちます。何も届かなければ、サーバーは20分後、その後40分、80分、160分の後、そして以降は240分ごとに再確認します。カードには、時刻を伴って**自分で設定したものを待機中 · 再確認時刻**と表示されます。
- **進捗がありませんでした。** 進捗とは、セグメント自身の作業でワークツリーが変わったこと、チェックリストが変わったこと、またはエージェントが何か新しいことをしたことを指します。進捗のないセグメントが3回続くと、ゴールは一時停止します: **直近のセグメントで進捗がありません。**
- **待ちが長すぎました。** 24時間待機した後、または進捗がないまま新しく設定したものを待つ待機が6回続いた後、ゴールは一時停止します: **進捗のないセグメントの後で待機中です。**
- **失敗しました。** サーバーは30秒後に再試行し、その後は間隔を延ばして最大15分まで再試行します。3回連続で失敗すると、ゴールは失敗します。
- **担当者に質問しました。** 誰かが回答するまでゴールは保留されます: **担当者の対応が必要です**。

ゴールは予算（**予算切れ**）、セグメントの上限、期限でも停止します。

## エージェントが完了したと言ったとき

エージェントは、各基準について根拠を添えてゴールの完了を主張します。その後:

1. **サーバーがチェックを実行します**。サーバーのマシン上で直接ではなく、サンドボックス内で実行されます。終了コードがゼロでないチェックは失敗します。まったく実行できないチェック（コマンドが見つからない、実行できない、存在しない環境タスクなど）は壊れているとみなされ、ゴールは**このチェックは実行できません:** そのコマンドを表示して担当者を待ちます。サーバーにサンドボックスがない場合、ゴールは**チェックを実行するサンドボックスがありません。** で停止します。（サーバーの所有者がすべての実行でサンドボックスを無効にしている場合は例外で、チェックはエージェント自身のコマンドと同じように実行されます。）チェックが失敗した後にワークツリーに変更がなければ、そのチェックは再実行されません。
2. **レビュー担当者が結果を確認します**。すべてのチェックが合格したとき、またはチェックがないときです。レビュー担当者は、ゴールのチェッカー、なければスペースのチェッカー、それもなければゴール自身のエージェントです。読み取り専用で、会話の履歴なしで実行されます。ファイルとチェックの出力は読めますが、何かを変更したり、コマンドを実行したり、他のエージェントを起こしたりはできません。また、エージェントが変更したテストとチェックスクリプトの差分全体を受け取り、会話とメモにエージェントが書いたことは証拠ではなく主張として扱います。基準のないゴールでは、目的全体を一つのものとして判断します。答えは、ゴールが完了している、完了していない、判断できない、のいずれかです。
3. **完了**: ゴールは完了します。**未完了**: エージェントはレビュー担当者の指摘を受け取り、作業を続けます。未完了が3回続くか、レビュー担当者が判断できない場合、ゴールは担当者を待ちます: **レビュー待ち: 完了したと報告されていますが、確認はされていません**。

レビュー担当者の実行中に入力したメッセージは、レビュー担当者には渡されず、レビューが終わっても送信されません。そのメッセージは、エージェントの次のセグメントまでキューに残ります。後続のセグメントがない場合は、そのメッセージは**保留中のメッセージを送信**の下であなたのために保留されます。

削除された、あるいは実行を読み取り専用に保てないアダプター（ACPエージェントなど）上にあるレビュー担当者は実行できず、ゴールは一時停止します: **チェッカーのエージェントが利用できません。別のチェッカーを選んでから再開してください。** 担当者の操作なしに、ほかのエージェントが代わりに入ることはありません。

ゴールのエージェントとは別のプロバイダーのチェッカーは、同じ見落としを共有しにくくなります。別のチェッカーがない場合、エージェントは自分の作業をレビューし、ゴールには**自身で検証（別のチェッカーなし）** と記録されます。

## ゴールを追う

- **会話内**: 会話の**一般**パネルにあるゴールカードには、保留状態、セグメント、予算に対する支出、残り時間、完了の条件、チェック、直近の判定が表示されます。
- **ゴールのページ**: サイドバー → **ゴール**。ゴールは**レビュー待ち**、**進行中**、**終了**に分類されます。
- **ゴールのページ**: ゴールを開くと、**現在**（セグメント、支出、期限、進捗なしの回数、次に起こること）、**完了の条件**、**検証**（直近の回の主張、各チェックとその出力、基準ごとのレビュー）、**スケジュールと起動予約**が表示されます。各ゴールには固有のアドレス（`/workspaces/<workspace>/goals/<goal id>`）があるので、リンクを共有できます。

スマートフォンでは、ゴールの画面でチェックとセグメントの上限を指定してゴールを開始でき、同じゴールと保留状態を表示します。

## ゴールを変更または停止する

| 操作 | 実行できるユーザー |
| --- | --- |
| **ゴールを一時停止**、**ゴールを停止** | スペースへのアクセス権を持つ人 |
| **ゴールを再開**、**予算を引き上げ** | ゴールを開始した人だけ（誰も開始していないゴールは、ワークスペース管理者） |
| 完了の条件を**編集**、**チェッカーを変更** | ゴールが一時停止している間は、ゴールを開始した人だけ（誰も開始していないゴールではワークスペース管理者）で、スペースのリポジトリへの書き込み権限を持つ人 |
| **完了を承認** | ゴールがレビュー待ちの間は、スペースへのアクセス権を持つ人。パイプラインが開始したゴールは、その実行を開始した人だけ（誰も開始していない場合はワークスペース管理者） |

- エージェントの実行で**停止**を押すと、ゴールは一時停止します（**担当者が一時停止しました**）。ゴールの未配信の起動予約は、あなたが再開するまで待機します。
- **完了を承認**すると、ゴールはあなたの判断で完了として閉じられます。ゴールには**合格したチェックなしに、担当者が完了として閉じました**と記録されます。
- 予算を使い切ったゴールは、より高い予算でのみ再開します。
- ゴールを開始した人がワークスペースから退出すると、そのゴールはすぐにレビュー待ちとして一時停止し、実行中のエージェントは停止します。誰もそれを再開できません。スペースにアクセスできる人なら誰でも停止できます。日次ダイジェストには、ワークスペース管理者向けにこのゴールが掲載されます。

## 誰も回答しない場合

セグメントが担当者に質問または承認を求め、誰も回答しない場合、その依頼は既定で72時間待ちます。その後、承認は却下、質問は未回答として扱われ、ゴールは一時停止します: **担当者への質問または承認リクエストに回答がありません。** 質問した実行は以降の回答を受け取らず、ほかに尋ねられた内容はすぐに拒否され、できる範囲で完了します。 ワークスペース管理者は、**設定 → ワークスペース → スケジュール → 誰も回答しない場合**で時間（1時間から7日）を設定します。毎日、設定した時刻に、あなたを待っているすべての項目をまとめたダイジェストが1通届きます。

`--unattended assume` を指定すると、停止条件が許す場合、エージェントは回答がないまま10分経過した後、想定を明示して先に進みます。これは質問にだけ適用されます。承認が想定されることはなく、レビューが何かを想定することもありません。

## 利用上限と再起動

- **プロバイダーの利用上限。** セグメントがプロバイダーの利用上限で停止し、プロバイダーがリセット時刻を示した場合（7日以内）、ゴールは違反扱いされずに一時停止します: **利用上限で一時停止中 · 時刻に再開**。リセットから30秒後に再開します。このような一時停止が8回続くと、ゴールは担当者を待ちます: **利用上限での一時停止が多すぎました。内容を確認してから再開してください。** 再開すると、カウントは最初からやり直されます。ACPエージェントはリセット時刻を報告しないため、そのゴールは利用上限で待機しません。
- **サーバーの再起動。** ゴールは再起動後も残ります。再起動によって中断されたセグメントは再び開始され、ゴールのスケジュールと保留中の起動予約は保持されます。

## ゴールの後の改善案

ゴールが検証を通過すると、短い読み取り専用のレビュー（1ドルまで）が、メモリの事実、ポリシー、エージェントへのメモ、スキルの変更といった改善を提案することがあります。会話の作業に対して同じレビューを求めるには `/refine` と入力します。1つの会話につき、レビューは20分ごとに最大1回実行されます。

提案は**改善案**ページ（サイドバー → **改善案**）に表示されます。開くと、何を変更するか、根拠、そして**承認**、**却下**、**ロールバック**が確認できます。

- 誰かが承認するまで、提案は何も変更しません。提案は30日で期限切れになります。
- スキルの変更や、ワークスペース全体に適用されるポリシーの変更には、ワークスペース管理者の判断が必要です（**管理者が判断**）。
- スキルの変更は、別のリビジョンとして保存されます。**評価を実行**を押すと、現在のスキルと比較します。**承認**は、評価が合格した後にのみ可能です。評価は、最後まで実行され、かつ変更を加えた場合にエージェントが解決した実行回数が現在のスキル以上だった場合に合格します。ページには両方の数字が表示されます。評価後にスキルが変わった場合は、もう一度評価してください。
- **ロールバック**は、誰も変更していない限り、以前のテキストを元に戻します。

## パイプラインで

パイプラインは**Pursue a goal**ステップ（`goal.pursue`）でゴールを開始できます。このステップはゴールが終了するまで待ち、その要約と判定を次に渡します。[パイプラインステップ](/ja-JP/マニュアル/リファレンス/パイプラインステップ/)を参照してください。
