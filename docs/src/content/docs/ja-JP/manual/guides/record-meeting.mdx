このガイドでは、ミーティングを録画して AI が生成した記録を取得する方法を説明します。
仕組みについては[ミーティングと文字起こし](/ja-JP/マニュアル/コンセプト/ミーティング/)を参照してください。

## 始める前に

- **音声モデルを待ってから、サーバーを再起動します。** 通常の起動では、選択された ASR
  モデル（多言語対応の既定である Parakeet TDT 0.6B v3、約 600 MB）がバックグラウンドで
  強制インストールされます。サーバーがモデルを解決するのは**起動時の 1 回だけ**なので、
  再起動するまで初回の実行には録音操作がありません。ディスク上にモデルがない場合、録音は
  `Could not start recording on the host: …` で失敗します。別のビルドを選ぶには、
  **設定 → サーバー → 音声と会議のモデル**を使用します。これにも再起動が必要です。
- 初回の録音時に OS から求められたら、**マイク**の権限を付与します。
- **macOS 14.4 以降**では、システムオーディオは Core Audio のプロセスタップでキャプチャされます。インストールするドライバーはありませんが、OS は 2 回目の権限として _オーディオキャプチャ_ の権限を求めます。これは画面収録ではなく、画面収録のインジケータが点灯することもありません。これを拒否すると、開始が `System-audio capture permission denied.` で失敗します。macOS 14.4 より前ではシステムオーディオのキャプチャはありません。
- **Linux** では、`parecord`（pulseaudio-utils）または `pw-record`（pipewire）が `PATH` 上になければなりません。キャプチャは PipeWire/PulseAudio のモニターソースに対してこれらのいずれかを起動します。どちらもない場合、開始は `No system-audio capture tool found` で失敗します。

:::caution[ミーティングの音声がどこへ行くのか]
キャプチャ、文字起こし、エコーキャンセル、話者分離はすべてオンデバイスで実行され、クラウド
呼び出しはありません。ただしここでの「デバイス」は **cc_server ホスト**を意味し、サーバーを
リモートで実行している場合は別のマシンになります。そして最終的な記録は通常のエージェント
実行です。`meeting_summary` パイプラインは、文字起こし全体とあなたの大まかなメモを、その
エージェントが使用するモデルプロバイダーに送信します。文字起こしをマシンの外に出しては
ならない場合は、そのエージェントをローカルプロバイダーに向けてください。

録音画面には録音中にこのことが表示されるため、送信する文字起こしができる前に判断材料が
目の前に示されます。
:::

## 録音を開始する

1. サイドバーで**ミーティング**を開きます。
2. **会議を録音**をクリックします。ライブ録音 HUD が `/meetings/record` で開きます。

録音はすぐに開始され、マイクとシステム出力オーディオ（他の参加者）をキャプチャします。
モードの確認も、オーディオソースの選択もありません。対面のシングルマイクモードは API には
存在しますが、現時点で UI はありません。

ブラウザーでも同じフローが機能しますが、1 点だけ異なります。ここでの「システムオーディオ」
は、オーディオトラックを含まなければならない画面共有です。ブラウザーのタブ（または画面
全体）を共有し、ピッカーで「タブの音声を共有」/「システム音声を共有」を有効にします。
Safari と Firefox、および macOS での全画面共有は、しばしばオーディオトラックを提供できません。

HUD にはレベルメーター、経過時間、そして片側に構築されていくライブ文字起こしが表示されます。

## ミーティング中

- **大まかなメモを取る**: メモペインに記入します。入力に応じて保存され、後で要約エージェントに渡されるため、文字起こしが見落とすかもしれない事柄を書き留めておきましょう。
- **会議メモのテンプレートを選ぶ**: **有効なテンプレート**行で選択します。これはこのミーティングの要約を形作り、録音とともに取り込まれるため、後で再実行するとここで選んだテンプレートが再現されます。
- **一時停止と再開**: 一時停止コントロールで操作します。一時停止中は文字起こしが停止し、タイマーも止まります。
- 文字起こしは話者タグ付きでストリーミングされます。あなたの発言は**自分**、通話の全員は**その他**として表示され、話者分離がその他を `Person 1`、`Person 2`、… に分割した後は、名前を変更できます。

:::note[非常に小さな声の話者は文字起こしされないことがあります]
文字起こしは、無音しきい値を一度も超えなかったオーディオウィンドウを、まったくデコード
せずにスキップします。これにより、静かなチャンネルが幻覚的な非音声トークンで CPU を消費
するのを防ぎますが、その一方で、かすかな声や遠くの話者は文字起こしが一切生成されない
可能性があります。レベルメーターは最後ではなく、早い段階で確認してください。
:::

## 停止して要約する

1. **停止して要約**をクリックします。
2. Control Center はミーティングの詳細ビューに直接移動し、**処理中**と表示されます。話者分離がリモートチャンネルを個々の話者に分割し、`meeting_summary` パイプラインが記録を生成します。
3. そのパイプラインが完了すると、ミーティングは**完了**に切り替わります。待つ必要はありません。詳細ビューは自動的に更新されます。

## 記録を確認する

ミーティングの詳細（`/meetings/:meetingId`）には 4 つのタブがあります:

| タブ             | 内容                                                                       |
| ---------------- | -------------------------------------------------------------------------- |
| **メモ**         | あなたの大まかなメモ + 文字起こしから構築された、AI の要約と拡張メモ      |
| **文字起こし**   | タイムスタンプ付きの、話者タグ付き文字起こし全体                          |
| **アクションアイテム** | 抽出された ToDo。それぞれに任意の担当者が付きます                   |
| **決定事項**     | 通話中に記録された決定事項                                                 |

ここから次のことができます:

- **話者の名前を変更**: `Person 1` を実際の名前に変えます。文字起こし全体に適用されます。
- **アクションアイテムをチェックオフ**: 完了したものにチェックを入れます。
- **チケットを作成**: アクションアイテムから作成します。アクションアイテムをタイトルにした、担当者のいない新しいチケットが起票され、その行にリンクされます。エージェントへの割り当てはチケット自体から行います（[エージェントに作業を委任](/ja-JP/マニュアル/ハウツーガイド/チケット委任/)を参照）。
- **要約を再実行**: 新たなパスを実行します（たとえば話者の名前を変更した後）。録音時に取り込まれたテンプレートを再利用します。有効なテンプレートは**設定 → ワークスペース → ミーティング**で選択します。

メモ、タイトル、アクションアイテム、決定事項の編集はどこでも機能します。
**要約を再実行**と処理中のミーティングのキャンセルは**デスクトップ専用**です。ブラウザーでは
どちらのボタンも何もしません。

## カレンダーの予定から直接録音する

[カレンダーを接続](/ja-JP/マニュアル/ハウツーガイド/カレンダー接続/)していれば、手動での
開始を省略できます。これは**デスクトップ専用**です。Web クライアントはこれを拒否します。

1. **カレンダー**から予定を開きます。
2. **録音を開始してリンク**をクリックします。

録音にはその予定のタイトルが初期値として設定され、予定にリンクして戻されるため、メモと
カレンダーの予定はつながったままになります。

:::note[ミーティングを削除しても音声は削除されません]
ミーティングを削除するとその行は削除されますが、`<dataDir>/meetings/<meetingId>/` 配下の
録音済み WAV ファイルはディスク上に残ります。保持ポリシー、サイズ上限、クリーンアップ
スイープのいずれもありません。音声が重要なら、そのディレクトリは自分で削除してください。
:::
