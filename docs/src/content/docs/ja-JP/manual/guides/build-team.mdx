このガイドでは、チームを作成し、リーダーを設定して、作業をチームにルーティングする方法を説明します。

チームとは、1 つのワークスペース内にある名前付きのエージェントのグループで、そのうち 1 人が**リーダー**として指定されます。チケットをチームに割り当てるとリーダーが起動し、作業を分解してメンバーに委任します。メンバーの実行が完了すると、次に何を行うかを決めるためにリーダーが再び起動されます。

チームの作成、名前の変更、メンバーの編成は **設定 → ワークスペース → エージェント → チーム** で行います。作業をチームにルーティングする方法は 2 つあります。エージェントがそのチームの `team_id` を指定して `assign_ticket` を呼び出すか、パイプラインの **Team dispatch** ノードがチームをディスパッチします（チケットは割り当てません）。チケットの担当者ピッカーには、あなたと個々のエージェントが表示されます。

## チームを作成する

1. **設定 → ワークスペース → エージェント**（`/settings/workspace/agents`）を開きます。
2. ページヘッダーの**チーム**をクリックします。
3. **チームを追加**をクリックします。
4. **名前**（例：「backend」「review squad」）と任意の**説明**を入力し、**作成**をクリックします。

チームが作成されて選択され、右側のペインにエディターが開きます。

## リーダーを設定する

これがこの機能全体の要となる手順です。チームのエディターで次を行います。

1. **リーダー**でエージェントを選択します。ヘルプテキストはそのまま次のように説明しています。「チームに割り当てられた作業を受け取り、最適なメンバーに委任するコーディネーターです。」
2. 任意で**運用指示**を入力します。これは、ルーティングされたチケットごとにリーダーへ渡される自由記述のテキストです。

エージェントをリーダーに昇格させると、まだメンバーでなければメンバーにもなります。**リーダーなし**のままのチームは機能しません。作業をルーティングしても何もディスパッチされず、メンバーリストから現在のリーダーを削除すると、チームは再びリーダー不在になります。

## メンバーを追加する

同じエディターで、メンバーカードを使ってワークスペースのエージェントを追加したり削除したりします。メンバーは、リーダーが委任する対象となる名簿です。

チームはワークスペース単位です。参加できるのは、このワークスペースのエージェントだけです。

## チームにスペースを割り当てる

チーム専用のスペースは自動では作成されません。必要な場合は、**スペース**で通常のスペースを作成し、そこにチームのエージェントを追加します。`Team` は名前、説明、リーダー、指示、メンバーを持ちますが、スペースとの関連付けはありません。

## 報告ラインは別の仕組みです

各エージェントには**報告先**フィールドもあり、**設定 → ワークスペース → エージェント**で設定します。これはワークスペースの報告ツリーを形成し、エージェントページの**組織図**ボタンで確認できます。

これはチームのルーティングには使われません。リーダーは報告チェーンからではなく、チームのメンバー名簿からスキルと役割に基づいて委任先を選びます。メモリアクセスの許可は、報告チェーンではなくエージェントの役割をキーにします。また、チームや階層で集計する分析画面はありません。委任ガードは深さを制限し、循環を検出しますが、委任先が部下であることを要求することはありません。

## ルーティングされたチケットの動作

チケットにチームの割り当てが含まれている場合、次のように動作します。

1. チケット、その運用指示、メンバー名簿とともに、チームのリーダーがディスパッチされます。
2. リーダーはメンバーに委任し、`record_team_activity` ツールでその評価を記録します。`action`（委任した）、`no_action`（これ以上行うことはなく、以降の再トリガーを停止します）、`failed` のいずれかです。
3. 完了したメンバーの実行はそれぞれリーダーを再び起動しますが、no-action ガードによる上限があります。

もう 1 つの入口は、パイプラインの **Team dispatch** ノードです。チーム ID、プロンプト、ディスパッチモードを取ります。

- `allParallel` — メンバーごとに 1 つのタスクを共有の非表示会話に投入し、すべての実行が完了するまで中断します。各メンバーの出力はノードの出力キーにまとめられます
- `manager` — リーダーのみをディスパッチし、リーダーが会話内でコーディネートします
