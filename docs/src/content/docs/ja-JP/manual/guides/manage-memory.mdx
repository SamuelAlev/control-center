このガイドでは、ワークスペースのナレッジストアを扱う方法を説明します。

作業を始める前に知っておくべき重要な点: **メモリの UI はレビューのサーフェスであり、作成のサーフェスではありません。** 事実とポリシーを書き込むのはエージェントです。`propose_fact` と `propose_policy` を通じて書き込み、置き換えるには `supersede_fact` と `supersede_policy` を使います。`remember` はセッションに閉じたホット層の項目を書き込み、それを `consolidate_memory` が後から事実へ昇格させることがあります。記録されたミーティングの決定は `decisions` ドメインへ取り込まれますが、完了したエージェント実行に対して取り込みが行われることはありません。ここで行うのは、エージェントが書いたものを読み、修正し、無効化し、あるいは削除することです。

メモリは **設定 → ワークスペース → メモリ**（`/workspaces/<id>/settings/memory`）にあります。サイドバーのトップレベル項目ではありません。

## 3 つのタブ

ページにはちょうど 3 つのタブがあります。事実とポリシーにはリアルタイムの件数が表示されますが、グラフには表示されません:

- **事実** — ワークスペース内のすべての事実。置き換えられていないものの件数付き
- **ポリシー** — ドメインごとにまとめられた規範的なルール。アクティブなものの件数付き
- **ナレッジグラフ** — ドメイン、トピック、事実、ポリシーを配置したインタラクティブなキャンバス

ドメインは作成するものではありません。エージェントが最初の事実またはポリシーを書き込んだ時点でドメインが生まれます。UI のどこにもドメインを作成するコントロールはありません。

## 事実を確認して修正する

1. **事実**タブを開きます。
2. 検索ボックスを使って一覧を絞り込みます。各事実のドメイン、トピック、コンテンツに対する単純な部分文字列フィルターであり、キーワードインデックスもランキングもありません。
3. スコープフィルターを使って、すべてのスコープ、ワークスペース全体の事実のみ、または 1 つのリポジトリの事実のみを表示します。
4. 並べ替えトグルを使って、新しさ順または確信度順に並べます。
5. 事実の編集コントロールをクリックします。

編集ダイアログでは次の項目を変更できます:

- **ドメイン** — 事実をドメイン間で移動する
- **トピック** — その短いラベル
- **コンテンツ** — ナレッジの本文
- **確信度** — 5% 刻みのスライダー

保存すると書き戻されます。**事実を追加**ボタンはありません。ダイアログは既存の行でのみ開きます。

## 置き換え済みの事実を確認する

事実タブには**置き換え済みを表示**スイッチがあります。置き換え済みの事実は既定で非表示で、このスイッチで表示されます。監査証跡はここにあり、置き換えても削除されることはありません。

## 事実を削除する

事実の削除コントロールを使って確認します。これは置き換えではなく実際の削除です。単に記録するのが誤りだった事実に使い、_コンテンツ_ が先に進んだ事実はエージェントに置き換えさせます。

## ポリシーを管理する

**ポリシー**タブはアクティブなポリシーをドメインごとにまとめ、非アクティブなものは末尾のセクションに降格します。ポリシーごとに次の操作ができます:

- **編集**する
- **削除**する
- **無効化** / **有効化**する — 可逆的な選択肢であり、通常はこちらが適切です。エージェントのプロンプトに届くのはアクティブなポリシーだけです。

事実と同様、作成用のコントロールはありません。

## ナレッジグラフを探索する

**ナレッジグラフ**タブは、ドメイン、トピック、事実、ポリシーを操作可能なノードキャンバスとして配置します。パン、ズーム、ノードのドラッグができます。ノードをタップすると詳細シートが開き、そこから同じ編集ダイアログに到達できます。どのドメインに実際にデータが入っているかを確認する最速の方法です。

## エージェントのワーキングメモリを編集する

ワーキングメモリはエージェントごとの非公開スクラッチパッドで、ディスパッチ時にそのプロンプトへ注入されます。エージェントは `record_observation` と `update_my_notes` を使って自分で書き込みますが、あなたが直接読み取り、編集することもできます:

**設定 → ワークスペース → エージェント** → エージェントを選択 → **メモリ**タブ。

## アクセスグラント

メモリのアクセスグラントは、エージェントのロールをドメインごとの権限（`none`、`read`、`write`）に対応付けます。`memory_access_grant.*` のオペレーションで書き込みます。

グラントがどのように解決されるかについて、理解しておくべき点が 2 つあります:

- **読み取りはフェイルオープンです。** (role, domain) のペアに対するグラントの行がない場合、実効権限は `read` になります。`write` なしで例外を投げる唯一の書き込みは `propose_policy` です。事実の書き込みはグラントによる制限を受けません。
- **グラントはエージェントのロールをキーにします。** 提案系のツールは、`agent_role` が欠けていると `general` を既定値とします。別のロールに対して書かれたグラントはそれらのエージェントを拘束しませんが、`general` のグラントは拘束します。

## 検索はどこでも同じではない

「メモリ検索」と呼ばれるものが 3 つあり、それらは一致しません:

| 場所                                | 動作                                                                                                         |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 事実タブの検索ボックス              | クライアントにすでに読み込まれている事実に対する部分文字列フィルター                                         |
| `memory_fact.search` の RPC オペレーション | FTS5 のキーワード検索のみ。シンクライアントはクエリの埋め込みを送れないため、ハイブリッド検索はホスト内に留まります |
| エージェント側の `search_memory` ツール | `keyword`、`semantic`、または `hybrid`（既定）。ハイブリッドは 4 つの声を統合します: 字句、セマンティック、時間、グラフ |

したがって、エージェントとメモリページが同じクエリを同じようにランク付けすることはありません。エージェントが実際に何を思い出せるかを確認したいときは、エージェントに尋ねてください。

## 埋め込み

事実が埋め込まれるのは**書き込み時**で、しかもオンデバイスの埋め込みモデルがインストールされている場合だけです。状態は **設定 → サーバー → 診断とプライバシー → セマンティック検索** で確認します。セマンティックリコールが必要なら、エージェントがメモリを書き始める前にモデルをインストールしてください。
