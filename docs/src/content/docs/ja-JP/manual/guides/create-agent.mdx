このガイドでは、ワークスペースにエージェントを追加し、実際に実行できるようになるまで設定する方法を説明します。

すべてのワークスペースには 5 体のエージェント — CEO と `qa`、`architect`、`engineer`、`librarian` — があらかじめシードされているため、何も設定していなくてもエージェントは存在します。以下の手順は、シードされたエージェントにも新しいエージェントにも同じように当てはまります。

## 開始する前に

- ワークスペース内で作業していることが前提です。画面全体は **設定 → ワークスペース → エージェント**（`/settings/workspace/agents`）にあります。
- エージェントにはバックエンドが必要です。**設定 → サーバー → モデルプロバイダー**で組み込みハーネス用のプロバイダーを接続するか、`cc_server` をホストしているマシンに Claude Code CLI をインストールしてください。
- エージェントにスキルを持たせる場合は、先に **設定 → ワークスペース → スキル**でインストールしてください。エージェントのフォームでは、ワークスペースにすでに存在するスキルしか切り替えられません。

## エージェントを追加する

1. **設定 → ワークスペース → エージェント**を開きます。
2. **新しいエージェント**をクリックします。

ダイアログもロールの選択もありません。「名前なしエージェント」という名前のエージェントがすぐに作成され、右側の詳細パネルで選択されます。

ここで、左側の名簿に「名前なしエージェント」が表示され、その詳細パネルの **設定** タブが開き、**名前** フィールドに「名前なしエージェント」が入っているはずです。

## 名前を付ける

- **名前** — @メンションで使われる短い識別子です。たとえば `alice`。メンションの解析は `@` に続く単語文字に一致するため、ハイフン、ドット、スペースを含む名前はメンションできません。
- **タイトル** — 人が読むためのラベルです。たとえば「Senior coder」。
- **システムプロンプト** — 任意の追加指示で、「Agent instructions」セクションとして注入されます。組み立てられたプロンプトの残りを置き換えるものではありません。

フォーム下部の **変更を保存** をクリックします。このページのすべてのフィールドは、この 1 つのボタンで保存されます。

## アダプターとモデルを設定する

**アダプター** ドロップダウンには、サーバーホストに実際にあるランナーが一覧表示されます。組み込みアダプターは常に検出されます（それがサーバーです）。Claude Code は、そのホストで CLI が検出された場合にのみ表示されます:

| アダプター                | バックエンド                                                |
| ------------------------- | ----------------------------------------------------------- |
| Control Center (built-in) | プロセス内のエージェントループ — 外部 CLI は不要            |
| Claude Code               | `claude -p --output-format stream-json`                     |

組み込みアダプターだけが、モード、ステアリング、一時停止と再開、完了契約、サブエージェントを強制します。Claude Code はそのいずれも提供しません。Cursor、Codex、その他のモデルプロバイダーは、別個のランナーではなく、組み込みアダプターに接続します。

:::note[アダプターが空の場合は組み込みループになります]
アダプターが未設定のエージェントは **Control Center (built-in)**、つまりサーバー内のループにディスパッチされるため、ホストに何もインストールする必要はありません。モデルも設定されていない場合は Anthropic にそのデフォルトを問い合わせるため、完全に未設定のエージェントが実行されるのは Anthropic アカウントを接続している場合だけです。シードされたスペシャリストはどちらも持たずに提供されます。使用する予定のエージェントには両方を設定してください。
:::

**モデル** ドロップダウンは、選んだアダプターによって決まります。組み込みアダプターの場合、一覧は **設定 → サーバー → モデルプロバイダー** で接続したプロバイダーからリアルタイムに取得されるため、資格情報が保存されていないプロバイダーはモデルを 1 つも提供しません。

## スキルを追加する

**スキル** は、このワークスペースにインストールされているスキルバンドルを対象とするチップピッカーです。チップをタップして切り替えます。チェックのグリフが選択済みのものを示します。ワークスペースにスキルがない場合、このフィールドには「No skills available. Create skills in Settings → Skills first.」と表示されます。

ここではリポジトリ自身のスキルを選ぶことはありません。スキルを同梱するリポジトリ（`.agents/skills/`、`.claude/skills/`、`.opencode/skills/`）は、そのリポジトリで作業するエージェントにスキルを自動的に提供し、エージェントが別のリポジトリへ移動すると入れ替わります — [リポジトリ単位のスキル](/ja-JP/マニュアル/コンセプト/エージェントモデル/#repo-scoped-skills) を参照してください。

## 報告ラインとペルソナを設定する

- **報告先** — 名前で別のエージェントを選びます。これはページヘッダーの **組織図** ボタンに表示される報告ツリーを構築します。チームリーダーが委任するときに使う名簿ではありません — それはチームのメンバーとそのスキルから決まります。
- **ペルソナ** — 口調と振る舞いを形作る自由記述です。たとえば「シンプルで読みやすい解決策を好む。新しいコードにはすべてテストを書く。」

## 実行を調整する

- **推論の程度** — 選択肢は、選択したモデル自身が公開しているレベルから来ます: Low / Medium / High、OpenAI 系のモデルでは Extra High、Claude 系のモデルでは Extra High + Max が加わります。選択したモデルが思考レベルを宣言していない場合、このフィールドは完全に非表示になり、モデル自身のデフォルトが使われます。
- **コンテキストウィンドウサイズ** — モデルを変更するたびに、そのモデルのコンテキストウィンドウから事前入力されます。モデルのデフォルト、200k、500k、1M のワンタップチップもあります。モデルを選んだ後に入力した値は、次にモデルを変更するまで優先されます。
- **無応答タイムアウト（分）** — 出力がないままこの時間が経過した実行を終了します。空のままにすると、モードごとのデフォルトが使われます。

## 権限を付与する

**サンドボックスの権限** は「ワークスペースのデフォルトを使用」から始まります。スイッチをオンにするとこのエージェント用に設定できるようになるので、各項目を切り替えます:

- **git push を許可** — エージェントがプッシュするために必要な GitHub トークンを注入します
- **GitHub API の呼び出しを許可** — エージェントが PR、Issue、リポジトリのメタデータを読み取れるようにします
- **チケット API の呼び出しを許可** — チケットプロバイダーのキーを注入します
- **一般的なネットワークアクセスを許可** — 組み込みハーネスの `web_fetch` と `web_search` ツールも有効にします

各トグルの状態は、実行の起動時に資格情報ブローカーが確認します。オフのケイパビリティとは、対応するトークンが実行環境に発行されないというだけのことです。

:::caution[ワークスペースのデフォルトはサーバーの保守的なセットを意味します]
「ワークスペースのデフォルトを使用」のままにしたエージェントは、git push、GitHub API、チケットがいずれも **オフ**、ネットワークが **オン** で実行されます。設定 → サーバー → 診断とプライバシーに表示されるケイパビリティのデフォルトは、クライアント側の設定です。エージェントにプッシュや PR の作成をさせたい場合は、スイッチをオンにしてケイパビリティを明示的に付与してください。

これらのケイパビリティが制御するのは資格情報とハーネスのツールであり、OS サンドボックスとは別の層です。`cc_server` は、存在する場合はホストのサンドボックスでエージェントの実行を包みます — Windows にはネイティブのバックエンドがなく、Linux と WSL2 には `bwrap` と `socat` が必要です。境界の全体像については [サンドボックスとセキュリティ](/ja-JP/マニュアル/コンセプト/サンドボックスとセキュリティ/) を参照してください。
:::

## 実行できることを確認する

1. **設定 → サーバー → モデルプロバイダー**を開き、選択したアダプターが「見つかりません」ではなくインストール済みのバージョンを報告することを確認します。**更新**をクリックして再プローブします — プローブは、いま見ているマシンではなく `cc_server` をホストしているマシンで実行されます。
2. エージェントを含むスペースを開いてメッセージを送るか、既存のスペースで @メンションします。
3. **設定 → ワークスペース → エージェント**に戻り、エージェントを選択して **ログ** タブを開きます。ステータスバッジ、所要時間、開始時刻、使用されたアダプターを伴う実行が表示されるはずです。**表示** でその実行のイベントストリームが開きます。

実行がまったく表示されない場合は、[エージェントの診断](/ja-JP/マニュアル/ハウツーガイド/エージェント診断/) を順に確認してください。

## エージェントを削除する

名簿でエージェントを選択します。**設定** タブで、フォーム最下部の **危険ゾーン** までスクロールし、**削除** をクリックします。
