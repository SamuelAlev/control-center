このガイドでは、自分のチャットアイデンティティを自分の Control Center ユーザーにリンクする方法と、そのリンクを解除する方法を説明します。

メンバーは誰でも、チャットプロバイダーごとに 1 回だけこれを行います。これはアプリの接続とは別の操作です。接続はボットをワークスペース全体から到達可能にし、リンクはワークスペース内で*あなた*を識別可能にします。

## なぜリンクが必要か

ブリッジは、ワークスペースのメンバーに解決できないチャットアカウントのために動作することを拒否します。これは意図的です — リンクがなければ、Slack からのすべてのメッセージは、アプリをインストールした人物に帰属せざるを得なくなり、監査証跡、プリンシパル単位のレート制限、チケットの報告者がすべて誤った人物を指すことになります。

リンクしていないメンバーがボットにメンションすると、その Slack スレッドでリンク方法を説明する返信が届きます。何もディスパッチされません。

## コードでリンクする

1. **設定 → ワークスペース → プロフィールと識別情報**に移動し、**連携済みチャットアカウント**カードまでスクロールします
2. Slack のブロックで、**自分のSlackアカウントを連携**をクリックします
3. 表示されるコマンドをコピーします。たとえば次のとおりです。

```text
/cc link K7M2QP
```

4. Slack で、そのコマンドをボットに送信します — DM がもっとも手軽な場所です
5. ボットは、リンク先となった Control Center ユーザーとともに確認を返し、開いたままにしていたダイアログも同じタイミングでその旨に更新されます — 一度閉じて確認し直す必要はありません

コードは次のとおりです。

- 単回使用で、発行から **15 分**後に失効します
- 常に*あなた*のために発行され、チームメイトのために発行されることはありません
- すでに保持しているコードを置き換えるため、ボタンをもう一度押すと前のコードは無効になります
- メモリ上にのみ存在するため、サーバーが再起動すると未使用のコードは無効になります — ボタンをもう一度押してください

未知のコード、期限切れのコード、別のワークスペース向けに発行されたコードは、いずれも見分けのつかない同じ形で失敗します: 「that code is not valid (or has expired)」。

## メールアドレスによる自動リンク

Slack プロフィールに検証済みのメールアドレスがあり、それが**すでにこのワークスペースのメンバーである** Control Center ユーザーと一致する場合、ブリッジは初めて話しかけた時点で自動的にリンクします。コードは必要ありません。

どちらの条件も欠かせません。メールアドレスの一致はアイデンティティを証明しますが、アクセスを付与するのはメンバーシップだけです。そのため、たまたまサーバー上にアドレスが存在するだけの部外者は何にもリンクされません。名簿には、各リンクがどのように作られたか（「メールアドレスで照合」または「コードで連携」）が表示されます。

自動リンクには `users:read.email` スコープが必要です。これがないと Slack はアドレスを開示しないため、コードによる経路だけが唯一の手段になります。

## 誰がリンクされているかを確認する

名簿はワークスペースの管理操作であるため、サーフェスの別の側にあります: **設定 → ワークスペース → 全般 → チャットブリッジ → 連携済みアカウント**。ここにはワークスペース内のリンク済みメンバーが全員一覧表示され、それぞれが対応する Slack アカウントと、リンクがどのように作られたかが示されます。

自分の状態は自分のプロフィールページにあります。**自分のSlackアカウントを連携**の行は、リンク済みであれば「_your-slack-id_に連携済み」と表示され、リンクしていなければリンクするよう促します。

名簿はライブ購読です。変更が反対側で起こるからです — コードを入力するのは Slack 側であり、アプリからのどのリクエストもその結果を持ち帰ることができません。

## リンクを解除する

ワークスペースの名簿の行で**連携解除**をクリックします。

- 誰でも自分自身のリンクを解除できます
- 他のメンバーのリンクを解除できるのは管理者だけです
- リンクを解除すると、そのメンバーの未使用のリンクコードもすべて失効します

リンクを解除すると、その Slack アカウントは再びリンクするまでエージェントを動かせなくなります。既存のスペース、トランスクリプト、チケットは元の帰属を保ちます — リンクの解除は過去の作業の撤回ではありません。

## トラブルシューティング

### ボットから、このワークスペースのメンバーではないと言われる

Slack アカウントは Control Center ユーザーにリンクされていますが、そのユーザーはこのワークスペースのメンバーシップを持っていません。管理者に招待を依頼してください。[マルチプレイヤー — アイデンティティ、メンバーシップ、プレゼンス](/ja-JP/マニュアル/コンセプト/マルチプレイヤー/)を参照してください。

### ボットから、自分のロールが読み取り専用だと言われる

`viewer` と `guest` のロールでは作業を開始できません。管理者があなたのロールを `member` 以上に引き上げる必要があります。

### スラッシュコマンドが認識されない

そのスラッシュコマンドが Slack に存在することと、設定ダイアログに表示されたコマンドを送信していることを確認してください — 管理者が名前を変更している可能性があり、その場合ダイアログには現在の名前が表示されます。
