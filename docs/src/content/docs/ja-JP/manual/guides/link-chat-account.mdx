このガイドでは、自分のチャットアイデンティティを自分の Control Center ユーザーにリンクする方法と、そのリンクを解除する方法を説明します。

メンバーは誰でも、チャットプロバイダーごとに 1 回だけこれを行います。これはアプリの接続とは別の操作です。接続はボットをワークスペース全体から到達可能にし、リンクはワークスペース内で*あなた*を識別可能にします。

## なぜリンクが必要か

ブリッジは、ワークスペースのメンバーに解決できないチャットアカウントのために動作することを拒否します。これは意図的です — リンクがなければ、Slack からのすべてのメッセージは、アプリをインストールした人物に帰属せざるを得なくなり、監査証跡、プリンシパル単位のレート制限、チケットの報告者がすべて誤った人物を指すことになります。

リンクしていないメンバーがボットにメンションすると、その Slack スレッドでリンク方法を説明する返信が届きます。何もディスパッチされません。

## コードでリンクする

リンクには両側が必要です。Slack からコードを送ることでその Slack アカウントが証明され、Control Center で確認することでそのアカウントがあなたのものであることが証明されます。

1. **設定 → 自分 → プロフィール**に移動し、**連携済みチャットアカウント**カードを見つけます
2. Slack のブロックで、**自分のSlackアカウントを連携**をクリックします。ダイアログに 1 回限りのコードが表示されます。たとえば次のとおりです。

```text
K7M2QP
```

3. Slack で、そのコードを**ダイレクトメッセージ**でボットに送信します。コードだけを送り、ほかには何も書きません
4. ボットが "Got it. Confirm this Slack account in Control Center to finish linking." と返信し、開いたままにしていたダイアログには、コードを送った Slack プロフィール（名前と Slack メンバー ID）が表示されます
5. 自分のアカウントであれば、**確認**をクリックします。リンクが作成され、ダイアログがその旨を表示し、ボットも同じダイレクトメッセージで確認を返します
6. 自分のものでなければ、**拒否**をクリックします。何もリンクされず、そのコードは使えなくなります。やり直すには**新しいコードを取得**をクリックします

ダイアログを閉じても申請は失われません。後から届いたコードは、このカードの**自分のSlackアカウントを連携**の行で、同じ**確認**と**拒否**とともに待機します。

確認の手順がある理由: そうしなければ、肩越しに読まれたコードが他人の Slack アカウントから送られた場合に、そのアカウントがあなたとして動作してしまいます。確認できるのはあなただけであり、確認できるのはコードを送ったプロフィールそのものだけです。

コードは次のとおりです。

- 単回使用で、発行から **15 分**後に失効します
- 常に*あなた*のために発行され、チームメイトのために発行されることはありません
- ボットへのダイレクトメッセージでのみ機能します。チャンネルではただのメッセージです
- 申請できるのは、ボットがインストールされている Slack ワークスペースの正規メンバーだけです。ゲストや他の組織の人は申請できません
- すでに保持しているコードを置き換えるため、ボタンをもう一度押すと前のコードは無効になります
- メモリ上にのみ存在するため、サーバーが再起動すると未使用のコードは無効になります — ボタンをもう一度押してください

未知のコード、期限切れのコード、拒否されたコード、別のワークスペース向けに発行されたコードは、いずれも見分けのつかない同じ形で失敗します: "That code is not valid (or has expired)."

## メールアドレスによる自動リンク

Slack プロフィールに確認済みのメールアドレスがあり、それが**すでにこのワークスペースのメンバーである** Control Center ユーザーの検証済みメールアドレスと一致する場合、ブリッジは初めて話しかけた時点で自動的にリンクします。コードは必要ありません。

Control Center 側のメールアドレスが検証済みとみなされるのは、シングルサインオンまたは SCIM がそのアドレスを設定した場合、または、サーバーオーナーが**設定 → サーバー → ユーザー**でそのアドレスを確認した場合です。自分のプロフィールに入力しただけのアドレスは検証済みではないため、オーナーが確認するまでは何にもリンクされません。それまでは、コードによる連携を使ってください。

どちらの条件も欠かせません。メールアドレスの一致はアイデンティティを証明しますが、アクセスを付与するのはメンバーシップだけです。そのため、たまたまサーバー上にアドレスが存在するだけの部外者は何にもリンクされません。名簿には、各リンクがどのように作られたか（「メールアドレスで照合」または「コードで連携」）が表示されます。

自動リンクには `users:read.email` スコープが必要です。これがないと Slack はアドレスを開示しないため、コードによる経路だけが唯一の手段になります。

## 誰がリンクされているかを確認する

名簿はワークスペースの管理操作であるため、管理者カードにあります: **設定 → ワークスペース → 連携 → チャットブリッジ → 連携済みアカウント**。ここにはワークスペース内のリンク済みメンバーが全員一覧表示され、それぞれが対応する Slack アカウントと、リンクがどのように作られたかが示されます。

自分の状態は **設定 → 自分 → プロフィール** にあります: **自分のSlackアカウントを連携**の行は、リンク済みであれば「_your-slack-id_に連携済み」と表示され、リンクしていなければリンクするよう促します。

名簿と申請はライブ購読です。変更が反対側で起こるからです — コードを送るのは Slack 側であり、アプリからのどのリクエストもその結果を持ち帰ることができません。

## リンクを解除する

ワークスペースの名簿の行で**連携解除**をクリックします。

- 誰でも自分自身のリンクを解除できます
- 他のメンバーのリンクを解除できるのは管理者だけです
- リンクを解除すると、そのメンバーの未使用のリンクコードもすべて失効します

リンクを解除すると、その Slack アカウントは再びリンクするまでエージェントを動かせなくなります。既存のスペース、トランスクリプト、チケットは元の帰属を保ちます — リンクの解除は過去の作業の撤回ではありません。

## トラブルシューティング

### ボットから、このワークスペースのメンバーではないと言われる

Slack アカウントは Control Center ユーザーにリンクされていますが、そのユーザーはこのワークスペースのメンバーシップを持っていません。管理者に招待を依頼してください。[マルチプレイヤー — アイデンティティ、メンバーシップ、プレゼンス](/ja-JP/マニュアル/コンセプト/マルチプレイヤー/)を参照してください。

### ボットから、自分のロールが読み取り専用だと言われる

`viewer` と `guest` のロールでは作業を開始できません。管理者があなたのロールを `member` 以上に引き上げる必要があります。

### ボットからコードが有効でないと言われる

コードが期限切れになったか、すでに使われたか、拒否されたか、新しいコードに置き換えられています。もう一度**自分のSlackアカウントを連携**をクリックし、新しいコードを送ってください。

### ボットが自分のコードをリクエストとして扱う

コードをチャンネルで送ったか、あなたの Slack アカウントがすでにリンク済みです。コードはダイレクトメッセージでのみ受け付けられ、リンク済みアカウントからのコード形式のメッセージは通常のリクエストとして扱われます。
