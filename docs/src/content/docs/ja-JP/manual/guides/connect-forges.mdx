Control Center は 3 つのコードホストに対応しています。アプリ全体ではこれらを**フォージ**と呼びます: **GitHub**、**GitLab**、**Bitbucket Cloud** です。どれも既定ではありません。1 つ接続すればすべてが機能し、複数接続すれば 1 つのワークスペースでそれらすべてのリポジトリを同時に保持できます。

コードホストは各**リポジトリ**のプロパティであり、登録時にその `origin` リモートから読み取られます。自分で選ぶことはなく、ワークスペースごとに設定を間違える余地もありません。

## コードホストを接続

1. **設定 → 自分 → プロフィール**を開きます（`/settings/you/profile`）。
2. **コードホスティング**カードを探します。対応するコードホストは接続の有無にかかわらずすべて一覧表示されます。
3. **GitHub** では **GitHubにサインイン** を押します。**GitLab** または **Bitbucket** では **トークンを追加** を押してトークンを貼り付けます。

**GitHub はサインインのみです。** サインインは、サーバー自身の GitHub App か Control Center Connect を通じて行われます（どちらを使うかはサーバー所有者が設定します）。または、ワークスペース管理者が **設定 → ワークスペース → 連携** でこのワークスペース向けに選んだアプリを通じて行われます（[GitHub インテグレーションを設定](/ja-JP/マニュアル/ハウツーガイド/github-インテグレーション/)を参照）。貼り付ける GitHub トークンはありません。GitLab と Bitbucket は引き続き個人トークンを使います。

どちらの場合も、資格情報は**あなたのものでありサーバー上に存在し**、ユーザー ID をキーとして管理されます。入力したマシンにはトークンは保存されず、サインインしたすべてのデバイスが同じものを使い、他のメンバーが読み取ることもできません。反映されるのは**次のリクエスト**からで、再起動するものは何もなく、切断すれば送信は即座に止まります。

カードには、あなたのアカウントがどこで使われるかが表示されます。GitLab と Bitbucket のトークンは**サーバー上のすべてのワークスペース**であなたのものとして使われるため、一度貼り付ければ済みます。GitHub のサインインも同様ですが、ワークスペースが独自のサインインアプリを持つ場合は除きます。そのワークスペースは独自の GitHub サインインを保持し、カードにはその旨が表示されます。

各行には、**あなたの**資格情報の状態が表示されます。あなた自身の資格情報だけがあなたの代わりに応答し、ほかのものが代わりになることはありません:

| 行の表示                                                      | 意味                                                                                                                                                       |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `octocatとしてサインインしています`                           | あなた自身の資格情報が使われています                 |
| `未接続`                                                      | このコードホストに対する資格情報がありません                                                                                                               |
| `octocat としての GitHub のサインインが切れています。もう一度サインインしてください。` | サインインの期限が切れたか、コードホスト上で取り消されました                                                                                    |
| `一時停止中: このワークスペースのサインインサービスが変更されました`        | このワークスペースは別のサインインサービスに切り替わりました。あなたのサインインは保持されており、切り替えが戻れば再び機能します。そのため、サインインボタンはありません |
| `現在 GitHub に接続できません。再試行しています。`                          | 一時的な障害です。Control Center は再試行を続けるので、あなたにできることはありません                                                                      |
| サインインを利用できない理由を説明する文                                  | 例: `このワークスペースでは GitHub のサインインが設定されていません。` または `このワークスペースのサインインサービスの識別情報が変わりました。管理者の確認が必要です。` 管理者には、それを修正する設定へのボタンが表示されます |

### 各コードホストに必要なトークン

| コードホスト  | トークン                                                                                                              | 作成場所                                            |
| ------------- | --------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| **GitLab**    | `api` を持つパーソナルアクセストークン                                                                                | gitlab.com → User settings → Access tokens          |
| **Bitbucket** | Atlassian の API トークンと、アカウントのメールアドレス                                                               | id.atlassian.com → Security → API tokens            |

Bitbucket は**アカウントのメールアドレスをユーザー名として**、API トークンをパスワードとして認証するため、Bitbucket のダイアログでは両方を入力します。Bitbucket のリポジトリ、プロジェクト、ワークスペースのアクセストークンは、どの個人にも属さないため、このダイアログでは受け付けません。代わりに[自動化トークン](#自動化トークンを追加)として登録します。GitLab のプロジェクトまたはグループのアクセストークンも同様です。GitLab は保存前にそのトークンが誰のものかを確認し、ボットのトークンはここでは拒否されます。

トークンが 1 つのワークスペースに結び付けられることはありません。コードホストごとに 1 つ持ち、サーバー上のすべてのワークスペースがそれを使います。**切断** は、すべてのワークスペースについてそれを削除します。

### バックグラウンド作業

背後に人がいない作業（エージェント実行、パイプライン、PR のポーリング）にも資格情報が必要で、コードホストごとに答え方が異なります:

- **GitHub** — 一度に 1 つのリポジトリ用のトークン。サーバーの GitHub App から、または Connect を通じて発行され、責任を負うメンバーがそこでできることに制限されます。個人のサインインがそのまま渡されることはなく、環境変数や貼り付けたトークンが代わりになることもありません。[GitHub インテグレーションを設定](/ja-JP/マニュアル/ハウツーガイド/github-インテグレーション/#認証情報が誰の代わりに動くか)を参照してください
- **GitLab** と **Bitbucket** — そのリポジトリの**自動化トークン**だけを使います。ワークスペース管理者が、そのリポジトリ用に、またはワークスペース内の同じコードホストのすべてのリポジトリ用に追加するボットのアクセストークンです。リポジトリ自身のトークンがワークスペースのトークンより優先されます。プルリクエストのポーリング、AI レビューのコメント、誰も依頼していないプッシュとマージリクエストはすべてこのトークンを使うため、コードホスト上ではメンバーではなくそのボットとして表示されます。メンバー個人のトークンが代わりになることはなく、サーバー全体のトークンや環境変数のトークンもありません。トークンがなければ、そのリポジトリのバックグラウンド作業は一時停止し、リポジトリアクセスの通知にその旨が表示されます。

あなたが依頼した作業（コメント、レビュー、あなたのために開かれたエージェントのマージリクエスト）は、引き続きあなた自身のトークンを使います。

## 自動化トークンを追加

自動化トークンを見たり変更したりできるのはワークスペース管理者だけです。各トークンは保存時にコードホストで検証されます。個人として動作するトークン（GitLab のパーソナルアクセストークン、Atlassian の API トークン、または誰かのアカウントとしてサインインする Bitbucket トークン）は拒否され、対象のリポジトリを読み取れないトークンも拒否されます。

- **1 つのリポジトリ向け:** **設定 → ワークスペース → リポジトリ**を開きます。**自動化トークン**カードに、GitLab と Bitbucket のリポジトリごとに、そこで動作するボットが表示されます。状態は**ワークスペースのトークンを使用**または**トークンがありません。ここでは自動化が一時停止しています。**のいずれかです。リポジトリの行で**トークンを追加**を押します。
- **コードホストのすべてのリポジトリ向け:** **設定 → ワークスペース → 連携**を開き、**自動化トークン**カードで、GitLab または Bitbucket の行の**トークンを追加**を押します。保存後、トークンが読み取れないリポジトリには名前が表示され、一時停止のままになります。

バックグラウンド作業がすでに一時停止している場合は、リポジトリアクセスの通知にも**トークンを追加**が表示されます。**トークンを更新**はトークンを置き換え、ゴミ箱のボタンはトークンを削除します。トークンのないリポジトリは一時停止します。後からコードホストが保存済みのトークンを拒否した場合（取り消されたか期限切れ）、その行にそう表示され、そのトークンが担当していたリポジトリは、トークンを置き換えるまで一時停止します。

| コードホスト | 自動化トークン | 作成場所 |
| ------------ | -------------- | -------- |
| **GitLab**   | `read_api` と `read_repository` 権限を持つ**プロジェクト**または**グループのアクセストークン**。コメント、マージリクエスト、プッシュには `api` と `write_repository` を追加します | プロジェクトまたはグループ → Settings → Access tokens |
| **Bitbucket** | リポジトリの読み取り権限を持つ**リポジトリ**、**プロジェクト**、または**ワークスペースのアクセストークン**。コメントとプルリクエストには、プルリクエストの書き込み権限を追加します（プッシュにはリポジトリの書き込み権限） | リポジトリ、プロジェクト、またはワークスペース → Settings → Access tokens |

GitLab はボットユーザーとして作業を表示し、Bitbucket はアクセストークンの名前で表示します。

### Bitbucket: アクセストークンか API トークンか

Bitbucket には 2 種類のトークンがあり、Control Center はそれらを区別します:

- **API トークン**（id.atlassian.com）は、あなたの Atlassian アカウントに属し、メールアドレスと組み合わせて使います。**あなた自身の**認証情報であり、**設定 → 自分 → プロフィール → コードホスティング**に入力します。
- **アクセストークン**（リポジトリ、プロジェクト、ワークスペースの設定で作成）は、個人ではなくそのリポジトリ、プロジェクト、ワークスペースに属します。**自動化トークン**であり、**自動化トークン**に入力します。

それぞれのダイアログは、もう一方の種類のトークンを拒否し、どこに入力すべきかを示します。

## コードホストごとに別人になる

同じ人間でも、GitHub では `octocat`、GitLab ではまったく別の名前になります。Control Center はあなたのアイデンティティを**コードホストごと**に解決し、リポジトリごとに適切なものを使用します。これにより、混在したワークスペースでも「自分のレビューが必要」「自分が作成」「あなたが承認済み」が正しくなります。

コードホストのアイデンティティが解決されていない場合、そのリポジトリは受信トレイに何も寄与しません（すべてに一致させることはしません）。受信トレイは、あなたがすべて確認済みだと主張する代わりに、その旨を表示します。

## あなたのアカウントから見えるものだけが見える

リポジトリのプルリクエストは、ワークスペースのロールでそのリポジトリが許可され、**かつあなた自身のコードホスト上のアカウントがそれを読める**場合にのみ届きます。ワークスペースの管理者と所有者も同じルールに従います。一部のリポジトリが非表示の場合、受信トレイと PR キューは、リポジトリ名を挙げずに、その件数と理由を示します:

- **GitHub にサインインすると、さらに 3 件のリポジトリのプルリクエストが表示されます**: そのコードホストにはまだここで接続していません。サインインすると表示されます
- **GitHub アカウントから見えないため、3 件のリポジトリが非表示です**: そのコードホストで権限を持つ人に確認してください
- **このワークスペースでアクセス権がないため、3 件のリポジトリが非表示です**: ワークスペース管理者にアクセスを依頼してください
- **さらに 3 件のリポジトリへのアクセスを確認しています…**: Control Center があなたのアカウントが読める範囲を確認している間、一時的に表示されます

コードも同じルールに従います。リポジトリのファイル、差分、検索、またはそのリポジトリ上のターミナルを開くには、このワークスペースでそのリポジトリの権限を持ち、かつ自分のコードホスト上のアカウントがそれを読めなければなりません。ワークスペースの管理者も同様で、例外はサーバーオーナーだけです。確認のためにコードホストに到達できない場合は、コードホスト名を含む **フォージへのアクセスを確認できませんでした。もう一度お試しください。** のようなメッセージが表示されます。[コードはフォージに従います](/ja-JP/マニュアル/コンセプト/認可/#コードはフォージに従う)。

同じルールは、それらのプルリクエストから作られるすべてのものにも適用されます。レビュースペース、そのメッセージ、エージェントの実行は、あなたがそのプルリクエストを見られない間は表示されず、開いているレビュースペースは、アクセス権を失うと閉じます。そのプルリクエストに関するパイプラインの実行は、あなたの実行一覧から外れます。あなたのために働くエージェントも、それらのレビュースペースを読むことはできません。ワークスペースのリポジトリ一覧には、コードホストのアカウントがまだ到達できないものも含め、このワークスペースであなたがアクセスできるすべてのリポジトリが表示されます。

コードホストがレート制限中またはダウンしている場合、Control Center は直近の数分間に確認できた内容を表示し続け、その後は再確認できるまでそれらのプルリクエストを非表示にします。

## 1 つの受信トレイ、すべてのコードホスト

受信トレイと PR キューは、ワークスペースに存在するすべてのコードホストにファンアウトし、結果を 1 つのストリームに統合します。GitHub のプルリクエストと Bitbucket のプルリクエストは、ベンダーごとにまとめられるのではなく時間順に並び、隣り合って表示されます。

障害は隔離されます。ダウンしている、またはレート制限中のコードホストは、ほかのコードホストには影響せず、そのリポジトリは復旧するまで最後に判明した状態を保ちます。受信トレイ全体が空になることはありません。サーバーがもう到達できないリポジトリは、古いプルリクエストを表示する代わりに一覧から外れ、**リポジトリアクセスの通知**がそのリポジトリを修正方法とともに示します: GitHub App を組織にインストールする、リポジトリを App のリポジトリに追加する、停止中のインストールを再開する、責任を負うメンバーに再度サインインしてもらう、または GitLab や Bitbucket のリポジトリに自動化トークンを追加する、のいずれかです。管理者には、GitHub App の手順とトークンの追加へのボタンが表示されます。

## 各コードホストにできること

どのコードホストも基本のループはサポートしています。プルリクエストの一覧表示とオープン、差分の読み取り、インラインおよびトップレベルでのコメント、レビュー、マージ、クローズです。それ以外の部分は本当に異なっており、Control Center は、黙って失敗する操作を表示するのではなく、そのコードホストにできないことを非表示にします。

| 機能                                        | GitHub | GitLab | Bitbucket |
| ------------------------------------------- | :----: | :----: | :-------: |
| 一括（保留中）レビュー                      |   ✓    |   ✓    |     —     |
| 変更をリクエスト                            |   ✓    |   ✓    |     ✓     |
| ファイルごとの「閲覧済み」状態の同期        |   ✓    |   —    |     —     |
| 絵文字リアクション                          |   ✓    |   ✓    |     —     |
| チーム / グループのレビュアー               |   ✓    |   ✓    |     —     |
| レビュアーの提案                            |   ✓    |   —    |     ✓     |
| PR の CI 結果                               |   ✓    |   ✓    |     ✓     |
| CI ジョブのステップ/ログの詳細表示          |   ✓    |   ✓    |     —     |
| スタックされたプルリクエスト                |   ✓    |   —    |     —     |
| PR 説明テンプレート                         |   ✓    |   ✓    |     —     |
| 通知のポーリング                            |   ✓    |   —    |     —     |
| リッチなユーザープロフィール                |   ✓    |   ✓    |     —     |
| サーバー側の PR head ref                    |   ✓    |   ✓    |     —     |

機能が欠けている場合、その機能は正直に縮退します:

- **閲覧済み状態**は引き続き機能しますが、設定したデバイス上でのみです。
- Bitbucket の**一括レビュー**はコメントを 1 件ずつ投稿するため、レビュアーにはまとめてではなく個別に届きます。
- Bitbucket には**PR head ref がない**ため、プルリクエストをチェックアウトするとソースブランチを名前で取得します。これはそのブランチが削除されると失敗します。

## 用語

GitLab はプルリクエストを**マージリクエスト**と呼びます。Control Center は自身のモデル全体では「プルリクエスト」と呼び、コードホストについて述べるときは各コードホスト自身の呼び方を使います。

## トラブルシューティング

### PR 一覧が空で、コードホストが未接続と表示される

そのコードホストの資格情報がありません。**設定 → 自分 → プロフィール → コードホスティング**で GitHub にサインインするか、GitLab または Bitbucket のトークンを貼り付けてください。他のコードホストのリポジトリには影響しません。

### コードホストを接続したのに、そのリポジトリが何も表示されない

行の状態を確認してから、PR 一覧の上に表示される通知を確認してください。「GitHub にサインインすると、さらに … 件のリポジトリのプルリクエストが表示されます」は、そのリポジトリについて自分のアカウントがまだ接続されていないことを意味します。「… 件のリポジトリが非表示です（アカウントから見えないため）」は、そのコードホストがあなたにアクセスを与えていないことを意味します。GitHub では、リポジトリアクセスの通知が、GitHub App がリポジトリの組織にインストールされていない、またはリポジトリを含んでいないことを知らせます。

### GitLab または Bitbucket のリポジトリでバックグラウンド作業が一時停止している

リポジトリにはそれを読み取れる自動化トークンがありません。ワークスペース管理者が、リポジトリ用、またはワークスペース全体用のトークンを追加する必要があります。[自動化トークンを追加](#自動化トークンを追加)を参照してください。あなた個人のトークンでは一時停止は解除されません。バックグラウンド作業がメンバーのトークンを使うことはありません。

### リポジトリを登録できない

登録には次の 3 つすべてが必要です。パスが git ワークツリーの内部にあること、`origin` リモートがあること、そしてそのリモートが github.com、gitlab.com、bitbucket.org のいずれかを指していることです。`origin` は、リンクしようとしているリポジトリ自身でもなければなりません。また、ワークスペース自身のストレージの外にあるフォルダーは、サーバーオーナーだけがリンクできます。[ワークスペースにリポジトリを追加](/ja-JP/マニュアル/ハウツーガイド/リポジトリ追加/)を参照してください。

### 権限はあるのに、アカウントで読めないと表示される

自分のコードホストアカウントではそのリポジトリを読めないため、ワークスペースの権限にかかわらず、そのコードは開けません。上の **コードホスティング** からコードホストにサインインするか、コードホスト上でそのリポジトリへのアクセス権を取得してください。

### 「フォージへのアクセスを確認できませんでした」

アクセスを確認するためにコードホストに到達できなかったため、Control Center は推測せずに拒否しました。しばらくしてからもう一度お試しください。

### _repo_ は別のリポジトリを指すようになりました

そのパスの背後にあるリポジトリが変わりました。削除されて作り直されたか、移動されて差し替えられたかのいずれかです。ワークスペース管理者が通知またはリポジトリの行で **再リンク** を押すまで、Control Center はそれに何も送信しません。単純な名前変更や移管は自動的に追従され、この表示が出ることはありません。

### 集中的に使ったあと、しばらく何も動かなくなる

それはレート制限のサーキットブレーカーです。コードホストがプライマリ制限を通知すると、クライアントはウィンドウが経過するまで、ネットワーク呼び出しを行わずに以降のリクエストをローカルで失敗させます。これにより、リトライの嵐が制限を深刻化させることはありません。一時的な失敗は指数バックオフで再試行されます。
