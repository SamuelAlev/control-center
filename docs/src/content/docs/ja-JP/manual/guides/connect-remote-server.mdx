どのクライアントも、データを所有する `cc_server` の上で動くレンダラーです。デスクトップは
自身の中で `cc_server` を起動できますが、[app.usectrl.dev](https://app.usectrl.dev) の
Web アプリはできません。ブラウザーのタブはサーバーをホストできないからです。いずれの場合も、このガイドでは
クライアントを別の場所で動いているサーバー — 小さなマシン、クラウド VM、ビルドサーバー — に向けます。

## 前提条件

- 稼働中の `cc_server`。まだない場合は、[ヘッドレスサーバーを実行](/ja-JP/マニュアル/ハウツーガイド/ヘッドレスサーバー実行/) を参照してください。
- サーバーが発行した 3 つのペアリング値 — **サーバー URL**（`ws://…/rpc` または `wss://…/rpc`）、**デバイス ID**、**ペアリングキー** — **または**、ワークスペース管理者からのワンタイムの**招待コード**、**または**それらを含む招待リンクかペアリングリンク。招待を引き換えると、あなたのユーザーがプロビジョニングされ、メンバーシップが記録され、このクライアントの資格情報が発行されるため、デバイス ID やキーを自分で扱う必要はありません。これらは信頼できるチャネルで入手し、初回接続時にサーバーのフィンガープリントを信頼できる QR コードや既知のピンと照合してください。

### サーバーに到達できることを確認する

ローカルサーバーには何も必要ありません。ブラウザーはループバックを信頼できるオリジンとして扱うため、`ws://localhost:9030/rpc` は
デスクトップとブラウザーの両方から動作します。

別のマシン上のサーバーは話が別です。`app.usectrl.dev` は HTTPS で提供されるため、
ブラウザーはすでに信頼している証明書を持つ `wss://` ソケットしか開きません — そして `cc_server` は
そもそも TLS なしで非ループバックアドレスをバインドすることを拒否します。次のいずれかを用意してください:

- `--tls-cert` と `--tls-key` を使って証明書を直接渡す
- 前面に TLS 終端のリバースプロキシを置き、サーバーを `--insecure` で起動する（外側のリスナーではプロキシとサーバーの間が平文。信頼できるネットワークでのみ。これは必須の暗号化クライアントセッションを無効にしません）
- 証明書を提供するトンネルまたは VPN — Tailscale、cloudflared など。**設定 → サーバー → 接続とステータス**の
  **このサーバーを共有**に、組み込みのトンネルのオプトインがあります。

サーバー側には、見落としやすい設定が 2 つあります。プロキシ、NAT、トンネルの背後では、
`--public-url` にクライアントが実際に接続すべきアドレスを設定してください — 既定では
ローカルのバインドになるため、設定しないとクライアントは誤ったホストに接続しようとします。また、Web ビルドを
自分でホストする場合は、そのオリジンを `--allowed-origins` に追加してください。既定では
`https://app.usectrl.dev` のみで、ループバックとネイティブクライアントは常に許可されます。

## デスクトップアプリを接続する

新規インストールの場合:

1. Control Center を起動します。初回起動画面に **Control Center へようこそ** と表示されます。
2. **サーバーに接続**をクリックし、サーバー URL と、招待コード、または**ペアリングキーを使用**でデバイス ID とペアリングキーを入力します。
3. **接続**をクリックします。Control Center はサーバーに接続し、ワークスペースの受信トレイに移動します。

招待リンクまたはペアリングリンクがある場合は、代わりに**ペアリングリンクを貼り付け**をクリックして貼り付けます。ダイアログにはリンク先のサーバーが表示されます。確認してから**接続**をクリックしてください。貼り付けただけでは接続されません。接続に失敗した場合、ダイアログはエラーと入力内容をすべて保持したまま開いています。

すでに自身でサーバーを実行しているデスクトップの場合:

1. **設定 → サーバー → 接続とステータス**を開きます。
2. **サーバーを追加**をクリックします。サーバー URL（`wss://host:9030/rpc`）と、招待コード、または**ペアリングキーを使用**でデバイス ID とペアリングキーを入力します。URL フィールドの末尾のボタンは、LAN または tailnet 上の `cc_server` インスタンスを検出します。
3. **接続**をクリックし、次に新しいサーバーの行の**切り替え**をクリックします。

切り替えはライブで行われます。アプリは再起動せず、新しいセッションを中心にその場で再構築されます。
接続に失敗した場合は、現在のサーバーにとどまり、エラーが表示されます。
接続中のサーバーの行には**切り替え**の操作はありません。ローカルサーバーは最初の行で、**このアプリ内で実行**というラベルが付いています。

切り替えた後は、デスクトップはデータベースを所有しません。すべての画面は、
署名済みでエンドツーエンドに暗号化された WebSocket セッションを介して
リモートサーバーを読み書きします。同じ保護はループバック経由でもリレー経由でも適用されます。

## Web クライアントを接続する

Web ビルドは常にリモートです。

1. [app.usectrl.dev](https://app.usectrl.dev)、または自分でホストしている Web ビルドのコピーを開きます。
2. **サーバーに接続**をクリックし、サーバー URL と、招待コード、または**ペアリングキーを使用**でデバイス ID とペアリングキーを入力します。招待リンクやペアリングリンクは、代わりに**ペアリングリンクを貼り付け**で受け付けます。
3. **接続**をクリックします。クライアントはサーバーに接続し、デスクトップと同じインターフェースを描画します。

URL にペアリング用のディープリンクがある場合、接続ダイアログはフィールドが入力された状態で開くので、**接続**をクリックする前にサーバーを確認できます。ペアリングキーは
URL の**フラグメント**に乗ります。ブラウザーはこれをページをホストするサーバーに送信しません。リンクは秘密として扱い、
Web クライアントを配信するページを信頼してください。フラグメントは悪意のあるページコードからあなたを守りません。

:::note[メディア、エディター、セキュリティ]
メディア（アバター、フィードの画像、PR のスクリーンショット）、バックアップ転送、埋め込みエディターのトラフィックは、
読める形の公開 HTTP ルートではなく、暗号化されたリソーストンネルを使います。信頼されたブラウザーエディターは Web アプリ自身のオリジンで動作し、
その Service Worker が、認証済みの暗号化セッションを通してリクエストを
`cc_server` 上の code-server バックエンドへ運びます。Service Worker を
利用できるよう、Web クライアントは HTTPS または安全なループバックで
ホストしてください。ネイティブクライアントは
ケイパビリティで制限されたループバックファサードを使います。
:::

### ブラウザーが行わないこと

Web クライアントはデスクトップと同じサーバーを読み書きしますが、いくつかの
サーフェスにはネイティブウィンドウか、そのマシン自身のデバイスが必要です:

- OS の通知トースト、通知音、常時表示のバナー列はありません（アプリ内の通知センターは引き続き動作します）
- **サーバーを追加**ダイアログでの LAN または tailnet のサーバー検出はありません
- アプリ内の記事リーダーはありません — ニュースフィードの記事は新しいタブで開きます
- ミーティング要約の再実行、および処理中の要約のキャンセルはできません

2 つは存在しないのではなく、動作が異なります。ミーティングの**録音**は
ブラウザーで動作し、マイクと、音声トラックを含む画面共有を取り込みます。**IDE で開く**も動作しますが、
サーバーに対して_サーバー自身の_ディスプレイでエディターを起動するよう要求するため、
エディターがインストールされていないヘッドレスホストに対しては、このボタンは表示されません。

## トラブルシューティング

- **接続がタイムアウトする**: サーバーにクライアントから到達できる必要があります。バインド（`--bind any`）、ポートが開いていること、`--public-url` がクライアントから実際に接続できるアドレスを指していることを確認してください。オープンなインターネット経由では TLS が必須です — 平文の非ループバックバインドは、プロキシの背後で `--insecure` を付けてサーバーを起動しない限り、起動時に拒否されます。
- **ブラウザーは接続を拒否するが、ネイティブクライアントは動作する**: ブラウザーのオリジンがサーバーの `--allowed-origins` リストにありません。既定では `https://app.usectrl.dev` のみが許可されます（加えてループバック）。
- **サーバーの識別情報が変わった**: クライアントは、保存したピンと異なるフィンガープリントを拒否します。サーバーの識別情報を帯域外で検証し、信頼できるチャネルで再ペアリングしてください。警告を無視したり、旧クライアントや平文クライアントに切り替えたりしないでください。
- **ペアリングキーが拒否される**: サーバーで `cc_server pair` を再実行してそのデバイスのキーをローテーションし、新しいキーを入力してください。失効したデバイスは資格情報が失われていることを検出し、フェイルクローズします。失効は数秒以内にライブセッションを切断します。
- **ワークスペースが違う**: ワークスペースは URL の一部（`/workspaces/:workspaceId/…`）であり、すべての呼び出しに付随するため、あるクライアントでワークスペースを切り替えても、変わるのは自分自身の表示だけです。到達できるのは自分がメンバーであるワークスペースだけです — それ以外は "Not a member of this workspace" で拒否されます。[ワークスペースと分離](/ja-JP/マニュアル/コンセプト/ワークスペース/) を参照してください。
