このガイドでは、GitHub から離れずに Control Center を操作する方法を説明します。
PR ページから AI レビューを依頼し、コメントでボットに質問し、そのレビュースレッドで
会話を続けられます。

返信はワークスペースの GitHub レーンを通じて届きます。あなたのサーバー自身の
[GitHub App](/ja-JP/マニュアル/ハウツーガイド/github-app/)、または Connect を通じた Control Center の
共有 App です。新しく登録するものは何もなく、インターネットから到達可能でなければ
ならないものもありません。サーバーはポーリングによって GitHub 上で発言された内容を
検出するため、NAT の背後にあるノート PC も公開デプロイとまったく同じように動作します。

## 前提条件

- ワークスペースに GitHub レーンがあること。サーバー自身の GitHub App か Connect で、
  リポジトリを所有するアカウントにアプリが[インストール](/ja-JP/マニュアル/ハウツーガイド/github-app/#リポジトリがある場所にインストールする)
  されている必要があります。自前の App には **Pull requests** と **Issues** の読み取りと
  書き込みが必要で、**自分のGitHubアプリを作成** はこれらをすでに付与します
- リポジトリが Control Center のワークスペースにリンクされていること
- このサーバーで [GitHub にサインイン](/ja-JP/マニュアル/ハウツーガイド/github-インテグレーション/)
  しており、そのリポジトリにプッシュできること
- Webhook URL もトンネルもコールバックも不要 — ネットワーク側で設定するものは
  何もありません

## ボットの名前を調べる

Control Center 専用の GitHub アカウント `@usectrl` をメンションします。これがデフォルトの起動方法です。リクエストの処理と返信の投稿は、引き続きワークスペースの GitHub レーンが行います。`usectrl` アカウントの認証情報は不要です。

App 固有のログイン名 `<appslug>[bot]` と短縮形 `@appslug` も使えます。自前の App でこの任意の別名を確認するには:

1. **設定 → サーバー → シングルサインオン**に移動し、**プロバイダーアプリ**カードまで
   スクロールします
2. **GitHub** ブロックを開き、**テスト**をクリックします
3. **ボットログイン**が入力されたらコピーします。空のヒントが表示されたままの
   場合は、ログイン名は常に `<appslug>[bot]` です — それを入力するか、短縮形の
   `@appslug` を入力します

GitHub の `@` オートコンプリートには App アカウントが表示されないため、App の別名は手入力するかコピーする必要があります。専用ユーザー `@usectrl` がデフォルトの呼び出し先です。`@myapp` と `@myapp[bot]` も引き続き App の別名として使用できます。

:::note[特徴のあるアプリ名を付ける]
短縮形はテキストとして照合されます。GitHub の人間のユーザーがたまたまあなたの
アプリのスラッグと同じ場合、そのユーザーを短縮形でメンションするとボットにも
届きます。完全な `@myapp[bot]` 形式は常に曖昧さがありません。
:::

## GitHub からレビューを依頼する

2 つの方法があり、どちらも **AIに質問**ボタンが開始するのと同じ、シード済みの
`pr_review` パイプラインを開始します。

- **PR に `ai-review` ラベルを追加する**。これは、ボットをレビュアーとして割り当てる
  ために GitHub が提供する最も近い手段です — アプリのアカウントは、GitHub
  ネイティブの「レビュー依頼」スロットを保持できません。あなたのアカウントが PR に
  👀 でリアクションし、レビューは Control Center で開始されます。コメントは投稿されません
- **PR 会話に `@usectrl review`**（または単に `@usectrl`）**をコメントする**。あなたの
  コメントに 👀 が付き、続いてレビューが開始された（またはすでに実行中である）という
  返信が届きます

レビュアーはその PR のレビュースペースで作業します。指摘の読み方と公開の仕方は
[AI レビューを使う](/ja-JP/マニュアル/ハウツーガイド/ai-レビュー/) と同じです。GitHub への公開は
Control Center で下す判断のままです — GitHub からレビューを開始しても、それだけで
GitHub に何かが公開されることはありません。

ラベルは PR ごとに 1 回だけ発火します。追加することが依頼であり、外して付け直しても
再び武装されることはありません。レビューをもう一度実行するには — たとえば push の後
など — ボットをメンションします。

## 質問する

PR 会話にコメントします:

```text
@usectrl why does the flaky test in runner_test.dart fail on CI but not locally?
```

何が起きるか、順番に:

1. あなた自身のアカウントからコメントに 👀 が付き、コメントが見られたことがわかります
2. 質問は**あなたとして**その PR のレビュースペースに投稿されます — Control Center
   で入力した場合と同じ帰属です
3. エージェントがスペースで回答し、その回答が PR に返信されます。すべての返信は
   `**Control Center** (for @your-login):` で始まります

まだレビューのない PR での質問は、ワークスペースの CEO エージェントを起こします。
レビューが一度実行された後は、最後に発言したエージェントが答えるため、
フォローアップはコンテキストを持っている相手に届きます。

## レビュースレッドでフォローアップする

ボットが参加しているインラインのレビュースレッドの中で返信します — ボットが残した
diff コメント、またはそのスレッドに投稿した回答です。メンションは不要です。
スレッド**自体が**宛先指定です:

```text
> @usectrl the retry loop looks O(n²) to me

what would the complexity be with the bounded queue instead?
```

マルチターンも同じように機能します。各返信は同じ会話におけるもう 1 つの質問であり、
レビュースペースがコンテキストとなり、回答はそのスレッドに返ってきます。

PR 会話のタイムラインでのフォローアップは新しいトップレベルのコメントになるため、
依然として @メンションが必要です。

## ボットが応答する相手

サーバーは、何かを行う前に、コメントの作者、または `ai-review` ラベルを付けた人を
解決します:

- **その GitHub アカウントが、このサーバーでサインインしている**必要があります。照合には
  ログイン名ではなく、GitHub の数値のアカウント id が使われます。**設定 → ワークスペース →
  プロフィールと識別情報 → コードホスティング**からサインインします
- そのリポジトリをリンクしているワークスペースで、**書き込みロールを持つ
  メンバー**（`member`、`admin`、`owner`）である必要があります
- GitHub 上でそのリポジトリに**プッシュできる**必要があります。返信にはその人の
  アクセス権に制限されたトークンが使われるため、読み取りしかできない人には返信が届きません

それ以外の相手は黙って無視されます。何も投稿されず、その発言がワークスペースに
入ることもありません。ボットからのコメントや、Control Center 自身の返信が質問として
扱われることはありません。

### 2 つのサーバー、1 つの PR

👀 は、どのサーバーが応答するかをサーバー同士が合意する手段でもあります。これは作者
自身のサインインで付けられ、GitHub はそのリアクションが新しいかどうかをサーバーに
伝えます。どちらもそのリポジトリをリンクしている 2 つの Control Center サーバーに
サインインしている場合、最初にリアクションを付けたサーバーが応答し、もう一方は沈黙します。
ラベルについても同じです。

## 想定される動作

| 項目                 | 動作                                                                     |
| -------------------- | ------------------------------------------------------------------------ |
| 確認                 | 1 回のスイープのうちに、あなたのアカウントからコメント（ラベルの場合は PR）に 👀 |
| 回答                 | 質問が投げかけられたレーンに、`**Control Center** (for @your-login):` で始まる形で投稿されます。自前の App では作者は App のボットで、Connect を通じる場合は共有 App を通じて動作するあなたのアカウントです |
| スペース内の帰属     | 質問はあなたのものです。エージェントはあなたの代理として、スペースの自律度設定のもとで実行されます |
| レビュー             | 指摘はレビュースペースに届きます。GitHub への公開は手動です               |

スイープは、自前の App では 1 分ごとに実行され、最大 25 件のプルリクエストを確認します。
Connect を通じる場合は 2 分ごとに実行され、最大 10 件を確認します。これらの呼び出しは
各メンバー自身の GitHub クォータを共有するためです。GitHub クォータの残りが 15% を
下回ったワークスペースは、回復するまでスキップされます。このレイテンシは、受信方向の
ネットワークアクセスを一切必要としないことの代償です。サーバーがオフラインの間に
失われるものはありません — 停止中に届いたコメントは、次のスイープで拾われます。

## トラブルシューティング

**ボットをメンションしたコメントに対して何も起きない。**

- アプリは、そのリポジトリを所有するアカウントに**インストール**されていますか。
  また、そのリポジトリはワークスペースに**リンク**されていますか。
  リンクされていないリポジトリは、何かが記録される前にスキップされるため、
  後からリンクしてもコメントは配信されます
- あなたはこのサーバーで GitHub にサインインしていて、書き込みロールを持つメンバーで、
  そのリポジトリにプッシュできますか。サーバーはそれ以外の人を、返信せずに無視します
- Control Center の共有 App の場合、組織のインストールはこのサーバーに対して承認されて
  いますか。[組織に対してこのサーバーを承認する](/ja-JP/マニュアル/ハウツーガイド/github-app/#組織に対してこのサーバーを承認する)
  を参照してください
- それでも何も起きない場合は、何かが失敗したときにサーバーログにスイープと PR が
  記録されます。`pr_conversation:`（ポーラー）と
  `github_pr_conversation:`（ブリッジ）を探してください

**ラベルを付けてもレビューが開始されない。**

これは PR ごとに 1 回だけ発火し、それを付けた人にはコメントの作者と同じチェックが
適用されます。レビューがすでに実行されたか、サーバーが PR を認識する前にラベルが
追加された場合（最初のスイープは未処理分を一斉に処理せず、黙って記録します）は、
代わりにボットをメンションしてください — `@usectrl review` は、レビューがすでに
進行中でない限り、必ず開始します。

**ボットの回答が GitHub に届かない。**

回答自体が失われることはありません — Control Center のその PR のレビュースペースに
あります。投稿の失敗（GitHub の障害、権限の変更）はログに記録され、
返信は再試行されません。重要であれば、スレッドでもう一度質問してください。
