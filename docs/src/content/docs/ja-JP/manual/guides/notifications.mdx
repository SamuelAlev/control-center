このガイドでは、通知を設定する方法と、各設定が実際に何を制御するのかを説明します。

通知は 2 つのサーフェスに届きます。**通知センター**（タイトルバーのベル）は、
サーバー上のワークスペースごとの永続フィードを読み取ります。**OS トースト**は
それとは別のデスクトップ専用のパスで、サーバーからプッシュされるライブフレーム
によって供給されます。

:::note[Web ビルドでは OS 通知が表示されません]
トーストのパイプラインを構築するのはデスクトップのブートストラップだけです。
`app.usectrl.dev` では OS トーストも通知音もアンビエントバナーもありません。
ベルとその履歴は、サーバーのフィードを読み取るため引き続き機能します。
スマートフォンクライアントには通知サーフェスがまったくありません。
:::

## カテゴリをオンまたはオフにする

1. **設定 → 自分 → 通知**を開きます
2. **通知を有効にする**をオンのままにします
3. 必要なカテゴリを切り替えます。カテゴリはちょうど 16 個あります：

| カテゴリ                  | 発火する条件                                                                |
| ------------------------- | -------------------------------------------------------------------------- |
| エージェント完了          | あなたが開始した実行でエージェントが返信した、または実行が失敗した                             |
| PR公開                    | エージェントが PR を公開した                                               |
| PRマージ                  | PR がマージされた                                                          |
| 新しいメッセージ          | スペースで誰かがあなたをメンションした                                   |
| プルリクエストでメンション | GitHub の通知ポーリングで、PR であなたがメンションされたことを検知した      |
| レビュー依頼              | 下書き以外の PR で、あなたのレビューが実際に依頼された                      |
| レビューが古くなっています | すでにレビューしたプルリクエストに新しいコミットが追加された               |
| マージ可能                | あなたが作成したプルリクエストがマージ可能になった、またはマージ可能でなくなった |
| レビュー判定              | レビュアーが承認した、変更を依頼した、または承認が取り消された              |
| チェック                  | あなたが作成したプルリクエストで CI が失敗した、または復旧した             |
| レビュースレッド          | あなたが参加しているスレッドに誰かが返信した、または解決した               |
| チケット割り当て          | チケットが割り当てられた                                                    |
| チケットのステータス変更  | チケットのステータスが変わった                                             |
| まもなく会議開始          | カレンダーの会議が事前通知の時間内に入った                                 |
| カレンダー切断            | 接続済みカレンダーの OAuth トークンが期限切れになった                      |
| エンクロージャーの更新    | エンクロージャーが引き継がれ、回収され、または失敗した                     |

このリストにないものは通知もフィルタリングもできません。「その他」というカテゴリは
存在しません。

これらの設定はユーザーに紐づいてデバイス間で引き継がれるため、スマートフォンと
ノート PC の設定は一致します。音量だけは意図的に例外で、デバイスごとに保持されます。

## Quiet hours を設定する

1. 同じページで **Quiet hours** をオンにします
2. 開始時刻と終了時刻を `HH:MM` 形式で入力します（既定の時間帯は 22:00–08:00）

Quiet hours の間は、緊急でない通知は破棄されます。後で再送するためにキューに
入れられることはありません。

2 つのカテゴリは**緊急**であり、常に配信され、Quiet hours とフォーカスモードの
_両方_を迂回します。**まもなく会議開始**と **PR公開**です。会議の通知は後から
見ても意味がないため、これがその理由です。

## 通知音を選ぶ

1. **通知音**までスクロールします
2. 同梱の 11 種類のサウンドから 1 つを選ぶか、**なし**を選択します
3. テストボタンを押して試聴し、スライダーで音量を設定します

サウンドはアプリ自体が再生します。OS 通知は無音で配信されるため、二重に
聞こえることはありません。

## 会議の事前通知時間を設定する

1. **事前通知時間**までスクロールします
2. **5**、**10**、**15**、**30** 分から選択します

これは、カレンダーの予定の何分前に **まもなく会議開始** 通知が発火するかを
示します。既定値は 5 分です。

## 通知が抑制される条件を知る

次のいずれかに当てはまる場合、通知は何も表示されずに破棄されます：

- 通知が全体でオフになっている、またはそのカテゴリがオフになっている
- すでにその通知が移動させる先のルートにいる（メッセージの場合は、すでにその
  スペースにいる）
- フォーカスモードが有効で、そのカテゴリが緊急ではない
- Quiet hours が有効で、そのカテゴリが緊急ではない

これらのチェックが適用されるのは OS トーストです。永続的なベルには引き続き
イベントが記録されます。

さらに上流、サーバーがそもそも送信する内容の段階にも、2 つの抑制があります：

- 別の**人間**からの、メンションのないメッセージは通知になりません
- 共有スペースでは、エージェントの返信はメンバー全員ではなく、その実行を
  開始した人にだけ通知されます
- エージェント同士のスペースはサイドバーでミュートされているため、人間の
  未読バッジが増えることはありません

スペース内に通知が届かない一角はありません。スレッドを含め、すべての会話が
等しく通知します。既読状態はスペース単位なので、未読は会話ごとではなく、
スペースの会話全体で集計されます。

## 通知センターを確認してクリアする

1. タイトルバーのベルをクリックします

ポップオーバーには最近のアクティビティが表示され、各項目はその対象へ
ディープリンクします。開いてもすべてが既読になるわけでは**ありません**。
ヘッダーの**すべて既読にする**を使うか、個別の行を既読にします。既読状態は
ユーザーに紐づいてデバイス間で引き継がれます。

:::note[すべてクリアは削除ではなくウォーターマーク]
**すべてクリア**はユーザーごとのウォーターマークを刻み、それより古いものを
すべて隠します。行自体は残ります。これとは別に、各ワークスペースは直近の
**200** 件のフィード行だけを保持し、新しい行が届くたびに古い行が削除されます。
ベルが購読するのは最新の **50** 件で、ポップオーバーにはそのうち最大 **15** 件が
表示されます。それより古い履歴は、既読状態にかかわらず失われます。
:::

## トラブルシューティング

### macOS で OS 通知が届かない

認可はアプリの起動時にネイティブに要求されます。拒否した場合は、システム設定 →
通知 で Control Center を再度有効にしてください。アプリ内から再要求する
プロンプトはありません。

### Web ビルドでは何も届かない

想定どおりの動作です。Web ビルドには OS 通知のパイプラインがありません。
ベルを使用してください。

### ベルバッジが 0 なのに新しいアクティビティが明らかにある

接続後に既読マークのストリームが解決するまでは、バッジが一瞬表示されてから
空になるのを避けるため、項目は既読として描画されます。マークが読み込まれると
落ち着きます。

### エージェントの実行が完了したのに通知が来ない

すでにその実行が行われたスペースにいなかったか確認してください。そのルートが
アクティブな場合、そのルート自身の OS トーストは抑制されます。共有スペースでは、
他の人が開始した実行の通知はその人に届き、あなたには届きません。返信もエラーも
なく終わったターンは何も送信しません。
