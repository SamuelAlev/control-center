このガイドでは、実行を手動で開始する方法を扱います。実行の監視、ステップ出力の
読み取り、失敗からの復旧については、[パイプライン実行を監視](/ja-JP/マニュアル/ハウツーガイド/パイプライン監視/)を参照してください。

## 実行を開始する

1. ワークスペースのサイドバーで**パイプライン**をクリックします。
2. ヘッダーの**パイプラインを実行**を押します。ランチャー
   （`/workspaces/<workspace-id>/pipelines/run`）が開きます。
3. 左のレールからテンプレートを選びます。各カードには、テンプレートの名前、説明、
   入力を取るかどうかが表示されます。
4. 右側の入力フォームに入力します。必須フィールドは値が入るまでボタンをブロックし、
   入力を持たないテンプレートはその旨を表示します。
5. **パイプラインを実行**を押します。

実行の詳細ページが開き、タイミングウォーターフォールとグラフキャンバスがライブで
表示されます。

## レールが空の場合

ランチャーがテンプレートを表示するのは、**両方**が真の場合だけです：

- **設定 → ワークスペース → パイプラインテンプレート**で、テンプレートのスイッチが
  オンになっている。
- テンプレートエディターの**手動実行**ダイアログで、**手動実行を許可**がオンになって
  いる — ランチャーが読む `manual` トリガーを作るのは、このスイッチです。

13 個の組み込みテンプレートのうち 8 個は無効の状態で提供されます：`external_pr_welcome`、
`cross_review`、`ticket_to_pr`、`pr_triage`、`pre_merge_gate`、`release_notes`、
`dep_audit`、`pr_digest` です。エンジンは無効なテンプレートの開始を拒否するため、
ここで探す前にスイッチをオンにしてください。

テンプレートの一覧にテンプレートごとの**実行**アクションはなく、エディター内にも
実行ボタンはありません — ランチャーが唯一の手動の入り口です。

## リポジトリの入力を埋める

**リポジトリ**型の入力は、ワークスペースに登録されたリポジトリを対象とするピッカーを
表示します。1 つ選ぶと、`repo_id`、`repo_local_path`、`repo_full_name`、そして
リポジトリに GitHub リモートがある場合は `repo_owner` と `repo_name` が実行
ペイロードに設定されるため、下流のステップは必要なものを読み取れます。

## 実行の様子を見る

実行の詳細ページは 3 つの部分で構成されます：メタストリップ（開始時刻、アクティブ
時間、ステップの進捗、失敗のバナー、**再試行**と**削除**）、ステップごとの所要時間と
コストを示す折りたたみ可能なタイミングウォーターフォール、そしてグラフキャンバス
です。ノードを選択すると、そのステップの詳細パネルが開きます。

[パイプライン実行を監視](/ja-JP/マニュアル/ハウツーガイド/パイプライン監視/)では、
一時停止したステップの読み方や、ステップが失敗したときの対処を含め、そのすべてを
説明しています。

アプリから開始する実行はすべて実際の実行です。
