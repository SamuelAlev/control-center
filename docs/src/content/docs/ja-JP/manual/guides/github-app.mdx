このガイドでは、サーバーに独自の GitHub App を持たせる方法を説明します。所要時間は約 2 分で、作業するのはサーバー所有者だけであり、サーバーごとに 1 回だけ行えば済みます。

:::note[不要な場合もあります]
Control Center Connect をオンにしている場合、人々は Control Center の共有 App、または組織の Connect が使う App を通じて GitHub にサインインします。**自分のアプリを使う** を選んだ場合は独自の App を登録します。サーバー自身の App が使われるのはその場合だけです。[Control Center Connect](/ja-JP/マニュアル/リファレンス/connect/) を参照してください。
:::

その後に自分のアカウントでサインインする方法については、[GitHub インテグレーションを設定](/ja-JP/マニュアル/ハウツーガイド/github-インテグレーション/) を参照してください。

## App の役割

1 回の登録が、2 つの異なる役割を担います:

| 役割                   | 何が応えるか                                | なぜ重要か                                                                                       |
| ---------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **人がサインインする** | App のクライアント ID とクライアントシークレット | 全員が、サーバー上で、すべてのデバイスで使える自分自身の GitHub 資格情報を得られます             |
| **サーバーが動作する** | App の ID と秘密鍵                          | エージェント、パイプライン、ポーラー、ボットの返信が、一度に 1 つのリポジトリ用のトークンを得ます |

2 つ目の役割が、個人の資格情報を丸ごと借りることはありません。サーバーが発行する各トークンは 1 つのリポジトリを対象とし、責任を負うメンバーがそこでできることに制限されます。リンクされたリポジトリの読み取りに必要なのは App だけで、書き込みを伴う操作にはプッシュできるメンバーが必要です。自動化がプルリクエストを承認することはありません。

サーバー自身の App が適用されるのは **自分のアプリを使う** の場合だけです。Control Center のものまたはカスタムの Connect を使う場合、Connect が GitHub を含むすべてのレーンを担当し、サーバーの App は切り替えて戻すまで保存されたまま使われません。[1 つのワークスペースに独自の App を使わせる](#1-つのワークスペースに独自の-app-を使わせる)で独自のアプリを使うワークスペースは、サーバーのモードにかかわらず、その App を使います。一部のフィールドが欠けた App はエラーであり、フォールバックはしません。すべてのフィールドがそろうまで、GitHub へのサインインは拒否されます。

## 前提条件

- あなたが**サーバー所有者**であること。**プロバイダーアプリ** カードはほかの誰にも表示されません
- GitHub アカウント。App はその下に作成されます
- ブラウザーから到達できるサーバーのアドレス。サーバーの公開 URL（デスクトップ自身のサーバーならループバック）が、GitHub があなたを戻す先になります

## ワンクリックで作成する

1. **設定 → サーバー → シングルサインオン** に移動し、**プロバイダーアプリ** カードまでスクロールします
2. **GitHub** ブロックで、App を所有させたい GitHub 組織を必要に応じて **Organization（任意）** に入力します。空のままにすると自分のアカウントの下に作成されます。組織の下に作成するには、その組織のオーナーである必要があります
3. **自分のGitHubアプリを作成** をクリックします
4. ブラウザーで、App の内容が入力済みの GitHub が開きます。**Create GitHub App** をクリックします
5. GitHub がサーバーに戻し、サーバーは App ID、秘密鍵、クライアント ID、クライアントシークレットを保存してから、App のインストールページを開きます

手作業でコピーするものは何もなく、変換コードは GitHub から直接サーバーに届きます。このリンクは 1 回だけ有効で、10 分後に失効します。失効した場合は、もう一度 **自分のGitHubアプリを作成** をクリックしてください。

App の名前は `Control Center <code>` となり、Control Center が使うものだけを要求します:

| 権限                                       | アクセス       |
| ------------------------------------------ | -------------- |
| Metadata                                   | Read           |
| Contents                                   | Read and write |
| Pull requests                              | Read and write |
| Issues                                     | Read and write |
| Checks, Actions, Commit statuses           | Read           |
| Organization members                       | Read           |

Webhook はオフです。サーバーはポーリングします。自分のアカウントの下に作成した App を後から組織に移すには、GitHub 上の App の詳細設定にある **Transfer ownership** を使います。

チェックポイント: GitHub ブロックに「サーバーが自身として動作でき、人がサインインできます。」と表示されます。

## リポジトリがある場所にインストールする

登録されただけでインストールされていない App は、人をサインインさせることはできても、何も読み取れません。

1. GitHub が開いたインストールページで、リポジトリを所有するアカウントまたは組織を選びます
2. **All repositories** を選ぶか、このサーバーが見るべきリポジトリを選択します

後から別のアカウントにインストールするには、ワークスペース管理者が **設定 → ワークスペース → 連携** に移動し、**コードホスティング** の下の **GitHub App** カードで **GitHubアプリのインストール** を見つけて **GitHubアプリをインストール** をクリックします。一覧には App がインストールされているすべてのアカウントが表示され、一時停止されたインストールには印が付きます。

## 組織のインストールを共有する

組織は GitHub App を一度インストールします。その後、Control Center サーバーで GitHub にサインインした組織の誰もが、そのサーバーが自分のものでも同僚のものでも、あるいは自分たちのものでも、インストールを使えます。サーバーごとに承認する必要はありません。

サーバーが受け取るトークンはすべて、サインインした本人のもので、1 つのリポジトリと、そこでの本人の役割に限定されます。そのため、GitHub 上で本人ができること以上には決して及びません。GitHub の監査ログには、App を通じて動作したその本人が記録されます。

Control Center が組織に届かないようにするには、組織のオーナーが GitHub 上でインストールを削除するか、そのリポジトリを絞り込みます。組織からメンバーを削除すると、そのメンバーのアクセスも止まります。

## 代わりに手動で登録する

**プロバイダーアプリ** カードには、自分で登録した App の値を直接入力することもできます:

| グループ                     | フィールド                                                                                      |
| ---------------------------- | ----------------------------------------------------------------------------------------------- |
| **サーバーとして動作**       | **アプリID** と **秘密鍵**（`.pem` 全体。`BEGIN` 行と `END` 行も含む）                           |
| **ユーザーのサインイン**     | **クライアントID** と **クライアントシークレット**。**コールバックURL** に登録すべき URL がそのまま表示されます |
| **プルリクエストでの会話**   | **ボットログイン**。接続をテストしたときに解決されます                                          |

コールバック URL `<server origin>/oauth/github/callback` をカードの表示どおりに登録し、**Expire user authorization tokens** はオンのままにして、上の表の権限を付与します。**テスト** をクリックすると、App がどのアカウントにインストールされているかを GitHub に問い合わせるため、「保存されている」と「機能する」を取り違えることはありません。

## サーバーの `.env` で設定する

ヘッドレスまたはスクリプトによるインストールでは、サーバーは保存された値がない最初の時点で、`.env` ファイルから各フィールドをシードします:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

鍵は**1 行**にしてください。`.env` の値は 1 行であり、二重引用符内の `\n` は改行にデコードされます。`GITHUB_APP_PRIVATE_KEY` または `GITHUB_CLIENT_SECRET` が、すべての子プロセスから読めてしまうプロセス環境にエクスポートされていると、サーバーは起動を拒否します。これらは `.env` ファイルに置いてください（Docker では `/app/bin/.env` にマウントします）。シードは**フィールドごとに 1 回**行われるため、設定画面での編集が次の再起動で取り消されることはありません。

## 1 つのワークスペースに独自の App を使わせる

ワークスペースは、サーバーの App の代わりに独自の App で動かすことができます:

1. ワークスペース管理者が **設定 → ワークスペース → 連携** に移動します
2. **Control Center Connect** カードで **自分のアプリを使う** を選び、**適用** をクリックします。ワークスペースのメンバー全員が、ワークスペースのアプリで再度サインインします
3. **コードホスティング** の下の **GitHub App** カードに、アプリのフィールドが表示されます。**このワークスペースの代理として動作** の下に **アプリID** と **秘密鍵**、**ユーザーのサインイン** の下に **クライアントID** と **クライアントシークレット** があります。設定したら **テスト** をクリックします

その後、メンバーはこのワークスペースではそのアプリにサインインします。独自のアプリを使うワークスペースが、サーバーの App や Connect にフォールバックすることはありません。フィールドがそろうまで、その GitHub 作業は拒否されます。同じ選択が Google Calendar、Linear、GIF 検索にも適用され、それぞれのフィールドは同じページの各プロバイダーの横にあります。詳しくは [ワークスペースに独自の Linear アプリを設定する](/ja-JP/マニュアル/ハウツーガイド/linear-インテグレーション/#ワークスペースに独自の-linear-アプリを設定する) と [ワークスペースに独自の Google クライアントを設定する](/ja-JP/マニュアル/ハウツーガイド/カレンダー接続/#ワークスペースに独自の-google-クライアントを設定する) を参照してください。このカードの他の選択肢とその動作は [ワークスペースごとの選択](/ja-JP/マニュアル/リファレンス/connect/#ワークスペースごとの選択) にあります。

## トラブルシューティング

### 自分のGitHubアプリを作成 で、サーバーにアドレスがないと表示される

サーバーには、ブラウザーが戻ってこられる公開 URL がありません。`CC_SERVER_PUBLIC_URL`（または `--public-url`）を設定して、もう一度試してください。

### GitHub にリンクの有効期限が切れたと表示される

1 回限りのページがすでに使われたか、10 分が経過しました。設定画面からやり直してください。

### テストで資格情報は機能すると表示されるが、App がどこにもインストールされていない

登録とインストールは別の手順です。App のインストールページを開くか、ワークスペース → 連携 の **GitHubアプリをインストール** を使ってください。

### テストで秘密鍵を読み取れないと表示される

`-----BEGIN` 行と `-----END` 行も含めて、`.pem` ファイル全体を貼り付けてください。`ed25519` や EC の鍵は使用できません。GitHub App は RSA で署名します。

### メンバーがサインインしたのにリポジトリが表示されない

App が、それらを所有するアカウントにインストールされていないか、そのインストールが別のリポジトリを選択しています。サインインは、App が見ることを許可されているものだけを付与します。

### エージェントに、GitHub App のインストールが一時停止されていると表示される

誰かが GitHub 上でインストールを一時停止しました。そのアカウントの **Settings → Applications → Installed GitHub Apps** で一時停止を解除してください。
