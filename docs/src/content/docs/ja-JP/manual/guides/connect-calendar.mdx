このガイドでは、Google Calendar をワークスペースに接続する方法を説明します。接続はワークスペース単位かつメンバー単位で、そのワークスペースでのあなたの予定を Control Center に同期し、そこで招待への返信、予定の予約、移動、削除もできます。全体像は[カレンダーとスケジュール](/ja-JP/マニュアル/コンセプト/カレンダー/)を参照してください。

## 前提条件

- サーバーが Google へのサインインを提供できること。Control Center Connect を通じて、またはサーバー自身の Google クライアント（[独自の Google クライアントを持ち込む](#独自の-google-クライアントを持ち込む)）で行います。どちらにするかはサーバー所有者が **設定 → サーバー → シングルサインオン** で選びます
- 開いているワークスペース。カレンダーアカウントは常にいずれか 1 つのワークスペースに属します

## アカウントを接続する

1. サイドバーで**カレンダー**を開きます。
2. カレンダーのサイドバーで**カレンダーアカウントを追加**をクリックします。（同じセクションは**設定 → 自分 → プロフィール**の**Google Calendar**の下にもあります。）
3. **Googleカレンダーを接続**をクリックします。ブラウザーで Google の同意ページが開きます。
4. アカウントを選び、カレンダーの予定とカレンダー一覧へのアクセスを承認します。

完了の仕方は、誰がサインインを実行するかによって異なります:

- **サーバー自身の Google クライアント:** Google がブラウザーをサーバーに戻し、ダイアログは自動的に閉じます
- **Control Center Connect:** ブラウザーのページに 8 文字のコードが表示されます。それをダイアログに入力するか、`control-center://` リンクを通じてブラウザーに Control Center を開かせ、入力を省きます

予定の同期はすぐに始まります。やり取りを完了して資格情報を保持するのは、あなたのデバイスではなくサーバーです。

アカウントが接続されるのは**アクティブなワークスペースだけ**で、それはあなたのものです。同じ Google アドレスを接続した 2 人のメンバーには、別々のアカウントができます。ワークスペースを切り替えると、そのワークスペースのカレンダーが表示されます。

接続フローは、どのクライアントで実行するかにかかわらず `calendar.events` と `calendar.calendarlist.readonly`、そして `openid email` を要求します。Control Center が Google に書き込めるようになる前に接続したアカウントは読み取り専用スコープしか持っていないため、再接続を求められ、新しいサインインで残りのスコープが付与されます。

## 予定を予約・移動・返信・削除する

- **予定を予約:** 週ビューまたは日ビューでタイムグリッドをドラッグして時間帯を指定します（月ビューでは日をまたいでドラッグすると終日の予定になります）。タイトル、時間、ゲスト、Google Meet リンク、場所、説明、予約先のカレンダーを含むカードが横に開きます。**保存**を押すと Google に予約され、その予定が開きます。カレンダーのヘッダーにある **+** ボタンは、次の空いている 15 分単位の時刻で同じカードを開きます。取り消すには Escape キーを押します
- **予定を移動:** 予定をドラッグして別の時間や日に移すか、下端をドラッグして終了時刻を変えます。Google が新しい時間を受け付けると表示が移り、拒否されると元の位置に戻ります。移動できるのは自分の予定と主催する予定だけで、招待された予定は主催者が置いた位置のままです
- **招待に返信:** 予定を開き、**はい**、**未定**、**いいえ** のいずれかを選びます
- **予定を削除:** 予定を開き、ゴミ箱アイコンをクリックします。確認画面には影響を受ける人が表示されます。自分が主催する予定を削除するとゲストに取り消しが通知され、招待を削除すると自分のカレンダーからだけ消えます。繰り返し予定の 1 回分を削除しても、シリーズの残りは残ります

ゲストには、Google 自身の招待・更新・キャンセルのメールが届きます。繰り返し予定の 1 回分を移動しても、シリーズの残りは残ります。予約できるのは、アカウントが書き込みを許可されているカレンダーだけで、それも自分のアカウントに限られます。ほかのメンバーが接続したカレンダーが候補として表示されることはありません。

## 同期の仕組み

スケジュールを所有するのは**サーバー**です。2 分ごとに各ワークスペースの接続済みアカウントをスイープし、予定をそのワークスペースのデータベースに書き込みます。クライアントが Google と通信することは決してなく、サーバーが書き込んだ内容を読み取るだけです。

スイープは増分式です。カレンダーごとの最初のパスでローリングウィンドウ（60 日前から 90 日先まで）を取得し、Google の同期トークンを取り込みます。以降のパスはそのトークンを提示し、変更された分だけを受け取ります。これが 2 分間隔を許容できるようにしています。ウィンドウは 24 時間ごと、および Google がトークンを無効化するたびに、完全同期によって基準を取り直します。

資格情報は、サーバーのデータディレクトリ配下にある `secrets.json` にサーバー側で保存され、所有者のみが読める権限（`0600`）で書き込まれます。OS のキーチェーンには置かれず、クライアントデバイス上に置かれることもありません。Connect を通じたサインインでは、Connect がこのサーバーのためだけに開ける封印された資格情報だけが保存され、そのアクセストークンはサーバーのメモリ内にとどまります。

## 複数のアカウントを接続する

1 つのワークスペースには複数の Google アカウントを接続できます（たとえば仕事用と個人用）。それぞれについて接続の手順を繰り返します。予定は同じ月 / 週 / アジェンダの各ビューにマージされます。各アカウントは独立して同期・更新され、個別に切断できます。

## 期限切れのアカウントを再接続する

Google がアカウントのサインインを恒久的に無効化した場合（セッションが取り消されたか、長期間失効した場合）、同期が停止し、Control Center はカレンダーに**再接続**バナーとデスクトップ通知を表示します。**再接続**をクリックしてもう一度サインインすると、次に同期が成功した時点でバナーが消えます。

このサーバーがそのサインインをもう使えない場合にも、同じバナーが表示されます。サーバー所有者が Connect サーバーを切り替えたか Connect 鍵を更新した場合、サーバー自身の Google クライアントが変わった場合、またはデータディレクトリが別のマシンに復元された場合です。

## アカウントを切断する

カレンダーのサイドバー（または**設定 → 自分 → プロフィール**）で、そのアカウントの**切断**をクリックします。これにより、同期済みの予定が削除され、サーバーに保存された資格情報が消去されます。

## 独自の Google クライアントを持ち込む

**自分のアプリを使う** を選んだ場合にだけ、独自の Google クライアントを運用します。サーバー自身のクライアントは、その場合にのみ適用されます。Control Center のものまたはカスタムの Connect を使う場合、Connect がすべてのレーンを担当し（Google も含みます）、サーバーのクライアントは保存されたまま使われません。サーバーが Connect を使いながら同意画面に自分のプロジェクト名を表示させたい場合は、ワークスペースを自分のアプリに切り替え、ワークスペース自身のクライアントを設定します（[下記](#ワークスペースに独自の-google-クライアントを設定する)）。これはサーバーのモードにかかわらず適用されます。

1. [Google Cloud Console](https://console.cloud.google.com/apis/credentials)で**Google Calendar API**を有効にし、**OAuth 同意画面**を構成して、`calendar.events`、`calendar.calendarlist.readonly`、`openid`、`email` の各スコープを追加します。アプリが未確認の間は、自分を**テストユーザー**として追加します。
2. アプリケーションの種類が**ウェブ アプリケーション**の**OAuth クライアント ID**を作成します。
3. 承認済みのリダイレクト URI `<server origin>/oauth/google/callback` を追加します。**設定 → サーバー → シングルサインオン → プロバイダーアプリ → Google** の**コールバックURL**に正確な URL が表示されるので、そのままコピーします。
4. **クライアントID** と **クライアントシークレット** をその Google ブロックに貼り付けるか、サーバーの `.env` ファイルに `GOOGLE_OAUTH_CLIENT_ID` と `GOOGLE_OAUTH_CLIENT_SECRET` として置きます。

`GOOGLE_OAUTH_CLIENT_SECRET` がプロセス環境にエクスポートされていると、サーバーは起動を拒否します。`.env` ファイルに置いてください（Docker では `/app/bin/.env` にマウントします）。シークレットがサーバーから外に出ることはなく、どの RPC 応答にも含まれません。シークレットのないクライアント ID は未完成のセットアップであり、両方がそろうまで Google へのサインインは拒否されます。

別のクライアントに切り替えると、全員が Google Calendar からサインアウトされます。サインインは、それを発行したクライアントに属するためです。

## ワークスペースに独自の Google クライアントを設定する

ワークスペースは、サーバーのものではなく独自のクライアントを使って Google Calendar に接続できます。設定できるのはワークスペースの管理者またはオーナーだけです。

1. 上記の手順 1 と 2 のとおりに、Google の**ウェブ アプリケーション**クライアントを作成します
2. **設定 → ワークスペース → 連携** に進み、**Control Center Connect** カードで **自分のアプリを使う** を選んで **適用** をクリックします
3. **カレンダー** の下に **Google Calendar アプリ** カードが表示されます。そのカードの**コールバックURL**に表示されるリダイレクト URI を、表示どおりにクライアントへ追加します
4. **クライアントID** と **クライアントシークレット** を貼り付けます

そのワークスペースで接続したカレンダーアカウントは、サーバーがサインインさせる方法にかかわらず、そのクライアントを通ります。サーバーのクライアントや Connect にフォールバックすることは決してありません。両方のフィールドが設定されるまで、ワークスペースでは Google Calendar がオフになり、そのカードに不足している項目が表示されます。シークレットがサーバーの外に出ることはありません。

**自分のアプリを使う** は、すべてのプロバイダーを同時に対象とします。GitHub、Linear、GIF 検索も、ワークスペース自身のアプリでのみ実行されます。ワークスペースのサインインアプリを切り替えたり、ワークスペースのクライアント ID を変更したりすると、そのワークスペースのすべての Google アカウントに再接続が必要になります。保存済みフィールドは、ワークスペースが別の選択に戻っても残りますが、**自分のアプリを使う** の場合にだけ使われます。サーバー上の他のワークスペースは影響を受けません。

## トラブルシューティング

| 症状                                                       | 考えられる原因                                                                                                                                                                          |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Googleカレンダーを接続** に、サインインが設定されていないと表示される | サーバーには独自の Google クライアントも Connect もありません。サーバー所有者が **設定 → サーバー → シングルサインオン** でどちらかを選びます                             |
| Google に `redirect_uri_mismatch` と表示される             | クライアントに登録したリダイレクトが **コールバックURL** の値と完全に一致していないか、サーバーの公開 URL が変わっています                                                            |
| Google から `invalid_client` が返る                        | ID とシークレットが別々のクライアントのものか、クライアントが削除されています                                                                                                         |
| 承認は成功するが同期が空になる                             | 同意画面で自分のアカウントが**テストユーザー**になっていないか、要求したスコープのどれかが付与されていません                                                                         |
| ダイアログに、コードが一致しないと表示される               | ブラウザーに表示されたとおりに 8 文字を正確に入力してください。誤ったコードを 5 回入力するとサインインは終了するので、やり直してください                                              |
| 「回答を更新できませんでした」、または予約・移動・削除に失敗する  | アカウントはカレンダーへの書き込みアクセスを許可していません。再接続し、要求されたすべてのスコープを承認してください。読み取り専用で共有されたカレンダーでも書き込みは拒否されます                                              |
| 全員が再接続しなければならない                             | サーバーまたはワークスペースの Google クライアントが変わったか、サーバーまたはワークスペースの Connect の選択、またはサーバーの鍵が変わりました。[期限切れのアカウントを再接続する](#期限切れのアカウントを再接続する)を参照してください             |
