このガイドでは、GitHub からワークスペースにスキルを揃える方法を説明します。
リポジトリをソースとして追加し、そこから必要なスキルをインストールし、その後も
最新の状態に保ちます。保存したリビジョンは、保持するかどうかを決める前に、対応する
ベースラインと比較して評価することもできます。

始める前に知っておくべき重要事項: **ソースリポジトリは信頼できません。** その
名前、説明、スター数は、リポジトリの所有者が書いたものです。ディスクやエージェントの
プロンプトに何かが届く前に、すべてのインストールがウイルス対策スキャンゲートを
通過します。その判定は受け入れ時のチェックであり、スキルが安全または有用である
証拠ではありません。インストールの仕組みについては
[エージェントモデルのスキルのセクション](/ja-JP/マニュアル/コンセプト/エージェントモデル/)を、
行動に関する証拠がスキャンとどう異なるかについては
[評価と品質](/ja-JP/マニュアル/コンセプト/評価と品質/)をお読みください。

スキルは **設定 → ワークスペース → スキル**
（`/workspaces/<id>/settings/workspace/skills`）にあります。スキルはワークスペース
単位です。ここでインストールしたスキルは、このワークスペースにのみ属します。ページには
2 つのタブがあります: **インストール済み**（ローカルのスキル。**新しいスキル**
エディターを含みます）と **ソース**（GitHub のカタログ）です。どちらの書き込みも
同じスキャンゲートを通過します。

## スキルリポジトリを追加する

1. **設定 → ワークスペース → スキル**を開き、**ソース**タブに切り替えます。
2. **リポジトリを追加**を押します。
3. GitHub リポジトリの URL を貼り付けます（例:
   `https://github.com/anthropics/skills`）。そして確定します。

サーバーは、そのリポジトリが存在し、資格情報で参照できることを確認してから、左側の
レールに追加します。間にキュレーションされたストアはありません: どの GitHub
リポジトリでも使えるということは、評判を判断するのはあなた自身だということでもあります
— スター数は証拠にはなりますが、保証には決してなりません。

リポジトリのスキルとは、`SKILL.md` を含むディレクトリのことです（最大 3 階層まで。
加えて Claude のプラグインマーケットプレイス形式
`plugins/<plugin>/skills/<skill>` も対象となり、依存関係とベンダーのツリーは
スキップされます）。後でグリッドにこのリポジトリにはスキルがないと表示されたら、
それはそのとおりの意味です: リポジトリ内にスキルの規約に一致するディレクトリが
ないということです。

## インストール前にスキルを確認する

レールでリポジトリを選択すると、そのスキルが右側にグリッドで表示され、上の
フィルターフィールドで名前、説明、slug からカタログを絞り込めます。カードを
クリックすると詳細ビューが開きます。詳細ビューには 3 つの情報があります:

- **README** — markdown としてレンダリングされます。スキルディレクトリの
  `README.md`、または README がない場合は `SKILL.md` の本文です。
- **スキャンプレビュー** — 判定（`pass`、`warn`、`quarantine`）、スキルの内容が
  宣言するケイパビリティ（シェルを実行、ファイルを書き込む、ネットワークに
  アクセス…）、そしてスキャナーが記録したすべての検出結果です。
- **ファイル数** — インストールでは、その `SKILL.md` だけでなくスキルの
  ディレクトリ全体が書き込まれます。

プレビューは、インストールが書き込むのとまったく同じバイト列をスキャンするため、
目にしている判定がそのままインストール時の判定になります。あなたの知らないうちに
判定し直されることはありません。

## スキルをインストールする

1. スキルの詳細ビューを開きます。
2. スキャン判定を読みます。`warn` または `pass` の判定なら、**インストール**を
   押します。
3. `quarantine` の判定の場合、**リスクを理解したうえでインストールする**に
   チェックを入れるまでインストールは無効のままです。この上書きは記録されます。
   暗黙に認められることはありません。

インストールするとスキルのディレクトリがワークスペースに書き込まれ、
`skills-lock.json` にピン（ソースリポジトリ、パス、取得元のコミット、コンテンツ
ハッシュ）が記録され、そのスキルがワークスペースのエージェントから利用できるように
なります。**使用中の名前**と表示されたカードは、別のスキルがすでにその名前を
ローカルで使用していることを意味します — 先にそちらをアンインストールしてください。

## スキルを継続的に更新する

インストール済みスキルのカードにはバッジが付きます: **インストール済み**、または
ピンしたコミットよりリポジトリが先に進んでいる場合は **更新あり** です。詳細ビューを
開いて **更新** を押すと、新しいコミットで再取得します。更新はインストールと同じ
スキャンゲートを通過します — 新しいバージョンが隔離されるスキルは拒否され、手元の
バージョンはそのまま残ります。古いバージョンのハッシュは、ロック内のロールバック
参照として保持されます。

## スキルを評価する

1. **設定 → ワークスペース → スキル**を開き、インストール済みのスキルを選択して
   変更内容を保存します。**スキル評価**でパッケージハッシュを確認します。
2. **評価を開始**を選択します。スキルの目的に合った**タスク集**と**アダプター**を
   選びます。組み込みハーネスは、設定済みのプロバイダーとツール対応モデルを
   使います。**Claude Code** は既定の管理対象 Claude アカウントと具体的な
   モデル識別子を使います。先に**設定 → アダプター**でサインインしてください。
   サーバー運用者個人のログインを借りることはありません。
3. 以下の表から**比較**を選びます。
4. **タスクごとの繰り返し回数**（1〜20）と**予算 (米セント)**を設定します。
   たとえば `100` は 1 米ドルを意味します。有料のプロバイダー処理を承認するには
   **評価を開始**を選択します。
5. **オブザーバビリティ → 品質**でキャンペーンを追うか、スキルパネルの
   **品質を開く**から戻ります。

**Claude Code** と **Codex OAuth** のサブスクリプションでは、予算は**API 換算の
使用量による停止しきい値**であり、請求上限でもサブスクリプション割り当ての
測定値でもありません。`100` は 1 米ドルのしきい値を認めます。実行中の呼び出しは
それを超えることがありますが、報告された使用量がそこに達すると、それ以上の呼び出しは
開始されません。使用量が不明な場合も、以降の呼び出しは停止します。予算が小さいと
比較が一部のみで終わることがありますが、選択したタスク集の完了を約束するものでは
ありません。

API キーのプロバイダーは、文書化されたトークン上限と価格設定に基づく保守的な
呼び出しごとの予約を維持します。安全に予約された 1 回の呼び出しがそれ以上を必要と
する場合、`100` を支出前に拒否することがあります。エラーには選択したモデルと最小
予約額が示されるので、より低コストのモデルを選ぶか、その予算を増やしてください。

| 比較 | 何を答えるために使うか |
| --- | --- |
| **不在 vs 利用可能** | このスキルが通常どおり発見されて使われることで、持っていない場合と比べて結果が良くなりますか? |
| **前回 vs 今回** | 更新によって、以前に取得したリビジョンに対する動作が保たれるか、改善されますか? |
| **強制読み込み vs 不在** | 明示的に読み込んだときに内容が役立つかどうかを確かめられますか? これは読み込みの問題を診断するもので、通常の検出を実証するものではありません。 |
| **構成** | 候補を追加すると、選択した常時利用可能なスキルを助けるか、それとも競合するか? ベースラインは、候補を除いた同じ常時利用可能な一覧を保ちます。 |

**前回 vs 今回**には、キャンペーン履歴のパッケージハッシュが必要です。
ベースラインとして使いたい場合は、置き換える前にそのリビジョンを評価しておいて
ください。任意の Git 履歴は取り込まれません。

保存されていない編集、利用できないハッシュ、読み取り専用のデモモードは起動を
無効にします。サーバーはワークスペース/リポジトリへのアクセス、スキャンの隔離、
アクションポリシー、モデルの対応、価格設定、実行のサンドボックスも確認します。失敗した
確認は回避せず解決してください。プロバイダーとモデルの識別情報は記録されますが、
リモートのモデルエイリアスはプロバイダーの基盤となる重みを固定しません。

### 確認、キャンセル、エクスポート

カバレッジと支出は、タスクごとの結果やリグレッションと併せて読みます。個々の試行を
開くと、観測されたスキルの読み込み、ツールイベント、エラー、検証者の証拠を確認
できます。**証拠が一部のみ**、**古い**、**結論なし**という結果は、リビジョンの採用を
勧めるものではありません。レポートのハッシュが識別するのは取得されたパッケージで
あり、現在インストールされているパッケージとはかぎりません。

キュー中または実行中の処理には**実行をキャンセル**を使います。完了した試行は
引き続き表示されます。キャンセルしても、すでに行われたプロバイダー処理の料金は
返金されません。**編集済みJSONをコピー**は、範囲を限定した証拠エクスポートを
クリップボードにコピーするもので、プライベートソースの完全なリプレイ用バンドルでは
ありません。証拠とプラットフォームの制約については
[評価と品質](/ja-JP/マニュアル/コンセプト/評価と品質/)を参照してください。

### 更新後の再評価

自動の有料再評価は**既定では無効**です。現在のリビジョンを評価したら、
**更新ポリシーの設定**でキャンペーンを選び、**更新時の評価を有効化**を選択します。
このポリシーの変更にはワークスペース管理者の権限が必要です。選択したキャンペーンが、
タスク集、アダプター、プロバイダー/モデル、比較、繰り返し回数、予算を提供します。

以降に受け入れられた内容の変更は、予算内の処理をスケジュールします。ハッシュが
変わらないものは重複排除されます。**更新時の評価を無効化**は、今後の自動的な
受け入れを防ぎます。すでに受け入れられたキャンペーンには**実行をキャンセル**を
使ってください。過去のレポートは元のパッケージハッシュに紐づいたままです。再評価が
スキルを公開、有効化、書き換えることはありません。

## スキルをアンインストールし、リポジトリを削除する

**アンインストール**（インストール済みスキルの詳細ビュー、または **インストール済み**
タブでの削除）は、スキルのディレクトリとロックのピンをまとめて削除します —
アンインストールされたスキルは何も残しません。

**レールからのリポジトリの削除**はカタログだけを削除します: そこからインストールした
スキルはインストールされたままで、引き続き更新されます。ピンはソースエントリへの
参照ではなく、リポジトリを名前で記録しているためです。もう一度閲覧したい場合は、
リポジトリを追加し直してください。

## スキルを呼び出す

スキルは独自の名前空間で呼び出されるため、組み込みのスラッシュコマンド
（`/plan`、`/goal`、`/loop`、`/compact`）と衝突しません:

- `/skill:<name>` — このワークスペースにインストールされたスキル、または
  エージェントに添付されたスキル
- `/skill:<repo>:<name>` — このスペースにチェックアウトされたリポジトリが
  提供するスキル

名前空間ができる前に書かれたメッセージのために、組み込みでない裸の名前も解決されます。
`plan` という名前のスキルに届くのは `/skill:plan` であり、`/plan` は常に組み込みです。

## リポジトリ単位のスキル

チェックアウトされたリポジトリは、`.agents/skills/`、`.agent/skills/`、
`.claude/skills/`、`.opencode/skills/` または `skills/` に、独自のスキルを
同梱できます。それらは**このページからは**インストールされません。エージェントが
保持するのは、現在作業しているリポジトリのスキルだけであり、リポジトリを移動すると
入れ替わります。コンポーザーはそのようにはスコープされません:
`/skill:<repo>:<name>` はスペース内のどのリポジトリにも届きます。

リポジトリのスキルは、そのフロントマターがプロンプトに届く前に、同じフェイル
クローズドなスキャン（`pass` / `warn` / `quarantine`）を通過します。`warn` は
許可され、`quarantine` は差し止められます。この経路に運用者による上書きは
ありません。

[リポジトリ単位のスキル](/ja-JP/マニュアル/コンセプト/エージェントモデル/#リポジトリ単位のスキル) と
[スラッシュコマンド](/ja-JP/マニュアル/リファレンス/スラッシュコマンド/)を参照してください。
