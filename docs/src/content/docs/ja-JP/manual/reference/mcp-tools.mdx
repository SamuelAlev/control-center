`cc_server` はひとつの MCP（JSON-RPC 2.0）ツールレジストリをホストし、メインサーバーポート（既定 `9030`）の `POST /mcp` と `GET /sse` で、プロトコルバージョン `2024-11-05` として提供します。デスクトップ、Web ビルド、外部 MCP クライアント、内蔵エージェントランタイムというすべてのクライアントが、同じレジストリに到達します。外部 MCP サーバーは、動的レイヤーとして同じレジストリにブリッジできます。

## レジストリの規模

| 項目                                                                      | 数  |
| ------------------------------------------------------------------------- | --- |
| `cc_server` が登録するツール                                              | 110 |
| `packages/cc_mcp` 由来                                                    | 108 |
| `packages/cc_mcp_client` 由来（ツールディスカバリ）                       | 2   |
| ベースレジストリに登録（`server_mcp_registry.dart`）                      | 63  |
| 起動後、各サービスが立ち上がるにつれて登録（`cc_server_runtime.dart`）   | 47  |
| ベースレジストリの 63 のうち、コードグラフリポジトリを条件とするもの      | 5   |

5 つのコードグラフツールは、ホストが `buildServerMcpRegistry` にコードグラフリポジトリを渡したときだけ登録されます。`cc_server` は常に渡すため、出荷されるバイナリでは 110 すべてが有効です。

完全なレジストリは、ディスカバリのゲートなしで `tools/list` に公開されます。チケットの編集は型付きツールです。

:::note[外部クライアントには常にカタログ全体が見えます]
`tools/list` が削減されることは決してありません。MCP クライアントはツール名を、そのリストの自身のキャッシュ済みコピーと照合して検証し、サーバーに問い合わせることなく、リストにないものを拒否します。そのため、そこで隠されたツールは単に静かなのではなく、到達不能です。

**内蔵ハーネス**は異なります。リクエストごとに定義の常駐サブセットだけを読み込み、残りは初回使用時に取り込みます。これはハーネス側の振る舞いであり、このレジストリを変えるものではありません。[ツールコンテキストとプロンプトキャッシュ](/ja-JP/マニュアル/コンセプト/ツールコンテキスト)を参照してください。
:::

:::note[すべてのツールクラスが登録されます]
`packages/cc_mcp/lib/src/tools/` 配下のソースファイルは、エージェントが呼び出せるツールです。新しいツールクラスがどこからも構築されていない場合、`packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart` がビルドを失敗させます。
:::

## 共通パラメータ

### `workspace_id`

ワークスペーススコープのデータに触れるすべてのツールで**必須**です。`workspace_id` がないか無効な場合は明示的なエラーが返り、対象エンティティのワークスペースと一致しない値は黙って無視されるのではなく拒否されます。真にグローバルなツールでは省略します。`list_workspaces` と 6 つのニュースフィードツール（`list_feeds`、`list_articles`、`get_article`、`set_article_read`、`set_article_saved`、`refresh_feeds`）で、これらはサーバー所有者のユーザー単位のフィードリストに乗ります。ディスカバリツール（`search_tool_bm25`、`list_my_tools`）では任意であり、会話モードごとに呼び出し可否を分類できるようにしています。サーバーがエージェントをディスパッチする場合、ワークスペースはサーバー側で強制されるため、エージェントは外部の id を渡して別のワークスペースに到達することはできません。

## ツールディスカバリ

どちらも `cc_mcp` ではなく `cc_mcp_client` 由来で、どちらもモードガードを参照するため、_現在_ の会話モードで呼び出し可能なものを報告します。

| ツール             | 説明                                                                                                                    |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| `search_tool_bm25` | キーワードでツールカタログを検索し、一致するツール、その引数スキーマ、それぞれが今呼び出し可能かどうかを返します        |
| `list_my_tools`    | この会話で今呼び出し可能なツールを、そのモードで絞り込んで一覧表示します                                                |

3 つ目のディスカバリツール **`search_tools`** は内蔵ハーネスの内側にのみ存在し、この MCP レジストリには含まれません。これは実行自身のツールサーフェスを順位付けし、`search_tool_bm25` と違って見つけたもののスキーマを**読み込む**ため、エージェントは次のターンで一致したものを呼び出せます。ハーネス上のエージェントはこちらを優先すべきです。MCP クライアントには `search_tool_bm25` があります。

## エージェント間のメッセージングと委任

エージェント同士はスペース（永続的で、ロスターに見える）を介して会話します。`ask_agent` は必須のタイムアウトを伴う要求／応答です。`delegate_task` はサーバー側で、深さの上限、循環検出、予算エンベロープ、自律性の上限によってガードされます。

| ツール          | 説明                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------ |
| `send_to_agent` | `to_agent_id` または完全一致の `to_agent_name` で宛先を指定し、別のエージェントへ一方向のメッセージを送ります |
| `ask_agent`     | 別のエージェントに質問し、その返信を待つか、タイムアウトします                                   |
| `delegate_task` | タスクを追跡対象の子チケットとして別のエージェントに委任します                                   |
| `consult_agent` | スキルに基づいて最適なスペシャリストをスペースに追加し、焦点を絞ったブリーフでディスパッチします |
| `todo_read`     | この会話に永続化されたタスクチェックリストを読み取ります                                         |

## コードグラフツール

ホストがコードグラフリポジトリを提供したときだけ登録されます。インデックスは同梱の文法セット（Dart、JS/TS、PHP、Python、Rust、Zig、C/C++、Go、Java、Ruby、C#、Swift、Kotlin、R、Assembly、MATLAB、Ada）を対象とし、それ以外の言語のシンボルは含まれません。

| ツール         | 説明                                                                               |
| -------------- | ---------------------------------------------------------------------------------- |
| `search_code`  | インデックス済みのシンボルを、名前、シグネチャ、doc コメントで検索します（BM25 + セマンティックのハイブリッド） |
| `code_symbol`  | 完全一致した名前でシンボルを検索します。`file:line` とシグネチャを返します         |
| `code_callers` | あるシンボルを呼び出す、または依存するシンボル（入力エッジ）を一覧表示します       |
| `code_callees` | あるシンボルが呼び出す、または依存するシンボル（出力エッジ）を一覧表示します       |
| `code_impact`  | あるシンボルの推移的な影響範囲を、指定した深さまで計算します                       |

## エンクロージャー（リグ）のツール

使い捨てのマシン — エンクロージャー内のブラウザや Linux デスクトップ、Android エミュレータ、iOS シミュレータ — を実行の内部から操作します。起動後に無条件で登録されます。マシンが実際に起動できるかどうかは、ツールが呼び出しごとに答えるプローブの問いです。1 つの会話で繰り返し呼び出すと 1 台のマシンが再利用されます。スクリーンショットは画像コンテンツとして返り、結果ごとに 1 枚という予算があり、抽出されたページ／UI のコンテンツは信頼できないデータとしてフェンスされます。4 つの use ツールと `rig_close` は `enclosureControl` の[アクションクラス](/ja-JP/マニュアル/コンセプト/ガードレール/)を宣言するため（use ツールは `networkEgress` と `processSpawn` も、`mobile_use` と `ios_use` は `packageInstall` も宣言します）、読み取り専用モードでは拒否されます。`rig_list` は何も宣言しません — ワークスペースの状態を読むだけです。サーフェスごとの動詞の語彙の全体は[リグのリファレンス](/ja-JP/マニュアル/リファレンス/リグ/#action-verbs)にあります。

| ツール         | 説明                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------- |
| `computer_use` | エンクロージャー内の VM で Linux デスクトップを操作します: 移動、クリック、ドラッグ、スクロール、入力、リサイズ、クリップボード、スクリーンショット |
| `browser_use`  | ヘッドレスの Chromium、Firefox、WebKit（`engine`）を操作します: ナビゲート、クリック、入力、抽出（a11y/DOM/コンソール）、クリップボード、スクリーンショット |
| `mobile_use`   | ADB 経由で Android を操作します: 検査／入力、スクリーンショット、アプリのインストール／起動／停止／リセット／アンインストール、ディープリンク、argv 形式のデバイスコマンド |
| `ios_use`      | WebDriverAgent/CoreSimulator を通じて iOS シミュレータを操作します: 検査／入力、スクリーンショット、アプリのインストール／起動／停止／アンインストール、ディープリンク、argv 形式のシミュレータプロセス |
| `rig_list`     | ワークスペースのリグを、サーフェス、ステータス、ディスプレイサイズ、コントローラーとともに一覧表示します |
| `rig_close`    | リグを破棄し、それが所有するマシンの状態を捨てます                                       |

## MCP では公開されないもの

カレンダーとミーティングには MCP ツールがありません。エージェントはあなたのカレンダー、ミーティング、文字起こし、アクションアイテム、決定を読むことはできません。アクションアイテムと決定を生成する要約は、エージェントが呼び出せるツールとしてではなく、内蔵の [`meeting_summary` パイプライン](/ja-JP/マニュアル/コンセプト/ミーティング/)として実行されます。

## モードによるツールのゲート

ゲートはひとつのテーブル（`ModeToolPolicy`）から 2 回適用されます。1 回は Claude Code アダプターの MCP ディスパッチャーで、もう 1 回は内蔵ハーネスのレジストリです。ブロックされた呼び出しは理由を返します。

| モード        | ツールサーフェス                                                                                                                                                                                                                    |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`        | 登録されたすべてのツール。許可リストなし                                                                                                                                                                                            |
| `plan`        | 厳選された許可リスト。ワークツリーへの書き込みと、`create` / `assign` / `delegate` のチケット動詞はありませんが、メモリ、アーティファクト、todo、`submit_plan`、`exit_plan_mode`、およびディスパッチされたチケットに対するチケット完了の動詞は許可されます |
| `review`      | 厳選された許可リスト: レビューへの参加、コミュニケーション、読み取り専用のコンテキスト取得、そして `create_ticket` と `assign_ticket` を含むチケット動詞の全体セット                                                                    |
| `orchestrate` | 厳選された許可リスト: 調査と読み取りのツール、および `propose_orchestration`、`create_playbook`、`run_playbook`。採用、分解、チケットの完了は承認後に決定的に行われ、実行の途中で行われることは決してありません                        |

許可リストに関係なく、すべてのモードで許可されるもの:

| セット               | ツール                                                                                                                                                                                                                                                            |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| メモリとアーティファクト | `search_memory`, `propose_fact`, `propose_policy`, `supersede_fact`, `supersede_policy`, `record_observation`, `update_my_notes`, `get_my_notes`, `list_memory_domains`, `list_policies`, `publish_artifact`, `revise_artifact`, `list_artifacts`, `get_artifact` |
| コードグラフ         | `search_code`, `code_symbol`, `code_callers`, `code_callees`, `code_impact`                                                                                                                                                                                       |
| 実行のメカニクス     | `search_tool_bm25`, `list_my_tools`, `todo_write`, `todo_read`                                                                                                                                                                                                    |

許可リストに載っているからといってツールが呼び出し可能になるわけではなく、逆もまた同様です。オペレーターへの質問のケイパビリティは**ハーネス**のツール（`ask_user`）であるため、この MCP カタログには一切現れません。

## 承認でゲートされるツール

ツールは `requiresApproval` を宣言できます。その場合ディスパッチャーは `ApprovalPayload` を構築し、ツールが実行される前に `ConfirmationPort` を通じてそれを提示します。`cc_server` がそのポートを配線するため、ゲートは有効です。

これを宣言している登録済みツール: `create_ticket`、`update_ticket`、`assign_ticket`、`reassign_ticket`、`close_ticket`、`ticket_relation`、`create_goal`、`update_goal_progress`、`create_approval`、`decide_approval`、`comment_approval`、`create_work_product`、`save_work_product_revision`、`create_runtime_profile`、`install_skill`、`update_skill`。

これとは別に、統合アクションガードレールは、空でない `ActionClass` セットを宣言するあらゆるツールをゲートします。承認者が接続されていない状態での `prompt` の決定は拒否されます。[ガードレール](/ja-JP/マニュアル/コンセプト/ガードレール/)を参照してください。

## ツールが背後にないケイパビリティ

製品のすべてのケイパビリティがエージェントから到達できるわけではありません。以下にはツールがまったくないため、他所で参照されているのを見かけたかもしれない名前は "unknown tool" を返します:

| ケイパビリティ                           | 代わりにどこにあるか                                                                                     |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| エージェントの採用、解雇、編集           | エージェント UI。`hire_agent` / `fire_agent` / `update_agent` ツールはありません                             |
| ワークスペースの作成                     | RPC 経由の `workspace.upsert`。これが所有権をシードして刻印します                                             |
| プロジェクト（作成／一覧／更新／ファイル登録） | チケット UI。プロジェクトはオペレーター向けのサーフェスです — [プロジェクト](/ja-JP/マニュアル/ハウツーガイド/プロジェクト/)を参照してください |
| オペレーターへのブロッキングな質問       | MCP ではなく**ハーネス**の `ask_user` ツール。会話内にフォームをレンダリングし、回答が来るまでブロックします |
| エージェントごとの診断                   | 何もありません。`doctor` は存在しません — [エージェントの診断](/ja-JP/マニュアル/ハウツーガイド/エージェント診断/)を参照してください |
| カレンダーとミーティング                 | 人間のクライアント専用の RPC（前述）                                                                         |
