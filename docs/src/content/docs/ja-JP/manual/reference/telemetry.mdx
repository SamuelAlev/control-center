Control Center は **仮名化された利用イベント** を [Umami](https://umami.is) のインスタンスに送信できます。利用状況の分析は **サーバーのオペレーターがオンにするまでオフ** です。この設定はサーバーに属し、そのサーバーに接続するすべてのクライアント (デスクトップアプリ、Web アプリ、スマートフォン、そしてサーバー自身) に適用されます。

利用状況の分析は、クラッシュやエラーの診断情報を扱うデバイスごとの設定である **クラッシュレポートを共有** とは別のものです。

## 誰が決めるのか

| スイッチ | 場所 | 効果 |
| --- | --- | --- |
| **利用状況の分析を共有** | オンボーディング (サンドボックスのステップ) と **設定 → プライバシー**。変更できるのはサーバーのオペレーターだけで、ほかのメンバーには現在の値が読み取り専用で表示されます | サーバー全体に適用されます。サーバー設定に `telemetry.usage_analytics` として保存されます。`true` に設定しない限りオフです |
| ビルドの種類 | 自動 | debug ビルドと profile ビルドは送信しません。代わりに各イベントをデバッグログに書き込みます |
| `CC_ANALYTICS_DEBUG=1` | `cc_server` の環境またはその `.env` | テスト用に、サーバーと、そのサーバーに接続するすべてのクライアントの debug ビルドと profile ビルドから実際に送信できるようにします。この場合も上のスイッチがオンになっている必要があります |
| `DO_NOT_TRACK=1` | `cc_server` の環境 | スイッチの状態にかかわらず、サーバー自身による送信を止めます。クライアントは引き続きスイッチに従います |
| デモサーバー | 自動 | 公開デモサーバーはそれ自身としては何も送信しません。訪問者はスイッチを変更できません |

クライアントは設定をサーバーから読み取ります (まず `telemetry.config`、その後は `telemetry.watch` でリアルタイムに)。応答が届くまで、イベントはメモリ上の小さなバッファで待機します。応答が「いいえ」ならバッファは破棄されます。スイッチをオフにすると、キューに残っているものはすべて破棄され、すべてのクライアントで送信がただちに止まります。

## 決して送信されないもの

- メッセージ、チケット、レビュー、ミーティングの内容、タイトル、プロンプト、シェルコマンド、検索クエリ
- 名前、ログイン名、メールアドレス、アバター、表示名
- ファイルパス、リポジトリ名、ブランチ名、ホスト名、URL (リポジトリは仮名化された `repo_id` としてのみ、ミーティングのリンクはプロバイダー名としてのみ送信されます)
- あらゆる種類の生の識別子

すべてのイベントは、プロセスの外に出る前にプロパティポリシーを通過します。テキスト、パス、URL、メールアドレス、ラップされていない ID、そして `email`、`*_name`、`path`、`title`、`prompt`、`content`、`token` などのキーに入った文字列は、送信されずに破棄されます。文字列が送信されるのは、enum の値、バージョン、ロケール、モデル ID のように、閉じた語彙に属する短いトークンである場合だけです。

## 仮名化された ID

ID は送信されますが、仮名としてだけです。ワークスペース、スペース、会話、エージェント、実行、ユーザー、デバイスの各 ID は、そのインストール固有の秘密のソルト (`telemetry.pseudonym_salt`) を使った HMAC-SHA256 に置き換えられ、16 進数 20 文字に切り詰められます。同じワークスペースは常に同じ値を報告するため、イベントを結び付けて数えることはできますが、生の ID がインストールの外に出ることはありません。ソルトはサーバーの初回起動時に作成され、分析プロバイダーに送信されることはありません。サーバーのデータディレクトリを削除すると新しいソルトとインストール ID が作成され、それ以前に記録されたものとの結び付きはすべて切れます。

## 画面の表示

ナビゲーションのたびに、URL が **ルートテンプレート** であるページビューが記録されます。たとえば `/workspaces/:workspaceId/spaces/:spaceId` のようなもので、具体的なアドレスが記録されることはありません。画面名はテンプレートのリテラルなセグメントで構成されるため、この例では `workspaces_spaces` になります。`Id` で終わるルートパラメーターは仮名化された `*_id` プロパティとして、数値のパラメーター (PR 番号など) は数値として付加されます。それ以外のパラメーターはすべて破棄されます。

## 配信

イベントは、最大 200 件を保持するメモリ上のキューから `<host>/api/send` に 1 件ずつ送信されます。ネットワークエラー、タイムアウト、`429`、`5xx` の場合はイベントを保持したまま、1 秒から最大 5 分までの指数バックオフで再試行します。それ以外の `4xx` ではイベントを破棄します。ディスクには何も書き込まれないため、アプリの終了時にキューに残っているイベントは失われます。キューは、アプリがバックグラウンドに移ったときとサーバーがシャットダウンするときにフラッシュされます。

## ビルドの送信先を別のインスタンスに向ける

送信先はビルド時に固定されます。

```bash
--dart-define=CC_ANALYTICS_HOST=https://analytics.example.com/
--dart-define=CC_ANALYTICS_WEBSITE_ID=<website uuid>
```

プロバイダーのアダプターは `packages/cc_analytics` にあります。別の分析サービスに対応するには、そこにアダプターを追加します。トラッキングプランとプライバシーのルールは変わりません。
