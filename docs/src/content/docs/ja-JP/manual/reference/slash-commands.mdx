スペースのコンポーザーで入力するコマンドです。効果を及ぼす場所によって 3 つのグループに分かれ、その違いは重要です。**ローカル**なコマンドはメッセージとして運ばれることがないため、トランスクリプトに現れることも、エージェントに届くこともありません。

| 実行される場所 | 意味                                                                                |
| ------------- | ---------------------------------------------------------------------------------- |
| **ローカル**   | クライアント（またはクライアントが起動したサーバー操作）で処理されます。コマンドがメッセージとして運ばれることはないため、どのエージェントにも見えません。 |
| **サイド**     | 会話についてのサーバー側のモデル呼び出し 1 回です。会話は変更されません。            |
| **ディスパッチ** | メッセージが開始する実行のモードまたは指示を設定します。                            |

---

## 実行の指示

### `/plan`

**ローカル → ディスパッチ。** 会話でプランモードを有効にします。完全に読み取り専用のワークツリーと、`read` までに制限されたツールサーフェスです。エージェントの成果物は編集ではなくプランです。引数なしの `/plan` はモードを切り替えるだけで、メッセージとして運ばれることはありません。プロンプトを伴う場合、その行の残りの部分が実行を開始します。

### `/goal <objective>`

**ディスパッチ。** 自律的な目的を開始し、ゴールスーパーバイザーがそれをセグメントをまたいで再ディスパッチし、再起動します。

`/goal` をテキスト付きで入力すると、まず**目的を明確にするヒアリング**が開きます — 次の 5 つがそろうまでドラフトを受け付けない短いパスです。判断を挟まずに評価者が決着できる成功基準、正確な検証コマンド、試行回数の上限、スコープの境界、停止条件です。各ステップには*スキップしてそのまま実行*が用意されています。このヒアリングは既定であり、ゲートではありません。

`/goal pause`、`/goal resume`、`/goal drop` はスラッシュコマンドではありません。一時停止、再開、停止は、サイドバーにあるその会話のゴール一覧にあります。目的そのものに指定する開始フラグは `--budget <dollars>`、`--max <N>`（実行予算）、`--days <N>`（期限）です。コスト上限に達したゴールは、同じサイドバーのコントロールからその上限を引き上げることによってのみ再開します。

:::note[そもそもなぜ中断するのか]
自律的なゴールは、曖昧なブリーフが本当に高くつく唯一の場所です。その実行は、誰も「完了」を定義していない目的のために何時間も働き、その後、自分自身の基準で成功を報告します。5 つの質問は、終わったと感じた時点で終わる夜通しの実行 1 回よりも安くつきます。
:::

### `/loop [budget] [task]`

**ディスパッチ。** 完了するまで反復的に作業します。上限を受け付けます: `/loop 10`、`/loop 30m`、`/loop 1h30m`、`/loop 10 minutes fix the tests`。

上限のように*見える*トークン（数字または符号で始まるもの）が解析に失敗した場合は、ハードエラーになります。散文はただの散文なので、`/loop keep going until the tests pass` は誤解析ではなく、インラインのプロンプトを伴う上限なしのループです。

### `/vibe [task]`

**ディスパッチ。** セッションを**ディレクター**にします。自身のツールは `read` と 5 つのワーカー動詞に落ち、編集はバックグラウンドのワーカーが行います。[バックグラウンドワーカーを指示](/ja-JP/マニュアル/ハウツーガイド/バックグラウンドワーカーの指示/)を参照してください。

ワーカーがモードより長生きすることはありません — モードを抜けると、そのすべてが強制終了されます。

## コンテキストの管理

### `/compact`

**ローカル → サーバー。** 古い履歴をアンカー付きの要約に畳み込み、圧縮されたコンテキストで続行します。モデルに渡る引数はありません。コマンドがメッセージとして運ばれることはなく、コンパクションのパスもフォーカスのヒントを受け取りません。

### `/shake [target]`

**ローカル → サーバー。** 要約**せずに**重いコンテンツを落とします。モデル呼び出しはなく、すべての語はそのまま残り、誰も読み返さないようなかさばりだけが空白になります。

| 対象          | 削除されるもの                    |
| ------------- | --------------------------------- |
| `tool_output` | これといった出来事のない古いツール結果（既定） |
| `images`      | 古いスクリーンショット（そのテキストは保持） |
| `all`         | 両方                              |

これは「コンテキストは膨らんでいるが要約はしたくない」ときの逃げ道です。

### `/context [agent]`

**ローカル。** この会話のエージェントのコンテキストエクスプローラーを、専用のタブで開きます。コンテキストウィンドウのすべてのセグメントと部分 — システムプロンプト、スキル、コンテキストファイル、ツールスキーマ、履歴、画像 — について、それぞれがどれだけコストになっているかと、その背後にあるそのままの内容を示します。

タブは（スペース、エージェント）の組をキーとするため、2 回実行しても同じ内訳のコピーが積み重なるのではなく、1 つのタブに再フォーカスします。

**エージェントが複数いる**スペースでは、引数なしの `/context` は、ヘッダーのコンテキストメーターが読んでいるウィンドウを開きます — ここで最後に作業したエージェント、つまりトレイルの一番下にメッセージがあるエージェントです — そしてタブには `コンテキスト · <name>` というラベルが付き、誰のものかが分かります。切り替えるには別の名前を指定します: `/context qa`（`@` は任意です）。入力した名前はあいまい一致ではなく完全一致で解決されます。2 体のエージェントは 2 つの異なるウィンドウを持つため、もう一方を開いてしまう惜しい一致は、尋ねていない質問へのもっともらしい答えになってしまうからです。

同じエクスプローラーはスペースヘッダーのコンテキストメーターのチップの背後にもあり、それも同じエージェントに追随します — コマンドとチップが、ここでの「コンテキスト」の意味について食い違うことはありません。

## 会話について尋ねる

これらはモデル呼び出しを 1 回消費し、**会話を変えることはありません**。エージェントの次の実際のターンは、どのみち見ていたはずのものをそのまま見ます。これが、尋ねることの価値のすべてです。

### `/handoff [focus]`

**サイド。** 作業を冷たい状態で引き継ぐ人向けのハンドオフドキュメントを書きます。タスクは何か、何が分かったか、何が残っているか。

### `/btw <question>`

**サイド。** ここまでの作業についての質問に、質問も答えもトランスクリプトに加えることなく答えます。

:::note[2 つのコマンド、1 つの実装]
どちらも同じ形です — 今のままの会話を取り、それについて 1 つ質問し、どちら側も永続化しません。1 度だけ実装されているので、「ここまでのコンテキスト」という 2 つの異なる概念にずれていくことはありません。
:::

## ナビゲートとエクスポート

### `/tree`

**ローカル。** ブランチナビゲーターを開きます。会話がどこで分岐したか、現在どのパスにいるか、離れたパスにどう戻るかが分かります。[会話をブランチ](/ja-JP/マニュアル/ハウツーガイド/会話のブランチ/)を参照してください。

### `/export`

**ローカル。** 会話を自己完結した HTML ファイルに書き出します — 折りたたみ可能なツールカードがあり、スタイルシートもスクリプトも画像ホストも不要です。デスクトップでは `Documents/ControlCenter/exports/` に保存され、Web ではダウンロードになります。

### `/dump`

**ローカル。** トランスクリプトを markdown としてクリップボードにコピーします。ツール呼び出しは折りたたみ可能なブロックになります。推論は意図的に除外されています。バグレポートに貼り付けられるトランスクリプトは、人が読むものだからです。

## その他すべて

### `/todo [subcommand]`

**ローカル。** 会話に永続化されたチェックリストを表示および編集します。引数なしの `/todo` はエディターを開きます。サブコマンド: `append`、`start`、`done`、`drop`（別名 `rm`）、`edit`、`copy`、`export`、`import`。

### `/skill:<name> [args]`

**ディスパッチ。** インストール済みのスキルを適用します。スキルは独自の `skill:` プレフィックスの下にあるため、組み込みコマンドとは名前空間を共有しません — そうでなければ、`plan` という名前のスキルは永久に到達不能になります。

### `/<your-command> [args]`

**ディスパッチ。** リポジトリ内の `.agents/commands`、`.agent/commands`、`.claude/commands`、`.codex/commands`、`.opencode/commands` の下にある任意の markdown ファイルです。ネストした `foo/bar.md` は `foo:bar` としても到達できます。

テンプレート: `$1`、`$@`、`$@[start:length]`、`$ARGUMENTS`。frontmatter では `description`（コンポーザーのオートコンプリート）を設定できます。`allowed-tools` と `model` はファイルから解析されますが、現時点でユーザーコマンドの呼び出しが行うのは本文への引数の置換だけです — 実行のモデルやツールサーフェスを変えることはありません。

ユーザーが作成したコマンドは、同名のスキルに優先します — 人間が引数付きで意図的に呼び出したショートカットだからです。

## マジックキーワード

コマンドではありません。プロンプト内のどこかにある、単独の小文字の単語が、そのターン用の隠れた指示を付け加えます。

| 単語          | 効果                                                               |
| ------------- | ------------------------------------------------------------------ |
| `ultrathink`  | そのターンの推論の程度を最大にする                                  |
| `orchestrate` | 独立した作業を並列で委任し、各フェーズを検証する                     |

マッチャーは境界について意図的に厳格です。`orchestrate,` は一致し、`orchestrated`、`orchestrate.ts`、`foo::orchestrate`、`orchestrate()` は一致しません。また、フェンス付きコードブロック、インラインスパン、XML セクションは先にマスクされます。これがなければ、スタックトレースを貼り付けるだけでエージェントの動作が変わってしまいます。
