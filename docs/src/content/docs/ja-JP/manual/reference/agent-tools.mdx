これらは、組み込みエージェントランタイムが直接登録する**サーバーにバインドされた**ツールです — 言語サーバー、構造検索、デバッガー、カーネル、コードモードのスクリプト、質問、ワーカー制御 — ブリッジして取り込む [MCP ツール](/ja-JP/マニュアル/リファレンス/mcp-ツール/)や、ハーネスランタイムの汎用のファイル・検索・シェルツールとは対照的です。これらは MCP レジストリには載りません。外部の MCP クライアントには見えません。それぞれが、1 回の実行に属する生きたサーバー側のリソース — 言語サーバープロセス、デバッグアダプター、インタープリター — にバインドされているからです。

ここにあるすべてのツールは、その背後にあるリソースがその実行向けに配線されている場合にのみ登録されます — 言語サーバーまたはデバッグのスーパーバイザー、tree-sitter パーサー、カーネルファクトリー、質問ポート、vibe のロスターです。*このチェックアウト*に対する言語サーバーやデバッグアダプターの検出は、別の、より後に行われるチェック（`status` / `adapters`）です。それらのツールがサーフェスに残るのは、推測するのではなく、なぜ何も使えないのかをエージェントが尋ねられるようにするためです。

## 承認ティア

各ツールはティアを宣言し、そのティアが**どのサーフェスから見えるか**を決めます — 単にプロンプトを出すかどうかではありません。プランモードと読み取り専用のサブエージェントは `read` が上限であるため、`write` または `exec` ティアのツールはそのスキーマにそもそも存在しません。

| ティア  | 意味                       | ここにあるツール                                 |
| ------- | -------------------------- | ------------------------------------------------ |
| `read`  | 副作用なし                 | `lsp`、`ast_grep`、`ask_user`、`repl`、5 つの `vibe_*` |
| `write` | ファイルを変更する         | `lsp_rename`、`ast_edit`、`resolve`              |
| `exec`  | プロセスを起動または制御する | `debug`、`eval`                                |

## 直接、スクリプトからのみ、または初回使用時に読み込み

サーバーがスクリプトを実行できる場合、実行は少数のツールを直接呼び出し、残りは [`repl`](#repl--ツールを呼び出すスクリプトを実行する) のスクリプトから到達します。ルール全体については、[コードモード](/ja-JP/マニュアル/コンセプト/コードモード/#エージェントが直接呼び出すツール)を参照してください。このページのツールについては、次のとおりです。

| ツール | `repl` あり | `repl` なし |
| ---- | ----------- | -------------- |
| `repl` | 直接 | 存在しません |
| `ask_user` | 直接 | 直接 |
| `lsp`, `lsp_rename`, `ast_grep`, `ast_edit`, `resolve`, `debug` | スクリプトからのみ | 初回使用時に読み込み |
| `eval` | 初回使用時に読み込み（スクリプトからは呼び出せません） | 初回使用時に読み込み |
| `vibe_*` | vibe モードでは直接、スクリプトからは決して呼び出せません | vibe モードでは直接 |

「スクリプトからのみ」と示されたツールは、サーバーがその実行のスクリプトを実行できなくなると、代わりに初回使用時に読み込まれます（[スクリプトを実行できない場合](/ja-JP/マニュアル/コンセプト/コードモード/#スクリプトを実行できない場合)）。

## `lsp` — 言語サーバークエリ

実行に言語サーバーのスーパーバイザーと作業ディレクトリがある場合に登録されます。サーバーが実際に応答できるかどうかは、呼び出し時に**積集合**として検出されます。ルートマーカーが存在し、*かつ*サーバーバイナリが解決できなければなりません。どちらか片方だけではサーバーは起動しません — そう `status` が告げます — 黙って推測することはありません。

サーバーは組み込みの表からのみ取得され、リポジトリの `lsp.json` は読み込まれません。サンドボックス内で実行される場合、実行ごとに独自の言語サーバーセッションが得られるため、サーバーは実行ごとに再び起動します。プロジェクトローカルのバイナリ（`node_modules/.bin`）はサンドボックス内で実行される場合にのみ使われ、プロジェクトルートが実行の作業ディレクトリより上に解決されることは決してありません。

位置は `line` と `symbol` の部分文字列で指定し、列番号は決して使いません。列番号を求められたモデルは推測し、その推測が外れると同じ行の別のシンボルに解決されます — 正しく見えるのに、別のものについての答えです。ナビゲーションアクションで `symbol` を省略することはエラーであり、先頭列の推測ではありません。

| アクション        | 引数                             | 戻り値                                     |
| ----------------- | -------------------------------- | ------------------------------------------ |
| `diagnostics`     | `file`（または `"*"`）           | エラーと警告。`"*"` は代わりにプロジェクトチェッカーを実行します |
| `definition`      | `file`、`line`、`symbol`         | シンボルが宣言されている場所               |
| `type_definition` | `file`、`line`、`symbol`         | その型が宣言されている場所                 |
| `implementation`  | `file`、`line`、`symbol`         | 具体的な実装                               |
| `references`      | `file`、`line`、`symbol`         | すべての使用箇所。上限は 50                |
| `hover`           | `file`、`line`、`symbol`         | シグネチャとドキュメントコメント           |
| `symbols`         | `query` または `file`            | `query` でワークスペース検索（上限 100）。`file` でドキュメントシンボル（上限 200） |
| `code_actions`    | `file`、`line`、`symbol`         | サーバーが提示するクイックフィックス       |
| `status`          | —                                | どのサーバーが、どのルートに対して実行中か |
| `reload`          | —                                | このルートのサーバーを再起動します         |

### 書き込み時の診断

見返りはツールそのものではありません。`write`、`edit`、`apply_patch` が**ラップされています**。書き込みの後、ファイルは言語サーバーを通して同期・保存され、**新たに導入された**診断だけがツールの結果に折り込まれます。エージェントは、ビルドを壊したまさにその瞬間に、壊したことを知ります。尋ねるのを覚えておく必要はありません。

すでに報告済みの診断は、重要度・コード・メッセージをキーとする実行ごとの台帳によって抑制されます — 位置は意図的に除外されているため、4 行下にずれただけの診断が新しいものとして再報告されることはありません。

## `lsp_rename` — プロジェクト全体のリネーム

別個の `write` ティアのツールである理由は、ただ 1 つです。ティアが可視性を決めるからです。リネームを `lsp` に畳み込むと、読み取り専用の探索者にリポジトリを書き換える能力を与えるか、すべての `hover` を承認プロンプトの背後に置くかのどちらかになります。

| 引数       | 意味                                   |
| ---------- | -------------------------------------- |
| `file`     | シンボルがある場所                     |
| `line`     | 1 始まりの行番号                       |
| `symbol`   | その行でシンボルを特定する部分文字列   |
| `new_name` | 新しい名前                             |

## `ast_grep` — 構造検索

コードをテキストではなく**形**で見つけます。`$NAME` は任意のノードにマッチし、`$$$NAME` は連続する兄弟にマッチし、`$_` は何も捕捉しないワイルドカードです。

これを「ひと手間多い正規表現」ではなくマッチャーにしている性質は、ひとつのパターンの中で繰り返されるメタ変数が同じテキストを捕捉しなければならないことです。

```
ast_grep(pattern: "if ($X != null) $X.dispose()", language: "dart")
```

これは、検査したものを破棄するガードにマッチし、別のものを破棄するガードには**マッチしません**。

| 引数          | 意味                                                        |
| ------------- | ----------------------------------------------------------- |
| `pattern`     | メタ変数を含むコードの断片                                  |
| `path`        | 検索するファイルまたはディレクトリ。デフォルトはワークスペース全体 |
| `language`    | 出荷されている文法 ID（`dart`、`python`、`rust`、`c`、…）。`path` がファイルを指すときは推論されます |
| `max_results` | デフォルトは 50                                             |

:::note[パターンはファイルと同じ文法でパースされます]
そのため `dispose(x)` は、スペースの入れ方や折り返し方、コメントの有無に関係なくその呼び出しにマッチし、文字列リテラルやコメントの中の同じ文字並びには決してマッチしません。
:::

:::caution[断片はそのままではなく、スキャフォールドの中でパースされます]
Dart のトップレベルでパースされた `dispose(x)` は、有効な*関数シグネチャ*です。パターンコンパイラーはコンテキストのはしご（文、式、クラスメンバー、宣言）を順に試し、その断片を受け入れた最初のものを採用します。どのコンテキストも受け入れないパターンは、検索して静かに見つからなかったことにするのではなく、パース不能として報告されます。
:::

## `ast_edit` — ステージングされる構造書き換え

同じマッチングに加えて、メタ変数を戻し入れる `rewrite` テンプレートを使います。**何も書き込まれません。** 変更はステージングされ、結果が `edit_id` を名指しします。

```
ast_edit(pattern: "dispose($X)", rewrite: "$X.dispose()", language: "dart")
→ (proposed) 12 replacements in 4 files … call resolve with edit_id "edit_1"
```

| 引数       | 意味                                        |
| ---------- | ------------------------------------------- |
| `pattern`  | マッチするもの                              |
| `rewrite`  | そこに置くもの。`$NAME` が置換されます      |
| `path`     | スコープ。デフォルトはワークスペース全体    |
| `language` | 言語 ID                                     |

## `resolve` — ステージングされた変更のコミットまたは破棄

| 引数      | 意味                             |
| --------- | -------------------------------- |
| `edit_id` | `(proposed)` の結果から          |
| `action`  | `accept` または `discard`        |

すべてのファイルは、ステージング時に捕捉した内容と照合され、**少しでも**食い違えば変更全体が拒否されます。部分的に適用された構造的書き換えは、古い形でも新しい形でもコンパイルできないツリーを残します。

## `debug` — デバッガーを操作する

実行にデバッグセッションのスーパーバイザー、作業ディレクトリ、会話 ID がある場合に登録されます。アダプターが実際に起動できるかどうかは、言語サーバーと同じ積集合のルール（ルートマーカー*かつ*バイナリ）で、呼び出し時に検出されます。`exec` ティアで、並列安全ではありません（セッションは呼び出しをまたぐ状態なので、`continue` が `stack` を追い越すと、すでに動いてしまったフレームを読むことになります）。

会話ごとにセッションは 1 つで、厳密な TTL（30 分）があります。2 回目の `launch` は、最初のものを黙って置き換えるのではなく拒否されます。サンドボックス内で実行される場合、セッションは終了するまでターンをまたいでサンドボックスを保持します。そのため、保持されるのは最大でその 30 分です。

| 操作          | 引数                          | 備考                                           |
| ------------- | ----------------------------- | ---------------------------------------------- |
| `adapters`    | —                             | ここでどのアダプターが使えるか、使えないならなぜか |
| `status`      | —                             | セッションが実行中かどうか、どこで停止したか   |
| `breakpoints` | `file`、`lines[]`             | `lines` が空だとそのファイルのブレークポイントを消去します。起動の**前に**設定できます |
| `launch`      | `program`、`args[]`           | ブレークポイントで停止した状態でプログラムを開始します |
| `attach`      | `port`                        | 実行自身の転送ポートのうち、すでに実行中のデバッグ対象に接続します。ほかのポートは、何も始まる前に拒否されます         |
| `continue`    | `thread_id?`                  | 次の停止まで実行します                         |
| `pause`       | `thread_id?`                  | その場で停止します                             |
| `step_over` / `step_in` / `step_out` | `thread_id?` | 1 ステップ動かします                  |
| `threads`     | —                             | スレッド ID と名前                             |
| `stack`       | `thread_id?`                  | フレーム。上限は 30                            |
| `scopes`      | `frame_id`                    | フレーム上のスコープ。それぞれ `reference` を持ちます |
| `variables`   | `reference`                   | 子。上限は 50、値は 400 文字まで               |
| `evaluate`    | `expression`、`frame_id?`     | フレーム自身のスコープで評価されます           |
| `output`      | —                             | デバッグ対象の stdout/stderr。上限あり         |
| `terminate`   | —                             | セッションを終了し、アダプターを停止します     |

### アダプター

| ID        | コマンド                     | ルートマーカー                                    |
| --------- | ---------------------------- | ------------------------------------------------- |
| `dart`    | `dart debug_adapter`         | `pubspec.yaml`                                    |
| `debugpy` | `python3 -m debugpy.adapter` | `pyproject.toml`、`setup.py`、`requirements.txt`  |
| `lldb`    | `lldb-dap`                   | `Cargo.toml`、`CMakeLists.txt`                    |
| `delve`   | `dlv dap`                    | `go.mod`                                          |

`debugpy` は、実行がサンドボックス内にある場合に限り、プロジェクトローカルの `.venv/bin` または `venv/bin` を `$PATH` より優先します。`$PATH` 上の python は別の環境であり、誤ったほうからアタッチすると、壊れたコードのように見える形で失敗します。サンドボックス外では `$PATH` だけを使うため、リポジトリがホスト上で動くインタープリターを選ぶことはできません。

## `repl` — ツールを呼び出すスクリプトを実行する

サーバーがスクリプトを実行できる場合、すべての実行に存在します（[実行が `repl` を持つとき](/ja-JP/マニュアル/コンセプト/コードモード/#実行が-repl-を持つとき)）。スクリプトはプレーンな JavaScript で、非同期関数の本体として書かれ、独自のプロセス内の新しいロックダウン済みインタープリターで実行されます。ファイルシステム、ネットワーク、プロセス、モジュールへのアクセスはありません。`repl` 自体は `read` ティアで、自身を守ります。スクリプトが行うすべてのツール呼び出しは、それぞれ個別にチェックされるからです。MCP エンドポイントでも、スクリプトを実行できるサーバー上のエージェント実行に提供されます。

| 引数 | 意味 |
| ------------------- | --------------------------------------------------------------------------------------------- |
| `code` | スクリプト。最大 256 KiB |
| `description` | 必須。会話の行に表示される短いラベル |
| `timeout_ms` | 省略可能。ワークスペースより短い時間制限。より長くすることはできません |
| `max_output_tokens` | 省略可能。ワークスペースより小さい出力上限。より大きくすることはできません |

```js
// Read three files together and report only which ones failed.
const paths = ["lib/a.dart", "lib/b.dart", "lib/c.dart"];
const results = await Promise.allSettled(paths.map((path) => tools.read({ path })));
return results
  .map((r, i) => (r.status === "rejected" ? `${paths[i]}: ${r.reason.message}` : null))
  .filter(Boolean);
```

`repl` の説明は、エージェントにこう伝えます。「直接呼び出しツールではないツールには、この要求に定義がありません。そのツールを初めて呼び出す前に、正確な呼び出し形式がこの会話ですでに示されていない限り、`describeTool(name)` または `searchTools(query)` で調べてください。」

`describeTool(name)` は、ツールの説明、その宣言、入力と出力のスキーマ、そして結果の注記（ある場合）を返します。結果の注記とは、完了した呼び出しからスクリプトが受け取るものを、ツール自身の言葉で説明したものです。`repl` の説明には、スクリプトが呼び出してよい直接呼び出しツールの注記が一覧されます。JSON テキストである結果は、解析された状態で届きます。ただし値の数が 131,072 個を超える場合は、テキストのまま届き、スクリプトが `JSON.parse` で解析します。外部 MCP サーバーのツールからの結果のテキストは 262,144 文字で切り詰められ、切り詰められたテキストはもう解析できません。

- `tools.<name>(args)` は、直接の呼び出しと同じフィルター、ガードレール、承認を通してツールを呼び出します。拒否されたり失敗したりした場合は、エラーで拒否されます。読み取り専用の呼び出しは同時に実行できます。何かを変更する呼び出しは、スクリプトが行った順番どおりに、1 つずつ実行されます。スクリプトの呼び出しのいずれかが人を待っている間は、そのスクリプトの他の呼び出しは開始されません。
- `ALL_TOOLS`、`searchTools(query, { limit, namespace })`、`describeTool(name)`、`describeNamespace(name)` でツールを探します。接続された MCP サーバーのツールも含まれます。直接呼び出しセットの外にあり、スクリプトが呼び出してよいツールは、スクリプトからのみ呼び出せます。そのツールを直接呼び出すと、`repl` から呼び出す方法が返されます。サーバーがその実行のスクリプトを実行できなくなると、そのようなツールは代わりに初回使用時に読み込まれます。
- 検索には制限があります。クエリは 1,024 文字以内、名前または名前空間は 256 文字以内、`limit` は 0 から 50 まで、そして 1 つのスクリプトにつき検索に使えるサーバー時間は合計 2 秒、最大 200 回までです。さらに同じワークスペースのすべてのスクリプトは、検索時間の 2 秒を共有します。この時間は 1 秒ごとに 0.25 秒ずつ戻ります。どちらかの上限を超えると、以降の検索は拒否されます。非常に大きなカタログでは、`ALL_TOOLS` の説明が約 100 万文字を均等に共有し、切られたものは `…` で終わります。`describeTool` は常に説明全体を返します。大きすぎて表示できない型は `unknown /* too large to show */` と表示され、存在しない名前には最も近い名前が返されます。
- ツールは名前空間にまとめられます：`builtin`（ハーネス自身のツール）、`control-center`（Control Center のツール）、そして接続された MCP サーバーごとに 1 つで、サーバー名が付けられます。`builtin`、`control-center`、`script` という名前のサーバー、または名前が `external-` で始まるサーバーは、大文字と小文字をどう混ぜても、また名前の前後に空白があってもなくても、`external-` の後にその名前を付けて一覧に表示されます。どのツールも `script` の名前空間に属することはありません。
- スクリプトが返した値、または `text()`、`image()`、`console.*` に渡された値だけがエージェントに戻ります。上限を超えた出力は先頭と末尾を残して短縮され、残りは `read_output` で読めます。
- `store(key, value)` / `load(key)` は、同じ会話とエージェントの後続のスクリプトのために JSON 値を保持します。値は、スクリプトが完了したときにだけ保存されます。サブエージェントのスクリプトには保存領域がありません。
- `await tools.ask_user(...)` は質問をします。その回答は結果にも追加されます。`sleep(ms)`、`setTimeout`、`limits()`、および `models.embed` / `rank` / `classify`（オンデバイスの埋め込み）も利用できます。
- `describeTool(name)` と `searchTools(query)` は、ツールではないスクリプト自身の関数についても答えます。それらは名前空間 `script` の下にあり、`text`、`image`、`store`、`load`、`sleep`、`setTimeout`、`clearTimeout`、`limits`、`exit`、`models.*` です。
- スクリプトから呼び出せないもの：`repl`、`eval`、`task`、`checkpoint`、`rewind`、`compact`、`search_tools`、および `vibe_*` の動詞。
- スクリプトは自身の実行の過去を読めます。`history({start, role, tool, limit})` は会話の文字起こしをページ単位で読み（呼び出しごとに最大 50 行。前のページの `next_start` を `start` として渡します）、`outputs()` はこの会話とエージェントについて保存されたツール出力を一覧し、`loadOutput(handle)` は 1 つの出力の 16,384 文字を読みます。`storedKeys()` は保存されたキーとそのサイズを一覧します。`keep(value, label)` は大きな値を、後のスクリプトや `read_output` が読める出力として保存します。保存されるのはスクリプトが完了したときだけです（1 値あたり 1 MiB、実行あたり 64 値と 16 MiB）。`limits().returnBudgetChars` は出力予算の残りを示します。読み取り専用の実行（ゴールのレビュー）は読めますが、保存や keep はできません。Claude Code と ACP では、`history()` は動作し、`outputs()`、`loadOutput()`、`keep()` は拒否されます。Control Center はそれらの実行のツール出力を保持しないためです。
- タイムアウト、出力のオーバーフロー、または呼び出し上限によるエラーには、その直し方が書かれています。

1 回の実行では、一度に 1 つのスクリプトだけが動きます。各制限と、その上限に達したときの動作は、[コードモード](/ja-JP/マニュアル/コンセプト/コードモード/#制限)のページにあります。すべてのスクリプトは**オブザーバビリティ → コード実行**に記録されます。

## `eval` — 永続インタープリター

変数、インポート、読み込んだデータが呼び出しをまたいで残る Python または JavaScript のセルです。`exec` ティアで、並列安全ではありません。`repl` スクリプトからは呼び出せず、セルからその実行のツールを呼び出すこともできません。コードからツールを呼び出すには、[`repl`](#repl--ツールを呼び出すスクリプトを実行する)を使います。

| 引数          | 意味                                             |
| ------------- | ------------------------------------------------ |
| `code`        | セル                                             |
| `description` | 必須。トランスクリプトのラベル用の 5〜10 語      |
| `language`    | `python`（デフォルト）または `javascript`        |
| `reset`       | インタープリターを破棄し、先にまっさらな状態から始めます |

- 最後の式は、ノートブックと同じようにエコーされます。
- `display()` は機能し、pandas のフレームは表としてレンダリングされ、matplotlib の図は**トランスクリプトが表示する画像**として返ります。
- 人が反射的に入力する IPython のイディオム — `%pip`、`%cd`、`!cmd`、`%%bash`、`%%timeit` — は素のコードに書き換えられます。`%pip` は `sys.modules` からも追い出すため、次の `import` はたった今インストールされたものを認識します。
- 出力予算を超えて出力するセルは、先頭の 4 分の 3 と末尾の 4 分の 1 を残し、削除された文字数と画像数を示す 1 行が付きます。
- インタプリタが頼まれていないのに終了した場合、次のセルには、以前の変数がなくなったことが一度だけ知らされます。

:::note[カーネルがどこで実行されるか]
会話がエンクロージャーを持つ場合はその中で、そうでなければホスト上の実行の OS サンドボックス内で実行されます。サンドボックスがオフまたは利用できない場合は制限なしで実行され、`eval` はホスト実行の承認を求めます。そこへ行くためにエンクロージャーを起動することはありません — リグのタブが自動起動しないのと同じルールです。
:::

## バックグラウンドでの `bash`

`run_in_background: true` 付きの `bash` は、コマンドを開始し、待たずにすぐハンドル（`b1`、`b2`、…）を返します。エージェントは作業を続けるか、ターンを終えてコマンドが終了したときに起動されます。

| 引数 | 意味 |
| ------------------- | ------- |
| `run_in_background` | 開始してすぐに返すには `true` |
| `timeout_seconds` | コマンドが強制終了されるまでの秒数: 既定では 600、最大 3,600 |
| `notify` | 省略可。単純なパターンです。コマンドの実行中、一致する出力行ごとにエージェントへ送られます（例: `listening on\|FAILED`） |

- 1 回の実行で同時に動くバックグラウンドコマンドは最大 4 つです。それぞれ、タイムアウトに達したときと実行が終わったときに、開始したすべてのプロセスとともに強制終了されます。
- コマンドが終了すると、エージェントには、終了コード、出力の最後の 2,000 文字、残りを読むための `read_output` ハンドルを含む通知が届きます。
- 残りの作業がバックグラウンドコマンドだけになったエージェントは、モデルを呼び出さずに待機します。その間、実行の無音ウォッチドッグは一時停止します。
- `bash_output(handle)` はコマンドの状態と最近の出力を読みます。`bash_kill(handle)` はそれを停止します。どちらも、結果がすでに届けられている場合にはそう示します。
- スクリプトはバックグラウンドコマンドを開始できません。Claude Code には独自のバックグラウンド Bash があり、Control Center は、タスクを実行したままにしたターンの後、その実行を最大 10 分間開いたままにします。

## `compact` — コンテキストウィンドウの空きを作る

次のモデル呼び出しの前に、会話の古いコンテキストを圧縮します。`focus` が指定したもの（最大 1,000 文字）は残します。最新のターンはそのまま残ります。エージェントのターンごとの予算行には、コンテキストの使用率が 70%、80%、90% で表示されます。長い新しい作業フェーズの前には、約 70% を超えた時点で呼び出す価値があります。サーバーオーナーの `preCompact` フックは焦点に追加できます（[シェルフック](/ja-JP/マニュアル/リファレンス/エージェント設定/#シェルフック)）。圧縮の後、サーバーは「Still in flight」ブロックを追加します。ゴール、待機中の起動予約、未解決の依頼、バックグラウンドコマンド、チェックリスト、保存されたキーで、それぞれに回復するための呼び出しが付きます。

## `ask_user` — 人間に質問する

`read` ティアです。実行がオペレーターに何かを尋ねる**唯一**の方法です。会話内に番号付きのカードをレンダリングし、誰かが回答するか、スキップするか、質問がタイムアウトするまでブロックします。質問をチャットメッセージとして書かないでください — それはターンを終わらせてしまいます。

| 引数              | 意味                                       |
| ----------------- | ------------------------------------------ |
| `question`        | 尋ねる内容                                 |
| `context`         | 任意: なぜ尋ねているのか、回答次第で何が変わるのか |
| `options[]`       | 選択肢。それぞれ `{label, description?}`   |
| `allow_free_text` | 入力された回答を受け付けるかどうか         |
| `multi_select`    | 複数の選択肢を選べるかどうか               |

スキップは成功です。明示した前提の上で進め、二度尋ねないでください。タイムアウトは、同じ指示を伴うエラーです。許可プロンプト（「これをやってもいいですか」）は別のゲートであり、会話内に同じカードとして表示されます。

質問ポートと対象スペースの両方が存在する場合にのみ登録されます。人間が接続されていない場合、その呼び出しは永遠にブロックするのではなく**失敗**します — 承認者が接続されていないときにガードレールの `prompt` が取るのと同じフェイルクローズの姿勢です。

## `vibe_*` — バックグラウンドワーカーの指示

[vibe モード](/ja-JP/マニュアル/ハウツーガイド/バックグラウンドワーカーの指示/)がオンの間だけ登録されます。5 つとも `read` ティアです。ゲートは、編集が実際に起こるワーカーのツール側にあるべきです。

| ツール       | 引数                                     | 備考                                        |
| ------------ | ---------------------------------------- | ------------------------------------------- |
| `vibe_spawn` | `brief`、`label`、`tier?`                | すぐに戻ります。ワーカーは動き続けます      |
| `vibe_send`  | `worker_id`、`message`                   | ブリーフに追記して再実行します              |
| `vibe_wait`  | `worker_id`、`timeout_seconds?`          | 決着するまでブロックします                  |
| `vibe_kill`  | `worker_id`                              | 停止します                                  |
| `vibe_list`  | —                                        | ティア、ステータス、経過時間、最後の結果    |

`tier` は `fast`（明確な仕様がある機械的な作業）または `good`（設計、判断、または `fast` ワーカーの出力のレビュー）です。
