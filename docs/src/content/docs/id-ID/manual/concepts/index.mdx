These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/id-ID/panduan-pengguna/panduan-praktis/); when you want to look
something up, go to the [reference](/id-ID/panduan-pengguna/referensi/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/id-ID/panduan-pengguna/konsep/ruang-kerja/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/id-ID/panduan-pengguna/konsep/model-agen/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/id-ID/panduan-pengguna/konsep/siklus-hidup-pengiriman/) — what happens between your message and the agent's first token
- [Modes](/id-ID/panduan-pengguna/konsep/mode/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/id-ID/panduan-pengguna/konsep/konteks-alat/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/id-ID/panduan-pengguna/konsep/kecerdasan-kode/) — the code graph, language server, structural search and debugger
- [Conversation history](/id-ID/panduan-pengguna/konsep/riwayat-percakapan/) — persistence, compaction and forking a transcript
