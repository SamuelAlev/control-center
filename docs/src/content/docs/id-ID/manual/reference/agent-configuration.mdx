Referensi ini mencantumkan setiap bidang pada entitas agen, beserta enum dan flag yang digunakannya. Untuk panduan langkah demi langkah dalam membuat atau mengedit agen di aplikasi, lihat [Buat dan konfigurasi agen](/id-ID/panduan-pengguna/panduan-praktis/buat-agen/).

## Bidang entitas agen

| ----------------------- | ---------------------- | ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                    | `String`               | Ya    | Pengenal unik agen                                                                                                                                                                                  |
| `name`                  | `String`               | Ya    | Pengenal pendek untuk @-mention                                                                                                                                                                     |
| `title`                 | `String`               | Ya    | Judul peran yang terbaca manusia                                                                                                                                                                    |
| `agentMdPath`           | `String`               | Ya    | Jalur absolut ke file definisi `.md` agen                                                                                                                                                           |
| `workspaceId`           | `String`               | Ya    | Ruang kerja pemilik (tidak boleh null)                                                                                                                                                              |
| `reportsTo`             | `String?`              | Tidak | ID agen induk                                                                                                                                                                                       |
| `skills`                | `AgentSkills`          | Ya    | Kumpulan pengenal skill                                                                                                                                                                             |
| `persona`               | `String?`              | Tidak | Instruksi perilaku berupa teks bebas                                                                                                                                                                |
| `systemPrompt`          | `String?`              | Tidak | Menimpa prompt sistem bawaan                                                                                                                                                                        |
| `adapterId`             | `String?`              | Tidak | ID adapter inferensi                                                                                                                                                                                |
| `modelId`               | `String?`              | Tidak | ID model di dalam adapter                                                                                                                                                                           |
| `strictMode`            | `bool`                 | Tidak | Default `false`. Dituliskan ke baris dan ke `AGENTS.md` agen                                                                                                                                        |

| `contextSize`           | `int?`                 | Tidak | Ukuran maksimum jendela konteks                                                                                                                                                                     |
| `role`                  | `AgentRole?`           | Tidak | Peran agen                                                                                                                                                                                          |
| `monthlyBudgetMicros`    | `int`                  | Tidak | Batas pengeluaran bulanan dalam mikrodolar (default `0`, tak terbatas)                                                                                                                                     |
| `silenceTimeoutMinutes` | `int?`                 | Tidak | Penimpaan batas waktu diam dalam menit; harus null atau dalam rentang 1–240 (ditegaskan oleh konstruktor)                                                                                           |
| `maxConcurrentTasks`    | `int`                  | Tidak | Default `1`. Angka kapasitas yang dilaporkan model kehadiran (jumlah yang berjalan dan yang mengantre dibandingkan dengannya)                                                                        |
| `visibility`            | `AgentVisibility`      | Tidak | Default `workspace`                                                                                                                                                                                 |
| `lifecycleStatus`       | `AgentLifecycleStatus` | Tidak | Status tata kelola (default `active`). Ditulis oleh penghentian paksa anggaran dan ditampilkan pada bagan organisasi serta daftar kehadiran. Pengiriman tetap menerima pekerjaan dari agen `paused` |
| `budgetPolicyId`        | `String?`              | Tidak | ID kebijakan anggaran bersama; saat null `monthlyBudgetMicros` berlaku langsung                                                                                                                      |
| `runtimeProfileId`      | `String?`              | Tidak | ID profil runtime kustom                                                                                                                                                                            |
| `createdAt`             | `DateTime`             | Ya    | Stempel waktu pembuatan                                                                                                                                                                             |

`name` dan `title` keduanya harus tidak kosong (ditegaskan oleh konstruktor).
Default `monthlyBudgetMicros` bernilai `0` berarti tak terbatas. Tetapkan batas
atas dengan `agents.upsert`.

## Izin

Agen tidak membawa flag izin. Push, membuka dan memublikasikan pull request, menulis ke pelacak, dan egress jaringan adalah kelas aksi (`gitPush`, `prCreate`, `prPublish`, `vendorSyncWrite`, `networkEgress`) yang diselesaikan oleh [pagar pengaman](/id-ID/panduan-pengguna/konsep/pagar-pengaman/) pada cakupan ruang kerja, agen, atau space. Token GitHub sebuah run selalu bercakupan baca; push melewati gateway run agen, yang menanyakan aturan `gitPush` sebelum meneruskannya.

## AgentSkills

Kumpulan pengenal skill yang tidak dapat diubah dan tidak peka huruf besar/kecil. Saat pengiriman, slug-slug tersebut disinkronkan sebagai tautan skill di overlay agen; harness kemudian memuat otomatis frontmatter skill yang ditautkan ke dalam prompt.

```
{'flutter', 'dart', 'rest-api'}
```

## Hook shell

Hook shell memungkinkan pemilik server menjalankan skrip mereka sendiri di sekitar run agen: sekali saat sesi dimulai, sebelum setiap pemanggilan alat, setelah setiap pemanggilan alat, saat agen akan mengakhiri gilirannya, dan sebelum kompaksi. Hook adalah kode arbitrer, sehingga hook merupakan konfigurasi host. Hanya pemilik server yang menyiapkannya, secara manual, di mesin server. Tidak ada pengaturan di aplikasi dan tidak ada operasi yang menulisnya.

Untuk agen, hook berada di folder miliknya di bawah direktori data server:

```text
<data dir>/_agent_hooks/<workspace id>/<agent slug>/hooks.json
```

`<agent slug>` adalah nama folder agen di ruang kerja (`agents/<slug>/`). Folder itu berada di luar penyimpanan setiap ruang kerja, dan setiap sandbox menyembunyikan direktori data, sehingga tidak ada anggota, run, atau terminal yang dapat menulisnya.

`hooks.json` memetakan salah satu dari lima kunci ke sebuah skrip, dengan path relatif terhadap folder hook:

| Kunci          | Kapan dijalankan             | Arti kode keluarnya                                              |
| -------------- | ---------------------------- | ---------------------------------------------------------------- |
| `sessionStart` | Sekali, saat run dimulai     | Tidak ada; hook hanya mengamati                                  |
| `preTool`      | Sebelum setiap pemanggilan alat | `0` mengizinkan pemanggilan; selain itu menolaknya            |
| `postTool`     | Setelah setiap pemanggilan alat | Tidak ada; hook hanya mengamati                               |
| `stop` | Saat agen akan mengakhiri gilirannya | `2` dengan teks di stdout membuat run terus berjalan dengan teks itu; selain itu, giliran dibiarkan berakhir |
| `preCompact` | Sebelum kompaksi | `0`: stdout-nya ditambahkan ke apa yang harus dipertahankan ringkasan |

- Setiap skrip dijalankan sebagai executable tersendiri, tanpa shell dan tanpa argumen, sehingga ia harus dapat dieksekusi dan dimulai dengan baris shebang. Ia menerima peristiwa sebagai JSON di stdin: nama peristiwa, dan untuk hook alat, nama alat beserta argumennya (`preTool`) atau hasilnya (`postTool`).
- Hook berjalan sebagai salah satu proses alat run, di direktori agen untuk run tersebut. Ketika server menjalankan agen di sandbox, hook berjalan di dalam sandbox run. Ia mendapat lingkungan minimal dan tidak ada kredensial run: tidak ada token forge atau penyedia, dan tidak ada akses gateway.
- Setiap hook memiliki 30 detik. Output dari `sessionStart`, `preTool` dan `postTool` dibaca lalu dibuang.
- `preTool` gagal tertutup. Kode keluar bukan nol, timeout, atau skrip yang tidak dapat dimulai akan menolak pemanggilan alat.
- Path yang absolut, tidak ada, atau yang keluar dari folder hook (tautan diselesaikan terlebih dahulu) ditolak, dan log run menyatakan hook mana yang ditolak dan alasannya. `preTool` yang ditolak atau tidak dapat dibaca akan menolak setiap pemanggilan alat sampai diperbaiki.
- Blok `hooks` di `.agents/harness.json`, baik di repositori maupun di folder agen itu sendiri, diabaikan. Repositori sering kali merupakan kode orang lain, dan folder agen dapat ditulis oleh anggota serta oleh run. Log run menyatakan bahwa blok itu diabaikan dan di mana hook dibaca sebagai gantinya.

### Hook stop dan preCompact

- `stop` menerima `event: "stop"`, pesan terakhir agen (`last_message`), `stop_hook_active` (true saat stop ini mengikuti kelanjutan yang dipicu hook) dan `block_count` (berapa kali sejauh ini ia telah membuat run terus berjalan, dimulai dari 0). Untuk membuat run terus berjalan, ia keluar dengan `2` dan mencetak apa yang harus dilakukan agen berikutnya. Teks itu, dipotong menjadi 2.000 karakter, sampai ke agen sebagai pesan sistem.
- Hook `stop` membuat run terus berjalan paling banyak 3 kali dalam sebuah run. Setelah itu ia tidak dijalankan lagi, dan giliran berakhir.
- `stop` gagal terbuka. Timeout, skrip yang tidak dapat dimulai, keluaran apa pun selain `2`, atau keluaran `2` tanpa apa pun di stdout membiarkan giliran berakhir, sehingga hook yang rusak tidak dapat menahan run tetap terbuka.
- `preCompact` menerima `event: "pre_compact"`. Stdout-nya, dipotong menjadi 1.000 karakter, ditambahkan ke fokus kompaksi. Skrip yang gagal tidak menambahkan apa pun.

Hook shell berlaku untuk harness bawaan. Di Claude Code, hook `stop` dan `preCompact` juga berjalan: hook `Stop` dan `PreCompact` milik Claude Code meminta server, dan server menjalankan skrip pemilik dengan cara yang sama. Tiga kunci lainnya hanya berlaku untuk harness bawaan. `preTool` atau `postTool` yang dikonfigurasi membuat run memanggil alatnya satu per satu.

## AgentLiveState (turunan)

Tidak disimpan. Tujuh nilai. Urutan deklarasi adalah urutan prioritas (`sortPriority`, dipatok oleh pengujian), yaitu urutan yang dipakai daftar untuk mengurutkan:

| Status      | `sortPriority` | Kondisi                                                                                                            |
| ----------- | -------------- | ------------------------------------------------------------------------------------------------------------------- |
| `running`   | 0              | Ada log run yang berstatus `running`                                                                                |
| `blocked`   | 1              | Liveness run terbaru adalah `blocked`, `stalled`, atau `looping`                                                     |
| `failed`    | 2              | Status run terbaru adalah `error`, atau liveness-nya `failed` atau `dead`                                           |
| `queued`    | 3              | Sebuah run dikirim tetapi tidak sedang dieksekusi — tertahan di belakang run lain dari agen yang sama, atau sudah ditulis tetapi belum dimulai |
| `succeeded` | 4              | Run selesai dengan sukses                                                                                           |
| `idle`      | 5              | Agen sudah pernah berjalan dan tidak ada yang sedang diproses                                                        |
| `neverRun`  | 6              | Tidak ada log run                                                                                                   |

`queued` dan `succeeded` hanya **per run**. `deriveAgentLiveState`, yang menghitung status daftar untuk sebuah agen, tidak pernah menghasilkan keduanya — fungsi itu mengembalikan `neverRun`, `running`, `failed`, `blocked`, atau `idle`.
