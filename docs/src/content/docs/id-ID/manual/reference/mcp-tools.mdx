`cc_server` menghosting satu registri alat MCP (JSON-RPC 2.0), yang dilayani pada port server utama (bawaan `9030`) di `POST /mcp` dan `GET /sse`, versi protokol `2024-11-05`. Setiap klien menjangkau registri yang sama: desktop, build web, klien MCP eksternal, dan runtime agen bawaan. Server MCP eksternal dapat dijembatani ke registri yang sama sebagai lapisan dinamis.

## Ukuran registri

| Ukuran                                                                    | Jumlah |
| ------------------------------------------------------------------------- | ------ |
| Alat yang didaftarkan oleh `cc_server`                                    | 110    |
| Dari `packages/cc_mcp`                                                    | 108    |
| Dari `packages/cc_mcp_client` (penemuan alat)                             | 2      |
| Didaftarkan di registri dasar (`server_mcp_registry.dart`)                | 63     |
| Didaftarkan pasca-boot saat layanannya menyala (`cc_server_runtime.dart`) | 47     |
| Dari 63 milik registri dasar, bergantung pada repo graf kode              | 5      |

Kelima alat graf kode itu didaftarkan hanya ketika host meneruskan repo graf kode ke `buildServerMcpRegistry`. `cc_server` selalu meneruskannya, sehingga seluruh 110-nya aktif di biner yang dikirim.

Registri lengkapnya diumumkan di `tools/list` tanpa gerbang penemuan. Penyuntingan tiket adalah alat bertipe.

:::note[Klien eksternal selalu melihat seluruh katalog]
`tools/list` tidak pernah dipangkas. Klien MCP memvalidasi nama alat terhadap salinan cache-nya sendiri atas daftar itu dan menolak apa pun yang tidak terdaftar tanpa bertanya ke server, sehingga alat yang disembunyikan di sana menjadi tidak terjangkau, bukan sekadar diam.

**Harness bawaan** berbeda: ia hanya memuat subset definisi residen per permintaan dan menarik sisanya saat pertama kali dipakai, yang merupakan perilaku di sisi harness dan tidak mengubah registri ini. Lihat [Konteks alat dan cache prompt](/id-ID/panduan-pengguna/konsep/konteks-alat).
:::

:::note[Setiap kelas alat terdaftar]
Sebuah berkas sumber di bawah `packages/cc_mcp/lib/src/tools/` adalah alat yang dapat
dipanggil agen. `packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart`
menggagalkan build jika ada kelas alat baru yang tidak dibangun oleh apa pun.
:::

## Parameter umum

### `workspace_id`

**Wajib** pada setiap alat yang menyentuh data bercakupan ruang kerja. `workspace_id` yang hilang atau tidak valid mengembalikan galat eksplisit dan nilai yang tidak cocok dengan ruang kerja entitas sasaran akan ditolak alih-alih diabaikan diam-diam. Hilangkan pada alat yang benar-benar global: `list_workspaces` dan keenam alat umpan berita (`list_feeds`, `list_articles`, `get_article`, `set_article_read`, `set_article_saved`, `refresh_feeds`), yang mengikuti daftar feed per pengguna milik pemilik server. Alat penemuan (`search_tool_bm25`, `list_my_tools`) menerimanya secara opsional agar dapat mengklasifikasikan kelayakan pemanggilan berdasarkan mode percakapan. Saat agen dikirim oleh server, ruang kerja dipaksakan di sisi server, sehingga agen tidak dapat menjangkau ruang kerja lain dengan memberikan id asing.

## Penemuan alat

Keduanya berasal dari `cc_mcp_client`, bukan `cc_mcp`, dan keduanya mengonsultasikan penjaga mode sehingga melaporkan apa yang dapat dipanggil pada mode percakapan _saat ini_.

| Alat               | Deskripsi                                                                                                                        |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| `search_tool_bm25` | Telusuri katalog alat berdasarkan kata kunci; mengembalikan alat yang cocok, skema argumennya, dan apakah masing-masing dapat dipanggil saat ini juga |
| `list_my_tools`    | Tampilkan daftar alat yang dapat dipanggil saat ini dalam percakapan ini, difilter berdasarkan modenya                           |

Alat penemuan ketiga, **`search_tools`**, hanya ada di dalam harness bawaan dan bukan bagian dari registri MCP ini. Alat itu memberi peringkat pada permukaan alat milik run itu sendiri dan, tidak seperti `search_tool_bm25`, **memuat** skema dari apa yang ditemukannya sehingga agen dapat memanggil kecocokan itu pada gilirannya berikutnya. Agen di harness sebaiknya memilihnya; klien MCP memiliki `search_tool_bm25`.

## Alat enclosure (rig)

Kendalikan mesin sekali pakai — browser atau desktop Linux yang terkurung, emulator
Android, atau Simulator iOS — dari dalam sebuah run. Didaftarkan pasca-boot,
tanpa syarat: apakah sebuah mesin benar-benar dapat boot adalah pertanyaan probe
yang dijawab alat tersebut per panggilan. Panggilan berulang dalam satu percakapan memakai ulang satu mesin;
tangkapan layar dikembalikan sebagai konten gambar dengan anggaran satu gambar per hasil, dan
konten halaman/UI yang diekstrak dipagari sebagai data tidak tepercaya. Keempat alat `*_use` plus
`rig_close` mendeklarasikan [kelas tindakan](/id-ID/panduan-pengguna/konsep/pagar-pengaman/) `enclosureControl`
(keempat alat itu juga mendeklarasikan `networkEgress` dan `processSpawn`; `mobile_use` dan
`ios_use` juga mendeklarasikan `packageInstall`), sehingga mode hanya-baca menolaknya. `rig_list`
tidak mendeklarasikan apa pun — ia hanya membaca status ruang kerja. Kosakata verba lengkap per permukaan ada di
[referensi rigs](/id-ID/panduan-pengguna/referensi/rigs/#action-verbs).

| Alat           | Deskripsi                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------ |
| `computer_use` | Kendalikan desktop Linux di VM terkurung: gerakkan, klik, seret, gulir, ketik, ubah ukuran, papan klip, tangkapan layar |
| `browser_use`  | Kendalikan Chromium, Firefox, atau WebKit headless (`engine`): navigasi, klik, isi, ekstrak (a11y/DOM/konsol), papan klip, tangkapan layar |
| `mobile_use`   | Kendalikan Android melalui ADB: periksa/masukkan, tangkapan layar, pasang/mulai/hentikan/atur ulang/copot pemasangan aplikasi, deep link, dan perintah perangkat berbentuk argv |
| `ios_use`      | Kendalikan Simulator iOS melalui WebDriverAgent/CoreSimulator: periksa/masukkan, tangkapan layar, pasang/mulai/hentikan/copot pemasangan aplikasi, deep link, dan proses simulator berbentuk argv |
| `rig_list`     | Tampilkan daftar rig sebuah ruang kerja beserta permukaan, status, ukuran layar, dan pengendalinya |
| `rig_close`    | Hancurkan rig dan buang status mesin yang dimilikinya                                            |

## Tidak diekspos melalui MCP

Kalender dan rapat tidak memiliki alat MCP. Agen tidak dapat membaca kalender, rapat, transkrip, item tindakan, atau keputusan Anda. Ringkasan yang menghasilkan item tindakan dan keputusan berjalan sebagai [pipeline `meeting_summary`](/id-ID/panduan-pengguna/konsep/rapat/) bawaan, bukan sebagai alat yang dapat dipanggil agen.

## Gerbang alat berdasarkan mode

Gerbang ditegakkan dua kali dari satu tabel (`ModeToolPolicy`): sekali di dispatcher MCP untuk adapter Claude Code dan sekali di registri harness bawaan. Panggilan yang diblokir mengembalikan alasannya.

| Mode          | Permukaan alat                                                                                                                                                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`        | Setiap alat yang terdaftar; tanpa daftar izin                                                                                                                                                                                         |
| `plan`        | Daftar izin terkurasi. Tanpa penulisan worktree dan tanpa verba tiket `create` / `assign` / `delegate`, tetapi memori, artefak, todo, `submit_plan`, `exit_plan_mode`, dan verba penyelesaian tiket pada tiket yang dikirim diizinkan   |
| `review`      | Daftar izin terkurasi: partisipasi tinjauan, komunikasi, pengambil konteks hanya-baca, dan seluruh rangkaian verba tiket termasuk `create_ticket` dan `assign_ticket`                                                                  |
| `orchestrate` | Daftar izin terkurasi: alat riset dan baca plus `propose_orchestration`, `create_playbook`, dan `run_playbook`. Perekrutan, dekomposisi, dan penyelesaian tiket terjadi secara deterministik setelah persetujuan, tidak pernah di tengah run |

Diizinkan di setiap mode terlepas dari daftar izin:

| Himpunan             | Alat                                                                                                                                                                                                                                                              |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Memori dan artefak   | `search_memory`, `propose_fact`, `propose_policy`, `supersede_fact`, `supersede_policy`, `record_observation`, `update_my_notes`, `get_my_notes`, `list_memory_domains`, `list_policies`, `publish_artifact`, `revise_artifact`, `list_artifacts`, `get_artifact` |
| Graf kode            | `search_code`, `code_symbol`, `code_callers`, `code_callees`, `code_impact`                                                                                                                                                                                       |
| Mekanika run         | `search_tool_bm25`, `list_my_tools`, `todo_write`, `todo_read`                                                                                                                                                                                                    |

Berada di daftar izin tidak membuat sebuah alat dapat dipanggil, dan sebaliknya juga berlaku: kemampuan bertanya ke operator adalah alat **harness** (`ask_user`), sehingga sama sekali tidak pernah muncul di katalog MCP ini.

## Alat dengan gerbang persetujuan

Sebuah alat dapat mendeklarasikan `requiresApproval`. Dispatcher kemudian membangun `ApprovalPayload` dan menampilkannya melalui `ConfirmationPort` sebelum alat berjalan; `cc_server` menyambungkan port itu, sehingga gerbangnya aktif.

Alat terdaftar yang mendeklarasikannya: `create_ticket`, `update_ticket`, `assign_ticket`, `reassign_ticket`, `close_ticket`, `ticket_relation`, `create_goal`, `update_goal_progress`, `create_approval`, `decide_approval`, `comment_approval`, `create_work_product`, `save_work_product_revision`, `create_runtime_profile`, `install_skill`, `update_skill`.

Secara independen, pagar pengaman tindakan terpadu menerapkan gerbang pada setiap alat yang mendeklarasikan himpunan `ActionClass` yang tidak kosong. Keputusan `prompt` tanpa pemberi persetujuan yang terhubung akan ditolak. Lihat [Pagar pengaman](/id-ID/panduan-pengguna/konsep/pagar-pengaman/).

## Kemampuan tanpa alat di baliknya

Tidak setiap kemampuan dalam produk dapat dijangkau agen. Kemampuan ini tidak punya alat
sama sekali, sehingga nama yang mungkin pernah Anda lihat dirujuk di tempat lain akan mengembalikan "unknown tool":

| Kemampuan                                | Di mana ia berada sebagai gantinya                                                                                                     |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Merekrut, memberhentikan, atau menyunting agen | UI agen. Tidak ada alat `hire_agent` / `fire_agent` / `update_agent`                                                              |
| Membuat ruang kerja                      | `workspace.upsert` melalui RPC, yang menyemai dan menstempel kepemilikan                                                               |
| Proyek (buat / daftar / perbarui / arsipkan) | UI tiket. Proyek adalah permukaan operator — lihat [Proyek](/id-ID/panduan-pengguna/panduan-praktis/proyek/)                        |
| Mengajukan pertanyaan yang memblokir ke operator | Alat **harness** `ask_user`, bukan MCP. Alat ini merender formulir di dalam percakapan dan memblokir sampai ada jawaban         |
| Diagnosis per agen                       | Tidak ada. Tidak ada `doctor` — lihat [Diagnosis agen](/id-ID/panduan-pengguna/panduan-praktis/diagnosis-agen/)                        |
| Kalender dan rapat                       | RPC hanya untuk klien manusia (lihat di atas)                                                                                          |
