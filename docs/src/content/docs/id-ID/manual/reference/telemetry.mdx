Control Center dapat mengirim **event penggunaan berpseudonim** ke instans [Umami](https://umami.is). Analitik penggunaan **nonaktif sampai operator server mengaktifkannya**. Pengaturan ini milik server dan berlaku untuk setiap klien yang terhubung ke server tersebut: aplikasi desktop, aplikasi web, ponsel, dan server itu sendiri.

Analitik penggunaan terpisah dari **Bagikan laporan crash**, yaitu pengaturan per perangkat untuk diagnostik crash dan error.

## Siapa yang memutuskan

| Sakelar | Lokasi | Efek |
| --- | --- | --- |
| **Bagikan analitik penggunaan** | Onboarding (langkah sandbox) dan **Pengaturan → Privasi**. Hanya operator server yang dapat mengubahnya; anggota lain melihat nilai saat ini dalam mode baca saja | Berlaku untuk seluruh server. Disimpan sebagai `telemetry.usage_analytics` di pengaturan server. Nonaktif kecuali disetel ke `true` |
| Jenis build | Otomatis | Build debug dan profile tidak mengirim apa pun. Sebagai gantinya, setiap event ditulis ke log debug |
| `CC_ANALYTICS_DEBUG=1` | Lingkungan `cc_server` atau file `.env`-nya | Mengizinkan build debug dan profile dari server, serta dari setiap klien yang terhubung ke server itu, benar-benar mengirim event untuk keperluan pengujian. Sakelar di atas tetap harus aktif |
| `DO_NOT_TRACK=1` | Lingkungan `cc_server` | Menghentikan pelaporan milik server itu sendiri, apa pun posisi sakelarnya. Klien tetap mengikuti sakelar |
| Server demo | Otomatis | Server demo publik tidak mengirim apa pun atas namanya sendiri. Pengunjung tidak dapat mengubah sakelar |

Klien membaca pengaturan dari server (`telemetry.config`, lalu secara langsung melalui `telemetry.watch`). Sampai jawabannya tiba, event menunggu di buffer kecil dalam memori. Jika jawabannya tidak, buffer dibuang. Menonaktifkan sakelar akan membuang semua yang masih dalam antrean dan langsung menghentikan pengiriman di setiap klien.

## Apa yang tidak pernah dikirim

- Isi pesan, tiket, tinjauan, atau rapat, judul, prompt, perintah shell, dan kueri pencarian
- Nama, login, alamat email, avatar, dan nama tampilan
- Path file, nama repositori, nama branch, nama host, dan URL (repositori hanya dikirim sebagai `repo_id` berpseudonim; tautan rapat hanya sebagai nama penyedianya)
- Pengenal mentah dalam bentuk apa pun

Setiap event melewati kebijakan properti sebelum meninggalkan proses. Teks, path, URL, alamat email, ID yang tidak dibungkus, serta string di bawah kunci seperti `email`, `*_name`, `path`, `title`, `prompt`, `content`, atau `token` dibuang alih-alih dikirim. Sebuah string hanya dikirim jika berupa token pendek dari kosakata tertutup, seperti nilai enum, versi, locale, atau ID model.

## ID berpseudonim

ID tetap dikirim, tetapi hanya sebagai pseudonim. Setiap ID ruang kerja, space, percakapan, agen, run, pengguna, dan perangkat diganti dengan HMAC-SHA256 menggunakan salt rahasia milik instalasi itu sendiri (`telemetry.pseudonym_salt`), dipotong menjadi 20 karakter heksadesimal. Ruang kerja yang sama selalu melaporkan nilai yang sama, sehingga event dapat digabungkan dan dihitung, tetapi ID mentahnya tidak pernah meninggalkan instalasi. Salt dibuat saat server pertama kali dijalankan dan tidak pernah dikirim ke penyedia analitik. Menghapus direktori data server akan membuat salt dan ID instalasi baru, sehingga semua yang tercatat sebelumnya tidak lagi tertaut.

## Tampilan layar

Setiap navigasi mencatat tampilan halaman dengan URL berupa **templat rute**, seperti `/workspaces/:workspaceId/spaces/:spaceId`, bukan alamat konkretnya. Nama layar adalah segmen literal dari templat tersebut, jadi contoh tadi menjadi `workspaces_spaces`. Parameter rute yang berakhiran `Id` dilampirkan sebagai properti `*_id` berpseudonim, dan parameter numerik (seperti nomor PR) sebagai angka. Semua parameter lain dibuang.

## Pengiriman

Event dikirim satu per satu ke `<host>/api/send` dari antrean dalam memori yang menampung hingga 200 event. Error jaringan, timeout, `429`, atau `5xx` mempertahankan event dan mencoba lagi dengan backoff eksponensial, mulai dari 1 detik hingga 5 menit. Setiap `4xx` lainnya membuang event tersebut. Tidak ada yang ditulis ke disk, jadi event yang masih dalam antrean saat aplikasi ditutup akan hilang. Antrean dikosongkan saat aplikasi masuk ke latar belakang dan saat server dimatikan.

## Mengarahkan build ke instans lain

Tujuannya ditetapkan saat build:

```bash
--dart-define=CC_ANALYTICS_HOST=https://analytics.example.com/
--dart-define=CC_ANALYTICS_WEBSITE_ID=<website uuid>
```

Adaptor penyedia berada di `packages/cc_analytics`. Untuk mendukung layanan analitik lain, tambahkan adaptor di sana. Rencana pelacakan dan aturan privasinya tetap sama.
