Setiap flag proses diisi lewat flag CLI atau variabel lingkungan; flag menang,
lalu variabel lingkungan, lalu nilai bawaan. Kredensial penyedia adalah
pengecualiannya — lihat [Aplikasi penyedia dan Connect](#aplikasi-penyedia-dan-connect).

:::caution[Flag yang tidak dikenal diabaikan secara diam-diam]
Parser argumen dibuat sendiri dan melewati apa pun yang tidak dikenali, sehingga salah ketik (`--tls-key-file`, `--bindany`) tidak menghasilkan galat — server tetap mulai dengan nilai bawaan. Periksa baris log startup bila suatu flag tampak tidak berpengaruh. Sebuah [flag mode kode](#mode-kode) dengan nilai yang tidak diterimanya berbeda: server menolak untuk mulai.
:::

## Aplikasi penyedia dan Connect

Tidak ada build yang membawa kredensial penyedia. Jika Control Center Connect aktif, Connect menjalankan setiap
penyedia dan app milik sendiri tetap tersimpan tetapi tidak digunakan. Di bawah **Gunakan aplikasi saya sendiri**,
setiap penyedia berjalan di app milik server ketika app itu sudah dikonfigurasi lengkap, jika tidak tidak
tersedia. App ruang kerja berlaku di kedua kasus. App milik sendiri diatur di **Pengaturan → Server → Single sign-on →
Aplikasi penyedia**, atau disemai sekali dari berkas `.env` server. Tidak ada flag untuk itu: rahasia
di baris perintah dapat dibaca lewat `ps`.

| Variabel                       | Arti                                                                                          |
| ------------------------------ | --------------------------------------------------------------------------------------------- |
| `GITHUB_APP_ID`                | Id GitHub App milik server                                                                    |
| `GITHUB_APP_PRIVATE_KEY`       | Kunci privatnya, dalam satu baris dengan escape `\n`. **Hanya `.env`**                         |
| `GITHUB_CLIENT_ID`             | Id klien-nya, untuk memasukkan orang                                                          |
| `GITHUB_CLIENT_SECRET`         | Rahasia klien-nya. **Hanya `.env`**                                                           |
| `GOOGLE_OAUTH_CLIENT_ID`       | Klien Google Web application milik server                                                     |
| `GOOGLE_OAUTH_CLIENT_SECRET`   | Rahasianya. **Hanya `.env`**                                                                  |
| `LINEAR_CLIENT_ID`             | App Linear milik server (PKCE, tanpa rahasia)                                                 |
| `LINEAR_API_KEY`               | Kunci layanan Linear untuk otomatisasi. **Hanya `.env`**                                      |
| `KLIPY_APP_KEY`                | Kunci Klipy milik server untuk pencarian GIF. Hanya dipakai di bawah **Gunakan aplikasi saya sendiri** |
| `CC_CONNECT_URL`               | `hosted`, `off`, atau URL Connect. Mengunci pilihan Connect; Pengaturan tidak dapat mengubahnya |
| `CC_SERVER_CONNECT_HOST`       | `on` memasang Control Center Connect di `<server>/connect`, dikonfigurasi oleh variabel `CONNECT_*`. Lihat [Jalankan server Connect](/id-ID/panduan-pengguna/panduan-praktis/jalankan-server-connect/#pasang-connect-di-dalam-cc_server) |

Berkas `.env` dibaca dari direktori kerja server, di samping executable, atau dari checkout sumber di
atasnya; di Docker, pasang di `/app/bin/.env`. Server **menolak mulai** (kode keluar `78`) ketika
`GITHUB_APP_PRIVATE_KEY`, `GITHUB_CLIENT_SECRET`, `GOOGLE_OAUTH_CLIENT_SECRET`, `LINEAR_API_KEY`, atau
`SLACK_*SECRET*` mana pun diekspor di lingkungan prosesnya, tempat setiap proses anak dapat
membacanya. Penyemaian dari `.env` terjadi sekali per kolom, sehingga penyuntingan di Pengaturan
nanti tidak dibatalkan oleh mulai ulang. Nilai kosong dibaca sebagai belum disetel.

Tidak ada kredensial forge yang berasal dari environment: GitHub, GitLab, dan Bitbucket semuanya
bertindak dengan proses masuk atau token milik anggota sendiri, atau dengan token GitHub App untuk
satu repositori yang dibatasi oleh anggota yang bertanggung jawab.

### `--sandbox`

Server memeriksa host sekali saat boot dan membungkus eksekusi perintah agen dalam
sandbox native OS bila backend tersedia: `sandbox-exec` (Seatbelt) di macOS,
`bwrap` plus `socat` di Linux dan WSL2. Keputusan dibuat sekali dan berlaku hingga server
dimulai ulang. Ada tiga hasil, masing-masing ditampilkan pada baris exposure saat startup:

| `sandbox=`    | Kapan                                   | Run agen siapa yang dimulai                                                      |
| ------------- | --------------------------------------- | -------------------------------------------------------------------------------- |
| `native`      | Backend tersedia dan `--sandbox` adalah `on` | Milik semua orang, dibungkus                                               |
| `off`         | `--sandbox off`                         | Milik semua orang, tanpa kurungan di host ini                                    |
| `unavailable` | `--sandbox on` dan tidak ada backend (Windows, atau Linux tanpa `bwrap` dan `socat`) | Hanya run yang dipertanggungjawabkan kepada pemilik server, tanpa kurungan. Yang lain ditolak dengan "Server ini tidak memiliki sandbox, sehingga hanya pemiliknya yang dapat menjalankan agen di sini." |

Untuk otomatisasi, orang yang bertanggung jawab adalah orang yang diikat oleh otomatisasi itu. Tanpa pemilik server yang tercatat, tidak ada run yang dimulai pada host `unavailable`. Pada Linux dan WSL2 dengan bubblewrap terpasang, dispatch native saat ini gagal tertutup untuk setiap run; lihat [Backend sandbox](/id-ID/panduan-pengguna/referensi/backend-sandbox/#linux-bubblewrap).

`--sandbox off` adalah pilihan pemilik server untuk semua orang yang memakai server: ini menjalankan agen setiap anggota tanpa kurungan di mesin ini. Gunakan pada host yang profil sandbox-nya sendiri berperilaku salah, atau untuk membiarkan anggota menjalankan agen di host tanpa backend. Ini tidak memerlukan build ulang, dan server mencatat peringatan sepanjang umur proses sehingga keadaan itu tidak pernah senyap.

### `--tool-deferral`

Run harness bawaan mengirim himpunan langsung kecil berisi definisi alat plus indeks hanya-nama untuk sisanya, yang memuat skemanya saat pertama kali dipakai, atau dipanggil dari skrip `repl`. Ini menjaga himpunan yang selalu terlihat tetap dalam rentang tempat model memilih alat secara andal. Diukur pada registri yang dibangun tes, alat chat standar agen bawaan berjumlah 14 definisi: sekitar 16,5 KB dengan `repl` (sekitar 4 KB di antaranya milik `repl`, yang definisinya tidak boleh melebihi 4.096 byte), sekitar 13 KB di server yang tidak dapat menjalankan skrip. Alat yang ditangguhkan tetap dapat dipanggil dengan namanya sepanjang run, dan `search_tools` menemukannya berdasarkan maksud. Lihat [Konteks alat dan cache prompt](/id-ID/panduan-pengguna/konsep/konteks-alat/).

`--tool-deferral off` mengirim setiap alat yang diizinkan dengan definisi lengkapnya di awal, kecuali bahwa run dengan `repl` tetap memanggil dari skrip alat-alat yang boleh dipanggil skrip. Ini sakelar pemutus untuk model yang buruk dalam menangani permukaan dua tingkat — sebuah flag, bukan build ulang. Ini hanya memengaruhi harness bawaan; `tools/list` MCP yang dilihat klien eksternal adalah katalog lengkap, kecuali untuk run agen pada server yang dapat menjalankan skrip [mode kode](/id-ID/panduan-pengguna/konsep/mode-kode/).

### `--credential-gate`

Run yang kredensial penyedianya hilang atau habis akan **diparkir**, bukan digagalkan:
operator mendapat perintah untuk memperbaikinya, dan run dilanjutkan jika mereka
melakukannya. Tenggat bawaannya 900 detik (15 menit), dibatasi 0–3600.

Tenggat ini sengaja jauh lebih panjang daripada tenggat prompt persetujuan: persetujuan
adalah keputusan yang dibuat seseorang dalam hitungan detik, sedangkan memperbaiki
kredensial berarti membuka terminal, masuk, lalu kembali. Batas atas itulah yang mencegah
run tanpa pengawasan — langkah pipeline, pemicu cron, webhook — menunggu seseorang yang
sedang tidur. Saat tenggatnya habis, run gagal dengan pesan yang sama seperti jika
digagalkan sejak awal.

`--credential-gate=0` adalah sakelar pemutusnya: tidak ada yang pernah diparkir dan
kredensial buruk mengakhiri giliran persis seperti sebelum gerbang ini ada.

### Mode kode

[Mode kode](/id-ID/panduan-pengguna/konsep/mode-kode/) memungkinkan agen menjalankan skrip JavaScript yang memanggil alatnya. Tidak ada flag yang menyalakan atau mematikannya: setiap run mendapat alat `repl` ketika server dapat menjalankan skrip, dan server demo publik tidak menjalankan skrip sama sekali.

Skrip berjalan di `cc_codemode`, sebuah program yang dikemas bersama server di `bin/codemode/`. Server tidak akan mulai tanpanya: ia mencetak satu baris yang menyebutkan apa yang hilang dan keluar dengan kode `78`. Saat mulai, server menjalankan self-test kunci program dan mencetak satu baris (hanya dibisukan oleh `--log-level error`):

```text
cc_server: code_mode=available (cc_codemode 0.1.0 quickjs-ng 0.16.2 protocol 2; 16 scripts at once, at most 12 per workspace; up to 64 more runners kept for scripts waiting on a person; heap at most 1024 MiB per script)
cc_server: code_mode=unavailable (<reason>) — runs on this host get no repl tool; scripts never run without full lockdown
```

`unavailable` berarti program tidak dapat mengunci dirinya di host ini, misalnya di dalam kontainer yang profil keamanannya menolak salah satu langkahnya, atau karena ia bukan build rilis. Server tetap berjalan seperti biasa, tidak ada run yang mendapat `repl`, dan pengaturan mode kode ruang kerja menampilkan alasannya.

Server terus memeriksa selama berjalan. Ketika program gagal dimulai karena alasan yang bukan dari skrip, server menjalankan self-test lagi, paling banyak sekali per menit. Jika itu gagal, server mencetak baris `unavailable` beserta alasannya dan tidak menjalankan skrip apa pun: run yang mulai sementara itu tidak mendapat `repl`, dan run yang sudah memilikinya memanggil alatnya secara langsung ([Saat skrip tidak dapat dijalankan](/id-ID/panduan-pengguna/konsep/mode-kode/#saat-skrip-tidak-dapat-dijalankan)). Server terus memeriksa, paling banyak sekali per menit, dan ketika self-test lolos lagi ia mencetak baris `available` dan kembali menjalankan skrip. Hanya self-test yang gagal saat mulai yang memerlukan restart. Alasan yang ditampilkan pengaturan ruang kerja sudah menghapus path host; baris log memuatnya utuh.

Dua flag mode kode membatasi apa yang boleh dipakai skrip. `--code-mode-max-processes` membatasi skrip yang berjalan bersamaan di seluruh ruang kerja (secara default dua kali inti prosesor, paling banyak 16; diterima 1–64). Dengan batas 2 atau lebih, satu ruang kerja paling banyak memakai batas itu dikurangi seperempatnya, sehingga tidak ada satu ruang kerja pun yang dapat mengambil semua tempat, dan skrip yang menunggu diterima bergiliran di antara ruang kerja. Skrip yang menunggu persetujuan atau jawaban seseorang menyerahkan tempatnya kepada skrip lain dan tidak memulai panggilan alat sampai dijawab; hingga empat kali batas skrip menunggu semacam itu tetap disimpan, paling banyak tiga perempatnya dari satu ruang kerja, dan masing-masing tetap dapat menghitung dalam batas waktu prosesornya sendiri. `--code-mode-max-heap-mb` adalah memori terbesar yang boleh dipakai satu skrip.

Nilai yang tidak diterima flag ini (angka di luar rentang, atau bukan angka) menghentikan server saat mulai (kode keluar `78`) dengan pesan yang menyebutkan nilai yang diterima. Nilai itu tidak pernah dibaca sebagai default.

## Subperintah

| Perintah                                      | Yang dilakukannya                                                                                   |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `cc_server`                                   | Menjalankan server hingga `SIGINT`/`SIGTERM`                                                        |
| `cc_server pair`                              | Menyediakan perangkat dan mencetak id serta kunci pairing-nya. Aman terhadap direktori data yang sudah disajikan server — server yang berjalan akan mengenali perangkat itu tanpa perlu dimulai ulang |
| `cc_server connect <command>`                 | Menampilkan atau mengubah Control Center Connect mana yang dipakai server ini, tanpa menjalankannya |
| `cc_server update`                            | Memeriksa, mengunduh, dan memverifikasi rilis mandiri yang lebih baru                               |
| `cc_server --version`                         | Mencetak versi build dan SHA git — identitas yang sama yang diiklankan `/healthz` dan handshake RPC |

### `pair`

| Flag           | Bawaan                                                    | Arti                                                                                                                                                                 |
| -------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--device`     | `web-client`                                              | Id perangkat. Platform disimpulkan darinya, jadi `--device desktop` membuat baris desktop dan `--device ios`/`android` membuat baris ponsel; selain itu diperlakukan sebagai web |
| `--label`      | nama platform plus hostname mesin ini                     | Nama tampilan di daftar perangkat                                                                                                                                    |
| `--host`       | `localhost`, atau `<this-host>` bila diikat ke semua antarmuka | Host yang disematkan di URL yang dicetak. Setel ke IP LAN atau host tunnel yang benar-benar akan dihubungi klien                                                |
| `--client-url` | belum disetel                                             | Origin klien **web** yang dihosting. Menambahkan deep link yang dapat dipindai dan QR terminal                                                                        |

`pair` juga menerima flag inti `--data-dir`, `--port`, dan `--bind`: flag itu
memilih direktori data yang akan ditulis dan membentuk URL server yang dicetak (`ws`
di loopback, `wss` bila `--bind any`). Menjalankan ulang `pair` untuk `--device`
yang sama memutar kuncinya dan memutus sesi aktif perangkat itu. Kredensial yang
dibuat di sini **tidak memiliki masa kedaluwarsa**, berbeda dari 30 hari yang
ditetapkan pemasangan di dalam aplikasi.

:::caution[QR `--client-url` bukan QR ponsel]
`pair --client-url` mengisi formulir koneksi klien **web** (URL server, id perangkat,
dan kunci di fragmen URL). Ponsel dipasangkan dengan payload berbeda yang dibuat dari
panel pemasangan di dalam aplikasi — deskriptor koneksi lengkap server plus masa
kedaluwarsa. Keduanya tidak dapat saling ditukar — lihat [Pasangkan perangkat](/id-ID/panduan-pengguna/panduan-praktis/pasangkan-perangkat/).
:::

### `connect`

Membaca dan menulis pengaturan yang sama dengan kartu **Control Center Connect** di **Pengaturan → Server →
Single sign-on**, dari direktori data. Server yang sedang berjalan menerima perubahan dalam 10 menit atau
saat dimulai ulang.

| Perintah                                | Yang dilakukannya                                                                                                                       |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `cc_server connect status`              | Mencetak mode, URL, apakah `CC_CONNECT_URL` mengunci, id instalasi, kesehatan, dan sumber setiap jalur (`own`, `connect`, atau `off`)     |
| `cc_server connect enable`              | Memakai Control Center Connect yang dihosting Control Center                                                                             |
| `cc_server connect enable --url <url>`  | Memakai Connect kustom di URL itu (HTTPS, atau `http` di loopback)                                                                       |
| `cc_server connect disable`             | Berhenti memakai Connect. Hanya app milik server yang memasukkan orang                                                                   |

`status` tanpa perintah adalah bawaan. Setiap perintah menerima `--data-dir`. `CC_CONNECT_URL` menimpa apa pun
yang disimpan perintah-perintah ini. Perintah yang tidak dikenal keluar dengan kode `64`. Lihat
[Control Center Connect](/id-ID/panduan-pengguna/referensi/connect/) untuk mode, identitas instalasi, dan kode status.

### `update`

`--apply` menggantikan instalasi; ini ditolak selama server masih menjawab di port yang
dikonfigurasi kecuali Anda memberikan `--force`. `--allow-downgrade` mengizinkan rilis
yang lebih lama.

Perintah ini menolak secara langsung, dengan penjelasan alih-alih galat, untuk instalasi
yang bukan miliknya:

| Lingkungan                    | Terdeteksi oleh                              | Yang dikatakannya                                           |
| ----------------------------- | -------------------------------------------- | ----------------------------------------------------------- |
| Server tertanam di desktop    | `CC_EMBEDDED=1` atau `CC_BOOTSTRAP_DEVICE_ID` | Perbarui aplikasinya sebagai gantinya — penginstal menukar seluruh pohon |
| Checkout sumber `dart run`    | jalur skrip berakhiran `.dart`               | Perbarui dengan git                                         |
| Docker                        | penanda kontainer                            | Tarik image yang lebih baru                                 |

## Siklus hidup proses

`cc_server` berjalan hingga `SIGINT` / `SIGTERM`. Satu variabel lingkungan tambahan
mengaturnya, dan variabel itu disetel oleh desktop, bukan oleh Anda:

| Variabel                 | Efek                                                                                                                                        |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `CC_EXIT_WITH_PARENT=1`  | Server keluar saat proses induknya keluar, dideteksi dari induk yang menutup ujung tulis pipa stdin-nya. Desktop menyetelnya agar aplikasi yang mogok tidak pernah meninggalkan server yatim yang memegang direktori data |

Setel sendiri hanya jika Anda mengawasi `cc_server` sebagai proses anak dan
menginginkan jaminan yang sama.

`DO_NOT_TRACK=1` (nilai apa pun selain kosong, `0` atau `false`) menghentikan
[analitik penggunaan](/id-ID/panduan-pengguna/referensi/analitik-penggunaan/) milik server itu sendiri meskipun sakelar tingkat server
aktif. Klien tetap mengikuti sakelar tersebut.

## Tata letak direktori data

Direktori data bawaannya adalah `~/Library/Application Support/control-center` di macOS,
`%APPDATA%\control-center` di Windows, dan `$XDG_DATA_HOME/control-center` (atau
`~/.local/share/control-center`) di tempat lain. `.cc_server` yang relatif terhadap cwd
hanya digunakan bila tidak ada direktori home atau direktori data aplikasi yang dapat
ditentukan.

Server menjaga direktori data tetap pribadi untuk akunnya sendiri (`0700`). Server menolak untuk mulai (kode keluar `78`) jika tidak bisa melakukannya, ketika `global.db` rusak atau ditulis oleh versi yang lebih baru, atau ketika berkas identitasnya tidak bisa dibaca.

| Jalur                             | Isi                                                                             |
| --------------------------------- | ------------------------------------------------------------------------------- |
| `global.db`                       | Registri ruang kerja, pengguna, perangkat yang dipasangkan, umpan berita, dan antrean fleet |
| `<workspaceId>/workspace.db`      | Satu basis data per ruang kerja — agen, space, tiket, memori          |
| `<workspaceId>/code_index.db` | Graf kode ruang kerja itu. Dibangun ulang saat hilang, tidak pernah dicadangkan |
| `pre_upgrade/`, `<workspaceId>/pre_upgrade/` | Dua salinan terbaru basis data dari sebelum pembaruan mengubah formatnya |
| `<workspaceId>/chat_credentials/` | Token bot chat, sebagai JSON biasa, sehingga ikut bersama ruang kerja            |
| `secrets.json`                    | Kunci pairing, kunci instalasi Connect, aplikasi penyedia, proses masuk pengguna (tersegel bila dibuat lewat Connect), rahasia webhook, SSO (`0600`) |
| `backups/<timestamp>/`            | Satu snapshot instalasi — `manifest.json`, `global.db`, dan salinan setiap ruang kerja |
| `backups/exports/`                | Ekspor satu ruang kerja, `<workspaceId>-<timestamp>.db`                          |
| `backups/transfer/`               | Area penampungan untuk unduhan dan unggahan cadangan; dibersihkan oleh rute yang menulisnya |
| `models/`                         | Model embedding, diarisasi, dan ucapan di perangkat                              |
| `codemode/` | Salinan pengembangan runner mode kode, dipasang oleh `scripts/natives/build_codemode.sh`; bundel rilis membawanya di `bin/codemode/` |
| `meetings/<meetingId>/`           | Audio rapat yang disimpan                                                        |
| `rigs/images/`                    | Image disk rig yang diimpor (permukaan desktop QEMU)                             |
| `rigs/smolvm/<rigId>/`            | Status runtime microVM per rig (rahasia broker, `0600`)                          |
| `rigs/smolvm-packs/`              | Paket mesin yang telah diekstrak — cache yang mempercepat boot rig berulang      |
| `rigs/tls/`                       | Otoritas sertifikat domain dev untuk HTTPS rig (kunci `0600`)                     |
| `rigs/run/<rigId>/`               | Overlay QEMU, image seed, dan kunci per VM (`0600`)                              |
