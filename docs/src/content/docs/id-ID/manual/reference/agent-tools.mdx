Berikut adalah alat **terikat server** yang didaftarkan langsung oleh runtime agen bawaan — server bahasa, pencarian struktural, debugger, kernel, skrip mode kode, pertanyaan, dan kontrol pekerja — berbeda dengan [alat MCP](/id-ID/panduan-pengguna/referensi/alat-mcp/) yang dijembatani ke dalamnya serta alat berkas, pencarian, dan shell generik dari runtime harness. Alat-alat ini tidak ada di registri MCP: klien MCP eksternal tidak akan melihatnya, karena masing-masing terikat pada sumber daya sisi server yang hidup — proses server bahasa, adapter debug, interpreter — yang menjadi milik satu run.

Setiap alat di sini hanya didaftarkan ketika sumber daya pendukungnya tersambung untuk run tersebut — supervisor server bahasa atau debug, parser tree-sitter, pabrik kernel, port pertanyaan, roster vibe. Deteksi server bahasa atau adapter debug untuk *checkout ini* adalah pemeriksaan terpisah yang berlangsung belakangan (`status` / `adapters`): alat-alat itu tetap ada di permukaan agar agen dapat menanyakan mengapa tidak ada yang bisa dipakai, alih-alih menebak.

## Tingkat persetujuan

Setiap alat mendeklarasikan sebuah tingkat, dan tingkat itulah yang menentukan **permukaan mana yang melihatnya** — bukan sekadar apakah alat itu memunculkan prompt. Mode rencana dan subagen hanya-baca dibatasi pada `read`, sehingga alat bertingkat `write` atau `exec` sama sekali tidak ada dalam skema mereka.

| Tingkat | Arti                         | Alat di sini                                     |
| ------- | ---------------------------- | ------------------------------------------------ |
| `read`  | Tanpa efek samping           | `lsp`, `ast_grep`, `ask_user`, `repl`, kelima `vibe_*` |
| `write` | Mengubah berkas              | `lsp_rename`, `ast_edit`, `resolve`              |
| `exec`  | Memulai atau mengendalikan proses | `debug`, `eval`                             |

## Langsung, hanya dari skrip, atau dimuat saat pertama kali dipakai

Ketika server dapat menjalankan skrip, sebuah run memanggil beberapa alat secara langsung dan menjangkau sisanya dari sebuah skrip [`repl`](#repl--jalankan-skrip-yang-memanggil-alat-anda); lihat [Mode kode](/id-ID/panduan-pengguna/konsep/mode-kode/#alat-mana-yang-dipanggil-agen-secara-langsung) untuk aturan lengkapnya. Untuk alat-alat di halaman ini:

| Alat | Dengan `repl` | Tanpa `repl` |
| ---- | ----------- | -------------- |
| `repl` | Langsung | Tidak ada |
| `ask_user` | Langsung | Langsung |
| `lsp`, `lsp_rename`, `ast_grep`, `ast_edit`, `resolve`, `debug` | Hanya dari skrip | Dimuat saat pertama kali dipakai |
| `eval` | Dimuat saat pertama kali dipakai (skrip tidak dapat memanggilnya) | Dimuat saat pertama kali dipakai |
| `vibe_*` | Langsung dalam mode vibe, tidak pernah dari skrip | Langsung dalam mode vibe |

Alat yang bertanda "Hanya dari skrip" dimuat saat pertama kali dipakai sebagai gantinya, begitu server tidak dapat menjalankan skrip run tersebut ([Saat skrip tidak dapat dijalankan](/id-ID/panduan-pengguna/konsep/mode-kode/#saat-skrip-tidak-dapat-dijalankan)).

## `lsp` — kueri server bahasa

Didaftarkan ketika run memiliki supervisor server bahasa dan direktori kerja. Apakah sebuah server benar-benar dapat menjawab dideteksi pada saat pemanggilan, sebagai sebuah **irisan**: penanda root harus ada *dan* biner server harus dapat di-resolve. Salah satu saja berarti tidak ada server yang dimulai — `status` yang mengatakannya — alih-alih tebakan diam-diam.

Server hanya berasal dari tabel bawaan; `lsp.json` milik repositori tidak dibaca. Dalam run yang di-sandbox, setiap run memiliki sesi server bahasanya sendiri, sehingga server dimulai lagi pada setiap run. Biner lokal proyek (`node_modules/.bin`) hanya dipakai saat run di-sandbox, dan root proyek tidak pernah di-resolve di atas direktori kerja run.

Posisi dialamatkan dengan `line` ditambah substring `symbol`, tidak pernah dengan kolom. Model yang diminta memakai kolom akan menebak, dan tebakan yang salah me-resolve ke simbol lain pada baris yang sama — jawaban yang tampak benar padahal membahas hal lain. Menghilangkan `symbol` pada aksi navigasi adalah galat, bukan tebakan kolom pertama.

| Aksi              | Argumen                         | Mengembalikan                             |
| ----------------- | ------------------------------- | ----------------------------------------- |
| `diagnostics`     | `file` (atau `"*"`)             | Galat dan peringatan; `"*"` menjalankan pemeriksa proyek sebagai gantinya |
| `definition`      | `file`, `line`, `symbol`        | Di mana simbol itu dideklarasikan         |
| `type_definition` | `file`, `line`, `symbol`        | Di mana tipenya dideklarasikan            |
| `implementation`  | `file`, `line`, `symbol`        | Implementasi konkret                      |
| `references`      | `file`, `line`, `symbol`        | Setiap pemakaian, dibatasi 50             |
| `hover`           | `file`, `line`, `symbol`        | Signature dan komentar dokumentasi        |
| `symbols`         | `query` atau `file`             | Pencarian ruang kerja dengan `query` (dibatasi 100); simbol dokumen dengan `file` (dibatasi 200) |
| `code_actions`    | `file`, `line`, `symbol`        | Perbaikan cepat yang ditawarkan server    |
| `status`          | —                               | Server mana yang berjalan, dan untuk root mana |
| `reload`          | —                               | Memulai ulang server untuk root ini       |

### Diagnostik saat menulis

Manfaat utamanya bukan alat ini. `write`, `edit`, dan `apply_patch` **dibungkus**: setelah penulisan, berkas disinkronkan dan disimpan melalui server bahasa, dan hanya diagnostik yang **baru muncul** yang dilipat ke dalam hasil alat. Agen mengetahui bahwa ia merusak build pada saat ia merusaknya, tanpa harus ingat untuk bertanya.

Diagnostik yang sudah dilaporkan ditekan oleh catatan per run dengan kunci berupa tingkat keparahan, kode, dan pesan — posisi sengaja dikecualikan, sehingga diagnostik yang hanya bergeser empat baris ke bawah tidak dilaporkan ulang sebagai baru.

## `lsp_rename` — penggantian nama seluruh proyek

Alat terpisah bertingkat `write` karena tepat satu alasan: tingkat itulah yang menentukan visibilitas. Melipat penggantian nama ke dalam `lsp` akan menyerahkan kemampuan menulis ulang repo kepada penjelajah hanya-baca, atau menempatkan setiap `hover` di balik prompt persetujuan.

| Argumen    | Arti                                       |
| ---------- | ------------------------------------------ |
| `file`     | Di mana simbol itu berada                  |
| `line`     | Baris dengan indeks mulai 1                |
| `symbol`   | Substring yang mengidentifikasinya pada baris itu |
| `new_name` | Nama barunya                               |

## `ast_grep` — pencarian struktural

Menemukan kode berdasarkan **bentuk**, bukan teks. `$NAME` mencocokkan node mana pun, `$$$NAME` mencocokkan rangkaian saudara, dan `$_` adalah wildcard yang tidak mengikat apa pun.

Sifat yang menjadikannya pencocok, bukan regex dengan langkah tambahan: metavariabel yang diulang dalam satu pola harus menangkap teks yang sama.

```
ast_grep(pattern: "if ($X != null) $X.dispose()", language: "dart")
```

mencocokkan penjaga yang membuang apa yang diujinya, dan **tidak** mencocokkan penjaga yang membuang hal lain.

| Argumen       | Arti                                                        |
| ------------- | ----------------------------------------------------------- |
| `pattern`     | Fragmen kode dengan metavariabel                            |
| `path`        | Berkas atau direktori yang dicari; default-nya seluruh ruang kerja |
| `language`    | Id grammar yang disertakan (`dart`, `python`, `rust`, `c`, …). Disimpulkan saat `path` menunjuk sebuah berkas |
| `max_results` | Default 50                                                  |

:::note[Pola ini diuraikan oleh grammar yang sama dengan berkasnya]
Sehingga `dispose(x)` mencocokkan pemanggilan itu bagaimanapun spasi, pembungkusan, atau komentarnya — dan tidak pernah mencocokkan karakter yang sama di dalam literal string atau komentar.
:::

:::caution[Fragmen diuraikan di dalam kerangka, bukan secara telanjang]
`dispose(x)` yang diuraikan pada tingkat atas Dart adalah *signature fungsi* yang valid. Compiler pola mencoba tangga konteks (pernyataan, ekspresi, anggota kelas, deklarasi) dan memakai konteks pertama yang menerima fragmen itu. Pola yang tidak diterima konteks mana pun dilaporkan sebagai tidak dapat diuraikan, alih-alih dicari lalu diam-diam tidak ditemukan.
:::

## `ast_edit` — penulisan ulang struktural, di-staging

Pencocokan yang sama, ditambah templat `rewrite` dengan metavariabelnya disubstitusikan kembali. **Tidak ada yang ditulis.** Perubahan itu di-staging dan hasilnya menyebut sebuah `edit_id`.

```
ast_edit(pattern: "dispose($X)", rewrite: "$X.dispose()", language: "dart")
→ (proposed) 12 replacements in 4 files … call resolve with edit_id "edit_1"
```

| Argumen    | Arti                                                |
| ---------- | --------------------------------------------------- |
| `pattern`  | Apa yang dicocokkan                                 |
| `rewrite`  | Apa yang diletakkan di sana, dengan `$NAME` disubstitusikan |
| `path`     | Cakupan; default-nya seluruh ruang kerja            |
| `language` | Id bahasa                                           |

## `resolve` — commit atau buang perubahan yang di-staging

| Argumen   | Arti                             |
| --------- | -------------------------------- |
| `edit_id` | Dari hasil `(proposed)`          |
| `action`  | `accept` atau `discard`          |

Setiap berkas dibandingkan dengan konten yang ditangkap pada saat staging, dan ketidakcocokan **apa pun** menolak seluruh perubahan. Penulisan ulang struktural yang diterapkan sebagian meninggalkan pohon yang tidak dapat dikompilasi, baik dalam bentuk lama maupun bentuk baru.

## `debug` — mengemudikan debugger

Didaftarkan ketika run memiliki supervisor sesi debug, direktori kerja, dan id percakapan. Apakah sebuah adapter benar-benar dapat dimulai dideteksi pada saat pemanggilan, dengan aturan irisan yang sama seperti server bahasa (penanda root *dan* biner). Bertingkat `exec`; tidak aman untuk paralel (sebuah sesi adalah status yang bertahan antar panggilan, sehingga `continue` yang menyalip `stack` akan membaca frame yang sudah bergeser).

Satu sesi per percakapan, dengan TTL yang tegas (30 menit). `launch` kedua ditolak alih-alih diam-diam menggantikan yang pertama. Dalam run yang di-sandbox, sesi mempertahankan sandbox-nya antar giliran hingga berakhir, jadi paling lama selama 30 menit tersebut.

| Operasi       | Argumen                       | Catatan                                        |
| ------------- | ----------------------------- | ---------------------------------------------- |
| `adapters`    | —                             | Adapter mana yang dapat dipakai di sini, dan mengapa tidak |
| `status`      | —                             | Apakah ada sesi yang berjalan, dan di mana ia berhenti |
| `breakpoints` | `file`, `lines[]`             | `lines` kosong menghapus breakpoint di berkas itu. Dapat ditetapkan **sebelum** peluncuran |
| `launch`      | `program`, `args[]`           | Menjalankan program dalam keadaan berhenti di breakpoint Anda |
| `attach`      | `port`                        | Menyambung ke debuggee yang sudah berjalan pada salah satu port teruskan milik run; port lain ditolak sebelum apa pun dimulai |
| `continue`    | `thread_id?`                  | Menjalankan sampai titik henti berikutnya      |
| `pause`       | `thread_id?`                  | Menghentikannya di tempatnya sekarang          |
| `step_over` / `step_in` / `step_out` | `thread_id?` | Bergerak satu langkah                  |
| `threads`     | —                             | Id dan nama thread                             |
| `stack`       | `thread_id?`                  | Frame, dibatasi 30                             |
| `scopes`      | `frame_id`                    | Scope pada sebuah frame, masing-masing dengan `reference` |
| `variables`   | `reference`                   | Anak, dibatasi 50, nilai dibatasi 400 karakter |
| `evaluate`    | `expression`, `frame_id?`     | Dievaluasi dalam scope milik frame itu sendiri |
| `output`      | —                             | stdout/stderr debuggee, dibatasi               |
| `terminate`   | —                             | Mengakhiri sesi dan mematikan adapter          |

### Adapter

| Id        | Perintah                   | Penanda root                                    |
| --------- | -------------------------- | ----------------------------------------------- |
| `dart`    | `dart debug_adapter`       | `pubspec.yaml`                                  |
| `debugpy` | `python3 -m debugpy.adapter` | `pyproject.toml`, `setup.py`, `requirements.txt` |
| `lldb`    | `lldb-dap`                 | `Cargo.toml`, `CMakeLists.txt`                  |
| `delve`   | `dlv dap`                  | `go.mod`                                        |

`debugpy` lebih memilih `.venv/bin` atau `venv/bin` milik proyek daripada `$PATH` saat run di-sandbox: python dari `$PATH` adalah lingkungan yang berbeda, dan menyambung dari lingkungan yang salah gagal dengan cara yang terbaca sebagai kode rusak. Tanpa sandbox ia hanya memakai `$PATH`, sehingga sebuah repositori tidak dapat memilih interpreter yang berjalan di host.

## `repl` — jalankan skrip yang memanggil alat Anda

Tersedia di setiap run ketika server dapat menjalankan skrip ([Saat run memiliki `repl`](/id-ID/panduan-pengguna/konsep/mode-kode/#saat-run-memiliki-repl)). Skrip adalah JavaScript biasa, isi fungsi async, dan berjalan di interpreter baru yang terkunci di prosesnya sendiri: tanpa akses ke sistem berkas, jaringan, proses, atau modul. `repl` sendiri termasuk tingkat `read` dan menjaga dirinya sendiri, karena setiap panggilan alat yang dibuat skrip diperiksa sendiri-sendiri. Juga tersedia di endpoint MCP, untuk run agen pada server yang dapat menjalankan skrip.

| Argumen | Arti |
| ------------------- | --------------------------------------------------------------------------------------------- |
| `code` | Skripnya. Paling banyak 256 KiB |
| `description` | Wajib. Label pendek untuk baris transkrip |
| `timeout_ms` | Opsional. Batas waktu yang lebih pendek dari batas ruang kerja; tidak pernah lebih panjang |
| `max_output_tokens` | Opsional. Anggaran keluaran yang lebih kecil dari ruang kerja; tidak pernah lebih besar |

```js
// Read three files together and report only which ones failed.
const paths = ["lib/a.dart", "lib/b.dart", "lib/c.dart"];
const results = await Promise.allSettled(paths.map((path) => tools.read({ path })));
return results
  .map((r, i) => (r.status === "rejected" ? `${paths[i]}: ${r.reason.message}` : null))
  .filter(Boolean);
```

Deskripsi `repl` memberi tahu agen: "Alat yang bukan salah satu alat langsung Anda tidak memiliki definisi dalam permintaan ini. Sebelum panggilan pertama ke alat seperti itu, cari dengan `describeTool(name)` atau `searchTools(query)`, kecuali bentuk panggilan persisnya sudah ditunjukkan kepada Anda dalam percakapan ini."

`describeTool(name)` mengembalikan deskripsi alat, deklarasinya, skema masukan dan keluarannya, serta catatan hasilnya bila ada: apa yang diterima skrip dari panggilan yang selesai, dengan kata-kata alat itu sendiri. Deskripsi `repl` mencantumkan catatan dari alat langsung yang boleh dipanggil skrip. Hasil yang berupa teks JSON tiba sudah terurai, kecuali jika memuat lebih dari 131.072 nilai: maka ia tiba sebagai teks, dan skrip menguraikannya dengan `JSON.parse`. Teks hasil dari alat server MCP eksternal dipotong pada 262.144 karakter, dan teks yang dipotong tidak lagi dapat diurai.

- `tools.<name>(args)` memanggil alat melalui filter, pagar pengaman, dan persetujuan yang sama dengan panggilan langsung, dan menolak dengan galat ketika panggilan ditolak atau gagal. Panggilan baca-saja dapat dijalankan bersamaan; panggilan yang mengubah sesuatu dijalankan satu per satu, sesuai urutan yang dibuat skrip. Selagi salah satu panggilannya menunggu seseorang, tidak ada panggilan lain dari skrip yang dimulai.
- `ALL_TOOLS`, `searchTools(query, { limit, namespace })`, `describeTool(name)` dan `describeNamespace(name)` menemukan alat, termasuk alat dari server MCP yang terhubung. Alat di luar himpunan langsung yang boleh dipanggil skrip hanya dapat dipanggil dari skrip; memanggilnya secara langsung mengembalikan cara memanggilnya dari `repl`. Setelah server tidak dapat menjalankan skrip run tersebut, alat seperti itu dimuat saat pertama kali dipakai sebagai gantinya.
- Pencarian dibatasi: query paling banyak 1.024 karakter, nama atau namespace paling banyak 256, `limit` dari 0 sampai 50, dan paling banyak 200 pencarian yang memakan total 2 detik waktu server per skrip, sementara semua skrip dalam satu ruang kerja berbagi 2 detik waktu pencarian, yang dikembalikan sebesar seperempat detik setiap detik; setelah salah satunya habis, pencarian berikutnya ditolak. Dalam katalog yang sangat besar, deskripsi di `ALL_TOOLS` berbagi sekitar satu juta karakter secara merata dan deskripsi yang terpotong berakhir dengan `…`; `describeTool` selalu mengembalikan deskripsi lengkap. Tipe yang terlalu besar untuk ditampilkan dibaca `unknown /* too large to show */`, dan nama yang tidak dikenal dijawab dengan nama-nama yang paling mirip.
- Alat dikelompokkan dalam namespace: `builtin` (alat milik harness), `control-center` (alat Control Center) dan satu namespace untuk setiap server MCP yang terhubung, dinamai sesuai server itu. Server yang bernama `builtin`, `control-center` atau `script`, atau yang namanya diawali `external-`, dalam kombinasi huruf kapital apa pun dan dengan atau tanpa spasi di sekelilingnya, dicantumkan sebagai `external-` diikuti namanya, dan tidak ada alat yang pernah berada di `script`.
- Hanya yang dikembalikan skrip, atau diteruskan ke `text()`, `image()` atau `console.*`, yang kembali ke agen. Keluaran melebihi anggaran menyisakan awal dan akhirnya, dan `read_output` membaca sisanya.
- `store(key, value)` / `load(key)` menyimpan nilai JSON untuk skrip berikutnya dalam percakapan dan agen yang sama, disimpan hanya ketika skrip selesai. Skrip subagen tidak memiliki penyimpanan.
- `await tools.ask_user(...)` mengajukan pertanyaan; jawabannya juga ditambahkan ke hasil. `sleep(ms)`, `setTimeout`, `limits()` dan `models.embed` / `rank` / `classify` (embedding di perangkat) juga tersedia.
- `describeTool(name)` dan `searchTools(query)` juga menjawab untuk fungsi milik skrip, yang bukan alat: `text`, `image`, `store`, `load`, `sleep`, `setTimeout`, `clearTimeout`, `limits`, `exit` dan `models.*`, di bawah namespace `script`.
- Tidak dapat dipanggil dari skrip: `repl`, `eval`, `task`, `checkpoint`, `rewind`, `compact`, `search_tools` dan verba `vibe_*`.
- Sebuah skrip membaca masa lalu run-nya sendiri: `history({start, role, tool, limit})` memberi halaman pada transkrip percakapan (paling banyak 50 baris per pemanggilan; teruskan `next_start` halaman sebelumnya sebagai `start`), `outputs()` mencantumkan keluaran alat yang disimpan untuk percakapan dan agen ini, dan `loadOutput(handle)` membaca 16.384 karakter dari satu keluaran. `storedKeys()` mencantumkan kunci yang disimpan beserta ukurannya. `keep(value, label)` menyimpan nilai besar sebagai keluaran yang dapat dibaca skrip nanti atau `read_output`, disimpan hanya ketika skrip selesai (1 MiB per nilai, 64 nilai dan 16 MiB per run). `limits().returnBudgetChars` menunjukkan berapa banyak anggaran keluaran yang tersisa. Run hanya-baca (tinjauan tujuan) dapat membaca tetapi tidak dapat menyimpan atau memakai keep. Di Claude Code dan ACP, `history()` berfungsi sementara `outputs()`, `loadOutput()` dan `keep()` menolak, karena Control Center tidak menyimpan keluaran alat dari run tersebut.
- Galat dari timeout, luapan keluaran, atau batas pemanggilan menjelaskan cara memperbaikinya.

Satu run hanya menjalankan satu skrip pada satu waktu. Batas dan apa yang terjadi di masing-masing ada di halaman [Mode kode](/id-ID/panduan-pengguna/konsep/mode-kode/#batas); setiap skrip direkam di bawah **Observabilitas → Eksekusi kode**.

## `eval` — interpreter persisten

Sel Python atau JavaScript yang variabel, impor, dan data termuatnya bertahan di antara panggilan. Bertingkat `exec`; tidak aman untuk paralel.. Tidak dapat dipanggil dari skrip `repl`, dan sel tidak dapat memanggil alat run: untuk memanggil alat dari kode, gunakan [`repl`](#repl--jalankan-skrip-yang-memanggil-alat-anda).

| Argumen       | Arti                                             |
| ------------- | ------------------------------------------------ |
| `code`        | Sel                                              |
| `description` | Wajib. 5–10 kata untuk label transkrip           |
| `language`    | `python` (default) atau `javascript`             |
| `reset`       | Buang interpreter dan mulai dari keadaan bersih lebih dahulu |

- Ekspresi terakhir ditampilkan kembali seperti yang dilakukan notebook.
- `display()` berfungsi, frame pandas dirender sebagai tabel, dan gambar matplotlib kembali sebagai **gambar yang ditampilkan transkrip**.
- Idiom IPython yang refleksif diketik orang — `%pip`, `%cd`, `!cmd`, `%%bash`, `%%timeit` — ditulis ulang menjadi kode biasa. `%pip` juga menggusur `sys.modules`, sehingga `import` berikutnya melihat apa yang baru saja dipasang.
- Sel yang mencetak lebih dari anggaran keluarannya mempertahankan tiga perempat pertama dan seperempat terakhir, dengan satu baris yang menyebutkan berapa karakter dan gambar yang dibuang.
- Ketika interpreter mati tanpa diminta, sel berikutnya diberi tahu sekali bahwa variabel sebelumnya sudah hilang.

:::note[Di mana kernel berjalan]
Di dalam enclosure percakapan bila percakapan itu memilikinya; bila tidak, di dalam sandbox OS run di host. Dengan sandbox dimatikan atau tidak tersedia, ia berjalan tanpa kurungan dan `eval` meminta persetujuan eksekusi host. Ia tidak menyalakan enclosure untuk sampai ke sana — aturan yang sama yang mencegah tab rig memulai otomatis.
:::

## `bash` di latar belakang

`bash` dengan `run_in_background: true` memulai perintah dan langsung kembali dengan handle (`b1`, `b2`, …) alih-alih menunggu. Agen terus bekerja, atau mengakhiri gilirannya dan dibangunkan saat perintah berakhir.

| Argumen | Arti |
| ------------------- | ------- |
| `run_in_background` | `true` untuk memulai dan langsung kembali |
| `timeout_seconds` | Detik sebelum perintah dihentikan: 600 secara default, paling banyak 3.600 |
| `notify` | Opsional. Pola sederhana; setiap baris keluaran yang cocok dikirim ke agen selagi perintah berjalan (misalnya `listening on\|FAILED`) |

- Paling banyak 4 perintah latar belakang berjalan sekaligus dalam satu run. Masing-masing dihentikan pada timeout-nya dan saat run berakhir, bersama setiap proses yang dimulainya.
- Ketika sebuah perintah berakhir, agen menerima pemberitahuan dengan kode keluar, 2.000 karakter terakhir keluaran, dan handle `read_output` untuk sisanya.
- Agen yang satu-satunya pekerjaan tersisanya adalah perintah latar belakang menunggu tanpa memanggil model, dan pengawas diam run dijeda selama menunggu.
- `bash_output(handle)` membaca status dan keluaran terbaru sebuah perintah; `bash_kill(handle)` menghentikannya. Keduanya menyebutkan kapan hasilnya sudah dikirim.
- Skrip tidak dapat memulai perintah latar belakang. Claude Code memiliki Bash latar belakangnya sendiri; Control Center membiarkan run itu terbuka paling lama 10 menit setelah giliran yang meninggalkan tugas berjalan.

## `compact` — mengosongkan ruang di jendela konteks

Memadatkan konteks lama percakapan sebelum pemanggilan model berikutnya, dengan mempertahankan apa yang disebut `focus` (paling banyak 1.000 karakter). Giliran terbaru tetap utuh. Baris anggaran per giliran agen menunjukkan pemakaian konteks pada 70, 80 dan 90%, dan alat ini layak dipanggil setelah sekitar 70% sebelum fase kerja baru yang panjang. Hook `preCompact` milik pemilik server dapat menambahkan ke fokus ([Hook shell](/id-ID/panduan-pengguna/referensi/konfigurasi-agen/#hook-shell)). Setelah kompaksi, server menambahkan blok "Still in flight": tujuan, pengingat yang menunggu, pertanyaan yang terbuka, perintah latar belakang, daftar periksa dan kunci yang disimpan, masing-masing dengan pemanggilan yang memulihkannya.

## `ask_user` — mengajukan pertanyaan kepada manusia

Bertingkat `read`. **Satu-satunya** cara sebuah run menanyakan apa pun kepada operator. Alat ini merender kartu bernomor di percakapan dan memblokir sampai seseorang menjawab, melewatinya, atau pertanyaannya kehabisan waktu. Jangan pernah menuliskan pertanyaannya sebagai pesan chat — itu mengakhiri giliran.

| Argumen           | Arti                                       |
| ----------------- | ------------------------------------------ |
| `question`        | Apa yang ditanyakan                        |
| `context`         | Opsional: mengapa Anda bertanya dan apa yang bergantung pada jawabannya |
| `options[]`       | Pilihan, masing-masing `{label, description?}` |
| `allow_free_text` | Apakah jawaban yang diketik diterima       |
| `multi_select`    | Apakah beberapa pilihan boleh dipilih      |

Melewati pertanyaan adalah keberhasilan: lanjutkan dengan asumsi yang dinyatakan dan jangan bertanya lagi. Kehabisan waktu adalah galat dengan instruksi yang sama. Prompt izin ("bolehkah saya melakukan ini?") adalah gerbang terpisah dan dirender sebagai kartu yang sama di percakapan.

Didaftarkan hanya ketika port pertanyaan dan space tujuan keduanya ada. Tanpa manusia yang terpasang, panggilan itu **gagal** alih-alih memblokir selamanya — postur fail-closed yang sama seperti yang diambil `prompt` pagar pengaman saat tidak ada penyetuju yang terhubung.

## `vibe_*` — mengarahkan pekerja latar belakang

Didaftarkan hanya selama [mode vibe](/id-ID/panduan-pengguna/panduan-praktis/arahkan-pekerja-latar-belakang/) aktif. Kelimanya bertingkat `read`: gerbangnya seharusnya ada pada alat milik pekerja, tempat penyuntingan benar-benar terjadi.

| Alat         | Argumen                                  | Catatan                                     |
| ------------ | ---------------------------------------- | ------------------------------------------- |
| `vibe_spawn` | `brief`, `label`, `tier?`                | Langsung kembali; pekerja terus berjalan    |
| `vibe_send`  | `worker_id`, `message`                   | Menambahkan ke instruksi dan menjalankan ulang |
| `vibe_wait`  | `worker_id`, `timeout_seconds?`          | Memblokir sampai pekerja itu selesai        |
| `vibe_kill`  | `worker_id`                              | Menghentikannya                             |
| `vibe_list`  | —                                        | Tingkat, status, waktu berlalu, dan hasil terakhir |

`tier` adalah `fast` (pekerjaan mekanis dengan spesifikasi yang jelas) atau `good` (desain, pertimbangan, atau peninjauan atas keluaran pekerja `fast`).
