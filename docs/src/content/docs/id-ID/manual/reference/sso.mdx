Semua hal yang dapat dikonfigurasi pada masuk tunggal, di satu tempat. Nilainya
berada di baris `sso_connections` pada `global.db` (memang dirancang untuk
seluruh server), diedit melalui **Pengaturan → Server → Single sign-on** atau
operasi RPC `sso.*`. Baris yang tersimpan adalah satu-satunya sumber kebenaran —
tidak ada jalur environment `CC_SAML_*` / `CC_OIDC_*` (koneksi yang dapat
berasal dari dua tempat adalah koneksi yang bisa saja bertentangan dengan layar
pengaturan).

## Bidang koneksi

| Bidang                 | Berlaku untuk | Bawaan          | Arti                                                                                                                                                 |
| ---------------------- | ------------- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `enabled`              | keduanya     | nonaktif        | login dapat memakai koneksi ini                                                                                                                      |
| `idpMetadataXml`       | SAML          | —               | XML `EntityDescriptor` milik IdP (wajib untuk mengaktifkan)                                                                                          |
| `spEntityId`           | SAML          | `<origin>/saml` | entity ID kami, dipatok saat origin-nya bervariasi                                                                                                   |
| `emailAttribute`       | SAML          | `email`         | atribut pembawa email; NameID berbentuk email adalah cadangannya                                                                                     |
| `displayNameAttribute` | SAML          | `displayName`   | atribut nama tampilan                                                                                                                                 |
| `groupsAttribute`      | SAML          | `groups`        | atribut nama grup                                                                                                                                     |
| `clockSkewSeconds`     | SAML          | 90              | toleransi pergeseran untuk validasi masa berlaku                                                                                                      |
| `allowIdpInitiated`    | SAML          | nonaktif        | terima Response yang tidak diminta yang valid (tanpa `InResponseTo`); browser harus mengklaim hibah berumur pendek sebelum menerima kredensial yang tersegel untuk penerimanya |
| `wantResponseSigned`   | SAML          | nonaktif        | wajibkan tanda tangan di akar Response (tanda tangan asertion selalu diwajibkan)                                                                      |
| `issuer`               | OIDC          | —               | URL dasar issuer (wajib untuk mengaktifkan)                                                                                                          |
| `clientId`             | OIDC          | —               | id klien publik (wajib untuk mengaktifkan)                                                                                                           |
| `clientSecret`         | OIDC          | —               | hanya untuk klien rahasia; disimpan di berkas rahasia bermode 0600, tidak pernah di basis data — hanya-tulis melalui RPC (`sso.getConfig` melaporkan `clientSecretPresent`) |
| `groupsClaim`          | OIDC          | `groups`        | claim pembawa nama grup                                                                                                                               |
| `defaultRole`          | keduanya     | `member`        | peran saat tidak ada grup yang dipetakan — tidak pernah `owner`                                                                                      |
| `groupRoleMap`         | keduanya     | `{}`            | grup → peran; pemetaan pemilik ditolak saat disimpan                                                                                                  |
| `autoMember`           | keduanya     | aktif           | tambahkan pengguna secara otomatis ke setiap ruang kerja saat login pertama                                                                          |
| `allowJit`             | keduanya     | aktif           | sediakan pengguna tak dikenal saat login                                                                                                              |

## Konfigurasi proses

Koneksi SSO tidak diisi dari environment. Satu flag proses yang tersisa memilih
tempat browser membuka klien web setelah callback SSO:

| Variabel / flag                                  | Arti                                                                                                                   |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| `--web-client-url` / `CC_SERVER_WEB_CLIENT_URL`  | URL klien web untuk penyerahan kredensial tersegel; tanpa nilai, penyerahannya tetap se-origin (hanya berguna jika klien web disajikan di sana). Untuk login `web-popup`, `client_origin` yang diizinkan dari tab pemrakarsa lebih diutamakan. |

URL issuer itu sendiri harus `https` (`http` hanya diterima untuk issuer
loopback `localhost`, `127.0.0.1`, dan `::1`). Gunakan TLS tepercaya untuk callback
IdP dan host klien web: halaman yang menghasilkan kunci penerima bersama
JavaScript yang dikirimkannya adalah bagian dari batas kepercayaan. HTTPS
melindungi bootstrap itu; setelah pairing, sesi `/rpc` langsung maupun melalui
relay sama-sama memerlukan enkripsi Noise dan identitas server yang disematkan.

## Endpoint HTTP

| Endpoint                                         | Auth                | Tujuan                                                                                                                                                                                                          |
| ------------------------------------------------ | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /saml/login?relay=…&handoff_key=…`                        | tidak ada (pengalihan) | mulai login yang diprakarsai SP dengan kunci penerima X25519 yang dipegang klien; `relay=desktop` menyerahkan ke aplikasi, `relay=web-popup` mengirim postMessage ke tab koneksi yang menunggu (`client_origin`-nya dihormati hanya ketika daftar-izin origin mempercayainya) |
| `POST /saml/acs`                                 | tidak ada (POST dari IdP) | verifikasi asertion dan sediakan pengguna; login yang diprakarsai SP menyegel kredensial perangkat yang diterbitkan ke kunci penerima pemrakarsa; SAML tak diminta yang diizinkan menghasilkan klaim yang terikat browser sebagai gantinya |
| `POST /saml/claim`                               | hibah browser se-origin | tukarkan hibah SAML tak diminta sekali pakai bersama cookie-nya dan `handoff_key` baru; mengembalikan kredensial tersegel untuk penerimanya, bukan kunci pairing teks polos |
| `GET /saml/metadata`                             | tidak ada           | `EntityDescriptor` SP kami                                                                                                                                                                                       |
| `GET /oidc/login?relay=…&handoff_key=…` / `GET /oidc/callback` | tidak ada           | perjalanan bolak-balik OIDC; login memerlukan kunci penerima yang dipegang klien; `relay=desktop` menyerahkan ke aplikasi, `relay=web-popup` ke tab koneksi yang menunggu (konvensi `client_origin` yang sama) |
| `GET /auth/providers`                            | tidak ada, CORS `*` | probe layar koneksi: koneksi SSO yang ditawarkan (`id`/`kind`/`label`) + `pairingEnabled`                                                                                                                        |
| `/scim/v2/Users…`                                | Bearer (token SCIM) | Users create/get/list+filter/PUT/PATCH/DELETE                                                                                                                                                                    |
| `/scim/v2/Groups`                                | Bearer              | hanya-baca; push grup menjawab 501 secara desain                                                                                                                                                                 |
| `/scim/v2/ServiceProviderConfig`                 | Bearer              | dokumen kapabilitas                                                                                                                                                                                              |

Untuk SAML dan OIDC yang diprakarsai SP, URL mulai login memerlukan `handoff_key`
yang valid (kunci publik X25519 milik klien pemrakarsa). Server menyimpan kunci itu
bersama login yang tertunda dan menyegel kredensial perangkat yang diterbitkan saat
callback memakai X25519 sementara, HKDF-SHA256, dan AES-256-GCM yang terikat pada
origin server. Penyerahan desktop memakai `control-center://pair`, penyerahan web
di tab yang sama memakai fragmen URL, dan `web-popup` mengirim postMessage ke
`client_origin` yang diizinkan jika disediakan (jika tidak, ke URL klien web yang
dikonfigurasi atau origin callback). Amplop tersegel, bukan kunci pairing teks
polos, yang menempuh fragmen atau pesan popup itu. Klien pemrakarsa menyimpan kunci
privat yang bersesuaian untuk membukanya. Amplop ini berbeda dari sesi Noise wajib
yang dibangun setelah pairing.

Response SAML yang diprakarsai IdP (bila diaktifkan) tidak memiliki penerima
pemrakarsa. Sebagai gantinya, ACS menyetel cookie browser lima menit, HttpOnly,
SameSite=Strict dan menyajikan pilihan **Open web client** / **Open desktop app**.
Halaman itu menghasilkan kunci penerima baru dan mengirim separuh publiknya beserta
handle hibahnya ke `POST /saml/claim` dari origin yang sama. Claim memerlukan
cookie dan origin yang cocok (batas CSRF), memakai hibah sekali, dan hanya
mengembalikan amplop tersegel untuk penerimanya. Fragmen web/desktop berikutnya
membawa amplop itu beserta materi kunci privat penerima agar klien tujuan dapat
membukanya, **bukan** kredensial perangkat teks polos. Browser lain atau hibah yang
kedaluwarsa tidak dapat menukarkannya. Origin klien web tujuan dapat mengakses
fragmen dan mendekripsinya; halaman callback atau origin klien web yang disusupi
dapat mencuri kredensial. Enkripsi tidak membuat kode yang disajikan tetapi tidak
tepercaya menjadi aman.

## Operasi RPC

Semua operasi `sso.*` berskala server dan dibatasi hanya untuk **pemilik
server** (operator instalasi, `ServerAuthority.serverOwner`). Memiliki sebuah
ruang kerja saja tidak cukup; sekadar melakukan pemasangan pun tidak pernah
memberikannya.

| Operasi                   | Tujuan                                                                                                                                                        |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sso.getConfig`           | koneksi tersimpan untuk suatu jenis                                                                                                                           |
| `sso.saveConfig`          | validasi, simpan, dan terapkan langsung                                                                                                                       |
| `sso.status`              | flag aktif/terkonfigurasi, keberadaan token SCIM, origin kanonis                                                                                              |
| `sso.testConnection`      | uji koneksi tanpa perjalanan bolak-balik browser (SAML: parse metadata + bangun AuthnRequest; OIDC: penemuan issuer), dengan nilai di layar yang belum disimpan sebagai opsi |
| `sso.spMetadata`          | terbitkan `EntityDescriptor` SP untuk sebuah origin                                                                                                           |
| `sso.setPairingEnabled`   | izinkan/larang pemasangan manual (kode undangan, kunci pemasangan); menolak menonaktifkannya selama belum ada koneksi SSO yang berfungsi mencegah pengguna terkunci di luar |
| `sso.sessionPolicy`       | baca usia maksimum dan batas waktu menganggur kredensial perangkat instalasi (menit; `0` = tidak disetel)                                                      |
| `sso.setSessionPolicy`    | setel batas tersebut; ditegakkan saat pemeriksaan perangkat, tidak diumumkan ke klien                                                                          |
| `sso.scimRegenerateToken` | buat + kembalikan token bearer SCIM (sekali saja)                                                                                                             |

## Kode error validasi

Kegagalan `cc_saml_verify_response` membawa kode yang stabil:

| Kode                   | Arti                                                                             |
| ---------------------- | -------------------------------------------------------------------------------- |
| `signature`            | tanda tangan hilang/tidak tepercaya/dirusak, atau algoritme/transformasi yang tidak diizinkan |
| `expired`              | di luar `NotBefore`/`NotOnOrAfter` (melampaui pergeseran)                          |
| `audience`             | pembatasan audiens tidak menyebut kami                                            |
| `destination`          | tujuan respons bukan ACS kami                                                     |
| `request_match`        | `InResponseTo` tidak cocok dengan permintaan yang tertunda, atau tidak diminta padahal tidak diizinkan |
| `issuer`               | issuer bukan IdP yang dikonfigurasi                                               |
| `recipient`            | penerima konfirmasi subjek bukan ACS kami                                         |
| `malformed`            | kegagalan pada tingkat XML/skema                                                  |
| `status`               | status yang dilaporkan IdP bukan Success                                          |
| `invalid` / `internal` | apa pun selain itu / kegagalan pada seam                                          |

## Permukaan basis data

- `sso_connections` (global.db) — satu baris per jenis, LINTAS RUANG KERJA
  MEMANG DIRANCANG DEMIKIAN.
- `users.sso_subject` + `users.sso_issuer` — penyematan subjek penyedia, unik
  per `(issuer, subject)` melalui indeks parsial.
- `users.deactivated_at` — stempel penonaktifan SCIM.
- Token bearer SCIM dan client secret OIDC berada di berkas rahasia bermode 0600,
  tidak pernah di basis data.
