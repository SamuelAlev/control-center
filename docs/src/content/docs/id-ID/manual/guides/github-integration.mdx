Panduan ini membahas bagian-bagian penyiapan yang khusus untuk GitHub. GitHub
adalah salah satu dari tiga host kode yang didukung. Lihat
[Hubungkan host kode](/id-ID/panduan-pengguna/panduan-praktis/hubungkan-host-kode/)
untuk menghubungkan GitLab atau Bitbucket, dan untuk cara sebuah ruang kerja
memadukan ketiganya.

## Prasyarat

- Akun GitHub dengan akses ke repo yang ingin Anda kerjakan
- Server yang dapat memasukkan orang ke GitHub: baik GitHub App milik server Anda (lihat
  [Buat GitHub App](/id-ID/panduan-pengguna/panduan-praktis/github-app/)) atau Control Center
  Connect, dipilih oleh pemilik server di **Pengaturan → Server → Single sign-on**

:::note[Kredensial tersimpan di server dan melekat pada Anda]
Tidak ada yang disimpan di mesin yang sedang Anda pakai untuk mengetik.
Proses masuk GitHub Anda dipegang oleh `cc_server` Anda, dikunci berdasarkan id pengguna
Anda, dan setiap perangkat tempat Anda masuk memakainya: desktop, web, dan
ponsel. Anggota lain di server yang sama tidak dapat memakainya, dan
memasukkan mereka adalah hal yang mereka lakukan sendiri.
:::

## Masuk ke GitHub

GitHub hanya memakai proses masuk: tidak ada token untuk ditempel.

1. Buka **Pengaturan → Ruang kerja → Profil & identitas → Hosting kode** (atau langkah pertama
   onboarding)
2. Pada baris **GitHub**, klik **Masuk ke GitHub**
3. Peramban Anda membuka GitHub. Setujui aplikasinya

Cara menyelesaikan proses masuk bergantung pada pihak yang menjalankannya:

- **App milik server:** GitHub mengirim peramban Anda kembali ke server dan dialog
  mendeteksinya sendiri. Anda tidak perlu mengetik apa pun
- **Control Center Connect:** halaman peramban menampilkan kode 8 karakter. Ketik kode itu
  ke dialog, atau biarkan peramban membuka Control Center melalui tautan `control-center://`
  dan lewati pengetikan kode

Titik pemeriksaan: baris **GitHub** berbunyi "Masuk sebagai _your-username_".

Dialog menolak kode atau tautan yang tidak ia mulai sendiri, dengan pesan **Proses masuk tidak
dimulai di sini**. Jika seseorang mengirimi Anda tautan masuk, jangan lanjutkan: menyelesaikannya
akan menghubungkan akun Anda ke server mereka.

Klik **Putuskan** untuk menghapus proses masuk Anda. Keluar dari GitHub, atau dikeluarkan dari
sebuah ruang kerja, juga membatalkan setiap token yang dicetak server atas nama Anda.

## Siapa yang diwakili kredensial Anda

- **Apa pun yang Anda lakukan** (membuka halaman PR, mengirim tinjauan, menyetujui, merge) berjalan
  di bawah proses masuk **Anda** dan tidak di bawah yang lain. Jika Anda belum masuk, aplikasi akan
  memberi tahu dan meminta Anda masuk. Tidak ada kredensial lain yang menggantikan Anda
- **Pekerjaan tanpa orang mengetik** (eksekusi agen, pipeline, polling PR, balasan bot, clone)
  menerima token untuk satu repositori, dicetak dari GitHub App server atau melalui Connect. Token
  itu dibatasi pada apa yang dapat dilakukan anggota yang bertanggung jawab di sana: yang meminta,
  atau jika tidak, pemilik ruang kerja. Anggota yang tidak dapat push akan membatasi token hanya ke baca
- **Otomatisasi tidak pernah menyetujui** sebuah pull request. Persetujuan adalah tindakan seseorang

## Yang Anda dapatkan dari integrasi ini

| Fitur                 | Cara                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------------- |
| Daftar dan detail PR  | API REST GitHub, dari server, dengan proses masuk Anda sendiri                                                 |
| Hasil pemeriksaan     | API Checks GitHub                                                                                             |
| Publikasi tinjauan    | Langkah dengan gerbang pengguna yang memposting tinjauan Anda ke PR, atas nama Anda                            |
| Pendaftaran repo      | Sebuah checkout diterima jika remote `origin`-nya menunjuk ke github.com, atau ke gitlab.com / bitbucket.org  |
| Akses GitHub agen     | Token untuk satu repositori milik run sebagai `GH_TOKEN` / `GITHUB_TOKEN`; push melewati Control Center         |
| Ping notifikasi       | Polling di sisi server atas kotak masuk notifikasi GitHub Anda memunculkan "Disebutkan di pull request" dan "Tinjauan diminta" |
| Profil pengguna       | Kartu hover profil dan pemfilteran PR per penulis                                                             |

Sejumlah jalur memakai API GraphQL alih-alih REST jika lebih murah: aktivitas
cabang untuk pemilih compose-PR dan keadaan tinjauan langsung yang menentukan
apakah notifikasi permintaan tinjauan masih menggantung.

## Perhatikan gangguan GitHub

Bilah judul menampilkan chip status saat sebuah penyedia sedang terganggu,
mencakup GitHub, Claude, OpenAI, dan Kimi. **Chip itu disembunyikan selama
semuanya sehat**: kehadirannya menandakan ada masalah, bukan ketiadaannya.

Klik chip itu untuk membuka panel sembul berisi status tiap penyedia dan tombol
segarkan. Statusnya diperbarui sendiri setiap dua menit.

## Pahami cara agen bertindak di GitHub

- Agen yang bekerja di worktree GitHub mendapat token untuk repositori tersebut. Ia dapat membaca
  kode dan berkomentar di pull request ketika anggota yang bertanggung jawab memiliki hak push, dan
  hanya membaca ketika tidak. Push melewati Control Center, yang menanyakan aturan **Push ke remote**
  lalu meneruskannya dengan token tulis yang tidak pernah dipegang agen. Lihat
  [Konfigurasi kebijakan sandbox](/id-ID/panduan-pengguna/panduan-praktis/kebijakan-sandbox/)
- Commit agen selalu memakai identitas Git peminta sebagai penulis dan committer. Secara default, trailer `Co-Authored-By: Control Center <hi@usectrl.dev>` mencantumkan akun GitHub `@usectrl` sebagai penulis bersama. Di **Pengaturan → Anda → Atribusi commit**, Anda dapat mematikan kredit penulis bersama ini tanpa mengubah identitas Anda. Pengaturan ruang kerja di **Pengaturan → Ruang kerja → Umum** diutamakan dan mengunci tombol pribadi. Atribusi bawaan Claude Code selalu dinonaktifkan. Penandatanganan commit tetap memerlukan konfigurasi valid tersendiri
- Terminal yang Anda buka di sebuah rig menerima proses masuk Anda sendiri, dipersempit ke satu repositori, sehingga push di sana adalah milik Anda
- Ketika tidak ada token yang dapat dicetak (tidak ada anggota yang bertanggung jawab yang sudah masuk, app tidak terpasang di pemilik, atau instalasinya ditangguhkan), run dimulai tanpa token dan catatannya menjelaskan alasannya. Tidak ada kredensial cadangan

## Pemecahan masalah

### Daftar PR kosong dan menyebut GitHub tidak terhubung

Anda belum masuk ke GitHub di server ini. Klik **Masuk ke GitHub** di **Hosting kode**.
Repo di host kode lain tidak terpengaruh.

### Baris GitHub menyatakan proses masuk belum disiapkan di server ini

Server tidak memiliki GitHub App sendiri maupun Connect. Pemilik server memilih salah satunya di
**Pengaturan → Server → Single sign-on**: **Buat aplikasi GitHub saya** memakan waktu sekitar dua
menit. Lihat [Buat GitHub App](/id-ID/panduan-pengguna/panduan-praktis/github-app/).

### Dialog menyatakan kode tidak cocok

Ketik kode persis seperti yang ditampilkan peramban: 8 huruf dan angka. Lima kali salah memasukkan
kode akan mengakhiri proses masuk; mulai lagi.

### Proses masuk menyatakan aplikasi belum dipasang

GitHub App tidak memiliki pemasangan apa pun di akun pemilik repo. Seorang admin ruang kerja
memasangnya dari **Pengaturan → Ruang kerja → Umum → Pemasangan aplikasi GitHub**. Untuk
organisasi yang memakai App bersama Control Center, admin organisasi tersebut mungkin perlu
mengklik **Otorisasi server ini**. Lihat [Buat GitHub App](/id-ID/panduan-pengguna/panduan-praktis/github-app/).

### Semua orang harus masuk ke GitHub lagi

Pemilik server memutar kunci Connect server, berpindah ke server Connect lain, atau direktori data
dipulihkan ke mesin lain. Proses masuk melalui Connect terikat pada server yang membuatnya.

### Penambahan repo ditolak

Pendaftaran mensyaratkan ketiganya: path berada di dalam work tree git, ada
remote `origin`, dan remote tersebut menunjuk ke host kode yang didukung
(github.com, gitlab.com, atau bitbucket.org). Lihat
[Tambahkan repo ke ruang kerja](/id-ID/panduan-pengguna/panduan-praktis/tambah-repo/).

### Semua berhenti berfungsi untuk sementara setelah pemakaian berat

Itulah pemutus sirkuit batas laju. GitHub menandai batas utamanya dengan `403`
yang membawa `x-ratelimit-remaining: 0` dan waktu reset; ketika melihatnya,
klien menggagalkan permintaan berikutnya secara lokal tanpa panggilan jaringan
sampai jendela waktunya lewat, sehingga badai percobaan ulang tidak dapat
memperparah batas tersebut. Kegagalan sementara dicoba ulang hingga tiga kali
dengan backoff eksponensial, dengan menghormati `retry-after`.
