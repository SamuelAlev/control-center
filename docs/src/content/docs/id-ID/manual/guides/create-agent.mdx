Panduan ini menunjukkan cara menambahkan agen ke ruang kerja dan mengonfigurasinya hingga benar-benar dapat berjalan.

Setiap ruang kerja menyemai lima agen — seorang CEO plus `qa`, `architect`, `engineer`, dan `librarian` — sehingga biasanya Anda sudah memiliki agen sebelum mengonfigurasi satu pun. Langkah-langkah di bawah ini berlaku sama untuk agen yang disemai maupun agen baru.

## Sebelum memulai

- Anda berada di dalam sebuah ruang kerja. Seluruh antarmukanya ada di **Pengaturan → Ruang kerja → Agen** (`/settings/workspace/agents`).
- Agen akan memerlukan backend. Hubungkan penyedia untuk harness bawaan di **Pengaturan → Server → Penyedia model**, atau pasang CLI Claude Code di mesin yang menghosting `cc_server`.
- Jika Anda ingin agen membawa skill, pasang dulu skill tersebut di **Pengaturan → Ruang kerja → Skill**. Formulir agen hanya memungkinkan Anda mengaktifkan skill yang sudah ada di ruang kerja.

## Tambahkan agen

1. Buka **Pengaturan → Ruang kerja → Agen**.
2. Klik **Agen baru**.

Tidak ada dialog dan tidak ada pemilih peran. Agen bernama "Agen tanpa nama" langsung dibuat dan dipilih di panel detail di sebelah kanan.

Anda sekarang akan melihat "Agen tanpa nama" di daftar agen di sebelah kiri, dengan tab **Pengaturan** pada panel detailnya terbuka dan kolom **Nama** yang berisi "Agen tanpa nama".

## Beri nama

- **Nama** — pengenal pendek yang dipakai dalam @-mention, misalnya `alice`. Penguraian mention mencocokkan `@` yang diikuti karakter kata, sehingga nama yang mengandung tanda hubung, titik, atau spasi tidak akan pernah dapat disebutkan.
- **Judul** — label yang terbaca manusia, misalnya "Pengembang senior".
- **Prompt sistem** — instruksi tambahan opsional, disuntikkan sebagai bagian "Agent instructions"; bagian ini tidak menggantikan sisa prompt yang dirakit.

Klik **Simpan perubahan** di bagian bawah formulir. Semua kolom di halaman ini disimpan oleh satu tombol itu.

## Berikan adapter dan model

Dropdown **Adapter** mencantumkan runner yang benar-benar dimiliki host server. Adapter bawaan selalu ditemukan (dialah servernya). Claude Code hanya muncul bila CLI-nya terdeteksi di host tersebut:

| Adapter                   | Backend                                      |
| ------------------------- | -------------------------------------------- |
| Control Center (built-in) | Loop agen dalam proses — tanpa CLI eksternal |
| Claude Code               | `claude -p --output-format stream-json`      |

Hanya adapter bawaan yang menegakkan mode, pengarahan, jeda dan lanjutkan, kontrak penyelesaian, serta subagen. Claude Code tidak memberi Anda satu pun dari itu. Cursor, Codex, dan penyedia model lainnya menempel pada adapter bawaan, bukan sebagai runner terpisah.

:::note[Adapter kosong berarti loop bawaan]
Agen yang adapternya tidak disetel dikirim ke **Control Center (built-in)**, loop di dalam server, sehingga tidak ada yang perlu dipasang di host. Karena modelnya pun tidak disetel, ia meminta defaultnya kepada Anthropic, sehingga agen yang sama sekali tidak disetel hanya berjalan jika Anda telah menghubungkan akun Anthropic. Agen spesialis yang disemai hadir tanpa keduanya; setel keduanya pada setiap agen yang ingin Anda gunakan.
:::

Dropdown **Model** dikendalikan oleh adapter yang Anda pilih. Untuk adapter bawaan, daftarnya diambil langsung dari penyedia yang Anda hubungkan di **Pengaturan → Server → Penyedia model**, sehingga penyedia tanpa kredensial tersimpan menyumbang nol model.

## Tambahkan skill

**Skill** adalah pemilih chip atas bundel skill yang terpasang di ruang kerja ini. Ketuk sebuah chip untuk mengaktifkan atau menonaktifkannya; glif centang menandai yang dipilih. Jika ruang kerja tidak memiliki skill, kolomnya berbunyi "No skills available. Create skills in Settings → Skills first."

Anda tidak memilih skill milik repo sendiri di sini. Repo yang menyertakannya (di `.agents/skills/`, `.claude/skills/`, atau `.opencode/skills/`) menyumbangkannya secara otomatis ke agen mana pun yang bekerja di repo itu, dan skill tersebut berganti saat agen berpindah ke repo lain — lihat [Skill dengan cakupan repo](/id-ID/panduan-pengguna/konsep/model-agen/#repo-scoped-skills).

## Tetapkan garis pelaporan dan persona

- **Melapor ke** — pilih agen lain berdasarkan nama. Ini membangun pohon pelaporan yang ditampilkan oleh tombol **Bagan organisasi** di header halaman. Ini bukan daftar agen yang dipakai pemimpin tim saat mendelegasikan — daftar itu berasal dari anggota tim dan skill mereka.
- **Persona** — teks bebas yang membentuk nada dan perilaku, misalnya: "Lebih menyukai solusi sederhana yang mudah dibaca. Menulis pengujian untuk semua kode baru."

## Sesuaikan run

- **Upaya penalaran** — opsinya berasal dari tingkat yang dipublikasikan model yang dipilih sendiri: Low / Medium / High, plus Extra High pada model bergaya OpenAI dan Extra High + Max pada model bergaya Claude. Kolom ini disembunyikan sepenuhnya ketika model yang dipilih tidak menyatakan tingkat pemikiran apa pun, dan nilainya default ke default model itu sendiri.
- **Ukuran jendela konteks** — terisi otomatis dari jendela konteks model setiap kali Anda mengganti model, dengan chip satu ketuk untuk default model, 200k, 500k, dan 1M. Nilai yang Anda ketik setelah memilih model akan menang sampai pergantian model berikutnya.
- **Batas waktu diam (menit)** — hentikan run setelah selama ini tanpa keluaran. Biarkan kosong untuk memakai default per mode.

## Berikan izin

Agen tidak memiliki tombol izin sendiri. Apa yang boleh di-push, dibuka, di-merge, atau dijangkaunya ditetapkan oleh aturan aksi di **Pengaturan → Ruang kerja → Izin agen**, tempat sebuah aturan dapat dibatasi ke agen ini. Secara bawaan, push, pull request, review atau merge, dan penulisan ke pelacak masing-masing menanyakan Anda terlebih dahulu, dan akses jaringan diizinkan.

Token GitHub agen selalu hanya-baca. Push melewati Control Center, yang menanyakan aturan **Push ke remote** sebelum meneruskannya. Lihat [Konfigurasi kebijakan sandbox](/id-ID/panduan-pengguna/panduan-praktis/kebijakan-sandbox/) untuk cara setiap aturan menjangkau sebuah run.

:::note[Aturan dan sandbox OS adalah lapisan yang terpisah]
Aturan menentukan apa yang boleh dilakukan agen; sandbox OS membatasi di mana prosesnya dapat membaca, menulis, dan terhubung. `cc_server` membungkus run agen dalam sandbox host bila tersedia — Windows tidak memiliki backend native, sedangkan Linux dan WSL2 memerlukan `bwrap` dan `socat`. Lihat [Sandbox dan keamanan](/id-ID/panduan-pengguna/konsep/sandbox-dan-keamanan/) untuk keseluruhan batasnya.
:::

## Pastikan agen dapat berjalan

1. Buka **Pengaturan → Server → Penyedia model** dan pastikan adapter yang Anda pilih melaporkan versi yang terpasang, bukan "Tidak ditemukan". Klik **Segarkan** untuk memeriksa ulang — pemeriksaan berjalan di mesin yang menghosting `cc_server`, bukan di mesin yang sedang Anda lihat.
2. Buka space dengan agen tersebut dan kirim pesan kepadanya, atau @-mention agen itu di space yang sudah ada.
3. Kembali ke **Pengaturan → Ruang kerja → Agen**, pilih agen tersebut dan buka tab **Log**. Sebuah run akan muncul dengan lencana status, durasi, waktu mulai, dan adapter yang dipakainya. **Lihat** membuka aliran peristiwa run tersebut.

Jika tidak ada run yang muncul sama sekali, telusuri [Diagnosis agen](/id-ID/panduan-pengguna/panduan-praktis/diagnosis-agen/).

## Hapus agen

Pilih agen itu di daftar. Di tab **Pengaturan**, gulir ke **Zona berbahaya** di bagian bawah formulir lalu klik **Hapus**.
