Panduan ini menunjukkan cara mendaftarkan checkout Git ke sebuah ruang kerja, mengindeksnya ulang, dan menghapusnya lagi.

Repo bersifat **bercakupan ruang kerja**. Tidak ada registri global dan tidak ada langkah penautan: menambahkan repo dan menaruhnya di ruang kerja adalah tindakan yang sama. Checkout yang sama yang didaftarkan di dua ruang kerja menjadi dua baris independen dengan dua id yang berbeda — lintas ruang kerja, identitas sebuah repo adalah jalur sistem berkasnya, tidak pernah id-nya.

## Sebelum memulai

Sebuah folder hanya dapat didaftarkan jika ketiga syarat berikut terpenuhi:

1. Folder itu berada di dalam **work tree git**.
2. Work tree tersebut memiliki **remote `origin`**.
3. Remote `origin` menunjuk ke **forge yang didukung**: github.com, gitlab.com atau bitbucket.org.

Apa pun selain itu ditolak pada saat pendaftaran dengan pesan eksplisit: "Folder is not inside a git work tree.", "No `origin` remote configured for this repository.", atau "The `origin` remote is not hosted on a supported forge (github.com, gitlab.com, bitbucket.org).". Tidak ada mode yang hanya berjalan secara lokal.

Forge-nya dibaca dari remote dan disimpan pada repo — Anda tidak pernah memilihnya. Sebuah ruang kerja dapat memuat repo dari ketiganya sekaligus, dan masing-masing diajak berkomunikasi melalui API-nya sendiri dengan kredensialnya sendiri. Namespace bertingkat milik GitLab dipertahankan, sehingga `gitlab.com/group/subgroup/project` terdaftar dengan owner `group/subgroup`, name `project`.

Folder itu juga harus berada di mesin yang menghosting `cc_server`, di dalam salah satu direktori `--repo-roots` milik server tersebut. Daftar izin itu default-nya adalah direktori home pengguna server, dan menelusuri di atas sebuah root akan ditolak.

## Daftarkan checkout

1. Buka **Pengaturan → Ruang kerja → Repositori** (`/workspaces/<id>/settings/workspace/repositories`).
2. Klik **Tambah repositori**.

Dialog itu adalah peramban yang dapat dinavigasi atas sistem berkas **server**, bukan sistem berkas Anda. Alirannya sama di desktop, web, dan ponsel, karena pemilih folder native akan memilih folder di mesin yang salah.

3. Telusuri di dalam root yang dikonfigurasi server. Folder yang merupakan checkout git akan ditandai.
4. Centang sebanyak yang Anda inginkan. Pilihan itu tetap tersimpan saat Anda menelusuri, sehingga Anda dapat mengumpulkan checkout dari beberapa folder.
5. Daftarkan semuanya dalam satu batch.

Satu pilihan yang gagal tidak pernah menggugurkan sisa batch — Anda mendapatkan id yang berhasil dibuat plus galat per jalur untuk setiap pilihan yang ditolak. Mendaftarkan ulang jalur yang sudah ada di ruang kerja ini akan mengembalikan repo yang sudah ada, bukan membuat duplikat.

Setiap repo yang terdaftar muncul di daftar dengan `owner/name`, lencana yang menyebutkan forge-nya, dan jalurnya di server. Repo GitHub juga menampilkan avatar pemiliknya; forge lain tidak memiliki URL avatar pemilik yang dapat ditebak, sehingga mereka beralih ke inisial.

Lencana forge penting di ruang kerja campuran: dua repo bisa sama-sama bernama `acme/web` di forge yang berbeda, dan keduanya berperilaku berbeda — apa yang dapat dilakukan sebuah tinjauan, dan ke mana sebuah tautan mengarah.

## Apa yang terjadi selanjutnya

Pendaftaran memicu peristiwa `RepoAdded` yang bercakupan ruang kerja ini, yang menjalankan pipeline `index_code` untuk checkout tersebut. Itulah yang mengisi graf kode, sehingga pencarian dan analisis dampak memiliki bahan untuk menjawabnya.

Hanya berkas yang bahasanya memiliki grammar yang disertakan yang diindeks (Dart, JavaScript, TypeScript, TSX, PHP, Python, Rust, Zig, C, C++, Go, Java, Ruby, C#, Swift, Kotlin, R, Assembly, MATLAB, dan Ada). Lihat [Cari kode dengan graf kode](/id-ID/panduan-pengguna/panduan-praktis/cari-kode/).

## Indekskan ulang repo

Setiap baris memiliki tombol **Indekskan kode**. Klik tombol itu untuk menjalankan ulang pengindeks bagi checkout tersebut; selama berjalan, tombol tersebut berubah menjadi tampilan progres yang menunjukkan berkas yang selesai dari totalnya, beserta kontrol pembatalan. Setelah selesai, tombol itu menetap menjadi tanda centang dengan jumlah simbol, atau peringatan jika eksekusinya gagal.

## Ubah urutan repo

Seret tuas pada sebuah baris. Urutan yang Anda tetapkan adalah urutan yang dibaca kembali oleh setiap daftar repo di aplikasi.

## Perbaiki tautan GitHub

Ikon tautan pada sebuah baris membuka editor untuk owner dan nama repositori GitHub milik repo tersebut — berguna ketika remote-nya diganti nama atau dialihkan.

## Hapus repo

1. Buka **Pengaturan → Ruang kerja → Repositori**.
2. Klik ikon tempat sampah pada baris tersebut.
3. Konfirmasi "Hapus repositori dari ruang kerja?"

Dialog itu menjelaskan apa yang dilakukannya: "_name_ akan dihapus dari ruang kerja ini. File lokal di disk tidak diubah."

Penghapusan akan menghapus baris repo dari ruang kerja ini dan menggugurkan baris-baris graf kodenya secara berantai — simbol, edge, berkas, dan checkpoint indeks — plus setiap pemberian izin repo per anggota padanya, tautan space-repo miliknya, dan catatan checkout terisolasinya. Checkout yang sama yang terdaftar di ruang kerja lain adalah baris independen dan tidak terpengaruh. Worktree di disk yang ditunjuk oleh catatan tersebut tidak dibongkar oleh penghapusan ini.
