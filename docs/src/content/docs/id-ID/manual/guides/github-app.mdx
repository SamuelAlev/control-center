Panduan ini menunjukkan cara memberi server Anda GitHub App sendiri. Prosesnya sekitar
dua menit, hanya pemilik server yang melakukannya, dan cukup sekali per server.

:::note[Anda mungkin tidak memerlukannya]
Dengan Control Center Connect diaktifkan, orang masuk ke GitHub melalui app bersama Control
Center, atau melalui app yang dipakai Connect organisasi Anda. Daftarkan app Anda sendiri ketika
Anda memilih **Gunakan aplikasi saya sendiri**: app server hanya berlaku dalam kasus itu. Lihat [Control Center Connect](/id-ID/panduan-pengguna/referensi/connect/).
:::

Untuk masuk ke akun Anda sendiri setelahnya, lihat
[Siapkan integrasi GitHub](/id-ID/panduan-pengguna/panduan-praktis/integrasi-github/).

## Apa yang dilakukan app ini

Satu pendaftaran menjawab dua pekerjaan berbeda:

| Pekerjaan             | Yang menjawabnya                                        | Mengapa penting                                                                                 |
| --------------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **Seseorang masuk**   | Client id dan client secret app                         | Setiap orang memiliki kredensial GitHub sendiri, di server, di setiap perangkat                  |
| **Server bertindak**  | Id app dan kunci privat                                 | Agen, pipeline, polling, dan balasan bot menerima token untuk satu repositori dalam satu waktu   |

Pekerjaan kedua tidak pernah meminjam kredensial seseorang secara utuh. Setiap token yang dicetak
server hanya mencakup satu repositori dan dibatasi pada apa yang dapat dilakukan anggota yang
bertanggung jawab di sana. Membaca repositori yang tertaut hanya memerlukan app; apa pun yang
menulis memerlukan anggota yang dapat push. Otomatisasi tidak pernah menyetujui pull request.

App server hanya berlaku di bawah **Gunakan aplikasi saya sendiri**. Dengan Connect milik Control Center
atau Connect kustom, Connect menangani GitHub, dan app server tetap tersimpan tetapi tidak digunakan sampai
Anda beralih kembali. App ruang kerja ([Berikan satu ruang kerja app yang berbeda](#berikan-satu-ruang-kerja-app-yang-berbeda))
tetap berlaku di semua mode. App yang sebagian kolomnya hilang
adalah kesalahan, bukan cadangan: proses masuk GitHub ditolak sampai setiap kolom diisi.

## Prasyarat

- Anda adalah **pemilik server**. Kartu **Aplikasi penyedia** tidak terlihat oleh orang lain
- Akun GitHub. App dibuat di bawah akun itu
- Alamat server yang dapat dijangkau peramban Anda. Alamat publik server (atau loopback, untuk
  server desktop lokal) adalah tempat GitHub mengirim Anda kembali

## Buat dengan satu klik

1. Buka **Pengaturan → Server → Single sign-on** dan gulir ke kartu **Aplikasi penyedia**
2. Pada blok **GitHub**, opsional ketik nama organisasi GitHub yang akan memiliki app di
   **Organisasi (opsional)**. Biarkan kosong untuk membuat app di bawah akun Anda sendiri;
   membuatnya di bawah organisasi memerlukan Anda menjadi pemilik organisasi tersebut
3. Klik **Buat aplikasi GitHub saya**
4. Peramban Anda membuka GitHub dengan app yang sudah terisi. Klik **Create GitHub App**
5. GitHub mengirim Anda kembali ke server, yang menyimpan app id, kunci privat, client id, dan
   client secret, lalu membuka halaman pemasangan app

Tidak ada yang disalin manual, dan kode konversi berjalan langsung dari GitHub ke server Anda.
Tautan itu hanya berlaku sekali dan kedaluwarsa setelah sepuluh menit; jika kedaluwarsa, klik
**Buat aplikasi GitHub saya** lagi.

App diberi nama `Control Center <code>` dan hanya meminta apa yang digunakan Control Center:

| Izin                                       | Akses          |
| ------------------------------------------ | -------------- |
| Metadata                                   | Baca saja      |
| Contents                                   | Baca dan tulis |
| Pull requests                              | Baca dan tulis |
| Issues                                     | Baca dan tulis |
| Checks, Actions, Commit statuses           | Baca saja      |
| Organization members                       | Baca saja      |

Webhook dimatikan: server melakukan polling. Untuk memindahkan app yang Anda buat di bawah akun
sendiri ke sebuah organisasi di kemudian hari, gunakan **Transfer ownership** di pengaturan lanjutan
app di GitHub.

Titik pemeriksaan: blok GitHub berbunyi "Server dapat bertindak sebagai dirinya sendiri, dan orang
dapat masuk".

## Pasang di tempat repositori Anda berada

App yang terdaftar tetapi tidak dipasang hanya dapat memasukkan orang dan tidak dapat membaca apa pun.

1. Pilih akun atau organisasi yang memiliki repositori Anda pada halaman pemasangan yang dibuka GitHub
2. Pilih **All repositories**, atau pilih repositori yang harus dilihat server ini

Untuk memasang di akun lain nanti, seorang admin ruang kerja membuka **Pengaturan → Ruang kerja →
Umum**, menemukan **Pemasangan aplikasi GitHub** pada kartu identitas GitHub, dan mengklik
**Pasang aplikasi GitHub**. Daftar tersebut menampilkan setiap akun tempat app dipasang dan menandai
pemasangan yang ditangguhkan.

## Otorisasi server ini untuk sebuah organisasi

Pada app bersama Control Center, pemasangan sebuah organisasi hanya melayani server yang admin-nya
telah mengotorisasi. Memasang melalui **Pasang aplikasi GitHub** mengotorisasi server yang
memulainya. Untuk pemasangan yang sudah ada:

1. Seorang admin organisasi tersebut masuk ke GitHub di server ini
2. Mereka membuka **Pengaturan → Ruang kerja → Umum → Pemasangan aplikasi GitHub**
3. Baris organisasi tersebut menampilkan **Belum diotorisasi**. Mereka mengklik **Otorisasi server ini**

Baris itu kemudian menampilkan **Diotorisasi**. App milik sendiri Anda tidak memerlukan ini: setiap
pemasangannya menjadi milik server Anda.

## Daftarkan secara manual sebagai gantinya

Kartu **Aplikasi penyedia** juga menerima nilai secara langsung, untuk app yang Anda daftarkan sendiri:

| Grup                          | Kolom                                                                                          |
| ----------------------------- | ---------------------------------------------------------------------------------------------- |
| **Bertindak sebagai server**  | **Id aplikasi**, dan **Kunci privat** (seluruh `.pem`, termasuk baris `BEGIN` dan `END`)       |
| **Memasukkan orang**          | **Id klien** dan **Rahasia klien**. **URL callback** menampilkan URL yang harus didaftarkan, apa adanya |
| **Percakapan pull request**   | **Login bot**, diselesaikan ketika Anda menguji koneksi                                         |

Daftarkan URL callback `<server origin>/oauth/github/callback` persis seperti yang ditampilkan kartu,
biarkan **Expire user authorization tokens** aktif, dan berikan izin dalam tabel di atas. Klik
**Tes**: ia menanyakan ke GitHub di akun mana app dipasang, sehingga "tersimpan" dan "berfungsi"
tidak tertukar.

## Konfigurasi dari `.env` server

Untuk instalasi headless atau berbasis skrip, server menyemai setiap kolom dari berkas `.env`-nya
saat pertama kali tidak memiliki nilai tersimpan:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

Letakkan kunci pada **satu baris**: nilai `.env` adalah satu baris, dan `\n` di dalam tanda kutip
ganda didekode menjadi baris baru. Server menolak mulai ketika `GITHUB_APP_PRIVATE_KEY` atau
`GITHUB_CLIENT_SECRET` diekspor di lingkungan prosesnya, tempat setiap proses anak dapat
membacanya; simpan di berkas `.env` (di Docker, pasang di `/app/bin/.env`). Penyemaian terjadi
**sekali per kolom**, sehingga penyuntingan di Pengaturan tidak dibatalkan oleh mulai ulang.

## Berikan satu ruang kerja app yang berbeda

Sebuah ruang kerja dapat memakai app milik sendiri alih-alih app server. Seorang admin ruang kerja
membuka **Pengaturan → Ruang kerja → Umum**, memilih **Gunakan GitHub App lain** pada kartu
**Identitas GitHub**, dan memasukkan id, kunci privat, client id, dan client secret app tersebut.
Anggota kemudian masuk ke app itu untuk ruang kerja ini. Ruang kerja dengan app sendiri tidak pernah
kembali ke app server maupun ke Connect: sampai kolomnya lengkap, pekerjaan GitHub-nya ditolak. Ini berlaku
apa pun cara server menjalankan proses masuk, Connect termasuk.

Kartu **Aplikasi penyedia** di halaman yang sama melakukan hal serupa untuk Google Calendar, Linear, dan
pencarian GIF. Lihat [Berikan satu ruang kerja aplikasi Linear miliknya](/id-ID/panduan-pengguna/panduan-praktis/integrasi-linear/#berikan-satu-ruang-kerja-aplikasi-linear-miliknya)
dan [Berikan satu ruang kerja klien Google miliknya](/id-ID/panduan-pengguna/panduan-praktis/hubungkan-kalender/#berikan-satu-ruang-kerja-klien-google-miliknya).

## Pemecahan masalah

### Buat aplikasi GitHub saya menyatakan server tidak memiliki alamat

Server tidak memiliki URL publik yang dapat dikembalikan peramban. Setel `CC_SERVER_PUBLIC_URL`
(atau `--public-url`) lalu coba lagi.

### GitHub menyatakan tautan sudah kedaluwarsa

Halaman sekali pakai sudah digunakan, atau sudah lewat sepuluh menit. Mulai lagi dari Pengaturan.

### Tes menyebut kredensial berfungsi tetapi app tidak dipasang di mana pun

Pendaftaran dan pemasangan adalah langkah terpisah. Buka halaman pemasangan app,
atau gunakan **Pasang aplikasi GitHub** di Ruang kerja → Umum.

### Tes menyebut kunci privat tidak dapat dibaca

Tempel seluruh berkas `.pem`, termasuk baris `-----BEGIN` dan `-----END`. Kunci
`ed25519` atau EC tidak dapat dipakai: GitHub Apps menandatangani dengan RSA.

### Seorang anggota berhasil masuk tetapi tidak melihat repositori

App tidak dipasang pada akun yang memilikinya, atau pemasangannya memilih
repositori yang berbeda. Proses masuk hanya memberikan apa yang boleh dilihat app.

### Agen menyatakan pemasangan GitHub App ditangguhkan

Seseorang menangguhkan pemasangan itu di GitHub. Batalkan penangguhannya di
**Settings → Applications → Installed GitHub Apps** pada akun tersebut.
