Panduan ini menunjukkan cara bekerja dengan Control Center tanpa meninggalkan
GitHub: minta tinjauan AI dari halaman PR, ajukan pertanyaan kepada bot di
sebuah komentar, dan lanjutkan percakapan di utas tinjauannya.

Balasan datang melalui jalur GitHub ruang kerja: [GitHub App](/id-ID/panduan-pengguna/panduan-praktis/github-app/)
milik server Anda sendiri, atau App bersama Control Center melalui Connect. Tidak ada yang didaftarkan
baru, dan tidak ada yang harus dapat dijangkau dari internet: server menemukan apa yang dikatakan di
GitHub lewat polling, sehingga laptop di balik NAT berperilaku persis seperti deployment publik.

## Prasyarat

- Ruang kerja memiliki jalur GitHub: GitHub App milik server atau Connect, dengan app
  [terpasang](/id-ID/panduan-pengguna/panduan-praktis/github-app/) di akun pemilik repositori. App milik sendiri
  memerlukan izin baca dan tulis **Pull requests** dan **Issues**, yang sudah diberikan **Buat aplikasi GitHub saya**
- Repositori sudah ditautkan ke sebuah ruang kerja di Control Center
- Anda sudah [masuk ke GitHub](/id-ID/panduan-pengguna/panduan-praktis/integrasi-github/) di server ini,
  dan Anda dapat push ke repositori tersebut
- Tanpa URL webhook, tanpa tunnel, tanpa callback — tidak ada yang perlu
  dikonfigurasi di sisi jaringan

## Cari nama bot Anda

Sebut `@usectrl`, akun GitHub khusus Control Center. Ini adalah pemicu default; jalur GitHub ruang
kerja Anda tetap memproses permintaan dan mengirim balasan. Anda tidak memerlukan kredensial akun `usectrl`.

Login app itu sendiri, `<appslug>[bot]`, dan bentuk singkat `@appslug` juga berlaku. Untuk mencari alias
opsional tersebut pada app milik sendiri Anda:

1. Buka **Pengaturan → Server → Single sign-on** dan gulir ke kartu
   **Aplikasi penyedia**
2. Buka blok **GitHub** dan klik **Tes**
3. Salin **Login bot** saat nilainya terisi. Jika masih menampilkan petunjuk
   kosong, login-nya selalu `<appslug>[bot]` — ketik itu, atau bentuk pendeknya
   `@appslug`

GitHub tidak menampilkan akun App di pelengkapan otomatis `@`, jadi alias App harus diketik atau disalin. Akun khusus `@usectrl` adalah cara default untuk memanggilnya; `@myapp` maupun `@myapp[bot]` tetap diterima sebagai alias App.

:::note[Pilih nama app yang khas]
Bentuk pendek dicocokkan sebagai teks. Jika ada pengguna GitHub manusia yang
kebetulan memiliki slug app yang sama, menyebut pengguna itu dengan bentuk
pendek juga akan menjangkau bot. Bentuk lengkap `@myapp[bot]` selalu tidak
ambigu.
:::

## Minta tinjauan dari GitHub

Ada dua cara, keduanya memulai pipeline `pr_review` bawaan yang sama seperti
yang dimulai tombol **Tanya AI**:

- **Tambahkan label `ai-review`** ke PR. Ini adalah hal terdekat yang
  ditawarkan GitHub untuk menugaskan bot sebagai peninjau — akun app tidak dapat
  mengisi slot peninjau yang diminta secara native. Akun Anda bereaksi 👀 pada PR dan
  tinjauan dimulai di Control Center; tidak ada komentar yang diposting
- **Komentari `@usectrl review`** (atau cukup `@usectrl`) di percakapan PR. Sebuah 👀
  muncul pada komentar Anda, lalu sebuah balasan menyatakan tinjauan sudah dimulai (atau bahwa
  satu tinjauan sedang berjalan)

Para peninjau bekerja di space tinjauan milik PR; baca dan publikasikan
temuannya seperti pada [Gunakan tinjauan bertenaga AI](/id-ID/panduan-pengguna/panduan-praktis/tinjauan-ai/). Penerbitan
kembali ke GitHub tetap merupakan keputusan yang Anda buat di Control Center —
memulai tinjauan dari GitHub tidak memublikasikan apa pun ke GitHub dengan
sendirinya.

Label ini menyala sekali per PR: menambahkannya adalah permintaannya, dan label
ini tidak dipersenjatai ulang saat dihapus lalu ditambahkan lagi. Untuk
menjalankan tinjauan lagi — misalnya setelah push — sebut bot.

## Ajukan pertanyaan

Komentari percakapan PR:

```text
@usectrl why does the flaky test in runner_test.dart fail on CI but not locally?
```

Apa yang terjadi, secara berurutan:

1. Sebuah 👀 muncul pada komentar Anda, dari akun Anda sendiri, agar Anda tahu komentarnya terlihat
2. Pertanyaan diposting ke space tinjauan milik PR **atas nama Anda** —
   atribusi yang sama seperti jika Anda mengetiknya di Control Center
3. Seorang agen menjawab di space tersebut, dan jawabannya diposting kembali di PR. Setiap
   balasan dimulai dengan `**Control Center** (for @your-login):`

Pertanyaan pada PR yang belum ditinjau akan membangunkan agen CEO ruang kerja;
setelah sebuah tinjauan berjalan, agen yang terakhir berbicara akan menjawab,
sehingga tindak lanjutnya sampai ke pihak yang memiliki konteksnya.

## Tindak lanjuti di utas tinjauan

Balas di dalam utas tinjauan inline tempat bot menjadi bagiannya — komentar
diff yang ditinggalkannya, atau jawaban yang dipostingnya di utas itu. Tidak
perlu sebutan; utas itu sendiri **adalah** alamatnya:

```text
> @usectrl the retry loop looks O(n²) to me

what would the complexity be with the bounded queue instead?
```

Percakapan multi-giliran bekerja dengan cara yang sama: setiap balasan adalah
pertanyaan lain dalam percakapan yang sama, dengan space tinjauan sebagai
konteks, dan jawabannya kembali di utas tersebut.

Tindak lanjut pada linimasa percakapan PR adalah komentar tingkat teratas yang
baru, jadi tetap memerlukan @mention.

## Dengan siapa bot berbicara

Server menyelesaikan penulis sebuah komentar, atau siapa pun yang menambahkan label `ai-review`,
sebelum melakukan apa pun:

- **Akun GitHub harus sudah masuk** di server ini. Pencocokannya memakai id akun GitHub numerik, tidak
  pernah login. Masuk dari **Pengaturan → Ruang kerja → Profil & identitas → Hosting kode**
- **Mereka harus anggota dengan peran tulis** (`member`, `admin`, atau `owner`) di ruang kerja
  yang menautkan repositori tersebut
- **Mereka harus dapat push** ke repositori di GitHub. Balasan memakai token yang dibatasi pada akses
  orang itu, sehingga seseorang yang hanya dapat membaca tidak mendapat balasan

Siapa pun selain itu diabaikan secara diam-diam: tidak ada yang diposting, dan kata-kata mereka tidak
pernah masuk ke ruang kerja. Komentar dari bot, dan balasan Control Center sendiri, tidak pernah diperlakukan
sebagai pertanyaan.

### Dua server, satu PR

Reaksi 👀 juga menjadi cara server-server menyepakati siapa yang menjawab. Reaksi itu ditambahkan
dengan proses masuk penulis sendiri, dan GitHub memberi tahu server apakah reaksi itu baru. Jika Anda masuk di
dua server Control Center yang sama-sama menautkan repositori, yang pertama bereaksi yang menjawab dan yang
lain tetap diam. Hal yang sama berlaku untuk label.

## Yang bisa Anda harapkan

| Hal                 | Perilaku                                                                 |
| ------------------- | ------------------------------------------------------------------------ |
| Pengakuan           | 👀 dari akun Anda pada komentar (atau pada PR, untuk label), dalam satu penyapuan |
| Jawaban             | Diposting di jalur tempat pertanyaan diajukan, dimulai dengan `**Control Center** (for @your-login):`. Pada app milik sendiri, penulisnya adalah akun bot app; lewat Connect, itu akun Anda, bertindak melalui App |
| Atribusi di dalam space | Pertanyaannya milik Anda; agen berjalan atas nama Anda, di bawah pengaturan otonomi space |
| Tinjauan            | Temuan mendarat di space tinjauan; publikasi ke GitHub dilakukan secara manual |

Penyapuan berjalan setiap menit pada app milik sendiri dan memeriksa hingga 25 pull request; lewat Connect,
berjalan setiap dua menit dan memeriksa hingga 10, karena panggilan-panggilan itu memakai kuota GitHub
milik masing-masing anggota. Ruang kerja yang kuota GitHub-nya di bawah 15% akan dilewati hingga pulih.
Latensi adalah harga yang dibayar agar tidak perlu akses jaringan masuk sama sekali. Tidak ada yang hilang
saat server offline — komentar yang tiba selama server mati akan tertangkap pada penyapuan berikutnya.

## Pemecahan masalah

**Tidak ada yang terjadi untuk komentar yang menyebut bot.**

- Apakah app sudah **dipasang** di akun yang memiliki repo tersebut, dan
  repo-nya sudah **ditautkan** ke sebuah ruang kerja? Repo yang belum ditautkan
  dilewati sebelum apa pun dicatat, jadi menautkannya nanti tetap akan
  mengantarkan
- Apakah Anda sudah masuk ke GitHub di server ini, apakah Anda anggota dengan peran tulis, dan
  dapatkah Anda push ke repo? Server mengabaikan siapa pun selain itu tanpa membalas
- Pada app bersama Control Center, apakah pemasangan organisasi sudah diotorisasi untuk server ini?
  Lihat [Buat GitHub App](/id-ID/panduan-pengguna/panduan-praktis/github-app/)
- Masih tidak ada? Log server menyebutkan penyapuan dan PR-nya ketika ada yang
  gagal; cari `pr_conversation:` (penyapu) dan
  `github_pr_conversation:` (jembatan)

**Label tidak memulai tinjauan.**

Label ini menyala sekali per PR, dan orang yang menambahkannya melewati pemeriksaan yang sama dengan penulis
komentar. Jika tinjauan sudah pernah berjalan, atau label ditambahkan sebelum server pernah melihat PR
tersebut (penyapuan pertama mencatat tumpukan yang tertunda secara senyap alih-alih menyerbunya), sebut bot
sebagai gantinya — `@usectrl review` selalu memulai tinjauan kecuali sudah ada tinjauan yang sedang berjalan.

**Jawaban bot tidak pernah tiba di GitHub.**

Jawabannya sendiri tidak pernah hilang — jawaban itu ada di space tinjauan milik
PR di Control Center. Kegagalan posting (GitHub mati, izin berubah) akan dicatat
dan balasannya tidak dicoba ulang; tanyakan lagi di utas tersebut jika hal itu
penting.
