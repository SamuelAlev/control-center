Panduan ini menunjukkan cara mengonfigurasi notifikasi dan apa yang sebenarnya
dikendalikan oleh setiap pengaturan.

Notifikasi tiba di dua permukaan. **Pusat notifikasi** — lonceng di bilah judul —
membaca feed per ruang kerja yang tahan lama di server. **Toast OS** adalah jalur
terpisah yang hanya ada di desktop, disuapi oleh frame langsung yang dikirim
server.

:::note[Build web tidak menampilkan notifikasi OS]
Pipeline toast hanya dibangun oleh bootstrap desktop. Di `app.usectrl.dev` tidak
ada toast OS, tidak ada suara notifikasi, dan tidak ada banner ambien — lonceng
beserta riwayatnya tetap berfungsi, karena keduanya membaca feed server. Klien
ponsel sama sekali tidak memiliki permukaan notifikasi.
:::

## Nyalakan atau matikan kategori

1. Buka **Pengaturan → Anda → Notifikasi**
2. Biarkan **Aktifkan notifikasi** tetap aktif
3. Nyalakan kategori yang Anda inginkan. Jumlahnya tepat tujuh belas:

| Kategori                  | Memicu ketika                                                              |
| ------------------------- | -------------------------------------------------------------------------- |
| Agen selesai              | Agen membalas dalam run yang Anda mulai, atau run tersebut gagal           |
| Agen menunggu Anda        | Agen memerlukan persetujuan Anda, mengajukan pertanyaan kepada Anda, atau tertahan oleh kredensial |
| PR dipublikasikan         | Agen memublikasikan sebuah PR                                              |
| PR digabungkan            | Sebuah PR digabungkan                                                      |
| Pesan baru                | Seseorang menyebut Anda di sebuah space                                    |
| Disebutkan di pull request | Polling notifikasi GitHub melihat Anda disebutkan di sebuah PR            |
| Tinjauan diminta          | Tinjauan Anda benar-benar diminta pada PR yang bukan draf                  |
| Tinjauan kedaluwarsa      | Commit baru masuk ke pull request yang sudah Anda tinjau                   |
| Siap digabungkan          | Pull request yang Anda tulis menjadi dapat digabungkan, atau berhenti begitu |
| Keputusan tinjauan        | Peninjau menyetujui, meminta perubahan, atau persetujuannya dibatalkan     |
| Checks                    | CI gagal pada pull request yang Anda tulis, atau pulih kembali             |
| Utas tinjauan             | Seseorang membalas atau menyelesaikan utas tempat Anda berada              |
| Tiket ditugaskan          | Sebuah tiket ditugaskan                                                    |
| Status tiket berubah      | Sebuah tiket berubah status                                                |
| Rapat segera dimulai      | Rapat kalender berada di dalam jendela jeda Anda                           |
| Kalender terputus         | Token OAuth kalender yang terhubung kedaluwarsa                            |
| Pembaruan enclosure       | Sebuah enclosure diambil alih, diklaim kembali, atau gagal                 |

Apa pun di luar daftar ini tidak dapat dinotifikasi atau difilter — tidak ada
kategori "segala hal lainnya".

**Agen menunggu Anda** memicu sekali untuk setiap penantian, saat penantian itu
dimulai: persetujuan yang tertunda (termasuk hibah eksekusi sandbox dan
persetujuan alat Claude Code), pertanyaan `ask_user`, atau run yang ditahan
karena kredensialnya tidak dapat melayaninya. Notifikasi ini membuka space
tempat Anda menjawab, dan tetap diam selama Anda sedang melihat space tersebut.

Preferensi ini mengikuti pengguna Anda lintas perangkat, sehingga ponsel dan
laptop tetap selaras. Volume adalah pengecualian yang disengaja dan tetap per
perangkat.

## Atur Quiet hours

1. Di halaman yang sama, nyalakan **Quiet hours**
2. Ketik waktu mulai dan waktu selesai dalam format `HH:MM` (jendela bawaannya
   22:00–08:00)

Selama Quiet hours, notifikasi yang tidak mendesak dibuang — bukan diantrekan
lalu diputar ulang nanti.

Dua kategori bersifat **mendesak** dan selalu terkirim, melewati Quiet hours
_dan_ mode fokus: **Rapat segera dimulai** dan **PR dipublikasikan**. Peringatan
rapat yang baru Anda lihat setelahnya tidak ada gunanya, dan itulah alasannya.

## Pilih suara

1. Gulir ke **Suara notifikasi**
2. Pilih salah satu dari sebelas suara bawaan, atau **Tidak ada**
3. Tekan tombol tes untuk mendengarkannya dan atur volumenya dengan penggeser

Aplikasi memutar suaranya sendiri; notifikasi OS dikirim tanpa suara sehingga
Anda tidak pernah mendengarnya dua kali.

## Atur waktu jeda rapat

1. Gulir ke **Waktu jeda peringatan**
2. Pilih **5**, **10**, **15**, atau **30** menit

Itulah seberapa jauh sebelum acara kalender notifikasi **Rapat segera dimulai**
dipicu. Bawaannya 5 menit.

## Ketahui kapan sebuah notifikasi dibuang

Sebuah notifikasi dibuang, secara senyap, ketika salah satu dari ini benar:

- Notifikasi dimatikan secara global, atau kategorinya dimatikan
- Anda sudah berada di rute yang akan dituju olehnya — dan, untuk sebuah pesan,
  sudah berada di space tersebut
- Mode fokus aktif dan kategorinya tidak mendesak
- Quiet hours aktif dan kategorinya tidak mendesak

Pemeriksaan itu berlaku untuk toast OS. Lonceng yang tahan lama tetap mencatat
peristiwanya.

Dua pembuangan lain terjadi lebih jauh di hulu, pada apa yang benar-benar
dikirim server:

- Pesan dari **manusia** lain yang tidak menyebut Anda tidak pernah menjadi
  notifikasi
- Di space bersama, balasan agen hanya memberi tahu orang yang memulai run
  tersebut, bukan setiap anggota
- Space antar-agen dibisukan di bilah sisi, sehingga tidak pernah menambah
  lencana belum dibaca milik manusia

Di dalam sebuah space tidak ada sudut yang tenang: setiap percakapan memberitahu
dengan setara, termasuk utas. Status baca berskala space, sehingga yang belum
dibaca teragregasi di seluruh percakapan sebuah space alih-alih dilacak per
percakapan.

## Baca dan bersihkan pusat notifikasi

1. Klik lonceng di bilah judul

Popover-nya menampilkan aktivitas terbaru, dan setiap entri bertaut langsung ke
hal yang dibahasnya. Membukanya **tidak** menandai semuanya sudah dibaca —
gunakan **Tandai semua sudah dibaca** di header, atau tandai satu baris saja.
Status baca mengikuti pengguna Anda lintas perangkat.

:::note[Hapus semua adalah tanda air, bukan penghapusan]
**Hapus semua** membubuhkan tanda air per pengguna yang menyembunyikan semua
yang lebih lama; barisnya tetap ada. Secara terpisah, setiap ruang kerja hanya
menyimpan **200** baris feed terbarunya, dipangkas saat baris baru datang,
sementara lonceng berlangganan **50** baris terbaru dan popover mencantumkan
hingga **15** di antaranya. Riwayat di luar itu hilang terlepas dari status
baca.
:::

## Pemecahan masalah

### Tidak ada notifikasi OS di macOS

Izin diminta secara native saat aplikasi diluncurkan. Jika Anda menolaknya,
aktifkan kembali Control Center di Pengaturan Sistem → Notifikasi; tidak ada
perintah di dalam aplikasi untuk memicunya lagi.

### Tidak ada yang tiba di build web

Sesuai harapan — build web tidak memiliki pipeline notifikasi OS. Gunakan
lonceng.

### Lencana lonceng menunjukkan nol padahal jelas ada aktivitas baru

Sampai aliran penanda baca selesai setelah terhubung, entri ditampilkan sebagai
sudah dibaca agar lencana tidak berkedip lalu kosong. Keadaannya stabil begitu
penandanya dimuat.

### Run seorang agen selesai tetapi tidak ada yang memberitahu saya

Periksa apakah Anda belum berada di space tempat hal itu terjadi — rute yang
aktif menekan toast OS-nya sendiri. Di space bersama, run yang dimulai orang lain
memberi tahu orang itu, bukan Anda. Giliran yang berakhir tanpa balasan dan tanpa
galat tidak mengirim apa pun.
