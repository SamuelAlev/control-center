Panduan ini menunjukkan cara menghubungkan klien MCP eksternal — Claude Code,
sebuah editor, MCP Inspector — ke server alat milik Control Center sendiri.

Control Center mendaftarkan **110** alat dan menyajikannya melalui Model Context
Protocol pada versi protokol `2024-11-05`. Seluruh keluarga alat yang mungkin
Anda harapkan tidak ada: tidak ada alat rapat atau kalender dan tidak ada alat
proyek.

## Temukan endpoint

Permukaan MCP berbagi listener utama `cc_server`. Tidak ada port MCP terpisah.

| Endpoint | Metode   | Tujuan                                                   |
| -------- | -------- | -------------------------------------------------------- |
| `/mcp`   | `POST`   | Transport HTTP Streamable — inilah yang dipakai klien    |
| `/mcp`   | `DELETE` | Akhiri sesi                                              |
| `/sse`   | `GET`    | Aliran notifikasi yang dikirim server                    |

Jadi instalasi lokal bawaan berada di `http://127.0.0.1:9030/mcp`.

1. Buka **Pengaturan → Server → Server MCP**
2. Baca kartu **Server MCP** — kartu itu menunjukkan berjalan atau berhenti dan
   port yang sedang didengarkannya

Permukaan ini aktif secara bawaan pada instalasi baru. Hanya pemilik server yang melihat token pada kartu, dan hanya mereka yang dapat memulai atau menghentikan endpoint. **Mulai saat aplikasi
diluncurkan** mengontrol apakah permukaan itu kembali setelah mulai ulang;
**Mulai** / **Berhenti** adalah kontrol sesi yang tidak mengubah preferensi
tersebut.

Server ini mengikat loopback secara bawaan, sehingga endpoint-nya hanya dapat
dijangkau dari mesin tempat `cc_server` berjalan kecuali Anda memulainya dengan
`--bind any`.

## Dapatkan token

Setiap permintaan memerlukan token MCP server, dari mesin mana pun, termasuk loopback. Server membuatnya saat pertama kali dijalankan. Tidak ada cara untuk mematikannya dan tidak ada cara untuk menghapusnya.

1. Di **Pengaturan → Server → Server MCP**, temukan baris **Token autentikasi**
2. Tekan **Tampilkan token** dan salin
3. Untuk menggantinya, tekan **Ganti token**. Server langsung beralih ke token baru, dan setiap klien yang masih memakai token lama ditolak sampai Anda memberinya token baru

## Hubungkan klien

Arahkan klien Anda ke endpoint HTTP Streamable dan kirimkan token sebagai `Authorization: Bearer <token>` pada setiap permintaan, termasuk `GET /sse`. Tidak ada cara lain untuk mengirimkannya: token di URL tidak diterima. Bentuk konfigurasi yang tepat adalah urusan klien Anda.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code tidak akan mengambil ini dari `.mcp.json` proyek — ia menahan server
MCP bercakupan proyek di balik prompt persetujuan yang tidak pernah dijawab oleh
`claude -p` noninteraktif. Berikan konfigurasinya secara eksplisit:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` membuat Claude hanya memakai file itu, sehingga server yang
sama tidak juga ditemukan dari proyek dan didaftarkan dua kali.

Titik periksa: minta klien menampilkan daftar alatnya. Anda semestinya melihat
entri `mcp__*` yang mencakup tiket, space, memori, graf kode, dan tinjauan.

## Apa yang ditolak endpoint

Token membuka setiap alat di server, jadi endpoint juga menolak apa pun yang dapat dikirim oleh halaman web, sebelum memeriksa token:

| Permintaan | Jawaban |
| ---------- | ------- |
| Header `Origin` yang bukan halaman di mesin ini (`http://localhost`, `http://127.0.0.1` atau `http://[::1]`, port apa pun) | `403`, "Permintaan lintas-origin tidak diterima" |
| Header `Host` yang bukan alamat loopback dan port listener ini, dan bukan nama host publik server | `403`, "Host tidak dikenal" |
| `POST` yang isinya bukan `application/json` | `415` |
| Tidak ada token, atau token yang salah | `401` |

Untuk melayani MCP di luar host, jalankan server dengan `--bind any` dan kirimkan token dari mesin lain, dengan menyebut server melalui nama host publiknya.

## Batasi setiap panggilan ke satu ruang kerja

Setiap alat yang menyentuh data bercakupan ruang kerja mewajibkan `workspace_id`
dan panggilan tanpanya ditolak, bukan diselesaikan terhadap semacam ruang kerja
"saat ini":

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

Id itu adalah id yang ada di peramban atau URL aplikasi Anda:
`/workspaces/<workspace_id>/…`. Satu-satunya pengecualian adalah alat yang
memang mencakup banyak ruang kerja, seperti `list_workspaces` dan alat umpan
berita — umpan berita bersifat per pengguna dan agen tidak punya pengguna
sendiri, sehingga alat-alat itu beroperasi pada feed milik pemilik server.

Alat bercakupan repo juga memeriksa bahwa repo tersebut ditautkan ke ruang kerja
itu.

## Ketahui apa yang akan ditolak permukaan

- **Gerbang mode.** Sebuah panggilan diselesaikan terhadap mode space agen
  pemanggilnya, di sisi server. Agen dalam mode hanya baca tidak dapat mencapai
  alat tulis dengan menghilangkan `space_id` — modenya dicari dari run aktifnya
  sebagai gantinya.
- **Pagar pengaman tindakan.** Alat yang mengubah keadaan mendeklarasikan kelas
  efeknya dan melewati kebijakan yang sama dengan yang dipakai seluruh produk
  lainnya. Lihat
  [Konfigurasi pagar pengaman](/id-ID/panduan-pengguna/panduan-praktis/konfigurasi-pagar-pengaman/).
- **Konfirmasi.** Sebagian alat destruktif menyusun muatan konfirmasi yang harus
  disetujui sebelum panggilan berlanjut.

Katalog lengkapnya diumumkan di `tools/list` tanpa gerbang penemuan — klien MCP
eksternal menolak memanggil alat yang tidak ada dalam daftar cache-nya, jadi
menyembunyikan alat justru merusaknya alih-alih merapikannya.

## Server MCP yang digunakan agen Anda

Panduan ini membahas endpoint milik Control Center sendiri. Arah sebaliknya adalah Server MCP yang dihubungkan Control Center dan diserahkan kepada agen yang dijalankannya. Anda mengaturnya di **Pengaturan → Server → Server MCP**, pada dua tingkat. Dalam kedua kasus, Control Center terhubung ke servernya sendiri dan meneruskan alatnya ke run, sehingga harness bawaan dan Claude Code mendapatkan alat serta permintaan persetujuan yang sama. Run Claude Code melihatnya di bawah `control-center`, sebagai `mcp__control-center__mcp__<server>__<tool>`.

### Server ruang kerja

Admin ruang kerja menambahkannya di **Server MCP ruang kerja**. Setiap run agen di ruang kerja itu mendapatkan alatnya, dan run di ruang kerja lain tidak.

1. Pilih **Tambah server** dan beri nama singkat: huruf, angka, `-` dan `_`, hingga 24 karakter. Alat muncul sebagai `mcp__<name>__<tool>`.
2. Pilih cara menjangkaunya:
   - **Perintah (stdio):** sebuah executable beserta argumennya, ditambah variabel lingkungan yang dibutuhkannya.
   - **URL (HTTP atau SSE):** endpoint-nya, ditambah header yang dibutuhkannya, seperti `Authorization: Bearer …`.
3. Simpan. Pemeriksaan: Server menampilkan **Terhubung** dengan jumlah alat.

Nilai variabel lingkungan dan header disimpan di berkas rahasia Server dan tidak pernah ditampilkan lagi. Untuk mengubah nilai, ganti nilainya; untuk menghapusnya, hapus namanya.

Perintah dijalankan di mesin pemilik Server sebagai pengguna Server itu sendiri, jadi perintah tidak mulai sebelum pemiliknya menyetujuinya. Sampai saat itu statusnya **Menunggu persetujuan**. Server URL langsung berfungsi, tetapi hanya dapat menjangkau alamat publik sampai pemiliknya menyetujuinya, yang juga mengizinkan `localhost` dan jaringan privat. Ketika pemiliknya menyimpan Server, itu dihitung sebagai persetujuan. Jika pihak lain mengubah cara Server dijalankan atau tempat ia terhubung, Server perlu disetujui lagi. Mengaktifkan atau menonaktifkan Server tidak menghapus persetujuannya.

### Server pribadi

Server pribadi adalah milik pemiliknya dan tercantum di bawah **Server MCP eksternal**. Server yang dikonfigurasi di mesin Server untuk Claude, Codex, Cursor, Gemini, VS Code, Windsurf, OpenCode, atau dalam `.mcp.json` ditemukan di sana secara otomatis. Pemilik juga dapat menambahkan Server sendiri dengan **Tambah server**, memakai formulir yang sama. Server yang Anda tambahkan mengalahkan Server yang ditemukan dengan nama yang sama.

Server pribadi bertindak dengan identitas dan kredensial pemiliknya:

- Server pribadi hanya tersedia dalam run yang dimulai pemiliknya atau yang dipertanggungjawabkan kepadanya, termasuk otomatisasi di ruang kerja yang dipertanggungjawabkan pemilik. Itu mencakup run harness bawaan dan run Claude Code.
- Run anggota, otomatisasi yang terikat pada anggota, dan setiap run yang berjalan tanpa pemilik tercatat tidak mendapatkan satu pun darinya. Di sana alat-alatnya tidak didaftarkan, tidak dapat dipanggil, dan tidak muncul dalam pencarian alat.
- Baik Server pribadi maupun Server ruang kerja tidak disajikan ke token MCP atau ke perangkat yang dipasangkan, dan sumber daya serta prompt-nya tidak diteruskan.

Masuk ke Server dengan OAuth tidak tersedia dari formulir. Gunakan Server yang menerima token di header, atau konfigurasikan untuk salah satu alat di atas agar ditemukan secara otomatis.

## Pemecahan masalah

### Klien tidak melihat alat apa pun

- Periksa kartu **Server MCP** menyatakan berjalan
- Periksa portnya cocok dengan port `cc_server` Anda
- Pada Claude Code, periksa Anda sudah memberikan `--mcp-config` dan
  `--strict-mcp-config`

### 401 Unauthorized

Permintaan tidak membawa token, atau membawa token lama. Salin token saat ini dari baris **Token autentikasi** dan kirimkan sebagai `Authorization: Bearer <token>`. Token di URL diabaikan.

### 403 dari klien yang dulu berfungsi

Permintaan membawa `Origin` dari halaman web, atau `Host` yang tidak dijawab server. Panggil endpoint dari klien, bukan dari halaman peramban, dengan alamat loopback server atau nama host publiknya.

### 415 Unsupported Media Type

Kirim isi `POST /mcp` sebagai `application/json`.

### Panggilan alat gagal dengan "Missing or invalid argument: workspace_id"

Tambahkan `workspace_id`. Tidak ada ruang kerja implisit.

### Panggilan alat ditolak sebagai tidak dikenal

[Alat MCP](/id-ID/panduan-pengguna/referensi/alat-mcp/) mencantumkan katalognya.
Panggil namanya persis seperti yang tertera di sana.
