Panduan ini menunjukkan cara menghubungkan klien MCP eksternal — Claude Code,
sebuah editor, MCP Inspector — ke server alat milik Control Center sendiri.

Control Center mendaftarkan **110** alat dan menyajikannya melalui Model Context
Protocol pada versi protokol `2024-11-05`. Seluruh keluarga alat yang mungkin
Anda harapkan tidak ada: tidak ada alat rapat atau kalender dan tidak ada alat
proyek.

## Temukan endpoint

Permukaan MCP berbagi listener utama `cc_server`. Tidak ada port MCP terpisah.

| Endpoint | Metode   | Tujuan                                                   |
| -------- | -------- | -------------------------------------------------------- |
| `/mcp`   | `POST`   | Transport HTTP Streamable — inilah yang dipakai klien    |
| `/mcp`   | `DELETE` | Akhiri sesi                                              |
| `/sse`   | `GET`    | Aliran notifikasi yang dikirim server                    |

Jadi instalasi lokal bawaan berada di `http://127.0.0.1:9030/mcp`.

1. Buka **Pengaturan → Server → Server MCP**
2. Baca kartu **Server MCP** — kartu itu menunjukkan berjalan atau berhenti dan
   port yang sedang didengarkannya

Permukaan ini aktif secara bawaan pada instalasi baru, sehingga klien loopback
berfungsi tanpa perlu mengutak-atik pengaturan. **Mulai saat aplikasi
diluncurkan** mengontrol apakah permukaan itu kembali setelah mulai ulang;
**Mulai** / **Berhenti** adalah kontrol sesi yang tidak mengubah preferensi
tersebut.

Server ini mengikat loopback secara bawaan, sehingga endpoint-nya hanya dapat
dijangkau dari mesin tempat `cc_server` berjalan kecuali Anda memulainya dengan
`--bind any`.

## Hubungkan klien

Arahkan klien Anda ke endpoint HTTP Streamable. Bentuk konfigurasi yang tepat
adalah urusan klien Anda; URL-nya sama saja.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp"
    }
  }
}
```

### Claude Code

Claude Code tidak akan mengambil ini dari `.mcp.json` proyek — ia menahan server
MCP bercakupan proyek di balik prompt persetujuan yang tidak pernah dijawab oleh
`claude -p` noninteraktif. Berikan konfigurasinya secara eksplisit:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` membuat Claude hanya memakai file itu, sehingga server yang
sama tidak juga ditemukan dari proyek dan didaftarkan dua kali.

Titik periksa: minta klien menampilkan daftar alatnya. Anda semestinya melihat
entri `mcp__*` yang mencakup tiket, space, memori, graf kode, dan tinjauan.

## Layani MCP di luar host

1. Di **Pengaturan → Server → Server MCP**, pada baris **Token autentikasi**,
   tekan **Atur** dan tempelkan token
2. Kirimkan sebagai `Authorization: Bearer <token>` pada setiap permintaan
   `POST /mcp`

Permukaan tanpa token menolak setiap pemanggil non-loopback dengan 403. Itu
memang fail-closed menurut desainnya: token itulah yang membuat layanan di luar
host mungkin sama sekali.

Perubahan token langsung berlaku pada permukaan yang aktif — tanpa mulai ulang.

:::note[`GET /sse` menerima token di string kueri]
Aliran notifikasi diperiksa tokennya seperti setiap rute lain, tetapi `EventSource`
peramban tidak dapat mengirim header `Authorization` — jadi `/sse` juga menerima
token sebagai `?token=<token>`. Tanpa token, ia menjawab 401.
:::

## Batasi setiap panggilan ke satu ruang kerja

Setiap alat yang menyentuh data bercakupan ruang kerja mewajibkan `workspace_id`
dan panggilan tanpanya ditolak, bukan diselesaikan terhadap semacam ruang kerja
"saat ini":

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

Id itu adalah id yang ada di peramban atau URL aplikasi Anda:
`/workspaces/<workspace_id>/…`. Satu-satunya pengecualian adalah alat yang
memang mencakup banyak ruang kerja, seperti `list_workspaces` dan alat umpan
berita — umpan berita bersifat per pengguna dan agen tidak punya pengguna
sendiri, sehingga alat-alat itu beroperasi pada feed milik pemilik server.

Alat bercakupan repo juga memeriksa bahwa repo tersebut ditautkan ke ruang kerja
itu.

## Ketahui apa yang akan ditolak permukaan

- **Gerbang mode.** Sebuah panggilan diselesaikan terhadap mode space agen
  pemanggilnya, di sisi server. Agen dalam mode hanya baca tidak dapat mencapai
  alat tulis dengan menghilangkan `space_id` — modenya dicari dari run aktifnya
  sebagai gantinya.
- **Pagar pengaman tindakan.** Alat yang mengubah keadaan mendeklarasikan kelas
  efeknya dan melewati kebijakan yang sama dengan yang dipakai seluruh produk
  lainnya. Lihat
  [Konfigurasi pagar pengaman](/id-ID/panduan-pengguna/panduan-praktis/konfigurasi-pagar-pengaman/).
- **Konfirmasi.** Sebagian alat destruktif menyusun muatan konfirmasi yang harus
  disetujui sebelum panggilan berlanjut.

Katalog lengkapnya diumumkan di `tools/list` tanpa gerbang penemuan — klien MCP
eksternal menolak memanggil alat yang tidak ada dalam daftar cache-nya, jadi
menyembunyikan alat justru merusaknya alih-alih merapikannya.

## Pemecahan masalah

### Klien tidak melihat alat apa pun

- Periksa kartu **Server MCP** menyatakan berjalan
- Periksa portnya cocok dengan port `cc_server` Anda
- Pada Claude Code, periksa Anda sudah memberikan `--mcp-config` dan
  `--strict-mcp-config`

### 403 dari mesin yang bukan server

Tidak ada token bearer yang dikonfigurasi. Tetapkan satu dan kirimkan.

### Panggilan alat gagal dengan "Missing or invalid argument: workspace_id"

Tambahkan `workspace_id`. Tidak ada ruang kerja implisit.

### Panggilan alat ditolak sebagai tidak dikenal

[Alat MCP](/id-ID/panduan-pengguna/referensi/alat-mcp/) mencantumkan katalognya.
Panggil namanya persis seperti yang tertera di sana.
