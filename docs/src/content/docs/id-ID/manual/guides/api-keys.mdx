Panduan ini menunjukkan kepada Anda di mana setiap kredensial yang digunakan
Control Center disimpan dan cara mengubahnya.

**Tidak ada yang disimpan di mesin yang Anda pakai untuk mengetik.** Setiap
kredensial berada di server; kredensial mana yang menjawab suatu permintaan
bergantung pada apakah ada manusia di baliknya.

| Kredensial                           | Disimpan                                                  | Siapa yang memakainya                                            |
| ------------------------------------ | --------------------------------------------------------- | ---------------------------------------------------------------- |
| Proses masuk host kode / tiket Anda  | Berkas rahasia 0600 milik server, dikunci berdasarkan id pengguna Anda | Apa pun yang Anda lakukan: permukaan PR, tinjauan, merge, tindakan Linear Anda |
| Aplikasi penyedia milik server       | Berkas yang sama, ditambah `server_settings` untuk bagian yang bukan rahasia | Menandatangani orang masuk, dan token satu-repositori untuk agen, pipeline, dan polling |
| Kunci instalasi Connect              | Berkas yang sama (`connect_install_key`)                  | Mengidentifikasi server ini kepada Control Center Connect        |
| Kunci penyedia model dan token OAuth | Penyimpanan kredensial milik server sendiri               | Adapter bawaan, untuk setiap ruang kerja pada instalasi          |
| Kredensial bot Slack                 | `<dataDir>/<workspaceId>/chat_credentials/` di server     | Jembatan chat untuk ruang kerja tersebut: token app Anda sendiri, atau hibah tersegel dari app bersama |
| Kredensial CLI eksternal             | Apa pun yang digunakan CLI tersebut                       | Claude Code, di host server                                      |

## GitHub: proses masuk Anda, dan token satu-repositori

- **Milik Anda**, dari **Masuk ke GitHub**. Inilah yang dipakai setiap permintaan yang
  dibuat *atas nama Anda*, sehingga ulasan yang dikirim untuk Anda membawa nama Anda.
  Anggota lain tidak dapat memakainya, dan mereka masuk sendiri. Tidak ada token GitHub
  untuk ditempel
- **Pekerjaan tanpa orang mengetik** (agen, pipeline, polling, balasan bot) menerima token
  untuk satu repositori dalam satu waktu, dicetak dari GitHub App server atau melalui
  Control Center Connect, dan dibatasi pada apa yang dapat dilakukan anggota yang
  bertanggung jawab di sana. Itu tidak pernah proses masuk Anda yang diserahkan utuh

Milik Anda diatur di kartu **Hosting kode** pada **Pengaturan → Ruang kerja → Profil &
identitas**; aplikasi server di **Aplikasi penyedia** pada **Pengaturan → Server → Single
sign-on**. Lihat [Siapkan integrasi GitHub](/id-ID/panduan-pengguna/panduan-praktis/integrasi-github/)
dan [Buat GitHub App](/id-ID/panduan-pengguna/panduan-praktis/github-app/).

GitLab dan Bitbucket masih menerima token pribadi yang ditempel, disimpan dengan cara yang
sama. Lihat [Hubungkan host kode](/id-ID/panduan-pengguna/panduan-praktis/hubungkan-host-kode/).

:::note[Ada juga layar yang hanya bisa diakses lewat URL]
`/workspaces/<workspaceId>/api-keys` menampilkan dua kartu yang sama seperti
langkah pertama onboarding. Layar ini **tidak punya entri navigasi di mana pun
dalam UI**; hanya bisa dicapai dengan mengetik URL-nya. Gunakan Pengaturan →
Ruang kerja → Profil & identitas sebagai gantinya.
:::

## Tetapkan kunci penyedia model

Adapter bawaan mengautentikasi penyedia sendiri dan kredensial tersebut berada
di server.

1. Buka **Pengaturan → Server → Penyedia model**
2. Gulir ke **Penyedia & model**
3. Hubungkan penyedianya — OAuth browser untuk OpenAI, Codex, Cursor, dan Kimi
   Code; kunci API untuk Anthropic dan sisanya

Lihat [Kelola adapter dan model](/id-ID/panduan-pengguna/panduan-praktis/adapter/) untuk daftar lengkapnya dan
untuk menambahkan endpoint kustom.

Kredensial ini **global per host**: satu kunci melayani setiap ruang kerja pada
instalasi. Token OAuth disegarkan sebelum kedaluwarsa.

CLI adapter eksternal menyimpan kredensialnya sendiri, di konfigurasinya sendiri,
di host server — Control Center tidak mengelolanya. Autentikasi Claude Code
sesuai yang dijelaskan dokumentasinya sendiri, di mesin tempat `cc_server`
berjalan.

Dialog **Variabel lingkungan** per adapter tampak seperti tempat menaruh kunci
untuk salah satunya, tetapi bukan: dialog itu menulis ke perangkat Anda,
sementara server membaca salinannya sendiri dan tidak ada yang menjembatani
keduanya. Lihat
[Kelola adapter dan model](/id-ID/panduan-pengguna/panduan-praktis/adapter/).

## Hubungkan vendor tiket

Kartu **Tiket** pada **Pengaturan → Ruang kerja → Umum** memuat kedua bagian
dari satu keputusan: di mana tiket Anda berada, dan siapa Control Center saat
berbicara dengannya. Memilih **Lokal** menyembunyikan baris Linear — tiket lokal
berada di basis data server ini sendiri dan tidak ada yang perlu diautentikasi.

Linear memiliki dua proses masuk dan tanpa kunci yang ditempel: **Linear** adalah milik
Anda, untuk apa yang Anda lakukan, dan **Otomatisasi Linear** adalah app Control Center
milik ruang kerja, dihubungkan oleh admin, untuk sinkronisasi tiket, pipeline, dan agen.
Server juga dapat menyimpan **Kunci API layanan** (**Aplikasi penyedia**) untuk ruang kerja
yang belum menghubungkan otomatisasi. Tidak ada kredensial tiket yang disuntikkan ke sandbox
agen; agen menulis tiket melalui alat Control Center, yang menanyakan aturan **Tulis ke
pelacak eksternal**. Lihat [Siapkan integrasi Linear](/id-ID/panduan-pengguna/panduan-praktis/integrasi-linear/).

## Rotasi atau cabut

- **Proses masuk GitHub Anda**: tekan **Putuskan**, lalu **Masuk ke GitHub** lagi.
  Memutuskan juga membatalkan setiap token yang dicetak server atas nama Anda
- **Token GitLab atau Bitbucket**: tekan **Perbarui token** dan tempel yang baru, lalu
  cabut yang lama di host kode
- **Aplikasi server**: buat kunci privat atau client secret baru di halaman penyedia
  aplikasi tersebut, tempel di **Aplikasi penyedia** dan tekan **Tes**
- **Kunci instalasi Connect**: **Rotasi kunci** pada kartu **Control Center Connect**, atau
  `cc_server connect rotate-key --yes`. Semua orang yang masuk melalui Connect harus masuk
  lagi. Lihat [Control Center Connect](/id-ID/panduan-pengguna/referensi/connect/)
- **Penyedia model**: pada barisnya, keluar (OAuth) atau hapus kuncinya, lalu
  hubungkan lagi
- **Slack**: untuk app Anda sendiri, tempel ulang token di dialog koneksi. App Slack bersama
  milik Control Center tidak memiliki token untuk dirotasi: token bot-nya diperbarui melalui
  Connect, dan **Putuskan** mencabutnya serta menghapus bot dari Slack. Lihat
  [Siapkan integrasi Slack](/id-ID/panduan-pengguna/panduan-praktis/integrasi-slack/)

## Pemecahan masalah

### Token GitLab atau Bitbucket berfungsi di `curl` tetapi tidak di sini

Periksa subjudul baris **Hosting kode**. Jika menyebut "dari environment", kredensial yang
menjawab adalah milik server, bukan milik Anda — milik Anda tidak tersimpan.

### Token GitLab atau Bitbucket diterima tetapi permintaan berikutnya gagal

Token diuji sebagaimana disimpannya, sehingga barisnya menyebut akun di baliknya
— tetapi hanya akunnya, bukan scope-nya. Token dengan scope terlalu sedikit
berhasil terhubung lalu gagal pada permintaan individual. Periksa scope dan masa
berlakunya di host kode.

### Penyedia menyatakan proses masuk belum disiapkan di server ini

Server tidak memiliki aplikasinya sendiri untuk penyedia itu maupun Control Center Connect.
Pemilik server memilih salah satunya di **Pengaturan → Server → Single sign-on**.
