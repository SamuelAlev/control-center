Panduan ini menunjukkan cara mendapatkan rencana terstruktur dari agen sebelum agen
itu menulis kode apa pun.

Dalam mode rencana, agen melakukan riset secara hanya-baca dan satu-satunya hasil
kerjanya adalah **rencana bertipe**: graf dependensi berisi langkah-langkah yang
Anda setujui, yang kemudian dikompilasi Control Center menjadi pekerjaan nyata.
Gunakan saat Anda ingin melihat cakupan sebuah perubahan, melihat langkah-langkahnya
terurai, atau mengetahui risiko dan dependensi sebelum ada yang disentuh.

## Alihkan sebuah space ke mode rencana

Salah satu dari tindakan berikut mengubah mode space dan perubahannya disimpan:

- Pilih **Plan** dari dropdown mode di ujung kiri bilah alat penyusun pesan
- Tekan **Shift+Tab**
- Kirim `/plan`. `/plan` saja hanya menyiapkan mode; `/plan <request>` menyiapkannya
  dan mengirim sisanya sebagai pesan Anda

`/plan` tidak pernah dikirim sebagai teks — perintah itu menetapkan mode tersimpan,
yang menjadi acuan permukaan alat, preset pagar pengaman, dan prompt. Jadi mode itu
berlaku untuk giliran ini dan setiap giliran setelahnya, sampai Anda mengubahnya
kembali.

Mode disimpan pada space, sehingga agen yang sama dapat berada dalam mode rencana di
sini dan dalam mode agen di tempat lain.

## Apa yang dihasilkan agen

1. Agen melakukan riset secara hanya-baca — memori, indeks kode, berkas
2. Agen memanggil `submit_plan` **satu kali**, dengan sebuah `goal` plus `nodes`,
   yang masing-masing membawa `key` yang stabil, `title`, `description`, dan key node
   yang menjadi `dependsOn`-nya (inilah yang memungkinkan pekerjaan independen
   berjalan secara paralel)
3. Agen berhenti

Alat ini memvalidasi graf tersebut — key duplikat, dependensi menggantung, siklus —
dan mengembalikan pelanggarannya agar diperbaiki oleh agen alih-alih menerima
rencana yang rusak.

Rencana muncul **di dalam percakapan** sebagai baris ringkas yang menampilkan tujuan,
statusnya, dan jumlah langkah. **Plan Studio** — graf dependensi, inspektur per node,
dan estimasi biaya — terbuka sebagai tab di samping percakapan: tekan **Buka** pada
baris itu, atau cukup tunggu, karena rencana yang tiba dalam 30 detik saat Anda
sedang mengamati percakapan akan membuka tabnya sendiri.

:::note[Jaminan hanya-baca bersifat struktural, tetapi hanya pada harness bawaan]
Harness milik Control Center sendiri membangun registri alat agen dari spesifikasi
permukaan mode rencana, sehingga memang tidak ada alat tulis, edit, atau perintah
yang dapat dipanggil — pembatasan itu bukan instruksi prompt yang bisa diloloskan
model dengan dalih apa pun.

Adapter Claude Code tidak mendapat penyaringan seperti itu: mode sampai ke sana
sebagai permintaan yang mungkin dipatuhi atau tidak oleh runner-nya sendiri, dan
Control Center hanya melihat panggilan `mcp__*`-nya. Lencana penegakan di samping
dropdown mode muncul tepat ketika hal itu terjadi.
:::

:::note[Agen dapat mengajukan pertanyaan klarifikasi kepada Anda]
Saat permintaan ambigu, agen mode rencana dapat berhenti sejenak dan mengajukan
hingga tiga pertanyaan yang memblokir dengan alat `ask_user`. Alat itu merender
formulir di percakapan — opsi, atau teks bebas — dan run terblokir sampai Anda
menjawab. Alat tersebut berada di tingkat baca, sehingga tetap bertahan di permukaan
hanya-baca mode rencana, dan dibebaskan dari pembungkus persetujuan (gerbang di
depan sebuah prompt akan gagal secara tertutup saat tidak ada penyetuju yang
terhubung, sehingga agen tidak diizinkan melakukan tindakan bertanya).

Alat itu memerlukan space untuk merendernya, sehingga pengiriman one-shot tanpa
percakapan tidak mendapatkannya. Menaruh cakupan, repo target, dan kriteria
penerimaan di awal pesan pertama Anda tetap lebih cepat daripada satu kali
bolak-balik.
:::

Prosa bukanlah hasil kerja di sini. Run yang berakhir tanpa memanggil `submit_plan`
memasang baris "Ended without submitting a plan (no `submit_plan` call)." yang
terlihat di percakapan dan menandai run tersebut sebagai tidak menyerahkan hasil
kerjanya. Status run sengaja tetap _completed_ — itu menjaga mesin status pipeline
dan tiket tetap utuh — jadi bacalah baris itu, bukan lencana statusnya.

## Setujui rencana

Dari baris rencana di percakapan, tekan **Setujui dan jalankan**. Dari bilah
persetujuan Plan Studio, tekan **Setujui rencana** (atau **Tolak** di sebelahnya;
persetujuan dinonaktifkan selama graf memiliki galat validasi).

Lalu:

1. Control Center mengompilasi rencana menjadi sebuah orkestrasi dan mewujudkannya —
   tiket dan run-nya. Tidak ada model yang terlibat dalam langkah ini; langkah ini
   deterministik
2. Rencana dieksekusi sebagai agen yang menulisnya. Apakah akan melibatkan pihak lain
   adalah keputusan agen itu saat berjalan — agen dapat `delegate_task` sebuah langkah
   kepada rekan setim yang lebih cocok, dalam batas kedalaman delegasi ruang kerja
3. Tujuan rencana menjadi **tujuan percakapan** dan pekerjaannya berjalan **di
   percakapan yang sama**: setiap langkah memasang apa yang diminta kepada agen dan
   menyiarkan gilirannya kembali, sehingga Anda mengikutinya (dan dapat menghentikan
   sebuah giliran) dari tempat Anda sudah berada
4. Baris tujuan di panel samping **Umum** percakapan (di bawah Todo) memuat kemajuan
   run sebagai `settled/total` beserta tombol berhentinya; Plan Studio menampilkan
   status per node pada graf dan juga dapat membatalkan dari sana

## Terus bekerja tanpa menyetujui

Jika Anda lebih memilih tetap berada di percakapan ini daripada menyetujui rencana,
agen dapat memanggil `exit_plan_mode`. Itulah satu-satunya jalan keluar yang
disahkan: perintah itu membuka permintaan persetujuan yang tahan lama yang tertaut ke
percakapan dan mengembalikan `pending` — space tetap dalam mode rencana dan agen
tidak boleh bertindak. Setelah permintaan itu disetujui, panggilan `exit_plan_mode`
berikutnya dari agen mengalihkan space dari mode rencana ke mode agen dan membuka
alat-alat pemutasinya. Penolakan memungkinkan agen membuka permintaan baru untuk
rencana yang direvisi.

Untuk keluar dari mode rencana, alihkan dropdown penyusun pesan (atau Shift+Tab),
atau setujui rencana yang diajukan. `exit_plan_mode` membuka persetujuan yang tahan
lama yang diputuskan dengan alat MCP `decide_approval`. Overlay pagar pengaman untuk
panggilan alat yang diblokir adalah antrean di memori yang berbeda dan tidak membawa
permintaan keluar dari mode rencana.

## Mode rencana dalam langkah pipeline

Node pipeline `messaging.createSpace` membaca mode percakapan dari **extra** `mode`
pada konfigurasi node — `extras['mode']: 'plan'`. Key tersebut harus cocok persis:
ejaan lain apa pun, termasuk `conversationMode` atau `dispatchMode`, diabaikan
diam-diam dan ruangan itu kembali ke default bodinya, yaitu mode **tinjauan**, bukan
chat. Langkah `promptAgent` bergabung ke ruangan yang tidak dibuatnya dan tidak
mengubah izinnya. Pemilih **Mode dispatch** di editor konfigurasi node (`allParallel`
/ `manager`) adalah untuk node pengiriman tim. Tetapkan mode percakapan dengan
`extras['mode']` pada templat yang membuka space, atau pada konfigurasi node tersebut
melalui API.
