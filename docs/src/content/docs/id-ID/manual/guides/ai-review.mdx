Panduan ini menunjukkan cara membuat agen peninjau meninjau sebuah pull request
dan cara memublikasikan hasilnya ke GitHub.

## Mulai tinjauan AI

1. Buka PR dan buka tab **Ikhtisar**-nya
2. Buka menu tambahan ⋯ di baris tindakan dan pilih **Tanya AI**

Item ini hanya muncul selama PR masih terbuka — ini tindakan sebelum
penggabungan. Tombol yang sama ditawarkan sebagai **Tanya AI** pada keadaan
kosong tab **Tinjau**, sebelum ada tinjauan apa pun.

Control Center memulai pipeline `pr_review` bawaan dan membuka tab **Tinjau**
milik PR agar Anda dapat memantaunya. Pipeline tersebut:

1. Membuka space tinjauan milik PR, yang worktree terisolasinya memuat PR dalam
   keadaan checkout pada head-nya
2. Menyebar para peninjau sesuai tingkat tinjauan ruang kerja — tiga secara
   bawaan (agen bawaan **qa**, **architect**, dan **engineer**, secara paralel).
   Tidak ada deteksi bahasa atau domain
3. Menyuruh agen pemimpin (CEO) mengonsolidasikan temuan mereka menjadi
   penelusuran terpandu
4. Menyelesaikan: mengelompokkan temuan ke dalam wadah konsensus dan menghitung
   putusan. Saat asosiasi mencapai `awaiting approval`, **Publikasikan ke
   GitHub** muncul di tab Tinjau

Seberapa dalam tinjauan berjalan ditentukan oleh **tingkat tinjauan** ruang
kerja — `light` (satu peninjau), `balanced` (tiga, bawaan), atau `thorough`
(kelima-limanya, menambahkan spesialis keamanan dan performa) — yang diatur di
**Pengaturan → Ruang kerja → Umum**, pada kartu **Kebijakan ruang kerja**.
Tingkat yang lebih ringan mencatat temuan sebanyak yang sama; ia melaporkan
lebih sedikit di antaranya secara menonjol.

Semua peninjau memposting ke satu space tinjauan milik PR, dan itulah yang
membuat temuan mereka dapat dibandingkan. Lihat
[Tinjauan AI](/id-ID/panduan-pengguna/konsep/tinjauan-ai/) tentang bagaimana
bagian-bagiannya saling terkait.

`pr_review` hanya dilengkapi pemicu manual. Agar pemicunya menyala pada setiap
PR yang dipublikasikan, tambahkan pemicu sendiri — lihat
[Kirim agen peninjau](/id-ID/panduan-pengguna/panduan-praktis/kirim-agen-peninjau/). Anda juga dapat
memulainya dari GitHub sendiri, tanpa perlu pemicu pipeline: sebut bot server
pada PR atau tambahkan label `ai-review` — lihat
[Bicara ke Control Center dari PR GitHub](/id-ID/panduan-pengguna/panduan-praktis/percakapan-pr-github/).

Jika ada notifikasi yang menyatakan tinjauan sudah berjalan untuk pull request
ini, berarti satu tinjauan sedang berlangsung; tetap di tab **Tinjau** atau buka
**Pipeline** untuk menemukannya.

## Baca temuan

Para peninjau mencatat temuan sebagai **node tinjauan** di space tinjauan.
Setiap node membawa:

| Bidang          | Deskripsi                                                     |
| -------------- | ------------------------------------------------------------- |
| Jenis          | `bug`, `suggestion`, `recommendation`, `question`, atau `ticket` |
| Prioritas      | P0 (kritis) → P3 (sepele)                                     |
| Kategori       | `security`, `stability`, `data_integrity`, `correctness`, `performance`, atau `maintainability` |
| File dan baris | Tempat temuan di-anchor                                       |
| Kode asli      | Kode yang menjadi pokok temuan                                |
| Kode yang disarankan | Perbaikan yang diusulkan                                |
| Keyakinan      | Seberapa yakin peninjau                                       |
| Status         | `open` → `consensus-ready` → `resolved` atau `dismissed`      |

Sebuah temuan hanya mencapai **consensus-ready** setelah peninjau _rekan_
mengonfirmasinya. Agen tidak dapat mengonfirmasi temuannya sendiri, jadi
pendapat satu peninjau tidak pernah naik kelas dengan sendirinya.

Tab **Tinjau** menampilkan daftar temuan, yang dapat difilter menurut jenis dan
status, dengan tombol alih untuk temuan yang ditutup, di samping artefak yang
dipublikasikan agen pengonsolidasi. Tampilan deterministik — kohort, dasbor
multi-sumbu, serta diff kontrak dan visual — dihitung di sisi server tetapi
tidak memiliki permukaan di aplikasi; lihat
[Komputasi tinjauan](/id-ID/panduan-pengguna/panduan-praktis/komputasi-tinjauan/) untuk mengetahui apa
yang dihasilkan proses tersebut.

## Periksa panel ketidaksepakatan

Ketika dua peninjau me-anchor temuan ke file dan baris yang sama tetapi
menilainya sangat berbeda — prioritas yang terpaut dua tingkat atau lebih, atau
satu menyebutnya `bug` sementara yang lain menyebutnya `suggestion` — panel
ketidaksepakatan muncul di atas daftar temuan. Baca itu lebih dahulu: di sanalah
pendapat para peninjau menyimpang dan penilaian Anda paling bernilai.

## Baca putusan

Saat agen pemimpin menyelesaikan, ia menghitung sebuah **putusan**:

| Putusan   | Arti                                         |
| --------- | -------------------------------------------- |
| **Ship**  | Tidak ada temuan yang menghambat             |
| **Hold**  | Masalah yang harus ditangani sebelum penggabungan |
| **Block** | Masalah kritis yang harus diperbaiki         |

Putusan ini membawa skor keyakinan agregat dan jumlah temuan per prioritas.

Sumbu-sumbu tinjauan kemudian dilipat ke dalamnya dan hanya dapat membuatnya
**lebih** berat. Sumbu bergerbang yang gagal memaksa **Block**; sumbu bergerbang
yang tidak dapat diselesaikan (`partial`) atau tidak dapat dijalankan sama sekali
(`unavailable`) memaksa setidaknya **Hold**. Tidak adanya bukti tidak pernah
membuka gerbang.

## Publikasikan tinjauan ke GitHub

Publikasi adalah langkah terpisah yang sengaja dijaga oleh pengguna. Pipeline
`pr_review` menyimpan tinjauan di Control Center; ia tidak mempostingnya ke
GitHub.

1. Di tab **Tinjau**, tunggu hingga **Publikasikan ke GitHub** muncul
2. Tekan **Publikasikan ke GitHub**

Control Center mengirim **satu** tinjauan GitHub. Temuan yang sudah diselesaikan
atau ditutup dilewati. Tombol ini menyertakan setiap temuan terbuka yang tersisa
dan, pada **Ship**, mengirimkan `APPROVE`. (Alat MCP `publish_review_to_github`
masih hanya menggunakan temuan yang dikonfirmasi rekan secara bawaan dan tidak
menyetujui kecuali Anda meneruskan `approve_on_ship`.) Temuan yang membawa anchor
file dan baris menjadi komentar inline; sisanya dilipat ke badan ringkasan,
masing-masing dengan footer "— Control Center AI review" agar sumbernya tidak
ambigu. Putusan **Block** dikirim sebagai `REQUEST_CHANGES`; **Hold** sebagai
`COMMENT`; **Ship** sebagai `APPROVE` dari tombol ini. Sebuah notifikasi kemudian
menampilkan **Dipublikasikan**. Tinjauan diposting dengan identitas aplikasi
milik server.

Jika GitHub menolak anchor inline karena barisnya bukan bagian dari diff,
seluruh tinjauan dikirim ulang dengan setiap temuan dilipat ke badan, sehingga
tidak ada yang hilang diam-diam.

:::caution[Publikasi dijaga oleh pagar pengaman]
`pr_review.publishReview` mendeklarasikan kelas tindakan `prPublish` dan berjalan
melalui titik pengunci pagar pengaman. Jika keputusan yang dihasilkan adalah
`prompt` dan tidak ada pemberi persetujuan yang terhubung, publikasi ditolak —
pagar pengaman gagal tertutup. Tetapkan aturan eksplisit di
Pengaturan → Ruang kerja → Izin agen jika Anda ingin ini berjalan tanpa
pengawasan.
:::

Pipeline bawaan lainnya memang memposting langsung ke GitHub: `cross_review`,
`pr_triage`, `ticket_to_pr`, dan `pre_merge_gate` masing-masing diakhiri dengan
langkah komentar. Hanya `pr_review` yang menahan keluarannya untuk Anda.

## Kirim peninjau sendiri

Untuk mengendalikan peran mana yang meninjau PR dan file mana yang dilihat
masing-masing peran, gunakan alat MCP `dispatch_reviewers` di dalam space
tinjauan yang sudah ada, atau tambahkan node peninjau ke pipeline. Kedua jalur
tersebut, beserta tanda tangan persis alatnya, ada di
[Kirim agen peninjau](/id-ID/panduan-pengguna/panduan-praktis/kirim-agen-peninjau/).
