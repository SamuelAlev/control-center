## Yang akan Anda bangun

Pada akhir tutorial ini, Anda sudah:

- Membuka pull request di workbench PR Control Center
- Membaca diff-nya dan meninggalkan komentar sebaris
- Mengirim verdikt tinjauan
- Menggabungkan PR

Prasyarat: [Kirim agen pertama Anda](/id-ID/panduan-pengguna/tutorial/agen-pertama/) sudah selesai dan ada satu pull request terbuka di repo yang terdaftar di ruang kerja ini. Untuk langkah-langkah tinjauan, pilih PR yang bukan Anda buka — tombol **Tinjau** disembunyikan pada PR Anda sendiri. Penggabungan tetap berfungsi pada PR yang Anda buat sendiri.

## Langkah 1: Buka pull request

1. Klik **Pull requests** di bilah sisi
2. Temukan PR Anda dan klik

**Pos pemeriksaan.** PR terbuka sebagai workbench bertab — Ikhtisar, Diff, Kontrol sumber, Chat, Tindakan — dengan fokus pada **Ikhtisar**: judul dan tindakannya, deskripsi dan linimasa aktivitas, serta bilah sisi berisi status, peninjau, penerima tugas, pemeriksaan, dan file yang berubah. Mengklik sebuah file di sana akan melompat ke file itu di tab Diff. Tab **PR review** tidak terbuka sampai seseorang meminta tinjauan AI.

:::note[Antrean kosong dengan perintah "hubungkan GitHub"]
Keadaan itu berarti _server_ tidak menyimpan token GitHub — klien Anda tidak pernah menyimpannya. Atur token di **Pengaturan → Ruang kerja → Profil & identitas → Hosting kode**, lalu muat ulang daftarnya.
:::

## Langkah 2: Baca diff

Buka tab **Diff**. Pohon file yang dapat dilipat berada di sebelah kiri, dan bilah di atas diff memuat pemilih rentang commit — persempit diff ke satu commit atau beberapa commit sekaligus — plus jumlah file serta penambahan dan penghapusan yang sedang berjalan.

Tombol pengaturan di bilah alat diff mengatur cara diff dirender:

- Tampilan **Terpisah** atau **Terpadu**
- **Bungkus baris** atau gulir baris panjang
- **Ligatur font kode**

Tandai sebuah file sebagai sudah dilihat untuk melacak kemajuan Anda pada diff yang besar. Navigasi keyboard ada di [Pintasan keyboard](/id-ID/panduan-pengguna/referensi/pintasan-keyboard/).

## Langkah 3: Tinggalkan komentar sebaris

1. Arahkan kursor ke sebuah baris di diff — pil `+` kecil muncul di gutter
2. Klik pil itu untuk mengomentari baris tersebut, atau seret dulu ke arah vertikal untuk memilih rentang
3. Ketik masukan Anda. Composer menawarkan dua cara mengirim:
   - **Mulai tinjauan** (atau **Tambahkan ke tinjauan** jika sudah ada tinjauan yang berjalan) mengantrekan komentar. Utas menampilkan **Menunggu tinjauan** sampai Anda mengirim verdikt di langkah 4.
   - **Tambahkan komentar tunggal** langsung mempostingnya ke GitHub. Utas menampilkan **Memposting…**, lalu **Disinkronkan**, dan menawarkan coba lagi jika postingan gagal.

Untuk tutorial ini, gunakan **Mulai tinjauan** agar komentarnya ikut terkirim bersama verdikt.

:::caution[Komentar yang diantrekan belum ada di GitHub]
**Mulai tinjauan** / **Tambahkan ke tinjauan** menahan komentar secara lokal sampai Anda mengirim verdikt. Hanya **Tambahkan komentar tunggal** yang langsung memposting. _Isi_ tinjauan yang Anda tulis di langkah 4 adalah draf terpisah.
:::

## Langkah 4: Kirim tinjauan

1. Klik **Tinjau** di baris tindakan Ikhtisar — tombol yang sama juga ada di bilah alat tab Diff. Tombol ini disembunyikan pada PR yang Anda buat sendiri serta pada PR yang ditutup atau digabungkan.
2. Tulis ringkasan di composer. Isinya tersimpan otomatis sebagai draf, jadi Anda bisa menutup overlay dan kembali lagi.
3. Pilih verdikt:
   - **Minta perubahan**
   - **Komentar**
   - **Setujui**

Verdiktnya adalah tombolnya. Setelah **Setujui** atau **Minta perubahan**, tombol itu mengganti labelnya menjadi **Disetujui** atau **Perubahan diminta**. Verdikt **Komentar** membiarkan tombolnya berlabel **Tinjau**.

**Pos pemeriksaan.** Tombolnya bertuliskan "Disetujui" atau "Perubahan diminta" jika Anda memilih salah satu dari keduanya.

## Langkah 5: Gabungkan

Tombol **Gabungkan** ada setiap kali GitHub melaporkan bahwa PR dapat digabungkan — tombol ini tidak dibatasi oleh persetujuan Anda sendiri. Warnanya melaporkan kesiapan, bukan izin: primer saat persetujuan yang diwajibkan dan pemeriksaan sudah hijau, sekunder saat masih ada pemeriksaan yang berjalan, destruktif saat peninjau yang diminta belum menyetujui atau ada pemeriksaan yang gagal.

1. Klik **Gabungkan**
2. Pilih metode: **Squash dan gabungkan**, **Buat commit merge**, atau **Rebase dan gabungkan**
3. Untuk dua metode pertama, edit judul dan pesan commit yang telah diisi sebelumnya
4. Konfirmasi

Masalah apa pun yang belum terselesaikan — "Pemeriksaan gagal", "Beberapa tinjauan masih tertunda" — dicantumkan di flyout sebelum Anda mengonfirmasi.

:::caution[Menggabungkan tidak dapat dibatalkan]
Menggabungkan akan mendorong commit ke GitHub. Tindakan ini tidak pernah masuk ke tumpukan urungkan Control Center dan tidak dapat dibatalkan dari sini.
:::

Setelah digabungkan, peristiwa domain `PrMerged` dipicu; analitik dan notifikasi mengonsumsinya. Lihat [Peristiwa domain](/id-ID/panduan-pengguna/referensi/peristiwa-domain/) untuk mengetahui apa lagi yang mendengarkannya.

## Meninjau dengan AI

Control Center dapat menempatkan pipeline peninjau pada PR yang terbuka, tetapi hanya saat Anda memintanya: templat `pr_review` hanya punya pemicu manual dan tidak ada yang lain.

1. Buka menu **Tindakan lainnya** di baris tindakan Ikhtisar dan pilih **Tanya AI**. Control Center memulai run dan membuka tab **PR review**, sehingga Anda dapat menyaksikan para spesialis bekerja.
2. Agen peninjau mencatat temuannya sebagai node tinjauan di space PR tersebut; langkah terakhir menggabungkannya menjadi satu laporan.

Pipeline ini sengaja tidak memposting ke GitHub — pipeline berakhir setelah menggabungkan temuan. Publikasi adalah langkah terpisah yang Anda lakukan sendiri, dengan tombol **Publikasikan ke GitHub** di tab **PR review**. Lihat [Gunakan tinjauan bertenaga AI](/id-ID/panduan-pengguna/panduan-praktis/tinjauan-ai/).

## Rekap

Anda membuka PR di workbench, membaca diff dengan penyorotan sintaks, meninggalkan komentar sebaris, mengirim verdikt, dan menggabungkan — tanpa meninggalkan aplikasi.

**Berikutnya:** [Bangun pipeline pertama Anda](/id-ID/panduan-pengguna/tutorial/pipeline-pertama/) untuk mengotomatiskan alur kerja multi-langkah.
