`cc_server` hostí jeden registr nástrojů MCP (JSON-RPC 2.0), vystavený na hlavním portu serveru (výchozí `9030`) na `POST /mcp` a `GET /sse`, verze protokolu `2024-11-05`. Ke stejnému registru se dostane každý klient: desktop, webové sestavení, externí klienti MCP i vestavěný runtime agenta. Externí servery MCP se dají přemostit do stejného registru jako dynamická vrstva.

## Velikost registru

| Ukazatel                                                                          | Počet |
| --------------------------------------------------------------------------------- | ----- |
| Nástroje registrované `cc_server`                                                 | 110   |
| Z `packages/cc_mcp`                                                               | 108   |
| Z `packages/cc_mcp_client` (objevování nástrojů)                                  | 2     |
| Registrované v základním registru (`server_mcp_registry.dart`)                    | 63    |
| Registrované po startu, jak jejich služby nabíhají (`cc_server_runtime.dart`)     | 47    |
| Z 63 v základním registru podmíněné repozitářem grafu kódu                        | 5     |

Těch pět nástrojů grafu kódu se registruje jen tehdy, když hostitel předá `buildServerMcpRegistry` repozitář grafu kódu. `cc_server` ho předává vždy, takže v dodávané binárce je živých všech 110.

Celý registr se v `tools/list` nabízí bez brány objevování. Úpravy ticketů jsou typované nástroje.

:::note[Externí klienti vždy vidí celý katalog]
`tools/list` se nikdy neořezává. Klienti MCP ověřují jména nástrojů proti vlastní kopii toho seznamu v cache a cokoliv, co v něm není, odmítnou, aniž by se serveru zeptali, takže nástroj skrytý tam je nedosažitelný, ne jen tichý.

**Vestavěný harness** je jiný: na každý požadavek načte jen rezidentní podmnožinu definic a zbytek dotáhne při prvním použití. Je to chování na straně harnessu a tenhle registr se tím nemění. Viz [Kontext nástrojů a cache promptů](/cs-CZ/prirucka/koncepty/kontext-nastroju/).
:::

:::note[Každá třída nástroje je registrovaná]
Soubor pod `packages/cc_mcp/lib/src/tools/` je nástroj, který agent umí
zavolat. `packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart`
shodí build, když novou třídu nástroje nic nekonstruuje.
:::

## Společné parametry

### `workspace_id`

**Povinné** u každého nástroje, který sahá na data vázaná na pracovní prostor. Chybějící nebo neplatné `workspace_id` vrátí výslovnou chybu a hodnota, která nesedí na pracovní prostor cílové entity, se odmítne, místo aby se tiše ignorovala. Vynech ho u nástrojů, které jsou opravdu globální: `list_workspaces` a šest nástrojů kanálu novinek (`list_feeds`, `list_articles`, `get_article`, `set_article_read`, `set_article_saved`, `refresh_feeds`), které jedou po seznamu kanálů vlastníka serveru, zvlášť pro každého uživatele. Nástroje objevování (`search_tool_bm25`, `list_my_tools`) ho berou volitelně, aby uměly klasifikovat volatelnost podle režimu konverzace. Když agenta odešle server, pracovní prostor se vynutí na straně serveru, takže se agent do jiného pracovního prostoru nedostane tím, že předá cizí id.

## Objevování nástrojů

Oba pocházejí z `cc_mcp_client`, ne z `cc_mcp`, a oba se radí s bránou režimu, takže hlásí, co je volatelné v _aktuálním_ režimu konverzace.

| Nástroj            | Popis                                                                                                                           |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| `search_tool_bm25` | Prohledá katalog nástrojů podle klíčových slov; vrátí shodné nástroje, jejich schémata argumentů a to, jestli je každý právě teď volatelný |
| `list_my_tools`    | Vypíše nástroje volatelné právě teď v téhle konverzaci, filtrované jejím režimem                                                |

Třetí nástroj objevování, **`search_tools`**, existuje jen uvnitř vestavěného harnessu a do tohohle registru MCP nepatří. Řadí vlastní plochu nástrojů běhu a na rozdíl od `search_tool_bm25` **načte** schémata toho, co najde, takže agent může shodu zavolat v dalším tahu. Agenti na harnessu mají dát přednost jemu; klienti MCP mají `search_tool_bm25`.

## Nástroje izolace (stanice)

Řídí jednorázové stroje — uzavřený prohlížeč nebo linuxový desktop, emulátor
Androidu, nebo iOS Simulator — zevnitř běhu. Registrují se po startu,
bezpodmínečně: jestli stroj opravdu naběhne, je otázka sondy, na kterou
nástroje odpovídají u každého volání. Opakovaná volání v jedné konverzaci
znovu použijí jeden stroj; snímky obrazovky se vracejí jako obrazový obsah
s rozpočtem jednoho obrázku na výsledek a vytažený obsah stránky nebo
rozhraní je ohrazený jako nedůvěryhodná data. Čtyři use nástroje plus
`rig_close` deklarují `enclosureControl` [třídu akcí](/cs-CZ/prirucka/koncepty/guardraily/)
(use nástroje deklarují taky `networkEgress` a `processSpawn`; `mobile_use` a
`ios_use` deklarují taky `packageInstall`), takže režimy jen pro čtení je
odmítnou. `rig_list` nedeklaruje žádnou — jen čte stav pracovního prostoru.
Úplný slovník sloves po plochách je v
[referenci stanic](/cs-CZ/prirucka/referencni-prirucka/stanice/#slovesa-akcí).

| Nástroj        | Popis                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------- |
| `computer_use` | Řídí linuxový desktop v uzavřeném VM: pohyb, klik, tažení, posun, psaní, změna velikosti, schránka, snímek obrazovky |
| `browser_use`  | Řídí headless Chromium, Firefox nebo WebKit (`engine`): navigace, klik, vyplnění, extrakce (a11y/DOM/konzole), schránka, snímek obrazovky |
| `mobile_use`   | Řídí Android přes ADB: inspekce a vstup, snímky obrazovky, instalace, start, stop, reset a odinstalace aplikací, deep linky a příkazy zařízení ve tvaru argv |
| `ios_use`      | Řídí iOS Simulator přes WebDriverAgent/CoreSimulator: inspekce a vstup, snímky obrazovky, instalace, start, stop a odinstalace aplikací, deep linky a procesy simulátoru ve tvaru argv |
| `rig_list`     | Vypíše stanice pracovního prostoru s plochou, stavem, velikostí displeje a řadičem |
| `rig_close`    | Zničí stanici a zahodí stav stroje, který vlastní |

## Přes MCP se nevystavuje

Kalendář a schůzky nemají nástroje MCP. Agenti nemohou číst tvůj kalendář, schůzky, přepisy, akční položky ani rozhodnutí. Shrnutí, ze kterého vzniknou akční položky a rozhodnutí, běží jako vestavěná [pipeline `meeting_summary`](/cs-CZ/prirucka/koncepty/schuzky/), ne jako nástroj, který agent může zavolat.

| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`        | Každý registrovaný nástroj; žádný seznam povolených                                                                                                                                                                                 |
| `plan`        | Sestavený seznam povolených. Žádné zápisy do worktree a žádná slovesa ticketů `create` / `assign` / `delegate`, ale paměť, artefakty, úkoly, `submit_plan`, `exit_plan_mode` a slovesa dokončení ticketu na odeslaném ticketu jsou povolená |
| `review`      | Sestavený seznam povolených: účast na kontrole, komunikace, načítání kontextu jen pro čtení a celá sada sloves ticketů včetně `create_ticket` a `assign_ticket`                                                                     |
| `orchestrate` | Sestavený seznam povolených: nástroje na výzkum a čtení plus `propose_orchestration`, `create_playbook` a `run_playbook`. Nábor, rozklad a dokončení ticketu proběhnou deterministicky po schválení, nikdy uprostřed běhu             |

Povolené v každém režimu bez ohledu na seznam povolených:

| Sada                 | Nástroje                                                                                                                                                                                                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Paměť a artefakty    | `search_memory`, `propose_fact`, `propose_policy`, `supersede_fact`, `supersede_policy`, `record_observation`, `update_my_notes`, `get_my_notes`, `list_memory_domains`, `list_policies`, `publish_artifact`, `revise_artifact`, `list_artifacts`, `get_artifact` |
| Graf kódu            | `search_code`, `code_symbol`, `code_callers`, `code_callees`, `code_impact`                                                                                                                                                                                       |
| Mechanika běhu       | `search_tool_bm25`, `list_my_tools`, `todo_write`, `todo_read`                                                                                                                                                                                                    |

To, že nástroj je na seznamu povolených, ho ještě neudělá volatelným, a platí to i naopak: schopnost zeptat se operátora je nástroj **harnessu** (`ask_user`), takže se v tomhle katalogu MCP vůbec neobjeví.

## Nástroje za schválením

Nástroj smí deklarovat `requiresApproval`. Dispečer pak sestaví `ApprovalPayload` a vystaví ho přes `ConfirmationPort` ještě před během nástroje; `cc_server` ten port zapojí, takže brána je živá.

Registrované nástroje, které to deklarují: `create_ticket`, `update_ticket`, `assign_ticket`, `reassign_ticket`, `close_ticket`, `ticket_relation`, `create_goal`, `update_goal_progress`, `create_approval`, `decide_approval`, `comment_approval`, `create_work_product`, `save_work_product_revision`, `create_runtime_profile`, `install_skill`, `update_skill`.

Nezávisle na tom sjednocené guardraily akcí brání každý nástroj, který deklaruje neprázdnou množinu `ActionClass`. Rozhodnutí `prompt` bez připojeného schvalovatele se odmítne. Viz [Guardraily](/cs-CZ/prirucka/koncepty/guardraily/).

## Schopnosti, za kterými není nástroj

Ne každá schopnost v produktu je pro agenta dosažitelná. Tyhle nemají nástroj
vůbec, takže jméno, které jsi mohl vidět jinde, vrátí „unknown tool“:

| Schopnost                              | Kde žije místo toho                                                                              |
| -------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Nabírání, propouštění nebo úprava agenta | Rozhraní agentů. Nástroj `hire_agent` / `fire_agent` / `update_agent` není                       |
| Vytvoření pracovního prostoru          | `workspace.upsert` přes RPC, které pracovní prostor založí a orazítkuje vlastnictví              |
| Projekty (založení / výpis / úprava / zařazení) | Rozhraní ticketů. Projekty jsou plocha operátora — viz [Projekty](/cs-CZ/prirucka/navody/projekty/) |
| Blokující otázka operátorovi           | Nástroj **harnessu** `ask_user`, ne MCP. Vykreslí formulář v konverzaci a čeká na odpověď        |
| Diagnostika po agentech                | Nic. `doctor` není — viz [Diagnostikujte agenta](/cs-CZ/prirucka/navody/diagnostika-agenta/)     |
| Kalendář a schůzky                     | RPC jen pro lidské klienty (viz výše)                                                            |
