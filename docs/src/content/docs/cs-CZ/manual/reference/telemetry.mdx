Control Center umí odesílat **pseudonymní události o používání** do instance [Umami](https://umami.is). Analytika používání je **vypnutá, dokud ji provozovatel serveru nezapne**. Nastavení patří serveru a platí pro každého klienta, který je k němu připojený: desktopovou aplikaci, webovou aplikaci, telefon i samotný server.

Analytika používání je oddělená od **Sdílet hlášení pádů**, což je nastavení pro každé zařízení zvlášť a týká se diagnostiky pádů a chyb.

## Kdo rozhoduje

| Přepínač | Kde | Účinek |
| --- | --- | --- |
| **Sdílet analytiku používání** | Úvodní nastavení (krok sandboxu) a **Nastavení → Soukromí**. Změnit ho může jen provozovatel serveru; ostatní členové vidí aktuální hodnotu jen pro čtení | Pro celý server. Uloženo jako `telemetry.usage_analytics` v nastavení serveru. Vypnuto, dokud není nastaveno na `true` |
| Typ sestavení | Automaticky | Sestavení debug a profile nic neodesílají. Každou událost místo toho zapíšou do debug logu |
| `CC_ANALYTICS_DEBUG=1` | Prostředí `cc_server` nebo jeho `.env` | Kvůli testování umožní sestavením debug a profile serveru i všech k němu připojených klientů skutečně odesílat. Přepínač výše musí být i tak zapnutý |
| `DO_NOT_TRACK=1` | Prostředí `cc_server` | Zastaví vlastní hlášení serveru bez ohledu na přepínač. Klienti se přepínačem řídí dál |
| Demo server | Automaticky | Veřejný demo server sám nic neodesílá. Návštěvníci přepínač změnit nemůžou |

Klienti čtou nastavení ze serveru (`telemetry.config`, potom průběžně přes `telemetry.watch`). Než odpověď dorazí, čekají události v malé vyrovnávací paměti v RAM. Pokud je odpověď záporná, vyrovnávací paměť se zahodí. Vypnutí přepínače okamžitě na všech klientech zahodí vše, co ještě čeká ve frontě, a odesílání zastaví.

## Co se nikdy neodesílá

- Obsah zpráv, ticketů, review a schůzek, názvy, prompty, příkazy shellu a vyhledávací dotazy
- Jména, loginy, e-mailové adresy, avatary a zobrazovaná jména
- Cesty k souborům, názvy repozitářů, názvy větví, názvy hostitelů a URL (repozitář se odesílá jen jako pseudonymní `repo_id`, odkaz na schůzku jen jako jeho poskytovatel)
- Nezpracované identifikátory jakéhokoli druhu

Každá událost před opuštěním procesu projde politikou vlastností. Text, cesty, URL, e-mailové adresy, nepseudonymizovaná ID a řetězce pod klíči jako `email`, `*_name`, `path`, `title`, `prompt`, `content` nebo `token` se místo odeslání zahodí. Řetězec se odešle jen tehdy, když je to krátký token z uzavřeného slovníku, například hodnota výčtu, verze, národní prostředí nebo ID modelu.

## Pseudonymní ID

ID se odesílají, ale jen jako pseudonymy. Každé ID pracovního prostoru, prostoru, konverzace, agenta, běhu, uživatele a zařízení se nahradí hodnotou HMAC-SHA256 s vlastní tajnou solí instalace (`telemetry.pseudonym_salt`), zkrácenou na 20 hexadecimálních znaků. Stejný pracovní prostor hlásí vždy stejnou hodnotu, takže jde události spojovat a počítat, ale nezpracované ID instalaci nikdy neopustí. Sůl vzniká při prvním spuštění serveru a poskytovateli analytiky se nikdy neodesílá. Smazáním datového adresáře serveru vznikne nová sůl i nové ID instalace, čímž se odpojí vše, co bylo zaznamenáno dřív.

## Zobrazení obrazovek

Každá navigace zaznamená zobrazení stránky, jehož URL je **šablona trasy**, například `/workspaces/:workspaceId/spaces/:spaceId`, nikdy konkrétní adresa. Název obrazovky tvoří pevné segmenty šablony, takže v příkladu je to `workspaces_spaces`. Parametry trasy končící na `Id` se připojí jako pseudonymní vlastnosti `*_id` a číselné (třeba číslo PR) jako čísla. Všechny ostatní parametry se zahodí.

## Doručování

Události se odesílají po jedné na `<host>/api/send` z fronty v paměti s kapacitou až 200 událostí. Při chybě sítě, vypršení časového limitu, `429` nebo `5xx` se událost ponechá a zkouší se znovu s exponenciálním odstupem od 1 sekundy až po 5 minut. Jakákoli jiná odpověď `4xx` ji zahodí. Nic se nezapisuje na disk, takže události, které jsou při ukončení aplikace ještě ve frontě, se ztratí. Fronta se vyprázdní, když aplikace přejde na pozadí a když se server vypíná.

## Nasměrování sestavení na jinou instanci

Cíl se pevně určuje při sestavení:

```bash
--dart-define=CC_ANALYTICS_HOST=https://analytics.example.com/
--dart-define=CC_ANALYTICS_WEBSITE_ID=<website uuid>
```

Adaptér poskytovatele je v `packages/cc_analytics`. Podpora jiné analytické služby znamená přidat tam adaptér. Plán sledování i pravidla ochrany soukromí zůstávají stejné.
