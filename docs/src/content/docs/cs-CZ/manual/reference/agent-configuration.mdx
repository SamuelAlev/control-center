Tahle stránka vypisuje všechna pole entity agenta a enumy a příznaky, se kterými pracuje. Jak agenta v aplikaci krok za krokem založit nebo upravit, popisuje [Vytvořte a nakonfigurujte agenta](/cs-CZ/prirucka/navody/vytvoreni-agenta/).

## Oprávnění

Agent nemá žádné příznaky oprávnění. Push, otevírání a zveřejňování pull requestů, zápis do trackeru a odchozí síťový provoz jsou třídy akcí (`gitPush`, `prCreate`, `prPublish`, `vendorSyncWrite`, `networkEgress`), které [guardraily](/cs-CZ/prirucka/koncepty/guardraily/) vyhodnocují v rozsahu pracovního prostoru, agenta nebo prostoru. Token GitHub běhu má vždycky rozsah jen pro čtení; pushe jdou přes bránu běhů agentů, která se před předáním dál zeptá pravidla `gitPush`.

## AgentSkills

Neměnná množina identifikátorů skillů bez rozlišení velikosti písmen. Při odeslání se tyhle slugy synchronizují jako odkazy na skilly v overlay agenta a harness pak do promptu automaticky načte frontmatter nalinkovaných skillů.

## Shell hooky

Shell hooky umožňují vlastníkovi serveru spouštět vlastní skripty kolem běhu agenta: jednou při startu relace, před každým voláním nástroje, po každém volání nástroje, když by agent chtěl ukončit svůj tah, a před kompakcí. Hook je libovolný kód, takže jsou součástí konfigurace hostitele. Nastavuje je jen vlastník serveru ručně, na stroji serveru. V aplikaci pro ně není žádné nastavení a žádná operace je nezapisuje.

Hooky agenta leží v jeho vlastní složce v datovém adresáři serveru:

```text
<data dir>/_agent_hooks/<workspace id>/<agent slug>/hooks.json
```

`<agent slug>` je název složky agenta v pracovním prostoru (`agents/<slug>/`). Tato složka leží mimo úložiště každého pracovního prostoru a každý sandbox skrývá datový adresář, takže ji nemůže zapsat žádný člen, běh ani terminál.

`hooks.json` mapuje kterýkoli z pěti klíčů na skript podle cesty relativní vůči složce hooků:

| Klíč           | Kdy běží                       | Co znamená její návratový kód                                  |
| -------------- | ------------------------------ | -------------------------------------------------------------- |
| `sessionStart` | Jednou, na začátku běhu        | Nic; hook jen pozoruje                                         |
| `preTool`      | Před každým voláním nástroje   | `0` volání povolí; cokoli jiného ho zamítne                    |
| `postTool`     | Po každém volání nástroje      | Nic; hook jen pozoruje                                         |
| `stop` | Když by agent chtěl ukončit svůj tah | `2` s textem na stdout udrží běh v chodu s tímto textem; cokoli jiného nechá tah skončit |
| `preCompact` | Před kompakcí | `0`: jeho stdout se přidá k tomu, co má souhrn zachovat |

- Každý skript se spouští jako samostatný spustitelný soubor, bez shellu a bez argumentů, takže musí být spustitelný a začínat řádkem shebang. Událost dostane jako JSON na stdin: název události a u hooků nástrojů název nástroje s jeho argumenty (`preTool`), nebo jeho výsledek (`postTool`).
- Hook běží jako jeden z procesů nástrojů běhu, v adresáři agenta pro daný běh. Když server spouští agenty v sandboxu, běží uvnitř sandboxu běhu. Dostane minimální prostředí a žádné přihlašovací údaje běhu: žádný token hostingu kódu ani poskytovatele a žádný přístup k bráně.
- Každý hook má 30 sekund. Výstup `sessionStart`, `preTool` a `postTool` se přečte a zahodí.
- `preTool` selhává zavřeně. Nenulový návratový kód, vypršení času nebo skript, který nejde spustit, volání nástroje zamítne.
- Cesta, která je absolutní, chybí, nebo vede ven ze složky hooků (odkazy se rozbalí), se odmítne a log běhu napíše, který hook byl odmítnut a proč. Odmítnutý nebo nečitelný hook `preTool` zamítá každé volání nástroje, dokud se neopraví.
- Blok `hooks` v `.agents/harness.json` se ignoruje, ať je v repozitáři, nebo ve vlastní složce agenta. Repozitář bývá často cizí kód a do složky agenta můžou zapisovat členové i běhy. Log běhu napíše, že blok byl ignorován, a kde se hooky místo toho čtou.

### Hooky stop a preCompact

- `stop` dostane `event: "stop"`, poslední zprávu agenta (`last_message`), `stop_hook_active` (true, když toto zastavení následuje po pokračování, které hook vyvolal) a `block_count` (kolikrát dosud běh udržel v chodu, od 0). Aby běh udržel v chodu, skončí s `2` a vypíše, co má agent udělat dál. Text, zkrácený na 2 000 znaků, dorazí agentovi jako systémová zpráva.
- Hook `stop` udrží běh v chodu nejvýš 3krát v jednom běhu. Potom se už nespustí znovu a tah skončí.
- `stop` selhává otevřeně. Vypršení časového limitu, skript, který nejde spustit, jakýkoli ukončovací kód jiný než `2`, nebo `2` s prázdným stdout nechá tah skončit, takže rozbitý hook nemůže držet běh otevřený.
- `preCompact` dostane `event: "pre_compact"`. Jeho stdout, zkrácený na 1 000 znaků, se přidá k zaměření kompakce. Skript, který selže, nepřidá nic.

Shell hooky platí pro vestavěný harness. Na Claude Code běží také hooky `stop` a `preCompact`: vlastní hooky Claude Code `Stop` a `PreCompact` se ptají serveru a server spustí skripty vlastníka stejným způsobem. Ostatní tři klíče platí jen pro vestavěný harness. Nastavený hook `preTool` nebo `postTool` způsobí, že běh volá své nástroje jeden po druhém.

## AgentLiveState (odvozený)

Neukládá se. Sedm hodnot. Pořadí deklarace je pořadí priority (`sortPriority`, zafixované testem) a podle něj se řadí soupiska:

| Stav        | `sortPriority` | Podmínka                                                                                                            |
| ----------- | -------------- | ------------------------------------------------------------------------------------------------------------------- |
| `running`   | 0              | Libovolný záznam běhu má stav `running`                                                                             |
| `blocked`   | 1              | Liveness posledního běhu je `blocked`, `stalled` nebo `looping`                                                     |
| `failed`    | 2              | Stav posledního běhu je `error`, nebo je jeho liveness `failed` či `dead`                                           |
| `queued`    | 3              | Běh je odeslaný, ale ještě neběží: čeká za jiným během téhož agenta, nebo je zapsaný a ještě se nespustil           |
| `succeeded` | 4              | Běh úspěšně skončil                                                                                                 |
| `idle`      | 5              | Agent už dřív běžel a nic nemá rozběhnuté                                                                           |
| `neverRun`  | 6              | Neexistuje žádný záznam běhu                                                                                        |

`queued` a `succeeded` platí **jen pro jeden běh**. `deriveAgentLiveState`, které pro agenta počítá stav soupisky, ani jedno z nich nikdy nevrátí: vrací `neverRun`, `running`, `failed`, `blocked` nebo `idle`.
