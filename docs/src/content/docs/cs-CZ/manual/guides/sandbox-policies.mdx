Jestli běh agenta běží v sandboxu, rozhoduje se na serveru při startu
(`--sandbox`). Přepínač **Zapnout sandboxing**, výběr **Backend** a
přepínače **Výchozí schopnosti · nové prostory** v **Nastavení → Server →
Diagnostika a soukromí** jsou preference uložené na tvém zařízení. Detekce
hostitele na kartě **Sandboxing** hlásí, co umí obalit hostitel serveru.

K běhu sahají dva ovládací prvky a tenhle návod pokrývá oba: **Oprávnění
sandboxu** u agenta níže a vlastní příznak `--sandbox` serveru.

## Co omezuje běh agenta

Agenta drží šest věcí. První je sandbox operačního systému a ta je
podmíněná — zbylých pět drží na každém hostiteli.

| Hranice                  | Co dělá                                                                                                                                                                            |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sandbox operačního systému | Seatbelt na macOS, bubblewrap na Linuxu a na WSL2. Obalí CLI Claude Code, adaptéry ACP a nástroj `bash` harnessu. **Chybí na Windows a na Linuxu bez `bwrap` a `socat`** |
| Vlastní worktree         | Každá konverzace dostane copy-on-write checkout. Původní checkout se do běhu vloží jako cesta se zákazem zápisu a vynucuje to sandbox                                              |
| Pověření od brokera      | Broker přihlašovacích údajů vystaví prostředí pro daný běh ze schopností agenta a při úklidu ho odebere. Žádná schopnost, žádný token v prostředí                                  |
| Guardraily akcí          | Každý mutující nástroj deklaruje své třídy efektů a strážce je vyhodnotí, než se volání spustí. `prompt` bez připojeného schvalovatele se odmítne                                 |
| Očištění prostředí       | ACP a nástroj `bash` harnessu dostanou filtrované prostředí. Claude Code přes `NoSandboxAdapter` dědí prostředí hostitele                                                         |
| Plocha nástrojů režimu   | Režim jen pro čtení sundá nástroje, které mění worktree, a připne vlastní výstupní sloveso režimu, aby pořád uměl doručit                                                         |

Tři věci jsou slabší, než vypadají:

- Jen **vestavěný harness** vynucuje bránu nástrojů, kontrakty dokončení a
  strukturální pravidla režimu. Adaptér Claude Code ne. Claude
  Code se navíc spouští s `--dangerously-skip-permissions`, protože
  neinteraktivní `claude -p` by jinak navždy čekalo na vlastní výzvu —
  takže vlastní volání Claude na čtení, zápis, úpravy a bash Control Center
  ani nevidí, ani nehlídá. Kde je sandbox zapnutý, je hranicí kolem nich.
- Souborové nástroje harnessu v procesu (read, write, edit, apply patch, search,
  find, search_files) běží uvnitř procesu serveru, takže je neomezuje žádný profil sandboxu.
  Sandboxovaným runnerem příkazů projde jen nástroj `bash`. Ty nástroje
  omezuje jejich vlastní omezení cest a k tomu guardraily akcí.
- Na hostiteli bez backendu první řádek neplatí vůbec. ACP a
  nástroj `bash` harnessu spadnou na očištění prostředí a politiku
  příkazů; Claude Code dědí prostředí hostitele přes `NoSandboxAdapter`.
  Server to řekne ve startovacím logu. Svůj si zkontroluj níže.

## Nastav schopnosti agenta

Tohle je jediný ovládací prvek schopností, který server čte. Je na agenta a
rozhoduje, co broker přihlašovacích údajů vloží do prostředí toho agenta.

1. Jdi do **Nastavení → Pracovní prostor → Agenti**
2. V soupisce vyber agenta
3. Na kartě **Nastavení** sjeď k **Oprávnění sandboxu**
4. Zapni přepínač — popisek řádku se změní z **Použít výchozí pracovního prostoru**
5. Nastav čtyři přepínače:

| Přepínač                         | Co hlídá                                                                                                                                                                                                                                |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Povolit git push**             | Když je vypnutý, běh dostane `GIT_ASKPASS=/usr/bin/false` a `GIT_TERMINAL_PROMPT=0`, takže push si nemůže vyžádat přihlašovací údaj                                                                                                     |
| **Povolit volání GitHub API**    | Spolu s **Povolit git push** rozhoduje, jestli broker vloží token GitHub jako `GH_TOKEN` / `GITHUB_TOKEN`                                                                                                                               |
| **Povolit volání ticketing API** | Rozhoduje, jestli broker vloží `TICKETING_API_KEY`                                                                                                                                                                                      |
| **Povolit obecný přístup k síti** | Kde je sandbox zapnutý, je to skutečná brána odchozího provozu: když je vypnutý, seznam povolených běhu je prázdný a každé odchozí spojení proxy odmítne. Kde backend není, zapíše se to na běh, ale nezablokuje nic, co udělá spuštěný proces |

6. Ulož

Kontrolní bod: otevři agenta znovu a přepínač je pořád zapnutý s tvými
volbami — uložená sada schopností se přes server vrátí a agent, který žádnou
nemá, spadne na konzervativní výchozí stav (push vypnutý, GitHub API vypnuté,
ticketing vypnutý, síť zapnutá).

:::caution[Dvě pasti]
Popisek říká **Použít výchozí pracovního prostoru**, ale žádné nastavení
schopností na úrovni pracovního prostoru server nečte. Agent s vypnutým
přepínačem dostane vestavěný konzervativní výchozí stav.

Zvlášť: přihlašovací údaj GitHubu u běhu je vždycky jen ten od brokera —
token instalace GitHub App vázaný na repozitář, nebo záložní PAT z prostředí —
nikdy vlastní uložený token člena, který o běh požádal. `actingUserId` se
předává, aby broker mohl *odepřít* PAT serveru členovi, který není vlastník a
nemá připojený GitHub; nesloží osobní token přes schopnost, která je vypnutá.
**Povolit volání GitHub API** neber jako tvrdou hranici odchozího provozu
na hostiteli bez sandboxu operačního systému: spuštěný proces se k síti pořád
dostane.
:::

## Zkontroluj, jestli jsou běhy agenta v sandboxu

Rozhodují o tom dvě věci, obě na serveru: jestli hostitel nabízí backend a
jestli je `--sandbox` zapnutý. Zkontroluj je v tomhle pořadí.

1. Jdi do **Nastavení → Server → Diagnostika a soukromí**
2. Přečti kartu **Sandboxing**. Údaj **Hostitel** je stroj, na kterém běží
   `cc_server`, ne stroj, na který se díváš. Pole **Backend** uvádí
   **Nativní sandbox** (Seatbelt na macOS, bubblewrap na Linuxu a na WSL2) nebo
   **Bez izolace**. Údaj **V platnosti** je preference tohohle zařízení, ne
   obal, který server skutečně používá.
3. Přečti startovací log serveru. Vypíše přesně jeden ze tří řádků:
   - `agent sandbox ON` plus poznámka k backendu — běhy jsou obalené
   - `no OS-native agent sandbox on this host` plus nápověda k instalaci, kde
     nějaká je — běhy obalené nejsou
   - `agent sandbox DISABLED by --sandbox off` — záměrné vypnutí

`GET /healthz` stav sandboxu nehlásí, takže kontrolou je startovací log.

Sandbox vypneš schválně — existuje proto, že na některém hostiteli se profil
chová špatně — tak, že server spustíš s `--sandbox off`, nebo nastavíš
`CC_SERVER_SANDBOX=off`. Výchozí hodnota je `on` a `on` znamená „použij
backend, když ho hostitel má“, nikdy „vyžaduj ho“.

Nativní obal sandboxu ve dvou situacích nevznikne vůbec. Na **Windows** nativní
sonda vždycky hlásí, že není k dispozici, a není co instalovat — odeslání
agenta používá `none`. Backend `microvm` je zvlášť (interaktivní terminály a
stanice) a pouští ho vlastní sonda podle jeho runtime. Na **Linuxu a WSL2**
musí být na `PATH` jak `bwrap`, tak `socat`; bez nich sonda hlásí, že není
k dispozici, a pojmenuje chybějící balíčky.

Na Linuxu a WSL2 s nainstalovaným bubblewrapem se globy tajných souborů
standardní politiky nedají vynutit u souborů, které agent vytvoří až později.
Takový nativní běh teď selže, místo aby pravidla potichu ignoroval. Kladná
sonda při startu proto nezaručí, že se odeslání na Linuxu umí rozběhnout.
`--sandbox off` je záměrné vypnutí bez omezení, ne náhradní bezpečnostní
hranice.

## Zjisti, co režim už zakazuje

Režim se ukládá na prostor a do vyhodnocovače guardrailů vstupuje jako vrstva
**Předvolba režimu**. Tři ze čtyř režimů jsou jen pro čtení a režim jen pro
čtení odmítne jedenáct tříd efektů rovnou:

| Režim               | Worktree         | Co předvolba odmítá                                                                                                                                                                                                                     |
| ------------------- | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Agent** (`chat`)  | Zapisovatelný    | Nic — platí vestavěné výchozí hodnoty                                                                                                                                                                                                   |
| **Plán**            | Jen pro čtení    | Smazat soubor, zápis mimo worktree, vytvořit commit, odeslat na remote, otevřít pull request, zveřejnit kontrolu nebo sloučení, zápis do externího trackeru, nainstalovat balíček, spustit proces, změnit strukturu pracovního prostoru, ovládat izolované prostředí (stanici) |
| **Kontrola**        | Jen pro čtení    | Stejných jedenáct. Nejde vybrat — composer nabízí jen Agent, Plán a Orchestraci                                                                                                                                                        |
| **Orchestrace**     | Jen pro čtení    | Stejných jedenáct                                                                                                                                                                                                                       |

Přístup k síti a čtení tajemství režim jen pro čtení schválně _neodmítá_:
výzkum je jeho smysl.

## Vyžaduj schválení, než akce proběhne

Schválení je rozhodnutí guardrailu, ne nastavení sandboxu.

1. Jdi do **Nastavení → Pracovní prostor → Oprávnění agentů**
2. Nastav třídu akce na **Nejdřív se zeptat** v rozsahu pracovního prostoru, agenta nebo prostoru

Rozhodnutí **Nejdřív se zeptat** běh přeruší a zeptá se tě. Když není
připojený schvalovatel, selže uzavřeně a akce se odmítne. Celé pořadí
vyhodnocení je v
[Nastavte guardraily](/cs-CZ/prirucka/navody/nastaveni-guardrailu/).

## Řešení problémů

### Agent nemůže pushnout a já jsem to nezakázal

Zkontroluj **Oprávnění sandboxu** agenta. Agent bez vlastní sady schopností
dostane konzervativní výchozí stav, ve kterém je **Povolit git push** vypnutý —
broker tedy nevloží token GitHub a git se nemá čím ověřit.

### Karta Sandboxing nehlásí nativní sandbox

Pak běhy agenta na tom hostiteli neobaluje Seatbelt ani bubblewrap a zbývající
hranice jsou to, co máš. Na Linuxu a na WSL2 nainstaluj oba chybějící
nástroje — `sudo apt-get install bubblewrap socat` — a restartuj server;
startovací log by pak měl říct, že je sandbox zapnutý. Na Windows není nativní
backend k instalaci, takže místo toho utáhni guardraily: viz
[Nastavte guardraily](/cs-CZ/prirucka/navody/nastaveni-guardrailu/).

### Agent se dostal k souboru mimo svůj worktree

Jestli je to očekávané, rozhoduje, který nástroj se k němu dostal.

Souborové nástroje harnessu v procesu (read, write, edit, apply patch, search,
find, search_files) běží v procesu serveru, takže se na ně žádný profil
sandboxu nevztahuje — jejich mez je vlastní omezení cest a k tomu guardraily.
Příkaz `bash` nebo CLI Claude Code se _obaluje_ tam, kde backend existuje, a
tvoje registrované checkouty jsou uvnitř toho obalu v každém režimu se zákazem
zápisu, včetně zápisů po rozřešení symlinku (na macOS se cesta dosažená přes
`/tmp` nebo `/var/folders` rozřeší pod `/private` a oba zápisy se teď odmítají).
Na hostiteli bez backendu nic z toho neplatí. V obou případech umí guardraily
rovnou odmítnout **Zápis mimo worktree**.
