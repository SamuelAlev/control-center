Tenhle návod ukazuje, kde leží každý přihlašovací údaj, který Control Center
používá, a jak ho změnit.

**Na stroji, na kterém píšeš, se neukládá nic.** Každý přihlašovací údaj leží
na serveru. Který z nich odpoví na daný požadavek, záleží na tom, jestli za ním
stojí člověk.

| Přihlašovací údaj                    | Uložení                                                   | Kdo ho používá                                                  |
| ------------------------------------ | --------------------------------------------------------- | ---------------------------------------------------------------- |
| Tvůj údaj k forge / ticketům         | Soubor tajemství serveru s právy 0600, klíčovaný tvým id uživatele | Všechno, o co požádáš: plocha PR, tvoje běhy agentů, tvoje obrázky |
| Identita aplikace serveru            | Tentýž soubor, plus `server_settings` pro netajné hodnoty | Práce, o kterou nikdo nepožádal: webhooky, dotazování na PR, synchronizace ticketů |
| Klíče poskytovatelů modelů a tokeny OAuth | Vlastní úložiště přihlašovacích údajů serveru        | Vestavěný adaptér, pro každý pracovní prostor na instalaci       |
| Tokeny bota Slack                    | `<dataDir>/<workspaceId>/chat_credentials/` na serveru    | Chatový most toho pracovního prostoru                            |
| Přihlašovací údaje externího CLI     | To, co používá dané CLI                                   | Claude Code, na hostiteli serveru                                |

## Dva přihlašovací údaje GitHubu a každý odpovídá na jinou otázku

- **Tvůj**, z přihlášení (device flow) nebo z vloženého tokenu. Ten použije každý
  požadavek *tvým jménem*, takže komentář odeslaný za tebe nese tvoje jméno.
  Jiný člen ho nepřečte a připojí si vlastní
- **Serverový**, z GitHub App, kterou zaregistroval operátor. Odpovídá na
  všechno, u čeho není volající, takže přístup k forge nezmizí, když někdo
  odejde nebo obmění token

Tvůj nastavíš na kartě **Hostování kódu** v **Nastavení → Pracovní prostor →
Profil a identita**; serverový v **Aplikace poskytovatelů** v **Nastavení →
Server → Jednotné přihlášení**. Viz
[Nastavte integraci GitHub](/cs-CZ/prirucka/navody/integrace-github/) a
[Vytvořte GitHub App](/cs-CZ/prirucka/navody/github-app/).

:::note[Je tu i obrazovka jen přes URL]
`/workspaces/<workspaceId>/api-keys` vykreslí tytéž dvě karty jako první krok
onboardingu. **V navigaci uživatelského rozhraní nikde položku nemá**; dostaneš
se na ni jen zadáním URL. Použij Nastavení → Pracovní prostor → Profil a identita.
:::

## Nastav klíče poskytovatelů modelů

Vestavěný adaptér se u poskytovatelů ověřuje sám a ty přihlašovací údaje leží
na serveru.

1. Jdi do **Nastavení → Server → Poskytovatelé modelů**
2. Sjeď k **Poskytovatelé a modely**
3. Připoj poskytovatele: OAuth v prohlížeči u OpenAI, Codex, Cursor a Kimi Code;
   API klíč u Anthropic a ostatních

Celý seznam a přidání vlastního endpointu jsou v
[Spravujte adaptéry a modely](/cs-CZ/prirucka/navody/adaptery/).

Tyhle přihlašovací údaje platí **pro celého hostitele**: jeden klíč obslouží
každý pracovní prostor na instalaci. Tokeny OAuth se obnoví dřív, než vyprší.

CLI externích adaptérů si drží vlastní přihlašovací údaje ve vlastní konfiguraci
na hostiteli serveru. Control Center je nespravuje. Claude Code ověř tak, jak
říká jeho dokumentace, na stroji, kde běží `cc_server`.

Dialog **Proměnné prostředí** u jednotlivých adaptérů vypadá jako místo, kam
klíč pro některé z nich vložíš, ale není. Zapisuje na tvoje zařízení, server
čte vlastní kopii a nic ty dvě nespojuje. Viz
[Spravujte adaptéry a modely](/cs-CZ/prirucka/navody/adaptery/).

## Připoj ticketovací službu

Karta **Ticketing** v **Nastavení → Pracovní prostor → Obecné** drží obě
poloviny jednoho rozhodnutí: ve které službě tickety žijí a jaký přihlašovací
údaj k ní patří. Když zvolíš **Místní**, řádek s údajem zmizí. Místní tickety
žijí v databázi tohoto serveru a není k čemu se ověřovat.

Tvůj klíč leží na serveru u tvého id uživatele, stejně jako ten k forge. Server
si vlastní klíč Linear drží zvlášť (**Aplikace poskytovatelů**). Na něm běží
synchronizace ticketů, když o ni nikdo nepožádal. Do sandboxu agenta se žádný
klíč ticketingu nevkládá; agenti zapisují tickety přes nástroje Control Center,
které se ptají pravidla **Zápis do externího trackeru**. Viz
[Nastavte integraci Linear](/cs-CZ/prirucka/navody/integrace-linear/).

## Obměň nebo odvolej

- **Tvůj přihlašovací údaj GitHubu**: stiskni **Odpojit**, pak se přihlas znovu
  nebo vlož nový token. Starý odvolej na GitHubu
- **Aplikace serveru**: na stránce aplikace na GitHubu vygeneruj nový soukromý
  klíč nebo client secret, vlož ho do **Aplikace poskytovatelů** a stiskni
  **Test**
- **Poskytovatel modelu**: na jeho řádku se odhlas (OAuth) nebo klíč odeber,
  pak se připoj znovu
- **Slack**: tokeny vlož znovu v dialogu připojení. Viz
  [Nastavte integraci Slack](/cs-CZ/prirucka/navody/integrace-slack/)

## Řešení problémů

### Seznam PR je prázdný, ale token mi v `curl` funguje

Podívej se na podtitul řádku **Hostování kódu**. Když jmenuje jiný zdroj
(„přes aplikaci tohoto serveru“, „z prostředí“), přihlašovací údaj, který
zkoušíš, není ten, který odpovídá. Tvůj se neuložil.

### Token projde, ale pozdější požadavky selžou

Token se ověřuje tak, jak je uložený, takže řádek pojmenuje účet za ním, ale
jen účet, ne scopes. Token s příliš úzkými scopes se připojí a pak selžou
jednotlivé požadavky. Zkontroluj scopes a platnost:

```bash
curl -H "Authorization: token YOUR_TOKEN" https://api.github.com/user
```
