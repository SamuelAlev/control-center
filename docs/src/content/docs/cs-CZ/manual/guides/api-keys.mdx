Tenhle návod ukazuje, kde leží každý přihlašovací údaj, který Control Center
používá, a jak ho změnit.

**Na stroji, na kterém píšeš, se neukládá nic.** Každý přihlašovací údaj leží
na serveru. Který z nich odpoví na daný požadavek, záleží na tom, jestli za ním
stojí člověk.

| Přihlašovací údaj                    | Uložení                                                   | Kdo ho používá                                                  |
| ------------------------------------ | --------------------------------------------------------- | ---------------------------------------------------------------- |
| Tvoje přihlášení k forge / ticketům | Soubor tajemství serveru s právy 0600, klíčovaný tvým id uživatele | Všechno, co děláš: plocha PR, revize, sloučení, tvoje akce v Linear |
| Aplikace poskytovatelů serveru       | Tentýž soubor, plus `server_settings` pro netajné hodnoty | Přihlašování lidí a tokeny pro jediný repozitář pro agenty, pipelines a dotazování |
| Instalační klíč Connect              | Tentýž soubor (`connect_install_key`)                    | Identifikace tohoto serveru vůči Control Center Connect          |
| Klíče poskytovatelů modelů a tokeny OAuth | Vlastní úložiště přihlašovacích údajů serveru        | Vestavěný adaptér, pro každý pracovní prostor na instalaci       |
| Pověření bota Slack                  | `<dataDir>/<workspaceId>/chat_credentials/` na serveru    | Chatový most toho pracovního prostoru: tokeny vlastní aplikace, nebo zapečetěný grant sdílené aplikace |
| Přihlašovací údaje externího CLI     | To, co používá dané CLI                                   | Claude Code, na hostiteli serveru                                |

## GitHub: tvoje přihlášení a tokeny pro jediný repozitář

- **Tvoje**, z **Přihlásit se k GitHub**. To použije každý požadavek *tvým
  jménem*, takže revize odeslaná za tebe nese tvoje jméno. Jiný člen ho použít
  nemůže a přihlásí se sám. Token GitHubu se nevkládá
- **Práce, u které nikdo nepíše** (agenti, pipelines, dotazování, odpovědi bota),
  dostane token vždy pro jeden repozitář, vydaný z GitHub App serveru nebo přes
  Control Center Connect a omezený na to, co tam smí odpovědný člen. Nikdy to
  není celé předané tvoje přihlášení

Tvoje nastavíš na kartě **Hostování kódu** v **Nastavení → Pracovní prostor →
Profil a identita**; aplikaci serveru v **Aplikace poskytovatelů** v **Nastavení →
Server → Jednotné přihlášení**. Viz
[Nastavte integraci GitHub](/cs-CZ/prirucka/navody/integrace-github/) a
[Vytvořte GitHub App](/cs-CZ/prirucka/navody/github-app/).

GitLab a Bitbucket pořád berou vložený osobní token, uložený stejným způsobem.
Viz [Připojte hostitele kódu](/cs-CZ/prirucka/navody/pripojeni-hostitele-kodu/).

:::note[Je tu i obrazovka jen přes URL]
`/workspaces/<workspaceId>/api-keys` vykreslí tytéž dvě karty jako první krok
onboardingu. **V navigaci uživatelského rozhraní nikde položku nemá**; dostaneš
se na ni jen zadáním URL. Použij Nastavení → Pracovní prostor → Profil a identita.
:::

## Nastav klíče poskytovatelů modelů

Vestavěný adaptér se u poskytovatelů ověřuje sám a ty přihlašovací údaje leží
na serveru.

1. Jdi do **Nastavení → Server → Poskytovatelé modelů**
2. Sjeď k **Poskytovatelé a modely**
3. Připoj poskytovatele: OAuth v prohlížeči u OpenAI, Codex, Cursor a Kimi Code;
   API klíč u Anthropic a ostatních

Celý seznam a přidání vlastního endpointu jsou v
[Spravujte adaptéry a modely](/cs-CZ/prirucka/navody/adaptery/).

Tyhle přihlašovací údaje platí **pro celého hostitele**: jeden klíč obslouží
každý pracovní prostor na instalaci. Tokeny OAuth se obnoví dřív, než vyprší.

CLI externích adaptérů si drží vlastní přihlašovací údaje ve vlastní konfiguraci
na hostiteli serveru. Control Center je nespravuje. Claude Code ověř tak, jak
říká jeho dokumentace, na stroji, kde běží `cc_server`.

Dialog **Proměnné prostředí** u jednotlivých adaptérů vypadá jako místo, kam
klíč pro některé z nich vložíš, ale není. Zapisuje na tvoje zařízení, server
čte vlastní kopii a nic ty dvě nespojuje. Viz
[Spravujte adaptéry a modely](/cs-CZ/prirucka/navody/adaptery/).

## Připoj ticketovací službu

Karta **Ticketing** v **Nastavení → Pracovní prostor → Obecné** drží obě
poloviny jednoho rozhodnutí: ve které službě tickety žijí a kým je Control
Center, když s ní mluví. Když zvolíš **Místní**, řádky Linear zmizí. Místní
tickety žijí v databázi tohoto serveru a není k čemu se ověřovat.

Linear má dvě přihlášení a žádný vkládaný klíč: **Linear** je tvoje, pro to, co
děláš ty, a **Automatizace Linear** je aplikace Control Center pracovního
prostoru, kterou připojí admin, pro synchronizaci ticketů, pipelines a agenty.
Server může navíc držet **Servisní klíč API** (**Aplikace poskytovatelů**) pro
pracovní prostory bez připojené automatizace. Do sandboxu agenta se žádné
pověření ticketingu nevkládá; agenti zapisují tickety přes nástroje Control
Center, které se ptají pravidla **Zápis do externího trackeru**. Viz
[Nastavte integraci Linear](/cs-CZ/prirucka/navody/integrace-linear/).

## Obměň nebo odvolej

- **Tvoje přihlášení ke GitHubu**: stiskni **Odpojit**, pak znovu **Přihlásit se
  k GitHub**. Odpojení zároveň zruší všechny tokeny, které server vydal tvým
  jménem
- **Token GitLabu nebo Bitbucketu**: stiskni **Aktualizovat token** a vlož nový,
  pak starý odvolej na forge
- **Aplikace serveru**: na stránce aplikace u poskytovatele vygeneruj nový
  soukromý klíč nebo client secret, vlož ho do **Aplikace poskytovatelů**
  a stiskni **Test**
- **Instalační klíč Connect**: **Vyměnit klíč** na kartě **Control Center
  Connect**, nebo `cc_server connect rotate-key --yes`. Každý, kdo se přihlásil
  přes Connect, se přihlásí znovu. Viz
  [Control Center Connect](/cs-CZ/prirucka/referencni-prirucka/connect/)
- **Poskytovatel modelu**: na jeho řádku se odhlas (OAuth) nebo klíč odeber,
  pak se připoj znovu
- **Slack**: u vlastní aplikace vlož tokeny znovu v dialogu připojení. Sdílená
  aplikace Control Center nemá token k obměně: její token bota se obnovuje přes
  Connect a **Odpojit** ho odvolá a bota ze Slacku odinstaluje. Viz
  [Nastavte integraci Slack](/cs-CZ/prirucka/navody/integrace-slack/)

## Řešení problémů

### Token GitLabu nebo Bitbucketu funguje v `curl`, ale tady ne

Podívej se na podtitul řádku **Hostování kódu**. Když v něm stojí „z prostředí“,
odpovídá přihlašovací údaj serveru, ne tvůj. Tvůj se neuložil.

### Token GitLabu nebo Bitbucketu projde, ale pozdější požadavky selžou

Token se ověřuje tak, jak je uložený, takže řádek pojmenuje účet za ním, ale
jen účet, ne scopes. Token s příliš úzkými scopes se připojí a pak selžou
jednotlivé požadavky. Zkontroluj jeho scopes a platnost na forge.

### Poskytovatel hlásí, že přihlášení na tomto serveru není nastavené

Server nemá pro daného poskytovatele vlastní aplikaci ani Control Center
Connect. Jedno z nich vybere vlastník serveru v **Nastavení → Server →
Jednotné přihlášení**.
