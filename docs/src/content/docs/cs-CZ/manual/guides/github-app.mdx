Tenhle návod ukáže, jak serveru dát vlastní GitHub App. Zabere to asi dvě
minuty, dělá to jen vlastník serveru a na každý server stačí jednou.

:::note[Možná ji nepotřebuješ]
Se zapnutým Control Center Connect se lidé ke GitHubu přihlašují přes
sdílenou App od Control Center, nebo přes App, kterou používá Connect tvé
organizace. Vlastní registruj, když jsi zvolil **Použít vlastní aplikace**: App serveru se použije jen v tom případě. Viz [Control Center Connect](/cs-CZ/prirucka/referencni-prirucka/connect/).
:::

Ke svému účtu se potom přihlásíš podle
[Nastavte integraci GitHub](/cs-CZ/prirucka/navody/integrace-github/).

## Co aplikace dělá

Jedna registrace obslouží dvě různé práce:

| Práce                  | Čím se plní                                     | Proč na tom záleží                                                                           |
| ---------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **Člověk se přihlásí** | Client id a client secret aplikace              | Každý dostane vlastní pověření ke GitHubu, na serveru, na každém zařízení                    |
| **Server jedná**       | Id aplikace a soukromý klíč                     | Agenti, pipelines, obchůzky a odpovědi bota dostávají tokeny vždy pro jeden repozitář        |

Druhá práce si nikdy nepůjčí celé pověření člověka. Každý token, který server
vydá, pokrývá jeden repozitář a je omezený na to, co tam smí odpovědný člen.
Ke čtení propojeného repozitáře stačí aplikace; cokoli, co zapisuje, potřebuje
člena, který smí pushovat. Automatizace pull request nikdy neschválí.

Aplikace serveru platí jen při **Použít vlastní aplikace**. S Control Center nebo vlastním Connect běží přes Connect každá dráha včetně GitHubu; aplikace serveru zůstává uložená, ale nepoužitá, dokud se nevrátíš zpět. Pracovní prostor na vlastních aplikacích používá místo toho svou App ([Dej pracovnímu prostoru vlastní aplikaci](#dej-pracovnímu-prostoru-vlastní-aplikaci)), ať je režim serveru jakýkoli. Aplikace, které
chybí některá pole, je chyba, ne přechod na náhradu: přihlášení ke GitHubu se
odmítají, dokud nejsou nastavená všechna pole.

## Než začneš

- Jsi **vlastník serveru**. Kartu **Aplikace poskytovatelů** nikdo jiný nevidí
- Účet na GitHubu. Aplikace se vytvoří pod ním
- Adresa serveru, na kterou tvůj prohlížeč dosáhne. Veřejná URL serveru (nebo
  loopback u vlastního serveru desktopu) je místo, kam tě GitHub vrátí

## Vytvoř ji jedním kliknutím

1. Jdi do **Nastavení → Server → Jednotné přihlášení** a sjeď ke kartě
   **Aplikace poskytovatelů**
2. V bloku **GitHub** můžeš do pole **Organizace (volitelné)** napsat
   organizaci na GitHubu, která má aplikaci vlastnit. Nech ho prázdné a
   aplikace vznikne pod tvým vlastním účtem; vytvořit ji pod organizací může
   jen vlastník té organizace
3. Klikni na **Vytvořit moji aplikaci GitHub**
4. Prohlížeč otevře GitHub s už vyplněnou aplikací. Klikni na
   **Create GitHub App**
5. GitHub tě vrátí na server, který si uloží id aplikace, soukromý klíč,
   client id a client secret, a pak otevře stránku instalace aplikace

Nic se neopisuje ručně a konverzní kód jde z GitHubu rovnou na tvůj server.
Odkaz funguje jednou a vyprší po deseti minutách; když vyprší, klikni na
**Vytvořit moji aplikaci GitHub** znovu.

Aplikace se jmenuje `Control Center <code>` a žádá přesně to, co Control Center
používá:

| Oprávnění                                  | Přístup          |
| ------------------------------------------ | ---------------- |
| Metadata                                   | Čtení            |
| Contents                                   | Čtení a zápis    |
| Pull requests                              | Čtení a zápis    |
| Issues                                     | Čtení a zápis    |
| Checks, Actions, Commit statuses           | Čtení            |
| Organization members                       | Čtení            |

Webhooky jsou vypnuté: server se dotazuje sám. Aplikaci vytvořenou pod
vlastním účtem později přesuneš do organizace přes **Transfer ownership**
v pokročilém nastavení aplikace na GitHubu.

Kontrolní bod: blok GitHub hlásí „Server může jednat jako on sám a lidé se
můžou přihlásit.“

## Nainstaluj ji tam, kde máš repozitáře

Aplikace, která je zaregistrovaná a nenainstalovaná, umí lidi přihlásit
a nepřečte nic.

1. Na stránce instalace, kterou GitHub otevřel, vyber účet nebo organizaci,
   která vlastní tvoje repozitáře
2. Zvol **All repositories**, nebo vyber ty, které má tenhle server vidět

Na další účet ji později nainstaluje admin pracovního prostoru: v **Nastavení →
Pracovní prostor → Integrace** najde na kartě **GitHub App** v části Hostování kódu **Instalace
aplikace GitHub** a klikne na **Nainstalovat aplikaci GitHub**. Seznam ukazuje
každý účet, na kterém je aplikace nainstalovaná, a označí pozastavenou
instalaci.

## Sdílej instalaci organizace

Organizace nainstaluje GitHub App jednou. Poté může kdokoli v ní, kdo se ke
GitHubu přihlásí na serveru Control Center, instalaci použít, ať je to jakýkoli
server: tvůj, kolegův nebo vlastní. Pro každý server není co autorizovat.

Každý token, který server dostane, patří přihlášené osobě, je omezený na jeden
repozitář a na její roli v něm, takže nikdy nedosáhne dál, než by mohla na
GitHubu. Auditní log GitHubu ukazuje tuto osobu, jak jedná přes aplikaci.

Aby Control Center ztratil přístup k organizaci, vlastník organizace instalaci na
GitHubu odebere nebo zúží její repozitáře. Odebráním člověka z organizace mu přístup
také zanikne.

## Zaregistruj ji raději ručně

Karta **Aplikace poskytovatelů** bere hodnoty i přímo, pro aplikaci, kterou
sis zaregistroval sám:

| Skupina                        | Pole                                                                                            |
| ------------------------------ | ----------------------------------------------------------------------------------------------- |
| **Jednání jako server**        | **ID aplikace** a **Soukromý klíč** (celý `.pem`, včetně řádků `BEGIN` a `END`)                  |
| **Přihlašování lidí**          | **Client id** a **Client secret**. **Adresy URL zpětného volání** ukazují URL k registraci, doslova |
| **Konverzace pull requestů**   | **Přihlášení bota**, vyřešené při testu spojení                                                 |

Zaregistruj callback URL `<server origin>/oauth/github/callback` přesně tak,
jak ji karta ukazuje, nech **Expire user authorization tokens** zapnuté a uděl
oprávnění z tabulky výše. Klikni na **Test**: zeptá se GitHubu, na kterých
účtech je aplikace nainstalovaná, takže si „uloženo“ a „funguje“ nesplete.

## Nastav ji ze souboru `.env` serveru

U instalace bez rozhraní nebo ze skriptu server každé pole naplní ze svého
souboru `.env` poprvé, kdy pro něj nemá uloženou hodnotu:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

Klíč dej na **jeden řádek**: hodnota v `.env` je jeden řádek a `\n` uvnitř
dvojitých uvozovek se dekóduje na nový řádek. Server odmítne nastartovat, když
je `GITHUB_APP_PRIVATE_KEY` nebo `GITHUB_CLIENT_SECRET` exportované v prostředí
jeho procesu, kde by je přečetl každý podřízený proces; drž je v souboru
`.env` (v Dockeru ho připoj na `/app/bin/.env`). Naplnění proběhne **pro každé
pole jednou**, takže úpravu v Nastavení další restart nevrátí.

## Dej pracovnímu prostoru vlastní aplikaci

Pracovní prostor může běžet na vlastní aplikaci místo aplikace serveru:

1. Admin pracovního prostoru otevře **Nastavení → Pracovní prostor → Integrace**
2. Na kartě **Control Center Connect** zvolí **Použít vlastní aplikace** a klikne na **Použít**. Všichni v pracovním prostoru se přihlásí znovu přes aplikace pracovního prostoru
3. Karta **GitHub App** pod Hostováním kódu teď obsahuje pole aplikace: **ID aplikace** a **Soukromý klíč** pod **Jedná za tento pracovní prostor**, **Client id** a **Client secret** pod **Přihlašování lidí**. Jakmile jsou vyplněná, klikni na **Test**

Členové se pak pro tenhle pracovní prostor přihlašují k té aplikaci. Pracovní prostor na vlastních aplikacích nikdy nepřejde na aplikaci serveru ani na Connect: dokud nejsou jeho pole úplná, jeho práce s GitHubem se odmítá. Stejná volba pokrývá Google Calendar, Linear a hledání GIF, každé s vlastními poli vedle svého poskytovatele na téže stránce. Viz [Dej pracovnímu prostoru vlastní aplikaci Linear](/cs-CZ/prirucka/navody/integrace-linear/#dej-pracovnímu-prostoru-vlastní-aplikaci-linear) a [Dej pracovnímu prostoru vlastního klienta Google](/cs-CZ/prirucka/navody/pripojeni-kalendare/#dej-pracovnímu-prostoru-vlastního-klienta-google).
Ostatní volby na té kartě a to, co dělá každá z nich, jsou v [Volba pro každý pracovní prostor](/cs-CZ/prirucka/referencni-prirucka/connect/#volba-pro-každý-pracovní-prostor).

## Řešení problémů

### Vytvořit moji aplikaci GitHub hlásí, že server nemá adresu

Server nemá veřejnou URL, na kterou by se prohlížeč mohl vrátit. Nastav
`CC_SERVER_PUBLIC_URL` (nebo `--public-url`) a zkus to znovu.

### GitHub hlásí, že odkaz vypršel

Jednorázová stránka už se použila, nebo uběhlo deset minut. Začni znovu
z Nastavení.

### Test hlásí, že údaje fungují, ale aplikace není nikde nainstalovaná

Registrace a instalace jsou dva kroky. Otevři stránku instalace aplikace, nebo
použij **Nainstalovat aplikaci GitHub** v Pracovní prostor → Integrace.

### Test hlásí, že soukromý klíč nešel přečíst

Vlož celý soubor `.pem`, včetně řádků `-----BEGIN` a `-----END`. Klíč `ed25519`
ani EC použít nejde: GitHub Apps se podepisují RSA.

### Člen se přihlásil, ale nevidí žádné repozitáře

Aplikace není nainstalovaná na účtu, který je vlastní, nebo její instalace
vybírá jiné repozitáře. Přihlášení pustí jen to, co aplikace smí vidět.

### Agenti hlásí, že instalace GitHub App je pozastavená

Někdo instalaci na GitHubu pozastavil. Zruš pozastavení v **Settings →
Applications → Installed GitHub Apps** daného účtu.
