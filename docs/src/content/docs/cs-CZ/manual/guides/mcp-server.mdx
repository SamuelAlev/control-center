Tenhle návod ukazuje, jak připojit externího klienta MCP — Claude Code, editor
nebo MCP Inspector — k vlastnímu serveru nástrojů Control Center.

Control Center registruje **110** nástrojů a poskytuje je přes Model Context
Protocol ve verzi protokolu `2024-11-05`. Celé rodiny nástrojů, které bys
čekal, chybí: nástroje pro schůzky a kalendář tu nejsou a projektové nástroje
taky ne.

## Najdi endpoint

Plocha MCP sdílí hlavní listener `cc_server`. Samostatný port pro MCP není.

| Endpoint | Metoda   | Účel                                              |
| -------- | -------- | ------------------------------------------------- |
| `/mcp`   | `POST`   | Přenos Streamable HTTP — tím klient mluví        |
| `/mcp`   | `DELETE` | Ukončení relace                                   |
| `/sse`   | `GET`    | Proud notifikací odesílaných serverem             |

Výchozí místní instalace je tedy na `http://127.0.0.1:9030/mcp`.

1. Jdi do **Nastavení → Server → Servery MCP**
2. Přečti kartu **Server MCP** — ukazuje **Běží** nebo **Zastaveno** a port,
   na kterém naslouchá

Na čerstvé instalaci je plocha zapnutá. Token na kartě vidí jen vlastník serveru
a jen on může endpoint spustit nebo zastavit. **Spustit při startu aplikace**
určuje, jestli se po restartu vrátí. **Start** a **Zastavit** platí jen pro
aktuální běh a tuhle předvolbu nemění.

Server se ve výchozím stavu váže na loopback, takže endpoint je dosažitelný jen
ze stroje, na kterém běží `cc_server`, pokud jsi ho nespustil s `--bind any`.

## Získej token

Každý požadavek potřebuje token MCP serveru, z kteréhokoli stroje, včetně
loopbacku. Server ho vytvoří při prvním startu. Vypnout ho ani vymazat nejde.

1. V **Nastavení → Server → Servery MCP** najdi řádek **Autentizační token**
2. Stiskni **Zobrazit token** a zkopíruj ho
3. Chceš-li ho nahradit, stiskni **Otočit token**. Server přejde na nový token
   okamžitě a každý klient, který ještě používá starý, bude odmítnut, dokud mu
   nedáš nový

## Připoj klienta

Namiř klienta na endpoint Streamable HTTP a pošli token jako
`Authorization: Bearer <token>` u každého požadavku, včetně `GET /sse`. Jinak ho
poslat nejde: token v URL se nepřijímá. Přesný tvar konfigurace je věc klienta.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code tohle z projektového `.mcp.json` nevezme. Projektové servery MCP
drží za výzvou ke schválení, na kterou neinteraktivní `claude -p` nikdy
neodpoví. Konfiguraci předej přímo:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` donutí Claude brát jen tenhle soubor, takže se stejný
server z projektu ještě neobjeví a nezaregistruje podruhé.

Kontrolní bod: požádej klienta, ať vypíše nástroje. Měl bys vidět položky
`mcp__*` pro tickety, prostory, paměť, graf kódu a kontrolu.

## Co endpoint odmítne

Token otevírá každý nástroj na serveru, takže endpoint odmítne i cokoli, co mohla
poslat webová stránka, dřív než se podívá na token:

| Požadavek                                                               | Odpověď |
| ----------------------------------------------------------------------- | ------- |
| Hlavička `Origin`, která není stránkou na tomto stroji (`http://localhost`, `http://127.0.0.1` nebo `http://[::1]`, na libovolném portu) | `403`, „Cross-origin requests are not accepted“ |
| Hlavička `Host`, která není ani loopback adresou a portem tohoto listeneru, ani veřejným jménem hostitele serveru | `403`, „Unknown host“ |
| `POST`, jehož tělo není `application/json`                              | `415`   |
| Žádný token, nebo špatný                                                | `401`   |

Pro obsluhu MCP mimo hostitele spusť server s `--bind any` a pošli token z jiného
stroje, přičemž server oslovuj jeho veřejným jménem hostitele.

## Omez každé volání na pracovní prostor

Každý nástroj, který sahá na data vázaná na pracovní prostor, vyžaduje
`workspace_id`. Volání bez něj se odmítne a nevyhodnotí se proti nějakému
„aktuálnímu“ pracovnímu prostoru:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

Id je to z URL v prohlížeči nebo v aplikaci: `/workspaces/<workspace_id>/…`.
Výjimku mají jen nástroje, které pracovní prostory opravdu přesahují, třeba
`list_workspaces` a nástroje kanálu novinek. Kanál novinek patří uživateli, ne
pracovnímu prostoru, a agent vlastního uživatele nemá, takže tyhle nástroje
pracují s kanály vlastníka serveru.

Nástroje vázané na repozitář navíc kontrolují, že je repozitář s tím pracovním
prostorem propojený.

## Poznej, co plocha odmítne

- **Brána režimu.** Volání se na serveru vyhodnotí podle režimu prostoru
  volajícího agenta. Agent v režimu jen pro čtení se k zapisovacímu nástroji
  nedostane tím, že vynechá `space_id`. Režim se vezme z jeho aktivního běhu.
- **Guardraily akcí.** Měnící nástroje deklarují třídy efektů a procházejí
  stejnou politikou jako zbytek produktu. Viz
  [Nastavte guardraily](/cs-CZ/prirucka/navody/nastaveni-guardrailu/).
- **Potvrzení.** Některé destruktivní nástroje sestaví potvrzovací payload a
  volání pokračuje až po jeho schválení.

Celý katalog se hlásí v `tools/list` a nic se z něj neschovává. Externí klient
MCP odmítne zavolat nástroj, který v jeho uloženém seznamu není, takže
schovávání nástrojů je rozbije, místo aby seznam uklidilo.

## Osobní servery MCP zůstávají vlastníkovi

Tahle příručka je o vlastním endpointu Control Center. Opačný směr, servery MCP,
které Control Center předává agentům, které spouští, najdeš v **Nastavení →
Server → Servery MCP → Externí servery MCP**. Servery nastavené na stroji serveru
pro Claude, Codex, Cursor, Gemini, VS Code, Windsurf, OpenCode nebo v `.mcp.json`
se tam najdou automaticky.

Tyto nalezené servery pocházejí z vlastní konfigurace nástrojů uživatele serveru
a jednají s jeho identitou a přihlašovacími údaji, takže patří vlastníkovi serveru:

- Jsou dostupné jen uvnitř vestavěných běhů harnessu, které vlastník serveru spouští nebo za které odpovídá, včetně automatizace v pracovním prostoru, za který vlastník odpovídá.
- Běh člena, automatizace navázaná na člena a každý běh na serveru bez zaznamenaného vlastníka žádný z nich nedostane. Tam nástroje nejsou vypsány, nelze je volat a neobjeví se ve vyhledávání nástrojů.
- Tenhle endpoint je nikdy nevypisuje, nevolá ani nehledá, pro nikoho, ani s tokenem vlastníka, a nepředává jejich zdroje ani prompty. Agentní CLI, které se k Control Center dostává přes MCP, například Claude Code, je tedy přes Control Center nezíská; používá vlastní konfiguraci.

Servery MCP nastavené pro pracovní prostor tím nejsou dotčeny.

## Řešení problémů

### Klient nevidí žádné nástroje

- Zkontroluj, že karta **Server MCP** ukazuje **Běží**
- Zkontroluj, že port sedí s portem tvého `cc_server`
- U Claude Code zkontroluj, že jsi předal `--mcp-config` a `--strict-mcp-config`

### 401 Neautorizováno

Požadavek nesl žádný token, nebo starý. Zkopíruj aktuální token z řádku **Autentizační token** a pošli ho jako `Authorization: Bearer <token>`. Token v URL se ignoruje.

### 403 od klienta, který dřív fungoval

Požadavek nesl `Origin` z webové stránky, nebo `Host`, na který server neodpovídá. Volej endpoint z klienta, ne z prohlížečové stránky, a to přes loopback adresu serveru nebo jeho veřejné jméno hostitele.

### 415 Nepodporovaný typ média

Pošli tělo `POST /mcp` jako `application/json`.

### Volání nástroje selže hláškou „Missing or invalid argument: workspace_id“

Přidej `workspace_id`. Implicitní pracovní prostor není.

### Volání nástroje se odmítne jako neznámé

[Nástroje MCP](/cs-CZ/prirucka/referencni-prirucka/nastroje-mcp/) vypisuje
katalog. Volej název přesně tak, jak tam stojí.
