Tenhle návod ukazuje, jak do pracovního prostoru přidat agenta a nastavit ho tak, aby opravdu běžel.

Každý pracovní prostor vznikne s pěti agenty: CEO a `qa`, `architect`, `engineer` a `librarian`. Agenty tedy obvykle máš dřív, než jsi nějakého nastavil. Postup níže platí stejně pro založeného agenta i pro nového.

## Než začneš

- Jsi uvnitř pracovního prostoru. Celá plocha je v **Nastavení → Pracovní prostor → Agenti** (`/settings/workspace/agents`).
- Agent potřebuje backend. Buď připoj poskytovatele pro vestavěný harness v **Nastavení → Server → Poskytovatelé modelů**, nebo na stroj, na kterém běží `cc_server`, nainstaluj CLI Claude Code.
- Má-li agent nést skilly, nainstaluj je nejdřív v **Nastavení → Pracovní prostor → Dovednosti**. Formulář agenta umí jen přepínat skilly, které v pracovním prostoru už jsou.

## Přidej agenta

1. Otevři **Nastavení → Pracovní prostor → Agenti**.
2. Klepni na **Nový agent**.

Žádný dialog a žádný výběr role. Agent jménem „Nepojmenovaný agent“ vznikne hned a vybere se v detailním panelu vpravo.

V soupisce vlevo teď uvidíš „Nepojmenovaný agent“, s otevřenou kartou **Nastavení** detailního panelu a polem **Název**, ve kterém je „Nepojmenovaný agent“.

## Pojmenuj ho

- **Název** — krátký identifikátor pro zmínky přes @, například `alice`. Parsování zmínky bere `@` a za ním znaky slova, takže jméno s pomlčkou, tečkou nebo mezerou zmínit nejde.
- **Název** — lidsky čitelný popisek, například „Seniorní vývojář“.
- **Systémový prompt** — volitelné další pokyny, vložené jako sekce „Agent instructions“. Zbytek složeného promptu nenahrazují.

Klepni na **Uložit změny** dole ve formuláři. Všechna pole na téhle stránce ukládá tohle jediné tlačítko.

## Dej mu adaptér a model

Rozbalovací seznam **Adaptér** vypisuje runnery, které hostitel serveru opravdu má. Vestavěný adaptér se najde vždy, protože je to server. Claude Code se objeví jen tehdy, když se na tom hostiteli našlo jeho CLI:

| Adaptér                   | Backend                                     |
| ------------------------- | ------------------------------------------- |
| Control Center (built-in) | Smyčka agenta v procesu, bez externího CLI |
| Claude Code               | `claude -p --output-format stream-json`     |

Režimy, řízení uprostřed běhu, pozastavení a obnovení, kontrakty dokončení a subagenty vynucuje jen vestavěný adaptér. Claude Code z toho neumí nic. Cursor, Codex a ostatní poskytovatelé modelů se připojují k vestavěnému adaptéru jako jeho poskytovatelé.

:::note[Prázdný adaptér znamená vestavěnou smyčku]
Agent bez nastaveného adaptéru se odešle na **Control Center (built-in)**, smyčku uvnitř serveru, takže na hostiteli není co instalovat. Není-li nastavený ani model, požádá Anthropic o jeho výchozí, takže úplně nenastavený agent běží jen tehdy, když máš připojený účet Anthropic. Založení specialisté nemají nastavené ani jedno. U každého agenta, kterého chceš používat, nastav obojí.
:::

Rozbalovací seznam **Model** řídí adaptér, který jsi vybral. U vestavěného adaptéru se seznam bere živě od poskytovatelů připojených v **Nastavení → Server → Poskytovatelé modelů**, takže poskytovatel bez uloženého přihlašovacího údaje nepřidá žádný model.

## Přidej skilly

**Dovednosti** je výběr chipů nad balíčky skillů nainstalovanými v tomhle pracovním prostoru. Klepnutím chip přepneš; značka zaškrtnutí označuje vybrané. Nemá-li pracovní prostor žádné skilly, pole hlásí „No skills available. Create skills in Settings → Skills first.“

Skilly vlastního repozitáře tady nevybíráš. Repozitář, který si je veze (v `.agents/skills/`, `.claude/skills/` nebo `.opencode/skills/`), je automaticky přidá tomu agentovi, který v tom repozitáři pracuje, a při přesunu do jiného se vymění. Viz [Skilly vázané na repozitář](/cs-CZ/prirucka/koncepty/model-agentu/#skilly-vázané-na-repozitář).

## Nastav nadřízeného a personu

- **Nadřízený** — vyber jiného agenta podle jména. Z toho se skládá strom nadřízenosti, který ukazuje tlačítko **Organizační schéma** v záhlaví stránky. Soupiska, podle které vedoucí týmu deleguje, je jiná věc: vychází ze členů týmu a jejich skillů.
- **Persona** — volný text, který tvaruje tón a chování, například: „Dává přednost jednoduchým, čitelným řešením. Ke každému novému kódu píše testy.“

## Vylaď běh

- **Úsilí uvažování** — volby přicházejí z úrovní, které vybraný model sám publikuje: Low / Medium / High, u modelů ve stylu OpenAI navíc Extra High a u modelů ve stylu Claude Extra High + Max. Pole je celé schované, když vybraný model žádné úrovně myšlení nedeklaruje, a jinak se předvyplní vlastní výchozí hodnotou modelu.
- **Velikost kontextového okna** — při každé změně modelu se předvyplní z kontextového okna modelu, s chipy na jedno klepnutí pro výchozí modelu, 200k, 500k a 1M. Hodnota, kterou po výběru modelu napíšeš, platí až do další změny modelu.
- **Časový limit ticha (minuty)** — po tolika minutách bez výstupu se běh ukončí. Necháš-li pole prázdné, použije se výchozí hodnota daného režimu.

## Přiděl oprávnění

Agent nemá vlastní přepínače oprávnění. Co smí pushnout, otevřít, sloučit nebo kam dosáhnout, určují pravidla akcí v **Nastavení → Pracovní prostor → Oprávnění agentů**, kde jde pravidlo omezit na tohohle agenta. Ve výchozím stavu se push, pull request, kontrola nebo sloučení a zápis do trackeru nejdřív zeptají tebe, každý zvlášť, a přístup k síti je povolený.

Token GitHub agenta je vždycky jen pro čtení. Push jde přes Control Center, které se před předáním dál zeptá pravidla **Odeslat na remote**. Jak se jednotlivá pravidla dostanou k běhu, popisuje [Nastavte politiky sandboxu](/cs-CZ/prirucka/navody/politiky-sandboxu/).

:::note[Pravidla a sandbox operačního systému jsou samostatné vrstvy]
Pravidla rozhodují, co agent smí dělat; sandbox operačního systému ohraničuje, kde jeho procesy smějí číst, zapisovat a připojovat se. `cc_server` obalí běhy agenta sandboxem hostitele, pokud tam nějaký je. Windows nativní backend nemá a Linux a WSL2 potřebují `bwrap` a `socat`. Úplnou sadu hranic popisuje [Sandbox a zabezpečení](/cs-CZ/prirucka/koncepty/sandbox-a-zabezpeceni/).
:::

## Ověř, že běží

1. Otevři **Nastavení → Server → Poskytovatelé modelů** a ověř, že zvolený adaptér hlásí nainstalovanou verzi, ne „Nenalezeno“. Klepni na **Obnovit** a sonda se spustí znovu. Běží na stroji, na kterém je `cc_server`, ne na stroji, na který se díváš.
2. Otevři prostor s tím agentem a pošli mu zprávu, nebo ho v existujícím prostoru zmiň přes @.
3. Vrať se do **Nastavení → Pracovní prostor → Agenti**, vyber agenta a otevři kartu **Protokoly**. Měl by se objevit běh s odznakem stavu, dobou trvání, časem začátku a adaptérem, který použil. **Zobrazit** otevře proud událostí toho běhu.

Neobjeví-li se žádný běh, projdi [Diagnostikujte agenta](/cs-CZ/prirucka/navody/diagnostika-agenta/).

## Smaž agenta

Vyber ho v soupisce. Na kartě **Nastavení** sjeď k **Nebezpečná zóna** dole ve formuláři a klepni na **Smazat**.
