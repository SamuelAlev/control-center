Tenhle návod ukazuje, jak pracovat s Control Center a neopustit GitHub:
požádat o AI kontrolu ze stránky PR, položit botovi otázku v komentáři a vést
konverzaci dál v jeho vláknech revize.

Odpovědi přicházejí přes dráhu GitHubu pracovního prostoru: vlastní
[GitHub App](/cs-CZ/prirucka/navody/github-app/) tvého serveru, nebo sdílenou
App od Control Center přes Connect. Nic nového se neregistruje a nic nemusí být
dostupné z internetu. Server zjistí, co se na GitHubu řeklo, obchůzkou, takže
notebook za NAT se chová stejně jako veřejné nasazení.

## Předpoklady

- Pracovní prostor má dráhu GitHubu: vlastní GitHub App serveru, nebo Connect,
  s aplikací [nainstalovanou](/cs-CZ/prirucka/navody/github-app/#nainstaluj-ji-tam-kde-máš-repozitáře)
  na účtu, který repozitář vlastní. Vlastní aplikace potřebuje **Pull requests**
  a **Issues** pro čtení i zápis, což **Vytvořit moji aplikaci GitHub** už udělí
- Repozitář je propojený s pracovním prostorem v Control Center
- Jsi na tomto serveru [přihlášený ke GitHubu](/cs-CZ/prirucka/navody/integrace-github/)
  a do repozitáře smíš pushovat
- Žádná URL webhooku, žádný tunel, žádný callback. Na straně sítě není co
  nastavovat

## Najdi jméno bota

Zmiň `@usectrl`, vyhrazený účet Control Center na GitHubu. Je to jediný způsob, jak spustit práci: zmínka o vlastním loginu aplikace nedělá nic; požadavek však dál zpracuje dráha GitHubu tvého pracovního prostoru a ta také odpovídá. Přihlašovací údaje k účtu `usectrl` nepotřebuješ.

## Požádej o kontrolu z GitHubu

Dvě cesty a obě spustí tutéž předpřipravenou pipeline `pr_review`, kterou
spouští tlačítko **Zeptat se AI**:

- **Přidej na PR štítek `ai-review`.** Je to nejblíž tomu, co GitHub umí místo
  přiřazení bota jako recenzenta. Účty aplikací nemůžou obsadit nativní slot
  požadovaného recenzenta. Tvůj účet na PR zareaguje 👀 a kontrola se spustí
  v Control Center; žádný komentář se neodešle
- **Napiš do konverzace PR `@usectrl review`** (nebo jen `@usectrl`). Na tvém
  komentáři se objeví 👀 a pak odpověď, že se kontrola spustila (nebo že už
  jedna běží)

Recenzenti pracují v prostoru kontroly daného PR. Zjištění čteš a zveřejňuješ
jako v [Používejte AI kontrolu](/cs-CZ/prirucka/navody/ai-kontrola/).
Zveřejnění zpět na GitHub zůstává rozhodnutím, které uděláš v Control Center.
Spuštění kontroly z GitHubu samo na GitHub nic nezveřejní.

Štítek se u jednoho PR spustí jednou: přidání je ta žádost a odebrání
s opětovným přidáním ho znovu nenatáhne. Další kontrolu, třeba po pushi,
spustíš zmínkou bota.

## Polož otázku

Napiš do konverzace PR:

```text
@usectrl why does the flaky test in runner_test.dart fail on CI but not locally?
```

Co se stane, po pořádku:

1. Na tvém komentáři se objeví 👀 od tvého vlastního účtu, abys věděl, že ho
   někdo viděl
2. Otázka se zapíše do prostoru kontroly daného PR **jako ty**, se stejným
   připsáním, jako bys ji napsal v Control Center
3. Agent odpoví v prostoru a odpověď se vrátí na PR. Každá odpověď začíná
   `**Control Center** (for @your-login):`

Otázka na PR, který ještě nemá kontrolu, probudí agenta CEO daného pracovního
prostoru. Jakmile kontrola proběhla, odpovídá agent, který mluvil naposled,
takže navázání přijde k tomu, kdo má kontext.

## Navazuj ve vlákně revize

Odpověz uvnitř vloženého vlákna revize, kterého se bot účastní. Komentář
u diffu, který tam nechal, nebo odpověď, kterou do toho vlákna poslal. Zmínka
není potřeba. Vlákno **je** to oslovení:

```text
> @usectrl the retry loop looks O(n²) to me

what would the complexity be with the bounded queue instead?
```

Více tahů funguje stejně: každá odpověď je další otázka v té samé konverzaci,
s prostorem kontroly jako kontextem, a odpověď se vrátí do vlákna.

Navázání na časové ose konverzace PR je nový komentář na nejvyšší úrovni,
takže pořád potřebuje zmínku přes @.

## S kým bot mluví

Server vyřeší autora komentáře, nebo toho, kdo přidal štítek `ai-review`, než
cokoli udělá:

- **Účet GitHub musí být na tomto serveru přihlášený.** Shoda se hledá podle
  číselného id účtu na GitHubu, nikdy podle loginu. Přihlas se v **Nastavení →
  Vy → Profil → Hostování kódu**
- **Musí jít o člena s rolí pro zápis** (`member`, `admin` nebo `owner`)
  v pracovním prostoru, který ten repozitář propojuje
- **Musí smět do repozitáře na GitHubu pushovat.** Odpovědi používají token
  omezený na přístup toho člověka, takže kdo smí jen číst, odpověď nedostane

Kdokoli jiný se potichu ignoruje: nic se neodešle a jeho slova do pracovního
prostoru nikdy nevstoupí. Komentáře od botů a vlastní odpovědi Control Center
se nikdy neberou jako otázky.

### Dva servery, jeden PR

Podle 👀 se servery taky dohodnou, kdo odpoví. Reakce se přidá vlastním
přihlášením autora a GitHub serveru řekne, jestli je nová. Když jsi přihlášený
na dvou serverech Control Center, které oba propojují repozitář, odpoví ten,
který zareaguje první, a druhý mlčí. Totéž platí pro štítek.

## Co čekat

| Věc                  | Chování                                                                                         |
| -------------------- | ----------------------------------------------------------------------------------------------- |
| Potvrzení            | 👀 od tvého účtu na komentáři (u štítku na PR), do jedné obchůzky                                 |
| Odpovědi             | Odeslané ve stopě, ve které se ptalo, se začátkem `**Control Center** (for @your-login):`. Autorem je bot aplikace. Na sdílené aplikaci Connect je odpověď uvnitř vlákna revize napsána z tvého účtu, pokud provozovatel Connectu tuto instalaci neuvedl na seznam |
| Připsání v prostoru  | Otázka je tvoje; agent běží tvým jménem, podle voliče autonomie prostoru                        |
| Kontroly             | Zjištění skončí v prostoru kontroly; zveřejnění na GitHub je ruční                              |

U vlastní aplikace běží obchůzka každou minutu a projde až 25 pull requestů;
přes Connect běží každé dvě minuty a projde až 10, protože ta volání sdílejí
vlastní kvótu GitHubu každého člena. Pracovní prostor, jehož kvóta GitHubu je
pod 15 %, se přeskočí, dokud se nezotaví. Latence je cena za to, že není
potřeba žádný příchozí síťový přístup. Nic se neztratí, když je server
offline: komentář, který přijde v té době, chytí další obchůzka.

## Řešení problémů

**U komentáře, který bota zmiňuje, se nic nestane.**

- Je aplikace **nainstalovaná** na účtu, kterému repozitář patří, a je
  repozitář **propojený** s pracovním prostorem? Nepropojený repozitář se
  přeskočí dřív, než se cokoli zapíše, takže pozdější propojení pořád doručí
- Jsi na tomto serveru přihlášený ke GitHubu, jsi člen s rolí pro zápis a smíš
  do repozitáře pushovat? Kohokoli jiného server ignoruje bez odpovědi
- Pořád nic? Log serveru při selhání jmenuje obchůzku a PR. Hledej
  `pr_conversation:` (obchůzka) a `github_pr_conversation:` (most)

**Štítek kontrolu nespustí.**

U jednoho PR se spustí jednou a ten, kdo ho přidal, prochází stejnými
kontrolami jako autor komentáře. Když už kontrola proběhla, nebo byl štítek
přidaný dřív, než server ten PR vůbec viděl (první obchůzka nevyřízené zapíše
potichu, místo aby je hromadně rozjela), zmiň místo toho bota. `@usectrl review`
kontrolu vždy spustí, pokud už jedna neběží.

**Odpověď bota na GitHub nedorazila.**

Samotná odpověď se neztratí. Je v prostoru kontroly daného PR v Control
Center. Nezdařené odeslání (GitHub je nedostupný, změnila se oprávnění) se
zapíše do logu a odpověď se nezkouší znovu. Když na ní záleží, zeptej se ve
vlákně ještě jednou.
