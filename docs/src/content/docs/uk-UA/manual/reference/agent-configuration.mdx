Цей довідник перелічує всі поля сутності агента, а також переліки та прапорці, які вона використовує. Покроковий опис того, як створити чи відредагувати агента в застосунку, дивіться на сторінці [Створити й налаштувати агента](/uk-UA/керівництво/практичні-посібники/створити-агента/).

| ----------------------- | ---------------------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## Дозволи

Агент не має прапорців дозволів. Push, відкриття й публікація pull request, запис у зовнішній трекер і вихідний мережевий трафік — це класи дій (`gitPush`, `prCreate`, `prPublish`, `vendorSyncWrite`, `networkEgress`), які [обмеження](/uk-UA/керівництво/поняття/обмеження/) розв’язують на рівні робочого простору, агента чи простору. Токен GitHub запуску завжди має область лише для читання; push проходить через шлюз запусків агентів, який перед передачею запитує правило `gitPush`.

## AgentSkills

Незмінний набір ідентифікаторів навичок без урахування регістру. Під час запуску ці назви синхронізуються як посилання на навички в оверлеї агента; далі harness автоматично завантажує frontmatter пов’язаних навичок у промпт.

```
{'flutter', 'dart', 'rest-api'}
```

## Shell-хуки

Shell-хуки дають власнику сервера змогу запускати власні скрипти навколо вбудованого запуску harness: один раз на початку сесії, перед кожним викликом інструмента і після кожного. Хук — це довільний код, тож хуки є конфігурацією хоста. Налаштовує їх лише власник сервера, вручну, на машині сервера. У застосунку немає жодного параметра, і жодна операція їх не записує.

Для агента хуки лежать у його власній теці всередині каталогу даних сервера:

```text
<data dir>/_agent_hooks/<workspace id>/<agent slug>/hooks.json
```

`<agent slug>` — це назва теки агента в робочому просторі (`agents/<slug>/`). Ця тека лежить поза сховищем кожного робочого простору, а кожна пісочниця приховує каталог даних, тож жоден учасник, запуск чи термінал не може її записати.

`hooks.json` зіставляє будь-який із трьох ключів зі скриптом за шляхом відносно теки хуків:

| Ключ           | Коли запускається                 | Що означає код виходу                                          |
| -------------- | --------------------------------- | -------------------------------------------------------------- |
| `sessionStart` | Один раз, коли запуск починається | Нічого; хук лише спостерігає                                   |
| `preTool`      | Перед кожним викликом інструмента | `0` дозволяє виклик; будь-що інше його забороняє               |
| `postTool`     | Після кожного виклику інструмента | Нічого; хук лише спостерігає                                   |

- Кожен скрипт запускається як окремий виконуваний файл, без оболонки й без аргументів, тож він має бути виконуваним і починатися з рядка shebang. Він отримує подію у форматі JSON на stdin: назву події, а для хуків інструментів — назву інструмента з його аргументами (`preTool`) або результатом (`postTool`).
- Хук виконується як один із процесів інструментів запуску, у теці агента для цього запуску. Коли сервер запускає агентів у пісочниці, хук працює всередині пісочниці запуску. Він отримує мінімальне середовище і жодних облікових даних запуску: ані токена хостингу чи провайдера, ані доступу до шлюзу.
- Кожен хук має 30 секунд. Його вихід зчитується й відкидається.
- `preTool` працює за принципом відмови. Ненульовий код виходу, тайм-аут або скрипт, який не вдалося запустити, забороняє виклик інструмента.
- Шлях, який є абсолютним, відсутній або виходить за межі теки хуків (після розв’язання посилань), відхиляється, а журнал запуску каже, який хук відхилено і чому. Відхилений або нечитабельний хук `preTool` забороняє кожен виклик інструмента, доки його не виправлено.
- Блок `hooks` у `.agents/harness.json` — чи то в репозиторії, чи в теці самого агента — ігнорується. Репозиторій часто є чужим кодом, а теку агента можуть записувати учасники та запуски. Журнал запуску повідомляє, що блок проігноровано, і звідки натомість читаються хуки.

Shell-хуки застосовуються лише до вбудованого harness. Налаштований хук `preTool` або `postTool` змушує запуск викликати свої інструменти по одному.

## AgentLiveState (виведений)

Не зберігається. Сім значень. Порядок оголошення — це порядок пріоритету (`sortPriority`, закріплений тестом), і саме за ним сортує реєстр:

| Стан        | `sortPriority` | Умова                                                                                                                   |
| ----------- | -------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `running`   | 0              | Будь-який журнал запуску має статус `running`                                                                            |
| `blocked`   | 1              | Живучість останнього запуску — `blocked`, `stalled` або `looping`                                                        |
| `failed`    | 2              | Статус останнього запуску — `error`, або його живучість — `failed` чи `dead`                                             |
| `queued`    | 3              | Запуск диспетчеризовано, але він не виконується — стоїть за іншим запуском того самого агента, або записаний, але ще не розпочатий |
| `succeeded` | 4              | Запуск завершився успішно                                                                                                |
| `idle`      | 5              | Агент уже запускався і нічого не виконує                                                                                 |
| `neverRun`  | 6              | Журналів запуску не існує                                                                                                |

`queued` і `succeeded` існують **лише для окремого запуску**. `deriveAgentLiveState`, який обчислює стан агента для реєстру, ніколи не видає жодного з них — він повертає `neverRun`, `running`, `failed`, `blocked` або `idle`.
