`cc_server` містить один реєстр інструментів MCP (JSON-RPC 2.0), який обслуговується на головному порту сервера (типово `9030`) за `POST /mcp` і `GET /sse`, версія протоколу `2024-11-05`. Кожен клієнт дістається того самого реєстру: настільний застосунок, вебзбірка, зовнішні клієнти MCP і вбудоване середовище виконання агентів. Зовнішні сервери MCP можна змішувати в той самий реєстр як динамічний шар.

## Розмір реєстру

| Показник                                                                  | Кількість |
| ------------------------------------------------------------------------- | --------- |
| Інструменти, які реєструє `cc_server`                                     | 110       |
| З `packages/cc_mcp`                                                       | 108       |
| З `packages/cc_mcp_client` (виявлення інструментів)                       | 2         |
| Зареєстровано в базовому реєстрі (`server_mcp_registry.dart`)             | 63        |
| Зареєстровано після завантаження, коли піднімаються їхні сервіси (`cc_server_runtime.dart`) | 47        |
| З 63 базового реєстру — умовні на наявність репозиторію з графом коду     | 5         |

П’ять інструментів графа коду реєструються лише тоді, коли хост передає репозиторій із графом коду в `buildServerMcpRegistry`. `cc_server` завжди передає його, тож усі 110 живі в бінарнику, який постачається.

Повний реєстр оголошується в `tools/list` без жодного фільтрування на етапі виявлення. Правки тікетів — це типізовані інструменти.

:::note[Зовнішні клієнти завжди бачать увесь каталог]
`tools/list` ніколи не підрізають. Клієнти MCP звіряють назви інструментів зі своєю кешованою копією цього списку й відкидають усе, чого в ньому немає, навіть не питаючи сервера, тож інструмент, схований там, недосяжний, а не просто тихий.

**Вбудований harness** інший: він завантажує на кожен запит лише резидентний набір означень, а решту підтягує за першого використання, і це поведінка на боці harness, яка не змінює цей реєстр. Див. [Контекст інструментів і кеш промптів](/uk-UA/керівництво/поняття/контекст-інструментів).
:::

:::note[Кожен клас інструментів зареєстровано]
Вихідний файл у `packages/cc_mcp/lib/src/tools/` — це інструмент, який агент може
викликати. `packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart`
завалює збірку, якщо новий клас інструмента нічим не конструюється.
:::

## Спільні параметри

### `workspace_id`

**Обов’язковий** для кожного інструмента, який торкається даних з областю робочого простору. Відсутній або неправильний `workspace_id` повертає явну помилку, а значення, яке не збігається з робочим простором цільової сутності, відхиляється, а не тихо ігнорується. Пропускайте його в справді глобальних інструментах: `list_workspaces` і шести інструментах стрічки новин (`list_feeds`, `list_articles`, `get_article`, `set_article_read`, `set_article_saved`, `refresh_feeds`), які працюють із персональним списком стрічок власника сервера. Інструменти виявлення (`search_tool_bm25`, `list_my_tools`) беруть його необов’язково, щоб класифікувати викликуваність за режимом розмови. Коли агента відправляє сервер, робочий простір примусово задається на боці сервера, тож агент не може дістатися іншого робочого простору, передавши чужий ідентифікатор.

## Виявлення інструментів

Обидва походять із `cc_mcp_client`, а не `cc_mcp`, і обидва звертаються до вартового режиму, тож повідомляють те, що можна викликати в _поточному_ режимі розмови.

| Інструмент         | Опис                                                                                                                        |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `search_tool_bm25` | Шукати в каталозі інструментів за ключовим словом; повертає відповідні інструменти, їхні схеми аргументів і те, чи можна кожен викликати просто зараз |
| `list_my_tools`    | Перелічити інструменти, які можна викликати просто зараз у цій розмові, відфільтровані за її режимом                        |

Третій інструмент виявлення, **`search_tools`**, існує лише всередині вбудованого harness і не входить до цього реєстру MCP. Він ранжує власну поверхню інструментів запуску й, на відміну від `search_tool_bm25`, **завантажує** схеми того, що знаходить, щоб агент міг викликати збіг наступного ходу. Агенти на harness мають віддавати йому перевагу; у клієнтів MCP є `search_tool_bm25`.

## Обмін повідомленнями й делегування між агентами

Агенти спілкуються між собою через простори (довготривалі, видимі в реєстрі). `ask_agent` — це запит/відповідь з обов’язковим тайм-аутом; `delegate_task` захищений на боці сервера обмеженням глибини, виявленням циклів, бюджетною оболонкою та стелею автономності.

| Інструмент      | Опис                                                                                           |
| --------------- | ---------------------------------------------------------------------------------------------- |
| `send_to_agent` | Надіслати односпрямоване повідомлення іншому агентові, адресоване за `to_agent_id` або точною `to_agent_name` |
| `ask_agent`     | Поставити іншому агентові запитання й дочекатися його відповіді або вичерпати тайм-аут          |
| `delegate_task` | Делегувати завдання іншому агентові як відстежуваний дочірній тікет                            |
| `consult_agent` | Додати до простору найкращого спеціаліста за навичками й відправити його із зосередженим брифом |
| `todo_read`     | Прочитати збережений контрольний список завдань цієї розмови                                   |

## Інструменти графа коду

Реєструються лише тоді, коли хост надає репозиторій із графом коду. Індекс охоплює граматики, які постачаються (Dart, JS/TS, PHP, Python, Rust, Zig, C/C++, Go, Java, Ruby, C#, Swift, Kotlin, R, Assembly, MATLAB, Ada); символів будь-якою іншою мовою там немає.

| Інструмент     | Опис                                                                               |
| -------------- | ---------------------------------------------------------------------------------- |
| `search_code`  | Шукати проіндексовані символи за назвою, сигнатурою й коментарем документації (гібрид BM25 + семантика) |
| `code_symbol`  | Знайти символи за точною назвою; повертає `file:line` і сигнатуру                  |
| `code_callers` | Перелічити символи, які викликають символ або залежать від нього (вхідні ребра)     |
| `code_callees` | Перелічити символи, які символ викликає або від яких залежить (вихідні ребра)       |
| `code_impact`  | Обчислити транзитивний радіус впливу символу до заданої глибини                     |

## Інструменти ізольованих середовищ (rig)

Керуйте одноразовими машинами — ізольованим браузером чи робочим столом Linux,
емулятором Android або симулятором iOS — зсередини запуску. Реєструються після
завантаження, безумовно: чи машина справді може завантажитися — це питання-проба,
на яке інструменти відповідають під час кожного виклику. Повторні виклики в одній
розмові повторно використовують одну машину; скриншоти повертаються як вміст
зображення з бюджетом в одне зображення на результат, а вилучений вміст сторінки
чи інтерфейсу загорнуто як недовірені дані. Чотири інструменти використання разом
із `rig_close` оголошують [клас дій](/uk-UA/керівництво/поняття/обмеження/)
`enclosureControl` (інструменти використання також оголошують `networkEgress` і
`processSpawn`; `mobile_use` та `ios_use` також оголошують `packageInstall`), тож
режими лише для читання їх забороняють. `rig_list` не оголошує жодного — він лише
читає стан робочого простору. Повний словник дієслів для кожної поверхні — у
[довідці з rigs](/uk-UA/керівництво/довідка/rigs/#action-verbs).

| Інструмент     | Опис                                                                                            |
| -------------- | ------------------------------------------------------------------------------------------------ |
| `computer_use` | Керувати робочим столом Linux в ізольованій ВМ: рух, клацання, перетягування, прокручування, введення, зміна розміру, буфер обміну, скриншот |
| `browser_use`  | Керувати headless-браузером Chromium, Firefox або WebKit (`engine`): навігація, клацання, заповнення, вилучення (a11y/DOM/консоль), буфер обміну, скриншот |
| `mobile_use`   | Керувати Android через ADB: огляд/введення, скриншоти, встановлення/запуск/зупинка/скидання/видалення застосунків, глибокі посилання та команди пристрою у формі argv |
| `ios_use`      | Керувати симулятором iOS через WebDriverAgent/CoreSimulator: огляд/введення, скриншоти, встановлення/запуск/зупинка/видалення застосунків, глибокі посилання та процеси симулятора у формі argv |
| `rig_list`     | Перелічити rig робочого простору з поверхнею, статусом, розміром екрана й контролером            |
| `rig_close`    | Знищити rig і відкинути стан його машини                                                         |

## Не доступні через MCP

Календар і зустрічі не мають інструментів MCP. Агенти не можуть читати ваш календар, зустрічі, транскрипти, пункти дій чи рішення. Підсумок, який створює пункти дій і рішення, виконується як вбудований [конвеєр `meeting_summary`](/uk-UA/керівництво/поняття/зустрічі/), а не як інструмент, який агент може викликати.

## Фільтрування інструментів за режимом

Фільтрування забезпечується двічі з однієї таблиці (`ModeToolPolicy`): один раз у диспетчері MCP для адаптера Claude Code і один раз у реєстрі вбудованого harness. Заблокований виклик повертає причину.

| Режим         | Поверхня інструментів                                                                                                                                                                                                               |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`        | Кожен зареєстрований інструмент; жодного списку дозволених                                                                                                                                                                           |
| `plan`        | Дібраний список дозволених. Жодних записів у worktree і жодних дієслів тікетів `create` / `assign` / `delegate`, але пам’ять, артефакти, списки завдань, `submit_plan`, `exit_plan_mode` і дієслова завершення тікета для відправленого тікета дозволено |
| `review`      | Дібраний список дозволених: участь у перевірці, спілкування, призначені лише для читання витягувачі контексту та повний набір дієслів тікетів, зокрема `create_ticket` і `assign_ticket`                                            |
| `orchestrate` | Дібраний список дозволених: інструменти дослідження й читання плюс `propose_orchestration`, `create_playbook` і `run_playbook`. Найм, декомпозиція й завершення тікетів відбуваються детерміновано після схвалення, ніколи посеред запуску |

Дозволено в кожному режимі незалежно від списку дозволених:

| Набір                | Інструменти                                                                                                                                                                                                                                                       |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Пам’ять і артефакти  | `search_memory`, `propose_fact`, `propose_policy`, `supersede_fact`, `supersede_policy`, `record_observation`, `update_my_notes`, `get_my_notes`, `list_memory_domains`, `list_policies`, `publish_artifact`, `revise_artifact`, `list_artifacts`, `get_artifact` |
| Граф коду            | `search_code`, `code_symbol`, `code_callers`, `code_callees`, `code_impact`                                                                                                                                                                                       |
| Механіка запуску     | `search_tool_bm25`, `list_my_tools`, `todo_write`, `todo_read`                                                                                                                                                                                                    |

Перебування в списку дозволених не робить інструмент доступним для виклику, і навпаки: можливість поставити запитання операторові — це інструмент **harness** (`ask_user`), тож він узагалі не з’являється в цьому каталозі MCP.

## Інструменти за шлюзом схвалення

Інструмент може оголосити `requiresApproval`. Тоді диспетчер будує `ApprovalPayload` і показує його через `ConfirmationPort`, перш ніж інструмент запуститься; `cc_server` підключає цей порт, тож шлюз чинний.

Зареєстровані інструменти, які його оголошують: `create_ticket`, `update_ticket`, `assign_ticket`, `reassign_ticket`, `close_ticket`, `ticket_relation`, `create_goal`, `update_goal_progress`, `create_approval`, `decide_approval`, `comment_approval`, `create_work_product`, `save_work_product_revision`, `create_runtime_profile`, `install_skill`, `update_skill`.

Окремо уніфіковані обмеження дій ставлять на шлюз кожен інструмент, що оголошує непорожній набір `ActionClass`. Рішення `prompt` без під’єднаного затверджувача відхиляється. Див. [Обмеження](/uk-UA/керівництво/поняття/обмеження/).

## Можливості, за якими не стоїть жодного інструмента

Не кожна можливість у продукті доступна агентові. Ці не мають жодного
інструмента взагалі, тож назва, яку ви, можливо, бачили деінде, повертає «невідомий інструмент»:

| Можливість                              | Де вона живе натомість                                                                          |
| --------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Наймання, звільнення чи редагування агента | Інтерфейс агентів. Інструментів `hire_agent` / `fire_agent` / `update_agent` немає              |
| Створення робочого простору             | `workspace.upsert` через RPC, який засіює та проставляє володіння                               |
| Проєкти (створення / перелік / оновлення / прив’язка) | Інтерфейс тікетів. Проєкти — це поверхня оператора — див. [Проєкти](/uk-UA/керівництво/практичні-посібники/проєкти/) |
| Запитання операторові, що блокує         | Інструмент **harness** `ask_user`, а не MCP. Він рендерить у розмові форму й блокує до відповіді |
| Діагностика окремого агента              | Нічого. Інструмента `doctor` немає — див. [Діагностика агента](/uk-UA/керівництво/практичні-посібники/діагностика-агента/) |
| Календар і зустрічі                      | RPC лише для людських клієнтів (див. вище)                                                     |
