Control Center Connect виконує входи в провайдерів для серверів, які не
зареєстрували власних застосунків. Сервер використовує або розміщений Connect
від Control Center, або Connect, який запускає його організація
([Запустити сервер Connect](/uk-UA/керівництво/практичні-посібники/запустити-сервер-connect/)),
або жодного. Вибір задається в **Налаштування → Сервер → Єдиний вхід → Control
Center Connect**, командою `cc_server connect` або змінною `CC_CONNECT_URL`.

## Канали

За **Використовувати власні застосунки** (або до того, як хтось обере) канал працює на власному застосунку сервера, якщо його повністю налаштовано, інакше він недоступний. З Control Center Connect або власним Connect Connect обслуговує кожен канал, який надає: власні застосунки сервера лишаються збереженими, але не використовуються — ні для входів, ні для автоматизації сервера, ні для статусу, який повідомляє сервер. Застосунок робочого простору перемагає в будь-якому режимі.

| Канал        | Що потрібно власному застосунку                   | Через Connect                                                       |
| ------------ | ------------------------------------------------- | ------------------------------------------------------------------- |
| `github`     | Id застосунку, приватний ключ, id клієнта й секрет клієнта | Люди входять у спільний GitHub App                         |
| `google`     | Id клієнта й секрет клієнта                       | Люди підключають Google Calendar                                    |
| `linear`     | Id клієнта                                        | Люди входять у Linear                                               |
| `linear_app` | Id клієнта                                        | Адміністратор робочого простору підключає актора застосунку Linear  |
| `slack`      | Підключення власного застосунку Slack робочого простору | Адміністратор робочого простору підключає Slack до спільного застосунку Slack |
| `klipy`      | `KLIPY_APP_KEY`                                   | Пошук GIF через проксі Connect                                      |

Власний застосунок, налаштований лише частково, переводить свій канал у помилку
й ніколи мовчки не переходить на Connect. Робочий простір, який використовує
власний GitHub App (**Налаштування → Робочий простір → Загальні → Ідентичність
GitHub**), ніколи не ходить через Connect для GitHub, а робочий простір, який використовує власний застосунок Google, Linear або Klipy (**Налаштування → Робочий простір → Загальні → Застосунки провайдерів**), ніколи не ходить через застосунок сервера чи Connect для цього провайдера. Зміна вибору Connect нікого не виводить із власного застосунку робочого простору.

## Що Connect бачить і чого не бачить ніколи

| Connect бачить                                                                                | Connect ніколи не бачить                                              |
| --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Ідентифікатор встановлення сервера й підписи запитів                                          | Вихідний код, вміст репозиторіїв, diff або текст pull request         |
| Обліковий запис провайдера, який виконав вхід, — під час входу                                | Тікети, транскрипти чи будь-що в базі даних робочого простору         |
| До якого робочого простору належать облікові дані — як непрозорий id усередині печатки        | Приватний ключ GitHub App: токени репозиторіїв беруться з входу людини |
| Репозиторій, для якого випускається токен GitHub для одного репозиторію                       | Токени оновлення в стані спокою: вони існують лише всередині печаток, які зберігає сервер |
| Id інсталяцій GitHub, прив’язаних до сервера                                                  | Секрети Linear: сервер сам обмінює код Linear                         |
| Пошукові запити GIF, коли він проксіює Klipy                                                  | Паролі, ключі сполучення чи ключі провайдерів моделей                 |
| Посилання на події Slack (команда, канал, id повідомлення) і текст slash-команд               | Текст повідомлень Slack: Connect відкидає його під час отримання, а сервер сам читає повідомлення зі Slack |

Connect зберігає короткоживучий стан (розпочаті входи, nonce, кеші) не довше
15 хвилин. Його єдині довготривалі записи — прив’язки інсталяцій: які сервери
можуть використовувати яку інсталяцію GitHub і до якого сервера прив’язана кожна
команда Slack. Помилки несуть код, а не відповідь провайдера, а журнали
записують ідентифікатори встановлення лише як ключові хеші.

## Режими

| Режим      | Налаштування                | Поведінка                                                                                                |
| ---------- | --------------------------- | -------------------------------------------------------------------------------------------------------- |
| Не задано  | Новий сервер                | Жоден канал не використовує Connect. Початкове налаштування просить власника сервера зробити вибір       |
| `hosted`   | **Використовувати застосунки Control Center** | `https://connect.usectrl.dev` з конфігурацією, підписаною офлайн. Власні застосунки сервера не використовуються                       |
| `custom`   | **Використовувати власний сервер Connect** | Connect за URL HTTPS (`http` лише на loopback), якому довіряють під час першого використання. Власні застосунки сервера не використовуються |
| `off`      | **Використовувати власні застосунки** | Жоден канал не використовує Connect. Вхід людей виконують лише власні застосунки               |

`CC_CONNECT_URL` у середовищі сервера або в `.env` фіксує вибір: `hosted`, `off`
або URL Connect. «Налаштування» тоді показують блокування й не можуть його
змінити.

У цю збірку не вкомпільовано ключ розміщеної конфігурації, тож режим hosted
повідомляє `hosted_unprovisioned` і не обслуговує жодного каналу. Власні
застосунки й власний Connect працюють.

Сервер читає конфігурацію Connect не частіше ніж раз на 10 хвилин і чекає на
кожен виклик не довше 5 секунд. Коли Connect недоступний, використовується
остання коректна конфігурація, а «Налаштування» позначають її застарілою.

## Ідентичність встановлення

| Елемент                  | Що це                                                                                                            |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| Ключ встановлення        | 32-байтове початкове значення у файлі секретів сервера (`connect_install_key`), окремо від ключів сполучення пристроїв |
| Ключ для кожного Connect | Ключ Ed25519, виведений із початкового значення й адреси Connect. Ним підписується кожен запит до Connect (RFC 9421) |
| Ідентифікатор встановлення | 26 символів, виведених із цього відкритого ключа. Показується в «Налаштуваннях» і командою `cc_server connect status` |

Той самий сервер має для кожної адреси Connect свій ідентифікатор встановлення.
Ідентифікатор змінюється, лише коли змінюється ключ.

## Запечатані облікові дані

Вхід через Connect повертає **печатку облікових даних**: зашифрований блок,
відкрити який може лише Connect, що його створив. Вона прив’язана до провайдера,
адреси Connect, ідентифікатора встановлення, робочого простору, облікового запису
провайдера, застосунку й покоління секрету.

- Сервер зберігає печатку й ідентифікатор встановлення, для якого її запечатано.
  Токени доступу залишаються в пам’яті
- Щоб оновити доступ, сервер надсилає печатку назад і отримує новий токен
  доступу й нову печатку
- Печатка, у якої ідентифікатор встановлення чи адреса Connect більше не
  збігається, видаляється під час наступного читання, і ця людина входить знову.
  Так буває після зміни ключа, перемикання на інший Connect або відновлення
  каталогу даних на іншому сервері
- Печатка, яку Connect не може відкрити, відхиляється з `access_denied`

## Інсталяції GitHub

Інсталяцією спільного GitHub App сервер може користуватися, лише коли Connect
прив’язав її до ідентифікатора встановлення цього сервера.

- **Установити застосунок GitHub** у **Налаштування → Робочий простір →
  Загальні** відкриває GitHub із 15-хвилинним квитком. Connect прив’язує нову
  інсталяцію, якщо той, хто встановлює, володіє особистим обліковим записом або
  адмініструє організацію
- **Авторизувати цей сервер** прив’язує вже наявну інсталяцію. Зробити це може
  лише адміністратор організації
- Інсталяцію в організації можна прив’язати до кількох серверів; для кожного
  потрібна авторизація адміністратора

## Довіра до конфігурації

| Connect     | Як сервер довіряє його конфігурації                                                                                                       |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Розміщений  | Перевіряє підпис Ed25519 за ключами, вкомпільованими в збірку. Відхиляє епоху, нижчу за найвищу з уже побачених (`rollback`)             |
| Власний     | Під час першого використання закріплює id застосунку GitHub та id клієнта, id клієнтів Google і Linear, а також id застосунку й клієнта Slack. Зміна призупиняє входи через Connect (`pins_changed`), доки власник сервера не натисне **Довіряти новим застосункам** |

## Операції

Усі налаштування Connect доступні лише власнику сервера.

| Операція              | Що робить                                                                              |
| --------------------- | -------------------------------------------------------------------------------------- |
| `connect.status`      | Режим, URL, блокування, ідентифікатор встановлення, стан, епоха конфігурації й джерело кожного каналу |
| `connect.configure`   | Задає `hosted`, `custom` (з `url`) або `off`                                           |
| `connect.test`        | Заново отримує конфігурацію й повідомляє стан                                          |
| `connect.confirmPins` | Приймає змінені ідентифікатори власного Connect                                        |
| `connect.rotateKey`   | Створює новий ключ встановлення. Усі входи через Connect на цьому сервері перестають працювати |

Самі входи використовують `oauth.lanes`, `oauth.begin`, `oauth.status`,
`oauth.complete`, `oauth.connections` і `oauth.disconnect`. Людина — це завжди
той, хто ввійшов і викликає операцію.

## Вхід через Connect

1. Сервер просить Connect розпочати канал і отримує URL авторизації провайдера,
   який перевіряє, перш ніж показати
2. Людина підтверджує в браузері. Провайдер повертається в Connect
3. Connect показує 8-символьний код і посилання `control-center://oauth-done`
4. Людина вводить код у застосунку або переходить за посиланням. Сервер забирає
   вхід із цим кодом і власним доказом запиту

Вхід спливає через 10 хвилин. П’ять неправильних кодів завершують його.
Посилання, яке цей застосунок не запускав, відхиляється з повідомленням **Вхід
розпочато не тут**.

## Змінити ключ встановлення

**Змінити ключ** на картці Connect або `cc_server connect rotate-key --yes`:

- Дає серверу новий ключ встановлення й новий ідентифікатор встановлення
- Виводить усіх із кожного каналу, що працює через Connect
- Не зачіпає входи через власні застосунки сервера
- Вимагає додати новий ідентифікатор встановлення до списку дозволених власного
  Connect

## Коди стану

| Код                    | Значення                                                             |
| ---------------------- | -------------------------------------------------------------------- |
| `hosted_unprovisioned` | У цій збірці немає ключа розміщеної конфігурації                     |
| `signature`            | Розміщена конфігурація не пройшла перевірку підпису                  |
| `rollback`             | Connect віддав конфігурацію, старішу за ту, яку сервер уже бачив     |
| `unreachable`          | Сервер не може зв’язатися з Connect                                  |
| `install_blocked`      | Connect не дозволяє цей ідентифікатор встановлення                   |
| `pins_changed`         | Власний Connect оголосив інші ідентифікатори застосунків             |
| `protocol`             | Connect відповів у формі, якої цей сервер не розуміє                 |
