Control Center може надсилати **псевдонімізовані події використання** до екземпляра [Umami](https://umami.is). Статистика використання **вимкнена, доки її не ввімкне оператор сервера**. Цей параметр належить серверу й діє для кожного підключеного до нього клієнта: настільного застосунку, вебзастосунку, телефона і самого сервера.

Статистика використання не пов'язана з параметром **Надсилати звіти про збої** — це налаштування окремого пристрою для діагностики збоїв і помилок.

## Хто вирішує

| Перемикач | Де | Дія |
| --- | --- | --- |
| **Надсилати статистику використання** | Початкове налаштування (крок пісочниці) і **Налаштування → Приватність**. Змінити його може лише оператор сервера; інші учасники бачать поточне значення лише для читання | Для всього сервера. Зберігається як `telemetry.usage_analytics` у налаштуваннях сервера. Вимкнений, якщо не задано `true` |
| Тип збірки | Автоматично | Налагоджувальні та профілювальні збірки нічого не надсилають. Натомість вони записують кожну подію в журнал налагодження |
| `CC_ANALYTICS_DEBUG=1` | Середовище `cc_server` або його файл `.env` | Дозволяє налагоджувальним і профілювальним збіркам сервера та кожного підключеного до нього клієнта надсилати дані насправді, для тестування. Перемикач вище все одно має бути ввімкнений |
| `DO_NOT_TRACK=1` | Середовище `cc_server` | Вимикає власне звітування сервера, хай що показує перемикач. Клієнти й далі дотримуються перемикача |
| Демосервер | Автоматично | Публічний демосервер нічого не надсилає від свого імені. Відвідувачі не можуть змінити перемикач |

Клієнти отримують значення параметра від сервера (`telemetry.config`, а потім наживо через `telemetry.watch`). Доки відповідь не надійшла, події чекають у невеликому буфері в пам'яті. Якщо відповідь заперечна, буфер відкидається. Вимкнення перемикача відкидає все, що ще стоїть у черзі, і одразу припиняє надсилання на кожному клієнті.

## Що ніколи не надсилається

- Вміст повідомлень, тікетів, рецензій і зустрічей, заголовки, промпти, команди оболонки та пошукові запити
- Імена, логіни, адреси електронної пошти, аватари та відображувані імена
- Шляхи до файлів, назви репозиторіїв і гілок, імена хостів та URL (репозиторій надсилається лише як псевдонімізований `repo_id`, посилання на зустріч — лише як її провайдер)
- Вихідні ідентифікатори будь-якого виду

Кожна подія, перш ніж залишити процес, проходить через політику властивостей. Текст, шляхи, URL, адреси електронної пошти, необгорнуті ID і рядки під такими ключами, як `email`, `*_name`, `path`, `title`, `prompt`, `content` або `token`, відкидаються, а не надсилаються. Рядок надсилається, лише якщо це короткий токен із закритого словника: значення переліку, версія, локаль або ID моделі.

## Псевдонімізовані ID

ID надсилаються, але лише як псевдоніми. Кожен ID робочого простору, простору, розмови, агента, запуску, користувача та пристрою замінюється на HMAC-SHA256 із власною секретною сіллю інсталяції (`telemetry.pseudonym_salt`), скорочений до 20 шістнадцяткових символів. Той самий робочий простір завжди повідомляє те саме значення, тож події можна пов'язувати й підраховувати, але вихідний ID ніколи не залишає інсталяцію. Сіль створюється під час першого запуску сервера й ніколи не передається постачальникові аналітики. Видалення каталогу даних сервера створює нову сіль і новий ID інсталяції, і зв'язок з усім записаним раніше зникає.

## Перегляди екранів

Кожен перехід записує перегляд сторінки, URL якої — **шаблон маршруту**, наприклад `/workspaces/:workspaceId/spaces/:spaceId`, а не конкретна адреса. Назва екрана складається з літеральних сегментів шаблону, тож для цього прикладу це `workspaces_spaces`. Параметри маршруту, що закінчуються на `Id`, додаються як псевдонімізовані властивості `*_id`, а числові (наприклад, номер PR) — як числа. Усі інші параметри відкидаються.

## Доставлення

Події надсилаються по одній на `<host>/api/send` із черги в пам'яті розміром до 200 подій. Мережева помилка, тайм-аут, `429` або `5xx` зберігають подію й повторюють спробу з експоненційною затримкою від 1 секунди до 5 хвилин. Будь-який інший `4xx` відкидає її. На диск нічого не записується, тому події, що лишаються в черзі під час закриття застосунку, втрачаються. Черга спорожнюється, коли застосунок переходить у фон і коли сервер завершує роботу.

## Спрямувати збірку на інший екземпляр

Адресат фіксується під час збирання:

```bash
--dart-define=CC_ANALYTICS_HOST=https://analytics.example.com/
--dart-define=CC_ANALYTICS_WEBSITE_ID=<website uuid>
```

Адаптер постачальника міститься в `packages/cc_analytics`. Щоб підтримати інший сервіс аналітики, додайте туди адаптер. План відстеження та правила приватності залишаються незмінними.
