Цей посібник показує, як налаштувати сповіщення і що насправді контролює кожен
параметр.

Сповіщення надходять на двох поверхнях. **Центр сповіщень** — дзвіночок на
панелі заголовка — читає довготривалий потік на сервері, окремий для кожного
робочого простору. **Системні тости** — це окремий шлях, доступний лише на
десктопі, який живиться кадрами, що їх сервер передає наживо.

:::note[Вебзбірка не показує системних сповіщень]
Конвеєр тостів будує лише десктопний завантажувач. На `app.usectrl.dev` немає ні
системних тостів, ні звуків сповіщень, ні фонових банерів — дзвіночок та його
історія все одно працюють, бо читають потік сервера. У мобільного клієнта немає
жодної поверхні сповіщень.
:::

## Увімкнути або вимкнути категорії

1. Перейдіть до **Налаштування → Ви → Сповіщення**
2. Залиште **Увімкнути сповіщення** увімкненим
3. Перемкніть потрібні категорії. Їх рівно шістнадцять:

| Категорія                  | Коли спрацьовує                                                            |
| -------------------------- | -------------------------------------------------------------------------- |
| Агент завершив роботу      | Агент завершив запуск                                                      |
| PR опубліковано            | Агент опублікував PR                                                       |
| PR злито                   | PR злили                                                                   |
| Нові повідомлення          | Повідомлення надійшло в простір, на який ви не дивитеся                    |
| Згадка в pull request      | Опитування сповіщень GitHub побачило, що вас згадали в PR                  |
| Запит на рев’ю             | Ваше рев’ю справді запитали для PR, який не є чернеткою                    |
| Рев’ю застаріло            | У pull request, який ви вже рев’ювали, з’явилися нові коміти               |
| Готово до злиття           | Написаний вами pull request став готовим до злиття або перестав ним бути   |
| Рішення рев’ю              | Рецензент схвалив, запитав зміни або схвалення скасували                   |
| Перевірки                  | CI не пройшов у написаному вами pull request або відновився                |
| Обговорення рев’ю          | Хтось відповів в обговоренні, у якому ви є, або закрив його                |
| Тікет призначено           | Тікет призначили                                                           |
| Статус тікета змінено      | Тікет змінив статус                                                        |
| Зустріч незабаром почнеться | Зустріч у календарі потрапляє у ваше вікно попередження                   |
| Календар відключено        | Токен OAuth підключеного календаря прострочився                            |
| Оновлення середовища       | Середовище перехопили, вилучили або воно зазнало збою                      |

Про все поза цим списком не можна ні сповістити, ні відфільтрувати — категорії
«все інше» не існує.

Ці налаштування супроводжують вашого користувача на всіх пристроях, тож телефон
і ноутбук залишаються синхронними. Гучність — навмисний виняток, вона
залишається окремою для кожного пристрою.

## Задати тихі години

1. На тій самій сторінці увімкніть **Quiet hours**
2. Введіть час початку й завершення у форматі `HH:MM` (типове вікно — 22:00–08:00)

У тихі години нетермінові сповіщення відкидаються — вони не стають у чергу й не
відтворюються пізніше.

Дві категорії **термінові** й доставляються завжди, оминаючи тихі години _та_
режим фокусу: **Зустріч незабаром почнеться** і **PR опубліковано**.
Попередження про зустріч, яке ви побачите лише після факту, нічого не варте —
саме в цьому причина.

## Виберіть звук

1. Прокрутіть до **Звук сповіщень**
2. Виберіть один із одинадцяти вбудованих звуків або **Немає**
3. Натисніть кнопку тесту, щоб почути його, і задайте гучність повзунком

Застосунок відтворює звук сам; системне сповіщення доставляється беззвучно, тож
ви ніколи не почуєте його двічі.

## Задати час попередження про зустріч

1. Прокрутіть до **Час попередження**
2. Виберіть **5**, **10**, **15** чи **30** хвилин

Саме за стільки до події в календарі спрацьовує сповіщення **Зустріч незабаром
почнеться**. Типово це 5 хвилин.

## Дізнатися, коли сповіщення придушується

Сповіщення відкидається мовчки, коли виконується будь-яка з цих умов:

- Сповіщення вимкнені глобально або вимкнена його категорія
- Ви вже на маршруті, куди воно мало вас привести — а для повідомлення — уже в
  тому просторі
- Режим фокусу активний, а категорія нетермінова
- Тихі години активні, а категорія нетермінова

Ці перевірки стосуються системних тостів. Довготривалий дзвіночок усе одно
записує подію.

Ще два придушення діють далі вгорі за потоком — у тому, що сервер узагалі
надсилає:

- Повідомлення від іншої **людини** без згадки вас ніколи не стає сповіщенням
- Простори агент-агент вимкнено на бічній панелі, тож вони ніколи не збільшують
  бейдж непрочитаного в людей

Усередині простору немає тихого куточка: кожна розмова сповіщає однаково,
зокрема й гілки. Стан прочитання прив’язаний до простору, тож непрочитане
збирається по всіх розмовах простору, а не відстежується окремо для кожної
розмови.

## Читати й очищати центр сповіщень

1. Натисніть дзвіночок на панелі заголовка

Спливне вікно показує останню активність і веде кожен запис глибоким посиланням
до того, чого він стосується. Його відкриття **не** позначає все прочитаним —
скористайтеся **Позначити все як прочитане** в заголовку або позначте окремий
рядок. Стан прочитання супроводжує вашого користувача на всіх пристроях.

:::note[Очистити все — це водяний знак, а не видалення]
**Очистити все** ставить для користувача водяний знак, який ховає все старіше;
рядки залишаються. Окремо кожен робочий простір зберігає лише останні **200**
рядків потоку, які прибираються в міру надходження нових, а дзвіночок
підписується на найновіші **50**, з яких спливне вікно показує до **15**.
Історія за цією межею зникає незалежно від стану прочитання.
:::

## Розв’язання проблем

### Немає системних сповіщень у macOS

Дозвіл запитується нативно під час запуску застосунку. Якщо ви його відхилили,
увімкніть Control Center знову в Системні параметри → Сповіщення; у застосунку
немає запиту, який викликав би його повторно.

### На вебзбірці нічого не надходить

Це очікувано — у вебзбірки немає конвеєра системних сповіщень. Скористайтеся
дзвіночком.

### Бейдж дзвіночка показує нуль, хоча нова активність явно є

Доки після підключення не розв’яжеться потік позначок прочитання, записи
відображаються як прочитані, щоб бейдж не блимав і потім не спорожнів. Усе
стабілізується, коли позначку завантажено.

### Запуск агента завершився, але мене ніхто не сповістив

Перевірте, чи ви не були вже в просторі, де це сталося — активний маршрут
придушує власний системний тост.
