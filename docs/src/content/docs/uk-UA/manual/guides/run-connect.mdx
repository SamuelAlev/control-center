Control Center Connect виконує входи в провайдерів (GitHub, Google Calendar,
Linear, Slack) для серверів, які не зареєстрували власних застосунків. Цей
посібник показує, як запустити власний Connect, щоб застосунки провайдерів, їхні
секрети й список серверів, яким дозволено ними користуватися, залишалися у вас.

Що Connect може й чого не може бачити, описано в
[довідці про Connect](/uk-UA/керівництво/довідка/connect/). Прочитайте її
спершу, якщо вирішуєте, чи запускати власний.

:::note[Можливо, він вам не потрібен]
Один сервер може натомість зареєструвати власні застосунки: **Налаштування →
Сервер → Єдиний вхід → Застосунки провайдера**, де **Створити мій застосунок
GitHub** налаштовує GitHub за один крок. Власні застосунки сервера застосовуються лише за **Використовувати власні застосунки**: з Control Center Connect або власним Connect Connect обслуговує всі канали, а застосунок робочого простору все одно діє. Запускайте Connect, коли кілька серверів мають
користуватися одним набором застосунків.
:::

## Передумови

- Публічна адреса **HTTPS** для Connect, наприклад `https://connect.example.com`,
  за проксі, що термінує TLS. Звичайний `http` приймається лише на loopback
- Docker або `cc_server`, який можна перезапустити з додатковими змінними
  середовища
- Право реєструвати застосунки в кожного провайдера, якого ви хочете обслуговувати
- Сервери, які ним користуватимуться, і їхні власники під рукою: кожен сервер
  має ідентифікатор встановлення, який ви додаєте до списку дозволених Connect

## Крок 1: Виберіть адресу

Виберіть URL зараз і більше його не змінюйте. `CONNECT_PUBLIC_URL` входить в усе,
що робить Connect: до нього прив’язані підписи запитів, запечатані облікові дані,
URL переспрямування провайдерів та ідентифікатор встановлення кожного сервера.
Змінити його пізніше — означає заново зареєструвати переспрямування й змусити
кожну людину ввійти знову.

## Крок 2: Зареєструйте застосунки провайдерів

Реєструйте лише тих провайдерів, яких хочете обслуговувати. Провайдер із неповним
набором змінних виключається з конфігурації Connect, і сервери бачать його
недоступним. Нижче `<base>` — це ваш `CONNECT_PUBLIC_URL`.

| Провайдер      | Що зареєструвати                                                                                                                                                                                                                                                       | Що зберегти                                  |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| **GitHub App** | Callback URL `<base>/oauth/github/callback`. Setup URL `<base>/oauth/github/setup` з увімкненим **Redirect on update**. Залиште **Request user authorization (OAuth) during installation** вимкненим: якщо його ввімкнено, GitHub ігнорує setup URL. Залиште **Expire user authorization tokens** увімкненим | Id застосунку, slug, id клієнта, секрет клієнта |
| **Google**     | Клієнт OAuth типу **Web application** з URI переспрямування `<base>/oauth/google/callback` і ввімкнений Google Calendar API                                                                                                                                          | Id клієнта, секрет клієнта                   |
| **Linear**     | Застосунок OAuth з URL зворотного виклику `<base>/oauth/linear/callback` і `<base>/oauth/linear_app/callback`                                                                                                                                                        | Лише id клієнта                              |
| **Slack**      | Redirect URLs `<base>/oauth/slack_oidc/callback` і `<base>/oauth/slack/callback`. Event Subscriptions за адресою `<base>/v1/hooks/slack/events` (`app_mention`, `message.*`, `assistant_thread_*`, `app_uninstalled`, `tokens_revoked`). Slash-команди за адресою `<base>/v1/hooks/slack/commands`. Ротацію токенів увімкнено | Id застосунку, id клієнта, секрет клієнта, секрет підпису |

Надайте GitHub App такі дозволи на репозиторій: **Metadata** — читання,
**Contents** — читання й запис, **Pull requests** — читання й запис, **Issues** —
читання й запис, **Checks**, **Actions** і **Commit statuses** — читання. Для
запитів на рев’ю від команд додайте дозвіл організації **Members** на читання.
Вебхуки можна залишити вимкненими: сервери опитують.

Connect ніколи не потребує приватного ключа GitHub App. Натомість він випускає
токени для одного репозиторію з власного входу людини. Linear теж не потребує
секрету: Connect повертає код серверу, який сам завершує обмін.

## Крок 3: Зберіть ідентифікатори встановлення

Connect відповідає лише серверам зі свого списку дозволених. На кожному сервері
спрямуйте його на свій Connect, а потім прочитайте його ідентифікатор
встановлення:

1. Відкрийте **Налаштування → Сервер → Єдиний вхід**, відкрийте картку **Control
   Center Connect** і виберіть **Використовувати власний сервер Connect**
2. Введіть свій URL і збережіть. Картка покаже **Ідентифікатор встановлення**
   сервера

З термінала на хості сервера те саме виглядає так:

```bash
cc_server connect enable --url https://connect.example.com
cc_server connect status
```

`status` друкує ідентифікатор встановлення. Доки не виконано крок 5, він показує
`install_blocked`, і це очікувано.

Ідентифікатор встановлення виводиться для кожної адреси Connect окремо, тож той
самий сервер має для кожного Connect, з яким спілкується, власний
ідентифікатор. Він змінюється лише тоді, коли власник сервера змінює ключ.

## Крок 4: Створіть ключ печатки

Connect шифрує всі облікові дані, які повертає, ключем печатки. Створіть його й
зберігайте як файл із секретом:

```bash
docker run --rm ghcr.io/samuelalev/cc-connect:latest \
  cc-connect-config seal-key > seal_keys
chmod 600 seal_keys
```

Втрата ключа печатки виводить усіх із системи: без нього жодну печатку не
відкрити.

## Крок 5: Запустіть контейнер

Кожен випуск публікує `ghcr.io/samuelalev/cc-connect` із підтвердженням
походження збірки. У продакшені закріплюйте тег версії.

```bash
docker run -d --name cc-connect -p 8790:8790 \
  -e CONNECT_PUBLIC_URL=https://connect.example.com \
  -e CONNECT_ALLOWED_INSTALLS=<install id>,<install id> \
  -e CONNECT_SEAL_KEYS_FILE=/run/secrets/seal_keys \
  -v "$PWD/seal_keys:/run/secrets/seal_keys:ro" \
  -e CONNECT_GITHUB_APP_ID=123456 \
  -e CONNECT_GITHUB_APP_SLUG=acme-control-center \
  -e CONNECT_GITHUB_CLIENT_ID=Iv23li0123456789abcd \
  -e CONNECT_GITHUB_CLIENT_SECRET_FILE=/run/secrets/github \
  -v "$PWD/github_secret:/run/secrets/github:ro" \
  -v cc-connect-data:/data \
  ghcr.io/samuelalev/cc-connect:latest
```

Спрямуйте зворотний проксі на порт `8790`. Образ працює від непривілейованого
користувача, зберігає свій стан у томі `/data` і має вбудовану перевірку
працездатності (`cc-connect --healthcheck`, яка опитує `/healthz`).

Connect відмовляється запускатися (код виходу `78`), якщо його конфігурація
відкрита, небезпечна або незавершена, і друкує, яка змінна неправильна. Його
зупиняють відсутній список дозволених, адреса `http` не на loopback,
некоректний ключ печатки або одночасно задані `NAME` і `NAME_FILE`.

Контрольна точка: на кожному сервері картка Connect показує **Працює**, а **Де
виконується кожен вхід** називає **Connect** для кожного зареєстрованого вами
провайдера. `cc_server connect status` друкує `Health: ok` і ті самі канали.

## Змонтувати Connect усередині cc_server

Сервер може сам розміщувати Connect замість окремого контейнера. Змонтований
сервіс — той самий, що запускає образ.

1. Помістіть змінні `CONNECT_*` у файл `.env` сервера (або в його середовище),
   як на кроці 5
2. Додайте `CC_SERVER_CONNECT_HOST=on`
3. Перезапустіть сервер. Його журнал надрукує `embedded Connect at <url>`

```bash
CC_SERVER_CONNECT_HOST=on
CONNECT_ALLOWED_INSTALLS=<install id>
CONNECT_SEAL_KEYS=<output of cc-connect-config seal-key>
CONNECT_GITHUB_APP_ID=123456
CONNECT_GITHUB_APP_SLUG=acme-control-center
CONNECT_GITHUB_CLIENT_ID=Iv23li0123456789abcd
CONNECT_GITHUB_CLIENT_SECRET=<secret>
```

Після цього Connect обслуговується за адресою `<server>/connect`:

- `CONNECT_PUBLIC_URL` типово — джерело публічного URL сервера плюс `/connect`.
  За проксі задайте його явно. Його шлях має бути рівно `/connect`, і він має
  бути HTTPS, якщо це не loopback
- До змонтованого сервісу доходять лише змінні `CONNECT_*`, тож він ніколи не
  позичає власні застосунки провайдерів сервера
- `CONNECT_ALLOWED_INSTALLS` і далі обов’язковий, зокрема для самого сервера,
  що розміщує Connect
- Неправильно налаштоване монтування не дає серверу завантажитися, а не
  обслуговує відкритого брокера
- Демонстраційний сервер його ніколи не монтує

Зареєструйте переспрямування провайдерів на `https://<server>/connect`, потім
спрямуйте сервери (включно з тим, що розміщує) на цей URL, як на кроці 3.

## Довідник конфігурації

Кожне налаштування — це змінна середовища. Будь-який секрет можна натомість
брати зі змонтованого файлу: задайте `NAME_FILE` замість `NAME`. Connect
перечитує файл не частіше ніж раз на 30 секунд і зберігає останнє коректне
значення. Секрети з позначкою **подвійний** під час зміни також приймають
`NAME_PREVIOUS` (або `NAME_PREVIOUS_FILE`).

### Адреса й доступ

| Змінна                          | Типово       | Значення                                                                                                                       |
| ------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `CONNECT_PUBLIC_URL`            | обов’язкова  | Канонічний публічний URL. HTTPS або `http` лише на loopback. Шлях означає монтування. Без query і фрагмента                    |
| `CONNECT_ALLOWED_INSTALLS`      | обов’язкова  | Ідентифікатори встановлення через кому. `*` приймається лише разом із `CONNECT_SIGNED_CONFIG_FILE`                             |
| `CONNECT_DENY_INSTALLS`         |              | Ідентифікатори встановлення, яким відмовляють, навіть якщо їх дозволено                                                        |
| `CONNECT_GITHUB_ALLOWED_OWNERS` |              | Числові id власників GitHub. Якщо задано, токени репозиторіїв випускаються лише для репозиторіїв, що їм належать               |
| `CONNECT_HOST`, `CONNECT_PORT`  | `0.0.0.0`, `8790` | Адреса прив’язки й порт                                                                                                   |
| `CONNECT_TRUST_PROXY`           | `0`          | Довірені переходи проксі в `X-Forwarded-For` (від 0 до 8). Використовується лише для ліміту запитів на адресу                  |

### Канали провайдерів

| Змінна                                                                      | Типово       | Значення                                                                     |
| --------------------------------------------------------------------------- | ------------ | ---------------------------------------------------------------------------- |
| `CONNECT_GITHUB_APP_ID`, `CONNECT_GITHUB_APP_SLUG`, `CONNECT_GITHUB_CLIENT_ID` |           | GitHub App                                                                   |
| `CONNECT_GITHUB_CLIENT_SECRET`                                              |              | Секрет, подвійний                                                            |
| `CONNECT_GOOGLE_CLIENT_ID`, `CONNECT_GOOGLE_CLIENT_SECRET`                  |              | Клієнт Google. Секрет подвійний                                              |
| `CONNECT_LINEAR_CLIENT_ID`                                                  |              | Застосунок Linear. Без секрету                                               |
| `CONNECT_SLACK_APP_ID`, `CONNECT_SLACK_CLIENT_ID`                           |              | Застосунок Slack                                                             |
| `CONNECT_SLACK_CLIENT_SECRET`, `CONNECT_SLACK_SIGNING_SECRET`               |              | Секрети, подвійні                                                            |
| `CONNECT_KLIPY_APP_KEY`                                                     |              | Ключ пошуку GIF Klipy. Секрет, подвійний                                     |
| `CONNECT_KLIPY_MODE`                                                        | `proxy`      | `proxy` залишає ключ у Connect; `key` передає його серверам                  |
| `CONNECT_<LANE>_SECRET_GENERATION`                                          | `1`          | GitHub, Google і Slack: покоління, що записується в нові печатки             |

## Запустити кілька екземплярів

Більшості організацій достатньо одного екземпляра з `CONNECT_STATE=memory`.
Кільком екземплярам за однією адресою потрібен `CONNECT_STATE=redis` і або
спільний `CONNECT_DATA_DIR`, або `CONNECT_BINDINGS=firestore`, щоб вхід, розпочатий
на одному екземплярі, міг завершитися на іншому.

## Змінити секрет провайдера

Ніхто не виходить із системи:

1. Створіть новий секрет у провайдера й збережіть старий
2. Перенесіть старе значення в `NAME_PREVIOUS`, помістіть нове в `NAME` і
   збільште `CONNECT_<LANE>_SECRET_GENERATION`. Змонтовані файли
   підхоплюються протягом 30 секунд
3. Дочекайтеся оновлення входів, потім видаліть старий секрет у провайдера й
   приберіть `NAME_PREVIOUS`

Щоб змінити ключ печатки, поставте новий запис `cc-connect-config seal-key`
першим у `CONNECT_SEAL_KEYS` і збережіть старий, доки його печатки не
оновляться.

## Замінити застосунок

Сервери запам’ятовують id застосунку й клієнта, які ваш Connect оголосив, коли
вони вперше ним скористалися. Якщо ви заміните застосунок, картка Connect на
кожному сервері покаже **Застосунки Connect змінилися**, і входи через Connect
призупиняться, доки власник сервера не натисне **Довіряти новим застосункам**.
Попередьте власників серверів перед перемиканням, щоб вони знали, що це запит
від вас.

## Заблокувати сервер

Додайте його ідентифікатор встановлення в `CONNECT_DENY_INSTALLS` і
перезапустіть. Його власник побачить «Connect заблокував ідентифікатор
встановлення цього сервера», і всі входи через Connect на ньому зупиняться.

## Усунення несправностей

### Сервер повідомляє, що Connect його заблокував

Його ідентифікатора встановлення немає в `CONNECT_ALLOWED_INSTALLS`, або він є в
`CONNECT_DENY_INSTALLS`. Ідентифікатор змінюється, коли власник сервера змінює
ключ; попросіть новий.

### Провайдер показано як недоступний

Бракує однієї з його змінних, тож Connect виключив канал. Перевірте журнал
запуску й таблиці вище. GitHub потрібні всі чотири значення: id застосунку,
slug, id клієнта й секрет клієнта; Google потрібні і id клієнта, і секрет.

### Входи завершуються помилкою невідповідності переспрямування

Переспрямування, зареєстроване в провайдера, не збігається точно з
`CONNECT_PUBLIC_URL`. Порівняйте схему, хост, порт і шлях `/connect` для
змонтованого Connect.

### Усім довелося ввійти знову

Ключ печатки змінився або втрачений, сервер змінив свій ключ, або дані сервера
відновили на іншій машині. Запечатані облікові дані відкриваються лише для того
встановлення й того Connect, які їх створили.
