Цей посібник показує, де зберігаються кожні облікові дані, які використовує
Control Center, і як їх змінити.

**Нічого не зберігається на машині, з якої ви працюєте.** Кожні облікові дані
живуть на сервері; які саме відповідають на конкретний запит, залежить від
того, чи стоїть за ним людина.

| Облікові дані                                | Де зберігаються                                                                 | Хто їх використовує                                                           |
| -------------------------------------------- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Ваші облікові дані хостингу коду / тікетингу | Файл секретів 0600 на сервері, прив’язаний до ідентифікатора вашого користувача | Усе, що ви просите: поверхня PR, запуски ваших агентів, ваші образи           |
| Ідентичність застосунку сервера              | Той самий файл, плюс `server_settings` для несекретних даних                    | Робота, якої не просила людина: вебхуки, опитування PR, синхронізація тікетів |
| Ключі постачальників моделей і токени OAuth  | Власне сховище облікових даних сервера                                          | Вбудований адаптер, для кожного робочого простору в інсталяції                |
| Токени ботів Slack                           | `<dataDir>/<workspaceId>/chat_credentials/` на сервері                          | Чат-міст для цього робочого простору                                          |
| Облікові дані зовнішніх CLI                  | Те, що використовує цей CLI                                                     | Claude Code, на хості сервера                                                 |

## Два типи облікових даних GitHub, які відповідають на різні питання

- **Ваші** — з входу (device flow) або вставленого токена. Саме їх використовує
  кожен запит, зроблений *від вашого імені*, тож коментар, опублікований за вас,
  несе ваше ім’я. Інший учасник не може їх прочитати й підключає власні
- **Серверні** — від GitHub App, який зареєстрував оператор. Вони відповідають
  на все, де немає викликача, — тож доступ до хостингу коду не зникає, коли
  хтось іде чи змінює токен

Ваші задаються в картці **Хостинг коду** за шляхом **Налаштування → Робочий
простір → Профіль і ідентичність**; серверні — у **Застосунки провайдера** за
шляхом **Налаштування → Сервер → Єдиний вхід**. Див. [Налаштувати інтеграцію
GitHub](/uk-UA/керівництво/практичні-посібники/інтеграція-github/) і [Створити
GitHub App](/uk-UA/керівництво/практичні-посібники/github-app/).

:::note[Існує також екран, доступний лише за URL]
`/workspaces/<workspaceId>/api-keys` показує ті самі дві картки, що й перший
крок онбордингу. Він **не має жодного запису в навігації інтерфейсу**; до нього
можна дістатися лише, ввівши URL. Натомість скористайтеся Налаштування →
Робочий простір → Профіль і ідентичність.
:::

## Задайте ключі постачальників моделей

Вбудований адаптер сам автентифікує провайдерів, і ці облікові дані зберігаються
на сервері.

1. Перейдіть до **Налаштування → Сервер → Постачальники моделей**
2. Прокрутіть до **Провайдери й моделі**
3. Підключіть провайдера — OAuth у браузері для OpenAI, Codex, Cursor і Kimi
   Code; API-ключ для Anthropic та решти

Повний список і додавання власного ендпоінта див. у [Керувати адаптерами та
моделями](/uk-UA/керівництво/практичні-посібники/адаптери/).

Ці облікові дані **глобальні для хоста**: один ключ обслуговує кожен робочий
простір в інсталяції. Токени OAuth оновлюються до завершення їхнього терміну дії.

Зовнішні CLI адаптерів тримають власні облікові дані у власній конфігурації на
хості сервера — Control Center ними не керує. Автентифікуйте Claude Code так, як
каже його власна документація, на машині, де працює `cc_server`.

Діалог **Змінні середовища**, що належить окремому адаптеру, виглядає як місце,
де можна покласти ключ для одного з них, але це не так: він пише на ваш
пристрій, а сервер читає власну копію, і ніщо ці дві не з’єднує. Див.
[Керувати адаптерами та моделями](/uk-UA/керівництво/практичні-посібники/адаптери/).

## Підключіть провайдера тікетів

Картка **Тікетинг** за шляхом **Налаштування → Робочий простір → Загальні**
містить обидві половини одного рішення: у якого провайдера живуть ваші тікети і
які облікові дані для нього. Вибір **Локально** ховає рядок облікових даних —
локальні тікети живуть у власній базі даних цього сервера, і автентифікуватися
їм ні до чого.

Ваш ключ зберігається на сервері з прив’язкою до ідентифікатора вашого
користувача, як і ключ хостингу коду. Сервер окремо тримає власний ключ Linear
(**Застосунки провайдера**) — саме на ньому працює синхронізація тікетів, коли
її не просила людина. Жоден ключ тікетингу не вставляється в пісочницю агента;
агенти пишуть тікети через інструменти Control Center, які запитують правило
**Запис у зовнішній трекер**. Див. [Налаштувати
інтеграцію Linear](/uk-UA/керівництво/практичні-посібники/інтеграція-linear/).

## Змініть або відкличте

- **Ваші облікові дані GitHub**: натисніть **Від’єднатися**, потім увійдіть
  знову або вставте новий токен. Відкличте старий на GitHub
- **Застосунок сервера**: згенеруйте новий приватний ключ або клієнтський секрет
  на сторінці застосунку в GitHub, вставте його в **Застосунки провайдера** і
  натисніть **Тест**
- **Постачальник моделей**: у його рядку вийдіть (OAuth) або видаліть ключ, потім
  підключіть знову
- **Slack**: вставте токени заново в діалозі підключення. Див. [Налаштувати
  інтеграцію Slack](/uk-UA/керівництво/практичні-посібники/інтеграція-slack/)

## Усунення проблем

### Список PR порожній, але мій токен працює в `curl`

Перевірте підзаголовок рядка **Хостинг коду**. Якщо там названо інше джерело
(«через застосунок цього сервера», «із середовища»), то облікові дані, які ви
перевіряєте, — не ті, що відповідають: ваші не збереглися.

### Токен приймається, але наступні запити не проходять

Токен перевіряють таким, як він збережений, тож рядок називає обліковий запис за
ним — але лише запис, не області доступу. Токен із надто вузькими областями
доступу підключається, а потім не проходить окремі запити. Перевірте області
доступу та термін дії:

```bash
curl -H "Authorization: token YOUR_TOKEN" https://api.github.com/user
```
