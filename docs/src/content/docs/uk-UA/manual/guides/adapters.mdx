Цей посібник показує, як підключити провайдерів моделей і вибрати, на чому
працює агент.

Усе це зібрано на одній сторінці: **Налаштування → Сервер → Постачальники моделей**.
Запис у бічному підменю читається як «Постачальники моделей», а заголовок
сторінки — «Адаптери».

## Що таке адаптер

Адаптер — це _раннер_, який виконує хід агента. Їх два, і цей список
фіксований — третього додати не можна.

| Адаптер                    | CLI      | Транспорт                                                           |
| -------------------------- | -------- | ------------------------------------------------------------------- |
| Control Center (вбудований) | немає    | Цикл агента в межах процесу, спілкується з провайдерами через HTTP  |
| Claude Code                | `claude` | `claude -p --output-format stream-json`                             |

Cursor, Codex, Anthropic, OpenAI та решта — це **провайдери** на вбудованому
адаптері, а не окремі CLI. Додати ви _можете_ ще одного провайдера — будь-яку
кінцеву точку, сумісну з OpenAI або Anthropic. Про це в наступному розділі.

:::note[Виявлення перевіряє сервер, а не вашу машину]
Картка **Виявлені раннери** перелічує те, що `cc_server` знайшов у `PATH`
_хоста сервера_. На тонкому або вебклієнті це інша машина, ніж та, на яку ви
дивитеся. Встановіть CLI на машині, де запущено `cc_server`.
:::

## Підключити провайдера моделей

Вбудованому адаптеру потрібен щонайменше один підключений провайдер, щоб він міг
працювати. У каталозі їх постачається чотирнадцять.

1. Перейдіть у **Налаштування → Сервер → Постачальники моделей**
2. Прокрутіть до **Провайдери й моделі**
3. Знайдіть свого провайдера й підключіть його:

| Провайдер                                                                                                | Як підключити                                                                                                                   |
| -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Anthropic                                                                                                | API-ключ. Підписка Claude Pro/Max — це не вхід в Anthropic API; для цього плану використовуйте адаптер Claude Code               |
| OpenAI, Codex, Cursor                                                                                    | Вхід через OAuth у браузері або API-ключ. Codex — це ChatGPT Plus/Pro через бекенд Codex Responses, а не запуск CLI              |
| Kimi Code                                                                                                | Лише OAuth у браузері — потік із кодом пристрою. Це план із фіксованою оплатою, тож ціни за токен немає                          |
| OpenRouter, Google Gemini, DeepSeek, Mistral, xAI, z.ai, z.ai GLM Coding Plan, Moonshot (Kimi API)       | API-ключ                                                                                                                        |

Контрольна точка: значок у рядку змінюється на «Підключено», а після
розгортання рядка з’являється список моделей, які обслуговує цей провайдер, —
кожна з ціною за мільйон токенів і вікном контексту.

Токени OAuth потрапляють у власне сховище облікових даних сервера й оновлюються
до завершення строку їхньої дії. Облікові дані провайдерів **глобальні для
хоста** — ними спільно користуються всі робочі простори цієї інсталяції, а не
лише один.

### Додати користувацького провайдера

Скористайтеся цим для Ollama, LM Studio, vLLM або приватного розгортання.

1. У розділі **Провайдери й моделі**, під **Користувацькі провайдери**, натисніть **Додати провайдера**
2. Заповніть **назву**, виберіть **Тип API** (сумісний з OpenAI або
   сумісний з Anthropic) і вкажіть **Базовий URL** (наприклад,
   `http://localhost:11434/v1`)
3. Додайте **API-ключ**, якщо кінцева точка його потребує, а потім натисніть **Додати провайдера**

Користувацький провайдер з’являється в тому самому списку, з кнопкою видалення,
якої немає в його вбудованих побратимів.

## Вибрати модель для агента

1. Перейдіть у **Налаштування → Робочий простір → Агенти** і виберіть агента
2. На вкладці **Налаштування** виберіть **адаптер**
3. Виберіть **модель** зі спадного меню поруч

Для вбудованого адаптера спадне меню збирається наживо з власного каталогу
кожного підключеного провайдера. Провайдер без збережених облікових даних не
додає жодної моделі, тож порожнє спадне меню майже завжди означає «ще нічого не
підключено», а не «нічого немає».

:::note[models.dev — це збагачення, а не джерело ідентифікаторів]
Вбудований каталог [models.dev](https://models.dev) дає ціну та вікно контексту
для моделі, яка вже є в живому списку. Він ніколи не додає ідентифікатор моделі.
Якщо очікуваної моделі немає, отже, кінцева точка провайдера її не повертає.
:::

Ідентифікатори моделей для вбудованого адаптера мають вигляд `provider/model` і
можуть нести ланцюжок запасних варіантів, розділених `|`. За наявності запасного
варіанта вартість рахується за моделлю, яка насправді обслужила хід, а не за
тією, яку ви запросили.

:::note[Агент без адаптера працює на вбудованому циклі]
Кожен робочий простір початково створює п’ять агентів — CEO плюс `qa`,
`architect`, `engineer` і `librarian` — без адаптера й без моделі. Диспетчеризація
повертається до **Control Center (вбудований)**, а не до налаштування
**Типові раннери** на цій сторінці, яке є клієнтською перевагою, що її шлях
диспетчеризації ніколи не читає. Журнал запусків записує для таких запусків
`cc-harness`, тож у транскрипті видно, що насправді виконувалося.

Якщо й моделі немає, вбудований цикл запитує в Anthropic її типову модель. Тож
повністю незаданий агент працює, якщо ви підключили обліковий запис Anthropic, а
інакше завершується помилкою `No credential for provider "anthropic"`.

Завершення кроку вибору адаптера під час початкового налаштування заднім числом
оновлює **кожного** агента, якому ще бракує адаптера чи моделі — CEO і фахівців,
у кожному робочому просторі, що існує на ту мить, — парою, яку ви вибрали. Робочі
простори, створені пізніше, усе одно початково створюють усіх п’ятьох незаданими.
Задавайте адаптер і модель явно для кожного агента, якого маєте намір
використовувати.
:::

## Встановити CLI раннера

Вбудований адаптер не потребує встановлення. Для Claude Code встановіть його
CLI **на хості сервера** за допомогою власного менеджера пакетів цього
інструмента, наприклад:

```bash
npm install -g @anthropic-ai/claude-code
```

Потім натисніть **Оновити** вгорі сторінки. Кожен виявлений рядок показує
визначену версію та шлях, а також мітки того, чи підтримує він режим JSON і вибір
моделі.

Зовнішній CLI зберігає власні облікові дані у власній конфігурації на хості
сервера. Control Center ними не керує.

:::caution[Аргументи адаптера та змінні середовища залишаються на цьому пристрої]
Кожен рядок адаптера пропонує поле **Аргументи** та діалог **Змінні
середовища**. Ці значення зберігаються на вашому пристрої. Сервер читає argv і
env запуску зі свого сховища налаштувань. Розміщуйте ключі провайдерів на
сервері (OAuth або поле ключа на сторінці «Постачальники моделей»), а не в цих
двох полях.
:::

## Обмежити, яких провайдерів може використовувати робочий простір

Керування провайдерами — на рівні робочого простору, і застосовується правило
«перемагає останній збіг».

1. У розділі **Провайдери й моделі** вимкніть перемикач **Дозволити** у рядку провайдера

Це записує для цього провайдера твердження `deny` в активному робочому просторі,
і його моделі випадають з каталогу цього робочого простору. Повторне ввімкнення
перемикача прибирає твердження.

## Усунення несправностей

### Раннер позначено як «не знайдено»

- Переконайтеся, що CLI є в `PATH` **хоста сервера**, а не лише у вашому
- Настільний застосунок, запущений із графічного середовища, породжує свій сервер
  із мінімальним `PATH`; CLI, встановлений у шляху, доступному лише з оболонки,
  може бути для нього невидимим
- Натисніть **Оновити** після встановлення

### Спадне меню моделей порожнє

- Адаптер вбудований, і жодного провайдера не підключено — підключіть його в
  розділі **Провайдери й моделі**
- Або провайдера підключено, але його відхилено перемикачем керування цього
  робочого простору

### Модель працює, але ціна позначена як невідома

Живий список моделей містить ідентифікатор; ціна й контекст надходять із
models.dev. Зовсім нова модель або модель від користувацького провайдера ще не
має запису в каталозі.
