Цей посібник показує, як під’єднати зовнішній клієнт MCP — Claude Code,
редактор, MCP Inspector — до власного сервера інструментів Control Center.

Control Center реєструє **110** інструментів і обслуговує їх через Model Context
Protocol за версією протоколу `2024-11-05`. Цілих родин інструментів, яких можна
було б очікувати, тут немає: немає інструментів зустрічей чи календаря й немає
інструментів проєктів.

## Знайти кінцеву точку

Поверхня MCP використовує той самий слухач, що й основний `cc_server`. Окремого
порту MCP немає.

| Кінцева точка | Метод    | Призначення                                            |
| ------------- | -------- | ------------------------------------------------------ |
| `/mcp`        | `POST`   | Транспорт Streamable HTTP — саме ним спілкується клієнт |
| `/mcp`        | `DELETE` | Завершити сесію                                        |
| `/sse`        | `GET`    | Потік сповіщень від сервера                            |

Отже, типова локальна інсталяція доступна за адресою `http://127.0.0.1:9030/mcp`.

1. Перейдіть у **Налаштування → Сервер → MCP-сервери**
2. Подивіться на картку **MCP-сервер** — вона показує, чи він працює чи
   зупинений, і порт, який він слухає

Поверхня типово увімкнена на чистій інсталяції, тож loopback-клієнт працює без
жодного втручання в налаштування. **Запускати разом із додатком** визначає, чи
повернеться вона після перезапуску; **Запустити** / **Зупинити** — це керування
сесією, яке не змінює цього налаштування.

Сервер типово прив’язується до loopback, тож кінцева точка доступна лише з
машини, на якій працює `cc_server`, якщо ви не запустили його з `--bind any`.

## Під’єднати клієнт

Спрямуйте клієнт на кінцеву точку Streamable HTTP. Точна форма конфігурації —
справа вашого клієнта; URL однаковий в обох випадках.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp"
    }
  }
}
```

### Claude Code

Claude Code не підхопить це з проєктного `.mcp.json` — він закриває MCP-сервери
рівня проєкту запитом на схвалення, на який неінтерактивний `claude -p` ніколи
не відповідає. Передайте конфігурацію явно:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` змушує Claude використовувати лише цей файл, тож той самий
сервер не буде ще й знайдено з проєкту та зареєстровано двічі.

Контрольна точка: попросіть клієнт перелічити свої інструменти. Ви маєте
побачити записи `mcp__*`, що охоплюють тікети, простори, пам’ять, граф коду та
перевірку.

## Обслуговувати MCP поза межами хоста

1. У розділі **Налаштування → Сервер → MCP-сервери**, у рядку **Токен
   автентифікації**, натисніть **Задати** і вставте токен
2. Надсилайте його як `Authorization: Bearer <token>` у кожному запиті
   `POST /mcp`

Поверхня без токена відхиляє будь-який не-loopback виклик із кодом 403. Це
задумано як відмова закрито: саме токен робить обслуговування поза хостом
узагалі можливим.

Зміни токена застосовуються до живої поверхні негайно — без перезапуску.

:::note[`GET /sse` приймає токен у рядку запиту]
Потік сповіщень перевіряють на токен, як і будь-який інший маршрут, але
браузерний `EventSource` не може надіслати заголовок `Authorization` — тож
`/sse` приймає токен і як `?token=<token>`. Без нього він відповідає 401.
:::

## Прив’язувати кожен виклик до робочого простору

Кожен інструмент, що торкається даних рівня робочого простору, вимагає
`workspace_id`, і виклик без нього відхиляють, а не зіставляють із якимось
«поточним» робочим простором:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

Це той id, що в URL вашого браузера чи застосунку:
`/workspaces/<workspace_id>/…`. Єдині винятки — інструменти, які справді
охоплюють кілька робочих просторів, як-от `list_workspaces` і інструменти
стрічки новин: стрічка новин — персональна для кожного користувача, а агент не
має власного користувача, тож ці інструменти працюють зі стрічками власника
сервера.

Інструменти рівня репозиторію додатково перевіряють, що репозиторій прив’язано
до цього робочого простору.

## Знати, що поверхня відхилить

- **Шлюз режиму.** Виклик зіставляють із режимом простору агента, що викликає,
  на боці сервера. Агент у режимі лише для читання не дістанеться до інструмента
  запису, опустивши `space_id` — натомість режим беруть з його активного запуску.
- **Обмеження дій.** Інструменти, що змінюють стан, оголошують свої класи
  ефектів і проходять ту саму політику, яку використовує решта продукту. Див.
  [Налаштувати обмеження](/uk-UA/керівництво/практичні-посібники/налаштувати-обмеження/).
- **Підтвердження.** Деякі руйнівні інструменти будують дані підтвердження, які
  треба схвалити, перш ніж виклик продовжиться.

Повний каталог оголошується в `tools/list` без шлюзу виявлення — зовнішній
клієнт MCP відмовляється викликати інструмент, якого немає в його кешованому
списку, тож приховування інструментів їх ламає, а не впорядковує.

## Усунення несправностей

### Клієнт не бачить жодного інструмента

- Перевірте, що картка **MCP-сервер** показує, що він працює
- Перевірте, чи порт збігається з портом вашого `cc_server`
- У Claude Code перевірте, чи ви передали `--mcp-config` і `--strict-mcp-config`

### 403 із машини, яка не є сервером

Bearer-токен не налаштовано. Задайте його й надсилайте.

### Виклик інструмента падає з «Missing or invalid argument: workspace_id»

Додайте `workspace_id`. Неявного робочого простору не існує.

### Виклик інструмента відхилено як невідомий

Каталог наведено в [Інструменти MCP](/uk-UA/керівництво/довідка/інструменти-mcp/).
Викликайте назву точно так, як вона там записана.
