Цей посібник показує, як під’єднати зовнішній клієнт MCP — Claude Code,
редактор, MCP Inspector — до власного сервера інструментів Control Center.

Control Center реєструє **110** інструментів і обслуговує їх через Model Context
Protocol за версією протоколу `2024-11-05`. Цілих родин інструментів, яких можна
було б очікувати, тут немає: немає інструментів зустрічей чи календаря й немає
інструментів проєктів.

## Знайти кінцеву точку

Поверхня MCP використовує той самий слухач, що й основний `cc_server`. Окремого
порту MCP немає.

| Кінцева точка | Метод    | Призначення                                            |
| ------------- | -------- | ------------------------------------------------------ |
| `/mcp`        | `POST`   | Транспорт Streamable HTTP — саме ним спілкується клієнт |
| `/mcp`        | `DELETE` | Завершити сесію                                        |
| `/sse`        | `GET`    | Потік сповіщень від сервера                            |

Отже, типова локальна інсталяція доступна за адресою `http://127.0.0.1:9030/mcp`.

1. Перейдіть у **Налаштування → Сервер → MCP-сервери**
2. Подивіться на картку **MCP-сервер** — вона показує, чи він працює чи
   зупинений, і порт, який він слухає

Поверхня типово увімкнена на чистій інсталяції. Токен картки бачить лише власник
сервера, і лише він може запускати або зупиняти кінцеву точку. **Запускати разом
із додатком** визначає, чи повернеться вона після перезапуску; **Запустити** /
**Зупинити** — це керування сесією, яке не змінює цього налаштування.

Сервер типово прив’язується до loopback, тож кінцева точка доступна лише з
машини, на якій працює `cc_server`, якщо ви не запустили його з `--bind any`.

## Отримайте токен

Кожен запит потребує MCP-токена сервера з будь-якої машини, включно з loopback.
Сервер створює його під час першого запуску. Вимкнути його або очистити не можна.

1. У **Налаштування → Сервер → MCP-сервери** знайдіть рядок **Токен автентифікації**
2. Натисніть **Показати токен** і скопіюйте його
3. Щоб замінити його, натисніть **Замінити токен**. Сервер одразу перемикається на
   новий токен, а кожен клієнт, який досі використовує старий, відхиляється, доки
   ви не дасте йому новий

## Під’єднати клієнт

Спрямуйте клієнт на кінцеву точку Streamable HTTP і надсилайте токен як
`Authorization: Bearer <token>` у кожному запиті, включно з `GET /sse`. Іншого
способу надіслати його немає: токен у URL не приймається. Точна форма
конфігурації — справа вашого клієнта.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code не підхопить це з проєктного `.mcp.json` — він закриває MCP-сервери
рівня проєкту запитом на схвалення, на який неінтерактивний `claude -p` ніколи
не відповідає. Передайте конфігурацію явно:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` змушує Claude використовувати лише цей файл, тож той самий
сервер не буде ще й знайдено з проєкту та зареєстровано двічі.

Контрольна точка: попросіть клієнт перелічити свої інструменти. Ви маєте
побачити записи `mcp__*`, що охоплюють тікети, простори, пам’ять, граф коду та
перевірку.

## Що кінцева точка відхиляє

Токен відкриває кожен інструмент на сервері, тож кінцева точка також відхиляє все,
що могла надіслати вебсторінка, ще до перевірки токена:

| Запит                                                                   | Відповідь |
| ----------------------------------------------------------------------- | --------- |
| Заголовок `Origin`, що не є сторінкою цієї машини (`http://localhost`, `http://127.0.0.1` або `http://[::1]`, будь-який порт) | `403`, «Міжджерельні запити не приймаються» |
| Заголовок `Host`, який не є ані loopback-адресою та портом цього слухача, ані публічним іменем хоста сервера | `403`, «Невідомий хост» |
| `POST`, тіло якого не є `application/json`                              | `415`     |
| Немає токена або токен неправильний                                     | `401`     |

Щоб обслуговувати MCP поза межами хоста, запустіть сервер з `--bind any` і
надсилайте токен з іншої машини, звертаючись до сервера за його публічним іменем
хоста.

## Прив’язувати кожен виклик до робочого простору

Кожен інструмент, що торкається даних рівня робочого простору, вимагає
`workspace_id`, і виклик без нього відхиляють, а не зіставляють із якимось
«поточним» робочим простором:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

Це той id, що в URL вашого браузера чи застосунку:
`/workspaces/<workspace_id>/…`. Єдині винятки — інструменти, які справді
охоплюють кілька робочих просторів, як-от `list_workspaces` і інструменти
стрічки новин: стрічка новин — персональна для кожного користувача, а агент не
має власного користувача, тож ці інструменти працюють зі стрічками власника
сервера.

Інструменти рівня репозиторію додатково перевіряють, що репозиторій прив’язано
до цього робочого простору.

## Знати, що поверхня відхилить

- **Шлюз режиму.** Виклик зіставляють із режимом простору агента, що викликає,
  на боці сервера. Агент у режимі лише для читання не дістанеться до інструмента
  запису, опустивши `space_id` — натомість режим беруть з його активного запуску.
- **Обмеження дій.** Інструменти, що змінюють стан, оголошують свої класи
  ефектів і проходять ту саму політику, яку використовує решта продукту. Див.
  [Налаштувати обмеження](/uk-UA/керівництво/практичні-посібники/налаштувати-обмеження/).
- **Підтвердження.** Деякі руйнівні інструменти будують дані підтвердження, які
  треба схвалити, перш ніж виклик продовжиться.

Повний каталог оголошується в `tools/list` без шлюзу виявлення — зовнішній
клієнт MCP відмовляється викликати інструмент, якого немає в його кешованому
списку, тож приховування інструментів їх ламає, а не впорядковує.

## Персональні сервери MCP залишаються за власником

Ця інструкція — про власну кінцеву точку Control Center. Інший напрям — сервери
MCP, які Control Center передає агентам, яких запускає, — перелічено в
**Налаштування → Сервер → MCP-сервери → Зовнішні MCP-сервери**. Сервери, налаштовані
на машині сервера для Claude, Codex, Cursor, Gemini, VS Code, Windsurf, OpenCode
або в `.mcp.json`, знаходяться там автоматично.

Ці знайдені сервери походять із власної конфігурації інструментів користувача
сервера і діють з його особою та обліковими даними, тож вони належать власнику
сервера:

- Вони доступні лише всередині вбудованих запусків harness, які запускає або за
  які відповідає власник сервера, зокрема автоматизації в робочому просторі, за
  який відповідає власник.
- Запуск учасника, автоматизація, прив’язана до учасника, і кожен запуск на
  сервері без записаного власника не отримують жодного з них. Там інструменти не
  перелічуються, не можуть бути викликані й не з’являються в пошуку інструментів.
- Ця кінцева точка ніколи не перелічує, не викликає й не шукає їх ні для кого,
  включно з токеном власника, і не передає їхні ресурси чи промпти. Тож агентський
  CLI, який під’єднується до Control Center через MCP, як-от Claude Code, не
  отримує їх і через Control Center; він користується власною конфігурацією.

Сервери MCP, налаштовані для робочого простору, на це ніяк не впливають.

## Усунення несправностей

### Клієнт не бачить жодного інструмента

- Перевірте, що картка **MCP-сервер** показує, що він працює
- Перевірте, чи порт збігається з портом вашого `cc_server`
- У Claude Code перевірте, чи ви передали `--mcp-config` і `--strict-mcp-config`

### 401 Unauthorized

Запит не мав токена або мав старий. Скопіюйте поточний токен із рядка **Токен
автентифікації** і надсилайте його як `Authorization: Bearer <token>`. Токен у URL
ігнорується.

### 403 від клієнта, що раніше працював

Запит мав `Origin` із вебсторінки або `Host`, на який сервер не відповідає.
Викликайте кінцеву точку з клієнта, а не зі сторінки браузера, за loopback-адресою
сервера або його публічним іменем хоста.

### 415 Unsupported Media Type

Надсилайте тіла `POST /mcp` як `application/json`.

### Виклик інструмента падає з «Missing or invalid argument: workspace_id»

Додайте `workspace_id`. Неявного робочого простору не існує.

### Виклик інструмента відхилено як невідомий

Каталог наведено в [Інструменти MCP](/uk-UA/керівництво/довідка/інструменти-mcp/).
Викликайте назву точно так, як вона там записана.
