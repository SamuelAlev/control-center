Цей посібник охоплює частини налаштування, специфічні для GitHub. GitHub — один
із трьох підтримуваних хостингів коду; див.
[Підключити хост коду](/uk-UA/керівництво/практичні-посібники/підключити-хост-коду/)
про підключення GitLab чи Bitbucket і про те, як робочий простір поєднує їх.

## Передумови

- Обліковий запис GitHub із доступом до репозиторіїв, з якими хочете працювати
- Сервер, який уміє виконувати вхід людей у GitHub: або власний GitHub App (див.
  [Створити GitHub App](/uk-UA/керівництво/практичні-посібники/github-app/)), або Control Center
  Connect — вибір робить власник сервера в **Налаштування → Сервер → Єдиний вхід**

:::note[Облікові дані живуть на сервері й прив’язані до вас]
Нічого не зберігається на машині, з якої ви друкуєте. Ваш вхід у GitHub тримає
`cc_server`, з прив’язкою до вашого ідентифікатора користувача, і кожен пристрій,
з якого ви входите, користується ним — комп’ютер, веб і телефон. Інший учасник
того самого сервера не може ним скористатися, а вхід для них — це те, що вони
роблять самі.
:::

## Увійти в GitHub

GitHub працює лише через вхід: токена для вставлення немає.

1. Перейдіть у **Налаштування → Робочий простір → Профіль і ідентичність → Хостинг коду** (або
   перший крок початкового налаштування)
2. У рядку **GitHub** натисніть **Увійти в GitHub**
3. Браузер відкриє GitHub. Підтвердьте застосунок

Як завершиться вхід, залежить від того, хто його виконує:

- **Власний застосунок сервера:** GitHub повертає браузер на сервер, і діалог
  сам це помічає. Вводити нічого не треба
- **Control Center Connect:** сторінка в браузері показує 8-символьний код.
  Введіть його в діалозі або дозвольте браузеру відкрити Control Center за
  посиланням `control-center://`, і вводити код не доведеться

Контрольна точка: рядок **GitHub** показує «Ви увійшли як _your-username_».

Діалог відхиляє код або посилання, які він не запускав сам, з повідомленням
**Вхід розпочато не тут**. Якщо хтось надсилає вам посилання для входу, не
продовжуйте: завершивши його, ви підключили б свій обліковий запис до сервера
цієї людини.

Натисніть **Від’єднатися**, щоб прибрати свій вхід. Вихід із GitHub або
вилучення з робочого простору також відкидає всі токени, які сервер випустив від
вашого імені.

## Від чийого імені діють ваші облікові дані

- **Усе, що робите ви** (відкриття сторінки PR, публікація рев’ю, схвалення,
  злиття), виконується на **вашому** вході й більше ні на чому. Якщо ви не
  ввійшли, застосунок про це повідомляє й просить увійти. Жодні інші облікові
  дані вас не підміняють
- **Робота, за якою ніхто не друкує** (запуски агентів, конвеєри, опитування
  PR, відповіді бота, клонування), отримує токен для одного репозиторію,
  випущений із GitHub App сервера або через Connect. Він обмежений тим, що може
  робити там відповідальний учасник: учасник, який попросив, а інакше власник
  робочого простору. Учасник, який не може робити push, обмежує токен читанням
- **Автоматизація ніколи не схвалює** pull request. Схвалення — дія людини

## Що дає інтеграція

| Можливість             | Як                                                                                                              |
| ---------------------- | --------------------------------------------------------------------------------------------------------------- |
| Список PR і подробиці  | GitHub REST API, із сервера, на вашому власному вході                                                            |
| Запуски перевірок      | GitHub Checks API                                                                                               |
| Публікація рев’ю       | Крок, який запускає користувач і який публікує ваше рев’ю в PR від вашого імені                                  |
| Реєстрація репозиторію | Копію приймають, якщо її remote `origin` указує на github.com — або на gitlab.com / bitbucket.org              |
| Доступ агента до GitHub | Токен для одного репозиторію запуску як `GH_TOKEN` / `GITHUB_TOKEN`; push проходить через Control Center         |
| Сповіщення             | Серверне опитування вашої скриньки сповіщень GitHub породжує «Згадка в pull request» і «Запит на рев’ю»        |
| Профілі користувачів   | Картки профілю при наведенні та фільтрування PR за автором                                                       |

Деякі шляхи використовують GraphQL API замість REST там, де це дешевше —
активність гілки для вибору гілки під час створення PR і живий стан рев’ю, який
вирішує, чи запит на рев’ю ще чинний.

## Стежте за збоями GitHub

У рядку заголовка з’являється індикатор стану, коли в провайдера проблеми, — це
стосується GitHub, Claude, OpenAI і Kimi. **Поки все гаразд, він прихований** —
присутність повідомляє про проблему, а не про її відсутність.

Натисніть індикатор, щоб відкрити висувну панель зі станом кожного провайдера та
кнопкою оновлення. Статуси оновлюються самі кожні дві хвилини.

## Знайте, як агенти діють у GitHub

- Агент, що працює у worktree GitHub, отримує токен для цього одного
  репозиторію. Він може читати код і коментувати pull request, коли
  відповідальний учасник може робити push, і лише читати, коли не може. Push
  проходить через Control Center, який запитує правило
  **Надіслати на віддалений репозиторій**, а тоді передає його з токеном
  запису, якого агент ніколи не має. Див.
  [Налаштувати політики пісочниці](/uk-UA/керівництво/практичні-посібники/політики-пісочниці/)
- У комітах агента завжди використовується ідентичність Git людини, яка зробила запит, і як автора, і як комітера. Типово трейлер `Co-Authored-By: Control Center <hi@usectrl.dev>` зазначає обліковий запис GitHub `@usectrl` як співавтора. У **Налаштування → Ви → Авторство комітів** можна вимкнути зазначення цього співавтора, не змінюючи своєї ідентичності. Налаштування робочого простору в **Налаштування → Робочий простір → Загальні** має перевагу й блокує особистий перемикач. Власне зазначення авторства Claude Code завжди вимкнено. Для підписування комітів, як і раніше, потрібне окреме чинне налаштування
- Термінал, який ви відкриваєте на rig, отримує ваш власний вхід, звужений до
  одного репозиторію, тож push звідти — ваші
- Коли токен не вдається випустити (ніхто відповідальний не ввійшов, застосунок
  не встановлено на власнику або інсталяцію призупинено), запуск починається без
  нього, а його нотатки пояснюють чому. Запасних облікових даних немає

## Усунення несправностей

### Список PR порожній і повідомляє, що GitHub не підключено

Ви не ввійшли в GitHub на цьому сервері. Натисніть **Увійти в GitHub** у
розділі **Хостинг коду**. Репозиторіїв інших хостингів коду це не зачіпає.

### Рядок GitHub повідомляє, що вхід на цьому сервері не налаштовано

Сервер не має ні власного GitHub App, ні Connect. Власник сервера вибирає один
варіант у **Налаштування → Сервер → Єдиний вхід**: **Створити мій застосунок
GitHub** займає близько двох хвилин. Див.
[Створити GitHub App](/uk-UA/керівництво/практичні-посібники/github-app/).

### Діалог повідомляє, що код не збігається

Введіть код точно так, як його показує браузер: 8 літер і цифр. П’ять
неправильних кодів завершують вхід; почніть його знову.

### Вхід повідомляє, що застосунок не встановлено

GitHub App не має інсталяції на обліковому записі, якому належить репозиторій.
Адміністратор робочого простору встановлює його в **Налаштування → Робочий
простір → Загальні → Встановлення застосунку GitHub**. Для організації на
спільному App від Control Center адміністратору цієї організації може знадобитися
натиснути **Авторизувати цей сервер**. Див.
[Створити GitHub App](/uk-UA/керівництво/практичні-посібники/github-app/#авторизуйте-цей-сервер-для-організації).

### Усім доводиться входити в GitHub знову

Власник сервера змінив ключ Connect сервера, перейшов на інший сервер Connect,
або каталог даних відновили на іншій машині. Входи через Connect прив’язані до
сервера, який їх виконав.

### Додавання репозиторію відхилено

Для реєстрації потрібні всі три умови: шлях лежить усередині робочого дерева git,
у нього є remote `origin`, і цей remote указує на підтримуваний хостинг коду
(github.com, gitlab.com або bitbucket.org). Див.
[Додати репозиторії до робочого простору](/uk-UA/керівництво/практичні-посібники/додати-репозиторії/).

### Після інтенсивного використання все на якийсь час перестає працювати

Це запобіжник на випадок обмеження частоти запитів. GitHub повідомляє про
досягнення основного ліміту відповіддю `403` із заголовком
`x-ratelimit-remaining: 0` і часом скидання; побачивши таку, клієнт локально
відхиляє подальші запити, без мережевого звернення, доки не спливе вікно, — тож
шквал повторних спроб не може поглибити ліміт. Тимчасові збої повторюють до трьох
разів з експоненційною затримкою, поважаючи `retry-after`.
