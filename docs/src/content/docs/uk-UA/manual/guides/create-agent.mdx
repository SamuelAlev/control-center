Цей посібник показує, як додати агента до робочого простору й налаштувати його, доки він справді не зможе запускатися.

Кожен робочий простір початково отримує п’ять агентів — CEO і `qa`, `architect`, `engineer` та `librarian` — тож зазвичай агенти у вас уже є, перш ніж ви налаштуєте хоч одного. Кроки нижче однаково стосуються як початково створеного агента, так і нового.

## Перш ніж почати

- Ви перебуваєте всередині робочого простору. Уся ця поверхня міститься в **Налаштування → Робочий простір → Агенти** (`/settings/workspace/agents`).
- Агенту знадобиться бекенд. Або підключіть провайдера для вбудованого harness у **Налаштування → Сервер → Постачальники моделей**, або встановіть CLI Claude Code на машині, де розміщено `cc_server`.
- Якщо хочете, щоб агент мав навички, спершу встановіть їх у **Налаштування → Робочий простір → Навички**. Форма агента дає змогу перемикати лише ті навички, які вже існують у робочому просторі.

## Додайте агента

1. Відкрийте **Налаштування → Робочий простір → Агенти**.
2. Натисніть **Новий агент**.

Жодного діалогу й жодного вибору ролі немає. Агент із назвою «Безіменний агент» створюється негайно й виділяється на панелі деталей праворуч.

Тепер ви маєте побачити «Безіменний агент» у реєстрі ліворуч, із відкритою вкладкою **Налаштування** на панелі деталей і полем **Назва**, що містить «Безіменний агент».

## Дайте йому назву

- **Назва** — короткий ідентифікатор, який використовують в @-згадках, наприклад `alice`. Під час розбору згадок зіставляється `@`, за яким ідуть символи слова, тож ім’я з дефісом, крапкою чи пробілом ніколи не можна згадати.
- **Назва** — зрозумілий людині підпис, наприклад «Senior coder».
- **Системний промпт** — необов’язкові додаткові вказівки; вставляються як розділ «Agent instructions» — решти зібраного промпту вони не замінюють.

Натисніть **Зберегти зміни** внизу форми. Усі поля на цій сторінці зберігає ця одна кнопка.

## Задайте йому адаптер і модель

Випадний список **Адаптер** перелічує раннери, які насправді є на хості сервера. Вбудований адаптер знаходиться завжди (це сам сервер). Claude Code з’являється лише тоді, коли його CLI виявлено на цьому хості:

| Адаптер                   | Бекенд                                                     |
| ------------------------- | ---------------------------------------------------------- |
| Control Center (вбудований) | Цикл агента всередині процесу — без зовнішнього CLI      |
| Claude Code               | `claude -p --output-format stream-json`                     |

Лише вбудований адаптер забезпечує примусово режими, коригування під час запуску, паузу й відновлення, контракти завершення та субагентів. Claude Code не дає нічого з цього. Cursor, Codex та інші провайдери моделей приєднуються до вбудованого адаптера, а не як окремі раннери.

:::note[Порожній адаптер означає вбудований цикл]
Агент, у якого адаптер не задано, спрямовується до **Control Center (вбудований)** — циклу всередині сервера, тож на хості нічого не треба встановлювати. Якщо й модель не задано, він запитує в Anthropic її типову, тож цілком незаданий агент запускається лише тоді, коли ви підключили обліковий запис Anthropic. Початково створені фахівці постачаються без жодного з них; задайте обидва для кожного агента, який має працювати.
:::

Випадний список **Модель** визначається обраним адаптером. Для вбудованого адаптера список надходить наживо від провайдерів, які ви підключили в **Налаштування → Сервер → Постачальники моделей**, тож провайдер без збережених облікових даних не додає жодної моделі.

## Додайте навички

**Навички** — це вибір чипами серед пакетів навичок, встановлених у цьому робочому просторі. Торкніться чипа, щоб перемкнути його; гліф галочки позначає вибрані. Якщо в робочому просторі немає навичок, поле показує «No skills available. Create skills in Settings → Skills first.»

Власні навички репозиторію тут не вибирають. Репозиторій, який їх постачає (у `.agents/skills/`, `.claude/skills/` або `.opencode/skills/`), додає їх автоматично тому агентові, який працює в цьому репозиторії, і вони змінюються, коли він переходить до іншого — дивіться [Навички в межах репозиторію](/uk-UA/керівництво/поняття/модель-агента/#repo-scoped-skills).

## Задайте лінію підпорядкування та персону

- **Керівник** — виберіть іншого агента за назвою. Це будує дерево підпорядкування, яке показує кнопка **Оргструктура** в заголовку сторінки. Це не той реєстр, який використовує лідер команди, коли делегує, — той походить від учасників команди та їхніх навичок.
- **Персона** — довільний текст, що формує тон і поведінку, наприклад: «Надає перевагу простим, читабельним рішенням. Пише тести для всього нового коду.»

## Налаштуйте запуск

- **Зусилля міркування** — варіанти походять із власних опублікованих рівнів вибраної моделі: Low / Medium / High, а також Extra High на моделях у стилі OpenAI та Extra High + Max на моделях у стилі Claude. Поле повністю приховане, коли вибрана модель не оголошує рівнів міркування, і типово дорівнює власному типовому значенню моделі.
- **Розмір вікна контексту** — попередньо заповнюється з вікна контексту моделі щоразу, коли ви змінюєте модель, із чипами в один дотик для типового значення моделі, 200k, 500k і 1M. Значення, яке ви введете після вибору моделі, перемагає до наступної зміни моделі.
- **Тайм-аут тиші (хвилини)** — зупинити запуск після цього часу без виводу. Залиште порожнім, щоб використати типове значення для режиму.

## Надайте дозволи

Агент не має власних перемикачів дозволів. Що він може надіслати, відкрити, злити чи куди звернутися, визначають правила дій у **Налаштування → Робочий простір → Дозволи агента**, де правило можна обмежити цим агентом. Типово push, pull request, рецензія чи злиття та запис у трекер спочатку запитують вас, кожне окремо, а доступ до мережі дозволено.

Токен GitHub агента завжди лише для читання. Push проходить через Control Center, який перед передачею запитує правило **Надіслати на віддалений репозиторій**. Як кожне правило доходить до запуску, дивіться в [Налаштувати політики пісочниці](/uk-UA/керівництво/практичні-посібники/політики-пісочниці/).

:::note[Правила й пісочниця ОС — окремі шари]
Правила вирішують, що агентові можна робити; пісочниця ОС обмежує, де його процеси можуть читати, писати й підключатися. `cc_server` загортає запуски агентів у пісочницю хоста там, де вона існує, — на Windows нативного бекенду немає, а Linux і WSL2 потребують `bwrap` і `socat`. Дивіться [Пісочниця та безпека](/uk-UA/керівництво/поняття/пісочниця-та-безпека/), щоб побачити повний набір меж.
:::

## Переконайтеся, що він запускається

1. Відкрийте **Налаштування → Сервер → Постачальники моделей** і переконайтеся, що вибраний адаптер показує встановлену версію, а не «Не знайдено». Натисніть **Оновити**, щоб перевірити знову, — перевірка виконується на машині, де розміщено `cc_server`, а не на машині, на яку ви дивитеся.
2. Відкрийте простір з агентом і надішліть йому повідомлення, або @-згадайте його в наявному просторі.
3. Поверніться до **Налаштування → Робочий простір → Агенти**, виберіть агента й відкрийте його вкладку **Журнали**. Має з’явитися запуск із бейджем статусу, тривалістю, часом початку та адаптером, який він використав. **Перегляд** відкриває потік подій цього запуску.

Якщо жодного запуску взагалі не з’являється, пройдіть [Діагностувати агента](/uk-UA/керівництво/практичні-посібники/діагностика-агента/).

## Видаліть агента

Виберіть його в реєстрі. На вкладці **Налаштування** прокрутіть до **Небезпечної зони** внизу форми й натисніть **Видалити**.
