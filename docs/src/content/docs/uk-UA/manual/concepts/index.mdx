These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/uk-UA/керівництво/практичні-посібники/); when you want to look
something up, go to the [reference](/uk-UA/керівництво/довідка/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/uk-UA/керівництво/поняття/робочі-простори/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/uk-UA/керівництво/поняття/модель-агента/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/uk-UA/керівництво/поняття/життєвий-цикл-запуску/) — what happens between your message and the agent's first token
- [Modes](/uk-UA/керівництво/поняття/режими/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/uk-UA/керівництво/поняття/контекст-інструментів/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/uk-UA/керівництво/поняття/інтелект-коду/) — the code graph, language server, structural search and debugger
- [Conversation history](/uk-UA/керівництво/поняття/історія-розмов/) — persistence, compaction and forking a transcript
