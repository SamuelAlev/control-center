## Що ви створите

Завершивши цей посібник, ви:

- Відкрили pull request у верстаку PR у Control Center
- Прочитали його diff і залишили коментар до рядка
- Надіслали вердикт рев’ю
- Злили PR

Передумови: пройдений посібник [Запустіть першого агента](/uk-UA/керівництво/посібники/перший-агент/) і один відкритий pull request у репозиторії, зареєстрованому в цьому робочому просторі. Для кроків рев’ю виберіть PR, який відкрили не ви — кнопка **Рев’ю** на ваших власних PR прихована. Злиття все одно працює для PR, автором якого є ви.

## Крок 1: Відкрити pull request

1. Натисніть **Pull requests** на бічній панелі
2. Знайдіть свій PR і натисніть на нього

**Контрольна точка.** PR відкривається як верстак із вкладками — **Огляд**, **Різниця**, **Керування кодом**, **Чат**, **Дії** — з фокусом на **Огляд**: заголовок і дії, опис і стрічка активності та бічна панель зі статусом, рев’юерами, призначеними, перевірками й зміненими файлами. Натискання файлу там перестрибує до нього на вкладці **Різниця**. Вкладка **Рев’ю PR** не відкривається, доки хтось не попросить ШІ-рев’ю.

:::note[Порожня черга із запитом «підключити GitHub»]
Такий стан означає, що GitHub-токен зберігає _сервер_ — ваш клієнт його ніколи не тримає. Задайте його в **Налаштування → Робочий простір → Профіль і ідентичність → Хостинг коду**, а потім оновіть список.
:::

## Крок 2: Прочитати diff

Відкрийте вкладку **Різниця**. Ліворуч розташоване дерево файлів, яке можна згортати, а смуга над diff містить селектор діапазону комітів — звузьте diff до одного коміту чи їхнього проміжку — а також кількість файлів і поточні додавання та вилучення.

Кнопка налаштувань на панелі інструментів diff керує тим, як він відображається:

- Вигляд **Поділений** чи **Об’єднаний**
- **Переносити рядки** або прокручувати довгі рядки
- **Лігатури шрифту коду**

Позначайте файл як переглянутий, щоб відстежувати поступ у великому diff. Навігація з клавіатури описана в [Гарячі клавіші](/uk-UA/керівництво/довідка/гарячі-клавіші/).

## Крок 3: Залишити коментар до рядка

1. Наведіть курсор на рядок у diff — у жолобі з’явиться маленька плашка `+`
2. Натисніть її, щоб прокоментувати цей рядок, або спершу протягніть її вертикально, щоб вибрати діапазон
3. Напишіть свій відгук. Композер пропонує два варіанти надсилання:
   - **Почати рев’ю** (або **Додати до рев’ю**, якщо рев’ю вже триває) ставить коментар у чергу. Обговорення показує **Очікує рев’ю**, доки ви не надішлете вердикт на кроці 4.
   - **Додати окремий коментар** публікує його на GitHub одразу. Обговорення показує **Публікація…**, потім **Синхронізовано** й пропонує повторити, якщо публікація не вдалася.

У цьому посібнику скористайтеся **Почати рев’ю**, щоб коментар вийшов разом із вердиктом.

:::caution[Коментар у черзі ще не на GitHub]
**Почати рев’ю** / **Додати до рев’ю** тримають коментар локально, доки ви не надішлете вердикт. Лише **Додати окремий коментар** публікує негайно. _Тіло_ рев’ю, яке ви пишете на кроці 4, — окрема чернетка.
:::

## Крок 4: Надіслати рев’ю

1. Натисніть **Рев’ю** в рядку дій на вкладці «Огляд» — ця сама кнопка є і на панелі інструментів вкладки **Різниця**. Її приховано для PR, автором яких є ви, а також для закритого чи злитого PR.
2. Напишіть підсумок у композері. Він автоматично зберігається як чернетка, тож ви можете закрити накладку й повернутися.
3. Виберіть вердикт:
   - **Запросити зміни**
   - **Коментар**
   - **Схвалити**

Вердикт — це і є кнопка. Після **Схвалити** або **Запросити зміни** кнопка перейменовується на **Схвалено** чи **Запитані зміни**. Вердикт **Коментар** залишає на ній підпис **Рев’ю**.

**Контрольна точка.** Кнопка показує «Схвалено» або «Запитані зміни», якщо ви вибрали один із цих двох варіантів.

## Крок 5: Злити

Кнопка **Злити** присутня завжди, коли GitHub повідомляє, що PR можна злити — її не обмежує ваше власне схвалення. Її колір повідомляє про готовність, а не про дозвіл: основного кольору, коли потрібні схвалення й перевірки зелені; другорядного, поки якась перевірка ще виконується; руйнівного, коли запитаний рев’юер не схвалив або перевірка не проходить.

1. Натисніть **Злити**
2. Виберіть спосіб: **Стиснути й злити**, **Створити коміт злиття** або **Перебазувати й злити**
3. Для перших двох відредагуйте попередньо заповнені заголовок і повідомлення коміту
4. Підтвердьте

Будь-які невирішені проблеми — «Перевірки не проходять», «Деякі рецензії ще очікуються» — перелічено у висувній панелі, перш ніж ви підтвердите.

:::caution[Злиття незворотне]
Злиття надсилає коміти на GitHub. Воно ніколи не потрапляє до стеку скасування Control Center, і його не можна скасувати звідси.
:::

Після злиття спрацьовує доменна подія `PrMerged`; її споживають аналітика й сповіщення. Про те, хто ще її слухає, дивіться в [Доменні події](/uk-UA/керівництво/довідка/доменні-події/).

## Рев’ю за допомогою ШІ

Control Center може запустити конвеєр рев’юерів на відкритому PR, але лише коли ви попросите: шаблон `pr_review` має ручний тригер і більше нічого.

1. Відкрийте меню переповнення ⋯ у рядку дій на вкладці «Огляд» і виберіть **Запитати AI**. Control Center запускає прогін і відкриває вкладку **Рев’ю PR**, щоб ви могли спостерігати за роботою спеціалістів.
2. Агенти-рев’юери записують свої знахідки як вузли рев’ю в просторі PR; фінальний крок об’єднує їх в один звіт.

Конвеєр навмисно не публікує нічого на GitHub — він завершується після об’єднання. Публікація — окремий крок, який ви робите самі, кнопкою **Опублікувати на GitHub** на вкладці **Рев’ю PR**. Дивіться [Використовувати ШІ-перевірку](/uk-UA/керівництво/практичні-посібники/ші-перевірка/).

## Підсумок

Ви відкрили PR у верстаку, прочитали diff із підсвічуванням синтаксису, залишили коментар до рядка, надіслали вердикт і злили — не виходячи із застосунку.

**Далі:** [Зберіть свій перший конвеєр](/uk-UA/керівництво/посібники/перший-конвеєр/), щоб автоматизувати багатокрокові робочі процеси.
