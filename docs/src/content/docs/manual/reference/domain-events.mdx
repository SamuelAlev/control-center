## Event bus

The `DomainEventBus` is an in-process broadcast publish/subscribe bus. Publishers call `publish(event)`; subscribers consume a typed `on<T>()` stream. Every event implements `DomainEvent` and carries `occurredAt`.

**The bus runs inside `cc_server`.** Every publisher and every live subscriber lives there. No client sees this bus — the server forwards a curated subset as `notifications/*` JSON-RPC frames, broadcast to every session and filtered client-side by workspace.

| Measure                                                     | Count                                                                                               |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Concrete event classes                                      | 79                                                                                                  |
| Source files (`packages/cc_domain/lib/core/domain/events/`) | 19                                                                                                  |
| Abstract bases that are never published directly            | 5 (`ArtifactEvent`, `MemoryEvent`, `OrchestrationEvent`, `PlanDocumentEvent`, `TaskLifecycleEvent`) |

Every event in the catalog below lives in that one directory; there are no domain events declared elsewhere.

## Workspace, agent and repo events

| Event               | Payload                                                | Fired when                                              |
| ------------------- | ------------------------------------------------------ | ------------------------------------------------------- |
| `WorkspaceCreated`  | `workspaceId`                                          | Workspace is created                                    |

## Task lifecycle events

The unified task-lifecycle stream — one dispatched agent run, keyed by its run-log id. Every event carries `taskId`, a monotonic per-task `seq`, `workspaceId?`, `agentId?` and a `phase`; the rows below list only the additional fields.

| Event                       | Payload                       | Fired when                                                                                       |
| --------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------ |
| `TaskQueued`                | —                             | Task accepted into the queue                                                                     |
| `TaskDispatched`            | —                             | Task handed to a backend for execution                                                           |
| `TaskRunning`               | —                             | Task started producing output                                                                    |
| `TaskWaitingLocalDirectory` | `lockedPath`, `holderTaskId?` | Task parked — another task owns the on-disk path lock it needs                                   |
| `TaskProgress`              | `note?`                       | Mid-run progress checkpoint                                                                      |
| `TaskMessage`               | `messageType`, `content`      | Streamed message (text/thinking/tool_use/tool_result/error); reported under the `progress` phase |
| `TaskCompleted`             | `summary?`                    | Task finished successfully                                                                       |
| `TaskFailed`                | `errorMessage`                | Task finished with an error                                                                      |
| `TaskCancelled`             | —                             | Task cancelled before completion                                                                 |

## Notification mapping

On the server, `NotificationFeedRecorder` and `RemoteEventForwarder` turn these events into `notifications/*` wire frames (`notification_wire.dart`). On the client, `RpcNotificationMapper` → `mapNotificationFrame` turns a frame into an `AppNotification`.

There are exactly eleven notification categories.

| Category               | Source event           | Wire method                           |
| ---------------------- | ---------------------- | ------------------------------------- |
| `newMessage`           | `MessageReceived`      | `notifications/message_received`      |
| `ticketAssigned`       | `TicketAssigned`       | `notifications/ticket_assigned`       |
| `ticketStatusChanged`  | `TicketStatusChanged`  | `notifications/ticket_status_changed` |
| `agentRunCompleted`    | `AgentRunCompleted`    | `notifications/agent_run_completed`   |
| `pullRequestPublished` | `PullRequestPublished` | `notifications/pr_published`          |
| `prMerged`             | `PrMerged`             | `notifications/pr_merged`             |
| `prMerged`             | `ExternalPrMerged`     | `notifications/external_pr_merged`    |
| `prMentioned`          | `PrMentioned`          | `notifications/pr_mentioned`          |
| `reviewRequested`      | `PrReviewRequested`    | `notifications/pr_review_requested`   |
| `meetingStartsSoon`    | `MeetingStartingSoon`  | `notifications/meeting_starting_soon` |
| `calendarAuthExpired`  | `CalendarAuthExpired`  | `notifications/calendar_auth_expired` |
| `rigStatusChanged`     | `RigControlChanged`    | `notifications/rig_control_changed`   |
| `rigStatusChanged`     | `RigReaped`            | `notifications/rig_reaped`            |
| `rigStatusChanged`     | `RigClosedEvent`       | `notifications/rig_closed`            |

The rig take-over frame is not delivered back to whoever took the wheel, a
release is unfiltered (the event does not record who let go), and only a
`backendFailure` close produces a `rig_closed` frame — the other reasons are
either requested or already covered by the reap frame.

`RemoteEventForwarder` additionally forwards `TicketReassigned` as `notifications/ticket_reassigned` and every `TaskLifecycleEvent` as `notifications/task_<phase>`. Neither maps to a notification category — they drive live UI, not the notification centre.
