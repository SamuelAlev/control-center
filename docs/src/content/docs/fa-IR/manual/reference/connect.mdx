Control Center Connect ورود به ارائه‌دهندگان را برای سرورهایی اجرا می‌کند که برنامه‌های
خودشان را ثبت نکرده‌اند. یک سرور یا از Connect میزبانی‌شدهٔ Control Center استفاده می‌کند، یا
از Connectی که سازمانش اجرا می‌کند ([اجرای سرور Connect](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/اجرای-سرور-connect/))،
یا هیچ‌کدام. انتخاب در **تنظیمات ← سرور ← ورود یکپارچه ← Control Center Connect**،
دستور `cc_server connect`، یا `CC_CONNECT_URL` قرار دارد.

## مسیرها

هر ارائه‌دهنده یک مسیر (lane) است. تحت **استفاده از برنامه‌های خودم** (یا پیش از انتخاب کسی)، مسیری روی برنامهٔ خود سرور اجرا می‌شود وقتی کاملاً پیکربندی شده باشد؛ در غیر این صورت غیرقابل‌دسترس است. با Control Center یا Connect سفارشی، Connect هر مسیری را که ارائه می‌دهد اجرا می‌کند: برنامه‌های خود سرور ذخیره می‌مانند اما برای ورود، برای خودکارسازی سرور یا برای وضعیت گزارش‌شده استفاده نمی‌شوند. برنامهٔ اختصاصی فضای کاری در همهٔ حالت‌ها اعمال می‌شود.

| مسیر         | برنامهٔ خودی لازم دارد                              | از طریق Connect                                              |
| ------------ | --------------------------------------------------- | ------------------------------------------------------------ |
| `github`     | App id، private key، client id و client secret      | افراد با GitHub App مشترک وارد می‌شوند                       |
| `google`     | Client id و client secret                           | افراد Google Calendar را متصل می‌کنند                        |
| `linear`     | Client id                                           | افراد با Linear وارد می‌شوند                                 |
| `linear_app` | Client id                                           | مدیر فضای کاری actor برنامهٔ Linear را متصل می‌کند          |
| `slack`      | اتصال برنامهٔ Slack خودِ فضای کاری                  | مدیر فضای کاری Slack را به برنامهٔ مشترک Slack متصل می‌کند   |
| `klipy`      | `KLIPY_APP_KEY`                                     | جست‌وجوی GIF که Connect آن را واسطه می‌کند                   |

برنامهٔ خودی که فقط تا حدی پیکربندی شده، مسیرش را خطا می‌کند، و هرگز بی‌سروصدا به Connect
برنمی‌گردد. فضای کاری‌ای که GitHub App خودش را به کار می‌برد (**تنظیمات ← فضای کاری ← عمومی ←
هویت GitHub**) هرگز برای GitHub از Connect عبور نمی‌کند، و فضای کاری‌ای که برنامهٔ اختصاصی Google، Linear یا Klipy را به کار می‌برد (**تنظیمات ← فضای کاری ← عمومی ← برنامه‌های ارائه‌دهنده**) برای آن ارائه‌دهنده هرگز از برنامهٔ سرور یا Connect عبور نمی‌کند. تغییر انتخاب Connect هیچ‌کس را از برنامهٔ اختصاصی یک فضای کاری خارج نمی‌کند.

## آنچه Connect می‌بیند و آنچه هرگز نمی‌بیند

| Connect می‌بیند                                                                                    | Connect هرگز نمی‌بیند                                                                 |
| ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| شناسهٔ نصب سرور و امضای درخواست‌ها                                                                | کد منبع، محتوای مخزن، diff یا متن درخواست‌های pull                                     |
| حساب ارائه‌دهنده‌ای که در همان ورود وارد شده است                                                   | تیکت‌ها، رونوشت‌ها یا هر چیزی در پایگاه‌داده‌های یک فضای کاری                          |
| اینکه اعتبارنامه به کدام فضای کاری تعلق دارد، به‌صورت یک شناسهٔ مبهم داخل مهر                     | کلید خصوصی GitHub App: توکن‌های مخزن از ورود خود فرد می‌آیند                            |
| مخزنی که برایش یک توکن GitHub تک‌مخزنی صادر می‌شود                                                 | توکن‌های تازه‌سازی در حالت ذخیره‌شده: فقط داخل مهرهایی وجود دارند که سرور نگه می‌دارد |
| شناسه‌های نصب GitHub که به سرور متصل‌اند                                                          | رازهای Linear: سرور کد Linear را خودش مبادله می‌کند                                    |
| عبارت‌های جست‌وجوی GIF، وقتی Klipy را واسطه می‌کند                                                | گذرواژه‌ها، کلیدهای جفت‌سازی یا کلیدهای ارائه‌دهندهٔ مدل                                |
| ارجاعات رویداد Slack (تیم، کانال، شناسهٔ پیام) و متن دستورهای اسلش                               | متن پیام‌های Slack: Connect آن را هنگام رسیدن دور می‌ریزد و سرور خودش پیام را از Slack می‌خواند |

Connect وضعیت کوتاه‌مدت (ورودهای در حال انجام، nonce ها، کش‌ها) را حداکثر ۱۵ دقیقه نگه می‌دارد.
تنها سوابق ماندگارش، اتصال‌های نصب است: اینکه کدام سرورها می‌توانند از کدام نصب GitHub استفاده
کنند، و هر تیم Slack به کدام سرور وصل است. خطاها فقط یک کد حمل می‌کنند، هرگز پاسخ ارائه‌دهنده را،
و گزارش‌ها شناسه‌های نصب را فقط به‌صورت hash کلیددار ثبت می‌کنند.

## حالت‌ها

| حالت     | تنظیم                          | رفتار                                                                                                     |
| -------- | ------------------------------ | --------------------------------------------------------------------------------------------------------- |
| تنظیم‌نشده | سرور تازه                    | هیچ مسیری از Connect استفاده نمی‌کند. راه‌اندازی از مالک سرور می‌خواهد انتخاب کند                          |
| `hosted` | **استفاده از برنامه‌های Control Center** | `https://connect.usectrl.dev`، با پیکربندی امضاشدهٔ آفلاین. برنامه‌های خود سرور استفاده نمی‌شوند                                       |
| `custom` | **استفاده از سرور Connect سفارشی** | یک Connect در نشانی HTTPS (فقط روی `http` برای loopback)، که در اولین استفاده معتبر شناخته می‌شود. برنامه‌های خود سرور استفاده نمی‌شوند       |
| `off`    | **استفاده از برنامه‌های خودم**  | هیچ مسیری از Connect استفاده نمی‌کند. فقط برنامه‌های خودی افراد را وارد می‌کنند                           |

`CC_CONNECT_URL` در محیط یا `.env` سرور، انتخاب را قفل می‌کند: `hosted`، `off` یا یک نشانی
Connect. آنگاه تنظیمات قفل را نشان می‌دهد و نمی‌تواند آن را تغییر دهد.

این ساخت هیچ کلید پیکربندی hosted را کامپایل نمی‌کند، پس حالت hosted، `hosted_unprovisioned`
گزارش می‌دهد و هیچ مسیری را ارائه نمی‌کند. برنامه‌های خودی و Connect سفارشی کار می‌کنند.

سرور حداکثر هر ۱۰ دقیقه پیکربندی Connect را می‌خواند و برای هر فراخوانی حداکثر ۵ ثانیه صبر
می‌کند. وقتی Connect در دسترس نباشد، آخرین پیکربندی معتبر در استفاده می‌ماند و تنظیمات آن را
قدیمی علامت می‌زند.

## هویت نصب

| مورد              | معنی                                                                                                                       |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------- |
| کلید نصب          | یک seed به طول ۳۲ بایت در فایل رازهای سرور (`connect_install_key`)، جدا از کلیدهای جفت‌سازی دستگاه                        |
| کلید هر Connect   | یک کلید Ed25519 که از seed و نشانی Connect مشتق می‌شود. هر درخواست به Connect با آن امضا می‌شود (RFC 9421)                 |
| شناسهٔ نصب        | ۲۶ کاراکتر که از آن کلید عمومی مشتق می‌شود. در تنظیمات و با `cc_server connect status` نمایش داده می‌شود                    |

همان سرور برای هر نشانی Connect شناسهٔ نصب متفاوتی دارد. شناسه فقط وقتی تغییر می‌کند که کلید
چرخانده شود.

## اعتبارنامه‌های مهروموم‌شده

ورود از طریق Connect یک **مهر اعتبارنامه** (credential seal) برمی‌گرداند: یک بلوک رمزنگاری‌شده
که فقط Connectی که آن را ساخته می‌تواند بازش کند. این مهر به ارائه‌دهنده، نشانی Connect، شناسهٔ
نصب، فضای کاری، حساب ارائه‌دهنده، برنامه و نسل راز گره خورده است.

- سرور مهر و شناسهٔ نصبی را که مهر برایش ساخته شده ذخیره می‌کند. توکن‌های دسترسی در حافظه
  می‌مانند
- برای تازه‌سازی، سرور مهر را پس می‌فرستد و یک توکن دسترسی تازه و یک مهر تازه دریافت می‌کند
- مهری که شناسهٔ نصب یا نشانی Connect آن دیگر تطبیق نمی‌کند، هنگام خواندن بعدی حذف می‌شود و
  فرد دوباره وارد می‌شود. این پس از چرخش کلید، تغییر به Connect دیگر، یا بازیابی پوشهٔ داده روی
  سرور دیگر رخ می‌دهد
- مهری که Connect نتواند بازش کند با `access_denied` رد می‌شود

## نصب‌های GitHub

یک نصب از GitHub App مشترک تنها وقتی برای یک سرور قابل‌استفاده است که Connect آن را به شناسهٔ
نصب آن سرور متصل کرده باشد.

- **Install GitHub App** در **تنظیمات ← فضای کاری ← عمومی** GitHub را با یک بلیت ۱۵ دقیقه‌ای باز
  می‌کند. Connect نصب تازه را وقتی متصل می‌کند که نصب‌کننده مالک حساب شخصی باشد یا سازمان را
  مدیریت کند
- **Authorize this server** نصبی را که از قبل وجود دارد متصل می‌کند. فقط مدیر سازمان می‌تواند این
  کار را انجام دهد
- یک نصب سازمانی می‌تواند به چند سرور متصل شود؛ هر کدام به مجوز یک مدیر نیاز دارد

## اعتماد به پیکربندی

| Connect | سرور چگونه به پیکربندی‌اش اعتماد می‌کند                                                                                                                                                                                                                          |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hosted  | امضای Ed25519 را در برابر کلیدهایی که در ساخت کامپایل شده‌اند تأیید می‌کند. epochِ کمتر از بالاترین epochی را که دیده رد می‌کند (`rollback`)                                                                                                                     |
| Custom  | app id و client id مربوط به GitHub، client id های Google و Linear، و شناسه‌های برنامه و کلاینت Slack را در اولین استفاده ثابت (pin) می‌کند. تغییر، ورودهای Connect را متوقف می‌کند (`pins_changed`) تا وقتی که مالک سرور **Trust new apps** را بزند |

## عملیات

همهٔ تنظیمات Connect فقط برای مالک سرور است.

| عملیات                | کار                                                                                                  |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| `connect.status`      | حالت، نشانی، قفل، شناسهٔ نصب، سلامت، epoch پیکربندی و منبع هر مسیر                                     |
| `connect.configure`   | `hosted`، `custom` (همراه با `url`) یا `off` را تنظیم می‌کند                                          |
| `connect.test`        | پیکربندی را دوباره می‌گیرد و سلامت را گزارش می‌کند                                                   |
| `connect.confirmPins` | شناسه‌های تغییرکردهٔ یک Connect سفارشی را می‌پذیرد                                                    |
| `connect.rotateKey`   | یک کلید نصب تازه صادر می‌کند. هر ورود از طریق Connect روی این سرور از کار می‌افتد                    |

خود ورودها از `oauth.lanes`، `oauth.begin`، `oauth.status`، `oauth.complete`،
`oauth.connections` و `oauth.disconnect` استفاده می‌کنند. فرد همیشه همان فراخوان واردشده است.

## ورود از طریق Connect

۱. سرور از Connect می‌خواهد مسیر را آغاز کند و نشانی authorize ارائه‌دهنده را دریافت می‌کند، که
   پیش از نمایش آن را بررسی می‌کند
۲. فرد در مرورگر تأیید می‌کند. ارائه‌دهنده او را به Connect برمی‌گرداند
۳. Connect یک کد ۸ کاراکتری و پیوند `control-center://oauth-done` را نشان می‌دهد
۴. فرد کد را در برنامه تایپ می‌کند یا پیوند را دنبال می‌کند. سرور ورود را با کد و اثبات خودش از
   درخواست ادعا می‌کند

ورود پس از ۱۰ دقیقه منقضی می‌شود. پنج کد اشتباه آن را پایان می‌دهد. پیوندی که این برنامه آغاز
نکرده با **Sign-in not started here** رد می‌شود.

## چرخش کلید نصب

**Rotate key** روی کارت Connect، یا `cc_server connect rotate-key --yes`:

- به سرور یک کلید نصب تازه و یک شناسهٔ نصب تازه می‌دهد
- همه را از هر مسیری که از طریق Connect اجرا می‌شود خارج می‌کند
- ورودها از طریق برنامه‌های خود سرور را بدون تغییر نگه می‌دارد
- نیاز دارد که شناسهٔ نصب جدید به فهرست مجاز یک Connect سفارشی اضافه شود

## کدهای وضعیت

| کد                     | معنی                                                                      |
| ---------------------- | ------------------------------------------------------------------------- |
| `hosted_unprovisioned` | این ساخت کلید پیکربندی hosted ندارد                                       |
| `signature`            | امضای پیکربندی hosted بررسی را نگذراند                                    |
| `rollback`             | Connect پیکربندی قدیمی‌تر از آنچه سرور قبلاً دیده بود ارائه داد           |
| `unreachable`          | سرور نمی‌تواند به Connect برسد                                             |
| `install_blocked`      | Connect این شناسهٔ نصب را مجاز نمی‌داند                                    |
| `pins_changed`         | یک Connect سفارشی شناسه‌های برنامهٔ متفاوتی اعلام کرد                      |
| `protocol`             | Connect پاسخی داد که این سرور نمی‌فهمد                                     |
