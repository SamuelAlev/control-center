هر چیزی که در ورود یکپارچه قابل پیکربندی است، یکجا. مقدارها در ردیف‌های
`sso_connections` در `global.db` زندگی می‌کنند (طبق طراحی در سطح کل سرور) و
از **تنظیمات → سرور → ورود یکپارچه** یا عملیات‌های RPC با پیشوند `sso.*`
ویرایش می‌شوند. ردیف ذخیره‌شده تنها منبع حقیقت است — هیچ مسیر محیطی
`CC_SAML_*` / `CC_OIDC_*` وجود ندارد (اتصالی که می‌تواند از دو جا برسد،
اتصالی است که صفحهٔ تنظیمات می‌تواند با آن ناسازگار باشد).

## فیلدهای اتصال

| فیلد                  | اعمال می‌شود به | پیش‌فرض         | معنا                                                                                                                                              |
| ---------------------- | ---------- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `enabled`              | هر دو       | خاموش             | ورودها می‌توانند از این اتصال استفاده کنند                                                                                                                       |
| `idpMetadataXml`       | SAML       | —               | XML مربوط به `EntityDescriptor` متعلق به IdP (برای فعال‌سازی الزامی)                                                                                |
| `spEntityId`           | SAML       | `<origin>/saml` | شناسهٔ موجودیت ما؛ وقتی مبدأ تغییر می‌کند پین می‌شود                                                                                                         |
| `emailAttribute`       | SAML       | `email`         | ویژگی‌ای که ایمیل را حمل می‌کند؛ NameID با شکل ایمیل جایگزین آن است                                                                                 |
| `displayNameAttribute` | SAML       | `displayName`   | ویژگی نام نمایشی                                                                                                                               |
| `groupsAttribute`      | SAML       | `groups`        | ویژگی نام گروه‌ها                                                                                                                                |
| `clockSkewSeconds`     | SAML       | 90              | میزان تحمل انحراف در اعتبارسنجی عمر                                                                                                                   |
| `allowIdpInitiated`    | SAML       | خاموش             | پذیرش پاسخ‌های ناخواستهٔ معتبر (بدون `InResponseTo`)؛ مرورگر باید پیش از دریافت اعتبارنامهٔ مهروموم‌شده برای گیرنده، یک گرنت کوتاه‌مدت را مطالبه کند |
| `wantResponseSigned`   | SAML       | خاموش             | الزام امضا روی ریشهٔ پاسخ (امضای assertion همیشه الزامی است)                                                                         |
| `issuer`               | OIDC       | —               | URL پایهٔ صادرکننده (برای فعال‌سازی الزامی)                                                                                                                 |
| `clientId`             | OIDC       | —               | شناسهٔ کلاینت عمومی (برای فعال‌سازی الزامی)                                                                                                                |
| `clientSecret`         | OIDC       | —               | فقط کلاینت‌های محرمانه؛ در فایل رازهای 0600 ذخیره می‌شود، هرگز در پایگاه‌داده — روی RPC فقط‌نوشتنی است (`sso.getConfig` مقدار `clientSecretPresent` را گزارش می‌کند) |
| `groupsClaim`          | OIDC       | `groups`        | ادعایی که نام گروه‌ها را حمل می‌کند                                                                                                                           |
| `defaultRole`          | هر دو       | `member`        | نقشی که وقتی هیچ گروهی نگاشت نمی‌شود اعمال می‌شود — هرگز `owner`                                                                                                              |
| `groupRoleMap`         | هر دو       | `{}`            | گروه → نقش؛ نگاشت‌های مالک هنگام ذخیره رد می‌شوند                                                                                                     |
| `autoMember`           | هر دو       | روشن              | افزودن خودکار کاربران به همهٔ فضاهای کاری در اولین ورود                                                                                                                     |
| `allowJit`             | هر دو       | روشن              | تأمین کاربران ناشناخته هنگام ورود                                                                                                                     |

## پیکربندی فرایند

اتصال‌های SSO از محیط بذرکاری نمی‌شوند. یک فلگ فرایندی باقی مانده است که تعیین
می‌کند مرورگر پس از بازگشت SSO، کلاینت وب را کجا باز کند:

| متغیر / فلگ                          | معنا                                                                                                              |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `--web-client-url` / `CC_SERVER_WEB_CLIENT_URL` | URL کلاینت وب برای واگذاری اعتبارنامهٔ مهروموم‌شده؛ خالی بماند، واگذاری هم‌مبدأ می‌ماند (تنها وقتی مفید است که کلاینت وب همان‌جا سرو شود). برای ورود `web-popup`، یک `client_origin` مجاز از زبانهٔ آغازکننده تقدم دارد. |

خودِ URL صادرکننده باید `https` باشد (`http` فقط برای صادرکننده‌های لوپ‌بک
`localhost`، `127.0.0.1` و `::1` پذیرفته می‌شود). برای بازگشت IdP و میزبان کلاینت
وب از TLS قابل‌اعتماد استفاده کنید: صفحه‌ای که کلید گیرنده را می‌سازد و JavaScript
تحویل‌داده‌شدهٔ آن بخشی از مرز اعتمادند. HTTPS از آن راه‌اندازی اولیه محافظت
می‌کند؛ پس از جفت‌سازی، نشست‌های `/rpc` مستقیم و رله‌شده هر دو به رمزنگاری Noise و
هویت پین‌شدهٔ سرور نیاز دارند.

## نقاط پایانی HTTP

| نقطهٔ پایانی                                         | احراز هویت                | هدف                                                                                                                                                                                                         |
| ------------------------------------------------ | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /saml/login?relay=…&handoff_key=…`                        | هیچ (تغییر مسیر)     | آغاز ورود آغازشده از SP با کلید گیرندهٔ X25519 در دست کلاینت؛ `relay=desktop` کار را به برنامه واگذار می‌کند و `relay=web-popup` به زبانهٔ اتصالِ در انتظار پیام postMessage می‌فرستد (`client_origin` آن تنها وقتی رعایت می‌شود که فهرست مجاز مبدأها به آن اعتماد کند) |
| `POST /saml/acs`                                 | هیچ (POST از سوی IdP)     | تأیید assertion و تأمین کاربر؛ ورود آغازشده از SP اعتبارنامهٔ دستگاه صادرشده را به کلید گیرندهٔ آغازکننده مهروموم می‌کند؛ SAML ناخواستهٔ مجاز به‌جایش یک claim مقید به مرورگر می‌دهد |
| `POST /saml/claim`                               | گرنت مرورگر هم‌مبدأ | بازخرید یک گرنت SAML ناخواستهٔ یک‌بارمصرف با کوکی‌اش و یک `handoff_key` تازه؛ اعتبارنامهٔ مهروموم‌شده برای گیرنده برمی‌گرداند، هرگز کلید جفت‌سازی متن ساده |
| `GET /saml/metadata`                             | هیچ                | `EntityDescriptor` مربوط به SP ما                                                                                                                                                                                       |
| `GET /oidc/login?relay=…&handoff_key=…` / `GET /oidc/callback` | هیچ                | رفت‌وبرگشت OIDC؛ ورود به کلید گیرندهٔ در دست کلاینت نیاز دارد؛ `relay=desktop` کار را به برنامه واگذار می‌کند و `relay=web-popup` به زبانهٔ اتصالِ در انتظار (با همان قاعدهٔ `client_origin`) |
| `GET /auth/providers`                            | هیچ، CORS با `*`      | کاوش صفحهٔ اتصال: اتصال‌های SSO ارائه‌شده (`id`/`kind`/`label`) به‌همراه `pairingEnabled`                                                                                                                      |
| `/scim/v2/Users…`                                | Bearer (توکن SCIM) | برای Users: ساخت/گرفتن/فهرست+فیلتر/PUT/PATCH/DELETE                                                                                                                                                                   |
| `/scim/v2/Groups`                                | Bearer              | فقط‌خواندنی؛ push گروه طبق طراحی 501 پاسخ می‌دهد                                                                                                                                                                     |
| `/scim/v2/ServiceProviderConfig`                 | Bearer              | سند قابلیت‌ها                                                                                                                                                                                             |

برای SAML و OIDC آغازشده از SP، URL آغاز ورود به یک `handoff_key` معتبر نیاز دارد
(کلید عمومی X25519 کلاینت آغازکننده). سرور آن کلید را با ورود در انتظار نگه می‌دارد
و اعتبارنامهٔ دستگاه صادرشده را در بازگشت با X25519 زودگذر، HKDF-SHA256 و
AES-256-GCM مقید به مبدأ سرور مهروموم می‌کند. واگذاری رومیزی از
`control-center://pair` استفاده می‌کند، واگذاری وب در همان زبانه از قطعهٔ URL، و
`web-popup` اگر `client_origin` مجاز داده شده باشد به آن postMessage می‌فرستد (وگرنه
به URL پیکربندی‌شدهٔ کلاینت وب یا مبدأ بازگشت). پاکت مهروموم‌شده، نه یک کلید
جفت‌سازی متن ساده، در آن قطعه یا پیام popup سفر می‌کند. کلاینت آغازکننده کلید خصوصی
متناظر را برای باز کردنش نگه می‌دارد. این پاکت از نشست Noise الزامی که پس از
جفت‌سازی برقرار می‌شود جداست.

یک پاسخ SAML آغازشده از IdP (وقتی فعال باشد) هیچ گیرندهٔ آغازکننده‌ای ندارد.
به‌جایش، ACS یک کوکی مرورگر پنج‌دقیقه‌ای، HttpOnly و SameSite=Strict می‌گذارد و
گزینهٔ **Open web client** / **Open desktop app** را عرضه می‌کند. آن صفحه یک کلید
گیرندهٔ تازه می‌سازد و نیمهٔ عمومی و دستهٔ گرنتش را از همان مبدأ به `POST /saml/claim`
می‌فرستد. claim به کوکی و مبدأ منطبق نیاز دارد (یک مرز CSRF)، گرنت را یک بار مصرف
می‌کند و تنها یک پاکت مهروموم‌شده برای گیرنده برمی‌گرداند. قطعهٔ وب/رومیزی بعدی
همان پاکت و مادهٔ کلید خصوصی گیرنده را حمل می‌کند تا کلاینت مقصد بتواند بازش کند،
**نه** یک اعتبارنامهٔ دستگاه متن ساده. مرورگر دیگر یا گرنت منقضی نمی‌تواند
بازخریدش کند. مبدأ کلاینت وب مقصد می‌تواند به قطعه دسترسی یابد و رمزگشایی‌اش کند؛
یک صفحهٔ بازگشت یا مبدأ کلاینت وب آلوده می‌تواند اعتبارنامه‌ها را بدزدد. رمزنگاری
کد سرو‌شدهٔ نامعتبر را امن نمی‌کند.

## عملیات RPC

همهٔ عملیات‌های `sso.*` در محدودهٔ سرورند و به **مالک سرور** (به‌کاربرندهٔ این
نصب، `ServerAuthority.serverOwner`) گره خورده‌اند. مالک‌بودن یک فضای کاری
کافی نیست؛ جفت‌سازی به‌تنهایی هرگز این دسترسی را نمی‌دهد.

| عملیات                        | هدف                                                                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sso.getConfig`           | اتصال ذخیره‌شده برای یک نوع                                                                                                                               |
| `sso.saveConfig`          | اعتبارسنجی، ذخیره و اعمال زنده                                                                                                                              |
| `sso.status`              | فلگ‌های فعال/پیکربندی‌شده، وجود توکن SCIM، مبدأ کانونیکال                                                                                               |
| `sso.testConnection`      | آزمایش یک اتصال بدون رفت‌وبرگشت مرورگر (SAML: تجزیهٔ فراداده + ساخت AuthnRequest؛ OIDC: کشف صادرکننده)، با مقدارهای ذخیره‌نشدهٔ اختیاری روی صفحه |
| `sso.spMetadata`          | تولید `EntityDescriptor` مربوط به SP برای یک مبدأ                                                                                                                  |
| `sso.setPairingEnabled`   | مجاز/ممنوعکردن جفت‌سازی دستی (کد دعوت، کلید جفت‌سازی)؛ خودداری از خاموش‌کردن آن تا وقتی هیچ اتصال SSO کارآمدی وجود ندارد، از قفل‌شدن حساب جلوگیری می‌کند                |
| `sso.sessionPolicy`       | خواندن حداکثر عمر اعتبارنامهٔ دستگاه و مهلت بیکاری این نصب (دقیقه؛ `0` = تعیین‌نشده)                                                                          |
| `sso.setSessionPolicy`    | تعیین آن حدود؛ در بررسی دستگاه اعمال می‌شود، نه اینکه به کلاینت‌ها اعلام شود                                                                                     |
| `sso.scimRegenerateToken` | تولید و بازگرداندن توکن bearer مربوط به SCIM (یک‌بار)                                                                                                                |

## کدهای خطای اعتبارسنجی

شکست‌های `cc_saml_verify_response` یک کد پایدار حمل می‌کنند:

| کد                   | معنا                                                                          |
| ---------------------- | -------------------------------------------------------------------------------- |
| `signature`            | امضای گمشده/غیرقابل‌اعتماد/دستکاری‌شده، یا الگوریتم/تبدیلی که مجاز نیست        |
| `expired`              | بیرون از `NotBefore`/`NotOnOrAfter` (فراتر از انحراف مجاز)                                 |
| `audience`             | محدودیت audience ما را نام نمی‌برد                                            |
| `destination`          | مقصد پاسخ همان ACS ما نیست                                              |
| `request_match`        | `InResponseTo` با هیچ درخواست در انتظاری مطابقت ندارد، یا پاسخ ناخواسته است در حالی که ناخواسته‌ها مجاز نیستند |
| `issuer`               | صادرکننده همان IdP پیکربندی‌شده نیست                                                 |
| `recipient`            | گیرندهٔ تأیید subject همان ACS ما نیست                                    |
| `malformed`            | شکست در سطح XML/شِما                                                         |
| `status`               | وضعیت گزارش‌شدهٔ IdP «Success» نبود                                                 |
| `invalid` / `internal` | هر چیز دیگر / شکست درز                                                     |

## سطوح پایگاه‌داده

- `sso_connections` (global.db) — یک ردیف به‌ازای هر نوع، طبق طراحی میان همهٔ
  فضاهای کاری.
- `users.sso_subject` + `users.sso_issuer` — سنجاق subject ارائه‌دهنده،
  به‌ازای هر `(issuer, subject)` از طریق یک ایندکس جزئی یکتا.
- `users.deactivated_at` — مُهر غیرفعال‌سازی SCIM.
- توکن bearer مربوط به SCIM و راز کلاینت OIDC در فایل رازهای 0600 زندگی
  می‌کنند، هرگز در پایگاه‌داده.
