هر پرچم فرایند هم به‌شکل یک پرچم خط فرمان و هم یک متغیر محیطی پذیرفته می‌شود؛
اولویت با پرچم است، سپس متغیر محیطی و در آخر مقدار پیش‌فرض. اعتبارنامه‌های
سرویس‌های ثالث استثنا هستند — [ارائه‌دهندگان برنامه و Connect](#ارائهدهندگان-برنامه-و-connect) را ببینید.

:::caution[پرچم‌های ناشناخته بی‌صدا نادیده گرفته می‌شوند]
تجزیه‌گر آرگومان دست‌ساز است و هر چیزی را که نشناسد رد می‌کند، پس یک غلط تایپی (`--tls-key-file`، `--bindany`) هیچ خطایی تولید نمی‌کند — سرور فقط با مقدار پیش‌فرض بالا می‌آید. وقتی به‌نظر می‌رسد پرچمی اثر ندارد، خطوط لاگ راه‌اندازی را بررسی کنید. یک [پرچم حالت کد](#حالت-کد) با مقداری که نمی‌پذیرد متفاوت است: سرور از شروع امتناع می‌کند.
:::

| `--bind`        | `CC_SERVER_BIND`       | `loopback`                                       | `loopback`، یا `any`/`all`/`0.0.0.0` برای همهٔ واسط‌ها (به TLS یا `--insecure` نیاز دارد)                        |
| `--repo-roots`  | `CC_SERVER_REPO_ROOTS` | پوشهٔ خانهٔ کاربر سرور                            | پوشه‌های پایهٔ جداشده با کاما که یک کلاینت هنگام ثبت مخزن می‌تواند در آن‌ها بگردد. گردش بالاتر از یک ریشه رد می‌شود |
| `--log-level`   | `CC_SERVER_LOG_LEVEL`  | `warning`                                        | `debug`، `info`، `warning` یا `error`. خطوط بوت‌شدن/آماده‌شدن همیشه چاپ می‌شوند                                  |
| `--server-name` | `CC_SERVER_NAME`       | نام میزبان ماشین                                 | نامی که در انتخاب‌گرها، کشف و سطوح جفت‌سازی نشان داده می‌شود                                                     |

## دسترس‌پذیری و TLS

| پرچم                | متغیر محیطی                 | پیش‌فرض                        | معنا                                                                                                                                                       |
| ------------------- | --------------------------- | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--tls-cert`        | `CC_SERVER_TLS_CERT`        | تنظیم‌نشده                     | زنجیرهٔ گواهی PEM. وقتی همراه کلید تنظیم شود، `wss://` را درون‌فرایندی سرو می‌کند                                                                           |
| `--tls-key`         | `CC_SERVER_TLS_KEY`         | تنظیم‌نشده                     | کلید خصوصی PEM متناظر با گواهی                                                                                                                             |
| `--insecure`        | `CC_SERVER_INSECURE`        | خاموش                          | اجازهٔ bind متن ساده روی غیر loopback. فقط پشت یک پروکسی مختوم‌کنندهٔ TLS روی شبکه‌ای قابل‌اعتماد؛ وقتی TLS پیکربندی شده باشد نادیده گرفته می‌شود             |
| `--public-url`      | `CC_SERVER_PUBLIC_URL`      | برگرفته از bind                | نشانی RPC‌ای که این سرور به کلاینت‌های جفت‌شده اعلام می‌کند. **پشت پروکسی، NAT یا تونل این را صریح تنظیم کنید** — مقدار پیش‌فرض فقط حدسی از bind محلی است     |
| `--allowed-origins` | `CC_SERVER_ALLOWED_ORIGINS` | `https://app.usectrl.dev`     | مبدأهای مرورگری جداشده با کاما که می‌توانند `/rpc` را میان‌مبدأیی صدا بزنند. loopback و کلاینت‌های بومی همیشه مجازند                                           |
| `--web-client-url`  | `CC_SERVER_WEB_CLIENT_URL`  | تنظیم‌نشده                     | مبدأ کلاینت وب میزبانی‌شده‌ای که بازگشت‌های ورود یکپارچه به آن برمی‌گردند                                                                                     |
| `--signaling-url`   | `CC_SERVER_SIGNALING_URL`   | `wss://signaling.usectrl.dev` | کارگزار رله‌ای که این سرور به آن می‌پیوندد تا یک تلفن بدون مسیر مستقیم بتواند به آن برسد                                                                    |
| `--mdns`            | `CC_SERVER_MDNS`            | `auto`                        | اعلان در شبکهٔ محلی: `auto` (فقط وقتی فراتر از loopback مقید شده باشد)، `on`، `off`. کشف فقط وجود را اعلام می‌کند — پیوستن هنوز به جفت‌سازی نیاز دارد        |
| `--tunnel`          | `CC_SERVER_TUNNEL`          | `off`                         | ارائه‌دهندهٔ تونل مدیریت‌شده: `off`، `cloudflared`، `ngrok`، `tailscale`. افشای عمومی فقط با انتخاب صریح شما فعال می‌شود                                      |
| `--tunnel-binary`   | `CC_SERVER_TUNNEL_BINARY`   | از `PATH` حل می‌شود            | مسیر صریح باینری تونل                                                                                                                                       |
| `--tunnel-sha256`   | `CC_SERVER_TUNNEL_SHA256`   | تنظیم‌نشده                     | SHA-256 مورد انتظار آن باینری، که پیش از هر spawn بررسی می‌شود                                                                                              |
| `--tunnel-args`     | `CC_SERVER_TUNNEL_ARGS`     | خالی                           | آرگومان‌های اضافی جداشده با کاما برای فراخوانی تونل                                                                                                         |

| پرچم                     | متغیر محیطی                     | پیش‌فرض                               | معنا                                                                                                                          |
| ------------------------ | ------------------------------- | ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `--sandbox`              | `CC_SERVER_SANDBOX`             | `on`                                  | `on` اجراهای عامل را در سندباکس بومی سیستم‌عامل میزبان می‌پیچد، و روی میزبانی بدون آن فقط اجراهای مالک سرور شروع می‌شوند. `off` اجراهای عضو همه را روی این میزبان بدون محدودسازی اجرا می‌کند. پایین را ببینید |
| `--code-index`           | `CC_SERVER_CODE_INDEX`          | `on`                                  | کلید قطع میدانی برای نمایه‌سازی پس‌زمینهٔ گراف کد. `off` بدون بازساخت، تمیز بوت می‌شود                                          |
| `--code-index-defer`     | `CC_SERVER_CODE_INDEX_DEFER`    | `15`                                  | ثانیه‌هایی که نخستین جاروب نمایه‌سازی پس از بنر آماده‌بودن به تعویق می‌افتد (محدود به ۰–۳۰۰)                                     |
| `--tool-deferral`        | `CC_SERVER_TOOL_DEFERRAL`       | `on`                                  | آیا اجراهای هارنس یک مجموعهٔ کوچک ابزار مستقیم به‌همراه یک نمایهٔ نامی می‌فرستند و بقیه را در نخستین استفاده بار می‌کنند. پایین را ببینید |
| `--credential-gate`      | `CC_SERVER_CREDENTIAL_GATE`     | `900`                                 | ثانیه‌هایی که یک اجرا پارک می‌ماند تا انسانی اعتبارنامه‌ای را که نمی‌تواند کارش را بسازد درست کند (محدود به ۰–۳۶۰۰). پایین را ببینید |
| `--code-mode-max-processes` | `CC_SERVER_CODE_MODE_MAX_PROCESSES` | `min(16, 2 × cores)` | اسکریپت‌های حالت کد که همزمان روی این سرور اجرا می‌شوند، به‌جز آن‌هایی که منتظر یک شخص‌اند، ۱ تا ۶۴. در ادامه را ببینید |
| `--code-mode-max-heap-mb` | `CC_SERVER_CODE_MODE_MAX_HEAP_MB` | `1024` | بیشترین حافظه‌ای که یک اسکریپت می‌تواند مصرف کند، ۱۶ تا ۱۰۲۴ MiB. سقف بالاتر حافظهٔ یک فضای کاری به آن کاهش داده می‌شود |

## ارائه‌دهندگان برنامه و Connect

هیچ build‌ای اعتبارنامهٔ ارائه‌دهنده همراه ندارد. با Control Center Connect روشن، Connect هر ارائه‌دهنده را اجرا می‌کند و این برنامه‌های خودی ذخیره‌شده اما بدون استفاده می‌مانند. تحت **استفاده از برنامه‌های خودم**، هر ارائه‌دهنده روی برنامهٔ خود سرور اجرا می‌شود وقتی کاملاً پیکربندی شده باشد، وگرنه در دسترس نیست. برنامهٔ اختصاصی فضای کاری در هر دو حالت اعمال می‌شود. برنامه‌های خودی در **تنظیمات ← سرور ← ورود یکپارچه ← برنامه‌های ارائه‌دهنده** تنظیم می‌شوند، یا یک‌بار از فایل `.env` سرور بذر می‌شوند. فلگ برای آن‌ها وجود ندارد: یک راز روی خط فرمان از طریق `ps` خوانده می‌شود.

| متغیر                          | معنا                                                                                                                      |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `GITHUB_APP_ID`                | شناسهٔ GitHub App سرور                                                                                                    |
| `GITHUB_APP_PRIVATE_KEY`       | کلید خصوصی آن، در یک خط با escapeهای `\n`. **فقط `.env`**                                                                |
| `GITHUB_CLIENT_ID`             | شناسهٔ کلاینت آن، برای ورود افراد                                                                                         |
| `GITHUB_CLIENT_SECRET`         | رازِ کلاینت آن. **فقط `.env`**                                                                                            |
| `GOOGLE_OAUTH_CLIENT_ID`       | کلاینت Web application سرور برای Google                                                                                    |
| `GOOGLE_OAUTH_CLIENT_SECRET`   | راز آن. **فقط `.env`**                                                                                                    |
| `LINEAR_CLIENT_ID`             | برنامهٔ Linear سرور (PKCE، بدون راز)                                                                                      |
| `LINEAR_API_KEY`               | یک کلید سرویس Linear برای خودکارسازی. **فقط `.env`**                                                                     |
| `KLIPY_APP_KEY`                | کلید Klipy خود سرور برای جست‌وجوی GIF، تنها تحت **استفاده از برنامه‌های خودم**                            |
| `CC_CONNECT_URL`               | `hosted`، `off` یا نشانی Connect. انتخاب Connect را قفل می‌کند؛ تنظیمات نمی‌توانند آن را تغییر دهند                       |
| `CC_SERVER_CONNECT_HOST`       | `on` یعنی Control Center Connect در `<server>/connect` سوار می‌شود، که با متغیرهای `CONNECT_*` پیکربندی می‌شود. ببینید [اجرای سرور Connect](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/اجرای-سرور-connect/#سوار-کردن-connect-درون-cc_server) |

فایل `.env` از پوشهٔ کاری سرور، کنار فایل اجرایی، یا یک checkout کد منبع بالاتر خوانده می‌شود؛ در Docker آن را در `/app/bin/.env` سوار کنید. سرور **از راه‌اندازی خودداری می‌کند** (کد خروج `78`) وقتی `GITHUB_APP_PRIVATE_KEY`، `GITHUB_CLIENT_SECRET`، `GOOGLE_OAUTH_CLIENT_SECRET`، `LINEAR_API_KEY` یا هر `SLACK_*SECRET*` در محیط فرایندش صادر شده باشد، جایی که هر فرایند فرزندی می‌تواند آن‌ها را بخواند. بذرگیری از `.env` برای هر فیلد یک‌بار انجام می‌شود، پس ویرایش بعدی در تنظیمات با راه‌اندازی مجدد پاک نمی‌شود. مقدار خالی به‌عنوان تنظیم‌نشده خوانده می‌شود.

هیچ اعتبارنامهٔ میزبانی کد از محیط نمی‌آید: GitHub، GitLab و Bitbucket همگی با ورود یا توکن خود یک عضو عمل می‌کنند، یا با توکن‌های GitHub App برای یک مخزن که یک عضو مسئول محدودشان می‌کند.

### `--sandbox`

سرور هنگام بوت یک‌بار میزبان را بررسی می‌کند و هرجا بک‌اندی در دسترس باشد، اجرای
فرمان عامل را در سندباکس بومی سیستم‌عامل می‌پیچد: `sandbox-exec` (Seatbelt) روی
macOS، `bwrap` به‌همراه `socat` روی Linux و WSL2. تصمیم یک‌بار گرفته می‌شود و تا راه‌اندازی مجدد سرور برقرار می‌ماند. سه نتیجه وجود دارد که هرکدام در خط exposure راه‌اندازی نشان داده می‌شود:

| `sandbox=`    | زمان                                    | اجرای چه کسانی شروع می‌شود                                                        |
| ------------- | --------------------------------------- | -------------------------------------------------------------------------------- |
| `native`      | یک بک‌اند در دسترس است و `--sandbox` روی `on` است | اجرای همه، پیچیده‌شده                                                        |
| `off`         | `--sandbox off`                         | اجرای همه، بدون محدودسازی روی این میزبان                                              |
| `unavailable` | `--sandbox on` و بدون بک‌اند (Windows، یا Linux بدون `bwrap` و `socat`) | فقط اجراهایی که مالک سرور مسئول آن‌هاست، بدون محدودسازی. بقیه با «این سرور سندباکس ندارد، پس فقط مالکش می‌تواند اینجا عامل اجرا کند.» رد می‌شوند |

برای خودکارسازی، شخص مسئول کسی است که خودکارسازی به او متصل است. اگر هیچ مالک سروری ثبت نشده باشد، روی میزبان `unavailable` هیچ اجرایی شروع نمی‌شود. روی Linux و WSL2 که bubblewrap نصب است، دیسپچ بومی در حال حاضر برای همهٔ اجراها بسته می‌ماند و شکست می‌خورد؛ [بک‌اندهای سندباکس](/fa-IR/راهنمای-کاربر/مرجع/بکاندهای-سندباکس/#linux-bubblewrap) را ببینید.

`--sandbox off` انتخاب مالک سرور برای همهٔ کسانی است که از سرور استفاده می‌کنند: اجرای عامل همهٔ اعضا را روی این ماشین بدون محدودسازی اجرا می‌کند. از آن روی میزبانی استفاده کنید که خود پروفایل سندباکس بدرفتاری می‌کند، یا برای اینکه اعضا روی میزبانی بدون بک‌اند عامل اجرا کنند. به بازساخت نیاز ندارد و سرور تا پایان عمر فرایند یک هشدار در لاگ می‌نویسد تا این وضعیت هرگز بی‌صدا نماند.

### `--tool-deferral`

اجراهای هارنس داخلی یک مجموعهٔ کوچک مستقیم از تعریف‌های ابزار به‌همراه یک نمایهٔ فقط‌نامی از بقیه می‌فرستند که اسکیماهایشان را نخستین‌بار که به کار روند بار می‌کنند، یا از یک اسکریپت `repl` فراخوانی می‌شوند. این کار مجموعهٔ همیشه‌پیدا را در محدوده‌ای نگه می‌دارد که مدل‌ها در آن ابزارها را قابل‌اتکا انتخاب می‌کنند. با اندازه‌گیری روی رجیستری‌ای که آزمون‌ها می‌سازند، ابزارهای استاندارد گفتگوی عامل داخلی به ۱۴ تعریف می‌رسند: حدود ۱۶٫۵ KB با `repl` (که حدود ۴ KB آن مال `repl` است، و تعریفش نمی‌تواند از ۴٬۰۹۶ بایت بیشتر شود)، و حدود ۱۳ KB روی سروری که نمی‌تواند اسکریپت اجرا کند. ابزارهای به‌تعویق‌افتاده در سراسر اجرا با نام فراخواندنی می‌مانند و `search_tools` آن‌ها را بر پایهٔ قصد پیدا می‌کند. [بافت ابزار و کش پرامپت](/fa-IR/راهنمای-کاربر/مفهومها/بافت-ابزار/) را ببینید.

`--tool-deferral off` هر تعریف ابزار پذیرفته‌شده را از ابتدا می‌فرستد، جز اینکه یک اجرای دارای `repl` همچنان ابزارهایی را که یک اسکریپت ممکن است فراخوانی کند از اسکریپت فراخوانی می‌کند. این کلید قطع برای مدلی است که سطح دوسطحی را بد اداره می‌کند — یک پرچم، به‌جای یک بازساخت. فقط هارنس داخلی را متأثر می‌کند؛ `tools/list`ی که MCP به کلاینت‌های بیرونی نشان می‌دهد فهرست کامل است، جز برای یک اجرای عامل روی سروری که می‌تواند اسکریپت‌های [حالت کد](/fa-IR/راهنمای-کاربر/مفهومها/حالت-کد/) اجرا کند.

### `--credential-gate`

اجرایی که اعتبارنامهٔ ارائه‌دهنده‌اش گم شده یا مصرف شده باشد، به‌جای شکست **پارک
می‌شود**: به اپراتور پیامی داده می‌شود تا آن را درست کند و اگر این کار را بکند،
اجرا از سر گرفته می‌شود. مهلت پیش‌فرض ۹۰۰ ثانیه (۱۵ دقیقه) است و به ۰–۳۶۰۰ محدود
می‌شود.

این مهلت عامدانه بسیار طولانی‌تر از مهلت پرامپت تأیید است: تأیید تصمیمی است که کسی
در چند ثانیه می‌گیرد، در حالی که درست‌کردن یک اعتبارنامه یعنی باز کردن ترمینال،
ورود و برگشتن. همین سقف است که نمی‌گذارد یک اجرای بی‌سرپرست — یک گام پایپ‌لاین، یک
تریگر cron، یک وبهوک — منتظر کسی بماند که خواب است. وقتی مهلت تمام شود، اجرا با
همان پیامی شکست می‌خورد که در هر حال می‌خورد.

`--credential-gate=0` کلید قطع است: هیچ‌چیز هرگز پارک نمی‌شود و یک اعتبارنامهٔ بد
همان‌طور که پیش از وجود این دروازه نوبت را پایان می‌داد، الان هم پایان می‌دهد.

### حالت کد

[حالت کد](/fa-IR/راهنمای-کاربر/مفهومها/حالت-کد/) به یک عامل اجازه می‌دهد اسکریپت JavaScript را اجرا کند که ابزارهایش را فراخوانی می‌کند. هیچ پرچمی آن را روشن یا خاموش نمی‌کند: وقتی سرور بتواند اسکریپت اجرا کند، هر اجرا ابزار `repl` را دارد، و یک سرور نمایشی عمومی هیچ اسکریپتی اجرا نمی‌کند.

اسکریپت‌ها در `cc_codemode` اجرا می‌شوند، برنامه‌ای که همراه سرور در `bin/codemode/` عرضه می‌شود. سرور بدون آن شروع نمی‌شود: نام آنچه کم است را در یک خط چاپ می‌کند و با کد خروج `78` خارج می‌شود. هنگام شروع، خودآزمایی قفل برنامه را اجرا می‌کند و یک خط چاپ می‌کند (که فقط با `--log-level error` خاموش می‌شود):

```text
cc_server: code_mode=available (cc_codemode 0.1.0 quickjs-ng 0.16.2 protocol 2; 16 scripts at once, at most 12 per workspace; up to 64 more runners kept for scripts waiting on a person; heap at most 1024 MiB per script)
cc_server: code_mode=unavailable (<reason>) — runs on this host get no repl tool; scripts never run without full lockdown
```

`unavailable` یعنی برنامه نمی‌تواند روی این میزبان خودش را قفل کند، برای مثال داخل کانتینری که پروفایل امنیتی‌اش یکی از مراحلش را رد می‌کند، یا ساخت انتشار نباشد. سرور عادی اجرا می‌شود، هیچ اجرایی `repl` نمی‌گیرد، و تنظیمات حالت کد فضای کاری دلیل را نشان می‌دهد.

سرور در حین اجرا همچنان بررسی می‌کند. وقتی برنامه برای دلیلی که به اسکریپت مربوط نیست آغاز نمی‌شود، سرور خودآزمایی را دوباره اجرا می‌کند، حداکثر یک بار در دقیقه. اگر این شکست بخورد، سرور خط `unavailable` را همراه دلیلش چاپ می‌کند و هیچ اسکریپتی اجرا نمی‌کند: اجراهایی که در این فاصله آغاز می‌شوند `repl` نمی‌گیرند، و اجرایی که از پیش آن را دارد ابزارهایش را مستقیم فراخوانی می‌کند ([وقتی اسکریپت‌ها نمی‌توانند اجرا شوند](/fa-IR/راهنمای-کاربر/مفهومها/حالت-کد/#وقتی-اسکریپتها-نمیتوانند-اجرا-شوند)). سرور حداکثر یک بار در دقیقه بررسی را ادامه می‌دهد و وقتی خودآزمایی دوباره بگذرد، خط `available` را چاپ می‌کند و دوباره اسکریپت اجرا می‌کند. فقط خودآزمایی‌ای که هنگام شروع شکست خورده باشد به راه‌اندازی مجدد نیاز دارد. دلیلی که تنظیمات فضای کاری نشان می‌دهد مسیرهای میزبان را ندارد؛ خط لاگ آن را کامل دارد.

دو پرچم حالت کد آنچه اسکریپت‌ها می‌توانند استفاده کنند را محدود می‌کنند. `--code-mode-max-processes` تعداد اسکریپت‌هایی را که همزمان در همهٔ فضاهای کاری اجرا می‌شوند محدود می‌کند (به‌طور پیش‌فرض دو برابر هسته‌های پردازنده، حداکثر ۱۶؛ پذیرفته‌شده ۱ تا ۶۴). با سقف ۲ یا بیشتر، یک فضای کاری حداکثر سقف منهای یک‌چهارم آن را استفاده می‌کند، تا هیچ فضای کاری تنهایی همهٔ جاها را نگیرد، و اسکریپت‌های در انتظار بین فضاهای کاری به نوبت پذیرفته می‌شوند. اسکریپتی که منتظر تأیید یا پاسخ یک شخص است جایش را به اسکریپت دیگری می‌دهد و تا پاسخ داده نشود هیچ فراخوانی ابزاری آغاز نمی‌کند؛ تا چهار برابر سقف از این اسکریپت‌های در انتظار نگه داشته می‌شوند، که حداکثر سه‌چهارم آن‌ها از یک فضای کاری باشد، و هر کدام می‌توانند در محدودهٔ زمان پردازندهٔ خودشان محاسبه کنند. `--code-mode-max-heap-mb` بیشترین حافظه‌ای است که هر اسکریپت می‌تواند مصرف کند.

مقداری که این پرچم‌ها نمی‌پذیرند (عددی خارج از بازه، یا عددی نیست) سرور را هنگام شروع متوقف می‌کند (کد خروج `78`) با پیامی که مقادیر پذیرفته‌شده را نام می‌برد. هرگز به‌عنوان پیش‌فرض خوانده نمی‌شود.

## زیرفرمان‌ها

| فرمان                                         | کارش                                                                                                 |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `cc_server`                                   | سرور را تا `SIGINT`/`SIGTERM` اجرا می‌کند                                                            |
| `cc_server pair`                              | دستگاهی را تأمین می‌کند و شناسه و کلید جفت‌سازی‌اش را چاپ می‌کند. در برابر پوشهٔ داده‌ای که سروری همین حالا سرو می‌کند ایمن است — سرور در حال اجرا دستگاه را بدون راه‌اندازی مجدد برمی‌دارد |
| `cc_server connect <command>`                 | نشان می‌دهد یا تغییر می‌دهد کدام Control Center Connect این سرور استفاده می‌کند، بدون اجرای آن                                  |
| `cc_server update`                            | یک نسخهٔ مستقل تازه‌تر را بررسی، دانلود و تأیید می‌کند                                               |
| `cc_server --version`                         | نسخهٔ ساخت و SHA گیت را چاپ می‌کند — همان هویتی که `/healthz` و دست‌دادن RPC اعلام می‌کنند            |

### `pair`

| پرچم           | پیش‌فرض                                                   | معنا                                                                                                                                                                  |
| -------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--device`     | `web-client`                                              | شناسهٔ دستگاه. پلتفرم از روی آن استنباط می‌شود، پس `--device desktop` یک سطر رومیزی و `--device ios`/`android` یک سطر تلفن می‌سازد؛ هر چیز دیگری وب در نظر گرفته می‌شود |
| `--label`      | نام پلتفرم به‌همراه نام میزبان این ماشین                    | نام نمایشی در فهرست دستگاه‌ها                                                                                                                                          |
| `--host`       | `localhost`، یا `<this-host>` وقتی به همهٔ واسط‌ها مقید شده باشد | میزبانی که در نشانی چاپ‌شده جای می‌گیرد. آن را روی IP شبکهٔ محلی یا میزبان تونلی بگذارید که کلاینت واقعاً با آن تماس می‌گیرد                                             |
| `--client-url` | تنظیم‌نشده                                                 | مبدأ کلاینت **وب** میزبانی‌شده. یک پیوند عمیق قابل‌اسکن و یک QR ترمینال اضافه می‌کند                                                                                     |

`pair` همچنین پرچم‌های هستهٔ `--data-dir`، `--port` و `--bind` را می‌پذیرد: آن‌ها
پوشهٔ داده‌ای را که نوشته می‌شود تعیین و نشانی چاپ‌شدهٔ سرور را شکل می‌دهند (`ws`
روی loopback، `wss` وقتی `--bind any`). اجرای دوبارهٔ `pair` برای همان `--device`
کلیدش را می‌چرخاند و نشست‌های زندهٔ آن دستگاه را قطع می‌کند. اعتبارنامه‌ای که اینجا
صادر می‌شود **بدون انقضا** است، برخلاف ۳۰ روزی که یک جفت‌سازی درون‌برنامه‌ای تعیین
می‌کند.

:::caution[QR مربوط به `--client-url` همان QR تلفن نیست]
`pair --client-url` فرم اتصال کلاینت **وب** را پر می‌کند (نشانی سرور، شناسهٔ دستگاه
و کلید در بخش fragment نشانی). تلفن با محتوای متفاوتی جفت می‌شود که از پنل
جفت‌سازی درون‌برنامه صادر می‌شود — توصیف‌گر کامل اتصال سرور به‌همراه یک انقضا. این
دو جانشین‌پذیر نیستند — [جفت‌کردن دستگاه](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/جفت-کردن-دستگاه/) را ببینید.
:::

### `connect`

همان تنظیماتی را می‌خواند و می‌نویسد که کارت **Control Center Connect** تحت **تنظیمات ← سرور ← ورود یکپارچه** دارد، از پوشهٔ داده. یک سرور در حال اجرا تغییر را ظرف ۱۰ دقیقه یا با راه‌اندازی مجدد می‌گیرد.

| فرمان                                  | کار آن                                                                                                                            |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `cc_server connect status`             | حالت، نشانی، اینکه آیا `CC_CONNECT_URL` آن را قفل کرده، شناسهٔ نصب، سلامت و منبع هر مسیر (`own`، `connect` یا `off`) را چاپ می‌کند |
| `cc_server connect enable`             | از Control Center Connect میزبانی‌شده استفاده می‌کند                                                                             |
| `cc_server connect enable --url <url>` | از Connect سفارشی در آن نشانی استفاده می‌کند (HTTPS، یا `http` روی loopback)                                                   |
| `cc_server connect disable`            | استفاده از Connect را متوقف می‌کند. فقط برنامه‌های خود سرور افراد را وارد می‌کنند                                               |

اگر `status` بدون فرمان باشد، پیش‌فرض است. هر فرمان `--data-dir` را می‌پذیرد. `CC_CONNECT_URL` هر آنچه را این فرمان‌ها ذخیره می‌کنند نادیده می‌گیرد. فرمان ناشناخته با کد `64` خارج می‌شود. برای حالت‌ها، هویت نصب و کدهای وضعیت، ببینید [مرجع Control Center Connect](/fa-IR/راهنمای-کاربر/مرجع/connect/).

### `update`

`--apply` نصب را جایگزین می‌کند؛ تا وقتی سروری هنوز روی پورت پیکربندی‌شده پاسخ
می‌دهد رد می‌شود، مگر اینکه `--force` را بدهید. `--allow-downgrade` یک نسخهٔ
قدیمی‌تر را مجاز می‌کند.

این فرمان برای نصب‌هایی که مالکشان نیست، سرراست رد می‌کند — با یک توضیح، نه یک
خطا:

| محیط                          | شناسایی با                                  | آنچه می‌گوید                                                |
| ----------------------------- | ------------------------------------------- | ----------------------------------------------------------- |
| سرور جاسیشدهٔ برنامهٔ رومیزی   | `CC_EMBEDDED=1` یا `CC_BOOTSTRAP_DEVICE_ID` | در عوض برنامه را به‌روزرسانی کنید — نصب‌کننده کل درخت را جابه‌جا می‌کند |
| یک checkout منبع `dart run`   | مسیر اسکریپت به `.dart` ختم می‌شود           | آن را با git به‌روزرسانی کنید                                |
| Docker                        | نشانگرهای کانتینر                           | یک ایمیج تازه‌تر را pull کنید                                |

## چرخهٔ عمر فرایند

`cc_server` تا `SIGINT` / `SIGTERM` اجرا می‌شود. یک متغیر محیطی اضافی این را کنترل
می‌کند و آن را برنامهٔ رومیزی تنظیم می‌کند، نه شما:

| متغیر                   | اثر                                                                                                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `CC_EXIT_WITH_PARENT=1` | سرور وقتی فرایند والدش خارج شود خارج می‌شود؛ این با بستن سرِ نوشتن لولهٔ stdin توسط والد تشخیص داده می‌شود. برنامهٔ رومیزی آن را تنظیم می‌کند تا یک برنامهٔ ازکارافتاده هرگز سروری یتیم را روی پوشهٔ داده جا نگذارد |

آن را خودتان فقط وقتی تنظیم کنید که `cc_server` را به‌عنوان یک فرایند فرزند
سرپرستی می‌کنید و همان تضمین را می‌خواهید.

`DO_NOT_TRACK=1` (هر مقداری جز خالی، `0` یا `false`) [تحلیل‌های استفادهٔ](/fa-IR/راهنمای-کاربر/مرجع/تحلیل-استفاده/)
خود سرور را متوقف می‌کند، حتی وقتی کلید سراسری سرور روشن است. کلاینت‌ها همچنان
از کلید پیروی می‌کنند.

## چیدمان پوشهٔ داده

پوشهٔ دادهٔ پیش‌فرض روی macOS `~/Library/Application Support/control-center`، روی
Windows `%APPDATA%\control-center` و جاهای دیگر
`$XDG_DATA_HOME/control-center` (در غیر این صورت
`~/.local/share/control-center`) است. یک `.cc_server` نسبت به پوشهٔ کاری جاری فقط
وقتی به کار می‌رود که هیچ پوشهٔ خانه یا دادهٔ برنامه‌ای حل نشود.

سرور دادهٔ پوشه را فقط برای حساب خودش خصوصی نگه می‌دارد (`0700`). اگر نتواند این کار را بکند، یا وقتی `global.db` آسیب دیده یا با نسخهٔ جدیدتری نوشته شده است، یا وقتی فایل هویتش خوانده نشود، از شروع خودداری می‌کند (کد خروج `78`).

| مسیر                              | محتوا                                                                            |
| --------------------------------- | -------------------------------------------------------------------------------- |
| `global.db`                       | دفتر ثبت فضاهای کاری، کاربران، دستگاه‌های جفت‌شده، خوراک خبری و صف ناوگان          |
| `<workspaceId>/workspace.db`      | یک پایگاه داده برای هر فضای کاری — عامل‌ها، فضاها، تیکت‌ها، حافظه         |
| `<workspaceId>/code_index.db` | گراف کد آن فضای کاری. وقتی نباشد بازسازی می‌شود و هرگز پشتیبان گرفته نمی‌شود |
| `pre_upgrade/`، `<workspaceId>/pre_upgrade/` | دو نسخهٔ تازه‌تر از پایگاه‌دادهٔ پیش از تغییر قالب در به‌روزرسانی |
| `<workspaceId>/chat_credentials/` | توکن‌های ربات گفتگو، به‌شکل JSON ساده، تا همراه فضای کاری بروند                    |
| `secrets.json`                    | کلید نصب Connect، برنامه‌های ارائه‌دهنده، ورودهای هر فرد (وقتی از طریق Connect ساخته شده باشند مهرشده)، رازهای وب‌هوک، SSO (`0600`) |
| `backups/<timestamp>/`            | یک اسنپ‌شات نصب — `manifest.json`، `global.db` و یک کپی از هر فضای کاری          |
| `backups/exports/`                | برون‌بری‌های تک‌فضای‌کاری، `<workspaceId>-<timestamp>.db`                          |
| `backups/transfer/`               | محوطهٔ آماده‌سازی دانلودها و بارگذاری‌های پشتیبان؛ توسط همان مسیری که آن را می‌نویسد پاک‌سازی می‌شود |
| `models/`                         | مدل‌های امبدینگ، تفکیک گوینده و گفتار روی دستگاه                                  |
| `codemode/` | یک نسخهٔ توسعه‌ای اجراکنندهٔ حالت کد، که با `scripts/natives/build_codemode.sh` نصب می‌شود؛ بسته‌های انتشار آن را در `bin/codemode/` دارند |
| `meetings/<meetingId>/`           | صدای نگه‌داشته‌شدهٔ جلسه                                                          |
| `rigs/images/`                    | ایمیج‌های دیسک ریگ درون‌بری‌شده (سطح رومیزی QEMU)                                 |
| `rigs/smolvm/<rigId>/`            | وضعیت زمان اجرای microVM هر ریگ (راز کارگزار، `0600`)                             |
| `rigs/smolvm-packs/`              | بسته‌های ماشین ازپیش‌استخراج‌شده — کشی که بوت‌های تکراری ریگ را سریع می‌کند        |
| `rigs/tls/`                       | مرجع گواهی دامنهٔ توسعه برای HTTPS ریگ (کلیدها `0600`)                            |
| `rigs/run/<rigId>/`               | اورلی‌های QEMU، ایمیج‌های بذر و کلیدهای هر VM (`0600`)                             |
