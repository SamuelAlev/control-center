این راهنما نشان می‌دهد چگونه برای سرور خودتان یک GitHub App مخصوص بسازید. حدود دو دقیقه طول می‌کشد، فقط مالک سرور آن را انجام می‌دهد، و فقط یک بار برای هر سرور لازم است.

وقتی Control Center Connect روشن باشد، افراد از طریق GitHub App مشترک Control Center، یا از طریق آن App‌ای که Connect سازمان شما استفاده می‌کند، با GitHub وارد می‌شوند. وقتی **استفاده از برنامه‌های من** را انتخاب کرده‌اید آن را خودتان ثبت کنید: برنامهٔ خود سرور فقط در آن حالت استفاده می‌شود. ببینید [Control Center Connect](/fa-IR/راهنمای-کاربر/مرجع/connect/).

برای ورود به حساب شخصی‌تان بعداً، ببینید [راه‌اندازی یکپارچه‌سازی GitHub](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/یکپارچهسازی-github/).

## این برنامه چه کاری انجام می‌دهد

یک ثبت دو کار متفاوت را پاسخ می‌دهد:

| کار                   | چه چیزی پاسخ می‌دهد                                         | چرا مهم است                                                                                   |
| --------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| **فرد وارد می‌شود**   | شناسهٔ کلاینت و رازِ کلاینت برنامه                           | هر کس اعتبارنامهٔ GitHub خودش را روی سرور و روی هر دستگاه می‌گیرد                              |
| **سرور عمل می‌کند**   | شناسهٔ برنامه و کلید خصوصی برنامه                            | عامل‌ها، پایپ‌لاین‌ها، نظرسنج‌ها و پاسخ‌های بات برای هر بار توکن یک مخزن می‌گیرند              |

کار دوم هرگز اعتبارنامهٔ یک فرد را به‌طور کامل قرض نمی‌گیرد. هر توکنی که سرور صادر می‌کند فقط یک مخزن را پوشش می‌دهد و به آنچه یک عضو مسئول می‌تواند در آنجا انجام دهد محدود است. خواندن یک مخزن متصل فقط به برنامه نیاز دارد؛ هر چیزی که بنویسد به عضوی نیاز دارد که بتواند push کند. خودکارسازی هرگز یک pull request را تأیید نمی‌کند.

برنامهٔ سرور تنها تحت **استفاده از برنامه‌های خودم** اعمال می‌شود. با Control Center یا Connect سفارشی، Connect هر مسیری از جمله GitHub را اجرا می‌کند و برنامهٔ سرور ذخیره‌شده اما بدون استفاده می‌ماند تا زمانی که برگردید. فضای کاری‌ای که روی برنامه‌های خودش است ([به یک فضای کاری برنامهٔ اختصاصی خودش را بدهید](#به-یک-فضای-کاری-برنامهٔ-اختصاصی-خودش-را-بدهید)) به‌جای آن از برنامهٔ خودش استفاده می‌کند، در هر حالتی که سرور دارد. برنامه‌ای که برخی فیلدهایش خالی است خطاست، نه یک جایگزین: ورود به GitHub تا وقتی همهٔ فیلدها تنظیم نشده‌اند رد می‌شود.

## پیش‌نیازها

- شما **مالک سرور** هستید. کارت **برنامه‌های ارائه‌دهنده** برای بقیه نامرئی است
- یک حساب GitHub. برنامه زیر آن ساخته می‌شود
- یک نشانی سرور که مرورگر شما بتواند به آن برسد. نشانی عمومی سرور (یا loopback، برای سرور خود یک دسکتاپ) همان جایی است که GitHub شما را به آن برمی‌گرداند

## یک‌باره بسازیدش

۱. به **تنظیمات ← سرور ← ورود یکپارچه** بروید و تا کارت **برنامه‌های ارائه‌دهنده** پایین بروید
۲. در بلوک **GitHub**، در صورت تمایل نام سازمان GitHub را که باید مالک برنامه باشد در **سازمان (اختیاری)** تایپ کنید. اگر خالی بگذارید، برنامه زیر حساب خودتان ساخته می‌شود؛ ساختن آن زیر یک سازمان، مالک آن سازمان را لازم دارد
۳. روی **ساختن GitHub App من** کلیک کنید
۴. مرورگر شما GitHub را باز می‌کند، با برنامه از قبل پرشده. روی **Create GitHub App** کلیک کنید
۵. GitHub شما را به سرور برمی‌گرداند؛ سرور شناسهٔ برنامه، کلید خصوصی، شناسهٔ کلاینت و رازِ کلاینت را ذخیره می‌کند، سپس صفحهٔ نصب برنامه را باز می‌کند

چیزی با دست کپی نمی‌شود، و کد تبدیل مستقیم از GitHub به سرور شما می‌رود. پیوند یک بار کار می‌کند و پس از ده دقیقه منقضی می‌شود؛ اگر منقضی شد، دوباره روی **ساختن GitHub App من** کلیک کنید.

برنامه `Control Center <code>` نام دارد و دقیقاً همان چیزی را می‌خواهد که Control Center استفاده می‌کند:

| مجوز                                       | دسترسی           |
| ------------------------------------------ | ---------------- |
| Metadata                                   | خواندن           |
| Contents                                   | خواندن و نوشتن   |
| Pull requests                              | خواندن و نوشتن   |
| Issues                                     | خواندن و نوشتن   |
| Checks، Actions، Commit statuses           | خواندن           |
| Organization members                       | خواندن           |

Webhookها خاموش‌اند: سرور نظرسنجی می‌کند. برای منتقل کردن برنامه‌ای که زیر حساب شخصی‌تان ساخته‌اید به یک سازمان، بعداً از **Transfer ownership** در تنظیمات پیشرفتهٔ برنامه در GitHub استفاده کنید.

نقطهٔ بازبینی: بلوک GitHub می‌نویسد "The server can act as itself, and people can sign in".

## آن را جایی نصب کنید که مخزن‌هایتان هستند

برنامه‌ای که ثبت شده اما نصب نشده، می‌تواند افراد را وارد کند و چیزی را نمی‌تواند بخواند.

۱. در صفحهٔ نصبی که GitHub باز کرده، حساب یا سازمانی را انتخاب کنید که مخزن‌هایتان مال آن است
۲. **All repositories** را انتخاب کنید، یا مخزن‌هایی را که این سرور باید ببیند انتخاب کنید

برای نصب آن روی حساب دیگری بعداً، یک مدیر فضای کاری به **تنظیمات ← فضای کاری ← یکپارچه‌سازی‌ها** می‌رود، **نصب‌های GitHub App** را زیر میزبانی کد روی کارت **برنامهٔ GitHub** پیدا می‌کند و روی **نصب GitHub App** کلیک می‌کند. فهرست هر حسابی را که برنامه روی آن نصب است نشان می‌دهد و یک نصب معلق را علامت می‌زند.

## اشتراک نصب یک سازمان

یک سازمان GitHub App را یک بار نصب می‌کند. از آن به بعد، هر کسی در آن سازمان که روی یک سرور Control Center با GitHub وارد شود می‌تواند از این نصب استفاده کند، هر سروری که باشد: سرور خودش، سرور همکارش یا سرور اختصاصی خودش. برای هر سرور چیزی برای مجاز کردن لازم نیست.

هر توکنی که یک سرور می‌گیرد متعلق به همان فرد واردشده است و به یک مخزن و نقش او در آن محدود است، بنابراین هرگز فراتر از چیزی نمی‌رود که او می‌توانست در GitHub انجام دهد. گزارش ممیزی GitHub همان فرد را نشان می‌دهد که از طریق برنامه عمل می‌کند.

برای اینکه Control Center به یک سازمان دسترسی نداشته باشد، یکی از مالکان سازمان نصب را حذف می‌کند یا مخزن‌های آن را در GitHub محدودتر می‌کند. حذف یک فرد از سازمان هم دسترسی او را قطع می‌کند.



## به‌جای آن دستی ثبتش کنید

کارت **برنامه‌های ارائه‌دهنده** مقادیر را مستقیم هم می‌پذیرد، برای برنامه‌ای که خودتان ثبت کرده‌اید:

| گروه                          | فیلدها                                                                                                                       |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **عمل به‌عنوان سرور**         | **App id**، و **Private key** (کل فایل `.pem`، با خطوط `BEGIN` و `END`)                                                    |
| **ورود افراد**                | **Client id** و **Client secret**. **Callback URLs** نشانی‌ای را نشان می‌دهد که باید ثبت شود، عیناً                          |
| **گفتگوهای pull request**     | **Bot login**، که وقتی اتصال را آزمایش می‌کنید حل می‌شود                                                                      |

نشانی callback را `<server origin>/oauth/github/callback` دقیقاً همان‌طور که کارت نشان می‌دهد ثبت کنید، گزینهٔ **Expire user authorization tokens** را روشن بگذارید، و مجوزهای جدول بالا را بدهید. روی **آزمایش** کلیک کنید: از GitHub می‌پرسد برنامه روی کدام حساب‌ها نصب شده، تا "ذخیره شد" و "کار می‌کند" با هم اشتباه گرفته نشوند.

## پیکربندی از `.env` سرور

برای نصب بدون رابط یا اسکریپتی، سرور هر فیلد را از فایل `.env` خود بار اول که مقدار ذخیره‌شده ندارد، بذر می‌کند:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

کلید را در **یک خط** بگذارید: یک مقدار `.env` یک خط است، و `\n` داخل گیومه‌های دوتایی به خط جدید تبدیل می‌شود. سرور وقتی `GITHUB_APP_PRIVATE_KEY` یا `GITHUB_CLIENT_SECRET` در محیط فرایندش صادر شده باشد، از راه‌اندازی خودداری می‌کند، جایی که هر فرایند فرزندی می‌تواند آن‌ها را بخواند؛ آن‌ها را در فایل `.env` نگه دارید (در Docker، آن را در `/app/bin/.env` سوار کنید). بذرگیری **برای هر فیلد یک بار** انجام می‌شود، پس ویرایش در تنظیمات با راه‌اندازی مجدد بعدی پاک نمی‌شود.

## به یک فضای کاری برنامهٔ اختصاصی خودش را بدهید

یک فضای کاری می‌تواند به‌جای برنامهٔ سرور، از برنامهٔ خودش استفاده کند:

۱. یک مدیر فضای کاری به **تنظیمات ← فضای کاری ← یکپارچه‌سازی‌ها** می‌رود
۲. در کارت **Control Center Connect**، **استفاده از برنامه‌های خودم** را انتخاب می‌کند و روی **اعمال** می‌زند. همهٔ اعضای فضای کاری دوباره از طریق برنامه‌های فضای کاری وارد می‌شوند
۳. کارت **برنامهٔ GitHub** زیر میزبانی کد اکنون فیلدهای برنامه را نشان می‌دهد: **شناسهٔ برنامه** و **کلید خصوصی** زیر **از طرف این فضای کاری عمل می‌کند**، و **شناسهٔ کلاینت** و **راز کلاینت** زیر **ورود افراد**. پس از تنظیم آن‌ها **آزمایش** را یک بار بزنید

اعضا آنگاه برای این فضای کاری به آن برنامه وارد می‌شوند. فضای کاری‌ای که روی برنامه‌های خودش است هرگز به برنامهٔ سرور یا Connect برنمی‌گردد: تا وقتی فیلدهایش کامل نشده‌اند، کار GitHub آن رد می‌شود. همین انتخاب Google Calendar، Linear و جست‌وجوی GIF را هم پوشش می‌دهد، هرکدام با فیلدهای خودش کنار ارائه‌دهندهٔ خودش در همین صفحه. ببینید [دادن برنامهٔ Linear اختصاصی به یک فضای کاری](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/یکپارچهسازی-linear/#دادن-برنامهٔ-linear-اختصاصی-به-یک-فضای-کاری) و [دادن کلاینت Google اختصاصی به یک فضای کاری](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/اتصال-تقویم/#دادن-کلاینت-google-اختصاصی-به-یک-فضای-کاری).
سایر گزینه‌های آن کارت و کار هرکدام در [انتخاب هر فضای کاری](/fa-IR/راهنمای-کاربر/مرجع/connect/#انتخاب-هر-فضای-کاری) آمده است.

## عیب‌یابی

### ساختن GitHub App من می‌گوید سرور نشانی ندارد

سرور نشانی عمومی‌ای ندارد که مرورگر بتواند به آن برگردد. `CC_SERVER_PUBLIC_URL` (یا `--public-url`) را تنظیم کنید و دوباره امتحان کنید.

### GitHub می‌گوید پیوند منقضی شده

صفحهٔ یک‌باره از قبل استفاده شده، یا ده دقیقه گذشته است. از تنظیمات دوباره شروع کنید.

### آزمایش می‌گوید اعتبارنامه‌ها کار می‌کنند، اما برنامه هیچ‌جا نصب نشده است

ثبت و نصب دو گام جدا هستند. صفحهٔ نصب برنامه را باز کنید، یا در فضای کاری → یکپارچه‌سازی‌ها از **نصب برنامهٔ GitHub App** استفاده کنید.

### آزمایش می‌گوید کلید خصوصی خوانده نشد

کل فایل `.pem` را بچسبانید، از جمله خطوط `-----BEGIN` و `-----END`. کلید `ed25519` یا EC قابل استفاده نیست: GitHub Appها با RSA امضا می‌کنند.

### یک عضو وارد شده اما هیچ مخزنی نمی‌بیند

برنامه روی حسابی که مخزن‌ها مال آن است نصب نشده، یا نصب آن مخزن‌های دیگری را انتخاب کرده است. یک ورود فقط آنچه را که برنامه اجازه دارد ببیند می‌دهد.

### عامل‌ها می‌گویند نصب GitHub App معلق است

کسی نصب را در GitHub معلق کرده است. آن را در **Settings → Applications → Installed GitHub Apps** حساب مربوطه رفع تعلیق کنید.
