این راهنما نشان می‌دهد چگونه بدون ترک GitHub با Control Center کار کنید: از صفحهٔ PR یک بازبینی AI درخواست کنید، در یک نظر از بات سؤال بپرسید، و گفتگو را در رشته‌های بازبینی‌اش ادامه دهید.

پاسخ‌ها از مسیر GitHub فضای کاری می‌آیند: GitHub App خود سرور، یا برنامهٔ مشترک Control Center از طریق Connect. هیچ چیز تازه‌ای ثبت نمی‌شود و هیچ‌چیز لازم نیست از اینترنت قابل‌دسترس باشد: سرور آنچه را که در GitHub گفته شده با نظرسنجی پیدا می‌کند، پس یک لپ‌تاپ پشت NAT دقیقاً مانند یک استقرار عمومی رفتار می‌کند.

## پیش‌نیازها

- فضای کاری یک مسیر GitHub دارد: GitHub App خود سرور یا Connect، با برنامه‌ای که [نصب](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/github-app/#نصب-کنید-در-جایی-که-مخزن‌هایتان-هستند) شده باشد روی حسابی که مخزن به آن تعلق دارد. برای برنامهٔ خودتان، مجوزهای **Pull requests** و **Issues** با خواندن و نوشتن لازم است، که **ساختن GitHub App من** از قبل آن‌ها را می‌دهد
- مخزن به یک فضای کاری در Control Center متصل است
- شما روی این سرور [با GitHub وارد شده‌اید](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/یکپارچهسازی-github/) و می‌توانید به مخزن push کنید
- نه نشانی webhook، نه تونل، نه callback — در سمت شبکه چیزی برای پیکربندی نیست

## نام بات خود را پیدا کنید

`@usectrl` را منشن کنید، حساب GitHub اختصاصی Control Center. این محرک پیش‌فرض است؛ مسیر GitHub فضای کاری شما همچنان درخواست را مدیریت می‌کند و پاسخ‌ها را ارسال می‌کند. برای حساب `usectrl` به هیچ اعتبارنامه‌ای نیاز ندارید.

ورود خود برنامه، `<appslug>[bot]`، و شکل کوتاه `@appslug` هم کار می‌کنند. برای پیدا کردن این نام مستعار اختیاری روی برنامهٔ خودتان:

۱. به **تنظیمات ← سرور ← ورود یکپارچه** بروید و تا کارت **برنامه‌های ارائه‌دهنده** پایین بروید
۲. بلوک **GitHub** را باز کنید و روی **آزمایش** کلیک کنید
۳. وقتی **Bot login** پر شد، آن را کپی کنید. اگر هنوز راهنمای خالی را نشان می‌دهد، ورود همیشه `<appslug>[bot]` است — همان را تایپ کنید، یا `@appslug` کوتاه را

GitHub حساب‌های برنامه را در تکمیل خودکار `@` نشان نمی‌دهد، پس نام‌های مستعار برنامه باید تایپ یا کپی شوند. کاربر اختصاصی `@usectrl` فراخوانی پیش‌فرض است؛ هم `@myapp` و هم `@myapp[bot]` به‌عنوان نام‌های مستعار برنامه پذیرفته می‌شوند.

:::note[یک نام برنامهٔ متمایز انتخاب کنید]
شکل کوتاه به‌صورت متن تطبیق داده می‌شود. اگر یک کاربر انسانی GitHub همان slug برنامهٔ شما را داشته باشد، با شکل کوتاه منشن کردن آن کاربر هم به بات می‌رسد. شکل کامل `@myapp[bot]` همیشه بی‌ابهام است.
:::

## درخواست بازبینی از GitHub

دو راه، که هر دو همان پایپ‌لاین `pr_review` دانه‌شده را راه می‌اندازند که دکمهٔ **از AI بپرس** راه می‌اندازد:

- **برچسب `ai-review` را به PR اضافه کنید**. نزدیک‌ترین کاری که GitHub برای واگذاری بات به‌عنوان بازبین می‌دهد، چون حساب‌های برنامه نمی‌توانند جای بازبین درخواست‌شدهٔ بومی را بگیرند. حساب شما با 👀 به PR واکنش نشان می‌دهد و بازبینی در Control Center شروع می‌شود؛ هیچ نظری ارسال نمی‌شود
- **در گفتگوی PR بنویسید `@usectrl review`** (یا فقط `@usectrl`). یک 👀 روی نظر شما ظاهر می‌شود، سپس پاسخی می‌گوید که بازبینی شروع شده است (یا اینکه از قبل یکی در حال اجراست)

بازبین‌ها در فضای بازبینی PR کار می‌کنند؛ یافته‌ها را همان‌طور که در [استفاده از بازبینی مبتنی بر AI](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/بازبینی-هوش-مصنوعی/) آمده بخوانید و منتشر کنید. انتشار دوباره در GitHub تصمیمی است که شما در Control Center می‌گیرید — شروع بازبینی از GitHub خودبه‌خود چیزی در GitHub منتشر نمی‌کند.

برچسب برای هر PR یک‌بار اجرا می‌شود: افزودن آن درخواست است، و با حذف و افزودن دوباره دوباره فعال نمی‌شود. برای اجرای دوبارهٔ بازبینی — مثلاً بعد از یک push — بات را منشن کنید.

## یک پرسش بپرسید

در گفتگوی PR نظر بگذارید:

```text
@usectrl why does the flaky test in runner_test.dart fail on CI but not locally?
```

آنچه پیش می‌آید، به ترتیب:

۱. یک 👀 روی نظر شما ظاهر می‌شود، از حساب خودتان، تا بدانید نظر دیده شده است
۲. پرسش در فضای بازبینی PR **به نام شما** ارسال می‌شود — همان انتسابی که اگر آن را در Control Center تایپ می‌کردید
۳. یک عامل در فضا پاسخ می‌دهد و پاسخ به PR برمی‌گردد. هر پاسخ با `**Control Center** (for @your-login):` شروع می‌شود

پرسش دربارهٔ یک PR که هنوز بازبینی ندارد، عامل CEO فضای کاری را بیدار می‌کند؛ وقتی یک بازبینی اجرا شده باشد، عاملی که آخرین بار صحبت کرده پاسخ می‌دهد، پس پیگیری‌ها به کسی می‌رسد که زمینه را دارد.

## در یک رشتهٔ بازبینی پیگیری کنید

درون یک رشتهٔ بازبینی درون‌خطی که بات بخشی از آن است پاسخ دهید — یک نظر diff که بات گذاشته، یا پاسخی که در آن رشته منتشر کرده است. نیازی به منشن نیست؛ رشته خودش نشانی است:

```text
> @usectrl the retry loop looks O(n²) to me

what would the complexity be with the bounded queue instead?
```

گفتگوی چندمرحله‌ای به همین شکل کار می‌کند: هر پاسخ پرسشی دیگر در همان گفتگوست، با فضای بازبینی به‌عنوان زمینه، و پاسخ در همان رشته برمی‌گردد.

پیگیری در خط زمانی گفتگوی PR یک نظر جدید سطح بالاست، پس همچنان به منشن نیاز دارد.

## با چه کسی بات صحبت می‌کند

سرور نویسندهٔ یک نظر، یا هر کسی که برچسب `ai-review` را اضافه کرده، را پیش از انجام هر کاری تشخیص می‌دهد:

- **حساب GitHub باید روی این سرور وارد شده باشد**. تطبیق بر اساس شناسهٔ عددی ثابت حساب GitHub است، هرگز نام کاربری. از **تنظیمات ← فضای کاری ← نمایه و هویت ← میزبانی کد** وارد شوید
- **باید عضو با نقش نوشتن** (`member`، `admin` یا `owner`) در فضای کاری‌ای باشد که مخزن را متصل می‌کند
- **باید بتواند به مخزن روی GitHub push کند**. پاسخ‌ها از توکنی استفاده می‌کنند که به دسترسی همان فرد محدود است، پس کسی که فقط می‌تواند بخواند پاسخی نمی‌گیرد

هر کس دیگری بی‌صدا نادیده گرفته می‌شود: چیزی منتشر نمی‌شود و کلماتش هرگز وارد فضای کاری نمی‌شوند. نظرهای بات‌ها و خود پاسخ‌های Control Center هرگز پرسش به حساب نمی‌آیند.

### دو سرور، یک PR

👀 همچنین راهی است که سرورها روی اینکه چه کسی پاسخ دهد توافق می‌کنند. با دسترسی خود نویسنده اضافه می‌شود و GitHub به سرور می‌گوید که آیا آن واکنش تازه است. اگر روی دو سرور Control Center که مخزن را متصل کرده‌اند وارد شده باشید، اولی که واکنش نشان دهد پاسخ می‌دهد و دیگری ساکت می‌ماند. همین برای برچسب هم صادق است.

## انتظارات

| چیز                 | رفتار                                                                                                                                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| تأیید دریافت         | 👀 از حساب شما روی نظر (یا روی PR، برای برچسب)، در یک چرخهٔ سریع                                                                                                                                                  |
| پاسخ‌ها              | در مسیری که پرسش در آن پرسیده شده منتشر می‌شوند و با `**Control Center** (for @your-login):` شروع می‌شوند. در برنامهٔ خودی، نویسنده بات `[bot]` برنامه است؛ از طریق Connect، حساب شما است که از طریق برنامهٔ مشترک عمل می‌کند |
| انتساب در فضا        | پرسش مال شماست؛ عامل به نیابت از شما اجرا می‌شود، تحت تنظیمات خودمختاری فضا                                                                                                                                       |
| بازبینی‌ها           | یافته‌ها در فضای بازبینی قرار می‌گیرند؛ انتشار در GitHub دستی است                                                                                                                                                  |

یک چرخهٔ سریع روی برنامهٔ خودی هر دقیقه اجرا می‌شود و تا ۲۵ درخواست pull را بررسی می‌کند؛ از طریق Connect هر دو دقیقه اجرا می‌شود و تا ۱۰ را بررسی می‌کند، چون آن فراخوانی‌ها سهمیهٔ GitHub هر عضو را به اشتراک می‌گذارند. فضای کاری‌ای که سهمیهٔ GitHub آن زیر ۱۵٪ است تا وقتی بازیابی شود رد می‌شود. تأخیر بهای نیاز نداشتن به هیچ ترافیک ورودی شبکه است. وقتی سرور خاموش است چیزی از دست نمی‌رود — نظری که در زمان قطعی برسد در چرخهٔ بعدی گرفته می‌شود.

## عیب‌یابی

**برای نظری که بات را منشن می‌کند هیچ‌چیز اتفاق نمی‌افتد.**

- آیا برنامه روی حسابی که مخزن به آن تعلق دارد **نصب** شده، و آیا مخزن به یک فضای کاری **متصل** است؟ مخزن غیرمتصل قبل از ثبت هر چیز رد می‌شود، پس اتصال بعدی همچنان پاسخ را می‌رساند
- آیا روی این سرور با GitHub وارد شده‌اید، عضو با نقش نوشتن هستید، و می‌توانید به مخزن push کنید؟ سرور هر کس دیگری را بدون پاسخ نادیده می‌گیرد
- روی برنامهٔ مشترک Control Center، آیا نصب سازمان برای این سرور مجاز است؟ ببینید [مجاز کردن این سرور برای یک سازمان](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/github-app/#authorize-this-server-for-an-organization)
- هنوز هیچ؟ گزارش سرور وقتی چیزی شکست بخورد، چرخه و PR را نام می‌برد؛ دنبال `pr_conversation:` (نظرسنج) و `github_pr_conversation:` (بریج) بگردید

**برچسب بازبینی را شروع نمی‌کند.**

برچسب برای هر PR یک‌بار فعال می‌شود، و کسی که آن را اضافه کرده همان بررسی‌ای را می‌گذراند که نویسندهٔ یک نظر. اگر از قبل یک بازبینی اجرا شده، یا برچسب پیش از اینکه سرور آن PR را دیده باشد اضافه شده (اولین چرخه عقب‌ماندگی را بی‌صدا ثبت می‌کند به‌جای اینکه سیلابی به راه بیندازد)، به‌جای آن بات را منشن کنید — `@usectrl review` همیشه یکی را شروع می‌کند، مگر اینکه یک بازبینی از قبل در حال اجرا باشد.

**پاسخ بات هرگز به GitHub نرسید.**

خود پاسخ هرگز از دست نمی‌رود — در فضای بازبینی PR در Control Center است. خطای ارسال (GitHub در دسترس نیست، مجوزها تغییر کرده‌اند) در گزارش ثبت می‌شود و دوباره امتحان نمی‌شود؛ اگر مهم است، در رشته دوباره بپرسید.
