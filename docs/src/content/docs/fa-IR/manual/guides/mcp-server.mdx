این راهنما نشان می‌دهد چگونه یک کلاینت MCP بیرونی — Claude Code، یک ویرایشگر،
MCP Inspector — را به سرور ابزار خودِ Control Center وصل کنید.

Control Center **۱۱۰** ابزار ثبت می‌کند و آن‌ها را از طریق پروتکل Model Context
در نسخهٔ پروتکل `2024-11-05` ارائه می‌دهد. خانواده‌های کامل ابزاری که انتظارشان را
دارید غایب‌اند: هیچ ابزار جلسه یا تقویمی و هیچ ابزار پروژه‌ای وجود ندارد.

## یافتن نقطهٔ پایانی

سطح MCP از همان شنوندهٔ اصلی `cc_server` استفاده می‌کند. پورت جدایی برای MCP
وجود ندارد.

| نقطهٔ پایانی | روش      | هدف                                                                    |
| ------------ | -------- | ---------------------------------------------------------------------- |
| `/mcp`       | `POST`   | انتقال Streamable HTTP — این همان چیزی است که یک کلاینت با آن گفتگو می‌کند |
| `/mcp`       | `DELETE` | پایان دادن به یک نشست                                                   |
| `/sse`       | `GET`    | جریان اعلان ارسالی از سرور                                              |

پس یک نصب محلی پیش‌فرض روی `http://127.0.0.1:9030/mcp` قرار دارد.

1. به **تنظیمات → سرور → سرورهای MCP** بروید
2. کارت **سرور MCP** را بخوانید — نشان می‌دهد در حال اجراست یا متوقف، و روی
   کدام پورت گوش می‌دهد

این سطح در یک نصب تازه به‌طور پیش‌فرض روشن است. فقط مالک سرور توکنِ کارت را می‌بیند، و فقط او می‌تواند نقطهٔ پایانی را شروع یا متوقف کند. **شروع هنگام راه‌اندازی برنامه** تعیین می‌کند که
پس از راه‌اندازی دوباره بازگردد یا نه؛ **شروع** / **توقف** کنترل‌های نشست‌اند و آن
ترجیح را تغییر نمی‌دهند.

سرور به‌طور پیش‌فرض به لوپ‌بک می‌بندد، پس نقطهٔ پایانی تنها از ماشینی که
`cc_server` روی آن اجرا می‌شود قابل‌دسترسی است، مگر آنکه آن را با `--bind any`
راه‌اندازی کرده باشید.

## دریافت توکن

هر درخواست به توکن MCP سرور نیاز دارد، از هر ماشینی، حتی از لوپ‌بک. سرور آن را در اولین راه‌اندازی می‌سازد. راهی برای خاموش کردن یا پاک کردن آن وجود ندارد.

1. در **تنظیمات → سرور → سرورهای MCP**، ردیف **توکن احراز هویت** را پیدا کنید
2. **نمایش توکن** را بزنید و آن را کپی کنید
3. برای جایگزینی، **چرخاندن توکن** را بزنید. سرور بی‌درنگ به توکن جدید می‌رود، و هر کلاینتی که هنوز از توکن قبلی استفاده می‌کند تا وقتی توکن جدید را به آن ندهید رد می‌شود

## اتصال یک کلاینت

کلاینت خود را به نقطهٔ پایانی Streamable HTTP اشاره دهید و توکن را روی هر درخواست به‌صورت `Authorization: Bearer <token>` بفرستید، از جمله `GET /sse`. راه دیگری برای فرستادن آن وجود ندارد: توکن در URL پذیرفته نمی‌شود. شکل دقیق پیکربندی به خودِ کلاینت مربوط است.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code این را از `.mcp.json` یک پروژه برنمی‌دارد — سرورهای MCP محدود به
پروژه را پشت یک پرامپت تأیید قرار می‌دهد که `claude -p` غیرتعاملی هرگز به آن
پاسخ نمی‌دهد. پیکربندی را صریح بدهید:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` باعث می‌شود Claude تنها از همان فایل استفاده کند، تا همان
سرور از پروژه هم کشف نشود و دو بار ثبت نگردد.

چک‌پوینت: از کلاینت بخواهید ابزارهایش را فهرست کند. باید ورودی‌های `mcp__*` را
ببینید که تیکت‌ها، فضاها، حافظه، گراف کد و بازبینی را پوشش می‌دهند.

## آنچه نقطهٔ پایانی رد می‌کند

توکن هر ابزار روی سرور را باز می‌کند، پس نقطهٔ پایانی پیش از نگاه کردن به توکن، هر چیزی را هم که یک صفحهٔ وب می‌توانست فرستاده باشد رد می‌کند:

| درخواست | پاسخ |
| ------- | ----- |
| هدر `Origin` که صفحه‌ای روی همین ماشین نیست (`http://localhost`، `http://127.0.0.1` یا `http://[::1]`، با هر پورتی) | `403`، درخواست بین‌مبدأ پذیرفته نمی‌شود |
| هدر `Host` که نه نشانی و پورت لوپ‌بکِ این شنونده است و نه نام میزبان عمومی سرور | `403`، میزبان ناشناخته |
| یک `POST` که بدنه‌اش `application/json` نیست | `415` |
| بدون توکن، یا با توکن نادرست | `401` |

برای ارائهٔ MCP فراتر از میزبان، سرور را با `--bind any` راه‌اندازی کنید و توکن را از ماشین دیگر بفرستید، و سرور را با نام میزبان عمومی‌اش نشانی دهید.

## محدودکردن هر فراخوانی به یک فضای کاری

هر ابزاری که به دادهٔ محدود به فضای کاری دست می‌زند `workspace_id` لازم دارد و
فراخوانی بدون آن رد می‌شود، نه اینکه در برابر فلان «فضای کاری جاری» حل شود:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

این شناسه همانی است که در URL مرورگر یا اپ شما هست:
`/workspaces/<workspace_id>/…`. تنها استثناها ابزارهایی‌اند که واقعاً فراتر از
فضای کاری‌اند، مانند `list_workspaces` و ابزارهای خوراک خبری — خوراک خبری
هر-کاربر است و یک عامل کاربر خودش را ندارد، پس آن ابزارها روی خوراک‌های مالک
سرور کار می‌کنند.

ابزارهای محدود به مخزن نیز علاوه بر آن بررسی می‌کنند که مخزن به همان فضای کاری
پیوند خورده باشد.

## بدانید سطح چه چیزی را رد می‌کند

- **دروازه‌گذاری حالت.** یک فراخوانی سمت سرور در برابر حالت فضای عامل فراخوان حل
  می‌شود. عاملی در یک حالت فقط‌خواندنی نمی‌تواند با حذف `space_id` به یک ابزار
  نوشتن برسد — در عوض، حالت از اجرای فعالش خوانده می‌شود.
- **گاردریل‌های کنش.** ابزارهای تغییردهنده کلاس‌های اثرشان را اعلام می‌کنند و از
  همان سیاستی می‌گذرند که بقیهٔ محصول استفاده می‌کند.
  [پیکربندی گاردریل‌ها](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/پیکربندی-گاردریلها/) را ببینید.
- **تأیید.** بعضی ابزارهای مخرب یک محمولهٔ تأیید می‌سازند که باید پیش از ادامهٔ
  فراخوانی تأیید شود.

کاتالوگ کامل در `tools/list` اعلام می‌شود، بدون هیچ دروازه‌گذاری کشف — یک کلاینت
MCP بیرونی از فراخوانی ابزاری که در فهرست کش‌شده‌اش نیست سر باز می‌زند، پس
پنهان‌کردن ابزارها آن‌ها را مرتب نمی‌کند، بلکه از کار می‌اندازد.

## سرورهای MCP شخصی متعلق به مالک می‌مانند

این راهنما دربارهٔ نقطهٔ پایانی خودِ Control Center است. جهت دیگر، سرورهای MCP‌ای است که Control Center به عامل‌هایی که اجرا می‌کند می‌دهد؛ آن‌ها در **تنظیمات → سرور → سرورهای MCP → سرورهای MCP خارجی** فهرست می‌شوند. سرورهایی که روی ماشین سرور برای Claude، Codex، Cursor، Gemini، VS Code، Windsurf، OpenCode یا در یک `.mcp.json` پیکربندی شده‌اند، به‌طور خودکار در آنجا پیدا می‌شوند.

آن سرورهای کشف‌شده از پیکربندی ابزار خودِ کاربر سرور می‌آیند و با هویت و اعتبارنامه‌های همان کاربر عمل می‌کنند، پس متعلق به مالک سرور هستند:

- فقط داخل اجراهای داخلی هارنس در دسترس‌اند که مالک سرور آغاز می‌کند یا پاسخ‌گوی آن است، از جمله خودکارسازی در فضای کاری‌ای که مالک پاسخ‌گوی آن است.
- اجرای یک عضو، خودکارسازی‌ای که به یک عضو بسته است، و هر اجرایی روی سروری که هیچ مالکی ثبت‌شده ندارد، هیچ‌کدام را نمی‌گیرند. آنجا ابزارها فهرست نمی‌شوند، قابل فراخوانی نیستند و در جستجوی ابزار هم دیده نمی‌شوند.
- این نقطهٔ پایانی هرگز آن‌ها را برای هیچ‌کس فهرست، فراخوانی یا جستجو نمی‌کند، حتی با توکن مالک، و منابع یا پرامپت‌هایشان را منتقل نمی‌کند. پس یک CLI عامل که از راه MCP به Control Center وصل می‌شود، مانند Claude Code، از طریق Control Center به آن‌ها دست نمی‌یابد؛ از پیکربندی خودش استفاده می‌کند.

سرورهای MCP پیکربندی‌شده برای فضای کاری تحت تأثیر هیچ‌کدام از این‌ها نیستند.

## عیب‌یابی

### کلاینت هیچ ابزاری نمی‌بیند

- بررسی کنید کارت **سرور MCP** در حال اجرا باشد
- بررسی کنید پورت با پورت `cc_server` شما بخواند
- روی Claude Code، بررسی کنید `--mcp-config` و `--strict-mcp-config` را
  فرستاده باشید

### 401 Unauthorized

درخواست توکنی نداشت، یا توکن قدیمی داشت. توکن فعلی را از ردیف **توکن احراز هویت** کپی کنید و به‌صورت `Authorization: Bearer <token>` بفرستید. توکنی که در URL باشد نادیده گرفته می‌شود.

### 403 از کلاینتی که پیش‌تر کار می‌کرد

درخواست یک `Origin` از یک صفحهٔ وب داشت، یا یک `Host` که سرور به آن پاسخ نمی‌دهد. نقطهٔ پایانی را از یک کلاینت صدا بزنید، نه از یک صفحهٔ مرورگر، و با نشانی لوپ‌بک سرور یا نام میزبان عمومی‌اش.

### 415 Unsupported Media Type

بدنه‌های `POST /mcp` را به‌صورت `application/json` بفرستید.

### فراخوانی یک ابزار با «Missing or invalid argument: workspace_id» شکست می‌خورد

`workspace_id` را اضافه کنید. هیچ فضای کاری ضمنی‌ای در کار نیست.

### فراخوانی یک ابزار به‌عنوان ناشناخته رد می‌شود

[ابزارهای MCP](/fa-IR/راهنمای-کاربر/مرجع/ابزارهای-mcp/) کاتالوگ را فهرست
می‌کند. نام را دقیقاً همان‌طور که آنجا آمده فراخوانی کنید.
