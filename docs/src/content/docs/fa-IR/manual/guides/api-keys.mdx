این راهنما نشان می‌دهد هر اعتبارنامه‌ای که یک کاربر Control Center از آن استفاده می‌کند کجا ذخیره می‌شود و چگونه آن را تغییر دهید.

**هیچ چیز روی دستگاهی که با آن وارد می‌شوید ذخیره نمی‌شود.** همهٔ اعتبارنامه‌ها روی سرور هستند؛ اینکه کدام‌یک به یک درخواست مشخص پاسخ می‌دهد به این بستگی دارد که آیا پشت آن درخواست یک فرد وجود دارد یا نه.

| اعتبارنامه                              | کجا ذخیره می‌شود                                              | چه کسی از آن استفاده می‌کند                                                          |
| --------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| ورود شما به میزبان کد / تیکتینگ          | فایل رازهای 0600 سرور، با کلید شناسهٔ کاربری شما               | هر کاری که انجام می‌دهید: سطح درخواست‌های pull، بازبینی‌ها، ادغام‌ها، کارهای Linear شما |
| برنامه‌های ارائه‌دهندهٔ سرور            | همان فایل، به‌علاوهٔ `server_settings` برای چیزهایی که راز نیستند | ورود افراد، و توکن‌های تک‌مخزنی برای عامل‌ها، پایپ‌لاین‌ها و نظرسنجی                 |
| کلید نصب Connect                        | همان فایل (`connect_install_key`)                              | شناسایی این سرور در برابر Control Center Connect                                       |
| کلیدهای ارائه‌دهندگان مدل و توکن‌های OAuth | انبار اعتبارنامهٔ خود سرور                                | آداپتور داخلی، برای هر فضای کاری روی این نصب                                          |
| اعتبارنامه‌های بات Slack                | `<dataDir>/<workspaceId>/chat_credentials/` روی سرور          | بریج گفتگو برای آن فضای کاری: توکن‌های برنامهٔ خودتان، یا مهر اعطای برنامهٔ مشترک |
| اعتبارنامه‌های CLI خارجی                | هر آنچه آن CLI استفاده می‌کند                                  | Claude Code، روی میزبان سرور                                                          |

## GitHub: ورود شما، و توکن‌های تک‌مخزنی

- **ورود شما**، از **ورود به GitHub**. این همان چیزی است که هر درخواستی را که _به نام شما_ انجام می‌شود به کار می‌برد، پس بازبینی‌ای که به نام شما منتشر می‌شود نام شما را دارد. عضو دیگری نمی‌تواند از آن استفاده کند و هر کس خودش وارد می‌شود. توکن GitHub‌ای برای چسباندن وجود ندارد
- **کاری که کسی آن را تایپ نمی‌کند** (عامل‌ها، پایپ‌لاین‌ها، نظرسنجی، پاسخ‌های بات) برای هر بار یک توکن برای یک مخزن می‌گیرد، که از GitHub App سرور یا از طریق Control Center Connect صادر می‌شود و به آنچه یک عضو مسئول می‌تواند در آنجا انجام دهد محدود است. هرگز ورود شما نیست که کامل واگذار شده باشد

ورود شما در کارت **میزبانی کد** در **تنظیمات ← فضای کاری ← نمایه و هویت** تنظیم می‌شود؛ برنامهٔ سرور در **برنامه‌های ارائه‌دهنده** در **تنظیمات ← سرور ← ورود یکپارچه** است. ببینید [راه‌اندازی یکپارچه‌سازی GitHub](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/یکپارچهسازی-github/) و [ساختن GitHub App](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/github-app/).

GitLab و Bitbucket هنوز یک توکن شخصی که چسبانده می‌شود می‌گیرند، و به همان روش ذخیره می‌شود. ببینید [اتصال میزبان کد](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/اتصال-میزبان-کد/).

:::note[یک صفحهٔ فقط با نشانی هم وجود دارد]
‏`/workspaces/<workspaceId>/api-keys` همان دو کارتی را نشان می‌دهد که گام اول راه‌اندازی اولیه نشان می‌دهد. **هیچ ورودی ناوبری در رابط ندارد**؛ فقط با تایپ کردن نشانی به آن می‌رسید. به جای آن از **تنظیمات ← فضای کاری ← نمایه و هویت** استفاده کنید.
:::

## تنظیم کلیدهای ارائه‌دهندگان مدل

آداپتور داخلی ارائه‌دهندگان را خودش احراز هویت می‌کند، و این اعتبارنامه‌ها روی سرور ذخیره می‌شوند.

۱. به **تنظیمات ← سرور ← ارائه‌دهندگان مدل** بروید
۲. تا **ارائه‌دهندگان و مدل‌ها** پایین بروید
۳. ارائه‌دهنده را متصل کنید — OAuth در مرورگر برای OpenAI، Codex، Cursor و Kimi Code؛ کلید API برای Anthropic و بقیه

برای فهرست کامل و افزودن نقطهٔ پایانی سفارشی، ببینید [مدیریت آداپتورها و مدل‌ها](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/آداپتورها/).

این اعتبارنامه‌ها **سراسری برای میزبان** هستند: یک کلید به همهٔ فضاهای کاری روی این نصب خدمت می‌کند. توکن‌های OAuth پیش از انقضا تازه می‌شوند.

CLI آداپتورهای خارجی اعتبارنامه‌های خودشان را در تنظیمات خودشان روی میزبان سرور نگه می‌دارد — Control Center آن‌ها را مدیریت نمی‌کند. Claude Code را طبق مستندات خودش احراز هویت کنید، روی دستگاهی که `cc_server` روی آن اجرا می‌شود.

گفتگوی **متغیرهای محیطی** که برای هر آداپتور وجود دارد شبیه جایی به نظر می‌رسد که کلید یکی از آن‌ها را بگذارید، اما چنین نیست: آن گفتگو روی دستگاه شما می‌نویسد، در حالی که سرور نسخهٔ خودش را می‌خواند و هیچ چیز این دو را به هم وصل نمی‌کند. ببینید [مدیریت آداپتورها و مدل‌ها](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/آداپتورها/).

## اتصال یک ارائه‌دهندهٔ تیکتینگ

کارت **تیکتینگ** در **تنظیمات ← فضای کاری ← عمومی** هر دو نیمهٔ یک تصمیم را نگه می‌دارد: تیکت‌هایتان در کدام ارائه‌دهنده زندگی کنند، و Control Center وقتی با آن صحبت می‌کند چه کسی است. انتخاب **محلی** ردیف‌های Linear را پنهان می‌کند — تیکت‌های محلی در پایگاه‌دادهٔ همین سرور هستند و چیزی برای احراز هویت ندارند.

Linear دو ورود دارد و کلید چسبانده‌شده ندارد: **Linear** مال شماست، برای کارهایی که خودتان انجام می‌دهید، و **خودکارسازی Linear** برنامهٔ Control Center فضای کاری است که توسط یک مدیر متصل شده، برای همگام‌سازی تیکت، پایپ‌لاین‌ها و عامل‌ها. سرور ممکن است یک **کلید API سرویس** (در **برنامه‌های ارائه‌دهنده**) برای فضاهای کاری‌ای که خودکارسازی متصل ندارند هم نگه دارد. هیچ اعتبارنامهٔ تیکتینگی در سندباکس عامل تزریق نمی‌شود؛ عامل‌ها تیکت‌ها را از طریق ابزارهای Control Center می‌نویسند که از قاعدهٔ **نوشتن در یک ردیاب خارجی** می‌پرسند. ببینید [راه‌اندازی یکپارچه‌سازی Linear](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/یکپارچهسازی-linear/).

## تعویض یا لغو

- **ورود شما به GitHub**: روی **قطع اتصال** کلیک کنید، سپس دوباره روی **ورود به GitHub**. قطع اتصال همهٔ توکن‌هایی را که سرور به نام شما صادر کرده هم باطل می‌کند
- **توکن GitLab یا Bitbucket**: روی **به‌روزرسانی توکن** کلیک کنید و توکن جدید را بچسبانید، سپس توکن قدیمی را روی میزبان کد باطل کنید
- **برنامهٔ سرور**: یک کلید خصوصی یا رازِ جدید در صفحهٔ ارائه‌دهندهٔ برنامه بسازید، آن را در **برنامه‌های ارائه‌دهنده** بچسبانید و روی **آزمایش** کلیک کنید
- **کلید نصب Connect**: **چرخاندن کلید** در کارت **Control Center Connect**، یا `cc_server connect rotate-key --yes`. همهٔ کسانی که از طریق Connect وارد شده‌اند دوباره وارد می‌شوند. ببینید [Control Center Connect](/fa-IR/راهنمای-کاربر/مرجع/connect/)
- **ارائه‌دهندهٔ مدل**: در ردیف آن، خروج (OAuth) کنید یا کلید را حذف کنید، سپس دوباره متصل شوید
- **Slack**: برای برنامهٔ خودتان، توکن‌ها را در گفتگوی اتصال دوباره بچسبانید. برنامهٔ مشترک Control Center توکنی برای چرخاندن ندارد: توکن بات آن از طریق Connect تمدید می‌شود، و **قطع اتصال** آن را باطل و بات را از Slack حذف می‌کند. ببینید [راه‌اندازی یکپارچه‌سازی Slack](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/یکپارچهسازی-slack/)

## عیب‌یابی

### توکن GitLab یا Bitbucket در `curl` کار می‌کند اما اینجا نه

زیرنویس ردیف **میزبانی کد** را بررسی کنید. اگر "از محیط" نوشته باشد، اعتبارنامه‌ای که پاسخ می‌دهد مال سرور است، نه شما — شما ذخیره نشده‌اید.

### توکن GitLab یا Bitbucket پذیرفته می‌شود اما درخواست‌های بعدی شکست می‌خورند

توکن همان‌طور که ذخیره شده بررسی می‌شود، پس ردیف حساب پشت آن را نشان می‌دهد — اما فقط حساب، نه محدوده‌ها. توکنی با محدوده‌های کم متصل می‌شود و سپس درخواست‌های مشخص را شکست می‌دهد. محدوده‌ها و انقضای آن را روی میزبان کد بررسی کنید.

### یک ارائه‌دهنده می‌گوید ورود روی این سرور تنظیم نشده است

سرور نه برنامهٔ خودش برای آن ارائه‌دهنده را دارد و نه Control Center Connect را. مالک سرور یکی از آن‌ها را در **تنظیمات ← سرور ← ورود یکپارچه** انتخاب می‌کند.
