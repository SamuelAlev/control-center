این راهنما نشان می‌دهد چگونه ارائه‌دهنده‌های مدل را متصل کنید و انتخاب کنید یک عامل روی چه چیزی اجرا شود.

همه‌چیز اینجا در یک صفحه است: **تنظیمات → سرور → ارائه‌دهندگان مدل**. عنوان در
نوارکنارِ فرعی «ارائه‌دهندگان مدل» است؛ عنوان صفحه «آداپتورها» است.

## آداپتور چیست

آداپتور همان _اجراکننده_ای است که یک نوبتِ عامل را اجرا می‌کند. دو مورد وجود دارد
و فهرست ثابت است — نمی‌توانید سومی را اضافه کنید.

| آداپتور                   | CLI      | انتقال                                                            |
| ------------------------- | -------- | ----------------------------------------------------------------- |
| Control Center (built-in) | هیچ      | حلقهٔ عامل درون‌فرایندی؛ از طریق HTTP با ارائه‌دهنده‌ها سخن می‌گوید |
| Claude Code               | `claude` | `claude -p --output-format stream-json`                           |

Cursor، Codex، Anthropic، OpenAI و بقیه **ارائه‌دهنده**هایی روی آداپتور داخلی‌اند،
نه CLIهای جداگانه. چیزی که _می‌توانید_ اضافه کنید یک ارائه‌دهندهٔ دیگر است — هر
نقطهٔ پایانی سازگار با OpenAI یا Anthropic. بخش بعدی همین است.

:::note[تشخیص، سرور را بررسی می‌کند، نه دستگاه شما]
کارت **اجراکننده‌های تشخیص‌داده‌شده** فهرست می‌کند که `cc_server` روی `PATH`
_میزبان سرور_ چه یافته است. روی یک کلاینت سبک یا وب، آن ماشینی متفاوت از ماشینی
است که به آن نگاه می‌کنید. CLI را روی ماشینی نصب کنید که `cc_server` را اجرا می‌کند.
:::

## اتصال یک ارائه‌دهندهٔ مدل

آداپتور داخلی پیش از آنکه بتواند اجرا شود به دست‌کم یک ارائه‌دهندهٔ متصل نیاز
دارد. چهارده مورد در فهرست همراه است.

1. به **تنظیمات → سرور → ارائه‌دهندگان مدل** بروید
2. به **ارائه‌دهنده‌ها و مدل‌ها** اسکرول کنید
3. ارائه‌دهندهٔ خود را پیدا کنید و آن را متصل کنید:

| ارائه‌دهنده                                                                                              | نحوهٔ اتصال                                                                                                                      |
| -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Anthropic                                                                                                | کلید API. اشتراک Claude Pro/Max یک ورود به API Anthropic نیست — برای آن طرح از آداپتور Claude Code استفاده کنید                  |
| OpenAI, Codex, Cursor                                                                                    | ورود OAuth در مرورگر، یا یک کلید API. Codex یک اشتراک ChatGPT Plus/Pro از طریق بک‌اند Codex Responses است، نه فراخوانی یک CLI     |
| Kimi Code                                                                                                | فقط OAuth در مرورگر — یک جریان کدِ دستگاه. طرحی با نرخ ثابت است، پس قیمت به‌ازای هر توکن ندارد                                     |
| OpenRouter, Groq, Google Gemini, DeepSeek, Mistral, xAI, z.ai, z.ai GLM Coding Plan, Moonshot (Kimi API) | کلید API                                                                                                                         |

نقطهٔ بازبینی: نشان سطر به «متصل» تغییر می‌کند و با باز کردن آن، مدل‌هایی که آن
ارائه‌دهنده عرضه می‌کند فهرست می‌شود، هرکدام با قیمت به‌ازای هر میلیون توکن و
پنجرهٔ بافت.

نشان‌های OAuth در مخزن اعتبارنامهٔ خودِ سرور ذخیره می‌شوند و پیش از انقضا
تازه‌سازی می‌شوند. اعتبارنامه‌های ارائه‌دهنده **سراسری در میزبان** هستند — میان
همهٔ فضاهای کاری این نصب مشترک‌اند، نه محدود به یکی.

### افزودن یک ارائه‌دهندهٔ سفارشی

از این برای Ollama، LM Studio، vLLM یا یک استقرار خصوصی استفاده کنید.

1. در **ارائه‌دهنده‌ها و مدل‌ها**، زیر **ارائه‌دهندگان سفارشی**، **افزودن ارائه‌دهنده** را فشار دهید
2. یک **نام** پر کنید، **نوع API** را انتخاب کنید (سازگار با OpenAI یا سازگار با
   Anthropic) و **URL پایه** را بدهید (برای مثال `http://localhost:11434/v1`)
3. اگر نقطهٔ پایانی به **کلید API** نیاز دارد آن را اضافه کنید، سپس **افزودن ارائه‌دهنده** را فشار دهید

یک ارائه‌دهندهٔ سفارشی در همان فهرست پدیدار می‌شود، با یک دکمهٔ حذف که هم‌تایان
داخلی‌اش ندارند.

## انتخاب مدل برای یک عامل

1. به **تنظیمات → فضای کاری → عامل‌ها** بروید و عامل را انتخاب کنید
2. در تب **تنظیمات**، **آداپتور** را انتخاب کنید
3. **مدل** را از منوی بازشوی کنارش انتخاب کنید

برای آداپتور داخلی، منوی بازشو به‌صورت زنده از فهرست خودِ هر ارائه‌دهندهٔ متصل
ساخته می‌شود. ارائه‌دهنده‌ای که اعتبارنامهٔ ذخیره‌ای ندارد صفر مدل می‌افزاید؛
به همین دلیل یک منوی بازشوی خالی تقریباً همیشه یعنی «هنوز چیزی متصل نشده»، نه
«چیزی در دسترس نیست».

:::note[models.dev فقط غنی‌سازی است، هرگز منبع شناسه‌ها نیست]
فهرست همراه [models.dev](https://models.dev) قیمت و پنجرهٔ بافت را برای مدلی که
پیش‌تر در فهرست زنده هست فراهم می‌کند. هرگز شناسهٔ مدلی را اضافه نمی‌کند. اگر
مدلی که انتظار دارید وجود ندارد، نقطهٔ پایانی ارائه‌دهنده آن را برنمی‌گرداند.
:::

شناسه‌های مدل برای آداپتور داخلی به‌صورت `provider/model` واجد صلاحیت‌اند و ممکن
است زنجیرهٔ جایگزینی جداشده با `|` داشته باشند. در حالت جایگزین، هزینه بر اساس
مدلی حساب می‌شود که واقعاً نوبت را سرو کرده است، نه مدلی که درخواست کرده‌اید.

:::note[عاملی که آداپتور ندارد روی حلقهٔ داخلی اجرا می‌شود]
هر فضای کاری پنج عامل ایجاد می‌کند — یک CEO به‌همراه `qa`، `architect`،
`engineer` و `librarian` — بدون آداپتور و بدون مدل. اعزام به
**Control Center (built-in)** بازمی‌گردد، نه به تنظیم **اجراکننده‌های پیش‌فرض** در
این صفحه، که یک ترجیح کلاینت است و مسیر اعزام هرگز آن را نمی‌خواند. گزارش اجرا
برای آن اجراها `cc-harness` را ثبت می‌کند، پس رونوشت نام چیزی را می‌آورد که
واقعاً اجرا شده است.

وقتی مدلی هم نباشد، حلقهٔ داخلی مدل پیش‌فرض را از Anthropic می‌پرسد. بنابراین
عاملی که کاملاً تنظیم‌نشده رها شود، اگر حساب Anthropic متصل کرده باشید اجرا
می‌شود، و در غیر این صورت با `No credential for provider "anthropic"` شکست
می‌خورد.

پایان دادن به گام آداپتورِ راه‌اندازی اولیه، **هر** عاملی را که هنوز آداپتور یا
مدل ندارد — مدیرعامل و متخصصان، در هر فضای کاری که در آن لحظه وجود دارد — با
جفت انتخابی شما به‌صورت عقب‌گرد وصله می‌کند. فضاهای کاری که بعداً ساخته می‌شوند
هنوز هر پنج عامل را تنظیم‌نشده ایجاد می‌کنند. آداپتور و مدل را روی هر عاملی که
قصد استفاده از آن را دارید صریحاً تنظیم کنید.
:::

## نصب CLI یک اجراکننده

آداپتور داخلی به نصب نیاز ندارد. برای Claude Code، CLI آن را **روی میزبان سرور**
با پکیج‌منیجر خودِ آن ابزار نصب کنید، برای مثال:

```bash
npm install -g @anthropic-ai/claude-code
```

سپس **تازه‌سازی** را در بالای صفحه فشار دهید. هر سطر تشخیص‌داده‌شده نسخه و مسیر
حل‌شده را نشان می‌دهد، به‌همراه برچسب‌هایی برای اینکه آیا از حالت JSON و انتخاب
مدل پشتیبانی می‌کند.

یک CLI خارجی اعتبارنامه‌های خود را، در پیکربندی خودش، روی میزبان سرور نگه
می‌دارد. Control Center آنها را مدیریت نمی‌کند.

:::caution[آرگومان‌های آداپتور و متغیرهای محیطی روی همین دستگاه می‌مانند]
هر سطر آداپتور یک فیلد **آرگومان‌های اضافه** و یک پنجرهٔ **متغیرهای محیطی** دارد.
آن مقادیر روی دستگاه شما ذخیره می‌شوند. سرور argv و env راه‌اندازی را از مخزن
تنظیمات خودش می‌خواند. کلیدهای ارائه‌دهنده را روی سرور بگذارید (OAuth یا فیلد
کلید در صفحهٔ ارائه‌دهندگان مدل)، نه در آن دو فیلد.
:::

## محدود کردن ارائه‌دهنده‌هایی که یک فضای کاری می‌تواند استفاده کند

حاکمیت ارائه‌دهنده به‌ازای هر فضای کاری است و با قاعدهٔ آخرین تطابق برنده
ارزیابی می‌شود.

1. در **ارائه‌دهنده‌ها و مدل‌ها**، کلید **اجازه** را روی یک سطر ارائه‌دهنده خاموش کنید

این کار یک گزارهٔ `deny` برای آن ارائه‌دهنده در فضای کاری فعال می‌نویسد و
مدل‌هایش از فهرست آن فضای کاری حذف می‌شوند. روشن‌کردن دوبارهٔ کلید آن گزاره را
حذف می‌کند.

## عیب‌یابی

### یک اجراکننده به‌صورت پیدا‌نشده نمایش داده می‌شود

- بررسی کنید CLI روی `PATH` **میزبان سرور** باشد، نه فقط مال خودتان
- یک برنامهٔ دسکتاپ که از رابط گرافیکی اجرا می‌شود سرورش را با `PATH` کمینه‌ای
  راه می‌اندازد؛ CLI نصب‌شده در مسیری که فقط در شل وجود دارد ممکن است برایش
  نامرئی باشد
- پس از نصب **تازه‌سازی** را فشار دهید

### منوی بازشوی مدل خالی است

- آداپتور داخلی است و هیچ ارائه‌دهنده‌ای متصل نیست — یکی را در
  **ارائه‌دهنده‌ها و مدل‌ها** متصل کنید
- یا ارائه‌دهنده متصل است اما کلید حاکمیت این فضای کاری آن را رد کرده است

### یک مدل اجرا می‌شود اما قیمت به‌صورت نامعلوم نمایش داده می‌شود

فهرست زندهٔ مدل‌ها شناسه را دارد؛ قیمت و بافت از models.dev می‌آید. یک مدل
کاملاً تازه، یا مدلی از یک ارائه‌دهندهٔ سفارشی، هنوز مدخلی در فهرست ندارد.
