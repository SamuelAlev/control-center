این راهنما بخش‌های مخصوص GitHub در راه‌اندازی را پوشش می‌دهد. GitHub یکی از سه میزبان کد پشتیبانی‌شده است. برای اتصال GitLab یا Bitbucket، و برای اینکه یک فضای کاری آن‌ها را با هم ترکیب کند، ببینید [اتصال میزبان کد](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/اتصال-میزبان-کد/).

## پیش‌نیازها

- یک حساب GitHub با دسترسی به مخزن‌هایی که می‌خواهید روی آن‌ها کار کنید
- سروری که بتواند افراد را به GitHub وارد کند: یا GitHub App خودش (ببینید [ساختن GitHub App](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/github-app/))، یا Control Center Connect، که مالک سرور در **تنظیمات ← سرور ← ورود یکپارچه** انتخاب می‌کند

:::note[اعتبارنامه‌ها روی سرور زندگی می‌کنند و به شما متصل‌اند]
چیزی روی دستگاهی که با آن تایپ می‌کنید ذخیره نمی‌شود. ورود شما به GitHub توسط `cc_server` شما نگهداری می‌شود، با شناسهٔ کاربری شما کلید می‌خورد، و هر دستگاهی که از آن وارد می‌شوید از آن استفاده می‌کند: دسکتاپ، وب و تلفن. عضو دیگری از همان سرور نمی‌تواند از آن استفاده کند، و وارد کردن آن‌ها کاری است که خودشان انجام می‌دهند.
:::

## ورود به GitHub

GitHub فقط ورود است: توکنی برای چسباندن وجود ندارد.

۱. به **تنظیمات ← فضای کاری ← نمایه و هویت ← میزبانی کد** بروید (یا به گام اول راه‌اندازی اولیه)
۲. در ردیف **GitHub**، روی **ورود به GitHub** کلیک کنید
۳. مرورگر شما GitHub را باز می‌کند. برنامه را تأیید کنید

ورود چگونه تمام می‌شود، به این بستگی دارد که چه کسی آن را اجرا می‌کند:

- **برنامهٔ خود سرور:** GitHub مرورگر شما را به سرور برمی‌گرداند و گفتگو خودش آن را تشخیص می‌دهد. چیزی برای تایپ کردن نیست
- **Control Center Connect:** صفحهٔ مرورگر یک کد ۸ کاراکتری نشان می‌دهد. آن را در گفتگو تایپ کنید، یا اجازه دهید مرورگر از طریق پیوند `control-center://` خود Control Center را باز کند و تایپ را نادیده بگیرید

نقطهٔ بازبینی: ردیف **GitHub** می‌نویسد "Signed in as _your-username_".

گفتگو کدی یا پیوندی را که خودش شروع نکرده رد می‌کند، با **ورود از اینجا آغاز نشده است**. اگر کسی برایتان پیوند ورود فرستاد، ادامه ندهید: تکمیل آن حساب شما را به سرور آن‌ها وصل می‌کند.

برای حذف ورودتان **قطع اتصال** را بزنید. خروج از GitHub، یا حذف شدن از یک فضای کاری، هر توکنی را که سرور به نیابت از شما صادر کرده هم باطل می‌کند.

## اعتبارنامهٔ شما به نام چه کسی صحبت می‌کند

- **هر کاری که خودتان انجام می‌دهید** (باز کردن صفحهٔ PR، ارسال بازبینی، تأیید، ادغام) روی **ورود خودتان** و هیچ چیز دیگری اجرا می‌شود. اگر وارد نشده باشید، برنامه این را می‌گوید و از شما می‌خواهد وارد شوید. هیچ اعتبارنامهٔ دیگری به جای شما نمی‌ایستد
- **کاری که کسی آن را تایپ نمی‌کند** (اجرای عامل‌ها، پایپ‌لاین‌ها، نظرسنجی PR، پاسخ‌های بات، کلون‌ها) برای هر بار یک توکن برای یک مخزن می‌گیرد، که از GitHub App سرور یا از طریق Connect صادر می‌شود. این توکن به آنچه یک عضو مسئول می‌تواند در آنجا انجام دهد محدود است: عضوی که درخواست کرده، وگرنه مالک فضای کاری. عضوی که نمی‌تواند push کند، توکن را به خواندن محدود می‌کند
- **خودکارسازی هرگز یک pull request را تأیید نمی‌کند.** تأیید کار یک فرد است

## یکپارچه‌سازی چه چیزی به شما می‌دهد

| امکان                  | روش                                                                                                                        |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| فهرست و جزئیات PR      | API مربوط به REST در GitHub، از سرور، با ورود خودتان                                                                       |
| اجراهای بررسی          | API مربوط به Checks در GitHub                                                                                               |
| انتشار بازبینی         | یک گام دارای دروازهٔ کاربر که بازبینی شما را به‌نام شما روی PR می‌گذارد                                                    |
| ثبت مخزن               | یک checkout پذیرفته می‌شود اگر remote آن `origin` به github.com، یا به gitlab.com / bitbucket.org، اشاره کند                  |
| دسترسی عامل به GitHub  | یک توکن برای مخزن واحد اجرا به‌عنوان `GH_TOKEN` / `GITHUB_TOKEN`؛ push ها از طریق Control Center انجام می‌شوند              |
| اعلان‌ها               | نظرسنجی سمت سرور از صندوق اعلان‌های GitHub شما «در pull request منشن شدید» و «بازبینی درخواست شد» را می‌سازد               |
| پروفایل کاربران        | کارت‌های شناور پروفایل و فیلتر PR به‌ازای نویسنده                                                                          |

برخی مسیرها به‌جای REST از API مربوط به GraphQL استفاده می‌کنند، هرجا که ارزان‌تر است: فعالیت شاخه برای انتخاب‌گر PR ساختن، و وضعیت زندهٔ بازبینی که تعیین می‌کند آیا اعلان «بازبینی درخواست شد» هنوز در انتظار است.

## مراقب قطعی GitHub باشید

نوار عنوان وقتی یک ارائه‌دهنده دچار مشکل است یک تراشهٔ وضعیت نشان می‌دهد، که GitHub، Claude، OpenAI و Kimi را پوشش می‌دهد. **وقتی همه‌چیز سالم است پنهان است**: حضور مشکل را گزارش می‌کند، نه نبودنش را.

روی تراشه کلیک کنید تا یک فلای‌اوت با وضعیت هر ارائه‌دهنده و دکمهٔ تازه‌سازی باز شود. وضعیت‌ها هر دو دقیقه خودبه‌خود تازه می‌شوند.

## بدانید عامل‌ها چگونه روی GitHub عمل می‌کنند

- عاملی که در یک worktree گیت‌هاب کار می‌کند، توکنی برای همان مخزن واحد می‌گیرد. می‌تواند کد را بخواند و وقتی عضو مسئول بتواند push کند، روی pull requestها نظر بگذارد، و وقتی نتواند، فقط بخواند. push از طریق Control Center انجام می‌شود، که از قاعدهٔ **push به یک remote** می‌پرسد و سپس آن را با یک توکن نوشتن که عامل هرگز در دست ندارد عبور می‌دهد. ببینید [پیکربندی سیاست‌های sandbox](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/سیاستهای-سندباکس/)
- کامیت‌های عامل همیشه هویت Git درخواست‌کننده را هم به‌عنوان نویسنده و هم به‌عنوان committer به کار می‌برند. به‌طور پیش‌فرض، trailer با متن `Co-Authored-By: Control Center <hi@usectrl.dev>` حساب GitHub ‏`@usectrl` را به‌عنوان هم‌نویسنده ثبت می‌کند. **تنظیمات ← شما ← انتساب کامیت** می‌تواند این اعتبار هم‌نویسنده را خاموش کند، بدون اینکه هویت شما تغییر کند. یک بازنویسی فضای کاری در **تنظیمات ← فضای کاری ← عمومی** مقدم است و آن گزینهٔ شخصی را قفل می‌کند. انتساب خود Claude Code همیشه غیرفعال است. امضای کامیت هنوز پیکربندی معتبر خودش را لازم دارد
- یک ترمینالی که روی یک rig باز می‌کنید ورود خودتان را دریافت می‌کند، محدود به همان یک مخزن، پس push های آنجا مال شماست
- وقتی هیچ توکنی نمی‌تواند صادر شود (هیچ‌کس مسئول وارد نشده، برنامه روی مالک نصب نیست، یا نصب معلق است)، اجرا بدون توکن شروع می‌شود و یادداشت‌هایش دلیلش را می‌گویند. اعتبارنامهٔ جایگزینی وجود ندارد

## عیب‌یابی

### فهرست PR خالی است و می‌گوید GitHub متصل نیست

شما روی این سرور با GitHub وارد نشده‌اید. زیر **میزبانی کد** روی **ورود به GitHub** کلیک کنید. مخزن‌های forgeهای دیگر تحت‌تأثیر نیستند.

### ردیف GitHub می‌گوید ورود روی این سرور تنظیم نشده است

سرور نه GitHub App خودش را دارد و نه Connect. مالک سرور یکی از آن‌ها را در **تنظیمات ← سرور ← ورود یکپارچه** انتخاب می‌کند: **ساختن GitHub App من** حدود دو دقیقه طول می‌کشد. ببینید [ساختن GitHub App](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/github-app/).

### گفتگو می‌گوید کد مطابقت ندارد

کد را دقیقاً همان‌طور که مرورگر نشان می‌دهد تایپ کنید: ۸ حرف و رقم. پنج کد اشتباه ورود را پایان می‌دهد؛ دوباره شروع کنید.

### ورود می‌گوید برنامه نصب نشده است

GitHub App روی حسابی که مخزن مال آن است نصب نشده. یک مدیر فضای کاری آن را از **تنظیمات ← فضای کاری ← عمومی ← نصب‌های GitHub App** نصب می‌کند. برای سازمانی که روی برنامهٔ مشترک Control Center است، ممکن است یک مدیر آن سازمان لازم باشد روی **Authorize this server** کلیک کند. ببینید [ساختن GitHub App](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/github-app/#authorize-this-server-for-an-organization).

### همه باید دوباره وارد GitHub شوند

مالک سرور کلید Connect سرور را چرخانده، بین سرورهای Connect جابه‌جا شده، یا پوشهٔ داده روی ماشین دیگری بازیابی شده است. ورودهای از طریق Connect به سروری که آن‌ها را ساخته گره خورده‌اند.

### افزودن یک مخزن رد می‌شود

ثبت هر سه شرط را لازم دارد: مسیر داخل یک درخت کاری git باشد، یک remote به نام `origin` داشته باشد، و آن remote به یک forge پشتیبانی‌شده (github.com، gitlab.com یا bitbucket.org) اشاره کند. ببینید [افزودن مخزن به فضای کاری](/fa-IR/راهنمای-کاربر/راهنماهای-عملی/افزودن-مخزن/).

### پس از استفادهٔ سنگین، برای مدتی همه‌چیز از کار می‌افتد

این کلید قطع‌کنندهٔ محدودیت نرخ است. GitHub محدودیت اصلی‌اش را با یک `403` که `x-ratelimit-remaining: 0` و زمان بازنشانی دارد اعلام می‌کند؛ وقتی کلاینت یکی را ببیند، درخواست‌های بیشتر را محلی و بدون تماس با شبکه شکست می‌دهد تا بازهٔ زمانی بگذرد، پس طوفان تلاش مجدد نمی‌تواند محدودیت را عمیق‌تر کند. خطاهای گذرا تا سه بار با backoff نمایی و با رعایت `retry-after` دوباره امتحان می‌شوند.
