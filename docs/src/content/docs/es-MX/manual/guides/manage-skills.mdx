Esta guía te muestra cómo llenar un espacio de trabajo con skills de GitHub:
agrega un repositorio como fuente, instala las skills que quieras de él y
mantenlas al día con el tiempo. También puedes evaluar una revisión guardada
frente a una línea base equivalente antes de decidir si la conservas.

Lo más importante que debes saber antes de empezar: **un repositorio de origen
no es de confianza.** Su nombre, su descripción y su número de estrellas los
escribe quien lo posee. Toda instalación pasa por el filtro del análisis
antivirus antes de que nada llegue al disco o al prompt de un agente. Ese
veredicto es una comprobación de admisión, no una prueba de que una skill sea
segura o útil. Lee la
[sección sobre skills del modelo de agentes](/es-MX/manual/conceptos/modelo-de-agentes/)
para el modelo de instalación y [Evaluaciones y
calidad](/es-MX/manual/conceptos/evaluaciones-y-calidad/) para saber en qué se
diferencia la evidencia de comportamiento de un análisis.

Las skills viven en **Ajustes → Espacio de trabajo → Habilidades**
(`/workspaces/<id>/settings/workspace/skills`). Tienen alcance de espacio de
trabajo: las skills que instales aquí pertenecen solo a este espacio. La página
tiene dos pestañas: **Instaladas** (skills locales, incluido un editor
**Nueva habilidad**) y **Fuentes** (catálogos de GitHub). Ambas escrituras
pasan por el mismo filtro del análisis.

## Agregar un repositorio de skills

1. Abre **Ajustes → Espacio de trabajo → Habilidades** y cambia a la pestaña
   **Fuentes**.
2. Presiona **Añadir repositorio**.
3. Pega la URL de un repositorio de GitHub, por ejemplo
   `https://github.com/anthropics/skills`, y confirma.

El servidor comprueba que el repositorio existe y es visible con sus
credenciales, y después lo agrega a la barra lateral izquierda. En medio no hay
ninguna tienda curada: cualquier repositorio de GitHub sirve, lo que también
significa que la reputación la juzgas tú — un número de estrellas es una
evidencia, nunca una garantía.

Las skills de un repositorio son los directorios que contienen un `SKILL.md`
(hasta tres niveles de profundidad, más la disposición del marketplace de
plugins de Claude `plugins/<plugin>/skills/<skill>`; los árboles de
dependencias y de terceros se omiten). Si más tarde la cuadrícula dice que el
repositorio no tiene skills, eso es lo que significa: ningún directorio de él
sigue la convención de skills.

## Inspeccionar una skill antes de instalarla

Selecciona un repositorio en la barra; sus skills aparecen como una cuadrícula
a la derecha, con un campo de filtro encima que acota el catálogo por nombre,
descripción o slug. Haz clic en una tarjeta para abrir la vista de detalle.
Muestra tres cosas:

- **El README**, renderizado como markdown — el `README.md` del directorio de
  la skill, o el cuerpo del `SKILL.md` cuando no hay README.
- **La vista previa del análisis** — el veredicto (`pass`, `warn` o
  `quarantine`), las capacidades que declara el contenido de la skill (ejecuta
  el shell, escribe archivos, acceso a la red…) y cada hallazgo que registró el
  escáner.
- **El recuento de archivos** — una instalación escribe todo el directorio de
  la skill, no solo su `SKILL.md`.

La vista previa analiza exactamente los bytes que escribiría una instalación,
así que el veredicto que ves es el veredicto que obtiene la instalación; no se
vuelve a juzgar nada a tus espaldas.

## Instalar una skill

1. Abre la vista de detalle de la skill.
2. Lee el veredicto del análisis. Si el veredicto es `warn` o `pass`, presiona
   **Instalar**.
3. Si el veredicto es `quarantine`, la instalación permanece desactivada hasta
   que marques **Entiendo el riesgo — instalar de todos modos**. Esa anulación
   se registra, no se da por supuesta.

La instalación escribe el directorio de la skill en el espacio de trabajo,
registra un pin en `skills-lock.json` (repositorio de origen, ruta, el commit
del que procede y un hash del contenido), y la skill queda disponible para los
agentes del espacio de trabajo. Una tarjeta marcada como **Nombre en uso**
significa que otra skill ya posee ese nombre en local — desinstala esa primero.

## Actualizar skills con el tiempo

Las tarjetas de las skills instaladas llevan insignias: **Instalada**, o
**Actualización disponible** cuando el repositorio ha avanzado más allá del
commit que fijaste. Abre la vista de detalle y presiona **Actualizar** para
volver a obtenerla en el nuevo commit. Una actualización pasa por el mismo
filtro del análisis que una instalación — una skill cuya nueva versión quede
en cuarentena se rechaza y la versión que tenías se queda como estaba. El hash
de la versión antigua se conserva como referencia de reversión en el archivo
de bloqueo.

## Evaluar una skill

1. Abre **Ajustes → Espacio de trabajo → Habilidades**, selecciona la skill
   instalada y guarda los cambios. En **Evaluación de habilidades**, comprueba
   el hash del paquete.
2. Selecciona **Iniciar evaluación**. Elige un **Conjunto de tareas** acorde
   con el propósito de la skill y un **Adaptador**. El harness integrado usa un
   proveedor configurado y un modelo con capacidad de herramientas. **Claude
   Code** usa la cuenta gestionada predeterminada de Claude y un identificador
   de modelo concreto; inicia sesión primero en **Ajustes → Adaptadores**. No
   toma prestado el inicio de sesión personal del operador del servidor.
3. Elige una **Comparación** en la tabla de abajo.
4. Define **Repeticiones por tarea** (1–20) y **Presupuesto (centavos de US)**.
   Por ejemplo, `100` significa 1 dólar estadounidense. Selecciona **Iniciar
   evaluación** para autorizar el trabajo de pago del proveedor.
5. Sigue la campaña en **Observabilidad → Calidad**, o vuelve mediante
   **Abrir Calidad** en el panel de la skill.

Para las suscripciones de Claude Code y Codex OAuth, el presupuesto es un
**umbral de detención del uso equivalente a la API**, no un límite de factura ni
una medida de la cuota de suscripción. `100` admite un umbral de 1 dólar
estadounidense: una llamada en curso puede superarlo, pero no se inicia ninguna
llamada más en cuanto el uso declarado lo alcanza. El uso desconocido también
detiene las llamadas siguientes. Un presupuesto pequeño puede dejar la
comparación parcial; no promete completar el conjunto de tareas seleccionado.

Los proveedores con clave de API mantienen reservas conservadoras por llamada a
partir de los límites de tokens y los precios documentados. Pueden rechazar
`100` antes de gastar cuando una sola llamada reservada con seguridad necesita
más. El error identifica el modelo seleccionado y la reserva mínima; elige un
modelo más barato o aumenta ese presupuesto.

| Comparación | Úsala para responder |
| --- | --- |
| **Ausente vs. disponible** | ¿Mejora el resultado el descubrimiento y uso normales de esta skill frente a no tenerla? |
| **Anterior vs. actual** | ¿La actualización conserva o mejora el comportamiento frente a una revisión capturada antes? |
| **Carga forzada vs. ausencia** | ¿Puede el contenido ayudar cuando se carga de forma explícita? Esto diagnostica problemas de carga; no demuestra el descubrimiento normal. |
| **Composición** | ¿Ayuda añadir el candidato o entra en conflicto con las skills ambientales seleccionadas? La línea base mantiene ese mismo inventario ambiental sin el candidato. |

La comparación **Anterior vs. actual** necesita un hash de paquete del
histórico de campañas. Evalúa una revisión antes de reemplazarla si quieres
usarla como línea base; el historial de Git arbitrario no se importa.

Las ediciones sin guardar, un hash no disponible y el modo demo de solo lectura
desactivan el inicio. El servidor también comprueba el acceso al espacio de
trabajo y al repositorio, la cuarentena del análisis, la política de acciones,
la compatibilidad de modelos, los precios y el confinamiento de la ejecución.
Resuelve una comprobación fallida en vez de eludirla. Se registra la identidad
del proveedor y del modelo, pero un alias remoto de modelo no congela los pesos
subyacentes del proveedor.

### Inspeccionar, cancelar y exportar

Lee la cobertura y el gasto junto con los resultados por tarea y las
regresiones. Abre intentos individuales para inspeccionar las cargas de skills
observadas, los eventos de herramientas, los errores y la evidencia de los
verificadores. Los resultados **Parciales**, **Desactualizados** y **No
concluyentes** no son recomendaciones para adoptar una revisión. El hash de un
informe identifica el paquete capturado, no necesariamente el paquete instalado
actualmente.

Usa **Cancelar ejecución** para el trabajo en cola o activo. Los intentos
completados siguen visibles; la cancelación no reembolsa el trabajo ya
realizado del proveedor. **Copiar JSON anonimizado** copia al portapapeles una
exportación acotada de evidencia, no un paquete completo de reproducción de
código privado. Consulta [Evaluaciones y
calidad](/es-MX/manual/conceptos/evaluaciones-y-calidad/) para la evidencia y
los límites de la plataforma.

### Reevaluar tras las actualizaciones

La reevaluación automática de pago está **desactivada por defecto**. Tras
evaluar la revisión actual, elige una campaña en **Configuración de la política
de actualizaciones** y selecciona **Activar evaluaciones de actualizaciones**.
Cambiar esta política requiere permiso de administrador del espacio de trabajo.
La campaña elegida aporta el conjunto de tareas, el adaptador, el
proveedor/modelo, la comparación, las repeticiones y el presupuesto.

Los cambios de contenido admitidos posteriores programan trabajo con
presupuesto; los hashes sin cambios se deduplican. **Desactivar evaluaciones de
actualizaciones** impide futuras admisiones automáticas. Usa **Cancelar
ejecución** para una campaña ya admitida. Los informes históricos permanecen
vinculados a los hashes de sus paquetes originales; la reevaluación no publica,
activa ni reescribe una skill.

## Desinstalar una skill, quitar un repositorio

**Desinstalar** (en la vista de detalle de una skill instalada, o eliminar en
la pestaña Instaladas) quita el directorio de la skill y su pin del archivo de
bloqueo a la vez — una skill desinstalada no deja nada atrás.

**Quitar un repositorio** de la barra elimina solo el catálogo: las skills que
instalaste de él siguen instaladas y se siguen actualizando, porque un pin
registra el repositorio por su nombre y no como una referencia a la entrada de
origen. Vuelve a agregar el repositorio si quieres explorarlo otra vez.

## Invocar una skill

Las skills se invocan bajo su propio espacio de nombres, así que nunca chocan
con los comandos slash integrados (`/plan`, `/goal`, `/loop`, `/compact`):

- `/skill:<name>` — una skill instalada en este espacio de trabajo, o asociada
  al agente
- `/skill:<repo>:<name>` — una skill que aporta un repo clonado en este espacio

Un nombre simple que no sea integrado todavía se resuelve, para los mensajes
escritos antes de que existiera el espacio de nombres. `/skill:plan` es lo que
llega a una skill llamada `plan`; `/plan` es siempre el integrado.

## Skills con alcance de repo

Un repo clonado puede aportar sus propias skills, en `.agents/skills/`,
`.agent/skills/`, `.claude/skills/`, `.opencode/skills/` o `skills/`. Esas
**no** se instalan desde esta página. Un agente solo lleva las skills del repo
en el que está trabajando en ese momento; cambian cuando él cambia. El
compositor no tiene ese alcance: `/skill:<repo>:<name>` llega a cualquier repo
del espacio.

Las skills de repo pasan por el mismo análisis que bloquea ante la duda
(`pass` / `warn` / `quarantine`) antes de que su frontmatter llegue a un
prompt. `warn` se admite; `quarantine` se retiene, sin ninguna anulación del
operador en esa ruta.

Consulta [Skills con alcance de repo](/es-MX/manual/conceptos/modelo-de-agentes/#repo-scoped-skills) y
[Comandos slash](/es-MX/manual/referencia/comandos-slash/).
