Esta guía muestra dónde se guarda cada credencial que usa Control Center y cómo
cambiarla.

**No se guarda nada en la computadora en la que estás escribiendo.** Todas las
credenciales viven en el servidor; cuál responde a una petición concreta depende
de si hay una persona detrás.

| Credencial                                          | Dónde se guarda                                                                 | Quién la usa                                                                                                  |
| --------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Tu inicio de sesión en el host de código / de tickets | El archivo de secretos 0600 del servidor, indexado por tu id de usuario       | Todo lo que haces tú: la superficie de PR, las revisiones, las fusiones y tus acciones en Linear               |
| Las apps de proveedor del servidor                  | El mismo archivo, más `server_settings` para lo que no son secretos             | Iniciar sesión a las personas, y tokens de un solo repositorio para agentes, pipelines y sondeo               |
| La clave de instalación de Connect                  | El mismo archivo (`connect_install_key`)                                        | Identificar este servidor ante Control Center Connect                                                          |
| Claves de proveedores de modelos y tokens OAuth     | El almacén de credenciales propio del servidor                                  | El adaptador integrado, para todos los espacios de trabajo de la instalación                                   |
| Credenciales del bot de Slack                       | `<dataDir>/<workspaceId>/chat_credentials/` en el servidor                      | El puente de chat de ese espacio de trabajo: los tokens de tu propia app o la concesión sellada de la app compartida |
| Credenciales de CLI externas                        | Lo que use esa CLI                                                              | Claude Code, en el host del servidor                                                                           |

## GitHub: tu inicio de sesión y tokens de un solo repositorio

- **El tuyo**, desde **Iniciar sesión en GitHub**. Es el que usa toda solicitud
  hecha *en tu nombre*, así que una revisión publicada por ti lleva tu nombre.
  Otro miembro no puede usarlo, e inicia sesión por su cuenta. No hay ningún
  token de GitHub que pegar
- **El trabajo sin nadie escribiendo** (agentes, pipelines, sondeo, respuestas
  del bot) recibe un token para un solo repositorio a la vez, emitido desde la
  GitHub App del servidor o a través de Control Center Connect, y limitado a lo
  que un miembro responsable puede hacer ahí. Nunca es tu inicio de sesión
  entregado completo

El tuyo se configura en la tarjeta **Alojamiento de código**, en
**Ajustes → Tú → Perfil**; la app del servidor, en
**Aplicaciones de proveedor**, en
**Ajustes → Servidor → Inicio de sesión único**. Consulta
[Configurar la integración de GitHub](/es-MX/manual/guias/integracion-github/)
y [Crear la GitHub App](/es-MX/manual/guias/github-app/).

GitLab y Bitbucket siguen usando un token personal pegado, que se guarda de la
misma forma. Consulta
[Conectar un host de código](/es-MX/manual/guias/conectar-host-de-codigo/).

:::note[También hay una pantalla solo accesible por URL]
`/workspaces/<workspaceId>/api-keys` muestra las mismas tarjetas que el
primer paso de la puesta en marcha. **No tiene ninguna entrada de navegación en
toda la interfaz**; solo se puede acceder a ella escribiendo la URL. En su
lugar, usa Ajustes → Tú → Perfil para tus propios inicios de sesión, y Ajustes → Espacio de trabajo → Integraciones para el proveedor de tickets.
:::

## Configurar las claves de los proveedores de modelos

El adaptador integrado autentica los proveedores por sí mismo, y esas
credenciales viven en el servidor.

1. Ve a **Ajustes → Servidor → Proveedores de modelos**
2. Desplázate hasta **Proveedores y modelos**
3. Conecta el proveedor —OAuth en el navegador para OpenAI, Codex, Cursor y Kimi
   Code; una clave API para Anthropic y el resto

Consulta [Administrar adaptadores y modelos](/es-MX/manual/guias/adaptadores/)
para ver la lista completa y para agregar un endpoint personalizado.

Estas credenciales son **globales del host**: una sola clave sirve a todos los
espacios de trabajo de la instalación. Los tokens OAuth se renuevan antes de
que caduquen.

Claude Code inicia sesión mediante **Cuentas de Claude Code** en **Ajustes → Servidor → Proveedores de modelos**: cada cuenta tiene su propio directorio de configuración en el servidor, y ejecutas ahí el comando `claude auth login` que te muestra la app.

El diálogo **Variables de entorno** de cada adaptador parece un buen sitio donde
poner la clave de uno de ellos, pero no lo es: escribe en tu dispositivo,
mientras que el servidor lee su propia copia y nada conecta ambas. Consulta
[Administrar adaptadores y modelos](/es-MX/manual/guias/adaptadores/).

## Conectar un proveedor de tickets

La tarjeta **Tickets** de **Ajustes → Espacio de trabajo → Integraciones** reúne la
parte del espacio de trabajo: en qué proveedor viven tus tickets, y quién es
Control Center cuando actúa allí por su cuenta. Elegir **Local** oculta las filas de
Linear: los tickets locales viven en la base de datos de este servidor y no hay
nada a lo que autenticarse.

Linear tiene dos inicios de sesión y ninguna clave que pegar: **Linear** es el
tuyo, para lo que haces tú, y vive en **Ajustes → Tú → Perfil**; **Automatización de Linear** es la app de Control
Center del espacio de trabajo, que conecta un administrador en la tarjeta **Tickets**, para la
sincronización de tickets, los pipelines y los agentes. El servidor también
puede tener una **Clave de API de servicio** (**Aplicaciones de proveedor**)
para los espacios de trabajo que no tienen la automatización conectada. En el
sandbox de un agente no se inyecta ninguna credencial de tickets; los agentes
escriben tickets con las herramientas de Control Center, que preguntan a la
regla **Escribir en un rastreador externo**. Consulta
[Configurar la integración de Linear](/es-MX/manual/guias/integracion-linear/).

## Rotar o revocar

- **Tu inicio de sesión de GitHub**: presiona **Desconectar** y luego otra vez
  **Iniciar sesión en GitHub**. Al desconectar también se descartan todos los
  tokens que el servidor emitió en tu nombre
- **Un token de GitLab o Bitbucket**: presiona **Actualizar token** y pega el
  nuevo; luego revoca el anterior en el host de código
- **La aplicación del servidor**: genera una nueva clave privada o un nuevo
  secreto de cliente en la página del proveedor de la aplicación, pégalo en
  **Aplicaciones de proveedor** y presiona **Probar**
- **La clave de instalación de Connect**: el propietario del servidor pulsa
  **Rotar la clave** en la tarjeta **Control Center Connect**. Todas las
  personas que iniciaron sesión a través de Connect vuelven a iniciarla. Si no
  se puede contactar a un servidor de Connect, no cambia nada y se te ofrece
  **Rotar de todos modos**. Consulta
  [Rotar la clave de instalación](/es-MX/manual/referencia/connect/#rotar-la-clave-de-instalación)
- **Un proveedor de modelos**: en su fila, cierra la sesión (OAuth) o elimina la
  clave, y vuelve a conectarlo
- **Slack**: con tu propia app, vuelve a pegar los tokens en el diálogo de
  conexión. La app compartida de Control Center no tiene ningún token que rotar:
  su token de bot se renueva a través de Connect, y **Desconectar** lo revoca y
  desinstala el bot de Slack. Consulta
  [Configurar la integración de Slack](/es-MX/manual/guias/integracion-slack/)

## Solución de problemas

### Un token de GitLab o Bitbucket funciona en `curl`, pero no aquí

Comprueba la fila **Alojamiento de código**. Si dice «No conectado» o te pide conectarlo de nuevo, tu token no se guardó o fue rechazado. En Bitbucket, escribe tu correo de cuenta de Atlassian junto con el token de API.

### Un token de GitLab o Bitbucket se acepta, pero las solicitudes posteriores fallan

El token se comprueba tal como se guarda, así que la fila nombra la cuenta que
hay detrás, pero solo la cuenta, no los ámbitos. Un token con pocos ámbitos se
conecta y luego falla en solicitudes concretas. Comprueba sus ámbitos y su
caducidad en el host de código.

### Un proveedor dice que el inicio de sesión no está configurado en este servidor

El servidor no tiene ni su propia app para ese proveedor ni Control Center
Connect. El propietario del servidor elige una opción en
**Ajustes → Servidor → Inicio de sesión único**.
