Esta guía te muestra cómo volver a un punto anterior de una conversación y llevarla a otro lugar, sin perder el camino que dejaste.

## Lo único que vale la pena saber

**Ramificar no escribe nada.** Una conversación es un árbol de mensajes con un puntero en la punta, y volver atrás mueve el puntero. No se elimina nada, no se oculta nada, y cambiar de vuelta es otro movimiento de puntero.

Por eso editar un prompt y volver a ejecutarlo es seguro aquí: la respuesta con la que estabas comparando sigue ahí.

## Ver las ramas

```
/tree
```

El navegador enumera cada mensaje, con sangría en cada bifurcación, y marca el camino actual como **En esta rama**. Una conversación que nunca se bifurcó se muestra como la lista plana de siempre: mirar el navegador no cuesta nada hasta que hay algo que navegar.

Cada fila ofrece dos acciones.

| Acción                          | Efecto                                                    |
| ------------------------------- | --------------------------------------------------------- |
| **Continuar desde aquí**          | Mueve el puntero. Tu siguiente mensaje continúa desde ese mensaje. |
| **Bifurcar en una conversación nueva** | Copia el camino hasta ese mensaje en una conversación nueva. |

## Rama: prueba otro enfoque

1. `/tree`
2. Busca el mensaje desde el que quieres empezar de nuevo — por lo general, el último con el que quedaste conforme.
3. **Continuar desde aquí.**
4. Escribe el nuevo prompt.

La continuación anterior sigue en el árbol; ahora `/tree` mostrará dos caminos desde ese punto, y puedes alternar entre ellos con total libertad.

:::note[El camino que dejaste sigue ahí]
Ramificar no oculta ni elimina nada. `/tree` enumera cada camino, marca el actual como **En esta rama** y es la forma de cambiar.
:::

## Bifurcación: llévala a otro lugar

Bifurcar copia el camino en una **conversación nueva** dentro del mismo espacio. Úsalo cuando las dos direcciones vayan a seguir separándose y las quieras lado a lado en lugar de ir alternando entre ellas.

La copia tiene ids de mensaje nuevos. Dos conversaciones que compartieran filas se mostrarían los mensajes posteriores de la otra, que es justo lo que una bifurcación debe impedir.

## Revertir frente a ramificar

Son herramientas distintas, y la diferencia importa.

|                     | Revertir                                             | Ramificar                          |
| ------------------- | -------------------------------------------------- | ------------------------------- |
| Los mensajes posteriores  | Se ocultan de la transcripción                          | Siguen visibles en `/tree`         |
| El **worktree**    | Se revierte a la instantánea de ese turno                 | Queda intacto                        |
| Deshacer                | **Deshacer reversión** restaura el lote                  | Mueve el puntero hacia atrás            |

Revertir es lo que quieres cuando el agente cambió *archivos* que quieres recuperar. Ramificar es lo que quieres cuando la conversación tomó el camino equivocado pero los archivos están bien.

Revertir también mueve la punta de la rama, así que tu siguiente mensaje continúa desde el lugar correcto y no desde una cola que ya nadie puede ver.

## Sácala de la app

### `/export`

Escribe un **archivo HTML autocontenido**: toda la conversación con tarjetas de herramientas plegables que muestran qué recibió cada llamada y qué devolvió. Sin hoja de estilos, sin scripts ni host de imágenes: funciona desde una memoria USB y seguirá funcionando dentro de cinco años.

- **Escritorio:** `Documents/ControlCenter/exports/`, con marca de tiempo para que una segunda exportación no sobrescriba la primera.
- **Web:** una descarga del navegador.

### `/dump`

Copia la transcripción al portapapeles como markdown, con las llamadas a herramientas en bloques plegables. Esta es la que conviene pegar en un issue.

El razonamiento se deja fuera a propósito: es el espacio de borrador del modelo, y un informe de error lo lee una persona.
