Esta guía cubre las partes específicas de GitHub de la configuración. GitHub es
uno de los tres hosts de código compatibles. Consulta
[Conectar un host de código](/es-MX/manual/guias/conectar-host-de-codigo/) para
conectar GitLab o Bitbucket, y para saber cómo los combina un espacio de trabajo.

## Requisitos previos

- Una cuenta de GitHub con acceso a los repos en los que quieres trabajar
- Un servidor que pueda iniciar la sesión de las personas en GitHub: con su
  propia GitHub App (consulta [Crear la GitHub App](/es-MX/manual/guias/github-app/))
  o con Control Center Connect, según elija el propietario del servidor en
  **Ajustes → Servidor → Inicio de sesión único**

:::note[Las credenciales viven en el servidor, vinculadas a ti]
No se guarda nada en la computadora en la que estás escribiendo. Tu inicio de
sesión de GitHub lo guarda tu `cc_server`, indexado por tu id de usuario, y lo
usa cada dispositivo desde el que inicias sesión — escritorio, web y teléfono.
Otro miembro del mismo servidor no puede usarlo, e iniciar sesión es algo que
cada persona hace por su cuenta.
:::

## Iniciar sesión en GitHub

GitHub solo admite inicio de sesión: no hay ningún token que pegar.

1. Ve a **Ajustes → Espacio de trabajo → Perfil e identidad → Alojamiento de
   código** (o al primer paso de la configuración)
2. En la fila **GitHub**, haz clic en **Iniciar sesión en GitHub**
3. Tu navegador abre GitHub. Aprueba la app

Cómo termina el inicio de sesión depende de quién lo ejecute:

- **La app propia del servidor:** GitHub regresa tu navegador al servidor y el
  diálogo lo detecta solo. No hay nada que escribir
- **Control Center Connect:** la página del navegador muestra un código de 8
  caracteres. Escríbelo en el diálogo, o deja que el navegador abra Control
  Center con el enlace `control-center://` y no tendrás que escribirlo

Punto de control: la fila **GitHub** dice «Sesión iniciada como
_tu-nombre-de-usuario_».

El diálogo rechaza un código o un enlace que no haya iniciado él mismo, con
**Inicio de sesión no iniciado aquí**. Si alguien te envía un enlace de inicio
de sesión, no continúes: completarlo conectaría tu cuenta a su servidor.

Haz clic en **Desconectar** para eliminar tu inicio de sesión. Cerrar sesión en
GitHub, o que te quiten de un espacio de trabajo, también descarta todos los
tokens que el servidor emitió en tu nombre.

## Para quién habla tu credencial

- **Todo lo que haces tú** (abrir la página de la PR, publicar una revisión,
  aprobar, fusionar) se ejecuta con **tu** inicio de sesión y nada más. Si no
  iniciaste sesión, la aplicación te lo dice y te pide que inicies sesión.
  Ninguna otra credencial te suplanta
- **El trabajo sin nadie escribiendo** (ejecuciones de agentes, pipelines,
  sondeo de PR, respuestas del bot, clonados) recibe un token para un solo
  repositorio, emitido desde la GitHub App del servidor o a través de Connect.
  Se limita a lo que un miembro responsable puede hacer ahí: el miembro que lo
  pidió o, si no, el propietario del espacio de trabajo. Un miembro que no puede
  hacer push limita el token a lectura
- **La automatización nunca aprueba** una pull request. Aprobar es un acto de
  una persona

## Qué te aporta la integración

| Función                       | Cómo                                                                                                                             |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Lista y detalle de PR         | La API REST de GitHub, desde el servidor, con tu propio inicio de sesión                                                         |
| Ejecuciones de comprobación   | La API Checks de GitHub                                                                                                          |
| Publicación de revisiones     | Un paso que depende de la acción del usuario y que publica tu revisión en la PR, en tu nombre                                    |
| Registro de repos             | Se acepta un checkout si su remoto `origin` apunta a github.com, o a gitlab.com / bitbucket.org                                  |
| Acceso de los agentes a GitHub | Un token para el único repositorio de la ejecución como `GH_TOKEN` / `GITHUB_TOKEN`; los push pasan por Control Center         |
| Avisos de notificación        | Un sondeo en el servidor de tu bandeja de notificaciones de GitHub genera «Mencionado en pull request» y «Revisión solicitada»   |
| Perfiles de usuario           | Tarjetas de perfil al pasar el cursor y filtrado de PR por autor                                                                 |

Algunas rutas usan la API GraphQL en lugar de REST cuando resulta más barato —
la actividad de ramas del selector al redactar una PR y el estado de revisión en
vivo que decide si una notificación de revisión solicitada sigue pendiente.

## Vigila las caídas de GitHub

La barra de título muestra un indicador de estado cuando un proveedor está
degradado, e incluye GitHub, Claude, OpenAI y Kimi. **Permanece oculto mientras
todo va bien** — su presencia informa de un problema, no de su ausencia.

Haz clic en el indicador para abrir un panel flotante con el estado de cada
proveedor y un botón de actualización. Los estados se actualizan solos cada dos
minutos.

## Cómo actúan los agentes en GitHub

- Un agente que trabaja en un worktree de GitHub recibe un token para ese único
  repositorio. Puede leer el código y comentar en pull requests cuando el
  miembro responsable puede hacer push, y solo leer cuando no puede. Un push
  pasa por Control Center, que pregunta a la
  regla **Enviar a un remoto** y luego lo reenvía con un token de escritura que
  el agente nunca tiene. Consulta
  [Configurar políticas de sandbox](/es-MX/manual/guias/politicas-de-sandbox/)
- Los commits del agente siempre usan la identidad de Git de quien los solicita como autor y como committer. Por defecto, el trailer `Co-Authored-By: Control Center <hi@usectrl.dev>` acredita como coautora a la cuenta de GitHub `@usectrl`. En **Ajustes → Tú → Atribución de commits** puedes desactivar esta coautoría sin cambiar tu identidad. La opción del espacio de trabajo en **Ajustes → Espacio de trabajo → General** tiene prioridad y bloquea el interruptor personal. La atribución propia de Claude Code siempre está desactivada. La firma de commits sigue necesitando su propia configuración válida
- Una terminal que abres en un rig recibe tu propio inicio de sesión,
  restringido a ese único repositorio, así que los push que hagas ahí son tuyos
- Cuando no se puede emitir ningún token (ninguna persona responsable inició
  sesión, la app no está instalada en el propietario o la instalación está
  suspendida), la ejecución inicia sin él y sus notas explican por qué. No hay
  ninguna credencial alternativa

## Solución de problemas

### La lista de PR está vacía y dice que GitHub no está conectado

No iniciaste sesión en GitHub en este servidor. Haz clic en
**Iniciar sesión en GitHub** en **Alojamiento de código**. Los repos de otros
hosts de código no se ven afectados.

### La fila de GitHub dice que el inicio de sesión no está configurado en este servidor

El servidor no tiene ni su propia GitHub App ni Connect. El propietario del
servidor elige una opción en **Ajustes → Servidor → Inicio de sesión único**:
**Crear mi app de GitHub** toma unos dos minutos. Consulta
[Crear la GitHub App](/es-MX/manual/guias/github-app/).

### El diálogo dice que el código no coincide

Escribe el código exactamente como lo muestra el navegador: 8 letras y dígitos.
Cinco códigos incorrectos terminan el inicio de sesión; vuelve a empezar.

### El inicio de sesión dice que la app no está instalada

La GitHub App no tiene ninguna instalación en la cuenta propietaria del
repositorio. Un administrador del espacio de trabajo la instala desde
**Ajustes → Espacio de trabajo → General → Instalaciones de la app de GitHub**.
En una organización que usa la App compartida de Control Center, es posible que
un administrador de esa organización tenga que hacer clic en
**Autorizar este servidor**. Consulta
[Crear la GitHub App](/es-MX/manual/guias/github-app/#autorizar-este-servidor-para-una-organización).

### Todo el mundo tiene que volver a iniciar sesión en GitHub

El propietario del servidor rotó la clave de Connect del servidor, cambió de
servidor Connect o el directorio de datos se restauró en otra máquina. Los
inicios de sesión a través de Connect están ligados al servidor que los hizo.

### Se rechaza al agregar un repo

El registro necesita las tres cosas: que la ruta esté dentro de un árbol de
trabajo de git, que tenga un remoto `origin` y que ese remoto apunte a un host de
código compatible (github.com, gitlab.com o bitbucket.org). Consulta
[Agregar repos a un espacio de trabajo](/es-MX/manual/guias/agregar-repos/).

### Todo deja de funcionar un rato tras un uso intenso

Ese es el cortacircuitos del límite de velocidad. GitHub señala su límite
principal con un `403` que lleva `x-ratelimit-remaining: 0` y la hora de
restablecimiento; al ver uno, el cliente hace que las peticiones posteriores
fallen localmente, sin ninguna llamada de red, hasta que transcurra la ventana,
así que una tormenta de reintentos no puede agravar el límite. Los fallos
transitorios se reintentan hasta tres veces con retroceso exponencial,
respetando `retry-after`.
