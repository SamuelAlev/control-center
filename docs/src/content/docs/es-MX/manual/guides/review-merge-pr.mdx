Esta guía te muestra cómo revisar y fusionar una pull request.

## Abrir el banco de trabajo de la PR

1. Ve a **Pull requests** en la barra lateral
2. Selecciona una PR de la lista

Una PR se abre como un banco de trabajo con pestañas, no como una sola página.
Cinco pestañas se abren de forma predeterminada, en este orden: **Resumen**,
**Diff**, **Control de código fuente**, **Chat** y **Acciones** (las
comprobaciones de CI agrupadas por flujo de trabajo). **Revisar** —el progreso
del pipeline de revisión y, después, el artefacto que publicó con su carril de
hallazgos— no es una de ellas a propósito: una PR no tiene revisión hasta que
alguien la pide, así que **Ask AI** la abre. Un terminal, un editor de un solo
archivo, un code-server integrado y un navegador dentro de la aplicación se
abren a demanda; las pestañas de despliegue de vista previa se inyectan
automáticamente cuando se detecta una URL de vista previa en la PR. La
disposición de tus pestañas se recuerda por PR.

La pestaña Resumen contiene los metadatos de la PR (autor, rama, etiquetas,
asignados, reacciones, commits, estado de las comprobaciones) y la fila de
acciones: actualizar, **Revisar**, **Merge**, abrir en el IDE y un menú de
desbordamiento ⋯.

## Leer el diff

Abre la pestaña **Diff** para ver todo el diff de la PR de una vez, con un árbol
de archivos para saltar entre archivos.

- El botón de ajustes de la barra de herramientas del diff alterna entre la
  vista **dividida** (en paralelo) y la **unificada**, y activa o desactiva el
  ajuste de líneas y las ligaduras de la fuente de código.
- Los encabezados de fragmento `@@` se sustituyen por los controles **Show N
  lines** / **Show end of file**, que insertan el contexto circundante al hacer
  clic.
- Presiona `j` / `k` para pasar de un archivo a otro, `c` para contraer o
  expandir el archivo enfocado, `t` para devolver la barra lateral al árbol de
  archivos y `⌘F` para buscar en todo el diff (`Enter` / `Shift+Enter` recorren
  las coincidencias).
- Presiona `v` para marcar el archivo enfocado como visto, y el cursor avanza
  hasta el siguiente archivo. En GitHub el estado de visto se guarda en el host
  de código, así que te acompaña entre clientes; GitLab y Bitbucket no tienen
  esa API, así que ahí solo se recuerda en este dispositivo.

Arrastrar con el mouse en el área de código selecciona el texto hasta la columna
exacta, y `⌘C` copia el código fuente sin procesar en lugar de los marcadores de
diff representados.

## Dejar comentarios en línea

1. Toca el margen de una fila de código para abrir un compositor anclado a esa
   línea, o usa el botón `+` del encabezado de un archivo para un comentario a
   nivel de archivo
2. Escribe tus comentarios en Markdown
3. Envía

En GitHub y GitLab el compositor ofrece dos envíos: **Añadir un solo
comentario** publica de inmediato, e **Iniciar una revisión** / **Añadir a la
revisión** pone el comentario en cola en una revisión pendiente que se envía con
**Aprobar**, **Solicitar cambios** o **Comentar**. Bitbucket no tiene
agrupación de revisiones pendientes, así que ahí cada envío publica de
inmediato. Una publicación inmediata muestra un estado pendiente hasta que el
host de código la confirma y luego pasa a sincronizado. Si la publicación falla,
el hilo se marca con el error y ofrece reintentarlo.

Solo el _cuerpo_ de la revisión es un borrador: se guarda en el servidor
asociado a (propietario, repo, número de PR) un momento después de que dejas de
escribir, así que sobrevive a una recarga y te acompaña entre los clientes de
escritorio y web.

## Enviar una revisión

1. Presiona **Revisar** en la fila de acciones de Resumen (se oculta en tus
   propias PRs y en una PR cerrada o fusionada)
2. Escribe el cuerpo de la revisión. Puedes adjuntar una imagen, insertar un
   emoji o un GIF y alternar entre escribir y la vista previa
3. Presiona **Solicitar cambios**, **Comentar** o **Aprobar**

El veredicto _es_ el botón: no hay un selector de veredicto aparte. Después de
**Aprobar** o **Solicitar cambios**, el botón se renombra a **Aprobado** o
**Cambios solicitados** y se borra el cuerpo del borrador. Un veredicto
**Comentar** deja el botón con la etiqueta **Revisar**.

:::caution[El envío es irreversible]
`pr_review.submitReview` publica en el host de código y nunca entra en la pila
de deshacer. Desde Control Center no se puede retirar un envío.
:::

## Fusionar

El botón **Merge** aparece cuando tienes acceso de escritura y la PR está
abierta y no es un borrador. Su color es una señal de preparación derivada de
las aprobaciones obligatorias y el estado de las comprobaciones (listo /
pendiente / bloqueado); solo es orientativa. El estado de la revisión nunca
desactiva el botón; es la propia protección de rama del host de código la que
aplica las reglas.

1. Presiona **Merge** para abrir el panel flotante de fusión
2. Elige un método de fusión: **squash**, **merge commit** o **rebase** (squash
   es el predeterminado). Bitbucket no tiene una fusión con rebase real, así que
   rebase se corresponde con su estrategia fast-forward y falla en una rama
   divergente
3. Para squash y merge commit, edita el título y la descripción del commit
   precargados. Rebase no admite ninguno de los dos y oculta ambos campos
4. Lee el panel de advertencias: nombra las comprobaciones que fallan y las
   revisiones pendientes, pero no te bloquea
5. Presiona el botón de fusión del panel flotante para confirmar

Fusionar es irreversible: envía los commits al host de código, por lo que recibe
un paso de confirmación en lugar de una entrada de deshacer. Después, la caché
de la PR se invalida, su estado pasa a **Fusionado** y se desencadena un evento
`PullRequestStatusChanged` con el estado `merged`. Ese evento libera el worktree
efímero de «abrir en el editor» e inicia dos pipelines predefinidos: **Stale
repository cleanup**, que elimina los worktrees obsoletos y las carpetas de
conversación de la PR, y **Release notes**, que redacta una entrada de
changelog.

:::note[El espacio de revisión de la PR no se archiva automáticamente]
El archivado automático de las conversaciones del espacio de revisión está
conectado a un evento de dominio `PrMerged` aparte que actualmente nada del
producto emite, así que el espacio se queda como lo dejaste tras una fusión. La
limpieza diaria sigue recuperando su worktree; elimina el espacio tú mismo si
quieres que salga de la barra lateral.
:::

## Entregar la PR a los agentes revisores

El menú de desbordamiento ⋯ de la pestaña Resumen contiene **Ask AI**, que
inicia el pipeline predefinido `pr_review` para esta PR. Solo aparece mientras
la PR está abierta. Consulta
[Usar revisión impulsada por IA](/es-MX/manual/guias/revision-con-ia/) para saber
qué hace el pipeline y cómo publicar sus hallazgos, y
[Cómputo de revisión](/es-MX/manual/guias/computo-de-revision/) para ver el
modelo determinista de cohortes y ejes.

## Revisar una PR externa

Control Center también importa PRs abiertas por personas fuera de la aplicación.
El flujo de revisión anterior es idéntico. El servicio de sondeo de PRs detecta
las PRs externas.
