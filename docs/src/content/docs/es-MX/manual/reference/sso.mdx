Todo lo configurable del inicio de sesión único, en un solo lugar. Los valores
viven en las filas de `sso_connections` de `global.db` (de alcance de servidor
por diseño) y se editan desde **Ajustes → Servidor → Inicio de sesión único** o
con las operaciones RPC `sso.*`. La fila guardada es la única fuente de verdad:
no existe ninguna vía que use variables de entorno `CC_SAML_*` / `CC_OIDC_*`
(una conexión que pudiera llegar desde dos lugares es una con la que la pantalla
de ajustes puede discrepar).

## Campos de la conexión

| Campo                  | Se aplica a | Predeterminado  | Significado                                                                                                                                          |
| ---------------------- | ----------- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `enabled`              | ambas       | desactivado     | los inicios de sesión pueden usar esta conexión                                                                                                       |
| `idpMetadataXml`       | SAML        | —               | el XML `EntityDescriptor` del IdP (obligatorio para activarla)                                                                                        |
| `spEntityId`           | SAML        | `<origin>/saml` | nuestro id de entidad, fijado cuando el origen varía                                                                                                  |
| `emailAttribute`       | SAML        | `email`         | atributo que lleva el correo electrónico; un NameID con forma de correo es la alternativa                                                             |
| `displayNameAttribute` | SAML        | `displayName`   | atributo de nombre para mostrar                                                                                                                       |
| `groupsAttribute`      | SAML        | `groups`        | atributo de nombres de grupo                                                                                                                          |
| `clockSkewSeconds`     | SAML        | 90              | margen de desfase al validar la vigencia                                                                                                              |
| `allowIdpInitiated`    | SAML        | desactivado     | aceptar respuestas no solicitadas válidas (sin `InResponseTo`); el navegador debe reclamar una concesión de corta duración antes de recibir una credencial sellada para el destinatario |
| `wantResponseSigned`   | SAML        | desactivado     | exigir una firma en la raíz de la respuesta (las firmas de aserción siempre son obligatorias)                                                         |
| `issuer`               | OIDC        | —               | URL base del emisor (obligatoria para activarla)                                                                                                      |
| `clientId`             | OIDC        | —               | id de cliente público (obligatorio para activarla)                                                                                                    |
| `clientSecret`         | OIDC        | —               | solo para clientes confidenciales; se guarda en el archivo de secretos con permisos 0600, nunca en la base de datos — solo escritura por RPC (`sso.getConfig` reporta `clientSecretPresent`) |
| `groupsClaim`          | OIDC        | `groups`        | claim que lleva los nombres de grupo                                                                                                            |
| `defaultRole`          | ambas       | `member`        | rol cuando ningún grupo se asigna — nunca `owner`                                                                                                     |
| `groupRoleMap`         | ambas       | `{}`            | grupo → rol; las asignaciones de propietario se rechazan al guardar                                                                                   |
| `autoMember`           | ambas       | activado        | añadir automáticamente a los usuarios a cada espacio de trabajo en el primer inicio de sesión                                                         |
| `allowJit`             | ambas       | activado        | aprovisionar usuarios desconocidos al iniciar sesión                                                                                                  |

## Configuración del proceso

Las conexiones SSO no se siembran desde el entorno. Queda un flag de proceso que
elige dónde abre el navegador el cliente web tras una devolución de llamada SSO:

| Variable / flag                                 | Significado                                                                                                                      |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `--web-client-url` / `CC_SERVER_WEB_CLIENT_URL` | URL del cliente web para un traspaso de credencial sellada; si no se define, el traspaso se mantiene en el mismo origen (solo útil si el cliente web se sirve ahí). En un inicio de sesión `web-popup`, prevalece un `client_origin` permitido de la pestaña que lo inicia. |

La propia URL del emisor debe ser `https` (`http` solo se acepta para emisores
de loopback: `localhost`, `127.0.0.1` y `::1`). Usa TLS confiable para la
devolución de llamada del IdP y el host del cliente web: la página que genera la
clave del destinatario y su JavaScript entregado forman parte de la frontera de
confianza. HTTPS protege ese arranque; tras el emparejamiento, tanto las sesiones
`/rpc` directas como las que pasan por el relevo requieren cifrado Noise y una
identidad de servidor fijada.

## Endpoints HTTP

| Endpoint                                         | Autenticación           | Propósito                                                                                                                                                                                                       |
| ------------------------------------------------ | ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /saml/login?relay=…&handoff_key=…`          | ninguna (redirección)   | comenzar un inicio de sesión iniciado por el SP con una clave de destinatario X25519 en poder del cliente; `relay=desktop` se lo entrega a la app y `relay=web-popup` envía un postMessage a la pestaña de conexión en espera (su `client_origin` se admite solo si la lista de orígenes permitidos confía en él) |
| `POST /saml/acs`                                 | ninguna (POST del IdP)  | verifica la aserción y aprovisiona al usuario; el inicio de sesión iniciado por el SP sella la credencial de dispositivo emitida con la clave del destinatario que lo inició; el SAML no solicitado permitido produce en su lugar una reclamación vinculada al navegador |
| `POST /saml/claim`                               | concesión de navegador en el mismo origen | canjear una concesión SAML no solicitada de un solo uso con su cookie y una `handoff_key` nueva; devuelve una credencial sellada para el destinatario, nunca una clave de emparejamiento en texto plano |
| `GET /saml/metadata`                             | ninguna                 | nuestro `EntityDescriptor` de SP                                                                                                                                                                                |
| `GET /oidc/login?relay=…&handoff_key=…` / `GET /oidc/callback` | ninguna | el ciclo de ida y vuelta de OIDC; el inicio de sesión requiere la clave del destinatario en poder del cliente; `relay=desktop` se lo entrega a la app y `relay=web-popup` a la pestaña de conexión en espera (misma convención de `client_origin`) |
| `GET /auth/providers`                            | ninguna, CORS `*`       | la sonda de la pantalla de conexión: las conexiones SSO ofrecidas (`id`/`kind`/`label`) + `pairingEnabled`                                                                                                       |
| `/scim/v2/Users…`                                | Bearer (token SCIM)     | Users: crear/obtener/listar+filtrar/PUT/PATCH/DELETE                                                                                                                                                            |
| `/scim/v2/Groups`                                | Bearer                  | solo lectura; el envío de grupos responde 501 por diseño                                                                                                                                                        |
| `/scim/v2/ServiceProviderConfig`                 | Bearer                  | documento de capacidades                                                                                                                                                                                        |

Para SAML y OIDC iniciados por el SP, la URL de inicio de sesión requiere una
`handoff_key` válida (la clave pública X25519 del cliente que lo inicia). El
servidor conserva esa clave junto con el inicio de sesión pendiente y sella la
credencial de dispositivo emitida en la devolución de llamada usando X25519
efímero, HKDF-SHA256 y AES-256-GCM vinculados al origen del servidor. El traspaso
al escritorio usa `control-center://pair`, el traspaso web en la misma pestaña
usa un fragmento de URL, y `web-popup` envía un postMessage al `client_origin`
permitido si se proporciona (si no, a la URL configurada del cliente web o al
origen de la devolución de llamada). En ese fragmento o mensaje emergente viaja
el sobre sellado, no una clave de emparejamiento en texto plano. El cliente que
lo inicia conserva la clave privada correspondiente para abrirlo. Este sobre es
distinto de la sesión Noise obligatoria que se establece tras el emparejamiento.

Una respuesta SAML iniciada por el IdP (cuando está habilitada) no tiene
destinatario iniciador. En su lugar, el ACS establece una cookie de navegador de
cinco minutos, HttpOnly y SameSite=Strict, y presenta una elección **Abrir el
cliente web** / **Abrir la app de escritorio**. Esa página genera una clave de
destinatario nueva y publica su mitad pública y el identificador de la concesión
en `POST /saml/claim` desde el mismo origen. Claim requiere la cookie y el origen
coincidentes (una frontera CSRF), consume la concesión una vez y devuelve solo un
sobre sellado para el destinatario. El fragmento posterior de web/escritorio
lleva ese sobre y el material de la clave privada del destinatario para que el
cliente de destino pueda abrirlo, **no** una credencial de dispositivo en texto
plano. Otro navegador o una concesión caducada no pueden canjearlo. El origen del
cliente web de destino puede acceder al fragmento y descifrarlo; una página de
devolución de llamada o un origen de cliente web comprometidos pueden robar
credenciales. El cifrado no hace seguro el código servido que no es de confianza.

## Operaciones RPC

Todas las operaciones `sso.*` tienen alcance de servidor y están restringidas al
**propietario del servidor** (el operador de la instalación,
`ServerAuthority.serverOwner`). Ser propietario de un espacio de trabajo no
basta, y el mero emparejamiento nunca las concede.

| Operación                 | Propósito                                                                                                                                                     |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sso.getConfig`           | la conexión guardada para un tipo                                                                                                                             |
| `sso.saveConfig`          | validar, persistir y aplicar en vivo                                                                                                                          |
| `sso.status`              | indicadores de activado/configurado, presencia del token SCIM, origen canónico                                                                                |
| `sso.testConnection`      | probar una conexión sin llegar al ciclo de ida y vuelta por el navegador (SAML: análisis de metadatos + construcción de AuthnRequest; OIDC: descubrimiento del emisor), con valores opcionales en pantalla aún sin guardar |
| `sso.spMetadata`          | emitir el `EntityDescriptor` de SP para un origen                                                                                                             |
| `sso.setPairingEnabled`   | permitir o prohibir el emparejamiento manual (códigos de invitación, claves de emparejamiento); negarse a desactivarlo mientras no exista ninguna conexión SSO funcional protege contra un bloqueo de acceso |
| `sso.sessionPolicy`       | leer la antigüedad máxima de las credenciales de dispositivo de la instalación y el tiempo de inactividad máximo (en minutos; `0` = sin definir)              |
| `sso.setSessionPolicy`    | fijar esos límites; se aplican en la verificación del dispositivo, no se anuncian a los clientes                                                               |
| `sso.scimRegenerateToken` | generar y devolver el token bearer SCIM (una sola vez)                                                                                                        |

## Códigos de error de validación

Los fallos de `cc_saml_verify_response` llevan un código estable:

| Código                 | Significado                                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `signature`            | firma ausente, no confiable o manipulada, o un algoritmo o transformación no permitido                                   |
| `expired`              | fuera de `NotBefore`/`NotOnOrAfter` (más allá del desfase)                                                               |
| `audience`             | la restricción de audiencia no nos nombra                                                                                |
| `destination`          | el destino de la respuesta no es nuestra ACS                                                                             |
| `request_match`        | `InResponseTo` no coincide con ninguna solicitud pendiente, o es una respuesta no solicitada mientras no estén permitidas |
| `issuer`               | el emisor no es el IdP configurado                                                                                       |
| `recipient`            | el destinatario de la confirmación del sujeto no es nuestra ACS                                                          |
| `malformed`            | fallo a nivel de XML o de esquema                                                                                        |
| `status`               | el estado informado por el IdP no era Success                                                                            |
| `invalid` / `internal` | cualquier otra cosa / fallo en la costura                                                                                |

## Superficies de base de datos

- `sso_connections` (global.db) — una fila por tipo, TRANSVERSAL A LOS ESPACIOS
  DE TRABAJO POR DISEÑO.
- `users.sso_subject` + `users.sso_issuer` — la fijación del sujeto del
  proveedor, única por `(issuer, subject)` mediante un índice parcial.
- `users.deactivated_at` — la marca de desactivación de SCIM.
- El token bearer SCIM y el secreto de cliente de OIDC viven en el archivo de
  secretos con permisos 0600, nunca en la base de datos.
