`cc_server` 託管單一 MCP（JSON-RPC 2.0）工具登錄，於主伺服器連接埠（預設 `9030`）以 `POST /mcp` 與 `GET /sse` 提供，通訊協定版本為 `2024-11-05`。每個用戶端存取的都是同一個登錄：桌面版、網頁版、外部 MCP 用戶端，以及內建代理執行環境。外部 MCP 伺服器可以動態層的形式橋接進同一個登錄。

## 登錄大小

| 指標                                                                      | 數量 |
| ------------------------------------------------------------------------- | ---- |
| 由 `cc_server` 註冊的工具                                                 | 110  |
| 來自 `packages/cc_mcp`                                                    | 108  |
| 來自 `packages/cc_mcp_client`（工具探索）                                 | 2    |
| 註冊於基礎登錄（`server_mcp_registry.dart`）                              | 63   |
| 開機後隨其服務啟動而註冊（`cc_server_runtime.dart`）                      | 47   |
| 基礎登錄的 63 個之中，以程式碼圖儲存庫為條件者                            | 5    |

這五個程式碼圖工具只有在主機把程式碼圖儲存庫傳給 `buildServerMcpRegistry` 時才會註冊。`cc_server` 一律會傳入一個，因此出貨的執行檔中 110 個全部可用。

完整登錄會透過 `tools/list` 完整公告，沒有任何探索閘門。工單編輯是具型別的工具。

:::note[外部用戶端一律看到完整目錄]
`tools/list` 絕不會被裁剪。MCP 用戶端會以自己的那份快取清單驗證工具名稱，並直接拒絕任何未列出的項目，不會去詢問伺服器，因此從中藏起來的工具是無法觸及，而不只是安靜無聲。

**內建執行環境**則不同：每次請求它只載入常駐的一部分定義，其餘則在第一次用到時才取入；這是執行環境端的行為，並不會改變這個登錄。請參閱[工具情境與提示快取](/zh-TW/手冊/概念/工具情境/)。
:::

:::note[每個工具類別都會被註冊]
`packages/cc_mcp/lib/src/tools/` 下的每個原始檔，都是代理可以呼叫的一個工具。
若有新的工具類別沒有被任何地方建構，`packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart`
會讓建置失敗。
:::

## 通用參數

### `workspace_id`

凡是會碰到工作區範圍資料的工具，此參數皆為**必填**。缺少或無效的 `workspace_id` 會回傳明確的錯誤，而與目標實體所屬工作區不符的值會被拒絕，而不是被默默忽略。在真正全域的工具上則省略它：`list_workspaces` 以及六個新聞動態工具（`list_feeds`、`list_articles`、`get_article`、`set_article_read`、`set_article_saved`、`refresh_feeds`），它們使用的是伺服器擁有者每位使用者的摘要來源清單。探索工具（`search_tool_bm25`、`list_my_tools`）則選填此參數，這樣它們才能依對話模式分類可呼叫性。當代理由伺服器派送時，工作區是在伺服器端強制決定的，因此代理無法藉由傳入外來的 id 觸及另一個工作區。

## 工具探索

兩者都來自 `cc_mcp_client`，而非 `cc_mcp`，且都會查詢模式守門程式，因此它們回報的是_當前_對話模式中可呼叫的項目。

| 工具               | 說明                                                                                                       |
| ------------------ | ---------------------------------------------------------------------------------------------------------- |
| `search_tool_bm25` | 依關鍵字搜尋工具目錄；回傳相符的工具、其引數結構描述，以及每個工具目前是否可呼叫                            |
| `list_my_tools`    | 列出此對話中目前可呼叫的工具，並依其模式篩選                                                               |

第三個探索工具 **`search_tools`** 只存在於內建執行環境內，並不屬於這個 MCP 登錄。它會為該次執行自身的工具介面排名，而且與 `search_tool_bm25` 不同，它會**載入**找到項目的結構描述，好讓代理能在下一個回合呼叫相符的工具。在執行環境上執行的代理應優先使用它；MCP 用戶端則有 `search_tool_bm25`。

## 代理對等訊息與委派

代理彼此透過空間交談（持久、名冊可見）。`ask_agent` 是請求／回覆，且有強制逾時；`delegate_task` 則在伺服器端受深度上限、循環偵測、預算包絡與自主程度上限保護。

| 工具            | 說明                                                                                           |
| --------------- | ---------------------------------------------------------------------------------------------- |
| `send_to_agent` | 傳送單向訊息給另一個代理，以 `to_agent_id` 或完全相符的 `to_agent_name` 指定對象                |
| `ask_agent`     | 向另一個代理提問並等待其回覆，或逾時                                                           |
| `delegate_task` | 以受追蹤的子工單形式，將任務委派給另一個代理                                                   |
| `consult_agent` | 依技能把最相符的專家加入該空間，並以聚焦的簡報派送它                                           |
| `todo_read`     | 讀取此對話已持久化的任務檢查清單                                                               |

## 隔離艙（機台）工具

在執行過程中驅動用完即丟的機器——封閉的瀏覽器或 Linux 桌面、Android
模擬器，或 iOS 模擬器。開機後無條件註冊：某台機器是否真的能開機，是這些
工具每次呼叫時回答的探測問題。同一對話中重複呼叫會重用同一台機器；
螢幕截圖會以圖片內容回傳，且每個結果僅限一張圖片，擷取到的頁面／UI
內容則會圍籬標記為不受信任的資料。四個使用類工具加上
`rig_close` 會宣告 `enclosureControl` [動作類別](/zh-TW/手冊/概念/護欄/)
（使用類工具也會宣告 `networkEgress` 與 `processSpawn`；`mobile_use` 與
`ios_use` 還會宣告 `packageInstall`），因此唯讀模式會拒絕它們。`rig_list`
不宣告任何類別——它只讀取工作區狀態。每個表面完整的動詞詞彙請見
[機台參考](/zh-TW/手冊/參考/機台/#action-verbs)。

| 工具           | 說明                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------- |
| `computer_use` | 在封閉的 VM 中驅動 Linux 桌面：移動、點擊、拖曳、捲動、輸入、調整大小、剪貼簿、螢幕截圖                 |
| `browser_use`  | 驅動無頭 Chromium、Firefox 或 WebKit（`engine`）：瀏覽、點擊、填寫、擷取（a11y/DOM/console）、剪貼簿、螢幕截圖 |
| `mobile_use`   | 透過 ADB 驅動 Android：檢視／輸入、螢幕截圖、安裝／啟動／停止／重設／解除安裝應用程式、深層連結與 argv 形式的裝置命令 |
| `ios_use`      | 透過 WebDriverAgent/CoreSimulator 驅動 iOS 模擬器：檢視／輸入、螢幕截圖、安裝／啟動／停止／解除安裝應用程式、深層連結與 argv 形式的模擬器程序 |
| `rig_list`     | 列出工作區的機台，包含表面、狀態、顯示大小與控制者                                                     |
| `rig_close`    | 銷毀機台並捨棄其擁有的機器狀態                                                                         |

## 未透過 MCP 暴露

日曆與會議沒有 MCP 工具。代理無法讀取你的日曆、會議、逐字稿、行動項目或決議。產出這些行動項目與決議的摘要是以內建的 [`meeting_summary` 管線](/zh-TW/手冊/概念/會議/)執行，而不是代理可呼叫的工具。

## 依模式的工具閘門

閘門由單一表格（`ModeToolPolicy`）強制執行兩次：一次在 Claude Code 配接器的 MCP 分派器中，一次在內建執行環境登錄中。被阻擋的呼叫會回傳原因。

| 模式          | 工具介面                                                                                                                                                                                                                            |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`        | 所有已註冊的工具；沒有允許清單                                                                                                                                                                                                      |
| `plan`        | 一份精選的允許清單。不可寫入工作樹，也沒有 `create` / `assign` / `delegate` 工單動詞，但允許記憶、成品、待辦事項、`submit_plan`、`exit_plan_mode`，以及對已派送工單的工單完成動詞                                                |
| `review`      | 一份精選的允許清單：審查參與、溝通、唯讀情境取得器，以及包含 `create_ticket` 與 `assign_ticket` 的完整工單動詞集                                                                                                                     |
| `orchestrate` | 一份精選的允許清單：研究與讀取工具，加上 `propose_orchestration`、`create_playbook` 與 `run_playbook`。聘用、分解與工單完成會在核准後確定性地發生，絕不會在執行途中進行                                                              |

無論允許清單為何，在每個模式中都允許：

| 集合                 | 工具                                                                                                                                                                                                                                                              |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 記憶與成品           | `search_memory`, `propose_fact`, `propose_policy`, `supersede_fact`, `supersede_policy`, `record_observation`, `update_my_notes`, `get_my_notes`, `list_memory_domains`, `list_policies`, `publish_artifact`, `revise_artifact`, `list_artifacts`, `get_artifact` |
| 程式碼圖             | `search_code`, `code_symbol`, `code_callers`, `code_callees`, `code_impact`                                                                                                                                                                                       |
| 執行機制             | `search_tool_bm25`, `list_my_tools`, `todo_write`, `todo_read`                                                                                                                                                                                                    |

名列允許清單並不代表工具就可呼叫，反之亦然：向操作者提問的能力是**執行環境**工具（`ask_user`），因此它完全不會出現在這個 MCP 目錄中。

## 需核准的工具

工具可以宣告 `requiresApproval`。分派器接著會建構 `ApprovalPayload`，並在工具執行前透過 `ConfirmationPort` 呈現；`cc_server` 會接上該埠，因此這道閘門是實際生效的。

宣告此項的已註冊工具：`create_ticket`、`update_ticket`、`assign_ticket`、`reassign_ticket`、`close_ticket`、`ticket_relation`、`create_goal`、`update_goal_progress`、`create_approval`、`decide_approval`、`comment_approval`、`create_work_product`、`save_work_product_revision`、`create_runtime_profile`、`install_skill`、`update_skill`。

另外，統一的動作護欄會對任何宣告非空 `ActionClass` 集合的工具設下閘門。在沒有連接任何核准者的情況下，`prompt` 決策一律拒絕。請參閱[護欄](/zh-TW/手冊/概念/護欄/)。

## 背後沒有工具的能力

產品中的每個能力並非都能由代理觸及。以下這些完全沒有工具，
因此你可能在別處看過被引用的名稱，會回傳「unknown tool」：

| 能力                                    | 實際所在位置                                                                                 |
| --------------------------------------- | -------------------------------------------------------------------------------------------- |
| 聘用、解僱或編輯代理                    | 代理介面。沒有 `hire_agent` / `fire_agent` / `update_agent` 工具                             |
| 建立工作區                              | 透過 RPC 的 `workspace.upsert`，它會播種並蓋上擁有權                                          |
| 專案（建立／列出／更新／歸入）           | 工單介面。專案是操作者介面——請參閱[專案](/zh-TW/手冊/操作指南/專案/)                          |
| 向操作者提出會阻擋的問題                | **執行環境**的 `ask_user` 工具，而非 MCP。它會在對話中呈現表單並等待答案                      |
| 個別代理診斷                            | 沒有。沒有 `doctor`——請參閱[診斷代理](/zh-TW/手冊/操作指南/診斷代理/)                         |
| 日曆與會議                              | 僅供人類用戶端使用的 RPC（見上文）                                                            |
