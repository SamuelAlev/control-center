Control Center Connect 會為尚未註冊自己應用程式的伺服器執行供應商登入。伺服器可以
使用 Control Center 代管的 Connect、其組織自行執行的 Connect
（[執行 Connect 伺服器](/zh-TW/手冊/操作指南/執行-connect-伺服器/)），或者都不使用。
這個選擇位於 **設定 → 伺服器 → 單一登入 → Control Center Connect**、
`cc_server connect`，或 `CC_CONNECT_URL`。

## 通道

在**使用我自己的應用程式**（或尚未有人選擇前），通道使用伺服器自己的應用程式（若已完整設定），否則無法使用。使用 Control Center Connect 或自訂 Connect 時，Connect 會服務其提供的每個通道：伺服器自己的應用程式保留但不使用，無論是登入、伺服器自動化或伺服器回報的狀態。工作區自己的應用程式在任何模式下都優先。

| 通道         | 自有應用程式需要                                 | 透過 Connect                                              |
| ------------ | ------------------------------------------------ | --------------------------------------------------------- |
| `github`     | App id、私鑰、用戶端 id 與用戶端密鑰             | 人們登入共用的 GitHub App                                 |
| `google`     | 用戶端 id 與用戶端密鑰                           | 人們連接 Google Calendar                                  |
| `linear`     | 用戶端 id                                        | 人們登入 Linear                                           |
| `linear_app` | 用戶端 id                                        | 由工作區管理員連接 Linear 的應用程式執行者                |
| `slack`      | 工作區自己的 Slack 應用程式連線                  | 由工作區管理員把 Slack 連接到共用的 Slack 應用程式        |
| `klipy`      | `KLIPY_APP_KEY`                                  | GIF 搜尋，由 Connect 代理                                 |

只設定了一部分的自有應用程式會讓它的通道成為錯誤狀態，絕不會悄悄退回 Connect。使用
自己 GitHub App 的工作區（**設定 → 工作區 → 一般 → GitHub 身分**）永遠不會為 GitHub
經過 Connect。若工作區使用自己的 Google、Linear 或 Klipy 應用程式（**設定 → 工作區 → 一般 → 供應商應用程式**），它對該供應商也永遠不會經過伺服器的應用程式或 Connect。變更 Connect 選擇不會讓任何人登出工作區自己的應用程式。

## Connect 看得到與永遠看不到什麼

| Connect 看得到                                                                                | Connect 永遠看不到                                                    |
| --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 伺服器的安裝 ID 與請求簽章                                                                    | 原始碼、儲存庫內容、差異或 pull request 文字                          |
| 登入期間，完成登入的那個供應商帳號                                                            | 工單、逐字稿或工作區資料庫中的任何內容                                |
| 某份憑證屬於哪個工作區，以封存內的不透明 ID 形式呈現                                          | GitHub App 私鑰：儲存庫權杖來自某個人的登入                           |
| 只適用於單一儲存庫的 GitHub 權杖是為哪個儲存庫簽發的                                          | 靜態儲存的重新整理權杖：它們只存在於伺服器保存的封存之內              |
| 綁定到該伺服器的 GitHub 安裝 ID                                                               | Linear 密鑰：伺服器會自行交換 Linear 的代碼                           |
| 代理 Klipy 時的 GIF 搜尋字詞                                                                  | 密碼、配對金鑰或模型供應商金鑰                                        |
| Slack 事件參照（團隊、頻道、訊息 id）與斜線指令文字                                           | Slack 訊息文字：Connect 在收到時就會丟棄，伺服器會自行從 Slack 讀取訊息 |

Connect 會保留短效狀態（暫存中的登入、nonce、快取），最多 15 分鐘。它唯一長期保存的
紀錄是安裝綁定：哪些伺服器可以使用哪個 GitHub 安裝，以及每個 Slack 團隊綁定到哪台
伺服器。錯誤只帶有代碼，絕不包含供應商的回應，而日誌只以帶金鑰的雜湊記錄安裝 ID。

## 模式

| 模式     | 設定                        | 行為                                                                                                     |
| -------- | --------------------------- | -------------------------------------------------------------------------------------------------------- |
| 未設定   | 全新的伺服器                | 沒有任何通道使用 Connect。入門引導會請伺服器擁有者選擇                                                   |
| `hosted` | **使用 Control Center 的應用程式** | `https://connect.usectrl.dev`，搭配一份離線簽署的設定。伺服器自己的應用程式不會被使用                                             |
| `custom` | **使用自訂 Connect 伺服器** | 位於 HTTPS 網址（僅回送位址可用 `http`）的 Connect，首次使用時即予以信任。伺服器自己的應用程式不會被使用                                 |
| `off`    | **使用我自己的應用程式**    | 沒有任何通道使用 Connect。只有自有應用程式能讓人們登入                                                   |

伺服器環境或 `.env` 中的 `CC_CONNECT_URL` 會鎖定這個選擇：`hosted`、`off` 或一個
Connect 網址。之後設定會顯示這個鎖定，且無法變更它。

這個建置版本沒有編入任何代管設定金鑰，因此代管模式會回報 `hosted_unprovisioned`，
且不提供任何通道。自有應用程式與自訂 Connect 都能運作。

伺服器最多每 10 分鐘讀取一次 Connect 的設定，每次呼叫最多等待 5 秒。當 Connect 無法
連線時，會繼續使用最後一份有效的設定，並由設定將其標示為過時。

## 安裝身分

| 項目            | 說明                                                                                                             |
| --------------- | ---------------------------------------------------------------------------------------------------------------- |
| 安裝金鑰        | 伺服器機密檔案中的一個 32 位元組種子（`connect_install_key`），與裝置配對金鑰分開                                 |
| 每個 Connect 的金鑰 | 由種子與該 Connect 的位址衍生出的 Ed25519 金鑰。每個送往 Connect 的請求都以它簽署（RFC 9421）                 |
| 安裝 ID         | 由該公開金鑰衍生出的 26 個字元。顯示在設定中，以及 `cc_server connect status` 的輸出裡                           |

同一台伺服器面對每個 Connect 位址都有不同的安裝 ID。只有在金鑰被輪替時，這個 ID
才會改變。

## 封存的憑證

透過 Connect 的登入會回傳一份**憑證封存**：一個只有建立它的 Connect 能開啟的加密
資料塊。它綁定到供應商、Connect 位址、安裝 ID、工作區、供應商帳號、應用程式與密鑰
世代。

- 伺服器儲存這份封存以及它所對應的安裝 ID。存取權杖只留在記憶體中
- 要重新整理時，伺服器會把封存送回，並取得新的存取權杖與新的封存
- 安裝 ID 或 Connect 位址不再相符的封存，會在下次讀取時被刪除，而那個人需要重新
  登入。這會發生在金鑰輪替、切換到另一個 Connect，或資料目錄被還原到另一台伺服器
  之後
- Connect 無法開啟的封存會以 `access_denied` 拒絕

## GitHub 安裝

只有在 Connect 已把共用 GitHub App 的某個安裝綁定到某台伺服器的安裝 ID 時，那台
伺服器才能使用這個安裝。

- **設定 → 工作區 → 一般** 中的**安裝 GitHub 應用程式**會以一張 15 分鐘的票證開啟
  GitHub。當安裝者擁有該個人帳號或管理該組織時，Connect 會綁定新的安裝
- **授權此伺服器**會綁定一個已經存在的安裝。只有組織管理員能這麼做
- 一個組織安裝可以綁定到數台伺服器；每一台都需要一位管理員的授權

## 設定信任

| Connect | 伺服器如何信任它的設定                                                                                                                    |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 代管    | 以編入建置版本的金鑰驗證 Ed25519 簽章。拒絕低於它見過之最高世代號的設定（`rollback`）                                                   |
| 自訂    | 首次使用時釘選 GitHub 應用程式 id 與用戶端 id、Google 與 Linear 的用戶端 id，以及 Slack 應用程式與用戶端 id。任何變更都會暫停透過 Connect 的登入（`pins_changed`），直到伺服器擁有者按下**信任新應用程式** |

## 操作

所有 Connect 設定都只限伺服器擁有者。

| 操作                  | 作用                                                                                   |
| --------------------- | -------------------------------------------------------------------------------------- |
| `connect.status`      | 模式、網址、鎖定、安裝 ID、健康狀態、設定世代號，以及每條通道的來源                   |
| `connect.configure`   | 設定 `hosted`、`custom`（搭配 `url`）或 `off`                                          |
| `connect.test`        | 重新擷取設定並回報健康狀態                                                             |
| `connect.confirmPins` | 接受自訂 Connect 已變更的識別碼                                                        |
| `connect.rotateKey`   | 產生新的安裝金鑰。這台伺服器上每一個透過 Connect 的登入都會停止運作                   |

登入本身使用 `oauth.lanes`、`oauth.begin`、`oauth.status`、`oauth.complete`、
`oauth.connections` 與 `oauth.disconnect`。登入者一律是已登入的呼叫者本人。

## 透過 Connect 登入

1. 伺服器要求 Connect 開始該通道，並取得供應商的授權網址，在顯示之前會先檢查它
2. 使用者在瀏覽器中核准。供應商返回 Connect
3. Connect 顯示一組 8 個字元的代碼與一個 `control-center://oauth-done` 連結
4. 使用者把代碼輸入應用程式，或點開連結。伺服器以該代碼及它自己對這次請求的證明
   認領這次登入

登入會在 10 分鐘後過期。輸錯五次代碼會結束它。不是由這個應用程式發起的連結會以
**登入並非從這裡發起**拒絕。

## 輪替安裝金鑰

在 Connect 卡片上按下**輪替金鑰**，或執行 `cc_server connect rotate-key --yes`：

- 讓伺服器取得新的安裝金鑰與新的安裝 ID
- 讓所有人從每一條經由 Connect 的通道登出
- 不影響透過伺服器自有應用程式的登入
- 需要把新的安裝 ID 加入自訂 Connect 的允許清單

## 狀態代碼

| 代碼                   | 意義                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| `hosted_unprovisioned` | 這個建置版本沒有代管設定金鑰                                         |
| `signature`            | 代管設定未通過簽章檢查                                               |
| `rollback`             | Connect 提供的設定比伺服器已見過的更舊                               |
| `unreachable`          | 伺服器無法連到 Connect                                               |
| `install_blocked`      | Connect 不允許這個安裝 ID                                            |
| `pins_changed`         | 自訂 Connect 公告了不同的應用程式識別碼                              |
| `protocol`             | Connect 的回應格式是這台伺服器無法理解的                             |
