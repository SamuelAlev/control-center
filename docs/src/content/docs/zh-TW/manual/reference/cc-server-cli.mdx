每個行程旗標都接受一個命令列旗標或一個環境變數；旗標優先，其次是環境變數，
最後才是預設值。供應商憑證是例外——見[供應商應用程式與 Connect](#供應商應用程式與-connect)。

:::caution[未知的旗標會被無聲忽略]
引數剖析器是手寫的，會略過任何它不認得的內容，因此打錯字 （`--tls-key-file`、`--bindany`）不會產生錯誤——伺服器只會以預設值啟動。 當某個旗標看似沒有作用時，請檢查啟動日誌的內容。[程式碼模式旗標](#程式碼模式)若帶有它不接受的值，則情況不同：伺服器會拒絕啟動。
:::

## 核心

| 旗標            | 環境變數               | 預設值                                           | 意義                                                                                                           |
| --------------- | ---------------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `--data-dir`    | `CC_SERVER_DATA_DIR`   | 作業系統的每位使用者應用程式資料目錄（見下文）   | 資料庫、密鑰、模型與快取媒體                                                                                   |
| `--port`        | `CC_SERVER_PORT`       | `9030`                                           | TCP 連接埠（`0` = 臨時）                                                                                       |
| `--bind`        | `CC_SERVER_BIND`       | `loopback`                                       | `loopback`，或 `any`/`all`/`0.0.0.0` 表示所有介面（需要 TLS 或 `--insecure`）                                  |
| `--repo-roots`  | `CC_SERVER_REPO_ROOTS` | 伺服器使用者的家目錄                             | 用戶端註冊儲存庫時可瀏覽的基準目錄，以逗號分隔。瀏覽某個根目錄之上的路徑會被拒絕                               |
| `--log-level`   | `CC_SERVER_LOG_LEVEL`  | `warning`                                        | `debug`、`info`、`warning` 或 `error`。啟動與就緒的日誌行一律會印出                                             |
| `--server-name` | `CC_SERVER_NAME`       | 本機主機名                                       | 顯示在選擇器、探索與配對介面上的名稱                                                                           |

## 索引與執行環境

| 旗標                     | 環境變數                        | 預設值                                | 意義                                                                                                          |
| ------------------------ | ------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `--sandbox`              | `CC_SERVER_SANDBOX`             | `on`                                  | `on` 會用作業系統原生沙箱包裹代理執行，而在沒有沙箱的主機上只啟動伺服器擁有者的執行。`off` 會讓該主機上每位成員的代理都不受沙箱限制地執行。見下文            |
| `--code-index`           | `CC_SERVER_CODE_INDEX`          | `on`                                  | 背景程式碼圖索引的現場終止開關。`off` 能在不需重新建置的情況下乾淨啟動                                        |

| `--tool-deferral`        | `CC_SERVER_TOOL_DEFERRAL`       | `on`                                  | 執行環境的執行是否只送出一小組直接工具加上一份名稱索引，其餘工具在首次使用時才載入。見下文                     |
| `--credential-gate`      | `CC_SERVER_CREDENTIAL_GATE`     | `900`                                 | 執行擱置等待真人修復無法服務它的憑證的秒數（限制在 0–3600 之間）。見下文                                       |
| `--code-mode-max-processes` | `CC_SERVER_CODE_MODE_MAX_PROCESSES` | `min(16, 2 × cores)` | 此伺服器上同時執行的程式碼模式指令碼數量（不計等待人員的指令碼），1–64。見下文 |
| `--code-mode-max-heap-mb` | `CC_SERVER_CODE_MODE_MAX_HEAP_MB` | `1024` | 單一指令碼可使用的最大記憶體，16–1024 MiB。工作區較高的記憶體上限會被降低至此值 |

## 供應商應用程式與 Connect

沒有任何建置版本會攜帶供應商憑證。開啟 Control Center Connect 時，Connect 會執行每個供應商，伺服器自己的應用程式則保留但不使用。在**使用我自己的應用程式**下，每個供應商在伺服器自己的應用程式設定完整時使用它，否則無法使用。工作區自己的應用程式在兩種情況下都優先。自己的應用程式
在 **設定 → 伺服器 → 單一登入 → 供應商應用程式** 中設定，或從伺服器的 `.env` 檔案
提供一次初始值。它們沒有對應的旗標：命令列上的密鑰可透過 `ps` 讀取。

| 變數                           | 意義                                                                                          |
| ------------------------------ | --------------------------------------------------------------------------------------------- |
| `GITHUB_APP_ID`                | 伺服器的 GitHub App id                                                                        |
| `GITHUB_APP_PRIVATE_KEY`       | 它的私鑰，寫成一行並使用 `\n` 跳脫。**僅限 `.env`**                                           |
| `GITHUB_CLIENT_ID`             | 它的用戶端 id，用於讓人們登入                                                                 |
| `GITHUB_CLIENT_SECRET`         | 它的用戶端密鑰。**僅限 `.env`**                                                               |
| `GOOGLE_OAUTH_CLIENT_ID`       | 伺服器的 Google 網頁應用程式用戶端                                                            |
| `GOOGLE_OAUTH_CLIENT_SECRET`   | 它的密鑰。**僅限 `.env`**                                                                     |
| `LINEAR_CLIENT_ID`             | 伺服器的 Linear 應用程式（PKCE，無密鑰）                                                      |
| `LINEAR_API_KEY`               | 供自動化使用的 Linear 服務金鑰。**僅限 `.env`**                                               |
| `KLIPY_APP_KEY`                | 伺服器自己用於 GIF 搜尋的 Klipy 金鑰，僅在**使用我自己的應用程式**下使用                         |
| `CC_CONNECT_URL`               | `hosted`、`off` 或一個 Connect 網址。會鎖定 Connect 的選擇；之後設定就無法變更它               |
| `CC_SERVER_CONNECT_HOST`       | `on` 會在 `<server>/connect` 掛載 Control Center Connect，並以 `CONNECT_*` 變數設定。見[執行 Connect 伺服器](/zh-TW/手冊/操作指南/執行-connect-伺服器/#在-cc_server-內掛載-connect) |

`.env` 檔案會從伺服器的工作目錄、可執行檔旁邊，或其上層的原始碼簽出中讀取；在
Docker 中，請將它掛載到 `/app/bin/.env`。若 `GITHUB_APP_PRIVATE_KEY`、
`GITHUB_CLIENT_SECRET`、`GOOGLE_OAUTH_CLIENT_SECRET`、`LINEAR_API_KEY` 或任何
`SLACK_*SECRET*` 被匯出到伺服器的行程環境中（每個子行程都讀得到），伺服器會
**拒絕啟動**（結束代碼 `78`）。從 `.env` 提供初始值每個欄位只發生一次，因此之後在
設定中所做的編輯不會因重新啟動而被復原。空值會被視為未設定。

沒有任何託管平台憑證來自環境變數：GitHub、GitLab 與 Bitbucket 都只會以某位成員自己的登入或權杖行事，或是以受該成員約束的單一儲存庫 GitHub App 權杖行事。

### `--sandbox`

伺服器在啟動時會探測主機一次，只要有可用的後端，就會用作業系統原生沙箱包裹代理
的命令執行：macOS 上是 `sandbox-exec`（Seatbelt），Linux 與 WSL2 上則是 `bwrap`
加 `socat`。決定只做一次，並一直維持到伺服器重新啟動為止。共有三種結果，每一種都會顯示在啟動時的暴露行上：

| `sandbox=`    | 何時                                    | 誰的代理執行會啟動                                                               |
| ------------- | --------------------------------------- | -------------------------------------------------------------------------------- |
| `native`      | 有可用後端，且 `--sandbox` 為 `on`      | 每個人的執行，皆經包裹                                                           |
| `off`         | `--sandbox off`                         | 每個人的執行，在此主機上不受限制                                                 |
| `unavailable` | `--sandbox on` 且沒有後端（Windows，或沒有 `bwrap` 與 `socat` 的 Linux） | 只有伺服器擁有者負責的執行，不受限制。其他人會被拒絕，並顯示「此伺服器沒有沙箱，因此只有其擁有者可以在此執行代理。」 |

對於自動化而言，負責的人是該自動化所綁定的人。若沒有記錄任何伺服器擁有者，在 `unavailable` 主機上就不會啟動任何執行。在安裝了 bubblewrap 的 Linux 與 WSL2 上，原生派送目前會對每一次執行失敗關閉；請見[沙箱後端](/zh-TW/手冊/參考/沙箱後端/#linuxbubblewrap)。

`--sandbox off` 是伺服器擁有者為所有使用伺服器的人所做的選擇：它會讓此機器上每位成員的代理都不受限制地執行。當主機上的沙箱設定檔本身行為異常時使用它，或讓成員能在沒有後端的主機上執行代理。它不需要重新建置，而且伺服器會在整個行程存續期間記錄一則警告，因此這個狀態絕不會無聲無息。

### `--tool-deferral`

內建執行環境的執行會送出一小組直接的工具定義，加上其餘工具的僅含名稱索引，這些工具會在首次使用時載入各自的結構描述，或由 `repl` 指令碼呼叫。它讓永遠可見的集合維持在模型能可靠選擇工具的區間內。依測試所建置的登錄表測量，內建代理的標準聊天工具共 14 個定義：有 `repl` 時約為 16.5 KB（其中約 4 KB 屬於 `repl`，其定義不得超過 4,096 位元組），在無法執行指令碼的伺服器上則約為 13 KB。隨需載入的工具自始至終都可以按名稱呼叫，而 `search_tools` 也能依意圖找到它們。參閱[工具情境與提示快取](/zh-TW/手冊/概念/工具情境/)。

`--tool-deferral off` 會把每一個被准入工具的定義預先送出，但有 `repl` 的執行中，指令碼可以呼叫的工具仍只能由指令碼呼叫。它是針對無法好好應付兩層式工具介面的模型所提供的終止開關——只要一個旗標，而不必重新建置。它只影響內建執行環境；外部用戶端看到的 MCP `tools/list` 是完整目錄，但在能執行[程式碼模式](/zh-TW/手冊/概念/程式碼模式/)指令碼的伺服器上，由代理執行的情況除外。

### `--credential-gate`

當某次執行所使用的供應商憑證缺少或已耗盡時，該次執行會被**擱置等待**，而不是
直接失敗：操作人員會收到提示去修復，修好後執行便會繼續。預設期限是 900 秒
（15 分鐘），限制在 0–3600 之間。

這個期限刻意比核准提示長得多：核准是某個人在幾秒內做出的決定，而修復憑證則意味著
打開終端機、登入再回來。正是這個上限讓無人看管的執行——管線步驟、cron 觸發器、
webhook——不必一直等待一個正在睡覺的人。期限一到，該次執行就會帶著它本來就會
出現的訊息失敗。

`--credential-gate=0` 是終止開關：任何東西都不會被擱置等待，憑證有問題時會像這個
閘門出現之前那樣結束該回合。

### 程式碼模式

[程式碼模式](/zh-TW/手冊/概念/程式碼模式/)讓代理執行呼叫其工具的 JavaScript 指令碼。沒有任何旗標能開啟或關閉它：伺服器能執行指令碼時，每次執行都會取得 `repl` 工具，而公開的示範伺服器則不執行任何指令碼。

指令碼在 `bin/codemode/` 中隨伺服器附帶的程式 `cc_codemode` 內執行。沒有它，伺服器無法啟動：它會印出一行說明缺少什麼的訊息，並以結束代碼 `78` 結束。啟動時，伺服器會執行該程式的鎖定自我測試，並印出一行（僅在 `--log-level error` 下會被隱藏）：

```text
cc_server: code_mode=available (cc_codemode 0.1.0 quickjs-ng 0.16.2 protocol 2; 16 scripts at once, at most 12 per workspace; up to 64 more runners kept for scripts waiting on a person; heap at most 1024 MiB per script)
cc_server: code_mode=unavailable (<reason>) — runs on this host get no repl tool; scripts never run without full lockdown
```

`unavailable` 表示該程式無法在此主機上鎖定自己，例如在某個容器的安全設定檔拒絕其中一個步驟的環境中，或該程式並非發行版建置。伺服器仍會正常運行，沒有任何執行會取得 `repl`，而工作區的程式碼模式設定會顯示原因。

伺服器會持續檢查。當程式因非指令碼本身的原因而無法啟動時，伺服器會再次執行自我測試，頻率最多每分鐘一次。若失敗，伺服器會輸出附帶原因的 `unavailable` 行，並不執行任何指令碼：期間啟動的執行不會取得 `repl`，而已取得它的執行則直接呼叫其工具（參閱[無法執行指令碼時](/zh-TW/手冊/概念/程式碼模式/#無法執行指令碼時)）。它會持續檢查，同樣最多每分鐘一次；當自我測試再次通過時，它會輸出 `available` 行，並再次執行指令碼。只有啟動時就失敗的自我測試才需要重新啟動。工作區的設定所顯示的原因已移除主機路徑；日誌行則保留完整內容。

兩個程式碼模式旗標限定了指令碼可以使用的資源。`--code-mode-max-processes` 限制所有工作區同時執行的指令碼數量（預設為處理器核心數的兩倍，最多 16；可接受 1–64）。當上限為 2 或以上時，單一工作區最多只能使用上限減去其四分之一，因此沒有任何單一工作區能佔滿所有位置，等待中的指令碼也會在各工作區之間輪流獲准。等待人員核准或回答的指令碼會讓出其位置給其他指令碼，並在獲得回答之前不啟動任何工具呼叫；此類等待中的指令碼最多保留上限的四倍，且其中至多四分之三來自同一個工作區，每一個仍可在其自己的處理器時間限制內繼續計算。`--code-mode-max-heap-mb` 是任一指令碼可使用的最大記憶體。

這些旗標不接受的值（超出範圍的數字，或根本不是數字），會使伺服器在啟動時停止（結束代碼 `78`），並顯示一則訊息說明可接受的值。它絕不會被當作預設值讀取。

## 子指令

| 指令                                          | 作用                                                                                                        |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `cc_server`                                   | 執行伺服器，直到收到 `SIGINT`/`SIGTERM`                                                                     |
| `cc_server pair`                              | 佈建一台裝置，並印出它的 id 與配對金鑰。即使伺服器正在提供某個資料目錄的服務也能安全執行——執行中的伺服器無需重新啟動就會接收該裝置 |
| `cc_server connect <command>`                 | 顯示或變更這台伺服器使用哪個 Control Center Connect，而不必啟動伺服器                                       |
| `cc_server update`                            | 檢查、下載並驗證較新的獨立發行版本                                                                          |
| `cc_server --version`                         | 印出建置版本與 git SHA——與 `/healthz` 及 RPC 交握所公告的身分相同                                           |

### `pair`

| 旗標           | 預設值                                                    | 意義                                                                                                                                                                 |
| -------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--device`     | `web-client`                                              | 裝置 id。平台會從它推斷，因此 `--device desktop` 會產生一列桌面裝置，而 `--device ios`/`android` 會產生一列手機裝置；其他任何值都是網頁用戶端                        |
| `--label`      | 平台名稱加上這台機器的主機名                              | 裝置清單中的顯示名稱                                                                                                                                                 |
| `--host`       | `localhost`，或繫結至所有介面時的 `<this-host>`           | 要嵌入所印出 URL 的主機。請將它設為用戶端實際會撥接的區域網路 IP 或通道主機                                                                                          |
| `--client-url` | 未設定                                                    | 託管**網頁**用戶端的來源。會額外加上可掃描的深層連結與終端機 QR 碼                                                                                                    |

`pair` 也接受核心的 `--data-dir`、`--port` 與 `--bind` 旗標：它們決定要寫入的資料
目錄，並形塑所印出的伺服器 URL（回送時為 `ws`，`--bind any` 時為 `wss`）。對同一個
`--device` 重新執行 `pair` 會輪替它的金鑰，並終止該裝置使用中的工作階段。在這裡
簽發的憑證**不會過期**，不像應用程式內配對會設定 30 天。

:::caution[`--client-url` 的 QR 碼不是手機用的 QR 碼]
`pair --client-url` 會填寫**網頁**用戶端的連線表單（伺服器 URL、
裝置 id 與金鑰都放在 URL 片段中）。手機配對用的是從應用程式內配對面板
簽發的另一種酬載——伺服器完整的連線描述元加上到期時間。兩者不能互換——參閱[配對裝置](/zh-TW/手冊/操作指南/配對裝置/)。
:::

### `connect`

從資料目錄讀取並寫入與 **設定 → 伺服器 → 單一登入** 中 **Control Center Connect**
卡片相同的設定。執行中的伺服器會在 10 分鐘內或重新啟動時接收變更。

| 指令                            | 作用                                                                                                             |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `cc_server connect status`      | 印出模式、網址、是否被 `CC_CONNECT_URL` 鎖定、安裝 id、健康狀態，以及每條通道的來源（`own`、`connect` 或 `off`） |
| `cc_server connect enable`      | 使用 Control Center 代管的 Connect                                                                               |
| `cc_server connect enable --url <url>` | 使用位於該網址的自訂 Connect（HTTPS，或回送位址上的 `http`）                                              |
| `cc_server connect disable`     | 停止使用 Connect。只有伺服器自己的應用程式能讓人們登入                                                           |

不帶指令時預設為 `status`。每個指令都接受 `--data-dir`。`CC_CONNECT_URL` 會覆寫這些
指令所儲存的內容。未知的指令會以 `64` 結束。模式、安裝身分與狀態代碼請參閱
[Control Center Connect](/zh-TW/手冊/參考/connect/)。

### `update`

`--apply` 會取代目前的安裝；只要設定的連接埠上仍有伺服器在回應，該操作就會遭拒，
除非你傳入 `--force`。`--allow-downgrade` 允許降級至較舊的發行版本。

對於它並不擁有的安裝，這個指令會直接拒絕，並給出說明而不是錯誤：

| 環境                          | 偵測方式                                    | 顯示的說明                                                   |
| ----------------------------- | ------------------------------------------- | ------------------------------------------------------------ |
| 桌面版內嵌的伺服器            | `CC_EMBEDDED=1` 或 `CC_BOOTSTRAP_DEVICE_ID` | 請改為更新應用程式——安裝程式會替換整棵目錄樹                 |
| 以 `dart run` 執行的原始碼簽出 | 指令碼路徑以 `.dart` 結尾                   | 請用 git 更新                                                |
| Docker                        | 容器標記                                    | 拉取較新的映像                                               |

## 行程生命週期

`cc_server` 會一直執行，直到收到 `SIGINT` / `SIGTERM`。有一個額外的環境變數控制
這件事，而且它是由桌面版設定，而不是由你設定：

| 變數                     | 作用                                                                                                                                                                          |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CC_EXIT_WITH_PARENT=1`  | 當父行程結束時，伺服器也會結束；判斷方式是父行程關閉了它 stdin 管道的寫入端。桌面版會設定它，這樣應用程式當掉時，絕不會留下一個仍佔用資料目錄的孤兒伺服器                    |

只有在你把 `cc_server` 當作子行程監管，並想要獲得同樣保證時，才需要自行設定它。

`DO_NOT_TRACK=1`（空值、`0` 或 `false` 以外的任何值）會停止伺服器本身的[使用情況分析](/zh-TW/手冊/參考/使用情況分析/)，即使伺服器層級的開關已開啟也一樣。用戶端仍會遵循該開關。

## 資料目錄配置

預設資料目錄在 macOS 上是 `~/Library/Application Support/control-center`，
在 Windows 上是 `%APPDATA%\control-center`，在其他平台上則是
`$XDG_DATA_HOME/control-center`（否則為 `~/.local/share/control-center`）。只有
在無法解析出家目錄或應用程式資料目錄時，才會使用相對於目前工作目錄的
`.cc_server`。

伺服器會將資料目錄設為僅其自身帳號可存取（`0700`）。當它無法做到這點、`global.db` 已損壞或是由較新版本寫入，或是無法讀取其身分檔時，伺服器會拒絕啟動（結束代碼 `78`）。

| 路徑                              | 內容                                                                     |
| --------------------------------- | ------------------------------------------------------------------------ |
| `global.db`                       | 工作區註冊表、使用者、已配對裝置、新聞動態與機群佇列                      |
| `<workspaceId>/workspace.db`      | 每個工作區一個資料庫——代理、空間、工單、記憶                    |
| `<workspaceId>/code_index.db`     | 該工作區的程式碼圖。缺少時會被重建，從不備份 |
| `pre_upgrade/`, `<workspaceId>/pre_upgrade/` | 更新改變格式之前的資料庫副本，最新的兩份 |
| `<workspaceId>/chat_credentials/` | 聊天機器人權杖，以純文字 JSON 保存，因此會隨工作區一起移動                |
| `secrets.json`                    | 配對金鑰、Connect 安裝金鑰、供應商應用程式、人們的登入（透過 Connect 建立者為封存形式）、webhook 密鑰、SSO（`0600`） |
| `backups/<timestamp>/`            | 一份安裝快照——`manifest.json`、`global.db` 以及每個工作區的副本          |
| `backups/exports/`                | 單一工作區的匯出，`<workspaceId>-<timestamp>.db`                         |
| `backups/transfer/`               | 備份下載與上傳的暫存區；由寫入它的路由負責清理                           |
| `models/`                         | 裝置端的嵌入、語者分離與語音模型                                          |
| `codemode/` | 由 `scripts/natives/build_codemode.sh` 安裝的程式碼模式執行器開發用副本；發行套件會將其放在 `bin/codemode/` 中 |
| `meetings/<meetingId>/`           | 保留的會議音訊                                                           |
| `rigs/images/`                    | 匯入的機台磁碟映像（QEMU 桌面介面）                                       |
| `rigs/smolvm/<rigId>/`            | 每台機台的 microVM 執行階段狀態（仲介程式的密鑰，`0600`）                  |
| `rigs/smolvm-packs/`              | 預先解壓縮的機器套件——讓機台重複啟動變快的快取                           |
| `rigs/tls/`                       | 機台 HTTPS 用的開發網域憑證授權單位（金鑰為 `0600`）                       |
| `rigs/run/<rigId>/`               | QEMU 疊層、種子映像與每台 VM 的金鑰（`0600`）                              |
