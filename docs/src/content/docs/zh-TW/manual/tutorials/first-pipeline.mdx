## 你會建立什麼

完成本教學後，你將會有：

- 一個已儲存的管線範本，能以提示詞派發代理
- 範本上已啟用手動執行，因此可以手動啟動
- 一次已完成的執行，並可看到該步驟的輸入與輸出

前置條件：已完成[派送你的第一個代理](/zh-TW/手冊/教學/第一個代理/)，因此你已有一個配備配接器與模型的代理。

管線是由步驟組成的 DAG。範本定義這張圖；執行則是實際的運行。想了解它背後的模型，請閱讀[管線與自動化](/zh-TW/手冊/概念/管線/)；完整的步驟詞彙請參閱[管線步驟類型](/zh-TW/手冊/參考/管線步驟/)。

## 步驟 1：建立範本

1. 前往 **設定 → 工作區 → 管線範本**
2. 按下 **新增範本**

編輯器會開啟一個名為 **新增管線**（id `pipeline_N`）的預先植入骨架。
點擊頁首中的標題將它重新命名 —— 本教學中，
`code_quality_check` 是個好名字。這裡沒有 id 對話框，也沒有描述
欄位。

畫布並非空白。新範本會預先接成 **Trigger → Step →
終端**，其中「Step」是提示代理節點，而終端則是一個
不可見的哨兵，編輯器會把它重新接到每個可達的匯點。

你要設定的，就是已經在那裡的 Step 節點。

## 步驟 2：設定該步驟

1. 在畫布上點擊 **Step** 節點
2. 在右側的 **節點設定** 面板中設定：
   - **代理**：你在上一個教學中建立的代理
   - **提示範本**：「審查目前分支上的程式碼有無品質問題。列出你找到的問題。」
3. **Triggers from** 保持原狀 —— 這個節點已經接好線，會在 Trigger 之後觸發

## 步驟 3：儲存

在編輯器頁首按下 **儲存**。

**檢查點。**「有未儲存的變更」標示會消失。

## 步驟 4：允許手動執行

1. 點擊畫布上虛線的 **新增觸發器** 磚（或從節點庫的 **觸發器** 區段把
   **手動執行** 拖進來），然後選擇 **手動執行**。
2. 選取該節點。在右側的檢視器中開啟 **已啟用** ——
   「顯示在執行頁面並可手動啟動。」

這並非可有可無，而且很容易漏掉。新範本建立時**完全沒有任何觸發器資料列**，因此在開啟這個開關之前，執行頁面不會列出它，也沒有任何東西可以啟動。這個開關會立即寫入觸發器；它不會等待另一次儲存。

編輯器頁首的 **手動執行** 背後也是同一個開關，它就位於範本所宣告的輸入旁邊。

## 步驟 5：執行它

1. 在側邊欄點擊 **管線**
2. 在頁首按下 **執行管線**
3. 在左側欄挑選 `code_quality_check`
4. 在表單上按下 **執行管線** —— 你的範本沒有宣告任何輸入，因此沒有東西要填

**檢查點。** 畫面會以快顯通知確認執行已開始，Control Center 並會開啟執行詳情。

引擎會建立執行記錄、完成觸發器、排程該步驟、派發代理，並在終端的傳入分支完成時完成整次執行。

## 步驟 6：檢視結果

在該次執行中點擊該步驟，即可開啟它的詳細資料面板：

- **已開始** 與 **已結束** 時間戳，以及 **時長**
- **輸入**：傳入該步驟的狀態
- **輸出**：它所產生的結果 —— 在這裡就是代理的回應
- **代理活動**，並附有可連到該步驟所驅動對話的連結

**檢查點。** 該步驟顯示為已完成，而它的輸出載有代理的審查結果。

## 新增更多步驟

新增節點的方法，是把左側節點庫中的項目拖到畫布上，或是在某個節點之後
不遠處按下 **新增步驟**（`+`）。從節點的輸出埠拖曳到另一個節點即可把它們
連接起來，或者選取新節點，並在 **Triggers from** 底下勾選它的上游步驟。

終端節點不會被繪製出來，也無法被選取。編輯器會把它重新接到每個可達的
匯點，因此你在植入的 Step 之後新增的節點仍會執行。

## 回顧

你建立了範本、設定它預先植入的提示代理節點、儲存它、讓它可以手動執行、啟動了一次執行，並讀取了該步驟的輸入與輸出。

管線可以比這大得多 —— 條件路由器、並行分支、匯合節點、for-each 扇出、人工閘門 —— 但形狀永遠不變：DAG 中的步驟，傳遞狀態。
