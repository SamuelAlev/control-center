## 你將完成什麼

讀完這份教學後，你將完成：

- 在 Control Center 的 PR 工作台開啟一個 pull request
- 閱讀它的差異，並留下一則行內留言
- 提交一個檢閱判定
- 合併該 PR

前置條件：[派送你的第一個代理](/zh-TW/手冊/教學/第一個代理/)已完成，且本工作區中已註冊的儲存庫上有一個開啟中的 pull request。進行檢閱步驟時，請挑一個不是你開啟的 PR——**檢閱**按鈕在你自己開啟的 PR 上會隱藏。合併在你自己撰寫的 PR 上仍然可用。

## 步驟 1：開啟 pull request

1. 在側邊欄中點擊 **Pull requests**
2. 找到你的 PR 並點擊它

**檢查點。** PR 會以分頁式工作台開啟——總覽、Diff、原始檔控制、聊天、動作——並聚焦於**總覽**：標題與動作、描述與活動時間軸，以及一個列出狀態、檢閱者、指派對象、檢查與變更檔案的側邊欄。點擊那裡的某個檔案，會跳至 Diff 分頁中的該檔案。除非有人要求 AI 檢閱，否則**檢閱**分頁不會開啟。

:::note[佇列是空的，並提示「連接 GitHub」]
這個狀態表示_伺服器_並未持有 GitHub 權杖——你的用戶端永遠不會持有。請在**設定 → 工作區 → 個人資料與身分 → 程式碼託管**中設定一組，然後重新整理清單。
:::

## 步驟 2：閱讀差異

開啟 **Diff** 分頁。左側是可折疊的檔案樹，差異上方的長條帶有提交範圍選擇器——可將差異縮小到單一提交或一段提交——以及檔案數量與持續累計的新增和刪除行數。

差異工具列中的設定按鈕控制它的呈現方式：

- **並排**或**整合**檢視
- **自動換行**或捲動長行
- **程式碼字型連字**

將檔案標示為已檢視，即可在大型差異中追蹤你的進度。鍵盤導覽請見[鍵盤快捷鍵](/zh-TW/手冊/參考/鍵盤快捷鍵/)。

## 步驟 3：留下行內留言

1. 將游標懸停在差異中的某一行——行號欄會出現一個小小的 `+` 膠囊按鈕
2. 點擊它即可在該行留言，或先垂直拖曳它來選取一段範圍
3. 輸入你的意見回饋。撰寫框提供兩種提交方式：
   - **開始檢閱**（若已有檢閱正在進行，則為**加入檢閱**）會將留言排入佇列。在你於步驟 4 提交判定之前，討論串會顯示**待送出的檢閱**。
   - **新增單則留言**會立即發佈到 GitHub。討論串會顯示**正在發佈…**，接著是**已同步**，並在發佈失敗時提供重試。

本教學請使用**開始檢閱**，讓留言隨判定一起送出。

:::caution[已排入佇列的留言尚未發佈到 GitHub]
**開始檢閱** / **加入檢閱**會把留言保留在本機，直到你提交判定。只有**新增單則留言**會立即發佈。你在步驟 4 撰寫的檢閱_內文_是一份獨立的草稿。
:::

## 步驟 4：提交檢閱

1. 在**總覽**的操作列中點擊**檢閱**——同一個按鈕也位於 Diff 分頁的工具列中。在你自己撰寫的 PR 上，以及已關閉或已合併的 PR 上，它都會隱藏。
2. 在撰寫框中寫一段摘要。它會自動儲存為草稿，因此你可以關閉浮層，稍後再回來。
3. 選擇一個判定：
   - **要求變更**
   - **留言**
   - **核准**

判定_就是_按鈕。按下**核准**或**要求變更**後，按鈕會自行改標為**已核准**或**請求的變更**。**留言**判定則讓按鈕維持**檢閱**標籤。

**檢查點。** 若你選擇了前述兩者之一，按鈕會顯示「已核准」或「請求的變更」。

## 步驟 5：合併

只要 GitHub 回報該 PR 可合併，**合併**按鈕就會出現——它並不以你自己的核准為前提。它的顏色代表的是就緒程度而非權限：必要核准與檢查全數通過時為主要色，仍有檢查在執行時為次要色，被要求的檢閱者尚未核准或某項檢查失敗時為破壞性色。

1. 點擊**合併**
2. 選擇一種方式：**Squash 並合併**、**建立合併 commit**或**Rebase 並合併**
3. 前兩種可編輯已預填的提交標題與訊息
4. 確認

任何尚未解決的問題——「檢查失敗」、「有待處理的審查」——都會在確認前列在彈出面板中。

:::caution[合併不可逆]
合併會將提交推送到 GitHub。它永遠不會進入 Control Center 的復原堆疊，也無法從這裡復原。
:::

合併之後，會觸發一個 `PrMerged` 領域事件；分析與通知會取用它。其他監聽者請見[領域事件](/zh-TW/手冊/參考/領域事件/)。

## 使用 AI 審查

Control Center 可以為開啟中的 PR 配置一條審查者管線，但只在你提出要求時才會：`pr_review` 範本只有手動觸發器，別無其他。

1. 打開**總覽**操作列中的溢出選單，選擇**詢問 AI**。Control Center 會啟動該次執行並開啟**檢閱**分頁，讓你可以看著各位專家工作。
2. 審查代理會把他們的發現記錄成該 PR 空間中的審查節點；最後一個步驟會將它們彙整成一份報告。

這條管線刻意不發佈到 GitHub——它在彙整後就結束。發佈是你自己另外執行的步驟，使用**檢閱**分頁上的**發佈到 GitHub**按鈕。請見[使用 AI 審查](/zh-TW/手冊/操作指南/ai-審查/)。

## 回顧

你在工作台開啟了一個 PR、閱讀帶有語法高亮的差異、留下一則行內留言、提交了判定並合併——全程沒有離開應用程式。
