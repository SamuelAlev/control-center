本指南說明如何將外部 MCP 用戶端（Claude Code、編輯器、MCP Inspector）連線至
Control Center 自身的工具伺服器。

Control Center 註冊了 **110** 個工具，並以 Model Context Protocol、通訊協定版本
`2024-11-05` 提供這些工具。你可能預期會有的整類工具並未提供：這裡沒有會議或
日曆工具，也沒有專案工具。

## 尋找端點

MCP 介面共用主要的 `cc_server` 監聽器。沒有另外獨立的 MCP 連接埠。

| 端點     | 方法     | 用途                                                     |
| -------- | -------- | -------------------------------------------------------- |
| `/mcp`   | `POST`   | Streamable HTTP 傳輸——這正是用戶端所用的通訊方式         |
| `/mcp`   | `DELETE` | 結束工作階段                                             |
| `/sse`   | `GET`    | 伺服器推送的通知串流                                     |

因此，預設的本機安裝位於 `http://127.0.0.1:9030/mcp`。

1. 前往 **設定 → 伺服器 → MCP 伺服器**
2. 查看 **MCP 伺服器**卡片——它會顯示執行中或已停止，以及正在監聽的連接埠

全新安裝時，這組介面預設為開啟。只有伺服器擁有者能看到卡片上的權杖，也只有他們能啟動或停止端點。**應用程式啟動時開始**控制它是否在重新啟動後回復；**開始**／**停止**是工作階段控制項，不會變更該偏好設定。

伺服器預設繫結至回送位址，因此除非你以 `--bind any` 啟動它，否則只有執行
`cc_server` 的機器能連上該端點。

## 取得權杖

每個要求都需要伺服器的 MCP 權杖，無論來自哪台機器，包括回送在內。伺服器會在首次啟動時建立它。沒有辦法將它關閉，也沒有辦法清除它。

1. 在 **設定 → 伺服器 → MCP 伺服器**中，找到**驗證權杖**列
2. 按下**顯示權杖**並複製它
3. 若要替換它，請按下**輪替權杖**。伺服器會立即切換到新權杖，而所有仍使用舊權杖的用戶端都會被拒絕，直到你把新權杖交給它們

## 連線用戶端

將你的用戶端指向 Streamable HTTP 端點，並在每個要求中以 `Authorization: Bearer <token>` 送出權杖，包括 `GET /sse`。沒有其他傳送方式：URL 中的權杖不被接受。確切的設定格式由你的用戶端決定。

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code 不會從專案的 `.mcp.json` 讀取這項設定——它會把專案範圍的 MCP 伺服器
擋在核准提示之後，而非互動式的 `claude -p` 永遠不會回應該提示。請明確傳入設定：

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` 會讓 Claude 只使用該檔案，因此同一個伺服器不會又從專案被
探索到而註冊兩次。

檢查點：請用戶端列出它的工具。你應該會看到 `mcp__*` 項目，涵蓋工單、空間、
記憶、程式碼圖與審查。

## 端點會拒絕什麼

權杖會開啟伺服器上的每一個工具，因此端點也會拒絕網頁可能送出的任何內容，並且在檢查權杖之前就先行拒絕：

| 要求                                                                    | 回應   |
| ----------------------------------------------------------------------- | ------ |
| 不是本機上網頁的 `Origin` 標頭（`http://localhost`、`http://127.0.0.1` 或 `http://[::1]`，任何連接埠） | `403`，"Cross-origin requests are not accepted" |
| 既不是此監聽器的回送位址與連接埠、也不是伺服器公開主機名稱的 `Host` 標頭 | `403`，"Unknown host" |
| 內容不是 `application/json` 的 `POST`                                   | `415`  |
| 沒有權杖，或權杖錯誤                                                    | `401`  |

要在主機之外提供 MCP 服務，請以 `--bind any` 啟動伺服器，並從另一台機器送出權杖，以伺服器的公開主機名稱來定址它。

## 將每次呼叫限定於某個工作區

每個會觸及工作區範圍資料的工具都需要 `workspace_id`，缺少它的呼叫會遭到拒絕，
而不是對某個「目前」工作區進行解析：

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

這個 id 就是你瀏覽器或應用程式 URL 中的那個：`/workspaces/<workspace_id>/…`。唯一
的例外是真正橫跨多個工作區的工具，例如 `list_workspaces` 與新聞動態工具——新聞
動態是依使用者區分，而代理沒有自己的使用者，因此這些工具會針對伺服器擁有者的
動態運作。

儲存庫範圍的工具會額外檢查該儲存庫是否已連結至該工作區。

## 了解介面會拒絕哪些項目

- **模式閘控。** 呼叫會在伺服器端依據發出呼叫之代理所在空間的模式進行解析。處於
  唯讀模式的代理無法藉由省略 `space_id` 觸及寫入工具——模式會改從它進行中的
  執行查得。
- **動作護欄。** 具變更性的工具會宣告其效果類別，並套用產品其他部分使用的同一套
  政策。請參閱[設定護欄](/zh-TW/手冊/操作指南/設定護欄/)。
- **確認。** 某些具破壞性的工具會建立確認承載內容，必須先獲得核准，呼叫才會
  繼續。

完整目錄會在 `tools/list` 中公告，且沒有探索閘控——外部 MCP 用戶端會拒絕呼叫不在
其快取清單中的工具，因此隱藏工具只會讓它們損壞，而不是讓它們更井然有序。

## 代理使用的 MCP 伺服器

本指南說明的是 Control Center 自己的端點。另一個方向是 Control Center 所連接、並交給其執行之代理使用的 MCP 伺服器。你可以在 **設定 → 伺服器 → MCP 伺服器** 下，以兩個層級進行設定：為整個工作區，或為你自己。無論哪一層，Control Center 都會連接伺服器本身，並把它的工具交給執行環境使用，因此內建 harness 與 Claude Code 取得的是相同的工具與相同的核准提示。Claude Code 的執行會在 `control-center` 伺服器下看到這些工具，名稱為 `mcp__control-center__mcp__<server>__<tool>`。

### 工作區伺服器

工作區管理員在 **工作區 MCP 伺服器** 中新增這些伺服器。工作區中的每次代理執行都會取得它們的工具，其他工作區的執行則不會。

1. 選取 **新增伺服器**，並為它取一個簡短的名稱：英文字母、數字、`-` 與 `_`，最多 24 個字元。工具會以 `mcp__<name>__<tool>` 的形式出現。
2. 選擇連線方式：
   - **命令（stdio）：** 一個可執行檔及其引數，以及它所需的任何環境變數。
   - **URL（HTTP 或 SSE）：** 端點，以及它所需的任何標頭，例如 `Authorization: Bearer …`。
3. 儲存。檢查點：伺服器會顯示 **已連線** 及工具數量。

環境變數與標頭的值會儲存在伺服器的密鑰檔案中，之後不會再顯示。要變更某個值，請將其取代；要移除，請刪除其名稱。

命令會以伺服器本身的使用者身分在伺服器所在的機器上執行，因此在伺服器擁有者核准之前不會啟動。在核准之前，它會顯示 **等待核准**。URL 伺服器可立即使用，但在伺服器擁有者核准之前，它只能連到公開位址；核准後才允許 `localhost` 與私有網路。伺服器擁有者儲存伺服器即視為核准。若其他人變更了伺服器的啟動方式或連線位置，則需要重新核准。啟用或停用伺服器不會影響其核准狀態。

### 你自己的伺服器

每位成員都在 **你的 MCP 伺服器** 中，使用同一份表單新增自己的伺服器。它們在本工作區中只屬於你：其他成員看不到它們，而你登入過的伺服器會以你的身分行事。

- 只有你在本工作區啟動的執行才會取得它們的工具。這同時涵蓋內建 harness 執行與 Claude Code 執行。
- 其他成員的執行、沒有人啟動的自動化，以及你在其他工作區的執行，都不會取得其中任何一個。在那些執行中，這些工具不會被列出、無法被呼叫，也不會出現在工具搜尋中。
- 你的伺服器可以與某個工作區伺服器同名。在你的執行中，使用的是你自己的那一個。
- 你自己的伺服器以 URL 連線，且只能連到公開位址。只有伺服器擁有者才能新增一個會執行命令的自有伺服器。

你的伺服器與工作區伺服器都不會提供給 MCP 權杖或已配對的裝置，其資源與提示也不會被轉交。

### 登入伺服器

要求登入的 URL 伺服器會顯示 **需要授權**。

1. 在伺服器上選取 **登入**。你的瀏覽器會開啟該伺服器自己的登入頁面。
2. 在該頁面核准請求。瀏覽器會回到 Control Center 並顯示一組代碼。
3. 在應用程式中輸入代碼。檢查點：伺服器顯示 **已連線**。

登入資訊會與為其而設的那個伺服器一併儲存。登入工作區伺服器需要工作區管理員，之後工作區中的每次執行都會以已登入的帳號身分行事。登入你自己的伺服器只影響你的執行。移除伺服器也會一併移除其登入資訊。

## 疑難排解

### 用戶端看不到任何工具

- 檢查 **MCP 伺服器**卡片顯示為執行中
- 檢查連接埠是否符合你的 `cc_server` 連接埠
- 在 Claude Code 上，檢查你是否傳入了 `--mcp-config` 與 `--strict-mcp-config`

### 401 Unauthorized

要求沒有帶權杖，或帶的是舊權杖。請從**驗證權杖**列複製目前的權杖，並以 `Authorization: Bearer <token>` 送出。URL 中的權杖會被忽略。

### 曾經可用的用戶端收到 403

要求帶有來自網頁的 `Origin`，或伺服器不回應的 `Host`。請從用戶端而非瀏覽器頁面呼叫端點，並使用伺服器的回送位址或其公開主機名稱。

### 415 Unsupported Media Type

請以 `application/json` 傳送 `POST /mcp` 的內容。

### 工具呼叫失敗並顯示 "Missing or invalid argument: workspace_id"

請加入 `workspace_id`。沒有隱含的工作區。

### 工具呼叫因不明而遭到拒絕

[MCP 工具](/zh-TW/手冊/參考/mcp-工具/)列出了目錄。請完全依照該處顯示的名稱來
呼叫。
