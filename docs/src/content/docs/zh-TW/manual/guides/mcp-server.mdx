本指南說明如何將外部 MCP 用戶端（Claude Code、編輯器、MCP Inspector）連線至
Control Center 自身的工具伺服器。

Control Center 註冊了 **110** 個工具，並以 Model Context Protocol、通訊協定版本
`2024-11-05` 提供這些工具。你可能預期會有的整類工具並未提供：這裡沒有會議或
日曆工具，也沒有專案工具。

## 尋找端點

MCP 介面共用主要的 `cc_server` 監聽器。沒有另外獨立的 MCP 連接埠。

| 端點     | 方法     | 用途                                                     |
| -------- | -------- | -------------------------------------------------------- |
| `/mcp`   | `POST`   | Streamable HTTP 傳輸——這正是用戶端所用的通訊方式         |
| `/mcp`   | `DELETE` | 結束工作階段                                             |
| `/sse`   | `GET`    | 伺服器推送的通知串流                                     |

因此，預設的本機安裝位於 `http://127.0.0.1:9030/mcp`。

1. 前往 **設定 → 伺服器 → MCP 伺服器**
2. 查看 **MCP 伺服器**卡片——它會顯示執行中或已停止，以及正在監聽的連接埠

全新安裝時，這組介面預設為開啟，因此回送用戶端無須動到任何設定即可運作。
**應用程式啟動時開始**控制它是否在重新啟動後回復；**開始**／**停止**是工作階段
控制項，不會變更該偏好設定。

伺服器預設繫結至回送位址，因此除非你以 `--bind any` 啟動它，否則只有執行
`cc_server` 的機器能連上該端點。

## 連線用戶端

將你的用戶端指向 Streamable HTTP 端點。確切的設定格式由你的用戶端決定；無論
哪種方式，URL 都相同。

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp"
    }
  }
}
```

### Claude Code

Claude Code 不會從專案的 `.mcp.json` 讀取這項設定——它會把專案範圍的 MCP 伺服器
擋在核准提示之後，而非互動式的 `claude -p` 永遠不會回應該提示。請明確傳入設定：

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` 會讓 Claude 只使用該檔案，因此同一個伺服器不會又從專案被
探索到而註冊兩次。

檢查點：請用戶端列出它的工具。你應該會看到 `mcp__*` 項目，涵蓋工單、空間、
記憶、程式碼圖與審查。

## 在主機之外提供 MCP 服務

1. 在 **設定 → 伺服器 → MCP 伺服器**的 **驗證權杖**列上，按下**設定**並貼上權杖
2. 在每個 `POST /mcp` 要求中，以 `Authorization: Bearer <token>` 傳送它

未設定權杖的介面會以 403 拒絕任何非回送的呼叫者。這是刻意採取的失效即關閉
設計：權杖正是讓主機外的服務得以成立的原因。

權杖變更會立即套用至執行中的介面——無須重新啟動。

:::note[`GET /sse` 會在查詢字串中接收權杖]
通知串流和其他所有路由一樣會檢查權杖，但瀏覽器的 `EventSource` 無法傳送
`Authorization` 標頭——因此 `/sse` 也接受以 `?token=<token>` 形式傳入的權杖。
若未提供，它會回應 401。
:::

## 將每次呼叫限定於某個工作區

每個會觸及工作區範圍資料的工具都需要 `workspace_id`，缺少它的呼叫會遭到拒絕，
而不是對某個「目前」工作區進行解析：

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

這個 id 就是你瀏覽器或應用程式 URL 中的那個：`/workspaces/<workspace_id>/…`。唯一
的例外是真正橫跨多個工作區的工具，例如 `list_workspaces` 與新聞動態工具——新聞
動態是依使用者區分，而代理沒有自己的使用者，因此這些工具會針對伺服器擁有者的
動態運作。

儲存庫範圍的工具會額外檢查該儲存庫是否已連結至該工作區。

## 了解介面會拒絕哪些項目

- **模式閘控。** 呼叫會在伺服器端依據發出呼叫之代理所在空間的模式進行解析。處於
  唯讀模式的代理無法藉由省略 `space_id` 觸及寫入工具——模式會改從它進行中的
  執行查得。
- **動作護欄。** 具變更性的工具會宣告其效果類別，並套用產品其他部分使用的同一套
  政策。請參閱[設定護欄](/zh-TW/手冊/操作指南/設定護欄/)。
- **確認。** 某些具破壞性的工具會建立確認承載內容，必須先獲得核准，呼叫才會
  繼續。

完整目錄會在 `tools/list` 中公告，且沒有探索閘控——外部 MCP 用戶端會拒絕呼叫不在
其快取清單中的工具，因此隱藏工具只會讓它們損壞，而不是讓它們更井然有序。

## 疑難排解

### 用戶端看不到任何工具

- 檢查 **MCP 伺服器**卡片顯示為執行中
- 檢查連接埠是否符合你的 `cc_server` 連接埠
- 在 Claude Code 上，檢查你是否傳入了 `--mcp-config` 與 `--strict-mcp-config`

### 從非伺服器所在的機器收到 403

未設定 Bearer 權杖。請設定一個並傳送它。

### 工具呼叫失敗並顯示 "Missing or invalid argument: workspace_id"

請加入 `workspace_id`。沒有隱含的工作區。

### 工具呼叫因不明而遭到拒絕

[MCP 工具](/zh-TW/手冊/參考/mcp-工具/)列出了目錄。請完全依照該處顯示的名稱來
呼叫。
