工作區中的代理可以彼此提問、諮詢專家、要求檢閱、傳送訊息，或委派工單。這一切都不需要代理坐著等待：提出問題的代理可以繼續工作，或結束這一輪，並在答覆送達時於自己的對話中被喚醒。

## 向其他代理提問

代理以 `ask_agent` 提問，方式有兩種：

- **等待**（預設）：代理會阻塞，直到答覆送達，預設最長 600 秒，最多 1,800 秒。
- **在背景進行**：呼叫會立即返回，代理繼續工作。

無論哪一種方式，問題都會在送出前先被記錄。若答覆未能在該次呼叫中送回，提問者會在其他代理的執行結束時被喚醒一次，並帶著答覆：可能是已回覆、失敗，或 24 小時後仍無答覆而過期。在這之前，提問者可能各會收到一次以下訊息：其他代理已承諾稍後回覆、正在等待人員處理，或在用量上限處停止。這些都不算答覆。

`consult_agent`（找出最符合的專家）、`request_peer_review`（對檢閱發現再做一次檢視）與 `send_to_agent`（單向訊息）都透過同一個佇列運作。`send_to_agent` 會說明對方代理是否已被喚醒、訊息是否排在其目前的執行之後等待，或為何被拒絕。

對方代理會將問題視為來自另一個代理的資訊，而非必須遵從的指令，且它不能執行斜線指令。

## 移交工作

- **委派的工單**（`delegate_task`）會在工單結算時，喚醒委派它的代理，並回到其委派的對話中。
- **團隊成員的執行**，若由領導者以 `@mention` 或訊息啟動，會在其結束時喚醒領導者，並回到喚醒該成員的對話中。（提問以其答覆為準，委派的工單則以其工單為準。）
- **背景工作程序**在指揮者模式（`/vibe`）中，會將其結果交給指揮者，而指揮者會繼續工作。
- **一個 `@mention`**，以及空間的檢查器，都會以喚醒的方式傳送。

代理可以在不提問的情況下查看另一個代理正在做什麼：`agent_activity` 會顯示對方代理的狀態、其目前的工具與其最近的訊息，且不會喚醒任何人。

## 限制

無論代理怎麼說，伺服器都會強制執行以下限制：

| 限制 | 數值 |
| --- | --- |
| 提問與移交構成的鏈可以延伸多深 | 3 |
| 循環（一個代理向另一個代理提問，而該代理經由其他代理正在等待它） | 拒絕 |
| 每個提問代理的待處理提問數 | 10 |
| 每個被提問代理的待處理提問數 | 20 |
| 對同一個代理再次提出同一個問題 | 10 分鐘內拒絕 |
| 一對代理之間的訊息 | 每分鐘 10 則 |
| 訊息或答覆的長度 | 16,384 個字元 |

移交工作也會遵守提問代理的自主權與預算：代理不能把工作交給自主權或金錢比它更高的另一個代理。你自己傳送的訊息則永遠不受此限制。

當被提問的代理在供應商的用量上限處停止時，若重設時間早於問題過期，其執行會等待重設。否則問題會立即失敗，並告知提問者原因。

## 查看代理在等待什麼

在對話中，**一般** 面板的 **提問** 區段會列出其他代理向該代理提出的問題：對象是誰、種類（**問題**、**諮詢** 或 **檢閱**）、時間，以及狀態（**等待中**、**已回覆**、**失敗**、**已過期** 或 **已取消**），並在適用時顯示 **已承諾稍後回覆** 或 **在背景進行**。失敗的提問會說明原因，例如 **其執行在供應商的用量上限處停止。**

任何可以存取該空間的人都可以 **取消提問**。提問的代理不會因此被喚醒，對方代理的執行也不會被停止。

等待代理的答覆、訊息與完成的工作，也會出現在輸入框上方的列中，並附上該代理正在等待的其他項目（見[排程與喚醒](/zh-TW/手冊/操作指南/排程與喚醒/#查看等待中的項目)）。
