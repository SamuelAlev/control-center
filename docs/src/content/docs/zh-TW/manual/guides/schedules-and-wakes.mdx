代理等待時不會休眠，也不會不斷輪詢。代理或你可以設定一個**喚醒**：這是一個持久的請求，會在某個時間或某件事發生時，於對話中啟動或繼續代理的執行。凡是伺服器在沒有人輸入的情況下啟動的執行，都以喚醒開始：目標的下一個分段、排程、監看、其他代理的回覆、已委派工作的完成、用量上限的結束，或重新啟動後遺留的工作。喚醒保存在工作區的資料庫中，因此在重新啟動後仍會保留。

## 自行為代理排程

在對話的輸入框中輸入以下其中一個指令：

```text
/loop every 30m --days 3 check the deploy and fix what broke
/loop keep the flaky tests green
/schedule in 2h look at the overnight benchmark
/schedule at 09:00 summarize what changed overnight
/schedule cron "0 9 * * 1-5" --max 20 triage new tickets
```

| 指令 | 作用 |
| --- | --- |
| `/loop every <interval> <prompt>` | 立即以該提示喚醒代理，之後每隔一段時間（每次至少相隔 60 秒）再次喚醒 |
| `/loop <prompt>` | 自行安排節奏的迴圈：立即喚醒代理，之後每次執行結束時，代理會自行選擇下一次的延遲，為 1 到 60 分鐘（預設 20 分鐘） |
| `/schedule in <duration> <prompt>` | 在延遲時間過後喚醒代理一次 |
| `/schedule at <HH:MM or ISO time> <prompt>` | 喚醒代理一次。`HH:MM` 為工作區時區中的下一個該時間；沒有時差的 ISO 時間則以 UTC 為準 |
| `/schedule cron "<expression>" <prompt>` | 依工作區時區解讀的五欄位 cron 運作，喚醒代理。引號可省略 |

- `--max <N>` 限制執行次數，`--days <N>` 會在指定天數後結束排程（預設 30 天，最多 365 天），`--budget <dollars>` 限制排程總共可以花費的金額（否則為工作區的預設值，起始為 50 美元）。
- `/loop` 會立即執行第一次。`/schedule` 會等待其指定的時間。
- 時間長度使用 `s`、`m`、`h` 與 `d`，例如 `90s`、`20m` 或 `1h30m`。
- 只有你自己輸入的訊息才會讀取這些指令。

輸入區會幫你撰寫它們。在 `/loop` 或 `/schedule` 與一個空格之後，建議清單會提供觸發時機，並隨你輸入而縮小範圍；在時間之後輸入 `--` 可看到限制選項。按 Enter 或 Tab 會選取一列，但不會送出任何內容。之後，輸入區上方的一行文字會回讀該指令：何時觸發、何時結束，以及還缺少什麼。若你在無法讀取的指令上按 Enter，該行會說明問題所在，而你的草稿會保留。

你也可以在 **排程** 頁面按下 **新增排程** 來建立排程：選擇空間、對話與代理，設定何時觸發、每次執行從什麼開始、結束條件、執行次數上限與花費上限。**如果代理忙碌** 用來選擇略過該次觸發，或等到代理空閒為止。**每次觸發時** 用來選擇開始執行，或只透過附註通知你。

## 代理會自行設定的項目

代理會使用 `wake_me` 工具處理同樣的事項，以及監看：

| 監看 | 觸發時機 |
| --- | --- |
| `on:pr_checks` | 空間的 PR 完成驗證時 |
| `on:pr_review` | 空間的 PR 收到檢閱或回覆時 |
| `on:pr_merged` | 空間的 PR 被合併時 |
| `on:environment` | 空間環境的某個工作結束，或環境變為就緒時 |
| `on:ticket:<id>` | 某張工單結算完成時 |
| `on:pipeline_run:<id>` | 管線執行結束時 |

- PR 監看會接收空間自身的 PR，或其指定的某一個 PR（`on:pr_checks:acme/shop-ui#12`）。若對某項內容的監看，其所屬人員無法讀取，該監看會被拒絕。
- 代理自己的動作不會觸發它的監看。代理工作期間到達的事件不會遺失：它會等到執行結束，之後的事件會併入同一個喚醒。
- 代理的排程必須設定執行次數上限或結束時間。預設在 7 天後結束，最多 30 天。監看預設執行 10 次。
- 代理在其自己某個排程所啟動的執行中設定的排程，會與第一個排程共用結束時間、執行次數上限與花費上限，因此代理的一連串連鎖排程不會比第一個更久。刪除第一個排程會結束整條連鎖；暫停它則只暫停該排程。連鎖透過其他代理啟動的執行，會計入同一個花費上限。你建立的排程不會開始任何連鎖：代理在其執行中設定的內容，其限制與它在你的訊息之後設定的任何內容相同。
- 代理以 `list_wakes` 列出其等待中的項目，並以 `cancel_wake` 取消自己設定的項目。它無法取消你設定的項目。

## 查看等待中的項目

**在輸入框上方。** 當對話中有喚醒正在等待代理時，會顯示一列：**N 個等待中的喚醒**、每個喚醒的來源（**目標**、**排程**、**監看**、**來自某個代理的回覆**、**用量上限已重設**、**復原**，…）、其到期時間，以及它被保留的原因。

| 按鈕 | 作用 | 誰可以 |
| --- | --- | --- |
| **立即傳送** | 立即傳送一個等待中的喚醒 | 只有該喚醒所代表的人 |
| **繼續** | 釋出一個被保留的喚醒 | 只有該喚醒所代表的人 |
| **取消喚醒** | 取消它 | 任何可以存取該空間的人 |

未被傳送的喚醒會在對話中留下一列，說明原因，例如 **此代理已暫停。** 或 **預算阻擋了執行。**

**排程頁面。** 側邊欄 → **排程** 會列出你可以看到的每個排程與監看，並依狀態分組；cron 排程會以你的時區顯示其接下來三次的時間。開啟其中一項，即可看到其附註、擁有者、接下來的觸發、執行、略過、花費與結束時間，以及 **最近的喚醒與執行**。每個排程都有自己的位址（`/workspaces/<workspace>/schedules/<id>`）。

| 動作 | 誰可以 |
| --- | --- |
| **暫停**、**刪除** | 任何可以存取該空間的人 |
| **繼續**、**延長** | 只有其擁有者（若為代理在無人參與的情況下建立的排程，則為工作區管理員） |

當排程的擁有者以外的人暫停它時，對話會顯示一列，列出該人的名字。

在手機上，目標畫面的 **重複執行** 會啟動一個重複的提示（每隔若干分鐘或小時，或自行安排節奏），並可設定花費上限與結束時間；**排程** 畫面則可暫停、繼續與刪除排程。對話的進度檢視會顯示等待中的項目，包括用量上限造成的暫停（**立即繼續**、**取消**），以及伺服器停止後遺留的工作。

## 排程如何執行

- 排程或監看的每次執行上限為 5 美元，若排程剩餘的額度較少，則以剩餘額度為上限，排程會在達到其花費上限時停止。
- 排程時間落在時鐘向前跳時被跳過的那個小時內，當天會延後一小時執行（02:30 會在 03:30 執行）。落在時鐘向後跳時重複出現的那個小時內的時間，只會執行一次。
- 排程的執行絕不會併入已在進行中的執行。若定時排程觸發時代理忙碌，該次觸發會被靜默略過，除非該排程設定為等待代理空閒。
- 排程或監看啟動的執行若順利結束，不會通知你，除非其中提到了某人。排程結束時，通知鈴會說明原因（**已用完其執行次數。**、**已達到結束日期。**，…），且不發出聲音。
- 一個對話中由喚醒啟動的執行，每小時最多 30 次；整個工作區則最多 300 次。
- 排程所代表的人員離開工作區時，該排程會結束。其他代表該人員行事的項目也會一併停止：他們等待中的喚醒會被取消，他們排入佇列與保留的訊息會被刪除，而他們正在執行的代理會被停止。

## 停止、重新啟動與用量上限

- **停止。** 在代理的執行中按下 **停止**，會保留其等待中的喚醒（不屬於目標的喚醒），以及你為它排入佇列的訊息。它們會等待 **繼續** 或 **傳送保留的訊息**。每個人只傳送自己保留的訊息，沒有人能代傳他人的保留訊息。
- **伺服器重新啟動。** 喚醒與排程都會保留。由喚醒啟動的執行會在重新啟動後接續進行，最多嘗試 3 次。由你自己啟動的執行不會自行再次執行：它會留下一個被保留的 **復原** 喚醒，並在你按下 **繼續** 後接續進行。若定時排程在伺服器關閉期間錯過了應執行的時間點，只有在很短的寬限期內（其間隔的一半，最多 10 分鐘；一次性排程為 24 小時）才會延後觸發，否則只記錄一次略過：**伺服器關閉期間錯過。**
- **供應商的用量上限。** 當執行在供應商的用量上限處停止，且供應商說明重設時間（7 天之內），該執行會暫停。由伺服器啟動的執行，例如目標的分段或排程的執行，會在重設後 30 秒自動繼續。對於你自己啟動的執行，它會等待你：對話會顯示 **已在** 供應商的 **用量上限。用量上限將於** 某個時間重設，並附上 **繼續**（只有你能按）與 **取消**（空間中的任何人皆可）。按下 **繼續** 後，它會在用量上限重設後繼續。你未繼續的暫停會在重設後 7 天過期。在上限時你排入佇列的訊息，會送入繼續後的執行；若該執行沒有等待重設，或暫停被取消或過期，這些訊息則改為保留給你，並列於 **傳送保留的訊息** 之下。其他人排入佇列的訊息會立即為他們保留。排程的下一次觸發會等待暫停的執行繼續。ACP 代理不回報重設時間，因此其執行不會等待。

## 工作區限制

工作區管理員可在 **設定 → 工作區 → 排程** 下設定限制：

- **排程限制**：一個代理在一個對話中可持有的有效或暫停排程數量（10 個）、在工作區各處（50 個），以及在整個工作區中（500 個）；排程預設的花費上限（50 美元）；以及 cron 排程與每日摘要所使用的時區（起始為 UTC）。
- **無人回應時**：伺服器啟動的執行等待人員回覆或核准的時間（預設 72 小時，可設定為 1 小時至 7 天），之後核准視為拒絕，問題視為未回覆（之後，同一執行再提出的任何其他問題都會立即被拒絕）；此外也設定每日摘要（列出你在目標、排程及其他由伺服器啟動的執行中等待處理的事項）的時間。

成員只能唯讀檢視此頁面。
