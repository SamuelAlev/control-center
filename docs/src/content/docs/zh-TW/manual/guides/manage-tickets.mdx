本指南說明如何建立與管理工單。

## 建立工單

### 透過 UI

1. 在工作區側邊欄中點擊**工單**。
2. 按下**新增工單**。
3. 填寫：
   - **標題** —— 簡短摘要。這是唯一必填的欄位。
   - **描述** —— Markdown，附有格式工具列。
   - **狀態** —— **待辦**（預設）或**待處理**。已啟動與終止狀態是透過
     生命週期到達，而不是在建立時設定。
   - **優先順序** —— 無、緊急、高、中或低。
   - **負責人** —— 你自己，或工作區中的任何代理。
   - **專案** —— 選填的分組。
4. 按下**建立**，或先開啟**建立更多**，讓對話方塊保持開啟以便快速連續輸入。

對話方塊中沒有供應商選擇器。工單會建立到工作區目前生效的工單供應商上。

### 透過代理

在空間中請代理：

> 為慢速連線上的登入逾時問題建立一張工單。

它會呼叫 `create_ticket` MCP 工具。該工具上的優先順序是**整數**，而不是名稱：

```
create_ticket(
  workspace_id: "...",
  title: "Fix login timeout on slow connections",
  description: "...",
  priority: 2
)
```

| 值    | 優先順序 |
| ----- | -------- |
| `0`   | 無       |
| `1`   | 緊急     |
| `2`   | 高       |
| `3`   | 中       |
| `4`   | 低       |

只有 `workspace_id` 和 `title` 是必填的；`description`、`priority`、
`assignee`（代理 id）和 `team_id` 都是選填的。該工具被歸類為供應商同步寫入，
執行前會請求你核准。

## 更新工單狀態

工單遵循以下生命週期：

```
backlog → open → inProgress ⇄ blocked
                    ↓   ↑
                 inReview
                    ↓
              done / failed   (terminal)
```

`done`、`failed` 和 `cancelled` 是終止狀態。`cancelled` 可以從任何非終止狀態
到達。`done` 和 `failed` 可以從 `inProgress` 或 `inReview` 到達；`open` 也可以
直接移至 `blocked`。UI 的狀態選擇器會列出除 `failed` 以外的每個狀態 —— 該狀態
由代理透過 `fail_ticket` 標示。

若要變更狀態，可以使用下列任一方式：

- 工單屬性欄中的**狀態**列，
- 清單中工單右鍵選單裡的**狀態**子選單，
- 多選工單後浮動工具列上的**狀態**晶片。

:::note[生命週期圖約束的是代理，不是你]
從 UI 發起的每一次狀態變更都會被強制執行，完全繞過這張圖 —— 你可以把工單移到
選擇器列出的任何狀態，包括重新開啟一張 `done`、`failed` 或 `cancelled` 的工單。
選擇器不提供 `failed` 作為目標。上方的圖約束的是代理與自動化：
MCP 工具或對帳器嘗試的非法轉換會被記錄並忽略，而不會套用。
:::

狀態變更會發出領域事件（`TicketStatusChanged`、`TicketCompleted` 等），
可用來觸發管線。請參閱
[設定管線觸發器](/zh-TW/手冊/操作指南/管線觸發器/)。

## 指派工單

1. 開啟該工單。
2. 在屬性欄中設定**負責人** —— 你自己、另一位工作區成員，或一個代理。

:::caution[指派不會啟動任何工作]
指派只記錄擁有權，僅此而已。它不會建立空間、不會變更狀態，也不會派送代理 ——
`TicketAssigned` 是純粹的稽核訊號，背後沒有任何派送器。若要讓代理開始工作，
請在空間中傳訊息給它（參閱[與代理聊天](/zh-TW/手冊/操作指南/與代理聊天/)）。

唯一的例外是：`TicketAssigned` 是一種你可以為其掛接管線觸發器的事件類型，
因此你自己撰寫的範本可以對指派做出反應。
:::

## 新增標籤

標籤是從工單清單批次套用，而不是在單張工單上 ——
屬性欄裡沒有標籤控制項。

1. 將游標停在工單清單中的某一列上，並勾選它的核取方塊。按需要勾選任意多列；
   一旦有項目被選取，就會出現一條浮動工具列。
2. 在該工具列中，開啟**標籤**晶片。
3. 選擇一個標籤。它會加到每一張尚無該標籤的選取工單上；現有標籤絕不會被
   清除。**清除標籤**會移除全部標籤。選擇器列出的是工作區中已出現在某張
   工單上的標籤。代理可以透過 `update_ticket` 或 `tickets.patch` 新增名稱。

## 連結工單

關聯關係位於屬性欄中工單的**關聯**卡片上，或清單右鍵選單的**關聯至**之下。

1. 開啟該工單，找到**關聯**卡片。
2. 按下它的新增控制項，選擇關係：

| 關係            | 意義                               |
| --------------- | ---------------------------------- |
| **子 issue…**   | 這張工單的父項是另一張             |
| **父 issue…**   | 另一張工單是這張的子項             |
| **被阻擋…**     | 這張工單被另一張阻擋               |
| **阻擋…**       | 這張工單阻擋另一張                 |
| **相關…**       | 對稱關係，不隱含方向               |
| **重複於…**     | 這張工單是另一張的重複項           |

3. 選擇目標工單。

**被重複**會出現在卡片中，但不會出現在選擇器裡 —— 它是**重複於…** 的反向
關係，並從另一張工單設定。列出的每個關係都可點擊以開啟被連結的工單，
並可在游標停留時移除。

父項與子 issue 關係儲存在工單本身，而不是作為連結資料列，因此刪除一張父工單會
串聯到它的子工單（見下文），而阻擋與相關連結則不會。

## 新增協作者

協作者是工單上的一份名冊 —— 記錄誰參與其中、以什麼身分參與。

1. 開啟該工單。
2. 按下**新增協作者**卡片上的人形加號控制項。
3. 選擇一個代理。

這三種角色是 **負責人**、**協作者**（預設）和 **審查者**。
UI 的選擇器只列出工作區代理，並且一律寫入預設角色；人員可以作為資料列出現，
但不會在該選單中提供。MCP 的 `add_ticket_collaborator` 工具接受一個 `role`。

新增協作者會寫入一筆資料列，但不會發布任何領域事件；它也不授予任何空間存取權。
要把代理帶進某段對話，請改從空間標頭將它新增為參與者 ——
參閱[空間](/zh-TW/手冊/操作指南/空間/)。

## 刪除工單

使用屬性欄底部的**刪除工單**、右鍵選單，或多選後浮動工具列上的刪除動作。

:::caution[刪除只在本地生效]
來自外部追蹤器的工單不會在那裡被刪除 —— 沒有供應商支援這一點 ——
因此它可能在下一次同步時重新出現。刪除也會串聯：該工單的協作者和任何子工單
都會一併被刪除。
:::
