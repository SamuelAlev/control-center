本指南說明如何連接模型供應商，以及如何選擇代理的執行平台。

這裡的一切都在同一個頁面上：**設定 → 伺服器 → 模型供應商**。子側邊欄的條目名為「模型供應商」；頁面標題則是「配接器」。

## 什麼是配接器

配接器是執行代理回合的_執行器_。共有兩個，而且清單是固定的——你無法新增第三個。

| 配接器                    | CLI      | 傳輸方式                                            |
| ------------------------- | -------- | --------------------------------------------------- |
| Control Center（內建）    | 無       | 行程內代理迴圈，透過 HTTP 與供應商通訊              |
| Claude Code               | `claude` | `claude -p --output-format stream-json`             |

Cursor、Codex、Anthropic、OpenAI 以及其他都是內建配接器上的**供應商**，而不是各自獨立的 CLI。你_可以_新增的是另一個供應商——任何與 OpenAI 或 Anthropic 相容的端點。那就是下一節的內容。

:::note[偵測探查的是伺服器，而不是你的機器]
**已偵測的執行器**卡片列出的是 `cc_server` 在_伺服器主機的_ `PATH` 上找到的內容。在精簡用戶端或網頁用戶端上，那是與你正在看的這台不同的機器。請把 CLI 安裝到執行 `cc_server` 的機器上。
:::

## 連接模型供應商

內建配接器在能夠執行之前，至少需要一個已連接的供應商。目錄中隨附了十四個。

1. 前往 **設定 → 伺服器 → 模型供應商**
2. 捲動到**供應商與模型**
3. 找到你的供應商並連接它：

| 供應商                                                                                                   | 連接方式                                                                                                                      |
| -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Anthropic                                                                                                | API 金鑰。Claude Pro/Max 訂閱不是 Anthropic API 登入——該方案請使用 Claude Code 配接器                                         |
| OpenAI、Codex、Cursor                                                                                    | 瀏覽器 OAuth 登入，或 API 金鑰。Codex 是透過 Codex Responses 後端提供的 ChatGPT Plus/Pro，而不是衍生出的 CLI                  |
| Kimi Code                                                                                                | 僅支援瀏覽器 OAuth——一種裝置碼流程。它是固定費率的方案，因此沒有按權杖計價的價格                                             |
| OpenRouter、Groq、Google Gemini、DeepSeek、Mistral、xAI、z.ai、z.ai GLM Coding Plan、Moonshot (Kimi API) | API 金鑰                                                                                                                      |

檢查點：該資料列的徽章會變成已連線，展開後會列出該供應商所提供的模型，每個模型都附有每百萬權杖的價格與情境視窗。

OAuth 權杖會存入伺服器自己的憑證儲存區，並在過期前重新整理。供應商憑證是**主機全域**的——由該安裝上的每個工作區共用，而不是只屬於某一個工作區。

### 新增自訂供應商

適用於 Ollama、LM Studio、vLLM 或私有部署。

1. 在**供應商與模型**中，於**自訂供應商**底下按**新增供應商**
2. 填寫**名稱**、選擇 **API 類型**（與 OpenAI 相容或與 Anthropic 相容），並提供 **Base URL**（例如 `http://localhost:11434/v1`）
3. 如果端點需要，再加入一個 **API 金鑰**，然後按**新增供應商**

自訂供應商會出現在同一個清單中，並帶有一個其內建同類所沒有的刪除按鈕。

## 為代理選擇模型

1. 前往 **設定 → 工作區 → 代理** 並選擇該代理
2. 在**設定**分頁上，選擇**配接器**
3. 從旁邊的下拉式選單中選擇**模型**

對於內建配接器，該下拉式選單是從每個已連線供應商自己的目錄即時組裝而成。沒有儲存憑證的供應商不會貢獻任何模型，因此空的下拉式選單幾乎總是代表「尚未連接任何供應商」，而不是「沒有可用項目」。

:::note[models.dev 只是補充資訊，絕不是 id 的來源]
隨附的 [models.dev](https://models.dev) 目錄會為已在即時清單中的模型提供價格與情境視窗。它從不新增模型 id。如果你預期會出現的模型缺失了，那就是供應商的端點沒有傳回它。
:::

內建配接器的模型 id 是帶限定詞的 `provider/model`，並可能帶有一條以 `|` 分隔的回退鏈。在有回退的情況下，費用是依實際服務該回合的模型計價，而不是依你請求的模型。

:::note[沒有配接器的代理會在內建迴圈上執行]
每個工作區都會預置五個代理——一位 CEO 加上 `qa`、`architect`、`engineer` 與 `librarian`——它們都沒有配接器，也沒有模型。派送會回退至 **Control Center（內建）**，而不是本頁的**預設執行器**設定；後者是用戶端偏好，派送路徑從不讀取它。執行日誌會為這些執行寫下 `cc-harness`，因此逐字稿會寫明實際執行的是什麼。

同樣沒有模型時，內建迴圈會向 Anthropic 索取其預設模型。因此，完全未設定任何項目的代理，只有在你已連接 Anthropic 帳號時才能執行，否則會以 `No credential for provider "anthropic"` 失敗。

完成入門引導的配接器步驟後，會用你選定的那一組配接器與模型，回填**每一個**仍然缺少配接器或模型的代理——CEO 與各專責代理，涵蓋當時已存在的每個工作區。之後建立的工作區仍會把五個代理全部預置為未設定狀態。請在你打算使用的每個代理上，明確設定配接器與模型。
:::

## 安裝執行器 CLI

內建配接器不需要安裝。若使用 Claude Code，請以該工具自己的套件管理工具，**在伺服器主機上**安裝其 CLI，例如：

```bash
npm install -g @anthropic-ai/claude-code
```

然後按頁面頂端的**重新整理**。每個偵測到的資料列都會顯示解析後的版本與路徑，並附上標示是否支援 JSON 模式與模型選擇的標籤。

外部 CLI 會在伺服器主機上，以自己的設定保存自己的憑證。Control Center 不會管理它們。

:::caution[配接器額外引數與環境變數只保存在本裝置上]
每個配接器資料列都提供一個**額外引數**欄位與一個**環境變數**對話方塊。這些值會儲存在你的裝置上。伺服器會從自己的設定儲存區讀取啟動 argv 與環境變數。請把供應商金鑰放在伺服器上（用 OAuth，或模型供應商頁面上的金鑰欄位），而不是放在這兩個欄位裡。
:::

## 限制工作區可使用的供應商

供應商治理以工作區為單位，並採最後符合者勝出的方式評估。

1. 在**供應商與模型**中，把供應商資料列上的**允許**開關關閉

這會在使用中的工作區裡，為該供應商寫入一條 `deny` 陳述，其模型也會從該工作區的目錄中消失。把開關重新打開即會移除該陳述。

## 疑難排解

### 執行器顯示為找不到

- 檢查 CLI 是否位於**伺服器主機的** `PATH` 上，而不只是你自己的
- 以 GUI 啟動的桌面應用程式，會以最小化的 `PATH` 啟動其伺服器；安裝在僅 shell 可見路徑下的 CLI，可能對它不可見
- 安裝後按**重新整理**

### 模型下拉式選單是空的

- 配接器是內建的那個，而且沒有連接任何供應商——請在**供應商與模型**中連接一個
- 或者供應商已連接，但被此工作區的治理開關拒絕

### 模型可以執行，但價格顯示為未知

即時模型清單帶有 id；價格與情境則來自 models.dev。全新的模型，或來自自訂供應商的模型，還沒有目錄條目。
