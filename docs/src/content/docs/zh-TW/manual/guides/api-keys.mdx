本指南說明 Control Center 使用的每一項憑證存放在何處，以及如何變更它們。

**你正在輸入的這台機器上不會儲存任何東西。** 每一項憑證都存放在伺服器上；某個請求由哪一項憑證回答，取決於它背後是否有真人。

| 憑證                                 | 儲存位置                                                  | 使用者                                                          |
| ------------------------------------ | --------------------------------------------------------- | ---------------------------------------------------------------- |
| 你的程式碼託管／工單憑證              | 伺服器的 0600 機密檔案，以你的使用者 id 為鍵                | 你要求的任何內容：PR 介面、你的代理執行、你的映像                 |
| 伺服器的應用程式身分                   | 同一個檔案，非機密項目則放在 `server_settings`              | 沒有真人要求的工作：webhook、PR 輪詢、工單同步                     |
| 模型供應商金鑰與 OAuth 權杖            | 伺服器自有的憑證存放區                                     | 內建配接器，供該安裝上的每個工作區使用                             |
| Slack 機器人權杖                       | 伺服器上的 `<dataDir>/<workspaceId>/chat_credentials/`     | 該工作區的聊天橋接                                                |
| 外部 CLI 憑證                          | 該 CLI 使用的任何儲存方式                                   | 伺服器主機上的 Claude Code                                        |

## 兩種 GitHub 憑證，各自回答不同的問題

- **你自己的**，來自登入（裝置流程）或貼上權杖。所有*代表你*發出的請求都用它，因此以你的名義張貼的留言會帶有你的名字。其他成員無法讀取它，他們會連接自己的憑證
- **伺服器的**，來自操作者註冊的 GitHub App。它回答一切沒有呼叫者的請求——因此當某個人離開或輪替權杖時，程式碼託管存取不會消失

你自己的憑證是在 **設定 → 工作區 → 個人資料與身分** 的**程式碼託管**卡片中設定；伺服器的憑證則在 **設定 → 伺服器 → 單一登入** 的**供應商應用程式**中設定。參見[設定 GitHub 整合](/zh-TW/手冊/操作指南/github-整合/)與[建立 GitHub App](/zh-TW/手冊/操作指南/github-app/)。

:::note[還有一個只能透過 URL 存取的畫面]
`/workspaces/<workspaceId>/api-keys` 會呈現與入門流程第一步相同的兩張卡片。它在**介面中的任何地方都沒有導覽入口**；只能透過輸入 URL 存取。請改用設定 → 工作區 → 個人資料與身分。
:::

## 設定模型供應商金鑰

內建配接器會自行向供應商完成驗證，而那些憑證存放在伺服器上。

1. 前往 **設定 → 伺服器 → 模型供應商**
2. 捲動至**供應商與模型**
3. 連接供應商——OpenAI、Codex、Cursor 與 Kimi Code 使用瀏覽器 OAuth；Anthropic 與其餘供應商則使用 API 金鑰

完整清單以及新增自訂端點的方法，請參見[管理配接器與模型](/zh-TW/手冊/操作指南/配接器/)。

這些憑證是**主機全域**的：一個金鑰就為該安裝上的每個工作區服務。OAuth 權杖會在到期前重新整理。

外部配接器 CLI 會以自己的設定，在伺服器主機上保存自己的憑證——Control Center 並不管理它們。請依照 Claude Code 自身文件的說明，在執行 `cc_server` 的機器上完成驗證。

每個配接器的**環境變數**對話方塊看起來像是可以為其中之一放置金鑰的地方，但其實不是：它會寫入你的裝置，而伺服器讀取的是自己的副本，兩者之間沒有任何東西橋接。參見[管理配接器與模型](/zh-TW/手冊/操作指南/配接器/)。

## 連接工單供應商

**設定 → 工作區 → 一般** 的**工單**卡片同時容納同一個決定的兩半：你的工單存放在哪個供應商，以及該供應商的憑證。選擇**本機**會隱藏憑證列——本機工單存放在這台伺服器自己的資料庫中，沒有需要驗證的對象。

你的金鑰會像程式碼託管憑證一樣，以你的使用者 id 存放在伺服器上。伺服器另外單獨保存自己的 Linear 金鑰（**供應商應用程式**），當沒有真人要求時，工單同步就是用它執行。代理收到的金鑰，只有在該代理具備**允許工單 API 呼叫**能力時才會被注入。參見[設定 Linear 整合](/zh-TW/手冊/操作指南/linear-整合/)。

## 輪替或撤銷

- **你的 GitHub 憑證**：按下**中斷連線**，然後重新登入或貼上新權杖。在 GitHub 上撤銷舊的憑證
- **伺服器的應用程式**：在該應用程式的 GitHub 頁面上產生新的私密金鑰或用戶端密鑰，貼到**供應商應用程式**中並按下**測試**
- **某個模型供應商**：在其資料列上登出（OAuth）或移除金鑰，然後重新連接
- **Slack**：在連接對話方塊中重新貼上權杖。參見[設定 Slack 整合](/zh-TW/手冊/操作指南/slack-整合/)

## 疑難排解

### PR 清單是空的，但我的權杖在 `curl` 中可用

檢查**程式碼託管**列的副標題。如果它顯示的是另一個來源（「透過此伺服器的應用程式」、「來自環境變數」），那麼你正在測試的憑證並不是在回答的那一個——你的憑證沒有被儲存。

### 權杖被接受了，但之後的請求失敗

權杖在儲存時就會被探測，因此該列會顯示它背後的帳號——但只有帳號，沒有範圍。範圍不足的權杖可以連線，之後卻會在個別請求上失敗。檢查範圍與到期時間：

```bash
curl -H "Authorization: token YOUR_TOKEN" https://api.github.com/user
```
