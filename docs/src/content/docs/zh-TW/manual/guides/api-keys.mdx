本指南說明 Control Center 使用的每一項憑證存放在何處，以及如何變更它們。

**你正在輸入的這台機器上不會儲存任何東西。** 每一項憑證都存放在伺服器上；某個請求由哪一項憑證回答，取決於它背後是否有真人。

| 憑證                                 | 儲存位置                                                  | 使用者                                                          |
| ------------------------------------ | --------------------------------------------------------- | ---------------------------------------------------------------- |
| 你的程式碼託管／工單登入              | 伺服器的 0600 機密檔案，以你的使用者 id 為鍵                | 你做的任何事：PR 介面、審查、合併、你在 Linear 上的動作           |
| 伺服器的供應商應用程式                 | 同一個檔案，非機密項目則放在 `server_settings`              | 讓人們登入，以及為代理、管線與輪詢簽發只適用於單一儲存庫的權杖     |
| Connect 安裝金鑰                       | 同一個檔案（`connect_install_key`）                         | 向 Control Center Connect 識別這台伺服器                          |
| 模型供應商金鑰與 OAuth 權杖            | 伺服器自有的憑證存放區                                     | 內建配接器，供該安裝上的每個工作區使用                             |
| Slack 機器人憑證                       | 伺服器上的 `<dataDir>/<workspaceId>/chat_credentials/`     | 該工作區的聊天橋接：你自己應用程式的權杖，或共用應用程式的封存授權 |
| 外部 CLI 憑證                          | 該 CLI 使用的任何儲存方式                                   | 伺服器主機上的 Claude Code                                        |

## GitHub：你的登入，以及只適用於單一儲存庫的權杖

- **你自己的**，來自**登入 GitHub**。所有*代表你*發出的請求都用它，因此以你的名義張貼的審查會帶有你的名字。其他成員無法使用它，他們會自己登入。沒有可貼上的 GitHub 權杖
- **沒有人在輸入的工作**（代理、管線、輪詢、機器人回覆）每次會取得一個只適用於一個儲存庫的權杖，由伺服器的 GitHub App 或透過 Control Center Connect 簽發，並限制在某位負責成員在那裡能做的事。它絕不是把你的登入整個交出去

你自己的登入是在 **設定 → 工作區 → 個人資料與身分** 的**程式碼託管**卡片中設定；伺服器的應用程式則在 **設定 → 伺服器 → 單一登入** 的**供應商應用程式**中設定。參見[設定 GitHub 整合](/zh-TW/手冊/操作指南/github-整合/)與[建立 GitHub App](/zh-TW/手冊/操作指南/github-app/)。

GitLab 與 Bitbucket 仍然使用貼上的個人權杖，儲存方式相同。參見[連接程式碼託管](/zh-TW/手冊/操作指南/連接程式碼託管/)。

:::note[還有一個只能透過 URL 存取的畫面]
`/workspaces/<workspaceId>/api-keys` 會呈現與入門流程第一步相同的兩張卡片。它在**介面中的任何地方都沒有導覽入口**；只能透過輸入 URL 存取。請改用設定 → 工作區 → 個人資料與身分。
:::

## 設定模型供應商金鑰

內建配接器會自行向供應商完成驗證，而那些憑證存放在伺服器上。

1. 前往 **設定 → 伺服器 → 模型供應商**
2. 捲動至**供應商與模型**
3. 連接供應商——OpenAI、Codex、Cursor 與 Kimi Code 使用瀏覽器 OAuth；Anthropic 與其餘供應商則使用 API 金鑰

完整清單以及新增自訂端點的方法，請參見[管理配接器與模型](/zh-TW/手冊/操作指南/配接器/)。

這些憑證是**主機全域**的：一個金鑰就為該安裝上的每個工作區服務。OAuth 權杖會在到期前重新整理。

外部配接器 CLI 會以自己的設定，在伺服器主機上保存自己的憑證——Control Center 並不管理它們。請依照 Claude Code 自身文件的說明，在執行 `cc_server` 的機器上完成驗證。

每個配接器的**環境變數**對話方塊看起來像是可以為其中之一放置金鑰的地方，但其實不是：它會寫入你的裝置，而伺服器讀取的是自己的副本，兩者之間沒有任何東西橋接。參見[管理配接器與模型](/zh-TW/手冊/操作指南/配接器/)。

## 連接工單供應商

**設定 → 工作區 → 一般** 的**工單**卡片同時容納同一個決定的兩半：你的工單存放在哪個供應商，以及 Control Center 與它溝通時是以誰的身分。選擇**本機**會隱藏 Linear 相關列——本機工單存放在這台伺服器自己的資料庫中，沒有需要驗證的對象。

Linear 有兩種登入，而且沒有要貼上的金鑰：**Linear** 是你自己的，用於你做的事；**Linear 自動化**則是工作區的 Control Center 應用程式，由管理員連接，用於工單同步、管線與代理。伺服器也可以保存一組**服務 API 金鑰**（**供應商應用程式**），供尚未連接自動化的工作區使用。代理的沙箱中不會注入任何工單憑證；代理透過 Control Center 的工具寫入工單，這些工具會詢問**寫入外部追蹤器**規則。參見[設定 Linear 整合](/zh-TW/手冊/操作指南/linear-整合/)。

## 輪替或撤銷

- **你的 GitHub 登入**：按下**中斷連線**，然後再次**登入 GitHub**。中斷連線也會讓伺服器代表你簽發的所有權杖一併失效
- **GitLab 或 Bitbucket 權杖**：按下**更新權杖**並貼上新的權杖，然後在該程式碼託管平台上撤銷舊的權杖
- **伺服器的應用程式**：在該應用程式的供應商頁面上產生新的私密金鑰或用戶端密鑰，貼到**供應商應用程式**中並按下**測試**
- **Connect 安裝金鑰**：在 **Control Center Connect** 卡片上按下**輪替金鑰**，或執行 `cc_server connect rotate-key --yes`。所有透過 Connect 登入的人都要重新登入。參見 [Control Center Connect](/zh-TW/手冊/參考/connect/)
- **某個模型供應商**：在其資料列上登出（OAuth）或移除金鑰，然後重新連接
- **Slack**：若是你自己的應用程式，在連接對話方塊中重新貼上權杖。共用的 Control Center 應用程式沒有需要輪替的權杖：它的機器人權杖會透過 Connect 更新，而**中斷連線**會撤銷它，並從 Slack 解除安裝該機器人。參見[設定 Slack 整合](/zh-TW/手冊/操作指南/slack-整合/)

## 疑難排解

### GitLab 或 Bitbucket 權杖在 `curl` 中可用，在這裡卻不行

檢查**程式碼託管**列的副標題。如果它顯示「來自環境變數」，那麼在回答的是伺服器的憑證，而不是你的——你的憑證沒有被儲存。

### GitLab 或 Bitbucket 權杖被接受了，但之後的請求失敗

權杖在儲存時就會被探測，因此該列會顯示它背後的帳號——但只有帳號，沒有範圍。範圍不足的權杖可以連線，之後卻會在個別請求上失敗。請到該程式碼託管平台上檢查它的範圍與到期時間。

### 供應商表示此伺服器尚未設定登入

伺服器既沒有該供應商的自有應用程式，也沒有 Control Center Connect。伺服器擁有者可在**設定 → 伺服器 → 單一登入**中擇一設定。
