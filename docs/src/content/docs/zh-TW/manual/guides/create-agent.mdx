本指南說明如何將代理加入工作區，並持續設定到它真的能執行為止。

每個工作區建立時都會預置五個代理——一位 CEO 加上 `qa`、`architect`、`engineer` 與 `librarian`——因此你通常在還沒設定任何代理之前就已經有代理可用。以下步驟對預置代理與新建代理同樣適用。

## 開始之前

- 你已位於某個工作區內。整個介面位於 **設定 → 工作區 → 代理**（`/settings/workspace/agents`）。
- 代理需要一個後端。你可以為內建執行環境在 **設定 → 伺服器 → 模型供應商** 連接供應商，或在裝載 `cc_server` 的機器上安裝 Claude Code CLI。
- 如果你希望代理具備技能，請先在 **設定 → 工作區 → 技能** 安裝它們。代理表單只能切換工作區中已存在的技能。

## 新增代理

1. 開啟 **設定 → 工作區 → 代理**。
2. 點擊 **新增代理**。

這裡不會出現對話框，也沒有角色選擇器。系統會立即建立一個名為「未命名代理」的代理，並在右側的詳細資料窗格中選取它。

此時你應該會在左側名冊中看到「未命名代理」，其詳細資料窗格已開啟 **設定** 分頁，且 **名稱** 欄位中包含「未命名代理」。

## 為它命名

- **名稱** — 用於 @提及的簡短識別碼，例如 `alice`。提及解析會比對 `@` 後接的文字字元，因此含有連字號、句點或空格的名稱永遠無法被提及。
- **標題** — 人類可讀的標籤，例如「資深程式設計師」。
- **系統提示** — 選用的額外指示，會以「代理指示」區段注入；它們不會取代組裝後提示的其餘部分。

點擊表單底部的 **儲存變更**。本頁的每個欄位都由這一個按鈕儲存。

## 為它設定配接器與模型

**配接器** 下拉式選單會列出伺服器主機上實際具備的執行器。內建配接器一律會被找到（它就是伺服器本身）。Claude Code 只在那台主機上偵測到它的 CLI 時才會出現：

| 配接器                    | 後端                                          |
| ------------------------- | --------------------------------------------- |
| Control Center (built-in) | 行程內的代理迴圈 — 不需要外部 CLI             |
| Claude Code               | `claude -p --output-format stream-json`       |

只有內建配接器會強制執行模式、操控、暫停/繼續、完成契約與子代理。Claude Code 這些全都沒有。Cursor、Codex 與其他模型供應商都掛接在內建配接器上，而不是獨立的執行器。

:::note[配接器留空代表使用內建迴圈]
配接器未設定的代理會派送至 **Control Center (built-in)**，也就是伺服器內部的迴圈，因此主機上完全不必安裝任何東西。若模型也未設定，它會向 Anthropic 要求預設模型，所以完全未設定的代理只有在你自己連接 Anthropic 帳戶時才能執行。預置的專家代理出廠時兩者都沒有；對於任何打算使用的代理，請把兩者都設好。
:::

**模型** 下拉式選單由你所選的配接器決定。對內建配接器而言，清單即時來自你在 **設定 → 伺服器 → 模型供應商** 已連接的供應商，因此沒有儲存憑證的供應商會貢獻零個模型。

## 新增技能

**技能** 是涵蓋此工作區中已安裝技能包的晶片選擇器。點按晶片即可切換；勾號圖示會標示已選取的項目。如果工作區沒有任何技能，該欄位會顯示「No skills available. Create skills in Settings → Skills first.」

你無法在這裡挑選儲存庫自帶的技能。帶有技能的儲存庫（放在 `.agents/skills/`、`.claude/skills/` 或 `.opencode/skills/`）會自動把它們貢獻給在該儲存庫中工作的任何代理，並在代理移到另一個儲存庫時換掉——參見[儲存庫範圍技能](/zh-TW/手冊/概念/代理模型/#repo-scoped-skills)。

## 設定回報關係與人設

- **直屬主管** — 依名稱挑選另一位代理。這會建立頁首 **組織圖** 按鈕所顯示的回報樹。它不是團隊領導者委派時所用的名冊——那名冊來自團隊的成員及其技能。
- **人設** — 塑造語氣與行為的自由文字，例如：「偏好簡單、易讀的解法。為所有新程式碼撰寫測試。」

## 調整執行參數

- **推理力度** — 選項來自所選模型自己公布的等級：Low / Medium / High，OpenAI 風格的模型另有 Extra High，Claude 風格的模型另有 Extra High + Max。當所選模型未宣告任何思考等級時，此欄位會完全隱藏，並採用模型本身的預設值。
- **上下文視窗大小** — 每次更換模型時會依模型的上下文視窗預先填入，並有一鍵晶片可選模型預設值、200k、500k 與 1M。你在選定模型之後輸入的值會生效，直到下次更換模型為止。
- **靜音逾時（分鐘）** — 超過這段時間沒有輸出就終止執行。留空則使用各模式的預設值。

## 授予權限

**沙箱權限** 一開始是「使用工作區預設值」。開啟開關即可為此代理個別設定，然後切換：

- **允許 git push** — 注入代理推送所需的 GitHub 權杖
- **允許 GitHub API 呼叫** — 讓代理讀取 PR、issue 與儲存庫中繼資料
- **允許工單 API 呼叫** — 注入工單供應商的金鑰
- **允許一般網路存取** — 同時啟用內建執行環境的 `web_fetch` 與 `web_search` 工具

執行啟動時，憑證仲介會檢查每一個開關：某項能力若為關閉，就代表對應的權杖永遠不會被簽發到該次執行的環境中。

:::caution[工作區預設值代表伺服器端的保守組合]
留在「使用工作區預設值」的代理，執行時 git push、GitHub API 與工單全都 **關閉**，而網路 **開啟**。設定 → 伺服器 → 診斷與隱私 底下顯示的能力預設值是用戶端偏好設定。若你希望代理推送或開啟 PR，請開啟開關並明確授予這些能力。

這些能力管制的是憑證與執行環境工具，與作業系統沙箱是不同的一層。主機上若存在沙箱，`cc_server` 會把代理執行包裝在其中——Windows 沒有原生後端，Linux 與 WSL2 則需要 `bwrap` 與 `socat`。完整的界線集合請參見[沙箱與資安](/zh-TW/手冊/概念/沙箱與資安/)。
:::

## 驗證它能執行

1. 開啟 **設定 → 伺服器 → 模型供應商**，確認你選擇的配接器回報的是已安裝版本，而不是「找不到」。點擊 **重新整理** 可重新探測——探測是在裝載 `cc_server` 的機器上執行，而不是在你正在檢視的這台機器上。
2. 開啟一個含有該代理的空間並傳訊息給它，或在既有空間中 @提及它。
3. 回到 **設定 → 工作區 → 代理**，選取該代理並開啟它的 **日誌** 分頁。應該會出現一次執行，帶有狀態徽章、執行時間長度、開始時間，以及它使用的配接器。**檢視** 會開啟該次執行的事件串流。

如果完全沒有出現任何執行，請依[診斷代理](/zh-TW/手冊/操作指南/診斷代理/)逐步排查。

## 刪除代理

在名冊中選取它。在 **設定** 分頁中，捲到表單底部的 **危險區域**，然後點擊 **刪除**。
