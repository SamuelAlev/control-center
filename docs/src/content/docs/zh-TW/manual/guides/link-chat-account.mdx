本指南說明如何將你的聊天身分連結到你的 Control Center 使用者，以及如何取消連結。

每位成員對每個聊天供應商都要做一次。這件事與連接應用程式不同：連線讓整個工作區都能觸及機器人，連結則讓_你_在其中有可辨識的身分。

## 為什麼必須連結

橋接會拒絕為無法解析到工作區成員的聊天帳號採取行動。這是刻意設計——沒有連結的話，來自 Slack 的每則訊息都將必須被歸屬到安裝應用程式的人身上，稽核軌跡、各主體的速率限制與工單報告者也都會指向錯誤的人。

未連結的成員提及機器人時，會在那個 Slack 討論串中收到一則說明如何連結的回覆。不會有任何東西被派送。

## 用代碼連結

1. 前往 **設定 → 工作區 → 個人資料與身分**，並捲動到 **已連結的聊天帳戶**卡片
2. 在 Slack 區塊中，點選 **連結我的 Slack 帳戶**
3. 複製它顯示的指令，例如：

```text
/cc link K7M2QP
```

4. 在 Slack 中把該指令傳送給機器人——私訊是最方便的地方
5. 機器人會以你現在連結到的 Control Center 使用者作為確認，而你原本開著的那個對話方塊會在同一時間更新並顯示這件事——你不必關掉它再去查看

這組代碼：

- 只能使用一次，並在產生後 **15 分鐘**過期
- 永遠是專為_你_產生，絕不會給團隊成員
- 會取代你手上既有的任何代碼，因此再次按下按鈕會讓前一組失效
- 只存在於記憶體中，因此伺服器重新啟動會讓尚未使用的代碼失效——請再次按下按鈕

未知、已過期，或為其他工作區產生的代碼，都會以同樣無法區分的方式失敗：「該代碼無效（或已過期）」。

## 依電子郵件自動連結

如果你的 Slack 個人資料帶有已驗證的電子郵件，且該郵件對應到一位**已經是這個工作區成員**的 Control Center 使用者，橋接會在你第一次與它對話時就將你連結起來。不需要任何代碼。

兩個部分都重要：電子郵件比對證明了身分，但唯有成員資格才授予存取權，因此一個電子郵件恰好在伺服器上存在的陌生人什麼也連結不到。名冊會顯示每個連結是如何建立的（「依電子郵件比對」或「以代碼連結」）。

自動連結需要 `users:read.email` 範圍。少了它，Slack 不會揭露該地址，用代碼就成了唯一的路徑。

## 查看誰已連結

名冊屬於工作區管理，因此它位於介面的另一半：**設定 → 工作區 → 一般 → 聊天橋接 → 已連結的帳戶**。它會列出工作區中每一位已連結的成員，以及各自對應到的 Slack 帳號與連結的建立方式。

你自己的狀態就在你的個人資料頁面上：**連結我的 Slack 帳戶**那一列在你完成連結後會顯示「已連結至 _your-slack-id_」，尚未連結時則會提示你進行連結。

名冊是一份即時訂閱，因為變更發生在另一端——你是在 Slack 中輸入代碼，因此應用程式發出的任何請求都無法把結果帶回來。

## 取消連結

在工作區名冊的某一列上點選 **取消連結**。

- 任何人都可以取消自己的連結
- 只有管理員可以取消其他成員的連結
- 取消連結也會撤銷該成員任何尚未使用的連結代碼

取消連結之後，該 Slack 帳號就無法再驅動代理，直到再次連結為止。既有的空間、對話紀錄與工單會保留原本的歸屬——取消連結並不是撤回過去的工作。

## 疑難排解

### 機器人說我不是這個工作區的成員

你的 Slack 帳號已連結到一位 Control Center 使用者，但該使用者並不具備這個工作區的成員資格。請要求管理員邀請你；參見[多人協作——身分、成員資格與線上狀態](/zh-TW/手冊/概念/多人協作/)。

### 機器人說我的角色是唯讀

`viewer` 與 `guest` 角色無法開始工作。必須由管理員把你的角色提升到 `member` 或以上。

### 斜線指令未被辨識

請確認該斜線指令存在於 Slack，而且你傳送的是設定對話方塊顯示給你的那個指令——管理員可能已將它重新命名，這種情況下對話方塊顯示的是目前的名稱。
