本指南說明如何讓你的伺服器擁有自己的 GitHub App。整個過程大約兩分鐘，只有伺服器擁有者需要操作，而且每部伺服器只需做一次。

:::note[你可能不需要它]
開啟 Control Center Connect 後，人們會透過 Control Center 的共用 App，或你的組織所用 Connect 的 App 登入 GitHub。當你選擇了**使用我自己的應用程式**時才需要註冊自己的應用程式：伺服器自己的應用程式只在那種情況下使用。請見 [Control Center Connect](/zh-TW/手冊/參考/connect/)。
:::

至於事後登入你自己的帳號，請見[設定 GitHub 整合](/zh-TW/手冊/操作指南/github-整合/)。

## 應用程式做什麼

一次註冊要承擔兩件不同的工作：

| 工作               | 由什麼來回應                 | 為什麼重要                                                         |
| ------------------ | ---------------------------- | ------------------------------------------------------------------ |
| **有人登入**       | 應用程式的用戶端 id 與用戶端密鑰 | 每個人都會取得屬於自己的 GitHub 憑證，位於伺服器上，在所有裝置皆通用 |
| **伺服器行事**     | 應用程式的 id 與私鑰         | 代理、管線、輪詢程式與機器人回覆每次取得只適用於一個儲存庫的權杖   |

第二件工作絕不會整個借用某個人的憑證。伺服器簽發的每個權杖只涵蓋一個儲存庫，並限制在某位負責成員在那裡能做的事。讀取已連結的儲存庫只需要應用程式；任何寫入都需要一位能推送的成員。自動化永遠不會核准 pull request。

伺服器自己的應用程式只在選擇了**使用我自己的應用程式**時適用。使用 Control Center Connect 或自訂 Connect 時，Connect 會執行每個通道，包括 GitHub；伺服器的應用程式會保留但不使用，直到你切換回來。選擇了自有應用程式的工作區（[為單一工作區提供自己的應用程式](#為單一工作區提供自己的應用程式)）改用其自己的 App，無論伺服器處於何種模式。缺少部分欄位的應用程式是一項錯誤，而不是退回其他方案：在每個欄位都設定好之前，GitHub 登入都會被拒絕。

## 先決條件

- 你是**伺服器擁有者**。其他所有人都看不到**供應商應用程式**卡片
- 一個 GitHub 帳號。應用程式會建立在它底下
- 一個你的瀏覽器能連到的伺服器位址。伺服器的公開網址（或桌面版自身伺服器的回送位址）就是 GitHub 送你回來的地方

## 一鍵建立

1. 前往 **設定 → 伺服器 → 單一登入**，並捲動到**供應商應用程式**卡片
2. 在 **GitHub** 區塊中，你可以選擇在**組織（選填）**中輸入應該擁有這個應用程式的 GitHub 組織。留空則會在你自己的帳號下建立；要在組織下建立，需要該組織的擁有者
3. 點選**建立我的 GitHub 應用程式**
4. 你的瀏覽器會開啟 GitHub，應用程式的內容已預先填好。點選 **Create GitHub App**
5. GitHub 會把你送回伺服器，伺服器會儲存應用程式 id、私鑰、用戶端 id 與用戶端密鑰，接著開啟應用程式的安裝頁面

不需要手動複製任何東西，而轉換代碼會直接從 GitHub 送到你的伺服器。這個連結只能使用一次，並在十分鐘後過期；若已過期，請再點選一次**建立我的 GitHub 應用程式**。

應用程式會命名為 `Control Center <code>`，所要求的權限正好是 Control Center 用到的：

| 權限                                       | 存取           |
| ------------------------------------------ | -------------- |
| Metadata                                   | 讀取           |
| Contents                                   | 讀取與寫入     |
| Pull requests                              | 讀取與寫入     |
| Issues                                     | 讀取與寫入     |
| Checks、Actions、Commit statuses           | 讀取           |
| Organization members                       | 讀取           |

Webhook 是關閉的：伺服器採用輪詢。若之後要把在你自己帳號下建立的應用程式移轉給組織，請在 GitHub 上該應用程式的進階設定中使用 **Transfer ownership**。

檢查點：GitHub 區塊顯示「伺服器能以自身身分行動，且人們可以登入」。

## 安裝到你的儲存庫所在之處

一個已註冊但未安裝的應用程式可以讓人們登入，卻讀不到任何內容。

1. 在 GitHub 開啟的安裝頁面上，挑選擁有你的儲存庫的帳號或組織
2. 選擇 **All repositories**，或挑選這部伺服器應該看見的儲存庫

若之後要安裝到另一個帳號上，由工作區管理員前往 **設定 → 工作區 → 整合**，在程式碼託管下的 **GitHub 應用程式**卡片上找到 **GitHub 應用程式安裝**，然後點選**安裝 GitHub 應用程式**。這份清單會列出應用程式安裝所在的每個帳號，並標示遭到停權的安裝。

## 分享組織的安裝

一個組織只需安裝一次 GitHub App。之後，組織內任何在 Control Center 伺服器上登入 GitHub 的人，都可以使用這個安裝，不論是哪台伺服器：你的、同事的，或他們自己的。無須為每台伺服器分別授權。

伺服器取得的每個權杖都屬於登入的那個人，只限於一個儲存庫，以及該人在該儲存庫中的角色，因此權限不會超出此人在 GitHub 上的權限。GitHub 的稽核紀錄會顯示這位透過應用程式操作的人。

要阻止 Control Center 存取某個組織，該組織的擁有者需要在 GitHub 上移除安裝，或縮小其儲存庫範圍。把某人移出組織也會停止其存取權。

## 改為手動註冊

**供應商應用程式**卡片也可以直接接受這些值，適用於你自行註冊的應用程式：

| 群組                         | 欄位                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------- |
| **以伺服器身分行動**         | **應用程式 id**，以及**私鑰**（完整的 `.pem`，包含 `BEGIN` 與 `END` 行）               |
| **讓人們登入**               | **用戶端 id** 與**用戶端密鑰**。**回呼網址**會原封不動地顯示要註冊的網址               |
| **Pull request 對話**        | **機器人登入名稱**，在你測試連線時解析                                                |

請完全依照卡片顯示的內容註冊回呼網址 `<server origin>/oauth/github/callback`，保持 **Expire user authorization tokens** 開啟，並授予上表中的權限。點選**測試**：它會向 GitHub 查詢該應用程式安裝在哪些帳號上，因此不會把「已儲存」與「可運作」混為一談。

## 從伺服器的 `.env` 設定

若是無介面或以指令碼完成的安裝，伺服器會在某個欄位尚無儲存值時，第一次從它的 `.env` 檔案為該欄位提供初始值：

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

請把金鑰放在**同一行**：`.env` 的值只有一行，而雙引號內的 `\n` 會被解碼為換行。若 `GITHUB_APP_PRIVATE_KEY` 或 `GITHUB_CLIENT_SECRET` 被匯出到伺服器的行程環境中（每個子行程都讀得到），伺服器會拒絕啟動；請把它們放在 `.env` 檔案中（在 Docker 中，將檔案掛載到 `/app/bin/.env`）。初始值的提供**每個欄位只發生一次**，因此在設定中所做的編輯不會在下一次重新啟動時被復原。

## 為單一工作區提供自己的應用程式

工作區可以改用自己的應用程式，而不使用伺服器的：

1. 工作區管理員前往 **設定 → 工作區 → 整合**
2. 在 **Control Center Connect** 卡片上選擇**使用我自己的應用程式**，然後點選**套用**。工作區中的每個人都會透過工作區的應用程式重新登入
3. 程式碼託管下的 **GitHub 應用程式**卡片現在包含該應用程式的欄位：**代表此工作區運作**下的**應用程式 id** 與**私鑰**，**讓人們登入**下的**用戶端 id** 與**用戶端密鑰**。全部填寫後點選**測試**

之後成員會在這個工作區中登入那個應用程式。使用自己應用程式的工作區永遠不會退回伺服器的應用程式或 Connect：在它的欄位填寫完整之前，它的 GitHub 工作都會被拒絕。Google Calendar、Linear 與 GIF 搜尋也採用同一選項，各自的欄位位於同一頁中對應的提供者旁。請見 [為一個工作區設定自己的 Linear 應用程式](/zh-TW/手冊/操作指南/linear-整合/#為一個工作區設定自己的-linear-應用程式) 與 [為一個工作區設定自己的 Google 用戶端](/zh-TW/手冊/操作指南/連接日曆/#為一個工作區設定自己的-google-用戶端)。卡片上的其他選項及其作用，請見 [每個工作區的選擇](/zh-TW/手冊/參考/connect/#每個工作區的選擇)。

## 疑難排解

### 建立我的 GitHub 應用程式表示伺服器沒有位址

伺服器沒有瀏覽器可以返回的公開網址。請設定 `CC_SERVER_PUBLIC_URL`（或 `--public-url`）後再試一次。

### GitHub 表示連結已過期

這個一次性頁面已經用過，或已經過了十分鐘。請從設定重新開始。

### 測試顯示憑證可用，但應用程式未安裝在任何地方

註冊與安裝是兩個不同的步驟。開啟應用程式的安裝頁面，或使用「工作區 → 整合」中的**安裝 GitHub 應用程式**。

### 測試顯示無法讀取私鑰

請貼上完整的 `.pem` 檔，包含 `-----BEGIN` 與 `-----END` 這兩行。`ed25519` 或 EC 金鑰無法使用：GitHub App 以 RSA 簽章。

### 有成員已登入，卻看不到任何儲存庫

應用程式沒有安裝在擁有那些儲存庫的帳號上，或其安裝選取的是其他儲存庫。登入只會授予應用程式被允許看見的內容。

### 代理表示 GitHub App 安裝已遭停權

有人在 GitHub 上將該安裝停權。請在該帳號的 **Settings → Applications → Installed GitHub Apps** 中解除停權。
