目標是代理持續投入、直到達到完成的標準為止的工作。代理以**分段**進行工作：每個分段都是一次有界限的執行，由伺服器依序啟動，即使中途重新啟動也會接續進行，直到目標通過驗證、由人員結束，或達到某個上限為止。代理不能靠自己說已完成來結束目標。伺服器會先執行目標的驗證，再由檢閱者查看結果。

## 開始目標

在對話的輸入框中輸入 `/goal` 與目標內容：

```text
/goal --budget 20 --days 2 --check "make test" make the importer handle files over 2 GB
```

若訊息一開頭先輸入 `/goal` 加上文字，會開啟目標訪談。訪談會詢問完成的標準、必須通過的驗證、界線與停止條件，並提供另外指定檢查器、每個分段都重新開始，以及讓代理自行回答其問題等選項。每個步驟都可以略過。

| 旗標 | 意義 |
| --- | --- |
| `--budget <dollars>` | 整個目標可以花費的金額。預設為 50 美元 |
| `--max <N>` | 目標最多可以使用的分段數。預設沒有上限 |
| `--days <N>` | 期限，從現在起算的天數 |
| `--check "<command>"` | 必須通過才能完成目標的指令，在工作樹中執行。可重複指定，最多 5 個 |
| `--checker <agent>` | 審查目標是否已完成這項聲明的另一個代理，可以用名稱或 ID 指定 |
| `--fresh` | 每個分段都不帶入對話歷史，只依據目標及其筆記開始 |
| `--unattended wait` 或 `--unattended assume` | 無人回應時，代理的提問會如何處理（見[無人回應時](#無人回應時)） |

- 旗標可以放在訊息的任何位置。未知的旗標、重複的旗標、錯誤的值，以及超過 5 個驗證，都會被拒絕，而你的草稿會留在輸入框中，並在下方顯示原因。
- 目標開頭的數字是目標內容的一部分。若要限制分段數，請使用 `--max`。
- 只有你自己輸入的訊息才會讀取 `/goal`。來自代理、管線或喚醒的相同文字，只是一般訊息。
- 代理在一個工作區中一次只追求一個目標。同一個代理已有進行中的目標時，第二個 `/goal` 會被拒絕。

### 完成的標準

目標的描述可以包含一些區段，這些區段會成為目標的約定：

```text
/goal make the importer handle files over 2 GB

## Success criteria
- A 3 GB fixture imports without running out of memory
- The progress bar reaches 100%

## Boundaries
- Don't change the public API

## Stop conditions
- A migration would drop data

## Checks
- `make test` (300 s)
- environment task `test` (600 s)
```

- **成功標準**：最多 12 項，每項最多 300 個字元。每一項都必須是審查者可以確認的事項。
- **驗證**：最多 5 項。驗證會在工作樹中執行，或作為空間的[環境](/zh-TW/手冊/操作指南/環境/)中一個具名的工作。每項預設有 300 秒，最多 1,800 秒。
- 超過上限的區段會被拒絕，不會被截斷。

沒有任何標準的目標會讓代理自行決定何時算是完成，而沒有任何驗證的目標只依賴檢閱。目標頁面會說明這一點。

## 目標如何延續

每個分段是一次執行，上限為 5 美元或預算剩餘的金額，以較低者為準。每個分段結束後，伺服器會根據該分段做了什麼，決定接下來要怎麼做：

- **有進展。** 下一個分段會開始。
- **它正在等待自己安排的事項**：排程、監看、向另一個代理提出的問題，或已委派的工單。目標會等待這些事項。若沒有任何結果送達，伺服器會在 20 分鐘後再次檢查，然後是 40、80、160 分鐘，之後每 240 分鐘檢查一次。卡片會顯示 **等待其所安排的工作 · 最遲於** 某個時間再次檢查。
- **沒有進展。** 進展是指工作樹因該分段自身的工作而改變、檢查清單有所改變，或代理做了新的事。連續 3 個分段沒有進展後，目標會暫停，並顯示 **最近幾個分段沒有任何進展。**
- **等待太久。** 在等待 24 小時之後，或在兩次等待之間沒有任何進展、連續 6 次為新安排的事項而等待之後，目標會暫停，並顯示 **在幾個沒有進展的分段之後等待中。**
- **失敗。** 伺服器會在 30 秒後重試，之後等待時間更長，最多到 15 分鐘。連續 3 次失敗後，目標即失敗。
- **它向人員提問。** 目標會一直保留，直到有人回覆：**需要人員處理**。

目標也會在預算用盡（**預算已用盡**）、分段上限或期限到達時停止。

## 代理宣告已完成時

代理會針對每項標準附上證據，宣告目標已完成。接著：

1. **伺服器會執行驗證**，並且是在沙箱中執行，絕不直接在伺服器的機器上執行。非零結束碼的驗證會失敗。無法執行的驗證（找不到指令、無法執行、環境工作不存在）即為損壞：目標會停下來等人員處理，並顯示 **此驗證無法執行：** 以及該指令。若伺服器上沒有沙箱，目標會停止並顯示 **沒有可用的沙箱來執行其驗證。**（若伺服器擁有者已為所有執行關閉沙箱，則為例外：驗證會以與代理自己的指令相同的方式在該處執行。）若驗證失敗後工作樹沒有任何變化，就不會重新執行。
2. **檢閱者會查看結果**，條件是所有驗證都已通過或沒有驗證。檢閱者是目標的檢查器，若沒有則為空間的檢查器，再沒有則為目標自己的代理。檢閱者以唯讀方式執行，且沒有對話歷史：它可以讀取檔案與驗證的輸出，但不能變更任何東西、執行指令或喚醒其他代理。它也會取得代理所變更之測試與驗證腳本的完整 diff，並將代理在對話與筆記中寫下的內容視為主張，而非證明。沒有準則的目標，則由它就目標整體進行判斷。它會回覆目標是已完成、未完成，或無法判斷。
3. **完成**：目標結束。**未完成**：代理會取得檢閱者的意見，並繼續工作。在 3 輪未完成之後，或檢閱者無法判斷時，目標會等待你的決定：**等待檢閱：目標聲稱已完成，但尚未獲得確認**。

在檢閱者執行期間你輸入的訊息，不會交給檢閱者，檢閱結束時也不會送出。該訊息會保留在佇列中，等待代理的下一個分段。若之後沒有接續的分段，該訊息會改為保留給你，列於**傳送保留的訊息**之下。

若檢閱者無法執行（已被刪除，或位於無法保持唯讀的介面卡上，例如 ACP 代理），目標會暫停，並顯示 **其檢查器代理無法使用。請選擇另一個檢查器，然後繼續。** 未經你同意，不會由其他代理接手。

與目標的代理來自不同供應商的檢查器，比較不容易與其共享盲點。若沒有另外的檢查器，代理會檢閱自己的工作，而目標會記錄 **由其自身驗證（沒有另外的檢查器）**。

## 追蹤目標

- **在對話中**：目標卡片位於 **一般** 面板中，顯示保留狀態、分段、花費相對於預算的情況、剩餘時間、完成的標準、驗證與最近的判定。
- **目標頁面**：側邊欄 → **目標**。目標會分為 **等待檢閱**、**進行中**與 **已結束** 三組。
- **單一目標的頁面**：開啟目標即可看到 **目前狀態**（分段、花費、期限、無進展次數，以及接下來會發生的事）、**完成的標準**、**驗證**（最近一輪：聲明、每項驗證及其輸出、每項標準的檢閱），以及 **排程與喚醒**。每個目標都有自己的位址（`/workspaces/<workspace>/goals/<goal id>`），因此可以分享連結。

在手機上，目標畫面可以啟動含驗證與分段上限的目標，並顯示相同的目標與保留項目。

## 變更或停止目標

| 動作 | 誰可以 |
| --- | --- |
| **暫停目標**、**停止目標** | 任何可以存取該空間的人 |
| **繼續目標**、**提高預算** | 只有啟動該目標的人（若沒有人啟動過，則為工作區管理員） |
| **編輯**完成的標準、**變更檢查器** | 只有發起該目標的人（沒有人發起的目標則為工作區管理員），需具有該空間儲存庫的寫入權限，且目標處於暫停狀態時 |
| **核准完成** | 任何可以存取該空間的人，且目標正在等待檢閱時。由管線發起的目標：僅限發起該執行的人員（無人發起時則為工作區管理員） |

- 在代理的執行中按下 **停止** 會暫停目標（**已由人員暫停**）。其等待中的喚醒會等到你繼續目標後才處理。
- **核准完成** 會依你的判斷，將目標結束為已完成。目標會記錄 **由人員在未通過驗證的情況下結束**。
- 用完預算的目標，只有在提高預算後才會繼續。
- 當發起目標的人員離開工作區時，目標會立即暫停等待檢閱，且其執行中的代理會被停止。沒有人可以繼續它；任何能存取該空間的人都可以停止它。每日摘要會把它列給工作區管理員。

## 無人回應時

當分段向人員提出問題或請求核准，而無人回應時，該請求預設會等待 72 小時。之後，核准視為拒絕，問題視為未回覆，目標會暫停並顯示 **給人員的問題或核准請求未獲回覆。** 該提出請求的執行不會再收到回覆：它之後再提出的任何其他問題都會立即被拒絕，並完成它能完成的部分。工作區管理員可在 **設定 → 工作區 → 排程 → 無人回應時** 下設定時間（1 小時至 7 天）。每天於該處設定的時間，你會收到一份摘要，列出所有等待你處理的事項。

使用 `--unattended assume` 時，若其停止條件允許，代理會在 10 分鐘無人回覆後，說明其假設並繼續進行。這只適用於問題。核准絕不會被假設，檢閱也絕不做任何假設。

## 用量上限與重新啟動

- **供應商的用量上限。** 當分段在供應商的用量上限處停止，且供應商說明了重設時間（7 天之內），目標會暫停且不計入失敗，並顯示 **已在用量上限處暫停 · … 繼續**。重設後 30 秒會繼續。若這類暫停達到 8 次，目標會等待你的決定：**它太常碰到用量上限。請檢視後再繼續。** 任何一次繼續都會重新計數。ACP 代理不會回報重設時間，因此其目標不會在用量上限處等待。
- **伺服器重新啟動。** 目標會在重新啟動後保留。被重新啟動中斷的分段會重新開始，目標的排程與待處理的喚醒都會保留。

## 目標之後的改進

目標通過驗證後，一個簡短的唯讀檢閱（最多 1 美元）可能會提出改進建議：記憶事實、政策、代理的備註，或技能的變更。輸入 `/refine` 可要求對對話中的工作進行同樣的檢閱。每個對話每 20 分鐘最多執行一次檢閱。

提案會顯示在 **改進** 頁面（側邊欄 → **改進**）。開啟一項提案即可看到它會變更什麼、其證據，以及 **接受**、**拒絕** 或 **回復**。

- 提案在有人接受之前不會改變任何事情。提案會在 30 天後過期。
- 技能的變更，或適用於整個工作區的政策變更，需要由工作區管理員決定（**由管理員決定**）。
- 技能變更會以獨立的修訂版本儲存。按下 **執行評估** 即可將其與目前的技能比較；只有評估通過後才能 **接受**。當評估完整執行，且使用此變更時代理解決的執行次數，不少於使用目前技能時，評估即為通過。頁面會顯示兩個數字。若評估後技能又有變更，請重新執行評估。
- **回復** 會還原先前的文字，但前提是此後沒有人變更過它。

## 在管線中

管線可以使用 **Pursue a goal** 步驟（`goal.pursue`）啟動目標。該步驟會等待目標結束，並傳遞其摘要與判定。請參閱[管線步驟](/zh-TW/手冊/參考/管線步驟/)。
