Linear 在 Control Center 中有兩種身分，而且兩者都是瀏覽器登入：你自己的，用於你
做的事；以及工作區的 Control Center 應用程式，用於代理與管線做的事。工單、專案、
連結、協作者、委派與指派全都透過 Control Center 自己的資料庫運作，不需要任何外部
服務——請參閱[建立與管理工單](/zh-TW/手冊/操作指南/管理工單/)。

## 先決條件

- 伺服器能讓人們登入 Linear：透過 Control Center Connect，或使用伺服器自己的
  Linear 應用程式（[註冊你自己的 Linear 應用程式](#註冊你自己的-linear-應用程式)）。
  由伺服器擁有者在 **設定 → 伺服器 → 單一登入** 中選擇
- 一位工作區管理員，負責選擇 Linear 做為工單供應商並連接 Linear 自動化

## 為工作區選擇 Linear

1. 前往 **設定 → 工作區 → 一般**，找到**工單**卡片
2. 將**工單供應商**設為 **Linear**

此後你建立的工單都會被標上 `provider: linear`。**本機**會把工單保存在這台伺服器
自己的資料庫中，並隱藏 Linear 相關列：沒有需要驗證的對象。

## 登入 Linear

在同一張卡片上，**Linear** 這一列是你自己的：

1. 點選**登入 Linear**
2. 在瀏覽器中核准
3. 使用伺服器自己的應用程式時，對話方塊會自行察覺。透過 Connect 時，請輸入瀏覽器
   顯示的 8 個字元代碼，或讓它透過 `control-center://` 連結開啟 Control Center

你從 Control Center 在 Linear 中做的任何事，都只使用這個登入，別無其他。如果你
尚未登入，應用程式會請你登入，而不是以別人的身分行事。

## 連接 Linear 自動化

**Linear 自動化**這一列是工作區在 Linear 中的 Control Center 應用程式。工單同步、
管線與代理都用它寫入，因此自動建立的議題與留言會以 Control Center 的身分出現，
而不是某個人。

1. 由工作區管理員點選**連接 Linear 以進行自動化**
2. 他在瀏覽器中為該 Linear 工作區核准這個應用程式，方式同上

接著該列會顯示「已連接到 _你的 Linear 工作區_」。只有工作區管理員能連接或中斷
它。

代理的沙箱中不會放入任何 Linear 憑證：代理透過 Control Center 自己的工具寫入工單，
這些工具會先詢問**寫入外部追蹤器**規則。

## 註冊你自己的 Linear 應用程式

當你選擇了**使用我自己的應用程式**時，就使用你自己的應用程式。伺服器自己的應用程式只在那種情況下適用：使用 Control Center Connect 或自訂 Connect 時，Connect 會執行每個通道（包括 Linear），伺服器的應用程式與服務 API 金鑰會保留但不使用。工作區自己的應用程式（[見下方](#為一個工作區設定自己的-linear-應用程式)）在任何模式下都適用。

1. 在
   [linear.app/settings/api/applications/new](https://linear.app/settings/api/applications/new)
   建立一個 OAuth 應用程式
2. 原封不動地加入 **設定 → 伺服器 → 單一登入 → 供應商應用程式 → Linear** 在
   **回呼網址**下顯示的兩個回呼網址：
   `<server origin>/oauth/linear/callback` 與
   `<server origin>/oauth/linear_app/callback`
3. 將**用戶端 id** 貼到 Linear 區塊中

不需要用戶端密鑰：伺服器以 PKCE 登入。Linear 的重新整理權杖在 30 天未使用後就會
過期，因此伺服器每天會更新一次所有超過 20 天的 Linear 登入。

同一個區塊還接受選填的**服務 API 金鑰**。它是伺服器自己的 Linear 憑證，供尚未連接
Linear 自動化的工作區進行自動化。請把它保存在**設定**中，或在伺服器的 `.env` 檔案
中寫成 `LINEAR_API_KEY`：若 `LINEAR_API_KEY` 被匯出到行程環境中，伺服器會拒絕
啟動。

## 為一個工作區設定自己的 Linear 應用程式

工作區可以改用自己的應用程式登入 Linear，而不使用伺服器的。只有工作區管理員或擁有者能設定。

1. 依照上方步驟建立 Linear OAuth 應用程式
2. 前往 **設定 → 工作區 → 一般 → 供應商應用程式**，開啟 **Linear**
3. 選擇**使用此工作區自己的應用程式**
4. 將該列在**回呼網址**下顯示的兩個回呼網址，原封不動地加入 Linear 應用程式
5. 貼上它的**用戶端 id**，並可選擇為此工作區的自動化填入**服務 API 金鑰**

此工作區的應用程式之後會回應此工作區中所有 Linear 登入與自動化請求，無論伺服器以何種方式讓人們登入。它絕不會退回伺服器的應用程式或 Connect：在設定用戶端 id 之前，此工作區的 Linear 會關閉，且該列會說明缺少什麼。其服務 API 金鑰只在此處使用；若沒有它，同步就需要**連接 Linear 以進行自動化**。

在伺服器的應用程式與工作區的應用程式之間切換，或變更工作區的用戶端 id，會讓此工作區中所有人登出 Linear 並中斷其自動化連線。他們會透過新的應用程式重新登入。**使用此伺服器的應用程式**會刪除工作區已儲存的欄位。密鑰只能寫入：該列只顯示是否已儲存密鑰。伺服器上的其他工作區不受影響。

## 疑難排解

### Linear 這一列表示尚未設定登入

伺服器既沒有自己的 Linear 應用程式，也沒有 Connect。由伺服器擁有者在
**設定 → 伺服器 → 單一登入** 中擇一設定。當工作區使用自己的應用程式時，該列會改為顯示設定尚未完成：工作區管理員需在 **設定 → 工作區 → 一般 → 供應商應用程式** 中加入用戶端 id。

### 工單同步因驗證錯誤而失敗

工作區尚未連接 Linear 自動化，而伺服器也沒有服務 API 金鑰，因此同步沒有任何憑證
可用。由工作區管理員點選**連接 Linear 以進行自動化**。

### 連接自動化時表示該 Linear 工作區已在別處連接

該 Linear 工作區的 Control Center 應用程式已經連接到另一台 Control Center 伺服器。
