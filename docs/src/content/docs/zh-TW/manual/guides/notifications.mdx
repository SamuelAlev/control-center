本指南說明如何設定通知，以及每一項設定實際控制什麼。

通知經由兩個介面送達。**通知中心**——標題列中的鈴鐺——讀取伺服器上每個工作區各自的持久動態饋送。**作業系統 Toast** 則是一條獨立的、僅限桌面端的路徑，由伺服器推送的即時訊框供給。

:::note[Web 版本不顯示作業系統通知]
Toast 管線只由桌面端啟動流程建構。在 `app.usectrl.dev` 上既沒有作業系統 Toast，也沒有通知音效與環境橫幅——鈴鐺與其歷史仍可運作，因為它們讀取的是伺服器動態饋送。手機用戶端則完全沒有通知介面。
:::

## 開啟或關閉各類別

1. 前往 **設定 → 你 → 通知**
2. 讓 **啟用通知** 保持開啟
3. 切換你想要的類別。一共恰好十六個：

| 類別                     | 觸發時機                                                               |
| ------------------------ | ---------------------------------------------------------------------- |
| 代理已完成               | 代理完成了一次執行                                                     |
| PR 已發布                | 代理發布了一個 PR                                                      |
| PR 已合併                | 某個 PR 被合併                                                         |
| 新訊息                   | 你目前沒有在看的空間收到訊息                                           |
| 在 pull request 中被提及 | GitHub 的通知輪詢發現你在某個 PR 中被提及                              |
| 已請求審查               | 某個非草稿 PR 確實請求你審查                                           |
| 審查已過時               | 你已審查過的 pull request 上出現了新提交                               |
| 可合併                   | 你撰寫的 pull request 變成可合併，或不再可合併                         |
| 審查決定                 | 審查者核准、要求變更，或核准遭到撤銷                                   |
| 檢查                     | 你撰寫的 pull request 上 CI 失敗或恢復正常                             |
| 審查討論串               | 有人在你參與的討論串中回覆，或解決了該討論串                           |
| 工單已指派               | 有工單被指派                                                           |
| 工單狀態已變更           | 有工單變更了狀態                                                       |
| 會議即將開始             | 日曆會議已進入你的提前提醒時間窗                                       |
| 日曆已中斷連線           | 已連接日曆的 OAuth 權杖已過期                                          |
| 機箱更新                 | 機箱被接管、收回或發生失敗                                             |

不在此清單中的任何事物都無法觸發通知，也無法篩選——並不存在「其他全部」這個類別。

這些偏好設定會跟著你的使用者跨裝置同步，因此手機與筆記型電腦會保持一致。音量是刻意留下的例外，依裝置各自設定。

## 設定 Quiet hours

1. 在同一頁開啟 **Quiet hours**
2. 以 `HH:MM` 格式輸入開始與結束時間（預設時間窗為 22:00–08:00）

在 Quiet hours 期間，非緊急通知會被丟棄——不會排入佇列稍後補送。

有兩個類別屬於**緊急**，一定會送達，並會繞過 Quiet hours _和_ 專注模式：**會議即將開始** 與 **PR 已發布**。事後才看到的會議提醒毫無價值，原因就在此。

## 選擇音效

1. 捲動到 **通知音效**
2. 從十一種內建音效中挑選一種，或選擇 **無**
3. 按下測試按鈕試聽，並以滑桿調整音量

音效由應用程式本身播放；作業系統通知則以靜默方式送達，因此你不會聽到兩次。

## 設定會議提前提醒時間

1. 捲動到 **提醒提前時間**
2. 選擇 **5**、**10**、**15** 或 **30** 分鐘

這就是 **會議即將開始** 通知會在日曆活動前多久觸發。預設為 5 分鐘。

## 了解通知何時會被抑制

只要符合下列任一情況，通知就會被靜默丟棄：

- 通知已全域關閉，或它的類別已關閉
- 你已經位在它會帶你前往的路由上——而若是訊息，則你已身處該空間
- 專注模式已啟用，且該類別並非緊急
- Quiet hours 已啟用，且該類別並非緊急

這些檢查適用於作業系統 Toast。持久的鈴鐺仍會記錄該事件。

另外還有兩層抑制位於更上游，取決於伺服器究竟送出什麼：

- 來自其他**人類**、未提及你的訊息永遠不會變成通知
- 代理對代理的空間在側邊欄中已靜音，因此永遠不會推升人類的未讀徽章

在一個空間內沒有安靜的角落：每段對話的通知待遇都相同，討論串也不例外。已讀狀態以空間為範圍，因此未讀數是匯總整個空間的對話，而不是按對話各自追蹤。

## 檢視並清除通知中心

1. 點按標題列中的鈴鐺

彈出面板會顯示最近的活動，並將每個項目深層連結到它所涉及的事物。開啟它**不會**把所有內容標示為已讀——請使用頂端的 **全部標示為已讀**，或標示單一列。已讀狀態會跟著你的使用者跨裝置同步。

:::note[全部清除是水位線，而不是刪除]
**全部清除** 會蓋上每位使用者的水位線，隱藏所有更舊的內容；資料列仍會保留。另外，每個工作區只保留最近的 **200** 筆動態饋送資料列，並隨著新資料列送達而汰除；而鈴鐺訂閱最新的 **50** 筆，彈出面板最多列出其中的 **15** 筆。超出這個範圍的歷史紀錄無論已讀與否都已消失。
:::

## 疑難排解

### macOS 上沒有作業系統通知

應用程式啟動時會以原生方式要求授權。如果你拒絕了，請在系統設定 → 通知中重新啟用 Control Center；應用程式內沒有可再次觸發該提示的按鈕。

### 在 Web 版本上什麼都收不到

這是預期行為——Web 版本沒有作業系統通知管線。請改用鈴鐺。

### 鈴鐺徽章顯示為零，但明顯有新的活動

在連線後已讀標記串流解析完成之前，項目會先以已讀狀態呈現，以避免徽章先閃現又隨即清空。標記載入完成後就會穩定下來。

### 代理的執行已完成，卻沒有任何通知

檢查你是否早已身處該次執行所在的空間——作用中的路由會抑制它自己的作業系統 Toast。
