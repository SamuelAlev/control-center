本指南說明如何將一個 Git 簽出註冊到工作區、重新為它建立索引，以及再次將它移除。新增來自伺服器資料夾的儲存庫需要伺服器擁有者；移除則需要工作區管理員。

儲存庫**以工作區為作用域**。這裡沒有全域登錄表，也沒有連結步驟：新增儲存庫和把它放進工作區是同一件事。同一個簽出註冊到兩個工作區後，會成為兩筆各自獨立、帶有不同 id 的資料列——跨工作區時，儲存庫的身分是它的檔案系統路徑，而絕不是它的 id。

## 開始之前

只有當以下三個條件全部成立時，資料夾才能被註冊：

1. 它位於一個 **git 工作樹**內。
2. 該工作樹設定了一個 **`origin` 遠端**。
3. `origin` 遠端指向一個**受支援的程式碼託管平台**：github.com、gitlab.com 或 bitbucket.org。

其他任何情況都會在註冊時被拒絕，並給出明確的訊息：「資料夾不在 git 工作樹內。」「此儲存庫未設定 `origin` 遠端。」或「`origin` 遠端並非託管於受支援的程式碼託管平台（github.com、gitlab.com、bitbucket.org）。」不存在僅限本機的模式。

程式碼託管平台是從遠端讀取並儲存在儲存庫上的——你從來不需要挑選它。一個工作區可以同時容納來自這三個平台的儲存庫，而每個平台都透過各自的 API 與各自的憑證溝通。GitLab 的巢狀命名空間會被保留，因此 `gitlab.com/group/subgroup/project` 註冊後的所有者為 `group/subgroup`，名稱為 `project`。

此外，該資料夾必須位於承載 `cc_server` 的機器上，且在該伺服器某個 `--repo-roots` 目錄之內。這份允許清單預設為伺服器使用者的家目錄，而瀏覽到某個根目錄之上會被拒絕。瀏覽伺服器的資料夾只提供給[伺服器擁有者](/zh-TW/手冊/概念/授權/#伺服器擁有者)，因為它列出的是機器自己的檔案。其他人會在**新增存放庫**應出現的位置看到「伺服器擁有者會從伺服器的資料夾中新增存放庫。」；而連到其任一工作區都未連結之儲存庫的連結，會說明該儲存庫並未連結到你的任何工作區，並請伺服器擁有者加以新增。

取得簽出的位置取決於由誰連結它：

- **位於伺服器上工作區自身儲存空間之內**：任何工作區管理員。
- **伺服器磁碟上的其他任何位置**：只有[伺服器擁有者](/zh-TW/手冊/概念/授權/#伺服器擁有者)，因為只有他們可以讓伺服器指向機器自己的檔案。其他人會看到「只有伺服器擁有者可以連結位於此工作區儲存空間之外的資料夾。」
- **伺服器的資料目錄或其中的任何東西**：永遠不行。

簽出的 `origin` 必須是你正在連結的儲存庫。`origin` 指向另一個儲存庫的資料夾會被拒絕，並顯示「該資料夾的 origin 指向另一個存放庫。」

### 伺服器暫不使用的資料夾

資料夾位於工作區儲存空間之外、且不是由伺服器擁有者連結的儲存庫（例如位於已匯入工作區中的儲存庫），會在其列之下顯示「此資料夾位於工作區儲存空間之外。請確認此伺服器可以使用它。」，直到伺服器擁有者確認為止。其他人則會看到「此資料夾位於工作區儲存空間之外。只有伺服器擁有者可以確認它。」來取代。

伺服器擁有者只需確認一次：在該列上按下**確認**，或在清單上方的通知中按下**全部確認**（當有多個儲存庫在等待時）。每個儲存庫都會以伺服器擁有者的身分再次檢查一次，與連結它時的檢查相同。在確認之前，它會留在清單中，但不會被開啟、佈建或建立索引：沒有任何編輯器、終端機、環境或空間簽出會使用它，程式碼圖也會略過它。以伺服器擁有者的身分再次新增同一個資料夾，效果與確認相同，並會保留該儲存庫的 id。

被符號連結移到別處的簽出，會以相同方式處理：它會保持列出且不被使用，直到被有權連結它現在所指向之資料夾的人重新連結為止。

你也需要登入該儲存庫的程式碼託管平台，而且你自己的帳號必須能看到該儲存庫。

## 註冊簽出

進行這些步驟需要伺服器擁有者身分。

1. 開啟 **設定 → 工作區 → 儲存庫**（`/workspaces/<id>/settings/workspace/repositories`）。
2. 點擊 **新增存放庫**。

這個對話框是一個可瀏覽的瀏覽器，瀏覽的是**伺服器**的檔案系統，而不是你自己的。桌面版、網頁版與手機版的流程完全相同，因為原生資料夾選擇器會在錯誤的機器上選取資料夾。

3. 在伺服器已設定的根目錄範圍內瀏覽。屬於 git 簽出的資料夾會被標示出來。
4. 勾選任意數量的資料夾。選取狀態會在你瀏覽時持續保留，因此你可以從多個資料夾蒐集簽出。
5. 將它們一次批次註冊。

某一次選取失敗絕不會拖垮批次中的其餘項目——你會取得已建立的 id，以及每個被拒絕項目對應的依路徑錯誤。重新註冊本工作區中已存在的路徑會傳回既有的儲存庫，而不會再建立一筆重複的。

每個註冊後的儲存庫都會出現在清單中，帶著它的 `owner/name`、一個標明其程式碼託管平台的徽章，以及它在伺服器上的路徑。GitHub 儲存庫還會顯示所有者的頭像；其他程式碼託管平台沒有可推測的所有者頭像 URL，因此會退回顯示姓名縮寫。

在混合了多個程式碼託管平台的工作區裡，這個徽章很重要：兩個儲存庫可以在不同平台上都叫 `acme/web`，而它們的行為並不相同——一次審查能做什麼，以及連結會連到哪裡。

## 接下來會發生什麼

註冊會觸發一個作用域限定在本工作區的 `RepoAdded` 事件，它會為該簽出啟動 `index_code` 管線。正是它充實了程式碼圖，讓搜尋與影響分析有內容可答。

只有語言已有隨附文法的檔案才會被建立索引（Dart、JavaScript、TypeScript、TSX、PHP、Python、Rust、Zig、C、C++、Go、Java、Ruby、C#、Swift、Kotlin、R、Assembly、MATLAB 與 Ada）。參見[用程式碼圖搜尋程式碼](/zh-TW/手冊/操作指南/程式碼搜尋/)。

## 重新為儲存庫建立索引

每一列都帶有一個 **建立程式碼索引** 按鈕。點擊它即可為該簽出重新執行索引器；執行期間，按鈕會變成顯示已完成檔案數與總數的進度讀數，並附有取消控制項。執行結束後，它會定為一個帶有符號數量的勾號，若執行失敗則顯示警告。

## 重新排列儲存庫

拖曳資料列上的控點。你設定的順序，就是應用程式內每個儲存庫清單讀回時所採用的順序。

## 修正 GitHub 連結

資料列上的連結圖示會開啟一個編輯器，用於編輯該儲存庫的 GitHub 所有者與儲存庫名稱。

你很少需要它。連結是綁定在該儲存庫於託管平台上的永久 id 上的，因此重新命名或轉移會被自動跟隨。

- 在 Control Center 中重新命名儲存庫只會變更其顯示名稱。
- 變更連結指向的託管平台儲存庫需要工作區管理員，並會以該管理員自己的登入對託管平台進行檢查，與連結它時相同。
- 已連結的儲存庫無法改為僅限本機的儲存庫。

若之後該路徑指向的是**另一個**儲存庫（原本的儲存庫被刪除後重新建立，或被移動並由另一個儲存庫取代），Control Center 會停止對它送出任何東西：不送權杖、不推送、不留言、不發出請求。這也涵蓋你個人的動作：你在這類儲存庫上所做的審查、合併或留言都會被拒絕，GitHub、GitLab 與 Bitbucket 皆然。資料列與該儲存庫的 pull request 會顯示「_repo_ 現在指向另一個存放庫」，直到工作區管理員按下**重新連結**為止。

## 誰可以開啟程式碼

單獨的儲存庫授權無法開啟該儲存庫的檔案。要為它開啟檔案、差異、搜尋或終端機，成員需要 Control Center 授權，而且他自己的程式碼託管平台登入必須能讀取該儲存庫。工作區管理員不享有豁免；伺服器擁有者則享有。請參見[程式碼跟隨託管平台](/zh-TW/手冊/概念/授權/#程式碼遵循託管服務)。

當你把儲存庫授權給某個託管平台帳號無法讀取它的人時，授權會被儲存，而你會看到一則警告，例如「已儲存。對方的 GitHub 帳戶目前仍無法讀取此存放庫，因此對他們保持隱藏。」

同樣的規則也決定誰能開啟空間。空間只對能開啟其使用的每一個儲存庫程式碼的成員開放，並對其他所有人隱藏，連同其中的搜尋結果、執行紀錄、待辦事項、活動與通知。沒有任何儲存庫的空間對每位成員都開放。請參見[空間隨其儲存庫而定](/zh-TW/手冊/概念/授權/#空間遵循其儲存庫)。

## 移除儲存庫

1. 開啟 **設定 → 工作區 → 儲存庫**。
2. 點擊該列上的垃圾桶圖示。
3. 確認「要從工作區移除儲存庫嗎？」

對話框會說明它會做什麼：「_name_ 將從此工作區移除。磁碟上的本機檔案不會受到更動。」

移除儲存庫需要工作區管理員。它也會忘記為該儲存庫儲存的託管平台憑證，例如 GitLab 或 Bitbucket 的自動化權杖。

移除會從本工作區刪除該儲存庫資料列，並串聯清除它的程式碼圖資料列——符號、邊、檔案與索引檢查點——以及針對它的每一項成員級儲存庫授權、它的空間與儲存庫連結，還有它的隔離簽出紀錄。同一個簽出若註冊在另一個工作區，則是一筆獨立資料列，不受影響。這些紀錄所指向的磁碟工作樹，不會因為這次刪除而被拆除。

## 疑難排解

### 我有授權，但儲存庫表示我的帳號無法讀取它

你自己的程式碼託管平台帳號無法讀取該儲存庫，因此儘管工作區已授權，Control Center 仍會讓你看不到它的程式碼。若你尚未登入，請在**設定 → 你 → 個人資料 → 程式碼託管**中登入該託管平台，或請該儲存庫在託管平台上的擁有者授予存取權限。當你的託管平台帳號能讀取該儲存庫後，它就會立即開啟。

### 「此資料夾位於工作區儲存空間之外」

該儲存庫的資料夾位於工作區儲存空間之外，且不是由伺服器擁有者連結的，或是某個符號連結現在指向了別處。它會保持列出且不被使用，直到伺服器擁有者確認它或再次新增該資料夾為止。若你不是擁有者，請詢問他們。若你是，請在該列上按下**確認**，或在清單上方按下**全部確認**；請參見[伺服器暫不使用的資料夾](#伺服器暫不使用的資料夾)。

### 「伺服器上此路徑已不存在任何東西」

資料夾已在伺服器的機器上被移動或刪除。請把它放回原處，或請工作區管理員在通知中按下**移除**移除該儲存庫，然後從其目前的資料夾重新新增。

### 「此資料夾無法作為存放庫使用」

儲存的資料夾是伺服器自己的資料目錄、其中的某個東西，或工作區儲存資料夾本身。這些都不能作為儲存庫。工作區管理員可在通知中按下**移除**將其移除，然後從該簽出的實際資料夾重新新增儲存庫。

### 「無法確認你的程式碼代管平台存取權限」

Control Center 無法連到託管平台來檢查你的帳號能否讀取該儲存庫，因此它會拒絕而不是猜測。請稍後再試一次。
