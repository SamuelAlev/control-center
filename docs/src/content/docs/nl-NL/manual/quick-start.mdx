Dit is het kortste volledige pad van niets naar een agent die op je eigen code werkt. Volg het op volgorde; elke stap bouwt voort op de vorige.

Je hebt Git nodig, een GitHub-account en ofwel een account bij een modelprovider (Anthropic, OpenAI, Codex, Cursor, Kimi Code of elke andere provider met een API-sleutel) ofwel de Claude Code CLI, al geïnstalleerd. Al het andere stel je onderweg in.

## Stap 1: Installeren en starten

Installeer Control Center zoals beschreven in [Installeren](/nl-NL/handleiding/installeren/) en open het.

Bij de eerste start vraagt de desktop-app **"Hoe moet Control Center draaien?"**. Kies **In deze app uitvoeren**. Control Center start op deze machine een headless `cc_server`, die je gegevens bezit en al het werk doet. Je krijgt hem nooit te zien; in plaats daarvan opent het onboardingscherm.

:::note[Liever niets installeren?]
Dezelfde app draait in de browser op [app.usectrl.dev](https://app.usectrl.dev) met
dezelfde functies. Een browsertab kan de server echter niet hosten, dus lever je er zelf
een aan — draai `cc_server` lokaal en verbind met `ws://localhost:9030`, of richt hem op een
server op een andere machine. Deze snelstart neemt het desktoppad, omdat daarvoor geen
server hoeft te worden ingesteld; zie [Installeren](/nl-NL/handleiding/installeren/#use-it-in-your-browser) voor de browserroute.
:::

## Stap 2: Het onboarden doorlopen

Het onboarden bestaat uit vijf stappen en ze lopen op volgorde — vooruit springen kan niet.

1. **Verbinden**: meld je aan met GitHub of plak een persoonlijk toegangstoken met `repo` en `read:org`. De inloggegevens worden op de server opgeslagen en aan je account gekoppeld.
2. **Werkruimte**: geef je eerste werkruimte een naam en kies optioneel een logo. Bij het aanmaken worden vijf agenten geseed — een CEO plus `qa`, `architect`, `engineer` en `librarian` — en de ingebouwde pipeline-sjablonen.
3. **Sandbox**: legt een sandboxvoorkeur vast. Bij beide keuzes kun je doorgaan.
4. **Adapter**: kies de adapter en het model die agenten standaard moeten gebruiken. Kies **Control Center (built-in)** en gebruik dan de providerkiezer die verschijnt om je bij een modelprovider aan te melden — de modellenlijst blijft leeg tot er een is verbonden. Met het afronden van deze stap worden de adapter en het model ook op de CEO-agent van de werkruimte vastgelegd.
5. **Stem (optioneel)**: installeer een spraakmodel op het apparaat voor dicteren, of sla deze stap over.

Control Center opent daarna het postvak van je werkruimte.

:::note[Wat een agentrun begrenst]
Agentopdrachten worden verpakt in de OS-native sandbox van de host wanneer die beschikbaar is — Seatbelt op macOS, bubblewrap op Linux. Windows heeft geen backend, dus worden runs daar alleen door de andere lagen begrensd: de eigen worktree van het gesprek (`git worktree` op Windows; copy-on-write waar `rift` meelevert), inloggegevens die per start worden bemiddeld en bij het opruimen worden ingetrokken, en de actiebeveiligingen. Zie [Sandbox en beveiliging](/nl-NL/handleiding/concepten/sandbox-en-beveiliging/).
:::

## Stap 3: Een repository toevoegen

Ga naar **Instellingen → Werkruimte → Repository's** en klik op **Repository toevoegen**.

De dialoog doorzoekt de mappen op de machine die de server draait, niet die van je client, en hij blijft binnen de roots die die server mag ontsluiten (standaard de homedirectory van zijn gebruiker). Alleen git-checkouts krijgen een selectievakje. Vink de jouwe aan en registreer hem.

Een checkout wordt alleen geaccepteerd als hij in een git-worktree staat, een `origin`-remote heeft en die remote naar een ondersteunde forge wijst — github.com, gitlab.com of bitbucket.org. Al het andere wordt met de reden geweigerd.

Repo's zijn werkruimtegebonden: een checkout die je hier registreert, komt in _deze_ werkruimte terecht. Er is geen aparte koppelstap.

## Stap 4: Een agent een adapter en een model geven

Ga naar **Instellingen → Werkruimte → Agenten**. Selecteer de agent `engineer` in de lijst.

Op het tabblad **Instellingen** stel je in:

- **Adapter**: `Control Center (built-in)`
- **Model**: kies er een van de provider die je tijdens het onboarden hebt verbonden

Klik op **Wijzigingen opslaan**.

Deze stap is in de praktijk niet optioneel. Alleen de CEO-agent erft de adapter die je tijdens het onboarden hebt gekozen; de vier specialisten worden zonder adapter aangemaakt. Ze vallen terug op **Control Center (built-in)** met het standaardmodel van Anthropic, dus ze draaien alleen als je een Anthropic-account hebt verbonden — en als je er een hebt verbonden, op een model dat je niet zelf hebt gekozen.

## Stap 5: De agent een taak sturen

1. Zoek in de zijbalk de sectie **Ruimtes** en klik op de knop **+**.
2. Geef de ruimte een naam, voeg de agent `engineer` toe onder **Agenten toevoegen** en maak hem aan.
3. Typ een concrete, kleine taak voor de repo die je hebt geregistreerd en druk op Enter.

Control Center voorziet voor dit gesprek in een copy-on-write worktree van de repo's van de werkruimte, stelt een prompt samen uit de rol, persona en skills van de agent en de context van de ruimte, en dispatcht de run. Je broncheckout wordt nooit aangeraakt.

## Stap 6: Kijken hoe hij werkt

Je zou het volgende moeten zien, in deze volgorde:

- De verzendknop van de composer verandert in een stopknop, omdat er een agent in dit gesprek werkt
- De redenering van de agent, toolaanroepen en tekst die in het transcript streamen
- De verzendknop komt terug wanneer de run eindigt

Open daarna **Instellingen → Werkruimte → Agenten**, selecteer de agent en bekijk het tabblad **Logboeken**: één runrij, met de status, duur, start- en eindtijd en de adapter waarop hij heeft gedraaid.

Dat is de lus. Al het andere in Control Center — pull-requestreview, pipelines, tickets, vergaderingen, Slack — hangt daaraan.
