Deze gids laat zien hoe je een werkruimte vult met skills van GitHub: voeg een
repository als bron toe, installeer de skills die je ervan wilt en houd ze in
de loop van de tijd actueel.

Wat je vóór je begint moet weten: **een bronrepository is onbetrouwbaar.** De
naam, beschrijving en het aantal sterren zijn geschreven door wie de repository
bezit. Het enige veiligheidssignaal dat Control Center vertrouwt, is het
oordeel van de antivirusscan, waar elke installatie doorheen gaat voordat er
iets de schijf of een agentprompt bereikt. Wil je de redenering erachter, lees
dan de [skills-sectie van het agentmodel](/nl-NL/handleiding/concepten/agentmodel/); deze
pagina blijft bij het doen.

Skills staan onder **Instellingen → Werkruimte → Vaardigheden**
(`/workspaces/<id>/settings/workspace/skills`). Ze zijn werkruimtegebonden: de
skills die je hier installeert, horen alleen bij deze werkruimte. De pagina
heeft twee tabbladen: **Geïnstalleerd** (lokale skills, inclusief een
**Nieuwe skill**-editor) en **Bronnen** (GitHub-catalogi). Beide schrijfacties
passeren dezelfde scanpoort.

## Een skillrepository toevoegen

1. Open **Instellingen → Werkruimte → Vaardigheden** en ga naar het tabblad
   **Bronnen**.
2. Klik op **Repository toevoegen**.
3. Plak een GitHub-repository-URL, bijvoorbeeld
   `https://github.com/anthropics/skills`, en bevestig.

De server controleert of de repository bestaat en met zijn inloggegevens
zichtbaar is, en voegt hem daarna toe aan de rail links. Er zit geen
gecureerde winkel tussen: elke GitHub-repository werkt, wat ook betekent dat je
de reputatie zelf moet beoordelen — een aantal sterren is een aanwijzing, nooit
een garantie.

De skills van een repository zijn de mappen die een `SKILL.md` bevatten (tot
drie niveaus diep, plus de indeling van de Claude plugin-marketplace
`plugins/<plugin>/skills/<skill>`, waarbij dependency- en vendorbomen worden
overgeslagen). Als het raster later zegt dat de repository geen skills heeft,
dan betekent dat precies dat: geen enkele map erin voldoet aan de
skillconventie.

## Een skill bekijken voordat je installeert

Selecteer een repository in de rail; de skills verschijnen rechts als een
raster, met daarboven een filterveld dat de catalogus vernauwt op naam,
beschrijving of slug. Klik op een kaart om de detailweergave te openen. Die
toont drie dingen:

- **De README**, weergegeven als markdown — de `README.md` van de skillmap, of
  de body van `SKILL.md` als er geen README is.
- **De scanpreview** — het oordeel (`pass`, `warn` of `quarantine`), de
  mogelijkheden die de inhoud van de skill opgeeft (shell uitvoeren, bestanden
  schrijven, netwerktoegang…) en elke bevinding die de scanner heeft
  vastgelegd.
- **Het bestandsaantal** — een installatie schrijft de hele map van de skill
  weg, niet alleen de `SKILL.md`.

De preview scant exact de bytes die een installatie zou wegschrijven, dus het
oordeel dat je ziet is het oordeel dat de installatie krijgt; er wordt niets
achter je rug om opnieuw beoordeeld.

## Een skill installeren

1. Open de detailweergave van de skill.
2. Lees het scanordeel. Klik bij een `warn`- of `pass`-oordeel op
   **Installeren**.
3. Bij een `quarantine`-oordeel blijft installeren uitgeschakeld tot je
   **Ik begrijp het risico — toch installeren** aanvinkt. Die override wordt
   vastgelegd, niet aangenomen.

De installatie schrijft de map van de skill in de werkruimte, legt een pin
vast in `skills-lock.json` (bronrepository, pad, de commit waar hij vandaan
kwam en een contenthash), en de skill wordt beschikbaar voor agenten in de
werkruimte. Een kaart met **Naam in gebruik** betekent dat een andere skill
die naam lokaal al bezit — verwijder die eerst.

## Skills in de loop van de tijd bijwerken

Kaarten van geïnstalleerde skills dragen badges: **Geïnstalleerd**, of
**Update beschikbaar** wanneer de repository verder is dan de commit die je
hebt vastgepind. Open de detailweergave en klik op **Bijwerken** om opnieuw op
te halen op de nieuwe commit. Een update gaat door dezelfde scanpoort als een
installatie — een skill waarvan de nieuwe versie in quarantaine raakt, wordt
geweigerd en de versie die je had blijft staan. De hash van de oude versie
wordt als rollbackreferentie in de lock bewaard.

## Een skill verwijderen, een repository verwijderen

**Verwijderen** (op de detailweergave van een geïnstalleerde skill, of
verwijderen in het tabblad **Geïnstalleerd**) haalt de map van de skill en de
lockpin samen weg — een verwijderde skill laat niets achter.

**Een repository verwijderen** uit de rail verwijdert alleen de catalogus:
skills die je ervan hebt geïnstalleerd, blijven geïnstalleerd en worden nog
steeds bijgewerkt, omdat een pin de repository bij naam vastlegt in plaats van
via een verwijzing naar het bronitem. Voeg de repository weer toe als je er
opnieuw doorheen wilt bladeren.

## Een skill aanroepen

Skills worden aangeroepen onder hun eigen namespace, zodat ze nooit botsen met
ingebouwde slash-commando’s (`/plan`, `/goal`, `/loop`, `/compact`):

- `/skill:<name>` — een skill die in deze werkruimte is geïnstalleerd, of aan
  de agent is gekoppeld
- `/skill:<repo>:<name>` — een skill die wordt meegeleverd door een repo die in
  deze ruimte is uitgecheckt

Een kale naam die niet ingebouwd is, wordt nog steeds herkend, voor berichten
die zijn geschreven voordat de namespace bestond. `/skill:plan` is wat een
skill met de naam `plan` bereikt; `/plan` is altijd de ingebouwde.

## Repo-gebonden skills

Een uitgecheckte repo kan zijn eigen skills meeleveren, in `.agents/skills/`,
`.agent/skills/`, `.claude/skills/`, `.opencode/skills/` of `skills/`. Die
worden **niet** via deze pagina geïnstalleerd. Een agent draagt alleen de
skills van de repo waarin hij op dat moment werkt; ze wisselen wanneer hij
verhuist. De composer is niet zo gebonden: `/skill:<repo>:<name>` bereikt elke
repo in de ruimte.

Reposkills doorlopen dezelfde scan die bij twijfel weigert (`pass` / `warn` /
`quarantine`) voordat hun frontmatter een prompt bereikt. `warn` wordt
toegelaten; `quarantine` wordt tegengehouden, zonder override van een operator
op dat pad.

Zie [Repo-gebonden skills](/nl-NL/handleiding/concepten/agentmodel/#repo-scoped-skills) en
[Slash-commando’s](/nl-NL/handleiding/referentie/slash-commandos/).
