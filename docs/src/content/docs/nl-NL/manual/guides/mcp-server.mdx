Deze gids laat je zien hoe je een externe MCP-client — Claude Code, een editor,
de MCP Inspector — verbindt met de eigen toolserver van Control Center.

Control Center registreert **110** tools en serveert die via het Model Context
Protocol op protocolversie `2024-11-05`. Hele toolfamilies die je zou
verwachten, ontbreken: er zijn geen vergaderings- of agendatools en geen
projecttools.

## Het endpoint vinden

Het MCP-oppervlak deelt dezelfde listener als `cc_server` zelf. Er is geen
aparte MCP-poort.

| Endpoint | Methode  | Doel                                                     |
| -------- | -------- | -------------------------------------------------------- |
| `/mcp`   | `POST`   | Streamable HTTP-transport — dit is wat een client spreekt |
| `/mcp`   | `DELETE` | Een sessie beëindigen                                    |
| `/sse`   | `GET`    | Notificatiestroom via server-sent events                 |

Een standaard lokale installatie draait dus op `http://127.0.0.1:9030/mcp`.

1. Ga naar **Instellingen → Server → MCP-servers**
2. Lees de kaart **MCP-server** — die toont **Actief** of **Gestopt** en de
   poort waarop hij luistert

Het oppervlak staat standaard aan bij een nieuwe installatie. Alleen de
serverbeheerder ziet het token op de kaart, en alleen hij kan het endpoint
starten of stoppen. **Starten bij app-lancering** bepaalt of het na een herstart terugkomt; **Starten** /
**Stoppen** gelden alleen voor de sessie en veranderen die voorkeur niet.

De server bindt standaard aan loopback, dus het endpoint is alleen bereikbaar
vanaf de machine waarop `cc_server` draait, tenzij je hem met `--bind any` hebt
gestart.

## Het token ophalen

Elke aanvraag heeft het MCP-token van de server nodig, vanaf welke machine dan ook,
ook via loopback. De server maakt het aan de eerste keer dat hij start. Er is geen
manier om het uit te zetten en geen manier om het te wissen.

1. Zoek op **Instellingen → Server → MCP-servers** de rij **Authenticatietoken**
2. Druk op **Token tonen** en kopieer het
3. Om het te vervangen, druk je op **Token vernieuwen**. De server schakelt meteen
   over op het nieuwe token, en elke client die nog het oude gebruikt, wordt
   geweigerd totdat je hem het nieuwe geeft

## Een client verbinden

Wijs je client naar het Streamable HTTP-endpoint en stuur het token mee als
`Authorization: Bearer <token>` bij elke aanvraag, ook `GET /sse`. Er is geen
andere manier om het mee te sturen: een token in de URL wordt niet geaccepteerd.
De exacte vorm van de configuratie is aan je client.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code neemt dit niet over uit een `.mcp.json` in het project — het zet
projectgebonden MCP-servers achter een goedkeuringsprompt die een
niet-interactieve `claude -p` nooit beantwoordt. Geef de configuratie expliciet
mee:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` zorgt ervoor dat Claude alleen dat bestand gebruikt,
zodat dezelfde server niet ook uit het project wordt ontdekt en tweemaal wordt
geregistreerd.

Controlepunt: vraag de client zijn tools op te sommen. Je zou `mcp__*`-vermeldingen
moeten zien die tickets, ruimtes, geheugen, codegraph en review dekken.

## Wat het endpoint weigert

Het token opent elke tool op de server, dus het endpoint weigert ook alles wat een
webpagina kan hebben gestuurd, voordat het naar het token kijkt:

| Aanvraag | Antwoord |
| -------- | -------- |
| Een `Origin`-header die geen pagina op deze machine is (`http://localhost`, `http://127.0.0.1` of `http://[::1]`, elke poort) | `403`, "Cross-origin-verzoeken worden niet geaccepteerd" |
| Een `Host`-header die niet het loopbackadres en de poort van deze listener is, en ook niet de openbare hostnaam van de server | `403`, "Onbekende host" |
| Een `POST` waarvan de body geen `application/json` is | `415` |
| Geen token, of een verkeerd token | `401` |

Om MCP buiten de host aan te bieden, start je de server met `--bind any` en stuur je
het token vanaf de andere machine, met de server aangesproken via zijn openbare
hostnaam.

## Elke aanroep aan een werkruimte koppelen

Elke tool die gegevens met werkruimtebereik aanraakt, vereist `workspace_id`; een
aanroep zonder dat veld wordt geweigerd in plaats van tegen een of andere
"huidige" werkruimte te worden opgelost:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

De id is die uit je browser- of app-URL: `/workspaces/<workspace_id>/…`. De
enige uitzonderingen zijn tools die echt werkruimteoverstijgend zijn, zoals
`list_workspaces` en de nieuwsfeed-tools — de nieuwsfeed is per gebruiker en een
agent heeft geen eigen gebruiker, dus die tools werken op de feeds van de
servereigenaar.

Tools met repobereik controleren bovendien of de repo aan die werkruimte is
gekoppeld.

## Weten wat het oppervlak weigert

- **Modusafdwinging.** Een aanroep wordt server-side bepaald aan de hand van de
  modus van de ruimte van de aanroepende agent. Een agent in een
  alleen-lezen-modus bereikt een schrijftool niet door `space_id` weg te laten —
  de modus wordt in plaats daarvan opgezocht via zijn actieve run.
- **Actiebeveiligingen.** Muterende tools declareren hun effectklassen en
  doorlopen hetzelfde beleid als de rest van het product. Zie
  [Beveiligingen configureren](/nl-NL/handleiding/gidsen/beveiligingen-configureren/).
- **Bevestiging.** Sommige destructieve tools bouwen een bevestigingspayload die
  moet worden goedgekeurd voordat de aanroep doorgaat.

De volledige catalogus wordt aangeboden in `tools/list`, zonder filtering bij de
ontdekking — een externe MCP-client weigert een tool aan te roepen die niet in
zijn gecachte lijst staat, dus tools verbergen maakt ze stuk in plaats van dat
het de lijst opruimt.

## Persoonlijke MCP-servers blijven van de eigenaar

Deze gids gaat over het eigen endpoint van Control Center. De andere richting,
MCP-servers die Control Center meegeeft aan de agents die het draait, staat onder
**Instellingen → Server → MCP-servers → Externe MCP-servers**. MCP-servers die op de
machine van de server zijn ingesteld voor Claude, Codex, Cursor, Gemini, VS Code,
Windsurf, OpenCode of in een `.mcp.json`, worden daar automatisch gevonden.

Die gevonden servers komen uit de eigen toolconfiguratie van de servergebruiker en
handelen met de identiteit en inloggegevens van die gebruiker, dus ze horen bij de
serverbeheerder:

- Ze zijn alleen beschikbaar binnen ingebouwde harness-runs die de serverbeheerder
  start of waarvoor hij verantwoordelijk is, inclusief automatisering in een
  werkruimte waarvoor de beheerder verantwoordelijk is.
- Een run van een lid, automatisering die aan een lid is gebonden, en elke run op een
  server zonder vastgelegde eigenaar krijgen er geen van. Daar worden de tools niet
  getoond, kunnen ze niet worden aangeroepen en verschijnen ze niet in de toolzoekopdracht.
- Dit endpoint toont, roept aan of doorzoekt ze nooit, voor niemand, ook niet met het
  token van de eigenaar, en het geeft hun resources of prompts niet door. Dus een
  agent-CLI die via MCP met Control Center verbindt, zoals Claude Code, krijgt ze via
  Control Center ook niet; die gebruikt zijn eigen configuratie.

MCP-servers die voor de werkruimte zijn ingesteld, worden door dit alles niet geraakt.

## Problemen oplossen

### De client ziet geen tools

- Controleer of de kaart **MCP-server** **Actief** vermeldt
- Controleer of de poort overeenkomt met je `cc_server`-poort
- Controleer bij Claude Code of je `--mcp-config` en `--strict-mcp-config` hebt
  meegegeven

### 401 Unauthorized

De aanvraag had geen token, of een oud token. Kopieer het huidige token uit de rij
**Authenticatietoken** en stuur het mee als `Authorization: Bearer <token>`. Een
token in de URL wordt genegeerd.

### 403 van een client die eerder werkte

De aanvraag had een `Origin` van een webpagina, of een `Host` waarop de server niet
antwoordt. Roep het endpoint aan vanaf een client in plaats van een browserpagina,
via het loopbackadres van de server of zijn openbare hostnaam.

### 415 Unsupported Media Type

Stuur `POST /mcp`-bodies als `application/json`.

### Een toolaanroep mislukt met "Missing or invalid argument: workspace_id"

Voeg `workspace_id` toe. Er is geen impliciete werkruimte.

### Een toolaanroep wordt geweigerd als onbekend

[MCP-tools](/nl-NL/handleiding/referentie/mcp-tools/) bevat de catalogus. Roep de
naam precies zo aan als daar staat.
