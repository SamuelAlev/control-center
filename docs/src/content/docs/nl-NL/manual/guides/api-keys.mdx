Deze gids laat zien waar elk inloggegeven dat Control Center gebruikt wordt
bewaard en hoe je het wijzigt.

**Er wordt niets opgeslagen op de machine waarop je typt.** Elk inloggegeven
staat op de server; welk gegeven een bepaald verzoek beantwoordt, hangt af van
of er een mens achter zit.

| Inloggegeven                                 | Opgeslagen                                                      | Wie gebruikt het                                                    |
| -------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------- |
| Je forge-/ticketinginloggegevens             | Het geheimenbestand van de server met modus 0600, op je gebruikers-id | Alles wat je vraagt: het PR-oppervlak, je agentruns, je afbeeldingen |
| De app-identiteit van de server              | Hetzelfde bestand, plus `server_settings` voor de niet-geheime waarden | Werk waar geen mens om vroeg: webhooks, PR-polling, ticketsynchronisatie |
| Sleutels van modelproviders en OAuth-tokens  | De eigen opslag van de server voor inloggegevens                 | De ingebouwde adapter, voor elke werkruimte op de installatie        |
| Slack-bottokens                              | `<dataDir>/<workspaceId>/chat_credentials/` op de server          | De chatbrug voor die werkruimte                                     |
| Inloggegevens van externe CLI's              | Wat die CLI ook gebruikt                                          | Claude Code, op de serverhost                                       |

## Twee GitHub-inloggegevens, en ze beantwoorden verschillende vragen

- **Die van jou**, van het aanmelden (device flow) of het plakken van een
  token. Elk verzoek dat *namens jou* wordt gedaan, gebruikt die, dus een
  reactie die voor jou wordt geplaatst, draagt je naam. Een ander lid kan hem
  niet lezen en koppelt zijn eigen inloggegevens
- **Die van de server**, van de GitHub App die de operator heeft
  geregistreerd. Die beantwoordt alles zonder aanroeper — zodat toegang tot de
  forge niet verdwijnt wanneer iemand weggaat of een token roteert

Die van jou stel je in op de kaart **Codehosting** bij **Instellingen →
Werkruimte → Profiel en identiteit**; die van de server op **Provider-apps**
bij **Instellingen → Server → Single sign-on**. Zie
[GitHub-integratie instellen](/nl-NL/handleiding/gidsen/github-integratie/) en
[De GitHub App maken](/nl-NL/handleiding/gidsen/github-app/).

:::note[Er is ook een scherm dat alleen via de URL bereikbaar is]
`/workspaces/<workspaceId>/api-keys` rendert dezelfde twee kaarten als de
eerste stap van onboarding. Het heeft **nergens in de UI een navigatie-item**;
je bereikt het alleen door de URL te typen. Gebruik in plaats daarvan
Instellingen → Werkruimte → Profiel en identiteit.
:::

## Sleutels voor modelproviders instellen

De ingebouwde adapter authenticeert providers zelf en die inloggegevens staan
op de server.

1. Ga naar **Instellingen → Server → Modelaanbieders**
2. Scroll naar **Providers en modellen**
3. Verbind de provider — OAuth via de browser voor OpenAI, Codex, Cursor en
   Kimi Code; een API-sleutel voor Anthropic en de rest

Zie [Adapters en modellen beheren](/nl-NL/handleiding/gidsen/adapters/) voor de
volledige lijst en voor het toevoegen van een aangepast endpoint.

Deze inloggegevens zijn **host-globaal**: één sleutel bedient elke werkruimte op
de installatie. OAuth-tokens worden vernieuwd voordat ze verlopen.

Externe adapter-CLI's houden hun eigen inloggegevens bij, in hun eigen
configuratie, op de serverhost — Control Center beheert ze niet. Authenticeer
Claude Code zoals de eigen documentatie voorschrijft, op de machine waarop
`cc_server` draait.

Het venster **Omgevingsvariabelen** per adapter lijkt een plek om een sleutel
voor een van hen neer te zetten, maar dat is het niet: het schrijft naar je
apparaat, terwijl de server zijn eigen kopie leest en niets de twee overbrugt.
Zie [Adapters en modellen beheren](/nl-NL/handleiding/gidsen/adapters/).

## Een ticketingprovider verbinden

De kaart **Tickets** bij **Instellingen → Werkruimte → Algemeen** bevat beide
helften van één beslissing: bij welke leverancier je tickets staan, en de
inloggegevens daarvoor. Als je **Lokaal** kiest, verdwijnt de rij met
inloggegevens — lokale tickets staan in de eigen database van deze server en er
valt niets te authenticeren.

Je sleutel wordt, net als die voor de forge, op de server bij je gebruikers-id
opgeslagen. De server houdt zijn eigen Linear-sleutel apart (**Provider-apps**),
en die wordt gebruikt voor ticketsynchronisatie wanneer geen mens erom vroeg.
In de sandbox van een agent wordt geen ticketingsleutel geïnjecteerd; agenten
schrijven tickets via de tools van Control Center, die de regel **Naar een
externe tracker schrijven** raadplegen. Zie
[Linear-integratie instellen](/nl-NL/handleiding/gidsen/linear-integratie/).

## Roteren of intrekken

- **Je GitHub-inloggegevens**: klik op **Loskoppelen**, meld je daarna opnieuw
  aan of plak het nieuwe token. Trek het oude in bij GitHub
- **De app van de server**: genereer een nieuwe privésleutel of een nieuw
  clientsecret op de GitHub-pagina van de app, plak die in **Provider-apps** en
  klik op **Testen**
- **Een modelprovider**: meld je op zijn rij af (OAuth) of verwijder de sleutel,
  en maak daarna opnieuw verbinding
- **Slack**: plak de tokens opnieuw in het verbindingsvenster. Zie
  [Slack-integratie instellen](/nl-NL/handleiding/gidsen/slack-integratie/)

## Problemen oplossen

### De PR-lijst is leeg, maar mijn token werkt in `curl`

Controleer de ondertitel van de rij **Codehosting**. Als daar een andere bron
staat ("via de app van deze server", "uit de omgeving"), dan is het
inloggegeven dat je test niet degene die antwoordt — die van jou zijn niet
opgeslagen.

### Het token wordt geaccepteerd, maar latere verzoeken mislukken

Het token wordt getest zoals het is opgeslagen, dus de rij noemt het account
dat erachter zit — maar alleen het account, niet de scopes. Een token met te
weinig scopes maakt verbinding en laat daarna afzonderlijke verzoeken
mislukken. Controleer de scopes en de vervaldatum:

```bash
curl -H "Authorization: token YOUR_TOKEN" https://api.github.com/user
```
