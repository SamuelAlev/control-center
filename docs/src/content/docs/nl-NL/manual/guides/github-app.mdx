Deze gids laat zien hoe je je server een eigen GitHub App geeft. Het kost
ongeveer twee minuten, alleen de servereigenaar doet het, en het hoeft maar
één keer per server te gebeuren.

:::note[Misschien heb je het niet nodig]
Met Control Center Connect ingeschakeld melden mensen zich bij GitHub aan via
de gedeelde App van Control Center, of via de App die de Connect van je
organisatie gebruikt. Registreer je eigen app als je **Mijn eigen apps
gebruiken** hebt gekozen: de app van de server geldt alleen in dat geval. Zie
[Control Center Connect](/nl-NL/handleiding/referentie/connect/).
:::

Voor het daarna aanmelden bij je eigen account, zie
[GitHub-integratie instellen](/nl-NL/handleiding/gidsen/github-integratie/).

## Wat de app doet

Eén registratie beantwoordt twee verschillende taken:

| Taak                    | Wat het beantwoordt                                     | Waarom het ertoe doet                                                                           |
| ----------------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **Een persoon logt in** | De client-id en het client-secret van de app            | Iedereen krijgt eigen GitHub-inloggegevens, op de server, op elk apparaat                       |
| **De server handelt**   | Het id en de privésleutel van de app                    | Agenten, pipelines, pollers en botantwoorden krijgen tokens voor telkens één repository         |

De tweede taak leent nooit de inloggegevens van een persoon in hun geheel. Elk
token dat de server uitgeeft, dekt één repository en is beperkt tot wat een
verantwoordelijk lid daar mag doen. Een gekoppelde repository lezen vraagt alleen
de app; alles wat schrijft, vraagt een lid dat mag pushen. Automatisering keurt
nooit een pull request goed.

De app van de server geldt alleen onder **Mijn eigen apps gebruiken**. Met de Connect van Control Center of een eigen Connect verzorgt Connect GitHub, en de app van de server blijft opgeslagen maar ongebruikt tot je terugschakelt. Een werkruimte op eigen apps ([Eén werkruimte een eigen app geven](#eén-werkruimte-een-eigen-app-geven)) gebruikt in plaats daarvan de eigen app, ongeacht de modus van de server. Een app waarvan
velden ontbreken, is een fout en geen terugval: GitHub-aanmeldingen worden
geweigerd tot elk veld is ingesteld.

## Vereisten

- Je bent de **servereigenaar**. De kaart **Provider-apps** is voor iedereen
  anders onzichtbaar
- Een GitHub-account. De app wordt daaronder aangemaakt
- Een serveradres dat je browser kan bereiken. De openbare URL van de server (of
  loopback, voor de eigen server van een desktop) is waar GitHub je naar
  terugstuurt

## Met één klik aanmaken

1. Ga naar **Instellingen → Server → Single sign-on** en scroll naar de kaart
   **Provider-apps**
2. Vul in het blok **GitHub** eventueel bij **Organisatie (optioneel)** de
   GitHub-organisatie in die eigenaar van de app moet worden. Laat het leeg om de
   app onder je eigen account te maken; voor een organisatie is een owner van die
   organisatie nodig
3. Klik op **Mijn GitHub-app maken**
4. Je browser opent GitHub met de app al ingevuld. Klik op
   **Create GitHub App**
5. GitHub stuurt je terug naar de server, die het app-id, de privésleutel, de
   client-id en het client-secret opslaat en daarna de installatiepagina van de
   app opent

Er wordt niets met de hand gekopieerd, en de conversiecode gaat rechtstreeks van
GitHub naar je server. De link werkt één keer en verloopt na tien minuten; is hij
verlopen, klik dan opnieuw op **Mijn GitHub-app maken**.

De app heet `Control Center <code>` en vraagt precies wat Control Center
gebruikt:

| Machtiging                                 | Toegang             |
| ------------------------------------------ | ------------------- |
| Metadata                                   | Lezen               |
| Contents                                   | Lezen en schrijven  |
| Pull requests                              | Lezen en schrijven  |
| Issues                                     | Lezen en schrijven  |
| Checks, Actions, Commit statuses           | Lezen               |
| Organization members                       | Lezen               |

Webhooks staan uit: de server pollt. Gebruik **Transfer ownership** in de
geavanceerde instellingen van de app op GitHub om een app die je onder je eigen
account hebt gemaakt later naar een organisatie te verplaatsen.

Checkpoint: bij het GitHub-blok staat "De server kan namens zichzelf handelen en
mensen kunnen inloggen."

## Installeren waar je repository's staan

Een app die is geregistreerd maar niet geïnstalleerd, kan mensen aanmelden en
niets lezen.

1. Kies op de installatiepagina die GitHub opende het account of de organisatie
   die eigenaar is van je repository's
2. Kies **All repositories**, of selecteer de repo's die deze server mag zien

Om hem later op een ander account te installeren, gaat een beheerder van de
werkruimte naar **Instellingen → Werkruimte → Integraties**, zoekt **Installaties
van de GitHub-app** op de kaart **GitHub-app** onder Codehosting en klikt op **GitHub-app
installeren**. De lijst toont elk account waarop de app is geïnstalleerd en
markeert een opgeschorte installatie.

## De installatie van een organisatie delen

Een organisatie installeert de GitHub App één keer. Daarna kan iedereen in de organisatie die op een Control Center-server bij GitHub aanmeldt, de installatie gebruiken, welke server dat ook is: die van jou, die van een collega of een eigen server. Er hoeft per server niets geautoriseerd te worden.

Elk token dat een server krijgt, is van de ingelogde persoon zelf, beperkt tot één repository en tot de rol van die persoon daarin, dus het reikt nooit verder dan wat die persoon op GitHub zelf zou kunnen. Het auditlogboek van GitHub toont die persoon, die via de app handelt.

Om te voorkomen dat Control Center een organisatie bereikt, verwijdert een eigenaar van de organisatie de installatie of beperkt de repositories op GitHub. Iemand uit de organisatie verwijderen stopt ook zijn of haar toegang.

## In plaats daarvan met de hand registreren

De kaart **Provider-apps** neemt de waarden ook direct aan, voor een app die je
zelf hebt geregistreerd:

| Groep                        | Velden                                                                                          |
| ---------------------------- | ----------------------------------------------------------------------------------------------- |
| **Handelen als de server**   | **App-id** en **Privésleutel** (het hele `.pem`-bestand, inclusief de regels `BEGIN` en `END`)  |
| **Mensen aanmelden**         | **Client-id** en **Client-secret**. **Callback-URL’s** toont de URL die je letterlijk registreert |
| **Pullrequest-gesprekken**   | **Bot-login**, bepaald wanneer je de verbinding test                                            |

Registreer de callback-URL `<server origin>/oauth/github/callback` precies zoals
de kaart die toont, laat **Expire user authorization tokens** aan staan en ken de
machtigingen uit de tabel hierboven toe. Klik op **Testen**: het vraagt GitHub op
welke accounts de app is geïnstalleerd, zodat "opgeslagen" en "werkt" niet
worden verward.

## Configureren vanuit de `.env` van de server

Voor een headless of gescripte installatie vult de server elk veld vanuit zijn
`.env`-bestand de eerste keer dat er nog geen opgeslagen waarde is:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

Zet de sleutel op **één regel**: een waarde in `.env` is één regel, en `\n`
tussen dubbele aanhalingstekens wordt gedecodeerd naar een nieuwe regel. De
server weigert te starten wanneer `GITHUB_APP_PRIVATE_KEY` of
`GITHUB_CLIENT_SECRET` in zijn procesomgeving is geëxporteerd, waar elk
kindproces het kan lezen; bewaar ze in het `.env`-bestand (koppel het in Docker
aan `/app/bin/.env`). Het vullen gebeurt **één keer per veld**, dus een
bewerking in Instellingen wordt niet ongedaan gemaakt door de volgende herstart.

## Eén werkruimte een eigen app geven

Een werkruimte kan op een eigen app draaien in plaats van die van de server:

1. Een beheerder van de werkruimte gaat naar **Instellingen → Werkruimte → Integraties**
2. Op de kaart **Control Center Connect** kiest die **Mijn eigen apps gebruiken** en klikt op **Toepassen**. Iedereen in de werkruimte meldt zich opnieuw aan via de apps van de werkruimte
3. De kaart **GitHub-app** onder Codehosting bevat nu de velden van de app: **App-id** en **Privésleutel** onder **Handelt namens deze werkruimte**, **Client-id** en **Client-secret** onder **Mensen aanmelden**. Klik op **Testen** zodra ze zijn ingevuld

Leden melden zich dan voor deze werkruimte bij die app aan. Een werkruimte met eigen apps valt nooit terug op de app van de server of op Connect: zolang de velden niet compleet zijn, wordt het GitHub-werk ervan geweigerd. Dezelfde keuze geldt voor Google Agenda, Linear en GIF-zoeken, elk met de eigen velden naast de provider op dezelfde pagina. Zie [Geef één werkruimte een eigen Linear-app](/nl-NL/handleiding/gidsen/linear-integratie/#geef-één-werkruimte-een-eigen-linear-app) en [Geef één werkruimte een eigen Google-client](/nl-NL/handleiding/gidsen/agenda-verbinden/#geef-één-werkruimte-een-eigen-google-client). De andere keuzes op die kaart, en wat elk ervan doet, staan in [Keuze per werkruimte](/nl-NL/handleiding/referentie/connect/#keuze-per-werkruimte).

## Probleemoplossing

### Mijn GitHub-app maken zegt dat de server geen adres heeft

De server heeft geen openbare URL waar een browser naar terug kan keren. Stel
`CC_SERVER_PUBLIC_URL` (of `--public-url`) in en probeer het opnieuw.

### GitHub zegt dat de link is verlopen

De eenmalige pagina is al gebruikt, of er zijn tien minuten verstreken. Begin
opnieuw vanuit Instellingen.

### Testen zegt dat de inloggegevens werken, maar de app is nergens geïnstalleerd

Registratie en installatie zijn aparte stappen. Open de installatiepagina van de
app, of gebruik **GitHub-app installeren** in Werkruimte → Integraties.

### Testen zegt dat de privésleutel niet kon worden gelezen

Plak het hele `.pem`-bestand, inclusief de regels `-----BEGIN` en `-----END`. Een
`ed25519`- of EC-sleutel kan niet worden gebruikt: GitHub Apps ondertekenen met
RSA.

### Een lid is ingelogd maar ziet geen repositories

De app is niet geïnstalleerd op het account dat eigenaar is van die repositories,
of de installatie ervan selecteert andere repositories. Een aanmelding geeft
alleen toegang tot wat de app mag zien.

### Agenten zeggen dat de installatie van de GitHub App is opgeschort

Iemand heeft de installatie op GitHub opgeschort. Hef de opschorting op in
**Settings → Applications → Installed GitHub Apps** van het account.
