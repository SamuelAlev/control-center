Deze gids behandelt de GitHub-specifieke delen van de installatie. GitHub is een
van de drie ondersteunde codehosts. Zie
[Een codehost verbinden](/nl-NL/handleiding/gidsen/codehost-verbinden/) voor het
verbinden van GitLab of Bitbucket, en voor hoe één werkruimte ze door elkaar
gebruikt.

## Vereisten

- Een GitHub-account met toegang tot de repo's waaraan je wilt werken
- Een server die mensen bij GitHub kan aanmelden: ofwel met zijn eigen GitHub
  App (zie [De GitHub App maken](/nl-NL/handleiding/gidsen/github-app/)), ofwel
  via Control Center Connect, gekozen door de servereigenaar in **Instellingen →
  Server → Single sign-on**

:::note[Inloggegevens staan op de server, aan jou gekoppeld]
Er wordt niets opgeslagen op de machine waarop je typt. Je GitHub-aanmelding
wordt vastgehouden door je `cc_server`, gekoppeld aan je gebruikers-id, en elk
apparaat waarmee je je aanmeldt gebruikt die: desktop, web en telefoon. Een ander
lid van dezelfde server kan hem niet gebruiken, en zich aanmelden doet ieder voor
zich.
:::

## Inloggen bij GitHub

GitHub kent alleen aanmelden: er is geen token om te plakken.

1. Ga naar **Instellingen → Werkruimte → Profiel en identiteit → Codehosting** (of
   de eerste stap van de onboarding)
2. Klik in de rij **GitHub** op **Inloggen bij GitHub**
3. Je browser opent GitHub. Keur de app goed

Hoe de aanmelding afloopt, hangt af van wie hem uitvoert:

- **De eigen app van de server:** GitHub stuurt je browser terug naar de server
  en het dialoogvenster merkt dat vanzelf. Niets te typen
- **Control Center Connect:** de browserpagina toont een code van 8 tekens. Typ
  die in het dialoogvenster, of laat de browser Control Center openen via de
  `control-center://`-link en sla het typen over

Controlepunt: in de rij **GitHub** staat "Ingelogd als _your-username_".

Het dialoogvenster weigert een code of link die het niet zelf heeft gestart, met
**Inloggen niet hier gestart**. Stuurt iemand je een aanmeldlink, ga dan niet
verder: als je die afrondt, wordt je account aan diens server gekoppeld.

Klik op **Loskoppelen** om je aanmelding te verwijderen. Als je je afmeldt bij
GitHub of uit een werkruimte wordt verwijderd, vervalt ook elk token dat de
server namens jou heeft uitgegeven.

## Namens wie je inloggegevens spreken

- **Alles wat jij doet** (de PR-pagina openen, een review plaatsen, goedkeuren,
  mergen) draait op **jouw** aanmelding en niets anders. Ben je niet aangemeld,
  dan zegt de app dat en vraagt je je aan te melden. Geen ander inloggegeven
  springt voor je in
- **Werk waarbij niemand typt** (agentruns, pipelines, PR-polling,
  botantwoorden, clones) krijgt een token voor één repository, uitgegeven via de
  GitHub App van de server of via Connect. Het is beperkt tot wat een
  verantwoordelijk lid daar mag doen: het lid dat het vroeg, anders de eigenaar
  van de werkruimte. Een lid dat niet mag pushen, beperkt het token tot lezen
- **Automatisering keurt nooit** een pull request goed. Goedkeuren is een
  handeling van een persoon

## Wat de integratie je oplevert

| Functie                    | Hoe                                                                                                            |
| -------------------------- | -------------------------------------------------------------------------------------------------------------- |
| PR-lijst en -detail        | De GitHub REST API, vanaf de server, op je eigen aanmelding                                                    |
| Check-runs                 | De GitHub Checks API                                                                                           |
| Review publiceren          | Een door de gebruiker gestarte stap die je review namens jou op de PR plaatst                                   |
| Reporegistratie            | Een checkout wordt geaccepteerd als zijn `origin`-remote naar github.com wijst, of naar gitlab.com / bitbucket.org |
| GitHub-toegang voor agenten | Een token voor de ene repository van de run als `GH_TOKEN` / `GITHUB_TOKEN`; pushes lopen via Control Center |
| Meldingspings              | Een poll aan de serverkant van je GitHub-meldingspostvak levert "Vermeld in een pull request" en "Review aangevraagd" op |
| Gebruikersprofielen        | Profielkaarten bij hover en PR-filtering per auteur                                                            |

Sommige paden gebruiken de GraphQL API in plaats van REST waar dat goedkoper is:
branchactiviteit voor de picker bij het opstellen van een PR en de actuele
reviewstatus die bepaalt of een melding "Review aangevraagd" nog openstaat.

## Houd GitHub-storingen in de gaten

De titelbalk toont een statuschip wanneer een provider in de problemen zit, voor
GitHub, Claude, OpenAI en Kimi. **Hij blijft verborgen zolang alles gezond is**:
aanwezigheid meldt een storing, niet het uitblijven ervan.

Klik op de chip om een flyout te openen met de status van elke provider en een
knop om te vernieuwen. De statussen vernieuwen vanzelf elke twee minuten.

## Weet hoe agenten op GitHub handelen

- Een agent die in een GitHub-worktree werkt, krijgt een token voor die ene
  repository. Het kan de code lezen en opmerkingen plaatsen op pull requests als
  het verantwoordelijke lid mag pushen, en alleen lezen als dat niet zo is. Een
  push loopt via Control Center, dat de regel **Naar een
  remote pushen** raadpleegt en hem daarna doorstuurt met een schrijftoken dat
  de agent nooit in handen heeft. Zie
  [Sandboxbeleid configureren](/nl-NL/handleiding/gidsen/sandboxbeleid/)
- Commits van agents gebruiken altijd de Git-identiteit van de aanvrager als auteur én committer. Standaard vermeldt de trailer `Co-Authored-By: Control Center <hi@usectrl.dev>` GitHub `@usectrl` als mede-auteur. Via **Instellingen → Jij → Toeschrijving van commits** kun je deze mede-auteursvermelding uitschakelen zonder je identiteit te wijzigen. Een werkruimte-instelling onder **Instellingen → Werkruimte → Algemeen** gaat voor en vergrendelt de persoonlijke knop. De eigen auteursvermelding van Claude Code is altijd uitgeschakeld. Voor commitondertekening blijft een eigen geldige configuratie nodig
- Een terminal die je op een rig opent, krijgt je eigen aanmelding, beperkt tot
  die ene repository, dus pushes daar zijn van jou
- Als er geen token kan worden uitgegeven (niemand die verantwoordelijk is, is
  aangemeld, de app is niet geïnstalleerd bij de eigenaar, of de installatie is
  opgeschort), start de run zonder, en zijn notities vermelden waarom. Er zijn
  geen reserve-inloggegevens

## Problemen oplossen

### De PR-lijst is leeg en zegt dat GitHub niet is verbonden

Je bent op deze server niet bij GitHub aangemeld. Klik op **Inloggen bij GitHub**
onder **Codehosting**. Repos op andere forges blijven onaangetast.

### De rij GitHub zegt dat aanmelden op deze server niet is ingesteld

De server heeft geen eigen GitHub App en ook geen Connect. De servereigenaar kiest
er een in **Instellingen → Server → Single sign-on**: **Mijn GitHub-app maken**
kost ongeveer twee minuten. Zie
[De GitHub App maken](/nl-NL/handleiding/gidsen/github-app/).

### Het dialoogvenster zegt dat de code niet klopt

Typ de code precies zoals de browser hem toont: 8 letters en cijfers. Vijf foute
codes beëindigen de aanmelding; start hem opnieuw.

### De aanmelding zegt dat de app niet is geïnstalleerd

De GitHub App heeft geen installatie op het account dat eigenaar is van de
repository. Een beheerder van de werkruimte installeert hem via **Instellingen →
Werkruimte → Algemeen → Installaties van de GitHub-app**. Voor een organisatie op
de gedeelde App van Control Center moet een beheerder van die organisatie
mogelijk op **Deze server autoriseren** klikken. Zie
[De GitHub App maken](/nl-NL/handleiding/gidsen/github-app/#deze-server-autoriseren-voor-een-organisatie).

### Iedereen moet zich opnieuw aanmelden bij GitHub

De servereigenaar heeft de Connect-sleutel van de server vervangen of is van
Connect-server gewisseld, of de gegevensmap is op een andere machine hersteld.
Aanmeldingen via Connect zijn gebonden aan de server die ze heeft gemaakt.

### Een repo toevoegen wordt geweigerd

Registratie vereist alle drie: het pad ligt binnen een git-worktree, er is een
`origin`-remote, en die remote wijst naar een ondersteunde forge (github.com,
gitlab.com of bitbucket.org). Zie
[Repos toevoegen aan een werkruimte](/nl-NL/handleiding/gidsen/repos-toevoegen/).

### Alles stopt een tijdje met werken na zwaar gebruik

Dat is de circuit breaker voor de limiet. GitHub meldt zijn primaire limiet met
een `403` met daarin `x-ratelimit-remaining: 0` en een resettijd; zodra de client
die ziet, laat hij verdere aanvragen lokaal mislukken zonder netwerkoproep tot het
venster is verstreken, zodat een storm van herhaalpogingen de limiet niet kan
verzwaren. Tijdelijke fouten worden tot drie keer opnieuw geprobeerd met
exponentiële backoff, met respect voor `retry-after`.
