Deze gids laat zien hoe je modelproviders verbindt en kiest waarop een agent
draait.

Alles wat hier wordt beschreven staat op één pagina: **Instellingen → Server →
Modelaanbieders**. De vermelding in de subsidebar heet "Modelaanbieders"; de
paginakop heet "Adapters".

## Wat een adapter is

Een adapter is de _runner_ die een agentbeurt uitvoert. Er zijn er twee en de
lijst ligt vast — je kunt geen derde toevoegen.

| Adapter                   | CLI      | Transport                                                  |
| ------------------------- | -------- | ---------------------------------------------------------- |
| Control Center (built-in) | geen     | In-process agentloop, praat via HTTP met providers         |
| Claude Code               | `claude` | `claude -p --output-format stream-json`                    |

Cursor, Codex, Anthropic, OpenAI en de rest zijn **providers** op de ingebouwde
adapter, geen afzonderlijke CLI's. Wat je wél kunt toevoegen is nog een provider
— elk OpenAI- of Anthropic-compatibel endpoint. Dat komt in de volgende sectie.

:::note[Detectie probeert de server, niet jouw machine]
De kaart **Gedetecteerde runners** laat zien wat `cc_server` op het `PATH` van de
_serverhost_ heeft gevonden. Op een thin client of webclient is dat een andere
machine dan degene waar je naar kijkt. Installeer de CLI op de machine die
`cc_server` draait.
:::

## Een modelprovider verbinden

De ingebouwde adapter heeft minstens één verbonden provider nodig voordat hij kan
draaien. Er zitten er veertien in de catalogus.

1. Ga naar **Instellingen → Server → Modelaanbieders**
2. Scroll naar **Providers en modellen**
3. Zoek je provider en verbind hem:

| Provider                                                                                                 | Hoe je verbindt                                                                                                               |
| -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Anthropic                                                                                                | API-sleutel. Een Claude Pro/Max-abonnement is geen Anthropic API-login — gebruik voor dat abonnement de Claude Code-adapter   |
| OpenAI, Codex, Cursor                                                                                    | OAuth-login in de browser, of een API-sleutel. Codex is ChatGPT Plus/Pro via de Codex Responses-backend, geen CLI-spawn       |
| Kimi Code                                                                                                | Alleen OAuth in de browser — een device-codeflow. Het is een abonnement met vast tarief, dus er is geen prijs per token       |
| OpenRouter, Google Gemini, DeepSeek, Mistral, xAI, z.ai, z.ai GLM Coding Plan, Moonshot (Kimi API)       | API-sleutel                                                                                                                   |

Controlepunt: de badge van de rij verandert naar verbonden en als je de rij
uitklapt, zie je de modellen die de provider aanbiedt, elk met zijn prijs per
miljoen tokens en zijn contextvenster.

OAuth-tokens belanden in de eigen referentieopslag van de server en worden
vernieuwd voordat ze verlopen. Providerreferenties zijn **host-globaal** — elke
werkruimte op de installatie deelt ze; ze zijn niet aan één werkruimte gebonden.

### Een aangepaste provider toevoegen

Gebruik dit voor Ollama, LM Studio, vLLM of een privé-implementatie.

1. Druk in **Providers en modellen**, onder **Aangepaste providers**, op
   **Provider toevoegen**
2. Vul een **naam** in, kies het **API-type** (OpenAI-compatibel of
   Anthropic-compatibel) en geef de **Basis-URL** op (bijvoorbeeld
   `http://localhost:11434/v1`)
3. Voeg een **API-sleutel** toe als het endpoint er een nodig heeft, en druk dan
   op **Provider toevoegen**

Een aangepaste provider verschijnt in dezelfde lijst, met een verwijderknop die
de ingebouwde providers niet hebben.

## Een model kiezen voor een agent

1. Ga naar **Instellingen → Werkruimte → Agenten** en selecteer de agent
2. Kies op het tabblad **Instellingen** de **adapter**
3. Kies het **model** in de keuzelijst ernaast

Voor de ingebouwde adapter wordt de keuzelijst live samengesteld uit de eigen
catalogus van elke verbonden provider. Een provider zonder opgeslagen referentie
levert nul modellen, en daarom betekent een lege keuzelijst bijna altijd "nog
niets verbonden" in plaats van "niets beschikbaar".

:::note[models.dev is verrijking, nooit een bron van id's]
De meegeleverde [models.dev](https://models.dev)-catalogus levert de prijs en het
contextvenster voor een model dat al in de live lijst staat. Hij voegt nooit een
model-id toe. Als een model dat je verwacht ontbreekt, geeft het endpoint van de
provider het niet terug.
:::

Model-id's voor de ingebouwde adapter zijn gekwalificeerd als `provider/model` en
kunnen een fallbackketen bevatten die met `|` wordt gescheiden. Bij een fallback
worden de kosten afgerekend op het model dat de beurt werkelijk heeft
afgehandeld, niet op het model dat je hebt opgevraagd.

:::note[Een agent zonder adapter draait op de ingebouwde loop]
Elke werkruimte maakt standaard vijf agenten aan — een CEO plus `qa`, `architect`,
`engineer` en `librarian` — zonder adapter en zonder model. Dispatch valt terug
op **Control Center (built-in)**, niet op de instelling **Standaard-runners** op
deze pagina; dat is een clientvoorkeur die het dispatchpad nooit leest. Het runlog
registreert `cc-harness` voor die runs, zodat het transcript vermeldt wat er
werkelijk draaide.

Zonder model erbij vraagt de ingebouwde loop Anthropic om zijn standaardmodel. Een
agent die volledig oningesteld blijft, draait dus als je een Anthropic-account
hebt verbonden, en mislukt anders met `No credential for provider "anthropic"`.

Als je de adapterstap van de onboarding afrondt, worden **alle** agenten die nog
geen adapter of model hebben — de CEO en de specialisten, in elke werkruimte die
op dat moment bestaat — bijgewerkt met het paar dat je hebt gekozen. Werkruimtes
die later worden aangemaakt, maken nog steeds alle vijf oningesteld aan. Stel de
adapter en het model expliciet in op elke agent die je wilt gebruiken.
:::

## Een runner-CLI installeren

De ingebouwde adapter hoeft niet te worden geïnstalleerd. Installeer voor Claude
Code de CLI **op de serverhost** met de eigen pakketbeheerder van dat hulpmiddel,
bijvoorbeeld:

```bash
npm install -g @anthropic-ai/claude-code
```

Druk daarna boven aan de pagina op **Vernieuwen**. Elke gedetecteerde rij toont de
gevonden versie en het pad, plus chips die aangeven of JSON-modus en
modelselectie worden ondersteund.

Een externe CLI houdt zijn eigen referenties bij, in zijn eigen configuratie, op
de serverhost. Control Center beheert ze niet.

:::caution[Adapterargumenten en omgevingsvariabelen blijven op dit apparaat]
Elke adapterrij biedt een veld **Extra argumenten** en een dialoogvenster
**Omgevingsvariabelen**. Die waarden worden op jouw apparaat opgeslagen. De server
leest de opstart-argv en env uit zijn eigen instellingenopslag. Zet
providersleutels op de server (OAuth of het sleutelveld op de pagina
Modelaanbieders), niet in die twee velden.
:::

## Beperken welke providers een werkruimte mag gebruiken

Providerbesturing is per werkruimte en wordt geëvalueerd volgens het principe dat
de laatste overeenkomst wint.

1. Zet in **Providers en modellen** de schakelaar **Toestaan** op een providerrij
   uit

Daarmee wordt een `deny`-statement voor die provider in de actieve werkruimte
geschreven, en zijn modellen verdwijnen uit de catalogus van die werkruimte. Zet
je de schakelaar weer aan, dan verdwijnt het statement.

## Problemen oplossen

### Een runner verschijnt als niet gevonden

- Controleer of de CLI op het `PATH` van de **serverhost** staat, niet alleen op
  dat van jou
- Een desktopapp die vanuit de GUI wordt gestart, start zijn server met een
  minimaal `PATH`; een CLI die alleen via een shellpad te vinden is, kan daarvoor
  onzichtbaar zijn
- Druk na de installatie op **Vernieuwen**

### De modelkeuzelijst is leeg

- De adapter is de ingebouwde en er is geen provider verbonden — verbind er een in
  **Providers en modellen**
- Of de provider is verbonden, maar wordt geweigerd door de besturingsschakelaar
  van deze werkruimte

### Een model draait, maar de prijs verschijnt als onbekend

De live modellenlijst bevat het id; prijs en context komen van models.dev. Een
gloednieuw model, of een model van een aangepaste provider, heeft nog geen
catalogusvermelding.
