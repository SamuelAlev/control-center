Deze gids laat je zien hoe je meldingen configureert en wat elke instelling
werkelijk bepaalt.

Meldingen komen binnen op twee oppervlakken. Het **meldingencentrum** — de bel in
de titelbalk — leest een blijvende feed per werkruimte op de server. **OS-toasts**
zijn een apart pad, alleen op de desktop, gevoed door live-frames die de server
doorstuurt.

:::note[De webbuild toont geen OS-meldingen]
De toast-pipeline wordt alleen door de desktop-bootstrap opgebouwd. Op
`app.usectrl.dev` zijn er geen OS-toasts, geen meldingsgeluiden en geen ambient
banners — de bel en zijn geschiedenis werken nog wel, omdat ze de feed op de
server lezen. De telefoonclient heeft helemaal geen meldingsoppervlak.
:::

## Categorieën aan- of uitzetten

1. Ga naar **Instellingen → Jij → Meldingen**
2. Laat **Meldingen inschakelen** aan staan
3. Zet de categorieën aan die je wilt. Het zijn er precies zestien:

| Categorie                  | Wordt geactiveerd wanneer                                                   |
| -------------------------- | --------------------------------------------------------------------------- |
| Agent voltooid             | Een agent heeft een run afgerond                                            |
| PR gepubliceerd            | Een agent heeft een PR gepubliceerd                                         |
| PR samengevoegd            | Een PR is samengevoegd                                                      |
| Nieuwe berichten           | Er is een bericht aangekomen in een ruimte waar je niet naar kijkt          |
| Vermeld in een pull request | De meldingspoll van GitHub zag dat je in een PR werd vermeld               |
| Review aangevraagd         | Je review is daadwerkelijk aangevraagd voor een PR die geen concept is      |
| Review verouderd           | Er zijn nieuwe commits geland op een pull request die je al hebt gereviewd  |
| Klaar om te mergen         | Een pull request die jij hebt gemaakt is mergebaar geworden, of niet meer   |
| Reviewbeslissingen         | Een reviewer heeft goedgekeurd, wijzigingen aangevraagd of een goedkeuring is vervallen |
| Controles                  | CI is gefaald op een pull request die jij hebt gemaakt, of is hersteld      |
| Reviewdraden               | Iemand heeft geantwoord in of een draad opgelost waarin je zit              |
| Ticket toegewezen          | Een ticket is toegewezen                                                    |
| Ticketstatus gewijzigd     | Een ticket is van status veranderd                                          |
| Vergadering begint zo      | Een agenda-afspraak valt binnen je voorlooptijd                             |
| Agenda losgekoppeld        | Het OAuth-token van een verbonden agenda is verlopen                        |
| Omheining-updates          | Een omheining is overgenomen, teruggehaald of mislukt                       |

Alles buiten deze lijst kan niet worden gemeld of gefilterd — er is geen
categorie "al het andere".

Deze voorkeuren volgen je gebruiker naar elk apparaat, dus een telefoon en een
laptop blijven gelijk lopen. Het volume is de bewuste uitzondering en blijft per
apparaat.

## Quiet hours instellen

1. Zet op dezelfde pagina **Quiet hours** aan
2. Typ een begin- en eindtijd in `HH:MM` (het standaardvenster is 22:00–08:00)

Tijdens Quiet hours worden niet-dringende meldingen verworpen — ze worden niet in
de wachtrij gezet en later opnieuw afgespeeld.

Twee categorieën zijn **dringend** en komen altijd aan; ze omzeilen Quiet hours
_en_ de focusmodus: **Vergadering begint zo** en **PR gepubliceerd**. Een
vergaderingsmelding die je pas achteraf ziet, is waardeloos — dat is precies de
reden.

## Een geluid kiezen

1. Scroll naar **Meldingsgeluid**
2. Kies een van de elf meegeleverde geluiden, of **Geen**
3. Druk op de knop **Testen** om het te horen en stel het volume in met de schuifregelaar

De app speelt het geluid zelf af; de OS-melding wordt stil afgeleverd, zodat je
het nooit twee keer hoort.

## De voorlooptijd voor vergaderingen instellen

1. Scroll naar **Voorlooptijd melding**
2. Kies **5**, **10**, **15** of **30** minuten

Dat is hoeveel voor een agenda-afspraak de melding **Vergadering begint zo**
wordt geactiveerd. De standaard is 5 minuten.

## Weten wanneer een melding wordt onderdrukt

Een melding wordt stil verworpen wanneer een van deze dingen waar is:

- Meldingen staan globaal uit, of de categorie staat uit
- Je bent al op de route waarheen ze je zou brengen — en, bij een bericht, al in
  die ruimte
- De focusmodus is actief en de categorie is niet dringend
- Quiet hours zijn actief en de categorie is niet dringend

Die controles gelden voor OS-toasts. De blijvende bel legt de gebeurtenis wel
vast.

Er zijn nog twee onderdrukkingen verder stroomopwaarts, in wat de server
verstuurt:

- Een bericht van een andere **mens** waarin je niet wordt vermeld, wordt nooit
  een melding
- Ruimtes van agent tot agent staan gedempt in de zijbalk, dus ze verhogen nooit
  de ongelezen-badge van een mens

Binnen een ruimte is er geen stille hoek: elk gesprek geeft evenveel meldingen,
draden inbegrepen. De leesstatus hoort bij de ruimte, dus ongelezen telt samen
over de gesprekken van een ruimte in plaats van per gesprek te worden
bijgehouden.

## Het meldingencentrum lezen en wissen

1. Klik op de bel in de titelbalk

De popover toont recente activiteit en geeft elk item een deep link naar waar het
over gaat. Als je hem opent, wordt **niet** alles als gelezen gemarkeerd —
gebruik **Alles als gelezen markeren** in de kopregel, of markeer één rij. De
leesstatus volgt je gebruiker over alle apparaten.

:::note[Alles wissen is een watermerk, geen verwijdering]
**Alles wissen** zet een watermerk per gebruiker dat alles wat ouder is verbergt;
de rijen blijven staan. Daarnaast bewaart elke werkruimte alleen zijn nieuwste
**200** feedrijen, die worden opgeschoond zodra er nieuwe binnenkomen, terwijl de
bel zich abonneert op de nieuwste **50** en de popover daarvan maximaal **15**
toont. Geschiedenis daarbuiten is weg, ongeacht de leesstatus.
:::

## Problemen oplossen

### Geen OS-meldingen op macOS

De toestemming wordt bij het starten van de app native aangevraagd. Heb je die
geweigerd, schakel Control Center dan weer in onder Systeeminstellingen →
Meldingen; er is geen melding in de app die dat opnieuw aanvraagt.

### Niets komt aan in de webbuild

Verwacht — de webbuild heeft geen pipeline voor OS-meldingen. Gebruik de bel.

### De badge van de bel staat op nul, maar er is duidelijk nieuwe activiteit

Zolang de stroom leesmarkeringen na het verbinden nog niet is opgelost, worden
items als gelezen weergegeven om te voorkomen dat een badge even oplicht en dan
weer leeg is. Het stabiliseert zodra de markering is geladen.

### De run van een agent is afgerond, maar ik heb geen melding gekregen

Controleer of je niet al in de ruimte was waar het gebeurde — een actieve route
onderdrukt zijn eigen OS-toast.
