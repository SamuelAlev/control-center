## Wat je gaat bouwen

Aan het einde van deze zelfstudie heb je:

- Een agent die je zelf hebt aangemaakt en geconfigureerd
- Een ruimte waarin jij en die agent praten
- Eén voltooide run, met gecommit werk in een geïsoleerde worktree en een regel in het runlog van de agent

Vereisten: [Je eerste werkruimte](/nl-NL/handleiding/zelfstudies/eerste-werkruimte/) is afgerond, dus in deze werkruimte is een repo geregistreerd en is minstens één modelprovider verbonden.

## Stap 1: Een agent aanmaken

1. Ga naar **Instellingen → Werkruimte → Agenten**
2. Klik op **Nieuwe agent**. Er wordt meteen een agent met de naam “Naamloze agent” aangemaakt, die in de agentenlijst wordt geselecteerd — er is geen dialoogvenster om aan te maken en niets te bevestigen. Je configureert hem op zijn plek.
3. Vul op het tabblad **Instellingen** in:
   - **Naam**: iets korts en makkelijk te onthouden, zoals `alice`. Dit is wat je na `@` typt.
   - **Titel**: wat hij doet, bijvoorbeeld “Backend-ontwikkelaar”
   - **Adapter**: `Control Center (built-in)`. Kies deze bewust — alleen de ingebouwde harness kan tijdens een run worden bijgestuurd en aan het einde van een beurt worden gepauzeerd, en er hoeft geen CLI op de serverhost te zijn geïnstalleerd.
   - **Model**: kies er een uit de lijst die de verbonden provider aanbiedt
   - **Vaardigheden**: voeg er een paar toe die passen, bijvoorbeeld `testing` of `architecture`
4. Klik op **Wijzigingen opslaan**

:::note[Een agent zonder adapter draait op de ingebouwde lus]
Als het veld Adapter niet is ingesteld, valt de dispatch terug op **Control Center (built-in)** — de agentloop in de server, dus er hoeft niets op de host te worden geïnstalleerd. Een model heeft hij nog steeds nodig: is er geen ingesteld, dan vraagt hij Anthropic om diens standaard, wat werkt als je een Anthropic-account hebt verbonden en anders mislukt met `No credential for provider "anthropic"`. Stel ze toch allebei expliciet in, anders draai je op een model dat je niet zelf hebt gekozen.
:::

**Controlepunt.** De rij in de agentenlijst toont de naam van je agent en een holle statusring.

## Stap 2: Een ruimte starten

1. Zoek in de zijbalk de sectie **Ruimtes** en klik op de knop **+**
2. Geef de ruimte een naam
3. Selecteer onder **Agenten toevoegen** de agent die je net hebt aangemaakt
4. Kies, als de werkruimte repo's heeft, op welke repo's deze ruimte moet werken
5. Klik op **Aanmaken**

De ruimte gaat open. Op de achtergrond voorziet Control Center dit gesprek van een copy-on-write-worktree van de geselecteerde repo's, op zijn eigen branch. Je broncheckout wordt nooit gewijzigd.

## Stap 3: Een taak sturen

Typ één concrete, kleine taak voor de repo die je hebt geregistreerd. Iets met een controleerbare uitkomst werkt het beste — voeg een test toe, los een lint op, hernoem een symbool.

Druk op Enter. Je hoeft niemand met `@` te vermelden: met één agent in de ruimte wekt een gewoon bericht hem. In een ruimte met meerdere agenten kies je er met `@name` één uit.

Control Center stelt de prompt samen uit de instructies, persona en skills van de agent en de context van de ruimte, en dispatcht daarna de run.

**Controlepunt.** De verzendknop van de composer verandert in een stopknop — er werkt een agent in dit gesprek — en er begint tekst binnen te komen.

## Stap 4: Kijken hoe hij werkt

Het gesprek toont de run terwijl hij plaatsvindt:

- **Redenering**, inline weergegeven terwijl de agent nadenkt
- **Toolaanroepen**: bestanden lezen en schrijven, zoekopdrachten, shell-commando's, elk met hun resultaat
- **Tekst**: samenvattingen, uitleg en vragen aan jou

Als de agent iets vraagt, antwoord je in het gesprek en gaat hij verder.

Voor de eigen statistieken van een run en de bediening om te pauzeren, te hervatten en te stoppen zoek je de draaiende agent op in de sectie **Agenten** van het paneel **Algemeen** van de ruimte en kies je **Activiteit openen**.

In het activiteitenpaneel staat de statusbadge op **Actief**, en daarna op **Geslaagd** wanneer de run eindigt. Een run die blijft hangen of in een lus raakt, toont **Geblokkeerd**; een run met een fout toont **Mislukt**. In het agentenregister is de statusring hol voordat de agent voor het eerst draait, en gevuld zodra hij weer inactief is.

Wat de run begrenst: zijn eigen copy-on-write-worktree, de inloggegevens die bij de start voor hem worden bemiddeld en bij het opruimen worden ingetrokken, een gesaneerde omgeving, het tooloppervlak dat zijn modus toestaat en de actiebeveiligingen. Effecten zoals het pushen van een branch of het openen van een pull request gaan door een aparte poort — zie [Beveiligingen](/nl-NL/handleiding/concepten/beveiligingen/).

## Stap 5: Het resultaat controleren

1. Open **Instellingen → Werkruimte → Agenten** en selecteer je agent
2. Open het tabblad **Logboeken**

**Controlepunt.** Eén runrij, met de status, duur, begin- en eindtijd en de adapter waarop hij heeft gedraaid.

De wijzigingen van de agent staan gecommit op de branch van het gesprek, in zijn worktree. Commits worden gemaakt onder de naam van de agent, en jij wordt vermeld in een `Co-Authored-By:`-trailer.

## Een pull request krijgen

Er opent niets vanzelf een pull request. Wil je er een, vraag er dan om in hetzelfde gesprek:

> Push deze branch en open een pull request tegen de standaardbranch.

Pushen (`gitPush`) en het aanmaken van een PR (`prCreate`) vragen standaard om je goedkeuring, dus verwacht voor elk een bevestiging. Als er geen goedkeurder is verbonden wanneer de vraag verschijnt, wordt de actie geweigerd in plaats van toegestaan — de beveiligingen vallen gesloten uit.

De PR wordt geopend onder de GitHub-identiteit waarvan de run het token gebruikte — de jouwe, als je een persoonlijk token hebt opgeslagen — en niet onder de naam van de agent. Het auteurschap van de agent staat op de commits.

Je kunt hem ook zelf openen: het paneel **Broncodebeheer** van de ruimte heeft een knop **Pull request aanmaken** die de branch van het gesprek meeneemt naar het scherm waarin je de PR opstelt, en **Pull requests → Nieuwe PR** opent datzelfde scherm leeg. Daar pakt de volgende zelfstudie het op.

## Samenvatting

Je hebt een agent aangemaakt, de adapter en het model ingesteld, hem een ruimte en een taak gegeven en toegekeken hoe een echte run in een geïsoleerde worktree werd afgerond zonder je checkout aan te raken.
