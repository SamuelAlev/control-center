## Wat je gaat bouwen

Aan het eind van deze zelfstudie heb je:

- Een werkruimte die vernoemd is naar je project
- Een Git-repository die erin geregistreerd is
- Vijf geseede agenten, waarvan je er één goed genoeg hebt geconfigureerd om te draaien
- Een tweede, lege werkruimte die de isolatiegrens bewijst

De onboarding heeft al een werkruimte voor je aangemaakt. Deze zelfstudie maakt bewust een nieuwe aan, zodat je elk onderdeel van het proces ziet.

Kies voordat je begint een Git-checkout die aan alle drie deze voorwaarden voldoet — de registratiestap weigert al het andere:

- hij bevindt zich in een git-worktree
- hij heeft een `origin`-remote
- die remote wijst naar github.com, gitlab.com of bitbucket.org

## Stap 1: Een werkruimte aanmaken

1. Klik op de werkruimtechip in de titelbalk
2. Kies **Werkruimte toevoegen…**
3. Voer een naam in die het project identificeert, zoals “api-service” of “frontend-v2”
4. Kies eventueel een logo
5. Klik op **Werkruimte toevoegen**

Control Center schakelt over naar de nieuwe werkruimte en komt uit op het postvak in (`/workspaces/<id>/inbox`).

Daarachter publiceert de server een `WorkspaceCreated`-gebeurtenis en zaait de werkruimte met:

- een **CEO-agent**, met als persona coördinatie en delegatie
- vier specialisten — `qa`, `architect`, `engineer` en `librarian` — elk met eigen instructies en skills
- de ingebouwde pipelinesjablonen en hun triggerrijen

Elke werkruimte die je aanmaakt krijgt dit allemaal, niet alleen de eerste.

Controleer het: open **Instellingen → Werkruimte → Agenten**. Er staan vijf agenten in de agentenlijst, elk met een holle statusring.

## Stap 2: Een repository registreren

1. Ga naar **Instellingen → Werkruimte → Repository's**
2. Klik op **Repository toevoegen**
3. Blader naar je checkout. Het dialoogvenster loopt door de mappen op de machine waarop `cc_server` draait — niet je client — en blijft binnen de roots die die server beschikbaar stelt (standaard de homedirectory van zijn gebruiker). Een git-checkout krijgt een apart mappictogram en een selectievakje; een gewone map krijgt geen van beide, dus alleen checkouts kunnen worden geselecteerd.
4. Vink een of meer checkouts aan en registreer de batch. Je selectie blijft behouden terwijl je navigeert, zodat je er meerdere in één keer kunt verzamelen en één verkeerde keuze de rest nooit laat vallen.

Control Center leest de `origin`-remote van elke checkout, bepaalt eigenaar en repo en maakt de repo-rij **binnen deze werkruimte** aan. Er is geen tweede stap om hem te koppelen: registratie is wat hem scope geeft.

Als je dezelfde checkout later in een andere werkruimte registreert, ontstaat een tweede, onafhankelijke repo-rij met een eigen id. Over werkruimtes heen wordt een checkout geïdentificeerd aan de hand van zijn bestandssysteempad, nooit aan de hand van zijn id.

Controleer het: de repo verschijnt in de lijst met zijn `owner/repo` en huidige branch.

## Stap 3: Maak één agent draaibaar

De vijf agenten die deze werkruimte net heeft geseed, hebben geen adapter en geen model. Dispatch draait ze op **Control Center (built-in)** en vraagt, als er geen model is ingesteld, Anthropic om het standaardmodel — ze werken dus alleen als je een Anthropic-account hebt verbonden, en dan op een model dat je niet zelf hebt gekozen. De onboarding bij de eerste start stempelt zijn keuze één keer op elke agent in de eerste werkruimte; een werkruimte die je daarna aanmaakt, begint met alle vijf oningesteld. Stel er nu één in.

1. Open **Instellingen → Werkruimte → Agenten**
2. Selecteer `engineer` in de agentenlijst
3. Stel op het tabblad **Instellingen** **Adapter** in op `Control Center (built-in)` en kies een **Model** bij een provider die je hebt verbonden onder Instellingen → Server → Modelaanbieders
4. Klik op **Wijzigingen opslaan**

Controleer het: open de agent opnieuw en de twee velden bevatten je keuzes.

Elke agent heeft zijn eigen adapter en model, dus herhaal dit voor elke andere agent die je wilt gebruiken. [Een agent maken en configureren](/nl-NL/handleiding/gidsen/agent-maken/) behandelt de rest van het formulier.

## Stap 4: Bekijk de isolatiegrens

Maak vanuit de chip in de titelbalk een tweede werkruimte aan, precies zoals in stap 1. Bekijk hem daarna:

- **Instellingen → Werkruimte → Repository's** is leeg. De repo die je een minuut geleden hebt geregistreerd staat er niet.
- **Instellingen → Werkruimte → Agenten** bevat vijf agenten, maar het zijn andere rijen — de adapter die je in stap 3 hebt ingesteld is verdwenen.
- De ruimtelijst, tickets en het geheugen zijn allemaal leeg.

Er is niets gelekt, want er is niets om uit te lekken: de rijen van elke werkruimte staan in het eigen databasebestand van die werkruimte. Een cross-workspace-leesopdracht is geen query die wordt gefilterd, maar een query die nergens kan draaien. Een werkruimte verwijderen is een bestand ontkoppelen.

Schakel terug met de chip in de titelbalk, of open **Werkruimtes beheren** om ze naast elkaar te zien.

Lees [Werkruimtes en isolatie](/nl-NL/handleiding/concepten/werkruimtes/) voor het volledige model.

## Samenvatting

Je hebt een werkruimte aangemaakt, hem een CEO en vier specialisten zien seeden, er een repo in geregistreerd, één agent een adapter en een model gegeven en bevestigd dat een tweede werkruimte daar niets van deelt.

**Volgende:** [Je eerste agent starten](/nl-NL/handleiding/zelfstudies/eerste-agent/) om de werkruimte aan het werk te zetten.
