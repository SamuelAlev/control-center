Deze referentie somt elk veld van de agent-entiteit op, plus de enums en vlaggen die hij gebruikt. Zie [Een agent maken en configureren](/nl-NL/handleiding/gidsen/agent-maken/) voor een stap-voor-stap doorloop van het maken of bewerken van een agent in de app.

## Velden van de agent-entiteit

| Veld                    | Type                   | Vereist | Beschrijving                                                                                                                                                                                        |
| ----------------------- | ---------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                    | `String`               | Ja      | Unieke identificatie van de agent                                                                                                                                                                   |
| `name`                  | `String`               | Ja      | Korte identificatie voor @-vermeldingen                                                                                                                                                             |
| `title`                 | `String`               | Ja      | Voor mensen leesbare functietitel                                                                                                                                                                   |
| `agentMdPath`           | `String`               | Ja      | Absoluut pad naar het `.md`-definitiebestand van de agent                                                                                                                                           |
| `workspaceId`           | `String`               | Ja      | Eigen werkruimte (niet null)                                                                                                                                                                        |
| `reportsTo`             | `String?`              | Nee     | Id van de bovenliggende agent                                                                                                                                                                       |
| `skills`                | `AgentSkills`          | Ja      | Set skill-identificaties                                                                                                                                                                            |
| `persona`               | `String?`              | Nee     | Vrije tekst met gedragsinstructies                                                                                                                                                                  |
| `systemPrompt`          | `String?`              | Nee     | Overschrijft de standaard systeemprompt                                                                                                                                                             |
| `adapterId`             | `String?`              | Nee     | Id van de inferentieadapter                                                                                                                                                                         |
| `modelId`               | `String?`              | Nee     | Model-id binnen de adapter                                                                                                                                                                          |
| `strictMode`            | `bool`                 | Nee     | Standaard `false`. Wordt naar de rij en naar de `AGENTS.md` van de agent geschreven                                                                                                                 |
| `effort`                | `String?`              | Nee     | Id van het redeneerniveau (bijv. `'low'`, `'xhigh'`), afkomstig uit de `thinkingLevels` van het geselecteerde model                                                                                 |
| `contextSize`           | `int?`                 | Nee     | Maximale grootte van het contextvenster                                                                                                                                                             |
| `role`                  | `AgentRole?`           | Nee     | Agentrol                                                                                                                                                                                            |
| `monthlyBudgetMicros`    | `int`                  | Nee     | Maandelijks uitgavenplafond in microdollar (standaard `0`, onbeperkt)                                                                                                                                    |
| `silenceTimeoutMinutes` | `int?`                 | Nee     | Overschrijving van de stiltetime-out in minuten; moet null zijn of tussen 1–240 liggen (met een assert in de constructor)                                                                          |
| `maxConcurrentTasks`    | `int`                  | Nee     | Standaard `1`. Capaciteitsgetal dat het aanwezigheidsmodel rapporteert (lopende en wachtende aantallen worden ermee vergeleken)                                                                     |
| `visibility`            | `AgentVisibility`      | Nee     | Standaard `workspace`                                                                                                                                                                               |
| `lifecycleStatus`       | `AgentLifecycleStatus` | Nee     | Governancestatus (standaard `active`). Geschreven door de hard-stop van het budget en weergegeven in het organigram en op de aanwezigheidslijst. Dispatch accepteert nog steeds werk van een agent met `paused` |
| `budgetPolicyId`        | `String?`              | Nee     | Id van het gedeelde budgetbeleid; is die null, dan geldt `monthlyBudgetMicros` direct                                                                                                                |
| `runtimeProfileId`      | `String?`              | Nee     | Id van het aangepaste runtimeprofiel                                                                                                                                                                |
| `createdAt`             | `DateTime`             | Ja      | Tijdstip van aanmaken                                                                                                                                                                               |

`name` en `title` mogen beide niet leeg zijn (met een assert in de constructor).
Een standaard `monthlyBudgetMicros` van `0` betekent onbeperkt. Schrijf een
plafond met `agents.upsert`.

## Machtigingen

Een agent draagt geen machtigingsvlaggen. Pushen, pull requests openen en publiceren, naar een tracker schrijven en uitgaand netwerkverkeer zijn actieklassen (`gitPush`, `prCreate`, `prPublish`, `vendorSyncWrite`, `networkEgress`) die de [beveiligingen](/nl-NL/handleiding/concepten/beveiligingen/) bepalen op het bereik werkruimte, agent of ruimte. Het GitHub-token van een run heeft altijd alleen leesrechten; pushes lopen via de agentrun-gateway, die de regel `gitPush` raadpleegt voordat hij ze doorstuurt.

## AgentSkills

Een onveranderlijke, hoofdletterongevoelige set skill-identificaties. Bij het dispatchen worden die slugs gesynchroniseerd als skill-links in de overlay van de agent; de harness laadt daarna de frontmatter van de gelinkte skills automatisch in de prompt.

```
{'flutter', 'dart', 'rest-api'}
```

## Shell-hooks

Shell-hooks laten de servereigenaar eigen scripts draaien rond een agentrun: één keer bij het starten van de sessie, vóór elke toolaanroep, na elke toolaanroep, wanneer de agent zijn beurt wil beëindigen, en vóór een compactie. Een hook is willekeurige code, dus hooks zijn hostconfiguratie. Alleen de servereigenaar stelt ze in, met de hand, op de machine van de server. Er is geen instelling in de app en geen operatie die ze schrijft.

Voor een agent staan de hooks in de eigen map onder de datamap van de server:

```text
<data dir>/_agent_hooks/<workspace id>/<agent slug>/hooks.json
```

`<agent slug>` is de naam van de map van de agent in de werkruimte (`agents/<slug>/`). Die map staat buiten de opslag van elke werkruimte, en elke sandbox verbergt de datamap, dus geen lid, run of terminal kan hem schrijven.

`hooks.json` koppelt een van vijf sleutels aan een script, via een pad ten opzichte van de hookmap:

| Sleutel        | Wanneer hij draait             | Wat de exitcode betekent                                       |
| -------------- | ------------------------------ | -------------------------------------------------------------- |
| `sessionStart` | Eén keer, wanneer de run start | Niets; de hook observeert alleen                               |
| `preTool`      | Vóór elke toolaanroep          | `0` staat de aanroep toe; alles anders weigert hem             |
| `postTool`     | Na elke toolaanroep            | Niets; de hook observeert alleen                               |
| `stop` | Wanneer de agent zijn beurt wil beëindigen | `2` met tekst op stdout houdt de run gaande met die tekst; al het andere laat de beurt eindigen |
| `preCompact` | Vóór een compactie | `0`: de stdout wordt toegevoegd aan wat de samenvatting moet bewaren |

- Elk script wordt gestart als een eigen uitvoerbaar bestand, zonder shell en zonder argumenten, dus het moet uitvoerbaar zijn en beginnen met een shebang-regel. Het ontvangt de gebeurtenis als JSON op stdin: de naam van de gebeurtenis, en voor de toolhooks de naam van de tool met zijn argumenten (`preTool`) of zijn resultaat (`postTool`).
- Een hook draait als een van de toolprocessen van de run, in de map van de agent voor de run. Wanneer de server agents in een sandbox zet, draait hij binnen de sandbox van de run. Hij krijgt een minimale omgeving en geen van de credentials van de run: geen forge- of providertoken en geen toegang tot de gateway.
- Elke hook heeft 30 seconden. De uitvoer van `sessionStart`, `preTool` en `postTool` wordt gelezen en weggegooid.
- `preTool` faalt gesloten. Een niet-nul exitcode, een time-out of een script dat niet kan starten, weigert de toolaanroep.
- Een pad dat absoluut is, ontbreekt, of de hookmap verlaat (links worden opgelost), wordt geweigerd, en het logboek van de run zegt welke hook is geweigerd en waarom. Een geweigerde of onleesbare `preTool`-hook weigert elke toolaanroep totdat hij is hersteld.
- Een `hooks`-blok in `.agents/harness.json`, of het nu in een repository staat of in de eigen map van de agent, wordt genegeerd. Een repository is vaak code van iemand anders, en de map van de agent kan door leden en door runs worden geschreven. Het logboek van de run zegt dat het blok is genegeerd en waar hooks in plaats daarvan worden gelezen.

### De stop- en preCompact-hooks

- `stop` krijgt `event: "stop"`, het laatste bericht van de agent (`last_message`), `stop_hook_active` (true wanneer deze stop volgt op een vervolg dat de hook veroorzaakte) en `block_count` (hoe vaak de run tot nu toe gaande is gehouden, vanaf 0). Om de run gaande te houden, eindigt het met `2` en drukt het af wat de agent hierna moet doen. De tekst, ingekort tot 2.000 tekens, bereikt de agent als systeembericht.
- Een `stop`-hook houdt een run maximaal 3 keer gaande. Daarna wordt hij niet meer uitgevoerd en eindigt de beurt.
- `stop` faalt open. Een time-out, een script dat niet kan starten, elke exit anders dan `2`, of een exit `2` met niets op stdout laat de beurt eindigen, zodat een kapotte hook een run niet open kan houden.
- `preCompact` krijgt `event: "pre_compact"`. Zijn stdout, ingekort tot 1.000 tekens, wordt toegevoegd aan de focus van de compactie. Een mislukt script voegt niets toe.

Shell-hooks gelden voor de ingebouwde harness. Op Claude Code lopen ook de hooks `stop` en `preCompact`: de eigen `Stop`- en `PreCompact`-hooks van Claude Code vragen de server om ze, en de server draait de scripts van de eigenaar op dezelfde manier. De andere drie sleutels gelden alleen voor de ingebouwde harness. Een ingesteld `preTool`- of `postTool`-hook zorgt ervoor dat de run zijn tools één voor één aanroept.

## AgentLiveState (afgeleid)

Niet opgeslagen. Zeven waarden. De declaratievolgorde is de prioriteitsvolgorde (`sortPriority`, vastgepind door een test), en dat is de volgorde waarin de ledenlijst sorteert:

| Status      | `sortPriority` | Voorwaarde                                                                                                          |
| ----------- | -------------- | ------------------------------------------------------------------------------------------------------------------- |
| `running`   | 0              | Minstens één runlog heeft de status `running`                                                                       |
| `blocked`   | 1              | De liveness van de laatste run is `blocked`, `stalled` of `looping`                                                 |
| `failed`    | 2              | De status van de laatste run is `error`, of zijn liveness is `failed` of `dead`                                     |
| `queued`    | 3              | Een run is gedispatcht maar wordt niet uitgevoerd — geparkeerd achter een andere run van dezelfde agent, of geschreven maar nog niet gestart |
| `succeeded` | 4              | De run is met succes afgerond                                                                                       |
| `idle`      | 5              | De agent heeft eerder gedraaid en heeft niets onderweg                                                              |
| `neverRun`  | 6              | Er bestaan geen runlogs                                                                                             |

`queued` en `succeeded` zijn **alleen per run**. `deriveAgentLiveState`, dat de ledenlijststatus van een agent berekent, levert geen van beide op — het retourneert `neverRun`, `running`, `failed`, `blocked` of `idle`.
