`cc_server` host één MCP-toolregister (JSON-RPC 2.0), aangeboden op de hoofdpoort van de server (standaard `9030`) via `POST /mcp` en `GET /sse`, met protocolversie `2024-11-05`. Elke client komt op hetzelfde register uit: de desktop, de webbuild, externe MCP-clients en de ingebouwde agentruntime. Externe MCP-servers kunnen als dynamische laag in hetzelfde register worden opgenomen.

## Omvang van het register

| Maatstaf                                                                  | Aantal |
| ------------------------------------------------------------------------- | ------ |
| Tools die `cc_server` registreert                                         | 110    |
| Uit `packages/cc_mcp`                                                     | 108    |
| Uit `packages/cc_mcp_client` (tooldiscovery)                              | 2      |
| Geregistreerd in het baseregister (`server_mcp_registry.dart`)            | 63     |
| Geregistreerd na het opstarten, zodra hun services beschikbaar komen (`cc_server_runtime.dart`) | 47 |
| Van de 63 van het baseregister, voorwaardelijk op een codegraaf-repository | 5     |

De vijf codegraaftools worden alleen geregistreerd wanneer de host een codegraaf-repository doorgeeft aan `buildServerMcpRegistry`. `cc_server` geeft er altijd een door, dus alle 110 zijn actief in de meegeleverde binary.

Het volledige register wordt aangekondigd in `tools/list`, zonder beperking op discovery. Ticketbewerkingen zijn getypeerde tools.

:::note[Externe clients zien altijd de volledige catalogus]
`tools/list` wordt nooit ingekort. MCP-clients valideren toolnamen tegen hun eigen gecachte kopie van die lijst en weigeren alles wat daar niet op staat, zonder het de server te vragen; een tool die daar verborgen blijft, is dus onbereikbaar in plaats van alleen maar stil.

De **ingebouwde harness** werkt anders: die laadt per verzoek alleen een residente subset van definities en haalt de rest binnen bij het eerste gebruik. Dat is gedrag aan de harnesskant en verandert niets aan dit register. Zie [Toolcontext en promptcaching](/nl-NL/handleiding/concepten/toolcontext).
:::

:::note[Elke toolklasse wordt geregistreerd]
Een bronbestand onder `packages/cc_mcp/lib/src/tools/` is een tool die een agent
kan aanroepen. `packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart`
laat de build falen als een nieuwe toolklasse door niets wordt geconstrueerd.
:::

## Algemene parameters

### `workspace_id`

**Vereist** bij elke tool die gegevens binnen de werkruimte aanraakt. Een ontbrekende of ongeldige `workspace_id` geeft een expliciete fout, en een waarde die niet overeenkomt met de werkruimte van de doeleniteit wordt geweigerd in plaats van stil genegeerd. Laat het weg bij de echt globale tools: `list_workspaces` en de zes nieuwsfeedtools (`list_feeds`, `list_articles`, `get_article`, `set_article_read`, `set_article_saved`, `refresh_feeds`), die meelopen op de persoonlijke feedlijst van de servereigenaar. Discovery-tools (`search_tool_bm25`, `list_my_tools`) nemen het optioneel, zodat ze de aanroepbaarheid per gespreksmodus kunnen classificeren. Wanneer de server een agent dispatcht, wordt de werkruimte serverside geforceerd, dus de agent kan geen andere werkruimte bereiken door een vreemd id mee te geven.

## Tooldiscovery

Beide komen uit `cc_mcp_client`, niet uit `cc_mcp`, en beide raadplegen de modusbewaking, zodat ze melden wat aanroepbaar is in de _huidige_ gespreksmodus.

| Tool               | Beschrijving                                                                                                                |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `search_tool_bm25` | Zoek de toolcatalogus op trefwoord; geeft overeenkomende tools terug, hun argumentschema's en of elke tool nu aanroepbaar is |
| `list_my_tools`    | Toon de tools die nu aanroepbaar zijn in dit gesprek, gefilterd op de modus                                                  |

Een derde discovery-tool, **`search_tools`**, bestaat alleen binnen de ingebouwde harness en maakt geen deel uit van dit MCP-register. Die rangschikt het eigen tooloppervlak van de uitvoering en **laadt**, anders dan `search_tool_bm25`, de schema's van wat hij vindt, zodat de agent een treffer in zijn volgende beurt kan aanroepen. Agenten op de harness kunnen die beter gebruiken; MCP-clients hebben `search_tool_bm25`.

## Omhulling- (rig-)tools

Bestuur wegwerpmachines — een ingesloten browser of Linux-desktop, een Android-
emulator of een iOS Simulator — van binnenuit een run. Ze worden na het
opstarten geregistreerd, onvoorwaardelijk: of een machine echt kan opstarten is
een probeervraag die de tools per aanroep beantwoorden. Herhaalde aanroepen in
één gesprek hergebruiken één machine; screenshots komen terug als
afbeeldingsinhoud met een budget van één afbeelding per resultaat, en opgehaalde
pagina-/UI-inhoud wordt als niet-vertrouwde data afgeschermd. De vier
gebruikstools plus `rig_close` declareren de `enclosureControl`
[actieklasse](/nl-NL/handleiding/concepten/beveiligingen/) (de gebruikstools
declareren ook `networkEgress` en `processSpawn`; `mobile_use` en `ios_use`
declareren ook `packageInstall`), dus alleen-lezenmodi weigeren ze. `rig_list`
declareert niets — die leest alleen werkruimtestatus. Het volledige
werkwoordenvocabulaire per oppervlak staat in de
[rigs-referentie](/nl-NL/handleiding/referentie/rigs/#action-verbs).

| Tool           | Beschrijving                                                                                    |
| -------------- | ----------------------------------------------------------------------------------------------- |
| `computer_use` | Bestuur een Linux-desktop in een ingesloten VM: verplaatsen, klikken, slepen, scrollen, typen, formaat wijzigen, klembord, screenshot |
| `browser_use`  | Bestuur een headless Chromium, Firefox of WebKit (`engine`): navigeren, klikken, invullen, extraheren (a11y/DOM/console), klembord, screenshot |
| `mobile_use`   | Bestuur Android via ADB: inspecteren/invoeren, screenshots, apps installeren/starten/stoppen/resetten/verwijderen, deep links en apparaatcommando's in argv-vorm |
| `ios_use`      | Bestuur de iOS Simulator via WebDriverAgent/CoreSimulator: inspecteren/invoeren, screenshots, apps installeren/starten/stoppen/verwijderen, deep links en simulatorprocessen in argv-vorm |
| `rig_list`     | Toon de rigs van een werkruimte met oppervlak, status, weergavegrootte en controller            |
| `rig_close`    | Vernietig een rig en gooi de bijbehorende machinestatus weg                                     |

## Niet beschikbaar via MCP

Agenda en vergaderingen hebben geen MCP-tools. Agenten kunnen je agenda, vergaderingen, transcripten, actiepunten of beslissingen niet lezen. De samenvatting die actiepunten en beslissingen oplevert, draait als de ingebouwde [`meeting_summary`-pipeline](/nl-NL/handleiding/concepten/vergaderingen/), niet als een tool die een agent kan aanroepen.

## Toolfiltering per modus

De filtering wordt tweemaal afgedwongen vanuit één tabel (`ModeToolPolicy`): één keer in de MCP-dispatcher voor de Claude Code-adapter en één keer in het register van de ingebouwde harness. Een geblokkeerde aanroep geeft de reden terug.

| Modus         | Tooloppervlak                                                                                                                                                                                                                        |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`        | Elke geregistreerde tool; geen allowlist                                                                                                                                                                                             |
| `plan`        | Een samengestelde allowlist. Geen worktree-schrijfacties en geen ticketwerkwoorden `create` / `assign` / `delegate`, maar geheugen, artefacten, todo's, `submit_plan`, `exit_plan_mode` en de ticketafrondingswerkwoorden op het gedispatchte ticket zijn toegestaan |
| `review`      | Een samengestelde allowlist: deelname aan reviews, communicatie, alleen-lezen contextophalers en de volledige set ticketwerkwoorden, inclusief `create_ticket` en `assign_ticket`                                                     |
| `orchestrate` | Een samengestelde allowlist: onderzoeks- en leestools plus `propose_orchestration`, `create_playbook` en `run_playbook`. Aannemen, opdelen en tickets afronden gebeuren deterministisch na goedkeuring, nooit midden in een run       |

In elke modus toegestaan, ongeacht de allowlist:

| Set                  | Tools                                                                                                                                                                                                                                                             |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Geheugen en artefacten | `search_memory`, `propose_fact`, `propose_policy`, `supersede_fact`, `supersede_policy`, `record_observation`, `update_my_notes`, `get_my_notes`, `list_memory_domains`, `list_policies`, `publish_artifact`, `revise_artifact`, `list_artifacts`, `get_artifact` |
| Codegraaf            | `search_code`, `code_symbol`, `code_callers`, `code_callees`, `code_impact`                                                                                                                                                                                       |
| Runmechanica         | `search_tool_bm25`, `list_my_tools`, `todo_write`, `todo_read`                                                                                                                                                                                                    |

Op een allowlist staan maakt een tool niet aanroepbaar, en het omgekeerde geldt ook: de mogelijkheid om de operator een vraag te stellen is een **harness**-tool (`ask_user`) en komt dus helemaal niet in deze MCP-catalogus voor.

## Tools met goedkeuringsplicht

Een tool kan `requiresApproval` declareren. De dispatcher bouwt dan een `ApprovalPayload` en toont die via de `ConfirmationPort` voordat de tool draait; `cc_server` koppelt die poort, dus de poort is actief.

Geregistreerde tools die het declareren: `create_ticket`, `update_ticket`, `assign_ticket`, `reassign_ticket`, `close_ticket`, `ticket_relation`, `create_goal`, `update_goal_progress`, `create_approval`, `decide_approval`, `comment_approval`, `create_work_product`, `save_work_product_revision`, `create_runtime_profile`, `install_skill`, `update_skill`.

Los daarvan bewaken de uniforme actiebeveiligingen elke tool die een niet-lege `ActionClass`-set declareert. Een `prompt`-beslissing zonder aangesloten goedkeurder wordt geweigerd. Zie [Beveiligingen](/nl-NL/handleiding/concepten/beveiligingen/).

## Mogelijkheden zonder tool erachter

Niet elke mogelijkheid in het product is bereikbaar voor een agent. Deze hebben
helemaal geen tool, dus een naam die je elders hebt zien staan levert
"unknown tool" op:

| Mogelijkheid                             | Waar het in plaats daarvan zit                                                                  |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Een agent aannemen, ontslaan of bewerken  | De agenten-UI. Er is geen `hire_agent` / `fire_agent` / `update_agent`-tool                       |
| Een werkruimte aanmaken                   | `workspace.upsert` via RPC, dat eigenaarschap initialiseert en vastlegt                            |
| Projecten (aanmaken / tonen / bijwerken / indienen) | De tickets-UI. Projecten zijn een operatoroppervlak — zie [Projecten](/nl-NL/handleiding/gidsen/projecten/) |
| De operator een blokkerende vraag stellen | De **harness**-tool `ask_user`, niet MCP. Die toont een formulier in het gesprek en wacht op het antwoord |
