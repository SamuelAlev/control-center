These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/nl-NL/handleiding/gidsen/); when you want to look
something up, go to the [reference](/nl-NL/handleiding/referentie/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/nl-NL/handleiding/concepten/werkruimtes/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/nl-NL/handleiding/concepten/agentmodel/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/nl-NL/handleiding/concepten/dispatch-levenscyclus/) — what happens between your message and the agent's first token
- [Modes](/nl-NL/handleiding/concepten/modi/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/nl-NL/handleiding/concepten/toolcontext/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/nl-NL/handleiding/concepten/code-intelligentie/) — the code graph, language server, structural search and debugger
- [Conversation history](/nl-NL/handleiding/concepten/gespreksgeschiedenis/) — persistence, compaction and forking a transcript

- [Rigs and enclosures](/nl-NL/handleiding/concepten/rigs/) — why agents get disposable VMs instead of your machine, and what the boundary actually is
