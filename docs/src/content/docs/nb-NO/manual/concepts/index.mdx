These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/nb-NO/handbok/slik-gjor-du/); when you want to look
something up, go to the [reference](/nb-NO/handbok/referanse/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/nb-NO/handbok/konsepter/arbeidsomrader/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/nb-NO/handbok/konsepter/agentmodell/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/nb-NO/handbok/konsepter/livssyklus-agentutsending/) — what happens between your message and the agent's first token
- [Modes](/nb-NO/handbok/konsepter/moduser/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/nb-NO/handbok/konsepter/verktoykontekst/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/nb-NO/handbok/konsepter/kodeintelligens/) — the code graph, language server, structural search and debugger
- [Conversation history](/nb-NO/handbok/konsepter/samtalehistorikk/) — persistence, compaction and forking a transcript
