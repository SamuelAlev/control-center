Denne guiden viser deg hvordan du kobler en ekstern MCP-klient — Claude Code, en
editor, MCP Inspector — til Control Centers egen verktøyserver.

Control Center registrerer **110** verktøy og betjener dem over Model Context
Protocol i protokollversjon `2024-11-05`. Hele verktøyfamilier du kanskje
forventer, mangler: det finnes ingen møte- eller kalenderverktøy og ingen
prosjektverktøy.

## Finn endepunktet

MCP-flaten deler den vanlige `cc_server`-lytteren. Det finnes ingen egen
MCP-port.

| Endepunkt | Metode   | Formål                                                     |
| --------- | -------- | ---------------------------------------------------------- |
| `/mcp`    | `POST`   | Streamable HTTP-transport — dette er det en klient snakker |
| `/mcp`    | `DELETE` | Avslutt en økt                                             |
| `/sse`    | `GET`    | Varselstrøm sendt fra serveren                             |

En standard lokalinstallasjon ligger altså på `http://127.0.0.1:9030/mcp`.

1. Gå til **Innstillinger → Server → MCP-servere**
2. Les **MCP-server**-kortet — det viser om serveren kjører eller er stoppet, og
   hvilken port den lytter på

Flaten er på som standard i en fersk installasjon. Bare serverens eier ser kortets token, og bare de kan starte eller stoppe endepunktet. **Start ved appstart** styrer om den kommer tilbake etter en omstart; **Start** / **Stopp** er øktkontroller som ikke endrer denne innstillingen.

Serveren binder til loopback som standard, så endepunktet er bare tilgjengelig
fra maskinen `cc_server` kjører på, med mindre du startet den med `--bind any`.

## Hent tokenet

Hver forespørsel trenger MCP-tokenet til serveren, fra hvilken som helst maskin, også fra loopback. Serveren oppretter det første gang den starter. Det finnes ingen måte å slå det av på, og ingen måte å tømme det på.

1. I **Innstillinger → Server → MCP-servere** finner du raden **Autentiseringstoken**
2. Trykk **Vis token** og kopier det
3. For å erstatte det trykker du **Roter token**. Serveren bytter til det nye tokenet med én gang, og hver klient som fortsatt bruker det gamle, avvises til du gir den det nye

## Koble til en klient

Pek klienten mot Streamable HTTP-endepunktet, og send tokenet som `Authorization: Bearer <token>` på hver forespørsel, også `GET /sse`. Det finnes ingen annen måte å sende det på: et token i URL-en godtas ikke. Den nøyaktige utformingen av konfigurasjonen er opp til klienten din.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code plukker ikke dette opp fra en `.mcp.json` i prosjektet — den setter
MCP-servere med prosjektomfang bak en godkjenningsprompt som en ikke-interaktiv
`claude -p` aldri svarer på. Send konfigurasjonen eksplisitt:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` gjør at Claude bare bruker den filen, så den samme
serveren ikke også oppdages fra prosjektet og registreres to ganger.

Kontrollpunkt: be klienten liste opp verktøyene sine. Du skal se
`mcp__*`-oppføringer som dekker saker, områder, minne, kodegrafen og
gjennomgang.

## Hva endepunktet avviser

Tokenet åpner hvert verktøy på serveren, så endepunktet avviser også alt en nettside kan ha sendt, før det ser på tokenet:

| Forespørsel | Svar |
| --- | --- |
| En `Origin`-header som ikke er en side på denne maskinen (`http://localhost`, `http://127.0.0.1` eller `http://[::1]`, med hvilken som helst port) | `403`, «Forespørsler fra andre opprinnelser godtas ikke» |
| En `Host`-header som verken er denne lytterens loopback-adresse og port eller serverens offentlige vertsnavn | `403`, «Ukjent vert» |
| En `POST` der kroppen ikke er `application/json` | `415` |
| Ingen token, eller feil token | `401` |

For å tilby MCP utenfor verten, start serveren med `--bind any` og send tokenet fra den andre maskinen, og adresser serveren med dens offentlige vertsnavn.

## Avgrens hvert kall til et arbeidsområde

Hvert verktøy som berører data med arbeidsområdeomfang, krever `workspace_id`,
og et kall uten den avvises i stedet for å løses mot et eller annet «gjeldende»
arbeidsområde:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

ID-en er den du ser i nettleser- eller app-URL-en: `/workspaces/<workspace_id>/…`.
De eneste unntakene er verktøy som virkelig spenner over arbeidsområder, som
`list_workspaces` og nyhetsstrømverktøyene — nyhetsstrømmen er per bruker, og en
agent har ingen egen bruker, så disse verktøyene opererer på servereierens
strømmer.

Verktøy med repo-omfang sjekker i tillegg at repoet er koblet til det
arbeidsområdet.

## Vit hva flaten vil avvise

- **Porting etter modus.** Et kall løses mot modusen til området til agenten som
  kaller, på serversiden. En agent i en skrivebeskyttet modus kan ikke nå et
  skriveverktøy ved å utelate `space_id` — modusen slås opp fra den aktive
  kjøringen i stedet.
- **Tillatelsesregler for handlinger.** Endrende verktøy deklarerer
  effektklassene sine og går gjennom den samme policyen som resten av produktet
  bruker. Se
  [Konfigurer tillatelsesregler](/nb-NO/handbok/slik-gjor-du/konfigurer-tillatelsesregler/).
- **Bekreftelse.** Noen destruktive verktøy bygger en bekreftelsesnyttelast som
  må godkjennes før kallet fortsetter.

Hele katalogen annonseres i `tools/list` uten noen porting ved oppdagelse — en
ekstern MCP-klient nekter å kalle et verktøy som ikke står i den mellomlagrede
listen sin, så å skjule verktøy ødelegger dem i stedet for å rydde i dem.

## MCP-servere som agentene bruker

Denne guiden handler om Control Centers eget endepunkt. Den andre retningen er MCP-servere som Control Center kobler seg til og gir til agentene det kjører. De settes opp under **Innstillinger → Server → MCP-servere**, på to nivåer: for hele arbeidsområdet, eller for deg selv. Uansett nivå kobler Control Center seg til selve MCP-serveren og sender verktøyene dens videre til kjøringen, slik at det innebygde harnesset og Claude Code får de samme verktøyene og de samme godkjenningsforespørslene. En Claude Code-kjøring ser dem under MCP-serveren `control-center` som `mcp__control-center__mcp__<server>__<tool>`.

### MCP-servere for arbeidsområdet

Administratorer av arbeidsområdet legger til disse under **MCP-servere for arbeidsområdet**. Hver agentkjøring i arbeidsområdet får verktøyene deres, og kjøringer i andre arbeidsområder gjør ikke det.

1. Velg **Legg til server** og gi den et kort navn: bokstaver, sifre, `-` og `_`, opptil 24 tegn. Verktøyene vises som `mcp__<name>__<tool>`.
2. Velg hvordan MCP-serveren nås:
   - **Kommando (stdio):** en kjørbar fil med argumentene sine, pluss eventuelle miljøvariabler den trenger.
   - **URL (HTTP eller SSE):** endepunktet, pluss eventuelle headere den trenger, for eksempel `Authorization: Bearer …`.
3. Lagre. Kontrollpunkt: MCP-serveren viser **Tilkoblet** med et antall verktøy.

Verdier for miljøvariabler og headere lagres i hemmelighetsfilen til MCP-serveren og vises aldri igjen. For å endre en verdi erstattes den; for å fjerne den fjernes navnet.

En kommando kjører på maskinen til MCP-serveren som MCP-serverens egen bruker, så den starter ikke før eieren av serveren godkjenner den. Inntil da står det **Venter på godkjenning**. En URL-server fungerer med én gang, men kan bare nå offentlige adresser til eieren godkjenner den, og da tillates også `localhost` og private nettverk. Når eieren lagrer en MCP-server, regnes det som godkjenning. Hvis noen andre endrer hvordan en MCP-server starter eller hvor den kobler seg til, må den godkjennes på nytt. Å slå en MCP-server av eller på beholder godkjenningen.

### Egne servere

Hvert medlem legger til sine egne i **Dine MCP-servere**, med samme skjema. De er bare dine i dette arbeidsområdet: andre medlemmer ser dem ikke, og en server du logger inn på, bruker din identitet.

- Bare kjøringer du starter i dette arbeidsområdet, får verktøyene deres. Det gjelder både innebygde harness-kjøringer og Claude Code-kjøringer.
- Et annet medlems kjøring, automatisering ingen har startet, og dine kjøringer i andre arbeidsområder får ingen av dem. Der listes ikke verktøyene, de kan ikke kalles og de dukker ikke opp i verktøysøket.
- Serveren din kan ha samme navn som en server i arbeidsområdet. I kjøringene dine er det din som brukes.
- Din egen server nås via URL og kan bare nå offentlige adresser. Bare eieren av serveren kan legge til en egen som kjører en kommando.

Verken egne MCP-servere eller MCP-servere for arbeidsområdet sendes til MCP-tokenet eller til parede enheter, og ressursene og promptene deres videresendes ikke.

### Logg inn på en server

En URL-server som ber deg logge inn, viser **Trenger autorisasjon**.

1. Velg **Logg inn** på serveren. Nettleseren åpner serverens egen innloggingsside.
2. Godkjenn forespørselen der. Nettleseren går tilbake til Control Center og viser en kode.
3. Skriv inn koden i appen. Kontrollpunkt: serveren viser **Tilkoblet**.

Innloggingen lagres sammen med serveren den ble laget for. Å logge inn på en server i arbeidsområdet krever en arbeidsområdeadministrator, og da handler hver kjøring i arbeidsområdet som kontoen som logget inn. Å logge inn på din egen server påvirker bare kjøringene dine. Å fjerne en server fjerner også innloggingen.

## Feilsøking

### Klienten ser ingen verktøy

- Sjekk at **MCP-server**-kortet sier at serveren kjører
- Sjekk at porten samsvarer med `cc_server`-porten din
- I Claude Code: sjekk at du sendte med `--mcp-config` og `--strict-mcp-config`

### 401 Unauthorized

Forespørselen hadde ingen token, eller et gammelt. Kopier det gjeldende tokenet fra raden **Autentiseringstoken** og send det som `Authorization: Bearer <token>`. Et token i URL-en ignoreres.

### 403 fra en klient som fungerte før

Forespørselen hadde en `Origin` fra en nettside, eller en `Host` serveren ikke svarer til. Kall endepunktet fra en klient i stedet for en nettleserside, med serverens loopback-adresse eller dens offentlige vertsnavn.

### 415 Unsupported Media Type

Send `POST /mcp`-kropper som `application/json`.

### Et verktøykall feiler med «Missing or invalid argument: workspace_id»

Legg til `workspace_id`. Det finnes ikke noe implisitt arbeidsområde.

### Et verktøykall avvises som ukjent

[MCP-verktøy](/nb-NO/handbok/referanse/mcp-verktoy/) viser katalogen. Kall navnet
nøyaktig slik det står der.
