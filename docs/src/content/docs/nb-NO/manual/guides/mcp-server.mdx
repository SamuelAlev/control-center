Denne guiden viser deg hvordan du kobler en ekstern MCP-klient — Claude Code, en
editor, MCP Inspector — til Control Centers egen verktøyserver.

Control Center registrerer **110** verktøy og betjener dem over Model Context
Protocol i protokollversjon `2024-11-05`. Hele verktøyfamilier du kanskje
forventer, mangler: det finnes ingen møte- eller kalenderverktøy og ingen
prosjektverktøy.

## Finn endepunktet

MCP-flaten deler den vanlige `cc_server`-lytteren. Det finnes ingen egen
MCP-port.

| Endepunkt | Metode   | Formål                                                     |
| --------- | -------- | ---------------------------------------------------------- |
| `/mcp`    | `POST`   | Streamable HTTP-transport — dette er det en klient snakker |
| `/mcp`    | `DELETE` | Avslutt en økt                                             |
| `/sse`    | `GET`    | Varselstrøm sendt fra serveren                             |

En standard lokalinstallasjon ligger altså på `http://127.0.0.1:9030/mcp`.

1. Gå til **Innstillinger → Server → MCP-servere**
2. Les **MCP-server**-kortet — det viser om serveren kjører eller er stoppet, og
   hvilken port den lytter på

Flaten er på som standard i en fersk installasjon, så en loopback-klient virker
uten å måtte innom innstillingene. **Start ved appstart** styrer om den kommer
tilbake etter en omstart; **Start** / **Stopp** er øktkontroller som ikke endrer
denne innstillingen.

Serveren binder til loopback som standard, så endepunktet er bare tilgjengelig
fra maskinen `cc_server` kjører på, med mindre du startet den med `--bind any`.

## Koble til en klient

Pek klienten mot Streamable HTTP-endepunktet. Den nøyaktige utformingen av
konfigurasjonen er opp til klienten din; URL-en er den samme uansett.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp"
    }
  }
}
```

### Claude Code

Claude Code plukker ikke dette opp fra en `.mcp.json` i prosjektet — den setter
MCP-servere med prosjektomfang bak en godkjenningsprompt som en ikke-interaktiv
`claude -p` aldri svarer på. Send konfigurasjonen eksplisitt:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` gjør at Claude bare bruker den filen, så den samme
serveren ikke også oppdages fra prosjektet og registreres to ganger.

Kontrollpunkt: be klienten liste opp verktøyene sine. Du skal se
`mcp__*`-oppføringer som dekker saker, områder, minne, kodegrafen og
gjennomgang.

## Tilby MCP utenfor verten

1. I **Innstillinger → Server → MCP-servere**, på raden **Autentiseringstoken**,
   trykker du **Sett** og limer inn et token
2. Send det som `Authorization: Bearer <token>` på hver `POST /mcp`-forespørsel

En flate uten token avviser enhver kaller som ikke kommer over loopback, med
403. Det er med vilje at den stenger ved feil: tokenet er det som i det hele
tatt gjør tjeneste utenfor verten mulig.

Endringer i tokenet trer i kraft i den aktive flaten umiddelbart — ingen
omstart.

:::note[`GET /sse` tar tokenet i spørringsstrengen]
Varselstrømmen sjekkes mot tokenet som enhver annen rute, men en `EventSource` i
nettleseren kan ikke sende en `Authorization`-header — derfor godtar `/sse`
også tokenet som `?token=<token>`. Uten token svarer den 401.
:::

## Avgrens hvert kall til et arbeidsområde

Hvert verktøy som berører data med arbeidsområdeomfang, krever `workspace_id`,
og et kall uten den avvises i stedet for å løses mot et eller annet «gjeldende»
arbeidsområde:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

ID-en er den du ser i nettleser- eller app-URL-en: `/workspaces/<workspace_id>/…`.
De eneste unntakene er verktøy som virkelig spenner over arbeidsområder, som
`list_workspaces` og nyhetsstrømverktøyene — nyhetsstrømmen er per bruker, og en
agent har ingen egen bruker, så disse verktøyene opererer på servereierens
strømmer.

Verktøy med repo-omfang sjekker i tillegg at repoet er koblet til det
arbeidsområdet.

## Vit hva flaten vil avvise

- **Porting etter modus.** Et kall løses mot modusen til området til agenten som
  kaller, på serversiden. En agent i en skrivebeskyttet modus kan ikke nå et
  skriveverktøy ved å utelate `space_id` — modusen slås opp fra den aktive
  kjøringen i stedet.
- **Tillatelsesregler for handlinger.** Endrende verktøy deklarerer
  effektklassene sine og går gjennom den samme policyen som resten av produktet
  bruker. Se
  [Konfigurer tillatelsesregler](/nb-NO/handbok/slik-gjor-du/konfigurer-tillatelsesregler/).
- **Bekreftelse.** Noen destruktive verktøy bygger en bekreftelsesnyttelast som
  må godkjennes før kallet fortsetter.

Hele katalogen annonseres i `tools/list` uten noen porting ved oppdagelse — en
ekstern MCP-klient nekter å kalle et verktøy som ikke står i den mellomlagrede
listen sin, så å skjule verktøy ødelegger dem i stedet for å rydde i dem.

## Feilsøking

### Klienten ser ingen verktøy

- Sjekk at **MCP-server**-kortet sier at serveren kjører
- Sjekk at porten samsvarer med `cc_server`-porten din
- I Claude Code: sjekk at du sendte med `--mcp-config` og `--strict-mcp-config`

### 403 fra en maskin som ikke er serveren

Det er ikke konfigurert noe bearer-token. Sett ett og send det.

### Et verktøykall feiler med «Missing or invalid argument: workspace_id»

Legg til `workspace_id`. Det finnes ikke noe implisitt arbeidsområde.

### Et verktøykall avvises som ukjent

[MCP-verktøy](/nb-NO/handbok/referanse/mcp-verktoy/) viser katalogen. Kall navnet
nøyaktig slik det står der.
