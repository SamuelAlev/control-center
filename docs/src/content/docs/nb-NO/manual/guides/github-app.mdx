Denne veiledningen viser deg hvordan du gir serveren din sin egen GitHub App. Det
tar omtrent to minutter, bare servereieren gjør det, og det må bare gjøres én
gang per server.

:::note[Du trenger den kanskje ikke]
Når Control Center Connect er slått på, logger folk inn på GitHub via den delte
appen til Control Center, eller via appen som organisasjonens Connect bruker.
Registrer din egen når du har valgt **Bruk mine egne apper**: serverens egen app gjelder bare da. Se
[Control Center Connect](/nb-NO/handbok/referanse/connect/).
:::

For å logge inn på din egen konto etterpå, se
[Sett opp GitHub-integrasjon](/nb-NO/handbok/slik-gjor-du/github-integrasjon/).

## Hva appen gjør

Én registrering løser to forskjellige oppgaver:

| Oppgave                   | Hva som svarer                                | Hvorfor det betyr noe                                                                       |
| ------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------- |
| **En person logger inn**  | Appens client id og client secret             | Alle får sin egen GitHub-påloggingsinformasjon, på serveren, på hver enhet                  |
| **Serveren opptrer**      | Appens id og private key                      | Agenter, pipelines, pollere og botsvar får tokener for ett repo om gangen                   |

Den andre oppgaven låner aldri en persons påloggingsinformasjon i sin helhet.
Hvert token serveren utsteder, dekker ett repo og er begrenset til det et
ansvarlig medlem kan gjøre der. Å lese et tilkoblet repo krever bare appen; alt
som skriver, krever et medlem som kan pushe. Automatisering godkjenner aldri en
pull request.

Serverens egen app gjelder bare under **Bruk mine egne apper**. Med Control Centers eller en egendefinert Connect håndterer Connect GitHub, og serverens app forblir lagret, men ubrukt til du bytter tilbake. Et arbeidsområde på egne apper ([Gi ett arbeidsområde en egen app](#gi-ett-arbeidsområde-en-egen-app)) bruker sin egen app i stedet, uansett serverens modus. En app der noen av
feltene mangler, er en feil, ikke en reserveløsning: GitHub-pålogginger avvises
til hvert felt er satt.

## Forutsetninger

- Du er **servereier**. Kortet **Leverandørapper** er usynlig for alle andre
- En GitHub-konto. Appen opprettes under den
- En serveradresse nettleseren din kan nå. Serverens offentlige URL (eller
  loopback, for skrivebordets egen server) er der GitHub sender deg tilbake

## Opprett den med ett klikk

1. Gå til **Innstillinger → Server → Enkel pålogging** og rull ned til kortet
   **Leverandørapper**
2. I **GitHub**-blokken kan du skrive inn GitHub-organisasjonen som skal eie
   appen, i **Organisasjon (valgfritt)**. La feltet stå tomt for å opprette appen
   under din egen konto; å opprette den under en organisasjon krever en eier av
   den organisasjonen
3. Klikk **Opprett min GitHub-app**
4. Nettleseren din åpner GitHub med appen allerede utfylt. Klikk
   **Create GitHub App**
5. GitHub sender deg tilbake til serveren, som lagrer app-id-en, den private
   nøkkelen, client id-en og client secret-en, og deretter åpner appens
   installasjonsside

Ingenting kopieres for hånd, og konverteringskoden går rett fra GitHub til
serveren din. Lenken fungerer én gang og utløper etter ti minutter; hvis den
utløper, klikker du **Opprett min GitHub-app** igjen.

Appen heter `Control Center <code>` og ber om nøyaktig det Control Center
bruker:

| Tillatelse                                 | Tilgang          |
| ------------------------------------------ | ---------------- |
| Metadata                                   | Les              |
| Contents                                   | Les og skriv     |
| Pull requests                              | Les og skriv     |
| Issues                                     | Les og skriv     |
| Checks, Actions, Commit statuses           | Les              |
| Organization members                       | Les              |

Webhooks er av: serveren poller. For senere å flytte en app du opprettet under
din egen konto til en organisasjon, bruker du **Transfer ownership** i appens
avanserte innstillinger på GitHub.

Sjekkpunkt: GitHub-blokken viser «Serveren kan opptre som seg selv, og folk kan
logge inn».

## Installer den der repoene dine ligger

En app som er registrert, men ikke installert, kan logge inn folk og leser
ingenting.

1. Velg kontoen eller organisasjonen som eier repoene dine, på
   installasjonssiden GitHub åpnet
2. Velg **All repositories**, eller velg de repoene denne serveren skal se

For å installere den på en annen konto senere går en administrator i
arbeidsområdet til **Innstillinger → Arbeidsområde → Integrasjoner**, finner
**Installasjoner av GitHub-appen** på kortet **GitHub-app** under Kodehosting og klikker
**Installer GitHub-appen**. Listen viser alle kontoer appen er installert på,
og markerer en suspendert installasjon.

## Del en organisasjons installasjon

En organisasjon installerer GitHub-appen én gang. Deretter kan alle i organisasjonen som logger inn på GitHub på en Control Center-server, bruke installasjonen, uansett hvilken server det er: din, en kollegas eller en egen. Det er ingenting å autorisere per server.

Hvert token en server får, tilhører den innloggede personen, begrenset til ett repo og til rollen vedkommende har der, så det rekker aldri lenger enn det personen kunne gjort på GitHub. GitHubs revisjonslogg viser den personen, som handler gjennom appen.

For å hindre at Control Center når en organisasjon, fjerner en eier av organisasjonen installasjonen eller snevrer inn repoene på GitHub. Å fjerne en person fra organisasjonen stopper tilgangen deres også.

## Registrer den for hånd i stedet

Kortet **Leverandørapper** tar også imot verdiene direkte, for en app du har
registrert selv:

| Gruppe                       | Felter                                                                                          |
| ---------------------------- | ----------------------------------------------------------------------------------------------- |
| **Opptre som serveren**      | **App-id** og **Privat nøkkel** (hele `.pem`-en, inkludert `BEGIN`- og `END`-linjene)           |
| **Logge inn folk**           | **Client id** og **Client secret**. **Callback-URL-er** viser URL-en som skal registreres, ordrett |
| **Pull request-samtaler**    | **Bot-innlogging**, løst opp når du tester tilkoblingen                                         |

Registrer callback-URL-en `<server origin>/oauth/github/callback` nøyaktig slik
kortet viser den, la **Expire user authorization tokens** stå på, og gi
tillatelsene i tabellen over. Klikk **Test**: den spør GitHub hvilke kontoer
appen er installert på, så «lagret» og «virker» ikke blandes sammen.

## Konfigurer den fra serverens `.env`

For en headless- eller skriptbasert installasjon fyller serveren hvert felt fra
`.env`-filen første gang det ikke har en lagret verdi:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

Legg nøkkelen på **én linje**: en `.env`-verdi er én linje, og `\n` inne i doble
anførselstegn dekodes til et linjeskift. Serveren nekter å starte når
`GITHUB_APP_PRIVATE_KEY` eller `GITHUB_CLIENT_SECRET` er eksportert i
prosessmiljøet, der hver underprosess kunne lese dem; hold dem i `.env`-filen (i
Docker monterer du den på `/app/bin/.env`). Fyllingen skjer **én gang per
felt**, så redigeringer i Innstillinger blir ikke overskrevet ved neste omstart.

## Gi ett arbeidsområde en egen app

Et arbeidsområde kan kjøre på en egen app i stedet for serverens:

1. En administrator i arbeidsområdet går til **Innstillinger → Arbeidsområde → Integrasjoner**
2. På kortet **Control Center Connect** velger de **Bruk mine egne apper** og klikker **Bruk**. Alle i arbeidsområdet logger inn på nytt gjennom arbeidsområdets apper
3. Kortet **GitHub-app** under Kodehosting holder nå appens felt: **App-id** og **Privat nøkkel** under **Handler for dette arbeidsområdet**, **Client id** og **Client secret** under **Logge inn folk**. Klikk **Test** når de er satt

Medlemmene logger da inn på den appen for dette arbeidsområdet. Et arbeidsområde på egne apper faller aldri tilbake på serverens app eller på Connect: til feltene er fullstendige, avvises GitHub-arbeidet. Det samme valget dekker Google Calendar, Linear og GIF-søk, hver med sine egne felt ved siden av leverandøren på samme side. Se [Gi ett arbeidsområde en egen Linear-applikasjon](/nb-NO/handbok/slik-gjor-du/linear-integrasjon/#gi-ett-arbeidsområde-en-egen-linear-applikasjon) og [Gi ett arbeidsområde en egen Google-klient](/nb-NO/handbok/slik-gjor-du/koble-til-kalender/#gi-ett-arbeidsområde-en-egen-google-klient). De andre valgene på kortet, og hva hvert av dem gjør, står i [Valg for hvert arbeidsområde](/nb-NO/handbok/referanse/connect/#valg-for-hvert-arbeidsområde).

## Feilsøking

### Opprett min GitHub-app sier at serveren ikke har noen adresse

Serveren har ingen offentlig URL som en nettleser kan komme tilbake til. Sett
`CC_SERVER_PUBLIC_URL` (eller `--public-url`) og prøv igjen.

### GitHub sier at lenken har utløpt

Engangssiden er allerede brukt, eller det har gått ti minutter. Start på nytt
fra Innstillinger.

### Test sier at påloggingsinformasjonen virker, men at appen ikke er installert noe sted

Registrering og installasjon er separate trinn. Åpne appens installasjonsside,
eller bruk **Installer GitHub-appen** under Arbeidsområde → Integrasjoner.

### Test sier at den private nøkkelen ikke kunne leses

Lim inn hele `.pem`-filen, inkludert linjene `-----BEGIN` og `-----END`. En
`ed25519`- eller EC-nøkkel kan ikke brukes: GitHub Apps signerer med RSA.

### Et medlem logget inn, men ser ingen repoer

Appen er ikke installert på kontoen som eier dem, eller installasjonen velger
andre repoer. En pålogging gir bare det appen har lov til å se.

### Agenter sier at installasjonen av GitHub App er suspendert

Noen har suspendert installasjonen på GitHub. Opphev suspensjonen under kontoens
**Settings → Applications → Installed GitHub Apps**.
