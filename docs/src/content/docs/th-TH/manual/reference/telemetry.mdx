Control Center สามารถส่ง **เหตุการณ์การใช้งานแบบใช้นามแฝง** ไปยังอินสแตนซ์ [Umami](https://umami.is) ได้ การวิเคราะห์การใช้งาน **ปิดอยู่จนกว่าผู้ดูแลเซิร์ฟเวอร์จะเปิด** การตั้งค่านี้เป็นของเซิร์ฟเวอร์และมีผลกับทุกไคลเอนต์ที่เชื่อมต่ออยู่ ได้แก่ แอปเดสก์ท็อป เว็บแอป โทรศัพท์ และตัวเซิร์ฟเวอร์เอง

การวิเคราะห์การใช้งานแยกจาก **แชร์รายงานข้อขัดข้อง** ซึ่งเป็นการตั้งค่ารายอุปกรณ์สำหรับการวินิจฉัยข้อขัดข้องและข้อผิดพลาด

## ใครเป็นผู้ตัดสินใจ

| สวิตช์ | ที่ไหน | ผลลัพธ์ |
| --- | --- | --- |
| **แชร์ข้อมูลวิเคราะห์การใช้งาน** | การเริ่มต้นใช้งาน (ขั้นตอนแซนด์บ็อกซ์) และ **การตั้งค่า → ความเป็นส่วนตัว** มีเพียงผู้ดูแลเซิร์ฟเวอร์ที่เปลี่ยนได้ สมาชิกคนอื่นเห็นค่าปัจจุบันแบบอ่านอย่างเดียว | มีผลทั้งเซิร์ฟเวอร์ เก็บเป็น `telemetry.usage_analytics` ในการตั้งค่าเซิร์ฟเวอร์ ปิดอยู่เว้นแต่ตั้งเป็น `true` |
| ประเภทบิลด์ | อัตโนมัติ | บิลด์ debug และ profile ไม่ส่งข้อมูล แต่จะเขียนแต่ละเหตุการณ์ลงในล็อกดีบักแทน |
| `CC_ANALYTICS_DEBUG=1` | สภาพแวดล้อมของ `cc_server` หรือไฟล์ `.env` ของมัน | อนุญาตให้บิลด์ debug และ profile ของเซิร์ฟเวอร์ และของทุกไคลเอนต์ที่เชื่อมต่ออยู่ ส่งข้อมูลจริงเพื่อการทดสอบ สวิตช์ด้านบนยังคงต้องเปิดอยู่ |
| `DO_NOT_TRACK=1` | สภาพแวดล้อมของ `cc_server` | หยุดการรายงานของเซิร์ฟเวอร์เอง ไม่ว่าสวิตช์จะเป็นอย่างไร ไคลเอนต์ยังคงทำตามสวิตช์ |
| เซิร์ฟเวอร์เดโม | อัตโนมัติ | เซิร์ฟเวอร์เดโมสาธารณะไม่ส่งข้อมูลใดในนามของตัวเอง ผู้เยี่ยมชมเปลี่ยนสวิตช์ไม่ได้ |

ไคลเอนต์อ่านการตั้งค่าจากเซิร์ฟเวอร์ (`telemetry.config` แล้วติดตามแบบสดผ่าน `telemetry.watch`) ระหว่างรอคำตอบ เหตุการณ์จะรออยู่ในบัฟเฟอร์ขนาดเล็กในหน่วยความจำ หากคำตอบคือไม่ บัฟเฟอร์จะถูกทิ้ง การปิดสวิตช์จะทิ้งทุกอย่างที่ยังค้างอยู่ในคิวและหยุดส่งทันทีบนทุกไคลเอนต์

## สิ่งที่ไม่มีวันถูกส่ง

- เนื้อหาของข้อความ ตั๋วงาน รีวิว หรือการประชุม ชื่อเรื่อง พรอมต์ คำสั่งเชลล์ และคำค้นหา
- ชื่อ ชื่อบัญชีสำหรับเข้าสู่ระบบ ที่อยู่อีเมล อวาตาร์ และชื่อที่แสดง
- พาธไฟล์ ชื่อรีโพซิทอรี ชื่อแบรนช์ ชื่อโฮสต์ และ URL (รีโพซิทอรีจะถูกส่งเป็น `repo_id` แบบนามแฝงเท่านั้น ลิงก์การประชุมจะถูกส่งเป็นผู้ให้บริการเท่านั้น)
- ตัวระบุดิบทุกประเภท

ทุกเหตุการณ์ต้องผ่านนโยบายพร็อพเพอร์ตีก่อนออกจากโปรเซส ข้อความ พาธ URL ที่อยู่อีเมล ID ที่ไม่ได้ห่อ และสตริงภายใต้คีย์อย่าง `email`, `*_name`, `path`, `title`, `prompt`, `content` หรือ `token` จะถูกทิ้งแทนที่จะถูกส่ง สตริงจะถูกส่งก็ต่อเมื่อเป็นโทเค็นสั้นจากชุดคำศัพท์ปิด เช่น ค่า enum เวอร์ชัน โลแคล หรือ ID ของโมเดล

## ID แบบนามแฝง

ID ถูกส่งไป แต่ในรูปของนามแฝงเท่านั้น ID ของเวิร์กสเปซ สเปซ บทสนทนา เอเจนต์ การรัน ผู้ใช้ และอุปกรณ์แต่ละรายการจะถูกแทนที่ด้วย HMAC-SHA256 ที่ใช้ salt ลับของการติดตั้งนั้นเอง (`telemetry.pseudonym_salt`) แล้วตัดเหลือ 20 อักขระฐานสิบหก เวิร์กสเปซเดียวกันจะรายงานค่าเดิมเสมอ จึงเชื่อมโยงและนับเหตุการณ์ได้ แต่ ID ดิบจะไม่ออกจากการติดตั้งเลย salt ถูกสร้างตอนเซิร์ฟเวอร์เริ่มทำงานครั้งแรกและไม่เคยถูกส่งให้ผู้ให้บริการวิเคราะห์ การลบไดเรกทอรีข้อมูลของเซิร์ฟเวอร์จะสร้าง salt และ ID การติดตั้งใหม่ ซึ่งตัดความเชื่อมโยงกับทุกอย่างที่บันทึกไว้ก่อนหน้า

## การดูหน้าจอ

การนำทางแต่ละครั้งจะบันทึกการดูหน้าที่มี URL เป็น **เทมเพลตเส้นทาง** เช่น `/workspaces/:workspaceId/spaces/:spaceId` ไม่ใช่ที่อยู่จริง ชื่อหน้าจอคือส่วนที่เป็นตัวอักษรตายตัวของเทมเพลต ตัวอย่างนี้จึงเป็น `workspaces_spaces` พารามิเตอร์เส้นทางที่ลงท้ายด้วย `Id` จะแนบเป็นพร็อพเพอร์ตี `*_id` แบบนามแฝง และพารามิเตอร์ที่เป็นตัวเลข (เช่น หมายเลข PR) จะแนบเป็นตัวเลข พารามิเตอร์อื่นทั้งหมดจะถูกทิ้ง

## การส่งข้อมูล

เหตุการณ์จะถูกส่งทีละรายการไปยัง `<host>/api/send` จากคิวในหน่วยความจำที่จุได้สูงสุด 200 เหตุการณ์ ข้อผิดพลาดเครือข่าย การหมดเวลา `429` หรือ `5xx` จะเก็บเหตุการณ์ไว้และลองใหม่ด้วย exponential backoff ตั้งแต่ 1 วินาทีไปจนถึง 5 นาที ส่วน `4xx` อื่นๆ จะทิ้งเหตุการณ์นั้น ไม่มีสิ่งใดถูกเขียนลงดิสก์ เหตุการณ์ที่ยังค้างอยู่ในคิวตอนปิดแอปจึงสูญหาย คิวจะถูกส่งออกจนหมดเมื่อแอปเข้าสู่เบื้องหลังและเมื่อเซิร์ฟเวอร์ปิดตัว

## ชี้บิลด์ไปยังอินสแตนซ์อื่น

ปลายทางถูกกำหนดตายตัวตอนบิลด์

```bash
--dart-define=CC_ANALYTICS_HOST=https://analytics.example.com/
--dart-define=CC_ANALYTICS_WEBSITE_ID=<website uuid>
```

อะแดปเตอร์ของผู้ให้บริการอยู่ใน `packages/cc_analytics` การรองรับบริการวิเคราะห์อื่นหมายถึงการเพิ่มอะแดปเตอร์ไว้ที่นั่น แผนการติดตามและกฎความเป็นส่วนตัวยังคงเหมือนเดิม
