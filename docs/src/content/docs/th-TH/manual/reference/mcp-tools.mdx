`cc_server` เป็นโฮสต์ของรีจิสทรีเครื่องมือ MCP (JSON-RPC 2.0) หนึ่งเดียว ให้บริการบนพอร์ตหลักของเซิร์ฟเวอร์ (ค่าเริ่มต้น `9030`) ที่ `POST /mcp` และ `GET /sse` เวอร์ชันโปรโตคอล `2024-11-05` ไคลเอนต์ทุกตัวเข้าถึงรีจิสทรีเดียวกัน: เดสก์ท็อป บิลด์เว็บ ไคลเอนต์ MCP ภายนอก และรันไทม์เอเจนต์ในตัว เซิร์ฟเวอร์ MCP ภายนอกเชื่อมเข้ารีจิสทรีเดียวกันได้ในฐานะเลเยอร์ไดนามิก

## ขนาดของรีจิสทรี

| ตัววัด                                                                       | จำนวน |
| ------------------------------------------------------------------------- | ----- |
| เครื่องมือที่ `cc_server` ลงทะเบียนไว้                                        | 110   |
| จาก `packages/cc_mcp`                                                     | 108   |
| จาก `packages/cc_mcp_client` (การค้นหาเครื่องมือ)                          | 2     |
| ลงทะเบียนในรีจิสทรีฐาน (`server_mcp_registry.dart`)                        | 63    |
| ลงทะเบียนหลังบูตเมื่อบริการต่าง ๆ พร้อมใช้งาน (`cc_server_runtime.dart`)      | 47    |
| ใน 63 รายการของรีจิสทรีฐาน เป็นเงื่อนไขกับรีโพกราฟโค้ด                        | 5     |

เครื่องมือกราฟโค้ดทั้งห้าตัวจะลงทะเบียนก็ต่อเมื่อโฮสต์ส่งรีโพกราฟโค้ดให้ `buildServerMcpRegistry` เท่านั้น `cc_server` ส่งให้เสมอ ทั้ง 110 รายการจึงทำงานอยู่ในไบนารีที่จัดส่ง

รีจิสทรีทั้งหมดถูกประกาศใน `tools/list` โดยไม่มีการกั้นการค้นหา การแก้ไขตั๋วงานเป็นเครื่องมือแบบมีชนิด

:::note[ไคลเอนต์ภายนอกเห็นแค็ตตาล็อกทั้งหมดเสมอ]
`tools/list` ไม่เคยถูกตัดทอน ไคลเอนต์ MCP ตรวจสอบชื่อเครื่องมือเทียบกับสำเนาแคชของตัวเองของรายการนั้น และปฏิเสธทุกอย่างที่ไม่อยู่ในรายการโดยไม่ถามเซิร์ฟเวอร์ เครื่องมือที่ซ่อนไว้ตรงนั้นจึงเข้าถึงไม่ได้ แทนที่จะแค่ไม่ส่งเสียง

**ฮาร์เนสในตัว** ต่างออกไป: มันโหลดเฉพาะชุดคำจำกัดความ**ประจำ**บางส่วนต่อคำขอ แล้วดึงที่เหลือเข้ามาเมื่อใช้งานครั้งแรก ซึ่งเป็นพฤติกรรมฝั่งฮาร์เนสและไม่เปลี่ยนรีจิสทรีนี้ ดู[บริบทเครื่องมือและการแคชพรอมต์](/th-TH/คู่มือ/แนวคิด/บริบทเครื่องมือ)
:::

:::note[คลาสเครื่องมือทุกคลาสถูกลงทะเบียน]
ไฟล์ซอร์สใต้ `packages/cc_mcp/lib/src/tools/` คือเครื่องมือที่เอเจนต์เรียกได้
`packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart`
ทำให้บิลด์ล้มเหลวหากมีคลาสเครื่องมือใหม่ที่ไม่มีใครสร้างขึ้นมา
:::

## พารามิเตอร์ทั่วไป

### `workspace_id`

**จำเป็น** สำหรับทุกเครื่องมือที่แตะข้อมูลในขอบเขตเวิร์กสเปซ `workspace_id` ที่หายไปหรือไม่ถูกต้องจะคืนข้อผิดพลาดที่ระบุชัดเจน และค่าที่ไม่ตรงกับเวิร์กสเปซของเอนทิตีเป้าหมายจะถูกปฏิเสธแทนที่จะถูกเพิกเฉยเงียบ ๆ ละเว้นมันสำหรับเครื่องมือระดับโลกจริง ๆ: `list_workspaces` และเครื่องมือฟีดข่าวทั้งหก (`list_feeds`, `list_articles`, `get_article`, `set_article_read`, `set_article_saved`, `refresh_feeds`) ซึ่งใช้รายการฟีดรายผู้ใช้ของเจ้าของเซิร์ฟเวอร์ เครื่องมือค้นหา (`search_tool_bm25`, `list_my_tools`) รับมันเป็นทางเลือก เพื่อให้จำแนกได้ว่าเรียกใช้ได้หรือไม่ตามโหมดการสนทนา เมื่อเซิร์ฟเวอร์สั่งงานเอเจนต์ เวิร์กสเปซจะถูกบังคับฝั่งเซิร์ฟเวอร์ เอเจนต์จึงเข้าถึงเวิร์กสเปซอื่นไม่ได้ด้วยการส่ง id แปลกปลอมเข้ามา

## การค้นหาเครื่องมือ

ทั้งสองตัวมาจาก `cc_mcp_client` ไม่ใช่ `cc_mcp` และทั้งคู่ปรึกษาตัวเฝ้าโหมด จึงรายงานว่าอะไรเรียกได้ในโหมดการสนทนา_ปัจจุบัน_

| เครื่องมือ | คำอธิบาย                                                                                                                 |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `search_tool_bm25` | ค้นหาแค็ตตาล็อกเครื่องมือด้วยคำค้น; คืนเครื่องมือที่ตรง สคีมาอาร์กิวเมนต์ของแต่ละตัว และว่าแต่ละตัวเรียกได้ในขณะนี้หรือไม่ |
| `list_my_tools`    | แสดงเครื่องมือที่เรียกได้ในขณะนี้ในการสนทนานี้ กรองตามโหมดของมัน                                                |

เครื่องมือค้นหาตัวที่สาม **`search_tools`** มีอยู่เฉพาะภายในฮาร์เนสในตัว และไม่ได้เป็นส่วนหนึ่งของรีจิสทรี MCP นี้ มันจัดอันดับพื้นผิวเครื่องมือของการรันเอง และต่างจาก `search_tool_bm25` ตรงที่มัน**โหลด**สคีมาของสิ่งที่พบ เพื่อให้เอเจนต์เรียกตัวที่ตรงได้ในเทิร์นถัดไป เอเจนต์บนฮาร์เนสควรใช้ตัวนี้ ส่วนไคลเอนต์ MCP มี `search_tool_bm25`

## การส่งข้อความและการมอบงานระหว่างเอเจนต์

เอเจนต์คุยกันผ่านสเปซ (ถาวร มองเห็นได้ในรายชื่อ) `ask_agent` เป็นแบบคำขอ/ตอบกลับที่มีการหมดเวลาแบบบังคับ ส่วน `delegate_task` ถูกป้องกันฝั่งเซิร์ฟเวอร์ด้วยเพดานความลึก การตรวจจับวงจร กรอบงบประมาณ และเพดานความเป็นอิสระ

| เครื่องมือ            | คำอธิบาย                                                                                    |
| --------------- | ---------------------------------------------------------------------------------------------- |
| `send_to_agent` | ส่งข้อความทางเดียวไปยังเอเจนต์อื่น โดยระบุด้วย `to_agent_id` หรือ `to_agent_name` ที่ตรงเป๊ะ   |
| `ask_agent`     | ถามคำถามกับเอเจนต์อื่นและรอคำตอบ หรือหมดเวลา                               |
| `delegate_task` | มอบงานให้เอเจนต์อื่นในรูปตั๋วงานลูกที่ติดตามได้                                     |
| `consult_agent` | เพิ่มผู้เชี่ยวชาญที่ตรงที่สุดตามสกิลเข้าสเปซ แล้วสั่งงานด้วยบรีฟที่เจาะจง |
| `todo_read`     | อ่านรายการสิ่งที่ต้องทำที่บันทึกไว้ของบทสนทนานี้                                              |

## เครื่องมือสกิล

การติดตั้งและการอัปเดตทุกครั้งผ่านด่านสแกนแบบล้มเหลวปลอดภัย ก่อนที่เนื้อหาสกิลใดจะถึงดิสก์หรือพรอมต์ของเอเจนต์

| เครื่องมือ                 | คำอธิบาย                                                               |
| -------------------- | ------------------------------------------------------------------------- |
| `list_skills`        | แสดง slug ของสกิลที่มีในเวิร์กสเปซ                             |
| `create_skill`       | สร้างสกิลใหม่จากเนื้อหา markdown                                  |
| `install_skill`      | ติดตั้งไดเรกทอรีทั้งหมดของสกิลจากรีโพสิทอรี GitHub ที่ ref ปักหมุดไว้ |
| `update_skill`       | อัปเดตสกิล GitHub ที่ติดตั้งแล้วไปยัง ref ใหม่ พร้อมสแกนและปักหมุดใหม่ |
| `list_skill_updates` | แสดงสกิลที่มีเวอร์ชันใหม่กว่าให้ใช้                                |
| `verify_skills`      | ตรวจสอบสกิลที่ล็อกไว้เทียบกับแฮชเนื้อหาบนดิสก์ของมัน                 |
| `pin_skill`          | แฮชสกิลที่มีอยู่บนดิสก์เข้าสู่ `skills-lock.json`                    |

## เครื่องมือรีวิว

| เครื่องมือ                       | คำอธิบาย                                                                                            |
| -------------------------- | ------------------------------------------------------------------------------------------------------ |
| `start_ai_review`          | เริ่มรีวิวด้วย AI สำหรับ PR: คำนวณพื้นที่รีวิว กระจายรีวิวเวอร์ผู้เชี่ยวชาญเข้าสเปซรีวิว เขียนคำอธิบายแบบพาไล่ดู และปิดท้าย |
| `add_review_node`          | เพิ่มข้อค้นพบการรีวิวแบบมีโครงสร้าง (ไฟล์ บรรทัด ลำดับความสำคัญ P0–P3) ลงในสเปซรีวิว                       |
| `confirm_review_node`      | ยืนยันข้อค้นพบของเพื่อนร่วมงาน; ผู้เขียนยืนยันข้อค้นพบของตัวเองไม่ได้                                               |
| `resolve_review_node`      | ทำเครื่องหมายว่าข้อค้นพบได้รับการแก้ไขแล้วหลังจากลงมือเปลี่ยนแปลงจริง; โพสต์ร่องรอยเข้าสเปซรีวิว              |
| `dismiss_review_node`      | ปิดข้อค้นพบที่ไม่เกี่ยวข้อง; บันทึกข้อเท็จจริงการระงับเพื่อให้รีวิวเวอร์หยุดตั้งธงซ้ำ                          |
| `request_peer_review`      | ขอให้เอเจนต์รีวิวเวอร์อีกตัวช่วยดูข้อค้นพบเป็นรอบที่สอง                                              |
| `dispatch_reviewers`       | กระจายเอเจนต์รีวิวเวอร์ที่จับคู่ได้เข้าสเปซรีวิวแบบพร้อมกัน                                   |
| `submit_reviewer_verdict`  | โพสต์คำตัดสิน ship/hold/block ต่อรีวิวเวอร์หนึ่งราย พร้อมความเชื่อมั่นและคำอธิบาย                         |
| `finalize_review`          | คำนวณฉันทามติต่อโหนดและคำตัดสินต่อ PR แล้วปิดรีวิว                                 |
| `set_cohort_summary`       | ตั้งสรุปภาษาธรรมชาติของ cohort รีวิวหนึ่งอัน                                                           |
| `add_review_diagram`       | แนบแผนภาพที่มีโครงสร้างและผ่านการตรวจสอบด้วยกราฟ (`sequence`, `entityRelation`, `stateMachine`) เข้ากับ cohort |
| `publish_review_to_github` | เผยแพร่รีวิวที่ปิดท้ายแล้วไปยัง GitHub เป็นความเห็นแบบอินไลน์พร้อมเนื้อความสรุป                          |

## เครื่องมือหน่วยความจำ

| เครื่องมือ                    | คำอธิบาย                                                                                         |
| ----------------------- | --------------------------------------------------------------------------------------------------- |
| `search_memory`         | ค้นหาข้อเท็จจริงและนโยบาย (คำค้น ความหมาย หรือแบบผสม — ค่าเริ่มต้นคือแบบผสม)                    |

## เครื่องมือเอนโคลเจอร์ (ริก)

ขับเครื่องแบบใช้แล้วทิ้ง — เบราว์เซอร์หรือเดสก์ท็อป Linux ที่ถูกปิดล้อม
เอมูเลเตอร์ Android หรือ iOS Simulator — จากภายในรัน ลงทะเบียนหลังบูต
แบบไม่มีเงื่อนไข: ว่าเครื่องจะบูตได้จริงหรือไม่เป็นคำถามเชิงตรวจสอบที่
เครื่องมือตอบเป็นรายการเรียก การเรียกซ้ำ ๆ ในบทสนทนาเดียวกันใช้เครื่องเดิมร่วมกัน;
สกรีนช็อตส่งกลับมาเป็นเนื้อหารูปภาพโดยมีงบหนึ่งภาพต่อผลลัพธ์ และ
เนื้อหาหน้าเว็บ/UI ที่สกัดออกมาถูกกั้นไว้เป็นข้อมูลที่ไม่น่าเชื่อถือ เครื่องมือใช้งานสี่ตัวบวก
`rig_close` ประกาศ[คลาสการกระทำ](/th-TH/คู่มือ/แนวคิด/กฎคุม/) `enclosureControl`
(เครื่องมือใช้งานยังประกาศ `networkEgress` และ `processSpawn` ด้วย; `mobile_use` และ
`ios_use` ยังประกาศ `packageInstall` ด้วย) โหมดอ่านอย่างเดียวจึงปฏิเสธเครื่องมือเหล่านี้ `rig_list`
ไม่ประกาศคลาสใดเลย — มันอ่านสถานะเวิร์กสเปซเท่านั้น คำศัพท์คำกริยาทั้งหมดต่อพื้นผิวอยู่ใน
[เอกสารอ้างอิงริก](/th-TH/คู่มือ/อ้างอิง/ริก/#action-verbs)

| เครื่องมือ           | คำอธิบาย                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------ |
| `computer_use` | ขับเดสก์ท็อป Linux ใน VM ที่ปิดล้อม: เลื่อน คลิก ลาก เลื่อนดู พิมพ์ ปรับขนาด คลิปบอร์ด สกรีนช็อต |
| `browser_use`  | ขับ Chromium, Firefox หรือ WebKit แบบไม่มีหน้าจอ (`engine`): นำทาง คลิก กรอก สกัด (a11y/DOM/console) คลิปบอร์ด สกรีนช็อต |
| `mobile_use`   | ขับ Android ผ่าน ADB: ตรวจสอบ/ป้อนข้อมูล สกรีนช็อต ติดตั้ง/เริ่ม/หยุด/รีเซ็ต/ถอนการติดตั้งแอป deep link และคำสั่งอุปกรณ์รูป argv |
| `ios_use`      | ขับ iOS Simulator ผ่าน WebDriverAgent/CoreSimulator: ตรวจสอบ/ป้อนข้อมูล สกรีนช็อต ติดตั้ง/เริ่ม/หยุด/ถอนการติดตั้งแอป deep link และโปรเซสจำลองรูป argv |
| `rig_list`     | แสดงริกของเวิร์กสเปซพร้อมพื้นผิว สถานะ ขนาดจอ และตัวควบคุม |
| `rig_close`    | ทำลายริกและทิ้งสถานะเครื่องที่เป็นของมัน |

## สิ่งที่ไม่เปิดให้เข้าถึงผ่าน MCP

ปฏิทินและการประชุมไม่มีเครื่องมือ MCP เอเจนต์อ่านปฏิทิน การประชุม ถอดเสียง รายการสิ่งที่ต้องทำ หรือคำตัดสินของคุณไม่ได้ สรุปที่ผลิตรายการสิ่งที่ต้องทำและคำตัดสินรันเป็น[ไปป์ไลน์ `meeting_summary`](/th-TH/คู่มือ/แนวคิด/การประชุม/) ในตัว ไม่ใช่เครื่องมือที่เอเจนต์เรียกได้

## การกั้นเครื่องมือตามโหมด

การกั้นถูกบังคับใช้สองครั้งจากตารางเดียว (`ModeToolPolicy`): ครั้งหนึ่งในตัวจัดส่ง MCP สำหรับอะแดปเตอร์ Claude Code และอีกครั้งในรีจิสทรีของฮาร์เนสในตัว การเรียกที่ถูกกั้นจะคืนเหตุผล

| โหมด          | พื้นผิวเครื่องมือ                                                                                                                                                                                                                        |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`        | เครื่องมือที่ลงทะเบียนไว้ทุกตัว; ไม่มีรายการที่อนุญาต                                                                                                                                                                                                |
| `plan`        | รายการที่อนุญาตที่คัดสรรไว้ ไม่มีการเขียน worktree และไม่มีคำกริยาตั๋วงาน `create` / `assign` / `delegate` แต่หน่วยความจำ อาร์ติแฟกต์ รายการสิ่งที่ต้องทำ `submit_plan`, `exit_plan_mode` และคำกริยาการปิดตั๋วงานบนตั๋วงานที่ถูกสั่งงานได้รับอนุญาต |
| `review`      | รายการที่อนุญาตที่คัดสรรไว้: การมีส่วนร่วมในรีวิว การสื่อสาร ตัวดึงบริบทแบบอ่านอย่างเดียว และชุดคำกริยาตั๋วงานทั้งหมดรวมถึง `create_ticket` และ `assign_ticket`                                                                    |
| `orchestrate` | รายการที่อนุญาตที่คัดสรรไว้: เครื่องมือค้นคว้าและอ่าน บวก `propose_orchestration`, `create_playbook` และ `run_playbook` การจ้าง การแบ่งงานย่อย และการปิดตั๋วงานเกิดขึ้นแบบกำหนดแน่นอนหลังการอนุมัติ ไม่เคยเกิดขึ้นกลางรัน                |

อนุญาตในทุกโหมดโดยไม่สนใจรายการที่อนุญาต:

| ชุด                  | เครื่องมือ                                                                                                                                                                                                                                                             |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| หน่วยความจำและอาร์ติแฟกต์ | `search_memory`, `propose_fact`, `propose_policy`, `supersede_fact`, `supersede_policy`, `record_observation`, `update_my_notes`, `get_my_notes`, `list_memory_domains`, `list_policies`, `publish_artifact`, `revise_artifact`, `list_artifacts`, `get_artifact` |
| กราฟโค้ด           | `search_code`, `code_symbol`, `code_callers`, `code_callees`, `code_impact`                                                                                                                                                                                       |
| กลไกการรัน        | `search_tool_bm25`, `list_my_tools`, `todo_write`, `todo_read`                                                                                                                                                                                                    |

การอยู่ในรายการที่อนุญาตไม่ได้ทำให้เครื่องมือเรียกได้ และกลับกันก็เช่นกัน: ความสามารถในการถามโอเปอเรเตอร์เป็นเครื่องมือของ **ฮาร์เนส** (`ask_user`) จึงไม่ปรากฏในแค็ตตาล็อก MCP นี้เลย

## เครื่องมือที่กั้นด้วยการอนุมัติ

เครื่องมืออาจประกาศ `requiresApproval` ได้ จากนั้นตัวจัดส่งจะสร้าง `ApprovalPayload` และแสดงมันผ่าน `ConfirmationPort` ก่อนที่เครื่องมือจะรัน; `cc_server` ต่อพอร์ตนั้นไว้ ด่านจึงทำงานจริง

เครื่องมือที่ลงทะเบียนไว้ซึ่งประกาศมัน: `create_ticket`, `update_ticket`, `assign_ticket`, `reassign_ticket`, `close_ticket`, `ticket_relation`, `create_goal`, `update_goal_progress`, `create_approval`, `decide_approval`, `comment_approval`, `create_work_product`, `save_work_product_revision`, `create_runtime_profile`, `install_skill`, `update_skill`.

โดยเป็นอิสระจากกัน กฎคุมการกระทำแบบรวมจะกั้นเครื่องมือใดก็ตามที่ประกาศชุด `ActionClass` ที่ไม่ว่าง คำตัดสิน `prompt` ที่ไม่มีผู้อนุมัติเชื่อมต่ออยู่จะถูกปฏิเสธ ดู[กฎคุม](/th-TH/คู่มือ/แนวคิด/กฎคุม/)

## ความสามารถที่ไม่มีเครื่องมือรองรับ

ไม่ใช่ทุกความสามารถในผลิตภัณฑ์ที่เอเจนต์เข้าถึงได้ สิ่งเหล่านี้ไม่มีเครื่องมือ
เลย ชื่อที่คุณอาจเคยเห็นอ้างถึงที่อื่นจึงคืนค่า "unknown tool":

| ความสามารถ                             | ที่อยู่จริงของมัน                                                                       |
| -------------------------------------- | -------------------------------------------------------------------------------------------- |
| การจ้าง การไล่ออก หรือการแก้ไขเอเจนต์      | UI ของเอเจนต์ ไม่มีเครื่องมือ `hire_agent` / `fire_agent` / `update_agent`                 |
| การสร้างเวิร์กสเปซ                    | `workspace.upsert` ผ่าน RPC ซึ่งเพาะข้อมูลเริ่มต้นและประทับความเป็นเจ้าของ                                  |
| โปรเจกต์ (สร้าง / แสดงรายการ / อัปเดต / ผูกไฟล์) | UI ของตั๋วงาน โปรเจกต์เป็นพื้นผิวสำหรับโอเปอเรเตอร์ — ดู[โปรเจกต์](/th-TH/คู่มือ/วิธีทำ/โปรเจกต์/)     |
| การถามคำถามแบบบล็อกกับโอเปอเรเตอร์ | เครื่องมือ `ask_user` ของ **ฮาร์เนส** ไม่ใช่ MCP มันเรนเดอร์ฟอร์มในบทสนทนาและบล็อกรอคำตอบ  |
| การวินิจฉัยรายเอเจนต์                   | ไม่มีเลย ไม่มี `doctor` — ดู[การวินิจฉัยเอเจนต์](/th-TH/คู่มือ/วิธีทำ/วินิจฉัยเอเจนต์/)      |
| ปฏิทินและการประชุม                   | RPC สำหรับไคลเอนต์มนุษย์เท่านั้น (ดูด้านบน)                                                          |
