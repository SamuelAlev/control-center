ทุกสิ่งที่ Control Center คัดลอก ส่งต่อ หรือนำมาใช้ได้ พร้อมรูปร่างที่แน่นอนของอาร์ติแฟกต์
แต่ละชิ้น หากต้องการสำรองข้อมูลจริง ๆ ดู
[สำรองและกู้คืน](/th-TH/คู่มือ/วิธีทำ/สำรองและกู้คืน/) ส่วนเหตุใดการเก็บข้อมูลถาวรจึง
แยกแบบนี้ ดู[เวิร์กสเปซและการแยกโดเมน](/th-TH/คู่มือ/แนวคิด/เวิร์กสเปซ/)

## อาร์ติแฟกต์

มีอาร์ติแฟกต์สำเนาฐานข้อมูลสามแบบ ซึ่งมีขอบเขตและนโยบายการลบต่างกัน

| อาร์ติแฟกต์                | เขียนโดย                     | รูปร่าง                                | ครอบคลุม                        |
| ----------------------- | ---------------------------- | ------------------------------------- | ----------------------------- |
| **สแนปช็อตการติดตั้ง**    | `server.backupNow`           | **ไดเรกทอรี**ที่ประทับเวลา           | ทุกฐานข้อมูลบนการติดตั้ง |
| **ข้อมูลสำรองของเวิร์กสเปซ**    | ไปป์ไลน์ `Workspace backup`  | ไดเรกทอรีที่ประทับเวลาซึ่งมี `.db` หนึ่งไฟล์  | ฐานข้อมูลของเวิร์กสเปซหนึ่งตัว      |
| **การส่งออกเวิร์กสเปซ**    | `workspace.export`           | **ไฟล์** `.db` ไฟล์เดียว               | ฐานข้อมูลของเวิร์กสเปซหนึ่งตัว      |

ทั้งหมดเขียนด้วย `VACUUM INTO` ของ SQLite ซึ่งปลอดภัยกับฐานข้อมูล WAL ที่ใช้งานอยู่:
มันเปิดทรานแซกชันแบบอ่าน สร้างสำเนาที่จัดเรียงข้อมูลใหม่และสอดคล้องเชิงทรานแซกชัน
และไม่ต้องหยุดเซิร์ฟเวอร์เลย

ไฟล์เหล่านี้และสำเนาที่ดาวน์โหลดมา **ไม่ได้ถูกเข้ารหัสขณะจัดเก็บ** โดย Control
Center การโอนที่เข้ารหัสแบบต้นทางถึงปลายทางปกป้องไบต์ระหว่างทางระหว่างไคลเอนต์
ที่จับคู่แล้วกับ `cc_server` ของมัน ทั้งบนการเชื่อมต่อโดยตรงและผ่านรีเลย์ที่
โบรกเกอร์ไว้ ปกป้องที่เก็บข้อมูลในเครื่องและสำเนานอกเครื่องแยกต่างหาก เซิร์ฟเวอร์
และผู้รับที่ได้รับอนุญาตสามารถอ่านไฟล์ฐานข้อมูลได้

## โครงร่างของสแนปช็อต

```
<dataDir>/backups/2026-07-28T09-12-33-000Z/
  manifest.json
  global.db
  <workspaceId>/workspace.db      one directory per workspace
```

โครงร่างสะท้อนไดเรกทอรีข้อมูลที่ใช้งานอยู่แบบตรงทั้งหมด ซึ่งเป็นสิ่งที่ทำให้การกู้คืน
การติดตั้งเป็นการคัดลอกกลับ ไม่ใช่การแปลง ชื่อไดเรกทอรีคือเวลาประทับ UTC
โดยแทน `:` และ `.` ด้วย `-` จึงปลอดภัยกับระบบไฟล์บน Windows และเรียงตามเวลาได้
ด้วยการเทียบสตริงธรรมดา

ข้อมูลสำรองของเวิร์กสเปซตามกำหนดเวลาอยู่แยกกันที่ `<dataDir>/backups/workspace-backups/<workspaceId>/<timestamp>/workspace.db` แต่ละรายการมี `manifest.json` สำหรับไฟล์นั้นเพียงไฟล์เดียว และไม่มี `global.db` มันไม่ใช่สแนปช็อตการติดตั้ง การกู้คืนจะเก็บฐานข้อมูลที่มันแทนที่ไว้ในที่เดิมในชื่อ `<timestamp>-pre-restore` ขั้นตอนการเก็บรักษาของไปป์ไลน์รายสัปดาห์ลบเฉพาะข้อมูลสำรองของเวิร์กสเปซตัวเองที่เก่ากว่าอายุที่กำหนดไว้ (ค่าเริ่มต้น 30 วัน) เท่านั้น สแนปช็อตการติดตั้งที่สร้างด้วยมือจะไม่ถูกหมุนเวียนโดยขั้นตอนนั้นเลย `server.listBackups` แสดงเฉพาะสแนปช็อตการติดตั้ง รวมถึงสแนปช็อตที่ยังไม่ได้ตรวจสอบด้วย ส่วน `workspace.listBackups` แสดงข้อมูลสำรองตามกำหนดเวลาของเวิร์กสเปซหนึ่งแห่ง

การลบเวิร์กสเปซจะคงไดเรกทอรีนี้ไว้ กำหนดการของเวิร์กสเปซหยุดไปพร้อมกับมัน
จึงไม่มีสิ่งใดหมุนเวียนข้อมูลสำรองเหล่านั้นอีก และข้อมูลสำรองจะอยู่จนกว่าเจ้าของการติดตั้งจะลบออก
`server.listOrphanedBackups` รายงานข้อมูลสำรองเหล่านี้


### `manifest.json`

| ฟิลด์                      | ชนิด            | ความหมาย                                                             |
| -------------------------- | --------------- | ------------------------------------------------------------------- |
| `format`                  | int             | รูปแบบของแมนิเฟสต์ ปัจจุบันคือ `2`                              |
| `created_at`               | ISO-8601 UTC    | เวลาที่ถ่ายสแนปช็อต                                         |
| `global`                   | object          | ข้อมูลของ `global.db` ไม่มีในข้อมูลสำรองของเวิร์กสเปซตามกำหนดเวลา |
| `workspaces[]`             | array           | หนึ่งระเบียนต่อเวิร์กสเปซที่จับมา                                    |
| `workspaces[].workspace_id`| string          | เวิร์กสเปซที่ไฟล์นี้เก็บไว้                                       |
| `skipped_workspaces[]`     | array           | เวิร์กสเปซที่ข้อมูลสำรอง **จับไม่ได้**                         |
| `skipped_workspaces[].workspace_id` | string | เวิร์กสเปซที่ถูกละไว้ |
| `skipped_workspaces[].reason` | string | `no_file`, `damaged` หรือ `failed` |

`global` และแต่ละรายการของ `workspaces[]` บันทึกไฟล์ที่คัดลอกหนึ่งไฟล์ โดยวัดบนสำเนาหลังจากเขียนเสร็จแล้ว:

| ฟิลด์ | ชนิด | ความหมาย |
| ---------------- | ------ | ------------------------------------------------------------------------------ |
| `file`        | string          | พาธเทียบกับรากของสแนปช็อต: `global.db` หรือ `<workspaceId>/workspace.db`    |
| `bytes`       | int             | ขนาดของสำเนานั้น                                                   |
| `sha256`         | string | SHA-256 ของสำเนา เป็นเลขฐานสิบหกตัวพิมพ์เล็ก |
| `quick_check`    | string | สิ่งที่ `quick_check` ของ SQLite รายงานเกี่ยวกับสำเนา: `ok` หรือผลการตรวจพบ |
| `user_version`   | int    | เวอร์ชันสคีมาของสำเนา |
| `application_id` | int    | `application_id` ของ SQLite ของสำเนา |

เวิร์กสเปซจะถูกข้ามเมื่อมันถูกลงทะเบียนแต่ยังไม่เคยถูกเขียนเลย (`no_file`) เมื่อฐานข้อมูลของมันไม่ผ่านการตรวจสอบความสมบูรณ์ (`damaged`; จะไม่มีการคัดลอกสำเนาที่เสียหาย) หรือเมื่อการคัดลอกหรือการตรวจสอบสำเนานั้นล้มเหลว (`failed`) ไม่ว่ากรณีใด สแนปช็อตก็ยังเสร็จสมบูรณ์ และแมนิเฟสต์ระบุสิ่งที่ขาดหายไว้ แมนิเฟสต์จะถูกเขียนเป็นลำดับสุดท้าย

### ความครบถ้วน

`server.listBackups` รายงานแฟล็ก `complete` ต่อสแนปช็อตหนึ่งตัว โดยเป็น false เมื่อแมนิเฟสต์หายไป อ่านไม่รู้เรื่อง หรือเป็นรูปแบบอื่น เมื่อไฟล์ที่มันระบุชื่อหายไปหรือมีขนาดต่างออกไป หรือเมื่อสำเนาไม่ผ่านการตรวจสอบ แอปจะแสดงสแนปช็อตเช่นนั้นเป็น **ยังไม่ได้ตรวจสอบ** สแนปช็อตที่ถูกจับก่อนรูปแบบ `2` อยู่ในสถานะนั้น

สแนปช็อตที่ยังไม่ได้ตรวจสอบยังคงถูกแสดง เพราะสแนปช็อตที่ผู้ดำเนินการมองไม่เห็นคือ
สแนปช็อตที่พวกเขาเชื่อว่ามีอยู่ เมื่ออ่านแมนิเฟสต์ไม่ได้ การแสดงรายการจะถอยไปใช้
โครงร่างเองและรายงานไฟล์ `<workspaceId>/workspace.db` ที่หาเจอ —
ไฟล์เหล่านั้นยังนำมาใช้ทีละไฟล์ผ่าน `workspace.import` ได้ แม้สแนปช็อต
ทั้งก้อนจะกู้คืนการติดตั้งไม่ได้ก็ตาม

สแนปช็อตหรือข้อมูลสำรองตามกำหนดเวลาที่ถูกแสดงจะมี `pinned_reason: "last_good_copy"` ขณะที่มันถือสำเนาที่ตรวจสอบแล้วล่าสุดของเวิร์กสเปซซึ่งฐานข้อมูลที่ใช้งานอยู่เสียหาย ขั้นตอนการเก็บรักษาจะข้ามมันไปจนกว่าเวิร์กสเปซนั้นจะถูกกู้คืน

## สิ่งที่ข้อมูลสำรองไม่มี

อาร์ติแฟกต์ทั้งสองเป็น**ฐานข้อมูลเท่านั้น** ไดเรกทอรีของเวิร์กสเปซเก็บมากกว่า
ฐานข้อมูลของมัน และส่วนที่เหลือไม่ได้เดินทางไปด้วยเลย:

| พาธ                                | อยู่ในสแนปช็อต? | อยู่ในการส่งออกเวิร์กสเปซ? |
| ----------------------------------- | -------------- | ---------------------- |
| `global.db`                         | ใช่            | ไม่                     |
| `<workspaceId>/workspace.db`        | ใช่            | ใช่ (มัน*คือ*ไฟล์นั้น) |
| `<workspaceId>/code_index.db`       | ไม่ | ไม่ |
| `<workspaceId>/blobs/`              | ไม่             | ไม่                     |
| `<workspaceId>/skills/`             | ไม่             | ไม่                     |
| `<workspaceId>/agents/`             | ไม่             | ไม่                     |
| `<workspaceId>/chat_credentials/`   | ไม่             | ไม่                     |
| `<workspaceId>/spaces/<spaceId>/`   | ไม่             | ไม่                     |
| `<workspaceId>/pr_clones/`          | ไม่             | ไม่                     |
| `secrets.json`                      | ไม่             | ไม่                     |
| `models/`                           | ไม่             | ไม่                     |
| `meetings/<meetingId>/`             | ไม่             | ไม่                     |
| `rigs/`                             | ไม่             | ไม่                     |
| `_agent_hooks/`                     | ไม่             | ไม่                     |

บางส่วนทิ้งได้ — `spaces/` เก็บเวิร์กทรีแบบ copy-on-write ที่จัดเตรียมใหม่จากรีโป `pr_clones/` เป็นแคช `code_index.db` ถูกสร้างใหม่ `models/` ดาวน์โหลดใหม่ได้ `rigs/` เป็นสถานะของเครื่อง บางส่วนทิ้งไม่ได้: `blobs/` เก็บรูปที่วางเข้ามาซึ่งแถวในฐานข้อมูลชี้ไปหา `skills/` และ `agents/` เก็บไฟล์ที่เอเจนต์ใช้รัน และ `secrets.json` เก็บคีย์จับคู่ทุกอัน ข้อมูลรับรองของผู้ให้บริการ และการตั้งค่า SSO ทั้งหมดบนการติดตั้ง ดู [สำรองและกู้คืน](/th-TH/คู่มือ/วิธีทำ/สำรองและกู้คืน/#คัดลอกข้อมูลสำรองออกนอกเครื่อง) สำหรับวิธีครอบคลุมส่วนที่เหลือ
:::note[ความลับไม่อยู่ในฐานข้อมูล]
`workspace.db` คือทั้งเวิร์กสเปซ: การสนทนา บันทึกการรัน การเชื่อมโยงรีโพ นิยามสภาพแวดล้อม และสมาชิก โทเคน webhook ของไปป์ไลน์และความลับ webhook ของการซิงก์ตั๋วงานอยู่ใน `secrets.json`: ฐานข้อมูลเก็บการอ้างอิงถึงแต่ละอัน และดัชนีเส้นทางเก็บแฮชแบบมีคีย์ของแต่ละโทเคน ดังนั้นเวิร์กสเปซที่กู้คืนบนการติดตั้งอื่นจะไม่ได้รับ webhook เลยจนกว่าทริกเกอร์ของมันจะถูกบันทึกใหม่ที่นั่น การลงชื่อเข้าใช้ของผู้ให้บริการ คีย์อุปกรณ์ และความลับของผู้ใช้อยู่ใน `global.db` และ `secrets.json`
:::

:::note[โทเค็นแชทจงใจไม่ให้ติดไปด้วย]
`chat_credentials/` ที่วางอยู่ข้างฐานข้อมูลแทนที่จะอยู่ข้างใน คือเหตุผลที่เวิร์กสเปซ
ที่ส่งมอบให้คนอื่นไม่มีโทเค็นบอทที่ใช้อยู่ติดไปด้วย ดู
[เอกสารอ้างอิงสะพานแชท](/th-TH/คู่มือ/อ้างอิง/สะพานแชท/)
:::

## ปฏิบัติการ

RPC สำหรับสำรองการติดตั้งและการส่งออก/นำเข้าเวิร์กสเปซใช้ได้เฉพาะ `fullClient`:
โทรศัพท์ที่จับคู่แล้วเรียกใช้ไม่ได้ ทั้งหมดไม่มีอยู่เลย — ไม่ใช่ถูกปฏิเสธ แต่หายไป
เชิงโครงสร้าง — บนเซิร์ฟเวอร์ที่ไม่ได้ต่อพอร์ตสำรองไว้ เช่นเซิร์ฟเวอร์สาธิต

| ปฏิบัติการ                   | ชนิด   | ขอบเขต     | บทบาทขั้นต่ำ | อาร์กิวเมนต์     | ส่งคืน                       |
| -------------------- | ------ | --------- | ------------ | ------------- | ----------------------------- |
| `server.backupNow`   | กลายพันธุ์ | การติดตั้ง   | **เจ้าของ** การติดตั้ง | ไม่มี     | `{ok, path}`                  |
| `server.listBackups` | อ่าน   | การติดตั้ง   | **เจ้าของ** การติดตั้ง | ไม่มี     | `{backups: [...]}`            |
| `server.deleteBackup` | กลายพันธุ์ | การติดตั้ง | **เจ้าของ** การติดตั้ง | `name` | `{ok}` |
| `server.listOrphanedBackups` | อ่าน | การติดตั้ง | **เจ้าของ** การติดตั้ง | ไม่มี | `{workspaces: [...]}` |
| `server.deleteOrphanedBackup` | กลายพันธุ์ | การติดตั้ง | **เจ้าของ** การติดตั้ง | `workspace_id`, `name` | `{ok}` |
| `workspace.listBackups` | อ่าน | เวิร์กสเปซ | `admin` | ไม่มี | `{backups: [...]}` |
| `workspace.deleteBackup` | กลายพันธุ์ | เวิร์กสเปซ | `owner` | `name` | `{ok}` |
| `workspace.export`   | อ่าน   | เวิร์กสเปซ | `admin`      | ไม่มี          | `{ok, path}`                  |
| `workspace.import`   | กลายพันธุ์ | เวิร์กสเปซ | `owner` และเจ้าของเซิร์ฟเวอร์ | `source_path` | `{ok, workspace_id}`          |
| `workspace.importHolds.list` | อ่าน | เวิร์กสเปซ | `owner` และเจ้าของเซิร์ฟเวอร์ | ไม่มี | `{holds: [...]}` |
| `workspace.importHolds.resolve` | กลายพันธุ์ | เวิร์กสเปซ | `owner` และเจ้าของเซิร์ฟเวอร์ | `hold_id`, `accept` | `{ok, applied}` |
| `workspace.delete`   | กลายพันธุ์ | การติดตั้ง*  | `owner`      | `id`          | แถวในทะเบียนถูกทำเครื่องหมายว่าลบแล้ว   |

* `workspace.delete` ไม่มีขอบเขตเพราะแถวที่มันทำเครื่องหมายอยู่ในทะเบียน
ส่วนกลาง ตัวจัดการของมันตรวจสอบสมาชิกภาพของผู้เรียกในเวิร์กสเปซที่ระบุชื่อ
และกำหนดให้ต้องเป็น `owner`

`path` ในทุกคำตอบเป็นพาธบน**โฮสต์เซิร์ฟเวอร์**

`server.listOrphanedBackups` ส่งคืนหนึ่งรายการต่อเวิร์กสเปซที่ไม่ได้ใช้งานอยู่แล้ว: `workspace_id`,
`workspace_name` เมื่อทะเบียนยังรู้จักชื่อนั้น และ `backups` เวิร์กสเปซที่ถูกลบไม่สามารถผ่านการตรวจสอบบทบาทของเวิร์กสเปซได้อีก
ข้อมูลสำรองของมันจึงเป็นของเจ้าของการติดตั้ง `server.deleteOrphanedBackup` ปฏิเสธเวิร์กสเปซที่ยังใช้งานอยู่
ซึ่งข้อมูลสำรองของเวิร์กสเปซนั้นยังอยู่หลัง `workspace.deleteBackup` และบทบาทของเวิร์กสเปซนั้นเอง
ปฏิบัติการลบทั้งสองรับเฉพาะชื่อไดเรกทอรีเวลาประทับที่อยู่ในรายการ ไม่รับพาธ

`workspace.importHolds.list` ส่งคืนสิ่งที่การนำเข้ากันไว้ แต่ละรายการที่กันไว้มี `id`, `kind` (`action_policy`, `sandbox_exec_grant`, `repo_grant`, `membership_role` หรือ `invite`), `payload` ที่มันจะคืนกลับไป, `imported_at` และ `source_install_id` `workspace.importHolds.resolve` ที่มี `accept: true` จะให้สิทธิ์นั้นอีกครั้ง และที่มี `false` จะทิ้งมัน `applied` เป็น false เมื่อผู้ใดหรือสิ่งใดที่สิทธิ์นั้นมีไว้ไม่ได้อยู่ในเวิร์กสเปซอีกต่อไป

:::note[สแนปช็อตของการติดตั้งทั้งหมดถูกกั้นด้วยสิทธิ์เจ้าของทั้งสองช่องทาง]
`server.backupNow`, `server.listBackups` และ `server.deleteBackup` ต้องเป็น
**เจ้าของ**การติดตั้ง (`ServerAuthority.serverOwner`) ซึ่งเป็นประตูเดียวกับ
`GET /backup/snapshot` สแนปช็อตจับฐานข้อมูลของทุกเวิร์กสเปซ ดังนั้น
การเป็นแอดมินของเวิร์กสเปซเดียวจึงไม่พอที่จะจัดการเวิร์กสเปซอื่น การลบ
รับเฉพาะชื่อไดเรกทอรีที่ประทับเวลาซึ่งอยู่ในรายการเท่านั้น ไม่ใช่พาธเซิร์ฟเวอร์
อะไรก็ได้ และลบสแนปช็อตทั้งก้อน (รวมถึงสแนปช็อตที่ยังไม่ได้ตรวจสอบ)
การส่งออกต่อเวิร์กสเปซและการดาวน์โหลดข้อมูลสำรองตามกำหนดเวลายังคงอยู่ที่แอดมินของเวิร์กสเปซ
:::

:::note[การกู้คืนเป็นของเจ้าของเซิร์ฟเวอร์]
`workspace.import` และ `POST /backup/restore` ทำให้เซิร์ฟเวอร์รับไฟล์ฐานข้อมูลมาเป็นของตัวเอง โดยปฏิบัติต่อแถวในนั้นเหมือนเป็นของเซิร์ฟเวอร์: การเชื่อมโยงรีโพและผู้ที่สร้าง นิยามสภาพแวดล้อมที่รันบนโฮสต์ พาธของเวิร์กทรีและบันทึก ดังนั้นทั้งสองคำสั่งต้องใช้เจ้าของเซิร์ฟเวอร์ (`ServerAuthority.serverOwner`) ซึ่งต้องเป็นเจ้าของเวิร์กสเปซนั้นด้วย ผู้อื่นทุกคน และทุกผู้เรียกบนโฮสต์ที่ไม่มีเจ้าของที่บันทึกไว้ จะถูกปฏิเสธด้วย `server_owner_required` ไม่มีทริกเกอร์ มุมมอง คอลัมน์ หรือข้อจำกัดใดที่ไฟล์นำมาด้วยจะถูกรับเข้ามา
:::

### คำตอบของ `server.listBackups`

ใหม่สุดก่อน เรียงตามชื่อไดเรกทอรี (ซึ่งก็คือเวลาประทับ ลำดับจึงยังถูกต้องแม้
กับสแนปช็อตที่อ่านแมนิเฟสต์ไม่ได้)

```json
{
  "backups": [
    {
      "path": "/…/backups/2026-07-28T09-12-33-000Z",
      "name": "2026-07-28T09-12-33-000Z",
      "created_at": "2026-07-28T09:12:33.000Z",
      "bytes": 481203712,
      "complete": true,
      "workspaces": [
        {
          "workspace_id": "w_9f2c…",
          "path": "/…/backups/2026-07-28T09-12-33-000Z/w_9f2c…/workspace.db",
          "bytes": 190840832
        }
      ],
      "skipped_workspace_ids": []
    }
  ]
}
```

`created_at` จะถูกละไว้เมื่ออ่านแมนิเฟสต์ไม่ได้ ส่วน `bytes` ระดับบนสุดคือ
ขนาดจริงบนดิสก์ของทั้งไดเรกทอรี ไม่ใช่ผลรวมในแมนิเฟสต์เอง — คำถามที่ผู้ดำเนินการ
ซึ่งคัดสแนปช็อตทิ้งถามคือไดเรกทอรีนี้กินพื้นที่เท่าไร ไม่ใช่ว่าข้อมูลสำรอง
ตั้งใจจะเขียนอะไร

`workspaces[].path` แต่ละรายการคือสิ่งที่ `workspace.import` รับเป็น `source_path`
พอดี เป็นเจตนา: "กู้คืนเวิร์กสเปซนี้จากสแนปช็อตนี้" *ก็คือ* ปฏิบัติการนำเข้า
ทั้งสองจึงแยกไปปฏิบัติต่อไฟล์เดียวกันต่างกันไม่ได้

### การตรวจสอบความถูกต้องของ `workspace.import`

ก่อนที่สิ่งใดจะถูกแทนที่ ไฟล์ตัวเลือกจะถูกคัดลอกไปยังไฟล์พักที่อยู่ข้างเป้าหมายและถูกตรวจสอบที่นั่น การปฏิเสธจะไม่แตะต้องสิ่งใดและจะระบุประเภทของมันเป็น `data.kind`

| เงื่อนไข                                        | ผลลัพธ์                                                          |
| ------------------------------------------------ | ---------------------------------------------------------------- |
| ไฟล์ไม่มีอยู่ | ปฏิเสธ `import.missing_source` |
| ไม่ใช่ฐานข้อมูล SQLite ที่อ่านได้ หรือไม่ผ่าน `quick_check` | ปฏิเสธ `import.damaged` |
| มาจากสแนปช็อตและ SHA-256 ของมันต่างจากของแมนิเฟสต์ | ปฏิเสธ `import.checksum_mismatch` |
| เวอร์ชันใหม่กว่าของเซิร์ฟเวอร์เป็นผู้เขียนมัน | ปฏิเสธ `import.newer_schema` |
| `application_id` ที่ต่างออกไป หรือไม่มี `workspace_meta` | ปฏิเสธ `import.foreign_file` |
| ไม่สามารถนำมาเข้าสู่สคีมาของเซิร์ฟเวอร์นี้ได้ | ปฏิเสธ `import.schema_mismatch` |
| webhook หรือคำเชิญของมันถูกส่งไปยังเวิร์กสเปซอื่นอยู่แล้ว | ปฏิเสธ `import.route_conflict` |
| ไอดีเวิร์กสเปซที่บันทึกไว้ ≠ เป้าหมาย                | **อนุญาต** แถวของมันจะถูกผูกคีย์ใหม่เข้ากับเป้าหมาย นี่คือวิธีทำสำเนาเวิร์กสเปซหรือกู้คืนภายใต้ไอดีใหม่ |
| ไอดีการติดตั้งที่บันทึกไว้ ≠ การติดตั้งนี้                | **อนุญาต** ไอดีผู้ใช้ของมันเป็นของการติดตั้งนั้นและจะรีโซลฟ์ที่นี่ไม่ได้ |

เมื่อยอมรับแล้ว ไฟล์พักจะถูกนำมาให้ตรงกับสคีมาของเซิร์ฟเวอร์นี้ และต้องตรงกันทุกประการหลังจากนั้น สิทธิ์ที่ไฟล์ไม่ควรมอบให้ตัวเองจะถูกนำออกจากมัน: การอนุมัติให้รันนิยามสภาพแวดล้อมบนโฮสต์จะถูกล้างออก และกฎการดำเนินการที่อนุญาตหรือให้ถาม สิทธิ์การรันแซนด์บ็อกซ์ สิทธิ์เข้าถึงรีโพสิทอรีที่สูงกว่าการอ่าน บทบาทที่สูงกว่าสมาชิก และคำเชิญสำหรับบทบาทเหล่านั้น จะกลายเป็นรายการที่กันไว้ให้เจ้าของเซิร์ฟเวอร์ตรวจทาน ตัวนำเข้าจะคงหรือได้รับบทบาทเจ้าของ ฐานข้อมูลที่ถูกแทนที่จะถูกเก็บเป็นข้อมูลสำรองตามกำหนดเวลาชื่อ `<timestamp>-pre-restore` ไฟล์พักจะถูกเปลี่ยนชื่อให้เข้าที่โดยปิดการเชื่อมต่อของเวิร์กสเปซ `code_index.db` จะถูกลบเพื่อให้สร้างใหม่ และดัชนี FTS จะถูกสร้างใหม่

## เส้นทางถ่ายโอน

ปฏิบัติการส่งออก/นำเข้าและแสดงรายการสแนปช็อตข้างต้นพูดถึงพาธฝั่งเซิร์ฟเวอร์
ซึ่งเป็นคำตอบที่ครบถ้วนเฉพาะเมื่อเซิร์ฟเวอร์คือเครื่องของคุณเอง เส้นทางที่มีรูป
เป็น HTTP เหล่านี้ขนย้ายไบต์ของข้อมูลสำรอง **ภายในอุโมงค์ทรัพยากรที่ผ่านการ
ยืนยันตัวตนและเข้ารหัสแบบต้นทางถึงปลายทางเดียวกัน** กับทรัพยากรละเอียดอ่อนอื่น ๆ
ไม่ว่าการเชื่อมต่อ RPC จะตรงหรือผ่านตัวกลาง มันไม่ใช่ปลายทางโอนไฟล์ HTTP สาธารณะ:
คำขอไปยังเส้นทางใดเส้นทางหนึ่งบนตัวรับฟังสาธารณะจะคืน `426 Upgrade Required`
แม้จากลูปแบ็ก ภายในอุโมงค์ที่เข้ารหัส อุปกรณ์ที่ผ่านการรับรองด้วย Noise ต้องตรงกับ
`d` และตัวจัดการยังตรวจสอบลายเซ็นของอุปกรณ์บนสตริงเป้าหมายของมันโดยใช้ PSK
การจับคู่และบทบาทด้านล่างด้วย

| เส้นทาง                   | เมธอด | คำค้น           | เป้าหมายที่ลงนาม                  | ต้องมี                |
| ----------------------- | ------ | --------------- | ------------------------------ | ----------------------- |
| `/backup/workspace`     | GET    | `w`, `d`, `s`   | `backup-workspace:<workspaceId>` | **แอดมิน** เวิร์กสเปซ   |
| `/backup/snapshot`      | GET    | `n`, `d`, `s`   | `backup-snapshot:<name>`         | **เจ้าของ** การติดตั้ง     |
| `/backup/stored`        | GET    | `w`, `n`, `d`, `s` | `backup-stored:<workspaceId>:<name>` | **แอดมิน** เวิร์กสเปซ; **เจ้าของ** การติดตั้งเมื่อเวิร์กสเปซถูกลบแล้ว |
| `/backup/restore`       | POST   | `w`, `d`, `s`   | `backup-restore:<workspaceId>`   | **เจ้าของ**การติดตั้งที่เป็น**เจ้าของ**เวิร์กสเปซด้วย (`403` พร้อม `server_owner_required` ในกรณีอื่น) |

`w` คือไอดีเวิร์กสเปซ `n` คือชื่อไดเรกทอรีสแนปช็อตหรือข้อมูลสำรองตามกำหนดเวลา `d` คือไอดีอุปกรณ์ที่เรียก
`s` คือลายเซ็น บน `/backup/snapshot` `n` ถูกเทียบกับรายการข้อมูลสำรอง ไม่ใช่ต่อเข้ากับรากของ backups
เส้นทางจึงไม่อาจเล็งไปที่ไดเรกทอรีที่รายการไม่เคยแสดง บน `/backup/stored` ต้องเป็นชื่อเวลาประทับ
และไฟล์ต้องเป็นไฟล์จริงภายในไดเรกทอรีข้อมูลสำรองของเวิร์กสเปซนั้นเอง

| สถานะ | สาเหตุ                                                                              |
| ------ | ----------------------------------------------------------------------------------- |
| `400`  | พารามิเตอร์คำค้นที่จำเป็นหายไป ชื่อข้อมูลสำรองไม่ถูกต้อง บอดี้อัปโหลดว่างเปล่า หรือไฟล์ที่อัปโหลดถูกปฏิเสธ (บอดี้เป็น `{error, kind}` ที่มีประเภท `import.*`) |
| `403`  | อุปกรณ์ไม่รู้จักหรือถูกเพิกถอน ลายเซ็นไม่ถูกต้อง หรือผู้เรียกไม่มีบทบาทนั้น              |
| `404`  | ไม่มีพอร์ตสำรองบนโฮสต์นี้ หรือสแนปช็อต ข้อมูลสำรอง หรือไฟล์เวิร์กสเปซที่ระบุชื่อไม่มีอยู่ |
| `405`  | เรียก `/backup/restore` ด้วยเมธอดอื่นที่ไม่ใช่ `POST`                                   |
| `413`  | บอดี้อัปโหลดเกิน 8 GiB ไม่ว่าจะตาม content-length ที่ประกาศไว้หรือตามไบต์ที่อ่านจริง     |
| `426`  | คำขอโดยตรงใด ๆ ไปยังเส้นทางถ่ายโอนบนตัวรับฟัง HTTP สาธารณะ; ใช้อุโมงค์ทรัพยากรที่เข้ารหัสของไคลเอนต์ที่จับคู่แล้ว |
| `500`  | การส่งออกหรือสร้างอาร์ไคฟ์ล้มเหลวฝั่งเซิร์ฟเวอร์                                            |

การดาวน์โหลดทั้งสามตอบกลับด้วย `Cache-Control: no-store` พร้อม `Accept-Ranges: none`
`/backup/workspace` และ `/backup/snapshot` สร้างสำเนา**ใหม่**ต่อคำขอและลบทิ้งเมื่อสตรีมจบ คำตอบที่ถูกแคชหรือสตรีมต่อ
จึงจะเชื่อมไบต์จากการส่งออกสองครั้งที่ต่างกันเข้าเป็นไฟล์เดียวที่ดูเหมือนถูกต้องแต่ไม่ใช่

`/backup/stored` เป็นข้อยกเว้น: มันสตรีมข้อมูลสำรองตามกำหนดเวลาเป็น `<workspaceId>-<name>.db`
และคงไฟล์ไว้ที่เดิม เพราะไฟล์นั้นคือข้อมูลสำรอง

`/backup/snapshot` ส่งคืน `<name>.zip` โดยรายการภายในอ้างจากรากของสแนปช็อต
การแตกไฟล์จึงสร้าง `manifest.json` + `global.db` + `<workspaceId>/workspace.db`
กลับขึ้นมาซ้ำ รายการถูกเขียนตามลำดับที่เรียงแล้ว อาร์ไคฟ์สองชุดของสแนปช็อตเดียวกัน
จึงเป็นอาร์ไคฟ์เดียวกัน

`/backup/restore` สตรีมบอดี้ออกไปยังไฟล์พักโดยตรงแทนการบัฟเฟอร์ จำกัดขนาดมัน
ก่อนและระหว่างการอ่าน และลบไฟล์ที่พักไว้ใน**ทุก**เส้นทางที่ออกไป
รวมถึงกรณีถูกปฏิเสธ

::::caution[การเชื่อมต่อตรงและรีเลย์ใช้การโอนที่เข้ารหัสเดียวกัน]
รีเลย์ขนส่งคำขอทรัพยากร การตอบกลับแบบสตรีม และไบต์อัปโหลดเป็นข้อความเข้ารหัส
มันอ่านเนื้อหาข้อมูลสำรองไม่ได้ พาธฝั่งเซิร์ฟเวอร์ยังคงเป็นพาธบนโฮสต์ของเซิร์ฟเวอร์
ไม่ใช่ไฟล์บนรีเลย์ การเข้าถึงยังต้องใช้อุปกรณ์ที่จับคู่แล้ว ลายเซ็นเป้าหมาย และ
บทบาทของเวิร์กสเปซหรือการติดตั้งที่ใช้บังคับ ไม่มีตัวรับส่งใดเข้ารหัสไฟล์ข้อมูล
สำรองที่ได้มาขณะจัดเก็บ
::::

## พาธและขีดจำกัด

| สิ่ง                          | ค่า                                                        |
| ------------------------------ | ------------------------------------------------------------ |
| สแนปช็อต                      | `<dataDir>/backups/<timestamp>/`                             |
| ข้อมูลสำรองของเวิร์กสเปซตามกำหนดเวลา    | `<dataDir>/backups/workspace-backups/<workspaceId>/<timestamp>/workspace.db` |
| การส่งออกเวิร์กสเปซ              | `<dataDir>/backups/exports/<workspaceId>-<timestamp>.db`     |
| ฐานข้อมูลที่ถูกแทนที่โดยการกู้คืน | `<dataDir>/backups/workspace-backups/<workspaceId>/<timestamp>-pre-restore/` |
| ฐานข้อมูลในสภาพก่อนที่การอัปเดตจะเปลี่ยนรูปแบบของมัน | `<dataDir>/pre_upgrade/` และ `<dataDir>/<workspaceId>/pre_upgrade/` สองชุดล่าสุดของแต่ละอัน |
| การพักการถ่ายโอน               | `<dataDir>/backups/transfer/` — โต๊ะทำงานที่ถูกกวาดเก็บโดยเส้นทางที่เขียนมัน |
| ชื่ออาร์ไคฟ์สแนปช็อต          | `<snapshot directory name>.zip`                              |
| เพดานการอัปโหลด                 | 8 GiB ต่อการอัปโหลดที่เข้ารหัสไปยัง `/backup/restore`        |
| การเก็บรักษา                      | สแนปช็อตการติดตั้ง: ลบด้วยมือ ข้อมูลสำรองของเวิร์กสเปซ: ไปป์ไลน์รายสัปดาห์ ค่าเริ่มต้น 30 วัน หรือลบด้วยมือ ข้อมูลสำรองของเวิร์กสเปซที่ถูกลบ: ลบด้วยมือเท่านั้น |

ไดเรกทอรี `exports/`, `transfer/` และ `workspace-backups/` ไม่ใช่
สแนปช็อตการติดตั้งและถูกตัดออกจาก `server.listBackups` มีเพียงไดเรกทอรี
สุดท้ายเท่านั้นที่มีการเก็บรักษาตามกำหนด และเฉพาะในขณะที่เวิร์กสเปซของมันยังอยู่ การลบสแนปช็อตการติดตั้งต้องมี
การดำเนินการอย่างชัดแจ้งของเจ้าของการติดตั้ง
