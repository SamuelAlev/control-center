คำสั่งที่พิมพ์ในคอมโพเซอร์ของสเปซหนึ่ง ๆ มันแบ่งเป็นสามกลุ่มตามว่าออกฤทธิ์ที่ไหน และความต่างนี้สำคัญ: คำสั่ง **ในเครื่อง** ไม่เคยเดินทางเป็นข้อความ จึงไม่ปรากฏในทรานสคริปต์และไปไม่ถึงเอเจนต์

| รันที่ไหน   | ความหมาย                                                                          |
| ------------- | ---------------------------------------------------------------------------------- |
| **ในเครื่อง**   | จัดการในไคลเอนต์ (หรือปฏิบัติการฝั่งเซิร์ฟเวอร์ที่ไคลเอนต์เป็นผู้เริ่ม) คำสั่งไม่เคยเดินทางเป็นข้อความ เอเจนต์จึงไม่เห็น |
| **ด้านข้าง**    | การเรียกโมเดลฝั่งเซิร์ฟเวอร์หนึ่งครั้งเกี่ยวกับบทสนทนา บทสนทนาไม่ถูกเปลี่ยนแปลง |
| **สั่งงาน**     | กำหนดโหมดหรือคำกำกับสำหรับการรันที่ข้อความนั้นเริ่ม                          |

---

## กำกับการรัน

### `/plan`

**ในเครื่อง → สั่งงาน** ติดอาวุธโหมดแผนให้บทสนทนา: worktree ที่อ่านอย่างเดียวเต็มรูปแบบ และพื้นผิวเครื่องมือที่จำกัดไว้เพียง `read` สิ่งที่เอเจนต์ต้องส่งมอบคือแผน ไม่ใช่การแก้ไข `/plan` เปล่า ๆ แค่สลับโหมดและไม่เคยเดินทางเป็นข้อความ เมื่อมีพร้อมต์ ส่วนที่เหลือของบรรทัดคือสิ่งที่เริ่มการรัน

### `/goal <objective>`

**สั่งงาน** เริ่มวัตถุประสงค์แบบอิสระที่ผู้ดูแลเป้าหมายสั่งงานใหม่ข้ามเซกเมนต์และการรีสตาร์ต

การพิมพ์ `/goal` พร้อมข้อความก่อนจะเปิด **การสัมภาษณ์วัตถุประสงค์** — ช่วงสั้น ๆ ที่ไม่ยอมรับฉบับร่างจนกว่าจะครบทั้งห้าอย่าง: เกณฑ์ความสำเร็จที่ผู้ประเมินตัดสินได้โดยไม่ต้องใช้ดุลพินิจ คำสั่งตรวจสอบที่แน่นอน เพดานจำนวนครั้งที่ลอง ขอบเขตงาน และเงื่อนไขการหยุด ทุกขั้นมี *ข้ามและรันตามที่เขียน* ให้เลือก: การสัมภาษณ์เป็นค่าเริ่มต้น ไม่ใช่ประตูคัดกรอง

`/goal pause`, `/goal resume` และ `/goal drop` ไม่ใช่คำสั่งสแลช การหยุดชั่วคราว การทำต่อ และการหยุด อยู่ในรายการเป้าหมายของบทสนทนาในแถบข้าง แฟล็กตอนเริ่มบนวัตถุประสงค์เองคือ `--budget <dollars>`, `--max <N>` (งบการรัน) และ `--days <N>` (กำหนดเส้นตาย) เป้าหมายที่ชนเพดานค่าใช้จ่ายจะกลับมาทำงานต่อได้เพียงโดยยกเพดานนั้นขึ้น จากตัวควบคุมเดียวกันในแถบข้าง

:::note[ทำไมมันจึงขัดจังหวะเลย]
เป้าหมายแบบอิสระเป็นที่เดียวที่บรีฟคลุมเครือแพงจริง ๆ การรันทำงานเป็นชั่วโมงกับวัตถุประสงค์ที่ไม่มีใครนิยามคำว่า “เสร็จ” ไว้ แล้วรายงานความสำเร็จตามเกณฑ์ของตัวเอง ห้าคำถามถูกกว่าการรันข้ามคืนหนึ่งครั้งที่จบลงเมื่อไหร่ก็ตามที่มันรู้สึกว่าจบแล้ว
:::

### `/loop [budget] [task]`

**สั่งงาน** ทำงานวนซ้ำจนเสร็จ รับขอบเขตได้: `/loop 10`, `/loop 30m`, `/loop 1h30m`, `/loop 10 minutes fix the tests`

โทเค็นที่*ดูเหมือน*เป็นขีดจำกัด (ขึ้นต้นด้วยตัวเลขหรือเครื่องหมาย) แล้วแยกวิเคราะห์ไม่สำเร็จจะกลายเป็นข้อผิดพลาดร้ายแรง ข้อความธรรมดาก็เป็นแค่ข้อความ `/loop keep going until the tests pass` จึงเป็นการวนซ้ำแบบไม่มีขอบเขตพร้อมพร้อมต์ในบรรทัดเดียวกัน ไม่ใช่การแยกวิเคราะห์ผิด

### `/vibe [task]`

**สั่งงาน** เปลี่ยนเซสชันให้เป็น **ผู้กำกับ**: เครื่องมือของตัวมันเองลดลงเหลือ `read` บวกกับคำสั่งของวอร์กเกอร์อีกห้าคำ และวอร์กเกอร์พื้นหลังเป็นฝ่ายแก้ไข ดู [กำกับวอร์กเกอร์พื้นหลัง](/th-TH/คู่มือ/วิธีทำ/กำกับวอร์กเกอร์พื้นหลัง/)

วอร์กเกอร์ไม่เคยอยู่รอดเกินโหมด — การออกจากโหมดฆ่ามันทุกตัว

## การจัดการบริบท

### `/compact`

**ในเครื่อง → เซิร์ฟเวอร์** พับประวัติเก่าให้เป็นบทสรุปที่มีจุดยึด แล้วทำต่อบนบริบทที่ถูกบีบอัด ไม่มีอาร์กิวเมนต์ที่ส่งถึงโมเดล: คำสั่งไม่เคยเดินทางเป็นข้อความ และรอบการบีบอัดไม่รับคำใบ้เรื่องโฟกัส

### `/shake [target]`

**ในเครื่อง → เซิร์ฟเวอร์** ทิ้งเนื้อหาหนัก ๆ **โดยไม่** สรุป: ไม่มีการเรียกโมเดล ทุกคำยังอยู่ มีเพียงส่วนที่หนาเกินกว่าจะมีใครกลับมาอ่านซ้ำเท่านั้นที่ถูกปิดให้ว่าง

| เป้าหมาย      | สิ่งที่ทิ้ง                        |
| ------------- | --------------------------------- |
| `tool_output` | ผลลัพธ์เครื่องมือเก่าที่ไม่มีเหตุการณ์อะไรเกิดขึ้น (ค่าเริ่มต้น) |
| `images`      | สกรีนช็อตเก่า โดยเก็บข้อความของมันไว้ |
| `all`         | ทั้งสองอย่าง                       |

นี่คือทางออกสำหรับ “บริบทของฉันอ้วนไปแล้ว แต่ฉันไม่อยากได้บทสรุป”

### `/context [agent]`

**ในเครื่อง** เปิดตัวสำรวจบริบทของเอเจนต์ในบทสนทนานี้ในแท็บของตัวเอง: ทุกเซกเมนต์และทุกส่วนของหน้าต่างบริบทของมัน — พรอมต์ระบบ สกิล ไฟล์บริบท สคีมาเครื่องมือ ประวัติ และรูปภาพ — พร้อมว่าส่วนไหนกินไปเท่าไรและเนื้อหาต้นฉบับที่อยู่เบื้องหลัง

แท็บนี้ผูกกับคู่ (สเปซ, เอเจนต์) ดังนั้นการรันมันสองครั้งจะโฟกัสแท็บเดิมแทนที่จะซ้อนสำเนาของรายละเอียดเดียวกัน

ในสเปซที่มี **เอเจนต์มากกว่าหนึ่งตัว** `/context` เปล่า ๆ จะเปิดหน้าต่างที่มิเตอร์บริบทบนส่วนหัวกำลังอ่านอยู่ — เอเจนต์ตัวที่ทำงานล่าสุดที่นี่ ซึ่งก็คือตัวที่ข้อความของมันอยู่ล่างสุดของสายการสนทนา — และแท็บจะมีป้ายว่า `Context · <name>` เพื่อบอกว่ามันเป็นของใคร ระบุชื่อตัวอื่นเพื่อสลับ: `/context qa` (เครื่องหมาย `@` ไม่จำเป็น) ชื่อที่พิมพ์จะจับคู่แบบตรงตัวเสมอ ไม่ใช่แบบคลุมเครือ: เอเจนต์สองตัวถือหน้าต่างคนละบาน การเปิดผิดตัวเพราะชื่อใกล้เคียงจึงกลายเป็นคำตอบที่ดูสมเหตุสมผลให้กับคำถามที่คุณไม่ได้ถาม

ตัวสำรวจเดียวกันนี้อยู่เบื้องหลังชิปมิเตอร์บริบทในส่วนหัวของสเปซ ซึ่งตามเอเจนต์ตัวเดียวกันนั้น คำสั่งกับชิปจึงขัดแย้งกันไม่ได้ว่าที่นี่ “บริบท” หมายถึงอะไร

## การถามเกี่ยวกับบทสนทนา

คำสั่งเหล่านี้ใช้การเรียกโมเดลหนึ่งครั้งและ**ไม่เปลี่ยนบทสนทนาเลย** เทิร์นจริงครั้งถัดไปของเอเจนต์จะเห็นสิ่งที่มันจะเห็นอยู่ดี ซึ่งนั่นคือคุณค่าทั้งหมดของการถาม

### `/handoff [focus]`

**ด้านข้าง** เขียนเอกสารส่งต่อสำหรับคนที่มารับงานช่วงต่อโดยไม่รู้อะไรมาก่อน: งานคืออะไร เรียนรู้อะไรไปแล้ว และเหลืออะไร

### `/btw <question>`

**ด้านข้าง** ตอบคำถามเกี่ยวกับงานที่ทำไปแล้ว โดยไม่เพิ่มทั้งคำถามและคำตอบลงในทรานสคริปต์

:::note[สองคำสั่ง หนึ่งการทำงาน]
ทั้งคู่มีรูปแบบเดียวกัน — หยิบบทสนทนาตามที่เป็นอยู่ ถามคำถามหนึ่งข้อเกี่ยวกับมัน และไม่บันทึกฝั่งใดฝั่งหนึ่งไว้ ใช้งานร่วมกันครั้งเดียวเพื่อไม่ให้มันแยกออกเป็นสองนิยามของ “บริบทที่ผ่านมา” ที่ต่างกัน
:::

## การนำทางและการส่งออก

### `/tree`

**ในเครื่อง** เปิดตัวนำทางสาขา: บทสนทนาแยกสาขาที่ไหน ตอนนี้อยู่บนเส้นทางใด และจะกลับไปยังสาขาที่คุณทิ้งไว้ได้อย่างไร ดู [แยกสาขาการสนทนา](/th-TH/คู่มือ/วิธีทำ/แยกสาขาการสนทนา/)

### `/export`

**ในเครื่อง** เขียนบทสนทนาลงไฟล์ HTML ที่สมบูรณ์ในตัวเอง — การ์ดเครื่องมือที่พับเก็บได้ ไม่มีสไตล์ชีต ไม่มีสคริปต์ และไม่ต้องพึ่งโฮสต์รูปภาพ ไฟล์จะไปอยู่ใน `Documents/ControlCenter/exports/` บนเดสก์ท็อป และดาวน์โหลดบนเว็บ

### `/dump`

**ในเครื่อง** คัดลอกทรานสคริปต์ไปยังคลิปบอร์ดเป็นมาร์กดาวน์ โดยการเรียกเครื่องมืออยู่ในบล็อกที่พับเก็บได้ ส่วนการคิดวิเคราะห์ถูกตัดออกโดยเจตนา: ทรานสคริปต์ที่วางลงในรายงานบั๊กมีคนอ่าน

## ทุกอย่างอื่น

### `/todo [subcommand]`

**ในเครื่อง** ดูและแก้ไขรายการสิ่งที่ต้องทำที่บันทึกไว้ของบทสนทนา `/todo` เปล่า ๆ เปิดตัวแก้ไข คำสั่งย่อย: `append`, `start`, `done`, `drop` (นามแฝง `rm`), `edit`, `copy`, `export`, `import`

### `/skill:<name> [args]`

**สั่งงาน** ใช้สกิลที่ติดตั้งไว้ สกิลอยู่ภายใต้คำนำหน้า `skill:` ของตัวเอง จึงไม่ใช้เนมสเปซร่วมกับคำสั่งในตัว — ถ้าไม่มีแบบนั้น สกิลชื่อ `plan` จะเข้าถึงไม่ได้เลยตลอดไป

### `/<your-command> [args]`

**สั่งงาน** ไฟล์มาร์กดาวน์ใด ๆ ภายใต้ `.agents/commands`, `.agent/commands`, `.claude/commands`, `.codex/commands` หรือ `.opencode/commands` ในรีโป ไฟล์ซ้อนอย่าง `foo/bar.md` ก็เรียกถึงได้ด้วยชื่อ `foo:bar` เช่นกัน

การทำเทมเพลต: `$1`, `$@`, `$@[start:length]` และ `$ARGUMENTS` frontmatter อาจกำหนด `description` (การเติมข้อความอัตโนมัติของคอมโพเซอร์) ได้ `allowed-tools` และ `model` ถูกอ่านจากไฟล์ แต่การเรียกคำสั่งของผู้ใช้ตอนนี้เพียงแทนที่อาร์กิวเมนต์ลงในเนื้อหาเท่านั้น — มันไม่เปลี่ยนโมเดลหรือพื้นผิวเครื่องมือของการรัน

คำสั่งที่ผู้ใช้เขียนเองชนะสกิลที่ชื่อเดียวกัน — มันคือทางลัดที่มนุษย์ตั้งใจเรียกใช้พร้อมอาร์กิวเมนต์

## คีย์เวิร์ดวิเศษ

ไม่ใช่คำสั่ง คำพิมพ์เล็กที่ยืนโดด ๆ ที่ไหนก็ได้ในพร้อมต์จะแนบคำสั่งที่ซ่อนอยู่สำหรับเทิร์นนั้น

| คำ            | ผล                                                                 |
| ------------- | ------------------------------------------------------------------ |
| `ultrathink`  | ความพยายามในการคิดสูงสุดสำหรับเทิร์นนั้น                          |
| `orchestrate` | มอบงานอิสระให้ทำขนานกันและตรวจสอบแต่ละช่วง                          |

ตัวจับคู่เข้มงวดกับขอบเขตคำโดยเจตนา `orchestrate,` จับคู่ได้ แต่ `orchestrated`, `orchestrate.ts`, `foo::orchestrate` และ `orchestrate()` ไม่จับคู่ และบล็อกโค้ดที่มีรั้ว ช่วงข้อความในบรรทัด และส่วน XML จะถูกปิดบังไว้ก่อน ถ้าไม่ทำเช่นนั้น การวางสแต็กเทรซก็จะเปลี่ยนพฤติกรรมของเอเจนต์
