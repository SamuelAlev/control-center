เหล่านี้คือเครื่องมือ**ที่ผูกกับเซิร์ฟเวอร์** ซึ่งรันไทม์เอเจนต์ในตัวลงทะเบียนไว้โดยตรง — เซิร์ฟเวอร์ภาษา การค้นหาเชิงโครงสร้าง ดีบักเกอร์ เคอร์เนล สคริปต์โหมดโค้ด คำถาม และการควบคุมวอร์กเกอร์ — ต่างจาก[เครื่องมือ MCP](/th-TH/คู่มือ/อ้างอิง/เครื่องมือ-mcp/)ที่มันเชื่อมเข้ามา และต่างจากเครื่องมือไฟล์ การค้นหา และเชลล์ทั่วไปจากรันไทม์ของฮาร์เนส พวกมันไม่ได้อยู่บนทะเบียน MCP: ไคลเอนต์ MCP ภายนอกจะมองไม่เห็น เพราะแต่ละตัวผูกกับทรัพยากรฝั่งเซิร์ฟเวอร์ที่มีชีวิต — โปรเซสเซิร์ฟเวอร์ภาษา อะแดปเตอร์ดีบัก อินเทอร์พรีเตอร์ — ซึ่งเป็นของรันหนึ่งครั้ง

เครื่องมือทุกตัวที่นี่จะถูกลงทะเบียนก็ต่อเมื่อทรัพยากรที่รองรับมันถูกต่อไว้สำหรับรันนั้น — ผู้ดูแลเซิร์ฟเวอร์ภาษาหรือดีบัก พาร์เซอร์ tree-sitter โรงงานเคอร์เนล พอร์ตคำถาม รายชื่อวอร์กเกอร์ vibe การตรวจหาว่ามีเซิร์ฟเวอร์ภาษาหรืออะแดปเตอร์ดีบักสำหรับ*เช็กเอาต์นี้*หรือไม่เป็นการตรวจแยกต่างหากที่เกิดทีหลัง (`status` / `adapters`): เครื่องมือเหล่านี้ยังคงอยู่บนพื้นผิวเพื่อให้เอเจนต์ถามได้ว่าทำไมถึงใช้งานอะไรไม่ได้ แทนที่จะเดา

## ระดับการอนุมัติ

เครื่องมือแต่ละตัวประกาศระดับหนึ่ง และระดับนั้นเป็นตัวตัดสินว่า**พื้นผิวใดเห็นมัน** — ไม่ใช่แค่ว่ามันจะขึ้นพรอมป์ต์หรือไม่ โหมดแผนและเอเจนต์ย่อยแบบอ่านอย่างเดียวถูกกำกัดไว้ที่ `read` เครื่องมือระดับ `write` หรือ `exec` จึงหายไปจากสคีมาของพวกมันทั้งหมด

| ระดับ   | ความหมาย                     | เครื่องมือที่นี่                                     |
| ------- | ---------------------------- | -------------------------------------------------- |
| `read`  | ไม่มีผลข้างเคียง               | `lsp`, `ast_grep`, `ask_user`, `repl` และ `vibe_*` ทั้งห้าตัว |
| `write` | เปลี่ยนแปลงไฟล์                | `lsp_rename`, `ast_edit`, `resolve`                |
| `exec`  | เริ่มหรือควบคุมโปรเซส           | `debug`, `eval`                                    |

## โดยตรง เฉพาะจากสคริปต์ หรือโหลดเมื่อใช้ครั้งแรก

เมื่อเซิร์ฟเวอร์รันสคริปต์ได้ การรันเรียกเครื่องมือบางตัวโดยตรง และเข้าถึงส่วนที่เหลือจากสคริปต์ [`repl`](#repl--รันสคริปต์ที่เรียกเครื่องมือของคุณ); ดู[โหมดโค้ด](/th-TH/คู่มือ/แนวคิด/โหมดโค้ด/#เครื่องมือใดที่เอเจนต์เรียกโดยตรง) สำหรับกฎทั้งหมด สำหรับเครื่องมือในหน้านี้:

| เครื่องมือ | เมื่อมี `repl` | เมื่อไม่มี `repl` |
| ---- | ----------- | -------------- |
| `repl` | โดยตรง | ไม่มีอยู่ |
| `ask_user` | โดยตรง | โดยตรง |
| `lsp`, `lsp_rename`, `ast_grep`, `ast_edit`, `resolve`, `debug` | เฉพาะจากสคริปต์ | โหลดเมื่อใช้ครั้งแรก |
| `eval` | โหลดเมื่อใช้ครั้งแรก (สคริปต์เรียกไม่ได้) | โหลดเมื่อใช้ครั้งแรก |
| `vibe_*` | โดยตรงในโหมด vibe ไม่เคยเรียกจากสคริปต์ | โดยตรงในโหมด vibe |

เครื่องมือที่ระบุว่า “เฉพาะจากสคริปต์” จะโหลดเมื่อใช้ครั้งแรกแทน เมื่อเซิร์ฟเวอร์รันสคริปต์ของการรันนั้นไม่ได้ ([เมื่อสคริปต์รันไม่ได้](/th-TH/คู่มือ/แนวคิด/โหมดโค้ด/#เมื่อสคริปต์รันไม่ได้))

## `lsp` — คำค้นเซิร์ฟเวอร์ภาษา

ลงทะเบียนเมื่อการรันมีผู้ดูแลเซิร์ฟเวอร์ภาษาและไดเรกทอรีทำงาน ว่าเซิร์ฟเวอร์จะตอบได้จริงหรือไม่นั้นถูกตรวจตอนเรียกใช้ เป็น**ส่วนตัดกัน**: ต้องมีมาร์กเกอร์ที่ราก *และ*ต้องค้นหาไบนารีของเซิร์ฟเวอร์เจอ อย่างใดอย่างหนึ่งเพียงอย่างเดียวแปลว่าไม่มีเซิร์ฟเวอร์เริ่มทำงาน — `status` บอกไว้เช่นนั้น — แทนที่จะเดาเงียบ ๆ

เซิร์ฟเวอร์มาจากตารางในตัวเท่านั้น ไม่อ่านไฟล์ `lsp.json` ของรีโพสิทอรี ในการรันที่อยู่ในแซนด์บ็อกซ์ แต่ละการรันจะมีเซสชันเซิร์ฟเวอร์ภาษาของตัวเอง ดังนั้นเซิร์ฟเวอร์จะเริ่มใหม่ในทุกการรัน ไบนารีในโปรเจกต์ (`node_modules/.bin`) จะถูกใช้เฉพาะเมื่อการรันอยู่ในแซนด์บ็อกซ์ และรากโปรเจกต์จะไม่ถูกแก้ไขขึ้นไปเหนือไดเรกทอรีทำงานของการรัน

ตำแหน่งถูกระบุด้วย `line` บวกกับสตริงย่อยใน `symbol` ไม่ใช่ด้วยคอลัมน์ โมเดลที่ถูกขอให้หาคอลัมน์จะเดา และการเดาผิดจะไปลงที่สัญลักษณ์อีกตัวบนบรรทัดเดียวกัน — คำตอบที่ดูเหมือนถูกแต่พูดถึงคนละเรื่อง การละ `symbol` ในการกระทำเชิงนำทางถือเป็นข้อผิดพลาด ไม่ใช่การเดาว่าเป็นคอลัมน์แรก

| การกระทำ          | อาร์กิวเมนต์                       | สิ่งที่คืนกลับ                                  |
| ----------------- | -------------------------------- | ------------------------------------------ |
| `diagnostics`     | `file` (หรือ `"*"`)              | ข้อผิดพลาดและคำเตือน; `"*"` รันตัวตรวจสอบของโปรเจกต์แทน |
| `definition`      | `file`, `line`, `symbol`         | ตำแหน่งที่สัญลักษณ์ถูกประกาศ                  |
| `type_definition` | `file`, `line`, `symbol`         | ตำแหน่งที่ไทป์ของมันถูกประกาศ                 |
| `implementation`  | `file`, `line`, `symbol`         | การนำไปใช้จริง                              |
| `references`      | `file`, `line`, `symbol`         | ทุกจุดที่ถูกใช้ จำกัดที่ 50                   |
| `hover`           | `file`, `line`, `symbol`         | ลายเซ็นและคอมเมนต์เอกสาร                     |
| `symbols`         | `query` หรือ `file`              | ค้นหาในเวิร์กสเปซด้วย `query` (จำกัดที่ 100); สัญลักษณ์ในเอกสารด้วย `file` (จำกัดที่ 200) |
| `code_actions`    | `file`, `line`, `symbol`         | การแก้แบบด่วนที่เซิร์ฟเวอร์เสนอ                |
| `status`          | —                                | เซิร์ฟเวอร์ตัวใดกำลังทำงาน และสำหรับรากใด        |
| `reload`          | —                                | รีสตาร์ตเซิร์ฟเวอร์สำหรับรากนี้                 |

### ผลวินิจฉัยเมื่อเขียน

ผลตอบแทนไม่ใช่ตัวเครื่องมือ `write`, `edit` และ `apply_patch` ถูก**ห่อไว้**: หลังการเขียน ไฟล์จะถูกซิงก์และบันทึกผ่านเซิร์ฟเวอร์ภาษา และมีเพียงผลวินิจฉัยที่**เพิ่งเกิดขึ้นใหม่**เท่านั้นที่ถูกพับรวมเข้าไปในผลลัพธ์ของเครื่องมือ เอเจนต์จึงรู้ว่าตัวเองทำให้บิลด์พังในจังหวะที่มันพัง โดยไม่ต้องนึกขึ้นมาได้ว่าต้องถาม

ผลวินิจฉัยที่ถูกแจ้งไปแล้วจะถูกระงับด้วยทะเบียนต่อการรันหนึ่งชุดที่ยึดความรุนแรง รหัส และข้อความเป็นคีย์ — ตำแหน่งถูกตัดออกอย่างจงใจ ผลวินิจฉัยที่แค่เลื่อนลงมาสี่บรรทัดจึงไม่ถูกแจ้งซ้ำว่าเป็นของใหม่

## `lsp_rename` — เปลี่ยนชื่อทั้งโปรเจกต์

เครื่องมือแยกต่างหากระดับ `write` ด้วยเหตุผลเดียวเท่านั้น: ระดับเป็นตัวตัดสินการมองเห็น การพับการเปลี่ยนชื่อเข้าไปใน `lsp` จะหมายถึงการมอบความสามารถในการเขียนรีโปใหม่ให้กับตัวสำรวจแบบอ่านอย่างเดียว หรือไม่ก็เอา `hover` ทุกครั้งไปไว้หลังพรอมป์ต์ขออนุมัติ

| อาร์กิวเมนต์ | ความหมาย                                |
| -------- | ------------------------------------------ |
| `file`   | ตำแหน่งที่สัญลักษณ์อยู่                       |
| `line`   | บรรทัดที่นับจาก 1                            |
| `symbol` | สตริงย่อยที่ระบุตัวมันบนบรรทัดนั้น             |
| `new_name` | ชื่อที่จะเรียกมัน                          |

## `ast_grep` — การค้นหาเชิงโครงสร้าง

หาโค้ดด้วย**รูปร่าง**แทนที่จะด้วยข้อความ `$NAME` จับคู่กับโหนดใดก็ได้ `$$$NAME` จับคู่กับโหนดพี่น้องที่ต่อเนื่องกัน และ `$_` เป็นไวลด์การ์ดที่ไม่ผูกอะไรเลย

คุณสมบัติที่ทำให้มันเป็นตัวจับคู่แทนที่จะเป็นรีจิกซ์ที่เพิ่มขั้นตอนเข้ามา: เมทาวาริเอเบิลที่ซ้ำกันในแพตเทิร์นเดียวต้องจับข้อความเดียวกัน

```
ast_grep(pattern: "if ($X != null) $X.dispose()", language: "dart")
```

จะจับคู่กับโค้ดป้องกันที่ dispose สิ่งที่มันเพิ่งตรวจสอบ และจะ**ไม่**จับคู่กับอันที่ dispose อย่างอื่น

| อาร์กิวเมนต์    | ความหมาย                                                     |
| ------------- | ----------------------------------------------------------- |
| `pattern`     | เศษโค้ดที่มีเมทาวาริเอเบิล                                     |
| `path`        | ไฟล์หรือไดเรกทอรีที่จะค้นหา; ค่าเริ่มต้นคือทั้งเวิร์กสเปซ        |
| `language`    | id ของไวยากรณ์ที่จัดส่งมา (`dart`, `python`, `rust`, `c`, …) จะถูกอนุมานเมื่อ `path` ชี้ไปที่ไฟล์ |
| `max_results` | ค่าเริ่มต้น 50                                               |

:::note[แพตเทิร์นถูกแยกวิเคราะห์ด้วยไวยากรณ์เดียวกับไฟล์]
ดังนั้น `dispose(x)` จึงจับคู่กับการเรียกได้ไม่ว่าจะเว้นวรรค ห่อ หรือคอมเมนต์ไว้อย่างไร — และไม่เคยจับคู่ตัวอักษรชุดเดียวกันที่อยู่ในสตริงลิเทอรัลหรือคอมเมนต์เลย
:::

:::caution[เศษโค้ดถูกแยกวิเคราะห์ในโครงร่าง ไม่ใช่แบบเปล่า]
`dispose(x)` ที่แยกวิเคราะห์ที่ระดับบนสุดของ Dart คือ**ลายเซ็นฟังก์ชัน**ที่ถูกต้อง ตัวคอมไพล์แพตเทิร์นจะไล่ลองบันไดของบริบท (คำสั่ง นิพจน์ สมาชิกคลาส การประกาศ) และใช้บริบทแรกที่ยอมรับเศษโค้ดนั้น แพตเทิร์นที่ไม่มีบริบทใดยอมรับจะถูกรายงานว่าแยกวิเคราะห์ไม่ได้ แทนที่จะถูกค้นหาแล้วเงียบ ๆ ว่าไม่พบ
:::

## `ast_edit` — เขียนใหม่เชิงโครงสร้าง แบบพักไว้

การจับคู่แบบเดียวกัน บวกกับเทมเพลต `rewrite` ที่เมทาวาริเอเบิลถูกแทนกลับเข้าไป **ไม่มีอะไรถูกเขียนลงไป** การเปลี่ยนแปลงถูกพักไว้ และผลลัพธ์ระบุ `edit_id`

```
ast_edit(pattern: "dispose($X)", rewrite: "$X.dispose()", language: "dart")
→ (proposed) 12 replacements in 4 files … call resolve with edit_id "edit_1"
```

| อาร์กิวเมนต์ | ความหมาย                                             |
| ---------- | --------------------------------------------------- |
| `pattern`  | สิ่งที่จะจับคู่                                       |
| `rewrite`  | สิ่งที่จะใส่แทน โดยมี `$NAME` ถูกแทนที่                 |
| `path`     | ขอบเขต; ค่าเริ่มต้นคือทั้งเวิร์กสเปซ                   |
| `language` | id ของภาษา                                          |

## `resolve` — คอมมิตหรือทิ้งการเปลี่ยนแปลงที่พักไว้

| อาร์กิวเมนต์ | ความหมาย                          |
| --------- | -------------------------------- |
| `edit_id` | จากผลลัพธ์ `(proposed)`            |
| `action`  | `accept` หรือ `discard`           |

ทุกไฟล์จะถูกตรวจเทียบกับเนื้อหาที่บันทึกไว้ตอนพักการเปลี่ยนแปลง และความไม่ตรงกัน**แม้แต่จุดเดียว**จะปฏิเสธการเปลี่ยนแปลงทั้งชุด การเขียนใหม่เชิงโครงสร้างที่ลงไปเพียงบางส่วนจะทิ้งทรีที่คอมไพล์ไม่ผ่านทั้งรูปร่างเดิมและรูปร่างใหม่

## `debug` — ขับเคลื่อนดีบักเกอร์

ลงทะเบียนเมื่อการรันมีผู้ดูแลเซสชันดีบัก ไดเรกทอรีทำงาน และ id ของบทสนทนา ว่าอะแดปเตอร์จะเริ่มทำงานได้จริงหรือไม่นั้นถูกตรวจตอนเรียกใช้ ด้วยกฎส่วนตัดกันเดียวกับเซิร์ฟเวอร์ภาษา (มาร์กเกอร์ที่ราก *และ*ไบนารี) ระดับ `exec`; ไม่ปลอดภัยเมื่อรันขนานกัน (เซสชันคือสถานะที่อยู่ข้ามการเรียก ดังนั้น `continue` ที่แซง `stack` จะอ่านเฟรมที่ขยับไปแล้ว)

หนึ่งเซสชันต่อหนึ่งบทสนทนา พร้อม TTL แบบตายตัว (30 นาที) `launch` ครั้งที่สองจะถูกปฏิเสธแทนที่จะไปแทนที่ครั้งแรกอย่างเงียบ ๆ ในการรันที่อยู่ในแซนด์บ็อกซ์ เซสชันจะคงแซนด์บ็อกซ์ของมันไว้ตลอดหลายเทิร์นจนกว่าจะจบ ดังนั้นจึงคงอยู่ได้ไม่เกิน 30 นาทีนั้นเท่านั้น

## `repl` — รันสคริปต์ที่เรียกเครื่องมือของคุณ

มีอยู่ในทุกการรันเมื่อเซิร์ฟเวอร์รันสคริปต์ได้ ([เมื่อการรันมี `repl`](/th-TH/คู่มือ/แนวคิด/โหมดโค้ด/#เมื่อการรันมี-repl)) สคริปต์เป็น JavaScript ธรรมดา เป็นตัวของฟังก์ชัน async และรันในอินเทอร์พรีเตอร์ใหม่ที่ล็อกแล้วในโปรเซสของตัวเอง ไม่มีการเข้าถึงระบบไฟล์ เครือข่าย โปรเซส หรือโมดูล `repl` เองอยู่ในระดับ `read` และป้องกันตัวเอง เพราะการเรียกเครื่องมือทุกครั้งที่สคริปต์ทำจะถูกตรวจแยกต่างหาก ใช้ได้ด้วยกับปลายทาง MCP สำหรับการรันของเอเจนต์บนเซิร์ฟเวอร์ที่รันสคริปต์ได้

| อาร์กิวเมนต์ | ความหมาย |
| ------------------- | --------------------------------------------------------------------------------------------- |
| `code` | สคริปต์ สูงสุด 256 KiB |
| `description` | จำเป็น ป้ายสั้น ๆ สำหรับแถวในบทสนทนา |
| `timeout_ms` | ไม่บังคับ ขีดจำกัดเวลาที่สั้นกว่าของเวิร์กสเปซ ไม่มีทางให้ยาวกว่า |
| `max_output_tokens` | ไม่บังคับ งบเอาต์พุตที่เล็กกว่าของเวิร์กสเปซ ไม่มีทางให้ใหญ่กว่า |

```js
// Read three files together and report only which ones failed.
const paths = ["lib/a.dart", "lib/b.dart", "lib/c.dart"];
const results = await Promise.allSettled(paths.map((path) => tools.read({ path })));
return results
  .map((r, i) => (r.status === "rejected" ? `${paths[i]}: ${r.reason.message}` : null))
  .filter(Boolean);
```

คำอธิบาย `repl` บอกเอเจนต์ว่า “เครื่องมือที่ไม่ใช่เครื่องมือโดยตรงของคุณจะไม่มีนิยามในคำขอนี้ ก่อนเรียกตัวใดเป็นครั้งแรก ให้ค้นหาด้วย `describeTool(name)` หรือ `searchTools(query)` เว้นแต่รูปแบบการเรียกที่แน่นอนของมันเคยถูกแสดงให้คุณเห็นแล้วในบทสนทนานี้”

`describeTool(name)` คืนคำอธิบายของเครื่องมือ การประกาศ สคีมาอินพุตและเอาต์พุต และหมายเหตุผลลัพธ์ของมัน เมื่อมีหมายเหตุ ซึ่งคือสิ่งที่สคริปต์ได้รับจากการเรียกที่เสร็จแล้ว ด้วยถ้อยคำของเครื่องมือเอง คำอธิบาย `repl` แสดงหมายเหตุของเครื่องมือโดยตรงที่สคริปต์เรียกได้ ผลลัพธ์ที่เป็นข้อความ JSON จะมาถึงในรูปที่แยกวิเคราะห์แล้ว เว้นแต่มีค่ามากกว่า 131,072 ค่า ซึ่งในกรณีนั้นจะมาถึงเป็นข้อความ และสคริปต์แยกวิเคราะห์เองด้วย `JSON.parse` ผลลัพธ์ที่เป็นข้อความของเครื่องมือจากเซิร์ฟเวอร์ MCP ภายนอกจะถูกตัดที่ 262,144 อักขระ และข้อความที่ถูกตัดแบบนี้จะไม่สามารถแยกวิเคราะห์ได้อีก

- `tools.<name>(args)` เรียกเครื่องมือผ่านตัวกรอง กฎคุม และการอนุมัติชุดเดียวกับการเรียกโดยตรง และปฏิเสธด้วยข้อผิดพลาดเมื่อถูกปฏิเสธหรือล้มเหลว การเรียกแบบอ่านอย่างเดียวรันพร้อมกันได้ การเรียกที่เปลี่ยนแปลงอะไรจะรันทีละรายการ ตามลำดับที่สคริปต์ทำ ขณะที่การเรียกหนึ่งรอคนอยู่ การเรียกอื่นของสคริปต์จะไม่เริ่ม
- `ALL_TOOLS`, `searchTools(query, { limit, namespace })`, `describeTool(name)` และ `describeNamespace(name)` ค้นหาเครื่องมือ รวมถึงของเซิร์ฟเวอร์ MCP ที่เชื่อมต่ออยู่ เครื่องมือนอกชุดโดยตรงที่สคริปต์เรียกได้จะเรียกได้เฉพาะจากสคริปต์ การเรียกตัวหนึ่งโดยตรงจะคืนวิธีเรียกจาก `repl` เว้นแต่เซิร์ฟเวอร์จะรันสคริปต์ของการรันนั้นไม่ได้ ซึ่งในกรณีนั้นเครื่องมือจะโหลดเมื่อใช้ครั้งแรกแทน
- การค้นหาถูกจำกัด: คำค้นยาวไม่เกิน 1,024 อักขระ ชื่อหรือเนมสเปซยาวไม่เกิน 256 `limit` อยู่ระหว่าง 0 ถึง 50 และการค้นหารวมกันต่อสคริปต์ไม่เกิน 200 ครั้งที่ใช้เวลาของเซิร์ฟเวอร์รวมไม่เกิน 2 วินาที ขณะที่สคริปต์ทั้งหมดของเวิร์กสเปซหนึ่งใช้เวลาค้นหาร่วมกัน 2 วินาที ซึ่งคืนกลับในอัตราหนึ่งในสี่วินาทีต่อวินาที เกินขีดใดขีดหนึ่งเหล่านี้ การค้นหาต่อไปจะถูกปฏิเสธ ในแคตตาล็อกที่ใหญ่มาก คำอธิบายใน `ALL_TOOLS` ใช้อักขระประมาณหนึ่งล้านตัวร่วมกันอย่างเท่าเทียม และคำอธิบายที่ถูกตัดจะลงท้ายด้วย `…`; `describeTool` จะคืนคำอธิบายเต็มเสมอ ชนิดที่ใหญ่เกินจะแสดงได้จะขึ้นว่า `unknown /* too large to show */` และชื่อที่ไม่รู้จักจะได้คำตอบเป็นชื่อที่ใกล้เคียงที่สุด
- เครื่องมือถูกจัดกลุ่มเป็นเนมสเปซ: `builtin` (เครื่องมือของฮาร์เนสเอง) `control-center` (เครื่องมือของ Control Center) และหนึ่งเนมสเปซต่อเซิร์ฟเวอร์ MCP ที่เชื่อมต่อ ตั้งชื่อตามเซิร์ฟเวอร์นั้น เซิร์ฟเวอร์ที่ชื่อ `builtin`, `control-center` หรือ `script` หรือที่ชื่อขึ้นต้นด้วย `external-` ไม่ว่าจะใช้ตัวพิมพ์ใหญ่หรือเล็กผสมกันแบบใด และมีหรือไม่มีช่องว่างรอบชื่อ จะถูกแสดงเป็น `external-` ตามด้วยชื่อของมัน และไม่มีเครื่องมือใดอยู่ใน `script` เลย
- มีเพียงสิ่งที่สคริปต์ส่งคืน หรือส่งให้ `text()`, `image()` หรือ `console.*` เท่านั้นที่กลับมายังเอเจนต์ เอาต์พุตที่เกินงบจะเก็บส่วนต้นและส่วนท้ายไว้ และ `read_output` อ่านส่วนที่เหลือได้
- `store(key, value)` / `load(key)` เก็บค่า JSON ไว้ให้สคริปต์ถัดไปของบทสนทนาและเอเจนต์เดียวกัน บันทึกเมื่อสคริปต์เสร็จสมบูรณ์เท่านั้น สคริปต์ของซับเอเจนต์ไม่มีที่เก็บค่า
- `await tools.ask_user(...)` ถามคำถาม และคำตอบของมันจะถูกเพิ่มเข้าไปในผลลัพธ์ด้วย ยังมี `sleep(ms)`, `setTimeout`, `limits()` และ `models.embed` / `rank` / `classify` (การฝังตัวบนอุปกรณ์) ให้ใช้ด้วย
- `describeTool(name)` และ `searchTools(query)` ตอบสำหรับฟังก์ชันของสคริปต์เองด้วย ซึ่งไม่ใช่เครื่องมือ ได้แก่ `text`, `image`, `store`, `load`, `sleep`, `setTimeout`, `clearTimeout`, `limits`, `exit` และ `models.*` อยู่ภายใต้เนมสเปซ `script` ตามที่ระบุ
- เรียกจากสคริปต์ไม่ได้: `repl`, `eval`, `task`, `checkpoint`, `rewind`, `compact`, `search_tools` และคำกริยา `vibe_*`
- สคริปต์อ่านประวัติการรันของตัวเองได้: `history({start, role, tool, limit})` แบ่งหน้าบทสนทนาของการสนทนา (สูงสุด 50 แถวต่อการเรียก ส่ง `next_start` ของหน้าก่อนเป็น `start`), `outputs()` แสดงรายการเอาต์พุตของเครื่องมือที่เก็บไว้สำหรับการสนทนาและเอเจนต์นี้ และ `loadOutput(handle)` อ่าน 16,384 ตัวอักษรของหนึ่งรายการ `storedKeys()` แสดงคีย์ที่เก็บไว้พร้อมขนาด `keep(value, label)` เก็บค่าขนาดใหญ่เป็นเอาต์พุตที่สคริปต์ถัดไปหรือ `read_output` อ่านได้ บันทึกเฉพาะเมื่อสคริปต์ทำงานเสร็จ (1 MiB ต่อค่า 64 ค่า และ 16 MiB ต่อการรัน) `limits().returnBudgetChars` บอกว่างบเอาต์พุตที่เหลืออยู่เท่าใด การรันแบบอ่านอย่างเดียว (การรีวิวเป้าหมาย) อ่านได้ แต่เก็บหรือ keep ไม่ได้ บน Claude Code และ ACP `history()` ใช้ได้ ส่วน `outputs()`, `loadOutput()` และ `keep()` จะปฏิเสธ เพราะ Control Center ไม่เก็บเอาต์พุตของเครื่องมือจากการรันเหล่านั้น
- ข้อผิดพลาดจากการหมดเวลา เอาต์พุตล้น หรือขีดจำกัดจำนวนการเรียก จะบอกวิธีแก้ไขไว้

หนึ่งการรันรันสคริปต์ทีละหนึ่งตัว ขีดจำกัดและสิ่งที่เกิดขึ้นเมื่อถึงแต่ละอย่างอยู่ในหน้า[โหมดโค้ด](/th-TH/คู่มือ/แนวคิด/โหมดโค้ด/#ขีดจำกัด) และทุกสคริปต์ถูกบันทึกภายใต้ **การสังเกตการณ์ → การรันโค้ด**

## `eval` — อินเทอร์พรีเตอร์แบบถาวร

เซลล์ Python หรือ JavaScript ที่ตัวแปร อิมพอร์ต และข้อมูลที่โหลดไว้อยู่ต่อระหว่างการเรียก ระดับ `exec`; ไม่ปลอดภัยเมื่อรันขนานกัน ไม่สามารถเรียกจากสคริปต์ `repl` ได้ และเซลล์เรียกเครื่องมือของการรันไม่ได้ หากต้องการเรียกเครื่องมือจากโค้ด ให้ใช้ [`repl`](#repl--รันสคริปต์ที่เรียกเครื่องมือของคุณ)

| อาร์กิวเมนต์    | ความหมาย                                        |
| ------------- | ------------------------------------------------ |
| `code`        | เซลล์                                            |
| `description` | จำเป็น 5–10 คำสำหรับป้ายในทรานสคริปต์               |
| `language`    | `python` (ค่าเริ่มต้น) หรือ `javascript`           |
| `reset`       | ทิ้งอินเทอร์พรีเตอร์และเริ่มใหม่ที่สะอาดก่อน        |

- นิพจน์สุดท้ายจะถูกสะท้อนกลับแบบที่โน้ตบุ๊กทำ
- `display()` ทำงาน ดาต้าเฟรมของ pandas เรนเดอร์เป็นตาราง และภาพของ matplotlib กลับมาเป็น**รูปภาพที่ทรานสคริปต์แสดง**
- สำนวนของ IPython ที่คนพิมพ์กันโดยไม่ทันคิด — `%pip`, `%cd`, `!cmd`, `%%bash`, `%%timeit` — ถูกเขียนใหม่เป็นโค้ดธรรมดา `%pip` ยังไล่ `sys.modules` ออกด้วย `import` ครั้งถัดไปจึงเห็นสิ่งที่เพิ่งติดตั้งไป
- เซลล์ที่พิมพ์เกินงบเอาต์พุตของมันจะเก็บสามในสี่แรกและหนึ่งในสี่สุดท้าย พร้อมบรรทัดหนึ่งที่บอกจำนวนตัวอักษรและรูปภาพที่ถูกตัดทิ้ง
- เมื่อตัวแปลภาษาตายโดยไม่มีใครขอ เซลล์ถัดไปจะได้รับแจ้งหนึ่งครั้งว่าตัวแปรก่อนหน้าของมันหายไปแล้ว

:::note[เคอร์เนลรันที่ไหน]
ในเอนโคลเจอร์ของบทสนทนาเมื่อมี ไม่งั้นอยู่บนโฮสต์ภายในแซนด์บ็อกซ์ของระบบปฏิบัติการของการรัน เมื่อปิดแซนด์บ็อกซ์หรือไม่มีให้ใช้ มันจะรันโดยไม่ถูกจำกัด และ `eval` จะขอการอนุมัติให้รันบนโฮสต์ มันไม่บูตเอนโคลเจอร์เพื่อไปให้ถึงตรงนั้น กฎเดียวกับที่หยุดแท็บริกไม่ให้สตาร์ตอัตโนมัติ
:::

## `bash` ในเบื้องหลัง

`bash` ที่มี `run_in_background: true` จะเริ่มคำสั่งและคืนค่าทันทีพร้อมแฮนเดิล (`b1`, `b2`, …) แทนการรอ เอเจนต์ทำงานต่อไปได้ หรือจบเทิร์นของมันและจะถูกปลุกเมื่อคำสั่งออก

| อาร์กิวเมนต์ | ความหมาย |
| ------------------- | ------- |
| `run_in_background` | `true` เพื่อเริ่มและคืนค่าทันที |
| `timeout_seconds` | จำนวนวินาทีก่อนที่คำสั่งจะถูกฆ่า: ค่าเริ่มต้น 600 สูงสุด 3,600 |
| `notify` | ไม่บังคับ รูปแบบอย่างง่าย แต่ละบรรทัดของเอาต์พุตที่ตรงกับรูปแบบจะถูกส่งให้เอเจนต์ขณะคำสั่งกำลังรัน (เช่น `listening on\|FAILED`) |

- มากที่สุด 4 คำสั่งเบื้องหลังทำงานพร้อมกันในการรันหนึ่งครั้ง แต่ละคำสั่งจะถูกฆ่าเมื่อหมดเวลาและเมื่อการรันสิ้นสุด พร้อมกระบวนการทั้งหมดที่มันเริ่มไว้
- เมื่อคำสั่งออก เอเจนต์จะได้รับการแจ้งเตือนพร้อมรหัสออก เอาต์พุต 2,000 ตัวอักษรสุดท้าย และแฮนเดิล `read_output` สำหรับส่วนที่เหลือ
- เอเจนต์ที่งานที่เหลือเพียงอย่างเดียวคือคำสั่งเบื้องหลัง จะรอโดยไม่เรียกโมเดล และ watchdog ความเงียบของการรันจะหยุดชั่วคราวระหว่างรอ
- `bash_output(handle)` อ่านสถานะและเอาต์พุตล่าสุดของคำสั่ง ส่วน `bash_kill(handle)` หยุดคำสั่งนั้น ทั้งสองจะบอกเมื่อผลลัพธ์ถูกส่งไปแล้ว
- สคริปต์เริ่มคำสั่งเบื้องหลังไม่ได้ Claude Code มี Bash เบื้องหลังของตัวเอง ส่วน Control Center จะเปิดการรันนั้นค้างไว้ได้ไม่เกิน 10 นาทีหลังเทิร์นที่ปล่อยงานค้างอยู่

## `compact` — เพิ่มพื้นที่ว่างในหน้าต่างบริบท

บีบอัดบริบทเก่าของการสนทนาก่อนการเรียกโมเดลถัดไป โดยเก็บสิ่งที่ `focus` ระบุไว้ (ไม่เกิน 1,000 ตัวอักษร) เทิร์นที่ใหม่ที่สุดยังคงอยู่โดยไม่เปลี่ยนแปลง บรรทัดงบต่อเทิร์นของเอเจนต์แสดงการใช้บริบทที่ 70, 80 และ 90% และเครื่องมือนี้คุ้มค่าที่จะเรียกเมื่อเกินประมาณ 70% ก่อนช่วงงานใหม่ที่ยาว ฮุก `preCompact` ของเจ้าของเซิร์ฟเวอร์เพิ่มเข้าไปในโฟกัสได้ ([ฮุกเชลล์](/th-TH/คู่มือ/อ้างอิง/การตั้งค่าเอเจนต์/#ฮุกเชลล์)) หลังการบีบอัด เซิร์ฟเวอร์จะเพิ่มบล็อก “Still in flight”: เป้าหมาย การปลุกที่รออยู่ คำขอที่เปิดอยู่ คำสั่งเบื้องหลัง เช็คลิสต์ และคีย์ที่เก็บไว้ แต่ละอย่างพร้อมการเรียกที่กู้คืนมัน

## `ask_user` — ถามคำถามกับมนุษย์

ระดับ `read` **วิธีเดียว**ที่การรันจะถามผู้ปฏิบัติงานได้ มันเรนเดอร์การ์ดแบบมีหมายเลขในบทสนทนาและบล็อกรอจนกว่าจะมีคนตอบ ข้าม หรือคำถามหมดเวลา ห้ามเขียนคำถามเป็นข้อความแชทเด็ดขาด — นั่นจะจบเทิร์น

| อาร์กิวเมนต์     | ความหมาย                                    |
| -------------- | ------------------------------------------ |
| `question`     | สิ่งที่จะถาม                                |
| `context`      | ไม่บังคับ: ทำไมคุณถึงถาม และอะไรขึ้นอยู่กับคำตอบ |
| `options[]`    | ตัวเลือก แต่ละอันเป็น `{label, description?}` |
| `allow_free_text` | รับคำตอบที่พิมพ์เองหรือไม่                 |
| `multi_select` | เลือกได้หลายตัวเลือกหรือไม่                  |

การข้ามถือว่าสำเร็จ: ไปต่อบนสมมติฐานที่ระบุไว้และอย่าถามอีก การหมดเวลาเป็นข้อผิดพลาดที่มีคำสั่งเดียวกัน พรอมป์ต์ขออนุญาต (“ฉันทำสิ่งนี้ได้ไหม?”) เป็นด่านแยกต่างหากและเรนเดอร์เป็นการ์ดแบบเดียวกันในบทสนทนา

ลงทะเบียนเมื่อมีทั้งพอร์ตคำถามและสเปซเป้าหมายเท่านั้น หากไม่มีมนุษย์เชื่อมต่ออยู่ การเรียกจะ**ล้มเหลว**แทนที่จะบล็อกไปตลอด — ท่าทีล้มเหลวแบบปิดเดียวกับที่ `prompt` ของกฎคุมใช้เมื่อไม่มีผู้อนุมัติเชื่อมต่ออยู่

## `vibe_*` — กำกับวอร์กเกอร์พื้นหลัง

ลงทะเบียนเฉพาะขณะ[โหมด vibe](/th-TH/คู่มือ/วิธีทำ/กำกับวอร์กเกอร์พื้นหลัง/)เปิดอยู่ ทั้งห้าตัวเป็นระดับ `read`: ด่านควรอยู่ที่เครื่องมือของวอร์กเกอร์ ซึ่งการแก้ไขเกิดขึ้นจริงตรงนั้น

| เครื่องมือ   | อาร์กิวเมนต์                            | หมายเหตุ                                    |
| ------------ | ---------------------------------------- | ------------------------------------------- |
| `vibe_spawn` | `brief`, `label`, `tier?`                | คืนค่าทันที; วอร์กเกอร์ทำงานต่อไป              |
| `vibe_send`  | `worker_id`, `message`                   | ต่อท้ายบรีฟแล้วรันใหม่                        |
| `vibe_wait`  | `worker_id`, `timeout_seconds?`          | บล็อกรอจนกว่ามันจะจบ                          |
| `vibe_kill`  | `worker_id`                              | หยุดมัน                                      |
| `vibe_list`  | —                                        | ระดับ สถานะ เวลาที่ผ่านไป และผลลัพธ์ล่าสุด       |

`tier` คือ `fast` (งานเชิงกลไกที่มีสเปกชัดเจน) หรือ `good` (การออกแบบ การใช้ดุลพินิจ หรือการรีวิวผลลัพธ์ของวอร์กเกอร์ระดับ `fast`)
