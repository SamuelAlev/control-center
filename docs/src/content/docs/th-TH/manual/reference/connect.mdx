Control Center Connect ดำเนินการลงชื่อเข้าใช้ผู้ให้บริการให้กับเซิร์ฟเวอร์ที่ยังไม่ได้ลงทะเบียนแอปของตัวเอง เซิร์ฟเวอร์สามารถใช้ Connect ที่ Control Center โฮสต์ให้ Connect ที่องค์กรของตัวเองรัน ([รันเซิร์ฟเวอร์ Connect](/th-TH/คู่มือ/วิธีทำ/รันเซิร์ฟเวอร์-connect/)) หรือไม่ใช้ก็ได้ การเลือกนี้อยู่ที่ **การตั้งค่า → เซิร์ฟเวอร์ → ลงชื่อเข้าใช้ครั้งเดียว → Control Center Connect**, `cc_server connect` หรือ `CC_CONNECT_URL` เวิร์กสเปซจะทำตามการเลือกนี้ เว้นแต่ผู้ดูแลจะเลือกอย่างอื่นให้เวิร์กสเปซนั้นใน **การตั้งค่า → เวิร์กสเปซ → การผสานรวม** ([การเลือกของแต่ละเวิร์กสเปซ](#การเลือกของแต่ละเวิร์กสเปซ))

## ช่องทาง

ภายใต้ **ใช้แอปของฉันเอง** (หรือก่อนที่ใครจะเลือก) ช่องทางใช้แอปของเซิร์ฟเวอร์เองเมื่อการตั้งค่าแอปนั้นครบถ้วน มิฉะนั้นจะใช้ไม่ได้ เมื่อใช้ Control Center Connect หรือ Connect แบบกำหนดเอง Connect จะให้บริการทุกช่องทางที่ให้บริการ แอปของเซิร์ฟเวอร์เองยังถูกบันทึกไว้แต่ไม่ได้ใช้งาน ทั้งสำหรับการลงชื่อเข้าใช้ ระบบอัตโนมัติของเซิร์ฟเวอร์ หรือสถานะที่เซิร์ฟเวอร์รายงาน เวิร์กสเปซที่ทำการเลือกของตัวเองจะรันทุกช่องทางตามการเลือกนั้นแทน

| ช่องทาง      | แอปของตัวเองต้องมี                               | ผ่าน Connect                                              |
| ------------ | ------------------------------------------------ | --------------------------------------------------------- |
| `github`     | App id, private key, client id และ client secret | คนลงชื่อเข้าใช้ GitHub App ที่ใช้ร่วมกัน                  |
| `google`     | client id และ client secret                      | คนเชื่อมต่อ Google Calendar                               |
| `linear`     | client id                                        | คนลงชื่อเข้าใช้ Linear                                    |
| `linear_app` | client id                                        | ผู้ดำเนินการแอปที่ผู้ดูแลเวิร์กสเปซเชื่อม Linear          |
| `slack`      | การเชื่อมต่อแอป Slack ของเวิร์กสเปซเอง            | ผู้ดูแลเวิร์กสเปซเชื่อม Slack เข้ากับแอป Slack ที่ใช้ร่วมกัน |
| `klipy`      | `KLIPY_APP_KEY`                                  | การค้นหา GIF ซึ่ง Connect เป็นพรอกซี                       |

แอปของตัวเองที่ตั้งค่าไว้เพียงบางส่วนจะทำให้ช่องทางนั้นอยู่ในสถานะข้อผิดพลาด และจะไม่ย้อนกลับไปใช้ Connect อย่างเงียบ ๆ เวิร์กสเปซที่เลือก **ใช้แอปของฉันเอง** จะไม่ผ่าน Connect หรือแอปของเซิร์ฟเวอร์สำหรับผู้ให้บริการใดเลย ไม่ว่าจะเป็นผู้ให้บริการใด การเปลี่ยนการเลือก Connect ของเซิร์ฟเวอร์จะไม่ทำให้ใครหลุดจากเวิร์กสเปซที่ทำการเลือกของตัวเอง

## Connect มองเห็นอะไรและมองไม่เห็นอะไร

| Connect มองเห็น                                                                               | Connect มองไม่เห็นเลย                                                 |
| --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| id การติดตั้งของเซิร์ฟเวอร์และลายเซ็นคำขอ                                                     | ซอร์สโค้ด เนื้อหาของรีโป diff หรือข้อความของ pull request              |
| บัญชีของผู้ให้บริการที่ทำการลงชื่อเข้าใช้ให้สำเร็จระหว่างการลงชื่อเข้าใช้                       | ตั๋วงาน บันทึกการถอดเสียง หรืออะไรก็ตามในฐานข้อมูลของเวิร์กสเปซ          |
| ข้อมูลรับรองนั้นเป็นของเวิร์กสเปซใด ในรูปของ id ทึบแสงที่อยู่ในการปิดผนึก                       | ความลับของแอปของเซิร์ฟเวอร์เอง: ไม่เคยออกจากเซิร์ฟเวอร์              |
| โทเค็น GitHub สำหรับรีโปเดียวที่ออกให้สำหรับรีโปใด                                            | โทเค็นรีเฟรชที่เก็บไว้ถาวร: มีอยู่เฉพาะในการปิดผนึกที่เซิร์ฟเวอร์เก็บไว้เท่านั้น |
| ทีม Slack ที่ผูกกับเซิร์ฟเวอร์นี้                                                 | คีย์ Linear: เซิร์ฟเวอร์แลกเปลี่ยนโค้ด Linear ด้วยตัวเอง                  |
| คำค้นหา GIF เมื่อเป็นพรอกซีให้ Klipy                                                          | รหัสผ่าน คีย์การจับคู่ หรือคีย์ของผู้ให้บริการโมเดล                       |
| การอ้างอิงเหตุการณ์ Slack (ทีม ช่อง id ข้อความ) และข้อความคำสั่งสแลช                           | ข้อความ Slack: Connect ทิ้งมันทันทีที่ได้รับ เซิร์ฟเวอร์อ่านข้อความจาก Slack เอง |

Connect เก็บการลงชื่อเข้าใช้ที่กำลังดำเนินอยู่ nonce และแคชไว้ไม่เกิน 10 นาที และตัวนับการใช้งานรายชั่วโมงไม่เกินสองชั่วโมง โทเค็น GitHub สำหรับรีโปเดียวที่ออกในฐานะบุคคลจะยังคงถูกบันทึกไว้ ปิดผนึกกับการลงชื่อเข้าใช้ที่ขอมัน จนกว่าจะหมดอายุ (ไม่เกิน 8 ชั่วโมง) เพื่อให้ Connect ออกให้อีกครั้งและเพิกถอนเมื่อตัดการเชื่อมต่อได้ บันทึกถาวรเดียวของมันคือการผูก Slack (แต่ละทีม Slack ผูกกับเซิร์ฟเวอร์ใด) และ id การติดตั้งที่เลิกใช้แล้ว ข้อผิดพลาดมีเพียงรหัส ไม่มีการตอบกลับจากผู้ให้บริการ บันทึกจะบันทึก id การติดตั้งเป็นแฮชที่มีคีย์เท่านั้น และบันทึกโทเค็น GitHub เป็นเพียง `hashed_token` ที่บันทึกการตรวจสอบขององค์กร GitHub แสดงสำหรับโทเค็นนั้น เพื่อให้เจ้าขององค์กรจับคู่ทั้งสองได้

## โหมด

| โหมด     | การตั้งค่า                  | พฤติกรรม                                                                                                 |
| -------- | --------------------------- | -------------------------------------------------------------------------------------------------------- |
| ยังไม่ตั้งค่า | เซิร์ฟเวอร์ใหม่          | ไม่มีช่องทางใดใช้ Connect ขั้นตอนการเริ่มต้นจะขอให้เจ้าของเซิร์ฟเวอร์เลือก                                 |
| `hosted` | **ใช้แอปของ Control Center** | `https://connect.usectrl.dev` พร้อมการตั้งค่าที่ลงนามแบบออฟไลน์ แอปของเซิร์ฟเวอร์เองจะไม่ถูกใช้                                       |
| `custom` | **ใช้เซิร์ฟเวอร์ Connect ที่กำหนดเอง** | Connect ที่ URL HTTPS (`http` ได้เฉพาะ loopback) เชื่อถือเมื่อใช้ครั้งแรก แอปของเซิร์ฟเวอร์เองจะไม่ถูกใช้                              |
| `off`    | **ใช้แอปของฉันเอง**          | ไม่มีช่องทางใดใช้ Connect มีเพียงแอปของตัวเองเท่านั้นที่ให้คนลงชื่อเข้าใช้ได้                              |

`CC_CONNECT_URL` ในสภาพแวดล้อมของเซิร์ฟเวอร์หรือ `.env` จะล็อกการเลือกนี้: `hosted`, `off` หรือ URL ของ Connect หลังจากนั้นการตั้งค่าจะแสดงการล็อกนี้และไม่สามารถเปลี่ยนได้

บิลด์นี้ไม่มีคีย์การตั้งค่าแบบโฮสต์ติดมาด้วย โหมดโฮสต์จึงรายงาน `hosted_unprovisioned` และไม่ให้ช่องทางใด แอปของตัวเองและ Connect แบบกำหนดเองยังใช้งานได้ตามปกติ

Connect แบบโฮสต์ทำงานในคอนเทนเนอร์เดียว คีย์การปิดผนึกและคีย์ส่วนตัวของ GitHub App ที่ใช้ร่วมกันเป็นตัวแปรสภาพแวดล้อมที่นั่น ไม่ได้อยู่ในคลังคีย์ที่ลงนามหรือถอดรหัสได้อย่างเดียว ตามที่ GitHub แนะนำสำหรับคีย์ส่วนตัวของ App นั่นเป็นช่องว่างที่ทราบอยู่ของการตั้งค่าปัจจุบัน

เซิร์ฟเวอร์อ่านการตั้งค่าของ Connect ไม่เกินทุก 10 นาที และรอการเรียกแต่ละครั้งไม่เกิน 5 วินาที เมื่อ Connect เข้าไม่ถึง มันจะใช้การตั้งค่าที่ใช้ได้ล่าสุดต่อไป และการตั้งค่าจะทำเครื่องหมายว่าเก่า

## การเลือกของแต่ละเวิร์กสเปซ

**การตั้งค่า → เวิร์กสเปซ → การผสานรวม → Control Center Connect** แทนที่การเลือกของเซิร์ฟเวอร์สำหรับเวิร์กสเปซหนึ่ง สมาชิกทุกคนเห็นการเลือกนี้และเห็นว่าแต่ละการลงชื่อเข้าใช้ทำงานที่ไหน มีเพียงผู้ดูแลเวิร์กสเปซเท่านั้นที่เปลี่ยนได้

| ตัวเลือก                         | พฤติกรรม                                                                                                                                                  |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **เหมือนเซิร์ฟเวอร์นี้**         | ค่าเริ่มต้น เวิร์กสเปซทำงานตามที่เจ้าของเซิร์ฟเวอร์เลือกไว้ ตัวเลือกจะระบุชื่อให้เห็น                                                                         |
| **ใช้แอปของ Control Center**     | Connect ที่ Control Center โฮสต์ไว้ ไม่ว่าเซิร์ฟเวอร์จะใช้อะไร                                                                                              |
| **ใช้แอปของฉันเอง**             | เฉพาะแอปของเวิร์กสเปซ: GitHub App, ไคลเอนต์ Google, แอปพลิเคชัน Linear, คีย์ Klipy และแอป Slack ผู้ให้บริการที่ไม่มีแอปของตัวเองจะปิดอยู่ที่นี่ ส่วนที่ตั้งค่าไม่ครบเป็นข้อผิดพลาดการตั้งค่า |
| **ใช้เซิร์ฟเวอร์ Connect ที่กำหนดเอง** | Connect ที่ URL HTTPS ซึ่งเวิร์กสเปซระบุ ที่อยู่ในเครือข่ายส่วนตัวหรือเครื่องภายในจะถูกปฏิเสธ                                                                |

- ตัวเลือกทุกอย่างนอกจาก **เหมือนเซิร์ฟเวอร์นี้** จะเก็บการลงชื่อเข้าใช้ GitHub และ Linear ของแต่ละคนไว้ในช่องของเวิร์กสเปซเอง จึงไม่ปะปนกับช่องที่ใช้ทั้งเซิร์ฟเวอร์
- การเปลี่ยนจะถามก่อน: ทุกคนในเวิร์กสเปซต้องลงชื่อเข้าใช้ GitHub, Linear และ Google Calendar อีกครั้งผ่านแอปใหม่
- การเชื่อมต่อ Slack ของแอป Slack ของเวิร์กสเปซใช้ได้ภายใต้ทุกตัวเลือก **เพิ่ม Control Center ไปยัง Slack** ทำตามตัวเลือกนั้น
- `CC_CONNECT_URL` ยังล็อกไม่ให้เวิร์กสเปซมี Connect ของตัวเองด้วย: พวกเขาทำตามเซิร์ฟเวอร์หรือใช้แอปของตัวเองได้
- Connect แบบกำหนดเองของเวิร์กสเปซเชื่อถือได้ตั้งแต่การใช้งานครั้งแรกสำหรับเวิร์กสเปซนั้นเท่านั้น: **เชื่อถือแอปใหม่** ที่นั่นจะไม่เปลี่ยนสิ่งที่เซิร์ฟเวอร์หรือเวิร์กสเปซอื่นเชื่อถือ

## ตัวตนการติดตั้ง

| รายการ         | คำอธิบาย                                                                                                         |
| -------------- | ---------------------------------------------------------------------------------------------------------------- |
| คีย์การติดตั้ง | seed 32 ไบต์ในไฟล์ความลับของเซิร์ฟเวอร์ (`connect_install_key`) แยกจากคีย์การจับคู่อุปกรณ์                            |
| คีย์ต่อ Connect | คีย์ Ed25519 ที่ได้จาก seed และที่อยู่ของ Connect นั้น คำขอทุกคำขอที่ส่งไปยัง Connect ถูกลงนามด้วยคีย์นี้ (RFC 9421) |
| id การติดตั้ง  | 26 อักขระที่ได้จากคีย์สาธารณะนั้น แสดงในการตั้งค่า และในผลลัพธ์ของ `cc_server connect status`                       |

เซิร์ฟเวอร์เดียวกันจะมี id การติดตั้งต่างกันสำหรับที่อยู่ Connect แต่ละแห่ง id นี้จะเปลี่ยนก็ต่อเมื่อคีย์ถูกหมุนเวียน

## ข้อมูลรับรองที่ปิดผนึก

การลงชื่อเข้าใช้ผ่าน Connect จะส่งคืน**การปิดผนึกข้อมูลรับรอง** ซึ่งเป็นบล็อกข้อมูลที่เข้ารหัสซึ่งเปิดได้เฉพาะโดย Connect ที่สร้างมันเท่านั้น โดยผูกกับผู้ให้บริการ ที่อยู่ Connect id การติดตั้ง เวิร์กสเปซ บัญชีผู้ให้บริการ แอป และรุ่นของคีย์

- เซิร์ฟเวอร์เก็บการปิดผนึกนี้พร้อม id การติดตั้งที่สอดคล้องกัน โทเค็นการเข้าถึงจะอยู่ในหน่วยความจำเท่านั้น
- เมื่อต้องรีเฟรช เซิร์ฟเวอร์ส่งการปิดผนึกกลับไป และได้โทเค็นการเข้าถึงใหม่พร้อมการปิดผนึกใหม่
- การปิดผนึกที่ id การติดตั้งหรือที่อยู่ Connect ไม่ตรงกันอีกต่อไป จะถูกลบเมื่ออ่านครั้งถัดไป และคนนั้นต้องลงชื่อเข้าใช้ใหม่ สิ่งนี้เกิดขึ้นหลังการหมุนเวียนคีย์ การสลับไปยัง Connect อื่น หรือการกู้คืนไดเรกทอรีข้อมูลไปยังเซิร์ฟเวอร์อื่น
- การปิดผนึกที่ Connect เปิดไม่ได้จะถูกปฏิเสธด้วย `access_denied`

## การติดตั้ง GitHub

การติดตั้ง GitHub App ที่ใช้ร่วมกันสามารถใช้ได้จากทุกเซิร์ฟเวอร์ Connect ไม่เก็บบันทึกว่าเซิร์ฟเวอร์ใดใช้การติดตั้งนั้นได้บ้าง

- **ติดตั้ง GitHub App** ใน **การตั้งค่า → เวิร์กสเปซ → การผสานรวม** จะเปิดหน้าติดตั้งแอปบน GitHub เซิร์ฟเวอร์สร้างลิงก์จากชื่อแอปในการตั้งค่า Connect
- โทเคนสำหรับรีโพเดียวต้องมีการติดตั้งแอปบนเจ้าของรีโพ และบุคคลที่ลงชื่อเข้าใช้ต้องมีสิทธิ์เข้าถึงรีโพ เป็นโทเคนของบุคคลนั้นเอง จำกัดตามบทบาทของเขา ไม่มากกว่านั้นเลย
- องค์กรจำกัด Control Center บน GitHub ได้โดยการลบการติดตั้ง จำกัดรีโพ หรือนำบุคคลออก
- สำหรับการเรียกที่มีแต่บุคคลนั้นทำได้ เช่นการแสดงรายการการติดตั้งของเขา Connect ส่งโทเค็นผู้ใช้ App ของบุคคลนั้นให้เซิร์ฟเวอร์ ไม่ใช่โทเค็นรีโปเดียว การลงชื่อเข้าใช้บนเซิร์ฟเวอร์คือการไว้วางใจเซิร์ฟเวอร์นั้นด้วยโทเค็นนั้น
- องค์กรที่บังคับใช้ GitHub IP allow list ใช้ Connect แบบโฮสต์ไม่ได้ เพราะที่อยู่ของมันไม่คงที่ องค์กรนั้นจะลงทะเบียน GitHub App ของตัวเองแทน บนเซิร์ฟเวอร์ของตน หรือบน Connect ที่มันรัน
- **ยกเลิกการเชื่อมต่อ** เพิกถอนเฉพาะการลงชื่อเข้าใช้นั้น: Connect ใช้โทเค็นรีเฟรชของมันหนึ่งครั้งแล้วลบสิ่งที่ได้กลับมา ลบโทเค็นผู้ใช้ของมัน และโทเค็นรีโปเดียวที่ Connect ออกให้สำหรับมัน สำเนาการปิดผนึกที่เก็บไว้ที่ใดก็ตามจะหยุดทำงาน การลงชื่อเข้าใช้ของคนบนเซิร์ฟเวอร์และเวิร์กสเปซอื่นยังทำงานต่อไป หากต้องการลบ Control Center ออกจากบัญชี GitHub ทั้งหมด ให้เพิกถอนใน GitHub ภายใต้ **การตั้งค่า → แอปพลิเคชัน → Authorized GitHub Apps → เพิกถอน**

### บอทที่ใช้ร่วมกัน

โทเค็นที่ออกในฐานะบอทของ App (`as: app`) แสดงบอทเดียวกันบน GitHub สำหรับทุกเซิร์ฟเวอร์ที่ใช้ Connect เดียวกัน GitHub ไม่สามารถแยกเซิร์ฟเวอร์เหล่านั้นออกจากกันได้

- ทุกเซิร์ฟเวอร์อาจให้บอทอ่านและแสดงความคิดเห็นได้: `read`, `review` และ `comment` (ความคิดเห็น ป้ายกำกับ ผู้รับผิดชอบ และปฏิกิริยาบนปัญหาและ pull request)
- การรีวิว pull request ในฐานะบอท (`bot` ซึ่งเขียน pull request) อนุญาตเฉพาะเซิร์ฟเวอร์ที่ผู้ดำเนินการ Connect ระบุใน `CONNECT_GITHUB_REVIEW_BOT_INSTALLS` เซิร์ฟเวอร์อื่นทุกเซิร์ฟเวอร์จะได้คำตอบ `needs_requester` และโพสต์รีวิวด้วยโทเค็นของบุคคลที่รับผิดชอบเอง ซึ่ง GitHub จำกัดให้เป็นของบุคคลนั้น: รีวิวจะปรากฏภายใต้ชื่อของเขา สิ่งนี้ครอบคลุมการเผยแพร่รีวิวด้วย AI ความคิดเห็นรีวิว และคำขอผู้รีวิว
- การพุช การสร้างบรานช์ และการเปิด pull request (`write`) ไม่เคยถูกออกในฐานะบอทที่ใช้ร่วมกัน ใช้การลงชื่อเข้าใช้ของผู้ขอเองเสมอ
- การอนุมัติ pull request ไม่เคยทำอัตโนมัติ ด้วยโทเค็นใดก็ตาม
- เซิร์ฟเวอร์หรือเวิร์กสเปซที่มี GitHub App ของตัวเองยังให้บอทดูแลทั้งหมดนี้ รวมถึงรีวิว

### สิ่งที่เจ้าขององค์กรและสมาชิกควรรู้

- เซิร์ฟเวอร์ที่มีคนลงชื่อเข้าใช้จะถือโทเค็นผู้ใช้ App ของคนนั้น: สูงสุด 8 ชั่วโมงต่อโทเค็น และต่ออายุจนกว่าเขาจะตัดการเชื่อมต่อ โทเค็นนั้นทำในฐานะเขาได้กับทุกรีโปที่ติดตั้ง App ที่ใช้ร่วมกันไว้ซึ่งเขาเข้าถึงได้ Connect สามารถตัดเซิร์ฟเวอร์ออกได้อย่างถาวร (การติดตั้งที่เลิกใช้หรือถูกปฏิเสธ) แต่โทเค็นที่ส่งออกไปแล้วยังใช้ได้จนกว่าจะหมดอายุ
- การติดตั้ง GitHub App ที่ใช้ร่วมกันบนองค์กรเป็นการยินยอมสำหรับทุกเซิร์ฟเวอร์ Control Center ที่สมาชิกคนใดลงชื่อเข้าใช้ ไม่ใช่สำหรับเซิร์ฟเวอร์เดียว
- บอทใช้ร่วมกัน ตามที่กล่าวข้างต้น: องค์กรไม่สามารถบอกได้บน GitHub ว่าเซิร์ฟเวอร์ใดกระทำในฐานะบอท
- องค์กรที่ต้องการขอบเขตของตัวเองจะลงทะเบียน GitHub App ของตัวเองและรัน Connect ของตัวเอง ([รันเซิร์ฟเวอร์ Connect](/th-TH/คู่มือ/วิธีทำ/รันเซิร์ฟเวอร์-connect/)) หรือตั้งค่า App บนเซิร์ฟเวอร์ของตัวเอง

## ความเชื่อถือการตั้งค่า

| Connect | วิธีที่เซิร์ฟเวอร์เชื่อถือการตั้งค่าของมัน                                                                                                    |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| โฮสต์   | ตรวจลายเซ็น Ed25519 ด้วยคีย์ที่ฝังในบิลด์ ปฏิเสธการตั้งค่าที่มีหมายเลขรุ่นต่ำกว่าสูงสุดที่เคยเห็น (`rollback`)                          |
| กำหนดเอง | ปักค่า id ของแอป GitHub และ client id, client id ของ Google และ Linear, และแอป Slack กับ client id เมื่อใช้ครั้งแรก การเปลี่ยนแปลงใดก็ตามจะระงับการลงชื่อเข้าใช้ผ่าน Connect (`pins_changed`) จนกว่าเจ้าของเซิร์ฟเวอร์จะคลิก **เชื่อถือแอปใหม่** |

## การดำเนินการ

การตั้งค่า Connect ของเซิร์ฟเวอร์จำกัดเฉพาะเจ้าของเซิร์ฟเวอร์

| การดำเนินการ          | สิ่งที่ทำ                                                                                              |
| --------------------- | ------------------------------------------------------------------------------------------------------ |
| `connect.status`      | โหมด URL การล็อก id การติดตั้ง สุขภาพ หมายเลขรุ่นการตั้งค่า และแหล่งที่มาของแต่ละช่องทาง                      |
| `connect.configure`   | ตั้งค่า `hosted`, `custom` (พร้อม `url`) หรือ `off`                                                    |
| `connect.test`        | ดึงการตั้งค่าใหม่และรายงานสุขภาพ                                                                       |
| `connect.confirmPins` | ยอมรับตัวระบุที่ Connect แบบกำหนดเองเปลี่ยนแปลงไป                                                       |
| `connect.rotateKey`   | สร้างคีย์การติดตั้งใหม่และ id การติดตั้งใหม่ (`force` แทนที่มันแม้ Connect ไม่สามารถยกเลิกคีย์เดิมได้); ดู[การหมุนเวียนคีย์การติดตั้ง](#การหมุนเวียนคีย์การติดตั้ง) |

การเลือกของเวิร์กสเปซแต่ละแห่งมีการดำเนินการของตัวเอง ซึ่งแต่ละรายการระบุเวิร์กสเปซนั้น:

| การดำเนินการ                    | ใคร                      | สิ่งที่ทำ                                                                             |
| ------------------------------ | ------------------------ | ------------------------------------------------------------------------------------- |
| `workspaceConnect.status`      | สมาชิกคนใดก็ได้          | การเลือก สิ่งที่ค่านี้ resolve เป็น สุขภาพ และแหล่งที่มาของแต่ละผู้ให้บริการ id การติดตั้งและการปักหมุดที่รอดำเนินการสำหรับผู้ดูแลเท่านั้น |
| `workspaceConnect.set`         | ผู้ดูแลเวิร์กสเปซ        | ตั้งค่า `inherit`, `hosted`, `custom` (พร้อม `url`) หรือ `own`                        |
| `workspaceConnect.test`        | ผู้ดูแลเวิร์กสเปซ        | ดึงการตั้งค่า Connect ของเวิร์กสเปซใหม่และรายงานสุขภาพ                                 |
| `workspaceConnect.confirmPins` | ผู้ดูแลเวิร์กสเปซ        | ยอมรับตัวระบุที่เปลี่ยนแปลงไปของ Connect แบบกำหนดเองของเวิร์กสเปซ                      |

การลงชื่อเข้าใช้เองใช้ `oauth.lanes`, `oauth.begin`, `oauth.status`, `oauth.complete`, `oauth.connections` และ `oauth.disconnect` ผู้ลงชื่อเข้าใช้เป็นผู้เรียกที่ลงชื่อเข้าใช้แล้วเสมอ

## การลงชื่อเข้าใช้ผ่าน Connect

1. เซิร์ฟเวอร์ขอให้ Connect เริ่มช่องทางนั้น และได้ URL การอนุญาตของผู้ให้บริการ ซึ่งจะถูกตรวจก่อนแสดง GitHub จะแสดงตัวเลือกบัญชีเสมอ
2. ผู้ใช้อนุมัติในเบราว์เซอร์ ผู้ให้บริการส่งกลับมาที่ Connect
3. Connect แสดงสิ่งที่เซิร์ฟเวอร์ที่เริ่มการลงชื่อเข้าใช้จะทำได้ในฐานะบุคคลนั้น และนานเท่าใด Connect ไม่สามารถบอกได้ว่าใครรันเซิร์ฟเวอร์นั้น หน้าจอจึงขอให้บุคคลนั้นดำเนินการต่อเฉพาะเมื่อเขาเป็นผู้เริ่มการลงชื่อเข้าใช้เอง และให้ปิดหากมีคนส่งลิงก์มาให้ เมื่อเบราว์เซอร์อยู่บนเครือข่ายอื่นจากที่เริ่มการลงชื่อเข้าใช้ หน้าจอจะบอกเช่นนั้น: ซึ่งเป็นเรื่องปกติสำหรับเซิร์ฟเวอร์โฮสต์หรืออุปกรณ์อื่น และก็เป็นลักษณะของฟิชชิงด้วย **ยกเลิก** จบการลงชื่อเข้าใช้: รหัสของผู้ให้บริการจะไม่ถูกใช้เลย แต่ละหน้าตอบได้ครั้งเดียว คำตอบที่ไม่ได้มาจากหน้าที่ Connect เพิ่งแสดงจะถูกปฏิเสธ
4. หลังจาก **ดำเนินการต่อ** Connect แสดงรหัสแปดอักขระและลิงก์ `control-center://oauth-done` ใครก็ตามที่ได้รหัสจะได้สิทธิ์เข้าถึงที่เพิ่งอนุมัติ จึงควรส่งไปยังที่ที่เริ่มการลงชื่อเข้าใช้เท่านั้น
5. ผู้ใช้ป้อนรหัสในแอป หรือเปิดลิงก์ เซิร์ฟเวอร์ใช้รหัสนั้นพร้อมหลักฐานของตัวเองสำหรับคำขอนี้เพื่ออ้างสิทธิ์การลงชื่อเข้าใช้

การลงชื่อเข้าใช้จะหมดอายุหลัง 10 นาที การป้อนรหัสผิดห้าครั้งจะทำให้มันจบลง ลิงก์ที่ไม่ได้เริ่มจากแอปนี้จะถูกปฏิเสธด้วย **การลงชื่อเข้าใช้นี้ไม่ได้เริ่มจากที่นี่** Connect จำกัดจำนวนการลงชื่อเข้าใช้ที่ที่อยู่เครือข่ายหนึ่งเริ่มได้ และความถี่ที่โทเค็น GitHub ถูกออกต่อคนและเซิร์ฟเวอร์ ต่อคนข้ามเซิร์ฟเวอร์ ต่อที่อยู่ และสำหรับทั้งแอป การลงชื่อเข้าใช้ใหม่มีงบประมาณของตัวเอง ดังนั้นจึงไม่เคยขัดขวางการต่ออายุที่คนอื่นต้องการ เมื่อเกินขีดจำกัด การเรียกจะถูกปฏิเสธด้วย `rate_limited` และเซิร์ฟเวอร์จะลองใหม่ภายหลังโดยไม่ทำให้ใครออกจากระบบ การลงชื่อเข้าใช้ที่เกินขีดจำกัดของบุคคลจะถูกยกเลิกที่ GitHub และถูกปฏิเสธ

## การหมุนเวียนคีย์การติดตั้ง

มีเพียงเจ้าของเซิร์ฟเวอร์เท่านั้นที่หมุนเวียนคีย์ได้ ด้วย **หมุนเวียนคีย์** บนการ์ด **Control Center Connect** ใน **การตั้งค่า → เซิร์ฟเวอร์ → ลงชื่อเข้าใช้ครั้งเดียว** ไม่มีคำสั่งสำหรับมัน การหมุนเวียน:

- ทำให้ทุกคนออกจากระบบจากทุกช่องทางที่ผ่าน Connect สำหรับแต่ละเซิร์ฟเวอร์ Connect ที่คีย์เก่าเคยถูกใช้ด้วย เซิร์ฟเวอร์จะเพิกถอนการลงชื่อเข้าใช้ GitHub และ Slack ที่มันถืออยู่จากที่นั่น (การลงชื่อเข้าใช้ Google ไม่มีอะไรให้เพิกถอนและจะหมดไปเอง)
- ยกเลิก id การติดตั้งเก่าที่ Connect แต่ละเซิร์ฟเวอร์ โดยลงนามด้วยคีย์เก่าและพิสูจน์ด้วยการปิดผนึกข้อมูลรับรองหนึ่งรายการที่เซิร์ฟเวอร์ถือจาก Connect นั้น นับจากนั้น Connect จะปฏิเสธทุกคำขอที่ทำด้วยคีย์เก่า ดังนั้นการปิดผนึกหรือสำเนาของคีย์เก่าที่นำมาจากเซิร์ฟเวอร์นี้จึงใช้ไม่ได้ และเวิร์กสเปซ Slack ที่ผูกกับ id เก่าจะถูกปล่อยให้เชื่อมต่อใหม่ได้ โทเค็นที่ออกไปแล้วยังใช้ได้จนกว่าจะหมดอายุ (หนึ่งชั่วโมงสำหรับโทเค็นบอท แปดชั่วโมงสำหรับของบุคคล) เซิร์ฟเวอร์ Connect ที่เซิร์ฟเวอร์นี้ไม่มีการปิดผนึกจากมันจะไม่มีอะไรให้ยกเลิกและจะถูกข้าม
- จากนั้นให้เซิร์ฟเวอร์ได้คีย์การติดตั้งใหม่และ id การติดตั้งใหม่
- หาก Connect เซิร์ฟเวอร์ใดเข้าไม่ถึง หรือปฏิเสธการยกเลิก id เก่า มันจะหยุดก่อนสลับคีย์และแสดง **Connect ยกเลิกคีย์เก่าไม่ได้** **หมุนเวียนต่อไป** สลับคีย์โดยไม่คำนึงถึงสิ่งนั้น; id การติดตั้งเก่าจะยังใช้ได้ที่ Connect นั้นจนกว่าโทเค็นจะหมดอายุ สูงสุดแปดชั่วโมงสำหรับ GitHub
- ไม่กระทบการลงชื่อเข้าใช้ผ่านแอปของเซิร์ฟเวอร์เอง
- ต้องเพิ่ม id การติดตั้งใหม่เข้าในรายการอนุญาตของ Connect แบบกำหนดเอง

## รหัสสถานะ

| รหัส                   | ความหมาย                                                             |
| ---------------------- | -------------------------------------------------------------------- |
| `hosted_unprovisioned` | บิลด์นี้ไม่มีคีย์การตั้งค่าแบบโฮสต์                                  |
| `signature`            | การตั้งค่าแบบโฮสต์ไม่ผ่านการตรวจลายเซ็น                              |
| `rollback`             | Connect ส่งการตั้งค่าที่เก่ากว่าที่เซิร์ฟเวอร์เคยเห็น                |
| `unreachable`          | เซิร์ฟเวอร์เข้าถึง Connect ไม่ได้                                    |
| `install_blocked`      | Connect ไม่อนุญาต id การติดตั้งนี้ หรือ id นั้นถูกยกเลิกแล้ว          |
| `pins_changed`         | Connect แบบกำหนดเองประกาศตัวระบุแอปที่ต่างออกไป                      |
| `protocol`             | การตอบกลับจาก Connect มีรูปแบบที่เซิร์ฟเวอร์นี้เข้าใจไม่ได้            |
