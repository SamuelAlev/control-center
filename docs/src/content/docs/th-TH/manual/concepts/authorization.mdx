Control Center ตอบคำถามด้านการอนุญาตสองข้อ ซึ่งแตกต่างกันจริง ๆ **“บุคคลนี้เรียกใช้การดำเนินการนี้ได้หรือไม่?”** เป็นเรื่องของคน บทบาท และรีโป ส่วน **“เอเจนต์นี้ก่อให้เกิดผลลัพธ์นี้ได้หรือไม่?”** เป็นเรื่องของการกระทำ อาร์กิวเมนต์ และขอบเขตความเสียหาย — ข้อหลังอยู่ใน[กฎคุม](/th-TH/คู่มือ/แนวคิด/กฎคุม/)

หน้านี้ว่าด้วยคำถามข้อแรก พร้อมทั้งบันทึกที่ทั้งสองข้อทิ้งไว้เบื้องหลัง

## จุดตัดสินใจจุดเดียว

การตัดสินด้านการอนุญาตฝั่งมนุษย์ทุกครั้งตัดสินผ่านฟังก์ชันเดียว:

```
can(principal, permission, resource) → allow | deny + why
```

**สิทธิ์**หนึ่งรายการเขียนเป็น `<domain>:<tier>` — `tickets:write`, `members:administer`, `repos:read` แค็ตตาล็อกนี้ถูก**อนุมาน**ขึ้นมา ไม่ได้เขียนด้วยมือ: มันคำนวณจากพื้นผิวการดำเนินการเอง (คำนำหน้าชื่อ op บอก domain ส่วนบทบาทขั้นต่ำที่ op บังคับใช้อยู่แล้วบอกระดับ) การดำเนินการทั้งหมดราว 550 รายการจึงมีสิทธิ์กำกับอยู่ โดยไม่มีใครต้องพิมพ์กำหนดแม้แต่รายการเดียว

การอนุมานเช่นนี้คือคุณสมบัติที่คุ้มค่าแก่การปกป้อง มันหมายความว่าการดำเนินการใหม่ถูกกั้นไว้โดยค่าเริ่มต้น — จุดล้มเหลวของโมเดลที่กำกับด้วยมือคือมีใครสักคนลืม และสิ่งที่เขาลืมก็คือด่านกั้นนั่นเอง มีการทดสอบแบบแรตเช็ตที่ตรึงชุดโดเมนอันเป็นผลลัพธ์ไว้ การเพิ่มการดำเนินการภายใต้คำนำหน้าใหม่จึงเป็นการตัดสินใจตั้งชื่อที่มนุษย์ตั้งใจเลือก ไม่ใช่ความบังเอิญ

ระดับทั้งสี่แมปกับบทบาทในตัวแบบพอดี:

| ระดับ | บทบาทขั้นต่ำ | ตัวอย่าง |
|---|---|---|
| `read` | แขก | `tickets:read` |
| `write` | สมาชิก | `tickets:write` |
| `administer` | แอดมิน | `members:administer` |
| `own` | เจ้าของ | `workspace:own` |

## บทบาท

บทบาทในตัวห้าบทบาท — **เจ้าของ, แอดมิน, สมาชิก, ผู้ดู, แขก** — เป็นพรีเซ็ตบนแค็ตตาล็อกนั้น ความเป็นเจ้าของมีได้เพียงตำแหน่งเดียวต่อเวิร์กสเปซ และโอนกันอย่างชัดเจนด้วย **โอนความเป็นเจ้าของ** (เจ้าของที่จากไปจะลบออกไม่ได้เลยหากไม่ทำเช่นนั้น: การถอนผู้ใช้ด้วย SCIM ปฏิเสธเจ้าของเวิร์กสเปซทุกคน — ต้องโอนก่อน)

**บทบาทที่กำหนดเองทำงานแบบลบออก** บทบาทที่กำหนดเองระบุพรีเซ็ตฐาน (`admin`, `member`, `viewer` หรือ `guest` — ไม่มีทางเป็น `owner`) พร้อมชุดสิทธิ์ที่ถูกนำออกจากพรีเซ็ตนั้น — “เป็นแอดมิน แต่จัดการสมาชิกไม่ได้” มันให้สิทธิ์เกินฐานไม่ได้เลย นี่คือเหตุผลที่นำมาใช้กับระบบที่ติดตั้งอยู่แล้วได้อย่างปลอดภัย: การตรวจสอบเดิมทุกจุดยังคงเป็นขอบเขตบนที่เชื่อถือได้ สมาชิกถือบทบาทเหล่านี้ในชื่อ `custom:<id>` และไคลเอนต์ที่เก่าเกินกว่าจะเข้าใจค่านั้นจะถอยกลับไปใช้แขกแทนที่จะเดา

ใต้บทบาทลงไปคือ**สิทธิ์ระดับรีโป** (`none` / `read` / `review` / `write`, ดู[การเปลี่ยนโค้ดต้องใช้สิทธิ์เขียน](#การเปลี่ยนโค้ดต้องใช้สิทธิ์เขียน)): การเป็นสมาชิกเวิร์กสเปซไม่เคยให้สิทธิ์เหนือกว่าโฮสต์โค้ดอย่างเงียบ ๆ ทุกพื้นผิวที่เปิดให้เข้าถึงโค้ดจะตรวจสอบสิทธิ์เหล่านี้ — รวมถึงเส้นทางที่เข้าถึงโค้ดทางอ้อม เช่นเทอร์มินัลหรือเซสชันตัวแก้ไขที่เปิดบน worktree ของสเปซ

## โค้ดเป็นไปตาม forge

การให้สิทธิ์เพียงอย่างเดียวไม่เปิดโค้ดของรีโป ในการดูไฟล์ ดิฟ หรือผลการค้นหา หรือเปิดเทอร์มินัลบนรีโปนั้น สมาชิกต้องมีสิทธิ์ของ Control Center **และ** การลงชื่อเข้าใช้ forge ของตนเองต้องอ่านรีโปนั้นได้ แอดมินเวิร์กสเปซไม่ได้รับการยกเว้น ส่วนเจ้าของเซิร์ฟเวอร์ได้รับการยกเว้น เพราะ checkout อยู่บนเครื่องของเขา รีโปที่ไม่มี remote ของ forge ต้องใช้แค่สิทธิ์เท่านั้น

- เมื่อแอดมินให้สิทธิ์รีโปแก่คนที่บัญชี forge ของเขาอ่านรีโปนั้นไม่ได้ สิทธิ์จะถูกบันทึกไว้ และแอดมินจะเห็นคำเตือน
- เมื่อไม่สามารถติดต่อ forge เพื่อตรวจสอบได้ คำตอบคือไม่ ไม่มีการเดา คนนั้นจะเห็น "ยืนยันสิทธิ์เข้าถึง GitHub ของคุณไม่ได้ ลองอีกครั้ง" (พร้อมชื่อ forge ของเขา) และลองใหม่ภายหลัง
- Pull request และทุกอย่างที่สร้างจากมันทำตามกฎเดียวกัน

### การเปลี่ยนโค้ดต้องใช้สิทธิ์เขียน

สิทธิ์รีโปมีสามระดับ และแต่ละระดับรวมระดับก่อนหน้าไว้ด้วย:

- **read**: ดูไฟล์ ดิฟ และผลการค้นหาของรีโปได้ โดยบัญชี forge ของคุณเองก็ต้องอ่านได้ด้วย
- **review**: read บวกการอนุมัติ การขอแก้ไข และการกระทำรีวิวอื่น ๆ บน pull request ของรีโปนั้น
- **write**: review บวกการเปลี่ยนโค้ด และการขับเคลื่อนการรันเอเจนต์ที่เขียนลงรีโป การเปลี่ยนโค้ดครอบคลุมการบันทึกหรือย้อนไฟล์ในเอดิเตอร์ การซิงก์ worktree ให้ตรงกับ head ของ pull request การคอมมิตและพุช การเผยแพร่บรานช์ และการกระทำของสแตกที่ตัด เช็กเอาต์ หรือเผยแพร่ส่วนย่อย

ทุกการพุชที่ทำให้บุคคลหนึ่ง ไม่ว่าจะโดยตัวเขาเองหรือโดยการรันเอเจนต์ที่เขาขอ จะตรวจสอบสิทธิ์เขียนของเขาบนรีโปนั้น ณ เวลาที่พุช ไม่ว่าจะบน GitHub, GitLab หรือ Bitbucket การเผยแพร่สแตกจะตรวจทุกรีโปในสแตกก่อนจะพุชรีโปใดรีโปหนึ่ง

การปฏิเสธจะระบุสิทธิ์ที่ขาดไป หากไม่มีสิทธิ์อ่าน แอปจะแสดง "คุณไม่มีสิทธิ์อ่านรีโพสิทอรีนี้ ผู้ดูแลเวิร์กสเปซสามารถให้สิทธิ์ได้" หากมีสิทธิ์อ่านแต่ไม่มีสิทธิ์เขียน แอปจะแสดง "คุณอ่านรีโพสิทอรีนี้ได้ แต่เปลี่ยนแปลงไม่ได้ ผู้ดูแลเวิร์กสเปซสามารถให้สิทธิ์เขียนได้"

### สเปซตามรีโปของมัน

เนื้อหาที่เอเจนต์เขียนเกี่ยวกับโค้ดจะตามโค้ดนั้น เนื้อหาของสเปซ (ข้อความ ทรานสคริปต์และเอาต์พุตของเครื่องมือ ผลการค้นหา บันทึกการรัน รายการงาน กิจกรรม และการแจ้งเตือน) บรรจุโค้ดของรีโปที่มันทำงานด้วย สเปซจึงเปิดได้เฉพาะกับสมาชิกที่ถือสิทธิ์อ่านบน**ทุก**รีโปที่สเปซใช้ และที่บัญชี forge ของตนเองอ่านได้ ได้แก่รีโปที่เลือกไว้ให้สเปซ หรือรีโปทั้งหมดของเวิร์กสเปซเมื่อไม่มีการบันทึกการเลือกไว้ สเปซที่สร้างโดยไม่มีรีโปใดจะเปิดให้สมาชิกทุกคน

สเปซที่ใครบางคนเปิดไม่ได้จะไม่ถูกแสดงให้เขาเห็นที่ใดเลย รวมถึงการค้นหา บันทึกการรัน รายการงาน กิจกรรม และการแจ้งเตือน แอดมินเวิร์กสเปซถือสิทธิ์ทุกระดับแต่ไม่ได้รับการยกเว้นจากส่วนของ forge ส่วนเจ้าของเซิร์ฟเวอร์ได้รับการยกเว้น

สำหรับการสนทนาที่ทุกคนควรอ่านได้ ให้สร้างสเปซโดยไม่มีรีโป หรือมีเฉพาะรีโปที่ทุกคนอ่านได้

## เจ้าของเซิร์ฟเวอร์

บุคคลที่ตั้งค่าเซิร์ฟเวอร์คือ**เจ้าของ** เซิร์ฟเวอร์บันทึกเจ้าของไว้ครั้งเดียวตอนเริ่มครั้งแรก และไม่มีอะไรที่ส่งผ่านเครือข่ายเปลี่ยนแปลงสิ่งนั้น แอดมินเวิร์กสเปซหรือเจ้าของเวิร์กสเปซไม่ใช่เจ้าของเซิร์ฟเวอร์: ใครก็ได้รับเวิร์กสเปซได้ แต่เครื่องของเซิร์ฟเวอร์มีเจ้าของเพียงคนเดียว

**ไม่มีอะไรรันบนเครื่องของเซิร์ฟเวอร์เองนอกแซนด์บ็อกซ์ เว้นแต่เจ้าของเซิร์ฟเวอร์จะเริ่มมันหรืออนุมัติการรันบนโฮสต์ประเภทนั้น** โดยเฉพาะ มีเพียงเจ้าของเซิร์ฟเวอร์เท่านั้นที่สามารถ:

- สร้างเวิร์กสเปซ คนอื่นทุกคนจะเห็นหน้าจอที่ขอให้เจ้าของสร้างให้ หรือให้แอดมินเวิร์กสเปซเชิญ
- เปิดเชลล์ของโฮสต์ในเทอร์มินัลที่โฮสต์บนเซิร์ฟเวอร์ คนอื่นจะได้เทอร์มินัลในแซนด์บ็อกซ์ พร้อมขีดจำกัดของเอเจนต์ ในไดเรกทอรีของเวิร์กสเปซนั้นเอง
- เปิดเอดิเตอร์โค้ดที่ฝังอยู่ มันรันในฐานะผู้ใช้ของเซิร์ฟเวอร์ พร้อมเทอร์มินัล งาน และส่วนขยาย
- เปิด pull request หรือ worktree ของการสนทนาในเอดิเตอร์เนทีฟ เอดิเตอร์เริ่มบนหน้าจอของเซิร์ฟเวอร์ ในฐานะผู้ใช้ของเซิร์ฟเวอร์
- บันทึกหรืออนุมัตินิยาม[สภาพแวดล้อม](/th-TH/คู่มือ/วิธีทำ/สภาพแวดล้อม/)ที่รันอะไรก็ตามบนโฮสต์: การวางบนโฮสต์ การตรวจสอบที่รันคำสั่ง หรืองานจัดเตรียมหรือเก็บถาวร
- รันเอเจนต์บนเซิร์ฟเวอร์ที่เครื่องไม่มีแซนด์บ็อกซ์ การรันของคนอื่นจะถูกปฏิเสธที่นั่น เว้นแต่เจ้าของเริ่มเซิร์ฟเวอร์ด้วย `--sandbox off` ซึ่งรันเอเจนต์ของสมาชิกทุกคนโดยไม่มีการจำกัดขอบเขต (ดู[เอเจนต์บนโฮสต์ที่ไม่มีแซนด์บ็อกซ์](/th-TH/คู่มือ/แนวคิด/แซนด์บ็อกซ์และความปลอดภัย/#เอเจนต์บนโฮสต์ที่ไม่มีแซนด์บ็อกซ์))
- เชื่อมโยง checkout ของรีโปที่อยู่นอกพื้นที่จัดเก็บของเวิร์กสเปซ ยืนยันการเชื่อมโยงที่ทำไว้ก่อนกฎนั้น และเรียกดูโฟลเดอร์ของเซิร์ฟเวอร์เมื่อเพิ่มรีโป (ดู[เพิ่มรีโป](/th-TH/คู่มือ/วิธีทำ/เพิ่มรีโป/))
- เห็นและหยุดโปรเซสเอเจนต์ที่กำลังรันทุกตัวบนเซิร์ฟเวอร์ คนอื่นเห็นและหยุดได้เฉพาะการรันเอเจนต์สดในเวิร์กสเปซที่ตนเป็นสมาชิก
- ให้เอเจนต์ใช้เซิร์ฟเวอร์ MCP ส่วนตัว ได้แก่ที่ตั้งค่าไว้ในเครื่องมือของผู้ใช้เซิร์ฟเวอร์เอง (Claude, Codex, Cursor และอื่น ๆ) และที่เจ้าของเพิ่มเข้ามา มีเพียงการรันที่เจ้าของรับผิดชอบเท่านั้นที่ได้รับ (ดู[เซิร์ฟเวอร์ส่วนตัว](/th-TH/คู่มือ/วิธีทำ/เซิร์ฟเวอร์-mcp/#เซิร์ฟเวอร์ส่วนตัว))
- อนุมัติเซิร์ฟเวอร์ MCP ของเวิร์กสเปซที่รันคำสั่งบนเครื่องของเซิร์ฟเวอร์ หรือเข้าถึงเครือข่ายส่วนตัวของมัน (ดู[เซิร์ฟเวอร์ของเวิร์กสเปซ](/th-TH/คู่มือ/วิธีทำ/เซิร์ฟเวอร์-mcp/#เซิร์ฟเวอร์ของเวิร์กสเปซ))
- ยืนยันอีเมลของใครบางคน เพื่อให้การลงชื่อเข้าใช้ครั้งเดียวจับคู่กับมันได้ (ดู[เชื่อมต่อผู้ให้บริการ OpenID Connect](/th-TH/คู่มือ/วิธีทำ/sso-oidc/#การลงชื่อเข้าใช้จับคู่กับบัญชีที่มีอยู่อย่างไร))
- เปลี่ยนการตั้งค่าทั้งการติดตั้ง: SSO ข้อมูลรับรองของผู้ให้บริการ เอนด์พอยต์ MCP และโทเค็นของมัน การจัดการโมเดล Connect และการสำรองข้อมูลทั้งการติดตั้ง การดำเนินการเหล่านี้ประกาศ**อำนาจของเซิร์ฟเวอร์** และถูกปฏิเสธสำหรับทุกคนอื่น

มีตัวตนของผู้ดำเนินการเพียงหนึ่งเดียวโดยเจตนา และมีนิยามของมันเพียงหนึ่งเดียว

## ร่องรอยการตรวจสอบ

การตัดสินด้านการอนุญาตทุกครั้ง — **ทั้งการอนุญาตและการปฏิเสธ** — ถูกต่อท้ายลงในร่องรอยการตรวจสอบแบบผูกด้วยแฮชของแต่ละเวิร์กสเปซ

ล็อกที่บันทึกแต่การปฏิเสธตอบได้แค่ว่า “เราบล็อกอะไรไปบ้าง?” แต่ตอบไม่ได้ว่า “เอเจนต์นี้ทำอะไรไปจริง ๆ และใครอนุญาต?” ซึ่งเป็นคำถามตั้งต้นของการทบทวนเหตุการณ์ ดังนั้นแต่ละรายการจึงบันทึกสายการอ้างอิงที่มาที่ไปอย่างครบถ้วน: ตัวตนผู้ลงมือ, มนุษย์ที่มันลงมือแทน, การมอบอำนาจที่ทำให้มันเข้ามา, การกระทำและอาร์กิวเมนต์ของมัน (ในรูปไดเจสต์), การตัดสิน และ**กฎที่ใช้ตัดสิน**

รายการต่าง ๆ ถูกต่อเป็นโซ่: แฮชของแต่ละรายการครอบคลุมแฮชของรายการก่อนหน้า การแก้ไข ลบ หรือสลับลำดับแถวใด ๆ จึงทำให้แฮชทุกตัวหลังจากนั้นขาด **ตรวจสอบโซ่**จะคำนวณใหม่ทั้งชุดและระบุจุดเชื่อมแรกที่ไม่ผ่าน ล็อกตรวจสอบที่คุณตรวจสอบไม่ได้ก็เป็นแค่ล็อก แต่ล็อกที่คำนวณซ้ำได้คือหลักฐาน

ผลที่ตามมาสองข้อที่ควรรู้:

- ตารางตรวจสอบ**ได้รับการยกเว้นจากการตัดทิ้งตามอายุ** โซ่แฮชตัดออกจากตรงกลางไม่ได้ การเก็บรักษาคือนำออกก่อนแล้วจึงตัดทอน และการตัดทอนจะทิ้งจุดตรวจที่พกแฮชปลายทางของช่วงที่ถูกนำออกไว้ ทำให้ส่วนที่เหลือยังตรวจสอบย้อนกลับไปถึงต้นทางได้
- มันวางอยู่**เคียงข้าง**ไทม์ไลน์กิจกรรม ไม่ได้ทับซ้อนอยู่บนนั้น ไทม์ไลน์คือสิ่งที่คนทำ ส่วนนี่คือสิ่งที่ถูกอนุญาตและถูกปฏิเสธ correlation id ที่ใช้ร่วมกันทำให้อ่านการเรียกหนึ่งครั้งได้จากทั้งสองที่

มันส่งออกเป็น JSON ที่คั่นด้วยบรรทัดใหม่ และสตรีมไปยัง SIEM ได้ (Splunk, Elastic, Sentinel — ปลายทาง HTTP พร้อม bearer token) โดยเจตนาออกแบบให้การสตรีมเป็นแบบพยายามให้ได้มากที่สุด: SIEM ล่มต้องไม่บล็อกการเรียกเครื่องมือของเอเจนต์ไม่ว่ากรณีใด และสำเนาถาวรที่ตรวจสอบได้ก็อยู่บนดิสก์อยู่แล้วทั้งสองทาง

## เซสชัน

การติดตั้งหนึ่งแห่งกำหนด**อายุเซสชันสูงสุด**และ**เวลาหมดอายุเมื่อไม่ใช้งาน**ได้ ทั้งสองอย่างถูกบังคับใช้ที่จุดตรวจข้อมูลรับรองอุปกรณ์ ซึ่งทุกช่องทางที่ผ่านการยืนยันตัวตนต้องผ่านจุดนี้ — ขอบเขตเซสชันที่ไคลเอนต์เพิกเฉยได้นั้นตอบได้แค่แบบสอบถาม ไม่ได้ตอบโจมตี การติดตั้งยังบังคับให้ใช้ SSO ได้ด้วย ซึ่งจะปิดการจับคู่ด้วยตนเองสำหรับอุปกรณ์ใหม่ (พร้อมการกันการล็อกเอาต์: มันจะปฏิเสธตราบใดที่ยังไม่มีการเชื่อมต่อ SSO ที่ใช้งานได้)

## สิ่งที่หน้านี้ไม่ใช่

- **ไม่ใช่ ACL ระดับวัตถุ** โดยเจตนาแล้วไม่มีสิทธิ์ระดับตั๋วงานหรือระดับข้อความ การแยกระดับรีโปคือสิ่งที่ทีมขอมาจริง และมีอยู่แล้ว ส่วนการแชร์ระดับวัตถุเป็นพื้นผิวที่ต้องจัดการชุดค่าผสมมากมายโดยยังไม่มีความต้องการที่พิสูจน์ได้ในที่นี้
- **ไม่ใช่เอนจินนโยบายที่คุณกำหนดค่าด้วย DSL** คำศัพท์ถูกปิดไว้โดยเจตนา นโยบายทั้งหมดจึงแสดงผล อธิบาย และแจกแจงได้
- **ไม่ถูกบังคับใช้ที่ใดนอกจากเซิร์ฟเวอร์** การตรวจสอบฝั่งไคลเอนต์มีอยู่เพียงเพื่อไม่ให้เสนอตัวควบคุมที่จะถูกปฏิเสธ การตัดสินที่มีผลชี้ขาดเป็นของเซิร์ฟเวอร์เสมอ
