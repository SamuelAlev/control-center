These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/th-TH/คู่มือ/วิธีทำ/); when you want to look
something up, go to the [reference](/th-TH/คู่มือ/อ้างอิง/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/th-TH/คู่มือ/แนวคิด/เวิร์กสเปซ/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/th-TH/คู่มือ/แนวคิด/โมเดลเอเจนต์/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/th-TH/คู่มือ/แนวคิด/วงจรชีวิตการสั่งงาน/) — what happens between your message and the agent's first token
- [Modes](/th-TH/คู่มือ/แนวคิด/โหมด/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/th-TH/คู่มือ/แนวคิด/บริบทเครื่องมือ/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/th-TH/คู่มือ/แนวคิด/ความฉลาดของโค้ด/) — the code graph, language server, structural search and debugger
- [Conversation history](/th-TH/คู่มือ/แนวคิด/ประวัติการสนทนา/) — persistence, compaction and forking a transcript

## Safety and control

What an agent is allowed to touch and who decides.

- [Sandbox and security](/th-TH/คู่มือ/แนวคิด/แซนด์บ็อกซ์และความปลอดภัย/) — what actually constrains an agent run today
- [Guardrails](/th-TH/คู่มือ/แนวคิด/กฎคุม/) — one policy engine for every mutating action and how a rule is resolved
- [Authorization](/th-TH/คู่มือ/แนวคิด/การอนุญาต/) — roles, the permission catalog and the audit trail
- [Rigs and enclosures](/th-TH/คู่มือ/แนวคิด/ริก/) — why agents get disposable VMs instead of your machine, and what the boundary actually is
