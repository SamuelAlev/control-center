pull request เป็นที่ที่บทสนทนาเกี่ยวกับโค้ดเกิดขึ้นอยู่แล้ว การสนทนาบน PR ทำให้มัน
กลายเป็นพื้นผิวหนึ่งบนเวิร์กสเปซของ Control Center เช่นเดียวกับที่
[สะพานแชท](/th-TH/คู่มือ/แนวคิด/สะพานแชท/)ทำให้ Slack เป็นพื้นผิวแบบนั้น: @mention
`@usectrl` บน PR ตอบกลับในเธรดรีวิวของมัน หรือเพิ่มป้ายกำกับ
`ai-review` แล้วงานก็จะเกิดขึ้นในสเปซรีวิวของ PR — ภายใต้การระบุที่มาและกฎคุม
ชุดเดียวกับทุกอย่างที่พิมพ์ในแอป ความคิดเห็นและป้ายกำกับถูกกั้นด้วยวิธีเดียวกัน: ขึ้นอยู่กับสมาชิกที่เขียนหรือเพิ่มมัน
คำตอบของบอตกลับไปบน GitHub ในช่องทางที่คำถามถูกถาม

การตัดสินใจสามข้อกำหนดรูปร่างของฟีเจอร์นี้ และแต่ละข้อก็คือการตัดสินใจเดียวกับที่
สะพานแชททำไว้สำหรับแชท เพียงพูดซ้ำให้เข้ากับโฮสต์โค้ด: **การเชื่อมต่อวิ่งไป
ทิศทางไหน** **อะไรให้สิทธิ์กับความคิดเห็นที่มาจากภายนอก** และ **แต่ละฝ่ายถูกระบุ
ที่มาให้ใคร**

## การโพลล์คือช่องทางขนส่ง

ช่องทางพุชเดียวของ GitHub สำหรับแอปคือ webhook และ webhook ต้องมี URL ขาเข้า —
ซึ่งเป็นสิ่งเดียวที่พื้นผิวนี้จงใจไม่ต้องใช้เลย การค้นหาจึงเป็นการกวาด: การค้นหาแบบใช้ alias
หนึ่งครั้งต่อการติดตั้งแอปแต่ละรายการจะถาม GitHub ขอ PR ที่กล่าวถึง `@usectrl`
และขอ PR ที่เปิดอยู่ซึ่งมีป้ายกำกับรีวิว ส่วน PR ที่มีสเปซรีวิวอยู่แล้วจะถูกอ่านเธรดความคิดเห็น
และทุกอย่างจะถูก diff ด้วย id ของความคิดเห็นเทียบกับสิ่งที่เห็นในการกวาดครั้งก่อน
แอปของตัวเองกวาดทุกนาทีบน PR ไม่เกิน 25 รายการ เมื่อผ่าน Connect การเรียกใช้โควต้า GitHub
ของสมาชิกแต่ละคนเอง การกวาดจึงทำงานทุกสองนาทีบน PR ไม่เกิน 10 รายการ และเวิร์กสเปซที่โควต้า
ต่ำกว่า 15% จะถูกข้ามจนกว่าจะฟื้นตัว Connect เองไม่เคยเห็นเนื้อหาของ PR

ผลที่ตามมาของการออกแบบนี้ควรค่าแก่การระบุให้ชัด:

- **ความหน่วงคือช่วงเวลาของการกวาด ไม่ใช่เหตุการณ์** การตอบรับด้วย 👀 จะมาถึง
  ภายในหนึ่งรอบการกวาด ไม่มีอะไรเร่งด่วนที่ต้องพึ่งมัน
- **ครั้งเดียวเท่านั้น ต่อความคิดเห็น** id ของความคิดเห็นไม่ซ้ำกันทั่ว GitHub
  แต่ละอันถูกบันทึกทันทีที่ถูกจัดว่าเข้าเกณฑ์ ก่อนที่สิ่งใดจะลงมือกับมัน
  การแครชอาจทำให้การจัดการความคิดเห็นหนึ่งหายไป แต่จะไม่ยิงซ้ำสองครั้ง
- **ช่วงที่ออฟไลน์ถูกตามเก็บให้ครบ ไม่ใช่เล่นซ้ำ** เซตของสิ่งที่เห็นแล้วถูกเก็บ
  ถาวร การรีสตาร์ตจึงส่งสิ่งที่มาถึงระหว่างที่ระบบล่มได้ ข้อยกเว้นเดียวคือ
  การกวาดครั้งแรกสุด: เมื่อไม่มีความจำให้ diff ทุกอย่างที่ค้างอยู่จะถูกบันทึก
  อย่างเงียบ ๆ — ผู้ดูแลที่ติดป้ายกำกับให้ PR ยี่สิบรายการก่อนเซิร์ฟเวอร์นี้จะ
  มีอยู่ ต้องไม่กลับมาเจอรีวิวยี่สิบรายการที่กำลังรันอยู่
- **ป้ายกำกับคือเซต ไม่ใช่เหตุการณ์** การค้นหารายงานการ _มีอยู่_ ของป้ายกำกับ
  PR ที่ติดป้ายจึงทริกเกอร์เพียงครั้งเดียวตลอดไป การเพิ่มป้ายกลับหลังลบออก
  จะมองไม่เห็นจากการกวาด การกล่าวถึงคือเส้นทางรันซ้ำ

การค้นหาทำงานครั้งเดียวต่อบัญชีการติดตั้ง บนไคลเอนต์ของเจ้าของรายนั้น เพราะ
โทเค็นการติดตั้งเห็นเฉพาะรีโพของการติดตั้งตัวเองเท่านั้น ข้อมูลรับรองชุดเดียวที่ใช้
ทั่วทั้งเซิร์ฟเวอร์จะพลาด PR ทุกอันภายใต้การติดตั้งอื่น ๆ ของแอปอย่างเงียบ ๆ

## สมาชิกภาพเป็นตัวให้สิทธิ์ ไม่ใช่ความคิดเห็น

ความคิดเห็นบน PR มาถึงโดยพาตัวผู้เขียนมาด้วย — ตัวตนภายนอกที่ยังไม่ผ่านการยืนยันจนกว่าจะพิสูจน์ได้
เซิร์ฟเวอร์จะแปลงตัวเลข ID บัญชี GitHub ที่ไม่เปลี่ยนแปลง (ไม่ใช่ login ที่เปลี่ยนชื่อได้และนำกลับมาใช้ใหม่ได้)
เทียบกับการลงชื่อเข้าใช้ GitHub ของสมาชิกในเวิร์กสเปซ ดัชนีนี้สร้างใหม่ตาม TTL เพราะมีคน
ลงชื่อเข้าใช้และได้รับเชิญระหว่างที่เซิร์ฟเวอร์ทำงาน สำหรับป้ายกำกับ `ai-review` สมาชิกที่ถูกระบุคือผู้ที่เพิ่มมันล่าสุด

การตรวจสามขั้นตามลำดับ และหากไม่ผ่านข้อใดข้อหนึ่งจะเป็นการเงียบ — ไม่มีการโพสต์อะไร:

- **สมาชิกที่ลงชื่อเข้าใช้แล้ว** บัญชีนั้นต้องเป็นสมาชิกของเวิร์กสเปซ _นี้_ และลงชื่อเข้าใช้ GitHub บนเซิร์ฟเวอร์นี้
- **บทบาทที่เขียนได้** `viewer` และ `guest` ไม่สามารถเริ่มงานได้
- **สิทธิ์การพุช** การตอบกลับใช้โทเค็นสำหรับรีโพสิทอรีนั้นเพียงหนึ่งเดียว จำกัดตามสิทธิ์การเข้าถึงของสมาชิกคนนั้นต่อรีโพสิทอรีนั้น หากเซิร์ฟเวอร์ออกโทเค็นนี้ไม่ได้ จะไม่ดำเนินการต่อ

ทุกการตรวจจะทำงานก่อนการตอบรับใด ๆ ดังนั้นคนแปลกหน้าจะไม่ได้รับปฏิกิริยาหรือคำตอบ
ความคิดเห็นจะไม่ถูกระบุที่มาให้ใครที่ไม่ได้ส่งมัน และถ้อยคำของคนนอกจะไม่มีทางเข้าไปในเวิร์กสเปซที่พวกเขามองไม่เห็น

### การจอง

งานสุดท้ายก่อนการทำงานใด ๆ คือปฏิกิริยา 👀 ที่เพิ่มด้วยการลงชื่อเข้าใช้ GitHub ของผู้เขียนเอง
GitHub ตอบ `201` สำหรับปฏิกิริยาใหม่ และ `200` สำหรับปฏิกิริยาที่มีอยู่แล้ว ดังนั้นปฏิกิริยานี้ทำหน้าที่เป็นตัวล็อกด้วย:
เมื่อบุคคลเดียวกันลงชื่อเข้าใช้บนเซิร์ฟเวอร์สองเครื่องที่เชื่อมรีโปนี้ มีเพียงเครื่องที่กดก่อนเท่านั้นที่ทำงาน
ความคิดเห็นที่หลายเวิร์กสเปซบนเซิร์ฟเวอร์เดียวกันมองเห็นจะถูกเสนอให้แต่ละเวิร์กสเปซ และการจองเดียวกันเป็นตัวตัดสิน

## สองตัวตน โดยเจตนา

แต่ละฝ่ายของการสนทนาถือตัวตนที่ต่างกัน และความต่างนั้นคือตัวฟีเจอร์เอง:

- **บน GitHub การตอบกลับคือระบบอัตโนมัติที่ทำแทนคุณ** ทุกการตอบกลับใช้โทเค็นสำหรับรีโพสิทอรีเดียว
  จำกัดตามสิทธิ์การเข้าถึงของสมาชิกที่ถาม และลงชื่อโดยบัญชี `[bot]` ของแอป มีข้อยกเว้นหนึ่ง: บนแอป Control Center Connect ที่ใช้ร่วมกัน
  บอตจะโพสต์ในเธรดรีวิวก็ต่อเมื่อผู้ดำเนินการ Connect ได้ระบุการติดตั้งนั้นไว้ มิฉะนั้นการตอบกลับภายในเธรดรีวิวจะลงชื่อโดยบัญชีของสมาชิกที่ถามเอง
  ไม่ว่าทางใด ทุกการตอบกลับจะขึ้นต้นด้วย `**Control Center** (for @login):` ซึ่งบอกว่าใครเป็นผู้ถาม และยังทำหน้าที่เป็นตัวกันการวนซ้ำด้วย การกล่าวถึง @ ในข้อความของเอเจนต์จะถูกทำให้ไม่มีผล เพื่อให้การตอบกลับไม่แจ้งผู้ใช้หรือทีมใด
- **ในสเปซ คำถามเป็นของคุณ** ข้อความถูกระบุที่มาให้สมาชิกที่ผู้เขียนเทียบได้ และ
  การรันเอเจนต์ทำงานในนามของสมาชิกคนนั้น: คอมมิตของการรันเป็นของพวกเขา และ
  ปุ่มปรับความเป็นอิสระกับกฎคุมการกระทำของสเปซจะใช้เหมือนกับข้อความที่พิมพ์ในแอป
  ทุกประการ การเขียนไปยังโฮสต์โค้ดจากการรันใช้โทเค็นที่จำกัดเฉพาะรีโปนั้นและถูกผูกกับสมาชิกคนนั้น
  ไม่ใช่การลงชื่อเข้าใช้ของเขาที่ส่งต่อทั้งชุด

การเผยแพร่ข้อค้นพบจากรีวิวกลับไปยัง GitHub ยังเป็นการตัดสินใจของคน ซึ่งทำใน
Control Center การกล่าวถึงสามารถ _เริ่ม_ รีวิวได้ มีเพียงมนุษย์เท่านั้นที่เผยแพร่มัน

## ตัวกันการวนซ้ำ

ทุกอย่างที่เขียนโดยบัญชีบอตจะถูกทิ้งก่อนที่ประตูใด ๆ จะทำงาน — ทั้งของเราโดยเฉพาะ
และทุกส่วนต่อท้าย `[bot]` บอตรีวิวของแอปอื่นจึงปลุกของเราไม่ได้เช่นกัน และความคิดเห็นทุกอันที่ขึ้นต้นด้วยคำนำหน้า
`**Control Center** (for @` ก็ถูกทิ้งเช่นกัน เพราะการตอบกลับในเธรดรีวิวผ่าน Connect อาจลงชื่อโดยบัญชีของบุคคล
หากไม่มีสิ่งนี้ คำตอบจะมาถึงในฐานะความคิดเห็นใหม่และทริกเกอร์สะพานซ้ำไม่รู้จบ

มีเพียง `@usectrl` เท่านั้นที่เริ่มงานได้ login ของ App เอง (`<slug>[bot]`) และ slug เปล่า ๆ ของมันไม่ได้ส่งถึงใคร: GitHub ไม่มี autocomplete ให้บัญชีแอป และ slug เปล่า ๆ อาจเป็นของผู้ใช้ที่เป็นมนุษย์ได้

## สิ่งที่จงใจไม่เสนอให้

- **ไม่มีการเผยแพร่อัตโนมัติ** ข้อค้นพบไปอยู่ในสเปซรีวิว การเผยแพร่ไปยัง GitHub
  เป็นการกระทำของมนุษย์ที่แยกต่างหาก
- **ไม่มีการเดาตัวตน** ผู้เขียนจะถูกเทียบได้กับสมาชิกหนึ่งคนเท่านั้น มิฉะนั้นจะถูกละเว้น — ไม่มีการระบุที่มาแบบคาดเดา
- **ไม่มีการอนุมัติอัตโนมัติ** ระบบอัตโนมัติสามารถแสดงความคิดเห็นและขอให้แก้ไขได้ แต่รีวิว `APPROVE` จะถูกปฏิเสธก่อนส่ง การอนุมัติเป็นการกระทำของคน
- **ไม่มี webhook ของ GitHub App** พื้นผิวนี้ไม่เคยลงทะเบียนมัน จึงไม่มี URL ขาเข้า
  ที่ต้องเปิดเผยสำหรับความคิดเห็นบน PR webhook อื่น ๆ ของผลิตภัณฑ์ (ไปป์ไลน์
  การซิงค์ตั๋วงาน) เป็นการตั้งค่าแยกต่างหากและเป็นทางเลือก
