Control Center เชื่อมต่อกับ Google Calendar เพื่อให้วันของคุณอยู่เคียงข้างฟลีต
มันซิงค์เหตุการณ์ของคุณ แสดงในมุมมองเดือน สัปดาห์ วัน และวาระ ให้คุณสร้าง ย้าย ตอบรับ และลบเหตุการณ์ได้ เตือนคุณก่อนการ
ประชุมจะเริ่ม และเปลี่ยนเหตุการณ์ใดก็ได้ให้เป็น[การประชุม](/th-TH/คู่มือ/แนวคิด/การประชุม/)
ที่บันทึกและสรุปไว้แล้ว

## มันเปลี่ยนอะไรบน Google

เฉพาะสิ่งที่คุณทำเองเท่านั้น คุณตอบรับคำเชิญ สร้างกิจกรรม (ลากข้ามกริดเวลาหรือใช้ปุ่ม **+**) และลบกิจกรรมได้ แต่ละการเปลี่ยนแปลงทำโดยเซิร์ฟเวอร์ ด้วยการลงชื่อเข้าใช้ของบัญชีคุณเอง ในปฏิทินของคุณเอง และเซิร์ฟเวอร์จะปฏิเสธกิจกรรมในบัญชีของสมาชิกคนอื่น หรือในปฏิทินที่แชร์ให้คุณแบบอ่านอย่างเดียว Google จะส่งอีเมลถึงแขก เหมือนที่ทำจาก Google Calendar การลบหนึ่งครั้งของกิจกรรมที่เกิดซ้ำจะไม่ลบซีรีส์ที่เหลือ คุณย้ายหรือยืดกิจกรรมบนกริดได้; เฉพาะกิจกรรมของคุณเองและที่คุณเป็นผู้จัดเท่านั้นที่ถูกย้าย

ทุกการเชื่อมต่อ ไม่ว่าจะผ่าน Connect หรือไคลเอนต์ Google ของเซิร์ฟเวอร์เอง จะขอ `calendar.events` (อ่านและเปลี่ยนแปลงกิจกรรม) และ `calendar.calendarlist.readonly` (ดูว่าบัญชีมีปฏิทินอะไรบ้าง) พร้อม `openid email` เซิร์ฟเวอร์จะปฏิเสธการลงชื่อเข้าใช้ที่ส่งกลับชุดสโคปที่ต่างออกไป ดังนั้นบัญชีที่เชื่อมต่อด้วยสโคปแบบอ่านอย่างเดียวรุ่นก่อนต้องเชื่อมต่อใหม่

เหตุการณ์ถูกซิงค์เข้าฐานข้อมูลของเวิร์กสเปซเอง **บนเซิร์ฟเวอร์**
(`<dataDir>/<workspaceId>/workspace.db`) และแสดงผลโดยไคลเอนต์ทุกตัวผ่าน RPC
ไม่มีไคลเอนต์ใดถือข้อมูลรับรองของ Google

## บัญชีแยกตามเวิร์กสเปซ

บัญชีปฏิทินผูกกับเวิร์กสเปซ เหมือนทุกอย่างอื่นใน Control Center และแต่ละบัญชีเป็นของสมาชิกที่เชื่อมต่อ
[เวิร์กสเปซ](/th-TH/คู่มือ/แนวคิด/เวิร์กสเปซ/)แต่ละแห่งเชื่อมบัญชี Google ของตัวเอง
(หรือหลายบัญชี) และเหตุการณ์กับข้อมูลรับรองของเวิร์กสเปซหนึ่งจะไม่ปรากฏให้เห็นจาก
อีกเวิร์กสเปซเลย สมาชิกสองคนที่เชื่อมที่อยู่ Google เดียวกันจะได้สองบัญชี การสลับเวิร์กสเปซจึงสลับว่าคุณเห็นปฏิทินใด

เวิร์กสเปซหนึ่งเชื่อมบัญชี Google ได้**หลายบัญชี** เช่นบัญชีที่ทำงานและ
บัญชีส่วนตัว โดยเหตุการณ์ของทั้งหมดถูกรวมเข้าด้วยกันในมุมมองเดียวกัน

## การลงชื่อเข้าใช้ไปถึงเซิร์ฟเวอร์อย่างไร

การเชื่อมต่อคือการลงชื่อเข้าใช้ผ่านเบราว์เซอร์ และเซิร์ฟเวอร์เป็นผู้ทำให้เสร็จ ว่าไคลเอนต์ใดเป็นผู้ดำเนินการนั้นขึ้นอยู่กับการเลือกของเจ้าของเซิร์ฟเวอร์:

- **ไคลเอนต์ Google ของเซิร์ฟเวอร์เอง** เป็นไคลเอนต์แบบ Web application ที่ลงทะเบียน redirect เป็น `<server origin>/oauth/google/callback` Google จะส่งเบราว์เซอร์กลับไปยังเซิร์ฟเวอร์โดยตรง ดังนั้นเบราว์เซอร์ต้องเข้าถึงเซิร์ฟเวอร์ได้
- **Control Center Connect** Google จะส่งเบราว์เซอร์กลับไปยัง Connect ซึ่งจะแสดงรหัสแปดตัวอักษรและลิงก์ `control-center://` ผู้ใช้พิมพ์รหัสลงในแอป หรือเปิดลิงก์ เซิร์ฟเวอร์จะใช้รหัสนั้นยืนยันการลงชื่อเข้าใช้ การทำเช่นนี้ไม่ต้องให้เซิร์ฟเวอร์มีที่อยู่สาธารณะ ซึ่งเป็นเหตุผลที่เซิร์ฟเวอร์แบบไม่มีส่วนติดต่อบนเครือข่ายส่วนตัวสามารถเชื่อมปฏิทินได้

ไคลเอนต์ของตัวเองจะมีความสำคัญเหนือกว่าเสมอ หากมี client id แต่ไม่มี secret ถือว่าการตั้งค่ายังไม่เสร็จ และจะปฏิเสธการลงชื่อเข้าใช้ แทนที่จะย้อนไปใช้ Connect

ข้อมูลรับรองไม่เคยออกจากเซิร์ฟเวอร์ ข้อมูลถูกเขียนลง `secrets.json` ในไดเรกทอรีข้อมูลของเซิร์ฟเวอร์ โดยใช้คีย์ `google_google:<workspaceId>:<userId>:<email>` อยู่ร่วมกับฐานข้อมูลและอยู่ภายใต้ขอบเขตความเชื่อถือของระบบไฟล์โฮสต์เดียวกัน การลงชื่อเข้าใช้ด้วยไคลเอนต์ของตัวเองจะเก็บทั้งโทเค็นการเข้าถึงและโทเค็นรีเฟรช ส่วนการลงชื่อเข้าใช้ผ่าน Connect จะเก็บเฉพาะข้อมูลรับรองที่ปิดผนึกไว้ซึ่ง Connect เท่านั้นที่เปิดให้เซิร์ฟเวอร์นี้ได้ โทเค็นการเข้าถึงจะอยู่ในหน่วยความจำเท่านั้น เซิร์ฟเวอร์รีเฟรชการเข้าถึงให้อัตโนมัติ และเมื่อ Google ทำให้บัญชีใช้ไม่ได้อย่างถาวร (เซสชันถูกเพิกถอนหรือหมดอายุไปนานแล้ว) เซิร์ฟเวอร์จะเผยแพร่ `CalendarAuthExpired` และแสดงแบนเนอร์ **เชื่อมต่ออีกครั้ง** แทนที่จะล้มเหลวอย่างเงียบ ๆ การลงชื่อเข้าใช้ที่เซิร์ฟเวอร์นี้ใช้ไม่ได้อีกต่อไป (ออกโดยไคลเอนต์ของตัวเองอีกตัว หรือถูกปิดผนึกไว้สำหรับการติดตั้งหรือ Connect อื่น) จะถูกลบในการอ่านครั้งถัดไป และแสดงแบนเนอร์เดียวกัน

ไม่มีบิลด์ใดแนบข้อมูลรับรองของ Google มาด้วย ไคลเอนต์ของเซิร์ฟเวอร์มาจาก **การตั้งค่า → เซิร์ฟเวอร์ → ลงชื่อเข้าใช้ครั้งเดียว → แอปผู้ให้บริการ** หรือไฟล์ `.env` ของเซิร์ฟเวอร์ (`GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET`) จงใจไม่มีแฟล็กบรรทัดคำสั่ง เพราะ secret บนบรรทัดคำสั่งอ่านได้ผ่าน `ps` และเซิร์ฟเวอร์จะปฏิเสธการเริ่มทำงานเมื่อ secret ถูกส่งออกไปยังสภาพแวดล้อมของโปรเซส

หากต้องการรันโปรเจกต์ Google ของคุณเอง ดู
[เชื่อมต่อ Google Calendar](/th-TH/คู่มือ/วิธีทำ/เชื่อมต่อปฏิทิน/)

## การซิงค์

เซิร์ฟเวอร์ดึงหน้าต่างแบบเลื่อนของเหตุการณ์จากแต่ละบัญชีที่เชื่อมไว้ — ทุกปฏิทิน
ในบัญชี ไม่ใช่แค่ปฏิทินหลัก — **ทุกสองนาที** และดึงตามต้องการด้วย (ตอนเริ่มทำงาน
ตอนเชื่อมต่อ รีเฟรชเอง) รอบที่ถี่ขนาดนี้ทำได้เพราะการกวาดเป็นแบบเพิ่มพูน
ปฏิทินแต่ละอันมีโทเค็นซิงค์ของตัวเอง ปฏิทินที่ไม่มีการจึงเสียเพียงการตอบกลับที่
เกือบว่างเปล่าหนึ่งครั้ง แทนที่จะดึงหน้าต่างห้าเดือนซ้ำ

เหตุการณ์ที่เกิดซ้ำถูกคลี่ออกฝั่งเซิร์ฟเวอร์ ไคลเอนต์จึงไม่ต้องตีความกฎ
การเกิดซ้ำเลย การไปยังเดือนที่อยู่นอกหน้าต่างปัจจุบันจะโหลดช่วงนั้นแบบ lazy
เหตุการณ์ที่ถูกลบหรือถูกย้ายออกนอกช่วงจะถูกปรับปรุงให้ตรงกันในรอบซิงค์ถัดไป

## มุมมอง

| มุมมอง    | สิ่งที่แสดง                                          |
| --------- | --------------------------------------------------- |
| **เดือน** | ตารางเต็มเดือน (ขับเคลื่อนด้วยแพ็กเกจ `kalender`) |
| **สัปดาห์** | เหตุการณ์ที่มีเวลาของหนึ่งสัปดาห์ในตารางเวลา       |
| **วัน**    | เหตุการณ์ที่มีเวลาของวันเดียวในตารางเวลา           |
| **วาระ**   | รายการเหตุการณ์ที่กำลังจะมาถึงแบบเลื่อนได้          |

เปิดปฏิทินได้ที่ `/calendar` ส่วนการเลือกเหตุการณ์จะเปิดรายละเอียดที่
`/calendar/:eventId` มุมมองที่คุณเลือกถูกเก็บไว้ในการตั้งค่าของไคลเอนต์ตัวนั้นเอง
จึงไม่ตามคุณไปยังอุปกรณ์อื่น

## การแจ้งเตือนการประชุม

ตัวจัดตารางทำงานทุกนาทีเพื่อสแกนหาเหตุการณ์ที่จะเริ่มภายในช่วงเวลาล่วงหน้าที่ ตั้งค่าได้ แล้วยิงการแจ้งเตือน **"การประชุมกำลังจะเริ่ม"** (เป็น [เหตุการณ์โดเมน](/th-TH/คู่มือ/แนวคิด/เหตุการณ์โดเมน/) `MeetingStartingSoon`) การแจ้งเตือนจะพา URL เข้าร่วมมาด้วยเมื่อมี และการคลิกจะเปิดรายละเอียดของเหตุการณ์ ปุ่มของการแจ้งเตือนนี้ ทั้งในแบนเนอร์ของแอปและการแจ้งเตือนของระบบปฏิบัติการ คือ **เข้าร่วมการประชุม** และ **เข้าร่วมและบันทึก** ซึ่งเปิดการโทรได้โดยไม่ต้องเปิดเหตุการณ์ก่อน เหตุการณ์ที่ไม่มีลิงก์การโทรจะแสดง **บันทึกการประชุม** แทน การแจ้งเตือนถูกตัดรายการซ้ำโดยเทียบกับ `alertedAt` ของเหตุการณ์ การประชุมเดียวกัน จึงไม่แจ้งเตือนซ้ำ แม้จะข้ามการรีสตาร์ต และเหตุการณ์ที่เวลาเริ่มผ่านไปแล้วตอนที่ แอปปิดอยู่จะไม่ถูกเล่นซ้ำ

มีสองขีดจำกัดที่พลาดได้ง่าย ตัวจัดตารางทำงาน **ฝั่งไคลเอนต์บนเดสก์ท็อป** และเฉพาะ
เวิร์กสเปซที่คุณเปิดอยู่เท่านั้น — เวิร์กสเปซที่คุณไม่ได้อยู่จะไม่แจ้งเตือนใดๆ
และบิลด์เว็บไม่มีไปป์ไลน์การแจ้งเตือนของระบบปฏิบัติการเลย จึงไม่แจ้งเตือนใดๆ เช่นกัน

## บันทึกและลิงก์

จากเหตุการณ์ในปฏิทิน คุณเริ่ม[การบันทึกการประชุม](/th-TH/คู่มือ/แนวคิด/การประชุม/)
ที่ตั้งต้นด้วยชื่อเหตุการณ์ได้ Control Center เก็บลิงก์แบบหนึ่งต่อหนึ่งระหว่าง
การบันทึกกับเหตุการณ์ บันทึกการประชุมและรายการในปฏิทินจึงเชื่อมกันอยู่
โดยที่ฟีเจอร์ใดไม่ต้องพึ่งพาอีกฟีเจอร์หนึ่ง

**เข้าร่วมและบันทึก** ใช้ได้เฉพาะเดสก์ท็อป บนไคลเอนต์เว็บ การกระทำนี้จะรายงานว่า
การบันทึกใช้งานไม่ได้ — แม้ว่ากระบวนการบันทึกของหน้าจอการประชุมเองจะทำงานได้ใน
เบราว์เซอร์

:::note[เอเจนต์อ่านปฏิทินของคุณไม่ได้]
ไม่มีเครื่องมือ MCP ด้านปฏิทิน เอเจนต์ไม่สามารถแสดงรายการเหตุการณ์ อ่าน
รายละเอียดเหตุการณ์ สร้าง ย้าย หรือลบเหตุการณ์ หรือตอบรับคำเชิญแทนคุณได้ พื้นผิว `calendar.*` เป็น RPC
สำหรับไคลเอนต์ที่เป็นมนุษย์เท่านั้น
:::
