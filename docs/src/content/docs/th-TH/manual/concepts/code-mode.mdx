เอเจนต์ปกติจะเรียกเครื่องมือของตนทีละอย่าง การเรียกแต่ละครั้งคือหนึ่งเทิร์นของโมเดล เอเจนต์ขอให้เรียก ผลลัพธ์ย้อนกลับเข้าสู่บริบทของมัน และเอเจนต์อ่านก่อนจะขอการเรียกถัดไป สำหรับงานที่ส่วนใหญ่เป็นงานซ้ำ ๆ เช่นการอ่านไฟล์ยี่สิบไฟล์เพื่อหาสามไฟล์ที่สำคัญ หรือการตรวจตั๋วที่เปิดอยู่ทุกใบเพื่อหาป้ายกำกับหนึ่งอัน เทิร์นส่วนใหญ่และบริบทส่วนใหญ่จะถูกใช้ไปกับผลลัพธ์ที่เอเจนต์ทิ้งไปในภายหลัง

โหมดโค้ดคือเครื่องมือหนึ่งตัว คือ `repl` ด้วยเครื่องมือนี้ เอเจนต์เขียนสคริปต์ JavaScript สั้น ๆ ที่เรียกเครื่องมืออื่นของตน วนลูป กรอง และรวมผลลัพธ์ของเครื่องมือเหล่านั้น แล้วส่งคืนเฉพาะสิ่งที่ต้องใช้ การเรียก `repl` ครั้งเดียวทำงานได้เท่ากับหลายสิบเทิร์นของเครื่องมือ และมีเพียงคำตอบของสคริปต์เท่านั้นที่เข้าสู่บริบท

ทุกการรันมี `repl` เมื่อเซิร์ฟเวอร์รันสคริปต์ได้ ไม่ต้องเปิดอะไรทั้งนั้น ดูที่[เมื่อการรันมี `repl`](#เมื่อการรันมี-repl)

## สคริปต์ทำอะไรได้บ้าง

สคริปต์เป็น JavaScript ธรรมดาที่เขียนเป็นตัวของฟังก์ชัน async จึงใช้ `await` และ `return` ได้ที่ระดับบนสุด การเรียก `repl` แต่ละครั้งเริ่มอินเทอร์พรีเตอร์ใหม่ที่ว่างเปล่า

- **เรียกเครื่องมือ** `await tools.read({ path: "README.md" })` เรียกเครื่องมือและได้ผลลัพธ์กลับมา หรือถูกปฏิเสธพร้อมข้อผิดพลาดเมื่อการเรียกล้มเหลวหรือถูกปฏิเสธ การเรียกที่ไม่ขึ้นต่อกันรันพร้อมกันได้ด้วย `Promise.allSettled`
- **ค้นหาเครื่องมือ** `ALL_TOOLS` แสดงรายการเครื่องมือทั้งหมดที่สคริปต์เรียกได้ `searchTools(query)` ค้นหาเครื่องมือจากสิ่งที่มันทำ `describeTool(name)` คืนคำอธิบายและอาร์กิวเมนต์ของเครื่องมือหนึ่งตัว และ `describeNamespace(name)` แสดงรายการเครื่องมือของกลุ่มหนึ่ง เครื่องมือของเซิร์ฟเวอร์ MCP ที่เชื่อมต่ออยู่ก็เข้าถึงได้ด้วยวิธีนี้เช่นกัน
- **ส่งผลลัพธ์กลับ** มีเพียงสิ่งที่สคริปต์ส่งคืน หรือส่งให้ `text()`, `image()` หรือ `console.log()` เท่านั้นที่กลับไปยังเอเจนต์ ส่งรูปภาพถึงโมเดลได้สูงสุดสี่รูป
- **เก็บค่า** `store(key, value)` และ `load(key)` เก็บค่า JSON ขนาดเล็กไว้ระหว่างสคริปต์ของบทสนทนาและเอเจนต์เดียวกัน ค่าจะถูกบันทึกเมื่อสคริปต์ทำงานเสร็จสมบูรณ์เท่านั้น ซับเอเจนต์ไม่มีที่เก็บค่า
- **ถามคน** `await tools.ask_user({ question, options })` ถามคำถามและรอคำตอบ
- **ใช้การฝังตัวบนอุปกรณ์** `models.embed`, `models.rank` และ `models.classify` ใช้โมเดลการฝังตัวของเซิร์ฟเวอร์เมื่อมีการติดตั้งไว้
- **รอ** `sleep(ms)` และ `setTimeout` ภายในเวลาจำกัดของสคริปต์ `limits()` คืนขีดจำกัดที่สคริปต์รันภายใต้

สคริปต์ไม่มีการเข้าถึงระบบไฟล์ เครือข่าย โปรเซส โมดูล หรือสภาพแวดล้อม จึงใช้ `fetch`, `require`, `import` หรือ `process` ไม่ได้ ทางออกเดียวคือการเรียกเครื่องมือ และการเรียกเครื่องมือทุกครั้งผ่านการตรวจสอบชุดเดียวกับการเรียกที่เอเจนต์ทำโดยตรง

การเรียกเครื่องมือที่สคริปต์ทำไปแล้วจะไม่ถูกย้อนกลับเมื่อสคริปต์ล้มเหลวในภายหลัง

## เครื่องมือใดที่เอเจนต์เรียกโดยตรง

ทุกการรันของเอเจนต์ในตัวได้รับชุดเครื่องมือเล็ก ๆ ชุดเดียวกันที่มันเรียกด้วยชื่อ:

- `repl` มาก่อน;
- เครื่องมือไฟล์และเชลล์ `read`, `write`, `edit`, `search`, `find`, `bash` และ `read_output`;
- `ask_user` และ `task`;
- `todo_write`, `search_memory` และ `send_message`;
- คำกริยาที่[โหมด](/th-TH/คู่มือ/แนวคิด/โหมด/)ของบทสนทนาต้องใช้เพื่อส่งผลลัพธ์หรือออกจากโหมด เช่น `submit_plan` ในโหมดแผน;
- `search_tools` เมื่อมีเครื่องมือบางตัวโหลดตอนใช้ครั้งแรกตามที่อธิบายด้านล่าง

เครื่องมืออื่นทุกตัวที่การรันอาจใช้เข้าถึงได้ด้วยสองวิธี:

- **เฉพาะจากสคริปต์** เมื่อสคริปต์เรียกเครื่องมือนั้นได้ เอเจนต์ค้นหาด้วย `searchTools()` หรือ `describeTool()` แล้วเรียกเป็น `tools.<name>(args)` คำอธิบายของมันไม่ไปถึงโมเดล จึงไม่เสียค่าใช้จ่ายในพรอมต์ หากเอเจนต์เรียกเครื่องมือนั้นโดยตรง คำตอบจะบอกให้เรียกเครื่องมือจากสคริปต์ หากเซิร์ฟเวอร์รันสคริปต์ของการรันนั้นไม่ได้ เครื่องมือจะโหลดเมื่อใช้ครั้งแรกแทน ([เมื่อสคริปต์รันไม่ได้](#เมื่อสคริปต์รันไม่ได้))
- **โหลดเมื่อใช้ครั้งแรก** เมื่อสคริปต์อาจไม่เรียกเครื่องมือนั้น เอเจนต์เห็นชื่อของมัน และการเรียกด้วยชื่อหรือการค้นหาด้วย `search_tools` จะโหลดเครื่องมือ

เครื่องมือบางตัวไม่เคยเรียกจากสคริปต์ได้ ได้แก่ `repl` เอง (สคริปต์เริ่มสคริปต์อื่นไม่ได้) `eval`, `task`, `checkpoint`, `rewind`, คำกริยา `vibe_*` และเครื่องมือที่เริ่มหรือส่งข้อความถึงการรันเอเจนต์อื่น สร้าง ตัดสิน หรือแสดงความเห็นต่อการอนุมัติ เปลี่ยนนโยบายหรือสกิล หรือออกจากโหมดแผน เอเจนต์เรียกเครื่องมือเหล่านั้นโดยตรง

การรันที่ไม่มี `repl` ได้ชุดเครื่องมือโดยตรงชุดเดียวกัน และทุกอย่างอื่นโหลดเมื่อใช้ครั้งแรก [บริบทเครื่องมือและการแคชพรอมต์](/th-TH/คู่มือ/แนวคิด/บริบทเครื่องมือ/) อธิบายว่าทำไมชุดนี้จึงเหมือนกันไม่ว่าจะเป็นแบบใด

โหมดโค้ดไม่เคยเพิ่มเครื่องมือที่โหมดของบทสนทนาไม่อนุญาต ตัวกรองเครื่องมือของโหมดถูกใช้ก่อน และสคริปต์เรียกได้เฉพาะสิ่งที่เหลืออยู่

## เมื่อการรันมี `repl`

การรันจะมี `repl` เมื่อตัวรันสคริปต์ของเซิร์ฟเวอร์ผ่านการตรวจการล็อกตอนเริ่มทำงาน ([สคริปต์ถูกจำกัดขอบเขตอย่างไร](#สคริปต์ถูกจำกัดขอบเขตอย่างไร)) ไม่มีการตั้งค่าของเวิร์กสเปซ เอเจนต์ หรือเซิร์ฟเวอร์ใดเปลี่ยนสิ่งนี้ได้ การรันจะยังไม่มี `repl` เมื่อ:

- ตัวรันไม่สามารถล็อกตัวเองบนเครื่องของเซิร์ฟเวอร์ได้ เซิร์ฟเวอร์จึงไม่รันสคริปต์เลยทั้งหมด;
- เซิร์ฟเวอร์เป็นเซิร์ฟเวอร์สาธิตสาธารณะ ซึ่งไม่รันสคริปต์;
- การรันไม่ได้อยู่ในเวิร์กสเปซใด;
- ไม่สามารถอ่านขีดจำกัดของเวิร์กสเปซได้ เพราะการรันภายใต้ค่าเริ่มต้นอาจเกินขีดจำกัดที่แอดมินตั้งไว้ต่ำกว่า;
- ไม่สามารถเขียนบันทึกของการรันได้ เพราะทุกสคริปต์ถูกบันทึกไว้ภายใต้การรันนั้นก่อนเริ่ม

การรันเช่นนี้เรียกเครื่องมือทั้งหมดของตนโดยตรง

โหมดโค้ดใช้ได้กับการรันของเอเจนต์ในตัว และกับเอเจนต์ที่เข้าถึงเครื่องมือของ Control Center ผ่านปลายทาง MCP ของมัน เช่น Claude Code สำหรับเอเจนต์ MCP รายการเครื่องมือที่มันได้รับมี `repl` เครื่องมือโดยตรง และเครื่องมือที่สคริปต์เรียกไม่ได้ ส่วนที่เหลือมันเรียกจากสคริปต์ มีเพียงการรันที่ Control Center เริ่มเองและเก็บบันทึกไว้เท่านั้นที่ได้ `repl` ตรงนั้น ไคลเอนต์อื่นทุกตัวจะได้รับเครื่องมือทุกตัวยกเว้น `repl`

**การตั้งค่า → เวิร์กสเปซ → โหมดโค้ด** แสดงใต้ **สถานะ** ว่าเซิร์ฟเวอร์นี้รันสคริปต์ได้หรือไม่ (**พร้อมใช้** หรือ **ไม่พร้อมใช้** พร้อมเหตุผลของเซิร์ฟเวอร์) และติดตั้ง **ตัวรัน** เวอร์ชันใด **ดูการรันโค้ด** เปิดรายการสคริปต์ที่รันไปแล้ว

เจ้าของเซิร์ฟเวอร์ปิดสคริปต์ไม่ได้ แต่กำหนดเพดานให้สคริปต์ได้ คือจำนวนที่รันพร้อมกันและหน่วยความจำที่สคริปต์หนึ่งใช้ได้ ดูรายละเอียดที่[ขีดจำกัด](#ขีดจำกัด)

### เมื่อสคริปต์รันไม่ได้

การรันจะไม่เคยสูญเสียเครื่องมือเพราะเซิร์ฟเวอร์รันสคริปต์ของมันไม่ได้ เมื่อเซิร์ฟเวอร์ปฏิเสธสคริปต์ด้วยเหตุผลที่สคริปต์อื่นใดก็หลีกเลี่ยงไม่ได้ (เช่น สคริปต์ไม่พร้อมใช้งาน สคริปต์รอช่องว่างไปแล้วครึ่งหนึ่งของเวลาที่มี บันทึกของมันเขียนไม่ได้ รายการเครื่องมือของการรันใหญ่เกินจะส่งให้สคริปต์ หรือตัวรันเริ่มทำงานหรือล็อกตัวเองไม่ได้) การรันนั้นจะหยุดใช้สคริปต์จนจบการรัน:

- การรันของเอเจนต์ในตัวยังคงมี `repl` และเครื่องมือทุกตัวที่มันเข้าถึงได้เฉพาะจากสคริปต์จะโหลดเมื่อใช้ครั้งแรกแทน เอเจนต์เรียกมันด้วยชื่อหรือค้นหาด้วย `search_tools`;
- การรันบนปลายทาง MCP จะได้รับรายการเครื่องมือที่มีทุกเครื่องมือและไม่มี `repl` และไคลเอนต์ของมันจะได้รับแจ้งว่ารายการเปลี่ยนแล้ว เซิร์ฟเวอร์จำการรันเช่นนี้ได้ล่าสุด 1,024 ครั้ง การรันที่เก่ากว่านั้นจะกลับไปใช้สคริปต์

เครื่องมือเหล่านั้นผ่านตัวกรองโหมด กฎคุม และการอนุมัติเหมือนเดิม ดังนั้นจึงไม่มีอะไรเรียกได้ที่ไม่เคยเรียกได้มาก่อน สคริปต์ที่ล้มเหลวด้วยสาเหตุของมันเอง ไม่ว่าจะโดยการโยนข้อผิดพลาด ใช้ขีดจำกัดจนหมด หรือถูกปฏิเสธการเรียก จะไม่เปลี่ยนแปลงอะไร

เซิร์ฟเวอร์ยังคงตรวจว่าสคริปต์รันได้อยู่ เมื่อตัวรันเริ่มทำงานไม่สำเร็จด้วยเหตุผลที่ไม่ใช่ของสคริปต์ เซิร์ฟเวอร์จะทำการตรวจการล็อกซ้ำ ไม่เกินหนึ่งครั้งต่อนาที หากการตรวจล้มเหลว เซิร์ฟเวอร์จะไม่รันสคริปต์ใดเลย และบันทึกบรรทัด `code_mode=unavailable` เหมือนตอนเริ่มทำงาน การรันที่เริ่มระหว่างนั้นจะไม่ได้ `repl` มันจะตรวจต่อไปไม่เกินหนึ่งครั้งต่อนาที และเมื่อการตรวจผ่าน มันจะรันสคริปต์อีกครั้งและบันทึกบรรทัด `code_mode=available` มีเพียงการตรวจที่ล้มเหลวตอนเซิร์ฟเวอร์เริ่มทำงานเท่านั้นที่ต้องรีสตาร์ท

## ขีดจำกัด

สคริปต์ทุกตัวรันภายใต้ขีดจำกัด แอดมินเวิร์กสเปซเปลี่ยนได้หกรายการภายใต้ **ขีดจำกัด** ใน **การตั้งค่า → เวิร์กสเปซ → โหมดโค้ด** (**ปรับขีดจำกัด**) เอเจนต์ขอเวลาหรืองบเอาต์พุตที่น้อยกว่าสำหรับสคริปต์หนึ่งได้ แต่ขอให้มากกว่าไม่ได้

| ขีดจำกัด | ค่าเริ่มต้น | ช่วง | เมื่อถึงขีดจำกัด |
| --- | --- | --- | --- |
| เวลาต่อสคริปต์ | 5 นาที | 1 วินาที ถึง 25 นาที | สคริปต์จะถูกหยุด และเอเจนต์ได้รับแจ้งว่าหมดเวลาแล้ว |
| เวลาของโปรเซสเซอร์ | 30 วินาที | 1 วินาที ถึง 2 นาที | สคริปต์จะถูกหยุด |
| หน่วยความจำ | 256 MiB | 16 MiB ถึง 1 GiB | สคริปต์จะถูกหยุด เจ้าของเซิร์ฟเวอร์ตั้งเพดานที่ต่ำกว่าสำหรับทั้งเซิร์ฟเวอร์ได้ |
| การเรียกเครื่องมือต่อสคริปต์ | 500 | 1 ถึง 5,000 | การเรียกเพิ่มเติมจะถูกปฏิเสธ และสคริปต์ได้รับแจ้งเหตุผล |
| การเรียกพร้อมกัน | 8 | 1 ถึง 32 | การเรียกแบบอ่านอย่างเดียวที่เกินขีดจำกัดนี้ต้องรอตามคิว การเรียกที่เปลี่ยนแปลงอะไรจะรันทีละรายการเสมอ |
| เอาต์พุตที่เอเจนต์อ่าน | 10,000 โทเค็น | 100 ถึง 50,000 | เอาต์พุตจะถูกตัดให้เหลือส่วนต้นและส่วนท้าย และเอเจนต์อ่านส่วนที่เหลือได้เมื่อขอ |

เวลาที่สคริปต์รอให้คนดำเนินการ ไม่ว่าจะเป็นการอนุมัติหรือคำถาม ไม่นับรวมในขีดจำกัดเวลา ขณะที่รออยู่ สคริปต์จะไม่เริ่มการเรียกเครื่องมืออื่น การเรียกที่สคริปต์ทำในระหว่างนั้นจะเริ่มตามลำดับเมื่อคุณตอบแล้ว

ขีดจำกัดบางอย่างตายตัว ซอร์สของสคริปต์มีขนาดไม่เกิน 256 KiB อาร์กิวเมนต์ของการเรียกเครื่องมือหนึ่งครั้งไม่เกิน 1 MiB และ 16,384 ค่า คำสั่งที่สคริปต์ส่งให้เครื่องมือในตัวที่รันมันไม่เกิน 16 KiB (รวมชื่อของเครื่องมือด้วย) ผลลัพธ์หนึ่งชิ้นที่ส่งให้สคริปต์ไม่เกิน 4 MiB ค่าที่เก็บหนึ่งค่าไม่เกิน 256 KiB และทุกอย่างที่บทสนทนาและเอเจนต์หนึ่งเก็บรวมกันไม่เกิน 1 MiB การรันหนึ่งครั้งรันสคริปต์ทีละหนึ่งตัวเท่านั้น

การค้นหาเครื่องมือของสคริปต์ก็ถูกจำกัดเช่นกัน: คำค้น `searchTools` ยาวไม่เกิน 1,024 อักขระ ชื่อเครื่องมือหรือเนมสเปซยาวไม่เกิน 256 ผลลัพธ์ไม่เกิน 50 รายการ และการค้นหาไม่เกิน 200 ครั้งที่ใช้เวลาของเซิร์ฟเวอร์รวมกันไม่เกิน 2 วินาที เกินนั้นการค้นหาต่อไปจะล้มเหลว สคริปต์ทั้งหมดของเวิร์กสเปซหนึ่งยังใช้เวลาค้นหาร่วมกัน 2 วินาที ซึ่งคืนกลับในอัตรา 0.25 วินาทีต่อวินาที ดัชนีการค้นหาให้เครื่องมือแต่ละตัวได้ส่วนแบ่งที่เท่ากันประมาณหนึ่งล้านอักขระ ใช้กับชื่ออาร์กิวเมนต์ก่อน แล้วจึงใช้กับคำอธิบาย และจัดทำดัชนีชื่อของเครื่องมือทุกตัวเสมอ ดังนั้นแม้ในแคตตาล็อกที่ใหญ่มาก เครื่องมือก็ยังถูกพบจากชื่อของมัน

เจ้าของเซิร์ฟเวอร์ยังจำกัดจำนวนสคริปต์ที่รันพร้อมกันบนเซิร์ฟเวอร์ได้ (`--code-mode-max-processes` ค่าเริ่มต้นคือสองเท่าของจำนวนคอร์โปรเซสเซอร์ และไม่เกิน 16) และหน่วยความจำที่สคริปต์หนึ่งใช้ได้ (`--code-mode-max-heap-mb`) สคริปต์ที่รอคนจะนับแยกต่างหาก ไม่เกินสี่เท่าของจำนวนนั้น เมื่อเพดานนั้นมากกว่าหนึ่ง เวิร์กสเปซหนึ่งจะใช้ได้มากที่สุดประมาณสามในสี่ของเพดานนั้น ดังนั้นเวิร์กสเปซเดียวยึดที่ทั้งหมดไม่ได้ การรันหนึ่งครั้งและซับเอเจนต์ของมันรวมกันใช้ช่องได้มากที่สุดครึ่งหนึ่งของช่องในเวิร์กสเปซของมัน (อย่างน้อยหนึ่งช่อง) สคริปต์เพิ่มเติมของพวกมันจึงรอ ขณะที่สคริปต์ของการรันอื่นในเวิร์กสเปซยังไปต่อได้ อ่านเพิ่มเติมได้ใน[CLI ของ `cc_server`](/th-TH/คู่มือ/อ้างอิง/cc-server-cli/#โหมดโค้ด)

## การอนุมัติและคำถาม

การเรียกเครื่องมือจากสคริปต์ถูกตรวจเหมือนการเรียกโดยตรงทุกประการ ได้แก่ ตัวกรองเครื่องมือของโหมด[กฎคุมของการกระทำ](/th-TH/คู่มือ/แนวคิด/กฎคุม/) คำขออนุมัติ และการตรวจสอบของเครื่องมือนั้นเอง สคริปต์ทำอะไรไม่ได้ที่เอเจนต์เรียกเครื่องมือเองไม่ได้

เมื่อการเรียกของสคริปต์ต้องได้รับการอนุมัติ การ์ดอนุมัติจะแสดง **จากสคริปต์ที่เอเจนต์กำลังรันอยู่** และ **แสดงสคริปต์** จะเปิดสคริปต์ในบทสนทนา เพื่อไม่ให้สคริปต์ส่งการ์ดมาให้คุณจำนวนมาก:

- หนึ่งสคริปต์ขออนุมัติได้มากที่สุด 10 ครั้ง และถามคำถามได้มากที่สุด 10 ข้อ;
- เมื่อคุณปฏิเสธการเรียกหนึ่งรายการของสคริปต์ การเรียกที่ตามมาซึ่งต้องได้รับอนุมัติจะถูกปฏิเสธโดยไม่ถาม

สำหรับการรันของเอเจนต์ในตัว การ์ดอนุมัติที่เกิดจากคำสั่งที่สคริปต์รัน เช่น การพุชของ git จะนับรวมในขีดจำกัดเดียวกัน และหยุดหลังจากถูกปฏิเสธในลักษณะเดียวกัน เมื่อสคริปต์ของซับเอเจนต์รันพร้อมกัน การ์ดดังกล่าวจะนับในขีดจำกัดของทั้งสองสคริปต์ และการปฏิเสธหนึ่งครั้งหยุดทั้งสองสคริปต์

ในการรันของเอเจนต์ในตัว การอนุมัติสำหรับเครื่องมือของเซิร์ฟเวอร์ MCP ภายนอกจะไม่ถูกจดจำไว้ การเรียกแต่ละครั้งจะถามใหม่ ไม่ว่าสคริปต์หรือเอเจนต์จะเป็นผู้เรียกโดยตรง เว้นแต่ความเป็นอิสระของสเปซจะตั้งเป็น **ทำได้อย่างอิสระ** มีเพียงคำขออนุมัติที่สคริปต์ก่อขึ้นจากการเรียกของตัวเองเท่านั้นที่นับเข้าการขออนุมัติได้มากที่สุด 10 ครั้งของสคริปต์นั้น

หากสคริปต์จบก่อนที่คุณจะตอบ การ์ดจะถูกถอนออก และคำตอบที่ให้มาหลังจากนั้นไม่อนุมัติอะไรเลย

## ในบทสนทนา

การเรียก `repl` แสดงในบทสนทนาเป็นแถวเดียวที่มีป้ายเป็นคำอธิบายของสคริปต์ การขยายแถวจะแสดงสคริปต์และเอาต์พุต และการเรียกเครื่องมือที่สคริปต์ทำอยู่ภายใต้ **การเรียกเครื่องมือ** พร้อมจำนวนที่กำลังรัน สำเร็จ ล้มเหลว ถูกปฏิเสธ ถูกยกเลิก อยู่ในคิว หรือข้ามแล้ว

### สคริปต์แสดงในบทสนทนาอย่างไร

ตัวรันรายงานบรรทัดและคอลัมน์ที่แต่ละการเรียกถูกทำ ดังนั้นการเรียกเครื่องมือจึงจัดเรียงตามโครงสร้างของสคริปต์ ไม่ได้เป็นรายการยาวรายการเดียว และแอปอ่านสคริปต์เพื่อหาลูป เงื่อนไข และฟังก์ชัน:

- **ลูป** (`for`, `while`) แสดงเป็นกลุ่ม **ลูป** โดยมีบรรทัดแรกของลูปเป็นหัว และฟังก์ชันเรียกกลับที่ส่งให้การเรียกเช่น `map` หรือ `forEach` แสดงเป็นกลุ่ม **สำหรับแต่ละรายการ** เส้นบางแยกการวนแต่ละรอบออกจากรอบถัดไปเมื่อแอปแยกได้
- **การเรียกที่รันด้วยกัน** ด้วย `Promise.all`, `Promise.allSettled` หรือตัวรวมที่คล้ายกัน แสดงเป็นกลุ่ม **ทำพร้อมกัน** ตามชื่อของมัน
- **สาขา** (`if`/`else`, `switch`, `try`/`catch`) แสดงหนึ่งกลุ่มต่อแขน โดยมีเงื่อนไขของแขนนั้นเป็นหัว
- **ฟังก์ชัน** ที่สคริปต์กำหนดและเรียกใช้แสดงเป็นกลุ่ม **ฟังก์ชัน** ตามชื่อของมัน

กลุ่มที่อยู่ข้างในกลุ่มอื่นจะถูกย่อหน้าเข้าไปอีกหนึ่งระดับ สูงสุดแปดระดับ กลุ่มที่ลึกกว่านั้นจะคงระยะย่อหน้าที่ระดับนั้น

หัวของแต่ละกลุ่มแสดงว่าการเรียกภายในจบลงอย่างไรจนถึงตอนนี้ ก่อนการเรียกจะรัน แถวของมันแสดงเครื่องมือและอาร์กิวเมนต์ตามที่เขียนไว้ในสคริปต์:

| แถว | ความหมาย |
| --- | --- |
| **อยู่ในคิว** | สคริปต์ยังไม่ถึงการเรียกนี้ |
| กำลังรัน | การเรียกกำลังรันอยู่ |
| เสร็จแล้ว | การเรียกจบแล้ว แถวแสดงผลลัพธ์และระยะเวลาที่ใช้ |
| **ข้ามแล้ว** | สคริปต์ข้ามการเรียกนี้ เช่น แขนของ `if` ที่ไม่ถูกเลือก หรือจบโดยไม่ถึงการเรียกนั้น |

การเรียกที่เขียนอยู่ในอาร์กิวเมนต์ของการเรียกไปยังเครื่องมือเดียวกันจะถูกรายงานจากตำแหน่งเดียวกันในสคริปต์กับการเรียกนั้น เมื่อแอปบอกไม่ได้ว่าการเรียกภายนอกถูกทำหรือไม่ แถวของมันจะไม่มีคำสถานะแทน **ข้ามแล้ว** เลย

เมื่อกลุ่มมีการเรียกเกินแปดครั้ง ส่วนกลางของมันจะยุบ โดยสองครั้งแรกและสามครั้งสุดท้ายยังมองเห็นได้ และการเรียกทุกครั้งที่ยังรันอยู่ ล้มเหลว หรือถูกปฏิเสธก็ยังมองเห็นได้ พร้อมการเรียกที่เริ่มรอบของลูปนั้น **แสดงเพิ่ม N การเรียก** เปิดเพิ่มครั้งละ 100 ครั้งทุกครั้งที่กด และระบุชื่อเครื่องมือของการเรียกที่ซ่อนอยู่สูงสุดสี่ตัวพร้อมจำนวนของแต่ละตัว เรียงจากตัวที่พบน้อยที่สุด เช่น **แสดงเพิ่ม 12 การเรียก** · Bash 1 · Read 11 ชื่อเครื่องมือที่ยาวกว่า 24 อักขระจะถูกตัดสั้นในป้ายปุ่มนั้น

การเรียกที่แอปวางในสคริปต์ไม่ได้ เช่นการเรียกที่ฟังก์ชันเรียกกลับของ `then` สร้างขึ้น จะแสดงหลังโครงสร้างข้างต้นภายใต้ **การเรียกที่ไม่ตรงกับตำแหน่งในสคริปต์** เมื่อแอปอ่านสคริปต์ไม่ได้ หรือไม่มีการเรียกใดระบุตำแหน่งที่ถูกทำ การเรียกจะแสดงเป็นรายการธรรมดาตามลำดับที่ถูกทำ

แต่ละแถวการเรียกแสดงส่วนต้นของอาร์กิวเมนต์ของการเรียกและส่วนต้นของผลลัพธ์ ไม่เกิน 8 KiB ต่อส่วน เมื่อส่วนต้นเหล่านี้ของแถวในสคริปต์หนึ่งรวมกันถึง 256 KiB แถวหลังจากนั้นจะแสดงเฉพาะเครื่องมือและผลลัพธ์ เมื่อสคริปต์เสร็จแล้ว **เปิดบันทึก** จะเปิดบันทึกฉบับเต็ม หากหาบันทึกไม่พบ จะเปิดรายการสคริปต์ของการรันนั้นแทน สคริปต์ที่ถูกปฏิเสธก่อนรัน (เช่น เพราะสคริปต์อื่นของการรันเดียวกันยังรันอยู่) ไม่มีบันทึกและไม่มีลิงก์

## บันทึก

ทุกสคริปต์ที่รันจะถูกบันทึกลงในเวิร์กสเปซก่อนเริ่ม และบันทึกจะสมบูรณ์เมื่อสคริปต์จบ **การสังเกตการณ์ → การรันโค้ด** แสดงรายการทั้งหมดเรียงจากใหม่ไปเก่า และกรองตามผลลัพธ์ได้ ลิงก์ **สคริปต์ในการรันนี้** และ **สคริปต์ของเอเจนต์นี้** ในบันทึกจะจำกัดรายการให้เหลือเฉพาะการรันหนึ่งครั้งหรือเอเจนต์หนึ่ง บันทึกแสดง:

- สคริปต์ เอาต์พุต และคอนโซลของมัน;
- เริ่มเมื่อใด ใช้เวลานานเท่าใด เวลาของโปรเซสเซอร์และหน่วยความจำสูงสุดที่ใช้ และรันผ่านเอเจนต์ในตัวหรือเอเจนต์ภายนอก;
- สิ้นสุดอย่างไร อธิบายเป็นภาษาธรรมดา (เช่น หมดเวลา หรือเกิดข้อผิดพลาดที่ไม่มีอะไรดักไว้);
- การเรียกเครื่องมือทุกครั้งตามลำดับ พร้อมผลลัพธ์ ว่าได้รับอนุญาต ได้รับอนุมัติจากคน หรือถูกปฏิเสธ คนใช้เวลาตัดสินนานเท่าใด อาร์กิวเมนต์ของมัน (ลบความลับออกแล้วและตัดให้เหลือ 8 KiB) และขนาดของผลลัพธ์ ไม่มีการเก็บผลลัพธ์นั้นเอง

บันทึกเก็บไว้ว่าแต่ละการเรียกถูกทำที่ตำแหน่งใดในสคริปต์ ดังนั้นการเรียกเครื่องมือของมันจึงจัดวางเหมือนในบทสนทนา การเรียกที่บุคคลอนุมัติจะไม่ถูกยุบซ่อนที่นั่นเลย

สคริปต์ที่ยังรันอยู่จะแสดงว่ากำลังรัน พร้อมการเรียกเครื่องมือที่เสร็จไปแล้วจนถึงตอนนี้ เอาต์พุต ระยะเวลา และการใช้ทรัพยากรจะปรากฏเมื่อสิ้นสุด หากเซิร์ฟเวอร์หยุดระหว่างที่สคริปต์รันอยู่ บันทึกจะถูกปิดเมื่อเซิร์ฟเวอร์เริ่มทำงานใหม่ และบันทึกระบุเช่นนั้น จนกว่าบันทึกจะถูกปิด จะไม่มีสคริปต์รันในเวิร์กสเปซนั้น

บันทึกถูกเก็บไว้คู่กับการรันของมัน การลบการรันหรือสเปซของมันจะลบบันทึกด้วย สมาชิกเห็นบันทึกของสเปซที่พวกเขาเปิดได้

## สคริปต์ถูกจำกัดขอบเขตอย่างไร

สคริปต์ไม่เคยรันภายในเซิร์ฟเวอร์ สคริปต์แต่ละตัวรันในโปรเซสของมันเอง ซึ่งเป็นโปรแกรมขนาดเล็กที่บรรจุมากับเซิร์ฟเวอร์ ชื่อ `cc_codemode` และรัน JavaScript ด้วยเอนจิน QuickJS-NG ก่อนอ่านสคริปต์ โปรแกรมจะล็อกตัวเองด้วยการควบคุมของระบบปฏิบัติการ บน Linux เป็นตัวกรองการเรียกระบบและขีดจำกัดทรัพยากร บน macOS เป็นโปรไฟล์แซนด์บ็อกซ์แบบปฏิเสธเป็นค่าเริ่มต้น บน Windows เป็น AppContainer และจ็อบ หลังจากนั้นโปรแกรมเปิดไฟล์ไม่ได้ ใช้เครือข่ายไม่ได้ เริ่มโปรเซสไม่ได้ หรือมองเห็นโปรแกรมอื่นไม่ได้ มันเริ่มโดยไม่มีตัวแปรสภาพแวดล้อม และไม่ถือข้อมูลรับรองใด ช่องทางเดียวของมันคือเซิร์ฟเวอร์ ซึ่งตอบการเรียกเครื่องมือของมัน

เซิร์ฟเวอร์ตรวจการล็อกตอนเริ่มทำงานโดยรันการทดสอบตัวเองของโปรแกรม หากการล็อกไม่มีผลบนเครื่องนั้น เช่น ภายในคอนเทนเนอร์ที่โปรไฟล์ความปลอดภัยปฏิเสธขั้นตอนหนึ่ง เซิร์ฟเวอร์จะไม่รันสคริปต์ที่นั่นเลย ไม่มีการรันใดได้ `repl` และหน้าการตั้งค่าแสดง **ไม่พร้อมใช้** พร้อมเหตุผล สคริปต์ไม่เคยรันด้วยการจำกัดขอบเขตที่น้อยกว่า ยังไม่ได้ทดสอบการล็อกของ Windows บนเครื่อง Windows

ตัวรันเป็นผู้รายงานตำแหน่งในสคริปต์ที่แต่ละการเรียกถูกทำ จึงใช้เพียงเพื่อจัดวางบทสนทนาและบันทึกเท่านั้น มันไม่เคยตัดสินว่าการเรียกใดได้รับอนุญาต
