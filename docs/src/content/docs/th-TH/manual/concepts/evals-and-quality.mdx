**การสังเกตการณ์ → คุณภาพ** มีทั้งชุด eval สำหรับงานเดียวและแคมเปญสกิลแบบจับคู่
แคมเปญสกิลวัดแพ็กเกจในลักษณะที่โมเดลหนึ่งและฮาร์เนสหนึ่งใช้งาน ไม่ใช่วัดคุณภาพ
ของ Markdown ในตัวมันเอง

## ชุด eval

**ชุด eval** คือคำจำกัดความระดับเวิร์กสเปซของงานที่จะรันกับเอเจนต์ ประกอบด้วยพรอมต์
เอเจนต์เป้าหมายและโหมด ขั้นตอนเซ็ตอัปที่ไม่บังคับ ฟิกซ์เจอร์ที่ไม่บังคับซึ่งปักหมุด SHA ไว้
และรายการเกรดเดอร์ เกรดเดอร์เป็นแบบดีเทอร์มินิสติกก่อนเป็นอันดับแรก ส่วนผู้ตัดสินแบบ LLM
ที่ใช้รูบริกจะครอบคลุมสิ่งที่การตรวจสอบเหล่านั้นไม่สามารถแสดงออกได้

ชุดเริ่มต้นห้าชุดจะถูก seed เมื่อสร้างเวิร์กสเปซ ชุดเหล่านี้ครอบคลุมข้อเสนอการประสานงาน
รีวิวที่ตรวจจับบั๊กที่ seed ไว้ โหมดแผนที่คงสถานะอ่านอย่างเดียว โหมดแผนที่สร้างแผน
และการไปกลับครบวงจรของตั๋วงาน การ seed จะฟังเหตุการณ์ `WorkspaceCreated`
(`workspace.upsert` หรือ `workspace.create`) ข้ามชื่อที่มีอยู่แล้ว และไม่เติมข้อมูลย้อนหลัง
ให้เวิร์กสเปซเก่า

### ตำแหน่งที่ชุดเหล่านี้ปรากฏ

**การสังเกตการณ์ → คุณภาพ** (`/workspaces/<id>/observability`) แสดงรายการชุด eval
แต่ละชุดในเวิร์กสเปซ

สร้าง แสดงรายการ แก้ไข และลบชุด eval ผ่าน `evals.upsertSuite`,
`evals.deleteSuite` และ `evals.watchSuites` แท็บคุณภาพคือรายการ
ส่วนการดำเนินการเหล่านั้นคือตัวแก้ไข

## แคมเปญสกิล

แคมเปญหนึ่งเปรียบเทียบสองกลุ่มทดลองภายใต้งานและการกำหนดค่าการทำงานเดียวกัน
ผู้สมัครอาจไม่มีอยู่ มีให้ใช้ตามปกติ ถูกโหลดอย่างชัดเจน หรือถูกเปรียบเทียบกับ
เวอร์ชันก่อนหน้าหรือชุดสกิลแวดล้อมที่ตรึงไว้ สิ่งเหล่านี้ตอบคำถามต่างกัน
การบังคับโหลดเป็นการวินิจฉัย ไม่ใช่คะแนนสำหรับการค้นพบตามปกติ
[คู่มือสกิล](/th-TH/คู่มือ/วิธีทำ/จัดการสกิล/#ประเมินสกิล) อธิบายวิธีเลือก
การเปรียบเทียบและอนุญาตการรันที่มีงบประมาณ

หลักฐานเป็นของ **แฮชของแพ็กเกจทั้งชุด** ที่เจาะจง: `SKILL.md` เมทาดาทา สคริปต์
เอกสารอ้างอิง และแอสเซต เซิร์ฟเวอร์บันทึกแพ็กเกจที่สแกนแล้วและไม่เปลี่ยนแปลง
และปักหมุดชุดงานทดสอบ อะแดปเตอร์ ตัวระบุผู้ให้บริการ/โมเดลเนทีฟ โพรโทคอล
สคีมาเครื่องมือ และชุดแวดล้อม แคมเปญ Claude แบบเนทีฟยังปักหมุดบัญชีที่จัดการไว้
และเวอร์ชัน CLI ที่สังเกตได้ การแก้ไขเอกสารอ้างอิงทำให้หลักฐานปัจจุบันใช้ไม่ได้
แม้ `SKILL.md` จะไม่เปลี่ยน นามแฝงของโมเดลบันทึกสิ่งที่ถูกขอ ไม่ใช่น้ำหนักของ
ผู้ให้บริการที่ไม่เปลี่ยนแปลง

แต่ละความพยายามได้บริบท โฮม และสถานะฟิกซ์เจอร์ใหม่ กลุ่มทดลองแบบจับคู่ใช้
นโยบายและเงื่อนไขงานเดียวกัน ยกเว้นการแทรกแซงสกิลที่ประกาศไว้ การไม่มีเป้าหมาย
หมายความว่าเมทาดาทาและไฟล์ของผู้สมัครไม่พร้อมใช้ ไม่ได้หมายความว่าคำสั่งหรือ
สกิลเบื้องหลังทั้งหมดถูกนำออก พรอมต์ของงานต้องไม่ระบุชื่อผู้สมัครในการเปรียบเทียบ
แบบค้นพบตามปกติ

เซิร์ฟเวอร์เป็นเจ้าของการอนุญาต การทำงาน งบประมาณ และการเก็บรักษาในเวิร์กสเปซ
ไคลเอนต์เลือกการตั้งค่าและแสดงหลักฐาน ความคืบหน้าอยู่รอดจากการเชื่อมต่อใหม่
การยกเลิกเก็บผลลัพธ์บางส่วนไว้ และการรีสตาร์ตจะทำเครื่องหมายงานที่ยังไม่เสร็จว่า
ถูกขัดจังหวะ แทนที่จะเรียกซ้ำแบบเงียบ ๆ ซึ่งมีค่าใช้จ่าย แคมเปญเหล่านี้ไม่ได้
จัดหาสัญญาตัวทำงานแยกต่างหากสำหรับชุด eval ตามอำเภอใจ

## อ่านหลักฐานอย่างระมัดระวัง

- **ผลลัพธ์เป็นตัวตัดสินความถูกต้อง** ผู้ตรวจสอบแบบมีชนิดข้อมูลที่เป็นอิสระ
  ตรวจสอบสิ่งประดิษฐ์และพฤติกรรมที่เป็นผล ไม่ใช่คำกล่าวอ้างของเอเจนต์ว่าสำเร็จ
  คำตอบที่คาดหวังอยู่ภายนอกเขตปิดของผู้สมัคร โค้ดที่สร้างขึ้นถูกให้คะแนนใน
  สำเนาที่แยกเขตปิดออกไป
- **การโหลดกับประโยชน์ใช้สอยเป็นคนละเรื่อง** ความพร้อมใช้ การโหลดเนื้อหาและ
  เอกสารอ้างอิง และการใช้สคริปต์ที่สังเกตได้อธิบายการทำงาน การอ่านไฟล์ไม่ได้
  พิสูจน์ว่าโมเดลทำตามคำสั่งของมัน การเข้าถึงที่สังเกตไม่ได้ยังคงไม่ทราบผล
- **เก็บเส้นฐานที่จับคู่ไว้** การรันของผู้สมัครที่สำเร็จเพียงครั้งเดียวไม่ได้
  ยืนยันว่ามีประโยชน์ รวมความพยายามที่สกิลซึ่งพร้อมใช้ถูกเพิกเฉย ความพยายามที่
  ล้มเหลวและค่าใช้จ่ายของมัน อย่าเก็บไว้แค่ความพยายามซ้ำที่ดีที่สุด
- **การทำซ้ำไม่ใช่งานใหม่** รายงานจัดกลุ่มความไม่แน่นอนตามงาน ตัวอย่างเล็ก
  ความครอบคลุมที่ขาด การเลื่อนของตัวตน และค่าใช้จ่ายที่ไม่ทราบ ไม่สามารถ
  ใช้เป็นเหตุผลสนับสนุนคำแนะนำให้รับเวอร์ชันได้ แคมเปญที่เสร็จแล้วอาจยังสรุปไม่ได้
  การที่พิสูจน์การปรับปรุงไม่ได้ก็ไม่ใช่หลักฐานของความเท่าเทียมหรือการถดถอย
- **ตรวจดูการถดถอยรายรายการ** กำไรโดยรวมต้องไม่บดบังงานที่เสียหายหรือผลข้างเคียง
  ที่ไม่ได้รับอนุญาต การสแกนความปลอดภัย การสังเกตความปลอดภัยขณะทำงาน และ
  ประโยชน์ใช้สอยยังคงแยกกัน การทำงานที่ถูกกว่าชดเชยหลักฐานด้านคุณภาพหรือ
  ความปลอดภัยที่ขาดไปไม่ได้
- **อย่ารวมผลลัพธ์ที่เข้ากันไม่ได้** โมเดล ฮาร์เนส นโยบาย ฟิกซ์เจอร์ หรือ
  การผสมสกิลอื่นคือการกำหนดค่าอื่น เก็บหลักฐานการถ่ายโอนและการประกอบบนชุดที่
  กันไว้แยกจากกรณีพัฒนา

คลังงานนำร่องเก้าชุดที่เขียนขึ้นในเครื่องมี 108 รายการงาน ครอบคลุมประโยชน์ใช้สอย
การจัดเส้นทาง/ความปลอดภัยเฉพาะตระกูล และการถ่ายโอน/การประกอบบนชุดที่กันไว้
เลือกตระกูลที่ตรงกับจุดประสงค์ของสกิล คำตอบอ้างอิงและเอาต์พุตที่รู้ว่าแย่
ใช้ตรวจสอบผู้ตรวจสอบ ฟิกซ์เจอร์เหล่านี้ไม่ใช่การทำซ้ำของเบนช์มาร์กสาธารณะ
และไม่ใช่หลักฐานว่าสกิลที่ติดตั้งไว้ใด ๆ มีประโยชน์ การรันทดสอบควันของ
การนำไปใช้ด้วยคำตอบผู้ให้บริการที่เขียนสคริปต์ไว้ ไม่ใช่การวัดคุณภาพสกิล
บนโมเดลจริง

## ขีดจำกัดด้านการทำงานและหลักฐาน

รองรับอะแดปเตอร์ที่ถูกควบคุม **ฮาร์เนสในตัว** และ **Claude Code** การกักขังและ
ข้อมูลรับรองที่ใช้งานได้ต้องผ่านก่อนการทำงาน ผู้ให้บริการในตัวต้องมีเอกสารรองรับ
เครื่องมือ ขีดจำกัดโทเคน และราคา ส่วน Codex OAuth ยืนยันบัญชีของตัวเอง แทนที่จะ
ต้องใช้คีย์ API ของ OpenAI แยกต่างหาก Claude Code ใช้บัญชีที่จัดการไว้เริ่มต้น
รหัสโมเดลที่เจาะจง และรายงานต้นทุนเทียบเท่า API แบบเนทีฟของตัวเอง

Claude Code และ Codex OAuth ใช้ **เกณฑ์หยุดการใช้งาน** การเรียกที่กำลังดำเนินอยู่
เกินงบประมาณได้ แล้วการเรียกต่อไปจะหยุด นี่ไม่ใช่ค่าใช้จ่ายของการสมัครใช้ที่ถูก
เรียกเก็บ และไม่ใช่เพดานใบแจ้งหนี้แบบตายตัว ผู้ให้บริการที่ใช้คีย์ API ยังคงสงวน
ไว้ล่วงหน้าอย่างอนุรักษ์นิยมก่อนการเรียก ค่าใช้จ่ายที่สังเกตได้แต่ไม่ทราบจะหยุด
การเรียกต่อไปสำหรับทุกอะแดปเตอร์ ความครอบคลุมที่ไม่ครบถ้วนยังคงเป็นแบบบางส่วน
หรือยังสรุปไม่ได้

Claude รันลูปโมเดลเนทีฟของตัวเองในไดเรกทอรีคอนโทรลเลอร์ส่วนตัว โดยปิดเครื่องมือ
ในตัวและสกิลแวดล้อมไว้ เครื่องมือของมันมีเพียงสะพาน MCP ที่ยืนยันตัวตนและมี
เซิร์ฟเวอร์เป็นเจ้าของ เชื่อมเข้าสู่แขกที่ถูกกักขังตัวเดียวกับที่ฮาร์เนสในตัวใช้
ข้อมูลรับรองอยู่ภายนอกแขกนั้น ตัวตน CLI หรือพื้นผิวเครื่องมือที่เปลี่ยนไปทำให้
ความพยายามนั้นใช้ไม่ได้ แทนที่จะเปลี่ยนตัวทำงานอย่างเงียบ ๆ การประเมินแบบฟลีต
และ Windows ไม่ได้รับการรองรับ การตรวจ Git ของวอร์กเกอร์ที่สำเร็จหรือการสะท้อน
พรอมต์ไม่นับเป็นการประเมิน

การกักขังบน macOS ปฏิเสธเครือข่ายของแขกและการเข้าถึงระบบไฟล์ภายนอก บล็อกการ
แยกโปรเซส จำกัด CPU/ไฟล์/เอาต์พุต และเก็บกวาดโปรเซสลูกที่ครอบครองไว้
แต่ **ไม่ได้บังคับโควตาหน่วยความจำแบบตายตัว** Linux ต้องใช้ bubblewrap และ
บังคับขีดจำกัดพื้นที่ที่อยู่ (address space) การตรวจสอบการกักขังครั้งแรก
ทดลองกับ macOS ไม่ใช่ Linux การกักขังที่ขาดหายไม่เคยถอยกลับไปใช้เชลล์ของโฮสต์
ข้อมูลรับรองของผู้ให้บริการอยู่บนเซิร์ฟเวอร์ นอกเครื่องมือของแขก

หลักฐานของความพยายามถูกปกปิดและจำกัดที่ 256 KiB การส่งออกจำกัดที่ 16 MiB
การส่งออกขนาดใหญ่ยังคงเก็บสรุปผลลัพธ์/ค่าใช้จ่ายแบบกะทัดรัดสำหรับทุกความพยายาม
ที่รับไว้ และรายงานเนื้อหาร่องรอยที่ถูกตัดออกหรือสรุปไว้อย่างชัดเจน ทั้งการส่งออก
และรายงานไม่มีชุดเล่นซ้ำของซอร์สส่วนตัวทั้งชุด การตรวจความปลอดภัยแบบสังเคราะห์
ไม่ได้ยืนยันความต้านทานต่อการรั่วไหลจริง ไม่ได้ลบล้างการกักกัน และไม่ได้
รับรองว่าสกิลปลอดภัย
