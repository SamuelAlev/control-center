## สิ่งที่คุณจะสร้าง

เมื่อจบบทสอนนี้ คุณจะได้:

- เปิด pull request ในเวิร์กเบนช์ PR ของ Control Center
- อ่าน diff ของมันและฝากความคิดเห็นแบบอินไลน์
- ส่งคำตัดสินการรีวิว
- รวม PR

สิ่งที่ต้องเตรียม: ทำ[สั่งงานเอเจนต์ตัวแรก](/th-TH/คู่มือ/บทสอน/เอเจนต์ตัวแรก/) ให้เสร็จ และมี pull request ที่เปิดอยู่หนึ่งใบในรีโปที่ลงทะเบียนไว้กับเวิร์กสเปซนี้ สำหรับขั้นตอนการรีวิว ให้เลือก PR ที่คุณไม่ได้เปิดเอง — ปุ่ม **รีวิว** จะถูกซ่อนไว้บน PR ของคุณเอง แต่การรวมยังใช้ได้กับ PR ที่คุณเป็นผู้เขียน

## ขั้นตอนที่ 1: เปิด pull request

1. คลิก **Pull request** ในแถบข้าง
2. ค้นหา PR ของคุณแล้วคลิกที่มัน

**จุดตรวจสอบ.** PR จะเปิดเป็นเวิร์กเบนช์แบบมีแท็บ — ภาพรวม, Diff, การควบคุมซอร์ส, แชท, การกระทำ — โดยโฟกัสที่ **ภาพรวม**: ชื่อเรื่องและการกระทำ คำอธิบายและไทม์ไลน์กิจกรรม และแถบด้านข้างที่มีสถานะ ผู้รีวิว ผู้รับมอบหมาย การตรวจ และไฟล์ที่เปลี่ยนแปลง การคลิกไฟล์ตรงนั้นจะพาไปยังไฟล์นั้นในแท็บ Diff แท็บ **รีวิว PR** จะยังไม่เปิดจนกว่าจะมีใครขอให้ AI รีวิว

:::note[คิวว่างพร้อมข้อความชวน “เชื่อมต่อ GitHub”]
สถานะนั้นหมายความว่า_เซิร์ฟเวอร์_ไม่มีโทเค็น GitHub — ไคลเอนต์ของคุณไม่เคยมีเลย ตั้งค่าได้ที่ **การตั้งค่า → เวิร์กสเปซ → โปรไฟล์และตัวตน → โฮสต์โค้ด** แล้วรีเฟรชรายการ
:::

## ขั้นตอนที่ 2: อ่าน diff

เปิดแท็บ **Diff** แผนผังไฟล์ที่ย่อและขยายได้อยู่ทางซ้าย ส่วนแถบเหนือ diff มีตัวเลือกช่วงคอมมิต — จำกัด diff ให้เหลือคอมมิตเดียวหรือหลายคอมมิตติดกัน — พร้อมจำนวนไฟล์และยอดเพิ่มลบสะสม

ปุ่มการตั้งค่าในแถบเครื่องมือของ diff ควบคุมวิธีแสดงผล:

- มุมมองแบบ **แยก** หรือ **รวม**
- **ตัดบรรทัด** หรือเลื่อนบรรทัดยาว
- **ลิเกเจอร์แบบอักษรโค้ด**

ทำเครื่องหมายว่าไฟล์ถูกดูแล้วเพื่อติดตามความคืบหน้าของคุณใน diff ขนาดใหญ่ การนำทางด้วยแป้นพิมพ์อยู่ใน[ทางลัดแป้นพิมพ์](/th-TH/คู่มือ/อ้างอิง/ทางลัดแป้นพิมพ์/)

## ขั้นตอนที่ 3: ฝากความคิดเห็นแบบอินไลน์

1. ชี้เมาส์ไปที่บรรทัดหนึ่งใน diff — ป้าย `+` เล็ก ๆ จะปรากฏขึ้นที่รางด้านข้าง
2. คลิกที่มันเพื่อแสดงความคิดเห็นบนบรรทัดนั้น หรือลากขึ้นลงก่อนเพื่อเลือกช่วงบรรทัด
3. พิมพ์ความคิดเห็นของคุณ กล่องเขียนความคิดเห็นมีปุ่มส่งสองแบบ:
   - **เริ่มรีวิว** (หรือ **เพิ่มในรีวิว** หากมีการรีวิวที่กำลังดำเนินอยู่แล้ว) จะเข้าคิวความคิดเห็นไว้ เธรดจะแสดง **รีวิวที่ค้าง** จนกว่าคุณจะส่งคำตัดสินในขั้นตอนที่ 4
   - **เพิ่มความคิดเห็นเดี่ยว** จะโพสต์ไปยัง GitHub ทันที เธรดจะแสดง **กำลังโพสต์…** จากนั้น **ซิงค์แล้ว** และเสนอให้ลองใหม่หากการโพสต์ล้มเหลว

ในบทสอนนี้ ให้ใช้ **เริ่มรีวิว** เพื่อให้ความคิดเห็นออกไปพร้อมกับคำตัดสิน

:::caution[ความคิดเห็นที่เข้าคิวแล้วยังไม่ได้อยู่บน GitHub]
**เริ่มรีวิว** / **เพิ่มในรีวิว** จะเก็บความคิดเห็นไว้ในเครื่องจนกว่าคุณจะส่งคำตัดสิน มีเพียง **เพิ่มความคิดเห็นเดี่ยว** เท่านั้นที่โพสต์ทันที ส่วน_เนื้อหา_รีวิวที่คุณเขียนในขั้นตอนที่ 4 เป็นฉบับร่างแยกต่างหาก
:::

## ขั้นตอนที่ 4: ส่งรีวิว

1. คลิก **รีวิว** ในแถวการกระทำของภาพรวม — ปุ่มเดียวกันนี้ก็อยู่ในแถบเครื่องมือของแท็บ Diff ด้วย มันถูกซ่อนบน PR ที่คุณเป็นผู้เขียน และบน PR ที่ปิดหรือรวมแล้ว
2. เขียนบทสรุปในกล่องเขียนรีวิว มันบันทึกอัตโนมัติเป็นฉบับร่าง คุณจึงปิดโอเวอร์เลย์แล้วกลับมาใหม่ได้
3. เลือกคำตัดสิน:
   - **ขอให้แก้ไข**
   - **ความคิดเห็น**
   - **อนุมัติ**

คำตัดสินคือปุ่มนั้นเอง หลังจาก **อนุมัติ** หรือ **ขอให้แก้ไข** ปุ่มจะเปลี่ยนป้ายของตัวเองเป็น **อนุมัติแล้ว** หรือ **ขอให้แก้ไขแล้ว** ส่วนคำตัดสิน **ความคิดเห็น** จะทำให้ปุ่มยังมีป้ายว่า **รีวิว**

**จุดตรวจสอบ.** ปุ่มจะแสดงข้อความ “อนุมัติแล้ว” หรือ “ขอให้แก้ไขแล้ว” หากคุณเลือกหนึ่งในสองอย่างนั้น

## ขั้นตอนที่ 5: รวม

ปุ่ม **รวม** จะปรากฏทุกครั้งที่ GitHub รายงานว่า PR รวมได้ — มันไม่ได้ถูกกั้นด้วยการอนุมัติของคุณเอง สีของมันบอกความพร้อมมากกว่าสิทธิ์: เป็นแบบหลักเมื่อการอนุมัติที่จำเป็นและการตรวจผ่านครบ เป็นแบบรองขณะที่การตรวจยังรันอยู่ และเป็นแบบอันตรายเมื่อผู้รีวิวที่ถูกร้องขอไม่อนุมัติ หรือมีการตรวจที่ล้มเหลว

1. คลิก **รวม**
2. เลือกวิธีการ: **สควอชแล้วรวม**, **สร้างคอมมิตการรวม** หรือ **รีเบสแล้วรวม**
3. สำหรับสองวิธีแรก ให้แก้ชื่อคอมมิตและข้อความคอมมิตที่กรอกไว้ล่วงหน้า
4. ยืนยัน

ปัญหาที่ค้างอยู่ทั้งหมด — “การตรวจล้มเหลว”, “มีรีวิวที่รออยู่” — จะแสดงในเมนูลอยก่อนที่คุณจะยืนยัน

:::caution[การรวมย้อนกลับไม่ได้]
การรวมจะพุชคอมมิตไปยัง GitHub มันไม่เคยเข้าสแตกเลิกทำของ Control Center และไม่สามารถเลิกทำจากที่นี่ได้
:::

หลังการรวม เหตุการณ์โดเมน `PrMerged` จะถูกยิงขึ้นมา โดยการวิเคราะห์และการแจ้งเตือนเป็นผู้บริโภคมัน ดู[เหตุการณ์โดเมน](/th-TH/คู่มือ/อ้างอิง/เหตุการณ์โดเมน/) ว่ายังมีอะไรที่ฟังอยู่

## รีวิวด้วย AI

Control Center วางไปป์ไลน์รีวิวเวอร์บน PR ที่เปิดอยู่ได้ แต่เฉพาะเมื่อคุณสั่งเท่านั้น: เทมเพลต `pr_review` มีทริกเกอร์แบบสั่งด้วยตนเองและไม่มีอย่างอื่น

1. เปิดเมนู ⋯ ในแถวการกระทำของภาพรวม แล้วเลือก **ถาม AI** Control Center จะเริ่มการรันและเปิดแท็บ **รีวิว PR** เพื่อให้คุณดูผู้เชี่ยวชาญทำงานได้
2. เอเจนต์รีวิวเวอร์บันทึกข้อค้นพบของพวกมันเป็นโหนดรีวิวในสเปซของ PR จากนั้นขั้นตอนสุดท้ายจะรวบรวมมันเป็นรายงานเดียว

ไปป์ไลน์นี้จงใจไม่โพสต์ไปยัง GitHub — มันจบลงหลังการรวบรวม การเผยแพร่เป็นขั้นตอนแยกต่างหากที่คุณทำเอง ด้วยปุ่ม **เผยแพร่ไปยัง GitHub** บนแท็บ **รีวิว PR** ดู[ใช้รีวิวด้วย AI](/th-TH/คู่มือ/วิธีทำ/รีวิวด้วย-ai/)

## สรุป

คุณเปิด PR ในเวิร์กเบนช์ อ่าน diff พร้อมการไฮไลต์ไวยากรณ์ ฝากความคิดเห็นแบบอินไลน์ ส่งคำตัดสิน และรวม — โดยไม่ต้องออกจากแอปเลย
