คู่มือนี้แสดงตำแหน่งที่ข้อมูลรับรองแต่ละรายการที่ Control Center ใช้งานถูกจัดเก็บไว้ และวิธีเปลี่ยนข้อมูลเหล่านั้น

**ไม่มีข้อมูลใดถูกจัดเก็บบนเครื่องที่คุณกำลังพิมพ์อยู่** ข้อมูลรับรองทุกๆ รายการอยู่บนเซิร์ฟเวอร์ และข้อมูลรับรองรายการใดจะตอบสนองคำขอหนึ่ง ๆ ขึ้นอยู่กับว่ามีมนุษย์อยู่เบื้องหลังหรือไม่

| ข้อมูลรับรอง                            | จัดเก็บที่                                                   | ใครใช้งาน                                                          |
| --------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------ |
| ข้อมูลรับรองโฮสต์โค้ด / ตั๋วงานของคุณ    | ไฟล์ข้อมูลลับ 0600 ของเซิร์ฟเวอร์ โดยใช้ user id ของคุณเป็นคีย์ | ทุกสิ่งที่คุณร้องขอ: ระบบ PR, การรันเอเจนต์ของคุณ, อิมเมจของคุณ      |
| ตัวตนแอปของเซิร์ฟเวอร์                   | ไฟล์เดียวกัน บวก `server_settings` สำหรับส่วนที่ไม่ใช่ข้อมูลลับ | งานที่ไม่มีมนุษย์ร้องขอ: webhook, การโพลล์ PR, การซิงค์ตั๋วงาน       |
| คีย์ผู้ให้บริการโมเดลและโทเค็น OAuth     | ที่เก็บข้อมูลรับรองของเซิร์ฟเวอร์เอง                          | อะแดปเตอร์ในตัว สำหรับทุกเวิร์กสเปซบนการติดตั้งนี้                   |
| โทเค็นบอต Slack                          | `<dataDir>/<workspaceId>/chat_credentials/` บนเซิร์ฟเวอร์     | สะพานแชทสำหรับเวิร์กสเปซนั้น                                        |
| ข้อมูลรับรองของ CLI ภายนอก               | แล้วแต่ CLI นั้นใช้งาน                                       | Claude Code บนโฮสต์เซิร์ฟเวอร์                                      |

## ข้อมูลรับรอง GitHub สองรายการที่ตอบคำถามต่างกัน

- **ของคุณ** มาจากการลงชื่อเข้าใช้ (device flow) หรือการวางโทเค็น เป็นสิ่งที่ทุกคำขอที่ทำ *ในนามของคุณ* ใช้ ดังนั้นคอมเมนต์ที่โพสต์แทนคุณจึงมีชื่อของคุณ สมาชิกคนอื่นอ่านข้อมูลนี้ไม่ได้ และจะเชื่อมต่อข้อมูลของตนเอง
- **ของเซิร์ฟเวอร์** มาจาก GitHub App ที่ผู้ดูแลระบบลงทะเบียนไว้ เป็นตัวตอบทุกอย่างที่ไม่มีผู้เรียก ดังนั้นการเข้าถึงโฮสต์โค้ดจึงไม่หายไปเมื่อมีคนลาออกหรือหมุนเวียนโทเค็น

ข้อมูลรับรองของคุณตั้งค่าในการ์ด **โฮสต์โค้ด** ที่ **การตั้งค่า → เวิร์กสเปซ → โปรไฟล์และตัวตน** ส่วนของเซิร์ฟเวอร์ตั้งค่าใน **แอปผู้ให้บริการ** ที่ **การตั้งค่า → เซิร์ฟเวอร์ → ลงชื่อเข้าใช้ครั้งเดียว** ดู[ตั้งค่าการผสาน GitHub](/th-TH/คู่มือ/วิธีทำ/การผสาน-github/) และ[สร้าง GitHub App](/th-TH/คู่มือ/วิธีทำ/github-app/)

:::note[ยังมีหน้าจอที่เข้าถึงได้ด้วย URL เท่านั้น]
`/workspaces/<workspaceId>/api-keys` แสดงการ์ดสองใบเดียวกันกับขั้นตอนแรกของการเริ่มต้นใช้งาน โดย**ไม่มีรายการนำทางอยู่ในส่วนใดของ UI เลย** เข้าถึงได้ด้วยการพิมพ์ URL เท่านั้น ให้ใช้ การตั้งค่า → เวิร์กสเปซ → โปรไฟล์และตัวตน แทน
:::

## ตั้งค่าคีย์ผู้ให้บริการโมเดล

อะแดปเตอร์ในตัวตรวจสอบสิทธิ์กับผู้ให้บริการเอง และข้อมูลรับรองเหล่านั้นอยู่บนเซิร์ฟเวอร์

1. ไปที่ **การตั้งค่า → เซิร์ฟเวอร์ → ผู้ให้บริการโมเดล**
2. เลื่อนไปที่ **ผู้ให้บริการและโมเดล**
3. เชื่อมต่อผู้ให้บริการ — ใช้ OAuth ผ่านเบราว์เซอร์สำหรับ OpenAI, Codex, Cursor และ Kimi Code; ใช้คีย์ API สำหรับ Anthropic และรายอื่น ๆ

ดู[จัดการอะแดปเตอร์และโมเดล](/th-TH/คู่มือ/วิธีทำ/อะแดปเตอร์/) สำหรับรายการทั้งหมด และสำหรับการเพิ่ม endpoint ที่กำหนดเอง

ข้อมูลรับรองเหล่านี้มีผล**ทั่วทั้งโฮสต์**: คีย์เดียวใช้ได้กับทุกเวิร์กสเปซบนการติดตั้งนี้ โทเค็น OAuth จะถูกต่ออายุใหม่ก่อนหมดอายุ

CLI ของอะแดปเตอร์ภายนอกเก็บข้อมูลรับรองของตนเองไว้ในการตั้งค่าของตนเอง บนโฮสต์เซิร์ฟเวอร์ — Control Center ไม่ได้จัดการข้อมูลเหล่านั้น ให้ตรวจสอบสิทธิ์ Claude Code ตามที่เอกสารของมันระบุไว้ บนเครื่องที่ `cc_server` ทำงานอยู่

กล่องโต้ตอบ **ตัวแปรสภาพแวดล้อม** ของแต่ละอะแดปเตอร์ดูเหมือนเป็นที่สำหรับใส่คีย์ของหนึ่งในนั้น แต่ไม่ใช่: กล่องนี้เขียนลงบนอุปกรณ์ของคุณ ขณะที่เซิร์ฟเวอร์อ่านสำเนาของตนเอง และไม่มีอะไรเชื่อมสองฝั่งเข้าด้วยกัน ดู[จัดการอะแดปเตอร์และโมเดล](/th-TH/คู่มือ/วิธีทำ/อะแดปเตอร์/)

## เชื่อมต่อผู้ขายระบบตั๋วงาน

การ์ด **ตั๋วงาน** บน **การตั้งค่า → เวิร์กสเปซ → ทั่วไป** เก็บทั้งสองส่วนของการตัดสินใจเดียว: ตั๋วงานของคุณอยู่กับผู้ขายรายใด และข้อมูลรับรองสำหรับผู้ขายนั้น การเลือก **ในเครื่อง** จะซ่อนแถวข้อมูลรับรอง — ตั๋วงานในเครื่องอยู่ในฐานข้อมูลของเซิร์ฟเวอร์นี้เอง และไม่มีอะไรต้องตรวจสอบสิทธิ์

คีย์ของคุณถูกจัดเก็บบนเซิร์ฟเวอร์โดยผูกกับ user id ของคุณ เช่นเดียวกับคีย์โฮสต์โค้ด เซิร์ฟเวอร์เก็บคีย์ Linear ของตนเองแยกต่างหาก (**แอปผู้ให้บริการ**) ซึ่งเป็นสิ่งที่การซิงค์ตั๋วงานใช้เมื่อไม่มีมนุษย์ร้องขอ ไม่มีคีย์ตั๋วงานใดถูกฉีดเข้าไปในแซนด์บ็อกซ์ของเอเจนต์ เอเจนต์เขียนตั๋วงานผ่านเครื่องมือของ Control Center ซึ่งถามกฎ **เขียนไปยังตัวติดตามภายนอก** ดู[ตั้งค่าการผสาน Linear](/th-TH/คู่มือ/วิธีทำ/การผสาน-linear/)

## หมุนเวียนหรือเพิกถอน

- **ข้อมูลรับรอง GitHub ของคุณ**: กด **ยกเลิกการเชื่อมต่อ** แล้วลงชื่อเข้าใช้อีกครั้งหรือวางโทเค็นใหม่ จากนั้นเพิกถอนโทเค็นเดิมบน GitHub
- **แอปของเซิร์ฟเวอร์**: สร้าง private key หรือ client secret ใหม่บนหน้า GitHub ของแอป วางใน **แอปผู้ให้บริการ** แล้วกด **ทดสอบ**
- **ผู้ให้บริการโมเดล**: ที่แถวของมัน ให้ลงชื่อออก (OAuth) หรือลบคีย์ แล้วเชื่อมต่ออีกครั้ง
- **Slack**: วางโทเค็นอีกครั้งในกล่องโต้ตอบการเชื่อมต่อ ดู[ตั้งค่าการผสาน Slack](/th-TH/คู่มือ/วิธีทำ/การผสาน-slack/)

## การแก้ปัญหา

### รายการ PR ว่างเปล่า แต่โทเค็นของฉันใช้ได้ใน `curl`

ตรวจสอบคำบรรยายใต้แถว **โฮสต์โค้ด** หากระบุแหล่งอื่น ("ผ่านแอปของเซิร์ฟเวอร์นี้", "จากสภาพแวดล้อม") แสดงว่าข้อมูลรับรองที่คุณกำลังทดสอบไม่ใช่ตัวที่ตอบสนอง — ของคุณยังไม่ได้ถูกบันทึก

### โทเค็นได้รับการยอมรับ แต่คำขอภายหลังล้มเหลว

โทเค็นจะถูกตรวจสอบตามที่จัดเก็บไว้ แถวจึงระบุบัญชีที่อยู่เบื้องหลัง — แต่ระบุเพียงบัญชี ไม่ได้ระบุขอบเขตสิทธิ์ โทเค็นที่มีขอบเขตสิทธิ์น้อยเกินไปจะเชื่อมต่อได้ แต่จะล้มเหลวเมื่อมีคำขอแต่ละรายการ ตรวจสอบขอบเขตสิทธิ์และวันหมดอายุ:

```bash
curl -H "Authorization: token YOUR_TOKEN" https://api.github.com/user
```
