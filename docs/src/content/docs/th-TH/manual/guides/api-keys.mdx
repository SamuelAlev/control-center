คู่มือนี้อธิบายว่าข้อมูลรับรองแต่ละรายการที่ Control Center ใช้ถูกเก็บไว้ที่ไหน และวิธีเปลี่ยนแปลงข้อมูลเหล่านั้น

**บนอุปกรณ์ที่คุณกำลังพิมพ์อยู่ไม่มีการจัดเก็บอะไรเลย** ข้อมูลรับรองทั้งหมดอยู่บนเซิร์ฟเวอร์ ส่วนข้อมูลรับรองใดจะตอบคำขอ ขึ้นอยู่กับว่ามีคนจริงอยู่เบื้องหลังหรือไม่

| ข้อมูลรับรอง                         | ที่เก็บ                                                   | ผู้ใช้                                                          |
| ------------------------------------ | --------------------------------------------------------- | ---------------------------------------------------------------- |
| การลงชื่อเข้าใช้โฮสต์โค้ด / ตั๋วงานของคุณ | ไฟล์ความลับ 0600 ของเซิร์ฟเวอร์ โดยใช้ user id ของคุณเป็นคีย์ | สิ่งที่คุณทำ: หน้า PR, รีวิว, การรวม, การกระทำ Linear ของคุณ |
| แอปผู้ให้บริการของเซิร์ฟเวอร์          | ไฟล์เดียวกัน พร้อม `server_settings` สำหรับค่าที่ไม่ใช่ความลับ | การลงชื่อเข้าใช้คน และโทเค็นรีโปเดียวสำหรับเอเจนต์ ไปป์ไลน์ และการโพลล์ |
| คีย์การติดตั้ง Connect                 | ไฟล์เดียวกัน (`connect_install_key`)                      | ระบุเซิร์ฟเวอร์นี้ต่อ Control Center Connect                    |
| คีย์ผู้ให้บริการโมเดลและโทเค็น OAuth | ที่เก็บข้อมูลรับรองของเซิร์ฟเวอร์เอง                      | อะแดปเตอร์ในตัว สำหรับทุกเวิร์กสเปซบนการติดตั้งนั้น               |
| ข้อมูลรับรองบอต Slack                 | `<dataDir>/<workspaceId>/chat_credentials/` บนเซิร์ฟเวอร์ | สะพานแชทของเวิร์กสเปซนั้น: โทเค็นของแอปของคุณเอง หรือการอนุญาตที่ปิดผนึกของแอปที่ใช้ร่วมกัน |
| ข้อมูลรับรอง CLI ภายนอก              | ที่เก็บที่ CLI นั้นใช้                                    | Claude Code บนโฮสต์ของเซิร์ฟเวอร์                                 |

## GitHub: การลงชื่อเข้าใช้ของคุณ และโทเค็นรีโปเดียว

- **ของคุณเอง** จาก **ลงชื่อเข้าใช้ GitHub** คำขอทุกคำที่ทำ *ในนามของคุณ* ใช้ข้อมูลนี้ ดังนั้นรีวิวที่โพสต์ในนามของคุณจะมีชื่อของคุณ สมาชิกคนอื่นใช้ไม่ได้ และพวกเขาต้องลงชื่อเข้าใช้เอง ไม่มีโทเค็น GitHub ให้วาง
- **งานที่ไม่มีคนพิมพ์อยู่** (เอเจนต์ ไปป์ไลน์ การโพลล์ การตอบกลับของบอต) จะได้โทเค็นสำหรับหนึ่งรีโปในแต่ละครั้ง ออกโดย GitHub App ของเซิร์ฟเวอร์ หรือผ่าน Control Center Connect และจำกัดให้อยู่ในสิ่งที่สมาชิกที่รับผิดชอบทำได้บนรีโปนั้น โทเค็นนี้ไม่เคยเป็นการลงชื่อเข้าใช้ของคุณที่ส่งต่อทั้งชุด

การลงชื่อเข้าใช้ GitHub ของคุณตั้งค่าใน การ์ด **โฮสต์โค้ด** ที่ **การตั้งค่า → เวิร์กสเปซ → โปรไฟล์และตัวตน** ส่วนแอปของเซิร์ฟเวอร์ตั้งค่าใน **แอปผู้ให้บริการ** ที่ **การตั้งค่า → เซิร์ฟเวอร์ → ลงชื่อเข้าใช้ครั้งเดียว** ดู[ตั้งค่าการผสาน GitHub](/th-TH/คู่มือ/วิธีทำ/การผสาน-github/) และ[สร้าง GitHub App](/th-TH/คู่มือ/วิธีทำ/github-app/)

GitLab และ Bitbucket ยังคงใช้โทเค็นส่วนบุคคลที่วางไว้ และเก็บไว้ในลักษณะเดียวกัน ดู[เชื่อมต่อโฮสต์โค้ด](/th-TH/คู่มือ/วิธีทำ/เชื่อมต่อโฮสต์โค้ด/)

:::note[ยังมีหน้าจอที่เข้าถึงได้ด้วย URL เท่านั้น]
`/workspaces/<workspaceId>/api-keys` แสดงการ์ดสองใบเหมือนขั้นตอนแรกของการเริ่มต้นใช้งาน ไม่มี**รายการนำทางใดในอินเทอร์เฟซเลย** เข้าถึงได้โดยพิมพ์ URL เท่านั้น ให้ใช้ การตั้งค่า → เวิร์กสเปซ → โปรไฟล์และตัวตน แทน
:::

## ตั้งค่าคีย์ของผู้ให้บริการโมเดล

อะแดปเตอร์ในตัวยืนยันตัวตนกับผู้ให้บริการด้วยตัวเอง ข้อมูลรับรองเหล่านี้เก็บไว้บนเซิร์ฟเวอร์

1. ไปที่ **การตั้งค่า → เซิร์ฟเวอร์ → ผู้ให้บริการโมเดล**
2. เลื่อนลงไปยัง **ผู้ให้บริการและโมเดล**
3. เชื่อมต่อผู้ให้บริการ — OpenAI, Codex, Cursor และ Kimi Code ใช้ OAuth ผ่านเบราว์เซอร์; Anthropic และอื่น ๆ ใช้คีย์ API

รายการทั้งหมดและวิธีเพิ่ม endpoint แบบกำหนดเอง ดู[จัดการอะแดปเตอร์และโมเดล](/th-TH/คู่มือ/วิธีทำ/อะแดปเตอร์/)

ข้อมูลรับรองเหล่านี้เป็นแบบ**ระดับโฮสต์** คีย์เดียวให้บริการทุกเวิร์กสเปซบนการติดตั้งนั้น โทเค็น OAuth จะรีเฟรชก่อนหมดอายุ

อะแดปเตอร์ CLI ภายนอกเก็บข้อมูลรับรองของตัวเองไว้ในการตั้งค่าของตัวเองบนโฮสต์ของเซิร์ฟเวอร์ — Control Center ไม่ได้จัดการสิ่งเหล่านี้ ให้ยืนยันตัวตนบนเครื่องที่รัน `cc_server` ตามเอกสารของ Claude Code เอง

ไดอะล็อก **ตัวแปรสภาพแวดล้อม** ของแต่ละอะแดปเตอร์ดูเหมือนเป็นที่สำหรับวางคีย์หนึ่งในนั้น แต่ไม่ใช่: มันเขียนลงอุปกรณ์ของคุณ ขณะที่เซิร์ฟเวอร์อ่านสำเนาของตัวเอง โดยไม่มีสะพานเชื่อมระหว่างทั้งสอง ดู[จัดการอะแดปเตอร์และโมเดล](/th-TH/คู่มือ/วิธีทำ/อะแดปเตอร์/)

## เชื่อมต่อผู้ให้บริการตั๋วงาน

การ์ด **ระบบตั๋วงาน** ใน **การตั้งค่า → เวิร์กสเปซ → ทั่วไป** รวมสองส่วนของการตัดสินใจเดียวกัน: ตั๋วของคุณอยู่กับผู้ให้บริการรายใด และ Control Center ทำตัวเป็นใครเมื่อคุยกับมัน การเลือก **ในเครื่อง** จะซ่อนแถว Linear — ตั๋วในเครื่องอยู่ในฐานข้อมูลของเซิร์ฟเวอร์นี้เอง และไม่มีอะไรต้องยืนยันตัวตน

Linear มีการลงชื่อเข้าใช้สองแบบและไม่ต้องวางคีย์: **Linear** เป็นของคุณ สำหรับสิ่งที่คุณทำ และ **ระบบอัตโนมัติของ Linear** คือแอป Control Center ของเวิร์กสเปซ ซึ่งผู้ดูแลเชื่อมต่อ ใช้สำหรับการซิงค์ตั๋ว ไปป์ไลน์ และเอเจนต์ เซิร์ฟเวอร์อาจมี **คีย์ API ของบริการ** (**แอปผู้ให้บริการ**) สำหรับเวิร์กสเปซที่ยังไม่ได้เชื่อมต่อระบบอัตโนมัติ ไม่มีข้อมูลรับรองตั๋วงานถูกฉีดเข้าไปในแซนด์บ็อกซ์ของเอเจนต์ เอเจนต์เขียนตั๋วผ่านเครื่องมือของ Control Center ซึ่งจะถามกฎ **เขียนไปยังตัวติดตามภายนอก** ก่อน ดู[ตั้งค่าการผสาน Linear](/th-TH/คู่มือ/วิธีทำ/การผสาน-linear/)

## เปลี่ยนหรือเพิกถอน

- **การลงชื่อเข้าใช้ GitHub ของคุณ:** กด **ยกเลิกการเชื่อมต่อ** แล้วกด **ลงชื่อเข้าใช้ GitHub** อีกครั้ง การยกเลิกการเชื่อมต่อจะทิ้งโทเค็นทั้งหมดที่เซิร์ฟเวอร์ออกให้ในนามของคุณด้วย
- **โทเค็น GitLab หรือ Bitbucket:** กด **อัปเดตโทเค็น** แล้ววางโทเค็นใหม่ จากนั้นเพิกถอนโทเค็นเก่าบนแพลตฟอร์ม
- **แอปของเซิร์ฟเวอร์:** สร้างคีย์ส่วนตัวหรือ client secret ใหม่บนหน้าแอปของผู้ให้บริการ วางใน **แอปผู้ให้บริการ** แล้วกด **ทดสอบ**
- **คีย์การติดตั้ง Connect:** กด **หมุนเวียนคีย์** ในการ์ด **Control Center Connect** หรือรัน `cc_server connect rotate-key --yes` ทุกคนที่ลงชื่อเข้าใช้ผ่าน Connect จะต้องลงชื่อเข้าใช้ใหม่ ดู [Control Center Connect](/th-TH/คู่มือ/อ้างอิง/connect/)
- **ผู้ให้บริการโมเดล:** บนแถวของมัน ให้ออกจากระบบ (OAuth) หรือลบคีย์ แล้วเชื่อมต่ออีกครั้ง
- **Slack:** สำหรับแอปของคุณเอง ให้วางโทเค็นใหม่ในไดอะล็อกการเชื่อมต่ออีกครั้ง แอปที่ใช้ร่วมกันของ Control Center ไม่มีโทเค็นให้หมุนเวียน: โทเค็นบอตของมันจะต่ออายุผ่าน Connect และ **ยกเลิกการเชื่อมต่อ** จะเพิกถอนมันและถอนการติดตั้งบอตจาก Slack ดู[ตั้งค่าการผสาน Slack](/th-TH/คู่มือ/วิธีทำ/การผสาน-slack/)

## การแก้ปัญหา

### โทเค็น GitLab หรือ Bitbucket ใช้ได้กับ `curl` แต่ไม่ใช้ได้ที่นี่

ตรวจดูคำบรรยายใต้ชื่อของแถว **โฮสต์โค้ด** หากขึ้นว่า “จากสภาพแวดล้อม” ข้อมูลรับรองที่ตอบอยู่คือของเซิร์ฟเวอร์ ไม่ใช่ของคุณ — โทเค็นของคุณยังไม่ได้ถูกบันทึก

### โทเค็นถูกยอมรับ แต่คำขอหลังจากนั้นล้มเหลว

โทเค็นถูกตรวจสอบขณะจัดเก็บ ดังนั้นแถวจะบอกบัญชีที่เป็นเจ้าของ — แต่แสดงเฉพาะบัญชี ไม่ใช่สโคป โทเค็นที่สโคปน้อยเกินไปจะเชื่อมต่อได้ แต่คำขอบางรายการจะล้มเหลว ให้ตรวจสอบสโคปและวันหมดอายุบนแพลตฟอร์ม

### ผู้ให้บริการแจ้งว่ายังไม่ได้ตั้งค่าการลงชื่อเข้าใช้บนเซิร์ฟเวอร์นี้

เซิร์ฟเวอร์ไม่มีทั้งแอปของตัวเองสำหรับผู้ให้บริการนั้น และไม่มี Control Center Connect เจ้าของเซิร์ฟเวอร์เลือกหนึ่งอย่างได้ใน **การตั้งค่า → เซิร์ฟเวอร์ → ลงชื่อเข้าใช้ครั้งเดียว**
