คู่มือนี้แสดงวิธีทำงานกับ Control Center โดยไม่ต้องออกจาก GitHub: ขอรีวิวด้วย AI
จากหน้า PR ถามคำถามกับบอตในความคิดเห็น และสนทนาต่อในเธรดรีวิวของมัน

การตอบกลับจะส่งผ่านช่องทาง GitHub ของเวิร์กสเปซ: คือ [GitHub App](/th-TH/คู่มือ/วิธีทำ/github-app/) ของเซิร์ฟเวอร์เอง หรือแอปที่ใช้ร่วมกันของ Control Center ผ่าน Connect ไม่มีอะไรต้องลงทะเบียนใหม่ และไม่มีอะไรต้องเข้าถึงได้จากอินเทอร์เน็ต: เซิร์ฟเวอร์ค้นพบสิ่งที่ถูกพูดบน GitHub
ด้วยการโพลล์ ดังนั้นโน้ตบุ๊กที่อยู่หลัง NAT จึงทำงานเหมือนการปรับใช้แบบสาธารณะ
ทุกประการ

## ก่อนเริ่ม

- เวิร์กสเปซมีช่องทาง GitHub: GitHub App ของเซิร์ฟเวอร์เองหรือ Connect โดยแอปถูก[ติดตั้ง](/th-TH/คู่มือ/วิธีทำ/github-app/#ติดตั้งในที่ที่รีโพของคุณอยู่)บนบัญชีที่เป็นเจ้าของรีโพ แอปของตัวเองต้องมีสิทธิ์ **Pull requests** และ **Issues** แบบอ่านและเขียน ซึ่ง **สร้างแอป GitHub ของฉัน** ให้อยู่แล้ว
- รีโพสิทอรีถูกเชื่อมกับเวิร์กสเปซใน Control Center
- คุณได้[ลงชื่อเข้าใช้ GitHub](/th-TH/คู่มือ/วิธีทำ/การผสาน-github/)บนเซิร์ฟเวอร์นี้ และคุณสามารถพุชไปยังรีโพได้
- ไม่มี URL ของ webhook ไม่มีทันเนล ไม่มี callback — ไม่มีอะไรต้องตั้งค่าฝั่งเครือข่าย

## ค้นหาชื่อบอตของคุณ

กล่าวถึง `@usectrl` ซึ่งเป็นบัญชี GitHub เฉพาะของ Control Center นี่เป็นตัวเรียกใช้งานเพียงตัวเดียว: การกล่าวถึงบัญชีของ App เองไม่ทำอะไรเลย ช่องทาง GitHub ของเวิร์กสเปซยังคงจัดการคำขอและโพสต์คำตอบ คุณไม่ต้องใช้ข้อมูลรับรองของบัญชี `usectrl`

## ขอรีวิวจาก GitHub

มีสองวิธี ทั้งคู่เริ่มไปป์ไลน์ `pr_review` ที่มาพร้อมระบบแบบเดียวกับที่ปุ่ม
**ถาม AI** เริ่ม:

- **เพิ่มป้ายกำกับ `ai-review`** ให้ PR นี่คือสิ่งที่ใกล้เคียงที่สุดที่ GitHub
  เสนอให้เทียบเท่าการมอบหมายบอตเป็นรีวิวเวอร์ — บัญชีแอปไม่อาจครองช่อง
  ผู้ขอรีวิวแบบเนทีฟได้ บัญชีของคุณจะแสดงปฏิกิริยา 👀 บน PR และรีวิวจะเริ่มใน Control Center โดยไม่มีความคิดเห็นถูกโพสต์
- **แสดงความคิดเห็น `@usectrl review`** (หรือแค่ `@usectrl`) ในบทสนทนาของ PR
  จะมี 👀 ปรากฏบนความคิดเห็นของคุณ แล้วคำตอบจะแจ้งว่ารีวิวเริ่มทำงานแล้ว (หรือแจ้งว่ามีรีวิวกำลังรันอยู่แล้ว)

รีวิวเวอร์ทำงานในสเปซรีวิวของ PR อ่านและเผยแพร่ข้อค้นพบได้ตามใน
[ใช้รีวิวด้วย AI](/th-TH/คู่มือ/วิธีทำ/รีวิวด้วย-ai/) การเผยแพร่กลับไปยัง GitHub
ยังเป็นการตัดสินใจที่คุณทำใน Control Center — การเริ่มรีวิวจาก GitHub
ไม่ได้เผยแพร่อะไรไปยัง GitHub ด้วยตัวเอง

ป้ายกำกับจะทำงานครั้งเดียวต่อ PR: การเพิ่มมันคือคำขอ และมันจะไม่ถูกตั้งกลับ
เมื่อลบออกแล้วเพิ่มใหม่ หากต้องการรันรีวิวอีกครั้ง — เช่นหลังพุช — ให้กล่าวถึงบอต

## ถามคำถาม

แสดงความคิดเห็นในบทสนทนาของ PR:

```text
@usectrl why does the flaky test in runner_test.dart fail on CI but not locally?
```

สิ่งที่เกิดขึ้น ตามลำดับ:

1. จะมี 👀 ปรากฏบนความคิดเห็นของคุณ เพื่อให้คุณรู้ว่าความคิดเห็นถูกเห็นแล้ว
2. คำถามถูกโพสต์เข้าสเปซรีวิวของ PR **ในนามของคุณ** — การระบุที่มาแบบเดียวกับ
   ที่คุณพิมพ์เองใน Control Center
3. เอเจนต์ตอบในสเปซ และคำตอบจะกลับไปแสดงบน PR เป็นความคิดเห็น โดยทุกคำตอบขึ้นต้นด้วย `**Control Center** (for @your-login):`

คำถามบน PR ที่ยังไม่มีรีวิวจะปลุกเอเจนต์หัวหน้า (CEO) ของเวิร์กสเปซ เมื่อรีวิว
รันไปแล้ว เอเจนต์ที่พูดเป็นคนสุดท้ายจะเป็นผู้ตอบ คำถามต่อยอดจึงตกอยู่กับคนที่มี
บริบท

## ติดตามต่อในเธรดรีวิว

ตอบกลับภายในเธรดรีวิวแบบอินไลน์ที่บอตเป็นส่วนหนึ่ง — ความคิดเห็นบน diff ที่มัน
ทิ้งไว้ หรือคำตอบที่มันโพสต์ในเธรดนั้น ไม่จำเป็นต้องกล่าวถึง ตัวเธรด**คือ**
การระบุเป้าหมาย:

```text
> @usectrl the retry loop looks O(n²) to me

what would the complexity be with the bounded queue instead?
```

การสนทนาหลายรอบก็ทำงานแบบเดียวกัน: แต่ละการตอบกลับคือคำถามอีกข้อในบทสนทนาเดิม
โดยมีสเปซรีวิวเป็นบริบท และคำตอบก็กลับมาในเธรด

การติดตามต่อบนไทม์ไลน์ของบทสนทนา PR ถือเป็นความคิดเห็นระดับบนสุดใหม่ จึงยังต้องมี
@mention

## บอตคุยกับใคร

เซิร์ฟเวอร์จะแยกผู้เขียนของความคิดเห็น (หรือผู้ที่เพิ่มป้ายกำกับ `ai-review`) ก่อนดำเนินการใด ๆ:

- **บัญชี GitHub ต้องลงชื่อเข้าใช้บนเซิร์ฟเวอร์นี้** การจับคู่ใช้ ID บัญชีตัวเลขของ GitHub ไม่ใช่ login ลงชื่อเข้าใช้จาก **การตั้งค่า → คุณ → โปรไฟล์ → โฮสต์โค้ด**
- **ต้องเป็นสมาชิกที่มีบทบาทแบบเขียน** (`member`, `admin` หรือ `owner`)
  ในเวิร์กสเปซที่เชื่อมรีโพสิทอรีนั้น
- **ต้องมีสิทธิ์พุช** ไปยังรีโพบน GitHub คำตอบใช้โทเค็นที่จำกัดตามสิทธิ์การเข้าถึงของบุคคลนั้น ดังนั้นคนที่อ่านได้อย่างเดียวจะไม่ได้รับคำตอบ

คนอื่นจะถูกเพิกเฉยอย่างเงียบ ๆ: ไม่มีการโพสต์อะไร และถ้อยคำของพวกเขาจะไม่เข้าไปในเวิร์กสเปซ ความคิดเห็นจากบอต และคำตอบของ Control Center เองจะไม่ถูกมองเป็นคำถามเลย

### สองเซิร์ฟเวอร์ หนึ่ง PR

👀 ยังเป็นวิธีที่เซิร์ฟเวอร์ตกลงกันว่าใครจะตอบ มันถูกเพิ่มด้วยการลงชื่อเข้าใช้ของผู้เขียน และ GitHub บอกเซิร์ฟเวอร์ว่าปฏิกิริยานั้นเป็นของใหม่หรือไม่ หากคุณลงชื่อเข้าใช้บนเซิร์ฟเวอร์ Control Center สองเครื่องที่เชื่อมรีโพเดียวกัน เครื่องที่กดก่อนจะตอบ และอีกเครื่องจะเงียบ สิ่งเดียวกันใช้กับป้ายกำกับด้วย

## สิ่งที่ควรคาดหวัง

| สิ่ง                | พฤติกรรม                                                                 |
| ------------------- | ------------------------------------------------------------------------ |
| การตอบรับ           | 👀 จากบัญชีของคุณบนความคิดเห็น (หรือบน PR สำหรับป้ายกำกับ) ภายในหนึ่งรอบการกวาด |
| คำตอบ               | โพสต์ในช่องทางที่คำถามถูกถาม ขึ้นต้นด้วย `**Control Center** (for @your-login):` ผู้เขียนคือบอตของแอป บนแอป Connect ที่ใช้ร่วมกัน คำตอบภายในเธรดรีวิวจะเป็นของบัญชีของคุณเอง เว้นแต่ผู้ดำเนินการ Connect จะระบุการติดตั้งนี้ |
| การระบุที่มาในสเปซ  | คำถามเป็นของคุณ เอเจนต์รันในนามของคุณ ภายใต้การตั้งค่าความเป็นอิสระของสเปซ |
| รีวิว               | ข้อค้นพบลงในสเปซรีวิว การเผยแพร่ไปยัง GitHub ต้องทำด้วยมือ                 |

บนแอปของตัวเอง การกวาดทำงานทุกนาทีและตรวจ PR ได้ไม่เกิน 25 รายการ ผ่าน Connect ทำงานทุกสองนาทีและตรวจได้ไม่เกิน 10 รายการ เพราะการเรียกเหล่านี้ใช้โควต้า GitHub ของสมาชิกแต่ละคนร่วมกัน เวิร์กสเปซที่โควต้า GitHub ต่ำกว่า 15% จะถูกข้ามจนกว่าจะฟื้นตัว ความหน่วงคือสิ่งที่แลกมากับการไม่ต้องมีการเข้าถึงเครือข่ายขาเข้าเลย ไม่มีอะไรสูญหายขณะเซิร์ฟเวอร์ออฟไลน์ — ความคิดเห็นที่มาถึงช่วงดาวน์ไทม์จะถูกเก็บในรอบกวาดถัดไป

## การแก้ปัญหา

**ไม่เกิดอะไรขึ้นกับความคิดเห็นที่กล่าวถึงบอต**

- แอปถูก**ติดตั้ง**บนบัญชีที่เป็นเจ้าของรีโพแล้วหรือยัง และรีโพถูก**เชื่อม**
  กับเวิร์กสเปซหรือยัง รีโพที่ยังไม่ถูกเชื่อมจะถูกข้ามก่อนที่จะมีการบันทึกสิ่งใด
  ดังนั้นการเชื่อมมันในภายหลังยังคงได้ผล
- คุณได้ลงชื่อเข้าใช้ GitHub บนเซิร์ฟเวอร์นี้ คุณเป็นสมาชิกที่มีบทบาทแบบเขียน และสามารถพุชไปยังรีโพได้หรือไม่ เซิร์ฟเวอร์จะเพิกเฉยต่อคนอื่นโดยไม่ตอบ
- ยังไม่มีอะไรเกิดขึ้นอีกหรือ บันทึกของเซิร์ฟเวอร์จะระบุรอบกวาดและ PR เมื่อมี
  อะไรล้มเหลว ให้มองหา `pr_conversation:` (ตัวโพลล์) และ
  `github_pr_conversation:` (สะพาน)

**ป้ายกำกับไม่เริ่มรีวิว**

มันทำงานครั้งเดียวต่อ PR และคนที่เพิ่มป้ายกำกับต้องผ่านการตรวจเดียวกับผู้เขียนความคิดเห็น หากรีวิวรันไปแล้ว หรือป้ายกำกับถูกเพิ่มก่อนที่
เซิร์ฟเวอร์จะเห็น PR นี้เลย (การกวาดครั้งแรกจะบันทึกงานที่ค้างอยู่ไว้อย่างเงียบ ๆ
แทนที่จะกระหน่ำรันทั้งหมด) ให้กล่าวถึงบอตแทน — `@usectrl review` เริ่มรีวิวเสมอ
เว้นแต่มีรีวิวกำลังดำเนินอยู่แล้ว

**คำตอบของบอตไม่มาถึง GitHub เลย**

ตัวคำตอบไม่เคยสูญหาย — มันอยู่ในสเปซรีวิวของ PR ใน Control Center ความล้มเหลว
ในการโพสต์ (GitHub ล่ม สิทธิ์เปลี่ยนไป) จะถูกบันทึกไว้ และคำตอบจะไม่ถูกลองใหม่
หากสำคัญให้ถามอีกครั้งในเธรด

## คู่มือที่เกี่ยวข้อง

- [สร้าง GitHub App](/th-TH/คู่มือ/วิธีทำ/github-app/): การลงทะเบียนที่ให้กำเนิดตัวตนของบอตของแอปตัวเอง
- [ใช้รีวิวด้วย AI](/th-TH/คู่มือ/วิธีทำ/รีวิวด้วย-ai/): การอ่านข้อค้นพบที่รีวิวซึ่ง
  เริ่มด้วยการกล่าวถึงสร้างขึ้น
- [ตั้งค่าการผสาน GitHub](/th-TH/คู่มือ/วิธีทำ/การผสาน-github/): การเชื่อมบัญชี
  GitHub ของคุณเอง ซึ่งเป็นสิ่งที่บอตใช้ระบุตัวคุณ
- [ใช้สเปซ](/th-TH/คู่มือ/วิธีทำ/สเปซ/): ห้องที่ทุกอย่างนี้ไปลงเอย
