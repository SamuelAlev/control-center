Control Center ทำงานกับโฮสต์โค้ดสามเจ้า ซึ่งแอปนี้เรียกว่า **ฟอร์จ** ตลอดทั้งแอป: **GitHub**, **GitLab** และ **Bitbucket Cloud** ไม่มีเจ้าใดเป็นค่าเริ่มต้น เชื่อมต่อเจ้าเดียวแล้วทุกอย่างก็ทำงาน เชื่อมหลายเจ้าและเวิร์กสเปซเดียวก็เก็บรีโปจากทุกเจ้าได้พร้อมกัน

ฟอร์จเป็นคุณสมบัติของแต่ละ**รีโป** โดยอ่านจาก remote `origin` ของมันตอนที่คุณลงทะเบียน คุณไม่ต้องเลือกเอง และไม่มีตั้งค่าใดต่อเวิร์กสเปซที่จะตั้งผิดได้

## เชื่อมต่อฟอร์จ

1. เปิด **การตั้งค่า → คุณ → โปรไฟล์** (`/settings/you/profile`)
2. หาการ์ด **โฮสต์โค้ด** ฟอร์จที่รองรับทั้งหมดจะอยู่ในรายการ ไม่ว่าเชื่อมต่อแล้วหรือไม่
3. ใน **GitHub** กด **ลงชื่อเข้าใช้ GitHub** ใน **GitLab** หรือ **Bitbucket** กด **เพิ่มโทเค็น** แล้ววางโทเค็นลงไป

**GitHub รองรับการลงชื่อเข้าใช้เท่านั้น** การลงชื่อเข้าใช้ทำงานผ่านแอป GitHub ของเซิร์ฟเวอร์เอง หรือ Control Center Connect ขึ้นอยู่กับที่เจ้าของเซิร์ฟเวอร์ตั้งค่าไว้ หรือผ่านแอปที่ผู้ดูแลเวิร์กสเปซเลือกไว้สำหรับเวิร์กสเปซนี้ใน**การตั้งค่า → เวิร์กสเปซ → การผสานรวม** (ดู [ตั้งค่าการผสาน GitHub](/th-TH/คู่มือ/วิธีทำ/การผสาน-github/)) จึงไม่มีโทเค็น GitHub ให้วาง GitLab และ Bitbucket ยังใช้โทเค็นส่วนบุคคล

ไม่ว่าจะทางไหน ข้อมูลรับรองเป็น**ของคุณและอยู่บนเซิร์ฟเวอร์** โดยใช้ user id ของคุณเป็นคีย์: ไม่มีโทเค็นถูกเก็บไว้บนเครื่องที่คุณพิมพ์มันลงไป ทุกอุปกรณ์ที่คุณลงชื่อเข้าใช้ใช้โทเค็นเดียวกัน และสมาชิกคนอื่นอ่านมันไม่ได้ มันมีผลตั้งแต่**คำขอถัดไป** — ไม่มีอะไรต้องรีสตาร์ต และการยกเลิกการเชื่อมต่อจะหยุดส่งมันทันที

การ์ดบอกว่าบัญชีของคุณถูกใช้ที่ไหน โทเค็น GitLab หรือ Bitbucket เป็นของคุณใน**ทุกเวิร์กสเปซบนเซิร์ฟเวอร์** จึงวางเพียงครั้งเดียว การลงชื่อเข้าใช้ GitHub ของคุณก็เช่นกัน เว้นแต่เวิร์กสเปซจะมีแอปลงชื่อเข้าใช้ของตัวเอง เวิร์กสเปซนั้นจะมีการลงชื่อเข้าใช้ GitHub ของตัวเอง และการ์ดจะระบุชื่อไว้

แต่ละแถวแสดงสถานะของ**ข้อมูลรับรองของคุณ** มีเพียงข้อมูลรับรองของคุณเองเท่านั้นที่ตอบแทนคุณได้ ไม่มีอย่างอื่นมาแทนที่:

| แถวแสดงว่า                                                            | ความหมาย                                                                                                                                  |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `ลงชื่อเข้าใช้เป็น octocat`                                            | ข้อมูลรับรองของคุณเองเป็นตัวที่ถูกใช้                          |
| `ยังไม่เชื่อมต่อ`                                                      | คุณไม่มีข้อมูลรับรองสำหรับฟอร์จนี้                                                                                                          |
| `การลงชื่อเข้าใช้ GitHub ของคุณในชื่อ octocat หมดอายุแล้ว ลงชื่อเข้าใช้อีกครั้ง` | การลงชื่อเข้าใช้ของคุณหมดอายุหรือถูกเพิกถอนบนฟอร์จ                                                                                         |
| `หยุดชั่วคราว: บริการลงชื่อเข้าใช้ของเวิร์กสเปซนี้เปลี่ยนไป`            | เวิร์กสเปซเปลี่ยนไปใช้บริการลงชื่อเข้าใช้อีกตัว การลงชื่อเข้าใช้ของคุณยังคงอยู่และกลับมาทำงานได้หากเปลี่ยนกลับ จึงไม่มีปุ่มลงชื่อเข้าใช้ |
| `ติดต่อ GitHub ไม่ได้ในขณะนี้ กำลังลองใหม่`                              | ระบบขัดข้องชั่วคราว Control Center จะลองใหม่ต่อไปและคุณไม่ต้องทำอะไร                                                                       |
| ประโยคที่อธิบายว่าทำไมการลงชื่อเข้าใช้จึงไม่พร้อมใช้งาน                 | เช่น `ยังไม่ได้ตั้งค่าการลงชื่อเข้าใช้ด้วย GitHub สำหรับเวิร์กสเปซนี้` หรือ `บริการลงชื่อเข้าใช้ของเวิร์กสเปซนี้เปลี่ยนตัวตนแล้ว ผู้ดูแลต้องยืนยัน` ผู้ดูแลจะมีปุ่มไปยังการตั้งค่าที่แก้ปัญหาได้ |

### แต่ละฟอร์จต้องการโทเค็นแบบไหน

| ฟอร์จ           | โทเค็น                                                                                                             | สร้างได้ที่ไหน                                             |
| --------------- | ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| **GitLab**      | โทเค็นการเข้าถึงส่วนบุคคลที่มี `api`                                                                                | gitlab.com → User settings → Access tokens                 |
| **Bitbucket**   | API token ของ Atlassian บวกอีเมลบัญชีของคุณ                                                                        | id.atlassian.com → Security → API tokens                   |

Bitbucket ยืนยันตัวตนด้วย**อีเมลบัญชีของคุณเป็นชื่อผู้ใช้** และใช้ API token เป็นรหัสผ่าน ดังนั้นไดอะล็อกของ Bitbucket จะขอทั้งสองอย่าง โทเค็นการเข้าถึงของรีโป โปรเจกต์ หรือเวิร์กสเปซของ Bitbucket ไม่ใช่ของบุคคลใด ดังนั้นไดอะล็อกนี้จะปฏิเสธมัน: มันคือ[โทเค็นระบบอัตโนมัติ](#เพิ่มโทเค็นระบบอัตโนมัติ)แทน เช่นเดียวกันกับ**โทเค็นการเข้าถึงโปรเจกต์**หรือ**กลุ่ม**ของ GitLab: GitLab จะถามว่าโทเค็นนั้นเป็นของใครก่อนบันทึก และโทเค็นของบอตจะถูกปฏิเสธที่นี่

โทเค็นไม่เคยผูกกับเวิร์กสเปซเดียว: คุณถือโทเค็นหนึ่งอันต่อฟอร์จ และทุกเวิร์กสเปซบนเซิร์ฟเวอร์ใช้โทเค็นนั้น **ยกเลิกการเชื่อมต่อ** จะลบมันสำหรับทุกเวิร์กสเปซ

### งานเบื้องหลัง

งานที่ไม่มีมนุษย์อยู่เบื้องหลัง (การรันเอเจนต์ ไปป์ไลน์ การโพลล์ PR) ต้องใช้ข้อมูลรับรองด้วย และแต่ละฟอร์จตอบต่างกัน:

- **GitHub** — โทเค็นสำหรับรีโปเดียวในแต่ละครั้ง ออกโดย GitHub App ของเซิร์ฟเวอร์ หรือผ่าน Connect และจำกัดอยู่ในขอบเขตของสิ่งที่สมาชิกที่รับผิดชอบทำได้บนรีโปนั้น ไม่เคยเป็นการลงชื่อเข้าใช้ของบุคคลที่ส่งต่อทั้งชุด และไม่มีตัวแปรสภาพแวดล้อมหรือโทเค็นที่วางไว้มาแทนที่ได้ ดู [ตั้งค่าการผสาน GitHub](/th-TH/คู่มือ/วิธีทำ/การผสาน-github/#โทเค็นของคุณเป็นของใคร)
- **GitLab** และ **Bitbucket** — เฉพาะ**โทเค็นระบบอัตโนมัติ**ของรีโปนั้นเท่านั้น: โทเค็นการเข้าถึงของบอทที่ผู้ดูแลเวิร์กสเปซเพิ่มให้รีโปนั้น หรือให้ทุกรีโปบนฟอร์จนั้นในเวิร์กสเปซ โทเค็นของรีโปเองจะชนะโทเค็นของเวิร์กสเปซ การโพลล์ PR, ความคิดเห็นรีวิวด้วย AI, และการพุชกับ merge request ที่ไม่มีใครขอ ใช้โทเค็นนี้ทั้งหมด ดังนั้นบนฟอร์จพวกมันจะแสดงเป็นบอทนั้น ไม่เคยแสดงเป็นสมาชิก ไม่มีโทเค็นส่วนบุคคลของสมาชิกใดมาแทน และไม่มีโทเค็นระดับเซิร์ฟเวอร์หรือตัวแปรสภาพแวดล้อม หากไม่มี งานเบื้องหลังของรีโปจะหยุดชั่วคราว และการแจ้งเตือนการเข้าถึงรีโปจะบอกเรื่องนี้

งานที่สมาชิกขอ (ความคิดเห็น การรีวิว หรือ merge request ที่เอเจนต์เปิดให้) ยังคงใช้โทเค็นของสมาชิกคนนั้นเอง

## เพิ่มโทเค็นระบบอัตโนมัติ

มีเพียงผู้ดูแลเวิร์กสเปซเท่านั้นที่เห็นหรือเปลี่ยนโทเค็นระบบอัตโนมัติได้ Control Center ตรวจโทเค็นแต่ละอันกับฟอร์จเมื่อคุณบันทึก โทเค็นที่ทำตัวเป็นบุคคลจะถูกปฏิเสธ (โทเค็นส่วนบุคคลของ GitLab, โทเค็น API ของ Atlassian หรือโทเค็นของ Bitbucket ที่ลงชื่อเข้าใช้เป็นบัญชีของใครบางคน) และโทเค็นที่อ่านรีโปที่มันมีไว้ไม่ได้ก็ถูกปฏิเสธเช่นกัน

- **สำหรับรีโปเดียว:** เปิด **การตั้งค่า → เวิร์กสเปซ → รีโพสิทอรี** การ์ด **โทเค็นระบบอัตโนมัติ** แสดงรีโป GitLab และ Bitbucket ทุกรายการพร้อมบอทที่ทำงานที่นั่น **ใช้โทเค็นของเวิร์กสเปซ** หรือ **ไม่มีโทเค็น ระบบอัตโนมัติหยุดชั่วคราวที่นี่** กด **เพิ่มโทเค็น** ที่แถวของรีโป
- **สำหรับทุกรีโปบนฟอร์จ:** เปิด **การตั้งค่า → เวิร์กสเปซ → การผสานรวม** หาการ์ด **โทเค็นระบบอัตโนมัติ** แล้วกด **เพิ่มโทเค็น** บนแถว GitLab หรือ Bitbucket รีโปที่โทเค็นอ่านไม่ได้จะถูกระบุชื่อหลังจากที่คุณบันทึก และจะยังคงหยุดชั่วคราว

เมื่องานเบื้องหลังหยุดชั่วคราวอยู่แล้ว ผู้ดูแลจะได้ **เพิ่มโทเค็น** ทันทีบนการแจ้งเตือนการเข้าถึงรีโปด้วย **อัปเดตโทเค็น** จะแทนที่โทเค็น ปุ่มถังขยะจะลบมัน และรีโปใดที่เหลือโดยไม่มีโทเค็นจะหยุดชั่วคราว หากภายหลังฟอร์จปฏิเสธโทเค็นที่บันทึกไว้ (ถูกเพิกถอนหรือหมดอายุ) แถวของมันจะบอกเช่นนั้น และรีโปที่โทเค็นนั้นครอบคลุมจะหยุดชั่วคราวจนกว่าคุณจะแทนที่

| ฟอร์จ           | โทเค็นระบบอัตโนมัติ                                                                                                                                                                              | สร้างได้ที่ไหน                                                 |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| **GitLab**      | โทเค็นการเข้าถึง**โปรเจกต์**หรือ**กลุ่ม** ที่มี `read_api` และ `read_repository`; เพิ่ม `api` และ `write_repository` สำหรับความคิดเห็น merge request และการพุช                                 | โปรเจกต์หรือกลุ่ม → Settings → Access tokens                  |
| **Bitbucket**   | โทเค็นการเข้าถึง**รีโพสิทอรี**, **โปรเจกต์** หรือ**เวิร์กสเปซ** ที่มีการอ่านรีโพสิทอรี พร้อมการเขียน pull request สำหรับความคิดเห็นและ pull request (การเขียนรีโพสิทอรีสำหรับการพุช) | รีโพสิทอรี โปรเจกต์ หรือเวิร์กสเปซ → Settings → Access tokens |

GitLab แสดงงานเป็นผู้ใช้บอทของโทเค็น ส่วน Bitbucket แสดงภายใต้ชื่อของโทเค็นการเข้าถึง

### Bitbucket: โทเค็นการเข้าถึงหรือ API token

Bitbucket มีโทเค็นสองชนิด และ Control Center แยกทั้งสองออกจากกัน:

- **API token** (id.atlassian.com) เป็นของบัญชี Atlassian ของคุณ และใช้คู่กับอีเมลของคุณ เป็น**ข้อมูลรับรองของคุณ** และอยู่ภายใต้ **โฮสต์โค้ด** ใน**การตั้งค่า → คุณ → โปรไฟล์**
- **โทเค็นการเข้าถึง** (สร้างในการตั้งค่าของรีโพสิทอรี โปรเจกต์ หรือเวิร์กสเปซ) เป็นของรีโปนั้น โปรเจกต์นั้น หรือเวิร์กสเปซนั้น ไม่ใช่ของบุคคล เป็น**โทเค็นระบบอัตโนมัติ** และอยู่ภายใต้ **โทเค็นระบบอัตโนมัติ**

ไดอะล็อกแต่ละอันจะปฏิเสธชนิดอื่นและบอกว่ามันควรอยู่ที่ใด

## คุณเป็นคนละคนกันในแต่ละฟอร์จ

มนุษย์คนเดียวกันเป็น `octocat` บน GitHub และเป็นชื่ออื่นโดยสิ้นเชิงบน GitLab Control Center แยกแยะตัวตนของคุณ**ตามฟอร์จ** และใช้ตัวตนที่ถูกต้องกับแต่ละรีโป นี่คือสิ่งที่ทำให้ “ต้องให้ฉันรีวิว” “สร้างโดยฉัน” และ “คุณอนุมัติสิ่งนี้” ถูกต้องในเวิร์กสเปซที่ใช้หลายฟอร์จ

ถ้าตัวตนของฟอร์จใดยังแยกแยะไม่ได้ รีโปของฟอร์จนั้นจะไม่ป้อนอะไรเข้าสู่กล่องขาเข้าเลย แทนที่จะจับคู่กับทุกอย่าง กล่องขาเข้าจะบอกตามนั้น แทนที่จะอ้างว่าคุณตามทันทุกอย่างแล้ว

## คุณเห็นเฉพาะสิ่งที่บัญชีของคุณเองมองเห็นได้

pull request ของรีโปจะมาถึงคุณก็ต่อเมื่อบทบาทของคุณในเวิร์กสเปซอนุญาตรีโปนั้น **และบัญชีของคุณเองบนฟอร์จนั้นอ่านรีโปได้** ผู้ดูแลเวิร์กสเปซและเจ้าของก็ทำตามกฎเดียวกัน เมื่อมีรีโปที่ถูกซ่อนอยู่ กล่องขาเข้าและคิว PR จะบอกจำนวนและเหตุผล โดยไม่ระบุชื่อรีโปเหล่านั้น:

- **ลงชื่อเข้าใช้ GitHub เพื่อดู pull request จากรีโพสิทอรีอีก 3 รายการ**: คุณยังไม่ได้เชื่อมต่อฟอร์จนั้นที่นี่ ลงชื่อเข้าใช้แล้วรีโปเหล่านี้จะปรากฏ
- **ซ่อนรีโพสิทอรี 3 รายการ เพราะบัญชี GitHub ของคุณมองไม่เห็น**: ขอให้คนที่มีสิทธิ์เข้าถึงบนฟอร์จช่วย
- **ซ่อนรีโพสิทอรี 3 รายการ เพราะคุณไม่มีสิทธิ์เข้าถึงในเวิร์กสเปซนี้**: ขอให้ผู้ดูแลเวิร์กสเปซให้สิทธิ์การเข้าถึง
- **กำลังตรวจสอบสิทธิ์เข้าถึงรีโพสิทอรีอีก 3 รายการ…**: แสดงชั่วครู่ขณะที่ Control Center ยืนยันว่าบัญชีของคุณอ่านอะไรได้บ้าง

โค้ดทำตามกฎเดียวกัน ในการเปิดไฟล์ diff หรือการค้นหาของรีโพสิทอรี หรือเทอร์มินัลบนรีโพสิทอรีนั้น คุณต้องมีสิทธิ์ของรีโปนั้นในเวิร์กสเปซนี้ และบัญชีฟอร์จของคุณเองต้องอ่านรีโปนั้นได้ ผู้ดูแลเวิร์กสเปซก็เช่นกัน มีเพียงเจ้าของเซิร์ฟเวอร์เท่านั้นที่ได้รับยกเว้น เมื่อไม่สามารถติดต่อฟอร์จเพื่อตรวจสอบได้ คุณจะเห็นข้อความ "ยืนยันสิทธิ์เข้าถึง forge ของคุณไม่ได้ ลองอีกครั้ง" (พร้อมชื่อฟอร์จ) ดู [โค้ดทำตามฟอร์จ](/th-TH/คู่มือ/แนวคิด/การอนุญาต/#โค้ดเป็นไปตาม-forge)

กฎเดียวกันนี้ครอบคลุมทุกสิ่งที่สร้างจาก pull request เหล่านั้น สเปซรีวิว ข้อความ และการรันเอเจนต์ของมันจะหายไปขณะที่คุณมองไม่เห็น pull request ของมัน และสเปซรีวิวที่เปิดอยู่จะปิดลงหากคุณสูญเสียสิทธิ์เข้าถึง การรันไปป์ไลน์เกี่ยวกับ pull request ที่ถูกซ่อนจะหลุดออกจากรายการการรันของคุณ เอเจนต์ที่ทำงานให้คุณก็อ่านสเปซรีวิวเหล่านั้นไม่ได้เช่นกัน รายการรีโพสิทอรีของเวิร์กสเปซแสดงทุกรีโปที่คุณเข้าถึงได้ในเวิร์กสเปซนี้ แม้แต่รีโปที่บัญชีฟอร์จของคุณยังเข้าไม่ถึง

หากฟอร์จถูกจำกัดอัตราหรือล่ม Control Center จะยังคงแสดงสิ่งที่ยืนยันล่าสุดไว้ได้ไม่กี่นาที จากนั้นจึงซ่อน pull request เหล่านั้นจนกว่าจะตรวจสอบได้อีกครั้ง

## กล่องขาเข้าเดียว ทุกฟอร์จ

กล่องขาเข้าและคิว PR กระจายคำขอไปยังทุกฟอร์จที่มีอยู่ในเวิร์กสเปซ แล้วรวมผลลัพธ์เป็นสตรีมเดียว — pull request ของ GitHub และ pull request ของ Bitbucket จะอยู่ข้างกัน เรียงตามเวลา ไม่ได้จัดกลุ่มตามผู้ให้บริการ

ความล้มเหลวถูกแยกออกจากกัน ฟอร์จที่ล่มหรือติดขีดจำกัดอัตราจะไม่กระทบเจ้าอื่น และรีโปของมันจะคงสถานะล่าสุดที่รู้จักจนกว่ามันจะกลับมา มันไม่เคยทำให้กล่องขาเข้าว่างทั้งใบ รีโปที่เซิร์ฟเวอร์เข้าถึงไม่ได้อีกต่อไปจะหลุดออกไปแทนที่จะแสดง pull request ที่ล้าสมัย และ**การแจ้งเตือนการเข้าถึงรีโป**จะระบุรีโปนั้นพร้อมวิธีแก้: ติดตั้งแอป GitHub บนองค์กรของรีโป เพิ่มรีโปในรายการรีโปของแอป กลับมาใช้การติดตั้งที่ถูกระงับ หรือให้สมาชิกที่รับผิดชอบลงชื่อเข้าใช้อีกครั้ง หรือเพิ่มโทเค็นระบบอัตโนมัติสำหรับรีโป GitLab หรือ Bitbucket ผู้ดูแลจะมีปุ่มไปยังขั้นตอนของแอป GitHub และสำหรับการเพิ่มโทเค็น

## แต่ละฟอร์จทำอะไรได้บ้าง

ทุกฟอร์จรองรับวงจรหลัก: แสดงรายการและเปิด pull request อ่าน diff แสดงความคิดเห็นในบรรทัดและระดับบนสุด รีวิว รวม และปิด เหนือกว่านั้นแต่ละเจ้าต่างกันจริง และ Control Center จะซ่อนสิ่งที่ฟอร์จทำไม่ได้ แทนที่จะแสดงตัวควบคุมที่ล้มเหลวเงียบ ๆ

| ความสามารถ                       | GitHub | GitLab | Bitbucket |
| --------------------------------- | :----: | :----: | :-------: |
| รีวิวแบบเป็นชุด (ที่ค้างอยู่)        |   ✓    |   ✓    |     —     |
| ขอให้แก้ไข                        |   ✓    |   ✓    |     ✓     |
| ซิงค์สถานะ “ดูแล้ว” ต่อไฟล์         |   ✓    |   —    |     —     |
| ปฏิกิริยาอีโมจิ                     |   ✓    |   ✓    |     —     |
| ผู้รีวิวแบบทีม / กลุ่ม               |   ✓    |   ✓    |     —     |
| ผู้รีวิวที่แนะนำ                    |   ✓    |   —    |     ✓     |
| ผลลัพธ์ CI บน PR                    |   ✓    |   ✓    |     ✓     |
| เจาะดูขั้นตอน/บันทึกของงาน CI       |   ✓    |   ✓    |     —     |
| Pull request ที่ซ้อนกัน             |   ✓    |   —    |     —     |
| เทมเพลตคำอธิบาย PR                 |   ✓    |   ✓    |     —     |
| การโพลล์การแจ้งเตือน                |   ✓    |   —    |     —     |
| โปรไฟล์ผู้ใช้แบบละเอียด             |   ✓    |   ✓    |     —     |
| PR head ref ฝั่งเซิร์ฟเวอร์          |   ✓    |   ✓    |     —     |

เมื่อความสามารถใดขาดไป ฟีเจอร์จะลดทอนลงอย่างตรงไปตรงมา:

- **สถานะดูแล้ว** ยังทำงานได้ แต่เฉพาะบนอุปกรณ์ที่คุณตั้งมันไว้เท่านั้น
- **รีวิวแบบเป็นชุด** บน Bitbucket จะโพสต์ทีละความคิดเห็น ผู้รีวิวจึงเห็นพวกมันมาทีละรายการ ไม่ได้มาพร้อมกันทั้งหมด
- **ไม่มี PR head ref** บน Bitbucket หมายความว่าการเช็กเอาต์ pull request จะดึงสาขาต้นทางตามชื่อ ซึ่งจะล้มเหลวเมื่อสาขานั้นถูกลบไปแล้ว

## คำศัพท์

GitLab เรียก pull request ว่า **merge request** Control Center ใช้คำว่า “pull request” ตลอดโมเดลของตัวเอง และใช้คำเรียกของแต่ละฟอร์จเองเมื่อพูดถึงฟอร์จนั้น

## การแก้ปัญหา

### รายการ PR ว่างเปล่าและบอกว่าฟอร์จยังไม่ได้เชื่อมต่อ

คุณไม่มีข้อมูลรับรองสำหรับฟอร์จนั้น ลงชื่อเข้าใช้ GitHub หรือวางโทเค็นของ GitLab หรือ Bitbucket ใน **การตั้งค่า → คุณ → โปรไฟล์ → โฮสต์โค้ด** รีโปของฟอร์จอื่นไม่ได้รับผลกระทบ

### ฉันเชื่อมต่อฟอร์จแล้ว แต่รีโปของมันยังไม่แสดงอะไร

ตรวจสถานะของแถวนั้นก่อน แล้วจึงดูการแจ้งเตือนเหนือรายการ PR ข้อความ “ลงชื่อเข้าใช้ … เพื่อดู pull request จาก … รีโพสิทอรี” หมายความว่าบัญชีของคุณเองยังไม่ได้เชื่อมต่อสำหรับรีโปเหล่านั้น ส่วน “ซ่อนรีโพสิทอรี … เพราะบัญชี … ของคุณมองไม่เห็น” หมายความว่าฟอร์จไม่ได้ให้สิทธิ์เข้าถึงแก่คุณ บน GitHub การแจ้งเตือนการเข้าถึงรีโปจะบอกเมื่อ GitHub App ไม่ได้ติดตั้งบนองค์กรของรีโปหรือไม่ครอบคลุมรีโปนั้น

### งานเบื้องหลังบนรีโป GitLab หรือ Bitbucket หยุดชั่วคราว

รีโปไม่มีโทเค็นระบบอัตโนมัติที่อ่านมันได้ ผู้ดูแลเวิร์กสเปซเพิ่มโทเค็นให้รีโปหรือทั้งเวิร์กสเปซได้ ดู [เพิ่มโทเค็นระบบอัตโนมัติ](#เพิ่มโทเค็นระบบอัตโนมัติ) โทเค็นส่วนบุคคลของคุณเองไม่ทำให้มันกลับมาทำงาน เพราะงานเบื้องหลังไม่เคยใช้โทเค็นของสมาชิก

### รีโปลงทะเบียนไม่ได้

การลงทะเบียนต้องเข้าเงื่อนไขทั้งสามข้อ: พาธอยู่ภายใน git work tree, มี remote `origin` และ remote นั้นชี้ไปที่ github.com, gitlab.com หรือ bitbucket.org `origin` ต้องเป็นรีโพสิทอรีที่คุณกำลังเชื่อมโยงด้วย และโฟลเดอร์นอกพื้นที่จัดเก็บของเวิร์กสเปซจะเชื่อมโยงได้เฉพาะโดยเจ้าของเซิร์ฟเวอร์เท่านั้น ดู [เพิ่มรีโปในเวิร์กสเปซ](/th-TH/คู่มือ/วิธีทำ/เพิ่มรีโป/)

### มีสิทธิ์เข้าถึงในเวิร์กสเปซแต่บัญชีของฉันอ่านรีโพสิทอรีนั้นไม่ได้

บัญชีฟอร์จของคุณเองอ่านรีโพสิทอรีนั้นไม่ได้ ดังนั้นโค้ดของมันจึงยังปิดกั้นคุณอยู่ ไม่ว่าเวิร์กสเปซจะให้สิทธิ์อะไร ลงชื่อเข้าใช้ฟอร์จภายใต้ **โฮสต์โค้ด** ด้านบน หรือขอสิทธิ์เข้าถึงรีโพสิทอรีบนฟอร์จ

### "ยืนยันสิทธิ์เข้าถึง forge ไม่ได้"

ไม่สามารถติดต่อฟอร์จเพื่อตรวจสอบสิทธิ์เข้าถึงของคุณได้ Control Center จึงปฏิเสธแทนการเดา ลองอีกครั้งในอีกสักครู่

### รีโพสิทอรีแจ้งว่าตอนนี้ชี้ไปยังรีโพสิทอรีอื่น

รีโพสิทอรีเบื้องหลังพาธนั้นเปลี่ยนไป: มันถูกลบแล้วสร้างใหม่ หรือถูกย้ายแล้วแทนที่ Control Center จะไม่ส่งอะไรไปยังมันจนกว่าผู้ดูแลเวิร์กสเปซจะคลิก **เชื่อมโยงใหม่** ในการแจ้งเตือนหรือแถวของรีโพสิทอรี การเปลี่ยนชื่อหรือการโอนธรรมดาจะถูกติดตามเองโดยอัตโนมัติและจะไม่แสดงข้อความนี้

### ทุกอย่างหยุดทำงานชั่วขณะหลังใช้งานหนัก

นั่นคือเซอร์กิตเบรกเกอร์ของขีดจำกัดอัตรา ฟอร์จที่ส่งสัญญาณว่าแตะขีดจำกัดหลักจะทำให้ไคลเอนต์ให้คำขอต่อไปล้มเหลวในเครื่องโดยไม่เรียกผ่านเครือข่ายจนกว่าหน้าต่างเวลาจะผ่านไป — พายุการลองใหม่จึงไม่สามารถทำให้ขีดจำกัดลึกลงได้ ความล้มเหลวชั่วคราวจะถูกลองใหม่ด้วย exponential backoff
