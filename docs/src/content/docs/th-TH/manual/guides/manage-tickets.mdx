คู่มือนี้แสดงวิธีสร้างและจัดการตั๋วงาน

## สร้างตั๋วงาน

### จากส่วนติดต่อผู้ใช้

1. คลิก **ตั๋วงาน** ในแถบข้างของเวิร์กสเปซ
2. กด **ตั๋วงานใหม่**
3. กรอกข้อมูลต่อไปนี้:
   - **ชื่อ** — สรุปสั้น ๆ เป็นฟิลด์เดียวที่จำเป็นต้องกรอก
   - **คำอธิบาย** — Markdown พร้อมแถบเครื่องมือจัดรูปแบบ
   - **สถานะ** — **สิ่งที่ต้องทำ** (ค่าเริ่มต้น) หรือ **งานค้าง** สถานะที่เริ่มแล้ว
     และสถานะสิ้นสุดจะเข้าถึงได้ผ่านวงจรชีวิต ไม่ใช่ตอนสร้าง
   - **ลำดับความสำคัญ** — ไม่มี เร่งด่วน สูง ปานกลาง หรือต่ำ
   - **ผู้รับมอบหมาย** — ตัวคุณเองหรือเอเจนต์ใด ๆ ในเวิร์กสเปซ
   - **โปรเจกต์** — การจัดกลุ่มแบบไม่บังคับ
4. กด **สร้าง** หรือเปิด **สร้างเพิ่ม** ก่อน เพื่อให้กล่องโต้ตอบเปิดค้างไว้
   สำหรับกรอกต่อเนื่องอย่างรวดเร็ว

กล่องโต้ตอบนี้ไม่มีตัวเลือกผู้ให้บริการ ตั๋วงานจะถูกสร้างโดยอิงกับผู้ให้บริการ
ตั๋วงานที่ใช้งานอยู่ของเวิร์กสเปซ

### จากเอเจนต์

ขอให้เอเจนต์ตัวหนึ่งในสเปซ:

> สร้างตั๋วงานสำหรับแก้ปัญหา login หมดเวลาเมื่อการเชื่อมต่อช้า

มันจะเรียกเครื่องมือ MCP `create_ticket` ลำดับความสำคัญในเครื่องมือนั้นเป็น
**จำนวนเต็ม** ไม่ใช่ชื่อ:

```
create_ticket(
  workspace_id: "...",
  title: "Fix login timeout on slow connections",
  description: "...",
  priority: 2
)
```

| ค่า   | ลำดับความสำคัญ |
| ----- | -------------- |
| `0`   | ไม่มี          |
| `1`   | เร่งด่วน       |
| `2`   | สูง            |
| `3`   | ปานกลาง        |
| `4`   | ต่ำ            |

มีเพียง `workspace_id` และ `title` ที่จำเป็น ส่วน `description`, `priority`,
`assignee` (id ของเอเจนต์) และ `team_id` เป็นทางเลือก เครื่องมือนี้ถูกจัดอยู่
ในประเภทการเขียนซิงค์ไปยังตัวติดตามภายนอก และจะขออนุมัติจากคุณก่อนรัน

## อัปเดตสถานะตั๋วงาน

ตั๋วงานดำเนินตามวงจรชีวิตนี้:

```
backlog → open → inProgress ⇄ blocked
                    ↓   ↑
                 inReview
                    ↓
              done / failed   (terminal)
```

`done`, `failed` และ `cancelled` เป็นสถานะสิ้นสุด `cancelled` เข้าถึงได้จาก
สถานะที่ไม่ใช่สถานะสิ้นสุดใด ๆ `done` และ `failed` เข้าถึงได้จาก `inProgress`
หรือ `inReview` ส่วน `open` ย้ายไปที่ `blocked` ได้โดยตรงด้วย ตัวเลือกสถานะ
ใน UI จะแสดงทุกสถานะยกเว้น `failed` — เอเจนต์จะทำเครื่องหมายสถานะนั้น
ด้วย `fail_ticket`

หากต้องการเปลี่ยนสถานะ ให้ใช้วิธีใดวิธีหนึ่งต่อไปนี้:

- แถว **สถานะ** ในแถบคุณสมบัติของตั๋วงาน
- เมนูย่อย **สถานะ** ในเมนูคลิกขวาของตั๋วงานในรายการ
- ชิป **สถานะ** บนแถบลอยหลังจากเลือกตั๋วงานหลายรายการ

:::note[กราฟวงจรชีวิตผูกมัดเอเจนต์ ไม่ใช่คุณ]
ทุกการเปลี่ยนสถานะที่ทำจาก UI จะถูกบังคับให้ผ่าน โดยข้ามกราฟไปทั้งหมด — คุณ
ย้ายตั๋วงานไปยังสถานะใดก็ได้ที่ตัวเลือกแสดงไว้ รวมถึงการเปิดตั๋วงานที่ `done`,
`failed` หรือ `cancelled` กลับมาอีกครั้ง ตัวเลือกไม่ได้เสนอ `failed` เป็น
ปลายทาง แผนภาพด้านบนใช้บังคับกับเอเจนต์และระบบอัตโนมัติ: การเปลี่ยนสถานะที่
ผิดกฎซึ่งเครื่องมือ MCP หรือตัวกระทบยอดพยายามทำ จะถูกบันทึกและเพิกเฉย ไม่ถูก
นำไปใช้
:::

การเปลี่ยนสถานะจะส่งเหตุการณ์โดเมน (`TicketStatusChanged`, `TicketCompleted`
และอื่น ๆ) ซึ่งสามารถทริกเกอร์ไปป์ไลน์ได้ ดู
[ตั้งทริกเกอร์ไปป์ไลน์](/th-TH/คู่มือ/วิธีทำ/ทริกเกอร์ไปป์ไลน์/)

## มอบหมายตั๋วงาน

1. เปิดตั๋วงาน
2. ในแถบคุณสมบัติ ตั้งค่า **ผู้รับมอบหมาย** — ตัวคุณเอง สมาชิกคนอื่นใน
   เวิร์กสเปซ หรือเอเจนต์

:::caution[การมอบหมายไม่ได้เริ่มงานใด ๆ]
การมอบหมายบันทึกความเป็นเจ้าของเท่านั้น ไม่ได้สร้างสเปซ ไม่เปลี่ยนสถานะ
และไม่จัดส่งเอเจนต์ — `TicketAssigned` เป็นสัญญาณสำหรับการตรวจสอบล้วน ๆ
ที่ไม่มีตัวจัดส่งอยู่เบื้องหลัง หากต้องการให้เอเจนต์ลงมือทำงาน ให้ส่งข้อความ
ถึงมันในสเปซ (ดู[แชทกับเอเจนต์](/th-TH/คู่มือ/วิธีทำ/แชทกับเอเจนต์/))

ข้อยกเว้นมีเพียงข้อเดียว: `TicketAssigned` เป็นชนิดเหตุการณ์ที่คุณต่อทริกเกอร์
ไปป์ไลน์ได้ ดังนั้นเทมเพลตของคุณเองจึงตอบสนองต่อการมอบหมายได้
:::

## เพิ่มป้ายกำกับ

ป้ายกำกับถูกนำไปใช้แบบกลุ่มจากรายการตั๋วงาน ไม่ใช่จากตั๋วงานทีละใบ —
แถบคุณสมบัติไม่มีตัวควบคุมป้ายกำกับ

1. วางเมาส์บนแถวในรายการตั๋วงานแล้วทำเครื่องหมายในช่องทำเครื่องหมายของมัน
   ทำเครื่องหมายได้มากเท่าที่ต้องการ แถบลอยจะปรากฏขึ้นเมื่อมีการเลือกสิ่งใด
   ก็ตาม
2. ในแถบนั้น เปิดชิป **ป้ายกำกับ**
3. เลือกป้ายกำกับหนึ่งรายการ ป้ายนั้นจะถูกเพิ่มให้กับทุกตั๋วงานที่เลือกซึ่งยัง
   ไม่มีป้ายนั้น ป้ายกำกับที่มีอยู่จะไม่ถูกลบออกเลย **ล้างป้ายกำกับ** จะลบป้าย
   ทั้งหมดออก ตัวเลือกจะแสดงป้ายกำกับที่มีอยู่แล้วบนตั๋วงานในเวิร์กสเปซ เอเจนต์
   สามารถเพิ่มชื่อใหม่ได้ผ่าน `update_ticket` หรือ `tickets.patch`

## ลิงก์ตั๋วงาน

ความสัมพันธ์อยู่บนการ์ด **ความสัมพันธ์** ของตั๋วงานในแถบคุณสมบัติ หรืออยู่
หลัง **เชื่อมโยงกับ** ในเมนูคลิกขวาของรายการ

1. เปิดตั๋วงานและหาการ์ด **ความสัมพันธ์**
2. กดปุ่มเพิ่มของการ์ดนั้น แล้วเลือกความสัมพันธ์:

| ความสัมพันธ์      | ความหมาย                                  |
| ----------------- | ----------------------------------------- |
| **ประเด็นย่อยของ…** | ตั๋วแม่ของตั๋วงานนี้คือตั๋วงานอีกใบ          |
| **แม่ของ…**        | ตั๋วงานอีกใบเป็นตั๋วย่อยของตั๋วงานนี้          |
| **ถูกบล็อกโดย…**   | ตั๋วงานนี้ถูกบล็อกโดยตั๋วงานอีกใบ             |
| **กำลังบล็อก…**    | ตั๋วงานนี้บล็อกตั๋วงานอีกใบ                  |
| **เกี่ยวข้องกับ…** | สมมาตร ไม่ได้สื่อทิศทาง                     |
| **ซ้ำกับ…**        | ตั๋วงานนี้เป็นสำเนาซ้ำของตั๋วงานอีกใบ          |

3. เลือกตั๋วงานปลายทาง

**ถูกทำซ้ำโดย** ปรากฏในการ์ดแต่ไม่อยู่ในตัวเลือก — มันเป็นภาพผกผันของ
**ซ้ำกับ…** และถูกตั้งค่าจากตั๋วงานอีกใบ ความสัมพันธ์แต่ละรายการที่แสดง
สามารถคลิกเพื่อเปิดตั๋วงานที่ลิงก์ไว้ และลบออกได้เมื่อวางเมาส์

ความสัมพันธ์แบบตั๋วแม่และตั๋วย่อยถูกเก็บไว้บนตั๋วงานเอง ไม่ใช่เป็นแถวลิงก์
ดังนั้นการลบตั๋วแม่จะส่งผลต่อเนื่องไปยังตั๋วย่อย (ดูด้านล่าง) ขณะที่ลิงก์
แบบบล็อกและแบบเกี่ยวข้องไม่เป็นเช่นนั้น

## เพิ่มผู้ร่วมงาน

ผู้ร่วมงานคือรายชื่อบนตั๋วงาน — ใครเกี่ยวข้อง และในบทบาทใด

1. เปิดตั๋วงาน
2. กดปุ่มเพิ่มบุคคลบนการ์ด **เพิ่มผู้ร่วมงาน**
3. เลือกเอเจนต์

บทบาทมีสามแบบคือ **assignee**, **collaborator** (ค่าเริ่มต้น) และ
**reviewer** ตัวเลือกใน UI แสดงเฉพาะเอเจนต์ในเวิร์กสเปซ และเขียนบทบาท
เริ่มต้นเสมอ มนุษย์สามารถปรากฏเป็นแถวได้แต่ไม่ถูกเสนอในเมนูนั้น
เครื่องมือ MCP `add_ticket_collaborator` รับพารามิเตอร์ `role`

การเพิ่มผู้ร่วมงานจะเขียนหนึ่งแถวและไม่เผยแพร่เหตุการณ์โดเมนใด ๆ ทั้งไม่ให้
สิทธิ์เข้าถึงสเปซใด ๆ หากต้องการนำเอเจนต์เข้าสู่บทสนทนา ให้เพิ่มมันเป็น
ผู้เข้าร่วมจากส่วนหัวของสเปซแทน — ดู[ใช้สเปซ](/th-TH/คู่มือ/วิธีทำ/สเปซ/)

## ลบตั๋วงาน

ใช้ **ลบตั๋วงาน** ที่ด้านล่างของแถบคุณสมบัติ เมนูคลิกขวา หรือการทำงานลบ
ของแถบลอยหลังจากเลือกหลายรายการ

:::caution[การลบมีผลเฉพาะภายในเครื่อง]
ตั๋วงานที่มาจากตัวติดตามภายนอกจะไม่ถูกลบบนตัวติดตามนั้น — ไม่มีผู้ให้บริการ
รายใดรองรับ — จึงอาจปรากฏกลับมาอีกครั้งในการซิงค์ครั้งถัดไป การลบยังส่งผล
ต่อเนื่องด้วย: ผู้ร่วมงานของตั๋วงานและตั๋วย่อยทั้งหมดจะถูกลบไปพร้อมกัน
:::
