คู่มือนี้ครอบคลุมส่วนที่เป็นเฉพาะของ GitHub ในขั้นตอนการตั้งค่า GitHub เป็นหนึ่งในสาม
โฮสต์โค้ดที่รองรับ ดู[เชื่อมต่อโฮสต์โค้ด](/th-TH/คู่มือ/วิธีทำ/เชื่อมต่อโฮสต์โค้ด/)
สำหรับการเชื่อมต่อ GitLab หรือ Bitbucket และสำหรับวิธีที่เวิร์กสเปซหนึ่งผสมโฮสต์เหล่านี้เข้าด้วยกัน

## ก่อนที่คุณจะเริ่ม

- บัญชี GitHub ที่มีสิทธิ์เข้าถึงรีโปที่คุณต้องการทำงานด้วย
- เซิร์ฟเวอร์ที่สามารถทำให้คนลงชื่อเข้าใช้ GitHub ได้: ไม่ว่าจะเป็น GitHub App ของตัวเอง (ดู
  [สร้าง GitHub App](/th-TH/คู่มือ/วิธีทำ/github-app/)) หรือ Control Center Connect ซึ่งเจ้าของเซิร์ฟเวอร์เลือกไว้ใน **การตั้งค่า → เซิร์ฟเวอร์ → ลงชื่อเข้าใช้ครั้งเดียว**

:::note[ข้อมูลรับรองอยู่บนเซิร์ฟเวอร์ ผูกติดกับคุณ]
ไม่มีอะไรถูกจัดเก็บบนเครื่องที่คุณกำลังพิมพ์อยู่ การลงชื่อเข้าใช้ GitHub ของคุณถูกเก็บไว้โดย
`cc_server` ของคุณ โดยใช้ user id ของคุณเป็นคีย์ และทุกอุปกรณ์ที่คุณลงชื่อเข้าใช้จะใช้
ข้อมูลนั้น — เดสก์ท็อป เว็บ และโทรศัพท์ สมาชิกคนอื่นในเซิร์ฟเวอร์เดียวกันใช้ข้อมูลนี้ไม่ได้
และการลงชื่อเข้าใช้ให้พวกเขาก็เป็นสิ่งที่พวกเขาทำด้วยตนเอง
:::

## ลงชื่อเข้าใช้ GitHub

GitHub รองรับการลงชื่อเข้าใช้เท่านั้น: ไม่มีโทเค็นให้วาง

1. ไปที่ **การตั้งค่า → เวิร์กสเปซ → โปรไฟล์และตัวตน → โฮสต์โค้ด** (หรือขั้นตอนแรก
   ของการเริ่มต้นใช้งาน)
2. ที่แถว **GitHub** คลิก **ลงชื่อเข้าใช้ GitHub**
3. เบราว์เซอร์ของคุณจะเปิด GitHub อนุมัติแอป

การลงชื่อเข้าใช้จะเสร็จสิ้นในรูปแบบที่ขึ้นอยู่กับผู้ดำเนินการ:

- **แอปของเซิร์ฟเวอร์เอง:** GitHub จะส่งเบราว์เซอร์ของคุณกลับไปยังเซิร์ฟเวอร์ และไดอะล็อกจะตรวจพบเองโดยอัตโนมัติ ไม่ต้องพิมพ์อะไร
- **Control Center Connect:** หน้าเบราว์เซอร์จะแสดงรหัสแปดตัวอักษร พิมพ์รหัสลงในไดอะล็อก หรือให้เบราว์เซอร์เปิด Control Center ผ่านลิงก์ `control-center://` เพื่อข้ามการพิมพ์

จุดตรวจสอบ: แถว **GitHub** แสดงข้อความ “ลงชื่อเข้าใช้เป็น _your-username_”

ไดอะล็อกจะปฏิเสธรหัสหรือลิงก์ที่ไม่ได้เริ่มจากตัวเอง และแสดง **การลงชื่อเข้าใช้นี้ไม่ได้เริ่มจากที่นี่** หากมีใครส่งลิงก์ลงชื่อเข้าใช้ให้คุณ อย่าดำเนินการต่อ: การทำให้เสร็จจะเชื่อมบัญชีของคุณเข้ากับเซิร์ฟเวอร์ของเขา

คลิก **ยกเลิกการเชื่อมต่อ** เพื่อลบการลงชื่อเข้าใช้ของคุณ การออกจากระบบ GitHub หรือถูกนำออกจากเวิร์กสเปซ ก็จะทิ้งโทเค็นทั้งหมดที่เซิร์ฟเวอร์ออกให้ในนามของคุณด้วย

## โทเค็นของคุณเป็นของใคร

- **งานใดก็ตามที่คุณทำ** (เปิดหน้า PR, เผยแพร่รีวิว, อนุมัติ, รวม) ใช้การลงชื่อเข้าใช้**ของคุณ**และไม่มีอย่างอื่น หากคุณยังไม่ได้ลงชื่อเข้าใช้ แอปจะแจ้งให้ทราบและขอให้คุณลงชื่อเข้าใช้ ไม่มีข้อมูลรับรองอื่นทำหน้าที่แทนคุณได้
- **งานที่ไม่มีคนพิมพ์อยู่** (การรันเอเจนต์ ไปป์ไลน์ การโพลล์ PR การตอบกลับของบอต การโคลน) จะได้รับโทเค็นที่ใช้กับรีโปเดียว ออกโดย GitHub App ของเซิร์ฟเวอร์หรือผ่าน Connect โทเค็นนี้จำกัดอยู่ในขอบเขตของสิ่งที่สมาชิกที่รับผิดชอบทำได้บนรีโปนั้น คือผู้ที่ร้องขอ หรือหากไม่มีคือเจ้าของเวิร์กสเปซ สมาชิกที่ไม่มีสิทธิ์พุชจะทำให้โทเค็นถูกจำกัดให้อ่านได้อย่างเดียว
- **การอนุมัติโดยระบบอัตโนมัติจะไม่เกิดขึ้นเด็ดขาด** การอนุมัติ pull request เป็นการกระทำของคน

## สิ่งที่การผสานนี้มอบให้

| ฟีเจอร์             | วิธีการ                                                                                                          |
| ------------------- | ---------------------------------------------------------------------------------------------------------------- |
| รายการและรายละเอียด PR | GitHub REST API จากเซิร์ฟเวอร์ โดยใช้การลงชื่อเข้าใช้ของคุณเอง                                              |
| การรันเช็ก          | GitHub Checks API                                                                                                |
| การเผยแพร่รีวิว    | ขั้นตอนที่ต้องมีผู้ใช้ยืนยัน ซึ่งโพสต์รีวิวของคุณไปที่ PR ในนามของคุณ                                             |
| การลงทะเบียนรีโป   | เช็กเอาต์จะได้รับการยอมรับหาก remote `origin` ของมันชี้ไปที่ github.com หรือ gitlab.com / bitbucket.org         |
| การเข้าถึง GitHub ของเอเจนต์ | โทเค็นสำหรับรีโปของการรันเป็น `GH_TOKEN` / `GITHUB_TOKEN`; การพุชผ่าน Control Center                   |
| การแจ้งเตือนแบบ ping | การโพลล์กล่องขาเข้าการแจ้งเตือน GitHub ของคุณฝั่งเซิร์ฟเวอร์จะสร้าง “ถูกกล่าวถึงใน pull request” และ “ขอรีวิวแล้ว”   |
| โปรไฟล์ผู้ใช้       | การ์ดโปรไฟล์เมื่อวางเมาส์ และการกรอง PR ตามผู้เขียนแต่ละราย                                                      |

บางเส้นทางใช้ GraphQL API แทน REST เมื่อประหยัดกว่า: กิจกรรมของสาขาสำหรับตัวเลือก
PR ในหน้าสร้าง และสถานะรีวิวสดที่ตัดสินว่าการแจ้งเตือนว่ามีผู้ขอรีวิวยังค้างอยู่หรือไม่

## เฝ้าระวังเหตุ GitHub ขัดข้อง

แถบชื่อเรื่องจะแสดงชิปสถานะเมื่อผู้ให้บริการรายใดทำงานบกพร่อง ครอบคลุม GitHub,
Claude, OpenAI และ Kimi **มันถูกซ่อนไว้ขณะที่ทุกอย่างปกติ** — การปรากฏตัวรายงาน
ปัญหา ไม่ใช่การไม่มีปัญหา

คลิกชิปเพื่อเปิดฟลายเอาต์ที่แสดงสถานะของผู้ให้บริการแต่ละรายและปุ่มรีเฟรช
สถานะจะรีเฟรชเองทุกสองนาที

## ทำความเข้าใจว่าเอเจนต์ทำอะไรบน GitHub

- เอเจนต์ที่ทำงานใน worktree ของ GitHub จะได้โทเค็นที่จำกัดอยู่ที่รีโปนั้น โดยอ่านโค้ดได้ และแสดงความคิดเห็นบน pull request ได้เมื่อสมาชิกที่รับผิดชอบพุชได้ ไม่เช่นนั้นจะอ่านได้อย่างเดียว การพุชผ่าน Control Center ซึ่งถามกฎ **พุชไปยังรีโมต** ก่อน แล้วจึงส่งการพุชต่อด้วยโทเค็นเขียนที่เอเจนต์ไม่เคยถือ ดู
  [ตั้งค่านโยบายแซนด์บ็อกซ์](/th-TH/คู่มือ/วิธีทำ/นโยบายแซนด์บ็อกซ์/)
- คอมมิตของเอเจนต์ใช้ตัวตน Git ของผู้ร้องขอเป็นทั้งผู้เขียนและผู้คอมมิตเสมอ โดยปกติบรรทัดท้าย `Co-Authored-By: Control Center <hi@usectrl.dev>` จะให้เครดิต GitHub `@usectrl` เป็นผู้ร่วมเขียน คุณปิดเครดิตผู้ร่วมเขียนนี้ได้ใน **การตั้งค่า → คุณ → การระบุที่มาในคอมมิต** โดยไม่เปลี่ยนตัวตนของคุณ การตั้งค่าเวิร์กสเปซใน **การตั้งค่า → เวิร์กสเปซ → ทั่วไป** มีลำดับความสำคัญเหนือกว่าและล็อกสวิตช์ส่วนตัว การระบุที่มาของ Claude Code เองถูกปิดเสมอ การลงนามคอมมิตยังต้องมีการกำหนดค่าที่ถูกต้องแยกต่างหาก
- เทอร์มินัลที่คุณเปิดบนริกจะได้รับการลงชื่อเข้าใช้ของคุณเอง จำกัดอยู่ที่รีโปเดียว ดังนั้นการพุชที่นั่นเป็นของคุณ
- เมื่อไม่สามารถออกโทเค็นได้ (ไม่มีผู้ที่รับผิดชอบลงชื่อเข้าใช้อยู่ แอปไม่ได้ติดตั้งบนเจ้าของ หรือการติดตั้งถูกระงับ) การรันจะเริ่มโดยไม่มีโทเค็น และหมายเหตุจะระบุเหตุผล ไม่มีข้อมูลรับรองสำรองใด ๆ

## การแก้ปัญหา

### รายการ PR ว่างเปล่าและบอกว่า GitHub ยังไม่ได้เชื่อมต่อ

คุณยังไม่ได้ลงชื่อเข้าใช้ GitHub บนเซิร์ฟเวอร์นี้ คลิก **ลงชื่อเข้าใช้ GitHub** ใต้
**โฮสต์โค้ด** รีโปบนโฮสต์โค้ดอื่นไม่ได้รับผลกระทบ

### แถว GitHub บอกว่ายังไม่ได้ตั้งค่าการลงชื่อเข้าใช้บนเซิร์ฟเวอร์นี้

เซิร์ฟเวอร์ไม่มีทั้ง GitHub App ของตัวเองและ Connect เจ้าของเซิร์ฟเวอร์เลือกหนึ่งอย่างได้ใน **การตั้งค่า → เซิร์ฟเวอร์ → ลงชื่อเข้าใช้ครั้งเดียว**: **สร้างแอป GitHub ของฉัน** ใช้เวลาประมาณสองนาที ดู
[สร้าง GitHub App](/th-TH/คู่มือ/วิธีทำ/github-app/)

### ไดอะล็อกบอกว่ารหัสไม่ตรงกัน

พิมพ์รหัสให้ตรงตามที่เบราว์เซอร์แสดง: ตัวอักษรและตัวเลข 8 ตัว หากป้อนรหัสผิดห้าครั้ง การลงชื่อเข้าใช้จะจบลง ให้เริ่มใหม่

### การลงชื่อเข้าใช้บอกว่าแอปยังไม่ได้ติดตั้ง

GitHub App ไม่มีการติดตั้งบนบัญชีที่เป็นเจ้าของรีโป ผู้ดูแลเวิร์กสเปซติดตั้งได้จาก **การตั้งค่า → เวิร์กสเปซ → ทั่วไป** ในส่วน **ติดตั้งแอป GitHub** สำหรับองค์กรที่ใช้แอปที่ใช้ร่วมกันของ Control Center ผู้ดูแลขององค์กรนั้นอาจต้องคลิก **อนุญาตเซิร์ฟเวอร์นี้** ดู
[สร้าง GitHub App](/th-TH/คู่มือ/วิธีทำ/github-app/#อนุญาตเซิร์ฟเวอร์นี้สำหรับองค์กร)

### ทุกคนต้องลงชื่อเข้าใช้ GitHub ใหม่

เจ้าของเซิร์ฟเวอร์หมุนเวียนคีย์ Connect ของเซิร์ฟเวอร์ สลับเซิร์ฟเวอร์ Connect หรือไดเรกทอรีข้อมูลถูกกู้คืนไปยังเครื่องอื่น การลงชื่อเข้าใช้ผ่าน Connect ผูกกับเซิร์ฟเวอร์ที่สร้างมัน

### การเพิ่มรีโปถูกปฏิเสธ

การลงทะเบียนต้องเข้าเงื่อนไขทั้งสามข้อ: พาธอยู่ภายใน git work tree, มี
remote `origin`, และ remote นั้นชี้ไปที่โฮสต์โค้ดที่รองรับ (github.com,
gitlab.com หรือ bitbucket.org) ดู
[เพิ่มรีโปในเวิร์กสเปซ](/th-TH/คู่มือ/วิธีทำ/เพิ่มรีโป/)

### ทุกอย่างหยุดทำงานชั่วขณะหลังใช้งานหนัก

นั่นคือเซอร์กิตเบรกเกอร์ของขีดจำกัดอัตรา GitHub ส่งสัญญาณขีดจำกัดหลักด้วย
`403` ที่แนบ `x-ratelimit-remaining: 0` และเวลารีเซ็ต เมื่อเจอแล้ว ไคลเอนต์จะทำให้
คำขอต่อไปล้มเหลวในเครื่องโดยไม่เรียกผ่านเครือข่ายจนกว่าหน้าต่างเวลาจะผ่านไป
พายุการลองใหม่จึงไม่สามารถทำให้ขีดจำกัดลึกลงได้ ความล้มเหลวชั่วคราวจะถูกลองใหม่
ไม่เกินสามครั้งด้วย exponential backoff โดยเคารพ `retry-after`
