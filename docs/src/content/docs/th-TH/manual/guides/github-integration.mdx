คู่มือนี้ครอบคลุมส่วนที่เป็นเฉพาะของ GitHub ในขั้นตอนการตั้งค่า GitHub เป็นหนึ่งในสาม
โฮสต์โค้ดที่รองรับ ดู[เชื่อมต่อโฮสต์โค้ด](/th-TH/คู่มือ/วิธีทำ/เชื่อมต่อโฮสต์โค้ด/)
สำหรับการเชื่อมต่อ GitLab หรือ Bitbucket และสำหรับวิธีที่เวิร์กสเปซหนึ่งผสมโฮสต์เหล่านี้เข้าด้วยกัน

## ก่อนที่คุณจะเริ่ม

- บัญชี GitHub ที่มีสิทธิ์เข้าถึงรีโปที่คุณต้องการทำงานด้วย
- เซิร์ฟเวอร์ที่สามารถทำให้คนลงชื่อเข้าใช้ GitHub ได้: ไม่ว่าจะเป็น GitHub App ของตัวเอง (ดู
  [สร้าง GitHub App](/th-TH/คู่มือ/วิธีทำ/github-app/)) หรือ Control Center Connect ซึ่งเจ้าของเซิร์ฟเวอร์เลือกไว้ใน **การตั้งค่า → เซิร์ฟเวอร์ → ลงชื่อเข้าใช้ครั้งเดียว**

:::note[ข้อมูลรับรองอยู่บนเซิร์ฟเวอร์ ผูกติดกับคุณ]
ไม่มีอะไรถูกจัดเก็บบนเครื่องที่คุณกำลังพิมพ์อยู่ การลงชื่อเข้าใช้ GitHub ของคุณถูกเก็บไว้โดย
`cc_server` ของคุณ โดยใช้ user id ของคุณเป็นคีย์ และทุกอุปกรณ์ที่คุณลงชื่อเข้าใช้จะใช้
ข้อมูลนั้น — เดสก์ท็อป เว็บ และโทรศัพท์ สมาชิกคนอื่นในเซิร์ฟเวอร์เดียวกันใช้ข้อมูลนี้ไม่ได้
และการลงชื่อเข้าใช้ให้พวกเขาก็เป็นสิ่งที่พวกเขาทำด้วยตนเอง
:::

## ลงชื่อเข้าใช้ GitHub

GitHub รองรับการลงชื่อเข้าใช้เท่านั้น: ไม่มีโทเค็นให้วาง

1. ไปที่ **การตั้งค่า → คุณ → โปรไฟล์ → โฮสต์โค้ด** (หรือขั้นตอนแรก
   ของการเริ่มต้นใช้งาน)
2. ที่แถว **GitHub** คลิก **ลงชื่อเข้าใช้ GitHub**
3. เบราว์เซอร์ของคุณจะเปิด GitHub อนุมัติแอป

การลงชื่อเข้าใช้จะเสร็จสิ้นในรูปแบบที่ขึ้นอยู่กับผู้ดำเนินการ:

- **แอปของเซิร์ฟเวอร์เอง:** GitHub จะส่งเบราว์เซอร์ของคุณกลับไปยังเซิร์ฟเวอร์ และไดอะล็อกจะตรวจพบเองโดยอัตโนมัติ ไม่ต้องพิมพ์อะไร
- **Control Center Connect:** หน้าเบราว์เซอร์จะแสดงรหัสแปดตัวอักษร พิมพ์รหัสลงในไดอะล็อก หรือให้เบราว์เซอร์เปิด Control Center ผ่านลิงก์ `control-center://` เพื่อข้ามการพิมพ์

จุดตรวจสอบ: แถว **GitHub** แสดงข้อความ “ลงชื่อเข้าใช้เป็น _your-username_”

ไดอะล็อกจะปฏิเสธรหัสหรือลิงก์ที่ไม่ได้เริ่มจากตัวเอง และแสดง **การลงชื่อเข้าใช้นี้ไม่ได้เริ่มจากที่นี่** หากมีใครส่งลิงก์ลงชื่อเข้าใช้ให้คุณ อย่าดำเนินการต่อ: การทำให้เสร็จจะเชื่อมบัญชีของคุณเข้ากับเซิร์ฟเวอร์ของเขา

คลิก **ยกเลิกการเชื่อมต่อ** เพื่อลบการลงชื่อเข้าใช้ของคุณ การออกจากระบบ GitHub หรือถูกนำออกจากเวิร์กสเปซ ก็จะทิ้งโทเค็นทั้งหมดที่เซิร์ฟเวอร์ออกให้ในนามของคุณด้วย

## โทเค็นของคุณเป็นของใคร

Control Center ทำตามการแบ่งของ GitHub เองระหว่างการกระทำ**ในฐานะบุคคล**กับ**ในฐานะแอป**:

| สิ่งที่เกิดขึ้น | แสดงบน GitHub เป็น |
| --- | --- |
| สิ่งที่คุณทำเองทั้งหมด: แสดงความคิดเห็น รีวิว อนุมัติ รวม ขอผู้รีวิว | **คุณ**. GitHub ทำเครื่องหมายความคิดเห็นในการสนทนาว่าทำด้วยแอป Control Center; รีวิวและความคิดเห็นแบบอินไลน์ของรีวิวไม่มีเครื่องหมายดังกล่าว |
| รีวิวด้วย AI, ข้อความตอบและคอมเมนต์ของเอเจนต์ในการสนทนา PR, ป้ายกำกับ, งานของไปป์ไลน์และบอท | **บอท Control Center** บนแอป Connect ที่ใช้ร่วมกัน รีวิวจะเป็นของบอทก็ต่อเมื่อการติดตั้งนั้นผู้ดำเนินการ Connect ระบุไว้เท่านั้น มิฉะนั้นจะแสดงเป็นบุคคลที่รับผิดชอบ |
| pull request ที่เอเจนต์เปิดให้คุณ การแก้ไขชื่อหรือคำอธิบายของ pull request นั้น การพุชของมัน และคอมมิตของมัน | **คุณ** Control Center ได้รับเครดิตเป็นผู้ร่วมเขียนเมื่อเปิดเครดิตผู้ร่วมเขียนไว้ |
| งานที่ไม่มีใครขอ (ตารางเวลา, webhook) | **บอท Control Center** ในฐานะผู้เขียนคอมมิตของมันด้วย บน Control Center Connect บอทไม่เคยพุชหรือเปิด pull request |

- **งานใดก็ตามที่คุณทำ** ใช้การลงชื่อเข้าใช้**ของคุณ**และไม่มีอย่างอื่น หากคุณยังไม่ได้ลงชื่อเข้าใช้ แอปจะขอให้คุณลงชื่อเข้าใช้ ไม่มีข้อมูลรับรองอื่นทำหน้าที่แทนคุณ
- **งานของบอท** ได้รับโทเค็นทีละหนึ่งรีโป จำกัดอยู่ในขอบเขตของสิ่งที่สมาชิกที่รับผิดชอบทำได้บนรีโปนั้น: สมาชิกที่ขอให้ทำงาน ไม่เช่นนั้นคือเจ้าของเวิร์กสเปซ สมาชิกที่พุชไม่ได้จะทำให้โทเค็นเป็นการอ่านอย่างเดียว การตอบกลับของบอทที่ทำแทนใครจะขึ้นต้นด้วย **Control Center (for @login)**
- **เอเจนต์เปิด pull request ผ่าน Control Center** ไม่เคยเปิดจากแซนด์บ็อกซ์ของตัวเอง ดังนั้น pull request เป็นของคุณ และกฎของ GitHub เองทำให้คุณอนุมัติมันไม่ได้ Control Center ยังปฏิเสธการอนุมัติจากคนที่ขอให้เอเจนต์ทำงานนั้น และจากผู้เขียน pull request ด้วย สำหรับการรันที่ตั้งเวลาหรือ webhook นั้นครอบคลุมผู้ดูแลทุกคนที่เปิดใช้งานทริกเกอร์หรือแก้ไขไปป์ไลน์ของมันขณะที่มันทำงานอยู่ ต้องให้คนอื่นรีวิว หาก Control Center ไม่สามารถยืนยันได้ว่าใครเปิด pull request หรือบัญชีใดบนฟอร์จเป็นของคุณ มันจะปฏิเสธและขอให้คุณลองอีกครั้ง
- **เอเจนต์คอมเมนต์ผ่าน Control Center ด้วย** โทเค็น GitHub ที่การรันเอเจนต์ได้รับอ่านได้อย่างเดียว เมื่อเอเจนต์คอมเมนต์บน pull request ที่กำลังทำงานอยู่ Control Center จะโพสต์ความคิดเห็นในฐานะบอท โดยขึ้นต้นด้วย **Control Center (for @login)** เมื่อมีใครขอให้รันนั้น เอเจนต์คอมเมนต์ได้เฉพาะบน pull request ของตัวเอง: ในรีโปเดียวกัน ไม่ใช่ fork และมี commit ล่าสุดที่เอเจนต์พุชไว้ หรือเป็น commit ปัจจุบันของสาขาพื้นที่ของมัน @-การกล่าวถึงในความคิดเห็นของเอเจนต์จะไม่แจ้งใคร นอกจากนี้ เอเจนต์ยังเปลี่ยนชื่อหรือคำอธิบายของ pull request ของตัวเองได้ขณะที่ยังเปิดอยู่ การแก้ไขนั้นทำในแบบเดียวกับที่เปิด pull request (ในนามคุณ เมื่อคุณขอให้รัน) ต้องขออนุมัติก่อนเป็นค่าเริ่มต้น และคำอธิบายของ pull request ยังคงมี @-การกล่าวถึงของมันไว้ ทั้งตอนที่เอเจนต์เปิดและตอนที่แก้ไข จึงแจ้งเตือนคนที่ถูกระบุชื่อ
- **บน Control Center Connect บอทไม่เคยพุชหรือเปิด pull request** การพุช การสร้างสาขา หรือการเปิด pull request ที่นั่นต้องมีบุคคลที่ขอให้ทำ และทำงานด้วยการลงชื่อเข้าใช้ของบุคคลนั้น การรันตามตารางเวลาหรือ webhook ที่พยายามพุชจะหยุดพร้อมข้อความที่บอกเหตุผล หากต้องการให้การรันที่ไม่มีคนดูแลพุชได้ ให้มอบ GitHub App ของตัวเองแก่เวิร์กสเปซใน **การตั้งค่า**
- **สิ่งที่บอท Connect ทำได้** ด้วยแอป Connect ที่ใช้ร่วมกัน บอทแสดงความคิดเห็น ป้ายกำกับ และปฏิกิริยาได้ มันโพสต์รีวิว (รีวิวด้วย AI ความคิดเห็นรีวิว คำขอผู้รีวิว) ได้เฉพาะเมื่อผู้ดำเนินการ Connect ระบุการติดตั้งของเซิร์ฟเวอร์นี้ไว้เท่านั้น มิฉะนั้นรีวิวจะถูกส่งผ่านการลงชื่อเข้าใช้ของบุคคลที่รับผิดชอบเอง และปรากฏภายใต้ชื่อของเขา บอทไม่เคยเปิด แก้ไข ปิด หรือเปลี่ยนชื่อ pull request ยกเลิกรีวิว หรือแก้ไขหรือลบความคิดเห็น สิ่งเหล่านั้นต้องใช้บุคคลที่ขอ ด้วยการลงชื่อเข้าใช้ของเขาเอง Connect ไม่ได้ผูกการติดตั้งขององค์กรคุณกับเซิร์ฟเวอร์ Control Center เครื่องเดียว: เซิร์ฟเวอร์ใดก็ได้ที่สมาชิกซึ่งพุชไปยังรีโปได้และลงชื่อเข้าใช้ผ่าน Connect สามารถขอโทเค็นความคิดเห็นของบอทนี้สำหรับรีโปนั้นได้
- **เซิร์ฟเวอร์หรือเวิร์กสเปซที่มี GitHub App ของตัวเอง** ยังให้บอทดูแลทุกอย่างข้างต้น รวมถึงรีวิว
- **การทำงานอัตโนมัติไม่เคยอนุมัติ** pull request การอนุมัติเป็นการกระทำของคน

เมื่อคุณเชื่อมรีโป Control Center จะตรวจว่าบัญชีของคุณมองเห็นรีโปนั้นได้ และเตือนเมื่อ GitHub App ไม่ได้ติดตั้งบนองค์กรของรีโป หรือไม่ได้ครอบคลุมรีโปนั้น พร้อมลิงก์ให้แก้ไข การเชื่อมและการยกเลิกการเชื่อมต้องใช้ผู้ดูแลเวิร์กสเปซ และ checkout ที่อยู่นอกพื้นที่จัดเก็บของเวิร์กสเปซเองจะเชื่อมได้เฉพาะโดยเจ้าของเซิร์ฟเวอร์ ดู[เพิ่มรีโปในเวิร์กสเปซ](/th-TH/คู่มือ/วิธีทำ/เพิ่มรีโป/)

การเชื่อมโยงตามรหัส GitHub ถาวรของรีโป ดังนั้นการเปลี่ยนชื่อหรือการโอนจึงไม่ต้องทำอะไรจากคุณ หากพาธในภายหลังชี้ไปยังรีโปอื่น Control Center จะหยุดส่งอะไรไปยังมัน และแสดงการแจ้งเตือนจนกว่าผู้ดูแลเวิร์กสเปซจะคลิก **เชื่อมโยงใหม่**

การเปิดโค้ดของรีโป (ไฟล์ ดิฟ การค้นหา หรือเทอร์มินัล) ต้องมีทั้งสิทธิ์ของรีโปนั้นในเวิร์กสเปซ และการลงชื่อเข้าใช้ GitHub ของคุณที่อ่านรีโปนั้นได้ ผู้ดูแลเวิร์กสเปซก็ใช้กฎเดียวกัน มีเพียงเจ้าของเซิร์ฟเวอร์เท่านั้นที่ได้รับการยกเว้น

## สิ่งที่การผสานนี้มอบให้

| ฟีเจอร์             | วิธีการ                                                                                                          |
| ------------------- | ---------------------------------------------------------------------------------------------------------------- |
| รายการและรายละเอียด PR | GitHub REST API จากเซิร์ฟเวอร์ โดยใช้การลงชื่อเข้าใช้ของคุณเอง                                              |
| การรันเช็ก          | GitHub Checks API                                                                                                |
| การเผยแพร่รีวิว    | ขั้นตอนที่ต้องมีผู้ใช้ยืนยัน ซึ่งโพสต์รีวิวของคุณไปที่ PR ในนามของคุณ                                             |
| การลงทะเบียนรีโป   | เช็กเอาต์จะได้รับการยอมรับหาก remote `origin` ของมันชี้ไปที่ github.com หรือ gitlab.com / bitbucket.org         |
| การเข้าถึง GitHub ของเอเจนต์ | ภายในการรัน `git fetch` ผ่าน Control Center ซึ่งดึงรีโปที่การรันทำงานด้วยโทเค็นแบบอ่านอย่างเดียวที่การรันไม่เคยถือไว้ `gh` อ่านรีโปเหล่านั้นด้วยโทเค็นแบบอ่านอย่างเดียวที่ Control Center ออกให้เมื่อถูกขอ และเพิกถอนเมื่อการรันสิ้นสุด การพุช pull request การแก้ไขเหล่านั้น และความคิดเห็นผ่าน Control Center |
| การแจ้งเตือนแบบ ping | การโพลล์กล่องขาเข้าการแจ้งเตือน GitHub ของคุณฝั่งเซิร์ฟเวอร์จะสร้าง “ถูกกล่าวถึงใน pull request” และ “ขอรีวิวแล้ว”   |
| โปรไฟล์ผู้ใช้       | การ์ดโปรไฟล์เมื่อวางเมาส์ และการกรอง PR ตามผู้เขียนแต่ละราย                                                      |

บางเส้นทางใช้ GraphQL API แทน REST เมื่อประหยัดกว่า: กิจกรรมของสาขาสำหรับตัวเลือก
PR ในหน้าสร้าง และสถานะรีวิวสดที่ตัดสินว่าการแจ้งเตือนว่ามีผู้ขอรีวิวยังค้างอยู่หรือไม่

## ทำความเข้าใจว่าเอเจนต์ทำอะไรบน GitHub

- เอเจนต์ที่ทำงานใน worktree ของ GitHub จะได้โทเค็นที่จำกัดอยู่ที่รีโปนั้น ซึ่งอ่านได้เฉพาะโค้ด ปัญหา และ pull request; ความคิดเห็นผ่าน Control Center ตามที่อธิบายไว้ข้างต้น การพุชผ่าน Control Center ซึ่งถามกฎ **พุชไปยังรีโมต** ก่อน แล้วจึงส่งการพุชต่อด้วยโทเค็นเขียนที่เอเจนต์ไม่เคยถือ ดู
  [ตั้งค่านโยบายแซนด์บ็อกซ์](/th-TH/คู่มือ/วิธีทำ/นโยบายแซนด์บ็อกซ์/)
- งานที่คุณเริ่มจะถูกคอมมิตในชื่อของคุณ เมื่อคุณขอให้เอเจนต์ทำอะไรบางอย่าง หรือคอมมิตใน IDE คุณคือผู้เขียนและผู้คอมมิต ภายใต้ที่อยู่ที่ forge ยืนยันแล้ว: ที่อยู่ noreply ของ GitHub จากการลงชื่อเข้าใช้ GitHub ของคุณ หรือบน GitLab และ Bitbucket อีเมลที่การลงชื่อเข้าใช้ของคุณรายงานที่นั่น ตัวตน Git ของเวิร์กสเปซจะถูกใช้เฉพาะสำหรับคอมมิตที่คุณทำด้วยมือในรีโปที่ไม่มี forge รับรองที่อยู่ของคุณ หากคุณไม่ได้ลงชื่อเข้าใช้ forge นั้น คอมมิตของเอเจนต์จะเป็นของบอทแทน และหมายเหตุของการรันจะบอกเหตุผล
- งานที่ไม่มีใครขอจะถูกคอมมิตในฐานะบอท การรันตามตารางเวลาหรือ webhook คอมมิตในชื่อ GitHub App ของเวิร์กสเปซ (`<app>[bot]` พร้อมที่อยู่ noreply ของ GitHub) หรือเป็น `Control Center <hi@usectrl.dev>` เมื่อไม่มี GitHub App หรือรีโปอยู่บน GitLab หรือ Bitbucket
- **ให้เครดิต Control Center เป็นผู้ร่วมเขียน** (**การตั้งค่า** → **คุณ** → **คอมมิต**) เพิ่มบรรทัด `Co-Authored-By:` สำหรับอีกฝ่าย: Control Center ในคอมมิตของคุณ และในคอมมิตของบอทคือแต่ละคนที่เปิดทริกเกอร์เบื้องหลังการรัน เปิดไว้เว้นแต่คุณจะปิด ผู้ดูแลเวิร์กสเปซตัดสินเรื่องนี้ให้ทุกคนได้ด้วย **เครดิตผู้ร่วมเขียน** ใน **การตั้งค่า** → **เวิร์กสเปซ** → **ทั่วไป** การตั้งค่าของคุณเองจะถูกบันทึกไว้แต่ไม่มีผลในเวิร์กสเปซนั้น การระบุที่มาของ Claude Code เองถูกปิดเสมอ
- คอมมิตของคุณลงนามได้ ภายใต้ **คอมมิตที่ได้รับการยืนยัน** ใน **การตั้งค่า** → **คุณ** → **คอมมิต** เลือก **สร้างคีย์สำหรับลงนาม** แล้วเพิ่มส่วนสาธารณะของมันไปยังบัญชี GitHub หรือ GitLab ของคุณเป็นคีย์สำหรับลงนาม หลังจากนั้นคอมมิตของการรันที่คุณขอ และคอมมิตที่คุณทำใน IDE จะแสดงว่าได้รับการยืนยัน ส่วนส่วนลับของคีย์อยู่บนเซิร์ฟเวอร์ของคุณ ดังนั้นใครก็ตามที่ควบคุมเซิร์ฟเวอร์นั้นสามารถลงนามคอมมิตในชื่อคุณได้ ขณะที่คีย์ยังอยู่บนบัญชีของคุณ และบน GitHub คอมมิตที่แสดงว่าได้รับการยืนยันแล้วจะยังคงได้รับการยืนยันหลังจากคุณลบคีย์ Bitbucket ไม่มีคีย์สำหรับลงนามอย่างเดียว อย่าเพิ่มคีย์ที่นั่น และคอมมิตบน Bitbucket จะไม่ถูกลงนาม คอมมิตของบอทจะไม่ถูกลงนามเลย
- คอมมิตที่คุณทำในแผง **การควบคุมซอร์ส** ของ IDE จะข้าม Git hook ของรีโป เหมือนที่ `git commit --no-verify` ทำ และ Git ของเซิร์ฟเวอร์จะเพิกเฉยต่อ credential helper เอดิเตอร์ เครื่องมือ diff ภายนอก และตัวลงนามที่รีโปกำหนดไว้: มันรัน Git บนเครื่องของตัวเอง ในต้นไม้ที่เอเจนต์หรือ pull request อาจเปลี่ยนได้ ดู[คอมมิตและพุชจากการควบคุมซอร์ส](/th-TH/คู่มือ/วิธีทำ/รีวิวและรวม-pr/#คอมมิตและพุชจากการควบคุมซอร์ส)
- ทุกคอมมิตที่เอเจนต์พุชจะถูกตรวจก่อน รวมถึงชั้นที่ `stack_publish` พุชสำหรับสแตก การพุชที่ระบุคนอื่น ลบหรือยืมเครดิต เพิ่มบรรทัด sign-off หรือไม่ได้ลงนามตามที่การตั้งค่าของคุณกำหนด จะถูกปฏิเสธ คอมมิตที่คุณพุชเองจาก IDE เป็นของคุณและไม่ถูกตรวจแบบนี้
- เทอร์มินัลที่คุณเปิดบนริกจะได้รับการลงชื่อเข้าใช้ของคุณเอง จำกัดอยู่ที่รีโปเดียว ดังนั้นการพุชที่นั่นเป็นของคุณ
- เมื่อไม่สามารถออกโทเค็นได้ (ไม่มีผู้ที่รับผิดชอบลงชื่อเข้าใช้อยู่ แอปไม่ได้ติดตั้งบนเจ้าของ หรือการติดตั้งถูกระงับ) คำสั่งที่ขอโทเค็นนั้นจะระบุเหตุผล ไม่มีข้อมูลรับรองสำรองใด ๆ

## การแก้ปัญหา

### รายการ PR ว่างเปล่าและบอกว่า GitHub ยังไม่ได้เชื่อมต่อ

คุณยังไม่ได้ลงชื่อเข้าใช้ GitHub บนเซิร์ฟเวอร์นี้ คลิก **ลงชื่อเข้าใช้ GitHub** ใต้
**การตั้งค่า → คุณ → โปรไฟล์ → โฮสต์โค้ด** รีโปบนโฮสต์โค้ดอื่นไม่ได้รับผลกระทบ

### แถว GitHub บอกว่ายังไม่ได้ตั้งค่าการลงชื่อเข้าใช้บนเซิร์ฟเวอร์นี้

เซิร์ฟเวอร์ไม่มีทั้ง GitHub App ของตัวเองและ Connect เจ้าของเซิร์ฟเวอร์เลือกหนึ่งอย่างได้ใน **การตั้งค่า → เซิร์ฟเวอร์ → ลงชื่อเข้าใช้ครั้งเดียว**: **สร้างแอป GitHub ของฉัน** ใช้เวลาประมาณสองนาที ดู
[สร้าง GitHub App](/th-TH/คู่มือ/วิธีทำ/github-app/)

ในเวิร์กสเปซที่ใช้แอปของตัวเอง แถวจะแจ้งเมื่อ GitHub App ของเวิร์กสเปซหายไปหรือกรอกไม่ครบ ผู้ดูแลเวิร์กสเปซกรอกข้อมูลได้ในการ์ด **GitHub App** ภายใต้ **การตั้งค่า → เวิร์กสเปซ → การผสานรวม** ดู [มอบแอปของตัวเองให้เวิร์กสเปซหนึ่งแห่ง](/th-TH/คู่มือ/วิธีทำ/github-app/#มอบแอปของตัวเองให้เวิร์กสเปซหนึ่งแห่ง)

### ไดอะล็อกบอกว่ารหัสไม่ตรงกัน

พิมพ์รหัสให้ตรงตามที่เบราว์เซอร์แสดง: ตัวอักษรและตัวเลข 8 ตัว หากป้อนรหัสผิดห้าครั้ง การลงชื่อเข้าใช้จะจบลง ให้เริ่มใหม่

### การลงชื่อเข้าใช้บอกว่าแอปยังไม่ได้ติดตั้ง

GitHub App ไม่มีการติดตั้งบนบัญชีที่เป็นเจ้าของรีโป ผู้ดูแลเวิร์กสเปซติดตั้งได้จาก **การตั้งค่า → เวิร์กสเปซ → การผสานรวม → การติดตั้งแอป GitHub**

### ทุกคนต้องลงชื่อเข้าใช้ GitHub ใหม่

เจ้าของเซิร์ฟเวอร์หมุนเวียนคีย์ Connect ของเซิร์ฟเวอร์ สลับเซิร์ฟเวอร์ Connect หรือไดเรกทอรีข้อมูลถูกกู้คืนไปยังเครื่องอื่น การลงชื่อเข้าใช้ผ่าน Connect ผูกกับเซิร์ฟเวอร์ที่สร้างมัน

### การเพิ่มรีโปถูกปฏิเสธ

การลงทะเบียนต้องเข้าเงื่อนไขทั้งสามข้อ: พาธอยู่ภายใน git work tree, มี
remote `origin`, และ remote นั้นชี้ไปที่โฮสต์โค้ดที่รองรับ (github.com,
gitlab.com หรือ bitbucket.org) `origin` ต้องเป็นรีโปที่คุณกำลังเชื่อม และโฟลเดอร์นอกพื้นที่จัดเก็บของเวิร์กสเปซเองจะเชื่อมได้เฉพาะโดยเจ้าของเซิร์ฟเวอร์ ดู[เพิ่มรีโปในเวิร์กสเปซ](/th-TH/คู่มือ/วิธีทำ/เพิ่มรีโป/)

### มีสิทธิ์ของเวิร์กสเปซแล้วแต่รีโปบอกว่าบัญชีของคุณอ่านไม่ได้

บัญชี GitHub ของคุณอ่านรีโปนั้นไม่ได้ ดังนั้นโค้ดของมันจึงปิดกั้นคุณแม้จะมีสิทธิ์ของเวิร์กสเปซ ลงชื่อเข้าใช้ GitHub ภายใต้ **โฮสต์โค้ด** หรือขอสิทธิ์เข้าถึงรีโปนั้นจาก GitHub

### "ยืนยันสิทธิ์เข้าถึง GitHub ของคุณไม่ได้ ลองอีกครั้ง"

GitHub ไม่สามารถติดต่อได้เพื่อตรวจสอบสิทธิ์ของคุณ Control Center จึงปฏิเสธแทนที่จะเดา ลองอีกครั้งในภายหลัง

### รีวิวบน Connect ปรากฏภายใต้ชื่อของคุณ ไม่ใช่ของบอท

บนแอป Connect ที่ใช้ร่วมกัน บอทโพสต์รีวิวเฉพาะการติดตั้งที่ผู้ดำเนินการ Connect ระบุไว้เท่านั้น นอกนั้นรีวิวจะถูกส่งผ่านการลงชื่อเข้าใช้ของบุคคลที่รับผิดชอบเอง หากต้องการให้บอทโพสต์รีวิว ให้มอบ GitHub App ของตัวเองแก่เวิร์กสเปซ

### ทุกอย่างหยุดทำงานชั่วขณะหลังใช้งานหนัก

นั่นคือเซอร์กิตเบรกเกอร์ของขีดจำกัดอัตรา GitHub ส่งสัญญาณขีดจำกัดหลักด้วย
`403` ที่แนบ `x-ratelimit-remaining: 0` และเวลารีเซ็ต เมื่อเจอแล้ว ไคลเอนต์จะทำให้
คำขอต่อไปล้มเหลวในเครื่องโดยไม่เรียกผ่านเครือข่ายจนกว่าหน้าต่างเวลาจะผ่านไป
พายุการลองใหม่จึงไม่สามารถทำให้ขีดจำกัดลึกลงได้ ความล้มเหลวชั่วคราวจะถูกลองใหม่
ไม่เกินสามครั้งด้วย exponential backoff โดยเคารพ `retry-after`
