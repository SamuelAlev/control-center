คู่มือนี้แสดงวิธีเติมสกิลจาก GitHub ให้เวิร์กสเปซ: เพิ่มรีโพสิทอรีเป็นแหล่ง
ติดตั้งสกิลที่คุณต้องการจากมัน และทำให้มันเป็นปัจจุบันอยู่เสมอ คุณยังสามารถ
ประเมินเวอร์ชันที่บันทึกไว้เทียบกับเส้นฐานที่จับคู่กันก่อนตัดสินใจว่าจะเก็บไว้
หรือไม่

สิ่งสำคัญที่ควรรู้ก่อนเริ่ม: **รีโพสิทอรีต้นทางไม่น่าเชื่อถือ** ชื่อ คำอธิบาย
และจำนวนดาวของมันเขียนขึ้นโดยเจ้าของของมัน การติดตั้งทุกครั้งต้องผ่านด่าน
การสแกนแอนติไวรัสก่อนที่สิ่งใดจะไปถึงดิสก์หรือพรอมต์ของเอเจนต์ คำตัดสินนั้น
คือการตรวจสอบเพื่อรับเข้า ไม่ใช่หลักฐานว่าสกิลปลอดภัยหรือมีประโยชน์ อ่าน
[ส่วนว่าด้วยสกิลของโมเดลเอเจนต์](/th-TH/คู่มือ/แนวคิด/โมเดลเอเจนต์/) สำหรับ
โมเดลการติดตั้ง และ[การประเมินและคุณภาพ](/th-TH/คู่มือ/แนวคิด/การประเมินและคุณภาพ/)
สำหรับความต่างระหว่างหลักฐานเชิงพฤติกรรมกับการสแกน

สกิลอยู่ที่ **การตั้งค่า → เวิร์กสเปซ → สกิล**
(`/workspaces/<id>/settings/workspace/skills`) สกิลมีขอบเขตอยู่ที่เวิร์กสเปซ:
สกิลที่คุณติดตั้งที่นี่เป็นของเวิร์กสเปซนี้เท่านั้น หน้านี้มีสองแท็บ:
**ติดตั้งแล้ว** (สกิลในเครื่อง รวมถึงตัวแก้ไข **สกิลใหม่**) และ **แหล่ง**
(แค็ตตาล็อก GitHub) การเขียนทั้งสองแบบผ่านด่านสแกนเดียวกัน

## เพิ่มรีโพสิทอรีสกิล

1. เปิด **การตั้งค่า → เวิร์กสเปซ → สกิล** แล้วสลับไปที่แท็บ **แหล่ง**
2. กด **เพิ่มรีโพสิทอรี**
3. วาง URL ของรีโพสิทอรี GitHub เช่น `https://github.com/anthropics/skills`
   แล้วยืนยัน

เซิร์ฟเวอร์ตรวจว่ารีโพสิทอรีมีอยู่จริงและมองเห็นได้ด้วยข้อมูลรับรองของมัน
จากนั้นเพิ่มมันลงในแถบด้านซ้าย ไม่มีที่เก็บที่คัดสรรอยู่ตรงกลาง: รีโพสิทอรี GitHub
ใดก็ได้ ซึ่งหมายความว่าชื่อเสียงเป็นสิ่งที่คุณต้องตัดสินเอง — จำนวนดาวเป็นหลักฐาน
ไม่ใช่สิ่งรับประกัน

สกิลของรีโพสิทอรีคือไดเรกทอรีที่มี `SKILL.md` (ลึกได้ถึงสามระดับ บวกกับเลย์เอาต์
Claude plugin-marketplace `plugins/<plugin>/skills/<skill>` โดยข้ามทรีของ
dependency และ vendor) หากภายหลังตารางการ์ดบอกว่ารีโพสิทอรีไม่มีสกิล
นั่นคือความหมายของมัน: ไม่มีไดเรกทอรีใดในนั้นตรงกับธรรมเนียมของสกิล

## ตรวจดูสกิลก่อนติดตั้ง

เลือกรีโพสิทอรีในแถบด้านซ้าย สกิลของมันจะปรากฏเป็นตารางการ์ดทางขวา
พร้อมช่องตัวกรองด้านบนที่จำกัดแค็ตตาล็อกตามชื่อ คำอธิบาย หรือ slug คลิกการ์ด
เพื่อเปิดมุมมองรายละเอียด ซึ่งแสดงสามอย่าง:

- **README** ที่เรนเดอร์เป็น markdown — `README.md` ของไดเรกทอรีสกิล หรือ
  เนื้อหา `SKILL.md` เมื่อไม่มี README
- **ตัวอย่างการสแกน** — คำตัดสิน (`pass`, `warn` หรือ `quarantine`)
  ความสามารถที่เนื้อหาของสกิลประกาศไว้ (รันเชลล์ เขียนไฟล์ เข้าถึงเครือข่าย…)
  และข้อค้นพบทุกข้อที่ตัวสแกนบันทึกไว้
- **จำนวนไฟล์** — การติดตั้งจะเขียนไดเรกทอรีทั้งหมดของสกิล ไม่ใช่แค่
  `SKILL.md` ของมัน

ตัวอย่างนี้สแกนไบต์ชุดเดียวกับที่การติดตั้งจะเขียน ดังนั้นคำตัดสินที่คุณเห็นคือ
คำตัดสินที่การติดตั้งจะได้รับ ไม่มีสิ่งใดถูกตัดสินใหม่ลับหลังคุณ

## ติดตั้งสกิล

1. เปิดมุมมองรายละเอียดของสกิล
2. อ่านคำตัดสินการสแกน สำหรับคำตัดสิน `warn` หรือ `pass` ให้กด **ติดตั้ง**
3. สำหรับคำตัดสิน `quarantine` ปุ่มติดตั้งจะยังใช้ไม่ได้จนกว่าคุณจะติ๊ก
   **เข้าใจความเสี่ยง — ติดตั้งต่อไป** การข้ามนี้ถูกบันทึกไว้ ไม่ใช่สันนิษฐาน

การติดตั้งจะเขียนไดเรกทอรีของสกิลลงในเวิร์กสเปซ บันทึกหมุดใน
`skills-lock.json` (รีโพสิทอรีต้นทาง พาธ คอมมิตที่มันมาจาก และแฮชเนื้อหา)
และสกิลจะพร้อมใช้กับเอเจนต์ในเวิร์กสเปซ การ์ดที่ทำเครื่องหมาย **ชื่อนี้ถูกใช้แล้ว**
หมายความว่าสกิลอื่นเป็นเจ้าของชื่อนั้นในเครื่องอยู่แล้ว — ถอนการติดตั้งตัวนั้นก่อน

## อัปเดตสกิลเมื่อเวลาผ่านไป

การ์ดของสกิลที่ติดตั้งแล้วมีป้าย: **ติดตั้งแล้ว** หรือ **มีอัปเดต**
เมื่อรีโพสิทอรีเดินหน้าไปไกลกว่าคอมมิตที่คุณปักหมุดไว้ เปิดมุมมองรายละเอียด
แล้วกด **อัปเดต** เพื่อดึงใหม่ที่คอมมิตใหม่ การอัปเดตผ่านด่านสแกนเดียวกับการติดตั้ง
— สกิลที่เวอร์ชันใหม่ถูกกักกันจะถูกปฏิเสธ และเวอร์ชันที่คุณมีอยู่จะคงเดิม
แฮชของเวอร์ชันเก่าถูกเก็บไว้เป็นข้อมูลอ้างอิงสำหรับย้อนกลับในไฟล์ล็อก

## ประเมินสกิล

1. เปิด **การตั้งค่า → เวิร์กสเปซ → สกิล** เลือกสกิลที่ติดตั้งแล้ว และบันทึก
   การแก้ไขทั้งหมด ใน **การประเมินทักษะ** ให้ตรวจสอบแฮชของแพ็กเกจ
2. เลือก **เริ่มประเมิน** จากนั้นเลือก **ชุดงานทดสอบ** ที่ตรงกับจุดประสงค์ของสกิล
   และเลือก **อะแดปเตอร์** ฮาร์เนสในตัวใช้ผู้ให้บริการที่ตั้งค่าไว้และโมเดลที่ใช้
   เครื่องมือได้ **Claude Code** ใช้บัญชี Claude ที่จัดการไว้เริ่มต้นและตัวระบุ
   โมเดลที่เจาะจง ลงชื่อเข้าใช้ที่ **การตั้งค่า → อะแดปเตอร์** ก่อน ไม่ได้ยืม
   การลงชื่อเข้าใช้ส่วนตัวของผู้ดำเนินการเซิร์ฟเวอร์
3. เลือก **การเปรียบเทียบ** จากตารางด้านล่าง
4. ตั้ง **จำนวนครั้งที่ทำซ้ำต่องาน** (1–20) และ **งบประมาณ (US cents)** ตัวอย่างเช่น
   `100` หมายถึง 1 ดอลลาร์สหรัฐ เลือก **เริ่มประเมิน** เพื่ออนุญาตงานผู้ให้บริการ
   ที่มีค่าใช้จ่าย
5. ติดตามแคมเปญใน **การสังเกตการณ์ → คุณภาพ** หรือกลับมาผ่าน **เปิดคุณภาพ**
   ในแผงสกิล

สำหรับการสมัครใช้ Claude Code และ Codex OAuth งบประมาณคือ **เกณฑ์หยุดการใช้
งานเทียบเท่า API** ไม่ใช่ขีดจำกัดใบแจ้งหนี้และไม่ใช่การวัดโควตาของการสมัครใช้
`100` ยอมรับเกณฑ์ 1 ดอลลาร์สหรัฐ การเรียกที่กำลังดำเนินอยู่เกินเกณฑ์ได้ แต่จะไม่
เริ่มการเรียกใหม่เมื่อการใช้งานที่รายงานถึงเกณฑ์แล้ว การใช้งานที่ไม่ทราบก็หยุด
การเรียกต่อไปเช่นกัน งบประมาณเล็กอาจทำให้การเปรียบเทียบไม่ครบถ้วน ไม่ได้
รับประกันว่าจะทำชุดงานทดสอบที่เลือกไว้จนจบ

ผู้ให้บริการที่ใช้คีย์ API ยังคงสงวนไว้ล่วงหน้าอย่างอนุรักษ์นิยมต่อการเรียกหนึ่ง
ครั้ง โดยอิงจากขีดจำกัดโทเคนและราคาที่มีเอกสารระบุ อาจปฏิเสธ `100` ก่อนใช้จ่าย
เมื่อการเรียกที่สงวนไว้อย่างปลอดภัยหนึ่งครั้งต้องใช้มากกว่านั้น ข้อผิดพลาดจะระบุ
โมเดลที่เลือกและจำนวนสงวนขั้นต่ำ ให้เลือกโมเดลที่ถูกกว่า หรือเพิ่มงบประมาณนั้น

| การเปรียบเทียบ | ใช้ตอบคำถามว่า |
| --- | --- |
| **ไม่มีเทียบกับมี** | การค้นพบและการใช้งานสกิลนี้ตามปกติทำให้ผลลัพธ์ดีขึ้นเมื่อเทียบกับตอนที่ไม่มีหรือไม่? |
| **เวอร์ชันก่อนหน้าเทียบกับปัจจุบัน** | การอัปเดตรักษาหรือปรับปรุงพฤติกรรมเมื่อเทียบกับเวอร์ชันที่บันทึกไว้ก่อนหน้าหรือไม่? |
| **บังคับโหลดเทียบกับไม่มี** | เนื้อหาช่วยได้หรือไม่เมื่อโหลดอย่างชัดเจน? การเปรียบเทียบนี้วินิจฉัยปัญหาการโหลด ไม่ได้แสดงให้เห็นการค้นพบตามปกติ |
| **องค์ประกอบ** | การเพิ่มผู้สมัครช่วยหรือขัดแย้งกับสกิลแวดล้อมที่เลือกไว้หรือไม่? เส้นฐานคงชุดแวดล้อมเดิมไว้โดยไม่มีผู้สมัคร |

**เวอร์ชันก่อนหน้าเทียบกับปัจจุบัน** ต้องใช้แฮชของแพ็กเกจจากประวัติแคมเปญ
ให้ประเมินเวอร์ชันก่อนแทนที่ หากคุณต้องการใช้มันเป็นเส้นฐาน ประวัติ Git
ตามอำเภอใจจะไม่ถูกนำเข้า

การแก้ไขที่ยังไม่บันทึก แฮชที่ใช้ไม่ได้ และโหมดสาธิตแบบอ่านอย่างเดียว
จะปิดการเปิดงาน เซิร์ฟเวอร์ยังตรวจสอบการเข้าถึงเวิร์กสเปซและรีโพสิทอรี
การกักกันจากการสแกน นโยบายการดำเนินการ การรองรับโมเดล ราคา และการกักขัง
การทำงาน แก้ไขการตรวจสอบที่ไม่ผ่านแทนที่จะข้ามมัน มีการบันทึกตัวตนของ
ผู้ให้บริการและโมเดล แต่นามแฝงของโมเดลระยะไกลไม่ได้ตรึงน้ำหนักพื้นฐานของ
ผู้ให้บริการไว้

### ตรวจสอบ ยกเลิก และส่งออก

อ่านความครอบคลุมและค่าใช้จ่ายควบคู่กับผลลัพธ์ต่องานและการถดถอย
เปิดแต่ละความพยายามเพื่อตรวจดูการโหลดสกิลที่สังเกตได้ เหตุการณ์เครื่องมือ
ข้อผิดพลาด และหลักฐานของผู้ตรวจสอบ ผลลัพธ์ที่ **ไม่ครบถ้วน** **ล้าสมัย** และ
**ยังสรุปไม่ได้** ไม่ใช่คำแนะนำให้รับเวอร์ชันนั้น แฮชของรายงานระบุแพ็กเกจที่
บันทึกไว้ ไม่ใช่แพ็กเกจที่ติดตั้งอยู่ในปัจจุบันเสมอไป

ใช้ **ยกเลิกการทำงาน** กับงานที่รออยู่หรือกำลังทำงาน ความพยายามที่เสร็จแล้ว
ยังคงมองเห็นได้ การยกเลิกไม่คืนเงินงานของผู้ให้บริการที่ทำไปแล้ว
**คัดลอก JSON ที่ปกปิดข้อมูลแล้ว** คัดลอกข้อมูลหลักฐานแบบจำกัดไปยังคลิปบอร์ด
ไม่ใช่ชุดเล่นซ้ำของซอร์สส่วนตัวทั้งชุด ดู
[การประเมินและคุณภาพ](/th-TH/คู่มือ/แนวคิด/การประเมินและคุณภาพ/) สำหรับ
หลักฐานและขีดจำกัดของแพลตฟอร์ม

### ประเมินใหม่หลังการอัปเดต

การประเมินซ้ำแบบมีค่าใช้จ่ายอัตโนมัติ **ปิดอยู่โดยค่าเริ่มต้น** หลังจากประเมิน
เวอร์ชันปัจจุบันแล้ว ให้เลือกแคมเปญใน **การตั้งค่านโยบายการอัปเดต** และเลือก
**เปิดการประเมินการอัปเดต** การเปลี่ยนนโยบายนี้ต้องใช้สิทธิ์ผู้ดูแลเวิร์กสเปซ
แคมเปญที่เลือกไว้จะจัดหาชุดงานทดสอบ อะแดปเตอร์ ผู้ให้บริการ/โมเดล การเปรียบเทียบ
จำนวนครั้งที่ทำซ้ำ และงบประมาณ

การเปลี่ยนแปลงเนื้อหาที่ได้รับอนุมัติในภายหลังจะจัดตารางงานตามงบประมาณ
แฮชที่ไม่เปลี่ยนแปลงจะถูกตัดรายการซ้ำ **ปิดการประเมินการอัปเดต** ป้องกัน
การรับอัตโนมัติในอนาคต ใช้ **ยกเลิกการทำงาน** กับแคมเปญที่รับไปแล้ว
รายงานในอดีตยังคงผูกกับแฮชแพ็กเกจเดิมของมัน การประเมินซ้ำไม่เผยแพร่
ไม่เปิดใช้งาน และไม่เขียนสกิลใหม่

## ถอนการติดตั้งสกิล ลบรีโพสิทอรีออก

**ถอนการติดตั้ง** (บนมุมมองรายละเอียดของสกิลที่ติดตั้งแล้ว หรือลบในแท็บ
ติดตั้งแล้ว) จะลบไดเรกทอรีของสกิลและหมุดในไฟล์ล็อกไปพร้อมกัน — สกิลที่ถอน
การติดตั้งแล้วไม่เหลืออะไรไว้ข้างหลัง

**การลบรีโพสิทอรี** ออกจากแถบด้านซ้ายลบเฉพาะแค็ตตาล็อก: สกิลที่คุณติดตั้งจากมัน
ยังคงติดตั้งอยู่และยังอัปเดตได้ เพราะหมุดบันทึกรีโพสิทอรีด้วยชื่อ ไม่ใช่ด้วย
การอ้างอิงถึงรายการต้นทาง เพิ่มรีโพสิทอรีกลับหากคุณต้องการเรียกดูมันอีกครั้ง

## เรียกใช้สกิล

สกิลถูกเรียกใช้ภายใต้เนมสเปซของตัวเอง จึงไม่ชนกับคำสั่งสแลชในตัว
(`/plan`, `/goal`, `/loop`, `/compact`):

- `/skill:<name>` — สกิลที่ติดตั้งในเวิร์กสเปซนี้ หรือที่แนบกับเอเจนต์
- `/skill:<repo>:<name>` — สกิลที่รีโปซึ่งเช็กเอาต์ในสเปซนี้จัดส่งมา

ชื่อเปล่า ๆ ที่ไม่ใช่คำสั่งในตัวยังคงแปลงได้ สำหรับข้อความที่เขียนไว้ก่อนที่
เนมสเปซจะมีอยู่ `/skill:plan` คือสิ่งที่ไปถึงสกิลชื่อ `plan`; `/plan`
เป็นคำสั่งในตัวเสมอ

## สกิลที่จำกัดขอบเขตตามรีโป

รีโปที่เช็กเอาต์มาสามารถจัดส่งสกิลของตัวเองได้ ใน `.agents/skills/`,
`.agent/skills/`, `.claude/skills/`, `.opencode/skills/` หรือ `skills/` เหล่านั้น
**ไม่**ได้ติดตั้งผ่านหน้านี้ เอเจนต์ถือเฉพาะสกิลของรีโปที่มันกำลังทำงานอยู่เท่านั้น
พวกมันจะสลับไปเมื่อมันย้าย ช่องเขียนข้อความไม่ได้จำกัดขอบเขตแบบนั้น:
`/skill:<repo>:<name>` ไปถึงรีโปใดก็ได้ในสเปซ

สกิลของรีโปผ่านการสแกนแบบปิดเมื่อล้มเหลวเช่นเดียวกัน
(`pass` / `warn` / `quarantine`) ก่อนที่ฟรอนต์แมตเทอร์ของมันจะไปถึงพรอมต์
`warn` ผ่านเข้าได้ ส่วน `quarantine` ถูกระงับไว้ โดยไม่มีทางข้ามของผู้ปฏิบัติการ
บนเส้นทางนั้น
