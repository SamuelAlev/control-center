คู่มือนี้แสดงวิธีทำให้เอเจนต์ใช้ดีบักเกอร์กับความล้มเหลวที่คำสั่งพิมพ์อธิบายไม่ได้

เครื่องมือ `debug` ขับเคลื่อนเซสชัน Debug Adapter Protocol จริง เฟรมที่ถูกหยุดไว้จะตอบทุกคำถามเกี่ยวกับขณะนั้นพร้อมกันในครั้งเดียว — ตัวแปรโลคอลทุกตัว ผู้เรียกทุกชั้น และนิพจน์ที่ประเมินในสโคปของเฟรมเอง — ในขณะที่คำสั่งพิมพ์ตอบได้แค่คำถามที่คุณคิดจะถามก่อนรัน

## ก่อนเริ่ม

เครื่องมือนี้ยังคงอยู่บนพื้นผิว เพื่อให้เอเจนต์ถามได้ว่าทำไมจึงใช้งานอะไรไม่ได้ แทนที่จะเดา อะแดปเตอร์จะเริ่มทำงานได้จริงก็ต่อเมื่อเข้าเงื่อนไข **ทั้งสอง** ข้อนี้:

- มีมาร์กเกอร์โปรเจกต์อยู่ในเช็กเอาต์ และ
- ค้นหาไบนารีของอะแดปเตอร์เจอ

ลองให้เอเจนต์ตรวจสอบ:

```
debug(op: "adapters")
```

มันจะตอบด้วยสิ่งที่พบ หรืออธิบายว่าอะแดปเตอร์ต้องมีครบทั้งสองส่วน

| ภาษา           | อะแดปเตอร์                   | มาร์กเกอร์                                      | การติดตั้ง                        |
| --------------- | ---------------------------- | ----------------------------------------------- | ---------------------------------- |
| Dart / Flutter  | `dart debug_adapter`         | `pubspec.yaml`                                   | มาพร้อม SDK — ไม่ต้องทำอะไร        |
| Python          | `python3 -m debugpy.adapter` | `pyproject.toml`, `setup.py`, `requirements.txt` | `pip install debugpy`              |
| Rust / C / C++  | `lldb-dap`                   | `Cargo.toml`, `CMakeLists.txt`                   | มาพร้อม LLVM                       |
| Go              | `dlv dap`                    | `go.mod`                                         | `go install github.com/go-delve/delve/cmd/dlv@latest` |

:::note[Python เลือกอินเทอร์พรีเตอร์ของโปรเจกต์]
`debugpy` จะถูกค้นหาใน `.venv/bin` หรือ `venv/bin` ก่อน `$PATH` Python ที่มาจาก `$PATH` เป็นคนละสภาพแวดล้อม และการแอตแทชจากตัวที่ผิดจะล้มเหลวในลักษณะที่อ่านดูเหมือนโค้ดพัง มากกว่าเหมือนการใช้อินเทอร์พรีเตอร์ผิดตัว
:::

## ตั้งเบรกพอยต์ก่อน แล้วค่อยเปิดโปรแกรม

ลำดับสำคัญ และเครื่องมือนี้บังคับใช้มัน: ตั้งเบรกพอยต์ได้**ก่อน**ที่เซสชันจะเกิดขึ้น เพราะนั่นคือลำดับที่โปรโตคอลกำหนดไว้

ลองสั่งเอเจนต์ประมาณนี้:

> ฟังก์ชัน `compute` ใน `bin/main.dart` คืนค่าผิด ตั้งเบรกพอยต์ที่บรรทัดที่กำหนดค่าให้ `product` เปิดมันภายใต้ดีบักเกอร์ แล้วบอกฉันว่าจริง ๆ แล้ว `a` กับ `b` เป็นเท่าไร

มันจะรันประมาณนี้:

```
debug(op: "breakpoints", file: "bin/main.dart", lines: [7])
debug(op: "launch", program: "bin/main.dart")
```

การเปิดโปรแกรมจะรายงานว่าหยุดที่ไหน:

```
Launched bin/main.dart on dart (session dart-1). Stopped: breakpoint. Use `stack` to see where.
```

:::caution[ถ้ามันรายงานว่าโปรแกรมจบการทำงานแทน]
เบรกพอยต์ไม่ได้ผูกติด บรรทัดที่เป็นบรรทัดว่าง เป็นคอมเมนต์ หรือไม่ได้ถูกคอมไพล์เข้าไปในบิลด์จะรับเบรกพอยต์ไม่ได้ การเรียก `breakpoints` กับเซสชันที่กำลังทำงานอยู่จะรายงานว่าตั้งไปได้จริงกี่รายการจากที่คุณตั้งไว้
:::

## อ่านเฟรม

```
debug(op: "stack")
→ #1 compute (bin/main.dart:7:3)
  #2 main (bin/main.dart:2:18)
```

จากนั้นไล่เข้าไปข้างใน:

```
debug(op: "scopes", frame_id: 1)
→ Locals (reference 12)

debug(op: "variables", reference: 12)
→ a (int) = 6
  b (int) = 7
  product (int) = 42
```

ออบเจกต์ที่มีสมาชิกลูกจะรายงาน `[expand: reference N]` — แต่เฉพาะเมื่อมีอะไรอยู่ข้างหลังจริง ๆ เท่านั้น การขยายที่เอเจนต์ใช้งานไม่ได้จึงไม่ถูกเสนอให้เลย

สำหรับอะไรก็ตามที่มองไม่เห็นในฐานะตัวแปรโลคอล:

```
debug(op: "evaluate", expression: "config.timeout.inSeconds", frame_id: 1)
```

## เดินทีละขั้น

| สิ่งที่ต้องการ              | อ็อป        |
| ---------------------- | ----------- |
| รันไปจนถึงจุดหยุดถัดไป   | `continue`  |
| บรรทัดถัดไป เฟรมเดิม    | `step_over` |
| เข้าไปในการเรียก         | `step_in`   |
| ออกไปยังผู้เรียก         | `step_out`  |
| หยุดโปรแกรมที่กำลังรัน    | `pause`     |

## แอตแทชกับสิ่งที่รันอยู่แล้ว

สำหรับโปรเซสที่ค้างอยู่ แทนที่จะเป็นโปรเซสที่คุณกำลังเริ่ม:

```
debug(op: "attach", port: 5858)
```

## จบเซสชัน

```
debug(op: "terminate")
```

ปิดเซสชันเสมอ อะแดปเตอร์ดีบักเป็นเจ้าของ**โปรเซสที่ถูกหยุดไว้**ซึ่งยึดอะไรก็ตามที่โปรเซสนั้นยึดอยู่ — พอร์ต ล็อก หรือการเชื่อมต่อฐานข้อมูล

:::note[มันหนีจากคุณไปไม่ได้]
ทุกเซสชันมี TTL แบบตายตัวที่ต่ออายุไม่ได้ มีเซสชันเดียวเท่านั้นต่อการสนทนาหนึ่งครั้ง และทุกอย่างจะถูกฉีกทิ้งเมื่อเซิร์ฟเวอร์หยุด `launch` ครั้งที่สองจะถูกปฏิเสธแทนที่จะไปแทนที่ครั้งแรก: เอเจนต์ที่เริ่มครั้งหนึ่งโดยไม่จบอีกครั้งเกือบแน่นอนว่าตามครั้งแรกไม่เจอแล้ว
:::

## เอาต์พุตที่มีขอบเขต

การขยาย `variables` บนกราฟออบเจกต์ที่ลึกนั้นไร้ขอบเขตโดยธรรมชาติ — วิดเจ็ต Flutter ตัวเดียวแตะถึงทรีอิลิเมนต์ทั้งต้น จำนวนสมาชิกลูกต่อสโคปถูกจำกัดไว้ที่ 50 ค่าต่าง ๆ ที่ 400 ตัวอักษร และเฟรมสแตกที่ 30 ผลลัพธ์ของเครื่องมือที่ถมเต็มหน้าต่างบริบทคือเครื่องมือที่ทำให้การรันที่มันกำลังช่วยอยู่ต้องจบลง
