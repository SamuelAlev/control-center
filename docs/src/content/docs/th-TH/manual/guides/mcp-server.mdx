คู่มือนี้แสดงวิธีเชื่อมไคลเอนต์ MCP ภายนอก — Claude Code, โปรแกรมแก้ไขโค้ด,
MCP Inspector — เข้ากับเซิร์ฟเวอร์เครื่องมือของ Control Center เอง

Control Center ลงทะเบียนเครื่องมือ **110** รายการและให้บริการผ่าน Model Context
Protocol ที่โปรโตคอลเวอร์ชัน `2024-11-05` ตระกูลเครื่องมือทั้งหมดที่คุณอาจคาดว่า
จะมีนั้นไม่มีอยู่เลย: ไม่มีเครื่องมือประชุมหรือปฏิทิน และไม่มีเครื่องมือโปรเจกต์

## ค้นหาปลายทาง

พื้นผิว MCP ใช้ตัวรับฟัง `cc_server` ตัวหลักร่วมกัน ไม่มีพอร์ต MCP แยกต่างหาก

| ปลายทาง | เมธอด    | จุดประสงค์                                                  |
| -------- | -------- | -------------------------------------------------------- |
| `/mcp`   | `POST`   | ทรานสปอร์ต Streamable HTTP — นี่คือสิ่งที่ไคลเอนต์พูดด้วย |
| `/mcp`   | `DELETE` | จบเซสชัน                                                  |
| `/sse`   | `GET`    | สตรีมการแจ้งเตือนแบบเซิร์ฟเวอร์ส่ง                        |

ดังนั้นการติดตั้งภายในเครื่องตามค่าเริ่มต้นจะอยู่ที่ `http://127.0.0.1:9030/mcp`

1. ไปที่ **การตั้งค่า → เซิร์ฟเวอร์ → เซิร์ฟเวอร์ MCP**
2. อ่านการ์ด **เซิร์ฟเวอร์ MCP** — การ์ดนี้แสดงว่ากำลังรันหรือหยุดแล้ว และพอร์ต
   ที่มันกำลังรับฟังอยู่

พื้นผิวนี้เปิดอยู่ตามค่าเริ่มต้นในการติดตั้งใหม่ มีเพียงเจ้าของเซิร์ฟเวอร์เท่านั้นที่เห็นโทเค็นของการ์ด
และมีเพียงเขาที่เริ่มหรือหยุดปลายทางได้ **เริ่มเมื่อเปิดแอป** ควบคุมว่าจะกลับมาหลังรีสตาร์ตหรือไม่ ส่วน **เริ่ม** / **หยุด**
เป็นการควบคุมเฉพาะเซสชันที่ไม่เปลี่ยนค่ากำหนดนั้น

เซิร์ฟเวอร์ผูกกับลูปแบ็กตามค่าเริ่มต้น ปลายทางจึงเข้าถึงได้จากเครื่องที่ `cc_server`
รันอยู่เท่านั้น เว้นแต่คุณเริ่มมันด้วย `--bind any`

## รับโทเค็น

ทุกคำขอต้องมีโทเค็น MCP ของเซิร์ฟเวอร์ จากเครื่องใดก็ได้ รวมถึงจากลูปแบ็ก เซิร์ฟเวอร์สร้างมันตอนเริ่มครั้งแรก ไม่มีวิธีปิดมัน และไม่มีวิธีล้างมัน

1. ที่ **การตั้งค่า → เซิร์ฟเวอร์ → เซิร์ฟเวอร์ MCP** หาแถว **โทเค็นยืนยันตัวตน**
2. กด **แสดงโทเค็น** แล้วคัดลอก
3. หากต้องการเปลี่ยนใหม่ ให้กด **หมุนเวียนโทเค็น** เซิร์ฟเวอร์จะสลับไปใช้โทเค็นใหม่ทันที และไคลเอนต์ทุกตัวที่ยังใช้โทเค็นเก่าจะถูกปฏิเสธจนกว่าคุณจะให้โทเค็นใหม่แก่มัน

## เชื่อมต่อไคลเอนต์

ชี้ไคลเอนต์ของคุณไปที่ปลายทาง Streamable HTTP และส่งโทเค็นเป็น `Authorization: Bearer <token>` ในทุกคำขอ รวมถึง `GET /sse` ไม่มีวิธีอื่นในการส่ง: โทเค็นใน URL จะไม่ถูกรับ รูปแบบการตั้งค่าที่แน่นอนเป็นเรื่องของไคลเอนต์คุณเอง

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code จะไม่รับการตั้งค่านี้จาก `.mcp.json` ของโปรเจกต์ — มันกันเซิร์ฟเวอร์
MCP ระดับโปรเจกต์ไว้หลังพรอมป์ขออนุมัติที่ `claude -p` แบบไม่โต้ตอบไม่มีทางตอบ
ส่งการตั้งค่าไปอย่างชัดเจน:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` ทำให้ Claude ใช้เฉพาะไฟล์นั้น เซิร์ฟเวอร์เดียวกันจึงไม่ถูก
ค้นพบจากโปรเจกต์แล้วลงทะเบียนซ้ำอีกทางหนึ่ง

จุดตรวจสอบ: ขอให้ไคลเอนต์แสดงรายการเครื่องมือของมัน คุณควรเห็นรายการ `mcp__*`
ที่ครอบคลุมตั๋วงาน สเปซ หน่วยความจำ กราฟโค้ด และรีวิว

## สิ่งที่ปลายทางปฏิเสธ

โทเค็นเปิดทุกเครื่องมือบนเซิร์ฟเวอร์ ดังนั้นปลายทางจึงปฏิเสธสิ่งที่หน้าเว็บอาจส่งมาได้ด้วย ก่อนที่จะดูโทเค็น:

| คำขอ | คำตอบ |
| ---- | ---- |
| เฮดเดอร์ `Origin` ที่ไม่ใช่หน้าบนเครื่องนี้ (`http://localhost`, `http://127.0.0.1` หรือ `http://[::1]` ทุกพอร์ต) | `403`, "Cross-origin requests are not accepted" |
| เฮดเดอร์ `Host` ที่ไม่ใช่ที่อยู่ลูปแบ็กและพอร์ตของตัวรับฟังนี้ หรือชื่อโฮสต์สาธารณะของเซิร์ฟเวอร์ | `403`, "Unknown host" |
| `POST` ที่เนื้อหาไม่ใช่ `application/json` | `415` |
| ไม่มีโทเค็น หรือโทเค็นผิด | `401` |

หากต้องการให้บริการ MCP นอกโฮสต์ ให้เริ่มเซิร์ฟเวอร์ด้วย `--bind any` และส่งโทเค็นจากอีกเครื่องหนึ่ง โดยระบุเซิร์ฟเวอร์ด้วยชื่อโฮสต์สาธารณะของมัน

## จำกัดขอบเขตทุกการเรียกไปที่เวิร์กสเปซ

เครื่องมือทุกตัวที่แตะข้อมูลระดับเวิร์กสเปซต้องมี `workspace_id` และการเรียกที่ไม่มี
ค่านี้จะถูกปฏิเสธ แทนที่จะถูกแก้ให้เข้ากับเวิร์กสเปซ “ปัจจุบัน” ใด ๆ:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

id นี้คือตัวที่อยู่ใน URL เบราว์เซอร์หรือแอปของคุณ: `/workspaces/<workspace_id>/…`
ข้อยกเว้นเดียวคือเครื่องมือที่ครอบคลุมหลายเวิร์กสเปซจริง ๆ เช่น `list_workspaces`
และเครื่องมือฟีดข่าว — ฟีดข่าวเป็นรายผู้ใช้ และเอเจนต์ไม่มีผู้ใช้เป็นของตัวเอง
เครื่องมือเหล่านั้นจึงทำงานกับฟีดของเจ้าของเซิร์ฟเวอร์

เครื่องมือระดับรีโปจะตรวจเพิ่มเติมว่ารีโปนั้นเชื่อมโยงกับเวิร์กสเปซนั้นด้วย

## รู้ว่าพื้นผิวจะปฏิเสธอะไร

- **การกั้นตามโหมด** การเรียกจะถูกแก้เทียบกับโหมดของสเปซของเอเจนต์ผู้เรียก
  ฝั่งเซิร์ฟเวอร์ เอเจนต์ในโหมดอ่านอย่างเดียวไม่สามารถเข้าถึงเครื่องมือเขียน
  ได้โดยการละ `space_id` — โหมดจะถูกค้นหาจากการรันที่ใช้งานอยู่ของมันแทน
- **กฎคุมการกระทำ** เครื่องมือที่เปลี่ยนแปลงข้อมูลจะประกาศคลาสผลกระทบของตัวเอง
  และผ่านนโยบายเดียวกับที่ผลิตภัณฑ์ส่วนที่เหลือใช้ ดู
  [ตั้งค่ากฎคุม](/th-TH/คู่มือ/วิธีทำ/ตั้งค่ากฎคุม/)
- **การยืนยัน** เครื่องมือที่ทำลายข้อมูลบางตัวสร้างเพย์โหลดการยืนยันที่ต้องได้
  รับอนุมัติก่อนการเรียกจะดำเนินต่อ

แค็ตตาล็อกทั้งหมดถูกประกาศใน `tools/list` โดยไม่มีการกั้นการค้นหา — ไคลเอนต์ MCP
ภายนอกจะปฏิเสธไม่เรียกเครื่องมือที่ไม่อยู่ในรายการแคชของมัน การซ่อนเครื่องมือจึง
ทำให้มันพังแทนที่จะเป็นระเบียบขึ้น

## MCP ส่วนตัวยังเป็นของเจ้าของ

คู่มือนี้เกี่ยวกับปลายทางของ Control Center เอง ทิศทางอีกด้านคือเซิร์ฟเวอร์ MCP ที่ Control Center ส่งต่อให้เอเจนต์ที่มันรัน ซึ่งแสดงอยู่ภายใต้ **การตั้งค่า → เซิร์ฟเวอร์ → เซิร์ฟเวอร์ MCP → เซิร์ฟเวอร์ MCP ภายนอก** เซิร์ฟเวอร์ที่ตั้งค่าไว้บนเครื่องของเซิร์ฟเวอร์สำหรับ Claude, Codex, Cursor, Gemini, VS Code, Windsurf, OpenCode หรือในไฟล์ `.mcp.json` จะถูกพบที่นั่นโดยอัตโนมัติ

เซิร์ฟเวอร์ที่พบเหล่านั้นมาจากการตั้งค่าเครื่องมือของผู้ใช้เซิร์ฟเวอร์เอง และทำงานด้วยตัวตนและข้อมูลรับรองของผู้ใช้คนนั้น ดังนั้นมันจึงเป็นของเจ้าของเซิร์ฟเวอร์:

- มีให้ใช้เฉพาะในการรันฮาร์เนสในตัวที่เจ้าของเซิร์ฟเวอร์เริ่มหรือรับผิดชอบ รวมถึงระบบอัตโนมัติในเวิร์กสเปซที่เจ้าของรับผิดชอบ
- การรันของสมาชิก ระบบอัตโนมัติที่ผูกกับสมาชิก และการรันทุกตัวบนเซิร์ฟเวอร์ที่ไม่มีเจ้าของที่บันทึกไว้ จะไม่ได้รับเซิร์ฟเวอร์เหล่านี้เลย ที่นั่นเครื่องมือจะไม่ถูกแสดงรายการ เรียกไม่ได้ และไม่ปรากฏในการค้นหาเครื่องมือ
- ปลายทางนี้ไม่เคยแสดงรายการ เรียก หรือค้นหาเซิร์ฟเวอร์เหล่านี้ สำหรับทุกคน รวมถึงโทเค็นของเจ้าของ และไม่ส่งต่อทรัพยากรหรือพรอมป์ของพวกมัน ดังนั้นเอเจนต์ CLI ที่เชื่อมมายัง Control Center ผ่าน MCP เช่น Claude Code ก็ไม่ได้รับเซิร์ฟเวอร์เหล่านี้ผ่าน Control Center เช่นกัน มันใช้การตั้งค่าของตัวเองแทน

เซิร์ฟเวอร์ MCP ที่ตั้งค่าไว้สำหรับเวิร์กสเปซไม่ได้รับผลกระทบจากเรื่องนี้เลย

## การแก้ปัญหา

### ไคลเอนต์ไม่เห็นเครื่องมือ

- ตรวจสอบว่าการ์ด **เซิร์ฟเวอร์ MCP** แสดงว่ากำลังรัน
- ตรวจสอบว่าพอร์ตตรงกับพอร์ต `cc_server` ของคุณ
- บน Claude Code ตรวจสอบว่าคุณส่ง `--mcp-config` และ `--strict-mcp-config` แล้ว

### 401 Unauthorized

คำขอไม่มีโทเค็น หรือมีโทเค็นเก่า คัดลอกโทเค็นปัจจุบันจากแถว **โทเค็นยืนยันตัวตน** แล้วส่งเป็น `Authorization: Bearer <token>` โทเค็นใน URL จะถูกละเว้น

### 403 จากไคลเอนต์ที่เคยทำงานได้

คำขอมีเฮดเดอร์ `Origin` มาจากหน้าเว็บ หรือ `Host` ที่เซิร์ฟเวอร์ไม่ตอบรับ ให้เรียกปลายทางจากไคลเอนต์แทนหน้าเว็บในเบราว์เซอร์ โดยใช้ที่อยู่ลูปแบ็กของเซิร์ฟเวอร์หรือชื่อโฮสต์สาธารณะ

### 415 Unsupported Media Type

ส่งเนื้อหา `POST /mcp` เป็น `application/json`

### การเรียกเครื่องมือล้มเหลวด้วย "Missing or invalid argument: workspace_id"

เพิ่ม `workspace_id` ไม่มีเวิร์กสเปซโดยนัย

### การเรียกเครื่องมือถูกปฏิเสธว่าไม่รู้จัก

ให้ตรงกับที่ปรากฏที่นั่น
