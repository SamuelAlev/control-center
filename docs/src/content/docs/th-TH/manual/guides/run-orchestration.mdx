คู่มือนี้แสดงวิธีเปลี่ยนเป้าหมายใหญ่ข้อเดียวให้เป็นแผนของทั้งทีมที่รันตัวเองได้
ดู[การประสานงาน](/th-TH/คู่มือ/แนวคิด/การประสานงาน/)สำหรับหลักการทำงาน

## เมื่อใดควรใช้การประสานงาน

ใช้การประสานงานเมื่อคำขอใหญ่เกินกว่าเอเจนต์ตัวเดียวจะรับไหว และคุณยังไม่รู้
ขั้นตอนที่แน่นอน สำหรับงานชิ้นเดียว ให้ส่งข้อความถึงเอเจนต์ใน
[สเปซ](/th-TH/คู่มือ/วิธีทำ/แชทกับเอเจนต์/) ส่วนกระบวนการที่คุณเขียนลำดับเองได้
ให้สร้าง[เทมเพลตไปป์ไลน์](/th-TH/คู่มือ/วิธีทำ/สร้างไปป์ไลน์/)

## ขั้นตอนที่ 1: ขอแผน

1. เปิด (หรือสร้าง) สเปซและ**ตั๋วงานหลัก** ทุกข้อเสนอต้องมีตั๋วงานหนึ่งใบ
   (`propose_orchestration` รับ `ticket_id`) และสเปซที่แชร์กันมาจากตั๋วงานนั้น
2. เลือกได้ว่าจะสลับเมนูโหมดแบบเลื่อนลงของคอมโพเซอร์เป็น **ประสานงาน** โหมดนี้
   จำกัดเอเจนต์ไว้ที่การอ่านและการเสนอ — หน่วยความจำ กราฟโค้ด การอ่านรีโปและ
   ตั๋วงาน `propose_orchestration` และเครื่องมือเพลย์บุ๊ก — จึงเริ่มเขียนโค้ด
   แทนที่จะวางแผนไม่ได้
3. @-mention ตัวประสานงานของคุณ (โดยปกติคือเอเจนต์ CEO) แล้วระบุเป้าหมายเป็น
   ภาษาธรรมชาติ:

> @ceo ค้นคว้าภาพรวมการแข่งขันของเครื่องบันทึกการประชุมแบบออฟไลน์ก่อน แล้วเขียน
> เอกสารวางตำแหน่งผลิตภัณฑ์ความยาวหนึ่งหน้า

ตัวประสานงานจะตอบกลับด้วยการ์ด**ข้อเสนอ**แบบมีโครงสร้างในสเปซ ประกอบด้วย
บทบาทที่ต้องการ งานที่แบ่งเป็นตั๋วงานย่อย เฟสการวิจัยและการอภิปรายซึ่งเลือกได้
ขั้นตอนการสังเคราะห์ที่ผลิตสิ่งที่ส่งมอบ และงบประมาณ

เนื่องจากข้อเสนอเป็นออบเจ็กต์แบบมีชนิด แอปจึงตรวจสอบความถูกต้อง (บทบาทที่ครบถ้วน
สคีมาเอาต์พุตที่ประกาศไว้ DAG ที่ไม่มีวัฏจักร) ก่อนที่สิ่งใดจะรัน ข้อเสนอที่ไม่ผ่าน
การตรวจสอบจะอนุมัติไม่ได้

## ขั้นตอนที่ 2: ตรวจทานและแก้ไขข้อเสนอ

การ์ดในแชทมีสามการดำเนินการ: **อนุมัติแผน** **ปฏิเสธ** และ **เปิด** — ซึ่งเปิด
แผนใน Plan Studio เป็นแท็บตัวแก้ไข ตัวการ์ดเองแก้ไขไม่ได้

หากต้องการเปลี่ยนสิ่งใด ให้กด **เปิด** แล้วทำงานในตัวตรวจสอบทางด้านขวา:

- **ชื่อเรื่อง** **คำอธิบาย** **บทบาท** **การพึ่งพา** และ**สคีมาเอาต์พุต**ของ
  ขั้นตอนงานใด ๆ บทบาทในที่นี้หมายถึงคีย์บทบาทที่มีอยู่แล้วของแผนซึ่งเป็นเจ้าของ
  ขั้นตอนนั้น — คุณปักหมุดบทบาทให้กับเอเจนต์ที่มีชื่อเจาะจงไม่ได้ แก้ไขรายการจ้าง
  จากตัวตรวจสอบไม่ได้ และแก้ไขงบประมาณไม่ได้

มีสองสิ่งที่เป็นแบบอ่านอย่างเดียว: โหนดเชิงโครงสร้าง (การวิจัย การอภิปราย
การสังเคราะห์) และโหนดใด ๆ ที่งานรันไปแล้ว การแก้ไขทำได้เฉพาะขณะที่การประสานงาน
ยังเป็น `proposed` เท่านั้น

กด **ประมาณการ** ในแถบอนุมัติเพื่อดูช่วงค่าใช้จ่าย ระยะเวลา และรัศมีผลกระทบ
ก่อนตัดสินใจ ดู[ทำงานใน Plan Studio](/th-TH/คู่มือ/วิธีทำ/plan-studio/)สำหรับ
ตัวแก้ไขฉบับเต็ม

:::note[งบประมาณไม่ใช่เพดานการใช้จ่าย]
งบประมาณของข้อเสนอจะถูกนำไปเทียบกับ_ค่าประมาณการ_ในแถบอนุมัติ เมื่อปลายบนของ
ค่าประมาณการสูงกว่างบประมาณ ยอดรวมจะเปลี่ยนเป็นสีแดงพร้อมคำเตือนเกินงบ ไม่มีอะไร
ตรวจสอบการใช้จ่ายขณะแผนรัน จึงไม่หยุดหรือทำให้การรันล้มเหลว หากต้องการหยุดการใช้
จ่ายจริง ๆ ให้ใช้นโยบายงบประมาณรายเอเจนต์ — ดู
[จัดการต้นทุน](/th-TH/คู่มือ/วิธีทำ/จัดการต้นทุน/)
:::

## ขั้นตอนที่ 3: อนุมัติ

อนุมัติแผนได้จากทั้งการ์ดในแชทหรือแถบอนุมัติของ Plan Studio
**นี่คือการตัดสินใจเพียงครั้งเดียวที่คุณต้องทำ** การอนุมัติเป็นหน้าที่ของ
โอเปอเรเตอร์เท่านั้น — ไม่มีเครื่องมือ MCP สำหรับการนี้ เอเจนต์จึงเสนอและแก้ไขได้
แต่ไม่มีทางอนุมัติแผนของตัวเองได้เลย

จากจุดนี้ ตัวจัดทำแบบดีเทอร์มินิสติก (ฟังก์ชันบริสุทธิ์ ไม่ใช้ LLM) จะแปลงข้อเสนอ
เป็น[ไปป์ไลน์](/th-TH/คู่มือ/แนวคิด/ไปป์ไลน์/)จริง และสร้างโครงรองรับ:

- จ้างบทบาทใหม่ (และบันทึก id ของเอเจนต์ที่จ้างไว้ เพื่อให้แครชกลางคันระหว่าง
  อนุมัติกลับมาทำต่อได้โดยไม่จ้างซ้ำ)
- จัดกลุ่มบทบาทเหล่านั้นเป็น **ทีม**
- สร้าง**โปรเจกต์**และจัดเก็บตั๋วงานหลักไว้ใต้โปรเจกต์นั้น
- เริ่ม**การรันไปป์ไลน์**ที่ขับเคลื่อนทุกอย่าง

สถานะจะเปลี่ยนเป็น `approved` แล้วจึงเป็น `executing`

## ขั้นตอนที่ 4: เฝ้าดูการรัน

ตั๋วงานย่อยจะรันเป็นขั้นตอนของไปป์ไลน์ หากคุณเปิดรอบการอภิปราย แต่ละบทบาทจะ
โพสต์จุดยืนก่อน ความคืบหน้าจะปรากฏในที่ที่คุณดูอยู่แล้ว:

- **ตั๋วงานหลัก**ที่การประสานงานยึดเกาะไว้
- **สเปซ**ที่แชร์กันซึ่งทีมสนทนากัน โดยแถวของแผนติดตามสถานะของแต่ละโหนด
- รายละเอียดของ**การรันไปป์ไลน์** พร้อมแผนภาพน้ำตกเวลาและค่าใช้จ่ายต่อขั้นตอน
  ตามปกติ — ดู[ติดตามรันไปป์ไลน์](/th-TH/คู่มือ/วิธีทำ/ติดตามไปป์ไลน์/)
- **โปรเจกต์**ที่ตั๋วงานหลักถูกจัดเก็บไว้

เมื่อตั๋วงานย่อยทั้งหมดเสร็จ สถานะจะเปลี่ยนเป็น `synthesizing` และขั้นตอนการ
สังเคราะห์จะผลิตสิ่งที่ส่งมอบ ข้อความนั้นจะถูกโพสต์ในสเปซที่แชร์กัน และตั๋วงานหลัก
จะถูกทำเครื่องหมายว่าเสร็จ จากนั้นสถานะจึงเป็น `completed`

## หยุดก่อนกำหนด

กด **ยกเลิกการประสานงาน** บนการ์ดในแชท หรือ **ยกเลิกรัน** ในแถบอนุมัติของ
Plan Studio การยกเลิกจะรื้องานที่กำลังดำเนินอยู่ทิ้ง

การประสานงานจะล้มเหลวเมื่อการจัดทำล้มเหลว หรือเมื่อการรันไปป์ไลน์ที่สร้างขึ้น
ล้มเหลว (การวิจัย การอภิปราย การสังเคราะห์ หรือการบันทึก — ขั้นตอนเหล่านี้จะไม่
ดำเนินต่อเมื่อล้มเหลว) ขั้นตอน**งาน**ที่สร้างขึ้นจะดำเนินต่อเมื่อล้มเหลวเสมอ
ตั๋วงานย่อยที่ล้มเหลวหนึ่งใบจึงไม่ทำให้การรันล้มเหลว ไม่มีเส้นทางความล้มเหลวจาก
การใช้งบเกิน และไม่มีเกณฑ์ “ตั๋วงานย่อยล้มเหลวทั้งหมด”

## คู่มือที่เกี่ยวข้อง

- [ทำงานใน Plan Studio](/th-TH/คู่มือ/วิธีทำ/plan-studio/): แก้ไข ประมาณการ เทียบความต่าง และอนุมัติแผน
- [สร้างและจัดการตั๋วงาน](/th-TH/คู่มือ/วิธีทำ/จัดการตั๋วงาน/): ตั๋วงานหลักที่การประสานงานยึดเกาะ
- [จัดงานด้วยโปรเจกต์](/th-TH/คู่มือ/วิธีทำ/โปรเจกต์/): ที่จัดเก็บตั๋วงานหลัก
- [ติดตามรันไปป์ไลน์](/th-TH/คู่มือ/วิธีทำ/ติดตามไปป์ไลน์/): การประสานงานที่จัดทำแล้วมีหน้าตาอย่างไรในเอนจิน
- [สร้างทีมเอเจนต์](/th-TH/คู่มือ/วิธีทำ/สร้างทีมเอเจนต์/): บทบาทที่การประสานงานเติมให้หรือจ้างมา
