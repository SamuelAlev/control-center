การรันของเอเจนต์จะอยู่ในแซนด์บ็อกซ์หรือไม่นั้นถูกตัดสินบนเซิร์ฟเวอร์ตอนบูต (`--sandbox`) สวิตช์ **เปิดใช้แซนด์บ็อกซ์** ตัวเลือก **แบ็กเอนด์** และสวิตช์ **ความสามารถเริ่มต้น · สเปซใหม่** ภายใต้ **การตั้งค่า → เซิร์ฟเวอร์ → การวินิจฉัยและความเป็นส่วนตัว** เป็นค่ากำหนดที่จัดเก็บไว้บนอุปกรณ์ของคุณ การตรวจหาโฮสต์ของการ์ด **แซนด์บ็อกซ์** รายงานว่าโฮสต์ของเซิร์ฟเวอร์ห่ออะไรได้บ้าง

มีส่วนควบคุมสองอย่างที่ไปถึงการรัน และคู่มือนี้ครอบคลุมทั้งคู่: **สิทธิ์แซนด์บ็อกซ์** แบบรายเอเจนต์ด้านล่าง และแฟล็ก `--sandbox` ของเซิร์ฟเวอร์เอง

## อะไรที่เป็นข้อจำกัดต่อการรันของเอเจนต์

มีหกสิ่งที่เป็นข้อจำกัดต่อเอเจนต์ อย่างแรกคือแซนด์บ็อกซ์ของ OS และเป็นสิ่งเดียวที่มีเงื่อนไข — อีกห้าสิ่งคงอยู่บนทุกโฮสต์

| ขอบเขต | สิ่งที่มันทำ |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| แซนด์บ็อกซ์ของ OS | Seatbelt บน macOS, bubblewrap บน Linux และ WSL2 ห่อ Claude Code CLI อะแดปเตอร์ ACP และเครื่องมือ `bash` ของฮาร์เนส **ไม่มีบน Windows และบน Linux ที่ไม่มี `bwrap` และ `socat`** |
| worktree ของตัวเอง | การสนทนาแต่ละรายการได้เช็กเอาต์แบบ copy-on-write เช็กเอาต์ต้นฉบับถูกพับเข้าในการรันเป็นเส้นทางที่ห้ามเขียน และแซนด์บ็อกซ์คือสิ่งที่บังคับใช้มัน |
| ข้อมูลรับรองที่ผ่านนายหน้า | นายหน้าข้อมูลรับรองสร้างสภาพแวดล้อมต่อการรันหนึ่งครั้งจากความสามารถของเอเจนต์ และเพิกถอนมันตอนรื้อถอน ไม่มีความสามารถ ก็ไม่มีโทเคนในสภาพแวดล้อม |
| กฎคุมการกระทำ | เครื่องมือที่เปลี่ยนแปลงสถานะทุกตัวประกาศคลาสผลกระทบของมัน และตัวคุมแปลงคลาสเหล่านั้นก่อนที่การเรียกจะรัน `prompt` ที่ไม่มีผู้อนุมัติเชื่อมต่ออยู่จะถูกปฏิเสธ |
| การชำระล้างสภาพแวดล้อม | ACP และเครื่องมือ `bash` ของฮาร์เนสได้สภาพแวดล้อมที่ถูกกรอง Claude Code ผ่าน `NoSandboxAdapter` สืบทอดสภาพแวดล้อมของโฮสต์ |
| พื้นผิวเครื่องมือของโหมด | โหมดอ่านอย่างเดียวถอดเครื่องมือที่เปลี่ยนแปลง worktree ออกไปเลย และตรึงคำกริยาผลลัพธ์ของโหมดเองไว้เพื่อให้ยังส่งมอบได้ |

มีสามสิ่งที่ยังอ่อนกว่าที่มันดู:

- มีเพียง **ฮาร์เนสในตัว** เท่านั้นที่บังคับใช้ด่านเครื่องมือ ข้อกำหนดการเสร็จงาน และกฎเชิงโครงสร้างของโหมด อะแดปเตอร์ Claude Code ไม่ทำเช่นนั้น โดยเฉพาะ Claude Code นั้นถูกเรียกใช้ด้วย `--dangerously-skip-permissions` เพราะ `claude -p` แบบไม่มีการโต้ตอบจะค้างอยู่ตลอดไปที่พรอมต์ของมันเอง — การเรียกอ่าน เขียน แก้ไข และเชลล์ของ Claude เองจึงไม่ถูกมองเห็นและไม่ผ่านด่านของ Control Center ที่ใดแซนด์บ็อกซ์เปิดอยู่ มันคือขอบเขตรอบ ๆ การเรียกเหล่านั้น
- เครื่องมือไฟล์ในโปรเซสของฮาร์เนส (read, write, edit, apply patch, search, find, search_files) ทำงานอยู่ภายในโปรเซสของเซิร์ฟเวอร์ จึงไม่มีโปรไฟล์แซนด์บ็อกซ์ใดคุมมัน มีเพียงเครื่องมือ `bash` เท่านั้นที่ผ่านตัวรันคำสั่งที่อยู่ในแซนด์บ็อกซ์ เครื่องมือเหล่านั้นถูกจำกัดด้วยการจำกัดเส้นทางในตัวมันเองบวกกับกฎคุมการกระทำ
- บนโฮสต์ที่ไม่มีแบ็กเอนด์ แถวแรกใช้ไม่ได้เลย ACP และเครื่องมือ `bash` ของฮาร์เนสถอยกลับไปพึ่งการชำระล้างสภาพแวดล้อมบวกกับนโยบายคำสั่ง; Claude Code สืบทอดสภาพแวดล้อมของโฮสต์ผ่าน `NoSandboxAdapter` เซิร์ฟเวอร์บอกเรื่องนี้ในล็อกเริ่มต้นของมัน ตรวจสอบของตัวเองด้านล่าง

## ตั้งค่าความสามารถของเอเจนต์

นี่คือส่วนควบคุมความสามารถเพียงอย่างเดียวที่เซิร์ฟเวอร์อ่าน มันเป็นรายเอเจนต์ และเป็นตัวตัดสินว่านายหน้าข้อมูลรับรองใส่อะไรลงในสภาพแวดล้อมของเอเจนต์ตัวนั้น

1. ไปที่ **การตั้งค่า → เวิร์กสเปซ → เอเจนต์**
2. เลือกเอเจนต์ในรายการ
3. ในแท็บ **การตั้งค่า** เลื่อนไปที่ **สิทธิ์แซนด์บ็อกซ์**
4. เปิดสวิตช์ — คำบรรยายใต้แถวจะเปลี่ยนจาก **ใช้ค่าเริ่มต้นของเวิร์กสเปซ**
5. ตั้งสวิตช์ทั้งสี่ตัว:

| สวิตช์ | สิ่งที่มันกั้น |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **อนุญาต git push** | เมื่อปิดอยู่ การรันจะได้ `GIT_ASKPASS=/usr/bin/false` และ `GIT_TERMINAL_PROMPT=0` การพุชจึงถามหาข้อมูลรับรองไม่ได้ |
| **อนุญาตการเรียก GitHub API** | ทำงานร่วมกับ **อนุญาต git push** เป็นตัวกั้นว่านายหน้าใส่โทเคน GitHub เป็น `GH_TOKEN` / `GITHUB_TOKEN` หรือไม่ |
| **อนุญาตการเรียก ticketing API** | กั้นว่านายหน้าใส่ `TICKETING_API_KEY` หรือไม่ |
| **อนุญาตการเข้าถึงเครือข่ายทั่วไป** | ที่ใดแซนด์บ็อกซ์เปิดอยู่ นี่คือด่านขาออกจริง: เมื่อปิดอยู่ รายการที่อนุญาตของการรันจะว่างเปล่า และทุกคำขอขาออกจะถูกปฏิเสธที่พร็อกซี ที่ใดไม่มีแบ็กเอนด์ มันถูกบันทึกไว้บนการรันแต่ไม่ได้กั้นอะไรที่โปรเซสลูกทำ |

6. บันทึก

จุดตรวจสอบ: เปิดเอเจนต์อีกครั้ง แล้วสวิตช์ยังเปิดอยู่พร้อมสวิตช์ของคุณ — ชุดความสามารถที่บันทึกไว้จะวนกลับมาผ่านเซิร์ฟเวอร์ และเอเจนต์ที่ไม่มีชุดใดเลยจะถอยกลับไปใช้ค่าเริ่มต้นแบบอนุรักษ์นิยม (พุชปิด, GitHub API ปิด, ticketing ปิด, เครือข่ายเปิด)

:::caution[สองจุดที่มักทำให้พลาด]
คำบรรยายใต้แถวบอกว่า **ใช้ค่าเริ่มต้นของเวิร์กสเปซ** แต่ไม่มีการตั้งค่าความสามารถระดับเวิร์กสเปซที่เซิร์ฟเวอร์อ่าน เอเจนต์ที่ปิดสวิตช์อยู่จะได้ค่าเริ่มต้นแบบอนุรักษ์นิยมในตัว

อีกเรื่องหนึ่ง ข้อมูลรับรอง GitHub ของการรันเป็นของนายหน้าเท่านั้นเสมอ — โทเคนการติดตั้ง GitHub App ที่จำกัดขอบเขตกับรีโป หรือ PAT ตัวสำรองจากสภาพแวดล้อม — ไม่เคยเป็นโทเคนที่จัดเก็บไว้ของสมาชิกผู้ร้องขอเอง `actingUserId` ถูกส่งไปเพื่อให้นายหน้า *ระงับ* PAT ของเซิร์ฟเวอร์จากสมาชิกที่ไม่ได้เป็นเจ้าของและยังไม่ได้เชื่อม GitHub; มันไม่ได้รวมโทเคนส่วนตัวทับความสามารถที่ปิดอยู่ อย่าถือว่า **อนุญาตการเรียก GitHub API** เป็นขอบเขตขาออกแบบแข็งบนโฮสต์ที่ไม่มีแซนด์บ็อกซ์ของ OS: โปรเซสลูกยังเข้าถึงเครือข่ายได้อยู่ดี
:::

## ตรวจสอบว่าการรันเอเจนต์ของคุณอยู่ในแซนด์บ็อกซ์หรือไม่

มีสองสิ่งตัดสินเรื่องนี้ ทั้งคู่อยู่บนเซิร์ฟเวอร์: ว่าโฮสต์มีแบ็กเอนด์ให้หรือไม่ และว่า `--sandbox` เปิดอยู่หรือไม่ ตรวจตามลำดับนั้น

1. ไปที่ **การตั้งค่า → เซิร์ฟเวอร์ → การวินิจฉัยและความเป็นส่วนตัว**
2. อ่านการ์ด **แซนด์บ็อกซ์** ข้อเท็จจริง **โฮสต์** คือเครื่องที่ `cc_server` รันอยู่ ไม่ใช่เครื่องที่คุณกำลังดูอยู่ ฟิลด์ **แบ็กเอนด์** แสดง **แซนด์บ็อกซ์เนทีฟ** (Seatbelt บน macOS, bubblewrap บน Linux และ WSL2) หรือ **ไม่แยก** ข้อเท็จจริง **มีผล** คือค่ากำหนดของอุปกรณ์นี้ ไม่ใช่การห่อที่เซิร์ฟเวอร์ใช้จริง
3. อ่านล็อกเริ่มต้นของเซิร์ฟเวอร์ มันพิมพ์หนึ่งในสามบรรทัดนี้เท่านั้น:
   - `agent sandbox ON` บวกกับบันทึกแบ็กเอนด์ — การรันถูกห่อ
   - `no OS-native agent sandbox on this host` บวกกับคำแนะนำการติดตั้งเมื่อมี — การรันไม่ถูกห่อ
   - `agent sandbox DISABLED by --sandbox off` — การเลือกปิดโดยเจตนา

`GET /healthz` ไม่รายงานสถานะแซนด์บ็อกซ์ ล็อกเริ่มต้นจึงเป็นการตรวจสอบ

หากต้องการปิดแซนด์บ็อกซ์โดยเจตนา — โฮสต์ที่โปรไฟล์ทำงานผิดพลาดคือเหตุผลที่มันมีอยู่ — ให้เริ่มเซิร์ฟเวอร์ด้วย `--sandbox off` หรือตั้ง `CC_SERVER_SANDBOX=off` ค่าเริ่มต้นคือ `on` และ `on` หมายถึง “ใช้แบ็กเอนด์ถ้าโฮสต์มี” ไม่เคยหมายถึง “บังคับว่าต้องมี”

มีสองสถานการณ์ที่ไม่เคยได้รับการห่อด้วยแซนด์บ็อกซ์เนทีฟ บน **Windows** การตรวจหาแบบเนทีฟจะรายงานว่าไม่มีให้ใช้เสมอ และไม่มีอะไรให้ติดตั้ง — การสั่งงานเอเจนต์ใช้ `none` แบ็กเอนด์ `microvm` แยกต่างหาก (เทอร์มินัลแบบโต้ตอบและริก) และถูกกั้นด้วยการตรวจหาบนรันไทม์ของมันเอง บน **Linux และ WSL2** ทั้ง `bwrap` และ `socat` ต้องอยู่บน `PATH`; หากไม่มี การตรวจหาจะรายงานว่าไม่มีให้ใช้และระบุชื่อแพ็กเกจที่ขาดไป

บน Linux/WSL2 ที่ติดตั้ง bubblewrap แล้ว กลอบของไฟล์ลับในนโยบายมาตรฐานไม่สามารถบังคับใช้กับไฟล์ที่เอเจนต์สร้างขึ้นในภายหลังได้ การรันแบบเนทีฟเช่นนั้นตอนนี้จะล้มเหลว แทนที่จะเพิกเฉยต่อกฎอย่างเงียบ ๆ การตรวจหาตอนบูตที่ผ่านจึงไม่รับประกันว่าการสั่งงานบน Linux จะเริ่มได้ `--sandbox off` เป็นการเลือกปิดโดยเจตนาให้ไม่ถูกกักขอบ ไม่ใช่ขอบเขตความปลอดภัยทดแทน

## รู้ว่าโหมดหนึ่งห้ามอะไรไว้แล้ว

โหมดถูกจัดเก็บเป็นรายสเปซ และป้อนเข้าตัวแปลงคำตัดสินของกฎคุมในฐานะชั้น **พรีเซ็ตโหมด** สามในสี่โหมดเป็นอ่านอย่างเดียว และโหมดอ่านอย่างเดียวจะปฏิเสธคลาสผลกระทบสิบเอ็ดคลาสทันที:

| โหมด | Worktree | ถูกปฏิเสธโดยพรีเซ็ต |
| ------------------ | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **เอเจนต์** (`chat`) | เขียนได้ | ไม่มี — ค่าเริ่มต้นในตัวมีผล |
| **แผน** | อ่านอย่างเดียว | ลบไฟล์, เขียนนอก worktree, คอมมิต, พุช, เปิด PR, เผยแพร่หรือรวม, เขียนไปยังตัวติดตามภายนอก, ติดตั้งแพ็กเกจ, รันโปรเซส, เปลี่ยนโครงสร้างเวิร์กสเปซ, บูตหรือควบคุมเอนโคลเจอร์ |
| **รีวิว** | อ่านอย่างเดียว | สิบเอ็ดคลาสเดิม ไม่ให้ผู้ใช้เลือก — ช่องเขียนข้อความมีเพียงเอเจนต์ แผน และประสานงาน |
| **ประสานงาน** | อ่านอย่างเดียว | สิบเอ็ดคลาสเดิม |

การเข้าถึงเครือข่ายและการเข้าถึงข้อมูลลับนั้น _ไม่_ ถูกปฏิเสธโดยโหมดอ่านอย่างเดียวโดยเจตนา: การค้นคว้าคือจุดหมายของมัน

## กำหนดให้ต้องอนุมัติก่อนการกระทำจะรัน

การอนุมัติเป็นคำตัดสินของกฎคุม ไม่ใช่การตั้งค่าแซนด์บ็อกซ์

1. ไปที่ **การตั้งค่า → เวิร์กสเปซ → สิทธิ์ของเอเจนต์**
2. ตั้งคลาสการกระทำเป็น **ถามก่อน** ที่ขอบเขตเวิร์กสเปซ เอเจนต์ หรือสเปซ

คำตัดสิน **ถามก่อน** จะขัดจังหวะการรันและถามคุณ เมื่อไม่มีผู้อนุมัติเชื่อมต่ออยู่ มันจะปิดเมื่อล้มเหลวและการกระทำนั้นถูกปฏิเสธ ดู[ตั้งค่ากฎคุม](/th-TH/คู่มือ/วิธีทำ/ตั้งค่ากฎคุม/) สำหรับลำดับการแปลงคำตัดสินทั้งหมด

## การแก้ปัญหา

### เอเจนต์พุชไม่ได้และฉันไม่ได้ห้ามมันเลย

ตรวจสอบ **สิทธิ์แซนด์บ็อกซ์** ของเอเจนต์ เอเจนต์ที่ไม่มีชุดความสามารถที่กำหนดเองจะได้ค่าเริ่มต้นแบบอนุรักษ์นิยม ซึ่งปิด **อนุญาต git push** อยู่ — นายหน้าจึงไม่ใส่โทเคน GitHub และ git ไม่มีทางยืนยันตัวตน

### การ์ดแซนด์บ็อกซ์รายงานว่าไม่มีแซนด์บ็อกซ์เนทีฟ

แสดงว่าการรันเอเจนต์บนโฮสต์นั้นไม่ถูกห่อด้วย Seatbelt หรือ bubblewrap และขอบเขตที่เหลืออยู่คือสิ่งที่มี บน Linux และ WSL2 ให้ติดตั้งเครื่องมือที่ขาดทั้งสองตัว — `sudo apt-get install bubblewrap socat` — แล้วรีสตาร์ตเซิร์ฟเวอร์ ล็อกเริ่มต้นจึงควรบอกว่าแซนด์บ็อกซ์เปิดอยู่ บน Windows ไม่มีแบ็กเอนด์เนทีฟให้ติดตั้ง จึงควรกระชับกฎคุมแทน: ดู[ตั้งค่ากฎคุม](/th-TH/คู่มือ/วิธีทำ/ตั้งค่ากฎคุม/)

### เอเจนต์เข้าถึงไฟล์นอก worktree ของมัน

เครื่องมือตัวใดที่เข้าถึงมันเป็นตัวตัดสินว่านี่เป็นเรื่องที่คาดหมายได้หรือไม่

เครื่องมือไฟล์ในโปรเซสของฮาร์เนส (read, write, edit, apply patch, search, find, search_files) ทำงานในโปรเซสของเซิร์ฟเวอร์ จึงไม่มีโปรไฟล์แซนด์บ็อกซ์ใดใช้กับมัน — ขอบเขตของมันคือการจำกัดเส้นทางในตัวมันเองบวกกับกฎคุม คำสั่ง `bash` หรือ Claude Code CLI _ถูก_ ห่อที่ใดมีแบ็กเอนด์ และเช็กเอาต์ที่ลงทะเบียนไว้ของคุณเป็นเส้นทางที่ห้ามเขียนภายในที่ห่อนั้นในทุกโหมด รวมถึงรูปที่แปลงซิมลิงก์แล้วของมันด้วย (บน macOS เส้นทางที่เข้าถึงผ่าน `/tmp` หรือ `/var/folders` จะแปลงค่าอยู่ใต้ `/private` และทั้งสองรูปแบบถูกปฏิเสธในตอนนี้) บนโฮสต์ที่ไม่มีแบ็กเอนด์ ไม่มีข้อใดนั้นใช้เลย ไม่ทางใดก็ทางหนึ่ง กฎคุมสามารถปฏิเสธ **เขียนนอก worktree** ได้ทันที
