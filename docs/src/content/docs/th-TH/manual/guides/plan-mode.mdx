คู่มือนี้แสดงวิธีดึงแผนที่มีโครงสร้างออกมาจากเอเจนต์ก่อนที่มันจะเขียนโค้ดใด ๆ

ในโหมดแผน เอเจนต์จะค้นคว้าแบบอ่านอย่างเดียว และสิ่งที่ต้องส่งมอบมีเพียงอย่างเดียว
คือ **แผนแบบมีชนิดข้อมูล**: กราฟการพึ่งพาของขั้นตอนที่คุณอนุมัติ ซึ่ง Control Center
จะคอมไพล์ให้กลายเป็นงานจริง ใช้โหมดนี้เมื่อคุณต้องการเห็นขอบเขตของการเปลี่ยนแปลง
ให้ขั้นตอนถูกแบ่งย่อยออกมา หรือให้ความเสี่ยงและการพึ่งพาถูกระบุชื่อก่อนที่สิ่งใด
จะถูกแตะต้อง

## สลับสเปซเข้าสู่โหมดแผน

การกระทำใดต่อไปนี้ก็สลับโหมดของสเปซ และการเปลี่ยนแปลงนั้นถูกบันทึกไว้:

- เลือก **แผน** จากดรอปดาวน์โหมดที่ซ้ายสุดของแถบเครื่องมือช่องเขียนข้อความ
- กด **Shift+Tab**
- ส่ง `/plan` การส่ง `/plan` เปล่า ๆ แค่เปิดโหมดไว้ ส่วน `/plan <request>`
  จะเปิดโหมดแล้วส่งส่วนที่เหลือเป็นข้อความของคุณ

`/plan` ไม่เคยเดินทางในฐานะข้อความ — มันตั้งค่าโหมดที่จัดเก็บไว้ ซึ่งเป็นแหล่ง
อ้างอิงที่พื้นผิวเครื่องมือ พรีเซ็ตของกฎคุม และพรอมป์ต์ต่างอ่านด้วยกัน โหมดจึงคงอยู่
ทั้งเทิร์นนี้และทุกเทิร์นถัดจากนี้ จนกว่าคุณจะเปลี่ยนมันกลับ

โหมดถูกจัดเก็บไว้ที่สเปซ เอเจนต์ตัวเดียวกันจึงอยู่ในโหมดแผนที่นี่และอยู่ในโหมด
เอเจนต์ที่อื่นได้

## สิ่งที่เอเจนต์ผลิตออกมา

1. มันค้นคว้าแบบอ่านอย่างเดียว — หน่วยความจำ ดัชนีโค้ด ไฟล์
2. มันเรียก `submit_plan` **หนึ่งครั้ง** พร้อมด้วย `goal` และ `nodes` โดยแต่ละโหนด
   มี `key` ที่คงที่ มี `title` มี `description` และมีคีย์ของโหนดที่มัน `dependsOn`
   (ซึ่งเป็นสิ่งที่ทำให้งานที่เป็นอิสระต่อกันรันแบบขนานได้)
3. มันหยุด

เครื่องมือนี้ตรวจสอบความถูกต้องของกราฟ — คีย์ซ้ำ การพึ่งพาที่หลุดลอย วงจร — และ
คืนค่าการละเมิดให้เอเจนต์แก้ไข แทนที่จะยอมรับแผนที่พัง

แผนจะปรากฏ **ในการสนทนา** เป็นแถวกะทัดรัดที่แสดงเป้าหมาย สถานะของมัน และจำนวน
ขั้นตอน **Plan Studio** — กราฟการพึ่งพา ตัวตรวจสอบรายโหนด และค่าประมาณการต้นทุน —
เปิดเป็นแท็บข้างการสนทนา: กด **เปิด** บนแถวนั้น หรือเพียงรอ เพราะแผนที่มาถึงภายใน
30 วินาทีขณะที่คุณกำลังดูการสนทนาอยู่ จะเปิดแท็บของมันเอง

:::note[การรับประกันการอ่านอย่างเดียวเป็นเชิงโครงสร้าง แต่เฉพาะบนฮาร์เนสในตัว]
ฮาร์เนสของ Control Center เองสร้างทะเบียนเครื่องมือของเอเจนต์จากสเปกพื้นผิวของ
โหมดแผน จึงไม่มีเครื่องมือเขียน แก้ไข หรือคำสั่งให้เรียกได้เลย — ข้อจำกัดนี้ไม่ใช่
คำสั่งในพรอมป์ต์ที่โมเดลจะโน้มน้าวตัวเองให้หลุดออกมาได้

อะแดปเตอร์ Claude Code ไม่ได้รับการกรองเช่นนี้: โหมดไปถึงมันในฐานะคำขอที่ตัวรัน
ของมันอาจทำตามหรือไม่ก็ได้ และ Control Center เห็นเพียงการเรียก `mcp__*` ของมัน
เท่านั้น ป้ายการบังคับใช้ข้างดรอปดาวน์โหมดจะปรากฏขึ้นเมื่อเป็นเช่นนั้นพอดี
:::

:::note[เอเจนต์ถามคำถามเพื่อความกระจ่างกับคุณได้]
เมื่อคำขอคลุมเครือ เอเจนต์โหมดแผนสามารถหยุดและถามคุณได้สูงสุดสามคำถามแบบบล็อก
ด้วยเครื่องมือ `ask_user` มันเรนเดอร์แบบฟอร์มในการสนทนา — ตัวเลือก หรือข้อความ
อิสระ — และการรันจะบล็อกจนกว่าคุณจะตอบ เครื่องมือนี้อยู่ระดับอ่าน จึงอยู่รอดบน
พื้นผิวอ่านอย่างเดียวของโหมดแผน และมันได้รับการยกเว้นจากตัวห่อการอนุมัติ (พรอมป์ต์
ที่วางไว้หน้าพรอมป์ต์จะล้มเหลวแบบปิดเมื่อไม่มีผู้อนุมัติเชื่อมต่ออยู่ ซึ่งจะปฏิเสธ
เอเจนต์ในเรื่องการถาม)

มันต้องมีสเปซให้เรนเดอร์ลงไป การสั่งงานครั้งเดียวที่ไม่มีการสนทนาจึงไม่ได้รับมัน
การใส่ขอบเขต รีโปเป้าหมาย และเกณฑ์การยอมรับไว้ล่วงหน้าในข้อความแรกของคุณยังเร็วกว่า
การไปกลับหนึ่งรอบ
:::

ความเรียงไม่ใช่สิ่งที่ต้องส่งมอบที่นี่ การรันที่จบลงโดยไม่เรียก `submit_plan` จะโพสต์
บรรทัดที่มองเห็นได้ว่า "Ended without submitting a plan (no `submit_plan` call)."
ในการสนทนา และติดธงว่าการรันนั้นพลาดสิ่งที่ต้องส่งมอบ สถานะของการรันจงใจคงเป็น
_completed_ — นั่นทำให้เครื่องสถานะของไปป์ไลน์และตั๋วงานไม่ถูกแตะต้อง — ดังนั้น
จงอ่านบรรทัดนั้น ไม่ใช่ป้ายสถานะ

## อนุมัติแผน

จากแถวของแผนในการสนทนา กด **อนุมัติและรัน** จากแถบอนุมัติของ Plan Studio กด
**อนุมัติแผน** (หรือ **ปฏิเสธ** ที่อยู่ข้าง ๆ การอนุมัติจะถูกปิดกั้นขณะกราฟมี
ข้อผิดพลาดในการตรวจสอบความถูกต้อง)

จากนั้น:

1. Control Center คอมไพล์แผนเป็นการประสานงานและทำให้มันเกิดขึ้นจริง — ตั๋วงานและ
   การรัน ไม่มีโมเดลเกี่ยวข้องในขั้นตอนนี้ มันเป็นแบบกำหนดแน่นอน
2. แผนรันในฐานะเอเจนต์ที่เขียนมันขึ้นมา การจะดึงใครอื่นเข้ามาหรือไม่เป็นดุลพินิจ
   ของเอเจนต์ตัวนั้นตอนรัน — มันสามารถ `delegate_task` ขั้นตอนหนึ่งให้เพื่อนร่วมทีม
   ที่เหมาะสมกว่าได้ ภายในเพดานความลึกของการมอบหมายของเวิร์กสเปซ
3. เป้าหมายของแผนกลายเป็น **เป้าหมายของการสนทนา** และงานรัน **ในการสนทนาเดียวกัน
   นั้น**: แต่ละขั้นตอนจะโพสต์สิ่งที่เอเจนต์ถูกสั่ง และสตรีมเทิร์นของมันกลับมา คุณจึง
   ติดตามมันได้ (และหยุดเทิร์นได้) ในที่ที่คุณอยู่แล้ว
4. แถวเป้าหมายในแผงด้านข้าง **ทั่วไป** ของการสนทนา (ใต้สิ่งที่ต้องทำ) แบกความ
   คืบหน้าของการรันเป็น `settled/total` พร้อมปุ่มหยุดของมัน; Plan Studio แสดงสถานะ
   รายโหนดบนกราฟและยกเลิกได้ที่นั่นด้วย

## ทำงานต่อโดยไม่อนุมัติ

หากคุณอยากอยู่ในการสนทนานี้มากกว่าจะอนุมัติแผน เอเจนต์สามารถเรียก `exit_plan_mode`
ได้ นั่นคือทางออกเดียวที่ได้รับอนุญาต: มันเปิดคำขออนุมัติแบบถาวรที่เชื่อมโยงกับ
การสนทนาและคืนค่า `pending` — สเปซยังคงอยู่ในโหมดแผนและเอเจนต์ต้องไม่ลงมือ เมื่อ
คำขอได้รับการอนุมัติ การเรียก `exit_plan_mode` ครั้งถัดไปของเอเจนต์จะสลับสเปซจาก
โหมดแผนไปเป็นโหมดเอเจนต์และปลดล็อกเครื่องมือที่เปลี่ยนแปลงสถานะของมัน การถูกปฏิเสธ
ทำให้มันเปิดคำขอใหม่กับแผนฉบับแก้ไขได้

หากต้องการออกจากโหมดแผน ให้สลับดรอปดาวน์ของช่องเขียนข้อความ (หรือ Shift+Tab)
หรืออนุมัติแผนที่ส่งเข้ามา `exit_plan_mode` เปิดการอนุมัติแบบถาวรที่ตัดสินด้วย
เครื่องมือ MCP `decide_approval` แผงซ้อนทับของกฎคุมสำหรับการเรียกเครื่องมือที่ถูก
บล็อกเป็นคิวในหน่วยความจำที่แยกกัน และไม่พกคำขอออกจากโหมดแผน

## โหมดแผนในขั้นตอนไปป์ไลน์

โหนดไปป์ไลน์ `messaging.createSpace` อ่านโหมดของการสนทนาจาก **extra** `mode` ของ
การตั้งค่าโหนด — `extras['mode']: 'plan'` คีย์นี้ต้องตรงตัว: การสะกดแบบอื่นใด
รวมถึง `conversationMode` หรือ `dispatchMode` จะถูกเพิกเฉยอย่างเงียบ ๆ และห้องจะ
ถอยกลับไปใช้ค่าเริ่มต้นของบอดี ซึ่งเป็นโหมด **รีวิว** ไม่ใช่โหมดแชท ขั้นตอน
`promptAgent` เข้าร่วมห้องที่มันไม่ได้สร้างและไม่ได้กำหนดสิทธิ์ให้มันใหม่ ตัวเลือก
**โหมดจัดส่ง** ในตัวแก้ไขการตั้งค่าโหนด (`allParallel` / `manager`) ใช้สำหรับโหนด
สั่งงานทีม ตั้งค่าโหมดของการสนทนาด้วย `extras['mode']` บนเทมเพลตที่เปิดสเปซ หรือ
บนการตั้งค่าโหนดนั้นผ่าน API
