คู่มือนี้แสดงวิธีเชื่อมต่อผู้ให้บริการโมเดลและเลือกสิ่งที่เอเจนต์ใช้รัน

ทุกอย่างในนี้อยู่ในหน้าเดียว: **การตั้งค่า → เซิร์ฟเวอร์ → ผู้ให้บริการโมเดล** รายการในแถบข้างย่อยเขียนว่า “ผู้ให้บริการโมเดล” ส่วนหัวเรื่องของหน้าเขียนว่า “อะแดปเตอร์”

## อะแดปเตอร์คืออะไร

อะแดปเตอร์คือ_ตัวรัน_ที่รันเทิร์นของเอเจนต์ มีอยู่สองตัวและรายการนี้ตายตัว — คุณเพิ่มตัวที่สามไม่ได้

| อะแดปเตอร์                | CLI      | การขนส่ง                                              |
| ------------------------- | -------- | ----------------------------------------------------- |
| Control Center (built-in) | ไม่มี    | ลูปเอเจนต์ในโปรเซสเดียวกัน สื่อสารกับผู้ให้บริการผ่าน HTTP |
| Claude Code               | `claude` | `claude -p --output-format stream-json`               |

Cursor, Codex, Anthropic, OpenAI และอื่น ๆ เป็น**ผู้ให้บริการ**บนอะแดปเตอร์ในตัว ไม่ใช่ CLI แยกต่างหาก สิ่งที่คุณ_เพิ่มได้_คือผู้ให้บริการอีกราย — ปลายทางใดก็ตามที่เข้ากันได้กับ OpenAI หรือ Anthropic นั่นคือหัวข้อถัดไป

:::note[การตรวจจับตรวจสอบเซิร์ฟเวอร์ ไม่ใช่เครื่องของคุณ]
การ์ด **ตัวรันที่ตรวจพบ** แสดงรายการสิ่งที่ `cc_server` พบบน `PATH` ของ_โฮสต์เซิร์ฟเวอร์_ บนไคลเอนต์แบบบางหรือไคลเอนต์เว็บ นั่นคือเครื่องคนละเครื่องกับที่คุณกำลังดูอยู่ ให้ติดตั้ง CLI บนเครื่องที่รัน `cc_server`
:::

## เชื่อมต่อผู้ให้บริการโมเดล

อะแดปเตอร์ในตัวต้องมีผู้ให้บริการที่เชื่อมต่ออย่างน้อยหนึ่งรายก่อนจึงจะรันได้ แค็ตตาล็อกมีมาให้ 14 ราย

1. ไปที่ **การตั้งค่า → เซิร์ฟเวอร์ → ผู้ให้บริการโมเดล**
2. เลื่อนไปที่ **ผู้ให้บริการและโมเดล**
3. ค้นหาผู้ให้บริการของคุณแล้วเชื่อมต่อ:

| ผู้ให้บริการ                                                                                             | วิธีเชื่อมต่อ                                                                                                                  |
| -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Anthropic                                                                                                | คีย์ API การสมัครสมาชิก Claude Pro/Max ไม่ใช่การลงชื่อเข้าใช้ API ของ Anthropic — ให้ใช้อะแดปเตอร์ Claude Code สำหรับแพ็กเกจนั้น |
| OpenAI, Codex, Cursor                                                                                    | ลงชื่อเข้าใช้ OAuth ผ่านเบราว์เซอร์ หรือใช้คีย์ API Codex คือ ChatGPT Plus/Pro ผ่านแบ็กเอนด์ Codex Responses ไม่ใช่การสปอว์น CLI |
| Kimi Code                                                                                                | OAuth ผ่านเบราว์เซอร์เท่านั้น — เป็นโฟลว์ device code เป็นแพ็กเกจเหมาจ่าย จึงไม่มีราคาต่อโทเคน                                   |
| OpenRouter, Groq, Google Gemini, DeepSeek, Mistral, xAI, z.ai, z.ai GLM Coding Plan, Moonshot (Kimi API) | คีย์ API                                                                                                                      |

จุดตรวจสอบ: แบดจ์ของแถวจะเปลี่ยนเป็น “เชื่อมต่อแล้ว” และเมื่อขยายแถวจะแสดงโมเดลที่ผู้ให้บริการรายนั้นให้บริการ แต่ละโมเดลมีราคาต่อโทเคนหนึ่งล้านและหน้าต่างบริบทกำกับอยู่

โทเคน OAuth จะไปอยู่ในที่เก็บข้อมูลรับรองของเซิร์ฟเวอร์เอง และถูกต่ออายุใหม่ก่อนหมดอายุ ข้อมูลรับรองของผู้ให้บริการเป็น**ระดับโฮสต์** — ใช้ร่วมกันโดยทุกเวิร์กสเปซในการติดตั้งนี้ ไม่ได้จำกัดขอบเขตไว้ที่เวิร์กสเปซใดเวิร์กสเปซหนึ่ง

### เพิ่มผู้ให้บริการที่กำหนดเอง

ใช้วิธีนี้กับ Ollama, LM Studio, vLLM หรือการติดตั้งใช้งานส่วนตัว

1. ใน **ผู้ให้บริการและโมเดล** ใต้ **ผู้ให้บริการที่กำหนดเอง** กด **เพิ่มผู้ให้บริการ**
2. กรอก **ชื่อ** เลือก **ชนิด API** (ที่เข้ากันได้กับ OpenAI หรือ Anthropic) และใส่ **Base URL** (ตัวอย่าง `http://localhost:11434/v1`)
3. เพิ่ม **คีย์ API** หากปลายทางต้องใช้ แล้วกด **เพิ่มผู้ให้บริการ**

ผู้ให้บริการที่กำหนดเองจะปรากฏในรายการเดียวกัน พร้อมปุ่มลบที่ผู้ให้บริการในตัวรายอื่นไม่มี

## เลือกโมเดลให้เอเจนต์

1. ไปที่ **การตั้งค่า → เวิร์กสเปซ → เอเจนต์** แล้วเลือกเอเจนต์
2. บนแท็บ **การตั้งค่า** เลือก **อะแดปเตอร์**
3. เลือก **โมเดล** จากเมนูแบบเลื่อนลงข้าง ๆ

สำหรับอะแดปเตอร์ในตัว เมนูแบบเลื่อนลงถูกประกอบขึ้นสด ๆ จากแค็ตตาล็อกของผู้ให้บริการที่เชื่อมต่อทุกราย ผู้ให้บริการที่ไม่มีข้อมูลรับรองที่เก็บไว้จะไม่มีโมเดลมาให้เลย เพราะฉะนั้นเมนูที่ว่างเปล่าเกือบทุกครั้งจึงหมายถึง “ยังไม่ได้เชื่อมต่ออะไรเลย” มากกว่า “ไม่มีอะไรให้ใช้”

:::note[models.dev เป็นเพียงข้อมูลเสริม ไม่เคยเป็นแหล่งของ id]
แค็ตตาล็อก [models.dev](https://models.dev) ที่มาพร้อมระบบให้ราคาและหน้าต่างบริบทสำหรับโมเดลที่อยู่ในรายการสดแล้วเท่านั้น มันไม่เคยเพิ่ม id ของโมเดล หากโมเดลที่คุณคาดว่าจะมีหายไป แปลว่าปลายทางของผู้ให้บริการไม่ได้ส่งโมเดลนั้นกลับมา
:::

id ของโมเดลสำหรับอะแดปเตอร์ในตัวอยู่ในรูปแบบที่ระบุคุณสมบัติ `provider/model` และอาจมีเชนสำรองที่คั่นด้วย `|` เมื่อใช้ตัวสำรอง ต้นทุนจะคิดราคาตามโมเดลที่ให้บริการเทิร์นนั้นจริง ๆ ไม่ใช่โมเดลที่คุณขอไป

:::note[เอเจนต์ที่ไม่มีอะแดปเตอร์จะรันบนลูปในตัว]
ทุกเวิร์กสเปซสร้างเอเจนต์เริ่มต้นห้าตัว — CEO หนึ่งตัว บวก `qa`, `architect`, `engineer` และ `librarian` — โดยไม่มีอะแดปเตอร์และไม่มีโมเดล การสั่งงานจะถอยกลับไปใช้ **Control Center (built-in)** ไม่ใช่การตั้งค่า **ตัวรันเริ่มต้น** ในหน้านี้ ซึ่งเป็นค่ากำหนดฝั่งไคลเอนต์ที่เส้นทางการสั่งงานไม่เคยอ่าน บันทึกการรันจะบันทึก `cc-harness` สำหรับการรันเหล่านั้น บันทึกการสนทนาจึงระบุได้ว่าอะไรคือสิ่งที่รันจริง

และเมื่อไม่มีโมเดลด้วย ลูปในตัวจะขอโมเดลเริ่มต้นจาก Anthropic เอเจนต์ที่ไม่ได้ตั้งค่าไว้เลยจึงรันได้หากคุณเชื่อมต่อบัญชี Anthropic ไว้ และถ้าไม่ก็จะล้มเหลวด้วย `No credential for provider "anthropic"`

การทำขั้นตอนอะแดปเตอร์ของการเริ่มต้นใช้งานให้เสร็จจะเติมย้อนหลังให้กับ**ทุก**เอเจนต์ที่ยังขาดอะแดปเตอร์หรือโมเดล — ทั้ง CEO และผู้เชี่ยวชาญ ทั่วทุกเวิร์กสเปซที่มีอยู่ในขณะนั้น — ด้วยคู่ที่คุณเลือก เวิร์กสเปซที่สร้างขึ้นภายหลังยังคงสร้างเอเจนต์เริ่มต้นทั้งห้าแบบไม่ตั้งค่าไว้ ให้ตั้งอะแดปเตอร์และโมเดลอย่างชัดเจนให้กับทุกเอเจนต์ที่คุณตั้งใจจะใช้
:::

## ติดตั้ง CLI ของตัวรัน

อะแดปเตอร์ในตัวไม่ต้องติดตั้งอะไร สำหรับ Claude Code ให้ติดตั้ง CLI ของมัน **บนโฮสต์เซิร์ฟเวอร์** ด้วยตัวจัดการแพ็กเกจของเครื่องมือนั้น ตัวอย่างเช่น:

```bash
npm install -g @anthropic-ai/claude-code
```

จากนั้นกด **รีเฟรช** ที่ด้านบนของหน้า แต่ละแถวที่ตรวจพบจะแสดงเวอร์ชันและพาธที่แก้ไขแล้ว พร้อมชิปที่บอกว่ารองรับโหมด JSON และการเลือกโมเดลหรือไม่

CLI ภายนอกเก็บข้อมูลรับรองของตัวเองไว้ในการกำหนดค่าของตัวเอง บนโฮสต์เซิร์ฟเวอร์ Control Center ไม่ได้จัดการสิ่งเหล่านั้น

:::caution[อาร์กิวเมนต์ของอะแดปเตอร์และตัวแปรสภาพแวดล้อมอยู่บนอุปกรณ์นี้]
แต่ละแถวของอะแดปเตอร์มีฟิลด์ **อาร์กิวเมนต์** และกล่องโต้ตอบ **ตัวแปรสภาพแวดล้อม** ค่าเหล่านั้นถูกเก็บไว้บนอุปกรณ์ของคุณ เซิร์ฟเวอร์อ่าน argv และ env สำหรับการเปิดใช้งานจากที่เก็บการตั้งค่าของตัวเอง ให้ใส่คีย์ของผู้ให้บริการไว้บนเซิร์ฟเวอร์ (OAuth หรือช่องกรอกคีย์ในหน้าผู้ให้บริการโมเดล) ไม่ใช่ในสองฟิลด์นั้น
:::

## จำกัดว่าผู้ให้บริการรายใดที่เวิร์กสเปซใช้ได้

การกำกับผู้ให้บริการเป็นรายเวิร์กสเปซ และประเมินแบบรายการที่ตรงท้ายสุดมีผล

1. ใน **ผู้ให้บริการและโมเดล** ปิดสวิตช์ **อนุญาต** บนแถวของผู้ให้บริการ

การทำเช่นนี้จะเขียนคำสั่ง `deny` สำหรับผู้ให้บริการรายนั้นในเวิร์กสเปซที่ใช้งานอยู่ และโมเดลของรายนั้นจะหลุดออกจากแค็ตตาล็อกของเวิร์กสเปซนั้น การเปิดสวิตช์กลับจะลบคำสั่งนั้นออก

## การแก้ไขปัญหา

### ตัวรันแสดงว่าไม่พบ

- ตรวจสอบว่า CLI อยู่บน `PATH` ของ**โฮสต์เซิร์ฟเวอร์** ไม่ใช่แค่ของเครื่องคุณ
- แอปเดสก์ท็อปที่เปิดผ่าน GUI จะสปอว์นเซิร์ฟเวอร์ของมันด้วย `PATH` ที่จำกัด CLI ที่ติดตั้งไว้ในพาธที่เข้าถึงได้จากเชลล์เท่านั้นอาจมองไม่เห็นสำหรับมัน
- กด **รีเฟรช** หลังติดตั้ง

### เมนูแบบเลื่อนลงของโมเดลว่างเปล่า

- อะแดปเตอร์เป็นแบบในตัวและยังไม่ได้เชื่อมต่อผู้ให้บริการ — ให้เชื่อมต่อรายหนึ่งใน **ผู้ให้บริการและโมเดล**
- หรือผู้ให้บริการเชื่อมต่ออยู่แต่ถูกปฏิเสธโดยสวิตช์กำกับของเวิร์กสเปซนี้

### โมเดลรันได้แต่ราคาแสดงเป็นไม่ทราบ

รายการโมเดลสดมี id อยู่ ส่วนราคาและบริบทมาจาก models.dev โมเดลที่ใหม่เอี่ยม หรือโมเดลจากผู้ให้บริการที่กำหนดเอง ยังไม่มีรายการในแค็ตตาล็อก
