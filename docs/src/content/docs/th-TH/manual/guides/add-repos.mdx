คู่มือนี้แสดงวิธีลงทะเบียนเช็กเอาต์ Git เข้าเวิร์กสเปซ จัดทำดัชนีใหม่ และลบมันออกอีกครั้ง การเพิ่มรีโพสิทอรีจากโฟลเดอร์ของเซิร์ฟเวอร์ต้องใช้เจ้าของเซิร์ฟเวอร์ ส่วนการลบต้องใช้ผู้ดูแลเวิร์กสเปซ

รีโปมี**ขอบเขตอยู่ที่เวิร์กสเปซ** ไม่มีทะเบียนส่วนกลางและไม่มีขั้นตอนเชื่อมโยงใด ๆ การเพิ่มรีโปกับการใส่รีโปเข้าเวิร์กสเปซคือการกระทำเดียวกัน เช็กเอาต์เดียวกันที่ลงทะเบียนในสองเวิร์กสเปซจะกลายเป็นสองแถวอิสระที่มี id ต่างกันสองค่า — เมื่อข้ามเวิร์กสเปซแล้ว ตัวตนของรีโปคือพาธในระบบไฟล์ของมัน ไม่ใช่ id ของมันเลย

## ก่อนที่คุณจะเริ่ม

โฟลเดอร์จะลงทะเบียนได้ก็ต่อเมื่อเข้าเงื่อนไขทั้งสามข้อนี้พร้อมกัน:

1. อยู่ภายใน **git work tree**
2. work tree นั้นมี **remote `origin`**
3. remote `origin` ชี้ไปที่ **โฮสต์โค้ดที่รองรับ**: github.com, gitlab.com หรือ bitbucket.org

สิ่งอื่นใดจะถูกปฏิเสธตอนลงทะเบียนพร้อมข้อความที่ชัดเจน: “Folder is not inside a git work tree.”, “No `origin` remote configured for this repository.” หรือ “The `origin` remote is not hosted on a supported forge (github.com, gitlab.com, bitbucket.org).” ไม่มีโหมดที่ทำงานในเครื่องเท่านั้น

โฮสต์โค้ดถูกอ่านจาก remote และเก็บไว้บนรีโป — คุณไม่เคยต้องเลือกมันเอง เวิร์กสเปซหนึ่งแห่งเก็บรีโปจากทั้งสามแห่งพร้อมกันได้ และแต่ละแห่งจะถูกสื่อสารผ่าน API ของตัวเองด้วยข้อมูลรับรองของตัวเอง เนมสเปซซ้อนกันของ GitLab จะถูกเก็บไว้ ดังนั้น `gitlab.com/group/subgroup/project` จึงลงทะเบียนด้วย owner `group/subgroup` และ name `project`

โฟลเดอร์ยังต้องอยู่บนเครื่องที่โฮสต์ `cc_server` ภายในไดเรกทอรี `--repo-roots` ตัวใดตัวหนึ่งของเซิร์ฟเวอร์นั้นด้วย รายการที่อนุญาตนี้มีค่าเริ่มต้นเป็นโฮมไดเรกทอรีของผู้ใช้เซิร์ฟเวอร์ และการเรียกดูเหนือรากขึ้นไปจะถูกปฏิเสธ การเรียกดูโฟลเดอร์ของเซิร์ฟเวอร์จะเสนอให้เฉพาะ[เจ้าของเซิร์ฟเวอร์](/th-TH/คู่มือ/แนวคิด/การอนุญาต/#เจ้าของเซิร์ฟเวอร์)เท่านั้น เพราะมันแสดงไฟล์ของเครื่อง ผู้อื่นจะเห็น "เจ้าของเซิร์ฟเวอร์เป็นผู้เพิ่มรีโพสิทอรีจากโฟลเดอร์ของเซิร์ฟเวอร์" ในตำแหน่งของปุ่ม **เพิ่มรีโพสิทอรี** และลิงก์ไปยังรีโพสิทอรีที่ไม่มีเวิร์กสเปซใดของพวกเขามี จะบอกว่ารีโพสิทอรีนั้นไม่ได้เชื่อมโยงอยู่ในเวิร์กสเปซใดของพวกเขาเลย และให้ขอให้เจ้าของเซิร์ฟเวอร์เพิ่มมัน

การเชื่อมโยงโฟลเดอร์ต่อไปนี้ขึ้นอยู่กับผู้เชื่อมโยง:

- **ภายในพื้นที่จัดเก็บของเวิร์กสเปซ** บนเซิร์ฟเวอร์: ผู้ดูแลเวิร์กสเปซคนใดก็ได้
- **ที่อื่นบนดิสก์ของเซิร์ฟเวอร์**: เฉพาะ[เจ้าของเซิร์ฟเวอร์](/th-TH/คู่มือ/แนวคิด/การอนุญาต/#เจ้าของเซิร์ฟเวอร์)เท่านั้น เพราะมีเพียงพวกเขาที่ชี้เซิร์ฟเวอร์ไปยังไฟล์ของเครื่องได้ ผู้อื่นจะเห็น "เฉพาะเจ้าของเซิร์ฟเวอร์เท่านั้นที่เชื่อมโยงโฟลเดอร์นอกพื้นที่จัดเก็บของเวิร์กสเปซนี้ได้"
- **โฟลเดอร์ข้อมูลของเซิร์ฟเวอร์** หรือสิ่งใดก็ตามที่อยู่ข้างใน: ไม่เคย

`origin` ของเช็กเอาต์ต้องเป็นรีโพสิทอรีที่คุณกำลังเชื่อมโยง โฟลเดอร์ที่ `origin` ระบุรีโพสิทอรีอื่นจะถูกปฏิเสธพร้อมข้อความ "origin ของโฟลเดอร์นั้นเป็นรีโพสิทอรีอื่น"

### โฟลเดอร์ที่เซิร์ฟเวอร์ยังไม่ใช้

รีโพสิทอรีที่โฟลเดอร์อยู่นอกพื้นที่จัดเก็บของเวิร์กสเปซและไม่ได้ถูกเชื่อมโยงโดยเจ้าของเซิร์ฟเวอร์ เช่น รีโพสิทอรีในเวิร์กสเปซที่นำเข้ามา จะแสดง "โฟลเดอร์นี้อยู่นอกพื้นที่จัดเก็บของเวิร์กสเปซ ยืนยันว่าเซิร์ฟเวอร์นี้อนุญาตให้ใช้โฟลเดอร์นี้" ใต้แถวของมัน จนกว่าเจ้าของเซิร์ฟเวอร์จะยืนยัน ผู้อื่นจะเห็น "โฟลเดอร์นี้อยู่นอกพื้นที่จัดเก็บของเวิร์กสเปซ เฉพาะเจ้าของเซิร์ฟเวอร์เท่านั้นที่ยืนยันได้" แทน

เจ้าของยืนยันเพียงครั้งเดียว: กด **ยืนยัน** ที่แถว หรือ **ยืนยันทั้งหมด** ในการแจ้งเตือนเหนือรายการเมื่อมีหลายรีโพสิทอรีรออยู่ แต่ละรายการจะถูกตรวจสอบอีกครั้งในนามของเจ้าของ ด้วยการตรวจสอบเดียวกับตอนเชื่อมโยง จนกว่าจะยืนยัน รีโพสิทอรีจะยังอยู่ในรายการแต่จะไม่ถูกเปิด จัดเตรียม หรือจัดทำดัชนี: ไม่มีตัวแก้ไข เทอร์มินัล สภาพแวดล้อม หรือเช็กเอาต์ของสเปซใดใช้มัน และตัวสร้างกราฟโค้ดจะข้ามมัน การเพิ่มโฟลเดอร์เดิมอีกครั้งในฐานะเจ้าของเซิร์ฟเวอร์ให้ผลเช่นเดียวกับการยืนยัน และคงรหัสของรีโพสิทอรีไว้

เช็กเอาต์ที่ symbolic link ย้ายไปที่อื่นจะถูกจัดการในลักษณะเดียวกัน: มันยังคงแสดงในรายการและไม่ถูกใช้ จนกว่าจะถูกเชื่อมโยงใหม่โดยผู้ที่มีสิทธิ์เชื่อมโยงโฟลเดอร์ที่มันชี้ไปในปัจจุบัน

คุณต้องลงชื่อเข้าใช้ฟอร์จของรีโพสิทอรีด้วย และบัญชีของคุณเองต้องมองเห็นรีโพสิทอรีนั้นได้

## ลงทะเบียนเช็กเอาต์

คุณต้องเป็นเจ้าของเซิร์ฟเวอร์สำหรับขั้นตอนเหล่านี้

1. เปิด **การตั้งค่า → เวิร์กสเปซ → รีโพสิทอรี** (`/workspaces/<id>/settings/workspace/repositories`)
2. คลิก **เพิ่มรีโพสิทอรี**

ไดอะล็อกนี้เป็นเบราว์เซอร์ที่เรียกดูได้บนระบบไฟล์ของ**เซิร์ฟเวอร์** ไม่ใช่ของคุณ ขั้นตอนเดียวกันทั้งบนเดสก์ท็อป เว็บ และโทรศัพท์ เพราะตัวเลือกโฟลเดอร์แบบเนทีฟจะเลือกโฟลเดอร์บนเครื่องผิดเครื่อง

3. เรียกดูภายในรากที่กำหนดค่าไว้ของเซิร์ฟเวอร์ โฟลเดอร์ที่เป็นเช็กเอาต์ git จะถูกทำเครื่องหมายไว้
4. เลือกได้ตามจำนวนที่ต้องการ และการเลือกจะคงอยู่แม้คุณจะเรียกดูต่อไป คุณจึงรวบรวมเช็กเอาต์จากหลายโฟลเดอร์ได้
5. ลงทะเบียนทั้งหมดในคราวเดียว

การเลือกที่ล้มเหลวหนึ่งรายการไม่เคยทำให้ส่วนที่เหลือของชุดหลุดไป — คุณจะได้ id ที่ถูกสร้างขึ้น บวกกับข้อผิดพลาดรายพาธสำหรับแต่ละรายการที่ถูกปฏิเสธ การลงทะเบียนพาธที่อยู่ในเวิร์กสเปซนี้อยู่แล้วซ้ำจะคืนรีโปที่มีอยู่แล้ว แทนที่จะสร้างรายการซ้ำขึ้นใหม่

รีโปที่ลงทะเบียนแต่ละรายการจะปรากฏในรายการพร้อม `owner/name` ป้ายชื่อที่บอกโฮสต์โค้ดของมัน และพาธของมันบนเซิร์ฟเวอร์ รีโป GitHub ยังแสดงอวตารของเจ้าของด้วย ส่วนโฮสต์โค้ดอื่นไม่มี URL อวตารของเจ้าของที่เดาได้ จึงถอยกลับไปใช้อักษรย่อ

ป้ายโฮสต์โค้ดสำคัญในเวิร์กสเปซแบบผสม: รีโปสองรายการอาจชื่อ `acme/web` เหมือนกันบนโฮสต์โค้ดต่างกัน และมันทำงานต่างกัน — รีวิวทำอะไรได้ และลิงก์จะพาไปที่ไหน

## สิ่งที่เกิดขึ้นต่อไป

การลงทะเบียนจะยิงเหตุการณ์ `RepoAdded` ที่มีขอบเขตอยู่ที่เวิร์กสเปซนี้ ซึ่งจะเริ่มไปป์ไลน์ `index_code` สำหรับเช็กเอาต์นั้น นั่นคือสิ่งที่เติมข้อมูลให้กราฟโค้ด การค้นหาและการวิเคราะห์ผลกระทบจึงมีอะไรให้ตอบ

เฉพาะไฟล์ที่ภาษาของมันมีไวยากรณ์ที่จัดส่งมาด้วยเท่านั้นที่จะถูกจัดทำดัชนี (Dart, JavaScript, TypeScript, TSX, PHP, Python, Rust, Zig, C, C++, Go, Java, Ruby, C#, Swift, Kotlin, R, Assembly, MATLAB และ Ada) ดู[ค้นหาโค้ดด้วยกราฟโค้ด](/th-TH/คู่มือ/วิธีทำ/ค้นหาโค้ด/)

## จัดทำดัชนีรีโปใหม่

แต่ละแถวมีปุ่ม **จัดทำดัชนีโค้ด** คลิกเพื่อรันตัวจัดทำดัชนีซ้ำสำหรับเช็กเอาต์นั้น ระหว่างที่มันรัน ปุ่มจะกลายเป็นตัวแสดงความคืบหน้าที่บอกจำนวนไฟล์ที่ทำเสร็จเทียบกับทั้งหมด พร้อมตัวควบคุมการยกเลิก เมื่อเสร็จ มันจะหยุดนิ่งเป็นเครื่องหมายถูกพร้อมจำนวนสัญลักษณ์ หรือเป็นคำเตือนหากการรันล้มเหลว

## จัดลำดับรีโปใหม่

ลากที่จับบนแถว ลำดับที่คุณตั้งไว้คือลำดับที่รายการรีโปทุกแห่งในแอปอ่านกลับมา

## แก้ไขลิงก์ GitHub

ไอคอนลิงก์บนแถวจะเปิดตัวแก้ไข owner และชื่อรีโพสิทอรีของ GitHub ของรีโป

คุณแทบไม่ต้องใช้มัน ลิงก์ผูกกับ id ถาวรของรีโพสิทอรีบนฟอร์จ ดังนั้นการเปลี่ยนชื่อหรือการโอนย้ายจะถูกติดตามโดยอัตโนมัติ

- การเปลี่ยนชื่อรีโพสิทอรีใน Control Center เปลี่ยนเฉพาะชื่อที่แสดงเท่านั้น
- การเปลี่ยนว่าลิงก์ชี้ไปที่รีโพสิทอรีบนฟอร์จรายการใดต้องใช้ผู้ดูแลเวิร์กสเปซ และจะตรวจสอบกับฟอร์จด้วยการลงชื่อเข้าใช้ของผู้ดูแลเอง เหมือนกับการเชื่อมโยง
- รีโพสิทอรีที่เชื่อมโยงแล้วไม่สามารถเปลี่ยนเป็นรีโพสิทอรีที่มีแต่ในเครื่องได้

หากพาธในภายหลังระบุ**รีโพสิทอรีอื่น** (ต้นฉบับถูกลบแล้วสร้างใหม่ หรือถูกย้ายแล้วแทนที่ด้วยอีกรายการ) Control Center จะหยุดส่งสิ่งใดไปยังมัน: ไม่มีโทเค็น การพุช ความคิดเห็น หรือคำขอ ซึ่งรวมถึงการกระทำของบุคคลเองด้วย การรีวิว การรวม หรือความคิดเห็นที่คุณทำกับรีโพสิทอรีเช่นนั้นจะถูกปฏิเสธ ไม่ว่าจะเป็น GitHub, GitLab หรือ Bitbucket แถวและ pull request ของรีโพสิทอรีจะแสดง "_repo_ ตอนนี้ชี้ไปยังรีโพสิทอรีอื่น" จนกว่าผู้ดูแลเวิร์กสเปซจะคลิก **เชื่อมโยงใหม่**

## ใครเปิดโค้ดได้บ้าง

การให้สิทธิ์รีโพสิทอรีเพียงอย่างเดียวไม่ได้เปิดไฟล์ของรีโพสิทอรี เพื่อเปิดไฟล์ diff การค้นหา หรือเทอร์มินัลของมัน สมาชิกต้องมีสิทธิ์ของ Control Center และการลงชื่อเข้าใช้ฟอร์จของตนเองต้องอ่านรีโพสิทอรีนั้นได้ ผู้ดูแลเวิร์กสเปซไม่ได้รับการยกเว้น มีเพียงเจ้าของเซิร์ฟเวอร์เท่านั้นที่ได้รับการยกเว้น ดู [โค้ดทำตามฟอร์จ](/th-TH/คู่มือ/แนวคิด/การอนุญาต/#โค้ดเป็นไปตาม-forge)

เมื่อคุณให้สิทธิ์รีโพสิทอรีแก่ใครสักคนที่บัญชีฟอร์จอ่านรีโพสิทอรีนั้นไม่ได้ สิทธิ์จะถูกบันทึกและคุณจะเห็นคำเตือน เช่น "บันทึกแล้ว บัญชี GitHub ของพวกเขายังอ่านรีโพสิทอรีนี้ไม่ได้ จึงยังคงซ่อนจากพวกเขาอยู่"

กฎเดียวกันนี้กำหนดว่าใครเปิดสเปซได้ สเปซจะเปิดได้เฉพาะสมาชิกที่เปิดโค้ดของทุกรีโพสิทอรีที่สเปซใช้ได้ และซ่อนจากทุกคนอื่น พร้อมผลการค้นหา บันทึกการรัน รายการสิ่งที่ต้องทำ กิจกรรม และการแจ้งเตือนของมัน สเปซที่ไม่มีรีโพสิทอรีเปิดให้สมาชิกทุกคน ดู [สเปซทำตามรีโพสิทอรีของมัน](/th-TH/คู่มือ/แนวคิด/การอนุญาต/#สเปซตามรีโปของมัน)

## ลบรีโป

1. เปิด **การตั้งค่า → เวิร์กสเปซ → รีโพสิทอรี**
2. คลิกไอคอนถังขยะบนแถว
3. ยืนยัน “ลบรีโพสิทอรีออกจากเวิร์กสเปซหรือไม่?”

ไดอะล็อกบอกว่ามันทำอะไร: “_name_ จะถูกลบออกจากเวิร์กสเปซนี้ ไฟล์ในเครื่องบนดิสก์จะไม่ถูกแตะต้อง”

การลบรีโพสิทอรีต้องใช้ผู้ดูแลเวิร์กสเปซ และยังลืมข้อมูลรับรองของฟอร์จที่เก็บไว้สำหรับรีโพสิทอรีนั้น เช่น โทเค็นระบบอัตโนมัติของ GitLab หรือ Bitbucket ด้วย

การลบจะลบแถวรีโปออกจากเวิร์กสเปซนี้ และลบแถวกราฟโค้ดของมันตามไปเป็นทอด — สัญลักษณ์ เส้นเชื่อม ไฟล์ และจุดตรวจสอบการจัดทำดัชนี — รวมถึงสิทธิ์รีโปต่อสมาชิกแต่ละคนบนมัน ลิงก์สเปซ-รีโปของมัน และบันทึกเช็กเอาต์แบบแยกโดดของมัน เช็กเอาต์เดียวกันที่ลงทะเบียนในเวิร์กสเปซอื่นเป็นแถวอิสระและไม่ได้รับผลกระทบ worktree บนดิสก์ที่บันทึกเหล่านั้นชี้ไปจะไม่ถูกรื้อถอนโดยการลบนี้

## การแก้ปัญหา

### มีสิทธิ์เข้าถึงในเวิร์กสเปซแต่บัญชีของฉันอ่านรีโพสิทอรีนั้นไม่ได้

บัญชีฟอร์จของคุณเองอ่านรีโพสิทอรีไม่ได้ ดังนั้น Control Center จึงกันโค้ดของมันไว้จากคุณ แม้เวิร์กสเปซจะให้สิทธิ์แล้วก็ตาม ลงชื่อเข้าใช้ฟอร์จที่ **การตั้งค่า → คุณ → โปรไฟล์ → โฮสต์โค้ด** หากคุณยังไม่ได้ทำ หรือขอสิทธิ์เข้าถึงรีโพสิทอรีจากเจ้าของบนฟอร์จ รีโพสิทอรีจะเปิดทันทีที่บัญชีฟอร์จของคุณอ่านได้

### "โฟลเดอร์นี้อยู่นอกพื้นที่จัดเก็บของเวิร์กสเปซ"

โฟลเดอร์ของรีโพสิทอรีอยู่นอกพื้นที่จัดเก็บของเวิร์กสเปซและเจ้าของเซิร์ฟเวอร์ไม่ได้เชื่อมโยงไว้ หรือตอนนี้ symbolic link ชี้ไปที่ที่อื่น มันยังคงแสดงในรายการแต่ไม่ถูกใช้งานจนกว่าเจ้าของเซิร์ฟเวอร์จะยืนยันหรือเพิ่มโฟลเดอร์อีกครั้ง หากคุณไม่ใช่เจ้าของ ให้ขอให้เขาทำ หากคุณเป็นเจ้าของ ให้กด **ยืนยัน** ที่แถว หรือ **ยืนยันทั้งหมด** เหนือรายการ ดู [โฟลเดอร์ที่เซิร์ฟเวอร์ยังไม่ใช้](#โฟลเดอร์ที่เซิร์ฟเวอร์ยังไม่ใช้)

### "ไม่มีอะไรอยู่ที่พาธนี้บนเซิร์ฟเวอร์อีกแล้ว"

โฟลเดอร์ถูกย้ายหรือลบบนเครื่องของเซิร์ฟเวอร์ นำกลับมาไว้ที่เดิม หรือให้ผู้ดูแลเวิร์กสเปซลบรีโพสิทอรีด้วย **ลบออก** ในการแจ้งเตือน แล้วเพิ่มใหม่จากโฟลเดอร์ปัจจุบัน

### "โฟลเดอร์นี้ใช้เป็นรีโพสิทอรีไม่ได้"

โฟลเดอร์ที่เก็บไว้เป็นโฟลเดอร์ข้อมูลของเซิร์ฟเวอร์เอง สิ่งที่อยู่ข้างในนั้น หรือโฟลเดอร์พื้นที่จัดเก็บของเวิร์กสเปซเอง ไม่มีสิ่งใดเหล่านี้ที่เป็นรีโพสิทอรีได้ ผู้ดูแลเวิร์กสเปซลบด้วย **ลบออก** ในการแจ้งเตือน จากนั้นเพิ่มรีโพสิทอรีใหม่จากโฟลเดอร์เช็กเอาต์จริง

### "ยืนยันสิทธิ์เข้าถึง forge ของคุณไม่ได้"

Control Center ไม่สามารถติดต่อฟอร์จเพื่อตรวจว่าบัญชีของคุณอ่านรีโพสิทอรีได้หรือไม่ จึงปฏิเสธแทนการเดา ลองอีกครั้งในอีกสักครู่
