คู่มือนี้แสดงวิธีทำงานกับแผนใน Plan Studio สำหรับความหมายของการประสานงานและ
เอกสารแผน ดู[การประสานงาน](/th-TH/คู่มือ/แนวคิด/การประสานงาน/)และ
[ใช้โหมดแผน](/th-TH/คู่มือ/วิธีทำ/โหมดแผน/)

## เปิดแผน

แผนเป็นของบทสนทนาที่สร้างมันขึ้นมา นั่นจึงเป็นที่ที่คุณเข้าถึงมันตามปกติ: แถวของแผน
ในบทสนทนามีการดำเนินการ **เปิด** และ Plan Studio จะเปิดเป็นแท็บตัวแก้ไขข้างบทสนทนา

:::note[ไม่มีรายการ "แผน" ในแถบข้าง]
นั่นเป็นความตั้งใจ ไม่ใช่การมองข้าม ฮับที่
`/workspaces/<workspace-id>/plans` เป็นเพียงดีปลิงก์ที่กำหนดเส้นทางได้เท่านั้น
จึงควรบุ๊กมาร์กไว้ถ้าคุณต้องการรายการถาวร
:::

ฮับแสดงสามส่วน:

- **แผนที่ใช้งาน** — การประสานงาน โดยเสนอไว้ก่อน พร้อมสถานะ จำนวนขั้นตอน
  และหมายเลขฉบับแก้ไข
- **เอกสารแผน** — แผนที่เอเจนต์ตัวเดียวส่งด้วย `submit_plan` ใน
  [โหมดแผน](/th-TH/คู่มือ/วิธีทำ/โหมดแผน/) ขณะที่ยังถูกเสนอหรืออนุมัติแล้ว
- **เพลย์บุ๊ก** — เทมเพลตแผนที่บันทึกไว้และรับพารามิเตอร์

คลิกการ์ดเพื่อเปิดใน Plan Studio เส้นทางคือ
`/workspaces/<workspace-id>/plans/<kind>/<plan-id>` โดย `kind` คือ
`orchestration` หรือ `document` คุณจึงดีปลิงก์แผนเดียวได้เช่นกัน

หากคุณเปิด **การประสานงาน** คุณจะได้แคนวาสที่แก้ไขได้ ไทม์ไลน์เวอร์ชัน และแถบ
อนุมัติ หากคุณเปิด **เอกสารแผน** กราฟเดียวกันจะเรนเดอร์แบบอ่านอย่างเดียว — เอกสาร
แผนเป็นผลงานของเอเจนต์ คุณรีวิว ประมาณการ และอนุมัติหรือปฏิเสธมัน และเอกสารที่
อนุมัติแล้วจะแสดงสถานะการรันจริงรายโหนดจากการประสานงานที่มันถูกแปลงเป็น

## แก้ไข DAG

แก้ไข **การประสานงาน** ได้ขณะสถานะเป็น `proposed` การแก้ไขบนแคนวาสทั้งหมด
ขับเคลื่อนด้วยแป้นพิมพ์:

1. คลิกแคนวาส แล้วเลื่อนส่วนที่เลือกด้วย**ปุ่มลูกศร**
2. กด **n** เพื่อเพิ่มขั้นตอน มันจะปรากฏเป็นเลือกอยู่ชื่อ "ขั้นตอนใหม่" ให้เปลี่ยน
   ชื่อในตัวตรวจสอบทางขวา
3. กด **e** บนขั้นตอนที่ต้องรันก่อน แล้วคลิกขั้นตอนที่พึ่งพามัน (หรือเลือกขั้นตอน
   นั้นแล้วกด **Enter**) เพื่อเชื่อมความสัมพันธ์พึ่งพา กด **Esc** เพื่อทิ้งการ
   เชื่อมที่ค้างอยู่
4. กด **x** เพื่อตัดความสัมพันธ์พึ่งพาใหม่สุดของขั้นตอนที่เลือก หรือสลับความ
   สัมพันธ์พึ่งพาแบบเจาะจงในตัวแก้ไขความสัมพันธ์พึ่งพาของตัวตรวจสอบ
5. กด **Delete** เพื่อลบขั้นตอนที่เลือก การอ้างอิงถึงมันจะถูกนำออกจากความสัมพันธ์
   พึ่งพาของขั้นตอนที่เหลือ

ในตัวตรวจสอบคุณยังแก้คำอธิบาย บทบาท และสคีมาเอาต์พุตของขั้นตอนได้ด้วย การแก้ไขจะ
บันทึกอัตโนมัติเป็นฉบับแก้ไขใหม่หลังหยุดพักสั้น ๆ ข้อผิดพลาดในการตรวจสอบความ
ถูกต้อง (แสดงในแถบอนุมัติ) จะปิดกั้นการบันทึกจนกว่าคุณจะแก้ให้เรียบร้อย

แก้ไขได้เฉพาะขั้นตอนที่เป็นงานเท่านั้น โหนดเชิงโครงสร้าง — การวิจัย การอภิปราย และ
การสังเคราะห์ — เป็นแบบอ่านอย่างเดียว เช่นเดียวกับขั้นตอนที่งานของมันรันไปแล้ว
(มันถูกทำเครื่องหมายว่า "รันแล้ว" เพราะการแก้ไขมันจะแยกแผนออกเป็นสองทาง)

การบันทึกใช้การควบคุมการทำงานพร้อมกันแบบ optimistic บนฉบับแก้ไขที่คุณเริ่มจากมัน
หากตัวประสานงานวางแผนใหม่ทับระหว่างนั้น การบันทึกของคุณจะถูกปฏิเสธด้วยข้อความ
"แผนเดินหน้าต่อไปแล้ว" แทนที่จะถูกผสานหรือทับอย่างเงียบ ๆ ให้อ่านฉบับแก้ไขปัจจุบัน
ใหม่แล้วแก้ไขของคุณอีกครั้ง การวางแผนใหม่ที่เอเจนต์เป็นผู้ริเริ่มเองก็ถูกจำกัดอัตรา
ไว้ที่หนึ่งครั้งทุกสองนาที เหตุการณ์แบบนี้จึงเกิดขึ้นไม่บ่อย

:::note
แคนวาสไม่มีการลากเพื่อจัดตำแหน่งใหม่ เลย์เอาต์คำนวณจากโครงสร้างความสัมพันธ์
พึ่งพา ดังนั้นการ "ย้าย" ขั้นตอนหมายถึงการต่อสายความสัมพันธ์พึ่งพาของมันใหม่
:::

## อ่านค่าประมาณการต้นทุน เวลา และความเสี่ยง

กด **ประมาณการ** ในแถบอนุมัติ

- แต่ละขั้นตอนบนแคนวาสจะได้ป้ายที่มีช่วงต้นทุนและขนาดตัวอย่างที่รองรับมัน หรือ
  "ยังไม่มีประวัติ" เมื่อบทบาทของขั้นตอนนั้นไม่เคยรัน เลือกขั้นตอนเพื่อดู
  รายละเอียดเต็มในตัวตรวจสอบ: ช่วงต้นทุนพร้อมขนาดตัวอย่าง ช่วงระยะเวลา และ
  รัศมีผลกระทบ (ไฟล์และสัญลักษณ์) ที่ได้มาจากแหล่งที่มาของขั้นตอน — หรือ
  "ไม่ทราบ" เมื่อขั้นตอนไม่มีแหล่งที่มา
- แถบอนุมัติแสดงยอดรวมของแผน: ช่วงต้นทุนโดยรวม ช่วงระยะเวลาของเส้นทางวิกฤต
  (สาขาที่ขนานกันทับซ้อนกัน จึงไม่ใช่ผลบวก) และเพดานงบประมาณเมื่อแผนกำหนดไว้
- หากมีเพียงบางขั้นตอนที่มีประวัติ ยอดรวมจะถูกทำเครื่องหมายว่า **บางส่วน** และ
  ครอบคลุมเฉพาะขั้นตอนที่ประมาณการได้ หากปลายบนของค่าประมาณการเกินเพดาน
  งบประมาณ ยอดรวมจะเปลี่ยนเป็นสีแดงพร้อมคำเตือนเกินงบ

ค่าประมาณการจะซื่อตรงหรือไม่มีเลย: ขั้นตอนที่บทบาทไม่มีประวัติการรันที่เสร็จจะ
รายงานขนาดตัวอย่างเป็นศูนย์โดยไม่มีช่วงใด ๆ เลย และแสดงเป็นไม่ทราบแทนที่จะเดา
ให้ถือว่า "ยังไม่มีประวัติ" หมายถึง "ไม่มีใครรู้" ไม่ใช่ "ถูก"

เพดานงบประมาณเป็นการเปรียบเทียบเพื่อการแสดงผลเทียบกับค่าประมาณการนี้ ไม่มีอะไร
บังคับใช้มันเมื่อแผนเริ่มรันแล้ว — ดู
[จัดการต้นทุน](/th-TH/คู่มือ/วิธีทำ/จัดการต้นทุน/) สำหรับกลไกควบคุมที่หยุดการใช้จ่ายได้จริง

## เทียบฉบับแก้ไขกับข้อเสนอก่อนหน้า

การแก้ไขทุกครั้งและการวางแผนใหม่ทุกครั้งของตัวประสานงานจะต่อท้ายไทม์ไลน์ฉบับ
แก้ไขแบบเพิ่มอย่างเดียว ซึ่งแสดงในแผง **เวอร์ชัน** ทางซ้ายของการประสานงาน

1. คลิกฉบับแก้ไขเพื่อเทียบกับข้อเสนอปัจจุบัน เมื่อไม่เลือกอะไร แผงจะเทียบฉบับ
   แก้ไขก่อนหน้ากับฉบับปัจจุบัน
2. อ่าน diff ในครึ่งล่างของแผง: ขั้นตอนที่เพิ่ม ลบ หรือเปลี่ยนไประหว่างสองฉบับ
   แก้ไข
3. หากแผนยังเป็น `proposed` ให้คลิกไอคอนย้อนกลับบนฉบับแก้ไขเพื่อย้อนไปยังฉบับ
   นั้น การย้อนกลับจะบันทึกข้อเสนอนั้นเป็นฉบับแก้ไข**ใหม่** — ไม่มีอะไรสูญหาย

`propose_orchestration` และตัวแก้ไขต่างก็ปฏิเสธการเปลี่ยนแปลงเมื่อแผนไม่ใช่
`proposed` อีกต่อไป การรันที่กำลังดำเนินอยู่จึงไม่รับการวางแผนใหม่กลางการทำงาน

## อนุมัติ ปฏิเสธ หรือขยายขอบเขตแผน

จากแอป แผนที่ถูกเสนอเป็นการตัดสินใจเดียวที่ทำทั้งชุด: **อนุมัติแผน** หรือ
**ปฏิเสธ** ในแถบอนุมัติ **อนุมัติแผน** จะอนุมัติทุกขั้นตอนเสมอ — ไม่มีทางเลือก
บางส่วนก่อนได้ การอนุมัติถูกปิดกั้นขณะข้อเสนอยังมีข้อผิดพลาดในการตรวจสอบความ
ถูกต้อง ซึ่งแสดงไว้ข้างปุ่ม

การอนุมัติเป็นหน้าที่ของโอเปอเรเตอร์เท่านั้น ไม่มีเครื่องมือ MCP สำหรับการนี้
เอเจนต์จึงเสนอและแก้ไขแผนได้แต่อนุมัติไม่ได้เลย

เมื่อการประสานงานกำลังดำเนินการอยู่ แถบจะเปลี่ยนไป:

- หากขั้นตอนหยุดเพื่อถามกลางการรัน ให้เลือกมันแล้วกด **ทำโหนดต่อ** เพื่อรันต่อ
- กด **อนุมัติที่เลือก** เพื่อขยายการอนุมัติแบบ _บางส่วน_ ให้ครอบคลุมขั้นตอนที่เลือก
  บวกทุกอย่างที่มันพึ่งพาแบบส่งผ่าน (ขั้นตอนจะถูกอนุมัติโดยไม่มีสิ่งที่มันพึ่งพา
  ไม่ได้) ตัวควบคุมนี้อยู่บนแถบที่กำลังดำเนินการของการประสานงานทุกอัน และเป็น
  การไม่ทำอะไรเลยเมื่อแผนถูกอนุมัติทั้งชุด
- กด **ยกเลิกรัน** เพื่อหยุดการประสานงานทั้งหมด

ขั้นตอนที่อยู่นอกชุดที่อนุมัติบางส่วนจะเรนเดอร์เป็นรอเลื่อนและจะไม่รันจนกว่าคุณจะ
ขยายชุดนั้น

:::note[การอนุมัติบางส่วนเริ่มต้นจากแอปไม่ได้]
การอนุมัติบางส่วนเกิดขึ้นเฉพาะเมื่อมีบางสิ่งเรียก `orchestration.approve` ผ่าน RPC
พร้อมรายการ `approved_node_keys` ที่ระบุชัดเจนเท่านั้น **อนุมัติแผน** ในแอปอนุมัติ
ทุกขั้นตอนเสมอ เอกสารแผนถูกอนุมัติทั้งชุดในทุกกรณี เอกสารที่กำลังดำเนินการจึงมี
ให้ใช้แค่ **ยกเลิกรัน**
:::

## รันเพลย์บุ๊กพร้อมพารามิเตอร์

เพลย์บุ๊กคือเทมเพลตแผนที่บันทึกไว้พร้อมตัวยึด `{{param}}` แบบมีชนิดในเป้าหมาย
ชื่อขั้นตอน คำอธิบาย และพรอมต์ของมัน การแทนที่เป็นแบบตรงตัว — ไม่มีภาษานิพจน์
หากคุณต้องการตรรกะ ให้ใช้
[ไปป์ไลน์](/th-TH/คู่มือ/วิธีทำ/สร้างไปป์ไลน์/)แทน

1. ในส่วน **เพลย์บุ๊ก** ของฮับ กด **รัน** บนเพลย์บุ๊ก (หรือเปิดพาเลตต์ ⌘K แล้ว
   เลือกเพลย์บุ๊กที่นั่น)
2. กรอกพารามิเตอร์ พารามิเตอร์แบบ enum เรนเดอร์เป็นดรอปดาวน์ พารามิเตอร์แบบรีโป
   และเอเจนต์รับการอ้างอิงรีโปหรือเอเจนต์ พารามิเตอร์แบบเลือกได้จะถอยกลับไปใช้
   ค่าเริ่มต้นของมัน
3. เลือก **ตั๋วงานหลัก** ที่แผนจะถูกเสนอต่อ แล้วยืนยัน

การรันเพลย์บุ๊กเพียง**เสนอ**แผนเท่านั้น — การประสานงานที่ถูกสร้างอินสแตนซ์เปิดใน
Plan Studio เป็น `proposed` และไม่มีอะไรทำงานจนกว่าคุณจะอนุมัติที่นั่น หากต้องการ
ลบเพลย์บุ๊ก ให้กดไอคอนถังขยะบนการ์ดของมัน

เอเจนต์สร้างและรันเพลย์บุ๊กด้วยเครื่องมือ MCP `create_playbook` และ `run_playbook`
ดู[เอกสารอ้างอิงเครื่องมือ MCP](/th-TH/คู่มือ/อ้างอิง/เครื่องมือ-mcp/)
