Control Center Connect ดำเนินการลงชื่อเข้าใช้ผู้ให้บริการ (GitHub, Google Calendar, Linear, Slack) ให้กับเซิร์ฟเวอร์ที่ยังไม่ได้ลงทะเบียนแอปของตัวเอง คู่มือนี้แสดงวิธีรัน Connect ของคุณเอง เพื่อให้แอปของผู้ให้บริการ คีย์ลับ และรายชื่อเซิร์ฟเวอร์ที่ได้รับอนุญาตให้ใช้ทั้งหมดอยู่กับคุณ

Connect มองเห็นอะไรและมองไม่เห็นอะไร ดูได้ที่ [อ้างอิง Connect](/th-TH/คู่มือ/อ้างอิง/connect/) อ่านก่อนหากคุณกำลังตัดสินใจว่าจะรันหรือไม่

:::note[คุณอาจไม่จำเป็นต้องใช้]
เซิร์ฟเวอร์เดียวสามารถลงทะเบียนแอปของตัวเองแทนได้: ใน **การตั้งค่า → เซิร์ฟเวอร์ → ลงชื่อเข้าใช้ครั้งเดียว → แอปผู้ให้บริการ** **สร้างแอป GitHub ของฉัน** จะตั้งค่า GitHub ได้ในขั้นตอนเดียว แอปของเซิร์ฟเวอร์เองใช้ได้เฉพาะภายใต้ **ใช้แอปของฉันเอง** เท่านั้น: เมื่อใช้ Control Center Connect หรือ Connect แบบกำหนดเอง Connect จะให้บริการทุกช่องทาง ส่วนแอปของเวิร์กสเปซยังคงใช้ได้ในทุกโหมด รัน Connect เมื่อเซิร์ฟเวอร์หลายตัวควรใช้ชุดแอปเดียวกัน
:::

## ข้อกำหนดเบื้องต้น

- ที่อยู่ **HTTPS** สาธารณะสำหรับ Connect เช่น `https://connect.example.com` อยู่หลังพร็อกซีที่ยุติ TLS เท่านั้น `http` ธรรมดาใช้ได้เฉพาะบน loopback
- Docker หรือ `cc_server` ที่คุณสามารถรีสตาร์ตพร้อมตัวแปรสภาพแวดล้อมเพิ่มเติมได้
- สิทธิ์ในการลงทะเบียนแอปกับผู้ให้บริการทุกรายที่คุณต้องการให้บริการ
- เซิร์ฟเวอร์ที่จะใช้งาน และเจ้าของเซิร์ฟเวอร์ที่คุณติดต่อได้ตลอดเวลา: เซิร์ฟเวอร์แต่ละตัวมี id การติดตั้งที่ต้องถูกเพิ่มในรายการอนุญาตของ Connect

## ขั้นตอนที่ 1: เลือกที่อยู่

เลือกและเก็บที่อยู่ไว้ตั้งแต่ตอนนี้ `CONNECT_PUBLIC_URL` เป็นส่วนหนึ่งของทุกอย่างที่ Connect ทำ: ลายเซ็นคำขอ ข้อมูลรับรองที่ถูกปิดผนึก URL การเปลี่ยนเส้นทางของผู้ให้บริการ และ id การติดตั้งของแต่ละเซิร์ฟเวอร์ ล้วนผูกกับมัน การเปลี่ยนแปลงภายหลังหมายถึงต้องลงทะเบียนการเปลี่ยนเส้นทางใหม่ และทุกคนต้องลงชื่อเข้าใช้อีกครั้ง

## ขั้นตอนที่ 2: ลงทะเบียนแอปของผู้ให้บริการ

ลงทะเบียนเฉพาะผู้ให้บริการที่คุณต้องการให้บริการ ผู้ให้บริการที่ตัวแปรไม่ครบจะถูกตัดออกจากการตั้งค่าของ Connect และเซิร์ฟเวอร์จะเห็นว่ามันใช้ไม่ได้ ในตารางด้านล่าง `<base>` คือ `CONNECT_PUBLIC_URL` ของคุณ

| ผู้ให้บริการ   | ลงทะเบียน                                                                                                                                                                                                                                                              | เก็บไว้                                  |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| **GitHub App** | Callback URL `<base>/oauth/github/callback` Setup URL `<base>/oauth/github/setup` และเปิด **Redirect on update** ปล่อย **Request user authorization (OAuth) during installation** ให้ปิดไว้: เมื่อเปิด GitHub จะไม่สนใจ Setup URL เปิด **Expire user authorization tokens** ไว้ | App id, slug, client id, client secret |
| **Google**     | OAuth client ชนิด **Web application** โดยมี redirect URI คือ `<base>/oauth/google/callback` และเปิดใช้ Google Calendar API                                                                                                                                              | client id, client secret                 |
| **Linear**     | แอป OAuth ที่มี callback URL คือ `<base>/oauth/linear/callback` และ `<base>/oauth/linear_app/callback`                                                                                                                                                                  | เฉพาะ client id                         |
| **Slack**      | Redirect URL `<base>/oauth/slack_oidc/callback` และ `<base>/oauth/slack/callback` Event Subscriptions อยู่ที่ `<base>/v1/hooks/slack/events` (`app_mention`, `message.*`, `assistant_thread_*`, `app_uninstalled`, `tokens_revoked`) Slash command อยู่ที่ `<base>/v1/hooks/slack/commands` เปิด token rotation | App id, client id, client secret, signing secret |

ให้สิทธิ์ที่เก็บของ GitHub App ดังนี้: **Metadata** อ่าน, **Contents** อ่านและเขียน, **Pull requests** อ่านและเขียน, **Issues** อ่านและเขียน และ **Checks**, **Actions** กับ **Commit statuses** อ่าน เพื่อให้คำขอรีวิวของทีมทำงานได้ ให้เพิ่ม **Members** อ่านของ organization Webhook ปิดไว้ได้: เซิร์ฟเวอร์จะทำการโพลล์

Connect ไม่เคยต้องการ private key ของ GitHub App แต่จะออกโทเค็นที่ใช้ได้กับรีโปเดียวผ่านการลงชื่อเข้าใช้ของบุคคลหนึ่ง Linear ก็ไม่ต้องใช้คีย์ลับเช่นกัน: Connect ส่งโค้ดกลับให้เซิร์ฟเวอร์ ซึ่งแลกเปลี่ยนโค้ดนั้นด้วยตัวเอง

## ขั้นตอนที่ 3: รวบรวม id การติดตั้ง

Connect จะตอบเฉพาะเซิร์ฟเวอร์ที่อยู่ในรายการอนุญาต บนเซิร์ฟเวอร์แต่ละตัว ให้ชี้ไปยัง Connect ของคุณ แล้วอ่าน id การติดตั้งของมัน:

1. ไปที่ **การตั้งค่า → เซิร์ฟเวอร์ → ลงชื่อเข้าใช้ครั้งเดียว** เปิดการ์ด **Control Center Connect** และเลือก **ใช้เซิร์ฟเวอร์ Connect ที่กำหนดเอง**
2. ป้อนที่อยู่ของคุณแล้วบันทึก การ์ดจะแสดง **id การติดตั้ง** ของเซิร์ฟเวอร์

ในเทอร์มินัลของโฮสต์เซิร์ฟเวอร์ ขั้นตอนเดียวกันเป็นดังนี้:

```bash
cc_server connect enable --url https://connect.example.com
cc_server connect status
```

`status` จะพิมพ์ id การติดตั้ง จนกว่าจะถึงขั้นตอนที่ 5 จะแสดง `install_blocked` ซึ่งเป็นสิ่งที่คาดไว้

id การติดตั้งได้มาจากที่อยู่ของ Connect ดังนั้นเซิร์ฟเวอร์เดียวกันจะมี id ต่างกันสำหรับ Connect แต่ละตัว และจะเปลี่ยนก็ต่อเมื่อเจ้าของของมันหมุนเวียนคีย์

## ขั้นตอนที่ 4: สร้างคีย์การปิดผนึก

Connect จะเข้ารหัสข้อมูลรับรองทุกชิ้นที่ส่งกลับด้วยคีย์การปิดผนึก สร้างหนึ่งคีย์และเก็บไว้เป็นไฟล์ลับ:

```bash
docker run --rm ghcr.io/samuelalev/cc-connect:latest \
  cc-connect-config seal-key > seal_keys
chmod 600 seal_keys
```

การทำคีย์การปิดผนึกหายจะทำให้ทุกคนต้องออกจากระบบ: หากไม่มีคีย์นี้ จะเปิดการปิดผนึกใด ๆ ไม่ได้

## ขั้นตอนที่ 5: เริ่มคอนเทนเนอร์

ทุกการเผยแพร่จะเผยแพร่ `ghcr.io/samuelalev/cc-connect` พร้อมหลักฐานต้นทางของการสร้าง ในระบบโปรดักชันให้ปักแท็กเวอร์ชันไว้

```bash
docker run -d --name cc-connect -p 8790:8790 \
  -e CONNECT_PUBLIC_URL=https://connect.example.com \
  -e CONNECT_ALLOWED_INSTALLS=<install id>,<install id> \
  -e CONNECT_SEAL_KEYS_FILE=/run/secrets/seal_keys \
  -v "$PWD/seal_keys:/run/secrets/seal_keys:ro" \
  -e CONNECT_GITHUB_APP_ID=123456 \
  -e CONNECT_GITHUB_APP_SLUG=acme-control-center \
  -e CONNECT_GITHUB_CLIENT_ID=Iv23li0123456789abcd \
  -e CONNECT_GITHUB_CLIENT_SECRET_FILE=/run/secrets/github \
  -v "$PWD/github_secret:/run/secrets/github:ro" \
  -v cc-connect-data:/data \
  ghcr.io/samuelalev/cc-connect:latest
```

ชี้พร็อกซีย้อนกลับของคุณไปที่พอร์ต `8790` อิมเมจรันด้วยผู้ใช้ที่ไม่มีสิทธิ์พิเศษ เก็บสถานะไว้ใน volume `/data` และมีการตรวจสุขภาพในตัว (`cc-connect --healthcheck` ซึ่งทดสอบ `/healthz`)

เมื่อการตั้งค่าเปิดกว้าง ไม่ปลอดภัย หรือตั้งค่าไว้เพียงครึ่งเดียว Connect จะปฏิเสธการเริ่มทำงาน (รหัสออก `78`) และพิมพ์ว่าตัวแปรใดผิด รายการอนุญาตที่หายไป ที่อยู่ `http` ที่ไม่ได้อยู่บน loopback คีย์การปิดผนึกที่รูปแบบผิด หรือการตั้งค่า `NAME` และ `NAME_FILE` พร้อมกัน จะทำให้มันหยุด

จุดตรวจสอบ: บนเซิร์ฟเวอร์แต่ละตัว การ์ด Connect แสดง **ปกติ** และ **การลงชื่อเข้าใช้แต่ละประเภทเกิดขึ้นที่ไหน** จะติดป้าย **Connect** ให้ผู้ให้บริการแต่ละรายที่คุณลงทะเบียนไว้ `cc_server connect status` จะพิมพ์ `Health: ok` และช่องทางเดียวกัน

## การโฮสต์ Connect ภายใน cc_server

เซิร์ฟเวอร์สามารถโฮสต์ Connect เองได้โดยไม่ต้องใช้คอนเทนเนอร์แยก บริการที่ mount ไว้เป็นตัวเดียวกับที่อิมเมจรัน

1. ใส่ตัวแปร `CONNECT_*` ไว้ในไฟล์ `.env` ของเซิร์ฟเวอร์ (หรือสภาพแวดล้อมของมัน) ตามขั้นตอนที่ 5
2. เพิ่ม `CC_SERVER_CONNECT_HOST=on`
3. รีสตาร์ตเซิร์ฟเวอร์ บันทึกของมันจะพิมพ์ `embedded Connect at <url>`

```bash
CC_SERVER_CONNECT_HOST=on
CONNECT_ALLOWED_INSTALLS=<install id>
CONNECT_SEAL_KEYS=<output of cc-connect-config seal-key>
CONNECT_GITHUB_APP_ID=123456
CONNECT_GITHUB_APP_SLUG=acme-control-center
CONNECT_GITHUB_CLIENT_ID=Iv23li0123456789abcd
CONNECT_GITHUB_CLIENT_SECRET=<secret>
```

จากนั้น Connect จะให้บริการที่ `<server>/connect`:

- `CONNECT_PUBLIC_URL` มีค่าเริ่มต้นเป็นต้นทางของ URL สาธารณะของเซิร์ฟเวอร์บวก `/connect` เมื่ออยู่หลังพร็อกซี ให้ตั้งค่านี้อย่างชัดเจน เส้นทางต้องเป็น `/connect` เท่านั้น และต้องใช้ HTTPS เว้นแต่จะเป็น loopback
- มีเพียงตัวแปร `CONNECT_*` เท่านั้นที่ส่งไปยังบริการที่ mount ไว้ ดังนั้นมันจะไม่ยืมแอปผู้ให้บริการของเซิร์ฟเวอร์เอง
- `CONNECT_ALLOWED_INSTALLS` ยังจำเป็นอยู่ รวมถึงสำหรับเซิร์ฟเวอร์ที่โฮสต์มันเองด้วย
- การ mount ที่ตั้งค่าผิดจะทำให้เซิร์ฟเวอร์เริ่มทำงานไม่ได้ แทนที่จะให้บริการตัวกลางแบบเปิด
- เซิร์ฟเวอร์ demo จะไม่ mount มันเด็ดขาด

ลงทะเบียนการเปลี่ยนเส้นทางของผู้ให้บริการด้วย `https://<server>/connect` แล้วชี้เซิร์ฟเวอร์แต่ละตัว (รวมถึงตัวที่โฮสต์มันด้วย) ไปยังที่อยู่นั้นตามที่อธิบายในขั้นตอนที่ 3

## อ้างอิงการตั้งค่า

การตั้งค่าแต่ละรายการคือตัวแปรสภาพแวดล้อมหนึ่งตัว ข้อมูลลับใดก็ได้สามารถอ่านจากไฟล์ที่ mount ไว้ได้: ใช้ `NAME_FILE` แทน `NAME` Connect จะอ่านไฟล์นั้นใหม่ไม่เกินทุก 30 วินาที และคงค่าที่ใช้ได้ล่าสุดไว้ ข้อมูลลับที่ระบุว่า **สองค่า** จะยอมรับ `NAME_PREVIOUS` (หรือ `NAME_PREVIOUS_FILE`) ด้วยระหว่างการหมุนเวียน

### ที่อยู่และการเข้าถึง

| ตัวแปร                          | ค่าเริ่มต้น       | ความหมาย                                                                                                                         |
| ------------------------------- | ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `CONNECT_PUBLIC_URL`            | จำเป็น            | URL สาธารณะรูปแบบมาตรฐาน HTTPS หรือ `http` ที่ loopback เท่านั้น มี path หมายถึงการ mount ห้ามมี query string หรือ fragment        |
| `CONNECT_ALLOWED_INSTALLS`      | จำเป็น            | id การติดตั้งคั่นด้วยจุลภาค จะรับ `*` ได้เฉพาะเมื่อใช้คู่กับ `CONNECT_SIGNED_CONFIG_FILE`                                          |
| `CONNECT_DENY_INSTALLS`         |                   | id การติดตั้งที่จะถูกปฏิเสธแม้ได้รับอนุญาตแล้ว                                                                                  |
| `CONNECT_GITHUB_ALLOWED_OWNERS` |                   | id เจ้าของ GitHub แบบตัวเลข เมื่อตั้งค่าแล้วจะออกโทเค็นรีโปเฉพาะรีโปที่เจ้าของเหล่านี้เป็นเจ้าของ                              |
| `CONNECT_HOST`, `CONNECT_PORT`  | `0.0.0.0`, `8790` | ที่อยู่และพอร์ตสำหรับผูก                                                                                                       |
| `CONNECT_TRUST_PROXY`           | `0`               | จำนวนฮ็อปของพร็อกซีที่เชื่อถือได้ใน `X-Forwarded-For` (0 ถึง 8) ใช้เฉพาะกับการจำกัดอัตราตามที่อยู่                                 |

### ช่องทางผู้ให้บริการ

| ตัวแปร                                                                      | ค่าเริ่มต้น | ความหมาย                                                                   |
| --------------------------------------------------------------------------- | ----------- | -------------------------------------------------------------------------- |
| `CONNECT_GITHUB_APP_ID`, `CONNECT_GITHUB_APP_SLUG`, `CONNECT_GITHUB_CLIENT_ID` |             | GitHub App                                                                 |
| `CONNECT_GITHUB_CLIENT_SECRET`                                              |             | ข้อมูลลับ สองค่า                                                            |
| `CONNECT_GOOGLE_CLIENT_ID`, `CONNECT_GOOGLE_CLIENT_SECRET`                  |             | ไคลเอนต์ Google ข้อมูลลับเป็นสองค่า                                          |
| `CONNECT_LINEAR_CLIENT_ID`                                                  |             | แอป Linear ไม่มีข้อมูลลับ                                                    |
| `CONNECT_SLACK_APP_ID`, `CONNECT_SLACK_CLIENT_ID`                           |             | แอป Slack                                                                  |
| `CONNECT_SLACK_CLIENT_SECRET`, `CONNECT_SLACK_SIGNING_SECRET`               |             | ข้อมูลลับ สองค่า                                                            |
| `CONNECT_KLIPY_APP_KEY`                                                     |             | คีย์การค้นหา GIF ของ Klipy ข้อมูลลับ สองค่า                                  |
| `CONNECT_KLIPY_MODE`                                                        | `proxy`     | `proxy` เก็บคีย์ไว้ใน Connect; `key` ส่งคีย์ให้เซิร์ฟเวอร์                    |
| `CONNECT_<LANE>_SECRET_GENERATION`                                          | `1`         | GitHub, Google และ Slack: รุ่นที่บันทึกในการปิดผนึกใหม่                        |

## การรันหลายอินสแตนซ์

สำหรับองค์กรส่วนใหญ่ อินสแตนซ์เดียวที่ใช้ `CONNECT_STATE=memory` ก็เพียงพอ หลายอินสแตนซ์ที่อยู่หลังที่อยู่เดียวกันต้องใช้ `CONNECT_STATE=redis` และ `CONNECT_DATA_DIR` ที่ใช้ร่วมกัน หรือ `CONNECT_BINDINGS=firestore` เพื่อให้การลงชื่อเข้าใช้ที่เริ่มบนอินสแตนซ์หนึ่งเสร็จสิ้นบนอีกอินสแตนซ์ได้

## การหมุนเวียนคีย์ของผู้ให้บริการ

จะไม่มีใครถูกออกจากระบบ:

1. สร้างคีย์ใหม่ที่ผู้ให้บริการ และเก็บคีย์เก่าไว้
2. ย้ายค่าเก่าไปยัง `NAME_PREVIOUS` วางค่าใหม่ใน `NAME` และเพิ่ม `CONNECT_<LANE>_SECRET_GENERATION` ไฟล์ที่ mount ไว้จะถูกอ่านภายใน 30 วินาที
3. รอให้การลงชื่อเข้าใช้แต่ละรายการรีเฟรช จากนั้นลบคีย์เก่าที่ผู้ให้บริการ และนำ `NAME_PREVIOUS` ออก

ในการหมุนเวียนคีย์การปิดผนึก ให้วางรายการ `cc-connect-config seal-key` ใหม่ไว้หน้าสุดของ `CONNECT_SEAL_KEYS` และเก็บรายการเก่าไว้จนกว่าการปิดผนึกทั้งหมดจะรีเฟรชแล้ว

## การเปลี่ยนแอป

เซิร์ฟเวอร์จะจดจำ id แอปและ client id ที่ Connect ของคุณประกาศในการใช้งานครั้งแรก หากคุณเปลี่ยนแอปใด การ์ด Connect ของแต่ละเซิร์ฟเวอร์จะแสดง **แอปของ Connect เปลี่ยนแปลงแล้ว** และการลงชื่อเข้าใช้ผ่าน Connect จะถูกระงับจนกว่าเจ้าของจะคลิก **เชื่อถือแอปใหม่** แจ้งเจ้าของเซิร์ฟเวอร์ทุกคนก่อนสลับ เพื่อให้พวกเขารู้ว่าคำเตือนนี้มาจากคุณ

## การบล็อกเซิร์ฟเวอร์

เพิ่ม id การติดตั้งของมันลงใน `CONNECT_DENY_INSTALLS` แล้วรีสตาร์ต เจ้าของจะเห็นข้อความ “Connect ได้บล็อก id การติดตั้งของเซิร์ฟเวอร์นี้แล้ว” และการลงชื่อเข้าใช้ทั้งหมดผ่าน Connect บนเซิร์ฟเวอร์นั้นจะหยุดทำงาน

## การแก้ปัญหา

### เซิร์ฟเวอร์แจ้งว่า Connect บล็อกมัน

id การติดตั้งของมันไม่อยู่ใน `CONNECT_ALLOWED_INSTALLS` หรืออยู่ใน `CONNECT_DENY_INSTALLS` id นี้จะเปลี่ยนเมื่อเจ้าของหมุนเวียนคีย์ ให้ขอ id ใหม่จากพวกเขา

### ผู้ให้บริการรายหนึ่งแสดงว่าใช้ไม่ได้

ตัวแปรบางตัวของมันหายไป Connect จึงตัดช่องทางนั้นออก ให้ตรวจสอบบันทึกการเริ่มทำงานและตารางด้านบน GitHub ต้องการ App id, slug, client id และ client secret ทั้งสี่รายการ ส่วน Google ต้องการทั้ง client id และ secret

### การลงชื่อเข้าใช้ล้มเหลวเนื่องจาก redirect ไม่ตรงกัน

redirect ที่ลงทะเบียนกับผู้ให้บริการไม่ตรงกับ `CONNECT_PUBLIC_URL` ทุกตัวอักษร ให้ตรวจสอบโปรโตคอล โฮสต์ พอร์ต และเส้นทาง `/connect` ของ Connect ที่ mount ไว้

### ทุกคนต้องลงชื่อเข้าใช้อีกครั้ง

คีย์การปิดผนึกเปลี่ยนแปลงหรือหาย เซิร์ฟเวอร์เครื่องหนึ่งหมุนเวียนคีย์ของมัน หรือข้อมูลของเซิร์ฟเวอร์เครื่องหนึ่งถูกกู้คืนไปยังอีกเครื่องหนึ่ง ข้อมูลรับรองที่ปิดผนึกจะเปิดได้เฉพาะสำหรับการติดตั้งและ Connect ที่สร้างมันเท่านั้น
