Ce guide explique comment revenir à un point antérieur d’une conversation pour l’emmener ailleurs — tout en conservant le chemin que vous avez quitté.

## La seule chose à savoir

**Créer une branche n’écrit rien.** Une conversation est un arbre de messages doté d’un pointeur à son extrémité, et revenir en arrière déplace ce pointeur. Rien n’est supprimé, rien n’est masqué, et revenir à la branche précédente n’est qu’un autre déplacement du pointeur.

C’est pourquoi modifier un prompt et le relancer est sans risque ici : la réponse à laquelle vous vous compariez est toujours là.

## Voir les branches

```
/tree
```

Le navigateur liste tous les messages, indentés à chaque embranchement, le chemin actuel étant signalé par **Sur cette branche**. Une conversation qui n’a jamais été dupliquée s’affiche comme la liste plate qu’elle a toujours été — consulter le navigateur ne coûte rien tant qu’il n’y a rien à parcourir.

Chaque ligne propose deux actions.

| Action                                       | Effet                                                             |
| -------------------------------------------- | ----------------------------------------------------------------- |
| **Continuer d’ici**                          | Déplace le pointeur. Votre prochain message repart de ce message. |
| **Dupliquer dans une nouvelle conversation** | Copie le chemin jusqu’à ce message dans une nouvelle conversation. |

## Créer une branche : essayer une autre approche

1. `/tree`
2. Repérez le message à partir duquel vous voulez repartir — en général le dernier qui vous convenait.
3. **Continuer d’ici.**
4. Saisissez le nouveau prompt.

L’ancienne suite est toujours dans l’arbre ; `/tree` affiche désormais deux chemins depuis ce point, et vous pouvez passer librement de l’un à l’autre.

:::note[Le chemin que vous avez quitté est toujours là]
Créer une branche ne masque ni ne supprime rien. `/tree` liste tous les chemins, marque le chemin actuel **Sur cette branche**, et c’est ainsi que vous changez de chemin.
:::

## Dupliquer : l’emmener ailleurs

La duplication copie le chemin dans une **nouvelle conversation** du même espace. Utilisez-la lorsque les deux directions vont continuer à diverger et que vous préférez les garder côte à côte plutôt que de passer de l’une à l’autre.

Une copie reçoit de **nouveaux identifiants de message**. Deux conversations qui partageraient des lignes se montreraient mutuellement leurs messages ultérieurs, exactement ce qu’une duplication est censée empêcher.

## Retour en arrière ou création d’une branche

Ce sont deux outils différents, et la différence compte.

|                         | Retour en arrière                     | Branche                        |
| ----------------------- | ------------------------------------- | ------------------------------ |
| Les messages ultérieurs | Masqués dans la transcription         | Toujours visibles dans `/tree` |
| L’**arbre de travail**  | Ramené à l’instantané de ce tour      | Intact                         |
| Annulation              | **Annuler le retour** restaure le lot | Ramener le pointeur en arrière |

Le retour en arrière est ce qu’il vous faut lorsque l’agent a modifié des *fichiers* que vous voulez récupérer. La création d’une branche est ce qu’il vous faut lorsque la conversation a mal tourné mais que les fichiers sont intacts.

Le retour en arrière déplace lui aussi la pointe de branche : votre prochain message repart donc du bon endroit plutôt que d’une fin que plus personne ne voit.

## Sortir la conversation de l’application

### `/export`

Écrit un **fichier HTML autonome** : toute la conversation, avec des cartes d’outils repliables indiquant ce qui a été fourni à chaque appel et ce qu’il a renvoyé. Aucune feuille de style, aucun script, aucun hébergeur d’images — le fichier fonctionne depuis une clé USB et fonctionnera encore dans cinq ans.

- **Application de bureau :** `Documents/ControlCenter/exports/`, horodaté pour qu’un second export n’écrase pas le premier.
- **Navigateur web :** un téléchargement par le navigateur.

### `/dump`

Copie la transcription dans le presse-papiers au format markdown, avec les appels d’outils dans des blocs repliables. C’est celui-ci qu’il faut coller dans une issue.

Le raisonnement est volontairement omis : c’est le brouillon du modèle, et un rapport de bug est lu par un humain.
