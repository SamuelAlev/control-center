Ce guide vous explique comment configurer les notifications et ce que chaque
réglage contrôle réellement.

Les notifications arrivent sur deux surfaces. Le **centre de notifications** — la
cloche de la barre de titre — lit un fil durable par espace de travail sur le
serveur. Les **toasts du système d’exploitation** constituent une voie distincte,
réservée au bureau, alimentée par les trames en direct que pousse le serveur.

:::note[La version web n’affiche aucune notification du système d’exploitation]
La chaîne de traitement des toasts n’est construite que par l’amorçage du bureau.
Sur `app.usectrl.dev`, il n’y a ni toasts du système d’exploitation, ni sons de
notification, ni bannières d’ambiance — la cloche et son historique fonctionnent
toujours, parce qu’ils lisent le fil du serveur. Le client mobile n’a aucune
surface de notification.
:::

## Activer ou désactiver des catégories

1. Allez dans **Paramètres → Vous → Notifications**
2. Laissez **Activer les notifications** activé
3. Activez ou désactivez les catégories que vous voulez. Il y en a exactement dix-sept :

| Catégorie                  | Se déclenche quand                                                         |
| ------------------------- | -------------------------------------------------------------------------- |
| Agent terminé            | Un agent a répondu dans une exécution que vous avez lancée, ou l’exécution a échoué |
| Un agent vous attend | Un agent a besoin de votre approbation, vous a posé une question ou est bloqué sur des identifiants |
| PR publiée              | Un agent a publié une PR                                                            |
| PR fusionnée            | Une PR a été fusionnée                                                            |
| Nouveaux messages              | Quelqu’un vous a mentionné dans un espace                                            |
| Mentionné dans une pull request | Le sondage de notifications de GitHub a vu que vous étiez mentionné sur une PR                       |
| Revue demandée          | Votre revue a réellement été demandée sur une PR qui n’est pas un brouillon                       |
| Revue obsolète        | De nouveaux commits sont arrivés sur une pull request que vous aviez déjà relue                       |
| Prêt à fusionner           | Une pull request dont vous êtes l’auteur est devenue fusionnable, ou a cessé de l’être                     |
| Décisions de revue          | Un relecteur a approuvé, demandé des modifications, ou a vu une approbation rejetée       |
| Vérifications                    | La CI a échoué sur une pull request dont vous êtes l’auteur, ou s’est rétablie                     |
| Fils de revue          | Quelqu’un a répondu dans un fil où vous êtes, ou l’a résolu                         |
| Ticket assigné           | Un ticket a été assigné                                                      |
| Statut du ticket modifié     | Un ticket a changé de statut                                                    |
| Réunion imminente     | Une réunion du calendrier entre dans votre fenêtre d’anticipation                              |
| Calendrier déconnecté     | Le jeton OAuth d’un calendrier connecté a expiré                                 |
| Mises à jour des enclos         | Un enclos a été repris, récupéré ou a échoué                           |

Tout ce qui ne figure pas dans cette liste ne peut être ni notifié ni filtré —
il n’existe pas de catégorie « tout le reste ».

**Un agent vous attend** se déclenche une fois par attente, au moment où elle
commence : une approbation en suspens (y compris les autorisations d’exécution du
bac à sable et les approbations d’outils de Claude Code), une question
`ask_user`, ou une exécution retenue parce que ses identifiants ne peuvent pas
la servir. La notification ouvre l’espace où vous répondez, et reste muette tant
que vous regardez déjà cet espace.

Ces préférences suivent votre utilisateur d’un appareil à l’autre, si bien qu’un
téléphone et un ordinateur portable restent synchronisés. Le volume est
l’exception délibérée et reste propre à chaque appareil.

## Définir les heures de silence

1. Sur la même page, activez **Quiet hours**
2. Saisissez une heure de début et une heure de fin au format `HH:MM` (la plage
   par défaut est 22:00–08:00)

Pendant les heures de silence, les notifications non urgentes sont écartées — ni
mises en file, ni rejouées plus tard.

Deux catégories sont **urgentes** et sont toujours délivrées, en contournant les
heures de silence _et_ le mode focus : **Réunion imminente** et **PR
publiée**. Une alerte de réunion que vous ne voyez qu’après coup ne vaut rien, et
c’est précisément la raison.

## Choisir un son

1. Faites défiler jusqu’à **Son de notification**
2. Choisissez l’un des onze sons inclus, ou **Aucun**
3. Appuyez sur le bouton de test pour l’écouter et réglez le volume avec le
   curseur

L’application joue le son elle-même ; la notification du système
d’exploitation est délivrée silencieusement, si bien que vous ne l’entendez jamais
deux fois.

## Définir le délai d’anticipation des réunions

1. Faites défiler jusqu’à **Délai d’alerte**
2. Choisissez **5**, **10**, **15** ou **30** minutes

C’est le délai avant un événement du calendrier auquel la notification **Réunion
imminente** se déclenche. La valeur par défaut est 5 minutes.

## Savoir quand une notification est supprimée

Une notification est écartée, en silence, lorsque l’une des conditions suivantes
est vraie :

- Les notifications sont désactivées globalement, ou sa catégorie l’est
- Vous êtes déjà sur la route vers laquelle elle vous mènerait — et, pour un
  message, déjà dans cet espace
- Le mode focus est actif et la catégorie n’est pas urgente
- Les heures de silence sont actives et la catégorie n’est pas urgente

Ces vérifications s’appliquent aux toasts du système d’exploitation. La cloche
durable enregistre quand même l’événement.

Deux autres suppressions interviennent plus en amont, dans ce que le serveur
envoie réellement :

- Un message d’un autre **humain** où vous n’êtes pas mentionné ne devient jamais
  une notification
- Dans un espace partagé, la réponse d’un agent notifie la personne qui a lancé
  cette exécution, pas tous les membres
- Les espaces entre agents sont en sourdine dans la barre latérale, si bien
  qu’ils n’incrémentent jamais la pastille de non-lus des humains

À l’intérieur d’un espace, il n’y a aucun coin tranquille : chaque
conversation notifie de la même façon, fils compris. L’état de lecture est propre
à l’espace, si bien que les non-lus s’agrègent entre les conversations d’un
espace au lieu d’être suivis conversation par conversation.

## Lire et vider le centre de notifications

1. Cliquez sur la cloche de la barre de titre

La fenêtre contextuelle montre l’activité récente et relie chaque entrée par un
lien direct à ce dont elle parle. L’ouvrir ne marque **pas** tout comme lu —
utilisez **Tout marquer comme lu** dans l’en-tête, ou marquez une seule ligne.
L’état de lecture suit votre utilisateur d’un appareil à l’autre.

:::note[Tout effacer est un filigrane, pas une suppression]
**Tout effacer** appose un filigrane propre à chaque utilisateur qui masque tout
ce qui est plus ancien ; les lignes restent. Par ailleurs, chaque espace de
travail ne conserve que ses **200** lignes de fil les plus récentes, élaguées à
mesure que de nouvelles arrivent, tandis que la cloche s’abonne aux **50** plus
récentes et que la fenêtre contextuelle en liste jusqu’à **15**. L’historique
au-delà a disparu, quel que soit l’état de lecture.
:::

## Dépannage

### Aucune notification du système d’exploitation sous macOS

L’autorisation est demandée nativement au lancement de l’application. Si vous
l’avez refusée, réactivez Control Center dans Réglages Système → Notifications ;
aucune invite dans l’application ne permet de la redemander.

### Rien n’arrive dans la version web

C’est normal — la version web n’a aucune chaîne de traitement des notifications
du système d’exploitation. Utilisez la cloche.

### La pastille de la cloche indique zéro alors qu’il y a clairement de l’activité nouvelle

Tant que le flux de marques de lecture n’est pas résolu après la connexion, les
entrées s’affichent comme lues pour éviter une pastille qui clignote puis se vide.
Tout se stabilise dès que la marque est chargée.

### L’exécution d’un agent s’est terminée sans que rien ne m’ait averti

Vérifiez que vous n’étiez pas déjà dans l’espace où elle a eu lieu — une route
active supprime son propre toast du système d’exploitation. Dans un espace
partagé, une exécution lancée par quelqu’un d’autre notifie cette personne, pas
vous. Un tour terminé sans réponse ni erreur n’envoie rien.
