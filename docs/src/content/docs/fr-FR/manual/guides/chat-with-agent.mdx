Ce guide vous montre comment travailler avec un agent dans un espace.

## Créer un espace

1. Accédez à **Espaces** dans la barre latérale
2. Cliquez sur le bouton **+** à côté du titre Espaces
3. Saisissez un **nom** — il est obligatoire. Un nom vide est refusé ;
   la boîte de dialogue reste ouverte
4. Ajoutez éventuellement des agents depuis l’espace de travail
5. Si l’espace de travail contient le moindre dépôt, un sélecteur de dépôts apparaît. Il démarre avec tous les dépôts sélectionnés ; restreignez la sélection (y compris en désélectionnant un seul dépôt) aux dépôts pour lesquels cet espace doit provisionner des arbres de travail
6. Confirmez

Control Center ouvre l’espace et commence à provisionner en arrière-plan un arbre de travail en copie sur écriture par dépôt sélectionné.

## Envoyer le premier message

Saisissez votre message dans le compositeur et appuyez sur Entrée. L’agent est lancé et commence à diffuser sa réponse.

Si l’espace est encore en cours de provisionnement, votre message est mis en attente plutôt que perdu — le compositeur le conserve et l’envoie automatiquement dès que les arbres de travail sont prêts.

Pendant que l’agent travaille, vous voyez son tour se diffuser en direct : segments de raisonnement, appels d’outils (lectures et écritures de fichiers, commandes shell) et texte de réponse, le tout dans un seul message de tour d’agent.

## Orienter un agent en cours d’exécution

Pendant qu’un agent travaille, du texte de conversation ordinaire **ne met pas** en file un nouveau tour. Il devient une carte de pilotage mise en file dans la bande au-dessus du compositeur et est injecté dans l’exécution en direct à la frontière de tour suivante. Aucune notification éphémère n’apparaît — la carte fait office de retour d’information.

Trois choses modifient ce comportement :

- Un message contenant une **@mention** est toujours envoyé comme message, jamais comme pilotage
- Un message commençant par une **commande slash** est toujours traité comme cette commande
- Un message accompagné d’une **pièce jointe** est toujours envoyé comme message — la file de pilotage est réservée au texte
- Si toutes les exécutions en direct sont déjà terminées, le texte passe à travers et est envoyé comme un message normal

:::note[Le pilotage nécessite le harnais intégré]
Seul le harnais intégré de Control Center injecte en cours d’exécution. Sur l’adaptateur Claude Code, le texte est tout de même mis en file sous forme de carte de pilotage ; à la fin de l’exécution, tout ce qui reste en file est converti en message normal.
:::

## Approuver une action bloquée

Lorsqu’un agent rencontre une action que ses garde-fous filtrent — une commande destructive, un outil privilégié — le serveur **bloque l’exécution** et publie une demande d’approbation vers chaque client connecté. Si vous avez cette conversation ouverte, la demande apparaît **dans le chat**, au-dessus du compositeur, sous la forme de la même carte d’options numérotées que celle utilisée pour `ask_user` (refuser, approuver, et éventuellement approuver pendant huit heures). Il n’y a pas d’option pour passer : un agent bloqué attend une décision.

Si vous êtes ailleurs dans l’application, un panneau toujours au premier plan dans l’interface liste quand même ce qui est en attente, ce qui vous permet de débloquer l’agent sans avoir à chercher l’espace. La superposition masque une demande dès que la conversation de cet espace est à l’écran, de sorte que vous ne répondez jamais deux fois à la même invite.

Il n’y a pas de délai d’expiration : un agent bloqué attend que quelqu’un décide. La même demande apparaît aussi dans le bandeau d’attention de la boîte de réception et sur le client mobile.

## Répondre à la question d’un agent

Un agent qui a besoin d’une préférence, d’une exigence manquante ou d’un véritable choix **doit** appeler `ask_user`. Écrire la question sous forme de message de chat termine le tour et vous devez relancer l’agent. L’outil affiche une carte numérotée dans la conversation — des options, un champ de texte libre facultatif, ou les deux — et l’exécution attend votre réponse.

Touchez une seule option pour l’envoyer (le numéro final devient une flèche au survol). Les réponses à choix multiples et saisies au clavier utilisent **Continuer** (`⌘↵` / `Ctrl↵`). **Ignorer** indique à l’agent de choisir une valeur par défaut raisonnable et de ne plus poser la question.

C’est un mécanisme distinct de la carte d’approbation ci-dessus : une approbation signifie « ai-je le droit de faire ceci ? », une question signifie « lequel de ces éléments vouliez-vous dire ? ». La fonction de question reste disponible sur le harnais intégré dans tous les modes, y compris les modes en lecture seule (elle ne modifie rien), et elle n’est délibérément pas enveloppée dans une invite d’approbation — une boîte de dialogue devant une autre boîte de dialogue échouerait en mode fermé si aucun approbateur n’est connecté. Une exécution sans conversation dans laquelle afficher la carte ne reçoit tout simplement pas l’outil.

## Arrêter un agent

Tant que des exécutions sont en direct, le bouton d’envoi du compositeur devient un bouton **Arrêter**. Videz le compositeur et appuyez dessus — cela arrête tous les agents en cours d’exécution dans cette conversation.

Il n’existe aucun contrôle d’arrêt dans l’en-tête de l’espace, ni raccourci clavier pour cela. Pour arrêter une seule exécution quand plusieurs sont en direct, ouvrez l’onglet d’activité de cette exécution — son en-tête comporte une pause/reprise et un arrêt propres à cette exécution (l’arrêt vous demande de confirmer). **Observabilité → En direct** liste chaque agent en cours d’exécution dans l’espace de travail avec le même contrôle.

Une exécution arrêtée est marquée comme arrêtée. Envoyez un nouveau message pour relancer.

## Utiliser les commandes slash

Tapez `/` dans le compositeur pour afficher la liste des commandes. Celles qui modifient le comportement de la conversation :

| Commande | Ce qu’elle fait |
| --- | --- |
| `/plan` | Bascule l’espace en mode plan. Un `/plan` seul arme simplement le mode ; `/plan <requête>` l’arme et envoie le reste comme votre message |
| `/goal <text>` | Enregistre l’objectif de travail de la conversation |
| `/loop <text>` | Itère sur une tâche jusqu’à ce qu’elle soit terminée |
| `/compact` | Replie l’historique plus ancien dans un résumé ancré et poursuit sur le contexte compacté |
| `/todo …` | Affiche et modifie la liste de tâches persistée de cette conversation |

Les skills apparaissent dans la même liste sous leur propre espace de noms `skill:`, de sorte qu’ils n’entrent jamais en collision avec les commandes ci-dessus — un skill nommé `plan` ou `compact` reste accessible :

| Commande | Ce qu’elle exécute |
| --- | --- |
| `/skill:<name>` | Un skill installé dans l’espace de travail, ou attaché à l’agent |
| `/skill:<repo>:<name>` | Un skill fourni par l’un des dépôts extraits dans cet espace |

Les skills de dépôt portent un badge indiquant le dépôt d’où ils proviennent, car un nom seul ne dit pas de quel service il encode les conventions et deux dépôts peuvent chacun fournir un `testing`. Vous n’avez pas besoin de saisir le préfixe pour en trouver un : saisir le nom nu du skill correspond aussi aux entrées préfixées par l’espace de noms.

Un agent ne porte jamais que les skills du dépôt dans lequel il travaille actuellement — voir [Skills limités à un dépôt](/fr-FR/manuel/concepts/modele-agent/#repo-scoped-skills). Le compositeur n’est pas limité de cette façon : vous pouvez invoquer le skill de n’importe quel dépôt en le nommant.

`/compact` et `/todo` sont interceptées par le client et ne sont jamais enregistrées comme messages — une ligne `/compact` dans la transcription repousserait d’un tour la coupure du prochain compactage. `/plan` bascule le mode stocké de l’espace plutôt que de circuler comme texte. Aucune des trois n’est donc « un message que vous envoyez à l’agent » ; ne vous attendez pas à les voir dans l’historique.

## Demander d’abord un plan

Avant une modification complexe, basculez l’espace en mode plan avec `/plan`, le menu déroulant de mode de la barre d’outils du compositeur, ou Maj+Tab. L’agent effectue alors ses recherches en lecture seule et vous remet un plan typé que vous approuvez avant le début du moindre travail. Voir [Utiliser le mode plan](/fr-FR/manuel/guides/mode-plan/).

## Atteindre un agent sans espace dédié

Vous n’avez pas besoin d’un espace par agent. Dans n’importe quel espace :

```
@alice can you look at the failing tests in src/auth_test.dart?
```

L’agent mentionné est ajouté à l’espace et lancé avec le contexte de cet espace. Voir [Mentionner des agents avec @](/fr-FR/manuel/guides/mentionner-agents/) pour savoir comment les noms sont mis en correspondance.
