Ce guide vous montre comment travailler avec le magasin de connaissances d’un espace de travail.

Le point important à savoir avant de commencer : **l’explorateur de mémoire est une surface de révision, pas de rédaction.** Les faits et les politiques sont écrits par les agents — au moyen de `propose_fact` et `propose_policy`, et de `supersede_fact` et `supersede_policy` pour les remplacer. `remember` écrit un élément de palier chaud limité à la session, que `consolidate_memory` pourra plus tard promouvoir en fait. Les décisions de réunion enregistrées sont recueillies dans le domaine `decisions` ; aucune récolte n’a lieu sur les exécutions d’agents terminées. Ici, vous lisez ce qu’ils ont écrit, vous le corrigez, vous le désactivez ou vous le supprimez.

La mémoire se trouve dans **Paramètres → Espace de travail → Mémoire** (`/workspaces/<id>/settings/memory`). Ce n’est pas une destination de premier niveau dans la barre latérale.

## Les trois onglets

La page comporte exactement trois onglets. Faits et Politiques affichent un compteur en direct ; le graphe, non :

- **Faits** — tous les faits de l’espace de travail, avec le nombre de ceux qui ne sont pas remplacés
- **Politiques** — les règles normatives regroupées par domaine, avec le nombre de celles qui sont actives
- **Graphe de connaissances** — une toile interactive de domaines, de sujets, de faits et de politiques

Un domaine ne se crée pas. Un domaine naît lorsqu’un agent y écrit le premier fait ou la première politique ; il n’existe aucune commande de création de domaine nulle part dans l’interface.

## Examiner et corriger un fait

1. Ouvrez l’onglet **Faits**.
2. Utilisez le champ de recherche pour restreindre la liste. Il s’agit d’un simple filtre par sous-chaîne sur le domaine, le sujet et le contenu de chaque fait — aucun index de mots-clés, aucun classement.
3. Utilisez le filtre de portée pour afficher toutes les portées, uniquement les faits à l’échelle de l’espace de travail, ou les faits d’un dépôt.
4. Utilisez la bascule de tri pour classer par récence ou par confiance.
5. Cliquez sur la commande de modification d’un fait.

La boîte de dialogue de modification vous permet de changer :

- **Domaine** — déplacer un fait d’un domaine à un autre
- **Sujet** — sa courte étiquette
- **Contenu** — le texte de la connaissance
- **Confiance** — un curseur par pas de 5 %

Enregistrez pour écrire la modification. Il n’y a pas de bouton **Ajouter un fait** ; la boîte de dialogue ne s’ouvre que sur une ligne existante.

## Voir les faits remplacés

L’onglet Faits comporte un interrupteur **Afficher remplacés**. Les faits remplacés sont masqués par défaut et révélés par cet interrupteur, qui est là où vit la piste d’audit — le remplacement ne supprime jamais.

## Supprimer un fait

Utilisez la commande de suppression d’un fait et confirmez. Il s’agit d’une vraie suppression, pas d’un remplacement : employez-la pour les faits qu’il était simplement erroné d’enregistrer, et laissez les agents remplacer les faits dont le _contenu_ a évolué.

## Gérer les politiques

L’onglet **Politiques** regroupe les politiques actives par domaine et relègue les inactives dans une section en fin de liste. Pour chaque politique, vous pouvez :

- La **modifier**
- La **supprimer**
- La **désactiver** / **activer** — l’option réversible, et généralement la bonne. Seules les politiques actives atteignent les prompts des agents.

Comme pour les faits, il n’existe aucune commande de création.

## Explorer le graphe de connaissances

L’onglet **Graphe de connaissances** dispose les domaines, les sujets, les faits et les politiques sous forme de toile de nœuds navigable — déplacez la vue, zoomez, faites glisser les nœuds. Toucher un nœud ouvre sa fiche de détail, depuis laquelle les mêmes boîtes de dialogue de modification sont accessibles. C’est le moyen le plus rapide de voir quels domaines sont réellement peuplés.

## Modifier la mémoire de travail d’un agent

La mémoire de travail est un bloc-notes privé propre à chaque agent, injecté dans son prompt au moment du lancement. Les agents l’écrivent eux-mêmes avec `record_observation` et `update_my_notes`, mais vous pouvez la lire et la modifier directement :

**Paramètres → Espace de travail → Agents** → sélectionnez l’agent → l’onglet **Mémoire**.

## Autorisations d’accès

Les autorisations d’accès à la mémoire associent le rôle d’un agent à une permission (`none`, `read`, `write`) par domaine. Écrivez-les avec les opérations `memory_access_grant.*`.

Deux points à comprendre sur la façon dont elles se résolvent :

- **Les lectures sont fail-open.** Sans ligne d’autorisation pour un couple (rôle, domaine), la permission effective est `read`. La seule écriture qui lève une exception sans `write` est `propose_policy`. Les écritures de faits ne sont pas soumises à autorisation.
- **Les autorisations sont indexées sur le rôle de l’agent.** Les outils de proposition appliquent la valeur `general` par défaut à un `agent_role` absent. Une autorisation écrite pour un autre rôle ne lie pas ces agents ; une autorisation `general`, si.

## La recherche n’est pas la même partout

Trois choses différentes portent le nom de « recherche de mémoire » et elles ne concordent pas :

| Où | Ce qu’elle fait |
| --- | --- |
| Le champ de recherche de l’onglet Faits | Un filtre par sous-chaîne sur les faits déjà chargés dans le client |
| L’opération RPC `memory_fact.search` | Recherche par mots-clés FTS5 uniquement — un client léger ne peut pas livrer d’embedding de requête, la recherche hybride reste donc interne à l’hôte |
| L’outil `search_memory` côté agent | `keyword`, `semantic` ou `hybrid` (le mode par défaut). Le mode hybride fusionne quatre voix : lexicale, sémantique, temporelle et de graphe |

Ainsi, un agent et la page Mémoire ne classeront pas la même requête de la même façon. Quand vous vérifiez ce qu’un agent peut réellement rappeler, demandez-le à l’agent.

## Les embeddings

Les faits sont vectorisés **au moment de l’écriture**, et uniquement lorsque le modèle d’embedding sur l’appareil est installé. Vérifiez son état dans **Paramètres → Serveur → Diagnostics et confidentialité → Recherche sémantique**. Installez le modèle avant que les agents ne commencent à écrire en mémoire si vous voulez un rappel sémantique.
