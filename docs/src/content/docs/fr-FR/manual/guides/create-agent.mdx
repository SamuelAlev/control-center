Ce guide vous montre comment ajouter un agent à un espace de travail et le
configurer jusqu’à ce qu’il puisse réellement s’exécuter.

Chaque espace de travail est amorcé avec cinq agents — un CEO, plus `qa`,
`architect`, `engineer` et `librarian` — vous disposez donc en général d’agents
avant d’en avoir configuré un seul. Les étapes ci-dessous s’appliquent de la même
façon à un agent amorcé qu’à un nouvel agent.

## Avant de commencer

- Vous êtes à l’intérieur d’un espace de travail. Toute cette surface se trouve
  sous **Paramètres → Espace de travail → Agents** (`/settings/workspace/agents`).
- L’agent aura besoin d’un backend. Soit vous connectez un fournisseur pour le
  harnais intégré sous **Paramètres → Serveur → Fournisseurs de modèles**, soit
  vous installez la CLI Claude Code sur la machine qui héberge `cc_server`.
- Si vous voulez que l’agent porte des skills, installez-les d’abord sous
  **Paramètres → Espace de travail → Compétences**. Le formulaire de l’agent ne
  permet que d’activer des skills qui existent déjà dans l’espace de travail.

## Ajouter l’agent

1. Ouvrez **Paramètres → Espace de travail → Agents**.
2. Cliquez sur **Nouvel agent**.

Il n’y a ni boîte de dialogue ni sélecteur de rôle. Un agent nommé « Agent sans
nom » est créé immédiatement et sélectionné dans le volet de détail à droite.

Vous devriez maintenant voir « Agent sans nom » dans la liste des agents à
gauche, avec l’onglet **Paramètres** de son volet de détail ouvert et un champ
**Nom** contenant « Agent sans nom ».

## Le nommer

- **Nom** — l’identifiant court utilisé dans les mentions @, par exemple
  `alice`. L’analyse des mentions reconnaît `@` suivi de caractères de mot : un
  nom contenant un trait d’union, un point ou un espace ne peut donc jamais être
  mentionné.
- **Titre** — le libellé lisible par un humain, par exemple « Développeur
  senior ».
- **Prompt système** — des instructions supplémentaires facultatives, injectées
  sous forme de section « Agent instructions » ; elles ne remplacent pas le reste
  du prompt assemblé.

Cliquez sur **Enregistrer les modifications** en bas du formulaire. Tous les
champs de cette page sont enregistrés par ce seul bouton.

## Lui attribuer un adaptateur et un modèle

Le menu déroulant **Adaptateur** liste les exécuteurs dont dispose réellement
l’hôte du serveur. L’adaptateur intégré est toujours détecté (c’est le serveur).
Claude Code n’apparaît que si sa CLI a été détectée sur cet hôte :

| Adaptateur                | Backend                                                     |
| ------------------------- | ----------------------------------------------------------- |
| Control Center (built-in) | La boucle d’agent interne au processus — aucune CLI externe |
| Claude Code               | `claude -p --output-format stream-json`                     |

Seul l’adaptateur intégré applique les modes, le pilotage, la pause et la
reprise, les contrats d’achèvement et les sous-agents. Claude Code n’en fournit
aucun. Cursor, Codex et les autres fournisseurs de modèles se rattachent à
l’adaptateur intégré, et non à des exécuteurs distincts.

:::note[Un adaptateur vide signifie la boucle intégrée]
Un agent dont l’adaptateur n’est pas défini est envoyé vers **Control Center
(built-in)**, la boucle à l’intérieur du serveur, si bien que rien n’a besoin
d’être installé sur l’hôte. Sans modèle défini non plus, il demande son modèle
par défaut à Anthropic : un agent entièrement non configuré ne s’exécute donc que
si vous avez connecté un compte Anthropic. Les spécialistes amorcés sont
livrés sans ni l’un ni l’autre ; définissez les deux sur tout agent que vous
comptez utiliser.
:::

Le menu déroulant **Modèle** est piloté par l’adaptateur que vous avez choisi.
Pour l’adaptateur intégré, la liste provient en direct des fournisseurs que vous
avez connectés sous **Paramètres → Serveur → Fournisseurs de modèles**, si bien
qu’un fournisseur sans identifiant enregistré ne contribue aucun modèle.

## Ajouter des skills

Le champ **Compétences** est un sélecteur de puces qui porte sur les ensembles de
skills installés dans cet espace de travail. Cliquez sur une puce pour l’activer
ou la désactiver ; le glyphe de coche marque celles qui sont sélectionnées. Si
l’espace de travail n’a aucun skill, le champ affiche « No skills available.
Create skills in Settings → Skills first. »

Vous ne choisissez pas ici les skills propres à un dépôt. Un dépôt qui en fournit
(dans `.agents/skills/`, `.claude/skills/` ou `.opencode/skills/`) les apporte
automatiquement à l’agent qui travaille dans ce dépôt, et ils sont échangés
lorsqu’il passe à un autre — voir [Skills limités au
dépôt](/fr-FR/manuel/concepts/modele-agent/#repo-scoped-skills).

## Définir la ligne hiérarchique et la persona

- **Rapporte à** — choisissez un autre agent par son nom. Cela construit l’arbre
  hiérarchique affiché par le bouton **Organigramme** dans l’en-tête de la page.
  Ce n’est pas la liste des agents dont se sert un chef d’équipe lorsqu’il
  délègue — celle-ci provient des membres de l’équipe et de leurs skills.
- **Persona** — du texte libre qui façonne le ton et le comportement, par
  exemple : « Préfère les solutions simples et lisibles. Écrit des tests pour
  tout code nouveau. »

## Ajuster l’exécution

- **Effort de raisonnement** — les options proviennent des niveaux publiés par le
  modèle sélectionné lui-même : Low / Medium / High, plus Extra High sur les
  modèles de style OpenAI et Extra High + Max sur ceux de style Claude. Le champ
  est entièrement masqué lorsque le modèle sélectionné ne déclare aucun niveau de
  réflexion, et sa valeur par défaut est celle du modèle.
- **Taille de la fenêtre de contexte** — pré-remplie à partir de la fenêtre de
  contexte du modèle à chaque changement de modèle, avec des puces en un clic
  pour la valeur par défaut du modèle, 200k, 500k et 1M. Une valeur que vous
  saisissez après avoir choisi le modèle l’emporte jusqu’au prochain changement
  de modèle.
- **Délai de silence (minutes)** — arrête une exécution après ce délai sans
  sortie. Laissez le champ vide pour utiliser la valeur par défaut du mode.

## Accorder des autorisations

Un agent n’a aucun interrupteur d’autorisation qui lui soit propre. Ce qu’il
peut pousser, ouvrir, fusionner ou atteindre est défini par les règles d’action
sous **Paramètres → Espace de travail → Autorisations des agents**, où une
règle peut être limitée à cet agent. Par défaut, un push, une pull request, une
revue ou une fusion et une écriture dans un outil de suivi vous demandent
chacun d’abord votre accord, et l’accès réseau est autorisé.

Le jeton GitHub de l’agent est toujours en lecture seule. Un push passe par
Control Center, qui interroge la règle **Pousser vers un dépôt distant** avant
de le transmettre. Voir
[Configurer les politiques de bac à sable](/fr-FR/manuel/guides/politiques-de-bac-a-sable/) pour
savoir comment chaque règle atteint une exécution.

:::note[Les règles et le bac à sable de l’OS sont des couches distinctes]
Les règles décident de ce qu’un agent peut faire ; le bac à sable de l’OS borne
l’endroit où ses processus peuvent lire, écrire et se connecter. `cc_server`
enveloppe les exécutions d’agents dans le bac à sable de l’hôte lorsqu’il en
existe un — Windows n’a aucun backend natif, et Linux et WSL2 ont besoin de
`bwrap` et `socat`. Voir [Bac à sable et
sécurité](/fr-FR/manuel/concepts/bac-a-sable-et-securite/) pour l’ensemble complet des
frontières.
:::

## Vérifier qu’il s’exécute

1. Ouvrez **Paramètres → Serveur → Fournisseurs de modèles** et vérifiez que
   l’adaptateur choisi signale une version installée plutôt que « Non trouvé ».
   Cliquez sur **Actualiser** pour relancer la sonde — la sonde s’exécute sur la
   machine qui héberge `cc_server`, et non sur celle que vous consultez.
2. Ouvrez un espace avec l’agent et envoyez-lui un message, ou mentionnez-le avec
   @ dans un espace existant.
3. Revenez à **Paramètres → Espace de travail → Agents**, sélectionnez l’agent et
   ouvrez son onglet **Journaux**. Une exécution devrait apparaître avec un badge
   d’état, une durée, une heure de début et l’adaptateur utilisé. **Vue** ouvre le
   flux d’événements de cette exécution.

Si aucune exécution n’apparaît du tout, suivez [Diagnostiquer un
agent](/fr-FR/manuel/guides/diagnostiquer-agent/).

## Supprimer un agent

Sélectionnez-le dans la liste des agents. Dans l’onglet **Paramètres**, faites
défiler jusqu’à la **Zone sensible** en bas du formulaire et cliquez sur
**Supprimer**.
