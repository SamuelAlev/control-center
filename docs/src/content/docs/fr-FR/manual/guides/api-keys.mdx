Ce guide indique où est stocké chaque identifiant utilisé par Control Center et
comment le modifier.

**Rien n’est stocké sur la machine sur laquelle vous tapez.** Chaque identifiant
vit sur le serveur ; celui qui répond à une requête donnée dépend de la présence
ou non d’un humain derrière elle.

| Identifiant                          | Stockage                                                  | Qui l’utilise                                                   |
| ------------------------------------ | --------------------------------------------------------- | --------------------------------------------------------------- |
| Votre connexion de forge ou de tickets | Le fichier de secrets en 0600 du serveur, indexé par votre identifiant d’utilisateur | Tout ce que vous faites : la surface des PR, les revues, les fusions, vos actions Linear |
| Les applications fournisseur du serveur | Le même fichier, plus `server_settings` pour les éléments non secrets | La connexion des personnes, et les jetons limités à un dépôt pour les agents, les pipelines et l’interrogation périodique |
| La clé d’installation Connect        | Le même fichier (`connect_install_key`)                   | Identifier ce serveur auprès de Control Center Connect          |
| Clés de fournisseurs de modèles et jetons OAuth | Le magasin d’identifiants propre au serveur      | L’adaptateur intégré, pour chaque espace de travail de l’installation |
| Identifiants du robot Slack          | `<dataDir>/<workspaceId>/chat_credentials/` sur le serveur | La passerelle de chat de cet espace de travail : les jetons de votre propre application, ou l’autorisation scellée de l’application partagée |
| Identifiants de CLI externe          | Ce que cette CLI utilise                                  | Claude Code, sur l’hôte du serveur                              |

## GitHub : votre connexion, et des jetons limités à un dépôt

- **La vôtre**, issue de **Se connecter à GitHub**. C’est elle qu’utilise
  chaque requête faite *en votre nom*, de sorte qu’une revue publiée pour vous
  porte votre nom. Un autre membre ne peut pas l’utiliser et se connecte
  lui-même. Il n’y a aucun jeton GitHub à coller
- **Le travail sans personne au clavier** (agents, pipelines, interrogation
  périodique, réponses du bot) reçoit un jeton limité à un seul dépôt à la fois,
  émis à partir de la GitHub App du serveur ou via Control Center Connect, et
  borné à ce qu’un membre responsable peut y faire. Ce n’est jamais votre
  connexion transmise telle quelle

La vôtre se définit dans la carte **Hébergement de code** sous **Paramètres → Vous → Profil** ; l’application du serveur, dans
**Applications fournisseur** sous **Paramètres → Serveur → Authentification
unique**. Voir [Configurer l’intégration GitHub](/fr-FR/manuel/guides/integration-github/)
et [Créer la GitHub App](/fr-FR/manuel/guides/github-app/).

GitLab et Bitbucket acceptent toujours un jeton personnel collé, stocké de la
même façon. Voir [Connecter un hébergeur de code](/fr-FR/manuel/guides/connecter-hebergeur-de-code/).

:::note[Il existe aussi un écran accessible uniquement par URL]
`/workspaces/<workspaceId>/api-keys` affiche les mêmes cartes que la
première étape de l’intégration initiale. Il n’a **aucune entrée de
navigation nulle part dans l’interface** ; il n’est accessible qu’en saisissant
l’URL. Utilisez plutôt Paramètres → Vous → Profil pour vos propres connexions, et Paramètres → Espace de travail → Intégrations pour le fournisseur de tickets.
:::

## Définir les clés de fournisseurs de modèles

L’adaptateur intégré authentifie lui-même les fournisseurs, et ces identifiants
vivent sur le serveur.

1. Allez dans **Paramètres → Serveur → Fournisseurs de modèles**
2. Faites défiler jusqu’à **Fournisseurs et modèles**
3. Connectez le fournisseur — OAuth par navigateur pour OpenAI, Codex, Cursor et
   Kimi Code ; une clé API pour Anthropic et les autres

Voir [Gérer les adaptateurs et les modèles](/fr-FR/manuel/guides/adaptateurs/)
pour la liste complète et pour ajouter un point de terminaison personnalisé.

Ces identifiants sont **globaux à l’hôte** : une seule clé sert chaque espace de
travail de l’installation. Les jetons OAuth sont renouvelés avant leur
expiration.

Claude Code se connecte via **Comptes Claude Code** dans **Paramètres → Serveur → Fournisseurs de modèles** : chaque compte reçoit son propre répertoire de configuration sur le serveur, et vous exécutez là-bas la commande `claude auth login` que l’application vous affiche.

La boîte de dialogue **Variables d’environnement** propre à chaque adaptateur
semble être l’endroit où déposer une clé pour l’un d’eux, mais ce n’est pas le
cas : elle écrit sur votre appareil, tandis que le serveur lit sa propre copie et
rien ne relie les deux. Voir
[Gérer les adaptateurs et les modèles](/fr-FR/manuel/guides/adaptateurs/).

## Connecter un fournisseur de tickets

La carte **Tickets** sous **Paramètres → Espace de travail → Intégrations** regroupe la part de l’espace de travail : chez quel fournisseur vivent vos tickets, et qui est Control Center lorsqu’il y travaille seul. Choisir **Local** masque
les lignes Linear — les tickets locaux vivent dans la base de données de ce
serveur et n’ont rien à authentifier.

Linear propose deux connexions et aucune clé à coller : **Linear** est la
vôtre, pour ce que vous faites, et se trouve dans **Paramètres → Vous → Profil** ; **Automatisation Linear** est l’application Control Center de l’espace de travail, connectée par un administrateur sur la carte **Tickets**, pour la synchronisation des tickets, les pipelines et les agents. Le serveur peut aussi
détenir une **Clé API de service** (**Applications fournisseur**) pour les
espaces de travail sans automatisation connectée. Aucun identifiant de tickets
n’est injecté dans le bac à sable d’un agent ; les agents écrivent les tickets
via les outils de Control Center, qui interrogent la règle **Écrire dans un
outil de suivi externe**. Voir
[Configurer l’intégration Linear](/fr-FR/manuel/guides/integration-linear/).

## Faire tourner ou révoquer

- **Votre connexion GitHub** : appuyez sur **Déconnecter**, puis de nouveau sur
  **Se connecter à GitHub**. La déconnexion invalide aussi tous les jetons que
  le serveur a émis en votre nom
- **Un jeton GitLab ou Bitbucket** : appuyez sur **Mettre à jour le jeton** et
  collez le nouveau, puis révoquez l’ancien sur la forge
- **L’application du serveur** : générez une nouvelle clé privée ou un nouveau
  secret client sur la page de l’application chez le fournisseur, collez-le dans
  **Applications fournisseur** et appuyez sur **Tester**
- **La clé d’installation Connect** : le propriétaire du serveur appuie sur **Renouveler la clé** sur la carte
  **Control Center Connect**. Toutes les personnes qui se sont connectées via
  Connect doivent se reconnecter. Si un serveur Connect est injoignable, rien ne
  change et l’on vous propose **Renouveler quand même**. Voir
  [Renouveler la clé d’installation](/fr-FR/manuel/reference/connect/#renouveler-la-clé-dinstallation)
- **Un fournisseur de modèles** : sur sa ligne, déconnectez-vous (OAuth) ou
  supprimez la clé, puis reconnectez-vous
- **Slack** : pour votre propre application, recollez les jetons dans la boîte
  de dialogue de connexion. L’application Control Center partagée n’a aucun
  jeton à renouveler : son jeton de robot est renouvelé via Connect, et
  **Déconnecter** le révoque et désinstalle le robot de Slack. Voir
  [Configurer l’intégration Slack](/fr-FR/manuel/guides/integration-slack/)

## Dépannage

### Un jeton GitLab ou Bitbucket fonctionne dans `curl` mais pas ici

Vérifiez la ligne **Hébergement de code**. Si elle indique « Non connecté » ou vous demande de vous reconnecter, votre jeton n’a pas été enregistré ou a été rejeté. Pour Bitbucket, saisissez l’adresse e-mail de votre compte Atlassian avec le jeton d’API.

### Un jeton GitLab ou Bitbucket est accepté mais les requêtes suivantes échouent

Le jeton est testé tel qu’il est stocké, donc la ligne nomme le compte derrière
lui — mais seulement le compte, pas les portées. Un jeton ayant trop peu de
portées se connecte, puis échoue à des requêtes individuelles. Vérifiez ses
portées et sa date d’expiration sur la forge.

### Un fournisseur indique que la connexion n’est pas configurée sur ce serveur

Le serveur n’a ni application propre pour ce fournisseur ni Control Center
Connect. Le propriétaire du serveur choisit l’une ou l’autre dans **Paramètres →
Serveur → Authentification unique**.
