Ce guide vous montre comment lier votre identité de chat à votre utilisateur Control Center et comment délier une liaison.

Chaque membre effectue cette opération une fois par fournisseur de chat. Elle est distincte de la connexion de l’application : la connexion rend le bot joignable pour tout l’espace de travail, la liaison vous rend _vous_ reconnaissable à l’intérieur.

## Pourquoi la liaison est requise

La passerelle refuse d’agir pour un compte de chat qu’elle ne peut pas rattacher à un membre de l’espace de travail. C’est délibéré — sans liaison, chaque message venu de Slack devrait être attribué à la personne qui a installé l’application, et la piste d’audit, les limites de débit par principal et les auteurs de tickets nommeraient tous la mauvaise personne.

Un membre non lié qui mentionne le bot reçoit une réponse dans ce fil Slack expliquant comment lier son compte. Rien n’est lancé.

## Lier avec un code

1. Allez dans **Paramètres → Espace de travail → Profil et identité** et faites défiler jusqu’à la carte **Comptes de messagerie liés**
2. Dans le bloc Slack, cliquez sur **Lier mon compte Slack**
3. Copiez la commande qui s’affiche, par exemple :

```text
/cc link K7M2QP
```

4. Dans Slack, envoyez cette commande au bot — un message privé est l’endroit le plus simple
5. Le bot confirme l’utilisateur Control Center auquel vous êtes désormais lié, et la boîte de dialogue que vous avez laissée ouverte se met à jour au même moment — vous n’avez pas à la fermer pour aller vérifier

Le code :

- Est à usage unique et expire **15 minutes** après sa génération
- Est toujours généré pour _vous_, jamais pour un coéquipier
- Remplace tout code que vous détenez déjà : appuyer de nouveau sur le bouton invalide le précédent
- Ne vit qu’en mémoire : un redémarrage du serveur invalide les codes en cours — appuyez de nouveau sur le bouton

Un code inconnu, expiré ou généré pour un autre espace de travail échoue de la même façon indiscernable : « ce code n’est pas valide (ou il a expiré) ».

## Liaison automatique par e-mail

Si votre profil Slack comporte une adresse e-mail vérifiée qui correspond à un utilisateur Control Center qui est **déjà membre de cet espace de travail**, la passerelle vous lie la première fois que vous lui parlez. Aucun code n’est nécessaire.

Les deux moitiés comptent : la correspondance d’e-mail prouve l’identité, mais seule l’appartenance accorde l’accès, donc un inconnu dont l’adresse e-mail existe par hasard sur le serveur ne se lie à rien. La liste des comptes liés indique comment chaque liaison a été établie (« associé par e-mail » ou « lié avec un code »).

La liaison automatique exige la portée `users:read.email`. Sans elle, Slack ne divulguera pas l’adresse et le parcours par code est la seule voie.

## Voir qui est lié

La liste des comptes liés relève de l’administration de l’espace de travail, elle se trouve donc sur l’autre moitié de la surface : **Paramètres → Espace de travail → Général → Ponts de messagerie → Comptes liés**. Elle répertorie chaque membre lié de l’espace de travail, avec le compte Slack auquel il correspond et la façon dont la liaison a été établie.

Votre propre état figure sur votre page de profil : la ligne **Lier mon compte Slack** affiche « Lié à _votre-identifiant-slack_ » une fois la liaison faite, et vous invite à établir la liaison dans le cas contraire.

La liste est un abonnement en direct, car le changement se produit de l’autre côté — vous saisissez le code dans Slack, donc aucune requête de l’application ne peut rapporter la réponse.

## Délier

Cliquez sur **Délier** sur une ligne de la liste de l’espace de travail.

- Chacun peut se délier lui-même
- Seul un administrateur peut délier un autre membre
- Délier révoque aussi tout code de liaison en cours pour ce membre

Après la dissociation, ce compte Slack ne peut plus piloter d’agents tant qu’il n’est pas de nouveau lié. Les espaces, transcriptions et tickets existants conservent leur attribution d’origine — délier n’est pas une rétractation du travail passé.

## Dépannage

### Le bot dit que je ne suis pas membre de cet espace de travail

Votre compte Slack est lié à un utilisateur Control Center, mais cet utilisateur n’a aucune appartenance dans cet espace de travail. Demandez à un administrateur de vous inviter ; consultez [Multijoueur — identité, appartenance et présence](/fr-FR/manuel/concepts/multijoueur/).

### Le bot dit que mon rôle est en lecture seule

Les rôles `viewer` et `guest` ne peuvent pas lancer de travail. Un administrateur doit élever votre rôle à `member` ou au-delà.

### La commande slash n’est pas reconnue

Vérifiez que la commande slash existe dans Slack et que vous envoyez bien la commande que la boîte de dialogue des paramètres vous a montrée — un administrateur l’a peut-être renommée, auquel cas la boîte de dialogue affiche le nom actuel.
