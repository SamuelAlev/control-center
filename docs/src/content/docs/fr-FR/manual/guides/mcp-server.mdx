Ce guide explique comment connecter un client MCP externe — Claude Code, un
éditeur, le MCP Inspector — au serveur d’outils propre à Control Center.

Control Center enregistre **110** outils et les sert via le Model Context
Protocol, en version de protocole `2024-11-05`. Des familles entières d’outils
que vous pourriez attendre sont absentes : il n’y a aucun outil de réunion ni de
calendrier, et aucun outil de projet.

## Trouver le point de terminaison

La surface MCP partage l’écouteur principal de `cc_server`. Il n’existe pas de
port MCP distinct.

| Point de terminaison | Méthode  | Rôle                                                     |
| -------------------- | -------- | -------------------------------------------------------- |
| `/mcp`               | `POST`   | Transport HTTP streamable — c’est ce que parle un client |
| `/mcp`               | `DELETE` | Terminer une session                                     |
| `/sse`               | `GET`    | Flux de notifications envoyées par le serveur            |

Une installation locale par défaut se trouve donc à l’adresse
`http://127.0.0.1:9030/mcp`.

1. Allez dans **Paramètres → Serveur → Serveurs MCP**
2. Lisez la carte **Serveur MCP** — elle indique s’il est en cours d’exécution ou
   arrêté, et le port sur lequel il écoute

La surface est active par défaut sur une installation neuve. Seul le propriétaire du serveur voit le jeton de la carte, et seul il peut démarrer ou arrêter le point de terminaison. **Démarrer au lancement
de l'app** détermine s’il revient après un redémarrage ; **Démarrer** / **Arrêter**
sont des commandes de session qui ne modifient pas cette préférence.

Le serveur se lie à loopback par défaut, de sorte que le point de terminaison
n’est joignable que depuis la machine sur laquelle `cc_server` s’exécute, sauf si
vous l’avez démarré avec `--bind any`.

## Obtenir le jeton

Chaque requête doit porter le jeton MCP du serveur, depuis n’importe quelle machine, y compris la boucle locale. Le serveur le crée la première fois qu’il démarre. Il n’existe aucun moyen de le désactiver ni de l’effacer.

1. Dans **Paramètres → Serveur → Serveurs MCP**, trouvez la ligne **Jeton d'authentification**
2. Appuyez sur **Afficher le jeton** et copiez-le
3. Pour le remplacer, appuyez sur **Renouveler le jeton**. Le serveur passe immédiatement au nouveau jeton, et chaque client qui utilise encore l’ancien est refusé jusqu’à ce que vous lui donniez le nouveau

## Connecter un client

Pointez votre client vers le point de terminaison HTTP streamable et envoyez le jeton sous la forme `Authorization: Bearer <token>` à chaque requête, `GET /sse` compris. Il n’existe pas d’autre moyen de l’envoyer : un jeton dans l’URL n’est pas accepté. La forme exacte de la configuration regarde votre client.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code ne récupérera pas cette configuration depuis un `.mcp.json` de projet —
il place les serveurs MCP limités au projet derrière une demande d’approbation à
laquelle un `claude -p` non interactif ne répond jamais. Passez la configuration
explicitement :

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` force Claude à n’utiliser que ce fichier, de sorte que le
même serveur n’est pas aussi découvert depuis le projet et enregistré deux fois.

Point de contrôle : demandez au client de lister ses outils. Vous devriez voir des
entrées `mcp__*` couvrant les tickets, les espaces, la mémoire, le graphe de code
et la revue.

## Ce que refuse le point de terminaison

Le jeton ouvre chaque outil du serveur ; le point de terminaison refuse donc aussi tout ce qu’une page web pourrait avoir envoyé, avant même d’examiner le jeton.

| Requête                                                                 | Réponse |
| ----------------------------------------------------------------------- | ------- |
| Un en-tête `Origin` qui n’est pas une page de cette machine (`http://localhost`, `http://127.0.0.1` ou `http://[::1]`, tout port) | `403`, « Les requêtes inter-origines ne sont pas acceptées » |
| Un en-tête `Host` qui n’est ni l’adresse loopback et le port de cet écouteur, ni le nom d’hôte public du serveur | `403`, « Hôte inconnu » |
| Un `POST` dont le corps n’est pas `application/json`                    | `415`   |
| Aucun jeton, ou un jeton erroné                                         | `401`   |

Pour servir MCP au-delà de l’hôte, démarrez le serveur avec `--bind any` et envoyez le jeton depuis l’autre machine, en adressant le serveur par son nom d’hôte public.

## Limiter chaque appel à un espace de travail

Chaque outil qui touche des données propres à un espace de travail exige
`workspace_id`, et un appel sans cet identifiant est refusé plutôt que résolu vers
un espace de travail « courant » :

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

L’identifiant est celui qui figure dans l’URL de votre navigateur ou de
l’application : `/workspaces/<workspace_id>/…`. Les seules exceptions sont les
outils qui couvrent réellement plusieurs espaces de travail, comme
`list_workspaces` et les outils du fil d’actualités — le fil d’actualités est
propre à chaque utilisateur et un agent n’a pas d’utilisateur à lui, si bien que
ces outils opèrent sur les fils du propriétaire du serveur.

Les outils limités à un dépôt vérifient en outre que le dépôt est lié à cet espace
de travail.

## Savoir ce que la surface refusera

- **Filtrage par mode.** Un appel est résolu côté serveur selon le mode de
  l’espace de l’agent appelant. Un agent en mode lecture seule ne peut pas
  atteindre un outil d’écriture en omettant `space_id` — le mode est alors
  recherché à partir de son exécution active.
- **Garde-fous d’action.** Les outils qui modifient l’état déclarent leurs classes
  d’effet et passent par la même politique que le reste du produit. Voir
  [Configurer les garde-fous](/fr-FR/manuel/guides/configurer-garde-fous/).
- **Confirmation.** Certains outils destructeurs construisent une charge utile de
  confirmation qui doit être approuvée avant que l’appel se poursuive.

Le catalogue complet est annoncé dans `tools/list` sans filtrage de découverte —
un client MCP externe refuse d’appeler un outil qui n’est pas dans sa liste mise
en cache, si bien que masquer des outils les casse plutôt que de les ranger.

## Serveurs MCP utilisés par vos agents

Ce guide porte sur le point de terminaison propre à Control Center. Dans l’autre sens, les serveurs MCP auxquels Control Center se connecte et qu’il transmet aux agents qu’il exécute se configurent sous **Paramètres → Serveur → Serveurs MCP**, à deux niveaux. Dans les deux cas, Control Center se connecte au serveur lui-même et transmet ses outils à l’exécution. Le harnais intégré et Claude Code reçoivent donc les mêmes outils et les mêmes demandes d’approbation. Une exécution de Claude Code les voit sous le serveur `control-center`, sous la forme `mcp__control-center__mcp__<server>__<tool>`.

### Serveurs d’espace de travail

Les administrateurs de l’espace de travail les ajoutent sous **Serveurs MCP de l'espace de travail**. Chaque exécution d’agent de l’espace de travail reçoit leurs outils, et les exécutions des autres espaces de travail n’en reçoivent pas.

1. Sélectionnez **Ajouter un serveur** et donnez-lui un nom court : lettres, chiffres, `-` et `_`, jusqu’à 24 caractères. Les outils apparaissent sous la forme `mcp__<name>__<tool>`.
2. Choisissez comment le joindre :
   - **Commande (stdio) :** un exécutable et ses arguments, ainsi que les variables d’environnement dont il a besoin.
   - **URL (HTTP ou SSE) :** le point de terminaison, ainsi que les en-têtes dont il a besoin, comme `Authorization: Bearer …`.
3. Enregistrez. Point de contrôle : le serveur affiche **Connecté** avec un nombre d’outils.

Les valeurs des variables d’environnement et des en-têtes sont stockées dans le fichier de secrets du serveur et ne sont plus jamais affichées. Pour modifier une valeur, remplacez-la ; pour la supprimer, retirez son nom.

Une commande s’exécute sur la machine du serveur, sous l’utilisateur propre au serveur ; elle ne démarre donc qu’après l’approbation du propriétaire du serveur. D’ici là, elle affiche **En attente d'approbation**. Un serveur par URL fonctionne immédiatement, mais il ne peut atteindre que des adresses publiques tant que le propriétaire du serveur ne l’a pas approuvé, approbation qui autorise aussi `localhost` et les réseaux privés. Lorsque le propriétaire du serveur enregistre un serveur, cela vaut approbation. Si une autre personne modifie la façon dont un serveur démarre ou l’adresse à laquelle il se connecte, une nouvelle approbation est requise. Activer ou désactiver un serveur conserve son approbation.

### Serveurs personnels

Les serveurs personnels appartiennent au propriétaire du serveur et sont listés sous **Serveurs MCP externes**. Les serveurs configurés sur la machine du serveur pour Claude, Codex, Cursor, Gemini, VS Code, Windsurf, OpenCode ou dans un `.mcp.json` y sont trouvés automatiquement. Le propriétaire du serveur peut aussi en ajouter avec **Ajouter un serveur**, à l’aide du même formulaire. Un serveur que vous ajoutez l’emporte sur un serveur découvert portant le même nom.

Ils agissent avec l’identité et les identifiants du propriétaire du serveur :

- Ils ne sont disponibles que dans les exécutions que le propriétaire du serveur démarre ou dont il est responsable, y compris l’automatisation d’un espace de travail dont le propriétaire est responsable. Cela couvre les exécutions du harnais intégré comme celles de Claude Code.
- L’exécution d’un membre, l’automatisation rattachée à un membre et toute exécution sur un serveur sans propriétaire enregistré n’en reçoivent aucun. Là, les outils ne sont pas listés, ne peuvent pas être appelés et n’apparaissent pas dans la recherche d’outils.
- Ni les serveurs personnels ni ceux de l’espace de travail ne sont servis au jeton MCP ni aux appareils appairés, et leurs ressources et prompts ne sont pas transmis.

La connexion à un serveur avec OAuth n’est pas disponible depuis le formulaire. Utilisez un serveur qui accepte un jeton dans un en-tête, ou configurez-le pour l’un des outils ci-dessus, où il est découvert.

## Dépannage

### Le client ne voit aucun outil

- Vérifiez que la carte **Serveur MCP** indique qu’il est en cours d’exécution
- Vérifiez que le port correspond à celui de votre `cc_server`
- Sur Claude Code, vérifiez que vous avez bien passé `--mcp-config` et
  `--strict-mcp-config`

### 401 Unauthorized

La requête ne portait aucun jeton, ou un ancien. Copiez le jeton actuel depuis la ligne **Jeton d'authentification** et envoyez-le sous la forme `Authorization: Bearer <token>`. Un jeton dans l’URL est ignoré.

### 403 depuis un client qui fonctionnait auparavant

La requête portait un `Origin` provenant d’une page web, ou un `Host` auquel le serveur ne répond pas. Appelez le point de terminaison depuis un client plutôt que depuis une page de navigateur, par l’adresse loopback du serveur ou son nom d’hôte public.

### 415 Unsupported Media Type

Envoyez les corps `POST /mcp` en `application/json`.

### Un appel d’outil échoue avec « Missing or invalid argument: workspace_id »

Ajoutez `workspace_id`. Il n’y a pas d’espace de travail implicite.

### Un appel d’outil est refusé comme inconnu

[Outils MCP](/fr-FR/manuel/reference/outils-mcp/) répertorie le catalogue. Appelez
le nom exactement tel qu’il y figure.
