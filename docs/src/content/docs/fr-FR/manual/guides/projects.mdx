Un projet est un regroupement de tickets à l’échelle d’un espace de travail,
orienté vers un objectif commun. Les projets sont propres à Control Center —
ils ne se synchronisent jamais avec un fournisseur externe tel que Linear.

## Créer un projet

1. Dépliez le groupe **Tickets** dans la barre latérale de l’espace de travail.
   Il liste **Tous les tickets**, une ligne par projet non archivé, puis
   **Nouveau projet**.
2. Cliquez sur **Nouveau projet**.
3. Renseignez le **Nom du projet**, une **Description** facultative et
   choisissez une **Couleur**.
4. Appuyez sur **Créer le projet**.

Vous arrivez sur la vue d’ensemble du nouveau projet, et celui-ci apparaît comme
une ligne de la barre latérale sous **Tickets**.

## Ajouter des tickets à un projet

Le projet est un champ propre au ticket, défini à l’un de ces deux endroits :

- Ouvrez le ticket et définissez **Projet** dans son panneau de propriétés.
- Faites un clic droit sur le ticket dans la liste et utilisez le sous-menu
  **Projet**.

Le sélecteur du panneau de propriétés propose aussi **Nouveau projet**, ce qui
vous permet de classer un ticket dans un projet que vous créez à la volée.
**Aucun projet** efface le champ.

Un ticket appartient au maximum à un seul projet.

:::note[Un projet n’est pas une action groupée]
La barre flottante qui apparaît lorsque vous sélectionnez plusieurs tickets
couvre le statut, la priorité, la personne assignée, les étiquettes et la
suppression. Elle n’a pas de puce de projet : classer de nombreux tickets oblige
donc à les traiter un par un.
:::

Vous pouvez aussi partir du projet : **Nouveau ticket** dans la vue d’ensemble
du projet crée un ticket et le classe dans ce projet.

## Suivre la progression d’un projet

Ouvrez un projet depuis sa ligne dans la barre latérale, ou rendez-vous à
l’adresse `/workspaces/<workspace-id>/projects/<project-id>`.

La vue d’ensemble affiche le glyphe et le nom du projet, un badge de statut, la
description et une barre de progression « terminés sur total ». En dessous, les
tickets du projet sont regroupés par statut.

Elle n’agrège rien d’autre — il n’y a ni répartition par personne assignée ni
répartition par priorité. Pour cela, filtrez plutôt la liste principale des
tickets.

## Changer le statut d’un projet

Les projets ont trois états :

| Statut      | Signification            |
| ----------- | ------------------------ |
| **Actif**   | Le travail est en cours  |
| **Terminé** | Tout le travail est fait |
| **Archivé** | Référence historique     |

Utilisez le menu **⋯** de l’en-tête du projet. Il propose **Modifier le projet**,
**Marquer comme terminé** / **Marquer comme actif**, **Archiver** / **Restaurer**
et **Supprimer le projet**.

L’archivage masque le projet dans la liste de la barre latérale et dans les
sélecteurs de tickets. Il est réversible — **Restaurer** remet le projet en
actif — mais le projet n’est accessible que par URL tant qu’il est archivé.

## Les projets créés pour vous

Approuver une orchestration crée un projet et y classe le ticket parent, aux
côtés de tout ce que vous avez classé à la main. Les éléments de travail générés
sont des étapes de pipeline, pas des lignes de ticket : ils n’apparaissent donc
pas sur le tableau du projet. C’est le seul chemin automatisé : aucun nœud de
pipeline ne crée de tickets, un pipeline ne peut donc pas alimenter un projet.
Voir [Lancer une orchestration](/fr-FR/manuel/guides/lancer-orchestration/).

:::note[Les projets sont une surface d’opérateur]
Créez, listez, mettez à jour et supprimez des projets dans l’application. Les
agents n’ont pas d’outils de projet.
