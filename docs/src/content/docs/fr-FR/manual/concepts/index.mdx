These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/fr-FR/manuel/guides/); when you want to look
something up, go to the [reference](/fr-FR/manuel/reference/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/fr-FR/manuel/concepts/espaces-de-travail/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/fr-FR/manuel/concepts/modele-agent/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/fr-FR/manuel/concepts/cycle-de-vie-du-lancement/) — what happens between your message and the agent's first token
- [Modes](/fr-FR/manuel/concepts/modes/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/fr-FR/manuel/concepts/contexte-des-outils/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/fr-FR/manuel/concepts/intelligence-du-code/) — the code graph, language server, structural search and debugger
- [Conversation history](/fr-FR/manuel/concepts/historique-des-conversations/) — persistence, compaction and forking a transcript
