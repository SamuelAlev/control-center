## Ce que vous allez construire

À la fin de ce tutoriel, vous aurez :

- Un agent que vous avez créé et configuré vous-même
- Un espace où vous et cet agent dialoguez
- Une exécution terminée, avec du travail validé dans un arbre de travail isolé et
  une ligne dans le journal d’exécution de l’agent

Prérequis : [Votre premier espace de travail](/fr-FR/manuel/tutoriels/premier-espace-de-travail/) terminé, pour que cet espace de travail ait un dépôt enregistré et au moins un fournisseur de modèles connecté.

## Étape 1 : Créer un agent

1. Allez dans **Paramètres → Espace de travail → Agents**
2. Cliquez sur **Nouvel agent**. Un agent nommé « Agent sans nom » est créé
   immédiatement et sélectionné dans l’effectif — il n’y a ni boîte de dialogue de
   création ni rien à confirmer. Vous le configurez sur place.
3. Dans l’onglet **Paramètres**, renseignez :
   - **Nom** : quelque chose de court et mémorable, comme `alice`. C’est ce
     que vous tapez après `@`.
   - **Titre** : ce qu’il fait, par ex. « Ingénieur backend »
   - **Adaptateur** : `Control Center (built-in)`. Choisissez-le
     délibérément — seul le harnais intégré peut être piloté en cours d’exécution
     et mis en pause à la limite d’un tour, et il ne nécessite aucune CLI
     installée sur l’hôte du serveur.
   - **Modèle** : choisissez dans la liste que sert le fournisseur connecté
   - **Compétences** : activez celles qui conviennent, par ex. `testing` ou
     `architecture`
4. Appuyez sur **Enregistrer les modifications**

:::note[Un agent sans adaptateur s’exécute sur la boucle intégrée]
Lorsque le champ Adaptateur n’est pas défini, le lancement retombe sur
**Control Center (built-in)** — la boucle d’agent à l’intérieur du serveur, si
bien que rien n’a besoin d’être installé sur l’hôte. Il lui faut quand même un
modèle : sans modèle défini, il demande son modèle par défaut à Anthropic, ce qui
fonctionne si vous avez connecté un compte Anthropic et échoue sinon avec
`No credential for provider "anthropic"`. Définissez les deux explicitement dans
tous les cas, sans quoi vous vous exécuteriez sur un modèle que vous n’avez pas
choisi.
:::

**Point de contrôle.** La ligne de l’effectif affiche le nom de votre agent et un
anneau d’état creux.

## Étape 2 : Démarrer un espace

1. Dans la barre latérale, trouvez la section **Espaces** et cliquez sur le bouton **+**
2. Donnez un nom à l’espace
3. Sous **Ajouter des agents**, sélectionnez l’agent que vous venez de créer
4. Si l’espace de travail contient des dépôts, choisissez ceux sur lesquels cet
   espace doit travailler
5. Cliquez sur **Créer**

L’espace s’ouvre. En arrière-plan, Control Center provisionne pour cette
conversation un arbre de travail copy-on-write des dépôts sélectionnés, sur sa
propre branche. Votre checkout source n’est jamais modifié.

## Étape 3 : Envoyer une tâche

Saisissez une tâche concrète et petite sur le dépôt que vous avez enregistré.
Quelque chose dont le résultat est vérifiable fonctionne le mieux — ajouter un
test, corriger un lint, renommer un symbole.

Appuyez sur Entrée. Vous n’avez besoin de mentionner personne avec `@` : avec
un seul agent dans l’espace, un simple message le réveille. Dans un espace à
plusieurs agents, `@name` en désigne un.

Control Center assemble le prompt à partir des instructions de l’agent, de sa
persona, de ses skills et du contexte de l’espace, puis lance l’exécution.

**Point de contrôle.** Le bouton d’envoi du compositeur devient un bouton
d’arrêt — un agent travaille dans cette conversation — et le texte commence à
arriver.

## Étape 4 : Regarder l’agent travailler

La conversation affiche l’exécution au fil de son déroulement :

- **Raisonnement**, affiché en ligne pendant que l’agent réfléchit
- **Appels d’outils** : lectures et écritures de fichiers, recherches,
  commandes shell, chacun avec son résultat
- **Texte** : résumés, explications et questions qui vous sont adressées

Si l’agent pose une question, répondez dans la conversation et il reprend.

Pour les métriques propres à une exécution et ses commandes de pause, de reprise
et d’arrêt, trouvez l’agent en cours dans la section **Agents** du panneau
Général de l’espace et choisissez **Ouvrir l’activité**.

Dans le volet d’activité, le badge d’état indique **En cours**, puis **Réussi**
quand l’exécution se termine. Une exécution qui cale ou boucle indique
**Bloqué** ; une exécution qui échoue indique **Échoué**. Dans le registre
des agents, l’anneau de l’effectif est creux avant la première exécution et plein
dès que l’agent redevient inactif.

Ce qui encadre l’exécution : son propre arbre de travail copy-on-write, les
identifiants délivrés par le courtier au lancement et révoqués au démontage, un
environnement assaini, la surface d’outils que son mode autorise et les
garde-fous d’action. Les effets comme pousser une branche ou ouvrir une pull
request passent par une porte distincte — voir
[Garde-fous](/fr-FR/manuel/concepts/garde-fous/).

## Étape 5 : Vérifier le résultat

1. Ouvrez **Paramètres → Espace de travail → Agents** et sélectionnez votre agent
2. Ouvrez l’onglet **Journaux**

**Point de contrôle.** Une ligne d’exécution, affichant son état, sa durée, ses
heures de début et de fin et l’adaptateur sur lequel elle s’est exécutée.

Les modifications de l’agent sont validées sur la branche de la conversation,
dans son arbre de travail. Les commits ont pour auteur l’agent, et vous y êtes
crédité dans un trailer `Co-Authored-By:`.

## Obtenir une pull request

Rien n’ouvre une pull request de lui-même. Si vous en voulez une, demandez-la
dans la même conversation :

> Poussez cette branche et ouvrez une pull request vers la branche par défaut.

Pousser (`gitPush`) et créer une PR (`prCreate`) demandent par défaut votre
approbation, attendez-vous donc à une confirmation avant chacun. Si aucun
approbateur n’est connecté au moment où l’invite se déclenche, l’action est
refusée plutôt qu’autorisée — les garde-fous échouent en mode fermé.

La PR est ouverte sous l’identité GitHub dont le jeton a servi à l’exécution — la
vôtre, si vous avez enregistré un jeton personnel — et non sous le nom de
l’agent. La paternité de l’agent apparaît sur les commits.

Vous pouvez aussi l’ouvrir vous-même : le panneau **Contrôle de source** de
l’espace comporte un bouton **Créer la pull request** qui reprend la branche de la
conversation dans l’écran de composition, et
**Demandes de tirage → Nouvelle PR** ouvre le même écran vide. C’est là que le
tutoriel suivant prend la suite.

## Récapitulatif

Vous avez créé un agent, configuré son adaptateur et son modèle, lui avez donné un
espace et une tâche, et regardé une véritable exécution se terminer dans un arbre
de travail isolé sans toucher à votre checkout.

**Ensuite :** [Examiner votre première demande de tirage](/fr-FR/manuel/tutoriels/premiere-pr/) pour découvrir le déroulement d’une revue.
