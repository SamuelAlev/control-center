## Ce que vous allez créer

À la fin de ce tutoriel, vous aurez :

- Ouvert une demande de tirage dans l’atelier de PR de Control Center
- Lu son diff et laissé un commentaire en ligne
- Soumis un verdict de revue
- Fusionné la PR

Prérequis : avoir terminé [Lancer votre premier agent](/fr-FR/manuel/tutoriels/premier-agent/) et avoir une demande de tirage ouverte sur un dépôt enregistré dans cet espace de travail. Pour les étapes de revue, choisissez une PR que vous n’avez pas ouverte — le bouton **Revue** est masqué sur vos propres PR. La fusion fonctionne tout de même sur une PR dont vous êtes l’auteur.

## Étape 1 : Ouvrir la demande de tirage

1. Cliquez sur **Demandes de tirage** dans la barre latérale
2. Trouvez votre PR et cliquez dessus

**Point de contrôle.** La PR s’ouvre sous la forme d’un atelier à onglets — Aperçu, Diff, Contrôle de source, Discussion, Actions — centré sur **Aperçu** : le titre et les actions, la description et la chronologie d’activité, ainsi qu’une barre latérale avec l’état, les relecteurs, les personnes assignées, les vérifications et les fichiers modifiés. Cliquer sur un fichier à cet endroit l’ouvre directement dans l’onglet Diff. L’onglet **Revue de PR** n’est pas ouvert tant que personne ne demande une revue par IA.

:::note[File d’attente vide avec une invite « Connecter GitHub »]
Cet état signifie que le _serveur_ ne détient aucun jeton GitHub — votre client n’en détient jamais. Définissez-en un sous **Paramètres → Espace de travail → Profil et identité → Hébergement de code**, puis actualisez la liste.
:::

## Étape 2 : Lire le diff

Ouvrez l’onglet **Diff**. Une arborescence de fichiers repliable se trouve à gauche, et la bande au-dessus du diff comporte un sélecteur de plage de commits — pour restreindre le diff à un commit ou à une série de commits — ainsi que le nombre de fichiers et le décompte courant des ajouts et des suppressions.

Le bouton de réglages de la barre d’outils du diff contrôle son rendu :

- Vue **Scindé** ou **Unifié**
- **Retour à la ligne** ou défilement des lignes longues
- **Ligatures de la police de code**

Marquez un fichier comme vu pour suivre votre progression dans un diff volumineux. La navigation au clavier est décrite dans [Raccourcis clavier](/fr-FR/manuel/reference/raccourcis-clavier/).

## Étape 3 : Laisser un commentaire en ligne

1. Survolez une ligne du diff — une petite pastille `+` apparaît dans la marge
2. Cliquez dessus pour commenter cette ligne, ou faites-la d’abord glisser verticalement pour sélectionner une plage
3. Saisissez votre retour. Le composeur propose deux envois :
   - **Démarrer une revue** (ou **Ajouter à la revue** si une revue est déjà en cours) met le commentaire en file d’attente. Le fil affiche **Revue en attente** jusqu’à ce que vous soumettiez un verdict à l’étape 4.
   - **Ajouter un seul commentaire** le publie immédiatement sur GitHub. Le fil affiche **Publication...**, puis **Synchronisé**, et propose une nouvelle tentative si la publication échoue.

Pour ce tutoriel, utilisez **Démarrer une revue** afin que le commentaire soit envoyé avec le verdict.

:::caution[Un commentaire en file d’attente n’est pas encore sur GitHub]
**Démarrer une revue** / **Ajouter à la revue** conservent le commentaire localement jusqu’à ce que vous soumettiez un verdict. Seul **Ajouter un seul commentaire** publie immédiatement. Le _corps_ de la revue que vous rédigez à l’étape 4 est un brouillon distinct.
:::

## Étape 4 : Soumettre une revue

1. Cliquez sur **Revue** dans la rangée d’actions de l’onglet Aperçu — le même bouton se trouve aussi dans la barre d’outils de l’onglet Diff. Il est masqué sur les PR dont vous êtes l’auteur et sur une PR fermée ou fusionnée.
2. Rédigez un résumé dans le composeur. Il s’enregistre automatiquement comme brouillon, ce qui vous permet de fermer la fenêtre superposée et d’y revenir.
3. Choisissez un verdict :
   - **Demander des modifications**
   - **Commenter**
   - **Approuver**

Le verdict, c’est le bouton. Après **Approuver** ou **Demander des modifications**, le bouton adopte le libellé **Approuvé** ou **Modifications demandées**. Un verdict **Commenter** laisse le libellé **Revue**.

**Point de contrôle.** Le bouton affiche « Approuvé » ou « Modifications demandées » si vous avez choisi l’un de ces deux verdicts.

## Étape 5 : Fusionner

Le bouton **Merge** est présent dès que GitHub signale que la PR est fusionnable — il n’est pas conditionné à votre propre approbation. Sa couleur traduit la préparation plutôt qu’une autorisation : primaire lorsque les approbations requises et les vérifications sont au vert, secondaire tant qu’une vérification est en cours, destructive lorsqu’un relecteur sollicité n’a pas approuvé ou qu’une vérification échoue.

1. Cliquez sur **Merge**
2. Choisissez une méthode : **Squash and merge**, **Create a merge commit** ou **Rebase and merge**
3. Pour les deux premières, modifiez le titre et le message de commit préremplis
4. Confirmez

Tout problème en suspens — « Échec des vérifications », « Some reviews are pending » — est listé dans le volet volant avant que vous ne confirmiez.

:::caution[La fusion est irréversible]
La fusion pousse des commits vers GitHub. Elle n’entre jamais dans la pile d’annulation de Control Center et ne peut pas être annulée depuis ici.
:::

Après la fusion, un événement de domaine `PrMerged` est déclenché ; les analyses et les notifications le consomment. Consultez [Événements de domaine](/fr-FR/manuel/reference/evenements-de-domaine/) pour savoir qui d’autre l’écoute.

## Relire avec l’IA

Control Center peut placer un pipeline de relecteurs sur une PR ouverte, mais uniquement lorsque vous le demandez : le modèle `pr_review` n’a qu’un déclencheur manuel, rien d’autre.

1. Ouvrez le menu de débordement de la rangée d’actions de l’onglet Aperçu et choisissez **Ask AI**. Control Center lance l’exécution et ouvre l’onglet **Revue de PR**, pour que vous puissiez regarder les spécialistes travailler.
2. Les agents relecteurs consignent leurs constats sous forme de nœuds de revue dans l’espace de la PR ; une étape finale les consolide en un seul rapport.

Le pipeline ne publie délibérément rien sur GitHub — il se termine après la consolidation. La publication est une étape distincte que vous accomplissez vous-même, avec le bouton **Publier sur GitHub** de l’onglet **Revue de PR**. Consultez [Utiliser la revue assistée par IA](/fr-FR/manuel/guides/revue-par-ia/).

## Récapitulatif

Vous avez ouvert une PR dans l’atelier, lu le diff avec la coloration syntaxique, laissé un commentaire en ligne, soumis un verdict et fusionné — sans quitter l’application.
