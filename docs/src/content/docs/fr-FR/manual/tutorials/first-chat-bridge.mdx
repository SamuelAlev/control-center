## Ce que vous allez construire

À la fin de ce tutoriel, vous aurez :

- Une application Slack créée pour votre espace de travail, avec les bonnes permissions et les bons événements déjà configurés
- Une connexion active entre Slack et Control Center
- Votre propre compte Slack lié à votre utilisateur Control Center
- Un agent qui vous répond dans un fil Slack et un ticket créé depuis une commande slash

Prérequis :

- [Votre premier espace de travail](/fr-FR/manuel/tutoriels/premier-espace-de-travail/) et [Lancer votre premier agent](/fr-FR/manuel/tutoriels/premier-agent/) terminés — un espace de travail sans agent peut recevoir un message Slack, mais n’a personne pour y répondre
- L’**agent CEO** de l’espace de travail dispose d’un adaptateur et d’un modèle définis dans **Paramètres → Espace de travail → Agents**. La passerelle réveille l’agent CEO, pas l’agent que vous avez configuré dans le tutoriel précédent, et un agent sans adaptateur s’exécute sur la boucle intégrée avec le modèle par défaut d’Anthropic.
- Le rôle `owner` ou `admin` dans l’espace de travail Control Center (connecter une application de chat parle au nom de tout l’espace de travail)
- La permission de créer et d’installer des applications dans votre espace de travail Slack

Rien ici n’exige d’adresse publique, de tunnel ni de port entrant. Control Center établit une connexion _sortante_ vers Slack via le Socket Mode, donc cela fonctionne depuis un portable derrière un NAT.

## Étape 1 : Obtenir un jeton de configuration d’application Slack

C’est le seul secret que vous devez récupérer à la main. Il permet à Control Center de créer l’application, puis de la modifier, à votre place.

1. Ouvrez [api.slack.com/apps](https://api.slack.com/apps)
2. Faites défiler jusqu’à la section des jetons de configuration d’application, en bas de la page
3. Générez une paire de jetons pour votre espace de travail Slack
4. Copiez le jeton d’**actualisation** — il commence par `xoxe-`

## Étape 2 : Laisser Control Center créer l’application

1. Dans Control Center, allez dans **Paramètres → Espace de travail → Général** et repérez la carte **Ponts de messagerie**
2. Dans le bloc **Slack**, cliquez sur **Créer l’app pour moi**
3. Collez le jeton de configuration d’application
4. Vérifiez l’apparence qu’aura le bot :
   - **Nom de l’app** : comment Slack liste l’application, par ex. `Control Center · Acme`
   - **Nom du bot** : ce que les gens tapent après `@`, par ex. `control-center`
   - **Description courte** et **Ce que le bot dit savoir faire**
   - **Commande** : `cc` par défaut, la commande est donc `/cc`
   - **Messages directs** : laissez activé pour que les membres puissent envoyer des messages privés au bot
5. Cliquez sur **Créer l’app**

Control Center compose toute la définition de l’application — Socket Mode activé, les scopes du bot et les abonnements aux événements dont il a besoin, la commande slash, l’onglet Messages — et la crée dans Slack.

## Étape 3 : Terminer les deux étapes que seul Slack peut faire

Slack n’a pas d’API pour générer un jeton au niveau de l’application ni pour installer une application, donc la boîte de dialogue vous présente les deux sous forme de liens :

1. **Générer un jeton au niveau de l’app** — ouvre **Basic Information → App-Level Tokens**. Créez un jeton avec la portée `connections:write` et copiez-le. Il commence par `xapp-`
2. **Installer l’app** — ouvre **Install App**. Installez l’application dans votre espace de travail, puis copiez le **Bot User OAuth Token**. Il commence par `xoxb-`

Gardez les deux valeurs à portée de main pour l’étape suivante.

## Étape 4 : Connecter

1. De retour dans la boîte de dialogue, cliquez sur **Coller les identifiants**
2. Saisissez le **Jeton du bot** (`xoxb-…`) et le **Jeton d’application** (`xapp-…`)
3. Laissez **Jeton de configuration d’app** vide — celui de l’étape 1 a déjà été enregistré (Slack l’a fait tourner, et Control Center a enregistré le nouveau)
4. Cliquez sur **Connecter**

Control Center vérifie le jeton du bot auprès de Slack avant de stocker quoi que ce soit, puis ouvre le socket. La ligne affiche désormais le nom du bot et celui de votre espace de travail Slack, avec une étiquette **En ligne**.

## Étape 5 : Lier votre propre compte Slack

La connexion rend le bot joignable ; la liaison fait que _vous_ êtes reconnaissable. Tant que votre identité Slack n’est pas liée, le bot n’agira pas sur vos messages — il n’attribue jamais un message à la personne qui a installé l’application.

La liaison est personnelle, elle se trouve donc sur une page distincte de celle de la connexion à l’échelle de l’espace de travail.

1. Allez dans **Paramètres → Espace de travail → Profil et identité** et repérez la carte **Comptes de messagerie liés**
2. Cliquez sur **Lier mon compte Slack**
3. Copiez la commande qui s’affiche, par exemple `/cc link K7M2QP`
4. Dans Slack, envoyez cette commande au bot en message privé
5. Le bot répond « Lié — vous êtes … »

Le code est à usage unique et expire au bout de 15 minutes. Si votre adresse e-mail Slack correspond à un utilisateur Control Center déjà membre de cet espace de travail, la passerelle vous lie automatiquement la première fois que vous lui parlez, et vous pouvez passer cette étape.

Si vous mentionnez le bot avant que cela soit fait, il refuse et en explique la raison. Les trois refus sont distincts, lisez donc bien celui que vous avez reçu :

- **Expéditeur non lié** : le bot vous indique comment lier votre compte. Revenez à cette étape.
- **Lié, mais pas membre de cet espace de travail** : demandez à un administrateur de vous inviter.
- **Membre avec un rôle en lecture seule** (viewer ou guest) : le bot ne lancera aucun travail en votre nom.

## Étape 6 : Confier quelque chose à un agent

1. Dans Slack, invitez le bot dans un canal : `/invite @control-center`
2. Mentionnez-le avec une vraie demande :

   > @control-center résume les PR ouvertes sur le dépôt api

La passerelle :

1. Crée un espace Control Center pour ce fil Slack, nommé d’après le canal Slack et votre demande
2. Réveille l’agent d’accueil de l’espace de travail (l’agent CEO quand il y en a un, sinon le premier agent)
3. Diffuse la réponse de l’agent dans le fil Slack au fur et à mesure de sa rédaction

Répondez dans le même fil Slack pour continuer — aucune nouvelle mention n’est nécessaire, car le fil Slack est désormais relié. Vous pouvez aussi envoyer un message privé au bot plutôt que d’utiliser un canal ; chaque conversation privée pilote son propre espace Control Center, avec un titre et une ligne d’état « is thinking… » tant que l’agent travaille.

La diffusion en continu exige l’API de streaming de Slack, que tous les forfaits ne proposent pas. Si l’accès est refusé à votre application, la passerelle cesse de réessayer pour toute la connexion et publie chaque réponse en un seul message, et la carte Ponts de messagerie indique « Le streaming en direct est désactivé pour cette app Slack — les réponses arrivent en un seul message. » Tout le reste fonctionne de la même manière.

## Étape 7 : Créer un ticket sans quitter Slack

```text
/cc ticket Fix the flaky login test | It fails on CI about once a day.
```

Le bot répond avec la clé du ticket qu’il a créé. Le ticket est un ticket Control Center local ordinaire, dont vous êtes l’auteur, prêt à être assigné à un agent. `/cc help` liste tout ce que la commande sait faire.

## Récapitulatif

Vous avez créé une application Slack depuis Control Center, l’avez connectée via un socket sortant, avez lié votre identité Slack à votre utilisateur Control Center et avez piloté un agent depuis un fil Slack. Tout ce qui s’est passé dans Slack existe aussi dans Control Center : le fil Slack est un espace, la réponse est une transcription, le ticket est un ticket.

**Ensuite :** [Configurer l’intégration Slack](/fr-FR/manuel/guides/integration-slack/) couvre la voie manuelle, la rotation des jetons et le dépannage. Pour le modèle sous-jacent, lisez [Passerelles de chat](/fr-FR/manuel/concepts/passerelles-de-chat/).
