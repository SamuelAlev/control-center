Este é o caminho completo mais curto entre o zero e um agente executando no seu
próprio código. Siga na ordem; cada etapa depende da anterior.

Você precisa de Git, de uma conta no GitHub e de uma conta em um provedor de
modelos (Anthropic, OpenAI, Codex, Cursor, Kimi Code ou qualquer provedor com uma
chave de API) ou da CLI do Claude Code já instalada. Todo o resto é configurado ao
longo do caminho.

## Etapa 1: Instalar e abrir

Instale o Control Center conforme descrito em [Instalar](/pt-BR/manual/instalar/) e
abra-o.

Na primeira inicialização, o aplicativo de desktop pergunta **“Como o Control
Center deve ser executado?”**. Escolha **Executar neste aplicativo**. O Control
Center inicia um `cc_server` headless nesta máquina, que é dono dos seus dados e
faz todo o trabalho. Você nunca o vê; em vez disso, a tela de onboarding é aberta.

:::note[Prefere não instalar nada?]
O mesmo aplicativo roda no navegador em [app.usectrl.dev](https://app.usectrl.dev) com
os mesmos recursos. Uma aba do navegador, porém, não consegue hospedar o servidor,
então você precisa fornecer um — execute `cc_server` localmente e conecte-se a
`ws://localhost:9030`, ou aponte-o para um servidor em outra máquina. Este início
rápido segue o caminho do desktop porque não exige nenhuma configuração de servidor;
consulte [Instalar](/pt-BR/manual/instalar/#use-it-in-your-browser) para a rota no
navegador.
:::

## Etapa 2: Concluir o onboarding

O onboarding tem cinco etapas e elas são executadas em ordem — não dá para pular
nenhuma.

1. **Conectar**: entre com o GitHub ou cole um token de acesso pessoal com `repo` e `read:org`. A credencial é armazenada no servidor, vinculada à sua conta.
2. **Espaço de trabalho**: dê um nome ao seu primeiro espaço de trabalho e, opcionalmente, escolha um logotipo. Criá-lo semeia cinco agentes — um CEO e mais `qa`, `architect`, `engineer` e `librarian` — e os modelos de pipeline integrados.
3. **Sandbox**: registra uma preferência de sandbox. Qualquer uma das opções permite continuar.
4. **Adaptador**: escolha o adaptador e o modelo padrão dos agentes. Selecione **Control Center (built-in)** e use o seletor de provedores que aparece para entrar em um provedor de modelos — a lista de modelos fica vazia até que um provedor seja conectado. Concluir esta etapa também grava o adaptador e o modelo no agente CEO do espaço de trabalho.
5. **Voz (opcional)**: instale um modelo de fala no próprio dispositivo para ditado, ou pule esta etapa.

Em seguida, o Control Center abre a caixa de entrada do seu espaço de trabalho.

:::note[O que limita uma execução de agente]
Os comandos dos agentes são envolvidos no sandbox nativo do sistema operacional do
host quando ele existe — Seatbelt no macOS, bubblewrap no Linux. O Windows não tem
backend, então as execuções nele são limitadas apenas pelas outras camadas: o worktree
da própria conversa (`git worktree` no Windows; copy-on-write onde o `rift` existe),
credenciais intermediadas a cada inicialização e revogadas no encerramento, e os
guardrails de ações. Consulte [Sandbox e segurança](/pt-BR/manual/conceitos/sandbox-e-seguranca/).
:::

## Etapa 3: Adicionar um repositório

Abra **Configurações → Espaço de trabalho → Repositórios** e clique em **Adicionar
repositório**.

A caixa de diálogo navega pelas pastas da máquina que executa o servidor, não do seu
cliente, e permanece dentro das raízes que o servidor está configurado para expor (por
padrão, o diretório pessoal do usuário dele). Somente checkouts do git recebem uma
caixa de seleção. Marque a sua e registre-a.

Um checkout só é aceito se estiver dentro de uma árvore de trabalho do git, tiver um
remoto `origin` e esse remoto apontar para um host de código compatível — github.com,
gitlab.com ou bitbucket.org. Qualquer outro caso é recusado com o motivo.

Os repos têm escopo de espaço de trabalho: registrar um checkout aqui o coloca _neste_
espaço de trabalho. Não há uma etapa separada de vinculação.

## Etapa 4: Dar a um agente um adaptador e um modelo

Abra **Configurações → Espaço de trabalho → Agentes**. Selecione o agente `engineer`
na lista.

Na aba **Configurações**, defina:

- **Adaptador**: `Control Center (built-in)`
- **Modelo**: escolha um dos modelos do provedor que você conectou no onboarding

Pressione **Guardar alterações**.

Na prática, esta etapa não é opcional. Somente o agente CEO herda o adaptador escolhido
durante o onboarding; os quatro especialistas são criados sem adaptador. Eles recorrem
ao **Control Center (built-in)** com o modelo padrão da Anthropic, então só são
executados se você tiver conectado uma conta da Anthropic — e, nesse caso, em um modelo
que você não escolheu.

## Etapa 5: Enviar uma tarefa ao agente

1. Na barra lateral, encontre a seção **Espaços** e clique no botão **+**.
2. Dê um nome ao espaço, adicione o agente `engineer` em **Adicionar agentes** e crie-o.
3. Digite uma tarefa pequena e concreta para o repo que você registrou e pressione Enter.

O Control Center prepara um worktree copy-on-write dos repos do espaço de trabalho para
esta conversa, monta um prompt a partir do papel, da persona e das skills do agente e do
contexto do espaço, e despacha a execução. Seu checkout de origem nunca é tocado.

## Etapa 6: Ver o agente trabalhar

Você deve ver, nesta ordem:

- O botão de enviar do composer virar um botão de parar, porque um agente está trabalhando nesta conversa
- O raciocínio, as chamadas de ferramentas e o texto do agente sendo transmitidos para a transcrição
- O botão de enviar voltar quando a execução terminar

Depois abra **Configurações → Espaço de trabalho → Agentes**, selecione o agente e
confira a aba **Registros**: uma linha de execução, com o status, a duração, os horários
de início e de término e o adaptador usado.

Esse é o ciclo. Todo o resto no Control Center — revisão de pull request, pipelines,
tickets, reuniões, Slack — deriva dele.
