Este guia mostra como dar ao seu servidor um GitHub App próprio. Leva cerca de
dois minutos, só o proprietário do servidor faz isso, e só precisa acontecer
uma vez por servidor.

:::note[Talvez você não precise disso]
Com o Control Center Connect ativado, as pessoas entram no GitHub pelo App
compartilhado do Control Center, ou pelo App que o Connect da sua organização
usa. Registre o seu quando tiver escolhido **Usar meus próprios apps**: o app próprio do
servidor só é usado nesse caso. Consulte [Control Center Connect](/pt-BR/manual/referencia/connect/).
:::

Para entrar com a sua própria conta depois, consulte
[Configurar a integração com o GitHub](/pt-BR/manual/guias/integracao-github/).

## O que o app faz

Um único registro atende a dois trabalhos diferentes:

| Trabalho               | O que responde                                  | Por que importa                                                                                  |
| ---------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **Uma pessoa entra**   | O id de cliente e o segredo de cliente do app   | Cada pessoa recebe uma credencial do GitHub só dela, no servidor, em todos os dispositivos       |
| **O servidor age**     | O id do app e a chave privada                   | Agentes, pipelines, pollers e respostas do bot recebem tokens para um repositório de cada vez    |

O segundo trabalho nunca toma emprestada a credencial de uma pessoa por
inteiro. Cada token que o servidor emite cobre um único repositório e é
limitado ao que um membro responsável pode fazer nele. Ler um repositório
vinculado só exige o app; qualquer coisa que grave exige um membro que possa
fazer push. A automação nunca aprova uma pull request.

O app próprio do servidor só se aplica em **Usar meus próprios apps**. Com os apps do
Control Center ou um Connect próprio, o Connect executa todas as faixas, inclusive a do
GitHub; o app do servidor continua salvo, mas sem uso, até você voltar a trocar. Um espaço de trabalho com os próprios apps
([Dar a um espaço de trabalho um app próprio](#dar-a-um-espaço-de-trabalho-um-app-próprio))
usa o app próprio dele no lugar, qualquer que seja o modo do servidor. Um app com alguns campos faltando é um erro, e não
um motivo para recorrer a outra coisa: os logins no GitHub são recusados até que todos
os campos estejam definidos.

## Pré-requisitos

- Você é o **proprietário do servidor**. O cartão **Apps do fornecedor** é
  invisível para todos os outros
- Uma conta do GitHub. O app é criado nela
- Um endereço do servidor que o seu navegador consiga alcançar. A URL pública do
  servidor (ou o loopback, no caso do servidor do próprio desktop) é para onde o
  GitHub manda você de volta

## Criar com um clique

1. Acesse **Configurações → Servidor → Início de sessão único** e role até o
   cartão **Apps do fornecedor**
2. No bloco **GitHub**, digite, se quiser, a organização do GitHub que deve ser
   dona do app em **Organização (opcional)**. Deixe em branco para criar o app
   na sua própria conta; criá-lo em uma organização exige um proprietário dessa
   organização
3. Clique em **Criar meu app do GitHub**
4. O navegador abre o GitHub com o app já preenchido. Clique em
   **Create GitHub App**
5. O GitHub manda você de volta ao servidor, que armazena o id do app, a chave
   privada, o id de cliente e o segredo de cliente e, em seguida, abre a página
   de instalação do app

Nada é copiado à mão, e o código de conversão vai direto do GitHub para o seu
servidor. O link funciona uma única vez e expira depois de dez minutos; se ele
expirar, clique em **Criar meu app do GitHub** de novo.

O app se chama `Control Center <code>` e pede exatamente o que o Control Center
usa:

| Permissão                                  | Acesso              |
| ------------------------------------------ | ------------------- |
| Metadata                                   | Leitura             |
| Contents                                   | Leitura e gravação  |
| Pull requests                              | Leitura e gravação  |
| Issues                                     | Leitura e gravação  |
| Checks, Actions, Commit statuses           | Leitura             |
| Organization members                       | Leitura             |

Os webhooks ficam desativados: o servidor faz polling. Para transferir depois
para uma organização um app que você criou na sua própria conta, use
**Transfer ownership** nas configurações avançadas do app no GitHub.

Ponto de verificação: o bloco do GitHub exibe "O servidor pode agir por si
próprio e as pessoas podem entrar".

## Instalar onde estão os seus repositórios

Um app registrado, mas não instalado, consegue fazer o login das pessoas e não
lê nada.

1. Na página de instalação que o GitHub abriu, escolha a conta ou a organização
   dona dos seus repositórios
2. Escolha **All repositories**, ou selecione os que este servidor deve ver

Para instalá-lo em outra conta mais tarde, um administrador do espaço de
trabalho acessa **Configurações → Espaço de trabalho → Integrações**, encontra
**Instalações do app do GitHub** no cartão **App do GitHub**, em Hospedagem de
código, e clica em **Instalar o app do GitHub**. A lista mostra todas as contas em que o app está
instalado e sinaliza uma instalação suspensa.

## Compartilhar a instalação de uma organização

Uma organização instala o GitHub App uma única vez. Depois disso, qualquer pessoa da organização que entrar no GitHub em um servidor do Control Center pode usar a instalação, seja qual for esse servidor: o seu, o de um colega ou um próprio. Não há nada a autorizar por servidor.

Cada token que um servidor recebe é da própria pessoa que entrou, limitado a um repositório e ao papel dela nele, então nunca vai além do que ela poderia fazer no GitHub. O log de auditoria do GitHub mostra essa pessoa, agindo pelo app.

Para impedir que o Control Center alcance uma organização, um dono da organização remove a instalação ou reduz os repositórios dela no GitHub. Remover uma pessoa da organização também interrompe o acesso dela.

## Registrar manualmente

O cartão **Apps do fornecedor** também aceita os valores diretamente, para um
app que você mesmo registrou:

| Grupo                          | Campos                                                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------------------------------ |
| **Agir como o servidor**       | **Id da app** e **Chave privada** (o `.pem` inteiro, incluindo as linhas `BEGIN` e `END`)              |
| **Entrada das pessoas**        | **Id de cliente** e **Segredo de cliente**. **URLs de callback** mostra a URL a registrar, tal como está |
| **Conversas de pull request**  | **Login do bot**, resolvido quando você testa a conexão                                                |

Registre a callback URL `<server origin>/oauth/github/callback` exatamente como
o cartão a mostra, deixe **Expire user authorization tokens** ativado e conceda
as permissões da tabela acima. Clique em **Testar**: ele pergunta ao GitHub em
quais contas o app está instalado, para que "salvo" e "funciona" não se
confundam.

## Configurar pelo `.env` do servidor

Em uma instalação headless ou automatizada, o servidor preenche cada campo a
partir do arquivo `.env` na primeira vez em que não tem nenhum valor
armazenado:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

Coloque a chave em **uma única linha**: um valor do `.env` ocupa uma linha, e
`\n` entre aspas duplas é decodificado como quebra de linha. O servidor se
recusa a iniciar quando `GITHUB_APP_PRIVATE_KEY` ou `GITHUB_CLIENT_SECRET` é
exportado no ambiente do processo dele, onde qualquer processo filho poderia
lê-lo; mantenha-os no arquivo `.env` (no Docker, monte-o em `/app/bin/.env`). O
preenchimento acontece **uma vez por campo**, então o que você edita em
Configurações não é desfeito no próximo reinício.

## Dar a um espaço de trabalho um app próprio

Um espaço de trabalho pode usar um app próprio em vez do app do servidor:

1. Um administrador do espaço de trabalho acessa **Configurações → Espaço de trabalho → Integrações**
2. No cartão **Control Center Connect**, ele escolhe **Usar meus próprios apps** e clica em **Aplicar**. Todos no espaço de trabalho entram de novo, pelos apps do espaço de trabalho
3. O cartão **App do GitHub**, em Hospedagem de código, passa a ter os campos desse app: **Id da app** e **Chave privada** em **Atuando por este espaço de trabalho**, **Id de cliente** e **Segredo de cliente** em **Entrada das pessoas**. Clique em **Testar** assim que eles estiverem definidos

Os membros passam então a entrar nesse app para este espaço de trabalho. Um espaço de trabalho com os próprios apps nunca recorre ao app do servidor nem ao Connect: enquanto os campos dele não estiverem completos, o trabalho dele no GitHub é recusado. A mesma escolha vale para o Google Calendar, o Linear e a busca de GIFs, cada um com os próprios campos ao lado do respectivo provedor, na mesma página. Consulte
[Dê ao espaço de trabalho o seu próprio aplicativo do Linear](/pt-BR/manual/guias/integracao-linear/#dê-ao-espaço-de-trabalho-o-seu-próprio-aplicativo-do-linear)
e [Dê ao espaço de trabalho o seu próprio cliente do Google](/pt-BR/manual/guias/conectar-calendario/#dê-ao-espaço-de-trabalho-o-seu-próprio-cliente-do-google).
As outras escolhas desse cartão, e o que cada uma faz, estão em
[Escolha por espaço de trabalho](/pt-BR/manual/referencia/connect/#escolha-por-espaço-de-trabalho).

## Solução de problemas

### "Criar meu app do GitHub" diz que o servidor não tem endereço

O servidor não tem uma URL pública para a qual um navegador possa voltar.
Defina `CC_SERVER_PUBLIC_URL` (ou `--public-url`) e tente de novo.

### O GitHub diz que o link expirou

A página de uso único já foi usada, ou passaram dez minutos. Comece de novo a
partir de Configurações.

### O teste diz que as credenciais funcionam, mas o app não está instalado em lugar nenhum

Registro e instalação são etapas separadas. Abra a página de instalação do app
ou use **Instalar o app do GitHub** em Espaço de trabalho → Integrações.

### O teste diz que não foi possível ler a chave privada

Cole o arquivo `.pem` inteiro, incluindo as linhas `-----BEGIN` e `-----END`.
Uma chave `ed25519` ou EC não pode ser usada: os GitHub Apps assinam com RSA.

### Um membro entrou, mas não vê nenhum repositório

O app não está instalado na conta dona deles, ou a instalação dele seleciona
outros repositórios. Um login só concede o que o app tem permissão de enxergar.

### Os agentes dizem que a instalação do GitHub App está suspensa

Alguém suspendeu a instalação no GitHub. Reative-a em
**Settings → Applications → Installed GitHub Apps** da conta.
