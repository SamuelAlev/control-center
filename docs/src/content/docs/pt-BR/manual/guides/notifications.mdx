Este guia mostra como configurar as notificações e o que cada ajuste realmente
controla.

As notificações chegam por duas superfícies. A **central de notificações** — o
sino da barra de título — lê um feed durável por espaço de trabalho no servidor.
Os **toasts do sistema operacional** são um caminho à parte, exclusivo do
desktop, alimentado por frames ao vivo enviados pelo servidor.

:::note[A versão web não mostra notificações do sistema operacional]
O pipeline de toasts só é construído pela inicialização do desktop. Em
`app.usectrl.dev` não há toasts do sistema operacional, nem sons de notificação,
nem banners ambientais — o sino e seu histórico continuam funcionando, porque
leem o feed do servidor. O cliente de celular não tem nenhuma superfície de
notificação.
:::

## Ativar ou desativar categorias

1. Acesse **Configurações → Você → Notificações**
2. Deixe **Ativar notificações** ligado
3. Alterne as categorias que você quiser. São exatamente dezessete:

| Categoria                 | Dispara quando                                                             |
| ------------------------- | -------------------------------------------------------------------------- |
| Agente finalizado         | Um agente respondeu em uma execução que você iniciou, ou a execução falhou |
| Um agente está esperando você | Um agente precisa da sua aprovação, fez uma pergunta a você ou está parado em uma credencial |
| PR publicada              | Um agente publicou uma PR                                                  |
| PR mesclada               | Uma PR foi mesclada                                                        |
| Novas mensagens           | Alguém mencionou você em um espaço                                         |
| Mencionado em um pull request | A sondagem de notificações do GitHub viu você mencionado em uma PR     |
| Revisão solicitada        | Sua revisão foi realmente solicitada em uma PR que não é rascunho          |
| Revisão desatualizada     | Novos commits chegaram a uma pull request que você já revisou              |
| Pronto para mesclar       | Uma pull request de sua autoria passou a ser mesclável, ou deixou de ser   |
| Decisões de revisão       | Um revisor aprovou, solicitou alterações ou teve uma aprovação descartada  |
| Verificações              | A CI falhou em uma pull request de sua autoria, ou se recuperou            |
| Tópicos de revisão        | Alguém respondeu em um thread do qual você participa, ou o resolveu        |
| Ticket atribuído          | Um ticket foi atribuído                                                    |
| Status do ticket alterado | Um ticket mudou de status                                                  |
| Reunião prestes a começar | Uma reunião do calendário está dentro da sua janela de antecedência       |
| Calendário desconectado   | O token de OAuth de um calendário conectado expirou                        |
| Atualizações de recintos  | Um recinto foi assumido, recuperado ou falhou                              |

Nada fora desta lista pode ser notificado nem filtrado — não existe uma
categoria “todo o resto”.

**Um agente está esperando você** dispara uma vez por espera, quando ela começa:
uma aprovação pendente (incluindo concessões de execução no sandbox e aprovações
de ferramentas do Claude Code), uma pergunta `ask_user` ou uma execução retida
porque a credencial dela não consegue atendê-la. A notificação abre o espaço
onde você responde e fica em silêncio enquanto você já está olhando para esse
espaço.

Essas preferências seguem o seu usuário entre dispositivos, então um celular e
um notebook ficam em sincronia. O volume é a exceção deliberada e permanece por
dispositivo.

## Definir o horário de silêncio

1. Na mesma página, ative **Quiet hours**
2. Digite um horário de início e um de fim em `HH:MM` (a janela padrão é
   22:00–08:00)

Durante o horário de silêncio, notificações não urgentes são descartadas — não
são enfileiradas nem reproduzidas depois.

Duas categorias são **urgentes** e sempre são entregues, ignorando o horário de
silêncio _e_ o modo foco: **Reunião prestes a começar** e **PR publicada**. Um
alerta de reunião que você só vê depois não vale nada, e é exatamente por isso.

## Escolher um som

1. Role até **Som de notificação**
2. Escolha um dos onze sons incluídos, ou **Nenhum**
3. Pressione o botão **Testar** para ouvi-lo e ajuste o volume com o controle
   deslizante

O app reproduz o som por conta própria; a notificação do sistema operacional é
entregue em silêncio, para que você nunca a ouça duas vezes.

## Definir a antecedência das reuniões

1. Role até **Antecedência do alerta**
2. Escolha **5**, **10**, **15** ou **30** minutos

É essa a antecedência com que a notificação **Reunião prestes a começar**
dispara antes de um evento do calendário. O padrão são 5 minutos.

## Saber quando uma notificação é suprimida

Uma notificação é descartada, em silêncio, quando qualquer uma destas condições
é verdadeira:

- As notificações estão desativadas globalmente, ou a categoria dela está
- Você já está na rota para onde ela levaria — e, no caso de uma mensagem, já
  está nesse espaço
- O modo foco está ativo e a categoria não é urgente
- O horário de silêncio está ativo e a categoria não é urgente

Essas verificações se aplicam aos toasts do sistema operacional. O sino durável
continua registrando o evento.

Há mais duas supressões, mais acima na cadeia, naquilo que o servidor chega a
enviar:

- Uma mensagem de outro **humano** em que você não é mencionado nunca se torna
  uma notificação
- Em um espaço compartilhado, a resposta de um agente avisa quem iniciou
  aquela execução, não todos os membros
- Os espaços entre agentes ficam silenciados na barra lateral, então nunca
  incrementam o indicador de não lidos dos humanos

Dentro de um espaço não existe canto tranquilo: toda conversa notifica
igualmente, threads incluídos. O estado de leitura tem escopo por espaço, então
o não lido se agrega entre as conversas de um espaço, em vez de ser rastreado
por conversa.

## Ler e limpar a central de notificações

1. Clique no sino da barra de título

O popover mostra a atividade recente e cada entrada tem um link direto para
aquilo de que ela trata. Abri-lo **não** marca tudo como lido — use **Marcar
tudo como lido** no cabeçalho, ou marque uma única linha. O estado de leitura
segue o seu usuário entre dispositivos.

:::note[Limpar tudo é uma marca-d'água, não uma exclusão]
**Limpar tudo** grava uma marca-d'água por usuário que oculta tudo o que é mais
antigo; as linhas permanecem. Separadamente, cada espaço de trabalho retém
apenas as suas **200** linhas de feed mais recentes, podadas conforme novas
chegam, enquanto o sino assina as **50** mais novas e o popover lista até
**15** delas. O histórico além disso se perde, independentemente do estado de
leitura.
:::

## Solução de problemas

### Nenhuma notificação do sistema operacional no macOS

A autorização é solicitada nativamente quando o app é iniciado. Se você a
recusou, reative o Control Center em Ajustes do Sistema → Notificações; não há
nenhum aviso dentro do app para solicitá-la novamente.

### Nada chega na versão web

É o esperado — a versão web não tem pipeline de notificações do sistema
operacional. Use o sino.

### O indicador do sino mostra zero, mas há claramente atividade nova

Até que o fluxo de marcas de leitura se resolva após a conexão, as entradas são
renderizadas como lidas para evitar um indicador que pisca e depois se esvazia.
Isso se estabiliza assim que a marca carrega.

### A execução de um agente terminou, mas nada me avisou

Verifique se você já não estava no espaço onde isso aconteceu — uma rota ativa
suprime o próprio toast do sistema operacional. Em um espaço compartilhado, uma
execução que outra pessoa iniciou avisa essa pessoa, não você. Uma rodada que
terminou sem resposta e sem erro não envia nada.
