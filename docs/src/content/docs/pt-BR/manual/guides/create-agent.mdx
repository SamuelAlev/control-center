Este guia mostra como adicionar um agente a um espaço de trabalho e configurá-lo
até que ele consiga de fato ser executado.

Todo espaço de trabalho é criado com cinco agentes — um CEO e mais `qa`,
`architect`, `engineer` e `librarian` —, então normalmente você tem agentes antes
mesmo de ter configurado qualquer um. As etapas abaixo valem igualmente para um
agente semeado e para um novo.

## Antes de começar

- Você está dentro de um espaço de trabalho. Toda a superfície fica em
  **Configurações → Espaço de trabalho → Agentes** (`/settings/workspace/agents`).
- O agente vai precisar de um backend. Conecte um provedor para o harness
  integrado em **Configurações → Servidor → Provedores de modelos**, ou instale a
  CLI do Claude Code na máquina que hospeda o `cc_server`.
- Se você quiser que o agente tenha skills, instale-as primeiro em
  **Configurações → Espaço de trabalho → Habilidades**. O formulário do agente só
  permite alternar skills que já existem no espaço de trabalho.

## Adicionar o agente

1. Abra **Configurações → Espaço de trabalho → Agentes**.
2. Clique em **Novo agente**.

Não há diálogo nem seletor de função. Um agente chamado “Agente sem nome” é criado
imediatamente e selecionado no painel de detalhes à direita.

Agora você deve ver “Agente sem nome” na lista à esquerda, com a aba
**Configurações** do painel de detalhes aberta e um campo **Nome** contendo
“Agente sem nome”.

## Dar um nome a ele

- **Nome** — o identificador curto usado nas menções com @, por exemplo `alice`.
  O analisador de menções reconhece `@` seguido de caracteres de palavra, então um
  nome que contenha hífen, ponto ou espaço nunca poderá ser mencionado.
- **Título** — o rótulo legível por pessoas, por exemplo “Programador sênior”.
- **Prompt do sistema** — instruções extras opcionais, injetadas como uma seção
  “Agent instructions”; elas não substituem o restante do prompt montado.

Clique em **Guardar alterações** na parte inferior do formulário. É esse único
botão que salva todos os campos desta página.

## Dar a ele um adaptador e um modelo

A lista suspensa **Adaptador** mostra os executores que o host do servidor
realmente tem. O adaptador integrado é sempre encontrado (ele é o servidor). O
Claude Code só aparece quando a CLI dele foi detectada nesse host:

| Adaptador                 | Backend                                     |
| ------------------------- | ------------------------------------------- |
| Control Center (built-in) | O loop de agente no mesmo processo — sem CLI externa |
| Claude Code               | `claude -p --output-format stream-json`     |

Só o adaptador integrado aplica modos, direcionamento, pausa/retomada, contratos
de conclusão e subagentes. O Claude Code não oferece nada disso. Cursor, Codex e
os demais provedores de modelos se conectam ao adaptador integrado, e não como
executores separados.

:::note[Um adaptador vazio significa o loop integrado]
Um agente sem adaptador definido é despachado para
**Control Center (built-in)**, o loop dentro do servidor, então nada precisa ser
instalado no host. Sem modelo definido também, ele pede à Anthropic o modelo
padrão dela, de modo que um agente totalmente não configurado só é executado se
você tiver conectado uma conta Anthropic. Os especialistas semeados vêm sem um e
sem outro; defina os dois em qualquer agente que você pretende usar.
:::

A lista suspensa **Modelo** é determinada pelo adaptador que você escolheu. No
caso do adaptador integrado, a lista vem em tempo real dos provedores que você
conectou em **Configurações → Servidor → Provedores de modelos**, então um
provedor sem credencial armazenada contribui com zero modelos.

## Adicionar skills

**Habilidades** é um seletor de chips sobre os pacotes de skills instalados neste
espaço de trabalho. Toque em um chip para alterná-lo; o glifo de verificação
marca os selecionados. Se o espaço de trabalho não tiver skills, o campo exibe
“No skills available. Create skills in Settings → Skills first.”

Você não escolhe aqui as skills do próprio repo. Um repo que as inclua (em
`.agents/skills/`, `.claude/skills/` ou `.opencode/skills/`) as fornece
automaticamente ao agente que estiver trabalhando nele, e elas são trocadas
quando ele passa para outro — consulte [Skills com escopo de
repo](/pt-BR/manual/conceitos/modelo-de-agentes/#repo-scoped-skills).

## Definir a linha de reporte e a persona

- **Reporta-se a** — escolha outro agente pelo nome. Isso monta a árvore de
  reporte exibida pelo botão **Organograma** no cabeçalho da página. Não é a lista
  que um líder de equipe usa quando delega — essa vem dos membros da equipe e das
  skills deles.
- **Persona** — texto livre que molda o tom e o comportamento, por exemplo:
  “Prefere soluções simples e legíveis. Escreve testes para todo código novo.”

## Ajustar a execução

- **Esforço de raciocínio** — as opções vêm dos níveis publicados pelo próprio
  modelo selecionado: Low / Medium / High, além de Extra High nos modelos no
  estilo OpenAI e Extra High + Max nos no estilo Claude. O campo fica totalmente
  oculto quando o modelo selecionado não declara níveis de pensamento e assume o
  padrão do próprio modelo.
- **Tamanho da janela de contexto** — preenchido com a janela de contexto do
  modelo sempre que você troca de modelo, com chips de um toque para o padrão do
  modelo, 200k, 500k e 1M. Um valor que você digitar depois de escolher o modelo
  prevalece até a próxima troca de modelo.
- **Tempo de silêncio (minutos)** — encerra uma execução depois desse tempo sem
  saída. Deixe vazio para usar o padrão de cada modo.

## Conceder permissões

Um agente não tem interruptores de permissão próprios. O que ele pode enviar,
abrir, mesclar ou alcançar é definido pelas regras de ação em **Configurações →
Espaço de trabalho → Permissões dos agentes**, onde uma regra pode ser limitada a
este agente. Por padrão, um push, um pull request, uma revisão ou merge e uma
escrita em um rastreador perguntam a você primeiro, cada um, e o acesso à rede é
permitido.

O token do GitHub do agente é sempre somente leitura. Um push passa pelo Control
Center, que pergunta à regra **Fazer push para um remoto** antes de encaminhá-lo.
Consulte [Configurar políticas de sandbox](/pt-BR/manual/guias/politicas-de-sandbox/) para
ver como cada regra chega a uma execução.

:::note[As regras e o sandbox do sistema operacional são camadas separadas]
As regras decidem o que um agente pode fazer; o sandbox do sistema operacional
limita onde os processos dele podem ler, escrever e se conectar. O `cc_server`
envolve as execuções dos agentes no sandbox do host onde ele existe — o Windows
não tem backend nativo, e o Linux e o WSL2 precisam de `bwrap` e `socat`.
Consulte [Sandbox e segurança](/pt-BR/manual/conceitos/sandbox-e-seguranca/) para ver o
conjunto completo de fronteiras.
:::

## Verificar se ele é executado

1. Abra **Configurações → Servidor → Provedores de modelos** e confirme que o
   adaptador escolhido informa uma versão instalada em vez de “Não encontrado”.
   Clique em **Atualizar** para testar de novo — o teste é executado na máquina que
   hospeda o `cc_server`, e não na máquina que você está vendo.
2. Abra um espaço com o agente e envie uma mensagem, ou mencione-o com @ em um
   espaço existente.
3. Volte a **Configurações → Espaço de trabalho → Agentes**, selecione o agente e
   abra a aba **Registros**. Uma execução deve aparecer com um selo de status, uma
   duração, um horário de início e o adaptador usado. **Visualizar** abre o fluxo
   de eventos dessa execução.

Se nenhuma execução aparecer, siga [Diagnosticar um
agente](/pt-BR/manual/guias/diagnosticar-agente/).

## Excluir um agente

Selecione-o na lista. Na aba **Configurações**, role até a **Zona de perigo** na
parte inferior do formulário e clique em **Excluir**.
