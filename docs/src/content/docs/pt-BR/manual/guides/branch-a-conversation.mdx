Este guia mostra como voltar a um ponto anterior de uma conversa e levá-la para outro lugar — mantendo o caminho que você deixou.

## A única coisa que vale saber

**Criar um branch não grava nada.** Uma conversa é uma árvore de mensagens com um ponteiro na ponta, e voltar apenas move o ponteiro. Nada é excluído, nada fica oculto, e voltar é só mais um movimento do ponteiro.

É por isso que editar um prompt e executar de novo é seguro aqui: a resposta com que você estava comparando continua lá.

## Ver os branches

```
/tree
```

O navegador lista cada mensagem, indentada em cada bifurcação, com o caminho atual marcado como **Neste ramo**. Uma conversa que nunca foi bifurcada é exibida como a lista simples de sempre — olhar o navegador não custa nada enquanto não houver algo para navegar.

Cada linha oferece duas ações.

| Ação                            | Efeito                                                    |
| ------------------------------- | --------------------------------------------------------- |
| **Continuar a partir daqui**    | Move o ponteiro. Sua próxima mensagem continua a partir dessa mensagem. |
| **Bifurcar numa nova conversa** | Copia o caminho até essa mensagem para uma nova conversa. |

## Branch: experimentar outra abordagem

1. `/tree`
2. Encontre a mensagem a partir da qual você quer começar de novo — normalmente a última com que você ficou satisfeito.
3. **Continuar a partir daqui.**
4. Digite o novo prompt.

A continuação antiga continua na árvore; agora o `/tree` mostra dois caminhos a partir desse ponto, e você pode alternar entre eles à vontade.

:::note[O caminho que você deixou continua lá]
Criar um branch não oculta nem exclui nada. O `/tree` lista cada caminho, marca o atual como **Neste ramo** e é assim que você alterna.
:::

## Bifurcar: levar para outro lugar

Bifurcar copia o caminho para uma **nova conversa** no mesmo espaço. Use isso quando as duas direções forem continuar divergindo e você quiser vê-las lado a lado, em vez de ficar alternando.

A cópia tem ids de mensagem novos. Duas conversas que compartilhassem linhas mostrariam as mensagens posteriores uma da outra, que é exatamente o que uma bifurcação deve evitar.

## Reverter versus criar um branch

São ferramentas diferentes, e a diferença importa.

|                     | Reverter                                           | Branch                          |
| ------------------- | -------------------------------------------------- | ------------------------------- |
| As mensagens posteriores | Ocultas da transcrição                        | Ainda visíveis em `/tree`        |
| O **worktree**      | Revertido para o instantâneo desse turno             | Intocado                        |
| Desfazer            | **Desfazer reversão** restaura o lote                | Mover o ponteiro de volta        |

Reverter é o que você quer quando o agente alterou *arquivos* que você quer de volta. Criar um branch é o que você quer quando a conversa tomou o rumo errado, mas os arquivos estão bons.

Reverter também move a ponta do branch, de modo que sua próxima mensagem continua do lugar certo, e não de uma cauda que ninguém mais consegue ver.

## Tirar do aplicativo

### `/export`

Grava um **arquivo HTML autocontido**: a conversa inteira, com cards de ferramentas recolhíveis mostrando o que cada chamada recebeu e o que retornou. Sem folha de estilo, sem script, sem host de imagens — funciona a partir de um pendrive e continua funcionando daqui a cinco anos.

- **Desktop:** `Documents/ControlCenter/exports/`, com carimbo de data e hora para que uma segunda exportação não sobrescreva a primeira.
- **Web:** um download do navegador.

### `/dump`

Copia a transcrição para a área de transferência como markdown, com as chamadas de ferramentas em blocos recolhíveis. É esta que você deve colar em uma issue.

O raciocínio é deixado de fora de propósito: é o espaço de rascunho do modelo, e um relatório de bug é lido por uma pessoa.
