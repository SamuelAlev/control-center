Este guia mostra como conectar provedores de modelos e escolher em que um agente
é executado.

Tudo aqui fica em uma única página: **Configurações → Servidor → Provedores de
modelos**. A entrada da sub-barra lateral se chama "Provedores de modelos"; o
título da página se chama "Adaptadores".

## O que é um adaptador

Um adaptador é o _executor_ que executa um turno de agente. Existem dois e a
lista é fixa — você não pode adicionar um terceiro.

| Adaptador                 | CLI      | Transporte                                                    |
| ------------------------- | -------- | ------------------------------------------------------------- |
| Control Center (built-in) | nenhuma  | Loop de agente no mesmo processo, que fala com os provedores via HTTP |
| Claude Code               | `claude` | `claude -p --output-format stream-json`                       |

Cursor, Codex, Anthropic, OpenAI e o restante são **provedores** do adaptador
integrado, e não CLIs separadas. O que você _pode_ adicionar é outro provedor —
qualquer endpoint compatível com OpenAI ou com Anthropic. É o assunto da próxima
seção.

:::note[A detecção sonda o servidor, não a sua máquina]
O cartão **Executores detectados** lista o que o `cc_server` encontrou no `PATH`
do _host do servidor_. Em um cliente leve ou web, essa é uma máquina diferente
da que você está usando. Instale a CLI na máquina que executa o `cc_server`.
:::

## Conectar um provedor de modelos

O adaptador integrado precisa de pelo menos um provedor conectado antes de poder
ser executado. O catálogo traz quatorze.

1. Vá em **Configurações → Servidor → Provedores de modelos**
2. Role até **Provedores e modelos**
3. Encontre o seu provedor e conecte-o:

| Provedor                                                                                                 | Como conectar                                                                                                                 |
| -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Anthropic                                                                                                | Chave de API. Uma assinatura Claude Pro/Max não é um login da API da Anthropic — use o adaptador Claude Code para esse plano  |
| OpenAI, Codex, Cursor                                                                                    | Login OAuth pelo navegador, ou uma chave de API. O Codex é o ChatGPT Plus/Pro via backend Codex Responses, não um processo da CLI |
| Kimi Code                                                                                                | Somente OAuth pelo navegador — um fluxo por código de dispositivo. É um plano de tarifa fixa, então não tem preço por token   |
| OpenRouter, Groq, Google Gemini, DeepSeek, Mistral, xAI, z.ai, z.ai GLM Coding Plan, Moonshot (Kimi API) | Chave de API                                                                                                                  |

Ponto de verificação: o selo da linha muda para conectado e, ao expandi-la, ela
lista os modelos que esse provedor atende, cada um com o preço por milhão de
tokens e a janela de contexto.

Os tokens de OAuth ficam no armazenamento de credenciais do próprio servidor e
são renovados antes de expirarem. As credenciais dos provedores são **globais ao
host** — são compartilhadas por todos os espaços de trabalho da instalação, e não
restritas a um deles.

### Adicionar um provedor personalizado

Use isto para Ollama, LM Studio, vLLM ou uma implantação privada.

1. Em **Provedores e modelos**, sob **Fornecedores personalizados**, pressione
   **Adicionar fornecedor**
2. Preencha um **nome**, escolha o **Tipo de API** (compatível com OpenAI ou com
   Anthropic) e informe a **URL base** (por exemplo `http://localhost:11434/v1`)
3. Adicione uma **Chave de API** se o endpoint precisar de uma e pressione
   **Adicionar fornecedor**

Um provedor personalizado aparece na mesma lista, com um botão de exclusão que os
seus equivalentes integrados não têm.

## Escolher um modelo para um agente

1. Vá em **Configurações → Espaço de trabalho → Agentes** e selecione o agente
2. Na aba **Configurações**, escolha o **adaptador**
3. Escolha o **modelo** na lista suspensa ao lado

Para o adaptador integrado, a lista suspensa é montada em tempo real a partir do
catálogo de cada provedor conectado. Um provedor sem credencial armazenada
contribui com zero modelos: é por isso que uma lista suspensa vazia quase sempre
significa "nada conectado ainda", e não "nada disponível".

:::note[models.dev é enriquecimento, nunca uma fonte de ids]
O catálogo [models.dev](https://models.dev) incluído fornece preço e janela de
contexto para um modelo que já está na lista em tempo real. Ele nunca adiciona um
id de modelo. Se um modelo que você espera está faltando, o endpoint do provedor
não o está retornando.
:::

Os ids de modelo do adaptador integrado são qualificados como `provider/model` e
podem trazer uma cadeia de fallback separada por `|`. Em um fallback, o custo é
calculado com base no modelo que de fato atendeu o turno, e não no que você
pediu.

:::note[Um agente sem adaptador é executado no loop integrado]
Cada espaço de trabalho cria cinco agentes — um CEO e mais `qa`, `architect`,
`engineer` e `librarian` — sem adaptador e sem modelo. O despacho recorre a
**Control Center (built-in)**, e não à configuração **Executores padrão** desta
página, que é uma preferência do cliente que o caminho de despacho nunca lê. O
log de execução registra `cc-harness` para essas execuções, de modo que a
transcrição nomeia o que realmente foi executado.

Sem modelo também, o loop integrado pede à Anthropic o modelo padrão dela. Um
agente totalmente não configurado, portanto, é executado se você tiver conectado
uma conta Anthropic; caso contrário, falha com
`No credential for provider "anthropic"`.

Concluir a etapa de adaptador da configuração inicial aplica retroativamente a
**todos** os agentes que ainda não têm adaptador nem modelo — CEO e
especialistas, em cada espaço de trabalho existente naquele momento — o par que
você escolheu. Espaços de trabalho criados depois ainda inicializam os cinco sem
configuração. Defina o adaptador e o modelo explicitamente em cada agente que
você pretende usar.
:::

## Instalar a CLI de um executor

O adaptador integrado não precisa de instalação. Para o Claude Code, instale a
CLI dele **no host do servidor** com o gerenciador de pacotes da própria
ferramenta, por exemplo:

```bash
npm install -g @anthropic-ai/claude-code
```

Depois, pressione **Atualizar** no topo da página. Cada linha detectada mostra a
versão e o caminho resolvidos, além de chips indicando se ele oferece suporte ao
modo JSON e à seleção de modelo.

Uma CLI externa mantém as próprias credenciais, na própria configuração, no host
do servidor. O Control Center não as gerencia.

:::caution[Argumentos e variáveis de ambiente do adaptador ficam neste dispositivo]
Cada linha de adaptador oferece um campo **Argumentos** e uma caixa de diálogo
**Variáveis de ambiente**. Esses valores são armazenados no seu dispositivo. O
servidor lê o argv e as variáveis de ambiente de inicialização do próprio
armazenamento de configurações. Coloque as chaves dos provedores no servidor
(OAuth ou o campo de chave na página Provedores de modelos), e não nesses dois
campos.
:::

## Restringir quais provedores um espaço de trabalho pode usar

A governança de provedores é por espaço de trabalho e vale a última
correspondência.

1. Em **Provedores e modelos**, desligue o interruptor **Permitir** de uma linha
   de provedor

Isso grava uma instrução `deny` para esse provedor no espaço de trabalho ativo, e
os modelos dele saem do catálogo desse espaço de trabalho. Religar o interruptor
remove a instrução.

## Solução de problemas

### Um executor aparece como não encontrado

- Verifique se a CLI está no `PATH` do **host do servidor**, e não apenas no seu
- Um aplicativo de desktop iniciado pela interface gráfica inicia o servidor com
  um `PATH` mínimo; uma CLI instalada em um caminho que só existe no shell pode
  ficar invisível para ele
- Pressione **Atualizar** depois de instalar

### A lista suspensa de modelos está vazia

- O adaptador é o integrado e nenhum provedor está conectado — conecte um em
  **Provedores e modelos**
- Ou o provedor está conectado, mas foi negado pelo interruptor de governança
  deste espaço de trabalho

### Um modelo é executado, mas o preço aparece como desconhecido

A lista de modelos em tempo real traz o id; o preço e o contexto vêm do
models.dev. Um modelo recém-lançado, ou de um provedor personalizado, ainda não
tem entrada no catálogo.
