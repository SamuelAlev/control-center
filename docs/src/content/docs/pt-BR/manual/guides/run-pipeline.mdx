Este guia aborda como iniciar uma execução à mão. Para acompanhar uma execução,
ler a saída das etapas e se recuperar de uma falha, consulte
[Monitorar execuções de pipeline](/pt-BR/manual/guias/monitorar-pipelines/).

## Iniciar uma execução

1. Clique em **Pipelines** na barra lateral do espaço de trabalho.
2. Pressione **Executar pipeline** no cabeçalho. Você chega ao seletor de
   execuções (`/workspaces/<workspace-id>/pipelines/run`).
3. Escolha um modelo na lista à esquerda. Cada cartão mostra o nome do modelo, a
   descrição e se ele aceita entradas.
4. Preencha o formulário de entradas à direita. Campos obrigatórios bloqueiam o
   botão até que tenham um valor; um modelo sem entradas informa isso.
5. Pressione **Executar pipeline**.

Você chega à página de detalhes da execução, com a cascata de tempos e o canvas
do grafo ao vivo.

## Se a lista à esquerda estiver vazia

O seletor de execuções só mostra um modelo quando **as duas** condições são
verdadeiras:

- O interruptor do modelo está ativado em **Configurações → Espaço de trabalho →
  Modelos de pipeline**.
- **Permitir execução manual** está ativado na caixa de diálogo **Execução
  manual** do editor de modelo — é esse interruptor que cria o gatilho `manual`
  que o seletor de execuções lê.

Oito dos treze modelos integrados vêm desativados: `external_pr_welcome`,
`cross_review`, `ticket_to_pr`, `pr_triage`, `pre_merge_gate`, `release_notes`,
`dep_audit` e `pr_digest`. O motor se recusa a iniciar um modelo desativado,
então ative o interruptor dele antes de procurá-lo aqui.

Não há nenhuma ação **Executar** por modelo na lista de modelos nem botão de
execução dentro do editor — o seletor de execuções é o único ponto de entrada
manual.

## Preencher uma entrada de repositório

Uma entrada do tipo **Repositório** exibe um seletor com os repos registrados do
espaço de trabalho. Ao escolher um, ele preenche `repo_id`,
`repo_local_path`, `repo_full_name` e — quando o repo tem um remoto do GitHub —
`repo_owner` e `repo_name` no payload da execução, para que as etapas a jusante
leiam o que precisarem.

## Acompanhar a execução

A página de detalhes da execução tem três partes: uma faixa de metadados
(horário de início, duração ativa, progresso das etapas, um banner de falha,
**Tentar novamente** e **Excluir**), uma cascata de tempos recolhível com a
duração e o custo de cada etapa e o canvas do grafo. Selecionar um nó abre o
painel de detalhes daquela etapa.

[Monitorar execuções de pipeline](/pt-BR/manual/guias/monitorar-pipelines/) cobre
tudo isso, incluindo como ler uma etapa suspensa e o que fazer quando uma falha.

Toda execução que você inicia pelo app é uma execução real.
