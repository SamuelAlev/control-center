Este guia mostra onde fica armazenada cada credencial usada pelo Control Center
e como alterá-la.

**Nada é armazenado na máquina em que você está digitando.** Todas as
credenciais ficam no servidor; qual delas responde a uma determinada requisição
depende de haver uma pessoa por trás dela ou não.

| Credencial                                   | Armazenada em                                                        | Quem a usa                                                                        |
| -------------------------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Seu login de forge / tickets                 | O arquivo de segredos 0600 do servidor, indexado pelo seu id de usuário | Tudo o que você faz: a superfície de PR, as revisões, os merges, as suas ações no Linear |
| Os apps de provedor do servidor              | O mesmo arquivo, mais `server_settings` para o que não é segredo      | Fazer o login das pessoas e emitir tokens de um único repositório para agentes, pipelines e polling |
| A chave de instalação do Connect             | O mesmo arquivo (`connect_install_key`)                               | Identificar este servidor perante o Control Center Connect                        |
| Chaves de provedores de modelos e tokens OAuth | O armazenamento de credenciais do próprio servidor                  | O adaptador integrado, para todos os espaços de trabalho da instalação             |
| Credenciais de bot do Slack                  | `<dataDir>/<workspaceId>/chat_credentials/` no servidor              | A ponte de chat daquele espaço de trabalho: os tokens do seu próprio app, ou a concessão selada do app compartilhado |
| Credenciais de CLIs externas                 | O que essa CLI usar                                                   | Claude Code, no host do servidor                                                  |

## GitHub: o seu login e tokens de um único repositório

- **O seu**, obtido com **Entrar no GitHub**. É ele que todas as requisições
  feitas *em seu nome* usam, então uma revisão publicada por você carrega o seu
  nome. Outro membro não consegue usá-lo, e cada um entra por conta própria. Não
  há nenhum token do GitHub para colar
- **O trabalho sem ninguém digitando** (agentes, pipelines, polling, respostas
  do bot) recebe um token para um repositório de cada vez, emitido a partir do
  GitHub App do servidor ou pelo Control Center Connect, e limitado ao que um
  membro responsável pode fazer ali. Nunca é o seu login entregue por inteiro

O seu é definido no cartão **Hospedagem de código** em **Configurações → Você → Perfil**; o app do servidor, em **Apps do
fornecedor**, em **Configurações → Servidor → Início de sessão único**. Consulte
[Configurar a integração com o GitHub](/pt-BR/manual/guias/integracao-github/)
e [Criar o GitHub App](/pt-BR/manual/guias/github-app/).

O GitLab e o Bitbucket continuam aceitando um token pessoal colado, armazenado
da mesma forma. Consulte
[Conectar um host de código](/pt-BR/manual/guias/conectar-host-de-codigo/).

:::note[Também existe uma tela que só aceita URL]
`/workspaces/<workspaceId>/api-keys` renderiza os mesmos cartões do
primeiro passo do onboarding. Ela **não tem entrada de navegação em lugar
nenhum da interface**; só dá para chegar até ela digitando a URL. Prefira
**Configurações → Você → Perfil** para os seus próprios logins, e
**Configurações → Espaço de trabalho → Integrações** para o fornecedor de tickets.
:::

## Definir chaves de provedores de modelos

O adaptador integrado autentica os provedores por conta própria, e essas
credenciais ficam no servidor.

1. Acesse **Configurações → Servidor → Provedores de modelos**
2. Role até **Provedores e modelos**
3. Conecte o provedor — OAuth no navegador para OpenAI, Codex, Cursor e Kimi
   Code; uma chave de API para Anthropic e os demais

Consulte [Gerenciar adaptadores e modelos](/pt-BR/manual/guias/adaptadores/)
para ver a lista completa e para adicionar um endpoint personalizado.

Essas credenciais são **globais do host**: uma única chave atende todos os
espaços de trabalho da instalação. Os tokens OAuth são renovados antes de
expirarem.

O Claude Code entra por meio de **Contas do Claude Code** em **Configurações → Servidor → Provedores de modelos**: cada conta recebe o próprio diretório de configuração no servidor, e você executa lá o comando `claude auth login` que o app mostra.

A caixa de diálogo **Variáveis de ambiente** de cada adaptador parece um lugar
para colocar a chave de um deles, mas não é: ela grava no seu dispositivo,
enquanto o servidor lê a própria cópia e nada liga as duas. Consulte
[Gerenciar adaptadores e modelos](/pt-BR/manual/guias/adaptadores/).

## Conectar um fornecedor de tickets

O cartão **Tickets** em **Configurações → Espaço de trabalho → Integrações** reúne o lado do
espaço de trabalho: em qual fornecedor ficam seus tickets e quem
o Control Center é quando trabalha lá por conta própria. Escolher **Local** oculta as linhas do
Linear — os tickets locais ficam no banco de dados do próprio servidor e não há
nada a autenticar.

O Linear tem dois logins e nenhuma chave para colar: **Linear** é o seu, para o
que você faz, e fica em **Configurações → Você → Perfil**; **Automação do Linear** é o app do Control Center do espaço de
trabalho, conectado por um administrador no cartão **Tickets**, para a sincronização de tickets, os
pipelines e os agentes. O servidor também pode ter uma **Chave de API de
serviço** (**Apps do fornecedor**) para os espaços de trabalho sem a automação
conectada. Nenhuma credencial de tickets é injetada no sandbox de um agente; os
agentes escrevem tickets pelas ferramentas do Control Center, que perguntam à
regra **Escrever em um rastreador externo**. Consulte [Configurar a
integração com o Linear](/pt-BR/manual/guias/integracao-linear/).

## Rotacionar ou revogar

- **Seu login no GitHub**: clique em **Desconectar** e depois em
  **Entrar no GitHub** de novo. Desconectar também derruba todos os tokens que o
  servidor emitiu em seu nome
- **Um token do GitLab ou do Bitbucket**: clique em **Atualizar token**, cole o
  novo e depois revogue o antigo na forge
- **O app do servidor**: gere uma nova chave privada ou um novo client secret na
  página do app no provedor, cole em **Apps do fornecedor** e clique em
  **Testar**
- **A chave de instalação do Connect**: o proprietário do servidor clica em
  **Trocar a chave** no cartão **Control Center Connect**. Todo mundo que
  entrou pelo Connect precisa entrar de novo. Se um servidor do Connect não
  puder ser acessado, nada muda e é oferecido o botão **Rotacionar mesmo
  assim**. Consulte [Trocar a chave de instalação](/pt-BR/manual/referencia/connect/#trocar-a-chave-de-instalação)
- **Um provedor de modelos**: na linha dele, saia (OAuth) ou remova a chave e
  conecte de novo
- **Slack**: no caso do seu próprio app, cole os tokens novamente na caixa de
  diálogo de conexão. O app compartilhado do Control Center não tem token para
  rotacionar: o token de bot dele é renovado pelo Connect, e **Desconectar** o
  revoga e desinstala o bot do Slack. Consulte
  [Configurar a integração com o Slack](/pt-BR/manual/guias/integracao-slack/)

## Solução de problemas

### Um token do GitLab ou do Bitbucket funciona no `curl`, mas não aqui

Confira a linha **Hospedagem de código**. Se ela indicar "Não conectado" ou pedir
para conectar de novo, o seu token não foi salvo ou foi recusado. No Bitbucket,
informe o e-mail da sua conta Atlassian junto com o token de API.

### Um token do GitLab ou do Bitbucket é aceito, mas as requisições seguintes falham

O token é verificado conforme está armazenado, então a linha mostra a conta por
trás dele — mas apenas a conta, não os escopos. Um token com escopos de menos se
conecta e depois falha em requisições individuais. Confira os escopos e a
expiração dele na forge.

### Um provedor diz que o login não está configurado neste servidor

O servidor não tem nem um app próprio para esse provedor nem o Control Center
Connect. O proprietário do servidor escolhe um dos dois em
**Configurações → Servidor → Início de sessão único**.
