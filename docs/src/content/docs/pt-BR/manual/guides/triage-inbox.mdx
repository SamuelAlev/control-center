Este guia mostra como trabalhar na caixa de entrada: a superfície única que
reúne tudo o que bloqueia você ou pede você explicitamente — aprovações de
agentes pendentes, sincronizações de tickets com falha e toda pull request que
envolve você como revisor ou autor.

## Abrir a caixa de entrada

1. Clique em **Caixa de entrada** na barra lateral. O badge dela conta as
   aprovações de agentes pendentes, as sincronizações com falha e as PRs
   abertas aguardando sua revisão.
2. Ou pressione <kbd>⌘K</kbd> e execute o comando de navegação **Caixa de
   entrada**.
3. Ou acesse direto por deep link: `/workspaces/<workspace-id>/inbox`.

A entrada na barra lateral sempre mostra a contagem ao vivo, para você ver o
trabalho de triagem se acumular sem abrir a página.

## Ler a gravidade de relance

Percorra de cima para baixo; a caixa de entrada já está ordenada por urgência:

1. A faixa fixada **Precisa da sua atenção** fica acima das seções de PR. Cada
   cartão traz um chip de gravidade. Fontes registradas (um agente parado em um
   prompt de confirmação, uma sincronização de tickets cujo espelho do
   fornecedor está desatualizado) emitem **Bloqueado**.
2. Dentro da faixa, a gravidade mais urgente vem primeiro; em caso de empate,
   ganha o item que está esperando há mais tempo.
3. Abaixo da faixa, as PRs são agrupadas em seções fixas do ciclo de vida de
   revisão — **Aguardando sua revisão**, **Devolvidas a você**, **Aprovadas**,
   **Rascunhos**, **Aguardando revisores**, **Em merge e mescladas
   recentemente**, **Aguardando o autor**. As primeiras seções são o que precisa
   de _você_; o resto mostra onde estão _suas_ PRs. **Aguardando sua revisão**
   inclui PRs que ainda pedem uma equipe à qual você pertence, nos forges que
   têm equipes (o GitHub remove a equipe assim que qualquer colega revisa).

Um item só cai na caixa de entrada quando bloqueia algo ou pede você
explicitamente. Uma faixa vazia somada a uma lista de seções vazia só mostra
**Você está em dia** quando esse vazio é confiável.

## Uma caixa de entrada, todos os forges

Se o espaço de trabalho tem repos em mais de uma hospedagem de código, a caixa
de entrada os mescla em um único fluxo — uma pull request do GitHub e uma pull
request do Bitbucket ficam na mesma seção, ordenadas por horário em vez de
agrupadas por fornecedor. O metadado `repo #number` da linha é o que permite
distingui-las.

O conceito de "suas" é resolvido **por forge**, porque você é uma conta
diferente em cada um. Uma pull request só conta como sua, ou como solicitando
sua revisão, quando corresponde à sua identidade no forge em que esse repo
realmente está.

Um forge fora do ar ou não conectado não contribui com nada e deixa o resto da
caixa de entrada intacto — uma conexão quebrada nunca esvazia a lista inteira. O
estado vazio aponta uma ressalva em vez de **Você está em dia** quando todos os
logins de forge ainda estão sem resolução (**Não foi possível confirmar sua
conta do GitHub** — o texto ainda cita o GitHub), quando o githubstatus.com
relata um incidente ou quando uma instalação do GitHub App que cobre repos
vinculados está suspensa.

## Limpar a faixa de atenção

Cada cartão da faixa tem uma única próxima ação:

1. Se o cartão for uma confirmação de agente pendente, clique em **Revisar** —
   você vai para o espaço desse agente com a confirmação pendente dele. Aprove
   ou rejeite por lá (consulte
   [Conversar com um agente](/pt-BR/manual/guias/conversar-com-agente/)).
2. Se um cartão disser **Falha na sincronização** para um fornecedor, clique em
   **Abrir** — você vai para **Configurações → Espaço de trabalho → Geral**,
   cujo cartão **Estado da sincronização** mostra a última sincronização de cada
   conexão, a sequência de falhas consecutivas e o último resultado. Só a falha
   mais recente por fornecedor aparece na caixa de entrada, então uma
   sincronização recuperada limpa o cartão.
3. Os cartões desaparecem sozinhos quando o estado subjacente se resolve (o
   agente é respondido, a sincronização se recupera) — não há nada para
   dispensar manualmente.

:::note[Estas são confirmações por turno, não aprovações de governança]
Um cartão de "aprovação de agente" é um agente em execução que pausa para pedir
permissão para uma ação, na própria conversa dele. É uma coisa diferente do
registro `Approval` de governança que os agentes criam com as ferramentas MCP de
aprovação — esses não têm nenhuma tela humana em lugar algum do app e nunca
aparecem aqui.
:::

:::caution[O Estado da sincronização é somente leitura]
O cartão informa sobre as conexões de sincronização de tickets; além de um botão
**Sincronizar**, ele não consegue criar, editar nem reconectar uma conexão, e
não há outra tela que consiga. Sem nenhuma conexão configurada, ele simplesmente
mostra "Ainda sem conexões de sincronização", que é o que um espaço de trabalho
novo exibe.
:::

## Filtrar para o que está bloqueando

1. Pressione <kbd>f</kbd> (com nenhum campo de texto em foco) para abrir o menu
   de filtros, ou clique no botão de filtro na barra de ferramentas.
2. Escolha qualquer combinação de status, autor, revisores, conteúdo,
   proprietário/nome do repo, janelas de data ou rápido de revisar. As
   contagens de facetas no menu mostram com quantos itens da caixa de entrada
   cada opção corresponde.
3. Os filtros ativos aparecem como chips na barra acima da lista; clique no ✕ de
   um chip para remover esse critério.
4. Use a barra lateral esquerda para pular entre as seções — cada entrada mostra
   a contagem ao vivo, e o destaque acompanha a sua posição de rolagem. Clique
   no cabeçalho de uma seção para recolher seções que você não tria (por
   exemplo, **Rascunhos** enquanto limpa revisões).
5. Clique no cabeçalho de uma coluna (título, alterações ou atualizado) para
   ordenar todas as seções; clique na coluna ativa de novo para inverter a
   direção. O botão de opções de exibição controla a visibilidade de rascunhos,
   a janela de mescladas recentemente, as propriedades da linha, a ordenação e o
   agrupamento (só o agrupamento por autor muda o layout da caixa de entrada).

Os filtros aqui são independentes da fila de PRs — restringir a caixa de entrada
nunca muda os filtros da fila, e vice-versa.

## Agir sobre um item de PR

1. Clique em qualquer linha para abrir a página de detalhes da PR.
2. Se a PR estiver em **Aguardando sua revisão**, revise-a e envie sua decisão —
   consulte
   [Revisar e fazer merge de uma PR](/pt-BR/manual/guias/revisar-e-fazer-merge-de-pr/).
3. Se a PR estiver em **Devolvidas a você** (alterações solicitadas ou falha na
   CI), faça push das correções a partir do seu checkout ou entregue o
   acompanhamento a um agente.
4. Se a PR estiver em **Aprovadas**, faça o merge dela na página de detalhes.
5. Se você preferir delegar uma revisão em vez de fazê-la você mesmo, consulte
   [Despachar agentes revisores](/pt-BR/manual/guias/despachar-revisores/) e
   [o ciclo de vida do despacho de agentes](/pt-BR/manual/conceitos/ciclo-de-vida-do-despacho/).

Assim que o estado subjacente muda (sua revisão é registrada, a PR faz merge), o
classificador reclassifica a PR na nova seção dela automaticamente.

## Desfazer uma ação equivocada

1. Pressione <kbd>⌘Z</kbd> para desfazer a última ação, <kbd>⌘⇧Z</kbd> para
   refazê-la.
2. Se um campo de texto estiver em foco, ⌘Z edita o texto do campo — clique fora
   do campo primeiro para desfazer uma ação do app.

## Consultar os atalhos na própria tela

Pressione <kbd>?</kbd> (com nenhum campo de texto em foco) para abrir a folha de
atalhos de teclado. Ela lista todos os atalhos ativos na rota atual, incluindo o
atalho de filtro <kbd>f</kbd> da caixa de entrada. O mapa completo está na
[referência de atalhos de teclado](/pt-BR/manual/referencia/atalhos-de-teclado/).

## Comandar pela paleta de comandos

1. Pressione <kbd>⌘K</kbd> em qualquer lugar para abrir a paleta de comandos.
2. Digite **Caixa de entrada** para pular até a página, ou digite o título de
   uma PR — a paleta lista as pull requests correspondentes e abre a que você
   escolher.
3. Com a caixa de entrada aberta, execute **Copiar link desta página** para
   copiar essa URL e compartilhá-la. O comando copia a rota atual, então ela só é
   a URL da caixa de entrada quando você está nesta página.

## Atualizar sob demanda

A caixa de entrada é atualizada ao vivo, mas, se você suspeitar de dados
desatualizados, clique no controle de atualização na barra de ferramentas — ele
força uma varredura imediata no servidor de todos os forges conectados e busca
de novo os overlays de mescladas/revisadas. O ícone gira até que toda busca seja
concluída.
