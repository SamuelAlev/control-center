代理一般逐一呼叫其工具。每次呼叫都是一個模型回合：代理要求呼叫，結果回傳到其上下文，代理讀取之後才會要求下一次呼叫。對於大部分屬機械性質的工作，例如讀取二十個檔案以找出真正重要的三個，或逐一檢查每張待處理工單是否帶有某個標籤，大部分回合與大部分上下文都耗在代理隨即丟棄的結果上。

程式碼模式只有一個工具，即 `repl`。代理可以用它撰寫一段簡短的 JavaScript 指令碼，呼叫其他工具、迴圈處理、篩選並合併結果，然後只回傳所需內容。一次 `repl` 呼叫便可完成數十個工具回合的工作，而只有指令碼的答案會進入上下文。

只要伺服器能夠運行指令碼，每次執行都會有 `repl`。無需開啟任何設定：請參閱[何時執行會有 `repl`](#何時執行會有-repl)。

## 指令碼可以做甚麼

指令碼是純 JavaScript，寫成非同步函式的主體，因此頂層可以使用 `await` 和 `return`。每次 `repl` 呼叫都會啟動一個全新、空白的直譯器。

- **呼叫工具。** `await tools.read({ path: "README.md" })` 會呼叫一個工具，並解析為其結果；若呼叫失敗或遭拒，則以錯誤拒絕。獨立的呼叫可以透過 `Promise.allSettled` 一併執行。
- **尋找工具。** `ALL_TOOLS` 列出指令碼可以呼叫的每一個工具。`searchTools(query)` 按工具的用途尋找工具，`describeTool(name)` 回傳一個工具的說明及其引數，`describeNamespace(name)` 列出某一組的工具。已連接的 MCP 伺服器的工具也可以用這種方式觸達。
- **回傳結果。** 只有指令碼回傳的內容，或傳給 `text()`、`image()` 或 `console.log()` 的內容，才會回傳給代理。最多四張圖片會傳給模型。
- **保存值。** `store(key, value)` 和 `load(key)` 可在同一對話及同一代理的指令碼之間，保存小型 JSON 值。值只會在指令碼完成時才保存。子代理沒有儲存區。
- **詢問人員。** `await tools.ask_user({ question, options })` 會提出問題並等待答覆。
- **使用裝置上的嵌入。** 當伺服器已安裝嵌入模型時，`models.embed`、`models.rank` 和 `models.classify` 會使用該模型。
- **等待。** `sleep(ms)` 和 `setTimeout` 可在指令碼的時間限制之內使用。`limits()` 會回傳指令碼運行時受到的限制。

指令碼沒有檔案系統、網絡、行程、模組或環境變數的存取權：不能使用 `fetch`、`require`、`import` 或 `process`。唯一的對外途徑是工具呼叫，而每次工具呼叫都會經過與代理直接呼叫時相同的檢查。

指令碼之後失敗時，它先前已完成的工具呼叫不會被撤銷。

## 代理直接呼叫哪些工具

內建代理的每次執行都會取得同一組小型工具，代理以名稱直接呼叫這些工具：

- `repl`，排第一；
- 檔案與 shell 工具 `read`、`write`、`edit`、`search`、`find`、`bash` 及 `read_output`；
- `ask_user` 與 `task`；
- `todo_write`、`search_memory` 及 `send_message`；
- 對話的[模式](/zh-HK/手冊/概念/模式/)為交付其輸出或離開模式所需的動詞，例如計劃模式中的 `submit_plan`；
- `search_tools`，在有工具於首次使用時載入時（見下文）。

其餘可供執行使用的工具，可透過以下兩種方式之一觸達：

- **僅指令碼**：當指令碼可以呼叫它時。代理以 `searchTools()` 或 `describeTool()` 找到它，並以 `tools.<name>(args)` 呼叫它。其說明永遠不會傳給模型，因此不佔用提示的空間。若代理仍直接呼叫它，回覆會告訴它改由指令碼呼叫該工具。若伺服器無法運行該執行的指令碼，它便改為在首次使用時載入（參見[指令碼無法運行時](#指令碼無法運行時)）。
- **首次使用時載入**：當指令碼不可呼叫它時。代理會看到其名稱；以名稱直接呼叫它，或以 `search_tools` 找到它，即會將其載入。

有些工具永遠不能由指令碼呼叫，其中包括 `repl` 本身（指令碼不能啟動指令碼）、`eval`、`task`、`checkpoint`、`rewind`、`vibe_*` 動詞，以及那些會啟動或傳訊息給其他代理執行、建立、就核准作出決定或留言、變更政策或技能，或離開計劃模式的工具。代理會直接呼叫這些工具。

沒有 `repl` 的執行會取得同樣的直接工具，其餘所有工具都在首次使用時載入。[工具上下文與提示快取](/zh-HK/手冊/概念/工具上下文/)解釋了為何兩種情況下這組工具都相同。

程式碼模式永遠不會加入對話模式不允許的工具。模式的工具篩選會先套用，指令碼只能呼叫剩下的工具。

## 何時執行會有 `repl`

當伺服器的指令碼執行器在啟動時通過其鎖定檢查（[指令碼如何受限](#指令碼如何受限)）時，執行便會有 `repl`。任何工作區、代理或伺服器設定都不會改變這一點。以下情況下，執行仍然不會有 `repl`：

- 伺服器所在機器上的執行器無法自行鎖定，伺服器因此完全不運行指令碼；
- 伺服器是公開示範，不運行指令碼；
- 該執行不屬於任何工作區；
- 無法讀取工作區的限制，因為以預設值運行可能超出管理員調低的限制；
- 無法寫入執行的記錄，因為每個指令碼都會在開始前記錄於其執行之下。

此類執行會以直接呼叫的方式呼叫其所有工具。

程式碼模式適用於內建代理的執行，以及透過 Control Center 的 MCP 端點連接其工具的代理，例如 Claude Code。對於 MCP 代理，它接收的工具清單包含 `repl`、直接工具，以及指令碼不可呼叫的工具；其餘工具則由指令碼呼叫。只有由 Control Center 啟動並為其保存記錄的執行，才會在此取得 `repl`；其他任何用戶端都會取得除 `repl` 以外的每一個工具。

**設定 → 工作區 → 程式碼模式** 在 **狀態** 之下顯示此伺服器能否運行指令碼（**可用** 或 **無法使用**，並附上伺服器給出的原因），以及已安裝的 **執行器** 版本。**查看程式碼執行記錄** 會開啟已運行指令碼的清單。

伺服器擁有者不能關閉指令碼。擁有者可以為其設定上限：同時運行的數目，以及單一指令碼可用的記憶體（請參閱[限制](#限制)）。

### 指令碼無法運行時

伺服器無法運行其指令碼時，執行絕不會因此失去任何工具。當伺服器因某個並非任何其他指令碼都能避開的原因而拒絕一個指令碼時（例如指令碼無法使用、指令碼等待空位的時間已用去一半、其記錄無法寫入、該執行的工具清單過大而無法交給指令碼，或執行器無法啟動或無法自行鎖定），該執行直至結束為止都不再使用指令碼：

- 內建代理的執行保留 `repl`，而所有原本只能從指令碼呼叫的工具，現在改為在首次使用時載入：代理以名稱呼叫它，或以 `search_tools` 找到它；
- 在 MCP 端點上的執行，會收到包含所有工具且不含 `repl` 的工具清單，其用戶端亦會獲告知清單已變更。伺服器會記住最近 1,024 個此類執行；較舊的執行會重新改用指令碼。

這些工具與之前一樣，經過相同的模式篩選、護欄與核准，因此沒有任何原本不可呼叫的工具會變得可呼叫。指令碼若因其本身的原因失敗，例如拋出錯誤、達到限制，或某次呼叫遭拒，不會改變任何事情，該執行仍繼續使用指令碼。

伺服器也會持續檢查指令碼能否運行。當執行器因非指令碼本身的原因而無法啟動時，伺服器會重新進行鎖定檢查，但頻率最多為每分鐘一次。若檢查失敗，伺服器便不運行任何指令碼，並記錄與啟動時相同的 `code_mode=unavailable` 行；期間才啟動的執行不會取得 `repl`。它會繼續檢查，同樣最多每分鐘一次；當某次檢查通過時，它會再次運行指令碼，並記錄 `code_mode=available` 行。只有啟動時即告失敗的檢查才需要重新啟動伺服器。

## 限制

每個指令碼都受限制。工作區管理員可以在 **設定 → 工作區 → 程式碼模式** 的 **限制** 下（按 **調整限制**）更改其中六項；代理可以為單一指令碼要求較短的時間或較小的輸出預算，但絕不能要求更多。

| 限制項目 | 預設值 | 範圍 | 耗盡時 |
| --- | --- | --- | --- |
| 每個指令碼的時間 | 5 分鐘 | 1 秒至 25 分鐘 | 指令碼會被停止，並告知代理其時間已用盡。 |
| 處理器時間 | 30 秒 | 1 秒至 2 分鐘 | 指令碼會被停止。 |
| 記憶體 | 256 MiB | 16 MiB 至 1 GiB | 指令碼會被停止。伺服器擁有者可以為整台伺服器設定更低的上限。 |
| 每個指令碼的工具呼叫數 | 500 | 1 至 5,000 | 之後的呼叫會被拒絕，並告知指令碼原因。 |
| 同時呼叫數 | 8 | 1 至 32 | 超過此上限的唯讀呼叫需要輪候。會改變某些東西的呼叫則一律逐一執行。 |
| 代理讀取的輸出 | 10,000 tokens | 100 至 50,000 | 輸出會縮短為開頭和結尾，代理可以按要求讀取其餘部分。 |

指令碼等待人員回應（核准或問題）的時間，不計入其時間限制。等待期間，指令碼不會開始其他工具呼叫：它在等待期間發出的呼叫，會在你作出回應後依次開始。

部分限制是固定的：指令碼原始碼最多 256 KiB，單次工具呼叫的引數 1 MiB 及 16,384 個值，指令碼傳給內建工具、由其執行的命令 16 KiB（工具名稱計入其中），交給指令碼的單一結果 4 MiB，單一儲存值 256 KiB，同一對話及代理所儲存的全部內容合計 1 MiB。一次執行每次只會運行一個指令碼。

指令碼的工具查找同樣有限制：`searchTools` 的查詢最多 1,024 個字元，工具或命名空間名稱最多 256 個字元，最多傳回 50 個結果，且所有查找合計最多 200 次、耗時合計 2 秒（以伺服器時間計）；超過之後，之後的查找都會失敗。同一工作區的所有指令碼共用 2 秒的查找時間，每秒歸還四分之一秒。搜尋索引會平均分配約一百萬個字元給每個工具，先用於其引數名稱，再用於其說明，並且永遠為每個工具的名稱建立索引，因此即使在極大的目錄中，工具仍可按名稱找到。

伺服器擁有者也會限制伺服器上同時運行的指令碼數目（`--code-mode-max-processes`，預設為處理器核心數目的兩倍，最多 16），以及單一指令碼可用的記憶體（`--code-mode-max-heap-mb`）；等待人員的指令碼另行計算，最多為此數目的四倍。當此上限大於一時，單一工作區最多只能佔用其中約四分之三，因此沒有任何單一工作區能佔滿每個位置。一次執行及其子代理合共最多只能使用其工作區位置的一半（至少一個），因此它們的其餘指令碼會等待，而該工作區其他執行的指令碼則照常先行。請參閱[`cc_server` CLI 參考](/zh-HK/手冊/參考/cc-server-cli/#程式碼模式)。

## 核准與提問

指令碼中的工具呼叫，會與直接呼叫一樣經過檢查：模式的工具篩選、[行動護欄](/zh-HK/手冊/概念/護欄/)、核准提示，以及工具本身的檢查。指令碼無法做到代理不能透過直接呼叫該工具而做到的任何事。

當指令碼的呼叫需要核准時，核准卡會顯示 **來自代理正在執行的指令碼**，而 **顯示指令碼** 會在對話中開啟該指令碼。為免指令碼令你收到大量核准卡，會有以下限制：

- 一個指令碼最多可要求核准 10 次，並最多提出 10 個問題；
- 一旦你拒絕其中一個呼叫，該指令碼之後需要核准的呼叫會被拒絕，而不再詢問。

對於內建代理的執行，由指令碼所執行的命令（例如推送（git push））所引發的核准提示，同樣計入同一上限，並在被拒絕一次後以同樣方式停止。當子代理的指令碼與另一指令碼同時運行時，此類核准提示同時計入兩者的上限，拒絕它會令兩者都停止。

在內建代理的執行中，對外部 MCP 伺服器工具的核准不會被記住：每次呼叫都會再次詢問，不論是指令碼還是代理本身發出，除非該空間的自主程度設為**自由行動**。由指令碼引發的每個此類核准提示，都計入該指令碼最多可要求核准 10 次的上限。

若指令碼在你作出回應前結束，核准卡便會被撤回；撤回之後才給出的回應不會核准任何東西。

## 在對話中

一個 `repl` 呼叫在對話中顯示為一行，標題為指令碼的簡短描述。展開後會顯示指令碼及其輸出，以及指令碼所作的工具呼叫，置於 **工具呼叫** 之下，並附上執行中、成功、失敗、遭拒、已取消、已排入佇列與已跳過的數目。

### 指令碼在對話中如何呈現

工具呼叫會按指令碼的寫法排列，而不是排成一長列。執行器會回報每個呼叫發出時的行與欄，應用程式再讀取指令碼，以找出其循環、分支與函數：

- **循環**（`for`、`while`）會顯示為一個 **循環** 群組，標題為其第一行；傳給 `map` 或 `forEach` 等呼叫的回呼，則顯示為一個 **逐項** 群組。當應用程式能夠區分時，一條細線會分隔循環的每一輪。
- 以 `Promise.all`、`Promise.allSettled` 或類似的組合器一同運行的 **並行** 呼叫，會顯示為 **並行** 群組。
- **分支**（`if`/`else`、`switch`、`try`/`catch`）會為每個分支各顯示一個群組，標題為其條件。
- 指令碼定義並呼叫的 **函數**，會顯示為 **函數** 群組。

群組內的群組會再縮進一級，最多八級；更深的群組維持在該縮進上。

每個群組標題都會顯示其呼叫目前已如何結束。在一個呼叫運行前，其列會顯示工具及指令碼中所寫的引數：

| 狀態 | 含義 |
| --- | --- |
| **已排入佇列** | 指令碼尚未執行到此呼叫。 |
| 執行中 | 呼叫正在運行。 |
| 已完成 | 呼叫已結束；此列顯示其結果及所花時間。 |
| **已跳過** | 指令碼略過了此呼叫，例如 `if` 中未被採用的分支，或是指令碼在未到達此處前已結束。 |

寫在同一工具呼叫引數內的呼叫，會報告為與該呼叫相同的位置。當應用程式無法判斷外層呼叫是否已發出時，其列不顯示狀態字詞，而非 **已跳過**。

當一個群組內的呼叫超過八次時，其中間部分會收合：前兩次與後三次保持可見，所有仍在運行、失敗或遭拒的呼叫，連同開始該輪循環的呼叫，也保持可見。每次按下 **再顯示 N 次呼叫** 會多開啟 100 次，並列出隱藏呼叫中最多四個工具的名稱及各自次數，最少見的排在前，例如 **再顯示 12 次呼叫** · Bash 1 · Read 11。工具名稱超過 24 個字元的，會在該按鈕標籤中截短。

應用程式無法將其置於指令碼中的呼叫，例如 `then` 回呼所發出的呼叫，會列在樹狀結構之後，於 **指令碼中未能定位的工具呼叫** 之下。當應用程式無法讀取指令碼，或沒有任何呼叫指明其發出位置時，這些呼叫會以純列表顯示，按其發出的先後排列。

每個呼叫列會顯示呼叫引數與結果的開頭，各最多 8 KiB；一個指令碼的各列合計達到 256 KiB 的摘錄後，其後各列便只顯示工具與呼叫的結束方式。指令碼完成後，**開啟記錄** 會開啟其完整記錄；若找不到該記錄，則改為開啟該次執行中的指令碼清單。若指令碼在運行前已被拒絕（例如同一次執行中另一個指令碼仍在運行），則沒有記錄，也沒有連結。

## 記錄

每個運行的指令碼都會在開始前記錄於其工作區，並在結束時完成記錄。**可觀測性 → 程式碼執行記錄** 會依最新者優先列出它們，並可依結果篩選。記錄中的 **本次執行的指令碼** 與 **此代理的指令碼** 連結，可將清單篩選至單次執行或單一代理。每筆記錄會顯示：

- 指令碼、其輸出及其主控台；
- 開始時間、耗時、所用的處理器時間與記憶體高峰，以及它是透過內建代理還是外部代理運行；
- 結束方式，以淺白文字描述（例如已超時，或引發了無人捕獲的錯誤）；
- 每個工具呼叫，依次列出其結果，包括是否獲准、是否由人員核准或遭拒、人員作出決定所花的時間、其引數（已移除機密，並截短至 8 KiB），以及其結果的大小。結果本身不會保存。

記錄會保存每個呼叫在指令碼中的發出位置，因此其工具呼叫的排列方式與對話中相同。人員核准過的呼叫，在此處絕不會被收合。

仍在運行的指令碼會顯示為運行中，並列出目前已完成的工具呼叫；其輸出、耗時及資源用量會在結束時顯示。若指令碼運行期間伺服器停止，記錄會在伺服器重新啟動時被關閉，並註明此事；在關閉之前，該工作區不會運行任何指令碼。

記錄與其執行一同保存：刪除執行或其空間，便會刪除這些記錄。成員可以看見他們有權開啟的空間之記錄。

## 指令碼如何受限

指令碼從不在伺服器內運行。每個指令碼都在自己的行程中運行，該行程是隨伺服器附送的小型程式 `cc_codemode`，它在 QuickJS-NG 引擎中運行 JavaScript。讀取指令碼之前，該程式會以作業系統本身的控制機制將自己鎖定：在 Linux 上是系統呼叫篩選與資源限制，在 macOS 上是預設拒絕的沙箱設定檔，在 Windows 上是 AppContainer 與作業物件（job object）。之後它便無法開啟檔案、使用網絡、啟動行程，或看見其他程式。它以零個環境變數啟動，也不持有任何憑證；它唯一的通道是伺服器，由伺服器回應其工具呼叫。

伺服器在啟動時會執行該程式的自我測試，以檢查鎖定是否生效。若鎖定在該機器上無法生效（例如在一個安全設定檔拒絕其中某個步驟的容器內），伺服器便在該處不運行任何指令碼：沒有任何執行會取得 `repl`，而設定頁面會以 **無法使用** 顯示原因。指令碼絕不會在較弱的隔離下運行。Windows 的鎖定尚未在 Windows 上實際執行過。

執行器會回報指令碼中每個呼叫的發出位置，因此它只用於排列對話與記錄，絕不決定某個呼叫是否獲准。

有關鎖定涵蓋與不涵蓋的範圍，請參閱[沙箱與保安](/zh-HK/手冊/概念/沙箱與保安/#程式碼模式中的指令碼)。
