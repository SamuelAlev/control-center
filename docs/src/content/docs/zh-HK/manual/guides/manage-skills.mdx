本指南說明如何用 GitHub 上的技能填滿一個工作區：把程式庫新增為來源、從中安裝
你想要的技能，並讓它們隨時間保持最新。你也可以在決定是否保留某個已儲存的修訂
版本之前，先把它與一個相配的基準比較。

開始之前必須知道的一件事：**來源程式庫並不受信任。** 它的名稱、描述與星星數
都由擁有者自行填寫。每次安裝都必須先通過防毒掃描閘門，內容才會到達磁碟或代理
提示。該判定是准入檢查，並非某個技能安全或實用的證明。請閱讀
[代理模型的技能一節](/zh-HK/手冊/概念/代理模型/)了解安裝模型，並閱讀
[評估與質素](/zh-HK/手冊/概念/評估與質素/)了解行為證據與掃描有何分別。

技能位於 **設定 → 工作區 → 技能**
（`/workspaces/<id>/settings/workspace/skills`）。它們以工作區為範圍：你在這裏
安裝的技能只屬於這個工作區。該頁面有兩個分頁：**已安裝**（本機技能，包含一個
**新增技能**編輯器）與**來源**（GitHub 目錄）。兩種寫入都會通過同一道掃描閘門。

## 新增技能程式庫

1. 開啟 **設定 → 工作區 → 技能**，並切換到**來源**分頁。
2. 按**新增程式庫**。
3. 貼上 GitHub 程式庫 URL，例如 `https://github.com/anthropics/skills`，
   然後確認。

伺服器會檢查該程式庫是否存在，以及在它的憑證下是否可見，然後把它加入左側邊欄。
中間並沒有策劃好的商店：任何 GitHub 程式庫都可以，這也意味着信譽要由你自己判斷
——星星數是證據，永遠不是保證。

一個程式庫的技能，就是含有 `SKILL.md` 的目錄（最多三層深，另加 Claude 外掛市集
版面配置 `plugins/<plugin>/skills/<skill>`，並略過依賴與廠商目錄樹）。如果之後格狀
清單顯示該程式庫沒有技能，那就是這個意思：它裏面沒有任何目錄符合技能慣例。

## 安裝前檢視技能

在左側邊欄選取一個程式庫；它的技能會在右邊以格狀清單出現，上方有篩選欄位，可按
名稱、描述或 slug 收窄目錄。點擊卡片即可開啟詳細檢視。它會顯示三項內容：

- **README**，以 markdown 呈現——技能目錄的 `README.md`，若沒有 README，
  則為 `SKILL.md` 的內文。
- **掃描預覽**——判定（`pass`、`warn` 或 `quarantine`）、技能內容所宣告的能力
  （執行 shell、寫入檔案、網絡存取…），以及掃描器記錄的每一項發現項目。
- **檔案數目**——一次安裝會寫入技能的整個目錄，不只是它的 `SKILL.md`。

預覽掃描的正是安裝會寫入的同一批位元組，所以你看到的判定就是安裝會得到的判定；
不會在你背後重新判定任何東西。

## 安裝技能

1. 開啟技能的詳細檢視。
2. 閱讀掃描判定。若判定為 `warn` 或 `pass`，按**安裝**。
3. 若判定為 `quarantine`，安裝會保持停用，直到你勾選
   **我了解風險——仍要安裝**。該覆寫會記錄下來，而不是假設。

安裝會把技能的目錄寫入工作區、在 `skills-lock.json` 中記錄一筆固定資料（來源
程式庫、路徑、它來自哪個提交，以及內容雜湊），之後該技能便可為工作區中的代理
所用。標有**名稱已被使用**的卡片，代表本機已有另一個技能佔用了該名稱——請先
解除安裝那一個。

## 隨時間更新技能

已安裝技能的卡片帶有標記：**已安裝**，或在程式庫已推進到你固定提交之後的版本時
顯示**有可用更新**。開啟詳細檢視並按**更新**，即會依新的提交重新取得。更新會與
安裝一樣通過同一道掃描閘門——新版本被隔離的技能會被拒絕，你原有的版本會保持
不變。舊版本的雜湊會保留在鎖定檔中，作為回滾參照。

## 評估技能

1. 開啟 **設定 → 工作區 → 技能**，選取已安裝的技能並儲存任何修改。在
   **技能評估**中檢查封裝雜湊。
2. 選取**開始評估**。選擇一個與技能用途相配的**任務集**，再選一個**配接器**。
   內建 harness 使用已設定的提供者與支援工具的模型。**Claude Code** 使用預設的
   受管理 Claude 帳戶與具體的模型識別碼；請先在**設定 → 配接器**登入。它不會
   借用伺服器操作者的個人登入。
3. 從下表選擇一種**比較**方式。
4. 設定**每項任務的重複次數**（1–20）與**預算 (美分)**。例如 `100` 代表
   1 美元。選取**開始評估**以授權提供者進行付費工作。
5. 在 **可觀測性 → 品質**追蹤該活動，或透過技能面板中的**開啟品質頁面**返回。

對 Claude Code 與 Codex OAuth 訂閱而言，預算是 **API 等價用量的停止臨界值**，
而不是帳單上限，也不是訂閱配額的度量。`100` 允許 1 美元臨界值：進行中的呼叫
可能超出臨界值，但一旦回報的用量達到臨界值，就不會再啟動新的呼叫。未知用量亦
會停止後續呼叫。預算太小可能使比較不完整；它並不保證完成所選任務集。

使用 API 金鑰的提供者會依成文的權杖限制與定價，保留保守的逐次呼叫預留。當一次
安全預留的呼叫需要更多時，它們可能在花費前就拒絕 `100`。錯誤會指出所選模型與
最低預留；請選擇成本較低的模型或提高該預算。

| 比較 | 用來回答 |
| --- | --- |
| **未提供與可用** | 與沒有此技能相比，正常的探索與使用能否改善結果？ |
| **前一版本與目前版本** | 與先前擷取的修訂版本相比，這次更新是保持還是改善了行為？ |
| **強制載入與未提供** | 內容在被明確載入時能否有所幫助？這是診斷載入問題，並不能證明正常的探索過程。 |
| **組成** | 加入候選技能對已選的環境技能是幫助還是衝突？基準會保留同一份環境技能清單，只是不含候選技能。 |

**前一版本與目前版本**需要來自活動歷程的封裝雜湊。若想把它當作基準，請在取代它
之前先評估該版本；任意的 Git 歷程不會被匯入。

未儲存的修改、無法取得的雜湊，以及唯讀示範模式都會使啟動被停用。伺服器亦會檢查
工作區／程式庫存取權、掃描隔離、動作政策、模型支援、價格與執行隔離。請解決未通過
的檢查，而不是繞過它。提供者與模型的識別會記錄下來，但遠端模型別名並不會凍結
提供者的底層權重。

### 檢視、取消與匯出

結合每項任務的結果與回歸情況來閱讀覆蓋範圍與開支。開啟個別嘗試，以檢視觀察到的
技能載入、工具事件、錯誤與驗證器證據。**不完整**、**已過時**與**無法判定**的
結果並不是採用某個修訂版本的建議。報告的雜湊所識別的是擷取到的封裝，未必是現時
安裝的封裝。

對排隊中或使用中的工作使用**取消執行**。已完成的嘗試仍然可見；取消不會退還提供者
已完成的工作。**複製已遮蔽資訊的 JSON** 會把一份有界的證據匯出複製到剪貼簿，
而不是完整的私有來源重播封裝。有關證據與平台限制，請參閱
[評估與質素](/zh-HK/手冊/概念/評估與質素/)。

### 更新後重新評估

自動付費重新評估**預設為停用**。評估完目前修訂版本後，在**更新政策設定**下選擇
一個活動，然後選取**啟用更新評估**。更改這項政策需要工作區管理員權限。所選活動會
提供任務集、配接器、提供者／模型、比較方式、重複次數與預算。

此後獲准入的內容變更會安排帶預算的工作；雜湊未變的會被去重。**停用更新評估**可阻止
日後的自動准入。對已獲准入的活動使用**取消執行**。歷來的報告仍與其原本的封裝雜湊
綁定；重新評估不會發佈、啟用或改寫某個技能。

## 解除安裝技能、移除程式庫

**解除安裝**（在已安裝技能的詳細檢視上，或在已安裝分頁中刪除）會一併移除技能的
目錄與它在鎖定檔中的固定資料——解除安裝後的技能不會留下任何東西。

從左側邊欄**移除程式庫**只會移除目錄：你從它安裝的技能會保持已安裝，也依然可以
更新，因為固定資料是以名稱記錄程式庫，而不是參照來源項目。若你想再次瀏覽它，
把程式庫重新加回來即可。

## 叫用技能

技能會在各自的命名空間下叫用，因此永遠不會與內建斜線指令（`/plan`、`/goal`、
`/loop`、`/compact`）衝突：

- `/skill:<name>`——安裝在此工作區中的技能，或附加到該代理的技能
- `/skill:<repo>:<name>`——本空間中已檢出的其中一個程式庫所隨附的技能

不加命名空間的非內建名稱仍然可以解析，以兼容命名空間出現之前所寫的訊息。
`/skill:plan` 才會觸達名為 `plan` 的技能；`/plan` 永遠都是內建指令。

## 以程式庫為界的技能

一個已檢出的程式庫可以隨附自己的技能，位置可在 `.agents/skills/`、
`.agent/skills/`、`.claude/skills/`、`.opencode/skills/` 或 `skills/`。那些技能
**不會**透過本頁安裝。代理只會攜帶它目前所在程式庫的技能；當它移動時，這些技能
就會替換。輸入框並不那樣劃分範圍：`/skill:<repo>:<name>` 可以觸達空間中的任何
程式庫。

程式庫技能的前置資料到達提示之前，會先通過同一道失效即拒絕掃描（`pass` / `warn` /
`quarantine`）。`warn` 會放行；`quarantine` 則不會放行，而該路徑上沒有任何操作
人員覆寫。

參見[以程式庫為界的技能](/zh-HK/手冊/概念/代理模型/#以程式庫為界的技能)與
[斜線指令](/zh-HK/手冊/參考/斜線指令/)。
