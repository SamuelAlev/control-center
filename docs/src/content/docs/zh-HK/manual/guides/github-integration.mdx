本指南涵蓋設定中專屬於 GitHub 的部分。GitHub 是三種受支援的程式碼託管平台
之一。連接 GitLab 或 Bitbucket，以及同一個工作區如何混用它們，請參見
[連接程式碼託管](/zh-HK/手冊/操作指南/連接程式碼託管/)。

## 先決條件

- 一個 GitHub 帳戶，且能存取你想處理的程式庫
- 一部能讓人們登入 GitHub 的伺服器：它自己的 GitHub App（參見
  [建立 GitHub App](/zh-HK/手冊/操作指南/github-app/)）或 Control Center Connect，
  由伺服器擁有者在 **設定 → 伺服器 → 單一登入** 中選擇

:::note[憑證存放在伺服器上，並歸屬於你]
你正在輸入的那部機器上不會儲存任何東西。你的 GitHub 登入由你的 `cc_server`
持有，以你的使用者 id 為鍵，你登入的每部裝置都會使用它：桌面端、網頁版和手機。
同一伺服器上的其他成員無法使用它，而為他們登入這件事，得由他們自己完成。
:::

## 登入 GitHub

GitHub 只能登入：沒有可貼上的權杖。

1. 前往 **設定 → 工作區 → 個人資料與身分 → 程式碼託管**（或新手導引的第一步）
2. 在 **GitHub** 一列上，按一下 **登入 GitHub**
3. 你的瀏覽器會開啟 GitHub。批准該應用程式

登入如何完成，取決於由誰執行：

- **伺服器自己的應用程式：** GitHub 會把你的瀏覽器送回伺服器，對話框會自行
  察覺。不需要輸入任何東西
- **Control Center Connect：** 瀏覽器頁面會顯示一個 8 個字元的代碼。把它輸入
  對話框，或讓瀏覽器透過 `control-center://` 連結開啟 Control Center，便不必輸入

檢查點：**GitHub** 一列顯示「已登入為 _your-username_」。

對話框會拒絕不是由它自己發起的代碼或連結，並顯示**登入並非從這裡發起**。如果有人
傳給你一條登入連結，請不要繼續：完成它會把你的帳戶連接到對方的伺服器。

按一下 **中斷連接** 即可移除你的登入。登出 GitHub，或被移出某個工作區，也會令
伺服器代表你簽發的所有權杖一併失效。

## 你的憑證代表誰

- **你做的任何事**（開啟 PR 頁面、發佈審查、批准、合併）都只使用**你的**登入，
  不會用其他任何東西。如果你未登入，應用程式會告訴你並請你登入。沒有任何其他
  憑證會頂替你
- **沒有人在輸入的工作**（代理執行、管線、PR 輪詢、機械人回覆、複製）會取得一個
  只適用於一個程式庫的權杖，由伺服器的 GitHub App 或經由 Connect 簽發。它被限制在
  某位負責成員在那裏能做的事：提出請求的成員，否則是工作區擁有者。無法推送的成員
  會把權杖限制為唯讀
- **自動化永遠不會批准** pull request。批准是人的行為

## 整合為你帶來甚麼

| 功能                 | 運作方式                                                                                                       |
| -------------------- | -------------------------------------------------------------------------------------------------------------- |
| PR 清單與詳情        | 由伺服器以你自己的登入呼叫 GitHub REST API                                                                     |
| 檢查執行             | GitHub Checks API                                                                                              |
| 發佈審查             | 一個需經使用者確認的步驟，會以你的身分把你的審查發佈到 PR                                                      |
| 程式庫註冊           | 只要檢出副本的 `origin` 遠端指向 github.com，或指向 gitlab.com / bitbucket.org，就會被接受                     |
| 代理的 GitHub 存取   | 一個只適用於該次執行那一個程式庫的權杖，作為 `GH_TOKEN` / `GITHUB_TOKEN`；推送經由 Control Center            |
| 通知提示             | 伺服器端輪詢你的 GitHub 通知收件箱，觸發「在 pull request 中被提及」與「已請求審查」                           |
| 使用者個人資料       | 個人資料懸浮卡，以及按作者篩選 PR                                                                              |

部分路徑在更划算的地方會改用 GraphQL API 而非 REST：例如供撰寫 PR 選擇器使用的
分支活動，以及決定某則已請求審查通知是否仍在待處理的即時審查狀態。

## 留意 GitHub 服務中斷

當某個供應商降級時，標題列會顯示一個狀態標籤，涵蓋 GitHub、Claude、OpenAI
和 Kimi。**一切正常時它是隱藏的**：它的出現是在報告問題，而不是報告沒有問題。

按一下該標籤會開啟一個浮出面板，列出每個供應商的狀態，並帶有一個重新整理
按鈕。這些狀態每兩分鐘會自行重新整理。

## 了解代理在 GitHub 上的行為

- 在 GitHub worktree 中工作的代理會取得一個只適用於那一個程式庫的權杖。當負責的
  成員可以推送時，它能讀取程式碼並在 pull request 上評論；成員無法推送時則只能
  讀取。推送會經由 Control Center，它先詢問**推送到遠端**規則，再用代理從不持有
  的寫入權杖轉送推送。參見[設定沙箱政策](/zh-HK/手冊/操作指南/沙箱政策/)
- 代理的提交一律使用提出請求者的 Git 身分作為作者和提交者。預設情況下，`Co-Authored-By: Control Center <hi@usectrl.dev>` 尾註會將 GitHub `@usectrl` 記為共同作者。你可在 **設定 → 你 → 提交署名** 關閉這項共同作者署名，而不改變自己的身分。**設定 → 工作區 → 通用** 的工作區設定優先，並會鎖定個人開關。Claude Code 自帶的署名一律停用。提交簽署仍須另行妥善設定
- 你在測試機上開啟的終端機會取得你自己的登入，並限制到那一個程式庫，因此在那裏
  的推送是你的
- 無法簽發權杖時（沒有任何負責人登入、應用程式沒有安裝在擁有者上，或該安裝已被
  暫停），執行會在沒有權杖的情況下開始，並在其備註中說明原因。沒有任何後備憑證

## 疑難排解

### PR 清單是空的，並顯示 GitHub 尚未連接

你未在這部伺服器上登入 GitHub。請在**程式碼託管**下按一下**登入 GitHub**。其他
託管平台上的程式庫不受影響。

### GitHub 一列表示此伺服器尚未設定登入

伺服器既沒有自己的 GitHub App，也沒有 Connect。由伺服器擁有者在 **設定 → 伺服器
→ 單一登入** 中選擇其一：**建立我的 GitHub 應用程式**約需兩分鐘。參見
[建立 GitHub App](/zh-HK/手冊/操作指南/github-app/)。

### 對話框表示代碼不相符

請完全按照瀏覽器顯示的內容輸入代碼：8 個字母和數字。輸錯五次會結束這次登入；
請重新開始。

### 登入表示應用程式未安裝

GitHub App 在擁有該程式庫的帳戶上沒有任何安裝。由工作區管理員從 **設定 → 工作區
→ 一般 → GitHub 應用程式安裝** 進行安裝。若組織使用的是 Control Center 的共用 App，
可能需要該組織的一位管理員按一下**授權此伺服器**。參見
[建立 GitHub App](/zh-HK/手冊/操作指南/github-app/#為組織授權這部伺服器)。

### 所有人都要重新登入 GitHub

伺服器擁有者輪替了伺服器的 Connect 金鑰、切換了 Connect 伺服器，或資料目錄被還原
到另一部機器上。經由 Connect 的登入會綁定到建立它們的那部伺服器。

### 加入程式庫被拒

註冊需要同時滿足以下三項：路徑位於 git 工作樹內、它有一個 `origin` 遠端，
而且該遠端指向受支援的程式碼託管平台（github.com、gitlab.com 或
bitbucket.org）。參見[將程式庫加入工作區](/zh-HK/手冊/操作指南/加入程式庫/)。

### 大量使用後，一切都會停擺一陣子

那是速率限制的斷路器。GitHub 以帶有 `x-ratelimit-remaining: 0` 的 `403` 及
一個重置時間來表示已達主要限制；用戶端一旦看到，就會在該時窗過去前，令後續
請求在本機失敗，不發出網絡呼叫，因此重試風暴無法加深限制。暫時性失敗會以
指數退避最多重試三次，並遵循 `retry-after`。
