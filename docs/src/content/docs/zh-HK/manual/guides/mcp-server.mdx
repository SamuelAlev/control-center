本指南說明如何把外部 MCP 用戶端——Claude Code、編輯器、MCP Inspector——連接到 Control Center 自己的工具伺服器。

Control Center 註冊了 **110** 個工具，並透過 Model Context Protocol 以協定版本
`2024-11-05` 提供它們。有些你可能預期會有的工具系列完全從缺：沒有會議或日曆工具，也沒有項目工具。

## 找到端點

MCP 介面共用主要的 `cc_server` 監聽器。沒有另外的 MCP 連接埠。

| 端點   | 方法     | 用途                                            |
| ------ | -------- | ----------------------------------------------- |
| `/mcp` | `POST`   | Streamable HTTP 傳輸——用戶端溝通的就是這個      |
| `/mcp` | `DELETE` | 結束工作階段                                    |
| `/sse` | `GET`    | 伺服器推送的通知串流                            |

因此，預設的本機安裝位於 `http://127.0.0.1:9030/mcp`。

1. 前往 **設定 → 伺服器 → MCP 伺服器**
2. 查看 **MCP 伺服器**卡片——它會顯示執行中還是已停止，以及它正在監聽的連接埠

全新安裝時該介面預設為開啟。只有伺服器擁有者能看到卡片上的權杖，也只有他們能啟動或停止端點。**應用程式啟動時開始**決定它在重新啟動後是否再次啟動；**開始** / **停止**是工作階段層級的控制項，不會改變該偏好設定。

伺服器預設繫結回送，因此除非你以 `--bind any` 啟動它，否則只有執行 `cc_server` 的那部機器可以連到該端點。

## 取得權杖

每個請求都需要伺服器的 MCP 權杖，無論來自哪部機器，包括回送。伺服器會在首次啟動時建立它。沒有辦法將它關閉，也沒有辦法清除它。

1. 在 **設定 → 伺服器 → MCP 伺服器**上，找到**驗證權杖**資料列
2. 按**顯示權杖**並複製它
3. 如要替換，請按**輪替權杖**。伺服器會立即切換到新權杖，而所有仍在使用舊權杖的用戶端都會被拒絕，直到你把新權杖交給它們

## 連接用戶端

把你的用戶端指向 Streamable HTTP 端點，並在每個請求上以 `Authorization: Bearer <token>` 傳送權杖，包括 `GET /sse`。除此之外沒有其他傳送方式：URL 中的權杖不被接受。具體的設定形式由你的用戶端決定。

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code 不會從專案的 `.mcp.json` 讀取這份設定——它把專案範圍的 MCP 伺服器擋在一個核准提示之後，而非互動式的 `claude -p` 永遠不會回應這個提示。請明確傳入設定：

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` 讓 Claude 只使用該檔案，這樣同一個伺服器就不會再從專案中被發現並註冊兩次。

檢查點：請用戶端列出它的工具。你應該會看到涵蓋工單、空間、記憶、程式碼圖與審查的 `mcp__*` 項目。

## 端點拒絕甚麼

權杖會開啟伺服器上的每個工具，因此端點也會在查看權杖之前，拒絕任何網頁可能送出的東西：

| 請求 | 回應 |
| --- | --- |
| 並非本機上某個網頁的 `Origin` 標頭（`http://localhost`、`http://127.0.0.1` 或 `http://[::1]`，任何連接埠） | `403`，不接受跨來源請求 |
| `Host` 標頭既不是此監聽器的回送位址與連接埠，也不是伺服器的公開主機名稱 | `403`，未知的主機 |
| 內容不是 `application/json` 的 `POST` | `415` |
| 沒有權杖，或權杖錯誤 | `401` |

如要在主機之外提供 MCP 服務，請以 `--bind any` 啟動伺服器，並從另一部機器傳送權杖，以伺服器的公開主機名稱來定址。

## 把每次呼叫限定到一個工作區

每個涉及工作區範圍資料的工具都要求提供 `workspace_id`，缺少它的呼叫會被拒絕，而不會改為對照某個「目前」工作區來解析：

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

這個 id 就是你瀏覽器或應用程式 URL 中的那個：`/workspaces/<workspace_id>/…`。唯一的豁免是真正跨越工作區的工具，例如 `list_workspaces` 和資訊動態工具——資訊動態是按使用者劃分的，而代理沒有屬於自己的使用者，因此那些工具操作的是伺服器擁有者的動態。

程式庫範圍的工具還會額外檢查該程式庫是否已連結到該工作區。

## 了解介面會拒絕哪些呼叫

- **模式把關。** 呼叫會在伺服器端按發起呼叫的代理所在空間的模式來解析。處於唯讀模式的代理無法藉由省略 `space_id` 來觸達寫入工具——模式會改為從它作用中的執行查找。
- **動作護欄。** 變更類工具會宣告自己的效果類別，並走產品其餘部分所用的同一套政策。參見
  [設定護欄](/zh-HK/手冊/操作指南/設定護欄/)。
- **確認。** 某些具破壞性的工具會建立一份確認載荷，必須先獲得核准，呼叫才能繼續。

完整目錄會在 `tools/list` 中公佈，沒有任何探索層面的把關——外部 MCP 用戶端會拒絕呼叫不在其快取清單中的工具，因此隱藏工具只會把它們弄壞，而不是把它們整理乾淨。

## 個人 MCP 伺服器屬於擁有者

本指南說明的是 Control Center 自己的端點。反方向——Control Center 交給它所運行代理的 MCP 伺服器——列於 **設定 → 伺服器 → MCP 伺服器 → 外部 MCP 伺服器** 之下。設定在伺服器機器上、供 Claude、Codex、Cursor、Gemini、VS Code、Windsurf、OpenCode 或 `.mcp.json` 使用的伺服器，會自動在那裏被發現。

那些被發現的伺服器來自伺服器用戶自己的工具設定，並以該用戶的身分與憑證行事，因此它們屬於伺服器擁有者：

- 它們只在伺服器擁有者啟動或負責的內建 harness 運行中可用，包括擁有者負責的工作區中的自動化。
- 成員的運行、綁定到成員的自動化，以及沒有記錄擁有者的伺服器上的每次運行，都得不到其中任何一個。在那裏，這些工具不會被列出、無法被呼叫，也不會出現在工具搜尋中。
- 此端點對任何人——包括擁有者的權杖在內——都從不列出、呼叫或搜尋它們，也不會轉交它們的資源或提示。因此，透過 MCP 連到 Control Center 的代理 CLI（例如 Claude Code）也無法透過 Control Center 取得它們；它使用自己的設定。

為工作區設定的 MCP 伺服器不受以上任何影響。

## 疑難排解

### 用戶端看不到任何工具

- 檢查 **MCP 伺服器**卡片是否顯示執行中
- 檢查連接埠是否與你的 `cc_server` 連接埠一致
- 在 Claude Code 上，檢查你是否傳入了 `--mcp-config` 和 `--strict-mcp-config`

### 401 Unauthorized

請求沒有附帶權杖，或附帶的是舊權杖。從**驗證權杖**資料列複製目前的權杖，並以 `Authorization: Bearer <token>` 傳送。URL 中的權杖會被忽略。

### 曾經運作的用戶端收到 403

請求帶有來自網頁的 `Origin`，或伺服器不回應的 `Host`。請從用戶端而非瀏覽器頁面呼叫端點，並使用伺服器的回送位址或其公開主機名稱。

### 415 Unsupported Media Type

以 `application/json` 傳送 `POST /mcp` 的內容。

### 工具呼叫失敗並顯示「Missing or invalid argument: workspace_id」

加入 `workspace_id`。並不存在隱含的工作區。

### 工具呼叫因為未知而被拒絕

[MCP 工具](/zh-HK/手冊/參考/mcp-工具/)列出了完整目錄。請完全按照那裏出現的名稱來呼叫。
