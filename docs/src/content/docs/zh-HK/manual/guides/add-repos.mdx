本指南說明如何把 Git 檢出註冊到工作區、重新索引它，之後再將它移除。從伺服器的資料夾新增程式庫需要伺服器擁有者；移除則需要工作區管理員。

程式庫是**以工作區為範圍**的。沒有全域註冊表，也沒有連結步驟：加入程式庫與把它放進工作區，是同一件事。同一個檢出註冊到兩個工作區，會變成兩筆各自獨立、帶有兩個不同 id 的資料列——跨工作區而言，程式庫的身分是它的檔案系統路徑，永遠不是它的 id。

## 開始之前

資料夾只有在同時符合以下三項時才能註冊：

1. 它位於一個 **git 工作樹**內。
2. 該工作樹設有一個 **`origin` 遠端**。
3. 該 `origin` 遠端指向**受支援的程式碼託管平台**：github.com、gitlab.com 或 bitbucket.org。

其他情況一律會在註冊當下被拒絕，並附上明確訊息：「資料夾不在 git 工作樹內。」、「此程式庫未設定 `origin` 遠端。」或「`origin` 遠端未託管於受支援的程式碼託管平台（github.com、gitlab.com、bitbucket.org）。」。沒有僅限本機的模式。

程式碼託管平台是從遠端讀取並存放於程式庫上的——你永遠不需要挑選它。一個工作區可以同時容納來自這三者的程式庫，而每個都會透過各自的 API 與自己的憑證溝通。GitLab 的巢狀命名空間會被保留，因此 `gitlab.com/group/subgroup/project` 註冊後的所有者為 `group/subgroup`，名稱為 `project`。

該資料夾還必須位於承載 `cc_server` 的那部機器上，且在其中一個 `--repo-roots` 目錄之內。該允許清單預設為伺服器使用者的主目錄，而越過某個根目錄向上瀏覽會被拒絕。瀏覽伺服器的資料夾只提供給[伺服器擁有者](/zh-HK/手冊/概念/授權/#伺服器擁有者)，因為它會列出機器本身的檔案。其他人會在 **新增存放庫** 按鈕原本所在之處看到「伺服器擁有者會從伺服器的資料夾中新增存放庫。」；而對於他們的任何工作區都未連結的程式庫連結，則會說明該程式庫並未連結到他們的任何工作區，並請他們詢問伺服器擁有者加入它。

程式庫檢出可以位於何處，取決於誰連結它：

- **伺服器上工作區自己的儲存空間內**：任何工作區管理員。
- **伺服器磁碟上的其他任何位置**：只有[伺服器擁有者](/zh-HK/手冊/概念/授權/#伺服器擁有者)，因為只有他們可以讓伺服器指向機器本身的檔案。其他人會看到「只有伺服器擁有者可以連接位於此工作區儲存空間之外的資料夾。」
- **伺服器的資料資料夾，或其中的任何東西**：永不可以。

檢出的 `origin` 必須是你正在連結的程式庫。`origin` 指向另一個程式庫的資料夾會被拒絕，並顯示「該資料夾的 origin 指向另一個存放庫。」

### 伺服器暫不使用的資料夾

工作區儲存空間之外、且並非由伺服器擁有者連結的資料夾所對應的程式庫（例如已匯入工作區中的程式庫），會在其列下顯示「此資料夾位於工作區儲存空間之外。請確認此伺服器可以使用它。」，直到伺服器擁有者確認為止。其他人則改為看到「此資料夾位於工作區儲存空間之外。只有伺服器擁有者可以確認它。」

擁有者只需確認一次：在該列上按 **確認**，或在清單上方的通知中，當有多個程式庫等待時按 **全部確認**。每一個都會以擁有者身分再次檢查，檢查項目與連結時相同。在確認之前，它會保留在清單中，但不會被開啟、佈建或索引：沒有編輯器、終端機、環境或空間檢出會使用它，而程式碼圖也會略過它。以伺服器擁有者的身分再次加入相同資料夾，效果與確認相同，並會保留該程式庫的 id。

被符號連結移到別處的檢出也一樣處理：它會保持列出但不被使用，直到有權連結它現在所指向之資料夾的人再次連結它為止。

你也需要登入該程式庫的程式碼託管平台，而你自己的帳戶必須能看到該程式庫。

## 註冊檢出

你需要是伺服器擁有者才能進行這些步驟。

1. 開啟 **設定 → 工作區 → 程式庫**（`/workspaces/<id>/settings/workspace/repositories`）。
2. 按一下 **新增存放庫**。

該對話框是一個可導覽的瀏覽器，瀏覽的是**伺服器**的檔案系統，而不是你自己的。桌面端、網頁端與手機端的流程完全相同，因為原生資料夾選取器會在錯誤的機器上選取資料夾。

3. 在伺服器已設定的根目錄範圍內導覽。屬於 git 檢出的資料夾會被標示出來。
4. 勾選任意數量的資料夾。選取狀態會在你導覽期間一直保留，因此你可以從多個資料夾收集檢出。
5. 以單一批次將它們註冊。

單一項目失敗絕不會拖垮批次中的其餘項目——你會取得已建立的 id，以及每個被拒絕項目各自的按路徑錯誤。重新註冊此工作區中已存在的路徑，會傳回現有的程式庫，而不會多建立一個重複項。

每個已註冊的程式庫都會出現在清單中，附有它的 `owner/name`、一個標明其程式碼託管平台的徽章，以及它在伺服器上的路徑。GitHub 程式庫亦會顯示所有者的頭像；其他程式碼託管平台沒有可推測的所有者頭像 URL，因此會退回顯示姓名首字母。

在混合了多個平台的工作區中，程式碼託管平台徽章很重要：兩個程式庫可以在不同平台上都叫 `acme/web`，而它們的行為並不相同——一次審查能做些什麼，以及連結會指向哪裏。

## 接下來會發生什麼

註冊會觸發一個範圍限定於此工作區的 `RepoAdded` 事件，它會為該檢出啟動 `index_code` 管線。正是它填充了程式碼圖，讓搜尋與影響分析有內容可回答。

只有語言已有隨附文法的檔案才會被索引（Dart、JavaScript、TypeScript、TSX、PHP、Python、Rust、Zig、C、C++、Go、Java、Ruby、C#、Swift、Kotlin、R、Assembly、MATLAB 與 Ada）。參見[以程式碼圖搜尋程式碼](/zh-HK/手冊/操作指南/程式碼搜尋/)。

## 重新索引程式庫

每一列都帶有一個 **索引程式碼** 按鈕。按一下它，即可為該檢出重新執行索引器；執行期間，按鈕會變成顯示已完成檔案數對總數的進度讀數，並附有取消控制項。完成後，它會定格成一個帶有符號數量的勾號；若執行失敗，則顯示警告。

## 重新排列程式庫

拖曳某一列上的控點。你設定的順序，就是應用程式內每個程式庫清單讀回時所依循的順序。

## 修正 GitHub 連結

某一列上的連結圖示會開啟一個編輯器，用來編輯該程式庫的 GitHub 所有者與程式庫名稱。

你很少需要它。連結綁定在程式碼託管平台上程式庫的永久 id 上，因此重新命名或轉移會被自動跟隨。

- 在 Control Center 中重新命名程式庫，只會更改它的顯示名稱。
- 更改連結所指向的程式碼託管平台程式庫，需要工作區管理員，並會以管理員自己的登入對照程式碼託管平台檢查，與連結它時相同。
- 已連結的程式庫不能改為僅限本機的程式庫。

若路徑之後指向的是**另一個**程式庫（原本的被刪除後重新建立，或被移動並由另一個取代），Control Center 會停止向它傳送任何東西：不傳送權杖、推送、評論或請求。這也涵蓋個人本身的操作：你在此類程式庫上所做的審查、合併或評論都會被拒絕，GitHub、GitLab 與 Bitbucket 皆然。該列與該程式庫的 pull request 會顯示「_repo_ 現在指向另一個存放庫」，直到工作區管理員按下 **重新連接** 為止。

## 誰可以開啟程式碼

僅憑程式庫授權並不能開啟程式庫的檔案。要開啟它的檔案、差異比較、搜尋或終端機，成員需要 Control Center 授權，而且其自身的程式碼代管平台登入必須能讀取該程式庫。工作區管理員不享有豁免；伺服器擁有者則享有。參見[程式碼遵循代管平台](/zh-HK/手冊/概念/授權/#程式碼跟隨程式碼託管)。

當你把程式庫授予一位其程式碼代管平台帳戶無法讀取它的人時，授權會被儲存，並且你會看到一則警告，例如「已儲存。對方的 GitHub 帳戶目前仍無法讀取此存放庫，因此對他們保持隱藏。」

同樣的規則也決定誰可以開啟空間。空間只會向能開啟它所使用的每一個程式庫之程式碼的成員開放，並對其他所有人隱藏，連同其搜尋結果、執行記錄、待辦事項、活動與通知。沒有任何程式庫的空間對每位成員開放。參見[空間跟隨其程式庫](/zh-HK/手冊/概念/授權/#空間跟隨其儲存庫)。

## 移除程式庫

1. 開啟 **設定 → 工作區 → 程式庫**。
2. 按一下該列上的垃圾桶圖示。
3. 確認「要從工作區移除程式庫嗎？」

對話框會說明它會做什麼：「_name_ 將從此工作區移除。磁碟上的本機檔案不會更動。」

移除程式庫需要工作區管理員。它也會忘記為該程式庫儲存的程式碼代管平台憑證，例如 GitLab 或 Bitbucket 的自動化權杖。

移除會從此工作區刪除該程式庫資料列，並串聯清除它的程式碼圖資料列——符號、邊、檔案與索引檢查點——以及它上面按成員劃分的每一項程式庫授權、它與空間的連結，還有它的隔離檢出記錄。同一個檢出若註冊在另一個工作區，就是一筆獨立資料列，不受影響。那些記錄所指向的磁碟 worktree，不會因為這次刪除而被拆除。

## 疑難排解

### 我有授權，但程式庫顯示我的帳戶無法讀取它

你自己的程式碼代管平台帳戶無法讀取該程式庫，因此即使工作區已授予授權，Control Center 仍會對你保留其程式碼。若你還沒有登入，請在 **設定 → 你 → 個人資料 → 程式碼託管** 中登入該平台，或請該程式庫在平台上的擁有者授予你存取權。一旦你的程式碼代管平台帳戶能讀取它，該程式庫就會開啟。

### 「此資料夾位於工作區儲存空間之外」

該程式庫的資料夾位於工作區儲存空間之外且並非由伺服器擁有者連結，或符號連結現在指向了別處。它會保持列出但不被使用，直到伺服器擁有者確認它或再次加入該資料夾為止。如果你不是擁有者，請詢問他們。如果你是，請在該列上按 **確認**，或在清單上方按 **全部確認**；參見[伺服器暫不使用的資料夾](#伺服器暫不使用的資料夾)。

### 「伺服器上此路徑已不存在任何東西」

資料夾在伺服器的機器上被移動或刪除。請把它放回原處，或請工作區管理員使用通知中的 **移除**，把該程式庫移除，然後從它目前的資料夾再次加入。

### 「此資料夾無法作為存放庫使用」

儲存的資料夾是伺服器自己的資料資料夾、其中的某個東西，或工作區的儲存資料夾本身。這些都不能作為程式庫。工作區管理員可以使用通知中的 **移除** 將其移除，然後從檢出的真實資料夾再次加入程式庫。

### 「無法確認你的程式碼代管平台存取權限」

Control Center 無法連到程式碼代管平台來檢查你的帳戶能否讀取該程式庫，因此它選擇拒絕，而不是猜測。請稍後再試。
