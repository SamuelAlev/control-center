本指南說明如何將 Google Calendar 連接到工作區。這項連接以工作區和成員為單位：它會把你在該工作區的活動同步到 Control Center，你也可以在那裡回覆邀請、建立、移動及刪除活動。完整說明請參閱[日曆與排程](/zh-HK/手冊/概念/日曆/)。

## 先決條件

- 伺服器能讓人們登入 Google：透過 Control Center Connect，或使用伺服器自己的 Google 用戶端（[自備 Google 用戶端](#自備-google-用戶端)）。由伺服器擁有者在**設定 → 伺服器 → 單一登入**中選擇
- 已開啟一個工作區：日曆帳戶一定屬於某個工作區

## 連接帳戶

1. 在側邊欄開啟**行事曆**。
2. 在日曆側邊欄中點擊**新增日曆帳號**。（同一區段也位於**設定 → 工作區 → 個人資料與身分**的 **Google Calendar** 之下。）
3. 點擊**連接 Google Calendar**。你的瀏覽器會開啟 Google 的同意頁面。
4. 選擇帳戶，並核准存取你的日曆活動與日曆清單。

如何完成，取決於由誰執行這次登入：

- **伺服器自己的 Google 用戶端：** Google 會把你的瀏覽器送回伺服器，對話框會自行關閉
- **Control Center Connect：** 瀏覽器頁面會顯示一個 8 個字元的代碼。把它輸入對話框，或讓瀏覽器透過 `control-center://` 連結開啟 Control Center，便不必輸入

你的活動會即時開始同步。完成這段交換、並保存憑證的是伺服器，而不是你的裝置。

帳戶只會連接到**目前作用中的工作區**，而且屬於你：兩位成員連接同一個 Google 地址，會得到各自獨立的帳戶。切換工作區後，你看到的會是該工作區的日曆。

無論由哪個用戶端執行，連接流程都會要求 `calendar.events` 與 `calendar.calendarlist.readonly` 加上 `openid email`。在 Control Center 能寫入 Google 之前連接的帳戶只有唯讀範圍；系統會要求你重新連接，新的登入會補上其餘範圍。

## 建立、移動、回覆及刪除活動

- **建立活動：** 在週或日檢視中，拖曳時間格線以框出時段（在月檢視中，拖曳跨越日期即可建立全日活動）。旁邊會開啟一張卡片，可設定標題、時間、來賓、Google Meet 連結、地點、說明，以及要在哪個日曆上建立。**儲存**會在 Google 上建立活動並開啟它。日曆標頭中的 **+** 按鈕會為下一個空閒的十五分鐘開啟同一張卡片。按 Escape 可放棄
- **移動活動：** 把它拖到另一個時間或日期，或拖動其底邊以更改結束時間。Google 接受新時間後活動才會更新；若 Google 拒絕，它會回到原處。你只能移動自己的活動及你所主辦的活動；邀請會留在主辦者放置的位置
- **回覆邀請：** 開啟活動並選擇**是**、**待定**或**否**
- **刪除活動：** 開啟活動並點擊垃圾桶圖示。確認視窗會顯示受影響的對象：你所主辦的活動被取消時，來賓會收到通知；刪除邀請則只會把它從你的日曆移除。刪除週期性活動的單一出現時，其餘系列會保留

來賓會收到 Google 自己的電郵邀請、更新或取消通知。你只能在你的帳戶有寫入權限的日曆上建立活動，而且只能使用你自己的帳戶：絕不會提供其他成員已連接的日曆。 移動週期性活動的單一出現時，其餘系列同樣會保留。


## 同步的運作方式

排程由**伺服器**掌管：它每兩分鐘掃描每個工作區已連接的帳戶，並把活動寫入該工作區的資料庫。用戶端從不直接與 Google 通訊——它們只讀取伺服器寫入的內容。

掃描是增量式的。每個日曆的第一次掃描會擷取一段滾動視窗（往前 60 天、往後 90 天），並記下 Google 的同步權杖；之後的掃描會帶上該權杖，只接收有變更的內容，這正是兩分鐘一次的頻率仍可負擔的原因。視窗每 24 小時會以一次完整同步重新定位，Google 每次使權杖失效時也是如此。

憑證存放於伺服器端的 `secrets.json`，位於伺服器的資料目錄下，僅限擁有者讀寫（`0600`）——不在作業系統鑰匙圈中，也永遠不會出現在用戶端裝置上。透過 Connect 的登入只會儲存一份密封的憑證，只有 Connect 能為這部伺服器開啟它；其存取權杖只留在伺服器的記憶體中。

## 連接多個帳戶

一個工作區可以連接多個 Google 帳戶（例如工作和個人帳戶）。為每個帳戶重複連接步驟；它們的活動會合併到相同的月／週／議程檢視中。每個帳戶各自獨立同步與重新整理，也可以各自中斷連接。

## 重新連接已過期的帳戶

如果 Google 永久使某個帳戶的登入失效（工作階段被撤銷或長期過期），同步就會停止，Control Center 會在日曆上顯示**重新連接**橫幅，並發出桌面通知。點擊**重新連接**並重新登入；下次同步成功後橫幅便會消失。

當這部伺服器已無法再使用該登入時，也會出現同樣的橫幅：伺服器擁有者切換了 Connect 伺服器或輪替了 Connect 金鑰、伺服器自己的 Google 用戶端已變更，或資料目錄被還原到另一部機器上。

## 中斷連接帳戶

在日曆側邊欄（或**設定 → 工作區 → 個人資料與身分**）中，點擊該帳戶的**中斷連接**。這會刪除其已同步的活動，並清除伺服器上儲存的憑證。

## 自備 Google 用戶端

當你選擇了**使用我自己的應用程式**時，才執行你自己的 Google 用戶端。伺服器自己的用戶端只在那種情況下適用：使用 Control Center Connect 或自訂 Connect 時，Connect 會執行每個通道（包括 Google），伺服器的用戶端會保留但不使用。若要在伺服器使用 Connect 時讓同意畫面顯示你自己專案的名稱，請為工作區提供自己的用戶端（[見下方](#為一個工作區設定自己的-google-用戶端)）；此設定在任何模式下都適用。

1. 在 [Google Cloud Console](https://console.cloud.google.com/apis/credentials) 中啟用 **Google Calendar API**，並設定 **OAuth 同意畫面**，加入 `calendar.events`、`calendar.calendarlist.readonly`、`openid` 和 `email` 範圍。應用程式尚未通過驗證時，請把自己加入為**測試使用者**。
2. 建立應用程式類型為 **Web application** 的 **OAuth 用戶端 ID**。
3. 加入已授權的重新導向 URI `<server origin>/oauth/google/callback`。**設定 → 伺服器 → 單一登入 → 供應商應用程式 → Google** 會在**回呼網址**下顯示確切的 URL；請原封不動地複製。
4. 把**用戶端 id** 和**用戶端密鑰**貼到同一個 Google 區塊中，或在伺服器的 `.env` 檔案中寫成 `GOOGLE_OAUTH_CLIENT_ID` 和 `GOOGLE_OAUTH_CLIENT_SECRET`。

若 `GOOGLE_OAUTH_CLIENT_SECRET` 被匯出到行程環境中，伺服器會拒絕啟動；請把它放在 `.env` 檔案中（在 Docker 中，把檔案掛載到 `/app/bin/.env`）。密鑰永遠不會離開伺服器：沒有任何 RPC 回應會帶上它。只有用戶端 ID 而沒有密鑰，代表設定尚未完成，在兩者都設定好之前，Google 登入都會被拒絕。

改用另一個用戶端會令所有人登出 Google Calendar：一次登入只屬於簽發它的用戶端。

## 為一個工作區設定自己的 Google 用戶端

一個工作區可以改用自己的用戶端連接 Google Calendar，而不使用伺服器的。只有工作區管理員或擁有者可以設定。

1. 按上方第 1、2 步建立 Google **Web application** 用戶端
2. 前往 **設定 → 工作區 → 一般 → 供應商應用程式**，開啟 **Google Calendar**
3. 選擇**使用工作區自家的應用程式**
4. 把該行在**回呼網址**下顯示的重新導向 URI 原封不動地加入用戶端
5. 貼上**用戶端 id** 和**用戶端密鑰**

此工作區連接的日曆帳戶之後都會透過該用戶端，不論伺服器以甚麼方式讓人登入。它絕不會退回伺服器的用戶端或 Connect：在兩個欄位都設定好之前，此工作區的 Google Calendar 會關閉，而該行會說明缺少甚麼。密鑰永遠不會離開伺服器。

在伺服器的用戶端與工作區的用戶端之間切換，或更改工作區的用戶端 id，都會令此工作區中每個 Google 帳戶需要重新連接。**使用伺服器的應用程式**會刪除工作區已儲存的欄位。伺服器上的其他工作區不受影響。

## 疑難排解

| 症狀 | 可能原因 |
| ---- | -------- |
| **連接 Google Calendar** 表示尚未設定登入 | 伺服器既沒有自己的 Google 用戶端，也沒有 Connect。伺服器擁有者可在**設定 → 伺服器 → 單一登入**中選擇其一 |
| Google 顯示 `redirect_uri_mismatch` | 用戶端上註冊的重新導向與**回呼網址**的值不完全相符，或伺服器的公開 URL 已變更 |
| Google 傳回 `invalid_client` | ID 與密鑰來自不同的用戶端，或該用戶端已被刪除 |
| 核准成功但同步內容為空 | 你的帳戶不是同意畫面上的**測試使用者**，或未獲授予任何所要求的範圍 |
| 對話框表示代碼不相符 | 請完全按照瀏覽器顯示的內容輸入這 8 個字元。輸錯五次會結束這次登入；請重新開始 |
| 回覆邀請時出現「無法更新你的回覆」，或建立、移動及刪除失敗 | 帳戶是以舊的唯讀範圍連接的，請重新連接；僅供你唯讀的共用日曆也會拒絕寫入 |
| 所有人都要重新連接 | 伺服器或工作區的 Google 用戶端已變更，或伺服器的 Connect 選擇或金鑰已變更。請參閱[重新連接已過期的帳戶](#重新連接已過期的帳戶) |
