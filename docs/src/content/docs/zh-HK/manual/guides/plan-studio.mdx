本指南說明如何在 Plan Studio 中處理計劃。關於編排與計劃文件是什麼，請參閱
[編排](/zh-HK/手冊/概念/編排/)與
[使用計劃模式](/zh-HK/手冊/操作指南/計劃模式/)。

## 開啟計劃

計劃隸屬於產生它的對話，因此你通常會在那裡找到它：對話中該計劃的列有
**開啟**操作，而 Plan Studio 會以對話旁邊的編輯器分頁開啟。

:::note[側邊欄沒有「計劃」這一項]
這是刻意為之，並非疏漏。`/workspaces/<workspace-id>/plans` 這個中樞只是
可路由的深層連結，因此若你想要一份常設清單，請將它加入書籤。
:::

中樞會列出三個區段：

- **進行中的計劃** — 編排，已提議的排在最前，並附上狀態、步驟數目與修訂號。
- **計劃文件** — 單一代理在
  [計劃模式](/zh-HK/手冊/操作指南/計劃模式/)中以 `submit_plan` 提交的計劃，
  當它們處於已提議或已批准狀態時會顯示。
- **劇本** — 已儲存、帶參數的計劃範本。

點擊卡片即可在 Plan Studio 中開啟。路由是
`/workspaces/<workspace-id>/plans/<kind>/<plan-id>`，其中 `kind` 為
`orchestration` 或 `document`，因此你也可以為單一計劃建立深層連結。

若你開啟的是**編排**，你會有可編輯的畫布、版本時間軸與批准列。若你開啟的
是**計劃文件**，同一張圖會以唯讀方式呈現——計劃文件由代理撰寫；你審閱、
預估並批准或拒絕它們，而獲批准的檔案會顯示它編譯成的編排之即時逐節點
執行狀態。

## 編輯 DAG

當**編排**處於 `proposed` 時可以編輯。所有畫布編輯都以鍵盤操作：

1. 點擊畫布，然後以**方向鍵**移動選取範圍。
2. 按 **n** 新增步驟。它會以選取狀態顯示為「新步驟」；在右側的檢視器中
   重新命名。
3. 在最先執行的步驟上按 **e**，然後點擊相依的步驟（或選取它並按
   **Enter**）以連接依賴關係。按 **Esc** 放棄待處理的連接。
4. 按 **x** 剪除所選步驟最新的依賴關係，或在檢視器的依賴關係編輯器中
   切換確切的依賴關係。
5. 按 **Delete** 移除所選步驟；其餘步驟的依賴關係中對它的參照也會一併
   移除。

在檢視器中，你也可以編輯步驟的描述、角色與輸出結構。編輯會在短暫停頓後
自動儲存為新的修訂；驗證錯誤（顯示於批准列）會阻止儲存，直到你修正為止。

只有工作步驟可以編輯。結構性節點——研究、討論與匯總——是唯讀的，任何
工作已執行過的步驟亦然（它會標示為「已執行」，因為編輯它會令計劃分岔）。

儲存是以你開始時的修訂為基礎的樂觀式並行。若編排者在背後重新規劃，你的
儲存會被拒絕並顯示「計劃已經改變」，而不會被合併或靜默覆蓋；請重新讀取
目前的修訂並重做你的編輯。代理發起的重新規劃本身也受到每兩分鐘一次的
限流，因此這種情況並不常見。

:::note
畫布不支援拖曳重新定位：版面是由依賴結構計算出來的，因此「移動」步驟
意味著重新接駁它的依賴關係。
:::

## 讀取成本、時間與風險預估

在批准列按**預估**。

- 畫布上每個步驟都會有一個徽章，附上成本範圍與其背後的樣本數，若該步驟
  的角色從未執行過則顯示「尚無歷史紀錄」。選取某個步驟即可在檢視器中
  查看完整詳情：成本範圍與樣本數、時長範圍，以及由步驟來源推導出的
  影響範圍（檔案與符號）——若該步驟沒有附帶來源，則顯示「未知」。
- 批准列會顯示計劃總計：整體成本範圍、關鍵路徑的時長範圍（並行分支會
  重疊，因此這不是加總），以及計劃設定預算上限時的該上限。
- 若只有部分步驟有歷史，總計會標示為**部分**，且只涵蓋可估算的步驟。
  若預估的高端超出預算上限，總計會轉為紅色並顯示超支警告。

預估若非誠實，就是從缺：角色沒有已完成執行歷史的步驟會回報樣本數為零，
且完全沒有範圍，並顯示為未知，而不是憑猜測填上。請把「尚無歷史紀錄」
理解為「沒有人知道」，而不是「便宜」。

預算上限只是與此預估作顯示上的比較。計劃開始執行後就沒有任何東西會
強制執行它——真正會停止支出的控制項，請參閱
[管理成本](/zh-HK/手冊/操作指南/管理成本/)。

## 將修訂與較早的提案比對

每一次編輯與編排者每一次重新規劃，都會附加到一個只可追加的修訂時間軸，
顯示在編排計劃左側的**版本**面板中。

1. 點擊某個修訂，將它與目前的提案比對。若沒有選取任何項目，面板會將
   上一個修訂與目前修訂比對。
2. 在面板下半部閱讀差異：兩個修訂之間新增、移除或變更的步驟。
3. 若計劃仍為 `proposed`，點擊某個修訂上的倒帶圖示即可回到該修訂。倒帶
   會把該提案儲存為**新的**修訂——不會遺失任何東西。

一旦計劃不再是 `proposed`，`propose_orchestration` 與編輯器都會拒絕變更，
因此進行中的執行不會套用執行中途的重新規劃。

## 批准、拒絕或擴大計劃

在應用程式中，一份已提議的計劃是一個整體的決定：在批准列選**批准計劃**
或**拒絕**。**批准計劃**一律會批准每一個步驟——無法先選取子集。當提案
有驗證錯誤時，批准會被阻止，這些錯誤會顯示在按鈕旁邊。

批准只限操作者。它沒有對應的 MCP 工具，因此代理可以提出與修訂計劃，但
永遠無法批准。

一旦編排進入執行階段，批准列就會改變：

- 若某個步驟在執行中途停下來提問，選取它並按**繼續節點**即可讓它繼續。
- 按**批准所選**可將*部分*批准擴大至所選步驟以及它遞移相依的一切（步驟
  永遠不能在沒有其依賴的情況下獲批准）。這個控制項在每個編排的執行列上
  都有；當計劃是整份獲批准時，它不會有任何作用。
- 按**取消執行**可停止整個編排。

部分批准範圍以外的步驟會以延後狀態呈現，在你擴大範圍之前不會執行。

:::note[部分批准無法源自應用程式]
唯有當某個東西透過 RPC 以明確的 `approved_node_keys` 清單呼叫
`orchestration.approve` 時，部分批准才會存在。應用程式中的**批准計劃**
一律會批准每一個步驟。計劃文件在任何情況下都是整份批准，因此執行中的
文件只會提供**取消執行**。
:::

## 以參數執行劇本

劇本是一個已儲存的計劃範本，在其目標、步驟標題、描述與提示中含有帶型別的
`{{param}}` 佔位符。替換是字面的——沒有表達式語言；若你需要邏輯，請改用
[管線](/zh-HK/手冊/操作指南/建立管線/)。

1. 在中樞的**劇本**區段中，於該劇本上按**執行**（或開啟 ⌘K 命令面板並在
   那裡挑選劇本）。
2. 填寫參數。列舉型參數會以下拉式選單呈現；程式庫與代理參數接受程式庫
   或代理參照；選填參數會沿用其預設值。
3. 選擇計劃所依據的**錨定工單**，然後確認。

執行劇本只會**提出**計劃——實例化後的編排會以 `proposed` 狀態在 Plan Studio
中開啟，在你於該處批准之前不會執行任何東西。若要移除劇本，請在其卡片上
按垃圾桶圖示。

代理使用 `create_playbook` 與 `run_playbook` MCP 工具建立並執行劇本；請參閱
[MCP 工具參考](/zh-HK/手冊/參考/mcp-工具/)。
