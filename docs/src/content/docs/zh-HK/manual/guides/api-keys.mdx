本指南說明 Control Center 使用的每一項憑證存放在何處，以及如何更換它們。

**你正在輸入的裝置上不會儲存任何內容。**每一項憑證都存放在伺服器上；某個請求由哪一項憑證應答，取決於它背後是否有真人。

| 憑證                                 | 儲存位置                                                  | 使用者                                                          |
| ------------------------------------ | --------------------------------------------------------- | ---------------------------------------------------------------- |
| 你的程式碼託管 / 工單憑證            | 伺服器的 0600 機密檔案，以你的用戶 id 為鍵                 | 你要求的一切：PR 介面、你的代理執行、你的映像                     |
| 伺服器的應用身分                     | 同一個檔案，非機密項則放在 `server_settings`               | 沒有真人要求的作業：webhook、PR 輪詢、工單同步                    |
| 模型供應商金鑰與 OAuth 權杖          | 伺服器自有的憑證儲存                                       | 內建配接器，服務於此安裝上的每個工作區                            |
| Slack 機械人權杖                     | 伺服器上的 `<dataDir>/<workspaceId>/chat_credentials/`     | 該工作區的聊天橋接                                                |
| 外部 CLI 憑證                        | 該 CLI 所用的任何儲存                                      | 伺服器主機上的 Claude Code                                        |

## 兩種 GitHub 憑證，回答不同的問題

- **你自己的憑證**，來自登入（裝置流程）或貼上權杖。所有*代表你*發出的請求都用它，因此以你的名義張貼的評論會帶上你的名字。其他成員無法讀取它，他們會連接自己的憑證
- **伺服器的憑證**，來自操作者註冊的 GitHub App。它應答一切沒有呼叫者的請求——因此當某個人離開或輪換權杖時，程式碼託管存取不會消失

你的憑證在 **設定 → 工作區 → 個人資料與身分** 的**程式碼託管**卡片中設定；伺服器的憑證則在 **設定 → 伺服器 → 單一登入** 的**供應商應用**中設定。參見[設定 GitHub 整合](/zh-HK/手冊/操作指南/github-整合/)和[建立 GitHub App](/zh-HK/手冊/操作指南/github-app/)。

:::note[還有一個只能透過 URL 存取的畫面]
`/workspaces/<workspaceId>/api-keys` 會渲染與新手導引第一步相同的兩張卡片。它在**介面的任何位置都沒有導覽項目**；只能透過輸入 URL 存取。請改用 設定 → 工作區 → 個人資料與身分。
:::

## 設定模型供應商金鑰

內建配接器自行向供應商完成認證，而這些憑證存放在伺服器上。

1. 前往 **設定 → 伺服器 → 模型供應商**
2. 捲動到**供應商與模型**
3. 連接供應商——OpenAI、Codex、Cursor 和 Kimi Code 使用瀏覽器 OAuth；Anthropic 及其餘供應商則使用 API 金鑰

完整清單以及新增自訂端點的方法，請參見[管理配接器與模型](/zh-HK/手冊/操作指南/配接器/)。

這些憑證是**主機全域**的：一個金鑰服務於此安裝上的每個工作區。OAuth 權杖會在過期前重新整理。

外部配接器 CLI 在伺服器主機上，以自己的設定保留自己的憑證——Control Center 不會管理它們。請按照 Claude Code 自身文件所述的方式，在執行 `cc_server` 的機器上完成認證。

每個配接器的**環境變數**對話框看起來像是可以為其中一個放置金鑰的地方，但事實並非如此：它會寫入你的裝置，而伺服器讀取自己的副本，兩者之間沒有任何橋接。參見[管理配接器與模型](/zh-HK/手冊/操作指南/配接器/)。

## 連接工單供應商

**設定 → 工作區 → 一般** 上的**工單系統**卡片承載同一個決定的兩半：你的工單存放在哪個供應商，以及其憑證。選擇**本機**會隱藏憑證列——本機工單存放在此伺服器自己的資料庫中，沒有任何需要認證的對象。

你的金鑰與程式碼託管憑證一樣，會按你的用戶 id 存放在伺服器上。伺服器另外單獨保存自己的 Linear 金鑰（**供應商應用**），當沒有真人要求時，工單同步就是用它執行。代理的沙箱中不會注入任何工單金鑰；代理透過 Control Center 的工具寫入工單，這些工具會詢問**寫入外部追蹤器**規則。參見[設定 Linear 整合](/zh-HK/手冊/操作指南/linear-整合/)。

## 輪換或撤銷

- **你的 GitHub 憑證**：按**中斷連線**，然後重新登入或貼上新的權杖。在 GitHub 上撤銷舊憑證
- **伺服器的應用**：在該應用的 GitHub 頁面上產生新的私密金鑰或用戶端密鑰，貼到**供應商應用**中並按**測試**
- **某個模型供應商**：在其所在列上登出（OAuth）或移除金鑰，然後重新連接
- **Slack**：在連接對話框中重新貼上權杖。參見[設定 Slack 整合](/zh-HK/手冊/操作指南/slack-整合/)

## 疑難排解

### PR 清單是空的，但我的權杖在 `curl` 中可用

檢查**程式碼託管**列的副標題。如果它顯示另一個來源（「透過此伺服器的應用」、「來自環境」），那麼你正在測試的憑證並不是應答的那一個——你的憑證未被儲存。

### 權杖被接受，但之後的請求失敗

權杖在儲存時會接受探測，因此該列會顯示它背後的帳戶——但只顯示帳戶，不顯示範圍。範圍不足的權杖可以連接，然後在個別請求上失敗。請檢查範圍與有效期限：

```bash
curl -H "Authorization: token YOUR_TOKEN" https://api.github.com/user
```
