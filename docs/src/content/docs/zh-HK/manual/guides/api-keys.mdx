本指南說明 Control Center 使用的每一項憑證存放在何處，以及如何更換它們。

**你正在輸入的裝置上不會儲存任何內容。**每一項憑證都存放在伺服器上；某個請求由哪一項憑證應答，取決於它背後是否有真人。

| 憑證                                 | 儲存位置                                                  | 使用者                                                          |
| ------------------------------------ | --------------------------------------------------------- | ---------------------------------------------------------------- |
| 你的程式碼託管 / 工單登入            | 伺服器的 0600 機密檔案，以你的用戶 id 為鍵                 | 你做的一切：PR 介面、審查、合併、你在 Linear 上的動作             |
| 伺服器的供應商應用程式               | 同一個檔案，非機密項則放在 `server_settings`               | 讓人們登入，以及為代理、管線與輪詢簽發只適用於單一程式庫的權杖     |
| Connect 安裝金鑰                     | 同一個檔案（`connect_install_key`）                        | 向 Control Center Connect 識別這部伺服器                          |
| 模型供應商金鑰與 OAuth 權杖          | 伺服器自有的憑證儲存                                       | 內建配接器，服務於此安裝上的每個工作區                            |
| Slack 機械人憑證                     | 伺服器上的 `<dataDir>/<workspaceId>/chat_credentials/`     | 該工作區的聊天橋接：你自己應用程式的權杖，或共用應用程式的密封授權 |
| 外部 CLI 憑證                        | 該 CLI 所用的任何儲存                                      | 伺服器主機上的 Claude Code                                        |

## GitHub：你的登入，以及只適用於單一程式庫的權杖

- **你自己的登入**，來自**登入 GitHub**。所有*代表你*發出的請求都用它，因此以你的名義發佈的審查會帶上你的名字。其他成員無法使用它，他們會自己登入。沒有可貼上的 GitHub 權杖
- **沒有人在輸入的作業**（代理、管線、輪詢、機械人回覆）每次會取得一個只適用於一個程式庫的權杖，由伺服器的 GitHub App 或透過 Control Center Connect 簽發，並限制在某位負責成員在那裏能做的事。它絕不是把你的登入整個交出去

你的登入在 **設定 → 你 → 個人資料** 的**程式碼託管**卡片中設定；伺服器的應用程式則在 **設定 → 伺服器 → 單一登入** 的**供應商應用程式**中設定。參見[設定 GitHub 整合](/zh-HK/手冊/操作指南/github-整合/)和[建立 GitHub App](/zh-HK/手冊/操作指南/github-app/)。

GitLab 和 Bitbucket 仍然使用貼上的個人權杖，儲存方式相同。參見[連接程式碼託管](/zh-HK/手冊/操作指南/連接程式碼託管/)。

:::note[還有一個只能透過 URL 存取的畫面]
`/workspaces/<workspaceId>/api-keys` 會渲染與新手導引第一步相同的卡片。它在**介面的任何位置都沒有導覽項目**；只能透過輸入 URL 存取。你自己的登入請改用 設定 → 你 → 個人資料，工單供應商則請改用 設定 → 工作區 → 整合。
:::

## 設定模型供應商金鑰

內建配接器自行向供應商完成認證，而這些憑證存放在伺服器上。

1. 前往 **設定 → 伺服器 → 模型供應商**
2. 捲動到**供應商與模型**
3. 連接供應商——OpenAI、Codex、Cursor 和 Kimi Code 使用瀏覽器 OAuth；Anthropic 及其餘供應商則使用 API 金鑰

完整清單以及新增自訂端點的方法，請參見[管理配接器與模型](/zh-HK/手冊/操作指南/配接器/)。

這些憑證是**主機全域**的：一個金鑰服務於此安裝上的每個工作區。OAuth 權杖會在過期前重新整理。

Claude Code 透過 **設定 → 伺服器 → 模型供應商** 之下的 **Claude Code 帳戶** 登入：每個帳戶在伺服器上都有自己的設定目錄，你在該處執行應用程式顯示給你的 `claude auth login` 命令。

每個配接器的**環境變數**對話框看起來像是可以為其中一個放置金鑰的地方，但事實並非如此：它會寫入你的裝置，而伺服器讀取自己的副本，兩者之間沒有任何橋接。參見[管理配接器與模型](/zh-HK/手冊/操作指南/配接器/)。

## 連接工單供應商

**設定 → 工作區 → 整合** 上的**工單**卡片承載工作區這一側：你的工單存放在哪個供應商，以及 Control Center 在那裡自行運作時以誰的身分。選擇**本機**會隱藏 Linear 相關列——本機工單存放在此伺服器自己的資料庫中，沒有任何需要認證的對象。

Linear 有兩種登入，而且沒有要貼上的金鑰：**Linear** 是你自己的，用於你做的事，位於 **設定 → 你 → 個人資料**；**Linear 自動化**則是工作區的 Control Center 應用程式，由管理員在**工單**卡片上連接，用於工單同步、管線與代理。伺服器亦可保存一組**服務 API 金鑰**（**供應商應用程式**），供未連接自動化的工作區使用。代理的沙箱中不會注入任何工單憑證；代理透過 Control Center 的工具寫入工單，這些工具會詢問**寫入外部追蹤器**規則。參見[設定 Linear 整合](/zh-HK/手冊/操作指南/linear-整合/)。

## 輪換或撤銷

- **你的 GitHub 登入**：按**中斷連接**，然後再次**登入 GitHub**。中斷連接也會令伺服器代表你簽發的所有權杖一併失效
- **GitLab 或 Bitbucket 權杖**：按**更新權杖**並貼上新的權杖，然後在該程式碼託管平台上撤銷舊的權杖
- **伺服器的應用程式**：在該應用程式的供應商頁面上產生新的私密金鑰或用戶端密鑰，貼到**供應商應用程式**中並按**測試**
- **Connect 安裝金鑰**：伺服器擁有者在 **Control Center Connect** 卡片上按**輪替金鑰**。所有透過 Connect 登入的人都要重新登入。如果無法連到 Connect 伺服器，不會有任何改變，並會提供**仍要輪替**。參見[輪替安裝金鑰](/zh-HK/手冊/參考/connect/#輪替安裝金鑰)
- **某個模型供應商**：在其所在列上登出（OAuth）或移除金鑰，然後重新連接
- **Slack**：如果是你自己的應用程式，在連接對話框中重新貼上權杖。共用的 Control Center 應用程式沒有需要輪換的權杖：它的機械人權杖經由 Connect 更新，而**中斷連接**會撤銷它，並從 Slack 解除安裝該機械人。參見[設定 Slack 整合](/zh-HK/手冊/操作指南/slack-整合/)

## 疑難排解

### GitLab 或 Bitbucket 權杖在 `curl` 中可用，在這裏卻不行

檢查**程式碼託管**列。如果它顯示「未連接」或要求你重新連接，代表你的權杖沒有儲存，或已被拒絕。若是 Bitbucket，請同時輸入你的 Atlassian 帳戶電郵與 API 權杖。

### GitLab 或 Bitbucket 權杖被接受，但之後的請求失敗

權杖在儲存時會接受探測，因此該列會顯示它背後的帳戶——但只顯示帳戶，不顯示範圍。範圍不足的權杖可以連接，然後在個別請求上失敗。請在該程式碼託管平台上檢查它的範圍與有效期限。

### 供應商表示此伺服器尚未設定登入

伺服器既沒有該供應商的自有應用程式，也沒有 Control Center Connect。伺服器擁有者可在**設定 → 伺服器 → 單一登入**中選擇其一。
