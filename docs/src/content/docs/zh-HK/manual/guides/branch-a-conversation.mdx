本指南說明如何回到對話中較早的位置，把它帶往別的方向——同時保留你離開的那條路徑。

## 唯一值得知道的一件事

**建立分支不會寫入任何內容。** 對話是一棵訊息樹，末端有一個指標，而回到較早的位置就是移動那個指標。沒有任何東西被刪除，也沒有任何東西被隱藏，切換回去不過是再一次移動指標。

這也是為甚麼在這裏修改提示並重跑是安全的：你用來對照的那個答案仍然在那裏。

## 查看分支

```
/tree
```

導覽器會列出每一則訊息，並在每個分叉處縮排，同時把目前的路徑標為**目前分支**。從未分叉過的對話，仍會像以往一樣以平鋪清單呈現——在真正有東西可導覽之前，看這個導覽器不費任何成本。

每一列提供兩個動作。

| 動作                            | 效果                                                    |
| ------------------------------- | --------------------------------------------------------- |
| **從此處繼續**          | 移動指標。你的下一則訊息會從那一則訊息接續。 |
| **分叉為新對話** | 把直到那一則訊息為止的路徑複製到一個新對話。 |

## 分支：嘗試另一種做法

1. `/tree`
2. 找出你想從哪一則訊息重新開始——通常是你最後覺得滿意的那一則。
3. **從此處繼續。**
4. 輸入新的提示。

舊的後續內容仍然在樹中；`/tree` 現在會從那一點顯示兩條路徑，你可以自由在兩者之間切換。

:::note[你離開的那條路徑仍然在那裏]
建立分支不會隱藏或刪除任何東西。`/tree` 會列出每一條路徑、把當前那一條標為**目前分支**，而切換也是靠它。
:::

## 分叉：把它帶到別處

分叉會把路徑複製到同一個空間中的**新對話**。當兩個方向會持續分歧，而你想讓它們並排存在、而不是來回切換時，就用它。

這份副本擁有全新的訊息 id。兩個共用資料列的對話會互相顯示對方後來的訊息，而那正是分叉應該避免的事。

## 還原與分支之別

它們是不同的工具，而這個差別很重要。

|                     | 還原                                             | 分支                          |
| ------------------- | -------------------------------------------------- | ------------------------------- |
| 後來的訊息  | 從敘述中隱藏                          | 仍然在 `/tree` 中可見         |
| **worktree**    | 回退到該回合的快照                 | 未受影響                        |
| 撤銷                | **撤銷還原**會把那一批變更還原回來                  | 把指標移回去            |

當代理改動了你想討回的*檔案*時，你要的是還原。當對話走錯了方向、但檔案無恙時，你要的是分支。

還原同樣會移動分支末端，因此你的下一則訊息會從正確的位置接續，而不是從一條再也沒有人看得見的尾巴接續。

## 把對話帶離應用程式

### `/export`

寫出一個**完整獨立的 HTML 檔案**：整段對話，加上可摺疊的工具卡片，顯示每次呼叫收到了甚麼、又回傳了甚麼。沒有樣式表、沒有腳本、沒有圖像主機——它放在 USB 隨身碟上能用，五年後也還能用。

- **桌面版：** `Documents/ControlCenter/exports/`，附上時間戳記，因此第二次匯出不會覆蓋第一次。
- **網頁版：** 交由瀏覽器下載。

### `/dump`

把敘述以 markdown 複製到剪貼板，工具呼叫放在可摺疊的區塊中。要貼進問題單的就是這一份。

推理內容刻意不包括在內：那是模型的草稿空間，而錯誤報告是給人讀的。
