本指南說明如何建立與管理工單。

## 建立工單

### 透過介面

1. 在工作區側邊欄中點擊**工單**。
2. 按**新增工單**。
3. 填寫：
   - **標題** —— 簡短摘要。這是唯一必填的欄位。
   - **描述** —— Markdown 格式，附有格式工具列。
   - **狀態** —— **待辦**（預設）或**待處理**。已開始狀態與終端狀態都經由生命
     週期到達，而不是在建立時設定。
   - **優先順序** —— 無、緊急、高、中或低。
   - **負責人** —— 你自己或工作區中的任何代理。
   - **專案** —— 可選的分組。
4. 按**建立**，或先開啟**建立更多**，讓對話框保持開啟以便快速連續輸入。

對話框中沒有供應商選擇器。工單會建立到工作區目前生效的工單供應商上。

### 透過代理

在空間中請代理幫忙：

> 為慢速連線上的登入逾時問題建立一張工單。

它會呼叫 `create_ticket` MCP 工具。該工具上的優先順序是**整數**，而不是名稱：

```
create_ticket(
  workspace_id: "...",
  title: "Fix login timeout on slow connections",
  description: "...",
  priority: 2
)
```

| 值 | 優先順序 |
| ----- | -------- |
| `0`   | 無     |
| `1`   | 緊急     |
| `2`   | 高     |
| `3`   | 中     |
| `4`   | 低      |

只有 `workspace_id` 和 `title` 是必填的；`description`、`priority`、
`assignee`（一個代理 id）和 `team_id` 都是可選的。該工具被歸類為供應商同步
寫入，執行前會請求你批准。

## 更新工單狀態

工單會依以下生命週期流轉：

```
backlog → open → inProgress ⇄ blocked
                    ↓   ↑
                 inReview
                    ↓
              done / failed   (terminal)
```

`done`、`failed` 和 `cancelled` 是終端狀態。`cancelled` 可以從任何非終端狀態
到達。`done` 和 `failed` 可以從 `inProgress` 或 `inReview` 到達；`open` 也可以
直接轉到 `blocked`。介面的狀態選擇器列出除 `failed` 以外的每一個狀態 —— 代理
會用 `fail_ticket` 標記該狀態。

如要變更狀態，可使用以下任何一種方式：

- 工單屬性欄中的**狀態**列，
- 清單中工單右鍵選單上的**狀態**子選單，
- 多選工單後，浮動欄上的**狀態**按鈕。

:::note[生命週期圖約束的是代理，而不是你]
從介面作出的每一項狀態變更都會被強制通過，完全繞過這張圖 —— 你可以把工單移到
選擇器列出的任何狀態，包括重新開啟一張 `done`、`failed` 或 `cancelled` 的工單。
選擇器不提供 `failed` 作為目標。上方的示意圖約束的是代理與自動化：
MCP 工具或對帳器嘗試的不合法轉換會被記錄並忽略，而不會生效。
:::

狀態變更會發出領域事件（`TicketStatusChanged`、`TicketCompleted` 等），這些事件
可以觸發管線。參見
[設定管線觸發器](/zh-HK/手冊/操作指南/管線觸發器/)。

## 指派工單

1. 開啟工單。
2. 在屬性欄中設定**負責人** —— 你自己、另一位工作區成員，或一個代理。

:::caution[指派不會啟動任何工作]
指派只記錄歸屬，別無其他。它不會建立空間、不會變更狀態，也不會派發代理 ——
`TicketAssigned` 是純粹的稽核訊號，背後沒有任何派發器。要讓代理開始工作，
請在空間中傳訊息給它（參見[與代理聊天](/zh-HK/手冊/操作指南/與代理聊天/)）。

唯一的例外：`TicketAssigned` 是一種你可以掛接管線觸發器的事件類型，因此你自己
編寫的範本可以對指派作出反應。
:::

## 新增標籤

標籤是從工單清單批量套用的，而不是在單張工單上 —— 屬性欄中沒有任何標籤控制項。

1. 將游標移到工單清單中的某一列並勾選其核取方塊。按需要勾選任意多列；
   一旦有任何項目被選取，就會出現浮動欄。
2. 在該浮動欄中，開啟**標籤**按鈕。
3. 選擇一個標籤。它會被加到每一張尚未有該標籤的選取工單上；現有標籤絕不會被
   清除。**清除標籤**會移除所有標籤。選擇器列出的是工作區中已經出現在某張
   工單上的標籤。代理可以透過 `update_ticket` 或 `tickets.patch` 新增名稱。

## 連結工單

關聯關係位於屬性欄中工單的**關聯**卡片上，或清單右鍵選單的**關聯至**之下。

1. 開啟工單，找到**關聯**卡片。
2. 按其新增控制項，然後選擇關係：

| 關係              | 含義                                    |
| ----------------- | --------------------------------------- |
| **子 issue…** | 這張工單的父項是另一張工單   |
| **父 issue…**    | 另一張工單是這張工單的子項 |
| **被阻擋…**   | 這張工單被另一張阻擋     |
| **阻擋…**     | 這張工單阻擋另一張            |
| **相關…**   | 對稱關係，不隱含方向         |
| **重複於…** | 這張工單是另一張的重複項        |

3. 選擇目標工單。

**被重複**會出現在卡片中，但不會出現在選擇器裏 —— 它是**重複於…**的逆向關係，
要從另一張工單設定。列出的每一個關聯都可以點擊以開啟被連結的工單，並可在游標
移上時移除。

父項與子問題關聯存放在工單本身，而不是作為連結列，因此刪除一張父工單會串聯到
它的子工單（見下文），而阻擋與相關連結則不會。

## 新增協作者

協作者是工單上的一份名冊 —— 記錄誰參與其中、以甚麼身份參與。

1. 開啟工單。
2. 按**新增協作者**卡片上的人形加號控制項。
3. 選擇一個代理。

三種角色分別是 **assignee**、**collaborator**（預設）和 **reviewer**。介面中的
選擇器只列出工作區代理，而且一律寫入預設角色；人員可以作為列出現，但不會在該
選單中提供。MCP 的 `add_ticket_collaborator` 工具接受一個 `role`。

新增協作者會寫入一列記錄，但不會發佈任何領域事件；它也不授予任何空間存取權限。
要把代理帶進某段對話，請改為從空間頂部把它新增為參與者 ——
參見[空間](/zh-HK/手冊/操作指南/空間/)。

## 刪除工單

使用屬性欄底部的**刪除工單**、右鍵選單，或多選後浮動欄上的刪除操作。

:::caution[刪除只在本機生效]
來自外部追蹤器的工單不會在那裏被刪除 —— 沒有任何供應商支援這項操作 ——
因此它可能在下一次同步時重新出現。刪除也會串聯：該工單的協作者和任何子工單
都會一併被刪除。
:::
