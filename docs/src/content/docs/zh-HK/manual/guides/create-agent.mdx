本指南說明如何把代理加入工作區，並把它設定到真正可以執行的程度。

每個工作區在建立時都會預置五個代理——一名 CEO，再加上 `qa`、`architect`、`engineer` 和 `librarian`——因此你通常在尚未設定任何代理之前就已經擁有它們。以下步驟對預置代理和新建代理同樣適用。

## 開始之前

- 你已身處某個工作區之內。整個介面位於 **設定 → 工作區 → 代理**（`/settings/workspace/agents`）。
- 代理需要一個後端。你可以在 **設定 → 伺服器 → 模型供應商** 下為內建執行框架連接一個供應商，也可以在託管 `cc_server` 的機器上安裝 Claude Code CLI。
- 如你想讓代理帶有技能，請先在 **設定 → 工作區 → 技能** 下安裝它們。代理表單只讓你切換工作區中已存在的技能。

## 加入代理

1. 開啟 **設定 → 工作區 → 代理**。
2. 點擊 **新增代理**。

這裏不會出現對話方塊，也沒有角色選擇器。系統會立即建立一個名為「未命名代理」的代理，並在右側的詳情面板中選取它。

你現在應該可以在左側的名冊中看到「未命名代理」，其詳情面板的 **設定** 分頁已開啟，而 **名稱** 欄位中包含「未命名代理」。

## 為它命名

- **名稱**——用於 @提及的簡短識別碼，例如 `alice`。提及解析會比對 `@` 及其後緊接的字詞字元，因此含有連字符、點號或空格的名稱永遠無法被提及。
- **標題**——供人閱讀的標籤，例如「資深程式員」。
- **系統提示**——可選的額外指示，會以「Agent instructions」區段的形式注入；它們不會取代組裝後提示的其餘部分。

點擊表單底部的 **儲存變更**。本頁上的每個欄位都由這一個按鈕儲存。

## 為它設定配接器和模型

**配接器** 下拉式選單會列出伺服器主機實際擁有的執行器。內建配接器一定會被找到（它就是伺服器本身）。只有在該主機上偵測到 Claude Code CLI 時，Claude Code 才會出現：

| 配接器                    | 後端                                          |
| ------------------------- | --------------------------------------------- |
| Control Center（內建）    | 行程內的代理迴圈——無需外部 CLI                |
| Claude Code               | `claude -p --output-format stream-json`       |

只有內建配接器會強制執行模式、執行中引導、暫停與恢復、完成契約和子代理。Claude Code 這些一樣都沒有。Cursor、Codex 以及其他模型供應商都掛接在內建配接器上，而不是作為獨立的執行器。

:::note[配接器留空即代表使用內建迴圈]
配接器未設定的代理會派發至 **Control Center（內建）**，也就是伺服器內部的迴圈，因此主機上無需安裝任何東西。若模型也未設定，它會向 Anthropic 索取其預設模型，所以一個完全未設定的代理，只有在你已連接 Anthropic 帳戶時才能執行。預置的專才代理出廠時兩者都沒有；對於任何你打算使用的代理，請把兩者都設定好。
:::

**模型** 下拉式選單由你所選的配接器決定。對於內建配接器，清單即時來自你在 **設定 → 伺服器 → 模型供應商** 下已連接的供應商，因此沒有儲存憑證的供應商會貢獻零個模型。

## 新增技能

**技能** 是一個晶片選擇器，涵蓋此工作區中已安裝的技能包。點按晶片即可切換；勾號標記表示已選取的項目。如果工作區沒有任何技能，該欄位會顯示「No skills available. Create skills in Settings → Skills first.」

你在這裏無法挑選程式庫自帶的技能。隨附技能的程式庫（技能位於 `.agents/skills/`、`.claude/skills/` 或 `.opencode/skills/`）會自動把它們貢獻給在該程式庫中工作的任何代理，而當它轉到另一個程式庫時，這些技能就會被替換——詳見 [以程式庫為界的技能](/zh-HK/手冊/概念/代理模型/#repo-scoped-skills)。

## 設定匯報關係與人設

- **直屬主管**——按名稱挑選另一個代理。這會建立頁首 **組織圖** 按鈕所顯示的匯報樹。它並不是團隊負責人在委派時使用的名冊——那名冊來自團隊的成員及其技能。
- **人設**——塑造語氣與行為的自由文字，例如：「偏好簡單、易讀的解決方案。為所有新程式碼撰寫測試。」

## 調整執行參數

- **推理力度**——可選項來自所選模型本身公布的等級：Low / Medium / High，在 OpenAI 風格的模型上還有 Extra High，在 Claude 風格的模型上則有 Extra High + Max。當所選模型未宣告任何思考等級時，此欄位會完全隱藏，並採用模型自身的預設值。
- **上下文視窗大小**——每次更換模型時，都會以該模型的上下文視窗預先填入，並為模型預設值、200k、500k 和 1M 提供一按即選的晶片。你在選定模型之後輸入的值會一直生效，直到下一次更換模型。
- **靜音逾時（分鐘）**——在這麼長時間沒有輸出之後終止執行。留空則使用按模式設定的預設值。

## 授予權限

**沙箱權限** 初始為「使用工作區預設值」。開啟開關即可為此代理設定，然後切換以下各項：

- **允許 git push**——注入代理推送所需的 GitHub 權杖
- **允許 GitHub API 呼叫**——讓代理讀取 PR、issue 和程式庫中繼資料
- **允許工單 API 呼叫**——注入工單供應商的 API 金鑰
- **允許一般網絡存取**——同時啟用內建執行框架的 `web_fetch` 和 `web_search` 工具

每次執行啟動時，憑證仲介都會檢查每個開關：某項能力若為關閉，就意味着相應的權杖永遠不會被簽發到該次執行的環境中。

:::caution[工作區預設值意味着伺服器那套保守設定]
留在「使用工作區預設值」的代理，執行時 git push、GitHub API 和工單全部為 **關閉**，而網絡為 **開啟**。設定 → 伺服器 → 診斷與隱私 下顯示的能力預設值只是用戶端的偏好設定。如你想讓某個代理推送或開啟 PR，請開啟開關並明確授予這些能力。

這些能力管控的是憑證與執行框架工具，與作業系統沙箱是相互獨立的一層。主機上存在沙箱時，`cc_server` 會把代理執行包裹在該沙箱中——Windows 沒有原生後端，而 Linux 和 WSL2 則需要 `bwrap` 和 `socat`。完整的邊界集合請參見 [沙箱與保安](/zh-HK/手冊/概念/沙箱與保安/)。
:::

## 驗證它能執行

1. 開啟 **設定 → 伺服器 → 模型供應商**，確認你所選的配接器回報的是已安裝的版本，而不是「找不到」。點擊 **重新整理** 可重新探測——探測在託管 `cc_server` 的機器上執行，而不是在你正在查看的這部機器上。
2. 開啟一個包含該代理的空間並向它傳送訊息，或者在現有空間中 @提及它。
3. 回到 **設定 → 工作區 → 代理**，選取該代理並開啟其 **日誌** 分頁。應該會出現一筆執行記錄，附有狀態徽章、時長、開始時間，以及它所使用的配接器。**檢視** 會開啟該次執行的事件串流。

如果完全沒有出現任何執行記錄，請按 [診斷代理](/zh-HK/手冊/操作指南/診斷代理/) 逐步排查。

## 刪除代理

在名冊中選取它。在 **設定** 分頁上，捲動到表單底部的 **危險區域**，然後點擊 **刪除**。
