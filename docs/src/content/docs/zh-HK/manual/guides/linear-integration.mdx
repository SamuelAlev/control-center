Linear 在 Control Center 中有兩種身分，而且兩者都是瀏覽器登入：你自己的，用於你
做的事；以及工作區的 Control Center 應用程式，用於代理與管線做的事。工單、項目、
連結、協作者、委派與指派全都對着 Control Center 自己的資料庫運作，無需任何外部
服務——參見[建立與管理工單](/zh-HK/手冊/操作指南/管理工單/)。

## 先決條件

- 伺服器能讓人們登入 Linear：經由 Control Center Connect，或使用伺服器自己的
  Linear 應用程式（[註冊你自己的 Linear 應用程式](#註冊你自己的-linear-應用程式)）。
  由伺服器擁有者在 **設定 → 伺服器 → 單一登入** 中選擇
- 一位工作區管理員，負責選擇 Linear 作為工單供應商並連接 Linear 自動化

## 為工作區選擇 Linear

1. 前往 **設定 → 工作區 → 整合**，找到**工單**卡片
2. 把**工單供應商**設為 **Linear**

你往後建立的工單都會蓋上 `provider: linear`。**本機**會把工單保存在這部伺服器
自己的資料庫中，並隱藏 Linear 相關列：沒有任何需要認證的對象。

## 登入 Linear

你自己的 Linear 登入位於 **設定 → 你 → 個人資料**，在**工單**卡片中：

1. 點擊**登入 Linear**
2. 在瀏覽器中批准
3. 使用伺服器自己的應用程式時，對話框會自行察覺。經由 Connect 時，請輸入瀏覽器
   顯示的 8 個字元代碼，或讓它透過 `control-center://` 連結開啟 Control Center

你從 Control Center 在 Linear 中做的任何事，都只使用這個登入，不會用其他任何東西。
如果你未登入，應用程式會請你登入，而不是以別人的身分行事。

這個登入在伺服器上的每個工作區都有效，除非某個工作區有自己的登入應用程式：該工作區會保有自己的 Linear 登入。卡片會說明哪一種適用。

## 連接 Linear 自動化

**工單**卡片（位於 **設定 → 工作區 → 整合**）中的**Linear 自動化**這一列，是工作區在 Linear 中的 Control Center 應用程式。工單同步、
管線與代理都用它寫入，因此自動建立的議題和評論會以 Control Center 的身分出現，
而不是某個人。

1. 由工作區管理員點擊**連接 Linear 以進行自動化**
2. 他在瀏覽器中為該 Linear 工作區批准這個應用程式，方式同上

之後該列會顯示「已連接到 _你的 Linear 工作區_」。只有工作區管理員能連接或中斷
連接它。

代理的沙箱中不會放入任何 Linear 憑證：代理透過 Control Center 自己的工具寫入工單，
這些工具會先詢問**寫入外部追蹤器**規則。

## 註冊你自己的 Linear 應用程式

當你選擇了**使用我自己的應用程式**時，就使用你自己的應用程式。伺服器自己的應用程式只在那種情況下適用：使用 Control Center Connect 或自訂 Connect 時，Connect 會執行每個通道（包括 Linear），伺服器的應用程式與服務 API 金鑰會保留但不使用。選擇了自家應用程式的工作區（[見下方](#為一個工作區設定自己的-linear-應用程式)）改用其自己的應用程式，無論伺服器處於何種模式。

1. 在
   [linear.app/settings/api/applications/new](https://linear.app/settings/api/applications/new)
   建立一個 OAuth 應用程式
2. 原封不動地加入 **設定 → 伺服器 → 單一登入 → 供應商應用程式 → Linear** 在
   **回呼網址**下顯示的兩個回呼 URL：
   `<server origin>/oauth/linear/callback` 和
   `<server origin>/oauth/linear_app/callback`
3. 把**用戶端 id** 貼到 Linear 區塊中

不需要用戶端密鑰：伺服器以 PKCE 登入。Linear 的重新整理權杖在 30 天未使用後便會
過期，因此伺服器每天會更新一次所有超過 20 天的 Linear 登入。

同一個區塊亦接受選填的**服務 API 金鑰**。它是伺服器自己的 Linear 憑證，供未連接
Linear 自動化的工作區進行自動化。請把它保存在**設定**中，或在伺服器的 `.env` 檔案
中寫成 `LINEAR_API_KEY`：若 `LINEAR_API_KEY` 被匯出到行程環境中，伺服器會拒絕
啟動。

## 為一個工作區設定自己的 Linear 應用程式

工作區可以改用自己的應用程式登入 Linear，而不使用伺服器的。只有工作區管理員或擁有者可以設定。

1. 按上方步驟建立 Linear OAuth 應用程式
2. 前往 **設定 → 工作區 → 整合**。在 **Control Center Connect** 卡片上選擇**使用我自己的應用程式**，然後按一下**套用**
3. 在**工單**下會出現 **Linear 應用程式**卡片。把該卡片在**回呼網址**下顯示的兩個回呼 URL，原封不動地加入 Linear 應用程式
4. 貼上它的**用戶端 id**，並可選擇為此工作區的自動化填入**服務 API 金鑰**

此工作區的應用程式之後會回應此工作區中所有 Linear 登入與自動化請求，不論伺服器以甚麼方式讓人登入。它絕不會退回伺服器的應用程式或 Connect：在設定用戶端 id 之前，此工作區的 Linear 會關閉，而該行會說明缺少甚麼。其服務 API 金鑰只在此處使用；若沒有它，同步就需要**連接 Linear 以進行自動化**。

**使用我自己的應用程式**對所有供應商同時生效：GitHub、Google Calendar 和 GIF 搜尋也只會在工作區自己的應用程式上執行，各自在同一頁中與其供應商並列設定。切換工作區的登入應用程式，或更改工作區的用戶端 id，會令此工作區中所有人登出 Linear 並中斷其自動化連線。他們會透過新的應用程式重新登入。已儲存的欄位在工作區切換回其他選項時會保留，但只會在**使用我自己的應用程式**下使用。密鑰只能寫入：卡片只顯示是否已儲存密鑰。伺服器上的其他工作區不受影響。

## 疑難排解

### Linear 這一列表示尚未設定登入

伺服器既沒有自己的 Linear 應用程式，也沒有 Connect。由伺服器擁有者在
**設定 → 伺服器 → 單一登入** 中選擇其一。當工作區使用自己的應用程式時，該行會改為顯示設定尚未完成：工作區管理員需在 **設定 → 工作區 → 整合** 的 **Linear 應用程式**卡片中加入用戶端 id。

### 工單同步因認證錯誤而失敗

工作區未連接 Linear 自動化，而伺服器也沒有服務 API 金鑰，因此同步沒有任何憑證
可用。由工作區管理員點擊**連接 Linear 以進行自動化**。

### 連接自動化時表示該 Linear 工作區已在別處連接

該 Linear 工作區的 Control Center 應用程式已經連接到另一部 Control Center 伺服器。
