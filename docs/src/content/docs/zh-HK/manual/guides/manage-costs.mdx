本指南說明如何查看代理執行的成本，以及如何為自主執行設定上限。

## 成本如何記錄

每一次代理執行都會寫入一份執行紀錄，記載其輸入 token、輸出 token、推理 token、快取讀取與快取寫入 token、以 cents 計算的預估成本，以及它所衍生任何子代理的成本。

定價來自 models.dev 目錄，它只用來為模型清單補充價格與上下文視窗，絕不是 model id 的來源。目錄無法定價的模型會記錄為 **$0**，而零成本的執行會排除在 **用量與費用** 摘要之外。因此本機的 Ollama 模型完全不會顯示任何花費，不過它的 token 數量仍會被記錄。固定費率方案（kimi-code、Claude 訂閱）只有在目錄沒有所服務模型的價格時才會如此；若目錄有價格，該次執行仍會按那些費率估算。在回退鏈之下，執行的計價依據是實際服務它的模型，而不是所請求的那一個。

## 查看你的花費

### 可觀測性 → 洞察

從側邊欄頁腳 → **可觀測性** 進入。首先會開啟**用量**分頁（累計 token 總數）；切換到第二個分頁**洞察**，就是主要的成本介面：

- 時間範圍選擇器：最近 24 小時、最近 7 天、最近 30 天，或所有時間
- 按代理、模型、狀態與角色分面篩選，以可移除的標籤呈現
- KPI 列：總執行次數、總成本、錯誤率、快取率、每秒 token 數、平均延遲與首個 token 時間，每項都附有與上一期間相比的變化（在「所有時間」下隱藏）
- 活動與成本圖表，以及**依角色的成本**細分，把支出分拆到主代理、其子代理與其顧問
- 按代理的表格，按成本排序，顯示前十項並附有顯示全部的切換開關。點按某一列，會把其他每個介面都篩選至該代理
- 細粒度的執行紀錄，會為所選的執行停靠一個對話紀錄抽屜

:::note[「所有時間」並非所有時間]
執行饋送會訂閱每個工作區中最近 2000 份執行紀錄，再篩選出目前作用中的工作區。在繁忙的多工作區伺服器上，較安靜工作區的較舊歷史就會落到這個窗口之外。
:::

### 設定 → 伺服器 → 模型供應商

此頁的 **用量與費用** 卡片會以單一美元金額顯示過去七天所觀察到的花費，附有按供應商的細分，以及（當供應商有公佈時）距離下一個配額視窗重設的時間。

### 單一代理的執行

**設定 → 工作區 → 代理** → 選擇一個代理 → **日誌** 會列出它的執行，附有狀態、時長、開始與完成時間、PID 與配接器。這個分頁**不會**顯示成本——請改用可觀測性 → 洞察中的按代理表格。

## 為自主執行設定上限

在空間的撰寫器中輸入的兩條斜線指令，是唯一帶有花費上限的執行：

```
/goal ship the auth refactor --budget 20
/loop keep the flaky tests green
```

- `/goal` 或 `/loop` 執行的每一分段，會在已計價的花費達到 **500 cents（$5.00）** 時停止。到達該數字的 80% 時，迴圈會先引導模型收尾並留下乾淨的交接，以免它在任務中途死去。
- 整個持久目標的上限是 **5000 cents（$50.00）**，除非你傳入 `--budget <dollars>`。監督器會把目標*剩餘*的預算貫穿到每個分段，因此明確指定的預算永遠不會被超出一整個分段。
- `--days N` 會加入以實際時間計算的期限，`--max N` 則加入執行次數上限。兩者都是選擇性啟用；沒有它們，目標就只受成本限制。
- 觸及其期限的目標會停在 `budgetExhausted`，而且只有提高預算才能恢復。

由於上限是按價格計算，目錄無法定價的模型永遠不會觸及它。這類執行改為受死循環重複防護、監督器在連續三次失敗後放棄，以及你自己所設限。

空間中的訊息、@ 提及或管線步驟都沒有花費上限。執行的結束時機，是模型停下、你把它停下，或死循環防護引導它。

## 減少 token 用量

### 壓縮冗長的對話

在空間的撰寫器中輸入 `/compact`。該指令會在用戶端被攔截，永遠不會落到對話紀錄中；伺服器會把較舊的歷史摺疊成一份有錨點的摘要，對話便以壓縮後的上下文繼續。

當代理正處於回合中途，或沒有足夠舊的內容可摺疊時，壓縮會被拒絕。內建運行器在歷史接近模型的上下文視窗時，也會自行壓縮。

### 刻意選擇力度等級

代理的**推理力度**（設定 → 工作區 → 代理）提供所選模型公佈的任何等級。等級越高，花費的推理 token 越多。請把最高等級留給真正需要它們的工作。

### 為每個代理選擇模型

模型是每個代理各自的欄位，因此格式化或分流代理可以跑在便宜的模型上，而架構代理則跑在昂貴的模型上。在可觀測性 → 洞察中按模型篩選按代理表格，即可看出哪個配對才真正在耗費你的成本。

### 找出 token 數量異常龐大的執行

開啟洞察的執行紀錄（最新的 50 次已篩選執行），並為任何不尋常的情況打開對話紀錄抽屜。常見成因是過長的系統提示或人格、本應被壓縮的上下文，以及本應拆成幾項較小工作的任務。

## 若預算在正常途徑之外被設定會怎樣

為求完整，若 `monthlyBudgetCents` 或某項預算政策被直接寫入代理資料列：

- 預算是在執行完成**之後**評估，而不是在派發之前。一個掛在執行完成上的監聽器，會把代理本月至今日的支出與其上限比較。
- 越過軟性門檻（預設 80%）會記錄一宗警告事故，並發出一個 `BudgetThresholdCrossed` 事件，你可以把管線觸發器掛在它上面。
- 用盡預算會記錄一宗硬性事故、發出同一個事件，並把代理的生命週期狀態切換為 `paused`。
- 派發前的封鎖確實存在，但只有在排程復原時，才會由孤兒執行清理器與擱淺工單對帳器查閱——一般的派發永遠不會觸及它，而派發路徑上也沒有任何東西會檢查 `paused` 狀態。唯一可見的訊號是組織架構圖上的生命週期徽章。
