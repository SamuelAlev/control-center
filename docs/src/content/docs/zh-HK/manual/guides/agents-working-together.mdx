工作區中的代理可以互相提問、諮詢專家、要求審核、傳送訊息或委派工單。這些都不需要代理坐著等待：提出問題的代理可以繼續工作，或結束其回合，並在答覆抵達時於其自己的對話中被喚醒。

## 向其他代理提問

代理使用 `ask_agent` 提問，方式有兩種：

- **等待**（預設）：代理會阻塞，直至答覆抵達，預設最多 600 秒，最多 1,800 秒。
- **在背景進行**：呼叫會立即返回，代理繼續工作。

無論哪種方式，問題都會在傳遞前被記錄。若在呼叫期間未有答覆返回，提問的代理會在另一個代理的執行結束時被喚醒一次，並附上答覆：可能是已回答、失敗，或在 24 小時後仍無答覆而過期。在此期間，它可能會收到以下三則訊息，每則至多一次：另一個代理已承諾稍後回答、它正在等待某人手處理，或它已在用量上限處停止。這些訊息都不算答覆。

`consult_agent`（引入最匹配的專家）、`request_peer_review`（對某項審核發現的第二意見）及 `send_to_agent`（單向訊息）都會透過同一個佇列運作。`send_to_agent` 會說明另一個代理是否已被喚醒、訊息是否會排在其目前執行之後等待，或為何被拒絕。

另一個代理會把這個問題視為來自另一代理的資料，而非必須遵從的指示，並且它不能執行斜線指令。

## 交接工作

- **委派的工單**（`delegate_task`）在工單定案時，會喚醒委派它的代理，喚醒發生在它委派時所在的對話中。
- **團隊成員的執行**若由組長以 `@mention` 或訊息啟動，會在其結束時喚醒組長，喚醒發生在它喚醒該成員時所在的對話中。（提問會由其回覆回答，委派的工單則由其工單回答。）
- 在指揮者模式（`/vibe`）中，**背景工作程式**會把其結果交給指揮者，而指揮者會繼續工作。
- **`@mention`** 提及代理，以及空間的審核代理，都會以同樣方式傳遞，即作為喚醒。

代理可以在不提問的情況下查看另一個代理正在做的事：`agent_activity` 會顯示另一個代理的狀態、其目前的工具及其最近的訊息，且不會喚醒任何人。

## 限制

無論代理怎樣說，伺服器都會強制執行以下限制：

| 限制 | 數值 |
| --- | --- |
| 提問與交接的鏈條可以有多深 | 3 |
| 循環（一個代理向另一個提問，而該另一個代理經由其他代理，正在等待它） | 拒絕 |
| 每個提問代理的待處理提問數 | 10 |
| 每個被提問代理的待處理提問數 | 20 |
| 對同一代理重複同一問題 | 在 10 分鐘內拒絕 |
| 一對代理之間的訊息 | 每分鐘 10 則 |
| 訊息或答覆的長度 | 16,384 個字元 |

委派同樣會考慮提問代理的自主權與預算：代理不能把工作交給自主權或金錢比它更多的另一個代理。你親自傳送的訊息則永遠不受此限制。

當被提問的代理在供應商的用量上限處停止時，若重設時間早於提問過期，其執行會等待重設；否則，該提問會立即失敗，並告知提問者原因。

## 查看代理正在等待什麼

在對話中，**一般** 面板的 **提問** 部分會列出其他代理向該對話中的代理所提出的問題：對象、類別（**問題**、**諮詢** 或 **審核**）、時間，以及狀態（**等待中**、**已回答**、**失敗**、**已過期** 或 **已取消**）；適用時會顯示 **已承諾稍後回答** 或 **在背景進行**。失敗的提問會說明原因，例如 **其執行已在供應商的用量上限處停止。**

任何可存取該空間的人都可以 **取消提問**。提問的代理不會因此被喚醒，而另一個代理的執行也不會被停止。

等待代理的答覆、訊息及已完成的工作，也會顯示在輸入框上方的狀態列中，並列出它正在等待的其他項目（請參閱[排程與喚醒](/zh-HK/手冊/操作指南/排程與喚醒/#查看等待中的項目)）。
