目標是代理持續努力直至完成的標準獲得滿足的工作。代理以**段**進行：即伺服器接連啟動的有限執行，即使重新啟動也會繼續，直至目標獲得驗證、由人手結束，或達到某個上限。代理不能單憑表示已完成而結束目標。伺服器會先執行目標的檢查，再由審核代理檢視結果。

## 開始目標

在對話的輸入框輸入 `/goal` 和目標內容：

```text
/goal --budget 20 --days 2 --check "make test" make the importer handle files over 2 GB
```

輸入 `/goal` 後先接文字，會開啟目標訪談。訪談會詢問成功準則、必須通過的檢查、界限與停止條件，並可選擇另設審核代理、每段都從頭開始，以及讓代理自行回答其問題。每個步驟都可以略過。

| 旗標 | 意思 |
| --- | --- |
| `--budget <dollars>` | 整個目標最多可花費的金額，預設為 50 美元 |
| `--max <N>` | 目標最多可執行的段數，預設沒有上限 |
| `--days <N>` | 期限，從現在起計的指定天數 |
| `--check "<command>"` | 必須通過才能完成目標的指令，在工作樹中執行。可重複使用以加入更多，最多 5 個 |
| `--checker <agent>` | 另一個代理，用來審核目標是否已完成的宣告，可用名稱或 ID 指定 |
| `--fresh` | 每段都不附帶對話紀錄開始，只依據目標及其筆記 |
| `--unattended wait` 或 `--unattended assume` | 沒有人回應時，代理的問題會如何處理（請參閱[無人回應時](#無人回應時)） |

- 旗標可以放在訊息的任何位置。未知的旗標、重複的旗標、錯誤的值，以及超過 5 個檢查，都會被拒絕，你的草稿會留在輸入框中，並附上原因。
- 目標開頭的數字是目標內容的一部分。若要限制段數，請使用 `--max`。
- 只有你自己輸入的訊息才會被當作 `/goal`。同樣的文字若來自代理、管線或喚醒，則只是一般訊息。
- 同一個工作區中，每個代理一次只追求一個目標。當第一個目標仍在進行時，同一代理的第二個 `/goal` 會被拒絕。

### 完成的標準

目標可以包含一些段落，成為目標的約定：

```text
/goal make the importer handle files over 2 GB

## Success criteria
- A 3 GB fixture imports without running out of memory
- The progress bar reaches 100%

## Boundaries
- Don't change the public API

## Stop conditions
- A migration would drop data

## Checks
- `make test` (300 s)
- environment task `test` (600 s)
```

- **成功準則**：最多 12 項，每項最多 300 個字元。每項都是審核者可以確認的事項。
- **檢查**：最多 5 項。檢查在工作樹中執行，或作為空間的[環境](/zh-HK/手冊/操作指南/環境/)中的一個具名任務執行。每項預設有 300 秒，最長 1,800 秒。
- 超出上限的段落會被拒絕，而不會被截短。

沒有成功準則的目標，會由代理自行決定何時完成；沒有檢查的目標則只靠審核。目標頁面會說明這點。

## 目標如何繼續

每段都是一次執行，上限為 5 美元或預算剩餘額，取兩者中較低的數額。每段結束後，伺服器會依該段的結果決定下一步：

- **有進展。** 下一段會開始。
- **正在等待它所設定的東西**：排程、監看、向其他代理提出的問題，或已委派的工單。目標會等待它。若沒有任何回覆，伺服器會在 20 分鐘後再查看，之後為 40、80、160 分鐘，然後每 240 分鐘查看一次。卡片會顯示 **正等待它所設定的工作 · 最遲將於** 某個時間再次查看。
- **沒有進展。** 進展指工作樹因該段自身的工作而改變、檢查清單有所變動，或代理做了新的事情。連續 3 段沒有進展後，目標會暫停：**最近幾段沒有進展。**
- **等待過久。** 等待 24 小時後，或期間沒有進展而又為新設定的事項等待了 6 次後，目標會暫停：**在多段沒有進展之後，正在等待。**
- **失敗。** 伺服器會在 30 秒後重試，之後間隔更長，最長至 15 分鐘。連續失敗 3 次後，目標會失敗。
- **它向人提出問題。** 目標會保持不動，直至有人回答：**需要人手處理**。

目標也會在預算耗盡（**預算已用盡**）、段數上限或期限到達時停止。

## 代理表示已完成時

代理會就每項準則提供證據，宣告目標已完成。之後：

1. **伺服器會執行檢查**，在沙箱中執行，絕不直接在伺服器的機器上執行。以非零代碼退出的檢查即告失敗。若檢查根本無法執行（找不到指令、不可執行，或環境任務不存在），即屬損壞：目標會停下來等待人手處理，並顯示 **此檢查無法執行：** 及該指令。若伺服器沒有可用的沙箱，目標會停下來，並顯示 **沒有可用的沙箱來執行其檢查。**（若伺服器擁有者已為所有執行關閉沙箱，則屬例外：檢查會像代理自己的指令一樣在該處執行。）若檢查失敗後工作樹沒有任何改變，則不會重新執行。
2. **審核代理會檢視結果**，前提是所有檢查都已通過或沒有檢查。審核代理是目標的審核代理；若沒有，則為空間的審核代理；再沒有，則為目標自身的代理。它以唯讀方式執行，不附帶對話紀錄：它可以讀取檔案及檢查的輸出，但不能更改任何東西、執行指令或喚醒其他代理。它也會取得代理所更改的測試與檢查腳本的完整差異，並把代理在對話及其筆記中所寫的內容視為聲明，而非證據。對於沒有準則的目標，它會從整體目標來判斷。它會回答目標是已完成、未完成，或無法判斷。
3. **已完成**：目標隨即完成。**未完成**：代理會取得審核代理的意見，並繼續工作。若連續 3 輪都是未完成，或審核代理無法判斷，目標會等待你決定：**等待審核：它表示已完成，但未有任何確認**。

你在審核代理執行期間輸入的訊息，不會傳送給審核代理，審核結束時也不會送出。該訊息會保持排隊，等待代理的下一段。若之後沒有下一段，該訊息會保留給你，並列於 **傳送已保留的訊息** 之下。

若審核代理無法執行（已被刪除，或所屬的適配器無法保持唯讀執行，例如 ACP 代理），目標會暫停：**其審核代理無法使用。請選擇另一個審核代理，然後繼續。** 沒有其他代理會在你未有指示的情況下代為接手。

若審核代理與目標的代理來自不同供應商，則較不容易與之有相同的盲點。若沒有另設審核代理，代理會審核自己的工作，而目標會記錄 **由其自身驗證（沒有另設審核代理）**。

## 追蹤目標

- **在對話中**：**一般** 面板內的目標卡片會顯示保留狀態、段數、與預算相比的花費、剩餘時間、完成的標準、檢查，以及最近一次的判定。
- **目標頁面**：側欄 → **目標**。目標會分為 **等待審核**、**進行中** 及 **已結束** 三組。
- **單一目標的頁面**：打開一個目標，即可看到 **目前狀況**（段數、花費、期限、沒有進展的次數，以及接下來的安排）、**完成的標準**、**驗證**（最近一輪：宣告、每項檢查及其輸出、按準則逐項的審核）及 **排程與喚醒**。每個目標都有自己的網址（`/workspaces/<workspace>/goals/<goal id>`），因此你可以分享連結。

在手機上，目標畫面可以開始一個附有檢查及段數上限的目標，並顯示相同的目標及保留狀態。

## 更改或停止目標

| 操作 | 誰可以操作 |
| --- | --- |
| **暫停目標**、**停止目標** | 可存取該空間的任何人 |
| **繼續目標**、**提高預算** | 只限啟動該目標的人（若目標並非由任何人啟動，則限工作區管理員） |
| **編輯**完成的標準、**更換審核代理** | 在目標暫停期間，只有發起該目標的人（若無人發起，則為工作區管理員），並且對該空間的程式庫具寫入權限 |
| **核准完成** | 在目標等待審核期間，可存取該空間的任何人。由管線發起的目標：只有發起該執行的人（若無人發起，則為工作區管理員）。 |

- 在代理的執行中按 **停止**，會令目標暫停（**已由人手暫停**）。其待處理的喚醒會等到你將目標繼續後才進行。
- **核准完成** 會以你的判斷將目標結束為已完成，目標會記錄 **由人手在沒有通過檢查的情況下結束**。
- 用盡預算的目標，只有在提高預算後才會繼續。
- 當發起某目標的人離開工作區時，該目標會立即暫停並等待審核，其執行中的代理亦會被停止。沒有人可以繼續它；任何可存取該空間的人都可以停止它。每日摘要會把它列給工作區管理員。

## 無人回應時

當某段向人提出問題或要求批准，而無人回應時，請求預設會等待 72 小時。之後，批准會被視為拒絕，問題會被視為未獲回答，目標會暫停：**給人手的一個問題或核准請求未獲回答。** 提出請求的執行之後不會再獲得回答：它所再提出的任何其他事項都會立即被拒絕，它會盡可能完成手上的工作。工作區管理員可在 **設定 → 工作區 → 排程 → 無人回應時** 下設定時間（1 小時至 7 天）。每天在所設定的時間，你會收到一則摘要，列出所有等待你處理的事項。

使用 `--unattended assume` 時，若在 10 分鐘內無人回答，且其停止條件允許，代理會說明它的假設並繼續進行。此規則只適用於問題，批准絕不會被假設，審核也絕不會作出假設。

## 用量上限與重新啟動

- **供應商用量上限。** 當某段在供應商的用量上限處停止，且供應商表示何時重設（7 天以內），目標會暫停而不計為失敗：**已在用量上限暫停 · 某時間繼續**。重設後 30 秒會繼續。若這樣的暫停達 8 次，目標會等待你處理：**它太常觸及用量上限。請檢視後再繼續。** 任何一次繼續都會重新計算次數。ACP 代理不會回報重設時間，因此它們的目標不會因用量上限而等待。
- **伺服器重新啟動。** 目標在重新啟動後依然存在。被重新啟動中斷的段會重新開始，目標的排程及待處理的喚醒都會保留。

## 目標之後的改進

目標通過驗證後，一個簡短的唯讀審核（最多 1 美元）可能會提出改進建議：記憶事實、政策、關於代理的註記，或對技能的更改。輸入 `/refine` 可要求對對話中的工作進行同樣的審核。每個對話每 20 分鐘最多只會執行一次審核。

建議會顯示在 **改進** 頁面（側欄 → **改進**）。打開其中一項，即可看到它會更改什麼、依據為何，以及 **接受**、**拒絕** 或 **回復**。

- 除非有人接受，否則建議不會改變任何東西。建議會在 30 天後過期。
- 對技能或整個工作區政策的更改，需要工作區管理員決定（**由管理員決定**）。
- 技能的更改會儲存為獨立的修訂版本。按 **執行評估** 可將其與目前的技能作比較；只有在評估通過後才能 **接受**。評估通過的條件是：完整執行，且使用更改後的技能所成功解決的執行次數，至少與使用目前技能時相同；頁面會顯示兩個數字。若技能在評估後有所改變，請再次執行評估。
- **回復** 會還原先前的文字，但前提是此後沒有人更改過它。

## 在管線中

管線可以用 **Pursue a goal** 步驟（`goal.pursue`）啟動目標。該步驟會等待目標結束，並傳遞其摘要與判定。請參閱[管線步驟](/zh-HK/手冊/參考/管線步驟/)。
