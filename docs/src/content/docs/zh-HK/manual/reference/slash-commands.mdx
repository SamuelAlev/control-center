在空間的輸入框中輸入的指令。它們按生效位置分為三個群組，而這個差別很重要：**本機**指令永遠不會以訊息形式傳送，因此既不會出現在轉錄中，也不會到達任何代理。

| 在哪裏執行 | 代表甚麼                                                                    |
| ------------- | ---------------------------------------------------------------------------------- |
| **本機**     | 在用戶端處理（或由用戶端發起的伺服器操作）。該指令永遠不會以訊息形式傳送，因此沒有代理會看到它。 |
| **旁路**      | 針對這段對話做一次伺服器端模型呼叫。對話不會被改變。 |
| **派發**  | 為訊息所啟動的執行設定一個模式或指示。                            |

---

## 指揮一次執行

### `/plan`

**本機 → 派發。** 為對話啟用計劃模式：一個完全唯讀的 worktree，以及上限為 `read` 的工具介面。代理的交付物是一份計劃，而不是一次編輯。單獨一個 `/plan` 只會切換模式，永遠不會以訊息形式傳送；如果帶上提示詞，該行其餘的內容就是啟動這次執行的東西。

### `/goal <objective>`

**派發。** 啟動一個自主目標，目標監督器會在各個分段之間以及重啟後重新派發它。

先輸入 `/goal` 再跟上文字，會開啟**目標訪談**——這是一個簡短的流程，在草稿集齊以下全部五項之前拒絕接受它：評估者毋須主觀判斷即可裁定的成功標準、一條確切的驗證指令、嘗試次數上限、範圍邊界，以及停止條件。每一步都提供*略過並按原樣執行*：訪談只是預設做法，而不是一道關卡。

`/goal pause`、`/goal resume` 與 `/goal drop` 不是斜線指令。暫停、繼續與停止位於側邊欄中該對話的目標清單上。目標本身可用的起始旗標有 `--budget <dollars>`、`--max <N>`（執行預算）與 `--days <N>`（截止時間）。已觸及成本上限的目標，只能透過提高該上限來恢復，而且要在同一個側邊欄控制項中操作。

:::note[它為何非打斷不可]
自主目標是含糊簡報真正昂貴的唯一場合。執行會為一個沒有人定義過「完成」的目標工作數小時，然後按自己的標準報告成功。五個問題，比一次甚麼時候「感覺完成了」就算完成的通宵執行更便宜。
:::

### `/loop [budget] [task]`

**派發。** 反覆迭代直至完成。接受一個界限：`/loop 10`、`/loop 30m`、`/loop 1h30m`、`/loop 10 minutes fix the tests`。

一個*看起來*像限制的權杖（以數字或正負號開頭）如果解析失敗，就是硬錯誤。普通文字就是普通文字，因此 `/loop keep going until the tests pass` 是一個帶行內提示詞的無界迴圈，而不是一次誤解析。

### `/vibe [task]`

**派發。** 把工作階段變成一名**指揮者**：它自己的工具降為 `read` 加上五個工作程式動詞，實際編輯交由背景工作程式完成。參見[指揮背景工作程式](/zh-HK/手冊/操作指南/指揮背景工作程式/)。

工作程式絕不會比該模式活得更久——退出會終止其中每一個。

## 管理上下文

### `/compact`

**本機 → 伺服器。** 把較舊的歷史摺疊成一份附有錨點的摘要，並在壓縮後的上下文上繼續。沒有面向模型的參數：該指令永遠不會以訊息形式傳送，而壓縮程序也不接受聚焦提示。

### `/shake [target]`

**本機 → 伺服器。****不**做摘要地丟棄沉重內容：不呼叫模型，每一個字都保留，只把沒有人會再讀一遍的大塊內容清空。

| 目標        | 丟棄內容                             |
| ------------- | --------------------------------- |
| `tool_output` | 無異常的較舊工具結果（預設） |
| `images`      | 舊截圖，保留其文字 |
| `all`         | 兩者                              |

這就是「我的上下文很臃腫，但我又不想要摘要」時的逃生出口。

### `/context [agent]`

**本機。** 在獨立的分頁中，為這段對話的代理開啟上下文瀏覽器：它上下文窗口的每一個分段與部分——系統提示、技能、上下文檔案、工具 schema、歷史與影像——並顯示每一項的耗費，以及它背後的逐字內容。

該分頁以（空間、代理）配對為鍵，因此執行兩次會重新聚焦同一個分頁，而不是把同一份分解堆疊成多份。

在擁有**多於一個代理**的空間中，單獨一個 `/context` 會開啟頁首的上下文計量器正在讀取的那個窗口——也就是最近在這裏工作過的代理，即訊息位於軌跡最底部的哪一個——而該分頁會標示為 `Context · <name>`，以說明它屬於誰。要切換到另一個，就指名它：`/context qa`（`@` 是選填的）。輸入的名稱會精確解析，絕不模糊匹配：兩個代理持有兩個不同的窗口，因此一次差之毫釐卻開啟了另一個窗口的匹配，會是對一個你並沒有提出的問題給出看似合理的答案。

空間頁首中的上下文計量條晶片背後也是同一個瀏覽器，它跟隨同一個代理——指令與該晶片對於這裏「上下文」所指為何，永遠不會產生分歧。

## 詢問這段對話

這些指令花費一次模型呼叫，並且**絕不改變對話**。代理下一個真正的回合看到的，與它本來就會看到的完全一樣，而這正是「詢問」的全部價值所在。

### `/handoff [focus]`

**旁路。** 為冷啟動接手這項工作的人寫一份交接文件：任務是甚麼、已經了解到甚麼、還剩甚麼。

### `/btw <question>`

**旁路。** 回答一個關於目前工作進展的問題，而不把問題或答案寫進轉錄。

:::note[兩個指令，一套實作]
兩者形狀相同——拿現有的對話照原樣，就它問一個問題，兩邊都不持久化。只實作一次，因此不會各自漂移出兩個不同的「截至目前為止的上下文」概念。
:::

## 導覽與匯出

### `/tree`

**本機。** 開啟分支導覽器：對話在哪裏分叉、目前位於哪一條路徑，以及如何回到你離開的那一條。參見[分支一則對話](/zh-HK/手冊/操作指南/分支對話/)。

### `/export`

**本機。** 把對話寫成一個自包含的 HTML 檔案——可摺疊的工具卡片，沒有樣式表、沒有指令碼、沒有圖片寄存服務。在桌面端會存到 `Documents/ControlCenter/exports/`，在網頁端則會下載。

### `/dump`

**本機。** 把轉錄以 markdown 形式複製到剪貼板，工具呼叫放在可摺疊的區塊中。推理內容被刻意排除在外：貼進 bug 報告的轉錄是要給人閱讀的。

## 其他指令

### `/todo [subcommand]`

**本機。** 檢視並編輯該對話持久化的待辦清單。單獨一個 `/todo` 會開啟編輯器。子指令：`append`、`start`、`done`、`drop`（別名 `rm`）、`edit`、`copy`、`export`、`import`。

### `/skill:<name> [args]`

**派發。** 套用一個已安裝的技能。技能位於它們自己的 `skill:` 前綴之下，因此與內建指令不共用命名空間——否則，一個名為 `plan` 的技能將永遠無法被觸達。

### `/<your-command> [args]`

**派發。** 程式庫中 `.agents/commands`、`.agent/commands`、`.claude/commands`、`.codex/commands` 或 `.opencode/commands` 下的任何 markdown 檔案。巢狀的 `foo/bar.md` 也可以透過 `foo:bar` 觸達。

模板化：`$1`、`$@`、`$@[start:length]` 與 `$ARGUMENTS`。frontmatter 可以設定 `description`（輸入框自動補全）。`allowed-tools` 與 `model` 會從檔案中解析出來，但使用者指令的呼叫目前只會把參數替換進內文——它們不會改變該次執行的模型或工具介面。

使用者自行編寫的指令優先於同名的技能——它是人類帶着參數刻意呼叫的一條快捷方式。

## 魔法關鍵詞

它們不是指令。提示詞中任何位置出現的一個小寫獨立單詞，都會為該回合附加一條隱藏指令。

| 單詞          | 效果                                                             |
| ------------- | ------------------------------------------------------------------ |
| `ultrathink`  | 該回合使用最高推理力度                              |
| `orchestrate` | 並行委派互相獨立的工作，並驗證每個階段        |

匹配器刻意對邊界要求嚴格。`orchestrate,` 會匹配；`orchestrated`、`orchestrate.ts`、`foo::orchestrate` 與 `orchestrate()` 不會，而且圍欄程式碼區塊、行內片段與 XML 區塊會先被遮蔽。否則，貼上一段堆疊追蹤就會改變代理的行為。
