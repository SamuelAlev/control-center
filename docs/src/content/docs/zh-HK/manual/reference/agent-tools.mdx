這些是內建代理執行框架直接註冊、**綁定伺服器端資源**的工具——語言伺服器、結構化搜尋、除錯器、核心、程式碼模式指令碼、提問與工作程式控制——有別於它橋接進來的 [MCP 工具](/zh-HK/手冊/參考/mcp-工具/)，以及執行框架所提供的通用檔案、搜尋與 shell 工具。它們不在 MCP 註冊表上：外部 MCP 用戶端看不到它們，因為每一個都綁定着一項伺服器端的即時資源——一個語言伺服器行程、一個除錯配接器、一個直譯器——而該資源只屬於一次執行。

這裏每一個工具，只有在它的支撐資源為本次執行接入之後才會註冊——語言伺服器或除錯監督程式、一個 tree-sitter 解析器、一個核心工廠、一個提問連接埠、一份 vibe 名冊。對*這次檢出*的語言伺服器或除錯配接器所做的偵測，是另一項更靠後的檢查（`status` / `adapters`）：那些工具會一直留在工具介面上，好讓代理能問清楚為甚麼甚麼都用不了，而不是靠猜。

## 核准層級

每個工具都會宣告一個層級，而層級決定的是**哪些介面能看到它**——而不只是它是否會提示。計劃模式與唯讀子代理都限制在 `read`，因此 `write` 或 `exec` 層級的工具根本不會出現在它們的 schema 中。

| 層級 | 含義 | 這裏的工具 |
| --- | --- | --- |
| `read` | 無副作用 | `lsp`、`ast_grep`、`ask_user`、`repl`，以及五個 `vibe_*` |
| `write` | 會改動檔案 | `lsp_rename`、`ast_edit`、`resolve` |
| `exec` | 啟動或控制一個行程 | `debug`、`eval` |

## 直接呼叫、僅指令碼或首次使用時載入

當伺服器能夠運行指令碼時，執行會直接呼叫少數工具，其餘工具則透過[`repl`](#repl--運行一段呼叫你工具的指令碼)指令碼觸達；完整規則見[程式碼模式](/zh-HK/手冊/概念/程式碼模式/#代理直接呼叫哪些工具)。本頁所列工具的情況如下：

| 工具 | 有 `repl` | 沒有 `repl` |
| ---- | ----------- | -------------- |
| `repl` | 直接 | 不存在 |
| `ask_user` | 直接 | 直接 |
| `lsp`, `lsp_rename`, `ast_grep`, `ast_edit`, `resolve`, `debug` | 僅指令碼 | 首次使用時載入 |
| `eval` | 首次使用時載入（指令碼不能呼叫它） | 首次使用時載入 |
| `vibe_*` | 在 Vibe 模式中直接呼叫，絕不由指令碼呼叫 | 在 Vibe 模式中直接呼叫 |

標記為「僅指令碼」的工具，在伺服器無法運行該執行的指令碼後，改為在首次使用時載入（[指令碼無法運行時](/zh-HK/手冊/概念/程式碼模式/#指令碼無法運行時)）。

## `lsp` — 語言伺服器查詢

當一次執行擁有語言伺服器監督程式與工作目錄時才會註冊。伺服器能否真正作答，是在呼叫時按**交集**來偵測的：根標記必須存在，*並且*伺服器二進位檔必須能被解析到。只有其中一項成立都不會啟動任何伺服器——`status` 會如實說明——而不是悄悄靠猜。

伺服器只來自內建的表格；不會讀取存放庫的 `lsp.json`。在沙箱中執行時，每次執行都有自己的語言伺服器工作階段，因此伺服器會隨每次執行重新啟動。只有在執行處於沙箱中時，才會使用專案本地的二進位檔（`node_modules/.bin`），而專案根目錄絕不會解析到該次執行的工作目錄之上。

定位是由 `line` 加一個 `symbol` 子串指定的，而絕不靠列號。被要求給出列號的模型只能靠猜，而猜錯會解析成同一行上的另一個符號——一個看起來正確、說的卻是別的東西的答案。在導覽類操作中省略 `symbol` 是一種錯誤，而不是默認猜第一列。

| 操作 | 引數 | 傳回 |
| --- | --- | --- |
| `diagnostics` | `file`（或 `"*"`） | 錯誤與警告；`"*"` 改為執行專案檢查器 |
| `definition` | `file`, `line`, `symbol` | 符號宣告的位置 |
| `type_definition` | `file`, `line`, `symbol` | 其型別宣告的位置 |
| `implementation` | `file`, `line`, `symbol` | 具體的實作 |
| `references` | `file`, `line`, `symbol` | 每一處使用，上限 50 處 |
| `hover` | `file`, `line`, `symbol` | 簽章與文件註解 |
| `symbols` | `query` 或 `file` | 以 `query` 做工作區搜尋（上限 100）；以 `file` 取文件符號（上限 200） |
| `code_actions` | `file`, `line`, `symbol` | 伺服器提供的快速修正 |
| `status` | — | 哪些伺服器正在執行，以及各自對應哪些根 |
| `reload` | — | 為這個根重新啟動伺服器 |

### 寫入時的診斷

真正的回報不在工具本身。`write`、`edit` 與 `apply_patch` 都被**包了一層**：寫入之後，檔案會經語言伺服器同步並儲存，而只有**新引入的**診斷會被併入工具結果。代理在弄壞組建的那一刻就知道自己弄壞了，毋須記得去問。

已經報告過的診斷，會由一份按執行維護的帳簿抑制，該帳簿以嚴重程度、代碼與訊息為鍵——刻意排除了位置，因此僅僅向下移動了四行的診斷，不會被當作新增而重新報告。

## `lsp_rename` — 全專案重新命名

它是一個獨立的 `write` 層級工具，理由只有一個：層級決定可見性。把重新命名併入 `lsp`，要不是把改寫程式庫的能力交給一個唯讀的探索者，就是讓每一次 `hover` 都要先過一道核准提示。

| 引數 | 含義 |
| --- | --- |
| `file` | 符號所在的位置 |
| `line` | 由 1 開始計數的行號 |
| `symbol` | 在該行上標識它的子串 |
| `new_name` | 改成甚麼名稱 |

## `ast_grep` — 結構化搜尋

它按**形狀**而不是按文字尋找程式碼。`$NAME` 匹配任意節點，`$$$NAME` 匹配一串同層節點，`$_` 則是萬用字元，不綁定任何東西。

令它成為一個匹配器、而不只是一條多繞幾步的正則表達式的特性在於：同一個模式中重複出現的元變數，必須捕獲相同的文字。

```
ast_grep(pattern: "if ($X != null) $X.dispose()", language: "dart")
```

它會匹配處置自己所檢查對象的守衛，而**不會**匹配處置其他東西的守衛。

| 引數 | 含義 |
| --- | --- |
| `pattern` | 一段帶元變數的程式碼片段 |
| `path` | 要搜尋的檔案或目錄；預設為整個工作區 |
| `language` | 隨附的語法 id（`dart`、`python`、`rust`、`c` 等）。當 `path` 指向單一檔案時會被推斷出來 |
| `max_results` | 預設 50 |

:::note[模式由與該檔案相同的語法解析]
因此 `dispose(x)` 無論怎樣加空格、換行或包裹，都能匹配到這個呼叫——也絕不會匹配字串常值或註解裏出現的相同字元。
:::

:::caution[片段是放在支架中解析的，而不是裸着解析]
`dispose(x)` 當作 Dart 頂層內容裸着解析時，是一個完全合法的*函式簽章*。模式編譯器會依次嘗試一整套上下文（陳述式、運算式、類別成員、宣告），並採用第一個接受該片段的上下文。沒有任何上下文接受的模式，會被報告為無法解析，而不是被搜尋一番後悄悄查無結果。
:::

## `ast_edit` — 結構化重寫，先暫存

匹配方式相同，另外還接受一個 `rewrite` 模板，把元變數代回其中。**不會寫入任何內容。** 改動會被暫存起來，而結果中會給出一個 `edit_id`。

```
ast_edit(pattern: "dispose($X)", rewrite: "$X.dispose()", language: "dart")
→ (proposed) 12 replacements in 4 files … call resolve with edit_id "edit_1"
```

| 引數 | 含義 |
| --- | --- |
| `pattern` | 要匹配甚麼 |
| `rewrite` | 換成甚麼，其中 `$NAME` 會被代回 |
| `path` | 作用範圍；預設為整個工作區 |
| `language` | 語言 id |

## `resolve` — 提交或丟棄一次暫存的改動

| 引數 | 含義 |
| --- | --- |
| `edit_id` | 來自 `(proposed)` 結果 |
| `action` | `accept` 或 `discard` |

每個檔案都會與暫存時擷取的內容比對，**任何**不一致都會拒絕整項改動。只套用了一半的結構化重寫，會留下一棵在舊形狀與新形狀下都編譯不過的樹。

## `debug` — 驅動除錯器

當一次執行擁有除錯工作階段監督程式、工作目錄與對話 id 時才會註冊。配接器能否真正啟動，是在呼叫時按與語言伺服器相同的交集規則偵測的（根標記*並且*二進位檔）。屬於 `exec` 層級；非平行安全（工作階段是跨呼叫累積的狀態，因此 `continue` 搶在 `stack` 前面，會讀到一個已經移動過的堆疊框）。

每個對話只允許一個工作階段，並帶一個硬性 TTL（30 分鐘）。第二次 `launch` 會被拒絕，而不是悄悄取代第一個。在沙箱中執行時，工作階段會在其結束之前於各輪之間保留自己的沙箱，因此最多就是那 30 分鐘。

| 操作 | 引數 | 說明 |
| --- | --- | --- |
| `adapters` | — | 這裏有哪些配接器可用，以及為甚麼不可用 |
| `status` | — | 是否有工作階段正在執行，以及它停在哪裏 |
| `breakpoints` | `file`, `lines[]` | `lines` 為空會清除該檔案的斷點。可以在啟動**之前**設定 |
| `launch` | `program`, `args[]` | 啟動程式，並停在你的斷點處 |
| `attach` | `port` | 連接到一個已在執行的被除錯程式，位於該次執行自己轉送的連接埠之一；任何其他連接埠都會在任何動作開始之前被拒絕 |
| `continue` | `thread_id?` | 執行至下一個停止點 |
| `pause` | `thread_id?` | 讓它就地停止 |
| `step_over` / `step_in` / `step_out` | `thread_id?` | 移動一步 |
| `threads` | — | 執行緒 id 與名稱 |
| `stack` | `thread_id?` | 堆疊框，上限 30 個 |
| `scopes` | `frame_id` | 某個堆疊框上的作用域，每個都帶一個 `reference` |
| `variables` | `reference` | 子項，上限 50 個；值上限 400 個字元 |
| `evaluate` | `expression`, `frame_id?` | 在該堆疊框自身的作用域中求值 |
| `output` | — | 被除錯程式的 stdout/stderr，有上限 |
| `terminate` | — | 結束工作階段並終止配接器 |

### 配接器

| Id | 指令 | 根標記 |
| --- | --- | --- |
| `dart` | `dart debug_adapter` | `pubspec.yaml` |
| `debugpy` | `python3 -m debugpy.adapter` | `pyproject.toml`, `setup.py`, `requirements.txt` |
| `lldb` | `lldb-dap` | `Cargo.toml`, `CMakeLists.txt` |
| `delve` | `dlv dap` | `go.mod` |

`debugpy` 在沙箱中執行時會優先選擇專案本地的 `.venv/bin` 或 `venv/bin`，而不是 `$PATH`：`$PATH` 裏的 python 是另一個環境，而從錯誤的那個附加時，失敗的樣子讀起來像程式碼壞了。未經沙箱時，它只使用 `$PATH`，因此存放庫無法選擇在主機上執行的直譯器。

## `repl` — 運行一段呼叫你工具的指令碼

伺服器能夠運行指令碼時，每次執行都會出現此工具（[何時執行會有 `repl`](/zh-HK/手冊/概念/程式碼模式/#何時執行會有-repl)）。指令碼為純 JavaScript，即非同步函式的主體，在其自身行程中、全新且已鎖定的直譯器內運行：沒有檔案系統、網絡、行程或模組存取權。`repl` 本身屬於 `read` 層級，並自行把關，因為指令碼所作的每一次工具呼叫都會各自被檢查。它也會出現在 MCP 端點上，供伺服器能夠運行指令碼時的代理執行使用。

| 引數 | 含義 |
| ------------------- | --------------------------------------------------------------------------------------------- |
| `code` | 指令碼本體，最多 256 KiB |
| `description` | 必填。供對話列使用的簡短標籤 |
| `timeout_ms` | 選填。比工作區所設更短的時間限制；絕不能更長 |
| `max_output_tokens` | 選填。比工作區所設更小的輸出預算；絕不能更大 |

```js
// Read three files together and report only which ones failed.
const paths = ["lib/a.dart", "lib/b.dart", "lib/c.dart"];
const results = await Promise.allSettled(paths.map((path) => tools.read({ path })));
return results
  .map((r, i) => (r.status === "rejected" ? `${paths[i]}: ${r.reason.message}` : null))
  .filter(Boolean);
```

`repl` 的說明告訴代理：「不是你的直接工具之一的工具，在本請求中沒有定義。在首次呼叫其中任何一個之前，除非其確切呼叫形式已在本對話中向你展示過，否則請先以 `describeTool(name)` 或 `searchTools(query)` 查找它。」

`describeTool(name)` 會回傳工具的說明、其宣告、其輸入與輸出 schema，以及結果說明（若有的話）：即指令碼從已完成的呼叫所收到的內容，以工具自己的用語表達。`repl` 的說明會列出指令碼可以呼叫的直接工具的結果說明。若工具結果為 JSON 文字，且所含的值不超過 131,072 個，它會以解析後的形式抵達指令碼；若超過，則會以文字抵達，由指令碼以 `JSON.parse` 自行解析。來自外部 MCP 伺服器工具的結果，其文字會在 262,144 個字元處被截短，而被截短的文字不能再解析。

- `tools.<name>(args)` 會透過與直接呼叫相同的篩選、護欄與核准來呼叫工具；若呼叫遭拒或失敗，則以錯誤拒絕。唯讀呼叫可以一併執行；會改變某些東西的呼叫則逐一執行，並依指令碼發出的順序進行。在其中一次呼叫等待人員時，指令碼不會開始任何其他呼叫。
- `ALL_TOOLS`、`searchTools(query, { limit, namespace })`、`describeTool(name)` 和 `describeNamespace(name)` 可用來尋找工具，包括已連接的 MCP 伺服器的工具。直接工具集以外、指令碼可以呼叫的工具，只能由指令碼呼叫；直接呼叫時，會回傳如何從 `repl` 呼叫它。伺服器無法運行該執行的指令碼後，此類工具便改為在首次使用時載入。
- 查找有限制：查詢最多 1,024 個字元，名稱或命名空間最多 256 個字元，`limit` 介乎 0 至 50，且每個指令碼的查找合計最多 200 次、耗時合計 2 秒（以伺服器時間計）；同一工作區的所有指令碼共用 2 秒的查找時間，每秒歸還四分之一秒。超過任何一項上限後，之後的查找都會遭拒。在極大的目錄中，`ALL_TOOLS` 內的說明會平均分享約一百萬個字元，被截斷的說明會以 `…` 結尾；`describeTool` 則永遠傳回完整說明。型別過大而無法顯示時會顯示 `unknown /* too large to show */`；對不存在的名稱，則會回覆最接近的名稱。
- 工具會按命名空間分組：`builtin`（執行框架自身的工具）、`control-center`（Control Center 的工具），以及每個已連接的 MCP 伺服器各一組，以該伺服器命名。名為 `builtin`、`control-center` 或 `script`、或名稱以 `external-` 開頭的伺服器（不論大小寫混合，亦不論前後是否有空格），會列為 `external-` 加上其名稱，且沒有任何工具會位於 `script` 之中。
- 只有指令碼回傳的內容，或傳給 `text()`、`image()` 或 `console.*` 的內容，才會回傳。超出預算的輸出會保留開頭和結尾，並可用 `read_output` 讀取其餘部分。
- `store(key, value)` / `load(key)` 會為同一對話及代理之後的指令碼保存 JSON 值，且只在指令碼完成時保存。子代理的指令碼沒有儲存區。
- `await tools.ask_user(...)` 會提出問題；其答覆也會加入結果。`sleep(ms)`、`setTimeout`、`limits()` 以及 `models.embed` / `rank` / `classify`（裝置上的嵌入）同樣可用。
- `describeTool(name)` 與 `searchTools(query)` 也會為指令碼自身的函數作答，這些函數不是工具：`text`、`image`、`store`、`load`、`sleep`、`setTimeout`、`clearTimeout`、`limits`、`exit` 及 `models.*`，屬於 `script` 命名空間之下。
- 指令碼不可呼叫：`repl`、`eval`、`task`、`checkpoint`、`rewind`、`compact`、`search_tools` 及 `vibe_*` 動詞。
- 指令碼會讀取自己這次執行的過去紀錄：`history({start, role, tool, limit})` 會分頁讀取對話的逐字稿（每次呼叫最多 50 列；把上一頁的 `next_start` 作為 `start` 傳入），`outputs()` 列出為此對話與代理儲存的工具輸出，而 `loadOutput(handle)` 會讀取其中一個的 16,384 個字元。`storedKeys()` 會列出已儲存的鍵及其大小。`keep(value, label)` 會把一個大型值儲存為輸出，供之後的指令碼或 `read_output` 讀取，且只會在指令碼完成時才儲存（每個值 1 MiB、每次執行 64 個值及 16 MiB）。`limits().returnBudgetChars` 會說明輸出預算尚餘多少。唯讀的執行（目標審核）可以讀取，但不能儲存或 keep。在 Claude Code 與 ACP 上，`history()` 可用，而 `outputs()`、`loadOutput()` 與 `keep()` 會拒絕使用，因為 Control Center 不會保存那些執行的工具輸出。
- 逾時、輸出溢出或呼叫次數上限所造成的錯誤，都會說明如何修正。

一次執行每次只運行一個指令碼。各項限制及達到限制時的情況，請參閱[程式碼模式](/zh-HK/手冊/概念/程式碼模式/#限制)頁面；每個指令碼都會記錄在 **可觀測性 → 程式碼執行記錄** 之下。

## `eval` — 持久直譯器

一個 Python 或 JavaScript 儲存格，其變數、匯入與已載入的資料在多次呼叫之間都會保留下來。屬於 `exec` 層級；非平行安全。不可由 `repl` 指令碼呼叫，且儲存格不能呼叫執行中的工具：若要從程式碼呼叫工具，請使用[`repl`](#repl--運行一段呼叫你工具的指令碼)。

| 引數 | 含義 |
| --- | --- |
| `code` | 儲存格 |
| `description` | 必填。5–10 個詞，用作逐字稿標籤 |
| `language` | `python`（預設）或 `javascript` |
| `reset` | 先丟棄直譯器，從乾淨狀態重新開始 |

- 最後一個運算式會像筆記本那樣被回顯。
- `display()` 可用，pandas 資料框會渲染成表格，而 matplotlib 圖形會以**逐字稿會顯示的影像**形式傳回。
- 人們下意識會敲的那些 IPython 慣用寫法——`%pip`、`%cd`、`!cmd`、`%%bash`、`%%timeit`——都會被改寫成普通程式碼。`%pip` 還會逐出 `sys.modules`，讓下一次 `import` 看到剛剛安裝的東西。
- 輸出超出其預算的儲存格，會保留前四分之三與最後四分之一，並以一行說明被捨去的字元數與圖像數。
- 直譯器在未被要求的情況下停止運作時，下一個儲存格會被告知一次，其先前的變數已不存在。

:::note[核心在哪裏執行]
對話設有隔離環境時，就在其中執行；否則在該次執行的作業系統沙箱中、於主機上執行。若沙箱關閉或無法使用，它會在無約束的情況下執行，而 `eval` 會要求主機執行核准。它不會為了做到這一點而啟動一個隔離環境——這與阻止測試機分頁自動啟動的是同一條規則。
:::

## 背景中的 `bash`

`bash` 以 `run_in_background: true` 執行時，會立即啟動命令並傳回一個句柄（`b1`、`b2`、…），而不是等待。代理會繼續工作，或結束其回合，並在命令結束時被喚醒。

| 引數 | 含義 |
| ------------------- | ------- |
| `run_in_background` | `true`：立即啟動並傳回 |
| `timeout_seconds` | 命令被終止前的秒數：預設 600，最多 3,600 |
| `notify` | 可選。一個簡單的模式；命令執行期間，每一行符合的輸出都會送給代理（例如 `listening on\|FAILED`） |

- 同一次執行中，最多同時執行 4 個背景命令。每個命令都會在其逾時時被終止，並且在執行結束時連同它啟動的所有程序一併終止。
- 命令結束時，代理會收到一則通知，內含結束碼、最後 2,000 個字元的輸出，以及供讀取其餘輸出的 `read_output` 句柄。
- 若代理剩下的唯一工作是一個背景命令，它會在不呼叫模型的情況下等待，而該次執行的靜默看門狗會在等待期間暫停。
- `bash_output(handle)` 會讀取命令的狀態與最近的輸出；`bash_kill(handle)` 會停止它。兩者都會說明結果是否已經送達。
- 指令碼不能啟動背景命令。Claude Code 有自己的背景 Bash；對於留下工作仍在執行的回合，Control Center 會把該次執行保持開啟，最多 10 分鐘。

## `compact` — 為上下文視窗騰出空間

在下一次模型呼叫之前，壓縮對話較舊的上下文，並保留 `focus` 所指定的內容（最多 1,000 個字元）。最新的回合會逐字保留。代理每回合的預算行會顯示上下文用量達 70%、80% 與 90%，而在一段長時間的新工作開始之前，用量超過約 70% 時值得呼叫此工具。伺服器擁有者的 `preCompact` 掛鉤可以為重點加入內容（[Shell 掛鉤](/zh-HK/手冊/參考/代理設定/#shell-掛鉤)）。壓縮之後，伺服器會加入一個「Still in flight」區塊：目標、等待中的喚醒、未決的提問、背景命令、檢查清單與已儲存的鍵，每項都附有可把它找回的呼叫。

## `ask_user` — 向人提問

屬於 `read` 層級。這是一次執行向操作者提問的**唯一**方式。它會在對話中渲染一張編號卡片，並一直阻塞，直到有人回答、跳過，或提問逾時。絕不要把問題寫成一則聊天訊息——那會結束當前回合。

| 引數 | 含義 |
| --- | --- |
| `question` | 要問甚麼 |
| `context` | 選填：你為甚麼問，以及答案會決定甚麼 |
| `options[]` | 可選項，每一項為 `{label, description?}` |
| `allow_free_text` | 是否接受手動輸入的答案 |
| `multi_select` | 是否可以選擇多項 |

跳過即成功：基於一個明確說明的假設繼續推進，並且不再詢問。逾時則是一種錯誤，附帶同樣的指示。權限提示（「我可以這樣做嗎？」）是另一道閘門，在對話中渲染為同樣的卡片。

只有在提問連接埠與目標空間都存在時才會註冊。在沒有真人接入的情況下，這次呼叫會**失敗**，而不是永遠阻塞下去——這與護欄 `prompt` 在沒有連接任何核准人時所採取的失效關閉姿態相同。

## `vibe_*` — 指揮背景工作程式

只有在 [Vibe 模式](/zh-HK/手冊/操作指南/指揮背景工作程式/) 開啟期間才會註冊。這五個都屬於 `read` 層級：閘門應當設在工作程式的那些工具上，因為編輯真正發生的地方在那裏。

| 工具 | 引數 | 說明 |
| --- | --- | --- |
| `vibe_spawn` | `brief`, `label`, `tier?` | 立即傳回；工作程式繼續執行 |
| `vibe_send` | `worker_id`, `message` | 追加到簡報中並重新執行 |
| `vibe_wait` | `worker_id`, `timeout_seconds?` | 阻塞，直到它結束 |
| `vibe_kill` | `worker_id` | 停止它 |
| `vibe_list` | — | 層級、狀態、已用時間與最近一次結果 |

`tier` 可以是 `fast`（規格明確的機械式工作）或 `good`（設計、判斷，或審查一個 `fast` 工作程式的產出）。
