Control Center 可以把**假名化的使用事件**傳送到一個 [Umami](https://umami.is) 實例。使用情況分析**預設關閉，直至伺服器營運者把它開啟**。這項設定屬於伺服器，並套用於連線到它的每一個用戶端：桌面應用程式、Web 應用程式、手機，以及伺服器本身。

使用情況分析與**分享當機報告**互不相干；後者是針對單一裝置的當機與錯誤診斷設定。

## 由誰決定

| 開關 | 位置 | 效果 |
| --- | --- | --- |
| **分享使用情況分析** | 首次設定（沙箱步驟）及**設定 → 隱私**。只有伺服器營運者可以更改；其他成員只能以唯讀方式看到目前的值 | 套用於整個伺服器。以 `telemetry.usage_analytics` 儲存在伺服器設定中。除非設為 `true`，否則保持關閉 |
| 建置類型 | 自動 | debug 及 profile 建置不會傳送，而是把每個事件寫入除錯日誌 |
| `CC_ANALYTICS_DEBUG=1` | `cc_server` 的環境或其 `.env` 檔案 | 讓伺服器及每個連線到它的用戶端的 debug 及 profile 建置真正傳送資料，以作測試。上方的開關仍須開啟 |
| `DO_NOT_TRACK=1` | `cc_server` 的環境 | 無論開關如何，都會停止伺服器本身的回報。用戶端仍會遵循該開關 |
| 示範伺服器 | 自動 | 公開的示範伺服器不會以自身名義傳送任何內容。訪客無法更改該開關 |

用戶端會從伺服器讀取這項設定（先透過 `telemetry.config`，之後透過 `telemetry.watch` 即時取得）。收到答覆之前，事件會在一個細小的記憶體緩衝區中等候。如果答覆是否，緩衝區便會被捨棄。關閉開關會捨棄所有仍在佇列中的內容，並即時在每個用戶端上停止傳送。

## 永遠不會傳送的內容

- 訊息、工單、審查或會議的內容、標題、提示詞、shell 指令及搜尋查詢
- 姓名、登入名稱、電郵地址、頭像及顯示名稱
- 檔案路徑、程式庫名稱、分支名稱、主機名稱及 URL（程式庫只以假名化的 `repo_id` 傳送；會議連結只以其提供方傳送）
- 任何形式的原始識別碼

每個事件離開行程之前都會先經過一套屬性政策。文字、路徑、URL、電郵地址、未經包裝的 ID，以及 `email`、`*_name`、`path`、`title`、`prompt`、`content` 或 `token` 等鍵之下的字串都會被捨棄，而不會傳送出去。只有來自封閉詞彙表的簡短代號才會以字串傳送，例如列舉值、版本、地區設定或模型 ID。

## 假名化 ID

ID 會被傳送，但只以假名的形式。每一個工作區、空間、對話、代理、執行、使用者及裝置的 ID，都會被替換成以該安裝本身的秘密鹽值（`telemetry.pseudonym_salt`）計算的 HMAC-SHA256，並截斷為 20 個十六進制字元。同一個工作區一律回報相同的值，因此事件可以互相關聯並加以計算，但原始 ID 永遠不會離開該安裝。鹽值在伺服器首次啟動時建立，並且從不傳送給分析服務提供方。刪除伺服器的資料目錄會產生新的鹽值及安裝 ID，與之前記錄的一切從此失去關聯。

## 每個事件都附帶的屬性

| 屬性 | 例子 | 意思 |
| --- | --- | --- |
| `app_type` | `desktop` | `desktop`、`web`、`remote`（手機）或 `server`。亦用作 Umami 中的主機名稱 |
| `app_version` | `0.0.11` | 發行版本 |
| `app_build` | `4baf980` | 該建置的 git 短提交 |
| `platform` | `macos` | `macos`、`windows`、`linux`、`web`，或手機的作業系統（`ios`、`android`） |
| `locale` | `fr_FR` | 介面語言 |
| `server_mode` | `local` | `local`（桌面應用程式執行自己的伺服器）或 `remote` |
| `server_version` | `0.0.11` | 已連線伺服器的版本（如已知） |
| `is_demo` | `false` | 用戶端是否連線到公開示範 |
| `install_id` | 假名 | 伺服器安裝 |
| `user_id` | 假名 | 已登入的使用者（得知後） |
| `device_id` | 假名 | 已配對的裝置（得知後）。亦是 Umami 中的唯一 ID |
| `launch_id` | 假名 | 一次應用程式啟動，用來排列一個工作階段的事件次序 |
| `event_seq` | `12` | 事件在這次啟動中的次序 |

此外，Umami 亦會收到請求的 IP 位址（它會據此推斷國家及地區，但不儲存位址本身），以及 User-Agent 及螢幕尺寸。

## 畫面瀏覽

每次導覽都會記錄一次頁面瀏覽，其 URL 是**路由範本**，例如 `/workspaces/:workspaceId/spaces/:spaceId`，而不是實際位址。畫面名稱由範本的字面片段組成，因此上例是 `workspaces_spaces`。以 `Id` 結尾的路由參數會以假名化的 `*_id` 屬性附加，數字參數（例如 PR 編號）則以數字附加。其他參數一律捨棄。

## 傳送

事件會從一個最多容納 200 個事件的記憶體佇列中逐一傳送到 `<host>/api/send`。遇到網絡錯誤、逾時、`429` 或 `5xx` 時會保留事件，並以指數退避重試，間隔由 1 秒逐步增加至 5 分鐘。其他任何 `4xx` 都會捨棄該事件。不會有任何內容寫入磁碟，因此應用程式結束時仍在佇列中的事件會遺失。應用程式轉到背景及伺服器關閉時，佇列會全數送出。

## 把建置指向另一個實例

目的地在建置時已經固定：

```bash
--dart-define=CC_ANALYTICS_HOST=https://analytics.example.com/
--dart-define=CC_ANALYTICS_WEBSITE_ID=<website uuid>
```

提供方轉接器位於 `packages/cc_analytics`。要支援其他分析服務，就是在那裏新增一個轉接器。追蹤計劃及私隱規則維持不變。
