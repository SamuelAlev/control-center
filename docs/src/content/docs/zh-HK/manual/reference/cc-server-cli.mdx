每一個行程旗標都可以用 CLI 旗標或環境變數提供；旗標勝過環境變數，再勝過預設值。供應商憑證是例外——見[供應商應用程式與 Connect](#供應商應用程式與-connect)。

:::caution[未知旗標會被靜默忽略]
參數剖析器是手寫的，會略過任何它不認識的東西，因此打錯字（`--tls-key-file`、`--bindany`）不會產生錯誤——伺服器只會以預設值啟動。當某個旗標似乎沒有作用時，請檢查啟動記錄行。值不被接受的[程式碼模式旗標](#程式碼模式)則不同：伺服器會拒絕啟動。
:::

## 核心

| 旗標            | 環境變數               | 預設值                                           | 含義                                                                                                           |
| --------------- | ---------------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `--data-dir`    | `CC_SERVER_DATA_DIR`   | 作業系統的每位使用者應用程式資料目錄（見下文）   | 資料庫、密鑰、模型與快取媒體                                                                                   |
| `--port`        | `CC_SERVER_PORT`       | `9030`                                           | TCP 連接埠（`0` = 臨時）                                                                                       |
| `--bind`        | `CC_SERVER_BIND`       | `loopback`                                       | `loopback`，或用 `any`/`all`/`0.0.0.0` 表示所有網絡介面（需要 TLS 或 `--insecure`）                            |
| `--repo-roots`  | `CC_SERVER_REPO_ROOTS` | 伺服器使用者的家目錄                             | 用戶端註冊程式庫時可瀏覽的基礎目錄（以逗號分隔）。瀏覽至某個根目錄之上會被拒絕                                 |
| `--log-level`   | `CC_SERVER_LOG_LEVEL`  | `warning`                                        | `debug`、`info`、`warning` 或 `error`。啟動與就緒的記錄行一律會印出                                            |
| `--server-name` | `CC_SERVER_NAME`       | 機器主機名稱                                     | 顯示於選擇器、探索與配對介面上的名稱                                                                           |

## 索引與執行環境

| 旗標                 | 環境變數                        | 預設值   | 含義                                                                                                                              |
| -------------------- | ------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `--sandbox`          | `CC_SERVER_SANDBOX`             | `on`     | `on` 會把代理執行包裹在主機的作業系統原生沙箱中，而在沒有沙箱的主機上只會啟動伺服器擁有者的執行。`off` 會在此主機上讓每位成員的代理無約束地執行。見下文                                     |
| `--code-index`       | `CC_SERVER_CODE_INDEX`          | `on`     | 背景程式碼圖索引的現場終止開關。`off` 會在不重建的情況下乾淨啟動                                                                   |
| `--code-index-defer` | `CC_SERVER_CODE_INDEX_DEFER`    | `15`     | 就緒橫幅之後，延後第一次索引掃描的秒數（限制於 0–300）                                                                             |
| `--tool-deferral`    | `CC_SERVER_TOOL_DEFERRAL`       | `on`     | 執行框架的執行是否只送出一個小的直接工具集加一個名稱索引，其餘在首次使用時載入。見下文                                             |
| `--credential-gate`  | `CC_SERVER_CREDENTIAL_GATE`     | `900`    | 某次執行因為憑證無法為它提供服務，而擱置等待真人修復的秒數（限制於 0–3600）。見下文                                               |
| `--code-mode-max-processes` | `CC_SERVER_CODE_MODE_MAX_PROCESSES` | `min(16, 2 × cores)` | 此伺服器上同時運行的程式碼模式指令碼數目（不計等待人員的指令碼），1–64。見下文 |
| `--code-mode-max-heap-mb` | `CC_SERVER_CODE_MODE_MAX_HEAP_MB` | `1024` | 單一指令碼可使用的最大記憶體，16–1024 MiB。工作區較高的記憶體上限會被降至此值 |

## 供應商應用程式與 Connect

沒有任何建置版本附帶供應商憑證。開啟 Control Center Connect 時，Connect 會執行每個供應商，伺服器自己的應用程式則保留但不使用。在**使用我自己的應用程式**下，每個供應商在伺服器自己的應用程式設定完整時使用它，否則無法使用。工作區自己的應用程式在兩種情況下都優先。自己的應用程式在 **設定 → 伺服器 → 單一登入 → 供應商應用程式** 中設定，或從伺服器的 `.env` 檔案提供一次初始值。它們沒有對應的旗標：命令列上的密鑰可以透過 `ps` 讀到。

| 變數                           | 含義                                                                                          |
| ------------------------------ | --------------------------------------------------------------------------------------------- |
| `GITHUB_APP_ID`                | 伺服器的 GitHub App id                                                                        |
| `GITHUB_APP_PRIVATE_KEY`       | 它的私鑰，寫成一行並使用 `\n` 跳脫。**只限 `.env`**                                           |
| `GITHUB_CLIENT_ID`             | 它的用戶端 id，用於讓人們登入                                                                 |
| `GITHUB_CLIENT_SECRET`         | 它的用戶端密鑰。**只限 `.env`**                                                               |
| `GOOGLE_OAUTH_CLIENT_ID`       | 伺服器的 Google 網頁應用程式用戶端                                                            |
| `GOOGLE_OAUTH_CLIENT_SECRET`   | 它的密鑰。**只限 `.env`**                                                                     |
| `LINEAR_CLIENT_ID`             | 伺服器的 Linear 應用程式（PKCE，無密鑰）                                                      |
| `LINEAR_API_KEY`               | 供自動化使用的 Linear 服務金鑰。**只限 `.env`**                                               |
| `KLIPY_APP_KEY`                | 伺服器自己用於 GIF 搜尋的 Klipy 金鑰，僅在**使用我自己的應用程式**下使用                         |
| `CC_CONNECT_URL`               | `hosted`、`off` 或一個 Connect URL。會鎖定 Connect 的選擇；之後設定便無法更改它                |
| `CC_SERVER_CONNECT_HOST`       | `on` 會在 `<server>/connect` 掛載 Control Center Connect，並以 `CONNECT_*` 變數設定。見[執行 Connect 伺服器](/zh-HK/手冊/操作指南/執行-connect-伺服器/#在-cc_server-內掛載-connect) |

`.env` 檔案會從伺服器的工作目錄、可執行檔旁邊，或其上層的原始碼檢出中讀取；在 Docker 中，請把它掛載到 `/app/bin/.env`。若 `GITHUB_APP_PRIVATE_KEY`、`GITHUB_CLIENT_SECRET`、`GOOGLE_OAUTH_CLIENT_SECRET`、`LINEAR_API_KEY` 或任何 `SLACK_*SECRET*` 被匯出到伺服器的行程環境中（每個子行程都讀得到），伺服器會**拒絕啟動**（結束代碼 `78`）。從 `.env` 提供初始值每個欄位只發生一次，因此之後在設定中所作的編輯不會因重新啟動而被還原。空值會視同未設定。

沒有任何託管平台憑證來自環境變數：GitHub、GitLab 與 Bitbucket 都只會以某位成員自己的登入或權杖行事，或是以受該成員約束的單一程式庫 GitHub App 權杖行事。

### `--sandbox`

伺服器會在啟動時探測主機一次，並在後端可用時，把代理的指令執行包裹在作業系統原生沙箱中：macOS 上是 `sandbox-exec`（Seatbelt），Linux 與 WSL2 上是 `bwrap` 加 `socat`。決定只做一次，並一直有效直到伺服器重新啟動。共有三種結果，各自顯示在啟動時的暴露行上：

| `sandbox=` | 何時 | 誰的代理執行會啟動 |
| --- | --- | --- |
| `native` | 後端可用且 `--sandbox` 為 `on` | 所有人的執行，皆被包裹 |
| `off` | `--sandbox off` | 所有人的執行，在此主機上無約束 |
| `unavailable` | `--sandbox on` 且沒有後端（Windows，或缺少 `bwrap` 與 `socat` 的 Linux） | 只有由伺服器擁有者負責的執行，無約束。其他人的執行會被拒絕，並顯示「此伺服器沒有沙箱，因此只有其擁有者可以在此執行代理。」 |

對於自動化而言，負責的人是該自動化所綁定的人。若未記錄伺服器擁有者，則在 `unavailable` 主機上不會啟動任何執行。在已安裝 bubblewrap 的 Linux 與 WSL2 上，原生派發目前會對每次執行都封閉式失敗；見[沙箱後端](/zh-HK/手冊/參考/沙箱後端/#linuxbubblewrap)。

`--sandbox off` 是伺服器擁有者為所有使用該伺服器的人所作的選擇：它會讓每位成員的代理在這部機器上無約束地執行。在沙箱設定檔本身行為失當的主機上使用它，或讓成員能在沒有後端的主機上執行代理。它不需要重建，而伺服器會在整個行程存續期間記錄一則警告，因此這個狀態永遠不會是無聲的。

### `--tool-deferral`

內建執行框架的執行會送出一個小的直接工具定義集，加上其餘工具的僅名稱索引；這些工具會在首次使用時載入其 schema，或由 `repl` 指令碼呼叫。這使永遠可見的集合保持在模型能可靠選擇工具的範圍之內。在測試所建立的註冊表上量度，內建代理的標準聊天工具共有 14 個定義：連同 `repl` 約 16.5 KB（其中 `repl` 約佔 4 KB，其定義不得超過 4,096 位元組），在無法運行指令碼的伺服器上則約 13 KB。隨需載入的工具全程都仍可按名稱呼叫，而 `search_tools` 會按意圖找到它們。參見[工具上下文與提示快取](/zh-HK/手冊/概念/工具上下文/)。

`--tool-deferral off` 會預先送出每個已准入工具的定義，但有 `repl` 的執行仍會由指令碼呼叫指令碼可以呼叫的工具。對於處理不好這種兩層式介面的模型，這是它的終止開關——是一個旗標，而不是要重建。它只影響內建執行框架；外部用戶端看到的 MCP `tools/list` 是完整目錄，但能夠運行[程式碼模式](/zh-HK/手冊/概念/程式碼模式/)指令碼的伺服器上的代理執行除外。

### `--credential-gate`

若某次執行的供應商憑證缺失或已耗盡，該次執行會被**擱置**而非失敗：操作者會收到提示去修復它，而若他們修好，執行便會繼續。預設期限是 900 秒（15 分鐘），限制於 0–3600。

這個期限刻意遠長於核准提示的期限：核准是有人在數秒內作出的決定，而修復憑證則意味着要開啟終端、登入然後再回來。這個上限的作用，是要讓無人看管的執行——管線步驟、cron 觸發器、webhook——不會無了期地等待一個正在睡覺的人。當它到期時，執行會以它本來就會失敗的那則訊息失敗。

`--credential-gate=0` 就是終止開關：任何東西都不會被擱置，而一個壞憑證會結束該回合，情況與這道關卡存在之前完全相同。

### 程式碼模式

[程式碼模式](/zh-HK/手冊/概念/程式碼模式/)讓代理運行一段呼叫其工具的 JavaScript 指令碼。沒有任何旗標可以開啟或關閉它：伺服器能夠運行指令碼時，每次執行都會取得 `repl` 工具；公開示範伺服器則不運行任何指令碼。

指令碼在 `cc_codemode` 中運行，這是隨附於伺服器、位於 `bin/codemode/` 中的程式。沒有它，伺服器便無法啟動：它會印出一行說明缺少什麼，並以結束代碼 `78` 退出。啟動時，伺服器會執行該程式的鎖定自我測試，並印出一行（僅在 `--log-level error` 時會靜默）：

```text
cc_server: code_mode=available (cc_codemode 0.1.0 quickjs-ng 0.16.2 protocol 2; 16 scripts at once, at most 12 per workspace; up to 64 more runners kept for scripts waiting on a person; heap at most 1024 MiB per script)
cc_server: code_mode=unavailable (<reason>) — runs on this host get no repl tool; scripts never run without full lockdown
```

`unavailable` 表示該程式無法在此主機上鎖定自己，例如在安全設定檔拒絕其中某個步驟的容器內，或該程式並非正式版建置。伺服器照常運行，沒有任何執行會取得 `repl`，而工作區的程式碼模式設定會顯示原因。

伺服器會持續檢查。當程式因非指令碼本身的原因而無法啟動時，伺服器會再次運行自我測試，但頻率最多為每分鐘一次。若測試失敗，伺服器會印出附有原因的 `unavailable` 行，且不運行任何指令碼：期間才啟動的執行不會取得 `repl`，而已取得它的執行則會直接呼叫其工具（[指令碼無法運行時](/zh-HK/手冊/概念/程式碼模式/#指令碼無法運行時)）。它會繼續檢查，同樣最多每分鐘一次；當自我測試再次通過時，它會印出 `available` 行，並重新運行指令碼。只有啟動時即告失敗的自我測試才需要重新啟動。工作區的設定所顯示的原因已移除主機路徑；記錄行則完整保留原因。

兩個程式碼模式旗標限制指令碼可使用的資源。`--code-mode-max-processes` 會限制所有工作區同時運行的指令碼數目（預設為處理器核心數目的兩倍，最多 16；接受 1–64）。當上限為 2 或以上時，單一工作區最多只能使用上限減去其四分之一，因此沒有任何單一工作區能佔滿每個位置，等待中的指令碼則會跨工作區依序獲准。等待人員核准或回答的指令碼會讓出其位置給另一個指令碼，並在獲回答之前不開始任何工具呼叫；此類等待中的指令碼最多保留上限的四倍，其中來自單一工作區的最多佔四分之三，而每個指令碼仍可在其自身的處理器時間限制內運算。`--code-mode-max-heap-mb` 是任何單一指令碼可使用的最大記憶體。

這些旗標不接受的值（超出範圍的數字，或並非數字的值）會令伺服器在啟動時停止（結束代碼 `78`），並列出接受的值。它絕不會被當作預設值讀取。

## 子指令

| 指令                                          | 它的作用                                                                                                             |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `cc_server`                                   | 執行伺服器，直到收到 `SIGINT`/`SIGTERM`                                                                              |
| `cc_server pair`                              | 佈建一部裝置並印出其 id 與配對金鑰。對一個伺服器正在提供服務的資料目錄也是安全的——執行中的伺服器無須重新啟動就會接收該裝置 |
| `cc_server connect <command>`                 | 顯示或更改這部伺服器使用哪個 Control Center Connect，而無需啟動伺服器                                                  |
| `cc_server update`                            | 檢查、下載並驗證較新的獨立發行版本                                                                                   |
| `cc_server --version`                         | 印出版本與 git SHA——`/healthz` 與 RPC 握手所公佈的同一個身分                                                         |

### `pair`

| 旗標           | 預設值                                                    | 含義                                                                                                                                                                 |
| -------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--device`     | `web-client`                                              | 裝置 id。平台由它推斷，因此 `--device desktop` 會建立一筆桌面資料列，而 `--device ios`/`android` 會建立一筆手機資料列；其他任何值都會當作網頁                       |
| `--label`      | 平台名稱加上本機的主機名稱                                | 裝置清單中的顯示名稱                                                                                                                                                 |
| `--host`       | `localhost`，或繫結至所有網絡介面時的 `<this-host>`       | 要嵌入所印出 URL 中的主機。請把它設為用戶端實際會撥打的 LAN IP 或通道主機                                                                                             |
| `--client-url` | 未設定                                                    | 受託管**網頁**用戶端的來源。會加入可掃描的深層連結與終端 QR 碼                                                                                                        |

`pair` 也接受核心的 `--data-dir`、`--port` 與 `--bind` 旗標：它們選定要寫入的資料目錄，並塑造所印出的伺服器 URL（回送上為 `ws`，`--bind any` 時為 `wss`）。對同一個 `--device` 重新執行 `pair` 會輪替它的金鑰，並丟棄該裝置的現行工作階段。在此簽發的憑證
**沒有到期時間**，不像應用程式內配對所設定的 30 天。

:::caution[`--client-url` 的 QR 碼不是手機 QR 碼]
`pair --client-url` 會填入**網頁**用戶端的連接表單（伺服器 URL、裝置 id 與金鑰都在 URL 片段中）。手機則以另一種承載內容配對，它是由應用程式內的配對面板簽發的——伺服器的完整連線描述元加上一個到期時間。兩者不能互換——參見[配對裝置](/zh-HK/手冊/操作指南/配對裝置/)。
:::

### `connect`

從資料目錄讀取並寫入與 **設定 → 伺服器 → 單一登入** 中 **Control Center Connect** 卡片相同的設定。執行中的伺服器會在 10 分鐘內或重新啟動時取用變更。

| 指令                            | 作用                                                                                                             |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `cc_server connect status`      | 印出模式、URL、是否被 `CC_CONNECT_URL` 鎖定、安裝 id、健康狀態，以及每條通道的來源（`own`、`connect` 或 `off`）  |
| `cc_server connect enable`      | 使用 Control Center 代管的 Connect                                                                               |
| `cc_server connect enable --url <url>` | 使用位於該 URL 的自訂 Connect（HTTPS，或回送地址上的 `http`）                                             |
| `cc_server connect disable`     | 停止使用 Connect。只有伺服器自己的應用程式能讓人們登入                                                           |

不帶指令時預設為 `status`。每個指令都接受 `--data-dir`。`CC_CONNECT_URL` 會凌駕這些指令所儲存的內容。未知的指令會以 `64` 結束。模式、安裝身分與狀態代碼請參見 [Control Center Connect](/zh-HK/手冊/參考/connect/)。

### `update`

`--apply` 會替換整個安裝；若設定的連接埠上仍有伺服器回應，除非你傳入 `--force`，否則它會被拒絕。`--allow-downgrade` 允許較舊的發行版本。

對於不屬於它管的安裝，這個指令會直接拒絕，並給出解釋而不是錯誤：

| 環境                          | 偵測方式                                          | 它會說甚麼                                      |
| ----------------------------- | ------------------------------------------------- | ----------------------------------------------- |
| 桌面應用程式內嵌的伺服器      | `CC_EMBEDDED=1` 或 `CC_BOOTSTRAP_DEVICE_ID`       | 請改為更新應用程式——安裝程式會替換整棵目錄樹    |
| `dart run` 原始碼檢出          | 指令碼路徑以 `.dart` 結尾                          | 請用 git 更新它                                 |
| Docker                        | 容器標記                                          | 拉取較新的映像                                  |

## 行程生命週期

`cc_server` 會一直執行到收到 `SIGINT` / `SIGTERM`。有一個額外的環境變數管轄這件事，而它是由桌面應用程式設定，而不是由你設定：

| 變數                    | 作用                                                                                                                                                                          |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CC_EXIT_WITH_PARENT=1` | 當它的父行程結束時，伺服器也會結束——判斷方式是父行程關閉其 stdin 管道的寫入端。桌面應用程式會設定它，這樣即使應用程式當掉，也永遠不會遺下一個仍持有資料目錄的孤兒伺服器            |

只有在你把 `cc_server` 當作子行程監督，並想要同樣的保證時，才自行設定它。

`DO_NOT_TRACK=1`（空值、`0` 或 `false` 以外的任何值）會停止伺服器本身的[使用情況分析](/zh-HK/手冊/參考/使用情況分析/)，即使伺服器層級的開關已開啟亦然。用戶端仍會遵循該開關。

## 資料目錄佈局

預設資料目錄在 macOS 上是 `~/Library/Application Support/control-center`，
在 Windows 上是 `%APPDATA%\control-center`，其他地方則是 `$XDG_DATA_HOME/control-center`（否則為
`~/.local/share/control-center`）。只有在無法解析出家目錄或應用程式資料目錄時，才會使用相對於 cwd 的 `.cc_server`。

伺服器會將資料目錄設為只限其自身帳戶存取（`0700`）。當它做不到這點、`global.db` 已損壞或由較新版本寫入，或其身分檔無法讀取時，伺服器會拒絕啟動（結束代碼 `78`）。

| 路徑                              | 內容                                                                             |
| --------------------------------- | -------------------------------------------------------------------------------- |
| `global.db`                       | 工作區註冊表、使用者、已配對裝置、資訊動態與機群佇列                             |
| `<workspaceId>/workspace.db`      | 每個工作區一個資料庫——代理、空間、工單、記憶                           |
| `<workspaceId>/code_index.db`     | 該工作區的程式碼圖。缺少時會被重建，從不備份 |
| `pre_upgrade/`, `<workspaceId>/pre_upgrade/` | 更新改變格式之前的資料庫副本，最新的兩份 |
| `<workspaceId>/chat_credentials/` | 聊天機械人權杖，以純 JSON 儲存，因此它們會跟着工作區走                           |
| `secrets.json`                    | 配對金鑰、Connect 安裝金鑰、供應商應用程式、人們的登入（經由 Connect 建立者為密封形式）、webhook 機密、SSO（`0600`） |
| `backups/<timestamp>/`            | 一份安裝快照——`manifest.json`、`global.db` 以及每個工作區的複本                  |
| `backups/exports/`                | 單一工作區匯出檔，`<workspaceId>-<timestamp>.db`                                 |
| `backups/transfer/`               | 備份下載與上傳的暫存區；由寫入它的路由清掃                                       |
| `models/`                         | 裝置上的嵌入、說話人分離與語音模型                                               |
| `codemode/` | 程式碼模式執行器的開發用副本，由 `scripts/natives/build_codemode.sh` 安裝；發行套件會將其放在 `bin/codemode/` 中 |
| `meetings/<meetingId>/`           | 保留的會議音訊                                                                   |
| `rigs/images/`                    | 匯入的測試機磁碟映像（QEMU 桌面介面）                                            |
| `rigs/smolvm/<rigId>/`            | 每部測試機的 microVM 執行階段狀態（仲介程式的密鑰，`0600`）                      |
| `rigs/smolvm-packs/`              | 預先解壓的機器套件——讓測試機重複啟動更快的快取                                   |
| `rigs/tls/`                       | 測試機 HTTPS 用的開發網域憑證頒發機構（金鑰 `0600`）                             |
| `rigs/run/<rigId>/`               | QEMU 覆寫層、種子映像與每個 VM 的金鑰（`0600`）                                  |
