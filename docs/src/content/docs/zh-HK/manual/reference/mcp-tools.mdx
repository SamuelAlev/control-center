`cc_server` 託管單一 MCP（JSON-RPC 2.0）工具註冊表，於主伺服器連接埠（預設 `9030`）的 `POST /mcp` 與 `GET /sse` 提供，協定版本 `2024-11-05`。每個用戶端都會連到同一個註冊表：桌面版、網頁版、外部 MCP 用戶端，以及內建的代理執行環境。外部 MCP 伺服器可以作為一個動態層，橋接進同一個註冊表。

## 註冊表大小

| 指標                                                                    | 數量 |
| ----------------------------------------------------------------------- | ---- |
| 由 `cc_server` 註冊的工具                                               | 110  |
| 來自 `packages/cc_mcp`                                                  | 108  |
| 來自 `packages/cc_mcp_client`（工具探索）                               | 2    |
| 在基礎註冊表中註冊（`server_mcp_registry.dart`）                        | 63   |
| 開機後隨所屬服務啟動而註冊（`cc_server_runtime.dart`）                  | 47   |
| 基礎註冊表那 63 個之中，視乎是否有程式碼圖程式庫而定                    | 5    |

這五個程式碼圖工具，只有在主機把程式碼圖程式庫傳給 `buildServerMcpRegistry` 時才會註冊。`cc_server` 一定會傳入一個，因此隨附的二進位檔中，全部 110 個工具都處於生效狀態。

整份註冊表都會在 `tools/list` 中對外宣告，沒有任何探索閘門。工單編輯是具型別的工具。

:::note[外部用戶端永遠看到整個目錄]
`tools/list` 永遠不會被裁剪。MCP 用戶端會用自己快取的該份清單來驗證工具名稱，對任何不在清單上的工具直接拒絕，不會先詢問伺服器；因此在該清單中藏起的工具是無法觸達的，而不只是低調。

**內建執行框架**則不同：它每次請求只載入一組常駐的定義子集，其餘會在首次使用時拉進來。這是執行框架端的行為，不會改變這個註冊表。見[工具上下文與提示快取](/zh-HK/手冊/概念/工具上下文)。
:::

:::note[每個工具類別都會註冊]
`packages/cc_mcp/lib/src/tools/` 下的每一個原始碼檔案，就是代理可以呼叫的一個工具。若某個新工具類別沒有被任何地方建構，`packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart` 會令組建失敗。
:::

## 通用參數

### `workspace_id`

凡涉及工作區範圍資料的工具都**必填**。缺少或無效的 `workspace_id` 會回傳明確的錯誤，而與目標實體所屬工作區不符的值會被拒絕，不會被靜默略過。真正全域性的工具則可省略：`list_workspaces` 與六個資訊動態工具（`list_feeds`、`list_articles`、`get_article`、`set_article_read`、`set_article_saved`、`refresh_feeds`），它們用的是伺服器擁有者的每位使用者訂閱清單。探索工具（`search_tool_bm25`、`list_my_tools`）可選填，好讓它們按對話模式判斷可呼叫性。當代理由伺服器派發時，工作區會由伺服器端強制指定，因此代理無法透過傳入外來的 id 觸達另一個工作區。

## 工具探索

兩者都來自 `cc_mcp_client`，而非 `cc_mcp`；兩者都會查詢模式防護，因此回報的是_當前_對話模式下可呼叫的工具。

| 工具               | 說明                                                                                                                        |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `search_tool_bm25` | 以關鍵字搜尋工具目錄；回傳相符的工具、它們的引數 schema，以及每一個目前是否可呼叫                                          |
| `list_my_tools`    | 列出這個對話中目前可呼叫的工具，並按其模式篩選                                                                              |

第三個探索工具 **`search_tools`** 只存在於內建執行框架之內，並不屬於這個 MCP 註冊表。它會為該次執行自身的工具介面排序；與 `search_tool_bm25` 不同，它會**載入**找到項目的 schema，讓代理可以在下一個回合呼叫相符的工具。在執行框架上運行的代理應優先使用它；MCP 用戶端則有 `search_tool_bm25`。

## 隔離環境（測試機）工具

從一次執行之中，驅動用完即棄的機器——隔離環境中的瀏覽器或 Linux 桌面、Android 模擬器，或 iOS Simulator。開機後無條件註冊：一部機器實際上能否開機，是工具每次呼叫時回答的探測問題。同一個對話中重複呼叫會重用同一部機器；螢幕截圖會以圖片內容回傳，每個結果有單一圖片的預算，而抽取到的頁面／UI 內容會被圍欄標示為不受信任的資料。四個 use 工具加上 `rig_close` 會宣告 `enclosureControl` [動作類別](/zh-HK/手冊/概念/護欄/)（該些 use 工具亦宣告 `networkEgress` 與 `processSpawn`；`mobile_use` 與 `ios_use` 亦宣告 `packageInstall`），因此唯讀模式會拒絕它們。`rig_list` 不宣告任何類別——它只讀取工作區狀態。各介面類型完整的動詞詞彙見[測試機參考](/zh-HK/手冊/參考/測試機/#action-verbs)。

| 工具           | 說明                                                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `computer_use` | 在隔離環境的 VM 中驅動 Linux 桌面：移動、點擊、拖曳、捲動、輸入、調整大小、剪貼板、螢幕截圖                                      |
| `browser_use`  | 驅動無介面的 Chromium、Firefox 或 WebKit（`engine`）：導覽、點擊、填寫、抽取（a11y/DOM/console）、剪貼板、螢幕截圖               |
| `mobile_use`   | 透過 ADB 驅動 Android：檢查／輸入、螢幕截圖、安裝／啟動／停止／重設／解除安裝應用程式、深層連結，以及 argv 形式的裝置指令          |
| `ios_use`      | 透過 WebDriverAgent/CoreSimulator 驅動 iOS Simulator：檢查／輸入、螢幕截圖、安裝／啟動／停止／解除安裝應用程式、深層連結，以及 argv 形式的模擬器行程 |
| `rig_list`     | 列出工作區的測試機，附上介面類型、狀態、顯示大小與控制器                                                                        |
| `rig_close`    | 銷毀一部測試機，並丟棄它所擁有的機器狀態                                                                                        |

## 不經 MCP 提供的功能

日曆與會議沒有 MCP 工具。代理無法讀取你的日曆、會議、轉錄、行動項目或決定。產生行動項目與決定的摘要，是以內建的 [`meeting_summary` 管線](/zh-HK/手冊/概念/會議/) 執行，而不是一個代理可以呼叫的工具。

## 按模式對工具施加閘門

閘門由同一份表（`ModeToolPolicy`）執行兩次：一次在 Claude Code 配接器的 MCP 分派器中，一次在內建執行框架的註冊表中。被封鎖的呼叫會回傳原因。

| 模式          | 工具介面                                                                                                                                                                                                                             |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`        | 每一個已註冊的工具；沒有允許清單                                                                                                                                                                                                    |
| `plan`        | 一份經策劃的允許清單。沒有 worktree 寫入，也沒有 `create` / `assign` / `delegate` 工單動詞，但記憶、產出物、待辦事項、`submit_plan`、`exit_plan_mode`，以及對已派發工單的工單完成動詞則獲允許                                       |
| `review`      | 一份經策劃的允許清單：審查參與、通訊、唯讀上下文取得工具，以及完整的工單動詞集，包括 `create_ticket` 與 `assign_ticket`                                                                                                            |
| `orchestrate` | 一份經策劃的允許清單：研究與讀取工具，加上 `propose_orchestration`、`create_playbook` 與 `run_playbook`。招聘、拆解與工單完成會在核准後以確定性方式發生，絕不會在執行中途進行                                                     |

無論允許清單為何，每種模式都允許：

| 組合         | 工具                                                                                                                                                                                                                                                                      |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 記憶與產出物 | `search_memory`, `propose_fact`, `propose_policy`, `supersede_fact`, `supersede_policy`, `record_observation`, `update_my_notes`, `get_my_notes`, `list_memory_domains`, `list_policies`, `publish_artifact`, `revise_artifact`, `list_artifacts`, `get_artifact`         |
| 程式碼圖     | `search_code`, `code_symbol`, `code_callers`, `code_callees`, `code_impact`                                                                                                                                                                                              |
| 執行機制     | `search_tool_bm25`, `list_my_tools`, `todo_write`, `todo_read`                                                                                                                                                                                                            |

列入允許清單，並不代表工具就一定可呼叫；反過來也一樣：向操作者提問的能力是一個**執行框架**工具（`ask_user`），因此它根本不會出現在這份 MCP 目錄中。

## 需經核准的工具

工具可以宣告 `requiresApproval`。分派器便會在工具執行之前建立 `ApprovalPayload`，並透過 `ConfirmationPort` 呈現出來；`cc_server` 會接上這個埠，因此這道閘門是實際生效的。

已註冊且宣告它的工具：`create_ticket`, `update_ticket`, `assign_ticket`, `reassign_ticket`, `close_ticket`, `ticket_relation`, `create_goal`, `update_goal_progress`, `create_approval`, `decide_approval`, `comment_approval`, `create_work_product`, `save_work_product_revision`, `create_runtime_profile`, `install_skill`, `update_skill`.

另外，統一的動作護欄會對任何宣告了非空 `ActionClass` 集合的工具施加閘門。若判定為 `prompt` 而未連接任何核准人，則會被拒絕。見[護欄](/zh-HK/手冊/概念/護欄/)。

## 背後沒有工具的能力

產品中並非每一項能力都能讓代理觸達。以下這些完全沒有工具，因此你可能在別處見過的名稱，會回傳「unknown tool」：

| 能力                             | 實際所在位置                                                                                             |
| -------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 招聘、解僱或編輯代理             | 代理介面。沒有 `hire_agent` / `fire_agent` / `update_agent` 工具                                          |
| 建立工作區                       | 透過 RPC 的 `workspace.upsert`，它會植入並蓋上擁有權戳記                                                  |
| 項目（建立／列出／更新／歸類）    | 工單介面。項目是操作者介面——見[項目](/zh-HK/手冊/操作指南/項目/)                                          |
| 向操作者提出會阻塞的問題         | **執行框架**的 `ask_user` 工具，而非 MCP。它會在對話中渲染一個表單，並阻塞等待答案                        |
| 逐代理診斷                       | 沒有。沒有 `doctor`——見[診斷代理](/zh-HK/手冊/操作指南/診斷代理/)                                        |
| 日曆與會議                       | 只為人類用戶端提供的 RPC（見上文）                                                                       |
