## 你將會建立甚麼

完成本教學後，你將會擁有：

- 一個由你親自建立並設定的代理
- 一個讓你與該代理對話的空間
- 一次完成的執行，在隔離的 worktree 中有已提交的工作，代理的執行紀錄中也有一列

先決條件：已完成[你的第一個工作區](/zh-HK/手冊/教學/第一個工作區/)，令此工作區已註冊程式庫，並連接了至少一個模型供應商。

## 第 1 步：建立代理

1. 前往 **設定 → 工作區 → 代理**
2. 按一下 **新增代理**。系統會立即建立一個名為「未命名代理」的代理，並在名冊中選取它——沒有建立對話框，也沒有任何需要確認的步驟。你就在原處設定它。
3. 在 **設定** 分頁上填寫：
   - **名稱**：簡短易記，例如 `alice`。這就是你在 `@` 之後輸入的內容。
   - **標題**：它的職責，例如「後端工程師」
   - **配接器**：`Control Center (built-in)`。刻意選擇這一個——只有內建執行框架可以在執行中途被引導，並在回合邊界暫停，而且它不需要在伺服器主機上安裝任何 CLI。
   - **模型**：從已連接供應商所提供的清單中選擇
   - **技能**：附加任何合適的技能，例如 `testing` 或 `architecture`
4. 按下 **儲存變更**

:::note[沒有配接器的代理會在內建迴圈上執行]
當「配接器」欄位未設定時，派發會回退到 **Control Center (built-in)**——即伺服器內部的代理迴圈，因此主機上沒有東西需要安裝。它仍然需要一個模型：若未設定任何模型，它會向 Anthropic 索取其預設模型，這在你已連接 Anthropic 帳戶時可行，否則會以 `No credential for provider "anthropic"` 失敗。無論如何，請明確設定兩者，否則你就會在一個並非由你選擇的模型上執行。
:::

**檢查點。** 名冊中的資料列會顯示你代理的名稱，以及一個空心狀態環。

## 第 2 步：開啟空間

1. 在側邊欄中，找到 **空間** 區段，然後按一下 **+** 按鈕
2. 為空間命名
3. 在 **新增代理** 之下，選取你剛才建立的代理
4. 若工作區有任何程式庫，請選擇這個空間應在哪幾個程式庫上工作
5. 按一下 **建立**

空間隨即開啟。Control Center 會在背景為這則對話，以寫入時複製的方式，在獨立分支上佈建所選程式庫的 worktree。你的來源檢出永遠不會被改動。

## 第 3 步：傳送任務

針對你已註冊的程式庫，輸入一項具體而細小的任務。有可檢查結果的任務效果最好——加入測試、修正 lint 問題、重新命名符號。

按 Enter。你不需要 `@` 提及任何人：空間中只有一個代理時，一則普通訊息就會喚醒它。空間中有多個代理時，`@name` 會選定其中一個。

Control Center 會從代理的指示、角色設定、技能和空間的上下文組合出提示，然後派發這次執行。

**檢查點。** 撰寫器的傳送按鈕會變成停止按鈕——有代理正在這則對話中工作——文字亦開始送達。

## 第 4 步：觀察它工作

對話會隨着執行發生而即時呈現：

- **推理**，在代理思考時即時內嵌顯示
- **工具呼叫**：檔案讀寫、搜尋、shell 指令，每項都附有結果
- **文字**：摘要、說明，以及向你提出的問題

若代理提出問題，就在對話中回答，它便會繼續。

若要查看某次執行自身的指標，以及其暫停、繼續和停止控制項，請在空間「一般」面板的 **代理** 區段中找到正在執行的代理，然後選擇 **開啟活動**。

在活動窗格中，狀態徽章會顯示 **執行中**，執行結束時則顯示 **已成功**。停滯或陷入迴圈的執行會顯示 **已封鎖**；發生錯誤的則顯示 **失敗**。在代理註冊表中，首次執行前的名冊狀態環是空心的，代理再次閒置後則變成實心。

約束這次執行的因素包括：它自己專屬、以寫入時複製的 worktree；在啟動時為它仲介、並在拆卸時撤銷的憑證；經清理的環境；其模式所允許的工具集，以及操作護欄。推送分支或開啟 pull request 之類的效果會另行設閘門——見[護欄](/zh-HK/手冊/概念/護欄/)。

## 第 5 步：檢查結果

1. 開啟 **設定 → 工作區 → 代理** 並選取你的代理
2. 開啟 **日誌** 分頁

**檢查點。** 一列執行紀錄，顯示其狀態、時長、開始與完成時間，以及它所使用的配接器。

代理的變更會提交到該對話的分支上、它自己的 worktree 中。提交的作者是代理，並在 `Co-Authored-By:` 尾註中記入你的貢獻。

## 取得 pull request

沒有任何東西會自行開啟 pull request。若你想要一個，就在同一則對話中提出要求：

> 推送這個分支，並對預設分支開啟一個 pull request。

推送（`gitPush`）與建立 PR（`prCreate`）預設都會提示你核准，因此預期每次之前都會先要求確認。若提示出現時沒有已連接的核准者，該動作會被拒絕，而非獲准——護欄會失效即拒絕。

這個 PR 會以該次執行所用權杖所屬的 GitHub 身分開啟——若你儲存了個人權杖，那就是你的身分——而不是以代理的名義。代理的作者身分則顯示在提交上。

你也可以自行開啟：空間的 **原始檔控制** 面板有一個 **建立 pull request** 按鈕，會把該對話的分支帶進撰寫畫面，而 **Pull requests → 新增 PR** 則會以空白狀態開啟同一個畫面。下一個教學就從這裏接續。

## 回顧

你建立了一個代理、設定它的配接器和模型、給它一個空間與一項任務，並看着一次真實的執行在隔離的 worktree 中完成，而沒有碰觸你的檢出。
