يبين هذا الدليل كيف تربط مزوّدي النماذج، وتختار ما يعمل عليه الوكيل.

كل ما هنا في صفحة واحدة: **الإعدادات ← الخادم ← مزوّدو النماذج**. بند الشريط الجانبي الفرعي «مزوّدو النماذج»، وعنوان الصفحة «المحوّلات».

## ما المحوّل؟

المحوّل هو _المشغّل_ الذي ينفّذ جولة الوكيل. هما اثنان، والقائمة ثابتة، ولا يمكن إضافة ثالث.

| المحوّل                   | CLI      | النقل                                              |
| ------------------------- | -------- | -------------------------------------------------- |
| Control Center (built-in) | لا شيء   | حلقة وكيل داخل العملية، تتحدث إلى المزوّدين عبر HTTP |
| Claude Code               | `claude` | `claude -p --output-format stream-json`            |

Cursor وCodex وAnthropic وOpenAI والبقية **مزوّدون** على المحوّل المضمّن، لا واجهات CLI منفصلة. ما _يمكن_ إضافته هو مزوّد آخر: أي نقطة نهاية متوافقة مع OpenAI أو Anthropic. هذا موضوع القسم التالي.

:::note[الاكتشاف يفحص الخادم لا جهازك]
تسرد بطاقة **المشغّلات المكتشفة** ما وجده `cc_server` على `PATH` لدى _مضيف الخادم_. على عميل خفيف أو عميل ويب يكون مضيف الخادم آلة غير التي أمامك. ثبّت CLI على الآلة التي تشغّل `cc_server`.
:::

## ربط مزوّد نماذج

يحتاج المحوّل المضمّن إلى مزوّد متصل واحد على الأقل قبل أن يستطيع العمل. يضم الكتالوج أربعة عشر مزوّدًا.

1. انتقل إلى **الإعدادات ← الخادم ← مزوّدو النماذج**
2. انزل إلى **الموفّرون والنماذج**
3. ابحث عن مزوّدك واربطه:

| المزوّد                                                                                                  | طريقة الربط                                                                                                          |
| -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Anthropic                                                                                                | مفتاح API. اشتراك Claude Pro/Max ليس تسجيل دخول إلى API لدى Anthropic. استخدم محوّل Claude Code لتلك الخطة           |
| OpenAI, Codex, Cursor                                                                                    | تسجيل دخول OAuth عبر المتصفح، أو مفتاح API. Codex هو ChatGPT Plus/Pro عبر خلفية Codex Responses، وليس إطلاق واجهة CLI |
| Kimi Code                                                                                                | OAuth عبر المتصفح فقط، بتدفق رمز الجهاز. هي خطة بسعر مقطوع، فلا سعر لكل رمز                                          |
| OpenRouter, Google Gemini, DeepSeek, Mistral, xAI, z.ai, z.ai GLM Coding Plan, Moonshot (Kimi API)       | مفتاح API                                                                                                            |

نقطة التحقق: تتبدّل شارة الصف إلى «متصل»، وتوسيعه يسرد النماذج التي يقدّمها ذلك المزوّد، لكل منها سعره لكل مليون رمز ونافذة سياقه.

تستقر رموز OAuth في مخزن بيانات اعتماد الخادم نفسه، وتُجدَّد قبل أن تنتهي صلاحيتها. بيانات اعتماد المزوّد **عامة على المضيف**: مشتركة بين مساحات العمل كلها في التثبيت، لا محصورة في واحدة.

### إضافة مزوّد مخصص

استخدم هذا لـ Ollama أو LM Studio أو vLLM أو لنشر خاص.

1. في **الموفّرون والنماذج**، تحت **مزوّدون مخصصون**، اضغط **إضافة مزود**
2. املأ **الاسم**، واختر **نوع API** (متوافق مع OpenAI أو متوافق مع Anthropic)، وأدخل **عنوان URL الأساسي** (مثل `http://localhost:11434/v1`)
3. أضف **مفتاح API** إن احتاجته نقطة النهاية، ثم اضغط **إضافة مزود**

يظهر المزوّد المخصص في القائمة نفسها، ومعه زر «إزالة المزود» لا يملكه المزوّدون المضمّنون.

## اختيار نموذج لوكيل

1. انتقل إلى **الإعدادات ← مساحة العمل ← الوكلاء** واختر الوكيل
2. في علامة تبويب **الإعدادات**، اختر **المحوّل**
3. اختر **النموذج** من القائمة المنسدلة بجانبه

في المحوّل المضمّن تُجمَّع القائمة المنسدلة مباشرة من كتالوج كل مزوّد متصل. المزوّد الذي لا يملك بيانات اعتماد مخزّنة لا يضيف أي نموذج، ولهذا تكاد القائمة الفارغة تعني دائمًا «لم يُربَط شيء بعد»، لا «لا شيء متاح».

:::note[models.dev إثراء، لا مصدر للمعرّفات]
يوفّر الكتالوج المضمّن من [models.dev](https://models.dev) السعر ونافذة السياق لنموذج موجود أصلًا في القائمة الحيّة. لا يضيف معرّف نموذج أبدًا. إن غاب نموذج تتوقعه، فنقطة نهاية المزوّد لا تعيده.
:::

معرّفات النماذج في المحوّل المضمّن مؤهَّلة بصيغة `provider/model`، وقد تحمل سلسلة رجوع مفصولة بـ `|`. عند الرجوع، تُحتسب التكلفة على النموذج الذي خدم الجولة فعلًا، لا على الذي طلبته.

:::note[الوكيل بلا محوّل يعمل على الحلقة المضمّنة]
تبذر كل مساحة عمل خمسة وكلاء، CEO ومعه `qa` و`architect` و`engineer` و`librarian`، بلا محوّل ولا نموذج. يرجع الإرسال إلى **Control Center (built-in)**، لا إلى إعداد **المشغّلات الافتراضية** في هذه الصفحة، وهو تفضيل على جهة العميل لا يقرأه مسار الإرسال أبدًا. يسجّل سجل التشغيل `cc-harness` لتلك التشغيلات، فيسمّي نص التشغيل ما اشتغل فعلًا.

وإن غاب النموذج أيضًا، تطلب الحلقة المضمّنة من Anthropic نموذجه الافتراضي. الوكيل المتروك بلا أي ضبط يعمل إذن إن كنت قد ربطت حساب Anthropic، وإلا فشل برسالة `No credential for provider "anthropic"`.

إتمام خطوة المحوّل في الإعداد الأول يحدّث بأثر رجعي **كل** وكيل ما زال بلا محوّل أو نموذج، CEO والمتخصصين، في كل مساحة عمل قائمة في تلك اللحظة، ويضبط عليه الزوج الذي اخترته. مساحات العمل التي تُنشأ لاحقًا تظل تبذر الخمسة بلا محوّل ولا نموذج. اضبط المحوّل والنموذج صراحة على كل وكيل تنوي استخدامه.
:::

## تثبيت CLI لمشغّل

لا يحتاج المحوّل المضمّن إلى تثبيت. أما Claude Code، فثبّت واجهة CLI الخاصة به **على مضيف الخادم** بمدير الحزم الخاص بتلك الأداة، مثل:

```bash
npm install -g @anthropic-ai/claude-code
```

ثم اضغط **تحديث** في أعلى الصفحة. يعرض كل صف مكتشف الإصدار والمسار المحسومين، ورقائق تبين هل يدعم وضع JSON واختيار النموذج.

تحتفظ واجهة CLI الخارجية ببيانات اعتمادها، في تهيئتها الخاصة، على مضيف الخادم. لا يديرها Control Center.

:::caution[وسائط المحوّل ومتغيرات البيئة تبقى على هذا الجهاز]
يعرض كل صف محوّل حقل **وسائط** وحوار **متغيرات البيئة**. تُخزَّن تلك القيم على جهازك. يقرأ الخادم وسيطات الإطلاق ومتغيرات البيئة من مخزن إعداداته الخاص. ضع مفاتيح المزوّد على الخادم (عبر OAuth أو حقل **مفتاح API** في صفحة **مزوّدو النماذج**)، لا في هذين الحقلين.
:::

## تقييد المزوّدين الذين يجوز لمساحة العمل استخدامهم

حوكمة المزوّدين خاصة بمساحة العمل، وتُقيَّم بقاعدة آخر تطابق يفوز.

1. في **الموفّرون والنماذج**، أطفئ مفتاح **السماح** في صف المزوّد

يُكتب بذلك بيان `deny` لذلك المزوّد في مساحة العمل النشطة، وتخرج نماذجه من كتالوج تلك المساحة. إعادة تشغيل المفتاح تزيل البيان.

## استكشاف الأخطاء

### يظهر مشغّل على أنه غير موجود

- تحقّق من أن CLI على `PATH` لدى **مضيف الخادم**، لا على مسارك وحدك
- تطبيق سطح المكتب الذي يُطلَق من الواجهة الرسومية يولّد خادمه بـ `PATH` محدود، فواجهة CLI المثبّتة على مسار لا يظهر إلا في الصدفة قد تبقى غير مرئية له
- اضغط **تحديث** بعد التثبيت

### القائمة المنسدلة للنماذج فارغة

- المحوّل هو المضمّن ولم يُربَط مزوّد. اربط واحدًا في **الموفّرون والنماذج**
- أو أن المزوّد متصل، لكن مفتاح الحوكمة في مساحة العمل هذه يمنعه

### يعمل نموذج والسعر يظهر غير معروف

تحمل قائمة النماذج الحيّة المعرّف، ويأتي السعر ونافذة السياق من models.dev. النموذج الجديد تمامًا، أو الآتي من مزوّد مخصص، ليس له بعد مدخل في الكتالوج.
