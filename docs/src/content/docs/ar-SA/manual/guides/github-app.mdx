يبيّن هذا الدليل كيف تعطي خادمك تطبيق GitHub خاصًا به. يستغرق الأمر نحو
دقيقتين، ولا يفعله إلا مالك الخادم، ويحدث مرة واحدة لكل خادم.

:::note[قد لا تحتاج إليه]
حين يكون Control Center Connect مفعّلًا، يسجّل الناس دخولهم إلى GitHub عبر تطبيق
Control Center المشترك، أو عبر التطبيق الذي يستخدمه Connect الخاص بمؤسستك. سجّل
تطبيقك حين تختار **استخدام تطبيقاتي الخاصة**: لا يُستخدم تطبيق خادمك إلا في تلك الحالة. انظر
[Control Center Connect](/ar-SA/دليل-المستخدم/مرجع/connect/).
:::

لتسجيل الدخول إلى حسابك بعد ذلك، انظر
[إعداد تكامل GitHub](/ar-SA/دليل-المستخدم/أدلة-إرشادية/تكامل-github/).

## ما الذي يفعله التطبيق

يجيب التسجيل الواحد عن عملين مختلفين:

| العمل | ما يجيب عنه | لماذا يهم |
| --- | --- | --- |
| **شخص يسجّل الدخول** | معرّف عميل التطبيق وسر العميل | يحصل كل واحد على اعتماد GitHub يخصّه، على الخادم وعلى كل جهاز |
| **الخادم يتصرّف** | معرّف التطبيق والمفتاح الخاص | يحصل الوكلاء وخطوط الأنابيب والمستطلِعات وردود البوت على رموز لمستودع واحد في كل مرة |

العمل الثاني لا يستعير أبدًا اعتماد شخص بكامله. كل رمز يسكّه الخادم يغطي مستودعًا
واحدًا، ومحدود بما يستطيع عضو مسؤول فعله هناك. قراءة مستودع مربوط لا تحتاج إلا
إلى التطبيق؛ وكل ما يكتب يحتاج إلى عضو يستطيع الدفع. والأتمتة لا توافق أبدًا على
طلب سحب.

يُطبَّق تطبيق الخادم فقط تحت **استخدام تطبيقاتي الخاصة**: مع Control Center أو Connect مخصص، يشغّل Connect كل مسار بما فيه GitHub، ويبقى تطبيق الخادم محفوظًا دون استخدام إلى أن تعود. ويُستخدم تطبيق مساحة العمل بدلًا منه ([امنح مساحة عمل تطبيقها الخاص](#امنح-مساحة-عمل-تطبيقها-الخاص)) أيًّا كان وضع الخادم. والتطبيق الذي تنقصه بعض حقوله
خطأ، لا رجوع إلى بديل: تُرفض تسجيلات الدخول إلى GitHub إلى أن يُضبط كل حقل.

## المتطلبات

- أنت **مالك الخادم**. بطاقة **تطبيقات الموفّرين** مخفية عن سواه
- حساب على GitHub. يُنشأ التطبيق تحته
- عنوان للخادم يستطيع متصفحك بلوغه. العنوان العام للخادم (أو loopback، لخادم
  الحاسوب نفسه) هو حيث يعيدك GitHub

## أنشئه بنقرة واحدة

1. انتقل إلى **الإعدادات ← الخادم ← تسجيل الدخول الموحّد** وانزل إلى بطاقة
   **تطبيقات الموفّرين**
2. في كتلة **GitHub**، اكتب إن شئت مؤسسة GitHub التي ينبغي أن تملك التطبيق في
   **المؤسسة (اختياري)**. اتركه فارغًا لإنشاء التطبيق تحت حسابك أنت؛ وإنشاؤه تحت
   مؤسسة يحتاج إلى مالك لتلك المؤسسة
3. انقر **إنشاء تطبيق GitHub الخاص بي**
4. يفتح متصفحك GitHub والتطبيق معبّأ مسبقًا. انقر **إنشاء تطبيق GitHub**
5. يعيدك GitHub إلى الخادم، فيخزّن معرّف التطبيق والمفتاح الخاص ومعرّف العميل وسر
   العميل، ثم يفتح صفحة تثبيت التطبيق

لا يُنسخ شيء باليد، ويذهب رمز التحويل مباشرة من GitHub إلى خادمك. الرابط يعمل مرة
واحدة وتنتهي صلاحيته بعد عشر دقائق؛ فإن انتهت، انقر **إنشاء تطبيق GitHub الخاص
بي** من جديد.

يُسمّى التطبيق `Control Center <code>`، ويطلب بالضبط ما يستخدمه Control Center:

| الإذن | الوصول |
| --- | --- |
| البيانات الوصفية | قراءة |
| المحتويات | قراءة وكتابة |
| طلبات السحب | قراءة وكتابة |
| المشكلات | قراءة وكتابة |
| الفحوصات، والإجراءات، وحالات الإيداع | قراءة |
| أعضاء المؤسسة | قراءة |

خطافات الويب معطّلة: الخادم يستطلع. ولنقل تطبيق أنشأته تحت حسابك إلى مؤسسة لاحقًا،
استخدم **نقل الملكية** في الإعدادات المتقدمة للتطبيق على GitHub.

نقطة تحقق: تقرأ كتلة GitHub «يمكن للخادم التصرف باسم نفسه، ويمكن للأشخاص تسجيل
الدخول».

## ثبّته حيث تعيش مستودعاتك

التطبيق المسجَّل غير المثبَّت يستطيع إدخال الناس، ولا يقرأ شيئًا.

1. اختر الحساب أو المؤسسة التي تملك مستودعاتك في صفحة التثبيت التي فتحها GitHub
2. اختر **كل المستودعات**، أو حدّد المستودعات التي يجب أن يراها هذا الخادم

ولتثبيته على حساب آخر لاحقًا، ينتقل مسؤول مساحة العمل إلى **الإعدادات ← مساحة
العمل ← التكاملات**، ويجد **عمليات تثبيت تطبيق GitHub** في بطاقة **تطبيق GitHub**
ضمن استضافة الكود، وينقر **تثبيت تطبيق GitHub**. تعرض القائمة كل حساب ثُبّت عليه التطبيق، وتنبّه إلى التثبيت
المعلّق.

## مشاركة تثبيت مؤسسة

تثبّت المؤسسة تطبيق GitHub مرة واحدة. بعد ذلك يستطيع كل من فيها يسجّل الدخول إلى
GitHub على خادم Control Center أن يستخدم التثبيت، على أي خادم كان: خادمك، أو خادم
زميل، أو خادم خاص به. لا حاجة إلى تصريح لكل خادم.

كل رمز يحصل عليه خادم يخص الشخص الذي سجّل الدخول، ومحدود بمستودع واحد وبدوره فيه،
فلا يصل أبدًا إلى أبعد مما يستطيعه على GitHub. ويُظهر سجل التدقيق في GitHub ذلك
الشخص وهو يتصرف عبر التطبيق.

ولإيقاف وصول Control Center إلى مؤسسة، يزيل مالك المؤسسة التثبيت على GitHub أو
يضيّق مستودعاته. وإزالة شخص من المؤسسة توقف وصوله هو أيضًا.

## أو سجّله باليد

تأخذ بطاقة **تطبيقات الموفّرين** القيم مباشرة أيضًا، لتطبيق سجّلته بنفسك:

| المجموعة | الحقول |
| --- | --- |
| **التصرف باسم الخادم** | **معرّف التطبيق**، و**المفتاح الخاص** (ملف `.pem` كاملًا، بما فيه سطرَا `BEGIN` و`END`) |
| **تسجيل دخول الأشخاص** | **معرّف العميل** و**سر العميل**. تعرض **عناوين URL لرد الاتصال** العنوان الذي يُسجَّل، حرفيًا |
| **محادثات طلبات السحب** | **اسم دخول البوت**، ويُحَل حين تختبر الاتصال |

سجّل عنوان رد الاتصال `<server origin>/oauth/github/callback` كما تعرضه البطاقة
تمامًا، وأبقِ **انتهاء صلاحية رموز تفويض المستخدم** مفعّلًا، وامنح الأذونات الواردة
في الجدول أعلاه. انقر **اختبار**: يسأل GitHub عن الحسابات التي ثُبّت التطبيق عليها،
فلا يلتبس «محفوظ» بـ«يعمل».

## اضبطه من ملف `.env` الخاص بالخادم

في التثبيت بلا واجهة أو المؤتمت، يبذر الخادم كل حقل من ملف `.env` الخاص به في أول
مرة لا تكون له فيها قيمة مخزّنة:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

ضع المفتاح على **سطر واحد**: قيمة `.env` سطر واحد، و`\n` داخل علامتي الاقتباس
المزدوجتين يُفكّ إلى سطر جديد. يرفض الخادم الإقلاع حين يكون `GITHUB_APP_PRIVATE_KEY`
أو `GITHUB_CLIENT_SECRET` مُصدَّرًا في بيئة عمليته، حيث تستطيع كل عملية فرعية
قراءته؛ أبقهما في ملف `.env` (في Docker، اربطه عند `/app/bin/.env`). يحدث البذر
**مرة واحدة لكل حقل**، فلا تلغي إعادة التشغيل التالية ما عدّلته في الإعدادات.

## امنح مساحة عمل تطبيقها الخاص

يمكن لمساحة العمل أن تعمل على تطبيق خاص بها بدل تطبيق الخادم:

1. ينتقل مسؤول مساحة العمل إلى **الإعدادات ← مساحة العمل ← التكاملات**
2. في بطاقة **Control Center Connect** يختار **استخدام تطبيقاتي الخاصة** وينقر **تطبيق**. يعيد كل أعضاء مساحة العمل تسجيل الدخول عبر تطبيقات مساحة العمل
3. تحمل بطاقة **تطبيق GitHub** ضمن استضافة الكود حقول التطبيق الآن: **معرّف التطبيق** و**المفتاح الخاص** تحت **يعمل نيابةً عن مساحة العمل هذه**، و**معرّف العميل** و**سر العميل** تحت **تسجيل دخول الأشخاص**. انقر **اختبار** بعد ملء الحقول

يسجّل الأعضاء دخولهم عندها إلى ذلك التطبيق لهذه المساحة. ومساحة العمل التي تعمل على تطبيقاتها الخاصة لا ترجع أبدًا إلى تطبيق الخادم ولا إلى Connect: ما دامت حقولها غير مكتملة، يُرفض عملها على GitHub. ويغطي الخيار نفسه تقويم Google وLinear والبحث عن GIF، ولكل منها حقولها بجانب مزوّدها في الصفحة نفسها. انظر [امنح مساحة العمل تطبيق Linear خاصًا بها](/ar-SA/دليل-المستخدم/أدلة-إرشادية/تكامل-linear/#امنح-مساحة-العمل-تطبيق-linear-خاصًا-بها) و[امنح مساحة العمل عميل Google خاصًا بها](/ar-SA/دليل-المستخدم/أدلة-إرشادية/ربط-التقويم/#امنح-مساحة-العمل-عميل-google-خاصًا-بها).
أما الخيارات الأخرى في تلك البطاقة، وما تفعله كل منها، فهي في [الاختيار لكل مساحة عمل](/ar-SA/دليل-المستخدم/مرجع/connect/#الاختيار-لكل-مساحة-عمل).

## استكشاف الأخطاء وإصلاحها

### يقول «إنشاء تطبيق GitHub الخاص بي» إن الخادم بلا عنوان

ليس للخادم عنوان عام يستطيع المتصفح العودة إليه. اضبط `CC_SERVER_PUBLIC_URL` (أو
`--public-url`) وأعد المحاولة.

### يقول GitHub إن الرابط انتهت صلاحيته

استُخدمت الصفحة ذات الاستعمال الواحد أصلًا، أو مضت عشر دقائق. ابدأ من جديد من
الإعدادات.

### يقول الاختبار إن بيانات الاعتماد تعمل لكن التطبيق غير مثبَّت في أي مكان

التسجيل والتثبيت خطوتان منفصلتان. افتح صفحة تثبيت التطبيق، أو استخدم **تثبيت تطبيق
GitHub** في مساحة العمل ← التكاملات.

### يقول الاختبار إن المفتاح الخاص تعذّرت قراءته

الصق ملف `.pem` كاملًا، بما فيه سطرَا `-----BEGIN` و`-----END`. مفتاح `ed25519` أو
EC لا يصلح: تطبيقات GitHub توقّع بـ RSA.

### سجّل عضو دخوله لكنه لا يرى أي مستودعات

التطبيق غير مثبَّت على الحساب الذي يملكها، أو يحدّد تثبيته مستودعات أخرى. تسجيل
الدخول لا يمنح إلا ما يُسمح للتطبيق برؤيته.

### يقول الوكلاء إن تثبيت تطبيق GitHub معلّق

علّق أحدهم التثبيت على GitHub. ألغِ تعليقه من **الإعدادات ← التطبيقات ← تطبيقات
GitHub المثبّتة** في ذلك الحساب.
