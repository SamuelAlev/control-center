يُحسم عزل تشغيل الوكيل على الخادم، عند الإقلاع (`--sandbox`). مفتاح
**تمكين البيئة المعزولة** ومنتقي **الخلفية** تحت
**الإعدادات ← الخادم ← التشخيص والخصوصية** تفضيلات مخزّنة على جهازك.
كشف المضيف في بطاقة **العزل** يبلّغ عما يستطيع مضيف الخادم تغليفه.

ضابطان يبلغان التشغيل، وهذا الدليل يغطيهما معًا: قواعد الإجراء في
**الإعدادات ← مساحة العمل ← أذونات الوكلاء**، التي تقرر ما يستطيع الوكيل
دفعه أو فتحه أو الوصول إليه، وعلم `--sandbox` الخاص بالخادم.

## ما الذي يقيّد تشغيل الوكيل

يُقيَّد الوكيل بستة حدود. أولها بيئة نظام التشغيل المعزولة، وهي الحد
المشروط — والخمسة الأخرى تثبت على كل مضيف.

| الحد | ما يفعله |
| --- | --- |
| بيئة نظام التشغيل المعزولة | Seatbelt على macOS، وbubblewrap على Linux وWSL2. تغلّف سطر أوامر Claude Code ومحوّلات ACP وأداة `bash` في الإطار. **غائبة على Windows وعلى Linux من غير `bwrap` و`socat`، حيث لا تبدأ إلا تشغيلات مالك الخادم** |
| شجرة العمل الخاصة به | تحصل كل محادثة على دليل عمل بالنسخ عند الكتابة. يُضم الدليل الأصلي إلى التشغيل مسارًا ممنوع الكتابة، والبيئة المعزولة هي التي تفرض ذلك |
| بيانات الاعتماد عبر الوسيط | يصدر وسيط بيانات الاعتماد بيئة لكل تشغيل، ويسحبها عند التفكيك. رمز GitHub فيها يقرأ ولا يدفع: يمر الدفع عبر Control Center، الذي يسأل قاعدة الدفع أولًا |
| ضوابط الإجراء | تصرّح كل أداة تعدّل الحالة بأصناف أثرها، ويحسمها الحارس قبل أن يجري الاستدعاء. يُرفض `prompt` إذا لم يتصل معتمِد |
| تعقيم البيئة | يحصل ACP وأداة `bash` في الإطار على بيئة مُرشَّحة. ويرث Claude Code عبر `NoSandboxAdapter` بيئة المضيف |
| سطح أدوات الوضع | ينزع وضع القراءة فقط أدوات تعديل شجرة العمل نزعًا كاملًا، ويثبّت فعل الإخراج الخاص بالوضع حتى يظل التسليم ممكنًا |

ثلاثة أمور تبقى أضعف مما تبدو:

- **الإطار المضمّن** وحده يفرض بوابة الأدوات وعقود الإكمال والقواعد
  البنيوية للوضع. محوّل Claude Code لا يفرض شيئًا من ذلك. ويُطلَق Claude
  Code تحديدًا مع `--dangerously-skip-permissions`، لأن `claude -p` غير
  التفاعلي كان سيتوقف إلى الأبد عند مطالبته الخاصة — فلا يرى Control Center
  استدعاءات read وwrite وedit الخاصة بـ Claude، ولا يضع عليها بوابة، ولا
  يفحص أوامر bash إلا خطاف يقرأ سطر الأمر. حيث تكون البيئة المعزولة مشغّلة،
  هي الحد الذي يحيط بهذه الاستدعاءات.
- أدوات الملفات داخل العملية في الإطار (read وwrite وedit وapply patch
  وsearch وfind وsearch_files) تعمل داخل عملية الخادم، فلا يقيّدها ملف
  تعريف للبيئة المعزولة. أداة `bash` وحدها تمر بمشغّل الأوامر المعزول.
  حدّ هذه الأدوات حصر مساراتها الخاص، مع ضوابط الإجراء.
- على مضيف بلا خلفية لا تبدأ إلا تشغيلات يتحمل مالك الخادم مسؤوليتها، وعندها لا ينطبق الصف الأول. تُرفض تشغيلات غيره. وتحت `--sandbox off` تبدأ تشغيلات كل الأعضاء بلا الصف الأول. وفي الحالتين يرجع ACP وأداة `bash` في الإطار إلى تعقيم البيئة وسياسة الأوامر، ويرث Claude Code بيئة المضيف عبر `NoSandboxAdapter`. ويقول الخادم أي الحالات أنت فيها في سجل إقلاعه. افحص سجلك أدناه.

## قرّر ما يستطيع الوكيل دفعه

لا توجد مبدّلات لكل وكيل لـ git push أو GitHub أو التذاكر أو الشبكة. كل منها قاعدة إجراء:

| القاعدة | الافتراضي المضمّن | ما تغطيه |
| --- | --- | --- |
| **الدفع إلى مستودع بعيد** | السؤال أولًا | كل `git push` إلى GitHub، من أي محوّل |
| **فتح طلب سحب** | السؤال أولًا | أدوات طلبات السحب في Control Center. لا يعمل `gh pr create` داخل التشغيل |
| **تحديث طلب سحب أو دمجه**   | السؤال أولًا | تعليقات الوكيل على طلب سحبه، وتعديلات عنوانه ووصفه، والمراجعات المنشورة، عبر أدوات Control Center. لا يعمل `gh pr comment` و`gh pr edit` و`gh pr review` و`gh pr merge` و`gh pr close` داخل التشغيل |
| **الكتابة إلى متتبع خارجي** | السؤال أولًا | كتابة التذاكر عبر أدوات Control Center و`gh issue` |
| **الوصول إلى الشبكة** | السماح | هل للبيئة المعزولة شبكة، وأدوات الويب في الإطار |

1. انتقل إلى **الإعدادات ← مساحة العمل ← أذونات الوكلاء**
2. اختر نطاقًا — **مساحة العمل** أو **الوكيل** أو **المساحة** — ثم اختر
   **السماح** أو **السؤال أولًا** أو **الرفض** في صف القاعدة

قواعد الدفع المقيّدة بالفروع، مثل قاعدة ترفض الدفع إلى `main`، تنطبق أيضًا:
انظر [الضوابط](/ar-SA/دليل-المستخدم/مفاهيم/ضوابط/).

نقطة التحقق: اطلب من وكيل أن يدفع فرعًا. مع **السؤال أولًا** يصلك طلب موافقة
يسمّي المستودع والمرجع؛ ومع **الرفض** يطبع git
`! [remote rejected] <ref> (Control Center policy: …)`.

كيف تبلغ كل قاعدة التشغيل:

- **الدفع** يُفرض بما يحمله التشغيل. رمز GitHub لديه يغطي مستودع التشغيل الواحد
  ولا يستطيع الدفع: يقرأ المحتوى، ويعلّق على طلبات السحب حين يستطيع العضو المسؤول
  الدفع. توجّه تهيئة git لديه كل
  دفع إلى GitHub نحو بوابة loopback على `cc_server`، تسأل القاعدة ثم تمرّر
  الدفع برمز كتابة لا يراه الوكيل أبدًا. لا تمرّر البوابة إلا إلى مستودع شجرة
  العمل نفسه أو إلى مستودع GitHub مرتبط بمساحة العمل. يصدق هذا على كل محوّل.
- **طلبات السحب والمشكلات من الصدفة** تُعرَف من سطر الأمر: في أداة `bash` في
  الإطار، وعبر خطاف في أداة `Bash` في Claude Code. الوكيل الذي يخفي الأمر
  (ملف نصي، أو `eval`، أو استدعاء API مباشر) يتجاوز هذا الفحص، لكنه لا يتجاوز
  بوابة الدفع.
- **مفاتيح التذاكر** لا توضع في البيئة المعزولة أبدًا. يكتب الوكلاء التذاكر عبر
  أدوات MCP في Control Center، وهي تسأل القاعدة.
- **الشبكة** تُحسم مرة واحدة عند بدء التشغيل. **الرفض** يطفئ شبكة البيئة
  المعزولة؛ و**السماح** و**السؤال أولًا** يبقيانها مشغّلة، ومع **السؤال أولًا**
  تظل أداتا الإطار `web_fetch` و`web_search` تسألان عند كل استدعاء. يبقى GitHub
  في قائمة السماح بالخروج ما دامت الشبكة مشغّلة.

:::note[من أين يأتي رمز GitHub الخاص بالتشغيل]
يُسكّ الرمز للتشغيل من GitHub App الخاص بمساحة العمل، أو من التطبيق الخاص بالخادم،
أو من Control Center Connect، وهو محدود بما يستطيع العضو المسؤول (الذي طلب، وإلا
فمالك مساحة العمل) فعله في ذلك المستودع. ولا يكون أبدًا تسجيل دخول العضو نفسه
مُسلَّمًا بكامله، ولا يوجد رمز بديل: حين يتعذر سكّ رمز، يبدأ التشغيل بلا رمز وتذكر
ملاحظاته السبب.
:::

## تحقق هل تشغيلات وكيلك معزولة

يحسمه أمران، وكلاهما على الخادم: هل يقدّم المضيف خلفية، وهل `--sandbox`
مشغّل. افحصهما بهذا الترتيب.

1. انتقل إلى **الإعدادات ← الخادم ← التشخيص والخصوصية**
2. اقرأ بطاقة **العزل**. حقيقة **المضيف** هي الآلة التي يعمل عليها
   `cc_server`، لا الآلة التي تنظر إليها. يسرد حقل **الخلفية** **بيئة معزولة أصلية**
   (Seatbelt على macOS، وbubblewrap على Linux وWSL2) أو **بلا عزل**. حقيقة
   **ساري المفعول** تفضيل هذا الجهاز، لا التغليف الذي يستخدمه الخادم فعلًا.
3. اقرأ سجل إقلاع الخادم. يطبع سطرًا واحدًا بالضبط من ثلاثة:
   - `agent sandbox ON` مع ملاحظة الخلفية: التشغيلات مغلَّفة
   - `no OS-native agent sandbox on this host` مع تلميح تثبيت حيث يوجد
     واحد: تبدأ فيه تشغيلات مالك الخادم فقط، وهي غير مغلَّفة، وتُرفض تشغيلات غيره.
   - `agent sandbox DISABLED by --sandbox off`: تبدأ تشغيلات كل الأعضاء، وهي غير مغلَّفة
4. يطبع الخادم عند الإقلاع سطر التعرض، ويقول الشيء نفسه في كلمة واحدة:
   `sandbox=native` أو `sandbox=off` أو `sandbox=unavailable`.

لا يبلّغ `GET /healthz` بحالة العزل، فسجل الإقلاع هو وسيلة الفحص.

لا يقرر تشغيل الوكيل دون بيئة معزولة إلا مالك الخادم. ولتشغيل ذلك للجميع، ابدأ الخادم بـ `--sandbox off`، أو اضبط `CC_SERVER_SANDBOX=off`. تعمل تشغيلات كل الأعضاء حينها بلا عزل على ذلك الجهاز، فالقرار يخص كل من يستخدم الخادم، ويُتخذ مرة واحدة عند الإقلاع. الافتراضي `on`: يغلّف كل تشغيل حين تكون للمضيف خلفية، وحين لا تكون يبدأ تشغيلات المالك وحدها.

حالتان لا تنالان تغليفًا ببيئة معزولة أصلية أبدًا. على **Windows** يبلّغ
الفحص الأصلي دائمًا بعدم التوفر، ولا شيء يُثبَّت ، فلا تبدأ إلا تشغيلات مالك الخادم، ما لم يمرّر المالك `--sandbox off`. خلفية `microvm` منفصلة (الطرفيّات التفاعلية والمنصات)، وفحصها
مرهون بزمن تشغيلها الخاص. على **Linux وWSL2** يجب أن يكون `bwrap` و`socat`
كلاهما على `PATH`؛ ومن دونهما يبلّغ الفحص بعدم التوفر ويسمّي الحزم الناقصة، ولا تبدأ إلا تشغيلات المالك.

على Linux أو WSL2 مع تثبيت bubblewrap، لا تُفرَض أنماط glob لملفات الأسرار
في السياسة القياسية على ملفات ينشئها الوكيل لاحقًا، لذلك يفشل كل تشغيل أصلي بدل أن يتجاهل القواعد في صمت، حتى تشغيلات المالك. ولذلك لا يعني نجاح فحص الإقلاع أن إرسال Linux يستطيع البدء: فالخادم على Linux اليوم يشغّل الوكلاء بالخيار `--sandbox off`، أو بلا bubblewrap لتشغيلات المالك وحده. `--sandbox off` انسحاب متعمّد بلا حصر، لا حد أمان بديل.

## اعرف ما يرفضه الوضع أصلًا

يُخزَّن الوضع لكل مساحة، ويغذّي محلّل الضوابط بطبقة **الإعداد المسبق للوضع**.
ثلاثة من الأوضاع الأربعة للقراءة فقط، ووضع القراءة فقط يرفض اثني عشر صنف
أثر رفضًا باتًا:

| الوضع | شجرة العمل | ما يرفضه الإعداد المسبق |
| --- | --- | --- |
| **الوكيل** (`chat`) | قابلة للكتابة | لا شيء — تنطبق الافتراضيات المضمّنة |
| **تخطيط** | للقراءة فقط | حذف ملف، والكتابة خارج شجرة العمل، وإنشاء إيداع، والدفع إلى مستودع بعيد، وفتح طلب سحب، ونشر مراجعة أو إجراء دمج، والكتابة إلى متتبع خارجي، وتثبيت حزمة، وتشغيل عملية، وتغيير بنية مساحة العمل، وقيادة حاوية معزولة (منصة)، وتشغيل أوامر على المضيف |
| **مراجعة** | للقراءة فقط | الاثنا عشر نفسها. لا يختاره المستخدم — لا يعرض حقل الكتابة إلا الوكيل والتخطيط والتنسيق |
| **تنسيق** | للقراءة فقط | الاثنا عشر نفسها |

الوصول إلى الشبكة وقراءة الأسرار _لا_ يرفضهما وضع القراءة فقط، عمدًا:
البحث هو غاية هذا الوضع.

## اطلب موافقة قبل تنفيذ الإجراء

الموافقة قرار من الضوابط، لا إعداد في البيئة المعزولة.

1. انتقل إلى **الإعدادات ← مساحة العمل ← أذونات الوكلاء**
2. اضبط صنف الإجراء على **السؤال أولًا** في نطاق مساحة العمل أو الوكيل أو المساحة

قرار **السؤال أولًا** يقطع التشغيل ويسألك. ومن غير معتمِد متصل يفشل مغلقًا،
ويُرفض الإجراء. انظر
[تهيئة الضوابط](/ar-SA/دليل-المستخدم/أدلة-إرشادية/تهيئة-الضوابط/) لترتيب
البتّ كاملًا.

## استكشاف الأخطاء وإصلاحها

### الوكيل لا يستطيع الدفع، ولم أرفضه قط

انظر ما يطبعه git. `Control Center policy: …` تعني أن قاعدة رفضت الدفع، أو أن
**السؤال أولًا** لم يلقَ جوابًا. `… is not linked to this workspace` تعني أن
الهدف ليس مستودع شجرة العمل نفسه ولا هو مرتبط بمساحة العمل.
`Control Center has no GitHub credential that can push …` تعني أنه تعذّر إصدار أي رمز دفع: ثبّت تطبيق GitHub على ذلك المستودع، أو سجّل الدخول إلى GitHub.

### رُفض تشغيل وكيلي برسالة "This server has no sandbox"

يعرض التشغيل **يحتاج الوكلاء إلى حاوية معزولة على هذا الخادم** مع الرسالة "لا توجد حاوية معزولة على هذا الخادم، لذا لا يمكن إلا لمالكه تشغيل الوكلاء هنا. يمكن للمالك تثبيت الحاوية المعزولة، أو إيقاف العزل للجميع." يعني ذلك أن جهاز الخادم لا يملك بيئة معزولة من نظام التشغيل، وأن الشخص المسؤول عن التشغيل ليس مالك الخادم، فلم يبدأ شيء. في الجدولة أو webhook أو غيرها من الأتمتة، الشخص المسؤول هو الشخص الذي ترتبط به الأتمتة، لا من ينظر إليها.

لا يغيّر هذا إلا مالك الخادم. على Linux وWSL2 يثبّت `bubblewrap` و`socat` ويعيد تشغيل الخادم (لكن اقرأ ملاحظة Linux أعلاه أولًا). على Windows لا توجد خلفية تُثبَّت. والخيار الآخر هو إعادة تشغيل الخادم بالخيار `--sandbox off`، فيشغّل تشغيلات كل الأعضاء بلا عزل على ذلك الجهاز.

### بطاقة العزل تبلّغ بغياب بيئة معزولة أصلية

عندئذ لا يغلّف Seatbelt ولا bubblewrap تشغيلات الوكيل على ذلك المضيف، فلا تبدأ إلا تشغيلات مالك الخادم،
والحدود الباقية هي ما لديهم. على Linux وWSL2، ثبّت الأداتين الناقصتين —
`sudo apt-get install bubblewrap socat` — ثم أعد تشغيل الخادم؛ يُفترض أن
يقول سجل الإقلاع بعدها إن البيئة المعزولة مشغّلة. على Windows لا خلفية
أصلية تُثبَّت، فشدّد الضوابط لتشغيلات المالك وحده: انظر
[تهيئة الضوابط](/ar-SA/دليل-المستخدم/أدلة-إرشادية/تهيئة-الضوابط/).

### بلغ الوكيل ملفًا خارج شجرة عمله

الأداة التي بلغته هي التي تقرر أهذا متوقع.

أدوات الملفات داخل العملية في الإطار (read وwrite وedit وapply patch
وsearch وfind وsearch_files) تعمل داخل عملية الخادم، فلا ينطبق عليها ملف
تعريف للبيئة المعزولة — حدّها حصر مساراتها الخاص مع الضوابط. أمر `bash` أو
سطر أوامر Claude Code _يُغلَّف_ حيث توجد خلفية، ونسخ العمل المسجّلة لديك
ممنوعة الكتابة داخل ذلك التغليف في كل وضع، بما في ذلك صيغها بعد حل الوصلة
الرمزية (على macOS، المسار الذي يُبلَغ عبر `/tmp` أو `/var/folders` يُحَل
تحت `/private`، والصيغتان مرفوضتان). تحت `--sandbox off`، أو لتشغيلات المالك وحدها على مضيف بلا خلفية، لا ينطبق شيء
من ذلك. وفي الحالتين تستطيع الضوابط رفض **الكتابة خارج شجرة العمل** رفضًا
باتًا.
