يُحسم عزل تشغيل الوكيل على الخادم، عند الإقلاع (`--sandbox`). مفتاح
**تمكين البيئة المعزولة**، ومنتقي **الخلفية**، ومفاتيح **القدرات الافتراضية · المساحات الجديدة**
تحت **الإعدادات ← الخادم ← التشخيص والخصوصية** تفضيلات مخزّنة على جهازك.
كشف المضيف في بطاقة **العزل** يبلّغ عما يستطيع مضيف الخادم تغليفه.

ضابطان يبلغان التشغيل، وهذا الدليل يغطيهما معًا: **أذونات البيئة المعزولة**
لكل وكيل، في القسم أدناه، وعلم `--sandbox` الخاص بالخادم.

## ما الذي يقيّد تشغيل الوكيل

يُقيَّد الوكيل بستة حدود. أولها بيئة نظام التشغيل المعزولة، وهي الحد
المشروط — والخمسة الأخرى تثبت على كل مضيف.

| الحد | ما يفعله |
| --- | --- |
| بيئة نظام التشغيل المعزولة | Seatbelt على macOS، وbubblewrap على Linux وWSL2. تغلّف سطر أوامر Claude Code ومحوّلات ACP وأداة `bash` في الإطار. **غائبة على Windows وعلى Linux من غير `bwrap` و`socat`** |
| شجرة العمل الخاصة به | تحصل كل محادثة على دليل عمل بالنسخ عند الكتابة. يُضم الدليل الأصلي إلى التشغيل مسارًا ممنوع الكتابة، والبيئة المعزولة هي التي تفرض ذلك |
| بيانات الاعتماد عبر الوسيط | يصدر وسيط بيانات الاعتماد بيئة لكل تشغيل من قدرات الوكيل، ويسحبها عند التفكيك. بلا قدرة، بلا رمز في البيئة |
| ضوابط الإجراء | تصرّح كل أداة تعدّل الحالة بأصناف أثرها، ويحسمها الحارس قبل أن يجري الاستدعاء. يُرفض `prompt` إذا لم يتصل معتمِد |
| تعقيم البيئة | يحصل ACP وأداة `bash` في الإطار على بيئة مُرشَّحة. ويرث Claude Code عبر `NoSandboxAdapter` بيئة المضيف |
| سطح أدوات الوضع | ينزع وضع القراءة فقط أدوات تعديل شجرة العمل نزعًا كاملًا، ويثبّت فعل الإخراج الخاص بالوضع حتى يظل التسليم ممكنًا |

ثلاثة أمور تبقى أضعف مما تبدو:

- **الإطار المضمّن** وحده يفرض بوابة الأدوات وعقود الإكمال والقواعد
  البنيوية للوضع. محوّل Claude Code لا يفرض شيئًا من ذلك. ويُطلَق Claude
  Code تحديدًا مع `--dangerously-skip-permissions`، لأن `claude -p` غير
  التفاعلي كان سيتوقف إلى الأبد عند مطالبته الخاصة — فلا يرى Control Center
  استدعاءات read وwrite وedit وbash الخاصة بـ Claude، ولا يضع عليها بوابة.
  حيث تكون البيئة المعزولة مشغّلة، هي الحد الذي يحيط بهذه الاستدعاءات.
- أدوات الملفات داخل العملية في الإطار (read وwrite وedit وapply patch
  وsearch وfind وsearch_files) تعمل داخل عملية الخادم، فلا يقيّدها ملف
  تعريف للبيئة المعزولة. أداة `bash` وحدها تمر بمشغّل الأوامر المعزول.
  حدّ هذه الأدوات حصر مساراتها الخاص، مع ضوابط الإجراء.
- على مضيف بلا خلفية لا ينطبق الصف الأول أصلًا. يرجع ACP وأداة `bash` في
  الإطار إلى تعقيم البيئة وسياسة الأوامر، ويرث Claude Code بيئة المضيف عبر
  `NoSandboxAdapter`. ويقول الخادم ذلك في سجل إقلاعه. افحص سجلك أدناه.

## اضبط قدرات الوكيل

هذا ضبط القدرات الوحيد الذي يقرأه الخادم. هو لكل وكيل، ويقرر ما يضعه وسيط
بيانات الاعتماد في بيئة ذلك الوكيل.

1. انتقل إلى **الإعدادات ← مساحة العمل ← الوكلاء**
2. اختر الوكيل من القائمة
3. في علامة تبويب **الإعدادات**، انزل إلى **أذونات البيئة المعزولة**
4. شغّل المفتاح — يتبدّل تعليق الصف، وكان **استخدام إعداد مساحة العمل الافتراضي**
5. اضبط المبدّلات الأربعة:

| المبدّل | ما يضبطه |
| --- | --- |
| **السماح بـ ⁨git push⁩** | مع إطفاء هذا المبدّل يحصل التشغيل على `GIT_ASKPASS=/usr/bin/false` و`GIT_TERMINAL_PROMPT=0`، فلا يستطيع الدفع أن يطلب بيانات اعتماد |
| **السماح باستدعاءات GitHub API** | مع **السماح بـ ⁨git push⁩**، يضبط هل يحقن الوسيط رمز GitHub على هيئة `GH_TOKEN` / `GITHUB_TOKEN` |
| **السماح باستدعاءات API للتذاكر** | يضبط هل يحقن الوسيط `TICKETING_API_KEY` |
| **السماح بالوصول العام إلى الشبكة** | حيث تكون البيئة المعزولة مشغّلة، هذه بوابة خروج حقيقية: مع إطفائها تفرغ قائمة سماح التشغيل، ويُرفض كل طلب صادر عند البروكسي. حيث لا توجد خلفية، يُسجَّل المبدّل على التشغيل ولا يحجب شيئًا تفعله عملية مُطلَقة |

6. احفظ

نقطة التحقق: أعد فتح الوكيل، فالمفتاح ما زال مشغّلًا وبمبدّلاتك — مجموعة
القدرات المحفوظة تُحفَظ على الخادم وتُسترجَع منه، والوكيل الذي بلا مجموعة
يرجع إلى الافتراضي المتحفّظ (الدفع مطفأ، وGitHub API مطفأ، والتذاكر مطفأة،
والشبكة مشغّلة).

:::caution[هنا يُخطَأ في أمرين]
يقول التعليق **استخدام إعداد مساحة العمل الافتراضي**، لكن لا يوجد إعداد
قدرات على مستوى مساحة العمل يقرأه الخادم. الوكيل الذي مفتاحه مطفأ يحصل على
الافتراضي المتحفّظ المضمّن.

وبمعزل عن ذلك، بيانات اعتماد GitHub للتشغيل هي ما لدى الوسيط لا غير —
رمز تثبيت GitHub App محصور بالمستودع، أو الرجوع إلى PAT من البيئة — لا
الرمز المخزّن للعضو الطالب. يُمرَّر `actingUserId` حتى يستطيع الوسيط *حجب*
PAT الخادم عن عضو ليس المالك ولم يربط GitHub، ولا يدمج رمزًا شخصيًا فوق
قدرة مطفأة. لا تعامل **السماح باستدعاءات GitHub API** على أنه حد خروج
صارم على مضيف بلا بيئة نظام التشغيل المعزولة: العملية المُطلَقة ما زالت
تبلغ الشبكة.
:::

## تحقق هل تشغيلات وكيلك معزولة

يحسمه أمران، وكلاهما على الخادم: هل يقدّم المضيف خلفية، وهل `--sandbox`
مشغّل. افحصهما بهذا الترتيب.

1. انتقل إلى **الإعدادات ← الخادم ← التشخيص والخصوصية**
2. اقرأ بطاقة **العزل**. حقيقة **المضيف** هي الآلة التي يعمل عليها
   `cc_server`، لا الآلة التي تنظر إليها. يسرد حقل **الخلفية** **بيئة معزولة أصلية**
   (Seatbelt على macOS، وbubblewrap على Linux وWSL2) أو **بلا عزل**. حقيقة
   **ساري المفعول** تفضيل هذا الجهاز، لا التغليف الذي يستخدمه الخادم فعلًا.
3. اقرأ سجل إقلاع الخادم. يطبع سطرًا واحدًا بالضبط من ثلاثة:
   - `agent sandbox ON` مع ملاحظة الخلفية — التشغيلات مغلَّفة
   - `no OS-native agent sandbox on this host` مع تلميح تثبيت حيث يوجد
     واحد — التشغيلات غير مغلَّفة
   - `agent sandbox DISABLED by --sandbox off` — انسحاب متعمّد

لا يبلّغ `GET /healthz` بحالة العزل، فسجل الإقلاع هو وسيلة الفحص.

لإطفاء البيئة المعزولة عمدًا — والمضيف الذي يختل فيه ملف التعريف هو سبب
وجود هذا الخيار — ابدأ الخادم بـ `--sandbox off`، أو اضبط
`CC_SERVER_SANDBOX=off`. الافتراضي `on`، ومعنى `on` «استخدم خلفية إن كانت
لدى المضيف»، لا «اشترط واحدة».

حالتان لا تنالان تغليفًا ببيئة معزولة أصلية أبدًا. على **Windows** يبلّغ
الفحص الأصلي دائمًا بعدم التوفر، ولا شيء يُثبَّت — وإرسال الوكيل يستخدم
`none`. خلفية `microvm` منفصلة (الطرفيّات التفاعلية والمنصات)، وفحصها
مرهون بزمن تشغيلها الخاص. على **Linux وWSL2** يجب أن يكون `bwrap` و`socat`
كلاهما على `PATH`؛ ومن دونهما يبلّغ الفحص بعدم التوفر ويسمّي الحزم الناقصة.

على Linux أو WSL2 مع تثبيت bubblewrap، لا تُفرَض أنماط glob لملفات الأسرار
في السياسة القياسية على ملفات ينشئها الوكيل لاحقًا. مثل هذا التشغيل الأصلي
يفشل الآن بدل أن يتجاهل القواعد في صمت. لذلك لا يضمن نجاح فحص الإقلاع أن
إرسالًا على Linux يستطيع البدء. `--sandbox off` انسحاب متعمّد بلا حصر، لا
حد أمان بديل.

## اعرف ما يرفضه الوضع أصلًا

يُخزَّن الوضع لكل مساحة، ويغذّي محلّل الضوابط بطبقة **الإعداد المسبق للوضع**.
ثلاثة من الأوضاع الأربعة للقراءة فقط، ووضع القراءة فقط يرفض أحد عشر صنف
أثر رفضًا باتًا:

| الوضع | شجرة العمل | ما يرفضه الإعداد المسبق |
| --- | --- | --- |
| **الوكيل** (`chat`) | قابلة للكتابة | لا شيء — تنطبق الافتراضيات المضمّنة |
| **تخطيط** | للقراءة فقط | حذف ملف، والكتابة خارج شجرة العمل، وإنشاء إيداع، والدفع إلى مستودع بعيد، وفتح طلب سحب، ونشر مراجعة أو إجراء دمج، والكتابة إلى متتبع خارجي، وتثبيت حزمة، وتشغيل عملية، وتغيير بنية مساحة العمل، وقيادة حاوية معزولة (منصة) |
| **مراجعة** | للقراءة فقط | الأحد عشر نفسها. لا يختاره المستخدم — لا يعرض حقل الكتابة إلا الوكيل والتخطيط والتنسيق |
| **تنسيق** | للقراءة فقط | الأحد عشر نفسها |

الوصول إلى الشبكة وقراءة الأسرار _لا_ يرفضهما وضع القراءة فقط، عمدًا:
البحث هو غاية هذا الوضع.

## اطلب موافقة قبل تنفيذ الإجراء

الموافقة قرار من الضوابط، لا إعداد في البيئة المعزولة.

1. انتقل إلى **الإعدادات ← مساحة العمل ← أذونات الوكلاء**
2. اضبط صنف الإجراء على **السؤال أولًا** في نطاق مساحة العمل أو الوكيل أو المساحة

قرار **السؤال أولًا** يقطع التشغيل ويسألك. ومن غير معتمِد متصل يفشل مغلقًا،
ويُرفض الإجراء. انظر
[تهيئة الضوابط](/ar-SA/دليل-المستخدم/أدلة-إرشادية/تهيئة-الضوابط/) لترتيب
البتّ كاملًا.

## استكشاف الأخطاء وإصلاحها

### الوكيل لا يستطيع الدفع، ولم أرفضه قط

افحص **أذونات البيئة المعزولة** لدى الوكيل. الوكيل الذي بلا مجموعة قدرات
مخصّصة يحصل على الافتراضي المتحفّظ، و**السماح بـ ⁨git push⁩** فيه مطفأ —
فلا يحقن الوسيط رمز GitHub، ولا سبيل لـ git إلى المصادقة.

### بطاقة العزل تبلّغ بغياب بيئة معزولة أصلية

عندئذ لا يغلّف Seatbelt ولا bubblewrap تشغيلات الوكيل على ذلك المضيف،
والحدود الباقية هي ما لديك. على Linux وWSL2، ثبّت الأداتين الناقصتين —
`sudo apt-get install bubblewrap socat` — ثم أعد تشغيل الخادم؛ يُفترض أن
يقول سجل الإقلاع بعدها إن البيئة المعزولة مشغّلة. على Windows لا خلفية
أصلية تُثبَّت، فشدّد الضوابط: انظر
[تهيئة الضوابط](/ar-SA/دليل-المستخدم/أدلة-إرشادية/تهيئة-الضوابط/).

### بلغ الوكيل ملفًا خارج شجرة عمله

الأداة التي بلغته هي التي تقرر أهذا متوقع.

أدوات الملفات داخل العملية في الإطار (read وwrite وedit وapply patch
وsearch وfind وsearch_files) تعمل داخل عملية الخادم، فلا ينطبق عليها ملف
تعريف للبيئة المعزولة — حدّها حصر مساراتها الخاص مع الضوابط. أمر `bash` أو
سطر أوامر Claude Code _يُغلَّف_ حيث توجد خلفية، ونسخ العمل المسجّلة لديك
ممنوعة الكتابة داخل ذلك التغليف في كل وضع، بما في ذلك صيغها بعد حل الوصلة
الرمزية (على macOS، المسار الذي يُبلَغ عبر `/tmp` أو `/var/folders` يُحَل
تحت `/private`، والصيغتان مرفوضتان الآن). على مضيف بلا خلفية لا ينطبق شيء
من ذلك. وفي الحالتين تستطيع الضوابط رفض **الكتابة خارج شجرة العمل** رفضًا
باتًا.
