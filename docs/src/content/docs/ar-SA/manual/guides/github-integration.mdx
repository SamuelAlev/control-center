يغطي هذا الدليل ما يخص GitHub من الإعداد. GitHub واحد من ثلاثة مضيفين مدعومين
للشفرة — انظر [ربط مضيف شفرة](/ar-SA/دليل-المستخدم/أدلة-إرشادية/ربط-مضيف-شفرة/)
لربط GitLab أو Bitbucket، ولكيف تضم مساحة العمل المضيفين معًا.

## المتطلبات

- حساب GitHub يصل إلى المستودعات التي تريد العمل عليها
- إما تطبيق GitHub مسجّل لخادمك (انظر
  [إنشاء تطبيق GitHub](/ar-SA/دليل-المستخدم/أدلة-إرشادية/تطبيق-github/)) حتى تستطيع **تسجيل الدخول**،
  **أو** رمز وصول شخصي بصلاحيتَي `repo` و`read:org` للصق

:::note[بيانات الاعتماد تعيش على الخادم، ومرتبطة بك]
لا يُخزَّن شيء على الجهاز الذي تكتب عليه. يحتفظ `cc_server` باعتمادك، ومفتاحه
معرّف مستخدمك، ويستخدمه كل جهاز تسجّل الدخول منه — الحاسوب والويب والهاتف. لا
يقرؤه عضو آخر على الخادم نفسه، وتسجيل دخوله أمر يفعله بنفسه.
:::

## تسجيل الدخول عبر GitHub

**تدفق الجهاز**: يعرض GitHub رمزًا قصيرًا، توافق عليه في github.com، ويتلقى
الخادم الاعتماد — بلا عنوان للرد، وبلا منفذ، وبلا شيء يُكشف. وهو متاح متى كان
للخادم معرّف عميل، والبناء الرسمي يتضمّنه أصلًا.

1. انتقل إلى **الإعدادات ← مساحة العمل ← الملف الشخصي والهوية ← استضافة الكود** (أو الخطوة الأولى
   من الإعداد الأولي)
2. في صف **GitHub**، انقر **تسجيل الدخول عبر GitHub**
3. يعرض حوار رمزًا من ثمانية محارف ويفتح
   [github.com/login/device](https://github.com/login/device) في متصفحك.
   وقد نُسخ الرمز إلى الحافظة
4. الصقه، ووافق على التطبيق، ثم عُد. يتحوّل الصف من تلقاء نفسه إلى
   «تم تسجيل الدخول باسم ⁨_your-username_⁩.»

يمكن إغلاق الحوار وأنت تُتم العمل في المتصفح — يواصل الخادم الاستطلاع حتى تنتهي
صلاحية الرمز (نحو 15 دقيقة)، فيكتمل تسجيل الدخول.

## أو الصق رمزًا

البديل حين لا تطبيق لدى الخادم، أو حين لا يكون التطبيق مثبّتًا على حساب تحتاجه،
أو حين تفضّل استخدام رمز وصول شخصي.

1. انتقل إلى **الإعدادات ← مساحة العمل ← الملف الشخصي والهوية ← استضافة الكود**
2. في صف **GitHub**، انقر **إضافة رمز وصول**
3. الصق رمزًا بصلاحيتَي `repo` و`read:org` (كلاسيكي) ثم احفظ. الرمز **دقيق الصلاحيات**
   يحتاج في المستودع إلى **المحتويات** و**طلبات السحب** (قراءة وكتابة)،
   وإلى **الفحوصات** و**الإجراءات** (قراءة).

يُسبَر الرمز لحظة تخزينه، فيستطيع الصف تسمية الحساب الذي يعود إليه. انقر
**قطع الاتصال** لإزالته.

نقطة التحقق: يقرأ صف **GitHub** «تم تسجيل الدخول باسم ⁨_your-username_⁩.». لاحقة
تسمّي المصدر حين لا يكون الاعتماد الذي يجيب اعتمادك — «عبر تطبيق هذا الخادم» أو
«من البيئة».

:::note[الأولوية ثابتة]
الطلب الذي يُقدَّم نيابة عنك يستخدم **اعتمادك** ولا شيء غيره — البيئة اعتماد
الخادم لا اعتمادك، فلا تنوب عنك. العمل الذي لا إنسان خلفه (خطافات الويب،
واستطلاع طلبات السحب، ومزامنة التذاكر) يحل هوية تطبيق الخادم أولًا، ثم اعتماد
مالك الخادم، ثم البيئة.
:::

## ما يوفّره التكامل

| الميزة | كيف |
| --- | --- |
| قائمة طلبات السحب وتفاصيلها | واجهة GitHub REST، من الخادم، بهوية التطبيق أو باعتمادك |
| تشغيلات الفحوصات | واجهة GitHub Checks |
| نشر المراجعة | خطوة لا يمرّرها إلا المستخدم، وتنشر مراجعتك على طلب السحب |
| تسجيل المستودع | تُقبل نسخة العمل إذا أشار مستودعها البعيد `origin` إلى github.com — أو إلى gitlab.com / bitbucket.org |
| وصول الوكيل إلى GitHub | يحقن وسيط بيانات الاعتماد رمزًا للقراءة فقط في `GH_TOKEN` / `GITHUB_TOKEN`؛ ويمر الدفع عبر Control Center |
| تنبيهات الإشعارات | استطلاع من الخادم لصندوق إشعارات GitHub يرفع «تمت الإشارة إليك في طلب سحب» و«تم طلب مراجعة» |
| ملفات المستخدمين | بطاقات الملف التي تظهر عند التحويم، وتصفية طلبات السحب حسب المؤلف |

بعض المسارات تستخدم واجهة GraphQL بدل REST حيث هي أقل كلفة — نشاط الفروع في
منتقي إنشاء طلب السحب، وحالة المراجعة الحية التي تقرّر إن كان إشعار «تم طلب
مراجعة» ما زال معلّقًا.

## راقب انقطاعات GitHub

يعرض شريط العنوان شارة حالة حين يتدهور مزوّد، وتشمل GitHub وClaude وOpenAI
وKimi. **تبقى مخفية ما دام كل شيء سليمًا** — فظهورها يبلّغ عن العطل، لا عن
غيابه.

انقر الشارة لفتح لوحة منبثقة فيها حالة كل مزوّد وزر تحديث. تتجدد الحالات من
تلقاء نفسها كل دقيقتين.

## اعرف كيف يتصرف الوكلاء على GitHub

- الوكيل الذي يعمل في شجرة عمل GitHub يحصل دائمًا على رمز GitHub للقراءة فقط.
  يمر الدفع عبر Control Center، الذي يسأل قاعدة **الدفع إلى مستودع بعيد** ثم
  يمرّر الدفع برمز كتابة لا يحمله الوكيل أبدًا. انظر
  [تهيئة سياسات البيئة المعزولة](/ar-SA/دليل-المستخدم/أدلة-إرشادية/سياسات-البيئة-المعزولة/)
- الإيداعات التي يصنعها الوكيل تُؤلَّف **باسم الوكيل** — اسم العرض مع
  ` (agent)`، على عنوان اصطناعي مفتاحه معرّف الوكيل — ولا تُؤلَّف أبدًا باسم
  إنسان. يُنسَب من طلب العمل بتذييل `Co-Authored-By`
- إذا ضُبط تطبيق GitHub، يصدر الوسيط لكل إطلاق رموز تثبيت دقيقة الصلاحيات،
  محصورة بالمستودع، لعمر يقارب الساعة، بدل تسليم رمز واسع. يُحَل التثبيت من
  **مالك** مستودع التشغيل، فيقتصر تطبيق واحد مثبّت على عدة حسابات على الحساب
  الذي يمسّه التشغيل. بلا تطبيق، يتلقى الوكلاء رمز البيئة، ولا يمكن حصره في
  القراءة: تلزم قاعدة الدفع حينها `git push`، لكنها لا تلزم الشفرة التي تستخدم
  الرمز مباشرة
- الرمز رمز الوسيط دائمًا، لا رمز العضو الطالب. ويُحجب رمز الخادم عن التشغيلات
  التي تعمل نيابة عن عضو ليس المالك ولم يربط GitHub

## استكشاف الأخطاء وإصلاحها

### قائمة طلبات السحب فارغة وتقول إن GitHub غير متصل

ليس لديك اعتماد GitHub على هذا الخادم. سجّل الدخول أو الصق رمزًا تحت
**استضافة الكود**. مستودعات المضيفين الآخرين لا تتأثر — وحدها مستودعات GitHub
لا تساهم بشيء.

### الصف يعرض «إضافة رمز وصول» ولا يعرض «تسجيل الدخول عبر GitHub»

لا معرّف عميل لدى الخادم — وهذه الحال الطبيعية عند البناء من المصدر، إذ لا
تُضمَّن بيانات الاعتماد إلا في البناءات الرسمية. انظر
[إنشاء تطبيق GitHub](/ar-SA/دليل-المستخدم/أدلة-إرشادية/تطبيق-github/): يستغرق نحو دقيقتين،
ولا يفعله إلا مالك الخادم، ومرة واحدة.

### يقول حوار تسجيل الدخول إن المزوّد لم يُرجع رمز جهاز

تطبيق GitHub موجود، لكن خانة **تدفق الجهاز** مطفأة. فعّلها من إعدادات التطبيق
(عام ← تدفق الجهاز) ثم أعد المحاولة.

### يقول الصف «عبر تطبيق هذا الخادم» وكنت أنتظر حسابي

لم تسجّل دخولك، وما تراه هوية تطبيق الخادم وهي تجيب. انقر **تسجيل الدخول عبر GitHub**
في ذلك الصف.

### رمز دقيق الصلاحيات لا يُظهر زر الدمج ولا حالة الفحوصات

يحتاج الرمز إلى **المحتويات** و**طلبات السحب** (قراءة وكتابة)، وإلى
**الفحوصات** و**الإجراءات** (قراءة). بعد تغيير الأذونات، الصقه مجددًا تحت
استضافة الكود.

### رُفضت إضافة مستودع

يشترط التسجيل الثلاثة معًا: أن يقع المسار داخل شجرة عمل Git، وأن يكون له مستودع
بعيد `origin`، وأن يشير ذلك البعيد إلى مضيف شفرة مدعوم (github.com أو
gitlab.com أو bitbucket.org). انظر
[إضافة مستودعات إلى مساحة عمل](/ar-SA/دليل-المستخدم/أدلة-إرشادية/إضافة-مستودعات/).

### يتوقف كل شيء فترة بعد الاستخدام الكثيف

هذا قاطع حد المعدّل. يشير GitHub إلى حدّه الأساسي بـ `403` يحمل
`x-ratelimit-remaining: 0` ووقت إعادة التعيين؛ وعند رؤية واحد، يفشل العميل ما
يلي من طلبات محليًا وبلا اتصال بالشبكة إلى أن تنقضي النافذة، فلا يعمّق تكرار
المحاولة الحد. تُعاد المحاولة عند الأعطال العابرة حتى ثلاث مرات بتراجع أسي، مع
الالتزام بـ `retry-after`.
