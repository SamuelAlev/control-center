يغطي هذا الدليل ما يخص GitHub من الإعداد. GitHub واحد من ثلاثة مضيفين مدعومين
للشفرة. انظر [ربط مضيف شفرة](/ar-SA/دليل-المستخدم/أدلة-إرشادية/ربط-مضيف-شفرة/)
لربط GitLab أو Bitbucket، ولكيف تضم مساحة العمل المضيفين معًا.

## المتطلبات

- حساب GitHub يصل إلى المستودعات التي تريد العمل عليها
- خادم يستطيع إدخال الناس إلى GitHub: إما بتطبيق GitHub خاص به (انظر
  [إنشاء تطبيق GitHub](/ar-SA/دليل-المستخدم/أدلة-إرشادية/تطبيق-github/))، وإما عبر
  Control Center Connect، بحسب ما يختاره مالك الخادم في **الإعدادات ← الخادم ←
  تسجيل الدخول الموحّد**

:::note[بيانات الاعتماد تعيش على الخادم، ومرتبطة بك]
لا يُخزَّن شيء على الجهاز الذي تكتب عليه. يحتفظ `cc_server` بتسجيل دخولك إلى
GitHub، ومفتاحه معرّف مستخدمك، ويستخدمه كل جهاز تسجّل الدخول منه: الحاسوب والويب
والهاتف. لا يستطيع عضو آخر على الخادم نفسه استخدامه، وتسجيل دخوله أمر يفعله بنفسه.
:::

## تسجيل الدخول إلى GitHub

GitHub بتسجيل الدخول فقط: لا يوجد رمز للصقه.

1. انتقل إلى **الإعدادات ← أنت ← الملف الشخصي ← استضافة الكود** (أو
   الخطوة الأولى من الإعداد الأولي)
2. في صف **GitHub**، انقر **تسجيل الدخول إلى GitHub**
3. يفتح متصفحك GitHub. وافق على التطبيق

طريقة إتمام تسجيل الدخول تتوقف على من يشغّله:

- **التطبيق الخاص بالخادم:** يعيد GitHub متصفحك إلى الخادم، ويلاحظ الحوار ذلك من
  تلقاء نفسه. لا شيء تكتبه
- **Control Center Connect:** تعرض صفحة المتصفح رمزًا من 8 أحرف. اكتبه في الحوار،
  أو دع المتصفح يفتح Control Center عبر الرابط `control-center://` فلا تحتاج إلى
  كتابته

نقطة التحقق: يقرأ صف **GitHub** «تم تسجيل الدخول باسم ⁨_your-username_⁩.».

يرفض الحوار أي رمز أو رابط لم يبدأه هو، بالرسالة **لم يبدأ تسجيل الدخول من هنا**.
إن أرسل إليك أحدهم رابط تسجيل دخول، فلا تتابع: إتمامه يربط حسابك بخادمه هو.

انقر **قطع الاتصال** لإزالة تسجيل دخولك. وتسجيل الخروج من GitHub، أو الإزالة من
مساحة عمل، يُسقط أيضًا كل رمز سكّه الخادم نيابة عنك.

## باسم من يتحدث اعتمادك

يفصل Control Center بين العمل **بصفتك شخصًا** والعمل **بصفتك التطبيق**، كما تفعل GitHub:

| ما يحدث | يظهر على GitHub بوصفه |
| --- | --- |
| كل ما تفعله بنفسك: التعليق، والمراجعة، والموافقة، والدمج، وطلب المراجعين | **أنت**. يضع GitHub علامة على تعليق المحادثة بأنه صادر عن تطبيق Control Center؛ أما المراجعة وتعليقاتها المضمّنة فلا تحمل هذه العلامة |
| مراجعة الذكاء الاصطناعي، وردود الوكلاء والتعليقات في محادثات طلبات السحب، والوسوم، وعمل خط الأنابيب والبوت | **بوت Control Center**. على تطبيق Connect المشترك لا تكون المراجعة للبوت إلا لتثبيت أدرجه مشغّل Connect؛ وإلا فتظهر باسم الشخص المسؤول |
| طلب سحب يفتحه وكيل لأجلك، وتعديلاته على عنوان طلب السحب ووصفه، ودفعاته، وإيداعاته | **أنت**. يُنسب Control Center كمؤلف مشارك حين يكون نسب الفضل كمؤلف مشارك مفعّلًا |
| عمل لم يطلبه أحد (الجداول، وwebhooks) | **بوت Control Center**، وهو مؤلف إيداعاته أيضًا. على Control Center Connect لا يدفع أبدًا ولا يفتح طلب سحب |

- **كل ما تفعله** يجري على تسجيل دخولك **أنت** ولا شيء غيره. إن لم تكن مسجّل الدخول، يطلب منك التطبيق تسجيل الدخول. لا ينوب عنك أي اعتماد آخر
- **عمل البوت** يحصل على رمز لمستودع واحد في كل مرة، محدود بما يستطيع عضو مسؤول فعله هناك: العضو الذي طلب، وإلا فمالك مساحة العمل. والعضو الذي لا يستطيع الدفع يحصر الرمز في القراءة. وتبدأ ردود البوت التي تتصرف نيابة عن شخص بعبارة **Control Center (لصالح @login)**
- **يفتح الوكلاء طلبات السحب عبر Control Center**، لا من بيئتهم المعزولة أبدًا، فيكون طلب السحب لك، وتمنعك قواعد GitHub نفسها من الموافقة عليه. ويرفض Control Center أيضًا الموافقة من الشخص الذي طلب من الوكيل العمل، ومن مؤلف طلب السحب. وفي التشغيل المجدول أو عبر Webhook، يشمل ذلك كل مشرف فعّل مشغّله أو عدّل خط أنابيبه وهو مفعّل. يجب أن يراجعه شخص آخر. وإن لم يستطع Control Center التحقق من مَن فتح طلب السحب، أو من أي حساب على المنصة هو حسابك، فإنه يرفض ويطلب منك المحاولة مرة أخرى
- **يعلّق الوكلاء عبر Control Center أيضًا.** لا يستطيع رمز GitHub الذي يحصل عليه تشغيل الوكيل إلا القراءة. حين يعلّق وكيل على طلب السحب الذي يعمل عليه، ينشر Control Center التعليق بوصفه بوتًا، ويبدأ بعبارة **Control Center (لصالح @login)** إن طلب أحد التشغيل. ولا يستطيع الوكيل التعليق إلا على طلب سحب خاص به: في المستودع نفسه، لا على fork، وآخر إيداع فيه دفعه الوكيل أو هو الإيداع الحالي لفرع مساحته. وتُعطَّل الإشارات @ في تعليق الوكيل، فلا تنبّه أحدًا. ويستطيع الوكيل أيضًا تغيير عنوان طلب السحب الخاص به أو وصفه ما دام مفتوحًا. ويُجرى هذا التعديل بالطريقة نفسها التي فُتح بها طلب السحب (باسمك حين طلبت التشغيل)، ويطلب موافقة أولًا افتراضيًا. يحتفظ وصف طلب السحب بإشارات @ الواردة فيه حين يفتحه الوكيل وحين يعدّله، فينبَّه الأشخاص الذين يذكرهم
- **على Control Center Connect لا يدفع البوت ولا يفتح طلب سحب أبدًا.** الدفع وإنشاء فرع وفتح طلب سحب هناك يحتاج إلى شخص طلبه، ويعمل بتسجيل دخوله هو. وتشغيل مجدول أو عبر Webhook يحاول الدفع يتوقف مع رسالة تقول ذلك. ولكي تستطيع التشغيلات بلا مراقبة الدفع، امنح مساحة العمل تطبيق GitHub خاصًا بها في **الإعدادات**
- **ماذا يستطيع بوت Connect.** مع تطبيق Connect المشترك، يعلّق البوت ويضع الوسوم ويتفاعل. وينشر مراجعة (مراجعة الذكاء الاصطناعي، وتعليقات المراجعة، وطلبات المراجعين) فقط حين يكون مشغّل Connect قد أدرج تثبيت هذا الخادم. وإلا فتخرج المراجعة بتسجيل دخول الشخص المسؤول نفسه، وتظهر باسمه. ولا يفتح البوت طلب سحب أو يحرره أو يغلقه أو يغيّر عنوانه، ولا يرفض مراجعة، ولا يحرّر تعليقًا أو يحذفه؛ هذه الأفعال تحتاج إلى شخص طلبها بتسجيل دخوله هو. ولا يربط Connect تثبيت مؤسستك بخادم Control Center واحد: أي خادم سجّل فيه عضو يملك حق الدفع إلى مستودع عبر Connect يستطيع الحصول على رمز تعليقات هذا البوت لذلك المستودع
- **خادم أو مساحة عمل لهما تطبيق GitHub خاص بهما** يحتفظان بالبوت لكل ما سبق، والمراجعات داخلة فيه
- **الأتمتة لا توافق أبدًا** على طلب سحب. الموافقة فعل إنسان

عند ربط مستودع، يتحقق Control Center من أن حسابك يراه، ويحذّرك إن لم يكن تطبيق GitHub مثبّتًا على مؤسسته أو لا يشمل المستودع، مع رابط لإصلاح ذلك. يحتاج ربط المستودع وفكّه إلى مسؤول مساحة عمل، ونسخة العمل الواقعة خارج تخزين مساحة العمل لا يربطها إلا مالك الخادم؛ انظر [إضافة مستودعات إلى مساحة عمل](/ar-SA/دليل-المستخدم/أدلة-إرشادية/إضافة-مستودعات/).

يتبع الربط المعرّف الدائم للمستودع على GitHub، فإعادة التسمية أو النقل لا يتطلب شيئًا منك. وإن صار المسار لاحقًا يسمّي مستودعًا آخر، يتوقف Control Center عن إرسال أي شيء إليه، ويعرض تنبيهًا حتى يضغط مسؤول مساحة العمل **إعادة الربط**.

يحتاج فتح شفرة مستودع (ملفاته، وفروقاته، وبحثه، وطرفيته) إلى المنحة الخاصة به في مساحة العمل وإلى تسجيل دخول GitHub خاص بك يستطيع قراءته. يخضع مسؤولو مساحة العمل للقاعدة نفسها؛ ومالك الخادم وحده معفى.

## ما يوفّره التكامل

| الميزة                      | كيف                                                                                                                                                   |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| قائمة طلبات السحب وتفاصيلها | واجهة GitHub REST، من الخادم، بتسجيل دخولك أنت                                                                                                        |
| تشغيلات الفحوصات            | واجهة GitHub Checks                                                                                                                                   |
| نشر المراجعة                | خطوة لا يمرّرها إلا المستخدم، وتنشر مراجعتك على طلب السحب باسمك                                                                                       |
| تسجيل المستودع              | تُقبل نسخة العمل إذا أشار مستودعها البعيد `origin` إلى github.com — أو إلى gitlab.com / bitbucket.org                                                 |
| الوصول إلى GitHub للوكلاء | داخل التشغيل، يمرّ `git fetch` عبر Control Center، فيجلب المستودعات التي يعمل عليها التشغيل برمز للقراءة فقط لا يحمله التشغيل أبدًا. ويقرأ `gh` المستودعات برمز للقراءة فقط يسلّمه Control Center عند الطلب، ويلغيه عند انتهاء التشغيل. الدفعات وطلبات السحب وتعديلاتها والتعليقات تمر عبر Control Center |
| تنبيهات الإشعارات           | استطلاع من الخادم لصندوق إشعارات GitHub يرفع «تمت الإشارة إليك في طلب سحب» و«تم طلب مراجعة»                                                           |
| ملفات المستخدمين            | بطاقات الملف التي تظهر عند التحويم، وتصفية طلبات السحب حسب المؤلف                                                                                     |

بعض المسارات تستخدم واجهة GraphQL بدل REST حيث هي أقل كلفة — نشاط الفروع في
منتقي إنشاء طلب السحب، وحالة المراجعة الحية التي تقرّر إن كان إشعار «تم طلب
مراجعة» ما زال معلّقًا.

## راقب انقطاعات GitHub

يعرض شريط العنوان شارة حالة حين يتدهور مزوّد، وتشمل GitHub وClaude وOpenAI
وKimi. **تبقى مخفية ما دام كل شيء سليمًا** — فظهورها يبلّغ عن العطل، لا عن
غيابه.

انقر الشارة لفتح لوحة منبثقة فيها حالة كل مزوّد وزر تحديث. تتجدد الحالات من
تلقاء نفسها كل دقيقتين.

## اعرف كيف يتصرف الوكلاء على GitHub

- الوكيل الذي يعمل في شجرة عمل GitHub يحصل على رمز لذلك المستودع الواحد. ولا يستطيع إلا قراءة الشفرة والمسائل وطلبات السحب، وتمر التعليقات عبر Control Center كما هو موضح أعلاه. يمر الدفع عبر Control Center، الذي يسأل قاعدة **الدفع إلى مستودع بعيد** ثم يمرّره برمز كتابة لا يحمله الوكيل أبدًا. انظر
  [تهيئة سياسات البيئة المعزولة](/ar-SA/دليل-المستخدم/أدلة-إرشادية/سياسات-البيئة-المعزولة/)
- العمل الذي تبدؤه يُودَع باسمك. حين تطلب من وكيل شيئًا، أو تودع من IDE، تكون أنت المؤلف والمُودِع، بعنوان تحقّقت منه منصتك: عنوان GitHub المجهول الخاص بك من تسجيل دخولك إلى GitHub، أو على GitLab وBitbucket البريد الذي يُبلغ عنه تسجيل دخولك هناك. ولا تُستخدم هوية Git الخاصة بمساحة العمل إلا لإيداع تودعه يدويًا في مستودع لا تزكّي منصة لعنوان لك فيه. وإن لم تكن مسجّلًا الدخول إلى تلك المنصة، فإيداعات الوكيل تكون للبوت، وتذكر ملاحظات التشغيل ذلك
- العمل الذي لم يطلبه أحد يُودَع باسم البوت. يودع التشغيل المجدول أو عبر Webhook باسم تطبيق GitHub الخاص بمساحة العمل (`<app>[bot]`، مع عنوان noreply الخاص به)، أو باسم `Control Center <hi@usectrl.dev>` حين لا يوجد تطبيق GitHub، أو حين يكون المستودع على GitLab أو Bitbucket
- **نسب الفضل إلى Control Center كمؤلف مشارك** (**الإعدادات ← أنت ← الإيداعات**) يضيف سطر `Co-Authored-By:` للطرف الآخر: Control Center على إيداعاتك، وعلى إيداعات البوت كل شخص فعّل المشغّل الذي وراء التشغيل. وهو مفعّل ما لم تطفئه. ويستطيع مسؤول مساحة العمل أن يقرر ذلك للجميع بـ**نسب الفضل كمؤلف مشارك** في **الإعدادات ← مساحة العمل ← عام**؛ فيُحفظ اختيارك الخاص عندها، لكنه لا يُطبَّق في تلك المساحة. أما إسناد Claude Code نفسه فمعطّل دائمًا
- يمكن توقيع إيداعاتك. تحت **إيداعات موثّقة** في **الإعدادات ← أنت ← الإيداعات**، اختر **إنشاء مفتاح التوقيع**، وأضف نصفه العام إلى حسابك على GitHub أو GitLab بصفته مفتاح توقيع؛ ومن ذلك الوقت تظهر إيداعات التشغيلات التي تطلبها، وإيداعاتك في IDE، موثّقة. يبقى النصف الخاص على خادمك، فمن يتحكم في ذلك الخادم يستطيع التوقيع باسمك ما دام المفتاح على حسابك، وعلى GitHub تبقى الإيداعات التي ظهرت موثّقة كذلك بعد أن تزيل المفتاح. Bitbucket لا يملك مفتاح توقيع للتوقيع وحده: لا تضف المفتاح هناك، والإيداعات على Bitbucket لا تُوقَّع. إيداعات البوت لا تُوقَّع أبدًا
- الإيداعات التي تجريها في لوحة **التحكم بالمصدر** في IDE تتجاوز خطافات Git الخاصة بالمستودع، كما يفعل `git commit --no-verify`، وGit على الخادم يتجاهل مساعدات بيانات الاعتماد والمحرّرات وأدوات الفروق الخارجية والموقّعين التي يضبطها المستودع: إذ يشغّل Git على جهازه هو، في شجرة قد يغيّرها وكيل أو طلب سحب. انظر [الإيداع والدفع من التحكم بالمصدر](/ar-SA/دليل-المستخدم/أدلة-إرشادية/مراجعة-ودمج-طلب-سحب/#الالتزام-والدفع-من-التحكم-بالمصدر)
- كل إيداع يدفعه الوكيل يُفحص أولًا، بما في ذلك الطبقات التي يدفعها `stack_publish` لستاك. ويُرفض الدفع الذي يذكر شخصًا آخر، أو يُسقط إسنادًا أو يستعيره، أو يضيف سطر توقيع، أو لا يكون موقّعًا بالطريقة التي تنص عليها إعداداتك. أما الإيداعات التي تدفعها بنفسك من IDE فهي لك، ولا تُفحص بهذه الطريقة
- الطرفية التي تفتحها على منصة تحصل على تسجيل دخولك أنت، محصورًا في المستودع الواحد، فيكون الدفع منها دفعك أنت
- حين يتعذر سكّ رمز (لا أحد مسؤولًا مسجّل الدخول، أو التطبيق غير مثبّت على المالك، أو التثبيت معلّق)، يذكر الأمر الذي طلب الرمز السبب. لا توجد بيانات اعتماد بديلة

## استكشاف الأخطاء وإصلاحها

### قائمة طلبات السحب فارغة وتقول إن GitHub غير متصل

لم تسجّل الدخول إلى GitHub على هذا الخادم. انقر **تسجيل الدخول إلى GitHub** تحت
**الإعدادات ← أنت ← الملف الشخصي ← استضافة الكود**. مستودعات المضيفين الآخرين لا تتأثر.

### يقول صف GitHub إن تسجيل الدخول غير مُعَدّ على هذا الخادم

ليس للخادم تطبيق GitHub خاص ولا Connect. يختار مالك الخادم أحدهما من **الإعدادات ←
الخادم ← تسجيل الدخول الموحّد**: **إنشاء تطبيق GitHub الخاص بي** يستغرق نحو
دقيقتين. انظر [إنشاء تطبيق GitHub](/ar-SA/دليل-المستخدم/أدلة-إرشادية/تطبيق-github/).

وفي مساحة عمل تعمل على تطبيقاتها الخاصة، يقول الصف ذلك حين يكون تطبيق GitHub الخاص بمساحة العمل ناقصًا أو غير مكتمل. يملأ مسؤول مساحة العمل الحقول في بطاقة **تطبيق GitHub** ضمن **الإعدادات ← مساحة العمل ← التكاملات**؛ انظر [امنح مساحة عمل تطبيقها الخاص](/ar-SA/دليل-المستخدم/أدلة-إرشادية/تطبيق-github/#امنح-مساحة-عمل-تطبيقها-الخاص).

### يقول الحوار إن الرمز غير مطابق

اكتب الرمز كما يعرضه المتصفح تمامًا: 8 أحرف وأرقام. خمسة رموز خاطئة تنهي تسجيل
الدخول؛ ابدأه من جديد.

### يقول تسجيل الدخول إن التطبيق غير مثبّت

ليس لتطبيق GitHub تثبيت على الحساب الذي يملك المستودع. يثبّته مسؤول مساحة العمل من
**الإعدادات ← مساحة العمل ← التكاملات ← تطبيق GitHub ← عمليات تثبيت تطبيق GitHub**.

### على الجميع تسجيل الدخول إلى GitHub من جديد

دوّر مالك الخادم مفتاح Connect الخاص بالخادم، أو بدّل خوادم Connect، أو استُعيد دليل
البيانات على جهاز آخر. تسجيلات الدخول عبر Connect مربوطة بالخادم الذي أجراها.

### رُفضت إضافة مستودع

يشترط التسجيل الثلاثة معًا: أن يقع المسار داخل شجرة عمل Git، وأن يكون له مستودع
بعيد `origin`، وأن يشير ذلك البعيد إلى مضيف شفرة مدعوم (github.com أو
gitlab.com أو bitbucket.org). يجب أن يكون `origin` هو المستودع الذي تربطه، ولا يستطيع ربط مجلد خارج تخزين مساحة العمل إلا مالك الخادم. انظر
[إضافة مستودعات إلى مساحة عمل](/ar-SA/دليل-المستخدم/أدلة-إرشادية/إضافة-مستودعات/).

### لدي منحة لكن المستودع يقول إن حسابي لا يستطيع قراءته

حسابك على GitHub لا يستطيع قراءة ذلك المستودع، لذا تبقى شفرته مغلقة عليك حتى مع منحة مساحة العمل. سجّل الدخول إلى GitHub من **استضافة الكود**، أو اطلب الوصول إلى المستودع على GitHub.

### «تعذّر التحقق من صلاحية وصولك إلى GitHub»

تعذّر الوصول إلى GitHub للتحقق من صلاحية وصولك، فرفض Control Center بدل أن يخمّن. حاول مرة أخرى بعد لحظة.

### تظهر المراجعات على Connect باسمي لا باسم البوت

على تطبيق Connect المشترك، ينشر البوت المراجعات للتثبيتات التي أدرجها مشغّل Connect فقط. وفي أي مكان آخر تخرج المراجعة بتسجيل دخول الشخص المسؤول نفسه. ولكي ينشر البوت المراجعات، امنح مساحة العمل تطبيق GitHub خاصًا بها.

### يتوقف كل شيء فترة بعد الاستخدام الكثيف

هذا قاطع حد المعدّل. يشير GitHub إلى حدّه الأساسي بـ `403` يحمل
`x-ratelimit-remaining: 0` ووقت إعادة التعيين؛ وعند رؤية واحد، يفشل العميل ما
يلي من طلبات محليًا وبلا اتصال بالشبكة إلى أن تنقضي النافذة، فلا يعمّق تكرار
المحاولة الحد. تُعاد المحاولة عند الأعطال العابرة حتى ثلاث مرات بتراجع أسي، مع
الالتزام بـ `retry-after`.
