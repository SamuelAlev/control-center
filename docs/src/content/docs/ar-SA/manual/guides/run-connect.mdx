يشغّل Control Center Connect تسجيلات الدخول لدى المزوّدين (GitHub وGoogle Calendar
وLinear وSlack) للخوادم التي لم تسجّل تطبيقات خاصة بها. يبيّن هذا الدليل كيف تشغّل
Connect الخاص بك، فتبقى تطبيقات المزوّدين وأسرارها وقائمة الخوادم المسموح لها
باستخدامها كلها لديك.

ما يستطيع Connect رؤيته وما لا يستطيع مذكور في
[مرجع Connect](/ar-SA/دليل-المستخدم/مرجع/connect/). اقرأه أولًا إن كنت تقرّر هل
تشغّل واحدًا.

:::note[قد لا تحتاج إليه]
يستطيع الخادم الواحد أن يسجّل تطبيقاته الخاصة بدلًا من ذلك: **الإعدادات ← الخادم ←
تسجيل الدخول الموحّد ← تطبيقات الموفّرين**، حيث يُعِدّ **إنشاء تطبيق GitHub الخاص
بي** GitHub في خطوة واحدة. تطبيقات الخادم الخاصة تُطبَّق فقط تحت **استخدام تطبيقاتي الخاصة**: مع Control Center أو Connect مخصص، يشغّل Connect كل مسار، بينما يبقى تطبيق مساحة العمل الخاص ساريًا. شغّل
Connect حين ينبغي أن تتقاسم عدة خوادم مجموعة تطبيقات واحدة.
:::

## المتطلبات

- عنوان **HTTPS** عام لـ Connect، مثل `https://connect.example.com`، خلف وكيل
  ينهي TLS. لا يُقبل `http` العادي إلا على loopback
- Docker، أو `cc_server` تستطيع إعادة تشغيله بمتغيرات بيئة إضافية
- إذن بتسجيل التطبيقات لدى كل مزوّد تريد خدمته
- الخوادم التي ستستخدمه، ومالكوها في متناولك: لكل خادم معرّف تثبيت تضيفه إلى قائمة
  السماح في Connect

## الخطوة 1: اختر العنوان

اختر عنوان URL الآن واحتفظ به. `CONNECT_PUBLIC_URL` جزء من كل ما يفعله Connect:
توقيعات الطلبات، وبيانات الاعتماد المختومة، وعناوين إعادة التوجيه لدى المزوّدين،
ومعرّف التثبيت لكل خادم، كلها مربوطة به. تغييره لاحقًا يعني تسجيل عناوين إعادة
التوجيه من جديد، وتسجيل دخول كل شخص من جديد.

## الخطوة 2: سجّل تطبيقات المزوّدين

لا تسجّل إلا المزوّدين الذين تريد خدمتهم. المزوّد الذي تنقصه بعض متغيراته يُستبعد من
إعدادات Connect، وتراه الخوادم غير متاح. `<base>` أدناه هو `CONNECT_PUBLIC_URL` الخاص
بك.

| المزوّد | ما يُسجَّل | ما يُحتفظ به |
| --- | --- | --- |
| **GitHub App** | عنوان رد الاتصال `<base>/oauth/github/callback`. عنوان الإعداد `<base>/oauth/github/setup` مع تفعيل **Redirect on update**. اترك **Request user authorization (OAuth) during installation** معطّلًا: حين يكون مفعّلًا يتجاهل GitHub عنوان الإعداد. أبقِ **Expire user authorization tokens** مفعّلًا | معرّف التطبيق، والاسم المختصر (slug)، ومعرّف العميل، وسر العميل، ومفتاح خاص |
| **Google** | عميل OAuth من نوع **Web application** بعنوان إعادة التوجيه `<base>/oauth/google/callback`، مع تفعيل Google Calendar API | معرّف العميل، وسر العميل |
| **Linear** | تطبيق OAuth بعنوانَي رد الاتصال `<base>/oauth/linear/callback` و`<base>/oauth/linear_app/callback` | معرّف العميل فقط |
| **Slack** | عنوانا إعادة التوجيه `<base>/oauth/slack_oidc/callback` و`<base>/oauth/slack/callback`. Event Subscriptions عند `<base>/v1/hooks/slack/events` (`app_mention`، `message.*`، `assistant_thread_*`، `app_uninstalled`، `tokens_revoked`). أوامر الشرطة المائلة عند `<base>/v1/hooks/slack/commands`. تدوير الرموز مفعّل | معرّف التطبيق، ومعرّف العميل، وسر العميل، وسر التوقيع |

امنح GitHub App أذونات المستودع هذه: **Metadata** قراءة، و**Contents** قراءة وكتابة،
و**Pull requests** قراءة وكتابة، و**Issues** قراءة وكتابة، و**Checks** و**Actions**
و**Commit statuses** قراءة. وأضف **Members** في المؤسسة قراءةً لطلبات مراجعة الفرق.
يمكن أن تبقى خطافات الويب معطّلة: الخوادم تستطلع.

يحتاج Connect إلى المفتاح الخاص لـ GitHub App (**توليد مفتاح خاص** في إعدادات التطبيق). يوقّع به طلبات التطبيق التي تجد التثبيت الذي يغطي مستودعًا (أو، إذا لم يكن للمستودع تثبيت، تثبيت المالك)، ويسكّ رمز تثبيت لمستودع واحد، ولا يفعل ذلك إلا بعد أن يثبت تسجيل دخول الشخص السائل صلاحيته على ذلك المستودع.

يشارك كل خادم على Connect الخاص بك بوت التطبيق نفسه. ويجوز لذلك البوت أن يقرأ ويعلّق ويضع الوسوم ويتفاعل بصفته البوت لأي منها. ومراجعة طلبات السحب بصفة البوت مسموحة فقط للخوادم المدرجة في `CONNECT_GITHUB_REVIEW_BOT_INSTALLS` (معرّفات تثبيتها مفصولة بفواصل)؛ وتنشر كل الخوادم الأخرى مراجعاتها برمز المراجع نفسه. ولا يتم الدفع أبدًا بصفة البوت. ولتمكين خادم تملكه من المراجعة بصفة البوت، أضف معرّف تثبيته هناك ثم أعد التشغيل. احفظ ملف المفتاح كسرّ، كما تحفظ مفتاح الختم. ولا يحتاج Linear إلى سر: يعيد Connect الرمز إلى الخادم، فيُتمّ الخادم التبادل بنفسه.

## الخطوة 3: اجمع معرّفات التثبيت

لا يجيب Connect إلا الخوادم المدرجة في قائمة السماح لديه. على كل خادم، وجّهه إلى
Connect الخاص بك، ثم اقرأ معرّف تثبيته:

1. انتقل إلى **الإعدادات ← الخادم ← تسجيل الدخول الموحّد**، وافتح بطاقة **Control
   Center Connect**، واختر **استخدام خادم Connect مخصص**
2. أدخل عنوانك واحفظ. تعرض البطاقة **مُعرّف التثبيت** الخاص بالخادم

ومن طرفية على مضيف الخادم، الأمر نفسه هو:

```bash
cc_server connect enable --url https://connect.example.com
cc_server connect status
```

يطبع `status` معرّف التثبيت. ويعرض `install_blocked` إلى أن تُنجَز الخطوة 5، وهذا
متوقَّع.

يُشتق معرّف التثبيت لكل عنوان Connect، فيكون للخادم نفسه معرّف مختلف لكل Connect
يخاطبه. ولا يتغيّر إلا حين يدوّر مالكه المفتاح.

## الخطوة 4: أنشئ مفتاح ختم

يشفّر Connect كل بيانات اعتماد يعيدها بمفتاح ختم. أنشئ واحدًا واحتفظ به ملفَّ سرٍّ:

```bash
docker run --rm ghcr.io/samuelalev/cc-connect:latest \
  cc-connect-config seal-key > seal_keys
chmod 600 seal_keys
```

فقدان مفتاح الختم يُخرج الجميع: لا يمكن فتح أي ختم من دونه.

## الخطوة 5: شغّل الحاوية

ينشر كل إصدار `ghcr.io/samuelalev/cc-connect` مع مصدر البناء (build provenance).
ثبّت وسم إصدار في الإنتاج.

```bash
docker run -d --name cc-connect -p 8790:8790 \
  -e CONNECT_PUBLIC_URL=https://connect.example.com \
  -e CONNECT_ALLOWED_INSTALLS=<install id>,<install id> \
  -e CONNECT_SEAL_KEYS_FILE=/run/secrets/seal_keys \
  -v "$PWD/seal_keys:/run/secrets/seal_keys:ro" \
  -e CONNECT_GITHUB_APP_ID=123456 \
  -e CONNECT_GITHUB_APP_SLUG=acme-control-center \
  -e CONNECT_GITHUB_CLIENT_ID=Iv23li0123456789abcd \
  -e CONNECT_GITHUB_CLIENT_SECRET_FILE=/run/secrets/github \
  -v "$PWD/github_secret:/run/secrets/github:ro" \
  -e CONNECT_GITHUB_APP_PRIVATE_KEY_FILE=/run/secrets/github_key \
  -v "$PWD/github_app_key.pem:/run/secrets/github_key:ro" \
  -v cc-connect-data:/data \
  ghcr.io/samuelalev/cc-connect:latest
```

وجّه الوكيل العكسي إلى المنفذ `8790`، واضبط `CONNECT_TRUST_PROXY` على عدد الوكلاء أمام Connect، حتى يرى حدّ العنوان عنوانَ كل عميل. تعمل الصورة بمستخدم غير ذي امتيازات، وتحفظ حالتها في وحدة التخزين `/data`، ولها فحص سلامة مدمج (`cc-connect --healthcheck`، الذي يسبر `/healthz`: تجيب العملية). ويتحقق `/readyz` أيضًا من أن مخازن الحالة والروابط تجيب، ومن أن Redis، إن استُخدم، ما زال يعمل بـ `maxmemory-policy noeviction`؛ وجّه فحص الجاهزية لدى المنسّق إلى هناك.

تُرسل صفحة موافقة تسجيل الدخول نموذجًا بطريقة POST، ولا يقبله Connect إلا من صفحته هو: `Sec-Fetch-Site`، إن أُرسل، يجب أن يكون `same-origin`، و`Origin`، إن أُرسل، يجب أن يكون أصل `CONNECT_PUBLIC_URL`؛ ويُرفض الطلب الذي لا يحمل أيًّا منهما. لذا يجب أن يمرّر الوكيل الترويستين كما هما، وأن يكون `CONNECT_PUBLIC_URL` هو العنوان الذي تستخدمه متصفحات الناس فعلًا. إن ظلّت المتابعة من تلك الصفحة تعرض دائمًا «انتهت صلاحية هذا الرابط»، وأظهر السجل `oauth.done_refused` بالسبب `origin` أو `no_origin`، فإحدى هاتين مضبوطة بشكل خاطئ.

يرفض Connect الإقلاع (رمز الخروج `78`) حين تكون إعداداته مفتوحة، أو غير آمنة، أو
ناقصة، ويطبع أي متغير هو الخاطئ. غياب قائمة السماح، أو عنوان `http` خارج loopback،
أو مفتاح ختم مشوّه، أو ضبط `NAME` و`NAME_FILE` معًا، كلها توقفه.

نقطة تحقق: على كل خادم، تقرأ بطاقة Connect **يعمل**، ويسمّي **أين يجري كل تسجيل
دخول** القيمة **Connect** لكل مزوّد سجّلته. ويطبع `cc_server connect status`
`Health: ok` والمسارات نفسها.

## تضمين Connect داخل cc_server

يستطيع الخادم أن يستضيف Connect بنفسه بدل حاوية منفصلة. والخدمة المضمّنة هي الخدمة
نفسها التي تشغّلها الصورة.

1. ضع متغيرات `CONNECT_*` في ملف `.env` الخاص بالخادم، كما في الخطوة 5.
   يرفض الخادم الإقلاع حين يكون أي سر من أسرار Connect مُصدَّرًا في بيئته، بما فيه `CONNECT_SENTRY_DSN`
2. أضف `CC_SERVER_CONNECT_HOST=on`
3. أعد تشغيل الخادم. يطبع سجله `embedded Connect at <url>`

```bash
CC_SERVER_CONNECT_HOST=on
CONNECT_ALLOWED_INSTALLS=<install id>
CONNECT_SEAL_KEYS=<output of cc-connect-config seal-key>
CONNECT_GITHUB_APP_ID=123456
CONNECT_GITHUB_APP_SLUG=acme-control-center
CONNECT_GITHUB_CLIENT_ID=Iv23li0123456789abcd
CONNECT_GITHUB_CLIENT_SECRET=<secret>
CONNECT_GITHUB_APP_PRIVATE_KEY_FILE=/etc/cc/github_app_key.pem
```

يُقدَّم Connect عندئذٍ عند `<server>/connect`:

- القيمة الافتراضية لـ `CONNECT_PUBLIC_URL` هي أصل العنوان العام للخادم مضافًا إليه
  `/connect`. اضبطه صراحة خلف وكيل. يجب أن يكون مساره `/connect` بالضبط، وأن يكون
  HTTPS ما لم يكن loopback
- لا تصل إلى الخدمة المضمّنة إلا متغيرات `CONNECT_*`، فلا تستعير أبدًا تطبيقات
  المزوّدين الخاصة بالخادم
- ما زال `CONNECT_ALLOWED_INSTALLS` مطلوبًا، بما في ذلك للخادم المستضيف نفسه
- التضمين المضبوط ضبطًا خاطئًا يمنع الخادم من الإقلاع بدل أن يقدّم وسيطًا مفتوحًا
- خادم العرض التجريبي لا يضمّنه أبدًا

سجّل عناوين إعادة التوجيه لدى المزوّدين على `https://<server>/connect`، ثم وجّه
الخوادم (والخادم المستضيف منها) إلى ذلك العنوان كما في الخطوة 3.

## مرجع الإعدادات

كل إعداد متغير بيئة. ويمكن لأي سر أن يأتي من ملف مربوط بدلًا من ذلك: اضبط `NAME_FILE`
مكان `NAME`. يعيد Connect قراءة الملف مرة كل 30 ثانية على الأكثر، ويحتفظ بآخر قيمة
سليمة. والأسرار الموسومة **مزدوج** تقبل أيضًا `NAME_PREVIOUS` (أو
`NAME_PREVIOUS_FILE`) أثناء التدوير.

### العنوان والوصول

| المتغير | الافتراضي | المعنى |
| --- | --- | --- |
| `CONNECT_PUBLIC_URL` | مطلوب | عنوان URL العام القانوني. HTTPS، أو `http` على loopback فقط. وجود مسار يعني التضمين. بلا استعلام ولا جزء |
| `CONNECT_ALLOWED_INSTALLS` | مطلوب | معرّفات تثبيت مفصولة بفواصل. لا يُقبل `*` إلا مع `CONNECT_SIGNED_CONFIG_FILE` |
| `CONNECT_DENY_INSTALLS` | | معرّفات تثبيت تُرفض حتى لو كانت مسموحًا بها |
| `CONNECT_GITHUB_ALLOWED_OWNERS` | | معرّفات رقمية لمالكين على GitHub. حين يُضبط، لا تُسكّ رموز المستودعات إلا لمستودعات يملكونها. لا يحدّ ذلك من يسجّل الدخول: فالشخص المسموح له باستخدام Connect هذا ما زال يتلقى رمز مستخدم التطبيق الخاص به. لخدمة مؤسسة واحدة فقط، اجعل التطبيق خاصًا بها |
| `CONNECT_GITHUB_REVIEW_BOT_INSTALLS` | | معرّفات تثبيت يجوز لبوت التطبيق فيها مراجعة طلبات السحب. فارغ افتراضيًا؛ و`*` مرفوض، ويجب أن يكون كل معرّف مسموحًا به أيضًا |
| `CONNECT_HOST`، `CONNECT_PORT` | `0.0.0.0`، `8790` | عنوان الربط والمنفذ |
| `CONNECT_TRUST_PROXY` | `0` | عدد قفزات الوكلاء الموثوقة في `X-Forwarded-For` (من 0 إلى 8). لا يُستخدم إلا لحدود كل عنوان، ولتلميح الشبكة في صفحة تسجيل الدخول، وللعنوان المسجَّل. خلف وكيل، يحسب `0` كل عميل على أنه الوكيل، ويقول السجل ذلك مرة واحدة |

### مسارات المزوّدين

| المتغير | الافتراضي | المعنى |
| --- | --- | --- |
| `CONNECT_GITHUB_APP_ID`، `CONNECT_GITHUB_APP_SLUG`، `CONNECT_GITHUB_CLIENT_ID` | | GitHub App |
| `CONNECT_GITHUB_CLIENT_SECRET` | | سر، مزدوج |
| `CONNECT_GITHUB_APP_PRIVATE_KEY` | | سر. المفتاح الخاص للتطبيق (PEM) |
| `CONNECT_GOOGLE_CLIENT_ID`، `CONNECT_GOOGLE_CLIENT_SECRET` | | عميل Google. السر مزدوج |
| `CONNECT_LINEAR_CLIENT_ID` | | تطبيق Linear. بلا سر |
| `CONNECT_SLACK_APP_ID`، `CONNECT_SLACK_CLIENT_ID` | | تطبيق Slack |
| `CONNECT_SLACK_CLIENT_SECRET`، `CONNECT_SLACK_SIGNING_SECRET` | | أسرار، مزدوجة |
| `CONNECT_KLIPY_APP_KEY` | | مفتاح بحث GIF من Klipy. سر، مزدوج |
| `CONNECT_KLIPY_MODE` | `proxy` | `proxy` يُبقي المفتاح في Connect؛ و`key` يسلّمه إلى الخوادم |
| `CONNECT_<LANE>_SECRET_GENERATION` | `1` | GitHub وGoogle وSlack: الجيل المسجّل في الأختام الجديدة |
| `CONNECT_<LANE>_MIN_SEAL_GENERATION` | `1` | GitHub وGoogle وSlack: الأختام الأقدم يجب أن تسجّل الدخول من جديد |
| `CONNECT_<LANE>_ACCEPTS_NEW` | `true` | كل مسار: `false` يوقف تسجيلات الدخول الجديدة بينما تواصل القائمة تجددها |

### الأختام والحالة والتخزين

| المتغير | الافتراضي | المعنى |
| --- | --- | --- |
| `CONNECT_SEAL_BACKEND` | `local` | `local` أو `gcp-kms` |
| `CONNECT_SEAL_KEYS` | | سر، مطلوب مع `local`. مدخلات `kid:key` مفصولة بفواصل، الأحدث أولًا؛ والمدخلات الأقدم ما زالت تفك التشفير |
| `CONNECT_KMS_KEY` | | `projects/…/locations/…/keyRings/…/cryptoKeys/…`، مطلوب مع `gcp-kms` |
| `CONNECT_STATE` | `memory` | `memory` لنسخة واحدة، و`redis` لعدة نسخ. تُرفض تسجيلات الدخول والطلبات الجديدة حين يمتلئ مخزن الذاكرة، بدل أن ينسى إدخالًا حيًّا |
| `CONNECT_REDIS_URL` | | سر. `redis://` أو `rediss://`. Redis 6.2 أو أحدث مع `maxmemory-policy noeviction`، ويُتحقق من الاثنين عند الإقلاع |
| `CONNECT_REDIS_CA_FILE` | | حزمة CA لـ `rediss://` |
| `CONNECT_BINDINGS` | `file` | أين تعيش روابط فرق Slack: `file` أو `firestore` |
| `CONNECT_DATA_DIR` | `data` (`/data` في الصورة) | يحوي `bindings.json`. يقفله Connect واحد: لا يبدأ Connect ثانٍ على الدليل نفسه |
| `CONNECT_FIRESTORE_PROJECT`، `CONNECT_FIRESTORE_DATABASE` | قاعدة البيانات `(default)` | لـ `CONNECT_BINDINGS=firestore`. لا يبدأ Connect حين لا يجيب Firestore |

### الإعدادات والسجلات والحدود

| المتغير | الافتراضي | المعنى |
| --- | --- | --- |
| `CONNECT_SIGNED_CONFIG_FILE` | | إعدادات موقّعة دون اتصال، تُقدَّم كما هي. يستخدمها Connect المستضاف من Control Center |
| `CONNECT_CONFIG_PUBLIC_KEYS` | | المفاتيح التي يجب أن تتحقق منها الإعدادات الموقّعة |
| `CONNECT_CONFIG_EPOCH` | `1` | حقبة الإعدادات التي يولّدها Connect المستضاف ذاتيًا |
| `CONNECT_LOG_HMAC_KEY` | عشوائي لكل عملية | سر. اضبطه لتبقى الوسوم التي تنوب عن معرّفات التثبيت ثابتة عبر إعادات التشغيل والنسخ |
| `CONNECT_SENTRY_DSN` | | سر. عنوان Sentry DSN بـ https تُبلَّغ إليه أسطر الأخطاء: نوع الخطأ، وإطارات المكدّس، والمسار ومعرّف الطلب، لا رسالة ولا محتوى ولا ترويسة |
| `CONNECT_SENTRY_ENVIRONMENT` | `self-hosted` | بيئة Sentry |
| `CONNECT_VERSION`، `CONNECT_IMAGE_DIGEST` | | يبلّغ عنهما `/v1/version` |
| `CONNECT_RATE_INSTALL_PER_MINUTE` | `600` | الطلبات لكل تثبيت |
| `CONNECT_RATE_IP_PER_MINUTE` | `300` | الطلبات لكل عنوان (عنوان IPv6 يُحسب لكل /64) |
| `CONNECT_RATE_GLOBAL_PER_SECOND` | `500` | الطلبات للنسخة كلها |
| `CONNECT_RATE_SLACK_HOOK_IP_PER_MINUTE` | `600` | تسليمات أحداث Slack والأوامر لكل عنوان، وتُحسب منفصلة عن الطلبات الأخرى |
| `CONNECT_RATE_SLACK_HOOK_GLOBAL_PER_SECOND` | `100` | تسليمات أحداث Slack والأوامر للنسخة كلها |
| `CONNECT_RATE_SLACK_TEAM_PER_MINUTE` | `600` | أحداث Slack لكل فريق |
| `CONNECT_RATE_KLIPY_PER_MINUTE` | `120` | عمليات بحث GIF لكل تثبيت |
| `CONNECT_RATE_KLIPY_IP_PER_MINUTE` | `240` | عمليات بحث GIF لكل عنوان، عبر الخوادم كلها |
| `CONNECT_RATE_LOGINS_IP_PER_10_MINUTES` | `60` | تسجيلات دخول تبدأ لكل عنوان |
| `CONNECT_RATE_GITHUB_TOKENS_ACCOUNT_PER_HOUR` | `30` | رموز GitHub الصادرة لكل حساب GitHub على خادم واحد (تسجيلات الدخول، والتجديدات، ورموز المستودعات) |
| `CONNECT_RATE_GITHUB_TOKENS_ACCOUNT_CEILING_PER_HOUR` | 4 × ما سبق (`120`) | الحد نفسه لكل حساب GitHub عبر كل الخوادم |
| `CONNECT_RATE_GITHUB_TOKENS_IP_PER_HOUR` | `600` | رموز GitHub الصادرة لكل عنوان |
| `CONNECT_RATE_GITHUB_EXCHANGE_CEILING_PER_HOUR` | `500` | تسجيلات دخول GitHub الجديدة للتطبيق كله |
| `CONNECT_RATE_GITHUB_APP_MINTS_INSTALL_PER_HOUR` | `120` | رموز البوت لكل خادم |
| `CONNECT_RATE_GITHUB_APP_MINTS_ACCOUNT_PER_HOUR` | `240` | رموز البوت لكل حساب GitHub طالب، عبر الخوادم |
| `CONNECT_RATE_GITHUB_APP_CEILING_PER_HOUR` | `3000` | رموز البوت للتطبيق كله |
| `CONNECT_RATE_GITHUB_TOKEN_CEILING_PER_HOUR` | `1500` | التجديدات ورموز المستودعات للتطبيق كله. لتسجيلات الدخول الجديدة حد خاص أعلاه |
| `CONNECT_GITHUB_TOKEN_CAP_WARN` | `10` | رموز المستودعات الحية التي يجوز لحساب GitHub واحد أن يحملها قبل أن يسجّل Connect تحذيرًا |
| `CONNECT_RATE_RETIRE_IP_PER_HOUR` | `10` | معرّفات تثبيت مُتقاعدة لكل عنوان (لكل /48 في IPv6) |

تُجاب المكالمة التي تتجاوز حدًّا بـ `rate_limited`. يعيد الخوادم المحاولة لاحقًا، ولا يُخرج أحدًا من الجلسة بسبب ذلك أبدًا.

## تشغيل أكثر من نسخة

نسخة واحدة بـ `CONNECT_STATE=memory` تكفي معظم المؤسسات. أما عدة نسخ خلف عنوان واحد
فتحتاج إلى `CONNECT_STATE=redis` و`CONNECT_BINDINGS=firestore`، حتى يكتمل على نسخة تسجيلُ دخول بدأ على نسخة أخرى، وحتى ترى كل نسخة الروابط نفسها لفرق Slack ومعرّفات التثبيت المتقاعدة نفسها. ولا يعمل `CONNECT_DATA_DIR` المشترك: فأول Connect يقفله. وحدود الطلبات لكل تثبيت ولكل عنوان وللنسخة هي لكل نسخة؛ أما الحدود الخاصة بتسجيلات الدخول ورموز GitHub ورموز البوت وعمليات بحث GIF لكل عنوان والتقاعد وفرق Slack فتُشارَك عبر مخزن الحالة.

## تدوير سر مزوّد

لا يخرج أحد:

1. أنشئ السر الجديد لدى المزوّد واحتفظ بالقديم
2. انقل القيمة القديمة إلى `NAME_PREVIOUS`، وضع الجديدة في `NAME`، وارفع
   `CONNECT_<LANE>_SECRET_GENERATION`. تُلتقط الملفات المربوطة في غضون 30 ثانية
3. انتظر حتى تتجدد تسجيلات الدخول، ثم احذف السر القديم لدى المزوّد وأزل
   `NAME_PREVIOUS`

ولتدوير مفتاح ختم، ضع مدخلًا جديدًا من `cc-connect-config seal-key` أولًا في
`CONNECT_SEAL_KEYS`، واحتفظ بالمدخل القديم إلى أن تتجدد أختامه.

## تغيير تطبيق

تتذكّر الخوادم معرّفات التطبيق والعميل التي أعلنها Connect الخاص بك في أول مرة
استخدمته. إن استبدلت تطبيقًا، تعرض بطاقة Connect في كل خادم **تغيّرت تطبيقات
Connect**، وتتوقف تسجيلات الدخول عبر Connect إلى أن يضغط مالكه **الوثوق بالتطبيقات
الجديدة**. أخبر مالكي الخوادم قبل التحويل، حتى يعرفوا أن التنبيه منك.

## حظر خادم

أضف معرّف تثبيته إلى `CONNECT_DENY_INSTALLS` وأعد التشغيل. يرى مالكه «حظر Connect
مُعرّف التثبيت لهذا الخادم. تواصل مع مُشغّل خادم Connect الخاص بك.» ويتوقف كل تسجيل دخول عبر Connect عليه.

يتقاعد الخادم أيضًا معرّف تثبيته القديم حين يدوّر مالكه المفتاح. ويثبت أن المعرّف له بختم واحد للاعتماد أنشأه له هذا Connect، لذا لا يستطيع تقاعد معرّف إلا خادم سجّل أحدهم دخوله. يحتفظ Connect بالمعرّفات المتقاعدة إلى الأبد، فيتوقف المفتاح القديم وكل ختم أُنشئ له عن العمل، وتُحرَّر فرق Slack المرتبطة بالمعرّف القديم. وتنتهي الرموز التي سُلّمت من قبل وحدها: خلال 8 ساعات لرموز الشخص، وساعة واحدة لرموز البوت. يحتفظ Connect بما لا يزيد على 100,000 معرّف متقاعد؛ وما زاد على ذلك يُرفض التدوير، ويقول السجل ذلك على مستوى الخطأ.

## استكشاف الأخطاء وإصلاحها

### يقول خادم إن Connect حظره

معرّف تثبيته ليس في `CONNECT_ALLOWED_INSTALLS`، أو هو في `CONNECT_DENY_INSTALLS`، أو تقاعد بسبب تدوير مفتاح.
يتغيّر المعرّف حين يدوّر مالكه المفتاح؛ فاطلب المعرّف الجديد.

### كل تسجيلات الدخول إلى مزوّد واحد تفشل

قد ينقصه أحد متغيراته، فاستبعد Connect ذلك المسار. افحص سجل الإقلاع والجداول أعلاه.
يحتاج GitHub إلى الخمسة كلها: معرّف التطبيق، والاسم المختصر، ومعرّف العميل، وسر
العميل، والمفتاح الخاص؛ ويحتاج Google إلى معرّف العميل وسرّه معًا.

### تفشل تسجيلات الدخول بعدم تطابق إعادة التوجيه

عنوان إعادة التوجيه المسجّل لدى المزوّد لا يطابق `CONNECT_PUBLIC_URL` تمامًا. قارن
المخطط والمضيف والمنفذ، ومسار `/connect` في Connect المضمّن.

### اضطر الجميع إلى تسجيل الدخول من جديد

تغيّر مفتاح الختم أو فُقد، أو دوّر خادم مفتاحه، أو استُعيدت بيانات خادم على جهاز آخر.
بيانات الاعتماد المختومة لا تُفتح إلا للتثبيت ولـ Connect اللذين أنشآها.
