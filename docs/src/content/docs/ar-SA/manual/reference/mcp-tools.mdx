يستضيف `cc_server` سجل أدوات MCP واحدًا (JSON-RPC 2.0)، يُقدَّم على منفذ الخادم الرئيسي (الافتراضي `9030`) عند `POST /mcp` و`GET /sse`، بإصدار البروتوكول `2024-11-05`. يصل كل عميل إلى السجل نفسه: تطبيق سطح المكتب، وبناء الويب، وعملاء MCP الخارجيون، وبيئة تشغيل الوكيل المضمّنة. يمكن جسر خوادم MCP الخارجية إلى السجل نفسه طبقةً ديناميكية.

## حجم السجل

| المقياس | العدد |
| --- | --- |
| الأدوات التي يسجّلها `cc_server` | 110 |
| من `packages/cc_mcp` | 108 |
| من `packages/cc_mcp_client` (اكتشاف الأدوات) | 2 |
| المسجَّلة في السجل الأساسي (`server_mcp_registry.dart`) | 63 |
| المسجَّلة بعد الإقلاع حين تصعد خدماتها (`cc_server_runtime.dart`) | 47 |
| من أدوات السجل الأساسي البالغ عددها 63، ما يُشترط له مستودع مخطط شفرة | 5 |

لا تُسجَّل أدوات مخطط الشفرة الخمس إلا حين يمرّر المضيف مستودع مخطط شفرة إلى `buildServerMcpRegistry`. يمرّر `cc_server` واحدًا دائمًا، فتعمل الأدوات الـ110 كلها في الثنائي المُشحَن.

يُعلَن السجل كاملًا في `tools/list` بلا بوابة اكتشاف. تعديلات التذاكر أدوات منمَّطة.

:::note[العملاء الخارجيون يرون الفهرس كاملًا دائمًا]
لا يُقتطع من `tools/list` شيء. يطابق عملاء MCP أسماء الأدوات مع نسختهم المخزَّنة من تلك القائمة، ويرفضون ما ليس فيها من غير أن يسألوا الخادم، فالأداة المخفية هناك بعيدة المنال لا صامتة فحسب.

يختلف **الإطار المضمّن**: يحمّل في كل طلب مجموعة مقيمة من التعريفات فقط، ويجلب الباقي عند أول استخدام. هذا سلوك من جهة الإطار، ولا يغيّر هذا السجل. انظر [سياق الأدوات وتخزين المطالبات مؤقتًا](/ar-SA/دليل-المستخدم/مفاهيم/سياق-الأدوات/).
:::

:::note[كل صنف أداة مُسجَّل]
كل ملف مصدر تحت `packages/cc_mcp/lib/src/tools/` أداة يستطيع الوكيل
استدعاءها. يُفشل
`packages/cc_server_core/test/mcp_tool_registration_ratchet_test.dart`
البناء إن بُني صنف أداة جديد من غير أن يبنيه شيء.
:::

## المعاملات المشتركة

### `workspace_id`

**مطلوب** في كل أداة تلمس بيانات على نطاق مساحة العمل. غياب `workspace_id` أو عدم صلاحيته يعيد خطأً صريحًا، والقيمة التي لا تطابق مساحة عمل الكيان المستهدف تُرفض بدل أن تُتجاهل بصمت. احذفه في الأدوات العالمية فعلًا: `list_workspaces` وأدوات موجز الأخبار الست (`list_feeds` و`list_articles` و`get_article` و`set_article_read` و`set_article_saved` و`refresh_feeds`)، فهي تسير على قائمة موجزات مالك الخادم الخاصة بكل مستخدم. تأخذ أدوات الاكتشاف (`search_tool_bm25` و`list_my_tools`) المعامل اختياريًا حتى تصنّف قابلية الاستدعاء حسب وضع المحادثة. حين يُرسَل الوكيل من الخادم، تُفرَض مساحة العمل من جهة الخادم، فلا يبلغ مساحة عمل أخرى بتمرير معرّف غريب.

## اكتشاف الأدوات

تأتي كلتاهما من `cc_mcp_client` لا من `cc_mcp`، وتستشيران حارس الوضع حتى تُبلغا عما يُستدعى في وضع المحادثة _الحالي_.

| الأداة | الوصف |
| --- | --- |
| `search_tool_bm25` | ابحث في فهرس الأدوات بكلمة مفتاحية؛ يعيد الأدوات المطابقة ومخططات وسائطها وهل كل منها قابلة للاستدعاء الآن |
| `list_my_tools` | اسرد الأدوات القابلة للاستدعاء الآن في هذه المحادثة، مرشَّحة بوضعها |

أداة اكتشاف ثالثة، **`search_tools`**، موجودة داخل الإطار المضمّن وحده وليست جزءًا من سجل MCP هذا. ترتّب سطح أدوات التشغيل نفسه، وبخلاف `search_tool_bm25` **تحمّل** مخططات ما تجده حتى يستطيع الوكيل استدعاء مطابقة في جولته التالية. يجدر بالوكلاء على الإطار أن يفضّلوها، ولدى عملاء MCP الأداة `search_tool_bm25`.

## أدوات مخطط الشفرة

تُسجَّل فقط حين يوفّر المضيف مستودع مخطط شفرة. يغطي الفهرس مجموعة القواعد النحوية المُشحَنة (Dart وJS/TS وPHP وPython وRust وZig وC/C++ وGo وJava وRuby وC# وSwift وKotlin وR وAssembly وMATLAB وAda)، ورموز أي لغة أخرى غير موجودة.

| الأداة | الوصف |
| --- | --- |
| `search_code` | ابحث في الرموز المفهرسة بالاسم والتوقيع وتعليق التوثيق (هجين من BM25 والدلالي) |
| `code_symbol` | ابحث عن الرموز بالاسم المطابق تمامًا؛ ويعيد `file:line` والتوقيع |
| `code_callers` | اسرد الرموز التي تستدعي رمزًا أو تعتمد عليه (الحواف الواردة) |
| `code_callees` | اسرد الرموز التي يستدعيها رمز أو يعتمد عليها (الحواف الصادرة) |
| `code_impact` | احسب نصف قطر التأثير المتعدي لرمز، حتى عمق معيّن |

| `list_feeds` | اسرد موجزات RSS/Atom المسجَّلة |
| `list_articles` | اسرد المقالات، مع تصفية اختيارية بالموجز أو غير المقروء أو المحفوظ |
| `get_article` | اجلب مقالًا واحدًا |
| `set_article_read` | علّم مقالًا مقروءًا أو غير مقروء |
| `set_article_saved` | احفظ مقالًا أو ألغِ حفظه |
| `refresh_feeds` | أعد جلب كل موجز مُفعَّل الآن |

## أدوات الحاوية المعزولة (المنصة)

قُد آلات يمكن التخلص منها — متصفحًا محصورًا أو سطح مكتب Linux، أو محاكي Android، أو محاكي iOS — من داخل تشغيل. تُسجَّل بعد الإقلاع بلا شرط: هل تستطيع الآلة أن تُقلع فعلًا سؤال سبر تجيب عنه الأدوات في كل استدعاء. تعيد الاستدعاءات المتكررة في محادثة واحدة استخدام آلة واحدة، وتعود لقطات الشاشة محتوى صورة بميزانية صورة واحدة لكل نتيجة، ويُسيَّج محتوى الصفحة أو الواجهة المستخرَج بوصفه بيانات غير موثوقة. تعلن أدوات الاستخدام الأربع و`rig_close` [صنف الأثر](/ar-SA/دليل-المستخدم/مفاهيم/ضوابط/) `enclosureControl` (وتعلن أدوات الاستخدام أيضًا `networkEgress` و`processSpawn`؛ ويعلن `mobile_use` و`ios_use` أيضًا `packageInstall`)، فترفضها أوضاع القراءة فقط. لا يعلن `rig_list` شيئًا — فهو يقرأ حالة مساحة العمل فقط. مفردات الأفعال الكاملة لكل سطح في [مرجع المنصات](/ar-SA/دليل-المستخدم/مرجع/منصات/#أفعال-الإجراء).

| الأداة | الوصف |
| --- | --- |
| `computer_use` | قُد سطح مكتب Linux في آلة افتراضية محصورة: تحريك، ونقر، وسحب، وتمرير، وكتابة، وتغيير حجم، وحافظة، ولقطة شاشة |
| `browser_use` | قُد Chromium أو Firefox أو WebKit بلا واجهة (`engine`): تنقّل، ونقر، وملء، واستخراج (إمكانية الوصول/DOM/وحدة التحكم)، وحافظة، ولقطة شاشة |
| `mobile_use` | قُد Android عبر ADB: فحص وإدخال، ولقطات شاشة، وتثبيت التطبيقات وبدؤها وإيقافها وإعادة ضبطها وإزالتها، وروابط عميقة وأوامر جهاز على شكل argv |
| `ios_use` | قُد محاكي iOS عبر WebDriverAgent/CoreSimulator: فحص وإدخال، ولقطات شاشة، وتثبيت التطبيقات وبدؤها وإيقافها وإزالتها، وروابط عميقة وعمليات محاكٍ على شكل argv |
| `rig_list` | اسرد منصات مساحة العمل مع السطح والحالة وحجم العرض والمتحكّم |
| `rig_close` | دمّر المنصة وتخلَّ عن حالة الآلة التي تملكها |

## غير المعروض عبر MCP

لا أدوات MCP للتقويم ولا للاجتماعات. لا يستطيع الوكلاء قراءة تقويمك، ولا اجتماعاتك، ولا النسخ النصي، ولا بنود العمل، ولا القرارات. الخلاصة التي تنتج بنود العمل والقرارات تعمل خطَّ أنابيب [`meeting_summary`](/ar-SA/دليل-المستخدم/مفاهيم/اجتماعات/) المضمّن، لا أداةً يستطيع وكيل استدعاءها.

## تقييد الأدوات حسب الوضع

يُفرَض التقييد مرتين انطلاقًا من جدول واحد (`ModeToolPolicy`): مرة في موزّع MCP لمحوّل Claude Code، ومرة في سجل الإطار المضمّن. يعيد الاستدعاء المحجوب السبب.

| الوضع | سطح الأدوات |
| --- | --- |
| `chat` | كل أداة مسجَّلة؛ بلا قائمة سماح |
| `plan` | قائمة سماح منتقاة. بلا كتابة في شجرة العمل وبلا أفعال تذاكر `create` / `assign` / `delegate`، لكن الذاكرة والمُخرَجات وقوائم المهام و`submit_plan` و`exit_plan_mode` وأفعال إكمال التذكرة على التذكرة المُرسَلة مسموحة |
| `review` | قائمة سماح منتقاة: المشاركة في المراجعة، والتواصل، وجالبات السياق للقراءة فقط، ومجموعة أفعال التذاكر كاملة ومنها `create_ticket` و`assign_ticket` |
| `orchestrate` | قائمة سماح منتقاة: أدوات البحث والقراءة إضافة إلى `propose_orchestration` و`create_playbook` و`run_playbook`. يقع التوظيف والتفكيك وإكمال التذكرة حتميًا بعد الموافقة، ولا يحدث شيء من ذلك في منتصف التشغيل |

مسموح في كل وضع بصرف النظر عن قائمة السماح:

| المجموعة | الأدوات |
| --- | --- |
| الذاكرة والمُخرَجات | `search_memory`، `propose_fact`، `propose_policy`، `supersede_fact`، `supersede_policy`، `record_observation`، `update_my_notes`، `get_my_notes`، `list_memory_domains`، `list_policies`، `publish_artifact`، `revise_artifact`، `list_artifacts`، `get_artifact` |
| مخطط الشفرة | `search_code`، `code_symbol`، `code_callers`، `code_callees`، `code_impact` |
| آليات التشغيل | `search_tool_bm25`، `list_my_tools`، `todo_write`، `todo_read` |

وجود الأداة في قائمة السماح لا يجعلها قابلة للاستدعاء، والعكس قائم أيضًا: قدرة سؤال المشغّل أداة في **الإطار** (`ask_user`)، فلا تظهر في فهرس MCP هذا أصلًا.

## الأدوات المحكومة بالموافقة

قد تعلن أداة `requiresApproval`. يبني الموزّع عندئذ `ApprovalPayload` ويعرضه عبر `ConfirmationPort` قبل أن تعمل الأداة، ويوصل `cc_server` ذلك المنفذ، فالبوابة حيّة.

الأدوات المسجَّلة التي تعلنه: `create_ticket`، `update_ticket`، `assign_ticket`، `reassign_ticket`، `close_ticket`، `ticket_relation`، `create_goal`، `update_goal_progress`، `create_approval`، `decide_approval`، `comment_approval`، `create_work_product`، `save_work_product_revision`، `create_runtime_profile`، `install_skill`، `update_skill`.

وعلى استقلال، تحكم ضوابط الإجراء الموحَّدة أي أداة تعلن مجموعة `ActionClass` غير فارغة. يُرفض قرار `prompt` إن لم يكن هناك معتمِد متصل. انظر [الضوابط](/ar-SA/دليل-المستخدم/مفاهيم/ضوابط/).

## قدرات بلا أداة خلفها

ليست كل قدرة في المنتج في متناول وكيل. هذه بلا أداة
أصلًا، فالاسم الذي ربما رأيته مشارًا إليه في موضع آخر يعيد "unknown tool":

| القدرة | أين تعيش بدل ذلك |
| --- | --- |
| توظيف وكيل أو فصله أو تحريره | واجهة الوكلاء. لا توجد أداة `hire_agent` / `fire_agent` / `update_agent` |
| إنشاء مساحة عمل | `workspace.upsert` عبر RPC، وهو يبذر الملكية ويختمها |
| المشاريع (إنشاء / سرد / تحديث / إيداع) | واجهة التذاكر. المشاريع سطح للمشغّل — انظر [المشاريع](/ar-SA/دليل-المستخدم/أدلة-إرشادية/مشاريع/) |
| سؤال المشغّل سؤالًا حاجبًا | أداة **الإطار** `ask_user`، لا MCP. تعرض نموذجًا في المحادثة وتنتظر الجواب |
| تشخيص كل وكيل | لا شيء. لا `doctor` — انظر [تشخيص وكيل](/ar-SA/دليل-المستخدم/أدلة-إرشادية/تشخيص-الوكيل/) |
| التقويم والاجتماعات | RPC لعملاء البشر فقط (انظر أعلاه) |
