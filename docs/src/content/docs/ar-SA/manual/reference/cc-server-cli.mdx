كل إعداد يقبل علم سطر أوامر أو متغير بيئة؛ يغلب العلم، ثم البيئة، ثم
الافتراضي. الاستثناء بيانات اعتماد المزوّدين — انظر [تطبيقات المزودين وConnect](#تطبيقات-المزودين-وconnect).

:::caution[الأعلام المجهولة تُتجاهل في صمت]
محلّل الوسائط مكتوب يدويًا ويتجاوز ما لا يتعرّف عليه، فالخطأ الإملائي (`--tls-key-file`، `--bindany`) لا يصدر خطأ — ويبدأ الخادم بالافتراضي. راجع أسطر سجل الإقلاع حين يبدو أن علمًا بلا أثر. أما علم [وضع الكود](#وضع-الكود) الذي يُعطى قيمة لا يقبلها فمختلف: يرفض الخادم البدء.
:::

## تطبيقات المزودين وConnect

لا يحمل أي بناء بيانات اعتماد للمزوّدين. مع تفعيل Control Center Connect يعمل كل مزوّد عبر Connect، وتبقى هذه التطبيقات الخاصة محفوظة دون استخدام. تحت **استخدام تطبيقاتي الخاصة**، يعمل كل مزوّد على التطبيق الخاص بالخادم حين يكون مضبوطًا بالكامل، وإلا فهو غير متاح. ويسري تطبيق مساحة العمل الخاص في الحالتين. تُضبط التطبيقات الخاصة في **الإعدادات ← الخادم ← تسجيل الدخول الموحّد
← تطبيقات الموفّرين**، أو تُبذر مرة واحدة من ملف `.env` الخاص بالخادم. لا أعلام
لها: السر على سطر الأوامر يُقرأ عبر `ps`.

| المتغير                        | المعنى                                                                                        |
| ------------------------------ | --------------------------------------------------------------------------------------------- |
| `GITHUB_APP_ID`                | معرّف تطبيق GitHub الخاص بالخادم                                                              |
| `GITHUB_APP_PRIVATE_KEY`       | مفتاحه الخاص، على سطر واحد مع تهريبات `\n`. **في `.env` فقط**                                 |
| `GITHUB_CLIENT_ID`             | معرّف عميله، لإدخال الناس                                                                      |
| `GITHUB_CLIENT_SECRET`         | سر عميله. **في `.env` فقط**                                                                    |
| `GOOGLE_OAUTH_CLIENT_ID`       | عميل Google من نوع Web application الخاص بالخادم                                              |
| `GOOGLE_OAUTH_CLIENT_SECRET`   | سرّه. **في `.env` فقط**                                                                        |
| `LINEAR_CLIENT_ID`             | تطبيق Linear الخاص بالخادم (PKCE، بلا سر)                                                      |
| `LINEAR_API_KEY`               | مفتاح خدمة Linear للأتمتة. **في `.env` فقط**                                                   |
| `KLIPY_APP_KEY`                | مفتاح Klipy الخاص بالخادم لبحث GIF، ويُستخدم فقط تحت **استخدام تطبيقاتي الخاصة**                        |
| `CC_CONNECT_URL`               | `hosted` أو `off` أو عنوان URL لـ Connect. يقفل اختيار Connect، فلا تستطيع الإعدادات تغييره بعدها |
| `CC_SERVER_CONNECT_HOST`       | `on` يضمّن Control Center Connect عند `<server>/connect`، ويُضبط بمتغيرات `CONNECT_*`. انظر [تشغيل خادم Connect](/ar-SA/دليل-المستخدم/أدلة-إرشادية/تشغيل-خادم-connect/#تضمين-connect-داخل-cc_server) |

يُقرأ ملف `.env` من دليل عمل الخادم، أو بجانب الملف التنفيذي، أو من نسخة مصدر فوقه؛
وفي Docker، اربطه عند `/app/bin/.env`. **يرفض الخادم الإقلاع** (رمز الخروج `78`) حين
يكون `GITHUB_APP_PRIVATE_KEY` أو `GITHUB_CLIENT_SECRET` أو `GOOGLE_OAUTH_CLIENT_SECRET`
أو `LINEAR_API_KEY` أو أي `SLACK_*SECRET*` مُصدَّرًا في بيئة عمليته، حيث تستطيع كل
عملية فرعية قراءته. البذر من `.env` يحدث مرة واحدة لكل حقل، فلا تلغي إعادة التشغيل
تعديلًا لاحقًا في الإعدادات. والقيمة الفارغة تُقرأ على أنها غير مضبوطة.

لا يأتي أي اعتماد لمضيف الشفرة من البيئة: فـ GitHub وGitLab وBitbucket يعملون
جميعًا عبر تسجيل الدخول الخاص بالعضو أو رمزه، أو عبر رموز تطبيق GitHub المقصورة
على مستودع واحد.

### `--sandbox`

يفحص الخادم المضيف مرة واحدة عند الإقلاع ويغلّف تنفيذ أوامر الوكيل في بيئة
نظام التشغيل المعزولة الأصلية حين تتوفر خلفية: `sandbox-exec` (Seatbelt) على
macOS، و`bwrap` مع `socat` على Linux وWSL2. يُحسم القرار مرة واحدة ويبقى حتى يعاد تشغيل الخادم. للقرار ثلاث نتائج، يظهر كل منها في سطر التعرض عند الإقلاع:

| `sandbox=`    | متى                                    | أي تشغيلات تبدأ                                                                  |
| ------------- | --------------------------------------- | -------------------------------------------------------------------------------- |
| `native`      | تتوفر خلفية و`--sandbox` على `on`       | تشغيلات الجميع، مغلَّفة                                                          |
| `off`         | `--sandbox off`                         | تشغيلات الجميع، بلا عزل على هذا المضيف                                           |
| `unavailable` | `--sandbox on` ولا توجد خلفية (Windows، أو Linux من غير `bwrap` و`socat`) | تشغيلات المسؤول عنها مالك الخادم وحده، بلا عزل. يُرفض غيرها برسالة "لا توجد حاوية معزولة على هذا الخادم، لذا لا يمكن إلا لمالكه تشغيل الوكلاء هنا." |

بالنسبة للأتمتة، الشخص المسؤول هو الشخص الذي ترتبط به الأتمتة. ومن دون مالك خادم مسجَّل لا يبدأ أي تشغيل على مضيف من نوع `unavailable`. وعلى Linux وWSL2 مع تثبيت bubblewrap يفشل التشغيل الأصلي حاليًا لكل تشغيل بشكل مغلق؛ انظر [خلفيات البيئة المعزولة](/ar-SA/دليل-المستخدم/مرجع/خلفيات-البيئة-المعزولة/#linux-bubblewrap).

`--sandbox off` هو اختيار مالك الخادم لكل من يستخدم الخادم: يشغّل تشغيلات كل الأعضاء بلا عزل على هذا الجهاز. استخدمه على مضيف يختل فيه ملف تعريف البيئة المعزولة نفسه، أو لتمكين الأعضاء من تشغيل الوكلاء على مضيف بلا خلفية. لا يحتاج إعادة بناء، ويسجّل الخادم تحذيرًا طوال عمر العملية حتى لا تبقى الحالة صامتة.

### `--tool-deferral`

ترسل تشغيلات الإطار المضمّن مجموعة مباشرة صغيرة من تعريفات الأدوات مع فهرس أسماء للبقية، فتُحمَّل مخططاتها أول مرة تُستخدم، أو تُستدعى من سكربت `repl`. ويبقي المجموعة الظاهرة دائمًا داخل النطاق الذي تختار فيه النماذج الأدوات بثبات. ومقاسةً على السجل الذي تبنيه الاختبارات، تبلغ أدوات الدردشة القياسية للوكيل المدمج 14 تعريفًا: نحو 16.5 KB مع `repl` (منها نحو 4 KB لـ `repl`، ولا يتجاوز تعريفها 4,096 بايت)، ونحو 13 KB على خادم لا يستطيع تشغيل السكربتات. تبقى الأدوات المؤجَّلة قابلة للاستدعاء بالاسم طوال الوقت، ويجدها `search_tools` بحسب القصد. انظر [سياق الأدوات وتخزين المطالبات مؤقتًا](/ar-SA/دليل-المستخدم/مفاهيم/سياق-الأدوات/).

`--tool-deferral off` يرسل تعريف كل أداة مقبولة مسبقًا، إلا أن التشغيل الذي يملك `repl` ما زال يستدعي من السكربتات الأدوات التي يجوز للسكربت استدعاؤها. هو مفتاح الإيقاف لنموذج يتعامل مع السطح ذي الطبقتين تعاملًا سيئًا — علم لا إعادة بناء. يؤثر في الإطار المضمّن وحده، و`tools/list` الذي يراه عملاء MCP الخارجيون هو الفهرس الكامل، إلا في تشغيل وكيل على خادم يستطيع تشغيل [سكربتات وضع الكود](/ar-SA/دليل-المستخدم/مفاهيم/وضع-الكود/).

### `--credential-gate`

التشغيل الذي تُفقد بيانات اعتماد مزوّده أو تُستنفد **يُرجَأ** بدل أن يفشل:
يتلقى المشغّل مطالبة بإصلاحها، ويستأنف التشغيل إن فعل. المهلة الافتراضية 900
ثانية (15 دقيقة)، مقيّدة بين 0 و3600.

المهلة أطول عمدًا من مهلة مطالبة الموافقة: الموافقة قرار يُتخذ في ثوانٍ، بينما
إصلاح بيانات الاعتماد يعني فتح طرفية وتسجيل الدخول ثم العودة. السقف هو ما يمنع
تشغيلًا بلا حضور — خطوة خط أنابيب، أو مشغّل cron، أو خطاف ويب — من الانتظار
على شخص نائم. حين تنتهي المهلة يفشل التشغيل بالرسالة التي كان سيفشل بها أصلًا.

`--credential-gate=0` هو مفتاح الإيقاف: لا يُرجَأ شيء، وبيانات الاعتماد التالفة
تُنهي الجولة كما كانت قبل وجود البوابة.

### وضع الكود

[وضع الكود](/ar-SA/دليل-المستخدم/مفاهيم/وضع-الكود/) يتيح لوكيل أن يشغّل سكربت JavaScript يستدعي أدواته. لا يوجد علم يُشغّله أو يوقفه: كل تشغيل يحصل على أداة `repl` حين يستطيع الخادم تشغيل السكربتات، ولا يشغّل خادم العرض العام أيًّا منها.

تعمل السكربتات في `cc_codemode`، وهو برنامج يأتي مع الخادم في `bin/codemode/`. لا يبدأ الخادم بدونه: يطبع سطرًا واحدًا يسمّي ما هو مفقود، ويخرج بالرمز `78`. وعند البدء يشغّل الفحص الذاتي لقفل البرنامج، ويطبع سطرًا واحدًا (ولا يُخفيه إلا `--log-level error`):

```text
cc_server: code_mode=available (cc_codemode 0.1.0 quickjs-ng 0.16.2 protocol 2; 16 scripts at once, at most 12 per workspace; up to 64 more runners kept for scripts waiting on a person; heap at most 1024 MiB per script)
cc_server: code_mode=unavailable (<reason>) — runs on this host get no repl tool; scripts never run without full lockdown
```

تعني `unavailable` أن البرنامج لا يستطيع قفل نفسه على هذا المضيف، مثلًا داخل حاوية يرفض ملف أمانها إحدى خطواته، أو لأنه ليس بناء الإصدار. ويعمل الخادم بشكل طبيعي، ولا يحصل أي تشغيل على `repl`، وتعرض إعدادات وضع الكود في مساحة العمل السبب.

يواصل الخادم الفحص أثناء تشغيله. وحين يفشل البرنامج في البدء لسبب لا يتعلق بالسكربت، يعيد الخادم الفحص الذاتي، بحد أقصى مرة في الدقيقة. فإن فشل، يطبع الخادم سطر `unavailable` مع سببه ولا يشغّل أي سكربت: تبدأ التشغيلات في الأثناء دون `repl`، ويستدعي التشغيل الذي يملكه أدواته مباشرةً ([حين لا تستطيع السكربتات العمل](/ar-SA/دليل-المستخدم/مفاهيم/وضع-الكود/#حين-لا-تستطيع-السكربتات-العمل)). ويواصل الفحص، بحد أقصى مرة في الدقيقة، فإذا نجح الفحص الذاتي مرة أخرى طبع سطر `available` وعاد إلى تشغيل السكربتات. ولا يحتاج الأمر إلى إعادة تشغيل إلا لفحص ذاتي فشل عند البدء. والسبب الذي تعرضه إعدادات مساحة العمل خالٍ من مسارات المضيف، أما سطر السجل فيحمل السبب كاملًا.

تحدّد علمَا وضع الكود ما يجوز للسكربتات استخدامه. يحدّ `--code-mode-max-processes` عدد السكربتات التي تعمل في وقت واحد عبر كل مساحات العمل (الافتراضي ضعف أنوية المعالج، بحد أقصى 16؛ ويُقبل من 1–64). ومع سقف 2 أو أكثر، لا تستطيع مساحة عمل واحدة أن تستخدم أكثر من السقف مطروحًا منه ربعه، فلا تستطيع مساحة عمل واحدة أن تأخذ كل المكان، وتُقبل السكربتات المنتظرة بالدور عبر مساحات العمل. والسكربت الذي ينتظر موافقة شخص أو جوابه يفسح مكانه لسكربت آخر، ولا يبدأ أي استدعاء أداة حتى يُجاب، ويُحتفظ بما يصل إلى أربعة أضعاف السقف من هذه السكربتات المنتظرة، على ألا يأتي من مساحة عمل واحدة أكثر من ثلاثة أرباعها، ويستطيع كل منها أن يواصل الحساب ضمن حد وقت المعالج الخاص به. و`--code-mode-max-heap-mb` هو أكبر قدر من الذاكرة يستطيع أي سكربت استخدامه.

تُوقف القيمةُ التي لا تقبلها هذه الأعلام (رقمٌ خارج النطاق، أو ما ليس برقم) الخادمَ عند البدء (رمز الخروج `78`) برسالة تسمّي القيم المقبولة. ولا تُقرأ هذه القيمة أبدًا على أنها الافتراضي.

## الأوامر الفرعية

| الأمر                                         | ما يفعله                                                                                                                                 |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `cc_server`                                   | يشغّل الخادم حتى `SIGINT`/`SIGTERM`                                                                                                      |
| `cc_server pair`                              | يصكّ جهازًا ويطبع معرّفه ومفتاح اقترانه. آمن مع دليل بيانات يقدّمه خادم أصلًا — يلتقطه الخادم الجاري من غير إعادة تشغيل                  |
| `cc_server connect <command>`                 | يعرض أي Control Center Connect يستخدمه هذا الخادم أو يغيّره، من غير تشغيله                                                               |
| `cc_server update`                            | يبحث عن إصدار مستقل أحدث، وينزّله، ويتحقّق منه                                                                                           |
| `cc_server --version`                         | يطبع إصدار البناء وبصمة git — الهوية نفسها التي يعلنها `/healthz` ومصافحة RPC                                                            |

### `pair`

| العلم          | الافتراضي                                              | المعنى                                                                                                                                                    |
| -------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--device`     | `web-client`                                           | معرّف الجهاز. تُستنتج المنصة منه، فـ `--device desktop` يصكّ صف حاسوب و`--device ios`/`android` صف هاتف، وأي قيمة أخرى تُعامل على أنها ويب              |
| `--label`      | اسم المنصة مع اسم مضيف هذا الجهاز                      | الاسم المعروض في قائمة الأجهزة                                                                                                                            |
| `--host`       | `localhost`، أو `<this-host>` حين يكون الربط على كل الواجهات | المضيف المُضمَّن في العنوان المطبوع. اضبطه على عنوان IP في الشبكة المحلية أو مضيف النفق الذي سيتصل به العميل فعلًا                                  |
| `--client-url` | غير مضبوط                                              | أصل عميل **الويب** المستضاف. يضيف رابطًا عميقًا قابلًا للمسح ورمز QR في الطرفية                                                                          |

يقبل `pair` أيضًا أعلام `--data-dir` و`--port` و`--bind` الأساسية: تختار دليل
البيانات الذي يُكتب فيه وتشكّل عنوان الخادم المطبوع (`ws` على loopback،
و`wss` مع `--bind any`). إعادة `pair` لنفس `--device` تدور مفتاحه وتُسقط جلسات
ذلك الجهاز الحيّة. بيانات الاعتماد التي تُصك هنا **بلا انتهاء صلاحية**، بخلاف
الثلاثين يومًا التي يضبطها الاقتران داخل التطبيق.

:::caution[رمز QR لـ `--client-url` ليس رمز الهاتف]
`pair --client-url` يملأ نموذج اتصال عميل **الويب** (عنوان الخادم ومعرّف
الجهاز والمفتاح في جزء العنوان). يقترن الهاتف بحمولة مختلفة تُصك من لوحة
الاقتران داخل التطبيق — واصف اتصال الخادم كاملًا مع انتهاء صلاحية. والاثنان
غير قابلين للتبادل — انظر [اقتران جهاز](/ar-SA/دليل-المستخدم/أدلة-إرشادية/اقتران-جهاز/).
:::

### `connect`

يقرأ الإعدادات نفسها التي تضبطها بطاقة **Control Center Connect** في **الإعدادات ←
الخادم ← تسجيل الدخول الموحّد** ويكتبها، من دليل البيانات. يلتقط الخادم الجاري
التغيير في غضون 10 دقائق أو عند إعادة التشغيل.

| الأمر                           | ما يفعله                                                                                                         |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `cc_server connect status`      | يطبع الوضع، والعنوان، وهل يقفله `CC_CONNECT_URL`، ومعرّف التثبيت، والسلامة، ومصدر كل مسار (`own` أو `connect` أو `off`) |
| `cc_server connect enable`      | يستخدم Connect المستضاف من Control Center                                                                        |
| `cc_server connect enable --url <url>` | يستخدم Connect مخصصًا عند ذلك العنوان (HTTPS، أو `http` على loopback)                                      |
| `cc_server connect disable`     | يتوقف عن استخدام Connect. لا يُدخِل الناس إلا تطبيقات الخادم الخاصة                                              |

`status` بلا أمر هو الافتراضي. يقبل كل أمر `--data-dir`. ويتقدّم `CC_CONNECT_URL` على
كل ما تخزّنه هذه الأوامر. والأمر المجهول يخرج بـ `64`. انظر
[Control Center Connect](/ar-SA/دليل-المستخدم/مرجع/connect/) للأوضاع وهوية التثبيت
ورموز الحالة.

### `update`

`--apply` يستبدل التثبيت، ويُرفض ما دام خادم يجيب على المنفذ المضبوط إلا إذا
مرّرت `--force`. `--allow-downgrade` يسمح بإصدار أقدم.

يرفض الأمر رفضًا باتًا، بشرح لا بخطأ، للتثبيتات التي لا يملكها:

| البيئة                              | يُكتشف عبر                              | ما يقوله                                              |
| ----------------------------------- | --------------------------------------- | ----------------------------------------------------- |
| الخادم المضمّن في تطبيق الحاسوب     | `CC_EMBEDDED=1` أو `CC_BOOTSTRAP_DEVICE_ID` | حدّث التطبيق — المثبّت يستبدل الشجرة كلها            |
| شجرة مصدر عبر `dart run`            | مسار السكربت ينتهي بـ `.dart`           | حدّثها بـ git                                         |
| Docker                              | علامات الحاوية                          | اسحب صورة أحدث                                        |

## دورة حياة العملية

يعمل `cc_server` حتى `SIGINT` / `SIGTERM`. يحكم ذلك متغير بيئة إضافي واحد،
ويضبطه تطبيق الحاسوب لا أنت:

| المتغير                 | الأثر                                                                                                                                                              |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CC_EXIT_WITH_PARENT=1` | يخرج الخادم حين تخرج عمليته الأم، ويُكتشف ذلك بإغلاق الأم طرف الكتابة من أنبوب stdin. يضبطه تطبيق الحاسوب حتى لا يخلّف التطبيق الذي تعطّل خادمًا يتيمًا يمسك دليل البيانات |

اضبطه بنفسك فقط إذا كنت تشرف على `cc_server` كعملية ابن وتريد الضمان نفسه.

يوقف `DO_NOT_TRACK=1` (أي قيمة غير الفارغة أو `0` أو `false`) [تحليلات الاستخدام](/ar-SA/دليل-المستخدم/مرجع/تحليلات-الاستخدام/) الخاصة بالخادم نفسه حتى حين يكون المفتاح العام للخادم مفعّلًا. يواصل العملاء اتباع المفتاح.

## تخطيط دليل البيانات

دليل البيانات الافتراضي هو `~/Library/Application Support/control-center` على
macOS، و`%APPDATA%\control-center` على Windows، و`$XDG_DATA_HOME/control-center`
(وإلا `~/.local/share/control-center`) في سواهما. لا يُستخدم `.cc_server`
النسبي إلى دليل العمل الحالي إلا إذا لم يُعثر على دليل المنزل ولا على دليل
بيانات التطبيق.

يُبقي الخادم دليل البيانات خاصًا بحساب الخادم نفسه (`0700`). ويرفض البدء (رمز الخروج `78`) حين لا يستطيع ذلك، أو حين يكون `global.db` تالفًا أو كتبه إصدار أحدث، أو حين يتعذّر قراءة ملف هويته.

| المسار                            | المحتويات                                                                              |
| --------------------------------- | -------------------------------------------------------------------------------------- |
| `global.db`                       | سجل مساحات العمل، والمستخدمون، والأجهزة المقترنة، وموجز الأخبار، وطابور الأسطول       |
| `<workspaceId>/workspace.db`      | قاعدة واحدة لكل مساحة عمل — الوكلاء والمساحات والتذاكر والذاكرة          |
| `<workspaceId>/code_index.db` | مخطط الشفرة الخاص بمساحة العمل تلك. يُعاد بناؤه حين يكون مفقودًا، ولا يُنسخ احتياطيًا أبدًا |
| `pre_upgrade/`، و`<workspaceId>/pre_upgrade/` | أحدث نسختين من قاعدة بيانات تعود إلى ما قبل أن يغيّر تحديث صيغتها |
| `<workspaceId>/chat_credentials/` | رموز بوت الدردشة بصيغة JSON عادي، لتنتقل مع مساحة العمل                                |
| `secrets.json`                    | مفاتيح الاقتران، ومفتاح تثبيت Connect، وتطبيقات المزوّدين، وتسجيلات دخول الناس (مختومة حين تجري عبر Connect)، وأسرار webhook، وSSO (`0600`) |
| `backups/<timestamp>/`            | لقطة تثبيت واحدة — `manifest.json` و`global.db` ونسخة من كل مساحة عمل                  |
| `backups/exports/`                | تصديرات مساحة عمل واحدة، `<workspaceId>-<timestamp>.db`                                |
| `backups/transfer/`               | تجهيز لتنزيلات النسخ الاحتياطي ورفعها، وينظّفه المسار الذي يكتب فيه                    |
| `models/`                         | نماذج التضمين وفصل المتحدثين والكلام على الجهاز                                        |
| `codemode/` | نسخة تطوير من مُشغِّل وضع الكود، يثبّتها `scripts/natives/build_codemode.sh`؛ وحزم الإصدار تحملها في `bin/codemode/` |
| `meetings/<meetingId>/`           | صوت الاجتماعات المحتفظ به                                                              |
| `rigs/images/`                    | صور أقراص المنصات المستوردة (سطح QEMU للحاسوب)                                         |
| `rigs/smolvm/<rigId>/`            | حالة تشغيل microVM لكل منصة (سر الوسيط، `0600`)                                        |
| `rigs/smolvm-packs/`              | حزم أجهزة مستخرجة سلفًا — الذاكرة المؤقتة التي تجعل إقلاع المنصة المتكرر سريعًا        |
| `rigs/tls/`                       | مرجع شهادات نطاق التطوير لـ HTTPS المنصات (المفاتيح `0600`)                            |
| `rigs/run/<rigId>/`               | تراكبات QEMU وصور البذرة ومفاتيح كل آلة (`0600`)                                       |
