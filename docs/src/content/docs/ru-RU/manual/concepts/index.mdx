These pages explain **how Control Center works and why**. They are for understanding,
not for doing: no page here is a procedure to follow. When you want to accomplish a
specific task, go to the [how-to guides](/ru-RU/руководство/практические-руководства/); when you want to look
something up, go to the [reference](/ru-RU/руководство/справка/).

Read them in any order. If you are new, the core model is the place to start.

## Core model

The four ideas everything else is built on.

- [Workspaces and isolation](/ru-RU/руководство/понятия/рабочие-пространства/) — the tenant boundary and why it is enforced by the database layout rather than by query discipline
- [The agent model](/ru-RU/руководство/понятия/модель-агента/) — what an agent is made of: identity, role, skills, capabilities, adapter and model
- [Agent dispatch lifecycle](/ru-RU/руководство/понятия/жизненный-цикл-запуска/) — what happens between your message and the agent's first token
- [Modes](/ru-RU/руководство/понятия/режимы/) — how `chat`, `plan`, `review` and `orchestrate` change what an agent may do
- [Tool context and prompt caching](/ru-RU/руководство/понятия/контекст-инструментов/) — why an agent sees a subset of its tools, how it reaches the rest and what keeps the provider cache warm
- [Code intelligence](/ru-RU/руководство/понятия/интеллект-кода/) — the code graph, language server, structural search and debugger
- [Conversation history](/ru-RU/руководство/понятия/история-разговоров/) — persistence, compaction and forking a transcript
