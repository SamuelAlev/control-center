Это руководство показывает, как дать вашему серверу собственный GitHub App. Это
занимает около двух минут, делать это должен только владелец сервера, и требуется
это один раз на сервер.

:::note[Возможно, оно вам не нужно]
Когда включён Control Center Connect, люди входят в GitHub через общий App от
Control Center или через App, который использует Connect вашей организации.
Регистрируйте собственное приложение, если вы выбрали **Использовать свои
приложения**: приложение сервера используется только тогда. См. [Control Center Connect](/ru-RU/руководство/справка/connect/).
:::

Чтобы после этого войти в собственный аккаунт, см.
[Настроить интеграцию GitHub](/ru-RU/руководство/практические-руководства/интеграция-github/).

## Что делает приложение

Одна регистрация отвечает на две разные задачи:

| Задача                | Что на неё отвечает                              | Почему это важно                                                                         |
| --------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| **Человек входит**    | ID клиента и секрет клиента приложения           | У каждого есть собственные учётные данные GitHub — на сервере и на каждом устройстве     |
| **Сервер действует**  | ID приложения и закрытый ключ                    | Агенты, конвейеры, опросчики и ответы бота получают токены для одного репозитория за раз |

Вторая задача никогда не заимствует учётные данные человека целиком. Каждый
токен, который выпускает сервер, охватывает один репозиторий и ограничен тем, что
может делать там ответственный участник. Для чтения привязанного репозитория
достаточно приложения; для всего, что пишет, нужен участник, который может делать
push. Автоматизация никогда не одобряет pull request.

Собственное приложение сервера применяется только при **Использовать свои приложения**. С Control Center Connect или собственным Connect Connect обслуживает все каналы, включая GitHub; приложение сервера остаётся сохранённым, но неиспользуемым, пока вы не переключитесь обратно. Рабочее пространство на собственных приложениях ([Дайте одному рабочему пространству собственное приложение](#дайте-одному-рабочему-пространству-собственное-приложение)) использует собственное приложение вместо приложения сервера, независимо от режима сервера. Приложение с незаполненными полями — это ошибка, а не переход на запасной вариант: входы в GitHub отклоняются, пока не заданы все поля.

## Предварительные требования

- Вы — **владелец сервера**. Карточка **Приложения провайдера** невидима для всех
  остальных
- Аккаунт GitHub. Приложение создаётся под ним
- Адрес сервера, доступный вашему браузеру. Публичный URL сервера (или loopback
  для собственного сервера настольного приложения) — это то место, куда GitHub
  вас возвращает

## Создайте его одним щелчком

1. Откройте **Настройки → Сервер → Единый вход** и прокрутите до карточки
   **Приложения провайдера**
2. В блоке **GitHub** при желании укажите в поле **Организация (необязательно)**
   организацию GitHub, которой должно принадлежать приложение. Оставьте поле
   пустым, чтобы создать приложение под собственным аккаунтом; для создания под
   организацией нужен владелец этой организации
3. Нажмите **Создать моё приложение GitHub**
4. Браузер откроет GitHub с уже заполненным приложением. Нажмите
   **Create GitHub App**
5. GitHub вернёт вас на сервер, который сохранит id приложения, закрытый ключ,
   id клиента и секрет клиента, а затем откроет страницу установки приложения

Ничего не копируется вручную, а код преобразования идёт прямо из GitHub на ваш
сервер. Ссылка работает один раз и истекает через десять минут; если она истекла,
снова нажмите **Создать моё приложение GitHub**.

Приложение называется `Control Center <code>` и запрашивает ровно то, что
использует Control Center:

| Разрешение                                 | Доступ            |
| ------------------------------------------ | ----------------- |
| Metadata                                   | Чтение            |
| Contents                                   | Чтение и запись   |
| Pull requests                              | Чтение и запись   |
| Issues                                     | Чтение и запись   |
| Checks, Actions, Commit statuses           | Чтение            |
| Organization members                       | Чтение            |

Вебхуки выключены: сервер опрашивает. Чтобы позже перенести приложение, созданное
под собственным аккаунтом, в организацию, используйте **Transfer ownership** в
расширенных настройках приложения на GitHub.

Проверка: блок GitHub показывает «Сервер может действовать от своего имени, и люди
могут входить».

## Установите его туда, где лежат ваши репозитории

Зарегистрированное, но не установленное приложение может выполнять вход людей, но
ничего не может читать.

1. На странице установки, которую открыл GitHub, выберите аккаунт или
   организацию, которой принадлежат ваши репозитории
2. Выберите **All repositories** или отметьте те, которые должен видеть этот
   сервер

Чтобы позже установить его на другой аккаунт, администратор рабочего пространства
открывает **Настройки → Рабочее пространство → Интеграции**, находит **Установки
приложения GitHub** на карточке **GitHub App** в разделе «Хостинг кода» и нажимает **Установить
приложение GitHub**. В списке видны все аккаунты, на которых установлено
приложение, а приостановленная установка помечена.

## Поделитесь установкой организации

Организация устанавливает GitHub App один раз. После этого любой её участник,
который входит в GitHub на сервере Control Center, может пользоваться установкой,
на каком бы сервере он ни работал: вашем, коллеги или своём. Авторизовать сервер
отдельно не нужно.

Каждый токен, который получает сервер, принадлежит вошедшему человеку, ограничен
одним репозиторием и его ролью в нём, поэтому он не даёт больше, чем этот человек
может на GitHub. Журнал аудита GitHub показывает этого человека, действующего через
приложение.

Чтобы остановить доступ Control Center к организации, владелец организации
удаляет установку или сужает её репозитории на GitHub. Удаление человека из
организации тоже прекращает его доступ.

## Зарегистрируйте его вручную

Карточка **Приложения провайдера** принимает и значения напрямую — для
приложения, которое вы зарегистрировали сами:

| Группа                         | Поля                                                                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------------ |
| **В роли сервера**             | **ID приложения** и **Закрытый ключ** (весь `.pem` вместе со строками `BEGIN` и `END`)          |
| **Вход пользователей**         | **ID клиента** и **Секрет клиента**. **URL обратного вызова** показывает URL для регистрации дословно |
| **Беседы в pull request**      | **Логин бота**, определяется при проверке подключения                                            |

Зарегистрируйте URL обратного вызова `<server origin>/oauth/github/callback`
точно так, как его показывает карточка, оставьте **Expire user authorization
tokens** включённым и выдайте разрешения из таблицы выше. Нажмите **Тест**: он
спрашивает у GitHub, на каких аккаунтах установлено приложение, чтобы не путать
«сохранено» и «работает».

## Настройте его из `.env` сервера

Для headless- или скриптовой установки сервер заполняет каждое поле из своего
файла `.env` в первый раз, когда у него нет сохранённого значения:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

Записывайте ключ **одной строкой**: значение в `.env` — это одна строка, а `\n`
внутри двойных кавычек декодируется в перевод строки. Сервер отказывается
запускаться, если `GITHUB_APP_PRIVATE_KEY` или `GITHUB_CLIENT_SECRET`
экспортированы в окружение его процесса, где их мог бы прочитать любой дочерний
процесс; храните их в файле `.env` (в Docker смонтируйте его в `/app/bin/.env`).
Заполнение происходит **один раз для каждого поля**, поэтому правка в «Настройках»
не отменяется следующим перезапуском.

## Дайте одному рабочему пространству собственное приложение

Рабочее пространство может использовать собственное приложение вместо приложения сервера:

1. Администратор рабочего пространства открывает **Настройки → Рабочее пространство → Интеграции**
2. На карточке **Control Center Connect** выбирает **Использовать свои приложения** и нажимает **Применить**. Все участники рабочего пространства входят заново, через приложения рабочего пространства
3. Карточка **GitHub App** в разделе «Хостинг кода» получает поля приложения: **ID приложения** и **Закрытый ключ** в разделе **Действует от имени этого рабочего пространства**, **ID клиента** и **Секрет клиента** в разделе **Вход пользователей**. Нажмите **Тест**, когда они заполнены

Участники затем входят в это приложение для этого рабочего пространства. Рабочее пространство на собственных приложениях никогда не переходит на приложение сервера или на Connect: пока его поля не заполнены, его работа с GitHub отклоняется. Тот же выбор касается Google Calendar, Linear и поиска GIF: у каждого свои поля рядом с его провайдером на той же странице. См. [Дайте одному рабочему пространству собственное приложение Linear](/ru-RU/руководство/практические-руководства/интеграция-linear/#дайте-одному-рабочему-пространству-собственное-приложение-linear) и [Дайте одному рабочему пространству собственный клиент Google](/ru-RU/руководство/практические-руководства/подключить-календарь/#дайте-одному-рабочему-пространству-собственный-клиент-google). Остальные варианты этой карточки и что делает каждый из них описаны в [Выбор для рабочего пространства](/ru-RU/руководство/справка/connect/#выбор-для-рабочего-пространства).

## Устранение неполадок

### «Создать моё приложение GitHub» сообщает, что у сервера нет адреса

У сервера нет публичного URL, на который мог бы вернуться браузер. Задайте
`CC_SERVER_PUBLIC_URL` (или `--public-url`) и попробуйте снова.

### GitHub сообщает, что ссылка истекла

Одноразовая страница уже использована, или прошло десять минут. Начните заново
из «Настроек».

### Тест сообщает, что учётные данные работают, но приложение нигде не установлено

Регистрация и установка — отдельные шаги. Откройте страницу установки приложения
или воспользуйтесь **Установить приложение GitHub** в разделе «Рабочее
пространство → Интеграции».

### Тест сообщает, что не удалось прочитать закрытый ключ

Вставьте файл `.pem` целиком, включая строки `-----BEGIN` и `-----END`. Ключ
`ed25519` или EC использовать нельзя: GitHub Apps подписывают с помощью RSA.

### Участник вошёл, но не видит ни одного репозитория

Приложение не установлено на аккаунте, которому они принадлежат, или его установка
выбирает другие репозитории. Вход даёт только то, что может видеть приложение.

### Агенты сообщают, что установка GitHub App приостановлена

Кто-то приостановил установку на GitHub. Возобновите её в разделе аккаунта
**Settings → Applications → Installed GitHub Apps**.
