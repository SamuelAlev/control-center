Это руководство показывает, как работать с хранилищем знаний рабочего пространства.

Важно понимать перед началом: **интерфейс памяти — это поверхность для проверки, а не для создания.** Факты и политики записывают агенты — через `propose_fact` и `propose_policy`, а для замены — `supersede_fact` и `supersede_policy`. `remember` записывает элемент горячего уровня, привязанный к сессии, который `consolidate_memory` позже может повысить до факта. Решения из записанных встреч извлекаются в домен `decisions`; при завершении запусков агентов такого извлечения нет. Здесь вы читаете то, что они записали, исправляете, деактивируете или удаляете.

Память находится в разделе **Настройки → Рабочее пространство → Память** (`/workspaces/<id>/settings/memory`). Это не отдельный пункт верхнего уровня в боковой панели.

## Три вкладки

На странице ровно три вкладки. Для «Фактов» и «Политик» показывается актуальное число; для графа — нет:

- **Факты** — все факты рабочего пространства со счётчиком тех, что не заменены
- **Политики** — нормативные правила, сгруппированные по доменам, со счётчиком активных
- **Граф знаний** — интерактивный холст из доменов, тем, фактов и политик

Домены вручную не создаются. Домен появляется, когда агент записывает в него первый факт или политику; элемента для создания домена в интерфейсе нет.

## Проверить и исправить факт

1. Откройте вкладку **Факты**.
2. Сузьте список через поле поиска. Это обычный фильтр по подстроке по домену, теме и содержимому каждого факта — без индексного поиска по ключевым словам и без ранжирования.
3. С помощью фильтра области покажите все области, только факты уровня рабочего пространства или факты одного репозитория.
4. Переключателем сортировки задайте порядок по недавности или по уверенности.
5. Нажмите элемент редактирования у факта.

В диалоге редактирования можно изменить:

- **Домен** — перенос факта между доменами
- **Тема** — её короткая метка
- **Содержимое** — текст знания
- **Уверенность** — ползунок с шагом 5%

Нажмите «Сохранить», чтобы записать изменения. Кнопки **Новый факт** нет; диалог открывается только для существующей строки.

## Посмотреть заменённые факты

На вкладке «Факты» есть переключатель **Показывать заменённые**. Заменённые факты по умолчанию скрыты и показываются этим переключателем — именно в них заключается история изменений: замена никогда не удаляет.

## Удалить факт

Нажмите элемент удаления у факта и подтвердите. Это настоящее удаление, а не замена: используйте его для фактов, которые вообще не стоило записывать, а факты, чьё _содержимое_ устарело, пусть заменяют агенты.

## Управлять политиками

Вкладка **Политики** группирует активные политики по доменам, а неактивные выносит в раздел в конце. Для каждой политики можно:

- **Изменить** её
- **Удалить** её
- **Деактивировать** / **Активировать** её — обратимый вариант, обычно именно он и нужен. В промпты агентов попадают только активные политики.

Как и для фактов, элемента создания здесь нет.

## Изучить граф знаний

Вкладка **Граф знаний** раскладывает домены, темы, факты и политики в виде навигационного холста узлов — перемещение, масштабирование, перетаскивание узлов. Нажатие на узел открывает панель сведений, из которой доступны те же диалоги редактирования. Так быстрее всего увидеть, какие домены действительно наполнены.

## Редактировать рабочую память агента

Рабочая память — это приватный черновик каждого агента, который подставляется в его промпт в момент запуска. Агенты пишут в него сами через `record_observation` и `update_my_notes`, но вы можете читать и редактировать его напрямую:

**Настройки → Рабочее пространство → Агенты** → выберите агента → вкладка **Память**.

## Разрешения на доступ

Разрешения на доступ к памяти сопоставляют роль агента с разрешением (`none`, `read`, `write`) для каждого домена. Создавайте их операциями `memory_access_grant.*`.

Вот что важно понимать о том, как они применяются:

- **Чтение разрешается при сбое.** Если для пары (роль, домен) нет строки разрешения, действующее разрешение — `read`. Единственная запись, которая выдаёт ошибку без `write`, — `propose_policy`. Запись фактов разрешением не ограничена.
- **Разрешения привязаны к роли агента.** Инструменты предложения по умолчанию подставляют `general`, если `agent_role` не указан. Разрешение, созданное для другой роли, на таких агентов не распространяется; разрешение для `general` — распространяется.

## Поиск везде разный

Три разные вещи называются «поиском по памяти», и они не согласованы между собой:

| Где                                    | Что делает                                                                                                                                    |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Поле поиска на вкладке «Факты»         | Фильтр по подстроке по фактам, уже загруженным в клиент                                                                                        |
| RPC-операция `memory_fact.search`      | Только поиск по ключевым словам через FTS5: тонкий клиент не может отправить эмбеддинг запроса, поэтому гибридный поиск остаётся внутри хоста  |
| Инструмент `search_memory` у агента    | `keyword`, `semantic` или `hybrid` (по умолчанию). Гибридный режим объединяет четыре голоса: лексический, семантический, временной и графовый  |

Поэтому агент и страница «Память» ранжируют один и тот же запрос по-разному. Когда нужно проверить, что агент действительно может вспомнить, спросите агента.

## Эмбеддинги

Факты получают эмбеддинг **в момент записи** и только если установлена локальная модель эмбеддингов. Проверить её состояние можно в разделе **Настройки → Сервер → Диагностика и конфиденциальность → Семантический поиск**. Установите модель до того, как агенты начнут писать в память, если хотите семантическое извлечение.
