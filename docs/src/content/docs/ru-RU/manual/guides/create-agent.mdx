В этом руководстве показано, как добавить агента в рабочее пространство и настраивать его, пока он действительно не сможет запускаться.

В каждом рабочем пространстве уже созданы пять агентов — CEO, а также `qa`, `architect`, `engineer` и `librarian`, — поэтому агенты обычно есть у вас ещё до того, как вы кого-то настроили. Шаги ниже одинаково применимы и к уже созданному агенту, и к новому.

## Перед началом

- Вы находитесь внутри рабочего пространства. Весь интерфейс живёт в разделе **Настройки → Рабочее пространство → Агенты** (`/settings/workspace/agents`).
- Агенту понадобится бэкенд. Либо подключите провайдера для встроенного харнесса в разделе **Настройки → Сервер → Провайдеры моделей**, либо установите CLI Claude Code на машине, где работает `cc_server`.
- Если вы хотите, чтобы у агента были навыки, сначала установите их в разделе **Настройки → Рабочее пространство → Навыки**. Форма агента позволяет только включать и выключать навыки, которые уже есть в рабочем пространстве.

## Добавьте агента

1. Откройте **Настройки → Рабочее пространство → Агенты**.
2. Нажмите **Новый агент**.

Диалогового окна и выбора роли нет. Агент с именем «Безымянный агент» создаётся сразу и выбирается в панели сведений справа.

Теперь в списке слева должен появиться «Безымянный агент», у него открыта вкладка **Настройки**, а поле **Имя** содержит «Безымянный агент».

## Дайте ему имя

- **Имя** — короткий идентификатор для @-упоминаний, например `alice`. Разбор упоминаний сопоставляет `@`, за которым идут словесные символы, поэтому имя с дефисом, точкой или пробелом упомянуть невозможно.
- **Название** — понятное человеку обозначение, например «Старший программист».
- **Системный промпт** — необязательные дополнительные инструкции; они подмешиваются как раздел с инструкциями агента и не заменяют остальную часть собранного промпта.

Нажмите **Сохранить изменения** внизу формы. Все поля на этой странице сохраняются одной этой кнопкой.

## Задайте адаптер и модель

В раскрывающемся списке **Адаптер** перечислены раннеры, которые действительно есть на хосте сервера. Встроенный адаптер находится всегда (это сам сервер). Claude Code появляется, только если его CLI был обнаружен на этом хосте:

| Адаптер                   | Бэкенд                                          |
| ------------------------- | ----------------------------------------------- |
| Control Center (built-in) | Внутрипроцессный цикл агента — без внешнего CLI |
| Claude Code               | `claude -p --output-format stream-json`         |

Только встроенный адаптер обеспечивает режимы, управление, пауза/возобновление, контракты завершения и субагентов. В Claude Code ничего этого нет. Cursor, Codex и остальные провайдеры моделей подключаются к встроенному адаптеру, а не работают как отдельные раннеры.

:::note[Пустой адаптер означает встроенный цикл]
Агент, у которого адаптер не задан, направляется в **Control Center (built-in)** — цикл внутри сервера, поэтому на хосте ничего не нужно устанавливать. Если и модель не задана, он запрашивает у Anthropic модель по умолчанию, так что полностью ненастроенный агент запускается, только если вы подключили аккаунт Anthropic. Поставляемые специалисты идут без того и другого; задайте и то и другое любому агенту, которым собираетесь пользоваться.
:::

Содержимое раскрывающегося списка **Модель** определяется выбранным адаптером. Для встроенного адаптера список берётся вживую у провайдеров, подключённых в разделе **Настройки → Сервер → Провайдеры моделей**, поэтому провайдер без сохранённых учётных данных не даёт ни одной модели.

## Добавьте навыки

**Навыки** — это выбор чипами из наборов навыков, установленных в этом рабочем пространстве. Нажмите на чип, чтобы включить или выключить его; глиф галочки отмечает выбранные. Если в рабочем пространстве нет навыков, поле показывает «No skills available. Create skills in Settings → Skills first.»

Навыки самого репозитория здесь не выбирают. Репозиторий, который их поставляет (в `.agents/skills/`, `.claude/skills/` или `.opencode/skills/`), добавляет их автоматически тому агенту, который работает в этом репозитории, и они сменяются, когда он переходит в другой, — см. [Навыки уровня репозитория](/ru-RU/руководство/понятия/модель-агента/#repo-scoped-skills).

## Задайте линию подчинения и персону

- **Руководитель** — выберите другого агента по имени. Так строится дерево подчинённости, которое показывает кнопка **Оргсхема** в шапке страницы. Это не тот состав, на который опирается руководитель команды при делегировании, — он складывается из участников команды и их навыков.
- **Персона** — свободный текст, задающий тон и поведение, например: «Предпочитает простые, читаемые решения. Пишет тесты для всего нового кода.»

## Настройте запуск

- **Усилие рассуждения** — варианты берутся из собственных опубликованных уровней выбранной модели: Low / Medium / High, плюс Extra High у моделей в стиле OpenAI и Extra High + Max у моделей в стиле Claude. Поле полностью скрывается, когда выбранная модель не объявляет уровней мышления, и по умолчанию принимает значение самой модели.
- **Размер контекстного окна** — подставляется из контекстного окна модели при каждой смене модели, с чипами в одно нажатие для значения по умолчанию модели, 200k, 500k и 1M. Значение, введённое вами после выбора модели, действует до следующей смены модели.
- **Таймаут тишины (минуты)** — завершает запуск после столького времени без вывода. Оставьте поле пустым, чтобы использовать значение по умолчанию для режима.

## Выдайте разрешения

**Права песочницы** изначально стоят на «По умолчанию рабочего пространства». Включите переключатель, чтобы задать их для этого агента, затем переключайте:

- **Разрешить git push** — подмешивает токен GitHub, нужный агенту для отправки
- **Разрешить вызовы GitHub API** — позволяет агенту читать PR, тикеты и метаданные репозитория
- **Разрешить вызовы API тикетов** — подмешивает ключ провайдера тикетов
- **Разрешить общий доступ к сети** — также включает инструменты `web_fetch` и `web_search` встроенного харнесса

Каждый переключатель проверяет брокер учётных данных при старте запуска: выключенная возможность означает лишь то, что соответствующий токен никогда не выпускается в окружение запуска.

:::caution[Значение по умолчанию рабочего пространства — это консервативный набор сервера]
Агент, оставленный на «По умолчанию рабочего пространства», запускается с выключенными git push, GitHub API и тикетами и включённой сетью. Значения по умолчанию для возможностей, показанные в разделе Настройки → Сервер → Диагностика и конфиденциальность, — это клиентская настройка. Если вы хотите, чтобы агент отправлял изменения или открывал PR, включите переключатель и явно выдайте возможности.

Эти возможности управляют доступом к учётным данным и инструментам харнесса, а это отдельный слой от песочницы ОС. `cc_server` оборачивает запуски агентов в песочницу хоста там, где она есть, — в Windows нативного бэкенда нет, а Linux и WSL2 нуждаются в `bwrap` и `socat`. Полный набор границ описан в разделе [Песочница и безопасность](/ru-RU/руководство/понятия/песочница-и-безопасность/).
:::

## Проверьте, что он запускается

1. Откройте **Настройки → Сервер → Провайдеры моделей** и убедитесь, что выбранный адаптер сообщает установленную версию, а не «Не найдено». Нажмите **Обновить**, чтобы перепроверить — проверка идёт на машине, где работает `cc_server`, а не на той, которую вы смотрите.
2. Откройте пространство с агентом и отправьте ему сообщение или упомяните его через @ в существующем пространстве.
3. Вернитесь в **Настройки → Рабочее пространство → Агенты**, выберите агента и откройте его вкладку **Журнал**. Должен появиться запуск со значком статуса, длительностью, временем начала и адаптером, который он использовал. **Просмотр** открывает поток событий этого запуска.

Если запуск вообще не появляется, пройдите [Диагностировать агента](/ru-RU/руководство/практические-руководства/диагностика-агента/).

## Удалите агента

Выберите его в списке. На вкладке **Настройки** прокрутите до **Опасной зоны** внизу формы и нажмите **Удалить**.
