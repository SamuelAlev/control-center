Это руководство показывает, как подключить внешний MCP-клиент — Claude Code,
редактор, MCP Inspector — к собственному серверу инструментов Control Center.

Control Center регистрирует **110** инструментов и предоставляет их по Model
Context Protocol, версия протокола `2024-11-05`. Целых семейств инструментов,
которых вы могли бы ожидать, здесь нет: нет инструментов для встреч и
календаря и нет инструментов для проектов.

## Найти эндпоинт

Поверхность MCP использует общий основной слушатель `cc_server`. Отдельного
порта MCP нет.

| Эндпоинт | Метод    | Назначение                                               |
| -------- | -------- | -------------------------------------------------------- |
| `/mcp`   | `POST`   | Транспорт Streamable HTTP — именно на нём говорит клиент |
| `/mcp`   | `DELETE` | Завершить сессию                                         |
| `/sse`   | `GET`    | Поток уведомлений, отправляемых сервером                 |

Так что локальная установка по умолчанию доступна по адресу
`http://127.0.0.1:9030/mcp`.

1. Откройте **Настройки → Сервер → MCP-серверы**
2. Посмотрите карточку **MCP-сервер** — она показывает, запущен сервер или
   остановлен, и порт, который он слушает

На свежей установке поверхность включена по умолчанию. Токен аутентификации в карточке видит только владелец сервера, и только он может запустить или остановить эндпоинт. **Запускать при старте приложения** определяет, вернётся ли она после перезапуска; **Запустить** / **Остановить** — это команды для текущей сессии, они не меняют эту настройку.

По умолчанию сервер привязывается к loopback, поэтому эндпоинт доступен только
с машины, на которой работает `cc_server`, если только вы не запустили его с
`--bind any`.

## Получить токен

Каждый запрос должен передавать MCP-токен сервера, с любой машины, включая loopback. Сервер создаёт его при первом запуске. Отключить его или очистить нельзя.

1. В **Настройки → Сервер → MCP-серверы** найдите строку **Токен аутентификации**
2. Нажмите **Показать токен** и скопируйте его
3. Чтобы заменить токен, нажмите **Перевыпустить токен**. Сервер сразу переключается на новый токен, а каждый клиент, который всё ещё использует старый, получает отказ, пока вы не передадите ему новый

## Подключить клиент

Направьте клиент на эндпоинт Streamable HTTP и передавайте токен как `Authorization: Bearer <token>` в каждом запросе, включая `GET /sse`. Другого способа нет: токен в URL не принимается. Точная форма конфигурации — дело вашего клиента.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

Claude Code не подхватит это из проектного `.mcp.json` — он ставит MCP-серверы
уровня проекта за запрос на одобрение, на который неинтерактивный `claude -p`
никогда не отвечает. Передайте конфигурацию явно:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` заставляет Claude использовать только этот файл, чтобы тот
же сервер не был ещё и обнаружен из проекта и зарегистрирован дважды.

Проверка: попросите клиент перечислить свои инструменты. Вы должны увидеть
записи `mcp__*`, охватывающие тикеты, пространства, память, граф кода и
проверку.

## Что отклоняет эндпоинт

Токен открывает каждый инструмент сервера, поэтому эндпоинт также отклоняет всё, что могла отправить веб-страница, ещё до проверки токена:

| Запрос | Ответ |
| ------ | ----- |
| Заголовок `Origin`, который не является страницей этой машины (`http://localhost`, `http://127.0.0.1` или `http://[::1]`, любой порт) | `403`, «Межсайтовые запросы не принимаются» |
| Заголовок `Host`, который не является ни loopback-адресом и портом этого слушателя, ни публичным именем хоста сервера | `403`, «Неизвестный хост» |
| `POST`, тело которого не `application/json` | `415` |
| Без токена или с неверным | `401` |

Чтобы обслуживать MCP за пределами хоста, запустите сервер с `--bind any` и передавайте токен с другой машины, обращаясь к серверу по его публичному имени хоста.

## Привязывать каждый вызов к рабочему пространству

Каждый инструмент, который затрагивает данные уровня рабочего пространства,
требует `workspace_id`, и вызов без него отклоняется, а не разрешается
относительно какого-то «текущего» рабочего пространства:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

Этот id — тот, что в URL вашего браузера или приложения:
`/workspaces/<workspace_id>/…`. Единственные исключения — инструменты, которые
действительно охватывают несколько рабочих пространств, например
`list_workspaces` и инструменты ленты новостей — лента новостей ведётся по
пользователю, а у агента нет собственного пользователя, поэтому такие
инструменты работают с лентами владельца сервера.

Инструменты уровня репозитория дополнительно проверяют, что репозиторий привязан
к этому рабочему пространству.

## Знать, что поверхность отклонит

- **Фильтрация по режиму.** Вызов разрешается на стороне сервера относительно
  режима пространства вызывающего агента. Агент в режиме только для чтения не
  может дотянуться до инструмента записи, опустив `space_id` — вместо этого
  режим определяется по его активному запуску.
- **Ограничения действий.** Изменяющие инструменты объявляют свои классы
  эффектов и проходят через ту же политику, что и остальная часть продукта. См.
  [Настроить ограничения](/ru-RU/руководство/практические-руководства/настроить-ограничения/).
- **Подтверждение.** Некоторые разрушительные инструменты формируют полезную
  нагрузку подтверждения, которую нужно одобрить, прежде чем вызов продолжится.

Полный каталог объявляется в `tools/list` без фильтрации на этапе обнаружения —
внешний MCP-клиент отказывается вызывать инструмент, которого нет в его
кэшированном списке, поэтому сокрытие инструментов ломает их, а не наводит
порядок.

## Личные MCP-серверы остаются у владельца

Это руководство описывает собственный эндпоинт Control Center. Обратное направление — MCP-серверы, которые Control Center передаёт агентам, за запуски которых отвечает, — перечислено в **Настройки → Сервер → MCP-серверы → Внешние MCP-серверы**. Серверы, настроенные на машине сервера для Claude, Codex, Cursor, Gemini, VS Code, Windsurf, OpenCode или в `.mcp.json`, находятся там автоматически.

Эти обнаруженные серверы берутся из собственной конфигурации инструментов пользователя сервера и действуют с его идентичностью и учётными данными, поэтому они принадлежат владельцу сервера:

- Они доступны только внутри запусков встроенного harness, которые владелец сервера запускает или за которые отвечает, включая автоматизацию в рабочем пространстве, за которое отвечает владелец.
- Запуск участника, автоматизация, привязанная к участнику, и каждый запуск на сервере без записанного владельца их не получают. Там инструменты не перечисляются, не могут быть вызваны и не появляются в поиске инструментов.
- Этот эндпоинт никогда не перечисляет, не вызывает и не ищет их ни для кого, в том числе с токеном владельца, и не передаёт их ресурсы или промпты. Поэтому агентский CLI, который обращается к Control Center по MCP, например Claude Code, не получает их и через Control Center; он использует собственную конфигурацию.

MCP-серверы, настроенные для рабочего пространства, на это никак не влияют.

## Устранение неполадок

### Клиент не видит ни одного инструмента

- Проверьте, что карточка **MCP-сервер** показывает, что сервер запущен
- Проверьте, что порт совпадает с портом вашего `cc_server`
- В Claude Code проверьте, что вы передали `--mcp-config` и
  `--strict-mcp-config`

### 401 — не авторизован

В запросе не было токена или был старый. Скопируйте текущий токен из строки **Токен аутентификации** и передавайте его как `Authorization: Bearer <token>`. Токен в URL игнорируется.

### 403 от клиента, который раньше работал

В запросе был `Origin` от веб-страницы или `Host`, на который сервер не отвечает. Обращайтесь к эндпоинту из клиента, а не со страницы браузера, по loopback-адресу сервера или его публичному имени хоста.

### 415 — неподдерживаемый тип медиа

Отправляйте тела `POST /mcp` как `application/json`.

### Вызов инструмента завершается ошибкой «Missing or invalid argument: workspace_id»

Добавьте `workspace_id`. Неявного рабочего пространства не существует.

### Вызов инструмента отклоняется как неизвестный

[Инструменты MCP](/ru-RU/руководство/справка/инструменты-mcp/) перечисляет
каталог. Вызывайте имя точно так, как оно там указано.
