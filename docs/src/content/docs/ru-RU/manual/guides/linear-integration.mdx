У Linear в Control Center две идентичности, и обе — входы через браузер: ваша —
для того, что делаете вы, и приложение Control Center рабочего пространства — для
того, что делают агенты и конвейеры. Тикеты, проекты, связи, соисполнители,
делегирование и назначение работают на собственной базе данных Control Center, и
внешний сервис не нужен — см. [Создавать и управлять
тикетами](/ru-RU/руководство/практические-руководства/управлять-тикетами/).

## Предварительные требования

- Сервер умеет выполнять вход людей в Linear: через Control Center Connect или с
  собственным приложением Linear сервера
  ([Зарегистрировать собственное приложение Linear](#зарегистрировать-собственное-приложение-linear)).
  Владелец сервера выбирает это в разделе **Настройки → Сервер → Единый вход**
- Администратор рабочего пространства — чтобы выбрать Linear как провайдера
  тикетов и подключить автоматизацию Linear

## Выбрать Linear для рабочего пространства

1. Откройте **Настройки → Рабочее пространство → Интеграции** и найдите карточку
   **Тикеты**
2. Установите для **Провайдер тикетов** значение **Linear**

Тикеты, которые вы создаёте с этого момента, помечаются `provider: linear`.
**Локальный** хранит тикеты в собственной базе данных этого сервера и скрывает
строки Linear: аутентифицироваться там не к чему.

## Войти в Linear

Ваш собственный вход в Linear находится в **Настройки → Вы → Профиль**, в карточке **Тикеты**:

1. Нажмите **Войти в Linear**
2. Подтвердите в браузере
3. С собственным приложением сервера диалог сам замечает вход. Через Connect
   введите 8-символьный код, который показывает браузер, или позвольте браузеру
   открыть Control Center по ссылке `control-center://`

Всё, что вы делаете в Linear из Control Center, выполняется через этот вход и
ничего больше. Если вы не вошли, приложение просит вас войти, а не действует от
имени кого-то другого.

Вход работает во всех рабочих пространствах сервера, если только в рабочем пространстве не заданы собственные приложения входа: тогда у этого рабочего пространства остаётся собственный вход в Linear. Карточка показывает, какой вариант действует.

## Подключить автоматизацию Linear

Строка **Автоматизация Linear** на карточке **Тикеты** в разделе **Настройки → Рабочее пространство → Интеграции** — это приложение Control Center рабочего
пространства в Linear. Синхронизация тикетов, конвейеры и агенты пишут через
него, поэтому автоматически созданные задачи и комментарии появляются от имени
Control Center, а не человека.

1. Администратор рабочего пространства нажимает **Подключить Linear для
   автоматизации**
2. Он подтверждает приложение для рабочего пространства Linear в браузере, как
   описано выше

После этого строка показывает «Подключено к _вашему рабочему пространству
Linear_». Подключать и отключать её могут только администраторы рабочего
пространства.

В песочницу агента учётные данные Linear не попадают: агенты пишут тикеты через
собственные инструменты Control Center, которые сначала спрашивают правило
**Писать во внешний трекер**.

## Зарегистрировать собственное приложение Linear

Используйте собственное приложение, если вы выбрали **Использовать свои
приложения**. Приложение сервера применяется только тогда: при Control Center Connect или собственном Connect Connect обслуживает все каналы, включая Linear, а приложение сервера и сервисный ключ API остаются сохранёнными, но неиспользуемыми. Рабочее пространство на собственных приложениях ([ниже](#дайте-одному-рабочему-пространству-собственное-приложение-linear)) использует собственное приложение вместо приложения сервера, независимо от режима сервера.

1. Создайте приложение OAuth на странице
   [linear.app/settings/api/applications/new](https://linear.app/settings/api/applications/new)
2. Добавьте дословно оба URL обратного вызова, которые раздел **Настройки → Сервер
   → Единый вход → Приложения провайдера → Linear** показывает в поле **URL
   обратного вызова**: `<server origin>/oauth/linear/callback` и
   `<server origin>/oauth/linear_app/callback`
3. Вставьте **ID клиента** в блок Linear

Секрета клиента нет: сервер входит с PKCE. Токены обновления Linear истекают
после 30 дней без использования, поэтому сервер раз в день обновляет каждый вход
в Linear старше 20 дней.

Тот же блок принимает необязательный **Сервисный ключ API**. Это собственные
учётные данные Linear сервера для автоматизации в рабочих пространствах, которые
не подключили автоматизацию Linear. Храните его в «Настройках» или в файле `.env`
сервера как `LINEAR_API_KEY`: сервер отказывается запускаться, если
`LINEAR_API_KEY` экспортирован в окружение его процесса.

## Дайте одному рабочему пространству собственное приложение Linear

Рабочее пространство может входить в Linear через собственное приложение вместо приложения сервера. Настроить это может только администратор или владелец рабочего пространства.

1. Создайте приложение OAuth для Linear, как в шагах выше
2. Откройте **Настройки → Рабочее пространство → Интеграции**. В карточке **Control Center Connect** выберите **Использовать свои приложения** и нажмите **Применить**
3. В разделе «Тикеты» появится карточка приложения **Linear**. Добавьте в приложение Linear оба callback-URL, которые карточка показывает в поле **URL обратного вызова**, дословно
4. Вставьте его **ID клиента** и, по желанию, **Сервисный ключ API** для автоматизации этого рабочего пространства

Приложение рабочего пространства затем отвечает на все входы в Linear и запросы автоматизации в этом рабочем пространстве, независимо от того, каким способом сервер выполняет вход людей. Оно никогда не переходит на приложение сервера или на Connect: пока не задан ID клиента, Linear в этом рабочем пространстве выключен, а карточка показывает, чего не хватает. Его сервисный ключ API используется только здесь; без него для синхронизации нужно **Подключить Linear для автоматизации**.

**Использовать свои приложения** действует сразу для всех провайдеров: GitHub, Google Calendar и поиск GIF тоже работают только через собственные приложения рабочего пространства, каждый настраивается рядом со своим провайдером на той же странице. Переключение между приложениями входа рабочего пространства или смена ID клиента рабочего пространства выводит всех участников этого рабочего пространства из Linear и отключает их автоматизацию. Они снова входят через новое приложение. Сохранённые поля остаются, когда рабочее пространство возвращается к другому варианту, но используются только при **Использовать свои приложения**. Секреты доступны только для записи: карточка показывает лишь, сохранён ли один из них. Другие рабочие пространства на сервере не затрагиваются.

## Устранение неполадок

### Строка Linear сообщает, что вход не настроен

У сервера нет ни собственного приложения Linear, ни Connect. Владелец сервера
выбирает один из вариантов в разделе **Настройки → Сервер → Единый вход**. Когда рабочее пространство использует собственные приложения, строка вместо этого сообщает, что его настройка не завершена: администратор рабочего пространства добавляет ID клиента на карточке **Linear** в разделе **Настройки → Рабочее пространство → Интеграции**.

### Синхронизация тикетов завершается ошибкой аутентификации

У рабочего пространства не подключена автоматизация Linear, а у сервера нет
сервисного ключа API, поэтому у синхронизации нет учётных данных. Администратор
рабочего пространства нажимает **Подключить Linear для автоматизации**.

### При подключении автоматизации сообщается, что рабочее пространство Linear подключено в другом месте

Приложение Control Center этого рабочего пространства Linear уже подключено к
другому серверу Control Center.
