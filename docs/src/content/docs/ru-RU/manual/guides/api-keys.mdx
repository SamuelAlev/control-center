Это руководство показывает, где хранятся учётные данные, которые использует
Control Center, и как их изменить.

**На машине, за которой вы печатаете, не хранится ничего.** Все учётные данные
живут на сервере; какие именно ответят на конкретный запрос, зависит от того,
есть ли за ним человек.

| Учётные данные | Где хранятся | Кто их использует |
| --- | --- | --- |
| Ваш вход в хост кода и систему тикетов | Файл секретов сервера с правами 0600, с ключом по вашему идентификатору пользователя | Всё, что делаете вы: поверхность PR, ревью, слияния, ваши действия в Linear |
| Приложения провайдеров сервера | Тот же файл, плюс `server_settings` для всего, что не является секретом | Вход людей и токены для одного репозитория для агентов, конвейеров и опроса |
| Ключ установки Connect | Тот же файл (`connect_install_key`) | Идентификация этого сервера перед Control Center Connect |
| Ключи провайдеров моделей и токены OAuth | Собственное хранилище учётных данных сервера | Встроенный адаптер, для каждого рабочего пространства в установке |
| Учётные данные бота Slack | `<dataDir>/<workspaceId>/chat_credentials/` на сервере | Чат-мост этого рабочего пространства: токены вашего собственного приложения или запечатанный грант общего приложения |
| Учётные данные внешней CLI | То, что использует эта CLI | Claude Code, на хосте сервера |

## GitHub: ваш вход и токены для одного репозитория

- **Ваш** — из **Войти в GitHub**. Именно его использует каждый запрос, сделанный
  *от вашего имени*, поэтому ревью, опубликованное за вас, несёт ваше имя. Другой
  участник не может им воспользоваться и входит сам. Вставлять токен GitHub не
  нужно
- **Работа, за которой никто не печатает** (агенты, конвейеры, опрос, ответы бота),
  получает токен для одного репозитория за раз, выпущенный из GitHub App сервера
  или через Control Center Connect и ограниченный тем, что может делать там
  ответственный участник. Это никогда не ваш вход, переданный целиком

Ваш задаётся в карточке **Хостинг кода** в разделе **Настройки → Вы → Профиль**, а приложение сервера — в карточке
**Приложения провайдера** в разделе **Настройки → Сервер → Единый вход**. См.
[Настроить интеграцию GitHub](/ru-RU/руководство/практические-руководства/интеграция-github/)
и [Создать GitHub App](/ru-RU/руководство/практические-руководства/github-app/).

GitLab и Bitbucket по-прежнему принимают вставленный личный токен, который
хранится так же. См. [Подключить хост кода](/ru-RU/руководство/практические-руководства/подключить-хост-кода/).

:::note[Есть ещё экран, доступный только по URL]
`/workspaces/<workspaceId>/api-keys` показывает те же карточки, что и первый
шаг первоначальной настройки. **В интерфейсе к нему нигде нет пункта навигации**;
попасть на него можно, только введя URL. Вместо него используйте **Настройки → Вы → Профиль** для собственных входов, а **Настройки → Рабочее пространство → Интеграции** для поставщика тикетов.
:::

## Задать ключи провайдеров моделей

Встроенный адаптер сам проходит аутентификацию у провайдеров, и эти учётные данные
живут на сервере.

1. Перейдите в **Настройки → Сервер → Провайдеры моделей**
2. Прокрутите до **Провайдеры и модели**
3. Подключите провайдера: OAuth в браузере для OpenAI, Codex, Cursor и Kimi Code;
   API-ключ для Anthropic и остальных

Полный список и порядок добавления собственной конечной точки — в разделе
[Управлять адаптерами и моделями](/ru-RU/руководство/практические-руководства/адаптеры/).

Эти учётные данные **глобальны для хоста**: один ключ обслуживает каждое рабочее
пространство в установке. Токены OAuth обновляются до истечения срока действия.

Claude Code входит через **Аккаунты Claude Code** в разделе **Настройки → Сервер → Поставщики моделей**: у каждого аккаунта есть собственный каталог конфигурации на сервере, а команду `claude auth login`, которую показывает приложение, вы выполняете там.

Диалог **Переменные окружения** у каждого адаптера выглядит подходящим местом для
такого ключа, но это не так: он пишет на ваше устройство, а сервер читает
собственную копию, и ничто их не связывает. См.
[Управлять адаптерами и моделями](/ru-RU/руководство/практические-руководства/адаптеры/).

## Подключить вендора тикетов

Карточка **Тикеты** в разделе **Настройки → Рабочее пространство → Интеграции**
содержит сторону рабочего пространства: в каком вендоре живут ваши тикеты и кем
Control Center выступает, когда работает там самостоятельно. Выбор **Локальный** скрывает
строки Linear — локальные тикеты живут в собственной базе данных этого сервера, и
аутентифицироваться им негде.

У Linear два входа и никакого вставляемого ключа: **Linear** — ваш, для того, что
делаете вы, и находится в **Настройки → Вы → Профиль**; **Автоматизация Linear** — это приложение Control Center рабочего
пространства, которое подключает администратор в карточке **Тикеты**, для синхронизации тикетов,
конвейеров и агентов. Кроме того, сервер может хранить **Сервисный ключ API**
(**Приложения провайдера**) для рабочих пространств без подключённой
автоматизации. В песочницу агента учётные данные тикетов не внедряются; агенты
пишут тикеты через инструменты Control Center, которые спрашивают правило
**Писать во внешний трекер**. См. [Настроить интеграцию Linear](/ru-RU/руководство/практические-руководства/интеграция-linear/).

## Смена и отзыв

- **Ваш вход в GitHub**: нажмите **Отключить**, затем снова **Войти в GitHub**.
  Отключение также отбрасывает все токены, которые сервер выпустил от вашего имени
- **Токен GitLab или Bitbucket**: нажмите **Обновить токен** и вставьте новый,
  затем отзовите старый на хосте кода
- **Приложение сервера**: создайте новый закрытый ключ или секрет клиента на
  странице приложения у провайдера, вставьте его в карточке **Приложения
  провайдера** и нажмите **Тест**
- **Ключ установки Connect**: владелец сервера нажимает **Сменить ключ** на
  карточке **Control Center Connect**. Все, кто входил через Connect, входят
  снова. Если сервер Connect недоступен, ничего не меняется и вам предлагается
  **Всё равно перевыпустить**. См.
  [Смена ключа установки](/ru-RU/руководство/справка/connect/#сменить-ключ-установки)
- **Провайдер моделей**: в его строке выйдите из системы (OAuth) или удалите ключ,
  затем подключите его снова
- **Slack**: для собственного приложения заново вставьте токены в диалоге
  подключения. У общего приложения Control Center нет токена для смены: его токен
  бота обновляется через Connect, а **Отключить** отзывает его и удаляет бота из
  Slack. См. [Настроить интеграцию Slack](/ru-RU/руководство/практические-руководства/интеграция-slack/)

## Устранение неполадок

### Токен GitLab или Bitbucket работает в `curl`, но не здесь

Проверьте строку **Хостинг кода**. Если там указано «Не подключено» или предлагается
подключиться снова, ваш токен не был сохранён или был отклонён. Для Bitbucket
введите адрес электронной почты вашего аккаунта Atlassian вместе с токеном API.

### Токен GitLab или Bitbucket принимается, но последующие запросы падают

Токен проверяется ровно в том виде, в каком он сохранён, поэтому строка называет
стоящую за ним учётную запись — но только учётную запись, а не области доступа.
Токен с недостаточными областями подключается, а затем падает на отдельных
запросах. Проверьте его области доступа и срок действия на хосте кода.

### Провайдер сообщает, что вход на этом сервере не настроен

У сервера нет ни собственного приложения для этого провайдера, ни Control Center
Connect. Владелец сервера выбирает один из вариантов в разделе **Настройки → Сервер
→ Единый вход**.
