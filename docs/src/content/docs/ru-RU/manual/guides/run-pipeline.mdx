Это руководство описывает запуск конвейера вручную. О том, как наблюдать за
запуском, читать вывод шагов и восстанавливаться после сбоя, см. в разделе
[Мониторить запуски конвейеров](/ru-RU/руководство/практические-руководства/мониторить-конвейеры/).

## Начать запуск

1. Нажмите **Конвейеры** на боковой панели рабочего пространства.
2. Нажмите **Запустить конвейер** в шапке. Откроется окно запуска
   (`/workspaces/<workspace-id>/pipelines/run`).
3. Выберите шаблон на панели слева. На каждой карточке указаны название
   шаблона, его описание и наличие входных данных.
4. Заполните форму входных данных справа. Обязательные поля блокируют кнопку,
   пока не заполнены; если у шаблона нет входных данных, он сообщает об этом.
5. Нажмите **Запустить конвейер**.

Откроется страница запуска, где в реальном времени отображаются хронология
этапов и холст графа.

## Если панель пуста

Окно запуска показывает шаблон, только когда верны **оба** условия:

- Переключатель шаблона включён в разделе **Настройки → Рабочее пространство
  → Шаблоны конвейеров**.
- В диалоге **Ручной запуск** редактора шаблона включён параметр **Разрешить
  ручной запуск** — именно этот переключатель создаёт триггер `manual`,
  который читает окно запуска.

Восемь из тринадцати встроенных шаблонов поставляются отключёнными:
`external_pr_welcome`, `cross_review`, `ticket_to_pr`, `pr_triage`,
`pre_merge_gate`, `release_notes`, `dep_audit` и `pr_digest`. Движок
отказывается запускать отключённый шаблон, поэтому включите его переключатель,
прежде чем искать его здесь.

В списке шаблонов нет действия **Запустить** для отдельного шаблона и нет
кнопки запуска внутри редактора — окно запуска остаётся единственной точкой
ручного входа.

## Заполнить входное поле «Репозиторий»

Входное поле типа **Репозиторий** отображает средство выбора по
зарегистрированным в рабочем пространстве репозиториям. При выборе репозитория
в полезную нагрузку запуска записываются `repo_id`, `repo_local_path`,
`repo_full_name`, а если у репозитория есть удалённый GitHub — ещё `repo_owner`
и `repo_name`, чтобы последующие шаги могли читать любое из них.

## Наблюдать за запуском

Страница запуска состоит из трёх частей: строка метаданных (время старта,
активная длительность, прогресс по шагам, баннер сбоя, **Повторить** и
**Удалить**), сворачиваемая хронология этапов с длительностью и стоимостью
каждого шага и холст графа. Выбор узла открывает панель с деталями этого шага.

[Мониторить запуски конвейеров](/ru-RU/руководство/практические-руководства/мониторить-конвейеры/)
описывает всё это, включая чтение приостановленного шага и что делать при сбое
шага.

Каждый запуск, начатый из приложения, — настоящий.
