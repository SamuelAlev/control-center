В этом руководстве показано, как работать с Control Center, не покидая GitHub:
запросить ИИ-проверку со страницы PR, задать боту вопрос в комментарии и
продолжить разговор в его ветках ревью.

Ответы приходят через канал GitHub рабочего пространства: собственный
[GitHub App](/ru-RU/руководство/практические-руководства/github-app/) вашего сервера
или общий App от Control Center через Connect. Ничего нового не регистрируется, и ничто не должно быть доступно из интернета:
сервер узнаёт о сказанном на GitHub путём опроса, поэтому ноутбук за NAT ведёт
себя точно так же, как публичное развёртывание.

## Предварительные требования

- У рабочего пространства есть канал GitHub: собственный GitHub App сервера или
  Connect, причём приложение [установлено](/ru-RU/руководство/практические-руководства/github-app/#установите-его-туда-где-лежат-ваши-репозитории)
  на аккаунте, которому принадлежит репозиторий. Собственному приложению нужны
  **Pull requests** и **Issues** на чтение и запись — **Создать моё приложение
  GitHub** уже выдаёт их
- Репозиторий привязан к рабочему пространству в Control Center
- Вы [вошли в GitHub](/ru-RU/руководство/практические-руководства/интеграция-github/) на
  этом сервере и можете делать push в репозиторий
- Ни URL вебхука, ни туннеля, ни callback — на стороне сети настраивать нечего

## Узнать имя бота

Упомяните `@usectrl` — отдельный аккаунт Control Center на GitHub. Это единственный вызов: упоминание собственного логина приложения ничего не делает. Канал GitHub вашего рабочего пространства по-прежнему обрабатывает запрос и публикует ответы. Учётные данные аккаунта `usectrl` вам не нужны.

## Запросить проверку из GitHub

Два способа, и оба запускают тот же предустановленный конвейер `pr_review`, что и
кнопка **Спросить AI**:

- **Добавьте метку `ai-review`** к PR. Это ближайший аналог назначения бота
  ревьюером из тех, что предлагает GitHub, — аккаунты приложений не могут занимать
  штатный слот запрошенного ревьюера. Ваш аккаунт ставит на PR реакцию 👀, и
  проверка запускается в Control Center; комментарий не публикуется
- **Напишите комментарий `@usectrl review`** (или просто `@usectrl`) в разговоре PR.
  На вашем комментарии появляется 👀, а затем ответ сообщает, что проверка
  запустилась (или что она уже идёт)

Ревьюеры работают в пространстве проверки этого PR; читайте и публикуйте замечания
так, как описано в разделе [Использовать ИИ-проверку](/ru-RU/руководство/практические-руководства/ии-проверка/).
Публикация обратно в GitHub остаётся решением, которое вы принимаете в Control
Center, — запуск проверки из GitHub сам по себе ничего в GitHub не публикует.

Метка срабатывает один раз на PR: её добавление и есть запрос, и она не взводится
заново при удалении и повторном добавлении. Чтобы запустить проверку снова —
скажем, после пуша, — упомяните бота.

## Задать вопрос

Оставьте комментарий в разговоре PR:

```text
@usectrl why does the flaky test in runner_test.dart fail on CI but not locally?
```

Что происходит, по порядку:

1. На вашем комментарии появляется 👀 от вашего собственного аккаунта, чтобы вы
   знали, что комментарий замечен
2. Вопрос публикуется в пространстве проверки этого PR **от вашего имени** — с тем
   же закреплением авторства, как если бы вы набрали его в Control Center
3. Агент отвечает в пространстве, и ответ публикуется обратно в PR. Каждый ответ
   начинается с `**Control Center** (for @your-login):`

Вопрос в PR, где проверка ещё не запускалась, будит CEO-агента рабочего
пространства; после запуска проверки отвечает агент, говоривший последним, поэтому
последующие вопросы попадают к тому, у кого есть контекст.

## Продолжить в ветке ревью

Ответьте внутри встроенной ветки ревью, в которой участвует бот, — комментария к
diff, который он оставил, или ответа, который он опубликовал в этой ветке.
Упоминание не нужно; сама ветка **и есть** адресация:

```text
> @usectrl the retry loop looks O(n²) to me

what would the complexity be with the bounded queue instead?
```

Многоходовый диалог работает так же: каждый ответ — это ещё один вопрос в том же
разговоре, где контекстом служит пространство проверки, и ответ возвращается в ту
же ветку.

Последующий вопрос в ленте разговора PR — это новый комментарий верхнего уровня,
поэтому ему всё ещё нужно @-упоминание.

## С кем разговаривает бот

Прежде чем что-либо делать, сервер сопоставляет автора комментария или того,
кто добавил метку `ai-review`:

- **В этот аккаунт GitHub должен быть выполнен вход** на этом сервере. Сопоставление идёт
  по числовому id аккаунта GitHub, а не по логину. Войдите в разделе **Настройки →
  Вы → Профиль → Хостинг кода**
- **Человек должен быть участником с ролью на запись** (`member`, `admin` или
  `owner`) в рабочем пространстве, к которому привязан репозиторий
- **Человек должен иметь право push** в репозиторий на GitHub. Ответы используют
  токен, ограниченный доступом этого человека, поэтому тот, кто может только
  читать, ответа не получает

Все остальные молча игнорируются: ничего не публикуется, и их слова никогда не
попадают в рабочее пространство. Комментарии ботов и собственные ответы Control
Center никогда не считаются вопросами.

### Два сервера, один PR

👀 — это ещё и способ, которым серверы договариваются, кто отвечает. Реакция
ставится собственным входом автора, и GitHub сообщает серверу, новая ли она. Если
вы вошли на двух серверах Control Center, которые оба привязали репозиторий,
отвечает тот, кто отреагировал первым, а другой молчит. То же верно и для метки.

## Чего ожидать

| Что                        | Поведение                                                                 |
| -------------------------- | ------------------------------------------------------------------------ |
| Подтверждение              | 👀 от вашего аккаунта на комментарии (или на PR, для метки) в течение одного обхода |
| Ответы                     | Публикуются в том же разговоре, где был задан вопрос, и начинаются с `**Control Center** (for @your-login):`. Автор — бот приложения. В общем приложении Connect ответ внутри ветки ревью пишется от вашего аккаунта, если только оператор Connect не добавил эту установку в список |
| Закрепление авторства в пространстве | Вопрос принадлежит вам; агент работает от вашего имени, согласно настройкам автономии пространства |
| Проверки                   | Замечания попадают в пространство проверки; публикация в GitHub выполняется вручную |

На собственном приложении обход выполняется каждую минуту и проверяет до 25 pull
request; через Connect — раз в две минуты и до 10, потому что эти вызовы
расходуют собственную квоту GitHub каждого участника. Рабочее пространство, у
которого осталось меньше 15 % квоты GitHub, пропускается, пока она не
восстановится. Задержка — это плата за то, что входящий сетевой доступ не нужен
вовсе. Ничего не теряется, пока сервер офлайн, — комментарий, пришедший во время
простоя, подхватывается на следующем обходе.

## Устранение неполадок

**На комментарий с упоминанием бота ничего не происходит.**

- Приложение **установлено** на аккаунте, которому принадлежит репозиторий, а сам
  репозиторий **привязан** к рабочему пространству? Непривязанный репозиторий
  пропускается до того, как что-либо будет записано, поэтому если привязать его
  позже, комментарий всё равно доставится
- Вы вошли в GitHub на этом сервере, являетесь участником с ролью на запись и
  можете делать push в репозиторий? Всех остальных сервер игнорирует без ответа
- Всё ещё ничего? При сбое журнал сервера называет обход и PR; ищите
  `pr_conversation:` (опросчик) и `github_pr_conversation:` (мост)

**Метка не запускает проверку.**

Она срабатывает один раз на PR, и тот, кто её добавил, проходит те же проверки,
что и автор комментария. Если проверка уже прошла или метка была добавлена до
того, как сервер впервые увидел PR (первый обход молча записывает накопившееся, а
не обрушивает это лавиной), вместо неё упомяните бота — `@usectrl review` всегда
запускает проверку, если только она уже не выполняется.

**Ответ бота так и не появился на GitHub.**

Сам ответ никогда не теряется — он находится в пространстве проверки этого PR в
Control Center. Сбой публикации (GitHub недоступен, разрешения изменились)
записывается в журнал, а ответ не повторяется; если это важно, спросите ещё раз в
ветке.
