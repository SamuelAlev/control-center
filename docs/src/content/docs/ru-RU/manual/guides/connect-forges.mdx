Control Center работает с тремя хостами кода, которые в приложении называются **forges**: **GitHub**, **GitLab** и **Bitbucket Cloud**. Ни один из них не используется по умолчанию. Подключите один — и всё работает; подключите несколько — и одно рабочее пространство сможет одновременно содержать репозитории всех трёх.

Хост кода — это свойство каждого **репозитория**: он считывается из его remote `origin` при регистрации. Вы никогда не выбираете его вручную, и здесь нет настройки уровня рабочего пространства, которую можно было бы задать неправильно.

## Подключить хост кода

1. Откройте **Настройки → Вы → Профиль** (`/settings/you/profile`).
2. Найдите карточку **Хостинг кода**. В ней перечислены все поддерживаемые хосты кода — подключённые и нет.
3. Для **GitHub** нажмите **Войти в GitHub**. Для **GitLab** или **Bitbucket** нажмите **Добавить токен** и вставьте токен.

**В GitHub можно только войти.** Вход проходит через собственный GitHub App сервера или через Control Center Connect — смотря что настроил владелец сервера, или через приложения, которые администратор рабочего пространства выбрал для этого рабочего пространства в **Настройки → Рабочее пространство → Интеграции** (см. [Настроить интеграцию GitHub](/ru-RU/руководство/практические-руководства/интеграция-github/)); вставлять токен GitHub не нужно. GitLab и Bitbucket по-прежнему принимают личный токен.

В любом случае учётные данные **принадлежат вам и хранятся на сервере** с привязкой к вашему идентификатору пользователя: токен не сохраняется на машине, в которую вы его ввели, все устройства, с которых вы входите, используют один и тот же токен, и ни один другой участник не может его прочитать. Он вступает в силу при **следующем запросе** — перезапускать ничего не нужно, а отключение немедленно прекращает его отправку.

На карточке видно, где используются ваши аккаунты. Токен GitLab или Bitbucket принадлежит вам **во всех рабочих пространствах сервера**, поэтому вставляйте его один раз. Ваш вход в GitHub тоже, если только рабочее пространство не использует собственные приложения входа: у такого рабочего пространства остаётся собственный вход в GitHub, и карточка называет его.

Каждая строка показывает состояние **ваших** учётных данных. Отвечают только ваши собственные учётные данные; ничто другое их не подменяет:

| Строка сообщает                                                | Значение                                                                                                                                         |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Вы вошли как octocat`                                         | Используются ваши собственные учётные данные |
| `Не подключено`                                                | У вас нет учётных данных для этого хоста кода                                                                                                    |
| `Ваш вход в GitHub как octocat истёк. Войдите снова.`          | Ваш вход истёк или был отозван на стороне хоста кода                                                                                             |
| `Приостановлено: служба входа этого рабочего пространства изменилась` | Это рабочее пространство перешло на другую службу входа. Ваш вход сохраняется и снова заработает, если рабочее пространство вернётся к прежней, поэтому кнопки входа нет |
| `Сейчас не удаётся связаться с GitHub. Повторяем попытку.`     | Временный сбой. Control Center продолжает повторять попытки; ничего делать не нужно                                                              |
| Фраза, объясняющая, почему вход недоступен                     | Например `Вход через GitHub не настроен для этого рабочего пространства.` или `Служба входа этого рабочего пространства сменила идентификацию. Администратор должен это подтвердить.` Администраторы получают кнопку перехода к настройке, которая это исправляет |

### Какой токен нужен каждому хосту кода

| Хост кода     | Токен                                                     | Где его создать                                           |
| ------------- | --------------------------------------------------------- | --------------------------------------------------------- |
| **GitLab**    | Персональный токен доступа с областью действия `api`      | gitlab.com → User settings → Access tokens                 |
| **Bitbucket** | Токен Atlassian API и адрес электронной почты вашего аккаунта | id.atlassian.com → Security → API tokens                   |

Bitbucket аутентифицируется, используя **адрес электронной почты аккаунта как имя пользователя** и токен API как пароль, поэтому диалог Bitbucket запрашивает оба значения. **Токен доступа** репозитория, проекта или рабочего пространства Bitbucket не принадлежит никому, поэтому этот диалог его отклоняет: вместо него нужен [токен автоматизации](#добавить-токен-автоматизации). То же относится к токену доступа проекта или группы GitLab: GitLab спрашивает, чей это токен, прежде чем его сохранить, а токен бота здесь отклоняется.

Токен никогда не привязан к одному рабочему пространству: у вас есть один токен на каждый хост кода, и его использует каждое рабочее пространство на сервере. **Отключить** удаляет его сразу для всех них.

### Фоновая работа

Работе, за которой не стоит человек (запуски агентов, конвейеры, опрос PR), тоже нужны учётные данные, и каждый хост кода решает это по-своему:

- **GitHub** — токен для одного репозитория за раз, выпущенный из GitHub App сервера или через Connect и ограниченный тем, что может делать там ответственный участник. Это никогда не вход человека, переданный целиком, и ни переменная окружения, ни вставленный токен его не заменяют. См. [Настроить интеграцию GitHub](/ru-RU/руководство/практические-руководства/интеграция-github/#от-чьего-имени-говорят-ваши-учётные-данные)
- **GitLab** и **Bitbucket** — только **токен автоматизации** репозитория: токен доступа бота, который администратор рабочего пространства добавляет для этого репозитория или для всех репозиториев этого хоста кода в рабочем пространстве. Собственный токен репозитория имеет приоритет над токеном рабочего пространства. Опрос PR, комментарии ИИ-ревью и push и merge request, которые никто не запрашивал, используют этот токен, поэтому на хосте кода они отображаются как этот бот, а не как участник. Личный токен участника их не заменяет, и токена уровня сервера или из переменной окружения не существует. Без него фоновая работа с репозиторием приостанавливается, и уведомление о доступе к репозиториям говорит об этом.

Работа, которую запрашивает участник (комментарий, ревью, merge request агента, открытый для него), по-прежнему использует токен самого участника.

## Добавить токен автоматизации

Только администраторы рабочего пространства видят или меняют токены автоматизации. Каждый проверяется у хоста кода при сохранении: отклоняется токен, который действует как человек (личный токен GitLab, токен API Atlassian или любой токен Bitbucket, который входит под чьим-то аккаунтом), а также токен, который не может читать свой репозиторий.

- **Для одного репозитория:** откройте **Настройки → Рабочее пространство → Репозитории**. Карточка **Токены автоматизации** перечисляет каждый репозиторий GitLab и Bitbucket вместе с ботом, который там действует: **Использует токен рабочего пространства** или **Токена нет. Автоматизация здесь приостановлена.** Нажмите **Добавить токен** в строке репозитория.
- **Для всех репозиториев хоста кода:** откройте **Настройки → Рабочее пространство → Интеграции**, найдите карточку **Токены автоматизации** и нажмите **Добавить токен** в строке GitLab или Bitbucket. Репозитории, которые токен не может прочитать, называются после сохранения и остаются приостановленными.

Если фоновая работа уже приостановлена, администраторы видят **Добавить токен** прямо в уведомлении о доступе к репозиториям. **Обновить токен** заменяет токен; кнопка корзины удаляет его, а любой репозиторий, оставшийся без токена, приостанавливается. Если хост кода позже отклонит сохранённый токен (отозван или истёк), его строка сообщит об этом, а покрывавшиеся им репозитории приостанавливаются до замены.

| Хост кода     | Токен автоматизации                                                                                                                                                                                | Где его создать                                                                                  |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **GitLab**    | **Токен доступа проекта** или **группы** с `read_api` и `read_repository`; добавьте `api` и `write_repository` для комментариев, merge request и push                                              | Проект или группа → Settings → Access tokens                                                     |
| **Bitbucket** | **Токен доступа** репозитория, проекта или рабочего пространства с чтением репозитория, а также с записью в pull request для комментариев и pull request (запись в репозиторий для push)           | Репозиторий, проект или рабочее пространство → Settings → Access tokens                          |

На GitLab работа отображается как пользователь-бот токена; на Bitbucket — под именем токена доступа.

### Bitbucket: токен доступа или токен API

Bitbucket имеет два типа токенов, и Control Center разделяет их:

- **Токен API** (id.atlassian.com) принадлежит вашему аккаунту Atlassian и используется вместе с вашим адресом электронной почты. Это **ваши** учётные данные, и он находится в разделе **Хостинг кода** в **Настройки → Вы → Профиль**.
- **Токен доступа** (создаётся в настройках репозитория, проекта или рабочего пространства) принадлежит этому репозиторию, проекту или рабочему пространству, а не человеку. Это **токен автоматизации**, и он находится в разделе **Токены автоматизации**.

Каждый диалог отклоняет другой тип и сообщает, куда он относится.

## На каждом хосте кода вы — другой человек

Один и тот же человек — `octocat` на GitHub и совсем кто-то другой на GitLab. Control Center определяет вашу идентичность **для каждого хоста кода** и использует подходящую для каждого репозитория — именно поэтому в смешанном рабочем пространстве корректно работают «нужно моё ревью», «создано мной» и «вы это одобрили».

Если идентичность для хоста кода не определена, его репозитории ничего не добавляют во «Входящие», а не совпадают со всем подряд. «Входящие» сообщают об этом, а не утверждают, что вы всё просмотрели.

## Вы видите только то, что видит ваш аккаунт

Pull request из репозитория попадает к вам, только если ваша роль в рабочем пространстве разрешает этот репозиторий **и ваш собственный аккаунт на этом хосте кода может его читать**. Администраторы и владелец рабочего пространства следуют тому же правилу. Когда часть репозиториев скрыта, «Входящие» и очередь PR сообщают, сколько их и почему, но не называют их:

- **Войдите в GitHub, чтобы видеть pull requests из других репозиториев: 3**: вы ещё не подключили этот хост кода здесь. Войдите — и они появятся
- **Скрыто репозиториев, которые не видит ваш аккаунт GitHub: 3**: попросите того, у кого есть доступ, на стороне хоста кода
- **Скрыто репозиториев, к которым у вас нет доступа в этом рабочем пространстве: 3**: попросите администратора рабочего пространства открыть доступ
- **Проверяем ваш доступ к другим репозиториям: 3…**: показывается ненадолго, пока Control Center подтверждает, что может читать ваш аккаунт

Код следует тому же правилу. Чтобы открыть файлы, диффы или поиск репозитория либо терминал на нём, нужен грант на этот репозиторий в этом рабочем пространстве, и ваш собственный аккаунт на хосте кода должен иметь право его читать; то же относится и к администраторам рабочего пространства, исключение — только владелец сервера. Если хост кода не удаётся проверить, вы видите «Не удалось подтвердить ваш доступ к forge. Попробуйте ещё раз.» (с названием хоста кода). См. [Код следует за forge](/ru-RU/руководство/понятия/авторизация/#код-следует-за-хостом-кода).

То же правило относится ко всему, что создаётся из этих pull request. Пространство ревью, его сообщения и запуски агентов пропадают, пока вы не видите pull request, а открытое пространство ревью закрывается, если вы теряете доступ. Запуски пайплайнов, связанные со скрытым pull request, исчезают из вашего списка запусков. Агенты, работающие для вас, тоже не могут читать эти пространства ревью. Список репозиториев рабочего пространства показывает все репозитории, к которым у вас есть доступ в этом рабочем пространстве, даже те, до которых ещё не дотягивается ваш аккаунт на хосте кода.

Если хост кода ограничивает частоту запросов или недоступен, Control Center ещё несколько минут показывает то, что подтвердил последним, а затем скрывает эти pull request до следующей проверки.

## Одни «Входящие» для всех хостов кода

«Входящие» и очередь PR расходятся по всем хостам кода, представленным в рабочем пространстве, и сливают результаты в один поток — pull request из GitHub и pull request из Bitbucket стоят рядом, упорядоченные по времени, а не сгруппированные по поставщику.

Сбои изолированы. Хост кода, который недоступен или ограничен по частоте запросов, не затрагивает остальные; его собственные репозитории продолжают показывать последнее известное состояние, пока он не восстановится, и никогда не опустошают «Входящие» целиком. Репозиторий, до которого сервер больше не может добраться, исчезает из списка вместо того, чтобы показывать устаревшие pull requests, а **уведомление о доступе к репозиториям** называет его вместе с исправлением: установить GitHub App в организации, добавить репозиторий в репозитории приложения, возобновить приостановленную установку или попросить ответственного участника войти снова, либо добавить токен автоматизации для репозитория GitLab или Bitbucket. Администраторы получают кнопку к шагам, связанным с GitHub App, и кнопку добавления токена.

## Что умеет каждый хост кода

Каждый хост кода поддерживает основной цикл: показывать список и открывать pull requests, читать диффы, комментировать построчно и на верхнем уровне, проводить ревью, мержить и закрывать. Помимо этого они действительно различаются, и Control Center скрывает то, чего хост кода не умеет, вместо того чтобы показывать элемент управления, который молча не сработает.

| Возможность                       | GitHub | GitLab | Bitbucket |
| --------------------------------- | :----: | :----: | :-------: |
| Пакетные (отложенные) ревью       |   ✓    |   ✓    |     —     |
| Запрос изменений                  |   ✓    |   ✓    |     ✓     |
| Синхронизация состояния «просмотрено» по файлам |   ✓    |   —    |     —     |
| Реакции эмодзи                    |   ✓    |   ✓    |     —     |
| Ревьюеры из команды или группы    |   ✓    |   ✓    |     —     |
| Предложенные рецензенты           |   ✓    |   —    |     ✓     |
| Результаты CI в PR                |   ✓    |   ✓    |     ✓     |
| Просмотр шагов и логов задачи CI  |   ✓    |   ✓    |     —     |
| Стек pull request                 |   ✓    |   —    |     —     |
| Шаблоны описания PR               |   ✓    |   ✓    |     —     |
| Опрос уведомлений                 |   ✓    |   —    |     —     |
| Подробные профили пользователей   |   ✓    |   ✓    |     —     |
| Серверная ссылка head для PR      |   ✓    |   ✓    |     —     |

Там, где возможности не хватает, функциональность честно деградирует:

- **Состояние просмотра** по-прежнему работает, но только на том устройстве, где вы его отметили.
- **Пакетные ревью** в Bitbucket публикуются комментарий за комментарием, поэтому ревьюеры видят, как они приходят по отдельности, а не все сразу.
- **Отсутствие ссылки head для PR** в Bitbucket означает, что при переключении на pull request его исходная ветка забирается по имени, а это перестаёт работать, как только ветка удалена.

## Терминология

GitLab называет pull request **merge request**. Control Center во всей своей модели говорит «pull request» и использует собственный термин каждого хоста кода там, где речь идёт именно о нём.

## Устранение неполадок

### Список PR пуст и сообщает, что хост кода не подключён

У вас нет учётных данных для этого хоста кода. Войдите в GitHub или вставьте токен GitLab или Bitbucket в разделе **Настройки → Вы → Профиль → Хостинг кода**. Репозитории других хостов кода не затрагиваются.

### Я подключил хост кода, но его репозитории по-прежнему ничего не показывают

Проверьте состояние строки, а затем уведомления над списком PR. «Войдите в … чтобы видеть pull requests из других … репозиториев» означает, что ваш аккаунт не подключён для этих репозиториев; «… скрыто, потому что ваш аккаунт … их не видит» означает, что хост кода не даёт вам доступа. Для GitHub уведомление о доступе к репозиториям сообщает, когда GitHub App не установлен на организации репозитория или не включает его.

### Фоновая работа с репозиторием GitLab или Bitbucket приостановлена

У репозитория нет токена автоматизации, который мог бы его читать. Администратор рабочего пространства добавляет токен для репозитория или для всего рабочего пространства; см. [Добавить токен автоматизации](#добавить-токен-автоматизации). Ваш личный токен не снимает паузу: фоновая работа никогда не использует токен участника.

### Репозиторий не регистрируется

Для регистрации нужны все три условия: путь находится внутри рабочего дерева git, у него есть remote `origin`, и этот remote указывает на github.com, gitlab.com или bitbucket.org. Сам `origin` также должен быть тем репозиторием, который вы подключаете, а папку вне собственного хранилища рабочего пространства может подключить только владелец сервера. См. [Добавить репозитории в рабочее пространство](/ru-RU/руководство/практические-руководства/добавить-репозитории/).

### У меня есть грант, но репозиторий сообщает, что мой аккаунт не может его читать

Ваш собственный аккаунт на хосте кода не может читать этот репозиторий, поэтому его код остаётся закрытым для вас, что бы ни давал грант рабочего пространства. Войдите в хост кода в разделе **Хостинг кода** выше или получите доступ к репозиторию на самом хосте кода.

### «Не удалось подтвердить ваш доступ к forge»

С хостом кода не удалось связаться для проверки вашего доступа, поэтому Control Center отказал, а не стал угадывать. Попробуйте ещё раз немного позже.

### Репозиторий сообщает, что теперь указывает на другой репозиторий

Репозиторий за этим путём изменился: его удалили и создали заново или переместили и заменили. Control Center ничего ему не отправляет, пока администратор рабочего пространства не нажмёт **Переподключить** в уведомлении или в строке репозитория. Простое переименование или передача отслеживаются автоматически и этого не показывают.

### После интенсивного использования всё на время перестаёт работать

Это автоматический выключатель при превышении лимита запросов. Когда хост кода сообщает о достижении основного лимита, клиент начинает локально отклонять дальнейшие запросы без сетевого обращения, пока окно не истечёт, — поэтому шквал повторных попыток не может усугубить лимит. Временные сбои повторяются с экспоненциальной задержкой.
