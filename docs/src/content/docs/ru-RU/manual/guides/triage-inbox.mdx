Это руководство показывает, как работать с входящими: единственной
поверхностью, которая собирает всё, что вас блокирует или явно запрашивает
вас, — ожидающие подтверждения агентов, неудачные синхронизации тикетов и
каждый pull request, где вы выступаете ревьюером или автором.

## Открыть входящие

1. Нажмите **Входящие** на боковой панели. Бейдж рядом считает ожидающие
   подтверждения агентов, неудачные синхронизации и открытые PR, ждущие
   вашего ревью.
2. Или нажмите <kbd>⌘K</kbd> и выполните команду навигации **Входящие**.
3. Или перейдите по прямой ссылке на `/workspaces/<workspace-id>/inbox`.

Элемент боковой панели всегда показывает актуальный счётчик, так что вы
видите, как накапливается работа по разбору, не открывая страницу.

## Оценить критичность с одного взгляда

Просматривайте сверху вниз: во входящих уже задан порядок по срочности:

1. Закреплённая полоса **Требует внимания** находится над разделами PR. На
   каждой карточке есть чип критичности. Зарегистрированные источники
   (агент, застрявший на запросе подтверждения, или синхронизация тикета,
   чьё зеркало у поставщика устарело) выдают **Заблокировано**.
2. Внутри полосы первой идёт самая высокая критичность; при равенстве выше
   то, что ждёт дольше всех.
3. Ниже полосы PR сгруппированы по фиксированным разделам жизненного цикла
   ревью — **Ждут вашего ревью**, **Возвращены вам**, **Одобрено**,
   **Черновики**, **Ожидают ревьюеров**, **Слияние и недавно слитые**,
   **Ожидают автора**. Верхние разделы — это то, что нужно _вам_; остальные
   показывают, как обстоят дела с _вашими_ PR. Раздел **Ждут вашего ревью**
   включает PR, которые всё ещё запрашивают команду, в которую вы входите, на
   тех хостах кода, где команды есть (GitHub убирает команду, как только
   кто-то из её участников провёл ревью).

Элемент попадает во входящие, только когда он что-то блокирует или явно
запрашивает вас. Пустая полоса вместе с пустым списком разделов показывают
**Вы всё просмотрели** только тогда, когда этой пустоте можно доверять.

## Одни «Входящие» для всех хостов кода

Если в рабочем пространстве есть репозитории на нескольких хостах кода,
входящие сливают их в один поток — pull request из GitHub и pull request из
Bitbucket стоят в одном разделе, упорядоченные по времени, а не
сгруппированные по поставщику. Различить их позволяет пометка
`repo #number` в строке.

«Ваше» определяется **для каждого хоста кода отдельно**, потому что на
каждом из них вы — другой аккаунт. Pull request считается вашим или
запрашивающим ваше ревью, только когда он совпадает с вашей идентичностью на
том хосте кода, где на самом деле лежит репозиторий.

Хост кода, который недоступен или не подключён, ничего не добавляет и
оставляет остальные входящие нетронутыми — одно сломанное подключение
никогда не опустошает весь список. Пустое состояние называет причину вместо
**Вы всё просмотрели**, когда идентичность ещё не определена ни на одном
хосте кода (**Не удалось подтвердить аккаунт GitHub** — текст всё равно
упоминает GitHub), когда githubstatus.com сообщает об инциденте или когда
установка GitHub App, покрывающая связанные репозитории, приостановлена.

## Разобрать полосу «Требует внимания»

У каждой карточки в полосе есть одно следующее действие:

1. Если карточка — это ожидающее подтверждение агента, нажмите **Ревью** —
   вы попадёте в пространство этого агента с его запросом на подтверждение.
   Одобрите или отклоните его там
   (см. [Общаться с агентом](/ru-RU/руководство/практические-руководства/общаться-с-агентом/)).
2. Если на карточке указано **Синхронизация не удалась** для какого-то
   поставщика, нажмите **Открытые** — вы попадёте в
   **Настройки → Рабочее пространство → Основные**, где карточка
   **Состояние синхронизации** показывает последнюю синхронизацию каждого
   подключения, серию сбоев подряд и последний результат. Во входящих
   появляется только последний сбой по каждому поставщику, поэтому
   восстановившаяся синхронизация убирает карточку.
3. Карточки исчезают сами, как только соответствующее состояние разрешается
   (агенту ответили, синхронизация восстановилась) — вручную закрывать
   нечего.

:::note[Это подтверждения в рамках хода, а не согласования управления]
Карточка «одобрение агента» — это работающий агент, который приостановился,
чтобы запросить разрешение на одно действие в своём разговоре. Это не то же
самое, что запись `Approval` системы управления, которую агенты создают с
помощью инструментов MCP для одобрения, — для неё нигде в приложении нет
человеческого экрана, и здесь она никогда не появляется.
:::

:::caution[Состояние синхронизации доступно только для чтения]
Карточка сообщает о подключениях синхронизации тикетов; помимо кнопки
**Синхронизировать** она не может создать, изменить или переподключить
подключение, и никакого другого экрана для этого тоже нет. Если подключение
не настроено, она просто пишет «Подключений синхронизации пока нет» — именно
это показывает новое рабочее пространство.
:::

## Отфильтровать то, что блокирует

1. Нажмите <kbd>f</kbd> (когда ни одно текстовое поле не в фокусе), чтобы
   открыть меню фильтров, или нажмите кнопку фильтра на панели инструментов.
2. Выберите любое сочетание статуса, автора, ревьюеров, содержимого,
   владельца/имени репозитория, временных окон или «Быстрое ревью».
   Счётчики фасетов в меню показывают, скольким элементам входящих
   соответствует каждый вариант.
3. Активные фильтры отображаются как чипы на панели над списком; нажмите ✕
   на чипе, чтобы убрать это условие.
4. Используйте левую панель, чтобы переходить между разделами — у каждого
   пункта показан актуальный счётчик, а подсветка следует за позицией
   прокрутки. Нажмите заголовок раздела, чтобы свернуть разделы, которые вы
   не разбираете (например, **Черновики**, пока разбираете ревью).
5. Нажмите заголовок столбца (название, изменения или обновлено), чтобы
   отсортировать все разделы; нажмите по активному столбцу ещё раз, чтобы
   сменить направление. Кнопка параметров отображения управляет видимостью
   черновиков, окном недавно слитых, свойствами строк, порядком и
   группировкой (на раскладку входящих влияет только группировка по автору).

Фильтры здесь не зависят от очереди PR — сужение входящих никогда не меняет
фильтры очереди, и наоборот.

## Действия с элементом PR

1. Нажмите любую строку, чтобы открыть страницу сведений о PR.
2. Если PR находится в разделе **Ждут вашего ревью**, проведите ревью и
   отправьте своё решение — см.
   [Проверить и смержить PR](/ru-RU/руководство/практические-руководства/проверить-и-смержить-pr/).
3. Если PR находится в разделе **Возвращены вам** (запрошены изменения или
   CI упал), отправьте исправления из своей рабочей копии или передайте
   доработку агенту.
4. Если PR в разделе **Одобрено**, смержите его со страницы сведений.
5. Если вы предпочитаете делегировать ревью, а не делать его самим, см.
   [Запускать агентов-ревьюеров](/ru-RU/руководство/практические-руководства/запускать-ревьюеров/)
   и [жизненный цикл запуска](/ru-RU/руководство/понятия/жизненный-цикл-запуска/).

Как только соответствующее состояние меняется (ваше ревью отправлено, PR
смержен), классификатор автоматически переносит PR в его новый раздел.

## Отменить ошибочное действие

1. Нажмите <kbd>⌘Z</kbd>, чтобы отменить последнее действие, и
   <kbd>⌘⇧Z</kbd>, чтобы вернуть его.
2. Если в фокусе текстовое поле, ⌘Z вместо этого меняет текст в поле —
   сначала кликните вне поля, чтобы отменить действие уровня приложения.

## Посмотреть горячие клавиши на месте

Нажмите <kbd>?</kbd> (когда ни одно текстовое поле не в фокусе), чтобы
открыть шпаргалку по клавиатуре. В ней перечислены все привязки, действующие
на текущем маршруте, включая сочетание <kbd>f</kbd> для фильтра во входящих.
Полная карта — в
[справочнике горячих клавиш](/ru-RU/руководство/справка/горячие-клавиши/).

## Управлять из палитры команд

1. Нажмите <kbd>⌘K</kbd> в любом месте, чтобы открыть палитру команд.
2. Введите **Входящие**, чтобы перейти на страницу, или введите название
   PR — палитра покажет подходящие pull request и откроет выбранный.
3. Пока входящие открыты, выполните команду **Скопировать ссылку на эту
   страницу**, чтобы скопировать этот URL для отправки. Команда копирует
   текущий маршрут, поэтому URL входящих она вернёт, только пока вы на этой
   странице.

## Обновлять по требованию

Входящие обновляются в реальном времени, но если вы подозреваете
устаревшие данные, нажмите элемент обновления на панели инструментов — он
запускает немедленный обход на стороне сервера по каждому подключённому
хосту кода и заново запрашивает оверлеи «слито» и «проверено». Значок
вращается, пока не завершатся все запросы.
