Control Center Connect выполняет входы в провайдеры (GitHub, Google Calendar,
Linear, Slack) для серверов, которые не зарегистрировали собственных приложений.
Это руководство показывает, как запустить собственный Connect, чтобы приложения
провайдеров, их секреты и список серверов, которым разрешено ими пользоваться,
оставались у вас.

Что Connect может и чего не может видеть, описано в
[справке по Connect](/ru-RU/руководство/справка/connect/). Прочитайте её сначала,
если решаете, запускать ли свой.

:::note[Возможно, он вам не нужен]
Один сервер может вместо этого зарегистрировать собственные приложения: **Настройки
→ Сервер → Единый вход → Приложения провайдера**, где **Создать моё приложение
GitHub** настраивает GitHub за один шаг. Собственные приложения сервера применяются только при **Использовать свои приложения**: с Control Center Connect или собственным Connect Connect обслуживает все каналы, а приложение рабочего пространства по-прежнему действует. Запускайте Connect, когда несколько
серверов должны пользоваться одним набором приложений.
:::

## Предварительные требования

- Публичный адрес **HTTPS** для Connect, например `https://connect.example.com`,
  за прокси, терминирующим TLS. Обычный `http` принимается только на loopback
- Docker или `cc_server`, который можно перезапустить с дополнительными
  переменными окружения
- Право регистрировать приложения у каждого провайдера, которого вы хотите
  обслуживать
- Серверы, которые будут им пользоваться, и их владельцы под рукой: у каждого
  сервера есть идентификатор установки, который вы добавляете в список
  разрешённых Connect

## Шаг 1: Выберите адрес

Выберите URL сейчас и больше его не меняйте. `CONNECT_PUBLIC_URL` входит во всё,
что делает Connect: к нему привязаны подписи запросов, запечатанные учётные
данные, URL перенаправления провайдеров и идентификатор установки каждого
сервера. Изменить его позже — значит заново зарегистрировать перенаправления и
заставить каждого человека войти снова.

## Шаг 2: Зарегистрируйте приложения провайдеров

Регистрируйте только тех провайдеров, которых хотите обслуживать. Провайдер с
неполным набором переменных исключается из конфигурации Connect, и серверы видят
его недоступным. Ниже `<base>` — это ваш `CONNECT_PUBLIC_URL`.

| Провайдер      | Что зарегистрировать                                                                                                                                                                                                                                                  | Что сохранить                           |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| **GitHub App** | Callback URL `<base>/oauth/github/callback`. Setup URL `<base>/oauth/github/setup` с включённым **Redirect on update**. Оставьте **Request user authorization (OAuth) during installation** выключенным: если он включён, GitHub игнорирует setup URL. Оставьте **Expire user authorization tokens** включённым | Id приложения, slug, id клиента, секрет клиента |
| **Google**     | Клиент OAuth типа **Web application** с URI перенаправления `<base>/oauth/google/callback` и включённый Google Calendar API                                                                                                                                        | Id клиента, секрет клиента              |
| **Linear**     | Приложение OAuth с URL обратного вызова `<base>/oauth/linear/callback` и `<base>/oauth/linear_app/callback`                                                                                                                                                       | Только id клиента                       |
| **Slack**      | Redirect URLs `<base>/oauth/slack_oidc/callback` и `<base>/oauth/slack/callback`. Event Subscriptions по адресу `<base>/v1/hooks/slack/events` (`app_mention`, `message.*`, `assistant_thread_*`, `app_uninstalled`, `tokens_revoked`). Slash-команды по адресу `<base>/v1/hooks/slack/commands`. Ротация токенов включена | Id приложения, id клиента, секрет клиента, секрет подписи |

Дайте GitHub App следующие разрешения на репозиторий: **Metadata** — чтение,
**Contents** — чтение и запись, **Pull requests** — чтение и запись, **Issues** —
чтение и запись, **Checks**, **Actions** и **Commit statuses** — чтение. Для
запросов ревью от команд добавьте разрешение организации **Members** на чтение.
Вебхуки можно оставить выключенными: серверы опрашивают.

Connect никогда не нужен закрытый ключ GitHub App. Вместо этого он выпускает
токены для одного репозитория из собственного входа человека. Linear тоже не
нужен секрет: Connect возвращает код серверу, который сам завершает обмен.

## Шаг 3: Соберите идентификаторы установки

Connect отвечает только серверам из своего списка разрешённых. На каждом сервере
направьте его на свой Connect, а затем прочитайте его идентификатор установки:

1. Откройте **Настройки → Сервер → Единый вход**, откройте карточку **Control
   Center Connect** и выберите **Использовать свой сервер Connect**
2. Введите свой URL и сохраните. Карточка покажет **Идентификатор установки**
   сервера

Из терминала на хосте сервера то же самое выглядит так:

```bash
cc_server connect enable --url https://connect.example.com
cc_server connect status
```

`status` печатает идентификатор установки. Пока не выполнен шаг 5, он показывает
`install_blocked`, и это ожидаемо.

Идентификатор установки выводится для каждого адреса Connect отдельно, поэтому у
одного и того же сервера для каждого Connect, с которым он общается, свой
идентификатор. Он меняется только тогда, когда владелец сервера меняет ключ.

## Шаг 4: Создайте ключ печати

Connect шифрует все учётные данные, которые возвращает, ключом печати. Создайте
его и храните как файл с секретом:

```bash
docker run --rm ghcr.io/samuelalev/cc-connect:latest \
  cc-connect-config seal-key > seal_keys
chmod 600 seal_keys
```

Потеря ключа печати выводит всех из системы: без него ни одну печать не открыть.

## Шаг 5: Запустите контейнер

Каждый выпуск публикует `ghcr.io/samuelalev/cc-connect` с подтверждением
происхождения сборки. В продакшене закрепляйте тег версии.

```bash
docker run -d --name cc-connect -p 8790:8790 \
  -e CONNECT_PUBLIC_URL=https://connect.example.com \
  -e CONNECT_ALLOWED_INSTALLS=<install id>,<install id> \
  -e CONNECT_SEAL_KEYS_FILE=/run/secrets/seal_keys \
  -v "$PWD/seal_keys:/run/secrets/seal_keys:ro" \
  -e CONNECT_GITHUB_APP_ID=123456 \
  -e CONNECT_GITHUB_APP_SLUG=acme-control-center \
  -e CONNECT_GITHUB_CLIENT_ID=Iv23li0123456789abcd \
  -e CONNECT_GITHUB_CLIENT_SECRET_FILE=/run/secrets/github \
  -v "$PWD/github_secret:/run/secrets/github:ro" \
  -v cc-connect-data:/data \
  ghcr.io/samuelalev/cc-connect:latest
```

Направьте обратный прокси на порт `8790`. Образ работает от непривилегированного
пользователя, хранит своё состояние в томе `/data` и имеет встроенную проверку
работоспособности (`cc-connect --healthcheck`, которая опрашивает `/healthz`).

Connect отказывается запускаться (код выхода `78`), если его конфигурация открыта,
небезопасна или не доделана, и печатает, какая переменная неверна. Его
останавливают отсутствующий список разрешённых, адрес `http` не на loopback,
некорректный ключ печати или одновременно заданные `NAME` и `NAME_FILE`.

Проверка: на каждом сервере карточка Connect показывает **Работает**, а **Где
выполняется каждый вход** называет **Connect** для каждого зарегистрированного вами
провайдера. `cc_server connect status` печатает `Health: ok` и те же каналы.

## Смонтировать Connect внутри cc_server

Сервер может сам размещать Connect вместо отдельного контейнера. Смонтированный
сервис — тот же самый, что запускает образ.

1. Поместите переменные `CONNECT_*` в файл `.env` сервера (или в его окружение),
   как на шаге 5
2. Добавьте `CC_SERVER_CONNECT_HOST=on`
3. Перезапустите сервер. Его журнал напечатает `embedded Connect at <url>`

```bash
CC_SERVER_CONNECT_HOST=on
CONNECT_ALLOWED_INSTALLS=<install id>
CONNECT_SEAL_KEYS=<output of cc-connect-config seal-key>
CONNECT_GITHUB_APP_ID=123456
CONNECT_GITHUB_APP_SLUG=acme-control-center
CONNECT_GITHUB_CLIENT_ID=Iv23li0123456789abcd
CONNECT_GITHUB_CLIENT_SECRET=<secret>
```

После этого Connect обслуживается по адресу `<server>/connect`:

- `CONNECT_PUBLIC_URL` по умолчанию — источник публичного URL сервера плюс
  `/connect`. За прокси задайте его явно. Его путь должен быть ровно `/connect`, и
  он должен быть HTTPS, если это не loopback
- До смонтированного сервиса доходят только переменные `CONNECT_*`, поэтому он
  никогда не заимствует собственные приложения провайдеров сервера
- `CONNECT_ALLOWED_INSTALLS` по-прежнему обязателен, в том числе для самого
  размещающего сервера
- Неправильно настроенное монтирование не даёт серверу загрузиться, а не
  обслуживает открытого брокера
- Демонстрационный сервер его никогда не монтирует

Зарегистрируйте перенаправления провайдеров на `https://<server>/connect`, затем
направьте серверы (включая размещающий) на этот URL, как на шаге 3.

## Справочник по конфигурации

Каждая настройка — это переменная окружения. Любой секрет можно вместо этого брать
из смонтированного файла: задайте `NAME_FILE` вместо `NAME`. Connect перечитывает
файл не чаще чем раз в 30 секунд и сохраняет последнее корректное значение.
Секреты с пометкой **двойной** во время смены также принимают `NAME_PREVIOUS` (или
`NAME_PREVIOUS_FILE`).

### Адрес и доступ

| Переменная                      | По умолчанию | Значение                                                                                                                       |
| ------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `CONNECT_PUBLIC_URL`            | обязательна  | Канонический публичный URL. HTTPS или `http` только на loopback. Путь означает монтирование. Без query и фрагмента             |
| `CONNECT_ALLOWED_INSTALLS`      | обязательна  | Идентификаторы установки через запятую. `*` принимается только вместе с `CONNECT_SIGNED_CONFIG_FILE`                           |
| `CONNECT_DENY_INSTALLS`         |              | Идентификаторы установки, которым отказывают, даже если они разрешены                                                          |
| `CONNECT_GITHUB_ALLOWED_OWNERS` |              | Числовые id владельцев GitHub. Если задано, токены репозиториев выпускаются только для принадлежащих им репозиториев           |
| `CONNECT_HOST`, `CONNECT_PORT`  | `0.0.0.0`, `8790` | Адрес привязки и порт                                                                                                     |
| `CONNECT_TRUST_PROXY`           | `0`          | Доверенные переходы прокси в `X-Forwarded-For` (от 0 до 8). Используется только для лимита запросов на адрес                   |

### Каналы провайдеров

| Переменная                                                                  | По умолчанию | Значение                                                                     |
| --------------------------------------------------------------------------- | ------------ | ---------------------------------------------------------------------------- |
| `CONNECT_GITHUB_APP_ID`, `CONNECT_GITHUB_APP_SLUG`, `CONNECT_GITHUB_CLIENT_ID` |           | GitHub App                                                                   |
| `CONNECT_GITHUB_CLIENT_SECRET`                                              |              | Секрет, двойной                                                              |
| `CONNECT_GOOGLE_CLIENT_ID`, `CONNECT_GOOGLE_CLIENT_SECRET`                  |              | Клиент Google. Секрет двойной                                                |
| `CONNECT_LINEAR_CLIENT_ID`                                                  |              | Приложение Linear. Без секрета                                               |
| `CONNECT_SLACK_APP_ID`, `CONNECT_SLACK_CLIENT_ID`                           |              | Приложение Slack                                                             |
| `CONNECT_SLACK_CLIENT_SECRET`, `CONNECT_SLACK_SIGNING_SECRET`               |              | Секреты, двойные                                                             |
| `CONNECT_KLIPY_APP_KEY`                                                     |              | Ключ поиска GIF Klipy. Секрет, двойной                                       |
| `CONNECT_KLIPY_MODE`                                                        | `proxy`      | `proxy` оставляет ключ в Connect; `key` передаёт его серверам                |
| `CONNECT_<LANE>_SECRET_GENERATION`                                          | `1`          | GitHub, Google и Slack: поколение, записываемое в новые печати               |
| `CONNECT_<LANE>_MIN_SEAL_GENERATION`                                        | `1`          | GitHub, Google и Slack: для более старых печатей нужно войти снова           |
| `CONNECT_<LANE>_ACCEPTS_NEW`                                                | `true`       | Любой канал: `false` останавливает новые входы, а существующие продолжают обновляться |

### Печати, состояние и хранилище

| Переменная                                                | По умолчанию               | Значение                                                                                                   |
| --------------------------------------------------------- | -------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `CONNECT_SEAL_BACKEND`                                    | `local`                    | `local` или `gcp-kms`                                                                                      |
| `CONNECT_SEAL_KEYS`                                       |                            | Секрет, обязателен для `local`. Записи `kid:key` через запятую, самая новая первой; старые записи по-прежнему расшифровывают |
| `CONNECT_KMS_KEY`                                         |                            | `projects/…/locations/…/keyRings/…/cryptoKeys/…`, обязателен для `gcp-kms`                                 |
| `CONNECT_STATE`                                           | `memory`                   | `memory` для одного экземпляра, `redis` для нескольких                                                     |
| `CONNECT_REDIS_URL`                                       |                            | Секрет. `redis://` или `rediss://`                                                                         |
| `CONNECT_REDIS_CA_FILE`                                   |                            | Пакет CA для `rediss://`                                                                                   |
| `CONNECT_BINDINGS`                                        | `file`                     | Где хранятся привязки установок GitHub: `file` или `firestore`                                             |
| `CONNECT_DATA_DIR`                                        | `data` (`/data` в образе)  | Содержит `bindings.json`                                                                                   |
| `CONNECT_FIRESTORE_PROJECT`, `CONNECT_FIRESTORE_DATABASE` | база данных `(default)`    | Для `CONNECT_BINDINGS=firestore`                                                                           |

### Конфигурация, журналы и лимиты

| Переменная                              | По умолчанию         | Значение                                                                                            |
| --------------------------------------- | -------------------- | --------------------------------------------------------------------------------------------------- |
| `CONNECT_SIGNED_CONFIG_FILE`            |                      | Конфигурация, подписанная офлайн, отдаётся как есть. Используется размещённым Connect от Control Center |
| `CONNECT_CONFIG_PUBLIC_KEYS`            |                      | Ключи, по которым должна проверяться подписанная конфигурация                                       |
| `CONNECT_CONFIG_EPOCH`                  | `1`                  | Эпоха конфигурации, которую генерирует самостоятельно размещённый Connect                           |
| `CONNECT_LOG_HMAC_KEY`                  | случайный для каждого процесса | Секрет. Задайте его, чтобы метки, заменяющие идентификаторы установки, оставались стабильными между перезапусками и экземплярами |
| `CONNECT_VERSION`, `CONNECT_IMAGE_DIGEST` |                    | Сообщаются через `/v1/version`                                                                      |
| `CONNECT_RATE_INSTALL_PER_MINUTE`       | `600`                | Запросов на установку                                                                               |
| `CONNECT_RATE_IP_PER_MINUTE`            | `300`                | Запросов на адрес                                                                                   |
| `CONNECT_RATE_GLOBAL_PER_SECOND`        | `500`                | Запросов на весь сервис                                                                             |
| `CONNECT_RATE_SLACK_TEAM_PER_MINUTE`    | `600`                | Событий Slack на команду                                                                            |
| `CONNECT_RATE_KLIPY_PER_MINUTE`         | `120`                | Поисков GIF на установку                                                                            |

## Запустить несколько экземпляров

Для большинства организаций достаточно одного экземпляра с `CONNECT_STATE=memory`.
Нескольким экземплярам за одним адресом нужен `CONNECT_STATE=redis` и либо общий
`CONNECT_DATA_DIR`, либо `CONNECT_BINDINGS=firestore`, чтобы вход, начатый на одном
экземпляре, мог завершиться на другом.

## Сменить секрет провайдера

Никто не выходит из системы:

1. Создайте новый секрет у провайдера и сохраните старый
2. Перенесите старое значение в `NAME_PREVIOUS`, поместите новое в `NAME` и
   увеличьте `CONNECT_<LANE>_SECRET_GENERATION`. Смонтированные файлы
   подхватываются в течение 30 секунд
3. Дождитесь обновления входов, затем удалите старый секрет у провайдера и уберите
   `NAME_PREVIOUS`

Чтобы сменить ключ печати, поставьте новую запись `cc-connect-config seal-key`
первой в `CONNECT_SEAL_KEYS` и сохраните старую, пока её печати не обновятся.

## Заменить приложение

Серверы запоминают id приложения и клиента, которые ваш Connect объявил, когда они
впервые им воспользовались. Если вы замените приложение, карточка Connect на
каждом сервере покажет **Приложения Connect изменились**, и входы через Connect
приостановятся, пока владелец сервера не нажмёт **Доверять новым приложениям**.
Предупредите владельцев серверов перед переключением, чтобы они знали, что это
запрос от вас.

## Заблокировать сервер

Добавьте его идентификатор установки в `CONNECT_DENY_INSTALLS` и перезапустите.
Его владелец увидит «Connect заблокировал идентификатор установки этого сервера», и
все входы через Connect на нём остановятся.

## Устранение неполадок

### Сервер сообщает, что Connect его заблокировал

Его идентификатора установки нет в `CONNECT_ALLOWED_INSTALLS`, или он есть в
`CONNECT_DENY_INSTALLS`. Идентификатор меняется, когда владелец сервера меняет
ключ; попросите новый.

### Провайдер показан как недоступный

Не хватает одной из его переменных, поэтому Connect исключил канал. Проверьте
журнал запуска и таблицы выше. GitHub нужны все четыре значения: id приложения,
slug, id клиента и секрет клиента; Google нужны и id клиента, и секрет.

### Входы завершаются ошибкой несовпадения перенаправления

Перенаправление, зарегистрированное у провайдера, не совпадает в точности с
`CONNECT_PUBLIC_URL`. Сравните схему, хост, порт и путь `/connect` для
смонтированного Connect.

### Всем пришлось войти снова

Ключ печати изменился или потерян, сервер сменил свой ключ или данные сервера
восстановили на другой машине. Запечатанные учётные данные открываются только для
той установки и того Connect, которые их создали.
