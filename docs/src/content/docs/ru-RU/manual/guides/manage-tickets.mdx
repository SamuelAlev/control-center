Это руководство показывает, как создавать тикеты и управлять ими.

## Создать тикет

### Из интерфейса

1. Нажмите **Тикеты** в боковой панели рабочего пространства.
2. Нажмите **Новый тикет**.
3. Заполните:
   - **Название** — краткое описание. Это единственное обязательное поле.
   - **Описание** — markdown, с панелью форматирования.
   - **Статус** — **К выполнению** (по умолчанию) или **Бэклог**. Начатые и
     терминальные состояния достигаются через жизненный цикл, а не при
     создании.
   - **Приоритет** — нет, срочный, высокий, средний или низкий.
   - **Исполнитель** — вы сами или любой агент в рабочем пространстве.
   - **Проект** — необязательная группировка.
4. Нажмите **Создать** или сначала включите **Создать ещё**, чтобы диалог
   остался открытым для быстрого ввода.

В диалоге нет выбора провайдера. Тикет создаётся в активном провайдере тикетов
рабочего пространства.

### Через агента

Попросите агента в пространстве:

> Создай тикет на исправление проблемы с тайм-аутом входа при медленном
> соединении.

Он вызывает инструмент MCP `create_ticket`. Приоритет в этом инструменте —
**целое число**, а не название:

```
create_ticket(
  workspace_id: "...",
  title: "Fix login timeout on slow connections",
  description: "...",
  priority: 2
)
```

| Значение | Приоритет |
| -------- | --------- |
| `0`   | Нет     |
| `1`   | Срочный   |
| `2`   | Высокий   |
| `3`   | Средний   |
| `4`   | Низкий      |

Обязательны только `workspace_id` и `title`; `description`, `priority`,
`assignee` (идентификатор агента) и `team_id` необязательны. Инструмент
отнесён к классу записи синхронизации с вендором и запрашивает ваше
подтверждение перед запуском.

## Изменить статус тикета

Тикеты проходят такой жизненный цикл:

```
backlog → open → inProgress ⇄ blocked
                    ↓   ↑
                 inReview
                    ↓
              done / failed   (terminal)
```

`done`, `failed` и `cancelled` — терминальные. `cancelled` достижим из любого
нетерминального статуса. `done` и `failed` достижимы из `inProgress` или
`inReview`; `open` также может перейти напрямую в `blocked`. Селектор статуса
в интерфейсе перечисляет все статусы, кроме `failed`, — агенты ставят его
через `fail_ticket`.

Чтобы изменить статус, используйте любой из способов:

- строку **Статус** в панели свойств тикета,
- подменю **Статус** в контекстном меню тикета в списке,
- чип **Статус** на плавающей панели после выбора нескольких тикетов.

:::note[Граф жизненного цикла обязателен для агентов, а не для вас]
Любое изменение статуса из интерфейса применяется принудительно и полностью
обходит граф — вы можете перевести тикет в любой статус из списка селектора, в
том числе открыть заново `done`, `failed` или `cancelled`. Селектор не
предлагает `failed` как целевой статус. Диаграмма выше управляет агентами и
автоматизацией: недопустимый переход, предпринятый инструментом MCP или
реконсилером, логируется и игнорируется, а не применяется.
:::

Изменения статуса порождают доменные события (`TicketStatusChanged`,
`TicketCompleted` и другие), которые могут запускать конвейеры. См.
[Настроить триггеры конвейера](/ru-RU/руководство/практические-руководства/триггеры-конвейера/).

## Назначить тикет

1. Откройте тикет.
2. В панели свойств задайте **Исполнитель** — себя, другого участника рабочего
   пространства или агента.

:::caution[Назначение не запускает никакой работы]
Назначение фиксирует владение и ничего больше. Оно не создаёт пространство, не
меняет статус и не запускает агента — `TicketAssigned` — это чистый сигнал
аудита, за которым нет диспетчера. Чтобы агент начал работу, напишите ему в
пространстве (см. [Общаться с агентом](/ru-RU/руководство/практические-руководства/общаться-с-агентом/)).

Единственное исключение: `TicketAssigned` — это тип события, к которому можно
привязать триггер конвейера, поэтому ваш собственный шаблон может реагировать
на назначение.
:::

## Добавить метки

Метки ставятся массово из списка тикетов, а не из отдельного тикета — в панели
свойств нет элемента управления для меток.

1. Наведите курсор на строку в списке тикетов и отметьте её флажок. Отметьте
   столько, сколько нужно; как только что-то выбрано, появляется плавающая
   панель.
2. На этой панели откройте чип **Метки**.
3. Выберите метку. Она добавляется ко всем выбранным тикетам, у которых её
   нет; существующие метки никогда не стираются. **Очистить метки** удаляет их
   все. Селектор перечисляет метки, которые уже есть на тикетах рабочего
   пространства. Агенты могут добавить новое имя через `update_ticket` или
   `tickets.patch`.

## Связать тикеты

Связи находятся на карточке **Связи** в панели свойств тикета или за пунктом
**Связать с** в контекстном меню списка.

1. Откройте тикет и найдите карточку **Связи**.
2. Нажмите её элемент добавления и выберите связь:

| Связь             | Значение                                |
| ----------------- | --------------------------------------- |
| **Подтикет для…** | Родитель этого тикета — другой          |
| **Родитель для…** | Другой тикет — дочерний для этого       |
| **Блокируется…**  | Этот тикет блокируется другим           |
| **Блокирует…**    | Этот тикет блокирует другой             |
| **Связано с…**    | Симметрично, направление не подразумевается |
| **Дубликат…**     | Этот тикет дублирует другой             |

3. Выберите целевой тикет.

**Дублируется** отображается в карточке, но отсутствует в селекторе — это
обратная сторона **Дубликат…**, и она задаётся со стороны другого тикета.
Каждую из перечисленных связей можно нажать, чтобы открыть связанный тикет, и
удалить при наведении.

Связи «родитель — подтикет» хранятся в самом тикете, а не как строки связей,
поэтому удаление родителя каскадно удаляет его дочерние тикеты (см. ниже), а
блокирующие и связанные ссылки — нет.

## Добавить соисполнителей

Соисполнители — это список на тикете: кто в нём задействован и в каком
качестве.

1. Откройте тикет.
2. Нажмите элемент с человечком и плюсом на карточке **Добавить участника**.
3. Выберите агента.

Есть три роли: **исполнитель**, **соисполнитель** (по умолчанию) и
**ревьюер**. Селектор в интерфейсе перечисляет только агентов рабочего
пространства и всегда записывает роль по умолчанию; люди могут отображаться
как строки, но в этом меню не предлагаются. Инструмент MCP
`add_ticket_collaborator` принимает `role`.

Добавление соисполнителя записывает строку и не публикует доменное событие;
оно не даёт доступа к пространству. Чтобы ввести агента в разговор, добавьте
его как участника из заголовка пространства — см.
[Использовать пространства](/ru-RU/руководство/практические-руководства/пространства/).

## Удалить тикет

Используйте **Удалить тикет** внизу панели свойств, в контекстном меню или
действие удаления на плавающей панели после выбора нескольких тикетов.

:::caution[Удаление происходит только локально]
Тикет, пришедший из внешнего трекера, там не удаляется — ни один провайдер это
не поддерживает, — поэтому он может появиться снова при следующей
синхронизации. Удаление также каскадно: вместе с тикетом удаляются его
соисполнители и все дочерние тикеты.
:::
