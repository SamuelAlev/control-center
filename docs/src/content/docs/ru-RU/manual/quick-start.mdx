Это самый короткий полный путь от нуля до агента, работающего с вашим собственным кодом. Проходите его по порядку: каждый шаг зависит от предыдущего.

Вам понадобятся Git, аккаунт GitHub и либо аккаунт у провайдера моделей (Anthropic, OpenAI, Codex, Cursor, Kimi Code или любого провайдера с API-ключом), либо уже установленный CLI Claude Code. Всё остальное настраивается по ходу.

## Шаг 1. Установка и запуск

Установите Control Center, как описано в разделе [Установка](/ru-RU/руководство/установка/), затем откройте его.

При первом запуске настольное приложение спрашивает: **«Как запускать Control Center?»** Выберите **Запустить в этом приложении**. Control Center порождает headless-процесс `cc_server` на этой машине: он хранит ваши данные и выполняет всю работу. Вы его никогда не видите — вместо него открывается экран онбординга.

:::note[Не хотите ничего устанавливать?]
То же приложение работает в браузере по адресу [app.usectrl.dev](https://app.usectrl.dev) с
теми же возможностями. Но вкладка браузера не может разместить сервер, поэтому его
предоставляете вы — запустите `cc_server` локально и подключитесь к `ws://localhost:9030`,
или укажите сервер на другой машине. Это краткое руководство идёт по пути настольного
приложения, потому что не требует настройки сервера; о браузерном варианте см.
[Установка](/ru-RU/руководство/установка/#use-it-in-your-browser).
:::

## Шаг 2. Пройдите онбординг

Онбординг состоит из пяти шагов, которые выполняются по порядку — пропустить их нельзя.

1. **Подключение**: войдите через GitHub или вставьте личный токен доступа с правами `repo` и `read:org`. Учётные данные хранятся на сервере и привязаны к вашему аккаунту.
2. **Рабочее пространство**: задайте имя первому рабочему пространству и при желании выберите логотип. При создании в него закладываются пять агентов — CEO плюс `qa`, `architect`, `engineer` и `librarian` — и встроенные шаблоны конвейеров.
3. **Песочница**: сохраняет предпочтение по песочнице. Любой выбор позволит продолжить.
4. **Адаптер**: выберите адаптер и модель по умолчанию для агентов. Укажите **Control Center (built-in)**, затем в появившемся списке провайдеров войдите в аккаунт провайдера моделей — список моделей остаётся пустым, пока ни один провайдер не подключён. Завершение этого шага также закрепляет адаптер и модель за агентом CEO рабочего пространства.
5. **Голос (необязательно)**: установите локальную речевую модель для диктовки или пропустите этот шаг.

После этого Control Center открывает входящие вашего рабочего пространства.

:::note[Что ограничивает запуск агента]
Команды агента оборачиваются в нативную песочницу ОС хоста, когда она доступна — Seatbelt в macOS, bubblewrap в Linux. В Windows бэкенда нет, поэтому запуски там ограничены только остальными слоями: собственным worktree разговора (`git worktree` в Windows; copy-on-write там, где поставляется `rift`), учётными данными, выдаваемыми брокером при каждом запуске и отзываемыми при завершении, и ограничениями действий. См. [Песочница и безопасность](/ru-RU/руководство/понятия/песочница-и-безопасность/).
:::

## Шаг 3. Добавьте репозиторий

Перейдите в **Настройки → Рабочее пространство → Репозитории** и нажмите **Добавить репозиторий**.

В диалоге отображаются папки на машине, где запущен сервер, а не на вашем клиенте, и он остаётся внутри корней, которые сервер настроен предоставлять (по умолчанию — домашний каталог его пользователя). Флажок получают только git-копии. Отметьте свою и зарегистрируйте её.

Рабочая копия принимается, только если она находится внутри рабочего дерева git, имеет удалённый репозиторий `origin`, и этот удалённый репозиторий указывает на поддерживаемый хост кода — github.com, gitlab.com или bitbucket.org. Всё остальное отклоняется с указанием причины.

Репозитории привязаны к рабочему пространству: регистрация рабочей копии здесь помещает её в _это_ рабочее пространство. Отдельного шага связывания нет.

## Шаг 4. Задайте агенту адаптер и модель

Перейдите в **Настройки → Рабочее пространство → Агенты**. Выберите агента `engineer` в списке.

На вкладке **Настройки** укажите:

- **Адаптер**: `Control Center (built-in)`
- **Модель**: выберите из провайдера, подключённого при онбординге

Нажмите **Сохранить изменения**.

На практике этот шаг не является необязательным. Только агент CEO наследует адаптер, выбранный при онбординге; четыре специалиста создаются без него. Они откатываются к **Control Center (built-in)** с моделью Anthropic по умолчанию, поэтому запускаются, только если вы подключили аккаунт Anthropic — и на модели, которую вы не выбирали, если подключили.

## Шаг 5. Дайте агенту задачу

1. На боковой панели найдите раздел **Пространства** и нажмите кнопку **+**.
2. Задайте имя пространства, добавьте агента `engineer` в разделе **Добавить агентов** и создайте его.
3. Введите конкретную небольшую задачу для зарегистрированного репозитория и нажмите Enter.

Control Center подготавливает для этого разговора worktree с copy-on-write из репозиториев рабочего пространства, собирает промпт из роли агента, его персоны, навыков и контекста пространства и запускает выполнение. Ваша исходная рабочая копия не затрагивается.

## Шаг 6. Наблюдайте за работой

Вы должны увидеть по порядку:

- Кнопка отправки в поле ввода превращается в кнопку остановки, потому что агент работает в этом разговоре
- Рассуждения агента, вызовы инструментов и текст, которые поступают в транскрипт
- Кнопка отправки возвращается, когда запуск завершается

Затем откройте **Настройки → Рабочее пространство → Агенты**, выберите агента и проверьте вкладку **Журнал**: одна строка запуска со статусом, длительностью, временем начала и завершения и адаптером, на котором он выполнялся.

Это и есть цикл. Всё остальное в Control Center — проверка pull request, конвейеры, тикеты, встречи, Slack — держится на нём.
