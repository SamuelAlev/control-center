## Что у вас получится

К концу этого учебника у вас будет:

- Открытый pull request в верстаке PR Control Center
- Прочитанный diff с оставленным построчным комментарием
- Отправленный вердикт ревью
- Смерженный PR

Предварительные требования: пройденный учебник [Запустите первого агента](/ru-RU/руководство/учебники/первый-агент/) и один открытый pull request в репозитории, зарегистрированном в этом рабочем пространстве. Для шагов ревью выберите PR, который открыли не вы, — на ваших собственных PR кнопка **Ревью** скрыта. Слияние всё равно работает и на PR, который открыли вы.

## Шаг 1. Откройте pull request

1. Нажмите **Pull requests** на боковой панели
2. Найдите свой PR и нажмите на него

**Контрольная точка.** PR открывается как верстак с вкладками — «Обзор», «Различия», «Контроль версий», «Чат», «Действия» — с фокусом на **Обзор**: название и действия, описание и лента активности, а также боковая панель со статусом, ревьюерами, исполнителями, проверками и изменёнными файлами. Нажатие на файл там переносит к нему на вкладке «Различия». Вкладка «Ревью PR» не открыта, пока кто-нибудь не запросит ИИ-проверку.

:::note[Пустая очередь с предложением «подключить GitHub»]
Это состояние означает, что у _сервера_ нет токена GitHub, — у вашего клиента его нет никогда. Задайте его в разделе **Настройки → Рабочее пространство → Профиль и идентичность → Хостинг кода**, затем обновите список.
:::

## Шаг 2. Прочитайте diff

Откройте вкладку «Различия». Слева расположено сворачиваемое дерево файлов, а полоса над diff несёт селектор диапазона коммитов — сузьте diff до одного коммита или промежутка из них — плюс число файлов и текущее число добавлений и удалений.

Кнопка настроек на панели инструментов diff управляет его отображением:

- **Раздельный** или объединённый вид
- **Переносить строки** или прокрутка длинных строк
- **Лигатуры шрифта кода**

Отметьте файл как просмотренный, чтобы отслеживать прогресс в большом diff. Навигация с клавиатуры описана в разделе [Горячие клавиши](/ru-RU/руководство/справка/горячие-клавиши/).

## Шаг 3. Оставьте построчный комментарий

1. Наведите курсор на строку в diff — в жёлобе появится небольшая пилюля `+`
2. Нажмите её, чтобы прокомментировать эту строку, или сначала перетащите её по вертикали, чтобы выбрать диапазон
3. Введите свой отзыв. Форма предлагает две отправки:
   - **Начать ревью** (или **Добавить в ревью**, если ревью уже идёт) ставит комментарий в очередь. В треде отображается **Ожидает ревью**, пока вы не отправите вердикт на шаге 4.
   - **Добавить один комментарий** публикует его на GitHub сразу. В треде отображается **Публикация…**, затем **Синхронизировано**, а если публикация не удалась, предлагается повторить.

Для этого учебника используйте **Начать ревью**, чтобы комментарий ушёл вместе с вердиктом.

:::caution[Комментарий в очереди ещё не на GitHub]
**Начать ревью** / **Добавить в ревью** держат комментарий локально, пока вы не отправите вердикт. Только **Добавить один комментарий** публикует сразу. _Тело_ ревью, которое вы пишете на шаге 4, — отдельный черновик.
:::

## Шаг 4. Отправьте ревью

1. Нажмите **Ревью** в строке действий на вкладке «Обзор» — та же кнопка есть и на панели инструментов вкладки «Различия». Она скрыта на PR, которые открыли вы, и на закрытом или смерженном PR.
2. Напишите резюме в форме. Оно автоматически сохраняется как черновик, поэтому можно закрыть оверлей и вернуться позже.
3. Выберите вердикт:
   - **Запросить изменения**
   - **Комментировать**
   - **Одобрить**

Вердикт — это и есть кнопка. После **Одобрить** или **Запросить изменения** кнопка переименовывается в **Одобрено** или **Запрошены изменения**. Вердикт **Комментарий** оставляет на ней подпись **Ревью**.

**Контрольная точка.** Кнопка показывает «Одобрено» или «Запрошены изменения», если вы выбрали один из этих двух вариантов.

## Шаг 5. Слияние

Кнопка **Слить** присутствует всякий раз, когда GitHub сообщает, что PR можно смержить, — она не привязана к вашему собственному одобрению. Её цвет сообщает о готовности, а не о разрешении: основной, когда требуемые одобрения и проверки зелёные, второстепенный, пока проверка ещё идёт, разрушительный — когда запрошенный ревьюер не одобрил или проверка падает.

1. Нажмите **Слить**
2. Выберите способ: **Объединить и слить**, **Создать коммит слияния** или **Перебазировать и слить**
3. Для первых двух отредактируйте предзаполненные заголовок и описание коммита
4. Подтвердите

Все нерешённые проблемы — «Проверки не проходят», «Есть незавершённые ревью» — перечислены в выпадающей панели до подтверждения.

:::caution[Слияние необратимо]
Слияние отправляет коммиты на GitHub. Оно никогда не попадает в стек отмены Control Center, и отменить его отсюда нельзя.
:::

После слияния срабатывает доменное событие `PrMerged`; его потребляют аналитика и уведомления. О том, кто ещё его слушает, см. [Доменные события](/ru-RU/руководство/справка/доменные-события/).

## Ревью с помощью ИИ

Control Center может поставить конвейер ревьюеров на открытый PR, но только когда вы попросите: у шаблона `pr_review` есть ручной триггер и больше ничего.

1. Откройте меню переполнения в строке действий на вкладке «Обзор» и выберите **Спросить AI**. Control Center запускает прогон и открывает вкладку «Ревью PR», так что вы можете наблюдать за работой специалистов.
2. Агенты-ревьюеры фиксируют свои находки как узлы проверки в пространстве PR; финальный шаг сводит их в один отчёт.

Конвейер намеренно ничего не публикует на GitHub — он завершается после сведения. Публикация — отдельный шаг, который вы делаете сами, кнопкой **Опубликовать на GitHub** на вкладке «Ревью PR». См. [Использовать ИИ-проверку](/ru-RU/руководство/практические-руководства/ии-проверка/).

## Итоги

Вы открыли PR в верстаке, прочитали diff с подсветкой синтаксиса, оставили построчный комментарий, отправили вердикт и смержили — не покидая приложения.
