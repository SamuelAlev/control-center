## Оболочка приложения

Оболочка приложения (`ControlCenterLayout`) оборачивает каждый маршрут внутри рабочего пространства через `ShellRoute`. **Каждый пункт назначения внутри оболочки имеет префикс рабочего пространства — `/workspaces/:workspaceId/…` — а идентификатор рабочего пространства в URL служит единственным источником истины для активного рабочего пространства.** Префикса не имеют только поверхности, существующие до контекста: `/splash`, `/onboarding`, `/signed-out` и голый выбор `/workspaces` — все на весь экран и вне оболочки.

Шлюз считается пройденным, когда **у вошедшего пользователя** подключён хотя бы один хост кода и существует хотя бы одно рабочее пространство.

Отсутствующие учётные данные и незавершённая настройка — разные экраны, и различителем служит `users.onboarding_finished_at`, считанный из собственного `identity.me` вызывающего, а **никогда** не «рабочее пространство существует»: последнее неверно в тот момент, когда кого-то приглашают в рабочее пространство, которое он не создавал. Без подключённого хоста кода аккаунт, прошедший онбординг, попадает на `/signed-out` для повторной аутентификации; аккаунт, не прошедший его, — на `/onboarding`. Пока флаг неизвестен, страж удерживает заставку, а не гадает, потому что он никогда не перенаправляет обратно из онбординга.

## Маршруты без префикса

| Путь                       | Экран                                            |
| -------------------------- | ------------------------------------------------ |
| `/splash`                  | Стартовая заставка, которая определяет результат шлюза онбординга |
| `/onboarding`              | Подключение хоста кода, создание рабочего пространства или присоединение к нему, песочница, адаптер по умолчанию, затем голос. Шаг выбора рабочего пространства пропускается, если аккаунт уже состоит в нём |
| `/signed-out`              | Повторная аутентификация: та же карточка подключений к хостам кода, которую отображает раздел «Настройки», без полосы шагов и кнопки продолжения — маршрутизатор уходит с неё сам, как только хост кода отчитается о подключении |
| `/workspaces`              | Список и выбор рабочего пространства             |
| `/workspaces/:workspaceId` | Перенаправляет на `/workspaces/:workspaceId/inbox` |

Пути ниже опускают префикс `/workspaces/:workspaceId`.

| --------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `/inbox`                                | —                                         | Единые входящие: pull request, классифицированные по жизненному циклу ревью, плюс работа без PR, блокирующая оператора. Целевой маршрут после прохождения шлюза; голый `/workspaces/:workspaceId` перенаправляет сюда |

| `/calendar/:eventId`                    | —                                         | Детали события календаря (соседний маршрут; использует тот же ключ страницы, что и календарь)                                                                            |

У разговоров и веток **нет собственных маршрутов** — ветка это разговор внутри `/spaces/:spaceId`, который открывается как вкладка редактора, а не адресуется по URL.

Маршрута `/dashboard` **не существует**, как и экрана дашборда. Аналитическая поверхность — это `/observability`, на которую попадают из нижней части боковой панели.

Пункта боковой панели «Планы» **нет**. Plan Studio открывается как вкладка редактора из строки плана в разговоре, который его создал; `/plans` и `/plans/:kind/:id` — глубокие ссылки.

У `/observability` и `/pull-requests/compose` нет записи в реестрах заголовков маршрутов и навигационных цепочек, поэтому в заголовке окна у обоих отображается только имя приложения, а цепочка навигации отсутствует.

## Маршруты настроек

`/settings` перенаправляет на `/settings/you/appearance`. Кнопка настроек на боковой панели и `Cmd/Ctrl + ,` ведут на `/settings/you/appearance`.

Пути настроек разнесены по пространствам имён по **области** — `you/`, `workspace/`, `server/` — потому что сегмент указывает, на кого влияет изменение. Два пути появились раньше такого разделения и не имеют области в URL: `/settings/memory` и `/settings/pipelines`.

### Вы

| Путь                          | Экран                                                                     |
| ----------------------------- | ------------------------------------------------------------------------- |
| `/settings/you/appearance`    | Тема, язык, типографика, тема редактора (стартовый экран настроек)         |
| `/settings/you/notifications` | Переключатели по событиям, тихие часы                                      |
| `/settings/you/keybindings`   | Справочник горячих клавиш (только для чтения)                              |
| `/settings/you/audio`         | Микрофон, диктовка, определение встреч и вывод звуковых пейзажей           |
| `/settings/you/devices`       | Привязанные телефоны и удалённое управление                                |
| `/settings/you/newsfeed`      | Управление лентой: источники, обновление, состояние прочитанного           |

### Рабочее пространство

| Путь                               | Экран                                                                                               |
| ---------------------------------- | --------------------------------------------------------------------------------------------------- |
| `/settings/workspace/profile`      | Профиль и идентичность в этом рабочем пространстве: имя, автор git, хостинг кода, календарь |
| `/settings/workspace/general`      | Название, логотип, glob-шаблоны секретов, параллелизм ревью, именование веток, состояние синхронизации, чат-мосты, опасная зона |
| `/settings/workspace/meetings`     | Шаблоны заметок встреч и сохранённые голосовые профили                                              |
| `/settings/workspace/members`      | Состав участников, приглашения, журнал аудита. Журнал аудита разбивается на страницы с необязательным `?cursor=` |
| `/settings/workspace/repositories` | Репозитории, зарегистрированные в этом рабочем пространстве                                          |
| `/settings/workspace/agents`       | Зарегистрированные идентичности агентов                                                              |
| `/settings/workspace/skills`       | Настройка навыков                                                                                    |
| `/settings/memory`                 | Память рабочего пространства: факты, политики, граф знаний                                           |
| `/settings/workspace/permissions`  | Разрешения агента: матрица ограничений и проверка «что если»                                         |
| `/settings/pipelines`              | Шаблоны конвейеров                                                                                   |
| `/settings/pipelines/:templateId`  | Редактор шаблона конвейера (полотно с перетаскиванием)                                               |

### Сервер

| Путь                           | Экран                                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------------- |
| `/settings/server/connection`  | Подключение и состояние                                                               |
| `/settings/server/sso`         | Единый вход (SAML, OIDC, провижининг SCIM)                                             |
| `/settings/server/providers`   | Провайдеры моделей и адаптеры                                                          |
| `/settings/server/mcp`         | Встроенные и внешние MCP-серверы                                                       |
| `/settings/server/voice`       | Голосовые модели и модели встреч (ASR, диаризация)                                     |
| `/settings/server/rigs`        | Rigs: что может загружать этот хост, базовые образы, свои образы, работающие машины    |
| `/settings/server/sandbox`     | Права на выполнение в песочнице: программы, которые агенты могут запускать из своей рабочей копии ваших репозиториев |
| `/settings/server/diagnostics` | Диагностика и конфиденциальность: песочница, эмбеддинг, логирование, отчёты о сбоях |
| `/settings/server/backup`      | Резервное копирование и восстановление: снапшоты установки, экспорт по рабочему пространству, импорт и удаление |
| `/settings/server/about`       | О программе и обновления                                                              |

`kSettingsNav` в `lib/features/settings/settings_nav.dart` — единственный источник истины для этого списка. `settings_nav_test.dart` фиксирует уникальность идентификаторов и маршрутов, плоский порядок обхода J/K и три области. Он не обходит каждый зарегистрированный `GoRoute`.
