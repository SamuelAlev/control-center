Всё, что можно настроить в едином входе, — в одном месте. Значения живут в
строках `sso_connections` базы `global.db` (по замыслу общих для всего
сервера) и редактируются через **Настройки → Сервер → Единый вход** или
RPC-операции `sso.*`. Сохранённая строка — единственный источник истины: пути
через переменные окружения `CC_SAML_*` / `CC_OIDC_*` нет (подключение,
которое могло бы прийти из двух мест, — это подключение, с которым экран
настроек способен разойтись).

## Поля подключения

| Поле                   | Применяется к | По умолчанию    | Значение                                                                                                                                                       |
| ---------------------- | ------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `enabled`              | оба           | выкл.           | входы могут использовать это подключение                                                                                                                       |
| `idpMetadataXml`       | SAML          | —               | XML `EntityDescriptor` вашего IdP (обязателен для включения)                                                                                                   |
| `spEntityId`           | SAML          | `<origin>/saml` | идентификатор сущности поставщика услуг; закрепляется, когда origin меняется                                                                                     |
| `emailAttribute`       | SAML          | `email`         | атрибут с адресом электронной почты; запасной вариант — NameID в форме адреса                                                                                  |
| `displayNameAttribute` | SAML          | `displayName`   | атрибут отображаемого имени                                                                                                                                     |
| `groupsAttribute`      | SAML          | `groups`        | атрибут имён групп                                                                                                                                               |
| `clockSkewSeconds`     | SAML          | 90              | допустимое расхождение при проверке сроков действия                                                                                                             |
| `allowIdpInitiated`    | SAML          | выкл.           | принимать действительные незапрошенные ответы (без `InResponseTo`); браузер должен запросить краткосрочное право, прежде чем получить запечатанные для получателя учётные данные |
| `wantResponseSigned`   | SAML          | выкл.           | требовать подпись в корне ответа (подписи утверждений обязательны всегда)                                                                                        |
| `issuer`               | OIDC          | —               | базовый URL издателя (обязателен для включения)                                                                                                                 |
| `clientId`             | OIDC          | —               | идентификатор публичного клиента (обязателен для включения)                                                                                                     |
| `clientSecret`         | OIDC          | —               | только для конфиденциальных клиентов; хранится в файле секретов с правами 0600 и никогда — в базе данных; записывается по RPC в одну сторону (`sso.getConfig` сообщает `clientSecretPresent`) |
| `groupsClaim`          | OIDC          | `groups`        | claim с именами групп                                                                                                                                           |
| `defaultRole`          | оба           | `member`        | роль, когда ни одна группа не совпала, — никогда не `owner`                                                                                                     |
| `groupRoleMap`         | оба           | `{}`            | группа → роль; сопоставления с владельцем отклоняются при сохранении                                                                                            |
| `autoMember`           | оба           | вкл.            | автоматически добавлять пользователей во все рабочие пространства при первом входе                                                                              |
| `allowJit`             | оба           | вкл.            | создавать неизвестных пользователей при входе                                                                                                                   |

## Конфигурация процесса

Подключения SSO не задаются из окружения. Один оставшийся флаг процесса выбирает,
где браузер открывает веб-клиент после колбэка SSO:

| Переменная / флаг                        | Значение                                                                                                              |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `--web-client-url` / `CC_SERVER_WEB_CLIENT_URL` | URL веб-клиента для передачи запечатанных учётных данных; если не задан, передача остаётся на том же origin (полезно, только если веб-клиент обслуживается там). Для входа через `web-popup` приоритет имеет разрешённый `client_origin` из вкладки-инициатора. |

Сам URL издателя обязан быть `https` (`http` принимается только для издателей
на loopback-адресах `localhost`, `127.0.0.1` и `::1`). Используйте доверенный TLS
для колбэка IdP и хоста веб-клиента: страница, генерирующая ключ получателя, и
поставляемый ею JavaScript входят в границу доверия. HTTPS защищает эту начальную
загрузку; после сопряжения и прямые, и ретранслируемые сеансы `/rpc` требуют
шифрования Noise и закреплённой идентичности сервера.

## HTTP-эндпоинты

| Эндпоинт                                         | Аутентификация      | Назначение                                                                                                                                                                                                                                      |
| ------------------------------------------------ | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /saml/login?relay=…&handoff_key=…`                        | нет (перенаправление) | запустить вход, инициированный SP, с ключом получателя X25519, который держит клиент; `relay=desktop` передаёт управление приложению, `relay=web-popup` отправляет postMessage ожидающей вкладке подключения (её `client_origin` учитывается, только если ему доверяет список разрешённых origin) |
| `POST /saml/acs`                                 | нет (POST от IdP)   | проверить утверждение и провизионит пользователя; вход, инициированный SP, запечатывает выпущенные учётные данные устройства ключом получателя-инициатора; разрешённый незапрошенный SAML вместо этого даёт привязанное к браузеру право |
| `POST /saml/claim`                               | право браузера на том же origin | погасить одноразовое право незапрошенного SAML вместе с его cookie и новым `handoff_key`; возвращает запечатанные для получателя учётные данные, а не ключ сопряжения открытым текстом |
| `GET /saml/metadata`                             | нет                 | наш `EntityDescriptor` SP                                                                                                                                                                                                                       |
| `GET /oidc/login?relay=…&handoff_key=…` / `GET /oidc/callback` | нет                 | обмен OIDC туда и обратно; для входа нужен ключ получателя, который держит клиент; `relay=desktop` передаёт управление приложению, `relay=web-popup` — ожидающей вкладке подключения (то же соглашение о `client_origin`) |
| `GET /auth/providers`                            | нет, CORS `*`       | проба экрана подключения: предлагаемые подключения SSO (`id`/`kind`/`label`) + `pairingEnabled`                                                                                                                                                  |
| `/scim/v2/Users…`                                | Bearer (токен SCIM) | создание, получение, список с фильтром, PUT, PATCH и DELETE пользователей                                                                                                                                                                       |
| `/scim/v2/Groups`                                | Bearer              | только чтение; передача групп отвечает 501 намеренно                                                                                                                                                                                            |
| `/scim/v2/ServiceProviderConfig`                 | Bearer              | документ возможностей                                                                                                                                                                                                                           |

Для SAML и OIDC, инициированных SP, URL начала входа требует действительного
`handoff_key` (открытый ключ X25519 клиента-инициатора). Сервер хранит этот ключ
вместе с ожидающим входом и запечатывает выпущенные учётные данные устройства при
колбэке с помощью эфемерного X25519, HKDF-SHA256 и AES-256-GCM, привязанных к
origin сервера. Передача на компьютер использует `control-center://pair`,
передача веб-версии в той же вкладке — фрагмент URL, а `web-popup` отправляет
postMessage на разрешённый `client_origin`, если он указан (иначе — на
настроенный URL веб-клиента или origin колбэка). В этом фрагменте или сообщении
popup едет запечатанный конверт, а не ключ сопряжения открытым текстом.
Клиент-инициатор хранит соответствующий закрытый ключ, чтобы его открыть. Этот
конверт отличается от обязательного сеанса Noise, устанавливаемого после
сопряжения.

Ответ SAML, инициированный IdP (когда это включено), не имеет
инициатора-получателя. Вместо этого ACS ставит пятиминутную cookie браузера,
HttpOnly и SameSite=Strict, и предлагает выбор **Open web client** /
**Open desktop app**. Эта страница генерирует новый ключ получателя и отправляет
его открытую половину и дескриптор права в `POST /saml/claim` с того же origin.
Claim требует совпадающих cookie и origin (граница CSRF), использует право один
раз и возвращает только запечатанный для получателя конверт. Последующий фрагмент
веб-версии или компьютера несёт этот конверт и материал закрытого ключа
получателя, чтобы конечный клиент мог его открыть, **а не** учётные данные
устройства открытым текстом. Другой браузер или истёкшее право не могут его
погасить. Origin конечного веб-клиента может получить доступ к фрагменту и
расшифровать его; скомпрометированная страница колбэка или origin веб-клиента
могут украсть учётные данные. Шифрование не делает код, отдаваемый из
недоверенного источника, безопасным.

## RPC-операции

Все операции `sso.*` относятся к серверу и доступны только **владельцу
сервера** (оператору установки, `ServerAuthority.serverOwner`). Владения
рабочим пространством недостаточно; одно лишь сопряжение их никогда не даёт.

| Операция                  | Назначение                                                                                                                                                    |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sso.getConfig`           | сохранённое подключение для вида                                                                                                                               |
| `sso.saveConfig`          | проверить, сохранить и применить на лету                                                                                                                       |
| `sso.status`              | флаги включено/настроено, наличие токена SCIM, канонический origin                                                                                              |
| `sso.testConnection`      | проверить подключение без похода в браузер (SAML: разбор метаданных + сборка AuthnRequest; OIDC: обнаружение издателя), с необязательными несохранёнными значениями из формы |
| `sso.spMetadata`          | выдать `EntityDescriptor` SP для origin                                                                                                                        |
| `sso.setPairingEnabled`   | разрешить/запретить ручное сопряжение (коды приглашения, ключи сопряжения); отказ отключить его, пока нет ни одного работающего подключения SSO, защищает от блокировки |
| `sso.sessionPolicy`       | прочитать максимальный срок действия учётных данных устройства и тайм-аут простоя установки (в минутах; `0` = не задано)                                        |
| `sso.setSessionPolicy`    | задать эти границы; применяются при проверке устройства и не сообщаются клиентам                                                                                |
| `sso.scimRegenerateToken` | создать и вернуть bearer-токен SCIM (один раз)                                                                                                                 |

## Коды ошибок валидации

Сбои `cc_saml_verify_response` несут устойчивый код:

| Код                    | Значение                                                                         |
| ---------------------- | -------------------------------------------------------------------------------- |
| `signature`            | подпись отсутствует, не заслуживает доверия или изменена, либо алгоритм/преобразование не разрешены |
| `expired`              | вне `NotBefore`/`NotOnOrAfter` (сверх расхождения)                               |
| `audience`             | ограничение аудитории не называет нас                                            |
| `destination`          | назначение ответа — не наш ACS                                                   |
| `request_match`        | `InResponseTo` не совпадает с ожидающим запросом, либо ответ незапрошен, когда это запрещено |
| `issuer`               | издатель — не настроенный IdP                                                    |
| `recipient`            | получатель подтверждения субъекта — не наш ACS                                    |
| `malformed`            | сбой на уровне XML/схемы                                                         |
| `status`               | статус, о котором сообщил IdP, — не Success                                      |
| `invalid` / `internal` | всё остальное / сбой на стыке                                                    |

## Поверхности базы данных

- `sso_connections` (global.db) — одна строка на вид; ПО ЗАМЫСЛУ ОБЩАЯ ДЛЯ
  ВСЕХ РАБОЧИХ ПРОСТРАНСТВ.
- `users.sso_subject` + `users.sso_issuer` — закрепление субъекта провайдера,
  уникальное по `(issuer, subject)` через частичный индекс.
- `users.deactivated_at` — отметка деактивации SCIM.
- Bearer-токен SCIM и секрет клиента OIDC живут в файле секретов с правами
  0600 и никогда — в базе данных.
