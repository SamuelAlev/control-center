Control Center может отправлять **псевдонимизированные события использования** в экземпляр [Umami](https://umami.is). Статистика использования **выключена, пока её не включит оператор сервера**. Этот параметр принадлежит серверу и действует для каждого подключённого к нему клиента: приложения для компьютера, веб-приложения, телефона и самого сервера.

Статистика использования не связана с параметром **Отправлять отчёты о сбоях** — это настройка отдельного устройства для диагностики сбоев и ошибок.

## Кто решает

| Переключатель | Где | Действие |
| --- | --- | --- |
| **Отправлять статистику использования** | Первоначальная настройка (шаг песочницы) и **Настройки → Конфиденциальность**. Изменить его может только оператор сервера; остальные участники видят текущее значение только для чтения | Для всего сервера. Хранится как `telemetry.usage_analytics` в настройках сервера. Выключен, если не задано `true` |
| Тип сборки | Автоматически | Отладочные и профилировочные сборки ничего не отправляют. Вместо этого они записывают каждое событие в журнал отладки |
| `CC_ANALYTICS_DEBUG=1` | Окружение `cc_server` или его файл `.env` | Позволяет отладочным и профилировочным сборкам сервера и всех подключённых к нему клиентов отправлять данные по-настоящему, для тестирования. Переключатель выше при этом должен быть включён |
| `DO_NOT_TRACK=1` | Окружение `cc_server` | Отключает собственную отправку данных сервером, что бы ни показывал переключатель. Клиенты по-прежнему следуют переключателю |
| Демо-сервер | Автоматически | Публичный демо-сервер ничего не отправляет от своего имени. Посетители не могут изменить переключатель |

Клиенты получают значение параметра от сервера (`telemetry.config`, затем в реальном времени через `telemetry.watch`). Пока ответ не пришёл, события ждут в небольшом буфере в памяти. Если ответ отрицательный, буфер отбрасывается. Выключение переключателя отбрасывает всё, что ещё стоит в очереди, и сразу прекращает отправку на каждом клиенте.

## Что никогда не отправляется

- Содержимое сообщений, тикетов, ревью и встреч, заголовки, промпты, команды оболочки и поисковые запросы
- Имена, логины, адреса электронной почты, аватары и отображаемые имена
- Пути к файлам, названия репозиториев и веток, имена хостов и URL (репозиторий отправляется только как псевдонимизированный `repo_id`, ссылка на встречу — только как её провайдер)
- Исходные идентификаторы любого вида

Каждое событие перед выходом из процесса проходит через политику свойств. Текст, пути, URL, адреса электронной почты, необёрнутые ID и строки под такими ключами, как `email`, `*_name`, `path`, `title`, `prompt`, `content` или `token`, отбрасываются, а не отправляются. Строка отправляется, только если это короткий токен из закрытого словаря: значение перечисления, версия, локаль или ID модели.

## Псевдонимизированные ID

ID отправляются, но только в виде псевдонимов. Каждый ID рабочего пространства, пространства, беседы, агента, запуска, пользователя и устройства заменяется на HMAC-SHA256 с собственной секретной солью установки (`telemetry.pseudonym_salt`), усечённый до 20 шестнадцатеричных символов. Одно и то же рабочее пространство всегда даёт одно и то же значение, поэтому события можно связывать и подсчитывать, но исходный ID никогда не покидает установку. Соль создаётся при первом запуске сервера и никогда не передаётся поставщику аналитики. Удаление каталога данных сервера создаёт новую соль и новый ID установки, и связь со всем записанным ранее теряется.

## Просмотры экранов

Каждый переход записывает просмотр страницы, URL которого — **шаблон маршрута**, например `/workspaces/:workspaceId/spaces/:spaceId`, а не конкретный адрес. Имя экрана составляется из литеральных сегментов шаблона, так что для этого примера это `workspaces_spaces`. Параметры маршрута, оканчивающиеся на `Id`, прикрепляются как псевдонимизированные свойства `*_id`, а числовые (например, номер PR) — как числа. Все остальные параметры отбрасываются.

## Доставка

События отправляются по одному на `<host>/api/send` из очереди в памяти размером до 200 событий. При сетевой ошибке, тайм-ауте, `429` или `5xx` событие сохраняется и отправляется повторно с экспоненциальной задержкой от 1 секунды до 5 минут. Любой другой `4xx` отбрасывает его. На диск ничего не записывается, поэтому события, оставшиеся в очереди при закрытии приложения, теряются. Очередь сбрасывается, когда приложение уходит в фон и когда сервер завершает работу.

## Направить сборку на другой экземпляр

Получатель фиксируется во время сборки:

```bash
--dart-define=CC_ANALYTICS_HOST=https://analytics.example.com/
--dart-define=CC_ANALYTICS_WEBSITE_ID=<website uuid>
```

Адаптер поставщика находится в `packages/cc_analytics`. Чтобы поддержать другой сервис аналитики, добавьте туда адаптер. План отслеживания и правила конфиденциальности остаются прежними.
