Este guia mostra como configurar as notificações e o que cada opção controla de
facto.

As notificações chegam por duas superfícies. O **centro de notificações** — o
sino na barra de título — lê um feed duradouro por espaço de trabalho no
servidor. As **notificações do sistema operativo** são um caminho separado,
exclusivo do computador, alimentado por frames em direto enviados pelo servidor.

:::note[A build web não mostra notificações do sistema operativo]
O pipeline de notificações do sistema operativo só é criado pelo arranque do
cliente de computador. Em `app.usectrl.dev` não há notificações do sistema
operativo, nem sons de notificação, nem banners ambiente — o sino e o seu
histórico continuam a funcionar, porque leem o feed do servidor. O cliente de
telemóvel não tem nenhuma superfície de notificação.
:::

## Ativar ou desativar categorias

1. Aceda a **Definições → Você → Notificações**
2. Deixe **Ativar notificações** ligado
3. Ative ou desative as categorias que quiser. São exatamente dezasseis:

| Categoria                 | Dispara quando                                                             |
| ------------------------- | -------------------------------------------------------------------------- |
| Agente finalizado         | Um agente respondeu numa execução que iniciou, ou a execução falhou        |
| PR publicada              | Um agente publicou uma PR                                                  |
| PR fundida                | Uma PR foi fundida                                                         |
| Novas mensagens           | Alguém o mencionou num espaço                                              |
| Mencionado em um pull request | A sondagem de notificações do GitHub detetou que foi mencionado numa PR |
| Revisão solicitada        | A sua revisão foi realmente solicitada numa PR que não é rascunho          |
| Revisão desatualizada     | Chegaram novos commits a uma pull request que já tinha revisto             |
| Pronto para fundir        | Uma pull request da sua autoria ficou pronta para fundir, ou deixou de estar |
| Decisões de revisão       | Um revisor aprovou, solicitou alterações ou viu uma aprovação anulada      |
| Verificações              | O CI falhou numa pull request da sua autoria, ou recuperou                 |
| Tópicos de revisão        | Alguém respondeu ou resolveu um tópico em que participa                    |
| Ticket atribuído          | Foi atribuído um ticket                                                    |
| Status do ticket alterado | Um ticket mudou de estado                                                  |
| Reunião prestes a começar | Uma reunião do calendário está dentro da sua janela de antecedência       |
| Calendário desligado      | O token OAuth de um calendário ligado expirou                              |
| Atualizações de recintos  | Um recinto foi assumido, recuperado ou falhou                              |

Nada fora desta lista pode gerar notificação nem ser filtrado — não existe
nenhuma categoria «tudo o resto».

Estas preferências acompanham o seu utilizador entre dispositivos, pelo que um
telemóvel e um portátil ficam em sintonia. O volume é a exceção deliberada e
mantém-se por dispositivo.

## Definir o horário de silêncio

1. Na mesma página, ative **Quiet hours**
2. Introduza uma hora de início e uma de fim em `HH:MM` (a janela predefinida é
   22:00–08:00)

Durante o horário de silêncio, as notificações não urgentes são descartadas —
não ficam em fila nem são reproduzidas mais tarde.

Duas categorias são **urgentes** e são sempre entregues, ignorando o horário de
silêncio _e_ o modo de concentração: **Reunião prestes a começar** e **PR
publicada**. Um alerta de reunião que só vê depois não serve para nada, e é essa
a razão.

## Escolher um som

1. Desça até **Som de notificação**
2. Escolha um dos onze sons incluídos, ou **Nenhum**
3. Prima o botão de teste para o ouvir e ajuste o volume com o cursor

A aplicação reproduz o som ela própria; a notificação do sistema operativo é
entregue em silêncio, para que nunca a ouça duas vezes.

## Definir a antecedência das reuniões

1. Desça até **Antecedência do alerta**
2. Escolha **5**, **10**, **15** ou **30** minutos

É com essa antecedência que a notificação **Reunião prestes a começar** é
disparada antes de um evento do calendário. O valor predefinido são 5 minutos.

## Saber quando uma notificação é suprimida

Uma notificação é descartada, em silêncio, quando qualquer uma destas condições
se verifica:

- As notificações estão globalmente desativadas, ou a categoria dela está
- Já está na rota para onde ela o levaria — e, no caso de uma mensagem, já está
  nesse espaço
- O modo de concentração está ativo e a categoria não é urgente
- O horário de silêncio está ativo e a categoria não é urgente

Estas verificações aplicam-se às notificações do sistema operativo. O sino
duradouro continua a registar o evento.

Há mais duas supressões a montante, naquilo que o servidor chega a enviar:

- Uma mensagem não mencionada de outro **humano** nunca se torna uma notificação
- Num espaço partilhado, a resposta de um agente avisa quem iniciou essa
  execução, não todos os membros
- Os espaços entre agentes estão silenciados na barra lateral, pelo que nunca
  fazem subir o distintivo de não lidos dos humanos

Dentro de um espaço não há nenhum recanto tranquilo: todas as conversas notificam
por igual, incluindo as threads. O estado de leitura é ao nível do espaço, pelo
que os não lidos agregam-se em todas as conversas do espaço, em vez de serem
seguidos por conversa.

## Ler e limpar o centro de notificações

1. Clique no sino da barra de título

A janela emergente mostra a atividade recente, ligando cada entrada por ligação
direta àquilo sobre que fala. Abri-la **não** marca tudo como lido — use **Marcar
tudo como lido** no cabeçalho, ou marque uma única linha. O estado de leitura
segue o seu utilizador entre dispositivos.

:::note[Limpar tudo é uma marca de água, não uma eliminação]
**Limpar tudo** aplica uma marca de água por utilizador que oculta tudo o que é
mais antigo; as linhas permanecem. Separadamente, cada espaço de trabalho retém
apenas as suas **200** linhas de feed mais recentes, eliminadas à medida que
chegam novas, enquanto o sino subscreve as **50** mais recentes e a janela
emergente lista até **15** dessas. O histórico para além disso desaparece,
independentemente do estado de leitura.
:::

## Resolução de problemas

### Sem notificações do sistema operativo no macOS

A autorização é pedida nativamente quando a aplicação arranca. Se a recusou,
volte a ativar o Control Center em Definições do Sistema → Notificações; não há
nenhum pedido dentro da aplicação para a voltar a acionar.

### Não chega nada na build web

É o esperado — a build web não tem nenhum pipeline de notificações do sistema
operativo. Use o sino.

### O distintivo do sino mostra zero, mas há claramente atividade nova

Enquanto o fluxo de marcas de leitura não é resolvido depois de ligar, as
entradas são apresentadas como lidas para evitar um distintivo que pisca e
depois se esvazia. Estabiliza assim que a marca é carregada.

### A execução de um agente terminou, mas não recebi nenhum aviso

Verifique se não estava já no espaço onde isso aconteceu — uma rota ativa suprime
a sua própria notificação do sistema operativo. Num espaço partilhado, uma
execução iniciada por outra pessoa avisa essa pessoa, não a si. Um turno que
terminou sem resposta e sem erro não envia nada.
