Este guia mostra-lhe como voltar a um ponto anterior de uma conversa e levá-la para outro sítio — mantendo o caminho que deixou.

## A única coisa que vale a pena saber

**Criar um branch não escreve nada.** Uma conversa é uma árvore de mensagens com um ponteiro na ponta, e voltar atrás move o ponteiro. Nada é eliminado, nada é ocultado, e voltar a alternar é apenas mais um movimento do ponteiro.

É por isso que editar um prompt e voltar a executá-lo é seguro aqui: a resposta com que estava a comparar continua lá.

## Ver os branches

```
/tree
```

O navegador lista todas as mensagens, indentadas a cada fork, com o caminho atual marcado como **Neste ramo**. Uma conversa que nunca teve fork é apresentada como a lista plana que sempre foi — consultar o navegador não custa nada enquanto não houver nada para navegar.

Cada linha oferece duas ações.

| Ação                             | Efeito                                                                    |
| -------------------------------- | ------------------------------------------------------------------------- |
| **Continuar a partir daqui**     | Move o ponteiro. A sua próxima mensagem continua a partir dessa mensagem. |
| **Bifurcar numa nova conversa**  | Copia o caminho até essa mensagem para uma nova conversa.                  |

## Branch: experimentar outra abordagem

1. `/tree`
2. Encontre a mensagem a partir da qual quer recomeçar — normalmente a última com que ficou satisfeito.
3. **Continuar a partir daqui.**
4. Escreva o novo prompt.

A continuação antiga continua na árvore; `/tree` mostrará agora dois caminhos a partir desse ponto, e pode alternar entre eles livremente.

:::note[O caminho que deixou continua lá]
Criar um branch não oculta nem elimina nada. `/tree` lista todos os caminhos, marca o atual como **Neste ramo** e é assim que alterna.
:::

## Fork: levá-la para outro sítio

O fork copia o caminho para uma **nova conversa** no mesmo espaço. Use-o quando as duas direções vão continuar a divergir e as quer lado a lado em vez de alternar entre elas.

A cópia tem ids de mensagem novos. Duas conversas que partilhassem linhas mostrariam uma à outra as suas mensagens posteriores, que é exatamente o que um fork deve impedir.

## Reversão versus branch

São ferramentas diferentes e a diferença importa.

|                     | Reversão                                            | Branch                          |
| ------------------- | --------------------------------------------------- | ------------------------------- |
| As mensagens posteriores | Ocultadas da transcrição                       | Ainda visíveis em `/tree`       |
| O **worktree**      | Revertido para o instantâneo desse turno            | Intacto                         |
| Anulação            | **Desfazer reversão** restaura o lote               | Mover o ponteiro para trás      |

A reversão é o que quer quando o agente alterou *ficheiros* que quer recuperar. O branch é o que quer quando a conversa seguiu o caminho errado mas os ficheiros estão bem.

Reverter também move a ponta do branch, por isso a sua próxima mensagem continua do sítio certo em vez de uma cauda que já ninguém consegue ver.

## Tirar a conversa da aplicação

### `/export`

Escreve um **ficheiro HTML autónomo**: a conversa completa com cartões de ferramentas recolhíveis que mostram o que foi fornecido a cada chamada e o que esta devolveu. Sem folha de estilos, sem script, sem alojamento de imagens — funciona a partir de uma pen USB e continuará a funcionar dentro de cinco anos.

- **Aplicação para computador:** `Documents/ControlCenter/exports/`, com data e hora para que uma segunda exportação não substitua a primeira.
- **Web:** uma transferência do navegador.

### `/dump`

Copia a transcrição para a área de transferência como markdown, com as chamadas de ferramentas em blocos recolhíveis. É esta que deve colar numa issue.

O raciocínio é deixado de fora de propósito: é o espaço de rascunho do modelo, e um relatório de erro é lido por uma pessoa.
