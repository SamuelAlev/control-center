Este guia mostra-lhe como trabalhar com o armazenamento de conhecimento de um espaço de trabalho.

O mais importante a saber antes de começar: **a interface de memória é uma superfície de revisão, não de autoria.** Os factos e as políticas são escritos pelos agentes — através de `propose_fact` e `propose_policy`, com `supersede_fact` e `supersede_policy` para os substituir. `remember` escreve um item de camada quente limitado à sessão que `consolidate_memory` pode mais tarde promover a facto. As decisões de reuniões gravadas são recolhidas para o domínio `decisions`; não há recolha em execuções de agentes concluídas. O que faz aqui é ler o que eles escreveram, corrigi-lo, desativá-lo ou eliminá-lo.

A memória está em **Definições → Espaço de trabalho → Memória** (`/workspaces/<id>/settings/memory`). Não é um destino de nível superior na barra lateral.

## Os três separadores

A página tem exatamente três separadores. Factos e Políticas mostram uma contagem em tempo real; o grafo não:

- **Factos** — todos os factos do espaço de trabalho, com uma contagem dos que não foram substituídos
- **Políticas** — regras normativas agrupadas por domínio, com uma contagem das que estão ativas
- **Grafo de conhecimento** — uma área de desenho interativa de domínios, tópicos, factos e políticas

Os domínios não são algo que se crie. Um domínio passa a existir quando um agente escreve nele o primeiro facto ou a primeira política; não há nenhum controlo de criação de domínios em parte alguma da interface.

## Rever e corrigir um facto

1. Abra o separador **Factos**.
2. Use a caixa de pesquisa para restringir a lista. É um simples filtro de subcadeias sobre o domínio, o tópico e o conteúdo de cada facto — sem índice de palavras-chave, sem classificação.
3. Use o filtro de âmbito para mostrar todos os âmbitos, apenas os factos de todo o espaço de trabalho ou os factos de um único repositório.
4. Use o alternador de ordenação para ordenar por recência ou por confiança.
5. Clique no controlo de edição de um facto.

A caixa de diálogo de edição permite-lhe alterar:

- **Domínio** — mover um facto entre domínios
- **Tópico** — a sua etiqueta curta
- **Conteúdo** — o texto do conhecimento
- **Confiança** — um deslizador em passos de 5%

Guarde para escrever as alterações. Não existe um botão **Adicionar facto**; a caixa de diálogo só abre a partir de uma linha existente.

## Ver factos substituídos

O separador Factos tem um interruptor **Mostrar substituídos**. Os factos substituídos estão ocultos por predefinição e são revelados por esse interruptor, que é onde reside o registo de auditoria — substituir nunca elimina.

## Eliminar um facto

Use o controlo de eliminação de um facto e confirme. Isto é uma eliminação real, não uma substituição: use-o para factos que simplesmente não deviam ter sido registados e deixe que os agentes substituam os factos cujo _conteúdo_ já evoluiu.

## Gerir políticas

O separador **Políticas** agrupa as políticas ativas por domínio e remete as inativas para uma secção final. Por política, pode:

- **Editar** a política
- **Eliminar** a política
- **Desativar** / **Ativar** a política — a opção reversível e, habitualmente, a mais adequada. Só as políticas ativas chegam aos prompts dos agentes.

Tal como nos factos, não há controlo de criação.

## Explorar o grafo de conhecimento

O separador **Grafo de conhecimento** dispõe domínios, tópicos, factos e políticas como uma área de desenho de nós navegável — desloque, amplie, arraste nós. Tocar num nó abre o respetivo painel de detalhes, a partir do qual se acede às mesmas caixas de diálogo de edição. É a forma mais rápida de ver quais os domínios que estão realmente preenchidos.

## Editar a memória de trabalho de um agente

A memória de trabalho é um bloco de notas privado de cada agente, injetado no respetivo prompt no momento do despacho. Os agentes escrevem-na eles próprios com `record_observation` e `update_my_notes`, mas pode lê-la e editá-la diretamente:

**Definições → Espaço de trabalho → Agentes** → selecione o agente → o separador **Memória**.

## Concessões de acesso

As concessões de acesso à memória mapeiam o papel de um agente a uma permissão (`none`, `read`, `write`) por domínio. Escreva-as com as operações `memory_access_grant.*`.

Duas coisas a compreender sobre a forma como são resolvidas:

- **As leituras são fail-open.** Sem uma linha de concessão para um par (papel, domínio), a permissão efetiva é `read`. A única escrita que gera erro sem `write` é `propose_policy`. As escritas de factos não dependem de concessão.
- **As concessões têm como chave o papel do agente.** As ferramentas de proposta assumem `general` quando o `agent_role` está em falta. Uma concessão escrita para outro papel não vincula esses agentes; uma concessão `general` vincula.

## A pesquisa não é a mesma em todo o lado

Há três coisas diferentes chamadas «pesquisa de memória» e não coincidem:

| Onde                                       | O que faz                                                                                                 |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| A caixa de pesquisa do separador Factos    | Filtro de subcadeias sobre os factos já carregados no cliente                                             |
| A operação RPC `memory_fact.search`        | Apenas pesquisa por palavras-chave FTS5 — um cliente leve não consegue enviar um embedding de consulta, por isso a pesquisa híbrida permanece interna ao anfitrião |
| A ferramenta `search_memory` do lado do agente | `keyword`, `semantic` ou `hybrid` (o modo predefinido). O modo híbrido funde quatro vozes: lexical, semântica, temporal e de grafo |

Por isso, um agente e a página Memória não irão ordenar a mesma consulta da mesma forma. Quando estiver a verificar o que um agente consegue realmente recuperar, pergunte ao agente.

## Embeddings

Os factos são convertidos em embeddings **no momento da escrita** e apenas quando o modelo de embeddings no dispositivo está instalado. Verifique o estado em **Definições → Servidor → Diagnóstico e privacidade → Pesquisa semântica**. Instale o modelo antes de os agentes começarem a escrever memória se quiser recuperação semântica.
