Este guia mostra como adicionar um agente a um espaço de trabalho e configurá-lo até que consiga realmente ser executado.

Todos os espaços de trabalho são criados com cinco agentes — um CEO e ainda `qa`, `architect`, `engineer` e `librarian` —, pelo que normalmente já tem agentes antes de ter configurado algum. Os passos abaixo aplicam-se tanto a um agente criado de origem como a um novo.

## Antes de começar

- Está dentro de um espaço de trabalho. Toda a superfície está em **Definições → Espaço de trabalho → Agentes** (`/settings/workspace/agents`).
- O agente vai precisar de um backend. Ou liga um fornecedor para o harness integrado em **Definições → Servidor → Fornecedores de modelos**, ou instala a CLI do Claude Code na máquina que aloja o `cc_server`.
- Se quiser que o agente tenha skills, instale-as primeiro em **Definições → Espaço de trabalho → Habilidades**. O formulário do agente só permite ativar skills que já existam no espaço de trabalho.

## Adicionar o agente

1. Abra **Definições → Espaço de trabalho → Agentes**.
2. Clique em **Novo agente**.

Não existe nenhuma caixa de diálogo nem seletor de funções. É criado imediatamente um agente com o nome “Agente sem nome”, que fica selecionado no painel de detalhe à direita.

Deve agora ver “Agente sem nome” na lista à esquerda, com o separador **Definições** do painel de detalhe aberto e um campo **Nome** que contém “Agente sem nome”.

## Dar-lhe um nome

- **Nome** — o identificador curto usado nas menções com @, por exemplo `alice`. A análise das menções corresponde a `@` seguido de caracteres de palavra, pelo que um nome com um hífen, um ponto ou um espaço nunca poderá ser mencionado.
- **Título** — a etiqueta legível por humanos, por exemplo “Programador sénior”.
- **Prompt do sistema** — instruções adicionais opcionais, injetadas como uma secção de instruções do agente; não substituem o resto do prompt montado.

Clique em **Guardar alterações**, na parte inferior do formulário. Todos os campos desta página são guardados por esse único botão.

## Atribuir um adaptador e um modelo

A lista pendente **Adaptador** apresenta os executores que o host do servidor tem realmente. O adaptador integrado aparece sempre (é o próprio servidor). O Claude Code só aparece quando a respetiva CLI foi detetada nesse host:

| Adaptador                 | Backend                                     |
| ------------------------- | ------------------------------------------- |
| Control Center (built-in) | O ciclo de agente em processo — sem CLI externa |
| Claude Code               | `claude -p --output-format stream-json`     |

Só o adaptador integrado aplica modos, direção, pausa/retoma, contratos de conclusão e subagentes. O Claude Code não oferece nada disso. O Cursor, o Codex e os restantes fornecedores de modelos ligam-se ao adaptador integrado, e não como executores separados.

:::note[Um adaptador vazio significa o ciclo integrado]
Um agente sem adaptador definido é despachado para o **Control Center (built-in)**, o ciclo que corre dentro do servidor, pelo que não é preciso instalar nada no host. Se também não tiver modelo definido, pede à Anthropic o modelo predefinido, de modo que um agente totalmente por configurar só é executado se tiver uma conta da Anthropic ligada. Os especialistas criados de origem são fornecidos sem nenhum dos dois; defina ambos em qualquer agente que tencione usar.
:::

A lista pendente **Modelo** é determinada pelo adaptador que escolheu. No caso do adaptador integrado, a lista vem em tempo real dos fornecedores que ligou em **Definições → Servidor → Fornecedores de modelos**, pelo que um fornecedor sem credencial guardada contribui com zero modelos.

## Adicionar skills

**Habilidades** é um seletor de chips sobre os pacotes de skills instalados neste espaço de trabalho. Toque num chip para o ativar ou desativar; o símbolo de verificação marca os selecionados. Se o espaço de trabalho não tiver skills, o campo indica “No skills available. Create skills in Settings → Skills first.”

Aqui não escolhe as skills próprias de um repo. Um repo que as inclua (em `.agents/skills/`, `.claude/skills/` ou `.opencode/skills/`) contribui com elas automaticamente para o agente que estiver a trabalhar nesse repo, e são trocadas quando este passa para outro — consulte [Skills com âmbito de repositório](/pt-PT/manual/conceitos/modelo-de-agentes/#repo-scoped-skills).

## Definir a linha de reporte e a persona

- **Reporta-se a** — escolha outro agente pelo nome. Isto constrói a árvore de reporte apresentada pelo botão **Organograma**, no cabeçalho da página. Não é a lista que um líder de equipa usa quando delega — essa vem dos membros da equipa e das respetivas skills.
- **Persona** — texto livre que molda o tom e o comportamento, por exemplo: “Prefere soluções simples e legíveis. Escreve testes para todo o código novo.”

## Ajustar a execução

- **Esforço de raciocínio** — as opções vêm dos níveis publicados pelo próprio modelo selecionado: Low / Medium / High, mais Extra High nos modelos ao estilo OpenAI e Extra High + Max nos ao estilo Claude. O campo fica completamente oculto quando o modelo selecionado não declara níveis de pensamento e assume a predefinição do próprio modelo.
- **Tamanho da janela de contexto** — preenchido a partir da janela de contexto do modelo sempre que muda de modelo, com chips de um toque para a predefinição do modelo, 200k, 500k e 1M. Um valor que escreva depois de escolher o modelo prevalece até à próxima mudança de modelo.
- **Tempo de silêncio (minutos)** — termina uma execução após este tempo sem qualquer saída. Deixe-o vazio para usar a predefinição de cada modo.

## Conceder permissões

Um agente não tem interruptores de permissão próprios. Aquilo que pode enviar, abrir, integrar ou alcançar é definido pelas regras de ação em **Definições → Espaço de trabalho → Permissões dos agentes**, onde uma regra pode ser limitada a este agente. Por predefinição, um push, um pull request, uma revisão ou merge e uma escrita num rastreador perguntam-lhe primeiro, cada um, e o acesso à rede é permitido.

O token do GitHub do agente é sempre só de leitura. Um push passa pelo Control Center, que pergunta à regra **Fazer push para um remoto** antes de o reencaminhar. Consulte [Configurar políticas de sandbox](/pt-PT/manual/guias/politicas-de-sandbox/) para ver como cada regra chega a uma execução.

:::note[As regras e o sandbox do sistema operativo são camadas separadas]
As regras decidem o que um agente pode fazer; o sandbox do sistema operativo limita onde os seus processos podem ler, escrever e ligar-se. O `cc_server` envolve as execuções dos agentes no sandbox do host quando este existe — o Windows não tem backend nativo, e o Linux e o WSL2 precisam de `bwrap` e `socat`. Consulte [Sandbox e segurança](/pt-PT/manual/conceitos/sandbox-e-seguranca/) para ver o conjunto completo de fronteiras.
:::

## Verificar que é executado

1. Abra **Definições → Servidor → Fornecedores de modelos** e confirme que o adaptador que escolheu indica uma versão instalada e não “Não encontrado”. Clique em **Atualizar** para voltar a sondar — a sondagem é executada na máquina que aloja o `cc_server`, não na máquina que está a usar.
2. Abra um espaço com o agente e envie-lhe uma mensagem, ou mencione-o com @ num espaço existente.
3. Volte a **Definições → Espaço de trabalho → Agentes**, selecione o agente e abra o separador **Registos**. Deverá aparecer uma execução com um distintivo de estado, uma duração, a hora de início e o adaptador que utilizou. **Visualizar** abre o fluxo de eventos dessa execução.

Se não aparecer nenhuma execução, siga [Diagnosticar um agente](/pt-PT/manual/guias/diagnosticar-agente/).

## Eliminar um agente

Selecione-o na lista. No separador **Definições**, desça até à **Zona de perigo**, na parte inferior do formulário, e clique em **Eliminar**.
