Este guia mostra como dar ao seu servidor uma GitHub App própria. Demora cerca
de dois minutos, só o proprietário do servidor o faz e só tem de acontecer uma
vez por servidor.

:::note[Pode não precisar disto]
Com o Control Center Connect ativado, as pessoas iniciam sessão no GitHub
através da App partilhada do Control Center, ou da App que o Connect da sua
organização usa. Registe a sua quando tiver escolhido **Usar as minhas próprias
apps**: a app própria do servidor só é usada nesse caso. Consulte
[Control Center Connect](/pt-PT/manual/referencia/connect/).
:::

Para iniciar sessão com a sua própria conta posteriormente, consulte
[Configurar a integração com o GitHub](/pt-PT/manual/guias/integracao-github/).

## O que a app faz

Um único registo dá resposta a duas tarefas diferentes:

| Tarefa                         | O que lhe responde                                 | Porque é que importa                                                                             |
| ------------------------------ | -------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **Uma pessoa inicia sessão**   | O ID de cliente e o segredo de cliente da app      | Cada pessoa recebe uma credencial do GitHub só sua, no servidor, em todos os dispositivos        |
| **O servidor atua**            | O ID da app e a chave privada                      | Agentes, pipelines, processos de sondagem e respostas do bot recebem tokens para um repositório de cada vez |

A segunda tarefa nunca pede emprestada a credencial de uma pessoa por inteiro.
Cada token que o servidor emite abrange um único repositório e está limitado ao
que um membro responsável pode fazer nele. Ler um repositório ligado só exige a
app; tudo o que escreva exige um membro que possa fazer push. A automação nunca
aprova uma pull request.

A app própria do servidor só se aplica em **Usar as minhas próprias apps**. Com as
apps do Control Center ou um Connect próprio, o Connect executa todas as faixas,
incluindo a do GitHub; a app do servidor continua guardada, mas sem uso, até voltar a
trocar. Um espaço de trabalho com as próprias apps
([Dar a um espaço de trabalho uma app própria](#dar-a-um-espaço-de-trabalho-uma-app-própria))
usa a app própria dele no lugar, qualquer que seja o modo do servidor. Uma app com alguns campos em falta é um erro, e não
um motivo para recorrer a outra coisa: os inícios de sessão no GitHub são recusados até
que todos os campos estejam definidos.

## Pré-requisitos

- É o **proprietário do servidor**. O cartão **Aplicações do fornecedor** é
  invisível para toda a gente
- Uma conta do GitHub. A app é criada nela
- Um endereço do servidor que o seu navegador consiga alcançar. O URL público
  do servidor (ou o loopback, no caso do servidor do próprio computador) é para
  onde o GitHub o envia de volta

## Criar com um clique

1. Vá a **Definições → Servidor → Início de sessão único** e desloque-se até ao
   cartão **Aplicações do fornecedor**
2. No bloco **GitHub**, escreva, se quiser, a organização do GitHub que deve ser
   proprietária da app em **Organização (opcional)**. Deixe em branco para criar
   a app na sua própria conta; criá-la numa organização exige um proprietário
   dessa organização
3. Clique em **Criar a minha app do GitHub**
4. O navegador abre o GitHub com a app já preenchida. Clique em
   **Create GitHub App**
5. O GitHub envia-o de volta para o servidor, que guarda o ID da app, a chave
   privada, o ID de cliente e o segredo de cliente e, em seguida, abre a página
   de instalação da app

Nada é copiado à mão, e o código de conversão vai diretamente do GitHub para o
seu servidor. A ligação funciona uma única vez e expira ao fim de dez minutos;
se expirar, clique de novo em **Criar a minha app do GitHub**.

A app chama-se `Control Center <code>` e pede exatamente o que o Control Center
usa:

| Permissão                                  | Acesso              |
| ------------------------------------------ | ------------------- |
| Metadata                                   | Leitura             |
| Contents                                   | Leitura e escrita   |
| Pull requests                              | Leitura e escrita   |
| Issues                                     | Leitura e escrita   |
| Checks, Actions, Commit statuses           | Leitura             |
| Organization members                       | Leitura             |

Os webhooks ficam desativados: o servidor faz sondagem. Para transferir mais
tarde para uma organização uma app que criou na sua própria conta, use
**Transfer ownership** nas definições avançadas da app no GitHub.

Ponto de verificação: o bloco do GitHub indica “O servidor pode agir por si
próprio e as pessoas podem entrar.”

## Instalar onde estão os seus repositórios

Uma app registada mas não instalada consegue iniciar a sessão das pessoas e não
lê nada.

1. Na página de instalação que o GitHub abriu, escolha a conta ou a organização
   proprietária dos seus repositórios
2. Escolha **All repositories**, ou selecione os que este servidor deve ver

Para a instalar noutra conta mais tarde, um administrador do espaço de trabalho
vai a **Definições → Espaço de trabalho → Integrações**, encontra **Instalações do
app do GitHub** no cartão **App do GitHub**, em Hospedagem de código, e clica em
**Instalar o app do GitHub**. A lista mostra todas as contas em que a app está instalada e
assinala uma instalação suspensa.

## Partilhar a instalação de uma organização

Uma organização instala a GitHub App uma única vez. Depois disso, qualquer pessoa da organização que inicie sessão no GitHub num servidor do Control Center pode usar a instalação, seja qual for esse servidor: o seu, o de um colega ou um próprio. Não há nada a autorizar por servidor.

Cada token que um servidor recebe é da própria pessoa que iniciou sessão, limitado a um repositório e ao seu papel nele, por isso nunca vai além do que ela poderia fazer no GitHub. O registo de auditoria do GitHub mostra essa pessoa, a atuar através da app.

Para impedir que o Control Center alcance uma organização, um proprietário da organização remove a instalação ou reduz os repositórios no GitHub. Remover uma pessoa da organização também termina o acesso dela.

## Registar manualmente

O cartão **Aplicações do fornecedor** também aceita os valores diretamente,
para uma app que registou por si:

| Grupo                          | Campos                                                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------------------------------ |
| **Agir como o servidor**       | **Id da aplicação** e **Chave privada** (o `.pem` completo, incluindo as linhas `BEGIN` e `END`)       |
| **Entrada das pessoas**        | **Id de cliente** e **Segredo de cliente**. **URLs de callback** mostra o URL a registar, tal como está |
| **Conversas de pull request**  | **Login do bot**, resolvido quando testa a ligação                                                     |

Registe a callback URL `<server origin>/oauth/github/callback` exatamente como
o cartão a mostra, deixe **Expire user authorization tokens** ativado e conceda
as permissões da tabela acima. Clique em **Testar**: pergunta ao GitHub em que
contas a app está instalada, para que “guardado” e “funciona” não se
confundam.

## Configurar a partir do `.env` do servidor

Numa instalação headless ou automatizada, o servidor preenche cada campo a
partir do ficheiro `.env` na primeira vez que não tem nenhum valor guardado:

```bash
GITHUB_APP_ID=123456
GITHUB_CLIENT_ID=Iv23li0123456789abcd
GITHUB_CLIENT_SECRET=<secret>
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIEow…\n-----END RSA PRIVATE KEY-----"
```

Coloque a chave numa **única linha**: um valor do `.env` ocupa uma linha, e
`\n` entre aspas duplas é descodificado como mudança de linha. O servidor
recusa-se a arrancar quando `GITHUB_APP_PRIVATE_KEY` ou `GITHUB_CLIENT_SECRET`
é exportado no ambiente do processo, onde qualquer processo filho o poderia
ler; mantenha-os no ficheiro `.env` (no Docker, monte-o em `/app/bin/.env`). O
preenchimento acontece **uma vez por campo**, pelo que o que edita nas
Definições não é desfeito no reinício seguinte.

## Dar a um espaço de trabalho uma app própria

Um espaço de trabalho pode usar uma app própria em vez da do servidor:

1. Um administrador do espaço de trabalho vai a **Definições → Espaço de trabalho → Integrações**
2. No cartão **Control Center Connect**, escolhe **Usar as minhas próprias apps** e clica em **Aplicar**. Todos no espaço de trabalho voltam a iniciar sessão, pelas apps do espaço de trabalho
3. O cartão **App do GitHub**, em Hospedagem de código, passa a ter os campos dessa app: **Id da aplicação** e **Chave privada** em **Atuando por este espaço de trabalho**, **Id de cliente** e **Segredo de cliente** em **Entrada das pessoas**. Clique em **Testar** assim que estiverem definidos

Os membros passam então a iniciar sessão nessa app para este espaço de trabalho. Um espaço de trabalho com as próprias apps nunca recorre à app do servidor nem ao Connect: enquanto os campos dele não estiverem completos, o trabalho dele no GitHub é recusado. A mesma escolha vale para o Google Calendar, o Linear e a pesquisa de GIFs, cada um com os próprios campos ao lado do respetivo provedor, na mesma página. Consulte
[Dê ao espaço de trabalho a sua própria aplicação do Linear](/pt-PT/manual/guias/integracao-linear/#dê-ao-espaço-de-trabalho-a-sua-própria-aplicação-do-linear)
e [Dê ao espaço de trabalho o seu próprio cliente Google](/pt-PT/manual/guias/ligar-calendario/#dê-ao-espaço-de-trabalho-o-seu-próprio-cliente-google).
As outras escolhas desse cartão, e o que cada uma faz, estão em
[Escolha por espaço de trabalho](/pt-PT/manual/referencia/connect/#escolha-por-espaço-de-trabalho).

## Resolução de problemas

### “Criar a minha app do GitHub” diz que o servidor não tem endereço

O servidor não tem um URL público para o qual um navegador possa voltar.
Defina `CC_SERVER_PUBLIC_URL` (ou `--public-url`) e tente novamente.

### O GitHub diz que a ligação expirou

A página de utilização única já foi usada, ou passaram dez minutos. Recomece a
partir das Definições.

### O teste diz que as credenciais funcionam mas a app não está instalada em lado nenhum

O registo e a instalação são passos separados. Abra a página de instalação da
app ou use **Instalar o app do GitHub** em Espaço de trabalho → Integrações.

### O teste diz que não foi possível ler a chave privada

Cole o ficheiro `.pem` completo, incluindo as linhas `-----BEGIN` e `-----END`.
Uma chave `ed25519` ou EC não pode ser usada: as GitHub Apps assinam com RSA.

### Um membro iniciou sessão mas não vê repositórios

A app não está instalada na conta que é proprietária deles, ou a sua instalação
seleciona repositórios diferentes. Um início de sessão só concede o que a app
tem permissão para ver.

### Os agentes dizem que a instalação da GitHub App está suspensa

Alguém suspendeu a instalação no GitHub. Reative-a em
**Settings → Applications → Installed GitHub Apps** da conta.
