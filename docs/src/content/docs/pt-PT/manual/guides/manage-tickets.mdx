Este guia mostra-lhe como criar e gerir tickets.

## Criar um ticket

### A partir da interface

1. Clique em **Tickets** na barra lateral do espaço de trabalho.
2. Clique em **Novo ticket**.
3. Preencha:
   - **Título** — resumo curto. É o único campo obrigatório.
   - **Descrição** — markdown, com uma barra de ferramentas de formatação.
   - **Status** — **A fazer** (a predefinição) ou **Backlog**. Os estados
     iniciados e terminais alcançam-se através do ciclo de vida, não na criação.
   - **Prioridade** — nenhuma, urgente, alta, média ou baixa.
   - **Responsável** — o próprio utilizador ou qualquer agente do espaço de
     trabalho.
   - **Projeto** — agrupamento opcional.
4. Clique em **Criar**, ou ative primeiro **Criar mais** para manter a caixa de
   diálogo aberta para introduções rápidas.

Não existe nenhum seletor de fornecedores na caixa de diálogo. O ticket é criado
no fornecedor de tickets ativo do espaço de trabalho.

### A partir de um agente

Peça a um agente num espaço:

> Cria um ticket para corrigir o problema de tempo limite de início de sessão em ligações lentas.

Chama a ferramenta MCP `create_ticket`. A prioridade nessa ferramenta é um
**inteiro**, não um nome:

```
create_ticket(
  workspace_id: "...",
  title: "Fix login timeout on slow connections",
  description: "...",
  priority: 2
)
```

| Valor | Prioridade |
| ----- | ---------- |
| `0`   | Nenhuma    |
| `1`   | Urgente    |
| `2`   | Alta       |
| `3`   | Média      |
| `4`   | Baixa      |

Só `workspace_id` e `title` são obrigatórios; `description`, `priority`,
`assignee` (um id de agente) e `team_id` são opcionais. A ferramenta está
classificada como uma escrita de sincronização de fornecedor e pede a sua
aprovação antes de ser executada.

## Atualizar o estado de um ticket

Os tickets seguem este ciclo de vida:

```
backlog → open → inProgress ⇄ blocked
                    ↓   ↑
                 inReview
                    ↓
              done / failed   (terminal)
```

`done`, `failed` e `cancelled` são terminais. `cancelled` é alcançável a partir
de qualquer estado não terminal. `done` e `failed` são alcançáveis a partir de
`inProgress` ou `inReview`; `open` também pode passar diretamente a `blocked`. O
seletor de estados da interface lista todos os estados exceto `failed` — os
agentes marcam-no com `fail_ticket`.

Para o alterar, use uma das seguintes opções:

- a linha **Status** no painel de propriedades do ticket,
- o submenu **Status** no menu de contexto de um ticket na lista,
- o botão **Status** na barra flutuante depois de selecionar vários tickets.

:::note[O grafo do ciclo de vida vincula os agentes, não o utilizador]
Todas as alterações de estado feitas na interface são forçadas, contornando o
grafo por completo — pode mover um ticket para qualquer estado que o seletor
apresente, incluindo reabrir um `done`, `failed` ou `cancelled`. O seletor não
oferece `failed` como destino. O diagrama acima rege os agentes e a
automatização: uma transição ilegal tentada por uma ferramenta MCP ou por um
reconciliador é registada e ignorada, não aplicada.
:::

As alterações de estado emitem eventos de domínio (`TicketStatusChanged`,
`TicketCompleted` e outros) que podem acionar pipelines. Ver
[Configurar disparadores de pipeline](/pt-PT/manual/guias/disparadores-de-pipeline/).

## Atribuir um ticket

1. Abra o ticket.
2. No painel de propriedades, defina **Responsável** — o próprio utilizador,
   outro membro do espaço de trabalho ou um agente.

:::caution[A atribuição não inicia nenhum trabalho]
A atribuição regista a propriedade e mais nada. Não cria nenhum espaço, não
altera nenhum estado e não despacha nenhum agente — `TicketAssigned` é um sinal
de auditoria puro, sem nenhum despachante por trás. Para pôr um agente a
trabalhar, envie-lhe uma mensagem num espaço
(ver [Conversar com um agente](/pt-PT/manual/guias/conversar-com-agente/)).

A única exceção: `TicketAssigned` é um tipo de evento ao qual pode associar um
disparador de pipeline, para que um modelo seu possa reagir a uma atribuição.
:::

## Adicionar etiquetas

As etiquetas são aplicadas em massa a partir da lista de tickets, e não a partir
de um ticket isolado — o painel de propriedades não tem nenhum controlo de
etiquetas.

1. Passe o cursor sobre uma linha da lista de tickets e marque a respetiva caixa
   de verificação. Marque tantas quantas precisar; aparece uma barra flutuante
   assim que algo estiver selecionado.
2. Nessa barra, abra o botão **Etiquetas**.
3. Escolha uma etiqueta. É adicionada a todos os tickets selecionados que não a
   tenham; as etiquetas existentes nunca são eliminadas. **Limpar etiquetas**
   remove-as todas. O seletor lista as etiquetas já presentes num ticket do
   espaço de trabalho. Os agentes podem adicionar um novo nome através de
   `update_ticket` ou `tickets.patch`.

## Ligar tickets

As relações estão no cartão **Relações** do ticket, no painel de propriedades,
ou atrás de **Relacionar com** no menu de contexto da lista.

1. Abra o ticket e localize o cartão **Relações**.
2. Clique no respetivo controlo de adição e escolha a relação:

| Relação            | Significado                            |
| ------------------ | -------------------------------------- |
| **Subtarefa de…**  | O ascendente deste ticket é o outro    |
| **Pai de…**        | O outro ticket é filho deste           |
| **Bloqueado por…** | Este ticket está bloqueado pelo outro  |
| **Bloqueando…**    | Este ticket bloqueia o outro           |
| **Relacionado a…** | Simétrica, sem direção implícita       |
| **Duplicado de…**  | Este ticket duplica o outro            |

3. Escolha o ticket de destino.

**Duplicado por** aparece no cartão mas não no seletor — é o inverso de
**Duplicado de** e é definido a partir do outro ticket. Cada relação listada é
clicável para abrir o ticket ligado e removível ao passar o cursor.

As relações de ascendente e de subtarefa são armazenadas no próprio ticket e não
como linhas de ligação, pelo que eliminar um ascendente se propaga em cascata
aos respetivos filhos (ver abaixo), enquanto as ligações de bloqueio e de
relação não o fazem.

## Adicionar colaboradores

Os colaboradores são uma lista associada ao ticket — quem está envolvido e em que
função.

1. Abra o ticket.
2. Clique no controlo «pessoa +» no cartão **Adicionar colaborador**.
3. Escolha um agente.

As três funções são **assignee**, **collaborator** (a predefinição) e
**reviewer**. O seletor da interface só lista agentes do espaço de trabalho e
escreve sempre a função predefinida; os humanos podem aparecer como linhas, mas
não são oferecidos nesse menu. A ferramenta MCP `add_ticket_collaborator` aceita
uma `role`.

Adicionar um colaborador escreve uma linha e não publica nenhum evento de
domínio; não concede acesso a nenhum espaço. Para colocar um agente numa
conversa, adicione-o antes como participante a partir do cabeçalho do espaço —
ver [Usar espaços](/pt-PT/manual/guias/espacos/).

## Eliminar um ticket

Use **Eliminar ticket** na parte inferior do painel de propriedades, no menu de
contexto, ou a ação de eliminação da barra flutuante depois de selecionar vários
tickets.

:::caution[A eliminação é apenas local]
Um ticket proveniente de um gestor externo não é aí eliminado — nenhum
fornecedor o suporta — pelo que pode reaparecer na sincronização seguinte. A
eliminação também se propaga em cascata: os colaboradores do ticket e quaisquer
tickets filhos desaparecem com ele.
:::
