Este guia mostra como ligar fornecedores de modelos e escolher aquilo em que um
agente é executado.

Está tudo numa única página: **Definições → Servidor → Fornecedores de modelos**.
A entrada da barra lateral secundária diz «Fornecedores de modelos»; o título da
página diz «Adaptadores».

## O que é um adaptador

Um adaptador é o _executor_ que executa um turno de agente. Existem dois e a
lista é fixa — não é possível acrescentar um terceiro.

| Adaptador                 | CLI      | Transporte                                                 |
| ------------------------- | -------- | ---------------------------------------------------------- |
| Control Center (built-in) | nenhum   | Ciclo de agente em processo, comunica com os fornecedores por HTTP |
| Claude Code               | `claude` | `claude -p --output-format stream-json`                    |

O Cursor, o Codex, a Anthropic, a OpenAI e os restantes são **fornecedores** do
adaptador integrado, e não CLIs separadas. O que _pode_ acrescentar é outro
fornecedor — qualquer endpoint compatível com OpenAI ou Anthropic. É disso que
trata a secção seguinte.

:::note[A deteção sonda o servidor, não a sua máquina]
O cartão **Executores detectados** lista o que o `cc_server` encontrou no `PATH`
do _anfitrião do servidor_. Num cliente leve ou web, essa é uma máquina diferente
daquela que está a ver. Instale a CLI na máquina que executa o `cc_server`.
:::

## Ligar um fornecedor de modelos

O adaptador integrado precisa de pelo menos um fornecedor ligado antes de poder
ser executado. O catálogo inclui catorze.

1. Vá a **Definições → Servidor → Fornecedores de modelos**
2. Desça até **Fornecedores e modelos**
3. Encontre o seu fornecedor e ligue-o:

| Fornecedor                                                                                               | Como ligar                                                                                                                    |
| -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Anthropic                                                                                                | Chave de API. Uma subscrição Claude Pro/Max não é um início de sessão na API da Anthropic — para esse plano, use o adaptador Claude Code |
| OpenAI, Codex, Cursor                                                                                    | Início de sessão OAuth no navegador ou uma chave de API. O Codex é ChatGPT Plus/Pro através do backend Codex Responses, e não um processo CLI lançado |
| Kimi Code                                                                                                | Apenas OAuth no navegador — um fluxo por código de dispositivo. É um plano de tarifa fixa, por isso não tem preço por token  |
| OpenRouter, Google Gemini, DeepSeek, Mistral, xAI, z.ai, z.ai GLM Coding Plan, Moonshot (Kimi API)       | Chave de API                                                                                                                  |

Verificação: o distintivo da linha passa a «ligado» e, ao expandi-la, são
listados os modelos que esse fornecedor serve, cada um com o seu preço por
milhão de tokens e a janela de contexto.

Os tokens OAuth ficam no armazenamento de credenciais do próprio servidor e são
renovados antes de expirarem. As credenciais dos fornecedores são **globais ao
anfitrião** — são partilhadas por todos os espaços de trabalho da instalação, e
não estão limitadas a um.

### Adicionar um fornecedor personalizado

Use isto para o Ollama, o LM Studio, o vLLM ou uma implementação privada.

1. Em **Fornecedores e modelos**, em **Fornecedores personalizados**, carregue em
   **Adicionar fornecedor**
2. Preencha um **nome**, escolha o **tipo de API** (compatível com OpenAI ou
   compatível com Anthropic) e indique a **URL base** (por exemplo
   `http://localhost:11434/v1`)
3. Adicione uma **chave de API** se o endpoint precisar de uma e, em seguida,
   carregue em **Adicionar fornecedor**

Um fornecedor personalizado aparece na mesma lista, com um botão de eliminação
que os seus congéneres integrados não têm.

## Escolher um modelo para um agente

1. Vá a **Definições → Espaço de trabalho → Agentes** e selecione o agente
2. No separador **Definições**, escolha o **adaptador**
3. Escolha o **modelo** na lista pendente ao lado

No caso do adaptador integrado, a lista pendente é composta em tempo real a
partir do catálogo de cada fornecedor ligado. Um fornecedor sem credencial
guardada contribui com zero modelos, e é por isso que uma lista pendente vazia
significa quase sempre «ainda nada ligado» e não «nada disponível».

:::note[O models.dev é enriquecimento, nunca uma fonte de ids]
O catálogo [models.dev](https://models.dev) incluído fornece o preço e a janela
de contexto de um modelo que já conste da lista em tempo real. Nunca acrescenta
um id de modelo. Se falta um modelo que esperava, é porque o endpoint do
fornecedor não o devolve.
:::

Os ids de modelo do adaptador integrado são qualificados como `provider/model` e
podem incluir uma cadeia de recurso separada por `|`. Em caso de recurso, o custo
é calculado em função do modelo que serviu efetivamente o turno, e não daquele
que pediu.

:::note[Um agente sem adaptador é executado no ciclo integrado]
Cada espaço de trabalho cria cinco agentes — um CEO mais `qa`, `architect`,
`engineer` e `librarian` — sem adaptador e sem modelo. O despacho recorre a
**Control Center (built-in)**, e não à definição **Executores padrão** desta
página, que é uma preferência do cliente que o percurso de despacho nunca lê. O
registo de execução regista `cc-harness` para essas execuções, de modo que o
transcript indica o que foi realmente executado.

Também sem modelo, o ciclo integrado pede à Anthropic o seu modelo predefinido.
Por isso, um agente totalmente por configurar é executado se tiver uma conta
Anthropic ligada e, caso contrário, falha com
`No credential for provider "anthropic"`.

Concluir o passo do adaptador da configuração inicial aplica retroativamente a
**todos** os agentes aos quais ainda falta um adaptador ou um modelo — CEO e
especialistas, em todos os espaços de trabalho existentes nesse momento — o par
que escolheu. Os espaços de trabalho criados mais tarde continuam a criar os
cinco sem configuração. Defina explicitamente o adaptador e o modelo em todos os
agentes que pretende utilizar.
:::

## Instalar uma CLI de executor

O adaptador integrado não precisa de instalação. Para o Claude Code, instale a
respetiva CLI **no anfitrião do servidor** com o gestor de pacotes da própria
ferramenta, por exemplo:

```bash
npm install -g @anthropic-ai/claude-code
```

Em seguida, carregue em **Atualizar** no topo da página. Cada linha detetada
mostra a versão e o caminho resolvidos, além de etiquetas que indicam se suporta
o modo JSON e a seleção de modelo.

Uma CLI externa mantém as suas próprias credenciais, na sua própria configuração,
no anfitrião do servidor. O Control Center não as gere.

:::caution[Os argumentos do adaptador e as variáveis de ambiente ficam neste dispositivo]
Cada linha de adaptador oferece um campo **Argumentos** e uma caixa de diálogo
**Variáveis de ambiente**. Esses valores são guardados no seu dispositivo. O
servidor lê o argv de lançamento e as variáveis de ambiente do seu próprio
armazenamento de definições. Coloque as chaves dos fornecedores no servidor
(OAuth ou o campo de chave na página Fornecedores de modelos), e não nesses dois
campos.
:::

## Restringir que fornecedores um espaço de trabalho pode usar

A governação de fornecedores é por espaço de trabalho e é avaliada com a última
correspondência a prevalecer.

1. Em **Fornecedores e modelos**, desative o interruptor **Permitir** numa linha
   de fornecedor

Isso escreve uma instrução `deny` para esse fornecedor no espaço de trabalho
ativo, e os seus modelos desaparecem do catálogo desse espaço de trabalho. Voltar
a ligar o interruptor remove a instrução.

## Resolução de problemas

### Um executor aparece como não encontrado

- Verifique se a CLI está no `PATH` do **anfitrião do servidor**, e não apenas no
  seu
- Uma aplicação de ambiente de trabalho lançada pela GUI inicia o seu servidor
  com um `PATH` mínimo; uma CLI instalada num caminho exclusivo da shell pode
  ser-lhe invisível
- Carregue em **Atualizar** depois de instalar

### A lista pendente de modelos está vazia

- O adaptador é o integrado e não há nenhum fornecedor ligado — ligue um em
  **Fornecedores e modelos**
- Ou o fornecedor está ligado, mas foi negado pelo interruptor de governação
  deste espaço de trabalho

### Um modelo é executado, mas o preço aparece como desconhecido

A lista de modelos em tempo real contém o id; o preço e o contexto vêm do
models.dev. Um modelo totalmente novo, ou um de um fornecedor personalizado,
ainda não tem entrada no catálogo.
