Este guia mostra-lhe como encher um espaço de trabalho com skills do GitHub:
adicione um repositório como fonte, instale as skills que quiser a partir dele e
mantenha-as atualizadas ao longo do tempo. Também pode avaliar uma revisão
guardada em relação a uma linha de base emparelhada antes de decidir se a
mantém.

O que é importante saber antes de começar: **um repositório de origem não é de
confiança.** O nome, a descrição e o número de estrelas dele são escritos por
quem é dono do repositório. Cada instalação passa pelo portão de análise
antivírus antes de qualquer coisa chegar ao disco ou ao prompt de um agente.
Esse veredicto é uma verificação de admissão, não prova de que uma skill seja
segura ou útil. Leia a
[secção de skills do modelo de agentes](/pt-PT/manual/conceitos/modelo-de-agentes/)
para o modelo de instalação e [Avaliações e
qualidade](/pt-PT/manual/conceitos/avaliacoes-e-qualidade/) para perceber como
as evidências de comportamento diferem de uma análise.

As skills ficam em **Definições → Espaço de trabalho → Habilidades**
(`/workspaces/<id>/settings/workspace/skills`). Têm âmbito de espaço de
trabalho: as skills que aqui instalar pertencem apenas a este espaço de trabalho.
A página tem dois separadores: **Instaladas** (skills locais, incluindo um editor
**Nova competência**) e **Fontes** (catálogos do GitHub). Ambas as gravações
passam pelo mesmo portão de análise.

## Adicionar um repositório de skills

1. Abra **Definições → Espaço de trabalho → Habilidades** e mude para o
   separador **Fontes**.
2. Clique em **Adicionar repositório**.
3. Cole o URL de um repositório do GitHub, por exemplo
   `https://github.com/anthropics/skills`, e confirme.

O servidor verifica que o repositório existe e está visível com as respetivas
credenciais, e depois adiciona-o à barra lateral esquerda. Não há nenhuma loja
curada pelo meio: qualquer repositório do GitHub serve, o que também significa
que julgar a reputação fica a seu cargo — o número de estrelas é um indício,
nunca uma garantia.

As skills de um repositório são os diretórios que contêm um `SKILL.md` (até três
níveis de profundidade, mais o esquema de mercado de plugins do Claude
`plugins/<plugin>/skills/<skill>`, com as árvores de dependências e de código de
terceiros ignoradas). Se a grelha disser mais tarde que o repositório não tem
skills, é exatamente isso que significa: nenhum diretório nele corresponde à
convenção de skills.

## Inspecionar uma skill antes de instalar

Selecione um repositório na barra lateral; as skills dele aparecem como uma
grelha à direita, com um campo de filtro por cima que restringe o catálogo por
nome, descrição ou slug. Clique num cartão para abrir a vista de detalhes. Esta
mostra três coisas:

- **O README**, renderizado como markdown — o `README.md` do diretório da skill,
  ou o corpo do `SKILL.md` quando não há README.
- **A pré-visualização da análise** — o veredicto (`pass`, `warn` ou
  `quarantine`), as capacidades que o conteúdo da skill declara (executa shell,
  escreve ficheiros, acesso à rede…) e cada constatação que o analisador
  registou.
- **A contagem de ficheiros** — uma instalação escreve o diretório inteiro da
  skill, e não apenas o `SKILL.md` dela.

A pré-visualização analisa exatamente os bytes que uma instalação escreveria,
pelo que o veredicto que vê é o veredicto que a instalação recebe; nada é
reavaliado à sua revelia.

## Instalar uma skill

1. Abra a vista de detalhes da skill.
2. Leia o veredicto da análise. Para um veredicto `warn` ou `pass`, clique em
   **Instalar**.
3. Para um veredicto `quarantine`, a instalação mantém-se desativada até
   assinalar **Compreendo o risco — instalar mesmo assim**. Essa exceção é
   registada, não presumida.

A instalação escreve o diretório da skill no espaço de trabalho, regista um pin
em `skills-lock.json` (repositório de origem, caminho, o commit de onde veio e
um hash de conteúdo), e a skill passa a estar disponível para os agentes do
espaço de trabalho. Um cartão marcado com **Nome em uso** significa que outra
skill já detém esse nome localmente — desinstale primeiro essa.

## Atualizar skills ao longo do tempo

Os cartões das skills instaladas ostentam distintivos: **Instalada**, ou
**Atualização disponível** quando o repositório avançou para além do commit que
fixou. Abra a vista de detalhes e clique em **Atualizar** para voltar a obter a
skill no novo commit. Uma atualização passa pelo mesmo portão de análise que uma
instalação — uma skill cuja nova versão fica em quarentena é recusada e a versão
que tinha permanece no lugar. O hash da versão antiga é guardado como referência
de reversão no ficheiro de lock.

## Avaliar uma skill

1. Abra **Definições → Espaço de trabalho → Habilidades**, selecione a skill
   instalada e guarde as alterações. Em **Avaliação de skill**, confirme o hash
   do pacote.
2. Selecione **Iniciar avaliação**. Escolha um **Conjunto de tarefas** adequado
   ao propósito da skill e um **Adaptador**. O harness integrado usa um
   fornecedor configurado e um modelo capaz de usar ferramentas. O **Claude Code**
   usa a conta Claude gerida predefinida e um identificador de modelo concreto;
   inicie sessão primeiro em **Definições → Adaptadores**. Não toma de empréstimo
   o início de sessão pessoal do operador do servidor.
3. Escolha uma **Comparação** na tabela abaixo.
4. Defina **Repetições por tarefa** (1–20) e **Orçamento (centavos de US$)**. Por
   exemplo, `100` significa 1 dólar americano. Selecione **Iniciar avaliação**
   para autorizar trabalho pago no fornecedor.
5. Acompanhe a campanha em **Observabilidade → Qualidade**, ou regresse através
   de **Abrir Qualidade** no painel da skill.

Para subscrições do **Claude Code** e do **Codex OAuth**, o orçamento é um
**limite de paragem de utilização equivalente à API**, não um limite de fatura
nem uma medida da quota da subscrição. `100` admite um limite de 1 dólar
americano: uma chamada em curso pode ultrapassá-lo, mas não começa nenhuma
chamada nova quando a utilização comunicada o atinge. Utilização desconhecida
também interrompe novas chamadas. Um orçamento pequeno pode deixar a comparação
parcial; não promete a conclusão do conjunto de tarefas selecionado.

Os fornecedores com chave de API mantêm reservas conservadoras por chamada, com
base em limites de tokens e preços documentados. Podem recusar `100` antes de
gastar quando uma única chamada reservada em segurança precisa de mais. O erro
identifica o modelo selecionado e a reserva mínima; escolha um modelo mais barato
ou aumente esse orçamento.

| Comparação | Utilize-a para responder |
| --- | --- |
| **Ausente vs. disponível** | A descoberta e a utilização normais desta skill melhoram o resultado em comparação com não a ter? |
| **Anterior vs. atual** | A atualização preserva ou melhora o comportamento em relação a uma revisão capturada anteriormente? |
| **Carregamento forçado vs. ausente** | O conteúdo pode ajudar quando é carregado explicitamente? Isto diagnostica problemas de carregamento; não demonstra a descoberta normal. |
| **Composição** | Acrescentar o candidato ajuda ou entra em conflito com as skills de ambiente selecionadas? A linha de base mantém o mesmo inventário de ambiente sem o candidato. |

**Anterior vs. atual** precisa de um hash de pacote do histórico de campanhas.
Avalie uma revisão antes de a substituir, se quiser usá-la como linha de base;
histórico Git arbitrário não é importado.

Alterações não guardadas, um hash indisponível e o modo de demonstração apenas
de leitura desativam o arranque. O servidor também verifica o acesso ao espaço de
trabalho e ao repositório, a quarentena da análise, a política de ações, o
suporte de modelos, os preços e o isolamento da execução. Resolva uma verificação
falhada em vez de a contornar. A identidade do fornecedor e do modelo é
registada, mas um alias de modelo remoto não congela os pesos subjacentes do
fornecedor.

### Inspecionar, cancelar e exportar

Leia a cobertura e o gasto a par dos resultados por tarefa e das regressões.
Abra tentativas individuais para inspecionar carregamentos de skills observados,
eventos de ferramentas, erros e evidências dos verificadores. Resultados
**parciais**, **desatualizados** e **inconclusivos** não são recomendações para
adotar uma revisão. O hash de um relatório identifica o pacote capturado, não
necessariamente o pacote atualmente instalado.

Use **Cancelar execução** para trabalho em fila ou ativo. As tentativas
concluídas continuam visíveis; o cancelamento não reembolsa o trabalho já
realizado no fornecedor. **Copiar JSON com dados ocultados** copia para a área de
transferência uma exportação de evidências limitada, não um pacote completo de
reprodução do código-fonte privado. Veja [Avaliações e
qualidade](/pt-PT/manual/conceitos/avaliacoes-e-qualidade/) para evidências e
limites da plataforma.

### Reavaliar após atualizações

A reavaliação paga automática está **desativada por predefinição**. Depois de
avaliar a revisão atual, escolha uma campanha em **Configuração da política de
atualização** e selecione **Ativar avaliações de atualização**. Alterar esta
política exige permissão de administrador do espaço de trabalho. A campanha
escolhida fornece o conjunto de tarefas, o adaptador, o fornecedor/modelo, a
comparação, as repetições e o orçamento.

Alterações de conteúdo admitidas depois disso agendam trabalho com orçamento;
hashes inalterados são deduplicados. **Desativar avaliações de atualização**
impede admissões automáticas futuras. Use **Cancelar execução** para uma campanha
já admitida. Os relatórios históricos permanecem ligados aos hashes de pacote
originais; a reavaliação não publica, não ativa nem reescreve uma skill.

## Desinstalar uma skill, remover um repositório

**Desinstalar** (na vista de detalhes de uma skill instalada, ou eliminando no
separador Instaladas) remove em conjunto o diretório da skill e o respetivo pin
de lock — uma skill desinstalada não deixa nada para trás.

**Remover um repositório** da barra lateral remove apenas o catálogo: as skills
que instalou a partir dele continuam instaladas e continuam a ser atualizadas,
porque um pin regista o repositório pelo nome e não por referência à entrada da
fonte. Volte a adicionar o repositório se o quiser navegar outra vez.

## Invocar uma skill

As skills são invocadas sob o seu próprio espaço de nomes, pelo que nunca
colidem com os comandos slash integrados (`/plan`, `/goal`, `/loop`,
`/compact`):

- `/skill:<name>` — uma skill instalada neste espaço de trabalho, ou associada
  ao agente
- `/skill:<repo>:<name>` — uma skill fornecida por um repo com checkout neste
  espaço

Um nome simples que não seja integrado continua a ser resolvido, para mensagens
escritas antes de o espaço de nomes existir. `/skill:plan` é o que alcança uma
skill chamada `plan`; `/plan` é sempre o integrado.

## Skills com âmbito de repo

Um repo com checkout pode trazer skills próprias, em `.agents/skills/`,
`.agent/skills/`, `.claude/skills/`, `.opencode/skills/` ou `skills/`. Essas
**não** são instaladas através desta página. Um agente transporta apenas as
skills do repo em que está a trabalhar no momento; elas são trocadas quando ele
muda. O compositor não tem esse âmbito: `/skill:<repo>:<name>` alcança qualquer
repo do espaço.

As skills de repo passam pela mesma análise fail-closed (`pass` / `warn` /
`quarantine`) antes de o respetivo frontmatter chegar a um prompt. `warn` é
admitido; `quarantine` é retido, sem exceção por parte do operador nesse caminho.

Consulte [Skills com âmbito de
repo](/pt-PT/manual/conceitos/modelo-de-agentes/#skills-com-âmbito-de-repositório)
e [Comandos slash](/pt-PT/manual/referencia/comandos-slash/).
