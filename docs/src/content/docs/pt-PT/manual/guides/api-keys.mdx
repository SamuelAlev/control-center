Este guia mostra onde é guardada cada credencial que o Control Center utiliza e
como alterá-la.

**Nada é guardado na máquina em que está a escrever.** Todas as credenciais
residem no servidor; qual delas responde a um determinado pedido depende de
haver ou não uma pessoa por trás dele.

| Credencial                            | Onde é guardada                                            | Quem a utiliza                                                      |
| ------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------- |
| A sua credencial de forge / de tickets | O ficheiro de segredos 0600 do servidor, indexado pelo id do seu utilizador | Tudo o que pedir: a superfície de PR, as execuções dos seus agentes, as suas imagens |
| A identidade da aplicação do servidor  | O mesmo ficheiro, mais `server_settings` para o que não são segredos | Trabalho que nenhuma pessoa pediu: webhooks, sondagem de PRs, sincronização de tickets |
| Chaves de fornecedores de modelos e tokens OAuth | O armazenamento de credenciais do próprio servidor | O adaptador integrado, para todos os espaços de trabalho da instalação |
| Tokens de bot do Slack                | `<dataDir>/<workspaceId>/chat_credentials/` no servidor    | A ponte de chat desse espaço de trabalho                            |
| Credenciais de CLIs externas          | O que essa CLI utilizar                                    | Claude Code, no host do servidor                                    |

## Duas credenciais do GitHub, que respondem a perguntas diferentes

- **A sua**, obtida ao iniciar sessão (fluxo de dispositivo) ou ao colar um
  token. É a que é usada em todos os pedidos feitos *em seu nome*, pelo que um
  comentário publicado por si traz o seu nome. Outro membro não a consegue ler, e
  liga a sua própria
- **A do servidor**, obtida a partir da GitHub App que o operador registou.
  Responde a tudo o que não tem autor — pelo que o acesso ao forge não desaparece
  quando alguém sai ou renova um token

A sua é definida no cartão **Hospedagem de código**, em **Definições → Espaço de
trabalho → Perfil e identidade**; a do servidor no cartão **Aplicações do
fornecedor**, em **Definições → Servidor → Início de sessão único**. Consulte
[Configurar a integração com o GitHub](/pt-PT/manual/guias/integracao-github/) e
[Criar a GitHub App](/pt-PT/manual/guias/github-app/).

:::note[Existe também um ecrã acessível apenas por URL]
`/workspaces/<workspaceId>/api-keys` apresenta os mesmos dois cartões do
primeiro passo do onboarding. **Não tem qualquer entrada de navegação na
interface**; só é acessível escrevendo o URL. Use antes
**Definições → Espaço de trabalho → Perfil e identidade**.
:::

## Definir as chaves dos fornecedores de modelos

O adaptador integrado autentica os fornecedores por si próprio e essas
credenciais residem no servidor.

1. Vá a **Definições → Servidor → Fornecedores de modelos**
2. Desça até **Fornecedores e modelos**
3. Ligue o fornecedor — OAuth no navegador para a OpenAI, Codex, Cursor e Kimi Code; uma
   chave de API para a Anthropic e as restantes

Consulte [Gerir adaptadores e modelos](/pt-PT/manual/guias/adaptadores/) para ver a
lista completa e para adicionar um endpoint personalizado.

Estas credenciais são **globais ao host**: uma chave serve todos os espaços de
trabalho da instalação. Os tokens OAuth são renovados antes de expirarem.

As CLIs de adaptadores externos mantêm as suas próprias credenciais, na sua
própria configuração, no host do servidor — o Control Center não as gere.
Autentique o Claude Code como indica a sua própria documentação, na máquina onde o
`cc_server` é executado.

A caixa de diálogo **Variáveis de ambiente** de cada adaptador parece um lugar
onde colocar uma chave para uma delas, mas não é: escreve no seu dispositivo,
enquanto o servidor lê a sua própria cópia e nada liga as duas. Consulte
[Gerir adaptadores e modelos](/pt-PT/manual/guias/adaptadores/).

## Ligar um fornecedor de tickets

O cartão **Tickets** em **Definições → Espaço de trabalho → Geral** contém as duas
metades de uma mesma decisão: em que fornecedor residem os seus tickets e a
credencial correspondente. Escolher **Local** oculta a linha da credencial — os
tickets locais residem na própria base de dados deste servidor e não há nada a
autenticar.

A sua chave é guardada no servidor associada ao id do seu utilizador, tal como a
do forge. O servidor guarda a sua própria chave do Linear em separado
(**Aplicações do fornecedor**), que é a usada pela sincronização de tickets
quando nenhuma pessoa o pediu. A chave que um agente recebe só é injetada quando
o agente tem a capacidade **Permitir chamadas à API de tickets**. Consulte
[Configurar a integração com o Linear](/pt-PT/manual/guias/integracao-linear/).

## Renovar ou revogar

- **A sua credencial do GitHub**: carregue em **Desligar** e volte a iniciar
  sessão ou cole o novo token. Revogue a antiga no GitHub
- **A aplicação do servidor**: gere uma nova chave privada ou um novo segredo de
  cliente na página da aplicação no GitHub, cole-a em **Aplicações do
  fornecedor** e carregue em **Testar**
- **Um fornecedor de modelos**: na respetiva linha, termine a sessão (OAuth) ou
  remova a chave e volte a ligar
- **Slack**: volte a colar os tokens na caixa de diálogo de ligação. Consulte
  [Configurar a integração com o Slack](/pt-PT/manual/guias/integracao-slack/)

## Resolução de problemas

### A lista de PRs está vazia, mas o meu token funciona no `curl`

Verifique o subtítulo da linha **Hospedagem de código**. Se indicar outra origem
(“através da aplicação deste servidor”, “do ambiente”), a credencial que está a
testar não é a que responde — a sua não foi guardada.

### O token é aceite, mas pedidos posteriores falham

O token é testado tal como está guardado, pelo que a linha indica a conta por
trás dele — mas apenas a conta, não os escopos. Um token com poucos escopos
liga-se e depois falha pedidos individuais. Verifique os escopos e a validade:

```bash
curl -H "Authorization: token YOUR_TOKEN" https://api.github.com/user
```
