Este guia mostra onde é guardada cada credencial que o Control Center utiliza e
como alterá-la.

**Nada é guardado na máquina em que está a escrever.** Todas as credenciais
residem no servidor; qual delas responde a um determinado pedido depende de
haver ou não uma pessoa por trás dele.

| Credencial                            | Onde é guardada                                            | Quem a utiliza                                                      |
| ------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------- |
| O seu início de sessão de forge / de tickets | O ficheiro de segredos 0600 do servidor, indexado pelo id do seu utilizador | Tudo o que fizer: a superfície de PR, as revisões, os merges, as suas ações no Linear |
| As aplicações de fornecedor do servidor | O mesmo ficheiro, mais `server_settings` para o que não são segredos | Iniciar a sessão das pessoas e emitir tokens de um único repositório para agentes, pipelines e sondagem |
| A chave de instalação do Connect      | O mesmo ficheiro (`connect_install_key`)                   | Identificar este servidor perante o Control Center Connect          |
| Chaves de fornecedores de modelos e tokens OAuth | O armazenamento de credenciais do próprio servidor | O adaptador integrado, para todos os espaços de trabalho da instalação |
| Credenciais de bot do Slack           | `<dataDir>/<workspaceId>/chat_credentials/` no servidor    | A ponte de chat desse espaço de trabalho: os tokens da sua própria aplicação, ou a concessão selada da aplicação partilhada |
| Credenciais de CLIs externas          | O que essa CLI utilizar                                    | Claude Code, no host do servidor                                    |

## GitHub: o seu início de sessão e tokens de um único repositório

- **O seu**, obtido com **Entrar no GitHub**. É o que é usado em todos os
  pedidos feitos *em seu nome*, pelo que uma revisão publicada por si traz o seu
  nome. Outro membro não o consegue usar, e cada um inicia sessão por si. Não há
  nenhum token do GitHub para colar
- **O trabalho sem ninguém a escrever** (agentes, pipelines, sondagem,
  respostas do bot) recebe um token para um repositório de cada vez, emitido a
  partir da GitHub App do servidor ou através do Control Center Connect, e
  limitado ao que um membro responsável pode fazer aí. Nunca é o seu início de
  sessão entregue por inteiro

O seu é definido no cartão **Hospedagem de código**, em **Definições → Você → Perfil**; a aplicação do servidor no cartão
**Aplicações do fornecedor**, em **Definições → Servidor → Início de sessão
único**. Consulte
[Configurar a integração com o GitHub](/pt-PT/manual/guias/integracao-github/) e
[Criar a GitHub App](/pt-PT/manual/guias/github-app/).

O GitLab e o Bitbucket continuam a aceitar um token pessoal colado, guardado da
mesma forma. Consulte
[Ligar um host de código](/pt-PT/manual/guias/ligar-host-de-codigo/).

:::note[Existe também um ecrã acessível apenas por URL]
`/workspaces/<workspaceId>/api-keys` apresenta os mesmos cartões do
primeiro passo do onboarding. **Não tem qualquer entrada de navegação na
interface**; só é acessível escrevendo o URL. Use antes
**Definições → Você → Perfil** para os seus próprios inícios de sessão, e **Definições → Espaço de trabalho → Integrações** para o fornecedor de tickets.
:::

## Definir as chaves dos fornecedores de modelos

O adaptador integrado autentica os fornecedores por si próprio e essas
credenciais residem no servidor.

1. Vá a **Definições → Servidor → Fornecedores de modelos**
2. Desça até **Fornecedores e modelos**
3. Ligue o fornecedor — OAuth no navegador para a OpenAI, Codex, Cursor e Kimi Code; uma
   chave de API para a Anthropic e as restantes

Consulte [Gerir adaptadores e modelos](/pt-PT/manual/guias/adaptadores/) para ver a
lista completa e para adicionar um endpoint personalizado.

Estas credenciais são **globais ao host**: uma chave serve todos os espaços de
trabalho da instalação. Os tokens OAuth são renovados antes de expirarem.

O Claude Code inicia sessão através de **Contas do Claude Code** em **Definições → Servidor → Fornecedores de modelos**: cada conta recebe o seu próprio diretório de configuração no servidor, e execute aí o comando `claude auth login` que a aplicação lhe mostra.

A caixa de diálogo **Variáveis de ambiente** de cada adaptador parece um lugar
onde colocar uma chave para uma delas, mas não é: escreve no seu dispositivo,
enquanto o servidor lê a sua própria cópia e nada liga as duas. Consulte
[Gerir adaptadores e modelos](/pt-PT/manual/guias/adaptadores/).

## Ligar um fornecedor de tickets

O cartão **Tickets** em **Definições → Espaço de trabalho → Integrações** contém o lado do
espaço de trabalho: em que fornecedor residem os seus tickets e quem é o
Control Center quando trabalha lá por conta própria. Escolher **Local** oculta as linhas do
Linear — os tickets locais residem na própria base de dados deste servidor e
não há nada a autenticar.

O Linear tem dois inícios de sessão e nenhuma chave para colar: **Linear** é o
seu, para o que fizer, e está em **Definições → Você → Perfil**; a
**Automação do Linear** é a aplicação do Control Center do espaço de trabalho, ligada
por um administrador no cartão **Tickets**, para a sincronização de
tickets, os pipelines e os agentes. O servidor pode também ter uma **Chave de
API de serviço** (**Aplicações do fornecedor**) para os espaços de trabalho sem
a automação ligada. Nenhuma credencial de tickets é injetada na sandbox de um
agente; os agentes escrevem tickets através das ferramentas do Control Center,
que perguntam à regra **Escrever num rastreador externo**. Consulte
[Configurar a integração com o Linear](/pt-PT/manual/guias/integracao-linear/).

## Renovar ou revogar

- **O seu início de sessão no GitHub**: carregue em **Desligar** e depois de
  novo em **Entrar no GitHub**. Desligar também faz cair todos os tokens que o
  servidor emitiu em seu nome
- **Um token do GitLab ou do Bitbucket**: carregue em **Atualizar token**, cole
  o novo e depois revogue o antigo na forge
- **A aplicação do servidor**: gere uma nova chave privada ou um novo segredo de
  cliente na página da aplicação no fornecedor, cole-a em **Aplicações do
  fornecedor** e carregue em **Testar**
- **A chave de instalação do Connect**: o proprietário do servidor carrega em
  **Trocar a chave** no cartão **Control Center Connect**. Toda a gente que
  iniciou sessão através do Connect tem de voltar a iniciar sessão. Se não for
  possível contactar um servidor do Connect, nada muda e é-lhe oferecido
  **Rodar mesmo assim**. Consulte
  [Trocar a chave de instalação](/pt-PT/manual/referencia/connect/#trocar-a-chave-de-instalação)
- **Um fornecedor de modelos**: na respetiva linha, termine a sessão (OAuth) ou
  remova a chave e volte a ligar
- **Slack**: no caso da sua própria aplicação, volte a colar os tokens na caixa
  de diálogo de ligação. A aplicação partilhada do Control Center não tem token
  para renovar: o token de bot dela é renovado através do Connect, e
  **Desligar** revoga-o e desinstala o bot do Slack. Consulte
  [Configurar a integração com o Slack](/pt-PT/manual/guias/integracao-slack/)

## Resolução de problemas

### Um token do GitLab ou do Bitbucket funciona no `curl`, mas não aqui

Verifique a linha **Hospedagem de código**. Se indicar “Não ligado” ou pedir para
ligar de novo, o seu token não foi guardado ou foi recusado. No Bitbucket,
indique o e-mail da sua conta Atlassian juntamente com o token de API.

### Um token do GitLab ou do Bitbucket é aceite, mas pedidos posteriores falham

O token é testado tal como está guardado, pelo que a linha indica a conta por
trás dele — mas apenas a conta, não os escopos. Um token com poucos escopos
liga-se e depois falha pedidos individuais. Verifique os escopos e a validade
dele na forge.

### Um fornecedor diz que o início de sessão não está configurado neste servidor

O servidor não tem nem uma aplicação própria para esse fornecedor nem o Control
Center Connect. O proprietário do servidor escolhe uma das opções em
**Definições → Servidor → Início de sessão único**.
