Este guia mostra-lhe como ligar um cliente MCP externo — o Claude Code, um
editor, o MCP Inspector — ao próprio servidor de ferramentas do Control Center.

O Control Center regista **110** ferramentas e serve-as através do Model Context
Protocol, na versão de protocolo `2024-11-05`. Faltam famílias inteiras de
ferramentas que poderia esperar: não há ferramentas de reuniões nem de calendário
e não há ferramentas de projetos.

## Encontrar o endpoint

A superfície MCP partilha o listener principal do `cc_server`. Não existe uma
porta MCP separada.

| Endpoint | Método   | Objetivo                                                        |
| -------- | -------- | --------------------------------------------------------------- |
| `/mcp`   | `POST`   | Transporte HTTP streamable — é o que um cliente utiliza          |
| `/mcp`   | `DELETE` | Terminar uma sessão                                             |
| `/sse`   | `GET`    | Fluxo de notificações enviado pelo servidor                     |

Assim, uma instalação local predefinida fica em `http://127.0.0.1:9030/mcp`.

1. Vá a **Definições → Servidor → Servidores MCP**
2. Leia o cartão **Servidor MCP** — mostra se está em execução ou parado e a
   porta em que está a escutar

A superfície está ativa por predefinição numa instalação nova. Só o proprietário do servidor vê o token do cartão, e só ele pode iniciar ou parar o endpoint. **Iniciar ao abrir a
aplicação** controla se volta depois de um reinício; **Iniciar** / **Parar** são
controlos de sessão que não alteram essa preferência.

Por predefinição, o servidor liga-se a loopback, pelo que o endpoint só é
acessível a partir da máquina onde o `cc_server` corre, a menos que o tenha
iniciado com `--bind any`.

## Obter o token

Todos os pedidos precisam do token MCP do servidor, a partir de qualquer máquina, incluindo loopback. O servidor cria-o na primeira vez que arranca. Não há forma de o desligar nem de o limpar.

1. Em **Definições → Servidor → Servidores MCP**, encontre a linha **Token de autenticação**
2. Prima **Mostrar token** e copie-o
3. Para o substituir, prima **Rodar token**. O servidor passa para o novo token de imediato, e todos os clientes que ainda usem o antigo são recusados até lhes dar o novo

## Ligar um cliente

Aponte o seu cliente ao endpoint HTTP streamable e envie o token como `Authorization: Bearer <token>` em cada pedido, incluindo `GET /sse`. Não há outra forma de o enviar: um token no URL não é aceite. A forma exata da configuração é uma questão do seu cliente.

```json
{
  "mcpServers": {
    "control-center": {
      "type": "http",
      "url": "http://127.0.0.1:9030/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

### Claude Code

O Claude Code não deteta isto a partir de um `.mcp.json` de projeto — coloca os
servidores MCP com âmbito de projeto atrás de um pedido de aprovação que um
`claude -p` não interativo nunca responde. Passe a configuração explicitamente:

```bash
claude --mcp-config /path/to/mcp.json --strict-mcp-config
```

`--strict-mcp-config` faz com que o Claude use apenas esse ficheiro, para que o
mesmo servidor não seja também detetado a partir do projeto e registado duas
vezes.

Ponto de verificação: peça ao cliente para listar as suas ferramentas. Deverá ver
entradas `mcp__*` que abrangem tickets, espaços, memória, grafo de código e
revisão.

## O que o endpoint recusa

O token abre todas as ferramentas do servidor, por isso o endpoint também recusa tudo o que uma página web possa ter enviado, antes de olhar para o token:

| Pedido | Resposta |
| --- | --- |
| Um cabeçalho `Origin` que não é uma página desta máquina (`http://localhost`, `http://127.0.0.1` ou `http://[::1]`, em qualquer porta) | `403`, "Cross-origin requests are not accepted" |
| Um cabeçalho `Host` que não é nem o endereço e a porta de loopback deste listener nem o nome público do servidor | `403`, "Unknown host" |
| Um `POST` cujo corpo não é `application/json` | `415` |
| Nenhum token, ou um token errado | `401` |

Para servir MCP para além do anfitrião, inicie o servidor com `--bind any` e envie o token a partir da outra máquina, endereçando o servidor pelo seu nome de anfitrião público.

## Limitar cada chamada a um espaço de trabalho

Todas as ferramentas que tocam dados com âmbito de espaço de trabalho exigem
`workspace_id`, e uma chamada sem ele é recusada em vez de resolvida contra um
qualquer espaço de trabalho «atual»:

```json
{
  "workspace_id": "acme",
  "title": "Fix login bug",
  "priority": "high"
}
```

O id é o que aparece no URL do seu navegador ou da aplicação:
`/workspaces/<workspace_id>/…`. As únicas exceções são as ferramentas que
abrangem genuinamente vários espaços de trabalho, como `list_workspaces` e as
ferramentas do feed de notícias — o feed de notícias é por utilizador e um agente
não tem utilizador próprio, pelo que essas ferramentas operam sobre os feeds do
proprietário do servidor.

As ferramentas com âmbito de repo verificam ainda que o repo está ligado a esse
espaço de trabalho.

## Saber o que a superfície vai recusar

- **Restrição por modo.** Uma chamada é resolvida no servidor em função do modo
  do espaço do agente que a faz. Um agente num modo só de leitura não consegue
  chegar a uma ferramenta de escrita omitindo `space_id` — o modo é procurado a
  partir da sua execução ativa.
- **Guardrails de ação.** As ferramentas mutáveis declaram as suas classes de
  efeitos e passam pela mesma política que o resto do produto usa. Consulte
  [Configurar guardrails](/pt-PT/manual/guias/configurar-guardrails/).
- **Confirmação.** Algumas ferramentas destrutivas constroem um payload de
  confirmação que tem de ser aprovado antes de a chamada prosseguir.

O catálogo completo é anunciado em `tools/list`, sem restrição de deteção — um
cliente MCP externo recusa chamar uma ferramenta que não esteja na sua lista em
cache, pelo que esconder ferramentas quebra-as em vez de as arrumar.

## Os servidores MCP pessoais continuam a ser do proprietário

Este guia trata do endpoint próprio do Control Center. A outra direção, os servidores MCP que o Control Center entrega aos agentes que executa, está listada em **Definições → Servidor → Servidores MCP → Servidores MCP externos**. Os servidores configurados na máquina do servidor para o Claude, o Codex, o Cursor, o Gemini, o VS Code, o Windsurf, o OpenCode ou num `.mcp.json` são encontrados aí automaticamente.

Esses servidores descobertos vêm da configuração de ferramentas do próprio utilizador do servidor e atuam com a identidade e as credenciais desse utilizador, por isso pertencem ao proprietário do servidor:

- Só estão disponíveis dentro das execuções do harness integrado que o proprietário do servidor inicia ou de que é responsável, incluindo a automação num espaço de trabalho de que o proprietário é responsável.
- A execução de um membro, a automação vinculada a um membro e cada execução num servidor sem proprietário registado não recebem nenhum deles. Aí as ferramentas não são listadas, não podem ser chamadas e não aparecem na pesquisa de ferramentas.
- Este endpoint nunca os lista, chama nem pesquisa, para ninguém, nem mesmo com o token do proprietário, e não transmite os seus recursos nem prompts. Por isso, um CLI de agente que alcança o Control Center por MCP, como o Claude Code, também não os obtém através do Control Center; usa a sua própria configuração.

Os servidores MCP configurados para o espaço de trabalho não são afetados por nada disto.

## Resolução de problemas

### O cliente não vê ferramentas

- Verifique se o cartão **Servidor MCP** diz que está em execução
- Verifique se a porta corresponde à porta do seu `cc_server`
- No Claude Code, verifique se passou `--mcp-config` e `--strict-mcp-config`

### 401 Não autorizado

O pedido não levava nenhum token, ou levava um antigo. Copie o token atual da linha **Token de autenticação** e envie-o como `Authorization: Bearer <token>`. Um token no URL é ignorado.

### 403 a partir de um cliente que funcionava antes

O pedido trazia um `Origin` de uma página web, ou um `Host` que o servidor não reconhece. Chame o endpoint a partir de um cliente e não de uma página do navegador, pelo endereço de loopback do servidor ou pelo seu nome de anfitrião público.

### 415 Tipo de conteúdo não suportado

Envie os corpos de `POST /mcp` como `application/json`.

### Uma chamada de ferramenta falha com «Missing or invalid argument: workspace_id»

Adicione `workspace_id`. Não existe nenhum espaço de trabalho implícito.

### Uma chamada de ferramenta é recusada como desconhecida

[Ferramentas MCP](/pt-PT/manual/referencia/ferramentas-mcp/) lista o catálogo.
Chame o nome exatamente como aparece lá.
