# Shrinking allowlist: cc_domain VALUE-OBJECT files that do not override both
# `==` and `hashCode`. Enforced by architecture_constraints_test.dart.
#
# Seeded 2026-08-22, when the guard was re-aimed at packages/cc_domain (it had
# been scanning `lib/**/domain/value_objects`, emptied by the backend exodus,
# and passing vacuously on the missing directories).
#
# Unlike the ENTITY list — which seeded with two files, both fixed on the spot,
# and is therefore empty — this one seeds with 28. They are not all bugs: a
# sealed action union, a codec, a paths holder and a descriptor are types you
# never compare by value, and forcing equality onto them would be ceremony. The
# ones that ARE bugs are the value objects a set/map/diff is keyed on. So this
# list is a starting point to work DOWN, file by file, with a judgement each
# time — not a to-do list to clear mechanically.
#
# The list only shrinks: a new value object without equality fails, and an entry
# that now overrides both (or was deleted) fails as stale.
